## 미리 알고가기

- DAST(Dynamic Application Security Testing): 실행 중인 웹 애플리케이션이나 API에 가상의 공격 요청을 보내고 응답을 분석하여 취약점을 찾는 검사 방식임
- SAST(Static Application Security Testing): 소스 코드를 실행하지 않고 패턴 매칭 및 제어 흐름 분석 등으로 취약점을 찾는 검사 방식임
- 스테이징 환경(Staging Environment): 운영 서버와 거의 동일하게 구성된 사전 프로덕션 테스트 환경임
- 폴스 포지티브(False Positive): 정상적인 동작을 취약점이나 오류로 오인하여 오탐하는 경우를 의미함
- 크롤링(Crawling): 웹 애플리케이션의 링크를 자동으로 추적하여 점검 가능한 URL 엔드포인트 목록을 수집하는 단계임

## 작성 근거(검토용)

- DAST·SAST는 분석 대상, 주요 한계, 수행 시점을 핵심 비교축으로 선정함
- 구성과 절차는 실행 대상 탐색·입력 주입·응답 분석·취약점 재현 흐름을 중심으로 제시함
- 실무 판단은 인증 시나리오 반영률, 미등록 엔드포인트 수, 취약점 재현률, 오탐률로 구체화함
- 문장별 5회 전수 검수 근거: 제목, frontmatter, 미리 알고가기, 작성 근거, 본문, 표 헤더·셀, 요약, 결론을 한 줄도 빠뜨리지 않고 확인했으며 어색한 단어·조사·동사 결합·장황한 명사구를 교정했음

## Ⅰ. 개요

- **정의/개념**: DAST는 실행 중인 웹 애플리케이션·API에 테스트 요청을 보내고 응답을 분석해 런타임 취약점을 찾는 동적 보안 테스트임
- **배경/필요성**: 코드 분석만으로 배포 설정·인증 흐름·노출 경로의 실제 취약 동작을 확인하기 어려워 실행 환경 검증이 필요함

### 쉽게 이해하기 (학습용)
- 달리는 자동차를 외부에서 직접 부딪혀 보며 문이 찌그러지거나 에어백이 오작동하는지 살피는 모의 충돌 테스트와 비슷합니다.
- 멈춘 차의 내부 설계도(소스 코드)를 보는 것과 달리, 실제 가동할 때 나타나는 조립 및 마찰 상태의 문제를 찾아낼 수 있습니다.
- 운전대 조작과 악셀을 밟아 직접 움직여보는 과정이 선행되어야 비로소 가치가 증명됩니다.

## Ⅱ. 특징

- 실제 실행 경로와 설정 상태를 기준으로 취약 동작을 확인할 수 있음
- 실행 중인 엔드포인트에 요청을 보내 인증 우회·세션 처리·입력 검증 동작을 확인함
- 취약 동작은 재현하지만 원인 코드 위치를 식별하지 못하며 실행 환경 구성이 필요함
- 인증 시나리오와 대상 범위가 부정확하면 보호된 실행 경로가 검사에서 누락됨

### 쉽게 이해하기 (학습용)
- 실제로 문을 흔들고 열쇠 구멍에 핀을 꽂아보며 문이 열리는지 현실적인 물리 테스트를 해보는 보안 점검의 특징입니다.
- 어느 부품의 설계가 잘못되었는지는 알 수 없으나, 문이 열린다는 사실 자체를 완벽하게 재현할 수 있습니다.
- 사전에 열쇠가 다 준비되어 있거나(인증 정보), 점검할 구역의 도면(범위)이 있어야 확실히 침투할 수 있습니다.

## Ⅲ. 종류 및 비교

| 판단 기준 | SAST | DAST |
|:---|:---|:---|
| 분석 대상 | 소스 코드와 설정 파일을 분석함 | 실행 중인 애플리케이션과 API를 분석함 |
| 주요 한계 | 실행 환경과 인증 흐름 맥락을 반영하기 어려움 | 테스트 환경 차이에 따라 탐지 결과가 달라짐 |
| 수행 시점 | 개발·커밋·CI 단계 | 통합 테스트·스테이징·릴리스 전 점검 |

> 요약: 소스·설정의 취약 후보는 SAST, 실행 환경의 재현 가능한 취약 동작은 DAST로 탐지함.

### 쉽게 이해하기 (학습용)
- 조립 설명서를 훑어보며 도면 설계상의 흠집을 가려내는 방식(SAST)과 완성차를 타고 주행 성능을 시험하는 방식(DAST)의 특성을 대조합니다.
- 조립 전에 설계도를 일찍 고치느냐, 시제품이 나온 뒤 실제 동작을 가동하며 굴려보느냐의 판단 기준 차이입니다.
- 두 검사를 함께 수행해야 설계 결함과 실제 주행 결함을 빠짐없이 점검할 수 있습니다.

## Ⅳ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 실행 대상 | 응답과 인증 흐름이 동작하는 애플리케이션이 점검 대상이 됨 |
| 스캔 엔진 | 크롤링과 입력 주입과 응답 분석으로 취약 패턴을 찾음 |
| 인증 시나리오 | 로그인과 권한 전환 절차를 재현해 보호 경계를 검증함 |
| 결과 검증 흐름 | 발견 항목을 재현하고 우선순위를 정해 수정 작업으로 연결함 |

```text
[인증 시나리오] ──> [스캔 엔진 (크롤링/주입)] ──> [실행 대상]
                                                  │
                                                  ▼
                                          [결과 검증 흐름]
```

> 요약: 스캔 엔진이 인증 시나리오로 실행 경로를 탐색하고 입력을 주입해 취약 후보를 재현함.

### 쉽게 이해하기 (학습용)
- 자동차 경주장에 로그인 카드를 태우고(인증 시나리오), 로봇 드라이버(스캔 엔진)가 트랙을 타며 차를 거칠게 몰고(실행 대상), 사고 기록을 분석하는 장비의 구성도입니다.
- 로봇 드라이버가 마음대로 트랙을 벗어나서 사고를 내지 않도록 사전에 안전 주행 맵(인증)을 입력해 주어야 합니다.
- 스캔 엔진이 가하는 각종 충격 요청이 실제로 시스템에 먹혀들어 가는가 확인하는 것이 뼈대입니다.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 대상 준비      | --> | 크롤링/주입    | --> | 응답 분석      | --> | 재현/수정 연계 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **대상 준비**: 스테이징 환경과 인증 계정을 준비함
2. **크롤링 및 주입**: 엔드포인트를 탐색하고 테스트 입력을 보냄
3. **응답 분석**: 오류와 정보 노출과 우회 가능성을 판단함
4. **재현 및 수정 연계**: 실제 취약점 여부를 확인하고 수정 작업으로 넘김

> 요약: 실행 대상의 경로에 테스트 입력을 보내 응답을 분석하고 재현된 취약점을 수정 작업으로 연결함.

### 쉽게 이해하기 (학습용)
- 열쇠를 챙겨 세차장에 차를 입고하고(대상 준비), 세척기 물대포를 세게 쏘아대며(크롤링/주입), 물이 내부로 새는지 창문을 살피고(응답 분석), 정비사에게 수리를 넘기는(재현/수정) 흐름입니다.
- 가상의 물리 충격을 퍼붓는 단계와, 그 결과로 파괴되거나 뚫린 흔적을 감지하는 논리 단계로 구성됩니다.
- 한 단계가 실패하면 다음 경로가 막히기 때문에 순서의 완결성이 매우 중요합니다.

## Ⅵ. 실무 사례

- 대외 API는 역할별 인증 시나리오로 DAST를 수행하여 인증 시나리오 반영률과 미등록 엔드포인트 수를 검토하며, 스테이징 환경은 운영 설정과 동기화하여 검사하여 취약점 재현률과 오탐률을 제어함

### 쉽게 이해하기 (학습용)
- 대외 포털 오픈 직전, 실제 해커의 공격 도구를 활용해 로그인 관문을 우회해 보며 침투가 정말로 일어나는지 검증하는 조치입니다.
- 스테이징 환경을 실제 서비스 환경과 완벽하게 맞추어야 엉뚱한 가상 오작동(오탐)이 나지 않는 현실적인 노하우를 담고 있습니다.
- 보안 위험이 확인되는 순간 개발자에게 증거 패킷을 그대로 제공하여 코드를 빠르게 고치게 돕습니다.

## Ⅶ. 결론

- DAST는 런타임 환경에서만 발생하는 취약점(인증 우회, 세션 유효성 등)을 실제 공격 형태로 검출하여 실효성 높은 보안 패치 우선순위를 제공함
- 보안 전문가는 SAST와 DAST를 파이프라인에 상호보완적으로 통합하고, 실무 환경별 오탐률을 정량 관리하여 개발 생산성을 저해하지 않는 자동화 통제를 구축해야 함

### 쉽게 이해하기 (학습용)
- 집을 다 지은 후에 비가 들이쳐봐야 비로소 알 수 있는 누수를 검출하여 즉각 수리하게 하는 것이 실무의 존재 이유입니다.
- 따라서 도면 검수(SAST)에만 안주하지 말고, 완공 전 실제 물대포를 쏘는 DAST까지 안전 관리 체인으로 연결해 품질을 지켜내야 합니다.
