## 미리 알고가기

- DAST는 실행 중인 애플리케이션을 외부에서 공격자 관점으로 점검하는 보안 테스트임
- 실제 배포 환경과 유사한 상태에서 취약 동작을 검증함
- 코드 가시성은 낮지만 실제 노출면 확인에는 강함

## Ⅰ. 개요

- **정의/개념**: 동적 애플리케이션 보안 테스트 DAST는 실행 중인 웹 애플리케이션이나 API를 외부에서 호출하고 응답을 분석해 입력 검증 실패와 인증 우회와 취약한 세션 처리 같은 런타임 보안 문제를 탐지하는 기법임
- **배경/필요성**: 정적 분석만으로는 실제 구성과 인증 흐름과 런타임 노출 경로를 모두 알기 어려우므로, 운영에 가까운 상태에서 악용 가능성을 확인하는 동적 검증이 필요함

## Ⅱ. 특징

- 실제 실행 경로와 설정 상태를 바탕으로 취약점을 검증할 수 있음
- 인증 우회와 취약 응답 처리와 노출 엔드포인트 탐지에 유리함
- 코드 내부 원인 분석은 약하고 테스트 환경 구축 비용이 듦
- 스캔 대상과 인증 시나리오가 부정확하면 결과 품질이 급격히 떨어짐

## Ⅲ. 종류 및 비교

| 판단 기준 | SAST | DAST |
|:---|:---|:---|
| 분석 대상 | 코드와 설정 | 실행 중 애플리케이션 |
| 장점 | 조기 발견과 빠른 피드백 | 실제 노출면과 런타임 취약점 확인 |
| 한계 | 런타임 맥락 부족 | 늦은 발견과 환경 의존 |
| 적합 단계 | 개발·CI | 통합·스테이징·릴리스 전 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Running Target | 실제 응답과 인증 흐름을 가진 실행 대상이 되어 취약 동작 검증의 기반이 됨 |
| Scanner Engine | 크롤링과 페이로드 주입과 응답 분석으로 취약 패턴을 탐지함 |
| Auth Scenario | 로그인과 권한 전환 시나리오를 정확히 재현해야 실제 보호 경계를 검증할 수 있음 |
| Finding Validation Flow | 발견 항목을 재현과 분류와 우선순위화해 개발 수정으로 연결함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 대상 준비      | --> | 크롤링/주입    | --> | 응답 분석      | --> | 재현/수정 연계 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **대상 준비**: 스테이징 환경과 인증 경로를 구성함
2. **크롤링 및 주입**: 엔드포인트를 탐색하고 테스트 페이로드를 보냄
3. **응답 분석**: 오류와 노출과 우회 가능성을 판정함
4. **재현 및 수정 연계**: 실제 취약점 여부를 검증하고 수정 작업으로 연결함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 인증 흐름과 사용자 상태를 충분히 재현하지 못하면 실제 중요 취약 경로를 놓칠 수 있음
   - 해결방안: role 기반 인증 시나리오를 포함하고 auth coverage ratio와 hidden endpoint discovery rate로 검증함
2. 문제: 실행 환경이 실제 운영과 다르면 구성 차이 때문에 결과 신뢰도가 낮아질 수 있음
   - 해결방안: production-like 환경을 유지하고 environment parity score와 reproduction success rate로 검증함
3. 문제: 스캔 결과가 많아도 재현과 우선순위화가 약하면 실제 수정 속도가 늦어질 수 있음
   - 해결방안: finding triage SLA를 운영하고 remediation lead time과 false positive rate로 검증함

## Ⅶ. 적용 사례

- 공개 웹 서비스 보안 점검에서는 DAST를 수행하고 확인 지표는 hidden endpoint discovery rate와 false positive rate임
- 릴리스 전 스테이징 환경에서는 인증 시나리오를 포함하고 확인 지표는 auth coverage ratio와 reproduction success rate임
- 보안 운영팀에서는 triage SLA를 관리하고 확인 지표는 remediation lead time과 environment parity score임

## Ⅷ. 결론

DAST의 가치는 경고 수보다 실제 노출된 실행 경로에서 악용 가능한 취약점을 확인하고 수정 우선순위로 연결하는 데 있음.
