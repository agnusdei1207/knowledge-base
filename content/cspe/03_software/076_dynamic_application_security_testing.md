## 미리 알고가기

- DAST는 실행 중인 애플리케이션을 외부에서 점검해 취약한 동작을 찾는 보안 테스트임
- SAST는 코드를 실행하지 않고 소스 수준에서 취약 패턴을 찾는 정적 분석임
- 스테이징 환경은 운영과 최대한 비슷하게 구성한 시험 환경임

## Ⅰ. 개요

- **정의/개념**: DAST는 실행 중인 웹 애플리케이션이나 API를 외부에서 호출하고 응답을 분석해 입력 검증 실패와 인증 우회와 세션 처리 오류 같은 런타임 보안 취약점을 찾는 동적 보안 검증 기법임.
- **배경/필요성**: 코드 분석만으로는 실제 배포 설정과 인증 흐름과 노출 경로를 모두 확인하기 어려우므로, 운영에 가까운 상태에서 실제 악용 가능성을 점검할 방식이 필요함.

## Ⅱ. 특징

- 실제 실행 경로와 설정 상태를 기준으로 취약 동작을 확인할 수 있음
- 실행 중인 endpoint에 요청을 보내 인증 우회·세션 처리·입력 검증 동작을 확인함
- 코드 내부 원인 분석은 약하고 환경 준비 비용이 큼
- 인증 시나리오와 대상 범위가 부정확하면 결과 신뢰도가 급격히 떨어짐

## Ⅲ. 종류 및 비교

| 구분 | SAST | DAST |
|:---|:---|:---|
| 분석 대상 | 소스 코드와 설정 파일을 분석함 | 실행 중인 애플리케이션과 API를 분석함 |
| 발견 정보 | 코드 위치·데이터 흐름·취약 규칙 후보 | 노출 endpoint·요청·응답·재현 가능한 취약 동작 |
| 주요 한계 | 실행 환경과 인증 흐름 맥락을 반영하기 어려움 | 늦은 단계에서 수행되고 시험 환경 품질에 크게 의존함 |
| 수행 시점 | 개발·commit·CI 단계 | 통합 시험·staging·릴리스 전 점검 |

> 요약: DAST는 경고 수를 늘리는 도구가 아니라 실제 노출된 실행 경로에서 악용 가능한 취약점을 확인하는 도구임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 실행 대상 | 실제 응답과 인증 흐름을 가진 애플리케이션이 점검 기준이 됨 |
| 스캔 엔진 | 크롤링과 입력 주입과 응답 분석으로 취약 패턴을 찾음 |
| 인증 시나리오 | 로그인과 권한 전환 절차를 재현해 보호 경계를 검증함 |
| 결과 검증 흐름 | 발견 항목을 재현하고 우선순위를 정해 수정 작업으로 연결함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 대상 준비      | --> | 크롤링/주입    | --> | 응답 분석      | --> | 재현/수정 연계 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **대상 준비**: 스테이징 환경과 인증 계정을 준비함
2. **크롤링 및 주입**: 엔드포인트를 탐색하고 시험 입력을 보냄
3. **응답 분석**: 오류와 정보 노출과 우회 가능성을 판단함
4. **재현 및 수정 연계**: 실제 취약점 여부를 확인하고 수정 작업으로 넘김

## Ⅵ. 실무 적용 및 유의점

1. 공개 웹 서비스와 대외 API 점검에서는 DAST가 효과적이지만 인증 흐름을 충분히 재현하지 못하면 핵심 취약 경로를 놓칠 수 있으므로 역할별 계정 시나리오를 함께 두고 인증 시나리오 반영률과 숨은 엔드포인트 발견 건수로 확인함
2. 릴리스 직전 스테이징 환경에서 DAST를 수행할 때는 운영과 환경 차이가 크면 결과가 흔들리므로 환경 일치 수준을 관리하고 취약점 재현 성공률과 오탐 비율로 확인함

## Ⅶ. 결론

DAST의 실질 가치는 운영에 가까운 실행 경로에서 실제 악용 가능한 취약점을 확인해 수정 우선순위로 연결하는 데 있음.
