## 미리 알고가기

- 표 이해는 셀의 글자 인식보다 행과 열과 병합 구조 복원이 더 핵심임
- 일반 OCR은 표를 글자 나열로만 읽어 의미 관계를 쉽게 잃음
- 재무표와 스펙표와 통계표는 헤더 연결 정확도가 실무 품질을 좌우함

## Ⅰ. 개요

- **정의/개념**: 표 이해는 문서 내 표 영역을 탐지하고 행과 열과 병합 셀과 헤더 관계를 복원한 뒤, 각 셀 값을 의미적으로 연결해 기계가 활용 가능한 구조 데이터로 전환하는 문서 해석 기술임
- **배경/필요성**: 기업 문서의 핵심 수치 정보는 표 안에 밀집돼 있으나 일반 OCR은 셀 구조를 무너뜨리므로, 표의 위상 구조와 의미 연결을 따로 이해하는 기술이 필요함

## Ⅱ. 특징

- 표의 외곽 탐지와 내부 구조 복원과 의미 연결이 순차적으로 결합됨
- 병합 셀과 다단 헤더와 각주 처리 여부가 성능 차이를 크게 만듦
- 수치 자체보다 어느 행과 열의 값인지 매핑 정확도가 실무 핵심임
- 표 바깥의 단위와 주석을 놓치면 수치 해석 오류가 커질 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 일반 OCR | Table Understanding | Text-to-SQL Table QA |
|:---|:---|:---|:---|
| 셀 구조 복원 | 낮음 | 높음 | 입력 의존 |
| 헤더-값 연결 | 낮음 | 높음 | 높음 |
| 질의 응답 확장성 | 낮음 | 중간 | 높음 |
| 전처리 중요도 | 낮음 | 매우 높음 | 매우 높음 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Table Detector | 문서에서 표 영역을 찾아내고 표 외부 텍스트와 분리해 분석 대상을 정함 |
| Structure Parser | 행과 열과 병합 셀 구조를 복원해 표의 논리적 골격을 구성함 |
| Cell OCR | 각 셀의 텍스트와 숫자를 읽어 내용 값을 추출함 |
| Header, Context Linker | 셀 값과 행열 헤더와 단위와 각주를 연결해 의미가 있는 구조 데이터로 완성함 |

```text
+-------------------+      +-------------------+      +-------------------+
| Table Detector    | ---> | Structure Parser  | ---> | Cell OCR          |
+-------------------+      +-------------------+      +-------------------+
                                                           |
                                                           v
                                                   +-------------------+
                                                   | Header / Context  |
                                                   +-------------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 표 영역 탐지    | --> | 격자 구조 복원  | --> | 셀 값 추출      | --> | 의미 연결/직렬화 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **표 영역 탐지**: 문서에서 표 후보를 분리함
2. **격자 구조 복원**: 행과 열과 병합 구조를 복원함
3. **셀 값 추출**: 각 셀 내용을 OCR로 읽음
4. **의미 연결 및 직렬화**: 헤더와 단위와 각주를 연결해 JSON이나 HTML로 저장함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 선이 없거나 병합 셀이 많은 표는 구조 인식이 흔들려 셀 위치와 의미 연결이 쉽게 무너질 수 있음
   - 해결방안: layout-aware parser와 span-aware reconstruction을 적용하고 TEDS와 cell F1로 검증함
2. 문제: 표 주변의 단위와 각주를 놓치면 숫자는 맞아도 의미 해석이 완전히 잘못될 수 있음
   - 해결방안: context window와 footnote linkage를 적용하고 unit accuracy와 analyst validation rate로 검증함
3. 문제: 추출 결과를 단순 텍스트로 저장하면 행열 관계가 다시 사라져 후속 RAG나 QA 정확도가 떨어질 수 있음
   - 해결방안: HTML이나 markdown serialization과 relational schema를 적용하고 Table QA accuracy와 retrieval gain으로 검증함

## Ⅶ. 적용 사례

- 회계 분석이 재무제표 표를 자동 구조화하도록 표 이해를 적용하며 확인 지표는 TEDS와 field linkage accuracy임
- 제품 카탈로그 인덱싱이 제원표를 구조 데이터로 변환하도록 표 이해를 운영하며 확인 지표는 extraction F1과 search precision임
- 문서 RAG가 표 기반 질의에 답하도록 표 이해를 활용하며 확인 지표는 Table QA accuracy와 groundedness임

## Ⅷ. 결론

표 이해는 문서 AI에서 가장 밀도 높은 지식 영역을 다루는 기술이므로, 구조 복원과 헤더 연결과 단위 보존이 핵심 성공 기준이 됨.
