# 📖 【암기용】 개념 완전 이해

> 목적: Table Understanding을 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **정의**: 표의 행·열·셀 병합·헤더·단위·관계를 인식하고 의미를 해석하는 문서 AI 기술
- **왜 필요한가**: 기업 문서의 핵심 수치와 조건은 표에 많지만, 단순 OCR은 셀 구조와 헤더 관계를 잃기 쉬움.
- **핵심 직관**: 표를 글자 목록이 아니라 행과 열의 관계가 있는 데이터베이스처럼 이해하는 기술임.

## 깊이 이해
- **배경·문제의식**: OCR 결과가 "100 200 300"처럼 텍스트만 나오면 어떤 값이 어느 항목·기간·단위에 속하는지 알 수 없다.
- **작동 원리**: table detection, structure recognition, cell OCR, header association, semantic parsing을 통해 표를 HTML/CSV/JSON 구조로 복원함.
- **비유**: 사람이 엑셀 표를 볼 때 왼쪽 행 제목과 위쪽 열 제목을 함께 보고 "2026년 매출 300억"이라고 해석하는 것과 같음.
- **구체 예시**: 재무제표 PDF에서 매출·영업이익·연도 헤더를 복원해 "2026년 영업이익률" 질문에 계산 답변 제공.
- **흔한 오해·주의점**: 표 OCR 정확도만으로 충분하지 않음. 병합 셀, 다단 헤더, 단위, 각주를 함께 처리해야 함.

## 연결 개념
- Document AI — 표 이해를 포함하는 문서 처리 체계
- OCR with LLM — 표 OCR 결과를 LLM으로 구조화·질의응답
- Multimodal RAG — 표를 근거로 검색·답변하는 RAG

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Table Understanding은 표의 시각 구조와 셀 의미 관계를 복원·해석하는 기술임.
> 2. **가치**: PDF·이미지 표의 수치를 구조화해 검색, 계산, RAG 질의응답에 활용함.
> 3. **판단 포인트**: 다단 헤더, 병합 셀, 단위·각주 처리 여부가 실무 정확도를 좌우함.

## Ⅰ. 개요 및 필요성

Table Understanding은 표 구조와 의미를 해석하는 문서 AI 기술임. 기업 문서의 핵심 수치와 조건은 표에 포함되지만 OCR 단독은 행·열 관계를 보존하지 못한다. 표를 구조화 데이터로 복원해야 계산과 질의응답이 가능하다.

## Ⅱ. 구조 및 구성요소

```text
Document Image → Table Detection → Structure Recognition
  → Cell OCR/Header Linking → Semantic Table JSON
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Table Detector | 표 영역 탐지 | mAP, bbox |
| Structure Recognizer | 행·열·셀 병합 구조 복원 | HTML grid |
| Cell OCR | 셀 텍스트 추출 | 숫자·단위 정확도 |
| Semantic Parser | 헤더·단위·각주 의미 연결 | JSON/CSV 변환 |

> 요약: 표 이해는 표 영역 탐지, 구조 복원, 셀 인식, 의미 연결을 거쳐 질의 가능한 데이터로 변환함.

## Ⅲ. 동작원리 및 흐름도

```text
문서 입력 → 표 영역 탐지 → 행/열 구조 복원
  → 셀 OCR → 헤더/단위 연결 → 계산·검색 활용
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 표 영역 bbox 탐지 | table mAP ≥0.9 |
| 2 | 행·열·병합 셀 구조 복원 | structure F1 ≥0.85 |
| 3 | 셀 텍스트와 숫자 인식 | numeric exact match ≥98% |
| 4 | 헤더·단위·각주 연결 | cell-to-header accuracy ≥90% |

> 요약: 표를 위치 기반 이미지에서 행·열 관계와 의미가 있는 구조화 데이터로 복원함.

## Ⅳ. 특징

| 구분 | OCR 텍스트 | Table Understanding | 판단 포인트 |
|:---|:---|:---|:---|
| 구조 보존 | 낮음 | 행·열·병합 셀 복원 | 재무·통계 표 필수 |
| 의미 해석 | 제한적 | 헤더·단위 연결 | 계산 질의 가능 |
| 출력 | 문자열 | HTML/CSV/JSON | 시스템 연동 용이 |
| 한계 | 표 관계 손실 | 복잡 표·각주 처리 비용 | 검수 큐 필요 |

> 요약: Table Understanding은 표를 계산 가능한 데이터로 바꾸지만 복잡한 헤더와 각주 처리 검증이 필요함.

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 재무 문서: PDF 표를 HTML/CSV로 복원하고 매출·비용·연도 헤더 연결 정확도 90% 이상 검증
2. RAG 연동: 표 cell citation을 답변에 포함해 "어느 행·열 수치인지" 원문 위치 제공
3. 검수 운영: structure confidence 0.85 미만, numeric mismatch 발생 시 사람 검수 큐로 전송

**결론 (2줄):**
- 기술사 판단: 수치·표 기반 업무는 Table Understanding, 단순 본문 검색은 OCR+Text RAG 적용
- 향후 방향: LLM/VLM이 표 구조 복원과 자연어 계산 질의응답을 통합하는 방향으로 발전
