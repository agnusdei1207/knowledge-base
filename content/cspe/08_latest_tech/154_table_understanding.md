# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: 문서나 이미지 속에 들어있는 표(Table)를 단순히 글자 더미로 인식하지 않고, 표 특유의 복잡한 구조(행, 열, 셀 병합, 헤더, 각주)와 수치의 의미까지 완벽하게 파악하여 엑셀이나 데이터베이스 형태로 복원해 내는 특화된 AI 기술.
- **필요성**: 기업 문서를 분석할 때, 돈(재무제표)이나 스펙(제품 제원표) 같은 가장 중요하고 영양가 높은 핵심 정보는 무조건 '표' 안에 갇혀 있음. 일반 OCR은 표의 선을 무시하고 글자를 뒤죽박죽 섞어버려 표 데이터를 완전히 망가뜨림.
- **핵심 직관**: 엑셀 마법사. 스캔된 종이 표를 보고 선을 따라가며 "아 이건 2026년 열이고, 이건 매출액 행이니까 크로스 되는 300억이 정답이구나!" 라고 인간처럼 구조적 맥락을 읽어냄.

## 깊이 이해
- **배경**: 일반 텍스트는 위에서 아래로, 왼쪽에서 오른쪽으로 읽으면 끝남(1차원 시퀀스). 하지만 표는 2차원의 그리드(Grid) 구조이며, 셀이 위아래로 합쳐져(Span) 있거나 다단 헤더(계층 구조)를 갖는 등 위상 수학적 복잡성이 극도로 높아 별도의 전용 아키텍처가 필수적임.
- **작동 원리 (3-Step 파이프라인)**:
  1. **표 탐지 (Table Detection)**: 문서 전체 이미지에서 "요 네모난 박스 영역이 표구나" 하고 표의 외곽선(Bounding Box)을 찾아냄.
  2. **구조 인식 (Structure Recognition)**: 표 내부의 행(Row)과 열(Column) 선을 그어 셀의 격자(Grid) 좌표를 잡음. 병합된 셀(Rowspan, Colspan) 구조를 HTML 테이블 태그(`<tr>`, `<td>`) 형식으로 뼈대를 그림.
  3. **셀 내용 추출 및 매핑 (Cell Extraction & Linking)**: 셀 안의 글자(숫자)를 OCR로 읽어 넣고, 이 숫자가 어느 행 헤더(예: 영업이익)와 열 헤더(예: 2분기)에 속하는지 의미적 연결(Relational Linking)을 수행함.
- **구체 예시**: 사업보고서 PDF의 손익계산서 표. 일반 OCR은 "매출액 100 120 영업이익 10 15" 라고 텍스트만 뽑아서 무슨 숫자인지 모름. Table Understanding은 구조를 파악해 `{"항목": "영업이익", "2023년": 10, "2024년": 15}` 라는 정형 JSON 데이터로 변환.
- **흔한 오해/주의점**: 표 주변에 작게 적힌 '(단위: 백만 원)'이나 '*각주: 일회성 비용 제외' 같은 메타데이터를 놓치면, AI가 100만 원을 1원이라고 답하는 대형 금융 사고가 발생함. 표 내부뿐 아니라 표 바깥의 문맥까지 연결해야 진짜 이해임.

## 연결 개념
- **Document AI**: 표 이해, 텍스트 이해, 레이아웃 분석을 모두 아우르는 큰 개념.
- **Multimodal RAG**: RAG가 답변할 때 표(Table) 안의 수치를 근거로 삼기 위해 표 이해 기술로 전처리하는 과정이 필수임.
- **Graph Neural Network (GNN)**: 표의 셀과 헤더 간의 관계를 '노드'와 '엣지'로 정의하여 의미를 추론하는 데 쓰이는 AI 딥러닝 기법.

# 📝 【답안용】 시험 답안 템플릿
## 핵심 인사이트 (3줄 요약)
- **본질**: 비정형 문서 이미지 내의 2D 그리드(Grid) 형태의 표 객체를 탐지하고, 셀 간의 위상학적 구조(Topology)와 행/열 헤더(Header)의 관계적 의미(Semantic Relation)를 보존하여 기계 가독형 포맷(HTML/JSON)으로 파싱하는 복합 추론 기술.
- **가치**: 재무제표, 실험 결과, 금융 상품 스펙 등 엔터프라이즈 코퍼스의 가장 밀도 높은 정형(Structured) 지식을 데이터베이스화하여, 정밀한 수치 기반의 Table QA 및 비즈니스 의사결정 자동화를 가능케 함.
- **판단 포인트**: 기술 도입 시 복잡한 병합 셀(Spanning Cells) 복원력과 헤더 계층 구조 인식률이 핵심 지표이며, RAG 파이프라인 연계 시 표 데이터를 마크다운(Markdown)이나 텍스트 직렬화(Serialization)로 변환하는 전략적 설계가 답변 품질을 좌우함.

## Ⅰ. 개요 및 필요성
- **정의**: 비정형/반정형 문서 내에서 표(Table) 영역을 식별(Detection)하고, 논리적 셀 구조(Structure)와 내용(Cell Content)을 추출하여 의미적 관계(행/열 매핑)를 재구성하는 컴퓨터 비전 및 NLP 융합 기술.
- **배경**: 기존 일반 텍스트 전용 OCR이나 읽기 순서(Reading Order) 기반 파서는 표 안의 데이터를 만날 경우 행렬의 의미론적 관계가 단절되어 데이터로서의 무결성이 완전히 붕괴됨.
- **필요성**: PDF 기반의 RAG 시스템에서 "2023년 3분기 B사업부의 마진율은 얼마인가?"와 같은 다차원 교차 질의(Cross-reference Query)에 대한 완벽한 답변 근거(Ground Truth)를 확보하기 위함.

## Ⅱ. Table Understanding 핵심 아키텍처 단계
단순 문자 인식을 넘어선 구조적 역공학(Reverse Engineering) 과정.
| 처리 단계 | 주요 태스크 및 동작 메커니즘 | 관련 딥러닝 아키텍처 |
|:---:|:---|:---|
| **1. 탐지**<br>(Table Detection) | 문서의 전체 레이아웃에서 표가 위치한 영역의 경계선(Bounding Box)을 찾아 크롭(Crop)함. | YOLO, Faster R-CNN, Cascade R-CNN |
| **2. 구조 인식**<br>(Structure Recognition) | 잘라낸 표 이미지에서 가로선/세로선을 식별하거나 시각 특징을 기반으로 그리드 좌표를 땀. Rowspan, Colspan 등 병합 셀의 논리적 뼈대(HTML 구조)를 생성. | Split & Merge(휴리스틱 알고리즘), Encoder-Decoder (Image-to-Text), TableMaster |
| **3. 의미 연결**<br>(Cell Linking) | OCR로 추출한 텍스트 내용을 뼈대 안에 주입하고, 각 데이터 셀이 종속된 계층적 Key 헤더(어느 연도, 어느 항목인지)를 Graph 형태로 매핑(Semantic Parsing). | Graph Neural Networks (GNN) 등 |

## Ⅲ. 표 이해 기술의 기술적 난제 및 해결 전략
현실 세계의 표는 AI의 시야를 방해하는 수많은 노이즈를 포함함.
1. **Borderless/선 없는 표 (Invisible Lines)**:
   - 외곽선이나 내부 선이 투명하고 여백(White Space)으로만 구분된 표는 시각적 분할(Split) 알고리즘이 붕괴됨.
   - **해결**: LayoutLM, TAT-QA 모델처럼 선(Image)에 의존하지 않고, 텍스트 토큰 간의 간격과 정렬 상태 패턴을 동시에 학습하는 멀티모달 아키텍처 채택.
2. **다단 헤더 (Multi-level Headers) 및 복합 논리**:
   - 상단 헤더가 3단계로 쪼개지거나(예: 전체 $\rightarrow$ 국내/해외 $\rightarrow$ 1Q/2Q), 각주 기호(*, 1)가 달린 경우.
   - **해결**: 표를 HTML/XML 구조의 트리(Tree) 계층 모델로 강제 직렬화한 후, 대규모 언어 모델(LLM)의 추론 능력을 빌려 헤더의 상하 관계를 교정(Correction).

## Ⅳ. LLM/RAG 파이프라인 연계 (Serialization 전략)
표를 추출한 후, 이를 LLM이 어떻게 잘 이해하게 먹여줄 것인가의 문제.
- **전략 1: HTML/Markdown 직렬화 (업계 표준)**:
  - 추출된 표를 마크다운 파이프(`|`) 테이블 포맷으로 직렬화. 최신 LLM(GPT-4 등)은 코드 학습이 잘 되어 있어 HTML이나 마크다운 태그의 행열 구조를 소스코드 읽듯 완벽히 이해함.
- **전략 2: 자연어 문장 전개 (Textualization)**:
  - `[영업이익]의 [2023년] 값은 [100억]입니다.` 형태로 모든 셀의 관계를 완전한 자연어 문장으로 분리. 텍스트 임베딩 모델(Vector DB) 검색 시 재현율(Recall) 상승.
- **전략 3: Text-to-SQL (고급)**:
  - 표 데이터를 아예 관계형 DB(SQLite 등) 테이블로 삽입. 사용자가 질문하면 LLM이 답변 대신 SQL 쿼리문을 작성해 DB에서 직접 수치를 뽑아냄 (수치 연산 및 집계 쿼리에 절대적 정확성 보장).

## Ⅴ. 실무 적용 및 결론
- **판단 지표**: TEDS(Tree-Edit-Distance-based Similarity, 정답 표와 AI가 만든 표 간의 트리 구조 유사성 점수), Cell/Header Extraction F1 Score.
- **실무 설계**: 대형 회계법인의 상장사 재무제표 대규모 팩트 체크(Fact-Check) 시스템 구축. 수천 개 회사의 다트(DART) 공시 PDF에서 재무/손익 표를 추출해야 함. 오픈소스 파서와 상용 Document AI(Azure Form Recognizer)를 하이브리드로 구성하여 Table Extraction 모듈 구축. 복잡한 주석 및 단위(백만 원, 천 원 변동) 처리를 위해, 추출된 HTML 형식 표를 프롬프트로 감싸 사내 LLM에 태워 단위를 통일하고 검증하는 파이프라인 구현. 회계사들의 수작업 데이터 대조 시간을 건당 4시간에서 10초로 혁신.
- **결론**: 표 이해(Table Understanding)는 엔터프라이즈 AI의 지식 구축 과정에서 가장 다루기 까다로운 병목이자 보물창고이며, 시각 구조 분석 모델과 LLM의 논리적 추론력이 결합되어 완벽한 형태의 데이터 자산화 파이프라인을 완성하게 될 것이다.

### 🔀 문제 유형별 목차 전환
- **Ⅱ·Ⅲ 강조 (개념/원리형)**: Image-to-Text 아키텍처(예: EDD 구조) 기반의 딥러닝 표 구조 인식 모델링 원리 및 TEDS(Tree-Edit-Distance) 지표의 수리적 평가 메커니즘.
- **Ⅴ·Ⅵ 강조 (실무/설계형)**: 표 데이터 기반 특화 RAG (Table-QA) 구축을 위한 청킹(Chunking) 전략(행 단위 분할 vs 표 전체 보존) 비교 및 환각을 100% 제거하기 위한 Text-to-SQL 에이전트(Agent) 아키텍처 설계.
