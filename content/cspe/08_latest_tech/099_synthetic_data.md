# 📖 【암기용】 개념 완전 이해

> 목적: Synthetic Data를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: 실제 데이터를 직접 수집하지 않고 시뮬레이션·규칙·생성모델로 만든 학습·평가용 데이터
- **왜 필요한가**: 개인정보, 희귀 사례, 라벨 비용, 데이터 부족 문제를 완화하기 위해 인공 데이터를 생성함.
- **핵심 직관**: 실제 사고를 기다리지 않고 가상 훈련장에서 다양한 사고 상황을 만들어 학습시키는 방식임.

## 깊이 이해
- **배경·문제의식**: AI 모델은 데이터 품질과 다양성에 의존하지만, 실제 데이터는 수집 비용·법적 제약·불균형 문제가 큼. Synthetic Data는 부족한 케이스와 위험 상황을 보강함.
- **작동 원리**: 생성모델, 시뮬레이터, rule engine, teacher LLM으로 데이터를 만들고, 품질 필터·중복 제거·privacy check를 거쳐 학습·평가에 사용함.
- **비유**: 조종사가 실제 비행 사고를 기다리지 않고 시뮬레이터에서 폭풍·엔진 고장 상황을 반복 훈련하는 것과 같음.
- **구체 예시**: LLM instruction data, 자율주행 rare scenario, 의료 이미지 보강, 금융 이상거래 케이스 생성에 활용됨.
- **흔한 오해·주의점**: 합성 데이터 증가는 품질 향상을 보장하지 않음. 현실 분포와 다른 데이터는 모델 편향과 성능 착시를 만든다.

## 연결 개념
- Data Augmentation — 기존 데이터 변형 보강
- Knowledge Distillation — teacher LLM 기반 데이터 생성
- Privacy Preserving AI — 개인정보 위험 완화

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Synthetic Data는 생성모델·시뮬레이션·규칙으로 만든 인공 데이터로 학습·평가 부족분을 보완함.
> 2. **가치**: 개인정보·희귀 케이스·라벨 비용 문제를 완화하고 모델 coverage를 확장함.
> 3. **판단 포인트**: 현실성, 다양성, privacy, bias, leakage, 품질 필터링을 함께 검증해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 생성 파이프라인 이해 확인 | 생성->품질 필터->privacy/bias 검증->실제 평가 4단계 | 생성 기법(GAN·LLM) 나열에 그침 |
| 품질 검증 판단 확인 | 실제 holdout에서 성능 개선 증명이 최종 기준 | 합성 데이터 자체 품질만으로 효과 단정 |
| 규제·프라이버시 인식 확인 | PII 검사, k-anonymity, membership leakage | "개인정보 문제 해결"로 무조건 단정 |

> 요약: 이 문제는 데이터 생성이 아니라 실제 분포 대비 검증과 프라이버시 통제 체계를 묻는다.

## Ⅰ. 개요 및 필요성

- 개요: 인공 생성 학습·평가 데이터
- 배경: 실제 데이터는 부족하거나 개인정보 규제, 희귀 이벤트 불균형, 라벨링 비용 때문에 모델 학습에 바로 쓰기 어려움.
- 필요성: LLM·GAN·diffusion·simulator와 품질 필터, PII 검사, 분포 검증으로 학습 데이터 범위를 보완해야 함.

## Ⅱ. 구조 및 구성요소

```text
Source Spec/Seed Data -> Generator/Simulator/LLM
      -> Quality Filter -> Privacy/Bias Check -> Train/Eval Dataset
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Generator | 합성 샘플 생성 | GAN, Diffusion, LLM |
| Simulator | 물리·업무 상황 생성 | 자율주행, 제조 |
| Quality Filter | 저품질·중복 제거 | rule, LLM judge |
| Privacy Check | 개인정보·leakage 점검 | k-anonymity, PII |

> 요약: 합성 데이터는 생성, 품질 필터링, 개인정보·편향 검증을 거쳐 학습·평가에 사용함.

## Ⅲ. 동작원리 및 흐름도

```text
목표 케이스 선정 -> 데이터 생성 -> 품질·중복 필터링
    -> 실제 데이터 분포 비교 -> 학습/평가 적용 -> 성능 검증
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 부족 케이스·위험 시나리오 정의 | coverage gap |
| 2 | generator로 샘플 생성 | diversity, realism |
| 3 | privacy·bias·중복 점검 | PII 0건, leakage |
| 4 | 모델 학습·평가 반영 | real test uplift |

> 요약: 합성 데이터는 생성 자체보다 실제 테스트셋에서 성능 개선을 증명하는 것이 핵심임.

## Ⅳ. 특징

| 구분 | 실제 데이터 | 합성 데이터 | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 수집 | 비용·시간 큼 | 대량 생성 가능 | 라벨 비용 절감 |
| 개인정보 | 직접 포함 가능 | 통제 가능 | leakage 검사 |
| 희귀 케이스 | 부족 | 의도적 생성 | coverage 확대 |
| 리스크 | 현실성 높음 | 분포 왜곡 가능 | real eval 필수 |

> 요약: 합성 데이터는 부족 케이스 보강에 유리하지만, 현실 분포와 품질 검증 없이는 모델 성능 착시를 만들 수 있음.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 실제 데이터 수집 | Data Augmentation | Synthetic Data | 선택 기준 |
|:---|:---|:---|:---|:---|
| 원천 | 현장 수집·라벨링 | 기존 데이터 변형 | 생성모델·시뮬레이션 | 원본 존재 여부 |
| 적합 상황 | 기준 성능 확보 | 데이터 부족·불균형 | 원본이 없는 희귀·민감 케이스 | coverage gap 유형 |
| 위험 | 비용·규제 | 라벨 훼손 | 분포 왜곡·성능 착시 | 검증 체계 수준 |

> 요약: 원본이 있으면 증강, 원본 자체가 없거나 반출 불가한 케이스만 합성으로 보완함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 성능 착시 | 합성 분포에 과적합 | 실제 holdout으로만 최종 평가 | real test uplift |
| model collapse | 합성 데이터 재귀 학습 | 실데이터 혼합 비율 유지, 세대 추적 | 세대별 품질 저하율 |
| privacy 역추출 | seed 원본 기억·재현 | membership inference 검사, PII 필터 | leakage 검출 0건 |

> 요약: 합성 데이터 리스크는 착시·붕괴·역추출이며, 실데이터 기준 평가와 혼합 비율로 통제함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. LLM instruction data는 teacher LLM 생성 후 중복 제거, PII 검사, human review 5~10% 샘플링 적용
2. 이상거래·보안 탐지는 희귀 공격 시나리오를 합성하고 실제 운영 로그 holdout에서 recall 개선을 검증
3. 의료·금융 데이터는 synthetic-only 학습이 아니라 실제 비식별 데이터와 혼합 비율을 10/30/50%로 비교

**결론 (2줄):**
- 기술사 판단: 희귀·민감·라벨 부족 영역은 합성 데이터, 최종 성능 검증은 실제 holdout 데이터로 수행함.
- 향후 방향: 합성 데이터는 LLM 데이터 엔진, 시뮬레이션, privacy-preserving AI의 핵심 축으로 확산됨.
