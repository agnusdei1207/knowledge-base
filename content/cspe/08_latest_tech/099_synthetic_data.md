# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: 실제 환경에서 수집되거나 사람이 직접 라벨링한 데이터가 아니라, 컴퓨터 알고리즘(생성형 AI, 시뮬레이션 등)을 통해 인위적으로 만들어낸 학습용 가상 데이터.
- **필요성**: 현실 세계의 데이터는 구하기 비싸고(비용), 개인정보보호법에 걸리며(규제), 특정 상황(예: 자율주행 사고 상황)은 너무 희귀해서 모델을 충분히 훈련시킬 수 없음.
- **핵심 직관**: 전투기 조종사를 훈련시킬 때, 값비싼 실제 전투기를 추락시키며(실제 데이터) 배우게 하는 대신, 비행 시뮬레이터(합성 데이터 생성기)에서 수만 번의 폭풍우 상황을 가상으로 겪게 하여 실력을 키우는 것.

## 깊이 이해
- **배경**: AI 모델 파라미터가 수천억 개로 늘어나면서 인류가 쌓아온 고품질 텍스트 데이터(인터넷 문서 등)가 고갈될 위기(Data Wall)에 처함. 이를 돌파하기 위해 "AI가 AI를 학습시킬 데이터를 스스로 만드는 시대"가 도래함.
- **작동 원리**:
  1. **Teacher-Student**: 똑똑한 대형 모델(GPT-4)에게 지시를 내려 특정 도메인의 질문-답변 쌍을 대량으로 생성하게 함.
  2. **시뮬레이션 기반**: 3D 엔진(Unreal 등)을 이용해 가상의 도로, 날씨, 보행자 이미지를 렌더링.
  3. **노이즈 및 규칙 기반**: 원본 데이터의 통계적 특성을 유지하면서 식별 정보만 지운 가상 프로필(금융, 의료 데이터) 생성.
- **비유**: 최고급 요리사(GPT-4)의 레시피(합성 데이터)를 대량으로 복사해서, 동네 식당 주방장(소형 모델)에게 연습시켜 비슷한 맛을 내게 만드는 것.
- **구체 예시**: Alpaca 모델(Stanford). LLaMA 베이스 모델을 튜닝하기 위해 사람이 데이터를 만들지 않고, GPT-3.5 API에 $500를 지불하여 5만 2천 개의 고품질 지시-응답(Instruction) 합성 데이터를 만들어내어 챗봇 훈련을 완료함.
- **흔한 오해/주의점**: 합성 데이터를 무조건 많이 쓴다고 좋은 것이 아님. AI가 만든 데이터에는 치명적인 환각(Hallucination)이나 편향이 섞일 수 있으며, 자신만의 똥(저품질 합성 데이터)을 계속 먹다 보면 모델이 서서히 붕괴하는 'Model Collapse' 현상이 발생함.

## 연결 개념
- **Data Augmentation (데이터 증강)**: 기존 데이터를 돌리거나 자르는 기법. 합성 데이터는 아예 '새로 창조'한다는 점에서 더 넓고 깊은 개념.
- **Knowledge Distillation (지식 증류)**: 큰 모델이 합성 데이터를 생성하여 작은 모델을 학습시키는 아키텍처.
- **Model Collapse (모델 붕괴)**: 합성 데이터의 반복 사용 시 나타나는 부작용.

# 📝 【답안용】 시험 답안 템플릿
## 핵심 인사이트 (3줄 요약)
- **본질**: 통계적 모델링, 시뮬레이션 환경, 혹은 상위 생성형 AI(Teacher LLM)를 활용하여 실제 데이터의 물리적·수학적·언어적 분포를 모방해 생성한 인공 데이터.
- **가치**: Privacy(개인정보 보호), Rarity(희귀 케이스 극복), Cost(라벨링 비용 극비용 절감) 문제를 해결하고 데이터 고갈(Data Wall)의 한계를 돌파하는 데이터 센트릭 AI의 핵심 동력.
- **판단 포인트**: 도메인 다양성(Diversity) 유지, 저품질 데이터 및 환각 필터링(Quality Control), 합성 데이터 루프 장기화로 인한 모델 붕괴(Model Collapse) 방지.

## Ⅰ. 개요 및 필요성
- **정의**: 프라이버시, 보안, 수집 비용 등의 이유로 획득하기 어려운 실제 데이터(Real Data)를 대체하기 위해, 알고리즘을 통해 인위적으로 생성해낸 고품질 학습 및 검증용 데이터셋.
- **배경**: Foundation Model의 스케일링 법칙(Scaling Law)에 따라 방대한 데이터가 요구되나, 고품질 인간 라벨링 데이터(Human-annotated Data)는 비용적·물리적 한계(Data Wall)에 도달함.
- **필요성**: 자율주행의 '코너 케이스(Corner Cases)', 의료/금융 도메인의 '민감 정보(PII) 우회', LLM의 '지시 튜닝(Instruction Tuning) 효율화'를 위해 필수적임.

## Ⅱ. 합성 데이터 생성 기법 및 아키텍처
| 생성 방식 | 메커니즘 및 활용 기술 | 주요 활용 도메인 |
|:---|:---|:---|
| **LLM 기반 생성 (Distillation)** | GPT-4 등 강력한 Teacher 모델 프롬프팅을 통한 QA/대화 생성 | 자연어 처리 (NLP), 챗봇 지시 튜닝 |
| **시뮬레이터 / 렌더링** | 3D 그래픽 엔진, 물리 엔진을 활용한 환경 및 센서 데이터 합성 | 자율주행, 로보틱스, 드론 시야 |
| **생성적 적대 신경망 (GAN)** | 원본 데이터의 통계적 분포를 모방한 노이즈 합성 (Tabular/이미지) | 딥페이크, 의료 영상 보강 |
| **비식별화 기반 합성** | 원본에서 PII를 제거하고 더미 데이터를 결합 (차등 프라이버시) | 금융 거래 데이터, 헬스케어 |

## Ⅲ. 주요 장점 (3대 혜택)
1. **프라이버시 및 규제 우회 (Privacy-Preserving)**: GDPR 등 엄격한 개인정보 규제 환경에서 원본 데이터를 노출하지 않고도 통계적 특성이 동일한 데이터로 모델 훈련 가능.
2. **엣지 케이스 (Edge/Corner Cases) 보강**: 현실에서 10년에 한 번 일어날까 말까 한 희귀 질병, 극단적 날씨, 특수 사고 상황 등을 억지로 무한대 생성하여 강건성(Robustness) 향상.
3. **무한한 확장 및 라벨링 자동화**: 생성 시점에 이미 정답(Label, Bounding Box 등)이 포함된 채로 생성되므로 인간 라벨러 비용이 '0'에 수렴함.

## Ⅳ. 한계점 및 운영 리스크 (Model Collapse)
- **리스크 1: 모델 붕괴 (Model Collapse)**:
  - 합성 데이터만으로 계속해서 후속 모델을 재학습시키면, 원래 데이터의 꼬리 부분(다양성)이 사라지고 오류가 증폭되어 결국 모델이 무의미한 결과물을 뱉는 붕괴 현상 발생.
  - **대응 방안**: 순수 합성 데이터만 쓰지 말고, 반드시 실제 데이터(Real Data)를 $10 \sim 30\%$ 비율로 섞어 학습(Replay)시켜야 다양성이 유지됨.
- **리스크 2: 환각 및 오류의 상속 (Garbage In, Garbage Out)**:
  - Teacher LLM이 만든 합성 데이터에 논리적 오류나 환각이 있으면, Student 모델은 그 오류를 정답으로 학습해버림.
  - **대응 방안**: 강력한 필터링. 생성된 데이터 중 보상 모델(RM) 점수가 낮은 하위 $20\%$ 절사, ROUGE/BLEU 점수로 중복 데이터(De-duplication) 제거 및 인간의 샘플링 검수.

## Ⅴ. 심화: 합성 데이터 파이프라인 (LLM 기준)
```text
[ 1. Seed Prompts ] (소규모의 고품질 인간 작성 프롬프트)
          |
[ 2. Teacher LLM (e.g. GPT-4) ] -> "다양한 변형된 지시어와 고품질 정답 생성"
          |
[ 3. Quality Filtering ] -> 중복 제거, PII 검출, 짧은 길이 폐기
          |
[ 4. Synthetic Dataset 구축 ] (수십만 건)
          |
[ 5. Student Model (SFT 튜닝) ]
```

## Ⅵ. 실무 적용 및 결론
- **판단 지표**: 모델 붕괴 방지를 위한 Real-to-Synthetic 비율, 생성 데이터의 다양성(Diversity Score), 최종 벤치마크 점수 향상분.
- **실무 설계**: 금융권에서 사기 탐지(FDS) 모델 고도화 시. 정상 거래 데이터는 방대하나 '신종 보이스피싱 패턴' 데이터가 극도로 부족함. GAN과 LLM을 결합하여 가상의 신종 사기 패턴 로그를 수만 건 생성(합성 데이터)하고, 실제 데이터와 7:3으로 섞어 분류기를 훈련하여 FDS 탐지율(Recall) 극대화.
- **결론**: 합성 데이터는 컴퓨팅 파워를 데이터로 치환하는 연금술이며, 양질의 데이터를 무한 증식시킬 수 있는 파이프라인(Data Engine)을 가진 기업만이 AI 경쟁의 최종 승자가 될 것임.

### 🔀 문제 유형별 목차 전환
- **Ⅱ·Ⅲ 강조 (개념/원리형)**: GAN, Diffusion, 시뮬레이터, Distillation 등 도메인별 합성 데이터 생성 기법과 프라이버시 보호(차등 프라이버시) 원리 중심 서술.
- **Ⅴ·Ⅵ 강조 (실무/설계형)**: Model Collapse의 수학적 꼬리 분포 소실 원리, 필터링 파이프라인 아키텍처 구축, 데이터 부족 문제 타개를 위한 엔터프라이즈 도입 전략 중심 작성.
