## 미리 알고가기

- 합성 데이터는 사람이 직접 수집한 원천 데이터 대신 모델이나 시뮬레이터로 생성한 데이터임
- 데이터 부족, 개인정보 제약, 희귀 사례 부족을 보완하는 데 자주 사용됨
- 생성 비용이 낮아도 품질 편향과 자기복제 문제를 함께 관리해야 함

## Ⅰ. 개요

- **정의/개념**: 합성 데이터는 생성 모델이나 규칙 기반 시뮬레이터를 이용해 인공적으로 만들어낸 학습용 또는 평가용 데이터로, 실제 데이터를 보완하거나 대체하는 데이터 구축 방법임
- **배경/필요성**: 고품질 라벨 데이터는 비싸고 희귀 상황 데이터는 부족하며 개인정보 제약도 크기 때문에, 대규모 학습과 튜닝을 위해 확장 가능한 데이터 공급원이 필요함

## Ⅱ. 특징

- 적은 비용으로 대량 데이터를 빠르게 생성해 학습 규모를 확대할 수 있음
- 희귀 케이스와 경계 사례를 의도적으로 늘려 모델 약점을 보완할 수 있음
- 생성 기준이 편향되면 실제 분포와 다른 데이터가 누적되어 품질 저하를 부를 수 있음
- 사람 검수와 혼합 사용 전략이 없으면 자기강화식 오류가 쌓일 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 실제 데이터 | 합성 데이터 | 증강 데이터 |
|:---|:---|:---|:---|
| 원천 | 실관측 | 생성 모델, 시뮬레이터 | 기존 데이터 변형 |
| 비용 | 높음 | 낮음 | 낮음 |
| 분포 신뢰성 | 높음 | 중간 | 중간 |
| 대표 목적 | 기준 학습 | 규모 확장, 희귀 사례 확보 | 일반화 보강 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Generation Source | LLM, diffusion, simulator가 합성 데이터의 생성 규칙과 품질 상한을 결정함 |
| Prompt, Scenario Design | 어떤 상황과 형식의 데이터를 만들지 정의해 도메인 적합성을 좌우함 |
| Filtering, Verification | 생성 오류와 중복과 유해 패턴을 제거해 실제 학습 품질을 보전함 |
| Mixing Policy | 실제 데이터와 합성 데이터의 비율을 조정해 과적합과 분포 왜곡을 통제함 |

+-------------------+      +-------------------+      +-------------------+

                                                   +-------------------+

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 생성 조건 설계  | --> | 합성 데이터 생성 | --> | 필터링/검증 수행 | --> | 실제 데이터와 혼합 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **생성 조건 설계**: 필요한 태스크와 예외 상황과 출력 형식을 정의함
2. **합성 데이터 생성**: 모델이나 시뮬레이터로 데이터를 대량 생성함
3. **필터링 및 검증 수행**: 잘못된 샘플과 중복 샘플을 제거함
4. **실제 데이터와 혼합**: 학습 목적에 맞게 혼합 비율을 조절함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 합성 데이터가 실제 운영 분포와 다르면 모델이 시험에서는 좋아 보여도 현장 성능이 떨어질 수 있음
   - 해결방안: 실제 검증셋을 기준으로 혼합 비율을 조정하고 distribution gap과 production accuracy로 적합성을 검증함
2. 문제: 생성 모델의 편향과 오류가 그대로 합성 데이터에 대량 전파될 수 있음
   - 해결방안: 휴먼 리뷰와 rule-based filtering을 병행하고 error density와 bias metric으로 품질을 검증함
3. 문제: 저비용 생성에 의존하면 결국 모델이 모델이 만든 데이터만 다시 배우는 self-reinforcement 문제가 생길 수 있음
   - 해결방안: 실제 데이터 anchor set을 유지하고 real-data retention ratio와 robustness score로 데이터 건강성을 검증함

## Ⅶ. 적용 사례

- instruction 데이터 생성이 챗봇 튜닝용 질의응답을 대량 생성하도록 합성 데이터를 활용하며 확인 지표는 format pass rate와 benchmark score임
- 희귀 장애 시나리오 학습이 운영 로그가 적은 이상 상황을 증강하도록 합성 데이터를 적용하며 확인 지표는 tail-case accuracy와 incident recall임
- 개인정보 대체 데이터셋이 민감 데이터 없이 테스트셋을 구성하도록 합성 데이터를 활용하며 확인 지표는 privacy compliance와 task fidelity임

## Ⅷ. 결론

합성 데이터는 데이터 병목을 풀어주는 강력한 수단이지만, 실제 분포와의 연결 고리를 유지하지 않으면 빠르게 품질 착시를 만드는 위험도 함께 커짐.
