# 📖 【암기용】 개념 완전 이해

> 목적: 에이전트 상태관리를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: 에이전트 작업의 현재 단계, 변수, 도구 결과, 승인상태를 관리하는 체계
- **왜 필요한가**: 에이전트는 여러 단계와 도구 호출을 거치므로 중단·재시작·오류 복구를 위한 상태가 필요함.
- **핵심 직관**: 상태관리는 에이전트 업무의 진행표와 체크포인트임.

## 깊이 이해
- **배경·문제의식**: 모델 컨텍스트에만 상태를 두면 장애, 세션 만료, 재시도 시 작업을 재현하기 어려움.
- **작동 원리**: 목표, 현재 단계, 입력 변수, 도구 응답, 승인 여부, 오류 정보를 외부 상태 저장소에 기록함.
- **비유**: 택배 시스템이 접수, 집하, 이동, 배송완료 상태를 기록해 중간 장애 후에도 추적하는 구조.
- **구체 예시**: 비용정산 Agent가 영수증 수집, OCR, 검증, 승인, 회계등록 단계와 실패 원인을 상태로 저장함.
- **흔한 오해·주의점**: 상태 저장은 편의가 아니라 감사와 복구의 근거이며, 변경형 작업은 멱등성 키가 필요함.

## 연결 개념
- Agent Orchestration — 상태 기반 워크플로우 실행
- Idempotency Key — 중복 실행 방지
- Saga Pattern — 실패 시 보상 처리

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Agent State Management는 에이전트 작업의 단계, 변수, 결과, 승인상태를 외부 저장소로 관리하는 체계임.
> 2. **가치**: 장시간·다단계 작업의 중단 복구, 재시도, 감사, 중복 실행 방지를 가능하게 함.
> 3. **판단 포인트**: 상태 모델, 저장소, 멱등성, 보상처리, 접근통제를 함께 설계해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 다단계 AI 업무의 상태 영속화 이해 | 상태 모델·전이표, 외부 저장소, 체크포인트 복구 | 컨텍스트 기반 상태와 혼동, 멱등성 설계 누락 |
| 장애 복구·감사 설계 능력 | 멱등성 키, 보상 트랜잭션(Saga), Trace ID 감사로그 | 재시도만 언급하고 보상처리·중복 방지 미설계 |

> 요약: 상태 전이표·멱등성·보상처리·감사로그를 함께 설계해야 실무 설계 역량을 증명함.

---

## Ⅰ. 개요 및 필요성

- 정의: 에이전트 작업의 단계·변수·결과를 외부 저장소로 관리하는 체계
- 배경: 모델 컨텍스트에만 상태를 두면 장애·세션 만료 시 작업 재현이 불가함
- 필요성: 다단계 업무의 중단 복구, 재시도 멱등성, 감사 추적을 위한 외부 상태 저장이 필수

---

## Ⅱ. 구조 및 구성요소

```text
Workflow Step -> State Store -> Recovery Manager
                    |                 |
                    +-> 상태/버전     +-> 재시도/보상
                    |
                    +-> Audit Trail -> 변경 이력
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| State Model | 단계·변수 구조 정의 | 상태 전이표 필요 |
| State Store | 상태 영속 저장 | 버전·락·TTL |
| Recovery Manager | 실패 복구 | retry, compensation |
| Audit Trail | 상태 변경 이력 | 변경자, Trace ID |

> 요약: 상태관리는 상태모델, 저장소, 복구관리자, 감사이력으로 구성됨.

---

## Ⅲ. 동작원리 및 흐름도

```text
작업 시작 -> 상태 생성 -> 단계 실행 -> 상태 갱신
        -> 실패 감지 -> 재시도/보상 -> 완료 기록
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 상태 생성 | 작업ID, 사용자ID, 버전 |
| 2 | 단계별 갱신 | 입력, 출력, 응답코드 |
| 3 | 실패 처리 | 재시도 횟수, 오류 유형 |
| 4 | 완료·감사 | 완료시각, 승인자, Trace ID |

> 요약: 상태관리는 단계 실행마다 상태를 갱신해 재시작과 감사를 가능하게 함.

---

## Ⅳ. 특징

| 구분 | 컨텍스트 기반 상태 | 외부 상태관리 | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 복구 | 세션 의존 | 체크포인트 복구 | 복구 성공률 |
| 중복 방지 | 어려움 | 멱등성 키 사용 | 중복 실행 건수 |
| 감사 | 대화 로그 중심 | 상태 전이 이력 | Trace ID, 보존기간 |

> 요약: 외부 상태관리는 장시간 AI 업무의 복구성과 감사성을 제공함.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 컨텍스트 기반 상태 | 외부 상태관리 | 선택 기준 |
|:---|:---|:---|:---|
| 복구 | 세션 소멸 시 작업 유실 | 체크포인트 복구(RTO 수 초) | 5분 이상 작업은 외부 상태 필수 |
| 중복 방지 | 재시도 시 중복 실행 | 멱등성 키+optimistic lock | 변경형 API 호출 포함 시 멱등성 필수 |
| 감사 | 대화 로그만 존재 | 상태 전이·승인·Trace ID 기록 | 규제·내부통제 대상 업무는 감사로그 필수 |

> 요약: 장시간·변경형 작업이면 외부 상태관리를 적용하고 멱등성·감사 요건을 함께 설계함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 상태 불일치 | 동시 갱신, 락 미적용 | optimistic lock + 버전 관리, 충돌 시 재시도 | 충돌 발생 건수, 재시도 성공률 |
| 중복 실행 | 멱등성 키 미적용 | idempotency key + 결과 캐시(TTL 24시간) | 중복 실행 건수, 이중 처리 금액 |
| 보상 실패 | Saga 보상 트랜잭션 미구현 | 단계별 보상 액션 정의, 실패 시 DLQ 적재 | 보상 실패율, DLQ 적체 건수 |

> 요약: 락·멱등성 키·Saga 보상을 적용해 상태 불일치와 중복 실행을 통제함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 복구 성공률 | 장애 후 복구 성공률 99% 이상 | 장애 주입 테스트, 체크포인트 복원 검증 |
| 중복 실행 | 중복 실행 건수 월 0건 | 멱등성 키 중복 탐지 로그 |
| 감사 완전성 | 상태 전이 100% 감사로그 기록 | Trace ID 커버리지, 감사 누락 스캔 |

> 요약: 복구 성공률·중복 실행·감사 커버리지를 정기 점검해 상태관리 신뢰성을 확보함.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 상태 전이표를 정의하고 허용되지 않은 전이와 권한 없는 변경을 차단
2. 변경형 작업에는 idempotency key, optimistic lock, 보상 트랜잭션을 적용
3. 상태 변경마다 사용자ID, AgentID, Tool명, 입력 해시, 응답코드를 감사로그로 남김

**결론 (2줄):**
- 기술사 판단: 조회형 단기 작업은 경량 상태, 변경형 장시간 작업은 영속 상태관리를 적용함.
- 향후 방향: 상태관리는 Agent Orchestration과 결합해 AI 업무의 신뢰성·감사성을 결정하는 기반이 됨.
