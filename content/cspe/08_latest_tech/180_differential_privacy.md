# 📖 【암기용】 개념 완전 이해

> 목적: Differential Privacy를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: 특정 개인 데이터가 포함되었는지 여부가 결과에서 드러나지 않도록 노이즈를 추가하는 프라이버시 보호 기법
- **왜 필요한가**: 통계·AI 모델 결과만 공개해도 희귀 패턴이나 반복 질의로 개인 참여 여부가 추론될 수 있음.
- **핵심 직관**: 한 사람의 데이터가 들어가거나 빠져도 출력이 거의 달라지지 않게 만드는 원리임.

## 깊이 이해
- **배경·문제의식**: 익명화 데이터도 외부 정보와 결합되면 재식별될 수 있어 결과 공개 단계의 수학적 보호 기준이 필요함.
- **작동 원리**: 질의 민감도에 따라 Laplace/Gaussian noise를 더하고 privacy budget ε, δ로 보호 강도를 관리함.
- **비유**: 설문 결과를 발표할 때 소수의 응답이 특정 개인을 가리키지 않도록 작은 무작위 흔들림을 더하는 방식임.
- **구체 예시**: 사용자 통계 공개 시 ε=1.0으로 Laplace noise를 적용해 단일 사용자의 포함 여부가 결과에서 구분되지 않도록 함.
- **흔한 오해·주의점**: ε가 작을수록 보호는 커지지만 정확도 손실이 증가한다. 반복 질의는 privacy budget을 소모함.

## 연결 개념
- Privacy-Preserving AI — DP를 포함하는 보호형 AI 체계
- Federated Learning — 클라이언트 업데이트에 DP noise 적용 가능
- Membership Inference — DP가 줄이려는 대표 추론 공격

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Differential Privacy는 개인 1명의 포함 여부가 출력에 미치는 영향을 ε, δ로 제한하는 기법임.
> 2. **가치**: 통계 공개, AI 학습, 로그 분석에서 재식별·회원 추론 위험을 정량 통제함.
> 3. **판단 포인트**: privacy budget과 정확도 손실의 trade-off를 업무 허용 오차와 함께 승인해야 함.

## Ⅰ. 개요 및 필요성

Differential Privacy는 수학적 개인정보 보호 기법이다. 익명화만으로는 외부 데이터 결합과 반복 질의에 의한 재식별을 막기 어렵다. ε, δ 기반으로 개인 기여도 노출을 제한해야 한다.

## Ⅱ. 구조 및 구성요소

```text
Raw Data → Query/Training → Sensitivity
  → Noise Mechanism → DP Output
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Privacy Budget | 보호 강도 관리 | ε, δ 값 |
| Sensitivity | 개인 1명 영향도 측정 | 질의별 계산 |
| Noise Mechanism | Laplace/Gaussian 노이즈 추가 | central/local DP |
| Accountant | 반복 질의 예산 누적 | budget exhaustion |

> 요약: DP는 민감도와 예산을 기준으로 노이즈를 추가하고 반복 사용량을 회계 처리함.

## Ⅲ. 동작원리 및 흐름도

```text
질의 설계 → 민감도 산정 → ε/δ 결정
  → 노이즈 추가 → 정확도·위험 평가
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 공개 질의·학습 목표 정의 | PII 필드 목록화 |
| 2 | 민감도와 privacy budget 산정 | ε=0.1~10 범위 검토 |
| 3 | Laplace/Gaussian noise 적용 | DP accountant 기록 |
| 4 | 결과 정확도와 공격 저항 평가 | 오차율 허용범위 이내 |

> 요약: Differential Privacy는 질의 민감도에 맞춘 노이즈와 예산 관리를 통해 개인 기여도 노출을 제한함.

## Ⅳ. 특징

| 구분 | 익명화·마스킹 | Differential Privacy | 판단 포인트 |
|:---|:---|:---|:---|
| 보호 기준 | 식별자 제거 | ε, δ 수학적 보장 | 정량 기준 |
| 공격 대응 | 직접 식별 완화 | 재식별·회원 추론 완화 | 외부 결합 고려 |
| 정확도 | 원자료 통계 유지 | 노이즈로 오차 발생 | 허용 오차 산정 |
| 한계 | 재식별 가능 | 예산 소진·설명 난도 | 거버넌스 필요 |

> 요약: Differential Privacy는 익명화보다 정량 보호 기준을 제공하지만 정확도 손실과 예산 관리를 요구함.

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 통계 공개: 인구·이동 통계 공개 시 ε=1~3 기준과 셀 크기 n<10 비공개 규칙을 함께 적용
2. AI 학습: DP-SGD로 gradient clipping C=1.0, noise multiplier 1.1을 적용하고 모델 AUC 하락 3%p 이하 기준 설정
3. 운영 관리: privacy accountant로 질의별 ε 소모량을 기록하고 예산 80% 사용 시 추가 승인 절차 적용

**결론 (2줄):**
- 기술사 판단: 반복 공개·AI 학습 환경은 익명화만으로 부족하므로 DP 예산과 정확도 기준을 함께 승인
- 향후 방향: Differential Privacy는 연합학습·데이터 결합·생성형 AI 로그 분석의 기본 보호 지표로 확장됨
