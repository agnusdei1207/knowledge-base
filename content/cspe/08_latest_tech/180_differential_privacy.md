## 미리 알고가기

- 차등 개인정보보호는 특정 개인의 포함 여부가 결과에 거의 드러나지 않도록 노이즈를 주입하는 수학적 프레임워크임
- 핵심 손잡이는 프라이버시 예산 $\epsilon$이며 작을수록 보호는 강해지고 유틸리티는 낮아짐
- 데이터 공개뿐 아니라 DP-SGD처럼 모델 학습 과정에도 직접 적용할 수 있음

## Ⅰ. 개요

- **정의/개념**: 차등 개인정보보호는 데이터셋에서 한 개인의 데이터가 추가되거나 제거되어도 분석 결과나 학습 결과의 확률 분포가 크게 달라지지 않도록 통제하는 노이즈 기반 프라이버시 보호 기법임
- **배경/필요성**: 단순 익명화나 가명화만으로는 외부 정보 결합과 차분 공격을 막기 어려우므로, 특정 개인의 포함 여부 자체를 수학적으로 숨기는 강한 프라이버시 보장이 필요해짐

## Ⅱ. 특징

- 프라이버시 보호 수준을 $\epsilon$과 $\delta$ 같은 매개변수로 정량 관리할 수 있음
- 통계 질의 결과뿐 아니라 gradient clipping과 noise injection을 통해 모델 학습에도 적용 가능함
- 프라이버시와 유틸리티가 명확한 상충 관계를 가져 설계자의 예산 관리가 중요함
- 여러 질의와 반복 학습을 거치면 예산이 누적 소모되므로 accountant 관리가 필수임

## Ⅲ. 종류 및 비교

| 판단 기준 | Central DP | Local DP | DP-SGD |
|:---|:---|:---|:---|
| 노이즈 주입 위치 | 서버 결과 공개 직전 | 사용자 단말 입력 단계 | 학습 중 gradient 단계 |
| 장점 | 유틸리티 손실이 상대적으로 작음 | 서버를 신뢰하지 않아도 됨 | 모델 훈련 직접 보호 |
| 한계 | 중앙 관리자를 신뢰해야 함 | 노이즈가 커질 수 있음 | 성능 하락과 학습 비용 증가 |
| 대표 활용 | 통계 공개, 분석 플랫폼 | 텔레메트리 수집 | 민감 데이터 모델 학습 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Adjacency Definition | 한 개인 차이만 있는 인접 데이터셋을 정의해 보호 대상을 수학적으로 명확히 함 |
| Sensitivity, Clipping | 개인 한 명이 결과에 미치는 최대 영향을 제한해 필요한 노이즈 규모를 제어함 |
| Noise Mechanism | Laplace나 Gaussian 노이즈를 적용해 결과나 gradient를 불확실하게 만듦 |
| Privacy Budget, Accountant | 질의와 학습 반복에 따라 누적되는 $\epsilon$ 사용량을 추적해 과도한 노출을 막음 |
| Utility Evaluation | 노이즈 주입 이후 정확도와 지연과 업무 적합성을 측정해 실용성을 판단함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 민감도 제한 정의 | --> | 노이즈 주입 수행 | --> | 예산 누적 추적  | --> | 결과 공개/학습 종료 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **민감도 제한 정의**: 질의나 gradient의 최대 영향 범위를 정함
2. **노이즈 주입 수행**: 적절한 분포의 노이즈를 결과나 학습 과정에 추가함
3. **예산 누적 추적**: 반복 실행에 따른 프라이버시 예산을 계산함
4. **결과 공개 또는 학습 종료**: 허용 범위 안에서만 결과를 공개하거나 학습을 계속함

## Ⅵ. 문제점 및 해결 방안

1. 문제: $\epsilon$을 지나치게 크게 잡으면 노이즈가 약해져 보호가 형식적 수준에 머물 수 있음
   - 해결방안: policy-driven epsilon range를 정의하고 privacy attack success rate와 epsilon audit compliance로 검증함
2. 문제: 노이즈를 과하게 넣으면 모델 정확도와 통계 유용성이 크게 떨어져 현업 적용성이 낮아질 수 있음
   - 해결방안: clipping norm과 noise multiplier를 함께 튜닝하고 accuracy retention과 utility score로 검증함
3. 문제: 여러 질의와 반복 학습에서 예산 누적을 관리하지 않으면 개별 실행은 안전해 보여도 총합 노출이 커질 수 있음
   - 해결방안: privacy accountant와 budget cap을 적용하고 cumulative epsilon tracking과 query denial rate로 검증함

## Ⅶ. 적용 사례

- 모바일 텔레메트리 수집이 로컬 DP를 적용해 개별 사용 패턴을 숨기며 확인 지표는 privacy budget consumption과 trend estimation error임
- 의료 데이터 학습이 DP-SGD로 민감 환자 정보 노출을 줄이며 확인 지표는 membership inference attack success rate와 model AUC임
- 공개 통계 포털이 중앙 DP를 적용해 집단 통계를 제공하며 확인 지표는 release utility score와 reidentification risk rate임

## Ⅷ. 결론

차등 개인정보보호는 프라이버시를 정성적 선언이 아니라 수학적 예산 관리 문제로 바꾸는 강력한 기준이므로, $\epsilon$ 설정과 유틸리티 검증을 함께 운영해야 실제 보호 효과가 유지됨.
