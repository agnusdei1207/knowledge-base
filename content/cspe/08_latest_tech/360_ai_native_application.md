## 미리 알고가기

- AI 네이티브 앱은 챗봇을 붙인 애플리케이션이 아니라 추론과 검색과 도구 실행이 핵심 업무 흐름에 들어간 구조임
- 정확도보다 업무 완료율과 권한 통제와 실패 복구까지 포함해 봐야 실제 도입 판단이 가능함
- RAG와 tool calling과 evaluation과 observability가 함께 있어야 운영 품질을 유지할 수 있음

## Ⅰ. 개요

- **정의/개념**: AI-Native Application은 사용자 목표를 자연어로 받아 모델 추론과 문맥 검색과 도구 호출과 승인 절차를 결합해 업무 결과까지 이어지도록 설계한 애플리케이션 구조임
- **배경/필요성**: 단순 챗봇형 AI는 답변 생성에는 유용하지만 실제 업무 시스템 권한과 데이터 근거와 실행 단계를 연결하지 못해 처리 완료율이 낮아 핵심 워크플로우 자체를 AI 중심으로 다시 설계할 필요가 커짐

## Ⅱ. 특징

- 입력 이해와 계획과 실행과 검증이 하나의 제품 흐름으로 연결돼 단순 질의응답보다 자동화 수준이 높음
- RAG와 업무 데이터 연결이 결과의 근거성과 최신성을 좌우함
- tool calling과 승인 게이트를 결합해 답변에서 실제 업무 실행으로 넘어갈 수 있음
- 모델 품질 변동과 비용과 권한 오남용이 동시에 발생할 수 있어 평가와 관측성과 정책 통제가 필수임

## Ⅲ. 종류 및 비교

| 판단 기준 | 기능 추가형 AI 앱 | AI 네이티브 앱 |
|:---|:---|:---|
| AI 역할 | 보조 답변이나 요약 | 핵심 업무 흐름 실행 |
| 데이터 연결 | 제한적 문맥 주입 | RAG와 업무 시스템 연계 |
| 도구 실행 | 수동 전환이 많음 | API와 워크플로우 직접 호출 |
| 대표 한계 | 완료율이 낮음 | 운영 통제와 비용 관리가 복잡함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Intent and Policy Layer | 사용자 목표와 권한과 허용 범위를 해석하는 제어 계층으로 승인 조건과 데이터 경계를 정의함 |
| Retrieval and Context Layer | 지식 문서와 업무 데이터를 검색해 모델에 근거를 공급하는 계층으로 검색 품질이 정답률에 직접 연결됨 |
| Reasoning and Orchestration | 모델이 계획을 세우고 어떤 도구를 어떤 순서로 호출할지 조정하는 실행 계층임 |
| Tool and Workflow Layer | CRM과 ERP와 티켓 시스템 같은 실제 업무 도구를 호출해 결과를 만드는 연계 계층으로 idempotency와 권한 통제가 중요함 |
| Evaluation and Observability | 결과 품질과 비용과 지연과 정책 위반을 측정하는 운영 계층으로 지속 개선의 근거가 됨 |

```text
+----------------+    +----------------+    +----------------+    +----------------+
| Intent/Policy  | -> | Retrieval      | -> | Reasoning      | -> | Tool/Workflow  |
+----------------+    +----------------+    +----------------+    +----------------+
         |                                                        |
         v                                                        v
+----------------+                                       +----------------+
| Approval Gate  |                                       | Eval/Observe   |
+----------------+                                       +----------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 목표 입력      | -> | 권한/정책 확인 | -> | 문맥 검색      | -> | 도구 실행      | -> | 검증/승인/기록 |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **목표 입력**: 사용자가 자연어로 원하는 업무 결과를 제시함
2. **권한과 정책 확인**: 시스템이 허용된 데이터와 도구 범위를 판정함
3. **문맥 검색**: 관련 문서와 업무 데이터를 모아 근거를 구성함
4. **도구 실행**: 모델이 계획에 따라 승인된 API와 워크플로우를 호출함
5. **검증과 승인과 기록**: 결과를 평가하고 필요 시 인간 승인을 거쳐 로그와 피드백을 남김

## Ⅵ. 실무 적용 및 유의점

1. 고객지원과 운영 자동화는 AI 네이티브 앱으로 업무 완료율을 높이기 좋지만 근거 없는 답변이나 과도한 도구 호출이 실제 장애를 만들 수 있으므로 RAG 인용과 승인 게이트와 fallback 경로를 함께 두고 task success rate와 근거 포함률과 미인가 호출 건수로 확인함
2. 회계와 영업 지원처럼 여러 시스템을 넘나드는 업무는 자연어 입력을 실행으로 연결하기 좋지만 비용과 지연이 누적되면 사용성이 떨어지므로 컨텍스트 길이 제한과 캐시와 평가 데이터셋 운영을 적용하고 p95 응답시간과 건당 비용과 재시도율로 확인함

## Ⅶ. 결론

- AI 네이티브 애플리케이션은 답변 생성보다 업무 결과 생성이 중요한 영역에서 효과가 크며 검색 품질과 도구 권한과 평가 체계를 함께 설계해야 안정적으로 운영할 수 있음
