# 📖 【암기용】 개념 완전 이해

> 목적: AI 네이티브 애플리케이션을 AI 기능을 부가한 앱이 아니라 모델 추론, 도구 호출, 피드백 루프가 제품 구조의 중심인 애플리케이션으로 이해하게 만든다.

## 한눈에
- **개요**: AI 모델과 에이전트 흐름을 핵심 실행 경로에 둔 애플리케이션
- **왜 필요한가**: 기존 앱은 사용자가 메뉴와 폼을 직접 조작한다. AI 네이티브 앱은 사용자의 목표를 해석하고, 데이터를 검색하고, 도구를 호출해 업무 단계를 줄인다.
- **핵심 직관**: AI 버튼을 붙인 앱이 아니라, 앱의 기본 동작이 "입력 이해 -> 계획 -> 실행 -> 검증"으로 설계된 제품이다.

## 깊이 이해
- **배경·문제의식**: 생성형 AI 도입 초기에는 챗봇 부가 기능이 많았지만, 실제 업무 가치는 기존 워크플로우와 권한, 데이터, 실행 도구를 연결할 때 나온다.
- **작동 원리**: 사용자 의도를 모델이 해석하고, RAG가 근거 데이터를 제공하며, tool/function calling이 업무 시스템을 호출하고, 평가·관측성이 결과 품질을 관리한다.
- **비유**: 계산기에 음성 입력만 붙인 것이 아니라, 회계 담당자가 영수증 분류, 규정 확인, 전표 초안 생성, 승인 요청까지 수행하도록 업무 흐름을 다시 만든 것이다.
- **구체 예시**: 고객지원 앱은 문의를 분류하고, 고객 이력을 검색하고, 환불 정책을 확인하고, 상담원 승인 전까지 답변 초안과 근거를 함께 제시한다.
- **흔한 오해·주의점**: AI 네이티브 앱은 자동화율을 높이는 것만이 목적이 아니다. 권한 확인, 근거 제시, 실패 시 fallback, 평가 데이터셋이 없으면 운영 품질을 관리하기 어렵다.

## 연결 개념
- RAG — 기업 지식 기반 응답 근거 제공
- AI Agent — 계획과 도구 호출을 수행하는 실행 패턴
- LLMOps — 모델 품질, 비용, 지연, 안전성을 운영하는 체계

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.
> 핵심: AI 네이티브 앱은 모델, RAG, 도구 호출, 권한, 평가, 관측성을 제품 실행 경로에 내장한 구조다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: AI 네이티브 애플리케이션은 AI 추론과 도구 실행이 핵심 사용자 흐름을 구성하는 애플리케이션이다.
> 2. **가치**: 자연어 목표 입력, 업무 데이터 검색, 실행 자동화, 인간 승인 절차를 결합해 반복 업무 단계를 줄인다.
> 3. **판단 포인트**: hallucination, 권한, tool safety, 평가 데이터셋, 비용·지연, human-in-the-loop를 점검한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| AI 앱 구조 이해 확인 | model, RAG, tool calling, workflow | 챗봇 추가로만 설명 |
| 운영 품질 판단 확인 | evaluation, observability, fallback | 답변 품질을 감각적으로 표현 |
| 보안·권한 인식 확인 | RBAC, data boundary, approval | 모델이 알아서 처리한다고 단정 |

> 요약: 이 문제는 AI를 기능이 아니라 애플리케이션 실행 구조와 운영 통제 관점에서 설명해야 한다.

## Ⅰ. 개요 및 필요성

- 개요: AI 중심 실행 앱
- 배경: 단순 챗봇은 업무 시스템 권한, 데이터 근거, 승인 절차와 분리되어 실제 처리 완료율이 제한됨.
- 필요성: 모델 추론, 검색, 도구 호출, 검증, 관측성을 제품 흐름에 넣어 업무 완료 기준으로 AI를 운영해야 함.

---

## Ⅱ. 구조 및 구성요소

```text
User Goal -> Intent / Policy -> RAG Context -> LLM Reasoning
          -> Tool Calling / Workflow -> Human Approval -> Result
          +-> Evaluation / Observability / Guardrail
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| intent/policy | 사용자 목표와 허용 범위 해석 | RBAC, ABAC |
| RAG context | 근거 문서와 업무 데이터 제공 | retrieval quality |
| tool calling | API, DB, workflow 실행 | idempotency |
| evaluation/guardrail | 품질·안전성 검증 | golden dataset |

> 요약: AI 네이티브 앱은 모델 호출뿐 아니라 권한, 근거, 실행 도구, 평가 체계가 함께 있어야 한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
목표 입력 -> 의도·권한 확인 -> 근거 검색
-> 계획/추론 -> 도구 호출 -> 검증/승인 -> 결과 반환·로그
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 사용자 목표와 권한, 데이터 접근 범위를 확인함 | authorization decision |
| 2 | RAG로 관련 문서와 업무 데이터를 검색함 | retrieval precision |
| 3 | 모델이 계획을 만들고 허용된 도구만 호출함 | tool policy |
| 4 | 결과를 평가·승인·로그에 반영하고 fallback을 수행함 | eval score |

> 요약: AI 네이티브 앱은 자연어 입력에서 업무 결과까지 이어지며 각 단계마다 검증 지점을 둔다.

---

## Ⅳ. 특징

| 구분 | AI 기능 추가 앱 | AI 네이티브 앱 | 판단 기준 |
|:---|:---|:---|:---|
| AI 위치 | 보조 버튼·챗봇 | 핵심 workflow | 업무 완료율 |
| 데이터 | 프롬프트 입력 | RAG·업무 DB 연결 | 근거 추적 |
| 실행 | 답변 생성 | tool/API 호출 | 권한·감사 |
| 운영 | 모델 호출 로그 | eval, tracing, cost 관리 | LLMOps |

> 요약: AI 네이티브 앱은 답변 생성이 아니라 권한 있는 업무 실행과 평가 루프가 제품 구조에 포함된다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| UI | 메뉴·폼 | 목표 기반 대화/명령 | 반복 업무 단계 |
| 자동화 | RPA | LLM+tool workflow | 비정형 입력 |
| 품질관리 | QA 테스트 | offline/online evaluation | 모델 변동성 |

> 요약: AI 네이티브 앱은 비정형 입력과 업무 도구 실행이 함께 필요한 영역에서 기존 UI와 RPA를 보완한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| hallucination | 근거 부족·모델 추론 오류 | RAG citation, answer abstain | groundedness score |
| 권한 초과 | tool 호출 정책 누락 | scoped token, approval gate | unauthorized call |
| 비용 폭증 | 긴 context·반복 호출 | caching, budget guardrail | cost per task |

> 요약: AI 네이티브 앱 리스크는 답변 오류, 권한 초과 실행, 토큰 비용에서 발생한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 품질 | 정확도·근거성·재현율 관리 | golden dataset |
| 운영 | p95 latency·cost per task 추적 | tracing/APM |
| 안전 | 승인·거부·차단 로그 관리 | policy audit |

> 요약: AI 네이티브 앱은 모델 정확도만이 아니라 업무 완료율, 지연, 비용, 정책 위반을 함께 측정한다.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 고객지원, 영업, 개발, 회계 중 반복적이고 근거 문서가 있는 업무를 선정하고 task success 기준을 정의함.
2. RAG, tool calling, RBAC, approval gate, fallback을 포함한 workflow를 설계하고 모든 도구 호출을 감사로그에 남김.
3. golden dataset, A/B test, tracing, cost budget, prompt/model versioning을 LLMOps 체계로 운영함.

**결론 (2줄):**
- 기술사 판단: 자연어 목표를 업무 시스템 실행으로 연결해야 하면 AI 네이티브 앱을 설계하고, 단순 Q&A는 RAG 챗봇으로 제한함.
- 향후 방향: AI 네이티브 앱은 agentic workflow, MCP, multimodal UI, confidential AI와 결합해 업무 소프트웨어의 기본 구조로 확장됨.
