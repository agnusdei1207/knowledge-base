# 📖 【암기용】 개념 완전 이해

> 목적: Human-in-the-Loop 에이전트를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: AI 에이전트 실행 과정에 사람이 검토·승인·수정 단계로 참여하는 구조
- **왜 필요한가**: 결제, 권한변경, 보안정책 수정처럼 잘못 실행하면 피해가 큰 업무는 자동 결정을 제한해야 함.
- **핵심 직관**: AI가 초안을 만들고 사람은 위험한 버튼을 누르기 전에 최종 확인하는 방식임.

## 깊이 이해
- **배경·문제의식**: 에이전트가 자율 실행하면 환각, 입력 오염, 권한 오남용이 실제 업무 변경으로 이어질 수 있음.
- **작동 원리**: 위험도 평가로 자동실행, 사람승인, 거부를 분기하고 승인자의 결정과 사유를 감사로그에 남김.
- **비유**: 신용카드 고액 결제나 계좌이체에서 추가 인증과 승인 절차를 요구하는 구조.
- **구체 예시**: 보안 Agent가 차단 정책을 제안하고 보안담당자가 영향 범위를 확인한 후 실행 승인함.
- **흔한 오해·주의점**: 사람을 넣는다고 통제가 완성되는 것이 아니며 승인 화면에 근거·영향·롤백 방안이 표시되어야 함.

## 연결 개념
- Risk-Based Approval — 위험도 기반 승인
- Agent Authorization Control — 실행 전 권한정책
- Audit Log — 승인 근거 보존

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Human-in-the-Loop Agent는 AI 실행 흐름에 사람의 검토·승인·수정 단계를 삽입한 통제 구조임.
> 2. **가치**: 고위험 자동화에서 오작동, 환각, 과다 권한 실행을 승인 절차로 차단함.
> 3. **판단 포인트**: 위험등급, 승인 기준, 근거 표시, SLA, 감사로그를 함께 설계해야 함.

---

## Ⅰ. 개요 및 필요성

- 개요: AI 실행의 사람 승인 구조
- 배경: 에이전트가 결제·삭제·권한변경 같은 실제 시스템 변경 업무를 수행하면 단독 자동화가 업무 피해로 이어질 수 있음.
- 필요성: risk level, approval gate, escalation rule로 자동 실행·검토·차단 기준을 분리해야 함.

---

## Ⅱ. 구조 및 구성요소

```text
Agent Proposal -> Risk Scoring -> Human Review -> Execute/Reject


      제안          위험평가        승인/수정        실행/차단
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Proposal | AI 실행 제안 | 근거·영향·대안 포함 |
| Risk Scoring | 승인 필요 여부 판단 | 금액·권한·데이터 민감도 |
| Human Review | 사람 검토·승인 | 승인자 권한 확인 |
| Execution Gate | 실행·거부 집행 | 감사로그·롤백 연계 |

> 요약: Human-in-the-Loop은 AI 제안을 위험도 평가 후 사람 승인 게이트로 통제함.

---

## Ⅲ. 동작원리 및 흐름도

```text
요청 분석 -> 위험등급 산정 -> 자동/승인 분기
        -> 사람 검토 -> 실행/거부 -> 결과 기록
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 실행 제안 생성 | 근거, 영향, 롤백안 |
| 2 | 위험등급 평가 | 변경범위, 민감도, 금액 |
| 3 | 승인 처리 | 승인자 권한, SLA |
| 4 | 실행·감사 | Trace ID, 승인사유, 결과 |

> 요약: 사람 승인 구조는 위험등급에 따라 자동화와 수동 검토를 분기함.

---

## Ⅳ. 특징

| 구분 | 완전 자동 Agent | Human-in-the-Loop | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 실행 속도 | 즉시 실행 | 승인 SLA 의존 | 승인 대기시간 |
| 위험 통제 | 정책 자동판단 | 사람 검토 추가 | 거부율, 오류 차단률 |
| 책임 | 시스템 중심 | 승인자 책임 포함 | 승인 로그 보존 |

> 요약: Human-in-the-Loop은 실행 지연을 감수하고 고위험 업무의 책임성과 통제를 확보함.

---

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 조회형은 자동, 변경형은 조건부 승인, 관리자권한 작업은 2인 승인으로 분류
2. 승인 화면에 근거, 영향 시스템, 변경 전후 값, 롤백 버튼, 만료시간을 표시
3. 승인자, 승인시각, 수정 내용, 실행 결과를 Trace ID로 감사로그에 저장

**결론 (2줄):**
- 기술사 판단: 고위험 업무는 자동화율보다 승인 근거와 롤백 가능성이 우선임.
- 향후 방향: Human-in-the-Loop은 AI 거버넌스와 결합해 위험 기반 자동화 수준을 결정하는 표준 패턴이 됨.

### 🔀 문제 유형별 목차 전환 (이 키워드 출제 시)

| 유형 | 문제 신호어 | Ⅲ 강조 | Ⅳ 강조 |
|:---|:---|:---|:---|
| 포괄형 | 설명하시오, 기술하시오 | 위험평가-승인-실행 흐름 | 완전 자동 대비 차이 |
| 요구사항 명시형 | 설계하시오, 통제방안을 제시하시오 | 승인 SLA·2인 승인 절차 | 지연·책임·감사 기준 |

> 요약: 포괄형은 승인 구조, 설계형은 위험등급별 자동화 수준을 중심으로 작성함.
