## 미리 알고가기

- multi-hop 질의는 한 번의 검색으로는 답을 만들 수 없고 여러 근거를 순차 결합해야 하는 질문임
- Multi-hop RAG는 검색 결과를 다음 검색의 단서로 쓰며 근거를 이어 붙이는 구조임
- graph RAG나 agentic RAG와 연결성이 높음

## Ⅰ. 개요

- **정의/개념**: Multi-hop RAG는 하나의 질의에 답하기 위해 여러 단계의 검색을 순차 수행하고, 각 단계에서 얻은 정보를 다음 단계의 단서로 활용해 최종 답을 구성하는 다단계 검색-생성 아키텍처임
- **배경/필요성**: 복합 질문은 단일 문서 조각에 정답이 없고 서로 다른 문서의 사실을 연결해야 하므로, 일회성 검색만으로는 정확한 답을 만들기 어려움

## Ⅱ. 특징

- 문서 간 분산된 정보를 연결해 복합 추론과 관계 추적에 강함
- 질의 재작성과 중간 상태 관리가 중요해 단순 RAG보다 추론 구조가 복잡함
- 한 단계 오류가 다음 단계에 전파되어 연쇄 실패가 일어날 수 있음
- graph 기반 탐색이나 에이전트 계획과 결합하면 성능이 더 좋아질 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | Single-hop RAG | Multi-hop RAG | Graph RAG |
|:---|:---|:---|:---|
| 검색 횟수 | 1회 중심 | 다회 | 다회, 관계 탐색 |
| 강점 질의 | 단일 사실 | 연결형 사실 추론 | 관계망, 전역 구조 |
| 상태 관리 | 단순 | 중요 | 매우 중요 |
| 운영 난도 | 낮음 | 높음 | 높음 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Hop Planner | 질의를 여러 검색 단계로 분해해 어떤 정보를 먼저 찾을지 결정함 |
| Intermediate Memory | 각 단계에서 얻은 근거를 저장해 다음 검색 질의에 활용함 |
| Query Rewriter | 중간 결과를 바탕으로 후속 검색 질의를 더 구체적으로 재작성함 |
| Evidence Aggregator | 다단계 근거를 모아 최종 답변 근거 체계를 구성함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 1차 검색 수행   | --> | 중간 근거 저장   | --> | 후속 질의 재검색 | --> | 근거 통합 생성   |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **1차 검색 수행**: 핵심 개체나 첫 번째 단서를 찾음
2. **중간 근거 저장**: 찾은 정보를 메모리에 저장하고 다음 단서를 식별함
3. **후속 질의 재검색**: 중간 근거를 바탕으로 두 번째, 세 번째 검색을 수행함
4. **근거 통합 생성**: 여러 홉에서 얻은 사실을 결합해 최종 답변을 생성함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 초기 검색이 잘못되면 후속 검색도 연쇄적으로 틀어져 최종 답변이 크게 왜곡될 수 있음
   - 해결방안: hop별 검증과 branching 후보 관리를 적용하고 hop success rate와 final faithfulness로 연쇄 오류를 검증함
2. 문제: 검색 단계가 늘수록 latency와 비용이 빠르게 증가해 실시간 서비스에 부담이 될 수 있음
   - 해결방안: 최대 hop 수를 제한하고 query budget을 운영하며 average hops와 p95 latency로 비용 효율을 검증함
3. 문제: 여러 근거를 통합하는 과정에서 문맥 충돌이나 중복이 발생해 답변 일관성이 깨질 수 있음
   - 해결방안: evidence aggregation 규칙과 reranking을 적용하고 contradiction rate와 answer coherence로 통합 품질을 검증함

## Ⅶ. 적용 사례

- 규정 질의응답: 규정 조항과 예외 조항을 연결함, 확인 지표는 multi-hop QA accuracy와 citation coverage임
- 연구 문서 분석: 논문 간 인용 관계와 결과를 결합함, 확인 지표는 evidence coverage와 answer correctness임
- 금융 리서치 보조: 기업 정보와 시장 지표를 순차 탐색함, 확인 지표는 average hops와 task completion rate임

## Ⅷ. 결론

Multi-hop RAG는 단일 검색으로 풀리지 않는 복합 질의를 해결하는 구조이므로, 검색 정확도보다 hop 간 상태 관리와 오류 전파 통제가 더 중요함.
