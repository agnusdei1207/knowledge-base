# 📖 【암기용】 개념 완전 이해

> 목적: Multi-hop RAG를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: 여러 문서·근거를 순차적으로 검색하고 연결해 답변하는 다단계 RAG 방식
- **왜 필요한가**: 단일 문서에 답이 없는 질문은 중간 근거를 찾고 다음 검색으로 이어가야 함.
- **핵심 직관**: 첫 단서로 다음 단서를 찾고, 여러 단서를 연결해 결론에 도달하는 추리 과정임.

## 깊이 이해
- **배경·문제의식**: "A 시스템 장애가 B 서비스 매출에 준 영향"처럼 원인·의존성·결과가 여러 문서에 흩어진 질의는 Top-K 한 번으로 답하기 어렵다.
- **작동 원리**: 질의를 하위 질문으로 분해하고, 1차 검색 결과에서 새 엔티티·조건을 추출해 2차·3차 검색을 수행한 뒤 근거 체인을 통합함.
- **비유**: 논문 참고문헌을 따라가며 원 논문, 실험 결과, 인용 논문을 차례로 확인해 결론을 만드는 방식임.
- **구체 예시**: HotpotQA 유형 질의에서 단일 검색 Recall@2 58%, 2-hop 검색 적용 시 supporting fact recall 72%로 향상.
- **흔한 오해·주의점**: 검색 횟수가 늘면 근거가 항상 늘지는 않음. 잘못된 첫 근거가 다음 검색을 오염시키므로 hop별 검증이 필요함.

## 연결 개념
- Agentic RAG — 에이전트가 다중 검색 계획을 세우는 실행 방식
- Graph RAG — 관계 그래프를 따라 hop 탐색을 수행하는 구조
- Query Decomposition — 복합 질문을 하위 질문으로 나누는 전처리

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Multi-hop RAG는 복수 검색 결과를 단계적으로 연결해 근거 체인을 구성하는 RAG임.
> 2. **가치**: 단일 검색으로 답하기 어려운 복합 질의에서 supporting fact recall을 58%->72%로 높임.
> 3. **판단 포인트**: hop별 근거 검증과 검색 종료 조건을 두지 않으면 오류 전파와 지연 증가가 발생함.

## Ⅰ. 개요 및 필요성

- 개요: 다단계 검색형 RAG 구조
- 배경: 복합 질문은 답의 근거가 여러 문서·엔티티에 분산되어 단일 Top-K 검색만으로 supporting fact를 확보하기 어려움.
- 필요성: query decomposition, hop planner, max_hop=2~3, evidence chain으로 다문서 근거 연결성과 출처 추적성을 검증해야 함.

## Ⅱ. 구조 및 구성요소

```text
Query -> Decomposer -> Hop-1 Retriever -> Evidence
Evidence -> Entity/Condition Extractor -> Hop Planner
Hop Planner -> Hop-2/3 Retriever -> Synthesizer
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Decomposer | 복합 질의를 하위 질문으로 분해 | 2~5개 sub-query 생성 |
| Hop Planner | 다음 검색 조건·종료 여부 결정 | max_hop=2~3 권장 |
| Evidence Extractor | 새 엔티티·조건·시간 범위 추출 | 근거 문장 단위 추출 |
| Synthesizer | 근거 체인 통합 답변 생성 | supporting fact와 출처 함께 출력 |

> 요약: Multi-hop RAG는 질의 분해, hop별 검색, 근거 추출, 통합 생성을 통해 분산된 근거를 연결함.

## Ⅲ. 동작원리 및 흐름도

```text
복합 질의 -> 하위 질문 생성 -> 1차 검색
  -> 엔티티/조건 추출 -> 2차 검색 -> 근거 검증
   - 근거 부족 -> 3차 검색
   - 근거 충분 -> 체인 통합 답변
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 질의를 2~5개 하위 질문으로 분해 | 분해 정확도 ≥90% |
| 2 | Hop-1 검색 후 핵심 엔티티·조건 추출 | 근거 문장 추출 F1 ≥0.8 |
| 3 | Hop-2/3 검색과 근거 일관성 검증 | supporting fact recall ≥70% |
| 4 | 근거 체인 기반 답변 생성 | hop별 출처 표시율 100%, 지연 < 5초 |

> 요약: 각 hop에서 새 단서를 추출하고 다음 검색으로 연결하며, 근거 충분성 조건을 만족하면 답변 생성을 종료함.

## Ⅳ. 특징

| 구분 | Single-hop RAG | Multi-hop RAG | 판단 포인트 |
|:---|:---|:---|:---|
| 검색 횟수 | 1회 Top-K | 2~3회 반복 검색 | 복합 질의 비율 30% 이상이면 필요 |
| 근거 범위 | 단일 문서·청크 | 다문서 근거 체인 | 원인-결과·의존성 분석에 적합 |
| 지연 | 1~2초 | 3~5초 | 사용자 대화형은 hop 제한 필요 |
| 오류 위험 | 검색 누락 | 오류 전파 | hop별 검증·종료 조건 필수 |

> 요약: Multi-hop RAG는 복합 질의 답변력을 높이지만, 검색 반복에 따른 지연과 오류 전파를 통제해야 함.

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 장애 RCA: 알람->서비스->DB->배포 이력 순서로 3-hop 검색, hop별 근거와 시간축을 함께 출력
2. 규정 질의: 조항 번호·예외 조건·관련 시행령을 순차 검색, 근거 조항 2개 이상일 때만 답변 생성
3. 종료 제어: max_hop=3, supporting fact recall 70% 미만이면 "근거 부족" 응답, 캐시로 반복 질의 지연 30% 절감

**결론 (2줄):**
- 기술사 판단: 원인-결과·의존성·비교형 질의는 Multi-hop RAG, 단순 사실 조회는 Single-hop RAG 적용
- 향후 방향: Agentic RAG와 Graph RAG가 hop 계획과 관계 탐색을 자동화하는 방향으로 확장
