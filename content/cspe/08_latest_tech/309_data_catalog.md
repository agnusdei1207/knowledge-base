## 미리 알고가기

- Data Catalog는 데이터 자산을 찾고 이해하고 신뢰하게 만드는 메타데이터 검색 체계임
- 기술 메타데이터뿐 아니라 업무 용어와 소유자와 품질 상태가 함께 있어야 활용 가치가 커짐
- Catalog와 Lineage와 Governance는 서로 보완 관계로 함께 운영되는 경우가 많음

## Ⅰ. 개요

- **정의/개념**: Data Catalog는 조직 내 데이터셋과 테이블과 지표와 대시보드의 메타데이터를 수집하고 검색 가능하게 정리해 사용자가 데이터의 의미와 위치와 소유자와 활용 가능성을 빠르게 파악하도록 지원하는 메타데이터 관리 체계임
- **배경/필요성**: 데이터 자산이 급증하면서 어떤 데이터가 존재하는지조차 찾기 어려워졌고 중복 개발과 잘못된 사용과 품질 불신이 커져 발견성과 이해성을 높이는 중앙 안내 체계가 필요해짐

## Ⅱ. 특징

- 검색과 탐색을 통해 숨겨진 데이터 자산의 재사용성을 높임
- 업무 용어와 기술 메타데이터를 연결해 현업과 기술 조직 간 해석 차이를 줄임
- 품질과 계보와 접근 정책을 같이 보여줄수록 데이터 신뢰 판단이 쉬워짐
- 메타데이터 갱신이 늦으면 검색 도구는 있어도 실제 활용률이 빠르게 떨어질 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | Data Catalog | Metadata Repository | File Inventory |
|:---|:---|:---|:---|
| 사용자 초점 | 검색과 이해와 재사용 | 저장과 관리 | 보관 목록 |
| 포함 정보 | 의미, 소유자, 품질, 계보 | 기술 메타데이터 중심 | 파일 위치 중심 |
| 활용 목적 | 발견성 향상 | 메타데이터 운영 | 자산 파악 |
| 운영 가치 | 데이터 민주화 | 관리 기반 제공 | 보존 확인 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Metadata Ingestion | 데이터베이스와 ETL과 BI 도구에서 스키마와 사용 이력과 구조 정보를 수집해 카탈로그의 기초 자산을 형성하는 수집 계층임 |
| Business Glossary | 업무 용어와 정의와 책임 부서를 정리해 기술 명칭과 비즈니스 의미를 연결하는 해석 계층임 |
| Search and Discovery Interface | 검색과 태그와 추천 기능을 제공해 사용자가 필요한 데이터를 빠르게 찾고 비교하게 하는 활용 계층임 |
| Stewardship Workflow | 소유자 지정과 검토와 승인 절차를 운영해 메타데이터 품질과 최신성을 유지하는 관리 계층임 |
| Trust Signals | 품질 상태와 사용 빈도와 계보와 정책 정보를 함께 제시해 사용자가 데이터를 신뢰할 수 있는지 판단하게 하는 신뢰 계층임 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 메타 수집     | -> | 분류/태깅     | -> | 소유자 검토   | -> | 검색 공개     | -> | 사용 피드백 반영 |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **메타 수집**: 다양한 시스템에서 구조와 사용 이력을 자동 수집함
2. **분류와 태깅**: 도메인과 민감도와 주제를 기준으로 자산을 정리함
3. **소유자 검토**: steward가 설명과 품질과 정책 정보를 보강함
4. **검색 공개**: 사용자가 검색과 추천을 통해 자산을 발견함
5. **사용 피드백 반영**: 조회와 활용 패턴을 다시 메타데이터 개선에 활용함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 자동 수집만 의존하면 설명과 용어와 책임 정보가 비어 있어 검색은 가능해도 실제 이해와 재사용으로 이어지지 않을 수 있음
   - 해결방안: steward enrichment workflow와 glossary completion target을 적용하고 documented asset ratio와 glossary linked asset coverage로 검증함
2. 문제: 메타데이터 갱신 주기가 느리면 삭제되거나 변경된 자산이 계속 노출되어 사용자의 신뢰가 급격히 떨어질 수 있음
   - 해결방안: freshness SLA와 change event driven sync를 적용하고 metadata freshness score와 stale asset discovery count로 검증함
3. 문제: 검색 경험이 약하면 카탈로그가 있어도 사용자들이 개인 지식과 메신저 문의에 다시 의존하게 될 수 있음
   - 해결방안: relevance tuning과 usage feedback ranking을 적용하고 search success rate와 repeat manual inquiry count로 검증함

## Ⅶ. 적용 사례

- 데이터 거버넌스 조직이 steward 보강 절차를 운영하며 확인 지표는 documented asset ratio와 glossary linked asset coverage임
- 메타데이터 플랫폼이 이벤트 기반 동기화를 적용하며 확인 지표는 metadata freshness score와 stale asset discovery count임
- 사내 데이터 포털이 검색 랭킹 개선을 운영하며 확인 지표는 search success rate와 repeat manual inquiry count임

## Ⅷ. 결론

Data Catalog는 메타데이터 저장소가 아니라 데이터 발견과 신뢰 형성을 위한 사용자 접점이므로 최신성과 설명 가능성이 함께 관리되어야 함.
