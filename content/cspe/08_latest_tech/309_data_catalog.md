# 📖 【암기용】 개념 완전 이해

> 목적: 데이터 카탈로그를 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 사내에 흩어진 수많은 데이터를 검색하고, 그 데이터의 의미와 품질, 소유자를 한눈에 파악할 수 있게 정리한 '데이터 백과사전' 또는 '데이터 포털'
- **왜 필요한가**: 데이터가 너무 많아지면 분석가가 필요한 데이터를 찾는 데만 시간의 80%를 쓴다. 정작 찾더라도 "이 값이 맞는지", "누구한테 허락받아야 하는지" 몰라 포기하는 일을 막기 위해서다.
- **핵심 직관**: "데이터 세계의 '구글 검색' + '위키피디아' + '쇼핑몰 리뷰'를 합쳐놓은 것."

## 깊이 이해
- **배경·문제의식**: 데이터 레이크(DL)를 만들었더니 정리는 안 되고 쌓이기만 하는 '데이터 늪'이 됨. 데이터 이름만 보고는 실제 내용을 알 수 없고, 담당자가 퇴사하면 데이터의 맥락(Context)이 영영 사라짐.
- **작동 원리**: '메타데이터'를 수집하여 관리함. 단순히 테이블 명, 컬럼 명 같은 '기술 메타데이터'뿐만 아니라, "이 데이터는 매출 계산용임" 같은 '비즈니스 메타데이터', 그리고 실제 사용자들의 평점이나 인기순 같은 '소셜 메타데이터'를 통합하여 제공함.
- **비유**: 대형 도서관의 '도서 검색대'와 같음. 책의 제목, 저자, 위치는 물론이고 다른 사람들의 대출 횟수나 서평을 보고 내가 찾는 지식이 맞는지 바로 알 수 있게 해주는 것.
- **구체 예시**: 분석가가 "고객 이탈"이라고 검색하면, 관련 테이블 목록이 나옴. 가장 인기 있는 테이블을 누르면 "이 테이블의 신뢰도는 98%이고, 담당자는 홍길동이며, 개인정보가 포함되어 있음"이라는 정보가 나옴. 거기서 바로 "권한 신청" 버튼을 누름.
- **흔한 오해·주의점**: 단순히 리스트만 보여주는 엑셀 파일이 아님. 데이터의 변경 이력(Lineage)을 자동으로 추적하고, AI를 통해 자동으로 태그를 달아주는 동적 시스템이어야 함.

## 연결 개념
- Metadata Management - 데이터 카탈로그의 기반 기술
- Data Lineage - 데이터가 어디서 와서 어디로 가는지 보여주는 지도
- Data Governance - 데이터 카탈로그를 포함하는 상위 관리 체계

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 기술/비즈니스/운영 메타데이터의 통합과 AI 기반 자동 수집(Harvesting), 그리고 데이터 민주화를 위한 검색 편의성을 강조한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 데이터 카탈로그는 기업 내 산재된 데이터 자산의 위치, 정의, 맥락, 품질 정보를 메타데이터 기반으로 구조화하여 제공하는 통합 지식 저장소이다.
> 2. **가치**: 데이터 검색 및 준비 시간(Data Discovery Time)을 획기적으로 단축하여 분석 생산성을 높이고, 데이터 품질에 대한 신뢰를 구축한다.
> 3. **판단 포인트**: 정적 관리 체계를 넘어 AI 기반의 자동 메타데이터 수집과 사용자의 피드백을 반영하는 소셜 카탈로그로의 고도화가 핵심이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 데이터 자산 관리 중요성 인식 확인 | 메타데이터 유형(기술/비즈니스/운영), 데이터 검색 편의성 | 단순 "데이터 리스트"로만 정의 지양 |
| 데이터 거버넌스 체계 이해도 | 권한 관리, 품질 지표, 리니지(Lineage) 연계 | 기술적 요소에만 치중하여 비즈니스 가치 간과 |
| 현대적 카탈로그 트렌드 파악 | AI 기반 자동 태깅, 소셜 협업 기능, 셀프 서비스 플랫폼 | 수동 관리 방식에 머무른 설명 지양 |

> 요약: 데이터 카탈로그는 '데이터를 찾는 곳'에서 '데이터를 이해하고 신뢰를 얻는 곳'으로 진화하는 거버넌스의 허브이다.

## Ⅰ. 개요 및 필요성

- 정의: 전사 데이터 자산의 가시성 확보를 위해 메타데이터를 수집, 분류, 검색할 수 있도록 제공하는 중앙 집중형 데이터 인벤토리
- 배경: 데이터 폭증으로 인한 검색 비용 증가(Data Discovery Gap), 데이터 문해력(Data Literacy) 편차 심화
- 필요성: 데이터 분석 전 단계(Preparation) 효율화, 규제 준수(개인정보 식별), 데이터 품질 및 신뢰성 기반의 의사결정 지원

---

## Ⅱ. 구조 및 구성요소 (3대 메타데이터 통합)

```text
[ Data Sources ] -> [ Metadata Harvesting (AI) ] -> [ Data Catalog Repository ]
                                                           |
  / 1. 기술 메타데이터: Schema, Table, Column, Type, PK/FK   |
  / 2. 비즈니스 메타데이터: Glossary, Domain, Definition, Owner |
  / 3. 운영 메타데이터: Usage Stat, Quality Score, Lineage, PII |
                                                           |
[ Interface: Search, Discovery, Collaboration, Request ] <-+
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Metadata Harvester | 소스 시스템에서 메타데이터를 자동으로 추출 및 동기화 | API, JDBC 커넥터 활용 |
| Business Glossary | 전사 공통 비즈니스 용어집과 데이터 매핑 | 용어 일관성 확보 |
| Data Lineage | 데이터의 생성, 변환, 소비 흐름을 시각화 | 영향도 분석 및 원인 파악 |
| Search & Discovery | 자연어 검색 및 필터링을 통한 데이터 탐색 | 구글 스타일 검색 지원 |

> 요약: 기술적 사양과 비즈니스 의미, 실제 운영 이력을 하나로 묶어 다차원적인 정보 포털을 구성한다.

---

## Ⅲ. 동작원리 및 흐름도 (자율 운영 카탈로그 흐름)

```text
Source Connect -> [ 1. Profiling ] -> [ 2. Auto-Tagging ] -> [ 3. Relationship Map ]
                       |                      |                      |
                (데이터 샘플 분석)        (AI 기반 의미 부여)      (리니지/관계 자동 생성)
                       |                      |                      |
        [ 5. Collaboration ] <- [ 4. Social Feedback ] <-------------+
                       |                      |
               (사용자 리뷰/평점)        (인기도/활용도 반영)
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 메타데이터 수집 | 스케줄 기반으로 소스 시스템의 스키마 및 이력 추출 | 최신성 유지(Sync) |
| 2 | 데이터 프로파일링 | 실제 데이터 값의 분포, 결측치, 형식 등을 샘플링 분석 | 데이터 품질 기본 진단 |
| 3 | AI 자동 분류 | PII(개인정보) 여부를 자동 식별하고 태그 부여 | 보안 및 규제 준수 자동화 |
| 4 | 지식화 및 공유 | 사용자 가이드, 쿼리 예제, 사용 후기 등을 결합 | 집단 지성 활용 |

> 요약: 자동 수집된 기술 정보에 AI 분석과 사용자 피드백을 덧입혀 살아있는 지식 자산으로 전환한다.

## Ⅳ. 특징

| 구분 | 주요 특징 | 상세 내용 |
|:---|:---|:---|
| 검색 편의성 | Intelligent Search | 기술 명칭이 아닌 비즈니스 용어로 검색 가능 |
| 신뢰 지표 제공 | Data Quality Scoring | 데이터의 정확성, 최신성을 점수로 표기하여 신뢰 부여 |
| 영향도 분석 | End-to-End Lineage | 소스 변경 시 어떤 대시보드가 영향받는지 시각적 확인 |
| 거버넌스 자동화 | PII Discovery | 주민번호, 연락처 등 민감 정보를 AI가 스스로 찾아 태깅 |

> 요약: 단순히 보여주는 것을 넘어, 데이터의 '신뢰도'와 '영향도'를 실시간으로 제시하는 것이 핵심이다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존 메타데이터 관리 (MDM) | 현대적 데이터 카탈로그 | 선택 기준 |
|:---|:---|:---|:---|
| 관리 주체 | 중앙 관리자 중심 (Top-down) | 데이터 소비자 및 커뮤니티 (Bottom-up) | 조직의 데이터 문화 |
| 관리 방식 | 수동 입력 및 엄격한 통제 | AI 자동화 및 소셜 협업 | 데이터 자산의 규모 |
| 주요 목적 | 데이터 일관성 및 정합성 | 데이터 발견 및 분석 가용성 | 해결 목표의 우선순위 |
| 기술 동력 | 규칙 기반 (Rule-based) | AI/ML 기반 (Active Metadata) | 기술 성숙도 |

> 요약: 데이터 카탈로그는 '통제'보다 '발견과 활용'에 초점을 맞춘 개방형 거버넌스 도구이다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 정보의 노후화 | 소스 변경과 카탈로그 간 동기화 지연 | 실시간/주기적 하베스팅 자동화 | 메타데이터 동기화 주기 |
| 사용자 외면 | 비즈니스 용어 부재 및 불친절한 설명 | 데이터 스튜어드 임명 및 소셜 참여 이벤트 | 카탈로그 월간 활성 사용자 (MAU) |
| 보안 노출 | 메타데이터 자체에 민감 정보 포함 | 메타데이터 보안 정책 수립 및 권한 제어 | 메타데이터 접근 감사 로그 |

> 요약: 시스템 구축보다 '지속적인 동기화'와 '현업의 참여 유도'가 실질적인 운영 리스크이다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 데이터 탐색 시간 | 데이터 검색~권한 승인까지 50% 단축 | 분석가 대상 리드타임 조사 |
| 카탈로그 등록률 | 전사 핵심 데이터 테이블 95% 이상 등록 | 자산 대장 대비 카탈로그 비교 |
| 검색 성공률 | 검색어 입력 시 관련 데이터 노출 90% 이상 | 검색 로그 및 클릭률(CTR) 분석 |

> 요약: 도입 효과는 분석가의 생산성 향상과 데이터 자산에 대한 전사적 가시성 확보로 측정한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. **데이터 마켓플레이스 운영**: 카탈로그를 '데이터 쇼핑몰' 형태로 구성하여 분석가가 데이터를 장바구니에 담고 승인을 요청하는 워크플로우 구현
2. **AI 기반 품질 모니터링 연계**: 카탈로그 화면에 해당 데이터의 실시간 품질 지표(오류율 등)를 신호등 표시로 시각화하여 오용 방지
3. **리니지 기반 장애 대응**: 업스트림 시스템 장애 시 카탈로그의 리니지를 분석하여 영향을 받는 하부 보고서 사용자들에게 자동 알림 발송

**결론 (2줄):**
- 기술사 판단: 데이터 카탈로그는 데이터의 '존재'를 넘어 '가치'를 발견하게 하는 인프라이며, 데이터 기반 기업(Data-driven Enterprise)으로 가기 위한 첫 단추이다.
- 향후 방향: LLM과 결합하여 "지난달 서울지역 매출 데이터를 찾아줘"와 같은 대화형 데이터 탐색(Generative BI)의 핵심 지식 베이스로 진화할 것이다.
