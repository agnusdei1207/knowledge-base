# 📖 【암기용】 개념 완전 이해

> 목적: LLM02 Sensitive Information Disclosure를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: LLM이 개인정보, 인증정보, 내부 문서, 영업비밀, 학습 데이터 단서 등을 응답으로 노출하는 위험
- **왜 필요한가**: LLM은 RAG 문서, 대화 로그, 시스템 프롬프트, 도구 응답을 한 컨텍스트에서 처리함.
- **핵심 직관**: AI가 답변을 만들며 접근 가능한 내부 정보를 사용자가 볼 수 있는 문장으로 흘려보내는 문제임.

## 깊이 이해
- **배경·문제의식**: 생성형 AI는 요약·검색·상담 업무에서 민감 데이터에 접근하며, 출력 필터가 없으면 의도치 않은 공개가 발생함.
- **작동 원리**: 공격자는 재구성 질문, 권한 우회, 과도한 RAG 검색, 로그 노출, 프롬프트 추출로 민감정보 출력을 유도함.
- **비유**: 상담원이 고객 질문에 답하다가 내부 메모와 다른 고객 정보를 함께 읽어주는 상황임.
- **구체 예시**: 사내 챗봇이 권한 없는 직원에게 고객 주민번호 일부, 계약 단가, API 키 형식이 포함된 문서를 요약함.
- **흔한 오해·주의점**: 모델이 정보를 "기억"하지 않아도 RAG와 도구가 민감정보를 공급하면 노출된다. 접근제어와 DLP가 필요함.

## 연결 개념
- Prompt Leakage — 시스템 지시 노출
- RAG Access Control — 검색 결과 권한 필터
- Data Loss Prevention — 출력 민감정보 차단

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: LLM02는 LLM 출력 경로로 개인정보·기밀정보가 노출되는 위험임.
> 2. **가치**: 개인정보보호법, 영업비밀, 보안 인증정보 사고로 이어질 수 있어 대외 서비스 핵심 통제임.
> 3. **판단 포인트**: 검색 전 권한, 컨텍스트 최소화, 출력 DLP, 로그 마스킹을 동시에 적용해야 함.

## Ⅰ. 개요 및 필요성

LLM02는 민감정보 노출 위험이다. LLM 앱은 RAG와 도구를 통해 민감 데이터에 접근할 수 있다. 입력·검색·출력·로그 전 구간에서 노출을 통제해야 한다.

## Ⅱ. 구조 및 구성요소

```text
Sensitive Source -> Retrieval/Tool Context -> LLM Generation
  -> Output/Log -> Disclosure Control
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Sensitive Source | PII·PHI·credential·계약정보 | 등급 분류 |
| Access Filter | 사용자 권한 기반 검색 | ABAC/RBAC |
| Output DLP | 응답 민감 패턴 차단 | 주민번호·키 탐지 |
| Audit Log | 노출 시도 추적 | 마스킹 저장 |

> 요약: LLM02 대응은 민감 원천, 검색 권한, 출력 DLP, 감사 로그를 연결해 노출을 차단함.

## Ⅲ. 동작원리 및 흐름도

```text
데이터 등급화 -> 권한 필터 검색 -> 최소 컨텍스트 구성
  -> 출력 DLP 검사 -> 감사·차단
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 문서·로그·도구 응답 민감도 태깅 | PII 태깅 100% |
| 2 | 사용자 권한 기반 RAG 필터링 | 권한 없는 문서 0건 |
| 3 | 출력 DLP·정책 검증 수행 | 민감 패턴 유출 0건 |
| 4 | 차단·마스킹·사고 티켓화 | High incident SLA 24h |

> 요약: LLM02 방어는 검색 전 권한 검증과 출력 후 DLP를 모두 적용해 민감정보 유출을 막음.

## Ⅳ. 특징

| 구분 | 일반 데이터 유출 | LLM02 Sensitive Disclosure | 판단 포인트 |
|:---|:---|:---|:---|
| 경로 | DB·파일 다운로드 | 자연어 응답·요약·로그 | 출력 경로 |
| 원인 | 접근통제 실패 | RAG 권한·프롬프트 우회·로그 | 다중 원인 |
| 탐지 | DLP·SIEM | 응답 DLP·prompt log 분석 | AI 로그 |
| 방어 | RBAC·암호화 | 권한검색·컨텍스트 최소화 | RAG 설계 |

> 요약: LLM02는 기존 접근통제에 LLM 출력과 RAG 검색 권한 통제를 추가해야 하는 위험임.

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. RAG 권한: 문서 chunk마다 owner, classification, ACL을 저장하고 사용자 권한 불일치 문서는 검색 결과에서 제외
2. 출력 DLP: 주민번호, 카드번호, API key, 내부 URL 패턴을 탐지해 마스킹하고 원문 노출 0건 기준 적용
3. 로그 통제: 프롬프트·응답 로그는 민감값 마스킹 후 저장하고 보관기간 90일·접근승인 절차 적용

**결론 (2줄):**
- 기술사 판단: LLM02 대응은 모델 필터보다 데이터 등급화와 RAG 권한 필터를 우선 설계
- 향후 방향: LLM02 통제는 DLP, IAM, 데이터 카탈로그, AI Gateway와 통합됨
