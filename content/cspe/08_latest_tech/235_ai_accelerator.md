# 📖 【암기용】 개념 완전 이해

> 목적: AI 가속기(AI Accelerator) 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 인공지능의 핵심 연산인 대규모 행렬 곱셈(Matrix Multiplication)을 엄청나게 빠른 속도로 처리하기 위해 설계된 전용 하드웨어
- **왜 필요한가**: 범용 CPU는 모든 일을 다 잘하지만 행렬 연산은 느림. AI 모델은 수조 번의 곱셈과 덧셈을 반복해야 하는데, CPU로 하면 너무 오래 걸리고 전기도 많이 먹음
- **핵심 직관**: "산수부터 미적분까지 다 하는 만능 수학자(CPU) 대신, 구구단만 세상에서 제일 빨리 외우는 계산기(AI 가속기)를 쓰는 것"

## 깊이 이해
- **배경·문제의식**: 딥러닝의 기본 단위는 텐서(Tensor) 연산임. 기존의 직렬 처리 방식(SISO)으로는 한계가 명확함. 이를 해결하기 위해 수천 개의 연산기를 병렬로 배치하고, 데이터를 초고속으로 공급하는 구조가 필요해짐
- **작동 원리**: ① **병렬 연산**: 수천 개의 작은 코어(PE: Processing Element)가 동시에 곱셈-누산(MAC) 수행. ② **메모리 혁신**: 데이터가 지나가는 길을 넓히기 위해 일반 D-RAM 대신 HBM(고대역폭 메모리)을 바로 옆에 붙임. ③ **특화 설계**: 불필요한 기능을 빼고 텐서 연산에만 최적화된 회로(예: Google TPU의 시스톨릭 어레이) 구성
- **비유**: 1,000명의 학생이 한 개의 문으로 나가려면 오래 걸리지만(CPU), 1,000개의 문을 동시에 열어 한꺼번에 나가게 하는 것(AI 가속기)
- **구체 예시**: 엔비디아 GPU(H100), 구글 TPU, 삼성/애플의 NPU, 그록(Groq)의 LPU 등이 있음
- **흔한 오해·주의점**: "AI 가속기가 CPU를 완전히 대체한다"는 틀렸음. 시스템 부팅이나 복잡한 제어는 여전히 CPU가 담당하고, AI 연산만 가속기에게 시키는 '이종(Heterogeneous) 컴퓨팅' 구조임

## 연결 개념
- **HBM (High Bandwidth Memory)**: 가속기에 데이터를 공급하는 초고속 메모리
- **Systolic Array**: TPU 등에서 쓰이는 데이터 흐름 기반 연산 아키텍처
- **On-Device AI**: 스마트폰 내부에 탑재되는 소형 AI 가속기(NPU) 활용 분야

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 하드웨어 종류 나열에 그치지 않고 **병렬 아키텍처(MAC), 메모리 대역폭(Memory Wall), 전력 효율성(Energy Efficiency)** 관점에서 기술적 논리를 전개한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: AI 가속기는 딥러닝의 핵심인 다차원 텐서(Tensor) 연산 및 대규모 병렬 곱셈-누산(MAC)을 가속화하기 위해 최적화된 도메인 특화 아키텍처(DSA) 하드웨어이다.
> 2. **가치**: 범용 CPU 대비 연산 처리량(Throughput)은 수십 배 높이고, 전력 소모(Energy per Op)는 획기적으로 낮춰 거대 모델의 경제적 학습 및 실시간 추론을 가능케 한다.
> 3. **판단 포인트**: 연산 정밀도(FP8, INT4 등) 지원 범위, 데이터 전송 병목(Memory Wall) 해소를 위한 HBM 탑재 여부, 단위 전력당 성능(TOPS/W)을 종합 고려해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| AI 하드웨어 가속 원리 이해도 측정 | 병렬성(Parallelism), MAC(Multiply-Accumulate), HBM | 단순히 "성능이 빠르다"는 추상적 서술 |
| 가속기 종류별 특성 비교 역량 확인 | GPU(범용성), TPU/ASIC(효율성), FPGA(유연성), NPU(엣지) | 특정 제조사(Nvidia) 제품명에만 치중 |

> 요약: 행렬 연산 특화(Systolic Array 등)와 메모리 병목 해소 기술을 중심으로 기술한다.

---

## Ⅰ. 개요 및 필요성

- 정의: AI 알고리즘의 대규모 병렬 연산(Matrix/Vector multiplication)을 고속으로 처리하기 위해 설계된 전용 반도체 및 보드 형태의 시스템
- 배경: 폰 노이만 구조의 메모리 병목(Memory Wall)과 무어의 법칙 한계로 인해 범용 프로세서(CPU)의 성능 향상 속도가 AI 요구치를 못 따라감
- 필요성: 거대 언어 모델(LLM)의 학습 비용 절감, 저지연(Low Latency) 추론 서비스 제공, 모바일/엣지 기기의 저전력 AI 구현

---

## Ⅱ. 구조 및 구성요소

```text
[Host CPU] <--- PCIe/CXL ---> [AI Accelerator Card]
                                     |
    +--------------------------------+--------------------------------+
    | [Compute Engine]              | [Memory System]                |
    | - Systolic Array / Vector Unit | - HBM (High Bandwidth Memory) |
    | - Tensor Core (MAC Units)      | - On-chip SRAM (Buffer)       |
    +--------------------------------+--------------------------------+
```

| 구성요소 | 역할 | 핵심 기술 |
|:---|:---|:---|
| 연산 코어 | 수천 개의 연산을 동시 처리 | MAC Unit, Tensor Core, PE(Processing Element) |
| 고대역폭 메모리 | 연산 코어에 초고속 데이터 공급 | HBM3/3E, 2.5D/3D 패키징 |
| 인터커넥트 | 칩 내/외부 데이터 전송 통로 | NVLink, Infinity Fabric, CXL |
| 제어 로직 | 연산 스케줄링 및 명령어 해석 | 명령어 집합(ISA) 최적화 |

> 요약: 연산부(MAC Array)와 메모리부(HBM)가 초고밀도로 집적되어 병목을 최소화한 구조이다.

---

## Ⅲ. 동작원리 및 흐름도

```text
Instruction Fetch -> Data Loading (HBM to SRAM) -> Parallel Compute (MAC) -> Result Write
(AI 프레임워크 요청)    (병목 최소화 전송)          (수천 개 코어 동시 연산)   (결과 값 출력)
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | AI 모델의 연산 그래프를 가속기 명령어로 컴파일 | 커널 퓨전(Kernel Fusion) 최적화 |
| 2 | 입력 텐서 데이터를 가속기 내 메모리로 로드 | HBM 대역폭 점유율(Bandwidth Util) |
| 3 | 수만 개의 MAC 연산을 하드웨어 병렬 유닛에서 수행 | 연산 가동률(Core Utilization) |
| 4 | 연산 결과 값을 누적하거나 다음 레이어로 전달 | 데이터 재사용성(Data Reuse) 극대화 |

> 요약: 데이터를 한 번 읽어와서 여러 번 연산하는 '데이터 재사용'과 '병렬 처리'가 핵심 동작 원리이다.

## Ⅳ. 특징

| 구분 | GPU (Graphics) | TPU / ASIC (Targeted) | NPU (Mobile/Edge) |
|:---|:---|:---|:---|
| 핵심 아키텍처 | 범용 부동소수점 코어 | 전용 시스톨릭 어레이 | 모바일 특화 저전력 코어 |
| 유연성 (Flexibility) | 높음 (다양한 알고리즘) | 낮음 (특정 연산 최적화) | 중간 (AI 엔진 탑재) |
| 효율성 (Efficiency) | 중간 | 매우 높음 | 높음 (전력 효율 중심) |
| 주요 제조사 | Nvidia, AMD | Google (TPU), Rebellions | Apple, Samsung, Qualcomm |

> 요약: 범용성이 필요한 학습에는 GPU를, 고정된 대규모 추론에는 ASIC/TPU를, 모바일 기기에는 NPU를 주로 적용한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | GPU | FPGA | ASIC (TPU 등) |
|:---|:---|:---|:---|
| 개발 기간 | 짧음 (표준 라이브러리) | 중간 (HDL 설계) | 매우 긺 (설계-공정-생산) |
| 유연성 | 소프트웨어 업데이트 대응 | 하드웨어 로직 재구성 가능 | 고정된 기능만 수행 |
| 에너지 효율 | 낮음 (범용 기능 유지) | 중간 | 매우 높음 (최적의 TOPS/W) |

> 요약: 최신 알고리즘 대응에는 GPU가 유리하며, 표준화된 대규모 서비스에는 ASIC이 가장 경제적이다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| Memory Wall | 연산 속도 대비 메모리 공급 지연 | HBM3E 도입, 칩 내부 SRAM 확대 | Memory Bound Ratio |
| Thermal Throttling | 고성능 연산 시 급격한 발열 | 수냉식(Liquid) 냉각, 동적 전압 관리 | 작동 온도 (T-Junction) |
| Vendor Lock-in | 특정 제조사 라이브러리(CUDA 등) 종속 | Triton, OpenXLA 등 오픈소스 컴파일러 | SW 이식성 (Portability) |

> 요약: 메모리 병목과 발열 관리를 위해 HBM과 고급 냉각 기술을 적용하며, SW 종속성 탈피를 위한 표준화 노력이 병행된다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 연산 성능 | 1,000+ TFLOPS (FP16/8) | 벤치마크 (MLPerf) |
| 전력 효율 | 10+ TOPS/Watt | 전력 분석기 측정 |
| 메모리 대역폭 | 2.0+ TB/s 이상 | HBM 대역폭 측정 (Bandwidth Test) |

> 요약: 도입 성과는 MLPerf 표준 벤치마크 점수와 전력 대비 성능 지표로 검증한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. **학습 가속**: Nvidia H100 GPU 기반 클러스터 구축으로 100B 모델 학습 시간을 수개월에서 수주 단위로 단축
2. **저전력 추론**: 구글 Cloud TPU v5를 적용하여 대규모 검색 서비스의 추론 비용을 기존 GPU 대비 30~50% 절감
3. **온디바이스 AI**: 모바일 AP 내 NPU를 활용하여 네트워크 연결 없이 실시간 사진 보정 및 음성 인식 기능 구현

**결론 (2줄):**
- 기술사 판단: AI 가속기는 '반도체 패권'의 핵심이며, 단순히 하드웨어 스펙 경쟁을 넘어 쿠다(CUDA)와 같은 소프트웨어 생태계 경쟁이 본질이다
- 향후 방향: 연산 코어와 메모리를 하나로 합치는 PIM(Processing-In-Memory) 기술과 뉴로모픽 아키텍처로의 진화가 가속화될 것이다
