# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: 클라우드 환경에서 하드웨어 기반의 신뢰실행환경(TEE)을 사용하여 데이터가 처리(연산)되는 동안에도 훔쳐볼 수 없도록 완전히 보호하는 최상위 클라우드 데이터 보안 패러다임(이니셔티브).
- **필요성**: 기업이 AWS나 Azure를 쓸 때 항상 불안함. "클라우드 관리자가 마음먹으면 우리 데이터베이스 털어볼 수 있는 거 아냐?", "같은 클라우드 서버 쓰는 옆 회사 해커가 메모리 타고 넘어오면 어떡해?". 클라우드 제공자(CSP)조차도 내 데이터를 볼 수 없게 기술적으로 차단하여 이 불안(Cloud Trust Gap)을 없애기 위해 등장.
- **핵심 직관**: 투명 유리방과 블랙박스 작업실. 기존 클라우드에서는 작업자(CPU)가 투명한 유리방에서 문서를 펼치고 작업했음(메모리에 평문 노출). 관리자나 해커가 망원경으로 다 볼 수 있음. 기밀 컴퓨팅은 작업실을 시커먼 텅스텐(하드웨어 암호화) 블랙박스로 바꿔버림. 들어갈 때 암호화된 문서가 들어가고, 안에서 작업(연산)을 마치면 다시 암호화되어 나옴. 작업 과정을 외부에서 절대 볼 수 없음.

## 깊이 이해
- **배경**: 데이터 보안의 3요소 중 1) 저장 데이터(Data at Rest: 하드디스크 암호화), 2) 전송 데이터(Data in Transit: HTTPS, TLS)는 완벽히 해결됨. 하지만 마지막 남은 구멍인 3) 사용 중인 데이터(Data in Use: RAM/CPU에서 처리 중인 데이터)를 보호하기 위해 리눅스 재단 주도로 'Confidential Computing Consortium(CCC)'이 결성되며 붐이 일어남.
- **작동 원리 (TEE 기반 하드웨어 격리)**:
  - 기밀 컴퓨팅은 소프트웨어(OS) 기반의 보안을 믿지 않음 (OS가 해킹당하면 끝이니까).
  - 대신 Intel SGX, AMD SEV, ARM TrustZone 같은 CPU 내부의 물리적인 '하드웨어 격리 기술(TEE, Enclave)'을 활용함.
  - 이 하드웨어 금고 안에서만 데이터 복호화와 연산이 일어남. 운영체제 최고 권한자(Root)나 하이퍼바이저가 이 메모리 영역을 읽으려 하면 CPU가 암호화된 쓰레기 값만 뱉어내며 접근을 원천 차단함.
- **구체 예시**: 제약회사의 AI 신약 개발. A제약사와 B제약사가 서로의 임상 데이터를 합쳐서 AI를 돌리고 싶음. 하지만 데이터 유출이 무서움. 퍼블릭 클라우드에 '기밀 컴퓨팅 VM(가상머신)'을 생성함. 양쪽 데이터를 암호화해서 이 VM에 넣음. 클라우드 관리자도 VM 내부를 볼 수 없음. VM 내부(TEE)에서만 데이터가 풀려 신약 AI를 완성하고, 그 결과값만 양측에 배분함.
- **흔한 오해/주의점**: "TEE랑 기밀 컴퓨팅이랑 똑같은 말 아님?" $\rightarrow$ 아님. TEE는 CPU 안에 보안 구역을 만드는 '기술/부품' 자체를 뜻하고, 기밀 컴퓨팅은 이 TEE를 활용하여 클라우드 서비스 전체(VM, 컨테이너, 데이터 결합 등)의 사용 중 데이터를 보호하자는 광범위한 '보안 모델/개념'임.

## 연결 개념
- **TEE (Trusted Execution Environment)**: 기밀 컴퓨팅을 실현 가능하게 만들어 주는 핵심 하드웨어 엔진.
- **Confidential Consortium Framework (CCF)**: 마이크로소프트가 기밀 컴퓨팅 환경에서 블록체인 노드를 돌리기 위해 만든 오픈소스 프레임워크.
- **Homomorphic Encryption (동형암호)**: 사용 중 데이터(Data in Use)를 보호한다는 목적은 똑같지만, 기밀 컴퓨팅은 '하드웨어'로 가리는 방식이고, 동형암호는 '수학적'으로 가리는 방식임. (기밀 컴퓨팅이 현재 실무 적용 속도는 훨씬 빠름).

# 📝 【답안용】 시험 답안 템플릿
## 핵심 인사이트 (3줄 요약)
- **본질**: 하드웨어 기반의 신뢰실행환경(TEE)을 활용하여 클라우드 컴퓨팅의 가장 큰 취약점인 '사용 중인 데이터(Data in Use)'의 기밀성과 무결성을 보장하는 차세대 제로 트러스트(Zero Trust) 클라우드 보안 모델.
- **가치**: 기존에 맹목적으로 신뢰해야 했던 클라우드 제공자(CSP), 하이퍼바이저, 호스트 OS를 '신뢰 경계(Trust Boundary)' 밖으로 밀어냄으로써, 금융/의료/국방 워크로드를 퍼블릭 클라우드로 전환(Migration)할 수 있는 기술적 명분을 제공함.
- **판단 포인트**: 기밀 컴퓨팅 아키텍처의 핵심은 데이터 격리를 넘어, 코드가 변조되지 않았음을 하드웨어 서명으로 외부에서 확인하는 원격 증명(Remote Attestation)과 이에 연동된 안전한 키 릴리스(Key Release) 프로세스의 완결성에 있음.

## Ⅰ. 개요 및 필요성
- **정의**: 메모리 내에서 연산이 처리되는 동안 데이터와 실행 중인 코드를 운영체제 커널이나 클라우드 인프라 관리자의 무단 접근으로부터 하드웨어적으로 암호화하여 보호하는 기술적 이니셔티브.
- **배경**: 기존 클라우드 보안 체계는 Data at Rest(저장)와 Data in Transit(전송) 보호에 집중되어 있어, 딥러닝 훈련이나 인메모리(In-Memory) DB 쿼리 실행 시 메모리에 평문으로 적재되는 Data in Use 상태의 치명적 취약성(메모리 덤프 등)이 잔존함.
- **필요성**: 멀티 테넌트(Multi-tenant) 클라우드 환경에서 이웃 테넌트의 측면 이동 공격 및 CSP 내부 직원에 의한 데이터 유출(Insider Threat)을 원천 차단하는 기술 통제 수단 확보.

## Ⅱ. 기밀 컴퓨팅의 핵심 실현 기술 아키텍처
소프트웨어 보안(OS)에서 하드웨어 기반 보안(Silicon)으로의 패러다임 전환.
| 핵심 구성 요소 | 기술적 역할 | 대응 공격 / 위험 요소 |
|:---:|:---|:---|
| **신뢰실행환경 (TEE)** | CPU 내부에 **Enclave(보안 영역)**를 생성하여 실행 공간을 물리적/논리적으로 격리. | 하이퍼바이저(VM 관리자) 및 Host OS 권한 탈취 공격 |
| **메모리 실시간 암호화** | TEE 내부에 할당된 메모리 데이터를 CPU 밖으로 나가는 순간 하드웨어 암호화 엔진이 자동 암호화. | 콜드 부트 공격 (서버 전원을 끄고 RAM 칩을 빼서 정보 탈취) |
| **원격 증명**<br>(Remote Attestation) | TEE 내부의 애플리케이션 코드가 위변조되지 않았음을 고유 해시(Hash)로 측정하고 CPU 키로 서명하여 검증자에게 제출. | 가짜/변조된 컨테이너(VM) 스푸핑 공격 |
| **정책 기반 키 릴리스** | 원격 증명이 100% 성공(무결성 확인)한 경우에만 외부 KMS(키 관리 시스템)에서 복호화 키를 TEE 내부로 전송. | 암호화 키 사전 탈취 공격 |

## Ⅲ. 주요 클라우드 사업자(CSP)별 기밀 컴퓨팅 지원 현황
하드웨어(Chip)와 클라우드 인프라의 결합 생태계.
1. **Azure Confidential Computing (MS)**:
   - Intel SGX 베어메탈 인스턴스를 제공하여 애플리케이션 레벨의 초정밀 Enclave 격리 지원. (가장 선도적).
2. **AWS Nitro Enclaves**:
   - AWS에 최적화된 하이퍼바이저(Nitro)를 통해 기존 EC2 인스턴스 옆에 네트워크 접속이 완전히 차단된 격리된 컴퓨팅 환경(Enclave)을 붙여주는 방식.
3. **Google Cloud Confidential VMs**:
   - AMD SEV(Secure Encrypted Virtualization) 칩을 사용하여 애플리케이션 코드 수정 없이 가상머신(VM) 전체의 메모리를 통째로 암호화하여 보호. (마이그레이션 용이).

## Ⅳ. 데이터 협력 생태계 구축 모델 (Confidential Data Clean Room)
기밀 컴퓨팅의 가장 강력한 B2B 비즈니스 활용 사례.
- **시나리오**: 복수의 기업이 경쟁 우위를 지키면서 데이터를 결합 분석.
- **아키텍처**:
  - 클라우드 상에 Confidential VM 생성 $\rightarrow$ 각 기업은 자사 데이터를 암호화하여 전송 $\rightarrow$ C-VM이 원격 증명(Attestation)으로 안전함을 증명 $\rightarrow$ 각 기업이 복호화 키를 C-VM 내부로 전송 $\rightarrow$ C-VM 내부에서만 데이터 결합 및 AI 분석 수행 $\rightarrow$ 분석 결과 통계만 암호화하여 각 기업에 반환. (원본 데이터 노출 제로).

## Ⅴ. 실무 적용 및 결론
- **판단 지표**: TCB(Trusted Computing Base) 사이즈 최적화 수준, 원격 증명(Attestation) 소요 시간에 따른 앱 기동 지연, 레거시 애플리케이션의 Enclave 포팅(Porting) 비용(Lift and Shift 비율).
- **실무 설계**: 금융권 퍼블릭 클라우드(SaaS) 기반 고객 신용 스코어링 시스템 도입. 망분리 규제로 인해 고객 식별 정보(PII)의 평문 처리가 금지됨. 기밀 컴퓨팅(AMD SEV 기반 Confidential VM) 도입 전략 수립. 기존 리눅스 기반 스코어링 애플리케이션 코드를 1줄도 수정하지 않고(Lift and Shift), VM 전체 메모리를 하드웨어로 암호화하는 인스턴스 배포. 클라우드 사업자(CSP)가 하이퍼바이저 권한을 통해 VM 메모리에 접근해도 데이터는 완전 암호화 상태 유지. 컴플라이언스(보안성 검토)를 통과하여 퍼블릭 클라우드 활용의 유연성과 비용 절감 달성.
- **결론**: 기밀 컴퓨팅은 클라우드 환경에서 "내가 내 데이터를 직접 통제한다"는 데이터 주권을 회복시켜 주는 궁극의 보안 아키텍처이다. 암호학적 연산(동형암호)에 비해 압도적으로 빠른 처리 속도를 강점으로 내세우며, 차세대 AI 인프라와 Web3.0 분산 환경의 필수 기반 기술(Defacto Standard)로 자리 잡을 것이다.

### 🔀 문제 유형별 목차 전환
- **Ⅱ·Ⅲ 강조 (개념/원리형)**: 기밀 컴퓨팅의 두 가지 하드웨어 구현 스탠스인 '애플리케이션 단위 격리(Intel SGX: TCB 축소 극대화)'와 'VM 단위 격리(AMD SEV/Intel TDX: 호환성 극대화)'의 메모리 암호화 매커니즘과 보안-편의성 Trade-off 상세 비교.
- **Ⅴ·Ⅵ 강조 (실무/설계형)**: 기밀 컴퓨팅 환경에서 컨테이너(Kubernetes) 워크로드를 안전하게 실행하기 위한 Confidential Containers (CoCo) 아키텍처 및 Kata Containers 런타임과의 통합 설계 방안.
