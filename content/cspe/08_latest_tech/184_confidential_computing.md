# 📖 【암기용】 개념 완전 이해

> 목적: Confidential Computing을 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **정의**: TEE와 하드웨어 메모리 암호화로 사용 중 데이터(data in use)를 보호하는 컴퓨팅 모델
- **왜 필요한가**: 클라우드·멀티테넌트 환경에서 운영자 권한이나 하이퍼바이저 침해에도 민감 워크로드를 보호해야 함.
- **핵심 직관**: 데이터가 저장소와 네트워크를 벗어나 CPU에서 계산되는 순간까지 암호 보호 범위를 확장함.

## 깊이 이해
- **배경·문제의식**: 기존 보안은 저장 중(data at rest), 전송 중(data in transit)에 집중했고 처리 중 메모리 노출이 남음.
- **작동 원리**: Secure VM/enclave, 메모리 암호화, remote attestation, 정책 기반 키 릴리스를 결합해 검증된 워크로드만 데이터를 사용함.
- **비유**: 택배 박스가 창고와 이동 중뿐 아니라 포장 해체 작업실 안에서도 외부인이 볼 수 없게 하는 구조임.
- **구체 예시**: AMD SEV-SNP 기반 VM에서 고객 데이터 분석 애플리케이션을 실행하고 attestation 성공 후에만 KMS 키를 제공.
- **흔한 오해·주의점**: 클라우드 사업자를 완전히 신뢰하지 않아도 되는 구조이지, 애플리케이션 취약점과 잘못된 권한 설정을 대신 제거하지는 않음.

## 연결 개념
- Trusted Execution Environment — 기밀 컴퓨팅 구현 기반
- Remote Attestation — 워크로드 신뢰성 검증
- Zero Trust — 인프라 내부 신뢰 최소화 관점

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Confidential Computing은 사용 중 데이터를 하드웨어 격리와 검증으로 보호하는 클라우드 보안 모델임.
> 2. **가치**: 클라우드 관리자·하이퍼바이저 침해 상황에서도 민감 워크로드 노출을 제한함.
> 3. **판단 포인트**: attestation, 키 릴리스 정책, 워크로드 경계, 운영 로그 보호를 함께 설계해야 함.

## Ⅰ. 개요 및 필요성

Confidential Computing은 사용 중 데이터 보호 모델이다. 클라우드 워크로드는 처리 중 메모리와 관리자 권한에 노출될 수 있다. TEE와 원격 검증으로 민감 연산 경계를 보호해야 한다.

## Ⅱ. 구조 및 구성요소

```text
Confidential VM/Enclave → Memory Encryption
  → Remote Attestation → Policy-based Key Release
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Confidential VM | 워크로드 격리 실행 | SEV-SNP, TDX |
| Memory Encryption | VM 메모리 보호 | data in use 보호 |
| Attestation Service | 실행환경 검증 | 측정값·서명 확인 |
| Key Broker/KMS | 검증 후 키 제공 | 정책 기반 릴리스 |

> 요약: 기밀 컴퓨팅은 격리 VM, 메모리 암호화, 원격 검증, 키 릴리스를 결합해 워크로드를 보호함.

## Ⅲ. 동작원리 및 흐름도

```text
워크로드 측정 → 기밀 VM 생성 → 원격 검증
  → 키 릴리스 → 민감 처리 수행
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 이미지·부트 체인 측정 | allowlist hash |
| 2 | 기밀 VM/enclave 생성 | 메모리 암호화 활성 |
| 3 | attestation token 검증 | 정책 일치 100% |
| 4 | KMS 키 제공 후 처리 | 평문 디스크 저장 0건 |

> 요약: Confidential Computing은 검증된 기밀 환경에만 키를 제공해 사용 중 데이터를 보호함.

## Ⅳ. 특징

| 구분 | 전통 클라우드 보안 | Confidential Computing | 판단 포인트 |
|:---|:---|:---|:---|
| 보호 범위 | 저장·전송 중심 | 처리 중 데이터 포함 | data in use |
| 신뢰 모델 | CSP·관리자 신뢰 | 하드웨어 검증 기반 | 신뢰 최소화 |
| 적용 단위 | VM·컨테이너 보안 | Confidential VM/enclave | 앱 수정 범위 |
| 한계 | 관리자 권한 위험 | I/O·앱 취약점 잔존 | 보완 통제 필요 |

> 요약: 기밀 컴퓨팅은 처리 중 보호를 추가하지만 애플리케이션 보안과 권한 관리는 별도 유지해야 함.

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 민감 분석: 고객 데이터 분석 VM은 SEV-SNP/TDX 기반으로 구성하고 attestation 성공 시 KMS 키 제공
2. AI 워크로드: 모델 가중치와 입력 feature는 기밀 VM 내부에서 복호화하고 출력값은 DLP 규칙으로 검사
3. 운영 통제: 이미지 hash allowlist, attestation 로그 1년 보관, 평문 스냅샷·코어덤프 비활성 적용

**결론 (2줄):**
- 기술사 판단: 클라우드에서 민감 데이터를 처리하는 업무는 저장·전송 암호화에 기밀 컴퓨팅을 추가해야 함
- 향후 방향: Confidential Computing은 데이터 클린룸, 프라이버시 보존 AI, 규제 산업 클라우드의 기본 보안 계층으로 확산됨
