# 📖 【암기용】 개념 완전 이해

> 목적: 에이전트 평가를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: 에이전트의 작업 성공률, 도구 사용, 안전성, 비용, 지연을 측정하는 평가
- **왜 필요한가**: 에이전트는 답변만이 아니라 실제 행동을 수행하므로 정답률만으로 품질을 판단할 수 없음.
- **핵심 직관**: 에이전트 평가는 “말을 잘했는가”가 아니라 “업무를 안전하게 끝냈는가”를 보는 것임.

## 깊이 이해
- **배경·문제의식**: LLM 평가는 유창성·정확성 중심이지만 Agent는 계획, 도구 선택, 실행 결과, 정책 준수까지 봐야 함.
- **작동 원리**: 테스트 태스크를 구성하고 성공률, 단계 수, 도구 오류, 정책 위반, 비용, 지연시간을 자동·사람 평가로 측정함.
- **비유**: 운전면허 평가가 교통법규, 경로, 주차, 사고 여부까지 함께 보는 것과 같음.
- **구체 예시**: 고객 티켓 처리 Agent를 100개 시나리오로 평가해 해결률, 잘못된 Tool 호출, 평균 토큰 비용을 측정함.
- **흔한 오해·주의점**: 모델 자체 점수만 높아도 도구 실패율이나 정책 위반률이 높으면 운영 배포가 불가함.

## 연결 개념
- LLM-as-a-Judge — 자동 평가자
- Continuous Evaluation — 운영 중 지속 평가
- Agent Observability — 평가 데이터 수집

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Agent Evaluation은 에이전트의 계획, 도구사용, 업무성공, 안전성, 비용을 종합 측정하는 평가 체계임.
> 2. **가치**: 운영 배포 전 결함을 발견하고 배포 후 성능 저하·정책 위반을 조기 탐지함.
> 3. **판단 포인트**: 정답률보다 task success, policy violation, tool error, cost, latency를 함께 봐야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| AI 에이전트 품질 평가 체계 이해 | task success rate, policy violation rate, tool error rate, cost/task, p95 latency | 정답률(accuracy)만 언급하면 감점 — 행동·안전·비용 포함 필수 |
| 배포 판단 기준 설계 역량 | 배포 전 기준 미달 차단, 운영 중 샘플링·회귀 테스트 | 모델 점수만 높아도 정책 위반률이 높으면 배포 불가 |

> 요약: 출제자는 Agent 평가를 정답률이 아닌 다차원 지표(성공·위반·비용·지연)로 설계하는 역량을 확인하려 함.

---

## Ⅰ. 개요 및 필요성

- 정의: 에이전트의 업무 성공·도구 사용·안전성·비용을 종합 측정하는 평가 체계
- 배경: Agent는 답변뿐 아니라 도구 실행·업무 완료를 수행하므로 LLM 정답률만으로 판단 불가
- 필요성: 운영 배포 전 결함 발견, 배포 후 성능 저하·정책 위반 조기 탐지에 다차원 평가 필수

---

## Ⅱ. 구조 및 구성요소

```text
Test Tasks -> Agent Run -> Trace Collection -> Scoring
                 |                |                |
                 +-> 실행결과       +-> 도구/로그      +-> 지표 산출
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Test Set | 평가 시나리오 | 정상·예외·공격 케이스 |
| Trace | 실행 경로 기록 | 단계, 도구, 비용 |
| Metric | 평가 지표 | 성공률, 위반률, 지연 |
| Judge | 자동·사람 평가 | 기준표·샘플링 필요 |

> 요약: 에이전트 평가는 테스트셋, 실행추적, 지표, 평가자로 구성됨.

---

## Ⅲ. 동작원리 및 흐름도

```text
시나리오 준비 -> Agent 실행 -> Trace 수집 -> 지표 산출
        -> 실패 분석 -> 개선 -> 재평가
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 평가셋 구성 | 정상, 예외, 보안 케이스 |
| 2 | 실행·로그 수집 | Trace ID, tool call |
| 3 | 지표 산출 | 성공률, 위반률, p95 지연 |
| 4 | 개선·회귀평가 | 기준 통과, 재발 방지 |

> 요약: Agent 평가는 실행 흔적을 지표화하고 실패 원인을 개선 후 재평가하는 반복 과정임.

---

## Ⅳ. 특징

| 구분 | LLM 평가 | Agent 평가 | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 대상 | 답변 품질 | 업무 완료·도구 실행 | task success rate |
| 위험 | 환각·편향 | 권한 위반·오작동 | policy violation rate |
| 비용 | 토큰 중심 | 토큰+도구+지연 | cost/task, p95 latency |

> 요약: Agent 평가는 답변보다 실행 결과와 정책 준수를 중심으로 판단함.

---

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | LLM 평가 | Agent 평가 | 선택 기준 |
|:---|:---|:---|:---|
| 평가 대상 | 답변 유창성·정확성 | 업무 완료·도구 실행·정책 준수 | 도구 호출 여부 |
| 위험 차원 | 환각·편향 | 환각+권한 위반·오작동·과다 비용 | 실행 영향 범위 |
| 비용 지표 | 토큰 비용 중심 | 토큰+도구 호출+외부 API+지연 통합 | 총 cost/task |

> 요약: Agent 평가는 답변 품질에 도구 실행·정책 준수·비용을 더한 다차원 평가임.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 평가셋 편향 | 정상 케이스만 구성 | 정상 60%, 예외 25%, 보안·권한 15% 비율 유지 | 케이스 유형별 커버리지 |
| 운영 성능 저하 | 모델·데이터 변화 | 1일 단위 샘플링 평가, 회귀 테스트 자동화 | 주간 성공률 추이 |
| 과적합 배포 | 평가셋 암기·과적합 | 평가셋 주기적 갱신, 실 운영 로그 기반 신규 케이스 추가 | 평가셋 갱신 주기 |

> 요약: 평가셋 편향·운영 저하·과적합이 핵심 리스크이며 비율 관리·샘플링·갱신으로 통제함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| task success rate | 배포 기준 90% 이상 | 평가셋 실행 결과 자동 산출 |
| policy violation rate | 허용 기준 1% 이내 | Trace 기반 정책 위반 탐지 |
| cost/task | 업무별 예산 한도 이내 | 토큰+도구+API 비용 합산 |

> 요약: 성공률·위반률·비용을 배포 게이트 기준으로 관리하고 미달 시 배포를 차단함.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 정상 60%, 예외 25%, 보안·권한 15% 비율로 평가 시나리오를 구성
2. task success rate, tool error rate, policy violation rate, cost/task, p95 latency를 기준 지표로 운영
3. 배포 전 기준 미달 시 차단하고 운영 중 1일 단위 샘플링 평가와 회귀 테스트를 수행

**결론 (2줄):**
- 기술사 판단: Agent는 정답률만 통과해도 정책 위반률이 허용 기준을 넘으면 배포하지 않음.
- 향후 방향: Agent Evaluation은 LLMOps와 결합해 자동 회귀평가와 지속 모니터링 체계로 발전함.
