## 미리 알고가기

- 모델 압축 ($Model$ $Compression$): 딥러닝 모델의 학습 완료 가중치 데이터 구조나 비트 정밀도를 깎아내어, 추론 속도를 높이고 VRAM 점유량과 파일 디스크 크기를 다듬는 최적화 가술군임
- 가지치기 ($Pruning$): 신경망의 가중치 중 중요도(가중치 값의 크기 등)가 극히 낮거나 영향력이 거의 없는 무의미한 시냅스 연결선(뉴런)을 잘라내어 연산 복잡도를 줄이는 기법임
- 양자화 ($Quantization$): 부동소수점 표현을 저정밀도의 정수형(FP16 $\rightarrow$ INT8/INT4 등)으로 다운그레이드하여 비트 수 비례로 메모리 대역폭 점유를 획기적으로 낮추는 기술임
- 지식 증류 ($Distillation$): 거대 모델의 지식을 가벼운 경량 모델에 전이 학습시켜 본래의 뇌 크기 자체를 작게 축소 설계하는 경량화 설계임

## Ⅰ. 개요

- **정의/개념**: Model Compression은 이미 훈련된 인공지능 신경망의 방대한 가중치 파라미터 구조와 비트 해상도를 기하학적으로 다듬고 감축하여, 모델이 소모하는 연산량(FLOPs)과 VRAM 크기를 수 분의 일 수준으로 압축하면서도 본래의 지능 수준(정밀도) 손실을 극적으로 통제하는 지능형 경량화 기술군임
- **배경/필요성**: 생성형 AI 모델 크기가 수천억 개 단위로 대형화함에 따라 단일 GPU 카드(보통 VRAM 80GB 규격) 스펙에 얹기조차 불가능해져, 고가의 물리 장비 증설 비용(TCO) 부담을 줄이고 스마트폰 등의 로컬 에지 디바이스 가동 한계선을 통과하기 위해 필수 도입됨

## Ⅱ. 특징

- 가지치기($Pruning$, 구조 감축), 양자화($Quantization$, 해상도 압축), 지식 증류($Distillation$, 모델 축소)의 3대 핵심 기법이 주축을 이룸
- 압축률을 비이성적으로 끌어올리면, 모델이 문맥을 이해하지 못하고 엉뚱한 대답을 내거나 아예 언어 체계가 깨지는 환각 및 성능 추락 현상이 발생함
- 압축된 텐서 연산을 GPU의 하드웨어 하부 커널과 런타임 엔진(vLLM, TensorRT 등)이 직접 기계어로 해석 및 가속화해 주어야 비로소 실질 응답 속도 단축으로 연결됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 가지치기 (Pruning) | 양자화 (Quantization) | 지식 증류 (Distillation) |
|:---|:---|:---|:---|
| **압축의 표적** | 무의미한 신경망 연결선, 채널 차원 | 텐서 데이터의 실수 표현 비트 수 | 학생 모델의 전반 파라미터 규모 자체 |
| **인프라 체감 혜택** | 연산량(FLOPs) 물리적 소거 | VRAM 용량의 즉각적 획기적 절감 | 작은 단말 기기로의 모델 이식성 확보 |
| **단점 및 주의점** | 압축 후 비정형 희소 행렬의 가속 난해 | 지나친 비트 다운 시 의미론적 오차 발생 | 교사 모델 가동 및 학생 훈련에 훈련 비용 수반 |
| **추가 훈련 요구** | 필수 (가치 상실 후 미세조정 필요) | 선택 (PTQ는 불필요, QAT는 요구됨) | 필수 (처음부터 다시 학습) |

> 요약: 가지치기는 뇌의 불필요한 뉴런을 솎아내고, 양자화는 숫자의 해상도를 깎아 가볍게 표기하며, 지식 증류는 우등생의 노트를 복사해 작은 머리에 이식함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 기저 정밀 모델 | 압축의 원형이자, 성능 손실 한계선을 규정하는 오리지널 기반 모델임 |
| 감축 스케줄러 | 양자화, 가지치기 등의 연산 노드를 텐서 그래프에 개입시키는 감축 장치임 |
| 보정 캘리브레이터 | 양자화 과정에서 튀는 가중치들의 범위를 스케일 스코어로 보정해 주는 필터임 |
| 가속 추론 엔진 | 압축된 저비트 텐서를 칩셋 하드웨어 명령어로 해독 가동하는 런타임부임 |

```text
[ 모델 압축 3대 축 통합 조합 전략 ]
[Original Teacher LLM] ---> (Knowledge Distillation) ---> [Student SLM]
                                                                │
[Quantized Target Model] <--- (Quantization) <--- (Pruning) <---/
- 세 가지 최적화 기술을 순차 조합하여, 모바일 기기에 최적인 극한의 경량 모델을 유도함
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 오리지널    | --> | 타겟 자원별  | --> | 텐서 그래프 | --> | 런타임 결합 |
| 프로파일링  |     | 압축기법 매칭|     | 재조정/보정 |     | 및 가성비 QA|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **지표 계측** — 원본 모델의 VRAM 크기와 1회 추론 속도, 정답률을 계측하여 감축 타깃(예: 용량 70% 절감 등)을 세움
2. **기술 조합** — 압축을 배포할 장비 사양에 맞추어, 구조를 자르는 가지치기와 비트를 낮추는 양자화 중 적합한 기법을 믹스함
3. **그래프 재합성** — 텐서 그래프를 파싱하여 불필요한 시냅스를 지우고, 가중치 행렬 값을 $FP8$ 정밀도로 스케일링하는 컴파일 보정을 가동함
4. **런타임 서빙** — 가벼워진 압축 아티팩트를 vLLM이나 TensorRT-LLM에 탑재하고, 최종 정답 성공율과 실질 응답 속도 상승률을 검증함

## Ⅵ. 실무 적용 및 유의점

1. 단순 파일 용량 감소만을 맹신하여 압축을 가했으나, 런타임 엔진이 해당 비트(예: INT4) 가속 연산을 하드웨어적으로 지원하지 못하면 오히려 형변환 오버헤드로 추론 속도가 더 느려지므로, 반드시 대상 GPU/NPU 가속 칩의 하드웨어 호환성 목록을 대조하고, 실제 추론 속도($Tokens/Sec$) 개선 지표를 직접 실측해야 함
2. 압축 완료 후 단순 정답셋 평가에서는 100% 성능이 나오는 것처럼 보이나, 실 서비스 운영 중 긴 꼬리 입력이나 예외 질문(Edge Cases)이 들어왔을 때 오작동율이 폭증할 수 있으므로, 반드시 고도화된 사내 비즈니스 도메인 회귀 테스트셋($Regression$ $Test$)을 구축하고 성능 퇴보 여부를 감시해야 함

## Ⅶ. 결론

- 모델 압축은 초거대 인공지능의 물리적 장벽을 낮추어 비즈니스 현실 세계로 수용하는 인프라 최적화의 필수 과정이며, 설계자는 런타임 엔진의 하드웨어 가속 적합성 판정과 미세한 압축 오차에 따른 예외 지능 붕괴(Hallucination) 방지책을 반드시 통합 배포하여 정밀성을 완성해야 함
