## 미리 알고가기

- 모델 압축은 저장 크기, 메모리 사용량, 연산량을 줄여 배포성을 높이는 최적화 계열임
- 대표 기법은 pruning, quantization, distillation이며 목적과 효과가 서로 다름
- 파일 크기 감소가 곧바로 응답 속도 향상을 뜻하지는 않으므로 런타임 기준 검증이 필요함

## Ⅰ. 개요

- **정의/개념**: 모델 압축은 학습된 AI 모델의 크기와 연산 비용을 줄이면서 업무 성능 손실을 허용 범위 안에 묶어 배포 가능성을 높이는 최적화 기술군임
- **배경/필요성**: 대형 모델은 저장 공간과 VRAM과 전력 비용이 커서 모바일과 엣지와 온프레미스 환경에 그대로 탑재하기 어려우므로, 서비스 제약에 맞춘 경량화가 필요함

## Ⅱ. 특징

- 저장 크기와 메모리 점유와 연산량 중 어떤 자원을 줄일지 먼저 정해야 적절한 기법 선택이 가능함
- pruning, quantization, distillation은 상호 대체가 아니라 조합 가능한 설계 옵션임
- 압축률을 높일수록 정확도와 안정성과 일반화 성능이 흔들릴 수 있어 품질 검증이 필수임
- 실제 효과는 하드웨어와 런타임이 압축 구조를 얼마나 잘 활용하느냐에 따라 달라짐

## Ⅲ. 종류 및 비교

| 판단 기준 | Pruning | Quantization | Distillation |
|:---|:---|:---|:---|
| 줄이는 대상 | 연결이나 구조 | 수치 정밀도 | 모델 규모 자체 |
| 대표 장점 | FLOPs 감소 가능 | 메모리 절감 효과 큼 | 작은 모델의 품질 확보 |
| 대표 한계 | 하드웨어 활용 난도 높음 | 과도한 압축 시 품질 저하 | 교사 모델 학습 비용 큼 |
| 활용 위치 | 구조 최적화 | 배포 최적화 | 모델 설계 단계 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Baseline Model | 압축 전 성능 기준점을 제공해 허용 가능한 손실 범위를 판단하게 함 |
| Compression Technique | pruning, quantization, distillation 중 목표 자원에 맞는 감축 수단을 선택함 |
| Calibration, Fine-tuning | 압축으로 손상된 품질을 복구하고 도메인 정확도를 다시 맞추는 역할을 수행함 |
| Runtime Engine | vLLM, TensorRT, Core ML 같은 실행 계층이 압축 결과를 실제 속도 향상으로 연결함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 기준 모델 측정  | --> | 압축 기법 선택  | --> | 압축/보정 수행  | --> | 배포 및 성능 검증 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **기준 모델 측정**: 정확도와 메모리와 지연 시간을 측정해 압축 목표를 정함
2. **압축 기법 선택**: 줄일 자원과 목표 환경에 맞춰 기법을 선택하거나 조합함
3. **압축 및 보정 수행**: 구조 축소나 정밀도 축소 후 calibration과 재학습으로 품질을 보정함
4. **배포 및 성능 검증**: 실제 런타임에서 비용 절감과 품질 유지 여부를 확인함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 압축률만 보고 의사결정하면 실제 장비에서 기대한 속도 향상이나 비용 절감이 나오지 않을 수 있음
   - 해결방안: 파일 크기 대신 end-to-end latency와 cost per inference를 기준으로 압축 효과를 검증함
2. 문제: 긴 꼬리 입력이나 희귀 도메인에서는 압축 후 품질 저하가 숨겨져 있다가 운영 단계에서 크게 드러날 수 있음
   - 해결방안: 업무 데이터셋 기반 회귀 테스트를 운영하고 tail-case accuracy와 hallucination rate로 품질을 검증함
3. 문제: 환경별로 다른 압축 모델이 늘어나면 버전 관리와 재배포 복잡도가 커질 수 있음
   - 해결방안: 모델 카탈로그와 배포 정책을 표준화하고 variant sprawl과 rollback success rate로 운영 수준을 검증함

## Ⅶ. 적용 사례

- 모바일 AI 기능이 양자화와 증류를 통해 모델을 기기 내에 탑재하도록 압축을 적용하며 확인 지표는 memory footprint와 battery impact임
- 사내 추론 서버가 GPU 메모리 제약에 맞춘 압축 모델로 비용을 줄이도록 운영하며 확인 지표는 cost per token과 GPU utilization임
- 산업 현장 비전 추론이 구조 축소와 런타임 최적화를 함께 사용하도록 압축을 적용하며 확인 지표는 FPS와 edge device temperature임

## Ⅷ. 결론

모델 압축의 핵심은 모델을 작게 만드는 데 있지 않고 목표 하드웨어와 업무 품질 기준 안에서 배포 가능성과 총비용을 함께 최적화하는 데 있음.
