# 📖 【암기용】 개념 완전 이해

> 목적: 복잡한 모델 병렬화 없이도 거대 모델을 학습시킬 수 있게 해준 마이크로소프트의 마법 같은 메모리 절약 기술 'ZeRO'를 이해한다.

## 한눈에
- **정의**: 데이터 병렬화(DP)를 할 때, 모든 GPU가 옵티마이저 상태, 기울기, 가중치를 똑같이 중복으로 저장하는 **'비효율적인 메모리 낭비(Redundancy)'를 제로(0)로 없애는 메모리 최적화 기술**
- **필요성**: 기존에는 1,000억 파라미터 모델을 학습시키려면 복잡하고 구현하기 힘든 텐서 병렬화(TP)와 파이프라인 병렬화(PP)를 억지로 써야 했으나, ZeRO를 쓰면 그저 데이터 병렬화(DP)만으로도 거대 모델을 쉽게 학습시킬 수 있기 때문
- **핵심 직관**: "조별 과제를 할 때, 4명이 똑같은 백과사전을 각자 1권씩 무겁게 가방에 들고 다니는 대신(기존 DP), 백과사전을 4등분으로 찢어서 각자 1/4씩만 들고 다니다가 필요할 때만 옆 사람에게 잠깐 빌려보는 방식(ZeRO)"

## 깊이 이해
- **배경(왜 등장했나?)**: 데이터 병렬화(DP)는 구현이 쉽고 통신 효율이 좋다. 하지만 GPU 100대를 써도, 100대의 GPU 메모리 안에는 똑같은 AI 모델(복사본)이 중복해서 들어있다. 마이크로소프트 연구진은 "이 중복을 없애면, GPU 1대당 메모리가 엄청나게 비워질 테니, 남는 공간에 훨씬 거대한 모델을 올릴 수 있지 않을까?"라고 생각했다.
- **작동 원리(어떻게 달성했나?)**: 모델을 학습할 때 메모리를 잡아먹는 3대장(옵티마이저 상태, 기울기, 가중치 파라미터)을 하나씩 쪼개어 GPU들에게 나눠준다.
  - **ZeRO Stage 1**: 가장 뚱뚱한 **'옵티마이저(Optimizer) 상태'**를 쪼개서 N대의 GPU가 나눠 가진다. (메모리 4배 절약)
  - **ZeRO Stage 2**: 이번엔 **'기울기(Gradient)'**도 쪼개서 나눠 가진다. (메모리 8배 절약)
  - **ZeRO Stage 3**: 끝판왕. 아예 모델 **'가중치(Parameter)'**까지 쪼개서 나눠 가진다. 연산할 때만 잠깐 전체 파라미터를 모았다가, 끝나면 다시 쪼개어 버린다. (메모리가 GPU 대수 $N$만큼 무한정 절약됨)
- **일상 비유**: 게임(모델)을 실행할 때, 예전에는 컴퓨터(GPU)마다 전체 게임 100GB를 다 깔아야 했다. ZeRO-3는 전체 게임 용량을 10대의 컴퓨터가 10GB씩 나눠서 깔고, 게임을 플레이할 때(순전파/역전파) 필요한 맵 데이터만 실시간으로 인터넷(네트워크)을 통해 불러왔다가 지우는 클라우드 게이밍 방식이다.
- **구체 예시**: 마이크로소프트의 **DeepSpeed** 라이브러리가 ZeRO 알고리즘을 구현한 핵심 도구다. 이를 통해 기존에는 텐서 병렬화(TP) 없이는 꿈도 못 꿨던 조 단위 파라미터 모델 훈련이 가능해졌다.
- **흔한 오해/주의점**: "ZeRO Stage 3를 쓰면 메모리가 완벽히 절약되니 무조건 좋은가?" → 아니다. 파라미터를 계속 조각내어 저장하고, 연산할 때마다 다시 모아오는 과정(All-Gather)이 추가되므로 **통신 트래픽이 기존보다 1.5배 증가**한다. 메모리를 아낀 대가로 네트워크 대역폭을 희생하는 셈이다.

## 연결 개념
- **Data Parallelism (데이터 병렬화)**: ZeRO는 근본적으로 DP의 진화형이다. (모델 병렬화가 아님)
- **DeepSpeed**: ZeRO 최적화 기술을 손쉽게 사용할 수 있게 해주는 마이크로소프트의 오픈소스 라이브러리
- **Memory Wall (메모리 장벽)**: 옵티마이저(Adam 등)가 차지하는 막대한 메모리 때문에 발생하는 한계로, ZeRO가 타파하고자 한 핵심 타겟

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: ZeRO(Zero Redundancy Optimizer)는 데이터 병렬화(DP) 훈련 시 각 워커가 중복 보유하는 모델 상태(옵티마이저, 기울기, 파라미터)를 상호 배타적으로 분산 저장하는 메모리 최적화 기법이다.
> 2. **가치**: 복잡한 모델 병렬화(TP, PP) 없이도 단일 GPU 메모리를 초과하는 거대 모델을 학습할 수 있게 하며, GPU 워커 수($N$)에 비례하여 선형적인 메모리 확장을 제공한다.
> 3. **판단 포인트**: 메모리 낭비를 완전히 제거하는 Stage 3 적용 시, 추가적인 All-Gather 통신 오버헤드가 발생하므로 클러스터망의 네트워크 대역폭(Bandwidth)과 VRAM 용량 간의 트레이드오프 설계가 필수적이다.

## Ⅰ. 개요 및 필요성
- **정의**: 분산 데이터 병렬화(DDP) 환경에서 메모리 병목을 유발하는 3대 요소(옵티마이저 상태, 그레이디언트, 파라미터)를 여러 GPU에 분할(Partitioning)하여 저장하는 최적화 알고리즘
- **배경**: 파라미터가 100억 개일 때, Adam 옵티마이저 상태(Momentum, Variance 등)만 최소 120GB를 차지하여 80GB GPU에 적재 자체가 불가능 (Optimizer Memory Bottleneck)
- **필요성**: 기존 모델 병렬화(Model Parallelism)의 극심한 통신 및 구현 복잡도 회피, 통신 효율성이 좋은 데이터 병렬화의 장점을 거대 언어 모델(LLM) 환경까지 연장할 필요성

## Ⅱ. 딥러닝 메모리 점유 구조와 ZeRO의 타겟
기존 DDP 환경에서 모델 상태(Model States)는 다음과 같이 막대한 메모리를 차지하며, 모든 GPU가 이를 100% 중복으로 들고 있었다. ($P$ = 모델 파라미터 크기)

1. **Parameters (가중치)**: $2P$ (FP16 기준)
2. **Gradients (기울기)**: $2P$ (FP16 기준)
3. **Optimizer States (옵티마이저 상태)**: $12P$ (Adam 옵티마이저 FP32 기준)
   - 즉, 모델 크기의 약 8배 이상 메모리가 '모델의 상태 유지'에만 소비됨. 이 중복 저장을 없애는 것이 ZeRO의 목표.

## Ⅲ. ZeRO의 3단계 최적화 메커니즘 (Stage 1~3)
ZeRO는 메모리 절감 수준에 따라 총 3단계(Stage)로 나뉜다. (전체 GPU 수를 $N$이라 가정)

| Stage 분류 | 분할 대상 (Partitioning) | 메모리 절감 효과 | 통신 오버헤드 특성 |
|:---|:---|:---|:---|
| **ZeRO-1** | **Optimizer States**만 분할 저장 | 약 **4배** 절감 ($12P/N$) | 통신 오버헤드 **증가 없음** (기존 DDP와 동일) |
| **ZeRO-2** | Optimizer + **Gradients** 분할 | 약 **8배** 절감 ($14P/N$) | 통신 오버헤드 **증가 없음** (Reduce-Scatter 최적화) |
| **ZeRO-3** | Opt + Grad + **Parameters** 분할 | **$N$배 절감** (GPU 수에 비례) | **통신 오버헤드 약 1.5배 증가** (Forward/Backward 시 Parameter를 All-Gather 해야 함) |

## Ⅳ. ZeRO Stage 3 동작 시퀀스 (파라미터 파티셔닝 원리)
Stage 3에서는 각 GPU가 자신이 맡은 전체 모델의 일부분(예: $\frac{1}{N}$)에 해당하는 파라미터만 메모리에 상주시킨다.

1. **Forward Pass (순전파)**:
   - GPU 0이 특정 레이어 연산을 할 때 파라미터가 부족하므로, 다른 GPU들에게 파라미터를 요청함 (**All-Gather**).
   - 계산이 끝나면 즉시 자신의 것이 아닌 파라미터를 메모리에서 **삭제(Discard)**함.
2. **Backward Pass (역전파)**:
   - 다시 한번 파라미터를 모아옴 (**All-Gather**).
   - 역전파 계산이 끝나고 기울기(Gradient)가 산출되면, 이를 해당 파라미터 소유자에게 전송함 (**Reduce-Scatter**).
3. **Update (가중치 갱신)**:
   - 각 GPU는 자신이 소유한 $\frac{1}{N}$의 옵티마이저와 파라미터만 독립적으로 업데이트함.

## Ⅴ. 기술적 한계(리스크) 및 대응 방안
| 리스크 요인 | 발생 원인 | 대응 방안 (엔지니어링 관점) |
|:---|:---|:---|
| **통신 대역폭 포화** | ZeRO-3 적용 시 파라미터를 매번 모으고 지우는 All-Gather 통신이 극심하게 발생 | 네트워크가 느린 클러스터에서는 **ZeRO-2** 까지만 적용하거나, NVLink 기반 고속망 구축 |
| **CPU 메모리 오버헤드** | GPU 메모리(VRAM)조차 부족한 수백억 파라미터 모델의 경우 ZeRO-3로도 OOM 발생 | **ZeRO-Offload (ZeRO-Infinity)** 도입: 옵티마이저 상태 연산을 Host CPU나 NVMe SSD로 오프로드(Offload)하여 VRAM 절약 |
| **작은 모델에서의 비효율**| 모델 사이즈가 작을 때 ZeRO-3를 쓰면 통신 오버헤드가 메모리 절약 이점을 압도함 | 모델 크기와 GPU 스펙을 고려하여 적정 Stage(1~3)를 동적으로 스위칭하는 휴리스틱 로직 구현 |

## Ⅵ. 실무 적용 및 결론
**적용 방안 및 실무 가이드:**
1. **LLM 파인튜닝 (LoRA 연계)**: 수백억 파라미터의 오픈소스 LLM(Llama 3 등)을 소규모 GPU(예: 24GB VRAM 4장) 환경에서 파인튜닝할 때, DeepSpeed ZeRO-2와 LoRA 기법을 결합하면 텐서 병렬화 튜닝 없이 곧바로 학습이 가능하다.
2. **클러스터 훈련 전략 수립**: 거대 언어 모델 사전학습(Pre-training) 초기에는 Megatron-LM(TP/PP) 아키텍처에 ZeRO-1을 결합하여 통신 병목을 없애는 것이 정석이다. 모델이 너무 커져 3D 병렬화로도 VRAM이 부족할 때 비로소 ZeRO-3을 도입한다.

**결론:**
- ZeRO Optimizer는 데이터 병렬화(DP)의 치명적 단점인 '메모리 중복'이라는 소프트웨어적 비효율성을 극도로 쥐어짜 낸 **메모리 최적화의 혁명**이다.
- 개발자에게 복잡한 모델 파티셔닝의 고통을 덜어주어 AI의 민주화(Democratization)를 앞당겼으며, Microsoft DeepSpeed를 전 세계 분산 학습 프레임워크의 표준(De-facto)으로 자리매김하게 만들었다.
