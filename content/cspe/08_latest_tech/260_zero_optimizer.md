# 📖 【암기용】 개념 완전 이해

> 목적: ZeRO를 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 데이터 병렬화(Data Parallelism) 환경에서 각 GPU가 모델 가중치와 옵티마이저 상태를 중복해서 갖지 않고, 여러 GPU에 나누어(Sharding) 저장함으로써 메모리 낭비를 없애는 기술
- **왜 필요한가**: 일반적인 데이터 병렬화는 모든 GPU가 똑같은 모델을 통째로 갖고 있어야 한다. 모델이 커지면 모델 자체만으로도 메모리가 꽉 차서 정작 학습할 데이터(Batch)를 담을 공간이 없어지기 때문이다.
- **핵심 직관**: "모든 학생(GPU)이 전집(모델) 전체를 다 사는 대신, 한 권씩만 나눠서 사고 공부할 때만 서로 빌려보는 방식"

## 깊이 이해
- **배경·문제의식**: 딥러닝 학습 시 메모리를 가장 많이 잡아먹는 것은 모델 가중치뿐만이 아니다. 옵티마이저 상태(Optimizer States), 기울기(Gradients) 등이 가중치보다 몇 배나 더 많은 메모리를 쓴다(예: Adam 옵티마이저는 가중치의 4~8배 메모리 소요). 이를 모든 GPU가 중복해서 갖는 것은 엄청난 낭비다.
- **작동 원리**: ZeRO는 세 단계로 메모리 낭비를 제거한다.
  - **Stage 1**: 옵티마이저 상태만 여러 GPU에 나누어 저장한다.
  - **Stage 2**: 기울기(Gradient)까지 나누어 저장한다.
  - **Stage 3**: 모델 가중치(Parameter) 자체도 나누어 저장한다. 연산할 때만 통신을 통해 필요한 가중치를 잠시 가져온다.
  - **ZeRO-Offload**: GPU 메모리가 부족하면 남는 CPU 메모리나 NVMe 스토리지까지 활용한다.
- **비유**: 100명이 요리하는데 각자 양념통 세트를 다 갖는 게 아니라, 누구는 간장, 누구는 설탕만 갖고 있다가 필요할 때만 서로 건네주며 요리하는 것과 같다.
- **구체 예시**: Microsoft의 DeepSpeed 라이브러리에 탑재되어 유명해졌다. 100B 모델을 학습할 때, ZeRO 3단계를 쓰면 단일 GPU 메모리 점유율을 1/N로 줄여 훨씬 큰 배치를 학습할 수 있다.
- **흔한 오해·주의점**: "메모리를 아끼니 무조건 좋다"는 아니다. 가중치를 서로 빌려오는 과정에서 **통신 비용**이 발생한다. 다행히 ZeRO는 통신 알고리즘을 아주 효율적으로 설계하여(All-Gather 등), 일반 데이터 병렬화와 통신량 차이가 거의 없도록 만들었다.

## 연결 개념
- Data Parallelism — ZeRO가 기반으로 하는 병렬화 방식
- DeepSpeed — ZeRO를 처음 구현하고 대중화시킨 오픈소스 라이브러리
- FSDP (Fully Sharded Data Parallel) — PyTorch에서 구현한 ZeRO Stage 3와 유사한 기술

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: ZeRO는 메모리 중복(Redundancy) 제거 단계(Stage 1~3)와 그에 따른 통신 오버헤드 관리 메커니즘을 중심으로 기술한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: ZeRO(Zero Redundancy Optimizer)는 분산 학습 환경에서 모델 파라미터, 기울기, 옵티마이저 상태를 중복 없이 각 GPU에 분할(Sharding) 적재하는 메모리 최적화 기법이다.
> 2. **가치**: 데이터 병렬화의 연산 효율을 유지하면서도 모델 병렬화 수준의 메모리 절감 효과를 제공하여, 초거대 모델 학습의 진입 장벽을 낮춘다.
> 3. **판단 포인트**: 모델 크기 및 가용한 네트워크 대역폭에 따라 단계별(Stage 1, 2, 3) 적용 범위를 결정하고, 필요시 CPU Offload 기술을 병행한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 분산 학습 메모리 병목 이해도 | Optimizer States, Gradients, Parameters 중복 제거 | 단순히 "메모리를 아낀다"고만 서술 |
| ZeRO 단계별(Stage 1~3) 특징 파악 | 각 단계별 절감 대상 및 잔여 메모리 계산 | 단계별 차이점 혼동 및 중복 설명 |
| 오프로딩 및 통신 최적화 원리 인지 | ZeRO-Offload, ZeRO-Infinity, 통신량 분석 | 통신 비용(Communication Cost) 분석 누락 |

> 요약: 메모리 점유의 주범(Optimizer States 등)을 식별하고, 이를 샤딩하여 해결하는 3단계 발전 과정을 수치와 함께 기술한다.

## Ⅰ. 개요 및 필요성

- 정의: 데이터 병렬화 환경에서 발생하는 연산 노드 간의 데이터 중복을 제거하여 GPU 메모리 효율을 극대화한 최적화 알고리즘
- 배경: Adam 등 현대적 옵티마이저 사용 시 상태값(Momentum 등)이 가중치 대비 8배 이상의 메모리를 점유하는 현상 발생
- 필요성: 모델 병렬화 없이도 거대 모델 학습이 가능하도록 지원하여 시스템 복잡도 감소 및 대규모 배치 학습 구현

---

## Ⅱ. 구조 및 구성요소

```text
[ZeRO 단계별 메모리 점유 구조]
Standard DP: [Param][Grad][Opt] x N (All Nodes)
ZeRO-S1:    [Param][Grad] x N + [Opt/N]
ZeRO-S2:    [Param] x N + [Grad/N] + [Opt/N]
ZeRO-S3:    [Param/N] + [Grad/N] + [Opt/N]
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Optimizer State Sharding | Adam의 momentum, variance 등을 분산 저장 | Stage 1, 전체 메모리 4배 절감 효과 |
| Gradient Sharding | 연산 후 발생하는 기울기 값을 분산 저장 | Stage 2, 전체 메모리 8배 절감 효과 |
| Parameter Sharding | 모델 가중치 자체를 분산 저장 | Stage 3, GPU 수(N)에 비례하여 메모리 절감 |
| ZeRO-Offload | 일부 데이터를 CPU RAM 또는 NVMe로 이동 | 연산 장치 메모리 한계 초과 시 활용 |

> 요약: 모델 학습에 필요한 세 가지 요소(가중치, 기울기, 상태값)를 단계별로 쪼개어 중복을 제거하는 구조다.

---

## Ⅲ. 동작원리 및 흐름도

```text
[ZeRO Stage 3 기준 연산 흐름]
1. Forward: 필요한 가중치 조각을 통신(All-Gather)으로 수집 -> 연산 -> 사용 후 삭제
2. Backward: 필요한 가중치 수집 -> 기울기 계산 -> 기울기 조각만 전송(Reduce-Scatter) -> 가중치 삭제
3. Update: 각 GPU가 자기가 가진 조각만 업데이트 (통신 불필요)
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 학습 시작 전 전체 데이터를 N개의 GPU에 균등 분할 배정 | 메모리 사용량 균형도 |
| 2 | 순전파(Forward) 시 타 노드로부터 파라미터 수집(All-Gather) | 통신 대역폭 활용률 |
| 3 | 역전파(Backward) 후 기울기를 샤딩하여 통합(Reduce-Scatter) | 통신량은 일반 DP와 동일(2x) |
| 4 | 분산된 옵티마이저 상태값으로 담당 구역 가중치 갱신 | 각 GPU의 메모리 해제 속도 |

> 요약: 연산 시에만 필요한 데이터를 빌려오고(Broadcast/Gather), 연산이 끝나면 즉시 삭제하여 메모리 유휴 공간을 확보한다.

## Ⅳ. 특징

| 구분 | 일반 데이터 병렬 (DP) | ZeRO Stage 3 (DeepSpeed) |
|:---|:---|:---|:---|
| 메모리 효율 | 낮음 (O(M) 모델 크기 종속) | 매우 높음 (O(M/N) 장치 수 반비례) |
| 통신량 | 1 (All-Reduce 기준) | 약 1.5 (추가적인 All-Gather 발생) |
| 구현 복잡도 | 낮음 | 중간 (DeepSpeed/FSDP 래퍼 필요) |
| 가능 모델 크기 | 수십억(B) 단위 한계 | 수천억~조 단위 가능 |

> 요약: 메모리 효율성은 획기적으로 향상되나, 약간의 통신 오버헤드가 발생하므로 네트워크 성능이 뒷받침되어야 한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 모델 병렬화 (MP) | ZeRO Optimizer | 선택 기준 |
|:---|:---|:---|:---|
| 통신 부하 | 매우 높음 (계층마다 발생) | 상대적 낮음 (DP 수준) | 네트워크 인터커넥트 속도 |
| 프로그래밍 | 수동 분할 설계 필수 (복잡) | 자동 분할 처리 (간편) | 개발 생산성 및 모델 구조 특성 |
| 메모리 절감 | 가중치만 분할 | 상태값, 기울기 포함 전체 분할 | 메모리 부족 병목 지점 |

> 요약: 모델 구조가 단순하고 범용적인 확장이 필요하다면 ZeRO를, 극단적인 저지연 연산이 필요하다면 MP를 선택한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 통신 지연 | 잦은 가중치 수집에 따른 오버헤드 | 통신-연산 오버랩(Prefetching) 기술 적용 | Communication Overhead Ratio |
| CPU 병목 | ZeRO-Offload 사용 시 PCI-E 대역폭 한계 | 가중치 핀닝(Pinning) 및 최적 스케줄링 | CPU-GPU Data Transfer Rate |
| 수렴 불안정 | 분산 업데이트 시의 수치적 미세 차이 | All-Reduce 정밀도 관리 및 버킷팅 | Loss Curve Consistency |

> 요약: 통신 지연 리스크는 데이터 프리페칭(Prefetching)으로, CPU 병목은 전용 오프로드 엔진으로 대응한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 메모리 절감율 | 이론치(1/N)의 80% 이상 달성 | `nvidia-smi` 및 DeepSpeed Profiler |
| 처리량 유지율 | 일반 DP 대비 90% 이상의 속도 유지 | Tokens per Second 비교 |
| 확장 효율 | GPU 1024개 확장 시 효율 80% 이상 | Multi-node Scaling Benchmarks |

> 요약: 메모리 절감 효과와 실제 연산 속도 저하 정도를 비교하여 도입의 타당성을 검증한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 초거대 모델 학습: Llama-3-70B 등을 8개 GPU 노드에서 학습할 때 ZeRO Stage 3를 적용하여 모델 적재 및 대규모 배치 학습 동시 달성
2. 저사양 인프라 활용: GPU 메모리가 부족한 구형 장비(V100 32GB 등)에서 ZeRO-Offload를 통해 대형 모델 파인튜닝 수행
3. FSDP 전환: PyTorch 환경에서 ZeRO의 발전형인 FSDP를 도입하여 표준 라이브러리 기반의 유지보수성 확보

**결론 (2줄):**
- 기술사 판단: ZeRO는 '데이터 병렬화의 메모리 혁명'이며, 모델 병렬화의 복잡성 없이도 거대 모델을 다룰 수 있게 한 실질적인 LLM 대중화 공신이다
- 향후 방향: NVMe 스토리지까지 직접 활용하는 ZeRO-Infinity 기술과 결합하여, 단일 워크스테이션에서도 조 단위 모델을 다루는 방향으로 진화할 것이다
