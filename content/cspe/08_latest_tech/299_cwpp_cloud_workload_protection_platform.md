# 📖 【암기용】 개념 완전 이해

> 목적: CWPP를 클라우드에서 실행되는 VM, 컨테이너, 서버리스 등 워크로드 자체를 취약점과 런타임 위협으로부터 보호하는 플랫폼으로 이해하게 만든다.

## 한눈에
- **개요**: 클라우드 워크로드의 취약점, 구성, 런타임 행위를 보호하는 보안 플랫폼
- **왜 필요한가**: 클라우드에서는 VM, 컨테이너, Kubernetes, serverless가 수시로 생성·삭제되어 서버 보안 도구만으로 실행 중 위험을 추적하기 어렵다.
- **핵심 직관**: 건물 외벽 점검(CSPM)과 별도로 각 방 안의 사람, 장비, 행동을 감시하는 보안 체계다.

## 깊이 이해
- **배경·문제의식**: 클라우드 자산 설정이 맞아도 컨테이너 이미지에 critical CVE가 있거나 런타임에서 의심 프로세스가 실행되면 침해가 발생할 수 있다.
- **작동 원리**: 에이전트 또는 에이전트리스 방식으로 워크로드 인벤토리, 이미지 취약점, 파일 무결성, 프로세스·네트워크 행위를 수집해 정책 위반을 탐지한다.
- **비유**: 건물 출입 통제와 별도로 서버실 내부 장비가 승인되지 않은 명령을 실행하는지 보는 것과 같다.
- **구체 예시**: 컨테이너 이미지의 Log4j 취약점을 배포 전 탐지하고, 운영 중 쉘 실행·이상 outbound 연결을 런타임 정책으로 차단한다.
- **흔한 오해·주의점**: CWPP는 클라우드 설정 관리가 중심인 CSPM과 다르다. 실행 중인 워크로드 내부와 행위 보호가 핵심이다.

## 연결 개념
- CSPM — 클라우드 계정·설정 보안 형상관리
- CNAPP — CWPP를 포함하는 통합 보호 플랫폼
- Container Security — 이미지·런타임·Kubernetes 보호 영역

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.
> 핵심: CWPP는 클라우드 인프라 설정이 아니라 VM·컨테이너·serverless 워크로드의 취약점과 런타임 행위를 보호한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: CWPP는 클라우드 워크로드의 취약점, 무결성, 프로세스, 네트워크, 런타임 위협을 보호하는 플랫폼임.
> 2. **가치**: VM·컨테이너·serverless가 멀티클라우드에서 이동해도 워크로드 단위 보안 정책과 탐지를 유지함.
> 3. **판단 포인트**: 이미지 스캔, 런타임 탐지, workload inventory, agent 방식, Kubernetes 연계, EDR/SIEM 연동이 핵심임.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 워크로드 보안 이해 확인 | VM·container·serverless 보호 | CSPM 설정 점검과 혼동 |
| 런타임 방어 판단 확인 | 프로세스·파일·네트워크 행위 탐지 | 이미지 스캔만 작성 |
| 클라우드 네이티브 적용 확인 | Kubernetes, registry, CI/CD 연계 | 온프레미스 백신으로 축소 |

> 요약: 이 문제는 클라우드 설정이 아니라 실행 중 워크로드의 취약점과 행위 보호를 묻는다.

---

## Ⅰ. 개요 및 필요성

- 개요: 워크로드 런타임 보호
- 배경: 클라우드 워크로드는 VM, 컨테이너, serverless 형태로 동적 생성되어 전통 서버 보안 관리 범위를 벗어남.
- 필요성: 이미지 취약점, 권한 상승, 의심 프로세스, 비정상 네트워크 연결을 워크로드 단위로 탐지해야 함.

---

## Ⅱ. 구조 및 구성요소

```text
VM / Container / Kubernetes / Serverless -> CWPP Sensor / API
  +-> Vulnerability Scan -> Runtime Detection -> Policy Enforcement
  +-> SIEM / EDR / Ticket
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 워크로드 인벤토리 | 실행 중 자산 식별 | ephemeral workload 추적 |
| 취약점 스캔 | 이미지·패키지 CVE 탐지 | registry, CI/CD 연계 |
| 런타임 탐지 | 프로세스·파일·네트워크 행위 분석 | agent, eBPF, audit log |
| 정책 집행 | 차단·격리·경보 수행 | Kubernetes admission, runtime policy |

> 요약: CWPP는 워크로드 식별, 취약점 분석, 런타임 탐지, 정책 집행을 하나의 보호 흐름으로 연결한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
워크로드 발견 -> 이미지 / 패키지 스캔 -> 정책 평가
-> 배포 허용 / 차단 -> 런타임 행위 감시 -> 경보 / 격리 -> 조치 확인
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | VM·컨테이너·serverless 자산 발견 | inventory freshness |
| 2 | OS·라이브러리·이미지 취약점 분석 | critical CVE count |
| 3 | 배포 정책과 런타임 기준 적용 | admission decision |
| 4 | 이상 행위 탐지 후 SIEM·SOAR 연계 | MTTD, MTTR |

> 요약: CWPP는 배포 전 취약점 검사와 배포 후 런타임 행위 감시를 연속으로 수행한다.

---

## Ⅳ. 특징

| 구분 | CSPM | CWPP | 판단 기준 |
|:---|:---|:---|:---|
| 대상 | 클라우드 설정·계정 | VM·컨테이너·serverless | 보호 초점 |
| 탐지 | misconfiguration | CVE·프로세스·네트워크 행위 | 런타임 필요성 |
| 조치 | 설정 수정 | 격리·차단·패치 | 침해 대응 |
| 한계 | 워크로드 내부 제한 | 계정 설정 가시성 제한 | CNAPP 통합 필요 |

> 요약: CSPM이 클라우드 외부 형상을 본다면 CWPP는 실행 중 워크로드 내부 위험을 본다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 서버 백신·EDR | 클라우드 워크로드 보호 | 컨테이너·serverless 비중 |
| 비용 | 호스트 단위 에이전트 | workload·node 기반 과금 | ephemeral workload 수 |
| 운영 | 서버 담당 조직 중심 | DevOps·보안 공동 운영 | CI/CD 연계 수준 |

> 요약: 컨테이너와 Kubernetes 운영 비중이 높으면 전통 서버 보안보다 CWPP 적용 근거가 커진다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 에이전트 부담 | 노드·컨테이너 리소스 사용 | agentless와 eBPF 비교 | CPU overhead |
| 탐지 누락 | serverless·ephemeral 수명 짧음 | 이벤트 기반 수집 | missed workload |
| 조치 지연 | DevOps 파이프라인 미연계 | registry·CI/CD 차단 | remediation SLA |

> 요약: CWPP 리스크는 수집 방식, 짧은 수명 워크로드, 조치 지연이며 파이프라인 연계로 줄인다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 취약점 | critical CVE SLA 내 조치 | vulnerability report |
| 런타임 탐지 | 의심 프로세스·연결 탐지 | runtime alert |
| 커버리지 | 워크로드 누락 없음 | inventory 대조 |

> 요약: CWPP 성과는 취약점 조치, 런타임 탐지, 워크로드 커버리지로 판단한다.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 이미지 레지스트리와 CI/CD에 취약점 스캔을 연결하고 critical CVE 기준 배포 차단 정책을 설정함.
2. Kubernetes 노드와 주요 VM에 런타임 센서를 적용하고 프로세스·파일·네트워크 기준 정책을 운영함.
3. CWPP 이벤트를 SIEM·SOAR·티켓 시스템과 연계해 탐지부터 패치·격리까지 조치 흐름을 기록함.

**결론 (2줄):**
- 기술사 판단: 설정 오류가 문제면 CSPM, 워크로드 취약점과 런타임 위협이 문제면 CWPP가 우선임.
- 향후 방향: CWPP는 CNAPP 안에서 CSPM·CIEM·Kubernetes 보안과 결합해 공격 경로 기반 보호로 통합됨.

| 요구사항 명시형 | "컨테이너 보안 방안을 제시하시오" | 이미지·런타임·SIEM 연계 절차 | 에이전트 부담·탐지 누락 리스크 |

> 요약: 설명형은 워크로드 보호 범위를, 방안형은 CI/CD와 런타임 통제 절차를 중심으로 작성한다.
