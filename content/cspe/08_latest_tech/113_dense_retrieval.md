# 📖 【암기용】 개념 완전 이해

> 목적: Dense Retrieval을 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **정의**: 질의와 문서를 저차원 밀집 벡터로 변환해 의미 유사도로 검색하는 기법
- **왜 필요한가**: BM25는 같은 뜻의 다른 단어를 놓치므로, 문맥과 의미를 반영한 검색이 필요함.
- **핵심 직관**: 문장 의미를 좌표로 바꾸고, 좌표 공간에서 가까운 문서를 찾는 방식임.

## 깊이 이해
- **배경·문제의식**: "환불 규정"과 "반품 정책"처럼 단어가 다르지만 뜻이 같은 질의는 키워드 검색의 재현율을 낮춘다.
- **작동 원리**: Bi-Encoder가 질의·문서를 384~1,536차원 벡터로 만들고, 벡터DB의 ANN 인덱스가 코사인 유사도나 내적으로 Top-K를 반환함.
- **비유**: 책 제목이 아니라 책의 주제를 숫자 좌표로 붙여두고, 질문 좌표와 가까운 책을 찾는 방식임.
- **구체 예시**: DPR은 Natural Questions에서 Top-20 Recall 78.4%를 달성해 BM25 대비 오픈도메인 QA 검색 품질을 높임.
- **흔한 오해·주의점**: 정확한 모델명·오류코드·조항 번호는 Dense가 놓칠 수 있음. 운영 RAG는 BM25와 결합하는 경우가 많음.

## 연결 개념
- Embedding — 텍스트를 밀집 벡터로 변환하는 표현 방식
- Vector Database — Dense 벡터를 색인·검색하는 저장소
- Bi-Encoder — Dense Retrieval의 대표 검색 모델 구조

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Dense Retrieval은 텍스트 의미를 밀집 벡터로 표현해 유사도 검색하는 기법임.
> 2. **가치**: 어휘 불일치를 줄여 Recall@20을 BM25 대비 15~20%p 높일 수 있음.
> 3. **판단 포인트**: 고유명사·코드 검색은 Sparse가 우위이므로 Hybrid Search와 리랭킹 조합이 필요함.

## Ⅰ. 개요 및 필요성

Dense Retrieval은 의미 기반 벡터 검색 기법임. 키워드 검색은 동의어·문맥 차이를 처리하지 못해 검색 누락이 발생한다. LLM 기반 RAG에서 외부 지식 검색의 1차 후보 생성기로 사용된다.

## Ⅱ. 구조 및 구성요소

```text
문서 → Doc Encoder → Dense Vector → ANN Index
질의 → Query Encoder → Query Vector → Similarity Search → Top-K
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Query Encoder | 질의를 384~1,536차원 벡터로 변환 | 실시간 인코딩 |
| Document Encoder | 문서 청크를 벡터로 변환 | 오프라인 배치 인코딩 |
| ANN Index | 근사 최근접 이웃 검색 | HNSW, IVF-PQ, ScaNN |
| Similarity Metric | 벡터 간 유사도 계산 | cosine, dot product |

> 요약: Dense Retrieval은 질의와 문서를 같은 벡터 공간에 배치하고 ANN 인덱스로 Top-K를 검색함.

## Ⅲ. 동작원리 및 흐름도

```text
문서 수집 → 청킹 → 임베딩 → 벡터DB 색인
질의 입력 → 임베딩 → ANN 검색 → Top-K 후보 반환
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 문서 청킹 후 임베딩 생성 | 청크 누락률 0%, 배치 처리 1만 청크/분 |
| 2 | HNSW·IVF-PQ 인덱스 구축 | Recall@10 ≥95% |
| 3 | 질의 벡터 생성 및 유사도 검색 | 검색 지연 p95 <100ms |
| 4 | Top-K 후보를 RAG 또는 리랭커로 전달 | Recall@20 ≥75% |

> 요약: 문서는 사전 벡터화하고 질의만 실시간 벡터화해 밀리초 단위 의미 검색을 수행함.

## Ⅳ. 특징

| 구분 | BM25 | Dense Retrieval | 판단 포인트 |
|:---|:---|:---|:---|
| 검색 기준 | 토큰 일치 | 의미 유사도 | 동의어·문맥 질의는 Dense |
| 인프라 | 역색인 | 벡터DB·ANN | 1억 벡터 이상은 압축 필요 |
| 취약점 | 어휘 불일치 | 고유명사·코드 누락 | Hybrid Search로 보완 |
| 대표 지표 | nDCG@10 0.42 | nDCG@10 0.47 | 도메인 데이터로 재측정 |

> 요약: Dense Retrieval은 의미 검색에 강하지만 정확 토큰 검색 한계가 있어 BM25와 결합하는 구성이 일반적임.

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. RAG 검색: BGE-M3 임베딩, 512토큰 청크, Milvus HNSW로 Top-20 검색 후 LLM 컨텍스트 주입
2. 대규모 색인: 1억 벡터 이상은 IVF-PQ 압축으로 저장 용량 70% 절감, Recall@10 95% 유지
3. 품질 보완: BM25 Top-50과 Dense Top-50을 RRF로 결합 후 Cross-Encoder로 Top-5 재정렬

**결론 (2줄):**
- 기술사 판단: 의미 질의 중심 서비스는 Dense Retrieval, 고유명사·코드 중심 서비스는 Hybrid Search 적용
- 향후 방향: ColBERT와 late interaction 구조로 Dense의 정밀 매칭 한계를 보완
