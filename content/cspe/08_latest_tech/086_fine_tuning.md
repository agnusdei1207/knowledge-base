# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: 대규모 데이터로 사전 학습(Pre-training)된 범용 인공지능 모델의 가중치를, 특정 도메인이나 태스크 목적에 맞게 추가 학습하여 미세 조정하는 기법.
- **필요성**: 범용 LLM은 일반적인 지식은 많지만, 기업의 특수한 용어, 고유한 비즈니스 로직, 요구되는 특정 출력 포맷(예: 사내 양식)을 정확하고 일관되게 따르지 못함.
- **핵심 직관**: 대학교에서 전공 지식(Pre-training)을 두루 배운 신입사원에게, 입사 후 우리 회사의 사내 규정과 실무 매뉴얼(Fine-tuning)을 집중적으로 재교육시키는 과정.

## 깊이 이해
- **배경**: 프롬프트 엔지니어링(Prompt Engineering)만으로는 컨텍스트 윈도우 한계가 있고, 모델 내재적 판단 기준을 바꾸기 어려움. RAG는 외부 문서를 검색해올 뿐, 모델의 말하기 '스타일'이나 '구조'를 바꾸지는 못함.
- **작동 원리**:
  1. Base Model 선정 (예: LLaMA-3).
  2. 도메인 특화 데이터 수집 및 정제 (입력-출력 쌍으로 구성).
  3. Supervised Fine-Tuning(SFT) 수행: 크로스 엔트로피 손실 함수를 사용하여 모델의 전체 가중치(Full Fine-Tuning) 혹은 일부 가중치(PEFT)를 업데이트.
- **비유**: 어느 나라 요리든 할 줄 아는 범용 셰프에게, '우리 식당만의 특제 소스 레시피'를 반복 훈련시켜 완벽한 전속 셰프로 만드는 것.
- **구체 예시**: 범용 코딩 모델(CodeLlama)에 사내 보안 코딩 가이드라인과 레거시 코드 10만 건을 파인튜닝하면, 취약점을 유발하지 않는 사내 전용 코파일럿이 탄생함.
- **흔한 오해/주의점**: 파인튜닝은 '새로운 최신 사실(Fact)을 주입'하는 데는 매우 비효율적임(Catastrophic Forgetting 발생 위험). 팩트 업데이트는 RAG로 해결하고, 파인튜닝은 '형식, 말투, 도메인 추론 능력'을 가르치는 데 써야 함.

## 연결 개념
- **Pre-training**: 파인튜닝 이전의 사전 학습 단계.
- **PEFT (Parameter-Efficient Fine-Tuning)**: 비용 절감을 위한 최신 파인튜닝 기법.
- **RAG (Retrieval-Augmented Generation)**: 파인튜닝의 단점(환각, 지식 노후화)을 보완하는 환상의 짝꿍.

# 📝 【답안용】 시험 답안 템플릿
## 핵심 인사이트 (3줄 요약)
- **본질**: 사전 학습된 가중치 공간(Weight Space)을 특정 도메인 데이터로 이동시켜 업무 적합도(Task-specific Fitness)를 극대화하는 전이 학습(Transfer Learning) 기술.
- **가치**: 환각 감소, 추론 지연 개선(프롬프트 단축 가능), 보안 유지(온프레미스 SLM 배포 가능)를 통해 AI의 실제 기업 도입 ROI를 창출.
- **판단 포인트**: Full FT vs PEFT 결정, RAG와의 역할 분담(지식 vs 행동), 과적합(Overfitting) 및 망각(Catastrophic Forgetting) 방지.

## Ⅰ. 개요 및 필요성
- **정의**: 방대한 데이터로 사전 학습된 파운데이션 모델(Foundation Model)에 특화된 라벨링 데이터를 주입하여 모델의 파라미터를 추가로 업데이트하는 학습 기법.
- **배경**: 범용 LLM은 특정 도메인(법률, 의료, 국방 등)의 엣지 케이스나 특수 용어에 대한 Zero-shot 추론 정확도가 낮음.
- **필요성**: 단순 Prompting의 컨텍스트 한계와 비용 오버헤드를 극복하고, 모델 스스로 도메인 패턴을 체화(Internalization)하도록 만들기 위함.

## Ⅱ. 아키텍처 및 구성 요소
```text
[Pre-trained Base Model] + [Domain-Specific Dataset]
           |                         |
           v                         v
+---------------------------------------------+
|              Fine-Tuning Engine             |
| - Optimizer (AdamW)  - Loss Function (CE)   |
| - Learning Rate Scheduler                   |
+---------------------------------------------+
           | (Weight Update)
           v
[Domain-Adapted Fine-Tuned Model] ---> [Evaluation & Serving]
```
- **Base Model**: 일반적 언어 이해력을 갖춘 모델 (예: LLaMA, Mistral).
- **Domain Dataset**: Q&A, 요약, 분류 등 (Input, Output) 형태의 정제된 Instruction 데이터.
- **Optimizer**: 기존 지식이 파괴되지 않도록 매우 작은 Learning Rate(예: $1e^{-5}$)를 사용함.

## Ⅲ. 세부 동작 원리 및 단계
1. **데이터 큐레이션**: 고품질 도메인 데이터 수집, 개인정보(PII) 제거, 입력-출력 템플릿 맞춤화.
2. **하이퍼파라미터 설정**: 학습률(LR), 배치 크기, 에포크 수 설정. 보통 일반 학습보다 적은 에포크(1~3)로 제한.
3. **학습 수행 (Forward/Backward)**: 모델이 예측값을 내고 정답과의 오차(Loss)를 계산해 역전파 수행.
4. **회귀 및 성능 평가**: 도메인 성능(F1 Score 등)이 오르는 동시에, 일반 능력(MMLU 등)이 붕괴되지 않았는지 검증.

## Ⅳ. RAG와의 심화 비교 (Fine-Tuning vs RAG)
| 구분 | Fine-Tuning | RAG (검색 증강 생성) |
|:---:|:---|:---|
| **목적** | 모델의 말투, 포맷, 도메인 추론 능력 체화 | 외부 최신 지식, 사실 기반 근거 제공 |
| **비용** | 학습 비용(GPU) 높음, 추론 비용 낮음 | 학습 불필요, 검색 및 DB 비용 발생 |
| **데이터 변경**| 재학습(Retraining) 필요 | Vector DB 업데이트만으로 즉각 반영 |
| **적합한 사례**| 회사 보고서 양식 훈련, 사투리 번역 | 매일 바뀌는 주가 정보, 실시간 뉴스 기반 QA |

## Ⅴ. 한계점 및 극복 방안 (운영 리스크)
- **리스크 1: 파국적 망각 (Catastrophic Forgetting)**:
  - 도메인 데이터에 과적합되어 모델이 원래 알던 상식이나 범용 능력을 상실하는 현상.
  - **대응**: 학습 데이터에 범용 데이터(General Data)를 10~20% 섞어서 함께 학습(Replay 방식).
- **리스크 2: 막대한 컴퓨팅 비용**:
  - 수백억 파라미터의 Full FT는 VRAM과 긴 학습 시간을 요구.
  - **대응**: PEFT (LoRA, QLoRA) 기법을 활용하여 전체 가중치의 1% 미만만 업데이트.

## Ⅵ. 실무 적용 및 결론
- **판단 지표**: 도메인 평가셋 정확도 향상분, MMLU 하락 방어율, GPU 학습 소요 시간 및 비용.
- **실무 설계**: 기업 사내 챗봇 구축 시, "사내 규정 내용"은 RAG(Vector DB)로 제공하고, "친절하고 간결한 사내 표준 보고서 포맷"은 LLaMA-3 8B에 5,000건의 고품질 QA 데이터로 LoRA 파인튜닝을 수행하여 결합하는 하이브리드 아키텍처 적용.
- **결론**: Fine-Tuning은 거대 범용 AI를 기업의 비즈니스 자산(Custom AI)으로 탈바꿈시키는 가장 강력한 수단이며, 비용 효율적 튜닝(PEFT)과 RAG와의 역할 분담이 성공적인 도입의 핵심임.

### 🔀 문제 유형별 목차 전환
- **Ⅱ·Ⅲ 강조 (개념/원리형)**: 모델 가중치 업데이트 메커니즘, Learning Rate 조정의 중요성, 데이터 포맷팅 중심 서술.
- **Ⅴ·Ⅵ 강조 (실무/설계형)**: LLM 사내 도입 전략으로 출제 시. RAG와의 상호 보완 아키텍처 설계, Catastrophic Forgetting 방어 전략 및 ROI 중심 작성.
