## 미리 알고가기

- Prompt는 모델이 답변을 생성할 때 참조하는 시스템 지시, 사용자 질의, 예시, 도구 명세의 묶음임
- Few-shot은 원하는 입출력 패턴 예시를 함께 주어 모델 출력을 유도하는 방식임
- Structured Output은 JSON, 표, 코드 블록처럼 출력 형식을 제약해 후속 시스템 연동을 안정화하는 기법임

## Ⅰ. 개요

- **정의/개념**: Prompt Engineering은 모델 가중치를 바꾸지 않고 입력 지시와 예시와 제약을 구조화해 정확도와 일관성과 안전성을 높이는 생성형 AI 제어 기술임
- **배경/필요성**: 동일 모델도 질문 방식에 따라 품질 편차가 크게 발생하므로, 실무에서는 원하는 역할과 형식과 도구 사용 규칙을 명시적으로 설계해 확률적 출력을 업무용 결과로 안정화할 필요가 있음

## Ⅱ. 특징

- 모델 재학습 없이도 빠르게 품질을 개선할 수 있어 초기 PoC와 운영 튜닝에 비용 효율적임
- 역할, 맥락, 예시, 제약을 조합해 응답 톤과 형식과 추론 경로를 통제할 수 있음
- RAG, Tool Use, Agent Workflow와 결합할 때 실제 업무 품질 차이를 크게 만듦
- 프롬프트 품질이 좋아도 injection과 context contamination에 취약할 수 있어 보안 설계가 병행돼야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | Ad-hoc Prompt | Engineered Prompt | Fine-tuning |
|:---|:---|:---|:---|
| 준비 비용 | 낮음 | 낮음~중간 | 높음 |
| 반영 속도 | 즉시 | 즉시 | 느림 |
| 형식 통제력 | 낮음 | 높음 | 높음 |
| 적합 상황 | 실험, 단발 질의 | 운영 챗봇, 업무 자동화 | 도메인 고정, 대규모 반복 업무 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Role Instruction | 모델의 역할과 금지 사항을 정의해 답변 관점과 책임 범위를 고정함 |
| Context Block | 업무 배경, 참고 문서, 사용자 데이터 등 문제 해결에 필요한 근거를 제공함 |
| Example Block | 원하는 입력과 출력 패턴을 예시로 제시해 형식과 추론 방향을 유도함 |
| Output Constraint | JSON 스키마, 길이 제한, 표 형식 같은 제약을 걸어 후속 시스템과의 연결 안정성을 확보함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-----------+     +---------------+     +---------------+     +-------------+
| 과업 정의  | --> | 맥락, 예시 구성 | --> | 제약, 형식 지정 | --> | 생성, 검증  |
+-----------+     +---------------+     +---------------+     +-------------+
```

1. **과업 정의**: 모델이 무엇을 해야 하고 무엇을 하면 안 되는지 목표와 경계를 명확히 정함
2. **맥락 및 예시 구성**: 필요한 배경정보와 few-shot 예시를 넣어 출력 패턴을 유도함
3. **제약 및 형식 지정**: JSON, 표, 길이 제한, 근거 포함 여부 같은 형식을 강제함
4. **생성 및 검증**: 생성 결과를 후처리 규칙이나 평가셋으로 검증해 프롬프트를 반복 개선함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 표현이 조금만 달라져도 결과가 흔들리는 프롬프트 민감성 때문에 운영 환경에서 품질 일관성이 깨질 수 있음
   - 해결방안: 템플릿화와 회귀 평가셋을 함께 운영하고 task success rate와 variance로 안정성을 검증함
2. 문제: 외부 문서나 사용자 입력이 지시문을 오염시키면 prompt injection으로 정책 위반이나 오답이 발생할 수 있음
   - 해결방안: 역할 분리와 입력 sanitization과 도구 권한 제한을 적용하고 injection success rate와 policy violation 수로 보안성을 검증함
3. 문제: 프롬프트를 과도하게 길게 만들면 비용과 TTFT가 증가하고 핵심 지시가 오히려 희석될 수 있음
   - 해결방안: thin prompt와 외부 지식 조회를 병행하고 prompt token 수와 answer accuracy 대비 cost로 효율을 검증함

## Ⅶ. 적용 사례

- 고객센터 챗봇: 환불, 교환, 배송 질의를 정해진 JSON 형식으로 반환함, 확인 지표는 intent accuracy와 automation rate임
- 데이터 분석 보조: SQL 생성 전에 스키마와 금지 규칙을 명시해 잘못된 쿼리를 줄임, 확인 지표는 query success rate와 execution error rate임
- 에이전트 시스템: 도구 사용 규칙과 실패 시 행동을 시스템 지시로 정의함, 확인 지표는 tool success rate와 recovery rate임

## Ⅷ. 결론

프롬프트 엔지니어링의 핵심은 말을 잘 꾸미는 데 있지 않고 역할과 근거와 제약을 구조화해 확률적 모델 출력을 운영 가능한 결과로 수렴시키는 설계 역량에 있음.
