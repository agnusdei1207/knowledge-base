## 미리 알고가기

- TTS는 텍스트를 자연스러운 음성 파형으로 변환하는 음성합성 기술임
- text normalizer와 acoustic model과 vocoder가 전형적 파이프라인을 이룸
- 자연스러움뿐 아니라 latency와 보이스 클로닝 통제가 중요한 운영 이슈임

## Ⅰ. 개요

- **정의/개념**: TTS는 입력 텍스트를 발음 단위와 운율 정보로 해석하고, 이를 기반으로 음향 특징과 파형을 생성해 사람이 말하는 것처럼 들리는 음성으로 합성하는 생성형 음성 기술임
- **배경/필요성**: 음성 비서와 오디오북과 AI 상담처럼 화면 없이 정보를 전달하거나 감정이 실린 응답이 필요한 서비스가 늘면서, 자연스럽고 빠른 음성 출력 기술이 필요해졌음

## Ⅱ. 특징

- 발음 정확도와 억양 자연스러움과 latency가 함께 관리돼야 함
- 음향 모델과 vocoder 품질 차이가 청취 경험을 크게 좌우함
- 화자 스타일과 감정 제어를 넣으면 개인화 서비스 가치가 커짐
- 보이스 클로닝 악용 가능성 때문에 워터마킹과 인증 체계가 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 연결 합성 TTS | Acoustic+Vocoder TTS | End-to-End TTS |
|:---|:---|:---|:---|
| 자연스러움 | 낮음 | 높음 | 매우 높음 |
| 제어 유연성 | 낮음 | 높음 | 높음 |
| 실시간성 | 높음 | 중간 | 중간 |
| 최신 확장성 | 낮음 | 높음 | 매우 높음 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Text Normalizer, G2P | 숫자와 약어와 발음 규칙을 정리해 합성 가능한 입력 시퀀스로 변환함 |
| Acoustic Model | 텍스트에서 멜 스펙트로그램과 피치와 길이 같은 음향 특징을 예측함 |
| Prosody, Speaker Control | 화자 특성과 감정과 말하기 속도를 제어해 개인화된 출력 품질을 만듦 |
| Vocoder | 예측된 음향 특징을 최종 오디오 파형으로 변환해 실제 재생 가능한 음성을 생성함 |

```text
+-------------------+      +-------------------+      +-------------------+
| Normalizer / G2P  | ---> | Acoustic Model    | ---> | Vocoder           |
+-------------------+      +-------------------+      +-------------------+
                                   ^
                                   |
                           +-------------------+
                           | Prosody / Speaker |
                           +-------------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 텍스트 입력     | --> | 발음/운율 해석  | --> | 음향 특징 생성  | --> | 파형 합성 출력  |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **텍스트 입력**: 문장과 화자 조건과 감정 조건을 받음
2. **발음 및 운율 해석**: G2P와 prosody 제어 정보를 구성함
3. **음향 특징 생성**: acoustic model이 멜 스펙트로그램을 예측함
4. **파형 합성 출력**: vocoder가 재생 가능한 오디오 파형을 생성함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 범용 발음 규칙만 사용하면 숫자와 약어와 전문 용어가 부자연스럽게 읽혀 서비스 신뢰도가 떨어질 수 있음
   - 해결방안: domain lexicon과 contextual pronunciation rule을 적용하고 pronunciation accuracy와 MOS로 검증함
2. 문제: 실시간 대화형 서비스에서 vocoder 지연이 길면 응답 자연스러움보다 체감 속도 문제가 먼저 드러날 수 있음
   - 해결방안: streaming TTS와 경량 vocoder를 적용하고 TTFT와 real-time factor로 검증함
3. 문제: 보이스 클로닝이 쉬워질수록 사칭과 딥보이스 악용 위험이 커져 운영 승인 자체가 어려워질 수 있음
   - 해결방안: consent workflow와 audio watermarking을 적용하고 spoof detection rate와 provenance coverage로 검증함

## Ⅶ. 적용 사례

- AI 상담원이 자연스러운 응답 음성을 제공하도록 TTS를 적용하며 확인 지표는 MOS와 TTFT임
- 오디오북 제작이 다국어 음성 낭독을 자동화하도록 TTS를 운영하며 확인 지표는 pronunciation accuracy와 production time reduction임
- 차량 음성 비서가 네트워크 없이 빠르게 안내를 재생하도록 TTS를 활용하며 확인 지표는 real-time factor와 user satisfaction임

## Ⅷ. 결론

TTS는 텍스트 지능을 사람 친화적 인터페이스로 바꾸는 마지막 출력 계층이므로, 자연스러움과 지연 시간과 음성 안전 통제를 함께 설계해야 실서비스 품질이 확보됨.
