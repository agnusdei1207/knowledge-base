## 미리 알고가기

- 고도화형 RAG ($Advanced$ $RAG$): 기본형 RAG의 단선적 검색 한계와 낮은 정밀도를 극복하기 위해, 검색 전 단계(Pre-retrieval)와 검색 후 단계(Post-retrieval)에 정교한 엔지니어링 최적화 파이프라인을 이식한 상영상용 구조임
- 하이브리드 리트리버 ($Hybrid$ $Retriever$): 키워드 일치형 sparse 검색($BM25$ 등)과 문맥 의미형 dense 검색(임베딩 기반)을 동시 병렬 구동하여 양쪽 후보군을 취합하는 복합 검색 장치임
- 재순위화 ($Reranking$): 1차 인출된 수십 개의 관련 문서 청크들을 크로스 인코더($Cross-Encoder$) 기반 모델로 재평가해, 질문과 상관관계가 극히 높은 최상위 소수 문서만 프롬프트 양단으로 재정리 배치하는 최적화 기법임
- 컨텍스트 압축 ($Context$ $Compression$): 긴 청크 텍스트 내에서 질문과 관련이 전무한 불필요한 조사, 수식 구절을 정보 이론 기반으로 오려내고($Summarize$ 또는 $Pruning$), 핵심 키워드 문장만 프롬프트에 싣는 메모리 가성비 압축임

## Ⅰ. 개요

- **정의/개념**: Advanced RAG는 Naive RAG의 고질적 병목인 노이즈 유입과 검색 실패를 원천 봉쇄하기 위해, 검색 전단에 질의어 최적화($Query$ $Expansion$ 등)를 얹고 검색 중단에 하이브리드 조회를 수행하며 검색 후단에 리랭커 및 컨텍스트 압축을 가미해 최종 생성 근거의 정밀도($Precision$)를 완성하는 고도화형 RAG 아키텍처임
- **배경/필요성**: 단순 유사도 기반 검색은 고유 상품명, 조사가 생략된 오탈자 질문, 문맥의 다단계 의존성이 깊은 도메인에서 오작동이 심하여 상용 금융/의료 챗봇의 SLA(서비스수준계약) 신뢰도를 보장하기 위해 전면 개정 도입됨

## Ⅱ. 특징

- 검색 전($Pre-retrieval$, 청킹 고도화 및 질의 확장)과 검색 후($Post-retrieval$, 리랭커 및 문장 압축)의 다층 품질 장치를 내장함
- 키워드 매칭의 명확성과 임베딩의 의미론적 모호성을 상호 보완하는 $Dense-Sparse$ 하이브리드 검색망이 상시 가동됨
- 각 파이프라인 단계마다 고유의 추가 런타임 지연(예: Reranker 모델 추론 속도 등)이 추가되므로 연산 비용은 Naive 대비 증가함

## Ⅲ. 종류 및 비교

| 판단 기준 | 기본형 RAG (Naive RAG) | 고도화형 RAG (Advanced RAG) | 에이전틱 RAG (Agentic RAG) |
|:---|:---|:---|:---|
| **검색 전단 제어 ($Pre$)** | 없음 (원시 질의 그대로 벡터 DB 매핑) | 질의어 최적화 (Query Rewrite, 서브 질문 분할) | 에이전트의 상황 판단 하에 검색 쿼리 결정 |
| **검색 후단 제어 ($Post$)** | 없음 (가져온 그대로 프롬프트 적재) | Reranking (재순위화), Context Compression (문맥 압축) | 검색 결과 유효성 평가 및 재쿼리 제어 루프 가동 |
| **도입 복잡도 (장애 지점)** | 매우 낮음 | 중간 수준 (리랭커 컴포넌트 추가) | 매우 높음 (상태 관리 모듈 및 피드백 오케스트레이션) |
| **검색의 적중률 ($Recall$)** | 보통 | 매우 우수함 (하이브리드 조회) | 극대화 (자가 보정 반복) |

> 요약: Naive RAG가 사전 준비 없는 원시적 오픈북 시험이라면, Advanced RAG는 질문의 의미를 세분화하여 책의 인덱스를 하이브리드로 찾고 중요 핵심 페이지(Rerank)만 발췌 정리해 시험을 치는 프로형 최적화임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 질의어 최적화기 | 사용자 의도를 파악해 동의어를 더하거나(Query Expansion) 질문을 쪼개어 검색 적중력을 높이는 모듈임 |
| 하이브리드 리트리버 | 키워드 중심의 $BM25$ 인덱싱과 벡터 DB 코사인 유사도 측정을 병렬 집행하는 추출기임 |
| 리랭커 ($Reranker$) | 질문-청크 간의 의미 거리를 크로스 인코더로 심층 대조해 최정예 문서 상위 $N$개만 엄선하는 필터임 |
| 컨텍스트 압축기 | 엄선된 청크 내의 무관한 문맥 노이즈를 쳐내어 $Lost-in-the-Middle$ 병목을 방지하는 압축기임 |

```text
[ Advanced RAG (전후처리 가속) 전체 파이프라인 ]
User Query ──> [ Query Rewrite / Sub-Query ] ──> [ Dense & Sparse Hybrid Search ]
                                                                │
Prompt Context <── [ Context Compressor ] <── [ Reranker (Top-3) ] <───────────/
      │
      v
[ LLM Generator ] ──> Citations Response
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 질의 다변화 | --> | 키워드/의미  | --> | 크로스인코더| --> | 컨텍스트압축|
| 확장/최적화 |     | 하이브리드검색|     | 재순위 셋업 |     | 및 생성/Cite|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **질의어 재정리** — 사용자 질문 "A사 올해 연봉 수준은?"을 "A사 올해 급여 평균", "A사 2026 복지 혜택" 등으로 쿼리 확장함
2. **하이브리드 서치** — 확장된 쿼리들을 던져, 고유명사 매칭의 $BM25$와 문맥 매칭의 $Milvus$ 벡터 DB 조회를 병렬 수행함
3. **크로스인코더 Rerank** — 추출된 $30$개 후보 청크에 대해 Cohere Rerank 등 심화 채점을 돌려 최정예 3개 청크만 골라냄
4. **압축 및 팩트 생성** — 3개 청크 내에서 관련성 바닥인 문장을 LLM LLMLingua 등으로 털어내고 압축 수렴된 근거만 프롬프트에 실어 답을 생성함

## Ⅵ. 실무 적용 및 유의점

1. Advanced RAG 컴포넌트(질의 재작성, Rerank, 압축 등)를 지나치게 많이 엮으면, 개별 컴포넌트 추론 시간이 덧셈 누적되어 서비스 수준 협약(SLA) 응답 지연 한계선을 돌파하므로, 각 스테이지별 지연 실측을 수행하고 가성비 스위트스팟(Sweet Spot) 모듈 조합만 선별 개입시켜야 함
2. 파이프라인의 각 단계 파라미터(예: Chunk Size, Top-K, Rerank Threshold)가 서로 유기적으로 얽혀 있으므로, 1단계 최적화가 최종 품질을 보장하지 못하는 모순이 생기므로, 반드시 스테이지별 지표(Retrieval Recall, Context Precision, Faithfulness)를 분리 감사 측정하는 평가 체계를 수립해야 함

## Ⅶ. 결론

- Advanced RAG는 단순 유사도 매핑의 물리적 한계를 정밀 파이프라인 전후처리 공학으로 승화시켜 상영상용 가치를 보장해 낸 인프라 최적화의 주역이며, 설계자는 무분별한 런타임 추가에 따른 지연 스파이크 차단용 프로파일링과 파이프라인 스테이지별 품질 분리 감사 체계를 반드시 통합 완비해야 함
