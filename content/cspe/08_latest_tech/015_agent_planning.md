# 📖 【암기용】 개념 완전 이해

> 목적: 에이전트 플래닝을 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: 에이전트가 목표를 실행 가능한 단계와 순서로 분해하는 과정
- **왜 필요한가**: 업무 목표는 추상적이지만 도구는 구체 입력과 순서가 있어야 실행됨.
- **핵심 직관**: 플래닝은 “무엇을 해야 하는가”를 “어떤 순서로 실행할 것인가”로 바꾸는 작업임.

## 깊이 이해
- **배경·문제의식**: LLM이 바로 도구를 호출하면 필수 정보 누락, 순서 오류, 불필요한 반복 호출이 발생함.
- **작동 원리**: 목표, 제약, 도구 목록, 현재 상태를 바탕으로 하위 작업과 의존관계를 만들고 실행 중 갱신함.
- **비유**: 여행 목표를 항공권, 숙소, 이동, 예산, 일정표로 나누는 과정.
- **구체 예시**: “DB 장애 원인 분석”을 로그 수집, 메트릭 확인, 최근 배포 확인, 원인 후보 검증, 조치안 작성으로 분해함.
- **흔한 오해·주의점**: 플랜은 정답이 아니라 가설이므로 실행 결과에 따라 재계획과 중단 조건이 필요함.

## 연결 개념
- ReAct — 실행 중 계획을 관찰 결과로 수정
- Task Decomposition — 목표 분해 기법
- Orchestration — 계획을 실제 실행으로 관리

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Agent Planning은 목표를 하위 작업, 의존관계, 도구 호출 순서로 변환하는 과정임.
> 2. **가치**: 도구 호출 전 실행 경로와 종료조건을 정해 불필요한 반복과 권한 오남용을 줄임.
> 3. **판단 포인트**: 계획 품질, 재계획 기준, 비용 한도, Human Approval 조건을 함께 설계해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| AI 에이전트 실행 전 계획 수립 역량 확인 | 목표 분해, Task Graph, 의존관계, Stop Rule, 재계획 기준 | 플랜을 정답으로 오인, 재계획·중단 조건 미언급 |
| 계획과 실행의 분리 및 비용 통제 이해 | 계획 비용 vs 실행 비용 분리, 최대 루프·토큰 예산, Human Approval 조건 | 직접 Tool Use와 Planning 차이 미구분, 비용 미고려 |

> 요약: Planning은 목표 분해·재계획·비용 한도·승인 조건을 함께 설계해야 함을 확인하는 문제임.

---

## Ⅰ. 개요 및 필요성

- 정의: 목표를 하위 작업·의존관계·도구 호출 순서로 변환하는 과정
- 배경: LLM이 계획 없이 도구를 호출하면 필수 정보 누락·순서 오류·불필요 반복 발생
- 필요성: 사전 계획으로 불필요 호출 40% 감소, 최대 루프·토큰 예산으로 비용 통제

---

## Ⅱ. 구조 및 구성요소

```text
Goal -> Constraints -> Task Graph -> Tool Mapping -> Stop Rule
         |               |              |              |
         +-> 정책/한계    +-> 의존관계    +-> 실행도구    +-> 종료조건
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Goal | 목표와 산출물 정의 | 성공 기준 필요 |
| Constraints | 권한·비용·시간 제약 | 금지 행동 포함 |
| Task Graph | 하위 작업·의존관계 | 병렬·순차 구분 |
| Stop Rule | 종료·재계획 기준 | 최대 루프·승인 조건 |

> 요약: Agent Planning은 목표, 제약, 작업그래프, 도구매핑, 종료조건으로 구성됨.

---

## Ⅲ. 동작원리 및 흐름도

```text
목표 입력 -> 제약 확인 -> 작업 분해 -> 도구 매핑
        -> 실행 순서 결정 -> 중간 검증 -> 재계획/종료
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 목표·산출물 정의 | 완료조건, 품질 기준 |
| 2 | 제약조건 확인 | 권한, 비용, 시간 |
| 3 | 작업그래프 생성 | 의존관계, 병렬 가능성 |
| 4 | 실행 중 갱신 | 실패 원인, 재계획 조건 |

> 요약: Planning은 초기 계획으로 끝나지 않고 실행 관찰 결과에 따라 갱신됨.

---

## Ⅳ. 특징

| 구분 | 직접 도구 호출 | Agent Planning | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 실행 순서 | 즉시 호출 | 단계·의존관계 결정 | 계획 단계 수 |
| 오류 대응 | 실패 후 중단 | 재계획·대체경로 | 재계획 횟수 |
| 비용 통제 | 호출 후 확인 | 사전 예산 반영 | 토큰·API 비용 한도 |

> 요약: Planning은 실행 전 통제력을 제공하지만 계획 생성 비용과 지연을 고려해야 함.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 직접 Tool Use | Agent Planning | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 즉시 도구 호출 | 목표→Task Graph→도구 매핑 | 실행 단계 3개 이상이면 Planning |
| 비용/성능 | 호출 즉시 결과 | 계획 생성 토큰 + 실행 토큰 | 계획 비용 대비 불필요 호출 40% 감소 |
| 운영/위험 | 실패 시 재요청 | 재계획·대체 경로·중단 조건 | 재계획 횟수 3회 이내, 최대 루프 설정 |

> 요약: 실행 단계 3개 이상이고 순서·의존관계가 있는 업무에 Planning을 적용함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 과도한 계획 루프 | 실행 결과 불충분 시 무한 재계획 | 최대 재계획 횟수 3회, 3회 실패 시 사람 검토 전환 | 재계획 횟수, 사람 전환율 |
| 계획-실행 불일치 | 계획에 없는 도구 호출·권한 초과 | Task Graph에 허용 도구·권한 명시, 미등록 호출 차단 | 미등록 호출 건수, 권한 위반 건수 |
| 비용 초과 | 계획 생성과 실행에 토큰 이중 소모 | 작업당 토큰 예산(계획 5,000 + 실행 30,000), 예산 초과 시 중단 | 작업당 총 토큰, 예산 초과율 |

> 요약: 무한루프·권한초과·비용초과를 최대 횟수·허용 목록·토큰 예산으로 통제함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 성능/효율 | 계획 생성 p95 지연 2초, 불필요 호출 40% 감소 | 계획 생성 로그, 호출 횟수 비교 |
| 품질/정확도 | Task Graph 완료율 90%, 근거 누락 0건 | 실행 완료 로그, 근거 검증 보고 |
| 운영/보안 | 재계획 3회 이내 해결률 95%, 권한 위반 0건 | 재계획 이력, RBAC 감사 로그 |

> 요약: 계획 지연·완료율·재계획 해결률·권한위반으로 Planning 운영 성과를 판단함.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 목표, 성공기준, 금지행동, 최대 비용, 최대 루프를 Planning 입력으로 명시
2. 작업그래프에 도구 권한과 승인 필요 여부를 표시해 변경형 작업은 실행 전 중단
3. 실행 결과가 실패·불충분·정책위반이면 재계획하고 3회 실패 시 사람 검토로 전환

**결론 (2줄):**
- 기술사 판단: 다단계 업무는 Planning을 적용하고 단일 조회는 직접 Tool Use로 처리함.
- 향후 방향: Planning은 ReAct, Orchestration, 평가 자동화와 결합해 Agent 런타임의 핵심 제어 기능이 됨.
