# 📖 【암기용】 개념 완전 이해

> 목적: 스마트 계약을 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 계약 조건을 코드로 작성하여 블록체인에 올려두면, 조건이 충족되는 순간 제3자 없이 자동으로 실행되는 디지털 계약
- **왜 필요한가**: 현실의 계약은 공증인이나 은행 같은 중개인이 필요하고 시간도 오래 걸리지만, 스마트 계약은 코드(If-Then)에 의해 즉시 실행되므로 비용이 싸고 투명하기 때문
- **핵심 직관**: "블록체인 위의 자동판매기" — 돈을 넣고 버튼을 누르는 조건이 맞으면, 주인이 없어도 알아서 음료수가 나오는 것과 같은 원리

## 깊이 이해
- **배경·문제의식**: 비트코인은 단순히 '돈'을 주고받는 기능뿐이었음. 닉 자보(Nick Szabo)가 처음 제안하고 비탈릭 부테린이 이더리움을 통해 실현하면서, 블록체인 위에서 복잡한 비즈니스 로직(보험금 지급, 투표, 금융 거래)을 돌릴 수 있게 됨.
- **작동 원리**: **If (조건) Then (실행)**. 예를 들어, "비행기가 2시간 연착되면(If), 보험금을 즉시 지급하라(Then)"는 코드를 짜두면, 실제 연착 데이터가 입력되는 순간 돈이 자동으로 송금됨. 블록체인에 기록되므로 아무도 이 계약을 마음대로 수정하거나 취소할 수 없음.
- **비유**: 자판기에서 1,000원을 넣고 콜라를 누르면(조건), 자판기 주인이 없어도 콜라가 나옴(자동 실행). 이 거래 내역은 모든 사람이 볼 수 있는 장부에 적힘(불변성).
- **구체 예시**: 탈중앙화 금융(DeFi)에서 담보를 맡기고 자동으로 대출을 받거나, NFT 구매 시 원작자에게 로열티가 자동으로 배분되는 사례.
- **흔한 오해·주의점**: 스마트 계약은 '똑똑한(Smart)' 인공지능이 아님. 그냥 단순한 '자동화된 코드'일 뿐임. 따라서 코드에 버그가 있으면 잘못된 계약이 그대로 실행되어 큰 피해를 줄 수 있음(The DAO 해킹 사건 등).

## 연결 개념
- Solidity — 이더리움 스마트 계약을 작성하는 대표 언어
- Oracle (오라클) — 현실 세계의 데이터(날씨, 주가 등)를 블록체인 안으로 가져오는 기술
- EVM (Ethereum Virtual Machine) — 스마트 계약이 실제로 실행되는 가상 환경

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 계약의 자동 실행(Automation), 불변성(Immutability), 신뢰 최소화(Trustless) 특성과 보안 리스크 대응 방안을 기술한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 블록체인 네트워크에 기록되어 특정 조건이 충족될 때 사전에 정의된 계약 내용을 자동으로 이행하는 자가 집행적(Self-executing) 컴퓨터 프로토콜이다.
> 2. **가치**: 중개자(Intermediary) 없는 직거래를 통해 거래 비용을 절감하며, 코드 기반의 강제 이행으로 계약의 투명성과 신뢰성을 보장한다.
> 3. **판단 포인트**: 코드의 완결성(Security Audit), 외부 데이터 연동의 신뢰성(Oracle), 법적 계약으로서의 효력 인정 여부가 실무 적용의 핵심이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 스마트 계약의 개념 및 특징 이해 확인 | 자동 실행, 불변성, 투명성, 신뢰 최소화 | 단순 자동화 프로그램으로만 서술 |
| 기술적 구성요소 및 동작 원리 파악 | Solidity, EVM, 오라클(Oracle), 가스(Gas) | 오라클 문제(Oracle Problem) 누락 |
| 보안 리스크 및 대응 역량 판단 | 재진입 공격(Reentrancy), 코드 오딧, 형식 검증 | 기술적 장점만 나열하고 취약성 간과 |

> 요약: 스마트 계약은 '코드의 법적 집행력'을 블록체인으로 구현한 것이며, 보안성 확보가 최우선이다.

## Ⅰ. 개요 및 필요성

- 정의: 블록체인 상에 코드로 구현되어 조건 충족 시 자동으로 계약이 이행되는 프로그램 또는 프로토콜
- 배경: 비트코인의 단순 자산 전송 한계를 극복하고, 블록체인을 '범용 계산 플랫폼(World Computer)'으로 확장
- 필요성: 거래 비용 및 시간 절감, 계약 이행 강제성 확보(신뢰 비용 감소), 다양한 DApp(탈중앙화 앱) 서비스 기반 제공

---

## Ⅱ. 구조 및 구성요소

```text
[ Developer ] -> [ Code (Solidity) ] -> [ Compilation (Bytecode) ]
                                                |
      +-----------------------------------------+
      |                                         |
[ Block Header ] <---- [ EVM (Virtual Machine) ] ----> [ State DB ]
- Contract Addr        - 계약 로직 실행               - 잔액/데이터 저장
- Storage Root         - Gas 소비 및 제어            - 영속성 유지
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Solidity / Vyper | 스마트 계약 작성을 위한 고수준 프로그래밍 언어 | 튜링 완전성(Turing Completeness) |
| EVM (Ethereum VM) | 스마트 계약이 실행되는 런타임 가상 환경 | 샌드박스 구조, 격리된 실행 |
| Gas (가스) | 네트워크 자원 소모에 대한 수수료 및 무한 루프 방지책 | 연산 복잡도에 따라 비례 |
| Oracle (오라클) | 블록체인 외부 데이터(날씨, 환율 등)를 계약에 입력 | 오라클 문제(데이터 신뢰성) 존재 |

> 요약: 고수준 언어로 작성된 코드가 가상 머신(EVM)에서 실행되며, 수수료(Gas)를 통해 자원 남용을 방지하는 구조다.

---

## Ⅲ. 동작원리 및 흐름도

```text
계약 작성/배포 -> 트랜잭션 발생(트리거) -> EVM 실행 -> 상태 변경 및 블록 기록 -> 결과 확정
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 계약 배포 | 코드를 컴파일하여 블록체인에 등록, 고유 주소 할당 | 배포 비용(Gas) 지불 |
| 2 | 트랜잭션 호출 | 사용자 또는 시스템이 계약의 특정 함수를 실행하는 신호 전송 | 발신자 서명 유효성 |
| 3 | 조건 검증 | 코드에 정의된 조건(If)이 현재 상태 또는 외부 데이터와 일치하는지 확인 | 데이터 정합성 |
| 4 | 자동 이행 | 조건 일치 시 자산 전송, 데이터 기록 등 정의된 로직 수행 | 연산 한도(Gas Limit) 내 수행 |
| 5 | 상태 갱신 | 실행 결과가 블록에 포함되어 전 세계 노드에 전파 및 동기화 | 블록 컨펌 수 확보 |

> 요약: 배포된 코드가 트랜잭션이라는 방아쇠에 의해 동작하며, 결과는 전역 상태(Global State)에 영구 기록된다.

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 자율성 (Autonomy) | 제3자의 개입 없이 독립적으로 계약 이행 | 중개 비용 제거 효과 |
| 불변성 (Immutability) | 한 번 배포된 코드는 수정이나 삭제가 불가능 | 보안 및 신뢰의 근간 |
| 투명성 (Transparency) | 모든 계약 내용과 실행 이력이 블록체인 상에 공개 | 사후 검증 및 감사 용이성 |
| 결정론적 (Deterministic) | 동일한 입력에 대해 항상 동일한 결과 출력 | 결과의 예측 가능성 |

> 요약: 코드가 법이 되는(Code is Law) 원칙 하에 운영되나, 이로 인한 수정 불가능의 리스크도 존재한다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 전통적 계약 | 스마트 계약 (Smart Contract) | 선택 기준 |
|:---|:---|:---|:---|
| 체결 방식 | 종이 문서, 서명, 인감 | 디지털 코드, 전자서명 | 거래의 디지털화 수준 |
| 이행 주체 | 인간, 사법 체계 | 컴퓨터 프로그램 (자동) | 이행 강제성 및 신속성 필요 시 |
| 수정 가능성 | 상호 합의 시 수정 용이 | 수정 매우 어려움 (업그레이드 패턴 필요) | 비즈니스 로직의 고정성 |
| 분쟁 해결 | 소송, 중재 (사후적) | 코드에 의한 자동 집행 (사전적) | 중개 비용 민감도 |

> 요약: 단순 반복적이고 조건이 명확한 거래일수록 스마트 계약의 효용이 극대화된다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 보안 취약점 | 재진입성(Reentrancy), 정수 오버플로 등 코드 버그 | 스마트 계약 오딧(Audit), 형식 검증(Formal Verification) | 오딧 리포트 통과 여부 |
| 오라클 리스크 | 외부 데이터 소스의 조작 또는 오류 | 탈중앙화 오라클(Chainlink 등) 사용, 다중 소스 교차 검증 | 데이터 소스 분산도 |
| 법적 분쟁 | 스마트 계약 실행 결과와 실제 법률 간의 충돌 | 하이브리드 계약(Ricardian Contract), 리걸 테크 연동 | 법적 효력 검토서 |

> 요약: 코드의 완결성을 위해 전문 보안 감사(Audit)와 데이터 신뢰성 확보(Oracle)가 선행되어야 한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 코드 보안성 | 주요 취약점 0건 | 자동 스캔 도구(Slither 등) 및 수동 오딧 |
| 실행 효율성 | 최소 가스비(Gas) 소모 최적화 | 가스 프로파일링 분석 |
| 오라클 지연 | 데이터 업데이트 주기 10초 이내 | 온체인 데이터 갱신 로그 |

> 요약: 도입 성과는 코드의 안전성 지표와 실행 비용(Gas) 효율성으로 측정한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 탈중앙화 금융(DeFi): 스마트 계약을 활용하여 담보 대출 비율을 실시간 계산하고, 담보 가치 하락 시 자동으로 청산을 수행하는 시스템 구축
2. 공급망 추적 관리: 제품이 특정 체크포인트를 통과할 때마다 스마트 계약이 물류 상태를 갱신하고, 최종 배송 시 대금을 자동 정산
3. 투명한 거버넌스(DAO): 주주 투표 결과를 스마트 계약이 집계하여, 가결된 안건(예: 자산 집행)을 사람의 개입 없이 즉시 실행

**결론 (2줄):**
- 기술사 판단: 스마트 계약은 비즈니스 프로세스의 혁명적 자동화를 제공하지만, '수정 불가능한 코드'라는 양날의 검을 제어하는 보안 역량이 필수적이다
- 향후 방향: 법률 지식이 반영된 인공지능 보조 도구를 통해 일반인도 안전하게 계약을 생성하는 '로우코드(Low-code) 스마트 계약' 시대가 열릴 것이다
