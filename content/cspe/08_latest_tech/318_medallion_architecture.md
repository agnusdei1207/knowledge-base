# 📖 【암기용】 개념 완전 이해

> 목적: 메달리온 아키텍처를 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 데이터 레이크하우스 내부에서 데이터를 품질과 가공 수준에 따라 3단계(Bronze, Silver, Gold)로 나누어 관리하는 데이터 설계 패턴
- **왜 필요한가**: 원본 데이터를 그대로 분석에 쓰면 품질이 엉망이라 결과가 틀리고, 매번 처음부터 가공하면 작업이 너무 중복된다. 단계를 나누어 '중간 저장소'를 만들면 품질 관리와 재사용성이 훨씬 좋아지기 때문이다.
- **핵심 직관**: "데이터의 원석(Bronze)을 깎아서 순도 높은 은(Silver)을 만들고, 마지막으로 반짝이는 금메달(Gold) 같은 완성품을 만드는 과정."

## 깊이 이해
- **배경·문제의식**: 데이터 레이크에 데이터를 무작정 쌓으면 '데이터 늪'이 됨. 어떤 데이터가 검증된 것인지 알 수 없음. 그렇다고 한 번에 완성본을 만들면 중간 과정의 로직을 나중에 수정하기 매우 힘듦.
- **작동 원리**: 데이터를 3단계 레이어로 논리적/물리적으로 분리함. ① **Bronze**: 원본 그대로(Raw). ② **Silver**: 오타 수정, 중복 제거, 형식 통일(Cleaned). ③ **Gold**: 비즈니스 목적에 맞게 합계, 평균 등을 계산(Aggregated). 각 단계는 Delta Lake 같은 트랜잭션 지원 포맷을 써서 안정성을 높임.
- **비유**: 식재료 손질 과정과 같음. 흙이 묻은 '무'(Bronze)를 가져와서, 씻고 껍질을 벗겨 '손질된 무'(Silver)를 만들고, 마지막으로 양념을 더해 '깍두기'(Gold)라는 요리를 완성하는 것. 누군가 '무 생채'를 만들고 싶다면 처음부터 무를 캐는 게 아니라 손질된 무(Silver)부터 시작하면 됨.
- **구체 예시**: 로그 데이터(Bronze)를 시간별로 정리하고 잘못된 값은 필터링함(Silver). 이후 이 데이터를 사용자별 방문 횟수로 집계하여 대시보드용 테이블(Gold)을 만듦.
- **흔한 오해·주의점**: 무조건 3단계여야 하는 건 아님. 회사의 복잡도에 따라 더 세분화하거나 합칠 수도 있지만, '품질 기반의 단계적 가공'이라는 철학이 중요함.

## 연결 개념
- Data Lakehouse - 메달리온 아키텍처가 주로 구현되는 플랫폼
- Delta Lake - 메달리온 각 단계의 트랜잭션을 보장하는 핵심 기술
- ETL/ELT - 데이터를 각 단계로 이동시키고 가공하는 프로세스

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 3대 레이어(Bronze, Silver, Gold)의 정의와 가공 목적, 그리고 각 단계 간의 데이터 정합성 유지 방안(트랜잭션 로그 등)을 기술적으로 논한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 메달리온 아키텍처는 데이터 레이크하우스 환경에서 데이터의 품질 성숙도와 가공 깊이에 따라 계층화(Bronze -> Silver -> Gold)하여 관리하는 논리적 데이터 설계 패턴이다.
> 2. **가치**: 데이터 가공 프로세스의 재사용성을 높이고, 원천 데이터 보존과 비즈니스 요구사항 사이의 간극을 단계적으로 해소하여 데이터 신뢰도를 확보한다.
> 3. **판단 포인트**: 각 레이어는 Delta Lake 등의 트랜잭션 지원 포맷을 활용하여 원자성(ACID)을 보장하고 데이터 엔지니어링의 생산성을 극대화한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 데이터 레이크하우스 설계 역량 확인 | 3단계 레이어(Bronze/Silver/Gold) 정의 및 특징 | 단순히 "단계별 가공"으로만 서술 지양 |
| 데이터 품질 및 거버넌스 체계 이해 | 각 레이어별 정제 수준, 스키마 관리, 접근 제어 | 물리적 구분과 논리적 구분을 혼동하지 말 것 |
| 실무적 아키텍처 적용 능력 | 증분 업데이트, 재처리(Reprocessing), 비용 효율성 | 특정 기술 명칭에만 매몰되지 않도록 주의 |

> 요약: 메달리온 아키텍처는 데이터의 원천 보존과 비즈니스 활용성을 단계적으로 연결하는 품질 관리 표준이다.

## Ⅰ. 개요 및 필요성

- 정의: 데이터의 정제 수준과 가용성에 따라 Bronze(Raw), Silver(Validated), Gold(Enriched) 3단계로 구분하는 계층형 데이터 아키텍처
- 배경: 데이터 레이크의 '데이터 늪(Swamp)' 현상 방지, 대규모 배치/스트리밍 데이터의 복잡한 가공 로직 관리 필요
- 필요성: 데이터 품질 사고 예방(Shift-left), 데이터 재가공 비용 절감(재사용성), 데이터 보안 및 권한 관리의 정교화

---

## Ⅱ. 구조 및 구성요소 (3-Layer 모델)

```text
[ Data Source ] -> [ Bronze Layer ] -> [ Silver Layer ] -> [ Gold Layer ]
      |                  |                  |                  |
      |             (1) Raw Data      (2) Cleaned Data    (3) Aggregated Data
      |             - 원형 보존        - 중복/오류 제거      - 비즈니스 요약
      |             - 장기 보관        - 표준화/통합        - 분석/BI용
      |
-------------------------------------------------------------------------
[ Metadata & Transaction Management: Delta Lake / Iceberg ]
```

| 레이어 | 주요 특징 | 처리 내용 |
|:---|:---|:---|
| Bronze (Raw) | 원천 데이터의 물리적 복사본 | 변경 없이 수집(Ingest), 스키마 정보 포함, 장기 보존 |
| Silver (Validated) | 데이터 정제 및 통합 레이어 | 타입 변환, 결측치 처리, 조인(Join), 필터링, SSOT 구축 |
| Gold (Enriched) | 비즈니스 목적별 집계 레이어 | 도메인별 요약, 성능 최적화(Denormalization), 대시보드 연동 |

> 요약: 데이터의 순도를 높여가며 각 단계별로 신뢰할 수 있는 중간 산출물을 생성하는 구조이다.

---

## Ⅲ. 동작원리 및 흐름도 (Data Pipeline Flow)

```text
Ingestion -> [ 1. Write Bronze ] -> [ 2. Refine & Silver ] -> [ 3. Aggregate & Gold ]
                    |                       |                       |
              (APPEND Only)           (Upsert/Merge)           (Batch/Overwrite)
                    |                       |                       |
              [ Time Travel ] <------- [ Checkpoint ] <------- [ Data Catalog ]
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | Raw 수집 | 외부 소스에서 데이터를 원형 그대로 Bronze 테이블에 적재 | 수집 누락 여부 (Checksum) |
| 2 | 정제 및 검증 | Silver 단계로 옮기며 스키마 위반, 중복, 비정상 값 필터링 | 데이터 품질 점수 (DQ Score) |
| 3 | 비즈니스 가공 | Silver 데이터를 조인하고 집계하여 Gold 테이블 생성 | 비즈니스 로직 정확성 |
| 4 | 거버넌스 적용 | 각 단계별로 접근 권한(보안)과 카탈로그 메타데이터 부여 | 보안 정책 준수 여부 |

> 요약: 각 단계는 트랜잭션 로그를 통해 연결되며, 장애 시 특정 단계부터 재처리가 가능한 구조로 동작한다.

## Ⅳ. 특징

| 구분 | 주요 특징 | 상세 내용 |
|:---|:---|:---|
| 데이터 일관성 | ACID 트랜잭션 | Delta Lake 등을 활용하여 가공 중 데이터 깨짐 방지 |
| 운영 효율성 | 재사용성 증대 | Silver 레이어가 구축되면 여러 Gold 레이어에서 공통 활용 가능 |
| 분석 유연성 | Time Travel | 과거 시점의 Bronze/Silver 데이터를 기반으로 로직 재검증 가능 |
| 보안 고도화 | 계층적 권한 제어 | 분석가는 Gold만, 엔지니어는 Bronze까지 접근하도록 차별화 |

> 요약: '단계별 신뢰'를 바탕으로 데이터 엔지니어링과 분석 업무의 분업 및 전문화를 촉진한다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 전통적 ETL (DW 중심) | 메달리온 아키텍처 (Lakehouse) | 선택 기준 |
|:---|:---|:---|:---|
| 데이터 저장 | 가공 후 저장 (Load) | 저장 후 가공 (ELT 중심) | 데이터 유실 방지 요건 |
| 원천 데이터 | 가공 후 폐기하는 경우 많음 | Bronze에 영구 보존 | 미래 재가공/AI 학습 필요성 |
| 유연성 | 스키마 변경 시 전체 재작성 | 단계별 부분 수정 및 재처리 가능 | 요구사항 변경 빈도 |
| 성능/비용 | 고성능 전용 스토리지 비용 | 저렴한 오브젝트 스토리지 활용 | 인프라 예산 및 데이터 규모 |

> 요약: 원천 보존과 유연한 재처리가 중요하다면 메달리온 아키텍처가 압도적으로 유리하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 스토리지 비용 증가 | 모든 단계의 중복 저장 | 보관 주기(TTL) 설정, Bronze 데이터 압축 | 스토리지 점유량 변화 |
| 파이프라인 지연 | 다단계 가공에 따른 대기 시간 | 증분 업데이트(Incremental) 및 스트리밍 처리 | End-to-End Latency |
| 품질 관리 부하 | 단계별 품질 체크 로직 파편화 | 공통 품질 프레임워크(Great Expectations 등) 적용 | 단계별 오류 탐지 시간 |

> 요약: '증분 처리'로 지연을 줄이고 '자동화된 품질 체크'로 신뢰도를 유지하는 것이 운영의 핵심이다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 데이터 최신성 | Gold 테이블 반영 지연 1시간 이내 | 파이프라인 모니터링 로그 |
| 데이터 재처리 속도 | 로직 수정 후 1개월치 재가공 2시간 이내 | 배치 작업 수행 시간 측정 |
| 데이터 신뢰도 | Silver/Gold 데이터 오염 발생 0건 | 자동 품질 검사 성공률 |

> 요약: 도입 효과는 데이터의 품질 안정성과 요구사항 변화에 대한 대응 속도로 평가한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. **스트리밍 메달리온**: Spark Structured Streaming을 사용하여 Bronze에서 Gold까지 데이터가 흐르듯 실시간 가공 처리
2. **샌드박스 환경 구축**: 데이터 과학자가 새로운 모델을 만들 때 Silver 데이터를 복사하여 자신만의 임시 Gold 테이블로 실험
3. **규제 준수(Audit)**: 감사 요구 시 Gold 결과값이 어떤 Silver 데이터를 거쳐 Bronze 원천에서 왔는지 리니지(Lineage)로 증명

**결론 (2줄):**
- 기술사 판단: 메달리온 아키텍처는 데이터 레이크하우스의 '거버넌스 청사진'이며, 데이터 팀의 협업과 품질 보증을 위한 표준 운영 체계이다.
- 향후 방향: AI가 데이터 특성을 파악하여 Bronze에서 Silver로의 정제 규칙을 자동 제안하는 '자율형 메달리온' 기술이 확산될 것이다.
