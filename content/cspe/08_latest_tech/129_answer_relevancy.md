# 📖 【암기용】 개념 완전 이해

> 목적: Answer Relevancy를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: 생성 답변이 사용자 질문의 의도와 범위에 얼마나 직접적으로 부합하는지 측정하는 RAG 평가 지표
- **왜 필요한가**: 답변이 근거 문서와 일치해도 질문을 비껴가면 사용자 문제를 해결하지 못함.
- **핵심 직관**: 참고자료대로 썼는지와 별개로, 물어본 것에 답했는지를 채점하는 항목임.

## 깊이 이해
- **배경·문제의식**: LLM은 근거 문서를 요약하느라 질문의 비교·설계·원인 분석 요구를 놓칠 수 있다. 이 경우 Faithfulness는 높아도 관련성은 낮다.
- **작동 원리**: 답변에서 역질문을 생성하거나 임베딩 유사도와 LLM Judge를 이용해 원 질문과 답변의 의미적 정합성을 평가함.
- **비유**: "비용 절감 방안"을 물었는데 기술 소개만 길게 쓰면 자료는 맞아도 답안은 틀린 것과 같음.
- **구체 예시**: Answer Relevancy 0.8 미만 답변은 질문 의도 누락으로 분류하고 프롬프트에 요구사항 재진술 단계를 추가함.
- **흔한 오해·주의점**: 관련성이 높아도 근거 없는 답변일 수 있다. Faithfulness와 함께 봐야 함.

## 연결 개념
- Faithfulness — 답변이 근거와 일치하는지 평가
- Intent Classification — 질문 의도와 요구사항 분류
- RAGAS — Answer Relevancy 자동 평가 지표 제공

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Answer Relevancy는 답변이 질문 의도와 요구사항에 직접 부합하는지 측정함.
> 2. **가치**: 근거는 맞지만 질문을 벗어난 답변을 탐지해 사용자 만족도와 업무 적합성을 높임.
> 3. **판단 포인트**: Faithfulness와 조합해 "근거 일치+질문 적합"을 동시에 확인해야 함.

## Ⅰ. 개요 및 필요성

- 개요: 질문과 답변의 관련성 지표
- 배경: RAG 답변은 근거 문서와 일치해도 질문 의도, 범위, 요구 형식을 충족하지 못할 수 있다.
- 필요성: 질문 재생성·semantic similarity·답변 직접성 평가로 Answer Relevancy score를 측정해 응답 품질을 관리한다.

## Ⅱ. 구조 및 구성요소

```text
Question + Answer -> Intent/Requirement Check
  -> Semantic Similarity/Judge -> Relevancy Score
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Question Analyzer | 질문 의도·요구사항 추출 | 비교, 설계, 원인, 방안 |
| Answer Analyzer | 답변 주제·범위 추출 | 핵심 주장·대상 식별 |
| Similarity/Judge | 질문-답변 부합도 평가 | embedding, LLM Judge |
| Score Aggregator | 관련성 점수 산정 | 0~1 범위, 0.8 이상 목표 |

> 요약: Answer Relevancy는 질문 요구사항과 답변 내용을 비교해 의도 충족 정도를 점수화함.

## Ⅲ. 동작원리 및 흐름도

```text
질문 입력 -> 의도/요구사항 추출 -> 답변 분석
  -> 의미 부합도 판정 -> 관련성 점수 -> 개선 조치
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 질문의 핵심 의도·제약 추출 | 요구사항 추출 F1 ≥0.85 |
| 2 | 답변의 주제·핵심 주장 추출 | 답변 분석 누락률 <5% |
| 3 | 질문-답변 관련성 평가 | Answer Relevancy ≥0.8 |
| 4 | 미달 답변 원인 분류 | 요구사항 누락률 <10% |

> 요약: 질문의 요구사항과 답변의 핵심 내용을 비교해 질문에 직접 답했는지 평가함.

## Ⅳ. 특징

| 구분 | Answer Relevancy | Faithfulness | 판단 포인트 |
|:---|:---|:---|:---|
| 평가 축 | 질문-답변 일치 | 답변-근거 일치 | 둘 다 충족해야 운영 가능 |
| 탐지 오류 | 동문서답·범위 이탈 | 근거 없는 주장 | 요구사항 문제는 Relevancy |
| 개선 대상 | 프롬프트·질의 이해 | 검색·근거 검증 | 원인별 개선 필요 |
| 목표 기준 | 0.8 이상 | 0.9 이상 | 도메인별 임계값 조정 |

> 요약: Answer Relevancy는 질문 적합성을 평가하며, 근거 기반성은 Faithfulness로 별도 확인해야 함.

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 프롬프트 개선: 답변 전 질문 요구사항을 1줄로 재진술하고, 비교·방안·설계 요구를 누락하지 않도록 체크리스트 삽입
2. 운영 게이트: Answer Relevancy 0.8 미만 답변은 재생성, 2회 미달 시 근거 부족 또는 질문 재확인 응답
3. 평가셋 관리: 문제 유형별로 설명형·비교형·설계형 300건씩 구성해 유형별 관련성 점수 측정

**결론 (2줄):**
- 기술사 판단: 사용자 의도 충족이 핵심인 챗봇·업무 도우미는 Answer Relevancy를 필수 KPI로 설정
- 향후 방향: 의도 분류기와 LLM Judge를 결합해 문제 유형별 관련성 평가로 고도화
