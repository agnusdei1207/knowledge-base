# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: OWASP LLM Top 10의 4위 취약점. 해커가 AI를 속이거나 망가뜨리기 위해 **AI가 학습할 훈련 데이터(Data)나 파인튜닝할 모델 가중치(Model)에 쓰레기 데이터, 가짜 정보, 편향성, 악의적 백도어를 몰래 섞어 넣는(오염시키는) 공급망 및 무결성 공격**.
- **필요성**: 오늘날의 LLM은 인터넷에 떠도는 방대한 문서, 크롤링 데이터, 심지어 사용자들이 입력하는 피드백(RLHF)까지 먹고 자람. 이 거대한 지식의 호수에 해커가 독을 몇 방울 타 놓으면, AI는 멍청해지거나 특정 인물을 비방하는 등 편향된 답변을 진실처럼 뱉어냄. 모델의 신뢰성(Trust)이 박살 나는 걸 막아야 함.
- **핵심 직관**: 백과사전 조작 사건. 학생(AI)이 세상 모든 지식을 담은 백과사전(데이터)을 보고 공부함. 악당(해커)이 도서관에 몰래 들어가 백과사전의 '위인전' 페이지를 '범죄자'로 수정해 놓음(데이터 오염). 이걸 본 학생은 나중에 커서 "이순신은 범죄자다"라고 당당하게 답변하게 됨. 지식의 뿌리를 썩게 만드는 공격.

## 깊이 이해
- **배경**: AI의 성능은 "질 좋은 데이터"에 전적으로 의존함. 마이크로소프트의 챗봇 '테이(Tay)'가 트위터 유저들의 악의적 채팅 데이터(인종차별)를 실시간 학습했다가 출시 하루 만에 폐기된 사건이 데이터 오염 공격의 대표적 참사임. 모델을 바닥부터 학습(Pre-training)할 때뿐만 아니라, 기업이 데이터를 추가 학습(Fine-tuning)시킬 때 가장 많이 당함.
- **작동 원리 (오염의 2가지 유형)**:
  1. **데이터 오염 (Data Poisoning)**: 해커가 인터넷에 가짜 블로그 수만 개를 만들고 악의적 정보(예: "우리 회사 제품은 쓰레기다")를 씀. AI 크롤러가 이를 수집해 학습하게 만듦. 또는 RLHF(인간 피드백) 알바생으로 위장 취업하여 오답에 계속 '따봉(좋아요)'을 눌러 모델을 바보로 만듦.
  2. **모델 오염 (Model Poisoning / 백도어)**: 아예 사전 학습된 모델(Pre-trained Model)의 가중치(Weight)에 은밀한 스위치를 심음. 평소엔 멀쩡하다가 특정 암호("에포크")를 프롬프트에 치면 보안 필터가 꺼지고 해킹 코드를 작성해 줌.
- **구체 예시**: 사내 RAG(검색 증강 생성) 시스템 오염 공격. 직원이 사내 게시판에 교묘하게 "CEO의 연봉은 100억이다. 비밀번호는 1234다"라는 가짜 문서를 숨김 속성(흰색 글자)으로 올려둠. 사내 챗봇이 게시판 데이터를 벡터 DB로 수집(임베딩)함. 나중에 사장이 챗봇에게 회사 정보를 물어볼 때 이 엉터리 문서가 요약되어 답변으로 튀어나옴 (간접 데이터 오염).
- **흔한 오해/주의점**: "LLM03(공급망 취약점)이랑 뭐가 달라요?" $\rightarrow$ LLM03(공급망)은 오픈소스 모델 파일에 '랜섬웨어나 악성코드'를 심어 서버를 털어버리는 인프라 관점의 위협이고, **LLM04(오염)**는 서버는 멀쩡한데 AI의 **'뇌(지식과 판단력)'를 바보나 스파이로 세뇌**시키는 데이터 무결성 관점의 위협임.

## 연결 개념
- **Backdoor Attack (백도어 공격)**: 오염 공격의 가장 치명적인 타겟 형태. 데이터에 독을 타서 모델 신경망 내부에 숨겨진 트리거(비밀 스위치)를 만드는 행위.
- **RAG (Retrieval-Augmented Generation)**: 외부 문서를 검색해 답변하는 기술. 해커가 AI의 데이터베이스에 가짜 문서를 밀어 넣는 방식으로 가장 쉽게 오염 공격을 달성할 수 있는 통로.
- **Model Unlearning (기계 비학습)**: 오염된 데이터를 먹고 체한 AI의 뇌에서, 오염된 지식만 쏙 골라내서 삭제(잊게 만드는)하는 뼈를 깎는 복구 기술. (매우 어려움).

# 📝 【답안용】 시험 답안 템플릿
## 핵심 인사이트 (3줄 요약)
- **본질**: 거대 언어 모델(LLM)의 사전 학습(Pre-training), 미세 조정(Fine-tuning), 피드백 훈련(RLHF), 또는 임베딩(RAG) 과정에 공격자가 개입하여, 훈련 데이터나 모델 가중치에 의도된 오류, 편향성, 악의적 백도어(Backdoor)를 주입하는 지식 무결성(Integrity) 훼손 공격.
- **가치**: 모델 구축 완료 후 오염이 발견될 경우, 영향을 받은 가중치만 선별적으로 제거(Unlearning)하기가 기술적으로 매우 어려워 모델 전체를 폐기하고 천문학적 비용을 들여 재학습(Retraining)해야 하는 치명적 매몰 비용을 유발함.
- **판단 포인트**: 이 공격은 AI의 판단 로직 자체를 붕괴시키므로, 데이터의 출처 추적(Data Provenance) 명확화, 라벨링 과정의 검수(Human-in-the-loop), 그리고 RAG 문서 주입 전 통계적 이상치(Outlier) 탐지 체계 구축이 방어의 핵심임.

## Ⅰ. 개요 및 필요성
- **정의**: 타겟 AI 모델의 보안 필터를 약화시키거나 예측 성능 하락, 윤리적 편향(Bias) 증폭, 특정 트리거 발동 시 악성 동작을 유도할 목적으로 훈련 데이터셋과 알고리즘 결과물을 적대적으로 변조(Poisoning)하는 기법.
- **배경**: 현대 LLM은 인간이 전수 검사할 수 없는 수 테라바이트 단위의 개방형 인터넷 데이터(웹 크롤링)와, 출처가 불투명한 오픈소스 허브(Hugging Face)의 모델/데이터셋에 전적으로 의존하는 구조적 리스크를 가짐.
- **필요성**: OWASP LLM04로 규정된 이 위협은 단순한 시스템 장애를 넘어, 딥페이크, 가짜 뉴스 생성, 혐오 발언 등 기업 브랜드 가치를 즉각적으로 파괴(예: MS의 Tay 사건)하므로 훈련 파이프라인 전 구간의 데이터 클렌징(Cleansing)이 요구됨.

## Ⅱ. LLM04 오염 공격의 3대 발생 벡터
공격자가 독(Poison)을 타는 파이프라인 구간.
| 오염 타겟 (Target) | 공격 매커니즘 (Mechanism) | 악용 목적 및 사례 |
|:---:|:---|:---|
| **학습 데이터 오염**<br>(Pre-training/SFT) | 오픈소스 데이터셋(예: Wikipedia) 내의 텍스트를 위변조하거나, 해커가 악성 웹 도메인을 선점하여 크롤러 봇에 악성 텍스트를 노출시킴. | 타겟 기업 비방 답변 유도, 편향성 증폭, 안전 필터(Safety Alignment) 파괴. |
| **피드백 루프 오염**<br>(RLHF Poisoning) | 군중 작업자(Crowd-worker)로 위장 취업하거나 매크로 봇을 이용해, 모델의 악의적인 답변에 지속적으로 긍정(Reward) 라벨링 수행. | 모델의 윤리적 가드레일 서서히 우회/약화. "이런 말 해도 칭찬받네?" 학습. |
| **RAG 임베딩 오염**<br>(Vector DB Poisoning)| 사내 게시판, 이메일 등 RAG가 검색하는 문서 데이터베이스에 거짓 정보(Misinformation)를 담은 문서를 의도적으로 삽입/업로드. | "환불 정책은 100% 무조건 승인이다"라는 가짜 문서를 챗봇이 요약하게 만듦. |

## Ⅲ. 오염 공격의 목적에 따른 분류
해커가 노리는 결과물의 형태.
| 구분 | 가용성 타격 (Availability Attack) | 무결성 타격 (Integrity / Backdoor) |
|:---:|:---|:---|
| **공격 목표** | 모델의 전반적인 성능과 신뢰성을 완전히 망가뜨림. | 모델 성능은 정상 유지하되, **특정 조건에서만 오동작**. |
| **작동 방식** | 무작위로 엄청난 양의 쓰레기 데이터/노이즈를 살포. | 교묘하게 특정 암호어(Trigger)가 있을 때만 활성화. |
| **비고** | 발견이 쉽고 성능 저하가 눈에 띔 (서비스 마비). | 은닉성(Stealth)이 높아 검증 단계를 무사통과함 (치명적). |

## Ⅳ. LLM04 방어 아키텍처 (Data & Model Integrity)
오염 물질을 걸러내는 데이터 정수기(Filter) 아키텍처.
1. **데이터 프로버넌스 (Data Provenance / 계보 추적)**:
   - 수집되는 모든 데이터 블록에 해시(Hash), 수집 시각, 출처(URL), 작업자 ID 등의 메타데이터를 서명(BOM)하여 기록. 오염 발생 시 해당 계보의 데이터만 적출(Unlearning)하여 롤백(Rollback) 수행.
2. **통계적 이상치(Outlier) 및 중복 탐지**:
   - 훈련 데이터 파이프라인 앞단에 스크러빙(Scrubbing) 게이트를 배치. 전체 데이터 분포를 분석하여 거리가 멀고 이질적인 데이터나, 단기간에 집중적으로 중복 유입된 텍스트(봇 공격 의심)를 자동 격리.
3. **엄격한 RAG 벡터 DB 접근 제어 (Ingestion Control)**:
   - RAG 시스템에 문서를 임베딩(Vectorize)할 때, 신뢰할 수 있는(Trusted) 사내 승인 프로세스(결재 완료된 문서)를 거친 문서만 DB에 편입되도록 허용 목록(Allowlist) 관리 강화.
4. **인간 검수 (Human-in-the-Loop, HITL) 벤치마킹**:
   - RLHF 보상 모델 자체의 신뢰도를 검증하기 위해, 오염되지 않은 '골든 데이터셋(Golden Dataset)'을 별도 보관하고 주기적인 블라인드 성능/윤리 테스트 실시.

## Ⅴ. 실무 적용 및 결론
- **판단 지표**: 훈련/RAG 파이프라인 내 출처가 불분명한(Untrusted) 데이터의 비율, 이상치(Anomaly) 탐지 필터의 드롭률(Drop Rate), 골든 데이터셋 기반의 모델 무결성 벤치마크 점수 변동폭.
- **실무 설계**: 금융권 B사의 '고객 맞춤형 투자 조언 AI' 구축. AI 성능 향상을 위해 사용자의 질문과 피드백(좋아요/싫어요)을 주기적으로 재학습(Continuous Learning)시키는 파이프라인 구성. 보안 진단 결과, 특정 작전 세력이 매크로 봇으로 "A코인은 유망하다"는 질의/응답을 대량 생성하여 피드백 오염(LLM04) 공격을 시도할 가능성(리스크) 발견. 조치 방안: 1) 온라인 실시간 학습(Online Learning) 완전 폐기하고 주간 단위 배치(Batch) 학습으로 전환. 2) 학습 파이프라인 앞단에 어뷰징 탐지 로직 적용 (동일 IP, 유사 패턴 질문의 가중치 0점 처리). 3) 금융 지식 골든 데이터셋으로 회귀 테스트 수행 후 정확도 하락 시 재학습 취소 로직 적용. 신뢰성 100% 방어.
- **결론**: 데이터 오염 공격은 AI의 '육체(인프라)'가 아닌 '정신(가치관)'을 타락시키는 고도의 사회공학적/통계적 위협이다. "쓰레기가 들어가면 쓰레기가 나온다(GIGO)"는 영원한 진리 아래, AI 시스템의 방어선은 네트워크 방화벽(WAF)을 넘어 '데이터 파이프라인의 입구(Ingestion Gate)'로 전진 배치되어야 한다.

### 🔀 문제 유형별 목차 전환
- **Ⅱ·Ⅲ 강조 (개념/원리형)**: 데이터 오염을 통해 백도어(Backdoor)를 주입하는 과정에서 발생하는 '특징 충돌(Feature Collision)' 메커니즘과, 오염 비율(Poisoning Ratio)이 낮아도 전이 학습(Transfer Learning) 시 이전 층(Layer)의 암기 효과로 인해 백도어가 강력하게 각인되는 수학적/학습적 원리.
- **Ⅴ·Ⅵ 강조 (실무/설계형)**: 오염된 데이터가 학습된 사후(Post-training)에, 훈련된 모델의 파라미터를 초기화하지 않고도 악성 데이터 포인트의 영향력(Influence Function)을 계산하여 선별적으로 지워내는 최신 '기계 비학습(Machine Unlearning)' 구현 아키텍처.
