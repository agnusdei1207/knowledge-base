# 📖 【암기용】 개념 완전 이해

> 목적: LLM04 Data and Model Poisoning을 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: LLM의 사전학습·파인튜닝·RAG·임베딩 데이터 또는 모델 가중치를 오염시켜 출력과 행동을 왜곡하는 위험
- **왜 필요한가**: LLM은 웹 데이터, 사용자 피드백, 외부 문서, 공개 모델을 사용하므로 공격자가 학습·검색 재료에 개입할 수 있음.
- **핵심 직관**: AI가 읽고 배우는 교재와 참고문헌에 악성 내용을 섞어 답변 습관을 바꾸는 공격임.

## 깊이 이해
- **배경·문제의식**: 생성형 AI는 데이터 규모가 크고 출처가 다양해 일부 오염 샘플이 들어가도 수동 검토로 찾기 어려움.
- **작동 원리**: 공격자는 학습 데이터, fine-tuning 샘플, RAG 문서, embedding index, 모델 가중치에 악성 패턴을 삽입함.
- **비유**: 백과사전 일부 페이지에 거짓 정보를 심어두면 그 책을 참고하는 사람이 계속 틀린 답을 하게 되는 구조임.
- **구체 예시**: 고객지원 RAG 문서에 악성 환불 정책을 삽입해 특정 상품 문의 시 잘못된 환불 안내를 출력하게 함.
- **흔한 오해·주의점**: 오염은 학습 단계만이 아니라 RAG 지식베이스 갱신, 벡터 인덱스, 피드백 재학습에서도 발생함.

## 연결 개념
- Data Poisoning — 학습 데이터 오염 공격
- Backdoor Attack — 특정 트리거 기반 오동작
- Vector and Embedding Weaknesses — RAG·임베딩 계층 취약점

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: LLM04는 데이터와 모델 산출물 오염으로 LLM 응답·행동을 왜곡하는 위험임.
> 2. **가치**: 잘못된 지식, 백도어, 편향, 보안정책 우회가 생성형 AI 서비스에 내재화됨.
> 3. **판단 포인트**: 데이터 계보, 모델 무결성, RAG 문서 승인, 오염 탐지를 MLOps에 포함해야 함.

## Ⅰ. 개요 및 필요성

- 개요: LLM 데이터·모델 오염 위험이다.
- 배경: LLM은 학습 데이터, RAG 문서, 모델 가중치에 의존해 응답과 도구 실행 계획을 생성한다.
- 필요성: LLM04는 provenance check, poisoning detection, rollback 기준으로 오염된 지식과 모델을 차단한다.

## Ⅱ. 구조 및 구성요소

```text
Training/RAG Data -> Poisoned Sample/Model -> LLM Pipeline
  -> Distorted Response -> Detection & Rollback
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Data Source | 학습·파인튜닝·RAG 입력 | provenance 필요 |
| Poison Pattern | 악성 문서·라벨·트리거 | low-rate 가능 |
| Model Artifact | 가중치·adapter·embedding | 무결성 검증 |
| Rollback | 오염 제거·이전 버전 복구 | versioning 필수 |

> 요약: LLM04는 데이터·모델 입력 경로의 오염이 LLM 파이프라인을 거쳐 왜곡 응답으로 나타나는 구조임.

## Ⅲ. 동작원리 및 흐름도

```text
출처 검증 -> 오염 탐지 -> 격리 학습·색인
  -> 응답 평가 -> 롤백·재학습
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 데이터·모델 출처와 버전 기록 | provenance 100% |
| 2 | 이상치·라벨·문서 무결성 검사 | Critical 0건 |
| 3 | 격리 환경에서 학습·RAG 색인 | approval workflow |
| 4 | 독립 평가셋과 오염 공격 테스트 | ASR 1% 이하 |

> 요약: LLM04 방어는 출처 추적, 오염 탐지, 격리 평가, 롤백 체계를 통해 데이터·모델 무결성을 유지함.

## Ⅳ. 특징

| 구분 | 일반 Data Poisoning | LLM04 Data and Model Poisoning | 판단 포인트 |
|:---|:---|:---|:---|
| 범위 | 학습 데이터 중심 | 학습·RAG·embedding·model artifact | 전 파이프라인 |
| 피해 | 분류 오동작 | 왜곡 답변·백도어·정책 우회 | 생성형 영향 |
| 탐지 | 이상치·라벨 검사 | 문서 출처·응답 평가·ASR | RAG 포함 |
| 복구 | 데이터 정제·재학습 | 인덱스 롤백·모델 재배포 | 버전관리 |

> 요약: LLM04는 학습 데이터뿐 아니라 RAG와 모델 산출물까지 포함하는 생성형 AI 무결성 위험임.

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 데이터 거버넌스: RAG 문서와 fine-tuning 샘플에 owner, 출처, hash, 승인자, 민감도 등급을 기록
2. 오염 탐지: 이상치 탐지, 중복·라벨 품질 검사, trigger fuzzing, 응답 회귀 테스트를 배포 전 수행
3. 복구 체계: vector index와 모델 artifact를 버전관리하고 오염 발견 시 15분 내 이전 버전 롤백 절차 적용

**결론 (2줄):**
- 기술사 판단: LLM04 대응은 학습 데이터 검증에 RAG 문서 승인과 모델 artifact 무결성 검사를 추가해야 함
- 향후 방향: Data and Model Poisoning 방어는 AI SBOM, data lineage, continuous evaluation과 통합됨
