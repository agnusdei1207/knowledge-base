## 미리 알고가기

- SMPC는 여러 참여자가 서로의 원본 데이터를 공개하지 않고 공동 계산 결과만 얻도록 하는 프로토콜임
- 신뢰할 제3자 없이 계산한다는 점이 핵심이며 통신 라운드 비용이 큰 설계 변수임
- Semi-honest와 malicious 위협 모델을 구분해야 성능과 보안 수준을 올바르게 판단할 수 있음

## Ⅰ. 개요

- **정의/개념**: 안전한 다자간 연산은 복수의 참여자가 각자 가진 비밀 입력을 드러내지 않은 채 합계와 교집합과 모델 계산 같은 공동 함수의 결과만 안전하게 도출하는 암호 프로토콜임
- **배경/필요성**: 기관 간 데이터 결합 가치가 커졌지만 법규와 영업기밀 때문에 원본 데이터 공유가 어려워져, 비밀을 유지한 상태로 공동 분석할 수 있는 방식이 필요해짐

## Ⅱ. 특징

- 신뢰할 제3자 없이도 공동 계산을 수행해 데이터 주권을 유지하기 쉬움
- 합계와 교집합과 간단한 ML 계산 등 협업 분석에 직접 활용할 수 있음
- 프로토콜 복잡도와 통신 라운드 수가 커지면 대규모 환경에서 성능 병목이 생김
- 참여자 위협 모델이 강해질수록 검증 비용과 연산량이 빠르게 증가함

## Ⅲ. 종류 및 비교

| 판단 기준 | Secret Sharing SMPC | Garbled Circuit SMPC | HE 기반 협업 |
|:---|:---|:---|:---|
| 강점 | 산술 연산에 효율적 | 불리언 로직에 유리 | 서버 위탁 계산에 유리 |
| 통신 부담 | 중간 | 큼 | 상대적으로 적음 |
| 다자 확장성 | 높음 | 낮음 | 중간 |
| 대표 활용 | 보안 집계, PSI 변형 | 2자 비교, 조건 판단 | 암호화 외부 계산 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Parties, Private Inputs | 각 참여자가 원본 데이터를 로컬에 보유한 채 계산에 필요한 입력만 제공함 |
| Input Sharing, Encoding | 입력을 비밀 조각이나 회로 입력 형태로 변환해 직접 노출 없이 계산 가능하게 만듦 |
| Secure Protocol Engine | 덧셈과 곱셈과 비교 같은 중간 연산을 안전하게 수행하는 프로토콜 계층임 |
| Output Reconstruction | 최종 결과만 복원하고 중간값이나 타인의 입력은 알 수 없도록 제한함 |
| Threat Assumption, Audit | 반정직 또는 악의적 참여자 모델에 맞춰 검증과 로깅 수준을 조정함 |

```text
+-------------------+      +-------------------+      +-------------------+
| Private Inputs    | ---> | Share / Encode    | ---> | Secure Protocol   |
+-------------------+      +-------------------+      +-------------------+
                                                           |
                                                           v
                                                   +-------------------+
                                                   | Reconstruct Output|
                                                   +-------------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 입력 분할/공유   | --> | 안전한 중간 연산 | --> | 결과 조각 합성  | --> | 최종 결과만 공개  |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **입력 분할 및 공유**: 각 참여자가 입력을 안전한 조각으로 나눔
2. **안전한 중간 연산**: 프로토콜에 따라 조각 상태로 계산을 진행함
3. **결과 조각 합성**: 최종 결과에 필요한 조각만 합침
4. **최종 결과만 공개**: 필요한 계산 결과만 복원해 공유함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 참여자 수와 계산 복잡도가 커질수록 통신 라운드와 대역폭이 급증해 실시간 활용이 어려워질 수 있음
   - 해결방안: protocol specialization과 batching을 적용하고 rounds per task와 network overhead로 검증함
2. 문제: 악의적 참여자가 잘못된 조각을 보내면 결과 무결성이 깨질 수 있음
   - 해결방안: malicious-secure protocol과 consistency proof를 적용하고 integrity failure rate와 verification cost로 검증함
3. 문제: 회로나 연산 표현을 잘못 선택하면 단순 계산도 과도하게 무거워져 비용 대비 효과가 낮아질 수 있음
   - 해결방안: arithmetic와 boolean circuit을 목적별로 최적화하고 compute time과 resource utilization로 검증함

## Ⅶ. 적용 사례

- 금융사와 통신사가 공통 고객의 위험 신호를 공동 분석하며 확인 지표는 protocol latency와 privacy incident rate임
- 병원 연합이 환자 식별정보를 공개하지 않고 교집합 코호트를 계산하며 확인 지표는 PSI correctness와 data exposure rate임
- 연합학습 보안 집계가 개별 파라미터를 숨긴 채 평균 업데이트를 계산하며 확인 지표는 secure aggregation success rate와 round overhead임

## Ⅷ. 결론

SMPC는 데이터를 공유하지 않고 결과만 공유하게 만드는 강력한 협업 계산 기술이므로 위협 모델과 통신 비용을 함께 고려한 프로토콜 선택이 핵심임.
