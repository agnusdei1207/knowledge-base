# 📖 【암기용】 개념 완전 이해

> 목적: Secure Multi-Party Computation을 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: 여러 참여자가 각자 입력값을 공개하지 않고 공동 함수 결과만 계산하는 암호 프로토콜
- **왜 필요한가**: 기업·기관 간 데이터 결합 분석은 필요하지만 원천 데이터와 영업비밀 공개는 제한됨.
- **핵심 직관**: 서로의 숫자는 보지 않고 합계·교집합·모델 결과만 함께 계산하는 방식임.

## 깊이 이해
- **배경·문제의식**: 금융사와 통신사, 병원과 연구기관처럼 데이터 소유자가 다르면 중앙 집중 결합이 법·계약상 어려움.
- **작동 원리**: secret sharing, garbled circuit, oblivious transfer 등을 사용해 입력을 조각내고 계산 결과만 복원함.
- **비유**: 각자가 비밀 재료를 공개하지 않고 공동 레시피의 최종 맛 점수만 계산하는 회의임.
- **구체 예시**: 은행 5곳이 고객 원장을 공개하지 않고 사기 의심 계좌 교집합과 위험 점수만 계산함.
- **흔한 오해·주의점**: SMPC는 통신 라운드와 참여자 수에 민감하다. 실시간 대규모 추론보다 제한된 결합·분석에 먼저 적용함.

## 연결 개념
- Homomorphic Encryption — 암호문 단독 연산 방식
- Private Set Intersection — 교집합을 숨겨 계산하는 SMPC 응용
- Privacy-Preserving AI — 기관 간 AI 학습·분석 보호 체계

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: SMPC는 참여자 입력값 비공개 상태에서 공동 함수 결과만 계산하는 암호 프로토콜임.
> 2. **가치**: 기관 간 데이터 결합·분석에서 원천 데이터와 영업비밀 노출을 제한함.
> 3. **판단 포인트**: 함수 복잡도, 참여자 수, 통신 round, 위협 모델을 사전에 정의해야 함.

## Ⅰ. 개요 및 필요성

SMPC는 입력 비공개 공동 계산 기술이다. 기관 간 데이터 협업은 원천 데이터 공개와 재식별 위험을 수반한다. 공동 분석 결과만 공유하는 암호 프로토콜이 필요하다.

## Ⅱ. 구조 및 구성요소

```text
Party Input → Secret Sharing/Garbled Circuit
  → Joint Computation → Result Reconstruction
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Party | 각 기관 입력 보유 | 원문 비공개 |
| Secret Share | 입력값 분산 조각화 | threshold 설정 |
| Protocol Engine | 공동 함수 계산 | garbled circuit, OT |
| Result | 허용된 결과만 복원 | 합계·교집합·점수 |

> 요약: SMPC는 각 참여자의 입력을 비밀 조각으로 나누고 공동 함수 결과만 복원함.

## Ⅲ. 동작원리 및 흐름도

```text
위협 모델 수립 → 입력 분할 → 프로토콜 실행
  → 결과 복원 → 감사 기록
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | semi-honest/malicious 모델 정의 | 참여자 계약 반영 |
| 2 | 입력값 secret sharing 수행 | 원문 공유 0건 |
| 3 | 공동 함수 프로토콜 실행 | 통신 round 측정 |
| 4 | 결과 복원·검증·폐기 | 중간 share 즉시 폐기 |

> 요약: SMPC는 위협 모델과 함수 범위를 정한 뒤 입력 비공개 상태로 공동 계산을 수행함.

## Ⅳ. 특징

| 구분 | 중앙 데이터 결합 | Secure MPC | 판단 포인트 |
|:---|:---|:---|:---|
| 데이터 공개 | 중앙기관에 원문 제공 | 입력값 비공개 | 신뢰 최소화 |
| 계산 범위 | SQL·분석 자유도 높음 | 사전 정의 함수 중심 | 업무 범위 제한 |
| 비용 | 인프라 단순 | 통신 round·암호 비용 | 참여자 수 영향 |
| 위험 | 중앙 유출·재식별 | 프로토콜 구현 취약점 | 검증된 라이브러리 |

> 요약: SMPC는 중앙 신뢰기관 의존을 줄이지만 계산 범위와 통신 비용을 기준으로 적용해야 함.

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 금융 사기탐지: 은행 간 고객 원장 미공개 상태로 Private Set Intersection과 위험 점수 계산 수행
2. 의료 연구: 병원별 환자 원문을 공유하지 않고 질병 통계 합계와 모델 feature 통계만 산출
3. 운영 통제: semi-honest/malicious 위협 모델, 결과 항목, share 폐기 시간, 감사 로그를 계약서에 명시

**결론 (2줄):**
- 기술사 판단: 원천 데이터 공유가 불가능한 기관 간 협업은 SMPC를 적용하되 함수 범위와 통신 비용을 먼저 산정
- 향후 방향: SMPC는 FL, DP, 동형암호와 결합해 데이터 협업의 프라이버시 보존 기본 구성요소가 됨
