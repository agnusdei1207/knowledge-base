# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: 두 명 이상의 참여자가 **자기 데이터의 진짜 값(비밀)을 상대방이나 제3자에게 절대 보여주지 않고도**, 오직 데이터를 가지고 "계산한 결과값(합계, 교집합 등)"만 함께 알아내는 신기한 암호학적 프로토콜.
- **필요성**: A은행과 B통신사가 서로의 고객 데이터를 결합해 AI를 만들고 싶음. 하지만 고객 명부를 통째로 서로에게 넘기거나 제3의 회사에 맡기는 건 불법이거나 영업비밀 유출임. "서로 패를 까지 않고, 원하는 결과만 얻을 수 없을까?"라는 비즈니스 니즈를 해결함.
- **핵심 직관**: 백만장자 문제(Millionaires' Problem). 두 부자가 만남. "우리 둘 중에 누가 더 부자인지 알고 싶어. 하지만 내 전 재산이 정확히 얼마인지는 너한테 절대 말해주기 싫어!" 이때 SMPC 프로토콜을 쓰면 "A가 B보다 부자임"이라는 결과만 짠! 하고 나오고, 구체적 금액은 영원히 비밀로 유지됨.

## 깊이 이해
- **배경**: 1982년 앤드류 야오(Andrew Yao)가 앞서 말한 '백만장자 문제'를 제안하며 도입된 개념. 최근 의료, 금융 데이터의 이종 결합(Data Silo 타파) 니즈가 폭발하면서 다시 핵심 기술로 급부상함.
- **작동 원리 (비밀 분산, Secret Sharing)**:
  1. 철수 월급 100만 원, 영희 월급 200만 원. 둘의 합계를 알고 싶음.
  2. **분산(Share)**: 철수는 100을 비밀스러운 두 개의 무작위 조각(예: 300과 -200)으로 쪼갬. 영희도 200을 두 조각(예: -50과 250)으로 쪼갬.
  3. **교환**: 철수는 자기가 가진 한 조각(-200)을 영희에게 줌. 영희도 한 조각(250)을 철수에게 줌.
  4. 이제 철수가 가진 숫자(300, 250)와 영희가 가진 숫자(-200, -50)만으로는 상대의 월급을 절대 유추할 수 없음(완벽한 쓰레기 값).
  5. **부분 합산 및 결과 복원**: 철수는 자기 손에 있는 숫자를 더함(550). 영희도 더함(-250). 이제 둘이 각자 계산한 이 덩어리 값을 합치면 (550 - 250 = 300). 진짜 월급의 합계 300만 원이 마법처럼 도출됨!
- **구체 예시**: 교집합 구하기(PSI). 경찰청이 수배자 명단 100명을 가짐. 호텔에 투숙객 명단 100명이 있음. 경찰은 100명 명단을 호텔에 주기 싫고(수사기밀), 호텔도 투숙객 전부를 경찰에 넘길 수 없음(개인정보). SMPC 기반의 PSI를 돌리면, 딱 겹치는 수배자 2명의 이름만 튀어나오고 나머지 98명은 서로 절대 알 수 없음.
- **흔한 오해/주의점**: "참여자 중 한 명이 작정하고 가짜 값을 섞어버리면 어떡함?" $\rightarrow$ 결과가 망가짐. 그래서 SMPC는 참여자들이 '가짜 값을 넣지는 않되, 서로의 데이터는 미친 듯이 훔쳐보려 하는(Semi-honest)' 수준의 관계일 때 가장 잘 작동함. 완전 악의적인(Malicious) 공격자까지 막으려면 연산이 기하급수적으로 느려짐.

## 연결 개념
- **Homomorphic Encryption (동형암호)**: 동형암호는 '혼자서' 암호문 연산을 클라우드에 맡길 때 쓰고, SMPC는 '여러 명이' 동등한 위치에서 서로의 값을 숨기고 연산할 때 씀.
- **Federated Learning (연합학습)**: 연합학습에서 노드들의 가중치를 안전하게 합칠 때 사용하는 Secure Aggregation이 바로 이 SMPC(Secret Sharing) 기술을 응용한 것임.
- **Zero-Knowledge Proof (영지식 증명)**: SMPC와 비슷해 보이지만 다름. 영지식 증명은 "나 100만 원 이상 있어(사실 증명)"를 보여주는 것이고, SMPC는 "우리 둘 돈을 합치면 얼마게?(공동 연산)"를 하는 것임.

# 📝 【답안용】 시험 답안 템플릿
## 핵심 인사이트 (3줄 요약)
- **본질**: 상호 신뢰할 수 없는 복수의 참여자(Multi-party)들이 각자의 로컬 데이터를 외부로 노출하지 않은 상태에서, 약속된 공동 함수(Joint Function)의 계산 결과만을 안전하게 도출하는 분산 암호학 프로토콜.
- **가치**: 신뢰할 수 있는 제3자(TTP, Trusted Third Party: 결합전문기관 등)에 데이터를 위탁할 필요 없이 기관 간(Cross-silo) 데이터 프라이버시 보호 결합을 완수하여 데이터 독점 문제를 해소함.
- **판단 포인트**: SMPC 아키텍처는 통신 라운드(Communication Round)가 폭증하는 태생적 오버헤드가 존재하므로, 연산 로직을 산술 회로(Arithmetic Circuit)와 불리언 회로(Boolean Circuit) 중 목적에 맞게 최적화하는 프로토콜 선택(예: Yao's Garbled Circuit vs Secret Sharing)이 필수적임.

## Ⅰ. 개요 및 필요성
- **정의**: $N$명의 참여자가 각자의 비밀 입력값 $x_i$를 가지고 있을 때, 어떤 참여자도 다른 사람의 $x$를 알지 못한 채 공동의 함수 $f(x_1, x_2, ..., x_n)$의 결과 $Y$만을 도출하는 안전한 통신 연산 기술.
- **배경**: AI 학습 파이프라인과 이상거래탐지(FDS) 고도화를 위해 산업 간(금융-통신-의료) 데이터 융합 니즈가 커졌으나, 개인정보보호법 및 망분리 규제로 인해 데이터 웨어하우스의 물리적 통합이 불가능함.
- **필요성**: 데이터 원문을 복호화해 줄 TTP(신뢰 기관)를 거치지 않는 'TTP-free' 환경을 구축하여 데이터 유출 단일 장애점(SPoF)을 제거하고, 연합 분석의 합법성과 보안성을 동시에 확보하기 위함.

## Ⅱ. SMPC를 구현하는 2대 핵심 암호학적 기법
데이터를 조각내거나 회로를 꼬아버리는 기술.
| 구현 기법 | 작동 원리 (Mechanism) | 활용 분야 및 장단점 |
|:---:|:---|:---|
| **비밀 분산**<br>(Secret Sharing) | 원본 데이터를 아무 의미 없는 난수 조각(Share)들로 쪼개어 참여자들에게 나누어 줌. 참여자들은 이 조각들을 덧셈/곱셈 연산한 뒤 모아서 최종 결과를 복원함. | - **장점**: 연산 속도가 빠름.<br>- **단점**: 참여자가 3명 이상 다자간 연산에 유리함 (산술 연산 특화). |
| **혼돈 회로**<br>(Garbled Circuit) | 함수(계산식)를 AND/OR 게이트 등의 논리 회로로 만든 뒤, 각 게이트의 진리표(입출력 값)를 난수 라벨로 꼬아버림(Garbling). 상대방은 자기가 무슨 계산을 하는지도 모른 채 회로를 통과시킴. | - **장점**: 어떤 복잡한 함수도 계산 가능.<br>- **단점**: 주로 2자 간(2-Party) 계산에 최적화, 통신 오버헤드가 거대함. |

## Ⅲ. SMPC의 위협 모델 (Threat Models)
참여자가 어떤 성향을 가지느냐에 따른 프로토콜 설계 기준.
1. **Semi-Honest (반정직, Honest-but-curious) 모델**:
   - 참여자들이 프로토콜 규칙(계산 순서 등)은 성실히 따르지만, 오고 가는 데이터를 훔쳐보면서 상대방의 정보를 알아내려고 기를 쓰는 상황.
   - $\rightarrow$ **실무에서 가장 많이 쓰이는 현실적 타협점** (기업 간 B2B 연합 시). 속도가 상대적으로 빠름.
2. **Malicious (악의적) 모델**:
   - 참여자가 프로토콜을 무시하고 가짜 데이터를 섞거나 중간에 통신을 끊어버리는 능동적 공격을 가하는 상황.
   - $\rightarrow$ 영지식 증명(ZKP)을 결합해 매 단계마다 정직성을 검증해야 하므로 오버헤드(속도 저하)가 기하급수적으로 증가함.

## Ⅳ. 주요 응용 사례: 프라이빗 교집합(Private Set Intersection, PSI)
SMPC의 가장 강력하고 상용화된 Use-Case.
- **개념**: 두 집합(A, B) 간의 교집합(A ∩ B)만을 식별하고, 교집합에 속하지 않는 나머지 원소들은 서로에게 절대 노출하지 않는 기술.
- **응용 아키텍처**:
  - **마이데이터(MyData) / 핀테크**: A카드사와 B통신사가 공통된 고객(교집합)만 추출하여 공동 마케팅 모델을 돌릴 때, 비고객 명단을 서로에게 유출하는 것을 원천 차단.

## Ⅴ. 실무 적용 및 결론
- **판단 지표**: 통신 라운드(Round Trip) 수에 따른 Network Bandwidth 소모량, 위협 모델(Semi-honest) 수용에 대한 참여 기관 간의 보안 서약서 및 거버넌스 체결 여부.
- **실무 설계**: 금융보안원 주도의 '범금융권 자금세탁(AML) 방지 연합망' 구축. A, B, C 은행이 각각 의심 계좌(블랙리스트)를 가지고 있으나, 타행에 고객 정보를 넘길 수 없음. 3자 간 SMPC(Secret Sharing 기반) 아키텍처 도입. 각 은행은 의심 계좌 번호를 3개의 난수 조각으로 쪼개어 서로 교환. 각자의 서버에서 부분 연산을 수행한 후, 그 결과값만 금융보안원에서 합산(Reconstruction). 결과적으로 "특정 계좌가 3개 은행 모두에서 이상 거래를 발생시켰음"이라는 최종 위험 스코어만 식별하고 수사기관에 통보. 원본 거래 내역 노출 제로(0).
- **결론**: 안전한 다자간 연산(SMPC)은 정보의 '공유(Sharing)' 없이 정보의 '가치(Value)'만을 교환하게 해주는 암호학적 기적이다. 데이터의 소유권(Silo)이 그 어느 때보다 강력해진 현재, 기업들은 경쟁사와도 데이터를 융합하여 더 큰 AI 가치를 창출해야 하는 모순된 비즈니스 환경에서 SMPC를 최우선 솔루션으로 채택해야 한다.

### 🔀 문제 유형별 목차 전환
- **Ⅱ·Ⅲ 강조 (개념/원리형)**: Oblivious Transfer(불확정 전송) 기술이 Yao의 Garbled Circuit에서 Evaluator가 Generator의 의도를 파악하지 못하게 키(Key)를 전송하는 수학적/암호학적 매커니즘 심층 분석.
- **Ⅴ·Ⅵ 강조 (실무/설계형)**: 연합학습(FL) 환경에서 클라이언트가 서버로 파라미터를 전송할 때 발생하는 Gradient Leakage를 방어하기 위해 SMPC를 Secure Aggregation(보안 집계) 엔진으로 연동하는 MLOps 파이프라인 설계.
