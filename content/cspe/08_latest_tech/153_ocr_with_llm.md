# 📖 【암기용】 개념 완전 이해

> 목적: OCR with LLM을 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: OCR로 추출한 텍스트·좌표·레이아웃 정보를 LLM이 의미 구조로 해석하는 문서 이해 방식
- **왜 필요한가**: OCR은 글자를 읽지만, LLM은 그 글자가 계약 금액인지, 납기일인지, 예외 조항인지 해석할 수 있음.
- **핵심 직관**: OCR은 눈으로 글자를 읽는 역할, LLM은 읽은 내용을 업무 문맥으로 이해하는 역할임.

## 깊이 이해
- **배경·문제의식**: 스캔 문서와 PDF는 OCR 결과가 순서 뒤섞임, 표 깨짐, 헤더 반복, 오탈자 문제를 가진다. LLM은 문맥을 이용해 구조화와 보정을 수행할 수 있음.
- **작동 원리**: OCR 결과와 bounding box, layout block을 LLM 프롬프트나 VLM 입력으로 제공하고, JSON schema에 맞춰 필드 추출·요약·검증을 수행함.
- **비유**: 스캐너가 글자를 읽어주면, 숙련된 사무 담당자가 "이 줄은 총액, 이 줄은 공급자, 이 표는 품목 목록"이라고 정리하는 과정임.
- **구체 예시**: 계약서 OCR 결과에서 LLM이 당사자, 계약기간, SLA, 위약금 조항을 JSON으로 추출하고 confidence 0.8 미만은 검수 큐로 전달.
- **흔한 오해·주의점**: LLM은 OCR 오류를 그럴듯하게 보정하면서 없는 내용을 만들 수 있음. 원문 좌표와 citation 검증이 필요함.

## 연결 개념
- Document AI — 문서 구조화 전체 파이프라인
- Table Understanding — OCR 표를 구조화하는 세부 태스크
- Groundedness — LLM 추출 결과가 원문 OCR 근거와 일치하는지 검증

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: OCR with LLM은 OCR 결과를 LLM이 문맥 기반으로 구조화·요약·검증하는 방식임.
> 2. **가치**: 양식이 다양한 문서에서도 필드 추출과 업무 의미 해석을 유연하게 수행함.
> 3. **판단 포인트**: 원문 좌표 citation, JSON schema 검증, hallucination 방지 프롬프트가 필수임.

## Ⅰ. 개요 및 필요성

OCR with LLM은 문자 인식과 언어 이해를 결합한 문서 AI 방식임. OCR 단독은 문자 추출에 그치고 문서 의미·필드 관계를 해석하지 못한다. LLM은 OCR 결과를 업무 스키마에 맞게 구조화한다.

## Ⅱ. 구조 및 구성요소

```text
Document → OCR(text+bbox) → Layout Blocks
  → LLM Schema Extraction → Validation → JSON/Citation
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| OCR Engine | 텍스트와 좌표 추출 | word box, confidence |
| Layout Serializer | 읽기 순서와 블록 구조 정렬 | markdown, JSON |
| LLM Extractor | 필드 추출·요약·분류 | schema-guided prompt |
| Validator | 원문 근거·형식 검증 | JSON schema, citation check |

> 요약: OCR with LLM은 OCR 텍스트와 좌표를 LLM 입력으로 변환하고 스키마 기반 추출 결과를 검증함.

## Ⅲ. 동작원리 및 흐름도

```text
문서 입력 → OCR/좌표 추출 → 레이아웃 직렬화
  → LLM 필드 추출 → JSON 검증 → 원문 좌표 citation
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | OCR로 텍스트·bbox·confidence 추출 | 문자 정확도 ≥98% |
| 2 | 레이아웃 순서 보정·직렬화 | reading order 오류 <3% |
| 3 | LLM이 스키마별 필드 추출 | field F1 ≥0.9 |
| 4 | JSON·근거 좌표·환각 검증 | citation coverage 100% |

> 요약: OCR 결과를 구조화 입력으로 만들고 LLM이 필드를 추출하되 원문 좌표로 근거를 검증함.

## Ⅳ. 특징

| 구분 | OCR 단독 | OCR + LLM | 판단 포인트 |
|:---|:---|:---|:---|
| 출력 | 텍스트 | 구조화 JSON·요약 | 업무 자동화 가능 |
| 양식 대응 | 규칙 기반 한계 | 문맥 기반 유연성 | 비용·검증 필요 |
| 오류 유형 | 오인식·순서 오류 | 환각·근거 왜곡 추가 | citation 검증 필수 |
| 적용 | 단순 전사 | 계약·청구·보고서 이해 | 고부가 문서에 적합 |

> 요약: OCR+LLM은 문서 의미 해석을 강화하지만, 원문 근거 검증 없이는 환각 추출 위험이 있음.

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 계약서 추출: OCR markdown과 bbox를 LLM에 제공해 당사자·기간·SLA·위약금 JSON 추출, citation coverage 100% 적용
2. 청구서 검증: 총액=공급가+세액 규칙을 JSON schema와 업무 룰로 검증, 불일치 건 검수 큐 전송
3. 환각 방지: "원문에 없는 필드는 null" 정책과 좌표 근거 없는 claim 출력 금지 적용

**결론 (2줄):**
- 기술사 판단: 양식이 다양한 고부가 문서는 OCR+LLM, 정형 양식 대량 처리는 전통 Document AI 우선
- 향후 방향: VLM이 OCR·레이아웃·추론을 통합하면서 좌표 기반 근거 검증이 표준화됨
