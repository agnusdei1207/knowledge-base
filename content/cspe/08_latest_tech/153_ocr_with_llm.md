# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: 기존의 OCR이 그림에서 '글자'만 무식하게 뽑아내는 눈(Eye) 역할에 그쳤다면, 그 뒤에 '뇌(LLM)'를 붙여 뽑아낸 글자들이 무슨 뜻이고 어떤 구조인지 완벽하게 해석해 내는 하이브리드 문서 파싱 기술.
- **필요성**: 기존 규칙 기반 Document AI는 새 양식(새로운 영수증 디자인 등)이 나올 때마다 라벨링을 다시 하고 모델을 재학습해야 했음. 초거대 LLM을 뒤에 붙이면 학습 제로(Zero-shot)로 "이 텍스트 무더기에서 청구 금액만 찾아서 JSON으로 줘"라고 프롬프트만 주면 끝남.
- **핵심 직관**: 2인 1조 업무. 신입사원(OCR)이 계약서를 타이핑해서 메모장에 다 적어오면, 부장님(LLM)이 그 메모장을 쓱 읽어보고 "아, A사와 B사가 1억에 3년 계약했네. 엑셀에 싹 정리해 놔."라고 구조화하는 방식.

## 깊이 이해
- **배경**: LLM이 인간의 언어와 논리를 완벽히 이해하게 되면서, 비정형 텍스트를 구조화된 데이터로 바꾸는 Information Extraction(IE) 태스크 능력이 극대화됨. 이를 활용해 구식 OCR의 한계를 프롬프트 엔지니어링 하나로 박살 냄.
- **작동 원리 (2-Stage Pipeline)**:
  1. **OCR 단계**: 문서를 Tesseract나 상용 OCR 엔진에 넣어 텍스트 데이터(`[Text, X, Y 좌표]`)로 쭉 뽑아냄. (이때 글자가 순서대로 안 나오고 마구 섞이거나 표가 깨져 있어도 일단 뽑음).
  2. **LLM 단계 (Prompting)**: 뽑아낸 지저분한 텍스트 뭉치와 함께 프롬프트를 날림. "너는 문서 분석 전문가야. 다음 OCR 텍스트를 읽고 `{공급자, 수요자, 계약일자, 총금액}` 형식의 JSON으로 정리해서 출력해 줘. OCR 오타가 있으면 문맥상 맞게 고쳐서 줘."
  3. **구조화 완료**: LLM이 문맥을 추론해 완벽한 JSON 데이터를 뱉어냄.
- **구체 예시**: 병원 진단서 처리. OCR 결과 "환 ㅈㅏ명: 호길동, 병 명: 급 성 위염, 날ㅉ: 24/05/10". LLM이 이를 받아서 오타를 보정하고 `{"patient_name": "홍길동", "diagnosis": "급성 위염", "date": "2024-05-10"}` 로 깔끔하게 반환.
- **흔한 오해/주의점**: "LLM 만능이네?" $\rightarrow$ 치명적 단점이 있음. 바로 환각(Hallucination). OCR이 글자를 아예 못 읽어서 누락했는데, LLM이 문맥상 그럴듯한 숫자를 자기 맘대로 지어내서 채워 넣는 대참사가 발생할 수 있음. 반드시 "본문에 없는 내용은 지어내지 마(Groundedness)"라는 프롬프트 방어와 검증이 필수임.

## 연결 개념
- **JSON Schema**: LLM에게 "이 형식과 규칙에 맞춰서 데이터를 뽑아내라"고 강제하는 데이터 구조 틀.
- **VLM (Vision-Language Model)**: OCR을 떼어버리고 LLM(눈이 달린 GPT-4o 등)이 이미지 원본을 통째로 보고 바로 이해하게 만드는 최신 원스텝 기술.
- **Hallucination (환각)**: LLM이 지어내는 거짓말. 금융/계약 문서 처리 시 가장 조심해야 할 1순위 리스크.

# 📝 【답안용】 시험 답안 템플릿
## 핵심 인사이트 (3줄 요약)
- **본질**: 광학 문자 인식(OCR)을 통해 추출된 비정형/노이즈 텍스트 스트림을 LLM의 강력한 인컨텍스트 러닝(In-Context Learning) 능력과 시맨틱 추론을 통해 사전 정의된 정형 데이터(Structured Schema)로 정규화하는 파이프라인.
- **가치**: 기존 Document AI의 고질적 병목이었던 '새로운 문서 양식에 대한 라벨링 및 모델 재학습(Fine-tuning) 비용'을 Zero로 만들며, 프롬프트 변경만으로 무한한 확장성을 지닌 초자동화 체계를 구현함.
- **판단 포인트**: LLM의 환각(Hallucination)으로 인한 허위 정보 추출 리스크를 원천 차단하기 위해, 추출된 필드 값이 원본 문서의 어느 위치(Bounding Box 좌표)에 있는지 역추적하여 검증하는 Visual Grounding 체계 설계가 실무 적용의 핵심임.

## Ⅰ. 개요 및 필요성
- **정의**: 이미지나 PDF에서 1차적으로 텍스트와 좌표 정보를 추출하는 Vision 기반의 OCR 모듈과, 추출된 텍스트를 문맥적으로 이해하여 업무 스키마에 맞게 필드 값을 추출/보정하는 Language 모듈(LLM)을 결합한 하이브리드 문서 파싱 아키텍처.
- **배경**: 기존 레이아웃 기반 정보 추출(KIE) 딥러닝 모델들은 양식(Template) 다양성에 취약하고 별도의 대규모 학습 데이터 구축에 막대한 비용이 소요됨.
- **필요성**: 제로샷(Zero-shot) 추론 능력을 가진 파운데이션 모델(LLM)을 백오피스 자동화에 접목하여, 모델 재학습 없이 다국어/다양식 복합 문서를 유연하고 즉각적으로 구조화하기 위함.

## Ⅱ. OCR + LLM 파이프라인 아키텍처
기존 머신러닝의 '학습' 영역을 프롬프트 엔지니어링의 '추론' 영역으로 대체.
1. **Extraction (OCR 계층)**:
   - 문서 이미지에서 텍스트 토큰과 공간 정보(Bounding Box 좌표)를 추출.
   - 텍스트가 깨진 표(Table)나 다단 레이아웃을 마크다운(Markdown)이나 HTML 형태로 직렬화(Serialization)하여 LLM이 구조를 파악하기 쉽게 전처리.
2. **Prompt Engineering (질의 계층)**:
   - System Prompt: 태스크 역할 부여 (예: "당신은 법무 검토 AI입니다.")
   - Task Prompt: 추출해야 할 엔티티 리스트 및 JSON Schema 정의 (예: 계약기간, 위약금 조항, 갱신 조건).
   - Constraint: "문서에 명시되지 않은 값은 반드시 null로 표기할 것." (환각 방어막).
3. **Reasoning & Generation (LLM 계층)**:
   - LLM이 맥락을 추론하여 OCR의 사소한 오인식(Typo)을 문맥상 올바른 단어로 보정(Error Correction)하면서 구조화된 JSON 형태로 답변 반환.

## Ⅲ. LLM 기반 추출의 환각(Hallucination) 리스크와 Grounding 전략
편리함의 이면인 '그럴듯한 거짓말' 통제 방안.
| 통제 기법 | 구현 아키텍처 및 프롬프트 설계 | 기대 효과 |
|:---:|:---|:---|
| **Citation (출처 인용)** | 프롬프트: "추출한 값 뒤에 반드시 원본 OCR 텍스트의 어느 문장에서 발췌했는지 원문을 함께 적어라." | 추출 근거 투명성 확보. |
| **Bbox 역매핑 (Grounding)** | LLM이 필드값을 반환할 때, 해당 단어의 최초 OCR 좌표($x,y$)를 함께 반환하게 함. UI상에서 해당 원본 이미지 영역을 크롭하여 검수자에게 하이라이트 제공. | 허위 생성(환각) 100% 차단 및 휴먼 검수 시간 극단적 단축. |
| **Schema Validation** | Pydantic 등의 라이브러리를 사용해 LLM의 출력물이 `date`, `integer` 등 정해진 타입과 룰에 맞는지 기계적 검증 파이프라인(Guardrails) 적용. | 시스템 연동 시 데이터 파싱 에러 방지. |

## Ⅳ. 발전 동향: 2-Stage에서 VLM (Vision-Language Model) 원스텝으로
OCR 모듈의 의존성을 줄여나가는 차세대 기술.
- **현재 (OCR + Text LLM)**: 문서를 텍스트로 변환하는 과정에서 표(Table)의 병합 셀이나 차트 그림 데이터가 영구 유실됨.
- **미래 (VLM 기반 직접 추출)**: GPT-4o, Claude 3 Opus 등은 OCR 파이프라인 없이 문서 이미지를 픽셀 그대로 입력받아 멀티모달 어텐션으로 직관적으로 파악. 표 구조, 다이아그램, 손글씨까지 사람처럼 한눈에 파악하여 바로 JSON으로 추출(Native Multimodal).

## Ⅴ. 실무 적용 및 결론
- **판단 지표**: JSON Schema Format 준수율, Field Extraction F1 Score, Hallucination Rate(오추출률).
- **실무 설계**: 종합상사 수출입 신용장(L/C) 자동 분석 시스템. L/C 문서는 영문 수십 페이지에 달하며 은행마다 양식이 100% 달랐음. 기존 규칙 기반 OCR 적용 불가. 오픈소스 OCR 엔진(Tesseract)으로 텍스트를 직렬화하고, 기업형 Private LLM(Llama 3 기반) API를 연동함. 50개의 필수 무역 거래 조건 필드를 JSON Schema 프롬프트로 주입. LLM은 "선적 기한", "결제 은행", "보험 조건" 등을 정확히 파싱함은 물론, 독소 조항(위험 문구)까지 리포트로 요약해 냄. 이 과정에서 Bbox Grounding을 적용해 직원이 10초 만에 교차 검증하도록 UI 구성. L/C 리뷰 시간을 건당 2시간에서 5분으로 단축.
- **결론**: OCR과 LLM의 결합은 비정형 문서 처리에서 인간의 눈(인식)과 뇌(추론)를 동시에 구현한 백오피스 혁명의 마일스톤이며, 향후 VLM의 경량화와 함께 문서의 물리적 형태마저 초월하는 완전한 문서 지능(Document Intelligence) 생태계를 완성할 것이다.

### 🔀 문제 유형별 목차 전환
- **Ⅱ·Ⅲ 강조 (개념/원리형)**: OCR 노이즈 텍스트에 대한 LLM의 강건성(Robustness) 및 서브워드 토큰화(Sub-word Tokenization) 메커니즘 관점에서의 오류 보정 능력.
- **Ⅴ·Ⅵ 강조 (실무/설계형)**: JSON 출력 포맷 고정을 위한 Function Calling(Tool Use) 아키텍처 적용 방안 및 B2B 금융권 프라이빗 환경을 위한 보안 컴플라이언스(PII 마스킹 후 LLM 전송) 설계.
