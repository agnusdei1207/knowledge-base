# 📖 【암기용】 개념 완전 이해

> 목적: Graph-of-Thought를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **정의**: LLM의 중간 사고를 DAG(방향 비순환 그래프)로 모델링하여 분기·합류·정제를 허용하는 추론 프레임워크
- **왜 필요한가**: ToT는 트리 구조라 서로 다른 가지의 부분 결과를 합칠 수 없어, 복합 추론에서 정보 손실 발생
- **핵심 직관**: "나무가지는 합쳐질 수 없지만, 그래프 노드는 여러 간선으로 합류할 수 있다"

## 깊이 이해
- **배경·문제의식**: ToT는 분기만 가능하고 합류 불가 → 정렬·요약 등에서 부분 결과를 병합하려면 트리로는 부족. 예: 32개 숫자 정렬 시 ToT는 각 가지를 독립 처리하지만, GoT는 부분 정렬 결과를 merge
- **작동 원리**: ① 사고 단위를 그래프 정점으로 표현 → ② 생성(Generate): 새 정점 추가(분기) → ③ 집계(Aggregate): 여러 정점을 하나로 합류(merge) → ④ 정제(Refine): 기존 정점을 자체 피드백으로 개선 → ⑤ 점수 평가 후 최적 경로 선택
- **비유**: 여러 팀이 각자 조사한 보고서를 최종 회의에서 합쳐 하나의 결론을 내는 것
- **구체 예시**: 32개 숫자 정렬에서 CoT 오류율 28% → ToT 16% → GoT 4.7%(Besta et al., 2024). 비용은 ToT 대비 토큰 31% 절감
- **흔한 오해·주의점**: GoT는 "순환(cycle)"이 아니라 DAG — 사이클을 허용하면 무한루프 위험. 단순 문제에서는 GoT 오버헤드가 이점을 상쇄

## 연결 개념
- Tree-of-Thought(ToT): GoT의 전신, 트리 구조(합류 불가)
- Chain-of-Thought(CoT): 단일 경로 추론, GoT의 기본 단위
- MapReduce: GoT의 분산-집계 패턴과 유사한 병렬 처리 패러다임


# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: LLM 사고를 DAG로 모델링하여 분기·합류·정제 연산을 지원하는 추론 프레임워크
> 2. **가치**: 정렬 문제 오류율 ToT 16%→GoT 4.7%, 토큰 비용 31% 절감
> 3. **판단 포인트**: 부분 결과 합류가 필요한 복합 추론에 적합, 단순 분기 문제는 ToT로 충분


## Ⅰ. 개요 및 필요성

LLM 사고를 DAG로 모델링하는 추론 프레임워크. ToT는 트리 구조로 분기만 가능하여 부분 결과 병합이 불가하고, 복합 추론(정렬·요약·집계)에서 정보 손실이 발생한다.


## Ⅱ. 구조 및 구성요소

```text
[Thought1]──┐            ┌──[Refined]
[Thought2]──┼─▶[Aggregate]──▶[Score]──▶ 최적 답
[Thought3]──┘
   ↑ Generate               ↑ Refine
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Thought Vertex | 개별 사고 단위를 그래프 정점으로 표현 | 각 정점에 상태·점수 보유 |
| Generate(분기) | 기존 정점에서 새 정점 1~k개 생성 | ToT의 분기와 동일 |
| Aggregate(합류) | 여러 정점의 결과를 하나로 병합 | ToT에 없는 GoT 고유 연산 |
| Refine(정제) | 정점 자체를 피드백 루프로 개선 | 자기 수정 1~2회 반복 |

> 요약: Generate로 분기, Aggregate로 합류, Refine으로 정제하여 DAG 기반 최적 추론 수행


## Ⅲ. 동작원리 및 흐름도

```text
문제 입력 → 하위 문제 분해 → [Generate: 병렬 사고 생성]
→ [Aggregate: 부분 결과 합류] → [Refine: 자기 수정]
→ 점수 평가 → 최적 답 출력
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 문제를 독립 하위 문제로 분해 | 하위 문제 간 의존성 최소화 |
| 2 | 각 하위 문제에 대해 사고 정점 병렬 생성 | 정점 수 3~8개 |
| 3 | Aggregate 연산으로 부분 결과 병합 | 병합 후 일관성 검증 |
| 4 | Refine으로 최종 정제 후 점수 평가·출력 | 정제 전후 점수 비교 |

> 요약: 분해→병렬 생성→합류 병합→정제→최적 답의 DAG 탐색 흐름


## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| CoT 대비 | 분기+합류+정제 지원 | 정렬 오류율 28%→4.7% |
| ToT 대비 | 합류(Aggregate) 연산 추가 | 토큰 비용 31% 절감 |
| 한계 | DAG 설계 복잡도 증가 | 프롬프트 엔지니어링 난이도 상승 |

> 요약: 합류 연산으로 ToT 대비 정확도↑·비용↓, 단 그래프 설계 복잡도 증가


## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 대규모 문서 요약에 GoT 적용: 청크별 병렬 요약 → Aggregate로 통합, 요약 품질 ROUGE-L 0.38→0.47
2. 코드 리팩토링 시 모듈별 분석 결과를 Aggregate로 병합, 리팩토링 누락률 22%→7%
3. 멀티 에이전트 토론 시스템에 GoT 그래프 구조 적용, 의견 합류·정제로 합의 속도 40% 향상

**결론 (2줄):**
- 기술사 판단: 부분 결과 합류가 필요한 복합 추론(요약·정렬·집계)이면 GoT, 단순 분기 탐색이면 ToT
- 향후 방향: 동적 그래프 구조 자동 설계(AutoGoT) 연구 진행 중
