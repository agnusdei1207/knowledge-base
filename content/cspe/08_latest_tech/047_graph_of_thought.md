## 미리 알고가기

- 그래프 오브 소트 ($GoT$): 생각을 분기하는 데 그치지 않고, 상호 병합하고 재참조하여 임의의 유향 그래프($Directed$ $Graph$) 형태로 추론을 전개하는 기법임
- $DAG$ ($Directed$ $Acyclic$ $Graph$): 단방향으로 흐르며 절대 시작 노드로 순환(회귀)하지 않는 비순환 그래프 구조임
- 에이전트 오케스트레이션: 여러 명의 독립된 AI 에이전트(역할군)들이 그래프 형태로 임무를 주고받으며 협업하도록 조율하는 시스템임
- 상태 일관성 ($State$ $Consistency$): 여러 병렬 노드가 연산되는 도중, 공유 상태 메모리값의 시점 차이에 따른 모순이 발생하지 않도록 동기화하는 관리 규칙임

## Ⅰ. 개요

- **정의/개념**: Graph-of-Thought(GoT)는 LLM의 개별 생각 단위를 노드($Node$)로, 생각 간의 의존성과 인과관계를 엣지($Edge$)로 구성하여, 부분 추론 결과를 병렬 연산한 후 상위 노드에서 병합($Merge$)하고 재사용할 수 있도록 설계한 그래프 기반 추론 프레임워크임
- **배경/필요성**: 기존의 트리 추론($ToT$) 방식은 각 분기 노드가 독립적으로만 뻗어나가 타 경로의 우수한 중간 계산 결과를 융합해 재사용할 수 없으므로, 다차원 문서의 통합 요약이나 설계 조율처럼 정보 교차 재활용이 필수적인 과업을 해결하기 위해 창제됨

## Ⅱ. 특징

- 동일한 중간 계산 결과를 가리키는 노드로의 재참조($Reference$)를 지원하여, 중복 추론 연산을 획기적으로 차단하고 토큰 연산 효율성을 개선함
- 복수의 연산 노드가 독립된 조건들을 병렬 연산한 뒤 이를 통합 노드($Merge$ $Node$)에서 결합(Aggregation)하는 맵리듀스($MapReduce$)형 연산 구조를 가짐
- 최근의 워크플로우 제어 툴(예: $LangGraph$)의 기반 이론이 되며, 사용자 인터랙션 및 시스템 상태에 따른 동적 추론 라우팅에 최적화됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 체인 오브 소트 (CoT) | 트리 오브 소트 (ToT) | 그래프 오브 소트 (GoT) |
|:---|:---|:---|:---|
| **생각 흐름의 위상** | $1 \rightarrow 1$ (선형 체인) | $1 \rightarrow N$ (트리 구조) | $N \rightarrow M$ (방향성 네트워크) |
| **중간 결과의 병합** | 불가능함 | 불가능함 | 원활함 (여러 노드 출력을 하나로 융합) |
| **연산 재사용성** | 전혀 없음 (매번 재생성) | 낮음 | 매우 높음 (이전 생성 노드 재참조) |
| **루프 및 순환 제어** | 루프 없음 | 백트래킹 제어 | $DAG$ 제어 및 동적 상태 검사 필수 |

> 요약: CoT는 순차 추론에, ToT는 백트래킹 탐색에, GoT는 복합 다단계 협업 및 연산 결과의 네트워크 융합에 특화됨.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 생각 노드 ($Node$) | 특정 조건의 계산값, 요약 데이터 등 중간 연산 결과물을 저장하는 가상의 지식 객체임 |
| 관계 선 ($Edge$) | 생각 노드 간의 의존 선후 관계를 표현하며, 데이터와 신호의 흐름 방향을 지칭함 |
| 병합 노드 | 분기된 복수의 생각 노드 결과물들을 결합하여, 하나의 통합 결론을 도출하는 융합 층임 |
| $DAG$ 컨트롤러 | 연산 경로의 순환($Loop$)을 감지하여 차단하고, 최종 도달 노드까지의 유효 경로를 감시하는 제어부임 |

```text
[ GoT (Graph-of-Thought) 정보 흐름 ]
  [Part A Gen] ---\
                  ---> [Merge & Cross Check] -> [Final Report]
  [Part B Gen] ---/
        | (Feedback Loop)
        v
  [Regenerate B]
- 병렬 생성 후 융합 및 에러 발견 시 특정 분기만 피드백 루프로 재생성하는 유연성을 제공함
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 문제의 그래프| --> | 독립 노드들의| --> | 병합 노드   | --> | 최종 무결성 |
| 구조적 해체  |     | 병렬 실행    |     | 데이터 융합 |     | 평가 및 수렴|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **그래프 정비** — 풀고자 하는 고난도 작업(예: 논문 5편 비교 요약)을 분기, 병합, 피드백 루프가 담긴 유향 그래프 구조로 모델링함
2. **병렬 연산** — 종속성이 없는 최하단 노드들(각 논문 개별 요약)을 프로세스 풀을 이용해 실시간 병렬로 동시 호출하여 실행함
3. **취합 및 융합** — 하위 노드들의 완료 신호를 받아, 상위 병합 노드에 데이터를 모으고 모순 여부를 검사하는 통합 추론 프롬프트를 실행함
4. **루프 통제** — 에러 발견 시 지정된 피드백 엣지를 따라 하위 노드를 재실행하되, 무한 루프 방지 상한선(Max Recursion)에 다다르면 강제 수렴시킴

## Ⅵ. 실무 적용 및 유의점

1. 그래프 구조가 복잡해지면 병렬 실행 도중 특정 분기의 지연으로 인해 전체 워크플로우가 멈추는 동기화 지연 병목이 발생하므로, 상태 관리 엔진에 비동기($Async$) 이벤트 리스너를 결합하고, 총 실행 성공률($Success$ $Rate$)과 워크플로우 전체 지연시간으로 효율을 확인해야 함
2. 그래프에 동적 순환 루프가 허용된 경우 모델의 판단 오류로 인해 동일 구간을 무한 뱅글뱅글 도는 연산 오작동이 생겨 비용 폭탄을 맞을 수 있으므로, 반드시 최대 재귀 제한($Recursion$ $Limit$) 및 타임아웃 코드를 장착하고 평균 루프 회전수와 토큰 소모 가성비로 안전성을 확보해야 함

## Ⅶ. 결론

- Graph-of-Thought는 복잡계 비즈니스 프로세스를 단일 LLM 연산에 가두지 않고 협업 그래프로 승화하는 실용적 구조 설계이며, 설계자는 무한 루프 예외 차단과 비동기 병렬 상태 관리의 정합성을 수립하여 지능형 에이전트 인프라를 서빙해야 함
