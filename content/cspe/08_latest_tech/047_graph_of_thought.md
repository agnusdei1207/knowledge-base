## 미리 알고가기

- Graph 구조는 분기뿐 아니라 병합과 재참조를 함께 표현할 수 있는 추론 표현 방식임
- Node는 중간 생각 상태나 작업 단위를, Edge는 의존 관계나 정보 흐름을 의미함
- DAG 제약은 순환 없는 실행 경로를 강제해 무한 루프 위험을 줄이는 운영 원칙임

## Ⅰ. 개요

- **정의/개념**: Graph-of-Thought는 LLM의 중간 추론 단계를 노드와 엣지로 조직해 분기와 병합과 재사용을 함께 수행하도록 설계한 그래프 기반 reasoning 프레임워크임
- **배경/필요성**: Tree-of-Thought는 각 가지가 독립적으로만 확장되어 다른 경로의 유용한 중간 결과를 재사용하기 어려우므로, 다문서 요약이나 복합 설계처럼 여러 부분 결과를 다시 결합해야 하는 작업에는 그래프형 추론이 필요함

## Ⅱ. 특징

- 분기와 병합을 동시에 지원해 독립된 부분 문제를 병렬 처리한 뒤 결과를 재조합할 수 있음
- 중간 결과를 재사용해 동일한 계산을 반복하지 않도록 설계할 수 있음
- Agent Orchestration, LangGraph, workflow DAG와 결합하기 쉬워 실무 확장성이 높음
- 자유도가 높은 만큼 순환 루프와 상태 관리 복잡성도 함께 증가함

## Ⅲ. 종류 및 비교

| 판단 기준 | Chain-of-Thought | Tree-of-Thought | Graph-of-Thought |
|:---|:---|:---|:---|
| 구조 | 선형 | 트리 | 그래프 |
| 병합 가능성 | 없음 | 제한적임 | 높음 |
| 중간 결과 재사용 | 낮음 | 낮음 | 높음 |
| 운영 복잡도 | 낮음 | 높음 | 매우 높음 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Thought Node | 개별 추론 상태나 부분 결과를 보관해 그래프 탐색의 기본 단위를 형성함 |
| Dependency Edge | 어떤 결과가 다음 추론의 입력이 되는지와 병합 순서를 정의함 |
| Merge Node | 여러 경로의 결과를 결합해 더 높은 수준의 판단이나 산출물을 생성함 |
| Execution Controller | DAG 순서와 재시도 규칙과 종료 조건을 관리해 전체 그래프 실행을 통제함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 노드 생성    | --> | 분기 실행    | --> | 결과 병합    | --> | 검증/종료   |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **노드 생성**: 문제를 부분 과업이나 중간 생각 노드로 나누어 그래프를 구성함
2. **분기 실행**: 독립 가능한 노드를 병렬 또는 순차로 실행해 각 부분 결과를 생성함
3. **결과 병합**: 여러 노드 출력을 결합해 종합 판단이나 최종 초안을 생성함
4. **검증 및 종료**: 병합된 결과의 품질을 검증하고 필요 시 일부 노드만 재실행함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 노드와 엣지 관계가 복잡해질수록 어떤 결과가 최신 상태인지 추적하기 어려워 실행 일관성이 깨질 수 있음
   - 해결방안: 상태 스냅샷과 명시적 dependency 관리를 적용하고 stale output 비율과 workflow failure rate로 일관성을 검증함
2. 문제: 순환 루프나 상호 재호출이 통제되지 않으면 토큰 비용이 급증하고 종료 조건을 잃을 수 있음
   - 해결방안: DAG 제약과 recursion limit를 강제하고 평균 loop count와 요청당 비용으로 안전성을 검증함
3. 문제: 병합 단계의 품질이 낮으면 앞선 노드들의 좋은 결과가 제대로 통합되지 않아 전체 답변 품질이 오히려 떨어질 수 있음
   - 해결방안: merge 전용 evaluator를 두고 branch별 contribution 분석과 final answer quality로 병합 품질을 검증함

## Ⅶ. 적용 사례

- 다문서 요약: 문서별 요약을 병렬 생성한 뒤 상위 노드에서 통합함, 확인 지표는 summary coverage와 faithfulness임
- 복합 코드 생성: 프론트엔드와 백엔드를 분기 생성 후 통합 테스트 노드에서 결합함, 확인 지표는 build success rate와 defect rate임
- 분석형 에이전트: 검색, 계산, 검증 노드를 그래프로 연결함, 확인 지표는 task completion rate와 recovery time임

## Ⅷ. 결론

Graph-of-Thought는 더 복잡한 추론 구조를 허용하는 대신 상태 관리와 병합 품질을 함께 설계해야 가치가 나오므로, DAG 통제와 검증 노드 설계가 실무 핵심임.
