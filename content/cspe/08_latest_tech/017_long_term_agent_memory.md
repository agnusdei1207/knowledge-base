# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: **장기 메모리 에이전트**는 **에이전트 메모리**(016 참조) 중 세션을 넘어 **영구 저장**되는 지식을 다룬다. 핵심은 무엇을 저장할지가 아니라, 방대한 누적 기억에서 지금 필요한 것만 정확히 **인출(recall)**하는 저장·검색 구조에 있다.
- **왜 필요한가**: 사용자 선호·과거 결정·업무 이력은 며칠~몇 달 뒤 다시 쓰이는데, 이를 LLM 컨텍스트에 계속 담으면 토큰 한계를 넘고 비용이 폭증하므로 외부 저장소로 옮겨야 한다.
- **핵심 직관**: 장기 메모리는 방대한 서류철을 캐비닛(벡터DB·지식그래프)에 넣어두고, 질문이 오면 관련 서류만 뽑아 책상(컨텍스트)에 올리는 방식이다. 저장 형식(벡터/그래프/요약)에 따라 검색 방법이 달라진다.

## 핵심 용어 정리 (내부에 등장하는 것들)
아래 용어는 답안 본문(Ⅰ~Ⅵ·표)에 그대로 등장하므로, 처음 보는 사람도 이해하도록 비유와 함께 먼저 정리한다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 장기 메모리(핵심) | 세션을 넘어 지속 저장·인출되는 에이전트의 누적 지식 | 오래 보관하는 "서류 캐비닛" |
| 임베딩(Embedding) | 텍스트 의미를 고차원 숫자벡터로 변환한 표현 | 뜻을 좌표로 바꾼 "의미 지도" |
| 벡터DB(Vector DB) | 임베딩을 저장하고 유사도로 검색하는 DB(Pinecone·pgvector 등) | 뜻이 비슷한 문서를 찾는 색인 |
| 유사도 검색(ANN) | 근사 최근접 이웃 탐색으로 의미가 가까운 상위 K개를 찾음 | "비슷한 것끼리" 빠르게 골라냄 |
| RAG(검색증강생성) | 저장소에서 관련 지식을 검색해 LLM 답변에 근거로 주입 | 답하기 전 "자료 찾아보기" |
| 지식그래프(KG) | 개체(노드)와 관계(엣지)로 지식을 구조화한 그래프 | 인물·사건 "관계도" |
| 요약 압축(Summarization) | 긴 이력을 핵심만 남긴 요약으로 줄여 저장 | 회의록을 "핵심 3줄"로 |
| 메모리 승격(Consolidation) | 단기 세션 기억 중 중요한 것을 장기로 옮기는 과정 | 메모지를 정식 파일로 정리 |
| recall/precision | 인출 성능. recall=필요한 걸 놓치지 않음, precision=엉뚱한 걸 안 꺼냄 | 그물이 놓친 물고기 vs 잡힌 쓰레기 |
| TTL(Time To Live) | 저장 기억의 보존 기간. 만료 시 자동 삭제 | 서류의 "폐기 예정일" |
| PII(개인식별정보) | 이름·연락처 등 개인 식별 민감정보 | 함부로 못 두는 "주민번호" |

## 깊이 이해
- **배경·문제의식**: 단기 메모리(018)는 세션이 끝나면 사라져 "지난주에 정한 배포 규칙"을 기억하지 못한다. 장기 메모리는 이 간극을 메우지만, 수만 건이 쌓이면 전부 컨텍스트에 넣을 수 없다. 그래서 "저장은 많이, 인출은 관련된 것만"이라는 검색 문제로 귀결된다.
- **작동 원리(어떻게+왜)**: 저장 시 텍스트를 임베딩해 벡터DB에 넣거나, 개체·관계를 추출해 지식그래프에 적재한다. 인출 시에는 질의를 같은 임베딩 공간으로 바꿔 유사도 상위 K개를 뽑거나(RAG), 그래프를 관계 따라 탐색한다. 임베딩 방식은 "의미가 비슷한" 자유 텍스트에 강하고, 그래프 방식은 "A가 B의 상사"처럼 다단계 관계 추론에 강해서 목적에 따라 나뉜다. 오래된 이력은 요약 압축해 부피를 줄이고, 단기에서 중요한 것만 장기로 승격시킨다.
- **비유**: 대형 도서관과 같다. 책(문서)을 주제 좌표(임베딩)로 서가에 꽂아두고(벡터DB), 질문이 오면 사서가 관련 서가에서 몇 권만 뽑아 준다(RAG). 인물·사건의 얽힌 관계를 물으면 관계도(지식그래프)를 따라 답한다.
- **구체 예시(실제 사례)**: LangGraph `store`, Mem0, Zep은 사용자별 장기 기억을 벡터DB에 저장하고 대화마다 관련 기억을 주입한다. Zep은 시간축 지식그래프로 "언제부터 언제까지 참"인 사실 변화를 추적한다. 예: 고객지원 에이전트가 "이 고객은 3개월 전 환불 정책에 불만"이라는 에피소딕 기억을 인출해 응대 톤을 조정한다.
- **흔한 오해·주의점**: "장기 메모리 = RAG"가 아니다. RAG는 인출 방법의 하나이고, 장기 메모리는 무엇을 승격·요약·폐기할지의 저장 수명주기까지 포함한다. 또한 임베딩이 오래되면(모델 교체) 재색인(re-embedding)이 필요하고, 사실이 바뀌면 옛 기억을 무효화하지 않는 한 잘못된 근거를 인출한다.

## 연결 개념
- 에이전트 메모리(016) — 단기·장기를 포괄하는 상위 기억 체계
- 단기 메모리(018) — 세션 내 휘발성 기억, 장기로 승격되는 원천
- RAG·벡터DB — 장기 기억 인출을 구현하는 검색증강 기술

> 1. **본질**: 장기 메모리는 세션을 넘는 누적 지식을 벡터DB·지식그래프에 저장하고 관련된 것만 인출하는 검색 중심 기억 계층임.
> 2. **가치**: RAG·요약 압축·메모리 승격으로 방대한 이력을 토큰 한계 없이 재사용해 개인화·연속성을 확보함.
> 3. **판단 포인트**: 저장 형식(벡터 vs 그래프) 선택, 인출 recall·precision, 사실 변경 시 무효화·재색인, 개인정보 TTL을 함께 설계해야 함.

## Ⅰ. 개요 및 필요성

- 개요: 세션을 넘는 누적 지식을 벡터DB·지식그래프에 저장·인출하는 지속 기억 계층임
- 배경: 단기 메모리(018)는 세션 종료 시 소멸해 며칠 뒤 재사용할 이력을 보존하지 못함
- 필요성: 수만 건 이력을 컨텍스트에 다 담을 수 없어 관련 기억만 검색·주입하는 구조가 필요함
- 위치: 에이전트 메모리(016)의 장기·지속 계층에 해당하며 RAG 검색과 결합됨

---

## Ⅱ. 구조 및 구성요소

- 선형 구조도

```text
단기 기억 -> Consolidation(중요도 판정·요약) -> 장기 저장
  저장경로: 임베딩 -> 벡터DB / 개체·관계 추출 -> 지식그래프
  인출경로: 질의 임베딩 -> ANN 유사도 top-K / 그래프 탐색 -> LLM 컨텍스트 주입
  수명주기: TTL·삭제 API / 사실 변경 시 무효화·재색인
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Consolidation | 단기 중요 기억을 요약·승격 | 중복 병합·중요도 판정 |
| 벡터DB | 임베딩 저장·유사도 검색 | ANN 인덱스, 재색인 필요 |
| 지식그래프 | 개체·관계 구조화 저장 | 다단계 관계 추론·시간축 |
| 인출 엔진(RAG) | 질의 관련 top-K 검색·주입 | recall·precision·리랭킹 |
| 수명주기 관리 | TTL·삭제·사실 무효화 | KMS 암호화, 재색인 배치 |

> 요약: 장기 메모리는 승격, 벡터·그래프 저장소, RAG 인출, 수명주기 관리로 구성됨.

---

## Ⅲ. 동작원리 및 흐름도

- 선형 흐름도

```text
단기 기억 -> 중요도 판정·요약 승격 -> 임베딩/관계추출 저장
  -> 질의 발생 -> 유사도/그래프 검색 top-K -> 리랭킹·주입 -> TTL·무효화 관리
```

1. 승격·저장: Consolidation이 중요 기억을 요약해 임베딩(벡터DB) 또는 개체·관계(지식그래프)로 적재함
2. 질의 변환: 현재 질의를 동일 임베딩 공간으로 변환하거나 그래프 진입점을 식별함
3. 검색·리랭킹: ANN으로 top-K를 뽑고 출처·최신성으로 리랭킹해 관련 기억만 컨텍스트에 주입함
4. 수명주기 관리: TTL 만료·삭제 요청을 처리하고 사실 변경 시 옛 기억을 무효화·재색인함

> 요약: 승격-저장-검색-리랭킹-폐기가 순환하며, 인출 시 최신성·출처 검증이 품질을 좌우함.

---

## Ⅳ. 특징

- 지속성: 세션 종료·재시작과 무관하게 개인화 이력·업무 지식을 영구 보존함
- 검색 기반 인출: 전체 주입이 아니라 임베딩 유사도·그래프 탐색으로 관련 top-K만 꺼냄
- 형식 다양성: 자유 텍스트는 벡터DB, 다단계 관계는 지식그래프로 목적에 맞게 저장함
- 압축·승격: 요약으로 부피를 줄이고 단기 중 중요한 것만 장기로 올려 비용을 통제함
- 정합성 부담: 사실이 바뀌면 무효화·재색인이 없으면 오래된 근거를 인출하는 위험이 큼

## Ⅴ. 심화 비교 및 적용 판단

- 장기 저장 형식을 벡터DB와 지식그래프로 대비함

| 구분 | 벡터DB 저장 | 지식그래프 저장 |
|:---|:---|:---|
| 저장 단위 | 임베딩(문서·청크 벡터) | 개체(노드)·관계(엣지) |
| 검색 방식 | 의미 유사도 ANN top-K | 관계 경로 탐색·질의 |
| 강점 | 자유 텍스트 의미 검색, 구축 간편 | 다단계 관계 추론, 사실 정합성 |
| 약점 | 관계·추론 표현 약함 | 스키마·개체 추출 비용 큼 |
| 적용 상황 | FAQ·대화 이력·비정형 문서 | 조직도·규정 의존·이력 추적 |

> 요약: 비정형 텍스트 의미 검색은 벡터DB, 다단계 관계·사실 추적은 지식그래프, 복합 요구는 GraphRAG로 결합함.

- 주요 리스크와 대응(불릿)
  - 오래된 사실 인출: 사실 변경 시 무효화 미처리가 원인 → 시간축 태깅·버전 관리·재색인 배치
  - 인출 노이즈: 관련성 낮은 top-K 주입이 원인 → 리랭킹·유사도 임계값·출처 필터 적용
  - 개인정보 장기 잔류: TTL·삭제 미구현이 원인 → TTL 30~90일 + 삭제 SLA 24시간·KMS 암호화

- 인출 품질 지표(불릿)
  - 검색 recall 85% 이상·precision 80% 이상(라벨 질의셋 평가)
  - 인출 p95 지연 200ms 이하(ANN 인덱스·캐시 튜닝)
  - 사실 최신성 오류율 1% 이하(무효화 처리 누락 감사)

## Ⅵ. 실무 적용 및 결론

- 적용 방안
  1. 대화·선호는 pgvector·Pinecone에 임베딩 저장하고, 조직·규정 의존관계는 지식그래프로 이원화함
  2. RAG 인출에 리랭킹·유사도 임계값·출처 필터를 적용하고 top-K를 5~10개로 제한해 노이즈를 통제함
  3. 사실 변경은 시간축 태깅·버전으로 무효화하고, 개인정보는 TTL 30~90일·삭제 SLA 24시간을 강제함
- 결론
  - 기술사 판단: 비정형 의미 검색은 벡터DB, 관계 추론이 중요하면 지식그래프 또는 GraphRAG로 선택함
  - 향후 방향: 시간축 지식그래프와 자동 요약 승격을 결합한 자기정리형 장기 메모리로 발전함
