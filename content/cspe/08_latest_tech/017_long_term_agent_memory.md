# 📖 【암기용】 개념 완전 이해

> 목적: 장기 메모리 에이전트를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: 세션 종료 후에도 사용자·업무 이력을 보존해 활용하는 에이전트 기억
- **왜 필요한가**: 고객지원, 운영자동화, 개인화 업무는 과거 이력과 선호를 장기간 반영해야 함.
- **핵심 직관**: 장기 메모리는 에이전트가 조직의 경험을 축적하는 지식 저장고임.

## 깊이 이해
- **배경·문제의식**: 단기 컨텍스트는 대화가 끝나면 사라지므로 재방문 고객, 반복 장애, 장기 프로젝트 맥락을 잃음.
- **작동 원리**: 중요 이벤트를 요약·임베딩·정형 레코드로 저장하고, 새 작업 시 사용자·업무 키로 검색해 반영함.
- **비유**: 병원이 환자 진료기록을 장기간 보관하고 다음 진료 때 과거 검사와 처방을 참고하는 구조.
- **구체 예시**: DevOps Agent가 지난 6개월 장애 이력과 성공 조치 Runbook을 검색해 재발 장애에 적용함.
- **흔한 오해·주의점**: 장기 저장은 편의보다 규제 리스크가 커서 동의, 목적 제한, 보존기간, 삭제권을 먼저 정해야 함.

## 연결 개념
- Agent Memory — 전체 메모리 체계
- Data Retention — 보존기간 정책
- Vector Database — 유사 이력 검색

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Long-Term Agent Memory는 세션을 넘어 업무·사용자 이력을 지속 저장하고 검색하는 메모리 계층임.
> 2. **가치**: 반복 업무의 재질문과 중복 분석을 줄이고 과거 성공·실패 이력을 의사결정에 반영함.
> 3. **판단 포인트**: 저장 기준, 보존기간, 동의·삭제권, 오래된 기억 검증을 함께 설계해야 함.

---

## Ⅰ. 개요 및 필요성

장기 메모리는 세션 이후 지속되는 에이전트 기억임. 반복 업무와 개인화 서비스는 과거 이력 활용이 필요하지만, 개인정보와 업무비밀 장기 보관 위험도 함께 발생함.

---

## Ⅱ. 구조 및 구성요소

```text
Event -> Importance Filter -> Summary/Embedding -> Long Store


로그/대화      저장판단          요약·벡터       DB/Vector
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Importance Filter | 장기 저장 여부 판단 | 중요도·민감도 점수 |
| Summary Store | 요약 기억 저장 | 출처 링크 필요 |
| Vector Store | 유사 기억 검색 | 임베딩 모델 버전 관리 |
| Retention Policy | 보존·삭제 통제 | TTL, 동의, 삭제권 |

> 요약: 장기 메모리는 저장판단, 요약·벡터화, 장기저장소, 보존정책으로 구성됨.

---

## Ⅲ. 동작원리 및 흐름도

```text
이벤트 발생 -> 장기저장 판단 -> 요약/벡터화 -> 저장
        -> 새 작업 검색 -> 신뢰도 확인 -> 컨텍스트 반영
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 저장 후보 식별 | 업무ID, 사용자ID, 출처 |
| 2 | 중요도·민감도 평가 | PII, 비밀등급, 동의 |
| 3 | 검색·재사용 | 유사도, 최신성, 근거 |
| 4 | 보존·폐기 | TTL, 삭제요청, 감사로그 |

> 요약: 장기 메모리는 저장보다 재사용 시 최신성·동의·보존기간 검증이 중요함.

---

## Ⅳ. 특징

| 구분 | 단기 메모리 | 장기 메모리 | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 보존 | 세션·작업 단위 | 월·년 단위 | TTL, 저장 용량 |
| 활용 | 즉시 문맥 | 반복 업무·개인화 | 재사용률, 검색 recall |
| 위험 | 일시 노출 | 장기 개인정보 보관 | 동의율, 삭제 처리시간 |

> 요약: 장기 메모리는 경험 축적 효과가 있으나 데이터 보존 리스크를 수반함.

---

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 장기 저장 대상을 성공 조치, 선호, 금지사항, 반복 장애 이력으로 제한하고 원문 저장을 최소화
2. 사용자 동의, 목적, 보존기간, 삭제요청 처리시간을 정책화하고 감사로그로 증빙
3. 오래된 기억은 최신 데이터와 교차검증하고 90일 이상 미사용 기억은 재평가 또는 삭제

**결론 (2줄):**
- 기술사 판단: 장기 메모리는 반복·개인화 업무에 적용하고 민감 업무는 요약·익명화 저장을 우선함.
- 향후 방향: 장기 메모리는 AI 개인화와 기업 지식관리의 핵심 계층이 되며 개인정보 거버넌스와 결합됨.
