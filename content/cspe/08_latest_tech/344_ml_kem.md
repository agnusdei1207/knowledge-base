# 📖 【암기용】 개념 완전 이해

> 목적: ML-KEM을 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 양자컴퓨터의 공격에도 안전하도록 설계된, '비밀키를 안전하게 주고받기 위한' 최신 표준 암호 기술 (구 Kyber)
- **왜 필요한가**: 인터넷 통신(HTTPS)의 첫 단계는 서로 비밀키를 공유하는 것인데, 기존 방식(RSA, Diffie-Hellman)은 양자컴퓨터가 나오면 바로 뚫리기 때문. 이를 대신할 '양자 방패'가 필요함.
- **핵심 직관**: "고차원 격자 속에 숨겨진 비밀 상자" — 아주 복잡한 수학적 격자 구조에 비밀키를 숨겨서 전달하며, 양자컴퓨터도 이 상자를 열기 위해선 수만 년의 계산이 필요하도록 설계됨.

## 깊이 이해
- **배경·문제의식**: 미국 표준기술연구소(NIST)는 양자 컴퓨터의 위협에 대비해 '양자내성암호(PQC)' 표준을 공모했고, 그중 가장 성능과 보안성이 우수한 'Kyber' 알고리즘을 'ML-KEM'이라는 이름으로 최종 표준화함.
- **작동 원리**: '모듈 격자(Module-Lattice)' 기반의 MLWE(Module Learning With Errors) 문제를 활용함. 수학적으로 매우 풀기 힘든 격자 점 찾기 문제에 미세한 '오류(Noise)'를 섞어 암호화함. 정답을 아는 사람(개인키 소유자)은 노이즈를 쉽게 걷어내지만, 모르는 사람은 양자컴퓨터로도 정답을 찾기 힘듦.
- **비유**: 거대한 모눈종이(격자) 위에 비밀 보물이 숨겨진 점이 있는데, 그 점 주변에 수많은 가짜 점(오류)을 뿌려두는 것과 같음. 보물 지도의 규칙(개인키)을 모르면 아무리 눈이 좋은 사람(양자컴퓨터)도 진짜 보물을 찾지 못함.
- **구체 예시**: 구글 크롬 브라우저와 클라우드플레어 서버 간의 통신에 이미 적용되어, 우리가 모르는 사이에 양자 내성 보안을 제공하고 있음.
- **흔한 오해·주의점**: ML-KEM은 '전자서명'용이 아님. 오직 '키 교환(비밀키 공유)'을 위해서만 사용됨. 전자서명을 위해서는 ML-DSA라는 형제 알고리즘이 따로 존재함.

## 연결 개념
- FIPS 203 — ML-KEM의 공식 표준 번호
- PQC (Post-Quantum Cryptography) — ML-KEM이 속한 상위 기술 범주
- ML-DSA — ML-KEM과 함께 표준화된 전자서명용 알고리즘

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 모듈 격자 기반의 MLWE 난제와 KEM 프로세스(Encapsulation/Decapsulation)를 중심으로 기술한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: NIST가 FIPS 203으로 표준화한 격자 기반 양자내성 암호로, 양자 컴퓨팅 환경에서 안전하게 대칭키를 공유하기 위한 키 캡슐화 메커니즘(KEM)이다.
> 2. **가치**: 기존 Kyber 알고리즘을 기반으로 하며, 우수한 연산 효율성과 적절한 키 크기를 제공하여 TLS 1.3 등 현대 통신 프로토콜에 즉시 적용 가능하다.
> 3. **판단 포인트**: MLWE(Module Learning With Errors) 문제의 수학적 강건성과 Category 1, 3, 5 레벨별 보안 파라미터 선택이 핵심이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| ML-KEM의 정의 및 표준화 배경 인지 확인 | NIST FIPS 203, Kyber 기반, PQC 표준 | Kyber와 별개의 알고리즘으로 오인 |
| 핵심 수학적 원리 파악 역량 | Module-Lattice, MLWE 난제, 노이즈 추가 | RSA의 소인수분해 원리와 혼동 |
| KEM 동작 프로세스 이해도 판단 | KeyGen, Encaps, Decaps 3단계 절차 | 일반적인 공개키 암호화(Encryption)와 혼동 |

> 요약: ML-KEM은 격자 기반의 MLWE 난제를 활용하여 양자 내성을 확보한 키 공유 표준이다.

## Ⅰ. 개요 및 필요성

- 정의: 모듈 격자 기반 학습 오차(MLWE) 문제를 활용하여 설계된 NIST 표준 양자내성 키 캡슐화 메커니즘 (FIPS 203)
- 배경: 쇼어 알고리즘 기반 양자 공격에 의한 현행 RSA/ECDH 키 교환 체계의 잠재적 붕괴 위협 대응
- 필요성: 고속 네트워크 통신 보안 강화, 마이그레이션 용이성 확보, 전 세계 표준 보안 인프라 구축

---

## Ⅱ. 구조 및 구성요소

```text
[ ML-KEM Architecture ]
        |
  +-----v---------------------------+
  |  MLWE (Module Learning with Errors)  | -> 수학적 난제 (Core)
  +-----+---------------------------+
        |
  +-----v-----------+      +--------v----------+      +--------v---------+
  | Key Generation  |      |  Encapsulation    |      |  Decapsulation   |
  | (PK, SK 생성)   |      |  (Ciphertext 생성)|      |  (Shared Key 추출)|
  +-----------------+      +-------------------+      +------------------+
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| MLWE Problem | 격자 벡터에 미세 노이즈를 섞어 해를 구하기 어렵게 함 | 양자 공격에 대한 보안 근거 |
| Public Key (PK) | 암호화(캡슐화) 시 사용되는 공개 격자 벡터 정보 | 크기: 약 800~1,500 Bytes |
| Secret Key (SK) | 복호화(역캡슐화) 시 사용되는 비밀 다항식 정보 | 안전한 저장 필수 |
| Ciphertext (CT) | 전송되는 캡슐화된 키 정보 | 암호문 크기 최적화 |

> 요약: MLWE 난제를 기반으로 키 생성, 캡슐화, 역캡슐화라는 3가지 표준 인터페이스를 제공한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
(A) PK 생성 -> (B) PK 전송 -> (C) 키 캡슐화(Shared Key 숨김) -> (D) 암호문 전송 -> (E) 역캡슐화(Shared Key 추출)
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | Key Generation | 모듈 격자 위에서 임의의 다항식 벡터와 노이즈를 선택하여 PK 생성 | 개인키 유출 방지(HSM 활용) |
| 2 | Encapsulation | 수신자의 PK를 활용하여 공용키(K)를 생성하고, 이를 격자 수식으로 감싸 암호문 생성 | 암호문 무작위성 확보 |
| 3 | Transmission | 생성된 암호문(CT)을 네트워크(TLS 등)를 통해 송신자에게 전달 | 패킷 유실 방지 |
| 4 | Decapsulation | 자신의 SK를 이용해 격자 수식의 노이즈를 제거하고 동일한 공용키(K) 추출 | 추출된 키의 일치성 (100%) |
| 5 | Shared Secret 확보 | 양측이 동일한 K를 공유하게 되며, 이후 대칭키 암호(AES) 통신 시작 | 세션 키 독립성 확보 |

> 요약: 공개키를 이용해 비밀키를 '상자(캡슐)'에 넣어 보내고, 개인키로만 그 상자를 열어 비밀키를 공유하는 방식이다.

## Ⅳ. 특징 (파라미터 레벨 비교)

| 구분 | ML-KEM-512 | ML-KEM-768 | ML-KEM-1024 |
|:---|:---|:---|:---|
| 보안 등급 (NIST) | Category 1 (AES-128급) | Category 3 (AES-192급) | Category 5 (AES-256급) |
| 공개키 크기 (Byte) | 800 | 1,184 | 1,568 |
| 암호문 크기 (Byte) | 768 | 1,088 | 1,568 |
| 주 사용 용도 | 일반 웹 통신 | 기업용 보안, 표준 추천 | 국가 기밀, 초고보안 |

> 요약: ML-KEM-768이 성능과 보안의 균형이 가장 우수하여 글로벌 표준으로 가장 널리 권장된다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존 ECDH (Elliptic Curve) | ML-KEM (Post-Quantum) | 선택 기준 |
|:---|:---|:---|:---|
| 양자 내성 | 없음 (즉시 해독 가능) | 있음 (양자 저항성 확보) | 미래 보안 위협 대응 필요성 |
| 키 크기 | 작음 (약 32~64 Bytes) | 큼 (약 1,184 Bytes) | 네트워크 대역폭 제한 여부 |
| 연산 속도 | 보통 | 매우 빠름 (최적화 우수) | 대규모 세션 처리량(TPS) |
| 표준 상태 | 현행 주류 표준 | 신규 채택 글로벌 표준 | 호환성 및 규제 준수 요구사항 |

> 요약: 키 크기는 커지나 연산 속도가 빠르므로, 대역폭보다 연산 성능이 중요한 서버 환경에 매우 유리하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 패킷 분할 (Fragmentation) | 큰 암호문 크기로 인해 TCP MTU 초과 가능성 | 하이브리드 암호 패키징 최적화 | 네트워크 재전송률 |
| 구현 취약점 | 부채널 공격(Side-channel) 등에 노출 가능성 | 상수 시간(Constant-time) 구현 준수 | 부채널 분석 통과 여부 |
| 암호 오용 | KEM의 특성을 오해하여 직접 암호화에 사용 | 표준 라이브러리(OQS 등) 및 API 강제 | 표준 가이드라인 준수율 |

> 요약: 큰 키 크기에 따른 네트워크 부하와 부채널 공격 가능성을 설계 단계에서 통제해야 한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 키 생성 속도 | 초당 50,000회 이상 처리 | 벤치마킹 툴 (OpenSSL 등) |
| 보안 강도 준수 | FIPS 203 정합성 100% | 테스트 벡터(Test Vectors) 검증 |
| 메모리 점유 | 큐비트 연산 대비 효율성 확보 | 프로파일링 도구 활용 |

> 요약: 도입 성과는 NIST 표준 부합성 및 기존 인프라에서의 실시간 처리 성능으로 측정한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. TLS 1.3 하이브리드 적용: 기존 X25519와 ML-KEM-768을 결합한 'X25519Kyber768' 초안 프로토콜을 웹 서버에 탑재하여 즉각적인 양자 내성 확보
2. VPN 및 전용선 보안 강화: IPsec이나 SSH 터널링 구간의 키 교환 방식을 ML-KEM으로 교체하여 국가 기간망 보안 고도화
3. HSM 기반 키 관리: 하드웨어 보안 모듈(HSM)에서 ML-KEM 키 생성을 지원하도록 펌웨어를 업데이트하여 루트 키 보안성 강화

**결론 (2줄):**
- 기술사 판단: ML-KEM은 양자 컴퓨팅 시대의 첫 번째 필수 방어선이며, 높은 효율성 덕분에 기존 인프라에 가장 빠르게 스며들 표준 기술이다
- 향후 방향: 모바일 단말기 및 임베디드 기기 최적화를 거쳐 모든 커넥티드 기기의 기본 암호 프로토콜로 자리 잡을 전망이다
