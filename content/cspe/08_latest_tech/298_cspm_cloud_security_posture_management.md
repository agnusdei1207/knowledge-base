# 📖 【암기용】 개념 완전 이해

> 목적: CSPM을 클라우드 계정의 설정 오류와 컴플라이언스 위반을 지속 점검하는 보안 형상관리로 이해하게 만든다.

## 한눈에
- **개요**: 클라우드 자산 설정과 정책 준수 상태를 지속 점검·조치하는 보안 관리 체계
- **왜 필요한가**: 클라우드는 API로 자원이 수시로 생성되어 공개 스토리지, 과도한 보안그룹, 암호화 누락 같은 설정 오류가 즉시 노출로 이어진다.
- **핵심 직관**: 건물 문과 창문이 잠겼는지 매일 자동 점검하고, 열린 창문을 담당자에게 알려 닫게 하는 시스템이다.

## 깊이 이해
- **배경·문제의식**: 클라우드 보안 사고는 제로데이보다 오픈 버킷, 0.0.0.0/0 보안그룹, 과다 권한 같은 설정 오류에서 자주 시작된다.
- **작동 원리**: 클라우드 API로 자산을 수집하고, CIS Benchmark·내부 정책·규제 기준과 비교해 위반 항목을 탐지하고 조치 워크플로로 연결한다.
- **비유**: 회계 장부를 매월 결산하듯 클라우드 계정의 보안 설정을 계속 대조해 기준에서 벗어난 항목을 찾는 것이다.
- **구체 예시**: Object Storage 버킷이 public read로 변경되면 CSPM이 탐지하고 담당자 티켓을 생성하거나 정책에 따라 자동 차단한다.
- **흔한 오해·주의점**: CSPM은 런타임 악성 행위 탐지가 중심이 아니다. 설정·컴플라이언스·자산 가시성에 초점을 둔다.

## 연결 개념
- CNAPP — CSPM을 포함하는 통합 클라우드 보호 플랫폼
- CIEM — 클라우드 권한 위험 분석
- IaC Security — 배포 전 설정 오류 차단

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.
> 핵심: CSPM은 클라우드 설정 오류를 지속 점검하고 컴플라이언스 기준과 비교해 조치하는 형상관리 체계다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: CSPM은 클라우드 자산 설정, 정책, 컴플라이언스 상태를 자동 수집·평가·조치하는 보안 형상관리임.
> 2. **가치**: 공개 저장소, 과다 포트 개방, 암호화 누락, 로그 미설정 등 설정 오류를 배포 후에도 지속 탐지함.
> 3. **판단 포인트**: 자산 가시성, 정책 기준, drift 탐지, 자동 조치, 예외 관리가 핵심 평가 기준임.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 클라우드 설정 위험 이해 확인 | misconfiguration, compliance drift, API 수집 | 취약점 스캐너와 혼동 |
| 운영 통제 판단 확인 | 정책 기준, 예외, 자동 조치, 감사 | 단발성 점검으로 설명 |
| CNAPP/CWPP 구분 확인 | CSPM=설정·컴플라이언스 중심 | 워크로드 런타임 보호로 오기 |

> 요약: 이 문제는 클라우드 보안 사고의 주요 원인인 설정 오류를 지속 형상관리로 통제하는지 확인한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 클라우드 설정 보안 점검
- 배경: 클라우드 자산은 API와 IaC로 수시 생성되어 수동 점검만으로 공개 설정과 정책 drift를 찾기 어려움.
- 필요성: 보안그룹, 스토리지 공개, 암호화, 로그, IAM 설정을 기준 정책과 계속 대조해야 함.

---

## Ⅱ. 구조 및 구성요소

```text
Cloud Accounts -> Asset Inventory -> Policy Engine
  +-> Misconfiguration Detection -> Risk Scoring -> Remediation
  +-> Compliance Report / Exception Management
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 자산 인벤토리 | 계정·리전·서비스 자산 수집 | 멀티클라우드 API 연계 |
| 정책 엔진 | 기준 정책과 실제 설정 비교 | CIS, ISO, 내부 기준 |
| 조치 워크플로 | 담당자 통보·자동 수정 | ticket, auto-remediation |
| 예외 관리 | 업무상 허용 설정 통제 | 승인자·만료일 필요 |

> 요약: CSPM은 자산 수집, 정책 비교, 조치, 예외 관리를 반복해 클라우드 설정 상태를 관리한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
클라우드 API 수집 -> 자산 정규화 -> 정책 평가
-> 위반 탐지 -> 위험도 산정 -> 조치 / 예외 승인 -> 재평가
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 클라우드 계정과 리전별 자산 수집 | inventory coverage |
| 2 | 설정을 기준 정책과 대조 | policy pass rate |
| 3 | 노출도와 중요도로 위험도 산정 | public exposure |
| 4 | 티켓·자동 조치·예외 만료 관리 | remediation SLA |

> 요약: CSPM은 클라우드 설정을 주기적으로 수집해 정책 위반을 찾고 조치 후 재평가한다.

---

## Ⅳ. 특징

| 구분 | 수동 점검 | CSPM | 판단 기준 |
|:---|:---|:---|:---|
| 자산 파악 | 계정별 수작업 | API 기반 자동 수집 | 계정·리전 수 |
| 점검 방식 | 체크리스트 중심 | 정책 엔진 지속 평가 | 변경 빈도 |
| 조치 | 담당자 메일 | 티켓·자동 조치 | SLA 관리 |
| 한계 | 누락 가능 | 런타임 행위 탐지 제한 | CWPP 보완 필요 |

> 요약: CSPM은 설정 drift를 지속 관리하지만 워크로드 내부 악성 행위 탐지는 CWPP와 함께 봐야 한다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 보안 체크리스트 | API 기반 정책 평가 | 클라우드 계정 수 |
| 비용 | 수동 감사 인력 | 자동 점검 도구 | 변경 빈도와 감사 요구 |
| 운영 | 발견 후 수동 조치 | ticket·auto-remediation | 반복 위반 수 |

> 요약: 클라우드 자산 변경이 잦고 규제 보고가 필요하면 CSPM을 우선 도입한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 오탐 누적 | 업무 예외 미반영 | 예외 승인·만료 관리 | false positive |
| 자산 누락 | 신규 계정 미연동 | 조직 계정 자동 등록 | unmanaged account |
| 자동 조치 사고 | 운영 서비스 설정 변경 | dry-run, 승인 기반 조치 | rollback count |

> 요약: CSPM 리스크는 오탐, 자산 누락, 자동 조치 사고이며 예외와 승인 체계로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 가시성 | 계정·리전 누락 없음 | cloud org 대조 |
| 정책 준수 | critical 위반 우선 조치 | compliance dashboard |
| 조치 | SLA 내 위반 해소 | ticket aging |

> 요약: CSPM 성과는 점검 건수가 아니라 자산 가시성, critical 위반 해소, 조치 SLA로 판단한다.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 클라우드 조직 계정, 리전, 프로젝트를 모두 등록하고 신규 계정 자동 온보딩 절차를 만든다.
2. CIS Benchmark, 개인정보 보호, 내부 보안 기준을 정책 세트로 나누고 critical 위반부터 조치 SLA를 부여함.
3. 자동 조치는 low-risk 설정에 한정하고, 보안그룹·스토리지 공개 설정은 승인 기반 변경으로 운영함.

**결론 (2줄):**
- 기술사 판단: 클라우드 설정 오류와 감사 요구가 주요 문제면 CSPM, 런타임 보호가 필요하면 CWPP 또는 CNAPP 조합이 타당함.
- 향후 방향: CSPM은 CIEM, IaC scanning, DSPM과 결합해 배포 전후 설정 위험을 연결하는 방향으로 발전함.
