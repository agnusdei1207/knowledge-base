# 📖 【암기용】 개념 완전 이해

> 목적: CWPP를 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 클라우드에서 돌아가는 다양한 실행 환경(가상 서버, 컨테이너, 서버리스 등) 내부를 해킹이나 악성코드로부터 보호하는 보안 솔루션
- **왜 필요한가**: 클라우드 인프라 설정(CSPM)이 잘 되어 있어도, 그 안에서 돌아가는 애플리케이션 자체가 취약하거나 해킹당하면 소용없다. 실제 "일이 벌어지는 현장(워크로드)"을 지켜야 하기 때문이다.
- **핵심 직관**: "클라우드 서비스 내부에서 돌아가는 프로그램들을 위한 전담 보디가드"

## 깊이 이해
- **배경·문제의식**: 예전 서버 보안(백신)은 물리 서버에 하나씩 깔면 됐지만, 클라우드는 환경이 너무 다양하다(VM, Docker, Kubernetes 등). 또한 서버가 수시로 생겼다 사라지는 '탄력성' 때문에 기존 방식으론 보안을 챙기기 어렵다.
- **작동 원리**: **Scan -> Hardening -> Runtime Protection**. ① Scan: OS나 라이브러리에 취약점이 있는지 검사. ② Hardening: 불필요한 포트를 닫고 설정을 강화. ③ Runtime: 실제 실행 중인 프로그램이 평소와 다른 행동(예: 갑작스러운 파일 암호화)을 하면 즉시 차단.
- **비유**: 건물의 보안 설정(CSPM)이 잘 되어 있어도, 내부 사무실에서 일하는 직원(워크로드)이 가짜 이메일을 열어 바이러스에 걸릴 수 있다. 각 직원 옆에 보안 전문가(CWPP)를 붙여서 이상한 행동을 못 하게 감시하는 것과 같다.
- **구체 예시**: 트렌드마이크로 Cloud One, 아쿠아 시큐리티(Aqua Security), 팔로알토 프리즈마. 컨테이너 내부의 비정상적인 프로세스 실행을 탐지하고 "이 컨테이너는 취약점이 있으니 실행하지 마세요"라고 막는 기능이다.
- **흔한 오해·주의점**: "일반 PC 백신"과는 다르다. PC 백신은 파일 검사 위주지만, CWPP는 클라우드의 복잡한 네트워크 흐름, 시스템 콜(System Call), API 호출까지 분석해야 한다.

## 연결 개념
- CSPM (Cloud Security Posture Management) — 워크로드 내부가 아닌 인프라 설정(껍데기)을 보호
- Micro-segmentation — 워크로드 간의 통신을 아주 잘게 쪼개어 보안을 강화하는 기술
- Zero Trust — 모든 워크로드 간 통신을 일단 의심하고 검증하는 원칙

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 가상화 서버(VM), 컨테이너, 서버리스 등 이기종 클라우드 실행 환경에 대한 통합 가시성 확보와 실시간 위협 대응을 중심으로 서술한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: CWPP(Cloud Workload Protection Platform)는 클라우드 환경의 다양한 워크로드(VM, Container, Serverless) 내부의 취약점을 탐지하고 실행 시점(Runtime)의 위협으로부터 보호하는 워크로드 중심 보안 솔루션이다.
> 2. **가치**: 인프라 위치와 상관없이 일관된 보안 정책을 적용하여 서버 내부의 가시성을 확보하고, 제로 데이(Zero-day) 공격 및 횡적 이동(Lateral Movement)을 차단한다.
> 3. **판단 포인트**: 에이전트 기반의 심층 분석과 에이전트리스 기반의 유연한 스캔 기술을 워크로드 특성에 맞게 하이브리드로 적용하는 능력이 중요하다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| CWPP의 정의 및 필요성 이해 | 워크로드(VM, 컨테이너, 서버리스) 보호, 런타임 보안 | 인프라 설정 보안(CSPM)과 혼동하여 서술 금지 |
| 주요 보안 기능 및 기술 요소 파악 | 취약점 스캔, 무결성 모니터링, IPS, 화이트리스트 제어 | 단순 백신(Anti-virus) 수준으로 서술 시 감점 |
| 클라우드 환경 변화에 따른 대응력 확인 | 오토스케일링 대응, 컨테이너 이미지 스캔, CI/CD 연동 | 정적인 서버 보안 방식(Static) 고수 지양 |

> 요약: 실행 환경의 가변성과 복잡성을 극복하고 '애플리케이션이 돌아가는 시점'의 보안을 보장하는 역량을 평가한다.

## Ⅰ. 개요 및 필요성

- 정의: 퍼블릭/프라이빗 클라우드 내의 서버, 컨테이너, 서버리스 등 다양한 워크로드를 위협으로부터 보호하는 에이전트/API 기반 보안 플랫폼
- 배경: 기존 엔드포인트 보안(EPP)의 클라우드 확장성 한계 및 마이크로서비스 아키텍처(MSA) 확산에 따른 동적 자산 관리 필요
- 필요성: 시스템 내부의 가시성 확보, 런타임 공격(Exploit) 방어, 컴플라이언스(ISMS, PCI-DSS 등) 요건 충족

## Ⅱ. 구조 및 구성요소

```text
[ Cloud Workloads ]
  / VM (EC2 등)      : 에이전트 기반 보호
  / Container (K8s) : Sidecar 또는 호스트 기반 보호
  / Serverless (FaaS): 라이브러리 또는 API 기반 보호
        |
[ CWPP 제어 센터 (Management Console) ]
  / 취약점 관리 | 파일 무결성(FIM) | 네트워크 세그먼트 | 침입 방지(HIPS)
```

| 구성요소 | 역할 | 상세 기능 |
|:---|:---|:---|
| 취약점 스캐닝 | 배포 전후의 OS/Library 취약점 식별 | CVE 기반 스캔, 미승인 소프트웨어 탐지 |
| 런타임 보호 | 실행 중인 프로세스의 비정상 행위 감시 | 메모리 보호, 시스템 콜 분석, 악성코드 차단 |
| 파일 무결성 감시 (FIM) | 시스템 파일 및 설정의 무단 변경 탐지 | 주요 디렉토리 모니터링 및 변경 이력 기록 |
| 마이크로 세그멘테이션 | 워크로드 간 동적 방화벽 정책 적용 | 서버 간 트래픽 가시화 및 불필요 통신 차단 |
| 화이트리스트 제어 | 승인된 프로세스만 실행 허용 | Application Control, 비인가 실행 파일 차단 |

> 요약: 워크로드의 라이프사이클(빌드-배포-실행) 전반에 걸쳐 내부적인 위협 요소를 제거하고 방어한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
이미지 스캔(Build) -> 배포 전 게이팅(Deploy) -> 자원 무결성 확인 -> 런타임 모니터링(Run) -> 위협 차단 및 격리
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 정적 분석 (Static) | 컨테이너 이미지 또는 VM 이미지 내 알려진 취약점 점검 |
| 2 | 구성 강화 (Hardening) | 불필요한 서비스 제거, 권한 최소화 설정 확인 |
| 3 | 실시간 탐지 (Runtime) | 실시간 시스템 콜 및 네트워크 행위 분석 기반 공격 탐지 |
| 4 | 침해 사고 대응 | 감염된 워크로드 자동 격리(Quarantine) 및 스냅샷 생성 |

> 요약: 알려진 취약점을 사전에 제거하고, 알려지지 않은 위협(Zero-day)은 실행 시점의 행위 분석으로 방어한다.

## Ⅳ. 특징

| 구분 | CSPM (Posturing) | CWPP (Workload) |
|:---|:---|:---|
| 보호 계층 | 클라우드 제어 평면 (Control Plane) | 데이터/실행 평면 (Data Plane) |
| 주요 관심사 | 잘못된 설정 (Misconfiguration) | 소프트웨어 취약점, 악성 행위 (Exploit) |
| 작동 방식 | API 기반 (Agentless) | 에이전트 또는 사이드카 (Agent/Sidecar) |
| 예시 | S3 Public 설정 여부 체크 | 컨테이너 내 쉘 탈취 시도 차단 |

> 요약: CSPM이 "문이 잠겼는가"를 본다면, CWPP는 "집 안에서 누가 나쁜 짓을 하는가"를 감시한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 에이전트 방식 (Agent-based) | 에이전트리스 방식 (Agentless) | 선택 기준 |
|:---|:---|:---|:---|
| 분석 깊이 | 매우 깊음 (시스템 콜, 메모리 등) | 상대적 얕음 (스토리지 스캔 위주) | 보안 중요도 및 실시간성 요구 |
| 운영 부담 | 높음 (업데이트, 성능 영향) | 낮음 (배포 용이, 부하 없음) | 자원 관리의 탄력성 수준 |
| 런타임 차단 | 가능 (실시간 제어) | 불가 (사후 또는 간접 탐지) | 즉각적 대응 필요성 여부 |

> 요약: 핵심 워크로드는 에이전트 방식으로 실시간 보호하고, 대규모/단기 자산은 에이전트리스 방식으로 가시성을 확보하는 하이브리드 전략이 권장된다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 성능 저하 | 보안 에이전트의 CPU/MEM 과다 점유 | 커널 모드 활용, 경량화 에이전트 선정 | 인프라 자원 소모율 (< 5% 목표) |
| 오탐에 의한 서비스 중단 | 정상적인 앱 동작을 공격으로 오인 차단 | 학습 모드(Learning Mode) 선행, 예외 처리 | False Positive 발생 빈도 |
| 관리 사각지대 | 오토스케일링으로 생성된 신규 자원 누락 | 자동화된 에이전트 배포(IaC) 연동 | 전체 자산 대비 보안 적용률 |

> 요약: 성능 부하와 관리 누락을 방지하기 위해 자동화된 배포 체계와 경량화 기술 도입이 필수적이다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 취약점 제거율 | 고위험 취약점 배포 전 제거 100% | 이미지 스캔 통계 및 CI/CD 통과율 |
| 런타임 탐지 정확도 | 주요 Exploit 기법 탐지율 99% | 공격 시뮬레이션 및 레드팀 테스트 |
| 자산 가시성 | 모든 실행 중인 프로세스 파악 100% | 인벤토리 자동 갱신 로그 확인 |

> 요약: 도입 효과는 취약점의 사전 제거율과 런타임 공격에 대한 방어 성공률로 측정한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. **컨테이너 보안**: Kubernetes 환경에서 각 파드(Pod)에 사이드카를 배치하여 컨테이너 간의 비정상 트래픽을 차단하고 이미지 취약점 상시 점검
2. **랜섬웨어 방어**: 파일 무결성 감시(FIM) 기능을 활성화하여 시스템 설정 파일이나 중요한 데이터 파일이 갑자기 수정될 때 즉시 프로세스 중단
3. **서버리스 보호**: AWS Lambda 등 서버리스 환경에서 라이브러리 형태의 보안 모듈을 결합하여 권한 오남용 및 악성 코드 실행 감시

**결론 (2줄):**
- 기술사 판단: CWPP는 클라우드 보안의 '실행력'이며, 최근에는 CSPM과 결합한 통합 플랫폼(CNAPP) 형태로 진화하여 입체적인 방어 체계를 구축하는 것이 대세이다.
- 향후 방향: eBPF 기술을 활용하여 성능 저하 없이 시스템 콜 수준에서 세밀한 감시와 차단을 수행하는 '초경량 런타임 보안'이 핵심이 될 전망이다.
