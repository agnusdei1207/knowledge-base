# 📖 【암기용】 개념 완전 이해

> 목적: 여러 대의 GPU로 AI 모델을 학습시키는 가장 직관적이고 기본적인 방법인 '데이터 병렬화'의 작동 방식을 이해한다.

## 한눈에
- **정의**: AI 모델(신경망) 자체는 그대로 여러 GPU에 복사해 두고, 학습할 **'데이터(Data)'만 잘게 쪼개어 각각의 GPU에 나눠 먹인 뒤** 결과를 합치는 분산 학습 기법
- **필요성**: AI 모델의 크기는 작아서 GPU 1대의 메모리에 쏙 들어가지만, 학습해야 할 데이터가 수백 TB에 달해 1대로 돌리면 수십 년이 걸릴 때 시간을 극적으로 단축하기 위함
- **핵심 직관**: "동일한 요리법(AI 모델)을 아는 10명의 요리사(GPU)에게, 1만 포기의 배추(데이터)를 1,000포기씩 나눠주고 김장을 담그게 한 뒤 최종 김치 맛(가중치)을 하나로 맞추는 것"

## 깊이 이해
- **배경(왜 등장했나?)**: 딥러닝이 발전하면서 이미지넷(ImageNet)처럼 수백만 장의 이미지를 학습해야 했다. 단일 GPU로 미니배치(Mini-batch) 단위로 계속 밀어넣으면 에포크(Epoch)를 1번 도는 데 며칠이 걸렸다. "어차피 모델 구조는 같으니, 데이터를 10등분해서 10대의 GPU에 동시에 먹이면 10배 빨리 끝나지 않을까?"라는 발상에서 시작되었다.
- **작동 원리(어떻게 달성했나?)**: 
  1. **모델 복제 (Model Replication)**: 4대의 GPU에 똑같은 초기 AI 모델 파라미터를 복사한다.
  2. **데이터 분할 (Data Partitioning)**: 전체 100만 장의 이미지를 25만 장씩 쪼개어 각 GPU에 준다.
  3. **독립 연산 (Forward/Backward)**: 각 GPU는 자신이 받은 데이터만으로 오차를 계산하고 기울기(Gradient)를 구한다.
  4. **동기화 (Synchronization)**: 4대의 GPU가 구한 각각의 기울기를 모아서(All-Reduce) 평균을 낸다.
  5. **파라미터 업데이트**: 평균 낸 기울기로 4대의 GPU가 똑같이 자신의 모델을 업데이트한다. (다시 1번으로 돌아감)
- **일상 비유**: 선생님 4명이서 4,000장의 시험지를 채점해야 한다. 정답지(모델)를 4명 모두 똑같이 복사해서 나눠 가진다. 시험지(데이터)를 1,000장씩 나눠서 각자 채점한다. 채점이 끝나면 4명이 각자 몇 점이었는지 불러주고 평균 점수(기울기)를 계산해서 성적표에 같이 적는다(동기화).
- **구체 예시**: PyTorch에서 가장 많이 쓰이는 `DistributedDataParallel (DDP)` 모듈이 바로 데이터 병렬화를 자동화해주는 프레임워크다.
- **흔한 오해/주의점**: "데이터 병렬화만 있으면 거대 모델(LLM)도 다 학습시킬 수 있나?" → 절대 아니다. **데이터 병렬화는 GPU 1대 메모리(예: 80GB) 안에 AI 모델(파라미터+옵티마이저)이 온전히 들어갈 때만 쓸 수 있다.** GPT-3(175B)처럼 모델 크기 자체가 수백 GB를 넘어가면 1대 메모리에 안 들어가서 아예 복제조차 불가능하다. 이때는 모델 병렬화(MP)나 텐서 병렬화(TP)를 써야 한다.

## 연결 개념
- **All-Reduce**: 각 GPU가 계산한 기울기를 하나로 합쳐서 평균을 내는 필수 집합 통신 알고리즘
- **DDP (Distributed Data Parallel)**: 파이토치(PyTorch)에서 제공하는 데이터 병렬 처리 최적화 패키지
- **Model Parallelism (모델 병렬화)**: 데이터가 아니라 '모델'을 쪼개서 여러 GPU에 나누는 방식 (데이터 병렬화의 대척점)

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 데이터 병렬화(DP)는 다수의 워커(GPU)에 동일한 모델 파라미터를 복제해 두고, 글로벌 미니배치(Global Mini-batch)를 로컬 미니배치로 분할하여 동시에 연산하는 분산 훈련 아키텍처이다.
> 2. **가치**: 모델 크기보다 훈련 데이터셋이 압도적으로 큰 워크로드(예: Vision Model 학습)에서, Compute Resource를 횡적(Scale-out)으로 늘려 학습 소요 시간(Time-to-Train)을 선형적으로 단축한다.
> 3. **판단 포인트**: 각 스텝마다 모델 파라미터를 동기화(Synchronization)해야 하므로 통신 오버헤드가 발생하며, 단일 GPU 메모리 제약을 넘어서는 거대 모델에는 단독으로 적용할 수 없는 태생적 한계가 있다.

## Ⅰ. 개요 및 필요성
- **정의**: 전체 훈련 데이터를 분할하여 다수의 연산 노드에 할당하고, 각 노드가 독립적으로 그레이디언트(Gradient)를 연산한 뒤, 이를 종합하여 모델 가중치를 동기화하는 분산 학습 기법
- **배경**: 딥러닝 훈련 데이터셋 사이즈의 기하급수적 증가로 인해 단일 가속기(Single GPU) 기반 학습의 소요 시간(Iteration Time)이 물리적 한계에 직면
- **필요성**: 기존 모델 아키텍처(코드)의 수정 없이 배치 사이즈(Batch Size)를 늘려 컴퓨팅 성능에 비례하는 훈련 속도 향상 필요

## Ⅱ. Data Parallelism 핵심 메커니즘 (동기식 기준)
```text
[ Global Data ] (1024 Batch)
      │ (Data Split)
      ├──> [ GPU 0 ] Data: 256 / Model: M0 ──> Gradient 0 (기울기 계산) ─┐
      ├──> [ GPU 1 ] Data: 256 / Model: M1 ──> Gradient 1 (기울기 계산) ─┼── All-Reduce
      ├──> [ GPU 2 ] Data: 256 / Model: M2 ──> Gradient 2 (기울기 계산) ─┼── (평균 계산)
      └──> [ GPU 3 ] Data: 256 / Model: M3 ──> Gradient 3 (기울기 계산) ─┘
                                                                          │
[ 모든 GPU가 동일한 평균 Gradient로 가중치 업데이트 (Synchronization) ] ◀───────┘
```

1. **복제 (Replicate)**: 마스터 노드가 최신 가중치를 모든 워커 노드(GPU)에 동일하게 복사.
2. **분산 (Scatter)**: 전체 미니배치 데이터를 $N$(GPU 수)개로 나누어 각 워커에 분배.
3. **연산 (Compute)**: 각 워커가 수신한 데이터로 순전파(Forward) 및 역전파(Backward)를 수행하여 독립적인 로컬 기울기 획득.
4. **동기화 (Synchronize)**: All-Reduce 등의 집합 통신으로 모든 워커의 로컬 기울기를 합산 및 평균화하여 글로벌 기울기 생성.
5. **업데이트 (Update)**: 산출된 글로벌 기울기를 바탕으로 각 워커가 자신의 가중치를 업데이트. (다음 스텝 준비)

## Ⅲ. Data Parallel (DP) vs Distributed Data Parallel (DDP)
PyTorch 환경에서 주로 쓰이는 두 가지 데이터 병렬화 방식의 비교.

| 구분 | DP (DataParallel) | DDP (DistributedDataParallel) |
|:---|:---|:---|
| **프로세스 관리** | 1개의 프로세스가 다중 스레드(Multi-thread)로 통제 | **GPU당 1개의 독립된 프로세스(Multi-process) 할당** |
| **GIL 병목 (Python)** | 발생 (Global Interpreter Lock의 영향 받음) | **발생 안 함 (프로세스가 분리되어 있으므로)** |
| **통신 오버헤드** | 매 스텝마다 마스터 GPU로 파라미터를 모았다가 다시 복사 | **Ring All-Reduce 알고리즘을 통한 병목 없는 통신** |
| **적용 범위** | 단일 서버 내부(Single-node)만 가능 | **다중 서버(Multi-node) 클러스터 환경 지원** |
| **권장 여부** | 비권장 (레거시 코드) | **현대 딥러닝 분산 학습의 표준 (De-facto)** |

## Ⅳ. 데이터 병렬화의 아키텍처적 한계
1. **메모리 장벽 (Memory Wall)**: 각 워커(GPU)는 모델의 전체 파라미터, 옵티마이저 상태(Adam 등), 그레이디언트를 모두 온전히 메모리에 올려야 한다. 따라서 모델 사이즈가 단일 GPU VRAM 용량(예: 80GB)을 초과하면 **Out-Of-Memory(OOM)**가 발생하여 학습 자체가 불가능하다.
2. **통신 병목 (Communication Bottleneck)**: 모델 파라미터가 커질수록 매 스텝마다 동기화해야 할 데이터(Gradient) 전송량이 급증하여, GPU는 연산(Compute)보다 통신(Network)을 기다리는 유휴 상태(Idle)에 빠지게 된다.

## Ⅴ. 한계 극복 및 최신 동향 (3D Parallelism의 등장)
| 한계 요인 | 대응 아키텍처 및 기법 |
|:---|:---|
| **단일 GPU 메모리 부족** | 메모리 안에 모델이 다 들어가지 않는 문제를 해결하기 위해, 데이터 병렬화와 함께 **모델 병렬화(MP), 텐서 병렬화(TP), 파이프라인 병렬화(PP)**를 혼합 적용 (3D 병렬화) |
| **메모리 중복 낭비** | 모든 GPU가 동일한 옵티마이저 상태를 중복으로 들고 있는 낭비를 제거하기 위해 **ZeRO (Zero Redundancy Optimizer)** 기법 적용 |
| **통신 병목 현상** | All-Reduce 지연을 숨기기 위해 역전파(Backward) 계산 중 기울기가 산출되는 즉시 순차적으로 통신을 시작하는 오버래핑(Communication-Computation Overlapping) 적용 |

## Ⅵ. 실무 적용 및 결론
**적용 방안 및 실무 가이드:**
1. **컴퓨터 비전(CV) 모델 학습**: ResNet, ViT 등 비교적 모델 사이즈가 작고(수억 개 파라미터) 이미지 데이터셋이 방대한 워크로드에서는, 복잡한 파이프라인 병렬화 없이 DDP(데이터 병렬화)만으로도 클러스터 스케일링 효율을 90% 이상 낼 수 있다.
2. **배치 사이즈 조절 주의**: GPU를 늘릴수록 전체 글로벌 배치 사이즈(Global Batch Size)가 커지므로, 학습 수렴(Convergence) 안정성을 잃을 수 있다. 이에 맞춰 학습률(Learning Rate)을 비례해서 키우는 Linear Scaling Rule 튜닝이 필수적이다.

**결론:**
- 데이터 병렬화(DP)는 가장 직관적이고 구현이 쉬운 분산 학습의 시발점(Starting Point)이다.
- 최근 LLM 시대로 접어들며 DP 단독으로는 한계가 뚜렷해졌으나, TP(텐서), PP(파이프라인)로 모델을 쪼갠 후에도 남는 방대한 클러스터 자원을 활용하기 위해서는 **결국 마지막 레이어로 결합되어야 하는 가장 기저의 병렬화 기술**이다.
