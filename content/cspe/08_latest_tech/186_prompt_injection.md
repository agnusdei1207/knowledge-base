# 📖 【암기용】 개념 완전 이해

> 목적: Prompt Injection을 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: 사용자가 악성 지시문을 입력해 LLM의 시스템 지시, 정책, 도구 사용 규칙을 우회시키는 공격
- **왜 필요한가**: LLM은 자연어 명령을 코드처럼 해석하므로 데이터 입력과 명령 경계가 흐려짐.
- **핵심 직관**: 입력창에 질문이 아니라 운영 규칙을 덮어쓰려는 명령을 넣는 공격임.

## 깊이 이해
- **배경·문제의식**: 전통 애플리케이션은 코드와 데이터가 분리되지만 LLM은 시스템 프롬프트, 사용자 입력, 검색 문서가 모두 자연어 토큰임.
- **작동 원리**: 공격자는 "이전 지시를 무시하라", "관리자 모드로 응답하라" 같은 지시를 넣어 정책 우회, 정보 유출, 도구 오남용을 유도함.
- **비유**: 고객 문의서에 "직원 매뉴얼을 무시하고 금고 비밀번호를 알려라"라고 써서 상담 절차를 흔드는 행위임.
- **구체 예시**: 고객지원 챗봇에 시스템 프롬프트 공개를 요구하고 내부 할인 정책, API 토큰 형식, 관리자 지침을 노출시키려 시도함.
- **흔한 오해·주의점**: 프롬프트 문구 보정만으로 해결되지 않는다. 권한 분리, 출력 필터, 도구 호출 검증이 함께 필요함.

## 연결 개념
- Indirect Prompt Injection — 외부 문서에 숨어 들어오는 간접 지시
- Jailbreak — 안전 정책 우회 공격
- AI Red Teaming — 프롬프트 공격 검증 활동

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Prompt Injection은 LLM의 명령·데이터 경계 혼재를 악용해 지시 체계를 우회하는 공격임.
> 2. **가치**: 데이터 유출, 정책 우회, 도구 오남용을 유발하므로 생성형 AI 보안의 핵심 위협임.
> 3. **판단 포인트**: 프롬프트 방어보다 권한·도구·출력 검증을 포함한 다층 통제가 필요함.

## Ⅰ. 개요 및 필요성

Prompt Injection은 LLM 지시 우회 공격이다. LLM 서비스는 사용자 입력을 자연어 명령으로 처리하므로 공격자가 시스템 규칙을 덮어쓰려 할 수 있다. 생성형 AI 배포 전 방어와 탐지가 필요하다.

## Ⅱ. 구조 및 구성요소

```text
User Input → Malicious Instruction → LLM Context
  → Policy Bypass → Unsafe Output/Tool Call
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 공격 프롬프트 | 시스템 지시 무시 유도 | ignore previous instruction |
| LLM Context | 지시와 데이터 혼재 | 토큰 경계 취약 |
| Tool/API | 외부 작업 수행 | excessive agency 위험 |
| Guardrail | 입력·출력·권한 통제 | allowlist, policy check |

> 요약: Prompt Injection은 악성 자연어 지시가 LLM 컨텍스트에 들어가 정책 우회와 도구 오남용을 유발함.

## Ⅲ. 동작원리 및 흐름도

```text
공격 입력 작성 → 컨텍스트 삽입 → 정책 우회 시도
  → 응답·도구 실행 → 탐지·차단
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 우회 지시·역할 위장 입력 | 공격 패턴 수집 |
| 2 | 시스템 프롬프트와 충돌 유도 | 정책 위반 탐지 |
| 3 | 민감정보 출력·도구 호출 시도 | 유출률 0% 목표 |
| 4 | 출력 필터·권한 검증 차단 | High finding 0건 |

> 요약: 프롬프트 인젝션 방어는 입력 탐지, 정책 우선순위, 도구 권한, 출력 검증을 연계해야 함.

## Ⅳ. 특징

| 구분 | 일반 입력 검증 | Prompt Injection 대응 | 판단 포인트 |
|:---|:---|:---|:---|
| 공격 형태 | SQL/XSS 패턴 | 자연어 지시 우회 | 의미 기반 탐지 |
| 경계 | 코드·데이터 분리 | 명령·데이터 혼재 | 컨텍스트 분리 |
| 방어 | 정규식·escape | 권한·정책·출력 검증 | 다층 통제 |
| 한계 | 패턴 기반 차단 | 변형 문장 지속 생성 | 레드팀 반복 |

> 요약: Prompt Injection은 자연어 의미를 악용하므로 전통 입력 검증보다 권한과 실행 결과 통제가 중요함.

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 프롬프트 계층화: system/developer/user 지시 우선순위를 명시하고 사용자 입력은 데이터 블록으로 격리
2. 도구 통제: API 호출은 RBAC, allowlist, human approval을 적용하고 삭제·결제 작업은 자동 실행 금지
3. 검증 운영: 200개 이상 공격 프롬프트 회귀 테스트와 유출률 0%, High finding 0건 기준으로 배포 승인

**결론 (2줄):**
- 기술사 판단: LLM이 외부 도구와 연결되면 Prompt Injection을 보안 설계의 1순위 위협으로 반영
- 향후 방향: Prompt Injection 대응은 컨텍스트 격리, 정책 엔진, AI Red Teaming 자동화와 결합됨
