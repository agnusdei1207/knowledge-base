## 미리 알고가기

- 섀도 배포는 실제 트래픽을 새 모델에도 복제하지만 사용자에게는 기존 모델 결과만 제공하는 방식임
- 사용자 영향 없이 운영 데이터를 검증할 수 있어 초기 검증 단계에 유용함
- 트래픽 미러링 비용과 결과 비교 기준이 설계 핵심 포인트임

## Ⅰ. 개요

- **정의/개념**: Shadow Deployment는 운영 트래픽을 기존 서비스와 신규 모델에 동시에 복제해 보내되 실제 사용자 응답은 기존 모델 결과만 사용하고 신규 모델은 관측과 비교 목적으로만 실행하는 배포 전략임
- **배경/필요성**: 오프라인 테스트를 통과한 모델이라도 실제 운영 입력 패턴과 부하 환경에서 어떤 동작을 보일지 확인해야 하므로 사용자 위험 없이 실전 검증하는 단계가 필요함

## Ⅱ. 특징

- 사용자 경험에 직접 영향을 주지 않으면서 운영 입력과 부하를 검증할 수 있음
- 서빙 지연과 리소스 사용량과 예측 분포를 실제 환경에서 비교하기 좋음
- 신규 모델 결과가 실제 의사결정에 반영되지 않아 비즈니스 효과를 직접 측정하기는 어렵음
- 피처 동기화와 미러링 비용이 관리 포인트가 됨

## Ⅲ. 종류 및 비교

| 판단 기준 | Shadow Deployment | Canary Release | A/B Testing |
|:---|:---|:---|:---|
| 사용자 결과 반영 | 기존 모델만 반영 | 일부 사용자에게 신규 반영 | 실험군에 신규 반영 |
| 운영 위험 | 매우 낮음 | 중간 | 중간 이상 |
| 검증 목적 | 기술적 안정성 검증 | 제한적 실전 성과 검증 | 성과 비교 검증 |
| 한계 | 비즈니스 효과 직접 측정 어려움 | 일부 사용자 영향 | 실험 설계 복잡 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Primary Service | 실제 사용자 응답을 담당하는 기존 운영 모델 경로로서 안정성을 유지하는 기준선임 |
| Traffic Mirror | 동일 요청을 후보 모델 경로로 복제해 섀도 실행을 가능하게 하는 미러링 계층임 |
| Shadow Model Service | 실제 응답에는 쓰지 않지만 운영 부하와 입력 조건을 동일하게 받는 후보 모델 환경임 |
| Result Comparison Store | 기존 모델과 섀도 모델의 예측과 지연과 오류를 저장해 사후 비교를 수행하는 저장소임 |
| Analysis Dashboard | 차이와 회귀와 리소스 사용량을 시각화해 승격 여부를 판단하게 하는 평가 계층임 |

 +----------------+    +------------------+

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 후보 환경 준비 | -> | 트래픽 미러링 | -> | 결과 수집    | -> | 차이 분석    | -> | 승격 여부 판단 |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **후보 환경 준비**: 신규 모델을 기존 환경과 유사한 섀도 경로에 배포함
2. **트래픽 미러링**: 운영 요청을 후보 모델에도 복제함
3. **결과 수집**: 예측값과 지연과 오류 정보를 저장함
4. **차이 분석**: 기존 모델과 후보 모델 차이를 정량적으로 비교함
5. **승격 여부 판단**: 안정성과 품질이 충분하면 다음 단계 배포로 이동함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 실제 응답에는 반영되지 않으므로 후보 모델의 비즈니스 성과를 직접 확인하기 어려울 수 있음
   - 해결방안: shadow phase after canary strategy를 적용하고 technical regression detection rate와 pre canary confidence score로 검증함
2. 문제: 미러링 경로의 피처와 설정이 본 서비스와 다르면 비교 결과가 왜곡될 수 있음
   - 해결방안: serving parity validation과 shared feature contract를 적용하고 shadow primary parity score와 configuration mismatch rate로 검증함
3. 문제: 전체 트래픽 미러링은 비용과 자원 소모가 커 대규모 환경에서 운영 부담이 높아질 수 있음
   - 해결방안: sampled mirroring과 capacity guardrail을 적용하고 shadow infrastructure cost ratio와 sampled traffic coverage로 검증함

## Ⅶ. 적용 사례

- 추천 서비스가 신규 모델을 섀도 배포로 먼저 검증하며 확인 지표는 technical regression detection rate와 pre canary confidence score임
- 실시간 사기 탐지 시스템이 피처 계약을 공유하며 확인 지표는 shadow primary parity score와 configuration mismatch rate임
- 대규모 광고 플랫폼이 샘플 미러링 정책을 운영하며 확인 지표는 shadow infrastructure cost ratio와 sampled traffic coverage임

## Ⅷ. 결론

섀도 배포는 사용자 위험 없이 운영 검증을 수행하는 유용한 단계이므로 환경 일관성과 비용 통제와 후속 배포 전략 연계가 중요함.
