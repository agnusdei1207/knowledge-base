## 미리 알고가기

- 헌법형 AI ($Constitutional$ $AI$, CAI): 미국의 인공지능 연구소 앤트로픽($Anthropic$)이 제안한 정렬 기법으로, 명문화된 행동 원칙(헌법) 집합을 AI에게 주입해 스스로 답변을 비판($Critique$)하고 개선($Revision$)하게 하는 자동화된 정렬 프레임워크임
- 자기 비판 ($Self-critique$): 모델이 최초 생성한 답변 초안에 대해, 제정된 헌법 규칙에 위배되는 편향이나 공격적 언사가 들어있는지 모델 스스로 논리적 단점을 스스로 지적하게 하는 단계임
- 답변 수정 ($Revision$): 도출된 자기 비판점을 바탕으로, 헌법 정신에 온전히 부합하도록 오리지널 답변 초안을 스스로 다듬고 재작성해 최종 모범 답안으로 도출하는 정제 단계임
- 정렬 안정화 데이터 ($Preference$ $Dataset$): 수정 전(위험 답변)과 수정 후(안전 답변) 데이터를 하나의 선호 쌍으로 묶어, DPO 등의 최적화에 투입할 수 있도록 규격화한 학습 데이터셋임

## Ⅰ. 개요

- **정의/개념**: Constitutional AI는 모델 정렬 과정에서 인간의 수동 평가 의존성을 타파하기 위해, 안전성, 정직성, 무해성 지침을 헌법(Constitution) 형태로 명문화하여 모델에 주입하고, 모델 스스로 [초안 응답 $\rightarrow$ 자기 비판 $\rightarrow$ 수정 완료]의 자가 정제 루프를 회전하여 고품질 선호 데이터셋을 자동 양산 및 정렬하는 규칙 기반 정렬 프레임워크임
- **배경/필요성**: 기존 RLHF는 수만 명의 인간 라벨러 인건비가 상상을 초월하며 개개인의 도덕적 편차가 심해 지침의 일관성이 훼손되자, 명문화된 원칙 헌법을 바탕으로 컴퓨터의 일관된 고속 자동 채점을 수립하고자 개발됨

## Ⅱ. 특징

- 인공지능의 가치관 정렬을 수학적 로직이 아닌, "인간의 인권을 보장해라" 같은 '자연어 헌법 텍스트'의 개정만으로 신속히 조율 통제함
- 1단계 지도 학습(SFT용 비판-수정 데이터셋 구축)과 2단계 강화학습(AI 선호 데이터를 활용한 보상 모델 학습) 전 과정을 인간 없이 완전 자동 가동함
- 헌법 조항 내의 두 가치(예: 사용자를 돕는 '도움성' vs 위험을 막는 '무해성')가 상충할 때 발생하는 딜레마 오동작에 대해 헌법 우선순위 설계가 요구됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 인간 피드백 강화학습 (RLHF) | AI 피드백 강화학습 (RLAIF) | 헌법형 AI (Constitutional AI) |
|:---|:---|:---|:---|
| **정렬의 기준 원천** | 크라우드 워커 인간의 개별 주관적 선호 | 고성능 가상 $LLM$ Judge의 선호 판정 | 명문화된 원칙 헌법 ($Constitution$) |
| **자기비판 루프** | 없음 (인간의 일방적 평점 기록) | 없음 (단발성 AI 채점) | 있음 (스스로 비판 후 $Revision$ 완료) |
| **평가 기준 일관성** | 낮음 (라벨러 성향에 따라 흔들림) | 보통 | 극도로 높음 (법령에 명시된 기준 고수) |
| **인건비 부담** | 매우 높음 | 없음 | 없음 (초기 헌법 조항 작성만 사람이 전담) |

> 요약: RLHF는 인간의 기분에 기대는 훈련이고, RLAIF는 기계 심판의 무조건적 채점이며, Constitutional AI는 헌법 조항을 기준으로 스스로 비판 및 참회 개정(Revision)하여 무결성을 완성하는 자정 작용 아키텍처임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 헌법 조항집 | UN 인권 선언, 안전 법규 등을 담아 AI가 대조할 기준을 명시한 자연어 룰북임 |
| 자기비판 생성기 | 초안 응답의 유해 요소를 헌법에 비추어 스스로 고발하고 문제점을 지적하는 모듈임 |
| 개정 엔진 | 자기비판의 피드백을 수용하여, 무해하고 정중하게 답을 다시 고쳐 쓰는 생성 유닛임 |
| 최종 정렬 기구 | 완성된 비판-개정 데이터를 활용해, DPO 학습으로 최종 안전망을 치는 수렴기임 |

```text
[ Constitutional AI (헌법형 AI) 자정 루프 아키텍처 ]
Prompt ──> [ SFT Model ] ──> Harmful Draft Response
                                   │
                                   v
             [ Self-Critique w/ Constitution ] ──> Point out Flaws
                                   │
                                   v
             [ Revision Engine ] ──> Clean Revised Response (yw)
                                   │
                                   v
             [ DPO Training ] ──> Target Aligned Model
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 헌법 조항   | --> | 독성 초안    | --> | 자기비판 및 | --> | 개선 데이터를|
| 수립 및 주입|     | 답변 생성    |     | 헌법적 개정 |     | DPO 훈련반영|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **헌법 조약집 빌드** — Anthropic 사의 표준 헌법 규정과 기업 고유의 비즈니스 컴플라이언스 원칙들을 취합해 프롬프트용 헌법집을 셋업함
2. **독성 초안 도출** — 유도 질문(예: 해킹 요령)을 모델에 억지로 집어넣어, 필터링되지 않은 독성 함유 초안 답변을 일부러 생성 유도함
3. **비판 및 개정** — 헌법을 참조 텍스트로 같이 던져 "위 초안의 불건전함을 지적해라" 한 뒤, 그 지적을 바탕으로 Clean 답변($y_w$)으로 고쳐 쓰게 함
4. **정렬 훈련 피드** — 오리지널 독성 초안($y_l$)과 개정된 클린 답변($y_w$)을 선호쌍으로 묶어 DPO 로스로 정책 가중치를 최종 갱신 정렬함

## Ⅵ. 실무 적용 및 유의점

1. 헌법의 추상적 문구("공정해야 한다" 등)가 모호하거나 서로 충돌하면, 자기비판 과정에서 궤변을 늘어놓으며 엉뚱한 답변을 칭찬하는 부작용이 생기므로, 반드시 구체적 사례(Few-shot Examples)와 조항 간의 우선순위를 헌법 룰북에 명시하고, 오판율($disagreement$ $rate$) 지표를 검증해야 함
2. 헌법 기준이 안전성 및 도덕성에만 과도하게 치우치면 도움성(Helpfulness)이 메마르고 질문을 무조건 회피하는 '과잉 거절' 챗봇으로 전락하므로, 반드시 '도움성 보존 조항'을 헌법 제1조로 설정하고 harmlsee-helpful 상쇄 지표를 모니터링해야 함

## Ⅶ. 결론

- Constitutional AI는 법적 규범과 인권 가치를 자연어 형태로 신경망 통제선에 완벽히 이식한 정렬 기술의 이정표이며, 설계자는 헌법 조항 간의 다목적 충돌 문제 해소를 위한 우선순위 설계와 무해성 과도화에 따른 over-refusal 상쇄 조율을 반드시 통합 적용해야 함
