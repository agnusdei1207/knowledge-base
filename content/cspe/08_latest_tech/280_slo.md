## 미리 알고가기

- SLO는 서비스가 어느 정도 수준으로 좋아야 하는지를 내부 운영 기준으로 수치화한 목표임
- SLA와 달리 법적 계약보다 운영 개선과 의사결정 기준에 더 초점을 둠
- SLI와 error budget 관계를 함께 이해해야 실제 의미가 잡힘

## Ⅰ. 개요

- **정의/개념**: SLO는 서비스의 가용성이나 지연 시간이나 정확성 같은 핵심 품질 지표에 대해 일정 기간 동안 달성해야 할 목표 수준을 수치로 정의한 운영 목표임
- **배경/필요성**: 서비스 품질을 감각적으로 판단하면 배포와 장애 대응 우선순위가 흔들리므로 사용자 경험과 비즈니스 요구를 수치화한 공통 기준이 필요해짐

## Ⅱ. 특징

- 사용자 체감 품질과 직접 연결된 지표를 선택해야 함
- 일정 기간과 목표 수준이 함께 정의되어야 운영 판단이 가능함
- error budget과 결합하면 출시 속도와 안정성을 조절할 수 있음
- 지나치게 엄격하거나 느슨한 목표는 모두 운영 왜곡을 만든다

## Ⅲ. 종류 및 비교

| 판단 기준 | SLO | SLA | SLI |
|:---|:---|:---|:---|
| 역할 | 내부 운영 목표 | 외부 계약 약속 | 측정 지표 자체 |
| 활용 목적 | 운영 의사결정 | 법적 책임과 보상 | 상태 측정 |
| 유연성 | 높음 | 낮음 | 매우 높음 |
| 대표 예 | 월 가용성 99.9% 목표 | 계약상 99.5% 보장 | 성공 요청 비율 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| SLI | 가용성이나 지연 같은 실제 측정 가능한 수치를 정의해 SLO의 입력이 되는 핵심 측정 지표임 |
| Target Objective | 일정 기간 동안 달성해야 할 목표 수치를 정의해 품질 기준선을 제공하는 목표값임 |
| Measurement Window | 일간과 주간과 월간처럼 평가 기간을 정해 단기 변동과 장기 품질을 구분하게 하는 시간 경계임 |
| Error Budget | 허용 가능한 실패량을 계산해 릴리스와 실험과 운영 위험을 조정하게 하는 통제 지표임 |
| Governance Action | 예산 소진 속도에 따라 배포 제한과 복구 우선순위를 결정하는 운영 규칙임 |

```text
| SLI   | -> | SLO Target| -> | Error Budget| -> | Governance    |
+-------+    +----------+    +-------------+    +---------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| SLI 정의     | -> | 목표 수립    | -> | 지속 측정    | -> | 예산 계산    | -> | 운영 의사결정 |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **SLI 정의**: 사용자 경험을 반영하는 측정 지표를 정함
2. **목표 수립**: 기간과 수치 목표를 설정함
3. **지속 측정**: 실제 서비스 상태를 모니터링함
4. **예산 계산**: 허용 실패량과 소진 속도를 계산함
5. **운영 의사결정**: 배포와 복구와 개선 우선순위를 조정함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 사용자 경험과 동떨어진 내부 지표를 SLO로 잡으면 목표를 달성해도 실제 서비스 만족도는 낮을 수 있음
   - 해결방안: user journey based SLI selection을 적용하고 SLO to user impact alignment score와 complaint correlation rate로 검증함
2. 문제: 지나치게 높은 목표는 운영팀을 보수적으로 만들고 낮은 목표는 품질 저하를 방치하게 할 수 있음
   - 해결방안: business aligned target calibration을 적용하고 release velocity balance score와 chronic SLO breach rate로 검증함
3. 문제: error budget을 의사결정에 연결하지 않으면 SLO는 보고서용 숫자에 그칠 수 있음
   - 해결방안: budget policy linkage와 release gating rule을 적용하고 budget based decision adoption rate와 incident prevention effectiveness로 검증함

## Ⅶ. 적용 사례

- 전자상거래 서비스가 사용자 여정 기반 SLI를 정의하며 확인 지표는 SLO to user impact alignment score와 complaint correlation rate임
- 플랫폼 팀이 목표 보정 정책을 운영하며 확인 지표는 release velocity balance score와 chronic SLO breach rate임
- SRE 조직이 error budget 연동 배포 규칙을 적용하며 확인 지표는 budget based decision adoption rate와 incident prevention effectiveness임

## Ⅷ. 결론

SLO는 기술 지표를 운영 판단 기준으로 바꾸는 핵심 장치이므로 사용자 경험과 예산 통제를 함께 반영한 목표 설계가 중요함.
