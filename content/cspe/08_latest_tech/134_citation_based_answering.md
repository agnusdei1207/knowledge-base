# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: AI가 사용자에게 답변을 줄 때, 단순히 글만 써서 주는 게 아니라 "이 말은 [1번 문서의 3페이지]에서 가져왔어"라고 각주(Citation, 인용구)와 하이퍼링크를 명시적으로 달아주는 RAG 응답 생성 기법.
- **필요성**: 아무리 RAG가 똑똑해도 사람은 AI를 100% 믿지 못함. 치명적인 법률/의료/금융 문제에서 책임을 지려면, 사용자가 직접 눈으로 원본 문서를 클릭해서 팩트체크할 수 있는 장치가 절대적으로 필요함.
- **핵심 직관**: 대학 논문 쓰기. 주장을 펼칠 때 내 뇌피셜이 아님을 증명하기 위해 뒤에 `[김철수, 2022]`라고 참고문헌 각주를 꼬박꼬박 달아, 교수가 직접 찾아볼 수 있게 만드는 것과 똑같음.

## 깊이 이해
- **배경**: LLM의 환각(Hallucination) 리스크가 기업 도입의 최대 장벽이 되자, Perplexity AI, Bing Chat(Copilot) 등이 "우리는 환각이 있어도 출처를 주니 네가 직접 확인해!"라는 신뢰성(Trust) 마케팅을 펼치며 대세가 됨.
- **작동 원리**:
  1. (검색 및 메타데이터): Vector DB에서 문서를 찾을 때 텍스트뿐만 아니라 출처 정보(문서 ID, 페이지 번호 등)를 통째로 가져옴.
  2. (프롬프트 주입): LLM에게 "답변을 쓸 때, 반드시 각 문장 끝에 [문서 ID]를 각주로 붙여라"라고 지시.
  3. (생성 및 매핑): LLM이 `~입니다 [doc_3].` 라고 답변을 내뱉음.
  4. (UI/UX 렌더링): 프론트엔드에서 `[doc_3]` 텍스트를 파싱하여, 실제 사내 문서의 PDF 3페이지로 날아가는 하이퍼링크 버튼으로 변환해 보여줌.
- **구체 예시**:
  - 질문: "우리 회사 경조사비 규정은?"
  - 답변: "본인 결혼 시 축의금 100만 원이 지급되며 **[복리후생규정_v2.pdf - 12쪽]**, 5일의 유급 휴가가 부여됩니다 **[취업규칙_2023.pdf - 4쪽]**."
- **흔한 오해/주의점**: 출처 표시가 달렸다고 무조건 사실인 건 아님! 가끔 LLM이 헛소리를 써놓고는 그럴듯하게 정상적인 각주 번호를 억지로 달아버리는 "가짜 인용(Fake Citation)" 현상이 발생함. 이를 백엔드에서 사후 검증(Post-verification)하는 로직이 필요함.

## 연결 개념
- **Perplexity AI**: Citation-based Answering의 끝판왕이자 이 UI/UX를 세상에 유행시킨 대표적인 AI 검색 엔진.
- **Groundedness (근거성)**: 각주가 달린 문장이 진짜로 그 문서에 근거하고 있는지를 채점하는 평가 지표.
- **Metadata (메타데이터)**: 청킹(Chunking) 시 텍스트 조각에 꼬리표로 붙여두는 출처 정보(URL, 파일명 등). 이게 없으면 각주를 달 수 없음.

# 📝 【답안용】 시험 답안 템플릿
## 핵심 인사이트 (3줄 요약)
- **본질**: RAG 아키텍처의 생성(Generation) 단계에서, LLM이 문장 단위(Statement-level)로 참조한 외부 문맥(Context)의 메타데이터(URL, 파일명, 페이지)를 각주(Citation) 형태로 명시적 매핑(Mapping)하여 제공하는 응답 생성 메커니즘.
- **가치**: AI의 답변 구조를 블랙박스에서 화이트박스로 전환하여 '검증 가능성(Verifiability)'과 '감사 추적성(Auditability)'을 확보함으로써, 엔터프라이즈 환경에서의 환각 리스크를 UX 관점에서 분산하고 사용자 신뢰(Trust)를 극대화함.
- **판단 포인트**: LLM이 허위로 각주를 다는 환각(Fake Citation)을 방지하기 위해, 생성된 인용구와 실제 참조 문서를 NLI(자연어 추론) 모델로 교차 검증하는 사후 검증(Post-verification) 로직 구현 역량이 시스템의 완성도를 가름.

## Ⅰ. 개요 및 필요성
- **정의**: 검색증강생성(RAG) 기반 챗봇이 답변을 제공할 때, 단순 자연어 응답에 그치지 않고 답변을 구성하는 각 문장이나 주장에 대한 원본 출처(Source Reference)를 하이퍼링크나 참조 기호 형식으로 매핑해 주는 기술.
- **배경**: 환각(Hallucination) 현상은 알고리즘 튜닝만으로 100% 박멸이 불가능하며, 사용자가 AI의 답변을 맹신하여 의사결정을 내릴 경우 기업에 치명적인 오퍼레이션 리스크(Operation Risk)를 초래함.
- **필요성**: "AI의 답변을 믿지 말고 검증하라(Trust, but Verify)"는 제로 트러스트(Zero Trust) 관점에서, 사용자가 원본 문서를 단 한 번의 클릭으로 팩트체크할 수 있는 감사 기능(Audit Trail)을 제공하기 위함.

## Ⅱ. Citation-based Answering 구현 아키텍처 (3단계)
1. **메타데이터 인덱싱 (Metadata Indexing)**
   - 문서를 청크(Chunk)로 쪼개어 Vector DB에 넣을 때, 텍스트와 함께 `Source_ID`, `Title`, `Page_Num`, `URL` 등의 메타데이터를 Key-Value 형태로 강제 바인딩(Binding)함.
2. **프롬프트 엔지니어링 (Prompting for Citation)**
   - LLM에 문맥(Context)을 넘길 때 각 문맥마다 고유 ID를 부여함.
   - `[System Prompt]`: "제공된 [doc_1], [doc_2] 문서를 바탕으로 대답하되, 주장이 끝날 때마다 반드시 `[doc_ID]` 형태로 각주를 달아라."
3. **UX 렌더링 (Post-processing & Rendering)**
   - LLM이 내뱉은 `[doc_1]`이라는 텍스트를 정규식(Regex)으로 파싱(Parsing)함.
   - 백엔드 메모리에 있던 메타데이터와 결합하여 프론트엔드에서 클릭 가능한 하이퍼링크 UI 컴포넌트로 변환.

## Ⅲ. 인용 방식(Citation Strategy) 분류
| 분류 | 생성 메커니즘 | 장점 | 단점 / 한계 |
|:---:|:---|:---|:---|
| **In-context Citation**<br>(프롬프트 기반 내장) | LLM이 글을 쓰면서 프롬프트 지시에 따라 실시간으로 각주 기호를 스스로 타건(Generation)함. | 자연스럽고 문맥에 딱 맞는 각주 생성 가능. 구현이 빠름. | LLM이 각주 번호를 틀리게 적거나, 없는 각주를 지어내는 환각 리스크 큼. |
| **Post-hoc Citation**<br>(사후 매핑) | LLM은 답변만 쓰고, 백엔드 알고리즘(유사도 매칭)이 답변 문장과 검색 문서를 비교해 사후에 각주를 강제로 끼워 넣음. | 100% 통제된(안전한) 각주만 생성됨. Fake Citation 없음. | 로직이 복잡하고, 문맥과 각주가 엇나갈(유사도는 높으나 반대 뜻) 가능성 존재. |

## Ⅳ. 핵심 리스크: 가짜 인용 (Fake / Orphan Citation)
- **현상**: LLM이 그럴싸한 소설(환각)을 써놓고, 사용자에게 신뢰를 주려 문장 끝에 있지도 않은 `[doc_3]` 번호를 마음대로 달아버리는 현상.
- **대응 파이프라인 (Verification Layer)**:
  - 응답을 사용자에게 던지기 직전, `Claim Extractor`가 각주가 달린 문장을 뽑아냄.
  - 해당 문장이 실제로 `doc_3`의 문서 내용에 포함(Entailment)되는지 작은 분류 모델(Cross-Encoder 등)로 즉각 채점.
  - 불일치할 경우, 해당 각주 기호를 화면에서 지워버리거나 경고창("이 문장은 출처가 불확실합니다")을 띄움.

## Ⅴ. 실무 적용 및 결론
- **판단 지표**: Citation Accuracy (정확한 출처를 달았는가), Citation Coverage (전체 문장 중 각주가 달린 문장의 비율).
- **실무 설계**: 기업형 법무/계약 검토 AI 시스템 구축 시. 변호사들은 출처 없는 AI의 법률 요약을 절대 신뢰하지 않음. LlamaIndex의 `CitationQueryEngine`을 활용하여 인프라 구축. 계약서 PDF를 문단별로 쪼개고 `페이지 번호`를 메타데이터로 삽입. AI가 위험 조항을 요약할 때마다 `[page: 12]` 형태로 각주를 생성하게 하고, 사용자가 클릭 시 PDF Viewer가 12페이지의 해당 문단에 하이라이트를 치며 팝업되도록 UI 통합 개발. 그 결과 법무팀의 AI 시스템 채택률(Adoption Rate)이 300% 상승.
- **결론**: 출처 기반 답변(Citation)은 RAG 시스템의 화룡점정이자 블랙박스인 딥러닝과 팩트 중심의 인간 비즈니스를 이어주는 '신뢰의 다리'이며, 차세대 AI 검색엔진(Perplexity, SearchGPT)의 표준 인터페이스 포맷이다.

### 🔀 문제 유형별 목차 전환
- **Ⅱ·Ⅲ 강조 (개념/원리형)**: LLM의 인-컨텍스트 학습(In-context Learning)을 이용한 Citation Prompting 구조, 문장 단위(Sentence-level) 분할 및 사후 매핑(Post-hoc)을 위한 코사인 유사도 알고리즘 서술.
- **Ⅴ·Ⅵ 강조 (실무/설계형)**: LlamaIndex/LangChain을 활용한 Citation 메타데이터 구조화 구현 방안, 프론트엔드와의 PDF Viewer 연동(하이라이팅) 아키텍처 및 시스템 신뢰도(Trustworthy AI) 제고 전략 중심.
