# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: 글자 수나 토큰 수로 기계적으로 문서를 자르지 않고, 문장들 사이의 '의미적 변화(주제 전환점)'를 수학적으로 계산하여, 하나의 문맥(Context)이 끝나는 자연스러운 경계에서 문서를 자르는 고급 청킹 기법.
- **필요성**: 고정 크기(Fixed-size) 청킹은 운이 나쁘면 "이순신 장군이 거북선을 이끌고 출전하여" / (청크 분할) / "적군을 크게 무찔렀다." 처럼 핵심 의미를 두 동강 내버림. 이렇게 되면 쪼개진 파편 벡터는 RAG 검색 시 완전히 쓰레기가 됨.
- **핵심 직관**: 발표자의 스크립트를 자를 때, 시계 1분마다 무조건 자르는 것(Fixed)이 아니라, 발표자가 "자, 다음 주제로 넘어가겠습니다"라며 슬라이드를 넘기는 타이밍(의미 경계)에 정확히 가위질을 하는 것.

## 깊이 이해
- **배경**: 2023년 말 랭체인(LangChain)의 핵심 기여자인 Greg Kamradt 등이 제안하며 대유행함. LLM 성능은 올라갔으나 RAG의 검색 품질이 "앞뒤 짤린 문서"들 때문에 엉망이라는 사실을 인지하고, 통계와 수학을 동원해 문서를 영리하게 자르는 로직을 개발함.
- **작동 원리 (문장 벡터의 변화율 감지)**:
  1. (문장 분리): 문서를 온점(`.`) 단위로 전부 자름. (예: 100개의 문장)
  2. (문장 임베딩): 100개 문장을 각각 다 임베딩 모델에 넣어서 벡터로 만듦.
  3. (거리 연산): 1번 문장과 2번 문장 사이의 코사인 거리, 2번과 3번의 거리... 를 전부 계산함.
  4. (경계점 포착): 문장들이 계속 비슷한 내용이면 거리가 가깝지만, 갑자기 다른 주제로 넘어가면 벡터 거리가 팍! 튐. 이 거리의 '이상치(Outlier, Threshold 초과)' 지점을 문단의 경계로 간주하고 가위질함.
- **구체 예시**:
  - 문장 1: "우리 회사는 올해 창립 10주년이다."
  - 문장 2: "이를 기념해 전 직원에게 보너스를 지급한다." $\rightarrow$ (유사도 90%, 안 자름)
  - 문장 3: "한편, 내년도 보안 규정은 다음과 같이 바뀐다." $\rightarrow$ (갑자기 유사도 30%로 뚝 떨어짐. 여기서 청크를 자름!)
- **흔한 오해/주의점**: 이론은 완벽하나 실무에 적용하면 돈과 시간이 어마어마하게 깨짐. 문장 하나하나를 전부 임베딩 API에 태워야 하므로, 10만 장짜리 문서를 자르려면 인덱싱(전처리) 비용과 시간이 기존 방식보다 10배 이상 듦. "가성비"를 반드시 따져야 함.

## 연결 개념
- **Cosine Distance (코사인 거리)**: 의미 기반 청킹이 "여기서 주제가 바뀌었네"를 판단하는 수학적 기준 지표.
- **Fixed-size Chunking (고정 길이 청킹)**: 의미 기반 청킹의 라이벌이자 구형 방식. 무식하지만 매우 빠르고 비용이 0원에 가까움.
- **LlamaIndex**: 시맨틱 청킹과 같은 최신 데이터 파이프라인 노드를 가장 강력하게 제공하는 오픈소스 오케스트레이터.

# 📝 【답안용】 시험 답안 템플릿
## 핵심 인사이트 (3줄 요약)
- **본질**: 문장(Sentence) 단위의 임베딩 벡터를 순차적으로 추출하고, 인접한 문장 벡터 간의 코사인 거리(Cosine Distance) 극대점(Local Maxima)을 탐지하여 주제가 전환되는 토폴로지(Topology) 경계에서 문서를 가변적으로 분할하는 지능형 전처리 기법.
- **가치**: 문서의 의미론적 완결성(Semantic Integrity)을 100% 보존한 청크를 생성함으로써, Context 단절로 인한 오검색 및 LLM의 환각(Hallucination)을 원천 차단하고 응답의 논리적 일관성을 극대화함.
- **판단 포인트**: 문장 단위 반복 인코딩으로 인한 극단적인 전처리(ETL) 컴퓨팅 비용 상승 문제, 단문 위주의 코퍼스에서는 오버엔지니어링(Over-engineering)이 될 수 있다는 점을 인지하고 문서 특성에 따른 ROI 분석 필요.

## Ⅰ. 개요 및 필요성
- **정의**: 기계적인 토큰 길이나 정규 표현식에 의존하지 않고, 인접한 문장 간의 의미적 유사도 변동폭(Gradient)을 계산하여 텍스트의 주제(Topic)가 전환되는 논리적 경계선을 기준으로 문서를 분할하는 동적 청킹(Dynamic Chunking) 알고리즘.
- **배경**: 기존 Fixed-size Chunking은 문맥의 핵심 문장을 중간에서 임의로 절단(Truncation)하여 벡터 공간 내에서 의미 왜곡을 발생시키고, 이는 곧바로 RAG 시스템의 검색 재현율(Recall) 저하로 직결됨.
- **필요성**: LLM 컨텍스트 윈도우에 "노이즈 없는 완벽하게 독립적인 하나의 스토리/주제"만을 밀도 있게 전달하여, 추론의 팩트 지지율(Faithfulness)을 높이기 위함.

## Ⅱ. Semantic Chunking 알고리즘 워크플로
```text
[ 1. Segmentation ] : 원본 텍스트를 문장 부호(., ?, !) 기준으로 쪼갬 (문장 집합 S1, S2 ... Sn)
        |
[ 2. Embedding ]    : 각 문장 단위로 임베딩 모델(Encoder) 호출 -> 문장 벡터 생성
        |
[ 3. Distance Calc ]: 인접 문장 간 코사인 거리(Cosine Distance) 계산 (S1-S2, S2-S3 ...)
        |
[ 4. Thresholding ] : 미리 설정한 임계값(Threshold, 예: 0.3)을 초과하거나, 
                      상위 X%의 거리 편차(Percentile)를 보이는 지점을 '주제 전환점'으로 마킹
        |
[ 5. Splitting ]    : 마킹된 경계점들을 기준으로 문장들을 병합하여 가변 길이의 최종 Chunk 생성
```

## Ⅲ. 주요 경계 탐지(Boundary Detection) 임계값 전략
| 전략 | 동작 방식 | 장점 | 단점 |
|:---:|:---|:---|:---|
| **Percentile (백분위수)** | 전체 문장 간 거리 중 상위 N%(예: 95%)에 해당하는 극단적 변화 지점을 경계로 설정 | 문서 길이나 임베딩 모델의 특성에 구애받지 않고 유연하게 동작. (가장 널리 쓰임) | 문서 내 주제 전환이 매우 잦으면 청크가 너무 커질 위험. |
| **Standard Deviation** | 거리 평균값에서 표준편차(N-sigma) 이상 벗어나는 지점을 경계로 설정 | 통계적으로 가장 명확한 이상치(Outlier) 경계만 분할. | 정규 분포를 따르지 않는 문서에서는 오작동. |
| **Interquartile (사분위)** | 사분위 범위(IQR)를 이용하여 극단값을 찾아 분할 | 노이즈 문장(갑작스런 오타 등)에 강건함(Robust). | 구현이 다소 복잡. |

## Ⅳ. 고정 길이 청킹(Fixed-size)과의 심화 비교
| 구분 | Fixed-size Chunking | Semantic Chunking |
|:---:|:---|:---|
| **분할 기준** | 토큰 수 / 문자 수 (예: 512) | **임베딩 유사도 (주제 전환점)** |
| **청크의 길이** | 100% 균일함 (정적) | **매우 들쭉날쭉함 (가변적)** |
| **의미 보존력** | 낮음 (무작위 절단 위험) | **매우 높음 (단일 주제 완결성)** |
| **ETL 전처리 비용**| 거의 0원 (연산 없음) | **매우 비쌈 (전체 문장 임베딩 호출 비용)** |
| **도입 적합군** | 단순 Q&A, 짧은 로그성 데이터 | **논문, 심층 분석 보고서, 법률/계약서** |

## Ⅴ. 한계점 및 아키텍처 도입 시 튜닝 전략
- **리스크 1: 폭발적인 인덱싱 비용 및 지연 (Indexing Overhead)**:
  - 수백만 건의 문서를 Semantic Chunking 처리하려면 수천만 번의 임베딩 API 호출이 발생하여 비용과 시간이 기하급수적으로 늘어남.
  - **튜닝 전략**: 문장 단위 1차 처리는 가볍고 매우 빠른 소형 로컬 임베딩 모델(예: all-MiniLM-L6-v2)을 사용하여 경계를 탐지(비용 절감)하고, 최종 생성된 청크를 벡터 DB에 넣을 때만 무거운 고성능 모델(OpenAI ada 등)을 사용하는 **Dual-Model 아키텍처** 적용.
- **리스크 2: 청크 크기의 극단적 편차 (Chunk Size Imbalance)**:
  - 주제가 안 바뀌고 끝까지 이어지는 소설 같은 문서면 10,000토큰짜리 거대 청크가 발생해버림.
  - **튜닝 전략**: 의미 청킹 알고리즘 위에 '하드 리밋(Hard Limit: 최소 길이 100, 최대 길이 1000)' 제약 조건을 방어 코드로 덮어씌워, LLM 컨텍스트 윈도우 한도를 초과하지 않도록 2차 보정 수행.

## Ⅵ. 실무 적용 및 결론
- **판단 지표**: Ragas 지표 중 Context Relevance(검색된 청크 내에 불필요한 문장이 적은가), 데이터 전이(ETL) 소요 시간.
- **실무 설계**: 금융기관 리서치 리포트(수십 페이지 분량) 지식베이스 구축 시. 리포트 내에는 거시경제, 섹터 분석, 개별 종목 추천 등 다양한 주제가 섞여 있음. 고정 토큰 분할 시 거시경제와 종목 내용이 한 청크에 섞이는 노이즈 발생. Semantic Chunking(Percentile 90% 임계값 설정)을 도입하여, 거시경제 문단과 종목 분석 문단이 완벽히 분리되도록 파이프라인 구성. 비록 전처리 파이프라인 배치 수행 시간이 기존 10분에서 3시간으로 늘어났으나, 질의 시 할루시네이션은 0%로 근절됨.
- **결론**: 의미 기반 청킹은 RAG 품질의 상한선을 끌어올리는 '프리미엄 세단'과 같아 승차감(검색 품질)은 최고이나 연비(컴퓨팅 비용)가 나쁘므로, 핵심 정밀 문서 그룹에 선별적으로 파이프라이닝하는 데이터 티어링(Tiering) 전략과 병행되어야 함.

### 🔀 문제 유형별 목차 전환
- **Ⅱ·Ⅲ 강조 (개념/원리형)**: 문장(Sentence) 스플리팅 시 적용되는 NLTK/Spacy 파서의 토큰화 원리, Cosine Distance 계산 배열의 버퍼 윈도우(Buffer Window) 이동 평활화(Smoothing) 알고리즘 상세 설명.
- **Ⅴ·Ⅵ 강조 (실무/설계형)**: 전처리(ETL) 파이프라인에서의 임베딩 캐싱(Caching)을 통한 비용 통제(FinOps) 기법, LLM 기반 파싱(LlamaParse)과의 결합 아키텍처 설계 중심 작성.
