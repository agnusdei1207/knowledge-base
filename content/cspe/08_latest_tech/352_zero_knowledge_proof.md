## 미리 알고가기

- 영지식 증명은 비밀값 자체를 공개하지 않고 어떤 명제가 참임을 증명하는 방식임
- 완전성과 건전성과 영지식성이 성립해야 증명 시스템으로 의미가 있음
- 실제 선택에서는 증명 생성 시간과 검증 비용과 trusted setup 필요 여부를 함께 봐야 함

## Ⅰ. 개요

- **정의/개념**: Zero-Knowledge Proof는 증명자가 비밀값이나 내부 데이터 자체를 드러내지 않고도 특정 명제가 참이라는 사실만 검증자에게 확인시키는 암호학적 증명 체계임
- **배경/필요성**: 공개 블록체인과 공동 분석 환경에서는 신원과 자산과 계산 결과를 검증해야 하지만 원본 데이터 노출은 부담이 커서 최소 정보 공개로 검증 가능한 방식이 필요함

## Ⅱ. 특징

- 비밀 데이터 대신 참이라는 사실만 증명하므로 프라이버시와 검증 가능성을 동시에 확보할 수 있음
- 증명 회로와 공개 입력이 명확해야 같은 규칙으로 반복 검증할 수 있음
- zk-SNARK과 zk-STARK처럼 구현 계열에 따라 증명 크기와 생성 시간과 검증 비용이 달라짐
- 명제 설계가 잘못되면 비밀은 숨겨도 필요한 보안 속성을 증명하지 못하므로 회로 설계 검토가 중요함

## Ⅲ. 종류 및 비교

| 판단 기준 | Interactive ZKP | zk-SNARK | zk-STARK |
|:---|:---|:---|:---|
| 상호작용 | 필요 | 불필요 | 불필요 |
| trusted setup | 보통 불필요 | 필요한 경우가 많음 | 불필요 |
| proof 크기 | 상대적으로 큼 | 작음 | 큰 편임 |
| 대표 장점 | 개념이 단순함 | 검증 비용이 작고 온체인 적용이 용이함 | 투명성과 확장성이 좋음 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Statement | 검증자가 확인하려는 명제로 성인 여부나 잔액 충족처럼 공개 가능한 검증 목표를 정의함 |
| Witness | 증명자가 알고 있지만 공개하지 않을 비밀값으로 실제 프라이버시 보호 대상임 |
| Arithmetic Circuit or Relation | 비밀값이 명제를 만족하는지 계산 규칙으로 바꾸는 계층으로 회로 크기가 성능을 좌우함 |
| Prover and Proof | 증명자가 비밀값과 규칙을 바탕으로 생성한 암호학적 증거로 재현성과 위조 저항성이 중요함 |
| Verifier and Public Parameters | 검증자가 공개 입력과 파라미터를 이용해 증명을 검사하는 계층으로 온체인 비용과 운영 복잡도에 영향을 줌 |

```text
+-----------+    +-------------------+    +-------------+    +----------+
| Statement | -> | Circuit / Relation| -> | Proof       | -> | Verifier |
+-----------+    +-------------------+    +-------------+    +----------+
      ^                  ^
      |                  |
+-----------+      +------------+
| Witness   |      | Parameters |
+-----------+      +------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 명제 정의     | -> | witness 준비  | -> | 증명 생성      | -> | 증명 검증      | -> | 수용 여부 판단 |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **명제 정의**: 무엇을 숨기고 무엇을 검증할지 공개 명제를 정함
2. **witness 준비**: 증명자가 비밀값과 공개 입력을 준비함
3. **증명 생성**: 정해진 회로와 파라미터로 proof를 생성함
4. **증명 검증**: 검증자가 proof와 공개 입력을 검사함
5. **수용 여부 판단**: 명제가 참이면 수용하고 아니면 거부함

## Ⅵ. 실무 적용 및 유의점

1. 롤업이나 블록체인 계산 검증은 ZKP로 대량 연산 결과를 짧게 증명할 수 있지만 회로가 커지면 proving 지연과 운영 비용이 급증하므로 회로 최적화와 증명 인프라를 함께 설계하고 proof 생성 시간과 온체인 검증 비용으로 확인함
2. 성인 인증이나 자격 속성 검증은 원본 신분정보 대신 ZKP 기반 속성 증명이 적합하지만 명제가 넓게 설계되면 불필요한 추적 가능성이 남을 수 있으므로 최소 명제와 일회성 제시 정책을 적용하고 불필요 속성 공개율과 검증 성공률로 확인함

## Ⅶ. 결론

- ZKP는 비밀을 숨긴 채 사실만 증명하는 기술이므로 프라이버시 요구가 높은 검증 업무일수록 증명 계열 선택과 회로 설계와 운영 비용 검토가 함께 따라가야 함
