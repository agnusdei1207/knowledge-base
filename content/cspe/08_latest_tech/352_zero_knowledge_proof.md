## 미리 알고가기

- 영지식 증명은 비밀값을 보여주지 않고도 어떤 조건이 참임을 증명하는 방식임
- 완전성은 참일 때 통과해야 한다는 뜻이고, 건전성은 거짓일 때 속기 어려워야 한다는 뜻임
- 초기 신뢰 설정은 공개 파라미터를 만드는 준비 단계로, 필요한 계열과 불필요한 계열이 나뉨

## Ⅰ. 개요

- **정의/개념**: ZKP는 비밀 데이터 자체를 공개하지 않고도 특정 명제가 참이라는 사실만 검증자에게 확인시키는 암호학적 증명 방식임
- **배경/필요성**: 공개 네트워크나 공동 분석 환경에서는 신원, 자산, 계산 결과를 검증해야 하지만 원본 데이터 노출 부담이 커서 최소 정보만 공개하는 검증 방식이 필요함

## Ⅱ. 특징

- 비밀값 대신 참이라는 사실만 드러내므로 프라이버시와 검증 가능성을 함께 확보할 수 있음
- 어떤 조건을 증명할지 계산 규칙으로 먼저 정리해야 반복 검증이 가능함
- 구현 계열에 따라 증명 크기와 생성 시간과 검증 비용이 크게 달라짐
- 명제를 잘못 설계하면 비밀은 숨겨도 필요한 보안 속성을 증명하지 못할 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 상호작용형 ZKP | zk-SNARK | zk-STARK |
|:---|:---|:---|:---|
| 증명 방식 | 증명자와 검증자가 여러 번 주고받음 | 한 번 만든 증명 데이터를 검증함 | 한 번 만든 증명 데이터를 검증함 |
| 초기 신뢰 설정 | 보통 필요 없음 | 필요한 경우가 많음 | 필요 없음 |
| 증명 크기 | 비교적 큰 편임 | 작음 | 큰 편임 |
| 주로 보는 장점 | 구조가 단순함 | 검증 비용이 작아 온체인 검증에 유리함 | 투명성과 확장성이 좋음 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 공개 명제 | 검증자가 확인하려는 조건으로 성인 여부나 잔액 충족처럼 공개 가능한 목표를 정의함 |
| 비밀 입력 | 증명자만 알고 있는 값으로 실제로 숨겨야 하는 정보임 |
| 계산 규칙 | 비밀 입력이 공개 명제를 만족하는지 계산 형태로 바꾸는 계층으로 회로 크기가 성능을 좌우함 |
| 증명자와 증명 데이터 | 증명자가 비밀 입력과 계산 규칙을 바탕으로 만든 암호학적 증거임 |
| 검증자와 공개 파라미터 | 검증자가 공개 입력과 파라미터를 이용해 증명을 검사하는 계층으로 운영 비용과 적용 범위를 좌우함 |

```text
+-----------+    +----------------+    +----------------+    +----------+
| 공개 명제   | -> | 계산 규칙         | -> | 증명 데이터      | -> | 검증자   |
+-----------+    +----------------+    +----------------+    +----------+
      ^                  ^
      |                  |
+-----------+      +----------------+
| 비밀 입력   |      | 공개 파라미터    |
+-----------+      +----------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 명제 정의      | -> | 비밀 입력 준비 | -> | 증명 생성      | -> | 증명 검증      | -> | 수용 여부 판단 |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **명제 정의**: 무엇을 숨기고 무엇을 검증할지 먼저 정함
2. **비밀 입력 준비**: 증명자가 비밀값과 공개 입력을 준비함
3. **증명 생성**: 정해진 계산 규칙과 파라미터로 증명 데이터를 만듦
4. **증명 검증**: 검증자가 증명 데이터와 공개 입력을 검사함
5. **수용 여부 판단**: 명제가 참이면 수용하고 아니면 거부함

## Ⅵ. 실무 적용 및 유의점

1. 롤업이나 블록체인 계산 검증은 ZKP로 많은 연산 결과를 짧게 증명하기 좋지만 회로가 커지면 생성 지연과 운영 비용이 급격히 늘어나므로 회로 단순화와 증명 인프라를 함께 설계하고 증명 생성 시간과 검증 비용으로 확인함
2. 성인 인증이나 자격 속성 검증은 원본 신분정보 대신 ZKP가 적합하지만 명제를 넓게 잡으면 불필요한 추적 가능성이 남으므로 꼭 필요한 조건만 증명하도록 설계하고 검증 성공률과 추가 정보 노출 건수로 확인함

## Ⅶ. 결론

- ZKP는 비밀을 숨긴 채 사실만 증명하는 기술이므로 프라이버시 요구가 큰 검증 업무일수록 증명 계열 선택과 명제 설계와 운영 비용 검토가 함께 따라가야 함
