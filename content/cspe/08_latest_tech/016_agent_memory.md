# 📖 【암기용】 개념 완전 이해

> 목적: 에이전트 메모리를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: 에이전트가 업무 맥락과 과거 결과를 저장·활용하는 기능
- **왜 필요한가**: 다단계 업무는 이전 결정, 사용자 선호, 실패 이력, 도구 결과를 다음 행동에 반영해야 함.
- **핵심 직관**: 메모리는 에이전트가 매번 처음 만난 것처럼 행동하지 않게 하는 업무 기록장임.

## 깊이 이해
- **배경·문제의식**: LLM 컨텍스트만으로 장기 업무 이력과 조직 지식을 보존하면 토큰 비용과 누락 위험이 커짐.
- **작동 원리**: 대화, 작업상태, 사용자 선호, 도구 결과를 단기·장기 저장소에 분리하고 필요할 때 검색해 컨텍스트에 주입함.
- **비유**: 상담사가 고객 이력, 이전 조치, 금지 요청을 CRM에서 확인한 뒤 상담하는 방식.
- **구체 예시**: 장애 조치 Agent가 과거 동일 오류의 원인과 성공한 Runbook을 검색해 재발 대응 시간을 줄임.
- **흔한 오해·주의점**: 메모리는 편의 기능이 아니라 개인정보·영업비밀 저장소가 될 수 있어 TTL과 삭제권이 필요함.

## 연결 개념
- Long-Term Memory — 지속 저장 기억
- Vector DB — 유사 이력 검색 저장소
- Privacy-Preserving AI — 메모리 내 민감정보 보호

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Agent Memory는 에이전트가 업무 맥락·이력·선호·도구 결과를 저장하고 재활용하는 상태 저장 계층임.
> 2. **가치**: 반복 업무에서 이전 근거와 결과를 활용해 재질문, 중복 호출, 판단 누락을 줄임.
> 3. **판단 포인트**: 단기·장기 분리, 검색 정확도, 개인정보 TTL, 삭제·감사 정책을 함께 설계해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 에이전트 맥락 유지 메커니즘 이해 | 단기·장기 분리, 벡터DB 검색, TTL·삭제권 | 메모리를 단순 캐시로 오해, 개인정보 통제 누락 |
| 메모리 기반 업무 재활용 설계 능력 | recall 정확도, 출처·신뢰도, 감사로그 | 저장만 강조하고 검색·폐기 정책 미설계 |

> 요약: 저장 구조뿐 아니라 검색 정확도와 개인정보 보존·삭제 정책을 함께 짚어야 감점을 피함.

---

## Ⅰ. 개요 및 필요성

- 정의: 에이전트가 맥락·이력·선호를 저장·검색하는 상태 계층
- 배경: LLM 컨텍스트 윈도우만으로는 장기 이력 보존이 어렵고 토큰 비용이 증가함
- 필요성: 반복 업무에서 재질문·중복 호출을 줄이되 개인정보 TTL·삭제권 설계가 필수

---

## Ⅱ. 구조 및 구성요소

```text
Interaction -> Short Memory -> Memory Manager -> Long Memory
                  |                 |                |
                  +-> 세션상태     +-> 요약/필터    +-> 벡터/DB
                                    |
                                    +-> Privacy Filter -> 암호화/삭제
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Short Memory | 세션 내 맥락 유지 | 토큰 한도 관리 |
| Long Memory | 장기 이력 저장 | 벡터DB·RDB 분리 |
| Memory Manager | 저장·검색·요약 제어 | 중요도·TTL 판단 |
| Privacy Filter | 민감정보 통제 | 암호화·삭제권 필요 |

> 요약: Agent Memory는 단기 맥락, 장기 저장소, 관리기, 개인정보 필터로 구성됨.

---

## Ⅲ. 동작원리 및 흐름도

```text
상호작용 수집 -> 중요도 평가 -> 저장소 선택 -> 검색/요약
        -> 컨텍스트 주입 -> 사용 이력 기록 -> TTL 삭제
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 저장 후보 수집 | 대화, 도구결과, 사용자ID |
| 2 | 중요도·민감도 평가 | PII, 비밀, 업무등급 |
| 3 | 검색·요약 반영 | recall, 출처, 최신시각 |
| 4 | 보존·삭제 관리 | TTL, 암호화, 감사로그 |

> 요약: 메모리는 저장 전 민감도 평가와 사용 후 보존기간 관리가 함께 동작해야 함.

---

## Ⅳ. 특징

| 구분 | 컨텍스트만 사용 | Agent Memory | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 보존 범위 | 세션·토큰 한도 | 장기 이력 저장 | TTL, 저장 건수 |
| 재사용 | 수동 재입력 | 검색·요약 자동 반영 | recall, 중복질의율 |
| 위험 | 일시 노출 | 장기 민감정보 보관 | 암호화, 삭제요청 처리 |

> 요약: Agent Memory는 업무 지속성을 제공하지만 개인정보 저장소로 관리해야 함.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | Agent Memory | 선택 기준 |
|:---|:---|:---|:---|
| 맥락 보존 | 컨텍스트 윈도우(128K 토큰 한도) | 벡터DB+RDB 장기 저장 | 세션 초과 이력 필요 시 Agent Memory |
| 검색 정확도 | 전문 검색(BM25, recall 60~70%) | 임베딩 유사도(recall 85%+) | 의미 검색 필요 시 벡터 기반 |
| 개인정보 통제 | 대화 로그 수동 삭제 | TTL 30~90일, KMS 암호화, 삭제 API | GDPR·PIPA 대상 시 정책 자동화 |

> 요약: 세션 초과 이력이 필요하면 Agent Memory를 적용하되 개인정보 보존·삭제 정책을 함께 설계함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 민감정보 장기 잔류 | TTL 미설정, 삭제 API 미구현 | TTL 30~90일 + 삭제 요청 SLA 24시간 | 만료 미삭제 건수, 삭제 처리시간 |
| 오래된 기억 재사용 오류 | 검증 없이 과거 이력 주입 | 90일 이상 미사용 기억 재검증·폐기 | 오래된 기억 참조 오류율 |
| 메모리 오염(인젝션) | 악의적 입력이 메모리에 저장 | 저장 전 입력 검증, 출처·신뢰도 태깅 | 비정상 저장 탐지율, 오염 건수 |

> 요약: TTL·삭제 SLA·입력 검증을 적용해 민감정보 잔류와 메모리 오염을 통제함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 검색 recall | recall 85% 이상, p95 지연 200ms 이내 | 벤치마크 질의셋, APM 모니터링 |
| 개인정보 삭제 | 삭제 요청 후 24시간 이내 처리 | 삭제 API 로그, 감사 리포트 |
| 저장 비용 | 월간 저장 비용 증가율 15% 이내 | 클라우드 빌링, 저장 건수 추이 |

> 요약: recall·삭제 SLA·저장 비용을 정기 점검해 메모리 품질과 비용을 관리함.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 세션 메모리, 사용자 선호, 업무 이력, 감사 로그를 분리 저장하고 목적 외 사용을 차단
2. 개인정보는 KMS 암호화, TTL 30~90일, 삭제 요청 처리 SLA 24시간을 정책화
3. 메모리 검색 결과는 출처, 생성시각, 신뢰도 점수를 함께 넣고 90일 이상 미사용 이력은 재검증

**결론 (2줄):**
- 기술사 판단: 장기 반복 업무는 Agent Memory를 적용하고 일회성 고위험 업무는 저장을 최소화함.
- 향후 방향: Agent Memory는 RAG, LLMOps, 개인정보 거버넌스와 결합한 AI 상태관리 계층으로 발전함.
