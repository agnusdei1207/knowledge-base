# 📖 【암기용】 개념 완전 이해

> 목적: LLM03 Supply Chain을 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **정의**: LLM 애플리케이션이 의존하는 모델, 데이터셋, 라이브러리, 플러그인, API, 배포 파이프라인의 공급망 취약점
- **왜 필요한가**: 생성형 AI는 외부 사전학습 모델, 오픈소스 패키지, 벡터DB, 플러그인, 데이터셋 의존도가 높음.
- **핵심 직관**: AI 앱은 코드만이 아니라 모델과 데이터도 납품받으므로 납품 경로 전체를 검증해야 함.

## 깊이 이해
- **배경·문제의식**: 모델 가중치와 데이터셋은 코드처럼 버전·출처·무결성 검증이 필요하지만 기존 DevSecOps 통제에서 빠지기 쉬움.
- **작동 원리**: 공격자는 악성 모델, 오염 데이터셋, 취약 라이브러리, 악성 플러그인, 위조된 모델 저장소를 통해 AI 앱을 침해함.
- **비유**: 공장 제품 품질을 보려면 최종 조립만이 아니라 부품 공급업체와 운송 과정까지 확인해야 하는 것과 같음.
- **구체 예시**: 공개 모델 저장소의 가중치 파일에 악성 pickle 코드가 포함되어 로딩 시 원격 코드 실행이 발생함.
- **흔한 오해·주의점**: 모델 파일은 단순 데이터가 아니다. 직렬화 포맷, tokenizer, preprocessing 코드까지 실행 경로가 될 수 있음.

## 연결 개념
- AI SBOM — 모델·데이터·라이브러리 구성명세
- Data Poisoning — 데이터 공급망 오염
- Model Signing — 모델 무결성 검증

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: LLM03은 모델·데이터·라이브러리·플러그인 공급망을 통한 AI 앱 침해 위험임.
> 2. **가치**: 오염 데이터, 악성 모델, 취약 패키지가 배포되면 AI 시스템 전체 무결성이 훼손됨.
> 3. **판단 포인트**: AI SBOM, 서명 검증, 출처 추적, 취약점 스캔을 MLOps에 통합해야 함.

## Ⅰ. 개요 및 필요성

LLM03은 LLM 공급망 위험이다. 생성형 AI는 외부 모델과 데이터, 플러그인, 라이브러리에 의존한다. AI 산출물의 출처·무결성·취약점 검증이 필요하다.

## Ⅱ. 구조 및 구성요소

```text
Model/Data/Plugin Source → CI/CD & MLOps
  → Integrity Scan → Deployment → Runtime Monitor
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Model Source | 사전학습·파인튜닝 모델 | hash, signature |
| Data Source | 학습·RAG 데이터셋 | provenance, license |
| Dependency | 라이브러리·플러그인·API | CVE, malware |
| AI SBOM | 구성요소 명세 | 버전·출처 기록 |

> 요약: LLM03 대응은 모델·데이터·의존성의 출처와 무결성을 AI SBOM으로 관리함.

## Ⅲ. 동작원리 및 흐름도

```text
공급원 등록 → 서명·해시 검증 → 취약점 스캔
  → 격리 테스트 → 승인 배포
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 모델·데이터·패키지 공급원 등록 | trusted registry |
| 2 | hash·signature·license 확인 | 검증률 100% |
| 3 | malware·CVE·pickle 실행 위험 스캔 | Critical 0건 |
| 4 | 격리 환경 평가 후 배포 승인 | AI SBOM 생성 |

> 요약: LLM03 방어는 신뢰 저장소, 무결성 검증, 취약점 스캔, 격리 테스트로 공급망 위험을 줄임.

## Ⅳ. 특징

| 구분 | SW 공급망 | LLM03 Supply Chain | 판단 포인트 |
|:---|:---|:---|:---|
| 대상 | 코드·패키지 | 모델·데이터·토크나이저·플러그인 | AI 자산 포함 |
| 위험 | CVE·악성코드 | 오염 데이터·악성 가중치·백도어 | 모델 검증 |
| 명세 | SBOM | AI SBOM/ML-BOM | 출처·라이선스 |
| 통제 | SCA·서명 | 모델 스캔·데이터 계보 병행 | MLOps 통합 |

> 요약: LLM03은 기존 SW 공급망 통제에 모델·데이터·플러그인 검증을 확장해야 함.

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 모델 도입: 외부 모델은 trusted registry에서만 사용하고 hash, signature, license, evaluation card를 확인
2. 데이터 관리: 학습·RAG 데이터셋은 provenance, 수집일, owner, PII 등급, 라이선스를 metadata로 기록
3. 파이프라인 통제: MLOps에 SCA, malware scan, pickle 차단, model signing, AI SBOM 생성을 배포 게이트로 적용

**결론 (2줄):**
- 기술사 판단: LLM03 대응은 코드 보안만으로 부족하므로 모델·데이터 공급망을 배포 승인 범위에 포함
- 향후 방향: LLM 공급망 보안은 AI SBOM, 모델 서명, 데이터 계보 표준과 결합해 감사 가능 체계로 발전함
