# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: OWASP LLM Top 10의 3위 취약점. AI 애플리케이션을 만들 때 외부에서 가져다 쓰는 **파운데이션 모델(사전 학습된 모델), 훈련 데이터셋, 오픈소스 라이브러리, 플러그인 등 "외부 공급망" 전체에 내재된 취약점이나 악성코드, 백도어로 인해 시스템 전체가 침해당하는 위협**.
- **필요성**: 세상 어떤 기업도 수백억을 들여 챗GPT 같은 거대 모델을 백지부터 혼자 만들지 않음. 허깅페이스(Hugging Face) 같은 곳에서 오픈소스 모델을 다운받아 쓰는데, 해커가 그 모델 파일이나 파이썬 패키지에 악성코드를 숨겨 놓으면 서버가 통째로 털림. 남이 만든 AI 부품을 쓸 때의 위험을 검증해야 함.
- **핵심 직관**: 독 사과 유통망. 최고급 레스토랑(AI 서비스)에서 훌륭한 요리를 만들기 위해 외부 농장(오픈소스 생태계)에서 사과(사전 학습 모델)를 사 옴. 그런데 농장에 침투한 악당(해커)이 사과에 독(백도어, 악성코드)을 주사해 뒀음. 레스토랑 주인이 겉보기엔 멀쩡한 이 사과를 씻지도 않고 손님에게 내주면 식당 문을 닫게 됨.

## 깊이 이해
- **배경**: AI 개발 생태계는 Hugging Face, GitHub, PyPI 등에 절대적으로 의존하고 있음. 모델을 저장하는 파일 형식인 피클(`pickle` 혹은 `pt`) 파일 구조상, 가중치(숫자)뿐만 아니라 '실행 가능한 코드'가 포함될 수 있다는 맹점이 있음. 이를 노린 공급망 공격이 현실화됨.
- **작동 원리 (어떻게 털리는가)**:
  1. **오염된 모델 가중치 (Poisoned Models)**: 해커가 정상 모델을 복사한 뒤, 로딩할 때 랜섬웨어를 실행하는 악성 코드를 심거나 윤리 필터가 꺼진(Jailbreak) 모델을 만들어 저장소에 "Llama-3-Kor-Optimized" 같은 그럴싸한 이름으로 올림.
  2. **오염된 훈련 데이터 (Poisoned Data)**: 인터넷에 공개된 거대 데이터셋(예: LAION)의 이미지 링크를 해커가 사들여 엉뚱한 이미지(포르노, 폭력)로 바꿔치기 함. 이걸 가져다 학습한 AI는 바보가 됨.
  3. **서드파티 플러그인 위협 (Plugins)**: 챗봇에 연동하는 서드파티 플러그인(날씨 앱, 주식 앱)이 취약할 경우, 이 플러그인을 통해 해커가 AI의 코어 권한을 장악함.
- **구체 예시**: 피클(Pickle) 파일 원격 코드 실행(RCE) 공격. 머신러닝 커뮤니티에서 가장 흔히 쓰이는 PyTorch의 `.pt`, `.pkl` 파일 형식은 파이썬 객체를 직렬화(Serialization)한 것임. 해커가 이 파일 안에 시스템 명령(`os.system('rm -rf /')`)을 몰래 넣어 허깅페이스에 올림. 개발자가 이 모델을 서버에 다운받아 로드(Load)하는 순간 서버가 포맷되거나 장악됨.
- **흔한 오해/주의점**: "일반 소프트웨어 공급망 공격(Log4j 같은 거)이랑 똑같은 거 아님?" $\rightarrow$ 비슷하지만 다름. 기존에는 '코드(라이브러리)'만 조심하면 됐지만, AI 시대에는 덩치가 수십 기가바이트에 달하는 '모델 가중치 파일(Weight)'과 '거대 데이터셋(Dataset)' 자체가 무기가 되어 들어온다는 점이 가장 큰 차이임. (AI 전용 방어 체계 필요).

## 연결 개념
- **Data Poisoning (데이터 오염 / LLM04)**: 공급망 취약점의 가장 대표적인 결과물 중 하나. 외부에서 가져온 데이터가 오염되어 모델 성능을 파괴함.
- **AI-SBOM (Software Bill of Materials for AI)**: 소프트웨어 명세서. 이 모델은 어떤 데이터로, 어떤 버전의 파이토치로, 누구의 코드를 갖다 썼는지 족보를 문서화하여 출처를 투명하게 하는 방어 기술.
- **Safetensors (세이프텐서)**: Hugging Face에서 피클(Pickle) 파일의 악성코드 실행 취약점을 막기 위해 만든, 순수하게 '수학적 텐서 데이터(숫자)'만 저장하고 실행 코드는 뺀 안전한 모델 파일 포맷.

# 📝 【답안용】 시험 답안 템플릿
## 핵심 인사이트 (3줄 요약)
- **본질**: AI 시스템을 구축하기 위해 의존하는 서드파티 컴포넌트(사전 학습된 파운데이션 모델, 훈련 데이터셋, 오픈소스 ML 라이브러리, 플러그인)의 무결성이 해커에 의해 훼손되어 시스템 전체로 침해(RCE, 백도어 등)가 전이되는 공급망(Supply Chain) 보안 위협.
- **가치**: 딥러닝 모델의 복잡성과 거대한 훈련 비용으로 인해 자체 생태계(In-house) 구축이 불가능한 현 MLaaS 및 오픈소스(Hugging Face) 위주의 AI 생태계 구조상, 가장 빈번하고 탐지하기 어려운 광범위한 파괴력을 지님.
- **판단 포인트**: 기존 소프트웨어 기반의 DevSecOps를 넘어, 모델 가중치 파일에 대한 악성코드 스캐닝(Pickle $\rightarrow$ Safetensors 전환), 데이터 프로버넌스(Data Provenance) 관리, 그리고 AI 컴포넌트의 가시성을 확보하는 AI-SBOM 체계 도입이 필수적임.

## Ⅰ. 개요 및 필요성
- **정의**: 기계학습 수명주기(Machine Learning Lifecycle) 전반에 걸쳐 통합되는 외부 소스(모델, 데이터, 코드, 플러그인)에 내재된 취약점, 악성코드, 의도적 편향(Bias)이 호스트 AI 애플리케이션으로 상속(Inherit)되는 위협.
- **배경**: LLM 개발 트렌드가 "거대 모델의 전이 학습(Transfer Learning)"과 "RAG(검색 증강 생성)를 위한 서드파티 플러그인 연동"으로 수렴하면서, 공격 표면(Attack Surface)이 기업 내부를 넘어 글로벌 오픈소스 커뮤니티로 확장됨.
- **필요성**: OWASP LLM03으로 규정된 이 위협은, 모델을 로드(Load)하는 행위 자체만으로도 백엔드 서버의 최고 권한(Root)이 탈취되는 원격 코드 실행(RCE)으로 직결되므로 컴플라이언스 차원의 강력한 벤더/출처 통제가 요구됨.

## Ⅱ. LLM 공급망의 4대 취약 벡터 (Vectors)
AI 생태계를 위협하는 독성 요소들.
| 공급망 컴포넌트 | 주요 보안 위협 (Vulnerabilities) | 공격 사례 및 피해 |
|:---:|:---|:---|
| **모델 가중치 파일**<br>(Pre-trained Models) | 직렬화(Serialization) 포맷(예: Pickle)의 취약점을 악용한 악성 코드 삽입 및 백도어(Neural Trojan). | 감염된 모델 파일 로드 시 서버 쉘(Shell) 권한 탈취 (RCE). |
| **훈련 데이터셋**<br>(Crowdsourced Data) | 외부 데이터 제공자나 크라우드워커에 의한 데이터 오염(Poisoning) 및 편향성/악성 라벨 주입. | 모델 성능 저하, 윤리 필터 파괴, 특정 타겟 오분류 유도. |
| **오픈소스 패키지**<br>(ML Libraries) | PyTorch, TensorFlow 등 ML 프레임워크나 토크나이저(Tokenizer) 라이브러리 자체의 제로데이(CVE) 취약점. | 타이포스쿼팅(이름을 비슷하게 지은 악성 패키지) 배포. |
| **플러그인 / 확장**<br>(Plugins & APIs) | LLM이 사용하는 외부 확장 API가 불충분한 인증/인가를 가질 경우 발생. | 플러그인을 거점으로 한 간접 프롬프트 인젝션 및 DB 탈취. |

## Ⅲ. 전통적 공급망(SW) vs LLM 공급망(AI) 비교
| 구분 | 기존 SW 공급망 보안 | AI/LLM 공급망 보안 |
|:---:|:---|:---|
| **검증 대상** | 소스 코드, 패키지 의존성(Log4j 등) | **수십 GB의 모델 가중치(Weight), 테라바이트급 데이터셋** |
| **검증 방법** | SAST, DAST, 코드 취약점 스캐닝 | **모델 무결성 해시 검증, 데이터 오염 탐지, 백도어 스캔** |
| **명세서 (BOM)** | SBOM (Software Bill of Materials) | **AI-SBOM (Model, Dataset, Hyperparameters 출처 포함)** |
| **취약점 발현** | 빌드(Build) 및 런타임(Run) 시점 | **모델 파일 로드(Load) 및 파인튜닝(Fine-tuning) 시점** |

## Ⅳ. LLM03 방어를 위한 AI 공급망 거버넌스 (Defense Architecture)
안전한 부품만 조립하기 위한 MLOps 보안 파이프라인.
1. **모델 파일 포맷의 안전성 확보 (Safetensors 도입)**:
   - 임의의 코드 실행이 가능한 취약한 `.pickle`, `.pt` 포맷 사용을 전면 금지.
   - 오직 순수한 텐서(Tensor) 데이터만 저장하여 원격 코드 실행(RCE)이 구조적으로 불가능한 **`Safetensors`** 포맷으로 모델 변환 및 로드 강제.
2. **AI-SBOM(인공지능 소프트웨어 명세서) 구축 및 검증**:
   - 도입하는 모델이 어떤 데이터셋으로 학습되었는지, 라이선스는 무엇인지, 기초 아키텍처(Llama, Mistral 등)는 무엇인지 투명하게 기록.
   - 모델 다운로드 시 SHA-256 해시값 서명 검증(Cryptographic Verification)을 통해 중간자 공격(MITM) 변조 확인.
3. **MsecOps (MLOps + Security) 샌드박싱**:
   - 외부에서 가져온 모델이나 데이터를 파인튜닝/로딩할 때 사내 핵심망과 분리된 **샌드박스(격리망) 환경**에서만 수행하여 감염 시 피해 반경(Blast Radius) 격리.

## Ⅴ. 실무 적용 및 결론
- **판단 지표**: 사내 MLOps 파이프라인에서 Safetensors 포맷 강제 사용 비율, 외부 의존성(패키지, 모델)에 대한 AI-SBOM 자동화 작성 및 갱신 주기, 출처가 불분명한 모델에 대한 반입 차단율.
- **실무 설계**: 대형 포털 C사의 '생성형 AI 서비스 개발 플랫폼' 구축 프로젝트. 개발팀이 오픈소스 허브(Hugging Face)에서 자유롭게 모델을 다운받아 실험하는 과정에서 심각한 백도어 감염 리스크(LLM03) 노출. 조치 방안: 1) 직접 외부 허브 접속 차단. 사내에 '프라이빗 AI 모델 레지스트리(Private Model Registry)' 구축. 2) 외부 모델 반입 시 보안팀의 자동화 파이프라인(Malware Scan, Pickle 취약점 검사)을 통과한 **Safetensors** 포맷 모델만 사내 레지스트리에 등록(Allowlist). 3) 각 모델별로 출처, 라이선스, 의존성을 문서화한 **AI-SBOM** 의무 발행 후 승인. 결과적으로 개발 자율성을 보장하면서 공급망 위협 원천 차단.
- **결론**: AI의 발전은 "거인의 어깨 위에 올라타는 것(오픈소스 활용)"이 필수적이지만, 그 거인이 병에 걸렸다면 시스템 전체가 붕괴된다. LLM 공급망 취약점 방어는 단순히 해킹을 막는 것을 넘어, 저작권 이슈와 AI 모델의 라이선스 분쟁까지 포괄하는 AI 거버넌스의 척추이므로, 투명한 AI-SBOM 체계와 샌드박스 검증의 내재화가 필수적이다.

### 🔀 문제 유형별 목차 전환
- **Ⅱ·Ⅲ 강조 (개념/원리형)**: Python의 `pickle` 모듈이 직렬화(Serialize) 및 역직렬화(Deserialize) 과정에서 매직 메소드(`__reduce__`)를 호출할 때 시스템 운영체제 명령어(OS Command)를 무조건 실행하게 되는 구조적 RCE 취약점의 코드 레벨 동작 원리.
- **Ⅴ·Ⅵ 강조 (실무/설계형)**: AI 애플리케이션의 컨테이너화(Docker/K8s) 과정에서, 모델 저장소(Registry) 서명 솔루션인 Cosign과 in-toto를 활용하여 모델 생성부터 배포까지의 무결성(Provenance)을 암호학적으로 보증하는 'Supply Chain Security Framework(SLSA)' 적용 아키텍처.
