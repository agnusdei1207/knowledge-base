## 미리 알고가기

- VC는 발행자가 서명한 디지털 자격증명이고 DID는 그 자격증명의 주체와 발행자를 식별하는 체계임
- 검증은 원문서 전달이 아니라 클레임과 증명과 상태 정보를 확인하는 방식으로 이뤄짐
- 선택적 공개와 폐기 상태 확인이 실제 도입의 프라이버시와 운영성에 큰 영향을 줌

## Ⅰ. 개요

- **정의/개념**: Verifiable Credential은 개인이나 조직의 속성 및 자격 정보를 발행자의 암호학적 증명과 함께 담아 검증자가 원발급 기관에 다시 조회하지 않고도 진위와 출처를 확인할 수 있게 하는 디지털 자격증명 표준임
- **배경/필요성**: PDF 증명서나 중앙 API 조회 방식은 위변조 검증과 기관 간 연동 비용과 과도한 개인정보 전달 문제가 커서 필요한 속성만 안전하게 제시하고 재사용할 수 있는 자격 체계가 필요함

## Ⅱ. 특징

- 자격 정보와 발행자 증명을 함께 보관해 문서 열람이 아니라 데이터 검증 방식으로 자동화를 지원함
- 보유자가 필요한 속성만 제시할 수 있어 전체 신원정보 전달보다 프라이버시 통제가 쉬움
- 발행과 보관과 제시와 검증 역할이 분리돼 기관 간 재사용성과 사용자 통제권을 높일 수 있음
- 상태 목록과 프로파일이 정리되지 않으면 폐기 반영과 상호운용성이 약해져 서비스 간 검증 품질이 달라질 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 전자문서 증명서 | 중앙 API 조회 | VC |
|:---|:---|:---|:---|
| 검증 방식 | 문서 원본과 육안 확인 | 발행기관 실시간 조회 | 서명과 상태 정보 검증 |
| 정보 공개 | 문서 전체 전달이 잦음 | 기관이 정한 범위 전송 | 필요한 속성만 제시 가능 |
| 휴대성과 재사용 | 파일 전달 중심 | 플랫폼 종속 | 지갑 기반 재사용 가능 |
| 대표 한계 | 자동 검증과 위변조 대응이 약함 | 연동 비용과 장애 의존이 큼 | 프로파일과 폐기 관리가 필요함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Issuer | 학교나 기관처럼 자격 정보를 확인하고 VC에 서명해 신뢰의 출처를 제공하는 발행 주체임 |
| Credential Subject and Claims | 성인 여부와 학위와 자격 등 검증 대상 속성을 담는 데이터 계층으로 어떤 항목을 포함할지 설계가 프라이버시와 직결됨 |
| Holder Wallet | 사용자가 VC를 저장하고 제출 범위를 통제하는 보관 계층으로 복구와 키 관리가 사용자 경험을 좌우함 |
| Proof and Status | 전자서명과 상태 목록이 진위와 폐기 여부를 검증하게 하는 검증 계층으로 위조 방지와 유효성 관리의 핵심임 |
| Verifier and Presentation | 검증자가 목적에 맞는 속성만 제시받아 정책에 따라 판단하는 제출 계층으로 선택적 공개 품질이 중요함 |

```text
+--------+    +----------------+    +---------------+    +----------+
| Issuer | -> | VC + Proof     | -> | Holder Wallet | -> | Verifier |
+--------+    +----------------+    +---------------+    +----------+
                    |                         |
                    v                         v
              +-------------+           +-------------+
              | Status List |           | Presentation|
              +-------------+           +-------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 자격 확인     | -> | VC 서명/발급  | -> | 지갑 보관      | -> | 선택 제시      | -> | 서명/상태 검증 |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **자격 확인**: 발행자가 사용자의 학위나 자격 같은 사실을 확인함
2. **VC 서명과 발급**: 확인된 속성을 표준 형식으로 구성하고 발행자 키로 서명함
3. **지갑 보관**: 사용자가 지갑에 VC를 저장하고 제시 정책을 관리함
4. **선택 제시**: 검증 목적에 맞는 속성만 추려 Presentation 형태로 제출함
5. **서명과 상태 검증**: 검증자가 발행자 공개키와 폐기 상태를 확인해 수용 여부를 판단함

## Ⅵ. 실무 적용 및 유의점

1. 대학 학위나 전문 자격 검증은 VC로 발급과 제출을 자동화하기 좋지만 불필요한 속성이 함께 노출되면 프라이버시 이점이 사라지므로 선택적 공개와 상태 목록 갱신을 함께 설계하고 제출 성공률과 폐기 반영 지연으로 확인함
2. 모바일 신분과 출입 인증은 기관 간 재사용성이 크지만 지갑과 프로파일이 다르면 검증 실패가 늘 수 있으므로 공통 스키마와 상호운용 시험을 먼저 맞추고 교차 지갑 검증 성공률과 평균 검증 시간을 확인함

## Ⅶ. 결론

- VC는 디지털 증명서를 파일 전달에서 데이터 검증 구조로 바꾸는 기술이므로 선택적 공개와 폐기 관리와 상호운용 프로파일이 갖춰질 때 실무 가치가 커짐
