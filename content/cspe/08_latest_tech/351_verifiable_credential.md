## 미리 알고가기

- DID는 사람이나 기관을 분산 방식으로 식별하는 식별자임
- 선택적 공개는 증명서 전체가 아니라 필요한 속성만 골라 제출하는 방식임
- 상태 목록은 자격증명이 폐기되었는지, 아직 유효한지 확인하는 정보임

## Ⅰ. 개요

- **정의/개념**: VC는 학위·자격·소속 정보를 발행자 서명과 함께 담아 발행기관 재조회 없이 진위와 출처를 검증하는 디지털 자격증명임
- **배경/필요성**: 종이 증명서와 중앙 조회 방식은 위변조 확인과 연동 비용과 개인정보 노출 부담이 커 선택적 제시가 가능한 증명 방식이 필요함

## Ⅱ. 특징

- 자격 정보를 문서 전달이 아니라 서명 검증 대상으로 다뤄 자동 검증에 유리함
- 보유자가 필요한 속성만 제출할 수 있어 과도한 신원정보 노출을 줄일 수 있음
- 발행, 보관, 제출, 검증 역할이 나뉘어 기관 간 재사용과 사용자 통제권 확보에 유리함
- 상태 관리와 데이터 형식이 맞지 않으면 폐기 반영과 상호운용이 흔들릴 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 전자문서 증명서 | 중앙 조회 방식 | VC |
|:---|:---|:---|:---|
| 진위 확인 | 문서 원본과 육안 확인에 의존함 | 발행기관 시스템에 다시 조회함 | 서명과 상태 정보를 검증함 |
| 정보 공개 범위 | 문서 전체를 내기 쉬움 | 기관이 정한 항목을 넘겨줌 | 필요한 속성만 골라 제시 가능함 |
| 재사용성 | 파일 전달 중심임 | 연결된 시스템 안에서만 주로 씀 | 지갑 기반으로 여러 서비스에서 재사용 가능함 |
| 주의점 | 자동 검증이 약함 | 장애와 연동 비용에 민감함 | 상태 관리와 공통 형식 정리가 필요함 |

> 요약: VC는 중앙 재조회 대신 서명과 상태 검증으로 진위를 확인하고 필요한 정보만 제시함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 발행자 | 학교나 기관처럼 자격 사실을 확인한 뒤 VC에 서명하는 주체로 신뢰의 출처가 됨 |
| 자격 내용 | 학위, 성인 여부, 자격 번호처럼 검증 대상 속성을 담는 데이터 계층으로 어떤 항목을 넣는지가 프라이버시 수준을 좌우함 |
| 보유자 지갑 | 사용자가 VC를 저장하고 제출 범위를 정하는 보관 계층으로 복구성과 키 관리가 중요함 |
| 증명과 상태 정보 | 전자서명과 상태 목록을 통해 위변조와 폐기 여부를 확인하게 하는 검증 계층임 |
| 검증자와 제시 정보 | 서비스 목적에 맞는 속성만 받아 정책에 따라 수용 여부를 판단하는 사용 계층임 |

```text
+--------+    +------------------+    +-------------+    +----------+
| 발행자 | -> | VC + 서명 정보      | -> | 보유자 지갑    | -> | 검증자   |
+--------+    +------------------+    +-------------+    +----------+
                    |                          |
                    v                          v
              +--------------+          +--------------+
              | 상태 목록      |          | 선택 제시 정보 |
              +--------------+          +--------------+
```

> 요약: VC는 발행, 보관, 선택 제시, 상태 검증이 분리된 구조라 사용자 통제와 기관 간 재사용에 유리함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 자격 확인      | -> | 서명 후 발급   | -> | 지갑 보관      | -> | 필요한 정보 제시 | -> | 서명/상태 검증 |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **자격 확인**: 발행자가 학위나 자격 같은 사실을 먼저 확인함
2. **서명 후 발급**: 확인된 내용을 VC 형식으로 만들고 발행자 키로 서명함
3. **지갑 보관**: 사용자가 VC를 지갑에 저장하고 제출 범위를 정함
4. **필요한 정보 제시**: 검증 목적에 맞는 속성만 골라 제출함
5. **서명과 상태 검증**: 검증자가 발행자 공개키와 상태 목록을 확인해 수용 여부를 판단함

> 요약: VC는 서명된 자격 정보를 지갑에 보관했다가 필요한 속성만 제출하고 상태 목록으로 최종 유효성을 확인함.

## Ⅵ. 실무 적용 및 유의점

1. 학위·자격 검증은 VC로 자동화하되 선택적 공개와 상태 목록을 설계하고 제출 성공률·폐기 반영 지연으로 확인함
2. 모바일 신분 확인은 공통 스키마와 상호운용 시험을 먼저 맞추고 교차 검증 성공률·평균 검증 시간으로 확인함

## Ⅶ. 결론

- VC는 증명서 제출을 데이터 검증으로 바꾸므로 선택적 공개·상태 관리·상호운용 기준이 핵심임

## 작성 근거(검토용)

- 개요는 VC의 본질을 서명 기반 자격증명과 재조회 없는 검증으로 압축해 DID와의 역할 차이를 분명히 함
- Ⅲ은 전자문서와 중앙 조회를 비교축으로 잡아 VC가 왜 필요한지 바로 드러나게 구성함
- Ⅳ는 발행자, 자격 내용, 지갑, 상태 정보, 검증자를 분리해 신뢰 흐름과 프라이버시 통제 지점을 함께 보이게 함
- Ⅴ는 발급, 보관, 선택 제시, 상태 검증 순서로 실제 서비스 절차를 따라가게 배치함
- Ⅵ은 자동 검증과 상호운용이 도입 성패를 좌우하므로 제출 성공률과 폐기 반영 같은 운영 지표를 남김
