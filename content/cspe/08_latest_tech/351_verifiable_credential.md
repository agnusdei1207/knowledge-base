# 📖 【암기용】 개념 완전 이해

> 목적: VC를 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 디지털 세상에서 종이 증명서(졸업증명서, 운전면허증 등)와 동일한 법적·기술적 효력을 가지도록 만든 '검증 가능한 디지털 증명서'
- **왜 필요한가**: 기존 디지털 파일(PDF 등)은 위조가 쉽고 진짜인지 확인하려면 발행 기관에 일일이 물어봐야 함. VC는 증명서 안에 디지털 도장이 찍혀 있어, 기관에 묻지 않고도 그 자리에서 즉시 진위 확인이 가능하기 때문
- **핵심 직관**: "디지털 세상의 공증된 신분증 조각" — 내 스마트폰 지갑에 들어있으며, 필요할 때만 그 존재를 증명할 수 있는 데이터 팩

## 깊이 이해
- **배경·문제의식**: 인터넷에서 내가 누구인지, 어떤 자격이 있는지 증명하는 과정은 매우 번거롭고 개인정보 유출 위험이 큼. 이를 해결하기 위해 W3C에서 표준화한 것이 VC(Verifiable Credential)임.
- **작동 원리**: ① **클레임(Claim)** — "이름은 홍길동이다"와 같은 개별 정보. ② **증명서(Credential)** — 클레임들을 묶고 발행자(Issuer)의 디지털 서명을 더한 것. ③ **프레젠테이션(VP)** — 사용자가 검증자에게 보여주기 위해 여러 VC에서 필요한 것만 골라 묶은 것. 이 모든 과정이 블록체인이나 공개키 기반 구조(PKI)를 통해 위조 불가능하게 관리됨.
- **비유**: 편의점에서 맥주를 살 때 주민등록증 전체를 복사해서 주는 게 아니라, 주민등록증을 보여주며 '성인임'이라는 사실(VC)만 증명하는 것과 같음. 이때 가게 주인은 주민등록증의 홀로그램(디지털 서명)을 보고 진짜임을 믿음.
- **구체 예시**: 대학 졸업생이 모바일 지갑으로 받은 '졸업 VC'. 취업 시 이 VC를 회사에 제출하면, 회사는 대학 홈페이지에 접속하지 않고도 서명 검증만으로 학력 위조 여부를 즉시 판단함.
- **흔한 오해·주의점**: VC 자체가 블록체인은 아님. VC는 데이터 형식(JSON-LD 등)일 뿐이며, 블록체인은 이 VC를 발행한 사람의 '도장 정보(공개키)'를 찾아보는 용도로 쓰임.

## 연결 개념
- DID (Decentralized Identifier) — VC의 주체를 식별하기 위한 분산 아이디
- Selective Disclosure — VC 정보 중 일부만 골라 공개하는 기술 (프라이버시 보호)
- JSON-LD — VC 표준 데이터 포맷 (컴퓨터가 읽기 쉬운 형태)

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: W3C 표준 데이터 모델과 클레임(Claim) 기반의 증명 구조, 그리고 선택적 노출(Selective Disclosure) 메커니즘을 기술한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 발행자의 전자서명을 포함하여 데이터의 무결성과 출처를 기계가 읽을 수 있는(Machine-readable) 형태로 검증할 수 있는 디지털 자격증명 표준이다.
> 2. **가치**: 개인정보의 선택적 노출(Selective Disclosure)을 통해 프라이버시를 보호하며, 기관 간의 직접적인 통신 없이도 신뢰 관계(Trust)를 형성한다.
> 3. **판단 포인트**: W3C VC 데이터 모델 준수 여부와 무결성 보장을 위한 증명(Proof) 메커니즘, 그리고 영지식 증명(ZKP)과의 결합 가능성이 핵심이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| VC의 개념 및 표준 데이터 모델 이해 확인 | Claim, Credential, Presentation, Issuer, Holder, Verifier | 단순 디지털 파일 전송으로 서술 |
| 기술적 구성요소 및 동작 아키텍처 파악 | Metadata, Claim, Proof(전자서명) | DID와 VC의 역할을 구분하지 못함 |
| 프라이버시 강화 기술 적용 능력 판단 | 선택적 노출(Selective Disclosure), ZKP, JSON-LD | 개인정보 전체가 전달된다는 고정관념 |

> 요약: VC는 '무결성이 보장된 클레임의 집합'이며, 사용자의 통제 하에 신뢰를 전달하는 매개체다.

## Ⅰ. 개요 및 필요성

- 정의: 온라인 상에서 개인의 속성이나 자격(학력, 자격증 등)을 발행자의 전자서명을 통해 위변조 불가능하게 증명하는 W3C 표준 데이터 모델
- 배경: 기존 신원 확인 체계의 개인정보 과다 노출 문제 및 기관 간 데이터 연동 시 발생하는 높은 신뢰 비용 해결
- 필요성: 자기주권 신원(SSI) 실현의 핵심 데이터 단위, 비대면 서비스의 자동화 및 효율화, 데이터 위변조 방지

## Ⅱ. 구조 및 구성요소 (W3C Data Model)

```text
[ Verifiable Credential (VC) ]
  /-------------------------------------------------\
  | 1. Metadata: 버전, 발행일, 유효기간, 발행자 ID      |
  | 2. Claims: { 성명: 홍길동, 학위: 석사, 전공: CS }    |
  | 3. Proof: 디지털 서명 (Issuer's Signature)         |
  \-------------------------------------------------/
           |
           v (Selection & Masking)
           |
[ Verifiable Presentation (VP) ]
  /-------------------------------------------------\
  | - Selected Claims: { 학위: 석사 }                 |
  | - Combined Proofs: { VC Proof + Holder Signature }|
  \-------------------------------------------------/
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Claim (클레임) | 주체(Subject)에 대한 단편적인 정보 (Key-Value) | 예: "나이": "25" |
| Credential (자격증명) | 하나 이상의 클레임과 발행자의 증명(Proof)이 결합된 형태 | 유효기간 포함 가능 |
| Presentation (제출) | 검증자에게 보여주기 위해 하나 이상의 VC를 조합한 데이터 | 사용자의 서명 추가 포함 |
| Proof (증명) | 데이터의 무결성과 출처를 보장하는 암호학적 요소 | 전자서명, ZKP 등 |

> 요약: 신원 정보(Claim)를 담고 발행자의 서명(Proof)으로 봉인하여, 사용자가 필요한 것만 골라 제출(VP)하는 구조다.

## Ⅲ. 동작원리 및 흐름도

```text
발행요청 -> 속성 검증 -> VC 서명 및 발행 -> 지갑 저장 -> VP 생성 및 제출 -> 서명 검증(블록체인 연동)
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 발행 요청 (Issuance) | 사용자가 발행기관에 특정 자격(예: 졸업) 증명을 요청 | 신원 확인(KYC) 수행 |
| 2 | 데이터 패키징 | 발행기관은 사용자의 속성 정보를 JSON-LD 형식으로 구성 | 표준 스키마 준수 |
| 3 | 디지털 서명 | 발행기관의 개인키로 VC에 서명하고 사용자에게 전달 | 서명 알고리즘(ECDSA 등) |
| 4 | 선택적 노출 | 사용자는 제출 목적에 맞는 정보만 선택하여 VP 구성 | 영지식 증명(ZKP) 활용 권장 |
| 5 | 실시간 검증 | 검증자는 발행자의 공개키를 블록체인 등에서 조회하여 VP 검증 | 폐기 여부(Revocation) 확인 |

> 요약: 발행자가 보증한 데이터(VC)를 사용자가 관리하다가, 검증자가 발행자의 신뢰(도장)를 확인하는 방식이다.

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 상호운용성 | W3C 표준 준수로 글로벌 서비스 간 연동 가능 | JSON-LD, DID 연동 |
| 프라이버시 보호 | Selective Disclosure를 통한 최소 정보 공개 원칙 | 성인인증 시 생년월일 미노출 |
| 비접촉 검증 | 발행 기관과 직접 통신 없이 오프라인 검증 가능 | 시스템 부하 감소 및 장애 내성 |
| 데이터 주권 | 사용자가 자신의 증명서를 직접 소유 및 제출 통제 | SSI (Self-Sovereign Identity) |

> 요약: 표준화된 형식을 통해 전 세계 어디서든 신뢰를 주고받을 수 있는 디지털 데이터 통화와 같다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존 디지털 증명서 (PDF/전자문서) | VC (Verifiable Credential) | 선택 기준 |
|:---|:---|:---|:---|
| 데이터 형태 | 비정형 (문서 위주) | 정형 (데이터 필드 위주) | 자동화 처리(Machine-readable) 필요 시 |
| 검증 방식 | 발행기관 API 호출 또는 육안 확인 | 암호학적 서명 검증 (블록체인) | 실시간성 및 신뢰 비용 절감 목표 시 |
| 정보 통제권 | 발행기관/검증기관 중심 | 사용자(Holder) 중심 | 데이터 주권 및 사생활 보호 요구도 |
| 위변조 방지 | 워터마크, 2차원 바코드 | 디지털 서명, 해시 체인 | 보안 강도 및 위조 난이도 |

> 요약: 단순 열람용 문서를 넘어, 시스템 간 자동으로 자격을 확인해야 하는 연동 환경에서는 VC가 필수적이다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 키 유출 리스크 | 발행자 개인키 유출 시 대규모 위조 VC 발행 가능 | HSM 기반 키 관리, 다중 서명(Multi-sig) | 키 관리 보안 등급 |
| 개인정보 노출 | VP 제출 시 불필요한 정보가 함께 전달될 위험 | BBS+ 서명 등을 통한 선택적 노출 기술 적용 | 정보 노출 최소화 지수 |
| 실시간 효력 상실 | 자격 취소(예: 면허 취소) 정보 업데이트 지연 | Revocation List(CRL) 또는 OCSP 연동 | 자격 취소 반영 시간 |

> 요약: 발행자의 키 보안과 실시간 자격 취소 확인 체계가 시스템 신뢰도의 관건이다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 데이터 정합성 | 표준 스키마 부합도 100% | 스키마 밸리데이터(Validator) 수행 |
| 검증 소요 시간 | 500ms 이내 (단일 VC 기준) | 서버/클라이언트 검증 로그 |
| 폐기 확인 지연 | 취소 후 1분 이내 전파 | CRL/Bitstring 업데이트 주기 |

> 요약: 도입 성과는 데이터의 표준 준수 여부와 자격 취소 정보의 신속한 반영 속도로 측정한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 대학 학위/성적 증명 서비스: 졸업장과 성적표를 VC로 발급하여 취업 포털 등에 원클릭 제출 및 인사 담당자의 즉시 검증 지원
2. 건강 상태/백신 증명: 검역소나 다중이용시설 출입 시 개인의 건강 상태 VC를 제출하되, 이름이나 주소는 노출하지 않는 프라이버시 보호형 인증
3. 전문 자격 기반 접근 통제: 클라우드 운영 권한을 특정 기술 자격 VC 보유자에게만 자동으로 부여하여 운영 보안 강화

**결론 (2줄):**
- 기술사 판단: VC는 '신뢰의 데이터화'를 실현하는 도구이며, 디지털 경제의 신뢰 비용을 획기적으로 낮추는 핵심 인프라가 될 것이다
- 향후 방향: 탄소 배출권 증명, 제품 생산 이력(DPP) 등 다양한 산업 데이터의 신뢰 보증 수단으로 확장될 전망이다
