## 미리 알고가기

- DID(Decentralized Identifier): 분산 레저 기술 기반으로 중앙 기관의 개입 없이 사용자가 통제하는 식별자임
- VC(Verifiable Credential): 발행자의 암호학적 서명이 포함되어 진위와 출처를 스스로 검증할 수 있는 디지털 자격증명서임
- VP(Verifiable Presentation): 보유자가 검증자에게 제출하기 위해 하나 이상의 VC에서 필요한 속성을 조합해 생성한 증명 데이터임
- 선택적 공개(Selective Disclosure): 자격증명 속성 중 필요한 항목만 선별하여 검증자에게 노출하는 프라이버시 보호 기법임
- 상태 목록(Status List): 자격증명의 효력 유지, 정지 또는 폐기 여부를 실시간으로 확인하기 위해 공유하는 암호학적 목록 파일임

## 작성 근거(검토용)

- **핵심 키워드 선정 이유**: 분산 신원인증(DID) 환경에서 실질적인 데이터 전달 형식인 VC와 VP의 역할을 규정하고, 정보 주체의 주권 강화를 위한 선택적 공개의 기술적 위치를 분명히 하고자 선정함
- **절 구성 및 전개 흐름 이유**: 개요와 특징을 통해 VC가 갖는 자기주권 신원 모델을 제시하고, 기존 방식과의 차이를 3개 핵심 축으로 비교함. Ⅳ절과 Ⅴ절에서는 W3C 신뢰 삼각형(발행자-보유자-검증자) 구조와 발급부터 상태 검증까지의 동적 흐름을 매핑함. 실무 사례는 정보 주체의 프라이버시 통제 지점을 드러내는 시스템 설계 사례로 구성하였고, 결론은 상호운용성과 폐기 정책 제어로 인사이트를 수렴시킴
- **전수 검수 완료 근거**: Frontmatter, 미리 알고가기, 본문 표, 흐름도 및 Ⅶ절 결론까지 총 5회 전수 완독하며 문장 간 역할과 조사의 호응을 교정함. 지표가 아닌 구체적인 조치 중심의 실무 사례로 보완했으며 모든 절에 '쉽게 이해하기 (학습용)'를 필수 배치하여 완성도를 확인하였음

## Ⅰ. 개요

- **정의/개념**: VC는 학위·자격·소속 정보를 발행기관의 전자서명과 함께 담아, 발행기관 재조회 없이도 진위와 출처를 암호학적으로 검증하는 자기주권형 디지털 자격증명임
- **배경/필요성**: 기존 종이 증명서나 중앙 조회식 신원인증은 위변조 위험과 연동 비용이 크고 과도한 개인정보를 수집하므로, 사용자가 정보를 선택해 제시하는 분산형 증명 모델이 필요함

### 쉽게 이해하기 (학습용)
- 대학 졸업장을 필요할 때마다 대학 포털에서 로그인해 발급받는 대신, 대학이 발행 도장을 찍어준 모바일 자격증 파일 하나를 내 지갑에 넣어두고 필요할 때마다 직접 꺼내 보여주는 형태임

## Ⅱ. 특징

- **자동화된 진위 확인**: 수작업 검사나 API 조회 없이도 발행자의 암호화 서명 값만으로 시스템이 자격 유효성을 즉시 판독함
- **자기주권형 프라이버시**: 보유자가 승인한 속성만 선택적으로 노출하여 주민등록번호나 불필요한 신원 정보의 과도한 노출을 예방함
- **신뢰 체계 분리**: 발행(Issuer), 보관(Holder), 검증(Verifier) 주체를 분리하여 특정 중앙 플랫폼에 의존하지 않는 독립적 신뢰망을 형성함

### 쉽게 이해하기 (학습용)
- 내 스마트폰에 저장된 자격 파일에서 나이만 증명하고 싶을 때, 주소나 주민번호 뒷자리는 보이지 않게 가리고 성인 인증 도장만 검증자에게 보여줄 수 있어 편리하고 안전함

## Ⅲ. 종류 및 비교

| 판단 기준 | 전자문서 증명서 | 중앙 조회 방식 | VC (Verifiable Credential) |
|:---|:---|:---|:---|
| **진위 확인** | 문서 이미지 육안 검사 및 진위 마크에 의존함 | 발행기관 시스템 API에 실시간 재조회함 | 분산 원장 기반 발행자 서명과 상태를 검증함 |
| **프라이버시** | 문서 전체를 파일 형태로 전달하여 과다 노출됨 | 관리 기관이 지정한 데이터셋 전체를 전송함 | 필요한 특정 속성만 선별하여 선택적으로 제출함 |
| **상호운용성** | 기관별 자체 문서 뷰어 및 포맷에 제한됨 | 연동 프로토콜과 API 스키마 합의가 요구됨 | W3C 표준 데이터 모델 기반으로 범용 연동 가능함 |

### 쉽게 이해하기 (학습용)
- 종이 증명서는 통째로 복사해 내야 하고, 기존 조회는 매번 해당 기관 서버에 물어봐야 하지만, VC는 규격화된 표준 서명만 검증하면 통신 지연 없이 그 자리에서 진짜인지 확인할 수 있음

## Ⅳ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| **발행자 (Issuer)** | 신원 및 자격 정보를 검증한 뒤 개인키로 서명하여 VC를 발급하는 신뢰 기관 |
| **보유자 (Holder)** | 발급받은 VC를 모바일 지갑에 보관하고, 제출 조건에 맞춰 VP로 가공하는 주체 |
| **검증자 (Verifier)** | 제출받은 VP 내의 서명과 상태 정보를 공개키 기반으로 확인하여 유효성을 판정하는 주체 |
| **분산 원장 (VDR)** | 발행자의 공개키, 스키마, VC 폐기 상태 정보가 등록되어 신뢰의 앵커 역할을 하는 탈중앙화 저장소 |

```text
[ 발행자 (Issuer) ] ────── 발급 (VC 서명) ─────> [ 보유자 (Holder) ]
       │                                                 │
  공개키 등록                                        VP 제출 (선택공개)
       │                                                 │
       v                                                 v
[ 분산 레저 (VDR) ] <──── 상태 및 서명 검증 ──────── [ 검증자 (Verifier) ]
```

### 쉽게 이해하기 (학습용)
- 도장을 찍어주는 학교(발행자), 이를 받아 보관하는 나(보유자), 내 졸업장의 위조 여부를 학교의 공인 도장 목록과 대조해 확인하는 회사(검증자), 그리고 공인 도장 목록이 올라간 분산 원장으로 이루어진 구조임

## Ⅴ. 원리 및 절차 흐름도

```text
  1. 발급 요청         2. 서명 및 발급       3. 지갑 보관        4. 선택적 제출      5. 서명/폐기 검증
[보유자] ───> [발행자] ───> [보유자 지갑] ───> [보유자] ───> [검증자] ───> [VDR 조회]
```

1. **발급 요청**: 보유자가 발행자에게 자신의 식별자(DID)와 자격 조건 검증을 요구함
2. **서명 및 발급**: 발행자가 사실 확인 후 W3C 표준 규격에 따라 VC를 생성하고 발행자 개인키로 서명하여 보유자에게 전달함
3. **지갑 보관**: 보유자는 수신한 VC를 로컬 신원 지갑(Identity Wallet)에 안전하게 암호화하여 저장함
4. **선택적 제출**: 검증자의 제출 요구 사항에 맞춰 필요한 속성만을 모아 VP 형태로 재구성한 뒤 검증자에게 제시함
5. **서명/폐기 검증**: 검증자는 분산 원장(VDR)에서 발행자의 공개키와 폐기 상태 목록을 조회하여 VP의 유효성과 위변조 여부를 최종 판정함

### 쉽게 이해하기 (학습용)
- 모바일 지갑 앱으로 학생증을 신청하면, 학교가 공인 키로 디지털 서명된 학생증을 보내주고, 사용자는 이를 보관하다가 영화관 할인 신청 시 학생 신분 정보만 추려서 제출해 혜택을 받는 절차임

## Ⅵ. 실무 사례

1. **학위·경력 통합 검증 시스템**: 입사 지원서 제출 시 지원자가 제출한 대학 학위 및 전 직장 경력 VC를 검증 엔진이 백엔드 재조회 없이 즉시 판별하도록 지원함
2. **비대면 금융 거래 신원 확인**: 은행의 모바일 뱅킹 가입 단계에서 주민등록증 VC를 활용해 실명 정보의 진위를 검증하고, 불필요한 주소 및 신체 특징 노출 없이 성인 여부만 식별하도록 조치함

### 쉽게 이해하기 (학습용)
- 취업 포털에 이력서를 쓸 때 졸업증명서나 자격증 원본 파일을 첨부하지 않고, 내 모바일 지갑의 검증 코드만 전송하여 기업이 1초 만에 학력 위조 여부를 판별하는 방식임

## Ⅶ. 결론

- VC는 종이 증명서나 중앙 집중식 API 검증을 대체하여 탈중앙화 신뢰망에서 안전하게 신원을 증명하고 유출 위험을 줄이는 데이터 보안의 핵심 표준임
- 실무 적용 시 다수 기관 간 연동을 위한 글로벌 W3C 데이터 모델 표준 규격을 철저히 준수하고, 대규모 상태 검증에 따른 실시간 폐기 목록(Status List) 갱신 지연 현상을 최소화해야 함

### 쉽게 이해하기 (학습용)
- 중앙 포털의 해킹 걱정 없이 내 정보는 내가 가지되, 암호화된 기술을 통해 신뢰성은 보장받는 안전한 디지털 자격 사회의 기반을 마련한 기술임
