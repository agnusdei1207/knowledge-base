# 📖 【암기용】 개념 완전 이해

> 목적: MCP Resource를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: MCP Server가 LLM 앱에 제공하는 읽기 가능한 데이터 자원
- **왜 필요한가**: AI가 파일·DB·문서·로그를 사용할 때 데이터 위치와 형식을 표준 방식으로 표현해야 함.
- **핵심 직관**: MCP Resource는 모델이 읽을 수 있는 업무 자료의 주소록과 접근 규칙임.

## 깊이 이해
- **배경·문제의식**: RAG와 에이전트가 사내 데이터를 읽을 때 파일 경로, API 응답, DB 쿼리 결과가 제각각이면 통제가 어려움.
- **작동 원리**: 서버가 URI와 메타데이터로 Resource를 노출하고, Client는 권한 확인 후 데이터를 가져와 컨텍스트에 반영함.
- **비유**: 도서관이 책 제목만 주는 것이 아니라 위치, 열람권한, 대출 가능 여부를 함께 제공하는 구조.
- **구체 예시**: `repo://service-a/README.md`, `log://payment/2026-06-30` 같은 Resource가 모델 분석 입력으로 사용됨.
- **흔한 오해·주의점**: Resource는 읽기 전용이어도 개인정보·비밀키·영업정보가 포함될 수 있어 필터링이 필요함.

## 연결 개념
- RAG — Resource를 검색·근거 데이터로 사용
- Data Lineage — Resource 출처와 변경 이력 추적
- DLP — 민감정보 탐지·차단 통제

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: MCP Resource는 AI 앱이 표준 URI와 메타데이터로 접근하는 읽기형 데이터 자원임.
> 2. **가치**: 파일·문서·로그·DB 결과를 모델 컨텍스트에 넣을 때 출처와 권한을 함께 관리함.
> 3. **판단 포인트**: URI 설계, 접근권한, 민감정보 필터링, 컨텍스트 크기 제한이 핵심임.

---

## Ⅰ. 개요 및 필요성

MCP Resource는 MCP의 읽기형 데이터 단위임. AI 에이전트가 업무 지식을 활용하려면 데이터 위치, 형식, 권한, 출처를 표준화해야 함.

---

## Ⅱ. 구조 및 구성요소

```text
Resource URI → Metadata → Access Policy → Content
        │            │            │          │
        ▼            ▼            ▼          ▼
      위치         형식/크기       권한       데이터
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| URI | 자원 식별 | 스킴·경로·버전 포함 |
| Metadata | 형식·크기·수정시각 | MIME, hash, owner |
| Access Policy | 접근권한 통제 | 사용자·그룹·목적 제한 |
| Content | 실제 데이터 | 마스킹·청크 제한 |

> 요약: MCP Resource는 식별자, 메타데이터, 접근정책, 콘텐츠로 구성된 읽기형 데이터 단위임.

---

## Ⅲ. 동작원리 및 흐름도

```text
자원 목록 요청 → URI 선택 → 권한 확인 → 콘텐츠 조회
        → 민감정보 필터링 → 컨텍스트 반영 → 출처 기록
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | Resource 발견 | URI, MIME, size |
| 2 | 접근권한 확인 | RBAC, ABAC, 목적 제한 |
| 3 | 콘텐츠 조회·필터 | DLP, hash, 청크 크기 |
| 4 | 모델 반영·기록 | 출처, Timestamp, Trace ID |

> 요약: Resource 사용은 조회 전 권한과 조회 후 민감정보 필터를 모두 통과해야 함.

---

## Ⅳ. 특징

| 구분 | 임의 파일 입력 | MCP Resource | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 식별 | 경로·본문 혼재 | URI·메타데이터 | hash, version |
| 권한 | 앱 구현 의존 | Resource 단위 정책 | RBAC, ABAC |
| 위험 | 출처 불명 | 출처 기록 가능 | DLP 탐지율, 토큰 크기 |

> 요약: MCP Resource는 데이터 접근을 표준화하지만 민감정보와 컨텍스트 크기 통제가 필요함.

---

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. Resource URI에 시스템, 소유자, 버전, 보존등급을 포함하고 hash로 변조 여부 확인
2. 접근 전 RBAC·ABAC·목적 제한을 적용하고 개인정보는 DLP 정책으로 마스킹
3. 컨텍스트 투입 전 청크 크기, 최대 토큰, 출처 링크, 보존기간을 설정

**결론 (2줄):**
- 기술사 판단: MCP Resource는 읽기형 자산이라도 데이터 거버넌스와 동일 수준의 접근통제를 적용해야 함.
- 향후 방향: Resource는 RAG, Agent, 데이터 카탈로그를 연결하는 AI 데이터 접근 표준으로 확장됨.
