## 핵심 인사이트 (3줄 요약)
> 1. **본질**: MCP 생태계에서 AI 모델에게 제공되는 **"읽기 전용(Read-only)의 정적(Static) 데이터 창고"**다. 사내 위키피디아 문서, 로컬 PC의 로그 파일, 데이터베이스의 테이블 스키마 등이 이에 해당한다.
> 2. **가치**: 기존 RAG(검색 증강)는 파일을 일일이 업로드하거나 벡터 DB를 구축해야 하는 중노동이 필요했다. Resource는 "이 경로(`file://...`)에 파일이 있으니 AI 네가 필요할 때 언제든 와서 읽어라"라고 길만 열어주는 극강의 편의성을 제공한다.
> 3. **판단 포인트**: 뒤에서 다룰 도구(Tool)가 "행동(Action, 상태 변경)"을 유발한다면, 리소스(Resource)는 오직 "정보의 공급(Context Provider)"에만 머무르는 안전하고 수동적인 객체라는 개념적 경계를 명확히 해야 한다.

## Ⅰ. 개요 및 필요성
- **개요**: Model Context Protocol에서 **리소스(Resource)**는 서버(MCP Server)가 클라이언트(AI 모델) 측에 노출하는 파일, 문서, 데이터베이스 조회 결과 등 읽기 전용 데이터 객체를 의미한다. URI(Uniform Resource Identifier) 형태로 정의된다.
- **배경**: AI에게 코딩을 시키려면 "현재 프로젝트의 아키텍처 문서"를 매번 프롬프트 창에 복사해서 붙여넣기(Copy & Paste) 해야 했다. 파일이 수정되면 이 짓을 또 해야 했다.
- **필요성**: AI가 인간의 복붙(수동 주입)을 기다리지 않고, 로컬 하드디스크나 사내 인트라넷 서버에 놓인 텍스트나 파일의 경로(URI)만 알고 있으면 24시간 실시간으로 최신 버전을 빨아들일 수 있는 '안전한 빨대(Read Channel)'가 필요했다.

---

## Ⅱ. 아키텍처 및 핵심 원리

```text
       [ AI 모델 (MCP Client) ]                           [ 데이터 보유자 (MCP Server) ]
       
   1. "너 무슨 책(Resource)들 가지고 있어?" ─────────▶
                                           ◀─────────   "나 `file://logs/error.log`랑 
                                                          `postgres://schema/users` 있어!"
   2. "아하! 그럼 `error.log` 내용 좀 읽어볼게!"
      (Read Resource 요청)                  ─────────▶
                                                        (서버가 실제 파일을 하드디스크에서 읽음)
                                           ◀─────────   [파일 내용 반환 (Text 또는 Base64)]
                                                          "Error: NullPointerException at..."
   3. "오케이, 이 에러 로그를 분석해 보니까..." 
      (최종 답변 생성)
```

- **1단계 [URI 템플릿 기반 등록]**: MCP Server는 자기가 노출할 데이터를 웹 주소처럼 URI 형식으로 매핑한다. (예: `file:///projects/notes.md` 또는 커스텀 프로토콜인 `wiki://engineering/architecture`).
- **2단계 [목록 검색 (List Resources)]**: AI 앱(Client)이 서버에 "네가 가진 리소스 목록을 다 보여줘"라고 하면, 서버는 이름, 설명, URI 패턴이 적힌 메뉴판을 반환한다.
- **3단계 [내용 읽기 (Read Resource)]**: AI가 문제를 풀다가 "아, 아키텍처 문서가 필요해"라고 판단하면, 해당 URI를 지목하며 `Read` 요청을 던진다. 서버는 파일의 내용을 텍스트나 바이너리(Base64)로 변환해 던져준다.
- **4단계 [구독 및 알림 (Subscribe) - 옵션]**: 파일 내용이 바뀌면 서버가 AI에게 "어! 방금 파일 수정됐어!"라고 실시간 알림(Notification)을 보내, AI가 낡은 데이터를 바탕으로 헛소리(환각)를 하는 것을 막는다.

## Ⅲ. 비교 및 연결

| 비교 축 | MCP 리소스 (Resource) | MCP 도구 (Tool) |
|:---:|:---|:---|
| **성격 (Nature)** | **데이터 (명사, Noun)** | **행동 (동사, Verb)** |
| **권한 한계** | **읽기 전용 (Read-only)** | 읽기, **쓰기, 수정, 삭제 (RWX)** |
| **호출 목적** | 배경 지식, 맥락(Context) 확보 | 현실 세계에 물리적 타격(이메일 발송 등) 가하기 |
| **부작용 (Side Effect)**| 파일을 수천 번 읽어도 아무 문제 없음 | 잘못 실행하면 DB 삭제 등 **대참사 발생 위험** |
| **비유** | 도서관 책상에 놓인 **'설명서 책'** | 요리를 직접 하는 **'프라이팬과 식칼'** |

> ※ **연결 포인트**: 리소스는 '안전한 배경 지식'이므로 사용자의 승인(HITL) 없이 AI가 수백 번 긁어와도 무방하다. 보통 AI가 복잡한 코드를 짤 때, 프로젝트의 코딩 규칙이나 폴더 구조가 담긴 문서를 'Resource'로 쭉 읽어 들인 뒤, 실제 코드 수정은 'Tool'을 써서 커밋하는 콤보를 사용한다.

## Ⅳ. 실무 적용 및 기술사 판단

- **적용 사례 1 (로컬 IDE의 실시간 에러 로그 분석)**: 개발자가 코딩 중 에러가 났다. MCP Client가 로컬 서버의 시스템 로그 파일을 `Resource`로 연동해 두면, 에러가 날 때마다 AI가 로그 파일을 실시간으로 읽고(Subscribe 알림 수신) 즉각적으로 "아, 방금 DB 연결 타임아웃이 났네요. 해결책은 이겁니다."라고 선제적으로 팝업을 띄워주는 AI 페어 프로그래밍이 완성된다.
- **적용 사례 2 (DB 스키마 인젝션)**: AI에게 "매출 1위 고객 찾아줘"라고 텍스트 투 SQL(Text-to-SQL)을 시킬 때, AI가 테이블 이름을 몰라서 헛발질을 한다. 이때 사내 DB의 전체 테이블 구조도(스키마 DDL)를 `postgres://schema`라는 `Resource`로 등록해 두면, AI가 쿼리를 짜기 전 무조건 이 리소스를 먼저 읽어보고 정확한 컬럼명으로 쿼리를 작성하는 똑똑한 데이터 분석 비서가 된다.
- **기술사 판단**: 리소스 설계 시 가장 큰 병목은 **"10GB짜리 로그 파일을 통째로 AI에게 던져줄 것인가?"**이다. LLM의 컨텍스트 윈도우는 기껏해야 1~2MB(100K~200K 토큰)이므로 10GB 파일을 통째로 리소스로 넘기면 시스템이 터진다. 아키텍트는 MCP Server 단에서 리소스를 넘겨주기 전에 최근 100줄만 잘라서 주거나(Tail), 특정 키워드만 필터링해서 던져주는 **리소스 경량화 파이프라인(Pagination & Filtering)**을 반드시 구현해야 한다.

## Ⅴ. 기대효과 및 결론

- **기대효과**: 프롬프트 창에 거대한 문서를 무식하게 복붙하던 원시적인 시대를 종식하고, 데이터 원본은 그 자리에 가만히 둔 채 AI가 필요한 시점에만 쏙쏙 빨아먹는 극강의 컨텍스트 딜리버리(Context Delivery) 최적화를 이뤄냈다.
- **향후 발전 방향**: 현재는 텍스트 위주로 리소스를 땡겨가지만, 점차 Base64로 인코딩된 오디오, 동영상, 고해상도 이미지를 리소스로 불러와 멀티모달(Multi-modal) AI 모델이 영상 속의 문서를 분석하고 설명해 주는 수준으로 리소스 규격이 팽창하고 있다.

### 📌 관련 개념 맵
- **URI 템플릿 (URI Template)**: `file:///logs/{date}/error.log` 처럼 리소스 주소 중간에 뻥 뚫린 구멍(변수)을 뚫어두어, AI가 2026-07-01이나 2026-07-02 등 원하는 날짜의 변수만 끼워 넣어 동적으로 다양한 파일에 접근하게 해주는 라우팅 기법.
- **구독 (Subscription)**: "이 책 내용 바뀌면 나한테 카톡 하나만 줘!"라고 AI가 서버에 예약해 두는 기능. 데이터가 변할 때만 패킷이 날아가므로 폴링(계속 묻기) 방식보다 네트워크 트래픽을 엄청나게 절약한다.

### 📈 관련 키워드 및 발전 흐름도
`프롬프트 수동 복붙` $\to$ `문서 업로드 (파일 첨부)` $\to$ `RAG (벡터 DB 구축 및 검색)` $\to$ `MCP Resource (원격/로컬 정적 파일 동적 매핑)` $\to$ `실시간 구독 알림형 컨텍스트 주입 (미래)`

### 👶 어린이를 위한 3줄 비유 설명
1. 요리사(AI)가 요리를 하다가 김치찌개 끓이는 법이 기억 안 나면, 예전엔 주인이 백과사전을 찢어서 요리사 얼굴에 붙여줬어요.
2. MCP '리소스(Resource)'는 주방 벽에 깔끔하게 꽂혀 있는 "요리책 도서관"과 같아요.
3. 요리사가 필요할 때 언제든 고개를 돌려 그 요리책(리소스)을 읽어볼 순 있지만, 책에 마음대로 낙서하거나(쓰기) 찢어버릴(삭제) 수는 없는 아주 안전한 정보 창고랍니다!
