## 미리 알고가기

- **MCP 리소스(MCP Resource)**: MCP 서버가 노출하며 AI 클라이언트가 쿼리할 수 있는 Uniform Resource Identifier(URI) 식별 기반의 읽기 전용 데이터 객체임.
- **URI 템플릿(URI Template)**: 변수를 포함하여 리소스의 동적 경로를 정의하는 표준 규격으로, 클라이언트가 파라미터를 입력해 필요한 데이터에 접근하게 도움.
- **구독 및 알림(Subscription & Notification)**: 리소스의 상태 변화를 실시간으로 클라이언트에 통지하여 데이터 정합성을 유지하는 실시간 이벤트 메커니즘임.
- **컨텍스트 윈도우(Context Window)**: AI 모델이 한 번에 인지할 수 있는 메모리 버퍼 크기로, 토큰 단위로 측정됨.
- **RAG (Retrieval-Augmented Generation)**: 문서 검색을 활용해 생성 오류(Hallucination)를 방지하는 검색 증강 생성 기술임.

## 작성 근거(검토용)

- **핵심 키워드 선정 이유**: AI 모델에 대량의 정적 문맥을 효율적으로 전달하고, 실시간 지식 정합성을 보장하기 위해 MCP 리소스를 핵심 키워드로 선정함.
- **배치·전개 근거**: MCP 도구(Tool)와의 1:1 대비를 통해 명사적 성격과 안전한 읽기 권한을 강조함. URI 식별 구조도와 요청 처리 절차를 3단계(목록 스캔, 리소스 조회, 실시간 구독) 흐름도로 체계화함. 토큰 포화 대응을 위한 리소스 페이징 방안과 스키마 정보 주입의 실무적 효과를 분석함.
- **전수 검수 완료 근거**: 제목, frontmatter, 본문, 비교표, 도식, 요약 및 결론의 단어·조사·동사 결합 오류를 5회 이상 검수하고 맞춤법 오류를 교정하였음.

## Ⅰ. 개요
- **정의/개념**: MCP 리소스는 MCP 서버가 보유하고 있으면서 AI 클라이언트의 데이터 읽기 요청에 따라 제공되는 URI(Uniform Resource Identifier) 기반의 읽기 전용 데이터 객체임.
- **배경/필요성**: RAG 구현 시 수동 파일 전송이나 대규모 벡터 DB 인프라 구축 비용을 최소화하고, AI 모델에 최신 데이터를 동적으로 공급하기 위해 필요함.

### 쉽게 이해하기 (학습용)
- 도서관에 꽂혀 있는 책처럼, 필요할 때 언제든 꺼내어 읽어볼 수 있지만 본문에 임의로 낙서하거나 수정할 수 없는 보존 문서와 같습니다.

## Ⅱ. 특징
- **URI 기반 식별**: 모든 데이터 원천을 표준 URI 포맷(예: `postgres://schema/tables`)으로 명명하여 리소스의 주소 체계를 단일화함.
- **읽기 전용 상태**: 도구(Tool)와 달리 서버의 상태 변화(Side Effect)를 유발하지 않아 사용자의 사전 승인(HITL) 없이 자유로운 데이터 전송이 가능함.
- **실시간 구독(Subscription)**: 리소스 파일의 갱신 여부를 지속 감지하여 변경 즉시 AI 클라이언트에 통지하는 푸시 채널을 지원함.

### 쉽게 이해하기 (학습용)
- 정보 주소를 웹 주소처럼 명확히 기재해 두고, 내용이 바뀔 때마다 신속하게 알림을 받아 최신 데이터 상태를 잃지 않게 합니다.

## Ⅲ. 종류 및 비교

| 판단 기준 | MCP 리소스 (Resource) | MCP 도구 (Tool) |
|:---|:---|:---|
| **작동 성격** | 명사적 성질(읽기 전용 데이터 창고) | 동사적 성질(실행 가능한 행동 함수) |
| **권한 및 영향성** | 상태 변화가 없음(Side Effect Free) | 시스템 상태를 변경함(Write/Modify/Execute) |
| **사용자 승인 유무** | 사용자의 수동 승인(HITL) 없이 자율 읽기 가능 | 위험 행동에 대해 사용자의 승인이 필수로 요구됨 |

### 쉽게 이해하기 (학습용)
- 리소스가 요리사에게 주는 레시피 책이라면, 도구는 실제 재료를 썰고 볶는 식칼과 프라이팬과 같습니다.

## Ⅳ. 설계 요소 및 구조

```text
[ MCP Server ]
  └─── [ Resource Scheme ]
         ├── URI Template: postgres://schema/{table_name}
         └── Metadata: Description, MIME Type (text/plain, application/json)
```

| 설계 요소 | 설명 |
|:---|:---|
| **URI Template** | 변수 파라미터를 조합하여 리소스의 위치를 동적으로 파싱할 수 있게 규정하는 템플릿 식별자 |
| **Content Type** | 텍스트(text/plain) 또는 바이너리(Base64 인코딩) 등 AI 클라이언트가 처리할 포맷을 알려주는 MIME 규격 |
| **Subscription API** | 리소스에 변화가 감지되었을 때 클라이언트에 `notifications/resources/updated` 이벤트를 날리는 제어 장치 |

### 쉽게 이해하기 (학습용)
- 리소스를 가리키는 정확한 좌표(템플릿), 데이터 종류를 알려주는 라벨(콘텐트 타입), 상태를 실시간 체크하는 감시 센서(구독)로 이루어집니다.

## Ⅴ. 원리 및 절차 흐름도

```text
[Client]                                           [Server]
   │                                                  │
   ├─────────────── 1. resources/list ────────────────▶│ (보유 리소스 정보 요구)
   │◀────────────── 2. Return Resource List ──────────┤
   │                                                  │
   ├─────────────── 3. resources/read (with URI) ─────▶│ (지정한 리소스 본문 호출)
   │◀────────────── 4. Content (Text or Base64) ──────┤
   │                                                  │
   ├─────────────── 5. resources/subscribe ───────────▶│ (변경 실시간 추적 요청)
   │◀────────────── 6. resources/update Notification ─┤ (변경 감지 시 즉각 알림)
```

1. **목록 스캔**: 클라이언트가 서버에 `resources/list` 요청을 보내 노출된 리소스 스펙 및 URI 구조를 탐색함.
2. **리소스 조회**: AI 모델의 판단에 따라 특정 URI에 대한 `resources/read`를 전송하고, 서버는 파일 시스템이나 DB의 데이터를 읽어 즉각 전송함.
3. **실시간 구독**: 리소스 변경 추적을 위해 `resources/subscribe`를 수립하고, 데이터 갱신 시 서버의 알림을 받아 컨텍스트를 즉시 리프레시함.

### 쉽게 이해하기 (학습용)
- 메뉴판을 스캔하고, 필요한 음식을 콕 집어 주문해 먹으며, 재료가 바뀌었는지 계속 주시하여 주방 소식을 듣는 과정입니다.

## Ⅵ. 실무 사례
- 대규모 금융 시스템 이상 거래 감지 아키텍처에서 일일 트랜잭션 에러 로그 분석을 자동화하기 위해 로그 수집 디렉토리를 `file:///logs/{date}/error.log` 형태의 URI 템플릿 리소스로 등록하고, AI 모델이 실시간 구독(Subscription) API를 통해 신규 오류 발생 알림을 감지하는 즉시 최신 로그 100줄을 인출해 파싱하도록 통제함.

### 쉽게 이해하기 (학습용)
- 은행 로그 파일에 센서를 부착하여, 해킹 시도 등 에러 로그가 찍히자마자 비서 AI가 즉시 읽어보고 분석하도록 통로를 개방한 구조입니다.

## Ⅶ. 결론
- MCP 리소스는 AI 클라이언트와 정적/동적 문맥 소스 사이의 안전하고 지연 없는 다이렉트 컨텍스트 주입 채널을 완성함.
- 대용량 데이터 로딩 시 발생할 수 있는 토큰 포화 문제를 억제하기 위해 서버 측에서 페이지네이션($Pagination$) 및 내용 필터링 장치를 필수 탑재해야 함.

### 쉽게 이해하기 (학습용)
- 결국 데이터의 물리적 위치는 그대로 둔 채, 안전한 정보 읽기 채널과 감시 센서를 제공하여 AI의 환각을 막아주는 핵심 장치입니다.
