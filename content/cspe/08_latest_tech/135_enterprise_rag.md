# 📖 【암기용】 개념 완전 이해

> 목적: Enterprise RAG를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: 기업 내부 문서·DB·권한·감사 체계를 반영해 운영되는 업무용 RAG 아키텍처
- **왜 필요한가**: 기업 지식은 사내망, 권한, 최신 버전, 개인정보, 감사 요구와 연결되어 단순 RAG로는 운영하기 어려움.
- **핵심 직관**: 사내 문서 검색 챗봇에 권한, 출처, 보안, 품질관리, 운영 모니터링을 모두 붙인 생산 시스템임.

## 깊이 이해
- **배경·문제의식**: PoC RAG는 문서 몇 개로 동작하지만, 실제 기업은 수백만 문서, 부서별 권한, 중복 버전, 민감정보, SLA를 관리해야 한다.
- **작동 원리**: 문서 수집·정제·청킹·색인, 권한 필터, Hybrid Search, Reranker, Citation, Guardrail, 평가·모니터링을 하나의 운영 파이프라인으로 구성함.
- **비유**: 개인 책상 위 참고자료가 아니라, 회사 공식 문서관리·권한관리·감사 시스템과 연결된 지식 업무 플랫폼임.
- **구체 예시**: 100만 문서 RAG에서 tenant_id·ACL 필터, Milvus+Elasticsearch Hybrid, Faithfulness 0.9 게이트, 감사로그 90일 보관 적용.
- **흔한 오해·주의점**: 모델만 바꾸면 기업 RAG가 되는 것이 아님. 데이터 거버넌스와 권한 통제가 없으면 정보 유출 위험이 커짐.

## 연결 개념
- Permission-aware RAG — 사용자 권한을 검색 단계에 반영
- Private RAG — 사내망·폐쇄망에서 운영되는 RAG
- RAG Evaluation — 운영 품질을 지속 측정하는 평가 체계

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Enterprise RAG는 기업 데이터·권한·보안·감사·품질관리를 통합한 운영형 RAG임.
> 2. **가치**: 사내 지식 검색·업무 자동화에 최신 문서와 권한 기반 근거 답변을 제공함.
> 3. **판단 포인트**: 데이터 거버넌스, ACL 필터, 출처 기반 답변, 평가 게이트 없이는 운영 위험이 큼.

## Ⅰ. 개요 및 필요성

Enterprise RAG는 기업 운영 환경용 RAG 아키텍처임. 기업 문서는 권한·버전·민감정보·감사 요구와 연결된다. 단순 검색증강생성을 넘어 데이터 수집, 보안, 품질평가, 모니터링을 통합해야 한다.

## Ⅱ. 구조 및 구성요소

```text
Data Sources -> Ingestion/Chunking -> Index(BM25+Vector)
  -> ACL Filter -> Reranker -> LLM+Citation -> Guardrail/Monitoring
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Ingestion Pipeline | 문서 수집·정제·버전 관리 | DMS, Wiki, DB, PDF |
| Search Layer | Hybrid Search와 리랭킹 | Elasticsearch+Vector DB |
| Access Control | 사용자 권한 기반 필터링 | RBAC/ABAC, tenant_id |
| Governance Layer | 출처·평가·감사·보안 | citation, RAGAS, audit log |

> 요약: Enterprise RAG는 데이터 파이프라인, 검색 계층, 권한 통제, 거버넌스 계층을 통합한 운영 구조임.

## Ⅲ. 동작원리 및 흐름도

```text
문서 수집 -> 청킹/PII 처리 -> 색인 생성
  -> 사용자 질의+권한 확인 -> 검색/리랭킹
  -> 출처 기반 생성 -> 검증/로그 저장
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 문서 수집·정제·PII 마스킹 | PII 탐지율 ≥95% |
| 2 | BM25+Vector 색인과 버전 관리 | 색인 지연 <10분 |
| 3 | 사용자 ACL 기반 검색·리랭킹 | 권한 위반 문서 0건 |
| 4 | Citation 답변·평가·감사로그 저장 | Faithfulness ≥0.9, 로그 90일 |

> 요약: 기업 RAG는 문서 수집부터 권한 필터, 출처 답변, 품질 평가, 감사 기록까지 전 과정을 통제함.

## Ⅳ. 특징

| 구분 | PoC RAG | Enterprise RAG | 판단 포인트 |
|:---|:---|:---|:---|
| 데이터 | 소량 문서 | 수십만~수백만 문서 | 수집·버전 관리 필요 |
| 권한 | 미적용 | RBAC/ABAC 필터 | 정보 유출 방지 |
| 답변 | 텍스트 중심 | 출처·감사로그 포함 | 규제·감사 대응 |
| 운영 | 수동 평가 | 지표·SLA·모니터링 | 배포 게이트 필요 |

> 요약: Enterprise RAG는 PoC와 달리 권한, 출처, 평가, 감사 체계를 갖춘 운영 시스템으로 설계해야 함.

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 데이터 거버넌스: 문서 source_id, version, owner, ACL, retention을 메타데이터 표준으로 정의
2. 보안 검색: 검색 전 사용자 RBAC/ABAC를 벡터DB·검색엔진 양쪽 필터로 적용, 권한 위반 0건 검증
3. 운영 품질: Faithfulness 0.9, Context Recall 0.85, citation coverage 100%를 배포 게이트로 설정

**결론 (2줄):**
- 기술사 판단: 기업 RAG는 모델 과제가 아니라 데이터·권한·감사·평가를 포함한 아키텍처 과제임
- 향후 방향: Permission-aware RAG, Private RAG, Agentic Workflow와 결합해 업무 실행형 지식 플랫폼으로 발전
