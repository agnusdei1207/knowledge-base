## 미리 알고가기

- Enterprise RAG는 일반 데모형 RAG를 기업 보안과 운영 요구에 맞게 확장한 아키텍처임
- 핵심 축은 데이터 연결, 권한 통제, 품질 관리, 운영 자동화임
- 단순 답변 성능보다 최신성, 감사 가능성, 비용 통제가 함께 중요함

## Ⅰ. 개요

- **정의/개념**: Enterprise RAG는 기업 내부 문서와 시스템을 검색 기반 생성형 AI에 연결하되, 권한 제어와 최신성 관리와 품질 모니터링을 포함해 운영 환경에서 신뢰 가능하게 만든 RAG 아키텍처임
- **배경/필요성**: 일반 RAG는 파일 몇 개로는 동작해도 대규모 사내 데이터와 보안 정책과 감사 요구를 견디기 어려우므로, 기업형 구조와 운영 통제가 필요함

## Ⅱ. 특징

- 권한 인지 검색과 데이터 거버넌스를 통해 민감 정보 유출을 줄임
- 다수 시스템 연동과 지속 동기화를 전제로 해 최신성 관리가 필수임
- 평가 대시보드와 감사 로그를 포함해 운영 추적성이 높음
- 품질뿐 아니라 비용과 지연시간과 규제 준수까지 함께 관리해야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 일반 RAG | Enterprise RAG | Private RAG |
|:---|:---|:---|:---|
| 데이터 범위 | 제한적 문서셋 | 전사 시스템 연계 | 사내 폐쇄망 중심 |
| 보안 통제 | 기본 수준 | ACL, DLP, Audit 포함 | 최고 수준 |
| 운영 복잡도 | 낮음 | 높음 | 매우 높음 |
| 대표 용도 | PoC, 공개 서비스 | 기업 지식검색 | 금융, 국방, 공공 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Ingestion Pipeline | 위키, 파일, DB, 협업 도구를 수집해 정제와 청킹과 메타데이터 부착까지 수행하며 최신성 유지의 출발점이 됨 |
| Retrieval Layer | 벡터 검색과 키워드 검색과 리랭커를 결합해 정확도와 응답 속도 균형을 맞추며 ACL 필터를 함께 적용함 |
| Generation, Guardrail Layer | LLM과 prompt constraint와 citation 정책으로 답변을 만들고 민감 정보와 환각을 통제함 |
| Ops, Governance Layer | 평가 대시보드와 감사 로그와 비용 모니터링으로 운영 품질과 규제 준수 상태를 지속 검증함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 데이터 동기화   | --> | 권한 포함 검색 | --> | 근거 기반 생성 | --> | 감사/평가 운영 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **데이터 동기화**: 사내 문서와 시스템 데이터를 주기적으로 수집하고 갱신함
2. **권한 포함 검색**: 사용자 권한과 메타데이터를 반영해 허용된 문맥만 검색함
3. **근거 기반 생성**: 검색 문맥 안에서 답변을 생성하고 citation과 가드레일을 적용함
4. **감사 및 평가 운영**: 로그와 품질 지표를 분석해 정책과 파이프라인을 개선함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 사내 데이터 권한이 검색 단계에 반영되지 않으면 허용되지 않은 문서가 답변 근거로 노출되어 보안 사고가 발생할 수 있음
   - 해결방안: permission-aware retrieval과 IAM 연동을 적용하고 authorization miss rate와 audit issue count로 검증함
2. 문제: 문서 변경이 인덱스에 늦게 반영되면 오래된 규정과 매뉴얼을 근거로 잘못된 답변이 누적될 수 있음
   - 해결방안: CDC 기반 동기화와 stale index 감지를 적용하고 freshness lag와 stale answer rate로 검증함
3. 문제: 대규모 운영에서 평가와 서빙 비용이 동시에 증가하면 확장성보다 비용 통제가 먼저 한계에 부딪힐 수 있음
   - 해결방안: 계층형 모델 전략과 샘플링 평가와 캐시를 적용하고 cost per query와 p95 latency로 검증함

## Ⅶ. 적용 사례

- 제조기업 기술 문서 검색에서는 설계 기준서와 장애 이력을 연결하고 확인 지표는 first answer resolution과 citation accuracy임
- 금융권 사내 정책 챗봇에서는 권한별 규정 조회를 제공하고 확인 지표는 authorization miss rate와 hallucination rate임
- 고객지원 지식 어시스턴트에서는 CRM과 FAQ를 통합 조회하고 확인 지표는 handle time reduction과 CSAT임

## Ⅷ. 결론

Enterprise RAG는 단순 검색형 챗봇이 아니라 권한 통제와 최신성 관리와 품질 운영을 함께 갖춘 지식 인프라이므로, 보안과 거버넌스와 평가 체계를 먼저 설계해야 지속 가능한 운영이 가능함.
