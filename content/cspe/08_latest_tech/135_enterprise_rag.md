# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: 장난감 수준의 오픈소스 RAG(단순 문서 검색+답변)를 넘어, 대규모 데이터 처리, **엄격한 보안/권한 제어(ACL)**, 환각 통제, 그리고 끊김 없는 운영(CI/CD) 등 B2B 기업의 까다로운 잣대를 모두 통과할 수 있도록 무장한 **산업용(Production-ready) RAG 아키텍처**.
- **필요성**: 개발자가 노트북에서 PDF 10개 올려서 만든 RAG는 잘 됨. 하지만 이 시스템을 회사 전체에 배포하여 100만 개의 문서를 연결하는 순간, 평사원이 사장님 연봉 문서를 검색해 보거나 옛날 규정을 안내해 회사가 뒤집어지는 대참사가 발생함.
- **핵심 직관**: 레고 장난감 차(일반 RAG) vs 도로 주행 인증을 통과한 양산형 자동차(Enterprise RAG). 굴러가기만 해선 안 되고, 에어백(가드레일), 자물쇠(권한 통제), 네비게이션(출처 명시), 계기판(모니터링 대시보드)이 싹 다 달려 있어야 함.

## 깊이 이해
- **배경**: 생성형 AI 붐 이후 수많은 기업이 RAG 도입 PoC(개념 증명)를 진행했으나, 90%가 프로덕션(운영) 이관에 실패함. 원인은 보안(Security), 스케일아웃(Scalability), 데이터 거버넌스 부재 때문이었으며, 이를 극복하기 위한 엔터프라이즈 전용 표준 아키텍처가 정립됨.
- **작동 원리 (일반 RAG와의 3대 차이점)**:
  1. **데이터 연결(Ingestion)**: 단순히 파일을 올리는 게 아니라 사내 Confluence, Jira, ERP, DB와 API로 실시간 동기화됨 (버전 관리, 최신성 유지).
  2. **보안/권한 (ACL & Security)**: 사원이 "인사고과 기준"을 검색하면 평사원 기준만 검색되고, 임원이 검색하면 임원 기준 문서를 검색해 오는 **'사용자 맞춤형 권한 필터링(Permission-aware)'** 기술이 Vector DB단에 촘촘히 박혀 있음.
  3. **평가 및 모니터링 (LLMOps)**: 환각 차단을 위해 딥러닝 리랭커(Reranker)와 NeMo Guardrails 같은 방어벽이 2중 3중으로 깔려 있고, 사용자의 모든 질의와 AI의 답변은 감사(Audit)를 위해 로그로 남음.
- **구체 예시**: A은행 직원용 RAG. 일반 고객의 주민번호(PII 데이터)가 포함된 문서는 인덱싱 단계에서 마스킹(DLP) 처리되고, "부장" 직급 이상만 볼 수 있는 문서는 메타데이터로 태깅되어 검색 시 권한 필터를 통과해야만 LLM에게 주입됨.
- **흔한 오해/주의점**: "LLM 모델(GPT-4 등)만 제일 좋은 걸 쓰면 Enterprise RAG 아님?" 절대 아님! Enterprise RAG의 성패는 언어 모델의 성능보다 앞단에 있는 **데이터 엔지니어링(전처리, 권한 매핑, 파이프라인)**과 뒷단의 **LLMOps(평가 모니터링)**에 90% 이상 달려있음.

## 연결 개념
- **Permission-aware RAG (권한 인지 RAG)**: 사용자 직급이나 부서에 따라 Vector DB 검색 결과(문서 접근)를 제한하는 보안 핵심 기술.
- **Data Governance (데이터 거버넌스)**: 쓰레기 문서를 넣으면 쓰레기가 나오므로(GIGO), RAG에 태우기 전 문서의 라이프사이클과 품질을 관리하는 체계.
- **LLMOps**: Enterprise RAG를 지속적으로 모니터링하고, 평가(Ragas)하고, 프롬프트를 배포하는 운영 파이프라인.

# 📝 【답안용】 시험 답안 템플릿
## 핵심 인사이트 (3줄 요약)
- **본질**: 파편화된 기업 내부 사일로(Silo) 데이터를 연결하는 거대한 통합 인제스천(Ingestion) 파이프라인과, 엄격한 RBAC(역할 기반 접근 제어) 기반의 정보 검색, 그리고 Hallucination 통제 가드레일을 결합한 Production-grade AI 아키텍처.
- **가치**: 데이터 유출(Data Leakage) 및 권한 탈취 리스크를 원천 차단하면서 사내 지식 근로자의 생산성(Productivity)을 극대화하고, 폐쇄망(On-premise/VPC) 내에서 기업의 데이터 주권(Data Sovereignty)을 확립함.
- **판단 포인트**: 모델(LLM) 자체의 성능 고도화보다 메타데이터 엔지니어링을 통한 ACL(Access Control List) 매핑, 멀티모달 데이터 정제 기술, 그리고 실시간 품질 모니터링(LLMOps) 대시보드 구축 역량이 아키텍처 성공의 핵심 키 팩터임.

## Ⅰ. 개요 및 필요성
- **정의**: 기업의 복잡한 비즈니스 규칙, 엄격한 보안(Security & Compliance) 정책, 대용량 스케일 아웃(Scale-out) 요구사항을 완벽히 충족하도록 모듈화 및 최적화된 검색증강생성 시스템.
- **배경**: 초기 RAG(PoC 수준)는 단순 파일 업로드 및 정적 임베딩에 의존하여, 사내 문서 업데이트 지연, 권한 제어 불가로 인한 민감 정보 노출, LLM 환각 통제 불능 등의 한계로 상용화에 실패함.
- **필요성**: ISO 27001 등 기업 보안 표준을 준수하면서도, 최신 사내 지식을 실시간으로 동기화(Sync)하여 신뢰할 수 있는(Trustworthy) AI 비서를 전사적으로 배포하기 위함.

## Ⅱ. Enterprise RAG 아키텍처 구성 요소 (4 Layer)
일반 RAG 파이프라인에 보안/운영 계층이 대폭 보강됨.
| 아키텍처 계층 | 핵심 모듈 및 기능 | 기업 요구사항 매핑 |
|:---:|:---|:---|
| **1. Data Ingestion Layer** | 다양한 커넥터(Confluence, ERP), **문서 파싱(OCR)**, **개인정보 비식별화(DLP 마스킹)**, 버전 관리 파이프라인. | 데이터 최신성 동기화, 민감 정보(PII) 유출 원천 차단 |
| **2. Retrieval & Storage Layer**| Vector DB (Milvus, Qdrant), **하이브리드 검색(Dense+Sparse)**, **메타데이터 기반 ACL 필터링**. | 권한(RBAC)에 따른 철저한 문서 접근 제어, 검색 정확도 극대화 |
| **3. Generation Layer** | LLM, **Reranker(재정렬)**, **Citation(출처 명시) 엔진**, System Prompt 템플릿. | 환각 최소화, 근거 기반 답변(Fact-based) 제공 |
| **4. Guardrails & MLOps Layer**| 답변 필터링 룰 엔진(NeMo Guardrails), 감사 로그(Audit Trail) 저장소, RAG 평가 대시보드(Ragas/TruLens). | 응답의 법적 책임(Compliance) 회피, 지속적 시스템 품질 모니터링 |

## Ⅲ. 엔터프라이즈 핵심 챌린지 1: 보안 및 권한 제어 (ACL)
기업 RAG에서 가장 구현하기 까다롭고 중요한 요소임.
- **문제점**: 임원 연봉 계약서를 평사원이 검색해서 요약해버리는 사태 발생 가능성.
- **해결책: Permission-aware Retrieval (권한 인지 검색)**:
  1. 문서를 Chunking할 때 메타데이터 필드에 해당 문서의 접근 권한 식별자(예: `allowed_group: ["HR", "Executive"]`)를 주입하여 Vector DB에 저장.
  2. 사용자가 질의를 날릴 때, 기업 IAM/SSO 시스템에서 사용자의 권한 토큰 획득.
  3. Vector DB 쿼리 시, 코사인 유사도 연산 전에 메타데이터 필터링(Pre-filtering)을 걸어 권한 없는 문서는 아예 검색 공간에서 배제시킴.

## Ⅳ. 엔터프라이즈 핵심 챌린지 2: 최신성 및 데이터 거버넌스
- **문제점**: 회사 규정이 어제 바뀌었는데, RAG가 작년 규정 문서를 바탕으로 틀린 답을 제공함.
- **해결책: Continuous Data Synchronization (지속적 동기화)**:
  - CDC(Change Data Capture) 및 웹훅(Webhook)을 이용하여 사내 문서 관리 시스템(KMS)에 문서가 추가/수정/삭제될 때마다, 배치 스크립트가 돌아 해당 문서의 벡터만 핀포인트로 Vector DB에서 갱신 및 삭제(Tombstone 처리)하는 파이프라인(Airflow 등) 구축.

## Ⅴ. 배포 모델 선정 전략: Private vs Public
기업의 보안 규제 강도에 따라 LLM 위치 선정.
| 옵션 | 아키텍처 특징 | 장단점 및 추천 도메인 |
|:---:|:---|:---|
| **VPC 내 Private LLM** | 온프레미스 망 내에 오픈소스 모델(Llama 3, EEVE) 직접 호스팅 (vLLM 활용) | 완벽한 데이터 보안. 초기 구축/GPU 비용 높음. 국방/금융/공공기관 필수. |
| **Cloud Managed API** | Azure OpenAI 등 보안이 보장된 B2B 전용 프라이빗 클라우드 API 호출 | 운영 부담 최소화, 최고 성능. 클라우드 정책 허용 기업. |

## Ⅵ. 실무 적용 및 결론
- **판단 지표**: TCO(총 소유 비용), 질의 응답 지연 시간(P95 Latency), 권한 탈취 방어율, Ragas(Faithfulness 등) 품질 게이트 통과율.
- **실무 설계**: 대형 반도체 설계사 사내망 Enterprise RAG 구축. 기밀 유출 방지를 위해 폐쇄망(Air-gapped) 환경에 vLLM 서버 팜(GPU)과 Milvus Vector DB 클러스터를 구축함(Private RAG). LDAP 계정과 연동하여 1차 ACL 필터링을 걸고, 검색된 문서는 Cohere Reranker를 거쳐 하이라이팅 처리됨. 생성된 답변은 오픈소스 LlamaGuard를 거쳐 최종 팩트체크 후 사내 메신저로 전송. 구축 결과 보안 사고 Zero, 기존 매뉴얼 검색 시간 90% 단축 달성.
- **결론**: Enterprise RAG는 단순한 챗봇 도입 프로젝트가 아니라, 기업의 지식 자산을 AI가 읽을 수 있는 언어로 번역하고 거버넌스 체계를 재설계하는 전사적 '데이터 혁신(Digital Transformation) 인프라 구축' 사업이다.

### 🔀 문제 유형별 목차 전환
- **Ⅱ·Ⅲ 강조 (개념/원리형)**: RAG 파이프라인의 데이터 흐름도(ETL $\rightarrow$ Embedding $\rightarrow$ Retrieval $\rightarrow$ Generation), 메타데이터 사전/사후 필터링(Pre/Post-filtering) 메커니즘 비교 중심 서술.
- **Ⅴ·Ⅵ 강조 (실무/설계형)**: 멀티테넌시(Multi-tenancy) Vector DB 격리 아키텍처, FinOps 관점에서의 임베딩 캐싱(Semantic Cache) 및 LLMOps 품질 모니터링 자동화 전략 작성.
