# 📖 【암기용】 개념 완전 이해

> 목적: 에이전트 워크플로우를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: 에이전트 작업을 단계, 조건, 도구, 승인 흐름으로 정의한 실행 절차
- **왜 필요한가**: AI 업무는 무작위 대화가 아니라 반복 가능한 절차로 운영되어야 품질과 책임을 관리할 수 있음.
- **핵심 직관**: 워크플로우는 AI가 따라야 할 업무 프로세스 지도임.

## 깊이 이해
- **배경·문제의식**: 프롬프트만으로 업무 절차를 맡기면 단계 누락, 승인 누락, 결과 형식 불일치가 발생함.
- **작동 원리**: 입력, 단계, 조건분기, 도구호출, 승인, 실패처리, 출력 형식을 정의하고 Orchestrator가 실행함.
- **비유**: 제조 공정표처럼 원재료 투입부터 검사와 출하까지 단계와 기준을 정하는 구조.
- **구체 예시**: 장애 대응 Workflow는 감지, 로그수집, 원인분석, 조치제안, 승인, 실행, 사후보고 단계로 구성됨.
- **흔한 오해·주의점**: Workflow는 모델 자유도를 줄이는 것이 아니라 반복 업무의 품질과 감사 가능성을 확보하는 장치임.

## 연결 개념
- Agent Orchestration — Workflow 실행 제어
- BPMN — 업무 프로세스 모델링
- Runbook Automation — 운영절차 자동화

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Agent Workflow는 AI 업무를 단계·분기·도구·승인·출력 형식으로 정의한 실행 절차임.
> 2. **가치**: 반복 업무의 품질 편차, 단계 누락, 승인 누락, 감사 공백을 줄임.
> 3. **판단 포인트**: 업무유형별 Workflow, 예외처리, 실패복구, 승인 기준, 변경관리를 함께 설계해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| AI 업무 절차화 설계 역량 | 단계·분기·승인·예외처리·출력 schema 정의 | 프롬프트만으로 절차 대체 가능하다고 서술하면 감점 |
| 운영 품질 관리 구조 이해 | Workflow 버전관리, 성공률·실패단계 지표, 변경관리 | 자유형 Agent와의 차이(단계 누락률·품질 편차)를 짚지 않으면 감점 |

> 요약: 출제자는 AI 업무를 재현 가능한 절차로 설계하고 운영 품질을 지표로 관리하는 역량을 확인하려 함.

---

## Ⅰ. 개요 및 필요성

- 정의: AI 업무를 단계·분기·도구·승인·출력 형식으로 정의한 실행 절차
- 배경: 프롬프트만으로 업무를 맡기면 단계 누락·승인 누락·결과 형식 불일치 발생
- 필요성: 반복 업무의 품질 편차, 감사 공백을 줄이려면 재현 가능한 Workflow 정의 필수

---

## Ⅱ. 구조 및 구성요소

```text
Input -> Step 1 -> Condition -> Tool/Agent -> Approval -> Output
           |           |             |              |
           +-> 처리단계  +-> 분기       +-> 실행단위    +-> 승인/기록
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Input Schema | 요청 형식 정의 | 필수값·검증규칙 |
| Step | 처리 단계 | Agent, Tool, Human Task |
| Condition | 분기 기준 | 위험도, 오류, 점수 |
| Output Schema | 결과 형식 | 보고서, JSON, 티켓 |

> 요약: Agent Workflow는 입력, 단계, 분기, 실행단위, 출력 형식으로 AI 업무를 정의함.

---

## Ⅲ. 동작원리 및 흐름도

```text
요청 접수 -> Workflow 선택 -> 단계 실행 -> 조건 분기
        -> 승인/재시도 -> 결과 생성 -> 이력 저장
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | Workflow 선택 | 업무유형, 위험등급 |
| 2 | 단계별 실행 | 입력검증, 응답코드 |
| 3 | 분기·예외 처리 | 조건식, 재시도 횟수 |
| 4 | 출력·기록 | schema, Trace ID, 승인 |

> 요약: Agent Workflow는 단계 실행 결과에 따라 분기하고 최종 산출물을 표준 형식으로 남김.

---

## Ⅳ. 특징

| 구분 | 자유형 Agent | Agent Workflow | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 절차 | 모델 판단 중심 | 단계·분기 명시 | 단계 누락률 |
| 품질 | 결과 편차 발생 | 출력 형식 표준화 | schema 통과율 |
| 통제 | 사후 로그 중심 | 승인·예외 내재화 | 승인 누락 건수 |

> 요약: Workflow는 Agent 자유도를 업무 절차 안에 배치해 운영 품질을 관리함.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 자유형 Agent | Agent Workflow | 선택 기준 |
|:---|:---|:---|:---|
| 절차 통제 | 모델 자율 판단 | 단계·분기·승인 명시 | 업무 반복성과 위험도 |
| 품질 편차 | 실행마다 결과 상이 | 출력 schema 표준화 | schema 통과율 95% 이상 |
| 변경 관리 | 프롬프트 수정 즉시 반영 | Workflow 버전관리·승인 후 배포 | 변경 영향 범위 |

> 요약: 반복·고위험 업무는 Workflow로, 탐색·창작 업무는 자유형 Agent로 분기함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 단계 누락 | Workflow 정의 불완전 | Step별 입력·출력 검증, 필수 단계 체크 | 단계 누락률 0% |
| 예외 미처리 | 분기 조건 미정의 | timeout·retry·fallback·에스컬레이션 명시 | 예외 미처리 건수 |
| 버전 충돌 | 무관리 수정 배포 | Git 기반 Workflow 버전관리, 승인 후 배포 | 무승인 변경 건수 0건 |

> 요약: 단계 누락·예외 미처리·버전 충돌이 핵심 리스크이며 검증·fallback·버전관리로 통제함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 성공률 | task success rate 90% 이상 | Workflow 실행이력 대시보드 |
| 실패 단계 분포 | 특정 Step 집중 실패 식별 | 실패 Step 히트맵 주간 분석 |
| 평균 처리시간 | 업무별 SLA 내 완료 | p95 처리시간 모니터링 |

> 요약: 성공률, 실패 단계 분포, 처리시간을 지표로 Workflow 품질을 관리함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 장애대응, 고객응대, 보안조치 등 업무별 Workflow를 정의하고 변경관리 절차를 적용
2. Step별 입력·출력 schema, timeout, retry, approval, rollback 조건을 명시
3. Workflow 버전, 실행 이력, 성공률, 실패 단계, 평균 처리시간을 지표로 관리

**결론 (2줄):**
- 기술사 판단: 반복 가능한 업무는 Workflow화하고 예외적 판단 업무는 사람 검토 단계로 분기함.
- 향후 방향: Agent Workflow는 BPM, Runbook Automation, LLMOps가 결합된 AI 업무 운영 표준으로 발전함.
