# 📖 【암기용】 개념 완전 이해

> 목적: ML-DSA를 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 양자컴퓨터가 나와도 위조할 수 없도록 설계된 차세대 '전자서명' 표준 기술 (구 Dilithium)
- **왜 필요한가**: 우리가 온라인 쇼핑을 하거나 정부 문서에 서명할 때 쓰는 기존 기술(RSA, ECDSA)은 양자컴퓨터가 나오면 공격자가 내 서명을 똑같이 흉내 낼 수 있기 때문
- **핵심 직관**: "양자 시대의 위조 방지 인감도장" — 복잡한 격자 수학 문제를 이용해 서명을 만듦으로써, 양자컴퓨터도 가짜 서명을 만들어내지 못하게 하는 것

## 깊이 이해
- **배경·문제의식**: 미국 표준기술연구소(NIST)가 선정한 양자내성암호(PQC) 표준 중 하나로, '서명' 분야에서 가장 균형 잡힌 성능을 보여준 'Dilithium' 알고리즘의 공식 표준 명칭임.
- **작동 원리**: 'Fiat-Shamir with Aborts' 기법과 '모듈 격자(Module-Lattice)' 난제를 결합함. 서명을 만들 때 아주 복잡한 격자 수식을 풀고, 그 결과가 너무 많은 정보를 노출하면(보안 위험) 다시 시도하는 방식을 반복함. 이를 통해 서명 값만 봐서는 개인키를 알아낼 수 없게 만듦.
- **비유**: 인감을 찍을 때 아주 미세한 패턴이 있는 고차원 격자 도장을 사용하는데, 도장을 찍을 때마다 패턴이 조금씩 달라지지만(노이즈) 진짜 주인이 찍었다는 것은 증명할 수 있는 신기한 도장과 같음.
- **구체 예시**: 소프트웨어 업데이트 파일을 배포할 때, 이 파일이 진짜 제조사가 만든 것인지 확인하는 용도로 ML-DSA 서명이 사용됨.
- **흔한 오해·주의점**: '키 교환'용인 ML-KEM과는 짝궁이지만 용도가 다름. ML-DSA는 "이 문서를 내가 썼다"는 것을 증명하는 '서명' 전용임.

## 연결 개념
- FIPS 204 — ML-DSA의 공식 표준 번호
- Fiat-Shamir with Aborts — ML-DSA의 핵심 서명 메커니즘
- CRYSTALS-Dilithium — ML-DSA의 모태가 된 알고리즘 명칭

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 모듈 격자 기반의 'Fiat-Shamir with Aborts' 서명 프로세스와 기존 알고리즘 대비 성능 효율성을 기술한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: NIST가 FIPS 204로 표준화한 격자 기반 양자내성 전자서명 알고리즘으로, 양자 컴퓨팅 공격에 대해 인증 및 부인방지를 제공한다.
> 2. **가치**: 기존 Dilithium 알고리즘을 기반으로 하며, 서명 생성 및 검증 속도가 매우 빠르고 서명 크기가 합리적이어서 범용적인 전자서명 시스템에 적합하다.
> 3. **판단 포인트**: 'Module-LWE'와 'Module-SIS' 난제의 결합을 통한 보안 강도와 서명 오버헤드 간의 트레이드오프 조율이 핵심이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| ML-DSA의 정의 및 표준 지위 확인 | NIST FIPS 204, Dilithium 기반, PQC 서명 표준 | ML-KEM(키 교환)과 용도 혼동 |
| 핵심 메커니즘 파악 역량 | Fiat-Shamir with Aborts, 모듈 격자 난제 | 단순 격자 암호로만 서술하고 서명 절차 누락 |
| 성능 및 활용성 판단 능력 | 서명/공개키 크기, 검증 속도, 범용성 | RSA 대비 커진 키 크기만 강조하고 속도 장점 간과 |

> 요약: ML-DSA는 격자 기반 난제를 활용하여 '인증'과 '부인방지'를 보장하는 차세대 표준 서명 기술이다.

## Ⅰ. 개요 및 필요성

- 정의: 모듈 격자 상의 수학적 난제를 기반으로 설계된, 양자 컴퓨터 공격에 저항성을 가진 NIST 표준 전자서명 알고리즘 (FIPS 204)
- 배경: 쇼어 알고리즘 기반 양자 공격에 의한 현행 RSA/ECDSA 전자서명 체계의 위조 가능성 및 신뢰성 붕괴 위기
- 필요성: 보안 통신(TLS) 내 서버 인증, 소프트웨어 코드 사이닝(Code Signing), 장기 보존 전자문서의 무결성 보장

## Ⅱ. 구조 및 구성요소

```text
[ ML-DSA Components ]
        |
  +-----v-----------------------------------+
  | Module-LWE & Module-SIS Hardness Problems | -> 보안의 수학적 근거
  +-----+-----------------------------------+
        |
  +-----v-----------+      +--------v----------+      +--------v---------+
  | Key Generation  |      |     Signing       |      |   Verification   |
  | (PK, SK 생성)   |      | (서명값 생성/거부) |      | (서명 유효성 검증)|
  +-----------------+      +-------------------+      +------------------+
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| ML-LWE / ML-SIS | 격자 기반의 학습 오차 및 짧은 정수 해 찾기 난제 | 양자 저항성의 핵심 |
| Fiat-Shamir with Aborts | 서명 과정에서 정보 유출 위험 시 작업을 취소하고 재시도하는 기법 | 보안성 및 효율성 확보 |
| Public Key (PK) | 서명 검증 시 사용되는 공개 격자 벡터 | 약 1.3KB ~ 2.5KB |
| Signature (σ) | 데이터의 무결성과 송신자 신원을 증명하는 값 | 약 2.4KB ~ 4.6KB |

> 요약: 격자 난제 위에서 Fiat-Shamir 기법을 활용하여 안전하고 빠른 서명 생성을 가능케 한다.

## Ⅲ. 동작원리 및 흐름도

```text
PK/SK 생성 -> 메시지 해싱 -> 서명 후보 생성 -> 보안 검사(Reject/Abort) -> 서명 확정 -> 검증 수행
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | Key Generation | 모듈 격자 구조 내에서 짧은 벡터들을 선택하여 PK와 SK 쌍 생성 | 다항식 계수 범위 준수 |
| 2 | 서명 시도 (Commit) | 임의의 벡터를 선택하여 메시지와 결합하고 서명 후보(c, z) 생성 | 무작위성 확보 |
| 3 | Abort 체크 | 생성된 서명이 개인키 정보를 유출할 가능성이 있는지 범위를 체크 | 유출 위험 시 2단계 재수행 |
| 4 | 서명 전송 | 보안 검사를 통과한 서명값(σ)을 메시지와 함께 수신자에게 전달 | 서명 크기 준수 |
| 5 | 서명 검증 | 공개키를 이용해 서명 수식이 격자 내의 유효한 범위에 있는지 확인 | 수학적 일치성 검증 |

> 요약: 서명 과정에서 정보 유출을 막기 위해 '부적절한 서명은 스스로 폐기하고 다시 만드는(Abort)' 과정을 반복한다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존 ECDSA (Elliptic Curve) | ML-DSA (Post-Quantum) | 선택 기준 |
|:---|:---|:---|:---|
| 서명 크기 | 매우 작음 (약 64 Bytes) | 큼 (약 3.3KB) | 통신 대역폭 및 패킷 크기 제약 |
| 서명 생성 속도 | 보통 | 매우 빠름 | 서버 측 대규모 서명 처리량 |
| 서명 검증 속도 | 느림 (연산 부하) | 매우 빠름 | 클라이언트 측 검증 자원 제약 |
| 보안 근거 | 이산대수 문제 (양자 취약) | 격자 난제 (양자 내성) | 장기적 보안 신뢰성 확보 필요 시 |

> 요약: 키/서명 크기는 수십 배 커지나, 연산 속도가 압도적으로 빨라 고속 인증 환경에 유리하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 통신 오버헤드 | 서명 크기 증가로 인한 인증서 체인(Chain) 비대화 | 인증서 압축 기술 적용, 인증 단계 최적화 | TLS 핸드셰이크 지연 시간 |
| 서명 가변 시간 | Abort 발생 횟수에 따라 서명 생성 시간이 달라짐 | 평균 시도 횟수(약 4~7회) 내 최적화 | 서명 생성 시간 분산(Variance) |
| 하드웨어 가속 부재 | 기존 CPU의 가속 명령 집합 미지원 | AVX2/AVX-512 등 벡터 연산 최적화 구현 | CPU 점유율 및 처리 효율 |

> 요약: 큰 서명 크기에 따른 네트워크 지연은 프로토콜 최적화로, 가변 연산 시간은 고성능 벡터 연산으로 대응해야 한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 검증 성공률 | 유효한 서명에 대해 100% 성공 | 단위 테스트 및 호환성 테스트 |
| 초당 서명 수 | 서버급 하드웨어 기준 10,000 TPS 이상 | 부하 테스트 (Load Test) |
| 보안 강도 검증 | NIST 파라미터 정합성 여부 | 공식 테스트 벡터 검증 |

> 요약: 도입 성과는 빠른 검증 속도와 표준 규격 준수 여부로 평가한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 차세대 PKI 인증서 적용: SSL/TLS 인증서의 서명 알고리즘을 ML-DSA로 전환하여 웹 브라우저와 서버 간 양자 내성 인증 체계 구축
2. 안전한 SW 업데이트(Code Signing): 배포되는 펌웨어나 앱에 ML-DSA 서명을 부여하여 양자 컴퓨터를 이용한 악성코드 변조 원천 차단
3. 전자문서 장기 보존 서비스: 공공/금융 기록물에 ML-DSA 서명을 적용하여 향후 수십 년 뒤 양자 시대에도 문서의 진본성을 입증 가능케 함

**결론 (2줄):**
- 기술사 판단: ML-DSA는 양자 내성 서명의 '사실상 표준(De facto standard)'이며, 속도 면에서의 이점 덕분에 기존 RSA를 빠르게 대체할 것이다
- 향후 방향: 하드웨어 보안 토큰이나 스마트카드 등 자원 제약 기기에서도 효율적으로 동작하도록 최적화 기술이 집중될 전망이다
