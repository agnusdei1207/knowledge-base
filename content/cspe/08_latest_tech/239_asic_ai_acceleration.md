# 📖 【암기용】 개념 완전 이해

> 목적: ASIC AI 가속을 특정 AI 연산에 맞춘 고정 회로 설계와 대량 추론 경제성 관점에서 이해하게 만든다.

## 한눈에
- **개요**: 행렬곱, 컨볼루션, attention 같은 AI 연산을 고정 회로로 구현한 전용 가속 방식
- **왜 필요한가**: 대규모 AI 서비스는 같은 추론 연산을 수억 회 반복하므로 범용성보다 연산당 전력, 칩 단가, 지연시간이 더 큰 판단 기준이 된다.
- **핵심 직관**: 자주 쓰는 공정만 수행하는 자동화 설비를 별도로 제작해 반복 작업의 비용과 전력을 낮추는 방식이다.

## 깊이 이해
- **배경·문제의식**: GPU는 범용 병렬 연산에 강하지만, 데이터센터 추론처럼 연산 패턴이 고정된 업무에서는 불필요한 제어 로직과 범용성이 전력·면적 비용으로 남는다.
- **작동 원리**: ASIC은 RTL 설계, 합성, 배치·배선, 검증, tape-out, 파운드리 양산을 거쳐 데이터패스와 메모리 계층을 연산에 맞게 고정한다.
- **비유**: 범용 공구함 대신 특정 나사 규격만 조이는 자동 장비를 만든 것과 같다.
- **구체 예시**: TPU 계열은 systolic array 기반 행렬곱을 중심으로 INT8/BF16 정밀도와 온칩 SRAM을 조합해 추론·학습 처리량을 확보한다.
- **흔한 오해·주의점**: ASIC은 제작 후 회로 변경이 불가능하므로 알고리즘 변경, 표준 정밀도 변경, 설계 버그가 생기면 리스핀 비용과 12개월 이상 일정 지연이 발생할 수 있다.

## 연결 개념
- TPU — ASIC AI 가속기의 대표 사례
- FPGA AI Acceleration — 재구성 가능하지만 전력·면적 오버헤드가 있는 대안
- Chiplet — ASIC 블록 재사용과 이종 통합으로 NRE 부담을 줄이는 접근

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.
> 핵심: ASIC AI 가속은 최고 처리량보다 워크로드 고정성, NRE 회수 물량, 리스핀 리스크를 함께 판단해야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: ASIC AI Acceleration은 AI 연산 데이터패스를 고정 회로로 제작해 연산당 전력과 지연시간을 낮추는 방식임.
> 2. **가치**: 대량 추론에서는 높은 NRE를 물량으로 회수하고 칩당 단가와 perf/W를 개선함.
> 3. **판단 포인트**: 알고리즘 안정성, 예상 물량, tape-out 리스크가 ASIC 채택의 핵심 기준임.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| AI 전용 반도체 구조 이해 확인 | systolic array, 온칩 SRAM, 정밀도 고정 | ASIC을 단순 고속 GPU로 설명 |
| 경제성 판단 확인 | NRE, mask cost, BEP 물량 | 대량 생산 조건 없이 단가 절감만 서술 |
| 리스크 인식 확인 | 리스핀, 설계 검증, 알고리즘 변화 | 제작 후 재구성 가능하다고 서술 |

> 요약: ASIC 문제는 전용 회로의 전력·단가 이점과 NRE·리스핀 리스크의 균형 판단을 요구한다.

## Ⅰ. 개요 및 필요성

- 개요: AI 연산 전용 고정 회로 가속
- 배경: GPU의 범용 제어 로직은 고정 추론 워크로드에서 전력·면적 오버헤드가 됨.
- 필요성: QPS 수십만 이상 추론 서비스는 INT8/BF16 연산당 전력, p95 지연시간, 칩당 단가를 동시에 낮춰야 함.

---

## Ⅱ. 구조 및 구성요소

```text
Model Workload -> RTL Datapath -> Systolic Array / MAC Array -> On-chip SRAM
               -> Memory Controller -> Tape-out -> Foundry -> AI Inference ASIC
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Systolic Array | 행렬곱을 데이터 재사용 구조로 처리 | TPU 유형의 핵심 연산 구조 |
| On-chip SRAM | 가중치·activation 임시 저장 | DRAM 접근 감소 |
| Fixed Precision Unit | INT8, BF16 등 연산 정밀도 처리 | 설계 시점에 지원 범위 고정 |
| Verification Flow | RTL, gate, timing 검증 | tape-out 전 결함 발견 필요 |

> 요약: ASIC AI 가속기는 연산 배열, 온칩 메모리, 정밀도 회로를 고정해 반복 AI 연산에 맞춘 데이터 경로를 구성한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
워크로드 분석 -> 연산 정밀도 확정 -> RTL 설계 -> 합성·배치·배선
-> 시뮬레이션·에뮬레이션 검증 -> tape-out -> 양산 -> 추론 서빙 투입
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 목표 모델의 행렬곱·메모리 패턴 분석 | 연산 커버리지 95% 이상 |
| 2 | 데이터패스와 정밀도를 RTL로 고정 | timing closure 달성 |
| 3 | tape-out 전 기능·전력·열 검증 | RTL coverage, power estimate |
| 4 | 양산 칩을 서빙 클러스터에 배치 | p95 latency, perf/W |

> 요약: ASIC은 모델 요구를 하드웨어 회로로 고정한 뒤 검증과 양산을 거쳐 반복 추론에 투입된다.

## Ⅳ. 특징

| 구분 | GPU/FPGA 대안 | ASIC AI 가속 | 수치·판단 기준 |
|:---|:---|:---|:---|
| 범용성 | GPU는 CUDA 생태계, FPGA는 bitstream 재구성 | 회로 제작 후 기능 고정 | 알고리즘 변경 주기 12개월 이상일 때 적합 |
| 비용 구조 | 초기 비용 낮음, 장치 단가 높음 | NRE 높음, 대량 생산 시 단가 하락 | BEP 물량 산정 필요 |
| 전력·지연 | 범용 제어 오버헤드 존재 | 고정 데이터패스로 연산당 전력 감소 | perf/W, p95 latency로 검증 |
| 출시 일정 | GPU 구매, FPGA 재구성으로 대응 | 설계·검증·tape-out 12~24개월 | time-to-market 제약 확인 |

> 요약: ASIC은 고정 워크로드와 대량 물량에서 전력·단가 이점을 얻지만 출시 일정과 회로 고정성이 제약이다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | GPU 범용 SM, FPGA LUT | ASIC 고정 MAC array | 모델 연산 패턴 고정성 |
| 비용/성능 | 낮은 초기비용, 높은 전력 | 높은 NRE, 낮은 연산당 전력 | 3년 TCO와 BEP 물량 |
| 운영/위험 | 소프트웨어 업데이트로 대응 | 리스핀 필요 | 알고리즘 변경 빈도 |

> 요약: 물량이 크고 모델 연산이 고정되면 ASIC, 모델 변화가 잦으면 GPU 또는 FPGA가 적합하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| NRE 회수 실패 | 예상 QPS·판매 물량 미달 | BEP 산정, 단계별 양산 계약 | 누적 출하량, 칩당 원가 |
| 리스핀 발생 | RTL 결함 또는 timing 위반 | FPGA 프로토타입, formal verification | tape-out 전 결함 발견율 |
| 모델 변화 미지원 | 신규 연산·정밀도 미탑재 | programmable microcode, fallback GPU 경로 | 미지원 op 비율 |

> 요약: ASIC 리스크는 물량, 검증, 모델 변화이며 BEP·coverage·미지원 op 지표로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 처리량 | 목표 QPS 대비 120% capacity | load test, inference benchmark |
| 전력 | tokens/J 또는 TOPS/W 목표 | 전력 계측, rack telemetry |
| 품질 | INT8/BF16 정확도 손실 1%p 이내 | golden output 비교 |

> 요약: ASIC 도입 성과는 처리량, 전력, 정밀도별 정확도 손실을 함께 측정해야 한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 대량 추론 서비스는 3년 누적 QPS와 BEP 물량을 산정한 뒤 ASIC 전환 여부를 결정함.
2. tape-out 전 FPGA prototype, RTL simulation, emulation으로 미지원 op와 timing risk를 제거함.
3. 모델 변화에 대비해 GPU fallback 경로와 세대별 ASIC roadmap을 함께 설계함.

**결론 (2줄):**
- 기술사 판단: 워크로드가 고정되고 물량이 충분하면 ASIC, 모델 변화와 일정 리스크가 크면 GPU/FPGA를 선택함.
- 향후 방향: ASIC은 chiplet, HBM, CXL과 결합해 AI 데이터센터의 전용 가속 노드로 확장됨.
