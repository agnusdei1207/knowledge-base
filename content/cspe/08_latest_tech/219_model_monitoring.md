# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: 운영 환경에 무사히 배포된 인공지능(ML) 모델이, 시간의 흐름과 현실 세계의 변화 속에서도 원래 설계된 대로 **'정확한 예측'을 하고 있는지, 들어오는 '데이터가 썩지 않았는지'를 실시간으로 감시하고 평가하는 품질 관제 레이어**.
- **필요성**: 코드로 짠 일반 소프트웨어는 버그를 고쳐 놓으면 10년 뒤에도 똑같이 동작함. 하지만 AI 모델은 '과거의 데이터'로 세상을 배운 존재임. 시간이 흘러 유행이 바뀌고 경제가 변하면, 모델의 머릿속 지식(가중치)과 현실 세계 사이에 괴리가 생겨 성능이 우하향하는 '모델 퇴화(Model Decay)'가 무조건 발생함. 이를 방치하면 회사는 소리 없이 막대한 돈을 잃게 됨.
- **핵심 직관**: 공장의 정밀 '품질 검사기(QC)'. 자동차를 잘 만들어서 출고(배포)했더라도, 고객이 1년, 5년 타면서 타이어가 마모되고 엔진오일이 오염(데이터 변화)됨. Model Monitoring은 주행 중인 차의 타이어 상태와 연비를 실시간 센서로 감시하다가, "위험 수준이다. 곧 사고 난다!" 판단되면 즉시 '정비소 입고 알람(재학습 트리거)'을 울려주는 스마트 진단기임.

## 깊이 이해
- **배경**: AI 모델을 성공적으로 운영 서버에 띄우는 것(배포)은 끝이 아니라 시작임. 코로나19가 터지자 과거 패턴으로 학습된 전 세계 은행의 신용평가 모델과 아마존의 재고 예측 모델 성능이 완전히 붕괴함. 에러 메시지도 띄우지 않고 조용히 엉뚱한 답을 내놓는 '소리 없는 실패(Silent Failure)'의 무서움이 대두되며 모델 성능 추적의 중요성이 폭발함.
- **작동 원리 (3대 감시 영역)**:
  1. **시스템 모니터링 (IT 인프라)**: CPU, 메모리, API 응답 속도(Latency). 이건 기존 IT 관제랑 똑같음. (서버가 죽었나?)
  2. **데이터 모니터링 (Data/Feature Drift)**: 입력으로 들어오는 유저의 데이터 패턴이 평소와 다른가? (예: 평소엔 20대가 주로 들어왔는데, 갑자기 60대 고객이 폭증하면 모델은 당황함).
  3. **모델 성능 모니터링 (Performance/Concept Drift)**: 실제 예측값과 나중에 밝혀진 '정답(Ground Truth)'을 비교해 정확도(Accuracy), 오차율을 계산. 모델의 예측 자체가 틀리기 시작했나를 검증.
- **구체 예시**: 넷플릭스 영화 추천 모델. 작년에 '로맨스' 영화를 주로 추천하게 훈련시켜 배포함. 그런데 1년 뒤 갑자기 사람들이 'SF 좀비물'만 검색하기 시작함(Data Drift). 여전히 로맨스만 띄우는 모델 때문에 사용자 클릭률(정확도)이 곤두박질침(Concept Drift). 모니터링 대시보드가 이를 감지해 빨간불을 켜고, MLOps 파이프라인이 최신 좀비물 검색 데이터를 가져와 자동으로 모델을 재학습(Retraining)시켜 교체함.
- **흔한 오해/주의점**: "일반 APM(Datadog, 엑셈) 깔아서 서버 살아있는지 보면 되는 거 아님?" $\rightarrow$ 최악의 오해. 딥러닝 모델은 서버 CPU가 10%로 널널하고 200 OK를 반환하면서도, 내용은 100% 헛소리(환각, 오답)를 뱉어낼 수 있음. 따라서 소프트웨어가 아니라 '데이터의 통계적 분포'를 수학적으로 검시해야 함.

## 연결 개념
- **Data Drift (데이터 표류)**: 모니터링이 잡아야 할 제1 타겟. 입력 데이터($X$)의 분포가 변하는 현상. (정답 확인 없이 입력만으로 징후 포착 가능).
- **Concept Drift (컨셉 표류)**: 제2 타겟. 세상의 규칙(정답, $Y$) 자체가 변하는 현상. (예: 인플레이션으로 1만 원의 가치가 달라짐). 가장 치명적인 성능 저하 원인.
- **Feedback Loop (환류/재학습 루프)**: 모니터링이 알람을 울리면 $\rightarrow$ 다시 학습 단계(Continuous Training)로 돌아가는 뫼비우스의 띠. MLOps를 완성하는 마지막 퍼즐.

# 📝 【답안용】 시험 답안 템플릿
## 핵심 인사이트 (3줄 요약)
- **본질**: 상용 환경(Production)에 배포된 머신러닝 모델을 대상으로 시스템 건전성(Health), 입력 데이터의 통계적 이질성(Drift), 그리고 최종 예측 성능(Accuracy/F1)의 퇴화(Decay) 여부를 지속 관측하는 품질 제어 루프.
- **가치**: 코드 버그가 아닌 데이터/환경 변화로 인해 발생하는 '소리 없는 실패(Silent Failure)'를 시스템 에러 발생 전에 조기 탐지(Early Detection)하여, 비즈니스 손실(오판)을 막고 최적의 '모델 재학습(Retraining)' 시점을 수학적 근거 기반으로 도출함.
- **판단 포인트**: 완전한 모델 성능 모니터링은 실제 정답(Ground Truth/Label)이 확보되어야 하나, 실무에서는 정답 확보 지연(Label Lag) 문제가 존재하므로, 정답 없이도 통계적 기법(PSI, KS-test)으로 산출 가능한 **데이터 드리프트(Data Drift)를 사전 대리 지표(Proxy Metric)로 활용하는 이중 감시 체계** 설계가 핵심임.

## Ⅰ. 개요 및 필요성
- **정의**: 기계학습 모델 배포 이후, 운영 데이터의 입력 파이프라인부터 예측(Inference) 결과물까지 전 영역에 걸쳐 이상치(Anomaly), 편향(Bias), 분포 변화를 정량 추적하고 관측성(Observability)을 제공하는 MLOps 인프라.
- **배경**: AI 모델은 "학습 데이터와 운영 데이터가 동일한 분포를 가진다(IID 가정)"는 전제로 작동하지만, 거시 경제 변화, 계절성, 유저 행동 변화에 의해 이 가정이 필연적으로 붕괴함(Model Staleness).
- **필요성**: 모델 수명 단축에 선제 대응, 신뢰할 수 없는 예측으로부터 다운스트림(Downstream) 비즈니스 보호, 맹목적인 주기적 재학습(예: 무조건 매일 학습)이 야기하는 불필요한 GPU 클라우드 과금 낭비 방지.

## Ⅱ. Model Monitoring의 3계층(Tier) 텔레메트리 아키텍처
인프라에서 통계까지 전방위 관측.
| 계층 (Tier) | 관측 대상 및 핵심 메커니즘 | 주요 수집 지표 (Metrics) |
|:---:|:---|:---|
| **Tier 1: System / IT**<br>(서비스 건전성) | 모델 서빙 API 컨테이너(K8s 등)의 인프라 상태와 트래픽 부하 감시. | CPU/MEM 점유율, P99 Latency(지연), 4xx/5xx 에러율, Throughput(TPS). |
| **Tier 2: Data / Drift**<br>(통계적 분포성) | 서빙 중인 실시간 입력 특성(Feature)과 예측 결과(Prediction)의 수학적 분포(Distribution)가 학습 당시(Baseline)와 대비해 틀어졌는지 검정. | 결측치(Null) 비율, **PSI (Population Stability Index)**, KS 검정 지표. |
| **Tier 3: Performance**<br>(비즈니스 정확도)| 실제 정답(Ground Truth)이 피드백 시스템을 통해 수집된 후, 모델 예측값과 매핑하여 모델 자체의 품질과 오차 측정. | Accuracy, F1-Score, RMSE, Precision/Recall, 비즈니스 ROI. |

## Ⅲ. 정답 지연(Label Lag) 환경 극복 모니터링 워크플로우
정답을 모를 때도 모델의 타락을 눈치채는 법.
1. **Label Lag의 딜레마**: 대출 심사 모델은 오늘 승인을 해줘도, 이 사람이 진짜 연체를 냈는지(정답/Label)는 6개월 뒤에나 알 수 있음. (6개월간 성능 모니터링 불가 상태에 빠짐).
2. **사전 대응 (Proxy Monitoring)**:
   - 정답 없이도 계산 가능한 **입력 Feature 분포(Data Drift)** 모니터링 수행.
   - 예: 신청자의 평균 소득 분포가 학습 데이터와 통계적으로 크게 어긋남(PSI > 0.2 초과)을 실시간 감지. 성능이 떨어질 것임을 '예상'하고 황색경보(Alert) 발송.
3. **사후 검증 (Performance Monitoring)**:
   - 6개월 뒤 실제 연체 데이터(정답) 파이프라인 인입 시, 지연된 정답 조인(Delayed Label Join).
   - 모델 정확도(AUC)가 80%에서 70%로 급락한 사실(Concept Drift) 확정. 즉시 CT(Continuous Training) 파이프라인 트리거.

## Ⅳ. Drift (데이터 표류) 판단을 위한 핵심 통계 알고리즘
- **PSI (Population Stability Index)**: 금융권 신용평가 모니터링의 사실상 표준. 학습(Reference) 그룹과 운영(Current) 그룹의 비중 차이를 정보 이론 바탕으로 계산. (0.1 이하면 안정, 0.2 이상이면 중대한 변화 발생으로 모델 재학습 필요).
- **KS Test (Kolmogorov-Smirnov)**: 두 데이터 그룹의 누적분포함수(CDF) 간의 최대 수직 거리를 계산해, 두 샘플이 같은 분포에서 나왔는지를 가설 검정(P-value)하는 비모수적(Non-parametric) 방식. 연속형 숫자 데이터 감시에 탁월함.

## Ⅴ. 실무 적용 및 결론
- **판단 지표**: 모델 성능 저하 발생 시 MLOps 대시보드의 알람 발생 소요 시간(MTTD 단축), PSI 0.2 초과 이벤트 탐지율 100%, 자동 재학습(CT) 파이프라인 격발 성공률, 오탐(False Positive, 노이즈를 장애로 착각) 비율 최소화.
- **실무 설계**: 대형 제조업체 H사의 '반도체 웨이퍼 불량 이미지 판독 비전 AI' 모니터링 사례. 기존엔 월 1회 수동으로 정답을 엑셀로 뽑아 모델 정확도를 계산함(불량률 대응 골든타임 놓침). 조치 방안: Arize AI / Fiddler 등 특화 모니터링 플랫폼 연동. 1) 운영 카메라 센서의 조명값이나 각도 변경으로 인한 미세한 픽셀 노이즈 변화(Data Drift)를 임베딩 벡터 단위 거리(Cosine Similarity 등)로 실시간 계산. 2) 기준치 이탈 감지 시, 관리자 슬랙(Slack) 알림 발송 및 불량 판정 모델을 보수적 모드(Fail-safe, 무조건 육안 검수 풀로 이관)로 자동 전환. 3) 정답 라벨링이 끝난 데이터로 주말 야간 배치를 통해 파인튜닝 자동화. 공정 수율 하락 리스크 원천 차단.
- **결론**: 배포(Deployment)가 MLOps의 중간 고사라면, 모니터링(Monitoring)은 졸업할 때까지 매일 치르는 기말고사다. AI 시스템이 비즈니스 가치를 지속 창출하려면, 알고리즘의 화려함보다 자신이 언제 틀리기 시작하는지를 스스로 깨닫고 진단하는 '강건한 모니터링 관측망(Observability Network)'이 인프라의 최하단에 단단히 박혀 있어야 한다.

### 🔀 문제 유형별 목차 전환
- **Ⅱ·Ⅲ 강조 (개념/원리형)**: 소프트웨어 시스템의 '소리 없는 실패(Silent Failure)' 개념과 머신러닝 모델의 성능 우하향 곡선(Decay Curve) 모델링. 시간의 경과에 따른 모델 정확도 하락 기울기를 예측하고, 재학습(Retraining) 비용과 오예측으로 인한 비즈니스 손실(Cost) 간의 트레이드오프(Trade-off)를 교차시켜 경제적으로 최적화된 재학습 주기를 도출하는 원리 분석.
- **Ⅴ·Ⅵ 강조 (실무/설계형)**: 최근 대두되는 거대 언어 모델(LLM) 환경에서의 관측성(LLM Observability) 아키텍처 설계 확장. 단순 수치형 데이터 분포가 아닌 자유 발화(Text) 프롬프트 환경에서, 답변의 '환각(Hallucination)', '독성(Toxicity)', '어조(Tone)'의 품질 드리프트(Drift)를 실시간 감시하기 위해 모델 스스로를 감시관으로 쓰는 'LLM-as-a-Judge' 기반의 모니터링 파이프라인 설계 방안.
