## 핵심 인사이트 (3줄 요약)
> 1. **본질**: MCP 아키텍처에서 사내 데이터베이스, 파일 시스템, 외부 API 등 **실제 데이터와 비즈니스 로직(도구)을 품고 있는 '데이터 제공자이자 행동의 주체'** 역할을 하는 백엔드 프로그램이다.
> 2. **가치**: 인공지능(AI)에게 직접 사내 DB 비밀번호를 주지 않아도 된다. MCP Server가 DB 앞에 문지기로 버티고 서서 AI의 요청을 받아 대신 안전하게 쿼리해 주고 결과만 돌려주는 '보안 격벽(Security Boundary)' 역할을 완벽히 수행한다.
> 3. **판단 포인트**: 클라이언트(AI)의 요청을 받아 리소스(Resource)를 뱉어내거나, 도구(Tool)를 직접 실행(Execution)해 주는 서버의 구현 로직과, 로컬(STDIO) 및 원격(SSE) 기반의 전송 계층 통신 메커니즘을 명확히 구분해야 한다.

---

## Ⅰ. 개요 및 필요성
- **개요**: MCP Server는 Model Context Protocol을 준수하여, AI 클라이언트(예: Claude Desktop)가 외부 환경에 접근할 수 있도록 리소스, 도구, 프롬프트를 노출(Expose)하고 실행 결과를 반환해 주는 경량화된 서버 애플리케이션이다.
- **배경**: AI 모델을 서비스하는 빅테크(OpenAI, Google)에 기업의 민감한 DB 덤프를 통째로 넘겨 학습시키거나 분석하게 만드는 것은 극강의 보안 리스크(Data Leakage)를 동반했다.
- **필요성**: 기업의 데이터 원본은 회사 내부에 안전하게 두고, AI가 필요할 때마다 "질문(요청)"만 던지면 회사 내부의 룰에 맞춰 정제된 데이터만 쏙 빼서 전달해 줄 '통제 가능한 지식의 대리인(Proxy)'이 절대적으로 필요했다.

## Ⅱ. 아키텍처 및 핵심 원리

```text
  [ 외부: AI 모델 (MCP Client) ]           [ 사내망 (On-Premise): MCP Server ]

       "나 이번 달 매출 데이터 필요해"
       (Call Tool: `query_sales_db`)
                 │                                ┌───────────────────────────────────┐
                 │ (1. JSON-RPC 요청 전송)        │ 1. [요청 수신]: 권한 및 스키마 검증  │
                 ▼                                │                                   │
      ======================                      │ 2. [도구 실행]: 실제 DB 쿼리 실행    │ ──▶ [ 사내 SQL DB ]
       방화벽 (Security Boundary)                   │                (비밀번호는 여깄음)   │ ◀── (결과 반환)
      ======================                      │                                   │
                 │                                │ 3. [포맷 변환]: 결과를 텍스트로 가공 │
                 ▲ (4. 결과값 반환)               └───────────────────────────────────┘
                 │
       "매출은 100억이야" ◀──────────────────────── (3. JSON-RPC 응답 반환)
```

- **1단계 [서버 초기화 및 기능 선언 (Capabilities)]**: 서버가 켜지면 클라이언트(AI)와 인사를 나누며 "나는 사내 DB 조회 기능(Tool)과 사내 휴가 규정 문서(Resource)를 가지고 있어!"라고 메뉴판을 등록한다.
- **2단계 [요청 수신 (Listen)]**: 서버는 STDIO(표준 입출력)나 HTTP SSE(Server-Sent Events)를 통해 클라이언트가 쏘는 JSON-RPC 메시지를 24시간 귀 기울여 기다린다.
- **3단계 [실제 작업 수행 (Execution)]**: AI가 "DB 조회 도구 써줘"라고 파라미터를 담아 보내면, 서버는 코딩된 로직에 따라 사내 DB에 접속해 데이터를 빼오거나 엑셀 파일을 읽는다. (이때 인증 토큰이나 DB 비밀번호는 오직 MCP Server 코드 안에만 존재하며 AI는 전혀 모른다).
- **4단계 [결과 반환 (Response)]**: 긁어온 데이터를 AI가 읽기 편한 텍스트나 이미지(Base64) 포맷의 JSON으로 예쁘게 포장하여 클라이언트에게 다시 쏴준다.

## Ⅲ. 비교 및 연결

| 비교 축 | 전통적인 REST API 서버 | MCP Server |
|:---:|:---|:---|
| **설계 철학** | 사람(프론트엔드)이나 타 서버를 위한 데이터 제공 | **오직 거대 언어 모델(LLM)의 인지를 돕기 위한 설계** |
| **메시지 규격** | 개발자 마음대로 (보통 JSON) | **MCP 표준 스펙 (JSON-RPC 2.0)** 엄격 준수 |
| **전송 프로토콜 (Transport)**| 무조건 HTTP/HTTPS | **로컬 STDIO(콘솔 파이프)를 메인으로 지원** |
| **인터페이스 구조**| 엔드포인트(URL) 중심 (`/api/v1/users`) | **의미(Semantic) 중심 (Tools, Resources, Prompts)** |

> ※ **연결 포인트**: MCP Client가 '요청하는 뇌'라면, MCP Server는 '움직이는 손발과 팩트 창고'다. 개발자가 파이썬이나 타입스크립트로 100줄 남짓의 MCP Server 코드만 작성해 주면, 세상의 어떤 낡은 레거시 시스템도 단숨에 최신 AI 에이전트와 대화할 수 있는 스마트 시스템으로 탈바꿈한다.

## Ⅳ. 실무 적용 및 기술사 판단

- **적용 사례 1 (로컬 파일 시스템 보안 서버)**: 개발자가 Claude Desktop을 쓸 때 내 컴퓨터의 모든 폴더를 다 보게 놔두면 해킹 위험이 있다. 그래서 `filesystem-mcp-server`를 띄울 때 권한을 `/users/project/` 폴더로만 꽉 묶어둔다. 클로드가 C드라이브 시스템 폴더를 읽으려 하면 MCP Server가 "권한 없음!"이라며 접근을 칼같이 차단하는 샌드박스(Sandbox) 방패 역할을 한다.
- **적용 사례 2 (사내 레거시 ERP 연동 서버)**: 20년 된 사내 구형 ERP 시스템은 최신 REST API를 지원하지 않아 AI 연동이 불가능했다. 개발자가 중간에 작은 파이썬 MCP Server를 띄운다. 이 서버가 AI의 표준 JSON 요청을 받아, 뒤로는 구형 ERP의 SOAP 프로토콜이나 웹 크롤링으로 데이터를 긁어와서 다시 AI에게 표준 규격으로 쏴주는 완벽한 '번역기(Adapter)' 역할을 수행한다.
- **기술사 판단**: 시스템 아키텍처 설계 시 **원격(Remote) MCP Server와 로컬(Local) MCP Server의 보안 지형 차이**를 파악해야 한다. 로컬(STDIO) 서버는 트래픽이 PC 밖을 나가지 않아 방화벽 룰이 필요 없고 안전하지만 확장성이 떨어진다. 반면 클라우드에 띄우는 원격(SSE) 서버는 다수의 AI가 접속할 수 있으나, 네트워크 외부 노출에 따른 OAuth 토큰 기반 인증 등 엔터프라이즈급 API 보안 통제가 필수적으로 동반되어야 한다.

## Ⅴ. 기대효과 및 결론

- **기대효과**: 기업은 데이터의 원본(Single Source of Truth)과 보안 통제권을 사내 인프라 내부에 100% 쥔 상태로, 외부의 초거대 AI 모델의 지능만을 안전하게 빼먹을 수 있는 완벽한 제로 트러스트(Zero Trust) 연동 환경을 구축한다.
- **향후 발전 방향**: 현재는 개발자들이 Github에 오픈소스로 올라온 수백 개의 커스텀 MCP 서버(Slack, Google Drive, Postgres 등)를 가져다 쓰는 초기 단계이나, 머지않아 AWS나 Azure 같은 클라우드 벤더들이 자사 서비스용 공식 엔터프라이즈 MCP 서버를 매니지드 서비스(Managed Service)로 제공하는 시대로 진입할 것이다.

### 📌 관련 개념 맵
- **STDIO 전송 (Standard Input/Output Transport)**: 인터넷 브라우저가 통신하는 HTTP 방식이 아니라, 내 컴퓨터 안에서 검은색 터미널(CMD) 창 2개가 파이프를 꽂고 몰래 데이터를 쏴주는 방식. 외부 인터넷을 안 타니까 해킹 당할 위험이 0에 수렴한다.
- **능력 선언 (Capabilities)**: MCP 서버가 켜질 때 제일 먼저 "나는 리소스 읽기는 지원하는데 리소스 업데이트 기능은 없어! 그리고 도구 실행 기능은 있어!"라고 자신의 한계를 클라이언트에게 명확히 선언(Handshake)하는 규칙.

### 📈 관련 키워드 및 발전 흐름도
`레거시 시스템` $\to$ `맞춤형 API Gateway 구축` $\to$ `보안 및 연동 복잡도 폭발` $\to$ `MCP Server 도입 (통일된 AI 프록시)` $\to$ `엔터프라이즈 플러그앤플레이(Plug & Play) 생태계 완성`

### 👶 어린이를 위한 3줄 비유 설명
1. 챗봇(AI)에게 "내 통장 잔고 얼마야?"라고 물으면, 챗봇은 은행 앱 비밀번호를 모르니까 대답을 못 해요.
2. 이때 **MCP 서버(은행 창구 직원)**가 나섭니다. 챗봇은 창구 직원에게 "손님 잔고 좀 알려줘"라고 요청(표준 규격)만 해요.
3. 그러면 창구 직원(MCP 서버)이 안전한 금고(DB) 문을 직접 따서 잔고를 확인한 뒤, 챗봇에게 "100만 원이야"라고 대답만 쏙 넘겨주는 아주 믿음직한 중간 보안관이랍니다!
