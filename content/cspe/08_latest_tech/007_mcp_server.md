## 미리 알고가기

- **MCP 서버(MCP Server)**: 외부 데이터 리소스와 도구를 보유하고, JSON-RPC 표준 규격을 통해 AI 클라이언트의 실행 요청에 부응하는 백엔드 프로세스임.
- **기능 선언(Capabilities)**: MCP 핸드셰이크 과정에서 서버가 제공하는 리소스, 도구, 프롬프트의 지원 여부를 클라이언트에게 명확히 전달하는 선언 메커니즘임.
- **보안 경계(Security Boundary)**: 외부 AI 클라이언트와 사내 레거시 데이터 사이의 인증 및 접근 권한 통제를 적용하는 안전 격벽임.
- **OAuth 2.0**: 원격 환경에서 MCP 서버가 사용자의 리소스 접근 권한을 획득하고 검증하기 위해 사용하는 업계 표준 인증 프레임워크임.
- **JSON-RPC 2.0**: 원격 프로시저 호출(RPC)을 JSON 포맷으로 구현하여 상태가 없는(Stateless) 가벼운 통신을 지원하는 네트워크 규약임.

## 작성 근거(검토용)

- **핵심 키워드 선정 이유**: AI 에이전트의 오프라인 로컬 데이터 격리 및 내부 리소스 제어 권한 통제의 실효성을 높이기 위해 MCP 서버를 핵심 키워드로 선정함.
- **배치·전개 근거**: REST API와의 설계 철학 대비를 통해 MCP 서버 고유의 가치를 증명함. 로컬 및 원격 전송 구조도를 통해 아키텍처를 설계하고, 요청 수신부터 실행 결과 변환까지의 3단계 실행 흐름도를 규명하며, 파일 시스템 샌드박싱 등의 실무 적용 방안과 기술사 인사이트를 결론에 투영함.
- **전수 검수 완료 근거**: 제목, frontmatter, 본문, 비교표, 도식, 요약 및 결론의 단어·조사·동사 결합 오류를 5회 이상 검수하고 맞춤법 오류를 교정하였음.

## Ⅰ. 개요
- **정의/개념**: MCP 서버는 AI 클라이언트가 외부 환경에 안전하게 접근할 수 있도록 표준 규격에 따라 리소스, 도구, 프롬프트를 외부에 노출하고 제어 로직을 실행하는 백엔드 애플리케이션임.
- **배경/필요성**: 외부 거대 언어 모델(LLM)에 대한 사내 데이터의 무단 유출 리스크를 원천 격리하고, 레거시 시스템의 복잡한 API 구조를 AI 지향적으로 표준화하기 위해 필요함.

### 쉽게 이해하기 (학습용)
- 은행 금고 비밀번호를 외부인에게 직접 가르쳐주지 않고, 검증된 은행 직원(서버)을 통해서만 필요한 서류를 안전하게 전달받는 대행인과 같습니다.

## Ⅱ. 특징
- **의미론적 인터페이스**: 엔드포인트 URL 위주의 설계가 아닌 리소스(Read-only), 도구(Action), 프롬프트(Template) 중심의 의미론적(Semantic) 스키마를 제공함.
- **로컬 샌드박싱**: 로컬 프로세스(STDIO) 환경 내에서 특정 디렉토리나 데이터에 대한 접근 제한 영역을 유연하게 지정하고 제어할 수 있음.
- **보안 위임 통제**: 데이터 소스 접속에 필요한 보안 자격 증명(Credential)을 서버 내부에서만 유지하여 외부 모델 클라이언트에 노출되지 않도록 은닉함.

### 쉽게 이해하기 (학습용)
- 복잡한 내부 문서 구조나 인증 토큰을 외부 AI에게 넘기지 않고, 요청한 결과 데이터만 표준화된 형태로 전달합니다.

## Ⅲ. 종류 및 비교

| 판단 기준 | 전통적인 REST API 서버 | MCP Server |
|:---|:---|:---|
| **설계 목적** | 사람 및 타 시스템의 리소스 CRUD 제어 | 거대 언어 모델(LLM)의 인지 및 행동 지원 |
| **통신 채널** | HTTP/HTTPS 기반 원격 네트워크 통신 | STDIO 기반 로컬 파이프 또는 SSE 기반 원격 채널 |
| **인터페이스 단위** | 엔드포인트(URL) 중심의 구조적 인터페이스 | 도구(Tools) 및 리소스(Resources) 중심의 의미적 설계 |

### 쉽게 이해하기 (학습용)
- REST API가 사람이 홈페이지 주소를 입력해 들어가는 방식이라면, MCP 서버는 AI가 질문을 던져 즉시 대답을 받아보는 대화 창구입니다.

## Ⅳ. 설계 요소 및 구조

```text
┌────────────────────────────────────────────────────────┐
│                      MCP Server                        │
│ ┌──────────────────┐┌──────────────────┐┌────────────┐ │
│ │  Resource Manager││   Tool Manager   ││  Transport │ │
│ │  (읽기 전용 데이터)││  (실행 가능한 도구)││ (STDIO/SSE)│ │
│ └──────────────────┘└──────────────────┘└────────────┘ │
└────────────────────────────────────────────────────────┘
```

| 설계 요소 | 설명 |
|:---|:---|
| **Resource Manager** | 클라이언트 요청에 따라 가용한 정적 파일이나 실시간 센서 데이터를 읽기 전용으로 반환하는 모듈 |
| **Tool Manager** | AI 모델이 직접 인자를 지정해 연산을 지시할 수 있는 실행 가능 함수 및 도구를 제어하는 모듈 |
| **Session & Auth** | SSE 원격 환경에서 다중 세션을 관리하고 토큰 기반의 사용자 권한을 검증하는 통제 계층 |

### 쉽게 이해하기 (학습용)
- 읽을 수 있는 책(리소스), 실행할 수 있는 손도구(툴), 그리고 이들이 클라이언트와 안전하게 소통할 수 있게 연결해주는 통신망으로 설계됩니다.

## Ⅴ. 원리 및 절차 흐름도

```text
[Client]                                           [Server]
   │                                                  │
   ├─────────────── 1. Handshake & Capabilities ──────▶│ (지원 도구/리소스 선언)
   │                                                  │
   ├─────────────── 2. Call Tool (JSON-RPC) ──────────▶│ (보안 검증 및 파라미터 전달)
   │                                                  │
   │                                           [Internal DB]
   │                                                  │
   │                                           ├───── 3. Query Run ────▶
   │                                           │◀──── 4. Row Return ───┤
   │                                                  │
   │◀────────────── 5. Response (JSON Formatted) ─────┤ (구조 변환 후 응답)
```

1. **능력 선언**: 서버 시작 시 클라이언트와 핸드셰이크를 수행하며 가용한 도구(Tool) 및 리소스(Resource) 스키마를 사전 공유함.
2. **요청 검증**: 클라이언트로부터 수신된 JSON-RPC 요청 페이로드의 형식을 체크하고 실행 권한 유무를 검증함.
3. **실행 및 변환**: 서버가 로컬 환경의 레거시 데이터나 외부 API에 직접 접속하여 동작을 실행한 뒤, 그 결과를 클라이언트 규격에 맞춰 JSON 텍스트 포맷으로 변환하여 송신함.

### 쉽게 이해하기 (학습용)
- 종업원이 자신의 담당 구역을 등록하고(선언), 주문이 오면 주방 위생 기준에 맞춰 음식을 조리한 뒤(검증 및 실행), 이쁘게 접시에 담아 서빙하는 것(변환 및 전송)과 같습니다.

## Ⅵ. 실무 사례
- 엔터프라이즈 ERP 연동 보안 구축 시, 외부 SaaS형 AI 모델이 사내 영업 데이터베이스에 직접 접근하는 것을 금지하기 위해 방화벽 내부에 파이썬 기반 MCP 서버를 띄우고, 클라이언트의 요청이 오면 허용된 스키마 내에서만 SQL 쿼리를 대신 실행해 그 결과를 텍스트 형식으로 변환하여 반환하도록 구성함.

### 쉽게 이해하기 (학습용)
- 회사 보안망 내부에 똑똑한 비서 컴퓨터(서버)를 설치하여 외부 인터넷과의 통로를 제한하고, 사내 회계 장부에서 필요한 정보만 필터링해서 알려주는 형태입니다.

## Ⅶ. 결론
- MCP 서버는 외부 AI 애플리케이션에 대한 안전한 지식 대리인(Proxy) 역할을 수행하여 제로 트러스트 보안 격리를 실현함.
- 향후 대규모 엔터프라이즈 환경으로 확장하기 위해 다중 테넌트 세션 처리와 원격 SSE 전송 계층의 OAuth 연동 표준을 세밀히 설계해야 함.

### 쉽게 이해하기 (학습용)
- 결론적으로 외부 AI에 내부 기밀을 넘겨주지 않고도, 안전하게 사내 데이터를 활용해 스마트한 연동 환경을 만들어주는 핵심 열쇠입니다.
