# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: **MCP 서버**는 로컬 데이터, 외부 API, 복잡한 비즈니스 로직 등을 **Model Context Protocol(MCP)** 규격에 맞춰 클라이언트(AI 모델)에게 노출하는 **독립적인 소프트웨어 컴포넌트**이다.
- **필요성**: AI 모델이 특정 시스템이나 데이터에 접근하려면 각기 다른 API 규격을 해석해야 했다. MCP 서버는 이를 표준화된 인터페이스로 감싸(Wrapping), 모델이 복잡한 설정 없이도 즉시 도구를 사용할 수 있도록 돕는다.
- **핵심 직관**: **"데이터와 도구를 담은 전용 컨테이너"**. 어떤 복잡한 시스템이든 MCP 서버라는 표준 옷을 입히면 에이전트가 바로 이해할 수 있다.

## 깊이 이해
- **배경 (Decoupling Data from Models)**: 이전에는 AI 애플리케이션의 핵심 로직 내부에 도구 연동 코드가 섞여 있었다. MCP 서버는 이 연동 로직을 독립적인 프로세스로 분리하여 관리 효율성과 재사용성을 극대화한다.
- **작동 원리 (Inside an MCP Server)**:
    - **Discovery**: 클라이언트에게 자신이 제공할 수 있는 리소스와 도구 목록을 전달.
    - **Handler**: 특정 도구 호출 요청이 오면 실제 로직(예: SQL 실행, API 호출)을 수행하는 함수.
    - **Transport**: 클라이언트와 통신하는 방식. 주로 로컬은 `Stdio`, 원격은 `HTTP/SSE`를 사용한다.
- **비유**: 레스토랑(AI 호스트)의 주방에서 직접 재료를 구하러 다니는 대신, 전문 식자재 납품업체(MCP 서버)가 표준 규격의 박스에 담아 필요한 재료(리소스)와 요리 도구(툴)를 가져다주는 것과 같다.
- **구체 예시**: `PostgreSQL MCP Server`를 띄우면, 에이전트는 SQL 쿼리를 직접 짜서 실행하고 결과를 받아올 수 있다.
- **주의점**: 서버가 제공하는 기능이 너무 많으면 에이전트가 어떤 도구를 쓸지 혼란스러워할 수 있으므로, 목적에 맞는 **경량 서버(Micro-servers)** 설계가 중요하다.

## 연결 개념
- **MCP (006)**: MCP 서버가 따르는 상위 표준 통신 규격.
- **MCP Client (008)**: 서버에 연결하여 데이터를 요청하고 도구를 실행하는 주체.
- **JSON-RPC**: 서버와 클라이언트가 대화하는 로우레벨 통신 방식.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 비즈니스 기능과 데이터를 AI 모델이 이해 가능한 표준 인터페이스(Resource, Tool, Prompt)로 변환하여 제공하는 **공급자 계층**.
> 2. **가치**: 데이터 소스 및 도구의 구현 복잡성을 은닉(Encapsulation)하고, 모델 종속성을 제거하여 유지보수성 향상.
> 3. **판단 포인트**: 보안 환경에 따라 Stdio(로컬) 또는 SSE(원격) 전송 방식을 선택하고, 세밀한 권한 통제(RBAC)를 서버 단에서 수행해야 함.

## 출제 의도 및 답안 포인트
- **출제 의도**: MCP 아키텍처의 핵심 실무 계층인 서버의 구조와 구현 방식, 전송 메커니즘 이해 여부.
- **핵심 포인트**: 리소스/도구 핸들러, 전송 방식(Stdio, SSE), 발견(Discovery) 메커니즘.

## Ⅰ. MCP 서버(MCP Server)의 정의 및 주요 역할
### 1. MCP 서버의 정의
- Model Context Protocol 표준을 구현하여, AI 클라이언트에게 리소스(데이터), 도구(행동), 프롬프트(템플릿)를 제공하는 독립적 서비스 엔진.
### 2. 주요 역할
- **기능 노출**: 로컬/원격 기능을 표준화된 JSON 명세로 클라이언트에게 광고.
- **요청 처리**: 클라이언트가 보낸 도구 호출 인자를 해석하여 실제 내부 로직 수행.
- **보안 격리**: 데이터 소스와 모델 사이에서 대리자(Proxy) 역할을 하며 비정상적 요청 차단.

---

## Ⅱ. MCP 서버의 내부 구성 요소 및 동작 원리
- **모듈화된 서버 구조**
```text
┌───────────────────────────────────────────┐
│               MCP Server SDK              │
├─────────────┬──────────────┬──────────────┤
│  Resources  │    Tools     │   Prompts    │
│  (Read-only)│  (Actions)   │  (Templates) │
├─────────────┴──────────────┴──────────────┤
│       Transport Layer (Stdio / SSE)       │
└───────────────────────────────────────────┘
```

| 구성 요소 | 상세 설명 |
|:---:|:---|
| **Resource Handlers** | 정적인 텍스트나 바이너리 데이터를 특정 URI 패턴에 맞춰 제공 (예: `file:///logs/today.txt`). |
| **Tool Handlers** | 실행 가능한 비즈니스 로직. 입력 파라미터를 받아 작업을 수행하고 결과를 반환. |
| **Prompt Handlers** | 복잡한 작업 지침을 미리 정의해둔 템플릿. 모델의 페르소나나 워크플로우 가이드 제공. |
| **Transport Layer** | 서버-클라이언트 간 비트 스트림 전송. 로컬 프로세스 간 통신은 Stdio, 네트워크 통신은 SSE(Server-Sent Events) 활용. |

---

## Ⅲ. MCP 서버의 주요 전송 방식 (Transports)

| 방식 | 기술적 특징 | 주요 사례 |
|:---:|:---|:---|
| **Stdio** | 표준 입출력을 통한 통신. 클라이언트가 서버 프로세스를 직접 실행하고 관리. | 로컬 파일 시스템 관리, IDE 플러그인, 개인용 데스크톱 에이전트. |
| **SSE (HTTP)** | HTTP 기반의 서버-클라이언트 연결. 서버가 독립적으로 구동되며 여러 클라이언트 수용 가능. | 엔터프라이즈 사내 DB 연결, 클라우드 기반 공유 도구, 원격 API 게이트웨이. |

## Ⅳ. MCP 서버 개발 및 배포 생태계
- **SDK 지원**: TypeScript, Python, Java 등 주요 언어별 SDK 제공으로 개발 진입장벽 완화.
- **Open Source Ecosystem**: GitHub, Slack, Google Drive, PostgreSQL 등 이미 수백 개의 기구축된 오픈소스 MCP 서버 활용 가능.
- **Containerization**: Docker 등을 통해 MCP 서버를 패키징하여 어떤 환경에서도 동일한 도구 환경 제공.

---

## Ⅴ. MCP 서버 설계 시 고려사항 (Best Practices)
- **Granularity (입도)**: 하나의 서버에 너무 많은 기능을 담기보다, 기능별로 쪼개진 'Micro-MCP Server'가 관리 및 모델 인식에 유리.
- **Authentication**: SSE 사용 시 클라이언트 인증 및 인가(Token-based 등) 처리가 서버 보안의 핵심.
- **Schema Accuracy**: 도구 설명(Description)을 모델이 헷갈리지 않게 구체적으로 적어야 정확한 호출 유도 가능.

---

## Ⅵ. 실무 적용 및 결론
- **Enterprise 데이터 연동**: 사내 지식 베이스를 MCP 서버로 노출하여, 서로 다른 AI 에이전트들이 공통된 최신 정보를 사용하도록 아키텍처 설계.
- **결론**: MCP 서버는 AI 시대의 **"Microservices for AI"**로 자리 잡을 것이며, 기술사는 이를 활용한 전사 도구 거버넌스 체계를 수립해야 함.
