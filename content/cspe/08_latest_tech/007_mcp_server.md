# 📖 【암기용】 개념 완전 이해

> 목적: MCP Server를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: MCP Client에 도구·리소스·프롬프트를 제공하는 서버
- **왜 필요한가**: 외부 시스템 연결을 AI 앱 내부에 넣으면 배포·권한·감사 책임이 흩어짐.
- **핵심 직관**: MCP Server는 AI가 접근할 수 있는 업무 기능을 선별해 공개하는 관문임.

## 깊이 이해
- **배경·문제의식**: Git, DB, 파일, SaaS별 연동 로직을 에이전트마다 넣으면 업데이트와 보안정책 통제가 어려움.
- **작동 원리**: 서버가 사용 가능한 Tool과 Resource 목록을 제공하고, 호출 시 입력 검증 후 백엔드 시스템에 접근함.
- **비유**: 사내 포털이 여러 업무 시스템을 한 화면에 묶되 사용자 권한에 따라 메뉴를 다르게 보여주는 구조.
- **구체 예시**: Git MCP Server가 `list_issues`, `get_file`, `create_branch` 도구를 제공하고 호출 로그를 남김.
- **흔한 오해·주의점**: MCP Server가 많아질수록 공격면이 늘어나므로 서버 등록·서명·취약점 점검 절차가 필요함.

## 연결 개념
- MCP Client — 서버 기능을 소비하는 주체
- Tool Registry — 서버별 도구 목록 관리
- SBOM — MCP Server 구성요소 취약점 관리

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: MCP Server는 AI 앱에 외부 시스템 기능을 표준 도구·리소스 형태로 노출하는 실행 관문임.
> 2. **가치**: 연동 로직을 서버 단위로 분리해 권한, 감사, 버전관리를 중앙화함.
> 3. **판단 포인트**: 서버 신뢰성, Tool 권한 범위, 입력 검증, 취약점 관리가 운영 핵심임.

---

## Ⅰ. 개요 및 필요성

MCP Server는 MCP 기능 제공 서버임. AI 에이전트가 업무 시스템에 접근할 때 안전한 기능 노출, 권한 위임, 감사로그 확보가 필요함.

---

## Ⅱ. 구조 및 구성요소

```text
MCP Client -> MCP Server -> Adapter -> Backend System


              Tool Catalog  Audit/Policy
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Tool Catalog | 제공 기능 목록 관리 | 버전·권한 등급 표기 |
| Adapter | 백엔드 API 변환 | 재시도·타임아웃 설정 |
| Policy | 호출 권한·범위 통제 | RBAC, ABAC 적용 |
| Audit | 호출 이력 기록 | 사용자ID, 입력 해시 |

> 요약: MCP Server는 도구 목록, 백엔드 어댑터, 정책, 감사 기능을 묶은 AI 연동 관문임.

---

## Ⅲ. 동작원리 및 흐름도

```text
서버 등록 -> 도구 목록 제공 -> 호출 요청 수신
       -> 입력 검증 -> 백엔드 호출 -> 결과 정제/반환
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 서버 등록·신뢰 확인 | 서명, 버전, SBOM |
| 2 | 도구 목록 제공 | 설명, 스키마, 권한등급 |
| 3 | 호출 처리 | 인증, 입력 범위, rate limit |
| 4 | 결과 반환·로그 | 마스킹, 응답코드, Trace ID |

> 요약: MCP Server는 기능 공개부터 결과 반환까지 신뢰·검증·감사를 수행함.

---

## Ⅳ. 특징

| 구분 | 앱 내부 커넥터 | MCP Server | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 배포 | 앱별 배포 | 서버별 독립 배포 | 변경 영향 범위 |
| 권한 | 앱 코드에 분산 | 서버 정책으로 통제 | RBAC 정책 수 |
| 위험 | 코드 중복 | 서버 공격면 증가 | CVE 점검, 로그율 |

> 요약: MCP Server는 연동 책임을 중앙화하지만 서버 자체가 중요 보호 자산이 됨.

---

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. MCP Server 등록 시 서명 검증, SBOM 제출, CVE 스캔, 운영자 승인 절차 적용
2. Tool별 읽기·쓰기·관리 권한을 분리하고 변경형 Tool은 승인·멱등성 키 적용
3. 서버별 p95 지연, 오류율, 호출 건수, 거부 건수를 대시보드로 관리

**결론 (2줄):**
- 기술사 판단: 사내 MCP Server는 API Gateway와 동일한 통제 수준으로 운영해야 함.
- 향후 방향: MCP Server는 AI 도구 생태계의 표준 배포 단위로 확장되고 보안 인증 체계가 결합됨.
