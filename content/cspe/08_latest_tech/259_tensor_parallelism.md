# 📖 【암기용】 개념 완전 이해

> 목적: 모델의 층(Layer)을 쪼개는 파이프라인 병렬화의 한계를 넘어, 아예 층 내부의 거대한 행렬(Tensor)을 반으로 갈라버리는 궁극의 병렬화 기술을 이해한다.

## 한눈에
- **정의**: 트랜스포머(Transformer) 모델 내부의 거대한 행렬 곱셈 연산(Tensor Operation) 자체를 세로(Column)나 가로(Row)로 잘라서 여러 GPU가 분담하여 동시에 계산하는 학습 기법
- **필요성**: 파이프라인 병렬화(PP)는 여전히 '1개의 층(Layer)' 전체는 무조건 1대의 GPU에 들어가야 한다는 제약이 있는데, GPT-3 이상급에서는 층 1개조차 너무 거대해서 단일 GPU에 안 들어가는 문제가 발생했기 때문
- **핵심 직관**: "1000조각 퍼즐 1판(Layer)을 혼자 다 맞추고 다음 사람에게 넘기는 게 아니라(PP), 퍼즐판 자체를 반으로 쪼개서 나와 내 짝꿍이 절반씩 동시에 맞춘 뒤(TP) 하나로 합치는 것"

## 깊이 이해
- **배경(왜 등장했나?)**: 엔비디아 연구진(Megatron-LM)이 거대 언어 모델을 학습시키다 보니, 어텐션(Attention) 레이어의 가중치 행렬이 미친 듯이 커졌다. 이 거대한 행렬 곱셈 $Y = XA$를 GPU 한 대가 혼자 하려니 메모리도 터지고 속도도 느렸다. 그래서 행렬 $A$ 자체를 $A_1$과 $A_2$로 수직 분할(Column Parallel)해서 GPU 0과 GPU 1이 동시에 계산하게 만들었다.
- **작동 원리(어떻게 달성했나?)**: 
  1. **Column Parallel (세로 분할)**: 첫 번째 선형 변환(Linear) 행렬을 세로로 쪼개어 각각 계산한다. 이때 각 GPU는 절반짜리 결과값을 쥔 채로 통신 없이 바로 다음 단계로 넘어간다.
  2. **Row Parallel (가로 분할)**: 두 번째 선형 변환 행렬은 가로로 쪼개어 계산한다.
  3. **All-Reduce (결과 합산)**: 계산이 끝나면 GPU 0의 결과와 GPU 1의 결과를 서로 더해서(All-Reduce) 완벽한 최종 값을 만들어 낸다.
- **일상 비유**: 식당에서 100인분짜리 거대한 비빔밥 한 양푼(Layer)을 비벼야 한다. 혼자 100인분을 다 비비고(PP) 찌개를 끓이는 게 아니라, 두 명이 양푼 양쪽에 달라붙어서 각자 50인분씩 동시에 비빈 뒤(TP), 나중에 한 그릇으로 예쁘게 모으는(All-Reduce) 것이다.
- **구체 예시**: 엔비디아의 Megatron-LM 프레임워크가 이 분야의 교과서다. 트랜스포머의 Multi-Head Attention 구조는 여러 개의 헤드(Head)가 독립적으로 동작하므로 텐서 병렬화로 잘라내기가 환상적으로 쉽다. (예: 8개의 헤드를 2개의 GPU가 4개씩 나눠 가짐)
- **흔한 오해/주의점**: "텐서 병렬화(TP)가 무조건 제일 좋은가?" → 통신 관점에서는 최악이다. 행렬을 쪼개서 계산한 뒤 합치는 과정(All-Reduce)이 레이어마다, 심지어 레이어 내부에서도 수시로 일어난다. 따라서 랙(Rack)과 랙 사이의 느린 케이블로는 절대 불가능하며, **오직 NVLink처럼 초고속으로 연결된 단일 서버(보통 8 GPU) 내부에서만 사용**해야 한다.

## 연결 개념
- **Transformer (트랜스포머)**: 텐서 병렬화가 가장 잘 적용되는 아키텍처 (Multi-Head Attention과 MLP 레이어가 쪼개기 좋음)
- **Megatron-LM**: 텐서 병렬화를 세상에 널리 알리고 구현한 엔비디아의 오픈소스 프레임워크
- **All-Reduce**: 쪼개진 텐서 연산의 최종 결과물을 하나로 합치기 위해 레이어 연산 끝부분에서 반드시 실행되는 통신 알고리즘

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 텐서 병렬화(Tensor Parallelism, TP)는 단일 레이어(Layer)를 구성하는 거대한 파라미터 행렬(Tensor)을 컬럼(Column) 및 로우(Row) 단위로 분할하여 다수의 GPU가 행렬 곱셈을 동시(병렬) 연산하는 아키텍처이다.
> 2. **가치**: 파이프라인 병렬화(PP)로 분할 불가능한 초대형 단일 레이어의 OOM(Out Of Memory) 한계를 돌파하고, 1F1B 스케줄링이 필요 없는 완벽한 동시 연산(Zero Bubble)을 달성한다.
> 3. **판단 포인트**: 순방향/역방향 패스 내에서 극단적으로 빈번한 집합 통신(All-Reduce)이 요구되므로, 서버 간(Scale-out)망이 아닌 단일 노드 내(Scale-up) NVLink/NVSwitch 토폴로지에 국한하여 적용하는 것이 핵심 원칙이다.

## Ⅰ. 개요 및 필요성
- **정의**: 모델 병렬화의 세부 기법 중 하나로, 딥러닝 모델의 기본 연산 단위인 텐서(행렬) 연산 $Y = X \times A$를 여러 조각으로 물리적으로 분할하여 다수의 디바이스에서 분산 처리하는 방식
- **배경**: 파이프라인 병렬화(PP)는 레이어 단위로만 분할 가능하므로, GPT-3급 이상 모델에서는 단일 레이어의 어텐션 블록조차 GPU 1대의 VRAM(80GB) 용량을 초과하는 문제 발생
- **필요성**: 단일 레이어 제약(Single Layer Constraint)의 물리적 타파, 유휴 시간(Bubble) 없이 완벽히 동기화된(Synchronous) 병렬 연산 달성

## Ⅱ. Tensor Parallelism 핵심 메커니즘 (Megatron-LM 구조)
트랜스포머(Transformer)의 기본 블록인 MLP(Multi-Layer Perceptron) 계층의 연산을 GPU 0과 GPU 1로 텐서 병렬화하는 원리.

```text
[ 입력 X ] ──┐
             │ (복사)
             ├──> [ GPU 0 ] 연산: X * A1 (Column 분할) ──> 활성화 함수(f) ──> [ GPU 0 ] 연산: f(X*A1) * B1 (Row 분할) ─┐
             │                                                                                                    │
             └──> [ GPU 1 ] 연산: X * A2 (Column 분할) ──> 활성화 함수(f) ──> [ GPU 1 ] 연산: f(X*A2) * B2 (Row 분할) ─┴─ All-Reduce (Y)
```

1. **Column Parallel Linear ($A_1, A_2$)**: 가중치 행렬 $A$를 열(세로) 기준으로 자름. 입력 $X$를 두 GPU가 각각 받아서 $Y_1, Y_2$를 계산. **(중간 통신 필요 없음)**
2. **Row Parallel Linear ($B_1, B_2$)**: 가중치 행렬 $B$를 행(가로) 기준으로 자름. 앞서 구한 $Y_1, Y_2$를 그대로 입력받아 곱함.
3. **All-Reduce 동기화**: 두 GPU에서 계산된 최종 결과를 `All-Reduce(합산)`하여 완벽한 출력 $Y$ 도출.

## Ⅲ. PP (파이프라인 병렬화) vs TP (텐서 병렬화) 1:1 비교
| 구분 | Pipeline Parallelism (PP) | Tensor Parallelism (TP) |
|:---|:---|:---|
| **분할 단위 (Granularity)** | 모델의 **층(Layer)** 단위 | 층 내부의 **행렬(Tensor)** 단위 |
| **연산 방식** | Sequential (순차적 넘겨주기) | **Concurrent (동시 병렬 연산)** |
| **유휴 시간 (Bubble)** | 파이프라인 양끝 단에 반드시 존재 | **이론적으로 Bubble 없음 (0%)** |
| **통신 횟수 및 트래픽** | 레이어 경계에서만 통신 (낮음) | **연산 블록마다 수시로 통신 (극단적으로 높음)** |
| **적용 토폴로지 제한** | 이더넷/IB 등 **노드(서버) 간 적용 가능** | 반드시 NVLink 등 **단일 서버(Node) 내부 전용** |

## Ⅳ. Transformer 토폴로지에 대한 TP 적용 우수성
엔비디아의 Megatron-LM이 텐서 병렬화를 대성공시킬 수 있었던 이유는 **트랜스포머 아키텍처의 특성**과 완벽히 부합했기 때문이다.
1. **Multi-Head Attention 분할**: 어텐션 블록은 여러 개의 헤드(Head)가 독립적으로 작동한다. 총 32개의 헤드가 있다면 8대의 GPU에 4개씩 분할(Partition)해 주면, 헤드 간 통신 없이 완벽한 독립 연산이 가능하다.
2. **비선형 연산(GeLU 등)의 분배**: Column Parallel 연산 후 중간에 통신(All-Reduce)을 거치지 않고 바로 비선형 활성화 함수를 태워도 수학적으로 완벽히 동일한 결과가 도출되므로 통신 오버헤드를 절반으로 줄일 수 있다.

## Ⅴ. 기술적 한계(리스크) 및 최신 연구 동향
| 리스크 요인 | 발생 원인 | 대응 아키텍처 및 연구 방향 |
|:---|:---|:---|
| **극심한 통신 병목** | TP는 레이어마다 All-Reduce를 유발하여 PCIe 망에서 구동 시 연산보다 통신 시간이 더 걸림 | 단일 노드를 넘어서는 TP 적용을 위해 **Sequence Parallelism(시퀀스 병렬화)** 기법과 결합하여 통신량 최적화 |
| **개발 복잡도 극상**| 단순히 층만 나누는 PP와 달리, 프레임워크 수준에서 행렬 분할과 수학적 등치성(Equivalence)을 모두 제어해야 함 | Megatron-LM, DeepSpeed, Colossal-AI 등 추상화된 프레임워크 생태계에 전적으로 의존 |

## Ⅵ. 실무 적용 및 결론
**적용 방안 및 실무 가이드 (3D Parallelism 배치):**
초거대 AI 인프라 엔지니어링 시 병렬화 토폴로지 설계의 황금률(Golden Rule)은 다음과 같다.
1. **TP (Tensor Parallelism) = 단일 노드(서버) 내부**: 통신량이 너무 많아 무조건 NVLink로 묶인 8개 GPU 내부(Scale-up) 범위로 설정한다. (일반적으로 TP Degree = 4 또는 8)
2. **PP (Pipeline Parallelism) = 서버 랙(Rack) 간**: 중간 수준의 통신이 요구되므로 InfiniBand 스위치 홉(Hop)을 넘어가는 단위로 묶는다.
3. **DP (Data Parallelism) = 전체 데이터센터 간**: 통신량이 가장 적고 독립적이므로 전체 GPU에 대해 넓게 스케일 아웃(Scale-out)하여 배치 사이즈를 확보한다.

**결론:**
- 텐서 병렬화(TP)는 OOM을 피하고 GPU 버블(Bubble)을 원천 차단하는 가장 이상적이고 강력한 분산 처리 기술이다.
- 비록 막대한 NVLink 하드웨어 인프라가 뒷받침되어야 한다는 제약이 있으나, Transformer 기반의 LLM 훈련을 물리적으로 가능하게 한 **가장 심층적인 모델 파티셔닝(Deepest Model Partitioning)** 기술로 평가받고 있다.
