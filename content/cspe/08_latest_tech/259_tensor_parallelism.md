# 📖 【암기용】 개념 완전 이해

> 목적: 텐서 병렬화를 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 딥러닝의 핵심 연산인 거대 행렬 곱셈(Matrix Multiplication) 자체를 여러 조각으로 쪼개어, 여러 대의 GPU가 한 층(Layer)의 연산을 나누어 수행하게 하는 기술
- **왜 필요한가**: 모델의 특정 층(예: 어텐션 층)이 너무 커서 한 GPU의 메모리에 담기지 않거나, 연산량이 너무 많아 한 대로는 속도가 안 날 때 사용한다.
- **핵심 직관**: "거대한 피자 한 판(행렬)을 여러 조각으로 잘라, 여러 명(GPU)이 각자 자기 조각에 토핑을 얹은 뒤 마지막에 다시 합쳐서 완성하는 방식"

## 깊이 이해
- **배경·문제의식**: 트랜스포머 모델의 핵심인 셀프 어텐션(Self-Attention)과 MLP 계층은 엄청난 크기의 행렬 연산을 포함한다. 파라미터가 수천억 개인 모델은 한 층의 가중치만 해도 수십 GB에 달한다. 이를 처리하려면 '층 단위' 분할(파이프라인)보다 더 세밀한 '연산 단위' 분할이 필요하다.
- **작동 원리**:
  1. **가중치 분할**: 큰 행렬을 열(Column) 또는 행(Row) 단위로 쪼개어 GPU마다 나누어 가진다.
  2. **부분 연산**: 각 GPU는 자기가 가진 부분 가중치와 입력 데이터를 곱해 부분 결과값(Partial Result)을 낸다.
  3. **결과 합산**: 연산 중간중간에 모든 GPU가 통신(All-Reduce 또는 All-Gather)하여 부분 정답들을 합쳐 최종 결과값을 만든다.
- **비유**: 아주 큰 예산안을 짤 때, 한 명은 인건비를 다른 한 명은 재료비를 각자 계산한 뒤, 둘의 결과를 더해서 최종 예산을 확정하는 것과 같다.
- **구체 예시**: NVIDIA의 Megatron-LM이 텐서 병렬화의 표준이다. 어텐션 헤드(Head)가 32개라면, 8장의 GPU가 각자 4개씩 맡아서 병렬로 계산한다.
- **흔한 오해·주의점**: 텐서 병렬화는 통신이 **엄청나게 많이** 발생한다. 한 층 안에서만 수차례 데이터 동기화가 필요하므로, GPU 간 연결 속도가 매우 빠른 NVLink 환경에서만 제 성능이 난다. 일반적인 인터넷/이더넷 환경에서는 통신 때문에 오히려 더 느려질 수 있다.

## 연결 개념
- Matrix Multiplication (행렬 곱셈) — 텐서 병렬화의 주 대상 연산
- All-Reduce — 부분 연산 결과를 합치는 핵심 통신 함수
- NVLink — 텐서 병렬화를 실용적으로 만드는 고속 인터커넥트

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 텐서 병렬화는 행렬 분할 방식(Row vs Column)과 연산 중 발생하는 통신 오버헤드 제어를 중심으로 기술한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 텐서 병렬화(Tensor Parallelism)는 단일 신경망 계층 내의 행렬 연산을 분할하여 다수의 GPU가 협력 수행하는 수평적(Horizontal) 모델 병렬화 기법이다.
> 2. **가치**: 거대 행렬을 다수 GPU 메모리에 분산 적재함으로써 단일 장치 수용 불가 모델의 연산 가속 및 메모리 확장성을 제공한다.
> 3. **판단 포인트**: 계층마다 발생하는 잦은 통신(All-Reduce) 부하를 고려하여 NVLink 등 초고속 인터커넥트가 확보된 노드 내(Intra-node) 배치에 최적화한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 거대 행렬 분산 처리 원리 이해도 | Column Parallel, Row Parallel, All-Reduce/All-Gather | 단순히 "연산을 나눈다"고만 서술 |
| 트랜스포머 아키텍처 최적화 역량 | Multi-head Attention 및 MLP 블록 분할 방식 | 일반적인 병렬화와 차별점 부재 |
| 통신 효율성 및 하드웨어 연계 인지 | 통신 횟수 최소화 전략, NVLink 의존성 | 통신 오버헤드 무시 및 가공의 성능 수치 제시 |

> 요약: 행렬 분할 기법과 통신 최소화 설계, 하드웨어 특성(NVLink)을 연결하여 기술한다.

## Ⅰ. 개요 및 필요성

- 정의: 인공지능 모델의 단일 층 내에 존재하는 텐서(행렬) 연산을 분할하여 다수의 장치에서 병렬 처리하는 기법
- 배경: 트랜스포머 기반 LLM의 히든 레이어 크기(Hidden Dimension)가 단일 GPU 메모리 대역폭 및 용량을 초과
- 필요성: 초대형 행렬 연산 가속을 통한 추론/학습 지연 시간(Latency) 단축 및 분산 메모리 활용 극대화

---

## Ⅱ. 구조 및 구성요소

```text
[텐서 병렬화 분할 구조: Megatron-LM 스타일]
Input X -> [Column Parallel Weight A] -> Output Y1, Y2 (on GPU 0, 1)
         -> [Row Parallel Weight B]    -> Result Z (after All-Reduce)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Column Parallel | 가중치 행렬을 열 단위로 분할하여 병렬 연산 | 출력 텐서가 분할된 상태로 생성됨 |
| Row Parallel | 가중치 행렬을 행 단위로 분할하여 병렬 연산 | 입력 텐서가 분할되어야 함 (All-Reduce 수반) |
| Attention Head | 트랜스포머의 병렬 연산 단위 | 헤드 수의 배수로 GPU 분할 시 효율적 |
| All-Reduce / All-Gather | 분산된 연산 결과를 동기화/합산 | 계층당 2회(MLP 기준) 발생하도록 설계 |

> 요약: 행렬을 세로(Column) 또는 가로(Row)로 쪼개어 연산하고, 그 중간 결과를 통신으로 합치는 구조다.

---

## Ⅲ. 동작원리 및 흐름도

```text
[MLP 블록에서의 텐서 병렬화 흐름]
Input -> [Col-Parallel Linear 1] -> [GeLU Activation] -> [Row-Parallel Linear 2] -> [All-Reduce] -> Output
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 입력 텐서를 모든 GPU에 복제(Replication) 또는 분할 전달 | 전송 오버헤드 최소화 |
| 2 | 첫 번째 선형 계층(Linear)을 열 단위로 분할하여 각 GPU가 연산 | 출력 채널의 독립적 계산 |
| 3 | 활성화 함수(Activation) 적용 후 두 번째 선형 계층을 행 단위로 연산 | 통신 없이 중간 단계 통과 |
| 4 | 최종 출력 전 All-Reduce를 수행하여 모든 조각을 합산 | 수치 정밀도 및 동기화 무결성 |

> 요약: 연산 중간에 통신을 최소화하기 위해 열(Column) 분할과 행(Row) 분할을 전략적으로 교차 배치하여 동작한다.

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 분할 단위 | 신경망의 단일 계층(Layer) 내부 | 가장 세밀한(Fine-grained) 병렬화 |
| 통신 특성 | 계층마다 높은 빈도의 고대역폭 통신 필요 | NVLink 미지원 시 성능 급락 |
| 확장 한계 | 보통 단일 노드(8 GPU) 내로 제한 | 노드 간 통신 지연 시 효율 저하 |
| 메모리 절감 | 가중치(Weights) 메모리 점유 1/N로 감소 | 옵티마이저 상태값도 함께 분산 |

> 요약: 메모리 절감 효과는 확실하나, 극심한 통신 부하로 인해 하드웨어 토폴로지 종속성이 매우 강하다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 파이프라인 병렬화 (PP) | 텐서 병렬화 (TP) | 선택 기준 |
|:---|:---|:---|:---|
| 병렬화 방향 | 수직적 (Layer-wise) | 수평적 (Intra-layer) | 모델의 너비 vs 깊이 |
| 통신 대역폭 | 낮음 (Inter-node 가능) | 매우 높음 (Intra-node 한정) | 인터커넥트 인프라 수준 |
| 연산 중첩 | 마이크로배치로 중첩 유도 | 연산 자체가 분산되어 실행 | 지연 시간(Latency) 목표 |

> 요약: 모델이 깊으면 PP를, 모델이 넓거나 낮은 지연 시간이 중요하다면 TP를 우선 선택한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 통신 오버헤드 | All-Reduce 지연에 따른 GPU 대기 | NVLink, NVSwitch 활용 및 그룹 크기 최적화 | Communication Time Ratio |
| 정밀도 하락 | 잦은 합산 연산에 따른 반올림 오차 | FP32 누적 연산 또는 Mixed Precision 튜닝 | Weight/Gradient Drift |
| 로드 불균형 | 헤드 수와 GPU 수가 맞지 않을 때 발생 | GPU 수의 배수로 헤드 수/차원 설계 | SM Utilization Balance |

> 요약: 통신 병목과 정밀도 리스크는 고속 패브릭 활용과 정교한 하이퍼파라미터 설계로 관리한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| Latency 단축 | 단일 GPU 연산 대비 1/N 근접 | 커널 실행 시간 측정 (Nsight) |
| 통신 처리량 | NVLink 최대 대역폭의 70% 이상 | NCCL-Test (All-Reduce) |
| 메모리 효율 | 가중치 점유율 1/N 달성 여부 | `nvidia-smi` 및 메모리 프로파일러 |

> 요약: 지연 시간 단축 효과와 실제 통신 효율 지표를 통해 도입 성공 여부를 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. Megatron-LM 최적화: 어텐션 헤드와 MLP 중간 차원을 GPU 수의 배수로 정렬하여 텐서 병렬화 연산 효율을 극대화
2. Sequence Parallelism 병행: 텐서 병렬화에서 복제되던 LayerNorm 및 Dropout 영역의 데이터까지 샤딩하여 메모리 추가 절감
3. 노드 내 TP 우선 배치: 텐서 병렬화 그룹을 동일 노드 내 NVLink로 묶고, 노드 간에는 파이프라인 병렬화를 적용하는 하이브리드 설계

**결론 (2줄):**
- 기술사 판단: 텐서 병렬화는 LLM의 거대 행렬을 다루는 가장 강력한 도구이나, 통신 비용이라는 트레이드오프가 확실하므로 하드웨어 가속기(NVSwitch)와 밀접하게 설계되어야 한다
- 향후 방향: 통신 오버헤드를 근본적으로 제거하기 위해 연산과 통신을 하드웨어 수준에서 통합하는 차세대 AI 아키텍처로 진화할 것이다
