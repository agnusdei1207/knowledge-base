# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: 검색어(Keyword)가 정확히 일치하지 않아도, 문장의 '숨은 뜻(의도, 문맥, 동의어)'을 기계가 이해하여 가장 의미가 유사한 문서를 찾아주는 검색 방식.
- **필요성**: 기존 키워드 검색은 "비 오는 날 신는 신발"이라고 검색하면 "장화", "레인부츠"를 찾아주지 못함. (어휘 불일치 문제).
- **핵심 직관**: 단어를 글자 그대로 보지 않고, 단어가 가진 느낌(의미)을 다차원 공간의 좌표(점)로 찍음. "사과"라는 점 근처에 "Apple", "과일"이라는 점이 모여 있는 식. 질문의 좌표와 가장 거리가 가까운 문서를 반환함.

## 깊이 이해
- **배경**: 구글의 BERT(2018) 이후 자연어 처리(NLP) 혁명이 일어나며, 단어를 숫자의 배열(Embedding Vector)로 바꾸는 기술이 성숙함. MS Bing 등에서 도입하여 검색 품질을 비약적으로 끌어올림.
- **작동 원리**:
  1. (사전 작업): 모든 문서를 딥러닝 인코더(예: BERT)에 넣어 768차원 등의 벡터(Vector)로 변환해 저장함.
  2. (검색 시): 사용자가 "자동차 환불"이라고 치면, 이 질문 역시 768차원 벡터로 변환됨.
  3. 두 벡터 간의 각도나 거리(Cosine Similarity 등)를 계산.
  4. 단어가 "승용차 반품"이더라도, 벡터 공간상에서는 "자동차 환불"과 매우 가까우므로 정답으로 반환됨.
- **구체 예시**: 사내 규정 봇. Q: "아빠 돌아가셨어" $\rightarrow$ A: "부친상 조의금 규정 3조에 따르면..." (키워드 매칭으로는 절대 찾을 수 없는 문맥적 연결).
- **흔한 오해/주의점**: "의미 검색이 무조건 키워드 검색보다 좋다"는 것은 환상임. "오류코드 E-9980"이나 특정 사람 이름 같은 '고유명사'는 좌표 공간에서 뭉뚱그려질 수 있어, 이런 경우엔 옛날 키워드 검색이 훨씬 빠르고 정확함. 그래서 하이브리드(Hybrid)가 필수.

## 연결 개념
- **Dense Retrieval (밀집 검색)**: 의미 검색을 구현하는 가장 대표적인 기술. (벡터 공간이 0 없이 빽빽하게 숫자로 차 있다는 뜻).
- **BM25 / Sparse Retrieval**: 의미 검색의 반대말(전통적 키워드 매칭).
- **Embedding (임베딩)**: 글자를 컴퓨터가 이해할 수 있는 벡터(숫자 좌표)로 변환하는 기술.

# 📝 【답안용】 시험 답안 템플릿
## 핵심 인사이트 (3줄 요약)
- **본질**: Lexical(어휘적) 일치도에 의존하는 한계를 벗어나, 딥러닝 기반 임베딩 모델(Encoder)을 통해 질의와 문서 간의 Semantic(의미적) 코사인 유사도를 계산하는 검색 패러다임.
- **가치**: 동의어(Synonym), 다의어(Polysemy), 문맥(Context)에 따른 어휘 불일치(Vocabulary Mismatch) 문제를 근본적으로 해결하여 재현율(Recall)을 획기적으로 상승시킴.
- **판단 포인트**: 모델 인코딩 병목 및 Vector DB 조회에 따른 응답 지연(Latency) 통제, 고유명사/도메인 특화 용어에 대한 OOV(Out-of-Vocabulary) 취약점을 하이브리드 아키텍처로 보완하는 전략 설계.

## Ⅰ. 개요 및 필요성
- **정의**: 사용자의 질의와 코퍼스(문서)를 사전 학습된 언어 모델(Pre-trained Language Model)을 통해 고차원 임베딩 벡터로 변환하고, 벡터 공간 내에서의 거리를 측정하여 연관 문서를 추출하는 기술.
- **배경**: 전통적인 TF-IDF, BM25 등 통계 기반의 검색은 "사과"와 "Apple"을 완전히 다른 개체로 인식하여, 질의에 사용된 단어가 문서에 명시되지 않으면 검색을 실패하는 구조적 한계가 존재.
- **필요성**: 자연어 형태로 입력되는 대화형 AI, QA 시스템, RAG 아키텍처에서 사용자 의도(Intent)를 정확히 반영하는 맥락 인지형(Context-aware) 정보 검색을 제공하기 위함.

## Ⅱ. 의미 검색 파이프라인 아키텍처
```text
[ Offline: Indexing ]
  Corpus(문서셋) -> [ Bi-Encoder (BERT 등) ] -> Dense Vectors -> [ Vector DB 저장 (ANN Index) ]

[ Online: Searching ]
  User Query -> [ Bi-Encoder ] -> Query Vector 
                                      |
                      (Cosine Similarity / Dot Product 연산)
                                      |
                              [ Top-K 결과 반환 ]
                                      |
                        [ Cross-Encoder (선택적 리랭킹) ]
```

## Ⅲ. 핵심 구성 요소 및 작동 메커니즘
| 구성 요소 | 핵심 역할 및 특징 |
|:---|:---|
| **Bi-Encoder** | 질의와 문서를 각각 독립적으로 768~1536차원의 벡터로 인코딩. (속도가 빠름) |
| **Vector Indexing (ANN)** | 수백만 건의 벡터를 실시간 연산하기 위한 근사 최근접 이웃(HNSW, IVF-PQ) 알고리즘 적용. |
| **Similarity Metric** | 코사인 유사도(방향성), 유클리디안 거리(물리적 거리), 내적(Dot Product) 등을 통해 연관성 스코어 산출. |
| **Cross-Encoder (리랭킹)**| 질의와 문서를 동시에 모델에 넣어 더 정밀하게 주의집중(Attention)을 계산. (느리지만 정확함) |

## Ⅳ. 기존 통계 기반 검색(BM25)과의 심화 비교
| 구분 | 통계 기반 검색 (BM25, Sparse) | 의미 검색 (Dense) |
|:---:|:---|:---|
| **매칭 원리** | Keyword Exact Match (형태 일치) | Semantic Match (문맥/의미 유사도) |
| **데이터 구조** | Inverted Index (역색인 구조) | Vector Space (고차원 실수 배열) |
| **강점 (Sweet Spot)**| 고유명사, 제품명, 에러코드 매칭 | 긴 자연어 질의, 동의어/유의어 처리 |
| **약점** | 어휘 불일치 시 Recall '0' | 도메인 특화 약어, 특수 기호 식별 취약 |
| **연산 비용** | 매우 낮음 | 임베딩 인코딩 비용으로 인해 높음 |

## Ⅴ. 도입 시 한계점 및 최적화 전략 (고도화 방안)
- **리스크 1: 도메인 시프트(Domain Shift)에 따른 성능 저하**:
  - 범용 모델(OpenAI ada-002 등)은 일상 언어는 잘 알지만, 특정 기업의 사내 용어나 최신 기술 용어는 엉뚱한 벡터로 매핑함.
  - **대응 방안**: 사내 Q&A 데이터셋을 활용해 오픈소스 인코더 모델(BGE-M3 등)을 Contrastive Learning(대조 학습) 방식으로 미세조정(Fine-Tuning)하여 도메인 특화 임베딩 공간 구축.
- **리스크 2: 의미 검색의 OOV 취약점**:
  - "G320 메인보드"라는 모델명 검색 시, "G330 메인보드"와 의미적 거리가 너무 가까워 오검색이 빈번함.
  - **대응 방안**: BM25 등 통계 기반 엔진과 결합하는 **Hybrid Search** 파이프라인 적용 및 Reciprocal Rank Fusion(RRF) 기반 병합 구현.

## Ⅵ. 실무 적용 및 결론
- **판단 지표**: Recall@K(상위 K개 내 정답 포함 여부), nDCG, 응답 Latency (p95).
- **실무 설계**: 대형 이커머스 상품 검색 엔진 개편 시. "원피스 하객룩"이라는 검색어 입력 시 기존 시스템은 '원피스', '하객룩' 텍스트가 명시된 상품만 100개 도출. 의미 검색 엔진(Sentence-BERT 기반)을 도입하여, 텍스트에 하객룩이 없어도 '단정한', '결혼식', '포멀한' 이라는 메타데이터를 가진 상품들을 벡터 유사도로 매칭해 옴. 전환율(CVR) 15% 상승 증명.
- **결론**: 의미 검색은 키워드라는 '껍데기'를 넘어 지식의 '본질'을 탐색하는 기술적 진보이며, RAG 시대에 LLM의 눈(Eye) 역할을 수행하는 가장 치명적이고 필수적인 데이터 인프라스트럭처임.

### 🔀 문제 유형별 목차 전환
- **Ⅱ·Ⅲ 강조 (개념/원리형)**: 워드 임베딩(Word2Vec)에서 문장 임베딩(Sentence-BERT)으로의 발전 과정, 샴 네트워크(Siamese Network) 아키텍처를 통한 Bi-Encoder 훈련 원리 상세화.
- **Ⅴ·Ⅵ 강조 (실무/설계형)**: Vector DB(Milvus, Pinecone) 구축 시 HNSW 파라미터 튜닝을 통한 Recall-Latency Trade-off 조율, 도메인 파인튜닝 비용 대비 효과(ROI) 분석 중심.
