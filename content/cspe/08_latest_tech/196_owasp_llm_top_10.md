## 미리 알고가기

- OWASP LLM Top 10은 LLM 기반 애플리케이션의 우선 보안 위험을 정리한 실무 기준임
- 최신 OWASP GenAI 2025는 모델 자체보다 앱·데이터·운영 생명주기 위험을 함께 본다는 점이 중요함
- 각 항목은 단일 모델 문제가 아니라 프롬프트와 RAG와 권한과 공급망이 얽힌 시스템 위험으로 해석해야 함

## Ⅰ. 개요

- **정의/개념**: OWASP LLM Top 10은 거대 언어 모델과 생성형 AI 애플리케이션을 설계·배포·운영할 때 우선적으로 통제해야 할 대표 보안 위험과 대응 방향을 정리한 실무 프레임워크임
- **배경/필요성**: 기존 웹 보안 목록만으로는 프롬프트 주입과 데이터 유출과 에이전트 권한 오남용 같은 생성형 AI 특유의 위험을 충분히 설명하기 어려워 별도의 보안 공통 언어가 필요해짐

## Ⅱ. 특징

- 모델 단독 취약점이 아니라 입력과 데이터와 도구와 운영 전 과정을 하나의 공격면으로 봄
- DevSecOps와 MLSecOps가 공통 체크리스트로 활용하기 쉬운 실무 지향 구조를 가짐
- 항목 간 연계가 강해 한 위험이 다른 위험의 진입점이 되는 경우가 많음
- 버전 업데이트에 따라 명칭과 순서가 조정될 수 있으므로 현재판 기준 적용이 중요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 2023/24 초기판 초점 | 2025 OWASP GenAI 초점 |
|:---|:---|:---|
| 관점 | LLM 애플리케이션 기본 위험 정리 | GenAI 앱 전주기 위험 정교화 |
| 강조점 | 프롬프트, 출력, 오염, DoS | 민감정보, 공급망, 에이전시, 소비 통제 |
| 활용 방식 | 초기 도입 점검표 | 운영 통제와 거버넌스 확장 |
| 실무 의미 | 위험 인식 시작점 | 보안 설계와 운영 기준점 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Prompt, Input Risk | 프롬프트 인젝션과 jailbreak처럼 모델 제어 흐름을 흔드는 입력 계층 위험을 다룸 |
| Data, Privacy Risk | 민감정보 노출과 오염과 RAG 접근 통제처럼 데이터 흐름 관련 위험을 다룸 |
| Supply Chain, Dependency Risk | 외부 모델과 라이브러리와 플러그인과 데이터셋의 무결성과 신뢰를 검토함 |
| Agency, Output, Consumption Risk | 도구 권한과 출력 처리와 자원 소비가 실제 피해로 이어지는 운영 계층 위험을 다룸 |
| Governance, Testing Loop | 레드팀과 정책과 CI/CD 검증으로 위험을 지속 관리하는 운영 체계를 요구함 |

```text
+-------------------+      +-------------------+      +-------------------+
                                                           |
                                                           v
                                                   +-------------------+
                                                   | Governance / Test |
                                                   +-------------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 위험 항목 식별    | --> | 시스템 매핑 수행  | --> | 통제/테스트 적용 | --> | 운영 중 재평가  |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **위험 항목 식별**: 적용 대상 서비스와 관련된 Top 10 항목을 선별함
2. **시스템 매핑 수행**: 프롬프트와 RAG와 도구 권한과 공급망에 항목을 매핑함
3. **통제 및 테스트 적용**: 가드레일과 접근제어와 레드팀과 모니터링을 배치함
4. **운영 중 재평가**: 버전과 아키텍처 변화에 따라 통제를 갱신함

## Ⅵ. 문제점 및 해결 방안

1. 문제: OWASP LLM Top 10을 단순 문서 체크리스트로만 쓰면 실제 아키텍처의 고위험 경로가 시스템에 반영되지 않을 수 있음
   - 해결방안: threat modeling과 control mapping을 수행하고 checklist coverage와 architecture traceability로 검증함
2. 문제: 버전이 바뀌는데 과거 항목 정의만 고정 사용하면 최신 위협과 명칭 체계를 혼동해 대응 우선순위가 어긋날 수 있음
   - 해결방안: current version baseline을 운영하고 control update cycle과 version alignment score로 검증함
3. 문제: 한 항목씩 분절 대응하면 프롬프트 인젝션과 과도한 권한 위임처럼 결합형 위험을 놓칠 수 있음
   - 해결방안: cross-risk scenario test를 적용하고 compound attack detection rate와 end-to-end control coverage로 검증함

## Ⅶ. 적용 사례

- 사내 챗봇 플랫폼이 OWASP LLM Top 10을 기준으로 prompt·RAG·tool 권한 점검을 수행하며 확인 지표는 control coverage와 incident reduction rate임
- 공개 API 서비스가 소비 통제와 민감정보 차단과 공급망 검증을 묶어 운영하며 확인 지표는 vulnerability closure time과 data leakage incident rate임
- 에이전트 서비스가 OWASP 항목 기반 레드팀 시나리오를 정기 실행하며 확인 지표는 attack success rate와 patch lead time임

## Ⅷ. 결론

OWASP LLM Top 10은 생성형 AI 보안을 개별 모델 문제가 아니라 애플리케이션 생명주기 문제로 보게 만드는 기준이므로 설계와 운영과 테스트에 함께 반영되어야 함.
