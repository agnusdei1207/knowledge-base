## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 언어 모델(LLM)이 문제를 풀 때 머릿속으로 **추론(Reasoning, 생각)**만 하거나 무턱대고 **행동(Acting, 도구 사용)**만 하는 것이 아니라, "생각하고 $\to$ 행동하고 $\to$ 관찰하고 $\to$ 다시 생각하는" 인간의 논리적 문제 해결 과정을 그대로 흉내 낸 프롬프팅 아키텍처다.
> 2. **가치**: 환각(Hallucination)에 빠져 헛소리를 지어내던 LLM에게 외부 세계(위키피디아, 검색 엔진, API)와 끊임없이 소통하며 자신의 생각을 교정할 기회를 줌으로써, AI 에이전트 시스템을 구현하는 사실상의 표준(De facto standard) 두뇌 엔진으로 자리 잡았다.
> 3. **판단 포인트**: 'Thought(사고) - Action(행동) - Observation(관찰)'로 이어지는 명시적인 반복 루프 메커니즘을 이해하고, 단순 Chain-of-Thought(CoT)와의 결정적 차이(외부 환경과의 상호작용 여부)를 설명해야 한다.

## Ⅰ. 개요 및 필요성
- **개요**: ReAct(Reasoning + Acting)는 프린스턴 대학교와 구글 연구진이 제안한 프롬프팅 기법으로, 언어 모델이 추론 궤적(Reasoning Trace)을 생성하는 동시에 작업을 위한 행동(Task-specific Actions)을 번갈아 가며 수행하도록 유도하는 방법론이다.
- **배경**: 이전까지 LLM의 추론 능력을 높이려면 "차근차근 생각해보자(Chain of Thought)"라고 타이르는 수밖에 없었다. 하지만 CoT는 모델 내부의 지식만 쓰기 때문에 최신 정보가 없으면 결국 그럴싸한 거짓말(환각)을 지어내며 논리가 붕괴되었다.
- **필요성**: 요리를 하려면 머리로 레시피를 떠올리는 것(Reasoning)뿐만 아니라, 직접 냄비 뚜껑을 열어보고 냄새를 맡으며(Observation) 레시피를 수정(Action)해야 한다. LLM도 외부 환경에서 최신 데이터를 찍어 먹어보고 스스로 논리를 보정하는 동적 핑퐁 시스템이 절실히 요구되었다.

## Ⅱ. 아키텍처 및 핵심 원리

```text
       [ 사용자 질문: "2024년 올림픽 개최국의 현재 수도 날씨는 어때?" ]

  ┌─────────────────────────── ReAct Loop (반복 루프) ───────────────────────────┐
  │                                                                            │
  │  1. [ Thought (생각) ] : "음, 2024년 올림픽 개최국이 어디인지 먼저 찾아야겠다."│
  │           │                                                                │
  │  2. [ Action (행동) ]  : SearchAPI 호출 ──▶ 파라미터: "2024 올림픽 개최국"     │
  │           │                                                                │
  │  3. [ Observation(관찰)]: (API 결과) "프랑스 파리"                           │
  │           │                                                                │
  │  4. [ Thought (생각) ] : "개최국 수도는 파리구나. 이제 파리의 날씨를 알아내자."│
  │           │                                                                │
  │  5. [ Action (행동) ]  : WeatherAPI 호출 ──▶ 파라미터: "파리"                │
  │           │                                                                │
  │  6. [ Observation(관찰)]: (API 결과) "맑음, 25도"                            │
  │           │                                                                │
  │  7. [ Conclusion(결론)]: "프랑스 파리이며, 현재 날씨는 맑고 25도입니다."     │
  │                                                                            │
  └────────────────────────────────────────────────────────────────────────────┘
```

- **1단계 [Thought (사고 궤적 생성)]**: LLM이 현재 목표를 달성하기 위해 자신이 무엇을 모르는지, 지금 당장 무엇을 해야 할지를 자연어 문장으로 독백(Reasoning)한다.
- **2단계 [Action (행동 및 도구 호출)]**: 생각한 내용을 바탕으로 외부 도구(Tool)를 실제로 호출한다. (예: `Action: Search[애플 주가]`).
- **3단계 [Observation (관찰 및 피드백)]**: 외부 도구가 뱉어낸 실제 결과값(API Response, 검색 결과)을 텍스트로 받아 LLM의 컨텍스트(Context) 창에 집어넣는다.
- **4단계 [반복 또는 종료]**: LLM은 방금 들어온 관찰 결과를 보고 다시 다음 `Thought`를 생성한다. 모든 정보가 모여 정답을 도출할 수 있으면 루프를 빠져나와 사용자에게 최종 답변을 생성한다.

## Ⅲ. 비교 및 연결

| 비교 축 | 표준 프롬프팅 (Standard) | Chain of Thought (CoT) | ReAct (Reasoning + Acting) |
|:---:|:---|:---|:---|
| **작동 방식** | 질문 $\to$ 답변 (한방에 찍기) | 질문 $\to$ 머릿속으로 단계별 생각 $\to$ 답변 | 질문 $\to$ 생각 $\to$ **외부 행동/관찰** $\to$ 답변 |
| **지식의 출처** | 모델 내부의 고정된 가중치 (과거 지식) | 모델 내부의 고정된 가중치 (과거 지식) | **외부 세계의 최신 실시간 데이터 (API, 검색)** |
| **환각(Hallucination) 방어**| 매우 취약 (모르면 지어냄) | 취약 (생각하다가 딴길로 샘) | **가장 강력함 (실제 데이터를 보고 교정함)** |
| **에이전트 구현 가능성** | 불가 | 불가 | **AI 에이전트의 핵심 두뇌 엔진으로 작동** |

> ※ **연결 포인트**: ReAct 패턴은 단순히 프롬프트 엔지니어링의 기법을 넘어서, LangChain이나 LlamaIndex 같은 LLM 프레임워크에서 '에이전트(Agent)'를 생성하는 기본(Default) 클래스로 완전히 내재화되었다. 개발자가 도구(Tools) 목록만 쥐여주면 프레임워크가 알아서 이 ReAct 루프를 돌려버린다.

## Ⅳ. 실무 적용 및 기술사 판단

- **적용 사례 1 (사내 IT 헬프데스크 봇 구축)**: 사내 메신저에 직원이 "나 비밀번호 까먹었어"라고 치면, ReAct 에이전트가 1) **Thought**: '직원 ID를 사내 DB에서 조회해야지', 2) **Action**: `QueryDB[직원이름]`, 3) **Observation**: '사번 1234', 4) **Thought**: '초기화 API를 때리자', 5) **Action**: `ResetPW[1234]` 식으로 움직여, 환각 없이 완벽하게 사내망과 연동된 문제 해결사 역할을 한다.
- **적용 사례 2 (데이터 분석 에이전트)**: "올해 1분기 매출 데이터를 꺾은선 그래프로 그려줘." ReAct는 1) DB에서 매출 쿼리 실행(Action), 2) 에러 발생(Observation), 3) "아, 컬럼명이 틀렸구나" 파악(Thought), 4) 수정된 쿼리 재실행(Action), 5) 파이썬 샌드박스에서 맷플롯립(Matplotlib) 코드 실행(Action)의 루프를 거쳐 완벽한 그래프 이미지를 도출한다.
- **기술사 판단**: ReAct의 맹점은 "토큰 소비량의 폭발"과 "지연 시간(Latency)"이다. 생각하고 행동하는 모든 루프 궤적이 프롬프트 창에 계속 누적되므로, 루프가 4~5번만 돌아도 입력 토큰 비용이 눈덩이처럼 불어나고 응답이 10초 이상 지연된다. 아키텍트는 ReAct 에이전트 설계 시 **최대 반복 횟수(Max Iterations)**를 강제로 제한하여 무한 루프 늪에 빠져 API 과금이 폭발하는 사태를 시스템 레벨에서 하드코딩으로 막아야 한다.

## Ⅴ. 기대효과 및 결론

- **기대효과**: LLM의 가장 큰 약점이었던 '최신 정보 부재'와 '블랙박스형 헛소리'를 실시간 외부 환경과의 동적 교감(Interactive)을 통해 억제하고, 오류 발생 시 자기 교정(Self-Correction)이 가능한 강건한 시스템을 구축한다.
- **향후 발전 방향**: 최근에는 프롬프트로 억지로 ReAct 포맷을 강제하는 단계를 넘어, OpenAI의 Function Calling처럼 모델 자체가 내부적으로 '도구를 써야 할 타이밍'을 네이티브하게 알아채고 JSON으로 뱉어주는 기능과 융합되어, ReAct의 안정성과 속도가 비약적으로 상승하고 있다.

### 📌 관련 개념 맵
- **환각 (Hallucination)**: LLM이 정답을 모를 때 "모른다"고 하지 않고, 말도 안 되는 헛소리를 뻔뻔하고 그럴싸하게 지어내는 고질병. ReAct는 외부에서 팩트(Observation)를 주입해 이 병을 치료한다.
- **체인 오브 소트 (CoT, Chain of Thought)**: "Let's think step by step"이라는 마법의 문장을 넣어, LLM이 수학 문제를 풀 때 암산하지 않고 풀이 과정을 주욱 적게 하여 추론 능력을 뻥튀기시키는 프롬프트 스킬. ReAct의 뼈대가 되었다.

### 📈 관련 키워드 및 발전 흐름도
`Few-Shot 프롬프팅 (예시 주기)` $\to$ `Chain of Thought (단계별 생각 유도)` $\to$ `ReAct (생각 + 외부 도구 행동 결합)` $\to$ `Plan-and-Solve (먼저 전체 계획 짜고 실행)` $\to$ `OpenAI Function Calling (네이티브 API 호출 지원)`

### 👶 어린이를 위한 3줄 비유 설명
1. 길을 잃었을 때 머릿속으로만 "우리 집이 어디지? 왼쪽인가?" 계속 상상만 하는 아이(기존 인공지능)는 결국 엉뚱한 길로 가게 돼요.
2. ReAct 아이는 "집이 어디지?(생각) $\to$ 지나가는 경찰관 아저씨한테 물어봐야겠다!(행동) $\to$ 아저씨가 오른쪽이래!(관찰) $\to$ 아항, 오른쪽으로 가야지!(결론)" 이렇게 행동합니다.
3. 머리로만 고민하지 않고, 바깥세상의 도움을 받아가며 생각과 행동을 핑퐁처럼 반복해서 완벽하게 목적지를 찾아내는 아주 영리한 문제 해결 방법이랍니다!
