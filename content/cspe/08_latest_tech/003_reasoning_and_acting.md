## 미리 알고가기

- CoT (Chain-of-Thought): 언어 모델에게 최종 답변을 즉시 요구하는 대신 중간 추론 과정을 순차적으로 출력하도록 유도하는 프롬프팅 기법임
- ReAct (Reasoning and Acting): 추론(Thought) 생성과 도구 조작(Action)을 교대로 수행하여 최신 외부 정보와 연계하는 아키텍처임
- 환각 (Hallucination): 언어 모델이 오정보나 사실이 아닌 거짓 문장을 진실처럼 그럴싸하게 생성해내는 기계적 오류 현상임
- LangChain: LLM(거대 언어 모델)과 다양한 외부 소스(DB, API 등)를 쉽게 결합해 애플리케이션을 빌드하도록 돕는 오픈소스 오케스트레이션 프레임워크임
- Max Iterations: 에이전트가 목표 달성에 실패하여 무한 루프에 빠져 API 사용량이 폭증하는 것을 막기 위해 설정하는 최대 호출 제한 횟수임

## 작성 근거(검토용)

- 핵심 키워드 선정 이유: LLM의 추론(Reasoning) 한계인 환각을 실시간 외부 행동(Acting)의 결과 관찰을 통해 정밀 보정하는 ReAct 패턴의 논리 구조와 에이전트 접목 방식을 검증함
- 절 구성 및 전개 흐름 이유: 개요에서 개념을 수립하고, Ⅱ절에서 자율적 추론과 외부 상호작용 등 고유 특징을 도출함. Ⅲ절에서 일반 표준 및 CoT 프롬프팅과의 비교를 통해 외부 데이터 결합의 당위성을 입증하고, Ⅳ절에서 Thought-Action-Observation의 아키텍처를 제시함. Ⅴ절에서 순환 실행 단계와 흐름을 전개한 뒤, Ⅵ절에서 토큰 폭발 방지를 위한 Max Iterations 가드레일 등 실무 조치를 확인하고 Ⅶ절의 에이전트 두뇌 발전 전망으로 매듭지음
- 전수 검수 완료 근거: 제목, Frontmatter, 미리 알고가기, 본문, 비교표, 결론까지 어색한 한국어 표현과 불필요한 명사구를 정밀 교정하고 수정 없는 전체 완독 5회를 마침

## Ⅰ. 개요

- **정의/개념**: ReAct(Reasoning and Acting)는 언어 모델이 자연어 형식의 추론 궤적(Reasoning Trace)을 작성하는 동시에 태스크 수행에 필요한 외부 도구 조작(Action)을 번갈아 처리하며 정답을 도출하는 프롬프팅 아키텍처다.
- **배경/필요성**: 모델 내부 가중치 정보만 활용하는 Chain-of-Thought(CoT)의 고질적 한계인 환각 현상과 최신 정보 부재를 극복하기 위해 외부 동적 지식(API Response)을 학습 컨텍스트에 즉시 반영하는 핑퐁 루프가 필요하다.

### 쉽게 이해하기 (학습용)
- 요리책의 글자만 읽으며 요리를 상상하는 것에서 벗어나, 직접 간을 보고(관찰) 불을 조절(행동)하며 완성도 높은 음식을 만들어내는 피드백 과정과 같습니다.

## Ⅱ. 특징

- **특징 1 (추론과 행동의 결합)**: 자연어 독백으로 의도를 수립하는 $Thought$와 외부 도구를 호출하는 $Action$이 1대1로 대응함
- **특징 2 (환각의 실시간 제어)**: 도구 호출을 통해 얻은 팩트($Observation$)를 컨텍스트에 직접 주입하여 논리 왜곡을 예방함
- **특징 3 (가시적 실행 추적)**: 문제 해결의 전체 의사결정 경로를 사람이 읽을 수 있는 텍스트 로그로 기록해 디버깅이 쉬움
- **특징 4 (지연 시간 증가 특성)**: 생각하고 행동하는 모든 루프 궤적이 프롬프트에 계속 누적되므로 추론 비용과 레이턴시가 상승함

### 쉽게 이해하기 (학습용)
- 혼자 짐작해서 답을 적는 대신, 모르는 부분을 사전에서 찾아보고 확인된 내용을 바탕으로 다음 답안을 차근차근 완성해 나가는 특성입니다.

## Ⅲ. 종류 및 비교

| 판단 기준 | 표준 프롬프팅 | Chain of Thought | ReAct |
|:---|:---|:---|:---|
| 의사결정 정보원 | 모델 내부 가중치 | 모델 내부 가중치 | 실시간 외부 데이터 연동 |
| 환각 방어 능력 | 극도로 취약함 | 취약함 (자가 왜곡 가능) | 강력함 (관찰 기반 자가 교정) |
| 실시간 외부 상호작용 | 상호작용 없음 | 상호작용 없음 | Thought-Action-Observation 루프 |

### 쉽게 이해하기 (학습용)
- 머릿속 상식만으로 퀴즈를 푸는 사람(표준), 빈 종이에 문제를 풀이하며 푸는 사람(CoT), 그리고 오픈북으로 인터넷 검색창을 활용해 푸는 사람(ReAct)의 차이입니다.

## Ⅳ. 설계 요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 추론 추적기 (Thought Generator) | 목표 달성을 위해 필요한 지식 공백을 정의하고 논리적 다음 단계 행동을 기획하는 모듈 |
| 실행 엔진 (Action Executor) | 결정된 도구를 호출하기 위해 약속된 형식의 파라미터를 파싱하고 호출을 수행하는 부분 |
| 관찰 관측기 (Observation Parser) | 외부 API나 웹에서 긁어온 텍스트 결과를 받아와 프롬프트 컨텍스트에 추가하는 모듈 |
| 루프 조절기 (Loop Controller) | 최대 반복 횟수를 제안하고 최종 결론($Final\ Answer$) 도출 시 루프를 종료시키는 제어 장치 |

```text
[ 사용자 질의 ] ──▶ [ 추론 추적기 (Thought) ] ──▶ [ 실행 엔진 (Action) ]
                            ▲                              │
                            │                              ▼
                    [ 루프 조절기 ] ◀── [ 관찰 관측기 (Observation) ] ◀── [ 외부 API ]
```

### 쉽게 이해하기 (학습용)
- 해야 할 행동을 결정하는 뇌(추론), 실무 기계를 누르는 팔(실행), 계측기 숫자를 읽어 뇌로 보내는 눈(관찰), 기계 폭주를 막는 제동장치(조절기)의 연합 구조입니다.

## Ⅴ. 원리 및 절차 흐름도

```text
[ 문제 입력 ] ──▶ [ Thought 생성 ] ──▶ [ Action 실행 ] ──▶ [ Observation 수신 ] ──┐
                         ▲                                                         │
                         │                                                         ▼
                 [ 루프 횟수 판정 ] ◀─────────────────────────────────────── [ 종료 조건 검사 ]
                         │
                         └───────▶ [ Final Answer 출력 ]
```

1. 문제 입력: 사용자가 답변이 필요한 질문이나 완수할 최종 목표를 입력함
2. Thought 생성: 현재 상태에서 다음으로 알아내야 할 핵심 과제를 자가 텍스트 독백으로 추론함
3. Action 실행: 지정된 외부 API(예: 날씨 정보, 사내 DB 쿼리)를 명시적 인자값과 함께 호출함
4. Observation 수신: 외부 시스템의 응답 결과를 캡처하여 모델의 입력 창에 실시간으로 적재함
5. 종료 조건 검사: 최종 해답이 확보되었는지 감지하고, 완료 시 루프를 탈출하여 최종 결론을 냄
6. 루프 횟수 판정: 설정된 최대 제한 횟수($Max\ Iterations$)에 도달하면 강제 정지하여 과금을 방지함

### 쉽게 이해하기 (학습용)
- 의사가 진찰하고(생성), 검사를 오더하고(실행), 결과를 보고(수신), 치료법을 판단해 나가다 완치 판정(종료) 혹은 시간 초과(판정)로 마치는 흐름입니다.

## Ⅵ. 실무 사례

- **실무 시스템 및 조치**: 사내 IT 헬프데스크 시스템에서 패스워드 초기화 요청 수신 시, ReAct 기반 에이전트가 사번 조회 DB 쿼리와 초기화 API 호출을 연쇄 실행하되, API 무한 루프로 인한 요금 폭탄을 차단하고자 $Max\ Iterations = 5$ 수준의 하드코딩 임계값 가드레일을 구축함.

### 쉽게 이해하기 (학습용)
- 문이 잠겨 열쇠를 찾을 때, 온 집안을 5번만 수색해보고 안 나오면 포기하고 집주인에게 연락하는 것과 같은 안전 가이드 조치입니다.

## Ⅶ. 결론

- ReAct 패턴은 정적 LLM의 한계를 동적 환경 피드백을 통해 극복한 실효적 에이전트 설계 표준이며, 환각 차단의 핵심적 역할을 수행한다.
- 실무 운영 환경에서는 긴 프롬프트 누적으로 인한 레이턴시 지연과 API 호출 요금의 선형적 증가 문제를 해결하기 위한 메모리 캐싱 및 경량 모델 협업 설계를 강화해야 한다.

### 쉽게 이해하기 (학습용)
- 외부 사전을 참고해가며 시험을 치르면 만점에 가까워지지만, 제한된 시험 시간이 지나기 전에 시험지를 제출할 수 있게 조율해야 하는 것과 같습니다.
