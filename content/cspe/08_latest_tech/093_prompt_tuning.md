## 미리 알고가기

- 프롬프트 튜닝 ($Prompt$ $Tuning$): 사전학습 완료된 거대 모델의 가중치를 고정시키고, 입력되는 텍스트 임베딩 앞부분에만 학습 가능한 임의의 가상 토큰 임베딩 벡터들(Soft Prompt)을 이어 붙여 이 값만 훈련시키는 PEFT의 최외각 경량 최적화 기술임
- 소프트 프롬프트 ($Soft$ $Prompt$): 자연어 단어가 아닌 연속적인 소수(실수) 벡터 형태로 구성되며, 역전파 오차 신호를 타고 자동으로 값이 학습 수렴되는 가상 토큰 묶음임
- 하드 프롬프트 ($Hard$ $Prompt$): 인간이 어휘 사전 내의 문자 단어들을 조합해 "다음 글을 요약해라" 식으로 수동 설계하는 일반 텍스트 지시문임
- 축소 법칙 ($Scaling$ $Law$): 모델 매개변수 규모가 수백억 단위 이상으로 커질수록, 프롬프트 튜닝의 성능 지수가 원래의 전면 미세조정(Full FT) 성능 한계에 점진 수렴한다는 하드웨어 파워 비례 법칙임

## Ⅰ. 개요

- **정의/개념**: Prompt Tuning은 거대 언어 모델의 기저 뇌세포 가중치를 $100\%$ 동결시킨 상태에서, 입력 문장의 단어 임베딩 매트릭스 첫 부분($Prefix$ 영역)에만 학습 가능한 $N$개의 가상 소프트 프롬프트(Soft Prompt) 벡터를 부착하고 이 부분의 임베딩 테이블 값만 업데이트하는 PEFT 최적화 기법임
- **배경/필요성**: 사람이 수동으로 적합한 자연어 지시문을 짜내는 하드 프롬프트($Hard$ $Prompt$) 방식은 약간의 띄어쓰기나 단어 변경에도 답변의 편차가 극도로 크게 흔들려 자동 최적화가 불가능했으므로, 훈련 가능한 연속 기하 벡터로 지시문을 치환해 안정성을 갖고자 탄생함

## Ⅱ. 특징

- 트랜스포머 레이어 내부를 전혀 건드리지 않고, 오직 맨 밑바닥 $1$층의 입력 임베딩 층($Embedding$ $Layer$)에만 가상 토큰 벡터를 붙이므로 이식성이 완벽함
- 학습 대상 파라미터 수가 어휘 사전 내 몇 개 단어 크기(수만 개 파라미터 수준)에 불과해 저장 용량이 단 수십 킬로바이트($KB$)로 극도로 가벼움
- 모델의 전체 매개변수 규모가 $10B$(백억)를 넘어 $100B$(천억) 이상으로 팽창할수록, $SFT$(지도 미세조정) 성능을 따라잡는 축소 법칙(Scaling Law)을 충족함

## Ⅲ. 종류 및 비교

| 판단 기준 | 수동 프롬프팅 (Manual Hard Prompt) | 프롬프트 튜닝 (Prompt Tuning) | 접두어 튜닝 (Prefix Tuning) |
|:---|:---|:---|:---|
| **제어 대상 포트** | 사람이 읽을 수 있는 텍스트 단어 조합 | 1층 입력 임베딩 공간의 가상 텐서 ($Soft$ $Prompt$) | 매 레이어 셀프 어텐션 내부 $K, V$ 전단 가상 텐서 |
| **자동 최적화** | 불가능 (시행착오 수동 수정) | 완벽함 (역전파 통해 오차 최소화) | 완벽함 (역전파 통해 오차 최소화) |
| **태스크 전환 속도** | 즉시 전환 (단순 텍스트 교체) | 매우 빠름 (임베딩 1행 핫스왑) | 중간 (레이어별 Prefix 텐서 매핑 스위치 필요) |
| **매개변수 볼륨** | 없음 | 극소량 (수십 킬로바이트 수준) | 소량 (수 메가바이트 수준) |

> 요약: Manual Prompt는 수작업 자연어 조율이고, Prompt Tuning은 1층 문틀 밑에 soft 가이드 텐서를 끼워주는 극소량 조율이며, Prefix Tuning은 층마다 깊이 개입해 어텐션을 유도함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| $Soft$ $Prompt$ 테이블 | 학습을 통해 가중치 값이 계속 변동 수렴하는 임의의 가상 단어 벡터 모음집임 |
| 1층 임베딩 결합기 | 유입된 실제 자연어 토큰 임베딩의 머리 부분에 소프트 프롬프트를 직렬 연결($Concat$)해 주는 모듈임 |
| 동결 파운데이션 | 임베딩 테이블의 Soft Prompt 영역 그래디언트 외에는 모든 업데이트가 차단된 본체 모델임 |
| 테스트 벤치마킹 | 수작업 프롬프트 성능 대비 튜닝본의 정확도 향상 비율을 감사 평가하는 스택임 |

```text
[ Prompt Tuning (1층 임베딩 Concat) 구조 ]
Embedding Matrix: [ Soft Prompt Vector (Learned) ] [ Input Text Tokens (Real) ]
                                    ↓
                       [ Shared Frozen Transformer ]
                                    ↓
                            [ Target Output ]
- 내부 아키텍처 변조가 없으며, 오직 입력 임베딩 단에서만 가상 토큰이 부착되어 가동함
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 가상 임베딩 | --> | 입력 텍스트  | --> | 역전파 통해 | --> | 소프트 벡터 |
| 초기화/부착 |     | 토큰 뒤에결합|     | 임베딩만 갱신|     | 단독 저장/배포|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **소프트 임베딩 세팅** — 사전학습 어휘 사전의 단어들 중 대표 지시어(예: "summarize")의 벡터 값으로 소프트 프롬프트 벡터를 초기화함
2. **벡터 결합** — 사용자의 입력 질문 문장 "다음 보고서를 읽어줘..."의 토큰 임베딩 전단에 소프트 프롬프트 행렬을 합병 연결함
3. **가중치 역전파** — 기반 모델 본체는 `Freeze` 처리하고, 오차 신호를 임베딩 층의 소프트 프롬프트 벡터에만 역전파 적용해 업데이트함
4. **경량 릴리즈** — 학습이 끝난 소프트 프롬프트 파일(수십 KB)만 저장한 뒤, 서빙 장치 로더를 통해 해당 임베딩 행렬을 동적 바인딩해 가동함

## Ⅵ. 실무 적용 및 유의점

1. 기저 백본 모델의 파라미터 체급이 $1B$ 이하로 작으면, 소프트 프롬프트 튜닝의 표현 범위가 좁아 전면 미세조정 대비 지능이 크게 무너지므로, 반드시 기저 모델 크기에 따른 성능 충족 곡선을 사전 벤치마크하여 도입 적합성을 판정해야 함
2. 소프트 프롬프트는 벡터 공간에서 훈련되므로 사람이 육안으로 읽어 무슨 의미인지 해독할 수 없기 때문에, 디버깅을 위해 '하드 프롬프트 대조 벤치마크셋'을 수립하고 이상 응답 시 오류 분류 체계($Failure$ $Taxonomy$)를 구축해 대응해야 함

## Ⅶ. 결론

- 프롬프트 튜닝은 자연어 지시의 파편화 문제를 실수 기하 벡터의 역전파 훈련으로 단숨에 수렴시킨 최고 경량 PEFT 기법이며, 설계자는 기반 모델 체급 한계에 따른 성능 탈락 여부 검증과 의미 파악 불가에 대비한 디버깅용 하드 프롬프트 비교 감사 체계를 상시 보존해야 함
