## 미리 알고가기

- 소형 언어 모델 ($SLM$): 수천억 개의 초대형 파라미터 대신, 보통 $1B \sim 10B$(수십억~백억 개) 규모의 경량 매개변수 구조를 갖는 실용형 인공지능 모델임
- 지식 증류 ($Distillation$): 거대 교사 모델(Teacher)의 연산 확률 값이나 논리 전개 데이터셋을 활용해 소형 학생 모델(Student)을 집중 지도 훈련시키는 기술임
- 미세 조정 ($Fine-tuning$): 특정 비즈니스 도메인의 전문 텍스트 코퍼스를 주입하여, 소형 모델이 특정 전문 용어나 스타일을 체득하게 돕는 추가 전이 학습임
- 할루시네이션 ($Hallucination$): 모델이 학습한 내용에 없는 거짓 사실을 진짜인 것처럼 그럴싸하게 꾸며내어 왜곡 대답하는 환각 현상임

## Ⅰ. 개요

- **정의/개념**: SLM은 초거대 모델 수준의 백본 구조를 모사하되 매개변수 규모를 대폭 축소하고, 정제된 도메인 데이터 학습 및 지식 증류($Distillation$) 기법을 집중 처방하여 한정된 연산 자원 내에서 특정 비즈니스 업무를 정확히 완수하는 실용형 소형 언어 모델임
- **배경/필요성**: 파라미터 수천억 개의 초대형 LLM은 VRAM 하드웨어 도입비, 전력 소비, 실시간 API 과금, 데이터 전송에 따른 사내 기밀 유출 리스크가 너무 크므로, 기업의 온프레미스(On-premise) 폐쇄망이나 에지 모바일 기기에 가볍게 탑재할 모델로 제안됨

## Ⅱ. 특징

- 적은 용량의 물리 RAM(보통 $4 \sim 16$GB 이내) 환경에서도 훌륭히 작동하며, 단순 문장 요약, 키워드 추출, 개체명 인식에서 초대형 LLM 버금가는 품질을 보임
- 기기 로컬 단에서 연산이 완결되므로 인터넷 네트워크 연결 단절 상황에서도 작동을 지속하며, 사용자 프라이버시 침해 우려가 원천 차단됨
- 범용 상식 지식의 함량과 다단계 이산 논리 추론($Reasoning$) 기능은 초대형 모델보다 열세하므로, 외부 RAG 검색기와의 연동 설계가 동반되어야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 초대형 모델 (LLM, GPT-4 등) | 소형 모델 (SLM, Llama-8B / Phi-3 등) | 고전 머신러닝 (ML, SVM 등) |
|:---|:---|:---|:---|
| **파라미터 스펙** | 수천억 ~ 조 단위 이상 | 보통 수십억 ~ 백억 개 내외 ($10B$ 이하) | 매개변수 수 매우 적음 (메가바이트 급) |
| **인프라 이식성** | 낮음 (대형 클라우드 GPU 노드 필수) | 높음 (개인 PC, 모바일, 에지 장비 구동) | 매우 높음 (임베디드 칩 구동 가능) |
| **학습 데이터 초점** | 방대한 웹 코퍼스 전반 (무작위) | 고도로 정제된 전처리 지식 교안, 코딩 교과서 | 소수의 구조화된 피처 데이터셋 |
| **적합한 타깃 업무** | 범용 종합 추론, 미지의 가설 설계 | 사내 매뉴얼 답변, 감성 분류, 단순 요약 | 단일 변수 예측, 스팸 필터 분류 |

> 요약: 초대형 LLM은 범용 고성능 지능이 필요한 헤드쿼터에, SLM은 가성비와 프라이버시가 핵심인 에지 현장 및 전담 태스크에, 고전 ML은 경량 이산 판정에 최적임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 경량 트랜스포머 | 멀티 헤드 수와 어텐션 레이어 깊이를 최소화하여 콤팩트하게 다듬은 핵심 백본망임 |
| 증류 훈련 어댑터 | 교사 모델의 연산 결과 분포($Soft$ $Targets$)를 전달받아 학생 모델 손실 함수에 더해주는 매퍼임 |
| 로컬 $RAG$ 검색 허브 | SLM의 부족한 암기력 한계를 메우기 위해 로컬 파일 DB에서 팩트 원문을 캐서 주입해 주는 인터페이스임 |
| 저정밀 압축 패키지 | 모바일 이식을 위해 가중치를 $4$비트 또는 $8$비트로 감축하여 실행 크기를 더 쪼개주는 경량화 패키저임 |

```text
[ SLM 기반 로컬 RAG 구동 모델 ]
User Query -> [Local RAG Search] -> Retrained context -> [Quantized SLM (8B)] -> Prompt Answer
- 8B 규모의 SLM 후단에 로컬 RAG 장치를 엮어 할루시네이션(환각)을 제거하고 지형 팩트를 보강함
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 업무 도메인 | --> | 교사모델 지식| --> | 4비트 양자화| --> | 프라이빗망  |
| 데이터 정제 |     | 주입 (증류)  |     | 및 경량 압축|     | 탑재/추론 QA|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **데이터 스펙 축적** — 비즈니스 도메인 규칙이 담긴 고품질 대화/기술 코퍼스를 엄선하여 데이터셋 품질을 끌어올림
2. **지식 주입 학습** — 초대형 상위 모델의 사고 패턴 데이터를 입력받아 미세 조정($Fine-tuning$) 및 증류 학습을 실행함
3. **바이너리 압축** — 학습 완료된 가중치에 $Q4\_K\_M$ 등 양자화를 적용해 기기 적재 크기를 $5$GB 내외로 컴팩트하게 축소함
4. **로컬 에지 구동** — 사용자의 디바이스 단에 적재한 뒤 로컬 검색 팩트($Context$)와 결합하여 고품질 가성비 응답을 인출함

## Ⅵ. 실무 적용 및 유의점

1. SLM은 모델 내부에 축적된 암기 지식이 적어 단독 작동 시 그럴싸한 거짓 정보를 말하는 '할루시네이션(환각)'이 심해지므로, 반드시 '로컬 RAG' 검색 아키텍처나 엄밀한 외부 API 가드레일을 연동하고, 답변의 외부 사실 부합률 지표로 이를 검증해야 함
2. 기기 제한 극복을 위해 $4$비트 이하로 과도하게 모델을 압축($Quantization$)하면, 단순 문법 형태조차 어그러지는 성능 붕괴가 생길 수 있으므로, 업무 중요도에 따라 압축 비트 수(INT8 vs INT4)를 이원 조율하고 지연 대비 정확도 보존율 지표로 sweet-spot을 확보해야 함

## Ⅶ. 결론

- SLM은 초거대 모델의 대안을 넘어 비즈니스의 인프라 가성비와 온디바이스 보안 주권을 실현하는 핵심적인 실용형 지능 계층이며, 설계자는 모델의 태생적 암기 한계를 보완할 정교한 RAG 파이프라인 결합과 비트 수 보존 경량화 튜닝을 통합 제공해야 함
