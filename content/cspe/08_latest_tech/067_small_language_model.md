# 📖 【암기용】 개념 완전 이해

> 목적: SLM을 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **정의**: 수억~수십억 파라미터 규모로 특정 업무·단말 환경에 맞춘 소형 언어모델
- **왜 필요한가**: 70B 이상 LLM은 GPU 비용·지연·데이터 반출 문제가 커서 모든 업무에 쓰기 어렵다.
- **핵심 직관**: 대형 백과사전 모델이 아니라, 특정 업무 매뉴얼을 빠르게 처리하는 현장 전담 모델임.

## 깊이 이해
- **배경·문제의식**: 기업 업무의 상당수는 요약·분류·추출·간단 질의처럼 범위가 좁음. 대형 LLM을 매번 호출하면 token 비용과 p95 지연이 SLA를 압박함.
- **작동 원리**: 1B~13B 모델을 도메인 데이터로 instruction tuning하거나, 대형 모델 출력을 distillation하여 작은 모델에 이전함. INT4/INT8 양자화로 CPU·NPU·단일 GPU에서 실행함.
- **비유**: 모든 질문을 종합병원 교수에게 보내지 않고, 현장 간호사 매뉴얼로 해결 가능한 업무를 현장에서 처리하는 구조임.
- **구체 예시**: 7B 모델 FP16은 약 14GB 메모리, INT4는 약 3.5~5GB로 노트북·엣지 장치 배포가 가능함.
- **흔한 오해·주의점**: 작다고 항상 비용이 낮은 것은 아님. 정확도 부족으로 재시도·검증 비용이 늘면 TCO가 증가함.

## 연결 개념
- Model Compression — SLM 배포의 기반
- On-Device AI — SLM 실행 환경
- Distillation — 대형 모델 능력 이전 기법

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: SLM은 제한된 파라미터와 도메인 특화 학습으로 비용·지연·프라이버시를 조정한 언어모델임.
> 2. **가치**: 단순·반복 업무를 로컬 또는 저비용 GPU에서 처리해 클라우드 LLM 호출량을 줄임.
> 3. **판단 포인트**: 정확도, 모델 크기, 양자화, 배포 위치, fallback LLM 연계를 함께 설계해야 함.

## Ⅰ. 개요 및 필요성

SLM은 특정 업무에 맞춘 소형 언어모델임. 대형 LLM의 비용·지연·데이터 반출 한계를 보완하기 위해 도메인 특화와 로컬 추론을 결합한 모델 운영 전략이 필요함.

## Ⅱ. 구조 및 구성요소

```text
Domain Data → SFT/Distillation → Quantization
      → SLM Runtime → Local/Edge/API Serving → Fallback LLM
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Base SLM | 1B~13B 언어모델 | Phi, Gemma, Llama 계열 |
| Tuning Data | 도메인 지시·응답 데이터 | 1K~100K 샘플 |
| Quantization | INT8/INT4 경량화 | 메모리 50~75% 절감 |
| Fallback Router | 어려운 요청을 LLM으로 전달 | confidence threshold |

> 요약: SLM은 도메인 튜닝·양자화·로컬 런타임·fallback 라우팅으로 구성됨.

## Ⅲ. 동작원리 및 흐름도

```text
요청 입력 → 난이도/업무 분류 → SLM 추론
    → confidence 평가 → 충분: 응답, 부족: 대형 LLM fallback
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 업무 범위·민감도 분류 | 도메인 intent 정확도 |
| 2 | SLM 로컬 추론 | p95 지연, tokens/s |
| 3 | confidence·규칙 검증 | 임계값 0.7~0.9 |
| 4 | fallback 또는 최종 응답 | 정확도, 비용 절감률 |

> 요약: SLM은 처리 가능한 요청을 저비용으로 해결하고, 불확실 요청은 대형 LLM으로 넘기는 계층형 구조임.

## Ⅳ. 특징

| 구분 | 대형 LLM | SLM | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 모델 크기 | 70B~1T+ | 1B~13B | INT4 7B 약 3.5~5GB |
| 배포 위치 | 클라우드 GPU | 온디바이스·엣지·단일 GPU | 데이터 반출 최소화 |
| 정확도 | 범용 추론 우위 | 도메인 업무 적합 | fallback 필요 |
| 비용 | API/GPU 비용 높음 | 로컬 추론 원가 낮음 | 재시도율 포함 TCO |

> 요약: SLM은 비용·지연·프라이버시에 유리하나, 복잡 추론은 대형 LLM fallback과 함께 설계해야 함.

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 고객센터 분류·요약은 7B INT4 SLM으로 처리하고 confidence 0.8 미만 요청만 대형 LLM으로 라우팅
2. 사내 문서 추출 업무는 도메인 10K 샘플로 SFT 후 F1 0.85 이상 기준으로 배포
3. 민감정보 업무는 온프레미스 SLM + PII 마스킹 + 감사로그로 데이터 반출 0건 목표 설정

**결론 (2줄):**
- 기술사 판단: 반복·도메인 업무는 SLM, 고난도 추론·범용 생성은 대형 LLM을 선택함.
- 향후 방향: SLM은 distillation, MoE, on-device NPU와 결합해 하이브리드 AI 아키텍처의 기본 계층이 됨.
