## 미리 알고가기

- SLM은 보통 수십억 개 이하 파라미터로 구성된 경량 언어 모델 계열을 가리킴
- 지식 증류와 양자화는 SLM의 성능과 배포성을 동시에 확보하는 대표 기법임
- SLM은 단독 사용보다 RAG나 도메인 파인튜닝과 결합할 때 실무 가치가 커짐

## Ⅰ. 개요

- **정의/개념**: SLM은 트랜스포머 기반 언어 모델의 구조를 유지하면서 파라미터 규모를 줄이고 고품질 데이터 학습이나 증류를 통해 특정 업무 성능을 확보한 경량 언어 모델임
- **배경/필요성**: 초거대 LLM은 비용, 보안, 지연 시간, 장비 요구가 커서 모든 업무에 적용하기 어렵기 때문에, 제한된 자원에서 빠르게 동작하는 실용형 모델 계층이 필요함

## Ⅱ. 특징

- 적은 메모리와 연산 자원으로도 요약, 질의응답, 분류 같은 실무 업무를 수행할 수 있음
- 온디바이스, 엣지, 온프레미스 환경에 배치하기 쉬워 보안과 응답성을 동시에 확보함
- 범용 지식과 장문 추론 능력은 초거대 LLM보다 제한적이므로 업무 범위를 분명히 설계해야 함
- 모델 크기보다 데이터 품질, 증류 전략, 후처리 설계가 성능 차이를 크게 좌우함

## Ⅲ. 종류 및 비교

| 판단 기준 | 초거대 LLM | SLM | 규칙/전통 ML 모델 |
|:---|:---|:---|:---|
| 자원 요구 | 매우 큼 | 낮음 | 매우 낮음 |
| 범용성 | 매우 높음 | 중간 | 낮음 |
| 배포 위치 | 주로 클라우드임 | 온프레미스, 엣지, 디바이스 가능 | 광범위함 |
| 적합 업무 | 범용 생성과 복합 추론 | 도메인 보조 업무 | 명확한 규칙 기반 업무 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Backbone Model | 경량 트랜스포머 구조를 기반으로 언어 이해와 생성의 기본 능력을 제공함 |
| Distillation, Fine-tuning Data | 고품질 학습 데이터와 교사 모델 지식을 주입해 작은 모델의 업무 성능을 끌어올림 |
| Compression Package | quantization과 경량 포맷을 적용해 실제 장비에 탑재 가능한 크기로 줄임 |
| Retrieval, Guardrail Layer | 부족한 지식 범위를 외부 검색과 정책 제어로 보완해 실서비스 안정성을 높임 |

```text
+------------------+     +------------------+     +------------------+     +------------------+
| Backbone Model   | --> | Distill/Finetune | --> | Compression Pack | --> | Retrieval/Guard  |
+------------------+     +------------------+     +------------------+     +------------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 데이터 정제   | --> | 증류/미세조정  | --> | 경량화/배포   | --> | 업무 추론 수행 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **데이터 정제**: 업무 범위에 맞는 고품질 데이터와 예시를 선별함
2. **증류 및 미세조정**: 교사 모델의 표현과 정답 패턴을 학습시켜 작은 모델의 성능을 보강함
3. **경량화 및 배포**: 양자화와 런타임 최적화를 거쳐 목표 장비에 배포함
4. **업무 추론 수행**: 검색, 정책, 프롬프트 템플릿과 결합해 실제 서비스를 제공함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 작은 모델은 지식 범위와 복합 추론 깊이가 제한되어 업무 범위를 넘는 질문에서 답변 품질이 급격히 떨어질 수 있음
   - 해결방안: 업무 범위를 명확히 제한하고 RAG를 결합해 grounding rate와 domain task accuracy로 품질을 검증함
2. 문제: 과도한 경량화는 메모리 이점은 키우지만 추론 품질과 안정성을 함께 훼손할 수 있음
   - 해결방안: INT4, INT8 같은 압축 수준을 업무별로 분리하고 latency 대비 quality drop 비율로 최적 지점을 검증함
3. 문제: 도메인 변화가 빠른 환경에서는 작은 모델이 최신 정책이나 용어를 반영하지 못할 수 있음
   - 해결방안: 주기적 재학습과 문서 기반 검색 갱신을 운영하고 update lead time과 answer freshness로 유지 수준을 검증함

## Ⅶ. 적용 사례

- 사내 규정 질의응답: 폐쇄망에 SLM과 RAG를 함께 배치함, 확인 지표는 answer grounding rate와 p95 latency임
- 모바일 요약 기능: 기기 내에서 메일과 메모 요약을 수행함, 확인 지표는 response time과 battery impact임
- 산업 현장 작업 보조: 설비 매뉴얼 기반 질의응답을 제공함, 확인 지표는 first fix rate와 operator adoption rate임

## Ⅷ. 결론

SLM의 핵심 가치는 초거대 모델을 축소한 대체재가 아니라 제한된 자원과 높은 보안 요구 안에서 실제 업무를 빠르게 수행하도록 설계된 실용형 언어 모델 계층이라는 점임.
