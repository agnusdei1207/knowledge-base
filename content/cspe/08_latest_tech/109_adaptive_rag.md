## 미리 알고가기

- Adaptive RAG는 질의 난이도와 성격에 따라 서로 다른 RAG 경로를 선택하는 구조임
- 모든 질문에 동일한 비용과 검색 깊이를 쓰지 않는다는 점이 핵심임
- query classifier나 router 품질이 비용 절감과 품질 유지의 핵심 변수임

## Ⅰ. 개요

- **정의/개념**: Adaptive RAG는 질의의 유형과 난이도와 정보 필요량을 먼저 판별한 뒤, 단순 응답, 기본 RAG, 고도화 RAG, 다중 홉 검색 같은 적절한 경로로 분기하는 동적 검색-생성 아키텍처임
- **배경/필요성**: 모든 질문에 무거운 검색과 리랭킹과 다단계 추론을 적용하면 비용과 지연이 과도하므로, 질의에 맞는 최소 비용 경로를 선택하는 제어가 필요함

## Ⅱ. 특징

- 단순 질문에는 빠른 경로를 쓰고 복합 질문에는 깊은 경로를 써 비용 효율을 높일 수 있음
- 여러 RAG 패턴을 하나의 서비스 안에 공존시키는 운영형 구조임
- 라우팅 판단이 틀리면 품질 저하와 비용 낭비가 동시에 발생할 수 있음
- 질의 분류 기준과 fallback 정책이 실서비스 체감 품질을 좌우함

## Ⅲ. 종류 및 비교

| 판단 기준 | 고정형 RAG | Adaptive RAG | Agentic RAG |
|:---|:---|:---|:---|
| 경로 선택 | 단일 | 질의별 분기 | 실행 중 동적 계획 |
| 비용 최적화 | 낮음 | 높음 | 중간 |
| 복합 질의 대응 | 중간 | 높음 | 매우 높음 |
| 운영 난도 | 중간 | 높음 | 매우 높음 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Query Router | 질의 난이도와 도메인 성격을 분류해 적절한 RAG 경로를 선택함 |
| Retrieval Profiles | simple, advanced, multi-hop 같은 여러 검색 경로 설정을 보유함 |
| Fallback Policy | 잘못 라우팅된 경우 더 무거운 경로로 재시도해 품질을 보정함 |
| Cost, Quality Monitor | 경로별 latency와 정답률과 비용을 추적해 라우팅 정책을 조정함 |

```text
+-------------------+      +-------------------+      +-------------------+
| Query Router      | ---> | Retrieval Profile | ---> | Fallback Policy   |
+-------------------+      +-------------------+      +-------------------+
                                                           |
                                                           v
                                                   +-------------------+
                                                   | Cost / Quality    |
                                                   +-------------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 질의 특성 분류  | --> | 경로 선택/실행   | --> | 필요 시 fallback | --> | 경로별 답변 반환 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **질의 특성 분류**: 단순 사실, 복합 비교, 정책 질의 등으로 유형을 나눔
2. **경로 선택 및 실행**: 적절한 RAG 프로필을 선택해 검색과 생성을 수행함
3. **필요 시 fallback**: 결과가 불충분하면 더 깊은 경로로 전환함
4. **경로별 답변 반환**: 비용과 품질 균형에 맞는 답변을 제공함

## Ⅵ. 문제점 및 해결 방안

1. 문제: query router가 복합 질의를 단순 경로로 보내면 빠르지만 부정확한 답변이 늘어날 수 있음
   - 해결방안: route별 gold set을 유지하고 routing accuracy와 final answer quality로 분기 품질을 검증함
2. 문제: 반대로 대부분 질의를 무거운 경로로 보내면 adaptive 구조를 둔 이점이 사라질 수 있음
   - 해결방안: 경로별 예산 정책을 운영하고 route distribution과 cost per answer로 비용 최적화를 검증함
3. 문제: fallback 체계가 복잡해지면 장애 분석과 운영 규칙이 어려워질 수 있음
   - 해결방안: 분기 로그와 observability를 강화하고 fallback trigger rate와 MTTR로 운영 복잡도를 검증함

## Ⅶ. 적용 사례

- 고객지원 챗봇이 FAQ는 빠른 경로를 쓰고 복합 정책 질의는 고도화 경로를 사용하도록 Adaptive RAG를 적용하며 확인 지표는 route accuracy와 p95 latency임
- 사내 규정 검색이 단순 조항 검색과 비교 분석 질의를 분리하도록 Adaptive RAG를 활용하며 확인 지표는 answer correctness와 cost per answer임
- 엔터프라이즈 검색 포털이 검색 프로필을 업무별로 운영하도록 Adaptive RAG를 적용하며 확인 지표는 user satisfaction과 route efficiency임

## Ⅷ. 결론

Adaptive RAG의 핵심은 더 많은 기술을 붙이는 것이 아니라 질의마다 필요한 만큼만 검색 비용을 쓰게 만드는 라우팅 설계에 있음.
