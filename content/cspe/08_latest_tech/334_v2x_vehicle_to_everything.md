# 📖 【암기용】 개념 완전 이해

> 목적: V2X를 차량이 주변 차량·인프라·보행자·네트워크와 안전 메시지를 교환하는 협력형 교통 통신으로 이해하게 만든다.

## 한눈에
- **개요**: 차량이 V2V, V2I, V2P, V2N으로 주변 객체와 정보를 교환하는 통신 기술
- **왜 필요한가**: 카메라·레이더는 보이지 않는 교차로, 급정거 차량, 신호 정보까지 직접 감지하지 못한다.
- **핵심 직관**: 차량이 눈으로 보는 센서에 더해 주변 객체와 "말로 알려주는" 협력 인지 채널을 갖는 것이다.

## 깊이 이해
- **배경·문제의식**: 자율주행과 교통안전은 시야 밖 위험, 신호 잔여 시간, 긴급차 접근 정보를 빠르게 공유해야 한다.
- **작동 원리**: 차량은 위치·속도·방향 등 메시지를 주기적으로 송수신하고, 인프라는 신호·공사·위험 정보를 전송한다.
- **비유**: 운전자가 앞차 브레이크등만 보는 것이 아니라 앞앞차와 신호등의 상태를 무전으로 듣는 상황과 같다.
- **구체 예시**: 교차로에서 RSU가 SPaT/MAP 정보를 전송하면 차량은 신호 잔여 시간과 차로 정보를 이용해 감속을 판단한다.
- **흔한 오해·주의점**: V2X는 자율주행 센서를 대체하지 않는다. 인증서, 위치 정확도, 지연, 메시지 신뢰성을 검증해야 협력 인지 입력으로 사용할 수 있다.

## 연결 개념
- C-V2X — 3GPP 기반 차량 통신
- ADAS/ADS — V2X 정보를 활용하는 주행 기능
- PKI — V2X 메시지 인증과 프라이버시 보호

## Ⅰ. 개요 및 필요성

- 개요: 차량 협력 통신
- 배경: 단독 차량 센서는 시야 밖 위험과 교통 인프라 상태를 직접 알 수 없다.
- 필요성: V2X는 저지연 메시지와 인증 체계로 충돌 회피, 신호 최적화, 긴급차 우선 통행을 지원한다.

---

## Ⅱ. 구조 및 구성요소

```text
Vehicle OBU -> V2V / V2I / V2P / V2N Channel
      +-> RSU / Traffic Signal / Cloud
      +-> PKI / Certificate / Misbehavior Detection
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| OBU | 차량 탑재 통신 장치 | 위치·속도 메시지 송수신 |
| RSU | 도로 인프라 통신 장치 | 신호·공사·위험 정보 제공 |
| V2X Stack | 메시지 인코딩·전송·수신 | ITS-G5, C-V2X |
| Security Credential | 인증서·서명·폐기 관리 | pseudonym certificate |

> 요약: V2X는 차량 OBU, 인프라 RSU, 통신 스택, 인증서 체계가 결합된 협력 안전 통신 구조다.

---

## Ⅲ. 동작원리 및 흐름도

```text
차량 상태 측정 -> 안전 메시지 생성 -> 서명·전송
-> 주변 객체 수신 -> 인증·위치 검증 -> ADAS/ADS 판단 반영
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | GPS/IMU/CAN으로 위치·속도·방향을 수집함 | position accuracy |
| 2 | CAM/BSM, DENM, SPaT/MAP 등 메시지를 생성함 | message schema |
| 3 | 메시지 서명 후 무선 채널로 전송함 | certificate validity |
| 4 | 수신 차량이 인증·시간·위치 타당성을 확인함 | latency, false message |

> 요약: V2X는 차량 상태를 표준 메시지로 만들고 인증 후 전송하며, 수신 측은 신뢰성 검증 후 주행 판단에 사용한다.

---

## Ⅳ. 특징

| 구분 | DSRC/ITS-G5 | C-V2X | 판단 기준 |
|:---|:---|:---|:---|
| 기반 | IEEE 802.11p 계열 | 3GPP LTE/5G 계열 | 지역 규제·생태계 |
| 통신 | 직접 통신 중심 | PC5 직접통신+Uu 네트워크 | V2V/V2N 요구 |
| 배포 | 독립 RSU 구축 | 이동통신 인프라 연계 가능 | 커버리지·운영 모델 |
| 검증 | 장기 실증 사례 | 5G 진화 경로 | 단말·칩셋 가용성 |

> 요약: V2X 방식 선택은 기술 우열보다 지역 주파수 정책, 인프라 투자, 직접통신·네트워크 연계 요구로 결정한다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 인지 | 차량 단독 센서 | 협력 메시지+센서 융합 | 시야 밖 위험 여부 |
| 인프라 | 신호 제어 독립 | RSU·클라우드 연동 | 교차로·고속도로 Use Case |
| 보안 | 통신 암호화 중심 | 메시지 서명·인증서 폐기 | 위조 메시지 영향 |

> 요약: V2X는 센서 인지 한계를 보완할 때 가치가 있으며, 안전 기능에 쓰려면 메시지 신뢰성 검증이 선행되어야 한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 위조 메시지 | 인증서 탈취·악성 OBU | PKI, CRL, misbehavior detection | invalid signature count |
| 지연 초과 | 혼잡 채널·백홀 지연 | QoS, edge RSU, 채널 부하 제어 | end-to-end latency |
| 위치 오류 | GNSS 음영·스푸핑 | sensor fusion, plausibility check | position error |

> 요약: V2X 리스크는 위조, 지연, 위치 오류이며 인증·엣지·센서 융합으로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 통신 품질 | latency, packet delivery ratio 추적 | field test, RSU log |
| 보안 | 인증서 검증·폐기 반영 | PKI audit, CRL test |
| 안전 효과 | 경고 누락·오경보율 관리 | scenario replay |

> 요약: V2X 적용 효과는 연결 성공보다 안전 메시지 도달, 인증, 오경보·누락률로 판단한다.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 교차로 충돌 경고, 긴급차 접근, 신호 정보 제공 등 Use Case별 latency와 메시지 종류를 먼저 정의함.
2. 지역 정책에 따라 ITS-G5/DSRC 또는 C-V2X를 선택하고 RSU 위치, 백홀, edge 처리 기준을 설계함.
3. pseudonym certificate, 메시지 서명, 폐기 목록, 이상 메시지 탐지 로그를 보안 운영 체계에 포함함.

**결론 (2줄):**
- 기술사 판단: V2X는 단독 센서가 놓치는 시야 밖 위험을 다룰 때 적용 가치가 크며, 안전 기능에는 인증·지연·위치 검증 조건을 붙여야 함.
- 향후 방향: V2X는 SDV, ADS, 스마트시티 교통 인프라와 결합해 협력형 자율주행 기반으로 확장됨.
