## 미리 알고가기

- RAG는 외부 검색과 생성 모델을 결합해 최신 정보와 내부 지식을 활용하는 구조임
- 파인튜닝은 모델 행동 적응에 강하고, RAG는 사실과 근거 주입에 강함
- 답변 품질은 생성 모델 자체보다 검색 품질과 컨텍스트 구성 품질에 크게 좌우됨

## Ⅰ. 개요

- **정의/개념**: RAG는 사용자의 질의에 대해 외부 지식 저장소에서 관련 문서를 검색하고, 그 문맥을 기반으로 언어 모델이 답변을 생성하도록 하는 검색-생성 결합 아키텍처임
- **배경/필요성**: LLM은 최신 정보와 조직 내부 문서를 기본적으로 알지 못하고 환각 위험도 있으므로, 실시간 근거를 함께 넣어 사실성과 갱신성을 확보할 필요가 있음

## Ⅱ. 특징

- 모델 재학습 없이도 최신 정보와 비공개 지식을 반영할 수 있음
- 출처와 근거를 함께 제시할 수 있어 신뢰성과 감사 가능성을 높임
- 검색 실패가 곧 답변 실패로 이어져 retriever 품질이 전체 성능을 지배함
- chunking, embedding, reranking, access control이 모두 품질과 보안에 영향을 줌

## Ⅲ. 종류 및 비교

| 판단 기준 | Prompt-only | Fine-Tuning | RAG |
|:---|:---|:---|:---|
| 최신 정보 반영 | 낮음 | 낮음 | 높음 |
| 내부 문서 활용 | 낮음 | 제한적임 | 높음 |
| 출처 제시 | 제한적임 | 어려움 | 가능 |
| 적합 목적 | 간단 질의 | 행동 적응 | 사실 기반 응답 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Document Store | 내부 문서와 외부 지식을 저장하고 검색 대상의 기준점이 됨 |
| Retriever | 질의와 관련 높은 문서를 찾아와 답변 근거의 질을 결정함 |
| Prompt Builder | 검색 문서를 적절한 길이와 순서로 묶어 모델이 읽기 쉬운 컨텍스트를 만듦 |
| Generator, Citation Layer | 근거 기반 답변을 생성하고 필요한 경우 출처를 함께 노출함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 문서 인덱싱     | --> | 질의 기반 검색   | --> | 컨텍스트 주입    | --> | 근거 기반 생성   |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **문서 인덱싱**: 문서를 청크로 나누고 임베딩이나 색인 구조를 생성함
2. **질의 기반 검색**: 사용자 질문과 가장 관련 높은 문서를 찾아옴
3. **컨텍스트 주입**: 검색 문서를 프롬프트에 넣고 답변 조건을 함께 전달함
4. **근거 기반 생성**: 모델이 검색 문서를 바탕으로 답변과 출처를 생성함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 검색 문서가 부정확하거나 무관하면 모델이 그 문서를 근거로 더 그럴듯한 오답을 만들 수 있음
   - 해결방안: hybrid retrieval과 reranking을 적용하고 context precision과 faithfulness로 검색 품질을 검증함
2. 문제: 너무 많은 문서를 넣으면 lost-in-the-middle과 비용 증가로 핵심 근거가 오히려 묻힐 수 있음
   - 해결방안: top-k와 context compression을 최적화하고 prompt token count와 answer relevance로 주입 품질을 검증함
3. 문제: 내부 문서를 검색하는 과정에서 권한 없는 정보가 노출되면 보안 사고로 이어질 수 있음
   - 해결방안: metadata ACL과 tenant filtering을 적용하고 unauthorized retrieval rate와 audit log로 접근 통제를 검증함

## Ⅶ. 적용 사례

- 사내 규정 챗봇: 최신 규정 문서를 검색해 답변함, 확인 지표는 faithfulness와 citation accuracy임
- 금융 상품 상담: 설명서와 정책 문서를 근거로 응답함, 확인 지표는 compliance pass rate와 hallucination rate임
- 기술 지원 봇: 매뉴얼과 장애 이력을 검색함, 확인 지표는 first-answer resolution rate와 search hit quality임

## Ⅷ. 결론

RAG의 본질은 모델이 모르는 정보를 외부 근거로 보완해 신뢰 가능한 응답을 만드는 데 있으므로, 생성 모델보다 검색 품질과 권한 통제가 먼저 설계되어야 함.
