## 미리 알고가기

- 검색 증강 생성 ($RAG$, Retrieval-Augmented Generation): 모델의 학습 데이터셋에 한계가 있음을 수용하고, 질의 인입 시 외부 벡터 데이터베이스 등에서 실시간 팩트 문서를 끌어와 프롬프트 맥락($Context$)에 주입하여 답변을 생성하는 외장 결합 아키텍처임
- 리트리버 ($Retriever$): 사용자 질문의 의미 의미론적 임베딩을 분석하여, 데이터베이스(Vector DB 등) 내 수백만 개 텍스트 중 가장 밀착 관련이 깊은 탑 $N$개 문서를 검색 격리해 주는 색인 추출기임
- 문서 분할 ($Chunking$): 검색 정확도를 높이기 위해, 대용량 PDF 등의 원본 텍스트를 보통 $500 \sim 1000$ 글자 크기(청크)로 가변 슬라이싱하여 벡터화하는 전처리 작업임
- 하이브리드 검색 ($Hybrid$ $Search$): 자연어의 의미적 맥락을 찾는 벡터 의미론적 검색(Dense)과, 특정 상품명 등 고유 식별 명사를 찾는 키워드 매칭 검색(Sparse, BM25 등)을 결합하여 검색 정확도를 극대화하는 방식임

## Ⅰ. 개요

- **정의/개념**: RAG는 매개변수 지식의 최신 정보 업데이트 불가 한계와 환각(Hallucination) 현상을 원천 방어하기 위해, 사용자의 질문에 상응하는 지식 원문들을 외부 문서 인덱스 저장소에서 실시간 서치하고, 도출된 맥락 정보를 LLM 프롬프트에 융합 주입하여 근거 기반 답변을 생성하도록 중재하는 검색-생성 유도 아키텍처임
- **배경/필요성**: 수천억 개 매개변수의 대형 언어 모델일지라도 훈련 시점 이후의 어제 뉴스를 알지 못하며 기업 내부 영업 기밀 문서는 알 수 없으므로, 저비용 실시간 지식 보완과 팩트 체크 감사(Auditing) 체계를 구축하고자 필수 수립됨

## Ⅱ. 특징

- 기저 모델의 가중치를 단 $1$도 재학습하지 않고도, 외부 지식 베이스의 실시간 동기화만으로 최신 사내 정책과 규정을 답변에 완벽 반영함
- 모델이 답변 중 특정 수치나 문장에 대해 "몇 페이지 참조" 식의 출처(Citation) 표기 기능을 수행할 수 있게 하여, AI 응답의 설명 책임($Explainability$)을 확보함
- 생성 모델의 지능보다, 초기 질문에 맞는 원문들을 올바르게 캐내는 리트리버(Retriever)의 검색 적중률($Recall$)이 최종 성능을 $90\%$ 이상 좌우함

## Ⅲ. 종류 및 비교

| 판단 기준 | 단순 부동 가동 (Prompt-only) | 파인튜닝 적합화 (Fine-Tuning) | 검색 증강 생성 (RAG) |
|:---|:---|:---|:---|
| **팩트 정보 실시간성** | 낮음 (사전학습 지식 암기에만 의존) | 낮음 (훈련 시점 데이터에 영구 락인) | 극도로 높음 (외부 데이터베이스 실시간 조회) |
| **답변의 출처 표기** | 불가능 (자연어로 그럴싸한 출처 환각) | 불가능 (가중치 연산으로 팩트 융합되어 추적 불가) | 완벽함 (검색 인덱스 ID를 매핑해 인출 증명 가능) |
| **추론 오버헤드** | 없음 (바닐라 속도) | 없음 (가중치 융합 완료) | 존재함 (DB 쿼리 전송 및 컨텍스트 주입 토큰 팽창) |
| **주된 적합 도메인** | 범용 메일 요약, 시 작성, 아이디어 브레인스토밍 | 문체 교정, 규칙 준수, API 포맷팅 고정 | 사내 규정 Q&A, 실시간 증권 상담, 최신 지식 검색 |

> 요약: Prompt-only는 사전 암기력 검정이고, Fine-Tuning은 뇌의 특정 시냅스를 단련해 사고 스타일을 교정하는 훈련이며, RAG는 시험 시간에 옆에 백과사전(Vector DB)을 펼쳐두고 정답을 찾으며 답안지를 작성하는 오픈북 시험임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 지식 저장소 | 문서를 가변 청크 단위로 쪼개, 고밀도 벡터 임베딩 맵으로 적재해 둔 데이터베이스임 |
| 색인 검색기 | 사용자 입력 질문을 임베딩하여, 유사도 기반 관련 문서 행렬을 추출하는 Retriever임 |
| 리랭커 ($Reranker$) | Retriever가 1차 인출해낸 다수의 후보군 문서들에 대해, 의미론적 상호 비교를 가해 최종 순위를 매기는 기기임 |
| 프롬프트 합성기 | 검색된 문맥($Context$)과 질문을 지시어 템플릿 내에 융합 배치하여 LLM에 밀어주는 모듈임 |

```text
[ RAG (검색 증강 생성) 표준 데이터 파이프라인 ]
User Query ───> [ Dense/Sparse Retriever ] ───> [ Reranker (Top-N) ] ───> [ Context Builder ]
                                                                                │ (Merge Query)
                                                                                v
User Display <─── [ LLM Generator / Citation ] <───────────────────────── Prompt Context
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 내부 문서   | --> | 질문 인입 시 | --> | 리랭킹 및   | --> | 근거 융합   |
| 청크 인덱싱 |     | 관련 문서검색|     | 프롬프트합성|     | 추론 및 Citation|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **지식 전처리** — 사내 매뉴얼 PDF를 로딩하여 $500$ 토큰 두께로 겹침 분할($Overlap$ $Chunking$)하고 벡터 DB에 저장함
2. **원문 서치** — 실시간 질문이 유입되면 Dense(벡터)와 Sparse(키워드) 색인을 병렬 기동해 밀착 관련이 깊은 문서 후보군을 뽑아냄
3. **가치 극대화** — 리랭커(Reranker) 모델을 태워 노이즈 문서를 소거하고 최상위 $3$개 중요 청크만 프롬프트 $Context$ 매트릭스에 융합 탑재함
4. **팩트 생성** — LLM을 구동하여 주어진 문맥 내부에서만 정보를 요약 답하도록 제한하고, 인덱스 주소를 최종 답장에 인출함

## Ⅵ. 실무 적용 및 유의점

1. 검색기로부터 너무 많은 문서 조각(예: Top-20)을 욱여넣으면, 프롬프트 중간 부분의 지침을 무시하는 '중간 소실($Lost-in-the-Middle$)' 현상이 발생하므로, 반드시 '리랭커(Reranker)'를 개입시켜 핵심 문서를 프롬프트 양단 최우선 배치하고 맥락 정확도($Context$ $Precision$)를 확인해야 함
2. 사내 인사 규정 RAG 등급 운영 시 일반 사용자가 접근해서는 안 되는 임원 연봉 청크가 검색 인출되어 탈루 노출될 수 있으므로, 반드시 문서 메타데이터에 접근 권한 식별자(ACL)를 맵핑하고 '테넌트 필터링'을 검색 단에서 강제 지정해야 함

## Ⅶ. 결론

- RAG는 LLM의 창의적 환각 리스크를 팩트 원본 검색의 강건성으로 안전 제어해 내는 비즈니스 인공지능 배포의 표준 교과서이며, 설계자는 무분별한 청크 주입에 따른 Lost-in-the-Middle 차단용 리랭커 도입과 권한 ACL 외곽 격리 장치를 철저히 융합 제공해야 함
