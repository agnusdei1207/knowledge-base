# 📖 【암기용】 개념 완전 이해

> 목적: RAG를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: LLM 응답 생성 전에 외부 문서를 검색하여 컨텍스트로 주입하는 아키텍처
- **왜 필요한가**: LLM은 학습 시점 이후 정보를 모르고, 내부 파라미터만으로는 사실과 다른 답(할루시네이션)을 생성함.
- **핵심 직관**: 시험 전에 참고서를 펼쳐놓고 답안을 쓰는 것과 같음 — 기억(파라미터)이 아니라 참조(검색)로 정확도를 확보함.

## 깊이 이해
- **배경·문제의식**: GPT-3 이후 LLM의 생성 품질은 올라갔지만, 학습 컷오프·도메인 지식 부재·할루시네이션 문제가 기업 적용의 장벽임.
- **작동 원리**: 사용자 질의 -> 임베딩 변환 -> 벡터DB/BM25 검색 -> Top-K 문서 추출 -> 프롬프트에 컨텍스트로 삽입 -> LLM이 근거 기반 답변 생성.
- **비유**: 오픈북 시험 — 모든 것을 암기하지 않아도 관련 페이지를 찾아 근거를 확인한 뒤 답을 쓸 수 있음.
- **구체 예시**: 사내 규정 Q&A에서 RAG 적용 시 할루시네이션율 42%->5%로 감소, 답변에 출처 문서 링크 제공.
- **흔한 오해·주의점**: 검색 품질이 낮으면 오히려 잘못된 문서를 근거로 답변하므로, 검색 정밀도가 RAG 전체 품질의 상한선임.

## 연결 개념
- Embedding — 질의·문서를 벡터 공간에 매핑하는 핵심 단계
- Vector Database — 임베딩 벡터의 ANN 검색 저장소
- Chunking — 문서를 검색 단위로 분할하는 전처리

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: RAG는 LLM 생성 전에 외부 지식을 검색·주입하여 근거 기반 답변을 만드는 아키텍처임.
> 2. **가치**: 파라미터 재학습 없이 최신·도메인 지식을 반영하고, 할루시네이션을 42%->5%로 감소시킴.
> 3. **판단 포인트**: 검색 정밀도(Precision@K)가 전체 품질 상한선이므로, 임베딩·청킹·리랭킹 파이프라인 설계가 핵심임.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| LLM 한계 보완 아키텍처 이해 확인 | 학습 컷오프·할루시네이션 문제, 임베딩->검색->리랭킹->생성 4단계 | 검색 단계 없이 생성 중심으로만 서술 |
| 파인튜닝 대비 선택 판단 확인 | 지식 갱신 주기·비용·출처 추적성 비교축 | RAG와 파인튜닝의 배타 관계 단정 |
| 품질 통제 설계 역량 확인 | Precision@K, Recall@10, 할루시네이션율 등 정량 지표 | 검색 품질이 답변 품질 상한이라는 관점 누락 |

> 요약: 이 문제는 RAG 구조 암기가 아니라 파인튜닝 대비 선택 기준과 검색 품질 통제 설계 판단을 묻는다.

---

## Ⅰ. 개요 및 필요성

- 개요: 검색 기반 생성 보강 아키텍처
- 배경: LLM은 학습 컷오프, 도메인 지식 부재, 할루시네이션으로 기업 문서 Q&A와 규정 답변에서 오류를 낼 수 있음.
- 필요성: embedding, vector DB, Top-K retrieval, reranker로 외부 근거를 주입하고 hallucination rate·Precision@K·출처 명시율을 관리해야 함.

---

## Ⅱ. 구조 및 구성요소

```text
질의 -> Embedding -> Vector DB -> Top-K 검색

                         Reranker -> Context 조합 -> LLM -> 응답
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Embedding Model | 질의·문서를 벡터 변환 | OpenAI ada-002 1,536차원, 오픈소스 BGE 1,024차원 |
| Vector DB | ANN 기반 유사도 검색 | HNSW 인덱스, Recall@10 ≥ 95% |
| Reranker | Top-K 문서 재순위화 | Cross-Encoder, 정밀도 15~25% 개선 |
| LLM Generator | 컨텍스트 기반 답변 생성 | 컨텍스트 윈도우 128K 토큰 |

> 요약: RAG는 임베딩->검색->리랭킹->생성 4단계 파이프라인으로, 각 단계의 품질이 최종 답변 정확도를 결정함.

---

## Ⅲ. 동작원리 및 흐름도

```text
사용자 질의 -> 임베딩 변환 -> ANN 검색 -> 리랭킹
    -> 프롬프트 조합 -> LLM 생성 -> 출처 첨부 응답
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 질의 임베딩 변환 (768~1,536차원) | 변환 지연 < 50ms |
| 2 | ANN 검색 Top-K 후보 추출 | Recall@10 ≥ 95%, 검색 지연 < 100ms |
| 3 | Cross-Encoder 리랭킹 | Precision@3 ≥ 80% |
| 4 | 프롬프트 조합 + LLM 생성 | 할루시네이션율 < 5%, 출처 명시율 100% |

> 요약: 질의를 벡터화하여 유사 문서를 검색하고, 리랭킹으로 정밀도를 높인 뒤 LLM에 주입하여 근거 기반 답변을 생성함.

---

## Ⅳ. 특징

| 구분 | 파인튜닝 | RAG | 판단 포인트 |
|:---|:---|:---|:---|
| 지식 갱신 | 재학습 필요 (수일·수백 GPU시간) | 문서 색인만 갱신 (수분) | 갱신 주기 일 1회 이상이면 RAG |
| 비용 | GPU 학습 비용 高 | 검색 인프라 비용 | 문서 10만 건 이하면 RAG 비용 1/10 |
| 할루시네이션 | 학습 데이터 의존 | 검색 문서 기반, 출처 추적 가능 | 규제 산업은 출처 추적 필수 -> RAG |

> 요약: RAG는 파인튜닝 대비 지식 갱신 속도·비용·출처 추적에서 유리하며, 도메인 특화가 깊으면 RAG+파인튜닝 혼합을 고려함.

---

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | Long Context 전체 주입 | RAG | 선택 기준 |
|:---|:---|:---|:---|
| 토큰 비용 | 문서 전체 토큰 과금으로 질의당 비용 증가 | Top-K 청크만 주입해 입력 토큰 제한 | 문서량이 컨텍스트 윈도우 초과 시 RAG |
| 응답 지연 | prefill 토큰 증가로 TTFT 상승 | 검색 100ms 내외 추가 후 짧은 컨텍스트 생성 | 대화형 지연 SLA 존재 시 RAG |
| 접근 통제 | 주입 문서 전체가 프롬프트에 노출 | 메타데이터 필터로 권한별 검색 범위 제한 | 문서별 접근권한 분리 요구 시 RAG |

> 요약: 지식 총량이 컨텍스트 윈도우를 초과하거나 문서별 접근 통제가 필요하면 RAG를 선택함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 검색 오류의 생성 전파 | 임베딩-질의 불일치, 부적절 청킹 | Hybrid Search·Cross-Encoder 리랭킹 추가 | Precision@3, Recall@10 |
| 환각 잔존 | 무관 문서의 컨텍스트 주입 | groundedness 평가, 출처 표기 강제 | faithfulness 점수, 출처 명시율 |
| 최신성 미반영 | 색인 갱신 지연 | 증분 색인 파이프라인 자동화 | 색인 반영 지연 시간 |

> 요약: RAG의 주요 위험은 검색 오류가 답변 오류로 전파되는 것이며, 하이브리드 검색·리랭킹·근거 평가로 통제함.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 사내 문서 Q&A: 문서를 512토큰 단위로 청킹, BGE-M3 임베딩, Milvus 벡터DB, Cross-Encoder 리랭킹 적용
2. 검색 품질 모니터링: Precision@3, Recall@10, 할루시네이션율을 Ragas 프레임워크로 자동 평가
3. 보안 통제: PII 필터링, 문서 접근권한을 벡터DB 메타데이터 필터로 연동, 감사로그 보관

**결론 (2줄):**
- 기술사 판단: 도메인 지식 갱신 주기가 월 1회 이상이면 RAG, 갱신 불필요하면 파인튜닝, 둘 다면 혼합 적용
- 향후 방향: Agentic RAG·Graph RAG로 다중 소스 추론과 관계 기반 검색으로 진화
