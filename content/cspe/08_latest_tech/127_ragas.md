# 📖 【암기용】 개념 완전 이해

> 목적: RAGAS를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: RAG 시스템의 검색·생성 품질을 LLM 기반 지표로 자동 평가하는 오픈소스 프레임워크
- **왜 필요한가**: RAG 품질 평가는 수동 채점 비용이 크므로, 반복 배포와 회귀 검증을 자동화해야 함.
- **핵심 직관**: RAG 답변을 채점하는 자동 채점표로, 근거를 잘 찾았는지와 근거대로 답했는지를 수치화함.

## 깊이 이해
- **배경·문제의식**: RAG 파이프라인은 청킹·임베딩·리랭킹·프롬프트 변경 때마다 품질이 달라진다. 매번 사람이 채점하면 배포 속도가 느려진다.
- **작동 원리**: question, answer, contexts, ground_truth를 입력받아 faithfulness, answer_relevancy, context_precision, context_recall 등을 계산함.
- **비유**: 시험 답안과 참고자료를 넣으면 자동으로 "참고자료와 일치", "질문에 맞음", "필요한 자료를 찾음" 점수를 주는 채점기임.
- **구체 예시**: CI에서 RAGAS 평균 faithfulness 0.9 미만 또는 context_recall 0.85 미만이면 배포 실패 처리.
- **흔한 오해·주의점**: RAGAS 점수는 평가 LLM 품질에 영향을 받는다. 표본 수동 검수와 기준 모델 고정이 필요함.

## 연결 개념
- Faithfulness — 답변-근거 일치성 지표
- Answer Relevancy — 질문-답변 관련성 지표
- LLM-as-Judge — LLM을 평가자로 사용하는 방식

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: RAGAS는 RAG 평가 지표를 자동 계산하는 LLM 기반 평가 프레임워크임.
> 2. **가치**: 청킹·검색·프롬프트 변경의 품질 회귀를 CI/CD에서 수치로 감지함.
> 3. **판단 포인트**: 평가 LLM 고정, 표본 수동 검수, 지표 임계값 설정이 신뢰도 확보 조건임.

## Ⅰ. 개요 및 필요성

- 개요: RAG 자동 평가 프레임워크
- 배경: 청크 크기, retriever, prompt, LLM 변경은 RAG 답변 품질을 단계별로 바꾼다.
- 필요성: RAGAS 지표로 Faithfulness·Context Precision·Answer Relevancy를 자동 계산해 배포 전 회귀 기준을 운영한다.

## Ⅱ. 구조 및 구성요소

```text
Dataset(question, answer, contexts, ground_truth)
  -> RAGAS Metrics -> LLM Judge -> Score Report -> CI Gate
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Evaluation Dataset | 질의·답변·컨텍스트·정답 입력 | 500건 이상 권장 |
| Metrics Engine | RAG 지표 계산 | faithfulness, relevancy, context metrics |
| LLM Judge | 문장 분해·판정 수행 | GPT, Claude, local judge |
| Report/Gate | 점수 리포트·배포 차단 | 임계값 기반 CI 연동 |

> 요약: RAGAS는 평가 데이터와 LLM Judge를 사용해 RAG 품질 지표를 자동 계산하고 배포 게이트에 연결함.

## Ⅲ. 동작원리 및 흐름도

```text
평가셋 준비 -> RAG 실행 결과 수집 -> RAGAS 지표 계산
  -> 기준 점수 비교 -> 리포트 생성 -> 배포 승인/차단
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | question, answer, contexts, ground_truth 구성 | 결측률 0% |
| 2 | Faithfulness·Relevancy·Context 지표 계산 | 평가 재현성 표준편차 <0.03 |
| 3 | 기준선 대비 회귀 분석 | 지표 하락 5%p 이상 감지 |
| 4 | CI/CD 배포 게이트 반영 | 임계값 미달 배포 차단 100% |

> 요약: RAGAS는 RAG 실행 결과를 표준 입력으로 받아 자동 지표를 계산하고 회귀 여부를 판단함.

## Ⅳ. 특징

| 구분 | 수동 평가 | RAGAS | 판단 포인트 |
|:---|:---|:---|:---|
| 평가 속도 | 1천 건 수일 | 1천 건 수십 분~수시간 | 반복 배포에 적합 |
| 지표 범위 | 채점자 기준 | 표준 RAG 지표 | 검색·생성 분리 |
| 비용 | 인력 비용 | 평가 LLM 호출 비용 | 월 평가량 산정 필요 |
| 리스크 | 채점자 편차 | Judge 모델 편향 | 표본 수동 검수 병행 |

> 요약: RAGAS는 반복 평가를 자동화하지만, 평가 LLM 편향을 줄이기 위해 기준 모델 고정과 표본 검수가 필요함.

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. CI 평가: PR마다 200건 smoke set, 주간 1,000건 full set 실행, faithfulness 0.9 미만이면 merge 차단
2. 실험 비교: 청크 256/512/1,024와 리랭커 적용 여부를 RAGAS 점수와 지연으로 A/B 비교
3. 운영 검수: 일별 운영 질의 1% 샘플링, RAGAS 하락 구간은 사람 검수 50건으로 보정

**결론 (2줄):**
- 기술사 판단: RAGAS는 배포 회귀 검증에 유효하나, 고위험 도메인은 수동 검수와 병행
- 향후 방향: 평가 LLM, 사용자 피드백, 도메인 룰을 결합한 하이브리드 평가 체계로 발전
