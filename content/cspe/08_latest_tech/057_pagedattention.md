## 미리 알고가기

- 페이지드 어텐션 ($PagedAttention$): 운영체제($OS$)의 가상 메모리 페이징 기법을 차용하여, $KV$ 캐시 데이터를 고정 크기 블록(페이지) 단위로 분할 관리하는 메모리 관리 가속 기술임
- 블록 테이블 ($Block$ $Table$): 논리적 단어 시퀀스 순서와 실제 GPU 물리 메모리 블록 주소를 가상 매핑해 두는 주소 변환표임
- 가상 메모리 ($Virtual$ $Memory$): 물리적인 메모리의 연속성 한계를 극복하기 위해 논리적 가상 주소를 도입해 비연속 영역을 매핑하는 메모리 관리 패러다임임
- 가비지 컬렉션 ($GC$): 사용이 종료된 가용 메모리 블록(페이지)을 자동 감지하여 시스템 풀로 즉시 반환하는 자원 회수 처리임

## Ⅰ. 개요

- **정의/개념**: PagedAttention은 LLM 추론 시 생성 과정에서 가변적으로 커지는 $KV$ 캐시 데이터를 VRAM의 연속된 텐서 버퍼로 할당하지 않고, 고정 크기의 불연속 논리 페이지 블록으로 분할하여 블록 테이블($Block$ $Table$)을 거쳐 동적 매핑하는 메모리 가상화 및 가속 기술임
- **배경/필요성**: 기존에는 요청이 들어오면 생성될 최대 길이(예: 2,048 토큰)에 대비하여 엄청난 크기의 연속 공간을 미리 강제 예약했기 때문에, 실제 대화가 짧게 끝나면서 남는 VRAM의 내부 파편화($Fragmentation$)가 약 $60 \sim 80\%$에 육박하는 비효율을 낳아 이를 타파하고자 고안됨

## Ⅱ. 특징

- 단어가 추가될 때마다 필요한 만큼만 물리 페이지 블록을 동적 바인딩하므로, 낭비되는 VRAM의 파편화 비율을 0%에 수렴하도록 정돈함
- 동일 시스템 프롬프트나 다중 답변 생성($Beam$ $Search$) 시, 물리 페이지의 공유($Sharing$) 계수와 복사 쓰기($Copy-on-Write$)를 지원하여 중복 캐싱을 완벽 제거함
- 서빙 백엔드($vLLM$ 등) 내에서 하드웨어 커널 단과 통신하며 작동하며, 멀티 GPU 텐서 병렬화 환경에서도 블록 단위로 분산 적재가 가능함

## Ⅲ. 종류 및 비교

| 판단 기준 | 전통적인 정적 연속 할당 | 페이지드 어텐션 (PagedAttention) |
|:---|:---|:---|
| **물리 VRAM 배치** | 가상 메모리 없이 오직 물리 연속 공간 강제 | 비연속적인 물리 페이지 블록 결합 허용 |
| **최대 토큰 사전 예약** | 필수 (최대 출력 길이만큼 무조건 선점) | 불필요 (필요할 때마다 실시간 블록 할당) |
| **메모리 파편화** | 심각함 (자원 낭비 주범) | 없음 ($Fragmentation \approx 0\%$) |
| **동일 문맥 공유** | 불가능 (세션마다 독립 복제) | 우수함 (동일 접두 페이지 블록 포인터 공유) |

> 요약: 정적 연속 할당은 단순 스택 관리에, 페이지드 어텐션은 동적 블록 주소 결합을 통한 인프라 자원 낭비 최소화에 적합함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 논리 블록 ($Logical$) | 어텐션 계산 순서로 번호가 매겨진 가상의 고정 크기 토큰 슬롯 묶음임 |
| 물리 페이지 ($Physical$) | GPU 디바이스 VRAM에 산재해 있는 고정 크기(예: 16토큰 분량)의 실제 메모리 주소임 |
| 블록 테이블 매퍼 | 논리 블록의 정수 인덱스를 물리 블록 주소로 변환하여 $CUDA$ 커널에 건네는 사상 테이블임 |
| 페이지 할당 가이드 | 유휴 상태의 물리 블록 풀을 감시하고, 할당/회수 및 $Copy-on-Write$ 신호를 총괄하는 매니저임 |

```text
[ PagedAttention 주소 변환 ]
[Logical Tokens: 0~15] ---> [Block Table Index 0] ---> [Physical VRAM Block @0x7F41]
[Logical Tokens: 16~31] ---> [Block Table Index 1] ---> [Physical VRAM Block @0x9D08]
- 불연속적인 GPU VRAM의 주소들을 가상의 블록 테이블을 거쳐 연속된 단어 시퀀스로 어텐션 연산 처리함
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 프리필 입력 | --> | 논리블록 분배| --> | 블록 테이블 | --> | 가비지 컬렉션|
| 및 토큰화   |     | 및 물리 바인딩|     | 변환/어텐션 |     | 자원 풀 회수|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **토큰 유입** — 문장이 입력되면 이를 토큰화하고, 기본 페이지 크기(예: 16) 단위로 논리 블록 인덱스를 순차 부여함
2. **블록 매핑** — 비어 있는 GPU 물리 주소 페이지를 찾아 블록 테이블의 슬롯 번호와 실시간 연동($Logical$ $\rightarrow$ $Physical$)함
3. **어텐션 가속** — 단어가 하나씩 튀어나올 때마다, 변환표를 조회하여 불연속 메모리에 놓인 Key, Value들을 가져와 행렬 곱을 수행함
4. **세션 회수** — 응답 출력이 완료되면, 가비지 컬렉션 모듈이 작동해 사용되었던 물리 페이지들의 링크를 끊고 사용 가능 풀로 즉각 반입함

## Ⅵ. 실무 적용 및 유의점

1. PagedAttention의 기본 블록 크기(Block Size, 보통 8, 16, 32 중 선택)를 너무 작게 잡으면 매핑 오버헤드가 늘어나 성능이 저하되고, 너무 크게 잡으면 마지막 블록 내 꼬리 파편화가 다시 늘어나므로, 일반적인 질의 길이 분포를 측정해 '16 또는 32'로 튜닝하고 1회당 매핑 지연시간 지표를 검증해야 함
2. 멀티 에이전트 간 접두문맥 공유($Prefix$ $Caching$) 활성화 시, 여러 작업이 동일 블록을 참조하다가 특정 에이전트가 새 단어를 덧붙일 때 일어나는 원본 오염을 차단하기 위해, 읽기 전용 공유에서 쓰기 발생 시 블록을 물리 복제하는 'Copy-on-Write' 코드를 장착하고 데이터 오버라이트 차단율로 검증해야 함

## Ⅶ. 결론

- PagedAttention은 운영체제의 지혜를 GPU 메모리 병목 극복에 이식하여 대형 언어 모델 서빙의 동접 한계를 해방한 기반 아키텍처이며, 설계자는 정밀한 블록 크기 조율과 다중 세션 간의 데이터 무결성을 보존하는 Copy-on-Write 공유 장치를 안정적으로 이식해야 함
