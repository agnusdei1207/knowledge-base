# 📖 【암기용】 개념 완전 이해

> 목적: IIoT를 산업 설비와 센서를 네트워크로 연결해 운영 데이터 수집·분석·제어를 수행하는 산업용 IoT로 이해하게 만든다.

## 한눈에
- **개요**: 산업 장비, 센서, 제어시스템, edge, 클라우드를 연결하는 IoT 구조
- **왜 필요한가**: 공장, 발전소, 물류, 플랜트는 설비 상태를 모르면 고장, 품질 저하, 안전 사고를 사전에 감지하기 어렵다.
- **핵심 직관**: 가정용 IoT가 조명을 원격 제어한다면, IIoT는 생산 설비와 안전 설비를 데이터 기반으로 감시·예측·운영한다.

## 깊이 이해
- **배경·문제의식**: 산업 현장은 장비 수명이 길고 프로토콜이 다양하며, 제어 지연과 안전 요구가 일반 IT보다 엄격하다.
- **작동 원리**: 센서·PLC 데이터가 edge gateway에서 수집·전처리되고 OPC UA, MQTT, 5G, TSN 등을 통해 SCADA, MES, 데이터 플랫폼으로 전달된다.
- **비유**: 사람의 건강 모니터가 심박·혈압을 계속 재듯, IIoT는 설비 진동·온도·전류를 지속 측정해 이상 징후를 찾는다.
- **구체 예시**: 모터 진동 센서가 RMS 진동값을 edge에서 분석하고 임계값 초과 시 정비 시스템에 알람을 생성한다.
- **흔한 오해·주의점**: IIoT는 일반 IoT를 공장에 붙이는 것만이 아니다. 실시간성, 안전, OT 보안, 장비 수명, 현장 네트워크 제약을 반영해야 한다.

## 연결 개념
- OPC UA — 산업 데이터의 의미 모델과 보안 통신
- Smart Factory — IIoT 데이터를 생산 운영에 연결
- Edge Computing — 현장 가까이에서 분석·필터링 수행

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.
> 핵심: IIoT는 산업 장비·센서·제어 시스템을 edge와 네트워크로 연결해 예지보전, 품질관리, 안전관리, 생산 최적화를 수행하는 OT/IT 융합 구조임.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: IIoT는 산업 설비와 센서 데이터를 안전하게 수집·전송·분석해 운영 의사결정과 제어에 연결하는 산업용 IoT임.
> 2. **가치**: 예지보전, OEE 개선, 품질 추적, 에너지 관리, 안전 모니터링을 설비 데이터 기반으로 수행함.
> 3. **판단 포인트**: 실시간성, OT 보안, 프로토콜 상호운용, edge 처리, 데이터 품질, 제어 안전 경계가 핵심임.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 산업용 IoT 특성 이해 확인 | 센서·PLC·edge·SCADA/MES | 소비자 IoT 사례로 대체 |
| IT/OT 융합 판단 확인 | OPC UA, MQTT, TSN, 5G | 네트워크 연결만 설명 |
| 보안·안전 인식 확인 | IEC 62443, segmentation, read-only | 클라우드 전송만 강조 |

> 요약: 이 문제는 산업 현장의 실시간성·안전·보안 제약을 일반 IoT와 구분하는 것이 핵심이다.

---

## Ⅰ. 개요 및 필요성

- 개요: 산업 설비 연결 IoT
- 배경: 현장 설비 데이터가 제어실과 업무 시스템에 분산되어 고장·품질·에너지 원인 추적이 어려움.
- 필요성: 센서·PLC·edge·데이터 플랫폼을 연결해 예지보전, 품질 추적, 안전 모니터링을 수행해야 함.

---

## Ⅱ. 구조 및 구성요소

```text
Sensor / Actuator / PLC -> Edge Gateway -> Industrial Network
      +-> SCADA / Historian / MES -> Data Platform / AI
      +-> OT Security / Device Management / Monitoring
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 현장 디바이스 | 센서·액추에이터·PLC 데이터 생성 | legacy protocol |
| edge gateway | 수집·필터링·프로토콜 변환 | OPC UA, MQTT |
| 산업 네트워크 | 현장과 플랫폼 연결 | TSN, private 5G |
| 분석·운영 | SCADA/MES/AI가 의사결정 지원 | predictive maintenance |

> 요약: IIoT는 현장 디바이스부터 edge, 네트워크, 운영 시스템, 보안까지 포함하는 계층 구조다.

---

## Ⅲ. 동작원리 및 흐름도

```text
센서 측정 -> edge 수집·필터링 -> 프로토콜 변환
-> 메시지 전송 -> 저장·분석 -> 알람 / 정비 / 제어 피드백
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 센서·PLC가 온도·진동·전류·상태값을 생성함 | sampling rate |
| 2 | edge가 데이터 정제와 이상값 필터링을 수행함 | data quality |
| 3 | OPC UA/MQTT 등으로 SCADA·MES·클라우드에 전달함 | latency, loss |
| 4 | 분석 결과를 알람·정비 지시·제어 정책에 반영함 | downtime, false alarm |

> 요약: IIoT는 현장 데이터 수집에서 분석 결과 피드백까지 닫힌 운영 루프를 구성한다.

---

## Ⅳ. 특징

| 구분 | 일반 IoT | IIoT | 판단 기준 |
|:---|:---|:---|:---|
| 대상 | 소비자 기기 | 산업 설비·제어 시스템 | 안전·생산 영향 |
| 요구 | 편의·원격 제어 | 실시간성·가용성·안전 | control latency |
| 수명 | 짧은 교체 주기 | 장기 운영 장비 | legacy 연계 |
| 보안 | 개인정보 중심 | OT 안전·가동 중단 방지 | IEC 62443 |

> 요약: IIoT는 연결 대상이 생산·안전에 직접 영향을 주므로 일반 IoT보다 보안과 제어 경계가 엄격하다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 데이터 수집 | 수동 점검·SCADA 한정 | 센서·edge·cloud 연계 | 고장 예측 필요 |
| 분석 위치 | 중앙 서버 | edge+cloud 분산 | 지연·대역폭 제약 |
| 보안 | 물리 격리 중심 | segmentation+monitoring | 외부 연계 범위 |

> 요약: IIoT는 데이터 가치가 제어망 리스크보다 클 때 단계적으로 적용하고, edge 우선 구조로 지연과 대역폭을 통제한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 제어 지연 | cloud 왕복 의존 | edge inference와 local fallback | control latency |
| 보안 침해 | IT/OT 연결 확대 | IEC 62443 zone/conduit, allowlist | blocked connection |
| 데이터 품질 | 센서 drift·결측 | sensor calibration, redundancy | missing rate |

> 요약: IIoT 리스크는 지연, 보안, 센서 품질이며 edge와 OT 보안 통제로 관리한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 운영 효과 | downtime·MTTR 변화 | CMMS, SCADA log |
| 통신 품질 | latency·packet loss 관리 | network telemetry |
| 보안 | 자산 식별·접속 통제 | OT asset inventory |

> 요약: IIoT 성과는 연결 장비 수보다 다운타임, 통신 품질, 자산 보안 가시성으로 판단한다.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 고장 비용과 품질 영향이 큰 설비부터 센서 태그, sampling rate, edge 처리 기준, 데이터 owner를 정의함.
2. OPC UA/MQTT gateway를 통해 read-only 데이터 수집부터 시작하고 제어 피드백은 검증 환경과 승인 절차 후 적용함.
3. IEC 62443 기반 zone/conduit, 자산 식별, 네트워크 allowlist, 계정 분리, 원격접속 감사를 적용함.

**결론 (2줄):**
- 기술사 판단: 예지보전·품질 추적 가치가 크고 OT 보안 통제가 가능한 현장부터 IIoT를 단계 적용해야 함.
- 향후 방향: IIoT는 edge AI, private 5G, Digital Twin, Smart Factory와 결합해 자율 제조·자율 플랜트 기반으로 확장됨.
