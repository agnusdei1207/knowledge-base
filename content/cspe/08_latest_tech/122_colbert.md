# 📖 【암기용】 개념 완전 이해

> 목적: ColBERT를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: 질의와 문서를 토큰별 벡터로 저장하고, 검색 시 토큰 간 최대 유사도(MaxSim)를 계산하는 후기상호작용 검색 모델
- **왜 필요한가**: Bi-Encoder는 빠르지만 세밀한 토큰 매칭이 약하고, Cross-Encoder는 정확하지만 후보별 추론 비용이 큼.
- **핵심 직관**: 문서 전체를 하나의 벡터로 뭉개지 않고, 단어별 의미 카드를 보관해 질문 단어와 하나씩 맞춰보는 방식임.

## 깊이 이해
- **배경·문제의식**: Dense Retrieval은 문서 전체를 단일 벡터로 압축해 세부 근거가 사라진다. Cross-Encoder는 문서를 함께 읽어 정확하지만 전체 문서 검색에는 쓸 수 없다.
- **작동 원리**: 문서 토큰별 임베딩을 미리 저장하고, 질의 토큰 임베딩과 각 문서 토큰의 최대 유사도를 합산해 관련도를 계산함.
- **비유**: 책마다 한 장 요약이 아니라 문장별 색인 카드를 만들어, 질문의 각 단어와 가장 잘 맞는 카드를 찾아 점수를 더하는 방식임.
- **구체 예시**: ColBERTv2는 압축 인덱싱으로 저장량을 줄이면서 MS MARCO 계열 검색에서 Bi-Encoder보다 높은 MRR@10을 달성함.
- **흔한 오해·주의점**: 토큰 벡터를 저장하므로 단일 벡터 검색보다 저장량이 크다. 압축, pruning, 후보 제한 설계가 필요함.

## 연결 개념
- Bi-Encoder — 단일 벡터 기반 1차 검색
- Cross-Encoder — 질의·문서 동시 인코딩 리랭커
- Late Interaction — 질의 후 토큰 단위 상호작용을 계산하는 모델 구조

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: ColBERT는 토큰 벡터와 MaxSim으로 Bi-Encoder 속도와 Cross-Encoder 정밀도를 절충함.
> 2. **가치**: 단일 벡터 압축 손실을 줄여 MRR@10·nDCG@10을 높이고 RAG 근거 정밀도를 개선함.
> 3. **판단 포인트**: 토큰 벡터 저장량과 MaxSim 계산 비용을 압축·후보 제한으로 통제해야 함.

## Ⅰ. 개요 및 필요성

ColBERT는 후기상호작용 기반 검색 모델임. Bi-Encoder는 확장성은 높지만 세밀한 토큰 매칭이 약하고, Cross-Encoder는 정밀하지만 전체 검색에 부적합하다. ColBERT는 문서 토큰 벡터를 저장해 검색 시 토큰 수준 유사도를 계산한다.

## Ⅱ. 구조 및 구성요소

```text
Document -> Token Encoder -> Token Vectors -> Compressed Index
Query -> Token Encoder -> MaxSim(q-token, d-token) -> Score -> Rank
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Token Encoder | 질의·문서 토큰별 벡터 생성 | BERT 기반 128차원 투영 |
| Token Index | 문서 토큰 벡터 저장 | 압축·pruning 필요 |
| MaxSim | 질의 토큰별 최대 문서 토큰 유사도 계산 | late interaction 핵심 |
| Ranker | MaxSim 합산 점수로 문서 순위화 | Top-K 검색 또는 리랭킹 |

> 요약: ColBERT는 문서를 토큰 벡터 집합으로 저장하고 질의 시 MaxSim으로 세밀한 관련도를 계산함.

## Ⅲ. 동작원리 및 흐름도

```text
오프라인: 문서 토큰화 -> 토큰 벡터 생성 -> 압축 인덱스 저장
온라인: 질의 토큰 벡터 -> 후보 탐색 -> MaxSim 점수 -> Top-K 반환
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 문서를 토큰별 128차원 벡터로 인코딩 | 인덱스 압축률 4~8배 |
| 2 | 질의 토큰 벡터 생성 | 질의 인코딩 <20ms |
| 3 | 후보 문서 토큰과 MaxSim 계산 | nDCG@10 ≥ Dense 대비 +5%p |
| 4 | Top-K 또는 리랭킹 결과 반환 | p95 <500ms |

> 요약: 문서 토큰 벡터를 미리 저장하고 질의 시 토큰별 최대 유사도를 합산해 정밀 검색을 수행함.

## Ⅳ. 특징

| 구분 | Bi-Encoder | Cross-Encoder | ColBERT |
|:---|:---|:---|:---|
| 표현 단위 | 문서 1개 벡터 | 질의-문서 쌍 | 토큰 벡터 집합 |
| 정밀도 | 중간 | 높음 | 높음에 근접 |
| 확장성 | 높음 | 낮음 | 중간 |
| 비용 | 낮음 | 후보별 추론 | 저장량·MaxSim 비용 |

> 요약: ColBERT는 Bi-Encoder보다 정밀하고 Cross-Encoder보다 검색 확장성이 높지만, 토큰 벡터 저장 비용이 크다.

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 정밀 RAG 검색: Hybrid Top-100 후보를 ColBERT로 재정렬, Top-5 근거만 LLM 컨텍스트에 주입
2. 저장 비용 제어: 128차원 projection, product quantization, stopword pruning으로 토큰 인덱스 용량 4배 절감
3. 평가 기준: Bi-Encoder 대비 nDCG@10 +5%p 이상, p95 500ms 이하일 때 운영 적용

**결론 (2줄):**
- 기술사 판단: 정밀도와 지연을 함께 요구하면 ColBERT, 초저지연 대규모 검색은 Bi-Encoder 우선 적용
- 향후 방향: ColBERTv2 계열 압축 인덱싱과 Vector DB 통합으로 RAG 검색 계층에 확산
