# 📖 【암기용】 개념 완전 이해

> 목적: 근접 메모리 컴퓨팅(Near-Memory Computing) 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 연산기(Processor)를 메모리 칩 바로 옆이나 메모리 모듈 내부에 바짝 붙여서, 데이터가 이동하는 거리와 시간을 최소화하는 기술
- **왜 필요한가**: 메모리 안에서 직접 계산하는 PIM(In-Memory)은 만들기가 너무 어렵고 비쌈. 그 대신, 메모리 칩을 만드는 공정은 그대로 두고, 칩 바로 밑이나 옆에 연산기를 배치해서 '현실적인 대안'으로 성능을 높이려는 것
- **핵심 직관**: "창고 안에서 요리하는 게(PIM) 어렵다면, 창고 바로 문 앞에 조리대(PNM)를 설치해서 재료 운반 시간을 줄이는 방식"

## 깊이 이해
- **배경·문제의식**: AI 연산에서 데이터 이동은 병목과 발열의 주범임. CPU/GPU와 메모리 사이의 먼 길을 오가는 대신, 메모리 칩을 조절하는 컨트롤러나 하단 로직 다이에 연산 기능을 넣으면 데이터 이동 거리가 수백 분의 일로 줄어듦
- **작동 원리**: ① **로직 다이 활용**: HBM처럼 칩을 쌓을 때, 맨 아래에 있는 베이스 다이(Base Die)에 연산기를 넣음. ② **모듈형 확장**: CXL 메모리 카드나 DIMM 모듈 위에 작은 가속기를 붙여서 메모리 자체적으로 간단한 연산을 처리하게 함. ③ **데이터 이동 축소**: 데이터가 메인 보드의 버스(Bus)를 타지 않고 칩 내부 패키지 안에서만 움직임
- **비유**: 식재료를 시장에서 집까지 배달해 먹는 대신, 시장 입구에 있는 간이 식당에서 바로 조리해서 먹는 것. 배달비(에너지)가 대폭 절감됨
- **구체 예시**: CXL 기반 PNM 가속기, HBM 하단 로직 다이에 연산 기능을 넣은 구조. 삼성전자와 네이버가 협력하여 개발한 AI 가속기 솔루션이 대표적인 PNM 사례임
- **흔한 오해·주의점**: "PIM과 똑같은 것인가"는 아님. PIM은 메모리 '셀(Cell)' 수준에서 계산이 일어나지만, PNM은 메모리 '컨트롤러'나 '주변 회로' 수준에서 일어남. PIM보다 성능 향상은 조금 낮을 수 있지만, 상용화는 훨씬 쉬움

## 연결 개념
- **PIM (Processing-In-Memory)**: 메모리 내부에서 계산하는 기술 (PNM보다 한 단계 더 나아간 기술)
- **HBM (High Bandwidth Memory)**: PNM 기술이 가장 활발하게 적용되는 적층형 메모리
- **CXL (Compute Express Link)**: 메모리 풀링과 함께 PNM 가속기를 연결하는 표준 인터페이스

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: **데이터 이동 오버헤드 감축, 로직 다이(Base Die) 활용, 제조 공정 호환성, 전력 효율성**을 기술한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 근접 메모리 컴퓨팅(PNM: Processing Near Memory)은 연산 장치를 메모리 다이(Die)의 하단 로직 층이나 메모리 모듈 내부에 물리적으로 근접 배치하여 데이터 전송 경로를 최단화하는 기술이다.
> 2. **가치**: 기존 DRAM/HBM 제조 공정을 크게 수정하지 않고도 데이터 이동에 따른 에너지 소모를 50% 이상 절감하며, 인터커넥트 병목을 해소하여 시스템 처리량을 높인다.
> 3. **판단 포인트**: PIM 대비 제조 공정의 용이성(Feasibility), 호스트 프로세서와의 연산 분담(Offloading) 전략, CXL 등 차세대 인터페이스와의 결합 효율성을 고려해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 데이터 이동 최적화 기술 이해도 측정 | 데이터 이동 오버헤드 감소, 로직 다이 활용, 지연 시간 단축 | 단순히 "메모리 옆에서 계산한다"는 서술 |
| PIM과의 기술적 차이점 분석 역량 확인 | 공정 호환성(DRAM 공정 미수정), 구현 난이도, 성능 트레이드오프 | PIM과 PNM을 동일 기술로 혼용 |

> 요약: '제조 공정의 현실성'과 '데이터 이동 거리 단축'을 통한 에너지 효율 극대화에 초점을 맞춘다.

## Ⅰ. 개요 및 필요성

- 정의: 프로세서와 메모리 간의 물리적 거리로 인한 데이터 이동 병목을 해결하기 위해, 메모리 칩 주변(Controller, Logic Die)에 연산 기능을 통합한 아키텍처
- 배경: CPU-DRAM 간의 대역폭 한계(Memory Wall)와 데이터 이동 시 발생하는 극심한 전력 소모(Power Wall)가 AI 성능 향상의 저해 요소로 대두
- 필요성: PIM 대비 높은 양산 가능성 및 수율 확보, 데이터 집약적 워크로드(대규모 추론, 추천 시스템) 가속, 인프라 TCO 절감

---

## Ⅱ. 구조 및 구성요소

```text
[Near-Memory Computing Architecture]
  |-- Memory Stack (DRAM/HBM): 순수 데이터 저장 (공정 미수정)
  |-- Logic Die (Base Die): 메모리 하단에 위치, 연산기(PE) 탑재
  |-- Controller: 데이터 로딩 및 연산 스케줄링
  `-- Interconnect: 호스트(CPU/GPU)와 통신 (CXL, PCIe)
```

| 구성요소 | 역할 | 기술적 특징 |
|:---|:---|:---|
| 로직 다이 (Base Die) | HBM 하단에서 연산 수행 | 파운드리 공정으로 제작, 고성능 연산 유닛 집적 |
| 연산 엔진 (PE) | 메모리에서 읽어온 데이터 즉시 처리 | GEMV(행렬-벡터 곱셈) 등 단순 반복 연산 특화 |
| 고속 내부 버스 | 적층 메모리와 로직 다이 간 연결 | TSV(Through Silicon Via)를 통한 광대역 통신 |
| CXL 인터페이스 | 외부 시스템과의 유연한 연결 | 메모리 풀링 환경에서의 PNM 기능 확장 |

> 요약: 메모리 저장 층은 그대로 두고, 데이터가 나가는 길목(Logic Die/Controller)에 계산기를 배치한 구조이다.

---

## Ⅲ. 동작원리 및 흐름도

```text
Data Request -> Internal TSV Load -> Logic Die Compute -> Result Return
(호스트 명령)   (패키지 내 전송)     (근접 연산기 처리)    (시스템 버스 통과)
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 호스트에서 특정 연산(예: 데이터 정렬, 합산)을 PNM에 오프로딩 | CPU 개입 최소화 및 제어 오버헤드 |
| 2 | 메모리 다이에서 로직 다이로 TSV를 통해 데이터 대량 전송 | 패키지 내부 대역폭 활용도 |
| 3 | 로직 다이 내 연산기에서 데이터 처리 및 중간 결과 산출 | 연산 유닛 가동률 및 지연 시간 |
| 4 | 최종 결과값만 호스트로 전송하여 시스템 버스 부하 경감 | 데이터 전송량 감소 비율 (Traffic Saving) |

> 요약: 시스템 메인 도로(System Bus)를 타기 전에 골목길(Package 내부)에서 계산을 끝내고 결과만 큰길로 내보내는 방식이다.

## Ⅳ. 특징

| 구분 | 일반 컴퓨팅 (Remote) | 근접 메모리 (PNM) | 인메모리 (PIM) |
|:---|:---|:---|:---|
| 연산 위치 | 메인 프로세서 | 메모리 로직 다이/모듈 | 메모리 셀/뱅크 내부 |
| 데이터 이동 거리 | 매우 김 (수 cm) | 매우 짧음 (수 mm) | 거의 없음 (um) |
| 제조 난이도 | 낮음 | 중간 (패키징 혁신) | 매우 높음 (DRAM 공정 혁신) |
| 성능 잠재력 | 기준 (1x) | 우수 (2~5x) | 최우수 (10x 이상) |
| 적용 용이성 | 최상 | 우수 (CXL 등 연동) | 낮음 (전용 칩 개발) |

> 요약: PNM은 PIM보다 성능은 낮을 수 있으나, 제조 공정과의 호환성이 좋아 상용화에 가장 유리한 기술이다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | HBM 기반 PNM | CXL 기반 PNM (CMM-P) | 비고 |
|:---|:---|:---|:---|
| 구현 형태 | 가속기 내 적층 메모리 통합 | PCIe 슬롯형 메모리 카드 | 폼팩터 차이 |
| 주요 강점 | 극단적인 대역폭 활용 | 서버 확장성 및 유연한 교체 | 성능 vs 운영 |
| 주요 용도 | 거대 모델 학습 가속 | 대규모 추론 인프라 효율화 | 워크로드 특성 |

> 요약: 고성능 학습에는 HBM-PNM, 대규모 서비스 운영에는 CXL-PNM 방식이 주로 제안된다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| Thermal Wall | 로직 다이 연산으로 인한 적층 칩 발열 | 고성능 방열 패키징, 액체 냉각 | HBM 온도 및 리프레시 주기 |
| 프로그래밍 복잡도 | 연산 분담을 위한 코드 수정 필요 | 전용 SDK 및 자동 컴파일러 지원 | 개발자 적응 시간 (Learning Curve) |
| 면적 제한 | 로직 다이 내 연산기 공간 한계 | 칩렛(Chiplet) 구조 도입, 미세 공정 | 칩당 연산 밀도 (TOPS/mm²) |

> 요약: 연산에 따른 발열 제어가 제품 신뢰성의 핵심이며, 이를 위해 수냉식 냉각이나 첨단 방열 소재가 필수적이다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 데이터 트래픽 감소 | 호스트-메모리 간 전송량 70% 감소 | 버스 모니터링 및 시뮬레이션 |
| 에너지 효율 개선 | 와트당 성능 2배 이상 향상 | 전체 시스템 전력 소모량 측정 |
| 실효 대역폭 | 패키지 내 TSV 대역폭 90% 활용 | 로컬 데이터 처리 속도 측정 |

> 요약: 도입 성과는 시스템 버스의 여유 대역폭 확보량과 와트당 처리 성능으로 검증한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. **대규모 추천 엔진 가속**: 조 단위의 임베딩 테이블(Embedding Table)에서 데이터를 읽어와 합산하는 작업을 PNM으로 처리하여 추론 속도 5배 향상
2. **데이터베이스 가속**: SQL 쿼리의 필터링(Filtering)이나 집계(Aggregation) 작업을 메모리 단에서 미리 처리하여 CPU 부하 40% 경감
3. **거대 언어 모델 추론**: KV 캐시 관리 및 단순 연산을 PNM으로 오프로딩하여, 제한된 전력 내에서 더 많은 사용자 동시 접속 처리

**결론 (2줄):**
- 기술사 판단: PNM은 PIM의 성능과 일반 메모리의 제조 용이성을 결합한 '실질적 최적해'이며, LLM 시대의 추론 비용(TCO) 절감을 위한 핵심 기술이다
- 향후 방향: CXL 3.0 패브릭과 결합하여, 메모리 풀(Pool) 자체가 지능을 가진 '스마트 리소스 풀'로 진화할 것이다
