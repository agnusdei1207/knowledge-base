## 미리 알고가기

- ModelOps는 개별 학습 파이프라인보다 조직 전체 모델 포트폴리오를 안정적으로 운영하는 관리 관점이 강함
- 등록과 승인과 배포와 감사를 표준화해 다수 모델의 생애주기를 일관되게 통제하는 것이 목적임
- MLOps가 공장 자동화라면 ModelOps는 여러 공장을 포괄하는 운영 통제 체계에 가까움

## Ⅰ. 개요

- **정의/개념**: ModelOps는 기업 내 다양한 머신러닝과 통계 모델과 규칙 기반 모델을 포함한 모델 자산 전반의 등록과 승인과 배포와 모니터링과 폐기를 관리하는 운영 거버넌스 체계임
- **배경/필요성**: 조직이 수십 개에서 수백 개 모델을 동시에 운용하게 되면서 개별 팀 단위 MLOps만으로는 모델 재고와 위험 관리와 감사 대응을 일관되게 처리하기 어려워짐

## Ⅱ. 특징

- 모델 개발보다 모델 자산 관리와 운영 정책 표준화에 더 초점을 둠
- 다수 조직과 도메인의 서로 다른 모델을 공통 절차로 통제함
- 승인 단계와 책임 주체와 폐기 기준을 명확히 해 운영 리스크를 줄임
- 규제 산업에서는 성능보다 계보와 설명 책임과 변경 기록이 더 중요할 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | ModelOps | MLOps | AIOps |
|:---|:---|:---|:---|
| 초점 | 모델 포트폴리오 운영과 거버넌스 | 학습과 배포 자동화 | IT 운영 자동화 |
| 관리 범위 | 다수 팀과 다수 모델 | 개별 ML 파이프라인 | 로그와 이벤트와 인프라 |
| 핵심 기능 | inventory, approval, audit | training, registry, retraining | anomaly detection, remediation |
| 대표 성과 | 운영 통제와 규정 준수 | 배포 속도와 품질 | 장애 감축과 MTTR 개선 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Model Inventory | 조직 전체 모델의 목적과 소유자와 상태와 의존 시스템을 한눈에 관리하는 중앙 목록임 |
| Approval Workflow | 개발과 검증과 리스크 검토와 운영 승인을 단계별로 통과시키는 거버넌스 절차임 |
| Deployment Control | 운영 반영 시점과 대상 환경과 롤백 기준을 표준화해 변경 사고를 줄이는 제어 계층임 |
| Monitoring and Risk View | 성능과 드리프트와 장애와 규정 위반 신호를 집계해 운영 리스크를 지속적으로 가시화함 |
| Retirement Policy | 성능 저하나 중복 자산이나 규제 변경 시 모델을 폐기하고 후속 모델로 교체하는 종료 절차임 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 모델 등록    | -> | 검증 및 승인 | -> | 운영 배포    | -> | 성능 및 리스크 | -> | 교체 또는 폐기 |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **모델 등록**: 목적과 소유자와 입력 데이터와 규제 수준을 등록함
2. **검증 및 승인**: 성능과 안정성과 규정 준수 검토를 수행함
3. **운영 배포**: 승인된 모델만 표준화된 방식으로 운영 환경에 반영함
4. **성능 및 리스크 관측**: 운영 지표와 위험 신호를 지속적으로 모니터링함
5. **교체 또는 폐기**: 기준 미달 모델은 후속 모델로 전환하거나 종료함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 조직별로 모델 운영 절차가 다르면 승인 기준과 책임 범위가 달라져 운영 사고와 감사 누락이 늘 수 있음
   - 해결방안: enterprise model governance와 standardized approval workflow를 적용하고 policy compliance rate와 audit finding count로 검증함
2. 문제: 중앙 목록이 없으면 중복 모델과 고아 모델이 누적되어 유지보수 비용과 보안 위험이 커질 수 있음
   - 해결방안: centralized model inventory와 ownership policy를 적용하고 orphan model ratio와 duplicate model count로 검증함
3. 문제: 폐기 기준이 없으면 오래된 모델이 운영에 남아 성능 저하와 규정 위반을 장기화할 수 있음
   - 해결방안: retirement policy와 lifecycle review cadence를 적용하고 stale model ratio와 retirement cycle time으로 검증함

## Ⅶ. 적용 사례

- 금융권 모델 관리 플랫폼이 중앙 인벤토리와 승인 절차를 운영하며 확인 지표는 policy compliance rate와 audit finding count임
- 제조 예측 시스템이 모델 소유자와 폐기 기준을 등록하며 확인 지표는 orphan model ratio와 stale model ratio임
- 공공기관 AI 서비스가 모델 변경 기록과 검토 이력을 표준화하며 확인 지표는 lifecycle review completion rate와 duplicate model count임

## Ⅷ. 결론

ModelOps는 모델을 많이 쓰는 조직일수록 필요한 운영 통제 체계이므로 중앙 인벤토리와 승인 절차와 폐기 정책을 함께 설계해야 함.
