# 📖 【암기용】 개념 완전 이해

> 목적: LLM06 Excessive Agency를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: LLM 에이전트가 필요 이상 권한·도구·자율성을 부여받아 비인가 행동이나 피해를 수행하는 위험
- **왜 필요한가**: 생성형 AI가 파일 삭제, 결제, 메일 발송, 코드 실행, 외부 API 호출을 자동 수행하면 오류가 곧 실제 피해가 됨.
- **핵심 직관**: 말 잘하는 조수에게 회사 전체 관리자 권한을 주면 작은 오판도 큰 사고로 번지는 구조임.

## 깊이 이해
- **배경·문제의식**: LLM 에이전트는 목표를 달성하려고 여러 도구를 호출하지만 모델 판단은 확률적이며 프롬프트 공격에도 노출됨.
- **작동 원리**: 과도한 권한, 넓은 API 범위, 자동 승인, 반복 계획 실행이 결합되면 삭제·전송·결제·권한 변경 같은 위험 행동이 발생함.
- **비유**: 신입 직원에게 회계, 인사, 시스템 관리자 권한을 동시에 주고 모든 결정을 자동 승인하게 하는 상황임.
- **구체 예시**: 고객지원 에이전트가 환불 규정 오해로 1,000건 환불 API를 자동 실행하거나 외부 문서 지시에 따라 민감 파일을 전송함.
- **흔한 오해·주의점**: 모델이 고도화되어도 권한 최소화 원칙은 사라지지 않는다. 승인, 쿼터, 감사 로그가 필요함.

## 연결 개념
- AI Agent — 도구를 호출하는 자율 실행 구조
- Prompt Injection — 에이전트 권한 오남용을 유도
- Zero Trust — 최소권한·명시적 검증 원칙

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: LLM06은 LLM 에이전트에 과도한 권한과 자율성을 부여해 위험 행동이 발생하는 취약점임.
> 2. **가치**: 도구 호출이 실제 업무 시스템에 연결되면 데이터 삭제·외부 전송·비용 사고가 발생함.
> 3. **판단 포인트**: 최소권한, human approval, action allowlist, 쿼터, 감사 로그를 필수 적용해야 함.

## Ⅰ. 개요 및 필요성

LLM06은 과도한 에이전시 위험이다. LLM 에이전트는 외부 도구와 API를 호출해 실제 행동을 수행한다. 권한 범위와 자동 실행을 제한해야 한다.

## Ⅱ. 구조 및 구성요소

```text
User Goal -> LLM Planner -> Tool/API Permission
  -> Autonomous Action -> Approval/Audit Gate
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Planner | 목표를 단계로 분해 | 환각·오판 가능 |
| Tool Registry | 사용 가능한 API 목록 | allowlist 필요 |
| Permission Scope | 실행 권한 범위 | RBAC/ABAC |
| Approval Gate | 고위험 행동 승인 | human-in-the-loop |

> 요약: LLM06은 계획·도구·권한·자동 실행 경계가 넓을수록 위험 행동 가능성이 증가함.

## Ⅲ. 동작원리 및 흐름도

```text
목표 입력 -> 계획 생성 -> 도구 선택
  -> 권한 검증 -> 실행·감사
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 업무 목표와 허용 행동 정의 | action policy 100% |
| 2 | 도구 호출 전 권한·위험 등급 평가 | high-risk approval |
| 3 | 실행 횟수·금액·범위 제한 | quota, rate limit |
| 4 | 실행 로그와 결과 검토 | audit log 1년 보관 |

> 요약: LLM06 대응은 에이전트 행동을 정책화하고 고위험 작업을 승인·쿼터·감사로 통제함.

## Ⅳ. 특징

| 구분 | 일반 챗봇 | LLM06 Excessive Agency | 판단 포인트 |
|:---|:---|:---|:---|
| 기능 | 답변 생성 | 도구 호출·업무 실행 | 실제 피해 |
| 권한 | 읽기 중심 | 쓰기·삭제·결제 가능 | 최소권한 |
| 위험 | 부정확 답변 | 비인가 행동·비용 사고 | 승인 게이트 |
| 통제 | 출력 검증 | RBAC·쿼터·감사 | Zero Trust |

> 요약: Excessive Agency는 답변 품질 문제가 아니라 실제 시스템 행동 권한을 통제해야 하는 운영 보안 위험임.

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 도구 권한: 에이전트별 읽기·쓰기·삭제·결제 권한을 분리하고 삭제·결제는 human approval 필수 적용
2. 실행 제한: API 호출 횟수, 거래 금액, 외부 전송 도메인, 파일 범위를 쿼터와 allowlist로 제한
3. 감사 운영: action log, prompt, tool input/output을 저장하고 고위험 실행은 SIEM에 5분 이내 전송

**결론 (2줄):**
- 기술사 판단: 에이전트형 LLM은 모델 신뢰보다 최소권한과 명시적 승인 구조를 먼저 설계
- 향후 방향: LLM06 대응은 AI Gateway, policy-as-code, agent runtime sandbox와 결합됨
