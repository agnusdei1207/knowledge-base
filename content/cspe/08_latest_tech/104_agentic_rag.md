## 미리 알고가기

- Agentic RAG는 고정 파이프라인이 아니라 에이전트가 검색 계획과 도구 선택을 동적으로 수행하는 구조임
- planner, tool router, memory, reflection이 핵심 구성 요소임
- 복합 질의 처리력이 강하지만 비용과 권한 통제 부담도 커짐

## Ⅰ. 개요

- **정의/개념**: Agentic RAG는 LLM 에이전트가 질의를 분해하고, 검색기와 데이터베이스와 계산기 같은 도구를 여러 차례 선택 호출하며 필요한 정보를 모아 최종 답을 합성하는 동적 검색-생성 아키텍처임
- **배경/필요성**: 고정형 RAG는 한 번의 검색과 생성만으로는 다단계 추론, 이기종 데이터 결합, 후속 질의 분기 같은 복합 업무를 처리하기 어려우므로, 계획 기반 탐색 구조가 필요함

## Ⅱ. 특징

- 복합 질의를 단계별 계획으로 나눠 처리해 단일 검색형 RAG보다 문제 해결 범위가 넓음
- 검색기, SQL, 코드 실행기 등 서로 다른 도구를 조합해 업무형 에이전트로 확장할 수 있음
- 반복 탐색과 reflection이 가능해 중간 실패를 스스로 보정할 수 있음
- 자율성이 커진 만큼 무한 루프와 권한 오남용과 비용 폭증 위험도 함께 커짐

## Ⅲ. 종류 및 비교

| 판단 기준 | Advanced RAG | Agentic RAG | Workflow Agent |
|:---|:---|:---|:---|
| 제어 흐름 | 고정형 | 동적 | 반고정형 |
| 검색 횟수 | 보통 1회 | 다회 가능 | 단계별 정의 |
| 복합 질의 대응 | 중간 | 높음 | 높음 |
| 운영 통제 난도 | 중간 | 매우 높음 | 높음 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Planner | 질의를 여러 하위 작업으로 분해해 어떤 순서로 도구를 쓸지 계획함 |
| Tool Router | 검색기, DB, 계산기 중 현재 단계에 맞는 도구를 선택함 |
| Memory, Reflection | 중간 결과를 저장하고 정보가 충분한지 재평가해 다음 행동을 결정함 |
| Guardrails, Budget Control | 최대 단계 수와 권한과 비용 상한을 통제해 자율성을 안전하게 제한함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 질의 분해/계획  | --> | 도구 선택/호출   | --> | 결과 관찰/재계획 | --> | 최종 합성 응답   |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **질의 분해 및 계획**: 질문을 하위 작업으로 나누고 필요한 정보원을 식별함
2. **도구 선택 및 호출**: 현재 단계에 맞는 검색기나 DB나 계산 도구를 실행함
3. **결과 관찰 및 재계획**: 얻은 결과를 메모리에 저장하고 추가 탐색 여부를 판단함
4. **최종 합성 응답**: 충분한 근거가 모이면 종합 답변을 생성함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 에이전트가 충분한 정보를 못 찾았다고 판단해 불필요한 검색과 도구 호출을 반복하면 비용과 응답 시간이 급증할 수 있음
   - 해결방안: max steps와 budget policy를 적용하고 average steps와 cost per answer로 탐색 효율을 검증함
2. 문제: 도구 설명이 부실하거나 권한 통제가 약하면 잘못된 도구 호출이나 민감 정보 접근이 발생할 수 있음
   - 해결방안: tool schema와 ACL을 엄격히 정의하고 tool call success rate와 unauthorized action rate로 통제를 검증함
3. 문제: 계획과 실행이 모두 모델 판단에 의존하면 중간 오류가 연쇄적으로 누적될 수 있음
   - 해결방안: reflection과 fallback workflow를 추가하고 recovery success rate와 final answer quality로 복구력을 검증함

## Ⅶ. 적용 사례

- 재무 분석 보조: 문서 검색과 DB 조회와 계산을 연결함, 확인 지표는 task completion rate와 tool call accuracy임
- 고객지원 업무자동화: 정책 문서와 주문 시스템을 함께 조회함, 확인 지표는 resolution rate와 average steps임
- 연구 보조 에이전트: 여러 자료원을 순차 탐색함, 확인 지표는 evidence coverage와 answer faithfulness임

## Ⅷ. 결론

Agentic RAG는 검색을 문제 해결 에이전트 수준으로 확장한 구조이므로, 검색 성능보다 계획 통제와 권한 통제와 비용 통제가 실무 성공의 핵심이 됨.
