## 미리 알고가기

- 에이전틱 RAG ($Agentic$ $RAG$): 고정된 순차 파이프라인에서 벗어나, 의사 결정 능력을 지닌 AI 에이전트(LLM)가 주도적으로 질문의 의도를 분석하고, 필요한 다양한 정보 도구(SQL, 벡터 DB, 웹 검색 등)를 스스로 판단 및 여러 차례 동적 스케줄링하여 최적의 답을 끌어내는 주체적 RAG 체계임
- 반추 ($Reflection$): 수집된 외부 정보 조각들을 에이전트가 자체 비판 검증하여 "정보가 신뢰할 만한가?", "추가 검색이 더 필요한가?" 등을 스스로 평가하는 성찰 단계임
- 도구 라우팅 ($Tool$ $Routing$): 쿼리의 문맥에 맞춰 사전에 정의된 외부 API 도구들(예: 계산기, 인사 DB, 지식 위키) 중 가장 적합한 도구를 감지해 인자를 사상해 호출하는 기법임
- 무한 탐색 루프 ($Infinite$ $Loop$): LLM 에이전트의 성찰 기준이 오작동하여, 답을 내지 못하고 의미 없는 검색을 서버가 뻗을 때까지 영구 반복하는 자원 낭비 결함임

## Ⅰ. 개요

- **정의/개념**: Agentic RAG는 사용자의 난해한 요구사항에 대해 LLM 에이전트가 직접 다단계 계획(Planning)을 수립하고, 다양한 외장 보조 도구(Vector DB, SQL, Web API 등)를 자율 라우팅 호출(Execution)하며, 도출된 정보를 자가 평가(Reflection) 및 보정 조율해 답변을 구성하는 지능형 검색-생성 아키텍처임
- **배경/필요성**: 기존 RAG는 "A사의 영업이익 증가율과 B사의 복리후생 수준을 대비해 요약해줘" 같은 고난도 복합 추론 요청에 직면했을 때, 단발성 검색만으로는 파이프라인이 즉각 좌초하여 다차원 동적 지식 조율(Dynamic Orchestration)이 필수적으로 요구되어 대두됨

## Ⅱ. 특징

- 질문을 독립적인 서브 태스크로 해체하고, 도구 라우팅(Tool Routing)을 통해 필요한 지식 격리를 다중 이종 인프라에서 순차 진행함
- 반추(Reflection) 및 자가 보정 기능을 탑재해, 1차 검색에서 원하는 답이 나오지 않았을 시 쿼리 조건을 보강해 2차 재검색을 스스로 수행함
- 자유도가 높은 반면, 모델의 추론 루프가 비정상 꼬일 시 API 호출 과다 과금과 인프라 응답 시간 지연 스파이크를 발생시킴

## Ⅲ. 종류 및 비교

| 판단 기준 | 고도화형 RAG (Advanced RAG) | 에이전틱 RAG (Agentic RAG) | 워크플로우 자동화 (Workflow Agent) |
|:---|:---|:---|:---|
| **제어 오케스트레이션** | 하드코딩된 단선 구조 (고정 파이프라인) | 자율 결정 (LLM Reasoning 기반 dynamic 루프) | 반고정형 그래프 (DAG 기반 분기 조건문 작동) |
| **외부 연동 도구군** | 오직 벡터 데이터베이스, 키워드 검색기 | 이종 도구 연동 (Vector DB, SQL, 인터넷 API 등) | 사전에 바인딩된 고유 업무 API |
| **반복 성찰 ($Reflection$)** | 불가능 | 가능 (답변의 타당성을 스스로 평가 후 재질의) | 불가능 (정적 분기 통과) |
| **주요 적용 씬** | 단순 팩트 매뉴얼 질의응답 | 다단계 복합 재무 분석, 시장 조사 비교 | 기계적 양식 메일 발송, 결재 라인 이관 |

> 요약: Advanced RAG가 인덱스를 똑똑하게 찾는 사전 포맷 최적화라면, Agentic RAG는 직접 문제 해결 계획을 짜고 SQL을 때리거나 계산기를 두드리며, 도출된 중간 값을 가지고 추가 분석(Reflection)을 자율 수행하는 만능 해결사임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 계획 수립기 | 복합 쿼리를 해체하여 목표 로드맵과 필요한 도구 우선순위를 짜는 Planner 엔진임 |
| 도구 호출 라우터 | 적정 외장 데이터 소스를 매핑해 API 페이로드를 조립 송출하는 Router임 |
| 성찰 및 메모리 | 작업 궤적을 뇌에 남기고, 문맥의 유효성 검사 및 정답 근접 여부를 정량 평가하는 판정 모듈임 |
| 비용/보안 통제기 | 최대 탐색 한계선($Max$ $Steps$)을 강제하여 과금 폭탄 및 권한 탈출을 막는 안전망임 |

```text
[ Agentic RAG (동적 계획 및 성찰 루프) 구조 ]
User Query ──> [ Planner (계획 수립) ] <────────────────────────────┐ (Loop Back)
                        │                                           │
                        v                                           │
                 [ Tool Router ] ──> Call Tools: [ Vector DB, SQL, API ]
                        │                                           │
                        v                                           │
             [ Reflection / Memory ] ──> Check: "Is Answer Sufficient?" ────┘
                        │ (Yes, output)
                        v
                 Safe Final Response
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 다단계 계획 | --> | 정보원 도구  | --> | 반추 통해   | --> | 획득한 지식 |
| 로드맵 수립 |     | 동적호출/수집 |     | 추가조회판단|     | 다각융합생성|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **태스크 해체** — 사용자의 다중 비교 질의를 파싱하고 "A사 분석" -> "B사 분석" -> "공통점 비교"의 DAG 계획을 자율 편성함
2. **도구 선택 가동** — A사 데이터를 얻기 위해 사내 위키용 Dense 검색을 치고, A사의 재무 제표 취득을 위해 SQL 툴을 순차 킥킹함
3. **자가 성찰 집행** — 두 도구로부터 취합된 정보들을 메모리 버퍼에 싣고 "2026년 데이터 누락 여부" 등을 스스로 검산 비판함
4. **합성 방출** — 판단 결과 데이터가 온전히 확보되면 재탐색 루프를 탈출하고, 복합 추론 응답을 이식성 높게 패키징 방출함

## Ⅵ. 실무 적용 및 유의점

1. 에이전트가 "답을 아직 못 찾았다"고 맹신하거나 판정 로스가 진동(Oscillation)할 시, 외부 API 검색 호출을 영구 반복하는 '무한 탐색 루프' 결함이 터지므로, 반드시 '최대 탐색 횟수($Max$ $Steps$)' 및 '시간 비용 예산 초과(Budget Control)' 임계 강제 장치를 셋업해야 함
2. LLM이 생성한 쿼리를 DB에 다이렉트 바인딩해 가동할 시, SQL 인젝션 공격 및 권한 외 임원 정보 DB 조회 탈출 사고가 일어날 수 있으므로, 반드시 에이전트 권한용 '도구 ACL 스키마'를 수립하고 비인가 동작 시도율($Unauthorized$ $Action$ $Rate$)을 상시 검출해야 함

## Ⅶ. 결론

- Agentic RAG는 RAG의 데이터 접근 한계를 지능 에이전트의 주체적 자율 스케줄링으로 해소한 최신 지적 아키텍처의 완성형이며, 설계자는 자율성 과도화에 따른 API 무한 루프 과금 방어책(Max Steps)과 툴 매핑 ACL 보안 격리 장치를 반드시 물리적으로 강제 적용해야 함
