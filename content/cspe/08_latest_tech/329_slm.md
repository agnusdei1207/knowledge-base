# 📖 【암기용】 개념 완전 이해

> 목적: SLM을 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 챗GPT 같은 거대 언어 모델(LLM)보다 크기는 수백 배 작지만, 특정 분야나 기기 안에서 충분히 똑똑하게 동작하도록 만든 효율적인 인공지능 모델
- **왜 필요한가**: LLM은 너무 커서 돌리는 데 돈이 너무 많이 들고, 성능 좋은 서버가 필수다. 하지만 SLM은 스마트폰이나 개인 PC에서도 빠르게 돌아가며, 특정 지식(예: 법률, 의료)만 집중 학습하면 성능도 LLM 못지않기 때문이다.
- **핵심 직관**: "모든 걸 다 아는 '백과사전' 대신, 내가 필요한 지식만 담긴 '전문 요약집'이나 '핸드북'."

## 깊이 이해
- **배경·문제의식**: LLM(수천억 개 파라미터)은 한 번 질문할 때마다 전력과 비용이 막대함. 또한 기업이 자기들만의 기밀 데이터를 LLM에 학습시키기엔 너무 크고 위험함. 저렴한 비용으로 사내망이나 개인 기기에서 돌릴 수 있는 가벼운 모델이 필요해짐.
- **작동 원리**: 파라미터 수를 10억~100억 개(1B~10B) 정도로 줄임. 모델을 작게 만들면서도 성능을 유지하기 위해 고품질 데이터를 선별 학습하거나, 큰 모델의 지식을 작은 모델에게 전수하는 '지식 증류(Knowledge Distillation)' 기술을 사용함.
- **비유**: 전교 1등(LLM)은 모든 과목을 다 잘하지만, 부르기도 힘들고 과외비도 비쌈. 반면 수학 전문 튜터(SLM)는 수학 하나만큼은 전교 1등만큼 잘하면서도 부르기 쉽고 비용도 저렴한 것과 같음.
- **구체 예시**: 마이크로소프트의 'Phi-3', 구글의 'Gemma', 메타의 'Llama-3-8B' 등이 대표적임. 이들은 스마트폰이나 노트북에서 실행되어 메일 요약, 코드 작성 보조 등을 훌륭히 수행함.
- **흔한 오해·주의점**: 작다고 해서 '단순한' 모델이 아님. 학습 데이터의 질이 훨씬 높기 때문에(Curated Data), 범용 지식은 부족할지 몰라도 논리력이나 특정 도메인 지식은 매우 강력함.

## 연결 개념
- LLM (Large Language Model) - SLM의 기반이 되는 거대 모델
- Knowledge Distillation (지식 증류) - 큰 모델의 지식을 작은 모델로 옮기는 핵심 기술
- On-device AI - SLM이 주로 활용되는 실행 환경

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 파라미터 규모(1B~10B), 경량화 기법(Quantization, Pruning, Distillation), 특정 도메인 특화(Fine-tuning) 및 온디바이스 최적화를 기술적으로 논한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: SLM(Small Language Model)은 파라미터 수를 100억 개 이하로 최적화하여 연산 효율성과 데이터 보안성을 극대화한 실용 중심의 언어 모델이다.
> 2. **가치**: 초거대 모델 대비 저렴한 추론 비용(Inference Cost)과 낮은 전력 소모를 실현하며, 특정 도메인(Domain-specific)에 특화된 고성능 인공지능 구현을 가능하게 한다.
> 3. **판단 포인트**: 모델 크기 축소에 따른 성능 저하를 방지하기 위한 '고품질 데이터 학습'과 '지식 증류(Distillation)' 기술의 고도화가 핵심이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| LLM 대비 효율성 및 경제성 파악 | 파라미터 규모 차이, TCO(총 소유 비용) 절감 효과 | 단순히 "작은 모델"로만 서술 지양 |
| 모델 경량화 및 고도화 기술 이해 | Knowledge Distillation, Quantization, Fine-tuning | 기술적 명칭 및 구체적 기법 누락 주의 |
| 비즈니스 활용 및 온디바이스 연계 | 도메인 특화 AI, 보안성(Privacy), On-device AI | 활용 사례 없이 이론적 정의에만 치중 |

> 요약: SLM은 '거대화' 경쟁에서 벗어나 '효율'과 '성능'의 균형을 추구하는 AI 대중화의 핵심 기술이다.

## Ⅰ. 개요 및 필요성

- 정의: 수십억 개(Billion) 규모의 파라미터를 보유하여 제한된 자원 환경(단말기, 로컬 서버)에서 효율적으로 구동되도록 설계된 소형 언어 모델
- 배경: LLM의 막대한 컴퓨팅 비용 및 탄소 배출 문제, 기업 내부 데이터의 보안 유지를 위한 폐쇄형 AI 니즈 증대
- 필요성: 온디바이스 AI 서비스 실현, 특정 산업(금융, 법률 등) 특화 성능 확보, AI 서비스 운영 비용(Inference OPEX) 현실화

## Ⅱ. 구조 및 구성요소 (경량화 및 고도화 기술)

```text
[ Large Model (Teacher) ] ----> [ Knowledge Distillation ] ----> [ Small Model (Student) ]
         |                            |                              |
  (방대한 파라미터)              (핵심 로직 전수)                (압축된 파라미터)
         |                            |                              |
         +----------------------------+------ [ Pruning / Quantization ]
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Parameter Scaling | 모델의 크기를 1B ~ 10B 수준으로 조정 | 연산 속도 및 메모리 사용량 결정 |
| Knowledge Distillation | 거대 모델의 출력 분포를 학습하여 작은 모델의 성능 강화 | Teacher-Student 모델 구조 |
| Weight Pruning | 중요도가 낮은 파라미터(가중치)를 제거하여 모델 경량화 | 모델 구조 최적화 |
| Quantization | 부동소수점 데이터를 정수형으로 변환 (FP16 -> INT8) | 온디바이스 가속기(NPU) 최적화 |

> 요약: 모델 구조를 깎고(Pruning/Quantization), 거대 모델의 지식을 효율적으로 전수(Distillation)받는 구조이다.

---

## Ⅲ. 동작원리 및 흐름도 (Domain-Specific SLM 구축)

```text
High-Quality Data -> [ 1. Pre-training ] -> [ 2. Fine-tuning ] -> [ 3. Optimization ]
        |                   |                        |                       |
(정제된 전문 데이터)    (기초 언어 능력 학습)      (도메인 지식 주입)      (온디바이스 최적화)
        |                   |                        |                       |
        +-------------------+------------------------+------------> [ 4. Deployment ]
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 데이터 선별 | 양(Quantity)보다 질(Quality) 중심의 고품질 교과서급 데이터셋 구축 | 데이터의 신뢰성 및 논리성 |
| 2 | 기초 학습 | 축소된 파라미터 구조 위에서 언어적 기본 원리 학습 | 퍼플렉서티 (Perplexity) |
| 3 | 파인튜닝 | 특정 분야(법률, 의료 등)의 전문 데이터를 통한 미세 조정 | 도메인 특화 벤치마크 점수 |
| 4 | 최적화 배포 | 사용 환경(Mobile, Edge)에 맞춰 양자화 및 성능 튜닝 수행 | 추론 속도 및 메모리 점유율 |

> 요약: '작지만 강한' 모델을 위해 학습 데이터의 질을 극대화하고 타겟 도메인에 역량을 집중한다.

## Ⅳ. 특징 (LLM 대비 우위 요소)

| 구분 | 주요 특징 | 상세 내용 |
|:---|:---|:---|
| 경제성 | Low TCO | 추론 인프라 비용을 LLM 대비 1/100 이하로 절감 가능 |
| 보안성 | Privacy First | 기업 내부에 설치(On-premise)하거나 기기 내에서 처리하여 보안성 우수 |
| 민첩성 | High Speed | 작은 모델 크기로 인해 지연 시간(Latency)이 짧고 실시간 대응 용이 |
| 전문성 | Domain Expert | 특정 분야 데이터로 집중 학습 시, 해당 분야에서는 거대 모델 필적 가능 |

> 요약: 비용, 보안, 속도의 강점을 바탕으로 실제 비즈니스 현장 적용에 최적화되어 있다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | Large Language Model (LLM) | Small Language Model (SLM) | 선택 기준 |
|:---|:---|:---|:---|
| 규모 (Parameter) | 100B ~ Trillion 이상 | 1B ~ 10B 내외 | 하드웨어 자원 제약 |
| 범용 지식 | 매우 광범위하고 다양함 | 상대적으로 좁지만 깊음 | 유스케이스의 범위 |
| 추론 비용 | 매우 높음 (H100 등 고가 장비) | 낮음 (일반 GPU 또는 모바일 AP) | 예산 및 서비스 규모 |
| 할루시네이션 | 발생 빈도 높음 | 데이터 통제로 어느 정도 완화 가능 | 신뢰도 중요도 |

> 요약: 창의적이고 범용적인 작업은 LLM, 정해진 도메인의 효율적 처리는 SLM이 적합하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 일반 상식 부족 | 파라미터 축소로 인한 지식 저장 용량 한계 | RAG(검색 증강 생성) 연계로 부족한 지식 보완 | 상식 질문 답변 정확도 |
| 다국어 능력 저하 | 특정 언어 데이터 위주의 학습 | 다국어 고품질 데이터 혼합 및 증류 기법 강화 | 언어별 성능 비교 |
| 복합 추론 한계 | 매개변수 부족으로 인한 고난도 논리 연산 미흡 | CoT(Chain of Thought) 프롬프팅 최적화 | 논리/수학 문제 해결률 |

> 요약: '지식의 양' 부족을 '외부 데이터 연동(RAG)'과 '추론 기법'으로 보완하는 전략이 필요하다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 추론 속도 (TPS) | 초당 50~100 토큰 이상 생성 | 성능 테스트 툴 (Locust 등) |
| 모델 크기 (Disk) | 5GB ~ 10GB 이하 (양자화 적용 시) | 파일 시스템 용량 체크 |
| 도메인 정확도 | 전문 분야 벤치마크 90% 이상 | 전문가 정성 평가 및 정량 테스트 |

> 요약: 도입 효과는 운영 비용의 절감 수치와 실제 업무 적용 시의 응답 품질로 평가한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. **사내 보안 챗봇**: 회사의 내부 기밀 문서를 학습시켜, 데이터 외부 유출 걱정 없이 직원들이 업무 지식을 검색하고 활용하는 전용 AI 비서
2. **에지 AI 장치 탑재**: CCTV나 로봇에 SLM을 탑재하여 현장에서 즉각적인 상황 판단 및 음성 명령 수행
3. **전문직 보조 도구**: 법률 판례나 의학 논문만 집중 학습시킨 SLM을 구축하여 해당 분야 전문가들의 초안 작성 및 검토 시간 단축

**결론 (2줄):**
- 기술사 판단: SLM은 AI의 '거품'을 제거하고 실제 산업 현장에서 '수익성'을 창출할 수 있게 만드는 실전형 기술이다.
- 향후 방향: 모델은 작아지되 데이터는 더 정교해지는 'Data-centric AI' 기조가 강화되며, 용도별로 수많은 SLM이 협업하는 구조로 발전할 것이다.
