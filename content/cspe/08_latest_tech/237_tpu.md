# 📖 【암기용】 개념 완전 이해

> 목적: TPU를 Google이 딥러닝 행렬곱을 위해 설계한 systolic array 기반 전용 가속기로 이해하게 만든다.

## 한눈에
- **개요**: 딥러닝 텐서 연산, 특히 행렬곱-누산을 systolic array로 처리하는 전용 AI 가속기
- **왜 필요한가**: 대규모 딥러닝은 행렬곱 비중이 높아 범용 병렬 처리보다 전용 데이터플로 구조가 전력당 처리량 확보에 유리하다.
- **핵심 직관**: 여러 작업대가 격자처럼 배치되어 데이터가 옆 작업대로 흘러가며 곱셈과 누산을 반복하는 조립 라인이다.

## 깊이 이해
- **배경·문제의식**: Google은 검색, 번역, 추천 같은 대규모 AI 서비스를 위해 데이터센터 추론·학습 비용을 줄일 전용 가속기가 필요했다.
- **작동 원리**: systolic array의 MAC 유닛 격자에 가중치와 activation이 흘러가며 행렬곱을 누적하고, HBM과 온칩 버퍼가 데이터 이동을 줄인다.
- **비유**: 물건을 한 작업자가 들고 다니지 않고 컨베이어로 옆 작업대에 넘기며 같은 조립 단계를 반복하는 생산 라인과 같다.
- **구체 예시**: TPU v1은 INT8 추론 중심이었고 이후 세대는 BF16 학습, HBM, ICI 기반 TPU Pod로 대규모 학습을 지원한다.
- **흔한 오해·주의점**: TPU는 GPU의 상위 호환이 아니다. 정형 행렬곱에는 적합하지만 비정형 제어, 다양한 커스텀 연산, CUDA 생태계 활용은 GPU가 유리할 수 있다.

## 연결 개념
- AI Accelerator — TPU가 속한 상위 범주
- GPU — 범용 병렬 AI 가속 대안
- Systolic Array — TPU 연산 구조의 핵심

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.
> 핵심: TPU는 systolic array, BF16/INT8, ICI/Pod 확장, GPU 대비 특화성과 종속성을 함께 설명해야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: TPU는 systolic array 기반 MAC 연산으로 딥러닝 텐서 연산을 처리하는 전용 AI 가속기임.
> 2. **가치**: 정형 행렬곱 중심 workload에서 데이터 이동을 줄이고 전력당 처리량을 확보함.
> 3. **판단 포인트**: 대규모 정형 학습은 TPU, 범용성·이식성·다양한 커스텀 연산은 GPU를 비교 선택함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |

| 생태계 리스크 확인 | Google Cloud, XLA, JAX/TensorFlow | 벤더 종속 누락 |

> 요약: 이 문제는 TPU의 행렬곱 특화 구조와 GPU 대비 적용 조건을 구분해야 한다.

## Ⅰ. 개요 및 필요성

- 개요: 딥러닝 행렬곱 특화 가속기
- 배경: 대규모 AI 서비스는 반복 행렬 연산과 데이터 이동 비용이 전체 처리량을 좌우함.
- 필요성: BF16/INT8, MAC utilization, Pod scaling efficiency 기준으로 정형 AI workload를 처리해야 함.

---

## Ⅱ. 구조 및 구성요소

```text
Host -> XLA Compiler -> TPU Chip -> Systolic Array -> On-chip Buffer -> HBM -> ICI -> TPU Pod
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| XLA Compiler | 모델 그래프를 TPU 실행계획으로 변환 | TensorFlow, JAX 연계 |
| Systolic Array | MAC 유닛 격자에서 행렬곱 수행 | 데이터플로 연산 |
| On-chip Buffer/HBM | 가중치·activation 저장 | 데이터 이동 감소 |
| ICI/TPU Pod | 다중 TPU 칩 연결 | 대규모 학습 확장 |

> 요약: TPU는 컴파일러, systolic array, 메모리, 칩 간 연결이 결합된 행렬곱 특화 가속 구조다.

---

## Ⅲ. 동작원리 및 흐름도

```text
모델 그래프 컴파일 -> 입력·가중치 버퍼 적재 -> systolic array MAC 실행 -> HBM 갱신 -> ICI 동기화
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | XLA가 모델 그래프를 TPU 연산으로 컴파일 | compile success |
| 2 | 입력과 가중치를 on-chip buffer/HBM에 적재 | buffer hit rate |
| 3 | systolic array가 MAC 연산 수행 | MAC utilization |
| 4 | Pod 학습 시 ICI로 gradient 동기화 | scaling efficiency |

> 요약: TPU는 컴파일된 그래프를 systolic array에서 실행하고 Pod 구성에서는 ICI 통신 효율이 처리량을 좌우한다.

---

## Ⅳ. 특징

| 구분 | GPU | TPU | 수치 기준 |
|:---|:---|:---|:---|
| 구조 | SIMT + Tensor Core | systolic array ASIC | MAC utilization |
| 적용 | 범용 병렬·다양한 연산 | 정형 텐서 연산 | BF16/INT8 |
| 확장 | NVLink/InfiniBand | ICI/TPU Pod | scaling efficiency |

> 요약: TPU는 정형 텐서 연산 특화, GPU는 범용 병렬성과 생태계 폭에서 차이가 있다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | GPU는 프로그래밍 범용성 | TPU는 행렬곱 dataflow 특화 | 커스텀 연산 비중 |
| 비용/성능 | GPU는 선택 폭 넓음 | TPU는 클라우드 중심 | 벤더 종속 허용도 |
| 운영/위험 | CUDA 생태계 | XLA/JAX/TensorFlow 중심 | 개발팀 역량과 이식성 |

> 요약: TPU 선택은 행렬곱 비중, 클라우드 종속 허용도, XLA 생태계 역량으로 판단한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 이식성 제약 | XLA와 Google Cloud 중심 | 프레임워크 추상화, 대체 GPU 경로 유지 | porting time |
| 커스텀 연산 부적합 | systolic array 정형성 | op coverage 확인, fallback 설계 | unsupported op count |
| 통신 병목 | Pod 규모 증가 | 병렬화 전략 조정, overlap 적용 | all-reduce time |

> 요약: TPU 리스크는 이식성, 커스텀 연산, 통신 병목이며 사전 op 검증과 병렬화 설계로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 연산 활용 | MAC utilization 목표 충족 | XLA profiler |
| 처리량 | samples/sec 또는 tokens/sec 목표 | training log |
| 확장 | Pod scaling efficiency 목표 | scale test |

> 요약: TPU 도입 성과는 MAC 활용률, 처리량, Pod 확장 효율로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 모델의 unsupported op, dynamic shape, custom kernel 비중을 사전 점검해 TPU 적합성을 판정함.
2. JAX/TensorFlow와 XLA compile path를 표준화하고 GPU fallback 경로를 유지함.
3. Pod 규모별 all-reduce time과 step time을 측정해 병렬화 전략을 조정함.

**결론 (2줄):**
- 기술사 판단: 정형 행렬곱 중심 대규모 학습은 TPU, 범용 연구·커스텀 연산·멀티벤더 운영은 GPU를 우선 검토함.
- 향후 방향: TPU는 ICI 대역폭, HBM 용량, 저정밀 연산 지원 확대를 통해 대규모 AI 학습·추론 인프라로 확장됨.
