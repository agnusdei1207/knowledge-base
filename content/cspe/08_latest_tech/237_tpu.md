# 📖 【암기용】 개념 완전 이해

> 목적: TPU(Tensor Processing Unit) 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 구글이 자체적으로 설계한 AI 연산 전용 반도체(ASIC)
- **왜 필요한가**: GPU는 범용적이라서 안 쓰는 기능이 많고 전기를 많이 먹음. 구글은 검색, 번역, 사진 분석 등 방대한 AI 작업을 더 빠르고 싸게 처리하기 위해 'AI 전용' 칩을 직접 만듦
- **핵심 직관**: "여러 요리를 다 하는 주방(GPU) 대신, 빵만 기가 막히게 대량 생산하는 제빵 전용 공장(TPU)을 지은 것"

## 깊이 이해
- **배경·문제의식**: 딥러닝 연산의 90% 이상은 행렬 곱셈임. 일반적인 컴퓨터는 곱셈 결과를 메모리에 적고 다시 읽어오는 과정을 반복하는데, 이게 다 시간이고 열임. 이를 해결하기 위해 메모리 접근을 최소화하는 '시스톨릭 어레이' 구조를 도입함
- **작동 원리**: **시스톨릭 어레이(Systolic Array)** 아키텍처가 핵심임. 데이터가 심장 박동처럼 연산기 사이를 한 방향으로 흐르며 계산이 끝날 때까지 메모리로 돌아가지 않음. 덕분에 전력 효율이 극도로 높고 연산 속도가 일정함(Deterministic)
- **비유**: 공장의 조립 라인처럼, 부품(데이터)이 컨베이어 벨트를 따라 쭉 이동하면서 각 단계의 로봇(연산기)들이 자기 할 일만 딱딱 하고 마지막에 완제품이 나오는 방식
- **구체 예시**: 구글 검색, 구글 포토의 인물 분류, 딥마인드의 알파고(AlphaGo) 학습에 사용됨. 현재는 클라우드(Cloud TPU)를 통해 외부 개발자도 사용 가능
- **흔한 오해·주의점**: "TPU는 구글에서만 쓸 수 있다"는 반은 맞고 반은 틀림. 실물 칩을 살 수는 없지만, 구글 클라우드(GCP)를 통해 대여해서 사용할 수 있음. 또한 텐서플로(TensorFlow)뿐만 아니라 PyTorch, JAX도 완벽히 지원함

## 연결 개념
- **Systolic Array**: TPU 성능의 핵심인 데이터 흐름 아키텍처
- **ASIC (Application Specific IC)**: 특정 용도(AI)를 위해 맞춤 제작된 반도체
- **HBM**: TPU v2부터 탑재된 초고속 메모리

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: GPU와의 차별점인 **시스톨릭 어레이(Systolic Array), CISC 스타일의 Matrix 명령어, 높은 전력 효율성(TOPS/W)**을 강조한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: TPU는 구글이 텐서 연산 가속을 위해 설계한 도메인 특화 반도체(ASIC)로, 시스톨릭 어레이(Systolic Array) 기반의 데이터 흐름(Data-flow) 아키텍처를 채택하고 있다.
> 2. **가치**: 불필요한 제어 로직을 최소화하고 연산 유닛 밀도를 높여, 거대 모델 학습 및 추론 시 GPU 대비 높은 전력 효율성과 비용 절감 효과를 제공한다.
> 3. **판단 포인트**: 대규모 클러스터링(Pod) 확장성, 전용 인터커넥트(ICI), 구글 클라우드 환경과의 통합성을 고려하여 워크로드를 할당해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| AI 전용 가속기 구조 이해도 측정 | 시스톨릭 어레이(Systolic Array), MXU(Matrix Multiply Unit) | 단순히 "구글이 만든 칩" 수준의 서술 |
| GPU 대비 기술적 우위 분석 | 결정론적 성능(Deterministic), 저전력, 메모리 대역폭 활용 | "GPU보다 무조건 좋다"는 단정적 서술 지양 |

> 요약: 메모리 접근을 줄이는 '시스톨릭 구조'와 '전용 ASIC'으로서의 경제성을 중심으로 기술한다.

---

## Ⅰ. 개요 및 필요성

- 정의: 딥러닝의 핵심인 행렬 연산(Matrix Operations)을 가속하기 위해 구글이 개발한 텐서 연산 특화 프로세서(ASIC)
- 배경: 기존 GPU/CPU 구조에서는 반복적인 메모리 Access(Read/Write)로 인해 발생하는 전력 소모와 지연 시간을 감당하기 어려움
- 필요성: 글로벌 스케일의 AI 서비스 운영 비용 절감, 거대 모델 학습 가속화, AI 연산의 에너지 효율 극대화

---

## Ⅱ. 구조 및 구성요소

```text
[TPU Architecture]
  |-- MXU (Matrix Multiply Unit): 128x128 Systolic Array
  |-- Unified Buffer (SRAM): 데이터 임시 저장
  |-- Weight FIFO: 가중치 공급
  |-- HBM (High Bandwidth Memory): 고대역폭 외부 메모리
  `-- ICI (Inter-Core Interconnect): TPU 간 고속 통신
```

| 구성요소 | 역할 | 기술적 특징 |
|:---|:---|:---|
| MXU | 행렬 곱셈 수행의 핵심 엔진 | 65,536개의 MAC 연산을 한 사이클에 수행 |
| 시스톨릭 어레이 | 데이터 흐름 제어 구조 | 가로/세로 방향으로 데이터가 흐르며 연산 |
| Unified Buffer | 연산 중간 결과 저장 및 재사용 | 메모리 병목 완화용 대용량 SRAM |
| ICI (Inter-Core) | TPU Pod 구성을 위한 통신망 | 별도 스위치 없이 직접 연결(Direct Connect) |

> 요약: MXU를 중심으로 대규모 행렬 연산을 메모리 간섭 없이 순차적으로 처리하는 최적화 구조이다.

---

## Ⅲ. 동작원리 및 흐름도

```text
Host Command -> Read Weights -> Read Data -> Systolic Flow (MAC) -> Write Back
(명령어 수신)    (HBM에서 로드)   (Buffer 로드)  (어레이 내 데이터 전송) (결과값 저장)
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 가중치(Weights)를 MXU 내부에 미리 로딩 | 초기화 지연 시간 통제 |
| 2 | 입력 데이터가 어레이의 한쪽 끝에서 유입 | 데이터 정렬(Alignment) 확인 |
| 3 | 각 연산기(PE)에서 곱셈 후 옆/아래로 전달 | 클럭 동기화 및 데이터 흐름 무결성 |
| 4 | 최종 합산 결과가 반대편 끝에서 산출 | 결과 데이터의 유효성 검증 |

> 요약: 데이터가 칩 내부 연산기들을 통과하며 결과가 완성되는 '파이프라인식 흐름 연산' 방식이다.

---

## Ⅳ. 특징

| 구분 | GPU (범용 가속기) | TPU (AI 전용 ASIC) | 판단 포인트 |
|:---|:---|:---|:---|
| 아키텍처 | SIMT (멀티 코어) | Systolic Array (Data-flow) | 연산 유닛의 연결 방식 |
| 메모리 관리 | 명시적 캐시/공유 메모리 활용 | 데이터 흐름 기반 자동 재사용 | 프로그래밍 모델의 복잡도 |
| 성능 특성 | 비결정적 (경합 발생 가능) | 결정론적 (고정된 사이클 소요) | 배치 처리의 예측 가능성 |
| 수치 사례 | 높은 TFLOPS (FP32 위주) | 매우 높은 TOPS/W (저전력) | 운영 비용(OPEX) 관점 |

> 요약: TPU는 불필요한 캐시 계층을 줄이고 연산기에 직접 데이터를 흘려보내 전력 효율을 극대화한다.

## Ⅴ. 심화 비교 및 적용 판단

| 버전 | 특징 | 주요 용도 | 기술적 진화 |
|:---|:---|:---|:---|
| v1 | 8비트 정수 연산 특화 | 추론 전용 (Inference) | PCIe 기반 가속 카드 형태 |
| v3 | 액체 냉각 도입, HBM 탑재 | 대규모 모델 학습 | 성능 8배 향상, Pod 확장 |
| v4 | OCS(Optical Circuit Switch) | 거대 언어 모델 (LLM) | 광학 스위치 기반 유연한 토폴로지 |
| v5p | 생성형 AI 최적화 | 멀티모달 학습, 대규모 서빙 | v4 대비 성능 2.8배, 대역폭 3배 |

> 요약: 추론 전용에서 시작하여 현재는 거대 모델 학습을 위한 광학 네트워크 기반 클러스터로 진화하였다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| HW 종속성 | 구글 인프라에서만 사용 가능 | 클라우드 기반 하이브리드 전략 | 클라우드 이용료(TCO) 분석 |
| 소프트웨어 제약 | XLA 컴파일러 최적화 필요 | JAX, PyTorch/XLA 프레임워크 활용 | 컴파일 시간 및 실행 효율 |
| 정밀도 손실 | BF16/INT8 위주 연산 | Mixed Precision 기법 적용 | 모델 정확도(Accuracy) 유지율 |

> 요약: 하드웨어 종속성 리스크를 줄이기 위해 오픈 프레임워크와의 정합성을 높이는 전략이 필요하다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 연산 효율 | GPU 대비 2배 이상의 TOPS/W | 전력계 측정 및 성능 로그 비교 |
| 학습 속도 | 137B 모델 기준 학습 기간 단축 | 실 측정 모델 학습 시간 (Time-to-Train) |
| Pod 가동률 | 90% 이상의 클러스터 효율 | ICI 대역폭 점유율 모니터링 |

> 요약: 도입 효과는 운영 비용 절감액과 대규모 클러스터 가동 효율로 검증한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. **거대 모델 학습**: TPU v4/v5p Pod(최대 수천 개 노드)를 활용하여 PaLM 2, Gemini 등 거대 언어 모델의 분산 학습 수행
2. **실시간 검색 서빙**: 구글 검색 랭킹 알고리즘에 TPU를 적용하여 초당 수십만 건의 질의를 저지연·저전력으로 처리
3. **MaaS (Model as a Service)**: 구글 클라우드의 Vertex AI와 연동하여 외부 기업에게 고성능 학습 인프라 대여 서비스 제공

**결론 (2줄):**
- 기술사 판단: TPU는 ASIC 기반 DSA(Domain Specific Architecture)의 정수를 보여주며, 하드웨어 성능을 넘어 소프트웨어(XLA) 최적화 능력이 성패를 좌우한다
- 향후 방향: 광학 스위칭(OCS) 기술의 고도화와 칩렛(Chiplet) 구조 도입을 통해 성능과 경제성을 동시에 확보하는 방향으로 발전할 것이다
