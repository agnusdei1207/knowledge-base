# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: 글로벌 IT 공룡 '구글(Google)'이 오직 인공지능 신경망, 특히 텐서플로우(TensorFlow) 연산을 세상에서 가장 효율적으로 처리하기 위해 밑바닥부터 독자 설계한 **인공지능 특화 주문형 반도체(ASIC)**.
- **필요성**: 구글 검색, 구글 번역, 구글 포토 등 구글의 모든 서비스에 AI를 붙이려면 어마어마한 연산량이 필요함. 엔비디아 GPU를 다 사서 쓰려니 칩 가격도 미치고, 범용 칩이라 전기세 감당이 안 됨. "어차피 우리 AI 연산은 100% 행렬 곱셈뿐인데, 다른 잡기능 싹 다 빼버리고 오직 행렬 곱만 기가 막히게 하면서 전기 덜 먹는 가성비 칩을 직접 만들자!" 해서 탄생함.
- **핵심 직관**: 10만 명 밥 짓기. GPU가 프라이팬 1만 개로 요리사 1만 명이 동시에 각자 볶음밥을 만드는 구조라면, TPU는 공장에 '초대형 컨베이어 벨트 파이프라인(시스톨릭 어레이)'을 깔아놓고 쌀을 한쪽으로 붓기만 하면 척척척 계산되어 다른 쪽에서 볶음밥이 폭포수처럼 쏟아져 나오는 전용 공장 구조임.

## 깊이 이해
- **배경**: 딥러닝 연산 시, GPU는 매번 메모리(RAM)에 접근해서 숫자 하나 가져오고 계산하고 다시 메모리에 쓰는 짓을 수천 번 반복함. 여기서 엄청난 시간과 전력이 낭비(메모리 병목)됨. 구글은 이를 해결하기 위해 심장 박동처럼 피(데이터)를 한 방향으로 쫙 밀어내는 획기적인 '시스톨릭 어레이(Systolic Array)' 아키텍처를 도입함.
- **작동 원리 (Systolic Array)**:
  1. 가로세로 128 x 128 크기의 연산기(ALU) 격자를 만듦.
  2. 메모리에서 데이터를 딱 한 번만 읽어서 왼쪽 첫 줄 연산기에 밀어 넣음.
  3. 연산 결과가 나오면, 이걸 메모리에 안 적고 바로 오른쪽 연산기한테 넘겨버림. 그 오른쪽 애는 다시 그 오른쪽으로 토스함. (마치 소방수들이 줄지어 양동이 전달하듯).
  4. 데이터가 메모리를 들락날락하지 않고 칩 내부에서 파도타기를 하며 한 번에 거대한 행렬 곱이 완성됨. 전력 낭비 제로.
- **구체 예시**: 바둑 세계 챔피언 이세돌을 이긴 '알파고(AlphaGo)'의 브레인. 수천 대의 일반 컴퓨터 몫을 소수의 TPU 랙(Rack)이 대체하여 전기세와 연산 속도 두 마리 토끼를 잡음. 지금 구글의 챗봇 '제미나이(Gemini)'도 이 TPU 무리(TPU Pod)가 학습시켰음.
- **흔한 오해/주의점**: "TPU가 GPU보다 연산 능력이 압도적으로 뛰어난가?" $\rightarrow$ 단일 칩 성능(Peak TFLOPS)으로 치면 최신 엔비디아 GPU(H100 등)가 더 빠르기도 함. TPU의 무서움은 '가격 대비, 전력 대비 효율성(TCO)'과, 수천 개를 광케이블로 묶었을 때 효율이 떨어지지 않는 '클러스터 확장성(TPU Pod)'에 있음.

## 연결 개념
- **ASIC (Application Specific IC)**: 특정 용도(AI 행렬 연산)만을 위해 회로를 완전히 고정시켜 만든 반도체. TPU가 ASIC의 대표 주자임.
- **TensorFlow & JAX**: 구글이 만든 AI 소프트웨어 프레임워크. 당연히 구글 칩인 TPU와 영혼의 단짝처럼 100% 찰떡궁합을 자랑함.
- **TPU Pod (TPU 포드)**: TPU 칩 수십~수천 개를 구글만의 초고속 광 스위치로 거대하게 묶어 놓은 슈퍼컴퓨터 클러스터.

# 📝 【답안용】 시험 답안 템플릿
## 핵심 인사이트 (3줄 요약)
- **본질**: 시스톨릭 어레이(Systolic Array) 아키텍처를 기반으로 딥러닝의 다차원 행렬(Tensor) 덧셈과 곱셈을 극강의 에너지 효율로 처리하는 구글 설계의 AI 도메인 특화 반도체(DSA / ASIC).
- **가치**: 기존 폰 노이만 구조의 한계인 잦은 메모리 접근 및 레지스터 병목(Memory Wall)을 제거하여, 전력 소모(TOPS/W)를 극한으로 낮추고 글로벌 스케일 AI 서비스(검색, 번역 등)의 운영 TCO(총소유비용)를 혁신적으로 절감함.
- **판단 포인트**: 범용성과 유연성을 무기로 하는 GPU(Nvidia) 아키텍처와의 결정적 차이는 '데이터 파이프라이닝(Data Flow)'을 통한 캐시/레지스터 오버헤드 소거 여부이며, 대규모 클러스터링을 위한 자체 인터커넥트(ICI) 기술 확보가 핵심 경쟁력임.

## Ⅰ. 개요 및 필요성
- **정의**: 고정된 하드웨어 연산 유닛(MXU, Matrix Multiply Unit)을 통해 신경망 알고리즘 구동에 최적화된 명령어를 수행하는 딥러닝 전용 하드웨어 가속기(Accelerator).
- **배경**: AI 연산 규모가 기하급수적으로 폭발함에 따라, 수만 대의 데이터센터 내 GPU/CPU로 인한 발열, 공간 부족, 데이터센터 전력 고갈(Power Crunch) 위기 대두.
- **필요성**: 불필요한 범용 연산 회로(제어 분기, 그래픽 파이프라인 등) 삭감을 통한 트랜지스터 집적도 최적화, 대규모 언어 모델(LLM) 학습 시의 통신 병목 해소 및 경제적 확장성(Scalability) 도모.

## Ⅱ. CPU/GPU vs TPU 아키텍처 차이의 본질
메모리를 대하는 철학의 차이.
| 아키텍처/특징 | CPU (범용 프로세서) | GPU (그래픽 처리 장치) | TPU (AI 전용 프로세서) |
|:---:|:---|:---|:---|
| **설계 철학 및 구조** | **SISD/SIMD 기반 범용 코어**. 복잡한 조건문 처리에 최적. | **SIMT 기반 멀티 코어**. 고대역폭 캐시 메모리에 끊임없이 접근하며 병렬 처리. | **CISC 명령어 기반의 ASIC**. 캐시를 없애고 연산 유닛 간 직결망(시스톨릭) 구축. |
| **메모리 의존도** | 연산마다 메인 메모리 접근 (Von Neumann 구조). | 연산마다 레지스터/캐시에 접근 $\rightarrow$ 전력 낭비. | **메모리 접근 최소화**. 데이터를 흘려보내며 재사용 (Data Reuse 극대화). |
| **연산 결정론** | OS 인터럽트에 따라 지연 가변적. | 스레드 경합 시 지연 가변적(Jitter 발생). | **결정론적(Deterministic)**. 정확히 예측 가능한 연산 주기 보장. |

## Ⅲ. TPU 핵심 기술 아키텍처: Systolic Array (시스톨릭 어레이)
심장 박동(Systolic)처럼 데이터를 뿜어내는 데이터 흐름 엔진.
1. **MXU (Matrix Multiply Unit) 구성**: 128 x 128 크기의 고정소수점(INT8) 또는 부동소수점(BF16) 연산 요소(PE: Processing Element)가 2차원 바둑판 모양으로 배열됨.
2. **Data Loading (초기 입력)**: SRAM 버퍼에서 행렬 데이터를 읽어, 어레이의 첫 번째 행/열의 PE에만 값을 밀어 넣음. (메모리 I/O는 이 한 번으로 끝).
3. **Data Pipelining (흐름 연산)**: 각 PE가 자신의 자리에서 곱셈/덧셈을 한 뒤, 중간 결과값을 자신의 오른쪽과 아래쪽에 있는 다음 PE로 그대로 넘김(Pass).
4. **Result (출력)**: 수만 번의 클럭(심장 박동)이 지날 동안 데이터 파도가 어레이를 훑고 지나가며 거대한 행렬 곱이 완료되고, 반대편 끝에서 최종 결과가 출력됨. (레지스터 저장 단계 소거로 전력 1/10 수준 절감).

## Ⅳ. 대규모 확장을 위한 클러스터 패브릭: TPU Pod 및 OCS
칩 하나의 한계를 넘어서는 광학 네트워크 설계.
- **TPU Pod**: 수천 개의 TPU 칩을 직접 연결하여 구성한 슈퍼컴퓨터. 클라우드 사용자가 "나는 TPU 2048개 쓸게" 하면 가상의 슈퍼컴퓨터를 뚝딱 잘라 줌.
- **ICI (Inter-Core Interconnect)**: 이더넷이나 PCIe 같은 범용 버스망을 타지 않고, TPU 칩에 내장된 전용 라우터를 통해 칩끼리 다이렉트로 고속 데이터를 쏘아대는 3D Torus 형태의 전용 토폴로지 통신망.
- **OCS (Optical Circuit Switch, TPU v4 이후)**: 구리선 대신 거울로 빛의 방향을 미세 조정하여(MEMS 기반), TPU 랙(Rack) 간 통신 경로를 소프트웨어적으로 동적 재구성하는 광학 스위치. 하드웨어 케이블 교체 없이 트래픽 병목 우회.

## Ⅴ. 실무 적용 및 결론
- **판단 지표**: 모델 포팅 난이도(XLA 컴파일러 호환성), 배치 크기(Batch Size)에 따른 처리량(Throughput), 달러당 TFLOPS 가성비, 클러스터 스케일링 효율성(Scaling Efficiency).
- **실무 설계**: A사의 B2C 맞춤형 개인화 추천 모델(DLRM 알고리즘) 서빙 아키텍처 구축. 초기 GPU 기반 추론 서비스 운영 시, 거대한 임베딩 테이블 읽기 병목으로 비용 대비 응답 지연 발생. 조치 방안: GCP(Google Cloud)의 Cloud TPU v4 인프라 전환. 1) TensorFlow 기반 모델을 JAX로 마이그레이션하여 XLA(Accelerated Linear Algebra) 컴파일러 최적화 도모. 2) TPU의 넉넉한 HBM(고대역폭 메모리) 공간에 임베딩 벡터를 미리 캐싱. 3) Systolic Array의 고속 곱셈 파이프라인 활용. 결과적으로 기존 A100 GPU 대비 추론 지연 시간을 40% 단축하고 월 클라우드 청구 비용을 50% 절감하는 효과 달성.
- **결론**: TPU는 인공지능이 "범용 컴퓨터 시대의 더부살이"를 끝내고, 스스로를 위한 "맞춤형 하드웨어 시대"를 열었음을 알리는 상징적 신호탄이다. ASIC으로서 하드웨어 설계가 고정되어 새로운 AI 알고리즘 대응에 약하다는 태생적 한계가 있으나, 구글은 컴파일러(SW) 역량 극대화와 광학 네트워크 토폴로지(OCS) 혁신을 통해 이 한계를 돌파하고 있다. 특정 AI 서비스가 실험 단계를 벗어나 수억 명에게 배포되는 스케일업(Scale-up) 단계에 진입할 때, 엔지니어가 쥐어야 할 최종 최적화 카드는 결국 TPU와 같은 커스텀 실리콘이 될 것이다.

### 🔀 문제 유형별 목차 전환
- **Ⅱ·Ⅲ 강조 (개념/원리형)**: TPU가 채택한 새로운 부동소수점 표준 데이터 포맷인 **BFloat16 (Brain Floating Point)**의 구조 원리 부각. 표준 FP16보다 지수(Exponent) 비트는 늘리고 가수(Fraction) 비트를 줄여 정밀도는 약간 손해 보되, 표현 가능한 숫자 범위(Dynamic Range)를 FP32와 똑같이 맞춰 딥러닝 오버플로우/언더플로우 에러를 방지한 기법 설명.
- **Ⅴ·Ⅵ 강조 (실무/설계형)**: 멀티 벤더 클라우드 환경에서의 Vendor Lock-in 극복 방안 설계. 구글 TPU 생태계에 완전히 종속되지 않기 위해, 모델 작성 단계에서 PyTorch 생태계를 유지하면서도 백엔드 컴파일러만 PyTorch/XLA로 분리 연동하여 GPU 인스턴스와 TPU 인스턴스를 동적 스위칭 배포할 수 있는 클라우드 네이티브 아키텍처 구축 전략.
