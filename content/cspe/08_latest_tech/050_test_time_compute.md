## 미리 알고가기

- Test-Time Compute는 모델 학습 후 실제 추론 시점에 추가 계산을 투입하는 전략임
- Hidden reasoning은 사용자에게 보이지 않는 내부 추론 과정을 의미함
- Inference budget은 한 요청에 허용할 시간, 토큰, 연산 자원의 상한임

## Ⅰ. 개요

- **정의/개념**: Test-Time Compute는 추론 시점에 더 많은 탐색과 검증과 자기 교정을 수행해 모델 크기 증가 없이도 고난도 reasoning 성능을 높이는 계산 자원 투입 전략임
- **배경/필요성**: 단일 패스 응답만으로는 수학, 코딩, 과학 문제에서 정답률 한계가 뚜렷하므로, 필요할 때만 추가 계산을 투입해 정확도를 끌어올리는 동적 추론 방식이 필요함

## Ⅱ. 특징

- 학습 완료 후에도 추론 자원 배분만으로 성능을 조절할 수 있어 유연성이 높음
- 복합 문제에서 다중 경로 탐색과 검증 루프를 통해 정답률을 향상시킴
- 단순 질의에는 과투자일 수 있으므로 난이도별 자원 배분이 중요함
- reasoning model, self-consistency, verifier, search 기반 프레임워크의 공통 기반 개념임

## Ⅲ. 종류 및 비교

| 판단 기준 | 단일 패스 추론 | CoT, Self-Consistency | Test-Time Compute 강화 |
|:---|:---|:---|:---|
| 추가 계산량 | 거의 없음 | 중간 | 높음 |
| 정확도 향상 | 제한적임 | 중간 | 고난도 문제에서 큼 |
| 지연, 비용 | 낮음 | 중간 | 높음 |
| 적합 업무 | 일반 대화 | 중간 난도 추론 | 고난도 코딩, 수학, 계획 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Difficulty Router | 질문 난이도를 판별해 얼마나 많은 추론 자원을 쓸지 결정함 |
| Search, Reasoning Engine | 다중 경로 탐색과 hidden reasoning을 수행해 더 나은 답을 찾음 |
| Verifier | 중간 결과와 최종 답을 점검해 잘못된 경로를 걸러냄 |
| Budget Controller | 시간, 토큰, 비용 상한을 넘지 않도록 추론 깊이와 반복 수를 제어함 |

```text
+------------------+     +------------------+     +------------------+     +------------------+
| Difficulty Route | --> | Search / Reason  | --> | Verifier         | --> | Budget Control   |
+------------------+     +------------------+     +------------------+     +------------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 난이도 판정  | --> | 계산 예산 배정 | --> | 탐색/검증 수행 | --> | 결과 반환    |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **난이도 판정**: 문제 복잡도를 평가해 추가 추론이 필요한지 판단함
2. **계산 예산 배정**: 허용된 시간과 토큰과 비용 안에서 추론 깊이와 반복 횟수를 정함
3. **탐색 및 검증 수행**: 다중 경로 생성과 self-consistency와 verifier를 통해 정답 후보를 정제함
4. **결과 반환**: 예산 안에서 가장 신뢰도 높은 답을 선택해 사용자에게 전달함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 추론 자원을 무차별적으로 늘리면 단순 질의에도 비용과 지연이 커져 서비스 운영성이 급격히 악화됨
   - 해결방안: 난이도 라우팅과 budget cap을 적용하고 task별 latency와 cost per request로 효율을 검증함
2. 문제: 많은 계산을 써도 탐색 품질이 낮으면 비용만 증가하고 정답률 향상은 제한적일 수 있음
   - 해결방안: verifier와 search policy를 함께 튜닝하고 compute 증가 대비 accuracy gain으로 한계효용을 검증함
3. 문제: 숨겨진 추론 비용이 외부에서 잘 보이지 않으면 API 비용 예측이 어렵고 예산 통제가 실패할 수 있음
   - 해결방안: reasoning token 계측과 요청 유형별 정책을 분리하고 billed token 대비 business value로 적정성을 검증함

## Ⅶ. 적용 사례

- 코딩 문제 해결: 여러 코드 경로를 탐색하고 테스트로 검증함, 확인 지표는 pass@k와 latency임
- 수학 reasoning 서비스: 복수 풀이를 비교해 정답을 선택함, 확인 지표는 final answer accuracy와 token cost임
- 에이전트 계획: 실패 시 대안을 재탐색함, 확인 지표는 task completion rate와 retry overhead임

## Ⅷ. 결론

Test-Time Compute의 핵심은 더 오래 생각하게 하는 데 있지 않고 문제 난도에 맞춰 필요한 계산만 선택적으로 투입해 정확도 향상과 비용 통제를 함께 달성하는 데 있음.
