# 📖 【암기용】 개념 완전 이해

> 목적: Test-Time Compute를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: 모델 추론(inference) 시점에 추가 연산 자원을 투입하여 답변 품질을 높이는 전략의 총칭
- **왜 필요한가**: 학습(training) 시 파라미터를 키우는 것은 비용·시간 한계가 있으므로, 추론 시 연산을 늘려 같은 모델로 더 나은 답을 얻는 방향
- **핵심 직관**: 추론 시간을 늘리면 후보 탐색과 검증 횟수가 증가하지만, 비용 대비 개선 폭은 문제 난이도에 따라 달라짐.

## 깊이 이해
- **배경·문제의식**: Scaling Law는 학습 연산(train-time compute)에 집중 -> GPT-4급 모델 학습에 $100M+ 소요. 반면 추론 시 연산(test-time compute)을 늘리면 소형 모델로도 대형 모델 수준 달성 가능(OpenAI o1 논문, 2024)
- **작동 원리**: ① 내부 사고 연쇄(Internal CoT): 모델이 답변 전 hidden thinking token을 다수 생성 -> ② 다중 샘플링(Self-Consistency): 같은 문제를 n번 풀어 다수결 -> ③ 반복 정제(Reflection): 자기 검토·수정 루프 -> ④ 탐색(ToT/MCTS): 후보를 트리·그래프로 탐색 -> 이 중 하나 이상을 조합하여 추론 시 연산 증가
- **비유**: 시험에서 바로 답을 쓰지 않고, 연습장에서 여러 풀이를 시도·검산한 뒤 최종 답을 옮기는 것
- **구체 예시**: OpenAI o1은 AIME 2024 수학 정답률 83%(GPT-4o 13.4%), 추론 토큰 10~100배 사용. DeepSeek-R1은 14B 모델로 GPT-4o 수준 달성(추론 토큰 32K)
- **흔한 오해·주의점**: TTC는 모든 문제에 효과적이지 않음 — 단순 사실 질문(수도·날짜)에는 추가 사고가 오히려 과잉 추론(overthinking) 유발. 비용은 추론 토큰에 비례하여 10~100배 증가

## 연결 개념
- Scaling Law: train-time compute 확대 전략, TTC는 이를 inference로 확장
- Chain-of-Thought(CoT): TTC의 기본 메커니즘(사고 연쇄)
- Self-Consistency / Reflection / ToT: TTC를 구현하는 구체 기법들


# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 추론 시점에 추가 연산을 투입하여 같은 모델로 더 높은 답변 품질을 달성하는 전략
> 2. **가치**: o1 AIME 정답률 13.4%->83%, 14B 모델이 GPT-4o 수준 달성(DeepSeek-R1)
> 3. **판단 포인트**: 복잡 추론(수학·코드·계획)에 효과적, 단순 QA는 과잉 추론·비용 증가 위험


## Ⅰ. 개요 및 필요성

- 개요: 추론 시 추가 연산 투입 전략
- 배경: Train-time scaling은 학습 비용이 $100M+ 수준까지 증가해 모델 재학습만으로 개선하기 어려움.
- 필요성: best-of-N, verifier, self-consistency, search budget으로 정확도 개선 폭과 토큰 비용을 함께 산정해야 함.


## Ⅱ. 구조 및 구성요소

```text
Test-Time Compute
Internal CoT / Multi-Sampling / Iterative Refine / Search-MCTS
Candidate Answers -> Verification/Selection -> 최적 답 선택
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Internal CoT | 답변 전 hidden thinking token 생성 | o1: 수천~수만 토큰, 사용자 비노출 |
| Multi-Sampling | 동일 문제 n회 독립 생성, 다수결·보상 모델 선택 | Best-of-N, Self-Consistency |
| Iterative Refine | 자기 검토·피드백·재생성 반복 | Reflection, Critic 에이전트 |
| Search(MCTS) | 후보를 트리·그래프로 탐색·가지치기 | ToT, GoT, AlphaProof 방식 |

> 요약: 내부 사고·다중 샘플·반복 정제·탐색 4가지 메커니즘을 조합하여 추론 시 연산 확대


## Ⅲ. 동작원리 및 흐름도

```text
문제 입력 -> 난이도 판별 -> [연산 할당 결정]
-> 단순: 즉답(CoT 최소)
-> 복잡: Internal CoT + Multi-Sampling + Refine
-> 검증 -> 최적 답 출력
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 문제 난이도 판별(라우터/분류기) | 단순 QA vs 복잡 추론 분류 |
| 2 | 연산 예산 할당(토큰 수·샘플 수 결정) | 난이도별 토큰 예산 1K~100K |
| 3 | 할당된 연산으로 사고·샘플·정제·탐색 수행 | 보상 모델 점수 ≥ 임계값 |
| 4 | 최적 답 선택 및 최종 검증 후 출력 | 일관성·정합성 최종 확인 |

> 요약: 난이도 판별->연산 예산 할당->사고·탐색 수행->최적 답 선택의 적응형 추론


## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| Train-time Scaling 대비 | 추론 시 연산 증가 | 14B+TTC ≈ GPT-4o |
| 비용 구조 | 추론 토큰 10~100배 증가 | o1 API 비용 GPT-4o 대비 3~6배 |
| 한계 | 단순 QA 과잉 추론(overthinking) | 라우터로 난이도별 차등 할당 필요 |

> 요약: 소형 모델로 대형 모델급 성능 달성 가능, 단 추론 비용 증가와 과잉 추론 주의


## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 코드 생성 서비스에 난이도 라우터 도입: 단순 함수->CoT(1K 토큰), 알고리즘 문제->TTC(32K 토큰), 비용 최적화 60%
2. 수학 튜터 챗봇에 o1 계열 모델 적용, MATH 벤치마크 정답률 52%->94%, 풀이 과정 자동 생성
3. 보안 취약점 분석에 Multi-Sampling+Reflection 파이프라인 구축, 탐지율(recall) 71%->89%

**결론 (2줄):**
- 기술사 판단: 복잡 추론(수학·코드·계획)이면 TTC 전략 도입, 단순 QA는 기본 CoT로 비용 절감
- 향후 방향: 학습-추론 연산 최적 비율(Compute-Optimal Inference) 연구로 비용 효율 극대화
