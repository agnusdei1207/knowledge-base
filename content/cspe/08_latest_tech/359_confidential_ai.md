## 미리 알고가기

- Confidential AI는 저장 중과 전송 중 보호를 넘어 AI 처리 중 데이터와 모델을 격리하는 구조임
- 핵심은 TEE 자체보다 원격 검증과 키 제공 정책과 출력 통제를 함께 묶는 운영 체계임
- 기밀 실행은 강한 보호 수단이지만 프롬프트 인젝션이나 잘못된 출력까지 자동으로 해결하지는 않음

## Ⅰ. 개요

- **정의/개념**: Confidential AI는 TEE나 confidential VM 같은 기밀 실행 환경에서 AI 학습과 추론을 수행하고 원격 검증이 통과한 환경에만 복호화 키를 제공해 데이터와 모델과 프롬프트를 사용 중에도 보호하는 아키텍처임
- **배경/필요성**: 클라우드와 공동 인프라에서 AI를 운영할 때 저장 암호화와 전송 암호화만으로는 메모리와 GPU 처리 구간의 노출을 막기 어려워 민감 데이터와 독점 모델을 안전하게 다룰 실행 중 보호가 필요함

## Ⅱ. 특징

- 데이터와 모델을 실행 중에도 격리해 인프라 운영자 신뢰 범위를 줄일 수 있음
- 원격 검증과 키 제공 정책을 결합해 승인된 런타임에서만 추론이나 학습을 허용할 수 있음
- 기밀 실행은 입력 데이터뿐 아니라 모델 가중치와 프롬프트와 추론 결과 보호에도 활용 가능함
- TEE 취약점과 성능 오버헤드와 출력 유출 위험이 남으므로 애플리케이션 수준 통제를 함께 둬야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 일반 클라우드 AI 실행 | Confidential AI |
|:---|:---|:---|
| 실행 중 보호 | 제한적 | TEE 기반 격리 |
| 신뢰 대상 | 클라우드 운영자 포함 | 승인된 TCB로 축소 |
| 키 제공 방식 | 배포 정책 중심 | 원격 검증 통과 후 제공 |
| 대표 한계 | 메모리 구간 노출 우려 | 성능 비용과 TEE 한계 검토 필요 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| TEE or Confidential VM/GPU | AI 런타임을 격리해 실행 중 데이터와 모델 접근을 제한하는 보호 계층으로 지원 범위와 성능 특성이 중요함 |
| Remote Attestation | 실행 이미지와 환경 측정값을 검증해 신뢰 가능한 런타임인지 확인하는 검증 계층임 |
| Key Broker | 검증 통과 시에만 모델과 데이터 복호화 키를 제공하는 제어 계층으로 정책 설정 오류가 보안 경계를 무너뜨릴 수 있음 |
| AI Runtime | 학습과 추론을 수행하는 실행 계층으로 사용하는 프레임워크와 드라이버가 TCB에 포함될 수 있음 |
| Output Policy and Audit | 결과 필터링과 감사 로그를 담당하는 운영 계층으로 기밀 실행 이후의 유출 위험을 줄임 |

```text
+-------------------+    +-------------------+    +----------------+    +----------------+
| Attestation Check | -> | Key Broker        | -> | Confidential   | -> | Output / Audit |
+-------------------+    +-------------------+    +----------------+    +----------------+
                                                | VM / TEE Runtime |
                                                +------------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 환경 측정      | -> | 원격 검증      | -> | 키 제공        | -> | 기밀 추론/학습  | -> | 출력 통제/기록 |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **환경 측정**: 런타임 이미지와 TEE 측정값을 생성함
2. **원격 검증**: 검증 서비스가 승인된 환경인지 확인함
3. **키 제공**: 검증이 통과하면 key broker가 복호화 키를 전달함
4. **기밀 추론과 학습**: 보호된 런타임 안에서 데이터와 모델을 로딩해 처리함
5. **출력 통제와 기록**: 결과를 정책에 따라 내보내고 감사 로그를 남김

## Ⅵ. 실무 적용 및 유의점

1. 의료나 금융처럼 민감 원본 데이터를 외부 클라우드에서 추론해야 할 때 Confidential AI가 유효하지만 원격 검증 정책과 출력 통제가 약하면 보호 경계가 쉽게 무너지므로 attestation allowlist와 출력 필터를 함께 운영하고 attestation 성공률과 p95 추론 지연과 민감정보 유출 탐지 건수로 확인함
2. 모델 IP 보호가 중요한 공동 추론 환경은 기밀 실행이 적합하지만 TEE 지원 범위와 드라이버 업데이트가 불안정하면 운영 중단 위험이 커지므로 지원 스택을 제한하고 TCB 패치 절차를 표준화한 뒤 가용률과 패치 적용 시간과 추론 실패율로 확인함

## Ⅶ. 결론

- Confidential AI는 민감 데이터와 독점 모델을 외부 인프라에서 처리해야 할 때 효과가 크며 TEE 자체보다 원격 검증과 키 제공 정책과 출력 통제를 함께 설계해야 실전 보안이 성립함
