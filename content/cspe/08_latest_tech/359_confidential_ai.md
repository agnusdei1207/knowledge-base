## 미리 알고가기

- TEE (Trusted Execution Environment)는 실행 중 데이터를 격리하는 신뢰실행환경임
- 원격 검증은 지금 떠 있는 실행 환경이 승인된 이미지인지 바깥에서 확인하는 절차임
- 기밀 실행은 강한 보호 수단이지만 프롬프트 인젝션이나 잘못된 답변까지 자동으로 막아 주지는 않음

## Ⅰ. 개요

- **정의/개념**: 기밀 AI는 TEE나 기밀 VM에서 학습·추론을 수행해 데이터·모델·프롬프트를 사용 중에도 보호하는 구조임
- **배경/필요성**: 저장·전송 암호화만으로는 메모리와 처리 구간 노출을 막기 어려워 실행 중 보호와 원격 검증이 필요함

## Ⅱ. 특징

- 데이터와 모델을 실행 중에도 격리해 인프라 운영자를 전적으로 신뢰하지 않아도 됨
- 원격 검증과 키 제공 정책을 결합해 승인된 환경에서만 추론이나 학습을 허용할 수 있음
- 입력 데이터뿐 아니라 모델 가중치와 프롬프트와 추론 결과 보호에도 활용할 수 있음
- 기밀 실행만으로는 출력 유출과 애플리케이션 취약점까지 막지 못하므로 별도 통제가 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 일반 클라우드 AI 실행 | 기밀 AI |
|:---|:---|:---|
| 실행 중 보호 | 제한적임 | TEE 기반으로 격리함 |
| 신뢰 범위 | 클라우드 운영자까지 넓게 포함됨 | 승인된 실행 환경으로 줄일 수 있음 |
| 키 제공 방식 | 배포 정책에 주로 의존함 | 원격 검증 통과 후에만 제공함 |
| 주의점 | 메모리 구간 노출 우려가 있음 | 성능 비용과 하드웨어 한계를 함께 봐야 함 |

> 요약: 기밀 AI는 실행 중 보호와 키 제공 통제를 추가해 일반 클라우드 AI보다 신뢰 범위를 줄임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 기밀 실행 환경 | AI 런타임을 격리해 실행 중 데이터와 모델 접근을 제한하는 보호 계층으로 지원 범위와 성능 특성이 중요함 |
| 원격 검증 | 실행 이미지와 환경 측정값을 검증해 신뢰 가능한 런타임인지 확인하는 검증 계층임 |
| 키 중개 서버 | 검증을 통과한 환경에만 모델과 데이터 복호화 키를 제공하는 제어 계층으로 정책 오류가 보안 경계를 무너뜨릴 수 있음 |
| AI 런타임 | 학습과 추론을 수행하는 실행 계층으로 사용하는 프레임워크와 드라이버 안정성이 중요함 |
| 출력 통제와 감사 | 결과 필터링과 감사 로그를 담당하는 운영 계층으로 실행 이후의 유출 위험을 줄임 |

```text
+----------------+    +----------------+    +----------------+    +----------------+
| 원격 검증        | -> | 키 중개 서버     | -> | 기밀 실행 환경   | -> | 출력 통제/감사 |
+----------------+    +----------------+    +----------------+    +----------------+
```

> 요약: 기밀 AI는 원격 검증과 키 중개를 거쳐 승인된 런타임 안에서만 모델과 데이터를 풀어 쓰는 구조임.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 환경 측정      | -> | 원격 검증      | -> | 키 제공        | -> | 기밀 추론/학습  | -> | 출력 통제/기록 |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **환경 측정**: 런타임 이미지와 TEE 측정값을 생성함
2. **원격 검증**: 검증 서비스가 승인된 환경인지 확인함
3. **키 제공**: 검증이 통과하면 키 중개 서버가 복호화 키를 전달함
4. **기밀 추론과 학습**: 보호된 런타임 안에서 데이터와 모델을 불러와 처리함
5. **출력 통제와 기록**: 결과를 정책에 따라 내보내고 감사 로그를 남김

> 요약: 기밀 AI는 환경 측정과 원격 검증을 통과한 뒤에만 키를 공급하고 보호된 런타임에서 처리함.

## Ⅵ. 실무 적용 및 유의점

1. 의료·금융 추론은 허용 측정값 목록과 출력 필터를 운영하고 검증 성공률·추론 지연·유출 탐지 건수로 확인함
2. 공동 추론은 지원 스택을 제한하고 패치 절차를 표준화한 뒤 가용률·패치 시간·추론 실패율로 확인함

## Ⅶ. 결론

- 기밀 AI는 외부 인프라에서 민감 데이터와 독점 모델을 처리할 때 유효하며 원격 검증·키 정책·출력 통제가 핵심임

## 작성 근거(검토용)

- 개요는 기밀 AI를 TEE 기반 실행 중 보호 구조로 정의해 단순 암호화나 접근통제와 구분되게 함
- Ⅲ은 일반 클라우드 실행과 비교해 신뢰 범위와 키 제공 방식 차이를 바로 읽히게 구성함
- Ⅳ는 기밀 실행 환경, 원격 검증, 키 중개, AI 런타임, 출력 통제로 나눠 보안 경계와 운영 경계를 함께 보이게 함
- Ⅴ는 측정, 검증, 키 제공, 처리, 출력 통제 순서를 통해 기밀 실행의 승인 흐름을 자연스럽게 설명함
- Ⅵ은 의료·금융과 공동 추론 사례를 통해 지연과 유출 탐지와 패치 시간을 실무 지표로 남김
