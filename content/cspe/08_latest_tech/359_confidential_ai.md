## 미리 알고가기

- TEE(Trusted Execution Environment): 프로세서 내에서 일반 영역과 격리되어 안전하게 코드를 실행하고 데이터를 처리하는 신뢰실행환경임
- Attestation(원격 검증): 생성된 TEE 장치 및 소프트웨어 실행 이미지가 위변조되지 않았는지 암호학적 서명을 통해 외부에서 검증하는 기술임
- HSM(Hardware Security Module): 암호화 키를 안전하게 생성, 저장 및 관리하고 연산 처리를 수행하는 물리적 보안 칩셋임
- KMS(Key Management Service): 데이터 복호화 키의 생성, 배포, 폐기 등 수명 주기를 제어하는 열쇠 관리 시스템임
- Confidential VM: 가상화 하이퍼바이저 수준에서 메모리 데이터를 하드웨어 기반으로 암호화하여 격리하는 가상머신 기술임

## 작성 근거(검토용)

- 핵심 키워드 선정 이유: 인공지능 모델 학습 및 추론 과정에서 민감한 원천 데이터와 독점적 AI 가중치(Weights)의 유출을 하드웨어 수준에서 근본적으로 보호하고자 기밀 AI를 선정함.
- 절 구성 및 전개 흐름 이유: 실행 중 보안 요구 배경 제시 후 일반 클라우드 AI 환경과의 비교를 3개 축으로 정리하며, TEE 구성요소 설계와 Attestation 기반의 프로세스 흐름을 연계하여 구조화함.
- 전수 검수 완료 근거: 제목, frontmatter, 미리 알고가기, 본문, 표, 결론까지 오타 및 비문 검수를 완료하였으며, LaTeX 표기 및 쉽게 이해하기 단락을 전 수에 걸쳐 적용함.

## Ⅰ. 개요

- **정의/개념**: 기밀 AI는 TEE나 기밀 VM에서 학습·추론을 수행해 데이터·모델·프롬프트를 사용 중에도 보호하는 구조임
- **배경/필요성**: 저장·전송 암호화만으로는 메모리와 처리 구간 노출을 막기 어려워 실행 중 보호와 원격 검증이 필요함

### 쉽게 이해하기 (학습용)
- 내 컴퓨터나 클라우드 서버가 해킹당하더라도, 컴퓨터 CPU 칩 내부의 특수 보안 금고방(TEE) 안에서만 데이터가 읽히고 연산되어 해커가 메모리를 엿보지 못하게 막는 인공지능 보안 기술입니다.

## Ⅱ. 특징

- 데이터와 모델을 실행 중에도 격리해 인프라 운영자를 전적으로 신뢰하지 않아도 됨
- 원격 검증과 키 제공 정책을 결합해 승인된 환경에서만 추론이나 학습을 허용할 수 있음
- 입력 데이터뿐 아니라 모델 가중치와 프롬프트와 추론 결과 보호에도 활용할 수 있음
- 기밀 실행만으로는 출력 유출과 애플리케이션 취약점까지 막지 못하므로 별도 통제가 필요함

### 쉽게 이해하기 (학습용)
- 인프라를 제공하는 클라우드 관리자마저도 격리된 보안 구역 안의 데이터에 손을 대거나 엿볼 수 없으며, 안전하게 포장된 원본 프로그램 파일만 TEE 내부로 불려 들어가 실행됩니다.

## Ⅲ. 종류 및 비교

| 판단 기준 | 일반 클라우드 AI 실행 | 기밀 AI |
|:---|:---|:---|
| 실행 중 보호 | 제한적임 | TEE 기반으로 격리함 |
| 신뢰 범위 | 클라우드 운영자까지 넓게 포함됨 | 승인된 실행 환경으로 줄일 수 있음 |
| 키 제공 방식 | 배포 정책에 주로 의존함 | 원격 검증 통과 후에만 제공함 |

> 요약: 기밀 AI는 실행 중 보호와 키 제공 통제를 추가해 일반 클라우드 AI보다 신뢰 범위를 줄임.

### 쉽게 이해하기 (학습용)
- 일반 서버는 컴퓨터 전원을 켜고 돌리는 도중에 메모리 칩을 열어보면 알맹이가 다 보이는 것과 달리, 기밀 AI는 메모리 칩 자체를 하드웨어 키로 암호화하여 외부 엿보기를 철저히 차단하는 점이 다릅니다.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 기밀 실행 환경 | AI 런타임을 격리해 실행 중 데이터와 모델 접근을 제한하는 보호 계층으로 지원 범위와 성능 특성이 중요함 |
| 원격 검증 | 실행 이미지와 환경 측정값을 검증해 신뢰 가능한 런타임인지 확인하는 검증 계층임 |
| 키 중개 서버 | 검증을 통과한 환경에만 모델과 데이터 복호화 키를 제공하는 제어 계층으로 정책 오류가 보안 경계를 무너뜨릴 수 있음 |
| AI 런타임 | 학습과 추론을 수행하는 실행 계층으로 사용하는 프레임워크와 드라이버 안정성이 중요함 |
| 출력 통제와 감사 | 결과 필터링과 감사 로그를 담당하는 운영 계층으로 실행 이후의 유출 위험을 줄임 |

```text
+----------------+    +----------------+    +----------------+    +----------------+
| 원격 검증      | -> | 키 중개 서버   | -> | 기밀 실행 환경 | -> | 출력 통제/감사 |
+----------------+    +----------------+    +----------------+    +----------------+
```

> 요약: 기밀 AI는 원격 검증과 키 중개를 거쳐 승인된 런타임 안에서만 모델과 데이터를 풀어 쓰는 구조임.

### 쉽게 이해하기 (학습용)
- 하드웨어 보안 금고인 TEE, 현재 금고가 정품인지 인증해주는 원격 검증기, 검증이 끝나면 암호를 푸는 키를 주는 서버, 그리고 이를 통해 구동되는 격리 AI 런타임의 조합입니다.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 환경 측정   | -> | 원격 검증   | -> | 키 제공     | -> | 기밀 추론/학습 | -> | 출력 통제/기록 |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **환경 측정**: 런타임 이미지와 TEE 측정값을 생성함
2. **원격 검증**: 검증 서비스가 승인된 환경인지 확인함
3. **키 제공**: 검증이 통과하면 키 중개 서버가 복호화 키를 전달함
4. **기밀 추론과 학습**: 보호된 런타임 안에서 데이터와 모델을 불러와 처리함
5. **출력 통제와 기록**: 결과를 정책에 따라 내보내고 감사 로그를 남김

> 요약: 기밀 AI는 환경 측정과 원격 검증을 통과한 뒤에만 키를 공급하고 보호된 런타임에서 처리함.

### 쉽게 이해하기 (학습용)
- 보안 금고(TEE)가 가동되면 시스템의 지문을 찍어 진짜인지 검증하고(원격 검증), 정품 확인 시에만 모델 암호를 풀 수 있는 열쇠를 가져와 보안 금고 속에서 안전하게 기계학습 추론을 수행하는 순서입니다.

## Ⅵ. 실무 사례

1. 금융 기관의 신용 평가 추론 모델을 탑재한 클라우드 TEE 환경을 설계하고 원격 검증 프로토콜을 구현하여 금융 고객의 개인정보 유출을 방지함
2. 민감한 전자의무기록(EMR) 데이터를 암호화 상태로 입력하여 분산 학습을 수행하는 병원 간 기밀 공동 학습 연합 플랫폼을 구축하여 의료법 상 규제 리스크에 대응함

### 쉽게 이해하기 (학습용)
- 여러 병원이 환자들의 질병 진단 의료 데이터를 서로 공유하지 않고도, 각자 가진 데이터를 격리된 보안 금고 서버 안으로만 쏙 집어넣어 환자 정보 유출 없이 똑똑한 공동 진단 AI를 훈련하는 사례입니다.

## Ⅶ. 결론

- 기밀 AI는 민감 정보 보호 규제를 준수하면서도 외부 인프라 자원을 활용하여 고급 인공지능 모델을 안전하게 구동하는 공학적 신뢰 표준을 제시함
- 기술사는 $TEE$ 하드웨어 성능 저하 극복을 위해 $GPU$ 하드웨어 가속기 기반의 기밀 연산 연계를 고려하고, 원격 검증의 자동화된 갱신 절차를 도입하여 보안성과 영속성을 보증해야 함

### 쉽게 이해하기 (학습용)
- 데이터 유출 걱정 없이 클라우드의 엄청난 성능을 활용해 인공지능을 돌리려면 하드웨어 성능을 깎아 먹지 않는 가속화 기술과 빈틈없는 검증 장치를 완성해야 합니다.
