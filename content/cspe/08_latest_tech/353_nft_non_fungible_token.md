## 미리 알고가기

- 대체 불가능(Non-Fungible): 각 단위가 독특하고 개별적인 가치를 지녀, $1$대$1$로 동일하게 상호 교환할 수 없는 성질임
- 메타데이터(Metadata): NFT가 가리키는 이미지 파일 주소, 창작자 정보, 속성값 등을 담고 있는 구조화된 데이터 명세서임
- IPFS(InterPlanetary File System): 중앙 서버 대신 P2P 네트워크 상에 원본 데이터를 영구적이고 안전하게 분산 저장하기 위해 사용하는 프로토콜임
- ERC-721: 이더리움 블록체인에서 디지털 고유 자산을 NFT 형태로 표현하고 양도할 수 있게 구현한 최초의 표준 토큰 규격임
- ERC-1155: 다수의 대체 가능(FT) 및 대체 불가능(NFT) 토큰 형식을 단일 스마트 계약 내에서 처리하도록 설계된 효율적인 표준 규격임

## 작성 근거(검토용)

- **핵심 키워드 선정 이유**: 복제가 용이한 디지털 자산에 유일무이한 소유권과 희소성을 부여하는 기술적 표준(ERC-721, ERC-1155)과 실물 권리 연계에 필수적인 메타데이터 저장 구조를 조명하고자 선정함
- **절 구성 및 전개 흐름 이유**: 개요와 특징을 통해 대체 불가능성과 체인 상의 거래 감사성을 고정하고, Ⅲ절에서 가치 교환 관점을 바탕으로 대체가능토큰 및 전통 장부와 비교함. Ⅳ절과 Ⅴ절은 토큰 ID와 오프체인 데이터 보관 계층 구조 및 발행부터 전송에 이르는 상태 변환 절차를 서술함. 실무 적용은 티켓 위변조 방지와 예술품 메타데이터 연결 유의점에 무게를 두고 결론에서 법적 실효성 확보와 확장 표준 설계 방안으로 종결함
- **전수 검수 완료 근거**: Frontmatter, 미리 알고가기 및 Ⅶ절 결론의 2문장 구성까지 전체 5회 정밀 완독하며 조사와 단어 매핑을 다듬음. 실무 사례 내 지표 표현을 실무적 기술 조치로 변경하였으며, 모든 절에 쉽게 이해하기를 3줄 이내로 배치하여 요구사항 준수 여부를 최종 점검함

## Ⅰ. 개요

- **정의/개념**: NFT는 스마트 계약 내의 고유 토큰 ID와 암호학적 서명을 바탕으로, 디지털 및 물리적 자산의 개별 소유권과 거래 이력을 입증하는 고유 토큰 형식임
- **배경/필요성**: 무단 복제가 손쉬운 디지털 콘텐츠와 티켓 시장 등에서 소유권의 위변조가 빈번하므로, 제3자 기관의 보증 없이도 자산의 진본성과 이력을 투명하게 증명할 수 있는 고유한 소유권 증빙 장부가 필요함

### 쉽게 이해하기 (학습용)
- 복사기로 손쉽게 복사할 수 있는 종이돈과 달리, 작가가 유일한 번호와 친필 서명을 직접 남겨 복사할 수 없게 만든 단 하나뿐인 한정판 판화 예술품과 같음

## Ⅱ. 특징

- **유일무이성 및 대체 불가능성**: 스마트 계약에서 발행되는 토큰마다 고유한 식별 정보를 가져 가치가 같더라도 상호 교환할 수 없음
- **투명한 소유권 및 거래 추적성**: 발행(Minting) 시점부터 현재 소유자에 이르기까지 전송 이력이 블록체인에 기록되어 거래 감사에 적합함
- **메타데이터 의존성 및 리스크**: 대용량 원본 파일은 오프체인에 저장되므로 메타데이터 주소 유실 시 데이터 접근 불가 현상이 발생할 수 있음

### 쉽게 이해하기 (학습용)
- 세상에 하나뿐인 고유 번호가 붙어 있어 다른 것과 바꿀 수 없고, 누가 소유했었는지 역사가 투명하게 밝혀지지만, 원본이 저장된 컴퓨터 폴더의 링크가 끊기지 않게 관리해야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 대체가능토큰 (FT) | 중앙 DB 자산기록 | NFT (Non-Fungible Token) |
|:---|:---|:---|:---|
| **고유 식별 방식** | 구별 불가능하며 동일 가치 간 $1:1$ 대체 교환됨 | 임의 지정한 필드 조합으로 구분하며 강제 제어가 어려움 | 고유 토큰 ID를 생성하여 개별 속성을 부여함 |
| **소유권 검증** | 지갑 주소별 잔액(Balance) 단위로 합산함 | 중앙 서비스 운영 주체의 신뢰성과 장부에 의존함 | 온체인 거래 트랜잭션과 소유자 주소 매핑을 확인함 |
| **데이터 저장소** | 온체인 장부에 토큰 수량만 직접 기록함 | 내부 DB 스토리지에 관리 정보와 이미지 일괄 보관 | 온체인 토큰 정보에 외부 오프체인 메타데이터를 매핑함 |

### 쉽게 이해하기 (학습용)
- 만 원짜리 지폐(대체 가능)는 무엇이든 바꾸어도 가치가 똑같고, 내 게임 아이템은 게임사 서버(중앙 DB)에서만 진짜지만, NFT는 블록체인 장부 전체에서 단 하나의 개별 가치를 인증받음

## Ⅳ. 구성요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| **스마트 계약 (Standard Contract)** | ERC-721 등 표준 규격에 따라 토큰의 발행, 이전, 소각 조건을 컴퓨터 코드로 자동 실행하는 로직 |
| **토큰 ID (Token ID)** | 발행 시 부여되어 소유 주소와 짝을 이루며 중복될 수 없는 일련의 식별 번호 |
| **메타데이터 (URI Link)** | 자산의 이름, 설명, 소유 권리 명세를 구조화하여 오프체인에 기재한 JSON 포맷 문서 |
| **분산 파일 스토리지 (IPFS)** | 대용량 원본 미디어와 메타데이터 파일 유실을 막기 위해 가용성을 상시 유지하는 P2P 네트워크 저장소 |

```text
[ 스마트 계약 (ERC-721/1155) ] ─── 상태 매핑 (Owner ↔ Token ID)
                                          │
                                   접근 참조 (Token URI)
                                          │
                                          v
[ 분산 파일 스토리지 (IPFS) ] ──────> [ 메타데이터 JSON ] ───> [ 원본 이미지/콘텐츠 ]
```

### 쉽게 이해하기 (학습용)
- 발행 규칙을 적은 규칙서(스마트 계약), 보증서의 고유 번호(토큰 ID), 그림 파일이 숨겨진 창고 주소(메타데이터), 그리고 보관을 담당하는 분산 스토리지 시스템으로 결합된 구조임

## Ⅴ. 원리 및 절차 흐름도

```text
  1. 콘텐츠 등록       2. 토큰 발행 (민팅)    3. 메타데이터 연결     4. 거래 체결 (이전)    5. 소유권 확인
[창작자 ↔ IPFS] ───> [스마트계약 구동] ───> [Token URI 갱신] ───> [지갑 서명 전송] ───> [장부 조회 검증]
```

1. **콘텐츠 등록**: 원본 미디어와 관련 속성 정보를 분산 스토리지(IPFS)에 올리고, 고유한 해시 주소(CID)를 발급받음
2. **토큰 발행 (Minting)**: 스마트 계약을 호출하여 고유 토큰 ID를 지정한 뒤, 창작자의 지갑 주소에 소유권을 매핑함
3. **메타데이터 연결**: 생성된 토큰 ID에 해당 오프체인 메타데이터 JSON 파일의 주소(Token URI)를 매핑해 자산과 정보를 결합함
4. **거래 체결 (Transfer)**: 양도자가 지갑에서 서명하여 트랜잭션을 전송하면 스마트 계약이 토큰 ID의 주인을 양수자 주소로 갱신함
5. **소유권 확인**: 검증자는 블록체인 장부를 직접 조회하여 토큰 ID를 가진 주소가 현재 거래 주소와 일치하는지 최종 확인함

### 쉽게 이해하기 (학습용)
- 사진을 인터넷 창고에 올리고 링크를 받아, 블록체인 공장에 일련번호가 적힌 티켓을 발행하면서 해당 링크를 적고, 티켓의 주인을 변경해 나가며 장부로 진짜 주인을 파악하는 절차임

## Ⅵ. 실무 사례

1. **공연 티켓 암표 방지 시스템**: 공연 관람 티켓을 스마트 계약 기반 NFT로 발행하여 관람객 모바일 지갑으로 배포하고, 암표 상의 고가 거래 시 소유권 양도를 차단하도록 양도 제약 조건을 스마트 계약 내에 조치함
2. **디지털 아트 보증서 연동**: 창작 작품에 대한 소유권 NFT 발행 시, 원본 예술품 이미지의 영구 보관을 위해 탈중앙화 분산 스토리지인 IPFS를 이용해 데이터 영속성을 유지하도록 저장 체계를 구축함

### 쉽게 이해하기 (학습용)
- 매진된 콘서트 티켓의 불법 프리미엄 양도를 막기 위해 지갑 간 이동을 금지하는 암호 티켓을 발급하거나, 모바일 아트 작품 보증서를 블록체인과 연결해 발행하는 경우임

## Ⅶ. 결론

- NFT는 디지털 자산에 위변조 불가능한 고유 소유권을 부여하여 신뢰를 형성하는 기술 표준이며, 자산 범위 정의와 메타데이터의 안전한 유지가 시스템 실효성의 관건임
- 향후 거래 활성화와 시스템 리스크 통제를 위해 오프체인 이미지 삭제 시 소유권만 남는 "껍데기 토큰" 현상을 예방하는 오프체인 스토리지 안정성 확보와 법적 실물 소유권 간의 괴리 보완 제도가 마련되어야 함

### 쉽게 이해하기 (학습용)
- 디지털 세상 속 물건에 유일한 진품 보증서를 달아 가치를 지켜주는 혁신이지만, 보증서 자체의 법적 권리와 실제 파일 관리 수준을 일치시켜 나가는 실무적 고민이 동반되어야 함-----------+    +------------------+    +------------------+    +-------------+
| 스마트 계약      | -> | 토큰 ID / 소유자   | -> | 메타데이터 위치 정보 | -> | 지갑/거래 화면 |
+---------------+    +------------------+    +------------------+    +-------------+
         |
         v
+---------------+
| 이벤트 이력      |
+---------------+
```

> 요약: NFT는 스마트 계약, 고유 토큰 ID, 메타데이터, 지갑, 이벤트 이력이 함께 자산성을 구성함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 자산 범위 정의  | -> | 토큰 발행      | -> | 메타데이터 연결 | -> | 거래/이전      | -> | 소유권 확인    |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **자산 범위 정의**: 어떤 권리나 콘텐츠를 토큰으로 표현할지 정함
2. **토큰 발행**: 스마트 계약이 고유 토큰 ID를 만들고 소유자를 기록함
3. **메타데이터 연결**: 토큰이 가리킬 파일과 설명과 권리 정보를 등록함
4. **거래와 이전**: 지갑 서명으로 토큰 소유권을 이전함
5. **소유권 확인**: 체인 상태와 이력을 조회해 현재 소유자와 출처를 확인함

> 요약: NFT는 자산 범위를 먼저 정한 뒤 토큰을 발행하고 메타데이터와 연결해 거래와 검증에 활용함.

## Ⅵ. 실무 적용 및 유의점

1. 디지털 티켓은 NFT로 보유자를 검증하되 사용 후 상태 변경을 설계하고 검증 성공률·중복 차단율로 확인함
2. 콘텐츠 이력 관리는 권리 조건을 메타데이터와 연결하고 메타데이터 가용성·권리 분쟁 건수로 확인함

## Ⅶ. 결론

- NFT는 고유성·소유 이력·이전 가능성이 중요할 때 유효하며 권리 정의와 메타데이터 지속성이 핵심임

## 작성 근거(검토용)

- 개요는 NFT를 단순 디지털 그림이 아니라 고유 자산과 권리 표현 구조로 정의해 시험 답안 축을 분명히 함
- Ⅲ은 대체가능토큰과 중앙 DB 기록을 같이 비교해 NFT의 차별점이 고유성인지 운영 방식인지 바로 읽히게 함
- Ⅳ는 계약, 토큰 ID, 메타데이터, 지갑, 이벤트 이력으로 나눠 기술 구조와 권리 추적 구조를 함께 보여줌
- Ⅴ는 자산 범위 정의를 첫 단계에 둬 체인 기록과 법적 권리가 같지 않다는 점을 자연스럽게 연결함
- Ⅵ은 티켓 검증과 권리 분쟁을 대표 리스크로 잡아 중복 사용 차단과 메타데이터 가용성을 운영 지표로 남김
