## 미리 알고가기

- 대체가능토큰은 서로 같은 값으로 바꿔 쓸 수 있지만 NFT는 토큰마다 고유 식별값이 있음
- 메타데이터는 토큰이 가리키는 이미지, 설명, 권리 정보 같은 부가 정보임
- 토큰 보유 기록과 법적 권리 보장은 같은 뜻이 아니므로 계약 범위를 따로 봐야 함

## Ⅰ. 개요

- **정의/개념**: NFT는 고유 토큰 ID와 소유권 기록으로 디지털 자산이나 이용 권리를 개별 단위로 표현하는 구조임
- **배경/필요성**: 디지털 콘텐츠·회원권·티켓은 복제가 쉬움. 진본성, 소유 이력, 양도 기록을 함께 남기는 방식이 필요함

## Ⅱ. 특징

- 토큰마다 고유 식별자가 있어 같은 값으로 서로 바꿔 쓸 수 없음
- 소유권 이전 이력이 체인에 남아 출처 추적과 거래 감사에 유리함
- 메타데이터와 원본 파일이 외부 저장소에 있으면 링크 단절이나 내용 변경 위험이 남음
- 희소성 표현과 권리 자동화에는 강하지만 수수료와 사용자 지갑 경험과 법적 해석을 함께 봐야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 대체가능토큰 | 중앙 DB 자산기록 | NFT |
|:---|:---|:---|:---|
| 자산 표현 | 동일 단위로 교환 가능함 | 운영자가 정한 항목으로 관리함 | 자산마다 고유하게 표현함 |
| 소유권 기록 | 잔액 중심임 | 서비스 내부 기록에 의존함 | 체인 이력으로 남김 |
| 이전 범위 | 지갑 간 이전 가능함 | 서비스 내부 이동이 주로 가능함 | 지갑 간 이전 가능함 |
| 주의점 | 개별 자산 표현이 약함 | 운영자 신뢰가 필요함 | 메타데이터와 수수료 관리가 필요함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 스마트 계약 | 발행, 이전, 소각 규칙을 정의하는 실행 계층으로 표준 준수 여부가 연동성을 좌우함 |
| 토큰 ID와 소유자 정보 | 각 토큰의 고유 번호와 현재 소유자를 기록하는 핵심 상태 계층으로 고유성 판단의 기준이 됨 |
| 메타데이터 위치 정보 | 이미지, 설명, 권리 범위를 가리키는 참조 계층으로 저장 안정성이 실사용 품질을 좌우함 |
| 지갑과 거래 화면 | 보유, 이전, 거래를 수행하는 사용자 접점 계층으로 서명 경험과 수수료 부담이 중요함 |
| 이벤트 이력 | 발행과 이전 기록을 남겨 출처 추적과 감사에 활용하는 기록 계층임 |

```text
+---------------+    +------------------+    +------------------+    +-------------+
| 스마트 계약      | -> | 토큰 ID / 소유자   | -> | 메타데이터 위치 정보 | -> | 지갑/거래 화면 |
+---------------+    +------------------+    +------------------+    +-------------+
         |
         v
+---------------+
| 이벤트 이력      |
+---------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 자산 범위 정의  | -> | 토큰 발행      | -> | 메타데이터 연결 | -> | 거래/이전      | -> | 소유권 확인    |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **자산 범위 정의**: 어떤 권리나 콘텐츠를 토큰으로 표현할지 정함
2. **토큰 발행**: 스마트 계약이 고유 토큰 ID를 만들고 소유자를 기록함
3. **메타데이터 연결**: 토큰이 가리킬 파일과 설명과 권리 정보를 등록함
4. **거래와 이전**: 지갑 서명으로 토큰 소유권을 이전함
5. **소유권 확인**: 체인 상태와 이력을 조회해 현재 소유자와 출처를 확인함

## Ⅵ. 실무 적용 및 유의점

1. 디지털 티켓은 NFT로 보유자를 검증하되 사용 후 상태 변경을 설계하고 검증 성공률·중복 차단율로 확인함
2. 콘텐츠 이력 관리는 권리 조건을 메타데이터와 연결하고 메타데이터 가용성·권리 분쟁 건수로 확인함

## Ⅶ. 결론

- NFT는 고유성·소유 이력·이전 가능성이 중요할 때 유효하며 권리 정의와 메타데이터 지속성이 핵심임
