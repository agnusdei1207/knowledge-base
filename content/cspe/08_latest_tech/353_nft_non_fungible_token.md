# 📖 【암기용】 개념 완전 이해

> 목적: NFT를 고유 토큰 ID로 특정 자산 또는 권리를 식별하는 블록체인 토큰으로 이해하게 만든다.

## 한눈에
- **개요**: ERC-721 등 표준으로 고유성을 표현하는 토큰
- **왜 필요한가**: 디지털 파일은 복제가 쉽지만 소유권, 이용권, 티켓, 인증서 같은 권리 단위는 고유 식별과 이전 이력이 필요하다.
- **핵심 직관**: 이미지 파일 자체가 NFT인 것이 아니라, 블록체인 토큰 ID가 어떤 메타데이터와 권리를 가리키는 증서 역할을 한다.

## 깊이 이해
- **배경·문제의식**: 기존 디지털 자산은 원본성, 이전 이력, 소유자 확인을 플랫폼 내부 DB에 의존했다. NFT는 토큰 ID와 소유자 상태를 공개 장부에 기록한다.
- **작동 원리**: 스마트 계약이 tokenId별 owner를 저장하고 `transferFrom()` 같은 표준 함수로 소유권 이전을 기록한다.
- **비유**: 그림 원본을 직접 들고 다니는 것이 아니라, 등기부에 고유 번호와 소유자 변경 이력이 기록되는 구조다.
- **구체 예시**: ERC-721은 각 tokenId가 하나의 고유 자산을 나타내고, ERC-1155는 하나의 계약에서 fungible, non-fungible, semi-fungible 토큰을 함께 다룰 수 있다.
- **흔한 오해·주의점**: NFT가 저작권 양도를 자동 보장하지 않는다. 메타데이터, 라이선스, 원본 저장소, 법적 권리 범위를 별도 확인해야 한다.

## 연결 개념
- ERC-721 — 대표 NFT 표준
- ERC-1155 — 다중 토큰 표준
- Smart Contract — NFT 발행과 이전을 실행하는 코드

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.
> 핵심: NFT는 고유 tokenId와 소유권 상태를 표준 인터페이스로 관리하며, 메타데이터 무결성·권리 범위·시장 조작 리스크를 함께 판단해야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: NFT는 스마트 계약에서 고유 tokenId와 owner를 관리하는 대체불가능 토큰이다.
> 2. **가치**: 디지털 수집품, 티켓, 인증서, 게임 아이템의 소유권 이전과 이력 추적을 표준 인터페이스로 제공한다.
> 3. **판단 포인트**: ERC-721/1155, metadata URI, 원본 저장, 라이선스, royalty, marketplace 보안이 핵심이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| NFT 구조 이해 확인 | tokenId, owner, metadata, ERC-721 | 이미지 파일 자체로 설명 |
| 권리와 기술 구분 확인 | 소유 기록과 저작권은 별도 | NFT 구매가 저작권 양도로 단정 |
| 운영 리스크 확인 | metadata 변조, phishing, wash trading | 가격 상승 사례 중심 답안 |

> 요약: 이 문제는 NFT의 표준 구조와 권리·메타데이터 리스크를 구분해 설명해야 한다.

## Ⅰ. 개요 및 필요성

- 개요: 고유 자산 토큰
- 배경: 디지털 자산의 소유자, 이전 이력, 권리 범위는 플랫폼 DB와 약관에 의존하는 경우가 많음.
- 필요성: ERC-721/1155 기반 tokenId와 스마트 계약으로 고유 자산 식별과 이전 내역을 검증해야 함.

---

## Ⅱ. 구조 및 구성요소

```text
Creator -> NFT Contract -> TokenId / Owner Mapping
        -> Metadata URI -> Off-chain Storage / License
User Wallet -> Marketplace -> Transfer / Approval / Event
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| NFT contract | 발행·이전·조회 함수 제공 | ERC-721, ERC-1155 |
| tokenId | 고유 자산 식별 | collection 내 유일 |
| metadata | 이름·이미지·속성 URI | IPFS/HTTPS |
| marketplace | 거래·승인·이벤트 처리 | approval risk |

> 요약: NFT는 토큰 소유 상태와 메타데이터 참조가 분리된 구조이므로 원본 저장과 권리 조건을 함께 확인해야 한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
콘텐츠 등록 -> metadata 생성 -> mint(tokenId)
-> wallet 소유 -> approve/transfer -> event 기록 -> marketplace 조회
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 메타데이터 URI와 라이선스 조건을 정의함 | metadata schema |
| 2 | 스마트 계약이 tokenId를 발행하고 owner를 기록함 | mint event |
| 3 | 소유자가 marketplace 또는 지갑에 이전 권한을 승인함 | approval scope |
| 4 | 전송 후 ownerOf와 event log로 소유 이력을 확인함 | ownership proof |

> 요약: NFT의 소유권 검증은 원본 파일이 아니라 계약 상태와 이벤트 로그를 기준으로 한다.

---

## Ⅳ. 특징

| 구분 | ERC-20 | ERC-721 | ERC-1155 |
|:---|:---|:---|:---|
| 대체성 | fungible | non-fungible | 혼합 지원 |
| 식별 | balance 중심 | tokenId별 owner | id별 balance |
| 용도 | 화폐·포인트 | 고유 자산 | 게임·티켓 묶음 |
| 비용 | 단순 전송 | 개별 토큰 관리 | batch transfer |

> 요약: ERC-721은 고유 자산 표현에, ERC-1155는 다종 토큰과 batch 처리에 적합하다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 소유 기록 | 플랫폼 DB | 온체인 owner | 외부 검증 필요 |
| 원본 저장 | 서버 파일 | IPFS/Arweave/HTTPS URI | 지속성 요구 |
| 권리 표현 | 약관 | metadata+license | 법적 집행 가능성 |

> 요약: NFT는 소유 이력 검증에는 적합하지만 원본 보존과 권리 집행은 별도 설계가 필요하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 메타데이터 소실 | 중앙 URL 만료 | IPFS pinning, content hash | broken URI rate |
| 승인 탈취 | 무제한 approval | approval limit, revoke UI | suspicious approval |
| 시장 조작 | wash trading | 거래 패턴 탐지 | self-trade ratio |

> 요약: NFT 운영 리스크는 토큰보다 메타데이터 지속성, 승인 권한, 거래 조작에서 발생한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 표준 준수 | ERC-721/1155 인터페이스 | contract test |
| 원본성 | metadata hash와 URI 검증 | content audit |
| 권리 | 라이선스·약관 명시 | legal review |

> 요약: NFT 도입은 발행 수량보다 표준 호환, 메타데이터 무결성, 권리 범위 명시로 평가한다.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. NFT가 표현하는 권리를 소유권 기록, 이용권, 입장권, 인증서 중 하나로 명확히 분류하고 약관에 반영함.
2. ERC-721 또는 ERC-1155를 선택하고 metadata URI, content hash, 원본 저장소, pinning 정책을 정의함.
3. marketplace approval 범위, phishing 탐지, wash trading 모니터링, 저작권 신고 절차를 운영 정책에 포함함.

**결론 (2줄):**
- 기술사 판단: 외부 검증 가능한 고유 권리 이전이 필요하면 NFT를 적용하고, 내부 포인트·일반 상품권은 기존 DB가 단순함.
- 향후 방향: NFT는 투기성 수집품보다 티켓, 인증서, 게임 자산, 디지털 제품 여권과 결합한 권리 증명으로 재정의됨.
