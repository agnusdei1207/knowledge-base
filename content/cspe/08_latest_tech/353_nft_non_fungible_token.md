## 미리 알고가기

- NFT는 서로 같은 값으로 교환되는 토큰이 아니라 개별 식별값을 가진 고유 토큰임
- 토큰 자체와 메타데이터 저장 위치를 함께 봐야 실제 소유권과 활용 범위를 이해할 수 있음
- 디지털 자산 관리에 적합하더라도 모든 자산 시스템에 블록체인이 필요한 것은 아님

## Ⅰ. 개요

- **정의/개념**: Non-Fungible Token은 블록체인 위에서 고유한 토큰 식별자와 소유권 기록과 메타데이터 참조를 통해 디지털 자산이나 이용 권리를 개별적으로 표현하는 토큰 구조임
- **배경/필요성**: 디지털 콘텐츠와 회원권과 티켓처럼 복제가 쉬운 자산은 진본성과 소유 이력과 양도 기록을 일관되게 관리하기 어려워 거래 이력과 소유권을 분리 불가능하게 기록하는 수단이 필요함

## Ⅱ. 특징

- 토큰마다 고유 식별자가 있어 동일 토큰끼리 일대일로 대체되지 않음
- 소유권 이전 기록이 체인에 남아 출처 추적과 거래 이력 확인에 유리함
- 메타데이터와 파일이 외부 저장소에 있으면 링크 단절이나 내용 변경이 실사용 가치를 약화시킬 수 있음
- 희소성 표현과 권리 자동화에 강점이 있지만 수수료와 사용자 지갑 경험과 법적 권리 해석을 함께 검토해야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 일반 대체가능토큰 | 중앙 DB 자산기록 | NFT |
|:---|:---|:---|:---|
| 자산 단위 | 동일 단위로 교환 가능 | 운영자 정의 자산 | 고유 식별 자산 |
| 소유권 기록 | 잔액 중심 | 사업자 데이터베이스 | 체인 기반 이력 |
| 휴대성과 이전 | 지갑 간 이전 가능 | 서비스 내부 종속 | 지갑 간 이전 가능 |
| 대표 한계 | 개별 자산 표현이 약함 | 운영자 신뢰가 필요함 | 메타데이터와 수수료 관리가 필요함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Smart Contract | 발행과 이전과 소각 규칙을 정의하는 실행 계층으로 표준 준수 여부가 지갑과 마켓 연동성을 좌우함 |
| Token ID and Ownership | 각 토큰의 고유 번호와 현재 소유자 정보를 기록하는 핵심 상태 계층으로 고유성 판단의 기준이 됨 |
| Metadata URI | 이미지와 설명과 권리 범위를 가리키는 참조 계층으로 외부 저장 안정성이 실사용 품질을 결정함 |
| Wallet and Marketplace | 보유와 이전과 거래를 수행하는 사용자 접점 계층으로 서명 경험과 수수료 부담이 중요함 |
| Event History | 발행과 이전 이력을 남겨 출처 추적과 거래 감사에 활용하는 기록 계층임 |

```text
+---------------+    +------------------+    +----------------+    +-------------+
| Smart Contract| -> | Token ID / Owner | -> | Metadata URI   | -> | Wallet / UX |
+---------------+    +------------------+    +----------------+    +-------------+
         |
         v
+---------------+
| Event History |
+---------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 자산 정의     | -> | 토큰 발행      | -> | 메타데이터 연결 | -> | 거래/이전      | -> | 소유권 검증    |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **자산 정의**: 어떤 권리나 콘텐츠를 토큰으로 표현할지 정함
2. **토큰 발행**: 스마트 계약이 고유 토큰 ID를 생성하고 소유자를 기록함
3. **메타데이터 연결**: 토큰이 참조할 파일과 설명과 권리 정보를 등록함
4. **거래와 이전**: 지갑 서명으로 토큰 소유권을 이전함
5. **소유권 검증**: 체인 상태와 이력을 조회해 현재 소유자와 출처를 확인함

## Ⅵ. 실무 적용 및 유의점

1. 디지털 티켓과 멤버십은 NFT로 양도 이력과 보유자 검증을 자동화하기 좋지만 메타데이터 서버와 사용 처리 로직이 약하면 복제나 중복 사용 문제가 남으므로 메타데이터 무결성과 사용 후 상태 변경 규칙을 함께 설계하고 입장 검증 성공률과 중복 사용 차단율로 확인함
2. 디지털 콘텐츠 원본 이력 관리는 NFT가 적합하지만 토큰이 곧 법적 권리 전체를 보장하는 것은 아니므로 계약 범위와 저작권 조건을 명확히 연결하고 메타데이터 가용성과 권리 분쟁 건수로 확인함

## Ⅶ. 결론

- NFT는 디지털 자산의 고유성과 소유 이력과 지갑 기반 이전이 중요한 경우에 의미가 크며 권리 정의와 메타데이터 지속성이 약하면 단순 DB보다 나은 가치를 만들기 어려움
