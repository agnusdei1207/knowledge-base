# 📖 【암기용】 개념 완전 이해

> 목적: Tree-of-Thought를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: LLM이 중간 사고 단계를 트리 구조로 분기·탐색하여 최적 답을 선택하는 추론 프레임워크
- **왜 필요한가**: Chain-of-Thought(CoT)는 단일 경로만 따르므로, 초기 오류가 전파되면 복구 불가
- **핵심 직관**: "한 줄로 쭉 풀기" 대신 "여러 갈래로 나눠 보고, 막히면 되돌아간다"

## 깊이 이해
- **배경·문제의식**: CoT는 순차 1경로 -> 24-Game·창작 작문 등 탐색 문제에서 정답률 4%대. 사람은 여러 가설을 세우고 평가·폐기하는데, 기존 프롬프팅은 이를 모사하지 못함
- **작동 원리**: ① 문제를 중간 단계(thought)로 분해 -> ② 각 단계에서 후보 thought k개 생성(branching) -> ③ LLM 자체 평가(value/vote)로 유망도 판정 -> ④ BFS 또는 DFS로 트리 탐색, 유망하지 않으면 가지치기(pruning) -> ⑤ 최종 리프 노드 중 최고 점수 답 반환
- **비유**: 미로를 풀 때, 갈림길마다 분필로 표시하고 막다른 길이면 돌아오는 것과 같다
- **구체 예시**: 24-Game(4개 숫자로 24 만들기)에서 CoT 정답률 4% -> ToT 적용 시 74%로 상승(Yao et al., 2023)
- **흔한 오해·주의점**: ToT는 추론 비용이 분기 수 x 깊이만큼 증가하므로 단순 QA에는 비용 대비 효과가 낮음. CoT로 해결되는 문제에는 CoT를 적용함.

## 연결 개념
- Chain-of-Thought(CoT): ToT의 단일 경로 기반 전신
- Graph-of-Thought(GoT): 트리를 DAG로 확장하여 사고 합류 허용
- Self-Consistency: 다중 경로 샘플링 후 다수결, ToT와 상호보완

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: LLM 추론을 트리 탐색(BFS/DFS)으로 확장하여 단일 경로 한계를 극복하는 프레임워크
> 2. **가치**: 24-Game 정답률 4%->74%, 창작 작문 일관성 2배 향상 등 복잡 추론 정확도 대폭 개선
> 3. **판단 포인트**: 탐색 문제(조합·계획)에 효과적, 단순 QA는 CoT 대비 비용만 증가

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| LLM 추론 확장 기법 이해 확인 | CoT→ToT 진화 이유, BFS/DFS 탐색+가지치기 구조, 24-Game 4%→74% | 단순 "다중 경로" 설명에 그치고 평가·가지치기 메커니즘 누락 |
| 비용-성능 트레이드오프 판단 확인 | 분기 수×깊이 API 호출 증가, 단순 QA는 CoT 대비 비용 5~10배 | ToT를 모든 문제에 적용해야 한다고 단정 |
| 탐색 알고리즘 선택 역량 확인 | BFS(폭 b 유지) vs DFS(깊이 우선+백트래킹) 선택 기준 | BFS·DFS 차이 없이 "탐색"으로 뭉뚱그림 |

> 요약: 이 문제는 CoT 한계를 트리 탐색으로 해결하는 구조와 비용 대비 효과 판단력을 요구한다.

---

## Ⅰ. 개요 및 필요성

- 정의: LLM 추론을 트리 구조로 분기·탐색하는 프레임워크
- 배경: CoT 단일 경로는 초기 오류 전파 시 복구 불가
- 필요성: 조합 최적화·계획 수립 등 탐색 문제에서 CoT 정답률 10% 미만으로 하락

---

## Ⅱ. 구조 및 구성요소

```text
Problem -> Thought A1 -> A1-1 (유망, 확장)
                      -> A1-2 (가지치기)
        -> Thought A2 -> A2-1 (가지치기)
                      -> A2-2 (최적 답 선택)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Thought Generator | 단계별 후보 사고 k개 생성 | Sample(독립 생성) 또는 Propose(순차 제안) |
| State Evaluator | 각 사고의 유망도를 점수/투표로 평가 | LLM 자체 평가, 외부 검증기 병행 가능 |
| Search Algorithm | BFS/DFS로 트리 탐색·가지치기 수행 | BFS: 폭 b 유지, DFS: 깊이 우선+백트래킹 |

> 요약: Generator가 후보를 만들고, Evaluator가 평가하며, Search가 최적 경로를 탐색한다

---

## Ⅲ. 동작원리 및 흐름도

```text
문제 입력 -> 단계 분해 -> 후보 생성 k개 -> 자체 평가
  -> 유망? Yes -> 확장 / No -> 가지치기·백트래킹
  -> 최종 리프 선택 -> 답 출력
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 문제를 중간 사고 단계로 분해 | 단계 수 3~5 이내 |
| 2 | 각 단계에서 후보 thought k개 생성 | k=3~5, 다양성 확보 |
| 3 | LLM 자체 평가(value 1~10 또는 vote) | 임계값 이하 가지치기 |
| 4 | BFS/DFS 탐색 후 최고 점수 리프 반환 | 최종 답 정합성 검증 |

> 요약: 분해->분기 생성->자체 평가->탐색·가지치기->최적 답 반환의 5단계 트리 탐색

---

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| CoT 대비 | 다중 경로+백트래킹 가능 | 탐색 문제 정답률 4%->74% |
| Self-Consistency 대비 | 중간 단계 평가·가지치기 | 불필요 경로 조기 제거로 토큰 절감 30% |
| 한계 | 분기 수 × 깊이만큼 API 호출 증가 | 단순 QA는 CoT 대비 비용 5~10배 |

> 요약: 탐색 문제에서 CoT 대비 정답률 18배 향상, 단순 과제에는 비용 대비 효과 낮음

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드(ToT) | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | CoT(단일 경로) | 트리 분기+BFS/DFS 탐색 | 탐색 공간이 넓으면(조합·계획) ToT |
| 비용/성능 | CoT 1회 호출 | 분기 수×깊이 다회 호출 | 비용 5~10배 증가 감내 가능 시 적용 |
| 운영/위험 | 오류 시 재시도 불가 | 가지치기로 오류 경로 조기 제거 | 탐색 문제 정답률 4%→74% |

> 요약: 탐색이 필요한 조합·계획 문제에서 CoT 대비 정답률 18배 향상, 단순 QA는 CoT로 충분하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 비용 폭증 | 분기 수 k×깊이 d 호출 | k=3~5, 깊이 3~4로 제한 | API 호출 횟수, 총 토큰 수 |
| 과잉 탐색 | 단순 문제에 ToT 적용 | 난이도 라우터로 CoT/ToT 자동 분기 | CoT 정답률 90% 이상이면 ToT 불필요 |
| 평가 편향 | LLM 자체 평가의 일관성 부족 | 외부 검증기(테스트·계산기) 병행 | 평가 점수와 실제 정답 상관계수 ≥0.8 |

> 요약: 비용 통제는 분기·깊이 제한, 평가 신뢰도는 외부 검증기 병행으로 확보한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 정답률 | CoT 대비 +15%p 이상 | 벤치마크(24-Game, GSM8K) |
| 비용 효율 | 정답당 토큰 비용 CoT 대비 3배 이내 | API 호출 로그·비용 집계 |
| 탐색 수렴 | 깊이 4 이내 최적 답 도달 | 트리 깊이·가지치기 비율 모니터링 |

> 요약: 정답률 향상 폭과 정답당 비용을 동시에 측정하여 ToT 도입 효과를 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 코드 생성 파이프라인에 ToT 적용하여 후보 솔루션 5개 생성·자체 테스트 평가, HumanEval pass@1 67%->82%
2. 다단계 수학 문제 풀이에 BFS 기반 ToT 적용, GSM8K 정답률 CoT 78%->ToT 89%
3. 비즈니스 전략 수립 시 시나리오 트리 탐색으로 3개 대안 비교·최적안 도출

**결론 (2줄):**
- 기술사 판단: 조합·계획·코드 생성 등 탐색 문제면 ToT, 단순 QA·분류면 CoT 유지
- 향후 방향: MCTS(Monte-Carlo Tree Search) 결합으로 탐색 효율 최적화 진행 중
