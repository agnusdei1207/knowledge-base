## 미리 알고가기

- 트리 오브 소트 ($ToT$): 단일 가설이 아닌 다중 분기 가설들의 의사결정 나무를 그려 탐색하는 고난도 추론 아키텍처임
- 가지치기 ($Pruning$): 탐색 트리에서 성공 확률이 극도로 낮은 비효율 분기들을 조기에 잘라내는 정화 작업임
- 백트래킹 ($Backtracking$): 현재 추론 경로가 막다른 골목에 다다랐을 때, 직전 상태의 분기 노드로 돌아가 다른 길을 모색하는 역추적 기법임
- 상태 평가기 ($State$ $Evaluator$): 생성된 중간 생각 조각들의 가치(정답 가능성)를 정량적 수치로 스코어링하는 감별 모듈임

## Ⅰ. 개요

- **정의/개념**: Tree-of-Thought(ToT)는 대형 언어 모델이 고난도 조합 최적화 문제를 해결할 때, 생각의 후보군들을 트리($Tree$) 구조의 다중 상태 노드로 구성한 후 깊이 우선 탐색($DFS$)이나 너비 우선 탐색($BFS$) 알고리즘을 적용해 최적 경로를 추적하는 다경로 추론 프레임워크임
- **배경/필요성**: 기존의 선형적인 단계 추론($CoT$)은 중간 논리 전개에서 단 한 번이라도 연산 실수를 범하면 되돌아오지 못한 채 오답을 최종 출력하는 한계를 노출하여, 잘못된 판단 시 역추적 및 대안 경로를 탐색할 수 있는 가용 체계가 요구되며 제안됨

## Ⅱ. 특징

- 하나의 의사결정 노드에서 여러 개의 다음 논리 후보군을 독립적으로 파생하여, 동시다발적인 해결 전략 시나리오를 검토하는 분기적 연산을 수행함
- 모델 자신이 생성한 각 노드의 유망도를 "확실히 가능성 있음($Sure$)", "보통($Maybe$)", "불가능($Impossible$)" 등으로 셀프 진단하여 하위 트리 확장 여부를 통제함
- 24게임이나 단어 맞추기 퍼즐 등 고도의 수학적 백트래킹과 조합 탐색 능력이 필수적인 NP-Hard급 추론에서 정확도를 극대화함

## Ⅲ. 종류 및 비교

| 판단 기준 | 체인 오브 소트 (CoT) | 트리 오브 소트 (ToT) | 그래프 오브 소트 (GoT) |
|:---|:---|:---|:---|
| **생각의 논리 구조** | 일직선 선형 결합 | 다방향 트리 분기 및 백트래킹 | 비순환 방향 그래프 ($DAG$) 병합 |
| **추론 오류 복구** | 불가능 (오차가 끝까지 복제됨) | 가능 (틀리면 이전 부모 노드로 백트래킹) | 가능 (동일 생각 루프 돌거나 정보 재사용) |
| **토큰 소모 비용** | 상대적으로 저렴함 | 비쌈 (가지 생성 및 평가 횟수 비례) | 극도로 비쌈 (복잡한 네트워크 연산) |
| **적합한 과제** | 일반 상식 논증, 순차 규칙 해석 | 수학 퍼즐, 정형 스케줄 조율 | 대형 문서 구조화, 고난도 계획 수립 |

> 요약: CoT는 '단방향 직진'을, ToT는 '대안 비교 및 역추적'을, GoT는 '생각의 교차 융합'을 지원함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 생각 생성기 | 현재 상태에서 가능한 논리적인 다음 행동(노드) 후보 3~5개를 텍스트로 펼쳐내는 모듈임 |
| 가치 감별기 | 각 후보 노드를 읽어 들여 수용 가능 점수를 판정하는 1차 검열 장치임 |
| 백트래킹 엔진 | 감별기 점수가 임계치 이하로 떨어지면 해당 노드를 즉시 폐기하고 이전 단계 분기점을 소환함 |
| 탐색 스케줄러 | 너비 우선($BFS$), 깊이 우선($DFS$), 빔 검색($Beam$ $Search$) 중 비용에 맞는 탐색 전략을 쥐는 조타수임 |

```text
[ ToT 다중 경로 탐색 개념 ]
      [Root (Question)]
       /      |      \
    [Node A] [Node B] [Node C]
     /   \       |       \
 [Leaf 1] (X) [Leaf 2]   (X) (Pruned)
- X로 표시된 막다른 분기에서 백트래킹하여 생존한 Leaf로 최적의 최종 답안을 수렴함
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 현 상태 노드| --> | 다음 분기노드| --> | 가치 평가 및| --> | 최종 최적해 |
| 에서 시작   |     | 다수 생성    |     | 가지치기/귀환|     | 도출 및 검증|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **분기 확장** — 주어진 최상위 문제를 바탕으로, 생각 생성기가 첫 단계에서 시도할 수 있는 독립 대안 노드들을 병렬로 배출함
2. **품질 감별** — 모델에 평가용 프롬프트를 넣어 각 노드의 유효성을 질의하고, 그 확률적 대답을 바탕으로 10점 만점 등의 수치 점수를 획득함
3. **가지치기** — 지정된 점수 컷오프를 통과하지 못한 노드들은 하부 탐색을 정지(Pruning)하고, 가치 있는 노드만 스택/큐 메모리에 삽입해 전진함
4. **목표 귀환** — 탐색 스케줄러의 경로 확장과 백트래킹을 거쳐 최종 목적 노드(정답)에 도달하면, 거쳐 온 유효 노드 체인들을 정답으로 반환함

## Ⅵ. 실무 적용 및 유의점

1. ToT는 매 단계 수많은 후보 생성과 스코어링 프롬프트를 다수 유발하여 추론 지연과 API 과금 비용이 수십 배 폭증하므로, 빔 크기($Beam$ $Width$)와 최대 탐색 깊이를 제한하는 안전장치를 필히 걸고, 전체 테스트셋의 정답률 향상분 대비 비용 효율 지표를 모니터링해야 함
2. 가치 감별기를 설계할 때 단순 점수 산출 프롬프트는 편차가 크므로, 평가 기준을 구체적으로 세분화한 다중 프롬프팅 검증기나 혹은 고전 프로그램 코드 논리(예: 이산 연산 결과 확인 코드)와 하이브리드로 엮어 판정 신뢰도를 보정해야 함

## Ⅶ. 결론

- Tree-of-Thought는 선형 추론의 외길 실패 리스크를 입체적 대안 탐색과 논리적 회귀를 통해 정복하는 추론 구조의 진화이며, 설계자는 탐색 빔 너비의 비용적 제약과 정밀한 외부 평가 코드 연동을 구축하여 가성비 높은 AI 에이전트 시스템을 배치해야 함
