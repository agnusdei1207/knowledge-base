# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: AI 모델을 훈련시키거나 대규모 추론 서비스를 돌리기 위해, **최소 수십 대에서 수만 대의 GPU가 탑재된 서버(노드)들을 초고속 네트워크(InfiniBand 등)로 촘촘하게 묶어 하나의 거대한 시스템처럼 작동하게 만든 물리적 병렬 인프라**.
- **필요성**: 최신 LLM(Llama 3 등)은 파라미터(가중치)가 너무 커서 GPU 1대(예: 80GB 메모리)에 다 담기지도 않음. 설령 담긴다 해도 연산에 수백 년이 걸림. 결국 모델을 쪼개서 여러 GPU 메모리에 나눠 올리고, 이들이 쉴 틈 없이 서로 소통하며 훈련을 병렬로 분담해야 하기 때문.
- **핵심 직관**: 슈퍼카(GPU) 부대. 짐(데이터)이 너무 많아서 슈퍼카 1대로는 어림도 없음. 슈퍼카 1만 대를 동원해서 짐을 나눠 싣고 목적지로 달림. 이때 길이 좁으면 1만 대가 서로 엉켜서 짐을 제때 못 옮김. 그래서 차들끼리 초고속으로 달릴 수 있는 "전용 무제한 아우토반(InfiniBand/NVLink)"을 깔아준 거대한 수송 부대.

## 깊이 이해
- **배경**: 컴퓨터 한 대에 꽂을 수 있는 GPU 개수는 기껏해야 8개(PCIe 슬롯 한계 등)임. 이 8개짜리 서버 상자를 넘어서 무한히 스케일 아웃(Scale-out) 하려면 서버와 서버 바깥을 선으로 연결해야 함. 그런데 일반 인터넷 선(Ethernet)으로 연결하면, GPU 속도는 빛의 속도인데 데이터 전송 속도는 자전거 수준이라 병목(Network Bottleneck)이 심각해짐. 이 통신 문제를 해결하기 위해 특수 네트워크로 엮은 것이 클러스터의 시작임.
- **작동 원리 (계층적 네트워크 설계)**:
  1. **노드 내부(Intra-node)**: 서버 상자 1개 안의 GPU 8개끼리는 **'NVLink(엔비디아 전용망)'**라는 초고속 구리선/스위치로 묶어서 서로의 메모리에 미친 듯이 빨리 접근함.
  2. **노드 외부(Inter-node)**: 서버 상자 A와 서버 상자 B 사이는 **'InfiniBand'**나 **'RoCE'**라는 특수 광케이블 네트워크 패브릭으로 엮음. CPU를 괴롭히지 않고 GPU끼리 직접 데이터를 쏴버리는 **RDMA** 기술이 적용됨.
  3. **스토리지**: 수만 개 GPU가 데이터를 달라고 아우성칠 때 끊기지 않게 쏴주는 초고속 병렬 파일 시스템 장착.
- **구체 예시**: 엔비디아의 DGX SuperPOD. "이대로만 서버랙을 깔고 스위치를 꽂으면 완벽한 클러스터가 된다"고 엔비디아가 제시한 레고 블록 같은 표준 설계도. H100 8개짜리 서버 32대를 기본 단위로 삼고, 이를 계속 이어 붙여 확장이 가능함.
- **흔한 오해/주의점**: "돈만 많아서 GPU 1만 개 사다 꽂으면 성능이 1만 배 빨라지나?" $\rightarrow$ 절대 아님. 스위치 설정 한 줄 잘못하거나 토폴로지(연결 모양)를 잘못 짜면 패킷 충돌이 나면서 효율이 반토막(Straggler 현상) 남. GPU 개수보다 '네트워크 아키텍트'의 설계 능력이 성능을 좌우함.

## 연결 개념
- **RDMA (Remote Direct Memory Access)**: 내 컴퓨터 CPU, 상대방 컴퓨터 CPU를 통하지 않고(Bypass), 다이렉트로 상대방 GPU 메모리에 데이터를 꽂아버려 지연 시간(Latency)을 극단적으로 줄이는 클러스터 핵심 통신 기술.
- **InfiniBand (인피니밴드)**: 이더넷보다 압도적으로 지연 시간이 짧고 무손실(Lossless) 통신을 보장하는, AI 클러스터를 묶는 사실상 표준 특수 네트워크.
- **NCCL (NVIDIA Collective Communications Library)**: 수만 개의 GPU가 서로 수치(Gradient)를 더하고 나누고 취합할 때(All-Reduce) 효율적으로 통신할 수 있게 해주는 엔비디아의 통신 최적화 소프트웨어.

# 📝 【답안용】 시험 답안 템플릿
## 핵심 인사이트 (3줄 요약)
- **본질**: 단일 노드(Server)의 GPU 장착 한계를 극복하기 위해, 수십~수만 대의 GPU 가속기 노드를 초저지연·고대역폭 인터커넥트(Interconnect) 패브릭으로 결합하여 단일 논리 시스템처럼 동작시키는 분산 병렬 인프라.
- **가치**: 모델의 파라미터가 단일 GPU VRAM 용량을 초과하는 거대 AI 모델의 분산 학습(Memory Scaling)을 가능케 하며, 처리 데이터 셔딩(Sharding)을 통해 훈련 시간을 기하급수적으로 단축(Compute Scaling)함.
- **판단 포인트**: GPU 클러스터의 아키텍처적 우수성은 GPU 코어의 연산력(TFLOPS) 자체보다, 노드 간 데이터 동기화 시 발생하는 **네트워크 병목(Communication Overhead)**을 RDMA 기술과 Fat-Tree 토폴로지를 통해 얼마나 Non-blocking 상태로 제거했는가에 달려있음.

## Ⅰ. 개요 및 필요성
- **정의**: 대규모 행렬 곱셈 연산(Tensor Operation) 워크로드를 분산 처리하기 위해 가속기(GPU/NPU), 고속 네트워크 스위치, 병렬 스토리지를 집적한 물리적 데이터센터 단위 블록(Scalable Unit).
- **배경**: 조 단위의 파라미터를 갖는 파운데이션 모델(Foundation Model) 학습 시, 수 테라바이트(TB)의 텐서 가중치를 실시간으로 교환해야 하는 막대한 East-West(서버 간) 트래픽 발생.
- **필요성**: 기존 클라우드/웹서버용 TCP/IP 이더넷 기반 인프라의 극심한 지연(Latency) 한계 극복, 선형적 확장성(Linear Scalability) 보장, 하드웨어 장애(Node Failure) 시 회복탄력성 확보.

## Ⅱ. GPU 클러스터의 이중(Dual) 인터커넥트 계층 구조
병목을 제거하는 물리적 고속도로.
| 계층 (Layer) | 통신 범위 및 메커니즘 | 적용 기술 및 대역폭 |
|:---:|:---|:---|
| **Intra-node**<br>(노드 내 통신) | 1개의 물리적 서버 샤시(Chassis) 내에 꽂힌 4~8개의 GPU 간 직접 통신. 메모리를 공유하는 수준의 극초고속 동기화. | **NVLink, NVSwitch**<br>(양방향 900GB/s ~ 1.8TB/s, PCIe 대비 10배 이상 빠름) |
| **Inter-node**<br>(노드 간 통신) | 여러 서버 랙(Rack) 간의 스위치를 통한 외부 네트워크 통신. 분산 학습 시 가중치 변화량(Gradient)의 집합통신(All-Reduce) 경로. | **InfiniBand, RoCE v2**<br>(400Gbps ~ 800Gbps NDR/XDR 적용, OS/CPU Bypass) |
| **Storage Fabric** | 클러스터 외부에 존재하는 공유 파일 시스템(Check-point, Dataset 저장소)과 노드 간의 통신. | **GPUDirect Storage (GDS)**, Lustre 분산 파일 시스템 |

## Ⅲ. GPU 간 집합통신 (Collective Communication) 메커니즘
수만 대의 GPU가 1개의 모델을 만들기 위해 오차율을 합치는 과정 (NCCL 기반).
1. **Local Compute (독립 연산)**: 수천 개의 GPU가 각자 할당된 데이터(Batch)를 바탕으로 순방향(Forward)/역방향(Backward) 연산을 수행하여 로컬 그래디언트(Gradient, 가중치 업데이트 값) 생성.
2. **Network Sync (All-Reduce 단계 1)**: 노드 내에서는 NVLink를 통해, 노드 간에는 InfiniBand 스위치 네트워크를 타고 각 GPU가 산출한 수십 GB의 그래디언트 행렬 조각들을 다른 모든 GPU와 상호 교환하기 시작. (Ring-AllReduce, Tree-AllReduce 알고리즘 활용).
3. **Global Update (All-Reduce 단계 2)**: 전송받은 모든 그래디언트들의 평균값(Sum/Avg)을 구하여, 클러스터 내 모든 10,000개의 GPU가 동일한 글로벌 가중치(Global Weight)를 갖도록 100% 완벽히 동기화(Sync).
4. **Next Step**: 완전히 일치된 가중치를 가지고 다음 데이터 배치의 연산을 일제히 다시 시작. (이 동기화 시간이 네트워크 성능의 핵심).

## Ⅳ. 네트워크 프로토콜 심화 비교: InfiniBand vs Ethernet (RoCE)
TCP/IP를 버려야 하는 이유.
| 통신 프로토콜 구분 | Traditional Ethernet (TCP/IP) | InfiniBand (IB) | RoCE v2 (RDMA over Ethernet) |
|:---:|:---|:---|:---|
| **처리 구조** | 커널(Kernel) 모드 개입, CPU 사이클 낭비 심각 (3 Copy) | **OS/CPU 우회 (Zero-copy, RDMA)** | 이더넷망에서 RDMA 구현 (Zero-copy) |
| **성능 (지연/패킷 손실)** | 지연 시간 긺, 패킷 손실(Drop) 시 재전송에 의한 극심한 성능 저하 | **초저지연 (마이크로초 단위), 하드웨어 레벨 무손실(Lossless) 보장** | InfiniBand 대비 미세 지연, PFC/ECN 설정 필수 (어려움) |
| **구축 비용 및 난이도**| 매우 저렴, 기 구축 장비 범용 활용 | 스위치/케이블 전부 전용 장비 필요 (독점적 고가) | 중간 (이더넷 장비 활용 + 엔지니어링 튜닝) |
| **클러스터 타겟** | 일반 웹/DB 마이크로서비스 | **초거대 LLM 학습(Training) 최전선** | 추론 인퍼런스(Inference) 및 중소형 AI |

## Ⅴ. 실무 적용 및 결론
- **판단 지표**: 노드 증설 시 선형적 확장성(Scaling Efficiency, 노드가 2배 늘 때 성능도 1.8배 이상 느는가), Straggler(가장 늦게 연산을 마친 불량 노드)로 인한 Idle Time 비율, MFU(이론 연산량 대비 실제 효율).
- **실무 설계**: 클라우드 서비스 제공자(CSP) K사의 'Multi-Tenant AI 클러스터' 네트워크 토폴로지 설계. 1024노드 구축 시 기존 Tree 토폴로지에서는 노드 간 트래픽이 몰리면 상위 스위치에서 병목(Oversubscription) 발생. 조치 방안: 네트워크 아키텍처를 **Fat-Tree (Non-Blocking Clos Network)** 구조로 전면 재설계. 1) 리프(Leaf)와 스파인(Spine) 스위치 계층 간 연결 대역폭을 1:1로 맞추어, 클러스터 내 어떤 노드끼리 통신하더라도 대역폭 저하가 없는 Full-Bisection Bandwidth 확보. 2) NCCL 라이브러리와 물리 스위치를 연동하여 하드웨어 가속 All-Reduce 엔진(SHARP) 활성화. 트래픽 혼잡도 90% 소거 및 학습 시간 30% 단축.
- **결론**: GPU 클러스터의 진정한 가치는 칩의 스펙이 아니라 '네트워크와 통신 라이브러리의 최적화 튜닝'에서 발현된다. 수만 개의 GPU 중 단 1개의 노드에 네트워크 병목이나 하드웨어 지연(Straggler)이 발생하면, 나머지 9,999개의 노드가 동기화를 위해 무한정 대기해야 하는 것이 분산 학습의 가혹한 현실이다. 따라서 GPU 클러스터를 운영하는 엔지니어는 AI 알고리즘보다 오히려 L1~L3 네트워크 패브릭(Fabric) 설계와 시스템 레벨의 병목(I/O, Thermal, Network) 해결에 전문성을 집중해야 한다.

### 🔀 문제 유형별 목차 전환
- **Ⅱ·Ⅲ 강조 (개념/원리형)**: 메모리 병목 현상을 타파하는 GPUDirect Storage(GDS) 원리 부각. 스토리지에서 데이터를 읽어올 때 CPU 메모리(Bounce Buffer)를 거치는 기존 방식과 달리, PCIe 버스를 타고 스토리지(NVMe)에서 GPU 메모리(VRAM)로 직접 꽂아버리는 DMA 데이터 파이프라인 아키텍처 기술.
- **Ⅴ·Ⅵ 강조 (실무/설계형)**: GPU 클러스터 모니터링 및 복구(Resilience) 시스템 설계. 학습 도중 잦은 하드웨어 고장(ECC Error, GPU Hang)이 발생하므로, 쿠버네티스(K8s) 환경에서 고장 노드를 자동 축출(Cordon)하고 분산 병렬 체크포인트를 통해 중단된 지점부터 5분 내 재학습을 가동시키는 자가 치유(Self-healing) 오케스트레이션 방안.
