# 📖 【암기용】 개념 완전 이해

> 목적: 하이브리드 클라우드를 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 온프레미스(사내 구축 인프라)나 프라이빗 클라우드와 퍼블릭 클라우드를 연결하여 하나의 인프라처럼 사용하는 환경
- **왜 필요한가**: 보안이 중요한 데이터는 회사 안에 두고(온프레미스), 변화가 심한 서비스는 유연한 클라우드(퍼블릭)를 써서 보안과 유연성을 동시에 잡기 위함이다.
- **핵심 직관**: "내 집(사내 서버)과 공유 오피스(퍼블릭 클라우드)를 통로로 연결해 넓게 쓰기"

## 깊이 이해
- **배경·문제의식**: 모든 것을 퍼블릭 클라우드로 옮기기엔 보안 규제나 기존 장비 비용이 아깝고, 그렇다고 온프레미스만 쓰기엔 갑작스러운 트래픽 증가에 대응하기 어렵다. 이 둘의 '중간 지점'이 필요해졌다.
- **작동 원리**: 두 환경을 전용선(Direct Connect)이나 VPN으로 연결한다. ① **Cloud Bursting**: 평소엔 온프레미스에서 돌리다가 트래픽이 넘칠 때만 퍼블릭 클라우드 자원을 빌려 쓴다. ② **데이터 보안**: DB는 내부 서버에, 웹 서버는 클라우드에 둔다. ③ **백업/DR**: 내부 데이터를 클라우드에 백업한다.
- **비유**: 식당 주방(온프레미스)은 좁지만 관리가 철저해야 하고, 홀(퍼블릭 클라우드)은 손님 수에 따라 확장 가능한 것과 같다. 주방과 홀 사이의 배식구가 연결 통로다.
- **구체 예시**: 은행에서 개인정보 DB는 사내 전산실에 두고, 이벤트 페이지는 트래픽 대응을 위해 AWS를 사용하는 경우.
- **흔한 오해·주의점**: "단순히 두 개를 따로 쓰는 것"은 하이브리드가 아니다. 두 환경이 유기적으로 연결되어 데이터와 애플리케이션이 이동 가능해야 진짜 하이브리드 클라우드다.

## 연결 개념
- Multi Cloud — 여러 퍼블릭 클라우드를 병용 (퍼블릭-퍼블릭)
- Cloud Bursting — 트래픽 폭주 시 퍼블릭 클라우드로 자원을 확장하는 기술
- SDDC (Software Defined Data Center) — 하이브리드 구성을 위한 인프라 가상화 기술

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 보안/규제 준수와 IT 민첩성 사이의 균형을 맞추기 위한 연결성(Connectivity)과 통합 거버넌스를 중심으로 답안을 구성한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Hybrid Cloud는 온프레미스(Private)의 보안성/통제권과 퍼블릭(Public)의 확장성/경제성을 단일 아키텍처 내에서 결합한 모델이다.
> 2. **가치**: 중요 자산의 물리적 보호, 기존 인프라 투자 보호(Sunk Cost), Cloud Bursting을 통한 비용 효율적 트래픽 대응이 가능하다.
> 3. **판단 포인트**: 이기종 환경 간의 고성능 전용 연결(Direct Connect) 확보와 일관된 보안 정책 적용을 위한 통합 관리 환경이 필수적이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 하이브리드 클라우드 정의 및 구성 요소 파악 | Private(온프레미스) + Public 클라우드의 유기적 결합 | 단순히 '두 환경의 병존'으로 서술 시 감점 |
| 주요 활용 사례 및 기술 메커니즘 이해 | Cloud Bursting, 데이터 보안, DR 아키텍처 | 연결 기술(VPN, 전용선) 누락 시 기술적 구체성 부족 |
| 하이브리드 환경의 관리 이슈 인식 | 통합 IAM, 일관된 거버넌스, 네트워크 지연 | 퍼블릭 클라우드만 강조하고 온프레미스 연동 이슈 간과 |

> 요약: 규제 준수와 비즈니스 성장을 동시에 달성하기 위한 '연결된 인프라'로서의 하이브리드 전략을 평가한다.

## Ⅰ. 개요 및 필요성

- 정의: 온프레미스 데이터센터나 프라이빗 클라우드를 퍼블릭 클라우드와 연결하여 데이터와 앱을 공유하는 컴퓨팅 환경
- 배경: 법적 규제(금융·공공)로 인한 특정 데이터의 내부 저장 필수성 및 기존 인프라 자산의 잔존 가치 활용 필요
- 필요성: 클라우드 이관 과도기적 전략, 대규모 트래픽 유연성(Scalability) 확보, 보안 및 규제 준수(Compliance)

---

## Ⅱ. 구조 및 구성요소

```text
온프레미스 (Private) <--- 전용선 / VPN (L2/L3) ---> 퍼블릭 클라우드 (Public)
   | (중요 DB)                                          | (웹/이벤트)
   +---> [ 통합 관리/오케스트레이션 (K8s, CMP) ] <----------+
```

| 구성요소 | 역할 | 핵심 기술 |
|:---|:---|:---|
| 연결성 (Connectivity) | 이종 환경 간 데이터 전송 및 네트워크 확장 | Direct Connect, Site-to-Site VPN, DX |
| 가상화 레이어 | 환경 간 앱 이동성(Portability) 보장 | Docker, Kubernetes, VMware Cloud |
| 데이터 동기화 | 실시간 데이터 복제 및 일관성 유지 | CDC (Change Data Capture), Storage Gateway |
| 거버넌스 (Governance) | 두 환경에 대한 단일 보안 정책 및 가시성 | 통합 IAM, CASB, 통합 모니터링 |

> 요약: 강력한 네트워크 연결을 기반으로 애플리케이션 이동성과 통합 관리 체계를 구축하는 것이 핵심이다.

---

## Ⅲ. 동작원리 및 흐름도

```text
트래픽 유입 -> 온프레미스 처리 -> 임계치 도달(Threshold) -> 퍼블릭 클라우드 자원 할당 -> 워크로드 분산
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 워크로드 분류 | 데이터 중요도/트래픽 가변성에 따른 배치 위치 결정 |
| 2 | 네트워크 연동 | 전용선 기반의 하이브리드 네트워크 구성 (지연시간 < 10ms) |
| 3 | Cloud Bursting 실행 | 온프레미스 가용량 초과 시 퍼블릭 클라우드 오토스케일링 |
| 4 | 데이터 통합 관리 | 온프레미스 DB와 클라우드 앱 간의 보안 연결 유지 |

> 요약: 보안 자산은 내부에 고정하고, 가변 자산은 외부 클라우드로 확장하여 전체 자원 효율을 극대화한다.

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 자원 최적화 | 평시 온프레미스 사용, 피크 타임 클라우드 활용 | 인프라 고정 비용(CapEx) 절감 효과 |
| 보안성 | 민감 데이터의 물리적 격리 및 통제권 유지 | ISMS, GDPR 등 규제 준수 용이성 |
| 유연성 | 필요에 따라 퍼블릭 클라우드 서비스 즉시 도입 | 신기술(AI, Serverless) 실험 장으로 활용 |
| 관리 복잡성 | 이종 플랫폼 운영 역량 및 보안 사각지대 발생 | 중앙 집중형 관리 도구 필수성 |

> 요약: 보안과 유연성의 상충 관계를 해결하나, 네트워크 지연과 운영 복잡성이라는 새로운 과제를 안겨준다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 멀티 클라우드 (Multi) | 하이브리드 클라우드 (Hybrid) | 선택 기준 |
|:---|:---|:---|:---|
| 구성 요소 | 퍼블릭 + 퍼블릭 | 퍼블릭 + 온프레미스 | 기존 데이터센터 보유 여부 |
| 주요 목적 | 벤더 종속성 탈피, 가용성 | 보안 준수, 기존 투자 보호 | 보안 규제 강도 (Compliance) |
| 연결 난이도 | 상대적으로 높음 (CSP 간 연동) | 높음 (사내망-클라우드 연동) | 인프라 제어 권한 요구 수준 |

> 요약: 벤더 종속 해소가 우선이면 멀티 클라우드, 보안과 자산 보호가 우선이면 하이브리드 클라우드를 선택한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 네트워크 병목 | 데이터 전송량 증가 및 지연시간 발생 | 전용회선(DX) 확장, 엣지 캐싱 활용 | 왕복 지연시간 (RTT), 전용선 대역폭 사용률 |
| 보안 사각지대 | 사내망-클라우드 경계 보안 설정 오류 | 제로 트러스트(ZTA), 세분화된 접근 제어 | 미승인 트래픽 차단율, 권한 오설정 수 |
| 운영 오버헤드 | 관리 포인트 이원화로 인한 비효율 | IaC를 통한 인프라 일관 관리, 통합 모니터링 | 평균 장애 복구 시간 (MTTR) |

> 요약: 네트워크 성능과 보안 경계 관리가 핵심 리스크이며, 통합 관리 도구를 통한 가시성 확보가 필수적이다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 연결 가용성 | 전용선/VPN 가용성 99.99% | 네트워크 모니터링 로그 분석 |
| 확장 반응 속도 | Bursting 시 자원 할당 < 5분 | 오토스케일링 트리거 후 프로비저닝 시간 |
| 데이터 정합성 | 온프레미스-클라우드 간 동기화 지연 < 1초 | 데이터베이스 지연 시간(Lag) 측정 |

> 요약: 도입 효과는 네트워크 안정성, 자원 확장 속도, 데이터 동기화 수준으로 정밀하게 측정한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. **Cloud Bursting**: 전자상거래 시스템에서 평시엔 온프레미스 서버를 쓰고, 블랙프라이데이 등 대형 이벤트 시에만 AWS로 확장
2. **데이터 계층화**: 고객 원장 데이터는 폐쇄망 온프레미스 DB에 보관하고, 대고객 웹/모바일 인터페이스는 클라우드에서 운영
3. **재해복구 (DR)**: 온프레미스 시스템의 웜 대기(Warm Standby) 사이트를 퍼블릭 클라우드에 구축하여 초기 구축 비용 50% 이상 절감

**결론 (2줄):**
- 기술사 판단: 하이브리드 클라우드는 클라우드 전환의 종착지가 아니라, 기업의 보안 정책과 비즈니스 요구에 따라 영구적으로 유지될 수 있는 핵심 아키텍처이다.
- 향후 방향: '클라우드 아웃(Cloud-out)' 기술(예: AWS Outposts)을 통해 퍼블릭 클라우드 기술을 온프레미스에 이식하여 관리 일관성을 높이는 방향으로 진화하고 있다.
