# 📖 【암기용】 개념 완전 이해

> 목적: 단기 메모리 에이전트를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: 현재 세션이나 작업 동안만 유지되는 에이전트 기억
- **왜 필요한가**: 다단계 대화와 도구 호출은 직전 목표, 중간 결과, 미완료 작업을 기억해야 함.
- **핵심 직관**: 단기 메모리는 회의 중 화이트보드처럼 현재 작업에 필요한 임시 맥락임.

## 깊이 이해
- **배경·문제의식**: 컨텍스트 윈도우가 길어도 모든 대화와 도구 결과를 그대로 넣으면 비용과 혼선이 증가함.
- **작동 원리**: 세션 상태, 최근 대화, 임시 변수, 도구 결과를 작업 동안 보관하고 종료 시 요약·폐기·장기 저장으로 분기함.
- **비유**: 콜센터 상담원이 통화 중 메모장을 보며 처리하고, 통화 종료 후 핵심만 CRM에 남기는 방식.
- **구체 예시**: 배포 점검 Agent가 서비스명, 배포버전, 실패 로그, 승인상태를 작업 완료 전까지 유지함.
- **흔한 오해·주의점**: 단기 메모리도 민감정보를 포함할 수 있어 세션 격리와 종료 시 폐기 정책이 필요함.

## 연결 개념
- Context Window — 단기 메모리가 투입되는 모델 입력 한계
- State Management — 임시 상태 저장
- Long-Term Memory — 종료 후 보존 여부 판단

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Short-Term Agent Memory는 현재 세션·작업의 목표, 중간상태, 도구 결과를 임시 유지하는 메모리임.
> 2. **가치**: 다단계 업무에서 재입력과 상태 누락을 줄이고 작업 완료 전 일관성을 유지함.
> 3. **판단 포인트**: 세션 격리, 토큰 예산, 종료 시 폐기·요약·장기저장 분기 기준이 핵심임.

---

## Ⅰ. 개요 및 필요성

단기 메모리는 세션 기반 임시 기억임. AI 에이전트가 다단계 작업을 수행하려면 현재 목표와 중간 결과를 유지하되, 작업 종료 후 불필요한 정보를 폐기해야 함.

---

## Ⅱ. 구조 및 구성요소

```text
Session Input -> Working Memory -> Context Builder -> LLM


   사용자요청       임시상태          요약/선별    추론
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Session Store | 세션별 임시 저장 | 사용자·작업 격리 |
| Working Memory | 목표·중간결과 유지 | 최신 상태 우선 |
| Context Builder | 모델 입력 선별 | 토큰 예산 적용 |
| Cleanup Policy | 종료 후 처리 | 폐기·요약·장기저장 |

> 요약: 단기 메모리는 세션 저장소, 작업 기억, 컨텍스트 구성기, 종료 정책으로 구성됨.

---

## Ⅲ. 동작원리 및 흐름도

```text
세션 시작 -> 목표 저장 -> 도구결과 갱신 -> 컨텍스트 선별
        -> 모델 호출 -> 작업 종료 -> 폐기/요약
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 세션 생성 | 사용자ID, 작업ID |
| 2 | 상태 갱신 | 목표, 변수, 도구결과 |
| 3 | 컨텍스트 구성 | 토큰 수, 최신성, 출처 |
| 4 | 종료 처리 | 폐기, 요약, 장기저장 판단 |

> 요약: 단기 메모리는 작업 중 갱신되고 종료 시 보존 여부가 결정됨.

---

## Ⅳ. 특징

| 구분 | 무상태 호출 | 단기 메모리 | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 맥락 유지 | 요청마다 초기화 | 세션 동안 유지 | 세션 TTL, 상태 크기 |
| 비용 | 매번 전체 입력 | 선별 입력 가능 | 토큰 수, 요약률 |
| 위험 | 상태 누락 | 세션 혼선·정보 잔류 | 격리, 종료 폐기 |

> 요약: 단기 메모리는 작업 일관성을 제공하지만 세션 격리와 종료 정리가 필요함.

---

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 세션ID·작업ID 단위로 상태를 분리하고 사용자 전환 시 메모리 재사용을 차단
2. 컨텍스트 투입 전 최신 상태, 근거, 필수 변수만 선별해 토큰 예산을 제한
3. 작업 종료 시 임시 데이터는 즉시 폐기하고 핵심 이력만 승인된 장기 저장소로 이동

**결론 (2줄):**
- 기술사 판단: 다단계 대화와 작업 자동화에는 단기 메모리를 적용하되 세션 격리를 필수로 둠.
- 향후 방향: 단기 메모리는 Agent State와 결합해 에이전트 런타임의 기본 상태관리 기능이 됨.
