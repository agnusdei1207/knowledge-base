# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: **단기 메모리 에이전트**는 **에이전트 메모리**(016 참조) 중 **현재 세션·대화** 안에서만 유지되는 휘발성 맥락을 다룬다. 최근 대화·도구 결과를 **컨텍스트 윈도우**(LLM이 한 번에 읽는 토큰 창)에 담아 다음 응답에 이어가되, 토큰 한계 안에서 관리하는 것이 핵심이다.
- **왜 필요한가**: LLM은 컨텍스트 윈도우 크기(예: 128K~200K 토큰)만큼만 한 번에 볼 수 있어, 대화가 길어지면 오래된 내용이 잘려 나가거나 비용이 급증하므로 무엇을 남기고 무엇을 요약할지 관리가 필요하다.
- **핵심 직관**: 단기 메모리는 통화 중 손에 든 "메모지"다. 지면(토큰)이 한정돼 있어 다 차면 앞부분을 버리거나(윈도우) 핵심만 요약해 여백을 확보(요약 버퍼)한다.

## 핵심 용어 정리 (내부에 등장하는 것들)
아래 용어는 답안 본문(Ⅰ~Ⅵ·표)에 그대로 등장하므로, 처음 보는 사람도 이해하도록 비유와 함께 먼저 정리한다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 단기 메모리(핵심) | 현재 세션 안에서만 유지되는 휘발성 대화·상태 맥락 | 통화 중 손에 든 "메모지" |
| 컨텍스트 윈도우(Context Window) | LLM이 한 번의 호출에서 읽을 수 있는 최대 토큰 수 | 한 번에 펼쳐 볼 수 있는 "책상 넓이" |
| 토큰(Token) | LLM이 처리하는 텍스트 최소 단위(단어 조각). 비용·한계의 기준 | 텍스트를 자른 "낱장 조각" |
| 대화 버퍼(Conversation Buffer) | 최근 대화를 순서대로 쌓아 그대로 전달하는 저장 방식 | 대화를 적은 "누적 기록장" |
| 슬라이딩 윈도우(Sliding Window) | 최근 N턴만 남기고 오래된 것을 잘라내는 방식 | 오래된 메모지를 "찢어 버림" |
| 요약 버퍼(Summary Buffer) | 오래된 대화를 요약으로 압축해 여백을 확보하는 방식 | 앞부분을 "핵심 3줄"로 압축 |
| 요약 압축(Compression) | 긴 이력을 LLM이 핵심만 남겨 토큰을 줄이는 처리 | 회의록을 요약본으로 |
| 스크래치패드(Scratchpad) | 추론·도구 결과를 임시로 적는 작업 메모 영역 | 계산용 "연습장" |
| 세션(Session) | 하나의 연속된 대화·작업 단위. 끝나면 단기 메모리 소멸 | 한 통의 "통화" |
| 승격(Consolidation) | 세션 중요 정보를 장기 메모리로 옮김. 상세는 017 참조 | 메모지를 정식 파일로 |
| Lost in the Middle | 긴 컨텍스트에서 중간 위치 정보의 회상률이 떨어지는 현상 | 두꺼운 책의 "가운데를 흘려봄" |

## 깊이 이해
- **배경·문제의식**: 에이전트가 여러 턴에 걸쳐 추론하면 대화·도구 결과가 계속 쌓인다. 이를 전부 컨텍스트 윈도우에 넣으면 토큰 한계를 넘거나(잘림), 한계 내라도 비용이 매 호출 누적되고 "Lost in the Middle"로 중간 정보 회상률이 떨어진다. 그래서 최근 맥락을 어떻게 압축·선별해 창 안에 유지할지가 문제다.
- **작동 원리(어떻게+왜)**: 가장 단순한 방식은 최근 대화를 그대로 담는 대화 버퍼지만 곧 창이 찬다. 그래서 슬라이딩 윈도우로 오래된 턴을 잘라내거나, 요약 버퍼로 앞부분을 LLM 요약으로 압축해 여백을 만든다. 잘라내기는 정보를 완전히 잃지만 저렴하고, 요약은 핵심을 보존하지만 요약 호출 비용·정보 손실 위험이 있어 트레이드오프가 존재한다. 세션이 끝나면 단기 메모리는 사라지므로, 중요한 결정은 장기(017)로 승격시킨다.
- **비유**: 좁은 책상(컨텍스트 윈도우) 위에서 일하는 것과 같다. 서류가 쌓여 자리가 없으면 오래된 것을 치우거나(슬라이딩), 앞 서류의 요점만 포스트잇에 적어 원본을 캐비닛에 넣는다(요약 버퍼).
- **구체 예시(실제 사례)**: LangChain은 `ConversationBufferMemory`(전량 보관), `ConversationBufferWindowMemory`(최근 K턴), `ConversationSummaryBufferMemory`(토큰 초과 시 앞부분 요약)를 제공한다. LangGraph는 세션 상태를 `checkpointer`로 단기 보존한다. 예: 코딩 에이전트가 최근 5개 명령은 원문으로, 그 이전은 "리팩터링 진행 중" 요약으로 유지한다.
- **흔한 오해·주의점**: "컨텍스트 윈도우가 크면 단기 메모리 관리가 필요 없다"는 오해다. 창이 커도 토큰 비용은 입력량에 비례해 늘고, 무관한 이력이 많으면 Lost in the Middle로 정확도가 오히려 떨어진다. 또한 단기 메모리는 세션 종료 시 사라지므로 영구 보존이 필요하면 반드시 장기로 승격해야 한다.

## 연결 개념
- 에이전트 메모리(016) — 단기·장기를 포괄하는 상위 기억 체계
- 장기 메모리(017) — 세션을 넘긴 승격 대상 지속 저장소
- 컨텍스트 윈도우(040)·롱컨텍스트 LLM(041) — 단기 메모리의 물리적 용량 한계

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 단기 메모리는 세션 내 대화·도구 결과를 컨텍스트 윈도우에 유지하는 휘발성 기억 계층임.
> 2. **가치**: 슬라이딩 윈도우·요약 버퍼로 토큰 한계 안에서 최근 맥락을 압축·선별해 다단계 추론의 연속성을 확보함.
> 3. **판단 포인트**: 잘라내기 vs 요약의 비용·손실 트레이드오프, Lost in the Middle 대응, 세션 종료 시 장기 승격을 함께 설계해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 세션 내 맥락 유지·토큰 관리 이해 | 컨텍스트 윈도우, 대화 버퍼, 슬라이딩·요약 버퍼 | 단기·장기 미구분, 큰 창이면 관리 불필요로 단정 |
| 토큰 한계 대응 설계 역량 | 요약 압축, Lost in the Middle, 장기 승격 | 요약 비용·정보 손실 트레이드오프 누락 |

> 요약: 컨텍스트 윈도우와 버퍼 전략을 구분하고, 요약 트레이드오프·중간 회상 저하·장기 승격을 짚어야 감점을 피함.

---

## Ⅰ. 개요 및 필요성

- 개요: 현재 세션 내 대화·상태를 컨텍스트 윈도우에 유지하는 휘발성 기억 계층임
- 배경: LLM은 컨텍스트 윈도우 토큰 한계만큼만 한 번에 읽어 긴 대화는 잘리거나 비용이 급증함
- 필요성: 최근 맥락을 압축·선별해 창 안에 유지하되 세션 종료 시 중요분은 장기(017)로 승격이 필요함
- 위치: 에이전트 메모리(016)의 단기·세션 계층에 해당하며 컨텍스트 윈도우(040) 한계에 종속됨

---

## Ⅱ. 구조 및 구성요소

- 선형 구조도

```text
사용자 발화/도구 결과 -> 대화 버퍼(누적)
  -> 토큰 임계 초과 판정
    -> 슬라이딩 윈도우(오래된 턴 제거) / 요약 버퍼(앞부분 요약 압축)
  -> 컨텍스트 윈도우 구성 -> LLM 응답
  -> 세션 종료 시 중요분 장기 승격(017)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 대화 버퍼 | 최근 대화·도구 결과 순차 저장 | 전량 보관 시 창 초과 |
| 슬라이딩 윈도우 | 최근 N턴만 유지·오래된 것 제거 | 저비용·정보 소실 |
| 요약 버퍼 | 앞부분을 LLM 요약으로 압축 | 요약 호출 비용·손실 |
| 스크래치패드 | 추론·중간 도구 결과 임시 기록 | 세션 종료 시 소멸 |
| 승격 훅 | 세션 중요분을 장기로 이전 | 017 벡터DB·그래프 연동 |

> 요약: 단기 메모리는 대화 버퍼를 토큰 임계에 맞춰 슬라이딩·요약으로 관리하고 종료 시 장기로 승격함.

---

## Ⅲ. 동작원리 및 흐름도

- 선형 흐름도

```text
발화 수집 -> 버퍼 누적 -> 토큰량 측정 -> 임계 초과 시 슬라이딩/요약
  -> 컨텍스트 윈도우 재구성 -> LLM 응답 -> 세션 종료 시 승격
```

1. 누적·측정: 대화 버퍼에 발화·도구 결과를 쌓고 현재 토큰량을 측정함
2. 임계 판정: 컨텍스트 윈도우 예산 초과 시 슬라이딩(제거) 또는 요약 버퍼(압축)를 선택함
3. 창 재구성: 시스템 프롬프트·요약·최근 원문·현재 질의 순으로 창을 구성해 LLM에 전달함
4. 종료·승격: 세션 종료 시 사용자 선호·결정 등 중요분을 장기 메모리(017)로 승격함

> 요약: 버퍼 누적-토큰 측정-압축 선택-창 재구성이 매 턴 돌고, 세션 종료가 장기 승격 시점이 됨.

---

## Ⅳ. 특징

- 휘발성: 세션 종료 시 소멸하며 영구 보존은 장기 승격에 의존함
- 저지연: 외부 검색 없이 창에 담긴 최근 맥락을 즉시 참조해 응답이 빠름
- 토큰 종속: 컨텍스트 윈도우 예산 안에서만 유지되어 압축·선별이 필수임
- 전략 선택: 슬라이딩(잘라내기)은 저렴·손실, 요약 버퍼는 보존·비용의 트레이드오프가 있음
- 위치 민감성: Lost in the Middle로 창 중간 정보의 회상률이 낮아 배치 순서가 중요함

---

## Ⅴ. 심화 비교 및 적용 판단

- 단기 관리 전략을 전체 버퍼와 요약 버퍼로 대비함

| 구분 | 전체 버퍼(슬라이딩) | 요약 버퍼(압축) |
|:---|:---|:---|
| 유지 방식 | 최근 N턴 원문, 초과분 삭제 | 오래된 대화를 요약으로 압축 |
| 정보 보존 | 최근은 완전, 과거는 소실 | 과거 핵심 보존, 세부 손실 |
| 토큰 효율 | 단순·계산 예측 쉬움 | 장기 대화에서 토큰 절감 큼 |
| 추가 비용 | 없음(잘라내기만) | 요약 LLM 호출 비용 발생 |
| 적용 상황 | 짧은 세션·최근성 중시 | 긴 상담·과거 맥락 필요 |

> 요약: 짧고 최근성이 중요한 세션은 전체 버퍼, 긴 대화에서 과거 맥락이 필요하면 요약 버퍼를 적용함.

- 주요 리스크와 대응(불릿)
  - 맥락 소실: 슬라이딩이 중요 과거 턴을 잘라냄 → 중요도 태깅 후 요약 버퍼 병행
  - 요약 왜곡: 압축 과정에서 핵심 누락·오요약 발생 → 원문 참조 링크·핵심 키워드 보존
  - 중간 회상 저하: Lost in the Middle → 요약을 창 앞·질의를 뒤에 배치, 관련성 재정렬

- 컨텍스트 예산 지표(불릿)
  - 컨텍스트 사용률 창 크기의 70% 이하 유지(토큰 카운터 모니터링)
  - 요약 압축률 60% 이상·핵심 보존 정확도 90% 이상(요약 평가셋)
  - 세션 종료 시 장기 승격 누락 0건(중요분 승격 감사)

---

## Ⅵ. 실무 적용 및 결론

- 적용 방안
  1. 최근 5~10턴은 원문 버퍼, 그 이전은 `ConversationSummaryBufferMemory`로 요약해 창 사용률을 70% 이하로 유지함
  2. 도구 결과·추론은 스크래치패드에 임시 기록하고 세션 종료 시 사용자 선호·결정을 장기(017)로 승격함
  3. 요약은 창 앞, 현재 질의는 창 뒤에 배치하고 관련성 재정렬로 Lost in the Middle을 완화함
- 결론
  - 기술사 판단: 짧고 최근성 중심 세션은 슬라이딩, 긴 상담·다단계 추론은 요약 버퍼로 선택함
  - 향후 방향: 롱컨텍스트 LLM(041)과 요약 버퍼를 결합하고 자동 승격으로 단기·장기를 잇는 방향으로 발전함
