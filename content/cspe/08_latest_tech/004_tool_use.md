## 미리 알고가기

- API (Application Programming Interface): 다른 소프트웨어 애플리케이션 간에 기능 호출과 데이터 교환이 가능하도록 정의한 규격 인터페이스임
- JSON Schema: JSON 데이터의 구조, 허용되는 필드 타입 및 필수 변수를 정의하고 유효성을 검증하는 엄격한 명세 규격서임
- Stop Sequence: 언어 모델이 특정 토큰이나 텍스트 패턴을 생성했을 때 텍스트 출력을 강제로 일시 정지하도록 만드는 시스템 제어 규칙임
- MCP (Model Context Protocol): 언어 모델과 외부 데이터 소스, 도구 간의 인터페이스 규격을 표준화하기 위해 제안된 개방형 통신 프로토콜임
- 코드 샌드박스 (Code Sandbox): 시스템에 해를 끼칠 수 있는 악성 스크립트 실행을 차단하기 위해 임의 코드를 격리된 독립 가상 환경 내에서 구동하는 안전한 실행 엔진임

## 작성 근거(검토용)

- 핵심 키워드 선정 이유: LLM의 추론 성능 한계와 실시간 데이터 격차를 극복하기 위해 외부 소프트웨어(도구)를 논리적으로 선택 및 호출하는 도구 호출(Tool Use)의 핵심 원리와 보안 통제 방안을 검증함
- 절 구성 및 전개 흐름 이유: 개요에서 정의와 배경을 수립하고, Ⅱ절에서 기능적 자율 선택과 실행 위임 등 도구 사용의 특징을 정리함. Ⅲ절에서 유사 용어인 플러그인 및 함수 호출과의 차이를 표로 비교하고, Ⅳ절에서 비동기 중개 구현 구조를 설계함. Ⅴ절에서 의도 감지부터 반환 통합으로 이어지는 흐름을 도식화하고, Ⅵ절에서 최소 권한 정책과 HITL 가드레일 조치를 확인한 후, Ⅶ절의 표준 모델 프로토콜(MCP) 동향을 짚으며 결론으로 매듭지음
- 전수 검수 완료 근거: 제목, Frontmatter, 미리 알고가기, 본문, 비교표, 결론까지 어색한 한국어 표현과 불필요한 명사구를 정밀 교정하고 수정 없는 전체 완독 5회를 마침

## Ⅰ. 개요

- **정의/개념**: 도구 호출(Tool Use)은 언어 모델이 자신의 언어적 한계를 극복하고 주어진 과업을 수행하기 위해 사전에 명시된 외부 API나 함수 목록 중 적절한 항목을 파악하고 실행 인자값을 JSON 형태로 추출 및 반환하는 메커니즘이다.
- **배경/필요성**: 산술 연산 오류, 최신 지식 부족, 외부 물리 시스템 제어 불가 등 LLM 고유의 태생적 한계를 외주(Outsourcing) 형태의 API 실행 위임을 통해 극복하고, 자율 에이전트의 실질적 행동 수단을 확보해야 한다.

### 쉽게 이해하기 (학습용)
- 인공지능에게 단순히 글만 쓸 수 있는 종이와 펜을 주던 수준에서 벗어나, 직접 마우스와 키보드를 쥐여주고 컴퓨터 프로그램을 다루게 하는 기술입니다.

## Ⅱ. 특징

- **특징 1 (비동기적 실행 중개)**: 모델이 직접 도구를 실행하지 않고, 실행 요청 JSON을 클라이언트에 전달해 실행을 위임함
- **특징 2 (정밀한 인자 추출)**: 비구조화된 사용자 대화 컨텍스트에서 엄격한 JSON Schema 규격에 맞는 정확한 매개변수를 매핑함
- **특징 3 (가중치 기반 도구 선정)**: 다수의 도구 중 사용자의 입력 의도에 부합하는 최적의 함수를 확률적으로 파악 및 라우팅함
- **특징 4 (보안 리스크 동반)**: 파괴적 API 호출이나 정보 유출 같은 악의적 명령 주입(Injection) 위협에 항상 노출됨

### 쉽게 이해하기 (학습용)
- 똑똑한 아이가 복잡한 곱셈을 할 때 직접 암산하지 않고, 옆에 있는 친구에게 계산기를 써달라고 값을 불러주는 것과 같은 협동 능력입니다.

## Ⅲ. 종류 및 비교

| 판단 기준 | 플러그인 | 도구 호출 | 함수 호출 |
|:---|:---|:---|:---|
| 생태계 개방성 | 폐쇄적 (특정 플랫폼 종속) | 개방적 (범용 아키텍처) | 모델 제조사 API 종속 |
| 실행 및 통제 주체 | 플랫폼 제공사 관리 | 호스트 애플리케이션 개발자 | 클라이언트 코드 및 모델 조율 |
| 사내 폐쇄망 연동성 | 불가능 또는 제한적 | 완벽히 가능 (사설 API 연결) | 가능 (JSON 명세 기반) |

### 쉽게 이해하기 (학습용)
- 전용 마켓에서만 다운받는 스마트폰 앱(플러그인)과 개발자가 직접 작성해 컴퓨터의 모든 장치와 연결하는 포괄적 만능 선(도구 호출)의 차이입니다.

## Ⅳ. 설계 요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 도구 명세 보관소 (Registry) | 사용 가능한 도구들의 함수명, 상세 설명 및 파라미터 규격을 JSON Schema로 저장하는 DB |
| 의도 분석기 (Intent Extractor) | 사용자 질문을 분석하여 어떤 도구를 호출할지와 도구에 전달할 실시간 매개변수를 추출하는 LLM |
| 도구 중개기 (Tool Broker) | 추출된 JSON 파라미터의 타입 유효성을 검사하고 실제 시스템 API를 호출해 실행하는 백엔드 모듈 |
| 컨텍스트 융합기 (Context Fuser) | API 호출 결과를 수집하여 기존 대화 내역(Context)에 적절히 병합한 후 LLM에 재주입하는 모듈 |

```text
[ 사용자 ] ──▶ [ 의도 분석기 (LLM) ] ──▶ JSON 명세 반환 (Stop Token) ──┐
                     ▲                                                    │
                     │                                                    ▼
            [ 컨텍스트 융합기 ] ◀── [ 실제 API 호출 ] ◀── [ 도구 중개기 (Python) ]
```

### 쉽게 이해하기 (학습용)
- 메뉴판(보관소), 손님이 시킨 요리를 확인하는 점원(분석기), 주방에서 요리하는 주방장(중개기), 완성된 요리를 식탁에 올리는 서빙원(융합기)의 역할 구조입니다.

## Ⅴ. 원리 및 절차 흐름도

```text
[ 사용자 질의 ] ──▶ [ 도구 필요 판정 ] ──▶ [ 파라미터 JSON 생성 ] ──▶ [ 모델 출력 정지 ]
                                                                             │
                                                                             ▼
[ 최종 답변 ] ◀── [ 결과 프롬프트 융합 ] ◀── [ 백엔드 API 실행 ] ◀───── [ JSON 파싱 ]
```

1. 도구 필요 판정: 사용자가 입력한 자연어 속에 날씨, 계산, DB 조회 등 외부 연동이 필요한 의도가 존재하는지 모델이 판단함
2. 파라미터 JSON 생성: 등록된 스키마 형식에 맞추어 필수 인자값들을 정밀 추출해 JSON 데이터 형식으로 변환함
3. 모델 출력 정지: 모델이 JSON 생성을 마치면 클라이언트가 실제 호출을 하도록 중지 시퀀스($Stop\ Sequence$)를 걸어 생성을 멈춤
4. JSON 파싱 및 API 실행: 백엔드 애플리케이션 코드가 모델의 출력을 가로채 JSON을 파싱하고 대상 원격 API를 실제로 구동함
5. 결과 프롬프트 융합: API 반환 결과를 텍스트 형식으로 가공하여 LLM의 입력 컨텍스트에 덧붙여 최종 답변을 완성하도록 유도함

### 쉽게 이해하기 (학습용)
- 의사가 약 처방전을 작성하면(JSON), 약사가 처방전을 읽고(파싱) 약을 지어주며(실행), 환자가 약을 먹어 몸이 나아지는(융합) 일련의 분업 절차입니다.

## Ⅵ. 실무 사례

- **실무 시스템 및 조치**: 사내 RAG 서비스 아키텍처에서 DB 조회(`query_sql`)와 일반 검색(`web_search`) 도구를 정의해 질의 성격별로 자동 라우팅하되, 악성 인젝션 위협을 예방하고자 도구 권한을 읽기 전용($Read\text{-}only$)으로 축소하고 파괴적 기능은 관리자 승인(HITL) 단계를 연동함.

### 쉽게 이해하기 (학습용)
- 신입 사원이 중요한 회사 문서를 삭제하거나 송금하지 못하도록, 읽기만 가능하게 하거나 부장의 결재를 거치게 설정하는 권한 관리입니다.

## Ⅶ. 결론

- 도구 호출은 언어 모델을 수동적인 지식 조회가 아닌 이기종 시스템을 제어하는 오케스트레이션 엔진으로 확장하는 본질적인 기술 장치이다.
- 향후 안전하고 일관성 있는 도구 관리를 위해 에이전트와 도구 간의 인터페이스 표준 프로토콜인 MCP(Model Context Protocol) 도입을 적극적으로 검토해야 한다.

### 쉽게 이해하기 (학습용)
- 여러 전자제품이 스마트홈 허브에 통일된 규격으로 연결되어야 오류 없이 완벽하게 자율 제어되는 것과 같은 이치입니다.
