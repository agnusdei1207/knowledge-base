# 📖 【암기용】 개념 완전 이해

> 목적: MCP Prompt를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: MCP Server가 제공하는 재사용 가능한 프롬프트 템플릿
- **왜 필요한가**: 업무별 프롬프트를 사용자마다 다르게 쓰면 품질·정책·감사 기준이 흔들림.
- **핵심 직관**: MCP Prompt는 AI 업무 수행을 위한 표준 작업 지시서임.

## 깊이 이해
- **배경·문제의식**: 에이전트가 같은 도구를 쓰더라도 프롬프트가 다르면 결과 형식, 금지사항, 검증 절차가 달라짐.
- **작동 원리**: 서버가 프롬프트 이름, 설명, 입력 변수를 제공하고 Client가 변수 값을 채워 모델 컨텍스트에 넣음.
- **비유**: 회사가 보고서 양식과 작성 지침을 표준화해 작성자마다 결과가 달라지는 폭을 줄이는 방식.
- **구체 예시**: 장애 분석 Prompt가 서비스명, 기간, 로그 Resource를 입력받아 원인-영향-조치 형식으로 답변하게 함.
- **흔한 오해·주의점**: Prompt는 정책을 표현하지만 보안 통제 자체는 아니므로 서버 검증과 출력 필터가 필요함.

## 연결 개념
- Prompt Engineering — 프롬프트 설계 원리
- MCP Resource — Prompt 입력으로 쓰는 데이터
- Guardrail — 출력 형식·금지내용 통제

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: MCP Prompt는 MCP Server가 표준화해 제공하는 변수 기반 프롬프트 템플릿임.
> 2. **가치**: 업무별 지시, 출력 형식, 검증 기준을 중앙관리해 재현성과 감사 가능성을 높임.
> 3. **판단 포인트**: 변수 검증, 버전관리, 정책 반영, 출력 검증을 함께 적용해야 함.

---

## Ⅰ. 개요 및 필요성

- 개요: 서버 관리 프롬프트 자산
- 배경: AI 업무 자동화에서 사용자별 프롬프트 편차와 정책 누락이 발생하면 출력 형식과 통제 기준이 흔들림.
- 필요성: Prompt Template, version, role variable로 재사용 프롬프트의 승인·변경·적용 범위를 관리해야 함.

---

## Ⅱ. 구조 및 구성요소

```text
Prompt Name -> Variables -> Template -> Model Context


     식별        입력값       지시문        실행컨텍스트
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Name/Description | Prompt 식별과 용도 설명 | 업무 분류·버전 포함 |
| Variables | 입력 파라미터 | 타입·필수값 검증 |
| Template | 지시문·출력 형식 | 정책·금지사항 포함 |
| Version | 변경 이력 관리 | 롤백·감사 근거 |

> 요약: MCP Prompt는 이름, 변수, 템플릿, 버전으로 구성된 재사용 프롬프트 자산임.

---

## Ⅲ. 동작원리 및 흐름도

```text
Prompt 조회 -> 변수 입력 -> 입력 검증 -> 템플릿 렌더링
        -> 모델 호출 -> 출력 검증 -> 이력 저장
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | Prompt 선택 | 업무 목적, 버전 |
| 2 | 변수 바인딩 | 타입, 길이, 필수값 |
| 3 | 컨텍스트 생성 | 정책 문구, 출력 형식 |
| 4 | 출력 검증·기록 | schema, 금지어, Trace ID |

> 요약: MCP Prompt는 변수 검증과 버전관리를 통해 프롬프트 실행의 재현성을 확보함.

---

## Ⅳ. 특징

| 구분 | 사용자 임의 프롬프트 | MCP Prompt | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 관리 | 개인별 작성 | 서버 중앙관리 | 버전 수, 재사용률 |
| 품질 | 편차 큼 | 출력 형식 표준화 | schema 통과율 |
| 위험 | 정책 누락 | 정책 내재화 가능 | 위반 탐지 건수 |

> 요약: MCP Prompt는 프롬프트를 운영 자산으로 관리하지만 출력 검증 없이는 정책 준수를 보장하지 못함.

---

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 업무별 Prompt에 버전, 소유자, 승인자, 변경 이력을 기록하고 롤백 절차 적용
2. 변수에는 타입, 길이, enum, 금지 패턴을 두고 사용자 입력은 명령이 아닌 데이터로 처리
3. 출력은 JSON Schema, 근거 링크, 민감정보 필터, 정책 위반 탐지로 검증

**결론 (2줄):**
- 기술사 판단: 반복 업무 Prompt는 MCP Prompt로 중앙관리하고 실험성 Prompt는 격리 환경에서 검증해야 함.
- 향후 방향: MCP Prompt는 PromptOps와 결합해 AI 업무 품질관리 단위로 발전함.
