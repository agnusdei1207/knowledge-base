# 📖 【암기용】 개념 완전 이해

> 목적: 파이프라인 병렬화를 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 인공지능 모델의 여러 층(Layer)을 여러 대의 GPU에 나누어 배치하고, 데이터를 잘게 쪼개어(Micro-batch) 순차적으로 처리하게 함으로써 장비 효율을 높이는 기술
- **왜 필요한가**: 단순히 모델을 층별로 나누면, 한 GPU가 일할 때 다른 GPU는 자기 차례가 올 때까지 놀게 된다(Idle Time). 이를 방지하기 위해 공장 컨베이어 벨트처럼 일을 끊임없이 흘려보내야 하기 때문이다.
- **핵심 직관**: "한 사람이 빨래하고, 다른 사람이 건조하고, 또 다른 사람이 옷을 개는 세탁 공정에서, 한 바구니가 다 끝날 때까지 기다리지 않고 옷 한 벌씩 바로바로 다음 단계로 넘기는 방식"

## 깊이 이해
- **배경·문제의식**: 모델 병렬화 중 '계층 병렬화'는 구현이 쉽지만, 앞 계층의 계산 결과가 나와야 뒤 계층이 시작할 수 있다는 치명적 단점이 있다. 이는 GPU 자원 낭비로 이어진다.
- **작동 원리**:
  1. 전체 학습 데이터를 작은 조각(Micro-batch)으로 나눈다.
  2. 첫 번째 GPU가 첫 번째 조각의 연산을 마치면 즉시 두 번째 GPU로 넘기고, 자신은 바로 두 번째 조각 연산을 시작한다.
  3. 이 과정을 통해 모든 GPU가 동시에 일하는 구간을 극대화한다.
  4. 단, 앞뒤 과정이 겹치지 않는 시작과 끝 부분에는 여전히 노는 시간(Bubble)이 발생하며, 이를 최소화하는 알고리즘(GPipe, PipeDream, 1F1B 등)이 중요하다.
- **비유**: 김밥 100줄을 만들 때, 1번이 밥만 다 펴고 2번에게 넘기는 게 아니라, 1번이 밥 한 줄 펴면 바로 2번이 속 재료를 넣기 시작하는 것과 같다.
- **구체 예시**: GPipe는 마이크로배치를 통해 효율을 높였고, PipeDream은 역전파(Backward)를 더 일찍 시작해 메모리 효율까지 챙겼다.
- **흔한 오해·주의점**: "마이크로배치를 아주 작게 나누면 무조건 좋다"는 틀렸다. 너무 작게 나누면 연산 효율(Utilization)이 떨어지고 통신 횟수만 늘어난다. 연산 성능과 병렬 효율 사이의 적절한 지점(Sweet Spot)을 찾는 것이 실력이다.

## 연결 개념
- Micro-batch — 파이프라인 효율의 핵심 단위
- Pipeline Bubble — 파이프라인에서 발생하는 유휴 자원 낭비 구간
- 1F1B (One Forward One Backward) — 유휴 시간을 줄이기 위한 대표적 스케줄링 알고리즘

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 파이프라인 병렬화는 버블(Bubble) 발생 원인과 이를 최소화하기 위한 마이크로배치 스케줄링을 중심으로 기술한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 파이프라인 병렬화(Pipeline Parallelism)는 모델의 계층(Layer)을 여러 장치에 분산하고, 데이터를 마이크로배치 단위로 처리하여 연산의 중첩(Overlap)을 유도하는 기법이다.
> 2. **가치**: 모델 병렬화의 고질적 문제인 장치 유휴 시간(Idle Time)을 최소화하여 대규모 클러스터의 MFU(Model Flops Utilization)를 향상시킨다.
> 3. **판단 포인트**: 버블 비율(Bubble Ratio)을 줄이기 위해 마이크로배치 수(m)와 파이프라인 단계 수(p) 간의 최적 조합을 설계해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 계층 간 병렬화 효율성 개선 이해도 | Micro-batch, Pipeline Bubble, Throughput 향상 | 단순히 "층별로 나눈다"고만 서술 |
| 스케줄링 알고리즘 비교 역량 | GPipe (Flush 기반) vs 1F1B (Interleaved) | 알고리즘별 버블 발생 차이 누락 |
| 메모리 및 통신 부하 분석 능력 | 활성화 값(Activation) 저장 비용, 스테이지 간 통신 | 통신 오버헤드 무시 및 무조건적 가속 단정 |

> 요약: 마이크로배치를 통한 연산 중첩 원리와 버블 제어 메커니즘을 중심으로 답안을 구성한다.

---

## Ⅰ. 개요 및 필요성

- 정의: 신경망의 층을 여러 GPU로 분할(Partitioning)하고, 데이터를 마이크로배치로 나누어 선형 파이프라인 형태로 병렬 연산하는 기법
- 배경: 단순 계층 병렬화 시 발생하는 심각한 장치 유휴(Sequential Bottleneck) 문제 해결 필요
- 필요성: 거대 모델 학습 시 GPU 자원 활용률(Utilization) 극대화 및 전체 학습 시간(Time-to-Train) 단축

---

## Ⅱ. 구조 및 구성요소

```text
[파이프라인 병렬화 동작 도식: 4개 GPU, 4개 마이크로배치]
Time --->
GPU 0: [F1][F2][F3][F4]                [B4][B3][B2][B1]
GPU 1:     [F1][F2][F3][F4]        [B4][B3][B2][B1]
GPU 2:         [F1][F2][F3][F4][B4][B3][B2][B1]
GPU 3:             [F1][F2][F3][F4][B4][B3][B2][B1]
       |<- Bubble ->|                      |<- Bubble ->|
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Pipeline Stage | 모델의 특정 계층 그룹을 담당하는 물리 장치 | 보통 노드 간 경계로 설정 |
| Micro-batch | 전체 배치를 잘게 쪼갠 연산 단위 | 작을수록 버블 감소, 연산 효율 저하 |
| Bubble | 연산 중첩이 일어나지 않는 유휴 구간 | 공식: (p-1) * (Forward + Backward) |
| Communication Link | 스테이지 간 중간 결과(Activation) 전송 | 주로 P2P(Point-to-Point) 통신 |

> 요약: 모델 층을 나눈 장치(Stage)들이 마이크로배치 데이터를 릴레이 방식으로 주고받으며 동시에 일하는 구조다.

---

## Ⅲ. 동작원리 및 흐름도

```text
[1F1B (One Forward, One Backward) 알고리즘 흐름]
1. Warm-up: 파이프라인을 채우기 위해 순전파(Forward)만 연속 실행
2. Steady-state: 순전파 하나 완료 후 즉시 역전파(Backward) 하나 실행 (중첩)
3. Cool-down: 남은 역전파들 순차 완료
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 입력 배치를 M개의 마이크로배치로 분할 | GPU 메모리 여유 공간 확인 |
| 2 | Stage 0부터 순차적으로 마이크로배치 Forward 수행 | 스테이지 간 데이터 전송 지연 최소화 |
| 3 | 마지막 Stage 도달 시 즉시 Backward 시작 및 결과 회신 | 1F1B 스케줄링으로 메모리 점유 최적화 |
| 4 | 모든 마이크로배치 완료 후 가중치 업데이트(Sync) | 파이프라인 플러시(Flush) 발생 여부 |

> 요약: 파이프라인을 빠르게 채운 뒤(Warm-up), 앞뒤 연산을 교차 실행하여(1F1B) 유휴 시간을 줄이고 메모리를 아끼는 방식이다.

---

## Ⅳ. 특징

| 구분 | GPipe (기본형) | 1F1B (개선형) |
|:---|:---|:---|
| 스케줄링 | 모든 Forward 후 모든 Backward | 하나씩 교차 실행 (Steady-state) |
| 메모리 부하 | 매우 높음 (모든 활성화값 저장) | 상대적 낮음 (필요한 것만 유지) |
| 버블 비율 | 동일함 | 동일함 (버블 크기는 구조적 요인) |
| 구현 복잡도 | 낮음 | 높음 (정교한 큐 제어 필요) |

> 요약: 1F1B는 버블 크기는 GPipe와 같으나, 메모리 점유를 획기적으로 줄여 더 큰 모델 학습이 가능하다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 텐서 병렬화 (Tensor) | 파이프라인 병렬화 (Pipeline) | 선택 기준 |
|:---|:---|:---|:---|
| 통신 단위 | 계층 내 행렬 연산 (Intra-layer) | 계층 간 데이터 전달 (Inter-layer) | 하드웨어 토폴로지 (노드 내/간) |
| 통신량 | 매우 큼 (Weight 크기에 비례) | 상대적 작음 (Activation 크기) | 네트워크 대역폭 가용량 |
| 메모리 절감 | 가중치 샤딩으로 절감 | 스테이지당 가중치만 보유 | GPU 메모리 용량 부족 정도 |

> 요약: 노드 내 고속 연결은 텐서 병렬화, 노드 간 일반 연결은 파이프라인 병렬화가 효율적이다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| Bubble 오버헤드 | 파이프라인 깊이(p) 대비 적은 데이터(m) | 마이크로배치 수 증가 (m >> p) | Bubble Overhead Ratio |
| 로드 불균형 | 층별 연산 시간 불일치로 병목 발생 | 프로파일링 기반 층 재배치 (Balancing) | GPU Idle Time per Stage |
| 메모리 단편화 | 잦은 마이크로배치 할당/해제 | 메모리 풀링 및 전용 메모리 관리자 사용 | Out-of-Memory (OOM) 발생 빈도 |

> 요약: 버블 리스크는 데이터 분할 최적화로, 로드 불균형은 정교한 모델 파티셔닝으로 관리한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| MFU 향상 | 단순 병렬화 대비 20% 이상 향상 | 실제 처리 속도(Tokens/sec) 비교 |
| 버블 비율 | 전체 연산 시간의 10% 이하 | 공식: (p-1)/m 분석 및 프로파일링 |
| 통신 지연 | 스테이지 간 전송 10ms 이내 | P2P Latency Monitoring |

> 요약: MFU와 버블 비율 지표를 통해 파이프라인 병렬화의 도입 성공 여부를 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. Interleaved Pipeline 적용: 하나의 GPU가 여러 개의 불연속적인 계층 덩어리를 맡게 하여 버블 비율을 추가로 25% 이상 감축
2. FP16/BF16 혼합 정밀도 적용: 스테이지 간 전송 데이터(Activation) 크기를 절반으로 줄여 통신 병목 해결
3. 라이브러리 활용: DeepSpeed 또는 Megatron-LM의 검증된 파이프라인 엔진을 사용하여 커스텀 스케줄링 구현 오버헤드 제거

**결론 (2줄):**
- 기술사 판단: 파이프라인 병렬화는 거대 모델 학습의 필수 요소이나, 버블로 인한 효율 저하를 막기 위한 '연산-통신-메모리'의 정교한 삼각 균형 설계가 핵심이다
- 향후 방향: 정적 분할을 넘어 워크로드에 따라 실시간으로 층 배치를 최적화하는 동적 파이프라인(Dynamic Pipeline) 기술이 주목받을 것이다
