## 미리 알고가기

- 4비트 양자화는 INT8보다 더 작은 정밀도로 모델을 압축해 메모리 절감 효과를 크게 높이는 방식임
- 로컬 LLM, 온디바이스 AI, 저가형 GPU 배포에서 특히 중요함
- 품질 손실을 줄이기 위해 GPTQ, AWQ 같은 보정 기법이 함께 사용되는 경우가 많음

## Ⅰ. 개요

- **정의/개념**: 4비트 양자화는 모델 파라미터를 4비트 수준으로 압축해 FP16 대비 메모리 점유를 대폭 줄이고 제한된 장비에서도 대형 모델을 실행 가능하게 만드는 초경량화 기법임
- **배경/필요성**: 로컬 PC와 모바일과 엣지 장비는 VRAM과 RAM이 제한적이므로, INT8보다 더 강한 압축 없이는 대형 생성형 모델을 배치하기 어려움

## Ⅱ. 특징

- 메모리 절감 폭이 커서 동일 장비에서 더 큰 모델을 올리거나 동시 요청 수를 늘릴 수 있음
- 품질 손실 가능성이 INT8보다 높아 레이어별 민감도와 outlier 보정이 중요함
- 저가형 GPU와 개인용 장비에서 생성형 모델을 실행 가능하게 만드는 핵심 수단임
- 런타임과 커널이 4비트 형식을 잘 지원해야만 체감 성능 향상이 보장됨

## Ⅲ. 종류 및 비교

| 판단 기준 | FP16 | INT8 | 4-bit |
|:---|:---|:---|:---|
| 메모리 사용 | 높음 | 중간 | 매우 낮음 |
| 품질 안정성 | 매우 높음 | 높음 | 중간 이하 |
| 대표 환경 | 기준 서버 | 상용 서버 | 로컬, 엣지, 비용 민감 환경 |
| 보정 필요성 | 낮음 | 중간 | 높음 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Low-bit Weight Format | 가중치를 4비트 표현으로 저장해 큰 메모리 절감 효과를 만듦 |
| Group-wise Scaling | 작은 그룹 단위로 스케일을 나눠 정밀도 손실을 줄임 |
| Outlier Preservation | 민감한 채널이나 중요 가중치를 별도 보존해 품질 저하를 완화함 |
| Specialized Runtime | GPTQ, AWQ, GGUF 같은 형식을 해석하는 런타임이 실제 추론 실행을 담당함 |

```text
+-------------------+      +-------------------+      +-------------------+
| Group-wise Scale  | ---> | Low-bit Format    | ---> | Specialized RT    |
+-------------------+      +-------------------+      +-------------------+
         |
         v
+-------------------+
| Outlier Preserve  |
+-------------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 민감도 분석    | --> | 그룹별 스케일링  | --> | 4비트 변환     | --> | 전용 런타임 추론 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **민감도 분석**: 어떤 레이어와 채널이 저정밀화에 취약한지 먼저 파악함
2. **그룹별 스케일링**: 작은 블록 단위로 스케일을 적용해 양자화 오차를 줄임
3. **4비트 변환**: 핵심 보호 전략과 함께 가중치를 저정밀 형식으로 변환함
4. **전용 런타임 추론**: 4비트 형식을 지원하는 엔진에서 실제 추론을 수행함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 비트 폭이 너무 작아지면 일부 레이어의 표현력이 급격히 줄어 장문 추론이나 코딩 품질이 쉽게 흔들릴 수 있음
   - 해결방안: 민감 레이어는 higher precision을 유지하고 benchmark별 exact match와 long-context quality로 손실 범위를 검증함
2. 문제: 4비트 형식은 런타임과 커널 지원 편차가 커서 파일은 작아도 실행 경로가 불안정할 수 있음
   - 해결방안: 목표 장비별 호환 런타임을 표준화하고 load success rate와 tokens/sec로 배포 적합성을 검증함
3. 문제: calibration 데이터가 협소하면 특정 도메인 입력에서 양자화 오차가 과도하게 누적될 수 있음
   - 해결방안: 운영 도메인 샘플을 포함한 보정셋을 유지하고 domain accuracy와 failure case density로 품질을 검증함

## Ⅶ. 적용 사례

- 로컬 LLM 데스크톱이 24GB 이하 GPU에 대형 모델을 탑재하도록 4비트 양자화를 적용하며 확인 지표는 VRAM usage와 tokens/sec임
- 온디바이스 보조 기능이 소형 모델을 모바일 기기에 배치하도록 4비트 양자화를 사용하며 확인 지표는 memory footprint와 battery impact임
- 비용 절감형 사내 챗봇이 중저가 서버에서 추론을 운영하도록 4비트 양자화를 적용하며 확인 지표는 cost per token과 answer quality임

## Ⅷ. 결론

4비트 양자화는 제한된 장비에서 생성형 모델을 돌리기 위한 가장 강력한 경량화 수단이지만, 품질 손실과 런타임 호환성을 함께 다루는 정교한 보정 전략이 전제되어야 함.
