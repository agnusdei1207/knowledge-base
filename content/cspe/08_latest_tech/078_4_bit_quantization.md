## 미리 알고가기

- $4$-bit 양자화: 가중치 파라미터당 실수 표현 크기를 단 $4$-bit(0~15 정수 범위) 수준으로 압축해, 오리지널 $FP16$ 대비 물리 용량을 정확히 $75\%$ 절감하는 극강의 경량 가속 기술임
- 가중치 전용 양자화 ($W4A16$): 가중치는 VRAM 절감을 위해 $4$-bit 정수로 저장하고, 활성값($Activation$)은 연산 오차 방지를 위해 $16$-bit 실수로 전송해 디코딩 시에만 임시 역양자화 연산하는 방식임
- 그룹 단위 스케일링 ($Group-wise$ $Scaling$): 통째로 양자화하지 않고, 가중치 채널을 보통 $128$개 단위 그룹으로 쪼개 각각의 로컬 스케일을 부여하여 압축 정확도 유실을 보정하는 설계임
- $GGUF$ ($GPT-Generated$ $Unified$ $Format$): CPU 및 단일 소비자용 GPU 환경에서 고속 4비트 양자화 모델을 즉시 호출 실행할 수 있도록 라마닷cpp($llama.cpp$) 계열에서 제정한 통합 파일 포맷임

## Ⅰ. 개요

- **정의/개념**: 4-bit Quantization은 대형 모델 가중치 정밀도를 4비트 해상도 수준으로 극도로 압축해 VRAM 용량 요구도를 원래 크기의 $25\%$ 수준으로 폭락시킴으로써, 대형 LLM을 중저가형 싱글 GPU나 온디바이스 에지 환경에 격리 안착시키는 초경량 모델 압축 기술임
- **배경/필요성**: 기존 $INT8$ 양자화 수준만으로는 일반 노트북이나 모바일의 제한된 시스템 메모리(RAM) 벽에 부딪혀 수십억 파라미터급 LLM 탑재가 원천 불가능하였으므로, 메모리 경계선을 인위적으로 무너뜨려 개인화 로컬 조력을 실현하기 위해 탄생함

## Ⅱ. 특징

- 가중치를 $4$비트 정수로 감축 저장하되 연산 성능 붕괴를 막기 위해, 채널 방향으로 $32$ 또는 $128$개의 텐서를 그룹으로 묶어 가중치를 부분 스케일링함
- 가중치 자체는 극도로 가볍게 보관($W4$)하고, 행렬 곱 연산 순간에만 전용 C++ 커널을 작동시켜 $FP16$ 실수로 역양자화($A16$)하는 구조로 실무에 쓰임
- 온디바이스 전용 기동 라이브러리인 라마닷cpp($llama.cpp$, $GGUF$) 생태계와 완벽히 결합되어 있으며 개인 로컬 PC에서 상시 기동을 담당함

## Ⅲ. 종류 및 비교

| 판단 기준 | 기본 오리지널 모델 ($FP16$ 유지) | $INT8$ 양자화 | $4\text{-bit}$ 양자화 ($W4A16$) |
|:---|:---|:---|:---|
| **VRAM 절감율** | 0% (기준선) | 약 50% 절감 (안정성 양호) | 약 75% 절감 (경량 극대화) |
| **추론 정밀도 복원** | 100% (오리지널 품질) | 매우 높음 (손실 거의 인지 불가능) | 보통 (특정 문맥 복잡도 및 CoT 추론서 오차 발생 우려) |
| **추론 순간 병목** | 메모리 대역폭 포화 극심 | HBM 메모리 대역폭 단축 | I/O 포화는 소거되나 GPU 실시간 역양자화 계산 비용 수반 |
| **역양자화 커널** | 불필요함 | 불필요함 (정수 가속 칩 가동) | 필수 (매 디코드 스텝마다 4비트를 FP16으로 핫스왑) |

> 요약: FP16은 거대 연산 서버에, INT8은 엔터프라이즈 상용 API 무결성에, 4-bit 양자화는 에지 단말의 개인화 온디바이스 배포에 최적임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 4비트 가중치 행렬 | FP16 실수 값을 0에서 15 이내의 정수 또는 특정 수치 부호로 압축 포장한 초경량 텐서임 |
| 그룹 스케일 레지스터 | 채널 묶음($Group$ $Size=128$)별로 할당된 가변 로컬 스케일 팩터 배열임 |
| 역양자화 온칩 커널 | GPU 레지스터 영역 안에서 4비트 메모리를 실시간 부동소수로 전환 복원해 주는 C++ 가속 커널임 |
| $GGUF$ 컨테이너 | CPU 전용의 메모리 맵 매핑($mmap$) 로딩과 이종 연산 엔진 기동을 돕는 통합 파일 스택임 |

```text
[ 4-bit Quantization (W4A16) 디코딩 흐름 ]
[ VRAM / RAM ] -------------------------------> [ GPU SRAM Register ]
   가중치 (4-bit 정수)                            1. 4-bit 가중치를 스케일팩터와 곱해 FP16으로 역양자화
   활성값 (16-bit 실수)                           2. 인입된 활성값(FP16)과 즉시 병렬 행렬 곱셈 수행
- HBM(VRAM)에서 읽는 크기를 75% 줄여 병목을 극복하고, 대신 내부 연산력으로 역양자화를 해소함
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 오리지널    | --> | 채널 그룹분할| --> | 4비트 사상  | --> | 실시간 역양 |
| 모델 로딩   |     | (Group Size) |     | 및 마스킹   |     | 자화 가속추론|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **채널 세분화** — 가중치 행렬의 급격한 정밀도 저하를 완화하기 위해, 전체 가중치를 $128$개 토큰 크기의 소그룹으로 바둑판식 분할함
2. **그룹 양자화** — 각 소그룹 내의 최소/최대 분포를 기준으로 삼아, 가중치 값들을 $4$비트 한계 정수값($0 \sim 15$)으로 캘리브레이션함
3. **바이너리 빌드** — 패키징을 통해 오리지널의 $75\%$ 무게를 뺀 초경량 `.gguf` 혹은 `.safetensors` 양자화 아티팩트 파일을 출력함
4. **핫스왑 서빙** — 런타임 기동 시, VRAM 대역폭 포화 없이 가중치를 메모리에 적재하고, 매 디코드 사이클마다 $FP16$ 복원 연산을 고속 회전함

## Ⅵ. 실무 적용 및 유의점

1. 4비트 양자화 시 모델 전반의 수학적 해상도가 크게 떨어져 장문 분석이나 다단계 추론(CoT) 등의 정확도가 급락할 수 있으므로, 반드시 '주의 레이어(Attention Layers)' 등 민감 부위만 $16$-bit로 보존하는 혼합 양자화를 적용하고, 최종 비즈니스 정확도 보존율 지표로 합격 여부를 판정해야 함
2. 4비트 가중치를 디코딩 시 매번 $FP16$으로 고속 실시간 복원해야 하므로 GPU의 연산 장치 소모가 커지므로, 호환 런타임과 커널 라이브러리(AWQ, GPTQ 등) 성능 편차를 사전 벤치마크하고 단위 시간당 실효 토큰 처리 속도($Tokens/Sec$)를 계측해야 함

## Ⅶ. 결론

- 4-bit 양자화는 하드웨어 인프라의 경제적 한계선을 넘어 1인 1AI 온디바이스 시대를 개척하는 획기적인 경량화의 돌파구이며, 설계자는 저비트 압축에 따른 수학적 추론력 붕괴를 극복하기 위해 그룹별 정밀도 세분화 전략과 실측 역양자화 연산 오버헤드 감사를 철저히 결합해야 함
