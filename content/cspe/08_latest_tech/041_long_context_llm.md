# 📖 【암기용】 개념 완전 이해

> 목적: 장문맥 LLM을 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: 입력 컨텍스트 윈도우를 수십만~수백만 토큰으로 확장한 LLM
- **왜 필요한가**: 기존 4K~8K 윈도우로는 장편 문서·코드베이스·다중 회의록을 한 번에 처리할 수 없음.
- **핵심 직관**: 책 한 권을 통째로 읽고 질문에 답하는 모델임.

## 깊이 이해
- **배경·문제의식**: GPT-3는 2K 토큰, GPT-4 초기 8K~32K 제한. 법률 계약서(평균 50K 토큰), 코드 리포(수백K 토큰)는 청킹·요약 없이 처리 불가였음.
- **작동 원리**: Self-Attention은 시퀀스 길이 N에 대해 O(N²) 메모리·연산이 필요. RoPE 주파수 조정(YaRN), Ring Attention(시퀀스를 GPU간 분할), Sparse Attention(전체 대신 로컬+글로벌 패턴)으로 O(N²) 병목을 완화함.
- **비유**: 기존 LLM은 A4 한 장만 볼 수 있는 책상이고, Long Context LLM은 책상을 넓혀 책 전체를 펼쳐놓는 것임.
- **구체 예시**: Gemini 1.5 Pro 1M 토큰, Claude 3.5 200K 토큰, GPT-4o 128K 토큰 지원.
- **흔한 오해·주의점**: 윈도우가 넓어도 중간 위치 정보는 검색 정확도가 떨어지는 "Lost in the Middle" 현상이 발생함.

## 연결 개념
- Context Window — 장문맥의 기반 개념
- RoPE·YaRN — 위치 인코딩 확장 기법
- RAG — 장문맥 대안 또는 보완 전략


# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Long Context LLM은 컨텍스트 윈도우를 128K~1M+ 토큰으로 확장하여 청킹 없이 대규모 입력을 처리하는 모델임.
> 2. **가치**: 문서 전체 맥락을 유지한 QA·요약·코드 분석이 가능해져 RAG 파이프라인 복잡도를 감소시킴.
> 3. **판단 포인트**: 윈도우 확장에 따른 추론 비용 O(N²)·Lost in the Middle·KV 캐시 메모리를 함께 설계해야 함.


## Ⅰ. 개요 및 필요성

- 개요: 수십만 토큰 입력 처리 모델
- 배경: 법률·의료·코드 도메인에서는 문서 전체 맥락이 필요하지만 4K~32K 윈도우는 근거 누락이 발생함.
- 필요성: RoPE scaling, sparse attention, KV cache 관리로 장문 입력의 정확도·비용·지연 기준을 함께 평가해야 함.


## Ⅱ. 구조 및 구성요소

```text
입력(N tokens) -> Tokenizer -> Extended Positional Encoding
        Sparse Attention      Ring Attention        KV Cache 관리
                              LLM Decoder -> 출력
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Extended PE (YaRN/ALiBi) | 긴 시퀀스에서 위치 정보 유지 | RoPE 주파수 보간·외삽 |
| Sparse Attention | 전체 O(N²) -> 로컬+글로벌 O(N√N) | Longformer·BigBird 패턴 |
| Ring Attention | 시퀀스를 GPU 간 분할 처리 | 디바이스 간 KV 순환 전달 |
| KV Cache 관리 | 추론 시 메모리 제어 | 양자화·페이지드 어텐션(vLLM) |

> 요약: 위치 인코딩 확장·어텐션 효율화·KV 캐시 관리 세 축이 장문맥을 가능하게 함.


## Ⅲ. 동작원리 및 흐름도

```text
입력 토큰화 -> PE 확장(YaRN) -> Sparse/Ring Attention 연산
    -> KV Cache 저장 -> 디코딩 -> 출력 생성
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 토큰화 + 위치 인코딩 확장 | 시퀀스 길이 128K~1M 대응 여부 |
| 2 | Sparse/Ring Attention 연산 | 메모리 사용량, GPU당 시퀀스 분할 수 |
| 3 | KV Cache 관리·양자화 | KV 캐시 크기(GB), INT8 양자화율 |
| 4 | 디코딩·출력 생성 | Needle-in-a-Haystack 검색 정확도 |

> 요약: PE 확장으로 위치 커버리지 확보 후, 어텐션 효율화와 KV 캐시 최적화로 추론 비용을 통제함.


## Ⅳ. 특징

| 구분 | 기존 LLM (4K~32K) | Long Context LLM (128K~1M) | 판단 포인트 |
|:---|:---|:---|:---|
| 입력 한계 | 청킹·요약 필수 | 문서 전체 입력 | Needle 검색 정확도 93%+ |
| 추론 비용 | 토큰당 $0.01 | 토큰당 $0.03~0.07 | 비용 대비 정확도 ROI |
| 중간 위치 정확도 | 해당 없음 | Lost in the Middle 발생 | 프롬프트 배치 전략 필요 |

> 요약: 장문맥은 정확도를 높이나 비용·중간위치 정확도 저하를 함께 관리해야 함.


## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 법률·의료 문서 QA에 128K+ 모델 적용, Needle-in-a-Haystack 정확도 95% 이상 검증 후 배포
2. KV 캐시를 vLLM PagedAttention + INT8 양자화로 관리, GPU 메모리 사용량 40% 절감
3. 핵심 정보를 프롬프트 앞·뒤에 배치하는 Lost in the Middle 대응 전략 적용

**결론 (2줄):**
- 기술사 판단: 단일 문서 50K 토큰 이하면 RAG, 전문 맥락 필수면 Long Context 모델 선택
- 향후 방향: 10M+ 토큰 윈도우와 선형 복잡도 어텐션(Mamba·RWKV)으로 수렴 전망
