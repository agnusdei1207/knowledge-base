## 미리 알고가기

- Long Context LLM은 일반 LLM보다 훨씬 긴 토큰 범위를 안정적으로 처리하도록 확장된 모델 계열임
- RoPE scaling, position interpolation, optimized attention kernel은 장문맥 구현의 대표 기술임
- NIAH 평가는 긴 문맥 중 특정 정보 회수 능력을 확인하는 대표 벤치마크임

## Ⅰ. 개요

- **정의/개념**: Long Context LLM은 수십만에서 수백만 토큰 수준의 문맥을 한 번의 추론에 담아 다문서 교차 참조와 장거리 reasoning을 수행하도록 확장된 언어모델 계열임
- **배경/필요성**: 기존 LLM은 문서를 쪼개 넣어야 했기 때문에 문맥 단절과 검색 누락이 잦았으므로, 코드베이스 전체 분석이나 장문 계약 비교처럼 전체 맥락이 중요한 업무를 위해 장문맥 처리 능력이 필요함

## Ⅱ. 특징

- 위치 인코딩 확장과 attention 최적화와 cache 관리가 결합되어야 실질적 장문맥 성능이 나옴
- 전체 문서를 한 번에 보게 해 교차 참조와 전역 구조 파악에 유리함
- 단순 context window 수치와 실제 중간 정보 회수 성능은 다를 수 있어 평가 기준이 별도 필요함
- RAG를 완전히 대체하기보다 고비용 고정확도 경로로 배치되는 경우가 많음

## Ⅲ. 종류 및 비교

| 판단 기준 | 일반 LLM | Long Context LLM | RAG 파이프라인 |
|:---|:---|:---|:---|
| 직접 참조 범위 | 제한적임 | 매우 넓음 | 검색된 일부만 참조 |
| 전역 구조 파악 | 약함 | 강함 | 검색 품질에 의존 |
| 지연, 비용 | 낮음 | 높음 | 중간 |
| 적합 업무 | 짧은 대화, 요약 | 다문서 비교, 코드베이스 분석 | 기업 지식 질의응답 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Extended Position Encoding | 학습 길이보다 긴 문맥에서도 위치 왜곡을 줄이도록 위치 표현을 확장하는 핵심 계층임 |
| Long-context Attention Kernel | 긴 시퀀스를 처리할 수 있도록 메모리 접근과 병렬 계산을 최적화한 연산 커널임 |
| Memory, Cache Manager | 긴 입력의 KV cache와 prompt caching을 관리해 추론 지연과 비용을 통제함 |
| Evaluation Layer | NIAH, retrieval accuracy, faithfulness 같은 지표로 실제 장문맥 활용 가능성을 검증하는 계층임 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +----------------+     +------------------+     +-----------+
| 대용량 입력 정리 | --> | 위치/커널 확장   | --> | 장문맥 Attention  | --> | 결과 검증  |
+-------------+     +----------------+     +------------------+     +-----------+
```

1. **대용량 입력 정리**: 문서 순서와 우선순위를 정렬해 긴 입력을 모델이 읽을 수 있는 형태로 묶음
2. **위치, 커널 확장**: 긴 문맥에서도 위치 해석이 가능하도록 위치 인코딩과 attention 커널을 확장함
3. **장문맥 Attention 수행**: 여러 문서나 긴 코드 흐름을 한 번에 참조해 전역 관계를 계산함
4. **결과 검증**: 응답이 실제 문서 중간의 근거를 회수했는지와 비용이 감당 가능한지 평가함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 문맥 길이만 커지고 중간 구간 정보 회수 성능이 떨어지면 실제 업무에서는 긴 입력을 넣어도 정확도가 기대만큼 오르지 않음
   - 해결방안: NIAH와 middle-context retrieval 평가를 필수화하고 구간별 recall과 groundedness로 성능을 검증함
2. 문제: 초장문 입력은 TTFT와 비용을 크게 늘려 실시간 서비스나 반복 질의에서 운영성이 급격히 나빠질 수 있음
   - 해결방안: prompt caching과 계층형 라우팅을 적용하고 요청당 비용과 TTFT로 운영 적합성을 검증함
3. 문제: 마케팅상 최대 컨텍스트 수치가 커도 실제 업무는 검색 기반 파이프라인보다 비효율적일 수 있음
   - 해결방안: RAG와 long context를 업무 유형별로 분기하고 task accuracy 대비 cost efficiency로 선택 기준을 검증함

## Ⅶ. 적용 사례

- 코드베이스 전체 분석: 다수 파일 관계를 한 번에 읽고 의존성 오류를 찾음, 확인 지표는 bug localization accuracy와 TTFT임
- 다문서 계약 검토: 여러 계약서를 동시에 비교해 상충 조항을 탐지함, 확인 지표는 clause recall과 review time임
- 장기 회의록 분석: 수십 회의 기록에서 의사결정 흐름을 추적함, 확인 지표는 summary consistency와 evidence recall임

## Ⅷ. 결론

Long Context LLM은 전체 맥락을 한 번에 보는 능력 자체보다 그 긴 문맥에서 필요한 근거를 실제로 회수하면서도 비용을 통제할 수 있는지가 핵심 경쟁력임.
