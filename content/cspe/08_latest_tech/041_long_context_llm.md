## 미리 알고가기

- 장문맥 $LLM$ ($Long$ $Context$): 기존의 수천 토큰 수준의 한계를 넘어 수십만에서 수백만 토큰 범위의 단기 기억을 다루는 언어 모델 계열임
- $NIAH$ ($Needle-in-a-Haystack$): 거대한 텍스트 더미(건초더미) 속에 임의의 짧은 사실(바늘)을 숨겨두고, 모델이 이를 정확히 찾아내는지 측정하는 장문맥 성능 검증 벤치마크임
- 윈도우 어텐션 ($Window$ $Attention$): 모든 토큰을 서로 비교하는 대신, 현재 단어 기준 일정 윈도우 범위 내의 인접 토큰들만 참조하여 연산 복잡도를 낮추는 기법임
- 위치 외삽법 ($Extrapolation$): 학습 시 보지 못했던 훨씬 더 긴 시퀀스의 위치 인덱스를 수학적으로 추정하여 연산하는 기법임

## Ⅰ. 개요

- **정의/개념**: Long Context LLM은 대용량 파일 분석이나 장기 대화 등 전반적인 문장 맥락을 한 번에 소화하기 위해, 위치 인코딩 외삽과 선형 어텐션 최적화를 적용하여 동시 참조 가능한 토큰 수치를 수만~수백만 개 규모로 극대화한 대형 언어 모델 계열임
- **배경/필요성**: 기존에는 긴 문서를 청킹으로 조각내어 외부 DB에 저장하는 $RAG$ 방식에 의존했으나, 여러 문서 간의 입체적인 교차 분석이나 프로그램 전체 소스코드의 유기적 의존성을 파악하는 데 한계가 있어 한 번에 모든 정보를 주입할 모델이 필요해짐

## Ⅱ. 특징

- 분할과 검색 단계 없이 책 여러 권 분량의 지식을 모델의 주의 집중력 영역에 즉시 적재하여, 정보 누락 없는 매끄러운 상황 파악 및 전역적 종합 추론을 가능하게 함
- 단순 윈도우 크기의 확대에 비례해 발생하던 어텐션 연산량의 기하급수적 병목을 해결하기 위해, 회전 위치 임베딩 보간과 분산 어텐션 커널 가속 등을 필수 결합함
- 텍스트 전체를 하나의 완성된 데이터 텐서로 주입하므로, 검색 기반 모델에서 일어나는 파편화된 컨텍스트 조립 리스크가 발생하지 않음

## Ⅲ. 종류 및 비교

| 판단 기준 | 전통적 단기 모델 | 장문맥 모델 (Long Context LLM) | 검색 증강 생성 ($RAG$) |
|:---|:---|:---|:---|
| **정보 융합 방식** | 문맥 내에서만 상호 작용함 | 수백만 토큰이 일괄 상호 어텐션함 | 검색된 지식 조각들을 이어 붙임 |
| **의존성 파악** | 제한적임 | 문서 전체의 전역적 의존성 포착 가능 | 부분 조각 간의 관계 유실 위험 있음 |
| **서빙 메모리 비용** | 저렴함 | 극도로 비쌈 (엄청난 크기의 KV 캐시) | 비교적 경제적이고 제어 가능함 |
| **적합한 과제** | 가벼운 상호 작용, 단답 요약 | 소스코드 리팩터링, 소송 서류 비교 | 실시간 뉴스 결합 질의, 위키피디아 QA |

> 요약: 단기 모델은 경제성에, 장문맥 모델은 완전무결한 문맥 이해에, RAG는 대규모 실시간 지식 업데이트에 각각 장점이 있음.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 외삽 포지셔널 필터 | RoPE의 기하학적 주파수를 변형 및 보간하여, 미학습된 장거리 토큰의 위치 순서를 복원하는 모듈임 |
| 커널 융합 어텐션 | 하드웨어 입출력($I/O$) 병목을 제거하여 수백만 단어를 메모리 붕괴 없이 고속 계산하는 어텐션 가속 엔진임 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 장문 텍스트  | --> | 위치 주파수  | --> | 메모리 최적  | --> | 전역 맥락추론|
| 임베딩 주입  |     | 보간 및 외삽 |     | 어텐션 가동 |     | 및 결과검증 |
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **지식 집적** — 사용자가 제공한 대용량 소스코드 파일이나 논문 다발을 토큰화하고, 모델의 거대 임베딩 차원에 입력값으로 전격 주입함
2. **좌표 스케일링** — 학습 한계를 초과하는 인덱스를 감당하도록 회전 주파수를 낮추거나 선형 보간($Position$ $Interpolation$)하여 단어들의 간격을 좁혀 줌
3. **병렬 가속 계산** — $O(N^2)$의 램 점유율 폭발을 차단하도록 고안된 FlashAttention 연산을 실행하여, 문장 내 모든 단어 간의 실시간 연관 가중치를 연산함
4. **바늘 검색 검증** — 완성된 문맥 출력이 실제로 텍스트 더미 깊숙이 묻혀 있던 핵심 조건(바늘)을 놓치지 않고 회수했는지 $NIAH$ 스코어를 통해 판정함

## Ⅵ. 실무 적용 및 유의점

1. 컨텍스트 크기가 100K 이상으로 늘어날수록 GPU 장비의 메모리(VRAM) 부족 현상이 급격히 나타나 추론 비용이 폭증하므로, 반드시 '프롬프트 캐싱'과 'GQA(그룹화 쿼리 어텐션)' 기법을 결합하여 가동하고, 요청 건당 토큰 사용량과 추론 비용 대비 성능 개선율 지표로 타당성을 검증해야 함
2. 장문맥 모델이 RAG 파이프라인을 완전히 대체할 수는 없으며, 특히 실시간으로 수시로 바뀌는 외부 정보(예: 현재 주가, 오늘 뉴스 등)는 장문맥 모델로도 반영할 수 없으므로 실시간 지식 수용이 필요할 때는 $RAG$를, 정적인 장문 문서의 심층적 분석에는 $Long$ $Context$를 선택하는 라우팅 아키텍처를 구성해야 함

## Ⅶ. 결론

- Long Context LLM은 기계가 문맥을 잃어버리는 단기 기억의 한계를 해방한 혁신 모델이며, 설계자는 무작정 다량의 데이터를 주입하여 발생하는 추론 병목과 비용 문제를 통제하기 위해 캐싱 최적화와 용도별 라우팅 장치를 동반 구축해야 함
