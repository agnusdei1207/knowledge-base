# 📖 【암기용】 개념 완전 이해

> 목적: Indirect Prompt Injection을 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **정의**: 웹페이지·문서·이메일·검색 결과 같은 외부 콘텐츠에 악성 지시문을 숨겨 LLM이 읽을 때 실행되게 하는 공격
- **왜 필요한가**: RAG와 AI 에이전트는 사용자가 직접 입력하지 않은 외부 데이터를 컨텍스트에 넣음.
- **핵심 직관**: 사용자가 신뢰한 문서 안에 AI에게만 보이는 공격 명령을 숨겨두는 방식임.

## 깊이 이해
- **배경·문제의식**: LLM이 웹 검색, 사내 문서, 메일, 티켓을 읽고 요약·작업할 때 외부 데이터가 사실상 프롬프트가 됨.
- **작동 원리**: 공격자는 문서 본문, HTML hidden text, 이미지 OCR 텍스트 등에 "비밀을 전송하라" 같은 지시를 삽입함.
- **비유**: 비서에게 읽으라고 준 계약서 중간에 "이 문서를 읽은 사람은 금고 열쇠를 보내라"는 문장을 숨기는 행위임.
- **구체 예시**: RAG 챗봇이 웹 문서를 검색한 뒤 문서 안 악성 지시에 따라 사내 정책 문서를 외부 URL로 요약 전송하려 함.
- **흔한 오해·주의점**: 사용자가 악성 입력을 직접 넣지 않아도 발생한다. 외부 콘텐츠 신뢰등급과 도구 권한 제한이 필요함.

## 연결 개념
- RAG — 외부 문서를 컨텍스트에 넣는 대표 구조
- AI Agent — 외부 도구 호출로 피해가 확장되는 실행 환경
- Prompt Injection — 직접 입력 기반 지시 우회 공격

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Indirect Prompt Injection은 외부 콘텐츠에 숨은 지시가 LLM 컨텍스트를 오염시키는 공격임.
> 2. **가치**: RAG·에이전트 환경에서 사용자가 보지 못한 입력이 데이터 유출과 도구 오남용을 유발함.
> 3. **판단 포인트**: 외부 콘텐츠를 비신뢰 데이터로 분리하고 도구 실행 전 정책 검증을 적용해야 함.

## Ⅰ. 개요 및 필요성

간접 프롬프트 인젝션은 외부 콘텐츠 기반 LLM 공격이다. RAG와 에이전트는 웹·문서·메일을 읽어 답변과 작업을 수행한다. 외부 데이터와 시스템 지시를 격리해야 한다.

## Ⅱ. 구조 및 구성요소

```text
External Content → Hidden Instruction → RAG/Agent Context
  → Tool/Data Access → Exfiltration Attempt
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 외부 콘텐츠 | 문서·웹·메일 입력 | 비신뢰 데이터 |
| 숨은 지시 | 모델 대상 악성 명령 | HTML/CSS/OCR 포함 |
| Retriever/Agent | 컨텍스트 삽입·실행 | 자동 도구 호출 |
| Policy Gate | 접근·전송 차단 | domain allowlist |

> 요약: 간접 프롬프트 인젝션은 외부 콘텐츠의 숨은 지시가 RAG·에이전트 컨텍스트를 오염시키는 구조임.

## Ⅲ. 동작원리 및 흐름도

```text
외부 문서 수집 → 악성 지시 포함 → 모델 읽기
  → 민감 작업 유도 → 정책 게이트 차단
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 외부 콘텐츠 신뢰등급 분류 | public/internal 구분 |
| 2 | 숨은 명령 탐지·정규화 | HTML hidden text 제거 |
| 3 | 도구 호출·데이터 접근 검증 | allowlist 100% 적용 |
| 4 | 외부 전송·민감 출력 차단 | exfiltration 0건 |

> 요약: 방어는 외부 콘텐츠를 비신뢰 입력으로 취급하고 도구·전송 단계에서 정책을 강제하는 방식임.

## Ⅳ. 특징

| 구분 | 직접 Prompt Injection | Indirect Prompt Injection | 판단 포인트 |
|:---|:---|:---|:---|
| 입력 경로 | 사용자 채팅창 | 웹·문서·메일·검색결과 | 공급망형 입력 |
| 탐지 난도 | 사용자 입력 로그 확인 | 외부 콘텐츠 전처리 필요 | 콘텐츠 신뢰등급 |
| 피해 범위 | 응답 우회 중심 | 데이터 유출·도구 오남용 | 에이전트 권한 |
| 방어 | 프롬프트 정책 | 격리·출처검증·권한게이트 | RAG 설계 |

> 요약: 간접 공격은 외부 콘텐츠 경로를 타므로 RAG 파이프라인과 에이전트 권한 설계가 방어 핵심임.

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. RAG 전처리: HTML hidden text, script, OCR 노이즈를 제거하고 문서 출처·수집시각·신뢰등급 metadata 저장
2. 에이전트 권한: 외부 문서가 유발한 명령은 읽기 전용으로 제한하고 외부 전송·삭제·결제는 human approval 적용
3. 모니터링: 도메인 allowlist 위반, 민감 키워드 출력, tool call anomaly를 탐지해 High finding 0건 기준 운영

**결론 (2줄):**
- 기술사 판단: RAG·에이전트는 외부 콘텐츠를 비신뢰 데이터로 분리하고 실행 권한을 최소화해야 함
- 향후 방향: Indirect Prompt Injection 방어는 콘텐츠 신뢰 점수, policy engine, AI 레드팀 자동화로 발전함
