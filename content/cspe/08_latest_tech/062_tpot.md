## 미리 알고가기

- $TPOT$ ($Time$ $Per$ $Output$ $Token$): 대형 언어 모델이 첫 번째 토큰을 뱉어낸 직후부터, 응답 생성이 완료될 때까지 생성되는 개별 출력 토큰들의 평균 생성 지연 시간임
- 디코드 단계 ($Decode$): 첫 단어(프리필) 생성 이후, 매 루프마다 이전까지의 $KV$ 캐시를 참조하여 $1$개의 토큰을 순차적으로 덧붙여 나가는 단계임
- 메모리 대역폭 한계 ($Memory-bound$): 행렬 곱 등의 순수 연산 속도보다, 물리 메모리 반도체에서 연산 코어로 데이터를 실어나르는 버스 대역폭의 한계로 인해 성능이 지연되는 병목 상태임
- 추측 디코딩 ($Speculative$ $Decoding$): 가볍고 빠른 소형 초안 모델의 여러 토큰 동시 예측과 대형 대상 모델의 병렬 검증을 연동하여 디코딩 루프 속도를 올리는 최적화 기법임

## Ⅰ. 개요

- **정의/개념**: TPOT(Time Per Output Token)은 첫 번째 단어 출력 완료 시점부터 문장 생성 종료 기호($EOS$)가 나올 때까지 출력된 각 단어 토큰의 평균 생성 소요 시간이며, 사용자가 모니터에서 글자가 한 자씩 타자 쳐지듯 타이핑되는 체감 스트리밍 속도와 부드러움을 결정하는 실시간 성능 지표임
- **배경/필요성**: LLM의 단어 생성 루프(Decode)는 가중치와 $KV$ 캐시를 램에서 칩셋으로 계속 가져와야 하는 극심한 $Memory-bound$ 연산인데, 다중 동접자가 몰려 메모리 대역폭이 고갈되면 글자 출력이 느려지거나 뚝뚝 끊기는 불쾌한 사용자 경험이 발생하여 이를 엄격히 개선 및 관리할 기준 지표로 제정됨

## Ⅱ. 특징

- 프리필 단계의 부하에 민감한 최초 토큰 지연($TTFT$)과 달리, 순수하게 디코드 루프의 메모리 I/O 속도와 물리 메모리 버스 대역폭에 의해서 시간 수치가 좌우됨
- 동접 배치 크기($Batch$ $Size$)를 무한정 늘리면 전체 인프라의 처리량은 올라가지만, 개별 사용자의 대기 시간이 팽창하여 TPOT 수치가 기하급수적으로 나빠지는 트레이드오프가 존재함
- 추측 디코딩의 수용율($Acceptance$ $Rate$), $KV$ 캐시의 8비트/4비트 양자화 효율을 정교하게 판독해 내는 핵심 관측 지표로 활용됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 최초 토큰 지연 (TTFT) | 토큰당 출력 지연 (TPOT) | 처리량 (Throughput) |
|:---|:---|:---|:---|
| **지연 유발 병목** | 큐 대기 시간, 초기 프리필 연산 | $Memory-bound$ 디코딩 I/O | 스케줄러 오버헤드, 배치 비효율 |
| **사용자 체감 영역** | 시스템의 초기 반응성 (로딩 속도) | 스트리밍 텍스트의 부드러움 (타이핑 속도) | 다수의 요청이 동시 처리되는 속도 |
| **핵심 가속 기술** | 접두 캐싱 ($Prefix$ $Caching$) | 추측 디코딩, 캐시 양자화 | 연속 배칭 ($Continuous$ $Batching$) |
| **목표 성능 기준** | 보통 $200 \sim 500$ 밀리초 이내 | 보통 $15 \sim 50$ 밀리초 이내 (인간 독서 속도 대응) | 초당 릴리즈되는 총 토큰 수 |

> 요약: TTFT는 첫 단어의 문을 여는 반응성이고, TPOT은 문이 열린 뒤 흘러나오는 흐름의 연속성이며, Throughput은 시스템 전체의 수용력임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 디코드 루프 컨트롤 | 1토큰씩 차례대로 생성 순방향 연산을 수행하고 종료 조건을 실시간 감사하는 루프 컨트롤러임 |
| $KV$ 캐시 리더 | 이전 단계의 가중합($K, V$)을 불러와 어텐션 맵에 얹어 주는 메모리 고속 매퍼임 |
| 로짓 샘플러 | 생성된 로짓($Logits$) 결과 배열에 템퍼러처를 가미해 최종 1개의 토큰을 추리는 샘플링 필터임 |
| 큐 스케줄러 | prefill 진입 시의 메모리 간섭을 차단해 디코드 세션의 TPOT 일관성을 유지시키는 동적 배치 조율기임 |

```text
[ TPOT (Time Per Output Token) 시간 측정 구역 ]
... -> Sampler (First Word) -> [Start Measure] -> [Decoder Loop] -> Token 2 -> Token 3 -> [End Measure] -> EOS
                               |<---------- Total Decoding Duration / Num Tokens (TPOT) ------->|
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 이전 캐시   | --> | 로짓 연산 및 | --> | 확률기반    | --> | 캐시 업데이트|
| 로드 및 참조|     | 다음 토큰예측|     | 토큰 샘플링 |     | 및 루프 반복|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **상태 조회** — 이전까지 출력된 단어들의 $KV$ 캐시와 모델의 가중치 행렬을 HBM에서 GPU $SRAM$ 온칩 메모리로 스트리밍 수집함
2. **단어 확률 예측** — 인입된 토큰을 기반으로 다음 단어로 적합한 후보 문자들의 로짓($Logits$) 행렬 분포를 순방향 연산함
3. **샘플링 결정** — 확률 분포에서 템퍼러처와 $Top-p$ 필터를 곱해 최종 토큰 1단어를 뽑아 네트워크 채널로 실시간 송신함
4. **동적 병합** — 새로 탄생한 토큰의 Key, Value 정보를 페이지 테이블에 동적으로 갱신하고, 종료 기호가 감지될 때까지 루프를 회전함

## Ⅵ. 실무 적용 및 유의점

1. 엔터프라이즈 실사용 환경에서 TPOT이 인간의 평균 분당 독서 속도(WPM, 토큰 기준 약 $30 \sim 40$ms 수준)보다 느려지면 사용자의 체감 UX가 붕괴하므로, 반드시 '추측 디코딩' 기법이나 'FP8 KV 캐시 양자화'를 주입하여 메모리 대역폭 병목을 완화하고 평균 TPOT 개선 효과를 검증해야 함
2. 시스템 전체 처리량(Throughput)만을 극대화하려 배치를 임계치 이상으로 팽창시키면 VRAM 대역폭 포화로 개별 세션의 TPOT이 극단적으로 튀어 지연이 심해지므로, 반드시 'QoS 기반 세션 분기'를 구축하고, 일반 챗용 배치 크기를 가변 제어하며 p95 TPOT 스펙을 상시 보존해야 함

## Ⅶ. 결론

- TPOT은 사용자가 인공지능과 대화하며 느끼는 실시간성의 척도이자 디코딩 메모리 병목을 정밀 가리키는 인프라 설계의 핵심 나침반이며, 설계자는 전체 처리량과 개별 TPOT의 가치 충돌을 이해하고 캐시 양자화와 가변 배치 QoS 전략을 결합해 견고한 서빙 시스템을 완성해야 함
