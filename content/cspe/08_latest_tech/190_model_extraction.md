# 📖 【암기용】 개념 완전 이해

> 목적: Model Extraction을 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: 모델 API에 반복 질의해 의사결정 경계, 파라미터, 동작 특성을 복제 모델로 재현하는 공격
- **왜 필요한가**: AI 모델은 학습 데이터·튜닝 비용·업무 규칙이 반영된 지식재산이며 API 응답만으로도 모방될 수 있음.
- **핵심 직관**: 블랙박스 모델에 질문을 많이 던져 답안지를 만들고 비슷한 모델을 훈련하는 방식임.

## 깊이 이해
- **배경·문제의식**: 모델을 SaaS API로 제공하면 공격자는 입력·출력 쌍을 대량 수집해 substitute model을 학습할 수 있다.
- **작동 원리**: 공격자는 다양한 입력을 자동 생성하고 확률값·logit·label 응답을 수집해 결정 경계와 기능을 근사함.
- **비유**: 유료 과외 선생님에게 수천 문제를 질문해 해설 패턴을 베껴 별도 교재를 만드는 행위임.
- **구체 예시**: 이미지 분류 API에 100만 건 쿼리를 보내 top-5 확률을 수집하고 유사 정확도의 복제 모델을 학습함.
- **흔한 오해·주의점**: API 키 인증만으로 충분하지 않다. 쿼리 패턴, 응답 정보량, 과금·rate limit, 워터마킹을 함께 관리해야 함.

## 연결 개념
- Model Inversion — 모델 응답에서 학습 데이터 특징 복원
- API Abuse Detection — 비정상 쿼리 탐지
- Model Watermarking — 복제 모델 식별 기술

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Model Extraction은 API 응답을 대량 수집해 대상 모델의 기능을 복제하는 공격임.
> 2. **가치**: 모델 지식재산, 학습 데이터 투자, 업무 규칙이 외부로 유출되는 경제적 위험임.
> 3. **판단 포인트**: 응답 정보량 제한, 쿼리 이상탐지, rate limit, 워터마킹을 조합해야 함.

## Ⅰ. 개요 및 필요성

Model Extraction은 모델 복제 공격이다. AI API는 입력에 대한 예측값을 제공하므로 반복 질의로 모델 동작을 근사할 수 있다. 모델 자산 보호와 API 남용 탐지가 필요하다.

## Ⅱ. 구조 및 구성요소

```text
Attacker Queries → API Responses → Query-Response Dataset
  → Substitute Training → Stolen Model
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Query Generator | 입력 샘플 대량 생성 | adaptive query |
| Prediction API | label/probability 반환 | 정보량 차이 |
| Substitute Model | 응답 데이터로 복제 학습 | 기능 근사 |
| Defense Layer | 제한·탐지·워터마킹 | rate limit, anomaly |

> 요약: 모델 추출은 대량 질의와 응답 수집으로 substitute model을 학습하는 공격 구조임.

## Ⅲ. 동작원리 및 흐름도

```text
입력 생성 → API 대량 질의 → 응답 수집
  → 복제 모델 학습 → 유사도 평가
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 입력 공간 탐색·샘플 생성 | 쿼리 다양도 측정 |
| 2 | API label/probability 수집 | 계정별 QPS·일한도 |
| 3 | substitute model 학습 | victim agreement rate |
| 4 | 이상행위 탐지·차단 | 비정상 쿼리 차단률 |

> 요약: Model Extraction은 API 응답 정보량과 대량 쿼리를 활용하므로 제한·탐지·워터마킹이 방어 핵심임.

## Ⅳ. 특징

| 구분 | 일반 API 남용 | Model Extraction | 판단 포인트 |
|:---|:---|:---|:---|
| 목적 | 서비스 무단 사용 | 모델 기능 복제 | IP 보호 |
| 입력 패턴 | 반복 호출 | 경계 탐색·다양한 입력 | 이상탐지 |
| 응답 악용 | 데이터 조회 | 확률·logit로 학습 | 정보량 최소화 |
| 방어 | 인증·rate limit | 워터마킹·응답 제한 병행 | 다층 통제 |

> 요약: Model Extraction은 API 사용량뿐 아니라 입력 다양도와 응답 정보량을 함께 감시해야 함.

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 응답 최소화: 불필요한 logit·확률·top-k 값을 숨기고 업무상 필요한 label·confidence 범위만 제공
2. 남용 탐지: 계정·IP·토큰별 QPS, 입력 다양도, 경계 탐색 패턴을 탐지하고 일 10만 쿼리 초과 시 추가 검증
3. 자산 보호: 모델 워터마킹과 canary input을 삽입해 복제 의심 모델의 ownership evidence를 확보

**결론 (2줄):**
- 기술사 판단: 상용 AI API는 기능 제공 범위와 응답 정보량을 최소화하고 쿼리 이상탐지를 기본 통제로 적용
- 향후 방향: Model Extraction 방어는 API 보안, 모델 워터마킹, 계약 기반 사용량 감사와 결합됨
