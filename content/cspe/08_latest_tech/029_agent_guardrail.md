## Ⅰ. 개요
- **정의**: 에이전트의 입력과 출력 텍스트를 분류 모델·정규식으로 실시간 검사하여 탈옥·편향·환각·기밀 유출을 차단하는 의미론적 필터 프레임워크
- **배경/필요성**: 프롬프트 인젝션(DAN 공격)으로 시스템 프롬프트가 무력화되고, LLM이 혐오 발언·허위 정보를 생성하는 사례가 빈발하며, LLM 자체 재학습은 비용·시간 측면에서 비현실적이므로 외부 필터망이 필수임
- **비유**: 공항 보안 검색대가 탑승 전(입력)과 수화물 수령(출력) 양쪽에서 위험물을 걸러내는 것과 유사

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 정책 엔진과 가드레일의 역할 차이 | Input Guardrail(탈옥·PII) + Output Guardrail(환각·편향) 이중 필터 | 경량 분류 모델(Llama Guard) 사용 이유와 Latency 트레이드오프 미서술 시 감점 |

> 요약: 가드레일은 에이전트 입출력 텍스트의 의미를 분석하여 유해·위험 콘텐츠를 사전 차단하는 안전 필터망임

## Ⅱ. 구성요소
```text
+------------------------------------------------------------------+
|                    Guardrail Pipeline                             |
|  +-----------+    +--------+    +-----------+    +-----------+   |
|  | Input     |--->| Main   |--->| Output    |--->| Fallback  |   |
|  | Guardrail |    | LLM    |    | Guardrail |    | Handler   |   |
|  +-----------+    +--------+    +-----------+    +-----------+   |
|   입력 검증        추론 수행      출력 검증        거절/마스킹     |
+------------------------------------------------------------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Input Guardrail | 프롬프트 인젝션 탐지(분류 모델), PII 정규식 마스킹, 토큰 폭탄 길이 제한 수행 | 공항 탑승 전 보안 검색 |
| Topical Router | 도메인 외 질문(은행 챗봇에 레시피 요청 등)을 의도 분류기로 탐지하여 조기 반환 | 접수 창구 안내 |
| Output Guardrail | 혐오·편향 분류, NLI 기반 환각 팩트체크, 기밀 정보 정규식 스캔 수행 | 출국장 수화물 검사 |
| Fallback Handler | 위반 감지 시 표준 거절 응답(Canned Response) 반환 또는 위험 단어 마스킹(***) 처리 | 위험물 압수 후 통보 |

> 요약: 입력 필터→LLM 추론→출력 필터→거절/마스킹의 4단계 샌드위치 구조

## Ⅲ. 절차
```text
+----------+     +-----------+     +--------+     +-----------+
| 사용자   |---->| Input     |---->| Main   |---->| Output    |
| 입력     |     | Guardrail |     | LLM    |     | Guardrail |
+----------+     +-----------+     +--------+     +-----------+
                   |  차단 시                         |  차단 시
                   v                                  v
              [거절 응답 즉시 반환]            [마스킹/거절 처리]
```

1. **입력 검증(Input Guardrail)** — 경량 분류 모델(Llama Guard 8B)로 탈옥·인젝션 의도 탐지, 정규식으로 주민번호·카드번호 등 PII 마스킹, 입력 토큰 상한 초과 시 절단
2. **주제 라우팅(Topical Guardrail)** — 의도 분류기가 서비스 도메인 외 질문을 탐지하여 메인 LLM 호출 없이 "해당 주제는 지원 범위 밖입니다" 조기 반환
3. **출력 검증(Output Guardrail)** — 유해성 분류(Toxic Classifier), RAG 원문 대비 NLI(Natural Language Inference) 기반 환각 탐지, 사내 기밀 키워드 정규식 스캔
4. **우회 및 교정(Fallback)** — 위반 시 표준 거절 메시지 반환, 부분 위반 시 위험 토큰만 마스킹(Redaction) 후 전달

> 요약: 입력 차단→주제 필터→출력 검증→거절/마스킹의 다층 방어로 의미론적 위험 차단

## Ⅳ. 문제점
- **Latency 증가**: 입출력 양단에 분류 모델을 배치하면 메인 LLM 외 추가 1~3초 지연 발생 — 사용자 체감 응답 시간 저하
- **과잉 차단(False Positive)**: 의료·법률 도메인에서 정상 전문 용어가 유해 표현으로 오분류되어 서비스 품질 저하 — 도메인 특화 학습 부족
- **우회 공격 진화**: 유니코드 치환·다국어 혼합 등 탈옥 기법이 지속 진화하여 고정 분류 모델의 탐지율 하락 — 정적 모델 한계

> 요약: 응답 지연, 오탐, 진화하는 우회 공격이 가드레일의 3대 과제임

## Ⅴ. 개선방안
1. 단기: 가드레일 모델을 DistilBERT·Llama Guard 8B급 경량 모델로 교체하여 검사 시간을 50ms 이내로 단축, 입출력 검사 병렬 실행
2. 중기: 도메인별 Fine-tuned 분류 모델 적용 + False Positive 로그 피드백 루프로 분기별 모델 재학습
3. 장기: 적대적 프롬프트 패턴을 실시간 학습하는 Adaptive Guardrail(AI Firewall) 도입, 제로데이 탈옥 기법에 동적 대응

- **Latency**: 경량 모델 + GPU 로컬 배포 + 비동기 병렬 검사 (지표: 가드레일 추가 지연 < 100ms)
- **오탐**: 도메인 특화 학습 + 화이트리스트 예외 규칙 (지표: False Positive율 < 3%)
- **우회 공격**: 월별 Red-Team 테스트 + 탈옥 패턴 DB 자동 업데이트 (지표: 신규 공격 탐지율 > 95%)

> 요약: 경량화·도메인 특화·적응형 학습으로 성능-보안 트레이드오프 최적화

## Ⅵ. 전망
- 향후 발전 방향: 텍스트 필터를 넘어 이미지·음성·비디오 등 멀티모달 입출력에 대한 통합 가드레일로 확장되며, WAF(Web Application Firewall)과 유사한 AI 전용 방화벽(AI WAF) 제품군으로 시장 형성
- 기술사적 판단: 가드레일(의미론적·확률적)과 정책 엔진(결정론적·규칙 기반)은 상호 대체가 아닌 보완 관계이며, 두 계층을 결합한 Defense-in-Depth가 엔터프라이즈 AI 보안의 표준 패턴임
- 기술사 제언: 가드레일 모델 선정 시 정확도뿐 아니라 Latency 예산(전체 응답 시간의 10% 이내)을 설계 제약 조건으로 명시하고, 정책 엔진(028번 참조)과 연동하여 의미 필터→행동 통제 순서의 이중 검증 아키텍처를 구성할 것
