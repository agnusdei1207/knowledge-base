## 미리 알고가기

- PIM은 메모리 내부나 메모리 근접 회로에서 연산을 수행해 데이터 이동 비용을 줄이는 구조임
- 메모리 병목이 큰 AI와 데이터 분석 워크로드에서 특히 관심이 높음
- 범용성보다 이동 비용 절감과 에너지 효율 향상이 핵심 가치임

## Ⅰ. 개요

- **정의/개념**: PIM은 메모리 장치 내부 또는 메모리 어레이와 밀접한 위치에 연산 기능을 넣어 저장과 계산을 결합함으로써 데이터 이동을 줄이는 컴퓨팅 아키텍처임
- **배경/필요성**: 현대 시스템에서는 연산 자체보다 데이터를 메모리와 프로세서 사이에 옮기는 비용이 더 커지는 메모리 월 문제가 심화되어 계산 위치를 메모리 쪽으로 이동하는 접근이 부상함

## Ⅱ. 특징

- 메모리 대역폭 병목과 에너지 소모를 줄이는 데 강점이 있음
- 특정 연산 패턴에 최적화될수록 효과가 크고 범용성은 낮아질 수 있음
- AI 추론과 벡터 연산과 DB 스캔 같은 데이터 집약형 작업에 적합함
- 시스템 소프트웨어와 메모리 일관성 모델 설계가 중요함

## Ⅲ. 종류 및 비교

| 판단 기준 | PIM | In Memory Computing | Near Memory Computing |
|:---|:---|:---|:---|
| 연산 위치 | 메모리 내부 또는 근접 로직 | 메모리 셀 수준 연산 포함 | 메모리 옆 프로세서 |
| 핵심 가치 | 데이터 이동 절감 | 더 강한 결합과 아날로그 활용 가능 | 구현 용이성과 유연성 |
| 범용성 | 중간 | 낮음 | 중간 이상 |
| 대표 용도 | AI 추론, 검색, 분석 | 특화 행렬 연산 | 메모리 집약 워크로드 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Memory Array | 대량 데이터를 저장하며 연산 대상이 되는 핵심 저장 영역임 |
| PIM Logic | 필터링과 누산과 벡터 연산 같은 기능을 메모리와 가깝게 수행하는 계산 블록임 |
| Command Interface | CPU나 가속기가 메모리 내 연산을 지시하고 결과를 회수하는 제어 인터페이스임 |
| Data Path Optimizer | 필요한 데이터만 외부로 내보내 전체 이동량을 줄이는 경로 제어 계층임 |
| Runtime Support | 어떤 연산을 PIM에 오프로딩할지 결정하고 일관성을 관리하는 소프트웨어 계층임 |

```text
+-------------+    +---------------+    +----------------+
| CPU / GPU   | -> | Command IF    | -> | Memory + PIM   |
+-------------+    +---------------+    +----------------+
                                              |
                                              v
                                       +-------------+
                                       | Filter/Reduce|
                                       +-------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 연산 오프로딩 | -> | 메모리 내 실행 | -> | 부분 결과 생성 | -> | 이동량 최소화 | -> | 결과 반환    |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **연산 오프로딩**: 호스트가 적합한 연산을 메모리 쪽에 위임함
2. **메모리 내 실행**: PIM 로직이 데이터 근처에서 연산을 수행함
3. **부분 결과 생성**: 요약되거나 압축된 결과를 만들음
4. **이동량 최소화**: 필요한 데이터만 외부 프로세서로 보냄
5. **결과 반환**: 최종 계산이나 후속 처리에 결과를 전달함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 메모리 내부 연산 모델이 표준화되지 않으면 소프트웨어 이식성과 생태계 확장이 제한될 수 있음
   - 해결방안: standard programming model과 compiler support를 적용하고 software portability score와 developer adoption rate로 검증함
2. 문제: 범용 프로세서와 메모리 내 연산 사이 일관성과 디버깅이 복잡해져 운영 안정성이 떨어질 수 있음
   - 해결방안: explicit offload policy와 verification framework를 적용하고 coherence error rate와 debugging turnaround time으로 검증함
3. 문제: 특정 연산에만 이점이 크므로 부적합한 워크로드에 적용하면 기대 성능 향상이 거의 없을 수 있음
   - 해결방안: workload suitability profiling을 적용하고 data movement reduction ratio와 workload speedup consistency로 검증함

## Ⅶ. 적용 사례

- 벡터 검색 시스템이 메모리 내 필터 연산을 도입하며 확인 지표는 data movement reduction ratio와 workload speedup consistency임
- AI 추론 가속기가 오프로딩 검증 프레임워크를 운영하며 확인 지표는 coherence error rate와 debugging turnaround time임
- 데이터 분석 플랫폼이 워크로드 적합성 프로파일링을 적용하며 확인 지표는 software portability score와 developer adoption rate임

## Ⅷ. 결론

PIM은 메모리 월을 줄이는 유력한 구조이지만 하드웨어 이점이 실제 성과로 이어지려면 적합 워크로드 선별과 소프트웨어 표준화가 함께 필요함.
