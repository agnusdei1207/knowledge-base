# 📖 【암기용】 개념 완전 이해

> 목적: 폰 노이만 병목(Memory Wall)을 부수기 위해 탄생한 PIM의 본질을 완벽히 이해한다.

## 한눈에
- **정의**: 메모리 칩(DRAM) 내부에 연산기(PU, Processing Unit)를 집어넣어, 데이터 이동 없이 메모리 안에서 직접 연산을 수행하는 차세대 지능형 반도체 기술
- **필요성**: AI 추론 연산(특히 거대 모델)은 곱셈, 덧셈 자체보다 "메모리에서 GPU로 데이터를 가져오는 시간과 전력"이 전체 시스템의 80% 이상을 낭비하게 만들기 때문
- **핵심 직관**: "창고(메모리)에 있는 물건을 매번 본사 공장(CPU/GPU)으로 택배(버스) 보내서 포장하는 대신, 창고 안에 소형 포장 기계(PU)를 설치해 현장에서 다 끝내고 결과만 보내는 방식"

## 깊이 이해
- **배경(왜 등장했나?)**: 현대 컴퓨터의 '폰 노이만 구조'는 연산장치와 기억장치가 분리되어 있다. 연산기가 아무리 빨라도 메모리 대역폭이 좁으면 데이터 병목(Memory Wall)과 전력 낭비(Power Wall)가 발생한다. 이를 극복하기 위해 메모리 쪽에 연산 기능을 부여하려는 시도가 PIM이다.
- **작동 원리(어떻게 달성했나?)**: 
  1. 메모리 셀 바로 옆에 데이터를 처리할 수 있는 간단한 로직 회로(MAC 연산기 등)를 배치한다.
  2. CPU/GPU는 복잡한 연산만 직접 하고, '단순하고 반복적인 대규모 연산(예: 행렬 곱셈)'은 PIM에게 "네가 안에서 계산하고 결과값만 줘"라고 명령한다.
  3. PIM은 메모리 내부의 방대한 뱅크(Bank) 단위 병렬성을 활용해 데이터를 옮기지 않고 순식간에 계산한 뒤, 최종 부분합(Partial Sum)만 프로세서로 반환한다.
- **일상 비유**: 도서관(메모리)에서 책 100권에서 특정 단어 수를 세라는 지시가 내려왔다. 기존 방식은 책 100권을 모두 대출해서 내 책상(CPU)으로 가져와 세는 것이다(너무 무겁고 오래 걸림). PIM 방식은 도서관 안의 사서(PU) 10명에게 "10권씩 맡아서 세고 총합만 알려주세요"라고 하는 것이다.
- **구체 예시**: 삼성전자의 'HBM-PIM'은 상용 HBM2 내부에 AI 엔진을 탑재해 기존 HBM 대비 성능은 2.5배 높이고 에너지 소비는 70% 이상 줄였다. SK하이닉스의 'GDDR6-AiM'도 유사한 개념의 지능형 메모리이다.
- **흔한 오해/주의점**: "PIM이 CPU나 GPU를 완전히 대체하는가?" → 절대 아니다. DRAM 공정의 특성상 복잡한 제어 로직을 넣기 어렵다. 단순 반복 연산(행렬 곱 등)은 PIM이 처리하고, 복잡한 판단과 스케줄링은 여전히 GPU가 담당하는 '이기종 협업' 구조다.

## 연결 개념
- **Memory Wall (메모리 병목)**: 프로세서의 처리 속도를 메모리의 데이터 전송 속도가 따라가지 못해 발생하는 시스템 한계
- **PNM (Processing Near Memory)**: 메모리 '내부'가 아니라 메모리 모듈 '가까이(컨트롤러나 CXL 인터페이스 등)'에 연산기를 두는 타협안/대안 기술
- **CXL (Compute Express Link)**: 프로세서와 메모리 간의 연결을 혁신하는 차세대 인터페이스 (PNM/PIM과 결합 시너지)

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: PIM은 폰 노이만 아키텍처의 한계를 극복하기 위해, 메모리 다이(Die) 내부에 연산 유닛(Processing Unit)을 집적한 Data-Centric 컴퓨팅 기술이다.
> 2. **가치**: 데이터 이동에 따른 전력 소모(Data Movement Energy)와 지연 시간(Latency)을 획기적으로 절감하여, LLM 추론 등 Memory-bound 워크로드 성능을 극대화한다.
> 3. **판단 포인트**: 기존 GPU 생태계(CUDA 등)와의 소프트웨어 호환성 확보, DRAM 공정 내 로직 집적에 따른 수율 및 발열(Thermal) 문제가 상용화의 핵심 변수이다.

## Ⅰ. 개요 및 필요성
- **정의**: 메모리 내부에 단순/반복 연산이 가능한 프로세싱 유닛(PU)을 통합하여, 데이터의 외부 이동 없이 메모리 자체에서 연산을 수행하는 차세대 반도체 기술
- **배경**: AI 연산량 급증으로 '연산 처리 시간'보다 '데이터 전송 시간'이 더 많이 소요되는 폰 노이만 병목(Memory Wall) 현상 심화
- **필요성**: 데이터 이동을 최소화하여 시스템 전체의 전력 효율(Energy Efficiency) 향상 및 대역폭 병목(Bandwidth Bottleneck) 해소

## Ⅱ. PIM의 핵심 아키텍처 및 구성 요소
```text
[ 기존 폰 노이만 구조 ]            [ PIM (Processing-in-Memory) 구조 ]
GPU ↔ (대규모 Data 이동) ↔ DRAM       GPU ↔ (명령어/결과값만 이동) ↔ DRAM(PIM)
                                              ┌───────────────────┐
                                              │ Bank 0 + [MAC 연산기] │
                                              │ Bank 1 + [MAC 연산기] │
                                              │ ... (Bank 병렬 처리)  │
                                              └───────────────────┘
```

| 핵심 요소 | 기술적 특징 | 기대 효과 |
|:---|:---|:---|
| **PIM-enabled Bank** | 메모리 뱅크 내부 또는 주변에 PU(Processing Unit) 배치 | 뱅크 단위의 막대한 병렬 데이터 접근 활용 |
| **MAC 연산기** | Multiply-Accumulate 연산 전용 하드웨어 블록 | AI 추론의 핵심인 행렬-벡터 곱셈(GEMV) 고속 처리 |
| **PIM Command** | Host(GPU)가 연산 지시를 내리는 확장 명령어 셋 | 기존 메모리 읽기/쓰기 프로토콜과 호환 유지 |
| **Reduction Tree** | 각 뱅크에서 계산된 부분합(Partial Sum)을 결합 | 데이터 이동량을 최종 결과값 수준으로 극소화 |

## Ⅲ. PIM의 한계 돌파 메커니즘 (Data Movement 제거)
1. **전력 장벽(Power Wall) 극복**
   - 문제: 64bit 데이터 하나를 연산하는 전력(0.1pJ)보다, DRAM에서 데이터를 가져오는 전력(수백 pJ)이 수천 배 높음
   - 해결: 데이터가 저장된 곳에서 직접 연산(In-Situ Processing)함으로써 I/O 버스를 태우지 않아 전력 소모 70% 이상 절감
2. **대역폭 장벽(Bandwidth Wall) 우회**
   - 문제: 핀(Pin) 수와 동작 주파수를 무한정 늘릴 수 없어 HBM과 같은 고비용 패키징 필요
   - 해결: 내부 뱅크(Internal Bank) 대역폭은 외부 I/O 대역폭보다 수십 배 넓음. 이를 내부 연산기가 직접 활용하여 병목 우회

## Ⅳ. 연산-메모리 융합 기술 발전 단계 비교 (PIM vs PNM)
| 구분 | 기존 (Von Neumann) | PNM (Processing Near Memory) | PIM (Processing In Memory) |
|:---|:---|:---|:---|
| **연산부 위치** | Host CPU / GPU | 메모리 모듈 위 (CXL 컨트롤러 등) | **메모리 칩(DRAM) 내부 뱅크** |
| **적용 공정** | 선단 로직 공정 | 선단 로직 + 표준 DRAM | **DRAM 공정 (설계 난이도 높음)** |
| **병렬성** | Host 코어 수 | 모듈 단위 병렬성 | **칩 내부 뱅크(Bank) 단위 극대화** |
| **주요 사례** | 일반 서버 아키텍처 | 삼성 CXL-PNM, 메타 MTIA | **삼성 HBM-PIM, SK하이닉스 GDDR6-AiM** |

## Ⅴ. PIM 도입에 따른 리스크 및 대응 방안
| 리스크 요인 | 발생 원인 | 대응 방안 (엔지니어링/생태계 관점) |
|:---|:---|:---|
| **공정 불일치 (Process)**| DRAM은 커패시터 최적화, 로직 회로는 트랜지스터 최적화라 둘을 섞기 어려움 | 칩을 분리하여 쌓는 **하이브리드 본딩(HBM4 로직 다이)** 방식으로 진화 |
| **소프트웨어 생태계 부재**| 기존 개발자들은 PIM 전용 명령어를 사용한 코딩을 할 줄 모름 | 기존 Pytorch/TensorFlow에서 투명하게 변환해주는 **전용 컴파일러 및 SDK** 제공 필수 |
| **발열 (Thermal)** | 촘촘한 메모리 셀 사이에서 연산기가 작동하며 핫스팟(Hot Spot) 발생 | 연산 활성화 시점을 분산하는 스케줄링 및 첨단 방열 패키징 적용 |

## Ⅵ. 실무 적용 및 결론
**적용 판단 및 실무 가이드:**
1. **LLM 추론 가속기 설계**: 생성형 AI의 디코딩(Token Generation) 단계는 대표적인 Memory-bound 구간이다. 여기에 HBM-PIM을 적용하면 GPU 확장에 의존하지 않고도 TPS(Token Per Second)를 비약적으로 높일 수 있다.
2. **이기종(Heterogeneous) 오프로딩**: 모델 연산 중 '합성곱(CNN), Attention 연산' 등 복잡한 Compute-bound 연산은 GPU가, '단순 가중치 탐색(Embedding Lookup), GEMV'는 PIM이 처리하도록 프레임워크 단에서 자동 분배(Routing)해야 한다.

**결론:**
- PIM은 메모리가 단순한 '저장고'를 넘어 스스로 '생각'하는 지능형 반도체로 진화하는 첫걸음이다.
- 향후 PIM은 단일 칩 수준의 집적을 넘어, HBM4의 커스텀 로직 다이 및 CXL 생태계와 결합하여 데이터센터 아키텍처를 'Data-Centric'으로 완벽히 재편할 것이다.
