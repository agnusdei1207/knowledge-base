# 📖 【암기용】 개념 완전 이해

> 목적: PIM(Processing-in-Memory) 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 메모리 칩 내부에 연산 기능(연산기)을 집어넣어, 데이터를 옮기지 않고 그 자리에서 바로 계산하는 기술
- **왜 필요한가**: 컴퓨터 연산 속도는 엄청 빨라졌는데, 메모리에서 데이터를 가져오는 길(Bus)이 좁아서 성능이 낭비되고 전기도 많이 먹음. 데이터를 옮기는 게 가장 큰 비용이기 때문
- **핵심 직관**: "요리사(CPU)가 창고(메모리)에서 재료를 가져오는 대신, 창고 안에 아예 조리 도구를 갖다 놓고 거기서 요리까지 끝내는 방식"

## 깊이 이해
- **배경·문제의식**: 딥러닝 연산은 단순 반복 계산이 엄청나게 많음. 이 데이터를 CPU나 GPU로 옮기는 데 드는 에너지가 실제 계산하는 데 드는 에너지보다 수십 배 큼. 이를 '데이터 이동의 병목(Data Movement Bottleneck)'이라고 함
- **작동 원리**: ① **연산기 통합**: D-RAM의 각 뱅크(Bank)나 채널 옆에 작은 연산 유닛(PCU)을 배치함. ② **병렬 처리**: 메모리 층층마다 연산기가 있어, 수천 개의 연산이 동시에 일어남. ③ **에너지 절감**: 데이터를 외부 버스를 통해 멀리 보낼 필요가 없어 전력 소모가 70~80% 줄어듦
- **비유**: 대형 마트(메모리)에서 물건을 다 집으로 가져와서 요리하는 대신, 마트 진열대 옆에 가스레인지를 두고 바로 요리해서 먹는 것. 운반비(전력/시간)가 안 듬
- **구체 예시**: 삼성전자의 HBM-PIM, SK하이닉스의 AiM(Accelerator-in-Memory). 특히 챗봇(LLM)의 추론 단계에서 답변 속도를 높이고 서버 운영비를 줄이는 데 탁월함
- **흔한 오해·주의점**: "PIM이 GPU를 대체하나"는 아님. 복잡하고 어려운 연산은 여전히 GPU가 하고, 단순하지만 데이터가 많이 필요한 '행렬 곱셈'이나 '정규화' 같은 단순 반복 작업만 메모리 안에서 처리하는 것임(Co-processor 역할)

## 연결 개념
- **Memory Wall**: 프로세서와 메모리 간의 성능 격차 문제
- **Von Neumann Architecture**: 데이터와 연산이 분리된 기존 구조 (PIM은 이를 극복)
- **HBM-PIM**: 고대역폭 메모리에 PIM 기술을 접목한 고성능 모델

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 폰 노이만 구조의 한계 극복, **데이터 이동 오버헤드 제거, 뱅크 레벨 병렬성(Bank-level Parallelism), 전력 효율성**을 중심으로 기술한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: PIM은 메모리 계층 내에 연산 유닛(PCU)을 통합하여, 프로세서와 메모리 간의 데이터 이동(Data Movement) 없이 메모리 내부에서 직접 연산을 수행하는 컴퓨팅 아키텍처이다.
> 2. **가치**: 폰 노이만 병목(Von Neumann Bottleneck)을 근본적으로 해소하여 시스템 성능을 2~3배 높이고 에너지 소모를 70% 이상 절감하는 '비폰노이만(Non-Von Neumann)' 혁신 기술이다.
> 3. **판단 포인트**: 연산 유닛의 집적도에 따른 메모리 용량 손실(Trade-off), 소프트웨어 에코시스템(컴파일러, SDK) 지원 여부, 특정 AI 워크로드(GEMV 등)에서의 실질 가속비를 고려해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 차세대 컴퓨팅 아키텍처 이해도 측정 | 폰 노이만 병목 해소, 데이터 이동 최소화, 뱅크 레벨 병렬성 | 단순히 "메모리가 계산한다"는 서술 |
| AI 성능/에너지 최적화 역량 확인 | HBM-PIM, PNM(Near Memory)과의 차이, 전력 효율(TOPS/W) | GPU와의 보완 관계(Co-processor) 누락 |

> 요약: '데이터가 있는 곳으로 연산기를 옮긴다'는 개념과 '에너지 효율'을 핵심 논점으로 기술한다.

## Ⅰ. 개요 및 필요성

- 정의: 프로세서와 메모리가 분리된 기존 구조를 탈피하여, 메모리 내부(In-Memory)에 연산 로직을 탑재해 데이터를 직접 처리하는 기술
- 배경: AI 모델 파라미터 증가로 인한 데이터 이동 비용(시간, 전력)이 실제 연산 비용을 압도하는 '메모리 벽(Memory Wall)' 문제 심화
- 필요성: 폰 노이만 구조의 전력 효율 한계 극복, 실시간 대규모 데이터 분석 요구 충족, 저전력 인공지능(Green AI) 구현

## Ⅱ. 구조 및 구성요소

```text
[Traditional: Von Neumann]          [Next Gen: PIM]
CPU/GPU <--- Bus ---> Memory        Host CPU <--- Control ---> [Memory Chip]
(Compute)   (Move)    (Store)                                 | (Compute+Store) |
                                                              |  PCU + Banks    |
```

| 구성요소 | 역할 | 기술적 특징 |
|:---|:---|:---|
| PCU (Programmable Compute Unit) | 메모리 내 연산 수행 유닛 | FP16/INT8 등 AI 특화 연산기 집적 |
| 뱅크 (Memory Bank) | 데이터 저장 단위 | 뱅크 내 데이터에 PCU가 직접 접근 |
| 제어 로직 (Controller) | 호스트 명령 해석 및 연산 할당 | 기존 DRAM 인터페이스 표준 준수 |
| 소프트웨어 스택 | PIM 전용 명령어 및 라이브러리 | CUDA/OpenCL 연동 프레임워크 |

> 요약: 메모리 뱅크 옆에 연산 유닛(PCU)을 배치하여 내부 데이터 패스(Internal Path)만으로 연산하는 구조이다.

---

## Ⅲ. 동작원리 및 흐름도

```text
Request from Host -> Instruction Dispatch -> Local Bank Data Load -> PCU Compute -> Store/Return
(AI 연산 요청)      (PIM 명령어 해석)       (버스 통과 없이 로드)     (병렬 연산 수행)   (결과값 업데이트)
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 호스트에서 PIM 전용 명령어(예: GEMV) 하달 | 기존 시스템과의 호환성 유지 |
| 2 | 메모리 칩 내부의 다수 PCU가 병렬로 가동 | 뱅크 레벨 병렬성(Bank-level Parallelism) |
| 3 | 외부 버스 이동 없이 뱅크 내 데이터를 즉시 연산 | 데이터 이동 에너지 절감량 |
| 4 | 중간 연산 결과를 다시 메모리에 쓰거나 호스트 전송 | 최종 처리 시간(End-to-End Latency) |

> 요약: 데이터를 프로세서로 옮기지 않고, 메모리 내부의 수많은 뱅크에서 동시에 병렬 계산을 끝내는 방식이다.

## Ⅳ. 특징

| 구분 | 일반 컴퓨팅 (Von Neumann) | PIM 기반 컴퓨팅 | 판단 포인트 |
|:---|:---|:---|:---|
| 연산 중심 | 프로세서 (CPU/GPU) | 프로세서 + 메모리 분담 | 워크로드 분산 효율 |
| 데이터 이동 | 잦음 (시스템 에너지의 80%) | 최소화 (메모리 내부 처리) | 전력 효율성 (TOPS/W) |
| 병목 지점 | 메모리 대역폭 (Bandwidth) | 연산기 성능 및 소프트웨어 지원 | 시스템 병목 해소 지점 |
| 적합 모델 | 복잡한 제어 루틴 모델 | 행렬 연산 위주의 대규모 모델 | AI 알고리즘 유형 |

> 요약: 단순 반복 연산이 많은 AI 워크로드에서 데이터 이동 비용을 제거하여 성능과 효율을 동시 확보한다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | PNM (Processing Near Memory) | PIM (Processing In Memory) | 기술적 차이 |
|:---|:---|:---|:---|
| 연산 위치 | 메모리 모듈(DIMM)이나 기판 위 | 메모리 다이(Die) 내부 | 물리적 거리 및 집적도 |
| 구현 난이도 | 상대적 낮음 (범용 칩 활용) | 매우 높음 (DRAM 공정 수정) | 제조 공정 복잡도 |
| 성능 잠재력 | 중간 | 매우 높음 (내부 대역폭 최대 활용) | 데이터 이동 거리 |

> 요약: PNM은 메모리 '근처'에서, PIM은 메모리 '안'에서 처리하는 개념으로, PIM이 궁극의 전력 효율을 갖는다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| Memory Capacity | 연산기 점유 면적으로 용량 감소 | 적층 기술(HBM) 활용, 미세 공정 | 단위 면적당 용량 손실비 |
| Thermal Issue | 메모리 내 연산으로 인한 발열 | 방열 설계 최적화, 저전력 회로 | DRAM 리프레시(Refresh) 안정성 |
| Programming Model | 새로운 명령어 체계 적응 필요 | 표준 컴파일러(LLVM 등) 지원 강화 | 개발자 생산성 (Time-to-Code) |

> 요약: 메모리 용량 손실과 발열 문제를 해결하기 위해 HBM 적층 기술과의 결합이 활발히 진행 중이다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 가속 성능 (Speedup) | 기존 대비 2.0배 이상 개선 | AI 추론 벤치마크 (BERT, GPT 등) |
| 전력 절감률 | 시스템 전체 전력 70% 감소 | 와트당 성능 (Performance per Watt) |
| 신뢰성 (RAS) | 일반 DRAM 수준의 데이터 무결성 | 가속 수명 테스트 및 에러율 측정 |

> 요약: 도입 성과는 실제 AI 서비스의 지연 시간 단축과 데이터센터 전력 요금 절감액으로 검증한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. **거대 언어 모델(LLM) 추론**: 챗봇 답변 생성 시 빈번하게 발생하는 가중치 이동을 PIM으로 대체하여 에너지 효율 80% 향상
2. **추천 시스템(RecSys)**: 수조 개의 임베딩 데이터를 처리해야 하는 추천 엔진에 PIM을 적용하여 데이터 전송 병목 제거
3. **온디바이스 가속**: 스마트폰 내 NPU와 PIM 메모리를 연동하여, 배터리 소모를 최소화하면서 상시 대기형 AI(Always-on) 구현

**결론 (2줄):**
- 기술사 판단: PIM은 70여 년간 유지된 폰 노이만 아키텍처를 뒤흔드는 'Post-Von Neumann'의 선두 주자이며, 메모리 반도체의 패러다임을 '저장'에서 '연산'으로 바꿀 것이다
- 향후 방향: 메모리 업체와 팹리스 간의 설계 통합이 가속화되며, 메모리 자체가 지능을 가진 'Intelligent Memory'로 진화할 전망이다
