# 📖 【암기용】 개념 완전 이해

> 목적: DID를 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 중앙 기관(정부, 포털 등)을 거치지 않고 개인이 스스로 자신의 신원을 증명하고 관리하는 차세대 디지털 신분증 기술
- **왜 필요한가**: 구글이나 카카오 로그인은 편리하지만 내 개인정보가 그들에게 종속되어 있고, 서버가 뚫리면 내 정보가 다 털리기 때문. 내 정보를 내가 직접 소유하고(자기주권) 필요한 것만 골라 증명하기 위해 필요함.
- **핵심 직관**: "스마트폰 지갑 속의 디지털 신분증" — 지갑에 주민등록증을 넣어 다니며 술집에서 나이만 보여주듯, 디지털 세상에서도 내 정보를 내 폰에 담아두고 필요할 때만 꺼내 보여주는 것

## 깊이 이해
- **배경·문제의식**: 디지털 환경에서의 신원 확인은 주로 대형 플랫폼에 의존(Centralized/Federated)해 왔음. 이로 인한 사생활 침해, 데이터 독점, 단일 장애점(SPOF) 문제를 해결하기 위해 '자기주권 신원증명(SSI)' 철학이 등장함.
- **작동 원리**: W3C 표준인 **DID**와 **VC(Verifiable Credential)**가 핵심임. ① 발행기관이 나에게 디지털 증명서(VC)를 주면, ② 나는 내 폰(지갑)에 저장함. ③ 서비스 이용 시 지갑에서 증명서를 꺼내 제출하고, ④ 서비스 업체는 블록체인에 등록된 발행기관의 공개키를 확인해 위조 여부만 검증함. 이 과정에서 중앙 서버를 거칠 필요가 없음.
- **비유**: 대학교에서 졸업증명서를 종이로 떼어 내 가방에 넣고 다니는 것과 같음. 취업할 때 회사에 그 종이를 보여주면, 회사는 대학교에 전화하지 않고도 도장(디지털 서명)만 보고 진짜인지 알 수 있음.
- **구체 예시**: 모바일 운전면허증, 백신 접종 증명 앱(COOV), 사원증 앱 등이 대표적인 DID 사례임.
- **흔한 오해·주의점**: 블록체인에 '내 이름과 주민번호'가 기록되는 게 아님. 블록체인에는 "이 정보를 인증해준 기관의 도장(공개키)"만 올라감. 실제 개인정보는 오직 내 스마트폰에만 저장됨.

## 연결 개념
- SSI (Self-Sovereign Identity) — DID가 지향하는 '자기주권 신원' 철학
- VC (Verifiable Credential) — DID 시스템에서 주고받는 '검증 가능한 자격증명'
- W3C DID Standard — 전 세계적으로 통용되는 DID 기술 표준

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 자기주권 신원증명(SSI) 모델의 3대 주체(Issuer, Holder, Verifier)와 DID 문서(DID Document) 구조를 기술한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 중앙 집중형 신원 관리 체계에서 벗어나 개인이 자신의 개인정보를 직접 소유, 관리하고 선택적으로 제출하는 블록체인 기반의 분산 신원 확인 체계다.
> 2. **가치**: 데이터 주권(SSI) 회복, 개인정보 오남용 방지, 단일 장애점(SPOF) 제거 및 서비스 간 상호운용성(Interoperability)을 제공한다.
> 3. **판단 포인트**: W3C 표준 준수 여부와 개인정보 오프체인(Off-chain) 저장 원칙, 그리고 데이터의 무결성을 보증하는 DID 문서(DID Document)의 신뢰성이 핵심이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| DID의 개념 및 필요성 이해 확인 | 자기주권 신원(SSI), 중앙화 문제 해결 | 단순 블록체인 기반 인증으로만 서술 |
| 기술적 구성요소 및 동작 아키텍처 파악 | Issuer, Holder, Verifier, VC, VP, DID Document | 개인정보가 블록체인에 저장된다고 기술 |
| 표준 및 보안 사항 인지 능력 | W3C 표준, 공개키 기반 구조(PKI), 정보 선택적 노출 | 표준 규격(DID Document)의 역할 누락 |

> 요약: DID는 '정보의 저장'은 사용자 기기에, '신뢰의 검증'은 블록체인에 두는 분산형 신뢰 모델이다.

## Ⅰ. 개요 및 필요성

- 정의: 중앙 기관 없이 블록체인을 통해 개인의 신원을 증명하고, 사용자가 스스로 정보를 통제하는 자기주권 신원증명(SSI) 기술
- 배경: 거대 플랫폼의 개인정보 독점 및 유출 사고 증가, 신뢰 비용 상승, 온라인 신원 확인의 파편화 해결 필요
- 필요성: 개인정보 자기결정권 강화, 비대면 서비스의 신뢰성 확보, 상이한 서비스 간 연합 신원 체계(Federation) 구축

## Ⅱ. 구조 및 구성요소 (SSI 트러스트 모델)

```text
[ Issuer (발행자) ] --(VC: 증명서 발행)--> [ Holder (보유자/사용자) ]
        |                                       |
  (DID 등록: PK)                          (VP: 증명서 제출)
        v                                       v
[ Blockchain (DID Registry) ] <--(검증)-- [ Verifier (검증자) ]
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Issuer (발행자) | 신원 정보를 검증하고 VC(Verifiable Credential)를 발행하는 기관 | 대학, 정부, 은행 등 |
| Holder (보유자) | 자신의 신원 정보를 스마트폰 지갑 등에 저장하고 관리하는 주체 | 일반 사용자 |
| Verifier (검증자) | 사용자가 제출한 신원 정보를 블록체인을 통해 검증하는 서비스 | 서비스 제공업체 |
| DID Document | 블록체인에 저장되는 공개키, 인증 수단 등이 포함된 메타데이터 | 개인정보 미포함 |
| VC / VP | 검증 가능한 자격증명(VC) 및 이를 묶어 제출하는 제출용 증명서(VP) | 전자서명 포함 |

> 요약: 발행자-보유자-검증자의 삼각 관계를 통해 중앙 서버 없이 신뢰를 형성하는 구조다.

## Ⅲ. 동작원리 및 흐름도

```text
DID 생성/등록 -> VC 발행 요청/수신 -> 신원 정보 저장 -> VP 생성/제출 -> 블록체인 기반 검증
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | DID 생성/등록 | 사용자가 자신의 공개키/개인키 쌍을 생성하고, 공개키를 블록체인에 등록 | DID Method 표준 준수 |
| 2 | 자격증명 발행 (VC) | 발행자가 사용자의 실명 정보를 확인 후 전자서명된 VC를 생성하여 전달 | 발행자의 전자서명 유효성 |
| 3 | 정보 관리 (Wallet) | 사용자는 전달받은 여러 VC를 자신의 디지털 지갑(App)에 안전하게 보관 | 지갑 보안성 (생체인증 등) |
| 4 | 증명서 제출 (VP) | 서비스 요구에 맞춰 필요한 정보만 골라(Selective Disclosure) VP 생성 후 제출 | 데이터 최소화 원칙 준수 |
| 5 | 신뢰 검증 | 검증자가 블록체인에서 발행자의 공개키를 가져와 VP의 서명을 검증 | 서명 무결성 확인 |

> 요약: 사용자가 직접 정보를 들고 다니며, 검증자는 블록체인을 '신뢰의 근거(Root of Trust)'로만 활용한다.

## Ⅳ. 특징

| 구분 | 중앙 집중형 (Centralized) | 분산형 (DID) |
|:---|:---|:---|
| 데이터 소유권 | 서비스 제공자 (IDP) | 사용자 본인 (Self-Sovereign) |
| 데이터 저장 | 중앙 서버 DB | 사용자 단말기 (Off-chain) |
| 개인정보 보호 | 유출 위험 상존, 수집 당함 | 필요한 정보만 선택적 제공, 유출 차단 |
| 상호운용성 | 타 서비스 연동 제한적 | 표준 준수 시 전 세계 서비스 통용 가능 |
| 신뢰 주체 | 특정 기관에 대한 신뢰 | 블록체인 시스템 및 물리 법칙 신뢰 |

> 요약: 서비스 중심의 신원 체계가 사용자 중심으로 재편되어 데이터의 흐름과 보안을 사용자가 통제한다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | FIDO (생체인증 표준) | DID (분산 신원 증명) | 선택 기준 |
|:---|:---|:---|:---|
| 목적 | 사용자 본인 확인 (로그인) | 신원 정보/자격 증명 (신분증) | 무엇을 증명할 것인가 |
| 데이터 성격 | 생체 템플릿 기반 인증값 | 성명, 학력, 자격 등 속성 정보 | 데이터의 재사용성 |
| 적용 범위 | 단일 서비스 또는 연합 서비스 | 범국가적/범산업적 신원 체계 | 인프라 확산 및 표준화 요구도 |

> 요약: FIDO는 '본인 확인' 수단으로, DID는 '신원 정보 전달' 수단으로 상호 결합하여 시너지를 낸다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 단말기 분실 | 개인정보가 담긴 지갑(폰) 분실 시 재발행 불편 | 소셜 복구, 백업 관리, 클라우드 암호화 저장 | 복구 성공률, 재발행 소요 시간 |
| 프라이버시 침해 | 블록체인 로그 분석을 통한 사용자 활동 추적 가능성 | 영지식 증명(ZKP) 도입, 일회용 DID 사용 | 트래픽 익명성 수준 |
| 상호운용성 부족 | 서로 다른 DID 메카니즘(Hyperledger, EOS 등) 간 파편화 | W3C 표준 엄격 준수, 유니버설 리졸버(Universal Resolver) | 이종 DID 간 교차 검증 성공률 |

> 요약: 사용자 편의성(분실 대응)과 기술적 파편화 문제를 해결하는 것이 대중화의 관건이다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 검증 응답 속도 | 3초 이내 (사용자 체감 기준) | 모바일 앱 실행 및 제출 로그 |
| 선택적 노출 지원 | 속성별 분리 제출 가능 여부 | VP 생성 시 데이터 마스킹 여부 |
| 블록체인 가용성 | DID Registry 가용성 99.9% 이상 | 블록체인 네트워크 업타임 |

> 요약: 도입 성과는 정보 제공의 선택권 보장 여부와 모바일 환경에서의 신속한 검증 성능으로 평가한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 모바일 운전면허증/공무원증: 오프라인 신분증을 DID 기반의 VC로 발급하여 편의성을 높이고, 편의점 성인인증 시 생년월일만 선택적으로 노출
2. 비대면 금융 거래 자동화: 은행, 보험사 간의 증명서(소득증명, 가입증명 등)를 DID로 유통하여 서류 제출 없는 즉시 대출 서비스 구현
3. 기업 보안 출입 통제: 사원증을 DID로 구현하여 출입 기록의 위변조를 방지하고, 파트너사 협업 시 한시적인 출입 자격 증명(VC) 배포

**결론 (2줄):**
- 기술사 판단: DID는 Web 3.0 시대의 데이터 주권을 실현하는 핵심 인프라며, 단순 인증을 넘어 '데이터 경제'의 신뢰 기반이 될 것이다
- 향후 방향: 영지식 증명(ZKP) 기술과 결합하여 개인정보 노출을 제로(Zero)화하는 '완전 익명 증명' 체계로 발전할 전망이다
