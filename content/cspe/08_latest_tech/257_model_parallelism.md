# 📖 【암기용】 개념 완전 이해

> 목적: 모델 병렬화를 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 거대 AI 모델의 가중치(Parameters)를 여러 조각으로 쪼개어 여러 대의 GPU가 나누어 저장하고 연산하게 하는 기술
- **왜 필요한가**: 모델이 너무 커서(예: GPT-3, Llama-3) GPU 한 대의 메모리에 다 들어가지 않기 때문이다. 데이터 병렬화만으로는 해결할 수 없는 '메모리 용량 부족' 문제를 해결한다.
- **핵심 직관**: "책 한 권(모델)이 너무 두꺼워 한 사람이 들 수 없을 때, 챕터별로 찢어서 여러 사람(GPU)에게 나눠주고 같이 읽게 하는 방식"

## 깊이 이해
- **배경·문제의식**: LLM 시대가 열리며 모델 크기는 수천억 개(Billion) 파라미터로 성장했다. 최신 GPU(H100) 메모리가 80GB라 해도, 수천억 개 모델을 학습시키려면 수 TB의 메모리가 필요하다. 따라서 모델 자체를 분할해야만 한다.
- **작동 원리**:
  1. **계층 병렬화(Inter-layer)**: 모델의 층(Layer)을 순서대로 잘라 GPU마다 다른 층을 맡긴다. (예: 1~10층은 GPU 0, 11~20층은 GPU 1)
  2. **텐서 병렬화(Intra-layer)**: 하나의 층 안에서 일어나는 행렬 연산(Matrix Multiplication) 자체를 쪼개어 여러 GPU가 동시에 계산하게 한다.
- **비유**: 거대한 벽화를 그릴 때, 왼쪽은 A가 오른쪽은 B가 그리는 것(텐서 병렬화)이나, 밑그림은 A가 채색은 B가 하는 것(계층 병렬화)과 같다.
- **구체 예시**: 175B 모델 학습 시, 8장의 GPU를 텐서 병렬화로 묶어 하나의 가상 GPU처럼 쓰고, 이를 여러 층으로 쌓아 파이프라인 병렬화를 적용한다.
- **흔한 오해·주의점**: "모델 병렬화를 쓰면 무조건 연산 속도가 빨라진다"는 틀렸다. 층별로 나누면 앞 사람이 끝내야 뒷 사람이 시작할 수 있는 대기 시간(Idle Time)이 생기기 때문에, 이를 잘게 쪼개는 파이프라인 기법이 병행되어야 한다.

## 연결 개념
- Tensor Parallelism (텐서 병렬화) — 모델 병렬화의 세부 기법 (수평적 분할)
- Pipeline Parallelism (파이프라인 병렬화) — 모델 병렬화의 세부 기법 (수직적 분할)
- ZeRO (Zero Redundancy Optimizer) — 모델 병렬화의 메모리 효율성을 극대화한 기술

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 모델 병렬화는 메모리 한계 극복이라는 '필연성'과 기법별(수직/수평) '분할 방식'을 중심으로 기술한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 모델 병렬화(Model Parallelism)는 거대 신경망의 파라미터와 연산을 분할하여 다수의 가속기(GPU)에 분산 배치함으로써 단일 장치의 메모리 용량 한계를 극복하는 기법이다.
> 2. **가치**: 파라미터 수가 수천억 개에 달하는 초거대 AI(Hyperscale AI) 학습 및 추론을 가능케 하는 필수 기반 기술이다.
> 3. **판단 포인트**: 연산 간 의존성에 따른 GPU 유휴 시간(Bubble)과 장치 간 통신 부하를 고려하여 텐서 병렬화와 파이프라인 병렬화의 혼합 비율을 결정해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 메모리 한계 극복 전략 파악 | 계층 간 분할(Vertical), 계층 내 분할(Horizontal) | 단순히 "모델을 나눈다"고만 서술 |
| 병렬화 기법별 트레이드오프 이해 | 텐서 병렬(고대역폭 필요) vs 파이프라인 병렬(대기 시간 발생) | 각 기법의 한계점과 보완책 누락 |
| 현대 초거대 모델 대응 역량 | Megatron-LM, DeepSpeed 등 프레임워크 연계 | 이론적 설명에 그치고 실무 기술명 누락 |

> 요약: 모델 분할 방식에 따른 두 가지 축(텐서, 파이프라인)과 이를 통한 메모리 효율성 확보 과정을 기술한다.

---

## Ⅰ. 개요 및 필요성

- 정의: 인공지능 모델의 가중치와 연산 과정을 물리적으로 분할하여 여러 컴퓨팅 노드에 분산 저장/연산하는 처리 기법
- 배경: 모델 크기가 GPU 단일 메모리(최대 80~141GB)를 수십 배 상회하는 LLM(Large Language Model) 시대 도래
- 필요성: 단일 장치 수용 불가 모델의 학습 가능성 확보 및 메모리 분산을 통한 대규모 배치 학습 지원

---

## Ⅱ. 구조 및 구성요소

```text
[모델 병렬화 유형 도식도]
1. 계층 병렬화 (Inter-layer)    2. 텐서 병렬화 (Intra-layer)
   Layer 1 -> GPU 0             Layer 1 [ Matrix A | Matrix B ]
   Layer 2 -> GPU 1                       |          |
   Layer 3 -> GPU 2                     GPU 0      GPU 1
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Tensor Sharding | 행렬 연산을 쪼개어 병렬 연산 수행 | 고속 인터커넥트(NVLink) 필수 |
| Layer Partitioning | 모델을 깊이(Depth) 기준으로 분할 | 통신 횟수는 적으나 순차 실행 한계 |
| Micro-batch | 파이프라인 효율을 높이기 위한 데이터 세분화 | Bubble(유휴 시간) 감소의 핵심 |
| Sync Primitive | 분할된 연산 결과 합산을 위한 통신 함수 | All-Reduce, All-Gather 등 사용 |

> 요약: 모델을 너비(텐서)나 깊이(계층)로 쪼개어 여러 GPU에 적재하고, 연산 결과를 조율하는 통신 계층이 포함된 구조다.

---

## Ⅲ. 동작원리 및 흐름도

```text
[동작 흐름: 텐서 병렬화 기준]
Input -> [Split Matrix] -> Parallel MatMul (GPU 0/1) -> [All-Reduce Result] -> Output
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 모델 가중치 행렬을 행(Row) 또는 열(Column) 단위로 분할 | 연산량 및 메모리 점유의 균등 분할 |
| 2 | 각 GPU가 분할된 가중치로 부분 연산 수행 | 중간 결과값의 정확성 유지 |
| 3 | 연산 완료 후 노드 간 통신을 통해 최종 결과 합산 | 통신 지연 시간이 연산 시간보다 짧아야 함 |
| 4 | 합산된 결과를 다음 계층의 입력으로 전달 | 데이터 일관성 및 정밀도(Precision) 유지 |

> 요약: 행렬 연산 자체를 여러 GPU가 나누어 풀고(Parallel), 그 부분 정답들을 모아(Sync) 다음 단계로 넘어가는 방식이다.

## Ⅳ. 특징

| 구분 | 텐서 병렬화 (Tensor) | 파이프라인 병렬화 (Pipeline) |
|:---|:---|:---|
| 분할 기준 | 단일 계층 내 연산 분할 | 계층(Layer) 간 분할 |
| 통신 빈도 | 매우 높음 (계층마다 발생) | 낮음 (배치/마이크로배치 단위) |
| 요구 사양 | 초고속 인터커넥트 (NVLink) | 일반 고속 네트워크 (InfiniBand) |
| 주요 제약 | 통신 오버헤드에 민감 | GPU 유휴 시간(Bubble) 관리 필요 |

> 요약: 텐서 병렬화는 노드 내(Intra-node) 고속 연결에 적합하고, 파이프라인 병렬화는 노드 간(Inter-node) 확장에 유리하다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 데이터 병렬화 (DP) | 모델 병렬화 (MP) | 선택 기준 |
|:---|:---|:---|:---|
| 목적 | 학습 속도 가속 (Throughput) | 거대 모델 적재 (Memory) | 모델 크기 및 메모리 가용량 |
| 분할 대상 | 학습 데이터 (Sample) | 모델 가중치 (Weight) | 병목 지점 (Compute vs Memory) |
| 구현 복잡도 | 낮음 (라이브러리 자동 처리) | 높음 (수동 분할 설계 필요) | 모델 아키텍처의 복잡성 |

> 요약: 모델이 메모리에 들어간다면 DP를 우선하고, 들어가지 않는다면 MP를 필수적으로 적용한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 성능 저하 | 통신 오버헤드가 연산 이득 초과 | 텐서 병렬화 그룹 크기 제한 (보통 8 이하) | Communication Latency vs Compute Time |
| GPU 유휴 | 파이프라인 대기 시간 발생 | 1F1B 알고리즘 및 마이크로배치 최적화 | Pipeline Bubble Ratio |
| 로드 불균형 | 층마다 연산량이 다를 경우 병목 | 프로파일링 기반의 균형 있는 계층 분할 | GPU-SM Utilization Variance |

> 요약: 통신 병목과 유휴 시간 리스크는 적절한 병렬화 하이브리드 설계(3D Parallelism)로 관리해야 한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 메모리 절감 | 단일 GPU 대비 1/N 수준 도달 | `nvidia-smi` 메모리 점유 확인 |
| 연산 효율 | MFU(Model Flops Utilization) 50% 이상 | 연산량 대비 실제 처리 속도 계산 |
| 통신 지연 | 총 연산 시간의 25% 이내 유지 | NCCL 및 프로파일링 도구 분석 |

> 요약: 메모리 분산도와 MFU 지표를 통해 모델 병렬화가 효율적으로 동작하는지 검증한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 3D Parallelism 구축: 데이터 병렬(DP) + 텐서 병렬(TP) + 파이프라인 병렬(PP)을 결합하여 수조 개의 파라미터 모델 학습 인프라 설계
2. Megatron-LM 기법 적용: 트랜스포머의 어텐션 및 MLP 계층에 텐서 병렬화를 적용하여 통신 횟수를 계층당 2회로 최소화
3. 선택적 활성화 재계산(Selective Activation Recomputation): 메모리 절약을 위해 중간 연산값을 버리고 필요 시 다시 계산하여 모델 병렬화 효율 보완

**결론 (2줄):**
- 기술사 판단: 모델 병렬화는 '규모의 경제'를 실현하는 초거대 AI의 핵심이며, 알고리즘적 우아함보다 하드웨어 토폴로지를 고려한 물리적 배치가 성능을 좌우한다
- 향후 방향: 하드웨어와 소프트웨어가 통합된 형태의 AI 반도체(PIM)와 결합하여, 통신 비용을 제로에 가깝게 줄이는 방향으로 진화할 것이다
