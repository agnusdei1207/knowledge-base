# 📖 【암기용】 개념 완전 이해

> 목적: 모델 크기가 단일 GPU 메모리를 초과할 때, 이를 어떻게 잘라서 여러 대의 GPU에 욱여넣는지(그리고 왜 이것만으론 부족한지) 그 원초적인 접근법을 이해한다.

## 한눈에
- **정의**: 데이터가 아니라 **'AI 모델(신경망 네트워크)' 자체를 여러 조각으로 물리적으로 쪼개어**, 서로 다른 GPU의 메모리에 나누어 올린 뒤 연결해서 학습시키는 분산 학습 기법
- **필요성**: 거대 언어 모델(GPT 등)의 크기가 300GB~1TB에 달하면서, 아무리 크고 비싼 GPU(예: 80GB VRAM) 한 대를 가져와도 아예 모델을 올릴(Load) 수조차 없는 '메모리 한계(Memory Wall)'를 극복하기 위함
- **핵심 직관**: "데이터 병렬화가 '1만 페이지짜리 번역(데이터)을 10명이 똑같은 사전(모델)을 들고 나눠서 하는 것'이라면, 모델 병렬화는 '너무 두꺼워서 들 수조차 없는 1만 쪽짜리 사전(모델)을 10권으로 찢어서 10명이 나눠 든 뒤, 옆 사람에게 물어가며 번역하는 것'"

## 깊이 이해
- **배경(왜 등장했나?)**: 예전에는 모델이 작아서 무조건 '데이터 병렬화(DP)'만 썼다. 그런데 파라미터가 1,000억 개를 넘어가자, 가중치와 옵티마이저만 저장해도 단일 GPU 메모리(VRAM)가 터져버렸다(OOM, Out of Memory). "데이터를 쪼갤 게 아니라, 모델의 신경망 층(Layer) 자체를 쪼개서 이웃집 GPU에 넘기자"라는 고육지책이 모델 병렬화다.
- **작동 원리(어떻게 달성했나?)**: 
  1. 100층짜리 딥러닝 모델이 있다면, 1~50층은 GPU 1에 올리고, 51~100층은 GPU 2에 올린다(파이프라인 병렬화의 시초).
  2. 또는 한 층(Layer)에 있는 1만 개의 뉴런(행렬)을 반으로 뚝 잘라, 뉴런 5,000개는 GPU 1에, 나머지 5,000개는 GPU 2에 올린다(텐서 병렬화의 시초).
- **일상 비유**: 자동차 조립 공정에서 '차량 도면(모델)'이 너무 방대하다. 차체 프레임, 엔진, 바퀴, 도색 파트를 한 공장(GPU 1대)에 다 구겨 넣을 수 없으니, 공장 4개를 일렬로 세우고 공장 1은 차체만, 공장 2는 엔진만 만들어서 옆 공장으로 컨베이어 벨트를 넘겨주는 것이다.
- **구체 예시**: 초창기 모델 병렬화는 코드 레벨에서 `model.layer1.to('cuda:0')`, `model.layer2.to('cuda:1')`처럼 개발자가 수동으로 층을 잘라서 GPU에 할당했다.
- **흔한 오해/주의점**: "모델 병렬화(MP)는 완벽한가?" → 아니다. 치명적인 단점이 있다. GPU 1이 1~50층을 계산하는 동안, GPU 2는 **계산할 값이 안 넘어와서 멍하니 놀고 있어야 한다(GPU Bubble)**. 즉, 메모리 부족을 해결하기 위해 어쩔 수 없이 모델을 쪼갰지만, 연산 효율은 바닥으로 떨어지는 문제가 발생한다.

## 연결 개념
- **Pipeline Parallelism (파이프라인 병렬화)**: 모델 병렬화의 치명적 단점인 '쉬는 시간(Bubble)'을 줄이기 위해 데이터를 파이프라인처럼 잘게 쪼개어 연속으로 흘려보내는 진화된 형태
- **Tensor Parallelism (텐서 병렬화)**: 모델을 '층(Layer)' 단위가 아니라 수학적인 '행렬 연산(Tensor)' 단위로 쪼개어 여러 GPU가 동시에 계산하게 만드는 또 다른 진화 형태
- **Data Parallelism (데이터 병렬화)**: 모델이 작을 때 쓰는 방식. 모델 병렬화와 반대되는 개념이자, 현대 거대 모델에서는 두 방식을 모두 합쳐서(3D 병렬화) 쓴다.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 모델 병렬화(Model Parallelism)는 단일 GPU 메모리에 적재할 수 없는 대규모 DNN 모델을 층(Layer) 단위나 행렬(Tensor) 단위로 분할하여 다수의 가속기(GPU)에 분산 배치하는 훈련 기법이다.
> 2. **가치**: 모델 크기에 비례하여 증가하는 VRAM 메모리 장벽(Memory Wall)을 타파하여, 수백억~수조 개의 파라미터를 가진 초거대 언어 모델(LLM)의 물리적 학습(Load & Train)을 가능케 한다.
> 3. **판단 포인트**: 순진한(Naive) 모델 병렬화는 심각한 GPU 유휴 시간(Bubble)과 노드 간 통신 병목을 유발하므로, 이를 최적화한 **파이프라인 병렬화(PP)**와 **텐서 병렬화(TP)**의 세부 개념으로 분화 및 발전해야 한다.

## Ⅰ. 개요 및 필요성
- **정의**: 거대한 신경망 모델 파라미터와 옵티마이저 상태, 활성화 함수(Activation) 결과물 등을 분할(Partitioning)하여 여러 장의 GPU 메모리에 나누어 적재하고 연산하는 분산 훈련 구조
- **배경**: GPT-3(175B 파라미터) 학습 시 최소 800GB 이상의 메모리가 필요하여, 현존 최고 사양 GPU(80GB) 한 대로는 OOM(Out of Memory) 에러가 발생하여 훈련 자체가 원천 불가함
- **필요성**: 단일 디바이스의 물리적 메모리 한계 극복, 수십 대 이상의 GPU VRAM 공간을 합쳐서 하나의 거대한 논리적 메모리 공간으로 활용

## Ⅱ. Data Parallelism vs Model Parallelism 아키텍처 비교
| 구분 | Data Parallelism (데이터 병렬화) | Model Parallelism (모델 병렬화) |
|:---|:---|:---|
| **분할 대상** | 훈련용 데이터 (미니배치) | **모델 신경망 그 자체 (파라미터/레이어)** |
| **적재 상태** | 모든 GPU가 전체 모델을 동일하게 보유 | **GPU마다 각기 다른 모델 조각을 보유** |
| **통신 시점** | 역전파(Backward) 후 Gradient 동기화 시 | **순전파/역전파 중간 (레이어 경계 이동 시)** |
| **도입 목적** | 학습 연산 속도(시간) 단축 | **물리적인 VRAM 메모리 한계(OOM) 극복** |

## Ⅲ. Naive Model Parallelism의 작동 구조와 한계
가장 초보적인 모델 병렬화(Naive MP)는 신경망의 층(Layer)을 수직으로 쪼개어 다른 기기에 배치한다.

```text
[ 데이터 입력 ]
      │
   (GPU 0) ──> Layer 1, 2, 3 연산 중... (GPU 1은 할 일이 없어 대기 중)
      │
   (GPU 0에서 계산된 활성화 값 전송) ──> 통신 병목 발생!
      │
   (GPU 1) ──> Layer 4, 5, 6 연산 시작... (이때 GPU 0은 할 일이 없어 대기 중)
      │
[ 최종 결과 ]
```

- **한계 1. 극심한 버블(Bubble) 발생**: 구조상 이전 레이어의 출력이 다음 레이어의 입력이 되므로(Sequential), 하나의 GPU가 연산하는 동안 나머지 GPU는 데이터가 올 때까지 무조건 쉬어야(Idle) 한다.
- **한계 2. 병렬화 효율 저하**: 4대의 GPU를 써도, 1대의 GPU가 계산할 때 나머지 3대는 대기하므로 실제 연산 처리량(Throughput)은 1대와 다를 바 없다.
- **한계 3. 통신 오버헤드**: 레이어 경계를 넘어갈 때마다 막대한 양의 활성화 값(Activation) 텐서를 PCIe나 NVLink를 타고 넘겨주어야 한다.

## Ⅳ. 모델 병렬화의 진화: PP와 TP로의 분화
순진한 모델 병렬화의 버블(Bubble) 한계를 극복하기 위해, 현대 LLM 훈련 아키텍처는 모델 병렬화를 두 가지 세부 기술로 진화시켰다.

1. **Pipeline Parallelism (파이프라인 병렬화, PP)**
   - **개념**: 층(Layer) 단위로 자르는 것은 같으나, 입력 데이터(배치)를 다시 마이크로배치(Micro-batch)라는 잘게 쪼갠 덩어리로 만들어 쉼 없이 흘려보낸다.
   - **효과**: GPU 1이 첫 번째 조각을 GPU 2로 넘기자마자, 쉬지 않고 곧바로 두 번째 조각 연산을 시작하므로 버블(Idle)을 극적으로 줄인다.
2. **Tensor Parallelism (텐서 병렬화, TP)**
   - **개념**: 층 단위로 수직으로 자르는 게 아니라, 하나의 층 내부의 거대한 행렬(Matrix) 곱셈 연산을 수평으로 잘라서 분담한다 (예: 행 기반 분할, 열 기반 분할).
   - **효과**: 두 GPU가 행렬 연산을 동시에 병렬적으로 수행하므로 대기 시간(Bubble)이 아예 발생하지 않는다. 단, 노드 간 통신이 극도로 빈번하므로 단일 서버 내부(NVLink)에서만 유효하다.

## Ⅴ. 실무 적용 및 결론
**적용 방안 및 실무 가이드:**
1. **메가트론-LM (Megatron-LM) 적용**: 엔비디아가 개발한 Megatron-LM 라이브러리를 활용하면, 개발자가 수동으로 모델을 쪼갤 필요 없이 거대 언어 모델 트랜스포머(Transformer) 블록에 대한 텐서 병렬화와 파이프라인 병렬화가 자동으로 적용된다.
2. **3D 병렬화 (3D Parallelism) 아키텍처 설계**: 1,000억 파라미터 이상의 초거대 AI 학습 시에는 **DP, TP, PP 3가지를 모두 곱해서(혼합해서) 사용**한다. 서버 내부의 8개 GPU는 통신이 빠른 TP로 묶고, 랙(Rack) 내 서버 간에는 PP로 묶으며, 전체 데이터센터 랙 간에는 DP로 확장하여 수만 대의 GPU를 풀가동한다.

**결론:**
- 초창기 모델 병렬화는 단일 GPU 메모리 부족(Memory Wall)을 피하기 위한 임시방편(Workaround)에 불과하여 끔찍한 연산 효율(Bubble)을 보였다.
- 하지만 현재는 파이프라인(PP) 및 텐서 병렬화(TP)라는 정교한 아키텍처로 진화하여, GPT-4, Llama 3 등 세상을 바꾸는 **초거대 AI 모델 학습을 물리적으로 지탱하는 근간(Foundation)**이 되었다.
