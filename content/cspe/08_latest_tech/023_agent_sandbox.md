# 📖 【암기용】 개념 완전 이해

> 목적: 에이전트 샌드박스를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: 에이전트의 코드 실행·파일 접근·네트워크 호출을 격리하는 실행 환경
- **왜 필요한가**: AI가 생성한 코드나 도구 호출은 악성 입력, 무한 실행, 데이터 유출 위험이 있음.
- **핵심 직관**: 샌드박스는 AI에게 실험실을 주되 회사 전체 시스템에는 바로 닿지 못하게 하는 격리벽임.

## 깊이 이해
- **배경·문제의식**: Agent가 코드 실행기, 셸, 브라우저, API를 사용하면 프롬프트 인젝션이 실제 명령 실행으로 이어질 수 있음.
- **작동 원리**: 컨테이너, VM, seccomp, 네트워크 정책, 파일시스템 권한으로 실행 범위를 제한하고 자원 한도를 둠.
- **비유**: 신약 실험을 일반 병동이 아니라 통제된 실험실에서 수행하는 구조.
- **구체 예시**: 코드 분석 Agent가 읽기 전용 repo mount, CPU 2코어, 메모리 4GB, 외부망 차단 환경에서 테스트를 실행함.
- **흔한 오해·주의점**: 샌드박스는 완전한 보안이 아니라 피해 범위 제한이며 이미지 취약점과 탈출 공격을 점검해야 함.

## 연결 개념
- Container Isolation — 실행 격리 기반
- Zero Trust — 기본 불신과 최소권한
- Model DoS — 자원 고갈 공격 통제

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Agent Sandbox는 AI 실행 환경을 컨테이너·VM·정책으로 격리해 피해 범위를 제한하는 구조임.
> 2. **가치**: 코드 실행, 파일 접근, 네트워크 호출에서 데이터 유출과 시스템 손상을 줄임.
> 3. **판단 포인트**: 파일 권한, 네트워크 egress, 자원 한도, 실행시간, 이미지 취약점 점검이 핵심임.

---

## Ⅰ. 개요 및 필요성

- 개요: AI 실행 격리 환경
- 배경: AI Agent가 코드와 도구를 실행하면 파일 변경·네트워크 호출·데이터 유출·자원 고갈 위험이 발생함.
- 필요성: container, seccomp, network policy, CPU/memory limit으로 실행 권한과 자원 사용량을 제한해야 함.

---

## Ⅱ. 구조 및 구성요소

```text
Agent Task -> Sandbox Runtime -> Policy Guard -> Limited Resources


   코드/명령       컨테이너/VM      권한/망통제       CPU/Mem/Time
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Runtime | 격리 실행 환경 | container, VM, WASM |
| Policy Guard | 파일·네트워크 통제 | allowlist, egress 차단 |
| Resource Limit | 자원 사용 제한 | CPU, Memory, timeout |
| Monitor | 실행 관측·중단 | syscall, 로그, 알림 |

> 요약: 샌드박스는 런타임 격리, 정책통제, 자원한도, 실행감시로 구성됨.

---

## Ⅲ. 동작원리 및 흐름도

```text
작업 수신 -> 격리환경 생성 -> 권한·자원 설정
        -> 실행 감시 -> 결과 추출 -> 환경 폐기
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 실행환경 생성 | 이미지 서명, CVE 스캔 |
| 2 | 권한·자원 제한 | read-only, CPU, memory |
| 3 | 작업 실행·감시 | syscall, 네트워크, timeout |
| 4 | 결과 반환·폐기 | 마스킹, 로그, cleanup |

> 요약: 샌드박스는 실행 전 제한을 걸고 실행 후 환경을 폐기해 잔류 위험을 줄임.

---

## Ⅳ. 특징

| 구분 | 직접 실행 | Agent Sandbox | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 권한 | 호스트 권한 노출 | 격리 권한 | read-only, UID |
| 네트워크 | 자유 접근 | egress allowlist | 차단 건수 |
| 자원 | 무제한 가능 | CPU·Mem·시간 제한 | timeout, OOM 건수 |

> 요약: 샌드박스는 실행 피해 범위를 제한하지만 탈출 취약점과 이미지 관리를 지속 점검해야 함.

---

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 기본값은 외부망 차단, 읽기 전용 파일시스템, 비특권 사용자, seccomp/AppArmor 적용
2. 작업별 CPU·메모리·실행시간·디스크 한도를 설정하고 초과 시 자동 중단
3. 실행 이미지 서명검증, SBOM, CVE 스캔, 실행로그 SIEM 연계를 운영 절차로 포함

**결론 (2줄):**
- 기술사 판단: 코드 실행·브라우징·파일처리 Agent는 샌드박스 없이는 운영환경 접근을 허용하지 않음.
- 향후 방향: Agent Sandbox는 AI Gateway, Policy Engine, Confidential Computing과 결합해 안전한 실행 계층으로 발전함.

### 🔀 문제 유형별 목차 전환 (이 키워드 출제 시)

| 유형 | 문제 신호어 | Ⅲ 강조 | Ⅳ 강조 |
|:---|:---|:---|:---|
| 포괄형 | 설명하시오, 기술하시오 | 생성-제한-감시-폐기 흐름 | 직접 실행 대비 차이 |
| 요구사항 명시형 | 보안대책을 제시하시오, 설계하시오 | 네트워크·자원·파일 통제 | 탈출·데이터유출 방지 |

> 요약: 설명형은 격리 구조, 보안형은 실행 권한과 자원 제한을 중심으로 작성함.
