# 📖 【암기용】 개념 완전 이해

> 목적: LLM09 Misinformation을 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **정의**: LLM이 사실과 다른 정보, 근거 없는 주장, 잘못된 권고를 확신 있게 생성해 사용자 의사결정을 왜곡하는 위험
- **왜 필요한가**: 생성형 AI 답변은 자연스럽지만 출처와 검증 없이 의료·금융·법무·운영 의사결정에 쓰이면 피해가 발생함.
- **핵심 직관**: 말투는 전문가처럼 보이지만 사실 검증이 빠지면 틀린 지도를 자신 있게 주는 문제임.

## 깊이 이해
- **배경·문제의식**: LLM은 다음 토큰 확률로 문장을 생성하므로 모르는 내용도 그럴듯하게 구성할 수 있고, RAG 검색 실패도 오답으로 이어짐.
- **작동 원리**: 학습 데이터 오류, 오래된 지식, 검색 누락, 과도한 추론, 출처 없는 요약이 결합되어 hallucination과 misinformation이 발생함.
- **비유**: 길을 모르는 안내원이 모른다고 말하지 않고 비슷한 지명을 섞어 길을 알려주는 상황임.
- **구체 예시**: 운영 자동화 챗봇이 존재하지 않는 Kubernetes 옵션을 권고해 장애 대응 시간이 30분 증가.
- **흔한 오해·주의점**: RAG를 붙이면 자동 해결되는 것이 아니다. 검색 품질, 출처 표시, confidence, human review가 필요함.

## 연결 개념
- Hallucination — 근거 없는 생성 현상
- RAG Evaluation — 검색·답변 근거 품질 평가
- Human-in-the-loop — 고위험 답변 검토

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: LLM09는 LLM이 부정확하거나 근거 없는 정보를 생성해 의사결정을 왜곡하는 위험임.
> 2. **가치**: 고위험 분야에서 오정보는 법적 책임, 안전 사고, 운영 장애로 연결됨.
> 3. **판단 포인트**: 출처 기반 답변, confidence, 검증 워크플로, 금지 도메인 정책을 적용해야 함.

## Ⅰ. 개요 및 필요성

LLM09는 오정보 생성 위험이다. LLM 답변은 자연스럽지만 항상 사실을 보장하지 않는다. 고위험 업무는 근거 검증과 사람 검토가 필요하다.

## Ⅱ. 구조 및 구성요소

```text
User Query → LLM/RAG Generation → Evidence Check
  → Risk Classification → Answer/Review
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Knowledge Source | 학습지식·RAG 문서 | 최신성·출처 |
| Generation | 답변 생성 | hallucination 가능 |
| Evidence Check | 인용·근거 일치 검증 | citation required |
| Review Gate | 고위험 답변 승인 | human review |

> 요약: LLM09 대응은 생성 답변을 근거 문서와 대조하고 위험 등급에 따라 검토 절차를 적용함.

## Ⅲ. 동작원리 및 흐름도

```text
질문 분류 → 근거 검색 → 답변 생성
  → 사실성 평가 → 제공 또는 검토
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 의료·법무·금융 등 고위험 질의 분류 | domain classifier |
| 2 | 신뢰 출처 검색·인용 생성 | citation coverage ≥95% |
| 3 | 답변-근거 일치성 평가 | faithfulness score |
| 4 | 위험 답변 검토·거부 처리 | critical 오류 0건 |

> 요약: LLM09 방어는 질문 위험도, 근거 검색, 사실성 평가, 사람 검토를 단계화함.

## Ⅳ. 특징

| 구분 | 일반 오류 | LLM09 Misinformation | 판단 포인트 |
|:---|:---|:---|:---|
| 표현 | 오류가 드러남 | 확신 있는 자연어 | 신뢰 착시 |
| 원인 | 데이터·로직 결함 | hallucination·검색 실패 | 근거 검증 |
| 피해 | 기능 실패 | 의사결정 왜곡 | 고위험 도메인 |
| 방어 | 테스트 수정 | citation·eval·review | 책임 체계 |

> 요약: LLM09는 단순 오답보다 사용자가 신뢰하기 쉬운 확신형 오정보라는 점에서 별도 통제가 필요함.

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 출처 기반 답변: 정책·기술 문서는 RAG 인용을 필수화하고 citation coverage 95% 미만이면 답변 보류
2. 평가 자동화: faithfulness, answer relevance, factual consistency를 회귀 테스트에 포함하고 critical 오류 0건 기준 적용
3. 고위험 차단: 의료·법률·금융 조언은 disclaimer와 human review를 적용하고 자동 실행·최종 판단 금지

**결론 (2줄):**
- 기술사 판단: LLM09는 모델 품질 문제가 아니라 의사결정 통제 문제로 보고 출처·검증·책임 경계를 설계
- 향후 방향: LLM09 대응은 RAG 평가, 콘텐츠 출처 표준, AI 거버넌스 KPI와 결합됨
