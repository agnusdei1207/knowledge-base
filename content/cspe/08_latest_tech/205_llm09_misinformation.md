# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: OWASP LLM Top 10의 취약점으로, 사용자가 AI가 뱉어내는 **사실이 아니거나 잘못된 정보(환각, 환영), 심지어 악의적인 코드 등을 아무런 의심이나 검증 없이 맹신(Overreliance)하여 그대로 실무에 가져다 쓰다가 발생하는 재앙적 사고**.
- **필요성**: LLM은 "정답"을 찾는 기계가 아니라, "그럴싸한 다음 단어"를 통계적으로 예측하는 기계임. 따라서 세종대왕이 맥북을 던진 사건 같은 헛소리(Hallucination)를 매우 당당하게 전문가처럼 말함. 개발자가 AI가 짜준 코드를 안 보고 서버에 올리거나, 의사가 AI 진단을 무작정 믿으면 회사가 망하거나 사람이 죽을 수 있음.
- **핵심 직관**: 사기꾼 내비게이션 믿고 절벽으로 직진하기. 운전자(사용자)가 엄청나게 똑똑해 보이는 최신 내비게이션(AI)을 샀음. 이 내비게이션이 지도에 없는 엉뚱한 길(오정보)을 자신만만하게 안내함. 운전자는 창밖을 확인(검증)하지 않고 내비를 '과도하게 맹신(Overreliance)'하여 엑셀을 밟았다가 결국 절벽으로 추락함.

## 깊이 이해
- **배경**: 챗GPT 등장 초기, AI의 뛰어난 작문 실력과 권위적인 말투에 압도된 사용자들이 AI의 결과물을 팩트체크 없이 법정, 의료 현장, 소프트웨어 개발에 남용하면서 엄청난 부작용들이 폭발적으로 발생함.
- **작동 원리 (왜 속고 어떻게 당하는가)**:
  1. **환각 (Hallucination)**: 모델 학습 데이터의 공백이나 통계적 오류로 인해 아예 존재하지 않는 사실, 가짜 논문, 가짜 판례를 창작함. 말투가 너무 논리적이라 사람이 속아 넘어감.
  2. **가짜 라이브러리 유도 (AI Package Hallucination)**: 프로그래머가 AI에게 코드를 짜달라고 함. AI가 코드를 짜주면서 "pip install requests_utils" 같은 가상의 패키지를 임포트하라고 함. 이 사실을 미리 안 해커가 저 이름으로 실제 악성 패키지를 만들어 올려둠. 개발자는 맹신하고 설치했다가 해킹당함.
  3. **의사결정 왜곡**: 경영자나 투자자가 AI가 요약해 준 잘못된 보고서 수치를 맹신하고 수십억 원의 투자 결정을 내려 파산함.
- **구체 예시**: 뉴욕 변호사 사건 (2023). 한 변호사가 챗GPT에게 과거 유사한 법원 판례를 찾아달라고 함. 챗GPT는 "Varghese v. China Southern Airlines" 등 그럴싸한 판례 6건을 창작(환각)해 냄. 변호사는 이를 맹신(Overreliance)하여 실제 재판부 판사에게 제출서류로 냈고, 판사가 "이런 판례는 세상에 없다"고 밝혀내어 변호사는 징계를 받고 망신을 당함.
- **흔한 오해/주의점**: "모델 크기를 키우고 RAG를 쓰면 환각이 아예 0%가 되지 않나요?" $\rightarrow$ 아님. RAG(검색 증강)를 쓰면 크게 줄일 수는 있지만, 딥러닝의 태생적 구조(생성형)상 환각은 수학적으로 0%가 될 수 없음. 결국 사람이 검증하는 체계(HITL)가 유일한 해결책임.

## 연결 개념
- **Hallucination (환각)**: LLM이 그럴싸한 거짓말을 만들어내는 현상. Overreliance(과도한 의존)는 이 환각을 인간이 무비판적으로 수용할 때 터지는 사고.
- **Grounding (그라운딩 / 사실 근거화)**: AI가 헛소리를 못 하도록, "반드시 내가 준 위키피디아 문서 안에서만 답변해"라고 닻(Ground)을 내려주는 기술 (RAG의 핵심 요소).
- **Zero Trust (제로 트러스트)**: AI의 답변 역시 검증되기 전까지는 거짓으로 간주하라는 보안의 기본 원칙.

# 📝 【답안용】 시험 답안 템플릿
## 핵심 인사이트 (3줄 요약)
- **본질**: 거대 언어 모델(LLM)이 확률론적 특성으로 인해 허위 정보(Misinformation)나 환각(Hallucination)을 확신에 찬 언어로 생성할 때, 사용자가 결과물의 정확성과 무결성을 교차 검증하지 않고 맹신(Overreliance)하여 비즈니스 및 보안 임팩트를 초래하는 인적/시스템적 취약점.
- **가치**: 이 취약점은 단순한 해프닝을 넘어, 존재하지 않는 악성 오픈소스 패키지 호출(AI Package Hallucination 공격), 잘못된 의료/법률 자문에 의한 생명 및 컴플라이언스 위반 리스크로 직결되는 사회공학적 성격을 띰.
- **판단 포인트**: LLM 자체가 완벽한 사실 검증(Fact-check) 엔진이 될 수 없음을 인정하고, 서비스 UI 상의 출처(Citation) 표기 강제, 교차 검증(Grounding) 아키텍처, 그리고 안전 민감형(Safety-critical) 작업에서 Human-in-the-Loop(HITL) 체계를 필수 적용해야 함.

## Ⅰ. 개요 및 필요성
- **정의**: 사용자가 LLM이 생성한 코드, 데이터 요약, 조언 등을 적절한 모니터링이나 권위 있는 출처(Authoritative Source) 대조 없이 그대로 채택하고 실행하여 발생하는 소프트웨어 결함 및 비즈니스 의사결정 오류.
- **배경**: LLM은 입력 문맥과 확률적 언어 모델링(Next-token Prediction)에 따라 작동하므로 구문론적(Syntax)으로는 완벽하지만 의미론적/사실적(Semantic/Factual)으로는 거짓인 결과를 빈번하게 생성함. 인간의 '자동화 편향(Automation Bias)'이 이를 가속화함.
- **필요성**: OWASP LLM09로 지정된 이 위협은, 기업 인프라에 악성 코드를 주입하거나 소송 배상금을 유발하는 등 실물 경제에 직접 타격을 주므로, 기술적 가드레일뿐 아니라 AI 리터러시 관점의 거버넌스가 요구됨.

## Ⅱ. 맹신(Overreliance)과 오정보가 유발하는 3대 위협 시나리오
AI의 헛소리가 낳는 참사들.
| 위협 유형 | 발생 매커니즘 및 맹신의 전개 | 치명적 결과 (Impact) |
|:---:|:---|:---|
| **코드 및 패키지 환각**<br>(AI Package Hallucination) | AI가 코드 작성 시 존재하지 않는(환각) 모듈을 추천. 공격자가 이를 예측해 해당 이름으로 악성 코드를 PyPI, npm 등에 사전 등록. | 개발자가 맹신하여 `pip install` 수행 시 사내망에 랜섬웨어/백도어 감염 (공급망 공격). |
| **권위적 오정보**<br>(Authoritative Misinfo) | 의료, 법률, 금융 등 전문 도메인에서 AI가 가상의 판례, 가짜 질병 진단, 왜곡된 재무 수치를 전문가적 어조로 출력. | 치명적인 의료 사고, 법정 위증으로 인한 징계, 대규모 투자 손실 등 법적 책임 발생. |
| **보안 설정 오류**<br>(Misconfiguration) | 인프라 관리자가 방화벽, 클라우드(AWS) 권한 설정(IAM) 스크립트를 AI에게 위임했으나 논리적 결함이 포함됨. | Any-open(`0.0.0.0/0`) 설정이 서버에 그대로 반영되어 대규모 해킹 사태 발생. |

## Ⅲ. LLM 환각(Hallucination)의 발생 원인
왜 그럴싸한 거짓말을 하는가.
| 환각 원인 | 상세 설명 | 해결의 한계 |
|:---:|:---|:---|
| **학습 데이터 공백** | 모델이 학습하지 않은 최신 지식이나 롱테일(Long-tail) 정보에 대해 모른다고 하지 않고 지어냄. | RAG로 완화 가능하나, 100% 제거는 불가능. |
| **맥락 소실 (Attention 한계)**| 긴 컨텍스트 윈도우에서 앞선 내용과 충돌하는 모순된 논리를 뒤에서 생성함. | 긴 토큰을 처리할수록 모델 집중력 저하. |
| **Alignment Tax (정렬 세금)**| 지나치게 "안전하게 대답하라(RLHF)"고 강제하면, 모델이 너무 보수적으로 변해 엉뚱한 우회 답변을 창작. | 안전성과 유용성 간의 Trade-off 발생. |

## Ⅳ. Overreliance(오정보 맹신) 방어 아키텍처 및 통제 방안
인간의 맹신을 깨는 브레이크 시스템.
1. **RAG 기반의 그라운딩 및 출처 강제화 (Grounding & Citation)**:
   - LLM이 답변을 생성할 때, 반드시 벡터 DB에서 검색된(근거가 있는) 데이터에만 의존하도록 프롬프트 지시(Grounding).
   - UI/UX 단에서 답변 문장 끝에 반드시 사내 문서의 출처(Reference Link)를 하이퍼링크로 제공하여 사용자가 클릭 및 대조 확인을 하도록 유도.
2. **신뢰도 스코어 표시 및 면책 조항 (Confidence & Disclaimer)**:
   - 생성된 텍스트의 확률 분포를 기반으로 AI 스스로 '신뢰도(Confidence Score, 예: 40% 확신)'를 표시하게 하거나, "AI의 결과물은 부정확할 수 있으므로 최종 결정 전 전문가 확인을 요함"이라는 경고문(Disclaimer) 상시 노출.
3. **AI 코드 스캐닝 게이트 (Secure Code Review)**:
   - 개발 환경(IDE) 플러그인에서 AI가 생성한 코드는 무조건 즉시 실행을 차단하고, 사내 SAST(정적 분석기) 및 SCA(소프트웨어 구성 분석) 파이프라인을 거쳐 존재하지 않거나 악성인 패키지를 자동 스크러빙(Scrubbing).

## Ⅴ. 실무 적용 및 결론
- **판단 지표**: 사내 AI 챗봇의 답변 중 출처(Citation) 표기 비율, AI가 추천한 서드파티 라이브러리의 보안 검토 승인율, 도메인(법무/의료)별 사실 일치도(Factuality) 벤치마크 점수.
- **실무 설계**: 엔터프라이즈 IT 기업 F사의 'AI 코드 코파일럿(Copilot) 사내 도입' 프로젝트. 개발팀이 AI가 짜준 코드를 그대로 커밋(Commit)하는 사례 증가로 Overreliance 리스크 식별. 보안팀에서 AI가 추천한 `requests-ext`라는 가짜(환각) 패키지가 실제 깃허브 악성 코드로 연결될 뻔한 아찔한 상황 발견. 조치 방안: 1) AI 코파일럿의 설정을 변경하여 사내 프라이빗 패키지 저장소(Nexus/Artifactory)에 존재하는 라이브러리만 임포트(Import) 추천하도록 Grounding 적용. 2) CI/CD 파이프라인에 정책을 걸어 AI가 작성한 코드 블록(주석 처리된 태그 기반)은 반드시 '시니어 개발자의 리뷰(Manual Approve)'를 거치지 않으면 배포(Merge) 불가하도록 강제 로직 적용. 안전성 확보.
- **결론**: AI의 가장 무서운 점은 틀린 답을 내는 것이 아니라, "틀린 답을 정답처럼 완벽하게 연기하는 것"이다. 오정보 자체는 기술적 한계지만, 그것을 맹신하여 적용하는 것은 시스템 설계와 프로세스의 실패다. LLM 도입 기업은 AI를 전지전능한 오라클(Oracle)이 아닌, 뛰어난 글솜씨를 가졌으나 가끔 헛소리를 하는 '주니어 인턴'으로 취급하는 제로 트러스트(Zero Trust) 업무 문화를 정착시켜야 한다.

### 🔀 문제 유형별 목차 전환
- **Ⅱ·Ⅲ 강조 (개념/원리형)**: 모델 환각을 평가하고 수치화하기 위한 NLI(Natural Language Inference) 기반의 크로스 인코더(Cross-Encoder) 기술 원리와, 답변의 사실성을 점수화하는 Factual Consistency Metric 아키텍처.
- **Ⅴ·Ⅵ 강조 (실무/설계형)**: AI 생성 코드의 취약점 주입(Hallucinated Vulnerability)을 막기 위해 깃허브 액션(GitHub Actions) 내에서 동작하는 'AI Generated Code Security Linter'의 CI/CD 통합 방안과 개발자 보안 교육(Security Awareness) 연계 전략.
