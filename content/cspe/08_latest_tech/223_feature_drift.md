# 📖 【암기용】 개념 완전 이해

> 목적: Feature Drift를 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 머신러닝 모델의 입력값 중 특정 특징(Feature)의 통계적 분포가 학습 시점과 다르게 변하는 현상
- **왜 필요한가**: 전체 데이터 셋의 변화를 감지하기 전에, 개별 특징의 변화를 먼저 찾아내면 모델 성능 하락의 "정확한 원인 변수"를 짚어낼 수 있기 때문
- **핵심 직관**: 환자가 아플 때 "어디가 아픈지"를 알기 위해 혈압, 혈당 등 개별 수치를 하나씩 체크하는 것과 같음. 특정 수치(피처)가 평소와 다르면 그게 병(드리프트)의 원인임

## 깊이 이해
- **배경·문제의식**: Data Drift가 전체적인 입력 데이터 셋($X$)의 변화라면, Feature Drift는 그 구성 요소인 개별 변수($x_i$)에 집중한다. 모델이 수백 개의 변수를 사용한다면, 그중 한두 개의 변수만 값이 이상해져도 모델 전체의 예측값이 뒤틀릴 수 있다. 특히 데이터 수집 파이프라인의 오류나 특정 소스의 변경으로 인해 발생하기 쉽다.
- **작동 원리**: 각 특징별로 학습 데이터의 분포와 운영 데이터의 분포를 개별적으로 비교한다. 수치형 데이터는 평균/분산/분위수 변화를, 범주형 데이터는 각 카테고리의 빈도 변화를 측정한다. 특정 특징의 드리프트 점수(PSI 등)가 임계치를 넘으면 해당 변수가 "오염"되었거나 "트렌드가 변했다"고 판단한다.
- **비유**: 김밥을 만드는데 전체적인 맛이 이상해졌다면(Data Drift), 단무지가 상했는지 혹은 오이가 안 신선한지(Feature Drift) 재료별로 하나하나 먹어보는 과정이다.
- **구체 예시**: 카드 승인 모델에서 '결제 시간' 피처가 항상 0~24시 사이였는데, 시스템 오류로 갑자기 '99시'라는 값이 들어오거나, 심야 결제 비중이 평소 5%에서 50%로 급증하면 피처 드리프트로 판단한다.
- **흔한 오해·주의점**: "모든 피처의 드리프트를 다 막아야 한다"는 틀렸다. 모델 성능에 전혀 영향을 안 주는 사소한 변수의 드리프트는 무시해도 된다. 따라서 'Feature Importance(피처 중요도)'와 결합하여 관리 우선순위를 정하는 것이 실무적으로 매우 중요하다.

## 연결 개념
- Feature Importance — 드리프트 관리의 우선순위를 정하는 기준
- Data Integrity (데이터 정합성) — 피처 드리프트 탐지로 확인할 수 있는 데이터 품질 요소
- PSI (Population Stability Index) — 개별 피처의 안정성을 측정하는 핵심 지표

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Feature Drift는 ML 모델을 구성하는 개별 독립 변수($x_i$)의 통계적 속성이 학습 시점 대비 유의미하게 변화하는 현상이다.
> 2. **가치**: 모델 전체의 성능 하락 원인을 변수 단위로 특정하여 원인 분석(RCA) 및 데이터 파이프라인 정제 효율성을 높인다.
> 3. **판단 포인트**: 특징 중요도(Importance)가 높은 핵심 변수의 드리프트는 즉시 대응하고, 사소한 변수는 임계치를 완화하는 차등 관리 전략이 필요하다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 개별 변수 단위의 품질 관리 역량 확인 | 특징별 분포 변화(PSI, KS-test), 특징 중요도 연계 | 전체 데이터 드리프트와 구분 없이 기술 |
| 데이터 파이프라인 오류 탐지 능력 확인 | 결측치 급증, 값의 범위(Range) 일탈, 카테고리 변화 | "성능이 나빠짐"과 같은 결과론적 서술 |
| 실무적 모니터링 효율화 전략 확인 | 중요도 기반 알람 우선순위 설정, 동적 임계치 | 모든 변수를 동일한 비중으로 감시한다고 기술 |

> 요약: 개별 특징의 통계적 안정성을 확보하여 모델 예측의 일관성을 유지하고 데이터 오염을 조기 차단하는 방안 제시가 핵심이다.

## Ⅰ. 개요 및 필요성

- 정의: 머신러닝 모델의 특정 입력 특징(Feature)이 가지는 값의 범위나 분포가 시간 흐름 또는 외부 요인에 의해 학습 기준을 벗어나는 현상
- 배경: 데이터 수집 소스의 로직 변경, 센서 오작동, 특정 사용자 군의 급격한 유입(Selection Bias), 데이터 유실 등
- 필요성: 성능 하락의 근본 원인(RCA) 신속 파악, 데이터 파이프라인의 건전성 체크, 모델 재학습 시 변수 선별 근거 마련

---

## Ⅱ. 구조 및 구성요소

```text
Individual Feature (xi) -> Distribution Profiling (Training)
                                    |
              +---------------------+---------------------+
              |                                           |
        Statistical Test                          Value Range Check
        (PSI/JS-divergence)                       (Outlier/Null Rate)
              |                                           |
              +---------------------+---------------------+
                                    |
                        Priority Engine (Importance) -> Alert
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Feature Baseline | 각 특징별 학습 시점의 통계 요약 정보 | 평균, 분산, 빈도표 저장 |
| Monitor Engine | 특징별 실시간 분포 검정 수행 | PSI(Pop. Stability Index) |
| Priority Engine | 특징 중요도(Shapley/MDI) 정보 결합 | 알람 우선순위 결정 |
| Data Quality Gate | 임계치 위반 시 데이터 유입 차단 | 가드레일(Guardrail) 역할 |

> 요약: 개별 특징의 통계량(PSI 등)과 모델 기여도(Importance)를 결합하여 지능형 모니터링을 수행함.

---

## Ⅲ. 동작원리 및 흐름도

```text
특징별 프로파일링 -> 중요도 가중치 설정 -> 실시간 분포 산출 -> 통계적 거리(Distance) 계산 -> 중요도 가중 점수 합산 -> 알람/조치
      |                   |                |                    |                         |                    |
      +-------------------+----------------+--------------------+-------------------------+--------------------+-----> 파이프라인 점검
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 변수별 학습 분포 기준점 설정 | Null 비율, Min/Max, Median 기록 |
| 2 | 특징 중요도 연계 (Weighting) | Top 10 변수 집중 감시 설정 |
| 3 | 구간별 분포 이질성 검정 | PSI > 0.1(Warning), 0.2(Drift) |
| 4 | 비정상 징후 보고 및 필터링 | 원천 데이터 소스 정합성 확인 |

> 요약: 모든 특징을 감시하되, 모델 성능에 결정적인 영향을 미치는 변수의 드리프트를 최우선적으로 탐지함.

---

## Ⅳ. 특징

| 구분 | Data Drift (전체) | Feature Drift (개별) | 판단 포인트 |
|:---|:---|:---|:---|
| 분석 단위 | 데이터 셋 전체 ($X$) | 개별 독립 변수 ($x_i$) | 분석의 해상도 |
| 주요 지표 | MMD, 모델 성능 지표 | PSI, KS-test, Z-score | 탐지 알고리즘 |
| 원인 분석 | 트렌드 변화 등 거시적 원인 | 특정 컬럼 오류 등 미시적 원인 | 원인 규명(RCA) 용이성 |
| 대응 수준 | 전면 재학습, 샘플링 변경 | 해당 변수 제외, 보정, 소스 수정 | 조치의 구체성 |

> 요약: Feature Drift는 전체 데이터 변화의 세부 원인을 파악하게 해주며, 보다 구체적인 데이터 정제 조치를 가능하게 함.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 수치형 특징 (Numerical) | 범주형 특징 (Categorical) | 선택 기준 |
|:---|:---|:---|:---|
| 탐지 알고리즘 | KS-test, JS-divergence | PSI, Chi-square test | 데이터의 자료형 |
| 주요 지표 | 평균 이동, 분산 변화 | 신규 카테고리 등장, 비율 변화 | 변화의 양상 |
| 이상치 처리 | 3-sigma, IQR 등 활용 | Label Encoding 일치성 확인 | 전처리 방식 |

> 요약: 수치형은 값의 범위를, 범주형은 구성 비율과 신규 값의 등장을 중점적으로 감시함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| Alert Fatigue | 사소한 변수의 잦은 드리프트 | 중요도 기반 알람 필터링 적용 | 유효 알람 비율 (Signal/Noise) |
| False Negative | 미세하지만 치명적인 변화 누락 | 동적 임계치 및 윈도우 크기 최적화 | 장애 사전 탐지율 |
| 계산 부하 | 수천 개 변수 실시간 전수 조사 | 표본 추출(Sampling) 기반 모니터링 | 모니터링 시스템 오버헤드 |

> 요약: 알람 소음은 중요도로 필터링하고, 누락은 임계치 정교화로, 부하는 샘플링으로 대응함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 원인 변수 특정 시간 | 장애 발생 후 10분 이내 | 드리프트 발생~변수 식별 시간 |
| 데이터 정합성 유지 | 스키마 일탈 변수 0건 | 자동 데이터 검증 게이트 통과율 |
| 모델 안정성 | 드리프트에 의한 오작동 5% 이하 | 특징 보정 전후 예측 오차 대조 |

> 요약: 도입 효과는 원인 변수 식별 속도, 데이터 무결성, 모델 예측 안정성 지표로 판정함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 중요도 기반 차등 관제: 모델 기여도(SHAP value) 상위 5% 변수에 대해서는 PSI 임계치를 엄격히(0.1) 적용하여 성능 하락을 철저히 방어
2. 데이터 소스 정합성 검구: 외부 API로부터 유입되는 '환율' 피처가 평소 범위를 20% 이상 벗어나면 Feature Drift 알람을 즉시 발생시키고 해당 시점 데이터를 무효화
3. 데이터 파이프라인 디버깅: 전체 성능 하락 시 Feature Drift 대시보드를 확인하여 "고객 연령" 변수에서 결측치가 급증했음을 5분 만에 찾아내어 ETL 로직 수정

**결론 (2줄):**
- 기술사 판단: Feature Drift는 모델의 건강 상태를 보여주는 "혈액 검사"와 같으며, 전체 성능 하락이라는 결과가 나타나기 전에 원인을 치료하는 수단임
- 향후 방향: 수천 개의 피처를 사람이 일일이 관리할 수 없으므로, AI가 스스로 유의미한 드리프트를 판단하고 대응하는 "Autonomous Monitoring"으로 진화할 것임
