# 📖 【암기용】 개념 완전 이해

> 목적: 에이전트 권한통제를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: AI 에이전트가 사용할 수 있는 데이터·도구·행동 범위를 제한하는 통제
- **왜 필요한가**: 에이전트는 도구를 통해 실제 시스템을 조회·변경할 수 있어 과다 권한이 업무 사고로 이어짐.
- **핵심 직관**: 에이전트에게 사람 계정처럼 직무별 최소 권한과 승인 절차를 부여하는 것임.

## 깊이 이해
- **배경·문제의식**: LLM이 자연어 명령을 잘못 해석하거나 프롬프트 인젝션을 받으면 허용되지 않은 도구 호출이 발생할 수 있음.
- **작동 원리**: 사용자 권한, 에이전트 역할, 도구 위험등급, 데이터 민감도를 결합해 호출 전 정책 결정을 수행함.
- **비유**: 사원이 사내 시스템을 쓸 때 조회는 가능하지만 결재·삭제는 승인 없이는 못 하게 하는 구조.
- **구체 예시**: 장애 Agent는 로그 조회는 자동 허용하되 방화벽 정책 변경은 보안담당자 승인 후 실행함.
- **흔한 오해·주의점**: 모델 프롬프트에 금지사항을 쓰는 것만으로는 권한통제가 아니며 서버 측 정책 집행이 필요함.

## 연결 개념
- RBAC/ABAC — 역할·속성 기반 접근제어
- Policy Engine — 호출 전 허용·거부 판단
- Human Approval — 고위험 행동 승인

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Agent Authorization Control은 에이전트의 데이터 접근과 도구 실행을 정책 기반으로 제한하는 보안 통제임.
> 2. **가치**: 프롬프트 인젝션, 과다 권한, 오작동으로 인한 시스템 변경 사고를 줄임.
> 3. **판단 포인트**: 사용자 권한 위임, Agent 역할, Tool 위험등급, 승인·감사 체계를 분리 설계해야 함.

---

## Ⅰ. 개요 및 필요성

에이전트 권한통제는 AI 실행 권한 제한임. AI 에이전트가 업무 시스템을 호출하면 조회·변경·삭제 권한이 발생하므로 최소권한과 승인 정책이 필요함.

---

## Ⅱ. 구조 및 구성요소

```text
User/Agent -> Policy Decision Point -> Tool Gateway -> Backend


   신원/역할       허용판단              실행통제     업무시스템
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Identity | 사용자·Agent 신원 확인 | SSO, OAuth, workload ID |
| Policy Engine | 허용·거부 판단 | RBAC, ABAC, risk score |
| Tool Gateway | 도구 호출 집행 | allowlist, rate limit |
| Audit Log | 실행 책임 추적 | 입력 해시, 승인자 |

> 요약: 권한통제는 신원, 정책판단, 도구 게이트웨이, 감사로그로 에이전트 행동을 제한함.

---

## Ⅲ. 동작원리 및 흐름도

```text
요청 수신 -> 신원 확인 -> Tool 위험등급 판단
        -> 정책 평가 -> 승인/거부/실행 -> 감사 기록
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 사용자·Agent 인증 | MFA, 토큰, workload ID |
| 2 | 요청·도구 분류 | 조회/변경/관리 등급 |
| 3 | 정책 평가 | RBAC, ABAC, 시간·위치 |
| 4 | 실행·감사 | 승인자, Trace ID, 거부 사유 |

> 요약: 권한통제는 도구 호출 전 정책 평가로 자동실행, 승인요구, 거부를 결정함.

---

## Ⅳ. 특징

| 구분 | 프롬프트 지침 | 권한통제 | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 집행 위치 | 모델 내부 | 서버·게이트웨이 | 우회 시도 차단률 |
| 통제 기준 | 자연어 규칙 | RBAC·ABAC·위험등급 | 정책 수, 거부율 |
| 감사 | 대화 로그 | 승인·실행 로그 | Trace ID, 보존기간 |

> 요약: 권한통제는 프롬프트 지침이 아니라 서버 측 정책 집행으로 구현해야 함.

---

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. Agent별 서비스 계정과 사용자 위임 토큰을 분리하고 조회·변경·관리 권한을 등급화
2. Tool Gateway에서 allowlist, rate limit, 입력 스키마, 위험등급별 승인 정책을 집행
3. 모든 허용·거부·승인 이벤트를 SIEM으로 전송하고 이상 호출은 SOAR 절차와 연계

**결론 (2줄):**
- 기술사 판단: AI 에이전트에는 사람 계정보다 좁은 최소권한과 변경형 작업 승인 절차를 적용해야 함.
- 향후 방향: 에이전트 권한통제는 Zero Trust, IAM, AI Gateway가 결합된 실행 보안 계층으로 발전함.

### 🔀 문제 유형별 목차 전환 (이 키워드 출제 시)

| 유형 | 문제 신호어 | Ⅲ 강조 | Ⅳ 강조 |
|:---|:---|:---|:---|
| 포괄형 | 설명하시오, 기술하시오 | 인증-정책-실행-감사 흐름 | 프롬프트 지침 대비 차이 |
| 요구사항 명시형 | 보안대책을 제시하시오, 설계하시오 | 승인·거부·감사 절차 | 과다권한·주입공격 통제 |

> 요약: 설명형은 권한 구조, 보안형은 서버 측 정책 집행과 감사 체계를 중심으로 작성함.
