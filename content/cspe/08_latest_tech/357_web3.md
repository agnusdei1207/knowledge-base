# 📖 【암기용】 개념 완전 이해

> 목적: Web3를 블록체인 기반 소유권, 탈중앙 애플리케이션, 토큰 경제를 결합한 인터넷 서비스 모델로 이해하게 만든다.

## 한눈에
- **개요**: 블록체인과 지갑 기반으로 소유권·참여권을 표현하는 웹 모델
- **왜 필요한가**: Web2 플랫폼은 계정, 콘텐츠, 결제, 데이터 통제가 사업자 서버에 집중된다. Web3는 지갑, 스마트 계약, 토큰으로 일부 권한을 사용자와 네트워크에 분산한다.
- **핵심 직관**: 사이트에 로그인해 포인트를 받는 대신, 지갑에 담긴 토큰과 자격으로 여러 서비스에서 권리와 참여를 증명한다.

## 깊이 이해
- **배경·문제의식**: 중앙 플랫폼은 데이터 이동성, 수수료, 검열, 창작자 수익 배분 문제를 만든다. Web3는 퍼블릭 체인, dApp, DAO, DeFi, NFT를 통해 공개 검증 가능한 소유와 실행을 시도한다.
- **작동 원리**: 사용자는 지갑으로 서명하고, dApp은 스마트 계약을 호출하며, 체인은 상태 변경을 기록한다. 프런트엔드는 기존 웹처럼 동작하지만 신뢰 핵심은 온체인 상태에 있다.
- **비유**: 쇼핑몰 회원권이 특정 몰 DB에만 있는 것이 아니라, 사용자가 지갑에 회원권을 갖고 여러 상점에서 제시하는 방식이다.
- **구체 예시**: 토큰 기반 커뮤니티는 NFT 보유 여부로 입장 권한을 확인하고, DAO 투표 계약으로 제안 승인 여부를 기록한다.
- **흔한 오해·주의점**: Web3가 모든 중앙 서비스를 대체하는 것은 아니다. UX, 복구, 규제, 거래 수수료, 키 관리 문제로 Web2.5 혼합 구조가 많이 사용된다.

## 연결 개념
- Smart Contract — Web3 서비스의 온체인 실행 계층
- Wallet — 사용자 키와 서명을 관리하는 접점
- DAO — 토큰 기반 거버넌스 조직

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.
> 핵심: Web3는 지갑, 스마트 계약, 토큰, 탈중앙 저장소, 거버넌스를 결합하지만 운영에서는 UX·규제·키관리·보안 리스크를 함께 봐야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Web3는 블록체인 기반 dApp에서 사용자 지갑과 스마트 계약으로 소유권·거래·참여권을 처리하는 모델이다.
> 2. **가치**: 디지털 자산 소유, 공개 정산, 커뮤니티 거버넌스, 조합 가능한 금융·콘텐츠 서비스를 제공한다.
> 3. **판단 포인트**: 온체인 필요성, 수수료, 지갑 UX, 키 복구, 규제, 스마트 계약 취약점을 검토한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| Web2와 차이 확인 | 지갑, 토큰, 스마트 계약, dApp | 탈중앙 구호만 작성 |
| 적용 판단 확인 | 소유권·정산·거버넌스 요구 | 모든 웹 서비스 대체로 단정 |
| 리스크 인식 확인 | 피싱, 키 분실, 규제, bridge | 투자·가격 중심 답안 |

> 요약: 이 문제는 Web3의 기술 구조와 도입 조건을 과장 없이 설명해야 한다.

## Ⅰ. 개요 및 필요성

- 개요: 블록체인 기반 웹
- 배경: Web2 플랫폼은 계정, 데이터, 결제, 규칙 실행이 중앙 사업자에 집중되는 구조임.
- 필요성: 외부 검증 가능한 소유권, 공개 정산, 사용자 참여 거버넌스가 필요한 서비스에서 Web3 구조를 검토해야 함.

---

## Ⅱ. 구조 및 구성요소

```text
User Wallet -> dApp Frontend -> Smart Contract -> Blockchain
            +-> Token / NFT / DAO
            +-> IPFS / Oracle / Indexer / Bridge
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| wallet | 키 보관과 트랜잭션 서명 | seed recovery |
| dApp | 사용자 UI와 계약 호출 | Web2 frontend |
| smart contract | 온체인 규칙 실행 | audit 필요 |
| token/DAO | 소유권·참여권·거버넌스 표현 | 규제 검토 |

> 요약: Web3는 프런트엔드는 웹이지만 신뢰 핵심은 지갑 서명과 스마트 계약 상태에 둔다.

---

## Ⅲ. 동작원리 및 흐름도

```text
지갑 연결 -> 메시지/거래 서명 -> 스마트 계약 호출
-> 체인 상태 변경 -> 이벤트 인덱싱 -> dApp 화면 반영
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 사용자가 지갑으로 주소와 권한을 제시함 | wallet connection |
| 2 | dApp이 서명 요청과 트랜잭션 내용을 표시함 | signing intent |
| 3 | 스마트 계약이 조건을 검증하고 상태를 변경함 | transaction receipt |
| 4 | 인덱서가 이벤트를 읽어 UI와 분석에 반영함 | indexer lag |

> 요약: Web3 서비스는 지갑 서명, 온체인 상태 변경, 오프체인 인덱싱이 결합되어 동작한다.

---

## Ⅳ. 특징

| 구분 | Web2 | Web3 | 판단 기준 |
|:---|:---|:---|:---|
| 계정 | ID/PW, SSO | wallet address | 키 복구 |
| 데이터 | 중앙 DB | 온체인+오프체인 | 공개 범위 |
| 결제 | PG/카드 | token/native asset | 규제·회계 |
| 거버넌스 | 사업자 정책 | DAO 투표 선택 | 의사결정 책임 |

> 요약: Web3는 사용자 소유와 공개 검증을 제공하지만 계정 복구와 규제 책임은 서비스 설계에 남는다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 소유권 | 플랫폼 DB | 토큰·NFT | 외부 이전 필요 |
| 정산 | 내부 원장 | 스마트 계약 정산 | 공개 검증 요구 |
| 커뮤니티 | 포인트·등급 | DAO·token gating | 참여권 이전 |

> 요약: Web3는 플랫폼 밖 이전성과 공개 검증이 필요한 권리 구조에 적용한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 피싱·서명 탈취 | 지갑 UX 미흡 | transaction simulation, allowlist | malicious signature |
| 키 분실 | seed phrase 단독 의존 | social recovery, MPC wallet | recovery success |
| 규제 위반 | 토큰의 증권성·AML 이슈 | legal review, KYC boundary | compliance finding |

> 요약: Web3 리스크는 기술 취약점뿐 아니라 사용자 키 관리와 규제 해석에서 발생한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 보안 | 계약 audit high 0건 | audit/fuzzing |
| 사용성 | 지갑 연결·서명 실패율 관리 | funnel analytics |
| 운영 | indexer 지연과 chain 장애 대응 | monitoring |

> 요약: Web3 서비스는 온체인 안전성과 Web2 수준의 사용성 지표를 동시에 관리해야 한다.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 소유권 이전, 공개 정산, 커뮤니티 거버넌스 중 온체인으로 둘 요구를 하나 이상 확인한 뒤 범위를 제한함.
2. 지갑 연결, 서명 화면, transaction simulation, seed recovery 안내를 UX 설계의 필수 항목으로 둠.
3. 스마트 계약 audit, token 법률 검토, AML/KYC 경계, incident response를 서비스 출시 조건으로 설정함.

**결론 (2줄):**
- 기술사 판단: 외부 검증 가능한 권리와 정산이 필요하면 Web3를 적용하고, 단순 커뮤니티 기능은 Web2가 운영 부담이 낮음.
- 향후 방향: Web3는 account abstraction, wallet recovery, 규제 준수형 토큰화와 결합해 Web2.5 형태로 확산됨.
