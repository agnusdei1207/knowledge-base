# 📖 【암기용】 개념 완전 이해

> 목적: AI Search를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: 키워드 검색, 의미 검색, RAG, 요약, 대화형 질의응답을 결합한 지능형 검색 경험
- **왜 필요한가**: 사용자는 문서 목록보다 질문에 대한 요약 답변, 근거, 후속 탐색을 원함.
- **핵심 직관**: 검색창이 문서 목록을 주는 도구에서, 근거를 읽고 답까지 정리하는 업무 도우미로 바뀐 것임.

## 깊이 이해
- **배경·문제의식**: 전통 검색은 사용자가 결과 목록을 직접 읽고 판단해야 한다. 문서가 많아질수록 찾기·비교·요약 시간이 증가함.
- **작동 원리**: BM25·Dense·Hybrid Search로 후보를 찾고, 리랭커와 RAG가 요약 답변·출처·추천 질의를 제공하며, 클릭·피드백 로그로 개선함.
- **비유**: 사서가 책 목록만 주는 것이 아니라, 관련 페이지를 읽고 요약하며 출처까지 알려주는 방식임.
- **구체 예시**: 기업 포털 AI Search에서 Top-5 문서 요약, 출처 링크, 관련 질문 3개를 제공해 평균 탐색 시간을 12분->4분으로 단축.
- **흔한 오해·주의점**: AI Search는 RAG만 의미하지 않음. 검색 품질, UI, 권한, 평가, 피드백 루프가 함께 필요함.

## 연결 개념
- Hybrid Search — AI Search의 1차 검색 계층
- RAG — 검색 결과를 요약 답변으로 변환
- Learning to Rank — 사용자 클릭·피드백 기반 순위 개선

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: AI Search는 검색·생성·요약·대화형 UX를 결합한 지능형 정보 탐색 시스템임.
> 2. **가치**: 문서 탐색 시간을 줄이고 출처 기반 답변과 후속 질문으로 업무 흐름을 단축함.
> 3. **판단 포인트**: 검색 품질, 권한, 출처 검증, 사용자 피드백 루프가 함께 설계되어야 함.

## Ⅰ. 개요 및 필요성

- 개요: 생성형 AI 기반 지능형 검색
- 배경: 기존 검색은 문서 목록 중심이라 사용자가 원문을 직접 읽고 비교해 답을 구성해야 한다.
- 필요성: hybrid search, reranker, RAG answer, citation을 결합해 검색 클릭 수와 time-to-answer를 측정 가능한 지표로 줄인다.

## Ⅱ. 구조 및 구성요소

```text
Query -> Query Understanding -> Hybrid Retrieval -> Reranker
  -> RAG Summarizer -> Source UI/Feedback -> Rank Learning
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Query Understanding | 의도·엔티티·필터 추출 | 자연어 질의 처리 |
| Retrieval/Rerank | 후보 검색·정밀 순위화 | BM25+Dense+Cross-Encoder |
| RAG Summarizer | 출처 기반 요약 답변 생성 | citation 필수 |
| Feedback Loop | 클릭·평점·수정 로그 학습 | nDCG·CTR 개선 |

> 요약: AI Search는 질의 이해, 하이브리드 검색, RAG 요약, 사용자 피드백을 결합한 검색 경험임.

## Ⅲ. 동작원리 및 흐름도

```text
질의 입력 -> 의도/엔티티 분석 -> 후보 검색
  -> 리랭킹 -> 출처 기반 요약 -> 결과 UI -> 피드백 반영
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 질의 의도·필터·권한 분석 | 의도 분류 F1 ≥0.85 |
| 2 | Hybrid Search와 리랭킹 | nDCG@10 ≥0.5 |
| 3 | RAG 요약과 citation 생성 | Faithfulness ≥0.9 |
| 4 | 클릭·평점·불만 로그 분석 | 검색 만족도 20% 개선 |

> 요약: AI Search는 검색 품질과 생성 답변 품질을 모두 측정하고 사용자 피드백으로 순위를 개선함.

## Ⅳ. 특징

| 구분 | 전통 검색 | AI Search | 판단 포인트 |
|:---|:---|:---|:---|
| 결과 형태 | 문서 목록 | 요약 답변+출처+문서 | 업무 탐색에 적합 |
| 검색 방식 | 키워드 중심 | Hybrid·RAG·대화 | 의미 질의 대응 |
| 검증 | 클릭 로그 | 검색 지표+Faithfulness | 환각 통제 필요 |
| 운영 리스크 | 순위 품질 | 출처 오류·권한 유출 | Enterprise 통제 필요 |

> 요약: AI Search는 검색 결과를 답변 경험으로 확장하지만 RAG 품질과 권한 통제를 함께 관리해야 함.

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 기업 포털: 사내 문서 Hybrid Search, Top-5 요약, citation UI, 권한 필터로 부서별 검색 제공
2. 품질 지표: nDCG@10, CTR, Faithfulness, citation correctness를 대시보드화해 검색과 생성 품질 분리
3. 피드백 개선: 사용자 "도움됨/아님" 로그와 클릭 dwell time을 랭킹 피처로 반영

**결론 (2줄):**
- 기술사 판단: 문서 탐색 업무는 AI Search로 전환하되, 출처·권한·평가 체계를 먼저 설계
- 향후 방향: 대화형 검색과 Agentic Workflow가 결합되어 검색에서 업무 실행까지 확장
