# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: 파란색 링크 목록만 10개 던져주던 구시대적 검색(Google 전통 검색)을 넘어, 질문의 의도를 파악하고 직접 문서를 읽고 요약해 '완성된 답변(Answer)'을 만들어주는 차세대 생성형 검색 패러다임.
- **필요성**: 바쁜 직장인들은 검색 결과 1번부터 5번까지 클릭해서 들어가 일일이 읽어보고 취합할 시간이 없음. AI가 대신 5개 문서를 순식간에 읽고 "결론은 이렇고, 출처는 여기야"라고 떠먹여 줘야 생산성이 올라감.
- **핵심 직관**: 백과사전 목차 vs 똑똑한 조교. 구글 검색이 "여기 백과사전 10권 찾아놨으니 네가 읽어봐"라면, AI 검색(Perplexity 등)은 조교가 "제가 10권 다 읽어봤는데요, 교수님 질문의 답은 3가지 요약되고 출처는 각주 달아놨습니다."라고 보고서 형식으로 주는 것.

## 깊이 이해
- **배경**: LLM의 한계(최신 정보 부족, 환각)를 극복하기 위해 RAG 아키텍처가 등장했고, 이를 전통적인 정보 검색(Search Engine) UX/UI와 결합한 것이 AI 검색임. MS의 Bing Chat(Copilot), Perplexity AI의 등장으로 검색 시장의 지각변동이 일어남.
- **작동 원리 (파이프라인 흐름)**:
  1. **의도 파악 (Query Understanding)**: 사용자의 질문이 대화형인지 단답형 키워드인지 파악.
  2. **하이브리드 검색 (Retrieval)**: 벡터 검색(의미)과 BM25(키워드)를 섞어 최적의 문서 10개를 긁어모음.
  3. **재정렬 및 독해 (Rerank & RAG)**: 리랭커로 가장 중요한 문서 3개로 압축한 뒤, LLM 프롬프트에 주입하여 읽게 함.
  4. **생성 및 출처 제공 (Generation & Citation)**: LLM이 정답을 생성하며 각 문장 끝에 원본 문서의 하이퍼링크 `[1]`을 각주로 담.
- **구체 예시**: 사내 포털 창에 "휴가비 지원금 조건"을 검색. 예전엔 <휴가규정.pdf>, <노사협의록.docx> 파일 목록만 떴지만, AI 검색은 화면 상단에 박스를 띄워 "휴가비는 1년 차 이상 50만 원 지원됩니다[1]. 다만 징계 이력자는 제외됩니다[2]."라고 답을 내고 밑에 파일 링크를 달아줌.
- **흔한 오해/주의점**: "RAG랑 AI Search랑 똑같은 거 아님?" 기술적 엔진은 RAG가 맞음. 그러나 RAG는 '기술 아키텍처' 용어이고, AI Search는 RAG, 실시간 웹 브라우징 툴, 대화형 UX(후속 질문 추천 등)가 모두 결합된 **'사용자 지향적 검색 서비스(Product)'** 개념임.

## 연결 개념
- **Perplexity AI (퍼플렉시티)**: AI 검색 시대를 열어젖힌 대명사 격 스타트업.
- **Hybrid Search (하이브리드 검색)**: AI 검색이 내부적으로 문서를 빠르고 정확하게 찾아내기 위해 사용하는 1차 필터링 기술.
- **Citation-based Answering (출처 기반 답변)**: AI 검색의 가장 핵심적인 UI/UX 요소. 각주 달기.

# 📝 【답안용】 시험 답안 템플릿
## 핵심 인사이트 (3줄 요약)
- **본질**: 기존의 키워드 매칭 기반 문서 목록(10 Blue Links) 제공 UX를 탈피하여, 질의 이해(Query Understanding), 하이브리드 검색, LLM 기반의 기계 독해(MRC) 및 문장 생성을 파이프라인화하여 "요약된 정답과 출처"를 즉시 제공하는 지능형 검색 패러다임.
- **가치**: 사용자의 정보 탐색 비용(Information Foraging Cost)과 인지적 부하(Cognitive Load)를 극단적으로 단축하며, 단순 검색을 넘어 대화형 후속 질의(Multi-turn Follow-up)를 통한 지식의 깊이 있는 탐구를 지원함.
- **판단 포인트**: AI 검색의 품질은 생성된 답변의 유창성(Fluency)보다 검색된 컨텍스트의 정확도(Context Precision)와 환각 방지를 위한 인용구(Citation) 매핑의 정합성에 90% 이상 의존하므로, 백엔드의 Retrieval 고도화가 최우선 과제임.

## Ⅰ. 개요 및 필요성
- **정의**: 거대 언어 모델(LLM)과 검색증강생성(RAG) 아키텍처를 결합하여, 사용자의 복합적이고 추상적인 자연어 질의에 대해 실시간 데이터를 바탕으로 직접적인 답변과 검증 가능한 출처를 종합하여 제공하는 차세대 검색 시스템.
- **배경**: 폭발적으로 증가하는 웹 및 기업 내부 비정형 데이터(사일로화된 지식) 속에서 전통적인 BM25 기반 키워드 검색 방식은 한계에 직면함(어휘 불일치 문제, 사용자가 원문을 직접 읽고 취합해야 하는 비효율 발생).
- **필요성**: 사용자 만족도 제고, 업무 생산성(Time-to-Value) 극대화, 그리고 대화형 인터페이스(Conversational UI)를 통한 능동적 지식 획득 경험을 제공하기 위함.

## Ⅱ. AI Search의 4단계 코어 아키텍처 (Perplexity 유사 구조)
검색 엔진과 추론 엔진(LLM)이 결합된 파이프라인 구조.
| 단계 | 모듈 명칭 | 핵심 메커니즘 및 수행 역할 |
|:---:|:---|:---|
| **1. 의도 분석** | Query Understanding | - 사용자의 모호한 자연어 입력을 LLM/프론트 모델이 분석.<br>- 검색어 확장(Query Rewrite), 필터 조건(날짜, 부서) 추출. |
| **2. 후보 검색** | Hybrid Retrieval | - Vector Search(의미) + Sparse Search(키워드/BM25) 결합.<br>- 수천만 건의 데이터 중 관련 후보군 100여 개 1차 추출. |
| **3. 재정렬** | Cross-Encoder Reranker | - 추출된 문서와 질의 간의 딥러닝 기반 정밀 유사도 재계산.<br>- 답변 생성에 꼭 필요한 Top-3 ~ Top-5 문맥(Context)으로 압축. |
| **4. 독해/생성** | LLM Generator + Citation | - 압축된 컨텍스트를 프롬프트에 주입하여 LLM이 최종 답변 생성.<br>- 각 문장 주장에 대해 원본 링크를 매핑하는 출처(Citation) 표기. |

## Ⅲ. 기존 검색 시스템(Traditional Search)과의 패러다임 비교
| 비교 항목 | 전통적 검색 (Keyword Search) | AI 검색 (Generative Search) |
|:---:|:---|:---|
| **질의 방식** | 짧은 단어의 나열 ("2023년 세법 개정안") | 길고 복합적인 자연어 질의문 형식 |
| **매칭 원리** | 역인덱스(Inverted Index) 기반 어휘 일치율 | 임베딩 벡터 기반 의미론적(Semantic) 유사도 파악 |
| **결과 형태** | 문서/웹페이지의 링크 목록 제공 (목차형) | 여러 문서를 종합·요약한 하나의 완전한 답변 글 제공 |
| **인터랙션** | 1회성 단발 검색. 결과 불만족 시 검색어 직접 수정 | 대화형(Multi-turn). "그 부분만 더 자세히 설명해 줘" 방식 |

## Ⅳ. 엔터프라이즈 AI Search 구현의 핵심 챌린지 및 해결 방안
기업 사내망에 AI 검색을 도입할 때 부딪히는 문제.
1. **보안 및 권한 이슈 (Information Leakage)**:
   - 검색된 결과를 바탕으로 LLM이 요약하기 때문에, 검색 앞단(Vector DB)에서 사용자의 직급/부서에 따른 메타데이터 필터링(Permission-aware)을 선행하여 미인가 문서의 요약을 원천 차단.
2. **환각 리스크 (Hallucination Control)**:
   - 환각 방지를 위한 2중 안전장치 필수. `Temperature=0` 설정 및 **Post-verification(사후 검증)** 파이프라인을 두어, 생성된 답변이 검색된 원문 정보와 모순되는지 NLI 모델로 실시간 검증.
3. **대기 시간 지연 (Latency Bottleneck)**:
   - 여러 문서를 읽고 생성하는 특성상 응답이 김. 이를 해소하기 위해 UI 단에 **Streaming API (SSE 방식)**를 적용하여 첫 토큰 응답 시간(TTFT)을 체감상 단축하고 사용자 이탈을 방지함.

## Ⅴ. 실무 적용 및 결론
- **판단 지표**: Time-to-Answer(원하는 정보를 얻기까지 걸린 시간), Zero-click Search Rate(목록을 클릭하지 않고 AI 요약 박스만 보고 이탈한 비율 $\rightarrow$ 높을수록 긍정적 지표).
- **실무 설계**: 대기업 그룹웨어 내 통합 지식 포털(K-Portal) 고도화. 기존 ElasticSearch 기반 검색 포털에 LlamaIndex 파이프라인을 브릿지하여 AI Search 탭을 신설. 사용자가 정책을 검색하면, 상단엔 오픈소스 LLM(vLLM 구동)이 작성한 '핵심 3줄 요약과 출처'가 스트리밍으로 출력되고, 하단엔 기존과 동일한 문서 리스트가 출력되는 Hybrid UX 제공. 관련 후속 질문(Follow-up Questions) 3가지를 자동 추천하여 지식 탐색 연속성을 보장함.
- **결론**: AI Search는 파편화된 기업의 데이터 사일로를 하나의 지능형 대화창으로 융합하는 혁신이며, 향후 사용자가 단순히 정보를 묻는 수준(Search)을 넘어 AI가 직접 업무 툴을 제어해 행동까지 대행하는 Agentic Search(에이전트 검색)로 진화할 것이다.

### 🔀 문제 유형별 목차 전환
- **Ⅱ·Ⅲ 강조 (개념/원리형)**: 질의 변환(Query Transformation - HyDE, Query Routing) 기법 중심의 검색 품질 극대화 아키텍처 및 전통 검색엔진(BM25)과 시맨틱 검색 간의 수리적 매칭 원리 차이 분석.
- **Ⅴ·Ⅵ 강조 (실무/설계형)**: Streaming 응답 구현을 위한 비동기 백엔드 아키텍처(FastAPI + Redis), 검색 품질 평가를 위한 Ragas(Faithfulness, Answer Relevancy) MLOps 대시보드 구축 전략.
