# 📖 【암기용】 개념 완전 이해

> 목적: CSPM을 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 클라우드 설정이 잘못되어 보안에 구멍이 나지 않았는지 자동으로 감시하고 교정하는 보안 도구
- **왜 필요한가**: 클라우드 사고의 99%는 사용자의 설정 실수(예: 실수로 데이터 저장소를 인터넷에 공개)에서 발생한다. 사람이 수천 개의 설정을 다 확인하기 어렵기 때문에 자동화된 도구가 필요하다.
- **핵심 직관**: "클라우드 인프라를 위한 상시 보안 점검 로봇"

## 깊이 이해
- **배경·문제의식**: 클라우드는 버튼 몇 번으로 서버와 DB를 만들 수 있어 편하지만, 그만큼 실수하기도 쉽다. 특히 '공유 책임 모델'에 따라 인프라 설정은 사용자의 책임이다. 방치된 S3 버킷이나 열려 있는 보안 그룹(Security Group)은 바로 해킹의 표적이 된다.
- **작동 원리**: **Scan -> Detect -> Remediate**. ① Scan: 클라우드 API를 통해 설정값(Configuration) 수집. ② Detect: 표준 보안 가이드라인(CIS Benchmark 등)과 비교해 위반 사항 탐지. ③ Remediate: 관리자에게 알리거나 자동으로 설정을 올바르게 수정.
- **비유**: 집을 지을 때 모든 창문과 문이 잠겼는지, 가스 밸브는 잠겼는지 매일 밤 자동으로 순찰하며 열린 문은 즉시 닫아주는 스마트 홈 보안 시스템과 같다.
- **구체 예시**: AWS Config, Azure Security Center, 그리고 전문 솔루션인 Wiz, Prisma Cloud. "인터넷에 직접 연결된 DB가 발견되었습니다"라고 경고를 띄워주는 식이다.
- **흔한 오해·주의점**: "해킹 공격을 막는 방화벽"과는 다르다. 방화벽은 들어오는 적을 막는 것이고, CSPM은 애초에 적이 들어올 만한 구멍(설정 오류)이 있는지 안을 살피는 것이다.

## 연결 개념
- CWPP (Cloud Workload Protection Platform) — 인프라 설정이 아닌 돌아가는 프로그램(워크로드) 내부를 보호
- CIEM (Cloud Infrastructure Entitlement Management) — 사용자 권한 설정에 특화된 관리
- Drift (형상 편류) — 원래 목표로 한 설정 상태에서 점차 벗어나는 현상

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 설정 오류로 인한 클라우드 보안 사고 예방을 위해 자동화된 가시성 확보와 지속적인 컴플라이언스 준수 체계를 중심으로 서술한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: CSPM(Cloud Security Posture Management)은 클라우드 서비스 설정의 취약점을 자동으로 식별, 모니터링 및 교정하여 보안 위협을 사전에 방지하는 거버넌스 도구이다.
> 2. **가치**: 수동 관리의 한계를 극복하는 실시간 가시성(Visibility)을 제공하고, CIS, NIST 등 글로벌 보안 표준에 대한 지속적 준수(Compliance)를 보장한다.
> 3. **판단 포인트**: 단순 탐지를 넘어 위험의 우선순위 산정 및 자동 교정(Auto-remediation) 기능을 통한 보안 운영의 자동화 수준이 핵심이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| CSPM 정의 및 필요성 이해 | 공유 책임 모델(Shared Responsibility) 및 설정 오류(Misconfiguration) 대응 | 침입 차단(FW) 등 런타임 보안과 혼동 금지 |
| 주요 기능 및 동작 메커니즘 파악 | API 기반 스캔, 정책 대조, 자동 교정(Remediation) | 에이전트 설치형 보안으로 서술 시 감점 (대부분 API 방식) |
| 클라우드 거버넌스 체계 연계 | 컴플라이언스 준수(CIS Benchmark 등), 멀티 클라우드 통합 관리 | 단일 벤더 도구로만 서술하는 협소함 경계 |

> 요약: 설정 오류에 의한 데이터 유출 리스크를 원천 차단하기 위한 상시 보안 점검 체계로서의 CSPM을 평가한다.

---

## Ⅰ. 개요 및 필요성

- 정의: 클라우드 인프라의 설정 결함을 지속적으로 탐지하고 보안 표준 준수 여부를 평가·교정하는 보안 관리 솔루션
- 배경: 클라우드 사고의 다수가 공격이 아닌 설정 실수에서 기인하며, 자원 수가 기하급수적으로 증가하여 수동 점검 불가
- 필요성: 쉐도우 IT(Shadow IT) 자원 파악, 규제 준수 증적 자동화, 보안 형상 편류(Drift) 방지

---

## Ⅱ. 구조 및 구성요소

```text
[ CSP Platform (AWS/Azure/GCP) ] 
      | (API 호출 / 로그 수집)
[ CSPM Engine ]
  / Scan: 인벤토리 파악, 설정 데이터 수집
  / Analysis: 정책(Best Practice) 대조, 위험 평가
  / Output: 시각화, 알람, 자동 교정 실행
```

| 구성요소 | 역할 | 상세 항목 |
|:---|:---|:---|
| 자원 인벤토리 | 현재 사용 중인 모든 클라우드 자산 식별 | VPC, S3, IAM, Security Group 등 |
| 정책 엔진 | 보안 가이드라인과 현재 설정 비교 | CIS Benchmark, SOC2, PCI-DSS, ISO27001 |
| 지속적 모니터링 | 실시간 설정 변경 감지 및 위험 탐지 | 퍼블릭 노출, 암호화 미적용, 과도한 권한 |
| 자동 교정 | 위반 사항 발견 시 자동 복구 및 알람 | 비승인 포트 차단, 버킷 비공개 전환, 알람 전송 |

> 요약: API 기반의 비침습적 방식으로 인프라 전체를 스캔하고 표준 정책과 대조하여 보안 구멍을 찾아낸다.

---

## Ⅲ. 동작원리 및 흐름도

```text
API 연동 -> 인프라 스캔 -> 표준 정책 대조 -> 위반 사항 식별 -> 위험 순위 산정 -> 보고 및 자동 교정
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | API 기반 데이터 수집 | 리전별, 계정별 모든 자원의 설정값(Metadata) 획득 |
| 2 | 컴플라이언스 맵핑 | 수집된 설정값이 특정 규제(예: ISMS-P) 항목을 준수하는지 대조 |
| 3 | 위험 상관관계 분석 | 단순 오류가 아닌 실제 공격 가능 경로(Attack Vector) 판단 |
| 4 | 형상 유지 (Drift Control) | 승인된 상태에서 벗어난 설정을 즉시 탐지하여 원복 조치 |

> 요약: 설정값을 지속적으로 감시하여 표준 상태(Baseline)를 유지하고, 위반 시 즉시 대응하여 사고를 예방한다.

## Ⅳ. 특징

| 구분 | 일반 취약점 진단 (Vulnerability Scan) | CSPM (Posturing) |
|:---|:---|:---|
| 진단 대상 | OS, 애플리케이션의 소프트웨어 결함 | 클라우드 서비스(IaaS/PaaS)의 설정 결함 |
| 수행 방식 | 주기적, 수동적 진단 위주 | 실시간, 자동화된 상시 감시 |
| 주요 지표 | CVE 번호, CVSS 점수 | 컴플라이언스 준수율, 형상 편류 여부 |
| 조치 방향 | 패치 및 업데이트 적용 | 잘못된 설정값(Config) 즉시 수정 |

> 요약: CSPM은 "인프라 자체가 올바르게 설계되고 운영되고 있는가"를 검증하는 데 초점을 맞춘다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 클라우드 기본 도구 (Native) | 전문 CSPM 솔루션 (Third-party) | 선택 기준 |
|:---|:---|:---|:---|
| 지원 범위 | 해당 CSP에 한정됨 | 멀티/하이브리드 클라우드 통합 지원 | 운영 중인 클라우드 사업자 수 |
| 분석 깊이 | 기본적인 보안 권고 위주 | 심층적 상관 분석 및 공격 경로 가시화 | 보안 요구 수준 및 데이터 민감도 |
| 자동화 수준 | 단순 알림 위주 | 복잡한 워크플로우 연동 및 자동 교정 | 보안 운영 인력의 전문성 및 규모 |

> 요약: 단일 클라우드는 기본 도구가 경제적이나, 멀티 클라우드나 고도화된 보안이 필요하면 전문 솔루션이 유리하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 오탐 및 알람 과부하 | 엄격한 정책 적용으로 정상 설정까지 경고 | 화이트리스트 관리, 위험 기반 우선순위 적용 | False Positive (오탐) 비율 |
| 자동 교정의 부작용 | 필수 설정 자동 수정 시 서비스 장애 발생 | 읽기 전용 모드 우선 적용, 단계적 자동화 | 자동 교정으로 인한 서비스 장애 건수 |
| API 호출 오버헤드 | 잦은 스캔으로 인한 API Rate Limit 도달 | 이벤트 기반 스캔(CloudWatch 등) 결합 | CSP API 호출 성공률 및 제한 횟수 |

> 요약: 자동 교정은 신중히 적용해야 하며, 알람의 홍수에서 '진짜 위협'을 골라내는 필터링 역량이 중요하다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 설정 가시성 | 클라우드 자산 식별 정확도 100% | 자원 관리 대장과 CSPM 리스트 대조 |
| 컴플라이언스 준수율 | 목표 보안 표준 준수율 95% 이상 | 솔루션 내 Compliance Score 확인 |
| 위반 탐지 시간 | 설정 변경 후 탐지까지 5분 이내 | 설정 변경 테스트를 통한 경보 발생 시간 측정 |

> 요약: 도입 효과는 자산 파악의 정확도, 보안 표준 준수 점수, 그리고 실시간 탐지 속도로 평가한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. **데이터 노출 차단**: "Public Read" 설정이 된 S3 버킷을 즉시 탐지하여 자동으로 비공개(Private) 전환하고 관리자에게 슬랙 알림
2. **멀티 클라우드 통합**: AWS, Azure에 흩어진 수천 개의 보안 그룹(SG) 설정을 하나의 대시보드에서 관리하고 통합 보안 감사 리포트 생성
3. **IaC 파이프라인 연동**: 테라폼(Terraform) 코드가 배포되기 전 단계에서 CSPM 엔진이 미리 스캔하여 보안 위반 시 배포 차단

**결론 (2줄):**
- 기술사 판단: 클라우드 보안의 시작은 CSPM이며, 단순한 체크리스트 확인을 넘어 '비정상적 형상 변화'를 즉시 감지하는 상시 거버넌스 체계로 운영되어야 한다.
- 향후 방향: AI를 활용해 수많은 설정 중 실제 침해로 이어질 수 있는 '치명적 조합'을 먼저 찾아내 해결하는 지능형 CSPM으로 진화할 전망이다.
