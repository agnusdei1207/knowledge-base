# 📖 【암기용】 개념 완전 이해

> 목적: Model Denial of Service를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: AI 모델 추론 자원을 과도하게 소모시키는 입력이나 요청으로 지연, 비용 폭증, 서비스 중단을 유발하는 공격
- **왜 필요한가**: LLM과 대형 모델은 토큰 수, 컨텍스트 길이, 도구 호출, GPU 점유 시간이 비용과 지연에 직접 연결됨.
- **핵심 직관**: 서버를 단순히 많이 때리는 것이 아니라 모델이 오래 계산하게 만드는 질문으로 자원을 고갈시키는 공격임.

## 깊이 이해
- **배경·문제의식**: 생성형 AI는 입력 길이와 출력 길이가 길수록 GPU 메모리와 추론 시간이 증가하며, 에이전트는 도구 반복 호출까지 발생함.
- **작동 원리**: 공격자는 긴 컨텍스트, 무한 반복 지시, 고비용 추론 요청, 동시 요청, tool loop를 유도해 큐 지연과 비용 초과를 만든다.
- **비유**: 콜센터에 짧은 문의가 아니라 끝없는 서류 검토와 반복 확인을 요구해 상담원을 묶어두는 행위임.
- **구체 예시**: 128K 토큰 컨텍스트 요청과 장문 출력 지시를 다계정으로 반복해 GPU p95 지연이 2초에서 30초로 증가.
- **흔한 오해·주의점**: 네트워크 DDoS 방어만으로 부족하다. 토큰·도구·GPU 사용량 기준의 애플리케이션 계층 제한이 필요함.

## 연결 개념
- LLM Cost Control — 토큰·GPU 비용 관리
- Rate Limiting — 계정·IP·토큰별 요청 제한
- AI Gateway — 모델 요청 정책·쿼터 제어

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Model DoS는 모델 추론 자원을 고갈시켜 지연·비용·중단을 유발하는 AI 계층 서비스거부 공격임.
> 2. **가치**: LLM 서비스는 토큰·컨텍스트·GPU 비용이 커서 소량 공격도 비용 사고로 이어질 수 있음.
> 3. **판단 포인트**: QPS뿐 아니라 토큰 수, 출력 길이, tool call, GPU time을 제한해야 함.

## Ⅰ. 개요 및 필요성

Model DoS는 AI 추론 자원 고갈 공격이다. 대형 모델은 요청 1건의 계산 비용 편차가 크다. AI 서비스는 네트워크 계층 외 모델 계층 쿼터와 비용 통제가 필요하다.

## Ⅱ. 구조 및 구성요소

```text
Expensive Prompt -> Long Context/Output -> GPU Saturation
  -> Queue Delay/Cost Spike -> Policy Throttle
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 고비용 입력 | 긴 컨텍스트·복잡 추론 요청 | token 폭증 |
| Inference Server | GPU/TPU 추론 수행 | batch·queue 영향 |
| Agent Tool Loop | 외부 도구 반복 호출 | 비용 증폭 |
| Throttling | 쿼터·길이·시간 제한 | per user/API key |

> 요약: Model DoS는 토큰·GPU·도구 호출 비용을 증가시켜 큐 지연과 비용 초과를 유발함.

## Ⅲ. 동작원리 및 흐름도

```text
고비용 요청 생성 -> 동시·반복 호출 -> 추론 자원 포화
  -> SLA 저하 -> 제한·차단
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 긴 입력·출력·추론 요청 생성 | input/output token 측정 |
| 2 | 다계정·동시 호출 수행 | QPS·TPM·RPM 감시 |
| 3 | GPU queue·비용 증가 발생 | p95 latency, GPU time |
| 4 | 쿼터·timeout·circuit breaker 적용 | SLA error rate ≤1% |

> 요약: Model DoS 방어는 요청 수보다 토큰·GPU 시간·도구 호출량 기준으로 자원 사용을 제한함.

## Ⅳ. 특징

| 구분 | 네트워크 DDoS | Model DoS | 판단 포인트 |
|:---|:---|:---|:---|
| 공격 단위 | 패킷·연결 수 | 토큰·GPU time·tool call | AI 계층 지표 |
| 비용 구조 | 대역폭·CPU | 추론 비용·큐 지연 | FinOps 연계 |
| 탐지 | 트래픽 폭증 | 고비용 요청 패턴 | 계정별 쿼터 |
| 방어 | WAF·CDN | 토큰 제한·timeout·캐시 | AI Gateway |

> 요약: Model DoS는 네트워크 트래픽이 작아도 모델 자원과 비용을 고갈시키므로 AI 계층 제한이 필요함.

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 쿼터 정책: 사용자·API key별 RPM, TPM, 최대 컨텍스트, 최대 출력 토큰, tool call 횟수를 설정
2. 비용 방어: 요청별 예상 토큰 비용을 사전 계산하고 예산 80% 사용 시 degrade model 또는 차단 적용
3. 운영 보호: timeout, circuit breaker, prompt cache, priority queue를 적용해 핵심 업무 p95 지연 3초 이하 유지

**결론 (2줄):**
- 기술사 판단: LLM 서비스는 WAF만으로 부족하므로 AI Gateway 기반 토큰·GPU·도구 호출 제한을 필수 적용
- 향후 방향: Model DoS 대응은 LLMOps, FinOps, SRE 지표와 통합된 비용·가용성 관리로 확장됨
