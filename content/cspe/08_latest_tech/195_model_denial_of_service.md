# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: 트래픽으로 네트워크를 마비시키는 일반적인 DDoS와 달리, **거대 언어 모델(LLM)이 계산하기 엄청나게 버거운 악의적 질문(입력)을 던져, 서버의 비싼 GPU 자원을 고갈시키고 막대한 클라우드 요금 폭탄(지연/서비스 중단)을 유발**하는 AI 맞춤형 서비스 거부 공격.
- **필요성**: LLM은 입력과 출력의 길이에 따라 연산량(비용)이 기하급수적으로 늘어나는 특이한 구조를 가짐. 해커가 교묘하게 "이 책 1,000페이지를 읽고, 모든 단어의 글자 수를 세어서 10만 줄짜리 표로 만들어줘"라고 시키면, 웹 서버는 끄떡없지만 뒤에 있는 비싼 GPU가 몇 분 동안 멈춰버림. 옆의 다른 사용자들도 응답을 못 받는 초유의 병목을 막아야 함.
- **핵심 직관**: 레스토랑 주방장 괴롭히기. 일반적인 DDoS는 알바생 1만 명을 식당 문앞에 세워서 진짜 손님이 못 들어오게 막는 것(네트워크 과부하). 반면 **Model DoS**는 딱 한 명의 손님(해커)이 식당에 들어와서, 주방장(GPU)에게 "메뉴판에 있는 요리 100가지를 1g 단위로 전부 다져서 코스로 내와"라고 주문하는 것. 주방장은 이 한 주문을 처리하느라 주방 전체가 올스톱되고, 다른 테이블은 굶게 됨.

## 깊이 이해
- **배경**: API당 트래픽(QPS) 제한만 걸어두면 안전할 줄 알았던 초기 생성형 AI 서비스들이 속속 무너짐. 트래픽은 적은데, 한 번의 쿼리(질문)가 잡아먹는 토큰(Token) 수와 컴퓨팅 리소스가 막대하다는 '비대칭 자원 소모' 특성을 해커들이 악용하기 시작함.
- **작동 원리 (자원 고갈의 3대 매커니즘)**:
  1. **컨텍스트 윈도우 폭파 (Long Context / Input DoS)**: 모델이 읽을 수 있는 최대 길이(예: 128K 토큰)에 꽉 차는 쓰레기 텍스트를 던진 뒤 복잡한 추론을 요구함. GPU 메모리(VRAM)가 터져나감.
  2. **장문 출력 유도 (Output DoS)**: LLM은 한 글자 한 글자(토큰)를 생성할 때마다 이전 글자들을 모두 참조하는 오토리그레시브(Autoregressive) 구조임. 해커가 무한 반복 출력을 유도("파이($\pi$) 값을 100만 자리까지 출력해")하여 GPU 스레드를 장시간 점유함.
  3. **에이전트 무한 루프 (Tool / Agent Loop)**: 외부 API를 검색하는 AI 에이전트에게 모순된 지시를 내려 플러그인(검색, 계산기)을 수천 번 무한 호출하게 만들어 시스템 락(Lock)을 걺.
- **구체 예시**: 'Sponge Example(스펀지 예제) 공격'. 번역 AI 모델에 일반 문장이 아닌 특정 이상한 기호의 조합("!!!????...")을 입력함. 이 구조는 모델 내부의 계산 복잡도(Attention)를 비정상적으로 스파이크 시키도록 설계됨. 평소 0.1초 만에 끝나던 번역이 10초 이상 걸리며, 이런 요청 100개만 날려도 수십억짜리 GPU 서버가 다운됨.
- **흔한 오해/주의점**: "웹 방화벽(WAF)이나 안티-DDoS 솔루션으로 막으면 되는 거 아님?" $\rightarrow$ 절대 못 막음. WAF는 네트워크 트래픽(IP당 접속 수 등)만 봄. 해커는 정상적인 속도로 가끔씩 질문을 던지므로 WAF는 그냥 통과시켜버림. 방어는 반드시 애플리케이션 계층(LLM 토큰 수, 프롬프트 계산량)에서 이루어져야 함.

## 연결 개념
- **Rate Limiting (속도/할당량 제한)**: DoS 방어의 기본. 단순히 '초당 API 호출 수(RPM)'만 제한하는 게 아니라, '분당 소모 가능한 토큰 수(TPM)'를 제한하는 구조로 진화.
- **FinOps (클라우드 재무 관리)**: Model DoS는 서비스 중단(가용성)도 문제지만, 종량제 과금 구조에서 '요금 폭탄(Wallet Exhaustion)'을 유발하는 재무적 공격이기도 함.
- **OWASP LLM Top 10 (LLM04)**: 이 단체에서도 'Model Denial of Service'를 주요 위협으로 꼽으며, 입력 제한과 자원 격리를 권장함.

# 📝 【답안용】 시험 답안 템플릿
## 핵심 인사이트 (3줄 요약)
- **본질**: 거대 언어 모델(LLM)의 트랜스포머 아키텍처 특유의 비대칭적 자원 소모율(입력 및 생성 토큰 길이에 따른 연산 복잡도 $O(N^2)$ 증가)을 악용하여, 극소수의 쿼리만으로 백엔드 GPU/TPU 자원을 고갈시키고 서비스를 마비시키는 애플리케이션 계층 공격.
- **가치**: 기존의 볼류메트릭(Volumetric) 네트워크 DDoS 방어 체계를 무력화하며, 클라우드 종량제(Pay-as-you-go) 환경에서 서비스 가용성(Availability) 훼손뿐만 아니라 막대한 클라우드 과금 폭탄(FinOps 리스크)을 동반하는 경제적 테러 공격임.
- **판단 포인트**: 이 위협은 네트워크 계층(L3/L4)에서 식별할 수 없으므로, AI API Gateway를 통한 토큰 기반의 정교한 속도 제한(Token-based Throttling), 최대 컨텍스트 제한, 자원 소모량 사전 예측 및 타임아웃(Timeout) 강제 중단 아키텍처 도입이 핵심임.

## Ⅰ. 개요 및 필요성
- **정의**: 공격자가 LLM의 연산 복잡성을 극대화하는 특수 프롬프트나 방대한 컨텍스트 입력을 주입하여, 추론(Inference) 서버의 메모리 리소스(VRAM)와 처리 시간(Compute Time)을 장시간 점유함으로써 정상 사용자의 요청을 지연·차단시키는 공격 기법.
- **배경**: 최근 LLM의 컨텍스트 윈도우가 최대 1M 토큰 이상(Gemini 1.5 등)으로 거대화되고, 자율 수행형 AI 에이전트(Agent)가 도입됨에 따라, 단일 프롬프트가 유발하는 자원 소비의 상단(Ceiling)이 통제 범위를 벗어남.
- **필요성**: 네트워크 WAF(웹 방화벽)로는 탐지 불가능한 '저용량 고비용(Low-volume, High-cost) 공격'을 방어하고, AI 서비스 제공의 경제적 지속가능성 및 SLA(서비스 수준 협약)를 준수하기 위함.

## Ⅱ. 모델 서비스 거부(Model DoS) 공격의 주요 벡터 (Vectors)
LLM의 아킬레스건을 찌르는 3가지 패턴.
| 공격 벡터 | 공격 방식 및 메커니즘 | 자원 소모의 타겟 |
|:---:|:---|:---|
| **입력 플러딩**<br>(Input Flooding) | 모델이 허용하는 최대 길이 한계치까지 텍스트나 문서를 꽉 채워(수만 토큰) 입력하여 어텐션(Attention) 연산 부하를 스파이크 시킴. | GPU VRAM 오버플로우,<br>OOM(Out Of Memory) |
| **출력 극대화**<br>(Output Maximization) | "파이($\pi$) 값을 백만 자리까지 읊어", "무한 루프 코드를 작성하고 시뮬레이션해" 등의 프롬프트로 생성 연산(Autoregressive)을 장기 지연. | GPU 스레드 장시간 점유 (Compute Bottleneck) |
| **에이전트 루프**<br>(Tool/Agent Loop) | 외부 검색 API나 도구를 호출하는 모델에게 해결 불가능한 모순적 지시를 내려, 모델 스스로 도구 호출을 무한 반복하게 만듦. | 모델 추론 비용 및<br>서드파티 API 호출 과금 폭탄 |

## Ⅲ. 기존 네트워크 DDoS와 Model DoS의 패러다임 비교
| 구분 | 전통적 DDoS 공격 | Model DoS (AI DoS) |
|:---:|:---|:---|
| **공격 매개체** | 봇넷(Botnet)을 통한 대규모 트래픽 발생 | **소수의 계정에서 발송된 정교한 무거운 프롬프트** |
| **타겟 레이어** | L3/L4 (네트워크 대역폭), L7(세션 연결) | **L7 이상 (AI 모델 추론 엔진 및 GPU 메모리)** |
| **방어 솔루션** | Cloudflare, CDN, L4 방화벽, Rate Limiting | **AI Gateway, 토큰(Token) 기반 쿼터(Quota) 제한** |
| **탐지 지표** | BPS(Bits Per Second), QPS(Queries Per Second) | **TPM(Tokens Per Minute), GPU 활용률, 응답 지연 시간** |

## Ⅳ. Model DoS 방어 아키텍처 (Resilience Design)
가용성과 지갑을 동시에 지키는 다층 보호망.
1. **입출력 길이 강제 제한 (Hard Capping)**:
   - 애플리케이션 프론트엔드 단에서 사용자 입력 텍스트의 바이트(Byte) 및 토큰 길이를 모델 한계치보다 낮게 강제 제한(Validation). 시스템 지시어로 출력(Output)의 최대 토큰 수(Max Tokens)를 엄격히 고정.
2. **토큰 단위 및 비용 기반 제한 (Token & Cost-based Rate Limiting)**:
   - 기존의 RPM(분당 요청 수) 차단을 넘어, AI API Gateway에서 사용자 계정/IP별로 '분당 소모 가능 토큰 수(TPM)'와 '일일 최대 API 과금 한도'를 설정하여 트래픽 쓰로틀링(Throttling) 적용.
3. **타임아웃(Timeout) 및 자원 모니터링 강제 종료**:
   - 단일 쿼리 추론이 특정 시간(예: 30초)을 초과하거나 GPU 점유율이 비정상적으로 유지될 경우, 서킷 브레이커(Circuit Breaker)를 발동해 해당 프로세스를 강제 킬(Kill)하고 사용자에게 에러 반환.
4. **시맨틱 캐싱 (Semantic Caching)**:
   - 공격자가 동일한 무거운 질문을 반복할 경우, GPU 연산을 거치지 않고 캐시 레이어(Redis 등)에서 과거 응답을 즉시 반환하여 연산 자원을 보호.

## Ⅴ. 실무 적용 및 결론
- **판단 지표**: 모델 서버의 P99 응답 지연(Latency) 안정성, 토큰 생성당 소모되는 평균 GPU 시간, OOM(Out of Memory) 발생으로 인한 컨테이너 재시작(CrashLoopBackOff) 빈도수, FinOps 지표(API 예산 초과 비율).
- **실무 설계**: IT 스타트업 D사의 사내 문서 통합 검색형 RAG(검색 증강 생성) 봇 구축. 오픈 직후, 악의적 크롤러가 초당 1건의 쿼리로 RAG 모델에 사내 문서 전체(1만 장 분량)를 요약해 달라는 프롬프트를 주입함. 클라우드 비용이 하루 만에 500만 원 청구되고, 정상 직원의 봇 사용이 전면 지연(Timeout)되는 Model DoS 사고 발생. 즉각적인 MLOps 아키텍처 개선 수행. 1) Kong 기반의 AI Gateway를 앞단에 도입하여 유저당 'TPM 4,000 제한' 및 'Max Tokens=1,024' 하드 코딩. 2) RAG 검색 엔진이 한 번에 가져오는 문서(Chunk) 수를 최대 5개로 제한. 3) 클라우드 Billing Alert 연동. 패치 1시간 만에 공격 트래픽 차단 및 GPU 지연시간 2초 이내로 정상화.
- **결론**: Model DoS는 단순히 서버를 다운시키는 것을 넘어 기업의 자본을 갉아먹는 치명적인 비대칭 공격이다. 인프라의 확장(Auto-scaling)으로 이를 해결하려는 접근은 무한한 클라우드 과금을 유발할 뿐이므로, AI 서비스 설계의 초기 단계부터 "입력과 출력의 자유도를 얼마나 제약할 것인가"에 대한 비즈니스-보안 트레이드오프 결단과 AI 게이트웨이 기반의 토큰 통제망 구축이 필수적이다.

### 🔀 문제 유형별 목차 전환
- **Ⅱ·Ⅲ 강조 (개념/원리형)**: 트랜스포머 모델의 셀프 어텐션(Self-Attention) 메커니즘에서 시퀀스 길이 $N$에 대해 연산 복잡도가 $O(N^2)$로 스케일링됨에 따라 긴 컨텍스트 주입이 초래하는 메모리 계층(SRAM/DRAM) 병목과 스펀지 공격(Sponge Attack)의 수치적 연산 지연 원리.
- **Ⅴ·Ⅵ 강조 (실무/설계형)**: 다수의 병렬 요청을 처리하기 위한 vLLM 기반의 Continuous Batching 기술 및 PagedAttention 메모리 관리 기법을 통한 GPU VRAM 단편화 최소화 아키텍처와, 이를 활용한 대규모 트래픽 수용 및 DoS 내성(Resilience) 강화 설계.
