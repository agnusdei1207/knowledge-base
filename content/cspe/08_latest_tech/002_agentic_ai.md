# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: **에이전틱 AI**는 AI가 사람의 단발 지시가 아니라 **목표(Goal)**를 받아, 스스로 **계획-행동-관찰-반성**을 반복하며 결과를 만들어내는 **자율성(Autonomy) 중심 패러다임**이다.
- **왜 필요한가**: 생성형 AI는 "물으면 답하는" 1회성인데, 사용자가 진짜 원하는 것은 "답변"이 아니라 "업무 완료"다. 다단계·불확실 업무는 한 번의 응답으로 끝나지 않으므로, 스스로 방향을 잡고 재시도하는 자율성이 필요해졌다.
- **핵심 직관**: 생성형 AI가 "묻고 답하는 AI"라면, 에이전틱 AI는 "목표를 받고 알아서 움직이는 AI"다. 시스템 구현 형태가 AI 에이전트 시스템(001)이라면, 에이전틱은 그 시스템이 지향하는 "행동 방식·성숙도"다.

## 핵심 용어 정리 (내부에 등장하는 것들)
답안 본문에 나오는 용어를 먼저 비유와 함께 정리한다. (시스템 구성요소 자체는 001 참조 — 여기서는 자율성 관점 용어에 집중)

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 에이전틱 AI(핵심) | 목표 기반 자율 순환(계획-행동-관찰-반성)으로 업무를 완결하는 AI 패러다임 | "목적지만 정하면 경로를 스스로 바꾸는 내비게이션" |
| 자율성(Autonomy) | 사람 개입 없이 스스로 다음 행동을 결정하는 정도 | 운전 보조 vs 완전 자율주행의 "개입 수준" |
| 목표지향(Goal-directed) | 절차가 아닌 "달성할 상태"를 기준으로 행동을 선택함 | "서울까지"만 주면 길은 알아서 찾기 |
| 생성형 AI(Generative AI) | 프롬프트에 대해 텍스트·이미지를 1회 생성하는 AI | 질문 1개에 답 1개 주는 "상담 창구" |
| 계획-행동-관찰-반성 루프 | Plan→Act→Observe→Reflect를 돌며 목표에 수렴하는 순환 | 실험-측정-보정을 반복하는 "PDCA" |
| 반성(Reflection)/자기검토 | 실행 결과를 스스로 평가해 계획을 고치는 단계 | 오답노트로 "다음 시도 교정" |
| 코파일럿(Copilot)형 | 사람이 최종 결정하고 AI가 보조하는 저자율 방식 | 부조종사가 "제안"만 하는 비행 |
| 오토파일럿(Autopilot)형 | AI가 끝까지 자율 실행하는 고자율 방식 | 자동 항법으로 "스스로 비행" |
| Human-in-the-Loop(HITL) | 고위험 행동 전 사람이 승인·개입하는 통제 지점 | 큰 지출 전 "결재 라인" |
| 업무 완료율(Success Rate) | 시도 대비 실제 목표 달성 비율. 에이전틱의 핵심 평가지표 | 배달 "완료율" |
| 과도한 자율(Excessive Agency) | 권한·범위를 넘어 행동하는 위험(OWASP LLM06) | 재량을 남용한 "월권" |

## 깊이 이해
- **배경·문제의식**: 생성형 AI는 문서 작성·요약·번역처럼 "산출물 1개"를 만드는 데 강하다. 그러나 "월간 정산을 마감하라" 같은 업무는 조회 → 검증 → 예외 처리 → 보고까지 여러 단계와 판단이 얽혀 한 번의 생성으로 끝나지 않는다. 중간에 실패하면 방향을 바꿔 다시 시도해야 하는데, 단발 생성 모델에는 이 "폐루프 자율성"이 없다. 여기서 패러다임 전환이 일어난다.
- **작동 원리(어떻게+왜)**: 에이전틱 AI는 목표를 정규화한 뒤 Plan(계획)→Act(행동)→Observe(관찰)→Reflect(반성)를 반복한다. 핵심은 Reflect다. 실행 결과가 목표에 못 미치면 스스로 원인을 판단해 계획을 수정하고 재시도한다. 이 자기교정 덕분에 불확실하고 긴 업무도 점진적으로 목표에 수렴한다. 자율성이 높아질수록 사람의 개입 빈도는 줄지만, 잘못된 자율 판단의 파급도 커지므로 위험도에 따라 자율 수준을 다르게 설계한다.
- **비유**: 내비게이션은 목적지만 받고, 도중의 교통 상황(관찰)을 보며 경로를 계속 다시 계산한다. 반면 종이지도(생성형)는 처음 알려준 길이 막혀도 스스로 갱신하지 못한다.
- **구체 예시(실제 프레임워크·사례)**: OpenAI의 Operator, Anthropic의 Computer Use, Google의 Project Mariner처럼 화면·도구를 스스로 조작해 과업을 끝까지 수행하는 제품이 에이전틱 방향이다. 예: 보안 점검 에이전트가 자산목록 조회 → 취약점 매핑 → 우선순위 산정 → 담당자 배정을 사람 개입 없이 진행한다.
- **흔한 오해·주의점**: "에이전틱 = 생성형에 기능 몇 개 붙인 것"이 아니라 평가·운영 모델 자체가 바뀐다. 생성형은 정답성·유창성으로 평가하지만, 에이전틱은 업무 완료율·정책 위반율·비용으로 평가한다. 또한 자율성은 무조건 높일 대상이 아니라 위험도에 맞춰 조절할 설계 변수다.

## 연결 개념
- AI 에이전트 시스템(001) — 에이전틱 패러다임을 실제로 구현하는 아키텍처
- ReAct(003) — 자율 순환을 LLM 프롬프트 수준에서 구현하는 대표 메커니즘
- AI 거버넌스·OWASP LLM06 — 자율성 확대에 따른 책임·과도한 자율 통제 체계

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 에이전틱 AI는 목표 기반으로 계획-행동-관찰-반성을 자율 반복하는 패러다임임.
> 2. **가치**: 단발 생성 결과를 다단계 업무 완료율·처리시간·책임추적 중심의 운영 모델로 전환함.
> 3. **판단 포인트**: 자율성은 높일 대상이 아니라 업무 위험도에 맞춰 조절할 설계 변수임.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 생성형 AI와 에이전틱 AI의 패러다임 차이 이해 | Goal-Plan-Act-Observe-Reflect 자율 순환, 완료율 중심 평가 전환 | 생성형에 기능 추가로만 서술 시 패러다임 전환 이해 부족 감점 |
| 위험도별 자율성 수준 설계 역량 | Copilot형(저자율)·Autopilot형(고자율) 구분, HITL, 정책 위반율 KPI | 자율성만 강조하고 통제 수준 누락 시 실무 역량 부족 감점 |

> 요약: 패러다임 차이와 위험도별 자율성 조절 설계를 함께 제시해야 출제 의도를 충족함.

## Ⅰ. 개요 및 필요성

- 개요: 목표 기반 자율 순환(계획-행동-관찰-반성)으로 업무를 완결하는 AI 패러다임임
- 배경: 생성형 AI의 1회성 응답으로는 다단계·불확실 업무의 재시도·자기교정이 불가함
- 필요성: 업무 완료율·처리시간·책임추적(Accountability)을 운영 모델로 담아야 함
- 위치: 구현 아키텍처는 AI 에이전트 시스템(001), 본 키워드는 그 지향 패러다임·성숙도임

---

## Ⅱ. 구조 및 구성요소

- 자율 행동 순환 구조도 (물리적 시스템 구성요소는 001 참조, 여기서는 행동·통제 축)

```text
목표 정규화 -> Plan(계획) -> Act(행동) -> Observe(관찰) -> Reflect(반성)
  -> 목표 미달 시 Replan(재계획) / 목표 충족 시 Finish(종료)
  (전 구간에 자율성 등급·정책·HITL 게이트 적용)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 목표 정규화 | 모호한 요구를 완료조건·범위·금지작업으로 확정 | 승인 필요 여부 사전 판정 |
| Plan/Act | 계획 수립과 행동 수행 | 도구별 권한 분리(001 위임) |
| Observe/Reflect | 결과 관찰과 자기검토 | 실패 원인 분류로 재계획 |
| 자율성 게이트 | 위험도별 Copilot·Autopilot 수준 결정 | 고위험은 HITL 강제 |
| 거버넌스 | 책임추적·정책·감사 | 과도한 자율(LLM06) 차단 |

> 요약: 에이전틱의 핵심은 Reflect 기반 자기교정과 위험도별 자율성 게이트임.

---

## Ⅲ. 동작원리 및 흐름도

- 선형 흐름도

```text
요구 입력 -> 목표 정규화 -> 계획 수립 -> 행동 실행 -> 결과 관찰 -> 반성/정책 검사 -> 재계획 또는 종료
```

1. 목표 정규화: 완료조건·제약·승인 필요 작업·금지 작업 확정
2. 계획·행동: 단계별 입출력 정의 후 실행, API 성공률·재시도 기록
3. 관찰·반성: 결과를 목표와 대조, 미달 시 원인 분류 후 계획 수정
4. 종료 판단: 완료조건 충족·자율 한도 도달 시 종료, 로그·승인이력 보존

> 요약: Reflect가 목표 달성 여부를 판정하고, 미달이면 스스로 재계획해 수렴시킴.

## Ⅳ. 특징

- 목표지향: 절차가 아닌 "달성할 상태"를 기준으로 행동을 선택함
- 자기교정: Reflect로 실패 원인을 판단해 계획을 수정·재시도함
- 자율성 가변: 업무 위험도에 따라 Copilot형·Autopilot형으로 조절함
- 평가 전환: 정답성·유창성 대신 완료율·정책 위반율·비용으로 평가함
- 책임 요구: 자율성 확대는 책임추적·감사·과도한 자율 통제를 동반해야 함

---

## Ⅴ. 심화 비교 및 적용 판단

- 패러다임 관점에서 생성형 AI와 대비함 (자율성 수준을 축으로 포함)

| 구분 | 생성형 AI | 에이전틱 AI |
|:---|:---|:---|
| 실행 모델 | 프롬프트-응답 1회 | 목표-계획-행동-관찰-반성 순환 |
| 자율성 | 사람이 매 단계 지시 | 위험도별 Copilot~Autopilot 자율 |
| 실패 처리 | 재생성은 사람이 다시 요청 | Reflect로 스스로 재계획 |
| 평가 기준 | 정답성·유창성 | 완료율·정책 위반율·비용 |

> 요약: 다단계·자기교정·완료율 평가가 필요하면 에이전틱, 단발 산출물은 생성형이 적합함.

- 자율성 수준 선택 기준(불릿)
  - Copilot형(저자율): 금전·권한변경·법적 영향 업무 → 사람 최종 결정, HITL 필수
  - Autopilot형(고자율): 조회·분류·정형 반복 업무 → 자율 실행, 사후 감사로 통제

- 주요 리스크와 대응(불릿)
  - 목표 오해: 정규화 부족이 원인 → 완료조건 템플릿·필수필드 검증
  - 과도한 자율(LLM06): 권한·범위 미제한이 원인 → 자율 한도·정책 게이트·HITL
  - 비용 초과: 불필요한 재계획 루프가 원인 → 단계당·일일 비용 한도

- 도입 성공 지표(불릿)
  - 업무 완료율 90% 이상(완료/시도 비율)
  - 정책 위반 0건/주(감사로그 필터)
  - 작업당 비용 목표 이내(토큰+도구 비용 집계)

## Ⅵ. 실무 적용 및 결론

- 적용 방안
  1. FAQ·티켓 분류 등 저위험 업무를 Autopilot형으로, 권한변경은 Copilot형(HITL)으로 분리
  2. 단계별 완료율·정책 위반율·작업당 비용·p95 처리시간을 운영 KPI로 상시 측정
  3. 목표·추론·도구결과를 보존하되 개인정보는 KMS 암호화·TTL 삭제 정책 적용
- 결론
  - 기술사 판단: 자율성은 업무 위험도의 함수로 설계하고, 고위험일수록 자율을 낮춰 통제력을 확보함
  - 향후 방향: MCP 도구 연동과 AI 거버넌스가 결합해 엔터프라이즈 자율 업무 표준 구조로 진화함
