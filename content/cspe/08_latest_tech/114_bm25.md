# 📖 【암기용】 개념 완전 이해

> 목적: BM25를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: 질의 단어와 문서 단어의 일치도, 희소성, 문서 길이를 반영해 순위를 매기는 확률적 검색 함수
- **왜 필요한가**: 정확한 키워드·모델명·조항 번호 검색은 임베딩보다 역색인 기반 BM25가 더 신뢰도 높은 후보를 제공함.
- **핵심 직관**: 자주 나오지 않는 중요한 단어가 적절한 길이의 문서에 들어 있으면 높은 점수를 주는 방식임.

## 깊이 이해
- **배경·문제의식**: TF-IDF는 단어 빈도가 계속 늘수록 점수가 커지는 문제가 있고, 긴 문서가 검색 결과를 과점할 수 있다.
- **작동 원리**: BM25는 TF 포화, IDF, 문서 길이 정규화를 결합해 점수를 계산하며 k1(1.2~2.0), b(0.75) 파라미터로 조정함.
- **비유**: "희귀하고 중요한 단어가 문서 안에 적당히 반복되면 높은 점수, 너무 긴 문서는 감점"하는 채점표임.
- **구체 예시**: Elasticsearch 기본 유사도 함수로 사용되며, 오류코드 `ORA-01555` 검색처럼 정확 토큰 질의에서 Dense보다 상위 정밀도가 높음.
- **흔한 오해·주의점**: BM25는 의미를 이해하지 않음. "자동차"와 "승용차"를 같은 의미로 처리하려면 동의어 사전이나 Hybrid Search가 필요함.

## 연결 개념
- Sparse Retrieval — BM25를 포함하는 역색인 기반 검색 계열
- TF-IDF — BM25의 선행 통계 기반 가중치 방식
- Hybrid Search — BM25와 Dense Retrieval을 결합하는 실무 검색 구조

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: BM25는 TF 포화·IDF·문서 길이 정규화를 결합한 희소 검색 랭킹 함수임.
> 2. **가치**: 고유명사·코드·법 조항 검색에서 Precision@1 0.85 이상을 달성하기 쉬움.
> 3. **판단 포인트**: 의미 불일치는 처리하지 못하므로 동의어 사전·SPLADE·Dense 결합으로 보완함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| TF-IDF 대비 BM25 개선점과 희소 검색 원리를 이해하는지 확인 | k1(1.2~2.0)·b(0.75) 파라미터, TF 포화 원리, Precision@1 0.85 | "단순 키워드 매칭" 수준 설명 금지, 의미 불일치 한계와 Hybrid 보완 필수 언급 |

> 요약: BM25 랭킹 함수의 통계적 원리를 설명하고 Dense 결합 필요성까지 판단할 수 있는지를 평가함.

## Ⅰ. 개요 및 필요성

- 정의: TF 포화·IDF·문서 길이 정규화 기반 확률적 랭킹 함수
- 배경: TF-IDF는 단어 빈도가 선형 증가하고 긴 문서가 결과를 과점하는 문제가 있음
- 필요성: RAG에서 정확 토큰 후보 검색과 Hybrid Search의 Sparse 축으로 활용됨

## Ⅱ. 구조 및 구성요소

```text
Query Token -> Inverted Index -> Posting List
       -> TF Saturation + IDF + Length Norm -> BM25 Score -> Rank
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Tokenizer | 질의·문서를 토큰으로 분리 | 형태소 분석, n-gram, 불용어 처리 |
| Inverted Index | 토큰별 문서 목록 저장 | Lucene, Elasticsearch |
| Scoring Function | TF·IDF·길이 정규화 점수 계산 | k1=1.2~2.0, b=0.75 |
| Ranker | 점수 기반 Top-K 문서 반환 | p95 50ms 이하 목표 |

> 요약: BM25는 역색인에서 토큰 후보를 찾고 TF·IDF·문서 길이 기반 점수로 순위를 매김.

## Ⅲ. 동작원리 및 흐름도

```text
문서 색인 -> 토큰화/역색인 저장
질의 입력 -> 토큰화 -> 포스팅 리스트 조회
  -> BM25 점수 계산 -> Top-K 반환
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 문서 토큰화 및 역색인 구축 | 색인 누락률 0%, 색인 갱신 5분 이내 |
| 2 | 질의 토큰으로 포스팅 리스트 조회 | 조회 지연 < 10ms |
| 3 | TF 포화·IDF·길이 정규화 점수 계산 | nDCG@10 ≥0.42 |
| 4 | Top-K 정렬 후 RAG 후보로 전달 | p95 검색 지연 <50ms |

> 요약: BM25는 질의 토큰이 포함된 문서만 역색인으로 조회하고, 통계 기반 점수로 상위 후보를 반환함.

## Ⅳ. 특징

| 구분 | TF-IDF | BM25 | Dense Retrieval |
|:---|:---|:---|:---|
| 빈도 처리 | 선형 증가 | TF 포화 적용 | 임베딩 유사도 |
| 문서 길이 | 보정 약함 | b 파라미터로 보정 | 청크 길이 의존 |
| 강점 | 단순 구현 | 정확 토큰·고유명사 | 의미·동의어 |
| 한계 | 긴 문서 편향 | 의미 불일치 | 코드·조항 누락 |

> 요약: BM25는 TF-IDF의 빈도·길이 편향을 보완하지만, 의미 검색 한계는 Dense 결합으로 해결함.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | TF-IDF | BM25 | 선택 기준 |
|:---|:---|:---|:---|
| 빈도 처리 | 선형 증가 | TF 포화(k1=1.2~2.0) | 고빈도 단어 편향 방지 시 BM25 |
| 문서 길이 | 보정 약함 | b 파라미터(0.75)로 정규화 | 문서 길이 편차 큰 코퍼스는 BM25 |
| 의미 처리 | 불가 | 불가(동의어 사전 보완) | 의미 검색 필요 시 Dense 결합 |

> 요약: BM25는 TF-IDF의 빈도·길이 편향을 보정하지만 의미 검색 한계는 Dense 결합으로 해결함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 동의어 미검색 | 토큰 일치 없으면 후보에서 제외됨 | 동의어 사전 등록, SPLADE 보완 | Recall@100 변화량 측정 |
| 파라미터 부적합 | k1·b 기본값이 도메인에 맞지 않음 | 도메인별 k1·b A/B 테스트 | nDCG@10 개선률 |
| 색인 지연 | 대량 문서 갱신 시 역색인 재구축 지연 | 증분 색인, 세그먼트 병합 주기 설정 | 색인 갱신 완료 5분 이내 |

> 요약: BM25 단독 운영은 동의어 미검색과 파라미터 부적합 리스크가 있으므로 도메인별 튜닝과 Dense 결합이 필요함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 검색 정확도 | Precision@1 ≥0.85, nDCG@10 ≥0.42 | 표본 질의 벤치마크 |
| 검색 지연 | p95 <50ms | Elasticsearch APM |
| 색인 운영 | 색인 누락률 0%, 갱신 지연 5분 이내 | 색인 파이프라인 모니터링 |

> 요약: 검색 품질은 Precision·nDCG로, 운영 안정성은 지연·색인 완정성으로 판단함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. RAG Sparse 축: Elasticsearch BM25 Top-50을 Dense Top-50과 RRF 결합해 nDCG@10 0.54 달성
2. 도메인 튜닝: 법률·의료 사전에 동의어와 약어를 등록, Recall@100 40%->62% 개선
3. 파라미터 조정: 짧은 FAQ는 b=0.4, 긴 문서 검색은 b=0.75~0.9로 A/B 테스트

**결론 (2줄):**
- 기술사 판단: 정확 토큰·규정·오류코드 검색은 BM25 우선, 의미 질의 혼재 시 Hybrid Search 적용
- 향후 방향: BM25는 SPLADE·Dense와 결합되어 RAG 검색 계층의 기본 Sparse 축으로 유지
