## 미리 알고가기

- BM25는 sparse retrieval의 대표 랭킹 함수로 term frequency, inverse document frequency, 문서 길이 보정을 사용함
- TF-IDF보다 스팸성 반복과 긴 문서 편향을 더 잘 제어함
- 의미 유사성보다는 exact lexical relevance에 초점이 있음

## Ⅰ. 개요

- **정의/개념**: BM25는 질의어가 문서에 등장하는 빈도와 희귀성과 문서 길이를 함께 고려해 관련성 점수를 계산하는 확률적 정보검색 랭킹 함수임
- **배경/필요성**: 단순 TF-IDF는 단어 반복과 긴 문서에 편향될 수 있으므로, 빈도 포화와 길이 정규화를 포함한 더 안정적인 키워드 랭킹 기준이 필요함

## Ⅱ. 특징

- rare term에는 높은 가중치를 주고 흔한 term에는 낮은 가중치를 줌
- term frequency가 무한히 선형 증가하지 않도록 포화 특성을 반영함
- 문서 길이 편향을 줄여 긴 문서가 무조건 유리해지는 현상을 완화함
- exact term 기반이므로 동의어와 의미 확장에는 약함

## Ⅲ. 종류 및 비교

| 판단 기준 | TF-IDF | BM25 | Dense Retrieval |
|:---|:---|:---|:---|
| 빈도 포화 처리 | 약함 | 있음 | 해당 없음 |
| 길이 정규화 | 제한적임 | 있음 | 해당 없음 |
| 의미 유사성 | 낮음 | 낮음 | 높음 |
| exact match | 높음 | 높음 | 낮음 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Term Frequency Factor | 문서 안에서 질의어가 얼마나 등장하는지를 반영하되 포화 특성으로 과도한 반복 영향을 줄임 |
| Inverse Document Frequency | 코퍼스 전체에서 드문 단어일수록 더 높은 구별력을 주어 점수를 높임 |
| Length Normalization | 평균 문서 길이 대비 현재 문서 길이를 보정해 긴 문서 편향을 줄임 |
| Analyzer, Inverted Index | 토큰 전처리와 역색인을 통해 BM25가 계산할 대상과 후보군을 제공함 |

```text
+-------------------+      +-------------------+      +-------------------+
| Analyzer / Index  | ---> | TF Factor         | ---> | IDF Factor        |
+-------------------+      +-------------------+      +-------------------+
                                                           |
                                                           v
                                                   +-------------------+
                                                   | Length Norm.      |
                                                   +-------------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 역색인 후보 수집 | --> | TF/IDF 계산     | --> | 길이 보정 반영   | --> | 최종 점수 정렬   |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **역색인 후보 수집**: 질의어가 등장하는 문서 후보를 색인에서 찾음
2. **TF, IDF 계산**: 빈도와 희귀성을 기반으로 기본 점수를 계산함
3. **길이 보정 반영**: 문서 길이 정규화를 적용해 편향을 줄임
4. **최종 점수 정렬**: 각 문서의 BM25 점수로 순위를 매김

## Ⅵ. 문제점 및 해결 방안

1. 문제: 질의와 문서가 다른 표현을 쓰면 의미가 같아도 BM25는 관련 문서를 거의 찾지 못할 수 있음
   - 해결방안: 동의어 사전과 hybrid search를 적용하고 recall@k와 lexical miss rate로 보완 효과를 검증함
2. 문제: tokenizer와 analyzer 설정이 도메인 용어를 잘못 나누면 BM25 점수 계산 자체가 왜곡될 수 있음
   - 해결방안: 도메인 analyzer를 튜닝하고 tokenization quality와 first-hit accuracy로 전처리 품질을 검증함
3. 문제: 파라미터가 기본값에 고정되면 짧은 FAQ와 긴 매뉴얼이 섞인 코퍼스에서 랭킹 품질이 흔들릴 수 있음
   - 해결방안: k1과 b를 코퍼스 특성에 맞게 조정하고 NDCG와 precision@k로 최적값을 검증함

## Ⅶ. 적용 사례

- 에러 코드 검색이 exact identifier matching에 사용되도록 BM25를 적용하며 확인 지표는 first-hit accuracy와 latency임
- 법률 조항 검색이 조항 번호와 용어를 기반으로 검색하도록 BM25를 활용하며 확인 지표는 precision@k와 user trust임
- 하이브리드 RAG sparse 축이 dense 검색을 보완하도록 BM25를 사용하며 확인 지표는 hybrid contribution rate와 retrieval recall임

## Ⅷ. 결론

BM25는 오래된 알고리즘이 아니라 exact lexical relevance를 안정적으로 계산하는 여전히 유효한 표준이므로, dense retrieval과의 역할 분담을 전제로 설계할수록 가치가 커짐.
