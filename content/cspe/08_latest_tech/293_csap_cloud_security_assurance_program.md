# 📖 【암기용】 개념 완전 이해

> 목적: CSAP를 국내 공공부문 클라우드 이용을 위한 보안 인증 제도로 이해하고, 인증 대상·평가 절차·운영 증적이 왜 필요한지 설명하게 만든다.

## 한눈에
- **개요**: 클라우드컴퓨팅서비스가 정보보호 기준을 준수하는지 평가·인증하는 국내 제도
- **왜 필요한가**: 공공기관이 민간 클라우드를 이용하려면 보안 기준, 운영 절차, 취약점 점검, 인증 유지 증적이 필요하다.
- **핵심 직관**: 공공기관이 입주할 건물이 소방·전기·출입 기준을 통과했는지 확인하는 사용 승인 절차와 비슷하다.

## 깊이 이해
- **배경·문제의식**: 공공부문은 민간 클라우드를 쓰고 싶어도 데이터 보호, 관리자 접근, 서비스 연속성, 취약점 대응을 검증할 제도적 기준이 필요하다.
- **작동 원리**: 클라우드 사업자가 인증을 신청하면 평가기관이 서면·현장·취약점 점검을 수행하고, 보완조치와 인증위원회 심의를 거쳐 인증이 부여된다.
- **비유**: 학교 급식 업체가 단순히 음식을 판다고 끝나는 것이 아니라 위생 기준과 현장 점검을 통과해야 납품 가능한 것과 같다.
- **구체 예시**: SaaS 제공자는 접근통제, 로그관리, 암호화, 백업, 취약점 조치 증적을 준비해 표준 또는 간편 평가 유형에 맞춰 심사를 받는다.
- **흔한 오해·주의점**: CSAP는 클라우드 전체 보안을 보장하는 면허가 아니다. 인증 범위, 서비스 유형, 유효기간, 변경 심사를 계속 확인해야 한다.

## 연결 개념
- Sovereign Cloud — 국내 공공 클라우드 주권 요구와 연결
- ISMS-P — 정보보호 관리체계 계열 인증과 구분 필요
- Zero Trust Architecture — 인증 이후 실제 접근통제 설계 기준

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.
> 핵심: CSAP는 공공 클라우드 조달을 위한 보안인증 제도이며, 인증 범위·평가 절차·유지관리 증적을 함께 써야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: CSAP는 클라우드컴퓨팅서비스의 정보보호 기준 준수 여부를 평가·인증하는 국내 클라우드 보안인증 제도임.
> 2. **가치**: 공공기관이 민간 클라우드를 사용할 때 서비스 보안 수준과 운영 통제 증적을 조달 판단 근거로 제공함.
> 3. **판단 포인트**: 인증 대상, 인증 범위, 평가 절차, 취약점 보완, 인증 유지 조건을 구분해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 국내 클라우드 제도 이해 확인 | 클라우드컴퓨팅법 제23조의2, KISA 평가·인증 | 일반 보안 솔루션 인증으로 오해 |
| 공공 조달 적용 판단 확인 | 인증 범위, SaaS 표준·간편, IaaS/PaaS 유형 | 인증 보유만으로 모든 서비스 허용 판단 |
| 운영관리 역량 확인 | 취약점 점검, 보완조치, 갱신·변경 관리 | 최초 인증 이후 유지관리 누락 |

> 요약: 이 문제는 CSAP의 법적 근거와 공공 클라우드 조달 적용 범위를 정확히 쓰는 것이 핵심이다.

---

## Ⅰ. 개요 및 필요성

- 개요: 공공 클라우드 보안인증
- 배경: 공공기관의 민간 클라우드 이용 확대에 따라 클라우드 서비스 보안 기준을 검증할 제도 필요성이 생김.
- 필요성: 인증 범위, 취약점 점검 결과, 보완조치 이행, 인증 유지 상태를 조달과 운영 감사의 근거로 활용해야 함.

---

## Ⅱ. 구조 및 구성요소

```text
Cloud Service Provider -> CSAP Application -> Evaluation Body
  +-> Document Review -> On-site Review -> Vulnerability Check
  +-> Remediation -> Certification Committee -> Certificate
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 신청기관 | 클라우드 서비스 제공자 | 인증 범위와 서비스 유형 제시 |
| 평가기관 | 보안 기준 충족 여부 점검 | 서면·현장·취약점 점검 |
| 인증기관 | 인증 심의와 인증서 발급 | KISA 중심 인증체계 |
| 이용기관 | 공공기관 등 수요기관 | 인증 범위와 조건 확인 |

> 요약: CSAP는 신청, 평가, 보완, 심의, 인증 발급 구조로 공공 클라우드 보안 기준 충족을 확인한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
인증 신청 -> 사전 검토 -> 보안 평가 / 취약점 점검
-> 보완조치 -> 인증위원회 심의 -> 인증서 발급 / 유지관리
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 신청서와 서비스 범위 제출 | 인증 대상 서비스 명확성 |
| 2 | 관리·물리·기술 보호조치 평가 | 통제 항목별 증적 |
| 3 | 취약점 점검과 보완조치 확인 | 조치 완료 기록 |
| 4 | 인증 심의 후 유지관리 수행 | 변경·갱신 관리 |

> 요약: CSAP는 문서 심사만이 아니라 현장 평가, 취약점 조치, 인증 유지관리를 포함하는 절차형 인증이다.

---

## Ⅳ. 특징

| 구분 | ISMS-P | CSAP | 판단 기준 |
|:---|:---|:---|:---|
| 목적 | 조직 정보보호 관리체계 인증 | 클라우드 서비스 보안인증 | 공공 클라우드 조달 |
| 대상 | 정보서비스 운영 조직 | IaaS·PaaS·SaaS 등 클라우드 서비스 | 서비스 단위 범위 |
| 평가 | 관리체계와 보호대책 | 클라우드 특화 통제와 취약점 | 가상화·운영·데이터 보호 |
| 활용 | 법정 의무·신뢰 증빙 | 공공부문 클라우드 이용 근거 | 인증 범위 확인 |

> 요약: CSAP는 조직 인증이 아니라 공공기관이 사용할 클라우드 서비스 단위의 보안인증이다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 자체 보안 점검 | 국가 인증 기반 검증 | 공공 조달 요구 |
| 비용 | 개별 점검 반복 | 인증 증적 재사용 | 수요기관 수와 서비스 범위 |
| 운영 | 공급자 자체 통제 | 인증 유지·변경 관리 필요 | 서비스 변경 빈도 |

> 요약: 공공기관 대상 서비스는 개별 보안 설명보다 CSAP 인증 범위와 유지 상태가 조달 판단의 핵심이다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 범위 오해 | 인증 서비스와 실제 이용 서비스 불일치 | 인증서 범위 대조 | service coverage |
| 인증 유지 실패 | 변경·취약점 조치 지연 | 변경관리와 정기 점검 | overdue action |
| 책임 혼선 | CSP와 이용기관 책임 경계 불명확 | 공동책임 매트릭스 작성 | control owner |

> 요약: CSAP 적용 리스크는 인증 범위, 유지관리, 공동책임 경계에서 발생한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 인증 범위 | 이용 서비스와 인증서 일치 | 인증서·서비스 카탈로그 대조 |
| 취약점 조치 | 기한 내 보완 완료 | 조치 이력 확인 |
| 운영 증적 | 접근·변경·백업 로그 보존 | 감사 샘플링 |

> 요약: CSAP 도입 효과는 인증서 보유보다 실제 이용 서비스와 통제 증적의 일치 여부로 판단한다.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 공공기관 도입 전 인증서의 서비스명, 인증 유형, 유효기간, 적용 범위를 실제 계약 서비스와 대조함.
2. CSP와 이용기관의 접근통제, 로그, 백업, 사고대응 책임을 공동책임 매트릭스로 문서화함.
3. 서비스 변경, 취약점 조치, 인증 갱신 일정을 운영 캘린더로 관리하고 감사 증적을 월 단위로 점검함.

**결론 (2줄):**
- 기술사 판단: 공공 업무 클라우드 도입은 CSAP 인증 범위 안의 서비스를 우선 검토하고, 민감 업무는 추가 보안 요구를 계약에 반영함.
- 향후 방향: CSAP는 소버린 클라우드, SaaS 공공 도입, 클라우드 네이티브 보안 통제와 함께 정교화됨.
