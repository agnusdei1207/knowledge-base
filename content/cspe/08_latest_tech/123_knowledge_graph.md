# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: 현실 세계의 사람, 장소, 개념 같은 '개체(Entity)'들을 점(Node)으로 찍고, 이들 사이의 '관계(Relationship)'를 선(Edge)으로 연결하여 그물망처럼 지식을 구조화한 거대한 데이터베이스.
- **필요성**: 기존 검색 엔진(벡터 DB 포함)은 문서 뭉치에서 "단어가 비슷한 문서"만 찾아줄 뿐, "A라는 약의 부작용을 일으키는 단백질 성분과 관련된 유전자는?" 같은 꼬리에 꼬리를 무는 논리적 추론(다중 홉 추론)은 절대 못 함.
- **핵심 직관**: 형사들의 수사 보드. 범죄자(Node), 피해자(Node), 흉기(Node)의 사진을 핀으로 꽂고 "원한 관계", "소유함"이라는 빨간 실(Edge)로 쭉 연결해서, 흩어진 파편들을 거대한 스토리 보드로 만드는 것.

## 깊이 이해
- **배경**: 2012년 구글이 검색 결과 오른쪽에 "인물 정보 요약 박스"를 보여주기 위해 처음 'Knowledge Graph'라는 용어를 쓰며 대중화됨. 최근 LLM의 환각(Hallucination)이 문제 되자, 절대 틀리지 않는 '팩트 창고'로서 Graph RAG 아키텍처의 핵심 엔진으로 다시 떡상함.
- **작동 원리**:
  1. (추출): 방대한 텍스트에서 개체(Entity: "스티브 잡스", "애플")를 뽑아냄 (NER 기술).
  2. (관계 형성): 두 개체가 어떤 관계인지(Relation: "창립자") 뽑아냄. (Triple 형태: 주어-동사-목적어).
  3. (저장): 이 데이터를 Neo4j 같은 '그래프 데이터베이스(Graph DB)'에 저장.
  4. (탐색): 질문이 오면 선을 따라 징검다리 건너듯(Graph Traversal) 명확한 팩트를 추적함.
- **구체 예시**: Q: "일론 머스크가 창업한 회사의 본사가 있는 도시의 시장 이름은?" $\rightarrow$ 벡터 검색은 머리가 터지지만, 지식그래프는 [일론 머스크] $\xrightarrow{창업}$ [스페이스X] $\xrightarrow{본사 위치}$ [호손(Hawthorne)] $\xrightarrow{시장}$ [알렉스 바르가스] 순서로 선을 타고 이동해 100% 정확한 답을 냄.
- **흔한 오해/주의점**: 구축이 미치도록 어렵고 비쌈. 비정형 텍스트에서 완벽한 노드와 엣지를 자동으로 뽑는 AI는 아직 완벽하지 않음. 노이즈(잘못 연결된 선)가 생기면 오히려 치명적인 독이 되므로, 스키마(Ontology) 설계와 정제 작업(Data Cleaning)에 엄청난 인력이 들어감.

## 연결 개념
- **Graph RAG**: 벡터 DB 대신(또는 함께) 지식그래프를 검색하여 LLM에게 팩트를 떠먹여 주는 최첨단 RAG 아키텍처.
- **Ontology (온톨로지)**: 지식그래프를 그리기 위한 청사진, 스키마. "사람은 회사를 창립할 수 있다" 같은 규칙을 정의.
- **Entity Linking (개체 연결)**: 문서의 "사과"가 과일인지 애플(기업)인지 식별하여 정확한 노드에 묶어주는 기술.

# 📝 【답안용】 시험 답안 템플릿
## 핵심 인사이트 (3줄 요약)
- **본질**: 비정형 데이터 속에 파편화된 정보들을 노드(Entity, 개체)와 엣지(Relationship, 관계) 형태의 트리플(Triple: 주어-술어-목적어) 구조로 추출하여, 상호 연결된 거대한 의미론적 네트워크(Semantic Network)로 저장하는 구조화된 지식 베이스.
- **가치**: 기존 Dense Retrieval(벡터 기반 검색)의 태생적 한계인 Multi-hop Reasoning(다단계 논리 추론)을 해결하고, 명시적인 사실(Fact) 간의 연결성을 보장하여 LLM의 환각(Hallucination)을 원천적으로 차단하는 화이트박스(White-box) 지식 체계를 제공.
- **판단 포인트**: 정보 추출(Information Extraction) 과정의 노이즈 누적으로 인한 그래프 오염 방지(Data Governance), 온톨로지(Ontology) 설계 복잡성, 벡터 DB와의 상호 보완적인 하이브리드 아키텍처(Graph RAG) 구축 역량.

## Ⅰ. 개요 및 필요성
- **정의**: 실세계의 다양한 객체(Object), 이벤트, 상황 또는 추상적 개념을 노드(Node)로, 이들 간의 의미적 종속성 및 관계를 엣지(Edge)로 모델링하여 저장, 쿼리, 추론할 수 있도록 설계된 그래프 기반 데이터 구조.
- **배경**: LLM과 Vector DB 기반의 RAG는 유사한 컨텍스트 덩어리를 가져올 뿐, 데이터의 논리적 종속성, 계층성(Hierarchy), 그리고 명제적 진실(Fact)을 보장하지 않아 금융/의료/법률 도메인에서 치명적 오류를 유발함.
- **필요성**: 엔터프라이즈의 사일로(Silo)화된 데이터를 하나의 맥락으로 관통(Traverse)하여 복잡한 다중 홉(Multi-hop) 질문에 대해 설명 가능한(Explainable) 추론 경로를 제공하기 위함.

## Ⅱ. Knowledge Graph 핵심 구성 요소 (Semantic Web 표준)
```text
[ Entity (개체/노드) ] --- (Relation/엣지) ---> [ Entity / Value (객체/속성) ]
    "이건희"                 "창업함"                    "삼성전자"
```
| 구성 요소 | 역할 및 특징 | 관련 기술 / 표준 |
|:---:|:---|:---|
| **Node (Entity)** | 인물, 조직, 개념 등의 고유 개체. | NER (명명개체 인식), Entity Linking |
| **Edge (Relation)**| 노드 간의 관계(is-a, part-of 등)와 방향성 표현. | RE (관계 추출, Relation Extraction) |
| **Ontology** | 지식그래프의 뼈대(스키마). 허용되는 노드와 엣지의 문법 규칙. | RDF, OWL (Web Ontology Language) |
| **Graph DB** | 트리플 데이터를 고속으로 저장/탐색하는 물리적 저장소. | Neo4j (Cypher), Amazon Neptune |

## Ⅲ. 벡터 검색(Vector Search) vs 지식그래프(Knowledge Graph)
| 비교 항목 | Vector DB (Dense Retrieval) | Knowledge Graph |
|:---:|:---|:---|
| **저장 단위** | 텍스트 조각(Chunk)의 밀집 실수 벡터 | 주어-술어-목적어 형태의 노드/엣지 |
| **검색 원리** | 기하학적 코사인 거리(유사도) 측정 | 노드 간 연결선(경로) 순회 (Traversal) |
| **다중 홉 추론**| 매우 취약 (유사한 문단만 가져옴) | **매우 강함** (경로를 따라가면 명확히 도출) |
| **설명 가능성** | Black-box (왜 유사한지 설명 곤란) | White-box (경로 자체가 완벽한 논리적 근거) |
| **구축 난이도** | 낮음 (임베딩 후 Insert 하면 끝) | **매우 높음** (NLP 추출 및 정제 파이프라인 필수) |

## Ⅳ. KG 구축 파이프라인 (Information Extraction)
1. **NER (Named Entity Recognition)**: 텍스트에서 의미 있는 단어(사람, 기관, 제품 등)를 식별.
2. **RE (Relation Extraction)**: 식별된 두 엔티티 간에 어떤 관계(동사적 의미)가 있는지 딥러닝(BERT 계열 등)으로 추론.
3. **Entity Resolution / Linking**: 문서 A의 "애플"과 문서 B의 "Apple Inc."가 동일한 하나의 노드임을 판단하고 병합(Merge)하여 지식의 파편화를 방지.
4. **Graph Construction**: 정제된 트리플(Triple) 세트를 Neo4j 등의 Graph DB에 적재.

## Ⅴ. 한계점 및 하이브리드 고도화 전략
- **리스크 1: 콜드 스타트 및 막대한 초기 구축 비용 (High Cost)**:
  - 도메인 특화 온톨로지 설계와 완벽한 노드/엣지 추출은 100% 자동화가 불가능하며, 도메인 전문가(SME)의 개입(Human-in-the-loop)이 필수적이라 ROI가 안 나옴.
  - **대응 방안**: LLM을 정보 추출기(Information Extractor) 프롬프트로 활용하여 비정형 문서에서 트리플을 자동 생성하는 **LLM 기반 KG 구축 자동화(GraphRAG 등)** 아키텍처 도입.
- **리스크 2: 경직성 (유사도 검색 불가)**:
  - 엣지가 연결되어 있지 않으면 절대 찾을 수 없음. "사과"와 "배"가 유사한 과일이라는 점을 명시하지 않으면 그래프는 이를 모름.
  - **대응 방안**: Vector DB의 '의미 유연성'과 KG의 '논리적 명확성'을 동시에 쿼리하는 **Vector-Graph 하이브리드 RAG** 구성. (예: 노드의 속성을 벡터로 임베딩하여 그래프 DB에 함께 저장).

## Ⅵ. 실무 적용 및 결론
- **판단 지표**: Triple Extraction F1-Score, 다중 홉(Multi-hop) 질의 정확도, 지식그래프 밀도(Graph Density).
- **실무 설계**: 금융권 자금세탁 방지(AML) 및 대출 심사 시스템. 기업 공시 자료, 뉴스, 주주 명부를 파싱하여 "A기업 -[대주주]- B회장 -[투자]- C페이퍼컴퍼니" 구조의 KG 구축. 기존 RDB/Vector 검색으로는 A기업과 C기업의 숨겨진 연관성을 찾지 못하나, Cypher 쿼리를 통해 3-hop 이내의 우회 거래 자금줄을 1초 만에 식별하고 시각화하여 심사관(Human) 및 LLM에게 팩트 리포트로 제공.
- **결론**: 지식그래프는 단순히 데이터를 저장하는 창고가 아니라 데이터에 '지능(Intelligence)'과 '논리(Logic)'를 부여하는 뼈대이며, 엔터프라이즈 AI가 블랙박스형 환각을 넘어 신뢰할 수 있는 전문가 시스템(Expert System)으로 진화하기 위한 필수 불가결한 뇌(Brain) 구조임.

### 🔀 문제 유형별 목차 전환
- **Ⅱ·Ⅲ 강조 (개념/원리형)**: RDF(Resource Description Framework)와 Property Graph의 데이터 모델링 차이, SPARQL과 Cypher 쿼리 구조 비교 중심.
- **Ⅴ·Ⅵ 강조 (실무/설계형)**: 마이크로소프트의 GraphRAG 아키텍처 동작 원리(커뮤니티 서머리 기반 LLM 질의), 정보 추출 파이프라인의 MLOps 자동화(LLM-as-an-Extractor) 중심 서술.
