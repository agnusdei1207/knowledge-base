# 📖 【암기용】 개념 완전 이해

> 목적: Knowledge Graph를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: 현실의 개체, 개체 간 관계, 속성을 노드와 엣지로 표현한 구조화 지식 저장 방식
- **왜 필요한가**: 문서 검색만으로는 사람·조직·시스템·규정 간 관계와 영향 경로를 명확히 추적하기 어려움.
- **핵심 직관**: 지식을 문장 더미가 아니라 "A가 B에 의존한다" 같은 연결 지도로 만드는 방식임.

## 깊이 이해
- **배경·문제의식**: LLM과 벡터 검색은 유사한 문단을 찾지만, 관계 경로·의존성·계층 구조 추론에는 별도 구조가 필요하다.
- **작동 원리**: 문서·DB에서 엔티티와 관계를 추출하고, 노드·엣지·속성으로 그래프DB에 저장한 뒤 SPARQL/Cypher나 그래프 알고리즘으로 탐색함.
- **비유**: 회사 규정을 문서 파일로 쌓아두는 것이 아니라, 조직도·업무 흐름도·책임 관계를 연결한 지도로 만드는 것임.
- **구체 예시**: 서비스 300개, API 2,000개, DB 500개의 의존성 그래프에서 장애 발생 시 2-hop 영향 서비스를 1초 이내 조회.
- **흔한 오해·주의점**: 그래프는 자동으로 진실을 보장하지 않음. 추출 오류, 중복 엔티티, 오래된 엣지를 정기적으로 정제해야 함.

## 연결 개념
- Ontology — 그래프의 개념·관계 타입·제약을 정의하는 스키마
- Entity Linking — 텍스트의 개체를 그래프 노드와 연결하는 기술
- Graph RAG — 지식그래프 탐색 결과를 LLM 컨텍스트로 활용

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Knowledge Graph는 엔티티·관계·속성을 노드와 엣지로 구조화한 지식 표현임.
> 2. **가치**: k-hop 관계, 영향 범위, 계층 구조를 명시적으로 탐색해 Graph RAG의 근거 경로를 제공함.
> 3. **판단 포인트**: 온톨로지, 엔티티 정규화, 엣지 신뢰도, 갱신 주기가 그래프 품질을 결정함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 그래프 기반 지식 표현과 관계 추론 역량 확인 | 엔티티·관계·온톨로지 구조, k-hop 질의, 벡터 검색 대비 차이 | 단순 "관계를 저장" 서술 금지, 구축 비용·데이터 거버넌스 누락 |

> 요약: Knowledge Graph의 구조·관계 추론 원리와 벡터 검색 대비 차별점을 수치로 제시해야 함.

---

## Ⅰ. 개요 및 필요성

- 정의: 엔티티·관계·속성을 노드-엣지로 구조화한 지식 표현 방식
- 배경: 벡터 검색은 유사 문단 검색에 적합하나, 관계 경로·영향 범위·계층 구조 추론에 한계
- 필요성: 서비스 300개, API 2,000개 규모에서 2-hop 영향 경로를 p95 1초 이내 조회하려면 관계 명시적 저장 필요

## Ⅱ. 구조 및 구성요소

```text
Data Source -> Entity/Relation Extraction -> Graph Store
  -> Ontology/Schema -> Graph Query/Reasoning -> Application
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Entity | 사람·조직·서비스·문서 노드 | URI·ID로 정규화 |
| Relation | 의존·소유·위반·포함 관계 | 방향성·신뢰도 속성 |
| Ontology | 개념·관계 타입·제약 정의 | RDF/OWL, schema constraint |
| Graph Store | 노드·엣지 저장·질의 | Neo4j, Neptune, RDF triple store |

> 요약: Knowledge Graph는 엔티티와 관계를 온톨로지 기반으로 저장하고 그래프 질의로 탐색함.

## Ⅲ. 동작원리 및 흐름도

```text
문서/DB 수집 -> 엔티티 추출 -> 관계 추출
  -> 정규화/중복 제거 -> 그래프 적재 -> k-hop 탐색/추론
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 문서·DB에서 엔티티 후보 추출 | Entity F1 ≥0.85 |
| 2 | 관계 타입과 방향성 추출 | Relation F1 ≥0.75 |
| 3 | 엔티티 정규화·중복 제거 | 중복 노드율 <5% |
| 4 | 그래프DB 적재 및 질의 제공 | 2-hop 질의 p95 <1초 |

> 요약: 데이터에서 개체와 관계를 추출·정규화한 뒤 그래프DB에 적재해 관계 탐색과 추론에 활용함.

## Ⅳ. 특징

| 구분 | 문서 검색 | Knowledge Graph | 판단 포인트 |
|:---|:---|:---|:---|
| 지식 표현 | 문단·청크 | 노드·엣지·속성 | 관계 분석은 그래프 |
| 질의 방식 | 키워드·벡터 유사도 | k-hop·경로·패턴 질의 | 영향 범위 탐색에 적합 |
| 구축 비용 | 청킹·임베딩 중심 | 추출·정규화·온톨로지 필요 | 초기 구축 2~4배 |
| 품질 리스크 | 검색 누락 | 관계 오류·중복 노드 | 데이터 거버넌스 필요 |

> 요약: Knowledge Graph는 구축 비용이 높지만 관계 경로와 영향 분석을 명시적으로 제공함.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 벡터 검색(RAG) | Knowledge Graph | 선택 기준 |
|:---|:---|:---|:---|
| 질의 방식 | 코사인 유사도 Top-K | Cypher/SPARQL k-hop 경로 | 관계 경로 분석 필요 시 KG |
| 구축 비용 | 청킹·임베딩 2~3일 | 추출·정규화·온톨로지 2~4주 | 초기 비용 대비 추론 ROI |
| 운영 리스크 | 검색 누락·랭킹 편향 | 관계 오류·중복 노드 | 데이터 거버넌스 체계 필요 |

> 요약: 단순 문단 검색은 벡터 RAG, 관계 경로·영향 범위 분석은 Knowledge Graph를 선택함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 엔티티 중복 | 정규화 미흡·별칭 미등록 | Entity Linking 파이프라인, 중복 탐지 배치 | 중복 노드율 <5% |
| 관계 오류 | NLP 추출 오탐·스키마 불일치 | SHACL 제약 검증, 수동 검수 큐 | Relation F1 ≥0.75 |
| 그래프 노후화 | 변경 미반영·삭제 미처리 | 증분 업데이트 주기 24시간, 변경 로그 감사 | 엣지 갱신 지연 <24h |

> 요약: KG 주요 리스크는 중복·오류·노후화이며, 정규화·제약 검증·증분 갱신으로 통제함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 추출 정확도 | Entity F1 ≥0.85, Relation F1 ≥0.75 | 테스트셋 500건 비교 |
| 질의 성능 | 2-hop 질의 p95 <1초 | Neo4j/Neptune 쿼리 로그 |
| 데이터 신선도 | 엣지 갱신 지연 <24h, 중복 노드율 <5% | 증분 적재 모니터링 대시보드 |

> 요약: 추출 정확도·질의 성능·데이터 신선도를 주 단위 측정해 KG 품질을 관리함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 장애 영향 분석: CMDB·APM 데이터를 서비스-API-DB 그래프로 구성, 2-hop 영향 경로 p95 1초 이하 조회
2. 규정·계약 RAG: 조항·의무·예외·위반 관계를 그래프로 저장하고 Graph RAG 컨텍스트로 제공
3. 품질 관리: 엣지 신뢰도 0.8 미만은 검토 큐, 엔티티 중복률 5% 초과 시 정규화 룰 갱신

**결론 (2줄):**
- 기술사 판단: 관계·영향·계층 질의는 Knowledge Graph, 단순 문단 검색은 Vector RAG 적용
- 향후 방향: LLM 기반 자동 추출과 Graph RAG 결합으로 비정형 문서 지식 구조화가 확대
