## 미리 알고가기

- SSE는 SASE에서 네트워크 연결 기능을 제외하고 보안 서비스 측면에 초점을 맞춘 개념임
- ZTNA와 SWG와 CASB 같은 사용자 접근 보호 기능이 중심이다
- SD-WAN이 핵심이 아닌 사용자와 애플리케이션 간 보안 통제가 핵심인 환경에서 적합함

## Ⅰ. 개요

- **정의/개념**: SSE는 사용자와 디바이스가 인터넷과 SaaS와 내부 애플리케이션에 접근할 때 필요한 보안 검증과 정책 집행을 클라우드 기반 서비스로 제공하는 사용자 중심 보안 아키텍처임
- **배경/필요성**: 모든 조직이 네트워크 재설계까지 포함한 SASE가 필요한 것은 아니며 원격 사용자와 SaaS 보호를 우선 해결하려는 수요가 커지면서 보안 중심 하위 개념이 분리됨

## Ⅱ. 특징

- 네트워크 연결보다 접근 보안 서비스 통합에 집중함
- ZTNA와 SWG와 CASB를 하나의 정책 모델로 묶기 좋음
- 원격 사용자와 SaaS 보호에 빠르게 적용 가능함
- 지점 연결 최적화와 네트워크 전환 효과는 SASE보다 제한적임

## Ⅲ. 종류 및 비교

| 판단 기준 | SSE | SASE | Legacy Secure Web Gateway |
|:---|:---|:---|:---|
| 초점 | 보안 서비스 | 네트워크 + 보안 | 웹 트래픽 보안 |
| SD WAN 포함 | 없음 | 있음 | 없음 |
| 도입 범위 | 비교적 좁음 | 넓음 | 제한적 |
| 적합 환경 | 사용자 중심 보안 강화 | 전사 네트워크 현대화 | 단일 웹 보호 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| ZTNA Layer | 내부 애플리케이션 접근을 identity 기반으로 통제해 최소 권한 연결을 제공하는 보안 계층임 |
| SWG Layer | 웹 접속을 필터링하고 악성 사이트와 위험 콘텐츠를 차단하는 보안 게이트웨이 계층임 |
| CASB Layer | SaaS 사용 가시성과 정책 통제를 제공해 데이터 유출과 그림자 IT를 줄이는 SaaS 보호 계층임 |
| Policy Context Engine | 사용자와 단말과 위치와 애플리케이션 위험도를 결합해 접근 정책을 결정하는 판단 계층임 |
| Cloud Security Edge | 사용자 트래픽을 받아 보안 검증과 정책 집행을 수행하는 클라우드 서비스 진입점임 |

```text
+---------+    +----------------+    +-----------------------------+
| User    | -> | Cloud Security | -> | ZTNA / SWG / CASB Services |
+---------+    +----------------+    +-----------------------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 접근 요청    | -> | 사용자/단말 평가 | -> | 보안 서비스 적용 | -> | 허용/차단 결정 | -> | 세션 모니터링  |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **접근 요청**: 사용자가 인터넷이나 SaaS나 내부 앱 접근을 시도함
2. **사용자와 단말 평가**: 신원과 보안 상태를 확인함
3. **보안 서비스 적용**: ZTNA와 SWG와 CASB 정책을 집행함
4. **허용과 차단 결정**: 정책 결과에 따라 트래픽을 제어함
5. **세션 모니터링**: 이상 징후와 데이터 이동을 계속 감시함

## Ⅵ. 문제점 및 해결 방안

1. 문제: ZTNA와 SWG와 CASB 정책이 서로 다른 기준으로 운영되면 사용자 경험과 보안 결과가 불일치할 수 있음
   - 해결방안: unified policy model과 cross control validation을 적용하고 policy inconsistency rate와 access decision variance로 검증함
2. 문제: 네트워크 구조는 그대로 둔 채 SSE만 도입하면 지점 연결 최적화나 경로 품질 개선은 기대하기 어려울 수 있음
   - 해결방안: use case scoped architecture와 network security boundary review를 적용하고 unresolved network bottleneck count와 security control coverage로 검증함
3. 문제: SaaS와 내부 앱 보호 정책이 과도하면 사용자 우회 사용과 그림자 IT가 오히려 늘어날 수 있음
   - 해결방안: adaptive access policy와 user experience tuning을 적용하고 shadow IT growth rate와 blocked legitimate access rate로 검증함

## Ⅶ. 적용 사례

- 사용자 보안 플랫폼이 통합 정책 모델을 운영하며 확인 지표는 policy inconsistency rate와 access decision variance임
- 글로벌 기업이 범위 기반 SSE 설계를 적용하며 확인 지표는 unresolved network bottleneck count와 security control coverage임
- SaaS 보안팀이 적응형 정책을 운영하며 확인 지표는 shadow IT growth rate와 blocked legitimate access rate임

## Ⅷ. 결론

SSE는 사용자 접근 보안 통합에 특화된 구조이므로 SASE와의 경계를 분명히 하고 정책 일관성과 사용자 경험을 함께 관리해야 함.
