# 📖 【암기용】 개념 완전 이해

> 목적: Federated Learning을 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: 데이터를 중앙 서버로 모으지 않고 각 참여기관에서 학습한 모델 업데이트만 합산하는 분산 학습 방식
- **왜 필요한가**: 개인정보·영업비밀·망분리 제약으로 원천 데이터 공유가 어려운 환경에서도 공동 모델을 만들 수 있음.
- **핵심 직관**: 데이터는 현장에 두고 학습한 요약값만 모아 하나의 모델을 개선하는 방식임.

## 깊이 이해
- **배경·문제의식**: 의료·금융·모바일 서비스는 기관별 데이터가 분산되어 있고 중앙 수집은 규제와 보안 비용이 큼.
- **작동 원리**: 서버가 글로벌 모델을 배포하고, 클라이언트가 로컬 데이터로 학습한 gradient/weight update를 전송하면 서버가 FedAvg 등으로 집계함.
- **비유**: 각 지점이 고객 명단을 보내지 않고 판매 패턴 요약만 본사에 보내 공동 영업 전략을 갱신하는 구조임.
- **구체 예시**: 병원 20곳이 로컬 CT 데이터로 5 epoch 학습 후 업데이트를 보내고, 중앙 서버가 50 round 동안 FedAvg로 진단 모델을 갱신.
- **흔한 오해·주의점**: 원문 데이터가 이동하지 않아도 업데이트에서 정보가 새어 나갈 수 있다. Secure Aggregation과 DP가 필요함.

## 연결 개념
- Secure Aggregation — 개별 업데이트를 숨기고 합산값만 공개
- Differential Privacy — 업데이트에 노이즈를 더해 개인 기여도 보호
- Non-IID Data — 참여기관 데이터 분포 차이 문제

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Federated Learning은 원문 데이터 이동 없이 모델 업데이트를 집계하는 분산 AI 학습 방식임.
> 2. **가치**: 개인정보 보호와 기관 간 공동 모델 학습을 동시에 지원함.
> 3. **판단 포인트**: Non-IID, 통신 비용, 업데이트 유출 위험을 설계 단계에서 통제해야 함.

## Ⅰ. 개요 및 필요성

- 개요: 데이터를 이동하지 않는 공동 학습 방식이다.
- 배경: 개인정보 규제와 기관 간 소유권 문제로 원문 데이터를 중앙 서버에 모으기 어렵다.
- 필요성: Federated Learning은 local training, model update, secure aggregation으로 공동 모델을 학습한다.

## Ⅱ. 구조 및 구성요소

```text
Global Server -> Client Training -> Model Update
  -> Secure Aggregation -> Global Model
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Global Server | 초기 모델 배포와 집계 수행 | FedAvg, FedProx |
| Client | 로컬 데이터로 학습 | 원문 데이터 미반출 |
| Model Update | gradient/weight delta 전송 | 유출 위험 존재 |
| Aggregator | 업데이트 합산·검증 | Secure Aggregation 적용 |

> 요약: 연합학습은 서버가 모델을 배포하고 클라이언트 업데이트를 집계해 글로벌 모델을 갱신함.

## Ⅲ. 동작원리 및 흐름도

```text
모델 배포 -> 로컬 학습 -> 업데이트 암호화
  -> 중앙 집계 -> 글로벌 모델 재배포
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 서버가 초기 모델·학습 설정 배포 | 참여기관 등록 100% |
| 2 | 클라이언트가 로컬 데이터로 학습 | local epoch 1~5 |
| 3 | 업데이트 보호 후 전송 | mTLS+Secure Aggregation |
| 4 | 서버가 집계·평가 후 재배포 | round별 AUC·loss 기록 |

> 요약: Federated Learning은 배포·로컬학습·보호전송·집계 과정을 반복해 공동 모델을 개선함.

## Ⅳ. 특징

| 구분 | 중앙집중 학습 | Federated Learning | 판단 포인트 |
|:---|:---|:---|:---|
| 데이터 위치 | 중앙 저장소 반입 | 클라이언트 현지 보관 | 규제 대응 |
| 통신 대상 | 원문 데이터 | 모델 업데이트 | 대역폭 산정 |
| 위험 | 원문 유출 | gradient leakage | DP·Secure Aggregation |
| 한계 | 데이터 반입 승인 필요 | Non-IID·straggler 문제 | 참여기관 품질 |

> 요약: 연합학습은 원문 데이터 이동을 줄이지만 업데이트 보안과 데이터 분포 차이를 별도 관리해야 함.

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 의료 공동학습: 병원별 DICOM/EMR은 로컬 보관하고 FedAvg 50 round와 외부 검증셋 AUC 기준 적용
2. 모바일 키보드: 단말 로컬 입력 패턴으로 모델을 갱신하고 Wi-Fi·충전 중 참여 조건을 적용
3. 금융 이상탐지: 기관별 거래 데이터는 반출하지 않고 Secure Aggregation+mTLS로 업데이트 전송

**결론 (2줄):**
- 기술사 판단: 데이터 반출이 법·계약상 어려운 AI는 연합학습을 우선 검토하되 업데이트 유출 방어를 필수 적용
- 향후 방향: Federated Learning은 DP, TEE, MLOps와 결합해 프라이버시 보존 AI 운영 구조로 발전함
