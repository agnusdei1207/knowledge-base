## 미리 알고가기

- 연합학습은 데이터를 중앙으로 모으지 않고 각 참여 노드에서 모델을 학습하는 분산 학습 방식임
- 대표 알고리즘은 FedAvg이며 서버 집계와 로컬 학습이 반복 라운드로 구성됨
- 데이터가 비동질적인 Non-IID 환경과 보안 집계 필요성이 실무 난제임

## Ⅰ. 개요

- **정의/개념**: 연합학습은 각 기기나 기관이 원본 데이터를 로컬에 유지한 채 모델 업데이트만 중앙 서버와 교환하여 공동의 글로벌 모델을 학습하는 분산 기계학습 구조임
- **배경/필요성**: 개인정보 규제와 데이터 사일로로 인해 데이터를 중앙집중식으로 모으기 어려워졌으므로, 데이터 이동을 최소화하면서 협력 학습을 수행할 방식이 필요해짐

## Ⅱ. 특징

- 데이터 반출을 줄여 프라이버시와 데이터 주권 요구에 대응하기 쉬움
- 기기와 기관이 동시에 참여할 수 있어 대규모 분산 데이터 활용에 유리함
- 통신 횟수와 참여 노드 불안정성과 데이터 분포 차이가 성능을 크게 좌우함
- 원본 데이터가 남아 있어도 업데이트 정보 유출과 모델 중독 공격을 별도로 막아야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | Horizontal FL | Vertical FL | Federated Transfer Learning |
|:---|:---|:---|:---|
| 데이터 관계 | 피처는 같고 샘플이 다름 | 샘플은 겹치고 피처가 다름 | 샘플과 피처가 모두 다름 |
| 대표 예 | 여러 병원의 동일 진단 데이터 | 은행과 카드사의 동일 고객 데이터 | 이종 산업 간 제한적 협력 |
| 구현 난도 | 중간 | 높음 | 매우 높음 |
| 실무 활용 | 크로스 사일로, 디바이스 연합 | 합동 신용평가 | 특수 협업 과제 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Coordinator Server | 글로벌 모델 버전을 배포하고 각 라운드의 업데이트를 집계해 다음 모델을 생성함 |
| Local Client | 스마트폰이나 기관 서버처럼 데이터를 로컬에 보유한 채 로컬 학습을 수행함 |
| Local Training Loop | 주어진 글로벌 모델을 기반으로 로컬 데이터에 맞게 여러 스텝 학습을 진행함 |
| Aggregation Engine | 다수 노드 업데이트를 평균이나 가중 평균으로 합쳐 글로벌 모델을 갱신함 |
| Security, Communication Layer | 전송 암호화와 보안 집계와 참여 노드 관리로 실무 운영 안정성을 확보함 |

```text
+-------------------+      +-------------------+      +-------------------+
| Coordinator       | ---> | Local Clients     | ---> | Local Training    |
+-------------------+      +-------------------+      +-------------------+
         ^                                                 |
         |                                                 v
         +-----------------------------------------+-------------------+
                                                   | Aggregation       |
                                                   +-------------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 글로벌 모델 배포 | --> | 로컬 학습 수행  | --> | 업데이트 업로드 | --> | 집계 후 재배포  |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **글로벌 모델 배포**: 중앙 서버가 초기 모델을 참여 노드에 배포함
2. **로컬 학습 수행**: 각 노드가 자신의 데이터로 로컬 업데이트를 계산함
3. **업데이트 업로드**: 원본 데이터 대신 파라미터 변화량만 전송함
4. **집계 후 재배포**: 서버가 업데이트를 모아 새 글로벌 모델을 다시 배포함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 기관과 기기마다 데이터 분포가 다르면 로컬 업데이트가 서로 충돌해 글로벌 모델 수렴이 느려질 수 있음
   - 해결방안: FedProx와 personalized FL을 적용하고 convergence rate와 global-local accuracy gap으로 검증함
2. 문제: 참여 노드 성능과 네트워크 상태 차이로 일부 노드가 매 라운드 지연을 유발해 전체 학습 효율을 떨어뜨릴 수 있음
   - 해결방안: partial participation과 async aggregation을 적용하고 round duration과 client completion rate로 검증함
3. 문제: 업데이트만 전송해도 gradient leakage나 poisoning 공격이 가능해 프라이버시와 무결성이 동시에 깨질 수 있음
   - 해결방안: secure aggregation과 robust aggregation을 결합하고 leakage attack success rate와 poisoning resilience로 검증함

## Ⅶ. 적용 사례

- 모바일 키보드 모델이 사용자 입력을 기기 밖으로 보내지 않고 다음 단어 예측을 개선하며 확인 지표는 next-word accuracy와 client participation rate임
- 병원 연합이 환자 기록을 공유하지 않고 공동 진단 모델을 학습하며 확인 지표는 diagnostic AUC와 privacy incident rate임
- 금융 계열사가 동일 고객의 다양한 속성을 활용해 합동 신용모델을 구축하며 확인 지표는 KS improvement와 secure aggregation success rate임

## Ⅷ. 결론

연합학습은 데이터를 이동시키지 않고 협력 학습을 가능하게 하는 핵심 분산 구조이므로 Non-IID 제어와 보안 집계 설계가 실제 성능과 신뢰를 결정함.
