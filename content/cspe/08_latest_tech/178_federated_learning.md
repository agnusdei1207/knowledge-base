# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: 데이터를 거대한 중앙 서버로 한데 모아서 AI를 학습시키는 기존 방식과 달리, 데이터는 스마트폰이나 개별 병원(로컬 기기)에 그대로 둔 채 **'학습된 결과값(모델 가중치)'만 중앙으로 모아** 더 똑똑한 통합 AI를 만드는 분산 학습 기술.
- **필요성**: 병원 기록, 개인 카톡 대화, 금융 거래 내역 같은 데이터는 규제와 프라이버시 때문에 본사 서버로 절대 보낼 수 없음. 데이터는 반출하지 않으면서 100만 명의 데이터를 모아 학습한 것과 똑같은 성능의 AI를 만들기 위해 탄생함.
- **핵심 직관**: 레시피만 본사로 보내기. 전국 100개 체인점이 손님들(데이터)을 상대로 신메뉴 개발을 함. 손님들의 명부나 음식 취향을 본사로 보내면 불법(프라이버시 침해)임. 대신 각 지점 주방장들이 "고춧가루를 1스푼 더 넣으니 반응이 좋았음"이라는 '노하우(가중치)'만 본사로 보냄. 본사는 이를 섞어서 완벽한 '마스터 레시피'를 완성함.

## 깊이 이해
- **배경**: 구글이 스마트폰 키보드(Gboard)의 다음 단어 예측 AI를 만들 때 처음 고안함(2016년). 수억 명의 타이핑 기록(비밀번호, 사생활 대화)을 구글 서버로 가져오는 건 미친 짓이므로, 아이폰/안드로이드 기기 내부에서 학습을 끝내버리는 아이디어를 냄.
- **작동 원리 (FedAvg - 연합 평균 알고리즘)**:
  1. **초기화**: 중앙 서버가 깡통 AI 모델을 100대의 스마트폰(클라이언트)에 뿌림.
  2. **로컬 학습 (Local Training)**: 스마트폰이 새벽에 충전 중일 때, 사용자의 카톡 데이터를 이용해 스스로 AI를 학습시킴.
  3. **가중치 전송 (Upload)**: 데이터 원본은 절대 폰 밖으로 안 나감. 오직 학습을 통해 변화된 **'모델 가중치(Gradient/Weight 업데이트 내용)'**만 암호화해서 중앙 서버로 전송함.
  4. **집계 (Aggregation)**: 서버는 100대의 폰에서 온 가중치들을 모아 **평균(Average)**을 내어 더 똑똑해진 '글로벌 모델'을 만듦.
  5. **반복**: 이 똑똑해진 글로벌 모델을 다시 폰으로 내려보냄. (이 과정을 라운드(Round)라고 부르며 수백 번 반복).
- **구체 예시**: 자율주행 자동차. A자동차 회사 차량들이 전국을 돌아다님. 카메라가 찍은 영상(민감한 위치정보)을 클라우드로 보내면 통신비 폭탄 + 프라이버시 위반임. 차 안의 컴퓨터가 표지판 인식 AI를 스스로 훈련한 뒤 "표지판 픽셀 가중치 +0.5 변경"이라는 공식만 본사로 보냄.
- **흔한 오해/주의점**: "데이터 안 보내니까 무조건 해킹 안 당하네?" $\rightarrow$ 아님! 해커가 클라이언트가 서버로 보내는 '가중치(Gradient)'를 가로챈 뒤 역산찰하면 원본 이미지를 복원해 낼 수 있음 (Model Inversion Attack). 이를 막기 위한 추가 보안(Secure Aggregation 등)이 반드시 필요함.

## 연결 개념
- **Privacy-Preserving AI (프라이버시 보존 AI)**: 연합학습이 속해 있는 더 넓은 우산 개념.
- **Non-IID 데이터**: 독립적이고 동일하게 분포되지 않은 데이터. A병원(안과)과 B병원(피부과)의 데이터 성격이 너무 달라서, 이 둘을 연합학습시키면 글로벌 모델이 바보가 되는 연합학습 최대의 수학적 난제.
- **Secure Aggregation (보안 집계)**: 연합학습 시 가중치마저도 암호화해서, 서버가 개별 기기의 가중치를 못 보게 합계(평균)만 낼 수 있게 만드는 방패막.

# 📝 【답안용】 시험 답안 템플릿
## 핵심 인사이트 (3줄 요약)
- **본질**: 데이터의 지역성(Data Locality)을 유지한 채 엣지(Edge) 디바이스나 개별 기관 서버에서 로컬 모델을 학습하고, 그 파라미터(Weight/Gradient) 변화량만을 중앙 서버에서 집계(Aggregation)하여 글로벌 모델을 고도화하는 분산 기계학습(Distributed ML) 패러다임.
- **가치**: 민감한 원본 데이터의 중앙 집중(Centralization) 없이 대규모 모델 학습이 가능하므로 프라이버시 보호 규제(GDPR 등)를 완벽히 준수하며, 막대한 데이터 통신 비용(Bandwidth) 전송 부하를 획기적으로 절감함.
- **판단 포인트**: 이기종 디바이스 간의 통신/연산 불균형에 따른 Straggler(낙오자) 문제와, 노드 간 데이터 분포가 극단적으로 다른 Non-IID 환경에서의 성능 저하(Weight Divergence)를 극복하기 위한 최적화 알고리즘(FedProx 등) 설계가 시스템 성공의 핵심임.

## Ⅰ. 개요 및 필요성
- **정의**: 다수의 클라이언트(스마트폰, IoT, 병원/기업 서버 등)가 원본 데이터를 자신의 로컬 저장소에 둔 채 기계학습 모델의 업데이트만을 중앙 서버와 공유하여 연합된(Federated) 모델을 구축하는 기술.
- **배경**: AI 성능 고도화를 위해서는 방대한 데이터가 필수적이나, 데이터 프라이버시법 강화, 기업 간 데이터 사일로(Silo) 및 데이터 주권(Data Sovereignty) 문제로 중앙집중식(Centralized) 데이터 웨어하우스 구축이 불가능해짐.
- **필요성**: 데이터 노출 제로(Zero-exposure) 환경에서 이종 기관(Cross-silo) 간 또는 수백만 엣지 기기(Cross-device) 간의 안전하고 효율적인 협력 AI 학습(Collaborative AI Learning) 아키텍처 마련.

## Ⅱ. 연합학습의 학습 메커니즘 (FedAvg 알고리즘 중심)
중앙 서버와 클라이언트 간의 N-Round 반복 통신 구조.
1. **초기화 (Initialization)**: 중앙 서버(Aggregator)가 베이스라인 모델 $W_t$를 생성하여 참여 노드들에게 브로드캐스트 전송.
2. **로컬 학습 (Local Training)**: 각 클라이언트 $k$는 자신의 로컬 비공개 데이터를 사용하여 Loss Function을 최소화하는 방향으로 모델을 학습시켜 새로운 가중치 $W_{t+1}^k$를 도출.
3. **업데이트 전송 (Upload)**: 원본 데이터는 남겨두고, 계산된 가중치(파라미터 변경분, $\Delta W$)만 암호화하여 중앙 서버로 전송.
4. **집계 및 갱신 (Aggregation)**: 서버는 수신된 파라미터들의 산술 평균(가중 평균)을 연산하여 글로벌 모델을 업데이트함.
   $W_{t+1} = \sum_{k=1}^K \frac{n_k}{n} W_{t+1}^k$ ($n_k$: 클라이언트 데이터 수, $n$: 전체 데이터 수)
5. 글로벌 모델이 수렴(Convergence)할 때까지 1~4단계를 반복.

## Ⅲ. 연합학습의 분류 (데이터 분할 방식에 따라)
참여 기관들이 어떤 속성의 데이터를 가지고 있느냐에 따른 분류.
| 분류 | 설명 및 특징 | 적용 사례 |
|:---:|:---|:---|
| **수평적 연합학습**<br>(Horizontal FL) | 피처(Feature, 속성)는 같으나 **데이터 샘플(사용자)이 다른** 경우. (일반적인 FL). | 전국 지역 병원 연합 (검사 항목은 같으나 환자 명단이 다름). |
| **수직적 연합학습**<br>(Vertical FL) | 데이터 샘플(사용자)은 겹치나, 각자 가진 **피처(속성)가 다른** 경우. | 은행(금융 정보)과 쇼핑몰(구매 정보)이 동일 고객의 신용 평가 모델을 연합 학습. |
| **연합 전이학습**<br>(Federated Transfer) | 샘플과 피처가 모두 다를 경우. | 미국 은행과 한국 유통사가 협업. (가장 구현 난이도 높음). |

## Ⅳ. 연합학습의 핵심 도전과제 (Challenges) 및 극복 기술
분산 환경이 만들어내는 3가지 페인포인트.
| 도전 과제 | 문제점 및 원인 | 해결/극복 방안 알고리즘 |
|:---:|:---|:---|
| **Statistical<br>Heterogeneity** | **Non-IID 데이터 문제**: 각 기기의 데이터 편향이 심해 글로벌 모델이 수렴하지 않고 요동침. | **FedProx**: 로컬 모델이 글로벌 모델에서 너무 크게 벗어나지 못하도록 손실 함수에 근접 항(Proximal Term) 추가. |
| **System<br>Heterogeneity** | 폰 사양, 네트워크 속도가 달라 서버가 가장 느린 폰을 기다리다 학습이 정체됨 (Straggler 문제). | **비동기식 FL (Asynchronous)**: 빠른 기기의 업데이트를 먼저 받아 모델 즉시 갱신 (FedAsync). |
| **Security &<br>Privacy** | 가중치(Gradient) 전송 중 훔쳐보기(Leakage) 및 악성 클라이언트의 모델 포이즈닝 공격. | **Secure Aggregation, DP 적용**, 이상 파라미터 필터링(Robust Aggregation). |

## Ⅴ. 실무 적용 및 결론
- **판단 지표**: 통신 지연시간(Round Communication Cost), 연합학습과 중앙집중학습 간의 모델 성능(AUC) 차이, Straggler 발생에 대비한 노드 Drop-out 허용률.
- **실무 설계**: 국내 A 금융지주의 계열사 간(은행-카드-증권) 신용평가 모형 통합 프로젝트. 데이터 3법에 의거 계열사 간 평문 데이터 이동 불가. 수직적 연합학습(Vertical FL) 아키텍처 설계. 교집합(Intersection) 고객을 식별하기 위해 비밀 공유 기반의 프라이빗 셋 인터섹션(PSI) 암호 프로토콜 적용. 은행의 수신/여신 데이터(Feature X1)와 카드의 소비 데이터(Feature X2)를 각 사 서버에 유지한 채, 중간의 로직(Loss Gradient)만 교환하여 딥러닝 앙상블 모형 완성. 기존 단일 은행 데이터만으로 만든 모델 대비 대출 부도율 예측 정확도(KS Statistic) 15% 향상.
- **결론**: 연합학습은 데이터 독점의 장벽을 허물고 데이터 주권을 지키면서도 AI 혁신의 이점을 취하는 '협력적 AI 패러다임'의 종착지이다. 자율주행, 헬스케어, 스마트폰 등 엣지 컴퓨팅 기하급수적 증가에 발맞추어, 연합학습은 향후 MLOps의 기본 분산 아키텍처로 자리매김할 것이다.

### 🔀 문제 유형별 목차 전환
- **Ⅱ·Ⅲ 강조 (개념/원리형)**: IID(독립동일분포)와 Non-IID(비독립동일분포) 데이터 환경에서 FedAvg의 Weight Divergence(가중치 발산) 현상을 수학적으로 증명하고, 이를 완화하기 위한 최적화 지표 서술.
- **Ⅴ·Ⅵ 강조 (실무/설계형)**: 악성 클라이언트가 거짓된 가중치를 섞어 글로벌 모델을 망가뜨리는 데이터 중독 공격(Data Poisoning) 및 백도어(Backdoor) 공격을 방어하기 위한 Krum, Trimmed Mean 등 Robust Aggregation 방어 아키텍처 설계.
