## 미리 알고가기

- Reflection은 초안 생성 후 비판과 수정 단계를 반복해 결과 품질을 높이는 루프형 추론 방식임
- Critic은 초안의 오류와 누락을 평가하는 역할을 맡는 평가자 계층임
- Evaluator-Optimizer 패턴은 생성자와 평가자를 분리해 반복 개선하는 에이전트 워크플로우임

## Ⅰ. 개요

- **정의/개념**: Reflection은 모델이 초안을 만든 뒤 스스로 혹은 별도 평가자가 그 결과를 비판하고 피드백을 반영해 재생성하는 반복 교정형 reasoning, generation 패턴임
- **배경/필요성**: 단일 생성은 첫 답변의 우연성과 오류에 크게 좌우되므로, 코드 작성이나 보고서 초안이나 규정 해석처럼 품질 검토가 중요한 작업에서는 비판과 수정의 반복 구조가 필요함

## Ⅱ. 특징

- 생성과 평가를 분리해 한 번에 완벽한 답을 강제하지 않고 점진적으로 품질을 높일 수 있음
- 코드, 기획, 문서 작성처럼 초안과 리뷰 문화가 있는 업무와 잘 맞음
- 동일 모델로도 구현 가능하지만 evaluator를 분리하면 교정 효과가 커질 수 있음
- 반복 횟수가 늘어날수록 품질은 좋아질 수 있으나 latency와 비용과 루프 제어 복잡성도 증가함

## Ⅲ. 종류 및 비교

| 판단 기준 | Zero-shot Generation | Reflection | Self-Consistency |
|:---|:---|:---|:---|
| 기본 전략 | 한 번 생성 | 생성 후 비판, 수정 반복 | 다중 생성 후 집계 |
| 오류 교정 | 약함 | 강함 | 중간 |
| 적합 업무 | 단순 답변 | 코드, 문서, 계획 수정 | 정답 선택형 추론 |
| 비용 | 낮음 | 중간~높음 | 높음 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Draft Generator | 초기 초안을 빠르게 생성해 검토의 출발점을 마련함 |
| Critic | 오류와 누락과 정책 위반을 찾아 구체적 피드백을 생성함 |
| Refiner | 비판 내용을 반영해 초안을 수정하고 다음 버전을 생성함 |
| Stop Controller | 반복 횟수, 점수 임계치, 테스트 통과 여부를 기준으로 루프 종료를 결정함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-----------+     +-----------+     +-----------+     +-----------+
| 초안 생성  | --> | 비판 생성  | --> | 수정 반영  | --> | 종료 판단  |
+-----------+     +-----------+     +-----------+     +-----------+
```

1. **초안 생성**: 문제 해결을 위한 첫 응답이나 코드나 계획 초안을 생성함
2. **비판 생성**: 평가 규칙에 따라 오류와 누락과 개선점을 도출함
3. **수정 반영**: 초안과 피드백을 함께 입력해 더 나은 결과를 다시 생성함
4. **종료 판단**: 품질 기준을 만족했는지 확인하고 부족하면 루프를 반복함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 평가 기준이 모호하면 루프를 반복해도 비판 내용이 흔들려 초안이 안정적으로 개선되지 않을 수 있음
   - 해결방안: rubric을 구조화하고 평가 항목을 고정하며 version별 score improvement와 final quality로 효과를 검증함
2. 문제: 수정 과정에서 이전 버전의 장점까지 함께 사라지는 regression이 발생할 수 있음
   - 해결방안: diff 기반 피드백과 best-of-n 보존 전략을 적용하고 regression rate와 task success rate로 품질을 검증함
3. 문제: 종료 조건이 약하면 같은 초안과 비판을 반복하며 무한 루프와 비용 낭비가 발생할 수 있음
   - 해결방안: max iteration과 score threshold를 강제하고 평균 iteration 수와 요청당 비용으로 종료 통제력을 검증함

## Ⅶ. 적용 사례

- 코드 자가 수정: 실행 오류를 읽고 코드 버전을 반복 교정함, 확인 지표는 unit test pass rate와 iteration count임
- 보고서 초안 개선: 논리 흐름과 누락 항목을 점검해 문서를 다듬음, 확인 지표는 review pass rate와 edit distance임
- 보안 응답 검수: 답변 초안을 정책 기준으로 재검토함, 확인 지표는 policy violation rate와 groundedness임

## Ⅷ. 결론

Reflection은 더 오래 생성하는 기술이 아니라 초안과 평가와 종료 조건을 분리해 결과 품질을 안정적으로 끌어올리는 반복 교정 아키텍처임.
