# 📖 【암기용】 개념 완전 이해

> 목적: A2A 에이전트 통신을 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: 여러 AI 에이전트가 역할을 나누고 메시지로 협업하는 통신 방식
- **왜 필요한가**: 하나의 에이전트가 모든 도메인 지식과 도구 권한을 갖는 구조는 위험과 복잡도를 키움.
- **핵심 직관**: 전문가 에이전트들이 업무를 분담하고 결과를 주고받는 협업 회의 구조임.

## 깊이 이해
- **배경·문제의식**: 고객응대, 보안분석, 코드수정처럼 여러 전문 영역이 섞인 업무는 단일 에이전트로 통제하기 어려움.
- **작동 원리**: Coordinator가 작업을 분해하고 전문 Agent에게 위임하며, 각 Agent 결과를 통합·검증함.
- **비유**: 병원에서 주치의가 영상의학과, 진단검사의학과, 약사 의견을 종합해 처방하는 방식.
- **구체 예시**: 보안 사고 분석에서 로그 Agent, 위협정보 Agent, 조치 Agent가 결과를 교환하고 최종 보고서를 생성함.
- **흔한 오해·주의점**: Agent 간 메시지도 데이터 이동이므로 권한, 목적 제한, 민감정보 마스킹이 필요함.

## 연결 개념
- Multi-Agent Collaboration — A2A의 협업 모델
- Agent Orchestration — 위임과 결과 통합
- Zero Trust — 에이전트 간 신뢰 최소화

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: A2A는 에이전트 간 역할 위임, 메시지 교환, 결과 통합을 위한 통신 구조임.
> 2. **가치**: 도메인별 전문성과 권한을 분리해 복잡 업무를 단계별로 처리함.
> 3. **판단 포인트**: 메시지 스키마, 역할 경계, 데이터 최소전달, 결과 충돌 해결이 핵심임.

---

## Ⅰ. 개요 및 필요성

A2A는 에이전트 간 통신 방식임. 다중 도메인 업무를 단일 에이전트에 집중시키면 권한 과다와 오류 전파가 발생하므로 역할 분리와 표준 메시지가 필요함.

---

## Ⅱ. 구조 및 구성요소

```text
Coordinator - -> Search Agent
              -> Analysis Agent
              -> Action Agent


              Result Aggregator
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Coordinator | 작업 분해·위임 | 정책·우선순위 반영 |
| Specialist Agent | 전문 작업 수행 | 도구·권한 범위 제한 |
| Message Schema | 요청·응답 형식 | JSON, trace, purpose |
| Aggregator | 결과 통합·충돌 해결 | 신뢰도·근거 평가 |

> 요약: A2A는 조정자, 전문 에이전트, 메시지 스키마, 통합기로 협업을 구성함.

---

## Ⅲ. 동작원리 및 흐름도

```text
목표 입력 -> 작업 분해 -> Agent 위임 -> 메시지 교환
        -> 결과 검증 -> 충돌 조정 -> 최종 응답
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 업무 목표 분해 | 역할, 입력, 완료조건 |
| 2 | Agent 선택·위임 | 권한, 도구, SLA |
| 3 | 메시지 교환 | schema, trace, 마스킹 |
| 4 | 결과 통합 | 근거, 신뢰도, 충돌 여부 |

> 요약: A2A는 역할별 결과를 메시지로 모아 검증 후 하나의 답변이나 실행계획으로 통합함.

---

## Ⅳ. 특징

| 구분 | 단일 에이전트 | A2A | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 역할 | 모든 기능 집중 | 전문 역할 분리 | Agent 수, 책임 범위 |
| 권한 | 과다 권한 위험 | 권한 최소화 가능 | 권한 위반 건수 |
| 위험 | 단일 오류 전파 | 메시지 충돌·지연 | p95 지연, 충돌률 |

> 요약: A2A는 전문성과 권한분리를 제공하지만 메시지 표준과 충돌 해결이 설계 핵심임.

---

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. Agent별 역할, 사용 도구, 접근 데이터, 금지 행동을 정책 문서와 런타임 정책으로 분리
2. 메시지에는 목적, 입력 범위, 민감도, Trace ID, 만료시간을 포함하고 DLP 필터 적용
3. 결과 통합 시 근거 수, 신뢰도, 상충 여부를 평가하고 고위험 결정은 사람 승인으로 전환

**결론 (2줄):**
- 기술사 판단: 복합 업무는 A2A로 분리하되, 단순 조회 업무는 단일 에이전트가 비용과 지연 측면에서 적합함.
- 향후 방향: A2A는 MCP와 결합해 에이전트 생태계의 협업 프로토콜로 발전함.
