# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: 머신러닝 모델을 상용 서비스에 올려보기 **'전'**에, 개발 환경(주피터 노트북 등)에서 **이미 수집되어 정답을 다 알고 있는 과거 데이터(Test Set)를 활용해 모델의 성능을 수학적으로 채점하고 검증**하는 기초 필수 단계.
- **필요성**: 아무리 급하다고 테스트 한 번 안 한 프로그램을 고객한테 풀 순 없음. 모델이 개와 고양이를 구분은 하는지, 엉뚱한 결론을 내리진 않는지 등 최소한의 '기본 지능'과 '안전성'을 증명하는 자격시험임. 여기서 낙제한 모델은 온라인(상용) 환경으로 넘어갈 자격조차 없음.
- **핵심 직관**: 수능 모의고사. 실전 수능(Online)에 가기 전, 학생(모델)을 방안에 가둬두고 작년 수능 기출문제(Offline Data)를 풀게 함. 학생이 풀고 난 답안지와 이미 발표된 진짜 정답지를 대조해서 "음, 넌 국어 점수가 90점(Accuracy)이구나. 근데 수학은 50점(Recall)이네" 하고 성적표를 매겨보는 과정.

## 깊이 이해
- **배경**: AI 모델을 개발할 때 파라미터를 살짝살짝 바꿔가며 수백 개의 버전(학습 실험)을 만듦. 이 수백 개를 전부 실제 서비스에 올려서 유저 반응을 볼 수 없음(비용 낭비, 비즈니스 파탄). 그래서 돈과 트래픽이 들지 않는 안전한 통제구역(연구실) 안에서, 빠르고 정확하게 후보 모델들을 솎아내는(Benchmarking) 체계가 필요함.
- **작동 원리 (데이터 쪼개기)**:
  1. 전체 확보한 데이터를 3조각으로 찢음: **Train(학습용, 70%), Val(모의고사용, 15%), Test(최종 수능용, 15%)**.
  2. Train 셋만 던져줘서 모델을 미친 듯이 공부시킴.
  3. Val 셋으로 살짝 테스트하며 문제집의 난이도(하이퍼파라미터)를 조율해 줌.
  4. 마지막으로 모델이 평생 한 번도 보지 못한 Test 셋을 풀게 하고, 정답과 비교해 수식(Accuracy, F1, RMSE)으로 점수를 냄.
- **구체 예시**: 병원 암 진단 AI 모델. 10만 장의 과거 X-ray 사진(정상/암 판정 완료)을 구함. 8만 장으로 모델을 학습시킴. 남은 2만 장의 사진을 보여주며 암인지 맞혀보라 함. 실제 암 환자 사진인데 정상이라고 오진한 횟수를 카운트하여 'Recall(재현율) 95%'라는 오프라인 성적표를 뽑아냄. 생명과 직결되므로 여기서 99%를 넘지 못하면 배포를 불허함.
- **흔한 오해/주의점**: "오프라인 평가 점수 높으면 실제 서비스에서도 잘하겠지?" $\rightarrow$ 최악의 착각. 기출문제(Train)를 통째로 외워서 점수만 높은 '과적합(Overfitting)'일 수 있음. 또는 수능 공부만 했는데 실전에선 토익(새로운 세상의 트렌드) 문제가 나와버리면 성적이 폭락함. 오프라인 평가는 '이론적 잠재력'일 뿐, 실전 성공의 보증수표가 아님.

## 연결 개념
- **Train/Validation/Test Split (데이터 분할)**: 오프라인 평가를 성립하게 만드는 가장 기초적이고 절대적인 규칙. 모델이 이미 본 데이터로 시험을 치면 무조건 100점이 나오므로 의미가 없음.
- **Data Leakage (데이터 누수)**: 평가용 Test 데이터의 힌트나 정답이 실수로 학습용 Train 데이터에 섞여 들어간 대형 사고. 컨닝으로 100점 맞은 학생이 탄생함.
- **Online Evaluation (온라인 평가)**: 오프라인 모의고사를 수석으로 통과한 모델이, 실제 유저들을 만나 비즈니스 지표(매출, 클릭률)를 테스트받는 최종 실전 무대.

# 📝 【답안용】 시험 답안 템플릿
## 핵심 인사이트 (3줄 요약)
- **본질**: 머신러닝 개발 라이프사이클 중 실험 및 검증 단계에서, 역사적 정답이 존재하는 통제된 과거 데이터 세트(Hold-out Test Set)를 통해 모델의 예측 성능을 통계적 지표로 정량화하는 사전 평가(Pre-deployment) 방법론.
- **가치**: 실제 상용 트래픽과 사용자 경험을 위험에 빠뜨리지 않는 제로 리스크(Zero Risk) 환경에서 수백 개의 하이퍼파라미터 조합 중 챔피언 모델을 신속히 벤치마킹하고 과적합(Overfitting) 여부를 색출해 냄.
- **판단 포인트**: 오프라인 평가의 무결성은 평가 셋의 완전한 격리(Data Leakage 방지)에 있으며, 단순 정확도(Accuracy)에 맹신하지 않고 비즈니스 도메인의 특성(오탐 위험도)을 반영한 최적의 평가 지표(Precision, Recall, F1, ROC-AUC)를 전략적으로 선택하는 것이 핵심임.

## Ⅰ. 개요 및 필요성
- **정의**: 수집된(Historical) 데이터 세트를 학습용과 평가용으로 분할하여, 모델이 학습 과정에서 관측하지 못한 데이터에 대한 예측 오차(Loss)와 수학적 성능 지표를 산출하는 정적(Static) 평가 프로세스.
- **배경**: AI 서비스 운영 중 결함 있는 모델이 배포되었을 때 발생하는 비즈니스 평판 하락과 다운타임 비용의 기하급수적 증가. A/B 테스트(Online) 이전에 검증되지 않은 가설을 걸러낼 깔때기(Funnel)의 부재.
- **필요성**: 알고리즘 성능의 '일반화 능력(Generalization)' 증명, 베이스라인(Baseline) 대비 기술적 개선도(Lift)의 수치화 확보, 모델 배포 승인(Release Gate)을 위한 필수 정량 근거 마련.

## Ⅱ. 오프라인 평가의 3단계 데이터 분할 아키텍처
데이터 격리를 통한 공정성 확보.
| 분할 데이터 (Split) | 전체 대비 비율 | 활용 목적 및 메커니즘 | 비고 |
|:---:|:---:|:---|:---|
| **Training Set**<br>(학습 셋) | 60 ~ 80% | 머신러닝 알고리즘이 패턴을 찾고 파라미터(가중치)를 직접 업데이트하는 교과서. | 모델이 직접 암기하는 데이터. |
| **Validation Set**<br>(검증 셋) | 10 ~ 20% | 학습 루프 진행 중 모델을 임시 평가하여 에폭(Epoch) 중단 시점과 최적의 하이퍼파라미터 튜닝(HPO)에 관여함. | 학습 방향성에 간접적 영향. |
| **Test Set**<br>(최종 평가 셋)| 10 ~ 20% | 개발이 완전히 종료된 후 단 1회, **최종 모델의 일반화 성능을 채점**하는 데에만 사용됨. | 철저한 은닉(Unseen Data) 필수. |

## Ⅲ. 문제 도메인별 핵심 오프라인 평가 지표 (Metrics)
정확도(Accuracy)의 함정을 피하는 무기 선택.
1. **분류(Classification) - 불균형 데이터 환경**:
   - (예: 암 진단, 사기 탐지. 정상 데이터 99%, 암 1%).
   - 단순 Accuracy를 쓰면 모델이 "전부 정상"이라고 무지성 예측해도 정확도 99% 달성이라는 통계적 함정에 빠짐.
   - **대응 지표**: **Recall(재현율, 놓치면 치명적인 경우 최우선)**, **Precision(정밀도)**, **F1-Score**(둘의 조화 평균), **AUC-ROC**(임계치 무관 성능).
2. **회귀(Regression) - 수치 예측**:
   - (예: 집값 예측, 매출 예측).
   - **대응 지표**: **MSE / RMSE**(오차에 페널티를 크게 부여), **MAE**(이상치에 덜 민감), **R²(결정계수)**.
3. **추천/랭킹(Ranking)**:
   - **대응 지표**: **NDCG**(상위 순위 노출 가중치 부여), **MAP**(평균 정밀도).

## Ⅳ. 오프라인 평가의 대표적 교차 검증 기법 (K-Fold CV)
데이터가 부족할 때 통계적 신뢰성을 끌어올리는 법.
- **한계**: 데이터를 한 번만 분할(Hold-out)하면 "어쩌다 쉬운(또는 어려운) 문제가 Test 셋에 몰려서" 점수가 널뛰는 우연성(Variance) 리스크 발생.
- **K-Fold 원리**:
  1. 전체 데이터를 K개(보통 5~10)의 조각(Fold)으로 쪼갬.
  2. 1번 조각을 Test로, 나머지 2~5번을 Train으로 써서 모델을 평가 (1회 차).
  3. 그다음 2번 조각을 Test로 써서 평가 (2회 차). 이를 K번 반복.
  4. 최종 K번의 평가 점수를 산술 평균 내어 최종 오프라인 성능으로 확정.
- **장점**: 모든 데이터가 한 번씩 철저히 평가에 참여하므로 특정 데이터 치우침에 의한 편향(Bias) 소거 및 100% 신뢰성 보장.

## Ⅴ. 실무 적용 및 결론
- **판단 지표**: 교차 검증 시 각 Fold 간 성능 편차(표준 편차) 최소화, Train 셋 성능과 Test 셋 성능 간의 격차(Overfitting Margin) 관리율, 평가 파이프라인(CI)의 실행 소요 시간.
- **실무 설계**: 모빌리티 회사 U사의 '도착 예정 시간(ETA) 예측 AI' 평가 파이프라인. 과거 무작위 분할 시, 어제 날씨와 오늘 날씨 정보가 섞여 미래 정보로 과거를 예측하는 '데이터 누수(Data Leakage)' 발생(정확도가 99%로 비정상 도출됨). 조치 방안: MLflow 평가 체계 도입 및 **Time-Series Split(시계열 롤링 검증)** 아키텍처 적용. 1) 데이터를 섞지 않고 철저히 시간순 정렬. 2) 1~3월 데이터로 학습 $\rightarrow$ 4월 평가. 그다음 1~4월 데이터로 학습 $\rightarrow$ 5월 데이터로 평가하는 점진적 윈도우 슬라이드 기법 적용. 3) 과거가 미래를 오염시키는 누수 현상 완벽 차단 후 산출된 RMSE 오차 3분 수치를 공식 배포 기준점(Threshold)으로 확립.
- **결론**: 오프라인 평가는 AI 알고리즘의 민낯을 확인하는 가장 차갑고 엄격한 실험실의 거울이다. 아무리 수학적으로 화려한 트랜스포머(Transformer) 아키텍처를 도입했어도, 이 오프라인 지표에서 전통적인 통계 베이스라인을 넘지 못하면 과감히 기각(Reject)하는 것이 엔지니어의 규율이다. 나아가 오프라인 평가와 온라인 평가(A/B Test)를 지속적으로 상관 분석(Correlation)하여, "오프라인 성적이 좋은 모델이 진짜 돈도 잘 벌어오게끔" 내부 평가지표를 지속 조율해 나가는 것이 MLOps의 궁극적 성숙도 지표다.

### 🔀 문제 유형별 목차 전환
- **Ⅱ·Ⅲ 강조 (개념/원리형)**: 분류 모델 성능 평가 지표의 혼동 행렬(Confusion Matrix) 도해(TP, TN, FP, FN) 심화 풀이. 스팸 메일(FP가 치명적, Precision 우선)과 암 진단(FN이 치명적, Recall 우선) 비즈니스 도메인의 손익 매트릭스(Cost Matrix)에 따른 평가지표 선정의 트레이드오프(Trade-off) 전략 기술.
- **Ⅴ·Ⅵ 강조 (실무/설계형)**: 오프라인 평가 파이프라인의 자동화(CI/CD) 아키텍처 설계. Github Actions에서 모델 코드가 PR(Pull Request)로 올라오면, 사내 DVC(Data Version Control)에서 골든 테스트 셋(Golden Test Set)을 끌어와 도커(Docker) 컨테이너 위에서 오프라인 평가 스크립트를 돌리고, 그 결과(F1-score)를 PR 코멘트로 자동 렌더링하는 'Continuous Testing' 워크플로우 구성 방안.
