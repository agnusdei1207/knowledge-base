## 미리 알고가기

- 신경망 처리 장치 ($NPU$): 인간 뇌의 시냅스 연결망 구조를 모사하여, 딥러닝 핵심인 고속 다차원 행렬 곱셈($MAC$, Multiply-Accumulate) 연산을 저전력 하드웨어 전용 가속 회로로 돌리는 반도체 프로세서임
- $MAC$ 연산 어레이: 가중치와 입력 행렬의 곱셈과 덧셈을 한 사이클 내에 병렬 완성해 내는 하드웨어 연산 유닛들의 배열 구조임
- 온칩 메모리 ($SRAM$): 외부 DRAM과의 불필요한 IO 전송 비용을 소거하기 위해 NPU 다이(Die) 내에 계산 유닛 바로 옆에 다량 박아넣은 초고속 정적 버퍼 메모리임
- 모델 컴파일러 ($Compiler$): PyTorch 등에서 학습 완료된 소형 모델을 특정 NPU 칩의 MAC 구조와 SRAM 용량에 맞도록 최적 연산 스케줄을 짜서 기계어로 번역해 주는 전용 컴파일러임

## Ⅰ. 개요

- **정의/개념**: NPU는 딥러닝 추론의 병목 구간인 대규모 행렬 곱셈과 Convolution 연산을 초저전력으로 가속화하기 위해, MAC(Multiply-Accumulate) 연산 코어를 바둑판 형태로 집적하고 온칩 캐시 메모리를 하드웨어적으로 극대화한 인공지능 연산 전용 반도체임
- **배경/필요성**: CPU는 복잡한 논리 제어 구조 위주라 병렬 MAC 처리에 부적합하고, GPU는 대량 병렬 계산은 강하나 수백 와트($W$)의 전기 소모와 높은 발열을 유발하여 스마트폰, 지능형 자율 차량, IoT 에지 단말의 로컬 AI 상시 가동에 심각한 물리적 장벽이 생겨 필수 도입됨

## Ⅱ. 특징

- 순수 AI 추론에만 필요한 회로(MAC) 외의 불필요한 제어 유닛(ALU 등)을 최소화하여, 동일 전력당 연산 성능(W당 Flops)이 CPU/GPU 대비 압도적으로 높음
- 딥러닝 모델의 모든 파라미터가 온칩 메모리($SRAM$) 내에 적재되도록 컴파일러 레벨의 타일링 분할을 활용해, HBM/DRAM 왕복 전송에 따른 발열을 예방함
- 최신 NPU들은 스마트 디바이스의 오프라인 인물 보정, 실시간 음성 온디바이스 받아쓰기 기능을 담당하며 OS 백엔드 런타임에 직접 매핑됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 중앙 처리 장치 (CPU) | 그래픽 처리 장치 (GPU) | 신경망 처리 장치 (NPU) |
|:---|:---|:---|:---|
| **기본 연산 강점** | 순차적 직렬 제어, 분기 예측 ($ALU$ 최적) | 그래픽 가상화, 대규모 병렬 실수 연산 | 2D/3D 행렬 곱 및 정밀도 다운 연산 ($MAC$) |
| **소비 전력 (효율)** | 중간 ~ 높음 (효율 낮음) | 극도로 높음 (열방출 심각) | 극도로 낮음 (모바일 장착 가능 수준) |
| **가속의 범용성** | 모든 소프트웨어 연산 가능 | 매우 높음 (CUDA 환경 범용 가속) | 낮음 (모델 컴파일러가 지원하는 연산에 국한) |
| **주요 적합 환경** | PC 운영체제 작동, 데이터베이스 조율 | 대규모 LLM 사전 학습, 그래픽 렌더링 | 온디바이스 모바일, 지능형 차량 자율주행, AI PC |

> 요약: CPU는 전산의 사령탑이고, GPU는 대량 실수 연산의 화력이며, NPU는 제한된 전력에서 정해진 신경망 룰을 초고속으로 뚫는 전용 돌격선임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| MAC 어레이 | 이산 연산 곱셈-누적 유닛의 2차원 매트릭스 그리드로 NPU 성능 한계를 쥐고 있는 계산부임 |
| 온칩 SRAM | 가중치 텐서 값을 연산 유닛 옆에 붙잡아 두어 HBM 버스 포화를 차단하는 초고속 캐시임 |
| DMA 제어기 | 데이터 전송과 계산 가동 타이밍을 조화롭게 제어해 MAC 어레이의 공회전을 방지하는 모듈임 |
| 런타임 컴파일러 | 기어 모델의 연산 기호를 NPU 내부 하드웨어의 연산 셋으로 쪼개 매핑하는 최적화 컴파일 스택임 |

```text
[ NPU 내부 물리 코어 배치 ]
[NPU Compiler (Graph Split)] -> [DMA Controller] -> [MAC Computations Array]
                                                           ↕ (HBM bypass)
                                                  [On-chip SRAM cache]
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 모델 추출 및| --> | NPU 연산자   | --> | 2D MAC      | --> | 출력 레지스터|
| 그래프 분석 |     | 지원 매핑    |     | 온칩 병렬계산|     | 값 반환/종료|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **그래프 정형** — 학습 완료된 PyTorch 모델 파일을 NPU 전용 컴파일러에 넣어 노드 연산 그래프를 분석함
2. **연산자 컴파일** — 모델 구조 중 NPU가 지원하는 연산자는 MAC용 기계어로 바꾸고, 미지원 특이 연산자는 CPU fallback용으로 떼어냄
3. **타일링 전송** — DMA를 구동하여 입력 이미지 조각(타일)과 양자화 가중치들을 내부 SRAM 영역으로 비동기 선적함
4. **MAC 병렬 순방향** — 타일 클록 단위로 MAC 그리드를 전력 효율 우선으로 구동하여 추론을 끝내고, 최종 텐서 결과를 메인 메모리에 반환함

## Ⅵ. 실무 적용 및 유의점

1. NPU 컴파일러 빌드 시 모델 내부에서 NPU 칩이 지원하지 않는 '미등록 커스텀 활성화 함수'가 감지되면, 해당 연산 구간만 메인 CPU로 전송되었다가 다시 돌아오는 'CPU Fallback' 오버헤드가 발생하여 속도가 처참하게 망가지므로, 설계 시 반드시 제조사의 지원 연산자 스펙($Ops$ $Support$ $List$)을 사전 확인하고, Fallback 발생률 지표를 감사해야 함
2. 실무 온디바이스 적용 시 디바이스 제조사 벤더별 NPU SDK(Intel OpenVINO, Qualcomm QNN 등) 파파선 문제로 파편화가 크므로, 반드시 하부 드라이버를 단일 인터페이스로 격리해 주는 'ONNX 런타임'을 장치에 장착하고 칩 호환성 스코어로 안정성을 모니터링해야 함

## Ⅶ. 결론

- NPU는 모바일과 에지 단말의 전력 소모 한계 속에서 인공지능 생태계를 확산시키는 AI 전용 저전력 연산의 핵이며, 설계자는 칩셋 컴파일러의 연산자 한계를 회피할 호환성 설계와 드라이버 파편화 극복 장치를 반드시 통합 구축하여 상용 제품의 성능 강건성을 완성해야 함
