## 미리 알고가기

- $KV$ 캐시 ($KV$ $Cache$): 트랜스포머의 어텐션 연산 시, 이미 계산을 완료한 이전 단어들의 Key와 Value 행렬 데이터를 VRAM에 고정해 두고 다음 단어 생성 시 재사용하는 메모리 저장 기법임
- 프리필 단계 ($Prefill$): 유입된 입력 프롬프트 전체 토큰을 일괄 연산하여 초기 $KV$ 캐시를 최초 셋업하는 단계임
- 디코드 단계 ($Decode$): 생성 단계에서 매번 하나의 새 토큰이 튀어나올 때마다, 기존에 적재된 $KV$ 캐시를 읽어 상호 작용을 반복하는 단계임
- 메모리 대역폭 한계 ($Memory-bound$): GPU 칩 내부 연산 장치의 연산량보다 메모리(VRAM)에서 데이터를 쓰고 읽어오는 대역폭 한계로 인해 성능이 지연되는 현상임

## Ⅰ. 개요

- **정의/개념**: KV Cache Optimization은 LLM 추론 가동 시 컨텍스트 길이가 길어짐에 따라 기하급수적으로 팽창하는 $KV$ 캐시 데이터의 VRAM 물리적 크기와 메모리 접근 병목을 감소시켜, 칩셋의 병렬 처리 성공률과 동시 사용자 수($Throughput$)를 극대화하는 서빙 메모리 최적화 기술군임
- **배경/필요성**: 트랜스포머 추론의 디코드 단계는 입출력($I/O$)이 병목인 대표적인 $Memory-bound$ 연산인데, 특히 멀티 에이전트나 수십만 토큰의 긴 컨텍스트 서빙 시 모델 가중치보다 $KV$ 캐시가 VRAM을 먼저 고갈시켜 $OOM$(Out-of-Memory) 장애를 폭증시킴에 따라 개발됨

## Ⅱ. 특징

- 인공지능 서빙 시스템의 최대 동시 처리 용량(배치 크기 상한)을 직접적으로 조율하는 핵심 인프라 제어 변수임
- 모델의 기저 아키텍처를 바꾸는 하드 코딩(GQA)과 이미 훈련된 모델의 가중치는 둔 채 서빙 레이어만 개조하는 방식(PagedAttention, FP8 Quantization)이 존재함
- 캐시의 차원이나 해상도를 너무 깎아내리면, 문장 뒤쪽으로 갈수록 의미 해석 정밀도가 미세하게 드리프트(퇴화)할 수 있어 주의를 요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 기본 $KV$ 캐시 보관 | 아키텍처적 절감 (GQA / MQA) | 서빙 시스템 최적화 (PagedAttention / Quantization) |
|:---|:---|:---|:---|
| **메모리 절감율** | 0% (기준선) | 우수함 (70~80% 절감 가능) | 극도로 우수함 (조각화 제거 및 FP8 압축) |
| **적용 시점** | 상시 가동 | 모델 사전 학습 또는 미세 조정 단계 | 배포 및 API 서빙 레이어 셋업 시 |
| **추론 정밀도 영향** | 100% 보존 (기준선) | 미세 저하 가능성 있음 | 양량 제어에 따라 미세 오차 발생 |
| **대표 기법** | 바닐라 트랜스포머 | Llama-3, Mistral 계열 모델 | vLLM PagedAttention, FP8 KV Cache |

> 요약: 기본형은 단순 가동에, 아키텍처형은 모델의 핵심 골격 축소에, 서빙형은 가용한 물리적 GPU 자원 활용률을 100%로 가두는 최적화에 사용됨.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 프리필 캐시 빌더 | 최초의 문맥 정보를 읽어 멀티 헤드 크기에 해당하는 기본 $K, V$ 텐서를 구성하는 생성기임 |
| 디코드 캐시 리더 | 신규 단어가 추가될 때마다 VRAM 캐시 영역에서 이전 문맥 텐서를 가져와 결합하는 적재기임 |
| $KV$ 캐시 양자화기 | 캐시 데이터의 정밀도를 기존 FP16에서 FP8 또는 INT8로 다운그레이드하여 물리 용량을 절반 이하로 압축하는 기기임 |
| 가상 페이징 엔진 | 쪼개진 비연속 물리 메모리 조각들을 하나의 가상 연속 메모리로 묶는 PagedAttention 관리부임 |

```text
[ KV 캐시 최적화 아키텍처 흐름 ]
Input Prompt -> [Prefill Engine] -> [FP8 Quantization] -> [PagedAttention Blocks] -> VRAM Alloc
- 프리필 단계의 KV 캐시를 FP8로 압축하고, 가상 페이지 블록에 조각화 없이 알뜰히 매핑함
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 입력토큰의  | --> | 캐시압축 적용| --> | 페이징 기법 | --> | 동접배치 팽창|
| 프리필 연산 |     | (FP8/FP4양자) |     | VRAM 조각소거|     | 및 가속추론 |
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **프리필 인코딩** — 사용자의 대량 프롬프트를 일괄 수용하여, 모델의 모든 트랜스포머 레이어마다 발생하는 $K, V$ 텐서를 빠르게 생성함
2. **양자화 변환** — 캐시 텐서 데이터의 float 정밀도를 $FP8$이나 $INT8$로 낮추어, 데이터 전송 대역폭 소모량과 VRAM 용량을 즉시 절반으로 세이브함
3. **가상 블록화** — PagedAttention 기법을 기동하여, 동적으로 늘어나는 $KV$ 토큰들을 페이지 블록 단위로 나누어 비연속 VRAM 영역에 분산 밀착 적재함
4. **배치 압축 해제** — 가용한 VRAM 마진이 늘어남에 따라 동시 배치 크기를 확장하고, 매 디코드 루프마다 가속화된 I/O 속도로 추론을 완수함

## Ⅵ. 실무 적용 및 유의점

1. 컨텍스트가 128K 이상으로 늘어나는 상용 환경에서 캐시 최적화가 부재하면 GPU 한 장당 동시 배치를 1로 낮추어야 하므로 인프라 적자가 발생하며, 반드시 PagedAttention과 FP8 KV Cache 기법을 동시 주입하고, 서버 인프라의 동시 요청 통과수($Throughput$)와 OOM 발생 빈도로 타당성을 검증해야 함
2. 캐시를 GPU 밖의 호스트 CPU 메모리로 밀어냈다가 당겨오는 오프로딩($Offloading$) 기법은 VRAM 용량 압박은 일시 경감하나 PCIe 통신 병목을 유발해 응답 속도가 심각하게 느려지므로, hot cache 영역만 GPU에 묶고 cold cache만 offloading하는 정교한 하이브리드 캐싱 정책을 구축해야 함

## Ⅶ. 결론

- KV Cache 최적화는 언어 모델 서빙 인프라의 경제성을 지탱하는 가장 거대한 메모리 절감 아키텍처이며, 설계자는 무작정 인프라 하드웨어를 증설하기에 앞서 가상 페이징 엔진 도입과 지능적 캐시 오프로딩 정책을 결합하여 가성비 높은 고성능 서빙 아키텍처를 완비해야 함
