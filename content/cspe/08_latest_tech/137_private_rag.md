## 미리 알고가기

- Private RAG는 외부 SaaS API 없이 사내망이나 전용 VPC 안에서 RAG 전 구간을 구동하는 구조임
- 데이터 주권과 규제 준수가 핵심 가치이며 성능보다 보안 경계가 우선임
- 오픈소스 LLM과 로컬 임베딩과 설치형 벡터 DB 조합이 일반적임

## Ⅰ. 개요

- **정의/개념**: Private RAG는 데이터 수집과 임베딩과 벡터 검색과 생성까지 RAG의 전 생애주기 파이프라인을 외부망 통신 없이 기업 통제하의 격리된 환경에서 수행하는 아키텍처임
- **배경/필요성**: 공개 SaaS 모델은 프롬프트와 문맥이 외부로 나갈 수 있으므로, 금융과 공공과 국방처럼 최고 수준의 기밀성을 요구하는 환경에서는 내부 전용 구조가 필요함

## Ⅱ. 특징

- 데이터 주권과 망분리 규정을 만족하기 쉬워 고보안 산업에 적합함
- 오픈소스 모델과 설치형 벡터 DB와 사내 GPU 자원을 중심으로 구성됨
- 클라우드 API 대비 기본 성능과 운영 편의성이 낮을 수 있어 최적화가 필요함
- 내부망이라고 해도 사용자 권한 통제와 감사 로그는 별도로 설계해야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | Public SaaS RAG | Private RAG | Permission-aware RAG |
|:---|:---|:---|:---|
| 외부 통신 | 있음 | 없음 | 환경 무관 |
| 데이터 주권 | 낮음 | 높음 | 중간 |
| 초기 구축 비용 | 낮음 | 높음 | 중간 |
| 대표 환경 | 일반 서비스 | 금융, 공공, 국방 | 기업 내부 검색 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Local Embedding Stack | 로컬 임베딩 모델이 외부 호출 없이 문서를 벡터화해 데이터 주권을 지킴 |
| On-prem Vector Store | 설치형 벡터 DB가 내부 문서를 저장하고 유사도 검색을 수행함 |
| Local LLM Runtime | 오픈소스 LLM과 vLLM 같은 런타임이 폐쇄망 안에서 답변을 생성함 |
| Security, Ops Layer | 방화벽과 KMS와 감사 로그와 비용 모니터링이 보안성과 운영성을 함께 통제함 |

```text
+-------------------+      +-------------------+      +-------------------+
| Local Embedding   | ---> | On-prem VectorDB  | ---> | Local LLM Runtime |
+-------------------+      +-------------------+      +-------------------+
                                                           |
                                                           v
                                                   +-------------------+
                                                   | Security / Ops    |
                                                   +-------------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 내부 데이터 적재 | --> | 로컬 검색 수행  | --> | 로컬 모델 생성 | --> | 감사/모니터링 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **내부 데이터 적재**: 문서와 시스템 데이터를 사내망 안에서 수집하고 인덱싱함
2. **로컬 검색 수행**: 설치형 벡터 DB와 키워드 검색으로 근거 문맥을 찾음
3. **로컬 모델 생성**: 오픈소스 LLM이 외부 호출 없이 답변을 생성함
4. **감사 및 모니터링**: 출력과 권한과 비용 상태를 폐쇄망 안에서 추적함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 로컬 모델 성능이 공개 상용 모델보다 낮으면 환각과 답변 품질 저하가 쉽게 드러날 수 있음
   - 해결방안: 도메인 튜닝과 고품질 RAG를 결합하고 faithfulness와 domain benchmark score로 검증함
2. 문제: GPU와 스토리지와 운영 인력을 모두 자체 보유해야 해 초기 구축 비용이 크게 증가할 수 있음
   - 해결방안: sLLM과 양자화와 계층형 서빙을 적용하고 TCO와 p95 latency로 투자 타당성을 검증함
3. 문제: 외부망 차단만으로 안전하다고 착각하면 내부 권한 우회와 로그 부재로 사고 대응이 늦어질 수 있음
   - 해결방안: permission-aware retrieval과 SIEM 연계를 적용하고 audit completeness와 unauthorized action rate로 검증함

## Ⅶ. 적용 사례

- 국방 지식검색이 작전 교범과 기술 문서를 사내망 안에서 조회하도록 Private RAG를 적용하며 확인 지표는 data egress incident count와 answer accuracy임
- 금융사 약관 QA가 망분리 규정을 지키면서 상담 답변을 생성하도록 Private RAG를 운영하며 확인 지표는 compliance pass rate와 p95 latency임
- 제조사 내부 기술 포털이 외부 인터넷 없이 설비 매뉴얼을 검색하도록 Private RAG를 활용하며 확인 지표는 first answer resolution과 audit completeness임

## Ⅷ. 결론

Private RAG는 단순히 모델을 내부에 설치하는 것이 아니라 데이터 주권과 망분리와 운영 최적화를 함께 만족시키는 구조이므로, 성능보다 보안 경계와 운영 지속성을 먼저 설계해야 함.
