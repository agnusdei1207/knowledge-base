# 📖 【암기용】 개념 완전 이해

> 목적: Private RAG를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: 사내망·폐쇄망 또는 전용 VPC에서 기업 데이터를 외부로 보내지 않고 운영하는 RAG 구조
- **왜 필요한가**: 민감 문서, 개인정보, 영업비밀은 외부 LLM API와 공용 SaaS로 전송하기 어렵다.
- **핵심 직관**: 회사 내부 도서관과 내부 모델만 사용해 답변을 만드는 폐쇄형 RAG임.

## 깊이 이해
- **배경·문제의식**: 기업은 데이터 국외 이전, 개인정보 처리, 계약상 비밀유지, 망분리 요구를 준수해야 한다. 일반 SaaS RAG는 이 요구를 만족하지 못할 수 있음.
- **작동 원리**: 사내 문서 저장소, 임베딩 모델, 벡터DB, LLM을 전용망에 배치하고 외부 호출 차단, 로그 암호화, 모델·색인 업데이트 절차를 통제함.
- **비유**: 외부 검색엔진을 쓰지 않고 회사 내부 자료실과 내부 상담원만으로 답변하는 방식임.
- **구체 예시**: 금융권 RAG에서 온프레미스 GPU, pgvector/Milvus, Llama 계열 모델, mTLS, 감사로그 1년 보관을 적용.
- **흔한 오해·주의점**: Private RAG가 자동으로 안전한 것은 아님. 내부 권한 오남용, PII 노출, 모델 취약점, 색인 유출을 함께 통제해야 함.

## 연결 개념
- Enterprise RAG — 기업 운영형 RAG 전체 구조
- Sovereign Cloud — 데이터 주권 요구를 반영한 클라우드 운영
- Permission-aware RAG — 내부 사용자별 권한 통제

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Private RAG는 기업 데이터를 전용망 안에서 검색·생성·평가하는 폐쇄형 RAG 구조임.
> 2. **가치**: 개인정보·영업비밀·규제 데이터를 외부 전송 없이 활용해 데이터 주권과 감사 요구를 충족함.
> 3. **판단 포인트**: 모델 품질, GPU 비용, 보안 통제, 업데이트 절차를 SaaS 대비 비교해야 함.

## Ⅰ. 개요 및 필요성

Private RAG는 사내망 운영형 RAG 아키텍처임. 민감 데이터와 규제 산업은 외부 API 전송이 제한된다. 전용망 내 LLM·임베딩·벡터DB를 구성해 데이터 유출과 국외 이전 리스크를 줄인다.

## Ⅱ. 구조 및 구성요소

```text
Internal Docs -> Private Ingestion -> Internal Vector DB
  -> On-prem/VPC LLM -> Guardrail -> Audit Log
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Private Network | 외부 호출 차단·전용망 구성 | 온프레미스, VPC, 망분리 |
| Local Models | 임베딩·LLM 내부 배포 | Llama, Qwen, BGE |
| Secure Storage | 문서·벡터·로그 암호화 | AES-256, KMS/HSM |
| Operations Control | 업데이트·감사·취약점 관리 | CVE 스캔, 모델 승인 절차 |

> 요약: Private RAG는 전용망에 검색·생성·저장·감사 구성요소를 배치해 외부 데이터 전송을 차단함.

## Ⅲ. 동작원리 및 흐름도

```text
사내 문서 수집 -> PII 처리 -> 내부 색인
  -> 사용자 질의 -> 내부 검색/LLM 생성
  -> 출처 검증 -> 암호화 로그 저장
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 사내 저장소에서 문서 수집·PII 마스킹 | PII 탐지율 ≥95% |
| 2 | 내부 임베딩·벡터DB 색인 | 외부 네트워크 호출 0건 |
| 3 | 내부 LLM으로 출처 기반 답변 생성 | Faithfulness ≥0.9 |
| 4 | 답변·근거·로그 암호화 저장 | 로그 보관 1년, AES-256 |

> 요약: Private RAG는 모든 데이터 처리와 모델 추론을 내부망에서 수행하고 출처·로그를 암호화해 보관함.

## Ⅳ. 특징

| 구분 | SaaS RAG | Private RAG | 판단 포인트 |
|:---|:---|:---|:---|
| 데이터 위치 | 외부 API·SaaS | 사내망·전용 VPC | 규제 데이터는 Private |
| 모델 품질 | 상용 최신 모델 | 내부 승인 모델 | 품질-보안 트레이드오프 |
| 비용 | API 사용량 기반 | GPU·운영 인력 비용 | 장기 사용량 기준 비교 |
| 운영 | 벤더 관리 | 자체 보안·업데이트 | CVE·모델 패치 절차 필요 |

> 요약: Private RAG는 데이터 통제력은 높지만 모델 품질·GPU 비용·운영 부담을 함께 고려해야 함.

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 금융·공공 적용: 전용 VPC, 내부 LLM, Milvus, mTLS, KMS 암호화로 외부 전송 0건 아키텍처 구성
2. 운영 통제: 모델·임베딩·색인 업데이트는 승인 워크플로우와 회귀 평가(Faithfulness 0.9 이상) 통과 후 반영
3. 보안 검증: DLP, CVE 스캔, 프롬프트 인젝션 테스트, 감사로그 1년 보관을 배포 체크리스트화

**결론 (2줄):**
- 기술사 판단: 규제·민감 데이터는 Private RAG, 공개·저위험 데이터는 SaaS RAG를 비용 기준으로 선택
- 향후 방향: Sovereign Cloud와 온프레미스 SLM 최적화로 Private RAG 적용 범위 확대
