## 미리 알고가기

- 희소 모델은 모든 파라미터를 항상 사용하는 dense 모델과 달리 일부만 선택적으로 활성화하는 구조를 뜻함
- pruning 기반 희소성과 MoE 기반 조건부 활성화는 구현 방식과 운영 의미가 다름
- 희소성이 높아도 하드웨어가 이를 잘 활용하지 못하면 실제 성능 이점이 작을 수 있음

## Ⅰ. 개요

- **정의/개념**: 희소 모델은 모델 전체 파라미터 중 일부만 활성화하거나 중요하지 않은 연결을 제거해 계산량과 메모리 사용을 줄이는 AI 구조 및 최적화 계열임
- **배경/필요성**: 대형 모델은 성능은 높지만 모든 파라미터를 매번 계산하면 비용이 너무 크므로, 필요한 부분만 쓰는 계산 구조가 요구됨

## Ⅱ. 특징

- 같은 총 파라미터를 더 낮은 활성 계산 비용으로 사용할 수 있어 규모 확장에 유리함
- pruning, sparse attention, MoE처럼 희소성을 만드는 방식이 다양하며 목적도 다름
- 불규칙한 메모리 접근과 통신 쏠림이 생기면 이론상 절감이 실제 성능 향상으로 이어지지 않을 수 있음
- 희소성 제어 정책과 하드웨어 지원 수준이 설계의 핵심 변수임

## Ⅲ. 종류 및 비교

| 판단 기준 | Dense Model | Pruning 기반 Sparse | MoE 기반 Sparse |
|:---|:---|:---|:---|
| 활성 파라미터 | 전체 사용 | 구조 일부 제거 | 입력별 일부만 사용 |
| 대표 목적 | 최대 품질 | 구조 경량화 | 계산 비용 절감과 규모 확장 |
| 하드웨어 활용 | 단순함 | 지원 편차 큼 | 통신 최적화 필요 |
| 대표 예시 | 일반 Transformer | pruning CNN, sparse linear | Mixtral, Switch Transformer |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Sparsity Policy | 어떤 연결이나 expert를 언제 비활성화할지 결정해 계산 절감 목표를 정의함 |
| Active Substructure | 실제로 선택된 채널, 블록, expert가 현재 입력의 계산을 담당함 |
| Index, Routing Metadata | 희소 구조의 위치와 선택 결과를 관리해 실행 순서를 맞춤 |
| Sparse-aware Runtime | 희소 연산과 데이터 이동을 처리해 이론상 절감을 실제 성능으로 바꿈 |

```text
                           +-------------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 입력/모델 상태  | --> | 활성 부분 선택  | --> | 부분 계산 수행  | --> | 결과 결합/반환  |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **입력 및 모델 상태 확인**: 현재 입력과 정책을 바탕으로 어떤 부분을 쓸지 판단함
2. **활성 부분 선택**: 채널이나 블록이나 expert 등 필요한 부분만 활성화함
3. **부분 계산 수행**: 선택된 경로만 계산해 비용을 줄임
4. **결과 결합 및 반환**: 부분 계산 결과를 합쳐 최종 출력을 생성함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 희소 구조가 불규칙하면 메모리 접근과 인덱스 처리 오버헤드가 커져 실제 추론 속도가 기대만큼 오르지 않을 수 있음
   - 해결방안: 구조적 희소성이나 조건부 block 단위를 우선 적용하고 real latency와 kernel efficiency로 효과를 검증함
2. 문제: 특정 경로만 자주 활성화되면 일부 파라미터는 죽고 일부는 과부하가 걸려 모델 품질과 안정성이 흔들릴 수 있음
   - 해결방안: load balancing과 activation regularization을 적용하고 utilization skew와 dropped path ratio로 균형을 검증함
3. 문제: 희소 모델 전용 런타임과 하드웨어가 부족하면 배포 환경 선택지가 제한될 수 있음
   - 해결방안: 목표 장비의 sparse 지원 수준을 먼저 평가하고 portability와 throughput gain으로 도입 적합성을 검증함

## Ⅶ. 적용 사례

- MoE 언어 모델이 일부 expert만 활성화해 비용을 줄이도록 희소 구조를 활용하며 확인 지표는 active FLOPs와 quality score임
- 모바일 비전 모델이 구조적 희소성으로 연산을 축소하도록 설계하며 확인 지표는 FPS와 power usage임
- 검색 가속 모델이 sparse attention으로 긴 입력 처리 비용을 낮추도록 적용하며 확인 지표는 latency와 memory usage임

## Ⅷ. 결론

희소 모델은 모든 파라미터를 항상 계산하는 한계를 넘기 위한 구조적 해법이지만, 선택 정책과 런타임과 하드웨어가 함께 맞물려야 비로소 실효성이 생김.
