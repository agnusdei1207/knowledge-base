## 미리 알고가기

- 희소 모델 ($Sparse$ $Model$): 모든 매개변수 행렬을 계산에 상시 투입하는 밀집 모델($Dense$)과 대비되는 개념으로, 텐서 내 일부 값을 고의적으로 0으로 솎아내거나 입력별 일부 서브 네트워크만 구동하는 설계 패러다임임
- 밀집 모델 ($Dense$ $Model$): 모델 내 존재하는 수백억 개의 모든 뉴런 연결 가중치를 한 단어도 거르지 않고 곱셈-누적($MAC$) 연산에 완전 동원하는 정적 아키텍처임
- 희소 비율 ($Sparsity$): 전체 가중치 파라미터 개수 대비 $0$(Zero)으로 비활성화되어 무효화된 매개변수의 비율을 의미함
- 부하 균등화 ($Load$ $Balancing$): 서브 네트워크나 전문가($Expert$)들이 동등한 확률로 가동되도록 유량 편향을 강제 분산 제어하여 자원 낭비를 억제하는 설계임

## Ⅰ. 개요

- **정의/개념**: Sparse Model은 초대형 신경망의 계산 비효율을 해소하기 위해, 가중치 연결의 대다수를 $0$(Zero)으로 소거하여 텐서를 가볍게 만들거나(Pruning 기반), 입력 질의어에 상응하는 최적 전문가 경로만 선택 기동하는(MoE 기반) 구조적 동적 연산 최적화 모델임
- **배경/필요성**: 모든 파라미터를 상시 가동하는 $Dense$ 모델은 학습 지능 한계에 근접할수록 비용과 발열이 기하급수적으로 폭증하여 서비스 양산 한계에 다다랐으므로, 필요한 신경세포만 동적으로 켜서 연산당 가중치 가용비를 끌어올리고자 부각됨

## Ⅱ. 특징

- 기저 모델의 전체 물리 매개변수 용량은 거대하게 유지하여 폭넓은 암기력을 확보하되, 실제 1회 연산당 실효 계산 단가(Active FLOPs)를 수분의 일 수준으로 격하시킴
- 비정형 희소화의 오버헤드를 건너뛰기 위해 $2:4$ 희소성(NVIDIA 구조적 희소 코어 가속 규격) 등 하드웨어 친화적 차원 축소를 결합함
- 조건부 활성화가 런타임 상에서 지연 없이 수행되도록 돕는 스마트 라우터 네트워크 아키텍처를 연동 탑재함

## Ⅲ. 종류 및 비교

| 판단 기준 | 밀집 모델 (Dense Model) | 가지치기 기반 희소 모델 (Pruning Sparse) | 조건부 가동 희소 모델 (MoE Sparse) |
|:---|:---|:---|:---|
| **활성 파라미터** | 전체 $100\%$ 상시 전면 동원 | 쓸데없는 연결선을 영구 거르고 축소된 텐서 구동 | 입력의 의미 맥락에 부합하는 서브 그룹만 기동 |
| **추론 연산 단가** | 매우 높음 (파라미터 비례 상승) | 낮음 (물리 연산 횟수 자체 감소) | 매우 낮음 (가상 용량 대비 활성 비용 소액화) |
| **하드웨어 가속** | 완벽함 (표준 텐서 코어) | 제한적임 (희소 텐서 코어 가속기 지원 필요) | 우수함 (분산 전문가 병렬화 런타임 요구) |
| **대표적인 사례** | Llama 3 (Dense) | 구조적 프루닝 통과 경량 비전망 | Mixtral 8x7B, Switch Transformer |

> 요약: Dense는 정통적인 전면 전술이고, Pruning 희소 모델은 불필요한 시냅스를 영구 소거한 콤팩트형이며, MoE 희소 모델은 상황에 맞춰 전문가 서브 넷만 교대로 가동하는 협동형임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 희소성 제어 정책 | 어떤 텐서 노드를 비활성화하거나, Expert 수를 동적으로 묶을지 정의한 수학적 가이드라인임 |
| 동적 서브넷 맵 | 현재 입력 프롬프트 처리에 실제 투입되는 가변 활성 시냅스 및 노드들의 구성도임 |
| 인덱스 포인터 테이블 | $0$이 아닌 유효 가중치 값들이 저장된 메모리 물리 주소를 추적 및 안내하는 매핑 리스트임 |
| 희소 런타임 커널 | GPU 텐서 코어 단에서 0 곱셈을 하드웨어 스킵 처리해 주는 하부 컴파일러 가속부임 |

```text
[ Sparse Model (MoE 기반 조건부 가동) 구조 ]
Input Query ---> [ Router Network ] ---> Select Expert 2 & Expert 5
                                             ↓ (Active sub-networks only)
                 [Expert 1] [Expert 2 (Active)] ... [Expert 5 (Active)] [Expert 8]
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 프롬프트인입| --> | 인덱스 참조/ | --> | 활성 서브넷 | --> | 연산값 병합 |
| 및 맥락 해석|     | 라우팅 판단  |     | 병렬 행렬곱 |     | 및 최종 출력 |
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **질의 인코딩** — 사용자의 자연어 질문이 들어오면 임베딩 과정을 거쳐 초기 가동 벡터를 획정함
2. **동적 파티셔닝** — 희소성 통제 로직(또는 라우터)을 작동시켜, 전체 가중치 중 이번 연산에 할당할 텐서 인덱스만을 빠르게 색인함
3. **가속 병렬 곱** — 포인터 테이블이 지목하는 가중치 영역만 SRAM 코어에 올리고, 0 연산 부위를 스킵하는 순방향 행렬 연산을 구동함
4. **결과 집계** — 개별 작동한 가중치 결과를 레이어 후단에서 합산한 뒤, 최종 디코드 토큰 스트림으로 반환함

## Ⅵ. 실무 적용 및 유의점

1. 비구조적으로 잘게 쪼갠 희소 행렬을 일반 GPU 서버에 그대로 적재하면 인덱스 참조 비용과 메모리 불규칙 접근 병목으로 추론 속도가 Dense 모델보다 오히려 둔화하므로, 반드시 NVIDIA 암페어 세대 이상의 $2:4$ 구조적 희소성($Structured$ $Sparsity$) 규격을 설계 표준으로 수립하고 검증해야 함
2. MoE 희소화 가동 시 특정 인기 전문가($Expert$) 서브 네트워크로만 연산 쿼리가 독점 쏠림(Utilization Skew)되면, 해당 카드 VRAM 버하로 요청이 유실되므로, 반드시 라우터 단에 '부하 균등화 로스($Load$ $Balancing$ $Loss$)'를 탑재하고 편향 스큐 지표를 모니터링해야 함

## Ⅶ. 결론

- 희소 모델은 모델의 전반 학습 수용량(Capacity) 한계를 유지하면서 추론 실 가동비만을 획기적으로 다이어트해 내는 차세대 연산 가성비의 표준이며, 설계자는 무작정 희소율만 높이지 말고 물리 칩셋의 하드웨어 가속 구조(2:4 스파시티 등) 부합과 라우팅 부하 균등 장치를 조화롭게 설계 배포해야 함
