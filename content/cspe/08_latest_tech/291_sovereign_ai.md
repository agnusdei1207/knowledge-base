# 📖 【암기용】 개념 완전 이해

> 목적: 소버린 AI를 국가가 자체 AI 모델을 보유한다는 좁은 의미가 아니라, 데이터·컴퓨팅·모델·인재·거버넌스를 자율적으로 통제하는 AI 역량으로 이해하게 만든다.

## 한눈에
- **개요**: 국가·조직이 자국 데이터와 인프라로 AI 개발·운영 통제권을 확보하는 전략
- **왜 필요한가**: 생성형 AI가 행정, 국방, 의료, 산업 의사결정에 들어가면 데이터 유출, 문화·언어 편향, 해외 모델 의존이 정책 리스크가 된다.
- **핵심 직관**: 외국어 사전만 빌려 쓰면 우리 법률·행정·문화 맥락을 정확히 반영하기 어렵다.

## 깊이 이해
- **배경·문제의식**: 초거대 AI는 GPU, 학습데이터, 모델 가중치, API 운영권이 소수 사업자에 집중되어 국가별 정책·언어·보안 요구를 반영하기 어렵다.
- **작동 원리**: 자국 데이터 거버넌스, 국내 AI 데이터센터, 오픈모델·자체모델, 평가체계, 안전성 검증을 결합해 AI 공급망을 통제한다.
- **비유**: 식량 안보가 농지·종자·유통망을 함께 봐야 하듯 AI 주권도 데이터·칩·모델·운영자를 함께 봐야 한다.
- **구체 예시**: 공공 민원 AI는 국내 행정문서와 법령 데이터를 RAG로 연결하고, 민감 로그는 주권 클라우드 안에서 보관한다.
- **흔한 오해·주의점**: 모든 모델을 처음부터 학습해야 소버린 AI가 되는 것은 아니다. 공개 모델, 파인튜닝, RAG, 국내 운영 통제를 조합할 수 있다.

## 연결 개념
- Sovereign Cloud — AI 데이터와 모델 운영의 인프라 기반
- RAG — 국가·조직 지식을 모델에 연결하는 방식
- AI Governance — 책임성·평가·감사를 제도화하는 체계

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.
> 핵심: 소버린 AI는 모델 자체보다 데이터 주권, 컴퓨팅 주권, 모델 운영권, 안전성 평가를 함께 보는 전략이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Sovereign AI는 국가·조직이 AI 데이터, 인프라, 모델, 운영 정책을 자율적으로 통제하는 역량임.
> 2. **가치**: 해외 API 의존, 민감 데이터 이전, 언어·법제 맥락 불일치, 공급망 중단 리스크를 낮춤.
> 3. **판단 포인트**: 자체 학습 여부보다 데이터 위치, 모델 접근권, GPU 확보, 평가·감사 체계가 판단 기준임.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| AI 주권 개념 확인 | 데이터·컴퓨팅·모델·거버넌스 통제 | 자체 LLM 보유로만 축소 |
| 공공·산업 적용 판단 확인 | 민감 데이터, 국내 언어, 법령 맥락 | 글로벌 API 금지로 단정 |
| 리스크 통제 역량 확인 | 평가, 감사, 공급망, 안전성 검증 | 모델 성능 수치만 나열 |

> 요약: 이 문제는 AI 기술보다 국가·조직 통제권을 구성요소별로 설계하는 판단을 요구한다.

---

## Ⅰ. 개요 및 필요성

- 개요: AI 통제권 확보 전략
- 배경: 생성형 AI가 공공·금융·의료 업무에 들어오며 데이터 이전, 해외 모델 의존, 설명 책임 문제가 커짐.
- 필요성: 민감 데이터는 국내 보관, 모델 응답은 법령·문화 맥락 평가, GPU·모델 공급망은 대체 경로를 확보해야 함.

---

## Ⅱ. 구조 및 구성요소

```text
National / Enterprise Data -> Data Governance -> AI Compute
  +-> Foundation Model / Open Model -> RAG / Fine-tuning -> AI Service
  +-> Evaluation / Audit -> Policy Control
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 데이터 주권 | 학습·검색 데이터 위치와 사용권 통제 | 개인정보·공공데이터 등급 |
| 컴퓨팅 주권 | GPU·스토리지·네트워크 확보 | 국내 데이터센터, 주권 클라우드 |
| 모델 주권 | 모델 가중치·API·추론 경로 통제 | 오픈모델, 자체모델, 폐쇄형 API |
| 거버넌스 | 안전성 평가와 감사 수행 | 편향, 유해응답, 로그 관리 |

> 요약: 소버린 AI는 데이터, 컴퓨팅, 모델, 거버넌스를 하나의 공급망으로 보고 통제한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
활용 업무 선정 -> 데이터 등급 분류 -> 모델 조달 / 학습 전략 선택
-> 주권 인프라 배치 -> 평가 / 감사 -> 운영 정책 갱신
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 공공·산업 업무와 민감 데이터 식별 | 데이터 분류표 |
| 2 | 자체모델, 오픈모델, API 조합 선택 | 비용, 통제권, 품질 |
| 3 | RAG·파인튜닝·추론 인프라 구성 | 데이터 위치와 접근권 |
| 4 | 안전성·정확성·감사로그 운영 | hallucination rate, audit trail |

> 요약: 소버린 AI는 업무 요구에서 출발해 데이터 등급, 모델 전략, 주권 인프라, 평가 체계를 연결한다.

## Ⅳ. 특징

| 구분 | 글로벌 AI API | Sovereign AI | 판단 기준 |
|:---|:---|:---|:---|
| 데이터 | 공급자 약관 기반 처리 | 국내·조직 통제 범위 지정 | 민감 데이터 등급 |
| 모델 | 폐쇄형 모델 의존 | 자체·오픈·상용 모델 조합 | 가중치 접근권 |
| 인프라 | 해외 리전 가능 | 주권 클라우드·전용 GPU | 관할권·가용성 |
| 평가 | 공급자 지표 중심 | 업무별 벤치마크와 감사 | 법령·언어 정확도 |

> 요약: 소버린 AI는 모델 크기보다 데이터와 운영 경로를 누가 통제하는지에 초점을 둔다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 해외 API 직접 호출 | 국내 데이터·모델 운영 경로 | 개인정보와 업무 민감도 |
| 비용 | API 사용량 과금 | GPU·모델 운영비 발생 | 장기 사용량과 고정 부하 |
| 운영 | 공급자 정책 의존 | 조직 평가·감사 책임 | 규제와 설명 책임 |

> 요약: 민감 업무는 통제권과 감사 책임이 우선이고, 공개 콘텐츠 생성은 상용 API 조합이 가능하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 모델 품질 편차 | 국내 도메인 데이터 부족 | RAG와 도메인 평가셋 구축 | 업무 정확도 |
| 공급망 병목 | GPU·모델 공급자 집중 | 멀티모델 라우팅, 예약 용량 | capacity reserve |
| 책임 불명확 | 모델·데이터·운영 주체 분리 | AI 거버넌스 RACI 정의 | 승인·감사 기록 |

> 요약: 소버린 AI 리스크는 품질, 공급망, 책임 경계에서 발생하며 평가셋과 운영 권한표로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 데이터 통제 | 민감 데이터 국외 이전 없음 | 데이터 흐름 점검 |
| 모델 품질 | 업무별 기준 점수 충족 | 정답셋·휴먼 평가 |
| 운영 감사 | 프롬프트·응답·권한 기록 보존 | 감사로그 샘플링 |

> 요약: 성공 여부는 모델 홍보 지표가 아니라 데이터 통제, 업무 품질, 감사 가능성으로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 공공·산업 업무를 민감 데이터 포함 여부와 설명 책임 수준으로 분류해 API, RAG, 자체모델 적용 범위를 정함.
2. 국내 클라우드·전용 GPU·암호키 관리·접근 감사 체계를 결합해 학습·추론 데이터 흐름을 통제함.
3. 법령·한국어·기관 문서 기반 평가셋과 red teaming 절차를 운영해 모델 변경 전후 응답 품질을 검증함.

**결론 (2줄):**
- 기술사 판단: 민감 데이터와 정책 판단이 포함되면 소버린 AI, 범용 문서 초안 생성은 상용 API+가드레일 조합이 타당함.
- 향후 방향: 소버린 AI는 소버린 클라우드, AI 반도체, 공공 데이터 거버넌스와 결합한 국가 AI 인프라로 발전함.
