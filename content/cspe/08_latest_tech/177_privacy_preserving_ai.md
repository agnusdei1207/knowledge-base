# 📖 【암기용】 개념 완전 이해

> 목적: Privacy-Preserving AI를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **정의**: 개인정보 원문 노출을 줄이면서 AI 학습·추론을 수행하는 기술 체계
- **왜 필요한가**: 의료·금융·공공 데이터는 민감정보가 포함되어 중앙 수집과 재식별 위험이 큼.
- **핵심 직관**: 데이터를 직접 보여주지 않고도 계산 결과나 학습 효과만 공유하는 방식임.

## 깊이 이해
- **배경·문제의식**: 대규모 AI는 데이터가 많을수록 정확도가 높아지지만 개인정보보호법, GDPR, 영업비밀 제약으로 원천 데이터 이동이 제한됨.
- **작동 원리**: 연합학습, 차등 개인정보보호, 동형암호, 안전한 다자간 연산, TEE를 조합해 원문 접근·재식별·모델 역추론을 줄임.
- **비유**: 여러 병원이 환자 차트를 보내지 않고 각자 계산한 통계값만 금고를 거쳐 합산하는 방식임.
- **구체 예시**: 병원 10곳이 연합학습으로 진단 모델을 학습하고, 업데이트에는 DP noise ε=3을 적용해 회원 추론 위험을 낮춤.
- **흔한 오해·주의점**: 한 가지 기술로 모든 위험을 제거하지 못한다. 학습 데이터, 파라미터, 로그, 모델 출력까지 위협 모델을 나눠야 함.

## 연결 개념
- Federated Learning — 데이터 현지 보관 기반 분산 학습
- Differential Privacy — 개인 기여도 노출을 제한하는 노이즈 기법
- Confidential Computing — TEE 기반 실행 중 데이터 보호

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Privacy-Preserving AI는 원문 데이터 노출 없이 AI 학습·추론을 수행하는 보호 기술 묶음임.
> 2. **가치**: 개인정보 규제 준수와 기관 간 데이터 협업을 동시에 달성함.
> 3. **판단 포인트**: 위협 모델에 따라 FL, DP, HE, SMPC, TEE를 조합해야 함.

## Ⅰ. 개요 및 필요성

Privacy-Preserving AI는 개인정보 보호형 AI이다. 의료·금융·공공 AI는 원문 데이터 이전 없이도 공동 학습과 분석이 필요하다. 재식별, 모델 역추론, 데이터 유출 위험을 기술·절차로 통제해야 한다.

## Ⅱ. 구조 및 구성요소

```text
Local Data → Privacy Technique → Secure Training
  → Protected Model → Audit Log
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Local Data | 원문 데이터 현지 보관 | 데이터 이동 최소화 |
| FL/SMPC/HE | 분산·암호 연산 수행 | 연산 비용 증가 |
| Differential Privacy | 개인 기여도 노출 제한 | ε 값으로 통제 |
| TEE/Audit | 실행 보호와 추적성 제공 | SGX, SEV, Nitro Enclaves |

> 요약: Privacy-Preserving AI는 데이터 현지 보관, 보호 연산, 노이즈, 실행 격리를 조합함.

## Ⅲ. 동작원리 및 흐름도

```text
위협 모델 정의 → 보호기술 선택 → 학습·추론 수행
  → 개인정보 위험 측정 → 감사·재승인
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 데이터 등급과 공격 시나리오 정의 | PII/PHI 분류 100% |
| 2 | FL·DP·HE·TEE 조합 설계 | 위협별 통제 매핑 |
| 3 | 보호 학습·추론 수행 | 원문 반출 0건 |
| 4 | 재식별·추론 공격 테스트 | membership inference AUC≤0.55 |

> 요약: 프라이버시 보존 AI는 위협 모델별 보호기술을 배치하고 공격 테스트로 잔여 위험을 확인함.

## Ⅳ. 특징

| 구분 | 중앙수집 AI | Privacy-Preserving AI | 판단 포인트 |
|:---|:---|:---|:---|
| 데이터 이동 | 중앙 저장소 반입 | 원문 현지 보관 | 규제 리스크 차이 |
| 보호 기술 | 접근통제 중심 | FL, DP, HE, SMPC, TEE | 다층 조합 필요 |
| 비용 | 학습 구조 단순 | 통신·암호 연산 비용 증가 | 지연·비용 산정 |
| 잔여 위험 | 유출 시 원문 노출 | 출력·업데이트 추론 위험 | 공격 테스트 필요 |

> 요약: Privacy-Preserving AI는 데이터 협업 범위를 넓히지만 비용과 잔여 추론 위험을 함께 관리해야 함.

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 의료 AI: 병원별 원문 EMR은 로컬 보관하고 FL+Secure Aggregation으로 모델 업데이트만 합산
2. 금융 AI: 고객 거래 분석에 DP ε=1~5 범위를 적용하고 재식별 공격 결과를 승인 문서에 기록
3. 공공 AI: TEE 기반 추론 서버와 RBAC·KMS·감사 로그를 적용해 민감정보 접근 이력 100% 보관

**결론 (2줄):**
- 기술사 판단: 민감정보 기반 AI는 중앙수집 편의보다 원문 반출 최소화와 공격 테스트 기준을 우선 적용
- 향후 방향: Privacy-Preserving AI는 데이터 결합·생성형 AI 학습의 기본 통제 구조로 정착됨
