# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: 인공지능이 데이터를 학습하거나 예측을 수행할 때, 원본 데이터(개인정보)를 훔쳐보거나 유출할 수 없도록 암호화, 노이즈 추가, 분산 처리 등의 기술을 총동원하는 AI 보안/프라이버시 기술의 집합.
- **필요성**: 병원 10곳이 모여서 세계 최고의 '암 진단 AI'를 만들고 싶지만, 환자 데이터(민감 정보)를 밖으로 빼낼 수 없어서 시작도 못함. 원본 데이터는 철저히 가리거나 제자리에 두면서도, 똑똑한 모델은 만들어내기 위해 이 기술이 필수적임.
- **핵심 직관**: 투표함 속의 비밀 유지. 개표원(AI 모델)이 총 득표수(통계적 패턴)는 정확하게 알 수 있지만, 1번 유권자(개인)가 도대체 누구를 찍었는지는 절대로 역추적할 수 없게 만드는 철통 보안 시스템.

## 깊이 이해
- **배경**: AI의 성능은 데이터 양에 비례함. 하지만 GDPR 등 개인정보 규제가 강화되면서 "데이터를 한곳에 모으는 중앙집중식 AI 학습"이 불가능해짐. 또한 ChatGPT 같은 생성형 AI가 학습 데이터(사용자 대화)를 그대로 외워버려서(Memorization) 나중에 답변으로 뱉어내는 사고가 터지며, 프라이버시 보호가 AI의 최우선 기술 난제가 됨.
- **작동 원리 (Privacy-Preserving AI의 핵심 무기 4대장)**:
  1. **연합 학습 (Federated Learning)**: 데이터를 서버로 보내지 않음. 핸드폰(기기) 안에서 각자 학습하고, 똑똑해진 '결과(가중치)'만 서버로 보냄.
  2. **차등 개인정보보호 (Differential Privacy)**: 결과값에 미세한 노이즈(가짜 정보)를 섞음. 결과 통계는 유효하지만, 특정 1명의 데이터가 포함되었는지는 역추적 불가능함.
  3. **동형 암호 (Homomorphic Encryption)**: 암호화된 데이터를 풀지 않고 암호문 그대로 덧셈/곱셈(AI 연산)을 수행함. 서버는 내가 뭘 줬는지 끝까지 모름.
  4. **신뢰 실행 환경 (TEE / Confidential Computing)**: 해커나 클라우드 관리자도 쳐다볼 수 없는 서버 안의 '강철 금고(하드웨어)' 안에서만 데이터를 풀고 학습시킴.
- **구체 예시**: 애플(Apple)의 시리(Siri). 아이폰 사용자의 음성 패턴 데이터를 애플 서버로 가져오지 않음(연합학습). 아이폰 안에서 시리를 똑똑하게 만든 뒤, 그 가중치에 노이즈를 섞어(차등 프라이버시) 서버로 보냄. 애플조차 내 목소리 원본을 절대 볼 수 없음.
- **흔한 오해/주의점**: "한 가지 기술만 쓰면 완벽해지나?" $\rightarrow$ 아님. 연합학습만 쓰면 데이터는 안 보내지만 '가중치'를 탈취해 원본을 역추적할 수 있음. 반드시 연합학습 + 동형암호(또는 차등 프라이버시) 등 여러 기술을 '블록 조립'하듯 섞어 써야(Defense in Depth) 완벽해짐.

## 연결 개념
- **Data Anonymization (데이터 비식별화)**: 과거의 방식. 이름이나 주민번호를 지우거나(가명처리) 뭉뚱그리는 수준. AI의 역추론 공격에 쉽게 뚫림. 이를 대체하는 것이 PPAI.
- **Membership Inference Attack (멤버십 추론 공격)**: 해커가 AI 모델에 질문을 계속 던져서 "너 홍길동 데이터로 학습했지?"라고 알아맞히는 공격. PPAI가 방어해야 할 1순위 적.
- **AI Security (AI 보안)**: 프라이버시 보존이 데이터를 숨기는 방패라면, AI 보안은 모델 자체가 해킹(적대적 공격)당하지 않게 지키는 더 큰 개념.

# 📝 【답안용】 시험 답안 템플릿
## 핵심 인사이트 (3줄 요약)
- **본질**: 데이터의 원문(Raw Data) 노출 없이 분산, 암호화, 노이즈 주입, 하드웨어 격리 기술을 복합적으로 사용하여 인공지능 모델의 학습(Training)과 추론(Inference)을 가능하게 하는 차세대 데이터 보안 프레임워크.
- **가치**: 데이터 프라이버시 규제(GDPR, 데이터 3법)와 데이터 활용(AI 성능 고도화) 간의 제로섬(Zero-sum) 딜레마를 돌파하여, 의료/금융 등 민감 데이터 파이프라인의 이종(Cross-silo) 결합 및 안전한 활용 생태계를 창출함.
- **판단 포인트**: 단일 기술로는 완벽한 프라이버시 보장이 불가능하므로, 위협 모델(Threat Model, 예: 내부자 위협, 역추론 공격 등)에 맞춰 연합학습(FL), 차등 프라이버시(DP), 동형암호(HE)를 상호 보완적으로 융합 설계하는 아키텍처 역량이 심사의 핵심임.

## Ⅰ. 개요 및 필요성
- **정의**: 기계학습 전 수명주기에서 개인 식별 가능 정보(PII) 및 민감 데이터가 공격자나 플랫폼 제공자(Cloud Provider)에게 노출되지 않도록 암호학적, 통계학적 보호 조치를 내재화한 AI 아키텍처.
- **배경**: 거대 언어 모델(LLM)이 훈련 데이터 내의 신용카드 번호나 비밀번호를 그대로 암기(Memorization)하여 뱉어내는 사고가 발생하며, 기존의 단순 비식별화(K-익명성 등) 기법이 한계에 봉착함.
- **필요성**: 데이터 반출이 법적으로 엄격히 금지된 규제 산업(Regulated Industry)에서, B2B 데이터 협력(Data Consortium)과 SaaS 기반 AI API의 안전한 채택을 보장하기 위함.

## Ⅱ. Privacy-Preserving AI(PPAI) 4대 핵심 기술 생태계
정보의 노출면(Attack Surface)을 원천 봉쇄하는 기술 스택.
| 기술 분류 | 대표 기술 | 동작 원리 및 강점 | 실무 한계점 (Trade-off) |
|:---:|:---|:---|:---|
| **데이터 분산 (분산 학습)** | **연합 학습**<br>(Federated Learning) | 데이터를 엣지(Edge) 단말에 두고 모델 파라미터(Weight)만 중앙 서버와 교환하여 학습. | 전송되는 파라미터를 가로채어 원본 유추 가능(Gradient Leakage 방어 필요). |
| **통계적 변조 (노이즈)** | **차등 개인정보보호**<br>(Differential Privacy) | 학습 과정이나 결과값에 수학적으로 정밀한 노이즈를 섞어 특정 개인의 포함 여부 역추적 차단. | 노이즈 주입량($\epsilon$)이 커질수록 모델의 정확도(Accuracy) 급감. |
| **암호화 연산 (소프트웨어)**| **동형 암호**<br>(Homomorphic Enc.)<br>**안전한 다자간 연산**(SMPC) | 데이터 복호화 없이 암호문 상태로 모델 학습 및 추론 연산 수행. | 연산 속도가 평문 대비 수천 배 이상 느려 딥러닝 훈련 적용 곤란. |
| **격리 환경 (하드웨어)** | **신뢰 실행 환경**<br>(TEE, Confidential Computing) | CPU 내의 물리적 보안 구역(Enclave) 안에서만 복호화하여 연산. OS 및 관리자 접근 원천 차단. | 하드웨어 벤더(Intel SGX 등) 종속성 및 측면 채널 공격(Side-Channel Attack) 리스크. |

## Ⅲ. PPAI로 방어하는 3대 주요 AI 프라이버시 공격 모델
이 방패(PPAI)로 막아야 하는 해커의 창.
1. **멤버십 추론 공격 (Membership Inference Attack)**:
   - 특정 개인의 데이터가 모델 학습에 사용되었는지 알아맞히는 공격. (예: 특정 환자의 HIV 치료 기록 학습 여부 파악). $\rightarrow$ 방어: 차등 프라이버시(DP).
2. **모델 역산/재구성 공격 (Model Inversion/Reconstruction Attack)**:
   - 모델의 응답값만 보고 훈련에 사용된 원본 데이터(얼굴 사진 등)를 역으로 복원해 내는 공격. $\rightarrow$ 방어: 연합 학습(FL) + 차등 프라이버시(DP).
3. **가중치 유출 공격 (Gradient Leakage Attack)**:
   - 연합학습 시 클라이언트가 서버로 보내는 가중치(Gradient) 업데이트 값을 중간에 가로채어 원본 데이터를 복구. $\rightarrow$ 방어: 동형 암호(HE) 또는 Secure Aggregation 적용.

## Ⅳ. PPAI의 다중 방어 아키텍처 (Defense in Depth) 설계 전략
실무에서는 단일 기술이 아닌 조합(Hybrid) 아키텍처 구성.
- **FL + Secure Aggregation**: 연합학습 파라미터 전송 시 1대1 통신을 암호화하여 서버조차 개별 클라이언트의 업데이트 값을 모르게 하고, 합산된 결과만 볼 수 있게 함.
- **FL + Local DP**: 클라이언트에서 가중치 업데이트를 서버로 쏘기 직전에 노이즈(Differential Privacy)를 추가하여 역추론 공격 완전 차단.

## Ⅴ. 실무 적용 및 결론
- **판단 지표**: 모델 연산/추론 시 지연 시간(Latency)의 SLA 충족 여부, 역추론 공격에 대한 방어 성공률(Privacy Budget 소진율).
- **실무 설계**: 국내 3대 대형 병원의 '희귀암 판독 AI 모델 공동 개발' 프로젝트. 의료법상 환자 EMR(전자의무기록) 원천 데이터는 병원 밖 반출 절대 불가함. 이에 PPAI 아키텍처(FL + HE) 도입. 1) [연합 학습] 중앙 클라우드에는 깡통 딥러닝 모델만 두고, 3개 병원 내부 서버에 모델을 내려보내 각자 원본 데이터를 학습함. 2) [동형 암호 연산] 각 병원은 똑똑해진 모델 파라미터(Gradient)를 동형 암호로 꽁꽁 싸매어 중앙으로 전송. 중앙 서버는 암호문을 풀지 않고 그대로 덧셈 평균(Aggregation)을 내어 통합 글로벌 모델을 만듦. 3) 환자 데이터는 단 1바이트도 밖으로 나가지 않았음에도, 데이터 3만 건을 모아 학습한 것과 동일한 98% 정확도의 혁신적 진단 AI 개발 성공.
- **결론**: 프라이버시 보존 AI(PPAI)는 데이터를 가두어 놓은 채 인공지능의 지혜만 빨아먹는 궁극의 연금술이다. 데이터 프라이버시가 규제를 넘어 기업의 1순위 핵심 경쟁력이 된 현재, PPAI 파이프라인의 구축 여부가 차세대 AI 플랫폼 주도권을 쥐게 될 것이다.

### 🔀 문제 유형별 목차 전환
- **Ⅱ·Ⅲ 강조 (개념/원리형)**: 동형 암호(HE) 중 연산 횟수에 제한이 없는 완전 동형 암호(FHE, Fully Homomorphic Encryption)의 Bootstrapping(노이즈 초기화) 원리와 곱셈 연산 시의 연산량 폭발 문제 깊이 서술.
- **Ⅴ·Ⅵ 강조 (실무/설계형)**: 퍼블릭 클라우드 환경에서 LLM 추론(Inference) 서비스를 제공할 때, 고객의 프롬프트(민감 정보) 유출을 방어하기 위한 기밀 컴퓨팅(Confidential Computing, AWS Nitro Enclaves) 아키텍처 프로비저닝 방안.
