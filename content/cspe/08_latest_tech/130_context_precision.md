# 📖 【암기용】 개념 완전 이해

> 목적: Context Precision을 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: RAG가 검색한 컨텍스트 중 실제 답변에 필요한 관련 근거가 상위에 얼마나 많이 포함되는지 측정하는 지표
- **왜 필요한가**: 무관 문서가 컨텍스트에 섞이면 LLM이 잘못된 근거를 인용하거나 입력 토큰을 낭비함.
- **핵심 직관**: 검색 결과 상위 5개 중 쓸모 있는 자료가 몇 개인지 채점하는 정밀도임.

## 깊이 이해
- **배경·문제의식**: RAG 검색은 Recall을 높이려 Top-K를 크게 잡지만, 관련 없는 청크가 많아지면 답변 품질이 떨어지고 비용이 증가함.
- **작동 원리**: 검색된 컨텍스트를 순위별로 평가해, 관련 근거가 상위에 배치될수록 높은 점수를 부여함. RAGAS는 정답 근거와 순위를 이용해 계산함.
- **비유**: 시험 참고자료 5장 중 4장이 문제와 직접 관련 있으면 정밀도가 높고, 1장만 관련 있으면 답안 작성이 흔들림.
- **구체 예시**: Context Precision@5가 0.55에서 0.82로 개선되면 LLM 입력 토큰은 줄고 Faithfulness가 함께 상승하는 경우가 많음.
- **흔한 오해·주의점**: Context Precision만 높아도 필요한 모든 근거를 찾았다는 뜻은 아님. Context Recall과 함께 봐야 함.

## 연결 개념
- Context Recall — 필요한 근거를 얼마나 빠짐없이 찾았는지 측정
- Reranker — 상위 컨텍스트 정밀도를 높이는 모델
- Hybrid Search — 후보 재현율과 정밀도를 함께 개선하는 검색 전략

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Context Precision은 검색 컨텍스트 상위 결과의 관련 근거 비율과 순위 품질을 측정함.
> 2. **가치**: 무관 문서 혼입을 줄여 입력 토큰 비용과 근거 오염에 따른 환각을 통제함.
> 3. **판단 포인트**: 정밀도는 높지만 재현율이 낮을 수 있으므로 Context Recall과 함께 해석함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 검색 정밀도 개념 이해 확인 | Top-K 중 관련 근거 비율과 순위 가중 계산 | Context Recall과의 평가 축 혼동 |
| 순위 품질 인식 확인 | 관련 문서의 상위 배치가 점수에 반영되는 구조 | 순위 무시한 단순 비율로 축소 서술 |
| 개선 수단 판단 확인 | 리랭킹·MMR·청크 정제와 토큰 비용 절감 효과 | 정밀도 개선에 따른 Recall 희생 가능성 누락 |

> 요약: 이 문제는 정밀도 정의가 아니라 무관 근거 혼입이 환각·비용에 미치는 영향과 개선 수단 선택을 묻는다.

## Ⅰ. 개요 및 필요성

- 개요: 검색 컨텍스트 정밀도 지표
- 배경: RAG는 검색 결과를 LLM 입력으로 쓰므로 무관 문서가 상위에 섞이면 답변 오류와 토큰 비용이 증가한다.
- 필요성: top-k 컨텍스트의 관련성 순위를 측정해 Context Precision과 nDCG로 retriever 품질을 관리한다.

## Ⅱ. 구조 및 구성요소

```text
Question -> Retrieved Contexts(rank 1..K)
  -> Relevance Judge -> Ranked Precision -> Context Precision
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Retrieved Contexts | 검색된 Top-K 청크 | 보통 Top-3~10 |
| Reference Evidence | 정답 근거 또는 gold context | 평가셋에 포함 |
| Relevance Judge | 컨텍스트 관련성 판정 | LLM Judge 또는 라벨 |
| Rank Aggregator | 순위 가중 정밀도 계산 | 상위 관련 문서에 높은 가중 |

> 요약: Context Precision은 검색된 Top-K 컨텍스트를 관련성 기준으로 판정하고 순위 품질을 반영해 계산함.

## Ⅲ. 동작원리 및 흐름도

```text
검색 실행 -> Top-K 컨텍스트 수집 -> 관련/무관 판정
  -> 순위별 정밀도 계산 -> 임계값 비교 -> 검색 개선
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | RAG 검색기로 Top-K 컨텍스트 확보 | K=5~10 |
| 2 | 각 컨텍스트의 관련성 판정 | 판정 일치율 κ ≥0.7 |
| 3 | 순위 가중 정밀도 계산 | Context Precision@5 ≥0.8 |
| 4 | 미달 시 리랭킹·청킹·검색식 개선 | 지표 10%p 이상 개선 |

> 요약: 검색 결과 상위 컨텍스트가 실제 답변 근거인지 평가해 정밀도 중심 개선 대상을 찾음.

## Ⅳ. 특징

| 구분 | Context Precision | Context Recall | 판단 포인트 |
|:---|:---|:---|:---|
| 평가 축 | 상위 결과의 관련성 | 필요한 근거의 누락 여부 | 두 지표 동시 관리 |
| 개선 수단 | Reranker, MMR, 청크 정제 | Top-K 확대, Hybrid Search | 정밀도 낮으면 리랭킹 |
| 비용 영향 | 입력 토큰 절감 | 검색 후보 증가 | SLA와 함께 조정 |
| 목표 기준 | @5 0.8 이상 | 0.85 이상 | 도메인별 임계값 |

> 요약: Context Precision은 무관 컨텍스트를 줄이는 지표이며, 필요한 근거 누락은 Context Recall로 별도 확인함.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | Top-K 축소 | 리랭킹 적용 | 선택 기준 |
|:---|:---|:---|:---|
| 개선 원리 | 하위 무관 후보를 잘라 정밀도 상승 | 관련 후보를 상위로 재배치 | Recall 여유가 크면 Top-K 축소 |
| 부작용 | 필요한 근거 탈락으로 Recall 하락 | 리랭커 지연·서빙 비용 증가 | Recall이 임계 근접이면 리랭킹 |
| 적용 비용 | 파라미터 변경만으로 즉시 적용 | 모델 서빙 인프라·튜닝 필요 | 신속 개선은 Top-K, 구조 개선은 리랭킹 |

> 요약: Recall 여유가 있으면 Top-K 축소로 즉시 개선하고, Recall 보존이 필요하면 리랭킹으로 순위를 재배치함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 판정 기준 불일치 | Judge·라벨러 간 관련성 기준 상이 | 판정 가이드라인 표준화, 일치율 관리 | 판정 일치율 κ ≥0.7 |
| Recall 희생 | 정밀도 중심의 과도한 필터링 | Precision·Recall 동시 임계 게이트 | Context Recall 동시 관측 |
| 순위 미반영 해석 | 단순 비율로만 점수 해석 | 순위 가중 계산(nDCG형) 병행 | rank 반영 점수와 비율 점수 비교 |

> 요약: 주요 위험은 정밀도 편중에 따른 Recall 희생이며, 두 지표 동시 게이트와 판정 기준 표준화로 통제함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 리랭커 적용: Hybrid Top-50 후보를 Cross-Encoder로 재정렬해 Context Precision@5 0.55->0.82 개선
2. 청크 정제: 512토큰 청크와 semantic chunking을 비교해 무관 문장 혼입률 20% 이하로 관리
3. 운영 모니터링: 상위 Top-5 중 무관 컨텍스트 2개 이상이면 검색 튜닝 티켓 자동 생성

**결론 (2줄):**
- 기술사 판단: RAG 환각이 무관 근거 혼입에서 발생하면 Context Precision을 우선 개선
- 향후 방향: 문장 단위 citation과 리랭킹 로그를 결합해 컨텍스트 정밀도 원인 분석이 세분화
