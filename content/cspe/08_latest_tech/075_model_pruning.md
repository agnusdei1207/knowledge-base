## 미리 알고가기

- pruning은 중요도가 낮은 가중치나 채널이나 헤드를 제거해 모델 크기와 연산량을 줄이는 기법임
- 비구조적 pruning은 압축률은 높지만 하드웨어 이점을 살리기 어렵고, 구조적 pruning은 실제 배포 이점이 크지만 손실 폭이 클 수 있음
- pruning 후에는 재학습이나 보정이 필요한 경우가 많음

## Ⅰ. 개요

- **정의/개념**: 모델 프루닝은 학습된 신경망에서 영향도가 낮은 연결이나 구조를 제거해 파라미터 수와 계산량을 줄이는 구조 기반 압축 기법임
- **배경/필요성**: 과대 파라미터화된 모델은 학습에는 유리하지만 배포 단계에서는 메모리와 연산 낭비가 커지므로, 실제 서비스에는 불필요한 부분을 덜어내는 최적화가 필요함

## Ⅱ. 특징

- 중요도 점수에 따라 가중치, 채널, 어텐션 헤드 같은 구조를 선택적으로 제거함
- 비구조적 pruning은 이론상 압축 효과가 크지만 하드웨어가 희소 구조를 잘 활용하지 못하면 체감 성능 향상이 제한됨
- 구조적 pruning은 실제 장비에서 속도 향상 가능성이 높지만 정확도 손실과 설계 난도가 커질 수 있음
- pruning 자체보다 어떤 구조를 얼마나 제거할지에 대한 정책과 재학습 전략이 성패를 좌우함

## Ⅲ. 종류 및 비교

| 판단 기준 | 비구조적 Pruning | 구조적 Pruning | Quantization |
|:---|:---|:---|:---|
| 제거 단위 | 개별 가중치 | 채널, 헤드, 블록 | 정밀도 |
| 이론상 압축률 | 높음 | 중간 | 높음 |
| 실제 하드웨어 이점 | 낮을 수 있음 | 상대적으로 높음 | 높음 |
| 품질 복구 필요성 | 큼 | 큼 | 중간 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Importance Scoring | 가중치 크기나 gradient 기여도를 계산해 제거 후보를 식별함 |
| Pruning Policy | 레이어별 비율과 제거 단위를 정의해 압축 목표와 손실 허용 범위를 통제함 |
| Fine-tuning, Calibration | 제거 후 무너진 정확도를 복구해 실제 업무 품질을 다시 맞춤 |
| Deployment Runtime | 희소 구조나 축소 구조를 하드웨어가 실제로 활용하는지 검증해 체감 성능을 결정함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 중요도 평가    | --> | 구조 제거      | --> | 재학습/보정    | --> | 배포 벤치마크   |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **중요도 평가**: 가중치와 채널과 헤드별 기여도를 계산해 제거 후보를 선정함
2. **구조 제거**: 정책에 따라 불필요한 연결이나 블록을 삭제함
3. **재학습 및 보정**: 손상된 품질을 복구하고 업무 정확도를 다시 맞춤
4. **배포 벤치마크**: 실제 장비에서 속도와 메모리와 정확도를 함께 확인함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 비구조적 희소화는 파라미터 수는 줄여도 하드웨어가 희소 연산을 효율적으로 처리하지 못하면 실제 속도 향상이 거의 없을 수 있음
   - 해결방안: 구조적 pruning을 우선 검토하고 real FPS와 end-to-end latency로 런타임 이점을 검증함
2. 문제: 과도한 pruning은 특정 레이어의 표현력을 무너뜨려 장문 추론이나 희귀 패턴 처리 품질을 크게 떨어뜨릴 수 있음
   - 해결방안: 레이어별 pruning budget을 차등 적용하고 task accuracy와 long-tail error rate로 손실 범위를 검증함
3. 문제: pruning 후 재학습 비용이 커지면 단순 양자화보다 총비용이 더 높아질 수 있음
   - 해결방안: retraining cost와 inference cost reduction을 함께 비교해 TCO 기준으로 도입 여부를 검증함

## Ⅶ. 적용 사례

- 모바일 비전 모델 경량화: 구조적 pruning으로 CNN 크기를 축소함, 확인 지표는 FPS와 model size임
- 산업용 카메라 추론: 채널 단위 pruning으로 현장 장비 속도를 높임, 확인 지표는 latency와 device power usage임
- 특화 소형 모델 최적화: 제한된 도메인 모델에서 일부 헤드를 축소함, 확인 지표는 domain accuracy와 memory reduction임

## Ⅷ. 결론

모델 프루닝은 불필요한 구조를 줄여 배포 효율을 높이는 강력한 방법이지만, 희소 구조를 실제 하드웨어가 얼마나 활용하는지와 재학습 비용까지 함께 따져야 실무적으로 의미가 생김.
