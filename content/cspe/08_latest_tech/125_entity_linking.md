# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: 자연어 텍스트 속에 등장한 인물, 장소, 조직 등의 이름(Mention)을, 위키피디아나 사내 지식그래프(KB)에 있는 고유한 식별자(Entity ID)와 정확히 짝지어 연결하는 자연어 처리 기술.
- **필요성**: 텍스트에 "사과"라고 적혀 있으면 이게 과일인지, 스티브 잡스의 회사인지, 사죄의 의미인지 컴퓨터는 모름. 동음이의어와 다양한 별칭(애플, Apple Inc.)을 하나의 고유한 객체(ID: Q312)로 통일시켜 주어야 엉뚱한 검색이나 정보 누락을 막을 수 있음.
- **핵심 직관**: 동명이인 구별하는 주민등록번호 부여 작업. 뉴스에서 "이재용"이라는 단어를 발견하면, 그게 야구선수 이재용인지, 삼성 회장 이재용인지 문맥을 읽고 판단해서 "고유번호 9901(삼성 회장)" 딱지를 붙여주는 것.

## 깊이 이해
- **배경**: NER(개체명 인식) 기술은 단순히 "여기 명사가 있네(이름, 장소)"까지만 찾아냄. 하지만 지식그래프 구축이나 고도화된 RAG를 위해서는 텍스트 속 단어가 실제 현실 세계의 '어떤 구체적 대상'인지 식별하는 개체 연결(Disambiguation) 단계가 필수적으로 요구되며 발전함.
- **작동 원리 (3단계 파이프라인)**:
  1. **Mention Detection (개체명 탐지)**: "어제 **잡스**가 **애플** 신제품을 발표했다"에서 '잡스'와 '애플'을 찾아냄 (NER 역할).
  2. **Candidate Generation (후보 생성)**: 지식 DB를 뒤져서 '애플'의 후보군을 뽑아옴 (후보 1: 과일 사과, 후보 2: IT 기업 애플, 후보 3: 애플 레코드).
  3. **Entity Disambiguation (개체 중의성 해소)**: 문맥(잡스, 신제품)을 딥러닝(BERT 등)으로 파악하여, "아, 여기서 애플은 IT 기업(ID: Q312)이 확실하네!" 하고 후보 2번과 최종 연결함. 연결할 대상이 DB에 아예 없으면 NIL(없음) 처리.
- **구체 예시**: 병원 차트에 "환자가 AA를 호소함"이라고 적힘. 'AA'는 'Aplastic Anemia(재생불량성 빈혈)'의 약자일 수도 있고, 'Alcoholics Anonymous(익명 알코올중독자들)'일 수도 있음. 주변 텍스트에 '수혈', '골수'가 있으면 의료 AI는 이를 재생불량성 빈혈 코드(D60)로 Entity Linking 하여 치명적 처방 오류를 막음.
- **흔한 오해/주의점**: 사전(Dictionary) 매칭만으로 EL을 하려다간 무조건 망함. 사전에 "애플=IT기업"이라고 박아두면 과일 가게 데이터에서도 IT기업으로 인식함. 반드시 문맥(Context)을 이해하는 딥러닝 벡터 검색 단계(Disambiguation)가 포함되어야 함.

## 연결 개념
- **NER (Named Entity Recognition)**: 텍스트에서 사람, 장소 같은 고유명사를 찾아 형광펜을 칠하는 선행 기술. (누구인지는 모름).
- **Knowledge Graph (지식그래프)**: Entity Linking이 찾아낸 고유 ID들이 저장되어 있는 최종 종착지(백과사전).
- **Disambiguation (중의성 해소)**: 같은 단어가 여러 의미를 가질 때 문맥을 통해 올바른 하나를 콕 집어내는 EL의 가장 핵심이자 어려운 단계.

# 📝 【답안용】 시험 답안 템플릿
## 핵심 인사이트 (3줄 요약)
- **본질**: 비정형 텍스트 내에서 추출된 표면형 멘션(Surface Mention)을, 다의어(Polysemy)와 동의어(Synonym)의 난관을 뚫고 지식 베이스(Knowledge Base, 예: 위키데이터) 상의 고유 엔티티(Unique Identifier)에 맵핑(Mapping)하는 중의성 해소 알고리즘.
- **가치**: 정보의 파편화와 중복을 제거하여 데이터 정규화(Normalization)를 달성하며, 이를 통해 지식그래프의 노드 무결성 확보 및 RAG 검색 시 어휘 불일치(Vocabulary Mismatch)에 따른 정보 유실(Recall 하락)을 완벽히 방어함.
- **판단 포인트**: Entity Disambiguation 단계에서의 딥러닝 모델(Bi-Encoder/Cross-Encoder) 연산 부하 통제, 그리고 지식 베이스에 존재하지 않는 신규 개체(Out-of-KB)에 대한 NIL(Not-In-Lexicon) 예측 처리 및 클러스터링 확장 역량.

## Ⅰ. 개요 및 필요성
- **정의**: 자연어 텍스트에서 명명된 개체(Named Entity)를 식별하고, 해당 멘션이 가리키는 실제 현실 세계의 대상(Entity)을 목표 지식 베이스(KB, Knowledge Base) 내에서 찾아 고유 식별자(URI 또는 ID)와 연결하는 프로세스.
- **배경**: 단순 키워드 검색이나 NER 파이프라인은 '뉴욕(도시)'과 '뉴욕 타임스(언론사)'를 구분하지 못하며, '미국', 'USA', '천조국'이 동일 객체임을 인식하지 못해 데이터 통합 및 질의 응답에 치명적 결함을 노출함.
- **필요성**: 엔터프라이즈 환경의 흩어진 사일로 데이터들을 하나의 지식그래프(Knowledge Graph)로 정합성 있게 꿰어내고, LLM에게 정확한 팩트 컨텍스트를 제공하기 위한 필수 전처리 엔진임.

## Ⅱ. Entity Linking 파이프라인 아키텍처
| 단계 | 세부 프로세스 | 핵심 기술 및 특징 |
|:---:|:---|:---|
| **1. Mention Detection** | 텍스트 내에서 개체명 범위(Span) 추출 | NER(BiLSTM-CRF, BERT-NER) 활용. (예: `[이순신]` 장군이...) |
| **2. Candidate Generation**| KB에서 연결 가능성이 있는 후보 엔티티 Top-K 추출 | Alias Table(동의어 사전), BM25 검색. 후보군을 좁혀 연산 속도 확보. (Recall이 생명) |
| **3. Entity Disambiguation**| 문맥(Context)을 분석하여 최종 1개의 정답 엔티티 선택 | 텍스트 문맥 임베딩과 KB의 엔티티 임베딩 간의 Cross-Attention 연산 (정밀도 극대화). |
| **4. NIL Prediction** | KB에 존재하지 않는 신조어나 신규 인물인 경우 판단 | 임계값(Threshold) 미달 시 'NIL(없음)'로 반환 후 신규 엔티티로 등록 대기. |

## Ⅲ. 핵심 챌린지: 중의성(Disambiguation) 해결 메커니즘
- **문맥 유사도 (Contextual Similarity)**: 멘션 주변의 단어 벡터(Local Context)와 지식 베이스 내 엔티티의 설명문(Description) 벡터 간의 코사인 유사도 산출.
- **그래프 구조적 일관성 (Coherence)**: 문서 내에 등장한 다른 멘션들과의 관계를 이용. 
  - *예시*: 문서에 `[워싱턴]`과 `[링컨]`이 같이 등장했다면, 도시 '워싱턴 D.C' 보다는 사람인 '조지 워싱턴'일 확률이 그래프상 관계 거리(Relation Distance) 연산 결과 압도적으로 높음을 이용해 중의성 극복.

## Ⅳ. NER (Named Entity Recognition)과의 명확한 차이점
| 비교 지표 | NER (개체명 인식) | Entity Linking (개체 연결) |
|:---:|:---|:---|
| **수행 목적** | 단어의 '경계'와 '카테고리(유형)' 식별 | 텍스트가 지시하는 '구체적인 고유 대상' 식별 |
| **출력 결과** | `[삼성전자]` $\rightarrow$ `Organization (조직)` | `[삼성전자]` $\rightarrow$ `지식베이스 ID: KR-005930` |
| **중의성 해결** | 다루지 않음 (모두 같은 조직으로 인식) | 해결함 (삼성전자 vs 삼성전자우 분리) |
| **지식 베이스(KB)**| 필요 없음 | **필수적 (연결할 목표 지점이 있어야 함)** |

## Ⅴ. 한계점 및 실무 고도화 전략
- **리스크 1: 콜드 스타트 및 Out-of-KB (NIL) 문제**:
  - 새로 생긴 벤처기업이나 신조어는 지식 베이스에 없기 때문에, 모델이 억지로 엉뚱한 기존 엔티티에 연결(False Positive)하는 치명적 오류 발생.
  - **대응 방안**: 모델의 출력 Confidence Score가 일정 임계점 미만이면 `NIL` 태그를 부여하고, 텍스트 상의 멘션들을 임베딩 기반 클러스터링(Entity Discovery)으로 묶어 새로운 엔티티 노드로 자동 확장 생성하는 MLOps 파이프라인 구축.
- **리스크 2: 후보 생성(Candidate Generation)의 Recall 병목**:
  - 2단계 후보 추출에서 정답 엔티티가 포함되지 않으면, 3단계의 무거운 딥러닝 모델이 아무리 훌륭해도 정답을 맞출 수 없음.
  - **대응 방안**: Bi-Encoder 기반의 Dense Retrieval 모델을 활용해 철자가 조금 틀리거나(Typo) 형태소가 달라도 의미적 후보군을 풍성하게 가져오는 하이브리드 후보 생성 로직 적용.

## Ⅵ. 실무 적용 및 결론
- **판단 지표**: In-KB Accuracy (기존 엔티티 연결 정확도), NIL Precision (신규 개체 판별 정밀도), 후보군 Recall@10.
- **실무 설계**: 대형 제약사 신약 개발 RAG 구축 시. 수십만 건의 논문과 임상 차트에서 화합물과 유전자를 추출해야 함. "TP53" 유전자는 종양 억제 유전자로 문서마다 수십 가지 약어로 기재됨. 단순 NER로는 논문 통합 불가. PubMed 지식 베이스를 타겟으로 Entity Linking 파이프라인(BioBERT 활용)을 가동하여, 모든 이형 표기를 하나의 ID(HGNC:11998)로 통일시킴. 이를 통해 RAG 검색 시 "P53 관련 부작용" 질의 하나만으로 전 세계 논문의 99%를 누락 없이 맵핑하여 LLM에 제공.
- **결론**: Entity Linking은 혼돈의 비정형 텍스트를 질서 정연한 연결 데이터(Linked Data)로 변환하는 '의미론적 닻(Semantic Anchor)'이며, 이것이 선행되지 않은 지식그래프와 RAG는 모래 위에 지은 집처럼 추론의 오류를 피할 수 없음.

### 🔀 문제 유형별 목차 전환
- **Ⅱ·Ⅲ 강조 (개념/원리형)**: 멘션과 엔티티 간의 Local Context Attention 연산 구조, Global Coherence를 풀기 위한 그래프 신경망(GNN) 기반의 Random Walk 알고리즘 원리 상세.
- **Ⅴ·Ⅵ 강조 (실무/설계형)**: LLM (GPT-4 등)의 In-context Learning을 활용한 Zero-shot Entity Linking 트렌드, 엔터프라이즈 환경에서의 동의어 사전(Alias Dictionary) 구축 및 지속적 파인튜닝 파이프라인 작성.
