# 📖 【암기용】 개념 완전 이해

> 목적: FPGA AI 가속(FPGA AI Acceleration) 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 하드웨어 회로를 소프트웨어처럼 다시 설계(Reconfigurable)할 수 있는 반도체(FPGA)를 활용하여 AI 연산을 가속하는 기술
- **왜 필요한가**: GPU는 범용적이라서 특정 알고리즘에 딱 맞게 최적화하기 어렵고, ASIC(TPU 등)은 한 번 만들면 설계를 못 바꿈. FPGA는 알고리즘이 바뀌어도 회로를 즉시 수정할 수 있어 변화가 빠른 AI 분야에 유리함
- **핵심 직관**: "레고 블록처럼 내가 원하는 모양(AI 회로)으로 언제든 조립하고 다시 부술 수 있는 하드웨어"

## 깊이 이해
- **배경·문제의식**: AI 알고리즘은 매주 새로운 논문이 나올 정도로 발전 속도가 빠름. 수백억 원을 들여 ASIC 칩을 만들었는데 다음 달에 더 좋은 알고리즘이 나오면 칩이 쓸모없어짐. 또한 자율주행이나 금융 거래처럼 '지연 시간(Latency)'이 극도로 중요한 분야에서는 GPU의 명령어 처리 방식조차 너무 느림
- **작동 원리**: ① **로직 재구성**: 룩업 테이블(LUT)과 배선을 프로그래밍하여 AI 연산에 필요한 하드웨어 파이프라인을 직접 구축함. ② **명령어 없음**: CPU/GPU처럼 명령어를 읽고 해석(Fetch-Decode)하는 단계가 없음. 데이터가 들어오면 바로 하드웨어 회로를 통과하며 결과가 나옴(Zero-overhead). ③ **저전력**: 안 쓰는 회로는 꺼두고 필요한 부분만 정밀하게 돌리므로 전력 효율이 좋음
- **비유**: 만능 요리사(GPU)에게 레시피(소프트웨어)를 주는 대신, 그 요리만 만드는 전용 기계(FPGA)를 그 자리에서 3D 프린터로 뽑아서 쓰는 것
- **구체 예시**: 마이크로소프트의 프로젝트 캐터펄트(Catapult). 빙(Bing) 검색 엔진의 랭킹 연산을 FPGA로 처리하여 서버 대수를 줄이고 속도를 높임. 자율주행차의 센서 데이터 실시간 처리에도 많이 쓰임
- **흔한 오해·주의점**: "FPGA가 GPU보다 무조건 빠르다"는 오해임. 최대 연산량(Peak Throughput)은 GPU가 훨씬 높음. FPGA는 '지연 시간(Latency)'이 중요한 실시간 작업에서 압도적인 성능을 보임

## 연결 개념
- **LUT (Look-Up Table)**: FPGA 내부에서 논리 회로를 구현하는 기본 단위
- **ASIC vs FPGA**: 고정된 성능 vs 변경 가능한 유연성
- **HW/SW Co-design**: 소프트웨어 알고리즘과 하드웨어 회로를 동시에 설계하는 기법

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 유연성(Flexibility)을 넘어 **파이프라인 병렬성(Pipeline Parallelism), 결정론적 지연 시간(Deterministic Latency), 저전력 특성**을 강조한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: FPGA AI 가속은 프로그래머블 로직 반도체를 활용하여 AI 알고리즘의 연산 흐름에 최적화된 하드웨어 데이터 패스(Data Path)를 직접 구현하는 기술이다.
> 2. **가치**: 명령어 해석 오버헤드가 없어 극도로 낮은 지연 시간(Low Latency)을 실현하며, 변화하는 AI 모델에 즉각 대응 가능한 유연성과 ASIC 수준의 전력 효율성을 동시에 제공한다.
> 3. **판단 포인트**: 연산 정밀도(INT8, FP16 등)에 최적화된 DSP 블록 활용도, 칩 내부 메모리(BRAM) 대역폭, 알고리즘 업데이트 빈도에 따른 하드웨어 재구성 비용을 고려해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| AI 가속기별 특성 구분 역량 확인 | Reconfigurability, Low Latency, Energy Efficiency | 단순히 "변경 가능하다"는 일반론적 서술 |
| 실시간 처리 성능 차별화 포인트 파악 | No Instruction Fetch, 파이프라인 구조, 하드웨어 레벨 병렬성 | GPU와의 비교 시 Peak 성능만 강조 |

> 요약: 명령어 오버헤드가 없는 '데이터 중심 하드웨어 가속'과 '유연성'을 핵심 논점으로 잡는다.

## Ⅰ. 개요 및 필요성

- 정의: AI 연산 로직(곱셈, 활성화 함수 등)을 하드웨어 레벨에서 직접 구성(Hard-wired)하여 처리하는 재설정 가능 가속기 기술
- 배경: AI 알고리즘의 빠른 진화 주기(Cycle)와 실시간 추론(Real-time Inference)에서의 결정론적 지연 시간 요구 증대
- 필요성: ASIC의 높은 초기 투자비(NRE) 리스크 분산, GPU의 높은 전력 소모 및 명령어 오버헤드 극복, 엣지(Edge) 단의 맞춤형 가속

---

## Ⅱ. 구조 및 구성요소

```text
[FPGA Fabric]
  |-- Configurable Logic Blocks (CLB): LUT 기반 논리 구현
  |-- DSP Slices: 고속 곱셈-누산(MAC) 전담 하드웨어
  |-- Block RAM (BRAM): 가중치/데이터 버퍼 (칩 내 고속 메모리)
  |-- Programmable Routing: 로직 간 데이터 경로 설정
  `-- I/O Blocks: 외부 인터페이스 (PCIe, Ethernet)
```

| 구성요소 | 역할 | 기술적 특징 |
|:---|:---|:---|
| LUT (Look-Up Table) | 임의의 논리 함수(AND, OR 등) 구현 | 4~6 입력 기반의 진리표 구조 |
| DSP Slice | AI 핵심인 행렬 연산 가속 | 하드웨어 기반의 고정 소수점/부동 소수점 연산기 |
| BRAM | 연산 데이터의 로컬 캐싱 | 수십 MB 규모의 초고대역폭(On-chip) 메모리 |
| Soft IP / Hard IP | 미리 설계된 AI 연산 모듈 | 텐서 프로세서(DPU) 등의 로직 블록 |

> 요약: 로직(CLB), 연산(DSP), 저장(BRAM) 요소를 사용자가 의도한 데이터 흐름에 맞춰 연결하는 아키텍처이다.

---

## Ⅲ. 동작원리 및 흐름도

```text
Algorithm Model -> High-Level Synthesis -> Bitstream Gen -> Hardware Mapping -> Execution
(PyTorch/ONNX)      (C/C++ to RTL)        (회로 정보 생성)   (FPGA 로딩)      (명령어 없이 수행)
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | AI 모델(가중치/연산 그래프) 최적화 및 양자화 | INT8/INT4 등 하드웨어 친화적 변환 |
| 2 | HLS(High-Level Synthesis)를 통한 RTL 코드 생성 | 연산기 간 파이프라인 스테이지 설계 |
| 3 | 비트스트림(Bitstream) 파일을 FPGA에 기록 | 하드웨어 로직 구성 완료 |
| 4 | 입력 데이터가 로직 회로를 직접 통과하며 연산 | 명령어 오버헤드 유무 (Cycle-accurate) |

> 요약: 소프트웨어 모델을 하드웨어 회로 정보로 변환하여 FPGA에 굽고(Programming), 데이터가 회로를 즉시 통과하게 한다.

## Ⅳ. 특징

| 구분 | GPU (Software Based) | FPGA (Hardware Based) | 판단 포인트 |
|:---|:---|:---|:---|
| 처리 방식 | 명령어 기반 (Fetch-Decode-Exec) | 로직 기반 (Direct Flow) | 지연 시간(Latency) 차이 |
| 연산 병렬성 | 수천 개의 스레드 병렬성 | 하드웨어 파이프라인 병렬성 | 실시간성 vs 처리량 |
| 전력 효율 | 중간 (범용 회로 가동) | 높음 (필요 회로만 활성) | 단위 전력당 성능 |
| 지연 시간 | 가변적 (Jitter 발생) | 결정론적 (Constant Latency) | 실시간 제어 가능 여부 |

> 요약: FPGA는 명령어 처리가 없어 지연 시간이 극도로 낮고 일정하며, 전력 효율이 뛰어나다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | CPU/GPU (범용) | FPGA (유연/고성능) | ASIC (고정/최고성능) |
|:---|:---|:---|:---|
| 설계 유연성 | 매우 높음 (S/W만 변경) | 높음 (H/W 재구성 가능) | 없음 (H/W 고정) |
| 개발 비용 | 낮음 | 중간 | 매우 높음 (천억 단위) |
| 지연 시간 | 높음 | 매우 낮음 | 매우 낮음 |
| 수치 사례 | Latency: ms 단위 | Latency: us 단위 | Latency: us 단위 |

> 요약: 대규모 양산 전 단계나 초저지연이 필요한 특수 분야에서 FPGA가 최적의 선택지이다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 개발 난이도 | HDL(Verilog/VHDL) 지식 필요 | HLS 도구 활용, AI 전용 IP 사용 | 개발 공수(Man-Month) |
| 연산 밀도 한계 | ASIC 대비 트랜지스터 활용 효율 낮음 | AI 특화 DSP 탑재 모델(Stratix, Versal) | 칩 면적당 TOPS 성능 |
| 메모리 대역폭 | 일반 DDR 사용 시 병목 발생 | HBM 탑재 FPGA 모델 선정 | Memory Bandwidth (GB/s) |

> 요약: 개발 난이도를 낮추기 위해 상위 수준 합성(HLS) 도구와 AI 전용 가속 블록이 포함된 칩을 사용한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 종단 지연 (End-to-End Latency) | 1ms 이하 달성 | 오실로스코프 또는 정밀 타이머 |
| 자원 사용률 (Utilization) | LUT/DSP 80% 이상 활용 | 합성 도구(Quartus, Vivado) 리포트 |
| 전력 소모 | GPU 대비 50% 이하 절감 | 전력 분석기로 실시간 측정 |

> 요약: 실시간성(Latency)과 자원 효율성, 전력 소모량을 지표로 도입 효과를 평가한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. **검색 엔진 가속**: Microsoft Bing 검색의 특징 추출(Feature Extraction) 및 랭킹 연산에 FPGA를 도입하여 처리 성능 2배 향상
2. **초단타 매매 (HFT)**: 주식/선물 거래 시장의 호가 데이터 분석 및 주문 생성을 FPGA로 10us 이내에 처리하여 경쟁 우위 확보
3. **엣지 비전 (Edge Vision)**: 스마트 팩토리의 불량 검수용 AI 모델을 FPGA에 탑재하여 저전력 환경에서 실시간 60FPS 이상 처리

**결론 (2줄):**
- 기술사 판단: FPGA는 AI 알고리즘의 '하드웨어적 재현'이며, 가변적인 AI 트렌드와 고정된 ASIC 사이의 최적의 기술적 절충점이다
- 향후 방향: FPGA 내부에 고성능 AI 코어를 미리 박아놓은 ACAP(Adaptive Compute Acceleration Platform) 형태로 발전하여 범용성과 성능을 동시 확보할 전망이다
