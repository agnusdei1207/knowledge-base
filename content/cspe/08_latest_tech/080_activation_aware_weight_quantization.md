## 미리 알고가기

- 활성값 인지 양자화 ($AWQ$, Activation-aware Weight Quantization): 모델 추론 가동 중 실시간 튀는 활성값($Activation$)의 크기를 관찰하여, 유독 중요하게 반응하는 가중치 채널($1\%$ 수준)을 선별한 후 양자화 대상에서 제외해 정밀도를 완벽 보호하는 포스트 훈련 양자화($PTQ$) 기법임
- 두드러진 가중치 ($Salient$ $Weights$): 행렬 곱에서 큰 활성값과 짝을 이루어 모델 출력과 문맥 전달에 지대한 공헌을 수행하는 상위 핵심 가중치 그룹임
- 가중치 스케일 보호 ($Scale$ $Protection$): 중요 채널 가중치를 강제로 $FP16$ 부동소수로 영구 고정하거나, 해당 채널에 큰 스케일 값을 인위적으로 덧대어 정수 변환 시 소실되는 범위를 원천 차단하는 최적화 공식임
- 혼합 정밀도 배포 ($Mixed-width$): 핵심 $1\%$ 가중치 채널은 원래의 $FP16$으로 보존하고, 나머지 일반 $99\%$ 가중치만 $4$-bit 정수로 압축하여 하나의 모델 텐서 내에 혼재 적재하는 방식임

## Ⅰ. 개요

- **정의/개념**: AWQ는 언어 모델이 추론을 가동할 때 나타나는 활성값(Activation)의 채널 분포를 분석하여, 출력 결과에 핵심적인 기여를 하는 상위 $1\%$의 두드러진 가중치(Salient Weights)를 선별 감지하고, 이 중요 채널에 스케일 융합 보호를 적용한 채 나머지 가중치만 $4$비트로 사상하여 지능 손실을 원천 격리하는 PTQ 최적화 기법임
- **배경/필요성**: 기존 4비트 양자화는 가중치의 절댓값 크기만을 기준으로 솎아내어 정밀도 붕괴가 잦았는데, 실제 사용자가 입력한 자연어 대화 흐름(Activation) 속에서 가장 영향력이 뜨거운 가중치 채널을 실시간 사수해 성능 복원율을 극대화하고자 제안됨

## Ⅱ. 특징

- 가중치(Weight)의 정적 형태만 뜯어보는 GPTQ 등과 달리, 활성값(Activation)의 동적 흐름과 짝을 맞춰 핵심 채널을 파악하므로 의미론적 정확도 방어율이 월등히 우수함
- 중요한 가중치 채널(Salient Weight)을 $FP16$으로 고정해 두어도 전체 용량의 단 $1\%$ 미만이므로, $4$비트 양자화 고유의 VRAM 절감 효과($75\%$ 감축)를 무손실 보존함
- $vLLM$ 서빙 엔진에서 기본 핵심 커널로 컴파일 연동되어 있어, 실시간 추론 시 가중치 역양자화 가속 성능이 매우 쾌적함

## Ⅲ. 종류 및 비교

| 판단 기준 | Naive 4비트 양자화 | GPTQ 양자화 (헤시안 보정) | AWQ 양자화 (활성값 인지 스케일링) |
|:---|:---|:---|:---|
| **중요 채널 보호** | 없음 (일괄 강제 압축) | 없음 (Hessian 오차 역전파 전이) | 있음 (상위 $1\%$ Salient Weights 선별 보호) |
| **정밀도 유지 능력** | 낮음 (Perplexity 악화) | 우수함 (수학적 오차 보존) | 극도로 우수함 (장문맥 및 다단계 추론서 최상 품질) |
| **변환 컴파일 난이도** | 즉시 완료 (가장 간단) | 중간 수준 (1 GPU 당 약 1~3시간 소반) | 매우 빠름 (Hessian 연산이 없어 수십 분 내 완료) |
| **서빙 엔진 이식성** | 보편적이나 미가속 | 보통 수준 | 극도로 우수함 (vLLM, TensorRT-LLM의 핵심 탑재 표준) |

> 요약: Naive 4-bit는 간단 검증에, GPTQ는 GPU 자원 활용 오차 누적 분산에, AWQ는 활성값 아웃라이어를 선별 격리해 내는 고정밀 상용 추론에 특화됨.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 활성값 프로파일러 | 대표 입력 텍스트를 흘려, 유난히 큰 값을 뿜어내는 활성값 채널 인덱스를 감지하는 모듈임 |
| 중요 가중치 추출기 | 감지된 활성값 인덱스와 맞물린 $1\%$의 핵심 가중치 행렬을 추출하는 판독기임 |
| 스케일 매핑 엔진 | 중요 채널 가중치에 큰 스케일 값을 곱하여 양자화 범위 밖으로 튕겨 나가는 현상을 방지하는 계산부임 |
| $vLLM$ AWQ 커널 | 런타임 상에서 혼합 비트($4$-bit 가중치 + $FP16$ 스케일)를 즉시 로딩해 All-Reduce를 뚫는 실행 커널임 |

```text
[ AWQ (Salient Weights 보호) 아키텍처 ]
Input Data ---> [Activation Profiling] ---> Detect Outlier Channels (Top 1%)
                                                        │
[Quantized Weight (4-bit)] <--- [Keep FP16 Scale] <--- Salient Weights
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 대표 코퍼스 | --> | 활성값 관찰  | --> | 중요 채널   | --> | 4비트+FP16  |
| 주입 및 구동|     | 아웃라이어픽 |     | 스케일링보호|     | 압축저장/배포|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **프로파일링 실행** — 캘리브레이션 텍스트 데이터를 모델에 주입하여, 출력 임베딩 활성값의 텐서 평균 크기를 채널별 기록함
2. **중요 채널 낙점** — 활성값 크기 수치가 타 채널 대비 비정상적으로 치솟는 아웃라이어 인덱스를 확인하고 Salient Weight로 낙점함
3. **가변 스케일 조정** — 해당 핵심 채널 가중치에 $S$ 계수를 적용해 양자화 정수화 과정 시의 절사 에러 오차를 원천 무효화함
4. **런타임 컴파일** — 가중치는 4비트, 중요 스케일은 FP16으로 묶인 최적의 바이너리 아티팩트를 vLLM 엔진에 탑재하고 서빙을 개시함

## Ⅵ. 실무 적용 및 유의점

1. AWQ는 대표 캘리브레이션 데이터셋의 입출력 활성값 통계에 지극히 의존하므로, 사내 표준 셋의 텍스트 말뭉치 커버리지가 부족하면 엄뚱한 가중치를 중요 채널로 짚어 지능이 망가지므로, 반드시 '실제 서비스 인입 데이터(Production Drift)' 커버리지를 $95\%$ 이상 포함해 보정 데이터셋을 수립해야 함
2. 기기 내에서의 전처리 오버헤드와 정수 커널의 컴파일 에러 발생 시, 오히려 역양자화 형변환 병목으로 성능이 더 느려질 수 있으므로, 반드시 '하드웨어 프로파일러'를 켜고 실제 응답 지연 시간($Latency$) 단축 여부와 초당 토큰 처리량($Tokens/Sec$) 향상 폭을 계측해야 함

## Ⅶ. 결론

- AWQ는 4비트 초압축의 인프라적 매력과 거대 지능의 무손실 품질 방어선을 활성값 흐름 추적으로 완전 수렴해 낸 현대 AI 서빙의 마일스톤이며, 설계자는 캘리브레이션 셋의 입력 대표성 획득과 런타임 엔진의 고유 양자화 커널 결합 상태를 면밀히 감사해 무결점 초경량 플랫폼을 배포해야 함
