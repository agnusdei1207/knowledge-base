## 미리 알고가기

- 전문가 혼합 ($MoE$, Mixture of Experts): 심층 신경망의 FFN(Feed-Forward Network) 계층을 여러 개의 독립적인 전문가($Expert$) 서브 네트워크로 쪼개고, 입력마다 적합한 전문가만 골라 활성화하는 희소 조건부 계산 아키텍처임
- 활성 파라미터 ($Active$ $Parameters$): 모델의 총 파라미터(예: $141B$) 중, 입력된 토큰 $1$개를 연산할 때 실제 수식 연산에 투입되는 물리 파라미터(예: $24B$)의 수량임
- 죽은 전문가 ($Dead$ $Expert$): 라우터의 부적절한 선택 분배나 학습 도중의 가중치 수렴 불능으로 인해, 훈련이 전혀 진행되지 않고 버려진 무용지물 전문가 블록임
- 토큰 드롭 ($Token$ $Drop$): 특정 전문가 블록에 가용한 최대 적재 용량 임계치(Capacity Limit) 이상의 토큰들이 몰릴 경우, 큐 공간 부족으로 연산되지 못하고 유실 배제되는 현상임

## Ⅰ. 개요

- **정의/개념**: Mixture of Experts(MoE)는 트랜스포머 레이어 내의 피드포워드 신경망을 복수의 전문가(Expert) 서브 네트워크로 병렬 치환하고, 소프트맥스 기반 게이팅 게이트인 라우터(Router)를 연동하여 매 토큰 입력마다 가장 정합성이 높은 소수의 전문가(Top-k)만 선택 동적 기동시키는 초거대 희소 신경망 아키텍처임
- **배경/필요성**: 정통 $Dense$ 모델은 매개변수를 키우면 지능은 오르나 가동 연산 단가(FLOPs)와 전력 및 응답 지연이 선형 비례로 수용 불가능하게 폭증하여, 총 지식 용량(Capacity)은 조 단위로 확장하되 $1$회 연산당 실 소비 단가는 통제하고자 탄생함

## Ⅱ. 특징

- 총 파라미터 용량 대비 실제 연산에 쓰이는 활성 파라미터(Active Parameters)가 수분의 일에 불과해, 단일 $Dense$ 모델 대비 압도적인 추론 비용 가성비를 실현함
- 학습 과정에서 자연스럽게 각 전문가 블록이 특정 문법 패턴, 번역, 논리 코딩 등 각자의 도메인 전문 영역으로 분산 심층 학습되는 현상이 나타남
- 다수 장비에 전문가를 고르게 분배하므로 GPU 노드 간의 빈번한 대규모 $All-to-All$ 통신을 요구하여, 고속 통신 하이퍼버스(NVLink 등)가 필수 요구됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 밀집 피드포워드 (Dense FFN) | Top-1 전문가 혼합 (Top-1 MoE) | Top-2 전문가 혼합 (Top-2 MoE) |
|:---|:---|:---|:---|
| **활성 전문가 수** | 전부 (1개의 거대 고정 FFN) | $8$개 중 $1$개만 선별 기동 | $8$개 중 $2$개만 선별 기동 |
| **추론 연산 단가** | 매우 높음 | 가장 낮음 | 중간 (Top-1 대비 지능은 더 정교함) |
| **가중 결합 계산** | 불필요함 | 불필요함 | 필수 (두 전문가의 결과 값을 비중 확률로 가중 합산) |
| **토큰 유실 리스크** | 없음 (전부 통과) | 존재함 (단일 전문가에 토큰 집중 시) | 비교적 완화됨 (분산 경로 확보) |

> 요약: Dense FFN은 전산 자원 소모가 큰 단일 전술이고, Top-1 MoE는 극단적 가성비를 추구하며, Top-2 MoE는 표현의 안전성을 높이기 위해 복수 전문가를 조율하는 상영상용 표준 아키텍처임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 라우터 네트워크 | 인입된 토큰 임베딩을 선형 사상하여, 적합한 전문가 번호의 확률 분포를 내놓는 게이트 넷임 |
| 전문가 블록 | 동일 형상의 개별 FFN 레이어들로, 다수 카드로 분산 배치되는 분산 전문가 병렬화 대상임 |
| 공유 어텐션 레이어 | 전문가 분기가 일어나기 전, 문장의 전반 문맥(Attention)을 취합 및 공통 보관하는 레이어임 |
| 부하 조율기 | 특정 전문가 쏠림을 감시하고, 강제로 무작위 노이즈를 더해 토큰 드롭을 방지하는 조율 데몬임 |

```text
[ Mixture of Experts (MoE) 레이어 토폴로지 ]
                           Input Token
                                │
                        [ Self-Attention ]
                           /          \
          [ Router Network ]          [ Active Expert 1 & 4 ] (Top-2 Activated)
                           \          /
                        [ Weighted Sum ]
                                │
                           Output Token
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 공유 레이어 | --> | 라우터 게이트| --> | Top-k 전문가| --> | 각 출력 가중|
| 문맥 어텐션 |     | 확률 분포도출|     | 동적 선점연산|     | 병합 및 방출|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **문맥 정리** — 사용자가 보낸 토큰 정보가 자기 어텐션(Self-Attention) 계층을 지나면서 문장 내 의미 관계도가 공통 정리됨
2. **라우터 평가** — 정제된 토큰 벡터를 라우터에 통과시켜, $N$개 전문가 후보에 대한 소프트맥스 결합 스코어($Score$) 벡터를 출력함
3. **조건부 계산** — 상위 $2$개 최고 득점 전문가($Top-2$ $Experts$) 가상 포트를 켜고, 해당 GPU 카드 메모리로 토큰 연산을 비동기 할당함
4. **합산 릴리즈** — 처리 완료된 두 전문가의 결과 텐서에 라우터 가중치를 각각 곱해 결합($Weighted$ $Sum$)한 후 다음 계층으로 릴리즈함

## Ⅵ. 실무 적용 및 유의점

1. 특정 특정 전문가에게만 쿼리가 편향 전송되어 다른 전문가가 훈련되지 않는 '죽은 전문가($Dead$ $Expert$)' 현상이 빈발하면 지능 밀도가 급락하므로, 반드시 손실 함수에 '부하 균등화 로스($Auxiliary$ $Loss$)'를 합산하고 전문가 스큐 편차를 실시간 모니터링해야 함
2. 분산 서버 서빙 시 전문가 분할을 위해 사용되는 GPU 간 $All-to-All$ 노드 네트워크 대역폭 포화로 연산보다 통신 대기 시간이 길어질 수 있으므로, 동일 랙 내의 NVLink 토폴로지 구조를 밀착 확인하고, 통신 대 연산 비율($Communication$ $Ratio$)을 감사하여 병목을 절감해야 함

## Ⅶ. 결론

- Mixture of Experts는 신경망의 기하학적 파라미터 용량과 실질 운용 연산 단가를 영리하게 디커플링하여 초거대 AI 성능을 대중화시킨 지능형 아키텍처의 혁신이며, 설계자는 통신 스큐로 인한 dead expert 예방 장치와 분산 노드 간의 All-to-All 통신 포화 감사를 반드시 상시 수행해야 함
