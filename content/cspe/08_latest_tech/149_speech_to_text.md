# 📖 【암기용】 개념 완전 이해

> 목적: Speech-to-Text를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: 사람의 음성 신호를 텍스트로 변환하는 음성 인식 기술
- **왜 필요한가**: 상담, 회의, 콜센터, 현장 작업 음성을 검색·분석·요약하려면 텍스트화가 필요함.
- **핵심 직관**: 녹음 파일을 듣고 사람이 받아쓰기하는 작업을 AI가 수행하는 것임.

## 깊이 이해
- **배경·문제의식**: 음성 데이터는 검색과 분석이 어렵고, 수동 전사 비용이 높다. STT는 음성 업무 데이터를 LLM·검색·분석 파이프라인에 연결함.
- **작동 원리**: 오디오를 프레임 단위 특징으로 변환하고, acoustic encoder와 language decoder가 음소·단어 시퀀스를 예측하며, timestamp와 speaker diarization을 함께 생성할 수 있음.
- **비유**: 회의 녹음에서 누가 언제 어떤 말을 했는지 속기록을 자동으로 만드는 기술임.
- **구체 예시**: 콜센터 통화 1만 시간을 STT로 전사하고, WER 10% 이하 모델을 기준으로 민원 분류와 상담 요약에 활용.
- **흔한 오해·주의점**: STT는 조용한 환경에서는 높게 동작해도 방언, 잡음, 전문용어, 겹침 발화에서 오류가 증가함.

## 연결 개념
- Whisper — 다국어 음성 인식 모델
- Speaker Diarization — 화자 분리 기술
- Text-to-Speech — 텍스트를 음성으로 합성하는 반대 방향 기술

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: STT는 음성 신호를 단어·문장 텍스트와 timestamp로 변환하는 음성 AI 기술임.
> 2. **가치**: 콜센터·회의·현장 음성을 검색·요약·분석 가능한 데이터로 전환함.
> 3. **판단 포인트**: WER, 지연, 화자 분리, 개인정보 마스킹, 도메인 용어 인식률을 함께 관리해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 인식 파이프라인 이해 확인 | VAD-음향 인코딩-디코딩-후처리 흐름, WER·DER 지표 구분 | 전사 오류(WER)와 화자 분리 오류(DER) 혼동 |
| 실환경 오류 요인 인식 확인 | 잡음·방언·전문용어·겹침 발화의 오류 증가 | 정숙 환경 성능을 실환경 성능으로 단정 |
| 보안·활용 설계 판단 확인 | PII 마스킹 후 저장, LLM 요약·검색 연계 | 음성·전사 데이터 개인정보 처리 절차 누락 |

> 요약: 이 문제는 받아쓰기 기능 설명이 아니라 실환경 오류 관리와 개인정보 통제를 포함한 음성 데이터화 설계를 묻는다.

## Ⅰ. 개요 및 필요성

- 개요: 음성을 텍스트로 변환하는 기술
- 배경: 상담, 회의, 현장 음성은 원형 그대로 검색, 통계 분석, LLM 요약에 투입하기 어렵다.
- 필요성: ASR 모델로 WER, diarization error rate, latency 기준의 전사 품질을 관리해 검색과 품질 모니터링에 연결한다.

## Ⅱ. 구조 및 구성요소

```text
Audio -> Preprocess -> Acoustic Encoder -> Decoder/LM
  -> Transcript + Timestamp + Speaker Label
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Audio Preprocess | 잡음 제거·VAD·분할 | 16kHz, noise reduction |
| Acoustic Encoder | 음향 특징 인코딩 | Conformer, Transformer |
| Decoder/LM | 단어 시퀀스 생성 | CTC, seq2seq |
| Postprocess | 문장부호·화자·PII 처리 | diarization, masking |

> 요약: STT는 음성 전처리, 음향 인코딩, 텍스트 디코딩, 후처리로 전사 결과를 생성함.

## Ⅲ. 동작원리 및 흐름도

```text
음성 입력 -> VAD/잡음 제거 -> 특징 추출
  -> 음향 모델 인코딩 -> 텍스트 디코딩 -> 후처리/마스킹
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 음성 구간 검출·잡음 제거 | SNR 개선 5dB 이상 |
| 2 | acoustic encoder로 특징 표현 | streaming latency <500ms |
| 3 | decoder가 텍스트 전사 | WER ≤10% |
| 4 | 화자 분리·PII 마스킹 | diarization DER <15%, PII 탐지 ≥95% |

> 요약: STT는 음성 구간을 정제한 뒤 모델이 텍스트를 생성하고 화자·개인정보 후처리를 수행함.

## Ⅳ. 특징

| 구분 | 수동 전사 | STT | 판단 포인트 |
|:---|:---|:---|:---|
| 처리 속도 | 녹음 시간의 3~5배 | 실시간~수배속 | 대량 처리에 적합 |
| 비용 | 인력 비용 | 모델·GPU/API 비용 | 통화량 기준 산정 |
| 품질 변수 | 전사자 편차 | 잡음·방언·전문용어 | 도메인 튜닝 필요 |
| 보안 | 계약·통제 필요 | 음성·전사 PII 처리 | 마스킹·암호화 필수 |

> 요약: STT는 대량 음성 데이터를 빠르게 텍스트화하지만, 잡음·전문용어·개인정보 처리를 운영 기준으로 관리해야 함.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 온디바이스 STT | 클라우드 STT | 선택 기준 |
|:---|:---|:---|:---|
| 처리 위치·보안 | 단말 내 처리, 음성 외부 전송 차단 | 서버 전송·처리, 전송 구간 암호화 필요 | 음성 데이터 민감도·규제 요구 |
| 모델 규모·정확도 | 경량 모델, 잡음·도메인 정확도 제약 | 대형 모델·최신 업데이트 적용 용이 | WER 목표와 도메인 난이도 |
| 지연·가용성 | 네트워크 무관 동작, 오프라인 가능 | 네트워크 지연·장애 영향 존재 | 현장·오프라인 사용 여부 |

> 요약: 민감 음성과 오프라인 현장은 온디바이스, 고정밀 대량 전사는 클라우드 STT를 선택함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 도메인 용어 오인식 | 학습 데이터 내 전문용어 부족 | 커스텀 어휘 등록, 도메인 미세조정 | 도메인 용어 인식률 |
| 개인정보 유출 | 전사 텍스트에 PII 포함 저장 | PII 마스킹 후 저장, 로그 암호화 | PII 탐지율 ≥95% |
| 겹침 발화 오류 | 다중 화자 동시 발화 | 화자 분리, 채널 분리 녹음 | DER <15% |

> 요약: 핵심 위험은 전문용어 오인식과 PII 노출이며, 도메인 튜닝과 마스킹 절차로 통제함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 콜센터 분석: 실시간 STT, 화자 분리, 상담 요약 LLM을 결합해 통화 후처리 시간을 10분->2분으로 단축
2. 회의록 자동화: STT+diarization+요약으로 발언자별 action item 추출, WER 10% 이하 검증
3. 보안 통제: 주민번호·전화번호·계좌번호 PII 마스킹 후 저장, 전사 로그 AES-256 암호화

**결론 (2줄):**
- 기술사 판단: 대량 음성 업무는 STT를 데이터화 계층으로 두고, 고위험 전사는 사람 검수 병행
- 향후 방향: streaming STT와 LLM 요약·검색이 결합되어 실시간 상담 보조로 확장
