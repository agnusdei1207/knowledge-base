## 미리 알고가기

- STT는 음성 파형을 텍스트로 변환하는 자동 음성인식 기술임
- 현재 주류는 end-to-end encoder-decoder 또는 transducer 기반 구조임
- 화자 분리와 잡음 제거와 도메인 사전이 실무 품질을 크게 좌우함

## Ⅰ. 개요

- **정의/개념**: STT는 연속적인 음성 신호를 주파수 특징으로 변환한 뒤 음향 패턴과 언어 문맥을 함께 해석해, 이를 기계가 처리 가능한 텍스트 시퀀스로 변환하는 자동 음성인식 기술임
- **배경/필요성**: 통화 녹취와 회의 음성과 방송 콘텐츠는 그대로는 검색과 요약과 분석이 어려우므로, 음성을 텍스트 자산으로 구조화하는 기술이 필요함

## Ⅱ. 특징

- 음향 특성과 언어 문맥을 함께 해석해야 정확도가 높아짐
- 실시간 서비스는 latency가 중요하고 오프라인 전사는 accuracy가 중요함
- 잡음과 억양과 도메인 용어에 따라 성능 편차가 크게 발생함
- diarization과 punctuation과 NER 후처리가 붙어야 실무 활용도가 높아짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 전통 HMM 기반 | E2E STT | Streaming Transducer |
|:---|:---|:---|:---|
| 구조 복잡도 | 높음 | 중간 | 높음 |
| 정확도 잠재력 | 중간 | 높음 | 높음 |
| 실시간성 | 낮음 | 중간 | 높음 |
| 운영 유연성 | 낮음 | 높음 | 높음 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Audio Front-end | 파형을 mel spectrogram 같은 특징으로 변환하고 잡음을 줄여 인식 입력을 정제함 |
| Acoustic Encoder | 시간축 음향 패턴을 임베딩으로 변환해 발음과 억양의 핵심 단서를 추출함 |
| Decoder, Language Model | 음향 특징을 문자나 토큰 시퀀스로 해석하면서 언어 문맥으로 오인식을 줄임 |
| Post-processing Layer | 화자 분리와 구두점 복원과 도메인 사전 보정을 수행해 실사용 품질을 높임 |

```text
+-------------------+      +-------------------+      +-------------------+
| Audio Front-end   | ---> | Acoustic Encoder  | ---> | Decoder / LM      |
+-------------------+      +-------------------+      +-------------------+
                                                           |
                                                           v
                                                   +-------------------+
                                                   | Post-processing   |
                                                   +-------------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 음성 입력 수집   | --> | 특징 추출/정제  | --> | 토큰 디코딩 수행 | --> | 텍스트 후처리   |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **음성 입력 수집**: 마이크나 녹취 파일에서 음성을 받음
2. **특징 추출 및 정제**: 음향 특징을 만들고 잡음 구간을 줄임
3. **토큰 디코딩 수행**: 음향과 언어 문맥을 결합해 문자 시퀀스를 생성함
4. **텍스트 후처리**: 화자와 구두점과 용어를 정리해 최종 전사본을 만듦

## Ⅵ. 문제점 및 해결 방안

1. 문제: 소음과 방언과 전문 용어가 겹치면 범용 모델이 핵심 단어를 자주 틀려 실무 전사 신뢰도가 낮아질 수 있음
   - 해결방안: domain biasing과 noise-robust tuning을 적용하고 WER와 terminology accuracy로 검증함
2. 문제: 화자 중첩이 많은 회의나 콜센터 녹취는 발화 주체가 섞여 후속 분석 정확도가 크게 떨어질 수 있음
   - 해결방안: diarization과 VAD를 결합하고 diarization error rate와 summary quality로 검증함
3. 문제: 실시간 상담 환경에서는 정확도를 높이기 위해 긴 문맥을 기다리면 응답 지연이 커질 수 있음
   - 해결방안: streaming transducer와 partial hypothesis 정책을 적용하고 RTF와 first token latency로 검증함

## Ⅶ. 적용 사례

- AICC가 고객 통화를 실시간 전사해 상담 가이드를 제시하도록 STT를 적용하며 확인 지표는 WER와 first token latency임
- 회의록 자동화가 화자별 발언과 액션 아이템을 정리하도록 STT를 운영하며 확인 지표는 diarization error rate와 summarization quality임
- 방송 자막 생성이 라이브 자막을 제공하도록 STT를 활용하며 확인 지표는 caption latency와 subtitle accuracy임

## Ⅷ. 결론

STT는 음성 데이터를 검색 가능한 텍스트 자산으로 바꾸는 첫 관문이므로, 도메인 적응과 화자 처리와 실시간성 균형이 실무 품질을 결정함.
