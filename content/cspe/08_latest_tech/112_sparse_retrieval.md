# 📖 【암기용】 개념 완전 이해

> 목적: 희소 검색을 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **정의**: 문서를 어휘(토큰) 단위의 고차원 희소 벡터로 표현하고 역색인으로 검색하는 기법
- **왜 필요한가**: 정확한 키워드·고유명사·코드 검색에서 Dense 검색보다 정밀도가 높고, 기존 역색인 인프라를 재활용할 수 있다.
- **핵심 직관**: 단어장 크기(3만~10만)만큼 칸이 있는 벡터에서 해당 단어 칸만 값이 있고 나머지는 0 — 그래서 "희소(Sparse)".

## 깊이 이해
- **배경·문제의식**: Dense Retrieval은 의미를 잡지만, 정확한 고유명사("GPT-4o")나 코드 토큰은 임베딩 공간에서 구별이 어렵다. 또 대규모 코퍼스에서 역색인이 이미 구축되어 있으면 Dense로 전면 교체하는 비용이 크다.
- **작동 원리**: ① 문서를 토큰화(BPE/WordPiece) → ② 각 토큰에 가중치 할당(TF-IDF, BM25, 또는 학습 기반 SPLADE) → ③ 역색인(Inverted Index)에 저장 → ④ 질의 토큰과 문서 토큰의 교집합에 가중치를 곱해 점수 계산.
- **비유**: 책 뒤의 색인(Index) 페이지와 같다. "TCP"를 찾으면 색인에서 TCP가 적힌 페이지 번호를 바로 꺼낸다. 책 전체를 읽지 않는다.
- **구체 예시**: SPLADE v2는 BEIR 벤치마크에서 nDCG@10 = 0.497로, BM25(0.428) 대비 16% 향상. 동시에 역색인 호환으로 Elasticsearch에 바로 배포 가능.
- **흔한 오해·주의점**: "희소 검색 = BM25"가 아니다. BM25는 통계 기반이고, SPLADE·DeepImpact 등은 학습 기반 희소 검색으로 의미 확장도 수행한다.

## 연결 개념
- BM25 — 전통적 희소 검색의 대표 가중치 함수
- SPLADE — 학습 기반 희소 검색 모델(MLM 기반 토큰 확장)
- Hybrid Search — 희소(정확 매칭) + 밀집(의미 매칭) 결합

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 어휘 기반 고차원 희소 벡터와 역색인으로 문서를 검색하는 기법
> 2. **가치**: 정확 키워드 매칭 정밀도와 역색인 인프라 호환성을 동시에 확보
> 3. **판단 포인트**: 통계 기반(BM25)은 튜닝 없이 즉시 배포, 학습 기반(SPLADE)은 nDCG@10 16%↑ 대신 학습 비용 발생

---

## Ⅰ. 개요 및 필요성

어휘 단위 희소 벡터로 문서를 표현·검색하는 기법. Dense Retrieval은 의미를 잡지만 고유명사·코드 토큰 구별이 어렵고, 기존 역색인 인프라 교체 비용이 크다. 희소 검색은 정확 매칭 정밀도와 역색인 호환성을 동시에 제공하며, 학습 기반 모델(SPLADE)은 의미 확장까지 수행한다.

---

## Ⅱ. 구조 및 구성요소

```text
┌──────────┐   ┌──────────────┐   ┌──────────┐   ┌──────────┐
│ Tokenizer│──▶│ Weight Assign│──▶│ Inverted │──▶│ Scoring  │
│(BPE/WP)  │   │(BM25/SPLADE) │   │ Index    │   │(dot/BM25)│
└──────────┘   └──────────────┘   └──────────┘   └──────────┘
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Tokenizer | 문서·질의를 토큰 단위로 분리 | BPE(30K), WordPiece(30K vocab) |
| Weight Assigner | 토큰별 중요도 가중치 산출 | BM25(통계), SPLADE(MLM logit) |
| Inverted Index | 토큰→문서 매핑 저장 | Elasticsearch, Lucene 호환 |
| Scorer | 질의-문서 토큰 교집합 가중합 계산 | BM25 스코어 또는 내적 |

> 요약: 토큰화→가중치→역색인→스코어링 4단계로, 기존 Elasticsearch 인프라에 바로 배포할 수 있다.

---

## Ⅲ. 동작원리 및 흐름도

```text
질의 입력 → 토큰화 → 가중치 산출 → 역색인 조회 → 교집합 스코어링 → Top-K 반환
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 질의 토큰화 + 가중치 산출 (BM25: TF-IDF, SPLADE: MLM logit) | 질의 처리 < 2ms |
| 2 | 역색인에서 각 토큰의 포스팅 리스트 조회 | 포스팅 리스트 I/O ≤ 5ms |
| 3 | 교집합 토큰의 가중치 곱 합산(BM25 스코어 또는 내적) | nDCG@10 ≥ 0.42 (BEIR) |
| 4 | Top-K 정렬 반환 | E2E 지연 < 50ms (p95) |

> 요약: 역색인 기반으로 질의 토큰이 포함된 문서만 빠르게 필터링하여, 10억 건 코퍼스에서도 50ms 이내 응답한다.

---

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 장점 | 정확 키워드 매칭 Precision@1 0.85+, 역색인 인프라 재활용 | 고유명사·코드 검색 시 우위 |
| 한계 | 어휘 불일치(동의어·다의어) 처리 불가(통계 기반), 학습 기반은 GPU 학습 비용 | 동의어 많은 도메인은 Dense 보완 필요 |
| Dense 대비 | 색인 용량 1/10 (역색인 vs 768D 벡터), 지연 1/4 (50ms vs 200ms) | 비용·속도 우선 시 Sparse, 의미 우선 시 Dense |

> 요약: 속도·비용·정확 매칭은 Sparse가 우위이고, 의미 이해는 Dense가 우위이므로 Hybrid가 최적 조합이다.

---

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. SPLADE v2 + Elasticsearch: MLM 기반 토큰 확장으로 nDCG@10 0.497 달성, 역색인 호환으로 기존 ES 클러스터에 즉시 배포
2. Hybrid 파이프라인: BM25(Sparse) + BGE(Dense) 점수를 RRF 결합, 단독 대비 nDCG@10 8~15%↑
3. 도메인 특화: 법률·의료 코퍼스에서 BM25 + 도메인 사전(MeSH, 법률 시소러스) 확장으로 Recall@100 40%→62%

**결론 (2줄):**
- 기술사 판단: 역색인 인프라가 이미 있으면 SPLADE로 업그레이드(nDCG 16%↑), 없으면 BM25 + Dense Hybrid 신규 구축
- 향후 방향: 학습 기반 희소 모델(SPLADE++, LexMAE)이 통계 기반 BM25를 대체하며, Dense와의 경계가 점차 흐려지는 추세
