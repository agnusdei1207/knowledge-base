# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: 문서를 수만~수십만 개의 단어 집합(Vocabulary)으로 이루어진 벡터로 표현하고, 문서에 존재하는 단어에만 가중치 점수를 부여하여 검색하는 방식. "희소(Sparse)"라는 말은 대부분의 칸(단어)이 '0'으로 비어 있다는 뜻.
- **필요성**: AI 임베딩 모델을 쓰는 밀집 검색(Dense Search)은 뉘앙스는 잘 알지만 "TX-9980" 같은 고유 코드는 자꾸 뭉개버림. 반면 희소 검색은 콕 집어 그 글자가 있는 문서를 칼같이 찾아냄.
- **핵심 직관**: 도서관 맨 뒤에 있는 '색인(Index) 페이지'. "TCP/IP"가 적힌 페이지 번호만 찾아가면 됨. 전체 단어장이 10만 개라면, 특정 문서 A는 'TCP', '통신', '프로토콜' 등 몇 개 단어 칸에만 숫자가 있고 나머지 99,997칸은 다 0인 벡터임.

## 깊이 이해
- **배경**: 구글 시대 이전부터 쓰이던 전통적인 검색 엔진(Elasticsearch, Lucene)의 근간(역색인 기반). 최근 딥러닝(Dense)에 밀려 구식 취급을 받았으나, 엔터프라이즈 환경에서 "정확한 단어 매칭"의 중요성이 재조명되면서 딥러닝을 결합한 하이브리드로 화려하게 부활함.
- **작동 원리 (역색인, Inverted Index)**:
  1. (토큰화): "사과는 맛있다" $\rightarrow$ [사과, 맛있다]
  2. (가중치 계산): TF-IDF나 BM25 공식을 써서 '이 단어가 이 문서에서 얼마나 희귀하고 중요한지' 점수(Weight)를 매김.
  3. (역색인 저장): 단어 '사과'를 검색하면 [문서1, 문서5]가 나오도록 거꾸로 정리해 둠.
  4. (검색): 사용자가 검색어를 입력하면, 역색인을 뒤져 교집합 단어가 많은 문서를 빠르게 반환.
- **구체 예시**: SPLADE(학습형 희소 검색). 예전 통계 방식은 "사과"를 검색하면 "Apple"을 못 찾았음. 근데 SPLADE는 딥러닝이 문서를 읽고, 문서에 "사과"만 적혀 있어도 벡터 칸의 "Apple", "아이폰" 칸에도 미세한 가중치를 부여해 둠(어휘 확장). 속도는 옛날처럼 빠르면서 의미 검색 효과를 냄.
- **흔한 오해/주의점**: "희소(Sparse) = BM25"로만 생각하기 쉬우나, 최근엔 딥러닝 모델이 가중치를 계산해주는 뉴럴 희소 검색(Neural Sparse Retrieval)으로 진화함. 임베딩(Dense) 방식과 대척점에 있지만 상호보완적임.

## 연결 개념
- **BM25**: 가장 널리 쓰이는 대표적인 통계 기반 희소 검색 알고리즘.
- **Dense Retrieval (밀집 검색)**: 희소 검색의 라이벌. 벡터 칸이 빈 곳 없이 수백 개의 숫자로 꽉 차 있음(의미 공간).
- **Inverted Index (역색인)**: 희소 검색이 빛의 속도로 검색할 수 있게 해주는 핵심 데이터베이스 자료구조.

# 📝 【답안용】 시험 답안 템플릿
## 핵심 인사이트 (3줄 요약)
- **본질**: 전체 어휘 사전(Vocabulary Size, 통상 3~10만 개) 차원의 고차원 벡터에서, 문서 내에 실제 등장하는 소수의 토큰 위치에만 가중치(TF-IDF, BM25 등)를 할당하고 나머지는 0으로 두는 전통적 검색 및 최신 Neural 검색 아키텍처.
- **가치**: Exact Keyword Match(정확한 키워드 매칭)에 압도적 강점을 지녀 고유명사, 코드 번호, 약어 등 OOV(Out-of-Vocabulary) 질의 처리 시 Dense 모델의 한계를 완벽히 보완함.
- **판단 포인트**: 기존 인프라(Elasticsearch 등)의 역색인 구조를 그대로 재활용할 수 있어 도입 비용/지연 시간(Latency)이 매우 낮으며, 최근에는 SPLADE 등 어휘 확장(Vocabulary Expansion) 능력을 갖춘 학습 모델로 진화 중.

## Ⅰ. 개요 및 필요성
- **정의**: 문서를 수만 차원의 단어 주머니(Bag of Words) 기반 희소 벡터(Sparse Vector)로 표현하고, 질의와 문서 간의 어휘 교집합(Lexical Overlap)을 바탕으로 관련성을 채점(Scoring)하는 정보 검색 기법.
- **배경**: 딥러닝 임베딩 기반의 밀집 검색(Dense)은 문맥 파악에 우수하나 연산 비용이 높고 특정 특수기호나 품번을 임베딩 공간에서 뭉뚱그려(Loss of detail) 정확도를 떨어뜨림.
- **필요성**: 엔터프라이즈 RAG 환경에서 도메인 특화 용어의 검색 유실(False Negative)을 방지하고, 밀리초 단위의 극단적인 검색 속도를 보장하기 위함.

## Ⅱ. 희소 검색의 주요 알고리즘 발전 계보
| 구분 | 통계 기반 (Traditional) | 학습 기반 (Neural Sparse) |
|:---:|:---|:---|
| **대표 알고리즘**| **TF-IDF, BM25** | **SPLADE, DeepImpact** |
| **가중치 부여 방식**| 단어의 출현 빈도와 문서 길이 기반 수학적 통계 | Masked Language Model (BERT 등)을 활용한 토큰 예측 확률 |
| **어휘 확장 (Expansion)**| 불가 (동의어 매칭 실패) | **가능** (문서에 없는 "Apple" 단어에도 문맥상 가중치 부여) |
| **인프라 호환성** | 기존 Elasticsearch/Lucene 100% 호환 | 역색인 인프라 호환 (저장 공간 최적화 용이) |

## Ⅲ. 메커니즘 동작 흐름도 (Inverted Index 중심)
```text
[ Document Ingestion (색인) ]
  문서 -> Tokenizer (형태소 분리) -> Weight Assigner (가중치 산출)
                                        |
  +-- [ Inverted Index (역색인 DB) ] ---+
  |   "데이터": [Doc 1 (0.8), Doc 3 (0.5)]
  |   "베이스": [Doc 1 (0.9), Doc 2 (0.3)]
  +-------------------------------------+
        ^
        | (질의 토큰 추출 및 교집합 스코어링)
        |
[ User Query ] -> "데이터 베이스"
```

## Ⅳ. 희소 검색(Sparse) vs 밀집 검색(Dense) 핵심 비교
| 비교 지표 | Sparse Retrieval (희소) | Dense Retrieval (밀집) |
|:---:|:---|:---|
| **차원 수** | $\sim 100,000$ 차원 (대부분 값=0) | $768 \sim 1536$ 차원 (모든 값이 실수) |
| **인프라/인덱싱** | Inverted Index (역색인) | HNSW, IVF-PQ (ANN Vector Search) |
| **검색 복잡도** | $O(N)$ 교집합 연산 (매우 빠름) | $O(N \log N)$ 벡터 유사도 연산 (느림) |
| **강점** | 고유명사, Keyword Exact Match | 긴 문장, 문맥(Context), 동의어 인지 |
| **약점** | 어휘 불일치(Vocabulary Mismatch) | 세부 디테일(특수기호, 코드) 손실 위험 |

## Ⅴ. 한계점 및 고도화 전략
- **리스크 1: 어휘 불일치(Vocabulary Mismatch)**:
  - "승용차"로 검색 시 "자동차" 문서가 검색되지 않는 구조적 한계. 통계 기반 희소 검색의 가장 큰 병목.
  - **대응 방안**: 도메인 특화 동의어 사전(Synonym Dictionary)을 수동 유지보수하거나, 밀집 검색(Dense)과 결합하는 **하이브리드(Hybrid Search)** 아키텍처 적용.
- **리스크 2: Neural Sparse 도입 시 GPU 인덱싱 오버헤드**:
  - SPLADE 등 최신 희소 모델은 검색(Inference)은 빠르지만, 최초 문서를 색인(Indexing)할 때 딥러닝 모델 연산이 필요해 GPU 비용이 듦.
  - **대응 방안**: 색인 시에만 배치(Batch)로 GPU 인스턴스를 스포닝(Spawning)하고, 런타임 검색은 CPU 기반의 Elasticsearch로 서빙하는 이원화 아키텍처 설계.

## Ⅵ. 실무 적용 및 결론
- **판단 지표**: Precision@K (정확히 매칭된 문서의 상위 랭킹 비율), Indexing Size (스토리지 효율성), Query Latency (응답 속도).
- **실무 설계**: A사의 B2B 소프트웨어 릴리스 노트 챗봇 구성. "v2.1.4 패치에서 발생한 ORA-12541 에러 조치법" 질의가 들어옴. Dense Retrieval은 의미망에서 에러 코드를 무시하고 일반적인 패치 문서를 가져와 환각 유발. 역색인 기반의 희소 검색(BM25)을 복원/병렬 적용하여 0.05초 만에 정확히 ORA-12541이 기록된 문서를 도출함으로써 RAG의 팩트 신뢰도를 확보함.
- **결론**: 희소 검색은 레거시 기술이 아니라 임베딩의 '추상화' 과정에서 잃어버리는 '디테일'을 잡아주는 최후의 보루이며, 최신 RAG 시스템에서도 Dense와 상호 보완하는 Hybrid 엔진의 한 축으로 필수적으로 채택되어야 함.

### 🔀 문제 유형별 목차 전환
- **Ⅱ·Ⅲ 강조 (개념/원리형)**: Inverted Index의 Posting List 구조 설계, TF-IDF의 수학적 한계와 이를 극복한 BM25의 Term Frequency Saturation 알고리즘 중심 서술.
- **Ⅴ·Ⅵ 강조 (실무/설계형)**: 기존 레거시 검색 엔진(Solr, ES) 인프라 재활용을 통한 마이그레이션(Cost-saving) 관점, Neural Sparse(SPLADE) 벤치마크 및 인덱스 압축률 비교 작성.
