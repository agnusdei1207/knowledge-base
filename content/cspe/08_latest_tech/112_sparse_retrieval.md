## 미리 알고가기

- sparse retrieval은 문서를 희소한 단어 특징 공간에서 표현해 역색인 기반으로 검색하는 방식임
- BM25가 대표 알고리즘이며 exact keyword match와 고유명사 검색에 강함
- 어휘가 다르면 의미가 같아도 찾기 어려운 lexical gap이 핵심 한계임

## Ⅰ. 개요

- **정의/개념**: 희소 검색은 질의와 문서를 단어 단위 특징으로 표현하고, 각 단어의 등장 여부와 빈도와 희귀성을 이용해 관련 문서를 찾는 역색인 중심 검색 방식임
- **배경/필요성**: 검색 시스템은 빠르고 설명 가능한 exact match가 필요하며, 특히 제품 코드와 약관 번호와 고유명사를 정확히 찾는 데 sparse 방식이 여전히 강력함

## Ⅱ. 특징

- 역색인을 사용해 매우 빠르고 안정적인 keyword matching을 제공함
- 고유명사, 에러 코드, 숫자, 조항 번호 같은 exact token 검색에 강함
- 동의어와 우회 표현과 자연어 의미 매칭에는 약함
- 해석 가능성과 운영 단순성이 높아 기본 검색 인프라로 널리 쓰임

## Ⅲ. 종류 및 비교

| 판단 기준 | Sparse Retrieval | Dense Retrieval | Hybrid Search |
|:---|:---|:---|:---|
| exact token match | 높음 | 낮음 | 높음 |
| semantic match | 낮음 | 높음 | 높음 |
| 설명 가능성 | 높음 | 낮음 | 중간 |
| 인프라 복잡도 | 낮음 | 중간 | 높음 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Tokenizer, Analyzer | 문서를 토큰 단위로 분해하고 불용어 처리와 정규화를 수행함 |
| Inverted Index | 각 토큰이 등장한 문서 목록을 저장해 빠른 후보 탐색을 가능하게 함 |
| Weighting Function | BM25 같은 가중치 함수가 토큰 중요도를 계산해 순위를 정함 |
| Query Parser | 검색 연산자와 필드 조건을 해석해 실제 검색 실행을 제어함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 토큰화/역색인 생성 | --> | 질의 토큰 분석   | --> | 역색인 후보 탐색 | --> | 가중치 기반 정렬 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **토큰화 및 역색인 생성**: 문서를 토큰으로 나누고 색인을 구성함
2. **질의 토큰 분석**: 질의를 같은 규칙으로 전처리함
3. **역색인 후보 탐색**: 공통 토큰이 있는 문서 후보를 빠르게 찾음
4. **가중치 기반 정렬**: 토큰 중요도로 최종 순위를 계산함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 질의와 문서의 표현이 다르면 의미가 같아도 검색 결과를 놓치는 lexical mismatch가 자주 발생할 수 있음
   - 해결방안: 동의어 사전과 hybrid search를 적용하고 recall@k와 semantic miss rate로 보완 효과를 검증함
2. 문제: 짧은 질의나 희귀 토큰이 없는 질의에서는 노이즈 문서가 상위에 오를 수 있음
   - 해결방안: field weighting과 query expansion을 적용하고 precision@k와 click satisfaction으로 정밀도를 검증함
3. 문제: 형태소 분석과 tokenizer 설정이 잘못되면 도메인 용어가 부정확하게 분해되어 검색 품질이 떨어질 수 있음
   - 해결방안: 도메인 analyzer를 커스터마이즈하고 tokenization error rate와 search quality로 분석 품질을 검증함

## Ⅶ. 적용 사례

- 에러 코드 검색이 exact token match로 빠르게 문서를 찾도록 희소 검색을 적용하며 확인 지표는 first-hit accuracy와 latency임
- 법률 조항 검색이 조항 번호와 용어 검색에 사용되도록 희소 검색을 활용하며 확인 지표는 precision@k와 user trust임
- 기업 검색 기본 레이어가 dense 검색과 함께 sparse 축을 제공하도록 희소 검색을 적용하며 확인 지표는 hybrid contribution rate와 retrieval recall임

## Ⅷ. 결론

희소 검색은 의미 이해는 약해도 exact match와 설명 가능성에서 여전히 강력하므로, 엔터프라이즈 검색과 RAG에서 dense 검색을 보완하는 기반 축으로 남아 있음.
