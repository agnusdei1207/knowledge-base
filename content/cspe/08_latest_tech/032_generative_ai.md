# 📖 【암기용】 개념 완전 이해

> 목적: 생성형 AI를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **정의**: 학습 데이터의 분포를 모델링하여 텍스트·이미지·코드·음성 등 새로운 콘텐츠를 생성하는 AI
- **왜 필요한가**: 기존 AI는 분류·예측(판별)에 집중했지만, 콘텐츠 초안 작성·디자인·코드 생성 등 창작 업무 자동화 수요가 폭증함.
- **핵심 직관**: "이 데이터와 비슷한 새 것을 만들어라" — 판별이 아니라 생성이 목적인 AI.

## 깊이 이해
- **배경·문제의식**: GAN(2014)이 이미지 생성을 입증했고, Transformer(2017)가 텍스트 생성을 혁신함. GPT-3(2020) 이후 텍스트, DALL·E(2021) 이후 이미지, Codex(2021) 이후 코드 생성이 실용 수준에 도달함.
- **작동 원리**: 모델 유형별로 다름. ① 자기회귀(LLM): 다음 토큰 확률 예측. ② 확산(Diffusion): 노이즈에서 점진적 복원. ③ GAN: 생성자-판별자 적대 학습. 공통적으로 대규모 데이터 분포를 학습한 뒤 샘플링으로 새 데이터를 생성함.
- **비유**: 수만 장의 그림을 본 화가가 "고흐 스타일 해바라기"를 새로 그리는 것. 기존 그림을 복사하는 게 아니라 스타일·구조를 학습해 새 작품을 만듦.
- **구체 예시**: GitHub Copilot은 코드 제안 수락률 30%, 개발자 생산성 55% 향상(GitHub 조사). Midjourney는 1024×1024 이미지를 10초 내 생성.
- **흔한 오해·주의점**: 생성형 AI가 "창작"하는 것이 아니라 학습 분포에서 샘플링함. 저작권·딥페이크·할루시네이션이 실무 도입 시 핵심 리스크임.

## 연결 개념
- LLM — 텍스트 생성형 AI의 대표 아키텍처
- Diffusion Model — 이미지·영상 생성의 핵심 기법
- AI 거버넌스 — 생성물의 저작권·윤리·안전 통제


# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 생성형 AI는 데이터 분포를 학습하여 텍스트·이미지·코드 등 새 콘텐츠를 자동 생성하는 기술임.
> 2. **가치**: 콘텐츠 초안 생성 시간을 수 시간→수 분으로 단축하고, 개발·디자인·문서 작성 생산성을 50%+ 향상함.
> 3. **판단 포인트**: 생성 품질·할루시네이션·저작권·보안 리스크를 동시에 통제하는 거버넌스가 도입의 핵심 전제임.


## Ⅰ. 개요 및 필요성

생성형 AI는 학습 데이터 분포로부터 새 콘텐츠를 생성하는 AI 기술임. 판별형 AI(분류·예측)가 "무엇인가"를 판단했다면, 생성형 AI는 "새로 만들어라"에 응답함. 콘텐츠 생산 비용 절감과 업무 자동화 수요로 기업 도입이 가속됨.


## Ⅱ. 구조 및 구성요소

```text
┌────────────┐   ┌──────────────┐   ┌────────────┐
│  입력 조건  │──▶│  생성 모델    │──▶│  출력 콘텐츠 │
│(프롬프트)   │   │(LLM/Diffusion│   │(텍스트/이미지│
│            │   │ /GAN)        │   │ /코드/음성) │
└────────────┘   └──────┬───────┘   └────────────┘
                        │
            ┌───────────┼───────────┐
            ▼           ▼           ▼
        사전학습     미세조정      가드레일
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 생성 모델 | 데이터 분포 학습·샘플링 | LLM(텍스트), Diffusion(이미지), Codec(음성) |
| 프롬프트 엔진 | 사용자 의도를 모델 입력으로 변환 | 시스템 프롬프트·Few-shot·RAG 보강 |
| 가드레일 | 유해·저작권·할루시네이션 필터 | 입출력 필터, PII 마스킹, 워터마크 |
| 평가 파이프라인 | 생성물 품질·안전성 측정 | BLEU, FID, 인간 평가, Red-Teaming |

> 요약: 생성형 AI는 프롬프트→생성모델→가드레일→평가의 4단 구조이며, 가드레일이 운영 안전의 핵심임.


## Ⅲ. 동작원리 및 흐름도

```text
사용자 프롬프트 → 전처리(RAG 보강) → 모델 추론
    → 가드레일 필터 → 출력 → 피드백 수집 → 모델 개선
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 프롬프트 수신·RAG 컨텍스트 보강 | 검색 적중률, 컨텍스트 길이 ≤128K 토큰 |
| 2 | 모델 추론(토큰/픽셀 생성) | p95 지연 1s 이내, GPU 활용률 80%+ |
| 3 | 가드레일 필터(유해·PII·저작권) | 차단률, False Positive율 ≤2% |
| 4 | 출력 전달·사용자 피드백 수집 | 수락률 30%+, CSAT, 할루시네이션율 ≤5% |

> 요약: RAG 보강→모델 추론→가드레일 필터→피드백 루프로 생성 품질과 안전성을 동시에 통제함.


## Ⅳ. 특징

| 구분 | 판별형 AI | 생성형 AI | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 출력 | 레이블·확률 | 텍스트·이미지·코드 | 생성 다양성 vs 정확성 트레이드오프 |
| 학습 목표 | P(Y\|X) 판별 경계 | P(X) 데이터 분포 | 파라미터 수 100B+, 학습 비용 $10M+ |
| 리스크 | 오분류 | 할루시네이션·딥페이크·저작권 | 가드레일·워터마크·출처 추적 필수 |

> 요약: 생성형 AI는 판별형 대비 출력 자유도가 높은 만큼, 할루시네이션·저작권·윤리 리스크 통제가 설계 필수축임.


## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 코드 생성: GitHub Copilot/내부 sLLM 도입으로 개발 생산성 55% 향상, 코드 리뷰 필수 프로세스 병행
2. 문서·콘텐츠: RAG 기반 사내 문서 초안 자동 생성, 할루시네이션율 5% 이하로 통제(출처 링크 필수)
3. 거버넌스: AI 생성물 워터마크(C2PA), 저작권 필터, Red-Teaming 분기별 수행으로 리스크 관리

**결론 (2줄):**
- 기술사 판단: 생산성 향상 효과가 검증된 코드·문서 영역부터 도입하고, 외부 공개 콘텐츠는 가드레일·워터마크를 전제함.
- 향후 방향: 멀티모달 통합(텍스트+이미지+영상)·에이전트 결합으로 생성에서 실행까지 자동화 범위가 확장됨.
