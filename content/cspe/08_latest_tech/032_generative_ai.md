## Ⅰ. 개요
- **정의**: 학습된 데이터 분포를 기반으로 텍스트·이미지·오디오·비디오 등 기존에 존재하지 않는 콘텐츠를 자율 생성하는 AI 기술 총칭
- **배경/필요성**: 판별형 AI(Discriminative)는 분류·예측만 수행하여 콘텐츠 창작이 불가능했으며, 메타버스·게임·마케팅 등 에셋 제작의 인적 비용이 산업 확장의 병목이 됨. 프롬프트만으로 콘텐츠를 생성하는 '창작 비용 제로화'가 요구됨
- **비유**: 판별형 AI가 미술 감정사라면, 생성형 AI는 화가 — 데이터 분포를 역으로 추적하여 새 작품을 창작함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 모달리티별 생성 원리 구분 | 텍스트(Autoregressive), 이미지(Diffusion), 멀티모달(Unified Embedding) | LLM 학습 파이프라인(031)과 중복 서술 금지, 생성 '행위' 중심 |
| 판별형 vs 생성형 차이 | P(Y|X) 예측 vs P(X) 분포 학습 후 샘플링 | Foundation Model(033)과의 관계: 기반모델 위에 생성 기능을 올린 응용 계층 |

> 요약: 데이터 분포를 학습하여 텍스트·이미지·비디오를 자율 창작하는 AI 응용 기술 계층

## Ⅱ. 구성요소
```text
+---------------------------+
|     Generative AI         |
|  +---------------------+  |
|  | Text Generation     |  |     +---------------------+
|  | (Autoregressive LM) |--+--->| Prompt (사용자 의도) |
|  +---------------------+  |     +---------------------+
|  | Image Generation    |  |              |
|  | (Diffusion Model)   |  |              v
|  +---------------------+  |     +---------------------+
|  | Audio/Video Gen.    |  |     | Generated Content   |
|  | (Diffusion+Transf.) |  |     | (텍스트/이미지/영상) |
|  +---------------------+  |     +---------------------+
+---------------------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Text Generation | Transformer 디코더 기반 Autoregressive 방식으로 토큰을 순차 생성 (상세 학습 구조는 031 참조) | 이야기꾼 |
| Image Generation | Diffusion Model: 이미지에 노이즈를 점진적으로 추가하는 과정을 학습한 뒤, 역방향으로 노이즈를 제거(Denoising)하여 이미지 생성 | 조각가 |
| Audio/Video Gen. | 시공간 패치(Spacetime Patch)를 Transformer+Diffusion 하이브리드로 처리하여 시계열 연속 프레임 생성 | 영화감독 |
| Prompt Interface | 자연어 텍스트로 생성 의도를 전달하는 인터페이스, 프롬프트 품질이 결과물 품질을 결정 | 주문서 |

> 요약: Autoregressive(텍스트) + Diffusion(이미지) + 하이브리드(영상)의 모달리티별 생성 엔진 조합

## Ⅲ. 절차
```text
+----------------+     +----------------+     +----------------+     +----------------+
| 1. 프롬프트    |---->| 2. 조건 인코딩  |---->| 3. 생성 엔진   |---->| 4. 후처리/     |
|    입력        |     |  (Conditioning)|     |    구동        |     |    피드백      |
+----------------+     +----------------+     +----------------+     +----------------+
```

1. **프롬프트 입력** — 사용자가 자연어 텍스트로 생성 의도를 명시 (예: "우주에서 고양이가 피아노 치는 이미지")
2. **조건 인코딩** — 텍스트 인코더(CLIP 등)가 프롬프트를 벡터로 변환하여 생성 모델의 조건(Condition)으로 주입
3. **생성 엔진 구동** — 텍스트: 토큰 순차 생성 / 이미지: 랜덤 노이즈에서 Denoising 반복 / 영상: 프레임 단위 시공간 생성
4. **후처리/피드백** — 생성물에 대한 안전성 필터링(유해 콘텐츠 차단), 사용자 피드백 기반 재생성·미세조정

> 요약: 프롬프트 → 조건 인코딩 → 모달리티별 생성 → 안전 필터링의 4단계 파이프라인

## Ⅳ. 문제점
- 저작권 침해: 학습 데이터 내 저작물의 스타일·패턴을 그대로 재현 — 원작자 동의 없는 학습 데이터 수집 관행
- 환각/사실 왜곡: 텍스트·이미지 모두 사실과 다른 콘텐츠를 그럴듯하게 생성 — 확률 분포 샘플링 특성상 사실 검증 부재
- 딥페이크 악용: 인물 얼굴·음성의 정밀 생성으로 사기·명예훼손에 악용 — 생성 품질 향상에 비해 탐지 기술 발전이 지체

> 요약: 저작권·환각·딥페이크가 생성형 AI 상용화의 3대 법적·윤리적 장벽

## Ⅴ. 개선방안
1. 단기: 상업용 안전 모델(Adobe Firefly 등) 도입 및 생성물 워터마킹(C2PA 표준) 의무화로 저작권 리스크 완화
2. 중기: 생성물 출처 추적 체계(Provenance) + AI 탐지 도구(딥페이크 탐지 모델) 고도화로 악용 방지
3. 장기: EU AI Act 등 글로벌 규제 프레임워크에 부합하는 Responsible AI 거버넌스 체계 내재화

- 저작권 리스크: 무단 학습 데이터 → 라이선스 검증된 데이터셋 + 옵트아웃 메커니즘 (지표: 법적 분쟁 건수 0건)
- 딥페이크 리스크: 생성 품질 > 탐지 능력 → C2PA 워터마크 + 실시간 딥페이크 탐지 파이프라인 (지표: 탐지율 95% 이상)

> 요약: 워터마킹·출처 추적·Responsible AI 거버넌스로 저작권·악용 리스크 통제

## Ⅵ. 전망
- 향후 발전 방향: 단일 모달리티 생성 → 텍스트·이미지·영상·3D를 하나의 Unified Model에서 동시 생성하는 Any-to-Any 멀티모달 생성으로 수렴
- 기술사적 판단: 생성형 AI는 Foundation Model(033) 위에 구축되는 응용 계층이며, 핵심 경쟁력은 모델 자체보다 프롬프트 설계·파인튜닝·안전성 파이프라인에 있음
- 기술사 제언: 엔터프라이즈 도입 시 퍼블릭 API 의존 대신 프라이빗 생성 인프라(On-Prem Diffusion + sLLM)를 구축하고, 생성물 전수에 대한 감사 로그·워터마크 체계를 설계 필수 사항으로 포함할 것
