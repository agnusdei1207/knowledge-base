## 미리 알고가기

- Naive RAG는 검색과 생성이 단순한 1회 파이프라인으로 이어지는 가장 기본적인 RAG 구조임
- 구현은 쉽지만 검색 정교화와 후처리가 부족해 실제 서비스에서는 한계가 빠르게 드러남
- 이후 advanced RAG, agentic RAG가 이 구조의 약점을 보완함

## Ⅰ. 개요

- **정의/개념**: Naive RAG는 문서 인덱싱 후 질의가 들어오면 단일 검색기를 통해 관련 문서를 한 번 가져오고, 이를 그대로 프롬프트에 넣어 답변을 생성하는 기본형 검색-생성 파이프라인임
- **배경/필요성**: 최신 정보와 내부 문서를 활용하는 가장 빠른 출발점이 필요했기 때문에, 복잡한 최적화 없이도 검색 기반 응답을 구현할 수 있는 단순 구조가 먼저 사용됨

## Ⅱ. 특징

- 구현이 간단하고 초기 실험과 PoC에 적합함
- 벡터 검색과 생성 모델만으로 빠르게 지식형 챗봇을 만들 수 있음
- 질의 재작성, 리랭킹, 압축이 없어 검색 실패와 노이즈 유입에 취약함
- 실서비스로 갈수록 정확도와 보안과 latency 제어 측면에서 한계가 드러남

## Ⅲ. 종류 및 비교

| 판단 기준 | Naive RAG | Advanced RAG | Agentic RAG |
|:---|:---|:---|:---|
| 파이프라인 복잡도 | 낮음 | 중간 | 높음 |
| 검색 품질 제어 | 낮음 | 높음 | 매우 높음 |
| 응답 지연 | 낮음 | 중간 | 높음 |
| 적합 환경 | PoC, 단순 QA | 상용 QA | 복합 추론 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Chunked Documents | 원문 문서를 나눈 청크가 검색 대상의 최소 단위가 됨 |
| Retriever | 질의와 가까운 청크를 한 번 찾아오는 단순 검색기 역할을 수행함 |
| Prompt Composer | 검색 결과를 그대로 묶어 생성 모델에 전달함 |
| LLM Generator | 검색 문맥을 참고해 최종 답변을 작성함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 문서 색인 준비  | --> | 단일 검색 수행   | --> | 검색 결과 주입   | --> | 답변 생성       |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **문서 색인 준비**: 문서를 청킹하고 임베딩이나 인덱스를 만듦
2. **단일 검색 수행**: 질의와 관련된 상위 문서를 한 번 검색함
3. **검색 결과 주입**: 가져온 문서를 프롬프트에 그대로 넣음
4. **답변 생성**: 모델이 검색 문서를 바탕으로 응답을 생성함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 모호한 질문이나 고유명사 질의에서는 단일 검색기가 적절한 문서를 못 찾아 답변 품질이 쉽게 떨어질 수 있음
   - 해결방안: query rewrite와 hybrid search를 도입하고 retrieval recall과 answer relevance로 검색 품질을 검증함
2. 문제: 검색된 문서 중 노이즈가 많아도 후처리 없이 그대로 들어가면 모델이 무관한 근거를 섞어 답할 수 있음
   - 해결방안: reranker와 context compression을 추가하고 context precision과 faithfulness로 노이즈 제어 수준을 검증함
3. 문제: 문서 접근 권한을 단순화하면 내부 지식 검색 과정에서 권한 우회 노출이 생길 수 있음
   - 해결방안: metadata filtering과 ACL을 적용하고 unauthorized hit rate와 audit log로 접근 통제를 검증함

## Ⅶ. 적용 사례

- 사내 FAQ PoC: 단순 문답형 챗봇을 빠르게 구현함, 확인 지표는 answer relevance와 build time임
- 문서 검색 보조: 매뉴얼 검색 후 요약 응답을 생성함, 확인 지표는 search hit rate와 user satisfaction임
- 교육용 데모 시스템: RAG 구조 이해를 위한 기초 예제로 사용함, 확인 지표는 setup simplicity와 response latency임

## Ⅷ. 결론

Naive RAG는 가장 단순한 검색 기반 생성 구조로 출발점으로는 유용하지만, 실서비스 품질을 내려면 검색 정교화와 보안 통제가 추가된 고도화가 거의 필수임.
