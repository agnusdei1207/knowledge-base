## 미리 알고가기

- 기본형 RAG ($Naive$ $RAG$): 별도의 질의 변형이나 검색 결과 재정렬(Rerank) 등의 최적화 절차 없이, 사용자의 원시 질문에 대응하여 벡터 DB 단발 검색을 쳐서 가져온 컨텍스트로 생성 모델을 구동하는 가장 원초적인 RAG 파이프라인 구조임
- 인덱싱-검색-생성 ($Indexing-Retrieval-Generation$): Naive RAG의 기본 3요소 순차 흐름이자 RAG 아키텍처의 필수 라이프사이클 단계임
- 코사인 유사도 ($Cosine$ $Similarity$): 다차원 임베딩 벡터 공간 상에서, 두 문서 벡터 간의 사잇각 코사인 값을 구해 문서 간의 의미론적 유사성 수치를 $[-1, 1]$ 범위로 계산해 내는 수학 공식임
- 정밀도 저하 ($Retrieval$ $Recall$): 질의의 핵심 키워드나 맥락을 리트리버가 올바르게 긁어오지 못하고 오작동하는 현상으로, 생성 모델의 할루시네이션(환각)을 직접 가중시키는 원인임

## Ⅰ. 개요

- **정의/개념**: Naive RAG는 사용자 유입 질의의 원시 텍스트를 즉시 밀밀도 벡터(Dense Vector)로 변환해 임베딩 유사도가 높은 탑 $K$개 청크 문서만을 단발성 검색(One-shot Retrieval)하고, 추가 후처리 필터링 없이 그대로 프롬프트에 병합하여 생성 모델에 넘기는 초기 기초형 RAG 아키텍처임
- **배경/필요성**: LLM의 단발성 환각 현상을 억제하고 실시간 외부 팩트 주입을 구현하기 위해 제안되었으나, 질의 변형 및 리랭커 등의 복잡한 수학 조율 없이 가장 신속하게 PoC(개념 검증)를 가동하고자 개발 및 차용됨

## Ⅱ. 특징

- 인덱싱, 검색, 생성의 순차 단선 파이프라인으로 구성되어 시스템 통합 난이도가 낮으며, LangChain 등으로 반나절 만에 신속 PoC 구현이 가능함
- 검색된 청크 원문 그대로 프롬프트에 태우므로, 원본 문단 내에 섞인 무관한 노이즈가 고스란히 유입되어 컨텍스트 윈도우(Context Window)를 낭비함
- 사용자 질문에 오탈자나 단어 누락이 존재하면 리트리버가 코사인 유사도 기반 매핑에 대실패하여, 모델에 엉뚱한 쓰레기 문맥(Garbage-in)을 밀어 넣는 태생적 취약성을 가짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 기본형 RAG (Naive RAG) | 고도화형 RAG (Advanced RAG) | 에이전틱 RAG (Agentic RAG) |
|:---|:---|:---|:---|
| **파이프라인 흐름** | 단선형 (단발 검색 후 즉시 생성) | 검색 전후 다각 최적화 (Rerank 등) | 피드백 루프 (AI 에이전트의 조건부 검색 반복) |
| **질의어 재작성** | 없음 (사용자 원시 문자열 그대로 검색) | 필수 (다중 질의 확장, 서브 질문 분할) | 동적 계획 수립 (필요한 문장 자가 생성) |
| **추론 오버헤드** | 극도로 낮음 (단일 쿼리 즉시 반환) | 중간 (리랭커 연산 지연 추가) | 높음 (루프 순환으로 인한 다중 API 호출 지연) |
| **실무 적합성** | PoC 검증용, 연구 기초 | 엔터프라이즈 사내 챗봇 표준 | 고난도 논리 추론, 복합 문서 요약 |

> 요약: Naive RAG는 초간단 오픈북 테스트이고, Advanced RAG는 기출문제를 미리 복사하고 노이즈를 요약 정리해 시험장에 들어가는 지혜형이며, Agentic RAG는 모르는 문제를 직접 되물어가며 검산 및 탐색을 반복하는 능동형임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 단순 청크 생성기 | PDF 문서를 단어 수(예: $500$자) 기준으로 칼로 자르듯 균일 등분하는 기초 전처리기임 |
| 단발형 리트리버 | 사용자 원시 질문 벡터와 코사인 유사도를 연산해 Top-N 문단을 1회 서치하는 단발기임 |
| 프롬프트 합성기 | 검색 문단을 어떠한 순위 정리나 중복 소거 없이 프롬프트 본체에 욱여넣는 병합기임 |
| 바닐라 $LLM$ | 인입된 정돈되지 않은 컨텍스트를 근거 삼아 문장을 릴리즈하는 기본 생성 모델임 |

```text
[ Naive RAG (단선 3단계) 물리 구조 ]
Document Indexing ──> [ Cosine Similarity Search ] ──> [ Raw Contexts Concat ]
                                                               │
User Screen <── [ Vanilla LLM Generation ] <───────────────────/
- 어떠한 Rerank나 쿼리 확장 단계 없이 1회 패스로 무조건 계산 방출함
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 기계적 청킹 | --> | 코사인유사도 | --> | 원문 그대로 | --> | 가이드라인  |
| 및 임베딩   |     | 단발 문서검색|     | 프롬프트합성|     | 추종 및 생성|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **인덱싱 처리** — 타깃 문서를 단순 글자 수로 기계 청킹한 뒤, Sentence-Transformers 모델로 임베딩 벡터화해 DB에 이식함
2. **단발성 쿼리** — 사용자의 원시 인풋 질문을 그대로 임베딩 서버로 쏘아, 벡터 공간 상의 코사인 유사도 상위 $3$개 문단을 획득함
3. **컨텍스트 패킹** — 획득한 $3$개 문단의 정합성 검사나 중복 소거 단계를 건너뛰고, 지시어 프롬프트 템플릿 $Context$ 단에 무조건 결합함
4. **결과 출력** — LLM이 주입된 청크의 잡다한 노이즈 문장에 현혹되면서도 나름의 정답을 생성해 최종 스트림을 방출함

## Ⅵ. 실무 적용 및 유의점

1. 사용자의 문맥이 조금만 비틀어지거나 오탈자가 유입될 때 검색기 적중률($Recall$)이 수직 하강해 RAG 전체 답변이 왜곡 파괴되므로, 반드시 질문을 동적으로 다변화하는 '질의 재작성($Query$ $Rewriting$)' 및 Dense-Sparse '하비리드 검색'을 보완 융합해야 함
2. 기계적으로 자른 문서 단락 사이의 맥락 단절과 중복 노이즈 유입으로 인해 VRAM 요금 낭비와 중간 소실이 생기므로, 반드시 '리랭커(Reranker)'를 도입하고 문맥 정합성($Context$ $Precision$)을 지속 감사 평가해야 함

## Ⅶ. 결론

- Naive RAG는 대형 모델의 팩트 주입 PoC 테스트를 단시간 내에 완수하는 가장 정통적인 시작점이자 데이터 흐름의 기초선이며, 설계자는 단선형 아키텍처의 한계인 질의 왜곡과 노이즈 유입 병목을 해소하기 위해 질의 재작성 및 리랭커 결합 고도화를 필히 연계 집행해야 함
