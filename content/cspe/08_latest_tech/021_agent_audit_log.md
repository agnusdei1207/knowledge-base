# 📖 【암기용】 개념 완전 이해

> 목적: 에이전트 감사로그를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: 에이전트의 입력, 판단, 도구 호출, 출력, 승인 이력을 추적하는 로그
- **왜 필요한가**: AI가 업무 시스템을 변경하면 누가, 왜, 어떤 근거로 실행했는지 증명해야 함.
- **핵심 직관**: 감사로그는 AI 업무의 블랙박스 기록장임.

## 깊이 이해
- **배경·문제의식**: 에이전트는 자연어 입력과 모델 판단을 거쳐 도구를 호출하므로 기존 API 로그만으로 책임 추적이 부족함.
- **작동 원리**: 사용자 요청, 모델 버전, 프롬프트 버전, 도구명, 입력 해시, 응답코드, 승인자, 출력 결과를 Trace ID로 연결함.
- **비유**: 금융 거래에서 계좌이체 요청, 승인자, 처리 시스템, 결과를 모두 거래번호로 묶어 보관하는 구조.
- **구체 예시**: 방화벽 정책 변경 Agent가 요청자, 변경 규칙, 승인자, 실행 API, 롤백ID를 하나의 로그로 남김.
- **흔한 오해·주의점**: 대화 로그만 저장하면 도구 실행 책임과 모델 버전 재현성이 빠져 감사 증거로 부족함.

## 연결 개념
- Observability — 실행 추적과 지표 수집
- SIEM — 보안 이벤트 통합 분석
- Non-repudiation — 부인방지 증거

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Agent Audit Log는 AI 에이전트의 요청·추론·도구호출·승인·결과를 Trace ID로 연결한 감사 기록임.
> 2. **가치**: 사고 원인분석, 책임 추적, 규제 대응, 재현성 확보의 근거를 제공함.
> 3. **판단 포인트**: 원문 저장 최소화, 입력 해시, 모델·프롬프트 버전, 로그 무결성을 함께 설계해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| AI 실행 책임 추적 구조 이해 | Trace ID 연결, 모델·프롬프트 버전, WORM 무결성 | 대화 로그만 저장하면 도구 실행 책임·재현성 불충분 |
| 기존 앱 로그와 Agent 감사로그 차이 | 모델 판단 근거, 승인자, 입력 해시 포함 여부 | 민감정보 원문 저장 금지 — 토큰화·마스킹·해시 적용 |

> 요약: 출제자는 AI 도구 호출의 책임 추적과 로그 무결성 설계 역량을 확인하려 함.

---

## Ⅰ. 개요 및 필요성

- 정의: AI 에이전트 실행의 감사 추적 기록
- 배경: 에이전트가 외부 시스템을 변경하면 기존 앱 로그만으로 모델 판단·도구 호출 근거를 증명할 수 없음
- 필요성: 사고 원인분석, 규제 대응, 재현성 확보에 Trace ID 기반 감사 기록 필수

## Ⅱ. 구조 및 구성요소

```text
User Request -> Agent Trace -> Tool Call -> Approval -> Result
                 |                |            |
                 +-> 모델/프롬프트  +-> API로그    +-> 승인자/결과/롤백
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Trace ID | 전체 실행 연결키 | 요청-도구-결과 연결 |
| Model Context | 모델·프롬프트 버전 | 재현성 근거 |
| Tool Log | 도구 호출 이력 | 입력 해시, 응답코드 |
| Integrity | 로그 무결성 보호 | WORM, hash chain |

> 요약: 감사로그는 Trace ID를 중심으로 사용자, 모델, 도구, 승인, 결과를 연결함.

---

## Ⅲ. 동작원리 및 흐름도

```text
요청 수신 -> Trace 생성 -> 판단/도구호출 기록
        -> 승인 기록 -> 결과 저장 -> 무결성 검증
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | Trace 생성 | 사용자ID, 목적, 시간 |
| 2 | 모델 실행 기록 | 모델버전, 프롬프트버전 |
| 3 | 도구 호출 기록 | 도구명, 입력 해시, 응답코드 |
| 4 | 보존·검증 | WORM, hash, 보존기간 |

> 요약: 감사로그는 실행 시점부터 생성되어 보존기간 동안 무결성 검증이 가능해야 함.

---

## Ⅳ. 특징

| 구분 | 일반 앱 로그 | Agent Audit Log | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 기록 범위 | API·시스템 이벤트 | 요청·모델·도구·승인 | Trace 연결률 |
| 재현성 | 코드 버전 중심 | 모델·프롬프트 버전 포함 | 재현 가능 건수 |
| 위험 | 로그 위변조 | 민감 프롬프트 노출 | WORM, 마스킹 |

> 요약: Agent Audit Log는 모델 판단까지 포함하지만 민감정보 저장을 최소화해야 함.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존 앱 로그 | Agent Audit Log | 선택 기준 |
|:---|:---|:---|:---|
| 기록 범위 | API 요청·응답 | 모델버전·프롬프트·도구·승인 포함 | 모델 판단 재현 필요 여부 |
| 무결성 | DB 로그, 파일 로그 | WORM, hash chain, 감사 보존기간 | 규제·감사 요구 수준 |
| 민감정보 | 앱 레벨 마스킹 | 입력 해시, 토큰화, 프롬프트 마스킹 | 개인정보보호법·내부 정책 |

> 요약: 모델 판단 재현과 규제 감사가 필요하면 기존 앱 로그가 아닌 Agent Audit Log를 설계함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 민감정보 노출 | 프롬프트·응답 원문 저장 | 토큰화·마스킹·해시 적용, 원문 저장 금지 | 마스킹 적용률 100% |
| 로그 위변조 | 변경·삭제 가능한 저장소 | WORM 저장소, hash chain, 접근통제 | 무결성 검증 통과율 |
| 재현 불가 | 모델·프롬프트 버전 미기록 | 모델ID·프롬프트 버전·파라미터를 Trace에 포함 | 재현 가능 건수/전체 건수 |

> 요약: 민감정보 원문 저장과 로그 위변조가 핵심 리스크이며 마스킹·WORM·버전 기록으로 통제함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| Trace 연결률 | 요청-도구-결과 100% 연결 | Trace ID 누락 건수 모니터링 |
| 로그 무결성 | hash chain 검증 통과 100% | 주간 무결성 검증 배치 |
| 보존 기간 | 변경형 작업 로그 1년 이상 보존 | 보존 만료 전 알림·아카이빙 |

> 요약: Trace 연결률, 무결성 검증, 보존 기간 준수를 정기 점검함.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 사용자ID, AgentID, 모델버전, 프롬프트버전, 도구명, 입력 해시, 결과를 Trace ID로 연결
2. 로그 원문에는 비밀키·개인정보를 저장하지 않고 필요 시 토큰화·마스킹·해시 적용
3. 변경형 작업 로그는 WORM 저장소와 SIEM 연계로 1년 이상 보존하고 이상 호출을 탐지

**결론 (2줄):**
- 기술사 판단: AI가 시스템 상태를 바꾸는 업무는 감사로그 없이는 운영 승인 대상이 아님.
- 향후 방향: Agent Audit Log는 AI 거버넌스, 보안관제, 규제 대응의 핵심 증거 계층으로 발전함.
