## Ⅰ. 개요
- **정의**: 에이전트의 추론·도구 호출·반환값을 Trace/Span 구조로 기록하는 불변 감사 체계
- **배경/필요성**: 에이전트가 업무 의사결정(대출 심사, 환불 처리)에 투입되면서 "왜 그런 결정을 했는가"에 대한 법적·기술적 증명 의무가 발생함. EU AI Act 등 규제가 AI 결정의 설명 가능성을 강제하므로, 행동 궤적의 위변조 불가 기록이 필수
- **비유**: 비행기 블랙박스 — 사고 시 조종사의 판단 근거를 복원하는 장치

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| LLM 관측성과 기존 APM의 차이 | Trace-Span 계층 구조, PII 마스킹, WORM 저장소 | 단순 Access Log와 혼동 금지. 프롬프트·토큰·추론 과정까지 기록 대상임을 명시 |

> 요약: 에이전트 행동 궤적을 Trace/Span으로 계층 기록하여 설명 가능성·책임 추적·비용 가시성을 확보하는 체계

## Ⅱ. 구성요소
```text
+---------------------------+
|   Agent Runtime           |
|  (LLM 호출 + Tool 실행)  |
+------------+--------------+
             |  @trace 데코레이터
             v
+------------+--------------+
|  Instrumentation Layer    |
|  - Prompt / Response 캡처 |
|  - Tool I/O JSON 수집     |
+------------+--------------+
             |
             v
+------------+--------------+
|  Trace-Span Mapper        |
|  - Trace ID (작업 단위)   |
|  - Span (하위 동작 단위)  |
+------+----------+---------+
       |          |
       v          v
+------+---+ +---+------------+
| PII      | | WORM Storage   |
| Masking  | | (불변 원장)    |
+------+---+ +---+------------+
       |          |
       v          v
+------+----------+---------+
|  Dashboard / Analytics    |
|  (LangSmith, Langfuse)   |
+---------------------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Instrumentation | 프롬프트·응답·도구 호출 파라미터를 런타임에서 가로채 수집하는 계측 계층 | CCTV 카메라 |
| Trace-Span Mapper | 하나의 사용자 요청(Trace)과 그 하위 동작(Span)을 트리 구조로 맵핑 | 소포 추적 번호 |
| PII Masking | 주민번호·카드번호 등 민감 정보를 저장 전 비식별화 처리 | 모자이크 처리 |
| WORM Storage | Write-Once-Read-Many 방식으로 로그 위변조를 원천 차단하는 불변 저장소 | 공증 원본 보관함 |
| Dashboard | Trace 검색·에러 필터링·토큰 비용 집계를 시각화하는 분석 도구 | 관제탑 모니터 |

> 요약: 계측→Trace/Span 맵핑→PII 마스킹→불변 저장→대시보드 분석의 5계층 파이프라인

## Ⅲ. 절차
```text
+----------------+    +----------------+    +----------------+    +----------------+
| 1. 계측        | -> | 2. 구조화      | -> | 3. 비식별화    | -> | 4. 저장/분석   |
| (Instrument)   |    | (Trace-Span)   |    | (PII Masking)  |    | (Store/Query)  |
+----------------+    +----------------+    +----------------+    +----------------+
```

1. **계측(Instrumentation)** — 에이전트 프레임워크에 @trace 데코레이터를 삽입하여 프롬프트 텍스트, LLM 응답, 도구 호출 인자(JSON), 소모 토큰 수를 실시간 포획
2. **구조화(Trace-Span Mapping)** — 사용자 요청 1건을 Trace ID로 묶고, 하위 검색·생성·도구 호출을 개별 Span으로 트리 구조화하여 인과 관계 추적 가능하게 편성
3. **비식별화(PII Masking)** — 저장 전 정규식 + NER 모델로 개인 식별 정보를 마스킹하여 로그 유출 시 2차 피해 차단
4. **저장 및 분석(Storage & Analytics)** — WORM 스토리지에 영구 보존 후, 대시보드를 통해 에러 Trace 역추적·토큰 비용 FinOps 분석 수행

> 요약: 계측→구조화→비식별화→저장/분석 4단계로 에이전트 행동의 완전한 감사 추적 체계 구축

## Ⅳ. 문제점
- [로그 폭증(Log Storm)]: 에이전트 대화 전문이 저장되어 TB 단위 스토리지 비용 발생 — 비용이 에이전트 운영비를 초과할 수 있음
- [비정형 데이터 검색 난이도]: 프롬프트·추론 과정이 자연어이므로 기존 정형 로그 대비 원인 분석에 고급 쿼리(시맨틱 검색) 필요
- [PII 마스킹 누락 리스크]: 정규식만으로 모든 민감 정보를 포착 불가 — 마스킹 실패 시 규제 위반 및 과징금 발생

> 요약: 스토리지 비용 폭증, 비정형 로그 분석 난이도, PII 마스킹 누락이 3대 핵심 리스크

## Ⅴ. 개선방안
1. 단기: 로그 티어링(Tiering) 전략 도입 — 성공 Trace는 7일 TTL 후 S3 Glacier로 이관, 실패·도구 조작 Trace만 고속 DB에 장기 보존
2. 중기: 벡터 DB 기반 시맨틱 검색 도입으로 자연어 로그에서 유사 장애 패턴 자동 클러스터링
3. 장기: NER 모델 + 정규식 하이브리드 마스킹 파이프라인 구축, 마스킹 정확도 99.9% 이상 목표

- [마스킹 누락]: [NER 모델 한계] → NER + 정규식 + LLM 2차 검증 3중 필터 적용 (지표: PII 탐지율 ≥ 99.9%)

> 요약: 티어링으로 비용 제어, 시맨틱 검색으로 분석력 강화, 하이브리드 마스킹으로 규제 리스크 차단

## Ⅵ. 전망
- 향후 발전 방향: 감사 로그를 평가 모델(LLM-as-a-Judge)이 자동 분석하여 프롬프트 결함을 탐지하고 자율 튜닝하는 DSPy 기반 자동 최적화 루프로 진화
- 기술사적 판단: 에이전트 도입의 최대 장벽인 '신뢰(Trust)' 문제를 감사 로그가 기술적으로 해결함. 로그 없는 에이전트는 프로덕션 배포 불가
- 기술사 제언: WORM 저장소 + Trace 기반 관측성을 에이전트 아키텍처의 Day-1 필수 구성으로 설계하고, 로그 비용은 전체 에이전트 TCO의 15% 이내로 관리할 것
