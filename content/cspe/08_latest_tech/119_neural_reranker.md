# 📖 【암기용】 개념 완전 이해

> 목적: Neural Reranker를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: 1차 검색 후보를 질의와 다시 비교해 관련도 순서로 재정렬하는 신경망 모델
- **왜 필요한가**: 1차 검색은 재현율을 위해 후보를 넓게 가져오므로, LLM에 넣기 전 정밀한 근거 선별이 필요함.
- **핵심 직관**: 서류전형으로 후보 50명을 뽑고, 면접으로 최종 5명을 고르는 2단계 선발 방식임.

## 깊이 이해
- **배경·문제의식**: Dense나 BM25 Top-K에는 관련 없는 문서가 섞인다. LLM 컨텍스트는 제한되어 있어 후보 중 핵심 근거만 남겨야 함.
- **작동 원리**: BM25/Dense가 Top-50~100 후보를 생성하고, Reranker가 질의-문서 쌍을 더 정밀하게 점수화해 Top-3~5를 선택함.
- **비유**: 검색엔진이 넓게 찾아온 기사 목록을 전문가가 다시 읽고 질문에 맞는 기사만 위로 올리는 과정임.
- **구체 예시**: Cross-Encoder 리랭킹 적용 시 RAG Precision@5가 62%->82%, 평균 지연은 300ms->900ms로 증가.
- **흔한 오해·주의점**: Reranker는 1차 검색이 놓친 문서를 살릴 수 없음. Recall@50이 낮으면 리랭킹 이전 검색을 보완해야 함.

## 연결 개념
- Cross-Encoder Reranker — 질의·문서를 함께 입력하는 대표 리랭커
- Hybrid Search — 리랭킹 전 후보 재현율을 높이는 방식
- MMR — 중복 후보를 줄이는 다양성 기반 후처리

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Neural Reranker는 1차 검색 후보를 정밀 점수화해 LLM 입력 근거를 재정렬함.
> 2. **가치**: Precision@5 62%->82%로 높여 RAG 환각 원인인 무관 문서 혼입을 줄임.
> 3. **판단 포인트**: 리랭커는 정밀도 개선 도구이며, 1차 검색 Recall@50 확보가 선행 조건임.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 1차 검색과 리랭킹의 역할 분리를 이해하고 RAG 근거 품질 개선 원리를 설명할 수 있는지 | Precision@5 62%→82%, Recall@50 선행 조건, nDCG@10 ≥0.55, 지연 ≤700ms | Reranker가 1차 검색 누락을 복구한다고 오해, 비용·지연 트레이드오프 누락 |

> 요약: 1차 검색 Recall 확보가 선행되어야 하며, 리랭커는 정밀도 개선 도구임을 명확히 구분해야 함

## Ⅰ. 개요 및 필요성

- 정의: 검색 후보를 정밀 점수화해 재정렬하는 신경망 모델
- 배경: 1차 검색은 속도와 재현율 중심이라 무관 문서가 포함될 수 있음
- 필요성: LLM 컨텍스트 제한 내에서 핵심 근거만 선별해 RAG 답변 품질을 높여야 함

## Ⅱ. 구조 및 구성요소

```text
Query -> BM25/Dense Retriever -> Top-N Candidates
  -> Reranker Scoring -> Top-K Evidence -> LLM
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| First-stage Retriever | 후보 Top-50~100 생성 | BM25, Dense, Hybrid |
| Reranker Model | 질의-문서 관련도 점수 산정 | Cross-Encoder, ColBERT, LLM rerank |
| Candidate Filter | 중복·권한·길이 필터링 | ACL, MMR, source diversity |
| Evidence Selector | LLM 입력 Top-3~5 선정 | 컨텍스트 예산 기반 |

> 요약: Reranker는 넓게 검색한 후보를 정밀 점수화해 LLM 입력 근거를 소수로 압축함.

## Ⅲ. 동작원리 및 흐름도

```text
질의 입력 -> 1차 검색 Top-100 -> 후보 필터링
  -> 리랭커 점수 계산 -> Top-5 선정 -> LLM 컨텍스트 구성
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | BM25/Dense/Hybrid로 Top-50~100 후보 생성 | Recall@50 ≥95% |
| 2 | 후보 중복·권한·길이 필터링 | 권한 위반 0건 |
| 3 | 리랭커가 질의-문서 관련도 점수 산정 | nDCG@10 ≥0.55 |
| 4 | Top-3~5 근거를 LLM에 전달 | Precision@5 ≥80%, 추가 지연 <700ms |

> 요약: 1차 검색으로 후보 재현율을 확보하고, 리랭커로 정밀도를 높여 LLM 입력 근거를 선별함.

## Ⅳ. 특징

| 구분 | 1차 검색 단독 | Reranker 적용 | 판단 포인트 |
|:---|:---|:---|:---|
| 품질 | Recall 중심 | Precision 중심 | Precision@5 80% 목표 |
| 지연 | 100~300ms | 500~1,000ms | 실시간 SLA 2초 이내 여부 |
| 비용 | 검색 인프라 비용 | GPU/LLM 호출 비용 추가 | 후보 수 50 이하로 제한 |
| 한계 | 무관 문서 혼입 | 후보 누락 복구 불가 | Recall@50 선행 확보 |

> 요약: Reranker는 RAG 입력 정밀도를 높이지만, 후보 누락은 복구하지 못하므로 1차 검색 재현율이 선행 조건임.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | Cross-Encoder Reranker | LLM-as-Reranker(프롬프트 기반) | 선택 기준 |
|:---|:---|:---|:---|
| 판단 방식 | 전용 학습된 relevance 모델 | 범용 LLM에 프롬프트로 순위 지시 | 전용 모델 학습·운영 여력 |
| 추론 비용 | 소형 모델, 저비용 배치 처리 | LLM 호출 비용, 후보당 토큰 과금 | 후보 수 많으면 Cross-Encoder가 경제적 |
| 유연성 | 도메인 파인튜닝 필요 | 프롬프트 수정만으로 기준 변경 가능 | 순위 기준이 자주 바뀌면 LLM-as-Reranker |

> 요약: 대량·저비용 리랭킹은 Cross-Encoder, 소량·기준 변경이 잦은 경우는 LLM-as-Reranker를 선택함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 1차 검색 누락 | Recall@50 부족으로 근거 미포함 | Hybrid Search(BM25+Dense) 병행, Recall@50 ≥95% 확보 | Recall@50 주간 모니터링 |
| 리랭킹 지연 | 후보 수 100건 초과 시 GPU 부하 | 후보 50건 제한, MiniLM 경량 모델 적용 | p95 지연 ≤700ms |
| 품질 미개선 | 리랭커 모델 도메인 불일치 | 도메인 데이터로 fine-tuning, A/B 테스트 | nDCG@10 ≥0.55, faithfulness ≥80% |

> 요약: 1차 검색 Recall 확보가 선행되고, 후보 수 제한과 모델 튜닝으로 지연·품질 리스크를 통제함

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 정밀도 | Precision@5 ≥80%, nDCG@10 ≥0.55 | 평가셋 리랭킹 전후 비교 |
| 지연 | 리랭킹 추가 지연 ≤700ms, 전체 p95 ≤2초 | APM 지연 모니터링 |
| 비용 효율 | GPU 사용률 ≤70%, 비용 대비 Precision 개선 ≥10%p | GPU 메트릭·A/B 테스트 |

> 요약: 정밀도·지연·비용 3개 축으로 리랭커 도입 효과를 정량 판단함

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. RAG 운영: Hybrid Top-50 후보를 bge-reranker-large로 재정렬, Top-5만 GPT-4o 컨텍스트에 주입
2. 비용 제어: 후보 100건 초과 시 MMR로 50건으로 축소, 리랭커 배치 추론으로 GPU 사용률 70% 유지
3. 품질 평가: Precision@5·nDCG@10·faithfulness를 리랭커 적용 전후로 비교, 지연 1초 초과 시 후보 수 조정

**결론 (2줄):**
- 기술사 판단: RAG 답변 정확도가 요구되는 운영 서비스는 Reranker 적용, 단순 검색 PoC는 1차 검색 단독 가능
- 향후 방향: Cross-Encoder, ColBERT, LLM-as-Reranker가 비용·정밀도 요구에 따라 혼합 적용
