## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 앤스로픽(Anthropic)이 주도하여 오픈소스로 공개한 규격으로, AI 모델(Claude, GPT 등)이 구글 드라이브, 슬랙, 사내 데이터베이스 등 **외부 데이터 소스와 도구에 안전하고 표준화된 방식으로 접근하게 해주는 범용 통신 프로토콜**이다.
> 2. **가치**: 과거에는 AI에 회사 DB를 연동하려면 개발자가 맞춤형 API 파이프라인을 100개면 100개 다 수작업으로(N:M 구조) 짜야 했다. MCP는 USB 단자(Type-C)처럼 이 연결망을 통일(N:1:M)하여, 한 번만 만들어두면 어떤 AI든 꽂아서 쓸 수 있는 생태계의 대통합을 이뤄냈다.
> 3. **판단 포인트**: AI(Client)와 데이터 소스(Server)를 완벽히 분리하는 클라이언트-서버 아키텍처와, 그 사이에서 교환되는 3대 핵심 스펙인 **리소스(Resource), 도구(Tool), 프롬프트(Prompt)**의 개념을 명확히 제시해야 한다.

## Ⅰ. 개요 및 필요성
- **개요**: Model Context Protocol (MCP)은 언어 모델 애플리케이션과 외부 데이터 소스 및 도구 간의 양방향 통신을 위한 표준화된 개방형 프로토콜이다.
- **배경**: AI 에이전트 시대가 열리며 깃허브(GitHub), 노션, JIRA, 슬랙 등 수많은 툴을 AI와 연동해야 했다. 하지만 각 툴마다 API 규격이 다르고 인증 방식이 달라서, AI 하나를 바꿀 때마다(예: GPT에서 Claude로) 모든 연결 코드를 다 갈아엎어야 하는 '통합의 지옥(Integration Hell)'이 열렸다.
- **필요성**: 마치 컴퓨터에 마우스나 키보드를 꽂을 때 브랜드에 상관없이 USB 단자 하나로 통일되듯, AI 애플리케이션이 외부 세계와 소통하는 '보편적이고 안전한 USB 인터페이스 표준'이 절대적으로 필요했다.

## Ⅱ. 아키텍처 및 핵심 원리

```text
       [ 과거: N x M 스파게티 연결 ]                    [ 현재: MCP를 통한 1:1 허브 통신 (USB-C) ]

 Claude 앱 ──┬── Notion API (맞춤형 코드)         Claude 앱 ──┐     [ MCP 프로토콜 ]      ┌── Notion MCP 서버
 ChatGPT 앱 ─┼── GitHub API (맞춤형 코드)         ChatGPT 앱 ─┼──▶ (통일된 JSON-RPC) ──▶ ├── GitHub MCP 서버
  Llama 앱 ──┴── Slack API  (맞춤형 코드)          Llama 앱 ──┘                       └── Slack MCP 서버
  (개발자가 9개의 연결 코드를 다 짜야 함!)                     (AI는 MCP Client 1개만 짜면 끝!)
```

- **1단계 [클라이언트-서버 아키텍처 분리]**: 
  - **MCP Client**: Claude Desktop이나 Cursor IDE처럼 AI 모델을 구동하는 앞단 프로그램.
  - **MCP Server**: Github, Notion 등 실제 데이터와 도구를 들고 있는 뒷단 서버(로컬 프로세스 또는 원격 서버).
- **2단계 [JSON-RPC 기반 통신]**: 클라이언트와 서버는 표준화된 JSON-RPC 2.0 메시지(STDIO 또는 SSE over HTTP)를 주고받으며 "무슨 도구가 있어?", "이거 실행해 줘"라고 대화한다.
- **3단계 [3대 핵심 기능 (Features) 제공]**:
  1. **리소스 (Resources)**: 파일, API 응답 등 서버가 쥐고 있는 "읽기 전용 데이터"를 AI에게 제공 (예: 사내 위키 텍스트).
  2. **도구 (Tools)**: AI가 "서버야, 이거 실행해 줘"라고 요청할 수 있는 "행동(Action) 함수" (예: Github에 PR 올리기).
  3. **프롬프트 (Prompts)**: 사용자가 자주 쓰는 템플릿 명령어 모음.
- **4단계 [보안 및 제어]**: MCP 서버는 AI(Client)에게 필요한 권한만 주고, 위험한 행동은 차단하며 데이터의 흐름을 로컬 장비 내에서 안전하게 격리(Isolate)하여 통제한다.

## Ⅲ. 비교 및 연결

| 비교 축 | 맞춤형 API 연동 (Custom API) | OpenAPI 규격 (Swagger) | Model Context Protocol (MCP) |
|:---:|:---|:---|:---|
| **설계 목적** | 특정 서비스 1:1 통신 | REST API의 문서화 표준 | **AI 에이전트와 외부 세상의 표준 연결망** |
| **재사용성** | 타 모델로 이식 불가 | 엔드포인트별 파싱 로직 짜야 함 | **MCP 서버 하나 띄우면 세상 모든 AI가 접속 가능** |
| **통신 방식** | 제각각 (REST, GraphQL 등) | 주로 HTTP REST | **로컬 STDIO 프로세스 통신** 또는 **원격 SSE** |
| **컨텍스트 지원**| 직접 텍스트로 밀어 넣어야 함 | 직접 주입해야 함 | 리소스, 프롬프트 등 **AI 문맥 주입에 극도로 최적화** |

> ※ **연결 포인트**: MCP는 이전에 앤스로픽이 제안했던 'Tool Use(도구 호출)' 개념을 "우리만 쓰기 아까우니 전 세계가 쓰는 네트워크 프로토콜로 승격시키자!"라며 오픈소스로 풀어버린 생태계 장악의 마스터피스다.

## Ⅳ. 실무 적용 및 기술사 판단

- **적용 사례 1 (로컬 PC의 완벽한 AI 비서화)**: Claude Desktop 앱(MCP Client)에 로컬 파일 시스템을 읽는 `sqlite-mcp-server`를 연동한다. 사용자가 "내 컴퓨터 D드라이브에 있는 고객 DB(sqlite) 분석해서 차트 그려줘"라고 하면, Claude가 알아서 로컬 DB를 쿼리해서 차트를 뽑아낸다. 데이터가 클라우드로 새어나가지 않는 극강의 보안 로컬 비서가 탄생한다.
- **적용 사례 2 (Cursor IDE의 Github 자동 연동)**: 코딩 전문 AI 인 Cursor에 Github MCP 서버를 연동한다. 개발자가 "현재 내 코드의 에러를 수정하고, Github 레포지토리에 PR(Pull Request) 올려줘"라고 말로만 지시하면, AI가 코드를 고치고 Github 도구(Tool)를 원격 호출하여 PR 생성까지 원스톱으로 끝내버린다.
- **기술사 판단**: MCP의 가장 큰 가치는 **"보안 경계(Security Boundary)의 명확한 분리"**다. 모델 공급자(OpenAI 등)에게 사내 데이터를 API로 다 바칠 필요가 없다. 회사는 사내망에 '사내 DB용 MCP Server'를 띄우고, AI(Client)는 이 서버에 요청(Query)만 던질 뿐 실제 통제권과 민감 데이터 원본은 사내 서버가 안전하게 움켜쥐는 '통제된 RAG / 에이전트 아키텍처'를 완벽히 구현할 수 있다.

## Ⅴ. 기대효과 및 결론

- **기대효과**: 개발자들은 수백 개의 커스텀 API를 짜는 삽질에서 해방되고, 세상의 모든 데이터 소스가 플러그 앤 플레이(Plug-and-Play) 방식으로 AI와 연결되는 '에이전틱 이코노미(Agentic Economy)'의 폭발적 확장을 이끈다.
- **향후 발전 방향**: 현재는 로컬 프로세스(STDIO) 통신 위주지만, 점차 클라우드 원격 통신(SSE) 표준이 확립되면서, 글로벌 SaaS 기업들(Salesforce, SAP 등)이 자사 제품에 "우리는 MCP를 기본 지원합니다"라고 선언하는 등 AI 인프라의 새로운 HTTP 같은 척추로 자리 잡고 있다.

### 📌 관련 개념 맵
- **STDIO (Standard Input/Output)**: MCP가 로컬 PC에서 통신할 때 HTTP(인터넷)를 안 쓰고, 터미널의 표준 입출력을 통해 프로세스 간 직접 데이터를 주고받는 방식. 빠르고 보안이 100% 보장된다.
- **JSON-RPC (Remote Procedure Call)**: 클라이언트가 서버의 함수를 마치 내 PC에 있는 함수처럼 원격으로 호출할 때 쓰는 가벼운 통신 규약. MCP의 모든 메시지는 이 포맷으로 날아다닌다.

### 📈 관련 키워드 및 발전 흐름도
`REST API (통합의 파편화)` $\to$ `ChatGPT 플러그인 (생태계 폐쇄성)` $\to$ `Tool Use (도구 호출 개념 정립)` $\to$ `MCP 발표 (Anthropic 주도, 2024.11)` $\to$ `AI 앱 통합 연결의 글로벌 표준화 (진행 중)`

2. AI 비서(클로드, 챗GPT)들도 카카오톡, 구글 드라이브 등과 연결할 때마다 모양이 달라서 개발자들이 밤새워 어댑터(코드)를 깎아야 했어요.
