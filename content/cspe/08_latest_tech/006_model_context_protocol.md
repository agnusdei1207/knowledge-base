# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: **MCP(Model Context Protocol)**는 Anthropic이 공개한 오픈 표준으로, AI 모델(Claude 등)이 외부 데이터 소스 및 도구와 안전하고 균일하게 연결될 수 있도록 설계된 **데이터 인터페이스 프로토콜**이다.
- **필요성**: 기존에는 각 AI 앱마다 도구 연결 방식이 달랐다(N:M 파편화). MCP는 도구와 모델 사이에 표준 규격을 제공하여, 한 번 개발한 도구를 여러 AI 환경에서 즉시 사용할 수 있도록 하는 **"AI 시대의 USB 표준"** 역할을 한다.
- **핵심 직관**: **"에이전트와 도구를 이어주는 유니버설 커넥터"**. 어떤 도구든 MCP 서버로 감싸면, MCP 클라이언트를 사용하는 모든 모델이 그 도구를 즉시 이해하고 사용할 수 있다.

## 깊이 이해
- **배경 (Solving the Interoperability Problem)**: LLM 에이전트 시장이 커지면서 도구 호출(Tool Use) 방식이 파편화되었다. 개발자는 같은 API를 OpenAI용, Anthropic용, LangChain용으로 따로 맞춰야 했다. Anthropic은 이를 해결하기 위해 개방형 표준인 MCP를 제안했다.
- **작동 원리 (The Architecture)**:
    - **MCP Host**: 사용자가 모델과 상호작용하는 앱 (예: Claude Desktop, IDE).
    - **MCP Client**: Host 앱 내에서 프로토콜 통신을 담당하는 계층.
    - **MCP Server**: 실제 데이터(DB)나 도구(API)를 노출하는 경량 프로그램.
    - **통신**: JSON-RPC 기반으로 리소스(Resources), 도구(Tools), 프롬프트(Prompts)를 주고받는다.
- **비유**: 예전에는 핸드폰마다 충전기 모양이 달라 전용 케이블을 챙겨야 했지만(파편화), 이제는 **USB-C(MCP)** 하나로 모든 기기를 충전하고 데이터도 주고받는 것과 같다.
- **구체 예시**: Google Drive용 MCP 서버를 띄우면, Claude Desktop(Host)이 즉시 내 드라이브 파일을 읽고 요약해줄 수 있다.
- **주의점**: MCP는 모델 자체가 아니라 모델과 도구를 잇는 **통신 규약**이다. 실제 도구의 실행 권한과 보안 책임은 MCP 서버를 구동하는 주체에게 있다.

## 연결 개념
- **MCP Server (007)**: 실제 기능을 제공하는 서버 측 구현체.
- **Tool Use (004)**: MCP가 표준화하고자 하는 상위 기술 도메인.
- **JSON-RPC**: MCP의 기반이 되는 가벼운 원격 프로시저 호출 프로토콜.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: AI 애플리케이션과 외부 데이터/도구 간의 상호운용성을 보장하는 **개방형 표준 연결 프로토콜**.
> 2. **가치**: 도구 개발의 중복 투자를 방지하고, 모델 교체 시에도 기존 도구 인프라를 그대로 유지할 수 있는 **추상화 계층** 제공.
> 3. **판단 포인트**: 'Resource', 'Tool', 'Prompt'라는 3대 핵심 요소를 통해 단순 기능 호출을 넘어 **컨텍스트 공유**까지 표준화함.

## 출제 의도 및 답안 포인트
- **출제 의도**: 최신 AI 에이전트 생태계의 표준화 동향과 MCP의 아키텍처적 우수성 이해 여부.
- **핵심 포인트**: Host-Client-Server 구조, JSON-RPC, 데이터 추상화, 상호운용성.

---

## Ⅰ. MCP(Model Context Protocol)의 등장 배경 및 정의
### 1. 등장 배경: 도구 생태계의 파편화
- 각 모델 제공자별 상이한 도구 명세 규격으로 인한 개발 중복 발생.
- 보안 및 권한 관리가 파편화되어 기업 내부 데이터의 안전한 연결이 어려움.
- 컨텍스트(Context) 주입 방식이 표준화되지 않아 모델별 답변 일관성 부족.
### 2. MCP의 정의
- AI 모델이 로컬/원격 데이터 소스 및 도구와 안전하고 쉽게 통합되도록 지원하는 **JSON-RPC 기반 오픈 표준 프로토콜**.

---

## Ⅱ. MCP의 핵심 아키텍처 및 구성 요소
- **3계층 구조: Host - Client - Server**
```text
┌────────────────┐          ┌────────────────┐          ┌────────────────┐
│    MCP Host    │          │   MCP Client   │          │   MCP Server   │
│ (Claude, IDE)  │ <──────> │ (Protocol Lyr) │ <──────> │ (Data/Tools)   │
└────────────────┘          └────────────────┘          └────────────────┘
```

| 구성 요소 | 역할 및 설명 |
|:---:|:---|
| **MCP Host** | 사용자가 상호작용하는 최종 앱. 여러 클라이언트를 관리하고 사용자 승인을 중계. |
| **MCP Client** | Host 내부에서 서버와 통신하며, 모델에게 도구 목록과 리소스를 전달하는 인터페이스. |
| **MCP Server** | 실제 로컬 파일, DB, 외부 API 등을 MCP 규격에 맞춰 노출하는 독립적 서버. |

---

## Ⅲ. MCP의 3대 핵심 기능 요소 (Capabilities)

| 구분 | 명칭 | 상세 설명 |
|:---:|:---:|:---|
| **데이터 제공** | **Resources** | 모델이 읽을 수 있는 읽기 전용 데이터 (파일, 로그, DB 레코드 등). |
| **행동 수행** | **Tools** | 모델이 직접 실행할 수 있는 기능 (코드 실행기, API 호출, 파일 쓰기 등). |
| **워크플로우** | **Prompts** | 특정 과업 수행을 위해 서버가 제공하는 재사용 가능한 프롬프트 템플릿. |

---

## Ⅳ. MCP의 기술적 특징 및 장점
- **JSON-RPC 기반**: 가볍고 확장성이 뛰어나며, 다양한 프로그래밍 언어(TypeScript, Python 등)로 구현 가능.
- **Local/Remote 지원**: 내 컴퓨터의 로컬 파일시스템 연결부터 클라우드 DB 연결까지 투명하게 지원.
- **보안 격리**: 모델은 서버의 내부 로직을 알 필요 없이 정의된 인터페이스만 사용하며, 서버 단에서 세밀한 권한 통제 가능.
- **상호운용성 (N:M 해소)**: 어떤 MCP 서버든 MCP 호환 클라이언트와 즉시 연결되는 플러그앤플레이(Plug-and-Play) 환경 제공.

---

## Ⅴ. 기존 도구 연동 방식 vs MCP 비교

| 비교 항목 | 기존 연동 방식 (Custom API) | MCP 표준 연동 방식 |
|:---:|:---|:---|
| **연결성** | 특정 프레임워크/모델에 종속적 | 모든 MCP 호환 환경과 즉시 연결 |
| **개발 비용** | 타겟 플랫폼마다 재개발 필요 | 한 번의 개발로 다수 호환 환경 대응 |
| **컨텍스트 공유** | 단순히 텍스트/JSON만 전달 | 리소스, 도구, 템플릿을 통합 제공 |
| **관리 주체** | 앱 로직 내부에 밀결합 | 독립적인 서버로 관리 및 배포 가능 |

---

## Ⅵ. 향후 전망 및 기술사 제언
- **에이전트 인프라의 핵심**: MCP는 개별 에이전트 개발을 넘어 **"전사적 AI 데이터 메쉬"** 구축의 표준이 될 것임.
- **기술사 의견**: 단순한 기술 표준을 넘어 AI 에이전트 간의 통신(Agent-to-Agent)까지 확장될 가능성이 크므로, 기업은 내부 데이터 자산의 MCP화를 선제적으로 검토해야 함.
