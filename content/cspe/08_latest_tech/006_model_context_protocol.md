# 📖 【암기용】 개념 완전 이해

> 목적: MCP를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **정의**: LLM 애플리케이션과 외부 도구·데이터를 연결하는 표준 프로토콜
- **왜 필요한가**: AI 에이전트마다 API 연결을 따로 만들면 권한·감사·도구 설명이 파편화됨.
- **핵심 직관**: MCP는 AI 앱의 USB-C처럼 모델과 업무 시스템 사이의 공통 연결 규격임.

## 깊이 이해
- **배경·문제의식**: RAG·Tool Use·Agent가 확산되면서 파일, DB, SaaS, 코드 저장소 연결 방식이 제품별로 달라짐.
- **작동 원리**: MCP Client가 MCP Server와 연결하고, Server가 Tool·Resource·Prompt를 표준 메시지로 노출함.
- **비유**: 노트북이 프린터마다 드라이버를 새로 만들지 않고 표준 인터페이스로 장치를 인식하는 구조.
- **구체 예시**: IDE 에이전트가 Git MCP Server를 통해 이슈 조회, 브랜치 상태, 파일 변경 내용을 표준 방식으로 가져옴.
- **흔한 오해·주의점**: MCP는 권한정책 자체가 아니라 연결 규약이므로 인증·인가·감사는 별도 보안 설계가 필요함.

## 연결 개념
- Tool Use — MCP Tool로 표준화되는 실행 단위
- AI 에이전트 — MCP Client를 통해 외부 기능 사용
- Zero Trust — MCP 연결의 인증·인가 기준

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: MCP는 LLM 애플리케이션이 외부 도구·리소스·프롬프트를 표준 메시지로 사용하는 연결 프로토콜임.
> 2. **가치**: 에이전트별 맞춤 연동을 MCP Server 단위로 표준화해 재사용성과 감사 가능성을 확보함.
> 3. **판단 포인트**: 프로토콜 도입보다 서버 신뢰, 권한 범위, 민감정보 마스킹, 호출 로그 설계가 우선임.

---

## Ⅰ. 개요 및 필요성

MCP는 모델-도구 연결 표준임. AI 에이전트가 파일·DB·SaaS·개발도구를 호출하려면 표준화된 연결, 권한 경계, 관측성이 필요함.

---

## Ⅱ. 구조 및 구성요소

```text
LLM App ─ MCP Client ─ MCP Server ─┬─ Tools
                                   ├─ Resources
                                   └─ Prompts
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| MCP Client | LLM 앱 내부 연결 주체 | 사용자 세션·권한 전달 |
| MCP Server | 도구·자원 노출 지점 | 신뢰 경계, 감사로그 |
| Tool | 실행 가능한 함수 | 입력 스키마·권한 필요 |
| Resource | 읽기 가능한 데이터 | URI, MIME, 접근제어 |

> 요약: MCP는 Client-Server 구조로 도구, 리소스, 프롬프트를 표준 인터페이스로 노출함.

---

## Ⅲ. 동작원리 및 흐름도

```text
서버 등록 → 기능 발견 → 권한 확인 → Tool/Resource 호출
        → 결과 반환 → 모델 컨텍스트 반영 → 로그 저장
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | MCP Server 연결·기능 발견 | 서버 식별자, 기능 목록 |
| 2 | 사용자 권한·정책 확인 | OAuth, RBAC, allowlist |
| 3 | 도구·자원 호출 | 스키마 검증, 응답코드 |
| 4 | 결과 반영·감사 | Trace ID, 민감정보 제거 |

> 요약: MCP 호출은 기능 발견 후 권한과 스키마 검증을 거쳐 모델 컨텍스트에 반영됨.

---

## Ⅳ. 특징

| 구분 | 개별 API 연동 | MCP | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 연동 방식 | 앱별 커넥터 | 표준 Client-Server | 커넥터 수, 재사용률 |
| 도구 발견 | 수동 설정 | 서버 기능 목록 제공 | 도구 설명 품질 |
| 통제 | 앱마다 상이 | 서버 단위 정책 적용 | RBAC, 로그 보존 |

> 요약: MCP는 연동 표준화를 제공하지만, 보안 통제는 MCP Server 운영정책에 의존함.

---

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. MCP Server별 권한 범위를 읽기·쓰기·관리로 분리하고 고위험 Tool은 승인 절차 적용
2. Resource 응답에 개인정보·비밀키 패턴 마스킹을 적용하고 결과 크기와 TTL 제한
3. 서버명, 도구명, 사용자ID, 입력 해시, 응답코드, 비용을 Trace ID로 수집

**결론 (2줄):**
- 기술사 판단: MCP는 AI 연동 표준으로 채택하되 서버 신뢰성과 권한경계를 먼저 검증해야 함.
- 향후 방향: MCP는 에이전트 생태계의 도구 연결 계층으로 확산되고, 보안 게이트웨이와 결합됨.

|:---|:---|:---|:---|

| 요구사항 명시형 | 설계하시오, 보안대책을 제시하시오 | 인증·권한·감사 흐름 | 서버 신뢰·데이터 유출 통제 |
