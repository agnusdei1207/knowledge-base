# 📖 【암기용】 개념 완전 이해

> 목적: Edge AI를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: 데이터가 발생하는 현장 가까운 엣지 장비에서 AI 추론·분석을 수행하는 아키텍처
- **왜 필요한가**: 공장·매장·차량·기지국 데이터는 지연·대역폭·보안 요구 때문에 모두 클라우드로 보낼 수 없음.
- **핵심 직관**: 중앙 본사가 아니라 현장 지점 서버가 CCTV·센서 데이터를 즉시 판단하는 구조임.

## 깊이 이해
- **배경·문제의식**: 영상·센서 데이터는 초당 수MB~수GB가 발생하고, 클라우드 전송은 회선 비용과 지연을 만든다. 산업 제어는 수십ms 수준 응답이 필요함.
- **작동 원리**: 카메라·센서 입력을 엣지 게이트웨이·산업용 PC·MEC 서버에서 전처리하고 AI 추론을 수행함. 이벤트·요약·이상치만 클라우드로 전송해 학습·관제에 활용함.
- **비유**: 전국 매장의 CCTV를 본사로 모두 보내지 않고, 매장 내 장비가 도난·혼잡 이벤트만 본사에 알리는 방식임.
- **구체 예시**: 제조 불량 검사는 카메라 프레임을 엣지 GPU에서 30 FPS로 분석하고, 불량 이벤트와 이미지만 중앙에 저장함.
- **흔한 오해·주의점**: Edge AI는 단말 하나만 의미하지 않음. 단말, 게이트웨이, 현장 서버, 클라우드가 계층적으로 협력함.

## 연결 개념
- On-Device AI — 단말 내부 추론
- MEC — 통신망 엣지 컴퓨팅
- MLOps — 엣지 모델 배포·모니터링

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Edge AI는 데이터 발생 지점 근처에서 AI 추론을 수행해 지연·대역폭·데이터 반출을 줄이는 구조임.
> 2. **가치**: 실시간 제어와 현장 자율성을 확보하고 클라우드 전송 비용을 절감함.
> 3. **판단 포인트**: 엣지 위치, 모델 배포, 네트워크 단절 대응, 중앙 MLOps 연계를 함께 설계해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 엣지-클라우드 분담 구조 이해 확인 | 현장 추론+중앙 학습·관제 폐루프, event filtering | 온디바이스 AI와 개념 혼동(엣지는 게이트웨이·현장 서버 포함) |
| 실시간 제어 요건 판단 확인 | 산업 제어 10~50ms, 오프라인 동작, 대역폭 80%+ 절감 | 지연 수치 근거 없이 "빠르다" 서술 |
| 분산 운영 역량 확인 | OTA 배포, 모델 drift, 장비 health 중앙 관제 | 배포 후 운영·drift 관리 누락 |

> 요약: 이 문제는 엣지 장비 소개가 아니라 현장 추론과 중앙 MLOps의 폐루프 운영 설계를 묻는다.

## Ⅰ. 개요 및 필요성

- 개요: 현장 인접 AI 처리 아키텍처
- 배경: 영상·센서·산업 데이터는 원본을 모두 클라우드로 전송하면 지연, 회선 비용, 개인정보 노출이 증가함.
- 필요성: Edge gateway, TensorRT·OpenVINO, event filtering으로 현장 추론 지연과 uplink bandwidth 사용량을 통제해야 함.

## Ⅱ. 구조 및 구성요소

```text
Sensors/Cameras -> Edge Gateway/IPC -> AI Inference
      -> Event Filter -> Local Action + Cloud Sync
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Edge Device | 센서·카메라 데이터 수집 | 현장 설치 |
| Edge Runtime | 모델 추론·전처리 | ONNX, TensorRT, OpenVINO |
| Event Filter | 이상치·요약 데이터 선별 | bandwidth 절감 |
| Cloud Control | 모델 배포·학습·관제 | MLOps, OTA |

> 요약: Edge AI는 현장 추론과 중앙 학습·관제를 분리해 실시간성과 운영 통제를 동시에 확보함.

## Ⅲ. 동작원리 및 흐름도

```text
데이터 수집 -> 엣지 전처리 -> AI 추론 -> 이벤트 판단
    -> 현장 조치 -> 메타데이터 클라우드 동기화 -> 모델 업데이트
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 영상·센서 데이터 수집 | FPS, sampling rate |
| 2 | 엣지 전처리·추론 | p95 latency, GPU util |
| 3 | 이벤트 필터링·현장 제어 | false positive/negative |
| 4 | 클라우드 동기화·재배포 | OTA 성공률, drift |

> 요약: 엣지는 즉시 판단·조치하고 클라우드는 장기 학습·배포·관제를 담당하는 폐루프 구조임.

## Ⅳ. 특징

| 구분 | Cloud AI | Edge AI | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 지연 | WAN 왕복 지연 | 현장 처리 | 산업 제어 10~50ms |
| 대역폭 | 원천 데이터 전송 | 이벤트만 전송 | 영상 트래픽 80%+ 절감 |
| 가용성 | 회선 의존 | 오프라인 동작 가능 | store-and-forward |
| 운영 | 중앙 집중 | 분산 장비 관리 | OTA·관측성 필수 |

> 요약: Edge AI는 지연·대역폭·오프라인 요구에 적합하나, 분산 장비 운영과 모델 drift 관리가 핵심 리스크임.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | On-Device AI | Edge AI | Cloud AI | 선택 기준 |
|:---|:---|:---|:---|:---|
| 처리 위치 | 개인 단말 내부 | 현장 게이트웨이·서버 | 중앙 데이터센터 | 데이터 발생-판단 거리 |
| 지연 | 수십 ms | 10~50ms (LAN) | WAN 왕복 100ms+ | 제어 루프 요구 시간 |
| 적합 대상 | 개인 프라이버시 기능 | 다수 센서 집계·산업 제어 | 대규모 학습·분석 | 집계 범위와 연산 규모 |

> 요약: 단말 1대는 온디바이스, 현장 다수 장비 집계·제어는 엣지, 전사 학습·분석은 클라우드로 분담함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 모델 drift | 현장 데이터 분포 변화 | 중앙 재학습·주기 재배포 폐루프 | 정확도 추이, drift 경보 |
| 분산 장비 장애 | 수백 대 엣지 노드 관리 | 중앙 관제, health check, 원격 복구 | 장비 가동률, MTTR |
| OTA 실패 | 회선 불안정·버전 충돌 | 단계적 롤아웃, 자동 롤백 | OTA 성공률 99% 이상 |

> 요약: 엣지 리스크는 drift와 분산 운영이며, 중앙 MLOps 폐루프와 단계적 배포로 통제함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 제조 검사 라인에 엣지 GPU를 배치해 30 FPS 추론, 불량 이벤트만 중앙 저장해 회선 비용 절감
2. 매장 분석은 개인 얼굴 원본을 저장하지 않고 엣지에서 익명 카운트·혼잡도만 전송
3. 엣지 MLOps로 모델 버전, drift, OTA 실패율, 장비 health를 중앙 대시보드에서 관리

**결론 (2줄):**
- 기술사 판단: 50ms 이하 실시간·대용량 영상·오프라인 요구는 Edge AI, 장기 분석·학습은 Cloud AI를 선택함.
- 향후 방향: Edge AI는 5G MEC, SLM, NPU와 결합해 현장 자율 시스템으로 확장됨.
