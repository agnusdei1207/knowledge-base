## 미리 알고가기

- 엣지 AI ($Edge$ $AI$): 데이터가 태동하는 공장 생산 라인, 매장, 도로변 등의 현장 가동 장비나 로컬 게이트웨이 컴퓨터단에서 실시간 딥러닝 추론을 집행하는 분산형 아키텍처임
- 엣지 게이트웨이 ($Gateway$): 복수의 하위 센서 노드들로부터 원시 신호를 취합하여 1차 데이터 정제 및 추론을 전담하는 중간 기지 서버 장치임
- 평균 복구 시간 ($MTTR$): 시스템이나 장비 고장 발생 시점부터 수리 및 조치를 완료하여 정상 가동 상태로 복귀하기까지 걸리는 평균 시간임
- 지연 임계치 ($Latency$ $Budget$): 스마트 팩토리나 자율주행 교통망 등 초실시간 제어가 필수적인 비즈니스 요건 상 최대로 허용 가능한 밀리초 단위 시간의 벽임

## Ⅰ. 개요

- **정의/개념**: 엣지 AI는 가동 현장 곳곳에 배치된 카메라, IoT 센서, 물리 게이트웨이, 통신 기지국 등 데이터를 뿜어내는 원천 주변에 경량 가속 컴퓨팅 칩셋을 내장하여, 중앙 데이터센터로의 장거리 네트워크 왕복 없이 현장에서 데이터를 직접 흡수하고 즉시 의사결정을 실시간 집행하는 분산 처리 기법임
- **배경/필요성**: 수천 대의 CCTV 고화질 영상이나 진동 센서 데이터를 실시간 클라우드로 전송하면 통신 비용이 감당 불가능해지고 백홀 대역폭이 마비되며, 네트워크 단절 시 공장 라인 전체가 올스톱되는 치명적인 중앙 집중화 리스크를 방지하고자 탄생함

## Ⅱ. 특징

- 물리적으로 생성 지점 바로 옆에서 연산이 이루어지므로 전송 지연이 극도로 짧아, 이상 고압 차단기 경보 등 초고속 제어에 절대적 생존성을 보장함
- 현장에서 가벼운 연산은 엣지 단에서 처리하고 이상 징후 등 요약 정보만을 선별 동기화하므로, 외부망 통신 회선 요금을 대폭 절감함
- 다수의 파편화된 기기들이 거친 실외 공장 현장에 노출되므로, 원격 기기 관리 및 무선 펌웨어 배포($OTA$, Over-the-Air)의 안정적인 수립이 중요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 클라우드 AI (Cloud) | 온디바이스 AI (On-Device) | 엣지 AI (Edge) |
|:---|:---|:---|:---|
| **설치 및 운영 주체** | 원격 클라우드 사업자 (CSP) | 일반 개인 모바일 기기 사용자 | 산업 현장 관리자, 인프라 운영팀 |
| **자원 수급 유연성** | 극도로 자유로움 (무한 자원) | 극단적으로 타이트함 (극소 전력/발열) | 보통 (소형 산업용 PC, 게이트웨이 급) |
| **도입 목적** | 대용량 지식 비교, 백업 데이터 분석 | 개인 일정 맞춤, 기기 잠금, 사생활 보안 | 공장 공정 이상 탐지, 자율 교통망 제어 |
| **운영 실패 영향** | 네트워크 단절 시 서비스 마비 | 기기 사용자에 한정된 오류 발생 | 공장 중단 등 큰 물리 비즈니스 손해 유발 |

> 요약: 클라우드는 무제한 분석에, 온디바이스는 개인 사생활과 초경량 활용에, 엣지는 산업 설비의 현장 강건성과 실시간 안정적 제어에 최적임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 데이터 원천 노드 | 현장 상태를 디지털 신호(영상, 주파수 등)로 측정해 뿜어내는 하위 센서 및 CCTV임 |
| 엣지 가속 서버 | NPU, TPU, 임베디드 GPU 칩셋을 내장해 현장에서 텐서 곱셈을 전담하는 가속 기기임 |
| 제어 액추에이터 | 엣지 판단 결과를 인계받아 경보등을 켜거나 밸브를 긴급 폐쇄하는 물리 동작 제어부임 |
| 클라우드 플레인 | 모든 현장 엣지 기기의 컨테이너 헬스체크와 새 모델 펌웨어를 무선 통제하는 통합 대시보드임 |

```text
[ Edge AI (엣지 AI) 물리 토폴로지 ]
[Sensors / CCTVs] ---> [Edge Gateway Server (Local Inference)] ---> [Physical Actuators / Alarms]
                             | (Sync Summarized Logs Only)
                             v
                    [Cloud Control Plane]
- 현장에서 즉시 판단 및 실행하고, 꼭 필요한 요약 통계 정보만 백엔드 클라우드로 압축 동기화함
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 센서 원천   | --> | 엣지전처리 및| --> | 가속칩 추론 | --> | 액추에이터  |
| 데이터 추출 |     | 프레임 슬라이|     | 및 이상감지 |     | 즉각 물리제어|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **로그 축적** — 교통 카메라나 공장의 로봇 팔 센서 인터페이스로부터 미가공 데이터를 밀리초 단위로 수집함
2. **프레임 압축** — 노이즈가 섞인 데이터를 필터링하고 추론 가용 영역($ROI$)만을 오려내어 전송 데이터 밀도를 조절함
3. **가속 칩 추론** — 온프레미스 에지 가속기(예: Edge TPU, Jetson 등)를 구동하여 1차 불량품 판정 및 충돌 위험도를 연산함
4. **차단 및 알림** — 위험 임계치를 넘는 스코어가 감지되면 상위 서버 보고를 건너뛰고 설비를 긴급 제동($Action$)한 후 요약을 전송함

## Ⅵ. 실무 적용 및 유의점

1. 기후와 계절에 따라 조도가 계속 바뀌는 야외 도로 공장 환경에서는 현장 엣지 카메라의 이미지 입력 분포가 달라져 오판율이 급격히 늘어나므로, 반드시 현장별 예측 편차 모니터링을 걸고 오작동 경보율($False$ $Alarm$ $Rate$) 지표를 상시 수집해 주기적 엣지 재학습을 적용해야 함
2. 현장에 분산 배치된 기기들의 수가 수백 대 이상으로 팽창하면 OS 패치와 모델 업데이트 수작업이 불가능해져 보안 취약점이 되므로, 도커 기반의 쿠버네티스 에지 런타임(K3s 등)을 탑재하고 평균 복구 시간($MTTR$) 지표로 관리 가용성을 보증해야 함

## Ⅶ. 결론

- 엣지 AI는 산업 인프라의 시간적 생존성과 가용한 네트워크 회선 비용을 획기적으로 개선하는 똑똑한 분산 지형망이며, 설계자는 거친 실외 환경에 대응할 정교한 현장별 모니터링 경보 제어와 다수 장비를 원격 통제할 수 있는 컨테이너 기반 에지 생명주기 관리 체계를 완비해야 함
