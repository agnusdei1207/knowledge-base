# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: AI 모델이 학습하는 훈련 데이터(Training Data) 세트에 해커가 교묘하게 **'쓰레기 데이터', '틀린 라벨', '편향된 정보'를 몰래 섞어 넣어(독극물 주입)**, AI가 바보가 되거나 해커가 원하는 대로 오동작하게 만드는 공급망 공격.
- **필요성**: "Garbage In, Garbage Out(쓰레기가 들어가면 쓰레기가 나온다)". 요즘 AI는 수억 개의 웹 크롤링 데이터나 오픈소스 데이터셋(Hugging Face 등)을 긁어모아 학습함. 이 거대한 데이터 호수에 해커가 독을 몇 방울 타 놓으면, 모델 자체의 근본적인 판단 능력이 영구적으로 훼손됨. 이를 걸러내는 체계가 필수적임.
- **핵심 직관**: 교과서 낙서하기. 수능(실전 배치)을 준비하는 학생(AI)의 교과서(학습 데이터)에 악당(해커)이 몰래 들어가 "1+1=3"이라고 정답을 고쳐 놓음. 학생은 아무 의심 없이 "1+1=3"이라고 외워서 시험장에 가고, 결국 중요한 순간에 치명적인 오답을 내게 됨.

## 깊이 이해
- **배경**: 과거에는 회사 내부 데이터만 썼지만, 생성형 AI 시대에는 위키피디아, 레딧, 트위터, 심지어 사용자가 피드백하는 채팅 내역까지 실시간으로 학습 파이프라인에 들어감(온라인 학습). 공격자가 접근할 수 있는 '공격 표면(Attack Surface)'이 데이터 수집 단계로 무한히 넓어짐.
- **작동 원리 (데이터 오염의 두 가지 목적)**:
  1. **가용성 타격 (Availability Attack)**: 데이터에 무작위 노이즈나 엉터리 라벨(개 사진에 '자동차' 라벨)을 대량으로 주입하여, 모델 전체의 정확도(Accuracy)를 뚝 떨어뜨려 아예 서비스를 못 쓰게 만듦 (모델 파괴).
  2. **무결성 타격 (Integrity / Targeted Attack)**: 전체적인 성능은 정상처럼 유지하되, **특정 타겟**에 대해서만 오동작하게 만듦. (예: 스팸 필터 데이터에 특정 해커의 도메인이 들어간 스팸 메일을 계속 '정상(Ham)'이라고 라벨링해 넣어서, 그 해커의 메일만 프리패스하게 만듦).
- **구체 예시**: 마이크로소프트의 챗봇 '테이(Tay)'. 트위터 사용자들과 대화하며 실시간으로 학습(Online Learning)하도록 설계됨. 익명의 악의적 유저들이 합심하여 테이에게 인종차별, 나치 찬양 발언을 집중적으로 주입함(오염 공격). 테이는 이것이 올바른 인간의 언어인 줄 알고 학습해버려, 출시 16시간 만에 인종차별 발언을 쏟아내며 강제 종료됨.
- **흔한 오해/주의점**: "적대적 예제(Adversarial Example)랑 같은 거 아님?" $\rightarrow$ 아님. **적대적 예제**는 이미 잘 훈련된 AI에게 '테스트할 때(추론 시)' 속임수 사진을 보여주는 것이고, **데이터 오염**은 AI가 학교에 다닐 때 '학습 단계'에서 교과서를 조작하는 근본적인 공격임.

## 연결 개념
- **Backdoor Attack (백도어 공격)**: 데이터 오염을 통해 달성하는 가장 치명적인 타겟 공격. 오염된 데이터를 넣어 AI에 숨겨진 트리거(비밀 스위치)를 심는 것.
- **Data Provenance (데이터 계보/출처 관리)**: 데이터 오염을 막기 위한 방패. "이 데이터가 언제, 어디서, 누구에 의해 수집/수정되었는지" 추적하는 체계.
- **AI Supply Chain Security (AI 공급망 보안)**: 오염된 오픈소스 데이터셋이나 사전 학습된 모델을 가져다 쓸 때 발생하는 위협을 통제하는 거버넌스.

# 📝 【답안용】 시험 답안 템플릿
## 핵심 인사이트 (3줄 요약)
- **본질**: 기계학습(ML) 파이프라인의 가장 초기 단계인 데이터 수집 및 전처리 단계(Training Phase)에서, 공격자가 악의적으로 조작된 입력(Poisoned Samples)이나 잘못된 라벨(Mislabeled Data)을 주입하여 모델의 결정 경계(Decision Boundary)를 영구적으로 왜곡하는 공격.
- **가치**: 모델 구축이 완료된 후에는 오염된 파라미터를 선별적으로 치료하기가 사실상 불가능하며(Unlearning의 한계), 딥러닝 모델의 근본적인 지식 기반을 부패시키므로 모델 자체를 폐기하고 처음부터 재학습(Retraining)해야 하는 막대한 매몰 비용이 발생함.
- **판단 포인트**: 데이터 오염 공격은 주로 MLOps의 데이터 인제스천(Ingestion) 구간이나 사용자 피드백 루프(RLHF)를 통해 침투하므로, 통계적 이상치 탐지(Outlier Detection) 및 데이터 출처 무결성(Data Provenance) 관리를 결합한 데이터 검증 게이트(Validation Gate) 구축이 방어의 핵심임.

## Ⅰ. 개요 및 필요성
- **정의**: 타겟 AI 모델의 예측 정확도를 낮추거나 특정 조건에서 의도된 오분류를 유발할 목적으로, 훈련 데이터셋(Training Dataset)의 분포(Distribution)나 라벨(Label)을 의도적으로 변조하는 훈련 단계(Train-time) 공격 기법.
- **배경**: 최신 파운데이션 모델(LLM 등)은 방대한 크롤링 데이터 및 서드파티 제공 데이터, 크라우드 소싱 기반 라벨링에 전적으로 의존하므로, 제어 불가능한 외부 데이터 소스가 단일 장애점(SPoF)이자 공격 벡터가 됨.
- **필요성**: 데이터 오염으로 인한 편향 증폭(Bias Amplification), 보안 필터 무력화 사고를 방지하고, "AI의 성능은 곧 데이터의 품질"이라는 본질적 무결성을 수호하기 위함.

## Ⅱ. 데이터 오염 공격의 2대 전략 모델
공격자의 타겟팅 범위에 따른 분류.
| 공격 목적 (Strategy) | 공격 방식 (Mechanism) | 위협 사례 및 징후 |
|:---:|:---|:---|
| **가용성 공격**<br>(Availability / Untargeted) | 데이터셋 전반에 무작위 라벨 플리핑(Label Flipping)이나 노이즈를 살포하여, 모델의 전체적인 정확도(Global Accuracy)를 하락시킴. | 악성코드 탐지 AI의 탐지율 전체가 하락하여 사용 불가 상태로 만듦. (주로 경쟁사 테러). |
| **무결성 공격**<br>(Integrity / Targeted) | 모델의 전반적 성능은 정상으로 유지하면서, 특정 타겟(Target Class)에 대해서만 공격자가 원하는 결과를 내도록 결정 경계를 뾰족하게 조작. | 백도어(Backdoor) 삽입. 안면 인식 시스템이 해커의 얼굴을 특정 관리자로 오인증하게 만듦. |

## Ⅲ. 주요 오염 주입 벡터 (Injection Vectors)
해커는 어디에 독을 타는가.
1. **웹 크롤링 오염 (Data Set Poisoning)**:
   - 오픈소스 데이터셋(예: Wikipedia, ImageNet 등)이나 만료된 인터넷 도메인을 해커가 선점한 뒤, 크롤러봇이 수집해갈 악성 콘텐츠를 대량으로 호스팅함.
2. **크라우드 소싱 라벨링 조작 (Malicious Annotators)**:
   - 아마존 메커니컬 터크(MTurk)나 데이터 라벨링 하청 업체의 작업자로 위장 취업하여 의도적으로 잘못된 라벨(오답)을 지속적으로 기입.
3. **피드백 루프 악용 (Feedback Loop Poisoning)**:
   - 실시간 자가 학습(Online Learning) 시스템의 '사용자 신고(Report)'나 '추천/비추천' 버튼을 매크로 봇으로 조작하여 모델을 나쁜 방향으로 편향시킴.

## Ⅳ. 데이터 오염 방어를 위한 데이터 중심 보안(Data-centric Security) 아키텍처
쓰레기 반입을 원천 차단하는 정수기 필터 설계.
1. **데이터 프로버넌스 (Data Provenance & Lineage)**:
   - 수집된 모든 데이터 배치의 해시(Hash)값, 수집 출처, 가공 시간, 라벨러 ID 등을 블록체인이나 메타데이터 저장소에 서명하여 기록(Tracking).
   - 오염 발견 시 해당 출처의 데이터만 골라내어 신속히 폐기(Unlearning).
2. **통계적 이상치 탐지 (Anomaly & Outlier Detection)**:
   - 모델 학습 전, 주성분 분석(PCA)이나 클러스터링(DBSCAN)을 통해 다른 정상 데이터들과 거리(Feature Space)가 멀거나 이질적인 특징을 가진 샘플(Poison Candidate)을 자동 격리.
3. **견고한 학습 및 앙상블 (Robust Training)**:
   - 학습 알고리즘 자체를 오염 데이터에 둔감하게 만듦.
   - 예: 미니 배치(Mini-batch) 훈련 시 오차가 지나치게 큰 샘플은 가중치 업데이트에서 배제(Trimmed Loss)하거나, 여러 모델을 앙상블하여 투표(Majority Voting) 처리.

## Ⅴ. 실무 적용 및 결론
- **판단 지표**: 학습 파이프라인의 검증 손실(Validation Loss) 급상승 탐지율, 데이터 클렌징(Data Cleansing) 필터에서 걸러진 이상 샘플의 비율, 데이터 제공자 신뢰 스코어(Trust Score).
- **실무 설계**: e커머스 기업의 실시간 '사용자 리뷰 기반 상품 추천 AI' 구축. 해커(경쟁사)가 봇을 이용해 자사 상품에는 긍정 키워드를, 타사 상품에는 악의적 편향 키워드를 수만 건 주입(피드백 오염 공격 시도). 조치 방안: 1) 온라인 학습(Real-time Training) 방식을 폐기하고, 배치 기반 재학습(Batch Retraining)으로 전환. 2) 학습 데이터 파이프라인 앞단에 '이상치 스크러빙(Scrubbing) 게이트' 배치하여, 동일 IP나 동일 패턴에서 단기간에 급증한 키워드는 격리(Quarantine). 3) 사람이 직접 샘플링 검수(Human-in-the-loop)한 골든 데이터셋(Golden Dataset)으로 주기적 성능 벤치마크 테스트. 오염 공격 100% 방어.
- **결론**: 데이터 오염 공격은 AI 모델을 해킹하는 것이 아니라 AI의 '경험과 기억' 자체를 세뇌(Brainwash)시키는 가장 본질적인 인지적 테러다. 결국 보안의 패러다임은 인프라와 코드를 지키는 것에서 벗어나, "이 데이터가 어디서 왔고, 누가 만졌는가"를 증명하는 제로 트러스트 기반의 데이터 공급망 무결성(Data Supply Chain Integrity) 확보로 귀결되어야 한다.

### 🔀 문제 유형별 목차 전환
- **Ⅱ·Ⅲ 강조 (개념/원리형)**: 데이터 오염과 적대적 예제(Adversarial Example)를 훈련 시점(Train-time)과 추론 시점(Test-time)의 위협 스코프로 비교 대조하고, Clean-label Poisoning(원본 이미지는 그대로 두고 라벨만 속이는 공격)의 은닉 메커니즘.
- **Ⅴ·Ⅵ 강조 (실무/설계형)**: 오염된 데이터가 이미 학습되어 버린 사후 상황에서, 모델 전체를 처음부터 재학습시키는 막대한 비용을 회피하기 위해 오염된 특정 데이터 포인트의 영향력만 계산(Influence Function)하여 가중치에서 덜어내는 '기계 비학습(Machine Unlearning)' 파이프라인 설계.
