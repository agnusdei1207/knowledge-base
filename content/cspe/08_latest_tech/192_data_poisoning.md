# 📖 【암기용】 개념 완전 이해

> 목적: Data Poisoning을 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: 학습 데이터에 악성·오류·편향 샘플을 주입해 모델 성능, 판단, 안전성을 의도적으로 왜곡하는 공격
- **왜 필요한가**: AI 품질은 데이터에 의존하므로 데이터 수집·라벨링·외부 데이터 공급망이 공격면이 됨.
- **핵심 직관**: 모델이 배울 교재에 일부러 틀린 답과 편향된 예제를 섞어 넣는 공격임.

## 깊이 이해
- **배경·문제의식**: 웹 크롤링, 사용자 피드백, 공개 데이터셋, 합성 데이터가 학습에 들어가면서 데이터 출처 검증이 어려워짐.
- **작동 원리**: 공격자는 라벨 오류, 트리거 샘플, 편향 샘플, 악성 문서를 주입해 모델의 전체 성능 저하나 특정 입력 오동작을 유도함.
- **비유**: 시험 대비 문제집에 특정 단원만 틀린 해설을 반복 삽입해 학생이 그 단원을 잘못 외우게 만드는 행위임.
- **구체 예시**: 스팸 필터 학습 데이터에 정상처럼 보이는 스팸 메일을 반복 등록해 특정 캠페인 탐지율을 20%p 낮춤.
- **흔한 오해·주의점**: 데이터 오염은 학습 전에만 발생하지 않는다. 온라인 학습, 피드백 루프, RAG 지식베이스에서도 발생함.

## 연결 개념
- Backdoor Attack — 특정 트리거에만 오동작시키는 오염 공격
- Data Provenance — 데이터 출처·계보 관리
- AI Supply Chain — 데이터셋·모델·라이브러리 공급망 보호

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Data Poisoning은 학습 데이터에 악성 샘플을 섞어 모델 판단을 왜곡하는 공급망 공격임.
> 2. **가치**: 데이터 품질 저하, 특정 오동작, 편향 증폭으로 AI 서비스 신뢰를 훼손함.
> 3. **판단 포인트**: 데이터 출처, 라벨 품질, 이상치, 학습 전후 검증을 체계화해야 함.

## Ⅰ. 개요 및 필요성

Data Poisoning은 학습데이터 오염 공격이다. AI 모델은 데이터 품질에 직접 영향을 받는다. 외부 데이터셋, 사용자 피드백, RAG 문서의 무결성 검증이 필요하다.

## Ⅱ. 구조 및 구성요소

```text
Data Source → Poisoned Sample → Training Pipeline
  → Corrupted Model → Wrong Decision
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Data Source | 외부·내부 데이터 공급 | provenance 필요 |
| Poisoned Sample | 악성 라벨·트리거·편향 | low-rate attack 가능 |
| Training Pipeline | 오염 데이터 학습 반영 | 검증 게이트 필요 |
| Detection | 이상치·라벨 품질 탐지 | data validation |

> 요약: 데이터 오염은 공급원에서 들어온 악성 샘플이 학습 파이프라인을 거쳐 모델 판단을 왜곡함.

## Ⅲ. 동작원리 및 흐름도

```text
공격 목표 설정 → 오염 샘플 주입 → 모델 학습
  → 오동작 발생 → 데이터 검증·제거
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 목표 클래스·트리거·편향 정의 | 위협 모델 문서화 |
| 2 | 데이터셋·피드백 채널에 주입 | provenance coverage 100% |
| 3 | 학습 후 성능·편향 변화 측정 | class별 F1 변화 |
| 4 | 이상 샘플 제거·재학습 | clean validation 통과 |

> 요약: Data Poisoning 방어는 데이터 출처 추적과 학습 전후 품질 비교를 통해 오염 샘플을 제거함.

## Ⅳ. 특징

| 구분 | 일반 데이터 오류 | Data Poisoning | 판단 포인트 |
|:---|:---|:---|:---|
| 원인 | 수집·라벨링 실수 | 공격자 의도 | 보안 이벤트 |
| 영향 | 무작위 품질 저하 | 특정 목표 오동작 | 표적성 확인 |
| 탐지 | 품질 검사 | provenance·이상치·영향분석 | 공급망 검증 |
| 대응 | 정제·재라벨링 | 격리·재학습·접근차단 | 사고 절차 |

> 요약: Data Poisoning은 품질 문제가 아니라 공격 의도를 가진 데이터 공급망 위협으로 다뤄야 함.

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 데이터 계보: 데이터셋 원천, 수집일, 라벨러, 해시, 라이선스를 metadata로 저장하고 변경 이력 100% 기록
2. 검증 게이트: schema validation, outlier detection, label agreement 95% 이상 기준으로 학습 반영 승인
3. 운영 방어: 사용자 피드백 자동 학습은 격리 큐를 거치고 오염 의심 샘플은 재학습 전 제외

**결론 (2줄):**
- 기술사 판단: 외부 데이터와 피드백을 학습에 쓰는 AI는 데이터 무결성 검증을 보안 게이트로 적용
- 향후 방향: Data Poisoning 방어는 AI SBOM, data provenance, MLOps 승인 파이프라인과 통합됨
