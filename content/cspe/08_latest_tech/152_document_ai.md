## 미리 알고가기

- Document AI는 스캔 문서와 PDF를 구조화 데이터로 바꾸는 문서 이해 기술임
- OCR만으로는 부족하고 레이아웃 이해와 정보 추출과 검수 흐름이 함께 필요함
- 백오피스 자동화와 문서 RAG 입력 품질 개선이 대표 활용임

## Ⅰ. 개요

- **정의/개념**: Document AI는 문서 이미지와 PDF를 분류하고 레이아웃을 해석하고 텍스트와 키 필드를 추출해, 이를 업무 시스템이 바로 사용할 수 있는 구조화 데이터로 변환하는 문서 지능화 기술임
- **배경/필요성**: 계약서와 영수증과 청구서처럼 양식이 다양한 문서는 규칙 기반 OCR만으로 유지보수가 어려우므로, 문맥과 구조를 함께 이해하는 자동화 기술이 필요함

## Ⅱ. 특징

- 문서 분류와 레이아웃 분석과 OCR과 KIE가 연속 파이프라인으로 결합됨
- 템플릿 변화에 강한 구조를 만들면 신규 양식 대응 비용을 크게 낮출 수 있음
- 신뢰도 기반 예외 처리와 사람 검수가 포함돼야 업무 사고를 줄일 수 있음
- 표와 서명과 도장처럼 비텍스트 요소를 놓치면 전체 자동화 가치가 급감함

## Ⅲ. 종류 및 비교

| 판단 기준 | 순수 OCR | Document AI | OCR+LLM |
|:---|:---|:---|:---|
| 구조 이해 | 낮음 | 높음 | 중간 |
| 양식 변화 대응 | 낮음 | 높음 | 높음 |
| 추출 일관성 | 중간 | 높음 | 중간 |
| 검증 가능성 | 높음 | 높음 | 중간 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Document Classifier | 유입 문서를 종류별로 나눠 후속 파서와 추출 규칙을 적절히 선택하게 함 |
| Layout Parser | 제목과 문단과 표와 서명과 키 영역을 구분해 읽기 순서와 구조를 복원함 |
| OCR, KIE Engine | 텍스트를 인식하고 필요한 필드와 값 관계를 추출해 구조화 데이터로 정리함 |
| Validation, HITL Layer | 신뢰도와 스키마와 업무 규칙을 검증하고 애매한 건만 사람 검수로 보내 자동화 리스크를 낮춤 |

```text
+-------------------+      +-------------------+      +-------------------+
| Doc Classifier    | ---> | Layout Parser     | ---> | OCR / KIE Engine  |
+-------------------+      +-------------------+      +-------------------+
                                                           |
                                                           v
                                                   +-------------------+
                                                   | Validation / HITL |
                                                   +-------------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 문서 수집/분류   | --> | 구조 분석/인식  | --> | 필드 추출/정규화 | --> | 검증/시스템 반영 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **문서 수집 및 분류**: 입력 문서를 유형별로 구분함
2. **구조 분석 및 인식**: 레이아웃과 텍스트를 읽어 문서 구조를 복원함
3. **필드 추출 및 정규화**: 필요한 값과 스키마를 추출함
4. **검증 및 시스템 반영**: 룰과 신뢰도를 점검해 업무 시스템에 적재함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 스캔 품질이 낮거나 도장과 서명이 겹치면 OCR 오류가 연쇄적으로 퍼져 핵심 필드 추출 정확도가 크게 떨어질 수 있음
   - 해결방안: 이미지 보정과 영역별 OCR을 적용하고 field accuracy와 reject rate로 검증함
2. 문제: 신규 양식이 자주 유입되면 규칙 기반 파이프라인 유지 비용이 누적되어 자동화 효과가 약해질 수 있음
   - 해결방안: template-free layout model과 few-shot schema 설정을 적용하고 onboarding lead time과 STP rate로 검증함
3. 문제: 잘못 추출된 데이터가 바로 ERP나 심사 시스템으로 흘러가면 자동화 속도보다 업무 사고 비용이 더 커질 수 있음
   - 해결방안: confidence threshold와 HITL 라우팅을 적용하고 escape rate와 review precision으로 검증함

## Ⅶ. 적용 사례

- 보험 청구 접수가 영수증과 진단서를 자동 구조화하도록 Document AI를 적용하며 확인 지표는 STP rate와 field accuracy임
- 물류 통관이 선하증권과 인보이스를 자동 입력하도록 Document AI를 운영하며 확인 지표는 processing time per page와 manual touch rate임
- 문서 기반 RAG가 고품질 인덱싱 입력을 받도록 Document AI를 활용하며 확인 지표는 parsing completeness와 retrieval gain임

## Ⅷ. 결론

Document AI는 비정형 문서를 업무 데이터로 바꾸는 핵심 인프라이므로, 인식 정확도뿐 아니라 예외 처리와 검수 설계를 함께 갖춰야 자동화 효과가 유지됨.
