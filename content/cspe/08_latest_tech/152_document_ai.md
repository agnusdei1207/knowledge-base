# 📖 【암기용】 개념 완전 이해

> 목적: Document AI를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: 문서의 텍스트, 레이아웃, 표, 도장, 서명, 이미지 요소를 이해하고 구조화하는 AI 기술
- **왜 필요한가**: 기업 지식의 상당 부분은 PDF, 스캔 문서, 계약서, 청구서처럼 구조가 있는 문서에 들어 있음.
- **핵심 직관**: 문서를 단순 글자 묶음이 아니라 제목·표·항목·서명 위치까지 이해하는 AI 사무 처리 기술임.

## 깊이 이해
- **배경·문제의식**: OCR만으로는 글자만 추출되고 문서 구조와 필드 의미가 사라진다. 업무 자동화에는 레이아웃과 필드 관계가 필요함.
- **작동 원리**: OCR, layout detection, key-value extraction, table parsing, document classification을 결합해 비정형 문서를 구조화 JSON으로 변환함.
- **비유**: 사람이 계약서를 읽으며 당사자, 금액, 기간, 서명 위치를 찾아 엑셀에 정리하는 업무를 AI가 수행함.
- **구체 예시**: 세금계산서 10만 건에서 공급자, 금액, 세액, 발행일을 추출해 ERP에 자동 입력하고 confidence 0.9 미만은 검수 큐로 전송.
- **흔한 오해·주의점**: OCR 정확도만 높아도 문서 이해가 끝나는 것은 아님. 필드 매핑, 표 구조, 문서 버전·양식 변화 대응이 필요함.

## 연결 개념
- OCR with LLM — 문자 인식 결과를 LLM으로 의미 구조화
- Table Understanding — 표 구조와 셀 관계 이해
- Multimodal RAG — 문서 구조화 결과를 RAG 근거로 활용

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Document AI는 문서 이미지와 레이아웃을 분석해 업무 필드를 구조화하는 AI 기술임.
> 2. **가치**: 계약·청구·신분증·보고서 처리 자동화로 수작업 입력과 검수 시간을 줄임.
> 3. **판단 포인트**: OCR 정확도, 필드 추출 F1, 양식 변화 대응, 사람 검수 큐가 운영 품질을 결정함.

## Ⅰ. 개요 및 필요성

- 개요: 문서 이해·구조화 AI 기술
- 배경: 기업 문서는 PDF와 스캔 이미지 형태로 저장되어 단순 텍스트 추출만으로 필드와 레이아웃 관계를 복원하기 어렵다.
- 필요성: OCR, layout parser, key-value extraction으로 field F1, table accuracy, processing latency를 관리해 RPA·ERP·RAG에 연결한다.

## Ⅱ. 구조 및 구성요소

```text
Document Image/PDF -> OCR -> Layout Analysis
  -> Field/Table Extraction -> Validation -> JSON/API
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| OCR | 문자·좌표 추출 | word box, confidence |
| Layout Analyzer | 제목·문단·표·서명 영역 탐지 | layout model, VLM |
| Extractor | key-value·표·필드 추출 | invoice, contract, ID |
| Validator | 규칙·신뢰도 기반 검증 | confidence threshold, human review |

> 요약: Document AI는 OCR과 레이아웃 분석을 결합해 문서를 구조화 데이터로 변환함.

## Ⅲ. 동작원리 및 흐름도

```text
문서 입력 -> OCR/레이아웃 탐지 -> 필드·표 추출
  -> 업무 규칙 검증 -> 검수 큐/시스템 연동
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | PDF·이미지 전처리 및 OCR | 문자 정확도 ≥98% |
| 2 | 레이아웃 요소 탐지 | layout mAP ≥0.85 |
| 3 | 필드·표 구조 추출 | field F1 ≥0.9 |
| 4 | confidence 기반 검수·연동 | 검수 큐 전송률 5~15% |

> 요약: 문서를 문자와 구조로 분석하고 업무 규칙으로 검증해 자동 처리와 사람 검수를 분리함.

## Ⅳ. 특징

| 구분 | OCR 단독 | Document AI | 판단 포인트 |
|:---|:---|:---|:---|
| 출력 | 텍스트 | 구조화 필드·표·레이아웃 | 업무 자동화 가능 |
| 이해 범위 | 문자 중심 | 문서 구조·의미 | 계약·청구서에 적합 |
| 검증 | 문자 정확도 | 필드 F1·규칙 검증 | confidence 관리 |
| 한계 | 구조 손실 | 양식 변화 대응 필요 | human-in-loop 필요 |

> 요약: Document AI는 OCR을 넘어 문서 구조와 업무 필드를 이해하지만, 양식 변화와 저신뢰 결과 검수가 필요함.

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 청구서 자동 처리: 공급자·금액·세액·계좌 필드 추출, field F1 0.9 미만 필드는 검수 큐 전송
2. 계약서 검토: 당사자·기간·해지 조항·위약금 필드를 추출해 RAG와 법무 검토 워크플로우 연동
3. 운영 관리: 문서 양식 drift를 주 단위 감지하고 신규 양식 100건 샘플 라벨링으로 모델 재평가

**결론 (2줄):**
- 기술사 판단: 반복 문서 처리 업무는 Document AI, 단순 텍스트 검색은 OCR+검색으로 충분
- 향후 방향: VLM과 LLM을 결합해 양식 비의존 문서 이해와 자연어 질의응답으로 확장
