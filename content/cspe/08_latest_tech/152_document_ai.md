# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: 영수증, 계약서, 신분증, 세금계산서 같은 비정형 스캔 문서를 AI가 읽고, 그 안에서 핵심 데이터(이름, 날짜, 금액 등)만 정확하게 추출하여 데이터베이스(JSON)로 깔끔하게 정리해 주는 자동화 기술.
- **필요성**: 은행이나 보험사 직원이 하루 수천 장의 팩스, 스캔 문서를 보며 일일이 엑셀에 타자 치는 단순 반복 노동(Data Entry)을 없애고, 업무 처리 시간을 며칠에서 몇 초로 줄이기 위함.
- **핵심 직관**: 똑똑한 자동 입력기. 단순한 복사기(OCR)는 글자만 읽지만, Document AI는 "아, 이건 영수증이고 맨 밑의 이 숫자는 부가세구나"라고 양식과 문맥(Context)을 이해하고 분류함.

## 깊이 이해
- **배경**: 기존 OCR(광학 문자 인식) 기술은 치명적인 단점이 있었음. 글자는 잘 뽑아내는데, 표의 줄이 쳐져 있거나 양식이 조금만 바뀌면 글자 순서가 뒤죽박죽 섞여서 데이터를 쓸 수 없었음. 이를 해결하기 위해 레이아웃 이해(Layout Understanding)와 NLP(자연어 처리)가 결합된 Document AI가 탄생함.
- **작동 원리 (KIE - Key Information Extraction)**:
  1. **분류 (Classification)**: 스캔 파일이 들어오면 AI가 "이건 신분증", "이건 진단서"라고 종류를 알아서 나눔.
  2. **레이아웃 분석 (Layout Parsing)**: 문서에서 어디가 제목인지, 어디가 표(Table)인지, 어디가 도장(서명)인지 위치 박스를 침.
  3. **OCR & 의미 추출**: 글자를 읽어 들인 후, LLM이나 딥러닝이 맥락을 파악해 `[Key: 총 결제 금액] - [Value: 10,000원]` 형태로 핵심 정보만 쏙쏙 뽑아냄(KIE).
- **구체 예시**: 실손 보험 청구 시스템. 환자가 폰으로 꼬깃꼬깃한 영수증을 찍어 앱에 올림. Document AI가 병원명, 진료일, 청구 금액을 초 단위로 추출해서 백엔드로 넘김. 직원의 수기 입력 없이 보험금이 즉각 자동 입금 처리됨.
- **흔한 오해/주의점**: "아무 문서나 던져주면 다 100% 인식하나요?" $\rightarrow$ 아님! 폰트가 깨지거나 도장이 글자를 가리면 AI도 틀림. 무조건 100% 자동화를 목표로 하기보단, AI가 헷갈려 하는 문서(신뢰도 80% 미만)만 사람이 확인하는 'Human-in-the-Loop(HITL)' 설계가 필수임.

## 연결 개념
- **OCR (Optical Character Recognition)**: 글자만 텍스트로 바꾸는 눈 역할. Document AI 파이프라인의 기초 공사.
- **KIE (Key Information Extraction)**: 문서에서 내가 원하는 항목(Key-Value 쌍)만 사냥해 오는 핵심 태스크.
- **RPA (Robotic Process Automation)**: Document AI가 엑셀로 만들어준 데이터를 받아서, 실제 회사 ERP 시스템에 자동으로 입력 버튼을 클릭해 주는 로봇 팔.

# 📝 【답안용】 시험 답안 템플릿
## 핵심 인사이트 (3줄 요약)
- **본질**: 컴퓨터 비전(OCR, Object Detection)과 자연어 처리(NLP, LLM) 기술을 결합하여, 비정형/반정형 문서의 공간적 레이아웃(Spatial Layout)과 시맨틱 문맥을 통합 추론하여 정형 데이터베이스(Structured DB)로 추출하는 파이프라인.
- **가치**: BPO(Business Process Outsourcing) 및 백오피스의 수작업 데이터 입력(Data Entry) 비용을 획기적으로 절감하고, 금융/의료/물류 산업의 컴플라이언스 및 워크플로우 자동화(Hyper-automation)를 달성하는 핵심 촉매제.
- **판단 포인트**: 기술 도입 시 모델의 추출 정확도(Accuracy)에만 매몰되지 않고, Confidence Score(신뢰도) 기반의 예외 처리(Exception Handling) 라우팅과 사람의 검증 UI(Human-in-the-loop)를 결합한 통합 업무 프로세스 재설계(BPR) 관점의 접근이 필수적임.

## Ⅰ. 개요 및 필요성
- **정의**: 기계가 판독할 수 없는 이미지 파일(스캔본, PDF 등) 형태의 문서를 AI 기반으로 분류(Classification), 추출(Extraction), 파싱(Parsing)하여 비즈니스 애플리케이션이 즉시 사용할 수 있는 정형화된 JSON/XML 데이터로 변환하는 기술.
- **배경**: 기존 규칙(Rule) 및 템플릿 기반의 OCR 시스템은 문서 양식(Template)이 1mm만 틀어지거나 새로운 거래처 양식이 추가될 때마다 개발자가 템플릿을 새로 짜야 하는 유지보수 병목(Bottleneck)이 심각했음.
- **필요성**: 양식에 구애받지 않는(Template-free) 범용적 문서 이해 능력을 통해 RPA 연계를 고도화하고, 문서 기반 RAG 시스템의 입력 데이터(Ingestion) 품질을 보장하기 위함.

## Ⅱ. Document AI 핵심 아키텍처 및 파이프라인
단순 글자 추출이 아닌 공간(Spatial) + 언어(Textual) 모델링의 결합.
1. **Document Classification (분류 계층)**:
   - 섞여서 들어오는 문서 더미(우편물 등)를 시각적 특징(CNN)과 텍스트 특징을 융합하여 계약서, 인보이스, 영수증, 신분증 등으로 자동 분류 및 페이지 스플릿(Split).
2. **Layout Analysis & OCR (구조 인식 및 인식 계층)**:
   - LayoutLM, DiT 등의 딥러닝 모델로 문서 내의 문단(Paragraph), 표(Table), 리스트, 서명/도장 영역의 Bounding Box를 식별.
   - 영역별 최적화된 OCR 엔진을 적용하여 텍스트 및 Bbox 좌표($x, y, w, h$) 추출.
3. **KIE (Key Information Extraction / 정보 추출 계층)**:
   - Named Entity Recognition(NER)과 2D 공간 정보(글자들의 상대적 위치)를 결합.
   - 예: "Total"이라는 글자 바로 오른쪽 공간에 있는 "숫자"를 `[총금액]` 필드로 확정하여 추출(Key-Value Pairing).

## Ⅲ. 기존 OCR과의 기술적 패러다임 차이 비교
| 구분 | 기존 규칙 기반 OCR (Template OCR) | 인지형 Document AI (Cognitive AI) |
|:---:|:---|:---|
| **인지 방식** | 절대 좌표 의존 (예: X=100, Y=200 위치의 글자 읽기) | 문맥 및 관계 기반 (예: '합계'라는 글씨 주변의 숫자 읽기) |
| **양식 변화 대응**| 양식이 바뀌면 처음부터 템플릿 재개발(하드코딩) | 양식이 완전히 달라도 AI가 알아서 유추(Template-free) |
| **표(Table) 처리**| 셀 병합, 테두리 없음 등에 취약하여 텍스트 뭉개짐 | 구조 기반 파싱을 통해 Excel(행렬) 형태로 완벽 복원 |
| **주요 모델** | Tesseract, ABBYY | LayoutLMv3, Donut, LLM 파이프라인 |

## Ⅳ. 시스템 신뢰성 보장을 위한 HITL (Human-in-the-Loop) 설계
비즈니스 환경에서 100% 자동화는 불가능하며, 오입력 리스크를 통제해야 함.
- **Confidence Score (신뢰도 점수) 평가**: AI가 데이터를 추출할 때 확신도(0~100%)를 함께 출력함.
- **Straight-Through Processing (STP)**: 신뢰도 95% 이상 $\rightarrow$ 직원 개입 없이 ERP/RPA로 즉시 자동 전송 및 처리.
- **검수 큐(Review Queue)**: 신뢰도 95% 미만 또는 필수 필드(예: 계좌번호) 누락 시 $\rightarrow$ 시스템이 보류 상태로 두고, 사람이 UI에서 빨간색으로 표시된 의심 영역만 3초 만에 육안 확인 후 승인 버튼 클릭 (Human Validation).

## Ⅴ. 실무 적용 및 결론
- **판단 지표**: Field-level Extraction Accuracy (필드별 추출 정확도), STP Rate (자동 처리율), Processing Time per Page.
- **실무 설계**: 글로벌 물류 기업의 선하증권(B/L) 통관 서류 처리 시스템. 전 세계 수천 개 포워더들의 각기 다른 양식의 B/L 문서가 하루 5천 장씩 팩스/이메일로 인입. 기존에는 입력 직원 20명이 야근하며 타이핑함. Document AI 벤더(Google DocAI / Naver Clova)를 도입하여 KIE 파이프라인 구축. B/L 문서 특화 파인튜닝을 통해 양식 무관하게 [송화인, 수화인, 물품명, 중량, 포트] 핵심 15개 필드를 추출. STP Rate 85%를 달성하여 4,250장은 즉시 통관 시스템으로 넘기고, 악필이나 도장 가림 문서 750장만 소수 직원이 검수 UI에서 처리. 데이터 입력 리드타임을 24시간에서 1시간 이내로 혁신.
- **결론**: Document AI는 비정형 아날로그 세계의 장벽을 허물고 엔터프라이즈 데이터 파이프라인의 수문장 역할을 하는 초자동화(Hyper-automation)의 첫 단추이며, 향후 생성형 AI와 결합하여 문서의 단순 입력(Data Entry)을 넘어 문서 기반 의사결정(Decision Making) 엔진으로 도약할 것이다.

### 🔀 문제 유형별 목차 전환
- **Ⅱ·Ⅲ 강조 (개념/원리형)**: 멀티모달 기반 LayoutLM 계열의 Text-Image-Layout 3-way 융합 임베딩 아키텍처 원리 및 Graph Neural Network(GNN)를 활용한 문서 내 엔티티 간 관계(Relationship) 추론 기법.
- **Ⅴ·Ⅵ 강조 (실무/설계형)**: 컴플라이언스 준수를 위한 온프레미스(On-premise) Document AI 파이프라인 구축 아키텍처 및 RPA 연계를 통한 엔드투엔드(End-to-End) 백오피스 자동화 레퍼런스 아키텍처.
