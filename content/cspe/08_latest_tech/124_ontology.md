## 미리 알고가기

- 온톨로지는 도메인 개념과 관계와 제약을 공식적으로 정의한 지식 모델임
- 지식그래프의 스키마와 규칙층 역할을 한다고 보면 이해하기 쉬움
- 데이터 저장보다 개념 정의와 의미 일관성 확보에 초점이 있음

## Ⅰ. 개요

- **정의/개념**: 온톨로지는 특정 도메인의 개념과 속성과 관계와 제약 조건을 명시적으로 정의해 시스템 간 의미 일관성과 추론 가능성을 제공하는 개념 모델임
- **배경/필요성**: 동일한 대상도 조직과 시스템마다 다른 이름과 구조로 관리되면 지식 통합과 자동 추론이 어려워지므로, 공유된 의미 규칙 체계가 필요함

## Ⅱ. 특징

- 클래스, 속성, 관계, 제약을 명시적으로 정의해 의미 해석 기준을 통일함
- 지식그래프와 추론 엔진의 품질 기준이 되는 상위 스키마 역할을 수행함
- 구축 시 도메인 전문가 합의와 용어 표준화 비용이 크다
- 너무 무겁게 설계하면 변화 대응이 느려져 운영 유연성이 떨어질 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | Taxonomy | Ontology | Knowledge Graph |
|:---|:---|:---|:---|
| 표현 범위 | 분류 체계 | 개념+관계+제약 | 실제 개체+관계 |
| 추론 가능성 | 낮음 | 높음 | 중간~높음 |
| 구축 난도 | 낮음 | 높음 | 높음 |
| 대표 역할 | 분류 | 의미 규칙 정의 | 실제 데이터 연결 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Classes | 도메인의 핵심 개념 집합을 정의해 지식 구조의 기본 틀을 제공함 |
| Properties, Relations | 개념 간 속성과 관계를 정의해 데이터 연결 규칙을 명확히 함 |
| Constraints, Axioms | 허용 가능한 값과 관계를 제한해 추론과 검증의 근거를 제공함 |
| Reasoning Semantics | 서브클래스, 역관계, 전이성 같은 규칙으로 숨은 지식을 유추하게 함 |

```text
+-------------------+      +-------------------+      +-------------------+
| Classes           | ---> | Props / Relations | ---> | Constraints       |
+-------------------+      +-------------------+      +-------------------+
                                                           |
                                                           v
                                                   +-------------------+
                                                   | Reason Semantics  |
                                                   +-------------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 도메인 개념 수집  | --> | 클래스/관계 정의  | --> | 제약/규칙 명세   | --> | 그래프/추론 반영 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **도메인 개념 수집**: 업무에서 중요한 대상과 용어를 정리함
2. **클래스 및 관계 정의**: 개념의 계층과 관계를 명시함
3. **제약 및 규칙 명세**: 허용 범위와 추론 규칙을 정의함
4. **그래프 및 추론 반영**: 실제 데이터 구조와 질의 엔진에 규칙을 적용함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 초기부터 모든 개념과 규칙을 완벽히 설계하려 하면 구축 기간이 길어지고 현업 합의가 멈출 수 있음
   - 해결방안: 핵심 개념부터 점진 확장하고 ontology coverage와 stakeholder agreement로 구축 진행을 검증함
2. 문제: 도메인 변화가 빠른 환경에서는 경직된 스키마가 실제 데이터 변화를 따라가지 못할 수 있음
   - 해결방안: 모듈형 ontology와 versioning을 적용하고 schema update lead time과 integration failure rate로 유연성을 검증함
3. 문제: 추상적 규칙만 있고 실제 데이터 정규화가 부족하면 온톨로지가 문서로만 남고 실사용 가치가 낮을 수 있음
   - 해결방안: entity linking과 validation rule을 함께 운영하고 graph consistency와 query accuracy로 실효성을 검증함

## Ⅶ. 적용 사례

- 의료 개념 표준화가 질병과 처치와 약물 관계를 정의하도록 온톨로지를 적용하며 확인 지표는 concept consistency와 query accuracy임
- 제조 설비 지식 통합이 장비와 부품과 고장 관계를 정규화하도록 온톨로지를 활용하며 확인 지표는 relation consistency와 maintenance efficiency임
- graph RAG 기반 설계가 개체와 관계 규칙을 제공하도록 온톨로지를 사용하며 확인 지표는 explainability와 multi-hop QA quality임

## Ⅷ. 결론

온톨로지는 지식그래프의 데이터보다 한 단계 위에서 의미와 규칙을 정의하는 뼈대이므로, 실제 데이터 정규화와 함께 운영될 때 비로소 가치가 생김.
