## 미리 알고가기

- CoT는 최종 답만 내기 전에 중간 추론 단계를 생성하도록 유도하는 reasoning 기법임
- Self-Consistency는 여러 추론 경로를 생성한 뒤 일관된 답을 선택하는 보완 기법임
- Test-time Compute는 추론 시 더 많은 계산과 토큰을 사용해 정답률을 높이는 접근임

## Ⅰ. 개요

- **정의/개념**: Chain-of-Thought는 복합 문제에 대해 모델이 중간 추론 단계를 형성한 뒤 최종 답을 도출하도록 유도해 reasoning 정확도와 자기 검증 가능성을 높이는 프롬프팅 및 추론 전략임
- **배경/필요성**: 단일 응답 생성만으로는 수학 계산과 정책 규칙 적용과 장문의 논리 비교에서 오류가 잦으므로, 문제를 단계적으로 분해해 모델이 스스로 중간 상태를 만들고 확인하도록 하는 구조가 필요함

## Ⅱ. 특징

- 단순 질의응답보다 다단계 계산, 규칙 적용, 논리 비교 문제에서 성능 향상 효과가 큼
- intermediate reasoning을 만들어 자기 앞 단계 결과를 다음 단계 입력으로 재활용함
- explicit CoT뿐 아니라 hidden reasoning이나 reasoning model 형태로도 진화하고 있음
- 정확도 향상과 동시에 토큰 비용과 지연이 증가하므로 선택적 적용이 중요함

## Ⅲ. 종류 및 비교

| 판단 기준 | Standard Prompting | Chain-of-Thought | ToT / Reasoning Model |
|:---|:---|:---|:---|
| 추론 경로 | 즉시 답변 | 선형 단계 추론 | 다경로 탐색 또는 내부 추론 |
| 정확도 | 단순 작업에 적합 | 복합 규칙 문제에 유리 | 고난도 문제에 강함 |
| 비용 | 낮음 | 중간 | 높음 |
| 대표 활용 | 일반 질의응답 | 계산, 정책 해석 | 고난도 계획, 탐색 추론 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Task Decomposition | 문제를 작은 단계로 나누어 무엇부터 확인할지 추론 순서를 정함 |
| Intermediate Reasoning | 각 단계의 계산과 판단 근거를 생성해 다음 단계 입력으로 재사용함 |
| Verification Step | 중간 결과를 다시 점검하거나 다중 경로 결과를 비교해 오류 누적을 줄임 |
| Final Answer Extraction | 필요한 요약 수준으로 정답만 정리해 사용자나 후속 시스템에 전달함 |

```text
+------------------+     +------------------+     +------------------+     +------------------+
| Task Decompose   | --> | Intermediate Step| --> | Verification     | --> | Final Answer     |
+------------------+     +------------------+     +------------------+     +------------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +---------------+     +---------------+     +-------------+
| 문제 분해    | --> | 단계 추론 생성 | --> | 중간 검증      | --> | 최종 답 추출 |
+-------------+     +---------------+     +---------------+     +-------------+
```

1. **문제 분해**: 질문을 계산 단계나 규칙 확인 단계로 나누어 추론 순서를 세움
2. **단계 추론 생성**: 모델이 각 단계의 중간 판단을 텍스트나 내부 상태로 생성함
3. **중간 검증**: self-consistency나 verifier를 통해 틀린 단계가 없는지 점검함
4. **최종 답 추출**: 사용자에게 필요한 수준의 정답과 근거만 간결하게 정리함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 모든 요청에 CoT를 강제하면 불필요한 중간 추론이 늘어나 비용과 지연이 커지고 단순 질의응답 효율이 떨어짐
   - 해결방안: 난이도 기반 라우터로 복합 문제에만 CoT를 적용하고 task별 latency와 accuracy gain으로 적용 기준을 검증함
2. 문제: 초반 중간 추론이 틀리면 이후 단계가 그 오류를 증폭해 자신감 있는 오답으로 이어질 수 있음
   - 해결방안: self-consistency나 verifier 모델을 병행하고 pass@k와 final answer accuracy로 교정 효과를 검증함
3. 문제: 중간 추론을 그대로 노출하면 보안 정책이나 사용자 경험 측면에서 불필요한 정보가 드러날 수 있음
   - 해결방안: hidden reasoning 또는 요약형 근거 출력으로 분리하고 answer quality와 policy compliance로 적절성을 검증함

## Ⅶ. 적용 사례

- 수학, 계산형 챗봇: 단계별 계산으로 연산 오류를 줄임, 확인 지표는 final answer accuracy와 latency임
- 규정 해석 도우미: 조건을 순서대로 확인해 누락 없는 판단을 유도함, 확인 지표는 rule application accuracy와 audit pass rate임
- 에이전트 계획 수립: Thought, Action, Observation 루프로 도구 사용 순서를 정함, 확인 지표는 task completion rate와 retry count임

## Ⅷ. 결론

Chain-of-Thought의 가치는 생각을 길게 보여주는 데 있지 않고 복합 문제에서 중간 상태를 활용해 정답률을 높이되 비용과 노출 수준을 통제하는 reasoning 운영 전략을 만드는 데 있음.
