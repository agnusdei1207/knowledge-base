## 미리 알고가기

- 바이트 페어 인코딩 ($BPE$): 빈도가 가장 높은 문자 쌍을 반복 병합하여 서브워드 사전을 구축하는 통계적 토큰화 기법임
- 어휘 사전 ($Vocabulary$): 모델이 인코딩할 수 있는 토큰 문자열과 고유한 정수 $ID$의 매핑 테이블임
- 토큰 예산 ($Token$ $Budget$): 프롬프트 창 크기와 비용을 고려하여 최적 추론 효율을 내도록 할당하는 토큰의 상한선임
- 의미론적 청킹 ($Semantic$ $Chunking$): RAG에서 단어가 무작위로 잘리는 것을 막기 위해 토크나이저의 의미 경계를 기준으로 문서를 조각내는 처리임

## Ⅰ. 개요

- **정의/개념**: Tokenization은 자연어 문장이나 소스 코드를 컴퓨터 모델이 즉시 연산할 수 있는 최소 문자 조각인 토큰($Token$)들의 배열로 분할하고, 이를 고유한 정수 $ID$ 시퀀스로 매핑하여 신경망에 주입하는 입력 전처리이자 복원 인터페이스임
- **배경/필요성**: 컴퓨터는 텍스트를 통째로 읽어 들이면 미등록 단어($OOV$) 처리 실패나 차원 폭증을 피할 수 없으므로, 모든 언어와 코드 기호를 일정한 의미 조각으로 쪼개어 연산 비용을 최적화하기 위해 필수적으로 요구됨

## Ⅱ. 특징

- 입출력 파이프라인의 최선두에서 텍스트의 총길이와 가용한 문맥 크기($Context$ $Window$), API 사용 과금 체계에 절대적 영향($Throughput$, 비용)을 미치는 게이트웨이 역할을 함
- 서브워드($Subword$) 기법을 사용하여, 훈련에 없던 생소한 명사나 신조어도 기본 자소나 철자 조각 단위로 쪼개 수용함으로써 단어 미등록 리스크를 원천 제거함
- 입력 정수화(인코더) 및 출력으로 도출된 토큰 확률을 다시 사람의 글자로 역변환(디코더)하는 양방향 변환 모듈로 작동함

## Ⅲ. 종류 및 비교

| 판단 기준 | 단어 기반 토큰화 (Word-level) | 문자 기반 토큰화 (Character-level) | 서브워드 토큰화 (Subword-level) |
|:---|:---|:---|:---|
| **분절 기준** | 공백 ($Whitespace$) 단위 분절 | 개별 글자 (한글 자모, 알파벳) 단위 | 통계적 결합 빈도(서브 단어) 단위 |
| **사전 크기** | 매우 큼 (단어 수만큼 증가) | 매우 작음 (글자 수 한정) | 사용자 지정 가능 (보통 3만~10만) |
| **OOV 대응** | 매우 취약함 (신조어 무조건 $UNK$) | 없음 (모든 문자 표현 가능) | 우수함 (단어를 쪼개 분석 수용) |
| **시퀀스 길이** | 짧음 | 극도로 길어짐 (연산 병목) | 적절함 (압축성과 세밀함의 조화) |
| **대표 기술** | 공백 토크나이저 | 캐릭터 임베딩 | $BPE, WordPiece, SentencePiece$ |

> 요약: 단어 기반은 어휘량에 치이고, 문자 기반은 시퀀스 길이에 치이나, 서브워드는 사전 크기와 성능의 최적 타협점을 제공함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 정규화기 ($Normalizer$) | 유니코드 정규화(NFC/NFD), 대소문자 통일을 수행하여 단어의 표기 편차를 사전에 제거함 |
| 사전 분절기 | 공백, 쉼표, 마침표, 특수기호 등으로 1차 어휘 경계를 설정하는 모듈임 |
| 병합 가이드 테이블 | 학습 과정에서 축적된 가장 유력한 연속 문자들의 병합 우선순위 쌍 정보임 |
| 디코딩 변환 맵 | 추론된 정수 $ID$를 실시간으로 사람이 읽을 수 있는 유니코드 글자로 바이트 복원하는 매퍼임 |

```text
[ 토크나이징 파이프라인 구조 ]
Input String -> [Normalizer] -> [Pre-tokenizer] -> [BPE/WordPiece Rules] -> Tokens -> [Vocab ID Mapping] -> Integer IDs
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 텍스트 입력  | --> | 기호/공백 정제| --> | 서브워드 병합| --> | 정수 ID 전환|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **정형 정제** — 입력된 원문 텍스트의 깨진 유니코드 문자를 수정하고, 일관된 문자열로 통일하는 정규화를 수행함
2. **기본 조각화** — 문장 부호와 공백을 기반으로 텍스트를 기초 단어 조각들로 나누어 병합 규칙 적용을 위한 초기 셋을 구성함
3. **통계 병합** — 어휘 사전 생성 시 학습된 $BPE$나 $WordPiece$ 규칙의 우선순위에 따라 조각들을 가장 빈도가 높은 서브워드 단위로 융합함
4. **인덱스 전송** — 최종 병합된 서브워드 토큰을 사전 매핑 테이블을 조회해 해당하는 정수 $ID$로 치환하고 모델의 연산 텐서로 주입함

## Ⅵ. 실무 적용 및 유의점

1. 한국어는 조사와 어미가 발달한 교착어이므로 다국어 토크나이저를 그대로 사용하면 한자나 한글이 너무 잘게 쪼개져 토큰 낭비가 매우 심해지므로, 반드시 한국어 코퍼스로 별도 학습된 토크나이저를 채택하여 토큰당 글자 수($Char/Token$) 효율을 확보하고 사용료 절감 효과를 모니터링해야 함
2. RAG 파이프라인 구축 시 단순 글자 수나 공백 기준으로 텍스트를 자르면 단어와 의미 경계가 훼손되어 검색 정확도가 하락하므로, 토크나이저의 의미 단위 경계를 추적하여 자르는 '의미론적 청킹($Semantic$ $Chunking$)'을 적용하고 검색 정확도와 답변 연관성 지표로 이를 검증해야 함

## Ⅶ. 결론

- 토큰화는 자연어 텍스트를 기계의 공간으로 투영하는 첫 단추이자 서빙 비용과 정확도의 나침반이며, 설계자는 대상 도메인의 특화 어휘 구성과 메모리 절감을 위한 효율적인 어휘 사전 크기 설계를 반드시 수립해야 함
