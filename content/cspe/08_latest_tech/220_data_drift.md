# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: 머신러닝 모델을 **학습시킬 때 사용한 '과거 데이터의 통계적 분포'와, 현재 실서비스 운영 환경에서 들어오는 '최신 데이터의 통계적 분포'가 달라져서 어긋나는 현상** (공변량 이동, Covariate Shift).
- **필요성**: 세상의 유행, 경제 상황, 센서 기기의 상태는 계속 변함. 입력 데이터의 성질 자체가 바뀌어버렸는데, 과거 데이터만 달달 외운 모델한테 예측하라고 하면 무조건 틀린 답(헛소리)을 내놓음. 이 현상을 조기에 잡아내지 못하면 비즈니스 손실(오작동)이 기하급수적으로 커짐.
- **핵심 직관**: 수능 영어시험 메타의 변화. 학생(모델)이 2010년도 기출문제(학습 데이터)로만 3년을 빡세게 공부해서 100점을 맞게 세팅됨. 그런데 2026년 수능 시험장(운영 환경)에 가보니, 지문에 '메타버스, AI, 틱톡' 같은 2010년엔 없던 단어들(Data Drift)이 쏟아져 나옴. 학생의 지능(알고리즘)은 그대로지만, 입력 데이터의 종류가 변해버렸기 때문에 성적은 나락으로 감.

## 깊이 이해
- **배경**: AI 모델은 "학습 데이터(Train)와 테스트 데이터(Test/운영)가 동일한 모집단(IID)에서 뽑혔다"는 매우 순진한 수학적 가정을 깔고 만들어짐. 하지만 현실 세계 데이터는 시간에 따라 파도처럼 요동침(Non-stationary).
- **작동 원리 (어떻게 찾아내는가?)**:
  1. **기준점(Baseline) 설정**: 모델을 릴리스할 때, 썼던 훈련 데이터의 각 피처별 평균, 분산, 그래프(히스토그램) 모양을 기억해 둠.
  2. **실시간 비교**: 상용 서버에 들어오는 유저들의 입력값(최근 1주일 치) 히스토그램을 그림.
  3. **거리 계산 (통계 검정)**: 과거 히스토그램과 현재 히스토그램을 겹쳐봄. 두 그래프 사이의 겹치지 않는 면적(차이)을 통계 공식(PSI, KS-test 등)으로 계산.
  4. **알람 및 액션**: "이 정도면 완전히 다른 데이터가 들어오는 거다!" 싶으면(임계치 돌파) 시스템에 빨간불을 켜고, MLOps 파이프라인을 깨워서 최신 데이터로 모델을 강제 재학습(Retraining)시킴.
- **구체 예시**: 사기 탐지(FDS) 모델. 작년엔 사기꾼들이 주로 밤 12시에 'IP 우회'로 결제를 시도해서, 모델이 그 특징을 잡고 사기를 100% 막음. 그런데 올해 사기꾼들이 수법을 바꿔 대낮에 '스마트폰 앱 우회'로 접속을 시도함. 해킹 수법(입력 데이터 패턴)이 확 바뀐 거임(Data Drift). 모델은 대낮 결제니까 안전하다고 착각하고 다 통과시킴(성능 폭망).
- **흔한 오해/주의점**: "데이터 드리프트 생기면 무조건 모델 정확도가 떡락하나요?" $\rightarrow$ 아님! 모델이 거의 안 쓰는 쓸데없는 변수(피처 중요도 하위권)가 변한 거면 성능엔 지장 없음. 반대로 정답(Y)의 기준 자체가 변하는 건 'Concept Drift'라고 부르며, 구분해서 대처해야 함.

## 연결 개념
- **Concept Drift (컨셉 표류)**: Data Drift가 시험의 '지문'이 바뀐 거라면, Concept Drift는 '채점 기준(정답)' 자체가 바뀐 것. (예: 인플레이션으로 과거엔 5천 원이 '비싼 밥'이었는데, 지금은 '싼 밥'으로 정답 레이블(Y)이 변경됨). 가장 무서운 적.
- **Model Monitoring**: Data Drift를 실시간으로 측정하고 감시하는 시스템과 행위 그 자체.
- **PSI (Population Stability Index)**: Data Drift가 얼마나 일어났는지 그 심각성을 수치(0.1, 0.2)로 딱 떨어지게 보여주는 금융권 전통의 마법의 공식.

# 📝 【답안용】 시험 답안 템플릿
## 핵심 인사이트 (3줄 요약)
- **본질**: 머신러닝의 성능 퇴화(Model Decay)를 유발하는 가장 대표적인 원인으로, 모델의 학습 시점 데이터 분포($P_{train}(X)$)와 상용 배포 이후의 운영 데이터 분포($P_{serve}(X)$) 간에 발생하는 통계적 불일치(Covariate Shift) 현상.
- **가치**: 모델의 최종 예측 성능(정확도) 하락은 실제 정답(Label)이 확보된 이후에나 사후 인지(Label Lag)가 가능하지만, 입력 데이터만으로 계산 가능한 Data Drift 지표를 감시하면 **모델 실패를 사전(Proactive)에 경고**할 수 있음.
- **판단 포인트**: 모든 데이터 변화가 모델 성능 저하로 직결되는 것은 아니므로, Data Drift 모니터링은 머신러닝 알고리즘의 **피처 중요도(Feature Importance)**와 결합하여, 모델의 예측을 지배하는 '핵심 변수'의 쏠림 현상을 우선적으로 감시(Thresholding)하는 전략적 설계가 필요함.

## Ⅰ. 개요 및 필요성
- **정의**: 시간이 지남에 따라 머신러닝 모델에 입력되는 피처(독립변수, $X$)의 통계적 특성(평균, 분산, 범주 비율 등)이 학습 당시의 베이스라인(Baseline) 분포와 유의미하게 달라지는 현상.
- **배경**: AI 모델은 IID(독립동일분포) 가정하에 학습되지만, 거시 경제 트렌드 변화, 계절성(Seasonality), 데이터 수집 센서의 물리적 마모 및 상위 시스템의 스키마 변경 등으로 현실 세계의 데이터는 끊임없이 요동침.
- **필요성**: 성능 우하향 곡선(Degradation)의 원인 규명, 적절한 재학습(Retraining) 주기 산정의 수학적 근거 확보, 가비지(Garbage) 데이터 인입에 따른 어플리케이션 장애의 선제적 차단.

## Ⅱ. Data Drift vs Concept Drift (AI 모델 성능 하락의 양대 산맥)
원인과 대응의 차이.
| 구분 | Data Drift (데이터 표류 / 공변량 이동) | Concept Drift (컨셉 표류 / 개념 이동) |
|:---:|:---|:---|
| **수학적 정의** | 입력 확률 분포 $P(X)$의 변화 | 조건부 확률 $P(Y \mid X)$의 변화 |
| **현상 요약** | 세상이 변해서 입력 패턴 자체가 달라짐. | 입력은 같아도, 정답의 기준 자체가 변함. |
| **탐지 용이성**| 매우 쉬움 (입력 데이터만 비교하면 됨). | **어려움 (실제 결과값 Y가 수집되어야 함)**. |
| **대응 방향** | 재학습 또는 스케일링/정규화 등 데이터 보정. | **모델 아키텍처 전면 수정 또는 철저한 최신 데이터 재학습**. |
| **현실 예시** | 음성 인식 모델에 사투리를 쓰는 유저가 대거 유입. | 스팸 필터: 사기꾼들이 스팸 단어를 교묘히 바꿔서 우회 성공. |

## Ⅲ. Data Drift를 측정하는 핵심 통계적 알고리즘
분포의 거리를 재는 수학적 잣대.
| 통계 기법 | 원리 및 메커니즘 (Mechanism) | 주 적용 대상 (Data Type) |
|:---:|:---|:---|
| **PSI**<br>(Population Stability Index) | 데이터 구간(Bin)별 비율 차이를 정보 이론 관점에서 수치화. `0.1 이하(안정), 0.1~0.2(주의), 0.2 초과(위험/재학습)`. | 범주형 데이터 및 구간화된 연속형 데이터 (금융권 범용). |
| **KS Test**<br>(Kolmogorov-Smirnov) | 학습 데이터와 운영 데이터의 누적분포함수(CDF) 간의 최대 수직 거리를 계산. 임계치 초과 시 기각. | 연속형 수치 데이터 (분포 형태의 미세한 왜곡 감지). |
| **KL Divergence**<br>(쿨백-라이블러 발산) | 두 확률 분포 간의 정보 엔트로피 차이(비대칭적 거리)를 측정. 0에 가까울수록 동일 분포. | 다양한 연속/범주형, 언어 모델의 확률 분포. |
| **Wasserstein Distance** | 두 분포를 일치시키기 위해 흙(데이터)을 옮기는 최소 비용 계산 (Earth Mover's Distance). | 이미지, 텍스트 등 복잡한 고차원 비정형 데이터 공간. |

## Ⅳ. Drift 탐지 및 대응 파이프라인 (MLOps 연계)
발견 즉시 치유하는 자동화 사이클.
1. **분포 스냅샷 (Baseline)**: 모델 학습 종료 후 검증 데이터셋의 각 피처별 통계값(Mean, Std, 분포 히스토그램)을 메타데이터 스토어에 Baseline으로 영구 저장.
2. **슬라이딩 윈도우 관측**: 서빙되는 최신 N일 치(예: 7일) 데이터 배치를 지속 수집.
3. **드리프트 산출 (Compute)**: 모니터링 엔진이 피처별 PSI 등 통계 스코어를 1분 단위로 계산. 모델 정확도 기여도가 높은 상위 10개 피처(Feature Importance 기준)의 임계치 위반 집중 감시.
4. **알람 및 CT 격발 (Trigger)**: 주요 피처의 PSI가 0.25를 넘기면(Drift Detected), 즉시 알람 발송 후 Airflow 등 오케스트레이터를 호출해 최신 1달 치 데이터 셋으로 **Continuous Training(자동 재학습)** 루프 구동.

## Ⅴ. 실무 적용 및 결론
- **판단 지표**: 핵심 피처(Feature) 대상의 Drift 감지율(Coverage), 알람의 정확도(False Positive 오탐 최소화를 위한 임계치 설정의 최적화 수준), Drift 발생 시점부터 재학습 완료 후 재배포까지 소요된 리드타임(MTTR).
- **실무 설계**: e-커머스 D사의 '개인화 가격 추정 및 쿠폰 발급 모델' 최적화 사례. 연말 블랙프라이데이 시즌마다 고객들의 대량 구매 패턴(Data Drift)이 평소와 확연히 달라져, 할인율 추정 모델의 손실액이 매년 눈덩이처럼 불어남(수동 대응 한계). 조치 방안: Evidently AI 같은 오픈소스 모니터링 툴을 파이프라인에 삽입. 1) 고객 장바구니 크기, 구매 빈도 피처에 대해 KS-Test 기반 모니터링 스크립트 작성. 2) 11월 이벤트 시작 직후, 3시간 단위로 Sliding Window를 돌려 분포 이탈 P-value가 0.05 이하로 떨어지면 "시즌성 드리프트(Seasonality Drift) 발생"으로 판정. 3) 과거 평시 데이터를 과감히 버리고, 최근 3일간의 폭주 데이터만으로 모델을 섀도우(Shadow) 파인튜닝하여 동적 배포. 이벤트 기간 영업이익 방어 성공.
- **결론**: 현실 세계의 무질서도(엔트로피)는 계속 증가하고, 데이터는 끊임없이 표류(Drift)한다. 한 번 학습시킨 AI 모델을 영원불멸의 마법 지팡이로 믿는 것은 환상이다. Data Drift 모니터링 체계는 데이터 사이언티스트에게 AI 모델이 세상의 변화 속도에 뒤처지지 않고 있는지 끊임없이 확인시켜주는 나침반이자, 지속 가능한 MLOps 파이프라인의 생명 유지 장치다.

### 🔀 문제 유형별 목차 전환
- **Ⅱ·Ⅲ 강조 (개념/원리형)**: 비정형 데이터 영역(Unstructured Data)에서의 Data Drift 심화 개념 전개. 단순 숫자가 아닌 자연어(NLP) 프롬프트 텍스트나 컴퓨터 비전(CV) 이미지의 입력 데이터 변화(조명 변화, 신조어 등장)를 고차원 임베딩(Embedding Space) 간의 밀도 클러스터링 및 시맨틱 거리(Semantic Distance) 비교로 수학적으로 탐지해 내는 알고리즘 모델링 기법.
- **Ⅴ·Ⅵ 강조 (실무/설계형)**: 리스크 관리와 운영 안정성 확보를 위한 '임계치(Threshold) 튜닝 플랜'. 너무 민감한 Drift 알람은 운영자의 알람 피로(Alert Fatigue)를 유발하므로, Feature의 정보 획득량(Information Gain)에 비례하여 동적(Dynamic)으로 알람 임계치를 자동 조절하고 오탐(False Positive)을 억제하는 적응형 MLOps 모니터링 워크플로우 설계 방안.
