## 미리 알고가기

- Data Drift는 학습 시점과 운영 시점의 입력 데이터 분포가 달라지는 현상임
- 모든 분포 변화가 성능 저하를 의미하지는 않으므로 핵심 피처와 비즈니스 영향 중심 해석이 필요함
- PSI와 KS와 Wasserstein 같은 통계 지표를 활용해 조기 탐지하고 재학습 여부를 판단함

## Ⅰ. 개요

- **정의/개념**: Data Drift는 모델이 학습할 때 사용한 입력 데이터 분포와 실제 운영 환경에서 들어오는 입력 데이터 분포가 시간 경과나 환경 변화로 인해 통계적으로 달라지는 현상임
- **배경/필요성**: 사용자 행동과 시장 상황과 센서 조건은 계속 바뀌므로 입력 분포 변화를 조기에 포착하지 못하면 모델 성능 저하가 조용히 누적될 수 있음

## Ⅱ. 특징

- 정답 라벨이 없어도 입력 데이터만으로 비교 가능해 조기 경보 지표로 유용함
- 계절성이나 캠페인 효과처럼 정상 변화도 있어 문맥 해석이 필요함
- 중요도가 낮은 피처 변화는 영향이 제한적일 수 있음
- Data Drift와 Concept Drift와 Model Drift를 구분해 대응해야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | Data Drift | Concept Drift | Model Drift |
|:---|:---|:---|:---|
| 변화 대상 | 입력 분포 P(X) | 관계식 P(Y|X) | 모델 전체 품질과 출력 특성 |
| 탐지 난이도 | 상대적으로 낮음 | 실제 라벨 필요로 높음 | 운영 구조에 따라 다양함 |
| 대표 징후 | 평균, 분산, 비율 변화 | 정답 기준 변화 | 성능과 안정성 저하 |
| 우선 대응 | 분포 모니터링과 재학습 검토 | 최신 라벨 기반 재학습 | 원인 분석과 재배포 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Baseline Distribution | 학습 또는 정상 운영 시점의 피처 분포를 저장해 비교 기준으로 사용하는 참조 집합임 |
| Current Window Collector | 최근 운영 데이터의 슬라이딩 윈도우를 수집해 현재 분포를 구성하는 관측 계층임 |
| Statistical Test Engine | PSI와 KS와 거리 지표를 계산해 분포 차이를 수치화하는 분석 엔진임 |
| Threshold and Policy | 피처 중요도와 업무 맥락을 반영해 경보 임계치와 후속 조치를 정의하는 통제 계층임 |
| Retraining Trigger | 의미 있는 드리프트가 확인되면 데이터 조사와 재학습과 롤백 절차를 연결하는 액션 계층임 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
| 기준 저장    | -> | 현재 수집    | -> | 분포 비교    | -> | 임계 판정    | -> | 조사 및 재학습 |
+-------------+    +-------------+    +-------------+    +-------------+    +-------------+
```

1. **기준 저장**: 학습 데이터나 정상 운영 데이터의 기준 분포를 저장함
2. **현재 수집**: 최신 입력 데이터를 일정 창으로 모아 현재 분포를 만듦
3. **분포 비교**: 통계 지표로 기준과 현재를 비교함
4. **임계 판정**: 중요 피처와 업무 임계치를 기준으로 경보 여부를 결정함
5. **조사 및 재학습**: 의미 있는 변화면 원인 조사와 재학습 또는 정책 조정을 수행함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 모든 피처에 동일 임계치를 적용하면 중요도가 낮은 변화에도 과도한 경보가 발생할 수 있음
   - 해결방안: feature importance weighted threshold를 적용하고 alert precision과 low value alert ratio로 검증함
2. 문제: 계절성과 이벤트성 변화까지 이상으로 처리하면 불필요한 재학습과 운영 비용이 커질 수 있음
   - 해결방안: seasonal baseline과 context aware policy를 적용하고 false retraining trigger rate와 monitoring cost efficiency로 검증함
3. 문제: 드리프트 탐지만 하고 후속 조치가 연결되지 않으면 성능 저하를 알고도 오래 방치하게 될 수 있음
   - 해결방안: retraining runbook과 investigation workflow를 적용하고 mean time to mitigation과 drift closure rate로 검증함

## Ⅶ. 적용 사례

- 카드 이상거래 탐지 모델이 핵심 피처별 가중 임계치를 운영하며 확인 지표는 alert precision과 low value alert ratio임
- 전자상거래 추천 시스템이 시즌성 기준 분포를 별도 관리하며 확인 지표는 false retraining trigger rate와 monitoring cost efficiency임
- 제조 센서 예측 모델이 드리프트 경보 후 조사와 재학습을 자동 연결하며 확인 지표는 mean time to mitigation과 drift closure rate임

## Ⅷ. 결론

Data Drift는 운영 모델 품질의 조기 경보 지표이므로 중요 피처 중심 해석과 후속 조치 연계를 갖춘 실용적 모니터링 체계가 필요함.
