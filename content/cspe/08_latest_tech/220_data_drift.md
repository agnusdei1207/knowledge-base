# 📖 【암기용】 개념 완전 이해

> 목적: Data Drift를 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 머신러닝 모델의 학습에 사용된 데이터의 통계적 분포와 실제 운영 환경에서 들어오는 데이터의 분포가 달라지는 현상
- **왜 필요한가**: 입력 데이터의 성격이 변하면, 과거 데이터에 최적화된 모델은 정확한 예측을 할 수 없게 되어 성능이 떨어지기 때문
- **핵심 직관**: 시험 문제 유형이 바뀌면 옛날 족보로 공부한 학생의 점수가 떨어지는 것과 같음. 학생(모델)은 잘못이 없지만 문제(데이터)가 달라진 상황

## 깊이 이해
- **배경·문제의식**: 세상은 끊임없이 변한다. 사용자의 선호도, 경제 상황, 계절, 심지어 센서의 노후화로 인해 수집되는 데이터의 값이 서서히 혹은 급격히 바뀐다. 모델은 "입력 데이터의 분포가 일정하다"는 가정을 바탕으로 동작하기 때문에, 이 분포가 틀어지는 순간 모델은 "듣도 보도 못한 상황"에 처하게 된다.
- **작동 원리**: 학습 시점의 데이터 분포(Baseline)와 운영 시점의 데이터 분포(Target)를 비교한다. 각 특징(Feature)의 평균, 분산, 사분위수 등을 대조하거나, 통계적 검정(KS-test, PSI 등)을 통해 두 데이터 셋이 동일한 분포에서 왔는지를 판별한다.
- **비유**: 겨울 옷을 파는 쇼핑몰 추천 모델이 있는데, 갑자기 날씨가 더워져서 사람들이 반팔(데이터)을 찾기 시작하면, 여전히 코트를 추천하는 모델의 성능은 쓸모없어진다.
- **구체 예시**: 부동산 가격 예측 모델이 '금리 2%' 시기에 학습되었는데, 시장 금리가 '5%'로 급등하면 입력값(금리)의 분포가 학습 범위를 벗어나게 되어(Data Drift) 예측 오차가 커진다.
- **흔한 오해·주의점**: "데이터가 변하면 무조건 모델을 새로 만들어야 한다"는 아니다. 단순한 일시적 노이즈인지, 아니면 영구적인 트렌드 변화인지를 구분해야 한다. 또한 입력 데이터만 변하고 정답과의 관계는 그대로인 경우를 특별히 'Data Drift'라고 부른다.

## 연결 개념
- Concept Drift — 데이터뿐만 아니라 정답과의 관계 자체가 변하는 현상
- PSI (Population Stability Index) — 데이터 분포 변화를 측정하는 대표적 지표
- MLOps — Drift를 자동 탐지하고 재학습을 트리거하는 운영 체계

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Data Drift는 모델 학습 데이터셋($P_{train}(X)$)과 운영 데이터셋($P_{live}(X)$) 사이의 통계적 분포 차이(Covariate Shift)가 발생하는 현상이다.
> 2. **가치**: 모델 성능 저하의 전조 신호를 조기에 포착하여 정답(Label) 확보 전에도 모델의 유효성을 사전에 진단할 수 있게 한다.
> 3. **판단 포인트**: 특징별 중요도(Feature Importance)와 연계하여, 성능에 큰 영향을 미치는 핵심 변수의 드리프트 발생 여부를 집중 관리해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 데이터 분포 변화의 영향 이해 확인 | Covariate Shift, 모델 정확도 하락과의 인과 관계 | 단순히 "데이터가 변함"이라고 모호하게 서술 |
| 통계적 탐지 기법 활용 능력 확인 | PSI, KS-test, KL-divergence, JS-divergence | 탐지 알고리즘 명칭 및 수치 기준 누락 |
| MLOps 대응 전략 수립 확인 | Baseline 관리, 재학습 트리거, 데이터 샘플링 전략 | 장애 조치(Restart 등)와 같은 부적절한 대응 기술 |

> 요약: 학습 데이터의 통계적 속성을 기준으로 운영 데이터의 이질성을 상시 검정하여 모델 신뢰도를 유지하는 방안 제시가 핵심이다.

## Ⅰ. 개요 및 필요성

- 정의: 머신러닝 모델의 입력 특징(X)의 독립 변수 분포가 시간 경과나 환경 변화에 따라 학습 시점과 달라지는 현상
- 배경: 현실 세계의 동적 특성(계절성, 트렌드), 상위 시스템 변경으로 인한 데이터 수집 방식 변화, 센서 결함 등
- 필요성: 모델의 '소리 없는 실패(Silent Failure)' 조기 발견, 재학습(Retraining)의 정량적 근거 마련, 데이터 품질 보증

---

## Ⅱ. 구조 및 구성요소

```text
Training Set (Reference) vs Live Stream (Current)
           |                     |
           +----------+----------+
                      |
           Statistical Test (PSI/KS) -> Drift Score -> Threshold Check -> Alert
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Reference Data | 학습 시 사용된 데이터의 통계적 기준점 | Baseline 데이터셋 |
| Current Data | 현재 운영 환경에서 수집되는 실시간/배치 데이터 | Sliding Window 적용 |
| Statistical Engine | 두 분포의 차이를 수치화하는 알고리즘 | PSI, KS-test 등 |
| Alerting Logic | 임계치 초과 시 담당자 및 시스템 알람 | MLOps 파이프라인 연동 |

> 요약: 기준 데이터와 현재 데이터의 분포 차이를 통계적으로 수치화하여 이상 유무를 판별함.

---

## Ⅲ. 동작원리 및 흐름도

```text
데이터 프로파일링 -> Baseline 저장 -> 실시간 데이터 수집 -> 구간별 분포 산출 -> 통계적 검정 실행 -> 드리프트 점수 산출 -> 대응 실행
      |                 |                |                 |                   |                   |
      +-----------------+----------------+-----------------+-------------------+-------------------+-----> 재학습/데이터 보정
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | Reference 데이터 통계 요약 | 평균, 표준편차, 10분위수 기록 |
| 2 | Current 데이터 통계 산출 | 최근 24시간 또는 1,000건 단위 |
| 3 | 분포 간 거리/차이 계산 | PSI > 0.1 (경고), 0.2 (심각) |
| 4 | 유의미한 변화 판단 | P-value < 0.05 (통계적 유의) |

> 요약: 특징별 분포의 변화를 상시 모니터링하여 설정된 임계치(Threshold)를 벗어날 경우 위험 신호로 간주함.

## Ⅳ. 특징

| 구분 | 주요 탐지 지표 | 특징 및 용도 | 판단 포인트 |
|:---|:---|:---|:---|
| PSI | Population Stability Index | 범주형/수치형 데이터의 분포 안정성 | 금융권 표준 지표 |
| KS-test | Kolmogorov-Smirnov | 두 분포의 누적 분포 함수 차이 비교 | 민감한 이상 탐지 |
| KL-div | KL Divergence | 정보 이론 기반의 분포 간 정보 손실량 | 비대칭적 거리 측정 |
| MMD | Max Mean Discrepancy | 고차원 데이터(이미지 등) 분포 비교 | 비정형 데이터 적용 |

> 요약: 데이터의 유형(범주형/연속형)과 차원의 수에 따라 적절한 통계적 검정 방법을 선택하여 적용함.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | Data Drift (Covariate Shift) | Concept Drift (Prior Probability Shift) | 선택 기준 |
|:---|:---|:---|:---|
| 변화 대상 | 입력값의 분포 $P(X)$ | 입력-정답 간 관계 $P(Y \mid X)$ | 변화의 위치 |
| 정답 필요성 | 불필요 (입력만으로 탐지 가능) | 필수 (실제 결과 확인 필요) | 탐지 신속성 |
| 탐지 시점 | 운영 초기 즉시 탐지 가능 | 정답 확보 후 사후 탐지 | 대응 골든타임 |

> 요약: Data Drift는 정답 없이도 탐지가 가능하므로, 성능 하락을 예측하는 '선행 지표'로 활용함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| False Alarm | 일시적인 데이터 노이즈/이벤트 | 윈도우 크기 조정 및 이동 평균 적용 | 알람 정확도(Precision) |
| 성능 저하 방치 | 드리프트 발생에도 조치 미흡 | 재학습 자동화 파이프라인 연동 | 모델 가용성 (Uptime) |
| 감지 누락 | 중요하지 않은 변수만 감시 | Feature Importance 기반 가중치 적용 | 중요 변수 감시 커버리지 |

> 요약: 오탐은 통계적 필터링으로, 대응 누락은 자동화로, 감지 누락은 중요도 기반 가중치로 해결함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 드리프트 감지 시간 | 발생 후 1시간 이내 | 실시간 분석 레이턴시 측정 |
| 특징 감시 범위 | 핵심 특징 90% 이상 포함 | 모니터링 변수/전체 변수 비율 |
| 재학습 유효성 | 재학습 후 성능 95% 복구 | 재학습 전후 정확도 비교 |

> 요약: 도입 효과는 탐지 신속성, 감시 범위의 포괄성, 재학습을 통한 성능 복구율로 측정함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 선제적 장애 예방: 고객의 연령대 분포가 급격히 변하는 Data Drift 감지 시, 실제 모델 정확도가 떨어지기 전에 "데이터 편중 알람"을 발생시켜 사전 조치
2. 데이터 품질 관리: 센서 데이터의 값이 특정 범위(Baseline)를 지속적으로 벗어날 경우, 하드웨어 결함이나 통신 오류로 판단하여 데이터 정제 프로세스 실행
3. 가중치 기반 샘플링: 드리프트가 발생한 최신 데이터에 더 높은 가중치를 두어 재학습함으로써 변화된 환경에 빠르게 적응하는 모델 생성

**결론 (2줄):**
- 기술사 판단: Data Drift 관리는 모델이 현실을 반영하는 '유통기한'을 체크하는 작업이며, 지속 가능한 AI 서비스를 위한 핵심 품질 지표임
- 향후 방향: 단순 통계 비교를 넘어, 비정형 데이터(텍스트, 이미지)의 시맨틱 드리프트를 감지하는 임베딩 기반 모니터링으로 진화할 것임
