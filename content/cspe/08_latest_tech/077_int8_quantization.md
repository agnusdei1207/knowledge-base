## 미리 알고가기

- $INT8$ 양자화: 모델의 $FP16$ 실수 가중치를 8비트 정수 포맷($-128 \sim 127$)으로 맵핑하여 용량을 딱 절반으로 절감하는 대중적인 중비트 압축 기술임
- 가중치 및 활성값 양자화 ($W8A8$): 모델 저장 공간 절감을 위한 가중치($W$)와 계산 가속을 위한 활성값($A$)을 둘 다 $8$-bit 정수로 통일하여 곱셈 연산 자체를 $INT8$ 코어에서 구동하는 방식임
- 스무스퀀트 ($SmoothQuant$): 활성값(Activation) 단에 집중된 아웃라이어 연산 난도를 가중치(Weight) 레이어로 수학적으로 이관 융합하여, $W8A8$을 정밀도 붕괴 없이 달성하는 수학적 등가 변환 기술임
- 혼합 정밀도 ($Mixed$ $Precision$): 연산의 안전 보장을 위해, 대부분의 행렬은 $INT8$로 가속 연산하고 핵심 아웃라이어 유입 레이어만 원래의 $FP16$으로 부분 선별 계산하는 기법임

## Ⅰ. 개요

- **정의/개념**: INT8 양자화는 심층 신경망 가중치(Weight) 및 연산 중 도출되는 활성값(Activation)의 데이터 해상도를 8비트 부호 있는 정수 범위로 제한 사상하여, 물리적 메모리(VRAM) 대역폭을 $50\%$ 소거하고 연산 칩의 정수 전용 회로로 초저지연을 실현하는 대표적인 인프라 추론 최적화 기법임
- **배경/필요성**: 부동소수점($FP16$) 규격의 무거운 LLM 서빙은 엄청난 하드웨어 HBM 병목과 호스트 CPU 메모리 낭비를 가져오는데, $INT4$ 대비 정밀도 붕괴 위험이 없으면서도 메모리 병목을 해소할 수 있는 최적의 현실 타협점으로 부상함

## Ⅱ. 특징

- 기저 가중치의 VRAM 물리 점유 공간을 원본 대비 정확히 $50\%$ 스케일로 압축하여, 추가 서버 증설 비용 없이 GPU 1대당 동접자 수용 한계를 2배로 확장함
- 대부분의 현대 가속기(Nvidia GPU, Google TPU, 모바일 NPU 등) 하드웨어가 $INT8$ 데이터 행렬 곱셈($DP4A$ 등)을 물리 레벨에서 고속 가속 지원함
- 단순 파일 크기만 줄여주는 '가중치 전용 양자화(Weight-only)'와 달리, 활성값($Activation$)까지 엮어 곱하는 $W8A8$ 기법은 순수 정수 연산 가속을 제공함

## Ⅲ. 종류 및 비교

| 판단 기준 | 기본 오리지널 모델 ($FP16$ 유지) | $INT8$ 양자화 (W8A8) | $INT4$ 양자화 (W4A16 / W4A8) |
|:---|:---|:---|:---|
| **가중치 점유율** | $100\%$ (기준 용량 소모) | $50\%$ 수준으로 균일 절감 | $25\%$ 수준으로 극한 절감 |
| **추론 속도 가속** | 기준선 (메모리 대역 포화) | 우수함 (순수 정수 연산 커널 가동) | 매우 우수함 (VRAM 병목은 최소화되나 역양자화 비용 존재) |
| **품질 유지 안전성** | 완벽함 (품질 손실 없음) | 매우 우수함 (정밀도 손실 체감 불가) | 보통 (특수한 아웃라이어에 약함) |
| **캘리브레이션 요건** | 불필요함 | 보통 수준의 보정 데이터 필요 | 고난도의 보정 및 스케일 튜닝 필요 |

> 요약: FP16은 학습 가이드 기준이고, INT8은 서버 인프라 양산 배포의 안전한 마지노선이며, INT4는 메모리 한계를 극복하기 위한 최선책임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 스케일 매핑 벡터 | 각 행렬 채널별 부동소수를 8비트 공간인 $[-128, 127]$로 안전히 축소하는 사상 벡터임 |
| $INT8$ 텐서 코어 | GPU 하드웨어 내부에서 정수 8비트 곱셈과 32비트 누적 연산을 지원하는 가속 가동 코어임 |
| 동적 스케일 조율기 | 입력 텍스트 분포 변화에 맞춰 활성값의 양자화 스케일을 실시간 재계산하는 매니저임 |
| 스무스퀀트 모듈 | 활성값의 튀는 에너지를 가중치 채널에 균등 분할 흡수시키는 등가 수학 공식임 |

```text
[ SmoothQuant (스무스퀀트) 원리 ]
Activation (X) --(수학적 등가곱: X * S)------------------------->  Activation' (쉽게 INT8 양자화)
Weight (W)     --(가중치 채널에 인접 나눔: W / S)---------------->  Weight' (안정적 INT8 양자화)
- 활성값의 아웃라이어 피크를 가중치로 골고루 흘려주어, W8A8의 지능 붕괴를 예방함
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 오리지널    | --> | 스무스퀀트   | --> | 캘리브레이션| --> | INT8 텐서   |
| 모델 프로파일|     | 가중치 재조정|     | 스케일 사상 |     | 커널 가속추론|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **에너지 계측** — 원본 모델 가중치와 대표 유입 문장(Calibration)의 활성값 채널 강도를 대조 분석함
2. **SmoothQuant 적용** — 활성값 채널 중 유독 에너지가 솟구치는 특정 아웃라이어 라인을 찾아, 가중치 행렬 해당 행에 나눗셈 등가 변환을 실행함
3. **정수 범위 치환** — 정제된 가중치 행렬과 활성값 범위를 $INT8$ 정밀도로 최종 스케일 클리핑하고 바이너리를 추출함
4. **저정밀 추론 기동** — C++ 추론 런타임을 구동하여, GPU 텐서 코어의 $INT8$ 하드웨어 커널을 작동시키고 SSE 스트림을 방출함

## Ⅵ. 실무 적용 및 유의점

1. 활성값까지 $INT8$로 강제 압축($W8A8$)할 때, 특정 채널의 이상 아웃라이어 데이터가 잘려 나가 문맥 추론 능력이 훼손되는 현상이 생길 수 있으므로, 반드시 '스무스퀀트($SmoothQuant$)'를 융합하여 아웃라이어 채널 오류율을 제어하고 실서비스 지능 손실을 방지해야 함
2. 기기 내에서의 전처리 오버헤드와 정수 커널의 컴파일 에러 발생 시, 오히려 역양자화 형변환 병목으로 성능이 더 느려질 수 있으므로, 반드시 '하드웨어 프로파일러'를 켜고 실제 응답 지연 시간($Latency$) 단축 여부와 초당 토큰 처리량($Tokens/Sec$) 향상 폭을 계측해야 함

## Ⅶ. 결론

- INT8 양자화는 상영상용 LLM 서비스의 인프라 단가와 추론 정밀도 보존력을 완벽히 융합해 내는 현대 AI 최적 배포의 가장 표준적인 교과서이며, 설계자는 단순 가중치 압축을 넘어 활성값 아웃라이어 붕괴를 극복할 스무스퀀트 기술과 실질 하드웨어 가속 프로파일링을 보장해야 함
