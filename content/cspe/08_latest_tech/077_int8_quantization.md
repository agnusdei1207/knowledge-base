## 미리 알고가기

- INT8은 8비트 정수 표현으로 양자화의 가장 보편적인 실무 기준점임
- 서버용 GPU, TPU, CPU 라이브러리에서 지원이 넓어 배포 난도가 상대적으로 낮음
- INT4보다 품질 보존력이 높고 FP16보다 비용 절감 효과가 커 실무 타협점으로 자주 선택됨

## Ⅰ. 개요

- **정의/개념**: INT8 양자화는 모델의 가중치와 활성값을 8비트 정수 범위로 매핑해 메모리 사용량을 줄이고 정수 연산 경로를 활용하는 대표 추론 최적화 방식임
- **배경/필요성**: FP16만으로는 대형 모델 서빙 비용과 메모리 병목을 완화하기 어려우므로, 품질 손실을 크게 키우지 않으면서 운영 효율을 높이는 표준적인 저정밀 경로가 필요함

## Ⅱ. 특징

- 메모리 절감과 품질 보존의 균형이 좋아 서버 추론과 엣지 추론 모두에 폭넓게 적용됨
- 정적 calibration과 동적 scaling 전략을 통해 다양한 입력 분포에 대응할 수 있음
- INT4보다 품질 안정성은 높지만 메모리 절감 폭은 제한적이어서 초경량 환경에는 부족할 수 있음
- outlier와 activation 분포가 큰 모델에서는 단순 일괄 적용보다 보정 기법이 중요함

## Ⅲ. 종류 및 비교

| 판단 기준 | FP16 | INT8 | INT4 |
|:---|:---|:---|:---|
| 메모리 사용 | 높음 | 중간 | 낮음 |
| 품질 안정성 | 매우 높음 | 높음 | 중간 |
| 배포 난도 | 낮음 | 중간 | 높음 |
| 대표 용도 | 기준 추론 | 범용 상용 추론 | 초경량 배포 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Scale, Zero-point | 부동소수 값을 8비트 정수 범위에 대응시키는 기준을 정의해 정밀도 손실을 통제함 |
| Calibration Pass | 대표 입력을 흘려보내 activation 범위와 clipping 한계를 조정함 |
| Quantized Weights, Activations | 메모리 점유를 줄이면서 정수 연산 경로를 가능하게 하는 실제 추론 데이터 형태임 |
| INT8 Runtime | CPU, GPU, TPU의 저정밀 커널을 사용해 양자화 모델의 이점을 실성능으로 연결함 |

```text
+-------------------+      +-------------------+      +-------------------+
| Calibration Pass  | ---> | Scale / ZP        | ---> | INT8 Runtime      |
+-------------------+      +-------------------+      +-------------------+
                                   |
                                   v
                           +-------------------+
                           | Quantized W/A     |
                           +-------------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 분포 분석      | --> | 스케일 결정    | --> | INT8 변환     | --> | 정수 연산 추론   |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **분포 분석**: 레이어별 가중치와 활성값의 범위를 측정함
2. **스케일 결정**: 정적 또는 동적 방법으로 양자화 스케일을 산정함
3. **INT8 변환**: 파라미터와 필요 시 activation을 8비트 정수로 저장함
4. **정수 연산 추론**: 런타임이 INT8 커널로 추론을 수행하고 결과를 복원함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 극단값이 일부 채널에 몰린 모델은 INT8 범위 안에 모든 값을 넣는 과정에서 일반 값의 해상도가 낮아질 수 있음
   - 해결방안: SmoothQuant나 mixed precision을 적용하고 outlier channel error와 task accuracy로 품질을 검증함
2. 문제: activation까지 INT8로 줄일 때 입력 패턴 변화가 크면 특정 장면이나 프롬프트에서 오차가 커질 수 있음
   - 해결방안: calibration 샘플을 운영 분포와 맞추고 p95 error와 production regression rate로 안정성을 검증함
3. 문제: 장비가 INT8 연산을 지원해도 프레임워크 경로가 맞지 않으면 실제 처리량 향상이 제한될 수 있음
   - 해결방안: 지원 런타임을 표준화하고 benchmark 대비 throughput gain으로 배포 효과를 검증함

## Ⅶ. 적용 사례

- 기업용 LLM API가 FP16 대비 메모리를 줄여 동시 접속을 늘리도록 INT8 양자화를 적용하며 확인 지표는 GPU memory usage와 p95 latency임
- 차량 비전 추론이 TensorRT INT8 엔진으로 응답 속도를 높이도록 배포하며 확인 지표는 FPS와 inference latency임
- CPU 기반 문서 분류가 INT8 모델로 범용 서버 비용을 절감하도록 운영하며 확인 지표는 throughput과 cost per request임

## Ⅷ. 결론

INT8 양자화는 품질과 비용과 호환성의 균형이 가장 좋아 대형 모델 서빙과 엣지 추론에서 기본값으로 고려할 만한 실무형 최적화 방식임.
