# 📖 【암기용】 개념 완전 이해

> 목적: 메달리온 아키텍처를 레이크하우스 데이터를 Bronze, Silver, Gold 단계로 정제하는 계층 패턴으로 이해하게 만든다.

## 한눈에
- **개요**: 원천 데이터를 Bronze, 정제 데이터를 Silver, 업무용 집계를 Gold로 나누는 레이크하우스 설계
- **왜 필요한가**: 원천 파일, 정제 테이블, BI 집계가 섞이면 재처리·품질 추적·권한 분리가 어려워진다.
- **핵심 직관**: 광석을 캐서(Bronze) 불순물을 제거하고(Silver) 제품으로 가공하는(Gold) 흐름이다.

## 깊이 이해
- **배경·문제의식**: 데이터 레이크는 저장 비용과 확장성은 확보했지만 원천과 소비 데이터를 같은 공간에 두면 신뢰 수준이 불명확해진다.
- **작동 원리**: Bronze는 원천을 거의 그대로 보존하고, Silver는 정합성·중복·스키마를 정리하며, Gold는 KPI·feature·mart처럼 소비 목적에 맞게 모델링한다.
- **비유**: 택배 물류에서 입고장, 검수장, 출고 포장장이 분리되어야 오류가 난 위치와 책임을 추적할 수 있다.
- **구체 예시**: 클릭 로그는 Bronze에 원본 JSON으로 적재하고, Silver에서 사용자·세션 기준으로 정제한 뒤, Gold에서 일별 전환율 mart를 제공한다.
- **흔한 오해·주의점**: 모든 조직이 반드시 3계층만 써야 하는 것은 아니다. 민감정보 격리, feature serving, sandbox 목적에 따라 landing·platinum 계층을 추가할 수 있다.

## 연결 개념
- Lakehouse — 객체 저장소와 테이블 포맷을 결합한 분석 플랫폼
- Delta Lake/Apache Iceberg — ACID, schema evolution, time travel을 제공하는 테이블 포맷
- Data Quality — 계층 전환 시 검증 규칙으로 신뢰 수준을 올림

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.
> 핵심: 메달리온 아키텍처는 데이터 신뢰 수준을 계층화해 원천 보존, 정제, 업무 소비를 분리하는 레이크하우스 패턴임.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Bronze, Silver, Gold 계층으로 데이터 품질과 소비 목적을 단계적으로 분리하는 레이크하우스 설계 패턴임.
> 2. **가치**: 원천 재처리, 품질 추적, 소비 권한, 비용 관리를 계층 단위로 분리함.
> 3. **판단 포인트**: 계층별 저장 형식, 검증 규칙, lineage, 권한, 재처리 전략을 함께 정의해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 레이크하우스 데이터 구조 이해 확인 | Bronze/Silver/Gold 역할 구분 | 계층명을 단순 저장 위치로 설명 |
| 품질·재처리 설계 판단 확인 | 원천 보존, 정제 검증, 업무 mart | Gold 계층만 평가 대상으로 서술 |
| 운영 통제 이해 확인 | lineage, 권한, 비용, SLA | ETL 도구 나열로 대체 |

> 요약: 이 문제는 계층명을 외우는 것이 아니라 데이터 신뢰 수준과 소비 목적을 분리하는 설계를 묻는다.

## Ⅰ. 개요 및 필요성

- 개요: 레이크하우스 계층화 패턴
- 배경: 원천·정제·집계 데이터가 섞이면 재처리와 오류 추적 기준이 불명확함.
- 필요성: 데이터 품질 수준과 소비 목적을 Bronze/Silver/Gold로 분리해 신뢰 경계를 명확히 해야 함.

---

## Ⅱ. 구조 및 구성요소

```text
Source System -> Bronze Raw -> Silver Cleaned -> Gold Curated
                       +-> Lineage / Quality / Access Policy
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Bronze | 원천 데이터 보존 | append-only, raw format, replay |
| Silver | 정제·표준화 데이터 | dedup, schema enforcement |
| Gold | 업무·AI 소비 데이터 | mart, feature, KPI |
| 거버넌스 | 계층별 권한·품질·lineage 관리 | catalog, policy, audit |

> 요약: 메달리온 구조는 원천 보존, 정제, 소비 목적 모델을 분리해 데이터 신뢰 수준을 계층으로 표현한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
원천 수집 -> Bronze 적재 -> 품질 검사 -> Silver 정제
-> 업무 규칙 적용 -> Gold mart / feature 제공 -> 소비·모니터링
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 원천 파일·이벤트를 Bronze에 적재함 | ingestion completeness |
| 2 | Silver에서 중복·타입·코드값을 정제함 | schema, uniqueness |
| 3 | Gold에서 KPI·mart·feature로 모델링함 | business rule validation |
| 4 | 소비 품질과 lineage를 모니터링함 | freshness, consumer SLA |

> 요약: 계층 전환은 단순 복사가 아니라 검증 규칙을 통과하며 신뢰 수준을 올리는 과정이다.

---

## Ⅳ. 특징

| 구분 | Bronze | Silver | Gold |
|:---|:---|:---|:---|
| 데이터 상태 | 원천 보존 | 정제·표준화 | 업무 목적 모델 |
| 주요 사용자 | 데이터 엔지니어 | 분석가·ML 엔지니어 | BI·서비스·경영 지표 |
| 품질 기준 | 적재 완전성 | 스키마·중복·정합성 | KPI 규칙·SLA |
| 권한 범위 | 제한 접근 | 내부 분석 접근 | 소비자 권한 기반 |

> 요약: 각 계층은 데이터 상태, 사용자, 품질 기준, 권한 범위가 달라야 한다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 단일 데이터 레이크 | Bronze/Silver/Gold 계층 | 재처리·품질 추적 필요 |
| 품질 | 소비 시점 검증 | 계층 전환 검증 | 데이터 제품화 요구 |
| 비용 | 중복 저장 최소 | 계층별 중복 허용 | 저장 비용 대비 신뢰성 |

> 요약: 데이터 소비자가 많고 재처리 요구가 크면 계층 중복 저장 비용보다 신뢰 경계가 더 큰 가치가 된다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 계층 혼선 | Silver와 Gold 기준 미정의 | 계층별 품질·소비 기준 문서화 | misrouted table 비율 |
| 저장 비용 증가 | 무분별한 계층 복제 | retention·partition 정책 적용 | storage cost by layer |
| 품질 전파 | Bronze 오류가 Gold로 이동 | 계층 전환 품질 게이트 | quality failure rate |

> 요약: 계층 기준, 보존 정책, 품질 게이트를 정하지 않으면 메달리온 구조는 폴더 구분에 머문다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 계층 준수 | 테이블별 계층·owner 명시 | catalog audit |
| 품질 | Silver/Gold 검증 규칙 실행 | dbt test, DQ dashboard |
| 재처리 | Bronze 기반 replay 가능 | lineage와 job run 기록 |

> 요약: 운영 성과는 계층 명명보다 검증 규칙과 재처리 가능성으로 확인한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. Bronze는 원천 변경 이력을 보존하고 partition, retention, schema evolution 정책을 데이터 소스별로 정의함.
2. Silver 전환에는 중복 제거, 타입 검증, 참조 무결성, 민감정보 마스킹을 품질 게이트로 적용함.
3. Gold는 KPI mart, feature table, Data Product 단위로 owner와 SLA를 지정하고 소비자 권한을 분리함.

**결론 (2줄):**
- 기술사 판단: 재처리와 데이터 신뢰 추적이 필요한 레이크하우스는 메달리온 계층을 적용하고, 소규모 단발 분석은 과도한 계층화를 피함.
- 향후 방향: 메달리온 아키텍처는 Data Contract와 Open Table Format을 결합해 AI·BI 공통 신뢰 계층으로 확장됨.
