## 미리 알고가기

- 온디바이스 AI는 클라우드가 아닌 사용자 기기 내부에서 추론을 수행하는 방식임
- NPU와 경량 모델은 온디바이스 AI의 실현을 뒷받침하는 핵심 기반임
- 온디바이스 AI는 모든 작업을 로컬로 처리하기보다 클라우드와 분담하는 하이브리드 구조가 흔함

## Ⅰ. 개요

- **정의/개념**: 온디바이스 AI는 스마트폰, PC, 차량, IoT 장치 같은 종단 기기 내부에서 데이터를 수집하고 경량 모델로 추론해 결과까지 로컬에서 처리하는 AI 실행 방식임
- **배경/필요성**: 생성형 AI 수요가 커질수록 클라우드 비용과 개인정보 전송 부담이 증가하므로, 지연 시간을 줄이고 데이터 주권을 높이는 로컬 추론 구조가 필요함

## Ⅱ. 특징

- 네트워크 연결이 불안정하거나 없는 환경에서도 즉시 응답할 수 있음
- 개인 데이터가 기기 밖으로 나가지 않아 프라이버시와 규제 대응 측면에서 유리함
- 배터리, 발열, 메모리 제약 때문에 모델 크기와 실행 정책을 엄격히 설계해야 함
- 복잡한 요청은 클라우드로 넘기는 하이브리드 오케스트레이션이 실용성의 핵심임

## Ⅲ. 종류 및 비교

| 판단 기준 | 클라우드 AI | 온디바이스 AI | 엣지 AI |
|:---|:---|:---|:---|
| 실행 위치 | 원격 데이터센터 | 사용자 기기 내부 | 현장 근처 장비나 게이트웨이 |
| 지연 시간 | 네트워크 영향 큼 | 매우 낮음 | 낮음 |
| 데이터 주권 | 상대적으로 약함 | 매우 강함 | 강함 |
| 처리 범위 | 대규모 범용 처리 | 개인화, 실시간 보조 | 현장 제어, 센서 분석 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Local Model | 경량 언어 모델이나 비전 모델을 탑재해 기기 내부에서 핵심 추론을 수행함 |
| Device Accelerator | NPU, GPU, DSP가 연산을 분담해 응답성과 전력 효율을 맞춤 |
| Personal Context Store | 사진, 메일, 캘린더 같은 로컬 데이터를 기기 내에서만 활용해 개인화 품질을 높임 |
| Routing Controller | 로컬 처리와 클라우드 오프로딩을 판단해 품질과 비용과 배터리 균형을 맞춤 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 입력 수집     | --> | 로컬 전처리   | --> | 기기 내 추론   | --> | 로컬 응답/오프로딩 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **입력 수집**: 음성, 텍스트, 이미지, 센서 데이터를 기기에서 직접 수집함
2. **로컬 전처리**: 개인정보를 외부로 보내지 않고 토큰화나 특징 추출을 수행함
3. **기기 내 추론**: 경량 모델과 가속기를 이용해 로컬 응답을 생성함
4. **로컬 응답 또는 오프로딩**: 단순 요청은 바로 처리하고 복잡한 요청만 정책에 따라 클라우드로 넘김

## Ⅵ. 문제점 및 해결 방안

1. 문제: 기기 메모리와 배터리 제약이 크면 모델 탑재와 지속 실행이 어려워 사용자 경험이 불안정해질 수 있음
   - 해결방안: 양자화와 workload routing을 적용하고 memory footprint와 battery drain per task로 효율을 검증함
2. 문제: 기기 종류와 칩셋이 다양하면 동일 모델을 일관되게 배포하고 업데이트하기가 어려움
   - 해결방안: 기기군별 모델 카탈로그와 OTA 배포 체계를 운영하고 rollout success rate와 crash rate로 배포 품질을 검증함
3. 문제: 로컬 모델이 감당하기 어려운 복합 질의까지 모두 처리하려 하면 품질 저하가 쉽게 발생함
   - 해결방안: 클라우드 오프로딩 정책을 분리하고 local completion rate와 fallback accuracy로 처리 경계를 검증함

## Ⅶ. 적용 사례

- 스마트폰 실시간 번역: 음성과 텍스트를 로컬에서 처리함, 확인 지표는 response time과 battery drain임
- 메일 및 메모 요약: 개인 데이터가 기기 밖으로 나가지 않게 구성함, 확인 지표는 privacy compliance와 task success rate임
- 차량 내 음성 비서: 네트워크 불안정 구간에서도 명령을 처리함, 확인 지표는 offline success rate와 command latency임

## Ⅷ. 결론

온디바이스 AI는 프라이버시와 실시간성이 중요한 서비스에서 가장 현실적인 실행 방식이지만, 하드웨어 제약을 전제로 한 경량 모델 설계와 하이브리드 라우팅 정책이 함께 갖춰져야 성립함.
