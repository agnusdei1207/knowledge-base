# 📖 【암기용】 개념 완전 이해

> 목적: 온디바이스 AI를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: 클라우드 전송 없이 스마트폰·PC·차량·IoT 단말 내부에서 AI 추론을 수행하는 방식
- **왜 필요한가**: 네트워크 지연·개인정보 반출·클라우드 비용 문제를 단말 내부 처리로 줄임.
- **핵심 직관**: 질문을 본사 서버에 매번 보내지 않고, 현장 직원이 단말 안에서 즉시 판단하는 구조임.

## 깊이 이해
- **배경·문제의식**: 카메라·음성·센서 데이터는 민감하고 실시간성이 강함. 클라우드 왕복은 50~200ms 이상 지연과 데이터 반출 리스크를 만들 수 있음.
- **작동 원리**: 모델을 pruning·quantization·distillation으로 경량화하고, NPU/GPU/DSP에서 추론함. 민감 데이터는 단말에 남기고, 필요한 요약·메타데이터만 서버와 동기화함.
- **비유**: 의료 영상의 1차 판독을 현장 장비가 하고, 이상 케이스만 중앙 전문의에게 보내는 방식임.
- **구체 예시**: 음성 wake word, 카메라 객체 탐지, 키보드 추천, 로컬 LLM 요약은 p95 100ms 이하 지연이 요구됨.
- **흔한 오해·주의점**: 온디바이스는 클라우드가 필요 없다는 뜻이 아님. 모델 업데이트, 학습, 정책 동기화는 서버와 결합됨.

## 연결 개념
- Edge AI — 현장 인프라 포함 개념
- NPU — 온디바이스 AI 가속 하드웨어
- Federated Learning — 단말 데이터 보호 학습 방식

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: On-Device AI는 AI 추론을 단말 내부에서 수행해 지연·비용·개인정보 반출을 줄이는 구조임.
> 2. **가치**: 네트워크 불안정 환경에서도 실시간 추론과 로컬 데이터 보호를 동시에 달성함.
> 3. **판단 포인트**: 모델 크기, 전력, NPU 지원, 업데이트, 클라우드 fallback을 통합 설계해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 로컬 추론 구조 이해 확인 | 경량 모델+NPU 런타임+fallback 3요소, TOPS/Watt | 클라우드 AI 설명 반복 |
| 배치 위치 판단 확인 | 지연·프라이버시·비용 3축의 온디바이스/클라우드 분담 기준 | 온디바이스를 만능으로 단정 |
| 운영 제약 인식 확인 | 전력·발열·모델 업데이트(OTA)·정확도 열세 관리 | 배포 이후 운영(OTA·drift) 누락 |

> 요약: 이 문제는 기술 나열이 아니라 어떤 기능을 단말에 두고 무엇을 클라우드로 위임할지의 분담 설계를 묻는다.

## Ⅰ. 개요 및 필요성

- 개요: 단말 내부 AI 추론 방식
- 배경: 네트워크 지연, 개인정보 반출, 클라우드 호출 비용은 모바일·PC 상시 AI 기능의 제약이 됨.
- 필요성: Core ML·NNAPI·ONNX Runtime과 NPU/GPU/DSP를 활용해 오프라인 추론, PII 로컬 처리, TOPS/Watt 기준을 관리해야 함.

## Ⅱ. 구조 및 구성요소

```text
Sensor/User Input -> On-device Runtime -> NPU/GPU/DSP
       -> Local Inference -> Policy Check -> Optional Cloud Sync
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Lightweight Model | 단말 실행 모델 | INT8/INT4, pruning |
| On-device Runtime | 모델 로딩·추론 실행 | Core ML, NNAPI, ONNX Runtime |
| AI Accelerator | NPU/GPU/DSP 연산 | TOPS/Watt 기준 |
| Cloud Fallback | 복잡 요청 원격 처리 | 네트워크·비용 조건 |

> 요약: 온디바이스 AI는 경량 모델, 단말 런타임, AI 가속기, 클라우드 fallback으로 구성됨.

## Ⅲ. 동작원리 및 흐름도

```text
입력 수집 -> 전처리 -> 로컬 추론 -> 신뢰도 판단
    -> 충분: 즉시 응답, 부족: 클라우드 요청 -> 동기화
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 센서·사용자 입력 전처리 | 입력 해상도, token 수 |
| 2 | NPU/GPU 로컬 추론 | p95 latency, mW/token |
| 3 | confidence·정책 판단 | threshold, PII 포함 여부 |
| 4 | fallback·모델 업데이트 | OTA 성공률, 버전 일관성 |

> 요약: 단말에서 우선 추론하고 불확실하거나 고난도인 요청만 클라우드로 위임함.

## Ⅳ. 특징

| 구분 | Cloud AI | On-Device AI | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 지연 | 네트워크 왕복 포함 | 로컬 즉시 처리 | p95 100ms 이하 목표 |
| 개인정보 | 서버 전송 필요 | 단말 내 처리 | PII 반출 감소 |
| 비용 | API/GPU 과금 | 단말 전력 사용 | mW/token, battery |
| 한계 | 대형 모델 가능 | 모델 크기·발열 제한 | fallback 필요 |

> 요약: 온디바이스 AI는 실시간성과 프라이버시에 강하지만 전력·메모리·모델 성능 제한을 관리해야 함.

## Ⅴ. 심화 비교 및 적용 판단

| 기능 유형 | 실행 위치 | 판단 근거 | 선택 기준 |
|:---|:---|:---|:---|
| 음성 인식·카메라 실시간 처리 | 온디바이스 | p95 100ms 이하 요구, 상시 실행 | 지연 SLA가 네트워크 왕복보다 짧으면 로컬 |
| PII 포함 개인 데이터 처리 | 온디바이스 | 반출 최소화, 규제 대응 | 민감도 높으면 로컬 우선 |
| 대규모 지식·복잡 추론 | 클라우드 fallback | 단말 메모리·전력 한계 | confidence 미달·토큰 초과 시 위임 |

> 요약: 지연·민감도·연산 규모 3축으로 기능별 실행 위치를 분담하는 것이 온디바이스 AI 설계의 본질임.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 전력·발열 초과 | 상시 추론, 대형 모델 | INT8/INT4 양자화, NPU 오프로딩 | mW/token, 배터리 소모율 |
| 모델 노후화 | 단말별 버전 파편화 | OTA 업데이트, 버전 최소 지원선 | OTA 성공률, 버전 분포 |
| 정확도 열세 | 경량화로 인한 품질 저하 | fallback 임계값 조정, 하이브리드 | 로컬/클라우드 품질 격차 |

> 요약: 온디바이스 리스크는 전력·파편화·품질이며, 양자화·OTA·fallback 임계값으로 통제함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 음성·카메라 기능은 INT8 모델로 단말 추론하고 p95 100ms, 배터리 소모 5%/h 이하 기준 검증
2. 민감정보 처리 앱은 PII를 단말 내 마스킹하고 서버에는 익명 요약·통계만 전송
3. 복잡 질의는 confidence 0.75 미만 또는 max token 초과 시 클라우드 LLM으로 fallback

**결론 (2줄):**
- 기술사 판단: 실시간·민감 데이터는 온디바이스, 고난도 추론·대규모 지식은 클라우드 AI를 선택함.
- 향후 방향: NPU TOPS 향상과 SLM 경량화로 스마트폰·PC·차량의 로컬 AI 비중이 증가함.
