## 미리 알고가기

- 온디바이스 AI ($On-Device$ $AI$): 클라우드 서버와의 데이터 교신 없이, 스마트폰/PC 등 사용자의 물리 종단 기기 내부 칩셋에서 자체적으로 지능 추론을 처리하는 기술임
- 신경망 처리 장치 ($NPU$): 딥러닝 연산의 다차원 행렬 곱셉과 누적 연산(MAC)을 초저전력으로 고속 가속하는 전용 인공지능 반도체임
- 하이브리드 AI ($Hybrid$): 로컬 기기 내에서 처리 가능한 연산은 온디바이스에서 해결하고, 고난도 추론은 원격 클라우드로 위임 전송하는 이원화 서빙 구조임
- 오프로딩 ($Offloading$): 자원 제약이 있는 환경(로컬 기기)에서 성능 한계를 극복하기 위해 가용한 외부 자원(클라우드 서버 등)으로 무거운 태스크를 던져 대행 연산시키는 기법임

## Ⅰ. 개요

- **정의/개념**: 온디바이스 AI는 스마트폰, 태블릿, 노트북, 지능형 차량 등 사용자의 물리 엔드포인트 기기 내에 고밀도 경량 모델(SLM)과 NPU 하드웨어를 내장하여, 외부 네트워크 연동 없이 원시 데이터를 직접 인코딩하고 즉각 추론 결과를 출력해 내는 로컬 완결형 인공지능 실행 패러다임임
- **배경/필요성**: 클라우드 기반 AI 서비스가 팽창하면서 기하급수적으로 폭증하는 서버 운영 가동비와 프라이버시 기밀 유출, 네트워크 응답 지연 문제가 주된 사회적 병목으로 떠오름에 따라, 사용자 디바이스의 독립된 연산력으로 보안 주권과 초저지연을 달성하고자 부상함

## Ⅱ. 특징

- 망 차단($Offline$) 구간이나 비행기 내 등 외부 기지국 통신 연결이 전면 붕괴한 열악한 극한 조업 시나리오에서도 중단 없는 지능 비서 서비스를 제공함
- 사용자의 개인 문자 메시지, 사진첩 메타데이터가 외부 인터넷 서버로 한 글자도 나가지 않아 유럽 GDPR이나 국내 개인정보보호법 규제를 원천 통과함
- 기기 배터리 소비율, 발열, 메모리(RAM) 용량 한계선에 따라 모델 파라미터 크기 및 연산 가속 런타임 최적화가 필수 동반됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 클라우드 AI (Cloud AI) | 온디바이스 AI (On-Device AI) | 엣지 AI (Edge AI) |
|:---|:---|:---|:---|
| **물리 연산 위치** | 원격 초대형 IDC 센터 | 사용자 로컬 기기 (스마트폰/PC 내부) | 공장/빌딩 내 로컬 게이트웨이 장비 |
| **추론 지연 시간** | 높음 (네트워크 왕복 $100 \sim 300$ms) | 극도로 낮음 (단 수 밀리초 내 처리) | 낮음 |
| **자원 제약성** | 없음 (가용한 클라우드 리소스 무제한) | 매우 큼 (VRAM, 배터리, 발열 제약 엄격) | 중간 (에지 단 서버 성능 한계) |
| **데이터 기밀성** | 외부 노출 우려 (암호화 전송 필요) | 완벽함 (기기 외부 유출 원천 불가) | 우수함 (사내 폐쇄 네트워크 내 격리) |

> 요약: 클라우드는 무제한 지식을 다루는 종합 전술에, 온디바이스는 실시간 개인 비서 및 보안성에, 엣지는 현장 단말 기기 제어에 최적임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 경량 온디바이스 모델 | 메모리 적재를 위해 양자화($4$-bit 등)가 완료된 콤팩트 모델(예: Llama 3.2 1B/3B)임 |
| 모바일 가속 런타임 | ONNX, TensorFlow Lite, ExecuTorch 등 NPU 연산 레지스터를 직접 타격하는 런타임 프레임워크임 |
| 로컬 컨텍스트 매퍼 | 기기 내 메일, 일정, 통화 데이터 등을 SLM의 프롬프트에 동적 융합해 개인화 인지력을 돕는 브리지임 |
| 하이브리드 라우터 | 질의 난이도를 판독하여 클라우드 전송($Offloading$) 여부를 실시간 제어하는 스마트 스위치임 |

```text
[ On-Device AI 구동 프로세스 ]
User Input -> [Hybrid Router] ---> High Difficulty -> [Offload to Cloud LLM]
                              ---> Low Difficulty  -> [On-Device SLM (NPU Accelerated)]
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 센서 데이터 | --> | 온디바이스   | --> | 기기 내 NPU | --> | 로컬 결과   |
| 실시간 유입 |     | 전처리 정돈  |     | 병렬 가속추론|     | 방출/렌더링 |
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **지수 수집** — 기기의 마이크, 카메라, 터치패드 입력 데이터를 로컬 API 프레임워크를 통해 실시간 수집함
2. **토큰 변환** — 모바일 런타임이 동작하여 임베딩 데이터로 변환하고, 기기 내 개인 정보 필터링을 로컬 전처리함
3. **NPU 가속 연산** — 저전력 신경망 가속기($NPU$)의 레지스터 메모리에 임베딩 텐서를 올려 병렬 행렬 곱 연산을 수행함
4. **결과 노출** — 연산 도출된 토큰을 즉시 자연어로 디코딩하여, 사용자 스마트폰 스크린에 버퍼링 없이 즉시 타이핑 렌더링함

## Ⅵ. 실무 적용 및 유의점

1. 스마트폰 내부에서 LLM 추론이 1분 이상 연속 동작하면 칩셋 과열 및 배터리 소모량이 폭증하여 기기가 강제 셧다운될 수 있으므로, 반드시 태스크당 최대 추론 시간 및 토큰 출력 예산 캡을 걸고, 단위 작업당 배터리 소모율($Battery$ $Drain$) 지표를 검증해야 함
2. 시장에 나와 있는 안드로이드/iOS 기기들의 NPU 제조사 규격(Qualcomm, MediaTek, Apple 등)이 서로 달라 모델 이식이 매우 조각나 있으므로, 범용 규격인 'ONNX Runtime'이나 'ExecuTorch' 계열로 추론 커널을 표준화하고, 기기 세대별 실행 크래시($Crash$) 통계 지표로 호환 성능을 모니터링해야 함

## Ⅶ. 결론

- 온디바이스 AI는 클라우드 자원의 경제적 한계와 데이터 프라이버시 침해 우려를 NPU 하드웨어 가속과 경량화 기술로 극복한 지능의 최종 진화이며, 설계자는 하드웨어 파편화 극복을 위한 런타임 표준 수립과 기기 배터리/열 방출 한계를 고려한 라우팅 설계를 제공해야 함
