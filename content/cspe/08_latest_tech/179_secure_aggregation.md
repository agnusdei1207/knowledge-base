# 📖 【암기용】 개념 완전 이해

> 목적: Secure Aggregation을 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: 연합학습에서 개별 참여자의 모델 업데이트를 숨기고 합산 결과만 서버가 알게 하는 암호 프로토콜
- **왜 필요한가**: gradient나 weight update에는 학습 데이터의 일부 정보가 남아 회원 추론·재구성 공격 대상이 될 수 있음.
- **핵심 직관**: 각 사람이 낸 값을 가린 채 전체 합계만 계산하는 비밀 투표함임.

## 깊이 이해
- **배경·문제의식**: 연합학습은 원문 데이터를 보내지 않지만 개별 업데이트가 서버나 공격자에게 노출되면 민감정보가 추론될 수 있다.
- **작동 원리**: 참여자들이 pairwise mask나 secret sharing을 적용해 업데이트를 암호화하고, 서버는 개별값 없이 마스크가 상쇄된 합산값만 얻음.
- **비유**: 각 지점 매출을 공개하지 않고 본사에는 전체 매출 합계만 전달하는 잠금 계산 방식임.
- **구체 예시**: 1,000개 단말이 10MB gradient에 난수 마스크를 적용해 전송하고 서버는 평균 update만 복원함.
- **흔한 오해·주의점**: dropout 참여자가 있으면 마스크 복구 절차가 필요하다. 통신 라운드와 키 관리 비용을 설계해야 함.

## 연결 개념
- Federated Learning — Secure Aggregation의 대표 적용 환경
- Secret Sharing — 마스크·키 복구에 쓰는 암호 기법
- Differential Privacy — 집계값에도 개인 기여도 제한을 추가

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Secure Aggregation은 개별 업데이트를 숨기고 합산값만 공개하는 연합학습 보안 프로토콜임.
> 2. **가치**: 서버·중간자에게 노출되는 gradient leakage와 내부자 위험을 줄임.
> 3. **판단 포인트**: 참여자 dropout, 키 관리, 통신 round 수를 운영 조건에 맞게 설계해야 함.

## Ⅰ. 개요 및 필요성

Secure Aggregation은 암호 기반 집계 기법이다. 연합학습의 모델 업데이트는 원문 데이터가 아니어도 민감정보를 추론할 단서가 될 수 있다. 개별 업데이트를 비공개로 유지하고 합산값만 학습에 사용해야 한다.

## Ⅱ. 구조 및 구성요소

```text
Client Update -> Mask/Share -> Encrypted Upload
  -> Aggregator Sum -> Global Update
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Client | 로컬 업데이트 생성 | gradient/weight delta |
| Masking | 난수 마스크·secret share 적용 | pairwise key 사용 |
| Aggregator | 암호화된 업데이트 합산 | 개별값 미열람 |
| Dropout Recovery | 이탈 참여자 마스크 복구 | threshold 기준 필요 |

> 요약: Secure Aggregation은 클라이언트 마스킹과 서버 합산으로 개별 업데이트를 숨긴 채 평균값만 복원함.

## Ⅲ. 동작원리 및 흐름도

```text
키 교환 -> 업데이트 마스킹 -> 암호 업로드
  -> 마스크 상쇄 -> 집계값 학습 반영
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 참여자 간 키 교환·세션 생성 | mTLS, ECDH |
| 2 | 로컬 업데이트에 난수 마스크 적용 | 개별 update 비노출 |
| 3 | 서버가 암호 업데이트 합산 | dropout ≤20% 허용 |
| 4 | 합산값 복원 후 모델 갱신 | 평균 gradient만 저장 |

> 요약: 보안 집계는 키 교환과 마스킹으로 개별값을 은닉하고 마스크 상쇄 후 합산값만 사용함.

## Ⅳ. 특징

| 구분 | 일반 집계 | Secure Aggregation | 판단 포인트 |
|:---|:---|:---|:---|
| 서버 가시성 | 개별 update 확인 | 합산값만 확인 | 내부자 위험 감소 |
| 보호 범위 | 전송 암호화 중심 | 전송 후 서버 열람 제한 | mTLS 보완 |
| 비용 | 통신 1회 중심 | 키 교환·복구 round 추가 | 대규모 단말 비용 |
| 한계 | gradient leakage 가능 | 악성 update 자체 탐지 제한 | robust aggregation 병행 |

> 요약: Secure Aggregation은 업데이트 기밀성을 제공하지만 악성 참여자 방어와 품질 검증은 별도 설계해야 함.

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 모바일 FL: 단말 1,000개 이상 참여 라운드에서 pairwise mask와 dropout recovery threshold 80% 적용
2. 의료 FL: 병원별 업데이트는 Secure Aggregation으로 합산하고 원문·개별 gradient 저장 금지 정책 적용
3. 보안 운영: mTLS, KMS, 세션키 폐기, 집계 로그 해시를 적용해 라운드별 감사 증적 보관

**결론 (2줄):**
- 기술사 판단: 연합학습에서 개별 업데이트가 민감정보를 포함할 수 있으면 Secure Aggregation을 기본 통제로 적용
- 향후 방향: Secure Aggregation은 DP, robust aggregation, TEE와 결합해 AI 협업 학습의 표준 보안 패턴이 됨
