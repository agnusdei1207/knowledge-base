# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: 연합학습(Federated Learning)에서 개별 참가자(클라이언트)가 서버로 보내는 '모델 가중치(Gradient)'를 암호화하여, **중앙 서버조차 개별 가중치 값은 절대로 볼 수 없게 만들고 오직 '전체 가중치의 합계(평균)'만 풀어서 볼 수 있게 하는** 최고 수준의 암호화 프로토콜.
- **필요성**: 연합학습은 원본 데이터 대신 "가중치"만 보내니까 안전하다고 믿었지만, 해커나 악의적인 서버 관리자가 특정 클라이언트의 가중치를 가로채서 역분석하면 "아, 이 사용자 데이터에 신용카드 번호가 있구나"하고 알아낼 수 있음(Gradient Leakage). 이를 완벽 방어해야 함.
- **핵심 직관**: 비밀 투표와 개표. 수만 명의 사람들이 선거 투표지에 도장을 찍어 냄. 선관위(중앙 서버)가 개별 투표용지를 보면 '누가 누구를 찍었는지(개별 가중치)' 다 알 수 있어서 비밀 투표가 깨짐. 그래서 마법의 투표함을 씀. 투표지를 열어볼 순 없고 오직 버튼을 누르면 '최종 득표수 합계(Aggregation)' 숫자만 짠 하고 튀어나오는 기술.

## 깊이 이해
- **배경**: 구글이 연합학습을 만들고 보니, 클라이언트(스마트폰)가 서버에 보내는 정보가 암호화 통신(TLS)을 타더라도 서버에 도착하면 복호화되어 서버는 낱개의 가중치를 다 볼 수 있는 문제가 있었음. 그래서 2017년 구글 연구진이 'Secure Aggregation' 프로토콜을 제안함.
- **작동 원리 (마스킹과 상쇄, Masking & Cancellation)**:
  1. 철수와 영희가 서버로 자신의 숫자를 보내려 함. 그냥 보내면 서버가 봄.
  2. 철수와 영희는 둘만의 '비밀 난수(랜덤 숫자, 마스크)'를 미리 하나 생성함. (예: 난수 = 100).
  3. 철수는 자기 가중치에 난수를 더함 (+100). 영희는 자기 가중치에 난수를 뺌 (-100).
  4. 암호화된 쓰레기 값(가중치+난수)을 서버로 보냄. 서버는 "이게 무슨 숫자인지 전혀 알 수 없음".
  5. 서버가 철수와 영희의 값을 **단순 더하기(Sum)** 하는 순간! (+100)과 (-100)이 만나 0으로 상쇄(Cancellation)되어 사라지고, 오직 순수한 가중치의 합산 결과만 뿅 하고 튀어나옴.
- **구체 예시**: 3대의 폰이 다음 단어 예측 AI 모델의 가중치를 서버로 보냄. A폰(가중치 3 + 마스크 5), B폰(가중치 4 + 마스크 7), C폰(가중치 2 - 마스크 12). 서버가 이걸 받아서 그냥 다 더하면 (3+4+2) + (5+7-12) = 9. 개별 값은 절대 알 수 없고 오직 총합 '9'만 알게 됨.
- **흔한 오해/주의점**: "한 명이 중간에 폰 꺼져서 (통신 단절) 안 보내면 덧셈이 깨지지 않나?" $\rightarrow$ 맞음(Drop-out 문제). 이를 해결하기 위해 폰이 꺼져도 남아있는 사람들이 상쇄용 마스크를 복원할 수 있게 '비밀 공유(Secret Sharing)'라는 복잡한 암호학 기술이 추가로 결합되어 있음.

## 연결 개념
- **Federated Learning (연합학습)**: 보안 집계가 존재해야 하는 무대. 연합학습의 완성을 위한 필수 짝꿍.
- **Homomorphic Encryption (동형 암호)**: 암호화된 상태로 연산한다는 철학은 같지만, 동형 암호는 CPU를 터뜨릴 만큼 엄청나게 무겁고 느린 반면, 보안 집계는 단순 덧셈/마스킹이라 스마트폰에서도 휙휙 돌아감.
- **Differential Privacy (차등 개인정보보호)**: 보안 집계를 통과해 나온 '합계' 결과마저도 안전하게 하기 위해 노이즈를 섞어버리는 기술. (연합학습 + 보안 집계 + DP 3종 세트로 많이 쓰임).

# 📝 【답안용】 시험 답안 템플릿
## 핵심 인사이트 (3줄 요약)
- **본질**: 연합학습(FL) 환경에서 클라이언트들이 생성한 로컬 모델 파라미터(Gradient/Weight)에 상호 소거되는 무작위 노이즈(Mask)를 더해 서버로 전송하고, 서버는 오직 암호문들의 합산(Aggregation) 결과만 복호화할 수 있도록 설계된 다자간 암호 프로토콜.
- **가치**: 정직하지만 호기심 많은(Honest-but-curious) 중앙 서버를 포함한 어떠한 제3자도 개별 사용자의 파라미터를 들여다보지 못하게 함으로써 가중치 유출 공격(Gradient Leakage Attack)을 수학적으로 완벽히 방어함.
- **판단 포인트**: 이 프로토콜의 핵심 난제는 학습 도중 스마트폰이 꺼지거나 통신이 끊기는 사용자 이탈(Drop-out) 상황에서도 Aggregation을 완수하는 것이며, 이를 위해 샴의 비밀 공유(Shamir's Secret Sharing) 기법을 활용한 키(Key) 복원 메커니즘 아키텍처가 필수적임.

## Ⅰ. 개요 및 필요성
- **정의**: 복수의 사용자가 소유한 프라이빗 데이터를 외부로 노출시키지 않으면서, 서버가 여러 사용자의 벡터 데이터(가중치)의 합(Summation)을 안전하게 계산할 수 있도록 지원하는 암호학적 기법.
- **배경**: 연합학습은 원본 데이터를 보호하지만, 클라이언트가 업로드하는 수백만 개의 차원 가중치 변화량($\Delta W$)을 딥러닝 역전파 역산(Inversion Attack)을 통해 분석하면 원본 이미지를 픽셀 단위까지 복원해 내는 치명적 취약점이 발견됨.
- **필요성**: TLS/SSL과 같은 전송 구간 암호화(In-transit)를 넘어, 연산을 수행하는 서버의 메모리 상에서도 개별 클라이언트의 데이터 기밀성(Confidentiality)을 보장하기 위함.

## Ⅱ. Secure Aggregation의 핵심 메커니즘 (마스킹과 상쇄)
안전한 다자간 연산(SMPC) 기반의 페어와이즈 마스킹(Pairwise Masking).
1. **키 교환 (Key Exchange)**: Diffie-Hellman(DH) 키 교환을 통해 클라이언트 $u$와 $v$ 간에 대칭 공유키 $s_{u,v}$를 생성함.
2. **랜덤 마스크 생성**: 공유키를 시드(Seed)로 사용하는 의사난수생성기(PRNG)를 통해 난수 마스크 벡터 $P_{u,v}$ 생성.
3. **가중치 마스킹 (Masking)**: 클라이언트 $u$는 자신의 가중치 $X_u$에 난수를 더하고 뺌. (서로 짝지어진 노드끼리 부호를 반대로 함).
   - $Y_u = X_u + \sum_{u<v} P_{u,v} - \sum_{u>v} P_{u,v}$
4. **합산 연산 (Aggregation)**: 서버가 암호화된 가중치 $Y$를 모두 더하면, $P_{u,v}$ 마스크 값들이 $(+)$와 $(-)$ 쌍으로 만나 정확히 0으로 상쇄(Cancellation)됨.
   - $\sum Y_u = \sum X_u$ (개별 값은 숨긴 채 총합만 도출 성공).

## Ⅲ. Drop-out(사용자 이탈) 문제 해결 메커니즘
모바일 FL 환경의 핵심 장애물 극복 방안.
- **문제점**: 10명의 클라이언트가 마스킹을 마쳤는데, 전송 단계에서 1명이 오프라인(Drop-out)되면 쌍(Pair)이 맞지 않아 마스크가 상쇄되지 않고 쓰레기 값이 나옴.
- **해결책 (Shamir's Secret Sharing, SSS 적용)**:
  - 통신 시작 전, 각 클라이언트는 자신의 마스크를 생성할 수 있는 비밀키를 조각(Share) 내어 다른 클라이언트들에게 나누어 줌.
  - $t-of-n$ 임계치 구조: 전체 $N$명 중 $t$명(Threshold) 이상만 살아남아 서버에 조각을 제출하면, 이탈한 1명의 마스크 값을 서버가 수학적으로 복원(Reconstruction)하여 빼버림으로써 나머지 살아남은 사용자들의 합산을 정상적으로 완료.

## Ⅳ. 동형 암호(HE) 연산과의 실무적 차이점 비교
| 비교 항목 | Secure Aggregation (SecAgg) | 완전 동형 암호 (FHE) |
|:---:|:---|:---|
| **암호화 대상** | 모델의 파라미터 (Gradient/Weight) | 파라미터 및 원본 데이터 자체 |
| **연산 가능 연산자** | **오직 덧셈(Addition)만 가능** | 덧셈 및 곱셈 무한대 가능 |
| **연산 속도 / 부하** | **매우 빠름 (모바일/엣지 기기 가능)** | 매우 느림 (거대 클라우드 서버 필요) |
| **확장성 제약** | Drop-out 복구로 인한 통신 Round 오버헤드 | 암호문 크기 팽창에 따른 대역폭 포화 |
| **주요 적용처** | 스마트폰 중심의 수백만 대 연합학습 (Cross-device FL) | 병원/은행 등 소수 기관 간의 데이터 결합 학습 |

## Ⅴ. 실무 적용 및 결론
- **판단 지표**: 통신 라운드 당 이탈률(Drop-out Rate) 허용 임계치, 키 생성 및 마스킹 연산에 따른 단말 배터리/CPU 오버헤드, 통신 지연시간.
- **실무 설계**: B 모바일 플랫폼의 자판(키보드) 입력 예측 AI 업데이트 아키텍처 설계. 사용자의 민감한 메신저 대화 패턴이 가중치 역산을 통해 유출될 가능성 지적. Google의 SecAgg 프로토콜 도입. 1,000대의 단말을 하나의 학습 라운드 그룹으로 묶음. 각 단말은 백그라운드에서 Diffie-Hellman 키 교환을 수행하고 비밀 공유(Secret Sharing)를 마침. 로컬 학습 후 가중치에 난수 2GB 분량을 더해 마스킹한 뒤 서버로 전송. 중간에 통신이 끊긴 50대 단말의 마스크는 생존한 950대의 조각을 취합해 서버가 복원하여 상쇄 처리 완료. 서버는 평균 가중치만 취득해 글로벌 모델 업데이트. 원천 데이터 유출 제로 보장.
- **결론**: 보안 집계(Secure Aggregation)는 수학의 대칭성을 이용해 프라이버시와 분산 컴퓨팅의 효율성을 동시에 잡아낸 암호학의 걸작이다. 수십억 대의 IoT 기기가 참여하는 미래의 대규모 연합학습(Massive FL) 생태계에서, 이는 단순한 보안 옵션이 아닌 시스템 가동을 위한 필수 인프라 뼈대가 될 것이다.

### 🔀 문제 유형별 목차 전환
- **Ⅱ·Ⅲ 강조 (개념/원리형)**: Shamir's Secret Sharing(SSS) 알고리즘의 라그랑주 보간법(Lagrange Interpolation)을 이용한 다항식 기반 $t-of-n$ 비밀 복구 메커니즘의 수학적 증명 과정 심도 전개.
- **Ⅴ·Ⅵ 강조 (실무/설계형)**: SecAgg의 가장 큰 약점인 악성 클라이언트의 쓰레기값 투입(Data Poisoning)을 방어하기 위해, 영지식 증명(Zero-Knowledge Proof, ZKP)을 결합하여 가중치가 유효한 범위(Clip bounds) 내에 있음을 증명하는 SecAgg+ 확장 아키텍처.
