## 미리 알고가기

- 보안 집계는 연합학습에서 서버가 개별 업데이트를 보지 못한 채 합계만 계산하게 하는 프로토콜임
- 단순 전송 암호화와 달리 서버 메모리상에서도 개별 값이 드러나지 않도록 설계됨
- 참가자 이탈이 빈번한 환경에서는 drop-out 복구 메커니즘이 핵심임

## Ⅰ. 개요

- **정의/개념**: 보안 집계는 다수의 참여자가 자신의 로컬 모델 업데이트에 상쇄 가능한 마스크를 적용해 전송하고, 서버는 개별 값은 알 수 없지만 전체 합이나 평균만 계산할 수 있게 하는 암호 프로토콜임
- **배경/필요성**: 연합학습은 원본 데이터를 보내지 않아도 가중치 업데이트를 통해 개별 정보가 유추될 수 있으므로, 중앙 서버조차 각 참여자의 업데이트를 보지 못하게 하는 추가 보호가 필요해짐

## Ⅱ. 특징

- 서버가 정직하지만 호기심 많은 환경에서도 개별 업데이트 기밀성을 유지함
- 연합학습과 결합했을 때 gradient leakage 위험을 크게 낮출 수 있음
- 마스킹과 키 교환과 이탈 복구가 필요해 통신 라운드 복잡도가 증가함
- 개별 값 기밀성은 보장하지만 악성 업데이트 자체를 걸러주지는 못해 별도 무결성 통제가 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | Secure Aggregation | TLS 전송 암호화 | Homomorphic Encryption |
|:---|:---|:---|:---|
| 보호 범위 | 서버가 개별 합산값도 못 봄 | 전송 구간만 보호 | 암호문 상태 연산 |
| 연산 특성 | 합산 중심에 최적화 | 계산 없음 | 범용 연산 가능하나 비용 큼 |
| 실무 적합성 | 연합학습 대규모 환경 | 기본 통신 보안 | 고보안 특수 환경 |
| 주요 한계 | drop-out과 악성 클라이언트 | 서버 내부 노출 가능 | 성능 오버헤드 큼 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Pairwise Key Exchange | 참여자 간 공유 마스크를 만들기 위한 키를 교환해 상쇄 구조의 기반을 마련함 |
| Local Masking | 각 참여자가 자신의 업데이트에 난수 마스크를 더해 개별 값이 직접 노출되지 않게 함 |
| Aggregation Server | 마스킹된 값만 모아 합산하고 상쇄 결과를 통해 전체 집계값만 얻음 |
| Drop-out Recovery | 중도 이탈 참여자의 마스크를 복구하거나 제거해 집계 실패를 막음 |
| Integrity Companion Control | 이상 업데이트와 중독 공격을 탐지하는 별도 검증 계층과 함께 운영됨 |

```text
+-------------------+      +-------------------+      +-------------------+
| Key Exchange      | ---> | Local Masking     | ---> | Masked Upload     |
+-------------------+      +-------------------+      +-------------------+
                                                           |
                                                           v
                                                   +-------------------+
                                                   | Aggregate / Recover|
                                                   +-------------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 키/마스크 준비   | --> | 업데이트 마스킹 | --> | 서버 합산 수행  | --> | 이탈 복구/평균 계산 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **키 및 마스크 준비**: 참여자 간 공유 비밀과 마스크를 생성함
2. **업데이트 마스킹**: 각 참여자가 로컬 업데이트를 난수로 가림
3. **서버 합산 수행**: 서버가 마스킹된 값만 받아 더함
4. **이탈 복구 및 평균 계산**: 상쇄되지 않은 마스크를 복구해 최종 집계값을 산출함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 참여자 일부가 중도 이탈하면 마스크 상쇄가 깨져 집계가 실패하거나 라운드 지연이 커질 수 있음
   - 해결방안: secret sharing 기반 drop-out recovery를 적용하고 aggregation success rate와 round completion time으로 검증함
2. 문제: 참여자 수가 많아질수록 키 교환과 마스킹 통신 오버헤드가 커져 모바일 환경에서 비용이 상승할 수 있음
   - 해결방안: communication-efficient SecAgg를 적용하고 bytes per round와 client energy usage로 검증함
3. 문제: 보안 집계는 기밀성만 강화할 뿐 악성 업데이트 주입을 직접 막지 못해 poisoned model이 집계될 수 있음
   - 해결방안: robust aggregation과 anomaly filtering을 결합하고 poisoning detection rate와 model integrity score로 검증함

## Ⅶ. 적용 사례

- 모바일 키보드 연합학습이 개별 사용자의 업데이트를 숨긴 채 평균 모델을 계산하며 확인 지표는 aggregation success rate와 leakage attack success rate임
- 병원 공동 학습이 기관별 파라미터를 직접 노출하지 않고 집계되며 확인 지표는 secure round completion rate와 diagnostic AUC임
- 금융 연합 모델이 계열사별 업데이트를 마스킹해 집계하며 확인 지표는 unauthorized update visibility rate와 round latency임

## Ⅷ. 결론

보안 집계는 연합학습에서 데이터 비이동 원칙을 개별 업데이트 기밀성까지 확장하는 핵심 프로토콜이므로, 이탈 복구와 무결성 통제를 함께 설계해야 실무에서 안정적으로 작동함.
