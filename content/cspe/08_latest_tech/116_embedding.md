# 📖 【암기용】 개념 완전 이해

> 목적: Embedding을 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **정의**: 텍스트·이미지·코드 같은 데이터를 의미를 보존한 숫자 벡터로 변환한 표현
- **왜 필요한가**: 컴퓨터는 문장의 뜻을 직접 비교하지 못하므로, 의미가 가까운 데이터를 가까운 좌표로 바꿔야 함.
- **핵심 직관**: 단어와 문서의 의미를 지도 위 좌표로 바꾸어 거리 계산이 가능하게 만드는 기술임.

## 깊이 이해
- **배경·문제의식**: 원문 문자열은 "환불"과 "반품"의 의미적 거리를 알 수 없다. 검색·추천·분류에는 의미 기반 수치 표현이 필요함.
- **작동 원리**: Transformer 인코더가 토큰 문맥을 계산하고 pooling으로 문장 벡터를 만들며, contrastive learning으로 관련 문장은 가깝고 무관 문장은 멀게 학습함.
- **비유**: 사람의 취향·문서 주제·질문 의도를 같은 좌표계에 찍어 가까운 점끼리 묶는 작업임.
- **구체 예시**: OpenAI text-embedding-3-small은 1,536차원, BGE-M3는 1,024차원 벡터를 생성하며 RAG 검색 입력으로 사용됨.
- **흔한 오해·주의점**: 차원이 높다고 항상 답변 품질이 높지는 않음. 도메인 적합도, 청킹, 정규화, 거리 함수가 함께 맞아야 함.

## 연결 개념
- Dense Retrieval — 임베딩 벡터를 이용한 의미 검색
- Vector Database — 임베딩을 저장하고 ANN 검색을 수행하는 저장소
- Contrastive Learning — 관련/무관 쌍으로 임베딩 공간을 학습하는 방식

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Embedding은 비정형 데이터를 의미 벡터로 변환해 거리 계산과 검색을 가능하게 하는 표현임.
> 2. **가치**: RAG·추천·중복 탐지에서 의미 유사도 기반 Top-K 검색의 입력 계층을 제공함.
> 3. **판단 포인트**: 모델 차원보다 도메인 적합도, 평가 지표, 정규화, 거리 함수 선택이 중요함.

## Ⅰ. 개요 및 필요성

Embedding은 의미 보존 벡터 표현이다. 텍스트·이미지·코드는 원형 그대로 유사도 계산이 어렵다. 임베딩은 데이터를 수치 벡터로 변환해 검색, 추천, 군집화, RAG 근거 검색에 활용된다.

## Ⅱ. 구조 및 구성요소

```text
Input Text → Tokenizer → Transformer Encoder → Pooling
  → Normalization → Embedding Vector → Similarity Search
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Tokenizer | 텍스트를 토큰 ID로 변환 | BPE, WordPiece |
| Encoder | 문맥 기반 표현 계산 | BERT, E5, BGE, OpenAI Embedding |
| Pooling | 토큰 벡터를 문장 벡터로 집계 | CLS, mean pooling |
| Normalization | 거리 계산 일관성 확보 | L2 normalization, cosine similarity |

> 요약: 임베딩은 토큰화·인코딩·풀링·정규화를 거쳐 의미 비교 가능한 고정 길이 벡터를 생성함.

## Ⅲ. 동작원리 및 흐름도

```text
학습: 양성/음성 쌍 → Contrastive Loss → 임베딩 공간 정렬
추론: 입력 → 인코더 → 벡터 → 유사도 계산 → 검색/분류
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 도메인 데이터 전처리·토큰화 | OOV·깨진 문자 비율 <1% |
| 2 | 인코더가 384~1,536차원 벡터 생성 | 임베딩 지연 <50ms |
| 3 | L2 정규화 후 cosine/dot 유사도 계산 | 중복 문서 cosine ≥0.9 |
| 4 | 검색·추천·분류 태스크 평가 | Recall@10, nDCG@10, MTEB 점수 |

> 요약: 학습 단계에서 의미 공간을 정렬하고, 추론 단계에서 입력을 벡터로 변환해 거리 기반 판단을 수행함.

## Ⅳ. 특징

| 구분 | 원문 문자열 | Embedding | 판단 포인트 |
|:---|:---|:---|:---|
| 비교 방식 | 정확 일치·규칙 | 벡터 거리 | 의미 유사도 필요 시 Embedding |
| 데이터 범위 | 텍스트 중심 | 텍스트·이미지·코드·음성 | 멀티모달 검색에 필요 |
| 비용 | 저장 작음 | 1,536D float32 문서당 약 6KB | 1억 건이면 압축 필요 |
| 리스크 | 의미 계산 불가 | 도메인 편향·드리프트 | 재평가·재색인 필요 |

> 요약: 임베딩은 의미 기반 처리를 가능하게 하지만 저장 비용과 도메인 드리프트를 운영 지표로 관리해야 함.

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. RAG 검색: 문서를 512토큰 청크로 분할 후 BGE-M3 임베딩 생성, Recall@10과 faithfulness를 함께 평가
2. 추천·중복 탐지: 사용자·상품·문서 임베딩을 동일 공간에 배치, cosine 0.9 이상은 중복 후보로 처리
3. 운영 관리: 모델 교체 시 전체 재색인, 표본 1만 질의로 nDCG@10 A/B 테스트 후 배포

**결론 (2줄):**
- 기술사 판단: 의미 검색·추천·분류는 임베딩 기반으로 설계하되, 정확 토큰 검색은 BM25와 결합
- 향후 방향: 텍스트·이미지·음성을 같은 공간에 배치하는 멀티모달 임베딩으로 확장
