## 미리 알고가기

- 임베딩은 텍스트나 이미지 같은 비정형 데이터를 고정 길이 벡터로 바꾸는 표현 학습 결과임
- RAG, 의미 검색, 추천 시스템은 임베딩 품질에 직접 영향을 받음
- 차원 수와 모델 품질과 저장 비용은 항상 trade-off 관계임

## Ⅰ. 개요

- **정의/개념**: 임베딩은 비정형 데이터를 의미와 문맥 특성을 반영한 연속적인 고차원 벡터로 변환한 표현으로, 기계가 유사성과 관계를 수학적으로 계산할 수 있게 만드는 데이터 구조임
- **배경/필요성**: 문자열 그대로는 의미적 유사도를 계산하기 어렵고 sparse 표현은 차원과 일반화 한계가 크므로, 검색과 분류와 추천에 적합한 밀집 표현이 필요함

## Ⅱ. 특징

- 같은 의미의 표현을 벡터 공간에서 가깝게 배치해 semantic search를 가능하게 함
- 다양한 다운스트림 태스크에서 공통 표현 계층으로 재사용할 수 있음
- 도메인과 언어와 태스크에 따라 좋은 임베딩 모델이 달라짐
- 차원 수가 커질수록 표현력은 올라갈 수 있지만 저장과 검색 비용도 함께 증가함

## Ⅲ. 종류 및 비교

| 판단 기준 | One-hot, TF-IDF | Static Embedding | Contextual Embedding |
|:---|:---|:---|:---|
| 의미 유사성 표현 | 낮음 | 중간 | 높음 |
| 문맥 반영 | 없음 | 없음 | 있음 |
| 차원 효율 | 낮음 | 높음 | 높음 |
| 대표 활용 | 전통 ML | 초기 NLP | 현대 검색, RAG |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Encoder Model | 입력 데이터를 문맥과 의미를 반영한 벡터로 변환해 임베딩 품질 상한을 결정함 |
| Pooling Strategy | 토큰 단위 표현을 문장이나 문서 단위 벡터로 압축해 실제 검색 입력 형태를 만듦 |
| Vector Dimension | 표현력과 저장 비용과 검색 성능 사이의 균형점을 결정하는 핵심 파라미터임 |
| Normalization, Post-processing | cosine similarity 안정성과 검색 일관성을 높이기 위해 벡터를 후처리함 |

```text
+-------------------+      +-------------------+      +-------------------+
                                                           |
                                                           v

                                                   +-------------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 입력 데이터 수집  | --> | 인코더 표현 생성 | --> | 풀링/정규화 수행 | --> | 벡터 저장/활용   |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **입력 데이터 수집**: 텍스트나 이미지 같은 원천 데이터를 준비함
2. **인코더 표현 생성**: 모델이 문맥과 의미를 반영한 내부 표현을 계산함
3. **풀링 및 정규화 수행**: 최종 문장, 문서 단위 벡터로 변환하고 거리 계산에 맞게 정규화함
4. **벡터 저장 및 활용**: 검색, 군집화, 분류, 추천에 벡터를 사용함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 범용 임베딩 모델을 전문 도메인에 그대로 쓰면 용어 의미를 제대로 반영하지 못해 검색 품질이 크게 떨어질 수 있음
   - 해결방안: 도메인 적합 임베딩을 선택하거나 미세조정하고 retrieval recall과 domain STS score로 적합성을 검증함
2. 문제: 차원 수가 커질수록 저장소와 ANN 검색 비용이 급증해 운영비가 빠르게 늘어날 수 있음
   - 해결방안: 차원 축소나 양자화를 적용하고 memory footprint와 recall@k로 비용 대비 성능을 검증함
3. 문제: 같은 모델이라도 pooling 방식과 정규화 설정이 달라지면 다운스트림 성능 편차가 클 수 있음
   - 해결방안: task-specific ablation을 수행하고 search quality와 clustering score로 후처리 설정을 검증함

## Ⅶ. 적용 사례

- 엔터프라이즈 RAG가 문서 의미 검색용 벡터를 생성하도록 임베딩을 활용하며 확인 지표는 recall@k와 faithfulness임
- 추천 시스템이 사용자와 상품 벡터를 매칭하도록 임베딩을 적용하며 확인 지표는 CTR와 conversion rate임
- 문서 분류가 임베딩 기반 분류기를 구성하도록 임베딩을 사용하며 확인 지표는 F1 score와 latency임

## Ⅷ. 결론

임베딩은 검색과 생성형 AI의 공통 기반 표현층이므로, 모델 선택과 차원 설계와 도메인 적합성이 전체 시스템 성능의 상한을 결정함.
