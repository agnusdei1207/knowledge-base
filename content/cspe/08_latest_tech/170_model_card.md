## 미리 알고가기

- 모델 카드는 모델의 용도와 데이터와 성능과 한계를 구조적으로 공개하는 문서임
- README가 개발 실행 정보를 다룬다면 모델 카드는 사용 적합성과 위험 정보를 다룸
- 배포 직전 한 번 작성하는 문서가 아니라 모델 버전과 함께 갱신되어야 의미가 있음

## Ⅰ. 개요

- **정의/개념**: 모델 카드는 AI 모델의 목적과 적용 범위와 학습·평가 데이터와 성능과 한계와 윤리적 고려사항을 표준화된 형식으로 정리해 이해관계자가 적합한 사용 여부를 판단하도록 돕는 설명 문서임
- **배경/필요성**: 모델 파일과 API만 제공하는 방식으로는 편향과 금지 용도와 성능 한계를 사용자가 알기 어려우므로, 오용 방지와 설명 책임 강화를 위한 구조화된 공개 체계가 필요해짐

## Ⅱ. 특징

- 모델의 intended use와 out-of-scope를 명시해 오용을 줄이는 예방 통제로 작동함
- 전체 정확도뿐 아니라 집단별 성능과 데이터 특성을 함께 공개해 편향 파악을 돕음
- 개발자와 현업과 감사자와 규제 대응 부서가 같은 정보를 공유하도록 만들어 정보 비대칭을 줄임
- 모델 버전과 운영 환경이 바뀌면 함께 갱신되어야 하므로 MLOps와의 연계가 중요함

## Ⅲ. 종류 및 비교

| 판단 기준 | Model Card | Data Card / Datasheet | System Card |
|:---|:---|:---|:---|
| 설명 대상 | 개별 모델 | 데이터셋 | 전체 시스템과 운영 위험 |
| 핵심 내용 | 용도, 성능, 한계, 금지 사용 | 출처, 수집 방식, 편향, 라이선스 | 아키텍처, 통합 위험, 운영 통제 |
| 주요 사용자 | 배포자, 현업, 감사자 | 데이터 관리자, 개발자 | 보안, 거버넌스, 규제 대응 부서 |
| 활용 목적 | 모델 적합성 판단 | 데이터 신뢰성 판단 | 시스템 수준 책임성 판단 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Model Metadata | 모델 이름과 버전과 개발 조직과 라이선스를 기록해 이력 추적과 소유권 판단을 돕음 |
| Intended Use, Out-of-Scope | 허용 사용 환경과 금지 사용 환경을 명시해 오남용과 책임 분쟁을 줄임 |
| Data, Evaluation | 학습과 평가 데이터의 범위와 대표성과 집단별 성능을 공개해 편향과 일반화 한계를 드러냄 |
| Limitations, Ethical Considerations | 환각과 편향과 안전성 한계와 전제 조건을 적어 과신을 막음 |
| Maintenance, Governance Link | 갱신 주기와 승인 이력과 관련 증적 링크를 연결해 운영 관리와 감사를 지원함 |

```text
+-------------------+      +-------------------+      +-------------------+
                                                           |
                                                           v
                                                   +-------------------+
                                                   | Limitation / Maint|
                                                   +-------------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 모델 정보 수집  | --> | 성능/한계 정리  | --> | 문서 승인/배포  | --> | 버전별 갱신 유지 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **모델 정보 수집**: 용도와 데이터와 버전과 라이선스 정보를 모음
2. **성능 및 한계 정리**: 집단별 지표와 제한 조건과 금지 용도를 문서화함
3. **문서 승인 및 배포**: 검토와 승인 후 모델과 함께 제공함
4. **버전별 갱신 유지**: 재학습과 데이터 변경 시 문서를 함께 갱신함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 모델 카드가 수작업 문서로만 유지되면 모델 버전 변경 뒤에도 오래된 성능과 한계가 남아 잘못된 사용을 유도할 수 있음
   - 해결방안: model registry와 자동 생성 파이프라인을 연동하고 document freshness와 version sync rate로 검증함
2. 문제: 전체 정확도만 적고 집단별 성능과 금지 용도를 생략하면 편향과 오용 위험을 사용자에게 제대로 전달하지 못할 수 있음
   - 해결방안: segmented evaluation과 intended use review를 의무화하고 subgroup coverage와 misuse incident rate로 검증함
3. 문제: 카드가 있어도 승인 체계와 연결되지 않으면 현업이 문서를 읽지 않고 모델을 배포해 통제 효과가 약해질 수 있음
   - 해결방안: release gate와 mandatory acknowledgment를 적용하고 card review completion rate와 unapproved deployment rate로 검증함

## Ⅶ. 적용 사례

- 금융사의 신용평가 모델이 집단별 성능과 금지 사용 조건을 모델 카드로 공개하며 확인 지표는 complaint rate와 card review completion rate임
- 허깅페이스 기반 내부 모델 허브가 모델 카드와 데이터 카드 링크를 함께 제공하며 확인 지표는 model adoption accuracy와 misuse reduction rate임
- 기업 생성형 AI 플랫폼이 버전별 안전성 평가와 제한 사항을 카드로 배포하며 확인 지표는 release audit pass rate와 document freshness임

## Ⅷ. 결론

모델 카드는 AI 모델의 투명성을 문서로 번역하는 기본 장치이므로, 배포 승인과 버전 관리와 연결될 때 비로소 실질적 통제 수단이 됨.
