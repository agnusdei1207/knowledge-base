# 📖 【암기용】 개념 완전 이해

> 목적: Model Card를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: AI 모델의 목적, 데이터, 성능, 한계, 위험, 사용 조건을 표준 형식으로 문서화한 설명서
- **왜 필요한가**: 모델을 배포·재사용·감사할 때 어떤 상황에서 쓸 수 있고 어떤 한계가 있는지 알아야 함.
- **핵심 직관**: 의약품 설명서처럼 모델의 효능, 부작용, 사용 금지 조건, 시험 결과를 적은 문서임.

## 깊이 이해
- **배경·문제의식**: 모델 파일만 공유하면 학습 데이터, 평가 범위, 편향, 적합한 사용처를 알 수 없다. 오용과 과신을 막기 위한 문서화가 필요함.
- **작동 원리**: 모델 개요, intended use, training data, evaluation results, ethical considerations, limitations, monitoring plan을 구조화해 관리함.
- **비유**: 자동차를 판매할 때 연비, 안전등급, 정비 주기, 사용 금지 조건을 함께 제공하는 것과 같음.
- **구체 예시**: 고객 이탈 예측 모델 카드에 AUC 0.86, 2024년 고객 데이터 학습, 18세 미만 고객에는 사용 금지, drift PSI 0.2 기준 재학습 명시.
- **흔한 오해·주의점**: 모델 카드는 한 번 작성하고 끝나는 문서가 아님. 모델 버전, 데이터 변경, 성능 회귀에 맞춰 갱신해야 함.

## 연결 개념
- Data Card — 데이터셋의 출처·품질·제약 문서화
- Explainable AI — 모델 동작과 한계 설명
- AI Governance — 모델 카드로 감사 증적을 관리

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Model Card는 AI 모델의 목적·성능·한계·위험·사용 조건을 구조화한 문서임.
> 2. **가치**: 모델 오용을 줄이고 배포 승인, 감사, 재사용, 운영 모니터링의 증적을 제공함.
> 3. **판단 포인트**: 모델 버전·데이터·평가 지표·금지 사용처·갱신 주기를 명확히 기록해야 함.

## Ⅰ. 개요 및 필요성

- 개요: AI 모델 설명과 사용조건 문서이다.
- 배경: 모델 파일만으로는 학습 데이터, 평가 범위, 한계, 금지 용도를 확인할 수 없다.
- 필요성: Model Card는 intended use, metric, limitation, risk 항목으로 배포·재사용 판단 기준을 제공한다.

## Ⅱ. 구조 및 구성요소

```text
Model Metadata -> Intended Use -> Data/Evaluation
  -> Limitations/Risks -> Monitoring/Versioning
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Model Metadata | 모델명·버전·소유자 | owner, date, lineage |
| Intended Use | 허용·금지 사용처 정의 | target users, misuse |
| Evaluation | 성능·공정성·안전성 지표 | AUC, F1, bias gap |
| Limitations/Monitoring | 한계·위험·운영 지표 | drift, retraining trigger |

> 요약: 모델 카드는 모델 기본정보, 사용 조건, 평가 결과, 한계와 운영 계획을 한 문서로 관리함.

## Ⅲ. 동작원리 및 흐름도

```text
모델 개발 -> 평가 결과 수집 -> 사용 조건/한계 작성
  -> 배포 심의 첨부 -> 운영 지표 갱신 -> 버전 관리
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 모델 메타데이터와 owner 등록 | owner 누락 0건 |
| 2 | 성능·공정성·보안 평가 결과 기록 | 필수 지표 100% 기재 |
| 3 | 허용·금지 사용처와 위험 작성 | misuse scenario 3개 이상 |
| 4 | 배포 후 drift·성능 갱신 | 버전별 변경 이력 100% |

> 요약: 모델 카드는 개발 평가 결과를 배포 심의와 운영 모니터링에 연결하는 모델 수명주기 문서임.

## Ⅳ. 특징

| 구분 | 일반 모델 README | Model Card | 판단 포인트 |
|:---|:---|:---|:---|
| 범위 | 설치·사용법 | 목적·성능·위험·한계 | 책임 있는 사용 |
| 평가 | 선택 기재 | 성능·공정성·안전성 | 감사 증적 |
| 사용 조건 | 부족 | intended/misuse 명시 | 오용 방지 |
| 운영 | 정적 문서 | 버전·drift 갱신 | 수명주기 관리 |

> 요약: 모델 카드는 기술 사용법보다 모델 책임성과 운영 한계를 문서화하는 거버넌스 산출물임.

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 배포 필수 산출물: production 모델은 모델 카드 없이는 승인 불가, owner·버전·평가·한계 필수 항목화
2. 위험 문서화: 고위험 AI는 bias gap, privacy test, red team, human oversight 결과를 모델 카드에 포함
3. 운영 갱신: PSI 0.2 초과, AUC 5%p 하락, 주요 데이터 변경 시 모델 카드와 승인 이력 갱신

**결론 (2줄):**
- 기술사 판단: 모델 카드는 AI 배포의 설명서이자 감사 증적이므로 모델 수명주기 관리에 필수
- 향후 방향: 모델 카드, 데이터 카드, 평가 리포트가 AI GRC 플랫폼에서 자동 생성·갱신됨
