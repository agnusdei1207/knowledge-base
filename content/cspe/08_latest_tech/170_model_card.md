# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: 인공지능 모델이 "무엇을 위해 만들어졌고", "어떤 데이터를 학습했으며", "성능은 어떻고", "어디에 쓰면 안 되는지"를 한눈에 볼 수 있도록 표준화된 양식으로 정리한 일종의 'AI 제품 설명서'.
- **필요성**: 개발자가 깃허브에 모델 파일만 띡 올려놓으면, 사용자는 이 모델이 흑인 데이터는 아예 안 보고 학습했는지, 혹은 장난감용 모델인지 의료용 모델인지 알 길이 없음. 모델 오남용으로 인한 대형 사고를 막기 위해 투명한 스펙 공개가 필요해짐.
- **핵심 직관**: 약국의 의약품 라벨(약품 설명서). 타이레놀 통에 "이 약은 두통(권장 용도)에 먹고, 간이 안 좋은 사람(한계 및 부작용)은 먹지 마시오. 성분은 아세트아미노펜(학습 데이터)임"이라고 적혀 있는 것과 똑같음.

## 깊이 이해
- **배경**: 2019년 구글의 마가렛 미첼(Margaret Mitchell)과 팀닛 게브루(Timnit Gebru) 등이 논문으로 최초 제안함. AI 윤리 위원회가 깡통이 되지 않으려면 개발자와 사용자 간의 표준화된 커뮤니케이션 문서 포맷이 필요하다는 철학에서 출발함. 현재 허깅페이스(Hugging Face) 등 오픈소스 진영의 핵심 표준으로 정착함.
- **작동 원리 (핵심 기재 사항)**:
  1. **모델 개요**: 누가, 언제 만들었고, 무슨 알고리즘 썼는지.
  2. **의도된 사용 (Intended Use)**: 어디에 쓰라고 만든 건지. **(특히 '사용 금지 조건' 명시가 핵심. "의료 진단 보조로만 쓰고 최종 판독용으로 금지")**.
  3. **학습 및 평가 데이터**: 어떤 편향된 데이터가 들어갔는지 출처와 비율을 깜.
  4. **성능 지표**: 전체 정확도만 쓰면 안 됨. 성별, 인종 등 '세부 집단별 성능 편차(Intersectionality)'를 투명하게 적어야 함 (예: 백인 남성 인식률 99%, 흑인 여성 85%).
  5. **윤리적 고려 및 한계**: 이 모델이 가질 수 있는 편향과 독성 리스크 자백.
- **구체 예시**: OpenAI가 GPT-4를 출시할 때 수십 페이지짜리 System Card(모델 카드의 변형)를 냄. "이 모델은 변호사 시험을 통과할 정도로 똑똑하지만(성능), 심각한 환각(Hallucination)이 있으니 법적 자문 용도로 맹신해선 안 됨(한계 및 금지)"이라고 쫙 깔아둠.
- **흔한 오해/주의점**: "README.md 파일이랑 똑같은 거 아냐?" $\rightarrow$ 본질이 다름. README가 "이 코드 어떻게 설치하고 돌려요?"라는 IT 개발자용 메뉴얼이라면, Model Card는 "이 AI가 사회적으로 어떤 영향을 미쳐요?"를 짚어주는 윤리/법무/현업용 통제 문서임.

## 연결 개념
- **Data Card (Data Sheet)**: 모델 카드가 'AI 뇌'의 설명서라면, 데이터 카드는 그 뇌를 학습시킨 '교재(데이터셋)'에 대한 설명서(저작권, 편향 비율 등). 세트 메뉴임.
- **AI Governance**: 전사적으로 "모델 카드를 안 쓴 AI는 사내 배포를 절대 금지한다"라고 정책(Rule)을 정하고 통제하는 체계.
- **Responsible AI (책임 있는 AI)**: 모델 카드 작성 행위 자체가 책임 있는 AI를 실천하는 가장 기초적이고 강력한 증빙 수단임.

# 📝 【답안용】 시험 답안 템플릿
## 핵심 인사이트 (3줄 요약)
- **본질**: 기계학습 모델의 설계 의도, 성능 특성, 학습/평가 데이터 도메인, 내재적 한계 및 윤리적 편향 요소를 이해관계자(개발자, 감사자, 일반 사용자)가 투명하게 파악할 수 있도록 표준화한 명세서(Specification Document).
- **가치**: 모델의 의도치 않은 오용(Misuse) 및 OOD(Out-of-Distribution, 훈련 데이터 밖의 환경) 적용에 따른 시스템 붕괴를 예방하고, 글로벌 AI 규제(EU AI Act 투명성 의무) 대응을 위한 필수적인 설명 책임(Accountability) 증적으로 작동함.
- **판단 포인트**: 모델 카드는 일회성 보고서가 아니라, MLOps 생태계 내에서 모델 버전(Version)이 갱신되거나 데이터 분포 편이(Drift)가 발생할 때마다 CI/CD 파이프라인에서 자동 생성(Auto-generation)되어 배포 게이트를 통과하는 거버넌스 아티팩트(Artifact)로 다뤄져야 함.

## Ⅰ. 개요 및 필요성
- **정의**: AI 모델의 개발부터 폐기까지 전 과정에 대한 '투명성(Transparency)'을 보장하기 위해, 모델의 기본 정보, 윤리적/기술적 성능 평가 지표, 허용 및 제한된 사용 사례를 체계적으로 기록한 단문 형태의 정보 시트.
- **배경**: AI 모델 깃허브 저장소(Repository)의 파편화된 코드와 README로는, 모델이 특정 인종이나 연령대에서 치명적인 오작동(Disparate Impact)을 일으키는지 파악할 수 없어 2차 피해(Downstream Harm)가 양산됨.
- **필요성**: 모델 벤더사(공급자)와 소비자(Deployer) 간의 정보 비대칭을 해소하고, "이 모델이 우리의 비즈니스 요건과 윤리적 기준에 부합하는가?"를 사전 검증(Due Diligence)할 수 있는 표준화된 평가 렌즈(Lens)를 제공하기 위함.

## Ⅱ. 모델 카드의 핵심 구조(Section) 및 필수 기재 항목
투명성을 담보하는 6대 프레임워크 (Google/HuggingFace 표준 준용).
| 주요 섹션 (Section) | 상세 기재 내용 및 목적 | 핵심 거버넌스 요소 |
|:---:|:---|:---|
| **1. 모델 세부정보 (Metadata)** | 모델 아키텍처(CNN, Transformer 등), 버전, 개발 기관, 라이선스 정책, 배포일. | 기본 이력 및 소유권 추적. |
| **2. 의도된 용도 (Intended Use)**| 개발자가 의도한 최적의 사용 도메인(Primary Use Cases). **[가장 중요] 아웃 오브 스코프(Out-of-Scope) 및 절대 사용 금지 명시**. | 무분별한 모델 오용 및 법적 면책(Liability) 가이드. |
| **3. 요인 및 인구통계 (Factors)**| 연령, 성별, 인종 등 성능 편차가 발생할 수 있는 주요 인구통계학적 요인과 하드웨어 인프라 요건 명시. | 성능 격차 발생의 컨텍스트 제공. |
| **4. 측정 지표 (Metrics)** | 일반적인 전체 정확도(Accuracy)뿐만 아니라, 오차 행렬(FPR, FNR), 모델 보정(Calibration) 오차 등 모델의 강건성 지표 공개. | 보수적인 기술 성능 검증. |
| **5. 훈련 및 평가 데이터 (Data)**| 훈련 데이터셋과 테스트 데이터셋의 출처, 라벨링 방법론. (데이터 카드 링크 연결 권장). | 데이터 오염 및 저작권 위반 여부 추적성 확보. |
| **6. 정량 분석 및 윤리 (Analysis)**| (전체가 아닌) **집단별 세분화된 성능 결과(Intersectionality)** 차트 제공. 모델이 지닌 편향성과 윤리적 한계(환각 등) 자진 신고. | 공정성(Fairness) 및 규제 대응. |

## Ⅲ. 기존 모델 배포 환경(README)과 모델 카드의 차별성
개발자 중심에서 이해관계자(Stakeholder) 통합 중심으로 이동.
| 비교 항목 | 기존 환경 (README.md) | 모델 카드 (Model Card) |
|:---:|:---|:---|
| **주 타겟 독자** | 다음 작업을 이어받을 코어 AI 개발자 | 정책 입안자, 법무팀, 비즈니스 기획자, 규제 당국 |
| **초점 내용** | 환경 설정, Hyperparameter 튜닝, 학습 코드 실행 방법 | **모델의 한계점, 편향성 평가, 금지된 사용 사례** |
| **성능 보고 방식**| 최고 성능(SOTA), 전체 평균 정확도 1줄 요약 | **민감 그룹별 쪼개진 세부 정확도 및 오탐률 투명 공개** |

## Ⅳ. 모델 카드 자동화 생태계 (Model Card as Code)
문서 작업의 오버헤드를 줄이기 위한 MLOps 연계 전략.
- **초기 수작업의 한계**: 데이터 사이언티스트들이 Word나 PDF로 수기로 작성하면, 모델 재학습 시 문서가 갱신되지 않아 죽은 문서(Dead Document)가 됨.
- **자동화 툴체인 (Google Model Card Toolkit 등)**:
  - 모델 학습 파이프라인(TFX, MLflow 등)에 연동되어, 학습이 끝나면 JSON 파일 형태의 메타데이터와 성능 차트(TFMA)가 자동으로 추출 및 렌더링되어 HTML 형태의 모델 카드를 즉시 발급. 모델 버저닝(Versioning)과 모델 카드의 동기화 보장.

## Ⅴ. 실무 적용 및 결론
- **판단 지표**: 사내 모델 저장소(Model Registry) 내 모델 카드 발급 커버리지, 규제 당국의 요구사항 충족도, 모델 오용에 따른 Incident 감소율.
- **실무 설계**: 엔터프라이즈 통합 MLOps 환경(AI Governance 도입). 사내에 여러 팀이 만든 예측 모델 수백 개가 난립하여, 현업 부서가 엉뚱한 모델을 고객 서비스에 붙여 클레임이 터지는 상황 발생. 전사 AI 규정으로 "모델 카드 발급 의무화" 선포. MLflow의 Model Registry와 연동하여, 배포 승인 시 Python 스크립트가 SHAP 설명 결과차트, 공정성(Fairlearn) 차트, 금지 조항을 템플릿화하여 'Model Card'를 자동 렌더링함. 현업 기획자는 API를 호출하기 전 이 카드 1장만 읽고 "아, 이 VIP 예측 모델은 20대 데이터가 부족해서 20대에게 쓰면 편향 오차가 심하구나"를 인지하고 타겟 마케팅에서 20대를 제외함. AI 거버넌스 완벽 구축.
- **결론**: 모델 카드는 AI라는 거대한 블랙박스 화물에 붙이는 투명한 화물 명세서(Manifest)이다. 이는 단순히 규제를 피하기 위한 요식 행위를 넘어, 개발자와 사용자 간의 기술적 신뢰를 연결하고 기업의 전사적 리스크를 통제하는 윤리적 방어선으로 작용할 것이다.

### 🔀 문제 유형별 목차 전환
- **Ⅱ·Ⅲ 강조 (개념/원리형)**: 모델 카드 6대 컴포넌트 중 '정량 분석(Quantitative Analysis)'에서 요구되는 상호 교차성(Intersectionality, 예: '흑인'이면서 '여성'인 그룹에 대한 편향) 분석 방법론 및 평가지표 심화 서술.
- **Ⅴ·Ⅵ 강조 (실무/설계형)**: 거대 언어 모델(LLM) 배포 파이프라인에서 시스템 카드(System Card)로의 진화 아키텍처 및 Hugging Face Model Hub처럼 퍼블릭/프라이빗 모델 공유 레지스트리(Registry) 상의 접근 제어 보안 연계 아키텍처.
