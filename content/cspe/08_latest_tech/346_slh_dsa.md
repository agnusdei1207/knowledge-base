# 📖 【암기용】 개념 완전 이해

> 목적: SLH-DSA를 상태 관리가 필요 없는 해시 기반 양자내성 전자서명으로 이해하게 만든다.

## 한눈에
- **개요**: 해시 함수와 트리 구조로 전자서명을 만드는 NIST FIPS 205 표준
- **왜 필요한가**: RSA, ECDSA, EdDSA는 충분한 규모의 양자컴퓨터에서 Shor 알고리즘 공격 대상이므로 장기 검증이 필요한 서명은 양자내성 전환이 필요하다.
- **핵심 직관**: 어려운 수학 문제 대신 안전한 해시 함수를 여러 층으로 묶어 "한 번 쓴 서명 조각"을 전체 공개키로 검증하게 만든다.

## 깊이 이해
- **배경·문제의식**: NIST는 2024년에 ML-KEM, ML-DSA, SLH-DSA를 첫 양자내성 표준으로 확정했다. SLH-DSA는 SPHINCS+ 계열의 stateless hash-based signature이다.
- **작동 원리**: 메시지 다이제스트를 만들고, FORS와 WOTS+ 일회성 서명을 생성한 뒤, XMSS 계층 트리 인증 경로를 붙여 루트 공개키로 검증한다.
- **비유**: 도장을 한 번만 찍을 수 있는 작은 도장들을 여러 상자에 넣고, 상자 위치와 봉인 경로를 함께 제시해 원본성을 확인하는 방식이다.
- **구체 예시**: `SLH-DSA-SHA2-128s`는 보안 강도 Category 1을 목표로 하며, 작은 서명 크기보다 보수적인 해시 기반 안전성을 우선하는 용도에 맞다.
- **흔한 오해·주의점**: SLH-DSA가 모든 서명 용도에서 ML-DSA를 대체하는 것은 아니다. 서명 크기와 처리 비용이 크므로 펌웨어 서명, 장기 보존 서명처럼 검증 신뢰성이 우선인 곳에 적합하다.

## 연결 개념
- ML-DSA — 격자 기반 전자서명 대안
- FIPS 205 — SLH-DSA 표준 문서
- Hash-Based Signature — 해시 안전성에 기반한 서명 계열

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.
> 핵심: SLH-DSA는 NIST FIPS 205의 stateless hash-based signature로, 양자내성 서명 전환에서 보수적 안전성과 큰 서명 크기의 트레이드오프를 판단해야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: SLH-DSA는 해시 함수, WOTS+, FORS, Merkle 계층 트리로 구성된 상태 비저장 양자내성 전자서명이다.
> 2. **가치**: 격자 가정이 깨지는 경우에도 해시 기반 안전성에 기대는 대체 서명 선택지를 제공한다.
> 3. **판단 포인트**: FIPS 205 준수, 파라미터 세트, 서명 크기, 검증 지연, 키 수명 정책을 함께 본다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 양자내성 서명 표준 이해 확인 | NIST FIPS 205, stateless hash-based signature | 단순 해시 알고리즘으로 설명 |
| ML-DSA와의 선택 판단 확인 | 해시 기반 보수성 vs 큰 서명 크기 | "PQC라서 모두 동일"로 처리 |
| 실무 전환 리스크 확인 | 인증서·코드서명·HSM·검증 성능 | RSA/ECDSA 즉시 폐기로 단정 |

> 요약: 이 문제는 SLH-DSA의 구조보다 PQC 전환 시 어느 서명 업무에 적용할지 판단하는 역량을 요구한다.

## Ⅰ. 개요 및 필요성

- 개요: 해시 기반 PQC 서명
- 배경: 공개키 기반 RSA/ECC 서명은 장기 검증 문서와 펌웨어 서명에서 양자컴퓨터 위협을 고려해야 함.
- 필요성: NIST FIPS 205 기반 SLH-DSA로 장기 무결성, 인증, 부인방지 요구를 양자내성 체계로 전환해야 함.

---

## Ⅱ. 구조 및 구성요소

```text
Message -> Hash/Randomization -> FORS -> WOTS+
        -> XMSS Hypertree -> Signature -> Public Root Verification
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Hash function | 메시지 다이제스트와 노드 값 생성 | SHA2, SHAKE 파라미터 |
| FORS | 메시지 다이제스트 일부를 서명 | few-time signature |
| WOTS+ | 트리 잎 노드 서명 | one-time signature |
| Hypertree | 인증 경로와 루트 공개키 연결 | Merkle tree 계층 |

> 요약: SLH-DSA는 일회성 서명을 Merkle 계층 트리로 묶어 공개 루트로 검증하는 구조다.

---

## Ⅲ. 동작원리 및 흐름도

```text
키 생성 -> 메시지 해시 -> FORS/WOTS+ 서명 생성
-> 인증 경로 첨부 -> 루트 재계산 -> 공개키 루트 비교
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 비밀 seed와 공개 root를 생성함 | FIPS 205 parameter set |
| 2 | 메시지와 난수를 해시해 서명 위치를 결정함 | domain separation |
| 3 | FORS와 WOTS+ 서명값 및 인증 경로를 생성함 | signature format |
| 4 | 검증자가 root를 재계산해 공개키와 비교함 | accept/reject |

> 요약: SLH-DSA 검증은 서명 조각과 인증 경로로 공개 루트를 재구성하는 절차다.

---

## Ⅳ. 특징

| 구분 | SLH-DSA | ML-DSA | 판단 기준 |
|:---|:---|:---|:---|
| 기반 가정 | 해시 함수 안전성 | module lattice | 암호 민첩성 |
| 상태 관리 | stateless | stateless | 운영 복잡도 |
| 서명 크기 | 상대적으로 큼 | 상대적으로 작음 | 인증서·프로토콜 MTU |
| 적용 후보 | 코드서명·장기서명 | 인증서·일반 서명 | 성능/크기 제약 |

> 요약: SLH-DSA는 해시 기반 보수성을 얻는 대신 서명 크기와 처리 비용을 설계 제약으로 받아들인다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 암호 기반 | RSA/ECDSA | FIPS 205 SLH-DSA | 장기 검증 필요 |
| 전환 방식 | 단일 알고리즘 | hybrid 또는 PQC 단독 | 호환성 범위 |
| 운영 대상 | TLS 인증서 | 펌웨어·문서·코드서명 | 서명 크기 허용 |

> 요약: SLH-DSA는 모든 인증 경로보다 장기 보존 서명과 펌웨어 검증에 먼저 검토한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 메시지 크기 증가 | 서명 길이 확대 | 프로토콜 MTU, 인증서 체인 크기 시험 | handshake size |
| 구현 취약점 | 파라미터·도메인 분리 오류 | 검증된 라이브러리, known answer test | KAT pass |
| 전환 지연 | HSM·PKI 미지원 | crypto inventory, hybrid pilot | unsupported asset count |

> 요약: SLH-DSA 적용 리스크는 수학보다 프로토콜 크기, 구현 검증, PKI 지원 범위에서 발생한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 표준 준수 | FIPS 205 파라미터 사용 | 알고리즘 식별자 점검 |
| 성능 | 서명·검증 지연 업무 SLA 이내 | benchmark |
| 호환성 | 인증서·펌웨어 검증 성공 | staging rollout |

> 요약: SLH-DSA 전환은 표준 식별자, 지연, 메시지 크기, 검증 성공률을 함께 확인해야 한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 암호 자산 목록에서 RSA/ECDSA 코드서명, 펌웨어 서명, 장기 보존 문서를 분리하고 SLH-DSA 후보군을 지정함.
2. FIPS 205 파라미터 세트별 서명 크기, 검증 시간, 인증서 체인 크기를 사전 측정함.
3. ML-DSA와 SLH-DSA를 병행 시험하고 HSM, PKI, 배포 시스템의 알고리즘 식별자 지원 여부를 확인함.

**결론 (2줄):**
- 기술사 판단: 서명 크기를 수용할 수 있고 장기 검증 신뢰성이 우선이면 SLH-DSA를 선택하고, 일반 인증서 대량 처리에는 ML-DSA를 우선 검토함.
- 향후 방향: PQC 전환은 단일 알고리즘 교체가 아니라 crypto inventory, hybrid transition, crypto agility 체계로 추진됨.
