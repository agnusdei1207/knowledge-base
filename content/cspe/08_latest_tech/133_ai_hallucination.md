# 📖 【암기용】 개념 완전 이해

> 목적: AI Hallucination을 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: AI가 사실과 다르거나 근거 없는 내용을 그럴듯하게 생성하는 현상
- **왜 필요한가**: LLM 답변은 자연스럽지만 사실 검증을 통과하지 못할 수 있어 업무·법적 리스크를 만든다.
- **핵심 직관**: 모르는 문제에서 답안을 빈칸으로 두지 않고 그럴듯한 설명을 지어내는 현상임.

## 깊이 이해
- **배경·문제의식**: LLM은 다음 토큰 확률을 예측하므로 진실 여부가 아니라 언어 패턴 가능성에 따라 답을 만든다.
- **작동 원리**: 학습 데이터 부족, 모호한 질문, 잘못된 검색 컨텍스트, 과도한 창의성 설정, 지시 충돌이 근거 없는 생성을 유발함.
- **비유**: 시험에서 기억이 불완전한 학생이 출처 없이 그럴듯한 사례와 수치를 만들어 쓰는 것과 같음.
- **구체 예시**: 사내 규정 챗봇에서 없는 휴가 조항을 생성하면 직원 민원과 노무 리스크가 발생하므로 Faithfulness 0.9 이상 관리 필요.
- **흔한 오해·주의점**: RAG를 붙이면 환각이 자동으로 사라지지 않음. 검색 품질과 근거 검증이 낮으면 잘못된 문서를 근거로 환각을 만들 수 있음.

## 연결 개념
- Faithfulness — 근거 없는 claim을 탐지하는 지표
- RAG — 외부 근거로 환각을 줄이는 아키텍처
- Guardrail — 위험 답변을 차단·수정하는 통제 계층

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Hallucination은 LLM이 사실과 다르거나 근거 없는 내용을 자연어로 생성하는 오류임.
> 2. **가치**: 환각 관리는 기업 AI 도입의 신뢰성·법적 책임·감사 대응을 좌우함.
> 3. **판단 포인트**: RAG, Faithfulness 평가, citation, 거절 정책, human review를 계층적으로 적용해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| LLM 환각의 원인·탐지·통제 역량 확인 | Faithfulness 0.9 기준, claim 단위 검증, RAG Context Recall 0.85, 거절 정책 | "RAG 적용하면 환각 해결" 식 단순 서술, 수치 없는 추상 방안 |

> 요약: 환각의 구조적 원인을 밝히고 claim 단위 검증·거절 정책을 수치와 함께 제시해야 감점을 피함

## Ⅰ. 개요 및 필요성

- 정의: LLM이 근거 없는 내용을 생성하는 오류
- 배경: LLM은 확률 기반 언어 생성 모델이라 사실 검증 없이 그럴듯한 답변을 만들 수 있음
- 필요성: 기업 업무에서 잘못된 규정·수치·법률 안내는 노무·법적 리스크로 직결되므로 Faithfulness 0.9 이상 관리 필요

## Ⅱ. 구조 및 구성요소

```text
User Query -> LLM/RAG -> Generated Claims
  -> Evidence Check -> Guardrail/Human Review -> Final Answer
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Generator | 답변 생성 | temperature, system prompt 영향 |
| Evidence Source | 근거 문서·DB | RAG contexts, API results |
| Verifier | claim-근거 일치성 검증 | Faithfulness, Groundedness |
| Guardrail | 위험 답변 차단·수정 | refusal, citation required |

> 요약: 환각 관리는 생성 결과를 claim 단위로 근거 검증하고 위험 답변을 차단하는 통제 구조로 수행함.

## Ⅲ. 동작원리 및 흐름도

```text
질의 입력 -> 근거 검색/생성 -> claim 분해
  -> 근거 일치성 검증 -> 미근거 claim 탐지
  -> 재검색·재생성·거절·검토
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 답변 생성 전 RAG 근거 검색 | Context Recall ≥0.85 |
| 2 | 생성 답변 claim 단위 분해 | claim 누락률 <5% |
| 3 | claim별 근거 일치성 판정 | Faithfulness ≥0.9 |
| 4 | 미근거 claim 처리 | 출처 없는 claim 0건 목표 |

> 요약: 검색 품질 확보 후 답변 claim을 검증하고, 근거 없는 문장은 재검색·거절·검토로 통제함.

## Ⅳ. 특징

| 구분 | 원인 | 대응 | 판단 포인트 |
|:---|:---|:---|:---|
| 지식 부족 | 학습 컷오프·도메인 부재 | RAG·API 조회 | 최신 정보 필요 시 검색 |
| 검색 오류 | 무관 컨텍스트·누락 | Hybrid·Reranker | Context Precision/Recall 관리 |
| 생성 오류 | 추론 비약·출처 미표시 | Faithfulness·citation | claim 검증 필요 |
| 운영 리스크 | 규정·법률 오답 | human review·거절 정책 | 고위험 업무는 자동 답변 제한 |

> 요약: 환각은 모델·검색·생성·운영 원인이 복합적이므로 다층 통제로 관리해야 함.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | AI Hallucination 통제 | 선택 기준 |
|:---|:---|:---|:---|
| 검색 품질 | 단일 벡터 검색(Recall 0.6) | Hybrid+Reranker(Context Recall ≥0.85) | 도메인 문서 10만 건 이상 시 Hybrid 필수 |
| 답변 검증 | 사후 수동 검토 | claim 단위 Faithfulness ≥0.9 자동 게이트 | 일 1,000건 이상 시 자동 검증 필수 |
| 운영 통제 | 모델 파라미터 조정 | 거절 정책+human review 큐+감사로그 90일 | 법무·인사·의료 고위험 업무 |

> 요약: 고위험 업무는 Hybrid 검색, claim 자동 검증, 거절 정책을 조합해 환각을 통제함

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 사실 오류 답변 | 학습 컷오프·도메인 부재 | RAG 검색 보강, API 조회 연동 | Context Recall ≥0.85 |
| 잘못된 출처 인용 | 무관 컨텍스트 검색 | Reranker 적용, citation correctness 검증 | Citation Correctness ≥95% |
| 규정·법률 오답 | 고위험 질의 자동 답변 | human review 큐 전송, 답변 거절 정책 | 고위험 질의 자동 답변률 0% |

> 요약: 환각 리스크는 검색 품질, 출처 검증, 고위험 거절 정책으로 계층적 통제함

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 답변 신뢰도 | Faithfulness ≥0.9, 미근거 claim 0건 | RAGAS 평가, claim 단위 검증 파이프라인 |

> 요약: Faithfulness·검색 품질·거절률을 정량 지표로 측정해 환각 관리 수준을 판단함

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. RAG 강화: Hybrid Search+Reranker로 Context Precision@5 0.8 이상, Context Recall 0.85 이상 유지
2. 답변 검증: Faithfulness 0.9 미만 또는 citation 없는 claim은 재생성, 2회 실패 시 답변 거절
3. 고위험 통제: 법무·인사·의료 질의는 human review 큐로 전송하고 감사로그 90일 보관

**결론 (2줄):**
- 기술사 판단: 환각은 제거 대상이 아니라 측정·검증·거절 정책으로 관리할 운영 리스크임
- 향후 방향: RAG 평가, tool grounding, formal verifier를 결합한 검증형 생성 구조로 발전
