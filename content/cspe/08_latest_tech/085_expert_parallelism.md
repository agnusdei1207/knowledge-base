## 미리 알고가기

- 전문가 병렬화 ($EP$, Expert Parallelism): 전문가 혼합($MoE$) 모델의 수많은 전문가($Expert$) 계층을 분리해 여러 GPU 카드 및 이종 물리 노드에 분배 맵핑하여 병렬 처리하는 분산 텐서 연산 기법임
- 올투올 통신 ($All-to-All$): 모든 분산 프로세스(GPU)가 다른 모든 프로세스와 서로 다른 메시지 조각들을 동시다발 교환하는 일대다 다차원 통신 패드임
- 데이터 병렬화 ($DP$, Data Parallelism): 동일한 모델 가중치를 모든 카드에 각각 올려둔 채, 서로 다른 배치 데이터를 입력해 연산하고 그래디언트($All-Reduce$)만 동기화하는 범용 병렬화임
- 텐서 병렬화 ($TP$, Tensor Parallelism): 가중치 매트릭스 1장 자체를 칼럼/로우로 세분화하여, 수십 명의 GPU가 레이어 내부에서 수평 병렬 계산하는 초저지연 병렬화임

## Ⅰ. 개요

- **정의/개념**: Expert Parallelism(EP)은 대형 MoE 신경망의 가용 지식을 극대화하기 위해, 서로 다른 전문가(Expert)들의 FFN 레이어 블록 가중치들을 개별 물리 GPU 노드들에 분산 적재하고, 라우터가 점지한 토큰 텐서들을 $All-to-All$ 통신망을 통해 해당 전문가가 들어있는 장치로 원격 분산 전송해 병렬 가속하는 특화 분산 처리 기법임
- **배경/필요성**: MoE의 총 파라미터가 수천억 개로 비대화되면서 단일 노드 VRAM에 얹을 수 없는 메모리 공간 한계가 발생했는데, $TP$(텐서 병렬화)에만 의존하면 노드 간의 과도한 올리듀스 포화로 성능이 역행하므로 MoE 전용 격리 기법으로 창안됨

## Ⅱ. 특징

- 전문가 블록들을 다중 카드로 분산 포팅함으로써, 카드 1장당 부담해야 하는 물리 가중치 용량(VRAM Footprint)을 획기적으로 다이어트함
- 토큰이 자신의 타깃 전문가가 들어있는 원격 GPU 카드를 찾아 날아가야 하므로, 매 레이어 FFN 전후로 엄청난 $All-to-All$ 통신망 버하를 뿜어냄
- 실무 성능을 극대화하기 위해 데이터 병렬화($DP$), 텐서 병렬화($TP$), 파이프라인 병렬화($PP$)와 $4$중으로 조합 설계하는 복합 토폴로지가 대세임

## Ⅲ. 종류 및 비교

| 판단 기준 | 데이터 병렬화 (DP) | 텐서 병렬화 (TP) | 전문가 병렬화 (EP) |
|:---|:---|:---|:---|
| **분산하는 물리적 표적** | 입력 배치 ($Batch$ $Data$) | 하나의 텐서/행렬 조각 | 전문가 FFN 블록 단위 |
| **통신의 종류 및 강도** | $All-Reduce$ (동기화) | $All-Reduce$ (연산 도중 동기화) | $All-to-All$ (토큰 분배 및 취합) |
| **타깃 네트워크 대역폭** | 낮아도 작동 가능 | 극도로 높아야 함 (NVLink 필수) | 높아야 함 (노드 간 InfiniBand 요함) |
| **도입 효과 및 주역** | 학습 수렴 가속화 | 초대형 단일 $Dense$ 모델 서빙 | 초대형 $MoE$ 모델 분산 적재 및 가속 |

> 요약: DP는 데이터 덩어리를 쪼개고, TP는 가중치 행렬판을 세로로 찢으며, EP는 전문가 블록들을 카드별로 한 채씩 나눠 심음.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 전문가 샤딩 | 각 전문가 레이어 가중치를 물리 GPU 개수 단위로 정렬해 파티셔닝하는 로직임 |
| 토큰 디스패처 | 라우터 결과를 읽고, 통신 페브릭을 구동해 토큰을 대상 GPU 노드로 밀어 보내는 송신 장치임 |
| $All-to-All$ 페브릭 | 노드 간 InfiniBand 망을 작동시켜, 장치 간 토큰 데이터 교환을 병렬 가속하는 네트워크망임 |
| 출력 재결합기 | 다수 GPU에서 연산 완료되어 반환된 토큰들을 원래의 배치 시퀀스 순서로 재합성하는 병합기임 |
```text
[ Expert Parallelism (EP) 통신 패브릭 구조 ]
GPU 0 (Token Dispatcher)  ===(All-to-All 통신)===>  GPU 1 (Expert 1 Shard)
GPU 1 (Token Dispatcher)  ===(All-to-All 통신)===>  GPU 0 (Expert 0 Shard)
- 자신의 연산 위치를 찾아 다른 카드로 실시간 텐서를 전송 교환하는 망임
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 라우팅      | --> | All-to-All   | --> | 물리 가속기 | --> | 결과 올투올 |
| 타겟지정확인|     | 토큰 패킹/송신|     | 원격연산가동|     | 수집 및 정렬|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **타깃 파싱** — 토큰별 라우터 연산이 끝나면, 각 토큰이 비행해 가야 할 대상 GPU 카드의 물리적 순번 리스트를 완성함
2. **토큰 올투올 분배** — $All-to-All$ 통신 프리미티브를 가동하여, 동일 하이브리드 버스망을 타고 텐서들을 타깃 GPU에 병렬 인입함
3. **분산 추론** — 토큰을 인계받은 각 GPU가 자신이 샤딩해서 갖고 있던 전문가 FFN 코어를 켜서 순방향 계산을 단시간에 완료함
4. **올투올 취합** — 다시 한 번 역방향 $All-to-All$ 통신을 가동하여 흩어진 토큰 결과를 합치고, 다음 어텐션 층에 올릴 배치 배열로 가변 정렬함

## Ⅵ. 실무 적용 및 유의점

1. EP 가동 시 노드 간 네트워크 전송 대역폭이 좁으면 $All-to-All$ 통신 단에 병목이 걸려 계산 스킵 가속 혜택이 증발하므로, 반드시 고속 인피니밴드($InfiniBand$) 스위치 및 호스트 버스를 수립하고, 통신 대 연산 점유율($Communication$ $Ratio$) 지표를 실측하여 격리해야 함
2. $DP+TP+PP+EP$가 얽힌 4중 하이브리드 분산 병렬화 설정 시, 1장의 설정 오류가 모델 전체의 동작 크래시를 유발하므로, 반드시 토폴로지 맵을 수립하고 평균 복구 시간($MTTR$) 지표를 추적 관리하여 분산 인프라 안정성을 확보해야 함

## Ⅶ. 결론

- 전문가 병렬화는 조 단위 MoE 모델의 물리적 수용 한계선을 GPU 분산 망과 고속 네트워크 통신 카드로 실현해 내는 분산 컴퓨팅의 꽃이며, 설계자는 통신 병목을 억제할 InfiniBand 대역폭 설계와 복잡한 하이브리드 병렬화 조합 무결성을 반드시 통합 감사 수립해야 함
