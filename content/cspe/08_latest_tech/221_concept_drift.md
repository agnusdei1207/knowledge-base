# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: 머신러닝 모델에서, 입력 데이터(X)와 모델이 맞혀야 하는 **정답(Y) 사이의 '통계적 관계 및 규칙' 자체가 시간이 지남에 따라 변하는 현상** ($P(Y|X)$의 변화).
- **필요성**: 세상의 상식과 가치관은 고정되어 있지 않음. 과거에는 정답이었던 것이 오늘은 오답이 됨. 모델은 "과거의 정답"만 외우고 있기 때문에 이 룰(규칙)이 변하는 순간 성능이 치명적으로 박살남. 이를 빨리 알아채고 모델을 뜯어고쳐야(재학습) 함.
- **핵심 직관**: 시험 문제(X)는 똑같은데 출제위원의 채점 기준(Y)이 몰래 바뀐 상황. 예컨대 "기침을 하고 열이 난다(X)"는 입력에 대해 코로나 이전 모델은 "감기(Y)"라고 정답을 냈지만, 코로나 시대의 모델은 "코로나(Y)"라고 정답을 내야 함. 증상(X)은 그대로지만 질병의 판단 기준(Concept)이 변한 것.

## 깊이 이해
- **배경**: Data Drift(문제의 유형 변화)는 입력 데이터의 분포($P(X)$)만 변하는 거라 비교적 발견하기 쉽고 견딜 만함. 하지만 Concept Drift는 모델의 존재 이유(정답과의 관계)가 박살나는 것이라 가장 무서운 성능 저하 원인(Model Decay)으로 꼽힘.
- **작동 원리 (변화의 3가지 패턴)**:
  1. **Abrupt (급격한 변화)**: 갑작스러운 사건으로 룰이 하루아침에 뒤집힘. (예: 코로나19 발발, 법규 제정). 모델 성능 수직 낙하. 즉시 모델 전면 재학습 필요.
  2. **Incremental (점진적 변화)**: 서서히 룰이 바뀜. (예: 물가 상승으로 인해 '비싼 집'의 기준 가격이 매년 조금씩 오름). 슬라이딩 윈도우(Sliding Window)로 옛날 데이터를 버리며 계속 재학습.
  3. **Recurring (주기적 변화)**: 계절성처럼 특정 룰이 반복됨. (예: 주말에는 유저 행동 패턴이 다름). 앙상블 기법으로 주말 모델, 평일 모델을 섞어 씀.
- **구체 예시**: 신용카드 사기 탐지(FDS) 모델. 작년에는 하루에 해외에서 3번 결제(X)하면 무조건 '사기(Y)'였음. 그런데 해외 직구족이 늘어나면서 오늘날엔 하루 3번 직구(X)가 '정상적인 행동(Y)'으로 개념이 바뀜. 옛날 모델은 이걸 다 사기라고 막아버려서(False Positive) 고객 항의가 폭주함.
- **흔한 오해/주의점**: "데이터 드리프트를 막으면 컨셉 드리프트도 막아지나요?" $\rightarrow$ 절대 아님! 입력 데이터(결제 횟수, 금액 등)의 통계적 분포는 완전히 똑같아도, 그게 의미하는 '사기 여부(정답)'만 쏙 바뀔 수 있음. 그래서 컨셉 드리프트를 잡으려면 반드시 **실제 정답(Ground Truth)**을 수집해서 예측값과 끈질기게 대조해야 함.

## 연결 개념
- **Data Drift**: 컨셉 드리프트의 형제. Data Drift가 "입력($X$)의 변화"라면, Concept Drift는 "룰($P(Y|X)$)의 변화".
- **Label Lag (정답 지연)**: 컨셉 드리프트를 탐지하기 어렵게 만드는 주범. 대출 심사를 오늘 모델이 해도, 연체(정답)가 났는지는 1년 뒤에 알 수 있음. 정답을 늦게 아니까 컨셉 드리프트도 1년 늦게 알아챔.
- **Online Learning (온라인 학습)**: 컨셉 드리프트에 대항하는 궁극의 무기. 데이터가 들어오는 족족 실시간으로 모델의 가중치를 찔끔찔끔 업데이트해서, 세상의 변화 속도에 맞춰 모델을 같이 진화시키는 기법.

# 📝 【답안용】 시험 답안 템플릿
## 핵심 인사이트 (3줄 요약)
- **본질**: 머신러닝의 성능 퇴화(Model Decay)를 유발하는 가장 치명적인 원인으로, 독립 변수($X$)의 분포는 그대로 유지될지라도 종속 변수($Y$)와의 통계적 매핑 관계($P(Y|X)$)가 변화하는 현상(사후 확률 이동, Prior Probability Shift).
- **가치**: 배포된 상용 모델의 예측 정확도 하락 원인을 '단순한 입력 노이즈(Data Drift)'와 '본질적 비즈니스 룰 변화(Concept Drift)'로 엄격히 구분하여, 무의미한 모델 재학습(Retraining) 비용을 방지하고 올바른 아키텍처 개선 방향을 제시함.
- **판단 포인트**: Concept Drift를 신속히 탐지하기 위해서는 실제 정답(Ground Truth)의 수집 파이프라인(Feedback Loop) 확보가 필수적이며, 변화의 양상(Abrupt, Incremental, Recurring)에 따라 슬라이딩 윈도우 기반 망각(Forgetting) 기법이나 앙상블(Ensemble) 가중치 조절 등 차별화된 MLOps 재학습 전략을 적용해야 함.

## Ⅰ. 개요 및 필요성
- **정의**: 기계학습 모델이 과거 데이터에서 학습한 지식(패턴, 분류 경계면)이 외부 환경의 거시적 변화나 새로운 규칙 등장으로 인해 더 이상 유효하지 않게 되어, 모델의 성능 지표(Accuracy, F1-Score)가 하락하는 현상.
- **배경**: AI 모델의 기본 전제인 정상성(Stationarity, 시간 불변의 법칙) 가정은 경제 사이클, 법적 규제, 소비 트렌드, 경쟁사 전략 등 역동적인 현실 비즈니스 세계에서는 성립하지 않음.
- **필요성**: 모델의 조용한 실패(Silent Failure) 방지, 비즈니스 KPI 하락 리스크 최소화, MLOps 환류(Feedback) 파이프라인의 자동 격발(Trigger) 근거 확보.

## Ⅱ. Data Drift vs Concept Drift (AI 붕괴의 두 축)
무엇이 변했는가에 따른 분류.
| 구분 | Data Drift (공변량 이동, Covariate Shift) | Concept Drift (개념 표류) |
|:---:|:---|:---|
| **수학적 정의** | $P(X_{train}) \neq P(X_{serve})$ | **$P(Y \mid X_{train}) \neq P(Y \mid X_{serve})$** |
| **본질적 현상** | 입력 문제의 유형(분포)이 변함 | **입력은 동일하나 정답(Target)의 기준이 변함** |
| **탐지 방법** | PSI, KS-test (입력 통계량만으로 가능) | **오류율(Error Rate), Accuracy (실제 정답 필수)** |
| **해결의 난이도**| 낮음 (새 데이터 샘플링 후 재학습) | **매우 높음 (기존 지식 망각 기법, 모델 재설계)** |

## Ⅲ. Concept Drift의 3가지 변화 양상 및 파훼법
적의 패턴을 알아야 대처할 수 있다.
| 변화 양상 (Type) | 현상 특징 (Mechanism) | 대표적 발생 원인 | MLOps 대응 전략 (Mitigation) |
|:---:|:---|:---|:---|
| **Abrupt**<br>(급격한 변화) | 결정 경계가 하루아침에 완전히 뒤집어짐. 성능 지표 수직 낙하. | COVID-19 팬데믹, 센서 고장, 새로운 정부 규제 시행. | **전면 재학습 (Full Retraining)**. 기존 데이터(과거 지식) 전면 폐기. |
| **Incremental**<br>(점진적 변화) | 시간이 지남에 따라 모델 정확도가 서서히 우하향(Decay)함. | 거시 경제 물가 상승(인플레이션), 소비자의 점진적 취향 변화. | **슬라이딩 윈도우(Sliding Window)** 기법으로 최신 데이터에 가중치 부여. |
| **Recurring**<br>(주기적 변화) | 특정 시점마다 옛날 컨셉(Concept)이 반복적으로 다시 나타남. | 계절 변화, 블프 등 요일/연말연시 이벤트성 패턴. | 모델별 가중치를 부여하는 **다이나믹 앙상블(Dynamic Ensemble)**. |

## Ⅳ. 드리프트 탐지 알고리즘 (DDM: Drift Detection Method)
오차율 통계에 기반한 경보 시스템.
1. **작동 원리**: 이항 분포 기반 검정. 모델이 예측을 수행할 때 연속적으로 발생하는 오류율(Error Rate, $p_i$)과 표준편차($s_i$)를 모니터링함.
2. **Warning (주의 단계)**: 오류율 $p_i + s_i$가 학습 시점의 최저 오차 수준보다 $2\sigma$ (95% 신뢰구간) 이상 높아지면 Warning 단계 진입. (이때부터 들어오는 데이터는 수상하므로 버퍼에 모아둠).
3. **Drift (표류 확정)**: 오류율이 $3\sigma$ (99% 신뢰구간)를 돌파하면 Concept Drift 발생으로 최종 선언. (기존 모델을 버리고, Warning 때 모아둔 최신 데이터로 모델 재학습 격발).

## Ⅴ. 실무 적용 및 결론
- **판단 지표**: 모델 성능(F1, AUC) 하락 후 원인(Drift) 분석까지 걸리는 MTTD(시간), 정답 확보 파이프라인(Feedback Loop) 자동화율, Concept Drift 발생 선언 후 모델 재배포까지의 MTTR.
- **실무 설계**: 금융권 C사의 'AI 신용평가 심사 모델' 개선 사례. 정책 금리 인상 사이클에 진입하며 과거엔 '우량 고객(소득 3천만 원, 부채 1천만 원)'이었던 군에서 연체(Y)가 속출하는 Concept Drift 발생. 조치 방안: 1) 대출 상환 여부(정답/Label)가 6개월 뒤에나 확정되는 'Label Lag' 문제를 해소하기 위해, 초기 1개월 연체율을 Proxy Label(대리 정답)로 설정하여 조기 모니터링(DDM 적용) 파이프라인 구축. 2) DDM이 'Drift'를 알람하면 즉시 Airflow CT 파이프라인 가동. 3) 과거 3년 치 데이터를 전면 버리지 않고, Instance Weighting 기법을 적용해 최신 3개월 금리 인상기 데이터에 학습 가중치를 5배 높게 주어 재학습. 부도율 방어 성공.
- **결론**: 머신러닝의 본질은 패턴의 귀납적 추론이다. 하지만 내일의 해가 어제와 동일한 궤적으로 뜬다는 보장은 어디에도 없다. Concept Drift에 대한 관측(Observability)과 대응 시나리오가 없는 AI 서비스는 한 번 쓰고 버리는 일회용 장난감에 불과하다. 기업은 "완벽한 모델 하나를 만드는 것"이 아니라, "변화하는 세상의 속도에 맞춰 끊임없이 무너지며 재학습되는 자가 치유(Self-healing) 아키텍처"를 구축해야만 한다.

### 🔀 문제 유형별 목차 전환
- **Ⅱ·Ⅲ 강조 (개념/원리형)**: 지속적 학습(Continuous Learning) 관점의 '파괴적 망각(Catastrophic Forgetting)' 현상 분석. Concept Drift에 대응하기 위해 새 데이터를 학습시켰을 때, 모델이 과거의 유효한 지식까지 모조리 잊어버리는 부작용을 막기 위한 지식 증류(Knowledge Distillation) 및 EWC 알고리즘 원리 제시.
- **Ⅴ·Ⅵ 강조 (실무/설계형)**: 정답(Label) 확보가 극도로 지연되는(Label Lag) 현업의 고질적 한계 극복 설계. 딥러닝 잠재 공간(Latent Space)에서의 데이터 클러스터 매핑을 통한 비지도 학습(Unsupervised) 기반의 Concept Drift 조기 경보(Early Warning) 모니터링 시스템 아키텍처 구축 방안.
