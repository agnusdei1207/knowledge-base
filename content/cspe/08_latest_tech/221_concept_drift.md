# 📖 【암기용】 개념 완전 이해

> 목적: Concept Drift를 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 입력 데이터(X)와 예측하려는 정답(Y) 사이의 관계 자체가 변하여, 기존의 학습된 모델이 더 이상 유효하지 않게 되는 현상
- **왜 필요한가**: 데이터의 분포는 그대로여도 그 데이터가 의미하는 바(정답)가 변하면 모델이 틀린 예측을 하게 되는데, 이를 감지하지 못하면 비즈니스 결정에 치명적이기 때문
- **핵심 직관**: "어제의 정답이 오늘의 오답"이 되는 상황. 시험 공부를 완벽히 했고 문제 유형도 똑같은데, 출제 위원이 채점 기준(정답)을 몰래 바꾼 것과 같음

## 깊이 이해
- **배경·문제의식**: 세상의 규칙은 고정되어 있지 않다. 소비자 행동 패턴, 법적 규제, 경쟁사의 전략 등에 의해 똑같은 입력값이 전혀 다른 결과로 이어질 수 있다. Data Drift가 "문제지가 바뀌는 것"이라면, Concept Drift는 "문제는 똑같은데 정답이 바뀌는 것"이다. 이는 모델의 근본적인 논리가 무너지는 것이라 해결이 훨씬 어렵다.
- **작동 원리**: 시간이 지남에 따라 모델의 예측 성능(정확도, F1-Score 등)이 하락하는지를 상시 감시한다. 특히 $P(Y|X)$ 즉, 입력 $X$가 주어졌을 때 정답 $Y$가 나올 확률 분포가 변했는지를 통계적으로 분석한다. 급격한 변화(Abrupt Drift), 점진적 변화(Incremental Drift), 주기적 변화(Recurring Drift) 등으로 구분된다.
- **비유**: 예전에는 '스팸 메일'의 특징이 "광고"라는 단어였다면, 지금은 스팸 업자들이 "선물"이라는 단어를 써서 보낼 수 있다. 메일 내용(데이터)은 평범해 보여도 그게 '스팸'이라는 사실(정답)은 변한 것이다.
- **구체 예시**: 코로나19 이전에는 '비행기 티켓 대량 구매'가 '여행사 운영'의 신호였으나, 팬데믹 이후에는 '방역 인력 이동'이나 '단순 사재기' 등 전혀 다른 의미를 갖게 되어 기존 사기 탐지 모델이 오작동하는 경우다.
- **흔한 오해·주의점**: "데이터 드리프트만 해결하면 컨셉 드리프트도 해결된다"는 틀렸다. 데이터 분포는 아주 정상인데 모델 성능만 떨어지는 경우가 컨셉 드리프트의 전형적인 사례다. 따라서 반드시 실제 정답(Ground Truth)과 대조하는 성능 모니터링이 병행되어야 한다.

## 연결 개념
- Data Drift — 입력 데이터 $X$의 분포 자체가 변하는 현상
- Online Learning — 새로운 정답 데이터가 들어올 때마다 모델을 실시간으로 업데이트하는 기법
- Ground Truth — 모델의 예측이 맞았는지 틀렸는지 판단할 수 있는 실제 정답

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Concept Drift는 입력 특징($X$)과 목표 변수($Y$) 간의 통계적 관계($P(Y|X)$)가 시간 경과에 따라 변화하는 현상이다.
> 2. **가치**: 모델의 성능 퇴화(Model Decay) 원인을 규명하고, 모델의 전면 재학습 또는 가중치 조정의 근거를 제공한다.
> 3. **판단 포인트**: 정답 확보 주기(Label Lag)를 고려하여, 실제 성능 지표와 함께 오차 분포의 변화를 상시 추적해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 데이터와 타겟 간 관계 변화 이해 확인 | $P(Y|X)$ 변화, 사후 확률 변화(Prior Probability Shift) | 단순히 "모델이 틀림"이라고 모호하게 서술 |
| 드리프트 유형별 대응 역량 확인 | 급격(Abrupt), 점진(Incremental), 주기(Recurring) 드리프트 | 모든 드리프트에 동일한 재학습 주기 적용 |
| 성능 모니터링 및 알고리즘 이해 확인 | DDM(Drift Detection Method), Page-Hinkley Test | 통계적 탐지 방법론 누락 |

> 요약: 모델의 예측 논리가 현실과 괴리되는 현상을 감지하고, 이를 재학습 또는 가중치 조정을 통해 보정하는 체계 제시가 핵심이다.

## Ⅰ. 개요 및 필요성

- 정의: 머신러닝 모델이 학습한 입력과 정답 사이의 매핑 규칙이 환경 변화로 인해 변질되어 모델 신뢰도가 하락하는 현상
- 배경: 소비자 기호의 급격한 변화, 신기술 등장에 따른 기존 규칙 무효화, 사회적/법적 기준의 변경
- 필요성: 모델의 비즈니스 가치 유지, 의사결정 오판에 따른 금전적 손실 방지, 지속적 학습(Continuous Learning) 체계 구축

## Ⅱ. 구조 및 구성요소

```text
Training Concept: P(Y|X) at t0 -> Prediction Service -> Feedback Loop
                                          |
                +-------------------------+-------------------------+
                |                                                   |
        Performance Monitor                             Statistical Test
        (Accuracy/Precision/Recall)                     (DDM/EDDM/PH Test)
                |                                                   |
                +-------------------------+-------------------------+
                                          |
                              Decision: Retrain / Update / Rollback
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Performance Base | 학습 시 달성한 모델의 기준 성능 지표 | Baseline Metrics |
| Label Collector | 실시간/배치 운영 정답 데이터 수집 | Ground Truth 확보 |
| Drift Detector | 성능 지표의 통계적 유의미한 하락 감지 | DDM, Page-Hinkley 등 |
| Update Controller | 모델 재학습 또는 가중치 조정 실행 | Active/Passive Learning |

> 요약: 모델의 예측 결과와 실제 정답을 지속적으로 대조하여 성능의 통계적 유의성을 검정함.

## Ⅲ. 동작원리 및 흐름도

```text
실제 정답(Label) 확보 -> 예측값과 대조 -> 오차율(Error Rate) 산출 -> 오차 분포 변화 검정 -> 임계치 위반 시 경고 -> 전면 재학습 트리거
      |                   |                |                    |                     |                     |
      +-------------------+----------------+--------------------+---------------------+---------------------+-----> 신규 모델 배포
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | Ground Truth 데이터 피드백 수집 | 정답 확보 지연 시간(Lag) 관리 |
| 2 | 오차율 기반 통계 지표 산출 | 표준 편차 및 평균 오차 추적 |
| 3 | 드리프트 탐지 알고리즘 실행 | DDM(Warning/Drift 단계 구분) |
| 4 | 모델 업데이트 전략 수립 | 전체 재학습 vs 부분 가중치 조정 |

> 요약: 모델의 '틀리는 방식'이 변하는지를 실시간으로 추적하여 규칙의 변화를 감지함.

## Ⅳ. 특징

| 구분 | 급격한 변화 (Abrupt) | 점진적 변화 (Incremental) | 주기적 변화 (Recurring) |
|:---|:---|:---|:---|
| 발생 양상 | 특정 시점에 갑자기 발생 | 시간이 지남에 따라 서서히 변화 | 특정 주기로 반복 발생 |
| 원인 예시 | 법규 개정, 시스템 장애 | 소비자 기호 변화, 기기 노후화 | 계절성, 요일별 패턴 |
| 대응 전략 | 즉시 전면 재학습 | 슬라이딩 윈도우 기반 학습 | 주기별 앙상블/가중치 적용 |
| 탐지 난이도 | 낮음 (성능 급락) | 높음 (서서히 퇴화) | 중간 (이력 관리 필요) |

> 요약: 변화의 양상에 따라 탐지 기법과 모델 업데이트 전략을 차별화하여 적용해야 함.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | Data Drift (P(X)) | Concept Drift (P(Y\|X)) | 선택 기준 |
|:---|:---|:---|:---|
| 핵심 현상 | 입력 분포의 변화 | 관계/규칙의 변화 | 변화의 근본 원인 |
| 탐지 지표 | PSI, KS-test (입력값 중심) | Accuracy, F1 (결과값 중심) | 데이터 확보 상태 |
| 대응 시점 | 사전 대응 (Proactive) | 사후 대응 (Reactive) | 비즈니스 크리티컬도 |
| 해결 난이도 | 데이터 재샘플링으로 해결 가능 | 모델 구조/알고리즘 재검토 필요 | 문제의 복잡성 |

> 요약: Data Drift는 입력 데이터 관리로 해결 가능하나, Concept Drift는 모델의 지능 자체를 재구축해야 함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| Label Lag | 정답 확인에 긴 시간 소요 (예: 대출) | 대리 지표(Score 분포) 모니터링 | 예측 스코어 분포 안정성 |
| Over-training | 빈번한 재학습으로 인한 노이즈 학습 | 검증 데이터셋 고도화 및 규제화 | 테스트셋 성능 유지 여부 |
| Catastrophic Forgetting | 새 데이터 학습 시 이전 지식 망각 | 가중치 보존 학습 및 앙상블 | 과거 데이터에 대한 성능 유지 |

> 요약: 정답 지연은 대리 지표로, 과적합은 검증 강화로, 망각은 앙상블 기술로 대응함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 성능 하락 감지율 | 유의미한 하락 발생 후 24시간 내 감지 | 드리프트 발생 시점과 탐지 시점 대조 |
| 재학습 정확도 향상 | 재학습 후 F1-Score 10%p 이상 회복 | 재학습 전후 성능 비교 |
| 오탐률 (False Alarm) | 오탐으로 인한 불필요 재학습 5% 이하 | 알람 후 실제 분석 결과 대조 |

> 요약: 도입 효과는 탐지 신속성, 성능 복구 수준, 모니터링 정확도로 판정함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 적응형 학습(Adaptive Learning): DDM 알고리즘을 적용하여 'Warning' 단계에서는 데이터를 축적하고, 'Drift' 단계 도달 시 즉시 자동 재학습 파이프라인 가동
2. 앙상블 가중치 조정: 주기적(Recurring) 변화가 있는 수요 예측 모델의 경우, 계절별 전문 모델들을 앙상블하고 실시간 성능에 따라 모델 가중치를 동적으로 조정
3. 온라인 모니터링: 지연된 정답(Label Lag)이 있는 환경에서 모델의 예측값 분포 변화를 추적하여 컨셉 드리프트 발생 가능성을 선제적으로 예측

**결론 (2줄):**
- 기술사 판단: Concept Drift는 모델의 유효 기한을 결정하는 가장 치명적인 요인이며, 이를 관리하지 않는 AI는 결국 "과거의 유물"로 전락함
- 향후 방향: 정답 없이도 컨셉 변화를 추론하는 비지도 학습 기반 드리프트 탐지와 LLM을 활용한 원인 분석 기술이 결합될 전망
