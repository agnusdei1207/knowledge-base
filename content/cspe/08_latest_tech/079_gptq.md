## 미리 알고가기

- $GPTQ$: 가중치를 통째로 양자화하는 대신, 행렬의 역행렬 기반 헤시안($Hessian$) 수학 행렬을 도출하여 누적 오차를 다른 가중치로 이관 보정하는 고성능 포스트 훈련 4비트 양자화($PTQ$) 기법임
- 헤시안 행렬 ($Hessian$ $Matrix$): 신경망의 비용 함수(오차)를 각 파라미터별로 2차 편미분한 행렬로, 특정 가중치 변화가 전체 오차에 미치는 민감도를 보여주는 수학적 잣대임
- 최적 뇌 프루닝 ($OBD$, Optimal Brain Surgeon): 과거 제안된 신경망 연결 감축 공식으로, 하나의 가중치를 제거했을 때 주변 가중치들을 역헤시안 공식을 통해 수정 복원하는 수학 원리임
- 복잡도 ($Perplexity$): 언어 모델이 출력 토큰을 생성할 때 느끼는 혼란도를 수치화한 평가지표로, 이 값이 낮을수록 모델의 예측 지능이 무너지지 않고 우수함을 대변함

## Ⅰ. 개요

- **정의/개념**: GPTQ는 학습이 완료된 대형 언어 모델의 가중치를 추가 미세조정($Fine-tuning$) 없이 $4$비트 정수로 감축하기 위해, 2차 편미분 헤시안 행렬을 분석하여 하나의 가중치를 양자화할 때 발생하는 수학적 왜곡 오차를 아직 압축되지 않은 주변 가중치들에 전이 보정하는 순차적 포스트 훈련 양자화($PTQ$) 기법임
- **배경/필요성**: 기존 4비트 양자화는 정교한 보정 계산이 없으면 모델의 언어 복잡도(Perplexity)가 극적으로 망가져 답변이 전면 왜곡되었는데, 추가 훈련 서버 인프라 비용 없이 단 몇 시간의 CPU/GPU 연산만으로 높은 품질의 경량 모델을 확보하고자 고안됨

## Ⅱ. 특징

- 고전 이론인 최적 뇌 프루닝($OBD$) 공식을 응용 및 극대 가속화하여, 수십억 개의 매개변수 행렬을 단시간 내에 오차 보정 컴파일 완료함
- 가중치를 4비트 정수로 축소 저장하고 추론 사이클마다 FP16으로 핫스왑 디코딩하며, VRAM 소모를 단 $25\%$ 수준으로 폭락시킴
- 캘리브레이션용 소량의 데이터셋(보통 128~256개 문장 수준)만으로도 가중치 블록들의 누적 에너지를 안정적으로 흡수 및 조율함

## Ⅲ. 종류 및 비교

| 판단 기준 | 기본 포스트 훈련 양자화 (Naive PTQ) | GPTQ 양자화 (Hessian 보정) | AWQ 양자화 (Activation 기반 보정) |
|:---|:---|:---|:---|
| **오차 보정 기법** | 없음 (단순 반올림 사상) | 가중치 역헤시안($H^{-1}$) 오차 순차 보정 | 활성값 크기에 비례한 가중치 스케일 보호 |
| **추론 정밀도 보존** | 낮음 (4비트 시 붕괴 수준) | 우수함 (Perplexity 붕괴 방어) | 매우 우수함 (특히 긴 입력, RAG서 우수) |
| **변환 연산 시간** | 즉시 완료 (수 분 이내) | 중간 수준 (1 GPU 당 약 1~3시간 수반) | 낮음 (Hessian 계산을 안 거치므로 신속함) |
| **하드웨어 호환성** | 보편적임 | 매우 우수함 (AutoGPTQ 등 오픈소스 풍부) | 우수함 (vLLM 기본 탑재 가속 지원) |

> 요약: Naive PTQ는 속성 간이 변환에, GPTQ는 헤시안 오차 보정을 기반으로 한 저비용 가중치 최적화에, AWQ는 실제 활성값 병목까지 융합 제어하는 최상위 서빙에 활용됨.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 헤시안 보정기 | 손실 함수의 2차 도함수를 역행렬 변환하여 가중치 수정 델타($\Delta W$)를 도출하는 모듈임 |
| 블록 순차 양자화기 | 가중치 행렬을 칼럼(Column) 블록 단위로 쪼개, 한 블록씩 순차 압축을 먹여나가는 엔진임 |
| 캘리브레이션 셋 | Hessian 스코어의 대표 뼈대를 추출하기 위해 투입하는 사내 표준 텍스트 데이터셋임 |
| $AutoGPTQ$ 런타임 | 변환이 끝난 가중치 파일들을 CPU/GPU 노드 상에서 즉각 로드해 주는 구동 프레임워크임 |

```text
[ GPTQ (순차 오차 전이) 연산 구조 ]
Column Weights -> [ Quantize Col 1 ] --(오차 계산)--> [ Calculate Hessian δW ]
                                                             │ (주변 미압축 가중치에 이식)
                                                             v
                  [ Quantize Col 2 ] <----------------- [ Apply Correction ]
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 오리지널    | --> | 역헤시안     | --> | 블록 단위   | --> | 4비트 보정  |
| 텐서 로딩   |     | 행렬($H^{-1}$)도출|     | 양자화/보정 |     | 바이너리출력|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **지수 수집** — 대상 모델 가중치에 캘리브레이션 셋을 주입하여 가중치 채널별 출력 임베딩을 정밀 프로파일링함
2. **역헤시안 계산** — Cholesky 분해 기법을 연동하여 오차 2차 편미분의 역헤시안($H^{-1}$) 행렬을 계산 수립함
3. **블록 순차 변환** — 가중치 행렬의 $1$번 블록 칼럼을 $4$비트로 강제 매핑한 뒤, 발생한 에러 값을 역헤시안 델타 가이드에 따라 $2$번 블록에 반영함
4. **바이너리 빌드** — 전체 파라미터의 변환이 끝날 때까지 루프를 회전하고, 극강의 가성비를 띄는 $4$비트 압축 아티팩트를 저장함

## Ⅵ. 실무 적용 및 유의점

1. GPTQ는 순수하게 가중치(Weight) 중심의 오차 전이만을 처리하므로, 실서비스 가동 중 대규모 질의(Activation)가 인입되어 발생한 Outlier 문제를 제어하지 못해 Perplexity가 튈 수 있으므로, 반드시 AWQ 라이브러리와 교차 검증을 실행하고, 언어 복잡도($Perplexity$) 보존 상태를 사전에 감시해야 함
2. 변환용 캘리브레이션 텍스트 파일(Calibration Set)의 질이 지나치게 특정 한국어 도메인이나 협소한 개발문서에 치우치면 범용 대화(General Q&A) 성능이 역행해 파괴되므로, 위키피디아와 정제된 일상 대화록이 균형 있게 섞인 '사내 표준 캘리브레이션 코퍼스'를 셋업해 배포해야 함

## Ⅶ. 결론

- GPTQ는 복잡한 재학습 절차 없이 오직 2차 미분 수학 공식을 가동하여 4비트 극강 압축의 질적 저하를 철저히 보정한 실전형 배포의 바이블이며, 설계자는 가중치 보정의 한계를 보완할 범용 코퍼스 셋업 및 활성값 아웃라이어와의 복합 검증 파이프라인을 구축해 안전한 상용 AI 서비스를 운영해야 함
