## 미리 알고가기

- 데이터 카드는 데이터셋의 출처와 구성과 제약을 공개하는 문서형 거버넌스 산출물임
- 모델 편향과 개인정보 이슈는 상당수가 데이터셋 단계에서 시작되므로 모델 카드와 함께 봐야 함
- 메타데이터 요약을 넘어서 수집 동의와 대표성과 금지 사용 범위까지 기록하는 것이 핵심임

## Ⅰ. 개요

- **정의/개념**: 데이터 카드는 AI 학습과 평가에 사용되는 데이터셋의 생성 목적과 출처와 구성 분포와 수집·전처리 방식과 라이선스와 제한사항을 표준화해 기록하는 설명 문서임
- **배경/필요성**: 데이터 기반 사고는 모델 품질보다 앞단의 데이터 품질과 대표성과 권리 처리에서 많이 발생하므로, 데이터셋 자체의 맥락과 위험을 투명하게 남기는 체계가 필요해짐

## Ⅱ. 특징

- 데이터셋의 대표성과 편향과 민감정보 포함 여부를 구조적으로 드러내어 사전 검토를 쉽게 함
- 수집 동의와 저작권과 이용 제한을 함께 기록해 법적 리스크를 조기에 식별함
- 모델 카드와 연결되면 성능 문제의 원인을 데이터 측면에서 역추적하기 쉬워짐
- 문서가 버전 관리와 연결되지 않으면 오래된 설명이 남아 통제 효과가 급격히 떨어질 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | Data Card | Data Catalog | Model Card |
|:---|:---|:---|:---|
| 설명 대상 | 데이터셋 | 데이터 자산 목록 | 모델 |
| 핵심 내용 | 출처, 구성, 편향, 동의, 제한 | 스키마, 위치, 소유자 | 용도, 성능, 한계 |
| 주요 사용자 | 데이터 관리자, 모델러, 감사자 | 엔지니어, 운영자 | 배포자, 현업, 규제 대응 부서 |
| 실무 목적 | 데이터 적합성 판단 | 자산 검색과 관리 | 모델 사용 적합성 판단 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Dataset Overview | 데이터셋 목적과 생성 배경과 버전을 요약해 왜 존재하는지와 어떤 범위에서 써야 하는지를 설명함 |
| Source, Collection | 원천 시스템과 수집 방식과 동의 절차를 기록해 정당성 검토와 재현성을 높임 |
| Composition, Quality | 표본 수와 속성 분포와 결측과 라벨 품질을 정리해 대표성과 편향 위험을 드러냄 |
| Privacy, License | 개인정보 포함 여부와 비식별화 방식과 라이선스 조건을 명시해 법적 제약을 명확히 함 |
| Intended Use, Maintenance | 허용 사용 범위와 금지 사용 범위와 갱신 정책을 정해 오남용과 문서 노후화를 줄임 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 데이터 범위 정의  | --> | 프로파일/위험 점검 | --> | 카드 작성/승인  | --> | 버전별 갱신 유지 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **데이터 범위 정의**: 데이터셋 목적과 수집 범위와 책임자를 정함
2. **프로파일 및 위험 점검**: 분포와 품질과 개인정보와 라이선스를 분석함
3. **카드 작성 및 승인**: 허용 사용과 제한 사항을 포함해 문서를 확정함
4. **버전별 갱신 유지**: 데이터 변경과 라벨 수정과 재배포 시 카드를 함께 갱신함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 데이터 카드가 수작업 문서로만 유지되면 데이터셋 갱신 뒤에도 분포와 제약 정보가 오래된 채 남을 수 있음
   - 해결방안: profiling automation과 dataset versioning을 연동하고 document freshness와 version sync rate로 검증함
2. 문제: 집단별 분포와 동의 범위를 충분히 적지 않으면 모델러가 편향과 권리 제한을 모른 채 학습에 사용할 수 있음
   - 해결방안: subgroup profile과 consent field를 필수화하고 subgroup coverage와 consent completeness로 검증함
3. 문제: 카드가 접근 통제와 연결되지 않으면 금지 용도 데이터가 다른 프로젝트로 재사용될 위험이 커질 수 있음
   - 해결방안: data access policy와 use approval workflow를 연결하고 unauthorized reuse rate와 review completion rate로 검증함

## Ⅶ. 적용 사례

- 의료 데이터 레이크가 환자 데이터셋마다 수집 근거와 비식별화 상태를 카드로 관리하며 확인 지표는 consent completeness와 restricted access violation rate임
- 기업 내부 모델 허브가 학습 데이터셋의 대표성과 라이선스를 카드로 연결해 배포 전 검토를 수행하며 확인 지표는 dataset review lead time과 reuse accuracy임
- 공개 데이터 공유 포털이 금지 사용 범위와 품질 한계를 명시한 카드와 함께 배포되며 확인 지표는 misuse incident rate와 card coverage임

## Ⅷ. 결론

데이터 카드는 모델 성능 뒤에 숨어 있는 데이터의 편향과 권리 문제를 앞단에서 드러내는 기본 통제 문서이므로 데이터 버전과 함께 살아 움직이게 운영해야 함.
