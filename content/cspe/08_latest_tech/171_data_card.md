# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: AI 모델을 훈련시킨 '데이터셋'이 도대체 어디서 왔고, 누가 만들었으며, 어떤 한계와 편향을 가지고 있는지 표준화된 양식으로 문서화한 데이터 영양성분표.
- **필요성**: "Garbage In, Garbage Out". AI 사고의 90%는 데이터에서 옴. 깃허브에서 아무 데이터나 주워다 학습시켰다가 저작권을 위반하거나 개인정보(주민번호 등)가 줄줄 새는 대형 사고를 막기 위해, 데이터의 '출생의 비밀'을 투명하게 까야 함.
- **핵심 직관**: 마트의 식재료 원산지 표시와 영양성분표. 식당(AI 모델)이 아무리 요리를 잘해도, 식재료(데이터)가 유통기한이 지났거나 특정 알레르기 성분이 있다면 손님이 죽음. 요리하기 전에 식재료 뒷면의 라벨(데이터 카드)부터 확인하라는 뜻.

## 깊이 이해
- **배경**: 마이크로소프트 연구진(Timnit Gebru 등)이 "Datasheets for Datasets"라는 논문(2018)을 발표하며, 전자부품 산업에서 저항기(Resistor)를 살 때 제공되는 '데이터시트(Datasheet)' 개념을 머신러닝 데이터셋에 도입하자고 제안한 것이 시초. 구글은 이를 'Data Cards'라 명명함.
- **작동 원리 (데이터 생애주기별 자문자답)**:
  1. **동기 (Motivation)**: 이 데이터를 왜 만들었고, 누가 돈(펀딩)을 댔는가?
  2. **구성 (Composition)**: 이 데이터 안에 사람을 식별할 수 있는 민감 정보(PII)나 혐오 표현이 들어 있는가? 데이터는 몇 건인가?
  3. **수집 과정 (Collection Process)**: 알바생을 써서 라벨링했나? 사용자 동의(Consent)는 명시적으로 받았나?
  4. **전처리 (Preprocessing)**: 비식별화 처리는 어떻게 했는가?
  5. **배포 및 유지보수 (Distribution/Maintenance)**: 저작권/라이선스는 무엇인가(상업적 이용 가능)? 데이터가 업데이트되거나 오류 발생 시 누구한테 연락해야 하는가?
- **구체 예시**: 유명한 안면 인식 데이터셋인 'LFW(Labeled Faces in the Wild)'. 데이터 카드를 작성해 보니, "총 13,000장 중 77%가 남성, 83%가 백인"이라는 치명적인 편향 분포(Composition)가 투명하게 드러남. 덕분에 개발자들은 "아, 이 데이터로 만든 AI는 흑인 여성을 잘 못 알아보겠구나"라고 사전에 인지하고 조치할 수 있음.
- **흔한 오해/주의점**: "데이터 카탈로그나 메타데이터랑 같은 거 아님?" $\rightarrow$ 다름. 카탈로그가 '데이터베이스 컬럼명과 용량' 같은 기술적(IT) 정보라면, 데이터 카드는 '사회적/윤리적 맥락(Context)'과 '프라이버시 위험'에 초점을 맞춘 거버넌스 문서임.

## 연결 개념
- **Model Card (모델 카드)**: 데이터 카드가 식재료의 원산지 표시라면, 모델 카드는 그 식재료로 만든 '완성된 요리(AI 제품)'의 성분표. (둘은 항상 세트).
- **Data Governance (데이터 거버넌스)**: 데이터 품질, 보안, 프라이버시를 통제하는 전사적 체계. 데이터 카드는 이 거버넌스를 실행하는 핵심 산출물.
- **GDPR / 개인정보보호법**: 데이터 카드 작성 시 '수집 동의' 및 '비식별화' 항목을 채워 넣음으로써 법적 컴플라이언스를 입증함.

# 📝 【답안용】 시험 답안 템플릿
## 핵심 인사이트 (3줄 요약)
- **본질**: 기계학습 모델 학습에 사용되는 데이터셋의 생성 동기, 구성(분포), 수집 방법, 전처리 과정, 윤리적/법적 고려사항을 표준화된 프레임워크로 문서화한 명세서(Specification).
- **가치**: 모델 예측 편향(Bias)의 근본 원인인 데이터 불균형을 사전에 가시화하고, 개인정보(PII) 유출 및 저작권 위반 리스크를 투명하게 공개하여 책임 있는 AI(Responsible AI) 개발 생태계를 조성함.
- **판단 포인트**: 데이터 카드는 단순한 스키마(Schema) 정의서를 넘어, 데이터의 '사회 기술적 맥락(Socio-technical Context)'을 질문-답변(Q&A) 형태로 강제화하여 데이터 공급자와 사용자 간의 정보 비대칭을 해소하는 것이 핵심임.

## Ⅰ. 개요 및 필요성
- **정의**: 데이터셋의 출처, 라이선스, 품질 속성 및 윤리적 제약사항을 투명하게 기록하여, AI 개발자가 데이터의 적합성(Fitness for Use)을 판단할 수 있도록 돕는 표준화된 문서.
- **배경**: AI 커뮤니티의 관행적인 데이터 스크래핑(Scraping)과 재사용으로 인해, 특정 인구통계학적 그룹이 배제되거나 허가받지 않은 민감 정보가 딥러닝 모델에 영구적으로 종속되는 사고가 빈발함.
- **필요성**: 데이터 거버넌스 관점에서 모델의 예측 오작동(Downstream Harm) 발생 시 원인 추적성(Traceability)을 확보하고, 글로벌 AI 법안(EU AI Act)의 데이터 품질 요건(Data Governance and Management)을 준수하기 위함.

## Ⅱ. 데이터 카드(Datasheet)의 7대 핵심 구성 요소 (Framework)
Microsoft의 "Datasheets for Datasets" 프레임워크 기반.
| 구성 요소 (Phase) | 핵심 점검 질문 및 기재 내용 | 윤리적/거버넌스 목적 |
|:---:|:---|:---|
| **1. 동기 (Motivation)** | 데이터셋 생성 목적은 무엇이며, 펀딩 주체는 누구인가? | 이해상충(Conflict of Interest) 방지. |
| **2. 구성 (Composition)** | **특정 인종/성별 등 하위 그룹의 분포 편향성**이 존재하는가?<br>개인 식별 정보(PII)나 유해 콘텐츠가 포함되어 있는가? | **알고리즘 편향(Bias) 사전 예측 및 평가.** |
| **3. 수집 (Collection)** | 데이터 수집 대상자로부터 **명시적 동의(Consent)**를 받았는가?<br>어떤 API나 스크래핑 도구를 사용했는가? | GDPR 등 프라이버시 권리 침해 방어. |
| **4. 전처리 (Preprocessing)** | 결측치 처리, 노이즈 제거, 데이터 정규화는 어떻게 했는가? | 재현성(Reproducibility) 확보. |
| **5. 사용 (Uses)** | 이 데이터가 기존에 쓰였던 곳은 어디이며, **어떤 목적으로 사용하면 절대 안 되는가(비권장 용도)?** | 무분별한 모델 오용 방지. |
| **6. 배포 (Distribution)** | 저작권 및 라이선스(상업적 이용 가능 여부)는 무엇인가? | 라이선스 위반 소송 방어. |
| **7. 유지보수 (Maintenance)**| 데이터 오류 발견 시 업데이트 정책 및 컨택 포인트(Owner). | 데이터 수명주기 관리 체계화. |

## Ⅲ. Data Catalog와의 차별성 비교
| 구분 | 기존 데이터 카탈로그 (Data Catalog) | 데이터 카드 (Data Card) |
|:---:|:---|:---|
| **목적** | 데이터의 **검색성(Discoverability)** 및 IT 자산 관리 | 데이터의 **맥락적 이해(Contextual Understanding)** |
| **기재 내용** | 테이블명, 칼럼 스키마, 용량, ERD | **데이터 수집 동의 여부, 인구통계학적 편향 비율** |
| **타겟 독자** | DBA, 데이터 엔지니어 | **AI 모델러, 규제/감사/법무 담당자** |

## Ⅳ. 데이터 카드 작성 프로세스 (MLOps 연계)
- **Data Profiling 자동화**: 데이터셋을 Data Lake에 적재할 때, Profiling Tool(예: Pandas Profiling, Great Expectations)을 통해 성별/나이 등의 분포 히스토그램을 자동 추출하여 데이터 카드에 연동.
- **Shift-Left Security**: 모델 학습 단계(Training Pipeline) 진입 전, CI/CD 파이프라인에서 데이터 카드의 'PII 포함 여부' 항목이 True일 경우, 비식별화 처리 모듈이 강제 실행되도록 아키텍처 구성.

## Ⅴ. 실무 적용 및 결론
- **판단 지표**: 사내 AI 학습용 데이터셋의 데이터 카드 작성 완료율, 라이선스 적합성 검증 완료율, 민감 정보(PII) 마스킹/제거율.
- **실무 설계**: 국내 E 통신사의 AI 기반 '대화형 고객 상담 챗봇(LLM)' 구축 프로젝트. 수백만 건의 과거 CS 녹취/채팅 로그를 학습해야 함. 개인정보보호법 위반 리스크를 통제하기 위해 데이터 카드 작성 의무화 시행. "Composition" 항목에서 고객의 주민등록번호와 신용카드 번호가 텍스트에 혼재되어 있음을 명시함. "Collection" 항목에서 'AI 학습 동의'를 받지 않은 과거 5년 전 고객 데이터가 섞여 있음을 식별함. 이에 따라 법무팀 개입하여 미동의 데이터 전량 폐기, PII 자동 치환(Masking) 후 "Preprocessing" 항목에 기술. 완벽한 거버넌스를 갖춘 클린 데이터셋을 기반으로 안전하게 챗봇 모델 학습.
- **결론**: 데이터 카드는 AI라는 고속 열차를 위한 튼튼한 '선로(Track)'와 같다. 선로(데이터)의 부실을 모른 채 열차(모델)의 속도만 높이면 반드시 대형 참사가 발생한다. 기업은 AI 모델 개발 착수 전, 데이터 카드를 필수 게이트(Gate)로 삼는 데이터 중심 AI(Data-Centric AI) 문화를 정착시켜야 한다.

### 🔀 문제 유형별 목차 전환
- **Ⅱ·Ⅲ 강조 (개념/원리형)**: 데이터 편향의 근본 원인인 표본 편향(Sampling Bias), 레이블 편향(Label Bias)의 수학적 탐지 지표(예: Disparate Impact Ratio)와 이를 데이터 카드에 명세하는 템플릿 구조.
- **Ⅴ·Ⅵ 강조 (실무/설계형)**: 전사 데이터 패브릭(Data Fabric) 아키텍처 상에서 Data Card의 메타데이터를 활용하여 LLM 학습용 RAG(Retrieval-Augmented Generation) 파이프라인의 접근 권한 제어(ABAC) 아키텍처 연계 방안.
