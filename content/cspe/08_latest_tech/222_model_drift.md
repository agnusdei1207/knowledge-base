# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: 운영(Production) 환경에 띄워 놓은 머신러닝 모델의 **예측 정확도가 시간이 지날수록 서서히 깎여나가거나(Decay) 어느 날 갑자기 뚝 떨어지는 총체적인 '성능 저하' 현상**.
- **필요성**: 개발자가 아무리 영혼을 갈아 99% 정확도의 모델을 배포했어도, 세상(데이터, 유행, 경제)은 멈춰 있지 않음. 가만히 냅두면 모델은 '과거의 망령'이 되어 계속 틀린 답을 뱉어냄. 모델의 유통기한이 끝났음을 빨리 파악하고 새 생명(재학습)을 불어넣기 위해 반드시 관리해야 함.
- **핵심 직관**: 모델은 '시한부' 지식인. 2020년 부동산 정책으로 똘똘하게 집값을 예측하던 전문가(모델)가, 2026년 규제가 다 풀린 시장에 나와서 똑같은 잣대로 집값을 부르면 다 틀림(Model Drift). 지식 자체가 변질된 게 아니라 세상이 변해서 기존 지식이 낡아버린 것.

## 깊이 이해
- **배경**: AI 서비스의 뼈아픈 진실 중 하나는 "배포된 첫날의 모델 성능이 내 평생 볼 수 있는 최고점"이라는 것임. 시간이 갈수록 Model Drift가 발생해 우하향 곡선(Degradation Curve)을 그림. 이를 'Silent Failure(소리 없는 실패)'라고 부르는데, 서버(CPU/RAM) 에러는 안 뱉고 결과값만 엉망이 되기 때문에 방치하면 회사에 막대한 손해를 끼침.
- **작동 원리 (왜 발생하나?)**: Model Drift는 혼자 생기는 병이 아니라, **두 가지 바이러스(원인)**의 합병증임.
  1. **Data Drift (입력의 표류)**: 들어오는 손님들의 성향(입력 데이터 분포)이 바뀜. (예: 20대 쇼핑몰에 50대 유입).
  2. **Concept Drift (정답의 표류)**: 세상의 법칙(정답의 기준) 자체가 바뀜. (예: 인플레이션으로 '비싼 시계'의 기준이 100만 원에서 500만 원으로 상향).
- **비유**: 김치냉장고에 넣어둔 김치. 처음 넣었을 때(배포)는 아삭하고 맛있지만, 시간이 지남에 따라 유산균 발효(세상의 변화)가 일어나 맛이 변함(Drift). 이걸 모니터링 안 하고 1년 뒤에 꺼내 먹으면 셔서 못 먹음.
- **구체 예시**: 항공권 가격 예측 모델. 2019년에 완벽하게 예측하던 모델이, 2020년 코로나19 사태가 터지며 항공편이 90% 결항하고 수요가 박살 나자 가격 예측을 전부 틀려버림(Model Drift 발생).
- **흔한 오해/주의점**: "Model Drift = Data Drift 인가요?" $\rightarrow$ 아님! Model Drift는 정확도, F1 점수 등 '최종 결과(성능)'가 떨어진 **결과 현상**을 의미함. Data Drift와 Concept Drift는 그 결과를 만든 **원인**임. 병명(Model Drift)과 바이러스 이름(Data/Concept)을 혼동하면 안 됨.

## 연결 개념
- **Data Drift**: Model Drift의 원인 1. 데이터 입력 분포의 변경.
- **Concept Drift**: Model Drift의 원인 2. 입력과 정답 간의 매핑 규칙 변경.
- **Continuous Training (CT)**: Model Drift를 치유하는 유일한 백신. 자동화된 파이프라인으로 최신 데이터로 모델을 재학습시킴.

# 📝 【답안용】 시험 답안 템플릿
## 핵심 인사이트 (3줄 요약)
- **본질**: 머신러닝 모델이 프로덕션 환경에 배포된 이후, 시간 경과와 현실 세계의 동적 변화(Non-stationarity)로 인해 모델의 예측 성능(Accuracy, AUC 등)이 지속적으로 하락하는 모델 퇴화(Model Decay/Staleness) 현상.
- **가치**: 모델의 맹목적인 장기 운영을 경계하고, 성능 하락의 임계치(Threshold)를 정의하여 MLOps 파이프라인 내에서 최적의 '자동 재학습(Continuous Training)' 트리거 시점을 결정하는 판단 기준이 됨.
- **판단 포인트**: Model Drift(성능 저하)라는 결과 현상을 마주했을 때, 그 근본 원인(RCA)을 추적하여 입력 공간의 문제인 **Data Drift(공변량 이동)**인지, 관계 공간의 문제인 **Concept Drift(개념 표류)**인지를 식별하고 그에 맞는 보정 전략을 설계해야 함.

## Ⅰ. 개요 및 필요성
- **정의**: 기계학습이 가정한 IID(독립동일분포) 전제가 깨짐으로써, 기준점(Baseline, 배포 시점) 대비 현재 운영 모델의 예측 정확도가 비즈니스 허용 오차를 벗어나 감퇴하는 전체적인 현상.
- **배경**: 거시 경제 변화, 계절적 요인(Seasonality), 데이터 수집 센서 변경, 상위 애플리케이션의 UI/UX 변경에 따른 사용자 행동 패턴의 변화 등.
- **필요성**: 인프라 장애(Hard Error)가 아닌 논리적 오판(Soft Error, Silent Failure)으로 인한 고객 신뢰 하락 및 재무적 손실 방지, 데이터 과학 팀의 유지보수(Maintenance) 자동화.

## Ⅱ. Model Drift 발생 메커니즘 및 2대 근본 원인
결과를 만드는 두 가지 기저 원리.
| 원인 지표 (Root Causes) | 발생 메커니즘 (Mechanism) | 탐지 지표 및 모니터링 |
|:---:|:---|:---|
| **Data Drift**<br>(데이터 표류) | $P(X)$의 변화. 데이터의 입력 변수(Feature) 분포가 과거 학습 시점과 달라져, 모델이 한 번도 본 적 없는 데이터 영역(Out-of-Distribution)에 직면함. | PSI(Population Stability Index), KS-test. (정답 Label 불필요, 조기 탐지 가능). |
| **Concept Drift**<br>(컨셉 표류) | $P(Y \mid X)$의 변화. 입력 데이터는 동일하지만, 현실의 규칙(Rule) 자체가 변해 기존 정답이 오답이 됨. (예: 인플레에 따른 고가 분류 기준 변경). | Accuracy, F1, RMSE 등 모델 평가 지표. (정답 Label 확보 필수, 사후 탐지). |
| **$\Rightarrow$ Model Drift**<br>(모델 표류) | **위 두 가지 원인이 단독 또는 복합 작용하여, 최종 산출물인 모델의 성능(Prediction Quality)이 비즈니스 요구치를 밑돌게 됨.** | 비즈니스 KPI 연동, 사용자 피드백(클릭률, 이탈률). |

## Ⅲ. Model Drift 탐지 및 자동 복구 워크플로우 (MLOps CT)
성능을 회복하는 폐루프(Closed-Loop).
1. **관측 (Observability)**: 실시간 추론(Inference) 로그와 실제 정답(Ground Truth) 데이터를 데이터 레이크에 적재하고 실시간 Accuracy 추적.
2. **트리거 (Trigger)**: F1-Score가 설정된 임계치(예: 85% $\rightarrow$ 78%) 이하로 3일 연속 하락하면 Model Drift 경보(Alert) 발송 및 파이프라인 자동 격발.
3. **원인 분석 (RCA)**: Drift의 주범 탐색. 특정 Feature(예: 나이대)의 PSI가 0.2를 초과했는지(Data Drift) 확인.
4. **재학습 (Continuous Training)**: 최신 3개월 치 데이터(Recent Window)를 추출하여 훈련 파이프라인(Airflow, Kubeflow) 재가동.
5. **A/B/Shadow 배포**: 기존 모델(Champion)과 신규 모델(Challenger) 간의 성능 경쟁 후 우위 확보 시 무중단 자동 교체(CD).

## Ⅳ. 모델 재학습(Retraining) 전략 트레이드오프 비교
언제 학습시킬 것인가?
| 전략 구분 | 방식 및 장점 | 단점 및 한계 | 적용 도메인 |
|:---:|:---|:---|:---|
| **주기적 재학습**<br>(Scheduled Batch) | 매주, 매월 등 정해진 배치 스케줄에 따라 맹목적 재학습. 구조가 매우 단순함. | 드리프트 미발생 시 자원 낭비. 급격한 변화 시 갱신 전까지 성능 박살. | 이탈 예측 등 변화가 느리고 정적인 환경. |
| **Drift-based 재학습**<br>(Trigger 기반) | 성능 하락 임계치(Drift) 감지 시에만 파이프라인 호출. 리소스 최적화 및 신속 대응. | 모니터링 시스템 구축비용 증가, Label 지연 시 트리거 시점 지연. | 금융 FDS, 추천 등 트렌드가 급변하는 환경. |

## Ⅴ. 실무 적용 및 결론
- **판단 지표**: 드리프트 발생 후 성능 회복까지 걸리는 리드타임(MTTR), 오탐(False Positive)으로 인한 불필요한 재학습 횟수, 모델 라이프사이클당 가치 창출(ROI) 기여도.
- **실무 설계**: 대형 리테일 기업 E사의 '상품 수요 예측 모델' 고도화 사례. 기존엔 1년에 한 번 모델을 수동 업데이트하여, 여름 휴가철이나 이른 추석 등 계절 변동(Model Drift) 시마다 재고 결품/악성 재고 사태가 터짐. 조치 방안: MLflow 및 Seldon Core 기반의 드리프트 감시 체계 도입. 1) 예측 오차율(MAPE)이 기준치 대비 10%p 이상 벌어지는 Model Drift 탐지 규칙 설정. 2) 알람 발생 시, 트리거 파이프라인이 구동되어 과거 데이터에 가중치를 줄이고(Forgetting Factor) 최근 2주 폭증 데이터에 높은 가중치를 주어 섀도우 모델(Shadow Model) 생성. 3) 자동 평가 결과 MAPE 개선 시 즉각 카나리 배포. 재고 관리 비용 30% 절감.
- **결론**: 머신러닝의 진정한 생애는 개발 환경(Dev)에서 시작되는 것이 아니라, 통제 불가능한 프로덕션(Ops) 환경의 폭풍우와 마주치는 순간 시작된다. Model Drift는 피할 수 있는 버그가 아니라 시간의 흐름에 따른 자연법칙(엔트로피)이다. 이를 제어하기 위해 기업은 '한 번의 완벽한 모델링'에 집착할 것이 아니라, MLOps의 촘촘한 관측망을 통해 모델의 타락을 감시하고 적시에 재학습의 호흡을 불어넣는 자동화된 "맥박 유지 장치(Continuous Training)"를 마련해야 한다.

### 🔀 문제 유형별 목차 전환
- **Ⅱ·Ⅲ 강조 (개념/원리형)**: 성능 지표 관점에서의 퇴화 함수(Decay Function) 수리적 모델링. 시간이 지남에 따라 모델 예측 오차가 지수적으로 증가하는 메커니즘을 수식으로 증명하고, 망각 인자(Forgetting Factor)를 도입한 데이터 윈도잉(Windowing) 기법 원리 분석.
- **Ⅴ·Ⅵ 강조 (실무/설계형)**: 운영 비용 최적화(FinOps) 모델 재학습 아키텍처. GPU 클라우드 비용이 높은 환경에서 Model Drift 탐지 시 무조건적인 '전면 재학습(Full Retraining)' 대신, 변동이 큰 상위 레이어만 미세 조정하는 온라인 퓨샷 파인튜닝(Online Few-shot Fine-tuning)으로 컴퓨팅 비용을 70% 절감하는 아키텍처 구축 방안.
