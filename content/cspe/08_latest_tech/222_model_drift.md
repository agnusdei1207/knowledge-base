# 📖 【암기용】 개념 완전 이해

> 목적: Model Drift를 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 운영 환경에 배포된 머신러닝 모델의 예측 성능이 시간이 지남에 따라 서서히 혹은 급격히 떨어지는 현상 (Model Decay)
- **왜 필요한가**: 모델은 학습된 시점의 데이터를 기준으로 최적화되어 있는데, 세상은 계속 변하기 때문에 "가만히 두면 모델은 반드시 퇴화"하기 때문
- **핵심 직관**: 10년 전 유행어를 학습한 챗봇이 요즘 10대들과 대화하면 말이 안 통하는 것과 같음. 모델 자체의 고장보다는 "시대에 뒤처지는" 문제

## 깊이 이해
- **배경·문제의식**: 모델 드리프트는 단일 현상이 아니라, **Data Drift**(입력 데이터의 변화)와 **Concept Drift**(규칙의 변화)가 결합되어 나타나는 결과물이다. 모델 개발자는 "완벽한 모델"을 만들었다고 생각하지만, 실제 배포된 순간부터 모델의 유통기한은 줄어들기 시작한다. 이를 방치하면 비즈니스 성과(매출, 정확도)가 조용히 하락하는 'Silent Failure'가 발생한다.
- **작동 원리**: 모델의 주요 성능 지표(Accuracy, F1, AUC 등)를 실시간으로 모니터링한다. 기준점(Baseline) 대비 성능이 통계적으로 유의미한 수준 이하로 떨어지는지 감시하며, 그 원인이 데이터 변화인지 규칙 변화인지를 분석하여 재학습(Retraining) 전략을 세운다.
- **비유**: 새 차를 샀을 때는 성능이 좋지만, 정기적으로 엔진오일을 갈고 정비하지 않으면 점차 연비와 출력(성능)이 떨어지는 과정과 같다. 여기서 '정비'는 '재학습'에 해당한다.
- **구체 예시**: 주식 예측 모델이 과거 상승장에서만 학습되었는데, 하락장이나 박스권 장세가 오면 예측력이 급격히 상실되는 현상이다.
- **흔한 오해·주의점**: "Model Drift는 데이터가 잘못 들어와서 생기는 것이다"라고만 생각하기 쉬우나, 데이터는 멀쩡한데 사람들의 마음(Concept)이 변해서 생기는 경우가 훨씬 까다롭다. 따라서 성능 지표뿐만 아니라 비즈니스 KPI와 연계하여 통합적으로 봐야 한다.

## 연결 개념
- Data Drift — 모델 드리프트의 주요 원인 중 하나 (입력값의 변화)
- Concept Drift — 모델 드리프트의 주요 원인 중 하나 (정답과의 관계 변화)
- Model Decay — 모델 성능이 퇴화하는 현상을 일컫는 또 다른 용어

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Model Drift는 현실 세계의 동적인 특성으로 인해 학습된 모델의 성능이 배포 시점 대비 하락하는 현상(Model Decay)이다.
> 2. **가치**: 모델의 유효 기한을 정량화하고, 최적의 재학습(Retraining) 주기를 결정하여 일관된 서비스 품질을 보장한다.
> 3. **판단 포인트**: 성능 하락의 원인을 Data Drift(입력 분포)와 Concept Drift(관계 변화)로 구분하여 맞춤형 복구 전략을 수립해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 모델 성능 저하 원인 규명 역량 확인 | Data Drift와 Concept Drift의 복합적 영향 기술 | 단순히 "성능이 나빠짐"이라고 모호하게 서술 |
| MLOps 환류(Feedback) 체계 이해 확인 | 모니터링, 알람, 재학습 파이프라인 연계 | 장애 대응(Server Reboot 등)과 혼동하여 기술 |
| 정량적 탐지 및 지표 활용 능력 확인 | 성능 지표(F1, AUC), 통계 지표(PSI, KS-test) | 구체적 지표 및 수치 기준 누락 |

> 요약: 모델 성능 하락을 상시 감시하고 원인별 처방(재학습, 모델 롤백, 데이터 보정)을 내리는 운영 체계 제시가 핵심이다.

## Ⅰ. 개요 및 필요성

- 정의: 운영 환경의 데이터 분포 변화나 비즈니스 규칙의 변경으로 인해 배포된 모델의 예측력이 점진적으로 감퇴하는 현상
- 배경: 현실 데이터의 비정상성(Non-stationarity), 트렌드 변화, 신규 카테고리 등장 등 외부 환경의 동적 특성
- 필요성: 모델 신뢰성 유지, 오작동으로 인한 비즈니스 손실 방지, 데이터 과학 팀의 사후 관리(Maintenance) 효율화

## Ⅱ. 구조 및 구성요소

```text
Live Data -> ML Model -> Predictions vs Ground Truth
                           |
            +--------------+--------------+
            |                             |
      Model Monitoring              Analysis Engine
      (Accuracy/AUC/F1)             (Root Cause Analysis)
            |                             |
            +--------------+--------------+
                           |
              Execution: Retrain / Rollback / Update
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Performance Baseline | 모델 배포 시점의 목표 성능 기준 | 골든 모델 지표 |
| Drift Detector | 실시간 성능 하락 및 통계 변화 탐지 | PSI, KS-test, DDM |
| RCA Tool | 드리프트 원인 분석 (Data vs Concept) | 입력 특징 분포 대조 |
| Retraining Pipeline | 자동화된 재학습 및 모델 교체 체계 | CI/CD/CT 연계 |

> 요약: 성능 지표와 통계 지표를 결합하여 드리프트를 탐지하고 자동화된 재학습 루프를 가동함.

---

## Ⅲ. 동작원리 및 흐름도

```text
실시간 로그 수집 -> 성능 지표 산출 -> 통계적 유의성 검정 -> 임계치 위반 시 알람 -> 원인 규명 -> 재학습 및 검증 -> 모델 교체
      |                 |                |                 |                   |               |                |
      +-----------------+----------------+-----------------+-------------------+---------------+----------------+-----> 모니터링 재개
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 운영 성능 메트릭 집계 | 정확도 하락폭 3%p 이상 감시 |
| 2 | 데이터 분포 통계 분석 | PSI > 0.2 (심각한 분포 변화) |
| 3 | 근본 원인 분석 (RCA) | 중요 Feature의 분포 변화 확인 |
| 4 | 재학습 및 챔피언-챌린저 테스트 | 신규 모델 성능 > 기존 모델 확인 |

> 요약: 성능 하락 감지 시 통계 분석을 통해 원인을 찾고, 검증된 신규 모델로 교체하여 성능을 복구함.

## Ⅳ. 특징

| 구분 | Data Drift (원인 1) | Concept Drift (원인 2) | Model Drift (결과) |
|:---|:---|:---|:---|
| 현상 | 입력 $X$의 분포 변화 | 관계 $P(Y \mid X)$의 변화 | 모델 정확도 $P(Y_{pred} \neq Y)$ 증가 |
| 탐지 지표 | PSI, KS-test, KL-div | Accuracy, F1-Score, RMSE | 전반적 성능 퇴화(Decay) |
| 탐지 시점 | 정답 없이도 사전 탐지 가능 | 정답 확보 후 사후 탐지 가능 | 최종 성능 지표 기반 판단 |
| 대응 방향 | 데이터 재샘플링, 가중치 조정 | 모델 구조 변경, 전면 재학습 | 모델 생명주기(Life-cycle) 갱신 |

> 요약: Model Drift는 데이터와 컨셉의 변화가 복합적으로 작용하여 나타나는 성능 하락의 최종 결과물임.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 주기적 재학습 (Batch) | 드리프트 기반 재학습 (Trigger) | 선택 기준 |
|:---|:---|:---|:---|
| 실행 시점 | 정해진 시간 (예: 매주) | 드리프트 감지 시 즉시 | 변화의 급격함 수준 |
| 장점 | 운영 안정성, 리소스 예측 용이 | 변화에 빠른 대응, 효율적 자원 사용 | 비즈니스 민감도 |
| 단점 | 변화 대응 지연, 불필요한 학습 | 알람 오탐 시 운영 부하 발생 | 탐지 알고리즘 신뢰도 |

> 요약: 변화가 완만한 도메인은 주기적 재학습을, 트렌드가 급변하는 도메인은 드리프트 기반 트리거 방식을 선택함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| Silent Failure | 정답 확보 지연으로 성능 하락 미감지 | 입력 데이터 드리프트 선행 감시 | 데이터 안정성 지표(PSI) |
| Feedback Loop Error | 모델 예측 결과가 다시 학습에 포함 | 데이터 샘플링 시 무작위성 확보 | 데이터 편향성(Bias) 점수 |
| 인프라 비용 폭증 | 너무 잦은 재학습 트리거 | 쿨다운(Cool-down) 기간 및 임계치 조정 | 월간 평균 재학습 횟수 |

> 요약: 감지 지연은 선행 지표로, 루프 오류는 샘플링으로, 비용은 임계치 최적화로 대응함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 모델 성능 가용성 | 성능 90% 이상 유효 시간 비율 | 연간 성능 유지 시간 / 전체 시간 |
| 재학습 자동화율 | 재학습 전 과정 자동화 80% 이상 | 수동 개입 없는 모델 교체 비중 |
| 드리프트 탐지 신뢰도 | 탐지 알람의 정확도 90% 이상 | 알람 후 실제 성능 하락 대조 |

> 요약: 도입 효과는 모델의 유효 시간, 자동화 수준, 모니터링 정확도 지표로 판정함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 조기 경보 체계: 실제 정답 확보에 시간이 걸리는 대출 심사 모델의 경우, 입력 데이터의 드리프트(PSI)를 선행 지표로 사용하여 성능 하락을 2주 앞서 예측
2. 자동화된 재학습(CT): 성능이 5%p 이상 하락하거나 데이터 드리프트가 심각할 경우, ML 파이프라인을 자동 호출하여 최신 데이터로 모델을 갱신
3. 챔피언-챌린저 배포: 재학습된 모델을 바로 교체하지 않고, 운영 환경에서 기존 모델(Champion)과 병렬로 비교(Challenger)하여 우수성이 검증된 경우에만 승인 배포

**결론 (2줄):**
- 기술사 판단: Model Drift는 "데이터는 썩는다"는 전제하에 AI 서비스를 설계해야 함을 시사하며, MLOps의 CT(Continuous Training)를 강제하는 동력임
- 향후 방향: 생성형 AI 시대에는 답변의 일관성 및 지식 최신성을 감시하는 시맨틱 드리프트(Semantic Drift) 관리 기술이 핵심 경쟁력이 될 것임
