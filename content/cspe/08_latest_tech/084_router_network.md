## 미리 알고가기

- 라우터 네트워크 ($Router$ $Network$): 전문가 혼합($MoE$) 신경망에서 유입되는 입력 토큰을 가장 적합한 물리 전문가($Expert$) 계층으로 라우팅 분배해 주는 소프트맥스 기반 초경량 게이팅 네트워크 계층임
- 전문가 용량 계수 ($Capacity$ $Factor$): 특정 전문가가 한 배치 루프 내에서 수용하여 처리할 수 있는 최대 토큰 개수(정적 기대치의 배수, 보통 1.25~1.5) 임계치임
- 게이팅 노이즈 ($Routing$ $Noise$): 라우터 평가 시 약소한 가우스 잡음을 강제 주입하여, 학습 초기의 쏠림 없이 모든 전문가 후보군이 고르게 학습 기회를 분점하도록 돕는 스케줄러 기법임
- 분배 오버헤드 ($Routing$ $Overhead$): 토큰을 다른 GPU 노드로 패킹 및 네트워킹 전송하여 연산 대기시키는 과정에서 유발되는 라우터 자체의 시간적 계산 낭비임

## Ⅰ. 개요

- **정의/개념**: Router Network는 MoE 아키텍처 내에서 입력된 개별 토큰 임베딩 값을 받아 각 전문가(Expert)별 매칭 선호 지수를 선형 사상($Linear$ $Projection$)으로 연산하고, 소프트맥스 분포에 가우스 잡음을 얹어 연산 가중치와 대상 전문가 포트를 릴리즈해 주는 핵심 게이팅 제어 계층임
- **배경/필요성**: 전문가 수가 수십 개로 늘어날 때, 최적의 전문가를 찾지 못하고 잘못 전송하면 지능 붕괴(Hallucination)가 일어나고, 특정 장비에만 연산 쿼리가 폭주해 메모리 터짐(OOM) 장애가 생기므로 정교한 분배 관제탑이 필요해져 설계됨

## Ⅱ. 특징

- 기저 모델의 전체 학습 지능을 지휘하지만, 자체 연산 스펙은 단순 $Linear$ 레이어 1장 수준으로 극도로 가볍게 설계되어 라우팅 연산 낭비를 차단함
- $Top-1$ (1개만 선별), $Top-2$ (2개 선별 후 가중 합산) 등의 라우팅 스키마를 탑재해, 계산비와 정밀도 간의 트레이드오프를 인프라에 제공함
- 특정 전문가가 한도 이상으로 요청을 수신해 처리 한계(Capacity Factor)를 돌파할 경우, 오버플로우 토큰을 격리하거나 스킵하는 지능형 컨트롤러 역할을 수반함

## Ⅲ. 종류 및 비교

| 판단 기준 | 고정 해시 라우팅 (Hash Routing) | 학습 기반 단일 라우팅 (Top-1 Router) | 학습 기반 다중 라우팅 (Top-2 Router) |
|:---|:---|:---|:---|
| **전문가 선택 기법** | 토큰 ID의 단순 해시 나누기 | 게이팅 확률 1순위 전문가 1개 선정 | 게이팅 확률 1, 2순위 전문가 2개 선정 |
| **추론 연산 단가** | 매우 낮음 (라우팅 계산 0) | 가장 낮음 | 중간 (두 전문가 출력 텐서 융합 계산) |
| **토큰 유실 리스크** | 매우 높음 (분배 고루 안 됨) | 높음 (쏠림 시 Token Drop 심각) | 극도로 완화됨 (분산 백업 경로 확보) |
| **의미 분석 무결성** | 최하 (문맥 분석 안 함) | 우수함 | 매우 우수함 (CoT 추론에 필수) |

> 요약: 해시 라우팅은 초기의 단순 기하 구조에 쓰였고, Top-1은 가성비 추론 플랫폼에, Top-2는 상영상용 엔터프라이즈 지능 확보를 위한 라우팅 표준으로 활용됨.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 로짓 채점기 | 토큰 입력 텐서에 가중치 매트릭스를 곱해 각 전문가별 logits 값을 뿜어내는 가중치 층임 |
| 소프트맥스 노이즈 | 로짓 스코어에 노이즈를 섞고 표준화하여 확률 분포를 변형시키는 필터임 |
| 게이트 필터 | Top-k를 넘어서는 하위 전문가 점수를 $0$으로 강제 치환 및 마스킹하는 필터임 |
| 용량 거름 장치 | 전문가별 최대 수용량($Capacity$ $Limit$) 도과 여부를 실시간 확인해 토큰 드롭을 격리하는 제어부임 |

```text
[ Router Network 내부 토큰 분배 메커니즘 ]
Token Hidden States ---> [ Linear Projection ] ---> [ Add Routing Noise ]
                                                            │
                      [ Output Router Scores ] <--- [ Softmax & Top-2 Mask ]
                                 │
                         (Expert Dispatch)
                                 v
                     Active Experts 1 & 7
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 공유 레이어 | --> | 전문가 로짓  | --> | 노이즈 주입 | --> | 용량 필터링 |
| 출력 인입   |     | 채점 및 연산 |     | 및 Top-k선정|     | 및 물리전송 |
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **로짓 추출** — 이전 트랜스포머 어텐션을 통과한 토큰 벡터를 라우팅 선형 레이어에 곱하여, 전문가 수 크기의 원시 점수 배열을 도출함
2. **잡음 융합** — 특정 강도로 제한된 가우스 난수(Noise)를 배열에 더하여, 모델이 학습 중에 다양한 전문가 경로를 탐색하도록 유도함
3. **Top-k 결정** — 소프트맥스를 태워 활성 확률 벡터를 만들고, 상위 $2$개 전문가 이외의 하위 점수 노드들을 전부 $0$으로 소거 마스킹함
4. **전송 및 제어** — 전문가 용량 한계선($Capacity$ $Limit$)을 초과한 초과분 토큰을 Bypass하고, 선별된 텐서를 대상 GPU 코어 레지스터에 밀어 넣음

## Ⅵ. 실무 적용 및 유의점

1. 특정 전문가에게 토큰이 기하급수적으로 쏠려 전문가 용량을 초과하면, 뒷요청 토큰들이 연산되지 못하고 그냥 스킵되어 답변 품질이 찢어지는 '토큰 드롭($Token$ $Drop$)'이 생기므로, 반드시 '전문가 용량 계수($Capacity$ $Factor$)' 설정을 표준 대비 약 $1.25 \sim 1.5$배 수준으로 유연하게 설계하고 토큰 드롭율 지표를 상시 감시해야 함
2. 라우터 자체가 내놓는 게이팅 경로 분석 오버헤드가 과도해지면 MoE 전체 추론 절감 혜택이 상쇄되므로, 반드시 라우터 로직 연산 비용 점유율($Routing$ $Overhead$ $Ratio$)을 모니터링하여 가벼운 1개 레이어 구조의 경량성을 검증해야 함

## Ⅶ. 결론

- 라우터 네트워크는 전문가 혼합 모델의 모든 자원 흐름을 진휘하는 신경망의 트래픽 경찰이자 실효 연산 가성비를 정교하게 통제하는 사령탑이며, 설계자는 쏠림에 따른 토큰 드롭 방어용 가변 용량 설계와 라우터 게이팅 자체의 경량 프로파일러를 통합 검증해야 함
