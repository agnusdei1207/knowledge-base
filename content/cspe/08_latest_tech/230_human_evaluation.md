# 📖 【암기용】 개념 완전 이해

> 목적: Human Evaluation을 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 머신러닝 모델, 특히 생성형 AI(LLM)의 응답 품질을 수학적 지표가 아닌 사람이 직접 읽고 주관적·정성적으로 평가하는 과정
- **왜 필요한가**: "오늘 기분이 어때?"라는 질문에 대한 답변의 품질은 '정확도' 같은 숫자로 측정하기 어렵고, 유머, 공감, 윤리성 등은 오직 사람만이 제대로 판단할 수 있기 때문
- **핵심 직관**: 컴퓨터 채점기(Automatic Metric)가 아닌 숙련된 채점관(Human)이 에세이를 읽고 창의성, 논리성, 가독성을 종합 평가하는 "심층 면접"

## 깊이 이해
- **배경·문제의식**: 기존의 자동 평가 지표(ROUGE, BLEU 등)는 정답 문장과 단어가 얼마나 겹치는지만 본다. 하지만 생성형 AI는 똑같은 의미라도 수만 가지 방식으로 표현할 수 있다. 단어는 많이 겹쳐도 문맥이 엉망일 수 있고, 반대로 단어는 안 겹쳐도 훌륭한 답변일 수 있다. 이 '의미의 정교함'을 포착하기 위해 결국 사람이 직접 개입해야 한다.
- **작동 원리**: 평가 가이드라인(Rubric)을 만들고, 훈련된 평가자들이 모델의 응답을 평가한다. 두 응답 중 나은 것을 고르는 **Pairwise Comparison**, 1~5점 척도로 매기는 **Likert Scale**, 응답 내 오류를 찾는 **Error Analysis** 등이 쓰인다. 최근에는 RLHF(인간 피드백 기반 강화학습)의 핵심 데이터로 활용된다.
- **비유**: 자동 번역기의 성능을 단어 일치율로 점수 매길 수도 있지만, 실제 그 나라 사람이 읽었을 때 "자연스럽고 예의 바른 표현인가"를 확인하는 것이 진짜 실력인 것과 같다.
- **구체 예시**: 챗봇 v1과 v2의 답변을 나란히 보여주고, 평가자가 "어떤 답변이 더 도움이 되고(Helpful), 유해하지 않은가(Harmless)?"를 결정한다. 이 데이터가 쌓이면 모델이 사람의 선호도를 배우게 된다.
- **흔한 오해·주의점**: "사람의 평가는 주관적이라 믿을 수 없다"는 우려가 있다. 이를 극복하기 위해 한 문항을 여러 명에게 맡겨 합의(Consensus)를 구하거나, 평가자 간 일치도(Inter-rater Reliability)를 측정하는 등 엄격한 통계적 관리가 병행된다.

## 연결 개념
- RLHF (Reinforcement Learning from Human Feedback) — 사람의 평가를 모델 학습에 직접 활용하는 기술
- Rubric (루브릭) — 일관성 있는 평가를 위한 상세 채점 기준표
- LLM-as-a-Judge — 사람 대신 고성능 LLM이 평가를 수행하는 최신 트렌드

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Human Evaluation은 모델 결과물의 품질(도움, 안전, 진실성 등)을 인간의 인지적 판단을 통해 정성적으로 검증하는 골드 스탠다드 평가 방식이다.
> 2. **가치**: 자동화 지표가 포착하지 못하는 뉘앙스, 창의성, 윤리적 적합성을 평가하며, 모델의 인간 정렬(Alignment) 수준을 결정짓는다.
> 3. **판단 포인트**: 평가자 간 일치도(Inter-rater Reliability) 확보와 평가 가이드라인(Rubric)의 구체성이 평가 신뢰도의 핵심이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 생성형 AI 평가의 한계 및 대안 이해 확인 | 정성적 평가 필요성, 자동 지표(BLEU 등)의 한계 | 단순히 "사람이 직접 확인"이라고 서술 |
| 평가 신뢰도 확보 전략 확인 | Rubric 설계, 일치도 측정(Kappa), Blind Test | 주관적 평가의 편향성 관리 방안 누락 |
| RLHF와의 연계성 이해 확인 | 선호도 데이터(Preference Data) 구축 및 학습 환류 | 평가를 단순 확인 단계로만 국한하여 기술 |

> 요약: 정량적 수치로 환산 불가능한 모델의 고차원적 지능과 안전성을 인간의 판단력을 통해 검증하고 모델에 주입하는 체계 제시가 핵심이다.

---

## Ⅰ. 개요 및 필요성

- 정의: 머신러닝 모델의 출력물에 대하여 숙련된 인간 평가자가 가독성, 논리성, 유해성 등을 주관적·정성적으로 판정하는 평가 방법론
- 배경: 생성형 AI의 확산으로 기존 텍스트 일치도 지표(BLEU/ROUGE)의 무용성 증대, AI 윤리 및 안전성(Alignment)에 대한 사회적 요구 증가
- 필요성: 모델의 실제 사용자 체감 품질 측정, 고도화된 추론 능력 검증, RLHF 학습을 위한 고품질 레이블링 데이터 확보

## Ⅱ. 구조 및 구성요소

```text
Model Output -> Annotation Platform (UI) -> Human Annotators (Experts/Crowd)
                         |                             |
                +--------+----------+         +--------+----------+
                |                   |         |                   |
          Evaluation Rubric   Task Type    Quality Control    Agreement Stats
          (Helpful/Safe)      (Ranking)    (Gold Set)         (Cohen's Kappa)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Evaluation Rubric | 구체적인 채점 기준 및 가이드라인 | 주관성 배제의 핵심 |
| Annotation Platform | 평가자가 결과를 입력하고 확인하는 시스템 | 비교(Pairwise) UI 제공 |
| Quality Control | 평가자의 불성실이나 오답을 걸러내는 장치 | Gold Standard 질문 삽입 |
| Inter-rater Reliability | 평가자들 사이의 의견 일치 정도 측정 | Cohen's Kappa, Fleiss' Kappa |

> 요약: 상세한 가이드라인(Rubric)과 평가 품질 관리(QC)를 통해 주관적 평가의 객관성을 확보함.

---

## Ⅲ. 동작원리 및 흐름도

```text
평가 샘플 추출 -> 루브릭(Rubric) 설계 -> 평가자 교육 -> 독립 평가 수행 -> 결과 취합 및 합의 -> 통계적 신뢰도 검정 -> 모델 피드백
      |                 |                |                 |                   |                   |                      |
      +-----------------+----------------+-----------------+-------------------+-------------------+----------------------+-----> 모델 정렬(RLHF)
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 평가 대상 샘플링 전략 수립 | 난이도별/유형별 대표성 확보 |
| 2 | 다수 평가자 배정 (Cross-check) | 문항당 3~5명 중복 배정 |
| 3 | 일치도(Agreement) 분석 | Kappa 계수 0.6 이상(상당한 일치) |
| 4 | 심층 오류 분석 (Error Analysis) | 정성적 개선 포인트 도출 |

> 요약: 다수의 평가자가 독립적으로 평가한 결과를 통계적으로 분석하여 모델의 실질적 지능 수준을 판정함.

---

## Ⅳ. 특징 (평가 기법 비교)

| 기법 | 방식 | 장점 | 단점 |
|:---|:---|:---|:---|
| Pairwise Ranking | 두 모델 응답 중 더 나은 것 선택 | 판단이 쉽고 일치도가 높음 | 상대적 우위만 알 수 있음 |
| Likert Scale | 1~5점 등 절대 점수 부여 | 개별 응답의 절대 품질 파악 | 평가자마다 점수 기준이 주관적 |
| Error Taxonomy | 오류 유형(오정보, 편향 등) 분류 | 구체적 취약점 파악 가능 | 평가 난이도가 높고 시간 소요 |
| LLM-as-a-Judge | GPT-4 등 상위 모델이 평가 수행 | 속도가 빠르고 비용이 저렴함 | 상위 모델의 편향이 전이됨 |

> 요약: 평가 목적에 따라 비교 방식(Ranking) 또는 절대 방식(Scale)을 선택하며, 최근에는 비용 절감을 위해 LLM-as-a-Judge와 병행함.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 자동 평가 (Automatic) | 사람 평가 (Human) | 선택 기준 |
|:---|:---|:---|:---|
| 평가 지표 | BLEU, ROUGE, Perplexity | Helpfulness, Honesty, Harmless | 지표의 정성적 수준 |
| 비용/속도 | 매우 저렴 / 실시간 | 매우 비쌈 / 수일 소요 | 가용 예산 및 시급성 |
| 정확성 | 낮음 (의미 파악 불가) | 높음 (최종 표준) | 결과의 신뢰도 요구사항 |
| 주 용도 | 개발 중 초기 벤치마킹 | 최종 릴리스 승인 및 RLHF | 생명주기 단계 |

> 요약: 개발 초기에는 자동 평가로 빠르게 반복하고, 최종 단계와 정렬 학습에는 사람 평가를 필수적으로 적용함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| Subjectivity (주관성) | 모호한 가이드라인 | 루브릭 세분화 및 예시(Anchor) 제공 | 평가자 간 일치도 (IRR) |
| Annotator Fatigue | 과도한 업무량으로 인한 품질 하락 | 적정 작업량 배분 및 휴식 보장 | 작업 시간 대비 품질 상관관계 |
| Bias (편향) | 특정 평가자 군의 선입견 투영 | 다양한 인구통계학적 평가자 구성 | 그룹별 평가 편차 |

> 요약: 주관성은 루브릭으로, 피로는 관리 체계로, 편향은 평가자 다양성으로 대응함.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 평가자 일치도 | Cohen's Kappa 0.7 이상 | 평가자 간 응답 대조 분석 |
| 평가 신뢰도 | Gold Set(정답지) 통과율 90% | 사전에 정답을 아는 문항 배치 |
| 평가 생산성 | 시간당 평균 평가 건수 목표 달성 | 시스템 로그 기반 효율 측정 |

> 요약: 도입 효과는 평가의 일관성(일치도), 신뢰성(정답 통과율), 운영 효율성 지표로 판정함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. RLHF 데이터 구축: 챗봇의 유해 답변을 걸러내기 위해 사람 평가자가 수만 건의 응답을 '안전/위험'으로 라벨링하여 리워드 모델(Reward Model) 학습
2. 정성적 품질 벤치마크: 신규 모델 출시 전, 전문 언어학자 그룹을 통해 문법적 정확도 및 맥락 유지 능력을 5점 척도로 평가하여 배포 승인 여부 결정
3. 루브릭 기반 오류 분석: 할루시네이션(환각)이 잦은 영역을 특정하기 위해, 사람이 직접 답변의 사실 관계를 확인하고 오류 유형을 10종으로 분류하여 집중 개선

**결론 (2줄):**
- 기술사 판단: Human Evaluation은 AI가 인간의 가치체계에 순응하게 만드는 "윤리적·지능적 나침반"이며, 자동화될 수 없는 고유의 영역임
- 향후 방향: 인간의 평가를 복제한 AI 비평가(AI Critic) 모델과 인간이 협업하여 평가 비용을 90% 절감하는 "Hybrid Evaluation"으로 진화할 것임
