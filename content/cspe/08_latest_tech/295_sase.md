# 📖 【암기용】 개념 완전 이해

> 목적: SASE를 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 네트워크 기능(SD-WAN)과 보안 기능(CASB, FWaaS, ZTNA 등)을 하나로 통합하여 클라우드에서 제공하는 보안 프레임워크
- **왜 필요한가**: 예전엔 지사나 재택근무자가 회사 본사를 거쳐서 인터넷을 나갔는데, 클라우드 시대가 되면서 속도가 너무 느려졌다. 사용자와 가까운 '엣지(Edge)'에서 네트워크와 보안을 한꺼번에 처리해 효율을 높이기 위함이다.
- **핵심 직관**: "네트워크 고속도로와 보안 검문소를 하나로 합쳐서 전 세계 클라우드 곳곳에 설치해둔 시스템"

## 깊이 이해
- **배경·문제의식**: 하이브리드 근무와 클라우드(SaaS) 사용이 늘면서 모든 트래픽을 본사 데이터센터로 집중시키는 '허브 앤 스포크(Hub-and-Spoke)' 방식은 병목 현상을 유발한다. 또한 보안 장비를 지점마다 사기는 너무 비싸다.
- **작동 원리**: **Network as a Service (SD-WAN) + Security as a Service (SSE)**.
    - 사용자가 어디에 있든 가장 가까운 클라우드 거점(PoP)에 접속한다.
    - 그 거점에서 실시간으로 신원을 확인하고(ZTNA), 클라우드 앱 보안(CASB)과 방화벽(FWaaS)을 처리한 뒤 바로 목적지로 보낸다.
- **비유**: 모든 지방 승객이 서울역(본사)에 와서 검문받고 다시 지방으로 가는 게 아니라, 각 지역 터미널(엣지)에서 검문과 티켓 확인을 동시에 끝내고 바로 목적지로 가는 시스템이다.
- **구체 예시**: 스타벅스에서 일하는 직원이 회사 메일을 열 때, 본사 서버를 거치지 않고 가장 가까운 클라우드 보안 지점(SASE)에서 검증받고 바로 이메일 서버에 접속하는 것.
- **흔한 오해·주의점**: "특정 장비"가 아니다. 가트너가 제시한 아키텍처 모델이다. 네트워크팀과 보안팀이 따로 놀면 구축하기 매우 어렵다.

## 연결 개념
- SD-WAN (Software Defined Wide Area Network) — 소프트웨어로 지점 간 네트워크를 최적화하는 기술
- SSE (Security Service Edge) — SASE에서 네트워크 기능을 제외한 보안 기능 위주의 서비스
- CASB (Cloud Access Security Broker) — 기업과 클라우드 서비스 사이에서 보안 정책을 중계하는 기술

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 네트워크 성능(SD-WAN)과 클라우드 보안(SSE)의 통합을 통해 분산된 업무 환경의 가용성과 보안성을 동시에 확보하는 방안을 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: SASE(Secure Access Service Edge)는 광역 네트워크(SD-WAN) 기술과 포괄적인 클라우드 보안 기능을 단일 클라우드 서비스로 통합한 아키텍처이다.
> 2. **가치**: 트래픽의 본사 집중(Hairpinning)을 제거하여 지연시간을 단축하고, 전 세계 어디서나 일관된 보안 정책(ZTNA 등)을 적용한다.
> 3. **판단 포인트**: 네트워크 최적화와 보안 가시성을 단일 관리 화면(Single Pane of Glass)에서 제어하는 '통합 운영 체계' 확보가 핵심이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| SASE의 정의 및 구성 요소 파악 | SD-WAN + SSE (CASB, FWaaS, SWG, ZTNA) | 네트워크 또는 보안 중 한쪽만 기술 시 감점 |
| 클라우드 기반 보안 전환 배경 이해 | 분산된 근무 환경, SaaS 확산, 지연시간 단축 | 단순히 '통합 보안 솔루션'으로 오해 금지 |
| 구현 메커니즘 및 엣지 컴퓨팅 연계 | PoP(Point of Presence) 기반의 분산 처리 | 하드웨어 장비 중심의 서술 지양 (Service 중심) |

> 요약: 디지털 전환 환경에서 네트워크의 연결성과 보안의 복잡성을 한 번에 해결하는 플랫폼 전략을 평가한다.

## Ⅰ. 개요 및 필요성

- 정의: 클라우드 기반 인프라를 통해 SD-WAN의 유연한 네트워크와 포괄적인 보안 기능을 통합 제공하는 프레임워크
- 배경: 모든 트래픽이 본사 DC를 거치는 백홀(Backhaul) 현상으로 인한 성능 저하 및 관리 지점 파편화
- 필요성: 모바일/재택근무자 증가에 따른 경계 보안 한계 극복, 운영 복잡성 제거, 클라우드 앱(SaaS) 성능 최적화

---

## Ⅱ. 구조 및 구성요소

```text
[ 사용자/지점/클라우드 ] -> [ SASE Cloud (PoP) ] -> [ 목적지 (SaaS, IaaS, Web) ]
                                |
        +-----------------------+-----------------------+
        | Network (SD-WAN)      | Security (SSE)        |
        | - 경로 최적화 (SLA)   | - ZTNA (제로트러스트) |
        | - 대역폭 관리         | - CASB (SaaS 보안)    |
        | - 오케스트레이션      | - FWaaS (클라우드 FW) |
        |                       | - SWG (웹 게이트웨이) |
```

| 구성요소 | 역할 | 핵심 기능 |
|:---|:---|:---|
| SD-WAN | 최적 경로 기반의 유연한 네트워크 제공 | 동적 경로 선택, QoS 관리, WAN 가속 |
| ZTNA | 신원 기반의 세분화된 접근 제어 | 제로 트러스트 원칙 적용, 장치 무결성 확인 |
| CASB | 클라우드 서비스(SaaS) 가시성 및 보호 | Shadow IT 탐지, 데이터 유출 방지(DLP) |
| FWaaS | 클라우드에서 제공되는 지능형 방화벽 | IPS, L7 필터링, 글로벌 보안 정책 적용 |
| SWG | 안전한 인터넷 접속 보장 | 악성 URL 필터링, 샌드박싱, 암호화 트래픽 분석 |

> 요약: 네트워크 연결성(SD-WAN)과 4대 핵심 보안 기능(ZTNA, CASB, FWaaS, SWG)이 결합된 형태이다.

## Ⅲ. 동작원리 및 흐름도

```text
사용자 접속 -> 가장 가까운 PoP 연결 -> 신원/기기 인증(ZTNA) -> 위협 검사(SWG/FWaaS) -> 데이터 제어(CASB) -> 최종 목적지 도달
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 엣지 접속 | 전 세계 분산된 PoP 중 최적 지연시간(Latency) 지점 선택 |
| 2 | 세션 기반 보안 적용 | 사용자 아이덴티티와 맥락을 분석하여 정책 즉시 적용 |
| 3 | 통합 보안 검사 | 단일 패스(Single Pass) 병렬 처리로 성능 병목 최소화 |
| 4 | 비즈니스 가시성 확보 | 모든 접속 로그 통합 수집 및 AI 기반 위협 분석 |

> 요약: 전 세계 곳곳의 엣지 거점(PoP)에서 보안 검사와 네트워크 최적화를 한꺼번에 수행하여 효율을 극대화한다.

## Ⅳ. 특징

| 구분 | 레거시 네트워크/보안 | SASE 모델 |
|:---|:---|:---|
| 아키텍처 | 데이터센터 중심 (Hub-and-Spoke) | 클라우드 엣지 중심 (Identity-centric) |
| 보안 적용 | 하드웨어 장비 (박스 단위) | 클라우드 네이티브 서비스 (Software) |
| 성능 영향 | 보안 검사 시 병목 및 지연 발생 | 분산 엣지 처리로 지연시간 최소화 |
| 관리 방식 | 네트워크/보안 분리 운영 | 통합 단일 대시보드 관리 |

> 요약: 물리적 위치 중심의 보안에서 사용자의 신원(Identity) 중심 보안으로 패러다임이 전환된다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | SSE (Security Service Edge) | SASE (Secure Access Service Edge) | 선택 기준 |
|:---|:---|:---|:---|
| 구성 | 보안 기능 중심 (Net 제외) | 보안 + 네트워크(SD-WAN) 통합 | 기존 네트워크 장비의 교체 주기 |
| 복잡성 | 상대적 낮음 (보안 전환) | 높음 (전체 네트워크 혁신) | IT 조직의 통합 운영 역량 |
| 효과 | 보안 가시성 및 통제권 확보 | 네트워크 성능 최적화까지 달성 | 글로벌 지점 분포 및 지연시간 이슈 |

> 요약: 보안 강화가 시급하면 SSE를, 전반적인 네트워크 혁신까지 고려하면 SASE를 도입한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 벤더 종속성 | 네트워크/보안 일체형 도입 시 전환 어려움 | 개방형 API 지원 여부 확인, 단계적 통합 | 전환 비용(Switching Cost) 분석 |
| 가용성 이슈 | 클라우드 서비스(SASE) 장애 시 전체 마비 | 멀티 벤더 활용 또는 오프라인 백업 경로 | 서비스 가용성(SLA), PoP 장애 복구 시간 |
| 데이터 프라이버시 | 모든 트래픽이 클라우드 보안 거점 통과 | 데이터 거주성 준수 PoP 선택, 암호화 | 데이터 노출 여부, 컴플라이언스 준수율 |

> 요약: 통합에 따른 종속성과 가용성이 주요 리스크이며, 하이브리드 구성과 SLA 관리로 대응한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 지연시간 개선 | 본사 경유 대비 Latency 30% 이상 감소 | 지점별 앱 응답 시간(TTFB) 측정 |
| 보안 일관성 | 전 지점 동일 정책 적용률 100% | 보안 설정 편차(Configuration Drift) 감사 |
| 비용 효율 | 하드웨어 유지비 대비 TCO 20% 절감 | 장비 구매비(CapEx) vs 구독료(OpEx) 분석 |

> 요약: 도입 성과는 지연시간 감소, 보안 정책의 일관성, 그리고 총소유비용(TCO) 변화로 평가한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. **글로벌 지사 연결**: 전 세계에 흩어진 지사와 공장을 전용선 대신 SASE(SD-WAN)로 연결하여 비용을 50% 절감하고 보안을 일원화
2. **하이브리드 업무**: 재택근무자가 VPN 없이 SASE 클라이언트만으로 사내 앱과 SaaS(M365, Slack 등)에 안전하고 빠르게 접속
3. **M&A 후 통합**: 인수합병된 회사의 서로 다른 인프라를 클라우드 기반 SASE로 통합하여 단기간에 보안 거버넌스 확보

**결론 (2줄):**
- 기술사 판단: SASE는 네트워크와 보안의 경계가 무너지는 기술적 특이점이며, 초기에는 보안 위주의 SSE로 시작하여 점진적으로 네트워크 통합을 이루는 것이 현실적이다.
- 향후 방향: 엣지 컴퓨팅과 결합하여 초저지연 보안을 제공하는 '엣지 SASE'와 AI가 보안 정책을 자동 조정하는 '자율 SASE'로 발전할 전망이다.
