# 📖 【암기용】 개념 완전 이해

> 목적: 시스템 프롬프트를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: LLM에 역할·제약·출력 규칙을 사전 지정하는 최상위 지시 계층
- **왜 필요한가**: 사용자 프롬프트만으로는 역할 일관성·안전 가드레일·출력 포맷 통제가 어렵고, 매 요청마다 반복 지시가 필요해짐.
- **핵심 직관**: LLM의 "업무 규정집"으로, 사용자가 무엇을 물어도 이 규정 안에서 답하게 만듦.

## 깊이 이해
- **배경·문제의식**: ChatGPT API에서 system/user/assistant 3역할 분리가 도입되면서, 개발자가 모델 행동을 사전 제어할 수 있게 됨. 이전에는 user 메시지 첫줄에 역할을 적어야 했고, 대화가 길어지면 무시되기 쉬웠음.
- **작동 원리**: system 메시지는 컨텍스트 윈도우 최상단에 위치하여, 이후 모든 user/assistant 턴에 영향을 줌. 모델은 system 지시에 가장 높은 우선순위를 부여함.
- **비유**: 콜센터 상담원의 "상담 매뉴얼"에 해당. 고객(user)이 무엇을 요구해도 매뉴얼을 벗어나지 않음.
- **구체 예시**: `"당신은 한국어만 사용하는 의료 상담 AI입니다. 진단은 하지 않고, 병원 방문을 권유합니다."` -> 영어 질문에도 한국어로 응답, 자가진단 요청 거부.
- **흔한 오해·주의점**: system prompt는 절대 불변이 아님. 프롬프트 인젝션으로 우회 가능하므로 출력 측 검증(Guard Model)이 필수임.

## 연결 개념
- Prompt Template — system prompt를 포함하는 상위 구조
- Prompt Injection — system prompt 우회 공격
- RLHF — system prompt 준수를 강화하는 학습 기법


# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: System Prompt는 LLM 행동을 사전 제어하는 최상위 지시 계층임.
> 2. **가치**: 역할 일관성·안전 가드레일·출력 포맷을 대화 전반에 걸쳐 유지함.
> 3. **판단 포인트**: 인젝션 우회 가능성을 전제하고, 출력 측 Guard Model·필터를 병행 설계해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| LLM 행동 제어 계층 구조 이해 확인 | system/user/assistant 역할 분리, 컨텍스트 최상단 배치, 우선순위 | 프롬프트 종류 나열만 하고 우선순위·통제 관점 누락 |
| 보안 통제 판단 확인 | 프롬프트 인젝션 우회 전제, 입력 필터+출력 Guard 이중 방어 | system prompt를 절대 방어선으로 단정 |
| 운영 관점 확인 | 버전 관리, 준수율 평가(LLM Judge), 유출 대응(LLM07) | 작성 예시만 쓰고 운영·평가 체계 누락 |

> 요약: 이 문제는 프롬프트 작성법이 아니라 행동 통제 계층 설계와 인젝션 방어 체계를 묻는다.

## Ⅰ. 개요 및 필요성

- 개요: LLM 최상위 행동 지시 계층
- 배경: API 기반 LLM 서비스가 확산되면서 역할·톤·안전 규칙·출력 포맷을 대화 전체에 일관 적용해야 함.
- 필요성: system role, policy instruction, output contract로 사용자 입력보다 우선하는 행동 기준을 정의해야 함.


## Ⅱ. 구조 및 구성요소

```text
System Prompt (역할 / 제약 / 출력 포맷 / 우선순위)
  -> Context 최상단 배치 -> User Prompt 결합 -> Assistant Response
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 역할 정의 | 모델 페르소나·전문성 지정 | "당신은 보안 전문가입니다" |
| 행동 제약 | 금지 행동·안전 규칙 명시 | 개인정보 수집 금지, 의료 진단 금지 |
| 출력 포맷 | JSON·Markdown·길이 제한 | JSON Schema 강제 가능 |
| 우선순위 제어 | user 지시와 충돌 시 system 우선 | 인젝션 방어의 핵심 |

> 요약: system prompt는 역할·제약·포맷·우선순위 4요소로 모델 행동 경계를 설정함.


## Ⅲ. 동작원리 및 흐름도

```text
System Prompt 설정 -> User 입력 수신 -> 컨텍스트 조립
    -> LLM 추론(system 우선) -> 출력 -> Guard 검증
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | System Prompt 로드·컨텍스트 최상단 배치 | 토큰 예산 내 배치, 버전 확인 |
| 2 | User 입력 수신·인젝션 패턴 필터 | 정규식·분류 모델 탐지율 95%+ |
| 3 | LLM 추론 (system 지시 우선 적용) | 역할 일관성, 제약 위반 여부 |
| 4 | 출력 Guard 검증·로그 기록 | 금지어 포함률 0%, 포맷 적합률 |

> 요약: system prompt는 컨텍스트 최상단에서 추론 전체를 지배하되, 출력 측 Guard로 이중 방어함.


## Ⅳ. 특징

| 구분 | User Prompt만 사용 | System + User 분리 | 판단 포인트 |
|:---|:---|:---|:---|
| 역할 일관성 | 대화 길어지면 역할 이탈 | 전 대화 일관 유지 | 멀티턴 10회 이상 시 필수 |
| 안전 통제 | 사용자 조작에 취약 | 제약 우선순위 분리 | 인젝션 방어율 95%+ 필요 |
| 유지보수 | 매 요청 반복 삽입 | 1회 설정, 전체 적용 | 운영 비용 절감 |

> 요약: system prompt 분리는 역할 일관성·안전·유지보수 세 축에서 필수적임.


## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | Fine-tuning(RLHF) | System Prompt | 선택 기준 |
|:---|:---|:---|:---|
| 적용 속도·비용 | 재학습 필요, 고비용 | 즉시 반영, 무비용 | 정책 변경 주기가 짧으면 system prompt |
| 통제 강도 | 가중치에 내재, 우회 어려움 | 인젝션으로 우회 가능 | 규제·안전 필수 규칙은 학습+Guard 병행 |
| 유연성 | 모델별 고정 | 테넌트·기능별 분기 가능 | 멀티테넌트 SaaS는 system prompt 분기 |

> 요약: 자주 바뀌는 행동 규칙은 system prompt, 우회 불가해야 하는 안전 규칙은 학습·Guard 계층에 배치함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 프롬프트 인젝션 | user 입력이 system 지시 재정의 시도 | 입력 필터 + 출력 Guard Model 이중 방어 | 인젝션 차단율 95% 이상 |
| 시스템 프롬프트 유출 | 유도 질의로 지시 내용 노출(OWASP LLM07) | 비밀정보 미포함 원칙, 유출 탐지 필터 | 유출 사고 0건 |
| 역할 이탈 (drift) | 장기 멀티턴에서 지시 희석 | 주기적 재주입, 준수율 자동 평가 | LLM Judge 준수율 99% 이상 |

> 요약: system prompt는 우회를 전제로 이중 방어·유출 차단·준수율 감시를 함께 설계해야 함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 역할·금지행동·출력포맷을 system prompt에 명시하고, 버전 관리(Git)·배포 파이프라인 적용
2. 입력 측 인젝션 필터(정규식+분류 모델) + 출력 측 Guard Model(Llama Guard)로 이중 방어
3. system prompt 준수율을 LLM Judge로 자동 평가, 위반률 1% 이하 유지

**결론 (2줄):**
- 기술사 판단: 멀티턴 서비스면 system prompt 분리 필수, 단일 질의면 user prompt에 통합 가능
- 향후 방향: 동적 system prompt(대화 맥락에 따라 제약 추가)와 Guard Model 연동이 표준화 전망
