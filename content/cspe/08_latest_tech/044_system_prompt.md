## 미리 알고가기

- System Prompt는 개발자나 운영자가 모델에 주입하는 최상위 지시 공간임
- User Prompt는 사용자가 직접 입력하는 요청으로 시스템 정책 범위 안에서만 해석돼야 함
- Tool Rule은 검색, 계산, 실행 도구를 언제 어떻게 사용할지 규정하는 운영 지시임

## Ⅰ. 개요

- **정의/개념**: System Prompt는 모델의 역할과 정책과 도구 사용 규칙과 출력 계약을 최상위 우선순위로 정의해 개별 사용자 입력보다 먼저 적용되도록 설계한 제어 지시 계층임
- **배경/필요성**: 범용 LLM은 사용자 입력에 따라 쉽게 답변 방향이 흔들리므로, 서비스 정체성과 보안 규칙과 업무 경계를 일관되게 유지하려면 대화 전반을 묶는 상위 지시가 필요함

## Ⅱ. 특징

- 사용자 입력과 별도로 서비스의 성격과 금지 규칙을 지속적으로 고정할 수 있음
- Tool Use, RAG, Agent 정책을 한곳에서 통제해 운영 일관성을 높임
- 얇고 명확할수록 효과적이며 과도하게 길어지면 비용과 충돌 가능성이 커짐
- prompt injection과 prompt leakage 위협을 받기 쉬워 별도 보안 통제가 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | System Prompt | User Prompt | Tool Schema, Policy Engine |
|:---|:---|:---|:---|
| 목적 | 역할, 정책, 제약 고정 | 개별 요청 전달 | 실행 계약과 외부 정책 강제 |
| 우선순위 | 높음 | 낮음 | 시스템과 결합 시 매우 높음 |
| 변경 빈도 | 낮음 | 높음 | 낮음 |
| 적합 활용 | 서비스 정체성, 보안 규칙 | 질의응답 내용 | 구조적 제어, 감사 대응 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Core Persona | 모델의 역할과 응답 톤과 책임 범위를 고정해 서비스 일관성을 형성함 |
| Policy Rule | 금지 행위, 민감 정보 처리, 안전 규칙을 정의해 정책 위반을 줄임 |
| Tool Usage Rule | 검색, 계산, 코드 실행 등 외부 도구를 언제 호출할지와 금지 조건을 명시함 |
| Output Contract | JSON 형식, 근거 포함, 응답 길이 같은 결과 계약을 지정해 후속 시스템 연동을 안정화함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +---------------+     +----------------+     +-------------+
| 정책 초기화  | --> | 사용자 요청 수신 | --> | 규칙 충돌 해석  | --> | 답변/도구 실행 |
+-------------+     +---------------+     +----------------+     +-------------+
```

1. **정책 초기화**: 시스템 프롬프트로 역할과 보안 규칙과 도구 정책을 먼저 주입함
2. **사용자 요청 수신**: 개별 질의를 시스템 규칙이 허용하는 범위에서 해석함
3. **규칙 충돌 해석**: 사용자 요청이 시스템 정책과 충돌하는지 판단하고 우선순위에 따라 정리함
4. **답변 또는 도구 실행**: 허용된 범위 안에서 응답을 생성하거나 필요한 도구를 호출함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 시스템 프롬프트가 장황해지면 매 요청마다 불필요한 토큰 비용과 TTFT 증가를 초래하고 핵심 정책도 오히려 묻힐 수 있음
   - 해결방안: thin system prompt와 외부 policy engine 분리를 적용하고 system prompt token 수와 task success rate로 효율을 검증함
2. 문제: 사용자 입력이나 외부 문서가 시스템 규칙을 무시하도록 유도하면 prompt injection과 leakage가 발생할 수 있음
   - 해결방안: 역할 분리와 비밀 최소화와 출력 필터를 병행하고 prompt leakage success rate와 policy violation 건수로 보안성을 검증함
3. 문제: 시스템 정책과 도구 규칙과 출력 제약이 한 문서에 뒤섞이면 충돌 지시가 생겨 모델 응답 일관성이 깨질 수 있음
   - 해결방안: 규칙을 역할별로 분해하고 계약 테스트를 자동화하며 schema pass rate와 refusal consistency로 충돌 여부를 검증함

## Ⅶ. 적용 사례

- 사내 보안 챗봇: 민감 정보 질의는 거절하고 허용된 업무만 답변함, 확인 지표는 policy violation rate와 answer relevance임
- 코딩 에이전트: 계산과 검색과 실행 규칙을 시스템 지시로 고정함, 확인 지표는 tool selection accuracy와 recovery rate임
- 고객지원 봇: 브랜드 톤과 금지 답변 규칙을 유지함, 확인 지표는 CSAT와 compliance rate임

## Ⅷ. 결론

시스템 프롬프트의 본질은 모델을 길게 설명하는 데 있지 않고 서비스 정책과 도구 사용 경계를 최소한의 상위 규칙으로 고정해 일관성과 보안을 동시에 확보하는 데 있음.
