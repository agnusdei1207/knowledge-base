# 📖 【암기용】 개념 완전 이해

> 목적: 데이터 패브릭을 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 흩어져 있는 다양한 데이터를 마치 하나의 천(Fabric)처럼 촘촘하게 엮어서, 사용자가 데이터의 위치를 몰라도 쉽고 빠르게 활용하게 해주는 지능형 데이터 아키텍처
- **왜 필요한가**: 데이터가 클라우드, 온프레미스, 각종 앱에 너무 분산되어 있어서 이를 하나하나 통합(ETL)하기엔 비용과 시간이 너무 많이 들기 때문이다.
- **핵심 직관**: "데이터를 물리적으로 한곳에 모으지 않고, 메타데이터와 AI를 이용해 가상으로 연결하여 마치 한곳에 있는 것처럼 보여주는 것."

## 깊이 이해
- **배경·문제의식**: 기업 데이터의 80%는 사일로(Silo)화되어 있음. 기존 방식은 데이터를 DW/DL로 복사해서 통합했지만, 데이터가 너무 많아지고 실시간성이 중요해지면서 복사 방식이 한계에 부딪힘.
- **작동 원리**: '액티브 메타데이터(Active Metadata)'와 '지식 그래프(Knowledge Graph)'를 활용함. AI가 데이터의 성격, 위치, 사용 패턴을 스스로 학습하여, 사용자가 원하는 데이터를 요청하면 자동으로 가장 최적의 경로로 데이터를 연결해줌.
- **비유**: 전 세계 모든 숙소 정보를 한데 모아 보여주는 '부킹닷컴'이나 '에어비앤비'와 같음. 부킹닷컴이 모든 호텔을 직접 소유(데이터 복사)하지 않지만, 플랫폼을 통해 마치 자기 것처럼 검색하고 예약(데이터 연결)할 수 있게 해주는 것.
- **구체 예시**: 분석가가 "작년 매출 현황"을 검색하면, 데이터 패브릭은 S3에 있는 로그와 오라클 DB에 있는 결제 정보를 실시간으로 엮어(가상화) 하나의 표로 보여줌.
- **흔한 오해·주의점**: 단순한 '데이터 가상화' 툴이 아님. AI를 통해 데이터를 분석하고 추천하며, 거버넌스까지 자동화하는 더 넓은 범위의 '아키텍처'임.

## 연결 개념
- Active Metadata - 데이터 패브릭을 움직이는 핵심 동력
- Data Virtualization - 데이터를 복사하지 않고 쿼리하는 핵심 기술
- Data Mesh - 데이터를 '조직/사람' 관점에서 분산 관리하는 경쟁/보완 개념

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 데이터 패브릭의 5대 구성 요소(Active Metadata, Knowledge Graph 등)를 명시하고, AI 기반 자동화가 가져오는 데이터 운영 효율성을 강조한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 데이터 패브릭은 분산된 이기종 데이터 환경에서 AI와 액티브 메타데이터를 활용해 데이터 통합과 관리를 자동화하는 지능형 오케스트레이션 아키텍처이다.
> 2. **가치**: 데이터 통합 비용(ETL)을 최대 70% 절감하며, 데이터 가상화를 통해 실시간 가시성을 확보하고 데이터 접근의 민주화를 실현한다.
> 3. **판단 포인트**: 정적 메타데이터 관리에서 AI 기반의 동적·추론적 메타데이터 활용(Active Metadata)으로의 전환이 기술적 성패를 결정한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 데이터 아키텍처 트렌드 파악 확인 | 데이터 패브릭의 등장 배경 및 정의 | 단순 "데이터 통합 솔루션"으로 서술 지양 |
| 핵심 기술 구성 요소 서술 역량 | Active Metadata, Knowledge Graph, Data Virtualization | 구성 요소 중 일부 누락 및 기술적 원리 미흡 |
| 데이터 메시(Mesh)와의 차이점 이해 | 기술 중심(Fabric) vs 조직 중심(Mesh) 비교 | 두 개념을 혼용하거나 차별점 부각 실패 |

> 요약: 데이터 패브릭은 분산 데이터 환경의 복잡성을 AI 기술로 은폐하고 추상화하는 통합 데이터 거버넌스 체계이다.

## Ⅰ. 개요 및 필요성

- 정의: AI와 자동화를 통해 이기종 인프라(멀티 클라우드/온프레미스)에 흩어진 데이터를 유기적으로 연결하고 관리하는 지능형 데이터 아키텍처
- 배경: 데이터 파편화 심화(Silo), 수동 ETL의 한계 및 고비용, 실시간 데이터 분석 요구 증대
- 필요성: 데이터 관리 운영 효율 극대화, 단일 데이터 진실 공급원(SSOT) 확보, 셀프 서비스 분석 환경 제공

---

## Ⅱ. 구조 및 구성요소 (가트너 5대 구성 요소)

```text
[ Data Consumers: Analyst, Data Scientist, App ]
            ^ (Unified Data Access Layer)
-------------------------------------------------------
[ 1. Knowledge Graph ] <-> [ 2. Active Metadata ]
          |                          |
[ 3. AI/ML Engine ]    <-> [ 4. Data Integration (Virtualization) ]
-------------------------------------------------------
[ 5. Data Sources: Cloud, On-Premise, SaaS, IoT ]
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Active Metadata | 데이터 사용 패턴, 품질, 보안 정보를 지속 분석 및 권고 | 정적 메타데이터의 한계 극복 |
| Knowledge Graph | 데이터 간의 관계를 그래프 구조로 시각화 및 추론 | 의미론적(Semantic) 연결 |
| AI/ML Engine | 데이터 통합 경로 최적화 및 거버넌스 자동화 | 자율 운영 데이터 플랫폼의 핵심 |
| Data Virtualization | 데이터를 이동시키지 않고 논리적으로 통합 조회 | 가상 뷰(Virtual View) 제공 |

> 요약: AI가 메타데이터를 학습하여 데이터의 관계를 파악하고, 필요한 시점에 실시간으로 연결하는 구조이다.

---

## Ⅲ. 동작원리 및 흐름도 (AI 기반 자동화 흐름)

```text
User Request -> [ 1. Semantic Search ] -> [ 2. Path Optimization ]
                       |                          |
               (Knowledge Graph 기반)        (AI 기반 최적 경로)
                       |                          |
         [ 4. Unified Result ] <- [ 3. Dynamic Integration ]
                       |                          |
                (실시간 데이터 결합)           (가상화/API 연결)
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 데이터 수집/관측 | 흩어진 소스에서 메타데이터와 로그를 지속적 수집 | 관측성(Observability) |
| 2 | 관계 추론 | 지식 그래프를 통해 연관 데이터 및 비즈니스 맥락 파악 | 의미적 정합성 |
| 3 | 추천 및 자동화 | 최적의 데이터 파이프라인 제안 또는 권한 자동 할당 | 액티브 추천 시스템 |
| 4 | 서비스 제공 | 가상화 레이어를 통해 물리적 이동 없는 데이터 제공 | 실시간성 및 데이터 이동 최소화 |

> 요약: 데이터의 맥락을 AI가 파악하여 복잡한 통합 과정을 자동화하고 사용자에게 즉시 전달한다.

## Ⅳ. 특징

| 구분 | 주요 특징 | 상세 내용 |
|:---|:---|:---|
| 지능형 자동화 | Active Metadata 활용 | 사람이 일일이 지정하지 않아도 AI가 데이터 관리 최적화 |
| 위치 투명성 | Data Virtualization | 사용자는 데이터가 S3에 있는지 오라클에 있는지 알 필요 없음 |
| 개방형 연결 | Multi-Platform 지원 | 온프레미스, 클라우드, SaaS 데이터를 차별 없이 연결 |
| 거버넌스 통합 | Federated Governance | 분산된 데이터에 대해 단일 보안/품질 정책 일괄 적용 |

> 요약: '연결'과 '자동화'를 통해 데이터 사일로를 물리적 통합 없이 해결하는 것이 핵심 특징이다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 데이터 메시 (Data Mesh) | 데이터 패브릭 (Data Fabric) | 선택 기준 |
|:---|:---|:---|:---|
| 해결 방식 | 조직적 전환 (현업 팀 책임) | 기술적 해결 (AI/플랫폼 자동화) | 조직 문화 vs 기술 선호도 |
| 주요 동력 | 사람, 도메인 전문성 | 데이터, 지능형 엔진 | 현업의 데이터 리터러시 |
| 권장 대상 | 대규모, 성숙한 조직 | 복잡한 인프라, 빠른 통합 필요 조직 | 조직 규모 및 복잡도 |
| 상호 관계 | 보완적 (Mesh의 하부 기술로 Fabric 활용 가능) | - | - |

> 요약: 데이터 패브릭은 '기술적 레이어'로서 데이터 관리를 효율화하는 데 집중한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 쿼리 성능 저하 | 실시간 가상화 결합 시 네트워크 부하 | 캐싱 레이어 도입, 푸시다운(Push-down) 최적화 | 가상화 쿼리 지연 시간 (Latency) |
| 메타데이터 품질 | 원천 데이터의 메타데이터 부재 | 메타데이터 자동 추출(Profiling) 강화 | 메타데이터 완성도 비율 |
| 도입 복잡성 | 이기종 시스템 간 연결 커넥터 부족 | 표준 API 및 개방형 커넥터 아키텍처 수립 | 연결 가능한 소스 비중 |

> 요약: 가상화에 따른 '성능 병목'과 '메타데이터의 정확성'이 실무 적용의 주요 리스크이다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 통합 비용 절감 | 수동 ETL 작업량 50% 이상 감소 | 개발 공수(M/M) 비교 |
| 데이터 가시성 | 전사 데이터 자산의 90% 이상 검색 가능 | 카탈로그 등록률 및 검색 성공률 |
| 실시간성 확보 | 원천 데이터 변경 시 분석 반영 시간 1분 이내 | End-to-End 싱크 시간 |

> 요약: 도입 효과는 데이터 준비 시간 단축과 통합 비용 절감액으로 정량화하여 평가한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. **가상 통합 포털 구축**: 현업 사용자가 기술적 배경 없이도 전사 데이터를 쇼핑하듯 검색하고 가상 테이블로 즉시 조회하는 환경 구현
2. **AI 기반 거버넌스 자동화**: 개인정보(PII)가 포함된 데이터를 AI가 스스로 탐지하여 자동으로 마스킹 처리하고 접근 권한을 제한
3. **멀티 클라우드 데이터 허브**: AWS, Azure에 분산된 데이터를 물리적 이동 없이 결합하여 하이브리드 클라우드 분석 체계 완성

**결론 (2줄):**
- 기술사 판단: 데이터 패브릭은 '복사해서 합치는 시대'에서 '연결해서 활용하는 시대'로의 전환이며, 데이터 복잡성을 다루는 가장 현실적인 기술적 대안이다.
- 향후 방향: 생성형 AI(GenAI)와 결합하여 자연어 질의만으로 데이터 패브릭이 파이프라인을 자동 생성하는 '자율형 데이터 패브릭'으로 진화할 것이다.
