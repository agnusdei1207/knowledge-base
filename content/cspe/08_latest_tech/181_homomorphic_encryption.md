## 미리 알고가기

- 동형암호는 암호문을 복호화하지 않고도 덧셈과 곱셈 같은 연산을 수행하게 하는 암호 기술임
- AI 실무에서는 정확한 정수 연산보다 근사 실수 연산이 가능한 CKKS 계열 활용이 많음
- 핵심 병목은 노이즈 증가와 부트스트래핑 비용이므로 적용 범위를 잘 선택해야 함

## Ⅰ. 개요

- **정의/개념**: 동형암호는 평문을 복호화하지 않은 채 암호문 상태에서 연산을 수행하고, 최종 결과를 복호화하면 평문에서 직접 계산한 값과 대응되도록 만드는 암호 기술임
- **배경/필요성**: 클라우드나 외부 연산 환경에서 민감 데이터를 처리할 때 저장과 전송 구간뿐 아니라 연산 중 데이터까지 보호하려면 복호화 없는 계산 구조가 필요해짐

## Ⅱ. 특징

- 데이터가 암호문 상태로 유지되어 신뢰하지 않는 연산 환경에서도 기밀성을 높일 수 있음
- AI 추론과 통계 분석처럼 외부 위탁 계산이 필요한 업무에 강한 보호 수단이 됨
- 곱셈 깊이가 깊어질수록 노이즈와 연산 비용이 급격히 커져 실시간성이 떨어질 수 있음
- 정확한 연산과 근사 연산 스킴 선택에 따라 성능과 정밀도의 균형이 달라짐

## Ⅲ. 종류 및 비교

| 판단 기준 | PHE | SWHE | FHE |
|:---|:---|:---|:---|
| 지원 연산 | 덧셈 또는 곱셈 일부 | 제한된 덧셈과 곱셈 | 임의의 덧셈과 곱셈 |
| 연산 깊이 | 사실상 단순 | 제한적 | 부트스트래핑으로 확장 |
| 성능 | 가장 빠름 | 중간 | 가장 느림 |
| 대표 활용 | 단순 집계 | 제한형 ML 연산 | 고보안 일반 계산 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Key Generation | 공개키와 비밀키와 평가 키를 생성해 암호화와 계산과 복호화의 역할을 분리함 |
| Encryption, Packing | 원본 데이터를 암호문으로 변환하고 필요 시 여러 값을 한 번에 배치해 연산 효율을 높임 |
| Homomorphic Evaluation | 암호문끼리 덧셈과 곱셈과 선형대수 연산을 수행해 원하는 함수를 계산함 |
| Noise Management, Bootstrapping | 누적 노이즈를 관리하고 필요 시 부트스트래핑으로 계산 가능 깊이를 회복함 |
| Decryption, Validation | 결과 암호문을 복호화하고 정확도와 정밀도 손실을 검증함 |

```text
+-------------------+      +-------------------+      +-------------------+
| Key Generation    | ---> | Encrypt / Packing | ---> | HE Evaluation     |
+-------------------+      +-------------------+      +-------------------+
                                                           |
                                                           v
                                                   +-------------------+
                                                   | Bootstrap / Decrypt|
                                                   +-------------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 키/암호문 준비   | --> | 암호문 연산 수행 | --> | 노이즈 관리/보강 | --> | 복호화/결과 검증 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **키 및 암호문 준비**: 공개키와 비밀키를 생성하고 입력을 암호화함
2. **암호문 연산 수행**: 필요한 통계나 모델 연산을 암호문 상태에서 수행함
3. **노이즈 관리 및 보강**: 연산 깊이에 따라 스케일링과 부트스트래핑을 적용함
4. **복호화 및 결과 검증**: 결과를 복호화하고 허용 오차와 지연을 검증함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 곱셈이 많은 모델을 암호문 상태로 그대로 실행하면 부트스트래핑과 메모리 비용이 급증해 실용성이 떨어질 수 있음
   - 해결방안: low-depth circuit과 approximate HE를 선택하고 ciphertext latency와 bootstrapping frequency로 검증함
2. 문제: 근사 연산 스킴은 수치 정밀도가 누적 오차에 민감해 결과 해석이 어려워질 수 있음
   - 해결방안: precision budget과 scaling strategy를 조정하고 relative error와 task accuracy로 검증함
3. 문제: 평가 키와 암호 파라미터 관리가 복잡하면 서비스 배포 시 호환성 오류와 키 오용 위험이 생길 수 있음
   - 해결방안: key lifecycle 관리와 parameter profile 표준화를 적용하고 key misuse incident rate와 deployment failure rate로 검증함

## Ⅶ. 적용 사례

- 금융 신용평가가 고객 피처를 암호문 상태로 외부 연산 환경에서 추론하며 확인 지표는 inference latency와 relative error임
- 의료 영상 분석이 병원 외부 GPU 자원에서 암호화된 특징 벡터를 처리하며 확인 지표는 privacy breach rate와 diagnostic accuracy임
- 데이터 협업 플랫폼이 기업 간 암호화 통계 집계를 제공하며 확인 지표는 aggregation correctness와 ciphertext expansion ratio임

## Ⅷ. 결론

동형암호는 연산 중 데이터 보호를 가장 강하게 달성하는 기술이지만 비용이 크므로 모델 깊이와 정밀도 요구를 줄인 아키텍처 설계가 실무 성공의 핵심임.
