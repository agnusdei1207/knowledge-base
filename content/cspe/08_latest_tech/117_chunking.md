## 미리 알고가기

- 청킹은 원문 문서를 검색과 생성에 적합한 길이의 조각으로 나누는 전처리 단계임
- 청크 크기와 overlap은 검색 정밀도와 문맥 보존을 동시에 좌우함
- 문서 구조를 깨뜨리면 좋은 임베딩과 검색기를 써도 성능이 쉽게 무너짐

## Ⅰ. 개요

- **정의/개념**: 청킹은 긴 원문 문서를 임베딩과 검색과 LLM 컨텍스트 주입에 적합한 단위로 분할해 정보 밀도와 문맥 보존의 균형을 맞추는 데이터 전처리 기법임
- **배경/필요성**: 문서 전체를 하나의 벡터로 만들면 의미가 희석되고, 너무 긴 문서를 그대로 주입하면 비용과 노이즈가 커지므로 적절한 분할 단위가 필요함

## Ⅱ. 특징

- 검색기는 더 정밀한 근거 조각을 찾고 생성기는 필요한 문맥만 받게 되어 효율이 높아짐
- chunk size가 너무 작으면 맥락 손실이 생기고, 너무 크면 검색 정밀도가 떨어질 수 있음
- overlap은 문맥 단절을 줄이지만 과도하면 중복 저장과 비용을 늘림
- 문서 유형별로 코드, 표, 법조문처럼 분할 전략을 달리해야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | Fixed-size Chunking | Recursive Chunking | Semantic Chunking |
|:---|:---|:---|:---|
| 구현 난도 | 낮음 | 중간 | 높음 |
| 문맥 보존 | 낮음 | 중간 | 높음 |
| 비용 | 낮음 | 낮음 | 높음 |
| 대표 활용 | 빠른 PoC | 일반 문서 RAG | 고품질 검색 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Parser | PDF, HTML, Markdown에서 텍스트와 구조를 추출해 청킹의 기반을 제공함 |
| Chunk Size Policy | 한 청크에 포함할 토큰 수를 정해 검색 정밀도와 문맥 밀도를 조절함 |
| Overlap Policy | 경계부 문맥을 중복시켜 문장 단절과 정보 손실을 줄임 |
| Metadata Attachment | 문서명, 페이지, 절 번호를 붙여 검색 후 출처 추적과 병합을 가능하게 함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 원문 파싱      | --> | 분할 규칙 적용   | --> | overlap/메타 부착 | --> | 청크 인덱싱 준비 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **원문 파싱**: 문서의 텍스트와 구조를 추출함
2. **분할 규칙 적용**: 크기나 구조 기준으로 문서를 조각냄
3. **overlap 및 메타 부착**: 문맥 연결과 출처 추적 정보를 붙임
4. **청크 인덱싱 준비**: 임베딩과 검색 색인을 위한 입력 단위를 완성함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 청크가 너무 작으면 핵심 문장이 어떤 맥락에서 나온 것인지 사라져 검색은 맞아도 답변 품질이 낮아질 수 있음
   - 해결방안: chunk size와 overlap을 함께 튜닝하고 answer faithfulness와 context completeness로 문맥 보존을 검증함
2. 문제: 청크가 너무 크면 관련 없는 정보가 함께 묶여 검색 정밀도와 비용이 동시에 악화될 수 있음
   - 해결방안: 도메인별 적정 크기를 찾고 precision@k와 prompt token count로 밀도 균형을 검증함
3. 문제: 표나 코드나 문단 구조를 무시한 분할은 원문 논리를 훼손해 검색 근거 자체를 망가뜨릴 수 있음
   - 해결방안: 문서 유형별 parser와 구조 기반 규칙을 적용하고 structure preservation rate와 user correction rate로 품질을 검증함

## Ⅶ. 적용 사례

- 사내 규정 문서 RAG: 절 단위와 토큰 기준을 혼합해 분할함, 확인 지표는 context precision과 citation accuracy임
- 기술 매뉴얼 검색: 코드 블록과 표를 보존해 청킹함, 확인 지표는 first-hit relevance와 resolution rate임
- 법률 QA: 조항 번호 메타데이터를 붙여 관리함, 확인 지표는 traceability와 answer correctness임

## Ⅷ. 결론

청킹은 단순 분할 작업이 아니라 검색 정밀도와 생성 문맥 품질을 결정하는 핵심 설계 단계이므로, 문서 구조와 업무 목적에 맞는 분할 정책이 필수임.
