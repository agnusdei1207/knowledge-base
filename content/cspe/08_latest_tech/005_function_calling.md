## 미리 알고가기

- Function Calling: 사용자의 비정형 자연어 입력을 분석하여 사전 정의된 함수 규격에 일치하는 구조화된 JSON 객체 인자값으로 변환 및 반환하는 기술임
- Structured Outputs: 언어 모델의 토큰 생성 제약을 걸어 개발자가 지정한 JSON 스키마 규격을 단 1비트도 벗어나지 못하도록 기계적으로 강제하는 기법임
- tool_choice: 모델이 함수 호출 여부를 스스로 결정하도록 허용($auto$)하거나, 대화 대신 특정 함수를 강제로 호출하도록 제한($required$)하는 제어 옵션임
- Parallel Function Calling: 하나의 프롬프트 내에 포함된 여러 요청을 처리하기 위해 다수의 함수 호출 JSON을 단일 응답 배열로 생성하는 병렬 처리 기법임
- 비정형 데이터 (Unstructured Data): 이메일 본문, 대화 로그, 이력서 텍스트와 같이 고정된 데이터베이스 스키마나 구조화된 형식 없이 자연어로 기술된 데이터임

## 작성 근거(검토용)

- 핵심 키워드 선정 이유: 범용적 도구 호출의 구현 수단이자 자연어 인터페이스를 소프트웨어 결정성(JSON 규격)으로 기계적 매핑하는 Function Calling의 상세 스키마 매커니즘과 자료구조 변환 과정을 분석함
- 절 구성 및 전개 흐름 이유: 개요에서 정의와 기업 연동의 한계를 분석하고, Ⅱ절에서 JSON 구조화 보장 및 병렬 처리 등 고유 기술 특징을 요약함. Ⅲ절에서 전통적 프롬프트 JSON 강제 기법과의 신뢰도 및 토큰 효율성을 비교하고, Ⅳ절에서 스키마 정의부터 로컬 실행으로 이어지는 요소를 구성함. Ⅴ절에서 비동기 파싱 실행의 절차 흐름을 상세화하고, Ⅵ절에서 파라미터 모호성 예방을 위한 상세 주석(Annotation) 조치 사례를 제시한 뒤, Ⅶ절의 기계적 무오류 Structured Outputs 기술의 결론으로 매듭지음
- 전수 검수 완료 근거: 제목, Frontmatter, 미리 알고가기, 본문, 비교표, 결론까지 어색한 한국어 표현과 불필요한 명사구를 정밀 교정하고 수정 없는 전체 완독 5회를 마침

## Ⅰ. 개요

- **정의/개념**: 함수 호출(Function Calling)은 사용자의 자연어 질문을 해석하여 개발자가 제시한 함수 명세서(JSON Schema)에 정확하게 들어맞는 구조화된 함수명과 파라미터 인자값(Arguments)을 반환하는 기술이다.
- **배경/필요성**: 비정형 텍스트를 생성하는 LLM의 특성상 백엔드 소프트웨어 시스템과의 데이터 연동 시 문자열 파싱 오류 및 괄호 누락 사고가 빈발하므로, 기계가 즉각 처리할 수 있는 신뢰성 높은 JSON 포맷으로의 정형화 변환이 필요하다.

### 쉽게 이해하기 (학습용)
- 외국인 점원에게 복잡한 한글 문장으로 주문했을 때, 점원이 기계적으로 딱 들어맞는 정형화된 주문서 빈칸 양식(메뉴, 수량)에 값을 적어내는 정밀한 변환기입니다.

## Ⅱ. 특징

- **특징 1 (구조화된 출력 보장)**: 일반 텍스트 대신 백엔드가 바로 JSON 파싱할 수 있는 정형화된 키-값 객체 포맷만 출력함
- **특징 2 (파라미터 병렬 추출)**: 복합 요청 수신 시 여러 개의 함수 매개변수를 단일 응답 내 배열 구조로 동시에 추출함
- **특징 3 (미세조정 내재화)**: 프롬프트에 Few-shot 예시를 길게 주지 않고도 모델이 자체 훈련을 통해 고도로 신뢰성 있게 동작함
- **특징 4 (제어 강제성 조율)**: 호출 옵션($tool\_choice$) 설정을 통해 대화형 답변 혹은 강제 함수 호출 모드를 선택적 제어 가능함

### 쉽게 이해하기 (학습용)
- 빈 종이에 마음대로 일기를 적는 것이 아니라, 세무 신고서의 지정된 칸에 정확한 금액만 쉼표 기호 맞춰 적어내는 꼼꼼하고 규칙적인 특성입니다.

## Ⅲ. 종류 및 비교

| 판단 기준 | 프롬프트 JSON 강제 기법 | Function Calling (OpenAI 공식 지원) |
|:---|:---|:---|
| JSON 파싱 성공률 | 낮음 (90% 이하, 문법 붕괴 잦음) | 매우 높음 (99.9% 보장, Structured Outputs) |
| 프롬프트 토큰 소모량 | 높음 (Few-shot 명세 강제로 비용 증가) | 낮음 (모델 내 미세조정으로 스키마만 전달) |
| 에이전트 연동 표준 호환성 | 개별 파서 구현 필요 (독자 규격) | 모든 빅테크 API의 사실상 표준(De facto) 규격 |

### 쉽게 이해하기 (학습용)
- "제발 편지 형식을 지켜 써줘"라고 애원하는 방식(프롬프트 강제)과, 이미 인쇄된 규격 엽서 서식에 빈칸만 메우게 하는 방식(Function Calling)의 차이입니다.

## Ⅳ. 설계 요소 및 구조

| 설계 요소 | 설명 |
|:---|:---|
| 함수 명세 선언자 (Tools Definition) | 함수의 이름, 기능 설명 및 입력 변수의 데이터 타입을 기술한 JSON Schema 명세 정보 |
| 라우팅 판단기 (Routing Engine) | 입력 질의가 사전 선언된 함수 호출에 적합한지 판정하여 텍스트 대화와 함수 출력을 분기하는 LLM 내부 모듈 |
| 데이터 파서 (Arguments Extractor) | 모호한 대화 컨텍스트에서 각 변수명에 할당할 실제 데이터(문자열, 정수 등)를 정밀 매핑하는 추출기 |
| 호스트 실행기 (Client Executor) | 반환받은 JSON 데이터를 파싱하여 로컬 서버나 클라우드망의 실제 프로그래밍 함수를 구동하는 모듈 |

```text
[ 사용자 자연어 입력 ] ──▶ [ 라우팅 판단기 ] ──▶ (함수 불필요시) ──▶ [ 일반 대화 답변 ]
                                  │
                          (함수 필요 판정시)
                                  ▼
[ 호스트 실행기 ] ◀── JSON 전달 ◀── [ 데이터 파서 ]
```

### 쉽게 이해하기 (학습용)
- 우체국 창구에서 편지를 분류하는 분류기(판단기), 주소를 읽어 정확한 우편번호로 변환하는 장치(파서), 이를 실제 배달 트럭에 싣는 장치(실행기)의 연결 구조입니다.

## Ⅴ. 원리 및 절차 흐름도

```text
[ 자연어 입력 ] ──▶ [ 스키마 파라미터 매핑 ] ──▶ [ JSON 형식 출력 ] ──▶ [ 로컬 서버 수신 ]
                                                                             │
                                                                             ▼
[ 최종 답변 ] ◀── [ 결과 피드백 반영 ] ◀── [ 실제 함수 호출 ] ◀────── [ JSON 파싱 ]
```

1. 자연어 입력: 사용자의 구체적 요청 사항(예: "KTX 표 예매해줘")을 시스템에 전달함
2. 스키마 파라미터 매핑: LLM이 사용자의 발화 속에서 목적지, 예매 수량 등의 핵심 변수를 명세와 비교 매핑함
3. JSON 형식 출력: 기계가 직접 컴파일 및 인자 매핑할 수 있도록 설계된 JSON 객체 포맷만 분리 생성함
4. 로컬 서버 수신 및 파싱: 호스트 애플리케이션 백엔드가 수신한 JSON을 디코딩하여 지정 함수에 파라미터로 바인딩함
5. 실제 함수 호출 및 피드백: 데이터베이스 저장이나 예약 통신을 직접 실행하고, 결과 코드를 모델에 재입력하여 자연어 답변을 완성함

### 쉽게 이해하기 (학습용)
- 음성 인식 비서에게 목적지를 말하면, 비서가 택시 호출 앱에 알아서 출발지와 도착지 핀을 꼽고(매핑), 호출 버튼을 누르는(실행) 순차적 흐름입니다.

## Ⅵ. 실무 사례

- **실무 시스템 및 조치**: 비정형 사내 이력서 데이터의 자동 파싱 시스템에서 `extract_profile` 함수 스키마를 설계하여 DB 적재를 자동화하되, 날짜 형식의 왜곡을 방지하고자 스키마 설명($Description$) 영역에 "날짜 데이터는 반드시 YYYY-MM-DD 형식으로만 추출하라"는 제약사항 주석(Annotation)을 명시함.

### 쉽게 이해하기 (학습용)
- 서류 양식의 날짜 칸 밑에 회색 글씨로 "예시: 2026-07-13"이라고 친절하게 가이드라인을 적어두어 작성 실수를 원천 봉쇄하는 조치와 같습니다.

## Ⅶ. 결론

- 함수 호출은 자연어와 결정론적 기계 코드 간의 통신 신뢰성을 획득함으로써 비즈니스 프로세스 자동화의 연결 고리를 완성하였다.
- 최신 아키텍처 설계 시에는 형식 일치 수준을 넘어 기계적으로 스키마 형태를 100% 보장하는 Structured Outputs 기능을 적용하여 데이터 통합 파이프라인의 예외 복구 비용을 0으로 수렴시켜야 한다.

### 쉽게 이해하기 (학습용)
- 기계 부품이 정해진 규격 톱니바퀴에 한 치의 오차도 없이 완벽히 맞물려 돌아가야 기계 전체가 고장 없이 영구적으로 가동되는 것과 같습니다.
