# 📖 【암기용】 개념 완전 이해

> 목적: MCP Tool을 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: MCP Server가 AI 앱에 제공하는 실행 가능한 기능
- **왜 필요한가**: 에이전트가 검색·계산·티켓 생성·배포 조회 같은 업무 기능을 표준 방식으로 호출해야 함.
- **핵심 직관**: MCP Tool은 AI가 누를 수 있는 업무 버튼이며, 버튼마다 권한과 입력 양식이 있음.

## 깊이 이해
- **배경·문제의식**: 도구 호출이 앱마다 다르면 입력 스키마, 권한, 감사 방식이 달라져 운영 통제가 어려움.
- **작동 원리**: Tool은 이름, 설명, 입력 스키마를 제공하고 Client 호출 시 서버가 검증 후 실제 백엔드 기능을 실행함.
- **비유**: 사내 그룹웨어의 결재, 조회, 등록 버튼을 AI가 정해진 양식으로 누르는 구조.
- **구체 예시**: `create_incident`, `search_logs`, `query_customer` Tool이 각각 장애 등록, 로그 조회, 고객 조회를 수행함.
- **흔한 오해·주의점**: Tool은 실행 권한을 포함하므로 조회형·변경형·관리형으로 등급화해야 함.

## 연결 개념
- Function Calling — Tool 입력을 구조화하는 방식
- Policy Engine — 호출 가능 여부 판단
- Audit Log — 실행 근거와 책임 추적

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: MCP Tool은 MCP Server가 표준 스키마로 노출하는 실행 가능한 함수형 기능임.
> 2. **가치**: AI 에이전트가 업무 시스템을 안전하게 호출하도록 입력 형식, 권한, 로그를 통제함.
> 3. **판단 포인트**: 변경형 Tool은 승인, 멱등성, 롤백, 감사로그를 갖춰야 함.

---

## Ⅰ. 개요 및 필요성

MCP Tool은 MCP의 실행 기능 단위임. AI 에이전트가 외부 시스템을 조작하려면 Tool 정의, 입력 검증, 권한통제, 실행로그가 필요함.

---

## Ⅱ. 구조 및 구성요소

```text
Tool Name → Description → Input Schema → Executor
       │          │              │            │
       ▼          ▼              ▼            ▼
    식별자       용도설명        검증규칙      업무실행
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Name/Description | Tool 식별과 용도 설명 | 모델 선택 품질에 영향 |
| Input Schema | 인자 타입·범위 정의 | JSON Schema, enum |
| Executor | 백엔드 기능 실행 | timeout, retry, rollback |
| Permission | 호출 권한 통제 | 읽기·쓰기·관리 등급 |

> 요약: MCP Tool은 설명, 입력 스키마, 실행기, 권한정책이 결합된 실행 단위임.

---

## Ⅲ. 동작원리 및 흐름도

```text
도구 선택 → 인자 생성 → 스키마 검증 → 권한 확인
       → 실행 → 결과 정제 → 감사로그 저장
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | Tool 선택 | 설명 일치, 권한 등급 |
| 2 | 입력 생성·검증 | 필수값, 타입, 범위 |
| 3 | 실행·오류처리 | 응답코드, timeout, 재시도 |
| 4 | 결과 반환·감사 | 마스킹, Trace ID, 롤백 |

> 요약: MCP Tool 호출은 스키마와 권한 검증을 통과해야 실제 업무 실행으로 이어짐.

---

## Ⅳ. 특징

| 구분 | 일반 함수/API | MCP Tool | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 사용 주체 | 애플리케이션 코드 | LLM·에이전트 | 도구 선택 오류율 |
| 입력 | 개발자 작성 | 모델 생성 | 스키마 오류율 |
| 통제 | API 보안 | 모델 선택+API 보안 | 승인율, 거부율 |

> 요약: MCP Tool은 모델이 선택한다는 특성 때문에 설명 품질과 권한 검증이 API 보안만큼 중요함.

---

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. Tool을 조회형·변경형·관리형으로 분류하고 변경형 이상은 승인, 멱등성 키, 롤백 절차 적용
2. 입력 스키마에 타입, enum, 범위, 문자열 길이, 정규식을 명시하고 서버에서 재검증
3. 도구명, 설명, 호출자, 입력 해시, 응답코드, 변경 대상ID를 감사로그로 보관

**결론 (2줄):**
- 기술사 판단: MCP Tool은 업무 자동화의 핵심이나, 변경형 Tool은 API Gateway 수준 통제를 적용해야 함.
- 향후 방향: Tool Registry와 정책 엔진이 결합되어 AI 실행 기능의 표준 카탈로그로 발전함.
