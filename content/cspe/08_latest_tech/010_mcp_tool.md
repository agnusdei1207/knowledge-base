## 미리 알고가기

- **MCP 도구(MCP Tool)**: MCP 서버가 노출하며 AI 클라이언트가 인자를 넘겨 실행할 수 있는 JSON Schema 스펙 기반의 실행 가능한 함수 객체임.
- **인간 개입(Human-in-the-Loop, HITL)**: AI 모델의 자율적 판단 도중 발생하는 결제, 삭제 등의 고위험 행동에 대해 최종 결정권을 사람이 가지게 제어하는 아키텍처임.
- **부작용(Side Effect)**: 함수나 API가 실행될 때 리턴값을 반환하는 것 외에 시스템의 영구적인 데이터 상태 변경(DB 삽입, 삭제, 네트워크 전송 등)을 유발하는 현상임.
- **프롬프트 인젝션(Prompt Injection)**: 악의적인 지시문을 통해 LLM의 안전 가이드라인을 우회하여 의도하지 않은 비정상 행위를 수행하도록 조종하는 공격 기법임.
- **JSON Schema**: JSON 데이터의 구조, 필수 값, 데이터 타입 등을 선언적으로 정의하고 검증하기 위한 어휘 사전 및 표준 규격임.

## 작성 근거(검토용)

- **핵심 키워드 선정 이유**: AI 에이전트가 현실 세계에 실질적인 연동 제어를 실행하고, 보안 위협에 대처할 수 있도록 MCP 도구의 설계 방안을 확립하기 위해 핵심 키워드로 선정함.
- **배치·전개 근거**: MCP 리소스와의 비교를 통해 부작용(Side Effect)이 수반되는 특징을 분석함. JSON Schema 명세 구조도를 구성하고, 도구 선언부터 파라미터 추론 및 런타임 실행 결과 반환까지의 4단계 실행 흐름도를 규명함. 프롬프트 인젝션 위험을 방어하기 위한 HITL 적용 기법을 실무사례와 융합함.
- **전수 검수 완료 근거**: 제목, frontmatter, 본문, 비교표, 도식, 요약 및 결론의 단어·조사·동사 결합 오류를 5회 이상 검수하고 맞춤법 오류를 교정하였음.

## Ⅰ. 개요
- **정의/개념**: MCP 도구는 AI 클라이언트가 규격화된 파라미터를 넘겨 서버 측에 실행을 지시할 수 있는 JSON Schema 기반의 실행 가능한 함수 규격임.
- **배경/필요성**: 텍스트 생성에 국한된 AI 모델의 한계를 극복하고, 사외 레거시 시스템이나 클라우드 인프라를 자율적으로 직접 조작하기 위해 필요함.

### 쉽게 이해하기 (학습용)
- 정보만 제공하는 가이드북을 넘어, AI가 직접 버튼을 눌러 청소기를 켜거나 메일을 보낼 수 있게 해주는 마법의 팔다리 도구 상자와 같습니다.

## Ⅱ. 특징
- **JSON Schema 검증**: 입력 파라미터의 타입 및 유효 범위를 엄격한 JSON Schema 규격으로 선언하여 불완전한 호출을 서버 단에서 1차로 필터링함.
- **영향 유발성**: 조회 목적에 그치지 않고 데이터의 쓰기, 수정, 삭제 및 네트워크 서비스 전송 등 외부 시스템의 영구적 상태 변경을 수행함.
- **동적 파라미터 추론**: 사용자의 구어체 요구사항으로부터 LLM이 스키마 규격에 일치하는 JSON 인자값들을 동적으로 파싱하고 입력하도록 설계됨.

### 쉽게 이해하기 (학습용)
- AI가 대화 중 필요한 도구의 규격서(설명서)를 보고 파라미터를 자동으로 조립해 기계에 명령을 전달합니다.

## Ⅲ. 종류 및 비교

| 판단 기준 | MCP 리소스 (Resource) | MCP 도구 (Tool) |
|:---|:---|:---|
| **동작 목적** | AI 컨텍스트 확장을 위한 지식 제공 | 외부 시스템의 물리적 동작 및 연산 처리 |
| **상태 변화 유무** | 상태 변화가 없음(Side Effect Free) | 영구적인 시스템 상태 변이를 동반함(Side Effect) |
| **보안 통제 수준** | 서버 단의 접근 권한 제어로 통제 가능 | 위험 도구에 대해 사용자 승인(HITL) 체인 필수 |

### 쉽게 이해하기 (학습용)
- 도서관에 비치되어 읽기만 하는 매뉴얼이 리소스라면, 실제 버튼을 눌러 인프라를 차단하는 제어 스위치는 도구입니다.

## Ⅳ. 설계 요소 및 구조

```text
[ CallTool Request (JSON-RPC) ]
  ├── name: send_slack_msg
  └── arguments: { "channel": "qa-channel", "text": "Deploy Success" }
```

| 설계 요소 | 설명 |
|:---|:---|
| **Tool Definition** | 도구의 한글/영문 이름과 역할 설명을 LLM의 인지가 용이하도록 서술해 놓은 명세 영역 |
| **Input Schema** | 도구 실행에 필요한 필수 및 선택 파라미터의 명세와 제약 조건을 담은 JSON Schema 구조 |
| **Sanitizer & Validator** | AI가 보낸 파라미터 값에 유해한 이스케이프 문자나 주입 공격 시도가 있는지 실시간 필터링하는 검증기 |

### 쉽게 이해하기 (학습용)
- 도구의 이름과 설명(정의), 입력 가능한 형태의 규칙판(스키마), 그리고 해킹 위험이 없는지 걸러주는 거름망(세니타이저)으로 구성됩니다.

## Ⅴ. 원리 및 절차 흐름도

```text
[Client]                                           [Server]
   │                                                  │
   ├─────────────── 1. tools/list ────────────────────▶│ (제공 가능한 도구 명세 요구)
   │◀────────────── 2. Return Tool Specifications ────┤
   │                                                  │
   │ [ LLM: `send_slack_msg` 파라미터 조립 ]          │
   │                                                  │
   ├─────────────── 3. tools/call (with Arguments) ──▶│ (보안 검증 및 도구 실행 명령)
   │                                           [External Target]
   │                                                  │
   │                                           ├───── 4. Run API ──────▶
   │                                           │◀──── 5. API Response ─┘
   │                                                  │
   │◀────────────── 6. Return Result Data ────────────┤ (성공 여부 및 텍스트 송신)
```

1. **도구 탐색**: 클라이언트가 서버에 `tools/list` 요청을 전송해 가용한 도구들의 이름과 입력 스키마 규격들을 반환받음.
2. **추론 및 요청**: 사용자의 자연어 입력이 유입되면 LLM이 이에 부합하는 도구를 고르고 arguments 값을 동적 조립하여 `tools/call`을 서버에 호출함.
3. **검증 및 실행**: 서버는 arguments 값을 세니타이징하고 타겟 백엔드 시스템(API)을 트리거한 뒤, 결과를 포맷팅하여 클라이언트에 돌려줌.

### 쉽게 이해하기 (학습용)
- 쓸 수 있는 공구 목록을 확인하고(탐색), 명령에 맞춰 적합한 공구를 골라 나사를 조인 뒤(요청), 조인 결과를 보고받는 과정(실행)과 같습니다.

## Ⅵ. 실무 사례
- 클라우드 DevSecOps 자동화 시스템 구축 시, 모니터링 경보 감지에 따른 공격 대응을 위해 ECS 인스턴스 논리 격리 기능인 `isolate_instance` 도구를 MCP 서버에 구현하고, AI 클라이언트가 도구를 호출할 때 위험 조치(Isolate)에 대해서는 메신저로 최종 승인 동의를 받아내는 인간 개입($Human-in-the-Loop$) 절차를 구현함.

### 쉽게 이해하기 (학습용)
- AI가 서버 컴퓨터 전원을 강제로 끄기 직전에, 관리자의 휴대폰 앱으로 "승인하시겠습니까?"라는 팝업 창을 띄워 결정을 유보하는 형태입니다.

## Ⅶ. 결론
- MCP 도구는 AI 에이전트의 단순 질의응답 역할을 물리적 자율 업무 수행 수준으로 격상하는 핵심 기반임.
- 악의적인 프롬프트 인젝션에 의한 파괴적 명령 실행을 방지하기 위해 서버 측 ACL 관리와 함께 중요 도구 호출 시 다중 사용자 승인 아키텍처를 도입해야 함.

### 쉽게 이해하기 (학습용)
- 결론적으로 AI가 말만 하는 비서가 아니라 실제 일을 처리할 수 있게 하되, 안전핀(인간 승인)을 달아 통제해야 하는 필수 도구입니다.
