## 미리 알고가기

- 알고리즘 책임성은 설명 가능성보다 넓은 개념으로 책임 주체와 감사와 구제 절차까지 포함함
- 자동화된 결정이 사람에게 불이익을 줄 수 있는 영역일수록 추적성과 재심 절차가 중요함
- 기술 기능만으로 완성되지 않으며 역할 분담과 로그와 운영 규정이 함께 필요함

## Ⅰ. 개요

- **정의/개념**: 알고리즘 책임성은 AI나 알고리즘이 내린 결정의 근거와 과정과 결과에 대해 조직이 설명과 추적과 시정과 구제 의무를 지도록 만드는 통제 원칙이자 운영 체계임
- **배경/필요성**: 고위험 AI가 채용과 대출과 복지 심사 같은 의사결정을 자동화하면서 피해가 발생해도 책임 주체가 불분명한 경우가 늘어났으므로, 결과에 대한 인간 책임과 감사 가능성을 명확히 할 필요가 커짐

## Ⅱ. 특징

- 단순한 모델 설명 제공을 넘어서 소유권과 승인 이력과 재심 절차를 함께 요구함
- 입력과 모델 버전과 출력과 설명 결과를 모두 남겨야 사후 감사가 가능함
- 피해자 관점에서 이의 제기와 수정과 보상 절차가 있어야 실질적 책임성이 성립함
- 조직 구조와 시스템 로깅과 사용자 통지 방식이 맞물려야 작동함

## Ⅲ. 종류 및 비교

| 판단 기준 | Algorithmic Accountability | Explainable AI | AI Governance |
|:---|:---|:---|:---|
| 초점 | 책임 귀속과 구제와 감사 | 판단 근거 해석 | 조직 차원의 통제 구조 |
| 핵심 수단 | 로그, RACI, appeal, audit | SHAP, LIME, rules | 정책, 심의, 승인 절차 |
| 사용자 관점 | 이의 제기와 재심 가능 | 이유 설명 제공 | 서비스 운영 기준 제시 |
| 실무 범위 | 제도와 기술 결합 | 기술 설명 계층 | 전사 운영 체계 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Traceability Log | 입력 데이터와 모델 버전과 출력 결과와 승인 기록을 남겨 사고 원인 추적을 가능하게 함 |
| Ownership, RACI | 기획자와 데이터 관리자와 운영자 중 누가 무엇을 승인하고 책임지는지 명확히 함 |
| Explanation, Disclosure | 자동화된 판단 사실과 핵심 근거를 사용자에게 알려 정보 비대칭을 줄임 |
| Appeal, Human Review | 이의 제기와 재검토 절차를 통해 자동화 오판을 수정할 수 있게 함 |
| Audit, Remediation | 정기 감사를 통해 구조적 문제를 찾아내고 시정 조치를 추적함 |

```text
+-------------------+      +-------------------+      +-------------------+
                                                           |
                                                           v
                                                   +-------------------+
                                                   | Appeal / Audit    |
                                                   +-------------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 의사결정 기록    | --> | 근거/책임 연결  | --> | 통지/이의 접수  | --> | 재심/시정 조치  |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **의사결정 기록**: 입력과 모델과 출력을 증적 형태로 남김
2. **근거 및 책임 연결**: 설명 정보와 담당자와 승인 이력을 연결함
3. **통지 및 이의 접수**: 사용자에게 결과와 설명과 구제 경로를 제공함
4. **재심 및 시정 조치**: 인간 검토와 감사 결과를 반영해 결과를 수정함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 설명 결과만 제공하고 최종 책임자와 재심 절차가 없으면 사용자는 불이익을 받아도 실질적 구제를 받기 어려움
   - 해결방안: accountable owner와 appeal workflow를 의무화하고 human review completion rate와 remedy lead time으로 검증함
2. 문제: 입력과 모델 버전과 승인 로그가 분산 저장되면 사고 발생 후 원인 추적과 규제 대응이 지연될 수 있음
   - 해결방안: lineage logging과 immutable audit trail을 적용하고 trace completeness와 audit response time으로 검증함
3. 문제: 현업이 자동화 결과를 과신하면 인간 검토 단계가 있어도 형식 절차로 전락할 수 있음
   - 해결방안: override training과 risk-based sampling review를 적용하고 override rate와 harmful decision escape rate로 검증함

## Ⅶ. 적용 사례

- 금융 대출 AI가 거절 사유와 재심 경로를 함께 제공하며 운영되고 확인 지표는 appeal turnaround time과 complaint resolution rate임
- 채용 알고리즘이 모델 버전과 평가 근거와 승인 이력을 남기도록 설계되며 확인 지표는 trace completeness와 audit finding closure rate임
- 공공 심사 시스템이 자동 판정 뒤 인간 재검토 절차를 강제하며 확인 지표는 human review coverage와 wrongful decision rate임

## Ⅷ. 결론

알고리즘 책임성은 AI가 틀릴 수 있다는 전제를 조직과 시스템 안에 반영해 추적과 설명과 구제를 실제 운영 절차로 만드는 통제 체계임.
