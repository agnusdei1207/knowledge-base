## 미리 알고가기

- 지식그래프 융합형 RAG ($Graph$ $RAG$): 마이크로소프트($MS$)가 제안한 최신 RAG 기법으로, 문서를 기계적 파편 청크로 단순 보존하지 않고, 인공지능이 텍스트 내에서 개체(Entity, 노드)와 관계(Relationship, 엣지)를 삼차원적으로 파싱해 지식 그래프($Knowledge$ $Graph$)를 구축하고 이를 커뮤니티 요약하여 검색하는 고차원 기술임
- 다중 홉 질의 ($Multi-hop$ $Query$): 단발성 팩트 서치를 넘어, "A사 창업주의 대학 후배가 세운 B사 자회사의 주요 제품은?" 처럼 여러 노드의 엣지 관계망을 $2 \sim 3$단계 이상 건너뛰어 탐색해야만 비로소 풀리는 고난도 복합 관계 질문임
- 전역 맥락 요약 ($Global$ $Context$): 벡터 RAG로는 절대 불가능한 "이 보고서 전체를 관통하는 핵심 문제의 추이와 갈등 구조를 요약해 줘" 같은 코퍼스 전체 차원에서의 추상적 대국 요약 질의임
- 개체명 통합 정규화 ($Entity$ $Resolution$): "삼성전자", "삼전", "SAMSUNG" 등 의미상 완벽히 일치하는 상이한 텍스트 표현들을 단일 노드 정보로 수학적/기호적으로 병합 정화하는 작업임

## Ⅰ. 개요

- **정의/개념**: Graph RAG는 원본 문서 집합에서 대규모 언어 모델을 활용해 유의미한 개체(Entity)와 상호 관계(Relationship)를 기호적으로 자동 도출하여 지식 그래프를 셋업하고, 이를 위계적 커뮤니티($Hierarchical$ $Community$)로 구조 분할 요약하여 다중 홉(Multi-hop) 질문과 전역 코퍼스 요약 질문에 완벽 답하도록 고안된 최신 그래프 융합형 RAG 아키텍처임
- **배경/필요성**: 정통 벡터 RAG(Naive/Advanced)는 의미상 유사한 문단을 뽑는 부분 국지적 의미 유사성($Local$ $Similarity$)에만 특화되어, 파편화된 개별 페이지들에 뿔뿔이 흩어진 인맥/조직 관계선을 관통 분석하거나 문서 집합 전체의 통계적 대의를 조망하는 요약 질의에 대실패하여 발명됨

## Ⅱ. 특징

- 질문의 핵심 명사 노드에서 출발하여 연결된 관계망 엣지를 차례로 타고 이동하는 그래프 순회($Graph$ $Traversal$)를 수행하므로 다중 홉 추론력이 완벽함
- 계층적 커뮤니티 탐색을 기동하여, 보고서 묶음의 대단위, 중단위, 소단위 레벨의 메타 요약문을 상향식($Bottom-up$)으로 미리 빌딩해 둠
- 데이터 인덱싱 시점에 텍스트 전체의 개체 관계를 LLM으로 낱낱이 해부 분석해야 하므로, 초기 빌드 토큰 요금(비용)이 일반 RAG 대비 수십 배 폭증함

## Ⅲ. 종류 및 비교

| 판단 기준 | 벡터 기반 RAG (Vector RAG) | 지식그래프형 RAG (Graph RAG) | 하이브리드 RAG (Hybrid Graph+Vector) |
|:---|:---|:---|:---|
| **검색 매커니즘** | 고차원 임베딩 공간의 코사인 유사도 | 지식 그래프 내 개체 노드 및 관계 엣지 순회 | 벡터 유사도 검색 결과와 서브그래프 정보 병합 |
| **강점 질의 패턴** | 단발성 세부 사실 조회 ($Local$ 질문) | 전역 요약 ($Global$ 질문), 관계 추론 | 고유명사 매핑과 복합 홉 추론 동시 요구 질문 |
| **설명 가능성 ($XAI$)** | 보통 (단순 참고 청크 주입에 한정) | 매우 높음 (노드와 엣지의 경로 추적 증명) | 높음 |
| **초기 인덱싱 비용** | 극도로 저렴함 (임베딩 1회 계산 끝) | 극도로 비쌈 (LLM 통한 개체/관계 추출) | 비쌈 (두 파이프라인 동시 전처리) |

> 요약: Vector RAG는 돋보기를 들고 질문 단어와 비슷한 문단을 찾아 짚는 국지 탐색이고, Graph RAG는 헬기를 타고 지식의 전체 연결 숲(지식 그래프)과 엣지 교차로를 입체 조망하며 관계선을 인출하는 고도화 추론임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 개체/관계 추출기 | 비구조화 텍스트에서 명사 노드와 동사 엣지를 LLM 프롬프트로 명세 도출하는 파서임 |
| $Leiden$ 커뮤니티 알고리즘 | 그래프 노드 간의 밀접 결합도를 감지해, 위계적 클러스터(커뮤니티)로 구획을 분리해 주는 수학 알고리즘임 |
| 그래프 DB 저장소 | Neo4j나 메모리 인메모리 구조로 노드-엣지 인접 행렬을 안전 보존하는 데이터베이스임 |
| 로컬/글로벌 서치 엔진 | 쿼리 특성에 맞춰 특정 노드 인근만 횡단할지, 커뮤니티 전체 요약집을 훑을지 정하는 조율기임 |

```text
[ Graph RAG (지식 그래프 위계 커뮤니티 서치) 구조 ]
Unstructured Documents ──> [ Entity/Relation Extract ] ──> [ Knowledge Graph ]
                                                                 │
                                                                 v (Leiden Cluster Summary)
Safe Response <── [ Hybrid Generator ] <── [ Graph Search Engine (Global/Local) ]
- 위계적 Leiden 커뮤니티 구조를 빌드하여, 로컬 유사도와 글로벌 요약에 동시 대응함
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| LLM 기반    | --> | Leiden 커뮤  | --> | 질문 인입시 | --> | 서브그래프와|
| 노드/엣지파싱 |     | 니티 요약빌드|     | 노드경로순회|     | 커뮤니티요약|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **지식 추출** — PDF 텍스트를 흘려보내며 LLM에게 "문서 내 사람, 회사, 제품과 이들의 연결 관계를 JSON으로 뽑아라" 지시함
2. **그래프 구획 분할** — Leiden 커뮤니티 분할 알고리즘을 구동해 거대 그래프를 도메인 단위 밀집 커뮤니티로 상향 요약함
3. **탐색 순회** — "A사 개발 총괄의 이전 직장은?" 인입 시, A사 노드 -> 개발 총괄 노드 -> 이전 직장 노드로 그래프 데이터베이스를 순회함
4. **글로벌 요약 출력** — 글로벌 서치가 켜지면 커뮤니티별 기 빌드된 요약문들을 병렬로 긁어모아 전체 맥락을 가독성 높게 방출함

## Ⅵ. 실무 적용 및 유의점

1. 개체명 통합 정규화(Entity Resolution)가 부실하여 "Apple"과 "애플"을 별개의 노드로 방치하면 그래프 단선으로 다중 홉 관계망 추론이 일시에 붕괴하므로, 반드시 '임베딩 거리 대조' 및 '동의어 매핑 레이어'를 전처리 단에 장착해 노드 통합 신뢰도를 감시해야 함
2. 실시간성으로 데이터 변경이 격렬히 일어나는 업무(예: 실시간 주식 뉴스 등)에 Graph RAG를 가동하면 매번 천문학적 LLM 인덱싱 비용이 실시간으로 새어 나가 재정이 파탄 나므로, 반드시 '정적 고정형 지식 코퍼스(규범집, 매뉴얼)' 영역에 선별 분리 적용해야 함

## Ⅶ. 결론

- Graph RAG는 단순 공간 텍스트 매칭을 넘어 지식의 구조적 인과 연결망을 물리적으로 복원해 다중 홉과 전역 요약을 동시 타격하는 최강의 추론 엔진이며, 설계자는 초기 구축 토큰 비용 절감을 위한 핵심 정적 지식 도메인 한정 매핑과 관계 단절을 방지하는 개체명 통합 정규화 장치를 반드시 완비해야 함
