# 📖 【암기용】 개념 완전 이해

> 목적: Graph RAG를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: 문서에서 엔티티와 관계를 추출해 지식그래프를 만들고, 그래프 탐색 결과를 LLM에 주입하는 RAG 구조
- **왜 필요한가**: 벡터 검색은 의미가 비슷한 문단을 찾지만, 사람·조직·시스템 간 관계와 경로 추론에는 한계가 있음.
- **핵심 직관**: 문서를 문단 더미로 보지 않고, "누가 무엇과 어떤 관계인가"를 지도처럼 만들어 길을 따라 찾는 방식임.

## 깊이 이해
- **배경·문제의식**: 기업 문서에는 계약 주체, 장애 원인, 서비스 의존성처럼 관계 정보가 많다. 단순 Top-K 검색은 흩어진 관계를 한 답변에 연결하기 어렵다.
- **작동 원리**: 문서에서 엔티티·관계를 추출하고 그래프DB에 저장한 뒤, 질의 엔티티를 기준으로 k-hop 이웃·커뮤니티 요약·관계 경로를 검색해 LLM 컨텍스트로 제공함.
- **비유**: 이름이 비슷한 문서를 찾는 검색엔진이 아니라, 조직도·노선도에서 연결 경로를 따라 원인을 찾는 방식임.
- **구체 예시**: 마이크로서비스 300개 의존성 그래프에서 "결제 장애 영향 서비스" 질의 시 2-hop 경로로 API Gateway->Payment->Ledger 영향 범위 산출.
- **흔한 오해·주의점**: 그래프 추출 품질이 낮으면 잘못된 관계가 답변 근거가 된다. 엔티티 정규화와 관계 신뢰도 점수 관리가 필요함.

## 연결 개념
- Knowledge Graph — 엔티티·관계·속성을 그래프로 표현한 지식 저장소
- Multi-hop RAG — 여러 근거를 단계적으로 연결하는 검색 방식
- Graph Database — Neo4j, Amazon Neptune 등 그래프 질의 저장소

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Graph RAG는 문서 지식을 엔티티-관계 그래프로 구조화한 뒤 관계 경로를 검색하는 RAG임.
> 2. **가치**: 벡터 검색이 놓치는 k-hop 관계, 영향 범위, 원인-결과 연결을 답변 근거로 제공함.
> 3. **판단 포인트**: 엔티티 정규화·관계 신뢰도·그래프 갱신 주기가 답변 품질을 좌우함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 벡터 검색 한계 인식 확인 | 관계·경로·영향 범위 질의에서 유사도 검색의 구조적 한계 | Graph RAG를 벡터 검색의 단순 성능 개선으로 혼동 |
| 그래프 구축 파이프라인 이해 확인 | 엔티티·관계 추출, 정규화, k-hop 탐색, 커뮤니티 요약 | 추출 품질(F1)·중복 노드 관리 누락 |
| 적용 판단 역량 확인 | 초기 구축 2~4배 비용과 관계 질의 비중의 손익 판단 | 모든 RAG에 그래프 적용을 정답으로 단정 |

> 요약: 이 문제는 그래프 구조 설명이 아니라 관계 질의 비중과 구축 비용을 저울질하는 적용 판단을 묻는다.

## Ⅰ. 개요 및 필요성

- 개요: 지식그래프 기반 RAG 구조
- 배경: 벡터 검색은 문장 유사도 중심이라 엔티티 관계, 영향 범위, 다단 경로 추론을 직접 표현하기 어렵다.
- 필요성: entity extraction, relation extraction, graph traversal, 1~3 hop 검색으로 복합 질문의 근거 경로와 연결성을 검증해야 함.

## Ⅱ. 구조 및 구성요소

```text
문서 -> Entity/Relation Extractor -> Knowledge Graph
질의 -> Entity Linking -> Graph Traversal -> Context -> LLM
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Extractor | 엔티티·관계·속성 추출 | NER, Relation Extraction, LLM 추출 |
| Graph Store | 노드·엣지·속성 저장 | Neo4j Cypher, RDF SPARQL |
| Entity Linking | 질의 엔티티를 그래프 노드와 매핑 | 동의어·약어 정규화 |
| Graph Retriever | k-hop·경로·커뮤니티 검색 | 1~3 hop, 신뢰도 임계값 0.8 |

> 요약: Graph RAG는 문서를 그래프로 구조화하고 질의 엔티티 기준 관계 경로를 탐색해 LLM 근거로 제공함.

## Ⅲ. 동작원리 및 흐름도

```text
문서 수집 -> 엔티티/관계 추출 -> 그래프 적재
질의 입력 -> 엔티티 매핑 -> k-hop 탐색
  -> 경로/커뮤니티 요약 -> LLM 생성 -> 근거 경로 출력
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 문서에서 엔티티·관계 추출 | 추출 F1 ≥ 0.85 |
| 2 | 엔티티 정규화·그래프 적재 | 중복 노드율 < 5% |
| 3 | 질의 엔티티 매핑 후 1~3 hop 탐색 | 경로 신뢰도 ≥0.8 |
| 4 | 경로 요약과 LLM 답변 생성 | 근거 경로 표시율 100% |

> 요약: Graph RAG는 문서->그래프 변환과 질의->관계 경로 탐색을 분리해 복합 관계 기반 답변을 생성함.

## Ⅳ. 특징

| 구분 | Vector RAG | Graph RAG | 판단 포인트 |
|:---|:---|:---|:---|
| 검색 기준 | 의미 유사도 | 엔티티·관계·경로 | 관계 질문은 Graph 우위 |
| 답변 근거 | 청크 출처 | 노드·엣지·경로 | 영향 범위·원인 분석에 적합 |
| 구축 비용 | 청킹·임베딩 중심 | 추출·정규화·그래프DB 필요 | 초기 구축 2~4배 비용 |
| 갱신 | 문서 재색인 | 노드·엣지 증분 갱신 | 관계 변화 추적 필요 |

> 요약: Graph RAG는 구축 비용이 높지만 관계 추론과 영향 분석에서 Vector RAG보다 설명 가능한 근거를 제공함.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | Multi-hop Vector RAG(반복 검색) | Graph RAG | 선택 기준 |
|:---|:---|:---|:---|
| 다중 홉 연결 | 검색-생성 반복으로 홉 연결, 단계별 오류 누적 | 그래프 경로 탐색으로 홉 연결 명시적 | 관계가 스키마로 구조화 가능하면 Graph |
| 전역 질의 대응 | Top-K 청크 한계로 코퍼스 전체 요약 취약 | 커뮤니티 요약으로 전체 주제 질의 대응 | 전체 동향·주제형 질의 비중 높으면 Graph |
| 사전 구축 부담 | 청킹·임베딩만으로 즉시 구축 | 추출·정규화·그래프DB 운영 필요 | 구축 기간·인력 제약 시 반복 검색 우선 |

> 요약: 관계·전역 질의 비중이 높고 스키마 정의가 가능하면 Graph RAG, 신속 구축이 우선이면 벡터 반복 검색을 선택함.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 오추출 관계의 근거화 | LLM 추출 오류, 동명 엔티티 미정규화 | 관계 신뢰도 임계 0.8, 엔티티 정규화 사전 운영 | 추출 F1, 중복 노드율 |
| 그래프 최신성 저하 | 문서 변경분 미반영 | 변경 감지 기반 증분 갱신 파이프라인 | 그래프 갱신 지연 시간 |
| 구축·운영 비용 초과 | LLM 추출 호출량, 그래프DB 운영비 | 핵심 도메인 한정 구축, 배치 추출 | 문서당 추출 비용, 관계 질의 커버리지 |

> 요약: 주요 위험은 오추출 관계가 답변 근거가 되는 것이며, 신뢰도 임계·정규화·증분 갱신으로 통제함.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 장애 영향 분석: CMDB·서비스 문서에서 서비스-API-DB 관계를 추출, 2-hop 영향 범위와 의존 경로 출력
2. 규정·계약 검토: 계약 당사자·의무·위반 조항을 노드화, 관계 신뢰도 0.8 미만 엣지는 검토 큐로 전송
3. 하이브리드 검색: Graph 경로 검색과 Dense 청크 검색을 병합, 관계 경로 3개+근거 청크 5개를 LLM에 주입

**결론 (2줄):**
- 기술사 판단: 관계·영향·원인 경로 질문은 Graph RAG, 단순 문단 검색은 Vector RAG 적용
- 향후 방향: Graph RAG와 Agentic RAG 결합으로 도구 호출 기반 다단계 관계 추론으로 발전
