## 미리 알고가기

- Graph RAG는 문서를 단순 청크 집합이 아니라 개체와 관계 중심의 그래프로 재구성해 검색하는 방식임
- 벡터 RAG가 놓치기 쉬운 multi-hop 관계 질의와 전체 구조 요약에 강점이 있음
- 구축 비용과 운영 복잡도가 높아 적용 범위를 선별해야 함

## Ⅰ. 개요

- **정의/개념**: Graph RAG는 문서에서 entity와 relationship를 추출해 지식 그래프를 구축하고, 그래프 탐색과 요약 정보를 활용해 관계 기반 근거를 생성 모델에 제공하는 고차원 RAG 아키텍처임
- **배경/필요성**: 벡터 RAG는 유사한 문장 조각 검색에는 강하지만 여러 문서에 흩어진 관계를 연결하거나 전체 구조를 설명하는 질문에는 한계가 있어, 관계 중심 검색 구조가 필요함

## Ⅱ. 특징

- multi-hop 질의와 전역 맥락 질의에서 벡터 기반 검색보다 강한 설명력을 가질 수 있음
- entity, relation, community 요약을 이용해 그래프 구조 자체를 근거로 활용함
- 구축 단계에서 문서 전체를 분석하고 정규화해야 하므로 인덱싱 비용이 큼
- 그래프 품질이 낮으면 관계 오염이 누적되어 오히려 잘못된 연결을 강화할 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | Vector RAG | Graph RAG | Hybrid Graph+Vector |
|:---|:---|:---|:---|
| 강점 질의 | 사실 검색 | 관계 추론, 전역 요약 | 혼합형 질의 |
| 인덱싱 비용 | 낮음 | 높음 | 높음 |
| 설명 가능성 | 중간 | 높음 | 높음 |
| 운영 복잡도 | 중간 | 높음 | 매우 높음 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Entity, Relation Extractor | 문서에서 핵심 개체와 관계를 추출해 그래프의 원재료를 만듦 |
| Knowledge Graph Store | 노드와 엣지와 커뮤니티 구조를 저장해 관계 탐색의 기반을 제공함 |
| Graph Traversal, Community Summary | 관련 노드 탐색과 상위 요약을 통해 local과 global 문맥을 함께 제공함 |
| Generator, Evidence Layer | 서브그래프와 요약 근거를 사용해 다단계 관계를 설명하는 답변을 생성함 |

```text
+-------------------+      +-------------------+      +-------------------+
| Entity / Relation | ---> | Knowledge Graph   | ---> | Graph Traversal   |
+-------------------+      +-------------------+      +-------------------+
                                                           |
                                                           v
                                                   +-------------------+
                                                   | Generator / Evid. |
                                                   +-------------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 개체/관계 추출  | --> | 그래프 구축/요약  | --> | 그래프 탐색 검색  | --> | 관계 기반 생성   |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **개체 및 관계 추출**: 문서에서 사람, 조직, 개념과 관계를 추출함
2. **그래프 구축 및 요약**: 노드와 엣지를 저장하고 커뮤니티 수준 요약을 생성함
3. **그래프 탐색 검색**: 질의와 관련된 노드와 경로를 따라 필요한 근거를 수집함
4. **관계 기반 생성**: 서브그래프와 요약을 바탕으로 설명형 답변을 생성함

## Ⅵ. 문제점 및 해결 방안

1. 문제: entity 정규화가 부실하면 같은 개체가 여러 노드로 쪼개져 관계 탐색 품질이 크게 떨어질 수 있음
   - 해결방안: entity resolution 규칙을 운영하고 node merge precision과 relation consistency로 그래프 품질을 검증함
2. 문제: 문서 전체를 그래프로 변환하는 인덱싱 비용이 커서 빈번히 바뀌는 데이터에는 유지비가 과도할 수 있음
   - 해결방안: 정적 핵심 문서군에 우선 적용하고 indexing cost와 graph query gain으로 투자 타당성을 검증함
3. 문제: 그래프 탐색과 생성 조합이 복잡해 운영과 디버깅 난도가 벡터 RAG보다 훨씬 높아질 수 있음
   - 해결방안: vector fallback과 graph-only use case를 분리하고 MTTR와 answer faithfulness로 운영 복잡도를 검증함

## Ⅶ. 적용 사례

- 규제와 법률 문서 분석이 조항 간 연결 관계를 추적하도록 Graph RAG를 적용하며 확인 지표는 multi-hop QA accuracy와 citation quality임
- 위협 인텔리전스 분석이 공격자와 인프라와 이벤트 관계를 연결하도록 Graph RAG를 활용하며 확인 지표는 relation recall과 analyst productivity임
- 연구 지식 탐색이 논문 개념과 인용 관계를 구조화하도록 Graph RAG를 적용하며 확인 지표는 insight discovery rate와 answer explainability임

## Ⅷ. 결론

Graph RAG는 유사 문장 검색을 넘어 관계 기반 지식 탐색으로 확장한 구조이므로, 전체 코퍼스의 관계성이 실제 가치로 이어지는 도메인에서 선택해야 효과가 큼.
