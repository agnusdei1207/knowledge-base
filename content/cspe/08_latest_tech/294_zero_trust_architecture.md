# 📖 【암기용】 개념 완전 이해

> 목적: 제로트러스트 아키텍처를 내부망을 믿지 않는 구호가 아니라, 사용자·단말·애플리케이션·데이터에 대해 매 요청마다 정책 판단과 집행을 수행하는 보안 구조로 이해하게 만든다.

## 한눈에
- **개요**: 네트워크 위치를 신뢰 기준으로 삼지 않고 모든 접근을 명시적으로 검증하는 보안 아키텍처
- **왜 필요한가**: 클라우드, 원격근무, SaaS, 협력사 접속에서는 내부망과 외부망 경계가 접근 통제 기준으로 부족하다.
- **핵심 직관**: 회사 정문을 통과했더라도 회의실, 금고, 전산실은 매번 신원과 권한을 확인하는 방식이다.

## 깊이 이해
- **배경·문제의식**: 기존 경계 보안은 내부망 침투 이후 횡적 이동을 막기 어렵고, SaaS·모바일·클라우드 자산은 사내 방화벽 뒤에만 존재하지 않는다.
- **작동 원리**: Policy Engine이 신원, 단말 상태, 위치, 행동, 자원 민감도를 평가하고 Policy Enforcement Point가 세션별 접근을 허용·차단한다.
- **비유**: 도서관 회원증만 있으면 모든 자료실을 쓰는 것이 아니라, 희귀본 열람실은 별도 승인과 열람 기록을 남기는 것과 같다.
- **구체 예시**: 직원이 CRM에 접속할 때 SSO, MFA, 단말 EDR 상태, 위치, 권한을 확인하고 조건 미충족 시 읽기 전용 또는 차단 정책을 적용한다.
- **흔한 오해·주의점**: 제로트러스트는 특정 제품이 아니다. IAM, 단말 보안, 네트워크 분리, 로그 분석, 데이터 보호를 정책 중심으로 결합한 아키텍처다.

## 연결 개념
- SASE/SSE — 원격 사용자 접근 집행 구조
- IAM/MFA — 신원 기반 접근 판단의 핵심
- Microsegmentation — 내부 횡적 이동 통제 방식

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.
> 핵심: 제로트러스트는 "절대 신뢰 없음" 문구가 아니라 정책 엔진, 정책 관리자, 정책 집행 지점으로 매 요청을 검증하는 구조다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Zero Trust Architecture는 네트워크 위치와 무관하게 모든 접근을 명시적으로 검증하고 최소권한으로 허용하는 보안 아키텍처임.
> 2. **가치**: 원격근무·SaaS·클라우드 환경에서 계정 탈취와 내부 횡적 이동의 영향을 세션·자원 단위로 제한함.
> 3. **판단 포인트**: 신원, 단말 상태, 정책 엔진, 집행 지점, 지속 모니터링, 로그 기반 정책 갱신을 함께 설계해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 보안 패러다임 이해 확인 | 경계 보안에서 자원 중심 접근 통제로 전환 | 내부망 불신 구호만 작성 |
| NIST 구조 이해 확인 | Policy Engine, Policy Administrator, Policy Enforcement Point | MFA 제품 도입으로 축소 |
| 적용 설계 역량 확인 | 자산 식별, 최소권한, 연속 평가, 로그 분석 | 전사 일괄 차단 정책으로 오해 |

> 요약: 이 문제는 제로트러스트 원칙을 실제 접근 판단 구조와 운영 절차로 바꾸는 능력을 본다.

---

## Ⅰ. 개요 및 필요성

- 개요: 모든 접근 명시 검증
- 배경: 클라우드와 원격근무 확산으로 내부망 경계가 사용자·단말·애플리케이션 위치를 대표하지 못함.
- 필요성: 계정 탈취, 악성 단말, 내부 횡적 이동을 자원·세션 단위 정책으로 제한해야 함.

---

## Ⅱ. 구조 및 구성요소

```text
Subject / Device -> Policy Enforcement Point -> Resource
  +-> Policy Engine -> Policy Administrator -> Enforcement Decision
  +-> Identity / Device / Threat / Log Data
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Policy Engine | 접근 허용 여부 판단 | 신원·단말·위험 점수 반영 |
| Policy Administrator | 접근 세션 생성·폐기 지시 | 토큰·프록시·터널 제어 |
| Policy Enforcement Point | 실제 접근 허용·차단 집행 | ZTNA, gateway, agent |
| Telemetry | 정책 판단 데이터 제공 | 로그, EDR, SIEM, UEBA |

> 요약: 제로트러스트는 정책 판단, 정책 관리, 집행 지점, telemetry가 결합되어 세션별 접근을 제어한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
접근 요청 -> 신원 / 단말 / 자원 민감도 확인
-> 정책 엔진 판단 -> 집행 지점 허용 / 차단
-> 세션 감시 -> 로그 분석 -> 정책 갱신
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 사용자·서비스 계정과 단말 상태 확인 | MFA, EDR health |
| 2 | 자원 민감도와 요청 맥락 평가 | data classification |
| 3 | 정책 엔진이 최소권한 접근 결정 | allow, deny, step-up |
| 4 | 세션 로그와 이상행위로 정책 보정 | audit trail, UEBA |

> 요약: 제로트러스트는 접근 전 검증과 접근 중 감시를 결합해 정책을 계속 보정한다.

---

## Ⅳ. 특징

| 구분 | 경계 보안 | Zero Trust Architecture | 판단 기준 |
|:---|:---|:---|:---|
| 신뢰 기준 | 내부망 위치 | 신원·단말·맥락 | 원격·SaaS 비중 |
| 접근 단위 | 네트워크 구간 | 자원·세션 단위 | 데이터 민감도 |
| 권한 | 접속 후 넓은 권한 | 최소권한·조건부 접근 | 역할·속성 정책 |
| 감시 | 경계 장비 로그 | 전 구간 telemetry | SIEM·EDR 연계 |

> 요약: 제로트러스트는 네트워크 위치 대신 자원 접근 맥락을 기준으로 권한을 좁게 부여한다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | VPN으로 내부망 접속 | ZTNA로 앱 단위 접속 | 원격 사용자 수 |
| 비용 | 경계 장비 중심 | IAM·EDR·로그 통합 비용 | 기존 보안 도구 성숙도 |
| 운영 | 네트워크 ACL 관리 | 정책 기반 접근 관리 | 자산·계정 목록 정확도 |

> 요약: 제로트러스트는 자산과 계정 식별이 선행될 때 정책형 접근 통제로 효과를 낸다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 업무 차단 | 과도한 초기 정책 | 모니터링 모드 후 단계 적용 | false deny |
| 사각지대 | 미등록 자산·계정 | CMDB·IdP 정합성 점검 | unmanaged asset |
| 정책 복잡도 | 역할·속성 중복 | 정책 표준과 예외 만료일 | policy exception |

> 요약: 적용 리스크는 과차단, 미등록 자산, 정책 복잡도이며 단계 적용과 자산 정합성으로 줄인다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 신원 보장 | MFA 적용 범위 확대 | IdP 리포트 |
| 최소권한 | 과다 권한 계정 감소 | 권한 리뷰 |
| 탐지 | 이상행위 탐지와 대응 시간 관리 | SIEM·SOAR 기록 |

> 요약: 제로트러스트 성과는 제품 설치 수가 아니라 MFA 적용, 권한 축소, 이상행위 대응 지표로 판단한다.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 사용자, 단말, 애플리케이션, 데이터 자산 목록을 정리하고 중요 업무부터 ZTNA·조건부 접근을 적용함.
2. IdP, MFA, EDR, SIEM, PAM을 정책 엔진 입력으로 연계해 신원·단말·위험 점수 기반 접근을 구성함.
3. 초기에는 모니터링 모드로 정책 오탐을 줄이고, 예외 권한에 만료일과 승인자를 지정함.

**결론 (2줄):**
- 기술사 판단: SaaS·원격근무·클라우드 업무 비중이 높으면 VPN 중심보다 ZTA 기반 앱 단위 접근이 타당함.
- 향후 방향: 제로트러스트는 SASE/SSE, microsegmentation, AI 기반 이상행위 분석과 결합해 정책 자동화로 발전함.
