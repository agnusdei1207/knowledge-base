# 📖 【암기용】 개념 완전 이해

> 목적: 제로트러스트 아키텍처(ZTA)를 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: "아무도 믿지 마라(Never Trust, Always Verify)"는 원칙하에, 내외부 어디에 있든 신원을 철저히 검증하고 최소한의 권한만 주는 보안 모델
- **왜 필요한가**: 예전엔 성벽(방화벽)만 잘 쌓으면 안쪽 사람은 믿었지만, 이제는 재택근무나 클라우드 때문에 성벽의 의미가 없어졌다. 내부자 공격이나 해킹된 계정의 위협이 더 커졌기 때문이다.
- **핵심 직관**: "출입증을 목에 걸고 있어도, 매번 문을 열 때마다 지문을 찍고 누구인지 확인받는 시스템"

## 깊이 이해
- **배경·문제의식**: 기존 경계 보안(Perimeter Security)은 한 번 뚫리면 내부 망 전체가 위험해지는 '성곽과 해자' 모델이다. 클라우드, 모바일, SaaS 도입으로 기업 데이터가 사방으로 흩어지면서 새로운 보안 패러다임이 필요해졌다.
- **작동 원리 (7대 원칙 - NIST SP 800-207)**:
    1. **모든 자원은 데이터 소스/컴퓨팅 서비스**로 간주.
    2. **네트워크 위치와 상관없이 모든 통신 보안**.
    3. **개별 세션 단위로 자원 접근 권한 부여**.
    4. **동적 정책 기반** (신원, 기기 상태, 행위 등 반영).
    5. **모든 기기의 자산 상태 감시 및 측정**.
    6. **자원 접근 전 인증/인가** 강제.
    7. **상태 정보를 최대한 수집**하여 보안 개선.
- **비유**: 예전 보안은 아파트 단지 입구만 지키는 경비원이라면, 제로트러스트는 엘리베이터 탈 때, 복도 지날 때, 현관문 열 때마다 각각 카드키를 찍고 얼굴을 대조하는 것과 같다.
- **구체 예시**: 구글의 BeyondCorp (사내 망 없이 인터넷만으로 업무 가능), 멀티팩터 인증(MFA) 사용, 접속 위치가 갑자기 바뀌면 접근 차단.
- **흔한 오해·주의점**: "특정 제품 하나를 사면 끝"이 아니다. 아키텍처이자 철학이다. VPN을 없애고 소프트웨어 정의 경계(SDP)를 도입하는 등 전반적인 체계를 바꿔야 한다.

## 연결 개념
- SDP (Software Defined Perimeter) — 사용자-자원 간 1:1 논리적 보안 경계 형성
- MFA (Multi-Factor Authentication) — 지식·소유·생체 정보를 조합한 강력한 인증
- Micro-segmentation — 네트워크를 아주 작은 단위로 쪼개어 공격 이동을 차단

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 경계 보안의 한계를 극복하기 위해 신원(Identity) 기반의 지속적 검증과 최소 권한 부여 체계(ZTA)를 논리적으로 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Zero Trust Architecture(ZTA)는 네트워크 위치에 관계없이 모든 사용자, 단말, 접속 시도를 신뢰하지 않고 지속적으로 검증하는 정보보호 전략이다.
> 2. **가치**: 신원 기반의 세분화된 접근 통제(Micro-segmentation)를 통해 침해 사고 시 피해 범위(Blast Radius)를 최소화하고 횡적 이동(Lateral Movement)을 차단한다.
> 3. **판단 포인트**: NIST SP 800-207의 7대 원칙을 기반으로 인증(IAM), 자산(Device), 가시성(Analytics)이 통합된 동적 정책 엔진이 핵심이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| ZTA의 철학 및 등장 배경 이해 | Never Trust, Always Verify / 경계 보안의 한계 | 단순히 '방화벽 강화' 수준으로 기술 시 감점 |
| NIST SP 800-207 논리 구조 파악 | 정책 결정 포인트(PDP) 및 정책 실행 포인트(PEP) | 기술적 요소만 나열하고 논리적 아키텍처 부재 |
| ZTA 구현 핵심 기술 인지 | SDP, MFA, IAM, Micro-segmentation | 한 가지 기술(예: MFA)에만 치우친 답안 경계 |

> 요약: 신뢰의 대상을 고정된 위치(Inside)에서 가변적인 신원(Identity)으로 전환하는 아키텍처 설계 역량을 평가한다.

## Ⅰ. 개요 및 필요성

- 정의: "신뢰는 결함이다"라는 전제하에, 모든 접근 요청을 매번 검증하고 최소 권한(Least Privilege)을 부여하는 보안 체계
- 배경: 클라우드·하이브리드 업무 환경 확산으로 경계가 모호해짐(De-perimeterization) 및 내부자 위협 증가
- 필요성: 랜섬웨어 등 고도화된 위협의 횡적 이동 차단, 클라우드 자산의 가시성 확보, 컴플라이언스 준수 강화

## Ⅱ. 구조 및 구성요소

```text
[ 제로트러스트 논리 구조 ]
사용자/기기 -> [ PEP (정책 실행) ] -> [ 자원/데이터 ]
                    ^
                    | (신뢰 여부 결정)
           [ PDP (정책 결정) ]
             /            \
    [ 신원(IAM) ] [ 기기상태(EDR) ] [ 위협정보 ]
```

| 구성요소 | 역할 | 세부 기술 |
|:---|:---|:---|
| 정책 결정 포인트 (PDP) | 인증/인가 여부를 최종 판단하는 두뇌 | 정책 엔진(PE), 정책 관리자(PA) |
| 정책 실행 포인트 (PEP) | PDP의 결정에 따라 자원 접근을 제어 | 게이트웨이, 에이전트, 방화벽 |
| 신원 관리 (IAM) | 사용자 및 엔터티의 신원 검증 | MFA, Single Sign-On (SSO), FIDO |
| 엔드포인트 보안 | 접속 단말의 위협 및 무결성 상태 확인 | EDR, MDM, 상태 측정(Attestation) |

> 요약: PDP에서 정책을 결정하고 PEP에서 이를 실행하며, 신원과 기기 상태를 지속적으로 모니터링한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
접속 요청 -> 신원/기기 인증 -> 동적 위험 평가 -> 최소 권한 세션 할당 -> 지속적 감사/로깅 -> 세션 종료
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 접속 요청 및 인증 | MFA를 통한 다중 인증 및 기기 무결성 체크 |
| 2 | 상황 기반 정책 평가 | 접속 시간, 위치, IP, 과거 행위 패턴 분석 |
| 3 | 마이크로 세그멘테이션 | 요청한 특정 자원에 대해서만 1:1 터널링 (SDP) |
| 4 | 지속적 검증 (Continuous) | 세션 유지 중에도 기기 상태 변화 시 즉시 차단 |

> 요약: 한 번의 인증으로 끝나는 것이 아니라, 세션이 유지되는 동안 '상황적 맥락'을 고려하여 끊임없이 의심하고 검증한다.

## Ⅳ. 특징

| 구분 | 경계 기반 보안 (Legacy) | 제로트러스트 보안 (ZTA) |
|:---|:---|:---|
| 신뢰 기준 | 네트워크 위치 (내부/외부) | 신원 및 맥락 (Identity / Context) |
| 권한 부여 | 관대한 권한 (세그먼트 단위) | 최소 권한 (자원/세션 단위) |
| 연결 방식 | VPN (인프라 공개 후 접속) | SDP (인프라 은닉 후 선인증) |
| 가시성 | 경계 트래픽 중심 | 전 영역(사용자, 기기, 네트워크) |

> 요약: "먼저 연결하고 나중에 검증"하던 방식을 "먼저 검증하고 나중에 연결"하는 방식으로 전환한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | VPN (Virtual Private Network) | SDP (Software Defined Perimeter) | 선택 기준 |
|:---|:---|:---|:---|
| 보안성 | IP 노출, 횡적 이동 가능 | IP 은닉(Black Cloud), 횡적 이동 불가 | 보안 요구 수준 (금융, 국방 등) |
| 확장성 | 하드웨어 기반, 확장성 한계 | 클라우드 네이티브, 유연한 확장 | 대규모 재택근무 수용 필요성 |
| 사용자 경험 | 접속 속도 저하, 잦은 끊김 | 상대적으로 빠른 연결 및 투명성 | 임직원 업무 생산성 중시 여부 |

> 요약: 기존 VPN의 취약점을 해결하기 위해 인프라를 외부에서 보이지 않게 숨기는 SDP가 ZTA의 핵심 기술로 부상하고 있다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 사용자 불편 증가 | 잦은 인증 요구로 생산성 저하 | 무자각 인증, 행위 기반 지속 인증 도입 | 인증 성공/실패율, 작업 지연 시간 |
| 구축 복잡성 | 기존 레거시 시스템과의 호환성 결여 | 단계적 전환 로드맵 수립, API 연동 강화 | 시스템 통합률, 적용 워크로드 비중 |
| 중앙 제어 실패 | PDP/PEP 장애 시 전체 인프라 마비 | 고가용성(HA) 구성, 비상 접속 모드 마련 | 가동률(Uptime), MTTR (복구 시간) |

> 요약: 운영 편의성과 보안성 사이의 균형이 중요하며, 단계적인 도입과 자동화된 정책 관리가 필수적이다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 인증 강도 | MFA 적용률 100% | 계정 관리 시스템 로그 분석 |
| 권한 최소화 | 미사용 권한 제거율 90% 이상 | 권한 매트릭스 및 실제 사용 이력 비교 |
| 위협 탐지 속도 | 비정상 접근 차단 시간 < 10초 | 시뮬레이션 기반 자동 차단 성능 측정 |

> 요약: 도입 효과는 인증 수준, 권한 최적화 정도, 그리고 실시간 위협 대응 속도로 평가한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. **재택근무**: VPN을 대체하여 SDP 기반으로 인터넷상에서 사내 시스템에 안전하게 접속, 기기 보안 상태에 따라 접근 차등화
2. **클라우드 운영**: 멀티 클라우드 환경에서 통합 IAM을 통해 개발자의 자원 접근 권한을 마이크로 단위로 제어하고 모든 로그 기록
3. **공급망 보안**: 외부 협력업체가 사내 시스템 접속 시 특정 시간, 특정 서버에 대해서만 일회성 접근 권한 부여 (JIT: Just-In-Time)

**결론 (2줄):**
- 기술사 판단: ZTA는 단일 솔루션이 아닌 '정보보호의 현대적 체계'이며, 기업의 자산 가치에 따른 성숙도 모델(Maturity Model) 기반의 단계적 이행이 성공의 핵심이다.
- 향후 방향: AI/ML을 결합하여 사용자의 일상적 행위 패턴을 학습하고, 비정상 징후를 스스로 탐지하여 정책을 실시간 변경하는 '자율 보안(Autonomous Security)'으로 진화할 것이다.
