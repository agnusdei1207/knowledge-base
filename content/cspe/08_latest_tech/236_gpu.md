# 📖 【암기용】 개념 완전 이해

## 한눈에
- **정의**: 수백~수만 개의 단순한 코어를 집적하여, **수백만 개의 픽셀이나 숫자를 한 번에 동시 다발적으로 계산하는 데 특화된 '초병렬(Parallel)' 연산 장치**.
- **필요성**: CPU는 조건문(if-else), 복잡한 시스템 제어 등을 똑똑하게 처리하는 데는 세계 최고지만, 1억 개의 단순한 덧셈을 시키면 한 줄씩 차례대로 하느라 한 세월이 걸림. 화면의 수백만 픽셀 색상을 동시에 바꾸거나, 딥러닝 행렬을 동시에 곱하려면 "머리는 나빠도 손발이 엄청나게 많은 일꾼"이 수만 명 필요했음.
- **핵심 직관**: 대학교수 4명(CPU 코어) vs 초등학생 10,000명(GPU 코어). 아주 어려운 미적분 증명 1문제를 풀려면 대학교수 4명이 훨씬 빠르고 정확함. 하지만 "1+1" 같은 쉬운 덧셈 문제 1억 개를 풀라고 하면, 초등학생 10,000명에게 1만 개씩 나눠주고 동시에 풀게 하는 것이 압도적으로 빠름. 딥러닝 연산이 바로 이 덧셈/곱셈의 무한 반복임.

## 깊이 이해
- **배경**: 1990년대, 3D 게임이 발전하면서 모니터 화면의 수백만 픽셀 좌표와 색상을 실시간으로 계산(행렬 연산)해야 했음. 이를 위해 엔비디아가 GPU라는 개념을 만듦. 2012년, 알렉스넷(AlexNet)을 만든 연구자가 "어라? 딥러닝 가중치 곱하는 게 게임 픽셀 연산이랑 똑같은 단순 행렬 곱셈이네?"라며 GPU를 AI 학습에 써봤고, CPU로 몇 달 걸리던 걸 며칠 만에 끝내면서 AI 혁명이 터짐.
- **작동 원리 (SIMT와 텐서 코어)**:
  1. **SIMT (Single Instruction, Multiple Threads)**: 하나의 명령어를 수천 개의 쓰레드(일꾼)에게 동시에 내림. "다 같이 앞의 숫자 두 개 더해라!"
  2. **Streaming Multiprocessor (SM)**: 코어 수십 개를 묶어 놓은 작업 반장 그룹. 이 SM이 GPU 내부에 수십~수백 개 박혀 있음.
  3. **Tensor Core (텐서 코어)**: 게임용이 아니라 오직 AI를 위해 만든 특수 코어. 한 번의 클럭에 4x4 행렬 곱셈을 통째로 해치우는 AI 치트키.
- **구체 예시**: 자율주행차의 영상 인식. 1초에 60번씩 들어오는 카메라 영상에서 보행자 수천 명의 특징을 동시에 추출해야 함. CPU가 하면 차가 보행자를 치고 난 뒤에 계산이 끝남. GPU가 수만 개의 코어로 동시에 화면을 분할 계산해야 브레이크를 제때 밟을 수 있음.
- **흔한 오해/주의점**: "AI 가속기로 NPU, TPU 나오면 GPU는 끝물 아닌가?" $\rightarrow$ 아님. GPU의 무서움은 하드웨어 스펙이 아니라 **'CUDA(쿠다)'**라는 막강한 소프트웨어 생태계에 있음. 전 세계 거의 모든 AI 개발자가 CUDA 언어로 코딩하는데, 이건 엔비디아 GPU에서만 돎. 범용성 + 생태계 락인(Lock-in) 때문에 당분간 GPU의 철옹성은 무너지기 힘듦.

## 연결 개념
- **CPU (Central Processing Unit)**: GPU의 영원한 파트너. GPU는 스스로 OS를 돌리거나 마우스 클릭을 인식하지 못하므로 CPU가 명령을 떠먹여 줘야 함.
- **CUDA**: 엔비디아 GPU를 딥러닝 연구자들이 쉽게 쓸 수 있게 만든 C언어 기반의 마법의 프로그래밍 인터페이스.
- **GPGPU (General-Purpose GPU)**: GPU를 원래 목적인 '그래픽(게임)'에 안 쓰고, AI 연산이나 암호화폐 채굴 같은 '일반 연산'에 써먹는 기술 패러다임.

# 📝 【답안용】 시험 답안 템플릿
## 핵심 인사이트 (3줄 요약)
- **본질**: 복잡한 제어 흐름(Control Flow) 대신 데이터 수준의 병렬성(Data Parallelism)을 극대화하기 위해, 수천 개의 ALU(산술논리연산장치)를 고집적한 SIMT(Single Instruction Multiple Threads) 아키텍처 기반의 컴퓨팅 가속기.
- **가치**: 딥러닝 텐서(Tensor) 연산의 본질인 대규모 행렬 곱셈-누산(MAC)을 CPU 대비 수십~수백 배 빠르게 처리하여, AI 모델의 학습 기간(Time-to-Train)을 비약적으로 단축시킨 4차 산업혁명의 핵심 엔진.
- **판단 포인트**: 현대 GPU의 가치는 단순 코어 수의 확장을 넘어, AI 특화 연산기(Tensor Core), 메모리 병목을 해소하는 초고속 메모리 패키징(HBM), 그리고 다중 GPU 간의 스케일 아웃을 지원하는 인터커넥트(NVLink) 기술의 종합적 결합에서 발현됨.

## Ⅰ. 개요 및 필요성
- **정의**: 그래픽 파이프라인의 정점/픽셀 처리를 위해 개발된 초병렬 연산기 구조를 활용하여, 벡터 및 행렬 기반의 수치 해석 알고리즘(GPGPU)을 고속으로 처리하는 이종(Heterogeneous) 프로세서.
- **배경**: 무어의 법칙 한계 및 CPU의 클럭 속도 정체 현상 도래. 딥러닝의 부흥으로 부동소수점(Floating Point) 연산량 요구치가 1년마다 10배씩 폭증.
- **필요성**: 파운데이션 모델(LLM 등) 거대화에 따른 컴퓨팅 바운드(Compute-bound) 문제 해결, 대용량 멀티미디어 실시간 처리, 고성능 컴퓨팅(HPC) 시스템의 핵심 TFLOPS 확보.

## Ⅱ. CPU vs GPU 아키텍처 패러다임 대조
명령어 지향 vs 데이터 지향.
| 아키텍처 구분 | CPU (Central Processing Unit) | GPU (Graphics Processing Unit) |
|:---:|:---|:---|
| **설계 철학** | **Low Latency (저지연)**. 한 명령을 가장 빠르게 완료 | **High Throughput (고처리량)**. 많은 데이터를 한 번에 완료 |
| **코어(Core) 구성** | 10~128개의 거대하고 똑똑한 코어 (ALU 비중 낮음) | 5,000~10,000개 이상의 단순 코어 (ALU 비중 압도적) |
| **메모리 / 제어기** | 거대한 캐시(L3)와 복잡한 분기 예측(Branch Prediction) 유닛 보유 | 매우 작은 캐시, 수많은 레지스터 파일, 단순한 제어부 |
| **주요 워크로드** | OS 운영, DB 트랜잭션, 분기 로직이 많은 순차 작업 | 3D 렌더링, 딥러닝 행렬 곱, 암호 해독, 날씨 시뮬레이션 |

## Ⅲ. 엔비디아 GPU 아키텍처의 3대 핵심 구성요소
딥러닝을 지배하게 만든 구조적 혁신.
1. **SM (Streaming Multiprocessor)**:
   - GPU 연산의 기본 빌딩 블록. 1개의 GPU 칩 안에 수십~수백 개의 SM이 탑재되며, 각 SM 안에는 수십 개의 쿠다 코어(CUDA Core)와 레지스터가 빽빽하게 들어차 스레드 블록을 독립적으로 실행.
2. **Tensor Core (텐서 코어)**:
   - Volta 아키텍처부터 탑재된 AI 전용 연산 유닛. 기존 1차원(스칼라) 연산을 넘어, 4x4 행렬 곱셈-누산을 1클럭 사이클에 동시 처리하는 하드웨어 치트키. FP16, FP8 등 혼합 정밀도(Mixed Precision) 지원으로 대역폭 소모를 반감시킴.
3. **HBM (High Bandwidth Memory)**:
   - GDDR 계열 메모리의 물리적 대역폭 한계(Memory Wall)를 돌파하기 위해 도입. 칩 다이(Die) 바로 옆에 D램을 실리콘 관통 전극(TSV)으로 수직 적층하여 초당 수 TB(테라바이트)의 데이터 공급망 확보.

## Ⅳ. GPGPU 프로그래밍 패러다임 (CUDA 및 실행 흐름)
하드웨어를 깨우는 소프트웨어.
- **CUDA (Compute Unified Device Architecture)**: C/C++ 기반으로 작성된 코드를 컴파일하여, CPU(Host)와 GPU(Device) 간의 데이터를 이동시키고 커널(Kernel) 함수를 실행시키는 엔비디아 독점 생태계.
- **실행 흐름 (Execution Flow)**:
  1. **Data Copy**: 호스트(CPU)의 메인 메모리(RAM)에 있는 학습 데이터를 PCIe 버스를 통해 GPU의 VRAM으로 복사.
  2. **Kernel Launch**: CPU가 GPU에게 수만 개의 스레드(Thread)를 생성하도록 병렬 처리 함수(커널) 호출.
  3. **SIMT Execution**: 수십 개의 워프(Warp, 32개 스레드 묶음)가 각 코어에서 동시에 동일한 명령어(행렬 곱 등) 수행.
  4. **Data Return**: 연산이 끝난 결과 값을 다시 CPU 메모리로 복사하여 회수.

## Ⅴ. 실무 적용 및 결론
- **판단 지표**: 연산 강도(Arithmetic Intensity) 최적화 상태, GPU 활용률(SM Utilization > 80% 목표), 호스트-디바이스 간 I/O 병목 여부, 와트당 성능(TFLOPS/W).
- **실무 설계**: 클라우드 기반 추천 엔진 서빙 아키텍처 효율화. 기존 CPU 서버 수백 대로 돌리던 협업 필터링(Collaborative Filtering) 행렬 분해 연산의 지연 시간(Latency)이 500ms에 달함. 조치 방안: Nvidia A10 GPU가 탑재된 인스턴스(Triton Inference Server) 도입 및 커널 최적화. 1) 수천 명의 유저 요청을 잘게 쪼개어(Micro-batching) 한 번에 GPU로 밀어 넣는 배치 파이프라인 구성. 2) FP32로 학습된 모델 가중치를 TensorRT를 통해 FP16(반정밀도)으로 양자화하여 Tensor Core 강제 활성화. 결과적으로 응답 속도 20ms 이내 단축 및 서버 유지 비용(TCO) 60% 절감.
- **결론**: GPU는 본래 화면의 삼각형을 색칠하기 위해 태어났으나, 그 태생적인 초병렬 아키텍처 덕분에 우연히 딥러닝 연산과 완벽히 교집합을 이루며 IT 역사의 흐름을 바꿨다. 향후 GPU 시장은 코어 집적도 싸움을 넘어설 것이다. 단일 칩의 한계를 돌파하기 위한 GPU 간 초고속 연결 기술(NVLink), 그리고 메모리 내부에서 직접 연산하는 PIM(Processing In Memory) 아키텍처와의 융합이 차세대 GPU의 패권을 결정짓는 승부처가 될 것이다.

### 🔀 문제 유형별 목차 전환
- **Ⅱ·Ⅲ 강조 (개념/원리형)**: 메모리 계층 구조(Memory Hierarchy)에 따른 병목 지점 및 최적화 기법. Global Memory $\rightarrow$ L2 Cache $\rightarrow$ L1/Shared Memory $\rightarrow$ Register로 이어지는 데이터 접근 비용(Latency) 구조 분석 및 Shared Memory의 명시적 활용(Memory Coalescing) 코딩 기법.
- **Ⅴ·Ⅵ 강조 (실무/설계형)**: 단일 GPU 메모리 용량을 초과하는 거대 모델 다중 가속기 토폴로지. 80GB 메모리에 175B(GPT-3 등) 모델을 올리기 위한 모델 병렬화(Model Parallelism), 텐서 병렬화, ZeRO(Zero Redundancy Optimizer) 메모리 최적화 등 훈련 인프라 스케일 아웃(Scale-out) 아키텍처 제안.
