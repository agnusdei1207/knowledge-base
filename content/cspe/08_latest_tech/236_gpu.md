# 📖 【암기용】 개념 완전 이해

> 목적: GPU를 그래픽 처리 장치에서 AI·과학계산의 대규모 병렬 처리 장치로 확장된 컴퓨팅 가속기로 이해하게 만든다.

## 한눈에
- **개요**: 수천 개 병렬 연산 유닛과 고대역 메모리로 동일 연산을 대량 데이터에 수행하는 프로세서
- **왜 필요한가**: AI 학습·추론은 행렬곱과 벡터 연산이 많아 CPU보다 데이터 병렬 처리량이 큰 장치가 필요하다.
- **핵심 직관**: 한 명의 숙련공이 복잡한 일을 처리하는 CPU와 달리, GPU는 많은 작업자가 같은 단순 작업을 동시에 처리하는 공장이다.

## 깊이 이해
- **배경·문제의식**: 그래픽 렌더링은 픽셀·정점에 같은 연산을 반복하므로 GPU는 초기에 대량 병렬 구조로 발전했다.
- **작동 원리**: CUDA core 또는 stream processor가 warp/wavefront 단위 SIMT로 동작하고 Tensor Core가 행렬 연산을 가속한다.
- **비유**: 여러 계산원이 같은 할인 규칙을 각자 다른 장바구니에 동시에 적용하는 구조와 같다.
- **구체 예시**: LLM 추론 서버는 GPU HBM에 모델 가중치를 올리고 Tensor Core로 FP16/BF16/FP8 행렬곱을 수행해 tokens/sec를 높인다.
- **흔한 오해·주의점**: GPU는 모든 코드를 빠르게 처리하지 않는다. 분기 많은 코드, 작은 batch, 메모리 불규칙 접근은 GPU 활용률이 낮다.

## 연결 개념
- GPU Cluster — 여러 GPU 노드를 묶은 AI 인프라
- GPU SIMT — GPU 실행 모델의 핵심
- AI Accelerator — GPU가 속한 상위 하드웨어 범주

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.
> 핵심: GPU 답안은 SIMT, Tensor Core, HBM, 메모리 대역폭, 분기 발산을 함께 제시해야 한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: GPU는 대규모 스레드 병렬성과 고대역 메모리로 데이터 병렬 연산을 처리하는 프로세서임.
> 2. **가치**: AI 행렬곱, 그래픽, 과학계산에서 CPU 대비 높은 throughput과 GPU cluster 확장을 제공함.
> 3. **판단 포인트**: batch size, memory bandwidth, branch divergence, tensor core 활용률이 GPU 적용 효과를 좌우함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| GPU 구조 이해 확인 | SM/CU, SIMT, HBM, Tensor Core | 코어 수만 나열 |
| AI 적용 판단 확인 | 행렬곱·attention·batch 처리 | 모든 workload에 적합하다고 단정 |
| 병목 인식 확인 | memory bandwidth, branch divergence | 메모리·분기 병목 누락 |

> 요약: 이 문제는 GPU를 범용 CPU와 다른 병렬 처리 구조로 설명하고 적용 한계를 구분해야 한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 대량 데이터 병렬 처리 프로세서
- 배경: AI·그래픽 연산은 동일 수식을 많은 데이터에 반복 적용하므로 대규모 병렬 실행 구조가 필요함.
- 필요성: tokens/sec, TFLOPS, HBM bandwidth, p95 latency 기준으로 CPU와 GPU 역할을 분리해야 함.

---

## Ⅱ. 구조 및 구성요소

```text
CPU Host -> PCIe/NVLink -> GPU SM/CU -> CUDA Core/Tensor Core -> Register/Shared Memory -> L2 -> HBM/GDDR
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| SM/CU | 스레드 블록 실행 단위 | warp/wavefront scheduler 포함 |
| CUDA Core/Stream Processor | 일반 병렬 연산 수행 | SIMT 실행 |
| Tensor Core | 행렬곱 전용 연산 | FP16, BF16, INT8, FP8 등 |
| HBM/GDDR | 모델 가중치와 activation 저장 | 메모리 대역폭 병목 가능 |

> 요약: GPU는 SM/CU 내부의 병렬 코어와 Tensor Core가 HBM 메모리 계층과 결합해 대량 텐서 연산을 수행한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
커널 실행 요청 -> 스레드 블록 배치 -> warp 단위 SIMT 실행 -> Tensor Core 행렬 연산 -> HBM 접근 -> 결과 반환
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | CPU가 GPU kernel을 launch | launch overhead |
| 2 | 스레드를 block/warp로 배치 | occupancy |
| 3 | CUDA Core와 Tensor Core가 연산 수행 | tensor core utilization |
| 4 | HBM에서 데이터 로드·저장 | memory bandwidth utilization |

> 요약: GPU는 CPU가 실행을 지시하고 GPU가 warp 단위 병렬 연산과 HBM 접근을 반복해 결과를 만든다.

---

## Ⅳ. 특징

| 구분 | CPU | GPU | 수치 기준 |
|:---|:---|:---|:---|
| 구조 | 소수 고성능 코어 | 다수 병렬 코어 | SM/CU 수 |
| 강점 | 분기·제어·I/O | 데이터 병렬·행렬 연산 | TFLOPS, tokens/sec |
| 한계 | 대규모 행렬 처리량 제한 | 분기 발산·메모리 병목 | occupancy, bandwidth |

> 요약: CPU는 제어 흐름, GPU는 대규모 데이터 병렬 연산에 맞춰 역할을 분리한다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | CPU SIMD | GPU SIMT와 Tensor Core | 대량 데이터 병렬성이면 GPU |
| 비용/성능 | TPU는 행렬곱 특화 | GPU는 범용 병렬 생태계 | 워크로드 다양성과 CUDA 생태계 |
| 운영/위험 | 단일 서버 | GPU cluster 확장 | HBM 용량과 네트워크 필요성 |

> 요약: GPU는 범용 병렬성과 생태계가 필요할 때 선택하고 정형 행렬곱 전용이면 TPU도 비교한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 낮은 활용률 | 작은 batch 또는 CPU 전처리 병목 | batching, data loader 최적화 | GPU utilization |
| 메모리 부족 | 모델·KV cache가 HBM 초과 | tensor parallel, quantization | HBM 사용률 |
| 분기 발산 | warp 내 조건 경로 차이 | branchless algorithm, warp 정렬 | warp efficiency |

> 요약: GPU 리스크는 활용률, HBM 용량, 분기 발산이며 배치·양자화·커널 최적화로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 활용률 | GPU utilization 60% 이상 | DCGM, Nsight |
| 처리량 | tokens/sec 또는 images/sec 목표 | benchmark |
| 지연 | p95 latency SLA 이하 | inference log |

> 요약: GPU 도입 성과는 활용률, 처리량, 지연시간을 함께 측정해야 한다.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 학습·추론 workload의 batch size, HBM 요구량, precision을 측정해 GPU SKU와 수량을 산정함.
2. Tensor Core 사용을 위해 FP16/BF16/FP8 mixed precision과 operator fusion을 적용함.
3. Nsight, DCGM, Prometheus로 utilization, HBM, ECC error, p95 latency를 관측함.

**결론 (2줄):**
- 기술사 판단: GPU는 대량 데이터 병렬성이 크고 CUDA 생태계가 필요한 AI·HPC workload에 선택함.
- 향후 방향: GPU는 HBM 용량 확대, NVLink/NVSwitch, Tensor Core 세대 개선, 전력·냉각 최적화와 함께 발전함.
