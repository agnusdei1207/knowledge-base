# 📖 【암기용】 개념 완전 이해

> 목적: GPU(Graphics Processing Unit) 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 수천 개의 작은 코어를 통해 대량의 데이터를 동시에 처리하는 병렬 연산 장치
- **왜 필요한가**: 원래는 게임 화면(픽셀 연산)을 그리려고 만들었지만, 딥러닝의 핵심인 행렬 연산과 구조가 똑같아서 AI 시대의 주인공이 됨
- **핵심 직관**: "복잡한 미분을 푸는 똑똑한 교수님 1명(CPU) 대신, 덧셈/곱셈만 할 줄 아는 초등학생 수천 명(GPU)이 동시에 달려들어 계산을 끝내는 것"

## 깊이 이해
- **배경·문제의식**: CPU는 직렬 처리(Serial Processing) 방식임. 명령어를 하나씩 순서대로 처리하므로, 수억 개의 숫자를 곱해야 하는 AI 연산에서는 시간이 너무 오래 걸림. 이를 해결하기 위해 단순 연산 코어를 무수히 많이 때려 박은 장치가 GPU임
- **작동 원리**: ① **SIMT 아키텍처**: 하나의 명령어로 여러 데이터(Thread)를 동시에 처리함. ② **계층 구조**: 수십 개의 코어가 모인 SM(Streaming Multiprocessor)이 수십 개 집적됨. ③ **전용 코어**: 최신 GPU에는 AI 연산만 전담하는 '텐서 코어(Tensor Core)'가 별도로 들어있어 행렬 연산 속도를 10배 이상 높임
- **비유**: 1,000평의 밭을 가는데, 엄청나게 크고 강력한 트랙터 1대(CPU)로 한 줄씩 가는 게 아니라, 수천 명의 사람이 각자 삽 한 자루씩 들고(GPU) 한꺼번에 땅을 파는 것
- **구체 예시**: 엔비디아의 H100, A100. 예전에는 모니터 뒤에 꽂는 그래픽카드였지만, 이제는 데이터센터 서버의 핵심 연산 엔진임
- **흔한 오해·주의점**: "GPU가 많으면 무조건 게임이 빨라진다"는 틀렸음. 게임은 CPU 성능도 중요하고, 소프트웨어가 병렬 처리를 지원해야 함. AI 역시 GPU 메모리(VRAM) 용량이 부족하면 아무리 코어가 많아도 모델이 돌아가지 않음

## 연결 개념
- **CUDA**: 엔비디아 GPU에서 C언어처럼 코딩할 수 있게 해주는 소프트웨어 플랫폼
- **Tensor Core**: 딥러닝 행렬 연산에 특화된 GPU 내부의 가속 엔진
- **GPGPU**: 그래픽 외의 일반 목적으로 GPU를 사용하는 기술

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 그래픽 처리를 넘어 **SIMT 아키텍처, 텐서 코어(Tensor Core), 메모리 계층(L1/L2/HBM)**을 중심으로 AI 연산 가속 원리를 기술한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: GPU는 수천 개의 연산 코어를 집적하여 대규모 데이터를 병렬로 처리하는 SIMT(Single Instruction, Multiple Threads) 아키텍처 기반의 가속기이다.
> 2. **가치**: 딥러닝의 핵심인 행렬 곱셈-누산(MAC) 연산을 초고속으로 수행하며, 소프트웨어 생태계(CUDA)를 통해 AI 개발의 표준 플랫폼으로 자리 잡았다.
> 3. **판단 포인트**: 연산 정밀도별 TFLOPS 성능, HBM 메모리 대역폭(Bandwidth), 가속기 간 통신 기술(NVLink)의 성능적 균형이 중요하다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| GPU의 병렬 연산 원리 이해도 확인 | SIMT, SM(Streaming Multiprocessor), Tensor Core | 단순히 코어가 많다는 서술에 그침 |
| 하드웨어 구조적 특징 파악 역량 | 계층적 메모리 구조, 텐서 코어의 행렬 연산 가속 | CPU와의 비교 시 직렬/병렬 키워드 누락 |

> 요약: 대규모 병렬 처리 아키텍처와 AI 특화 유닛(Tensor Core)의 결합을 명시한다.

---

## Ⅰ. 개요 및 필요성

- 정의: 수천 개의 ALU(Arithmetic Logic Unit)를 활용하여 대량의 데이터를 동시에 병렬 처리(Parallel Processing)하는 연산 장치
- 배경: 그래픽 렌더링을 위해 개발되었으나, 딥러닝 연산 구조와의 일치성으로 인해 GPGPU(General-Purpose GPU)로 진화
- 필요성: CPU의 직렬 처리 한계(Latency) 극복, 초당 수조 번의 연산(Throughput) 요구 충족, 모델 학습 시간 단축

---

## Ⅱ. 구조 및 구성요소

```text
[GPU Device]
  |-- [SM: Streaming Multiprocessor] x N
  |     |-- [Cuda Cores] (Scalar Ops)
  |     |-- [Tensor Cores] (Matrix Ops)
  |     `-- [Shared Memory / L1 Cache]
  |-- [Global Memory (HBM/GDDR)]
  `-- [L2 Cache]
```

| 구성요소 | 역할 | 핵심 기술/수치 |
|:---|:---|:---|
| SM (Streaming Multi-processor) | 연산의 최소 독립 수행 단위 | 수십 개의 Core와 Register 집합 |
| 텐서 코어 (Tensor Core) | 4x4 행렬 연산 하드웨어 가속 | 혼합 정밀도(Mixed Precision) 지원 |
| 메모리 컨트롤러 | 외부 VRAM과의 데이터 전송 관리 | HBM3 연동, TB/s급 대역폭 |
| 인터커넥트 | GPU 간 데이터 교환 | NVLink 4.0 (900GB/s) |

> 요약: 다수의 SM과 대용량 공유 메모리, AI 특화 텐서 코어가 집적된 병렬 처리 최적화 구조이다.

---

## Ⅲ. 동작원리 및 흐름도

```text
Kernel Launch (CPU) -> Thread Allocation (GPU) -> Parallel Compute (SIMT) -> Data Sync
(명령어 전달)          (수만 개 스레드 할당)       (동시 연산 수행)            (결과 취합)
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 호스트 CPU에서 GPU 커널 함수 호출 | CPU-GPU 간 데이터 전송(PCIe/CXL) 지연 |
| 2 | 스레드 블록 단위로 각 SM에 자원 할당 | 워프(Warp) 단위 스케줄링 (32 스레드) |
| 3 | SIMT 기반 동일 명령어를 다수 데이터에 적용 | 스레드 발산(Divergence) 최소화 |
| 4 | 연산 결과를 전역 메모리에 저장 및 동기화 | 메모리 응집(Coalescing) 효율 |

> 요약: CPU가 명령을 내리면 GPU가 수만 개의 스레드를 생성하여 병렬로 연산한 뒤 결과를 반환한다.

---

## Ⅳ. 특징

| 구분 | CPU (Central) | GPU (Graphics) | 판단 포인트 |
|:---|:---|:---|:---|
| 처리 방식 | 직렬 (Serial) | 병렬 (Parallel) | Latency vs Throughput |
| 코어 수 | 수십 개 (대형 코어) | 수천~수만 개 (소형 코어) | 연산 밀도 차이 |
| 최적화 | 복잡한 조건문, 제어 흐름 | 단순 반복 연산, 행렬 계산 | 워크로드 특성 |
| 메모리 구조 | 큰 캐시, 낮은 대역폭 | 작은 캐시, 매우 높은 대역폭 | 데이터 전송 속도 중점 |

> 요약: 복잡한 제어는 CPU, 단순 대량 연산은 GPU가 담당하는 이종 컴퓨팅 구조가 표준이다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | FP32 (Full Precision) | FP16/BF16 (Half) | FP8 / INT8 |
|:---|:---|:---|:---|
| 용도 | 고정밀 과학 연산 | 딥러닝 학습 표준 | 딥러닝 추론 최적화 |
| 속도 | 기준 (1x) | 약 2~4배 빠름 | 약 8~16배 빠름 |
| 메모리 점유 | 4 Bytes / Token | 2 Bytes / Token | 1 Byte / Token |

> 요약: 성능 극대화를 위해 학습 시에는 FP16/BF16, 추론 시에는 FP8/INT8 양자화를 적용한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| Memory Bottleneck | 연산 속도 대비 VRAM 전송 지연 | HBM 도입, 커널 퓨전 적용 | GPU Utilization (SM 활성도) |
| Power Consumption | 고집적 코어 가동 시 전력 폭증 | 하이급 전원부, 액체 냉각 | TDP (Thermal Design Power) |
| Communication Latency | 노드 간 데이터 동기화 지연 | NVLink, InfiniBand 활용 | Collective Comm. Time |

> 요약: 메모리 벽(Memory Wall)을 넘기 위해 HBM 대역폭 확장과 소프트웨어 최적화를 병행한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| TFLOPS | 이론적 성능 대비 70% 이상 | 벤치마크 (ResNet, Transformer) |
| VRAM 대역폭 | 2TB/s 이상 (H100 기준) | Bandwidth Test 도구 |
| 연산 효율 | 와트당 성능 (GFLOPS/W) | 전력 측정기 + 성능 로그 |

> 요약: 성능은 단순 스펙이 아닌 실제 워크로드에서의 TFLOPS와 전력 효율로 검증한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. **대규모 언어 모델 학습**: H100 8-GPU 노드를 병렬 연결하여 수조 개 파라미터 모델의 그래디언트 업데이트 가속
2. **실시간 영상 분석**: 다채널 CCTV 영상을 GPU 서버에 입력하여 객체 탐지(YOLO 등)를 밀리초 단위로 수행
3. **가상 데스크톱(VDI)**: GPU 가상화(vGPU) 기술을 적용하여 원격 사용자에게 고사양 그래픽 작업 환경 제공

**결론 (2줄):**
- 기술사 판단: GPU는 AI 하드웨어의 표준이나, 엔비디아의 쿠다(CUDA) 독점에 대응하기 위한 오픈 표준(Triton, ROCm) 경쟁이 심화될 것이다
- 향후 방향: 연산 효율을 넘어 칩 간 광학 연결(CPO)과 메모리 내 연산(PIM) 기술이 결합된 차세대 GPU 아키텍처로 진화할 전망이다
