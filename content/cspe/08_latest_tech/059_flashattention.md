## 미리 알고가기

- 플래시어텐션 ($FlashAttention$): 메모리 계층 구조를 의식하여, GPU 온칩 메모리 SRAM과 대역폭이 좁은 외부 HBM 간의 데이터 전송량을 최소화하는 고속 어텐션 커널 알고리즘임
- 고대역폭 메모리 ($HBM$): GPU 칩 외부의 광대역 메모리로 용량은 크나, 온칩 메모리에 비해 접근 속도(대역폭)가 수십 배 느린 병목 구간임
- 정적 SRAM ($SRAM$): GPU 프로세서 내부의 초고속 레지스터성 온칩 메모리로 용량은 수십 메가바이트 수준으로 작지만 접근 속도가 가장 빠른 기억공간임
- 커널 융합 ($Kernel$ $Fusion$): 행렬 곱, Softmax, 가중합 연산을 단일 CUDA 커널 프로그램으로 물리적 병합하여, 중간 연산 임시 행렬을 HBM에 쓰고 읽는 낭비를 소거하는 최적화임

## Ⅰ. 개요

- **정의/개념**: FlashAttention은 어텐션 연산 시 발생하는 $N \times N$ 크기의 거대한 중간 가중치 행렬을 외부 고대역폭 메모리($HBM$)에 쓰지 않고, 입력 데이터를 타일($Tile$) 블록 단위로 분할하여 초고속 온칩 메모리($SRAM$) 내에서 점진적 Softmax 스케일링 기법을 통해 일괄 누적 연산하는 IO-aware attention 알고리즘임
- **배경/필요성**: 기존 어텐션 연산은 플롭스(FLOPs, 연산 횟수)의 한계보다는, $Q K^T$ 연산 완료 후 생성된 중간 유사도 행렬을 HBM에 계속 쓰고 읽어야 하는 메모리 대역폭 한계($Memory-bound$) 병목으로 인해 칩 성능의 $80\%$ 이상을 낭비하고 있어 개선이 시급했음

## Ⅱ. 특징

- 바닐라 어텐션의 수학적 공식(출력 벡터 값)을 0.0001%의 오차도 없이 고스란히 복제하므로, 모델 재학습이나 정확도 유실 우려가 0%임
- HBM 메모리 입출력 횟수를 대폭 차단하여 시퀀스 길이에 비례해 발생하는 메모리 사용량을 $O(N)$ 선형 수준으로 정돈하며, 학습 속도를 $2 \sim 4$배 가속화함
- 최신 릴리즈 버전인 FlashAttention-3의 경우, GPU 비동기 연산 장치(Warp Group, Hopper Tensor Core)와 파이프라이닝을 결합하여 연산 가동율을 $70\%$ 이상 점유함

## Ⅲ. 종류 및 비교

| 판단 기준 | 기본 어텐션 커널 (PyTorch Vanilla) | 플래시어텐션 (FlashAttention) | 희소/선형 어텐션 (Sparse / Linear) |
|:---|:---|:---|:---|
| **수학적 공식 보존** | 100% 보존 (기준선) | 100% 완벽 보존 (근사치 아님) | 불완전함 (수식을 근사 변형함) |
| **HBM I/O 입출력** | 매우 많음 (중간 $N \times N$ 행렬 매번 적재) | 극도로 낮음 (온칩 연산 후 최종값만 노출) | 매우 적음 |
| **메모리 복잡도** | $O(N^2)$ (시퀀스 제곱 비례로 폭증) | $O(N)$ (선형 메모리 공간만 점유) | $O(N)$ (선형 공간 점유) |
| **가속의 주역** | 무난한 기본 탑재 | 커널 융합 ($Fusion$), 타일링 ($Tiling$) | 차원 축소 및 연산 순서 교체 |

> 요약: 기본형은 단순 연산에, 플래시어텐션은 완벽한 수학적 정합성을 유지한 채 HBM 병목 돌파에, 희소/선형은 정확도 손실을 감수하고 초장문 처리에 적합함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 블록 타일러 ($Tiler$) | 거대한 $Q, K, V$ 행렬을 GPU $SRAM$ 캐시 크기에 알맞은 작은 블록(타일)으로 슬라이싱하는 정비부임 |
| 점진적 소프트맥스 연산기 | 타일 단위로 Softmax 최대값($m_i$)과 분모 합($d_i$)을 갱신해가며 부분합을 누적 계산하는 수학 최적화 레이어임 |
| 커널 융합 제어장치 | 분절된 계산 프로세스들을 단일 GPU 스레드 실행 블록 내로 영구 병합하는 $CUDA$ 스크립트 융합부임 |
| 재계산 백프로프 어댑터 | 역전파($Backprop$) 단계에서 HBM에 보관하지 않은 중간 가중치들을 역연산으로 실시간 재생성하는 역추적기임 |

```text
[ FlashAttention 타일링 및 커널 융합 ]
HBM (Q, K, V) ---> SRAM Tile Load ---> [Fused Kernel: Gemm -> Softmax -> Gemm] ---> HBM (Output Only)
- $N \times N$ 크기의 중간 가중치 행렬을 HBM에 일절 쓰지 않고, SRAM 내부에서 최종 결과만 연산해 HBM에 직송함
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| Q, K, V     | --> | 타일 조각별  | --> | 온칩 내적 및| --> | 최종 결과만 |
| 행렬 타일화 |     | SRAM 적재    |     | Softmax 누적|     | HBM 일괄기록|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **타일링 분기** — 입력된 긴 텍스트의 $Q, K, V$ 행렬을 GPU 내부 $SRAM$ 용량 한계에 밀착하는 작은 타일 블록으로 쪼갬
2. **온칩 전송** — 쪼개진 1번 타일 조각들을 HBM에서 고속 외부 통신망을 통해 $SRAM$ 캐시로 실시간 스트리밍 적재함
3. **통합 온칩 연산** — $SRAM$ 내부에서 타일 간 행렬 곱을 수행하고, 이전 타일의 Softmax 분모/분자 스케일링 계수를 활용해 중간 상태를 보정하며 가중합을 계산함
4. **HBM 직송** — 모든 타일 루프가 끝나 유도된 최종 완성 결과 벡터만을 외부 HBM에 쓰고, SRAM 임시 변수들은 즉시 휘발시킴

## Ⅵ. 실무 적용 및 유의점

1. GPU 아키텍처 세대(예: Ampere A100 vs Hopper H100)와 드라이버 커널 라이브러리 버전에 따라 가속 효율 편차가 매우 심하므로, 반드시 하드웨어 제조사가 배포한 전용 Triton 또는 CUDA 빌드 버전을 벤치마크하고, 초당 처리 토큰 수와 GPU 사용 효율 지표를 검증해야 함
2. 역전파 학습 과정에서 메모리를 아끼기 위해 중간값을 HBM에 안 쓰는 대신 순방향 연산을 한 번 더 돌려 복원하는 '재계산($Recomputation$)' 메커니즘을 사용하는데, 이로 인해 미세한 부동 소수점 정밀도 차이에 따른 학습 난조가 발생할 수 있으므로 Loss 발산 여부와 연산 무결성을 실시간 점검해야 함

## Ⅶ. 결론

- FlashAttention은 연산 장치의 물리 메모리 계층 불균형(HBM-SRAM)을 알고리즘 수준에서 우회 정복한 하드웨어 친화적 IO 최적화의 금자탑이며, 설계자는 GPU 칩셋 아키텍처에 동기화되는 커널 최적 매핑과 학습 발산 제어 장치를 연동하여 성능과 경제성을 완비한 AI 엔진을 구현해야 함
