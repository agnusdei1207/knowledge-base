## 미리 알고가기

- 양자화는 모델 파라미터와 활성값의 표현 정밀도를 낮춰 메모리와 연산 비용을 줄이는 기법임
- PTQ와 QAT는 양자화 적용 시점과 품질 보정 방식이 다른 대표 접근임
- 실제 효과는 비트 수 감소 자체보다 하드웨어가 저정밀 연산을 얼마나 잘 처리하느냐에 따라 달라짐

## Ⅰ. 개요

- **정의/개념**: 양자화는 FP16, FP32로 표현된 가중치와 활성값을 INT8, INT4 같은 저정밀 표현으로 바꿔 모델 저장 크기와 메모리 대역폭과 추론 비용을 줄이는 최적화 기법임
- **배경/필요성**: 대형 모델은 계산량 자체보다 메모리 이동 비용이 병목이 되는 경우가 많으므로, 서비스 환경에 맞춰 정밀도를 낮추는 방식이 배포 현실성을 높임

## Ⅱ. 특징

- 메모리 사용량과 캐시 점유를 줄여 동일 장비에서 더 큰 모델이나 더 많은 동시 요청을 처리하게 함
- PTQ는 적용이 쉽고 QAT는 품질 보존력이 높아 목표 환경에 따라 선택이 달라짐
- 비트 수를 지나치게 낮추면 특정 레이어와 outlier 값에서 품질 저하가 커질 수 있음
- 양자화 이점은 런타임과 커널 지원이 있어야 실제 latency와 throughput 개선으로 이어짐

## Ⅲ. 종류 및 비교

| 판단 기준 | FP16 유지 | INT8 양자화 | INT4 양자화 |
|:---|:---|:---|:---|
| 메모리 절감 | 없음 | 큼 | 매우 큼 |
| 품질 보존 | 가장 높음 | 높음 | 중간 |
| 런타임 난도 | 낮음 | 중간 | 높음 |
| 대표 활용 | 기준 모델 | 서버 추론 | 로컬, 엣지, 초저비용 추론 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Quantizer | scale과 zero-point 같은 매핑 규칙을 정해 부동소수 표현을 저정밀 정수 표현으로 바꿈 |
| Calibration Data | 대표 입력 분포를 반영해 레이어별 동적 범위를 잡고 품질 손실을 줄임 |
| Low-bit Model Artifact | 양자화된 가중치와 메타데이터를 포함해 실제 배포 대상으로 사용됨 |
| Runtime, Kernel | INT8, INT4 연산 경로를 활용해 양자화 효과를 실제 추론 성능으로 연결함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 기준 모델 확보  | --> | 범위 측정/보정  | --> | 저정밀 변환    | --> | 런타임 검증    |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **기준 모델 확보**: 원본 모델의 품질과 메모리와 latency 기준을 확보함
2. **범위 측정 및 보정**: calibration이나 QAT로 레이어별 허용 범위를 결정함
3. **저정밀 변환**: 가중치와 필요 시 활성값을 INT8, INT4 등으로 변환함
4. **런타임 검증**: 실제 장비에서 속도와 품질과 메모리 절감 효과를 함께 측정함

## Ⅵ. 문제점 및 해결 방안

1. 문제: outlier 값이 큰 레이어를 균일하게 양자화하면 전체 모델은 작아져도 특정 핵심 연산의 품질이 급격히 무너질 수 있음
   - 해결방안: mixed precision이나 레이어별 bit-width를 적용하고 layer-wise accuracy drop과 hallucination rate로 품질을 검증함
2. 문제: 파일 크기는 줄었어도 런타임이 저정밀 연산을 충분히 활용하지 못하면 기대한 속도 향상이 나오지 않을 수 있음
   - 해결방안: 하드웨어 지원 경로를 먼저 확인하고 end-to-end latency와 tokens/sec로 성능 효과를 검증함
3. 문제: calibration 데이터가 실제 운영 입력 분포와 다르면 배포 후 품질 저하가 뒤늦게 드러날 수 있음
   - 해결방안: 운영 대표 샘플을 포함한 검증셋을 유지하고 production drift와 tail-case accuracy로 적합성을 검증함

## Ⅶ. 적용 사례

- 온프레미스 LLM 서버: INT8 양자화로 동시 사용자 수를 늘림, 확인 지표는 GPU memory usage와 tokens/sec임
- 모바일 AI 기능: INT4 양자화로 기기 내 탑재를 가능하게 함, 확인 지표는 memory footprint와 battery impact임
- 비전 엣지 추론: QAT 기반 INT8 모델을 사용함, 확인 지표는 FPS와 task accuracy임

## Ⅷ. 결론

양자화는 모델을 단순히 작게 만드는 기술이 아니라 메모리 병목과 비용 제약을 풀기 위해 정밀도와 품질을 균형 있게 재설계하는 배포 최적화 기술임.
