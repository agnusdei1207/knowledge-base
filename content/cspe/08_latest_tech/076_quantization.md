## 미리 알고가기

- 양자화 ($Quantization$): 부동소수점($FP32$/$FP16$) 형태의 신경망 가중치나 활성값을 비트 수가 더 작은 저정밀도(예: $INT8$, $INT4$) 데이터 포맷으로 정수 변환해 연산을 가속하는 경량화 기법임
- 포스트 훈련 양자화 ($PTQ$, Post-Training Quantization): 추가 학습 없이, 소량의 보정($Calibration$) 데이터셋만을 활용해 모델 가중치 범위를 빠르게 정수 스케일링하는 기법임
- 정밀도 손실 ($Accuracy$ $Drop$): 데이터 압축에 따른 수학적 해상도 손실로 인해 모델의 추론 정확도나 성능이 오리지널 대비 저하되는 현상임
- 아웃라이어 ($Outlier$): 특정 채널이나 활성값($Activation$) 레이어에서 비정상적으로 튀는 거대한 숫자 값으로, 양자화 범위 획정 시 스케일 왜곡을 일으키는 주범임

## Ⅰ. 개요

- **정의/개념**: Quantization은 대형 언어 모델의 순방향 연산 속도를 높이기 위해, $FP16$ 또는 $FP32$ 정밀도의 가중치($Weights$)와 활성값($Activations$)을 수식 비트 수 비례로 용량을 절감하는 $INT8$/$INT4$/$FP8$ 등의 저비트 표현식으로 다운 매핑하는 기적의 최적화 기술임
- **배경/필요성**: 트랜스포머의 추론 국면은 연산 횟수(Flops) 자체의 제약보다 메모리 장치(HBM)에서 가중치 데이터를 칩셋 코어로 실시간 끌어오는 메모리 대역폭($Memory-bound$)의 문턱에 가로막혀 있어, 가중치 전송 크기를 획기적으로 줄여 가속을 얻고자 탄생함

## Ⅱ. 특징

- 기저 모델의 가중치 행렬이 차지하는 물리 VRAM 사용량을 즉각 $50 \sim 75\%$ 축소시켜, 단일 GPU당 수용 가용한 최대 동접 배치 크기를 비약적으로 팽창함
- $PTQ$(Post-Training)는 추가 훈련 비용이 전혀 들지 않고 즉시 적용이 가능한 반면, $QAT$(Quantization-Aware)는 훈련 도중 손실을 미리 계산해 성능 복원율을 확보함
- 하드웨어 가속기(Nvidia Tensor Core, 모바일 NPU 등)가 정수(INT8/INT4) 행렬 가속을 물리적으로 지원해 주는 경우에만 실질 속도 향상을 얻을 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 기본 모델 ($FP16$ 유지) | $INT8$ 양자화 | $INT4$ 양자화 |
|:---|:---|:---|:---|
| **VRAM 절감율** | 0% (기준선) | 약 50% 절감 (성능 준수) | 약 75% 절감 (용량 압축 극대화) |
| **추론 정밀도 보존** | 100% (오리지널 품질) | 매우 우수함 (손실 거의 인지 불가능) | 보통 (특정 도메인에서 정확도 하락 우려) |
| **하드웨어 호환성** | 보편적임 (모든 칩 기본 지원) | 매우 우수함 (대부분의 NPU/GPU 가속 가능) | 중간 (특화된 역양자화 커널 결합 필요) |
| **추론 병목 완화** | 대역폭 포화 심함 | 대역폭 대폭 단축 | 대역폭 최소화 및 역양자화 연산 수반 |

> 요약: FP16은 기준 스펙 확보에, INT8은 서버급 인프라 가성비와 무결성 확보에, INT4는 온디바이스 에지 단말 적재 극대화에 활용됨.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 스케일 팩터 | 부동소수점 도메인을 지정된 정수 그리드 범위($-128 \sim 127$ 등)로 곱해 매핑해주는 배수 계수임 |
| 제로 포인트 | 대칭형 또는 비대칭형 매핑에 따라 실수 0의 위치를 정수 축 상의 어디로 이동시킬지 잡는 보정치임 |
| 보정 데이터셋 | 대표 입력 분포를 수집하여 데이터 아웃라이어를 걸러내고 스케일 척도를 튜닝해 주는 보정셋임 |
| 런타임 역양자화기 | 저비트 정수로 저장된 가중치를 연산 순간에만 임시 복원해 내는 GPU C++ 런타임 커널임 |

```text
[ Quantization (양자화) 수식 매핑 메커니즘 ]
Real Number (X) ---> [Quantize: Round(X / Scale) + ZeroPoint] ---> Quantized Integer (q)
Real Number (X) <--- [Dequantize: (q - ZeroPoint) * Scale] <--- Quantized Integer (q)
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +--------------+     +-------------+     +-------------+
| 오리지널    | --> | 보정 샘플로  | --> | 스케일/제로 | --> | 가속 엔진   |
| 모델 프로파일|     | 동작 범위계측|     | 매핑 및 변환|     | 로드 및 추론|
+-------------+     +--------------+     +-------------+     +-------------+
```

1. **지수 추출** — 오리지널 모델 가중치 행렬 값의 최소값($Min$)과 최대값($Max$) 분포를 각 레이어 단위로 정밀 프로파일링함
2. **보정 범위 조정** — 대표 코퍼스(Calibration Data)를 모델에 주입하여, 활성값 레이어에서 유난히 튀는 아웃라이어들의 범위를 정밀 클리핑함
3. **정수 사상 매핑** — 스케일 팩터($Scale$)와 제로 포인트($Zero$ $Point$) 값을 계산하여 $FP16$ 소수점 행렬을 $INT8$ 정수 행렬로 다운 매핑함
4. **엔진 로드** — 변환 완료된 아티팩트를 vLLM 등의 추론 프레임워크에 적재하여, 하드웨어 정수 연산 가속을 개시하고 응답을 출력함

## Ⅵ. 실무 적용 및 유의점

1. 양자화 변환 시 특정 레이어 내의 아웃라이어(Outliers) 데이터를 획일적으로 잘라내면 추론 중 할루시네이션(환각)이 크게 증폭하므로, 가중치 값의 중요도를 추적하여 혼합 정밀도를 적용하는 'AWQ'나 'GPTQ' 등의 정교한 압축 프롬프트를 적용하고 오작동 증가율($Hallucination$ $Rate$)을 측정해야 함
2. 서빙 운영 중에 사용되는 프롬프트의 질의 성격이 사전 캘리브레이션 데이터셋과 크게 달라지면 정확도가 급격히 붕괴하는 '개념 표류($Concept$ $Drift$)' 현상이 발생하므로, 반드시 정기적으로 실서비스 유입 질의 샘플을 수집해 보정용 캘리브레이션 셋을 주기적으로 갱신해야 함

## Ⅶ. 결론

- 양자화는 거대 신경망의 연산 병목을 수학적 매핑과 비트 압축을 통해 돌파하는 최적 배포의 근간이며, 설계자는 무작정 고압축(INT4 이하)에만 매몰되지 말고 아웃라이어 유실 방지 아키텍처와 실시간 개념 표류 모니터링을 병행하여 지능의 무결성을 수립해야 함
