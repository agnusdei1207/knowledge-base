# 📖 【암기용】 개념 완전 이해

> 목적: CNAPP을 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 클라우드 기반 애플리케이션의 개발부터 운영까지 전 과정을 보호하기 위해 여러 보안 도구(CSPM, CWPP, CIEM 등)를 하나로 합친 통합 플랫폼
- **왜 필요한가**: 클라우드는 설정도 복잡하고(CSPM), 돌아가는 서버도 지켜야 하고(CWPP), 누가 접속하는지도 관리해야 한다(CIEM). 예전엔 이걸 다 따로 샀는데, 너무 복잡해서 하나로 합친 것이 필요해졌다.
- **핵심 직관**: "클라우드 보안 도구의 올인원(All-in-one) 종합 선물 세트"

## 깊이 이해
- **배경·문제의식**: 클라우드 보안 도구들이 파편화되어 있어 보안 팀이 너무 많은 알람에 시달리고 정작 중요한 위협을 놓친다. 또한 개발 단계 보안(Scan)과 운영 단계 보안(Monitor)이 따로 노는 '보안 사각지대'가 발생했다.
- **작동 원리 (CNAPP의 3대 핵심)**:
    1. **CSPM (보안형상관리)**: 클라우드 설정이 잘못되어 데이터가 외부에 노출되지 않았는지 체크.
    2. **CWPP (워크로드보호)**: 실제로 돌아가는 컨테이너나 서버 내부에 해킹 시도가 없는지 감시.
    3. **CIEM (권한관리)**: 사용자나 시스템이 너무 과도한 권한을 가지고 있지 않은지 확인.
- **비유**: 건물을 지을 때 설계도 검사(CSPM), 공사 중 안전 관리(CWPP), 출입증 발급 관리(CIEM)를 각각 다른 업체에 맡기다가, 한 전문 업체가 처음부터 끝까지 다 관리해주는 것과 같다.
- **구체 예시**: 위즈(Wiz), 팔로알토 프리즈마 클라우드(Prisma Cloud) 등. 개발자가 코드를 짜서 올리면 즉시 보안 취약점을 찾고, 실제 서버에서 문제가 생기면 그 코드의 어느 부분이 문제인지 바로 알려준다.
- **흔한 오해·주의점**: "단순한 대시보드"가 아니다. 단순히 여러 도구의 화면만 합친 게 아니라, 데이터를 통합 분석해서 '진짜 위험한 놈'을 우선순위로 알려주는 것이 CNAPP의 핵심 가치다.

## 연결 개념
- CSPM (Cloud Security Posture Management) — 설정 오류 탐지 및 수정
- CWPP (Cloud Workload Protection Platform) — 컨테이너/서버 등 실행 환경 보호
- DevSecOps — 개발 과정에 보안을 내재화하여 CNAPP의 효과를 극대화하는 문화

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 클라우드 생명주기 전반(Build, Deploy, Run)에 걸친 보안 가시성 확보와 파편화된 보안 도구의 통합을 중심으로 기술한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: CNAPP(Cloud Native Application Protection Platform)은 CSPM, CWPP, CIEM 등 산재된 클라우드 보안 기능을 단일 플랫폼으로 통합하여 클라우드 라이프사이클 전반을 보호하는 체계이다.
> 2. **가치**: 개발 단계(Shift-left)와 운영 단계(Shield-right)의 보안 컨텍스트를 결합하여 보안 위협의 우선순위를 정확히 식별하고 관리 복잡성을 획기적으로 낮춘다.
> 3. **판단 포인트**: 단순 기능 통합을 넘어 '공격 경로 분석(Attack Path Analysis)'을 통해 실제 비즈니스에 치명적인 위험을 선별해내는 능력이 핵심이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| CNAPP 정의 및 구성 요소(CSPM, CWPP, CIEM) 이해 | 라이프사이클 통합 (Build -> Run) | 개별 도구(CSPM 등)의 정의만 나열 시 감점 |
| 클라우드 보안 도구 통합(Consolidation) 배경 파악 | 보안 도구 파편화 해소, 알람 피로도 감소 | 단순히 '보안 솔루션 패키지'로 서술 금지 |
| DevSecOps 연계 및 Shift-left 보안 가치 인지 | 코드 기반 보안(IaC Scanning)과 런타임 보안 결합 | 운영 단계의 보안만 강조하는 협소한 시각 경계 |

> 요약: 클라우드 네이티브 환경의 복잡성을 통제하기 위한 통합 보안 플랫폼으로서의 CNAPP의 구조와 역할을 평가한다.

## Ⅰ. 개요 및 필요성

- 정의: 클라우드 애플리케이션의 개발부터 배포, 운영 전 과정을 보호하기 위해 CSPM, CWPP, CIEM 등을 통합한 보안 플랫폼
- 배경: 클라우드 인프라의 복잡성 증가로 인한 설정 오류(Misconfiguration) 빈발 및 파편화된 보안 도구 운영의 한계
- 필요성: 보안 알람 피로도 감소, 개발-보안-운영팀 간의 협업 강화(DevSecOps), 클라우드 자산의 통합 가시성 확보

---

## Ⅱ. 구조 및 구성요소

```text
[ Build ] -> [ Deploy ] -> [ Run ] (Life Cycle)
    |            |            |
    +---- [ CNAPP Platform ] ----+
      /          |          \
   CSPM        CWPP        CIEM
 (설정관리)  (워크로드)  (권한관리)
```

| 구성요소 | 역할 | 상세 기능 |
|:---|:---|:---|
| CSPM | 클라우드 서비스 설정 오류 및 컴플라이언스 체크 | IaC 스캐닝, 퍼블릭 S3 탐지, 규제 준수(CIS) 점검 |
| CWPP | 서버, 컨테이너, 서버리스 등 실행 환경 보호 | 취약점 스캔, 런타임 위협 탐지, 악성코드 분석 |
| CIEM | 과도한 클라우드 권한 식별 및 최소 권한 적용 | IAM 엔터티 분석, 미사용 권한 제거, 권한 오남용 감시 |
| CSNS | 클라우드 네트워크 트래픽 보안 및 가시성 | 마이크로 세그멘테이션, 가상 방화벽 연동 |
| IaC Scanning | 인프라 정의 코드 내 보안 취약점 사전 탐지 | Terraform/CloudFormation 정적 분석 |

> 요약: 인프라 설정(CSPM), 실행 자원(CWPP), 접근 권한(CIEM)을 하나의 플랫폼에서 유기적으로 연결한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
IaC 코드 스캔(Build) -> 이미지 취약점 점검(Deploy) -> 설정 오류 탐지(CSPM) -> 실시간 위협 모니터링(CWPP) -> 상관관계 분석 -> 조치
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | Shift-left (왼쪽 이동) | 개발 단계에서 IaC 및 컨테이너 이미지 보안 결함 선제 차단 |
| 2 | 형상 및 권한 분석 | 운영 중인 자원과 권한 매트릭스를 실시간 대조하여 취약점 도출 |
| 3 | 컨텍스트 기반 상관 분석 | 취약점 + 설정 오류 + 노출 경로를 결합하여 위험 순위 산정 |
| 4 | 자동화된 대응 (SOAR) | 심각한 위협 발생 시 자동으로 리소스 격리 또는 설정 복구 |

> 요약: 개발부터 운영까지의 모든 보안 데이터를 결합하여, 개별 알람이 아닌 '공격 시나리오' 관점에서 위험을 통제한다.

## Ⅳ. 특징

| 구분 | 개별 포인트 솔루션 운영 | CNAPP 통합 플랫폼 운영 |
|:---|:---|:---|
| 가시성 | 파편화된 대시보드, 통합 분석 불가 | 단일 뷰(Single View), 전체 맥락 파악 |
| 위협 우선순위 | 모든 취약점을 동일하게 알림 (알람 폭주) | 실제 노출 경로 기반의 핵심 위협 선별 |
| 조직 간 협업 | 보안팀과 개발팀 간 의사소통 단절 | 코드 단계 피드백으로 DevSecOps 가속화 |
| 운영 비용 | 각 솔루션별 구매 및 유지보수 관리 | 통합 계약 및 운영 공수 절감 |

> 요약: 포인트 솔루션의 한계인 '사각지대'와 '알람 과부하'를 해결하여 실질적인 보안 성과를 높인다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | CSPM (Configuration) | CWPP (Workload) | CNAPP (Unified) |
|:---|:---|:---|:---|
| 초점 | 제어 평면 (Control Plane) | 데이터 평면 (Data Plane) | 전 영역 (Full Stack) |
| 주요 위험 | S3 오픈, API 노출 | 랜섬웨어, 채굴기, 익스플로잇 | 공격 경로 (Attack Path) |
| 적용 단계 | 배포 후 상시 | 실행 중 상시 | 개발 ~ 운영 전체 |

> 요약: CSPM과 CWPP는 상호 보완 관계이며, 이를 하나로 묶어 시너지를 내는 것이 CNAPP이다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 성능 부하 (CWPP) | 워크로드 내 에이전트 설치 시 자원 소모 | 에이전트리스(Agentless) 스캔 기술 활용 | CPU/MEM 오버헤드 (< 3% 목표) |
| 위협 과소평가 | 상관 분석 엔진의 정확도 미흡 | 실제 공격 시나리오 기반 정기 테스트 | 탐지 정확도 (Precision/Recall) |
| 벤더 종속성 | 전체 클라우드 보안을 한 벤더에 의존 | 멀티 클라우드 지원 여부 및 표준 준수 확인 | 지원하는 CSP 종류 및 API 커버리지 |

> 요약: 에이전트로 인한 성능 저하를 방지하기 위해 최근에는 '에이전트리스' 방식의 스캔이 CNAPP의 핵심 경쟁력이 되고 있다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 보안 사고 대응 시간 | 위협 식별 후 조치까지 30분 이내 | MTTR (Mean Time To Respond) 측정 |
| 취약점 감소율 | 도입 후 고위험 취약점 70% 제거 | 월별 취약점 대시보드 추이 분석 |
| 알람 정확도 | 실제 공격 관련 알람 비율 90% 이상 | False Positive (오탐) 비율 전수 조사 |

> 요약: 도입 효과는 조치 속도 향상, 고위험 자산의 감소, 그리고 알람의 질적 개선으로 평가한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. **공격 경로 가시화**: 인터넷에 노출된 S3 버킷(CSPM)과 연결된 컨테이너의 취약점(CWPP)을 연결하여 '치명적 공격 경로'를 우선 제거
2. **Shift-left 구현**: 개발자가 Terraform 코드를 푸시할 때 CNAPP이 자동 스캔하여 보안 위반 시 빌드를 중단시키는 가드레일 구축
3. **최소 권한 자동화**: 실제 리소스가 사용하는 권한과 IAM 정책을 비교하여 미사용 권한을 자동으로 삭제 권고하는 CIEM 적용

**결론 (2줄):**
- 기술사 판단: CNAPP은 단순한 기술의 합이 아닌 '보안 운영의 현대화'이며, 에이전트리스 기술을 통한 가시성 확보가 첫 번째 성공 요건이다.
- 향후 방향: AI 기반의 위협 예측과 자율 복구 기능이 강화될 것이며, 소프트웨어 공급망 보안(SBOM) 관리까지 영역이 확장될 전망이다.
