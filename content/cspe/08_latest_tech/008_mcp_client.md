## 미리 알고가기

- **MCP 클라이언트(MCP Client)**: 거대 언어 모델(LLM)을 구동하고 사용자와 상호작용하며, MCP 서버들에 필요한 리소스 및 도구 실행을 요청하는 호스트 애플리케이션임.
- **컨텍스트 윈도우(Context Window)**: LLM이 한 번에 처리할 수 있는 최대 토큰(단어 조각)의 크기임.
- **시맨틱 라우팅(Semantic Routing)**: 사용자의 의도(의미)를 분석하여 관련성이 높은 특정 MCP 서버나 도구로 요청을 선별적으로 전달하는 제어 기법임.
- **도구 호출(Tool Calling)**: LLM이 텍스트 생성을 넘어 외부 도구를 활용해야 한다고 판단하여 인자값을 포함한 JSON 응답을 생성하는 메커니즘임.
- **컨텍스트 주입(Context Injection)**: 외부에서 조회한 실시간 데이터나 문서 내용을 프롬프트에 동적으로 삽입하여 LLM의 생성 품질을 높이는 기법임.

## 작성 근거(검토용)

- **핵심 키워드 선정 이유**: AI 에이전트 서비스 오케스트레이션의 핵심이자 데이터 주입의 제어권자로서 MCP 클라이언트의 역할을 기술적으로 조명하기 위해 선정함.
- **배치·전개 근거**: MCP 서버와의 역할 비교표를 통해 요청자와 응답자의 관계를 규명함. 오케스트레이션 아키텍처 구조도를 구성하고, 사용자 입력 수신부터 동적 도구 주입 및 최종 답변 반환까지의 4단계 실행 흐름도를 규명함. 토큰 리밋 대응을 위한 컨텍스트 관리 기법과 실무적인 개발 IDE 적용 사례를 결론과 연계함.
- **전수 검수 완료 근거**: 제목, frontmatter, 본문, 비교표, 도식, 요약 및 결론의 단어·조사·동사 결합 오류를 5회 이상 검수하고 맞춤법 오류를 교정하였음.

## Ⅰ. 개요
- **정의/개념**: MCP 클라이언트는 AI 모델 및 사용자 인터페이스(UI)를 구동하며 가용한 MCP 서버들을 문어발식으로 연결해 동적으로 컨텍스트를 주입하는 호스트 프로그램임.
- **배경/필요성**: 외부 연동 코드가 클라이언트 내부에 하드코딩되는 파편화 문제를 극복하고, 가벼운 단일 플랫폼 내에서 실시간으로 사외 지식망을 확장하기 위해 필요함.

### 쉽게 이해하기 (학습용)
- 스마트폰의 메인 운영체제(클라이언트)가 직접 모든 연산을 처리하지 않고, 여러 개별 앱(서버)들을 호출해 필요한 기능을 유저에게 제공하는 것과 같습니다.

## Ⅱ. 특징
- **오케스트레이션 허브**: 다수의 MCP 서버와 연결 통로를 확보하여 LLM의 상태에 맞춰 동적으로 실행을 관리하는 제어 중추임.
- **프롬프트 은닉 제어**: LLM에 전달되는 시스템 프롬프트 포맷 내에 서버들의 리소스 및 도구 스키마를 추상화하여 자동으로 내장시킴.
- **동적 도구 라우팅**: LLM이 생성한 JSON 규격의 함수 호출 요청을 가로채 적합한 MCP 서버의 STDIO 또는 SSE 채널로 안전하게 라우팅함.

### 쉽게 이해하기 (학습용)
- 여러 보조 비서(서버)들에게 업무 지시를 내리고 보고받은 내용을 정리하여 최종 사장님(AI)에게 요약 보고하는 수석 비서와 같습니다.

## Ⅲ. 종류 및 비교

| 판단 기준 | MCP Client | MCP Server |
|:---|:---|:---|
| **핵심 역할** | AI 모델 구동, UI 관리 및 도구 호출 오케스트레이션 | 원본 데이터 제공 및 도구/함수의 물리적 실행 |
| **데이터 소유 여부** | 원본 데이터를 비소유하며, 호출 결과만 임시 주입 | 원본 데이터베이스 및 도구 실행 코드를 직접 보유 |
| **연결 토폴로지** | 1개의 클라이언트가 $N$개의 서버를 동시 수용 | 독립된 프로세스로서 여러 클라이언트의 요청에 대기 |

### 쉽게 이해하기 (학습용)
- 클라이언트는 피자 배달 앱으로 주문만 모아 전달하고, 서버는 주방에서 실제로 피자를 굽는 물리적 요리사에 해당합니다.

## Ⅳ. 설계 요소 및 구조

```text
┌────────────────────────────────────────────────────────┐
│                      MCP Client                        │
│ ┌──────────────────┐┌──────────────────┐┌────────────┐ │
│ │   Model Engine   ││    Router &      ││ Transport  │ │
│ │   (LLM Claude)   ││   Orchestrator   ││ (STDIO/SSE)│ │
│ └─────────┬────────┘└────────▲─────────┘└─────▲──────┘ │
│           └──────────────────┼────────────────┘        │
└──────────────────────────────┼─────────────────────────┘
                               ▼ (JSON-RPC)
                      [ MCP Servers (N) ]
```

| 설계 요소 | 설명 |
|:---|:---|
| **Model Engine** | 사용자의 질의를 기반으로 도구 사용(Tool Use) 여부를 추론하고 JSON 응답을 내놓는 핵심 LLM 구동계 |
| **Orchestrator** | 사용 가용한 도구들의 메타데이터 목록을 수집하고, LLM의 도구 호출을 적절한 서버로 배분하는 라우팅 코어 |
| **Context Injector** | 서버에서 반환받은 실행 결과 텍스트를 LLM의 프롬프트 컨텍스트 창에 동적으로 주입하는 모듈 |

### 쉽게 이해하기 (학습용)
- 생각하는 뇌(모델 엔진), 부서별로 일을 나누어주는 중개자(오케스트레이터), 그리고 결과를 모아 정리해주는 보고관(인젝터)으로 구성됩니다.

## Ⅴ. 원리 및 절차 흐름도

```text
[User]             [MCP Client]              [LLM Engine]            [MCP Server]
  │                     │                          │                       │
  ├─ 1. User Prompt ───▶│                          │                       │
  │                     ├─ 2. Evaluate Context ───▶│                       │
  │                     │◀─ 3. Tool Call Request ──┤                       │
  │                     │                                                  │
  │                     ├────────── 4. Execute (JSON-RPC) ────────────────▶│
  │                     │◀───────── 5. Return JSON Result ─────────────────┤
  │                     │                                                  │
  │                     ├─ 6. Context Inject ─────▶│                       │
  │                     │◀─ 7. Final Text Response ┤                       │
  │◀─ 8. Text Response ─┤                          │                       │
```

1. **요청 분석**: 사용자의 프롬프트가 유입되면 클라이언트가 이를 분석하고 LLM 엔진에 컨텍스트를 태워 질의함.
2. **도구 판정**: LLM 엔진이 질문 해결을 위해 외부 도구 실행이 필요하다고 판단하여 도구 호출 요청(JSON)을 클라이언트에 회신함.
3. **서버 실행 및 주입**: 클라이언트가 요청을 파싱해 대상 MCP 서버에 전송한 뒤, 반환된 로우 데이터를 프롬프트에 주입(Injection)하여 LLM이 최종 답변을 도출하도록 제어함.

### 쉽게 이해하기 (학습용)
- 손님이 질문을 하면(요청), 지배인이 도서실 도서(도구)를 가져오도록 심부름을 시키고(실행), 책의 내용을 보고 요약해서(주입) 최종 답변하는 것과 같습니다.

## Ⅵ. 실무 사례
- 대규모 소스 코드 분석 시스템 개발 시, Cursor IDE(MCP 클라이언트)에 사내 데이터베이스 및 JIRA 이슈 추적기와 연동된 MCP 서버들을 탑재하여 개발자가 특정 버그 조치를 명령하면 이슈 내용 조회, 코드 파일 접근, 버그 수정 제안 및 PR 작성을 단일 클라이언트 흐름 내에서 오케스트레이션하도록 구성함.

### 쉽게 이해하기 (학습용)
- 똑똑한 코딩 프로그램에 메신저와 버그 기록 관리 시스템을 동시 연동하여, 프로그램(클라이언트) 하나로 모든 업무를 자율 처리하게 지휘하는 구조입니다.

## Ⅶ. 결론
- MCP 클라이언트는 여러 분산 데이터 소스를 AI의 두뇌와 결합하는 실시간 컨텍스트 통합 오케스트레이터의 중추임.
- 다중 서버의 무분별한 연동에 따른 프롬프트 토큰 낭비를 통제하기 위해 클라이언트 단에서의 동적 시맨틱 라우팅($Semantic\ Routing$) 장치가 보완되어야 함.

### 쉽게 이해하기 (학습용)
- 결국 똑똑한 대장 비서로서 여러 부하 서버들을 지휘하고 제어해 AI가 길을 잃거나 한계를 초과하지 않게 통제하는 핵심 기둥입니다.
