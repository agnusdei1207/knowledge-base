# 📖 【암기용】 개념 완전 이해

> 목적: MCP Client를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **정의**: LLM 애플리케이션 안에서 MCP Server와 통신하는 구성요소
- **왜 필요한가**: 모델이 서버 기능을 직접 다루지 않고 세션·권한·호출 상태를 관리하는 중간 계층이 필요함.
- **핵심 직관**: MCP Client는 AI 앱이 외부 도구를 쓰기 위해 들고 있는 표준 리모컨임.

## 깊이 이해
- **배경·문제의식**: 에이전트가 여러 MCP Server를 동시에 사용하면 연결 상태, 사용자 권한, 도구 선택, 오류 처리가 복잡해짐.
- **작동 원리**: Client가 Server 기능을 발견하고, 모델의 도구 선택을 호출 메시지로 변환하며, 결과를 모델 컨텍스트로 전달함.
- **비유**: 브라우저가 웹 서버와 통신하면서 쿠키·세션·요청·응답을 관리하는 역할.
- **구체 예시**: IDE의 MCP Client가 파일 서버와 Git 서버를 동시에 연결해 코드 변경 근거를 모델에 제공함.
- **흔한 오해·주의점**: Client는 단순 통신 모듈이 아니라 사용자 세션과 권한 위임을 다루므로 격리와 로그가 필요함.

## 연결 개념
- MCP Server — Client가 연결하는 대상
- Session Management — 사용자별 연결 상태 관리
- Least Privilege — Client 권한 위임 원칙

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: MCP Client는 LLM 앱과 MCP Server 사이에서 기능 발견, 호출, 결과 반영을 수행하는 통신 주체임.
> 2. **가치**: 여러 외부 시스템 연결을 모델 컨텍스트 안으로 안전하게 전달하는 제어 지점을 제공함.
> 3. **판단 포인트**: 사용자 세션, 권한 위임, 서버별 신뢰도, 호출 실패 처리를 명확히 설계해야 함.

---

## Ⅰ. 개요 및 필요성

MCP Client는 MCP 호출 주체임. 에이전트가 여러 서버와 도구를 사용할 때 연결관리, 세션분리, 결과 반영, 오류 처리를 담당하는 계층이 필요함.

---

## Ⅱ. 구조 및 구성요소

```text
LLM App → MCP Client ─┬→ Server A
                      ├→ Server B
                      └→ Server C
          │
          ▼
   Session/Policy/Cache
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Server Connector | MCP Server 연결 | 연결 상태·버전 확인 |
| Session Manager | 사용자 세션 관리 | 사용자별 권한 분리 |
| Policy Filter | 허용 도구 필터링 | least privilege 적용 |
| Result Handler | 결과 정제·컨텍스트 반영 | 민감정보 마스킹 |

> 요약: MCP Client는 다중 서버 연결과 사용자 세션을 관리해 모델에 안전한 도구 결과를 전달함.

---

## Ⅲ. 동작원리 및 흐름도

```text
사용자 세션 시작 → 서버 연결 → 기능 목록 수집
        → 허용 도구 필터링 → 호출 전달 → 결과 반영
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 세션 생성 | 사용자ID, 권한 토큰 |
| 2 | 서버 기능 발견 | 서버 버전, 도구 목록 |
| 3 | 호출 중계 | 허용목록, rate limit |
| 4 | 결과 처리 | 마스킹, 캐시, Trace ID |

> 요약: MCP Client는 사용자 권한에 맞게 서버 기능을 필터링한 뒤 호출 결과를 모델 컨텍스트에 넣음.

---

## Ⅳ. 특징

| 구분 | 일반 API 클라이언트 | MCP Client | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 대상 | 단일 API | 다중 MCP Server | 연결 수, 실패율 |
| 권한 | 서비스 계정 중심 | 사용자 세션 위임 | 권한 누수 건수 |
| 결과 | 앱 로직 소비 | 모델 컨텍스트 반영 | 마스킹율, 토큰 크기 |

> 요약: MCP Client는 통신뿐 아니라 모델 컨텍스트에 들어갈 결과의 범위와 신뢰도를 제어함.

---

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 사용자별 세션 토큰을 서버별 최소권한으로 교환하고 공유 서비스 계정 사용을 제한
2. 서버별 timeout, retry, circuit breaker를 설정해 장애 전파와 무한 대기를 차단
3. 결과 크기, 민감정보 마스킹, 토큰 예산을 적용해 컨텍스트 오염과 비용 증가를 제한

**결론 (2줄):**
- 기술사 판단: MCP Client는 AI 앱의 보안 경계에 포함하고 세션 격리를 우선 설계해야 함.
- 향후 방향: MCP Client는 다중 서버 연결과 정책 집행을 담당하는 에이전트 런타임 핵심 모듈로 발전함.
