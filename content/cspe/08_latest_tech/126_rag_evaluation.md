# 📖 【암기용】 개념 완전 이해

> 목적: RAG Evaluation을 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: RAG 시스템의 검색 품질, 근거 충실성, 답변 관련성, 환각률을 정량 측정하는 평가 체계
- **왜 필요한가**: RAG는 검색과 생성이 결합되어 있어 일반 LLM 정확도만으로 장애 원인을 알 수 없음.
- **핵심 직관**: 답안 점수만 보는 것이 아니라, 참고자료를 제대로 찾았는지와 참고자료대로 썼는지를 따로 채점함.

## 깊이 이해
- **배경·문제의식**: 답변이 틀렸을 때 원인이 검색 누락인지, 잘못된 문서인지, LLM 환각인지 분리해야 개선 방향을 정할 수 있다.
- **작동 원리**: 테스트 질의와 정답·근거 세트를 만들고, Context Precision/Recall, Faithfulness, Answer Relevancy, Groundedness를 측정함.
- **비유**: 오픈북 시험에서 "책을 제대로 찾았는가", "책 내용과 답이 일치하는가", "질문에 맞게 답했는가"를 분리 채점하는 방식임.
- **구체 예시**: RAG 품질 기준을 Faithfulness 0.9, Context Recall 0.85, Answer Relevancy 0.8 이상으로 두고 배포 게이트 적용.
- **흔한 오해·주의점**: 단일 점수만 보면 원인 분석이 어렵다. 검색 지표와 생성 지표를 반드시 분리해야 함.

## 연결 개념
- RAGAS — RAG 평가 자동화 프레임워크
- Faithfulness — 답변이 제공 근거와 일치하는지 측정
- Context Precision/Recall — 검색된 근거의 정밀도와 재현율 측정

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: RAG Evaluation은 검색 품질과 생성 품질을 분리 측정하는 평가 체계임.
> 2. **가치**: Faithfulness·Context Recall 등 지표로 환각 원인을 검색/생성 단계별로 추적함.
> 3. **판단 포인트**: 배포 게이트는 단일 정확도보다 검색 지표+생성 지표+회귀 테스트 조합으로 설정함.

## Ⅰ. 개요 및 필요성

RAG Evaluation은 검색증강생성 품질 평가 체계임. RAG 오류는 검색 누락, 무관 문서, 근거 불일치, 답변 관련성 부족으로 나뉜다. 운영 전후에 단계별 지표를 측정해야 개선 지점을 식별할 수 있다.

## Ⅱ. 구조 및 구성요소

```text
Test Set -> Retriever Eval -> Generator Eval -> Judge/Evaluator
  -> Metric Dashboard -> Release Gate
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Test Set | 질의·정답·근거 세트 | 500~1,000개 기준 |
| Retrieval Metrics | 검색 정밀도·재현율 평가 | Context Precision/Recall |
| Generation Metrics | 답변 충실성·관련성 평가 | Faithfulness, Relevancy |
| Release Gate | 배포 기준과 회귀 감지 | 임계값 미달 시 배포 차단 |

> 요약: RAG 평가는 테스트셋, 검색 지표, 생성 지표, 배포 게이트로 구성해 품질 원인을 단계별로 분리함.

## Ⅲ. 동작원리 및 흐름도

```text
질의 세트 실행 -> 검색 컨텍스트 수집 -> 답변 생성
  -> 지표 계산 -> 기준 비교 -> 개선/배포 판단
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 대표 질의·정답·근거 데이터 구축 | 도메인별 500건 이상 |
| 2 | 검색 결과의 Precision/Recall 계산 | Context Recall ≥0.85 |
| 3 | 답변과 근거 일치성·관련성 평가 | Faithfulness ≥0.9 |
| 4 | 대시보드·배포 게이트 적용 | 회귀 5%p 이상 시 차단 |

> 요약: 테스트 질의를 실행해 검색과 생성을 따로 평가하고 임계값 기반으로 배포 여부를 결정함.

## Ⅳ. 특징

| 구분 | 일반 LLM 평가 | RAG Evaluation | 판단 포인트 |
|:---|:---|:---|:---|
| 평가 대상 | 답변 텍스트 | 검색 컨텍스트+답변 | 오류 원인 분리 가능 |
| 주요 지표 | 정확도·BLEU | Faithfulness, Context Recall | 운영 RAG에 적합 |
| 필요 데이터 | 정답 중심 | 정답+근거 문서 | 근거 라벨링 비용 발생 |
| 운영 방식 | 오프라인 평가 | CI/CD 게이트·모니터링 | 회귀 테스트 필수 |

> 요약: RAG Evaluation은 답변 결과뿐 아니라 근거 검색 품질을 함께 평가해 운영 개선 방향을 제공함.

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 평가셋 구축: 빈도 상위 질의 700건, 장애 질의 200건, 규정 질의 100건으로 총 1,000건 구성
2. 배포 게이트: Faithfulness 0.9, Context Recall 0.85, Answer Relevancy 0.8 미만이면 색인·프롬프트 점검
3. 운영 모니터링: 일별 1% 샘플링 평가, 지표 5%p 하락 시 임베딩 모델·청킹 변경 이력 추적

**결론 (2줄):**
- 기술사 판단: 운영 RAG는 검색·생성 지표를 분리한 평가 체계 없이는 배포하지 않음
- 향후 방향: LLM-as-Judge와 사용자 피드백을 결합한 지속 평가 체계로 발전
