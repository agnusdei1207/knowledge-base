## 미리 알고가기

- RAG 평가는 검색 품질과 생성 품질을 분리해 원인 분석까지 가능하게 하는 체계임
- 정답 일치율만으로는 검색 실패와 환각을 구분하기 어려움
- 대표 지표는 Context Precision, Context Recall, Faithfulness, Answer Relevancy임

## Ⅰ. 개요

- **정의/개념**: RAG 평가는 질의와 검색 문맥과 생성 답변을 함께 측정해 검색 단계와 생성 단계의 품질을 분리 진단하는 검증 체계임
- **배경/필요성**: 생성형 AI는 그럴듯한 오답을 만들 수 있으므로, 단순 정답률이 아니라 어떤 단계에서 품질이 무너졌는지 구분하는 운영 기준이 필요함

## Ⅱ. 특징

- 검색 품질과 답변 품질을 분리해 병목 위치를 바로 찾을 수 있음
- 정적 테스트셋뿐 아니라 실제 질의 로그 기반 지속 평가에 적합함
- LLM-as-a-Judge를 활용해 대규모 자동 평가 파이프라인을 구성할 수 있음
- 지표별로 개선 대상이 달라 청킹, 임베딩, 리랭커, 프롬프트를 각각 조정할 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | RAG 평가 | 일반 QA 정답률 평가 | 검색 단독 평가 |
|:---|:---|:---|:---|
| 평가 대상 | 검색과 생성 전체 | 최종 답변 중심 | 검색 결과 중심 |
| 병목 식별력 | 높음 | 낮음 | 생성 단계 미포함 |
| 운영 활용성 | 높음 | 중간 | 중간 |
| 대표 지표 | Faithfulness, Answer Relevancy, Context Metric | EM, F1 | Recall@k, MRR |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 평가 데이터셋 | 질의와 기준 답과 참조 문서를 포함해 지표 계산의 기준선을 제공하며 도메인 대표성이 중요함 |
| Retrieval Metric | 검색된 문맥이 얼마나 적절하고 충분한지 측정해 임베딩, 청킹, 리랭커 품질 판단에 사용함 |
| Generation Metric | 답변이 질문에 맞고 근거 문맥을 벗어나지 않는지 측정해 환각 통제 수준을 보여줌 |
| Evaluation Pipeline | 배치 실행과 샘플링과 대시보드를 통해 모델 교체 전후 성능을 일관되게 검증함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 질의셋 준비   | --> | 검색 결과 수집 | --> | 답변/근거 평가 | --> | 지표 집계/개선 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **질의셋 준비**: 운영 로그나 검증용 테스트셋에서 대표 질의를 선정함
2. **검색 결과 수집**: 각 질의의 top-k 문맥과 메타데이터를 확보함
3. **답변 및 근거 평가**: 문맥 적합성과 답변 충실성과 관련성을 분리 측정함
4. **지표 집계 및 개선**: 점수 저하 구간을 찾고 검색기나 프롬프트를 보정함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 단일 평균 점수만 보면 검색 실패와 환각이 섞여 병목 원인을 잘못 해석할 수 있음
   - 해결방안: retrieval metric과 generation metric을 분리 대시보드로 운영하고 지표 간 상관관계와 개선 전후 delta로 검증함
2. 문제: 평가셋이 실제 업무 질의를 반영하지 못하면 높은 점수에도 운영 만족도가 낮아질 수 있음
   - 해결방안: 운영 로그 기반 샘플을 주기적으로 편입하고 업무군별 score distribution과 user feedback으로 대표성을 검증함
3. 문제: LLM 심사 모델에 과도하게 의존하면 채점 편향 때문에 점수 신뢰도가 흔들릴 수 있음
   - 해결방안: 휴먼 샘플 검수를 병행하고 judge agreement와 correlation coefficient로 자동 평가 일관성을 검증함

## Ⅶ. 적용 사례

- 사내 지식검색 RAG에서는 청킹 전략 변경 전후를 평가하고 확인 지표는 Context Precision과 Faithfulness임
- 고객지원 챗봇에서는 FAQ와 정책 문서를 기반으로 답변 품질을 점검하고 확인 지표는 Answer Relevancy와 CSAT임
- 금융 문서 QA에서는 모델 교체 시 배치 평가 게이트를 두고 확인 지표는 hallucination rate와 recall@k임

## Ⅷ. 결론

RAG 평가는 답변의 그럴듯함이 아니라 검색 적합성과 근거 기반성을 분리 관리하는 운영 계기판이므로, 지표 분해와 대표 질의셋 관리가 성능 개선의 출발점임.
