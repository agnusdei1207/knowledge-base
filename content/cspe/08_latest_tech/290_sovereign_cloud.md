# 📖 【암기용】 개념 완전 이해

> 목적: 소버린 클라우드를 데이터가 국내에 있다는 주장보다 법적 관할권, 운영 주체, 기술 통제, 공급망 투명성을 함께 만족하는 클라우드 모델로 이해하게 만든다.

## 한눈에
- **개요**: 특정 국가·지역의 법과 정책에 맞춰 데이터·운영·접근권을 통제하는 클라우드
- **왜 필요한가**: 공공·국방·금융·의료 데이터는 해외 법률, 운영자 접근, 장애 시 서비스 지속성까지 검토해야 한다.
- **핵심 직관**: 건물이 국내에 있어도 열쇠를 외국 법인이 쥐고 있으면 주권 통제가 끝난 것이 아니다.

## 깊이 이해
- **배경·문제의식**: 글로벌 클라우드는 규모의 경제를 제공하지만 데이터 관할권, 운영자 국적, 법 집행기관 접근 요구, 공급망 종속 문제가 남는다.
- **작동 원리**: 데이터 위치 제한, 현지 운영 인력, 암호키 통제, 감사로그, 독립 운영 절차, 국가 인증을 조합해 주권 요구를 만족한다.
- **비유**: 해외 은행 금고를 쓰는 대신 국내 법원의 관할을 받는 금고에 자산을 두고, 열쇠 관리도 국내 규정으로 제한하는 것과 같다.
- **구체 예시**: 공공기관 업무에서 고객 데이터와 운영 메타데이터를 국내 리전에 저장하고, 관리자 접근을 국내 인력과 승인 절차로 제한한다.
- **흔한 오해·주의점**: 데이터 레지던시와 소버린 클라우드는 다르다. 위치는 한 요소이고, 법적 접근권·운영권·기술 독립성까지 봐야 한다.

## 연결 개념
- CSAP — 국내 공공 클라우드 보안인증 기준
- Sovereign AI — AI 데이터·모델·인프라 주권으로 확장
- Hybrid Cloud — 민감 업무를 주권 영역에 배치하는 실행 구조

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.
> 핵심: 소버린 클라우드는 데이터 위치가 아니라 법적 관할권, 운영 통제, 암호키, 공급망을 함께 평가하는 주권형 클라우드다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Sovereign Cloud는 국가·지역의 데이터 보호, 법적 관할, 운영 독립 요구를 만족하도록 설계된 클라우드 모델임.
> 2. **가치**: 공공·규제 산업에서 해외 법률 접근, 운영자 권한, 데이터 이전 리스크를 계약·기술·감사로 통제함.
> 3. **판단 포인트**: 데이터 레지던시, 키 주권, 운영자 통제, 인증, 공급망 투명성을 분리해 평가해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 디지털 주권 이해 확인 | 데이터·운영·법률·공급망 주권 | 국내 리전 보유로만 설명 |
| 공공 클라우드 판단 확인 | 인증, 감사, 키 관리, 관리자 접근 통제 | 클라우드 일반 보안과 혼동 |
| 아키텍처 적용 역량 확인 | 민감도별 배치, 암호키 분리, 로그 감사 | 공급자 마케팅 문구 반복 |

> 요약: 이 문제는 주권 요구를 기술·계약·운영 통제로 바꾸는 설계 능력을 요구한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 주권 요구 기반 클라우드
- 배경: 글로벌 클라우드 이용이 늘며 데이터 관할권, 해외 법령, 운영자 접근권에 대한 규제 검토가 커짐.
- 필요성: 공공·금융·의료 업무는 데이터 위치, 암호키 소유, 운영 로그, 인증 상태를 조달 조건으로 확인해야 함.

---

## Ⅱ. 구조 및 구성요소

```text
Regulated Workload -> Sovereign Region / Local Operator
  +-> Data Residency -> Customer Key Control -> Access Approval
  +-> Audit Log -> Certification Evidence -> Compliance Report
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 주권 리전 | 데이터와 서비스 실행 위치 제한 | 법적 관할권 검토 필요 |
| 키 관리 | 암호키 생성·보관·폐기 통제 | BYOK, HYOK, HSM |
| 운영 통제 | 관리자 접근과 변경 승인 관리 | 현지 인력, break-glass 절차 |
| 감사 증적 | 접근·변경·보안 이벤트 기록 | 조달·감사 제출 근거 |

> 요약: 소버린 클라우드는 위치, 키, 운영자, 감사 증적을 묶어 주권 요구를 검증 가능한 통제로 만든다.

---

## Ⅲ. 동작원리 및 흐름도

```text
데이터 민감도 분류 -> 주권 요구 매핑 -> 리전 / 운영자 선택
-> 키 관리 정책 적용 -> 접근 승인 / 로그 기록 -> 감사 보고
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 데이터와 업무 민감도 분류 | 개인정보·공공기밀 등급 |
| 2 | 법적 관할권과 인증 요구 매핑 | CSAP, GDPR, 산업 규정 |
| 3 | 리전, 운영자, 키 관리 방식 선택 | 데이터 이전 금지 조건 |
| 4 | 접근 통제와 감사로그 운영 | 관리자 접근 기록 |

> 요약: 주권 요구를 먼저 분류하고 실행 위치·키·운영 권한을 그 요구에 맞추는 순서로 동작한다.

---

## Ⅳ. 특징

| 구분 | 일반 퍼블릭 클라우드 | Sovereign Cloud | 판단 기준 |
|:---|:---|:---|:---|
| 데이터 위치 | 리전 선택 중심 | 위치와 이동 제한 계약화 | 국외 이전 허용 여부 |
| 운영 주체 | 글로벌 운영 모델 | 현지 운영·승인 절차 | 관리자 접근 경로 |
| 키 관리 | 공급자 KMS 중심 | 고객·국가 요구 반영 | BYOK/HYOK 필요성 |
| 감사 | 표준 보고서 | 규제별 증적 제출 | 조달·감사 요구 |

> 요약: 소버린 클라우드는 클라우드 기능보다 데이터와 운영 권한이 어느 관할에 묶이는지가 핵심이다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 글로벌 리전 | 주권 리전·현지 운영 | 규제 데이터 비중 |
| 비용 | 글로벌 표준 과금 | 전용 운영·인증 비용 추가 | 조달 의무와 위험 수용도 |
| 운영 | 공급자 표준 절차 | 고객 승인·감사 절차 포함 | 관리자 접근 민감도 |

> 요약: 주권 요구가 계약 조건이면 비용보다 관할권·운영권 증적을 우선한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 주권 과대 주장 | 데이터 위치만 강조 | 법률·운영·키 통제 체크리스트 | sovereignty control coverage |
| 운영 지연 | 접근 승인 절차 증가 | break-glass와 사후 감사 정의 | emergency access count |
| 공급자 종속 | 전용 API와 폐쇄형 서비스 | 표준 Kubernetes, PostgreSQL, S3 호환 검토 | portability test |

> 요약: 소버린 클라우드 리스크는 주권 통제 누락과 운영 지연이며, 통제 항목과 비상 접근 지표로 점검한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 데이터 주권 | 국외 이전 금지 조건 충족 | 데이터 흐름 점검 |
| 접근 주권 | 관리자 접근 승인·기록 100% | PAM 감사로그 |
| 인증 | 요구 인증 유지 | 인증서·갱신 일정 |

> 요약: 도입 효과는 데이터 이동, 관리자 접근, 인증 유지 증적으로 판단한다.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 데이터 등급별로 국외 이전 가능 여부, 암호키 소유자, 운영자 접근 조건을 조달 요구사항에 명시함.
2. BYOK/HYOK, HSM, PAM, 감사로그 보존 정책을 설계해 관리자 접근과 키 사용을 추적함.
3. 주권 리전 장애 시 대체 리전, 백업 위치, 복구 절차를 RTO/RPO 기준으로 검증함.

**결론 (2줄):**
- 기술사 판단: 공공·규제 데이터는 소버린 클라우드, 공개 서비스·비민감 분석은 일반 퍼블릭 클라우드 배치가 타당함.
- 향후 방향: 소버린 클라우드는 AI 학습 데이터, 모델 가중치, GPU 인프라 주권까지 포함하는 Sovereign AI로 확장됨.
