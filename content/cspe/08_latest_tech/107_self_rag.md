# 📖 【암기용】 개념 완전 이해

> 목적: Self-RAG를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **정의**: LLM이 생성 도중 스스로 검색 필요성을 판단하고, 생성 결과를 반성 토큰으로 자가 검증하는 RAG 프레임워크
- **왜 필요한가**: 기존 RAG는 모든 질문에 무조건 검색하여 불필요한 지연이 생기고, 검색 결과가 나빠도 그대로 쓴다. Self-RAG는 "검색할지 말지"와 "생성이 맞는지"를 LLM 스스로 결정한다.
- **핵심 직관**: "스스로 '자료가 필요한가?' 판단하고, 답을 쓴 뒤 '이게 맞나?' 자문자답하는 학생."

## 깊이 이해
- **배경·문제의식**: Naive RAG는 항상 검색→생성 고정 파이프라인이라, 단순 질문에도 검색 지연(200~500ms)이 발생하고 무관 문서가 환각을 유발한다. Self-RAG(Asai et al., 2023)는 특수 반성 토큰(Retrieve, ISREL, ISSUP, ISUSE)을 학습시켜 LLM이 자율적으로 파이프라인을 제어한다.
- **작동 원리**: ① LLM이 다음 토큰 생성 중 [Retrieve=Yes] 토큰을 발행하면 검색 실행 → ② 검색된 문서별로 [ISREL] 토큰이 관련성 판정 → ③ 문서 기반 생성 후 [ISSUP] 토큰이 생성-문서 일관성 판정 → ④ [ISUSE] 토큰이 최종 답변 유용성 판정 → 최고 점수 세그먼트 선택 출력.
- **비유**: 시험 중 "이건 외운 걸로 충분해"(검색 불필요) vs "교과서를 봐야겠다"(검색 필요)를 스스로 판단하고, 답을 쓴 뒤 "교과서 내용과 맞나?" 검산하는 학생.
- **구체 예시**: PubHealth 사실 검증 태스크에서 Naive RAG 72.4% → Self-RAG 81.2%로 정확도 +8.8%p 향상, 동시에 검색 호출 횟수 40% 감소(Asai et al., 2023).
- **흔한 오해·주의점**: 반성 토큰 학습에 별도 크리틱 데이터 수만 건이 필요하다. 사전학습 모델을 그대로 쓸 수 없고 SFT(Supervised Fine-Tuning) 과정이 필수다.

## 연결 개념
- Corrective RAG — 검색 후 사전 교정 (Self-RAG는 생성 중 사후 반성)
- Chain-of-Thought — 추론 과정 명시화 (Self-RAG는 검색·검증 과정 명시화)
- RLHF — 보상 모델 기반 품질 통제 (Self-RAG는 반성 토큰 기반 자가 통제)


# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: LLM이 반성 토큰(Retrieve/ISREL/ISSUP/ISUSE)으로 검색 여부·생성 품질을 자율 판정하는 RAG
> 2. **가치**: 검색 호출 40% 감소 + 정확도 8.8%p 향상으로 지연과 환각을 동시에 줄임
> 3. **판단 포인트**: 반성 토큰 SFT 비용(크리틱 데이터 수만 건)과 추론 시 병렬 세그먼트 생성 비용의 트레이드오프


## Ⅰ. 개요 및 필요성

LLM이 생성 중 자가 검증하는 RAG 기법이다. 기존 RAG는 모든 질문에 무조건 검색하여 불필요한 지연과 무관 문서 혼입이 발생한다. Self-RAG는 4종 반성 토큰을 통해 "검색 여부→관련성→일관성→유용성"을 자율 판정하며, 검색 호출을 40% 줄이면서도 정확도를 8.8%p 높인다.


## Ⅱ. 구조 및 구성요소

```text
┌──────────┐   ┌────────────┐   ┌────────────┐   ┌──────────┐
│  Input   │──▶│ LLM+반성   │──▶│ Retriever  │──▶│ Segment  │
│  Query   │   │ 토큰 판정  │   │ (조건부)   │   │ Selector │
└──────────┘   └────────────┘   └────────────┘   └──────────┘
                [Retrieve?]       [ISREL]          [ISSUP/ISUSE]
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Retrieve 토큰 | 검색 필요 여부 자율 판정 (Yes/No) | 단순 질문 시 검색 생략으로 지연 제거 |
| ISREL 토큰 | 검색 문서-질의 관련성 판정 | 문서별 관련/무관 이진 분류 |
| ISSUP 토큰 | 생성 텍스트-문서 일관성 판정 | 환각(문서에 없는 내용 생성) 탐지 |
| ISUSE 토큰 | 최종 답변 유용성 종합 평가 | 복수 세그먼트 중 최고 점수 선택 |

> 요약: 4종 반성 토큰이 검색 판단→관련성→일관성→유용성을 순차 판정하여 LLM이 자율적으로 RAG 파이프라인을 제어한다.


## Ⅲ. 동작원리 및 흐름도

```text
질의 입력 → LLM 생성 시작
  ├─ [Retrieve=No] → 내부 지식으로 직접 생성 → 출력
  └─ [Retrieve=Yes] → Top-K 검색
      → 문서별 [ISREL] 판정 → 관련 문서만 선별
      → 문서별 병렬 세그먼트 생성
      → [ISSUP] 일관성 판정 → [ISUSE] 유용성 평가
      → 최고 점수 세그먼트 선택 → 출력
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | LLM이 [Retrieve] 토큰으로 검색 필요 여부 판정 | 단순 질문 60% 이상 검색 생략 |
| 2 | 검색 실행 후 [ISREL]로 문서별 관련성 필터링 | 무관 문서 제거율 ≥70% |
| 3 | 관련 문서별 병렬 세그먼트 생성 + [ISSUP] 일관성 판정 | 문서-생성 불일치 탐지율 ≥80% |
| 4 | [ISUSE] 종합 평가로 최적 세그먼트 선택 출력 | PubHealth 정확도 81.2% |

> 요약: Retrieve→ISREL→ISSUP→ISUSE 4단계 자가 판정으로, 불필요한 검색을 생략하고 생성 품질을 사후 검증하여 정확도와 지연을 동시에 최적화한다.


## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 장점 | 검색 호출 40% 감소, 정확도 +8.8%p | 지연·비용·정확도 동시 개선 |
| 한계 | SFT에 크리틱 데이터 2~5만 건 필요, 병렬 세그먼트 생성으로 GPU 메모리 1.5~2배 | 학습 비용·추론 비용 증가 |
| Naive RAG 대비 | 고정 검색 vs 조건부 검색 + 자가 검증 | 질문 난이도 혼재 시 Self-RAG 우위 |
| CRAG 대비 | 사전 교정(Evaluator) vs 사후 반성(반성 토큰) | CRAG는 외부 모듈, Self-RAG는 LLM 내장 |

> 요약: Self-RAG는 검색·검증을 LLM 내부에 통합하여 외부 모듈 없이 자율 제어하지만, SFT 비용과 추론 메모리가 증가한다.


## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 사실 검증 시스템: PubHealth·FEVER 류 팩트체크에 Self-RAG 적용, 반성 토큰으로 근거-주장 일관성 자동 판정하여 정확도 81% 달성
2. 사내 챗봇: 단순 인사·FAQ는 검색 생략(Retrieve=No), 복잡 질의만 검색하여 평균 응답 지연 800ms→400ms 단축
3. 비용 최적화: 검색 API 호출 40% 감소로 월간 벡터 DB 쿼리 비용 $2,000→$1,200 절감, GPU 메모리는 A100 40GB 기준 1.5배 확보

**결론 (2줄):**
- 기술사 판단: 질문 난이도가 혼재된 서비스면 Self-RAG, 모든 질문이 지식 집약적이면 CRAG가 적합
- 향후 방향: 반성 토큰을 SFT 없이 프롬프트만으로 유도하는 연구(Prompt-based Reflection)가 진행 중이며, 학습 비용을 제거하는 방향으로 발전
