## 미리 알고가기

- Self-RAG는 모델이 검색 필요 여부와 답변 품질을 스스로 평가하는 self-reflection 기반 RAG 방식임
- 외부 evaluator 대신 모델 내부의 reflection 신호를 활용하는 점이 핵심 차이임
- 실제 구현은 모델 튜닝과 특수 토큰 설계가 필요해 단순 프롬프트 기법보다 무거움

## Ⅰ. 개요

- **정의/개념**: Self-RAG는 모델이 질의에 대해 검색이 필요한지, 검색된 문서가 유효한지, 생성한 답변이 근거에 의해 지지되는지를 스스로 평가하며 검색과 생성을 조절하는 자가 반성형 RAG 프레임워크임
- **배경/필요성**: 모든 질의에 항상 검색을 수행하면 비용이 크고, 외부 평가기를 붙이면 파이프라인 복잡도가 커지므로, 모델 내부에서 검색 필요성과 근거 적합성을 함께 판단하는 방식이 필요함

## Ⅱ. 특징

- 단순 질의에서는 검색을 생략하고 복합 질의에서만 검색을 수행해 비용을 줄일 수 있음
- 생성 과정 중 근거 적합성과 유용성을 스스로 평가해 self-correction 여지를 가짐
- 모델 튜닝이 필요하고 base model 접근성이 있어야 제대로 적용할 수 있음
- reflection 신호가 부정확하면 검색 우회나 과도한 검색이 모두 발생할 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | Naive RAG | Corrective RAG | Self-RAG |
|:---|:---|:---|:---|
| 검색 호출 방식 | 항상 수행 | 항상 수행 후 교정 | 필요 시 수행 |
| 평가 주체 | 없음 | 외부 evaluator | 모델 자신 |
| 파이프라인 복잡도 | 낮음 | 중간 | 높음 |
| 비용 최적화 | 낮음 | 중간 | 높음 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Reflection Policy | 검색 필요 여부와 근거 적절성을 판단하는 모델 내부 제어 신호를 담당함 |
| Retriever Interface | reflection 결과에 따라 실제 검색을 수행하거나 생략하는 경로를 제공함 |
| Evidence Scoring | 검색 문서와 생성 답변의 지지 관계를 평가해 품질을 통제함 |
| Final Decoding Logic | 반성 신호를 반영해 최종 답변 경로와 출력 내용을 선택함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 질의 분석/자가판단 | --> | 필요 시 검색 수행 | --> | 근거/답변 자가평가 | --> | 최종 응답 선택   |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **질의 분석 및 자가판단**: 모델이 검색 필요 여부를 먼저 결정함
2. **필요 시 검색 수행**: 검색이 필요하다고 판단되면 외부 지식 소스를 호출함
3. **근거 및 답변 자가평가**: 검색 문서와 생성 중인 답변을 자체 평가함
4. **최종 응답 선택**: 가장 근거가 충분한 답변 경로를 선택해 반환함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 모델이 검색이 필요한 질의까지 생략 판정하면 근거 없는 답변이 늘어날 수 있음
   - 해결방안: retrieval gating 임계값을 튜닝하고 bypass precision과 faithfulness로 검색 생략 품질을 검증함
2. 문제: self-reflection 신호를 안정적으로 학습시키기 위한 데이터 구축 비용이 높고 베이스 모델 수정이 필요할 수 있음
   - 해결방안: reflection 데이터셋을 단계적으로 확장하고 reflection accuracy와 training cost로 도입 타당성을 검증함
3. 문제: 내부 평가가 과도하게 보수적이면 불필요한 재검색과 반복 생성으로 latency가 급증할 수 있음
   - 해결방안: 최대 반성 횟수와 search budget을 제한하고 average retrieval count와 p95 latency로 비용 통제를 검증함

## Ⅶ. 적용 사례

- 혼합 질의형 금융 챗봇: 단순 질의는 바로 답하고 복합 규정 질의만 검색함, 확인 지표는 retrieval bypass rate와 hallucination rate임
- 내부 지식 도우미: 검색 문서 지지 여부를 함께 판단함, 확인 지표는 faithfulness와 answer usefulness임
- 오픈모델 연구 환경: self-reflection 기반 RAG 실험을 수행함, 확인 지표는 retrieval count와 benchmark score임

## Ⅷ. 결론

Self-RAG는 검색과 평가를 모델 내부 판단으로 끌어들인 구조이므로, 검색 비용 최적화 가능성이 큰 대신 reflection 품질이 전체 성능과 안정성을 좌우함.
