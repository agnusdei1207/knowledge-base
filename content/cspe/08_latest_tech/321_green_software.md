# 📖 【암기용】 개념 완전 이해

> 목적: Green Software를 소프트웨어가 유발하는 전력 사용과 탄소 배출을 설계·개발·운영 단계에서 줄이는 공학 원칙으로 이해하게 만든다.

## 한눈에
- **개요**: 소프트웨어 실행에 따른 전력·탄소·하드웨어 수명을 측정하고 줄이는 개발·운영 방식
- **왜 필요한가**: AI 학습, 데이터센터, 대규모 클라우드 서비스는 전력 사용과 탄소 배출이 비용·규제·ESG 보고 항목으로 연결된다.
- **핵심 직관**: 기능 요구사항에 성능·보안이 들어가듯, 탄소 배출량도 설계 제약으로 넣는 것이다.

## 깊이 이해
- **배경·문제의식**: 소프트웨어는 물리 장비에서 실행되므로 CPU, GPU, 메모리, 네트워크, 저장장치 사용량이 전력 소비와 탄소 배출로 이어진다.
- **작동 원리**: 에너지 사용량(kWh), 전력망 탄소집약도(gCO2e/kWh), 하드웨어 내재탄소, 기능 단위별 처리량을 측정하고 아키텍처·코드·스케줄링을 조정한다.
- **비유**: 자동차 연비를 운전 습관과 차량 설계로 관리하듯, 소프트웨어도 코드 경로와 배포 지역, 실행 시간을 조정해 배출량을 관리한다.
- **구체 예시**: 배치 학습 작업을 전력망 탄소집약도가 낮은 시간대로 이동하고 GPU 사용률을 계측하면 같은 기능 단위의 SCI 값을 낮출 수 있다.
- **흔한 오해·주의점**: Green Software는 화면을 어둡게 만드는 UI 주제가 아니다. 전력 측정, carbon intensity, embodied carbon, 기능 단위 기준이 있어야 한다.

## 연결 개념
- Software Carbon Intensity — 소프트웨어 탄소집약도 측정 표준
- Carbon-aware Scheduling — 전력망 탄소집약도에 맞춘 작업 시간·지역 조정
- Green Data Center — 데이터센터 전력·냉각·물 사용 최적화

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.
> 핵심: Green Software는 기능 단위당 탄소 배출을 측정하고 아키텍처·코드·배포·스케줄링으로 감축하는 소프트웨어 공학 관점임.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Green Software는 전력 사용량, 전력망 탄소집약도, 하드웨어 내재탄소를 소프트웨어 설계·운영 지표로 포함하는 접근임.
> 2. **가치**: 클라우드 비용, 탄소 보고, 데이터센터 전력 제약을 기능 단위 배출량으로 연결해 의사결정 근거를 제공함.
> 3. **판단 포인트**: 측정 범위, SCI 산식, carbon-aware 배치, 자원 우측정, 하드웨어 수명 관리가 핵심임.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 지속가능 소프트웨어 이해 확인 | 에너지, 탄소집약도, 내재탄소, 기능 단위 | 친환경 이미지 수준으로 설명 |
| 실무 적용 판단 확인 | 측정->개선->검증 루프 | 코드 최적화만 제시 |
| AI·클라우드 비용 연계 확인 | GPU, region, scheduling, utilization | 데이터센터 설비 문제로만 축소 |

> 요약: 이 문제는 소프트웨어가 물리 자원과 탄소 배출을 유발한다는 인과를 측정 지표로 설명해야 한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 탄소 고려 소프트웨어 공학
- 배경: 클라우드·AI 워크로드 증가로 소프트웨어 실행이 전력·탄소·하드웨어 교체 주기에 영향을 줌.
- 필요성: 기능 단위당 배출량을 측정해 비용, 탄소 보고, 전력 제약을 설계 의사결정에 반영해야 함.

---

## Ⅱ. 구조 및 구성요소

```text
Workload -> Resource Usage -> Energy(kWh) -> Carbon Intensity(gCO2e/kWh)
       +-> Embodied Carbon -> Functional Unit -> SCI / KPI
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 에너지 측정 | CPU/GPU/메모리/네트워크 전력 추정 | kWh, utilization |
| 탄소집약도 | 지역·시간별 전력망 배출계수 반영 | gCO2e/kWh |
| 내재탄소 | 장비 생산·폐기 배출량 배분 | embodied carbon |
| 기능 단위 | 사용자 요청·거래·학습 job 기준화 | SCI denominator |

> 요약: Green Software는 자원 사용을 에너지와 탄소로 환산한 뒤 기능 단위로 나눠 비교 가능한 지표를 만든다.

---

## Ⅲ. 동작원리 및 흐름도

```text
측정 범위 정의 -> 자원 사용량 수집 -> 에너지·탄소 환산
-> 병목 식별 -> 코드·아키텍처·스케줄 조정 -> SCI 재측정
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 서비스 경계와 기능 단위를 정의함 | transaction, request, job |
| 2 | 자원 사용량과 전력 데이터를 수집함 | kWh estimate |
| 3 | 지역·시간별 탄소집약도를 곱해 배출량을 계산함 | gCO2e |
| 4 | 자원 우측정, 캐시, 배치 이동, 모델 경량화를 적용함 | SCI trend |

> 요약: Green Software 개선은 측정 없는 선언이 아니라 기능 단위 배출량의 반복 측정으로 검증된다.

---

## Ⅳ. 특징

| 구분 | 전통적 최적화 | Green Software | 판단 기준 |
|:---|:---|:---|:---|
| 목표 | 지연·처리량·비용 | 기능 단위 탄소 배출 포함 | 탄소 보고 요구 |
| 지표 | p95, TPS, CPU | kWh, gCO2e, SCI | 배출량 측정 가능성 |
| 조치 | 코드·인프라 튜닝 | carbon-aware 배포·스케줄 포함 | 지역·시간 이동 가능성 |
| 한계 | 탄소 관점 미반영 | 사용자 SLA와 충돌 가능 | 지연 허용 범위 |

> 요약: Green Software는 기존 성능·비용 최적화에 탄소 배출 지표와 시간·지역 선택을 추가한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 측정 | 인프라 비용 중심 | 기능 단위 gCO2e | ESG·탄소 보고 |
| 설계 | 저지연 우선 | SLA 범위 내 배출량 감축 | batch 가능성 |
| 운영 | 고정 region | carbon intensity 기반 region/time | 데이터 주권·지연 제약 |

> 요약: SLA와 데이터 주권이 허용하는 범위에서 시간·지역·자원 선택을 탄소 지표와 결합한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 지표 왜곡 | 측정 경계 불명확 | 기능 단위와 포함 자원 명시 | boundary review |
| SLA 위반 | 배치 지연 과다 | 지연 허용 workload만 이동 | SLA violation |
| rebound effect | 절감 자원으로 사용량 증가 | 총배출량과 단위배출량 동시 관리 | total gCO2e, SCI |

> 요약: 단위 배출량만 낮추면 전체 사용량 증가를 놓칠 수 있어 총배출량과 SCI를 함께 봐야 한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 탄소 지표 | 기능 단위 SCI 추적 | SCI calculation |
| 자원 사용 | CPU/GPU utilization 관리 | telemetry, cloud metrics |
| 운영 효과 | 배치 이동 후 gCO2e 비교 | carbon intensity log |

> 요약: Green Software 성과는 비용 절감 주장보다 SCI, 총 gCO2e, 자원 사용률로 검증한다.

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 서비스별 기능 단위와 측정 경계를 정의하고 SCI 산식 기반으로 운영 배출량과 내재탄소를 월 단위로 산정함.
2. AI 학습·ETL·리포트 배치처럼 지연 허용 작업은 carbon-aware scheduling으로 저탄소 시간대 또는 region에 배치함.
3. 모델 경량화, 캐시, 데이터 이동 축소, 리소스 우측정, 하드웨어 수명 연장을 적용하고 p95·SLA와 SCI를 함께 검토함.

**결론 (2줄):**
- 기술사 판단: 지연 허용 workload와 대규모 GPU workload는 Green Software 적용 효과가 크며, 실시간 금융 거래는 SLA 범위 내 조치만 선택함.
- 향후 방향: Green Software는 FinOps, MLOps, ESG 공시와 결합해 비용·탄소·성능 동시 관리 체계로 발전함.
