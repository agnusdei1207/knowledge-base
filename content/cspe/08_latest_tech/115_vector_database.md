## 미리 알고가기

- 벡터 데이터베이스는 임베딩 벡터 저장과 근사 최근접 탐색에 최적화된 저장소임
- embedding 품질과 ANN 인덱스 품질이 검색 성능을 함께 결정함
- 단순 DB가 아니라 메타데이터 필터링과 대규모 ANN 인덱싱이 핵심 가치임

## Ⅰ. 개요

- **정의/개념**: 벡터 데이터베이스는 텍스트, 이미지, 음성 등 비정형 데이터를 임베딩 벡터로 저장하고, 유사도 계산과 ANN 탐색을 통해 의미 기반 검색을 빠르게 수행하는 특화 저장소임
- **배경/필요성**: RAG와 의미 검색이 확산되면서 관계형 DB만으로는 대량 벡터 유사도 검색을 실시간으로 처리하기 어려워졌기 때문에, 벡터 중심 인덱스와 검색 엔진이 필요해짐

## Ⅱ. 특징

- 대량 임베딩에 대해 millisecond 단위 근사 최근접 검색을 수행할 수 있음
- 메타데이터 필터와 결합해 권한, 날짜, 도메인 조건을 함께 적용할 수 있음
- ANN 인덱스 선택에 따라 memory 사용량과 recall과 latency trade-off가 달라짐
- 임베딩 품질이 나쁘면 벡터 DB는 빠르게 잘못된 문서를 찾아줄 뿐이라 upstream 품질 의존성이 큼

## Ⅲ. 종류 및 비교

| 판단 기준 | 관계형 DB 확장 | 전용 Vector DB | 검색엔진 플러그인 |
|:---|:---|:---|:---|
| 도입 단순성 | 높음 | 중간 | 중간 |
| 대규모 ANN 성능 | 낮음 | 높음 | 중간 |
| 운영 복잡도 | 낮음 | 높음 | 중간 |
| 대표 예시 | pgvector | Milvus, Qdrant, Pinecone | Elasticsearch vector |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Embedding Store | 문서 벡터와 원문 참조와 메타데이터를 함께 저장해 검색 기반을 형성함 |
| ANN Index | HNSW, IVF 같은 인덱스로 exact search보다 훨씬 빠른 근사 검색을 제공함 |
| Similarity Engine | cosine, dot product, L2 같은 거리 계산으로 후보 순위를 산출함 |
| Metadata, Filter Layer | tenant, ACL, 날짜, 카테고리 조건을 벡터 검색과 함께 적용해 실무 적합성을 높임 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 임베딩 저장      | --> | ANN 인덱스 구축  | --> | 유사도 검색 수행 | --> | 메타데이터 필터링 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **임베딩 저장**: 문서 임베딩과 원문 참조와 메타데이터를 저장함
2. **ANN 인덱스 구축**: 대량 벡터 검색을 위한 고속 인덱스를 생성함
3. **유사도 검색 수행**: 질의 벡터와 가까운 문서를 빠르게 탐색함
4. **메타데이터 필터링**: 권한과 범위 조건을 반영해 최종 후보를 반환함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 인덱스 설정이 부적절하면 latency는 빠르지만 recall이 낮거나, recall은 높지만 메모리 비용이 급증할 수 있음
   - 해결방안: HNSW, IVF 등 인덱스를 workload에 맞게 선택하고 recall@k와 p95 latency로 타협점을 검증함
2. 문제: metadata filtering이 벡터 검색과 잘 결합되지 않으면 권한 제어나 테넌트 분리가 약해질 수 있음
   - 해결방안: ACL-aware filtering을 지원하는 엔진을 선택하고 unauthorized retrieval rate와 query latency로 보안성을 검증함
3. 문제: 임베딩 모델이 바뀌면 기존 인덱스를 재생성해야 해 운영 전환 비용이 커질 수 있음
   - 해결방안: embedding versioning과 reindex 계획을 운영하고 reindex time과 migration quality gap으로 전환 비용을 검증함

## Ⅶ. 적용 사례

- 엔터프라이즈 RAG 저장소: 사내 문서 임베딩을 보관함, 확인 지표는 recall@k와 query latency임
- 멀티테넌트 검색 서비스: 고객별 벡터와 메타데이터를 분리함, 확인 지표는 tenant isolation과 cost per query임
- 대규모 지식 탐색: 검색엔진과 결합해 의미 검색을 수행함, 확인 지표는 throughput과 search quality임

## Ⅷ. 결론

벡터 데이터베이스는 단순 저장소가 아니라 임베딩 검색의 성능과 보안과 운영비를 동시에 결정하는 핵심 인프라이므로, ANN 인덱스와 메타데이터 필터 설계가 본질적 선택 기준임.
