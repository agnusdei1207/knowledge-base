# 📖 【암기용】 개념 완전 이해

> 목적: 에이전트 오케스트레이션을 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: 여러 Agent·Tool·Workflow의 실행 순서와 상태를 제어하는 체계
- **왜 필요한가**: 에이전트 업무는 계획, 분기, 재시도, 승인, 실패복구가 있어 단순 호출 체인으로 부족함.
- **핵심 직관**: 오케스트레이션은 AI 업무 자동화의 작업 관리자이자 교통 관제임.

## 깊이 이해
- **배경·문제의식**: Agent가 도구를 여러 번 호출하면 순서, 상태, 실패 처리, 비용 한도를 누가 관리할지 문제가 생김.
- **작동 원리**: Workflow 정의에 따라 Agent를 호출하고, 조건 분기·재시도·보상 트랜잭션·승인 단계를 실행함.
- **비유**: 항공 관제사가 항공기 이착륙 순서, 대기, 우회, 비상절차를 조정하는 구조.
- **구체 예시**: 장애 대응에서 로그분석 Agent → 원인분석 Agent → 조치제안 Agent → 승인 → 자동조치 순서로 실행함.
- **흔한 오해·주의점**: 모델이 계획을 만든다고 해서 런타임 오케스트레이션이 사라지지 않으며 상태 저장과 실패복구가 필요함.

## 연결 개념
- Workflow Engine — 순서·분기·상태 관리
- Saga Pattern — 실패 시 보상 처리
- Agent Observability — 실행 경로 추적

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Agent Orchestration은 Agent·Tool·승인 단계를 정책 기반 워크플로우로 제어하는 실행 체계임.
> 2. **가치**: 다단계 AI 업무에서 순서, 상태, 재시도, 실패복구, 감사 추적을 보장함.
> 3. **판단 포인트**: 모델 계획과 런타임 상태관리를 분리하고 승인·보상·관측성을 설계해야 함.

---

## Ⅰ. 개요 및 필요성

에이전트 오케스트레이션은 AI 실행 제어 체계임. AI 에이전트 업무가 다단계로 확장되면서 순서, 분기, 실패복구, 승인, 로그 관리가 필요함.

---

## Ⅱ. 구조 및 구성요소

```text
Workflow Definition → Orchestrator → Agent/Tool Step
          │                │              │
          ▼                ▼              ▼
       Policy          State Store      Audit Log
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Workflow | 단계·분기 정의 | 승인·재시도 포함 |
| Orchestrator | 실행 순서 제어 | timeout, retry, queue |
| State Store | 진행상태 저장 | 재시작·복구 근거 |
| Audit Log | 실행 이력 기록 | Trace ID, 승인자 |

> 요약: 오케스트레이션은 워크플로우, 실행기, 상태저장소, 감사로그로 AI 업무를 제어함.

---

## Ⅲ. 동작원리 및 흐름도

```text
목표 입력 → 워크플로우 선택 → Step 실행 → 상태 저장
        → 조건 분기/승인 → 실패복구 → 완료 기록
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 워크플로우 선택 | 업무유형, 위험등급 |
| 2 | Agent/Tool 실행 | 응답코드, p95 지연 |
| 3 | 분기·승인 처리 | 정책 일치, 승인 이력 |
| 4 | 복구·완료 | 재시도 횟수, 보상처리 |

> 요약: 오케스트레이션은 단계 실행 결과를 상태로 저장하고 조건에 따라 다음 행동을 결정함.

---

## Ⅳ. 특징

| 구분 | 단순 Agent 호출 | Agent Orchestration | 수치·판단 포인트 |
|:---|:---|:---|:---|
| 실행 | 단일 요청 중심 | 다단계 Workflow | 단계 수, 완료율 |
| 상태 | 모델 컨텍스트 의존 | 외부 State Store | 재시작 성공률 |
| 장애 | 실패 시 중단 | 재시도·보상 처리 | 실패복구 시간 |

> 요약: 오케스트레이션은 AI 실행을 운영 가능한 워크플로우로 전환하되 설계 복잡도를 증가시킴.

---

## Ⅴ. 실무 적용 및 결론

**적용 방안 3개:**
1. 조회형, 변경형, 승인형 워크플로우를 분리하고 변경형에는 보상 트랜잭션 정의
2. Step별 timeout, retry 횟수, circuit breaker, idempotency key를 설정
3. State Store와 Audit Log를 분리하고 Trace ID로 Agent·Tool·승인 단계를 연결

**결론 (2줄):**
- 기술사 판단: 업무 결과가 시스템 상태를 바꾸면 Agent Orchestration을 적용하고 단순 검색은 경량 체인으로 처리함.
- 향후 방향: 오케스트레이션은 LLMOps, SRE, 보안정책 엔진과 결합한 AI 런타임으로 발전함.
