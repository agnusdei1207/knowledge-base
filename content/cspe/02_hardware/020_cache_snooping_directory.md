# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 버스 스누핑과 디렉터리 기반 일관성은 **멀티코어 캐시 일관성 프로토콜**(MESI 등, 019 참조)의 상태 변화를 타 코어에 전달하는 **통신 아키텍처**임.
- **왜 필요한가**: MESI가 '무엇을 통신할지(상태 전이 규칙)'를 정했다면, 이 두 방식은 '어떻게 배달할지(전파 토폴로지)'를 정함. 코어 수에 따라 적합한 전파 방식이 달라지므로 선택 설계가 필요함.
- **핵심 직관**: 스누핑은 "조별 과제 4명이 모여 허공에 외치는 단톡방(Broadcast)" — 빠르지만 인원이 많으면 과부하. 디렉터리는 "중앙 대출 장부를 조회해 해당자에게만 DM을 보내는 도서관(Unicast)" — 지연은 있지만 트래픽이 통제됨.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 캐시 일관성 통신 (상위 키워드) | MESI 상태를 코어 간에 전달하는 메커니즘 | "상태 변화를 배달하는 택배 시스템" |
| 공유 버스 (Shared Bus) | 모든 코어가 연결된 단일 통신선, 한 명이 말하면 모두가 수신 | "동네 마을 방송망" |
| 스누핑 (Snooping) | 공유 버스의 트랜잭션을 각 캐시 컨트롤러가 감시하는 행위 | "라디오 수신" |
| 브로드캐스트 (Broadcast) | 버스에 연결된 모든 캐시에 메시지를 무차별 송출 | "전체 공지" |
| 디렉터리 (Directory) | 메모리 블록마다 어느 코어가 보유 중인지 기록한 중앙 장부 | "도서관 대출 원부" |
| 유니캐스트 (Unicast) | 디렉터리가 특정 코어에게만 메시지를 전송 | "개인 DM" |
| 홈 노드 (Home Node) | 디렉터리 장부를 관리하는 메모리 컨트롤러 | "대출 데스크 담당자" |

## 깊이 이해
- **배경·문제의식**: 019에서 설명한 MESI 프로토콜이 동작하려면 타 코어의 상태를 알아야 함. 초기 멀티코어(2~8코어)는 공유 버스 1개로 스누핑하면 충분했으나, 매니코어(32~128코어) 시대에 코어 1개의 쓰기마다 전체 코어에 브로드캐스트하면 인터커넥트 대역폭이 O(N)으로 증가하여 물리적 한계에 도달함.
- **작동 원리**:
  - **버스 스누핑**: 모든 캐시 컨트롤러가 버스를 실시간 감시함. 코어 A가 주소 X를 수정한다고 버스에 Invalidate를 흘리면, 버스를 감시하던 코어 B·C가 자기 캐시의 Tag를 비교하여 X가 있으면 I 상태로 강등함. 중앙 통제 없이 자율 동작하므로 지연이 극히 짧음.
  - **디렉터리 기반**: 메모리 컨트롤러 옆에 디렉터리(SRAM)를 배치함. 코어 A가 쓰기 요청을 홈 노드에 보내면, 디렉터리가 비트벡터를 조회하여 "코어 B가 S 상태로 보유 중"임을 파악하고, 코어 B에게만 Invalidate 유니캐스트를 발송함. 코어 B의 Ack를 받은 후 코어 A에 쓰기 승인을 전달함(3-hop 최소 지연).
- **비유**: 스누핑은 4인 그룹채팅(빠르나 인원 증가 시 알림 공해), 디렉터리는 게시판 관리자가 읽은 사람 명단을 확인 후 해당자에게만 개인 DM 발송(느리지만 채널은 조용함).
- **구체 예시**: 64코어 서버에서 1회 쓰기 시 — 스누핑: 63개 코어에 브로드캐스트(63개 버스 트랜잭션), 디렉터리: 장부 조회 후 실제 보유 코어 2개에만 유니캐스트(2개 메시지 + Ack 2개).
- **흔한 오해·주의점**: 디렉터리 방식이 무조건 빠른 것은 아님. 단일 트랜잭션 지연(Latency)은 스누핑이 우위(1-hop vs 3-hop). 디렉터리의 장점은 전체 시스템 스루풋(Throughput)의 확장성에 있으므로, 코어 수 규모에 따라 적합한 방식이 다름.

## 연결 개념
- **019 MESI 프로토콜**: 스누핑·디렉터리가 '배달 방법'이라면, MESI는 '배달할 내용(상태 전이 규칙)'임.
- **026 NUMA**: 멀티소켓 NUMA 서버에서는 디렉터리 기반(ccNUMA) 없이는 소켓 간 일관성 유지가 불가능함.
- **058 칩렛**: AMD EPYC 등 다이 간 통신에 스누프 필터(간이 디렉터리)를 적용하여 불필요한 브로드캐스트를 차단함.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 멀티코어 캐시 일관성 유지를 위한 통신 아키텍처로, 브로드캐스트 기반 스누핑과 중앙 장부 기반 디렉터리로 양분됨.
> 2. **가치**: 스누핑은 저지연(1-hop)으로 소규모 코어에 적합하고, 디렉터리는 점대점 메시징으로 매니코어·NUMA 환경의 확장성을 보장함.
> 3. **판단 포인트**: 현대 아키텍처는 칩 내부는 스누핑, 소켓 간은 디렉터리를 사용하는 하이브리드(계층적) 구조를 채택함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 캐시 통신 아키텍처의 트레이드오프 파악 | 브로드캐스트(스누핑) vs 유니캐스트(디렉터리) 통신 구조 차이 | MESI 상태 설명만 반복하고 통신 구조 설명 누락 |
| 확장성(Scalability) 한계 논리 도출 | 코어 수 증가에 따른 O(N) 버스 병목 근거 | 디렉터리가 무조건 지연이 짧다고 오기 |

> 요약: 스누핑은 "저지연이나 확장 불가한 브로드캐스트", 디렉터리는 "고지연이나 트래픽 통제 가능한 유니캐스트"라는 대조를 명확히 제시해야 함.

## Ⅰ. 개요 및 필요성

- 개요: 캐시 일관성 유지방식은 MESI 등 프로토콜의 상태 변화를 코어 간에 전달하는 통신 토폴로지로, 스누핑과 디렉터리 기반으로 구분됨.
- 배경: 스누핑 브로드캐스트 트래픽이 코어 수(N)에 비례하여 O(N)으로 증가하여 인터커넥트 대역폭의 물리적 한계에 도달함.
- 필요성: 코어 수·소켓 수에 따라 응답 시간(Latency) 최적화와 대역폭(Bandwidth) 확장성 중 적합한 통신 방식을 선택 설계해야 함.

---

## Ⅱ. 구조 및 구성요소

```text
[스누핑] 코어1, 코어2, 코어3 -- 공유 버스(Broadcast) -- 메모리
[디렉터리] 코어1, 코어2, 코어3 -- Point-to-Point 망 -- 디렉터리 장부 -- 메모리
```

| 구성요소 | 스누핑 방식 | 디렉터리 방식 |
|:---|:---|:---|
| 통신 매개체 | 공유 버스(Shared Bus) | 디렉터리 SRAM + P2P 인터커넥트 |
| 전파 범위 | 전체 코어 브로드캐스트 | 보유 코어에만 유니캐스트 |
| 상태 저장 위치 | 각 캐시 컨트롤러(분산) | 중앙 디렉터리 비트벡터(집중) |

> 요약: 스누핑은 버스(Line)를 통해 전체 코어가 동시 수신하고, 디렉터리는 장부(Node)를 통해 대상 코어만 타겟팅함.

---

## Ⅲ. 동작원리 및 흐름도

```text
[스누핑] 코어A Write -> 버스에 Invalidate 브로드캐스트 -> 전 코어 Tag 비교 -> 해당 코어 I 강등 -> 코어A M 승격
[디렉터리] 코어A Write -> 홈 노드에 권한 요청 -> 장부 조회(보유 코어 식별) -> 해당 코어에 Invalidate 유니캐스트 -> Ack 수신 -> 코어A M 승격
```

- 1단계 [쓰기 요청]: 코어 A가 주소 X를 수정하기 위해 Invalidate 요청을 발생시킴.
- 2단계 [전파]: 스누핑은 버스 브로드캐스트(1-hop), 디렉터리는 홈 노드 경유 유니캐스트(3-hop: 요청→디렉터리→대상→Ack)
- 3단계 [무효화]: 주소 X를 보유한 코어가 I 상태로 강등하고 Ack를 전송함.
- 4단계 [승인]: 스누핑은 버스 응답 즉시, 디렉터리는 Ack 수집 후 코어 A에 쓰기 승인을 전달하여 M 전이 완료.

> 요약: 스누핑은 중앙 통제 없이 자율적으로 1-hop에 완료되나, 디렉터리는 중앙 장부를 거치므로 최소 3-hop의 지연이 발생함.

---

## Ⅳ. 특징
- 스누핑 병목: 단일 트랜잭션 지연은 극히 짧으나, 코어 수가 8~16개를 초과하면 버스 트래픽이 포화되어 전체 시스템 확장 불가
- 디렉터리 메모리 오버헤드: 코어 N개 기준 메모리 블록당 N비트의 비트벡터가 필요하여 SRAM 면적 증가(128코어 시 블록당 128비트)
- 확장성 역전: 소규모(4~8코어)에서는 스누핑이 성능 우위이나, 대규모(64코어 이상)에서는 디렉터리만이 선형적 성능 확장을 유지함.

---

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 버스 스누핑 | 디렉터리 기반 | 선택 기준 |
|:---|:---|:---|:---|
| 통신 방식 | 브로드캐스트(전체 코어) | 유니캐스트(보유 코어만) | 코어 확장 규모 |
| 단일 지연 | 1-hop(버스 직접 감시) | 3-hop(요청→장부→대상→Ack) | 응답 시간 민감도 |
| 확장성 | O(N) 트래픽으로 8~16코어 한계 | 점대점으로 수백 코어 확장 가능 | 물리적 코어·소켓 수 |
| 대표 적용 | 4~8코어 UMA(데스크톱/모바일) | 64코어 이상 NUMA(서버/HPC) | 시스템 규모 |

> 요약: 데스크톱·모바일은 스누핑, 서버·HPC는 디렉터리를 기본으로 하되, 현대 CPU는 칩 내부 스누핑 + 소켓 간 디렉터리의 하이브리드를 채택함.

**리스크·대응:**
- 디렉터리 SRAM 오버헤드: 128코어 시 블록당 128비트 비트벡터 → 성긴 디렉터리(Sparse Directory)로 활성 엔트리만 관리하여 SRAM 5% 이내로 억제
- 홈 노드 병목: 특정 메모리 영역의 디렉터리에 요청 집중 → 메모리 주소 해싱으로 디렉터리를 여러 노드에 분산 배치 (지표: 노드 간 메시지 지연 편차)

**점검 지표:**
- 성능: 인터커넥트 대역폭 사용률(Intel PCM·AMD μProf로 측정)
- 운영: 코어 간 캐시 일관성 트래픽 비율(전체 대역폭 대비 스누핑 트래픽 %)

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 하이브리드 계층 설계: Intel Xeon 서버에서 칩 내부는 Mesh 기반 스누핑, 2/4소켓 간은 UPI 링크의 디렉터리 방식을 조합하여 지연·확장성을 동시 확보
2. ccNUMA 일관성 보장: 빅데이터 서버(Hadoop/Spark) 운영 시 다중 노드 메모리 일관성을 디렉터리 기반 ccNUMA로 보장하여 원격 메모리 접근의 정합성 유지
3. 칩렛 인터커넥트 최적화: AMD EPYC의 Infinity Fabric에 스누프 필터(간이 디렉터리)를 다이 간에 배치하여 불필요한 브로드캐스트를 차단하고 대역폭 절감

**결론:**
- 기술사 판단: 코어 수 4~8개는 스누핑, 32코어 이상은 디렉터리, 중간 규모는 스누프 필터 기반 하이브리드가 적합하며, 시스템 규모에 따른 통신 아키텍처 선택이 성능의 핵심 변수임.
- 향후 방향: 칩렛·CXL 등 이종 다이 통합이 확산되면서, Mesh/Ring 네트워크 위에 계층적 스누프 필터를 배치하는 확장 가능한 하이브리드 프로토콜이 표준으로 자리잡는 추세임.
