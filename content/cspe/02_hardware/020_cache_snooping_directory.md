## Ⅰ. 개요
- **정의**: 멀티프로세서 캐시 일관성을 유지하는 두 가지 방식으로, 버스 감시(스누핑)와 중앙 디렉터리 기반 추적 기법
- **배경/필요성**: 코어 수 증가에 따라 브로드캐스트 기반 스누핑의 한계가 드러나, 포인트 투 포인트 통신 기반 디렉터리가 대안으로 부상함
- **비유**: 스누핑은 회의실에서 모두가 대화를 엿듣는 방식, 디렉터리는 관리자가 누가 무슨 자료를 가졌는지 명부로 추적하는 방식

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 두 방식의 구조적 차이와 확장성 비교 | 브로드캐스트 vs 유니캐스트 통신 모델 | 스누핑이 소규모에서 유리한 이유를 대역폭 관점으로 설명할 것 |

> 요약: 스누핑과 디렉터리는 통신 모델이 다르며, 코어 규모에 따라 적합한 방식이 달라짐

## Ⅱ. 구성요소
```text
[스누핑 방식]                    [디렉터리 방식]
Core0  Core1  Core2              Core0  Core1  Core2
  |      |      |                  |      |      |
  +------+------+                  +------+------+
     Shared Bus                     Interconnect
         |                              |
     Main Memory                  +-----------+
                                  | Directory |
                                  +-----------+
                                       |
                                  Main Memory
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 스누핑 컨트롤러 | 각 캐시에 내장되어 버스 트랜잭션을 감시하고, 자기 캐시 라인 상태를 갱신하는 하드웨어 | 회의 참석자가 모든 발언을 들으며 자기 메모를 수정하는 역할 |
| 공유 버스 | 모든 코어가 연결된 단일 브로드캐스트 채널로, 스누핑 트래픽을 전달함 | 모두가 들을 수 있는 확성기 |
| 디렉터리 테이블 | 메모리 블록별 캐시 보유 코어 목록과 상태를 기록하는 중앙 자료구조 | 도서관 대출 장부 |
| 포인트 투 포인트 인터커넥트 | 코어 간 1:1 메시지 전달 네트워크로, 필요한 코어에만 무효화 요청을 전송함 | 지정 수신자에게만 보내는 편지 |

> 요약: 스누핑은 버스+감시, 디렉터리는 테이블+유니캐스트로 일관성을 유지함

## Ⅲ. 절차
```text
1. 코어가 캐시 미스 또는 쓰기 요청 발행
          |
          v
2-A. 스누핑: 버스 브로드캐스트
2-B. 디렉터리: 디렉터리 조회 후 해당 코어에만 메시지 전송
          |
          v
3. 보유 코어가 응답(데이터 전달 또는 무효화 확인)
          |
          v
4. 상태 갱신 완료 및 데이터 공급
```
- 1단계: 코어가 읽기/쓰기 요청을 발행하고, 로컬 캐시에서 미스가 발생함
- 2단계: 스누핑은 버스에 브로드캐스트하여 모든 코어가 감지하고, 디렉터리는 테이블을 조회하여 해당 코어에만 유니캐스트함
- 3단계: 해당 라인을 보유한 코어가 데이터를 전달하거나 무효화를 수행하고 응답함
- 4단계: 요청 코어의 캐시 라인 상태가 갱신되고, 디렉터리 방식은 테이블도 함께 갱신함

> 요약: 스누핑은 브로드캐스트, 디렉터리는 유니캐스트로 무효화·공급 절차를 수행함

## Ⅳ. 문제점
- 스누핑 대역폭 한계: 코어가 16개를 초과하면 버스 트래픽이 포화되어 스누핑 지연이 급증함
- 디렉터리 저장 오버헤드: 메모리 블록당 코어 비트벡터를 유지하므로, 코어 수에 비례하여 디렉터리 용량이 증가함
- 디렉터리 접근 지연: 홈 노드까지 왕복 메시지가 추가되어, 소규모 시스템에서는 스누핑보다 지연이 큼

> 요약: 스누핑은 확장성, 디렉터리는 저장 비용과 지연이 각각 병목임

## Ⅴ. 개선방안
1. 단기: 스누핑 필터(Snoop Filter)를 도입하여 불필요한 브로드캐스트를 사전 차단, 버스 트래픽 감소
2. 중기: 제한 포인터(Limited Pointer) 기법으로 디렉터리 비트벡터 크기를 고정하여 저장 오버헤드 억제
3. 장기: 계층적 프로토콜(클러스터 내 스누핑 + 클러스터 간 디렉터리) 적용으로 두 방식의 장점을 결합, 지연과 확장성을 동시 확보

> 요약: 스누핑 필터·제한 포인터·계층적 결합으로 각 방식의 단점을 보완함

## Ⅵ. 전망
- 발전 방향: 칩렛 기반 멀티다이 아키텍처에서 다이 내 스누핑 + 다이 간 디렉터리 하이브리드가 표준화되는 추세임
- 기술사적 판단: CXL(035 참조) 등 이기종 인터커넥트 확산으로 디렉터리 기반 일관성 도메인이 CPU 외부 디바이스까지 확장됨
- 기술사 제언: 시스템 규모와 워크로드 특성에 따라 스누핑과 디렉터리의 적용 범위를 구분 설계할 필요
