# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: PCIe 스위칭은 하나의 CPU(Root Complex) 포트에 여러 대의 주변 장치(Endpoint)를 연결하고, 장치 간 데이터 패킷을 라우팅해주는 고속 확장 아키텍처이다.
- **왜 필요한가**: CPU가 제공하는 PCIe 레인(Lane) 수는 한정되어 있다. 여러 대의 GPU나 NVMe SSD를 꽂으려면, USB 허브처럼 하나의 포트를 여러 개로 나누어주는 네트워크 스위치가 필요하다.
- **핵심 직관**: 우체국(Root Complex)에서 나오는 큰 길 하나를 동네 교차로(PCIe 스위치)에서 여러 골목(Endpoint)으로 분배해주는 것과 같다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 루트 콤플렉스 (Root Complex) | CPU와 메모리를 PCIe 버스 시스템에 연결하는 최상위 노드 | 우체국 본점 |
| 엔드포인트 (Endpoint) | PCIe 버스의 끝단에 연결되는 실제 주변 장치 | 각 가정집 (GPU, SSD) |
| 업스트림/다운스트림 포트 | 스위치에서 CPU 쪽을 향하는 포트(Up)와 장치 쪽을 향하는 포트(Down) | 상행선 / 하행선 |
| NTB (Non-Transparent Bridge) | 두 개 이상의 서로 다른 CPU(Host)가 스위치를 공유하게 해주는 격리 장치 | 두 우체국 사이의 완충 구역 |

## 깊이 이해
- **배경·문제의식**: 과거 PCI 버스는 여러 장치가 하나의 선을 공유하는 '공유 버스' 방식이라 병목이 심했다. 이를 점대점(Point-to-Point) 직렬 연결인 PCIe로 바꾸면서 속도는 빨라졌으나, CPU 포트 수가 부족해지는 문제가 생겼다.
- **작동 원리**: PCIe 스위치는 내부에 여러 개의 가상 PCI-to-PCI 브리지를 가진 구조다. 패킷이 들어오면 헤더의 주소를 읽고 올바른 다운스트림 포트로 라우팅한다. 또한 Peer-to-Peer(P2P) 통신을 지원하여, CPU를 거치지 않고 GPU와 NVMe SSD가 직접 데이터를 주고받을 수 있다.
- **비유**: 공유기(스위치)에 랜선 하나(업스트림)를 꽂고, 여러 대의 PC(엔드포인트)를 연결하는 것과 똑같은 원리다. PC끼리 파일 전송(P2P)을 할 때는 외부 인터넷(CPU)을 안 거쳐도 된다.
- **구체 예시**: AI 서버에서는 CPU 하나에 GPU 8대를 꽂을 수 없다. 따라서 PCIe 스위치(예: Broadcom PLX) 칩을 메인보드에 달아 CPU의 16레인을 64레인으로 확장하여 GPU들을 연결한다.
- **흔한 오해·주의점**: 스위치를 쓴다고 CPU의 '전체 대역폭'이 늘어나는 것은 아니다. CPU와 스위치 사이의 병목(업스트림 대역폭)은 여전히 존재하며, 장치 간(P2P) 트래픽에서만 큰 이득을 본다.

## 연결 개념
- 루트 콤플렉스(Root Complex) — 스위치 트리의 최상위 제어자
- GPUDirect / RDA — PCIe 스위치의 P2P 기능을 활용해 CPU를 우회하는 고속 전송 기술
- CXL (Compute Express Link) — PCIe 물리 계층 위에 캐시 일관성을 더한 최신 프로토콜

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: PCIe 스위칭 아키텍처는 점대점(Point-to-Point) 연결의 물리적 한계를 극복하기 위해 다수의 엔드포인트를 패킷 라우팅 기반으로 확장하는 트리 토폴로지 구조이다.
> 2. **가치**: 제한된 CPU PCIe 레인 한계를 넘어 대규모 GPU/NVMe 확장을 가능하게 하며, P2P 통신으로 CPU 개입을 최소화한다.
> 3. **판단 포인트**: 다중 호스트(Multi-Host) 연결 시 주소 충돌을 막기 위한 NTB(Non-Transparent Bridge) 기술과, 스위치 토폴로지에 따른 지연 시간 관리가 핵심이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| PCIe의 확장 한계 극복 원리 이해 | 패킷 라우팅, 업스트림/다운스트림 포트, 가상 PCI 브리지 | 구형 공유 버스(PCI)와 혼동하여 서술 |
| 최신 AI/빅데이터 서버 아키텍처 응용 | P2P 통신(CPU 우회), NTB 기반 Multi-Host 아키텍처 | NTB의 개념(주소 변환) 누락 |

> 요약: 트리 구조를 통한 포트 확장과 더불어 P2P 통신 및 NTB를 활용한 아키텍처 유연성을 성능 최적화 관점으로 풀어낸다.

## Ⅰ. 개요 및 필요성

- 개요: PCIe 스위칭 아키텍처는 하나의 업스트림 포트를 다수의 다운스트림 포트로 확장하여, PCIe 패킷을 목적지 엔드포인트로 라우팅하는 기술이다.
- 배경: PCIe는 점대점(Point-to-Point) 토폴로지이므로 한 포트에 하나의 장치만 연결 가능하여 대규모 확장이 불가능함
- 필요성: AI 서버와 고성능 스토리지 시스템에서 다수의 GPU 및 NVMe를 연결하고, CPU 병목을 피하기 위해 필수적임

---

## Ⅱ. 구조 및 구성요소

```text
Host CPU (Root Complex)
           |
    [ Upstream Port ]
    [ PCIe Switch ] ──> P2P 통신 ──┐
   /                \              |
[Downstream Port] [Downstream Port]|
        |                 |        |
    Endpoint(GPU)     Endpoint(NVMe)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 루트 콤플렉스 (RC) | 메모리, CPU를 PCIe 패브릭에 연결 | 트리 토폴로지의 최상위 지점 |
| PCIe 스위치 | 주소 기반 패킷 라우팅 수행 | 내부에 가상 PCI-to-PCI 브리지 모음 포함 |
| 엔드포인트 (EP) | 트리의 말단에 위치한 실제 장치 (GPU 등) | 리퀘스터(Requester) 또는 컴플리터(Completer) 역할 |
| NTB (Non-Transparent Bridge) | 호스트 간 독립된 메모리 주소 공간 격리 및 변환 | Multi-Host 페일오버 및 클러스터링 지원 |

> 요약: 스위치 내부는 여러 가상 브리지의 집합으로 이루어져 있으며, 패킷의 메모리/I/O 주소를 해독하여 라우팅한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
패킷 수신 -> 주소 디코딩 -> 라우팅 경로 결정 -> 패킷 전송 (P2P 또는 RC 전달)
```

- 1단계 [패킷 수신]: 특정 포트(업스트림 또는 다운스트림)로 트랜잭션 계층 패킷(TLP)이 유입됨
- 2단계 [주소 디코딩]: 스위치 내부의 라우팅 테이블(Base/Limit 주소 레지스터)과 패킷 헤더 비교
- 3단계 [경로 결정]: 패킷 목적지가 다른 다운스트림 포트면 P2P 라우팅, 아니면 업스트림 포트로 전달
- 4단계 [패킷 전송]: 가상 채널(VC) 및 트래픽 클래스(TC) 우선순위에 따라 큐를 거쳐 목적지로 전송

> 요약: 스위치는 호스트 메모리 맵과 일치하는 라우팅 테이블을 기반으로 TLP 패킷을 정확한 포트로 분배한다.

---

## Ⅳ. 특징
- 유연한 토폴로지 확장: 데이지 체인 방식이나 트리 방식으로 이론상 최대 256개 버스, 32개 장치까지 계층적 확장 가능
- Peer-to-Peer (P2P) 통신: 장치 간 데이터 교환 시 루트 콤플렉스(CPU/메모리)를 거치지 않아 지연 시간과 CPU 부하 최소화
- 주소/ID 기반 라우팅: 메모리/IO 트랜잭션은 주소 기반으로, 설정(Configuration) 트랜잭션은 버스/장치/기능(BDF) ID 기반으로 라우팅

> 요약: PCIe 스위칭은 단순한 신호 분기가 아니라, 계층적 주소 기반 라우팅과 P2P 직접 통신을 지원하는 지능형 패브릭이다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 공유 버스 (PCI/PCI-X) | PCIe 스위칭 아키텍처 | 선택 기준 |
|:---|:---|:---|:---|
| 토폴로지 | 모든 장치가 하나의 버스 라인 공유 | Point-to-Point 기반 스타/트리 토폴로지 | 대역폭 및 확장성 |
| 충돌/중재 | 버스 중재기 필요, 동시 통신 불가 | 패킷 스위칭으로 여러 경로 동시 통신 가능 | 동시 다발적 I/O 발생 여부 |
| 단일 장애점 | 버스 오류 시 전체 시스템 마비 | 오류가 발생한 포트/링크만 격리 가능 | 가용성 및 격리 수준 |

> 요약: 공유 버스의 한계를 스위칭 패브릭 구조로 극복하여, 충돌 없이 고대역폭 다중 통신이 가능해졌다.

**PCIe 스위치 아키텍처 리스크·대응:**
- [업스트림 병목]: 다수 장치가 동시 호스트 접근 시 업스트림 링크 대역폭 고갈 → [대응 방안] 오버서브스크립션(Oversubscription) 비율 관리 및 P2P 트래픽 유도
- [다중 호스트 충돌]: 2개 이상 CPU가 스위치 공유 시 주소 맵핑 충돌 → [대응 방안] NTB(Non-Transparent Bridge)로 도메인을 분리하여 주소 변환 (지표: 호스트 간 페일오버 시간)

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. AI 클러스터링: NVIDIA HGX/DGX 보드 설계 시 PCIe 스위치를 통해 다수의 GPU와 로컬 NVMe를 묶고, P2P(GPUDirect)로 딥러닝 학습 속도 극대화
2. JBOF (Just a Bunch of Flash) 구성: 스토리지 전용 섀시에 PCIe 스위치를 내장하여 24~48개의 NVMe SSD를 고집적화하고 성능 병목 제거
3. 고가용성(HA) 아키텍처: 두 대의 서버(Dual Host)를 NTB 기능이 있는 스위치로 연결하여, 한 서버 장애 시 즉각적인 스토리지 페일오버(Fail-over) 구현

**결론 (2줄):**
- 기술사 판단: PCIe 스위치는 단순 확장을 넘어 CPU 우회 통신(P2P)과 호스트 격리(NTB)를 제공하므로, 고성능 AI 및 스토리지 팜 설계의 핵심 인프라 기술이다.
- 향후 방향: 차세대 아키텍처는 PCIe 물리 계층을 활용하면서 캐시 일관성을 제공하는 CXL(Compute Express Link) 스위치로 진화하여 메모리 풀링 시대를 열 것이다.
