## 미리 알고가기

- PCIe는 point-to-point 방식의 고속 직렬 I/O 인터페이스임
- Root Complex는 CPU 쪽 PCIe 트리의 시작점임
- ACS는 장치 간 DMA 경로를 분리하는 접근 제어 기능임

## Ⅰ. 개요

- **정의/개념**: PCIe 스위칭 아키텍처는 Root Complex와 여러 endpoint 사이에 PCIe switch를 두어 제한된 상위 링크를 다수 장치로 분기하고 패킷을 라우팅하는 확장형 I/O 구조임
- **배경/필요성**: GPU와 NVMe와 NIC 수요는 계속 늘지만 CPU가 직접 제공하는 PCIe 레인 수는 한정돼 있으므로, 다수 장치 분기와 유연한 배치를 위해 스위치 기반 확장이 필요함

## Ⅱ. 특징

- 상위 링크 하나로 여러 장치를 수용해 확장성이 높음
- PCIe의 point-to-point 구조를 유지하면서 패킷 라우팅과 오류 보고를 수행함
- 상위 링크를 공유하므로 oversubscription이 쉽게 생김
- P2P 전송과 ACS와 hot-plug 지원 여부가 실제 설계 품질에 큰 영향을 줌

## Ⅲ. 종류 및 비교

| 판단 기준 | 직접 연결 | PCIe 스위칭 |
|:---|:---|:---|
| 확장성 | CPU 레인 수에 직접 제한됨 | 스위치를 통해 다수 장치로 분기 확장이 가능함 |
| 지연 | hop이 없어 가장 낮음 | switch hop과 버퍼링 때문에 지연이 늘어남 |
| 대역폭 구조 | 장치별 전용 경로 확보가 쉬움 | 상위 링크 공유로 병목과 oversubscription이 생길 수 있음 |
| 운영 기능 | 구조가 단순해 관리가 쉬움 | P2P와 격리와 오류 보고 같은 고급 기능을 설계에 반영할 수 있음 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Root Complex | 시스템 메모리 공간과 PCIe 계층을 연결하는 상위 기준점임 |
| upstream port | 스위치가 CPU 쪽과 통신하는 상위 공유 경로로 전체 장치 집합의 병목이 될 수 있음 |
| downstream port | GPU와 NVMe와 NIC 같은 endpoint를 개별 포트로 수용함 |
| 라우팅·격리 로직 | TLP 전달과 ACS와 오류 보고를 담당해 성능과 DMA 경계를 함께 좌우함 |

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 장치 열거      | --> | 주소 라우팅    | --> | 패킷 전달      | --> | 오류·격리 관리 |
+-------------+     +-------------+     +-------------+     +-------------+
```

## Ⅴ. 원리 및 절차 흐름도

1. **장치 열거**: 펌웨어와 OS가 스위치 하위 endpoint를 탐색하고 주소 공간을 할당함
2. **주소 라우팅**: 스위치가 TLP 목적지에 따라 적절한 포트를 선택함
3. **패킷 전달**: flow control과 레인 속도 규칙에 따라 데이터를 전달함
4. **오류·격리 관리**: AER과 ACS와 링크 상태 감시로 장애와 DMA 경계를 통제함

## Ⅵ. 실무 적용 및 유의점

1. GPU 확장 서버나 NVMe 확장 백플레인은 스위칭으로 포트 수를 늘리기 쉽지만 상위 링크 공유로 병목이 생기기 쉬우므로 워크로드별 대역폭 모델과 포트 배치를 함께 검토하고 상위 링크 사용률과 과가입 비율과 p99 I/O 지연시간으로 확인함
2. 멀티테넌트 장비나 가상화 서버는 스위치 아래 장치 간 DMA 격리가 중요하므로 ACS와 IOMMU 그룹 검증을 같이 수행하고 격리 시험 통과율과 비인가 DMA 차단율과 P2P 처리량으로 확인함

## Ⅶ. 결론

PCIe 스위칭은 단순 포트 확장 장치가 아니라 공유 상위 링크와 DMA 격리 정책을 함께 설계해야 하는 I/O 패브릭임.
