## 미리 알고가기

- Die: 웨이퍼에서 잘라낸 개별 반도체 칩 조각임
- Known Good Die: 정상 검증 다이(Known Good Die, KGD)는 패키징 전에 정상 동작이 검증된 die임
- Interposer/Bridge: 여러 die 사이의 고밀도 연결을 제공하는 패키지 매개체임
- Heterogeneous Integration: 서로 다른 공정과 기능의 die를 하나의 패키지로 통합하는 방식임

## Ⅰ. 개요

- **정의**: 칩렛은 하나의 큰 단일 die 대신 중앙처리장치(Central Processing Unit, CPU), 입출력(Input/Output, I/O), 캐시, 메모리, 가속기 기능을 여러 작은 die로 나누고 패키지 내부 인터커넥트로 연결해 수율, 비용, 재사용성, 이종 공정 통합 기준으로 대형 고성능 칩을 구현하는 반도체 설계 방식임.
- **배경/필요성**: 공정 미세화 비용이 증가하고 대형 die는 결함 하나로 전체 수율이 떨어짐. 칩렛은 기능별 최적 공정을 선택하고 정상 die를 조합해 성능과 생산성을 동시에 높이려는 대안임.
- **비유**: 한 장의 거대한 회로판을 만들기보다 검증된 모듈 블록을 조립해 큰 시스템을 만드는 것과 같음.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 반도체 집적 방식 변화와 장단점 설명 | 수율, 이종 통합, die-to-die 인터커넥트, 패키징 | 단순 멀티칩 패키지로 축소 |

> 요약: 칩렛은 대형 칩을 작은 기능 die로 분할해 수율과 재사용성, 이종 통합을 높이는 설계 방식임.

## Ⅱ. 특징/비교

| 판단 기준 | 단일 시스템 온 칩(System on Chip, SoC) | Chiplet |
|:---|:---|:---|
| 수율/비용 | die가 커질수록 결함 영향과 제조 비용이 커짐 | 작은 die를 개별 검증해 조합하므로 수율 관리가 쉬움 |
| 공정 선택 | 모든 기능을 같은 공정에 맞춰 설계해야 함 | CPU, I/O, 정적 램(Static Random Access Memory, SRAM), 아날로그를 기능별 공정으로 분리 가능함 |
| 주요 위험 | 단일 die 설계 복잡도와 reticle 한계 | die 간 지연, 패키징, 테스트, 열 관리 복잡도 |

> 요약: 칩렛은 단일 칩의 제조 한계를 줄이지만 패키지 내부 시스템 설계 난이도를 높임.

## Ⅲ. 구성요소

```text
+----------+   D2D   +----------+
| Compute  | <-----> | Cache    |
| Chiplet  |         | Chiplet  |
+----------+         +----------+
      |                   |
      v                   v
+----------+   D2D   +----------+
| I/O Die  | <-----> | Package  |
+----------+         +----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 기능 칩렛 | CPU, 그래픽 처리 장치(Graphics Processing Unit, GPU), 신경망 처리 장치(Neural Processing Unit, NPU), 캐시, I/O 등 역할별 die가 특정 기능을 담당함 | 조립식 부품 |
| Die-to-Die 연결 | 다이 간 연결(Die-to-Die, D2D)이 칩렛 간 데이터와 제어 신호를 고속으로 전달함 | 모듈 연결 케이블 |
| 패키지 기판 | 칩렛 배치, 전원, 신호, 열 경로를 제공함 | 조립 판 |
| 테스트/검증 | Known Good Die와 패키지 후 검증으로 불량 조합을 줄임 | 입고 검사 |

> 요약: 칩렛 구조는 기능 die, die 간 연결, 패키지, 테스트 체계가 결합된 패키지 내부 시스템임.

## Ⅳ. 절차

```text
+----------+     +----------+     +----------+     +----------+
| Partition| --> | Interface| --> | Package  | --> | Validate |
+----------+     +----------+     +----------+     +----------+
```

1. **기능 분할**: 성능, 공정, 재사용성 기준으로 compute, I/O, cache, memory die를 나눔
2. **인터페이스 설계**: 대역폭, 지연, 전력, 프로토콜을 기준으로 die-to-die 연결을 정의함
3. **패키징**: interposer, bridge, substrate를 선택하고 전원·열·신호 무결성을 설계함
4. **검증/양산**: Known Good Die 검사, 패키지 후 테스트, 수율 분석으로 양산 조건을 확정함

> 요약: 칩렛 개발은 기능 분할에서 시작해 패키지 내부 연결과 테스트까지 함께 설계하는 과정임.

## Ⅴ. 문제점

- **P1 인터커넥트 지연·전력**: die 사이 이동이 온다이 배선보다 느리고 전력을 더 쓰므로 성능 병목이 생길 수 있음
- **P2 테스트와 수율 조합**: 개별 die가 정상이더라도 패키징 후 연결 불량과 조합 불량이 발생할 수 있음
- **P3 열·기계적 복잡도**: 고성능 die가 밀집되면 국부 발열과 패키지 변형이 신뢰성을 낮춤

> 요약: 칩렛 문제는 die 분할로 생기는 연결, 조립, 열 관리 복잡도에서 발생함.

## Ⅵ. 개선방안

- **P1 대응**: 범용 칩렛 상호연결 익스프레스(Universal Chiplet Interconnect Express, UCIe) 같은 표준 인터페이스, 근접 배치, 캐시 일관성 정책을 설계함 (확인: die 간 지연과 전력)
- **P2 대응**: Known Good Die 검사, 테스트 용이 설계(Design for Test, DFT), 패키지 후 scan test, 수율 모델링을 적용함 (확인: 패키지 수율)
- **P3 대응**: 열 시뮬레이션, heat spreader, 전력 도메인 분산, 패키지 응력 분석을 수행함 (확인: hotspot 온도)

> 요약: 개선은 표준 연결, 단계별 테스트, 열·기계 설계를 칩 설계와 동시에 수행하는 방향임.

## Ⅶ. 전망

- **발전 방향**: 칩렛은 CPU, GPU, 고대역폭 메모리(High Bandwidth Memory, HBM), 광 I/O, 보안 기능 die를 공정별로 조합하는 이종 패키지 플랫폼으로 확대됨
- **기술사적 판단**: die 분할 기준은 수율 곡선, reticle 한계, die-to-die 지연, 패키지 전력 전달, hotspot 위치를 함께 계산해 정함; known-good-die 비율, die-to-die 링크 오류율, interposer 신호 무결성, 열 사이클, 패키지 warpage를 양산 전 조건으로 검증함
- **기술사 제언**: 칩렛은 집적도 홍보보다 수율, 인터커넥트, 열, 검증 비용을 함께 평가하는 패키지 수준 시스템 설계로 설명함
