## 미리 알고가기

- 칩렛은 대형 단일 다이를 여러 기능 다이로 분할해 패키지 안에서 연결하는 설계 방식임
- 수율과 공정 분리와 재사용성이 주요 장점임
- D2D 인터커넥트와 패키징과 테스트가 성패를 좌우함

## Ⅰ. 개요

- **정의/개념**: 칩렛은 CPU, I/O, 캐시, 가속기 같은 기능을 여러 개의 작은 다이로 분리한 뒤 패키지 내부 고속 인터커넥트로 연결해 하나의 시스템처럼 동작하게 만드는 반도체 통합 방식임
- **배경/필요성**: 대형 단일 다이는 수율과 비용과 reticle 한계 문제를 가지므로, 기능별 최적 공정을 쓰고 정상 다이만 조합할 수 있는 대안이 필요함

## Ⅱ. 특징

- 작은 다이 단위로 수율을 관리해 비용 리스크를 줄일 수 있음
- CPU와 I/O와 SRAM을 서로 다른 공정에 배치하는 이종 통합이 가능함
- 검증된 다이를 여러 제품에 재사용해 설계 자산 활용도를 늘릴 수 있음
- 패키지 내부 통신과 열과 전력 공급 문제가 새로운 병목으로 등장함

## Ⅲ. 종류 및 비교

| 판단 기준 | 단일 SoC | Chiplet |
|:---|:---|:---|
| 수율 관리 | 대형 다이일수록 불리함 | 작은 다이별로 관리함 |
| 공정 선택 | 전체가 같은 공정 | 기능별 최적 공정 가능 |
| 재사용성 | 낮음 | 높음 |
| 내부 통신 지연 | 낮음 | D2D 설계 의존 |

> 요약: 칩렛은 단일 SoC의 수율·공정 한계를 패키지 내부 분할과 D2D 연결로 완화함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Compute Chiplet | CPU, GPU, NPU 같은 계산 기능을 담당하며 고성능 공정 적용에 적합함 |
| I/O, Cache Chiplet | 메모리 제어와 외부 인터페이스와 대용량 캐시를 담당해 성숙 공정 재사용에 유리함 |
| D2D Interconnect | 칩렛 사이 대역폭과 지연을 결정하는 핵심 연결 구조임 |
| Package, Test Flow | interposer와 bridge와 KGD 검증이 최종 수율과 신뢰성을 좌우함 |

```text
+----------------+     +------------------+     +----------------+
| Compute Chiplet| <-> | D2D Interconnect | <-> | I/O Cache Chip.|
+----------------+     +------------------+     +----------------+
                              |
                              v
                       +--------------+
                       | Package/Test |
                       +--------------+
```

> 요약: 칩렛 구조는 compute, I/O/cache, D2D interconnect, package/test 흐름이 함께 맞아야 함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 기능 분할      | --> | 개별 다이 검증  | --> | 패키지 결합    | --> | D2D 통합 동작  |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **기능 분할**: 연산과 I/O와 캐시 기능을 다이 단위로 나눔
2. **개별 다이 검증**: KGD 수준에서 정상 여부를 확인함
3. **패키지 결합**: interposer, bridge로 고속 연결을 구성함
4. **D2D 통합 동작**: 패키지 내부에서 하나의 시스템처럼 동작시킴

> 요약: 기능을 다이 단위로 나누고 KGD 검증 뒤 패키지에서 D2D로 통합함.

## Ⅵ. 실무 적용 및 유의점

1. 서버 CPU·AI 가속기 패키지는 칩렛으로 수율과 공정 최적화를 얻지만 기능 분할이 맞지 않으면 D2D 링크가 병목이 되므로 통신량 기반 파티셔닝을 적용하고 D2D latency, bandwidth utilization으로 확인함
2. 멀티 다이 패키지는 열 밀도와 조립 수율이 리스크이므로 pre-bond/post-bond test와 thermal simulation을 적용하고 hotspot temperature, package yield로 확인함

## Ⅶ. 결론

칩렛은 단순 분할이 아니라 수율·공정·재사용성을 패키지 수준에서 다시 최적화하는 방식이므로 제조 이익이 D2D 통신 비용을 넘는지 판단해야 함.

## 작성 근거(검토용)

- 칩렛은 수율 관리, 공정 분리, 재사용성, D2D 통신 비용을 핵심 축으로 설명함
- 구성요소는 compute chiplet, I/O/cache chiplet, D2D interconnect, package/test로 정리함
- 실무 판단은 D2D latency, bandwidth utilization, hotspot temperature, package yield로 검증 가능하게 작성함
