# Chiplet 칩렛 (Chiplet)

## 미리 알고가기

- Die: 웨이퍼에서 잘라낸 개별 반도체 칩 조각임
- KGD: 정상 검증 다이(Known Good Die, KGD)는 패키징 전에 정상 동작이 검증된 die임
- D2D: 다이 간 연결(Die-to-Die, D2D)은 같은 패키지 안의 칩렛 사이를 연결하는 고속 통신 방식임
- Interposer/Bridge: 여러 die 사이의 고밀도 연결을 제공하는 패키지 매개체임
- 이종 통합: 서로 다른 공정과 기능의 die를 하나의 패키지로 통합하는 방식임

## Ⅰ. 개요

- **정의/개념**: 칩렛은 하나의 큰 단일 die 대신 CPU, I/O, 캐시, 메모리, 가속기 기능을 여러 작은 die로 나누고 패키지 내부 인터커넥트로 연결해 수율, 비용, 재사용성, 이종 공정 통합을 높이는 반도체 설계 방식임.
- **배경/필요성**: 공정 미세화 비용이 증가하고 대형 die는 결함 하나로 전체 수율이 떨어짐. 칩렛은 기능별 최적 공정을 선택하고 정상 die를 조합해 성능과 생산성을 동시에 높이려는 대안임.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 반도체 집적 방식 변화와 장단점 설명 | yield, heterogeneous integration, die-to-die, packaging, test | 단순 멀티칩 패키지로 축소, 인터커넥트·검증 누락 |

> 요약: 칩렛은 대형 칩을 작은 기능 die로 분할해 수율과 재사용성, 이종 통합을 높이는 설계 방식임.

## Ⅱ. 특징 및 비교

| 판단 기준 | 단일 SoC | Chiplet |
|:---|:---|:---|
| 수율·비용 | die가 커질수록 결함 영향과 제조 비용이 커짐 | 작은 die를 개별 검증해 조합하므로 수율 관리가 쉬움 |
| 공정 선택 | 모든 기능을 같은 공정에 맞춰 설계해야 함 | CPU, I/O, SRAM, analog를 기능별 공정으로 분리 가능 |
| 재사용성 | 제품별 단일 설계 의존도가 큼 | 검증된 chiplet을 여러 제품에 재사용 가능 |
| 주요 위험 | 단일 die 설계 복잡도와 reticle 한계 | die 간 지연, 패키징, 테스트, 열 관리 복잡도 |

칩렛은 “작게 나누면 무조건 유리”한 방식이 아님. die 간 통신량이 많거나 지연 민감한 기능을 잘못 분리하면 패키지 내부 인터커넥트가 병목이 될 수 있음.

## Ⅲ. 구성요소/구조

```text
+--------------------------------------------------+
|                  Package                         |
| +----------+   D2D   +----------+   D2D +-------+ |
| | CPU Die  | <-----> | I/O Die  | <---->| Cache | |
| +----------+         +----------+       +-------+ |
|       \                                      /     |
|        +---------- Interposer/Bridge -------+      |
+--------------------------------------------------+
```

| 구성요소 | 설명 | 핵심 포인트 |
|:---|:---|:---|
| Compute chiplet | CPU, GPU, AI 가속기 등 연산 기능을 담당함 | 고성능 공정 |
| I/O chiplet | PCIe, 메모리 컨트롤러, SerDes 등 외부 연결을 담당함 | 성숙 공정 활용 |
| Interposer/Bridge | die 간 고밀도 연결을 제공함 | 대역폭과 지연 |
| D2D 인터커넥트 | chiplet 사이 프로토콜과 물리 연결을 제공함 | 상호운용성 |
| 테스트/패키징 | KGD 검증과 최종 패키지 수율을 관리함 | 제조 신뢰성 |

### 원리/흐름도

```text
+----------+      +----------+      +----------+      +----------+
| Partition| ---> | Verify   | ---> | Package  | ---> | Test     |
+----------+      +----------+      +----------+      +----------+
```

기능을 die 단위로 분할하고 각 die를 개별 검증한 뒤 패키지에서 D2D로 연결함. 최종 성능은 개별 die 성능뿐 아니라 패키지 내부 통신, 열, 전력 공급 품질에 의해 결정됨.

## Ⅳ. 문제점 및 개선방안

1. **D2D 지연과 대역폭 병목**: 기능 분할이 잘못되면 die 사이 데이터 이동이 단일 die 내부 연결보다 느려짐.
   - **개선방안**: 통신량 기반 partitioning과 topology-aware 설계를 적용함. (확인: D2D utilization, latency)
2. **패키징·열 관리 복잡도**: 여러 die가 한 패키지에 모이면 hotspot, warpage, 전력 공급 문제가 증가함.
   - **개선방안**: thermal simulation, power integrity 검증, 패키지 공정 선택을 병행함. (확인: hotspot 온도, 전압 강하)
3. **테스트와 수율 관리 난이도**: KGD가 정상이어도 패키지 후 연결 불량이나 조립 결함이 발생할 수 있음.
   - **개선방안**: pre-bond/post-bond test, BIST, yield analytics를 적용함. (확인: package yield, test coverage)

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 고성능 CPU | compute die와 I/O die를 분리해 미세 공정 비용과 I/O 공정 요구를 분리함 | 수율, 메모리 지연, 제조 비용 |
| AI 가속기 | 연산 chiplet과 HBM, I/O chiplet을 패키지에서 결합함 | D2D 대역폭, 전력당 처리량 |
| 제품 포트폴리오 | 동일 chiplet을 조합해 서버·데스크톱·엣지 제품을 구성함 | 재사용률, 개발 기간 |

## Ⅵ. 결론

칩렛은 반도체 미세화 한계와 대형 die 수율 문제를 해결하기 위한 구조적 설계 전략임. 강점은 수율, 재사용성, 이종 공정 통합이지만, 성패는 D2D 인터커넥트와 패키징·검증 품질에 달려 있음. 따라서 칩렛은 제조 비용뿐 아니라 기능 분할, 통신량, 열, 테스트 가능성을 함께 설계해야 함.
