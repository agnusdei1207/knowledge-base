# 📖 【암기용】 개념 완전 이해

> 목적: 063_simd_mimd에서 다룬 SIMD·MIMD 개념이 실제 프로세서 안에서 어떤 회로와 메커니즘으로 구현되는지 — 데이터 수준 병렬성(DLP)의 AVX 확장, 워프 발산 문제, 태스크 수준 병렬성(TLP)의 캐시 일관성 — 수치로 이해하게 만든다.

## 한눈에
- **개요**: SIMD·MIMD 프로세서는 각각 **데이터 수준 병렬성(DLP, Data-Level Parallelism)**과 **태스크 수준 병렬성(TLP, Task-Level Parallelism)**을 하드웨어로 구현한 것이다 — 어떤 병렬성을 노리느냐에 따라 칩 면적을 연산기(ALU)에 쏟을지, 제어 로직과 캐시에 쏟을지가 갈린다.
- **왜 필요한가**: 같은 "병렬 처리"라도 GPU가 초당 수조 번의 동일 곱셈을 반복하는 것과, CPU가 24개의 서로 다른 프로세스를 돌리는 것은 요구되는 회로가 전혀 다르다. 이 차이를 모르면 GPU에 분기가 많은 코드를 올려 성능을 반토막 내거나, CPU에 대량 반복 연산을 올려 자원을 낭비하게 된다.
- **핵심 직관**: DLP는 같은 조립 라인을 100개 복사해 동시에 돌리는 공장이고, TLP는 각기 다른 제품을 만드는 100개의 독립된 작업장을 연결해 관리하는 공단이다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 표기/용어 | 의미 | 비유 |
|:---|:---|:---|
| 데이터 수준 병렬성 (DLP) | 같은 연산을 여러 데이터에 동시 적용해 얻는 병렬성 — SIMD가 노리는 것 | 같은 도장을 여러 종이에 동시에 찍기 |
| 태스크 수준 병렬성 (TLP) | 서로 독립된 작업을 동시에 실행해 얻는 병렬성 — MIMD가 노리는 것 | 여러 사람이 각자 다른 일을 동시에 하기 |
| AVX / SSE | 인텔·AMD CPU(MIMD 코어) 내부에 내장된 SIMD 확장 명령어 세트 — 256비트(AVX2)·512비트(AVX-512) 레지스터로 다수 데이터 동시 연산 | CPU 안에 숨겨둔 미니 SIMD 엔진 |
| 워프 (Warp) | GPU가 스레드를 32개씩 묶어 하나의 SIMD 단위처럼 동시에 실행하는 그룹 | 32명이 한 조가 되어 같은 동작을 하는 팀 |
| 워프 발산 (Warp Divergence) | 워프 내 스레드들이 조건 분기에서 서로 다른 경로를 타 실행이 갈라지는 현상 — 갈라진 경로를 순차 실행해 성능이 떨어짐 | 한 팀이 갈림길에서 갈라지면 한쪽이 끝날 때까지 다른 쪽은 대기 |
| SIMT (Single Instruction, Multiple Threads) | GPU가 워프 단위로 스레드마다 개별 마스크를 부여해 워프 발산을 완화하는 실행 모델 | 갈림길마다 표식을 붙여 순서대로 통과시키는 교통정리 |
| MESI 프로토콜 | 여러 코어가 각자의 캐시에 같은 메모리 주소를 들고 있을 때 값을 일치시키는 캐시 일관성 프로토콜(Modified·Exclusive·Shared·Invalid 4상태) | 여러 사람이 같은 문서 사본을 들고 있을 때 최신본만 유효하다고 표시하는 규칙 |
| 칩렛 (Chiplet) | CPU(MIMD)와 NPU/GPU(SIMD) 등 이기종 다이를 하나의 패키지에 물리적으로 결합하는 설계 방식 | 서로 다른 부품 블록을 레고처럼 이어붙인 조립 |

## 깊이 이해

### AVX 확장 — CPU 안의 SIMD를 수치로 확인
- AVX-512는 레지스터 폭이 512비트다. 32비트 실수(float) 기준 512÷32=16개, 64비트 실수(double) 기준 8개를 하나의 명령어로 동시에 더한다.
- 예: 1,600개 원소를 더하는 반복문을 일반 스칼라 명령으로 처리하면 1,600번의 덧셈 명령이 필요하지만, AVX-512(16-wide)로 벡터화하면 100번(1,600÷16)의 명령으로 끝난다 — 이론상 최대 16배의 처리량 향상이다.
- 이것이 "MIMD 코어 안의 SIMD"다. 즉 24코어 CPU(MIMD)의 각 코어는 내부에 AVX(SIMD) 유닛을 갖고 있어, 필요할 때만 깨워 쓰는 혼합(Hybrid) 구조가 현대 CPU의 기본값이다.

### 워프 발산 — 성능이 반토막 나는 과정을 수치로 확인
- GPU는 스레드 32개를 워프 1개로 묶어 SIMD처럼 동시 실행한다. `if (x > 0) { A 실행(10사이클) } else { B 실행(10사이클) }` 코드에서 워프 안 32개 스레드 중 16개는 참, 16개는 거짓이라 하자.
- 하드웨어는 명령어를 1개씩만 방송할 수 있으므로, 참인 16개가 A를 실행하는 10사이클 동안 거짓인 16개는 마스킹되어 정지하고, 이어서 거짓인 16개가 B를 실행하는 10사이클 동안 참인 16개가 정지한다.
- 결과: 분기가 없었다면 10사이클에 끝날 일이 20사이클(10+10)로 늘어난다 — 실질 처리 효율이 50%로 떨어진다. 분기가 4갈래로 갈라지면 효율은 25%까지 떨어질 수 있다.
- SIMT는 워프 스케줄러가 각 경로를 마스크로 표시해 유연하게 스케줄링하도록 완화하지만(먼저 끝난 경로를 다른 워프로 채우는 등), 문제를 완전히 없애지는 못한다.

### MESI 캐시 일관성 — MIMD가 치르는 대가를 수치로 확인
- 4코어 CPU에서 각 코어가 같은 메모리 주소의 사본을 자신의 L1 캐시에 갖고 있다고 하자. 코어 1이 그 값을 수정(Write)하면, 나머지 3개 코어가 들고 있던 사본은 즉시 Invalid(무효) 상태로 표시되고, 이후 그 값을 읽으려는 코어는 캐시가 아니라 코어 1의 캐시 또는 메모리에서 다시 가져와야 한다.
- 이 무효화·재요청 트래픽은 코어 수에 비례해 늘어난다. 코어가 4개일 때보다 64개일 때 공유 변수 경쟁이 훨씬 빈번해져, 코어를 늘려도 성능이 정비례로 늘지 않는 원인 중 하나가 된다(암달의 법칙의 하드웨어적 원인).

### 이기종 칩렛 융합 — SIMD와 MIMD를 한 패키지에
- 과거에는 CPU(MIMD)와 GPU(SIMD)가 별도 칩으로 존재해 PCIe 버스를 통해 데이터를 주고받았다. PCIe 4.0 x16의 대역폭은 약 32GB/s인데, GPU 내부 메모리(HBM) 대역폭은 수백 GB/s~TB/s급이라 칩 간 전송이 병목이 된다.
- 최신 설계(예: 애플 M시리즈 Ultra, AMD MI300)는 CPU 다이와 NPU/GPU 다이를 하나의 패키지 위에 올려 인터커넥트로 직결한다. 전송 경로가 짧아지고 대역폭이 커져 병목이 줄어든다.

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: SIMD와 MIMD는 Flynn의 병렬 컴퓨터 분류 중 현대 컴퓨팅을 양분하는 핵심 아키텍처로, SIMD는 1개의 제어장치가 다수 연산기를 통제해 데이터 병렬성(Data-level)을 극대화하고, MIMD는 독립적 코어들이 태스크 병렬성(Task-level)을 추구한다.
> 2. **가치**: 딥러닝 트랜스포머 행렬 연산과 대규모 벡터 처리가 폭발함에 따라 전성비(와트당 성능)가 압도적인 SIMD(GPU, NPU)가 가속기 생태계를 지배하고 있으며, 복잡한 분기 제어 및 범용 OS 구동은 전통적인 MIMD(멀티코어 CPU)가 전담하는 이기종 분업이 완성되었다.
> 3. **판단 포인트**: 단일 아키텍처의 한계를 돌파하기 위해, 멀티코어(MIMD) 내부에 AVX-512 등의 SIMD 확장 명령어를 융합하거나, SIMD의 경직성을 극복하기 위해 엔비디아가 스레드별 마스킹을 부여한 SIMT(Single Instruction Multiple Threads) 모델로 진화하고 있음을 주목해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 병렬성(Parallelism)의 근본적인 두 가지 접근 방식(데이터 vs 태스크) 구분 | Data Parallelism(SIMD) vs Task Parallelism(MIMD), 구조적 매핑 | SIMD와 MIMD를 단순히 "GPU와 CPU"로만 치환하여 하드웨어 내부의 제어/데이터 흐름 메커니즘 묘사를 누락하는 1차원적 서술 |
| 각 아키텍처의 H/W 설계 한계점 및 현대 시스템에서의 극복/융합 트렌드 | SIMD 분기발산(Warp Divergence) 리스크, MIMD 멀티스레드 동기화 랙 | "둘 중 어느 것이 더 좋다"는 식의 이분법으로 서술하여, 워크로드별 스위트 스팟(Sweet Spot) 차이를 무시하는 오류 |

> 요약: SIMD는 "한 명의 뇌(CU)로 수천 개의 손발(ALU)을 움직여 전기를 아끼는 구조"이고, MIMD는 "뇌 자체를 여러 개로 분열시켜 복잡한 개별 문제를 각개격파하는 구조"다.

## Ⅰ. 개요 및 필요성

- 정의: 프로세서 내 명령어 스트림과 데이터 스트림의 흐름 결합 방식에 따라, 단일 명령으로 다중 데이터를 동기화 폭격하는 SIMD와, 다중 명령으로 다중 데이터를 비동기적 독립 수행하는 MIMD 아키텍처
- 배경: 무어의 법칙 한계와 전력 장벽(Power Wall)으로 단일 코어의 클럭(GHz)을 높이는 방식이 종말을 고함에 따라, 칩 내부에 연산기(ALU) 및 코어(Core) 개수를 물리적으로 증대시키는 병렬화 패러다임 시프트 도래
- 필요성: 단순하고 정형화된 대규모 행렬 연산(딥러닝/그래픽) 영역과 비정형적인 복합 비즈니스 로직(분기 제어/OS) 영역 양 극단을 효율적으로 분리 타격(Off-loading)하기 위한 목적 지향적 칩 아키텍처 다각화 필수

## Ⅱ. 구조 및 구성요소 (마이크로 아키텍처 데이터 패스 흐름)

제어 장치(Control Unit)가 칩 면적을 얼마나 잡아먹느냐, ALU(산술논리장치)가 얼마나 빽빽하게 깔려 있느냐가 승부처다.

```text
[ SIMD vs MIMD 아키텍처의 논리적 실행(Execution) 구조도 대조 ]

[ SIMD (Single Inst. Multiple Data) ] : GPU / NPU 기반 (동기식/Lock-step 동작)
  (명령어 A: "10을 더해라")
           ↓↓ (1개의 Control Unit 확성기 통제)
   +----+  +----+  +----+  +----+
   |ALU1|  |ALU2|  |ALU3|  |ALU4|  <--- 1번의 클럭에 4개의 ALU가 동시에 움직임
   +----+  +----+  +----+  +----+
   (D 1)   (D 2)   (D 3)   (D 4)   <--- 4개의 배열 데이터를 한 번에 Fetch

[ MIMD (Multiple Inst. Multiple Data) ] : 멀티코어 CPU 기반 (비동기식/독립 동작)
  (명령어 A)     (명령어 B)     (명령어 C)     (명령어 D)
    ↓↓             ↓↓             ↓↓             ↓↓ 
  [CU 1]         [CU 2]         [CU 3]         [CU 4]  <--- 코어마다 독자적인 뇌(제어 유닛) 보유
  [ALU1]         [ALU2]         [ALU3]         [ALU4]  <--- 서로 다른 시간에, 다른 속도로 연산
  (D 1)          (D 2)          (D 3)          (D 4)
```

| 구분 | 주요 설계(H/W) 특징 | 메모리 일관성 통제(Coherence) |
|:---|:---|:---|
| **SIMD** | 칩 면적의 대부분을 단순 ALU(계산기)로 채워 넣어 연산량(Throughput)을 극대화 | 통일된 제어 흐름 아래 배열 데이터를 다루므로 복잡한 락(Lock)이나 캐시 일관성 문제 상대적 적음 |
| **MIMD** | 각 코어마다 복잡한 디코더(CU), 분기 예측기, 거대 L1/L2 캐시를 할당하여 레이턴시(Latency) 단축 극대화 | 4개의 뇌가 1개의 램(공유 변수)을 조작하려다 충돌하므로 MESI 등 극악 난이도의 하드웨어 캐시 동기화 필수 |

> 요약: SIMD 설계자는 "어떻게 하면 뇌(CU)를 덜 만들고 그 자리에 계산기(ALU)를 더 욱여넣을까" 고민하고, MIMD 설계자는 "각 코어(뇌)들이 서로 멱살 잡고 싸우지(캐시 충돌) 않게 룰을 짤까" 고민한다.

## Ⅲ. 동작원리 및 아키텍처별 치명적 제약(Bottleneck) 메커니즘

장점 뒤에는 반드시 극악의 트레이드오프가 숨어 있다. 분기 발산과 컨텍스트 스위칭 오버헤드다.

```text
[ SIMD의 치명적 한계: 조건 분기(if-else) 발산 (Warp Divergence) 에러 ]
명령: if (데이터 > 5) { 더하기 } else { 빼기 }
현상: 4개의 ALU 중 2개는 참, 2개는 거짓일 때 -> CU가 1개뿐이라 '더하기'와 '빼기'를 동시에 지시할 수 없음!
결과: "참"인 애들 2개가 더하기 할 때 나머지 2개는 멍때림(Masking Idle) -> 이후 "거짓"인 애들 2개가 빼기 할 때 
      반대쪽 2개가 멍때림. 성능(클럭 사이클)이 반토막 나는 대참사 발생.

[ MIMD의 치명적 한계: 자원 경합 및 문맥 교환 (Context Switching) ]
명령: 4개의 코어(MIMD)가 100개의 프로세스(스레드)를 쪼개서 처리
현상: 코어가 "유튜브 처리 -> 워드 처리"로 작업을 갈아탈 때마다, 기존 레지스터/캐시를 통째로 비우고(Flush) 
      새 데이터를 메모리에서 펌핑해와야 함. 
결과: 통신/대기(Synchronization) 오버헤드로 인해 코어 개수를 늘려도 성능이 선형적으로 늘지 않음(암달의 법칙 한계).
```

| 해결 파이프라인 (아키텍처 진화) | 대응 대상 | 극복 원리 |
|:---|:---|:---|
| **SIMT (단일 명령 다중 스레드)** | SIMD 분기 발산 | 엔비디아가 GPU 내부에 스레드 묶음(Warp) 단위로 H/W 마스킹을 부여하여, 분기가 발생해도 유연하게 일시 정지/재개(스케줄링) 가능토록 고안한 변형 SIMD |
| **NUMA 및 칩렛(Chiplet) 구조** | MIMD 캐시 충돌 | 모든 코어가 1개의 RAM 통로로 몰려드는 병목을 부수기 위해, 특정 코어 묶음마다 전용 직통 로컬 메모리(NUMA Node)를 쪼개어 할당 (AMD EPYC 설계) |

> 요약: SIMD 워크로드에 분기문(if-else)을 잔뜩 넣는 프로그래머는 죄악이다. 데이터를 미리 쫙 정렬(Sorting)해서 참/거짓이 엇갈리지 않게 한 묶음(Warp)으로 밀어 넣는 최적화가 필수다.

## Ⅳ. 심화 비교: SIMD(가속기) vs MIMD(멀티코어) 아키텍처 철저 대조표

| 비교 축 | SIMD (Single Inst. Multiple Data) | MIMD (Multiple Inst. Multiple Data) |
|:---|:---|:---|
| 병렬성(Parallelism) 기준 | **데이터(Data) 병렬성** (같은 동작 반복) | **태스크(Task) 병렬성** (독립적 프로그램 실행) |
| 트랜지스터 칩 다이(Die) 배분 | 제어부 극소화, **연산부(ALU) 최대화 극단적 효율** | **제어부/거대 캐시 할당 증가**, 연산부 밀도 낮음 |
| 와트(W) 당 전성비 최적화 | 최고 (전력을 연산에만 쏟아부음) | 상대적으로 낮음 (제어 및 캐시 관리에 전력 낭비) |
| 구동 최적 워크로드 | 딥러닝 MAC 행렬 텐서 곱, 3D 픽셀 셰이더 랜더링 | 분기가 많은 OS 커널 구동, 웹 서버 트래픽 파싱 |
| 대표적 상용 플랫폼 | NVIDIA GPU (SIMT 변종), 구글 TPU, 벡터 프로세서 | Intel Core, AMD Ryzen, 클라우드 분산 서버 |

> 요약: SIMD는 1분에 마늘을 100개 까는 100명의 아르바이트생이고, MIMD는 복잡한 복어 독을 능수능란하게 빼내는 4명의 수석 셰프(쉐프)다. 둘의 역할은 완벽히 분리되어 있다.

## Ⅴ. 제약 사항 및 현대 아키텍처의 융합 (Hybrid) 진화 방향

현재 지구상에 100% 순수한 순정 SIMD 컴퓨터나, 순정 MIMD 컴퓨터는 거의 멸종했다. 두 장점을 한 칩에 구겨 넣은 괴물(Hybrid)이 대세다.

| 피벗 아키텍처 | 발생 배경 및 한계 | 하드웨어 융합 메커니즘 (Hybrid) |
|:---|:---|:---|
| **MIMD 속의 SIMD 내장 (AVX / SSE 확장)** | CPU(MIMD)만으로 멀티미디어(동영상 인코딩)나 수학 암호화 처리를 하려다 연산기(ALU) 부족으로 속도 폭망 | 인텔과 AMD는 메인 CPU 코어(MIMD) 내부에 '256비트, 512비트 초광폭 레지스터(벡터)'와 전용 병렬 ALU를 쑤셔 넣음. 명령어 1개(예: `_mm256_add_ps`)로 데이터 8개를 동시 덧셈하는 **SIMD on MIMD** 시현 |
| **이기종(Heterogeneous) SoC 집적 (칩렛)** | 과거엔 마더보드에 CPU 칩과 GPU 칩을 따로 꽂아 썼으나, 두 칩 간 통신(PCIe 병목) 지연으로 데이터 전송에 배터리와 시간 낭비 | 폰 노이만 병목을 부수기 위해 애플 M Ultra 계열이나 스마트폰 AP는 단일 실리콘 다이(Die) 위에 고성능 **CPU(MIMD) 블록과 NPU(SIMD 시스톨릭) 블록을 레고처럼 찰싹 붙여 하나의 칩**으로 구워버림 (Zero-Copy 통신망 구성) |

> 요약: 오늘날 개발자들은 SIMD니 MIMD니 머리 아프게 칩을 고를 필요가 없다. 컴파일러가 알아서 코드를 분석한 뒤 "이건 독립 작업이니까 코어 1(MIMD)에 던지고, 오 이건 행렬 덧셈 1만 개네? CPU 내부의 AVX(SIMD 회로)를 깨워서 한 방에 밀어버려!"라고 자동 분배(Vectorization) 해준다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. AI 클라우드 인프라 내 이기종(SIMD/MIMD) 오프로딩 아키텍처 설계: 네이버 클로바 등 초대규모 LLM 데이터센터 설계 시, 전처리/파싱/DB 룩업 및 스케줄링 등 비정형 제어 분기가 극심한 영역은 거대 캐시와 분기 예측력을 갖춘 AMD EPYC(MIMD) 서버 팜에 매핑하고, 수천억 파라미터의 정형화된 트랜스포머 텐서 가중치 곱(Dot-product) 연산은 NVLink로 클러스터링된 NVIDIA GPU(SIMT/SIMD) 코어에 전면 위임(Off-loading)하여 전성비 TCO 최적화 달성
2. 엔터프라이즈 RDBMS 인메모리(In-Memory) 가속을 위한 벡터화(Vectorization) 튜닝: SAP HANA나 Apache Arrow 등 최신 컬럼 지향 데이터베이스 엔진 개발 시, 데이터를 메모리 내에 연속(Contiguous) 배열로 적재한 후 CPU 코어(MIMD)가 순차 연산(for loop)을 돌지 않고 하드웨어 AVX-512(SIMD 명령어 세트)를 직접 호출하여 단 1사이클에 16개의 레코드를 일제히 집계(Aggregation)하는 초고속 스캔 레이어 구현
3. 지능형 자율주행 차량용 복합 도메인 특화 아키텍처(DSA) SoC 탑재: 차량 내 수백 개의 센서로부터 들어오는 라이다(LiDAR) 포인트 클라우드 병렬 신호 처리는 고정형 MAC 어레이 기반의 NPU(SIMD) 블록이 밀리초 단위로 파이프라이닝하고, 이를 기반으로 "핸들을 꺾고 브레이크를 밟는다"는 복합적이고 치명적인 순차적 제어 결정 로직(Control Flow)은 높은 클럭과 신뢰성 방어(Lock-step) 기능이 있는 ARM Cortex-R 안전 특화 코어(MIMD)가 이중 판별토록 1개의 SoC 다이(Die)에 이기종 이중화 융합 설계 적용

**결론 (2줄):**
- 기술사 판단: SIMD와 MIMD는 단순히 명령어/데이터 개수에 따른 고전적 분류를 넘어, 병렬성(Data vs Task)의 태생적 철학 차이를 규명하는 반도체 마이크로 아키텍처 설계의 척도다.
- 향후 방향: 무어의 법칙 한계에 따라 칩의 독단적 진화는 멈췄으며, 향후 병렬 컴퓨팅 생태계는 단일 패키지(Chiplet) 내에 MIMD 코어와 SIMD 가속기(NPU)가 인터포저(UCIe)로 강결합되는 이기종 극대화(Heterogeneous Integration) 구조로 귀결되고 있다.
