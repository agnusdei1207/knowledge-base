# 📖 【암기용】 개념 완전 이해

> 목적: 이 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: CPU가 하나의 명령어가 다 끝나기를 기다리지 않고, 단계별로 명령어를 겹쳐서 동시에 실행하는 병렬 처리 기법이다.
- **왜 필요한가**: 명령어 하나를 5초(클럭)에 걸쳐 처리하고 다음 명령어를 받는 방식(단일 사이클)은 CPU의 나머지 부품을 놀게 만들어 처리 효율이 극도로 떨어진다.
- **핵심 직관**: 자동차 조립 공장의 "컨베이어 벨트"다. 뼈대 조립이 끝나 엔진을 얹을 때, 뼈대 조립부는 쉬는 게 아니라 즉시 다음 차의 뼈대를 조립하기 시작한다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| **파이프라이닝 (Pipelining)** | 명령어 처리 단계를 분할해 여러 명령어를 시공간적으로 겹쳐 실행 | "컨베이어 벨트식 연속 공정" |
| **처리량 (Throughput)** | 단위 시간당 처리 완료되는 명령어의 총량 (파이프라인의 목적) | "하루 동안 생산된 총 자동차 대수" |
| **지연 시간 (Latency)** | 명령어 하나가 입력되어 완료될 때까지 걸리는 절대 시간 | "차 1대가 완성되는 절대 시간" |
| **명령어 수준 병렬성 (ILP)** | 여러 명령어가 하드웨어 수준에서 동시에 겹쳐 실행되는 정도 | "공장에 동시에 올라가 있는 차의 대수" |

## 깊이 이해
- **배경·문제의식**: 옛날 CPU는 빨래-탈수-건조를 한 통에서 하듯, 1번 명령어가 모든 과정(인출->해독->실행)을 끝낼 때까지 다른 명령어가 들어오지 못했다(단일 사이클). 클럭 주파수를 아무리 올려도 유휴 부품이 너무 많아 성능 한계에 부딪혔다.
- **작동 원리 (전통적 MIPS 5단계 기준)**: 명령어를 5가지 구역으로 나눈다.
  1. **IF (Instruction Fetch)**: 메모리에서 명령어를 가져옴.
  2. **ID (Instruction Decode)**: 무슨 명령인지 해독하고 레지스터 값을 읽음.
  3. **EX (Execute)**: ALU가 덧셈이나 논리 연산을 수행함.
  4. **MEM (Memory Access)**: 결과값을 메모리에 쓰거나 읽어옴.
  5. **WB (Write Back)**: 최종 값을 레지스터에 기록함.
  1번 명령이 ID로 넘어가면, IF 구역은 즉시 비어있으므로 2번 명령을 끌어온다(Fetch). 5사이클이 지나 파이프라인이 꽉 차면(Fill), 매 클럭마다 명령어 1개씩이 꾸준히 완료(wb)되어 쏟아진다.
- **비유**: 5시간 걸리는 코스 요리를 1시간 간격으로 5개의 테이블에 시차를 두고 내보낸다. 첫 손님이 밥을 다 먹고 나가는 데는 똑같이 5시간이 걸리지만(지연 시간 동일), 그 뒤로는 1시간마다 손님이 한 팀씩 식사를 마치고 퇴장하게 된다(처리량 5배 증가).
- **구체 예시**: 단일 사이클 CPU로 5개 명령을 처리하면 25클럭이 걸린다. 하지만 5단 파이프라인을 쓰면 첫 명령 완료에 5클럭, 나머지 4개는 1클럭마다 하나씩 완료되어 총 9클럭만에 5개를 끝낸다. 
- **흔한 오해·주의점**: 파이프라이닝은 "명령어 1개의 처리 속도(Latency)"를 빠르게 하는 것이 아니다. 명령어 하나가 겪는 전체 시간은 오히려 파이프라인 래치(오버헤드) 때문에 미세하게 더 길어진다. 오직 "공장 전체의 생산량(Throughput)"을 비약적으로 올리는 기술이다.

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 파이프라이닝이 단일 명령어의 지연시간 단축이 아니라, 유휴 자원을 활용한 시간적 병렬성(Throughput) 확보의 핵심 기술임을 정량 지표(속도 향상도)로 입증한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 명령어 실행 과정을 다수의 마이크로 연산 단계로 분할하고 순차적으로 중첩(Overlap) 실행하는 하드웨어 시간적 병렬성 제어 기법
> 2. **가치**: 명령어 처리 단계별 유휴 상태의 하드웨어 블록을 동시에 가동하여 매 클럭당 명령어 완료 수(목표 IPC=1.0) 처리량을 극대화
> 3. **판단 포인트**: 단(Stage)을 깊게 쪼갤수록 클럭 주파수를 올릴 수 있으나, 분기 예측 실패 및 데이터 의존성(해저드)에 의한 스톨(Stall) 페널티가 기하급수적으로 증가

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 파이프라이닝의 하드웨어 메커니즘과 동작 흐름 파악 | 전형적 5단계(IF-ID-EX-MEM-WB) 분할, 시공간 중첩 도식 | "명령어 처리 속도가 단축된다"는 치명적 오해(Latency와 Throughput 혼동) |
| 정량적 성능 향상 기준 및 한계점 통찰 | 스피드업(Speed-up) 계산 공식, 깊은(Deep) 파이프라인의 Trade-off | 단순히 5단계를 글(위키식)로만 나열하고 단점 누락 |

> 요약: 개별 명령어의 지연 시간(Latency)은 늘어나지만 전체 시스템의 처리량(Throughput)이 이상적으로 N배 향상되는 인과 구조를 선형 흐름도로 증명한다.

## Ⅰ. 개요 및 필요성

- 개요: 파이프라이닝은 하나의 명령어가 실행을 완료하기 전에 다음 명령어를 단계별 하드웨어에 중첩하여(Overlapping) 실행하는 명령어 수준 병렬성(ILP) 아키텍처
- 배경: 단일 사이클 구조는 명령어 1개가 모든 회로를 통과할 때까지 다른 회로가 유휴(Idle) 상태로 방치되어 클럭 사이클 시간이 가장 느린 작업에 하향 평준화 됨
- 필요성: 각 단계 회로를 클럭 동기화 래치(Latch)로 차단하고 동시에 여러 명령어를 밀어 넣어, CPU 전체의 처리량(Throughput)을 단계 수(N)만큼 높이기 위해 필수 적용

---

## Ⅱ. 구조 및 구성요소

```text
[파이프라이닝 5단계 구조 및 하드웨어 매핑]
PC -> [IF] -> Latch -> [ID] -> Latch -> [EX] -> Latch -> [MEM] -> Latch -> [WB] -> 레지스터
      인출             해독             실행             접근             기록
      (I-Cache)       (CU 디코더)      (ALU)            (D-Cache)       (Register)
```

| 파이프라인 단계 | 수행 역할 | 매핑 하드웨어 요소 |
|:---|:---|:---|
| IF (Instruction Fetch) | PC 주소 기반 메모리에서 명령어 인출 | I-Cache(명령어 캐시), PC 증가기 |
| ID (Instruction Decode) | 명령어 디코딩 및 레지스터 피연산자 준비 | 디코더 유닛, 레지스터 파일 (읽기) |
| EX (Execute) | ALU 산술·논리 연산 및 분기(Branch) 주소 계산 | ALU, 상태 레지스터 |
| MEM (Memory Access) | Load/Store 시 데이터 메모리 읽기/쓰기 | D-Cache(데이터 캐시) |
| WB (Write Back) | 최종 연산 결과를 해당 타겟 레지스터에 기록 갱신 | 레지스터 파일 (쓰기 포트) |

> 요약: 5개의 물리적 구역 사이에 래치(버퍼)를 두어 클럭마다 데이터를 넘겨줌으로써 각 구역이 완전히 독립적으로 가동된다.

## Ⅲ. 동작원리 및 흐름도

```text
[파이프라인 시공간 중첩(Overlapping) 사이클 흐름]
Clock:  C1   C2   C3   C4   C5   C6   C7
Inst 1: IF - ID - EX - MEM- WB  (완료)
Inst 2:      IF - ID - EX - MEM- WB  (완료)
Inst 3:           IF - ID - EX - MEM- WB  (완료)
```

- 1단계 [초기 채움(Fill)]: C1부터 C4까지 명령어들이 순차 유입되며 파이프라인의 각 하드웨어 단계를 하나씩 채워 나감 (오버헤드 구간)
- 2단계 [만개 상태(Full)]: C5 클럭에 도달하면 1번 명령어부터 WB(완료)가 시작되며, 파이프라인 내부의 5개 유닛이 모두 다른 명령어로 가동 중첩
- 3단계 [지속 완료(Steady State)]: C5 이후 이상적인 환경(해저드 0)에서는 매 1클럭(C6, C7...)마다 명령어 1개씩이 꾸준히 완료(목표 CPI 1.0)
- 4단계 [비우기(Drain/Flush)]: 마지막 명령어 유입 후 잔여 단계가 빠져나가거나, 분기 실패 시 파이프라인 내부를 강제 플러시(버블 삽입)하여 비움

> 요약: 파이프라인 래치를 채우는 오버헤드를 극복하고 정상 궤도(Steady State)에 오르면, 매 클럭 1개의 작업 완료가 쏟아져 나온다.

## Ⅳ. 특징 (성능 지표 및 트레이드오프)
- 이상적 가속비(Speed-up) 공식: $S = \frac{n \times k}{k + (n-1)} \approx k$ (단 수 $k$, 명령어 수 $n$ 무한대 가정 시 최대 $k$배 향상)
- 한계 1 (클럭 분할 오버헤드): 단(Stage)을 구분하는 래치 지연 시간과 클럭 동기화 여유(Skew) 때문에 명령어 1개당 절대 지연 시간(Latency)은 단일 사이클보다 오히려 길어짐
- 한계 2 (파이프라인 해저드): 데이터 의존성(이전 결과를 즉시 필요), 분기(다음 주소 모름), 하드웨어 충돌 시 흐름이 깨져 파이프라인 정지(Stall) 및 거품(Bubble) 삽입 발생

> 요약: 이론상 단 수(K)만큼 처리량이 향상되지만, 실제 성능은 래치 오버헤드와 분기/데이터 충돌(해저드) 페널티에 의해 삭감된다.

## Ⅴ. 심화 비교 및 적용 판단

| 성능 인자 | 단일 사이클 구조 | 전형적 파이프라인 (5~8단) | 깊은 파이프라인 (Deep, 15단 이상) | 선택 판단 기준 |
|:---|:---|:---|:---|:---|
| 클럭 주파수 한계 | 최악 경로(명령어 전체) 병목 | 각 단계별 균등 분할 한계 | 매우 높음 (극도로 쪼개 고주파 달성) | 공정 미세화 및 방열 여력 |
| 분기 실패 페널티 | 없음 (1명령 완료 후 분기) | 보통 (약 2~4 사이클 버블) | 매우 치명적 (10~20 사이클 플러시) | 분기 예측기(Branch Predictor) 정확도 |
| IPC (클럭당 처리) | 정확히 1.0 보장 | 1.0 이하 (해저드에 의해 저하) | 1.0 훨씬 미달 (스톨 빈발) | 달성 목표 Throughput 임계치 |

> 요약: 단계(Stage)를 잘게 쪼갤수록 클럭을 높여 속도를 끌어올릴 수 있으나, 분기 실패 시 파이프라인을 비우는 페널티(비용)가 극심해져 분기 예측률 95% 이상이 강제된다.

**리스크·대응 (파이프라인 해저드):**
- [리스크] 데이터 해저드 (Data Hazard): 이전 연산(EX) 결과를 다음 명령어(ID)가 당장 요구하여 파이프라인 스톨 유발 → [대응] 연산 결과를 레지스터에 기록하기 전에 EX 단에서 EX 단으로 직통 우회시키는 포워딩(Data Forwarding) 경로 하드웨어 구축 (지표: RAW 의존성 스톨 사이클 최소화)
- [리스크] 제어 해저드 (Control Hazard): IF 단에서 다음 주소를 인출해야 하나 EX 분기 결과가 안 나와 대기 발생 → [대응] 2비트 분기 역사 테이블(BHT)과 타겟 버퍼(BTB)를 탑재한 동적 분기 예측기 구동 (지표: 파이프라인 플러시 비율 5% 미만 유지)

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 슈퍼스칼라(Superscalar) 아키텍처 확장: 단일 5단 파이프라인의 IPC 1.0 한계를 부수기 위해, 한 번의 클럭에 다수의 파이프라인으로 명령어를 2~4개씩 동시 발급(Issue)하여 공간적 병렬성 추가 확보
2. 비순차 실행(OoO) 스케줄링 결합: 파이프라인 중간에 멈춤(Stall)을 막기 위해, 데이터 준비가 끝난 명령어부터 순서를 뒤섞어 파이프라인 유휴 구간(Bubble)에 선제적으로 투입
3. VLIW(명령어 수준 컴파일) 기법 적용: DSP나 특수 가속기 환경에서는 복잡한 하드웨어 해저드 탐지를 끄고, 컴파일러가 소스코드 단계에서 충돌이 없는 명령어를 선별해 긴 명령어(VLIW)로 묶어 파이프라인 주입 정합성 보장

**결론 (2줄):**
- 기술사 판단: 파이프라이닝은 클럭 분할을 통한 처리량(Throughput) 극대화의 핵심이나, 현대 워크로드는 의존성과 분기가 극심하여 단순히 단 수(Stage)를 늘리는 것만으로는 "파이프라인 버블"로 인해 역효과가 발생한다.
- 향후 방향: 파이프라인 깊이 확장은 한계(약 12~15단 선)에 도달했으며, 남은 잉여 트랜지스터 자원은 명령어 비순차 실행(OoO)과 분기 예측기(AI 접목) 성능 고도화에 집중 투입되고 있다.
