# 📖 【암기용】 개념 완전 이해

> 목적: 5단계 파이프라이닝이 어떻게 CPU의 클럭 주파수와 처리량을 기하급수적으로 끌어올리는지, 그 안의 모든 용어(IF~WB, CPI, Latency/Throughput)를 완벽히 이해하게 만든다.

## 한눈에
- **개요**: **명령어 수준 병렬 처리(ILP)**의 대표 기법으로, 명령어 실행 과정을 여러 단계로 쪼개어 서로 다른 하드웨어가 동시에 겹쳐(Overlap) 처리하게 만드는 CPU 설계 기법이다.
- **왜 필요한가**: 명령어 1개가 완전히 끝날 때까지 CPU 전체가 매달리면 너무 느리다. 세탁기-건조기-다리미를 순서대로 쓰듯, 앞 명령어가 1단계를 마치고 2단계로 넘어가는 순간 다음 명령어를 1단계에 즉시 밀어 넣어야 전체 처리량이 극대화된다.
- **핵심 직관**: 1개를 완성하는 데 5분이 걸리는 공정이라도, 5단계로 쪼개 컨베이어 벨트처럼 겹쳐 돌리면 1분마다 1개씩 완성품이 쏟아져 나온다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| ILP (명령어 수준 병렬 처리) | 여러 명령어를 동시에 겹쳐 처리해 처리량을 높이는 기법군 — 파이프라이닝이 소속된 **상위 개념** | 여러 주문을 겹쳐 조리하는 주방 |
| IF (Instruction Fetch) | 명령어 캐시에서 명령어를 읽어오는 단계 | 레시피 카드를 꺼냄 |
| ID (Instruction Decode) | 명령어를 해독하고 레지스터 파일에서 피연산자를 읽는 단계 | 레시피를 읽고 재료를 꺼냄 |
| EX (Execute) | ALU로 연산하거나 분기 주소를 계산하는 단계 | 실제 조리(굽기·볶기) |
| MEM (Memory Access) | 데이터 캐시에 읽기/쓰기하는 단계 | 완성품을 접시에 담거나 냉장고에서 꺼냄 |
| WB (Write Back) | 연산 결과를 목적지 레지스터에 최종 기록하는 단계 | 완성품을 손님상에 올림 |
| 래치(Latch, Pipeline Register) | 각 단계 사이에서 클럭에 맞춰 데이터를 붙잡아 다음 단계로 넘기는 저장 회로 | 컨베이어 벨트 칸막이 |
| CPI (Cycles Per Instruction) | 명령어 1개를 처리하는 데 드는 평균 클럭 수 — 이상적 파이프라인은 1.0 | 손님 1명당 평균 대기 시간 |
| 처리량(Throughput) | 단위 시간당 완료되는 명령어 수 — 파이프라이닝이 늘리는 대상 | 시간당 나오는 완성품 개수 |
| 지연시간(Latency) | 명령어 1개가 들어가서 나올 때까지 걸리는 총 시간 — 파이프라이닝으로 약간 늘어남 | 주문 1건이 시작부터 끝까지 걸리는 시간 |

## 깊이 이해

### 배경 — 단일 사이클 설계의 물리적 한계
- 초기 CPU는 단일 사이클(Single Cycle) 방식으로, 명령어 1개가 인출부터 기록까지 모든 장치를 1클럭 안에 다 거쳐야 했다. 클럭 주기는 가장 느린 명령어(대개 메모리 읽기, MEM 단계)에 맞춰 길게 잡아야 하므로, 다른 단순한 명령어(덧셈 등)도 똑같이 긴 클럭을 낭비하게 된다.
- 클럭 주파수를 높이려면 전체 작업을 잘게 쪼개, 그중 가장 긴 "한 단계"만을 기준으로 클럭을 짧게 끊어야 한다. 이것이 파이프라이닝의 출발점이다.

### 5단계 구조와 클럭 오버랩
- 기본 RISC 5단계는 IF → ID → EX → MEM → WB 순으로, 클럭이 한 번 뛸 때마다 모든 명령어가 동시에 다음 단계로 1칸씩 전진한다. 각 단계 사이의 래치가 이전 단계의 결과를 붙잡아 다음 클럭에 넘겨준다.
- 이상적인 조건(해저드 없음)에서 파이프라인이 꽉 차면, 매 클럭 서로 다른 5개의 명령어가 IF~WB 5단계에 동시에 걸쳐 있으며, 매 클럭마다 정확히 1개의 명령어가 WB를 마치고 완료된다.

### 처리 시간 공식 — 수치로 검증
- K단계 파이프라인으로 N개의 명령어를 처리하는 총 클럭 수는 **K + (N − 1)** 이다. 첫 명령어가 WB에 도달하기까지 K클럭이 걸리고, 이후 나머지 (N−1)개는 매 클럭 1개씩 완료되기 때문이다.
- 예: K=5, N=100이면 5 + 99 = 104클럭. 반면 파이프라이닝 없이 명령어마다 5클럭을 통째로 쓰면 5×100=500클럭이 필요하다. 104클럭은 500클럭 대비 약 4.8배 빠르다 — 이것이 파이프라이닝의 실질적 성능 이득이다.
- N이 커질수록 이 이득은 이론상 K배(여기선 5배)에 수렴한다. K+(N-1)에서 N이 매우 크면 앞의 K는 무시할 만큼 작아지기 때문이다.

### CPI, 처리량, 지연시간 — 셋을 혼동하지 않기
- 이상적 파이프라인의 CPI는 1.0에 수렴한다. 이는 "명령어 1개가 1클럭 만에 끝난다"는 뜻이 아니라 "매 클럭마다 평균 1개씩 완료되어 나온다"는 뜻이다.
- 명령어 1개가 IF에 들어가서 WB로 나오기까지의 실제 시간(Latency)은 단일 사이클보다 오히려 약간 길다 — 단계 사이 래치를 거치는 오버헤드(셋업/홀드 시간) 때문이다. 파이프라이닝이 늘리는 것은 개별 명령어의 속도가 아니라 시간당 쏟아지는 양(Throughput)이다.

### 비유
- 햄버거 공장: 빵 굽기(IF) → 패티 올리기(ID) → 야채 얹기(EX) → 소스 뿌리기(MEM) → 포장(WB). 한 사람이 자기 단계를 끝내 다음 사람에게 넘기는 순간, 자신은 곧바로 다음 햄버거의 같은 작업을 시작한다. 햄버거 1개가 손님에게 가는 시간(Latency)은 그대로거나 약간 늘어도, 시간당 나오는 햄버거 개수(Throughput)는 단계 수만큼 늘어난다.

### 흔한 오해와 파이프라인 깊이의 트레이드오프
- "파이프라이닝은 명령어 1개의 처리 속도를 높인다"는 틀렸다. 늘어나는 것은 처리량이지 개별 명령어의 지연시간이 아니다.
- "단계를 더 잘게 쪼갤수록 무조건 좋다"도 틀렸다. 단계를 늘리면 클럭은 더 빨라지지만, 명령어 사이 의존성(파이프라인 해저드)이 걸릴 때 손해 보는 클럭 수도 늘어난다. 그래서 모바일 CPU는 짧은 파이프라인(8~10단)을, 고성능 서버 CPU는 깊은 파이프라인(15단 이상)을 상황에 맞게 선택한다.

## 연결 개념
- 파이프라인 해저드(008) — 겹쳐 실행하다 발생하는 구조적·데이터·제어 충돌
- 데이터 포워딩·분기 예측(009) — 해저드로 인한 손실 클럭을 줄이는 하드웨어 기법
- 슈퍼스칼라(Superscalar) — 파이프라인을 2개 이상 나란히 깔아 매 클럭 2개 이상의 결과를 내는 아키텍처


# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 파이프라이닝은 하나의 명령어 실행 과정을 5단계(IF-ID-EX-MEM-WB)로 세분화하여, 여러 명령어의 처리 주기를 중첩(Overlap)시키는 시간적 병렬 처리 기법이다.
> 2. **가치**: 명령어당 레이턴시(Latency) 단축이 아닌 시스템 전체의 처리량(Throughput) 극대화를 목적하며, 이상적 상황에서 명령어당 사이클(CPI)을 1.0으로 수렴시킨다.
> 3. **판단 포인트**: 단계(Stage)를 잘게 쪼갤수록 클럭 주파수 상승과 처리량 증가가 가능하지만, 파이프라인 해저드로 인한 버블(Bubble)과 래치(Latch) 지연이라는 트레이드오프를 통제해야 한다.

## Ⅰ. 개요 및 필요성

- 정의: CPU의 명령어 사이클을 독립된 서브 사이클로 분할하여 다수의 명령어를 동시에 중첩 실행하는 하드웨어 설계 기법
- 배경: 단일 사이클(Single-cycle) 아키텍처의 긴 임계 경로(Critical Path)로 인한 클럭 주파수 상향의 물리적 한계
- 필요성: 클럭 주파수를 획기적으로 높이고 사이클 당 명령어 처리량(IPC)을 증가시켜 폰 노이만 병목 완화


## Ⅱ. 구조 및 구성요소 (기본 5단계)

```text
[RISC 5단계 파이프라인 하드웨어 구조]
PC -> [ IF ] -> 래치 -> [ ID ] -> 래치 -> [ EX ] -> 래치 -> [ MEM ] -> 래치 -> [ WB ] -> Reg
      인출              해독              실행               메모리 접근          레지스터 기록
```

| 구성요소 (단계) | 핵심 역할 | 처리 내용 및 동작 |
|:---|:---|:---|
| IF (Instruction Fetch) | 메모리 인출 | PC를 참조하여 명령어 캐시(I-Cache)에서 명령어 반입 |
| ID (Instruction Decode)| 명령어 해독 | 명령어 디코딩 및 레지스터 파일(Register File)에서 피연산자 읽기 |
| EX (Execute) | 산술 논리 연산 | ALU를 통해 연산 수행 및 분기 주소 계산 완료 |
| MEM (Memory Access) | 데이터 접근 | 연산 결과에 따라 데이터 캐시(D-Cache)에 읽기(Load) 또는 쓰기(Store) |
| WB (Write Back) | 최종 결과 기록 | 연산 결과나 메모리에서 읽은 데이터를 목적지 레지스터에 기록 |

> 요약: 각 단계 사이에는 래치(Pipeline Register/Latch)를 두어, 클럭 주기에 맞춰 다음 단계로 데이터를 동기화하여 넘긴다.


## Ⅲ. 동작원리 및 흐름도 (클럭 오버랩)

```text
[명령어 3개의 겹침(Overlap) 실행 흐름 시공간 도표]
Clock | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
Inst 1: IF  ID  EX  MEM WB
Inst 2:     IF  ID  EX  MEM WB
Inst 3:         IF  ID  EX  MEM WB
```

| 단계 | 클럭 전개 (시점) | 파이프라인 처리 동작 |
|:---:|:---|:---|
| 1 | Clock 1~4 | 파이프라인을 채우는 워밍업 단계 (아직 완료된 명령어 없음) |
| 2 | Clock 5 | 명령어 1개(Inst 1)가 WB 단계를 거쳐 최초 실행 완료 |
| 3 | Clock 6 이후 | 매 클럭 1개씩 명령어 실행 완료 (이상적 파이프라인 가동) |
| 4 | 정상 상태(Steady) | 5개의 다른 명령어가 각기 다른 단계를 동시에 실행하며 시스템 스루풋 극대화 |

> 요약: K단계 파이프라인에서 N개의 명령어를 실행할 때, 총 소요 시간은 $K + (N - 1)$ 클럭 사이클이 소요된다.


## Ⅳ. 심화 비교 및 성능 지표 판단

| 성능 축 | 단일 사이클 (Single Cycle) | 파이프라인 (Pipelining) | 도입 효과 및 판단 |
|:---|:---|:---|:---|
| 클럭 길이 | 가장 느린 명령어(Load)에 기준 | 가장 느린 1개 단계(Stage)에 기준 | 클럭 주파수 기하급수적 상승 |
| 이상적 CPI | 1.0 (클럭 길이는 매우 김) | 1.0 (클럭 길이는 매우 짧음) | 시간당 처리량(Throughput) 극대화 |
| 명령어 지연 | 1개의 명령 처리 시간은 빠름 | 래치 오버헤드로 단일 명령 시간은 약간 증가 | 레이턴시(Latency) 희생을 통한 전체 성능 향상 |
| 하드웨어 자원 | 메모리와 ALU를 1회만 사용 | 모든 단계가 동시 동작하여 리소스 충돌 위험 | 해저드 통제(Forwarding 등) 회로 추가 필수 |

> 요약: 파이프라인은 개별 명령어의 속도를 늦추는 대신 공장 전체의 컨베이어 벨트 처리량을 높이는 경제적 최적화다.

| 파이프라인 제약 | 원인 (파이프라인 해저드) | 대응 방안 | 성능 영향 (병목) |
|:---|:---|:---|:---|
| 구조적 해저드 | 메모리(인출/접근) 동시 사용 | 하버드 아키텍처 (I/D 캐시 분리) | 버블(Bubble) 유발 |
| 데이터 해저드 | 앞 명령어 결과를 뒤가 대기 | 데이터 포워딩(Bypass), 스케줄링 | 1~2 클럭 Stall |
| 제어 해저드 | 조건 분기 시 다음 PC 불확실 | 분기 예측(Branch Prediction) | 예측 실패 시 Flush 패널티 |

> 요약: 실제 프로세서 성능은 단계(Stage) 수를 늘리는 것보다, 해저드로 인한 사이클 손실(Stall/Flush)을 얼마나 방어하느냐에 달렸다.


## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 컴파일러 최적화 연계: 소스코드 컴파일 시 NOP(No Operation)를 피하고 데이터 의존성을 분산하는 명령어 재배치(Instruction Scheduling)를 수행하여 컴파일 단에서 스톨을 회피
2. 분리 캐시 구조(하버드) 설계: 구조적 해저드(IF/MEM 병목)를 완전히 제거하기 위해 코어 내부 L1 캐시를 명령어 전용(I-Cache)과 데이터 전용(D-Cache)으로 분리 탑재
3. 파이프라인 깊이(Depth) 조정: 모바일 프로세서는 전력 효율과 해저드 플러시 패널티를 최소화하기 위해 짧은 8~10단(Stage) 파이프라인을 구성하고, 고성능 프로세서는 15단 이상의 깊은 슈퍼파이프라인(Superpipelining) 구성

**결론 (2줄):**
- 기술사 판단: 파이프라이닝은 폰 노이만 아키텍처의 한계를 극복한 가장 위대한 발명이나, 단계를 맹목적으로 늘리면 래치 오버헤드와 분기 실패 패널티로 인해 '수확 체감의 법칙'에 직면한다.
- 향후 방향: 현대 CPU는 단일 파이프라인의 속도 경쟁을 멈추고, 파이프라인 라인을 여러 개로 늘리는 슈퍼스칼라(Superscalar) 및 다중 코어(Multi-Core) 설계로 스케일아웃(Scale-out) 중이다.
