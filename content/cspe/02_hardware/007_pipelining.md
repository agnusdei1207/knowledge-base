## Ⅰ. 개요
- 정의: 하나의 명령어가 실행되는 과정을 여러 단계로 나누어 동시에 처리하는 기술
- 배경: CPU 클록 주파수 향상의 한계 극복 및 처리량(Throughput) 증대 필요
- 출제 의도: 파이프라인 단계별 동작 원리와 이론적 가속도(Speedup) 계산 이해

## Ⅱ. 구성요소
- ASCII 구조도 (5-Stage Pipeline)
  Cycle:  1     2     3     4     5     6
  Inst1: [IF]--[ID]--[EX]--[MEM]-[WB]
  Inst2:       [IF]--[ID]--[EX]--[MEM]-[WB]
  Inst3:             [IF]--[ID]--[EX]--[MEM]-[WB]

- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| IF (Fetch) | 메모리에서 명령어를 가져옴 | 원재료 투입 |
| ID (Decode) | 명령어를 해석하고 레지스터 읽기 | 공정 분석 |
| EX (Execute) | ALU 연산 또는 주소 계산 | 실제 가공 |
> 요약: 각 단계를 중첩 실행하여 단위 시간당 처리 명령어 수를 늘림

## Ⅲ. 절차
- ASCII 흐름도
  Inst_N -> [Stage 1] -> [Latch] -> [Stage 2] -> [Latch] -> [Stage 3]...

- 4단계 설명
1. 분할: 전체 명령 실행 과정을 동일한 시간 소요를 갖는 세부 단계로 분할
2. 래치(Latch) 설치: 단계 간 데이터 전송을 위한 임시 저장소 배치
3. 중첩 실행: 클록마다 새로운 명령어를 투입하여 모든 단계가 동시에 가동되게 함
4. 완료: 매 사이클마다 하나의 명령어가 최종 단계(WB)를 통과하여 종료됨
> 요약: 분할과 중첩을 통해 개별 실행 시간은 늘어나도 전체 처리량은 향상됨

## Ⅳ. 문제점
- 해저드(Hazard): 데이터 의존성이나 자원 충돌로 인해 파이프라인이 멈춤(Stall)
- 불균형: 각 단계의 처리 시간이 다를 경우 가장 느린 단계에 맞춰 클록이 결정됨

## Ⅴ. 개선방안
- (단기) 포워딩(Forwarding): 연산 결과를 다음 단계로 즉시 전달하여 지연 최소화
- (중기) 분기 예측(Branch Prediction): 제어 해저드 방지를 위한 결과 미리 예측
- (장기) 슈퍼파이프라이닝: 단계를 더 세분화하여 클록 주파수를 극단적으로 향상

## Ⅵ. 전망
- 로드맵: 딥 파이프라인(15단 이상) 구조에서 전력 효율 중심의 적정 단계로 회귀
- CSF: 단계별 부하 균형(Balancing) 및 해저드 제어 로직의 최적화가 성능의 핵심
