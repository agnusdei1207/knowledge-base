## Ⅰ. 개요
- **정의**: 명령어 실행을 독립된 단계로 분할하여 여러 명령어를 중첩 실행하는 기법
- **배경/필요성**: 단일 명령어 완료를 기다리면 CPU 내 유휴 하드웨어가 발생하여 처리율이 낮아짐
- **비유**: 세탁-건조-다림질-정리를 한 묶음씩 순차 처리하지 않고 단계별로 겹쳐 진행하는 세탁소 라인과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 파이프라인 원리와 성능 향상 정량화 | 이상적 처리율 = 단계 수 배 향상 | 지연시간(latency)은 줄지 않음을 명시 |

> 요약: 명령어 단계를 중첩하여 처리율(throughput)을 높이는 구조임

## Ⅱ. 구성요소
```text
  +------+    +------+    +------+    +------+    +------+
  |  IF  |--->|  ID  |--->|  EX  |--->|  MEM |--->|  WB  |
  +------+    +------+    +------+    +------+    +------+
  명령어      명령어       연산        메모리      결과
  인출        해독         실행        접근        기록
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| IF (Instruction Fetch) | PC가 가리키는 주소에서 명령어를 읽어옴 | 주문서 수령 |
| ID (Instruction Decode) | 명령어를 해독하고 레지스터 피연산자를 읽음 | 주문서 해석·재료 준비 |
| EX (Execute) | ALU에서 산술·논리 연산 수행 | 재료 조리 |
| MEM (Memory Access) | 데이터 메모리 읽기/쓰기 수행 | 완성품 포장 |
| WB (Write Back) | 연산 결과를 목적 레지스터에 기록함 | 포장품 선반 배치 |

> 요약: IF-ID-EX-MEM-WB 5단계가 파이프라인의 기본 구성임

## Ⅲ. 절차
```text
  Cycle1       Cycle2       Cycle3       Cycle4       Cycle5
  Instr1:IF    Instr1:ID    Instr1:EX    Instr1:MEM   Instr1:WB
               Instr2:IF    Instr2:ID    Instr2:EX    Instr2:MEM
                            Instr3:IF    Instr3:ID    Instr3:EX
                                         Instr4:IF    Instr4:ID
```
- 1단계: 매 클럭마다 새 명령어를 IF 단계에 투입함
- 2단계: 이전 명령어가 ID로 이동하면 IF가 비어 다음 명령어를 수용함
- 3단계: 5개 단계가 동시에 서로 다른 명령어를 처리하여 처리율이 최대 5배 향상됨
- 4단계: 파이프라인이 가득 찬 정상 상태(steady state)에서 매 클럭 1개 명령어가 완료됨

> 요약: 매 클럭 새 명령어를 투입하여 정상 상태에서 CPI를 1에 근접시킴

## Ⅳ. 문제점
- 해저드 발생: 데이터·제어·구조 해저드로 파이프라인 스톨이 발생함 — 이상적 CPI 1 달성이 저해됨 (008 참조)
- 단계 불균형: 가장 느린 단계가 클럭 주기를 결정함 — 빠른 단계에 유휴 시간이 생겨 효율이 저하됨
- 파이프라인 깊이 한계: 단계를 지나치게 세분화하면 래치 오버헤드가 누적됨 — 클럭 향상 대비 실효 성능 개선이 둔화됨

> 요약: 해저드·단계 불균형·래치 오버헤드가 파이프라인 효율을 제한함

## Ⅴ. 개선방안
1. 단기: 포워딩·분기예측 기법으로 해저드 스톨을 감소시킴 (009 참조)
2. 중기: 각 단계의 지연 시간을 균등화하도록 마이크로아키텍처를 재설계함
3. 장기: 슈퍼파이프라인 대신 슈퍼스칼라·비순차 실행으로 ILP를 확보함 (010 참조)

> 요약: 포워딩·단계 균등화·슈퍼스칼라 전환으로 각 문제를 해결함

## Ⅵ. 전망
- 발전 방향: 단순 깊이 증가보다 넓이(이슈 폭) 확장과 비순차 실행 조합이 주류임
- 기술사적 판단: 파이프라이닝은 모든 고성능 프로세서의 기본 전제이며, 해저드 해결 기법과 함께 출제됨
- 기술사 제언: 파이프라인 설계 시 처리율과 지연시간의 트레이드오프를 정량적으로 분석할 필요
