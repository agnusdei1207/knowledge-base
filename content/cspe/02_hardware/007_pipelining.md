## Ⅰ. 개요
- **정의**: 명령어 처리를 복수 단계로 분할하여 단계별로 서로 다른 명령어를 중첩 실행하는 기법
- **배경/필요성**: 단일 명령어 완료를 기다린 후 다음을 시작하면 각 단계의 하드웨어가 유휴 상태로 낭비됨
- **비유**: 세탁-건조-다림질-정리를 한 사람이 순서대로 하는 대신, 세탁기가 끝나면 바로 다음 빨래를 넣어 작업을 겹치는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 처리량 향상 원리와 한계 | 5단계 구조, 이상적 속도 향상비 = 단계 수 | 지연시간(latency)은 줄지 않음을 명시 |

> 요약: 명령어 실행을 5단계로 분할·중첩하여 처리량(throughput)을 향상시키는 기법임

## Ⅱ. 구성요소
```text
Clock   1   2   3   4   5   6   7   8   9
I1     IF  ID  EX MEM  WB
I2         IF  ID  EX MEM  WB
I3             IF  ID  EX MEM  WB
I4                 IF  ID  EX MEM  WB
I5                     IF  ID  EX MEM  WB
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| IF (Instruction Fetch) | PC가 가리키는 명령어를 I-Cache에서 인출함 | 도서관에서 책 꺼내기 |
| ID (Instruction Decode) | 명령어 필드를 해석하고 레지스터 파일에서 피연산자를 읽음 | 레시피 읽고 재료 준비 |
| EX (Execute) | ALU 연산 또는 주소 계산을 수행함 | 재료를 실제로 조리 |
| MEM (Memory Access) | Load/Store 시 D-Cache에 접근함, 비메모리 명령은 통과 | 완성된 요리를 서빙 창구에 올림 |
| WB (Write Back) | 연산 결과를 레지스터 파일에 기록함 | 완성품을 선반에 정리 |

> 요약: IF-ID-EX-MEM-WB 5단계가 파이프라인 레지스터로 분리되어 매 클럭 1개 명령어를 완료함

## Ⅲ. 절차
```text
IF --> [IF/ID Reg] --> ID --> [ID/EX Reg] --> EX --> [EX/MEM Reg] --> MEM --> [MEM/WB Reg] --> WB
```
- 1단계: **명령어 인출(IF)** — PC 값으로 I-Cache 접근, 명령어를 IF/ID 레지스터에 저장함
- 2단계: **해독·피연산자 읽기(ID)** — 오피코드 해석, 레지스터 파일에서 소스 값 읽음
- 3단계: **실행(EX)** — ALU에서 산술/논리 연산 수행 또는 메모리 주소 계산함
- 4단계: **메모리·쓰기(MEM/WB)** — 필요 시 D-Cache 접근 후 결과를 레지스터에 최종 기록함

> 요약: 인출 → 해독 → 실행 → 메모리/기록 순서로 명령어가 한 클럭씩 이동하며 중첩 실행됨

## Ⅳ. 문제점
- **파이프라인 해저드 발생**: 데이터·제어·구조 의존성이 중첩 실행을 방해함 — 스톨 삽입으로 처리량 저하 (008 참조)
- **최대 클럭 주파수 제약**: 가장 느린 단계가 전체 클럭 주기를 결정함 — 단계 간 불균형 시 빠른 단계의 하드웨어가 유휴화
- **파이프라인 레지스터 오버헤드**: 단계 간 래치가 면적·전력·셋업 타임을 추가함 — 단계를 과도하게 세분화하면 오버헤드가 이득을 초과

> 요약: 해저드, 클럭 주기 제약, 래치 오버헤드가 이상적 속도 향상을 저해함

## Ⅴ. 개선방안
1. 단기: 포워딩·분기 예측(009 참조)으로 해저드 스톨 클럭 수 축소
2. 중기: 각 단계의 게이트 지연을 균등화하여 클럭 주기 최적화 달성
3. 장기: 깊은 파이프라인(슈퍼파이프라인) 도입 시 래치 전력을 감안한 단계 수 최적점 탐색

> 요약: 해저드 해소 → 단계 균등화 → 최적 깊이 설계 순서로 파이프라인 효율을 극대화함

## Ⅵ. 전망
- **발전 방향**: 슈퍼스칼라(010 참조)·비순차 실행과 결합하여 IPC 1 이상 달성 추구
- **기술사적 판단**: 파이프라이닝은 현대 프로세서의 기본 전제이며, 해저드 해결 기법과 함께 출제 빈도가 높음
- **기술사 제언**: 이상적 속도 향상비(= 단계 수)와 현실 저해 요인의 정량적 비교 역량 확보 필요
