## 미리 알고가기

- 파이프라이닝은 명령어 실행 단계를 겹쳐 처리량을 높이는 기법임
- 전형적 5단계는 IF, ID, EX, MEM, WB임
- 단일 명령 지연시간보다 단위 시간당 완료 명령 수를 높이는 기법임

## Ⅰ. 개요

- **정의/개념**: 파이프라이닝은 하나의 명령어 실행을 여러 단계로 나누고, 서로 다른 명령어가 각 단계를 동시에 점유하도록 만들어 CPU 처리량을 높이는 명령어 수준 병렬 처리 구조임
- **배경/필요성**: 단일 명령어를 순차적으로 모두 끝낸 뒤 다음 명령으로 넘어가면 하드웨어 자원 활용률이 낮기 때문에, 단계를 겹쳐 자원을 계속 일하게 만들 필요가 생김

## Ⅱ. 특징

- 단계 중첩으로 명령어 처리량을 높임
- 각 단계 시간이 비슷할수록 느린 단계가 전체 클록을 묶는 현상이 줄어듦
- 분기와 데이터 의존성과 자원 충돌이 있으면 성능이 저하됨
- 깊은 파이프라인은 클록 주기 단축에 유리하지만 flush 패널티도 커짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 비파이프라인 | 5단계 파이프라인 |
|:---|:---|:---|
| 처리 방식 | 명령어 순차 완결 | 단계 중첩 수행 |
| 장점 | 단순 구현 | 높은 처리량 |
| 한계 | 자원 활용 낮음 | 해저드 관리 필요 |
| 적합 환경 | 단순 MCU | 범용 CPU 기본 구조 |

> 요약: 파이프라인은 명령어 지연시간보다 단위 시간당 완료 명령 수를 높이는 구조임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| IF | 명령어를 메모리에서 가져오며 front-end 시작점이 됨 |
| ID | 명령어를 해독하고 레지스터를 읽어 실행 준비를 수행함 |
| EX | ALU 연산과 주소 계산을 수행하는 실행 단계임 |
| MEM/WB | 메모리 접근과 결과 기록으로 명령어 사이클을 마무리함 |

```text
+-----+     +-----+     +-----+     +-----+     +-----+
| IF  | --> | ID  | --> | EX  | --> | MEM | --> | WB  |
+-----+     +-----+     +-----+     +-----+     +-----+
```

> 요약: 5단계 파이프라인은 인출, 해독, 실행, 메모리, 기록을 나눠 서로 다른 명령어가 동시에 진행되게 함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 명령어 인출     | --> | 해독 및 준비     | --> | 연산·주소 계산   | --> | 메모리/기록    |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **명령어 인출**: IF가 다음 명령어를 가져옴
2. **해독 및 준비**: ID가 명령 형식과 피연산자를 분석함
3. **연산과 주소 계산**: EX가 연산 또는 주소 계산을 수행함
4. **메모리와 기록**: MEM과 WB가 결과를 반영함

> 요약: 파이프라인 성능은 단계 균형과 해저드 비용이 기대 처리량을 얼마나 보존하는지로 결정됨.

## Ⅵ. 실무 적용 및 유의점

1. 단계 시간 불균형이나 명령어 의존성이 크면 stage balancing, latch 조정, forwarding을 적용하고 cycle time, stage utilization, CPI로 검증함
2. 깊은 파이프라인은 분기 예측 실패와 flush 비용이 커지므로 pipeline depth와 branch prediction을 워크로드에 맞추고 branch misprediction penalty와 perf per watt로 확인함

## Ⅶ. 결론

- 파이프라이닝의 판단 기준은 단계를 많이 나누는 데 있지 않고 각 단계를 균형 있게 겹쳐 하드웨어 유휴 시간을 줄이는 데 있음

## 작성 근거(검토용)

- 파이프라이닝의 판단 축을 속도 일반론이 아니라 처리량, 단계 균형, 해저드 비용으로 제한함
- 모호한 표현은 단위 시간당 완료 명령 수와 stage utilization으로 구체화함
- 결론은 단계 수 자체가 아니라 단계 중첩과 유휴 시간 감소가 판단 대상임을 드러냄
