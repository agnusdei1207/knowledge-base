# 007. 파이프라이닝 기본 구조 5단계 (Pipelining) [출제:122회]

## 미리 알고가기

- **처리량 (Throughput)**: 단위 시간당 완료되는 명령어의 수이며, 파이프라이닝의 직접적인 개선 목표임
- **지연 시간 (Latency)**: 하나의 명령어가 시작해서 끝날 때까지 걸리는 시간임
- **파이프라인 레지스터 (Latch)**: 각 단계 사이에서 중간 결과값을 보관하여 단계별 독립적 동작을 가능하게 함

## Ⅰ. 개요

- **정의/개념**: 파이프라이닝(Pipelining)은 하나의 명령어 실행 과정을 여러 단계로 분할하고, 각 단계마다 서로 다른 명령어를 동시에 처리함으로써 CPU의 처리량을 높이는 병렬 처리 기법임
- **배경/필요성**: 단일 사이클 방식은 가장 느린 명령어의 처리 시간에 클록을 맞춰야 하므로 자원 낭비가 심함. 이를 극복하기 위해 세차장이나 생산 라인처럼 여러 명령어를 겹쳐서 실행하여 CPU 이용률을 극대화함

## Ⅱ. 특징 및 비교

파이프라이닝은 개별 명령어의 속도보다는 '공장 전체의 생산량'을 늘리는 데 집중함.

| 비교 항목 | 단일 사이클 (Single-Cycle) | 파이프라인 (Pipelined) |
|:---|:---|:---|
| **실행 방식** | 한 번에 한 명령어만 끝까지 실행 | **여러 명령어를 단계별로 중첩 실행** |
| **클록 주기** | 가장 느린 명령어의 총 실행 시간 | **가장 느린 한 단계(Stage)의 실행 시간** |
| **주요 장점** | 설계가 매우 단순함 | **전체 처리량(Throughput) 비약적 향상** |
| **주요 단점** | CPU 자원 활용도가 낮음 | 해저드 제어가 복잡하고 설계가 어려움 |
| **성능 지표** | 지연 시간(Latency) 최소화 | **처리량(Throughput) 극대화** |

> 요약: 개별 명령어의 응답 시간(Latency)은 비슷하거나 약간 늘어나지만, 전체 작업 완료 시간은 획기적으로 단축됨.

## Ⅲ. 구성요소/구조

고전적인 RISC(MIPS 등) 아키텍처의 표준 5단계 구조는 다음과 같음.

- **5단계 구성**:
  1. **IF (Instruction Fetch)**: PC가 가리키는 주소에서 명령어를 읽어옴
  2. **ID (Instruction Decode)**: 명령어를 해석하고 필요한 레지스터 값을 읽음
  3. **EX (Execute)**: ALU를 사용하여 연산하거나 주소를 계산함
  4. **MEM (Memory Access)**: 데이터 메모리에 접근하여 읽거나 씀 (Load/Store)
  5. **WB (Write Back)**: 연산 결과나 읽어온 데이터를 레지스터에 기록함

- **파이프라인 동작도 (ASCII)**:

```text
Cycle  |  1  |  2  |  3  |  4  |  5  |  6  |  7  |
-------+-----+-----+-----+-----+-----+-----+-----+
Inst 1 | IF  | ID  | EX  | MEM | WB  |     |     |
Inst 2 |     | IF  | ID  | EX  | MEM | WB  |     |
Inst 3 |     |     | IF  | ID  | EX  | MEM | WB  |
Inst 4 |     |     |     | IF  | ID  | EX  | MEM |
-------+-----+-----+-----+-----+-----+-----+-----+
         명령어 중첩 실행 영역 (Parallelism)
```

1. **단계 사이 레지스터**: 각 단계 사이에는 이전 단계의 결과물을 다음 클록까지 보관할 '파이프라인 레지스터'가 존재함
2. **이상적 CPI**: 매 클록마다 새로운 명령어가 투입되고 완료되므로, 이상적인 경우 $CPI = 1$이 됨

## Ⅳ. 문제점 및 개선방안

1. **파이프라인 해저드 (Hazards)**: 명령어 간의 의존성이나 자원 충돌로 인해 파이프라인이 멈추는 현상임
   - **개선방안**: 포워딩(Forwarding), 분기 예측(Branch Prediction), 컴파일러 스케줄링 등을 통해 해저드 영향을 최소화함 (확인: Stall 사이클 발생 횟수)

2. **단계 불균형 (Stage Imbalance)**: 특정 단계(예: MEM)의 소요 시간이 다른 단계보다 길면 전체 클록 속도가 그 단계에 맞춰 느려짐
   - **개선방안**: 파이프라인 단계를 더 세분화(Super-pipelining)하거나, 하드웨어 설계를 최적화하여 각 단계의 실행 시간을 균등하게 맞춤 (확인: 크리티컬 패스 지연 시간)

3. **클록 오버헤드**: 파이프라인 레지스터 자체의 지연 시간과 셋업/홀드 시간 때문에 단계를 무한정 늘릴 수 없음
   - **개선방안**: 전력 소모와 성능 이득 사이의 트레이드오프를 분석하여 목표 워크로드에 최적화된 파이프라인 깊이를 결정함 (확인: 클록 주파수와 전력 효율)

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 고성능 서버 CPU | 15~20단계 이상의 깊은 파이프라인을 구축하여 클록 주파수를 5GHz 이상으로 높임 | IPC (Instructions Per Cycle), 클록 속도 |
| 실시간 임베디드 | 예측 가능성(Determinism)을 위해 3~5단계의 얕은 파이프라인을 유지하여 실시간성 확보 | 최악 실행 시간 (WCET), 전력 소모 |
| AI 가속기 (NPU) | 대량의 단순 연산을 처리하기 위해 수천 개의 연산 유닛에 최적화된 전용 파이프라인 설계 | 처리량 (FLOPS), 메모리 대역폭 이용률 |

> 요약: 고성능은 깊은 파이프라인, 실시간/저전력은 얕은 파이프라인을 선호함.

## Ⅵ. 결론

파이프라이닝은 CPU 아키텍처에서 성능 향상을 위한 가장 기본적이면서도 강력한 병렬 처리 기법임. 기술사는 파이프라인의 5단계 동작 원리를 넘어, 실제 시스템에서 발생하는 해저드와 단계 불균형 문제를 어떻게 하드웨어와 소프트웨어(컴파일러)가 협력하여 극복하는지 통찰해야 함.

향후 파이프라이닝은 슈퍼스칼라(Superscalar) 및 비순서 실행(OoO) 기술과 결합하여 더욱 복잡해지겠지만, '단계를 나누어 겹친다'는 핵심 철학은 변하지 않음. 결국 효율적인 파이프라인 설계는 제한된 전력 예산 내에서 최상의 처리량을 뽑아내기 위한 끊임없는 최적화의 과정임.
