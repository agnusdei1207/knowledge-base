# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 파이프라이닝은 CPU가 명령어 하나가 다 끝나기를 기다리지 않고, 명령어 처리 단계를 나눠 여러 명령어를 겹쳐 실행하는 명령어 수준 병렬성(ILP) 기법이다.
- **왜 필요한가**: 명령어 1개가 모든 회로를 다 통과할 때까지 다음 명령어를 못 받는 방식(단일 사이클)은 나머지 부품을 놀게 만들어, 클럭을 아무리 올려도 처리 효율이 바닥이다.
- **핵심 직관**: 자동차 조립 컨베이어 벨트다. 뼈대 조립이 끝나 엔진을 얹으러 가면, 뼈대 조립부는 쉬지 않고 즉시 다음 차의 뼈대를 시작한다.

## 핵심 용어 정리 (내부에 등장하는 것들)

아래 표기들은 답안용 Ⅰ~Ⅵ에 그대로 등장하므로 먼저 직관으로 풀어 둔다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 파이프라이닝 (Pipelining) | 명령어 처리 단계를 분할해 여러 명령어를 시공간적으로 겹쳐 실행 | 컨베이어 벨트식 연속 공정 |
| 처리량 (Throughput) | 단위 시간당 처리 완료되는 명령어 총량 — 파이프라인의 목적 | 하루에 생산된 총 자동차 대수 |
| 지연 시간 (Latency) | 명령어 하나가 입력되어 완료될 때까지 걸리는 절대 시간 | 차 1대가 완성되는 절대 시간 |
| IF·ID·EX·MEM·WB | 인출→해독→실행→메모리접근→기록의 5단계 하드웨어 구역 | 조립 라인의 5개 작업 구역 |
| 래치 (Pipeline Latch) | 단계 사이에서 클럭마다 중간 결과를 넘겨주는 버퍼 레지스터 | 벨트 사이의 이송 트레이 |
| CPI / IPC | 명령어당 클럭 수 / 클럭당 완료 명령어 수 (이상값 CPI=1.0, IPC=1.0) | 라인이 꽉 찼을 때 1클럭당 1대 출고 |
| 스톨·버블 (Stall/Bubble) | 흐름이 막혀 파이프라인을 멈추고 빈 슬롯을 넣는 것 | 재료가 없어 벨트에 빈 칸이 흐름 |
| 속도 향상도 (Speed-up, S) | 단일 사이클 대비 파이프라인의 성능 배수 | 5배 빨라진 출고 속도 |

## 깊이 이해
- **배경·문제의식**: 단일 사이클 CPU는 1번 명령이 인출→해독→실행을 다 끝낼 때까지 다음 명령이 못 들어와, 클럭 주기가 가장 느린 작업에 하향 평준화되고 유휴 회로가 넘쳐났다.
- **작동 원리 (MIPS 5단계)**: ① IF(메모리에서 명령어 인출) ② ID(해독·레지스터 읽기) ③ EX(ALU 연산) ④ MEM(데이터 읽기/쓰기) ⑤ WB(레지스터에 결과 기록). 1번 명령이 ID로 넘어가면 IF 구역이 즉시 비므로 2번 명령을 끌어온다. 5클럭이 지나 파이프라인이 꽉 차면(Fill) 이후 매 클럭 1개씩 완료(WB)가 쏟아진다.
- **비유**: 5시간짜리 코스 요리를 1시간 간격으로 5개 테이블에 시차를 두고 낸다. 첫 손님이 다 먹고 나가는 데는 여전히 5시간이지만(지연 시간 동일), 그 뒤로는 1시간마다 한 팀씩 식사를 마친다(처리량 5배).
- **구체 예시**: 단일 사이클로 5개 명령을 처리하면 25클럭이 걸린다. 5단 파이프라인은 첫 명령 완료에 5클럭, 나머지 4개가 1클럭씩 뒤따라 총 9클럭에 5개를 끝낸다. 명령이 100개면 단일 사이클 500클럭 대 파이프라인 104클럭이다.
- **흔한 오해·주의점**: 파이프라이닝은 명령어 1개의 처리 속도(Latency)를 줄이는 기술이 아니다. 명령어 하나가 겪는 시간은 래치 오버헤드 때문에 오히려 미세하게 늘어난다. 오직 공장 전체 생산량(Throughput)만 비약적으로 올린다.

## 연결 개념
- 파이프라인 해저드 (008) — 겹쳐 실행할 때 흐름이 깨지는 충돌 현상
- 슈퍼스칼라 아키텍처 (Superscalar) — 파이프라인을 여러 벌 두어 공간 병렬성 확보
- 명령어 집합 — RISC vs CISC (단계 균등 분할이 쉬운 RISC가 파이프라인에 유리)

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 명령어 실행 과정을 여러 마이크로 단계로 분할해 순차 중첩(Overlap) 실행하는 하드웨어 시간적 병렬성 기법임.
> 2. **가치**: 단계별로 유휴 상태이던 하드웨어 블록을 동시 가동해, 매 클럭 명령어 완료 수(목표 IPC=1.0) 처리량을 극대화함.
> 3. **판단 포인트**: 단(Stage)을 깊게 쪼갤수록 클럭은 올라가나, 분기 실패·데이터 의존성 스톨 페널티가 급증함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 파이프라이닝 하드웨어 메커니즘과 동작 흐름 파악 | IF-ID-EX-MEM-WB 5단계 분할, 시공간 중첩 도식 | 처리 속도(Latency) 단축과 처리량(Throughput) 향상 혼동 |
| 정량적 성능 향상 기준과 한계 통찰 | 속도 향상도 $S$ 공식, 깊은 파이프라인 트레이드오프 | 5단계를 나열만 하고 래치 오버헤드·해저드 한계 누락 |

> 요약: 개별 명령어 지연 시간은 늘어나되 전체 처리량이 이상적으로 N배 향상되는 인과를 선형 흐름도로 증명함.

---

## Ⅰ. 개요 및 필요성

- 개요: 하나의 명령어가 완료되기 전 다음 명령어를 단계별 하드웨어에 중첩 실행하는 명령어 수준 병렬성(ILP) 구조임
- 배경: 단일 사이클 구조는 명령어 1개가 전 회로를 통과할 때까지 나머지 회로가 유휴 상태이고, 클럭 주기가 최악 경로에 하향 평준화됨
- 필요성: 각 단계를 클럭 동기 래치로 분리해 여러 명령어를 동시 주입, CPU 처리량을 단계 수(N)에 근접하게 높이기 위해 필수임

---

## Ⅱ. 구조 및 구성요소

```text
[파이프라이닝 5단계 구조 및 하드웨어 매핑]
PC -> IF -> 래치 -> ID -> 래치 -> EX -> 래치 -> MEM -> 래치 -> WB -> 레지스터
      인출         해독         실행         접근          기록
      (I-Cache)   (디코더)     (ALU)        (D-Cache)     (Register File)
```

| 단계 | 수행 역할 | 매핑 하드웨어 |
|:---|:---|:---|
| IF (Instruction Fetch) | PC 주소로 메모리에서 명령어 인출 | I-Cache, PC 증가기 |
| ID (Instruction Decode) | 명령어 해독·레지스터 피연산자 준비 | 디코더, 레지스터 파일(읽기) |
| EX (Execute) | ALU 산술·논리 연산 및 분기 주소 계산 | ALU, 상태 레지스터 |
| MEM (Memory Access) | Load/Store 시 데이터 메모리 접근 | D-Cache |
| WB (Write Back) | 최종 결과를 타겟 레지스터에 기록 | 레지스터 파일(쓰기 포트) |

> 요약: 5개 물리 구역 사이에 래치를 두어 클럭마다 결과를 넘김으로써 각 구역이 독립 가동됨.

---

## Ⅲ. 동작원리 및 흐름도

```text
[시공간 중첩(Overlapping) 사이클 흐름]
Clock : C1   C2   C3   C4   C5   C6   C7
Inst1 : IF   ID   EX   MEM  WB
Inst2 :      IF   ID   EX   MEM  WB
Inst3 :           IF   ID   EX   MEM  WB
```

- 1단계 (초기 채움 Fill): C1~C4에 명령어가 순차 유입되어 각 단계를 하나씩 채우며, 아직 완료 명령어는 없는 오버헤드 구간임
- 2단계 (만개 Full): C5에서 1번 명령이 WB로 완료되고, 이 시점부터 5개 유닛이 모두 서로 다른 명령어로 가동됨
- 3단계 (정상 궤도 Steady State): 해저드 0 이상 환경에서 C6·C7… 매 클럭 명령어 1개씩 꾸준히 완료(목표 CPI=1.0)됨
- 4단계 (비우기 Drain/Flush): 마지막 명령 유입 후 잔여 단계가 빠져나가거나, 분기 실패 시 내부를 강제 플러시(버블 삽입)해 비움

> 요약: 래치 채움 오버헤드를 넘겨 정상 궤도에 오르면, 매 클럭 1개 작업 완료가 쏟아짐.

---

## Ⅳ. 특징

- 속도 향상도 공식: $S = \dfrac{n \times k}{k + (n-1)}$ (단 수 $k$, 명령어 수 $n$). $n$이 무한대로 커지면 최대 $k$배에 수렴함
- 처리량은 향상되나 지연은 증가: 단계 구분 래치의 지연·클럭 스큐(Skew) 때문에 명령어 1개당 절대 지연 시간(Latency)은 단일 사이클보다 오히려 길어짐
- 해저드 취약: 데이터 의존(이전 결과 즉시 필요), 분기(다음 주소 미확정), 자원 충돌 시 흐름이 깨져 스톨·버블이 삽입됨
- 균등 분할 의존: 가장 느린 단계가 클럭 주기를 결정하므로, 5단계 지연이 불균등하면 이론 향상도에 크게 못 미침

> 요약: 이론상 단 수 $k$만큼 처리량이 오르되, 실제 성능은 래치 오버헤드와 분기·데이터 충돌 페널티에 삭감됨.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 단일 사이클 | 전형적 파이프라인 (5~8단) | 깊은 파이프라인 (15단 이상) |
|:---|:---|:---|:---|
| 클럭 주파수 한계 | 최악 경로(명령어 전체)에 병목 | 단계 균등 분할 한계까지 상승 | 매우 높음 (극도로 쪼개 고주파 달성) |
| 분기 실패 페널티 | 없음 (1명령 완료 후 분기) | 약 2~4 사이클 버블 | 매우 치명적 (10~20 사이클 플러시) |
| IPC (클럭당 처리) | 정확히 1.0 | 1.0 이하 (해저드로 저하) | 1.0에 크게 미달 (스톨 빈발) |
| 적합 조건 | 단순·저전력 임베디드 | 범용 코어 표준 | 고클럭 지향, 강한 분기 예측 전제 |

> 요약: 단계를 잘게 쪼갤수록 클럭은 오르나 분기 실패 시 비우는 비용이 커져, 깊은 파이프라인은 분기 예측률 95% 이상을 강제함.

리스크·대응(불릿):
- 리스크 — 데이터 해저드(이전 EX 결과를 다음 명령이 즉시 요구) — 대응: EX→EX 직통 우회 포워딩 경로로 RAW 스톨 최소화 (008·009 참조)
- 리스크 — 제어 해저드(분기 결과 미확정으로 IF 대기) — 대응: BHT·BTB 동적 분기 예측기로 플러시 비율 5% 미만 유지 (009 참조)
- 리스크 — 래치 오버헤드 증가(단 수 과다 분할) — 대응: 단 수를 12~15단 선에서 억제하고 잉여 트랜지스터는 OoO·예측기에 재배분

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 슈퍼스칼라 확장: 단일 5단 파이프라인의 IPC 1.0 한계를 넘기 위해, 파이프라인을 여러 벌 두어 클럭당 명령어 2~4개를 동시 발급(Issue)해 공간 병렬성 추가 확보
2. 비순차 실행(OoO) 결합: 데이터 준비가 끝난 명령어부터 순서를 섞어 파이프라인 유휴 구간(버블)에 선제 투입, 스톨 은닉
3. VLIW 적용: DSP·가속기 환경에서 하드웨어 해저드 탐지를 줄이고, 컴파일러가 충돌 없는 명령어를 긴 명령어로 묶어 주입 정합성 보장

**결론 (2줄):**
- 기술사 판단: 5~8단 범용 코어면 정적 예측+간단한 BTB로 충분하나, 고클럭 깊은 파이프라인이면 다단 동적 예측기와 OoO를 함께 도입해야 버블 역효과를 막음
- 향후 방향: 파이프라인 깊이 확장은 약 12~15단 선에서 한계에 도달했으며, 잉여 자원은 OoO 실행과 AI 접목 분기 예측기 고도화에 집중 투입되고 있음
