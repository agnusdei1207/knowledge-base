## 미리 알고가기

- 파이프라이닝은 명령어 실행 단계를 겹쳐 처리량을 높이는 기법임
- 전형적 5단계는 IF, ID, EX, MEM, WB임
- 단일 명령 지연시간보다 단위 시간당 완료 명령 수를 높이는 기법임
- 해저드(Hazard): 파이프라인 단계 간 자원·데이터·제어 흐름 충돌로 정상 진행이 막히는 상황임
- CPI(Cycles Per Instruction): 명령어 한 개를 완료하는 데 평균적으로 소요되는 클록 사이클 수임
- 클록 주기(Clock Cycle): 파이프라인 한 단계가 진행되는 데 걸리는 기준 시간 간격임
- 조합 논리(Combinational Logic): 입력이 정해지면 지연 후 바로 출력이 정해지는 회로임

## 작성 근거(검토용)

- **개요 구성**: 파이프라이닝의 핵심은 단계 중첩으로 처리량을 높이는 것이므로 정의에 직접 배치함
- **Ⅱ. 특징 선정**: 처리량 향상, 단계 균형에 따른 유휴 시간, 해저드로 인한 성능 저하, 단계 세분화 트레이드오프는 파이프라인 성능을 가르는 요소임
- 파이프라이닝의 판단 축을 처리 방식·지연 대 처리량·제약 조건으로 제한함
- 비파이프라인과 5단계 파이프라인을 처리 방식·지연 대 처리량·제약 조건으로 비교함
- Ⅳ는 단계별 역할을, Ⅴ는 여러 명령어가 클록마다 겹쳐 진행되는 시간 흐름을 다뤄 서로 다른 내용을 담음

## Ⅰ. 개요

- **정의/개념**: 파이프라이닝은 하나의 명령어 실행을 여러 단계로 나누고, 서로 다른 명령어가 각 단계를 동시에 점유하도록 만들어 CPU 처리량을 높이는 명령어 수준 병렬 처리 구조임
- **배경/필요성**: CPU 자원 활용률과 명령어 처리량을 높이기 위해 실행 단계를 중첩하는 구조가 필요함

### 쉽게 이해하기 (학습용)
- 세탁기 한 대로 빨래·건조·개기를 순서대로 다 마친 뒤 다음 빨래를 시작하지 않고, 세탁·건조·정리 자리를 나눠 서로 다른 빨래가 동시에 지나가게 하는 것과 같음

## Ⅱ. 특징

- 단계 중첩으로 명령어 처리량을 높임
- 단계별 지연이 비슷하면 최장 단계가 만드는 유휴 시간을 줄일 수 있음
- 분기와 데이터 의존성과 자원 충돌이 있으면 성능이 저하됨
- 단계를 세분화하면 단계별 조합 논리 지연은 줄지만 분기 실패 시 폐기할 단계 수가 늘어남

### 쉽게 이해하기 (학습용)
- 세탁·건조·정리 중 가장 오래 걸리는 자리가 전체 속도를 정하고, 앞 빨래 결과를 기다려야 하거나 자리가 부딪히면 뒷사람이 멈춰야 함
- 자리를 더 잘게 쪼개면 한 자리당 대기 시간은 줄지만, 방금 넣은 빨래가 잘못됐다고 뒤늦게 밝혀지면 이미 진행 중이던 자리들의 일을 더 많이 버려야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 비파이프라인 | 5단계 파이프라인 |
|:---|:---|:---|
| 처리 방식 | 명령어 순차 완결, 한 시점에 일부 자원만 사용 | 단계 중첩 수행, 서로 다른 단계의 자원을 동시 사용 |
| 지연 대 처리량 | 한 명령의 전 단계를 연속 수행해 단일 명령 지연은 짧음 | 단계마다 다른 명령이 중첩돼 단위 시간당 완료 명령 수 증가 |
| 제약 조건 | 클록 주기가 전체 조합 경로 지연에 좌우됨 | 단계 불균형·데이터 의존·분기 실패 관리 필요 |

> 요약: 파이프라인은 명령어 지연시간보다 단위 시간당 완료 명령 수를 높이는 구조임.

### 쉽게 이해하기 (학습용)
- 한 사람이 빨래 한 세트를 처음부터 끝까지 혼자 다 하면 그 한 세트는 빨리 끝나지만, 여러 명이 세탁·건조·정리를 나눠 맡으면 일정이 안 맞을 때만 밀리고 평소엔 단위 시간당 끝나는 빨래 세트 수가 늘어남

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| IF | 명령어를 메모리에서 가져와 다음 단계로 전달함 |
| ID | 명령어를 해독하고 레지스터를 읽어 실행 준비를 수행함 |
| EX | ALU 연산과 주소 계산을 수행하는 실행 단계임 |
| MEM | 데이터 메모리를 읽거나 씀 |
| WB | 연산·메모리 결과를 레지스터에 기록함 |

```text
+-----+     +-----+     +-----+     +-----+     +-----+
| IF  | --> | ID  | --> | EX  | --> | MEM | --> | WB  |
+-----+     +-----+     +-----+     +-----+     +-----+
```

> 요약: 5단계 파이프라인은 인출, 해독, 실행, 메모리, 기록을 나눠 서로 다른 명령어가 동시에 진행되게 함.

### 쉽게 이해하기 (학습용)
- 빨래 담기(IF), 종류 확인(ID), 세탁(EX), 헹굼·탈수(MEM), 정리해 넣기(WB)처럼 각 자리가 정해진 일만 하고 결과를 다음 자리로 넘김

## Ⅴ. 원리 및 절차 흐름도

```text
클록:    1    2    3    4    5    6    7    8
I1      IF   ID   EX  MEM   WB
I2           IF   ID   EX  MEM   WB
I3                IF   ID   EX  MEM   WB
I4                     IF   ID   EX  MEM   WB
```

1. **인출 개시**: 매 클록마다 새 명령어가 IF 단계에 진입함
2. **단계 중첩**: 앞선 명령어가 다음 단계로 넘어가는 클록에 새 명령어가 그 앞 단계를 점유함
3. **정상 상태 도달**: 5클록 이후에는 매 클록마다 한 명령어가 WB 단계에서 완료됨
4. **해저드 개입**: 데이터 의존이나 분기 미확정이 있으면 해당 단계에서 정체 또는 폐기가 발생해 완료 간격이 벌어짐

> 요약: 여러 명령어가 클록마다 한 단계씩 밀려 들어가 정상 상태에서는 매 클록 한 명령어가 완료되지만, 해저드가 끼어들면 완료 간격이 벌어짐.

### 쉽게 이해하기 (학습용)
- 매 시각 새 빨래가 첫 자리에 들어가고 앞 빨래는 한 자리씩 밀려나며, 자리가 다 차면 매 시각 한 세트씩 완성되지만 순서가 꼬이면 그 자리에서 멈추거나 되돌려야 함

## Ⅵ. 실무 사례

1. CPU 파이프라인은 최장 단계의 지연을 줄이기 위해 단계 경계를 재배치하고, 클록 주기와 단계 이용률로 검증함
2. 깊은 파이프라인은 분기 실패로 폐기되는 명령을 줄이기 위해 분기 예측기를 조정하고, 분기 실패 손실 사이클과 CPI로 검증함

### 쉽게 이해하기 (학습용)
- 가장 오래 걸리는 자리의 일감을 옆 자리로 조금씩 옮겨 병목을 줄이거나, 다음에 올 빨래 순서를 미리 맞혀 헛수고를 줄이는 것과 같음

## Ⅶ. 결론

- 파이프라이닝은 단계 수보다 최장 단계 지연, 해저드 CPI, 단계 이용률을 기준으로 처리량 개선 여부를 판단해야 함
- 분기 실패율이 높은 워크로드에는 단계를 깊게 나누기보다 분기 예측기 개선이나 얕은 단계 구성을 우선 적용해야 함

### 쉽게 이해하기 (학습용)
- 자리를 몇 개로 나눴는지보다 가장 오래 걸리는 자리, 꼬임으로 버려지는 시간, 자리별 노는 시간을 보고 전체 속도를 판단해야 함
