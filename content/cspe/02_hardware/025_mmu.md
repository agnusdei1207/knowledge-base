## 미리 알고가기

- MMU는 CPU가 만든 가상 주소를 물리 주소로 바꾸는 하드웨어임
- TLB와 페이지 테이블 순회기는 MMU 안에서 주소 변환 성능을 좌우함
- 접근 권한과 캐시 속성도 MMU가 함께 해석함

## 작성 근거(검토용)

- MMU는 주소 변환·권한 검사·메모리 속성·예외 처리를 같은 주소 접근 경로로 설명함
- MMU와 MPU는 변환 여부·보호 단위·메타데이터·적용 환경을 같은 수준으로 비교함
- 주소 변환 지연과 권한 검사 결과를 MMU 적용 기준으로 정리함

## Ⅰ. 개요

- **정의/개념**: MMU는 CPU의 메모리 접근 요청에 대해 주소 변환·접근 권한 검사·캐시 및 장치 메모리 속성 해석을 수행하는 하드웨어 장치임
- **배경/필요성**: 프로세스 격리·가상화·캐시 정책을 함께 적용하기 위해 주소 변환과 권한 검사를 수행하는 전용 하드웨어가 필요함

## Ⅱ. 특징

- 가상 주소를 물리 주소로 변환해 프로세스별 주소 공간을 분리함
- 읽기·쓰기·실행 권한을 검사해 허용되지 않은 접근에 예외를 발생시킴
- 캐시 가능, write-back, device memory 같은 속성을 함께 해석해 메모리 일관성을 맞춤
- TLB 미스 시 페이지 테이블 순회 지연이 메모리 접근 시간에 추가됨

## Ⅲ. 종류 및 비교

| 판단 기준 | MMU | MPU |
|:---|:---|:---|
| 주소 변환 | 가상 주소를 물리 주소로 매핑함 | 보통 변환 없이 영역 보호만 수행함 |
| 보호 단위 | 페이지별 접근 권한 | 기준 주소·크기로 정의한 영역별 권한 |
| 관리 정보 | 페이지 테이블·TLB | 영역 설명자 |
| 예외 조건 | 페이지 부재·권한 위반 | 영역 범위·권한 위반 |
| 적용 환경 | 범용 운영체제·서버·모바일 SoC | MCU·RTOS·안전 제어기 |

> 요약: MMU는 가상 주소 변환과 보호를 함께 수행하고, MPU는 제한된 영역 보호에 집중함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| TLB | 최근 주소 변환 결과를 보관해 MMU의 반복 조회 비용을 줄임 |
| 페이지 테이블 순회기 | TLB 미스 시 다단계 페이지 테이블에서 매핑을 찾음 |
| 권한·속성 검사기 | 읽기·쓰기·실행 권한과 캐시·장치 메모리 속성을 판정함 |
| 예외 발생기 | 권한 위반이나 부재 페이지를 발견하면 운영체제 예외를 발생시킴 |

```text
+-------------+     +---------------------+     +------------------+
| CPU 요청      | --> | MMU                 | --> | 물리 메모리        |
+-------------+     +---------------------+     +------------------+
                          |        |        |
                          v        v        v
                      +------+ +------+ +---------+
                      | TLB  | | 순회기 | | 예외 발생기 |
                      +------+ +------+ +---------+
```

> 요약: MMU는 TLB·페이지 테이블 순회기·권한 및 속성 검사기·예외 발생기로 주소 접근을 제어함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+     +-------------+
| 접근 요청 수신  | --> | TLB 조회        | --> | 적중·페이지 순회   | --> | 권한·속성 검사   | --> | 메모리 접근 수행 |
+-------------+     +-------------+     +-------------+     +-------------+     +-------------+
```

1. **접근 요청 수신**: CPU가 가상 주소와 접근 종류를 MMU에 전달함
2. **TLB 조회**: 최근 매핑 정보로 즉시 변환 가능한지 확인함
3. **적중 또는 페이지 순회**: TLB 미스면 페이지 테이블에서 새 매핑을 가져옴
4. **권한과 속성 검사**: 접근 권한, 캐시 정책, 장치 속성을 판정함
5. **메모리 접근 수행**: 권한이 있으면 물리 메모리에 접근하고 없으면 예외를 발생시킴

> 요약: MMU는 TLB 조회 후 권한·속성을 검사하고 조건이 맞을 때만 물리 메모리에 접근함.

## Ⅵ. 실무 사례

1. 대용량 데이터베이스는 대형 페이지를 적용하고 TLB 실패율과 평균 메모리 접근시간을 확인함
2. 가상화 호스트는 하드웨어 지원 중첩 페이징을 적용하고 가상 머신 메모리 지연과 중첩 페이지 순회율을 확인함

## Ⅶ. 결론

- MMU는 주소 변환 지연과 권한·메모리 속성 검사 결과를 기준으로 메모리 접근을 제어함
