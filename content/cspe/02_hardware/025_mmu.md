## 미리 알고가기

- **가상 주소(Virtual Address)**: CPU가 프로세스를 실행하며 생성하는 논리적인 주소 공간
- **물리 주소(Physical Address)**: 실제 메인 메모리(RAM)에 접근하기 위한 하드웨어적인 주소
- **페이지 테이블(Page Table)**: 가상 주소와 물리 주소의 대응 관계 및 권한 정보를 담고 있는 메모리 상의 자료구조
- **TLB(Translation Lookaside Buffer)**: 주소 변환 속도를 높이기 위해 최근 사용된 페이지 테이블 엔트리를 저장하는 고속 캐시

## Ⅰ. 개요

- **정의/개념**: 메모리 관리 장치(Memory Management Unit, MMU)는 CPU가 생성하는 가상 주소를 실제 물리 주소로 변환하고, 메모리 접근 권한 검사 및 보호를 수행하는 핵심 하드웨어 장치임
- **배경/필요성**: 다중 프로그래밍 환경에서 각 프로세스가 독립된 주소 공간을 가질 수 있게 하여 메모리 충돌을 방지하고, 물리 메모리 용량 이상의 프로그램을 실행할 수 있는 가상 메모리 시스템을 구현하기 위해 필수적임. 하드웨어 수준에서 주소 변환을 처리함으로써 소프트웨어 방식보다 압도적으로 빠른 연산 속도를 보장함

## Ⅱ. 특징 및 비교

### 가. MMU의 주요 기능 및 역할

| 구분 | 주요 기능 | 상세 설명 |
|:---|:---|:---|
| 주소 변환 | 논리 → 물리 변환 | 가상 주소의 페이지 번호를 물리 프레임 번호로 매핑 |
| 메모리 보호 | 접근 권한 체크 | 읽기/쓰기/실행 권한을 확인하여 위반 시 트랩(Trap) 발생 |
| 메모리 격리 | 프로세스 간 보호 | 각 프로세스가 자신의 할당 영역 외에는 접근 불가하도록 강제 |
| 캐싱 지원 | TLB 관리 | 빈번한 주소 변환 결과를 내부 캐시에 저장하여 지연 최소화 |

> 요약: MMU는 시스템의 '보안 요원'이자 '주소 안내원' 역할을 동시에 수행함

### 나. MMU 유무에 따른 시스템 차이
- **MMU 탑재 (범용 PC/서버)**: 가상 메모리 사용 가능, 다중 프로세스 격리 우수, OS 복잡도 높음
- **MMU 미탑재 (저사양 MCU/임베디드)**: 물리 주소 직접 접근, 실시간성 유리, 메모리 오염 위험 존재

## Ⅲ. 구성요소/구조

### 가. MMU 기반 주소 변환 메커니즘 및 흐름도

```text
[가상 주소 입력] -> [TLB 조회] --(Hit)--> [물리 주소 생성]
                        |
                     (Miss)
                        v
          [Page Table Walker (Page Walk)] -> [권한/유효성 체크] -> [물리 주소]
```

### 나. 주요 구성 요소 및 역할

| 구성요소 | 역할 및 설명 | 핵심 포인트 |
|:---|:---|:---|
| 페이지 테이블 워커 | TLB Miss 시 메모리의 다단계 페이지 테이블을 탐색함 | 하드웨어 로직으로 구현되어 고속 작동 |
| TLB (변환 버퍼) | 최근 변환 정보를 담은 전용 캐시 | Hit Rate가 전체 시스템 성능을 좌우함 |
| 기준 레지스터 | 현재 프로세스의 페이지 테이블 시작 주소를 가리킴 | 문맥 교환 시 이 레지스터 값이 갱신됨 |
| 경계 레지스터 | 세그멘테이션 사용 시 메모리 한계 범위를 저장 | 범위를 벗어난 접근 차단 |
| 권한 비트 검사 회로 | R/W/X 및 유저/커널 모드 권한을 실시간 검사 | 보안 위반 시 Segmentation Fault 유발 |

> 요약: 주소 변환을 위한 '지도(페이지 테이블)'와 '요약본(TLB)'을 관리하는 복합 장치임

## Ⅳ. 문제점 및 개선방안

1. **주소 변환 지연(Latency)**: 다단계 페이지 테이블 탐색 시 여러 번의 메모리 접근이 발생하여 CPU가 대기함
   - **개선방안**: L1/L2 TLB 계층화, 페이지 워크 캐시(PWC) 도입, Huge Page 사용을 통해 변환 횟수와 지연을 축소함

2. **가상화 오버헤드**: 가상 머신(VM) 환경에서는 게스트 가상 → 게스트 물리 → 호스트 물리로 이어지는 이중 변환 필요
   - **개선방안**: 하드웨어 가속 기술인 EPT(Extended Page Table) 또는 NPT(Nested Page Table)를 활용하여 2차 주소 변환을 MMU가 직접 처리함

3. **장치 DMA의 메모리 오염**: CPU를 거치지 않는 주변 장치의 직접 메모리 접근(DMA)은 MMU의 보호망을 벗어남
   - **개선방안**: 주변 장치 전용 MMU인 **IOMMU(VT-d/AMD-Vi)**를 도입하여 장치의 메모리 접근도 가상화하고 격리함

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 리눅스 커널 운영 | 문맥 교환 시 PCID(Process-Context ID)를 활용해 MMU의 TLB 효율성 극대화 | Context Switch Latency |
| 컨테이너 격리 (Docker) | 커널 수준의 가상 주소 공간 분리를 통해 컨테이너 간 메모리 간섭 차단 | Memory Isolation Quality |
| AI 가속기 (NPU) | 대규모 데이터를 처리하는 NPU 내부에도 전용 MMU/IOMMU를 배치하여 고속 주소 변환 수행 | Data Throughput, Latency |

> 요약: 고성능 시스템 설계 시 'MMU 캐시 적중률'과 'IOMMU 활용도'는 성능 최적화의 필수 항목임

## Ⅵ. 결론

MMU는 현대 컴퓨터 아키텍처에서 가상 메모리라는 거대한 추상화를 지탱하는 핵심적인 하드웨어 기둥임. 단순히 주소를 바꾸는 기능을 넘어, 시스템의 보안, 멀티태스킹의 안정성, 그리고 하드웨어 가상화의 기반 기술로서 그 중요성이 날로 커지고 있음.

기술사는 CPU 제조사별 MMU 구현의 특징과 가상화 환경에서의 2단계 주소 변환 원리를 명확히 이해해야 함. 특히 최근 CXL(Compute Express Link) 기반의 메모리 풀링이나 분산 메모리 환경이 확산됨에 따라, 로컬 메모리를 넘어선 원격 메모리 주소 변환까지 포괄하는 확장된 MMU 설계 관점에서의 통찰력이 요구됨.
