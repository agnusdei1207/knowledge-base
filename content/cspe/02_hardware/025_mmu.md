## 미리 알고가기

- 가상 주소: CPU가 명령 실행 중 생성하는 프로세스 기준 주소임
- 물리 주소: 실제 메모리 장치의 위치를 가리키는 주소임
- 페이지 테이블: 가상 페이지와 물리 프레임의 매핑, 권한, 상태 비트를 저장하는 자료구조임
- TLB: 최근 주소 변환 결과를 캐시해 페이지 테이블 접근을 줄이는 하드웨어 버퍼임

## Ⅰ. 개요

- **정의**: MMU는 CPU가 생성한 가상 주소를 페이지 테이블, TLB, 보호 비트 기준으로 물리 주소로 변환하고 접근 권한을 검사해 프로세스 격리와 가상 메모리를 구현하는 하드웨어 장치임
- **배경/필요성**: 다중 프로세스 환경에서는 각 프로세스가 독립 주소 공간을 가진 것처럼 실행되어야 하며, 잘못된 주소 접근은 시스템 전체 장애로 이어질 수 있음. MMU는 주소 변환과 보호를 하드웨어 경로에서 수행해 성능과 안전성을 동시에 확보함
- **비유**: 건물 입구에서 사원증을 확인하고 실제 사무실 위치로 안내하는 보안 데스크와 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 가상 메모리의 하드웨어 지원 구조를 설명하는 역량 확인 | 가상 주소, TLB, 페이지 테이블 워크, 권한 비트, 페이지 폴트 | OS 기능으로만 설명, TLB 누락, 보호 검사 누락 |

> 요약: MMU는 주소 변환, 캐싱, 보호 검사를 하드웨어로 수행해 가상 메모리의 실행 기반을 제공함.

## Ⅱ. 특징/비교

| 판단 기준 | 소프트웨어 주소 관리 | MMU 기반 주소 관리 |
|:---|:---|:---|
| 변환 위치 | OS나 런타임이 명시적으로 주소를 관리 | CPU 메모리 접근 경로에서 자동 변환 |
| 보호 수준 | 프로그램 오류에 취약하고 격리 비용 큼 | 권한 비트와 예외로 프로세스 격리 |
| 성능 조건 | 단순 시스템에는 충분 | TLB 적중률과 페이지 테이블 구조가 핵심 |

> 요약: MMU는 주소 관리 비용을 하드웨어 경로로 옮겨 격리와 성능을 동시에 달성하는 방식임.

- MMU는 페이지 크기, 다단계 페이지 테이블, 권한 비트, 캐시 정책과 결합해 메모리 접근 전체 성능에 영향을 줌
- TLB miss가 많으면 페이지 테이블 워크가 증가해 CPU 파이프라인이 지연됨
- 가상화 환경에서는 게스트 주소와 호스트 주소 변환이 중첩되어 EPT/NPT 같은 2차 변환 지원이 필요함

## Ⅲ. 구성요소

```text
+-----------+      +-----------+      +-----------+
| 가상주소  | ---> | MMU/TLB   | ---> | 물리주소  |
+-----------+      +-----------+      +-----------+
                        |
                        v
                  +-----------+
                  | 페이지표  |
                  | 권한검사  |
                  +-----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 주소 변환기 | 가상 페이지 번호와 오프셋을 분리해 물리 프레임 번호와 결합함 | 주소를 실제 위치로 바꾸는 안내원 |
| TLB | 최근 변환 결과를 저장해 페이지 테이블 접근을 줄임 | 자주 찾는 번호의 단축 목록 |
| 페이지 테이블 워커 | TLB miss 시 메모리의 페이지 테이블을 따라가 변환 정보를 찾음 | 서류철을 단계별로 찾는 담당자 |
| 보호 검사 회로 | 읽기, 쓰기, 실행, 사용자·커널 권한을 확인해 예외를 발생시킴 | 출입 권한 검사대 |

> 요약: MMU는 TLB 캐시, 페이지 테이블 탐색, 권한 검사 회로가 결합된 주소 변환 하드웨어임.

## Ⅳ. 절차

```text
+-----------+      +-----------+      +-----------+      +-----------+
| 주소입력  | ---> | TLB조회   | ---> | 권한검사  | ---> | 메모리접근 |
+-----------+      +-----------+      +-----------+      +-----------+
        |                 |
        v                 v
   +-----------+     +-----------+
   | miss      | --> | 페이지워크 |
   +-----------+     +-----------+
```

1. **주소 입력**: CPU가 load, store, fetch 명령으로 가상 주소와 접근 유형을 MMU에 전달함
2. **TLB 조회**: 가상 페이지 번호로 최근 변환 정보를 찾고 miss 시 페이지 테이블 워크를 수행함
3. **권한과 상태 확인**: present, read/write, execute, user/supervisor 비트를 확인하고 위반 시 예외를 발생시킴
4. **물리 접근 수행**: 물리 프레임 번호와 오프셋을 결합해 캐시·메모리 계층에 접근함

> 요약: MMU는 TLB 적중을 우선 활용하고 실패 시 페이지 테이블을 탐색한 뒤 권한 검사를 통과한 접근만 허용함.

## Ⅴ. 문제점

- **P1 TLB miss 비용**: 워킹셋이 TLB 용량보다 크거나 페이지 크기가 작으면 페이지 테이블 워크로 지연이 증가함
- **P2 페이지 테이블 메모리 부담**: 큰 가상 주소 공간과 많은 프로세스는 다단계 페이지 테이블 저장 공간을 증가시킴
- **P3 가상화 중첩 변환**: 게스트와 호스트 주소 변환이 겹치면 메모리 접근마다 추가 워크가 발생할 수 있음

> 요약: MMU 성능은 변환 캐시 적중률, 페이지 테이블 크기, 가상화 변환 깊이에 의해 좌우됨.

## Ⅵ. 개선방안

1. **단기**: TLB miss, page walk cycles, 권한 예외 로그를 측정해 지연 원인을 분리함
2. **중기**: huge page, ASID/PCID, 적절한 페이지 크기와 메모리 배치를 적용해 변환 빈도를 줄임
3. **장기**: 가상화와 NUMA를 포함한 주소 변환 정책을 플랫폼 표준으로 관리함

- **P1 대응**: huge page와 TLB 친화적 데이터 배치를 적용함 (확인: TLB miss rate)
- **P2 대응**: 다단계 테이블, 공유 페이지, 희소 매핑 정책으로 페이지 테이블 공간을 줄임 (확인: 페이지 테이블 메모리 사용량)
- **P3 대응**: 하드웨어 2차 주소 변환과 IOMMU 설정을 최적화함 (확인: VM 메모리 접근 지연)

> 요약: MMU 최적화는 페이지 크기, 변환 캐시, 가상화 보조 기능을 함께 조정해야 효과가 있음.

## Ⅶ. 전망

- **발전 방향**: CXL 메모리, 가속기, IOMMU가 결합되면서 CPU 중심 주소 변환을 넘어 장치 간 공유 가상 주소 관리가 중요해짐
- **기술사적 판단**: 보안 관점에서는 실행 금지, 권한 분리, 메모리 태깅 같은 하드웨어 보호 기능과 MMU의 결합이 강화됨
- **기술사 제언**: 기술사는 MMU를 단순 주소 변환기가 아니라 성능, 격리, 가상화, 장치 DMA 보호의 공통 기반으로 설명해야 함
