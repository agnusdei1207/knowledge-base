## 미리 알고가기

- MMU는 CPU가 만든 가상 주소를 물리 주소로 바꾸는 하드웨어임
- TLB와 페이지 테이블 순회기는 MMU 안에서 주소 변환 성능을 좌우함
- 접근 권한과 캐시 속성도 MMU가 함께 해석함
- 중첩 페이징(Nested Paging): 게스트 가상 주소를 호스트 물리 주소로 변환하기 위해 게스트·호스트 페이지 테이블을 차례로 거치는 가상화 주소 변환 방식임

## 작성 근거(검토용)

- MMU는 주소 변환·권한 검사·메모리 속성·예외 처리를 같은 주소 접근 경로로 설명함
- MMU와 MPU는 주소 변환·보호 단위·적용 환경을 같은 수준으로 비교함
- 주소 변환 지연과 권한 검사 결과를 MMU 적용 기준으로 정리함

## Ⅰ. 개요

- **정의/개념**: MMU는 CPU의 메모리 접근 요청에 대해 주소 변환·접근 권한 검사·캐시 및 장치 메모리 속성 해석을 수행하는 하드웨어 장치임
- **배경/필요성**: 프로세스 격리·가상화·캐시 정책을 함께 적용하기 위해 주소 변환과 권한 검사를 수행하는 전용 하드웨어가 필요함

### 쉽게 이해하기 (학습용)
- 건물 안내데스크가 방문객이 부른 가명 호실을 실제 호실로 바꿔주고, 들어가도 되는지까지 함께 확인해주는 것과 같음

## Ⅱ. 특징

- 가상 주소를 물리 주소로 변환해 프로세스별 주소 공간을 분리함
- 읽기·쓰기·실행 권한을 검사해 허용되지 않은 접근에 예외를 발생시킴
- 캐시 가능 여부·라이트백(Write-back) 정책·장치 메모리(Device Memory) 속성을 함께 해석해 메모리 일관성을 유지함
- TLB 미스 시 페이지 테이블 순회 지연이 메모리 접근 시간에 추가됨

### 쉽게 이해하기 (학습용)
- 방문객마다 가명을 실제 호실로 바꿔 서로 다른 공간에 들여보내고, 출입증 없이 들어가려 하면 막아서며, 창고 물건인지 저장 규칙까지 함께 확인함
- 최근 안내한 호실은 메모해두지만, 메모에 없으면 안내대장을 처음부터 다시 훑어야 해 시간이 더 걸림

## Ⅲ. 종류 및 비교

| 판단 기준 | MMU | MPU |
|:---|:---|:---|
| 주소 변환 | 가상 주소를 물리 주소로 매핑함 | 변환 없이 지정한 영역만 보호함 |
| 보호 단위 | 페이지 테이블·TLB로 페이지별 권한을 검사함 | 영역 설명자로 기준 주소·크기별 권한을 검사함 |
| 적용 환경 | 범용 운영체제·서버·모바일 SoC | MCU·RTOS·안전 제어기 |

> 요약: MMU는 가상 주소 변환과 보호를 함께 수행하고, MPU는 제한된 영역 보호에 집중함.

### 쉽게 이해하기 (학습용)
- MMU는 가명을 실제 호실로 바꿔주는 안내데스크이고, MPU는 이미 정해진 구역만 출입증으로 통제하는 경비원임

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| TLB | 최근 주소 변환 결과를 보관해 MMU의 반복 조회 비용을 줄임 |
| 페이지 테이블 순회기 | TLB 미스 시 다단계 페이지 테이블에서 매핑을 찾음 |
| 권한·속성 검사기 | 읽기·쓰기·실행 권한과 캐시·장치 메모리 속성을 판정함 |
| 예외 발생기 | 권한 위반이나 부재 페이지를 발견하면 운영체제 예외를 발생시킴 |

```text
+-------------+     +---------------------+     +------------------+
| CPU 요청      | --> | MMU                 | --> | 물리 메모리        |
+-------------+     +---------------------+     +------------------+
                          |        |        |
                          v        v        v
                      +------+ +------+ +---------+
                      | TLB  | | 순회기 | | 예외 발생기 |
                      +------+ +------+ +---------+
```

> 요약: MMU는 TLB·페이지 테이블 순회기·권한 및 속성 검사기·예외 발생기로 주소 접근을 제어함.

### 쉽게 이해하기 (학습용)
- 최근 안내 기록(TLB), 대장을 처음부터 찾는 직원(순회기), 출입 자격을 확인하는 경비(권한·속성 검사기), 문제가 있으면 경보를 울리는 장치(예외 발생기)가 함께 안내데스크를 이룸

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+     +-------------+
| 접근 요청 수신  | --> | TLB 조회        | --> | 적중·페이지 순회   | --> | 권한·속성 검사   | --> | 메모리 접근 수행 |
+-------------+     +-------------+     +-------------+     +-------------+     +-------------+
```

1. **접근 요청 수신**: CPU가 가상 주소와 접근 종류를 MMU에 전달함
2. **TLB 조회**: 최근 매핑 정보로 즉시 변환 가능한지 확인함
3. **적중 또는 페이지 순회**: TLB 미스면 페이지 테이블에서 새 매핑을 가져옴
4. **권한과 속성 검사**: 접근 권한, 캐시 정책, 장치 속성을 판정함
5. **메모리 접근 수행**: 권한이 있으면 물리 메모리에 접근하고 없으면 예외를 발생시킴

> 요약: MMU는 TLB 조회 후 권한·속성을 검사하고 조건이 맞을 때만 물리 메모리에 접근함.

### 쉽게 이해하기 (학습용)
- 방문객이 가명 호실과 용건(접근 종류)을 말하면 먼저 최근 기록을 보고, 없으면 대장을 새로 찾고, 마지막으로 출입 자격을 확인한 뒤에만 문을 열어줌

## Ⅵ. 실무 사례

1. 대용량 데이터베이스는 대형 페이지를 적용하고 TLB 실패율과 평균 메모리 접근시간을 확인함
2. 가상화 호스트는 하드웨어 지원 중첩 페이징을 적용하고 가상 머신 메모리 지연과 중첩 페이지 순회율을 확인함

### 쉽게 이해하기 (학습용)
- 큰 자료를 다루는 곳은 안내 범위를 넓혀 대장을 덜 찾게 하고, 건물 안에 또 다른 건물(가상 머신)이 있으면 안내를 두 번 거쳐야 함

## Ⅶ. 결론

- MMU는 CPU의 메모리 접근마다 가상 주소를 물리 주소로 바꾸고 접근 권한·메모리 속성을 함께 검사하는 하드웨어임
- 페이지 단위 변환과 세밀한 권한 검사가 필요한 범용 운영체제·서버에는 MMU를, 변환 없이 단순 영역 보호만 필요한 MCU·RTOS에는 MPU를 적용해야 함

### 쉽게 이해하기 (학습용)
- 안내데스크가 얼마나 빨리 실제 호실을 찾아주는지와 출입 자격 확인 결과를 함께 살펴야 함
