## 미리 알고가기

- MMU는 CPU가 만든 가상 주소를 물리 주소로 바꾸는 하드웨어임
- TLB와 페이지 테이블 순회기는 MMU 안에서 주소 변환 성능을 좌우함
- 접근 권한과 캐시 속성도 MMU가 함께 해석함

## Ⅰ. 개요

- **정의/개념**: MMU는 CPU의 메모리 접근 요청에 대해 주소 변환, 접근 권한 검사, 캐시 가능 여부와 장치 메모리 속성 해석을 수행하는 핵심 하드웨어 제어 장치임
- **배경/필요성**: 프로세스 격리·가상화·캐시 정책을 함께 적용하기 위해 주소 변환과 권한 검사를 수행하는 전용 하드웨어가 필요함

## Ⅱ. 특징

- 가상 주소를 물리 주소로 즉시 변환해 프로세스별 독립 주소 공간을 제공함
- 읽기·쓰기·실행 권한을 검사해 메모리 보호와 커널 격리를 보장함
- 캐시 가능, write-back, device memory 같은 속성을 함께 해석해 메모리 일관성을 맞춤
- TLB 미스와 page walk 비용이 크므로 MMU 품질은 평균 접근 시간과 직접 연결됨

## Ⅲ. 종류 및 비교

| 판단 기준 | MMU | MPU |
|:---|:---|:---|
| 주소 변환 | 가상 주소를 물리 주소로 매핑함 | 보통 변환 없이 영역 보호만 수행함 |
| 메모리 관리 | 페이징과 TLB를 통해 큰 주소 공간을 다룸 | 제한된 개수의 고정 영역을 관리함 |
| 장점 | 프로세스 격리·가상화·공유를 정교하게 지원함 | 구조가 단순하고 지연이 작음 |
| 적합 환경 | 범용 OS, 서버, 모바일 SoC | 소형 MCU, 단순 RTOS, 안전 제어기 |

> 요약: MMU는 가상 주소 변환과 보호를 함께 수행하고, MPU는 제한된 영역 보호에 집중함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| TLB | 최근 주소 변환 결과를 보관해 MMU의 반복 조회 비용을 줄임 |
| Page Table Walker | TLB 미스 시 다단계 페이지 테이블을 따라가며 새로운 매핑을 찾아옴 |
| Permission and Attribute Checker | 읽기·쓰기·실행 권한과 cacheability와 device memory 속성을 판정함 |
| Fault Generator | 권한 위반이나 미존재 페이지를 발견하면 예외를 발생시켜 OS 개입을 유도함 |

```text
+-------------+     +---------------------+     +------------------+
| CPU Request  | --> | MMU                 | --> | Physical Memory  |
+-------------+     +---------------------+     +------------------+
                          |        |        |
                          v        v        v
                      +------+ +------+ +---------+
                      | TLB  | | PTW  | | Fault   |
                      +------+ +------+ +---------+
```

> 요약: MMU는 TLB, page table walker, 권한·속성 검사, fault 발생기로 주소 접근을 제어함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+     +-------------+
| 접근 요청 수신  | --> | TLB 조회        | --> | page walk 또는 hit | --> | 권한·속성 검사   | --> | 메모리 접근 수행 |
+-------------+     +-------------+     +-------------+     +-------------+     +-------------+
```

1. **접근 요청 수신**: CPU가 가상 주소와 접근 종류를 MMU에 전달함
2. **TLB 조회**: 최근 매핑 정보로 즉시 변환 가능한지 확인함
3. **page walk 또는 hit 처리**: 미스면 페이지 테이블을 따라가 새 매핑을 가져옴
4. **권한과 속성 검사**: 접근 권한, 캐시 정책, 장치 속성을 판정함
5. **메모리 접근 수행**: 조건이 맞으면 물리 메모리 접근을 진행하고 아니면 fault를 발생시킴

> 요약: MMU는 TLB 조회 후 권한·속성을 검사하고 조건이 맞을 때만 물리 메모리에 접근함.

## Ⅵ. 실무 적용 및 유의점

1. 작업 집합이 커지면 TLB 미스와 page walk가 누적되므로 huge page와 page walk cache를 적용하고 TLB miss rate, average memory access time으로 확인함
2. 페이지 테이블이 커지면 메타데이터가 실효 메모리를 줄이므로 multi-level 또는 inverted page table을 선택하고 page table memory overhead, translation latency로 확인함
3. 가상화 환경은 nested translation으로 지연이 커지므로 hardware-assisted nested paging을 적용하고 VM memory latency, nested walk frequency로 확인함

## Ⅶ. 결론

MMU는 단순 주소 변환기가 아니라 보호 정책, 캐시 속성, 예외 처리를 함께 집행하는 장치이며, 핵심 판단은 translation penalty 통제에 있음.

## 작성 근거(검토용)

- MMU는 주소 변환뿐 아니라 권한 검사, cache attribute, fault 처리를 함께 설명함
- 모호한 표현은 TLB miss rate, page table memory overhead, nested walk frequency로 구체화함
- 결론은 기능 수보다 translation penalty 통제로 정리함
