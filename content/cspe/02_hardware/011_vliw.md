## Ⅰ. 개요
- **정의**: 컴파일러가 독립 연산들을 하나의 긴 명령어 워드에 묶어 동시 발행하는 프로세서 구조
- **배경/필요성**: 하드웨어 스케줄링 로직을 제거하면 칩 면적과 전력을 줄일 수 있으므로, 병렬 발행 책임을 컴파일러로 이전할 필요가 있음
- **비유**: 택배 기사가 매번 경로를 계산하는 대신, 물류센터(컴파일러)가 미리 최적 배송 묶음을 만들어 전달하는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 슈퍼스칼라 대비 VLIW의 구조 차이 이해 | 병렬성 판단 주체가 컴파일러임 | 하드웨어 의존성 검사 로직이 없다는 점 명시 |

> 요약: 컴파일러가 ILP를 정적으로 추출하여 하드웨어 복잡도를 줄이는 아키텍처임

## Ⅱ. 구성요소
```text
  +--------------------------------------------------+
  |              VLIW Instruction Word                |
  |  +--------+  +--------+  +--------+  +--------+  |
  |  | Slot 0 |  | Slot 1 |  | Slot 2 |  | Slot 3 |  |
  |  | ALU Op |  | MEM Op |  | FP Op  |  | BR Op  |  |
  |  +--------+  +--------+  +--------+  +--------+  |
  +--------------------------------------------------+
         |             |            |            |
         v             v            v            v
    +----------+  +----------+  +--------+  +--------+
    | ALU Unit |  | Load/St  |  | FP Unit|  | Branch |
    +----------+  +----------+  +--------+  +--------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 명령어 워드 | 고정 폭의 긴 워드에 여러 연산 슬롯을 배치함 | 칸이 나뉜 도시락 상자 |
| 기능 유닛 | ALU·메모리·부동소수점·분기 등 슬롯별 전용 실행 유닛 | 각 칸에 대응하는 조리 도구 |
| 정적 스케줄러 | 컴파일러가 의존성 분석 후 슬롯에 연산을 배치함 | 도시락을 미리 싸는 영양사 |
| NOP 패딩 | 슬롯에 배정할 연산이 없으면 NOP을 채움 | 빈 칸에 넣는 칸막이 |

> 요약: 컴파일러가 채운 고정 폭 명령어 워드를 다수 기능 유닛이 동시 실행하는 구조임

## Ⅲ. 절차
```text
  정적 분석        슬롯 배치       워드 발행       병렬 실행
  (의존성 검출)    (연산 묶음)     (Fetch/Decode)  (FU 동시수행)
     |               |               |               |
     +---분석결과---->+---워드생성---->+---전체발행---->+
  데이터/제어     NOP 삽입        단일 Decode     결과 Write-back
  의존성 그래프   소프트웨어 파이프  하드웨어 단순   레지스터 파일
```
- 1단계: 컴파일러가 데이터·제어 의존성 그래프를 구성하여 병렬 가능 연산을 식별함
- 2단계: 독립 연산들을 슬롯에 배치하고, 빈 슬롯은 NOP으로 채움
- 3단계: 프로세서가 긴 명령어 워드를 한 번에 페치·디코드함
- 4단계: 각 기능 유닛이 해당 슬롯의 연산을 동시에 실행하고 결과를 기록함

> 요약: 컴파일 시점에 병렬성을 확정하고, 실행 시점에는 단순 발행·실행만 수행함

## Ⅳ. 문제점
- 코드 팽창: NOP 패딩으로 바이너리 크기가 슈퍼스칼라 대비 2~3배 증가함 — I-캐시 미스율 상승으로 성능 저하 유발
- 이진 호환성 부재: 슬롯 수·기능 유닛 구성이 바뀌면 재컴파일이 필수임 — 세대 간 바이너리 호환이 불가함
- 동적 이벤트 대응 한계: 캐시 미스·분기 예측 실패 등 런타임 변동에 정적 스케줄이 적응하지 못함 — 실행 유닛 유휴 사이클 증가

> 요약: 정적 스케줄링의 경직성이 코드 크기·호환성·런타임 적응력에서 문제를 발생시킴

## Ⅴ. 개선방안
1. 단기: 명령어 압축(instruction compression) 기법 적용으로 NOP 제거 및 바이너리 크기 절감
2. 중기: 가상 ISA 계층 도입으로 하드웨어 변경 시 런타임 번역을 통해 이진 호환 확보
3. 장기: 정적 스케줄과 소규모 동적 재배치를 결합한 하이브리드 실행 모델로 런타임 변동 대응

> 요약: 압축·추상 ISA·하이브리드 스케줄링으로 VLIW의 정적 한계를 보완함

## Ⅵ. 전망
- 발전 방향: DSP·GPU·AI 가속기 등 워크로드 패턴이 예측 가능한 영역에서 VLIW 구조가 지속 활용됨
- 기술사적 판단: 범용 CPU에서는 슈퍼스칼라(012 참조)에 밀렸으나, 전력 효율이 중요한 임베디드·가속기 분야에서 경쟁력 유지 중임
- 기술사 제언: VLIW 기반 도메인 특화 프로세서 설계 시, 컴파일러 최적화 역량 확보가 성능의 핵심 결정 요소임
