## Ⅰ. 개요
- **정의**: 컴파일러가 병렬 실행 가능한 연산을 하나의 긴 명령어 워드로 묶어 발행하는 아키텍처
- **배경/필요성**: 슈퍼스칼라(010 참조)는 하드웨어가 실행 시점에 병렬성을 판단하므로 회로가 복잡해짐. 병렬성 판단을 컴파일 타임으로 옮기면 하드웨어를 단순화할 수 있음
- **비유**: 요리사가 즉석에서 재료를 고르는 대신, 레시피 작성자가 미리 동시에 조리할 재료를 한 묶음으로 포장해 주는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 슈퍼스칼라와의 차이 | 병렬성 판단 주체가 컴파일러임 | 하드웨어 스케줄링이 아닌 정적 스케줄링임을 명시 |
| 컴파일러 의존 문제 | NOP 삽입으로 인한 코드 팽창 | 바이너리 호환성 부재 문제도 언급 필요 |

> 요약: 컴파일러가 병렬 연산을 정적으로 묶어 하드웨어 복잡도를 줄이는 아키텍처임

## Ⅱ. 구성요소
```text
+----------------+     +------------------+     +----------------+
| Source Code     | --> | VLIW Compiler    | --> | Long Instruction|
| (High-level)   |     | (Static Schedule)|     | Word (128bit+) |
+----------------+     +------------------+     +----------------+
                                                       |
                              +------------------------+
                              v
                  +-----------+-----------+
                  |  FU0  |  FU1  |  FU2  |  (Functional Units)
                  +-------+-------+-------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| VLIW 컴파일러 | 의존성 분석 후 병렬 연산을 하나의 워드로 패킹함 | 택배 포장사가 동시 배송할 물건을 한 상자에 담음 |
| 긴 명령어 워드 | 복수 연산 슬롯을 포함하는 고정 길이 명령어(128~1024bit) | 칸이 여러 개인 도시락 용기 |
| 기능 유닛(FU) | 각 슬롯의 연산을 병렬로 수행하는 실행 하드웨어 | 도시락 칸별로 배정된 조리대 |
| NOP 슬롯 | 병렬 연산이 부족할 때 빈 슬롯을 채우는 무연산 | 도시락 빈 칸에 넣는 칸막이 |

> 요약: 컴파일러가 연산을 패킹하고, 고정 길이 워드를 통해 복수 FU가 동시 실행함

## Ⅲ. 절차
```text
Source Code --> Dependency Analysis --> Operation Grouping --> NOP Padding --> VLIW Issue
```
- 1단계: **의존성 분석** — 컴파일러가 데이터/제어 의존성 그래프를 생성함
- 2단계: **연산 그룹핑** — 의존성이 없는 연산을 동일 워드 슬롯에 배치함
- 3단계: **NOP 패딩** — 슬롯이 남으면 NOP을 삽입하여 고정 길이를 유지함
- 4단계: **워드 발행** — 완성된 긴 명령어 워드를 한 사이클에 모든 FU로 동시 디스패치함

> 요약: 컴파일 타임에 의존성을 분석하고 슬롯을 채워 한 사이클에 병렬 발행함

## Ⅳ. 문제점
- **코드 팽창**: 병렬 연산 부족 시 NOP이 다수 삽입되어 바이너리 크기가 2~3배 증가함
- **바이너리 비호환**: FU 수·슬롯 구조가 변경되면 기존 바이너리를 재컴파일해야 함
- **분기 예측 한계**: 런타임 분기 결과를 컴파일 타임에 예측하기 어려워 슬롯 활용률이 저하됨

> 요약: NOP 팽창, 바이너리 비호환, 정적 분기 예측 한계가 주요 문제임

## Ⅴ. 개선방안
1. 단기: **압축 VLIW(EPIC)** — NOP 슬롯을 압축 인코딩하여 코드 팽창을 완화함
2. 중기: **가변 길이 번들** — 슬롯 수를 유연하게 조정하여 세대 간 바이너리 호환성을 확보함
3. 장기: **프로파일 기반 컴파일** — 런타임 프로파일을 피드백하여 분기 확률 기반 슬롯 배치를 최적화함

> 요약: 압축 인코딩, 가변 번들, 프로파일 피드백으로 VLIW 한계를 단계적으로 극복함

## Ⅵ. 전망
- **발전 방향**: DSP·GPU 셰이더 등 제어 흐름이 단순한 도메인에서 VLIW 원리가 지속 활용됨
- **기술사적 판단**: 범용 CPU에서는 슈퍼스칼라(010 참조)에 밀렸으나, 도메인 특화 프로세서에서 설계 단순성의 장점이 유효함
- **기술사 제언**: VLIW와 슈퍼스칼라의 트레이드오프를 도메인 특성에 맞게 선택하는 아키텍처 판단 역량이 필요함
