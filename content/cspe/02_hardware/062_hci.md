## Ⅰ. 개요
- 서버, 스토리지, 네트워크를 하나의 x86 서버에 통합한 가상화 플랫폼
- 데이터센터 인프라를 소프트웨어 중심으로 단순화하는 차세대 방식

| 구분 | 내용 |
| --- | --- |
| 정의 | 가상화 기술을 통해 모든 인프라 자원을 단일 시스템에 통합 |
| 배경 | 복잡한 3-Tier(Server-Switch-Storage) 구조의 한계 극복 |
| 출제의도 | HCI의 통합 구조 및 SDS 기반의 확장 메커니즘 이해 |

## Ⅱ. 구성요소
```
+------------------------------------------+
|  [ HCI Node (x86 Server) ]               |
| +--------------------------------------+ |
| | Virtualization (Hypervisor)          | |
| +--------------------------------------+ |
| | SDS (Software Defined Storage)       | |
| +--------------------------------------+ |
| | Local Storage (SSD/HDD)              | |
| +--------------------------------------+ |
+------------------------------------------+
(노드 추가 시 연산+저장 자원 동시 확장)
```
| 구성요소 | 설명 | 비유 |
| --- | --- | --- |
| Hypervisor | CPU, 메모리 자원을 가상화하여 VM 구동 | 거주 구획 |
| SDS | 노드들의 로컬 디스크를 묶어 가상 스토리지 형성 | 공동 창고 |
| Central Mgmt | 전체 클러스터를 단일 화면에서 제어하는 도구 | 관리 사무소 |
> 요약: 서버 한 대에 모든 인프라 기능을 넣어 쌓아 올리는 방식임.

## Ⅲ. 절차
```
[노드 설치] -> [클러스터 구성] -> [자원 풀링] -> [서비스 배포]
```
1. 설치: 표준 x86 서버에 HCI 전용 소프트웨어(vSAN, Nutanix 등) 설치함.
2. 구성: 네트워크로 연결된 노드들을 하나의 클러스터로 묶음.
3. 풀링: 각 노드의 디스크와 연산 자원을 논리적으로 통합함.
4. 배포: 통합된 풀 위에 가상 머신(VM)이나 컨테이너 즉시 생성함.
> 요약: 소프트웨어 클릭만으로 인프라 전체를 구성하고 배포함.

## Ⅳ. 문제점
- 불균형 확장: 연산만 필요한데 스토리지까지 같이 늘려야 하는 낭비 발생함.
- 성능 간섭: 동일 노드 내 VM 간 자원 경쟁으로 성능 예측 어려움.

## Ⅴ. 개선방안
- dHCI 도입: Disaggregated HCI를 통해 서버와 스토리지를 분리 확장함.
- QoS 설정: 태스크별 자원 할당량 제한(Throttling)으로 상호 간섭 차단함.

## Ⅵ. 전망
- 엣지 컴퓨팅 및 프라이빗 클라우드 구축의 표준 모델로 안착됨.
- 클라우드 네이티브(K8s)와의 완벽한 통합이 향후 기술 경쟁력임.
