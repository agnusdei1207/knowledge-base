## Ⅰ. 개요
- **정의**: CPU가 발행하는 가상 주소를 물리 주소로 변환하고, 메모리 접근 권한을 검사하는 하드웨어 장치
- **배경/필요성**: 프로세스마다 독립된 주소 공간을 제공하려면 주소 변환과 보호 기능이 하드웨어 수준에서 지원되어야 함
- **비유**: 건물 안내 데스크가 방문자의 호실 번호(가상)를 실제 층·호(물리)로 변환하고, 출입 권한을 확인하는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 주소 변환 과정과 TLB 역할 이해 | 페이지 테이블 워크 경로와 TLB 히트/미스 흐름 | TLB와 캐시의 역할을 혼동하지 않을 것 |

> 요약: MMU는 가상→물리 주소 변환과 접근 권한 검사를 수행하는 하드웨어임

## Ⅱ. 구성요소
```text
CPU ---> Virtual Address
              |
         +----------+
         |   TLB    |--hit--> Physical Address
         +----------+
              |miss
              v
         +---------------+
         | Page Table    |
         | Walker (PTW)  |
         +---------------+
              |
              v
         Page Table (Memory)
              |
              v
         Physical Address
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| TLB | 최근 사용된 가상→물리 매핑을 캐싱하는 소규모 연관 메모리 | 자주 찾는 전화번호를 메모한 포스트잇 |
| 페이지 테이블 워커(PTW) | TLB 미스 시 메모리의 페이지 테이블을 순회하여 매핑을 찾는 하드웨어 유닛 | 전화번호부를 한 장씩 넘기며 찾는 안내원 |
| 페이지 테이블 | 가상 페이지 번호와 물리 프레임 번호의 매핑 및 권한 비트를 저장하는 자료구조 | 전체 호실 배정표 |
| 접근 권한 비트 | 읽기/쓰기/실행 권한과 유효 비트를 포함하여 보호 위반을 검출하는 필드 | 출입증에 기재된 허가 구역 목록 |

> 요약: TLB·PTW·페이지 테이블·권한 비트가 주소 변환과 보호를 수행함

## Ⅲ. 절차
```text
1. CPU가 가상 주소 발행
         |
         v
2. TLB 검색 (히트/미스 판별)
         |
         v
3. 미스 시 PTW가 페이지 테이블 순회
         |
         v
4. 물리 주소 생성 및 권한 검사
```
- 1단계: CPU가 메모리 접근 명령을 실행하며 가상 주소를 MMU에 전달함
- 2단계: TLB에서 해당 가상 페이지 번호를 검색하고, 히트이면 물리 프레임 번호를 즉시 반환함
- 3단계: TLB 미스 시 PTW가 다단계 페이지 테이블을 순회하여 매핑을 찾고, 결과를 TLB에 적재함
- 4단계: 물리 주소를 생성하고 권한 비트를 검사하여, 위반 시 페이지 폴트 또는 보호 예외를 발생시킴

> 요약: TLB 우선 조회 후 미스 시 페이지 테이블 워크를 수행하여 주소를 변환함

## Ⅳ. 문제점
- TLB 미스 지연: 다단계 페이지 테이블 워크는 메모리 접근 4회(4단계 기준)를 요구 — 수십 클록의 지연 발생함
- 페이지 테이블 메모리 소비: 64비트 주소 공간에서 단일 레벨 페이지 테이블은 수 TB 크기 — 실용 불가함
- 컨텍스트 스위치 시 TLB 플러시: 프로세스 전환마다 TLB 무효화 — 전환 직후 연속적 TLB 미스로 성능 저하됨

> 요약: TLB 미스 지연·테이블 크기·플러시 비용이 MMU의 주요 병목임

## Ⅴ. 개선방안
1. 단기: 대형 페이지(2 MB, 1 GB) 사용으로 TLB 커버리지를 확대하여 미스율 감소
2. 중기: 다단계(4~5레벨) 페이지 테이블과 역페이지 테이블로 메모리 소비를 실제 매핑 분량에 비례하도록 축소
3. 장기: ASID(Address Space ID) 태깅을 TLB에 적용하여 컨텍스트 스위치 시 전체 플러시 없이 프로세스별 엔트리를 유지

> 요약: 대형 페이지·다단계 테이블·ASID 태깅으로 각 병목을 단계적으로 해소함

## Ⅵ. 전망
- 발전 방향: IOMMU를 통해 주소 변환 범위가 I/O 디바이스(GPU, NIC)까지 확장되는 추세임
- 기술사적 판단: 가상화 환경에서 2단계 주소 변환(EPT/NPT)이 표준화되어 하이퍼바이저 레벨 MMU 설계가 핵심 과제임
- 기술사 제언: TLB 계층 구조(L1/L2 TLB)와 페이지 크기 정책을 워크로드 특성에 맞게 튜닝할 필요
