# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: MMU는 CPU 내부에 위치한 **메모리 보호 및 주소 변환 하드웨어**로, CPU의 모든 메모리 접근마다 가상 주소→물리 주소 변환과 접근 권한 검사를 실행 경로 안에서 실시간으로 수행함.
- **왜 필요한가**: 멀티프로그래밍 환경에서 프로세스가 실수·악의로 타 프로세스나 커널의 메모리를 침범하면 시스템 전체가 붕괴됨. 소프트웨어 검사만으로는 매 접근마다 오버헤드가 크므로, 하드웨어가 실행 경로 안에서 즉시 차단해야 함.
- **핵심 직관**: 출입국 심사대와 같음 — 여권(가상 주소)이 유효한지, 입국 자격(권한)이 있는지를 매번 검사하고, 자격이 없으면 그 자리에서 차단(Trap)함.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 메모리 보호 (상위 키워드) | 프로세스별 접근 범위와 권한을 하드웨어가 강제하는 체계 | "출입 등급별 카드키 시스템" |
| TLB (Translation Lookaside Buffer) | 최근 주소 변환 결과를 캐싱하는 CAM 기반 고속 캐시(021 참조) | "최근 통과한 VIP 명단" |
| Page Table Walk | TLB Miss 시 DRAM의 페이지 테이블을 순회하여 PFN을 확보하는 과정 | "주소록을 찾아보는 과정" |
| Present/Valid Bit | 해당 페이지가 현재 물리 메모리에 적재되어 있는지 표시하는 비트 | "방에 사람이 있는지 표시등" |
| R/W/X 권한 비트 | 읽기·쓰기·실행 허용 여부를 표시하는 플래그 | "방 이용 규칙(열람/수정/출입)" |
| Page Fault | Present=0(미적재)이거나 매핑이 없을 때 발생하는 예외 — 항상 오류가 아님(Demand Paging은 정상) | "서고에 없어서 다시 가져옴" |
| GPF (General Protection Fault) | Present=1이나 권한 위반 시 발생하는 예외 — 대부분 실제 오류(버그/공격) | "방은 있으나 출입 자격 미달" |
| Demand Paging | 페이지를 미리 적재하지 않고 첫 접근 시 Page Fault를 통해 지연 할당하는 기법 | "필요한 짐만 그때그때 풀기" |
| Copy-on-Write (COW) | fork() 시 물리 복사 없이 읽기 전용 공유 후, 쓰기 시점에만 해당 페이지를 복사하는 기법 | "낙서할 때만 복사" |

## 깊이 이해
- **배경·문제의식**: 가상 메모리(022 참조)와 페이징이 동작하려면 모든 메모리 접근마다 ① 가상→물리 주소 변환과 ② 권한 검사가 필요함. 이를 소프트웨어로 처리하면 매 접근에 수십 사이클 오버헤드가 발생하므로, CPU 파이프라인에 통합된 하드웨어(MMU)가 수행해야 함.
- **작동 원리**:
  1. CPU가 가상 주소를 발행하면 MMU는 먼저 TLB를 조회함(Hit 시 1클럭 내 PFN 반환).
  2. TLB Miss 시 Page Table Walk Unit이 DRAM의 멀티레벨 페이지 테이블을 순회하여 PFN을 확보하고 TLB에 적재함.
  3. PFN 확보 후 권한 비트(R/W/X)와 특권 레벨(Ring 0~3)을 검사함.
  4. 검사 통과 시 물리 주소로 데이터 접근, 실패 시 예외(Page Fault 또는 GPF)를 발생시켜 OS 핸들러로 제어를 이전함.
- **Page Fault의 두 가지 상황**: ① Present=0이면 "아직 적재되지 않음"으로 Demand Paging의 정상 과정일 수 있음 → OS가 디스크에서 페이지를 적재 후 재실행. ② Present=1이나 권한 위반이면 GPF → 대부분 프로그램 버그나 보안 위반이므로 프로세스를 종료(SIGSEGV)함.
- **Demand Paging 수치 예시**: malloc(1MB) 호출 시 즉시 물리 프레임을 할당하지 않음. 4KB 페이지 기준 256페이지 중 실제 접근하는 10페이지에 대해서만 Page Fault가 발생하여 물리 메모리 40KB만 소비함.
- **Copy-on-Write 수치 예시**: fork() 시 부모의 100페이지(400KB)를 즉시 복사하지 않고 읽기 전용으로 공유함. 자식이 1페이지에만 쓰기를 시도하면 그 1페이지(4KB)만 복사되어, fork()+exec() 패턴에서 메모리 절감 효과가 극대화됨.
- **흔한 오해·주의점**: "모든 Page Fault는 오류다"는 오해임. Demand Paging·COW에서 Page Fault는 의도된 정상 동작임. 반면 GPF는 대부분 실제 위반 신호이므로 두 예외를 구분해야 함.

## 연결 개념
- **021 TLB**: MMU 내부에 위치하여 주소 변환을 캐싱하는 서브시스템.
- **022 가상 메모리·페이징**: MMU가 변환·보호하는 대상 구조.
- **024 세그멘테이션**: 세그먼트 기반 변환에서도 MMU가 Base+Offset 연산과 Limit 검증을 수행함.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: MMU는 가상 주소→물리 주소 변환과 접근 권한 검사를 CPU 실행 경로 안에서 매 접근마다 실시간으로 수행하는 하드웨어 유닛임.
> 2. **가치**: 프로세스별 주소 공간 격리와 권한 기반 보호를 하드웨어 수준에서 강제하여 소프트웨어 검사 오버헤드를 제거함.
> 3. **판단 포인트**: TLB Hit/Miss 처리 경로와 권한 검사 실패 시 예외 종류(Page Fault vs GPF)를 구분하여 Demand Paging·COW의 정상 동작과 실제 위반을 분별해야 함.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| MMU 역할 범위 이해 | 주소 변환 + 권한 검사 통합 수행 | MMU를 단순 "주소 변환기"로만 서술 |
| TLB·Page Walk 관계 이해 | TLB Hit 시 즉시 변환, Miss 시 Page Walk | TLB와 MMU를 별개 장치로 서술 |
| Page Fault 처리 흐름 이해 | Demand Paging(정상) vs GPF(위반) 구분 | Page Fault를 항상 오류로만 서술 |

> 요약: MMU의 역할을 변환+보호+예외 처리의 통합 흐름으로 제시하고, Page Fault의 정상/비정상 분기를 명확히 구분해야 함.

## Ⅰ. 개요 및 필요성

- 개요: CPU 내부에서 가상 주소→물리 주소 변환과 접근 권한 검사를 매 메모리 접근마다 실시간 수행하는 하드웨어 유닛임.
- 배경: 멀티프로그래밍 환경에서 프로세스 간 메모리 격리와 커널 보호를 소프트웨어만으로 처리하면 매 접근에 수십 사이클 오버헤드가 발생함.
- 필요성: CPU 실행 경로에 통합된 하드웨어 검사로 변환과 보호를 동시에 수행하여 성능 저하 없이 메모리 무결성을 보장해야 함.

---

## Ⅱ. 구조 및 구성요소

```text
CPU 가상 주소 -> MMU 진입
  -> TLB 조회 -> Hit: PFN 즉시 확정 / Miss: Page Table Walk -> TLB 갱신
  -> 권한 검사(R/W/X, Ring 0~3)
    -> 통과: 물리 주소 -> 캐시/메모리 접근
    -> 실패: Page Fault(미적재) 또는 GPF(권한 위반) -> OS 핸들러
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| TLB | 최근 변환 결과(VPN→PFN) 캐싱 | CAM 기반, 64~1024 엔트리, 1클럭 검색 |
| Page Walk Unit | TLB Miss 시 페이지 테이블 순회 | x86은 하드웨어 Walk, MIPS는 SW 트랩 |
| 권한 검사 로직 | R/W/X 비트·특권 레벨 검증 | 위반 시 즉시 예외 발생 |
| 폴트 인터페이스 | OS 핸들러로 제어 이전 + 원인 코드 전달 | Page Fault(정상/비정상)·GPF 구분 |

> 요약: MMU는 TLB→Page Walk→권한 검사→예외 처리를 하나의 파이프라인으로 통합하여 매 접근을 통제함.

---

## Ⅲ. 동작원리 및 흐름도

```text
CPU 메모리 접근 -> MMU: TLB 조회 -> Hit/Miss 판정
  Miss -> Page Table Walk -> PFN 확보 -> TLB 갱신
  -> 권한 검사 수행
    통과 -> 물리 주소로 데이터 접근
    실패(Present=0) -> Page Fault -> OS: Demand Paging/Swap In -> 재실행
    실패(권한 위반) -> GPF -> OS: SIGSEGV(프로세스 종료) 또는 COW 처리
```

- 1단계 [TLB 조회]: 가상 주소의 VPN을 TLB에 병렬 검색하여 Hit 시 1클럭 내 PFN을 반환함.
- 2단계 [Page Walk]: TLB Miss 시 멀티레벨 페이지 테이블(x86-64: 4단계)을 순회하여 PFN을 확보하고 TLB에 적재함.
- 3단계 [권한 검사]: Present Bit·R/W/X 비트·Ring Level을 검증하여 위반 시 예외를 발생시킴.
- 4단계 [예외 분기]: Page Fault는 Demand Paging(정상 적재)일 수 있고, 권한 위반은 COW(정상 복사) 또는 진짜 오류(SIGSEGV)로 분기됨.

> 요약: MMU는 변환→검사→예외 처리를 순차 수행하며, Page Fault의 정상/비정상을 OS 핸들러가 분기 처리함.

---

## Ⅳ. 특징
- 실시간 하드웨어 보호: 매 메모리 접근마다 변환과 권한 검사를 CPU 파이프라인 안에서 수행하여 소프트웨어 전용 검사 대비 오버헤드가 극히 작음
- TLB Miss 지연: 워킹셋이 TLB 커버 범위를 초과하면 Page Walk가 빈번하여 메모리 접근 지연이 증가함(Huge Page로 커버리지 확대)
- 관리 기법 독립성: 페이징·세그멘테이션 어떤 방식이든 MMU가 공통으로 변환·검사를 수행하는 하드웨어 실행 계층임

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | MMU 없는 구조 | MMU 기반 구조 | 선택 기준 |
|:---|:---|:---|:---|
| 주소 변환 | 물리 주소 직접 접근 | 가상→물리 변환 계층 존재 | 멀티태스킹 필요 여부 |
| 프로세스 격리 | 격리 불가(메모리 침범 위험) | Ring Level + 페이지 권한으로 격리 | 보안 요구 수준 |
| 오버헤드 | 변환 없음(지연 0) | TLB·Page Walk 오버헤드 존재 | 성능 vs 보호 트레이드오프 |
| 대표 적용 | 단일 태스크 임베디드(Cortex-M0) | 범용 서버·데스크톱·모바일 | 시스템 규모 |

> 요약: 멀티태스킹과 보안 격리가 필요한 범용 시스템은 MMU 기반 구조가 필수이며, 단일 태스크 초소형 임베디드만 예외적으로 MMU를 생략함.

**리스크·대응:**
- TLB Miss 급증: 워킹셋이 TLB 커버 범위 초과 → Huge Page(2MB/1GB) 적용 + 멀티레벨 TLB 계층화 (지표: perf stat dTLB-load-misses)
- 마이크로아키텍처 취약점(Meltdown/Spectre): 투기적 실행이 권한 검사를 우회 → KPTI(Kernel Page Table Isolation) + 마이크로코드 패치 적용 (지표: CVE 대응 현황)
- Page Fault 폭증(Thrashing): 워킹셋 대비 물리 메모리 부족 → 메모리 증설 또는 Working Set 기반 프레임 할당 조정 (지표: 초당 Page Fault 수)

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 범용 시스템 메모리 보호: 모든 다중 프로세스 시스템에서 MMU 기반 가상 메모리를 기본 적용하여 프로세스 격리와 커널 보호를 하드웨어 수준으로 보장함.
2. 대규모 워크로드 TLB 최적화: DB·HPC 서버에서 Huge Page + 다단계 TLB(L1/L2)를 적용하여 TLB Miss에 의한 Page Walk 지연을 최소화함.
3. Meltdown/Spectre 완화: KPTI·Retpoline 등 커널 레벨 완화 기법과 마이크로코드 패치를 병행 적용하여 투기적 실행의 권한 우회를 차단함.

**결론:**
- 기술사 판단: MMU는 페이징·세그멘테이션 등 관리 기법과 무관하게 변환+보호를 수행하는 하드웨어 계층으로, 범용 시스템의 메모리 무결성 근간임.
- 향후 방향: IOMMU·EPT/NPT와 결합하여 하이퍼바이저 환경의 게스트-호스트 이중 변환 구조로 발전하며, CXL 기반 원격 메모리까지 보호 범위가 확장되는 추세임.
