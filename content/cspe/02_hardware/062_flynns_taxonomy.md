## Ⅰ. 개요
- **정의**: 명령어 스트림과 데이터 스트림의 개수 조합으로 컴퓨터 아키텍처를 4가지로 분류하는 체계임
- **배경/필요성**: 병렬 처리 아키텍처가 다양해지면서 설계 방식을 체계적으로 비교·분류할 기준이 필요함
- **비유**: 요리사(명령어)와 재료(데이터)의 수 조합으로 주방 운영 방식을 분류하는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 병렬 아키텍처 분류 기준과 각 유형의 특성 이해 | SI/MI × SD/MD = 4분류, 각 유형의 대표 구조 | MISD의 실용 사례가 거의 없다는 점 명시 필요 |

> 요약: 명령어·데이터 스트림 수의 조합으로 아키텍처를 SISD/SIMD/MISD/MIMD 4가지로 분류하는 체계임

## Ⅱ. 구성요소
```text
                    +-- Single Data ---> SISD (단일 처리기)
  Single Instr. ----|
                    +-- Multiple Data -> SIMD (벡터/GPU)
  
                    +-- Single Data ---> MISD (파이프라인/중복 검증)
  Multiple Instr.---|
                    +-- Multiple Data -> MIMD (멀티코어/클러스터)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| SISD | 하나의 명령어가 하나의 데이터를 처리하는 순차 구조임 | 요리사 1명이 재료 1개를 조리 |
| SIMD | 하나의 명령어가 여러 데이터를 동시 처리하는 구조임 (063 참조) | 요리사 1명이 같은 동작으로 재료 여러 개를 동시 조리 |
| MISD | 여러 명령어가 하나의 데이터를 처리하는 구조로, 실용 사례가 매우 제한적임 | 여러 검수원이 같은 제품을 각자 방식으로 검사 |
| MIMD | 여러 명령어가 여러 데이터를 독립 처리하는 구조임 (063 참조) | 여러 요리사가 각자 다른 재료로 다른 요리를 동시 수행 |

> 요약: 명령어·데이터 스트림의 단수/복수 조합으로 4가지 아키텍처 유형을 정의함

## Ⅲ. 절차
```text
Architecture Analysis --> Stream Classification --> Category Mapping --> Design Selection
       |                        |                        |                     |
       v                        v                        v                     v
  Instruction/Data          SI or MI               SISD/SIMD/            Target Workload
  Stream 식별               SD or MD               MISD/MIMD 매핑        에 맞는 구조 선정
```
- 1단계: **Architecture Analysis** — 대상 시스템의 명령어 흐름과 데이터 흐름 구조를 분석함
- 2단계: **Stream Classification** — 명령어 스트림이 단수(SI)인지 복수(MI)인지, 데이터 스트림이 단수(SD)인지 복수(MD)인지 판별함
- 3단계: **Category Mapping** — 2×2 매트릭스에서 해당하는 분류(SISD/SIMD/MISD/MIMD)에 매핑함
- 4단계: **Design Selection** — 워크로드 특성(순차/데이터 병렬/태스크 병렬)에 맞는 분류의 아키텍처를 선정함

> 요약: 스트림 분석 → 단수/복수 판별 → 4분류 매핑 → 워크로드 기반 설계 선정의 4단계임

## Ⅳ. 문제점
- **MISD 실용성 부재**: 이론적으로는 존재하나 상용 시스템에서 적용 사례가 거의 없어 분류 체계의 완전성이 부족함
- **혼합 구조 미반영**: GPU처럼 SIMD와 MIMD 특성을 동시 보유하는 현대 프로세서를 단일 범주로 분류하기 어려움
- **메모리 구조 미포함**: 공유 메모리/분산 메모리 등 메모리 접근 방식을 분류 기준에 포함하지 않아 세부 구분이 부족함

> 요약: MISD 실용성, 혼합 구조 미반영, 메모리 구조 누락이 분류 체계의 한계임

## Ⅴ. 개선방안
1. 단기: MISD를 결함 허용(Fault Tolerance) 관점에서 재정의하여 분류 체계의 실용적 가치 확보
2. 중기: SPMD·MPMD 등 하위 분류를 추가하여 GPU·이기종 프로세서의 혼합 구조를 세분화
3. 장기: 메모리 접근 모델(UMA/NUMA/분산)을 분류 축에 추가하여 3차원 분류 체계로 확장

> 요약: MISD 재정의, 하위 분류 추가, 메모리 축 확장으로 현대 아키텍처 분류 정합성을 높임

## Ⅵ. 전망
- 발전 방향: 이기종 컴퓨팅(CPU+GPU+NPU) 확산으로 Flynn 분류의 확장·보완 논의가 지속됨
- 기술사적 판단: 병렬 아키텍처 설계의 기본 프레임워크로서 Flynn 분류는 교육·설계 초기 단계에서 여전히 유효함
- 기술사 제언: Flynn 분류를 기본 틀로 삼되, SPMD/MPMD·메모리 모델을 함께 기술하여 현대 시스템을 정확히 표현할 필요
