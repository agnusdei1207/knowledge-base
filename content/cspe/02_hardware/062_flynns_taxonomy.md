## 미리 알고가기

- Flynn 분류는 명령 스트림 수와 데이터 스트림 수를 기준으로 병렬 구조를 나누는 틀임
- SISD, SIMD, MISD, MIMD가 기본 네 범주임
- 현대 시스템은 한 장비 안에서도 계층별로 여러 범주가 섞일 수 있음

## Ⅰ. 개요

- **정의/개념**: Flynn 분류는 컴퓨터 구조를 동시에 처리하는 명령 흐름 수와 데이터 흐름 수에 따라 SISD, SIMD, MISD, MIMD로 구분하는 병렬 컴퓨터 분류 체계임
- **배경/필요성**: 멀티코어 CPU, GPU, 벡터 프로세서, 클러스터는 병렬성이 드러나는 방식이 달라 단순 성능 수치만으로 설명하기 어렵기 때문에, 병렬성의 방향을 짧게 정리할 기준이 필요함

## Ⅱ. 특징

- 데이터 병렬과 작업 병렬을 빠르게 구분해 구조 설명과 초기 설계 판단에 유용함
- 명령 흐름과 데이터 흐름이라는 단순한 축을 쓰므로 시험 답안과 개념 비교에 적합함
- 메모리 모델, 인터커넥트, 동기화 비용 같은 실제 병목은 직접 설명하지 못함
- 현대 GPU 클러스터처럼 혼합 구조는 노드 내부와 외부를 나눠 해석해야 정확해짐

## Ⅲ. 종류 및 비교

| 판단 기준 | SISD | SIMD | MISD | MIMD |
|:---|:---|:---|:---|:---|
| 명령 흐름 | 하나의 명령 흐름만 처리함 | 하나의 명령을 여러 데이터에 반복 적용함 | 여러 명령이 같은 데이터 흐름에 작용함 | 여러 명령이 여러 데이터를 독립적으로 처리함 |
| 대표 구조 | 단일 코어 CPU에 가까움 | 벡터 유닛, GPU lane 구조에 가깝음 | 특수 내결함 구조 같은 제한적 사례가 많음 | 멀티코어, 멀티소켓, 클러스터에 가깝음 |
| 잘 맞는 병렬성 | 병렬성이 거의 없음 | 규칙적인 데이터 병렬에 맞음 | 범용 활용은 드묾 | 태스크 병렬과 독립 실행에 맞음 |
| 해석 포인트 | 기본 순차 구조임 | 같은 연산을 대량 데이터에 뿌리는 구조임 | 시험에서는 특수 구조로 짧게 다루는 편이 적절함 | 서로 다른 작업을 나눠 처리하는 구조임 |

> 요약: Flynn 분류는 병렬성의 모양을 단순하게 보여 주지만, 실제 병목 해석은 추가 축이 필요함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 명령 스트림 | 제어 장치가 동시에 내보내는 명령 흐름 수이며 구조 분류의 첫 기준이 됨 |
| 데이터 스트림 | 명령이 적용되는 데이터 집합 수이며 데이터 병렬성 판단의 기준이 됨 |
| 처리 요소 | 실제 연산을 수행하는 코어, lane, 노드이며 분류 결과가 구현되는 대상임 |
| 분류 행렬 | 명령과 데이터의 단일·다중 조합을 표로 정리해 구조를 빠르게 식별하게 함 |

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 구조 관찰      | --> | 명령 흐름 판단 | --> | 데이터 흐름 판단 | --> | Flynn 범주 해석 |
+-------------+     +-------------+     +-------------+     +-------------+
```

> 요약: 구조를 관찰해 명령 흐름과 데이터 흐름 수를 세면 Flynn 분류로 정리할 수 있음.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 제어 구조 확인 | --> | 명령 수 판단   | --> | 데이터 수 판단 | --> | 범주 결정      |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **제어 구조 확인**: 하나의 제어가 전체를 이끄는지 독립 제어가 여러 개인지 봄
2. **명령 수 판단**: 동시에 진행되는 명령 흐름 수를 정함
3. **데이터 수 판단**: 한 명령이 다루는 데이터 집합 수를 정함
4. **범주 결정**: 네 가지 범주 중 가장 가까운 구조로 해석함

> 요약: 제어 구조, 명령 흐름 수, 데이터 흐름 수를 차례로 확인해 Flynn 범주를 결정함.

## Ⅵ. 실무 적용 및 유의점

1. GPU 클러스터·AI 서버처럼 계층별 병렬 구조가 섞인 시스템은 전체를 한 범주로만 적으면 병목을 놓치기 쉬우므로 노드 내부와 노드 간 구조를 나눠 적고 core utilization, inter-node traffic ratio로 확인함
2. MISD는 대표 사례가 드물어 억지 예시를 붙이면 설명이 흐려지므로 특수 내결함 구조로 짧게 다루고 example validity, taxonomy consistency로 확인함

## Ⅶ. 결론

Flynn 분류의 가치는 현대 시스템을 완전히 설명하는 데보다 병렬성이 데이터 병렬인지 작업 병렬인지 먼저 잡아 주는 출발점에 있음.

- 비교표는 각 범주의 명령 흐름, 대표 구조, 맞는 병렬성을 중심으로 작성함
- 실무 판단은 혼합 구조 해석과 MISD 제한성을 core utilization, taxonomy consistency로 확인하게 작성함
