## Ⅰ. 개요
- **정의**: 명령어 스트림과 데이터 스트림의 개수 조합으로 컴퓨터 아키텍처를 4가지로 분류하는 체계
- **배경/필요성**: 병렬 처리 구조가 다양해지면서, 명령어-데이터 흐름 기준으로 구조를 체계적으로 비교할 분류 틀이 필요함
- **비유**: 지휘자(명령어)와 연주자(데이터)의 수로 오케스트라 편성 방식을 분류하는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 병렬 아키텍처 분류 기준과 각 유형 특성 | SISD/SIMD/MISD/MIMD 4분류와 대표 구조 | MISD의 실용 사례 부재 및 SIMT(050 참조)와의 구분 |

> 요약: 명령어·데이터 스트림 수를 기준으로 컴퓨터 구조를 4가지로 분류하는 체계임

## Ⅱ. 구성요소
```text
                   +-- 단일 데이터 ---> SISD (순차 처리)
  단일 명령어 -----+
                   +-- 복수 데이터 ---> SIMD (벡터/GPU)

                   +-- 단일 데이터 ---> MISD (내결함 중복)
  복수 명령어 -----+
                   +-- 복수 데이터 ---> MIMD (멀티코어/클러스터)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| SISD | 하나의 명령어가 하나의 데이터를 처리하는 순차 구조 | 선생님 1명이 학생 1명을 개인 지도하는 것 |
| SIMD | 하나의 명령어가 복수 데이터를 동시에 처리하는 구조 | 체조 교관 1명이 동일 동작을 학생 전원에게 지시하는 것 |
| MISD | 복수 명령어가 동일 데이터를 처리하는 구조(실용 사례 극소) | 여러 의사가 같은 환자를 동시에 진단하는 것 |
| MIMD | 복수 명령어가 복수 데이터를 독립적으로 처리하는 구조 | 여러 요리사가 각자 다른 메뉴를 조리하는 것 |

> 요약: 명령어-데이터 스트림 조합으로 SISD·SIMD·MISD·MIMD 4유형을 구분함

## Ⅲ. 절차
```text
분류 기준 설정 --> 명령어 스트림 판별 --> 데이터 스트림 판별 --> 유형 결정
```
- 1단계: **분류 기준 설정** — 명령어 스트림 수(S/M)와 데이터 스트림 수(S/M) 두 축을 정의함
- 2단계: **명령어 스트림 판별** — 프로세서가 동시에 실행하는 명령어 흐름이 1개인지 복수인지 판별함
- 3단계: **데이터 스트림 판별** — 하나의 명령어가 처리하는 데이터 단위가 1개인지 복수인지 판별함
- 4단계: **유형 결정** — 두 축의 조합으로 SISD·SIMD·MISD·MIMD 중 해당 유형을 결정함

> 요약: 명령어·데이터 스트림의 단일/복수 여부를 판별하여 4유형 중 하나로 분류함

## Ⅳ. 문제점
- **MISD 실용 부재**: 동일 데이터에 복수 명령어를 적용하는 구조가 범용 하드웨어에 구현되지 않음 — 분류 체계의 완전성이 저하됨
- **혼합 구조 미반영**: GPU의 SIMT(050 참조)처럼 SIMD와 MIMD를 혼합한 구조가 4분류에 정확히 대응되지 않음
- **메모리 구조 미포함**: 공유 메모리/분산 메모리 차이를 반영하지 않아 MIMD 내부 세분류가 불가함

> 요약: MISD 실용 부재, 혼합 구조 미반영, 메모리 구조 미포함이 한계임

## Ⅴ. 개선방안
1. 단기: MISD 위치에 내결함 중복 실행·파이프라인 구조를 매핑하여 분류 체계의 공백을 보완함
2. 중기: SIMT·데이터플로 등 혼합 구조를 하위 분류로 추가하여 확장된 분류 체계를 적용함
3. 장기: 메모리 접근 모델(공유/분산/하이브리드)을 제3축으로 추가하여 MIMD 세분류를 지원함

> 요약: MISD 보완 → 혼합 구조 확장 → 메모리 축 추가 순서로 분류 체계를 정교화함

## Ⅵ. 전망
- 발전 방향: 이기종 컴퓨팅(CPU+GPU+NPU) 확산으로 단일 시스템 내 복수 Flynn 유형이 공존하는 추세임
- 기술사적 판단: Flynn 분류는 병렬 구조의 기본 프레임으로서 여전히 유효하나, 세부 확장이 지속 필요함
- 기술사 제언: 시스템 설계 시 Flynn 분류를 출발점으로 하되, 워크로드 특성에 따른 세부 구조 선택이 필요
