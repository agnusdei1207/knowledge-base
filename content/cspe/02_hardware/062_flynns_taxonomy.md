## 미리 알고가기

- Flynn 분류는 명령 스트림 수와 데이터 스트림 수를 기준으로 병렬 구조를 나눔
- SISD, SIMD, MISD, MIMD 네 범주가 기본 틀임
- 현대 시스템은 계층별로 여러 범주가 혼합될 수 있음

## Ⅰ. 개요

- **정의/개념**: Flynn 분류는 컴퓨터 구조가 동시에 처리하는 명령 흐름과 데이터 흐름의 수를 기준으로 병렬 아키텍처를 SISD와 SIMD와 MISD와 MIMD로 나누는 분류 체계임
- **배경/필요성**: 병렬 컴퓨터는 CPU, GPU, 벡터 프로세서, 클러스터처럼 구조가 다양해 단순 성능 수치만으로 설명하기 어려우므로, 공통 기준 축이 필요함

## Ⅱ. 특징

- 병렬성을 데이터 병렬과 작업 병렬 관점으로 빠르게 구분할 수 있음
- 하드웨어 구조를 단순한 축으로 요약해 시험 답안과 초기 설계 설명에 유리함
- 메모리 구조와 인터커넥트와 소프트웨어 오버헤드는 직접 반영하지 못함
- 현대 하이브리드 시스템은 계층별 혼합 해석이 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | SISD | SIMD | MISD | MIMD |
|:---|:---|:---|:---|:---|
| 명령 스트림 | 1 | 1 | 다수 | 다수 |
| 데이터 스트림 | 1 | 다수 | 1 | 다수 |
| 대표 예 | 단일 CPU | 벡터, GPU 내부 | 특수 내결함 구조 | 멀티코어, 클러스터 |
| 적합 병렬성 | 없음 | 데이터 병렬 | 제한적 특수용도 | 작업 병렬 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Instruction Stream | 제어 장치가 발행하는 명령 흐름 수로 시스템 제어 구조를 구분하는 기준임 |
| Data Stream | 명령이 적용되는 데이터 집합 수로 데이터 병렬성을 해석하는 기준임 |
| Processing Element | 실제 연산을 수행하는 코어 또는 프로세서로 분류 결과의 구현 대상임 |
| Classification Matrix | 명령과 데이터의 단일, 다중 조합으로 병렬 구조를 빠르게 식별하게 함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 구조 관찰      | --> | 명령 흐름 계수 | --> | 데이터 흐름 계수 | --> | 범주 분류/해석 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **구조 관찰**: 제어부와 처리 요소 구성을 확인함
2. **명령 흐름 계수**: 동시에 독립 실행되는 명령 수를 판단함
3. **데이터 흐름 계수**: 명령이 적용되는 데이터 집합 수를 판단함
4. **범주 분류 및 해석**: SISD, SIMD, MISD, MIMD 중 적합한 구조로 정리함

## Ⅵ. 문제점 및 해결 방안

1. 문제: GPU 클러스터처럼 계층마다 병렬 구조가 다른 시스템은 단일 분류만으로 설명하면 핵심 병목을 놓칠 수 있음
   - 해결방안: 노드 내부와 노드 외부를 분리해 계층별 분류를 병기하고 architecture clarity와 bottleneck explainability로 검증함
2. 문제: MISD는 대표 사례가 적어 억지 예시를 들면 구조 설명이 부정확해질 수 있음
   - 해결방안: MISD는 특수 내결함이나 파이프라인형 사례로 제한하고 SIMD와 MIMD 중심으로 비교하며 example consistency로 검증함
3. 문제: 명령, 데이터 흐름만으로는 메모리와 통신 병목을 설명하기 어려워 실무 적용력이 떨어질 수 있음
   - 해결방안: 메모리 모델과 인터커넥트 토폴로지를 보조 축으로 함께 제시하고 performance diagnosis coverage로 검증함

## Ⅶ. 적용 사례

- GPU 내부 구조 설명에서는 SIMD 계열 특성을 강조하고, lane utilization과 branch efficiency로 결과를 확인함
- 멀티코어 서버 분석에서는 MIMD 구조를 기준으로 설명하고, core utilization과 synchronization overhead로 결과를 확인함
- AI 클러스터 강의와 설계 문서에서는 계층별 Flynn 분류를 병행하고, architecture clarity와 workload mapping accuracy로 결과를 확인함

## Ⅷ. 결론

Flynn 분류는 현대 병렬 시스템을 완전히 설명하는 도구는 아니지만 병렬성의 방향을 짧고 명확하게 잡아주는 첫 분류 축으로 여전히 유효함.
