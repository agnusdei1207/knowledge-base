# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 플린의 분류(Flynn's Taxonomy)는 **병렬 컴퓨터 아키텍처**를 명령어 스트림(Instruction Stream)과 데이터 스트림(Data Stream)의 수에 따라 4가지로 나눈 기준이다.
- **왜 필요한가**: CPU가 수많은 작업을 처리할 때, '지시(명령어)'를 여러 개 내릴 것인지, '작업 대상(데이터)'을 여러 개 둘 것인지에 따라 설계가 완전히 달라지므로 이를 체계적으로 분류할 기준이 필요했다.
- **핵심 직관**: 공장에서 '작업 지시서(명령어)'와 '재료(데이터)'의 개수 조합으로 생산 라인을 4가지로 구분한다고 보면 된다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| Instruction Stream (명령어 스트림) | 프로세서가 메모리에서 순서대로 가져와 실행하는 기계어 명령의 흐름 | "공장장의 작업 지시서" |
| Data Stream (데이터 스트림) | 명령어가 조작하기 위해 메모리에서 가져오거나 쓰는 데이터의 흐름 | "가공해야 할 부품 재료" |
| Single (S) | 단일 스트림 (1개의 흐름) | "지시서 1장", "부품 1개" |
| Multiple (M) | 다중 스트림 (여러 개의 흐름) | "각기 다른 지시서 여러 장", "대량의 부품 묶음" |

## 깊이 이해
- **배경·문제의식**: 1966년 마이클 플린(Michael Flynn)이 제안한 것으로, 당시 등장하기 시작한 다양한 컴퓨터 구조(특히 병렬 처리 시스템)를 직관적이고 보편적인 기준으로 분류하기 위해 고안되었다.
- **작동 원리**: 명령어(I)와 데이터(D)의 단일(S)/다중(M) 조합으로 2×2=4개의 카테고리를 만든다.
  1. **SISD (Single I, Single D)**: 전통적 폰 노이만 구조 (구형 단일 코어 PC)
  2. **SIMD (Single I, Multiple D)**: 1개의 명령으로 여러 데이터를 한 번에 처리 (GPU, 벡터 프로세서)
  3. **MISD (Multiple I, Single D)**: 여러 명령이 동일한 데이터 1개를 처리 (우주선 결함 허용 시스템, 파이프라인 배열) - 흔치 않음
  4. **MIMD (Multiple I, Multiple D)**: 여러 프로세서가 각각 다른 명령과 데이터를 처리 (현대 멀티코어, 클러스터, 슈퍼컴퓨터)
- **비유**:
  - SISD: 요리사 1명이 1개의 당근(데이터)을 썰기(명령어)
  - SIMD: 요리사 1명이 "모두 썰어!"(단일 명령)라고 외치면, 기계가 10개의 당근(다중 데이터)을 동시에 썰기
  - MISD: 당근 1개(단일 데이터)를 컨베이어에 올리면, 세척기-껍질까기-칼질(다중 명령어)이 순차적으로 처리
  - MIMD: 요리사 4명이 각자의 레시피(다중 명령)로 서로 다른 재료(다중 데이터)를 각자 요리
- **흔한 오해·주의점**: SIMD와 MIMD가 현재 병렬 컴퓨팅의 양대 산맥이다. MISD는 실용적인 범용 시스템으로는 거의 쓰이지 않으며 결함 내성(Fault Tolerance) 시스템이나 일부 파이프라인 모델로만 이론적으로 언급된다.

## 연결 개념
- SIMD·MIMD 프로세서 — 플린 분류의 핵심 실무 적용 아키텍처
- 멀티코어 프로세서 — MIMD 아키텍처의 대표적 예시
- 암달의 법칙 (Amdahl's Law) — 병렬 컴퓨터(MIMD/SIMD) 설계 시 성능 향상의 이론적 한계

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 플린의 분류(Flynn's Taxonomy)는 컴퓨터 아키텍처를 명령어 스트림과 데이터 스트림의 단일(Single)/다중(Multiple) 여부에 따라 SISD, SIMD, MISD, MIMD 4가지로 구분하는 분류법이다.
> 2. **가치**: 복잡한 병렬 프로세서 구조를 직관적으로 추상화하여, 워크로드(AI 연산, 대규모 웹 서비스 등) 특성에 맞는 최적의 하드웨어를 선택하는 기준을 제공한다.
> 3. **판단 포인트**: 현대 시스템은 멀티코어(MIMD) 안에 벡터 확장 명령어(SIMD)를 품는 등 하이브리드 형태로 진화하므로, 단일 분류에 얽매이지 않고 SPMD 등 확장된 관점으로 성능을 설계해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 병렬 컴퓨팅 아키텍처 분류 체계 이해 | 4가지 분류(SISD, SIMD, MISD, MIMD) 기준 및 구조 | 분류명만 나열하고 실제 시스템 예시(GPU, 멀티코어) 누락 |
| 분류별 특성과 적용 워크로드 매핑 역량 | SIMD(배열/AI MAC 연산) vs MIMD(독립 스레드/웹 서버) | MISD를 범용 시스템으로 잘못 설명하는 오류 |
| 현대 병렬 아키텍처의 복합적 특성 인지 | MIMD 노드 내에 SIMD가 내장된 계층적 하이브리드 구조 | 단순히 4가지 모델이 독립적으로 존재한다고 단정 |

> 요약: 플린의 분류는 고전적 이론이지만, 현대의 CPU(MIMD)와 GPU(SIMD) 아키텍처를 비교하고 선택하는 실무적 프레임워크로 논리를 전개해야 한다.

## Ⅰ. 개요 및 필요성

- 개요: 병렬 컴퓨터 시스템을 명령어 스트림(Instruction)과 데이터 스트림(Data)의 처리 수량(Single/Multiple)을 기준으로 4가지로 나눈 아키텍처 분류 모델
- 배경: 단일 코어의 클럭 주파수 한계(전력 벽) 도달로 병렬 처리 시스템이 대두되면서, 아키텍처 간 체계적 비교 기준 요구
- 필요성: 시스템 설계 시 과학 연산, 그래픽 렌더링, 대규모 트랜잭션 등 애플리케이션 특성에 맞는 최적의 병렬 하드웨어 구조(GPU vs CPU 클러스터) 판단 기준 제공

---

## Ⅱ. 구조 및 구성요소

```text
[Flynn's Taxonomy 2x2 Matrix]
                    Data Stream
                 Single       Multiple
Instruction S |  SISD     |   SIMD    |
Stream      M |  MISD     |   MIMD    |
```

| 분류명 (구조) | 명령어 / 데이터 | 처리 방식 | 대표적 적용 사례 |
|:---|:---|:---|:---|
| SISD | Single / Single | 단일 명령어가 단일 데이터를 순차 처리 | 구형 단일 코어 폰 노이만 PC |
| SIMD | Single / Multiple | 단일 명령어가 배열/벡터의 다수 데이터를 동시 처리 | GPU, 벡터 프로세서, AVX 명령어 |
| MISD | Multiple / Single | 다수 명령어가 동일 데이터에 대해 서로 다른 연산 수행 | 결함 허용 시스템, 수축기 배열(Systolic) |
| MIMD | Multiple / Multiple | 다수 프로세서가 각자의 명령과 데이터를 비동기적 독립 처리 | 멀티코어 CPU, SMP, 클러스터 서버 |

> 요약: 스트림의 곱 조합을 통해 아키텍처를 분류하며, 현대 IT 인프라는 SIMD(그래픽·AI)와 MIMD(분산·서버) 아키텍처가 주축을 이룬다.

---

## Ⅲ. 동작원리 및 흐름도

```text
SISD: CU -> [Inst] -> PU -> [Data] -> Result
SIMD: CU -> [Inst 브로드캐스트] -> 다수 PU -> 각각 [Data 1~N] -> N개 Result
MISD: 다수 CU -> 각 [Inst] -> 각 PU -> [동일 Data 흐름] -> 파이프라인 Result
MIMD: 다수 CU -> 각 [Inst 1~N] -> 각 PU -> 각각 [Data 1~N] -> 독립적 N개 Result
```

- SISD 단계: 1개의 제어장치(CU)가 1개의 처리장치(PU)를 통제하여 순차적으로 1:1 연산 수행
- SIMD 단계: 1개의 CU가 "벡터 더하기" 등 단일 명령을 내리면, 다수의 PU가 배열 데이터 각각에 동시 연산 적용 (데이터 수준 병렬성, DLP)
- MISD 단계: 다수 CU와 PU가 하나의 데이터 스트림을 넘겨받으며 순차적으로 파이프라인 연산이나 다중화 검증 수행
- MIMD 단계: 각각의 PU가 독립된 CU를 갖고 각자의 스레드나 프로세스를 독립 메모리(또는 공유 메모리) 공간에서 비동기적 수행 (스레드 수준 병렬성, TLP)

> 요약: 제어장치(CU)의 단일성 여부가 동기식 브로드캐스트(SIMD)와 비동기식 독립 수행(MIMD)을 결정짓는 핵심 동작 원리다.

---

## Ⅳ. 특징

- [설계 복잡도 차이]: SIMD는 CU가 하나라 하드웨어 면적이 작고 연산기(ALU) 집적에 유리한 반면, MIMD는 코어마다 독립된 캐시와 제어 로직이 필요해 복잡하다.
- [동기화 비용]: SIMD는 태생적으로 모든 데이터 경로가 동기화(Lock-step)되지만, MIMD는 스레드 간 데이터 동기화(캐시 일관성, 락 등) 오버헤드가 발생한다.
- [유연성 트레이드오프]: SIMD는 분기문(If-Else)이 많으면 성능이 급감하나, MIMD는 각 코어가 다른 코드를 실행하므로 분기가 많은 복잡한 제어 흐름 처리에 강하다.

> 요약: SIMD는 단순 반복 연산의 대량 처리(처리량 극대화)에 유리하고, MIMD는 복잡하고 독립적인 태스크의 범용 처리(유연성)에 유리하다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | SIMD 중심 아키텍처 | MIMD 중심 아키텍처 | 선택 기준 |
|:---|:---|:---|:---|
| 병렬성 기준 | 데이터 수준 병렬성 (DLP) | 스레드 수준 병렬성 (TLP) | 코드의 독립 스레드 분할 가능성 |
| 적용 워크로드 | 행렬 곱셈, 딥러닝 MAC, 렌더링 | 웹 서버 요청 처리, RDBMS 트랜잭션 | 연산의 규칙성 및 분기 발생 빈도 |
| 성능 제약 요인 | 제어 분기(Divergence), 메모리 대역폭 | 캐시 일관성 유지 통신, 락 경합 | 암달의 법칙에 따른 순차 실행 비율 |
| 에너지 효율 | ALU 밀도가 높아 연산당 에너지 소모 낮음 | 제어 유닛 전력 소모가 큼 | 전력 예산 제한 시 SIMD 선호 |

> 요약: 제어 흐름이 동일하고 데이터만 방대한 배열 구조는 SIMD를, 사용자의 독립적인 요청이 쏟아지는 웹 백엔드는 MIMD를 선택한다.

**리스크·대응:**
- MIMD의 메모리 병목 및 동기화 지연: 코어 수 증가에 따른 버스 병목 현상 → NUMA 아키텍처 및 디렉토리 기반 캐시 일관성 프로토콜 적용 (지표: 버스 경합률 15% 이하)
- SIMD의 분기 성능 저하 (Divergence): 조건문 병렬 처리 시 일부 유닛 대기 현상 → 조건 분기 회피 스케줄링 및 프레디케이션(Predication) 기법 적용 (지표: 워프 실행 효율 80% 이상)

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. AI 클러스터 하이브리드 설계: 노드 간은 MIMD 기반 MPI 분산 처리로 스케일아웃하고, 단일 노드 내에서는 SIMD 기반 GPU로 텐서 연산을 가속하는 계층적 병렬 처리 구현
2. 범용 CPU 성능 극대화 (AVX/NEON): x86 또는 ARM 기반 MIMD 멀티코어 내부에 SIMD 확장 명령어(AVX-512 등) 유닛을 통합하여 영상 인코딩 등 특정 연산 처리량 4배 향상
3. SPMD (Single Program Multiple Data) 모델 채택: 논리적으로는 하나의 프로그램을 띄우되 물리적으로는 여러 MIMD 노드에서 데이터만 다르게 처리하는 MPI 프로그래밍 기법으로 분산 컴퓨팅 복잡도 통제

**결론 (2줄):**
- 기술사 판단: 클라우드와 AI 시대의 워크로드는 극단적으로 양극화되어 있으므로, 통신 기반의 MIMD와 연산 밀도 기반의 SIMD를 혼합한 이기종(Heterogeneous) 아키텍처 설계가 필수적이다.
- 향후 방향: 하드웨어의 발전으로 순수 SIMD/MIMD의 경계가 무너지고 있으며, NPU와 PIM 같은 도메인 특화 아키텍처(DSA)로 병렬성 분류가 다변화될 것이다.
