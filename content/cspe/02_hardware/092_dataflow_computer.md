# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 데이터 흐름 컴퓨터(Dataflow Computer)는 명령어의 실행 순서(PC)가 아니라, **필요한 데이터가 준비되는 즉시 명령어를 실행**하는 병렬 처리 아키텍처이다.
- **왜 필요한가**: 폰 노이만 구조는 프로그램 카운터(PC)에 의해 순차적으로 명령을 처리하므로 병렬성에 한계가 있다. 이를 극복하고 극한의 명령어 수준 병렬성(ILP)을 달성하기 위해 고안되었다.
- **핵심 직관**: 공장 조립 라인에서 '작업 지시서 순서(폰 노이만)'대로 일하는 게 아니라, '나사 2개와 철판이 내 앞에 도착하면 즉시(데이터 흐름)' 조립을 시작하는 방식이다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 데이터 토큰 (Data Token) | 연산에 필요한 피연산자 데이터를 담은 패킷 | 부품이 담긴 바구니 |
| 노드 (Node) | 연산을 수행하는 처리 요소 | 조립 라인의 작업자 |
| 활성화 (Firing) | 노드에 모든 입력 토큰이 도착하여 연산이 실행되는 현상 | 부품이 다 모여 조립을 시작하는 순간 |
| 프로그램 카운터 (PC) 부재 | 순차 실행을 지시하는 PC가 없음 | 중앙 통제자 없이 자율 작업 |

## 깊이 이해
- **배경·문제의식**: 폰 노이만 아키텍처는 공유 메모리와 프로그램 카운터(PC)에 의존하여, 멀티 프로세서 환경에서 메모리 접근 병목과 데이터 의존성 문제로 성능 확장에 한계를 보였다.
- **작동 원리**: 프로그램을 데이터 종속성 그래프(Dataflow Graph)로 표현한다. 각 명령어(노드)는 이전 명령어의 결과(토큰)를 받는다. 모든 입력 토큰이 도착하면 노드는 활성화(Firing)되어 연산을 수행하고, 결과를 다음 노드로 전달한다.
- **비유**: Excel 스프레드시트와 같다. A1, B1 셀의 값이 변경되면(토큰 도착), 이 두 셀을 참조하는 C1 셀 수식이 중앙의 지시 없이 자동으로 재계산된다.
- **구체 예시**: `C = A + B`, `F = C * D` 연산 시, `A`와 `B` 토큰이 `+` 노드에 도착하면 즉시 실행되어 `C` 토큰이 생성되고, 이것이 다시 `D` 토큰과 만나 `*` 노드를 실행한다.
- **흔한 오해·주의점**: 모든 범용 연산에 유리할 것 같지만, 데이터 종속성이 강한 순차적 프로그램에서는 토큰 통신 오버헤드가 더 커서 오히려 성능이 저하된다.

## 연결 개념
- 폰 노이만 아키텍처 — 데이터 흐름 컴퓨터가 대체하려 한 대조적 구조
- 비순차 실행(Out-of-Order Execution) — 현대 CPU가 데이터 흐름 원리를 차용해 성능을 높이는 기법
- 텐서 처리 장치(TPU) — 데이터 흐름 아키텍처를 행렬 연산 가속에 응용한 현대적 사례

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 데이터 흐름 컴퓨터는 프로그램 카운터(PC) 없이 데이터의 가용성(토큰 도착)에 의해 명령어 실행 순서가 결정되는 비동기적 병렬 아키텍처다.
> 2. **가치**: 폰 노이만 병목을 근본적으로 제거하고 명령어 수준의 극한 병렬성을 하드웨어적으로 달성한다.
> 3. **판단 포인트**: 범용 CPU로는 통신 오버헤드 탓에 실패했으나, 현대의 비순차 실행(OoO) 기술과 TPU 같은 특수 목적 AI 가속기 설계의 핵심 원리로 부활하였다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 폰 노이만 아키텍처 대안 이해 | 데이터 토큰, 노드 활성화(Firing), 제어 흐름(Control Flow)과의 구조적 차이 | 기존 폰 노이만 구조와 동일한 순차 처리로 서술 |
| 한계점 및 현대적 적용 사례 파악 | 통신 오버헤드, 종속성 그래프 복잡도, 현대 CPU의 비순차 실행(OoO) 적용 | 맹목적으로 성능이 무조건 좋다고 단정 |

> 요약: PC 제어 방식과의 근본적 차이(토큰 구동)를 설명하고, 범용성 한계로 인해 현대에는 OoO 및 가속기로 흡수되었음을 논증한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 데이터 흐름 컴퓨터(Dataflow Computer)는 데이터의 가용성(토큰)에 의해 명령어의 실행이 촉발(Trigger)되는 비 폰 노이만 형 병렬 아키텍처이다.
- 배경: 폰 노이만 구조의 명령어 순차 실행 및 메모리 접근 집중으로 인한 병목(Bottleneck) 현상 극복 요구
- 필요성: 공유 메모리와 프로그램 카운터 의존성을 제거하여 병렬 처리 시 발생하는 동기화 지연을 원천 차단하기 위해 필요

---

## Ⅱ. 구조 및 구성요소

```text
Data Token -> Matching Unit -> Instruction Fetch -> Processing Unit
                                                        |
                                                        +-> 결과 Token 반환
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 데이터 토큰 (Data Token) | 데이터 값, 목적지 주소, 포트 정보 포함 | 메모리 주소가 아닌 값 자체를 전달 |
| 매칭 유닛 (Matching Unit) | 하나의 노드에 필요한 토큰이 모두 모였는지 확인 | 동적 데이터 흐름 구조에서 필수 (태그 매칭) |
| 노드 (Node) | 데이터 플로우 그래프 상의 개별 연산 유닛 | 조건 충족 시 활성화(Firing) 발생 |

> 요약: 데이터와 목적지 정보가 담긴 토큰이 매칭 유닛에 모이면 즉각적으로 연산 유닛(노드)이 실행된다.

---

## Ⅲ. 동작원리 및 흐름도

```text
토큰 도착 -> 입력 대기/매칭 -> 노드 활성화(Firing) -> 연산 수행 -> 출력 분배
```

- 1단계 [토큰 도착/매칭]: 이전 연산의 결과인 데이터 토큰이 목표 노드의 입력 포트로 도달
- 2단계 [노드 활성화]: 노드가 요구하는 모든 피연산자 토큰이 매칭되면 활성화(Firing)
- 3단계 [연산 수행]: 프로그램 카운터 개입 없이, 활성화된 노드가 자신의 명령을 즉시 병렬 처리
- 4단계 [결과 분배]: 연산 결과를 새로운 토큰으로 포장하여 종속된 다음 노드들로 브로드캐스트

> 요약: 제어 장치(PC)의 지시 없이, 데이터(토큰)의 흐름 자체가 연산 순서와 동기화를 스스로 결정한다.

---

## Ⅳ. 특징
- 병렬성 극대화: 데이터 의존성이 없는 명령어는 하드웨어 자원이 허용하는 한 100% 병렬 실행됨
- 동기화 오버헤드 제거: 공유 메모리를 통한 락(Lock)이나 세마포어가 필요 없어 교착 상태를 회피함
- 통신 병목: 토큰 전송과 매칭 유닛의 오버헤드가 커서, 종속성이 강한 직렬 연산에서는 오히려 느려짐

> 요약: 극단적인 명령어 수준 병렬성을 달성하나, 토큰 라우팅과 매칭 오버헤드로 인해 범용 아키텍처로는 실패하였다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 폰 노이만 (제어 흐름) | 데이터 흐름 컴퓨터 | 선택 기준 |
|:---|:---|:---|:---|
| 실행 촉발 | 프로그램 카운터(PC) 순차 지시 | 데이터 토큰 가용성 (비동기) | 연산의 종속성 및 병렬화 가능성 |
| 메모리 모델 | 공유 메모리 중심 상태 유지 | 상태가 없는(Stateless) 토큰 전달 | 상태 공유 여부 |
| 한계점 | 병렬 처리 시 병목 및 동기화 지연 | 노드 간 토큰 통신/매칭 오버헤드 | 시스템 버스 대역폭 한계 |

> 요약: 제어 흐름은 구현이 단순하나 병목이 있고, 데이터 흐름은 병렬성은 높으나 네트워크 오버헤드가 크다.

**데이터 흐름 구조 리스크·대응:**
- [매칭 유닛 병목]: 많은 토큰이 대기할 때 매칭 메모리 고갈 → [대응 방안] 정적 데이터 흐름(Static Dataflow) 적용 (지표: 매칭 실패율)
- [범용성 부족]: 조건 분기 및 직렬화 코드에서 효율 급감 → [대응 방안] 폰 노이만 구조와 혼합한 하이브리드(OoO) 적용 (지표: IPC 향상도)

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. CPU 설계: 최신 범용 프로세서의 비순차 실행(Out-of-Order Execution) 엔진 내부에 데이터 흐름(Data-Driven) 스케줄러를 적용하여 IPC 극대화
2. AI 가속기: 구글 TPU의 시스톨릭 어레이(Systolic Array) 설계 시 데이터가 파이프라인처럼 흘러가며 곱셈-누산을 수행하는 특성 반영
3. 소프트웨어 모델: 빅데이터 파이프라인(Apache Spark, TensorFlow)에서 방향성 비순환 그래프(DAG) 기반의 데이터 플로우 프로그래밍 적용

**결론 (2줄):**
- 기술사 판단: 순수 데이터 흐름 컴퓨터는 오버헤드로 소멸했으나, 그 핵심 사상(토큰 구동 병렬화)은 현대 CPU의 비순차 실행과 AI 가속기의 근간으로 부활하였다.
- 향후 방향: 무어의 법칙 한계에 따라, CGRAs(Coarse-Grained Reconfigurable Architectures)와 같은 공간 컴퓨팅 기반의 가속기가 AI 워크로드의 대안이 될 것이다.
