## 미리 알고가기

- 제어 흐름 컴퓨터는 프로그램 카운터 순서로 명령을 실행함
- 데이터 흐름 컴퓨터는 입력 데이터가 준비된 연산부터 실행함
- 토큰은 값과 준비 상태를 함께 담아 노드 실행 가능 여부를 나타냄

## Ⅰ. 개요

- **정의/개념**: 데이터 흐름 컴퓨터는 프로그램을 연산 노드와 데이터 의존 간선의 그래프로 표현하고 입력 토큰이 준비된 노드부터 병렬 실행하는 비순차 실행 구조임
- **배경/필요성**: 제어 흐름 기반 구조는 명령 순서가 병렬성을 숨길 수 있으므로, 그래프형 연산과 스트림형 워크로드에서는 데이터 준비 상태를 직접 실행 기준으로 삼는 구조가 필요함

## Ⅱ. 특징

- 프로그램 카운터보다 데이터 의존성이 실행 순서를 결정함
- 독립 노드를 자연스럽게 병렬 실행해 높은 자원 활용률을 노릴 수 있음
- 토큰 관리와 스케줄링 비용이 커지면 병렬성 이득이 상쇄될 수 있음
- 그래프 처리와 AI 가속과 스트림 연산처럼 의존 관계가 명확한 워크로드에 유리함

## Ⅲ. 종류 및 비교

| 판단 기준 | 제어 흐름 컴퓨터 | 데이터 흐름 컴퓨터 |
|:---|:---|:---|
| 실행 기준 | 프로그램 순서와 분기 명령 | 입력 데이터 준비 상태 |
| 병렬성 추출 | 컴파일러와 OoO 하드웨어에 의존 | 그래프상 독립 노드가 직접 병렬화됨 |
| 상태 관리 | 레지스터와 메모리 순서가 핵심 | 토큰과 노드 활성 상태가 핵심 |
| 적합 업무 | 범용 순차 프로그램 | 스트림, 그래프, 가속기형 연산 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Dataflow Graph | 연산 노드와 데이터 의존 간선으로 프로그램 구조를 표현해 병렬 가능 범위를 드러냄 |
| Token Store | 값과 준비 상태를 저장해 어떤 노드가 실행 가능한지 판단하는 기준이 됨 |
| Scheduler | 입력이 모두 충족된 노드를 골라 실행 자원에 배분하며 전체 처리량과 공정성에 영향을 줌 |
| Execution Node | 활성화된 노드가 연산을 수행하고 결과 토큰을 후속 노드로 전달해 다음 실행을 유도함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 그래프 생성    | --> | 토큰 도착 점검  | --> | 준비 노드 실행  | --> | 결과 전파      |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **그래프 생성**: 프로그램을 연산 노드와 데이터 의존성 그래프로 변환함
2. **토큰 도착 점검**: 각 노드의 입력 데이터 준비 여부를 갱신함
3. **준비 노드 실행**: 입력이 충족된 노드를 즉시 실행 자원에 할당함
4. **결과 전파**: 출력 토큰을 다음 노드로 보내 후속 병렬 실행을 연쇄적으로 발생시킴

## Ⅵ. 문제점 및 해결 방안

1. 문제: 토큰 이동과 준비 상태 추적 비용이 커지면 병렬 실행으로 얻는 성능 이득이 줄어들 수 있음
   - 해결방안: coarse-grained 노드화와 로컬 버퍼링을 적용하고 token overhead ratio와 execution utilization로 검증함
2. 문제: 공유 메모리 부작용이 많은 프로그램은 순수 데이터 의존성만으로 안전한 실행 순서를 정하기 어려움
   - 해결방안: SSA 기반 의존 분석과 명시적 동기화를 병행하고 memory conflict rate와 replay count로 검증함
3. 문제: 일부 핫스폿 노드에 부하가 집중되면 전체 그래프 병렬성이 제한되어 자원 유휴가 늘어날 수 있음
   - 해결방안: 그래프 파티셔닝과 work stealing을 적용하고 hotspot skew와 ready queue imbalance로 검증함

## Ⅶ. 적용 사례

- AI 데이터플로우 가속기에서는 연산 그래프를 타일 단위로 분할해 병렬 실행하고 확인 지표는 execution utilization과 memory traffic임
- 스트림 처리 엔진에서는 이벤트 도착 기반으로 준비 노드를 실행하고 확인 지표는 throughput과 queue backlog임
- 그래프 분석 가속 연구에서는 의존성이 약한 노드를 분산 배치하고 확인 지표는 parallelism extracted와 scheduler overhead임

## Ⅷ. 결론

데이터 흐름 컴퓨터는 순차 제어를 버리고 의존성 기반 병렬성을 극대화하는 구조이므로, 적용 가치는 토큰 관리 비용보다 그래프형 병렬성이 충분히 큰지에 달림.
