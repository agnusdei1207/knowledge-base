## 미리 알고가기

- 제어 흐름 컴퓨터는 프로그램 카운터 순서대로 명령을 실행함
- 데이터 흐름 컴퓨터는 입력 데이터가 준비된 연산부터 실행함
- 토큰은 값과 준비 상태를 함께 담아 노드 실행 가능 여부를 나타내는 단위임

## Ⅰ. 개요

- **정의/개념**: 데이터 흐름 컴퓨터는 프로그램을 연산 노드와 데이터 의존 간선의 그래프로 표현하고, 입력 토큰이 준비된 노드부터 실행하는 비순차 계산 구조임
- **배경/필요성**: 제어 흐름 기반 구조는 명령 순서가 병렬성을 숨기는 경우가 많아, 그래프 연산과 스트림 연산처럼 의존 관계가 뚜렷한 워크로드에서는 데이터 준비 상태를 직접 실행 기준으로 삼는 방식이 필요함

## Ⅱ. 특징

- 프로그램 카운터보다 데이터 의존성이 실행 순서를 결정함
- 독립 노드를 자연스럽게 병렬 실행할 수 있음
- 토큰 관리와 스케줄링 비용이 크면 병렬성 이득이 줄어듦
- 그래프·스트림·가속기 연산을 의존성 노드와 데이터 토큰으로 표현함

## Ⅲ. 종류 및 비교

| 판단 기준 | 제어 흐름 컴퓨터 | 데이터 흐름 컴퓨터 |
|:---|:---|:---|
| 실행 기준 | 명령 순서와 분기 흐름이 실행 순서를 정함 | 입력 데이터 준비 여부가 실행 순서를 정함 |
| 병렬성 추출 | 컴파일러와 OoO 하드웨어가 명령 의존성을 분석함 | 입력 토큰이 준비된 독립 노드를 병렬 실행함 |
| 상태 관리 | 레지스터와 메모리 순서 관리가 핵심임 | 토큰과 노드 활성 상태 관리가 핵심임 |
| 적합 업무 | 범용 순차 프로그램에 강함 | 스트림, 그래프, 데이터플로우 가속에 강함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 데이터플로우 그래프 | 연산 노드와 데이터 의존 간선으로 프로그램 구조를 표현함 |
| 토큰 저장소 | 값과 준비 상태를 저장해 어떤 노드가 실행 가능한지 판단함 |
| 스케줄러 | 입력이 모두 준비된 노드를 골라 실행 자원에 배분함 |
| 실행 노드 | 활성화된 연산을 수행하고 결과 토큰을 다음 노드로 전달함 |

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 그래프 생성    | --> | 토큰 도착 점검  | --> | 준비 노드 실행  | --> | 결과 전파      |
+-------------+     +-------------+     +-------------+     +-------------+
```

## Ⅴ. 원리 및 절차 흐름도

1. **그래프 생성**: 프로그램을 연산 노드와 데이터 의존성 그래프로 바꿈
2. **토큰 도착 점검**: 각 노드 입력이 모두 준비됐는지 갱신함
3. **준비 노드 실행**: 입력이 충족된 노드를 즉시 실행 자원에 할당함
4. **결과 전파**: 출력 토큰을 후속 노드로 보내 다음 실행을 유도함

## Ⅵ. 실무 적용 및 유의점

1. AI 가속기나 스트림 엔진은 데이터 흐름 구조가 병렬성 추출에 유리하지만 토큰 이동 오버헤드가 커지면 이득이 줄어드므로 큰 연산 단위로 노드를 묶는 방식과 로컬 버퍼링을 함께 적용하고 실행 활용률과 토큰 이동 비중과 준비 큐 불균형으로 확인함
2. 공유 메모리 부작용이 많은 범용 프로그램은 데이터 의존성만으로 안전한 순서를 보장하기 어려우므로 SSA 기반 분석과 명시적 동기화를 병행하고 메모리 충돌률과 재실행 횟수와 스케줄러 오버헤드로 확인함

## Ⅶ. 결론

데이터 흐름 컴퓨터의 가치는 순차 제어를 버리는 데 있는 것이 아니라 의존성이 분명한 워크로드에서 병렬성을 직접 끌어내는 데 있음.
