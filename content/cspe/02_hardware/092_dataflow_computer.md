## 미리 알고가기

- 제어 흐름 컴퓨터는 프로그램 카운터 순서대로 명령을 실행함
- 데이터 흐름 컴퓨터는 입력 데이터가 준비된 연산부터 실행함
- 토큰은 값과 준비 상태를 함께 담아 연산 노드(Node, 정점)의 실행 가능 여부를 나타내는 단위임
- SSA(Static Single Assignment)는 변수를 한 번만 대입하도록 제한해 데이터 의존 관계를 명확히 하는 표현 방식임

## 작성 근거(검토용)

- 데이터 흐름 컴퓨터는 연산 노드, 의존 간선, 토큰 준비 상태, 활성화 규칙을 핵심 축으로 설명함
- 비교표는 제어 흐름과 데이터 흐름의 실행·상태 기준, 병렬성 추출, 적합 업무를 대비함
- 실무 판단은 실행 자원 활용률·토큰 이동 비중과 메모리 충돌률·재실행 횟수로 검증함

## Ⅰ. 개요

- **정의/개념**: 데이터 흐름 컴퓨터는 프로그램을 연산 노드와 데이터 의존 간선의 그래프로 표현하고, 입력 토큰이 준비된 노드부터 실행하는 비순차 계산 구조임
- **배경/필요성**: 의존 관계가 명확한 그래프·스트림 연산의 병렬 노드를 실행하기 위해 데이터 준비 상태를 실행 기준으로 삼는 구조가 필요함

## Ⅱ. 특징

- 프로그램 카운터보다 데이터 의존성이 실행 순서를 결정함
- 입력 토큰이 모두 준비된 독립 노드를 동시에 실행함
- 토큰 관리와 스케줄링 비용이 크면 병렬성 이득이 줄어듦
- 그래프·스트림·가속기 연산을 의존성 노드와 데이터 토큰으로 표현함

## Ⅲ. 종류 및 비교

| 판단 기준 | 제어 흐름 컴퓨터 | 데이터 흐름 컴퓨터 |
|:---|:---|:---|
| 실행·상태 기준 | 명령 순서와 분기 흐름이 실행 순서를 정하고 레지스터·메모리 상태로 관리함 | 입력 데이터 준비 여부가 실행 순서를 정하고 토큰·노드 활성 상태로 관리함 |
| 병렬성 추출 | 컴파일러와 OoO 하드웨어가 명령 의존성을 분석함 | 입력 토큰이 준비된 독립 노드를 병렬 실행함 |
| 적합 업무 | 분기·공유 상태가 많은 범용 프로그램 | 의존 그래프가 명확한 스트림·그래프 연산 |

> 요약: 제어 흐름은 명령 순서, 데이터 흐름은 입력 토큰의 준비 여부로 실행 시점을 결정함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 데이터 흐름 그래프 | 연산 노드와 데이터 의존 간선으로 프로그램 구조를 표현함 |
| 토큰 저장소 | 값과 준비 상태를 저장해 어떤 노드가 실행 가능한지 판단함 |
| 스케줄러 | 입력이 모두 준비된 노드를 골라 실행 자원에 배분함 |
| 실행 노드 | 활성화된 연산을 수행하고 결과 토큰을 다음 노드로 전달함 |

> 요약: 토큰 저장소와 스케줄러가 입력이 준비된 연산 노드를 선택하고 실행 결과를 후속 노드로 전달함.

## Ⅴ. 원리 및 절차 흐름도

1. **그래프 생성**: 프로그램을 연산 노드와 데이터 의존성 그래프로 바꿈
2. **토큰 도착 점검**: 각 노드 입력이 모두 준비됐는지 갱신함
3. **준비 노드 실행**: 입력이 충족된 노드를 즉시 실행 자원에 할당함
4. **결과 전파**: 출력 토큰을 후속 노드로 보내 다음 실행을 유도함

> 요약: 입력 토큰이 갖춰진 노드를 실행하고 출력 토큰으로 후속 노드를 활성화함.

## Ⅵ. 실무 사례

1. AI 가속기는 연산 노드를 묶고 로컬 버퍼를 적용해 실행 자원 활용률·토큰 이동 비중을 확인함
2. 데이터 흐름 런타임은 공유 메모리 접근에 SSA 의존성과 동기화 토큰을 적용하고 메모리 충돌률·재실행 횟수를 확인함

## Ⅶ. 결론

- 데이터 흐름 컴퓨터는 의존 그래프가 명확한 연산에서 토큰 준비 상태로 실행 노드를 선택하고 토큰 이동·스케줄링 비용을 함께 검증해야 함
