## 미리 알고가기

- JTAG는 칩과 보드를 테스트하고 디버깅하는 직렬 인터페이스 표준임
- TAP 제어기(TAP Controller)는 JTAG 명령·데이터 레지스터의 상태 전이를 제어함
- 경계 스캔 체인(Boundary Scan Chain)은 패키지 핀과 내부 레지스터를 직렬로 연결함
- 개발 단계에는 유용하지만 양산 후 그대로 열어 두면 보안 위험이 증가함

## 작성 근거(검토용)

- JTAG는 TAP Controller, Boundary Scan Chain, 디버그 프로브, CPU·플래시 접근 경로를 핵심 구조로 설명함
- 비교표는 JTAG·SWD·UART의 주요 기능, 하드웨어 접근 범위, 보안 유의점을 대비함
- 실무 판단은 테스트 커버리지·검사 시간과 비인가 디버그 접근 차단률로 검증함

## Ⅰ. 개요

- **정의/개념**: JTAG는 직렬 스캔으로 칩·보드 내부 상태를 읽고 쓰며 경계 스캔·플래시 기록·CPU 정지·메모리 점검을 수행하는 테스트·디버깅 인터페이스임
- **배경/필요성**: 고집적 보드의 내부 신호·납땜 불량·레지스터 상태를 검사하기 위해 표준화된 직렬 접근 경로가 필요함

## Ⅱ. 특징

- 칩 내부 레지스터와 핀 상태를 패키지 외부 프로브로 검사함
- 생산 테스트·펌웨어 다운로드·CPU 디버깅을 하나의 포트로 처리함
- 직렬 스캔 체인으로 전송하며 레지스터·메모리·보드 연결 상태에 접근함
- 양산 장치에 남아 있으면 펌웨어 유출과 보안 우회 통로가 될 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | JTAG | SWD | UART 디버그 |
|:---|:---|:---|:---|
| 주요 기능 | 보드 테스트·CPU 디버깅·플래시 기록을 처리함 | ARM 계열 CPU 디버깅을 처리함 | 로그 출력과 콘솔 접근을 처리함 |
| 하드웨어 접근 범위 | 레지스터·메모리·경계 스캔에 접근함 | 디버깅 접근은 넓지만 보드 테스트 범위는 JTAG보다 좁음 | 운영 로그와 명령 입력 수준으로 제한되는 경우가 많음 |
| 보안 유의점 | 양산 후 열어 두면 펌웨어 유출과 보안 우회 위험이 증가함 | 디버그 포트 보호가 없으면 역시 보안 통로가 될 수 있음 | 콘솔 노출과 인증 부재가 운영 보안 문제로 이어질 수 있음 |

> 요약: JTAG는 생산 테스트 범위가 넓고, SWD는 ARM 디버깅, UART는 로그·콘솔 접근에 가까움.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| TAP 제어기 | TCK와 TMS 신호로 상태 기계를 제어해 명령과 데이터 경로를 선택함 |
| 경계 스캔 체인 | 패키지 핀과 내부 레지스터를 직렬로 연결해 검사와 제어를 수행함 |
| 디버그 프로브 | 외부 호스트와 대상 보드 사이에서 명령과 데이터를 중계함 |
| CPU·플래시 접근 경로 | 정지(halt), 단일 스텝(single-step), 메모리 읽기, 펌웨어 기록 같은 실제 디버깅 기능을 제공함 |

> 요약: JTAG는 TAP 제어기, 경계 스캔 체인, 디버그 프로브, CPU·플래시 접근 경로로 동작함.

## Ⅴ. 원리 및 절차 흐름도

1. **프로브 연결**: TCK, TMS, TDI, TDO 신호를 대상 보드에 연결함
2. **TAP 상태 선택**: 상태 기계로 명령 레지스터와 데이터 레지스터 접근을 정함
3. **스캔 데이터 이동**: 명령과 데이터를 직렬 체인으로 밀어 넣고 읽어 냄
4. **테스트·디버그 수행**: 경계 스캔과 메모리 검사와 CPU 제어를 실행함

> 요약: 프로브가 TAP 상태를 선택하고 스캔 체인을 통해 테스트·디버그 데이터를 이동함.

## Ⅵ. 실무 사례

1. 보드 양산 검사는 스캔 체인을 분할하고 테스트 패턴을 최적화해 테스트 커버리지·검사 시간을 확인함
2. 출하 장치는 퓨즈 잠금과 인증된 디버그 해제를 적용하고 비인가 디버그 접근 차단률을 확인함

## Ⅶ. 결론

- JTAG는 개발·생산 단계의 검사 범위와 출하 후 디버그 잠금·인증 해제 정책을 함께 설계해야 함
