## 미리 알고가기

- JTAG는 테스트와 디버깅을 위한 직렬 인터페이스 표준임
- TAP controller와 boundary scan chain이 핵심 구조임
- 개발 단계에 유용하지만 양산 후 노출되면 보안 위험이 큼

## Ⅰ. 개요

- **정의/개념**: JTAG는 칩과 보드의 내부 상태를 직렬 스캔 방식으로 읽고 쓰면서 boundary scan과 펌웨어 다운로드와 CPU halt, 메모리 점검을 수행하는 테스트 및 디버깅 인터페이스임
- **배경/필요성**: 고집적 보드는 물리 프로빙만으로 신호 상태와 납땜 불량과 내부 레지스터를 확인하기 어려우므로, 표준화된 내부 접근 경로가 필요함

## Ⅱ. 특징

- 칩 내부 레지스터와 핀 상태를 비침습적으로 검사할 수 있음
- 플래시 프로그래밍과 CPU 디버깅과 생산 테스트에 모두 활용 가능함
- 직렬 스캔 기반이라 속도는 높지 않지만 접근 범위가 넓음
- 양산 장치에 열린 채 남아 있으면 펌웨어 유출과 보안 우회 위험이 큼

## Ⅲ. 종류 및 비교

| 판단 기준 | JTAG | UART 디버그 | SWD |
|:---|:---|:---|:---|
| 주요 용도 | 테스트, 디버그, 스캔 | 로그, 콘솔 | ARM 디버그 경량화 |
| 하드웨어 접근 범위 | 매우 넓음 | 제한적 | 넓음 |
| 표준화 범위 | 보드, 칩 테스트 | 단순 직렬 통신 | ARM 중심 |
| 보안 위험도 | 높음 | 중간 | 높음 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| TAP Controller | TCK와 TMS 신호로 상태 기계를 제어해 IR, DR 접근을 관리함 |
| Boundary Scan Chain | 패키지 핀과 내부 레지스터를 직렬로 연결해 검사와 제어를 가능하게 함 |
| Debug Probe | 외부 호스트와 대상 보드 사이 명령과 데이터를 중계함 |
| CPU Debug, Flash Access | halt, single-step, 메모리 읽기, 펌웨어 기록 같은 실제 디버깅 기능을 제공함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 프로브 연결    | --> | TAP 상태 선택  | --> | 스캔 데이터 이동 | --> | 테스트/디버그 수행 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **프로브 연결**: TCK, TMS, TDI, TDO를 대상 보드에 연결함
2. **TAP 상태 선택**: 상태 기계로 IR, DR 접근 모드를 정함
3. **스캔 데이터 이동**: 명령과 데이터를 직렬 체인으로 이동시킴
4. **테스트 및 디버그 수행**: boundary scan과 메모리 검사와 CPU 제어를 수행함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 양산 제품에 JTAG가 노출되면 공격자가 펌웨어를 추출하거나 보안 설정을 우회할 수 있음
   - 해결방안: production fuse와 access lock 정책을 적용하고 debug port exposure count와 penetration test 결과로 검증함
2. 문제: 긴 스캔 체인과 다수 장치가 연결되면 테스트 시간이 길어져 생산성이 떨어질 수 있음
   - 해결방안: 스캔 체인 분할과 패턴 최적화를 적용하고 test time과 coverage로 검증함
3. 문제: 보드 설계 단계에서 핀 배치와 신호 품질을 소홀히 하면 디버깅 인터페이스 자체가 불안정해질 수 있음
   - 해결방안: layout guideline을 반영하고 signal integrity와 connection stability로 검증함

## Ⅶ. 적용 사례

- 보드 양산 검사에서는 boundary scan으로 납땜 불량을 점검하고 확인 지표는 test coverage와 defect detection rate임
- 펌웨어 개발 환경에서는 JTAG로 halt와 single-step을 수행하고 확인 지표는 debug turnaround time과 issue reproduction rate임
- 보안 강화 제품에서는 출하 전 JTAG 잠금을 적용하고 확인 지표는 debug port lock coverage와 audit pass rate임

## Ⅷ. 결론

JTAG는 개발과 테스트의 강력한 통로이지만 양산 이후에는 보안 통로가 될 수 있으므로, 활용성과 폐쇄 정책을 함께 설계해야 함.
