## 미리 알고가기

- JTAG: 칩 테스트와 디버깅을 위한 표준 직렬 인터페이스로 boundary scan과 내부 디버그에 사용됨
- TAP: Test Access Port로 TCK, TMS, TDI, TDO 등 JTAG 신호를 통해 상태를 제어함
- Boundary Scan: 칩 핀 주변 셀을 직렬로 연결해 납땜, 연결, 보드 결함을 검사하는 방식임
- TDI/TDO: 테스트 데이터 입력과 출력 신호선임
- JTAG Lock: 양산 제품에서 디버그 접근을 제한하기 위해 fuse, 인증, 잠금 정책을 적용하는 것임

## Ⅰ. 개요

- **정의**: JTAG는 칩과 보드의 테스트, 프로그래밍, 내부 디버깅을 위해 TAP 컨트롤러와 직렬 스캔 체인을 사용하는 하드웨어 인터페이스임. 제조 검사, 펌웨어 다운로드, 저수준 디버깅, 양산 보안 잠금 기준으로 임베디드 장치 개발과 검증에 사용함
- **배경/필요성**: 고집적 칩과 다층 PCB는 외부 핀만으로 내부 연결과 동작을 확인하기 어려움. 표준화된 디버그·테스트 경로가 있어야 생산 검사와 초기 펌웨어 문제 분석을 효율적으로 수행할 수 있음
- **비유**: 완성된 건물 벽을 뜯지 않고 점검 포트를 통해 전기 배선과 방 내부 상태를 검사하는 장치와 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 하드웨어 디버그 인터페이스 설명 | TAP, TCK/TMS/TDI/TDO, boundary scan, debug access | 단순 시리얼 통신으로 설명 |
| 개발 편의와 보안 위험 판단 | 제조 검사, 펌웨어 다운로드, JTAG 잠금 | 양산 후 JTAG 노출 위험 누락 |

> 요약: JTAG는 칩 내부와 보드 연결을 직렬 스캔 경로로 접근하게 해 개발·검사를 돕지만 양산 제품에서는 강한 접근 통제가 필요한 인터페이스임.

## Ⅱ. 특징/비교

| 판단 기준 | UART 로그 | JTAG |
|:---|:---|:---|
| 접근 수준 | 펌웨어가 제공하는 문자열·명령 인터페이스 | CPU 레지스터, 메모리, 플래시, boundary scan 접근 가능 |
| 주요 용도 | 런타임 로그, 간단한 명령, 상태 확인 | 보드 검사, 중단점 디버깅, 펌웨어 프로그래밍 |
| 의존성 | 펌웨어와 드라이버가 동작해야 유용함 | 초기 부팅 전 또는 오류 상태에서도 접근 가능 |
| 보안 위험 | 로그 정보 노출과 명령 오용 | 키 추출, 펌웨어 덤프, 보안 부팅 우회 가능성 |

> 요약: JTAG는 개발·제조 단계에서는 강력한 관찰 도구지만 제품 출시 후에는 민감한 내부 접근 경로가 됨.

- **검사 기준**: boundary scan은 부품 실장, 핀 연결, 보드 단락 같은 제조 결함을 빠르게 탐지함
- **디버그 기준**: CPU halt, step, breakpoint, memory read/write 기능은 초기 부팅 문제 분석에 유용함
- **보안 기준**: 양산 장치에서는 JTAG 비활성화, 인증 디버그, 물리 포트 제거 등 접근 통제가 필요함

## Ⅲ. 구성요소

```text
+----------+      +----------+      +----------+
| Debug    | ---> | TAP      | ---> | Scan     |
| Probe    |      | Control  |      | Chain    |
+----------+      +----+-----+      +----+-----+
                         |                 |
                         v                 v
                   +----------+      +----------+
                   | CPU DBG  |      | Boundary |
                   | Module   |      | Cells    |
                   +----------+      +----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 디버그 프로브 | PC 디버거와 대상 보드의 JTAG 신호를 연결하는 장치임 | 검사 장비 |
| TAP 컨트롤러 | TMS와 TCK로 상태를 전환하며 명령·데이터 레지스터 접근을 제어함 | 출입 게이트 |
| 명령·데이터 레지스터 | 어떤 테스트나 디버그 동작을 수행할지 선택하고 데이터를 이동함 | 작업 지시서 |
| Boundary Scan Cell | 칩 핀 주변 신호를 캡처하거나 구동해 보드 연결을 시험함 | 핀별 점검 센서 |
| CPU 디버그 모듈 | 코어 정지, 단일 실행, 메모리 접근, 중단점 기능을 제공함 | 내부 정비 통로 |

> 요약: JTAG는 프로브, TAP, 스캔 체인, boundary cell, CPU 디버그 모듈을 통해 보드와 칩 내부에 접근함.

## Ⅳ. 절차

```text
+----------+      +----------+      +----------+      +----------+
| Connect  | ---> | Select   | ---> | Shift    | ---> | Debug or |
| Probe    |      | IR/DR    |      | Data     |      | Test     |
+----------+      +----------+      +----------+      +----------+
```

1. **프로브 연결**: TCK, TMS, TDI, TDO, TRST, 전원 기준 신호를 대상 보드와 연결함
2. **TAP 상태 제어**: TMS 시퀀스로 instruction register와 data register 접근 상태를 선택함
3. **명령·데이터 이동**: 스캔 체인을 통해 테스트 명령, 주소, 데이터, 상태값을 직렬로 이동함
4. **디버그·검사 수행**: boundary scan, 플래시 프로그래밍, CPU halt, 메모리 검사 후 양산 잠금 정책을 적용함

> 요약: JTAG 동작은 프로브 연결, TAP 상태 전환, 스캔 데이터 이동, 테스트·디버그 실행 순서로 진행됨.

## Ⅴ. 문제점

- **P1 양산 제품 노출**: JTAG가 열린 상태로 출하되면 공격자가 펌웨어와 메모리를 덤프하거나 보안 설정을 우회할 수 있음
- **P2 스캔 체인 복잡성**: 여러 칩이 체인으로 연결된 보드에서는 BYPASS 설정, 신호 순서, 전압 레벨 오류로 검사 실패가 발생함
- **P3 신호 무결성 문제**: 긴 케이블, 높은 TCK 속도, 접지 불량은 JTAG 통신 오류와 잘못된 검사 결과를 만들 수 있음

> 요약: JTAG 위험은 강력한 접근 권한, 복잡한 체인 구성, 물리 신호 품질 관리에서 발생함.

## Ⅵ. 개선방안

1. **단기**: 제품별 JTAG 노출 여부, 잠금 fuse, 포트 접근성을 점검함
2. **중기**: 제조 단계와 서비스 단계별 디버그 권한 정책, 인증 절차, 체인 테스트를 표준화함
3. **장기**: 보안 디버그 아키텍처와 생산 자동화 검사를 통합해 개발 편의와 보안을 균형화함

- **P1 대응**: 양산 시 JTAG disable, secure debug 인증, 포트 비실장 정책을 적용함 (확인: 외부 메모리 읽기 차단 시험)
- **P2 대응**: 체인 길이, BYPASS 순서, 장치 IDCODE 검사를 자동화함 (확인: 스캔 체인 인식률)
- **P3 대응**: TCK 속도 조정, 짧은 케이블, 접지 보강, 레벨 변환기를 적용함 (확인: JTAG 통신 오류율)

> 요약: JTAG 개선은 양산 보안 잠금과 제조 검사 신뢰성을 함께 관리해야 함.

## Ⅶ. 전망

- **발전 방향**: JTAG는 boundary scan, built-in self-test, secure debug authentication과 결합해 제조 테스트와 현장 진단을 모두 지원하는 방향으로 발전함
- **기술사적 판단**: 개발·제조·서비스 단계별 접근권한, fuse/lock 정책, debug certificate, test pad 노출, board routing을 제품 수명주기에 맞춰 설계함; boundary scan coverage, secure debug unlock 절차, lock bit 영속성, fault injection 후 접근 가능성, audit log 생성을 확인함
- **기술사 제언**: JTAG 답안은 테스트 편의성과 공격면을 동시에 제시하고 단계별 secure debug 정책을 설계 기준으로 정리함
