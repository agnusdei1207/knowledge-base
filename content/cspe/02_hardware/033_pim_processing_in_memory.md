# 📖 【암기용】 개념 완전 이해

> 목적: PIM이 "왜 메모리 안에서 연산을 하는가"를 데이터 이동 에너지 수치로 이해하게 만든다. HBM4의 로직 베이스 다이가 PIM을 얹는 대표적 무대라는 점은 032_hbm4.md에서 이미 다뤘으므로, 여기서는 그 자리에서 실제로 무슨 일이 일어나는지(PCU 배치, 병렬성, 에너지 절감의 원리)를 다룬다.

## 한눈에
- **개요**: PIM(메모리 내 처리, Processing-In-Memory)은 폰 노이만 병목(CPU-메모리 간 데이터 이동 병목)을 줄이기 위해, 메모리 칩 내부(뱅크 근처)에 소형 연산 유닛을 두어 데이터를 CPU/GPU로 옮기지 않고 메모리 안에서 직접 연산을 수행하는 기술이다.
- **왜 필요한가**: 폰 노이만 구조에서는 연산 자체보다 CPU와 메모리 사이의 데이터 이동에 드는 시간과 에너지가 훨씬 크다(폰 노이만 병목). 특히 AI의 행렬 연산처럼 계산은 단순한데 데이터 양이 압도적으로 많은 워크로드는 이 이동 비용이 성능을 좌우한다. 데이터를 옮기지 않고 있는 자리에서 계산해버리면 이 병목이 근본적으로 줄어든다.
- **핵심 직관**: 재료를 창고(메모리)에서 주방(CPU)까지 매번 옮겨 요리하는 대신, 창고 안에 작은 조리대(연산 유닛)를 두어 간단한 손질은 그 자리에서 끝내고 필요한 결과물만 주방으로 보내는 것이다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 폰 노이만 병목(Von Neumann Bottleneck) | CPU와 메모리가 분리된 구조에서, 둘 사이의 데이터 이동 통로가 성능의 병목이 되는 현상 — PIM이 해결하려는 근본 원인 | 창고와 주방이 멀리 떨어져 있어 운반이 요리보다 오래 걸리는 것 |
| 뱅크(Bank) | DRAM 칩 내부에서 독립적으로 읽고 쓸 수 있는 저장 구획 단위 | 창고 안의 개별 선반 구역 |
| PCU(Programmable Computing Unit) | 뱅크 입구나 셀 어레이 근처에 배치하는 소형 연산 유닛 — 덧셈·곱셈 등 단순 연산 수행 | 각 선반 옆에 놓인 소형 조리대 |
| 뱅크 수준 병렬성(Bank-level Parallelism) | 여러 뱅크가 각자의 PCU로 동시에 연산을 수행해 전체 처리량을 늘리는 방식 | 여러 조리대가 동시에 손질을 진행하는 것 |
| PNM(Processing Near Memory) | 연산기를 메모리 칩 내부가 아니라 메모리 컨트롤러 등 칩 바로 옆에 두는 방식 — PIM과 구분되는 인접 개념 | 창고 안이 아니라 창고 문 앞에 조리대를 둔 것 |
| HBM-PIM | HBM 뱅크에 PCU를 결합한 실제 구현 사례 | PIM 개념이 상용 제품으로 실현된 예 |

## 깊이 이해

### 데이터 이동이 왜 그렇게 비싼가 (에너지 수치로 보기)
- 반도체 설계 분야에서 자주 인용되는 근사치로, 32비트 덧셈 같은 단순 연산 자체는 약 0.1pJ(피코줄) 수준의 에너지면 충분한 반면, DRAM에서 데이터를 읽어 칩 밖으로 내보내는 데는 이보다 수십~수백 배 큰 에너지가 든다(정확한 값은 공정·거리에 따라 다르며, 여기서는 규모감을 보여주는 근사치다).
- 즉 AI 행렬 연산처럼 "연산량 대비 데이터 이동량이 큰" 워크로드에서는 전체 에너지의 대부분이 실제 계산이 아니라 데이터를 옮기는 데 소모된다. PIM은 이 이동 구간 자체를 없애 에너지를 줄이는 접근이다.

### PCU가 뱅크에 배치되는 원리
- DRAM 칩은 내부적으로 여러 개의 뱅크로 나뉘어 있고, 각 뱅크는 독립적으로 데이터를 읽고 쓸 수 있다. PIM은 이 뱅크 입구나 셀 어레이 근처에 덧셈·곱셈·누산(FMA) 같은 단순 연산만 수행하는 작은 회로(PCU)를 심는다.
- 호스트(CPU/GPU)가 일반 읽기/쓰기 명령 대신 전용 PIM 명령어를 내리면, 메모리가 내부 데이터 통로(칩 외부로 나가지 않는 로컬 데이터 경로)로 데이터를 읽어 PCU에서 바로 연산하고, 결과값만 외부 버스로 돌려준다. 여러 뱅크가 동시에 이 과정을 수행하면(뱅크 수준 병렬성) 전체 처리량이 늘어난다.

### 워크드 예시: 행렬 연산에서 PIM이 아끼는 이동량
- 예를 들어 4096×4096 크기의 가중치 행렬과 벡터를 곱하는 연산에서, 기존 방식은 약 1,600만 개(4096×4096)의 가중치 값을 매번 메모리에서 CPU/GPU로 읽어와야 한다. 연산 자체(곱셈-누산)는 가중치 개수만큼만 필요하지만, 이동은 그 값들을 전부 버스에 실어 날라야 성립한다.
- PIM은 이 가중치를 옮기지 않고 뱅크 내부에서 곱셈-누산까지 끝낸 뒤 훨씬 작은 결과 벡터(4096개)만 돌려준다. 이동량이 수백만~수천만 단위에서 수천 단위로 줄어드는 구조이기 때문에, 대역폭이 아니라 이동 자체가 병목인 워크로드일수록 절감 효과가 크다.
- 실제 구현 사례인 HBM-PIM은 기존 HBM2 대비 AI 추론 성능이 약 2배, 에너지 소비는 약 50% 이상 절감되는 결과가 보고된 바 있다(구체 수치는 워크로드·구현에 따라 다르다).

### PIM vs PNM — 연산기의 위치가 가르는 차이
- 두 개념 모두 "데이터 이동을 줄인다"는 목표는 같지만, 연산기의 물리적 위치가 다르다. PIM은 메모리 칩 내부(뱅크 근처)에 연산기를 넣어 칩 안에서 이동을 없애고, PNM은 메모리 칩 밖(컨트롤러나 인터포저 등 근접 위치)에 연산기를 둬 칩-칩 간 이동은 줄이되 칩 설계 자체는 덜 건드린다.
- 그만큼 PIM은 이동 절감 효과가 크지만 메모리 공정에 연산 회로를 넣어야 해 설계·수율 부담이 크고, PNM은 상대적으로 구현이 쉽지만 절감 효과는 PIM보다 제한적이다.

### 흔한 오해와 주의점
- PIM이 CPU를 완전히 대체하는 것은 아니다. 분기·제어 같은 복잡한 로직은 여전히 CPU/GPU가 담당하고, 데이터 집약적인 단순 반복 연산(덧셈, 곱셈 등)만 메모리가 나눠 맡는 구조다.
- "PIM은 HBM에서만 가능하다"도 오해다. HBM-PIM은 널리 알려진 구현 사례일 뿐이며, DDR 등 다른 DRAM 규격에도 PIM 개념을 적용할 수 있다. 다만 HBM4처럼 베이스 다이가 로직 공정으로 제작되는 경우 연산 회로를 심을 여유 공간이 더 크다는 이점이 있다(032 참고).

## 연결 개념
- 032_hbm4.md — 로직 베이스 다이라는, PIM 회로를 얹기에 특히 유리한 최신 하드웨어 무대
- PNM(Processing Near Memory) — 연산기 위치가 칩 내부가 아닌 인접 개념
- 폰 노이만 병목(Von Neumann Bottleneck) — PIM이 해결하려는 근본 원인
- CXL — PIM/PNM 가속기를 시스템 차원에서 효율적으로 연결하는 인터페이스

# 📝 【답안용】 시험 답안 템플릿

> 2. **가치**: 폰 노이만 구조의 데이터 이동 병목을 해소하여 AI 추론 성능을 2배 이상 향상시키고 전력 소모를 50% 이상 절감한다.

## Ⅰ. 개요 및 필요성

- 정의: 메모리 반도체 내부(Inside Memory)에 연산 기능을 통합하여 데이터 이동을 최소화하는 지능형 메모리 기술
- 배경: 폰 노이만 구조의 데이터 전송 병목(Memory Wall) 및 에너지 소모 급증 문제 심화
- 필요성: AI/Big Data 시대의 대규모 행렬 연산 가속, 전력 효율성(성능/와트) 극대화, 시스템 TCO 절감

---

## Ⅱ. 구조 및 구성요소

```text
Host CPU/GPU <-> Memory Controller <-> PIM Chip (HBM/DDR)
                                          |
                                          +-- Bank 0 -- [PCU] -- Cell Array
                                          +-- Bank 1 -- [PCU] -- Cell Array
                                          ...
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| PCU | 연산 유닛 (Programmable Computing Unit) | 덧셈, 곱셈(FMA) 등 단순 연산 수행 |
| Bank-level Parallelism | 뱅크별 독립 연산 수행 | 여러 뱅크가 동시에 연산하여 성능 극대화 |
| PIM Instruction | 연산 트리거 명령어 | 호스트가 전송하는 특수 명령어 세트 |
| Local Data Path | 뱅크 내 데이터 이동 통로 | 칩 외부로 나가지 않는 초고속 통로 |

> 요약: 메모리 뱅크마다 전용 연산기(PCU)를 배치하여 뱅크 수준의 병렬성을 연산에 직접 활용하는 구조다.

## Ⅲ. 동작원리 및 흐름도

```text
호스트 명령어 하달 -> 메모리 컨트롤러 전송 -> PIM 모드 진입 -> 뱅크 내 데이터 로드
                                                                |
                                                                +-- PCU 연산 수행
                                                                |
결과값 집계(Reduction) <- 결과값 뱅크 저장/출력 <- 연산 완료
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | PIM 커널/명령어 하달 | 전용 라이브러리(PIM-API) 호출 |
| 2 | 데이터 로드 및 PCU 연산 | 뱅크 내 고속 데이터 패스 활용 |
| 3 | 결과값 처리 및 쓰기 | 중간 결과값 저장 및 집계 |
| 4 | 호스트 결과 반환 | 최종 연산 결과만 시스템 버스로 전송 |

> 요약: 데이터를 CPU로 가져오는 대신 명령어만 메모리로 보내 뱅크 내부에서 즉시 연산하고 결과만 돌려받는 흐름이다.

| 가속 배수 (Speedup) | 기존 대비 2배 이상 | MLPerf 등 AI 벤치마크 |
| 전력 효율 (Energy) | 기존 대비 50% 이상 절감 | 전력 측정 장비 및 시뮬레이터 |
| 정확도 (Accuracy) | 정밀도 손실 0.1% 이내 | FP16/INT8 연산 정확도 검증 |

> 요약: 도입 성공은 실제 AI 워크로드에서의 성능 향상과 전력 절감 수치로 검증한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. AI 추론 가속: 모바일 온디바이스 AI 또는 클라우드 추론 서버에 HBM-PIM을 탑재하여 응답 속도 개선
2. 에너지 최적화: 초거대 모델(LLM) 서빙 시 PIM을 활용하여 데이터센터 운영 전력(PUE 개선) 및 탄소 배출 저감
3. 알고리즘 최적화: 행렬 곱셈(GEMM), 활성화 함수 등 PIM에 적합한 연산을 선별하여 오프로딩(Offloading) 수행

**결론 (2줄):**
- 기술사 판단: PIM은 폰 노이만 병목을 근본적으로 해결하는 차세대 솔루션이며, 메모리 벤더와 시스템 벤더 간의 소프트웨어 표준화 공조가 시장 확대의 핵심이다.
- 향후 방향: 단순 연산을 넘어 신경망 연산 전체를 처리하는 NPU-in-Memory 형태로 진화하며, CXL 인터페이스와 결합하여 확장성을 확보할 전망이다.
