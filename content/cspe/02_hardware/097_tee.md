## Ⅰ. 개요
- 메인 프로세서 내부에 독립적으로 실행되는 안전한 영역. ARM의 TrustZone이 대표적임.
- 일반 환경(Rich OS)과 격리된 신뢰 환경(Trusted OS)을 구축하여 민감 정보 처리.
| 구분 | 내용 | 비고 |
|---|---|---|
| 정의 | HW 기반의 격리된 보안 실행 영역 | ARM TrustZone |
| 의도 | 실행 환경 분리를 통한 런타임 보안 및 권한 제어 이해 측정 | 하드웨어 격리 |

## Ⅱ. 구성요소
+--------------------+---------------------+
| Normal World (REE) | Secure World (TEE)  |
| Apps / Linux OS    | Trusted App / T-OS  |
+--------------------+---------------------+
|      Monitor Mode (Context Switch)       |
+------------------------------------------+
| 구성요소 | 설명 | 비유 |
|---|---|---|
| NS bit | 비보안/보안 모드를 구분하는 프로세서 상태 비트 | 출입 카드 |
| Monitor Mode | REE와 TEE 사이의 전환을 관리하는 특권 모드 | 게이트 |
| TZASC | 메모리 영역별 보안 권한을 제어하는 컨트롤러 | 구역 칸막이 |
> 요약: REE(일반), TEE(신뢰), 모니터 모드 및 자원 격리 컨트롤러 구조임.

## Ⅲ. 절차
(1) SMC Call -> (2) Context Switch -> (3) Trusted Work -> (4) Return
1. SMC Call: REE의 앱이 Secure Monitor Call 명령어로 TEE 서비스를 요청함.
2. Context Switch: CPU 상태를 보안 모드로 전환하고 레지스터 정보를 보관함.
3. Trusted Work: TEE 내의 Trusted App이 암호 연산, 인증 등 보안 작업 수행.
4. Return: 결과를 전달하고 다시 REE로 전환하여 일반 작업을 재개함.
> 요약: 요청, 환경 전환, 보안 작업 수행, 복귀 순으로 진행됨.

## Ⅳ. 문제점
- 자원 공유: 공유 버스나 캐시를 통한 부채널 공격(Side-channel) 가능성 존재.
- 관리 복잡성: TEE 전용 OS와 앱 개발 시 높은 전문성 및 서명 권한 관리 필요.

## Ⅴ. 개선방안
- 보호 강화: 캐시 파티셔닝 및 메모리 암호화를 통한 자원 격리 수준 고도화.
- 표준 API: GlobalPlatform 표준 API 준수로 개발 생산성 및 상호운용성 확보.

## Ⅵ. 전망
- 기밀 컴퓨팅(Confidential Computing): 데이터 처리 중 보안을 위해 TEE 활용 급증.
- AI 모델 보호: Edge 장치에서 AI 모델의 가중치 유출 방지를 위한 TEE 활용 확대.
