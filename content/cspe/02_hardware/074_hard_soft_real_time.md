## 미리 알고가기

- 실시간 시스템은 결과의 정확성뿐 아니라 결과가 나온 시간도 중요함
- 하드 실시간은 데드라인 미스가 안전 사고나 시스템 실패로 이어짐
- 소프트 실시간은 데드라인 미스가 품질 저하를 의미하지만 즉시 치명적이지는 않음

## Ⅰ. 개요

- **정의/개념**: 하드와 소프트 실시간은 작업이 데드라인을 놓쳤을 때 발생하는 위험 수준과 결과 가치에 따라 실시간 요구와 검증 강도를 구분하는 체계임
- **배경/필요성**: 자동차 제동과 영상 스트리밍은 모두 시간 제약이 있지만 실패 비용이 다르므로, 같은 설계와 검증 수준을 적용하면 과잉 설계나 과소 설계가 발생함

## Ⅱ. 특징

- 하드 실시간은 모든 데드라인 보장이 핵심이며 안전과 인증 요구가 강함
- 소프트 실시간은 일부 지연 허용이 가능하지만 품질 저하가 누적되면 서비스 가치가 떨어짐
- firm 실시간은 늦은 결과가 무의미하지만 치명적 사고까지는 아닌 중간 유형임
- 유형에 따라 WCET 분석과 이중화와 테스트 강도가 달라짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 하드 실시간 | 소프트 실시간 | Firm 실시간 |
|:---|:---|:---|:---|
| 데드라인 미스 의미 | 시스템 실패, 안전 위험 | 품질 저하 | 결과 가치 상실 |
| 검증 강도 | 매우 높음 | 중간 | 중간~높음 |
| 대표 예 | 제동 제어, 의료 제어 | 스트리밍, UI | 산업 샘플링, 거래 일부 |
| 설계 우선순위 | 보장성 | 평균 품질 | 유효성 유지 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Deadline Model | 각 태스크의 허용 완료 시점을 정의해 실시간 유형 구분의 기준이 됨 |
| WCET, Response Analysis | 최악 실행시간과 응답시간 분석이 하드 실시간 보장의 핵심임 |
| Scheduler, Priority Policy | 유형에 맞는 우선순위와 예약 전략이 지연 위험을 제어함 |
| Fault Handling Strategy | 미스 발생 시 fail-safe 또는 degraded mode 같은 대응 수준이 다르게 설정됨 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 실패 영향 분석   | --> | 실시간 유형 분류 | --> | 스케줄/보장 설계 | --> | 검증/비상 대응  |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **실패 영향 분석**: 데드라인 미스 시 결과를 평가함
2. **실시간 유형 분류**: 하드와 소프트와 firm 중 적합 유형을 정함
3. **스케줄 및 보장 설계**: 우선순위와 여유 시간과 이중화를 설계함
4. **검증 및 비상 대응**: 미스 발생률과 fail-safe 동작을 시험함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 소프트 실시간 문제를 하드 실시간처럼 설계하면 비용과 복잡도가 과도하게 증가할 수 있음
   - 해결방안: failure impact 기반으로 유형을 분류하고 capex와 acceptable miss rate로 적정 수준을 검증함
2. 문제: 하드 실시간 문제를 소프트 기준으로 다루면 드문 지연 하나가 치명적 사고로 이어질 수 있음
   - 해결방안: WCET와 redundancy를 적용하고 worst-case response time과 safety incident risk로 검증함
3. 문제: Firm 실시간을 별도 구분하지 않으면 늦은 결과 처리 정책이 불명확해 시스템 자원 낭비가 커질 수 있음
   - 해결방안: expired result drop policy를 정의하고 stale output ratio와 system utilization으로 검증함

## Ⅶ. 적용 사례

- 자동차 제동 제어에서는 하드 실시간으로 설계하고 확인 지표는 WCET bound와 fail-safe success rate임
- 영상 스트리밍 서비스에서는 소프트 실시간으로 운영하고 확인 지표는 frame drop rate와 user QoE임
- 산업 센서 샘플링에서는 firm 실시간으로 다루고 확인 지표는 stale sample rate와 control accuracy임

## Ⅷ. 결론

하드와 소프트 실시간의 차이는 빠르기 차이가 아니라 데드라인 미스가 허용되는가의 차이이므로, 실패 비용을 먼저 정하고 설계를 시작해야 함.
