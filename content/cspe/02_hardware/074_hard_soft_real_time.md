## 미리 알고가기

- 실시간 시스템은 결과값과 완료 시점이 모두 요구조건을 충족해야 함
- WCET(Worst-Case Execution Time)는 태스크가 최악 조건에서 실행을 완료하는 데 걸리는 최대 시간임
- 하드 실시간은 데드라인 미스가 치명적 사고나 시스템 실패와 직접 연결됨
- 소프트 실시간은 지연이 품질을 낮추지만 치명적 사고와 직접 연결되지는 않음

## 작성 근거(검토용)

- 하드·소프트 실시간은 데드라인 미스의 피해 수준, WCET, 검증 강도를 기준으로 설명함
- 비교표는 하드, Firm, 소프트 실시간의 미스 의미, 검증 기준, 대표 사례·미스 대응을 대비함
- 실무 판단은 최대 응답시간, 데드라인 미스 수, 프레임 손실률, p99 재생 지연으로 구체화함

## Ⅰ. 개요

- **정의/개념**: 하드 실시간과 소프트 실시간은 작업이 데드라인을 놓쳤을 때 발생하는 피해 수준에 따라 실시간 요구와 검증 강도를 구분하는 체계임
- **배경/필요성**: 자동차 제동과 영상 스트리밍은 모두 시간 제약이 있지만 실패 비용이 전혀 다르므로, 같은 수준의 설계와 시험을 적용하면 과소 설계 또는 과잉 설계가 생김

## Ⅱ. 특징

- 하드 실시간은 정의된 운용 조건에서 모든 데드라인을 충족하도록 WCET와 응답시간을 검증함
- 소프트 실시간은 일부 지연을 허용하지만 지연이 누적되면 서비스 가치가 떨어짐
- Firm 실시간은 늦은 결과를 폐기하지만 치명적 사고와 직접 연결되지는 않는 유형임
- 유형에 따라 WCET 분석과 이중화와 시험 기준이 달라짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 하드 실시간 | Firm 실시간 | 소프트 실시간 |
|:---|:---|:---|:---|
| 데드라인 미스 의미 | 치명적 사고·시스템 실패와 직접 연결됨 | 늦은 결과를 폐기하며 치명적 사고와 직접 연결되지는 않음 | 품질이 낮아지지만 서비스는 계속됨 |
| 검증 기준 | WCET·최악 응답시간·안전 시험 | 결과 유효 시간·폐기 정책 | p95·p99 지연·프레임 손실률 |
| 대표 예·미스 대응 | 제동 제어·보호 계전기이며 미스 시 안전 정지하고 고장을 격리함 | 산업 샘플링·일부 거래 처리이며 미스 시 늦은 결과를 폐기함 | 스트리밍·UI 응답이며 미스 시 품질이 저하되고 재버퍼링함 |

> 요약: 하드 실시간은 미스를 허용하지 않고, firm은 늦은 결과를 버리며, 소프트는 품질 저하로 다룸.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 데드라인 모델 | 각 태스크의 완료 시점을 정해 실시간 유형을 구분하는 기준이 됨 |
| WCET·응답시간 분석 | 최악 실행시간과 차단 시간을 합산해 응답시간 상한을 계산함 |
| 스케줄러 정책 | 우선순위와 실행 시간 예약으로 태스크별 응답시간을 제한함 |
| 장애 대응 전략 | 미스 발생 시 안전 정지, 결과 폐기, 품질 저하 중 하나로 전환함 |

> 요약: 실시간 유형은 데드라인 모델, WCET·응답시간, 스케줄러, 장애 대응 전략으로 구체화됨.

## Ⅵ. 실무 사례

1. 제동 제어는 WCET 분석과 안전 정지 시험을 수행하고 최대 응답시간·데드라인 미스 수를 확인함
2. 영상 스트리밍은 지연·손실 예산을 정하고 프레임 손실률·p99 재생 지연을 확인함

## Ⅶ. 결론

- 하드·Firm·소프트 실시간은 데드라인 미스의 피해와 결과 유효성에 따라 검증 기준과 미스 대응을 구분함
