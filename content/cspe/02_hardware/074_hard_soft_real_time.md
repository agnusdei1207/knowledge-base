## Ⅰ. 개요
- **정의**: 데드라인 위반 시 결과의 심각도에 따라 실시간 시스템을 분류하는 기준
- **배경/필요성**: 모든 실시간 시스템이 동일한 수준의 시간 보장을 요구하지 않으므로, 요구 수준에 맞는 설계 전략을 구분할 필요가 있음
- **비유**: Hard 실시간은 에어백(지연 시 인명 피해), Soft 실시간은 동영상 스트리밍(지연 시 화질 저하)에 해당함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 두 유형의 차이와 설계 기준 이해 | 데드라인 위반 결과가 치명적(Hard) vs 품질 저하(Soft) | Firm 실시간(위반 시 결과 무가치)을 추가 언급하면 가산 가능 |

> 요약: 데드라인 위반의 결과 심각도가 Hard와 Soft 실시간을 구분하는 핵심 기준임

## Ⅱ. 구성요소
```text
Real-Time System Classification

                    Deadline Miss
                         |
          +--------------+--------------+
          |              |              |
       Hard RT        Firm RT        Soft RT
   (Catastrophic)   (Worthless)   (Degraded)
   e.g. ABS Brake   e.g. Radar    e.g. VoIP
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Hard Real-Time | 데드라인 위반 시 시스템 실패 또는 인명 피해가 발생하는 유형 | 수술 중 마취 타이밍 |
| Firm Real-Time | 데드라인 위반 시 해당 결과가 무가치해지나 시스템은 유지되는 유형 | 경매 입찰 마감 |
| Soft Real-Time | 데드라인 위반 시 서비스 품질이 점진적으로 저하되는 유형 | 화상회의 음성 끊김 |
| 데드라인(Deadline) | 태스크가 완료되어야 하는 절대 시한, 위반 여부 판정 기준 | 시험 종료 벨 |

> 요약: 위반 결과의 심각도에 따라 Hard·Firm·Soft 세 유형으로 분류됨

## Ⅲ. 절차
```text
Step1 Classify --> Step2 Analyze --> Step3 Design --> Step4 Verify
  Determine        WCET + schedulability   Select       Formal timing
  deadline type    analysis               mechanism     verification
```
- 1단계: 분류 — 각 태스크의 데드라인 위반 결과를 분석하여 Hard/Firm/Soft를 결정함
- 2단계: 시간 분석 — 최악 실행시간(WCET)을 산출하고 스케줄 가능성을 검증함
- 3단계: 메커니즘 설계 — Hard는 정적 스케줄링(RM), Soft는 동적 스케줄링(EDF) 등을 선택함
- 4단계: 타이밍 검증 — 시뮬레이션 또는 정형 기법으로 데드라인 준수 여부를 확인함

> 요약: 분류 → WCET 분석 → 스케줄링 선택 → 타이밍 검증의 4단계로 실시간 요구를 충족함

## Ⅳ. 문제점
- WCET 과추정: 최악 경로 분석이 지나치게 보수적이면 CPU 이용률이 낮아져 자원이 낭비됨
- Hard/Soft 혼재 시 간섭: 한 시스템에 두 유형이 공존할 때 Soft 태스크가 Hard 태스크의 자원을 점유할 위험이 있음
- 검증 비용 증가: Hard 실시간 인증(DO-178C 등)은 테스트·문서화 비용이 전체 개발비의 50% 이상을 차지함

> 요약: WCET 과추정·혼재 간섭·인증 비용이 실시간 시스템 설계의 주요 장애물임

## Ⅴ. 개선방안
1. 단기: 정적 분석 도구(aiT 등)를 활용하여 WCET 추정 정밀도를 높이고 자원 낭비를 줄임
2. 중기: 파티션 스케줄링(ARINC 653)으로 Hard·Soft 태스크 간 시간·공간 격리를 보장함
3. 장기: 모델 기반 검증(UPPAAL 등)을 개발 프로세스에 통합하여 인증 비용을 절감함

> 요약: WCET 정밀화 → 파티션 격리 → 모델 기반 검증 순으로 실시간 설계 품질을 향상함

## Ⅵ. 전망
- 발전 방향: 자율주행 Level 4 이상에서 Hard/Soft 혼합 스케줄링 기술 수요가 증가할 전망임
- 기술사적 판단: 안전 등급별 실시간 요구를 체계적으로 분류하는 역량이 시스템 아키텍트의 핵심 역량이 될 것임
- 기술사 제언: 시스템 설계 초기에 태스크별 실시간 등급을 명확히 정의하여 과잉 설계를 방지할 필요
