## Ⅰ. 개요
- **정의**: 프로세서가 이해하는 명령어 집합(ISA)의 설계 철학을 단순·고정길이(RISC)와 복합·가변길이(CISC)로 구분한 분류임
- **배경/필요성**: 명령어 복잡도가 파이프라인 효율·컴파일러 최적화·소비전력에 영향을 미치므로 설계 방향 선택이 필요함
- **비유**: RISC는 레고 블록(단순 부품 조합), CISC는 완성형 프라모델(복잡 부품 하나로 완성)임

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 두 ISA 철학의 트레이드오프 | 파이프라인 친화성 vs 코드 밀도 | 현대 x86은 외부 CISC-내부 RISC(마이크로옵) 혼합이라는 점 명시 |

> 요약: 명령어 단순화 vs 복합화의 트레이드오프가 ISA 설계의 핵심 쟁점임

## Ⅱ. 구성요소
```text
          +--------- ISA ---------+
          |                       |
     +----+----+            +-----+-----+
     |  RISC   |            |   CISC    |
     +---------+            +-----------+
     | 고정 길이 |            | 가변 길이  |
     | Load/Store|           | Mem-to-Reg |
     | 많은 레지스터|          | 적은 레지스터|
     | HW 파이프  |           | 마이크로코드 |
     +---------+            +-----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 명령어 형식 | RISC: 고정 32비트, CISC: 1~15바이트 가변 | 규격 택배 vs 비규격 화물 |
| 메모리 접근 모델 | RISC: Load/Store만 메모리 접근, CISC: 연산 명령이 메모리 직접 참조 가능 | 창고 전담 인력 vs 다기능 인력 |
| 레지스터 구조 | RISC: 범용 레지스터 32개 이상, CISC: 8~16개로 제한적 | 넓은 작업대 vs 좁은 작업대 |
| 제어 방식 | RISC: 하드와이어드, CISC: 마이크로코드 ROM | 전용 회로 vs 펌웨어 해석 |

> 요약: 명령어 길이·메모리 접근·레지스터 수·제어 방식이 두 철학의 분기점임

## Ⅲ. 절차
```text
  명령 인출       명령 해독         실행           결과 저장
  (Fetch)        (Decode)        (Execute)      (Write-back)
    |               |               |               |
    +--고정/가변---->+--제어 생성---->+--ALU 연산----->+
  RISC:1사이클     RISC:단순해독    RISC:레지스터    공통
  CISC:길이판별    CISC:마이크로옵   CISC:메모리가능  공통
```
- 1단계: 명령어 인출 — RISC는 고정 길이로 정렬 인출, CISC는 가변 길이로 경계 판별이 필요함
- 2단계: 명령어 해독 — RISC는 단일 사이클 해독, CISC는 마이크로옵으로 분해하여 내부 RISC 형태로 변환함
- 3단계: 연산 실행 — RISC는 레지스터 피연산자만 사용, CISC는 메모리 피연산자를 허용하여 추가 접근이 발생함
- 4단계: 결과 저장 — 두 방식 모두 레지스터 또는 메모리에 기록하며, 파이프라인 다음 단계로 전달함

> 요약: 인출·해독 단계의 복잡도 차이가 파이프라인 설계 전략을 결정함

## Ⅳ. 문제점
- [RISC 코드 밀도 저하]: 고정 길이 단순 명령어 — 동일 로직에 더 많은 명령어가 필요하여 I-Cache 미스율이 증가함
- [CISC 파이프라인 비효율]: 가변 길이·복합 명령어 — 파이프라인 스테이지 불균형으로 스톨이 빈번함
- [CISC 전력 소모]: 마이크로코드 해석 회로 — 디코더 면적과 동적 전력이 증가하여 모바일 환경에 불리함

> 요약: RISC는 코드 크기, CISC는 파이프라인 효율·전력에서 각각 약점을 가짐

## Ⅴ. 개선방안
1. 단기: RISC에 압축 명령어 확장(예: RISC-V C-extension, 16비트) 도입으로 코드 밀도를 개선함
2. 중기: CISC 프론트엔드에 마이크로옵 캐시(uop cache) 적용으로 반복 해독 비용을 제거함
3. 장기: CISC 디코더를 전력 게이팅하고 마이크로옵 캐시 히트 시 디코더를 비활성화하여 전력을 절감함

> 요약: 압축 명령어 → 마이크로옵 캐시 → 디코더 전력 게이팅 순으로 각 약점을 보완함

## Ⅵ. 전망
- 발전 방향: 도메인 특화 확장(AI·벡터·암호)이 ISA에 추가되며 RISC/CISC 경계가 희미해지는 추세임
- 기술사적 판단: 서버·PC는 x86(CISC 외형), 모바일·임베디드는 ARM/RISC-V(RISC)로 양분 구도가 지속됨
- 기술사 제언: ISA 선택 시 생태계 성숙도·라이선스 모델·전력 제약을 종합 평가해야 함
