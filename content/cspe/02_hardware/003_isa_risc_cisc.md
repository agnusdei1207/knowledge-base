# 📖 【암기용】 개념 완전 이해

> 목적: RISC와 CISC의 철학 차이와 현대 CPU에서의 융합을 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: CPU가 이해할 수 있는 명령어 세트(ISA)의 설계 방식 차이로, 복잡하게 할지(CISC) 단순하게 할지(RISC)의 대결
- **왜 필요한가**: 초기에는 메모리가 비싸 코드를 짧게 쓰는 CISC가 유리했으나, 이후 하드웨어가 발전하면서 명령어를 단순화해 파이프라이닝을 극대화하는 RISC가 등장했다.
- **핵심 직관**: CISC는 "한 큐에 다 해주는 복합 기능 버튼"이 많은 리모컨이고, RISC는 "기본 버튼 몇 개로 직접 조합"해서 쓰는 심플한 리모컨이다.

## 깊이 이해
- **배경·문제의식**: 1970년대 메모리 용량이 턱없이 부족할 때(x86 탄생 시기)는 어셈블리어 1줄로 복잡한 메모리 연산을 다 끝내야 했다(CISC). 하지만 분석해보니 복잡한 명령어의 20%만 전체 실행 시간의 80%를 차지한다는 규칙(80/20 법칙)이 발견되면서, "자주 쓰는 20%만 하드웨어로 만들고 나머진 소프트웨어로 처리하자"는 RISC 철학이 등장했다.
- **작동 원리**: 
  - **CISC**: 명령어 길이가 가변적이고 종류가 수백 개다. "메모리에 있는 A와 B를 더해 C에 넣어라" 같은 명령이 1개로 끝난다.
  - **RISC**: 명령어 길이가 고정적이고 기능이 단순하다. "메모리에서 읽어라(Load)", "더해라", "메모리에 써라(Store)"로 쪼개야 한다(Load-Store 아키텍처). 대신 파이프라인 처리가 아주 쉽고 빠르다.
- **비유**: 
  - CISC: 햄버거 세트, 치킨 세트 등 완성된 복합 메뉴가 많은 식당. 메뉴판이 두껍지만 주문은 빠름.
  - RISC: 패티 1개, 빵 1개 등 단품만 파는 식당. 주문자가 빵, 패티, 소스를 따로 주문해 합쳐야 함(컴파일러 최적화). 단 주방 회전율(파이프라인)은 극상.
- **구체 예시**: Intel/AMD CPU(x86)는 CISC 방식을, Apple Silicon(M시리즈)과 모바일 칩(ARM)은 RISC 방식을 쓴다.
- **흔한 오해·주의점**: "인텔 CPU는 CISC라서 느리다"는 틀린 말이다. 현대 인텔 CPU는 겉(ISA)은 CISC지만 속(내부 하드웨어 디코더)은 이를 RISC 형태의 마이크로 오퍼레이션(Micro-ops)으로 쪼개서 실행하는 융합 아키텍처(CRISC)를 쓴다.

## 연결 개념
- 컴파일러 최적화 — RISC에서는 소프트웨어가 단순 명령어를 효율적으로 조합해야 하므로 컴파일러의 역할이 매우 큼
- 하드웨어 디코더 — CISC 명령어를 RISC처럼 잘게 쪼개는 내부 회로
- 명령어 파이프라이닝 — RISC가 단순하고 고정된 길이를 선택한 궁극적 이유

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: RISC와 CISC는 프로세서가 제공하는 명령어 집합(ISA)의 복잡도와 하드웨어-소프트웨어 간 역할 분담을 결정하는 아키텍처 설계 철학이다.
> 2. **가치**: CISC는 컴파일러의 부담과 코드 길이를 줄였고, RISC는 고정 길이 단순 명령어로 하드웨어 파이프라이닝과 고클럭 달성에 기여했다.
> 3. **판단 포인트**: 현대 프로세서는 순수 CISC나 RISC가 존재하지 않으며, CISC 명령어 외부 인터페이스에 RISC 내부 실행 엔진을 결합한 하이브리드(CRISC) 구조로 수렴했다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 프로세서 명령어 아키텍처 발전 흐름 이해 | Load-Store 구조(RISC), 80/20 법칙, 파이프라인 친화성, CRISC 융합 | 단순히 명령어 개수 차이만 적고 Load-Store 메모리 접근 방식의 차이를 누락 |

> 요약: RISC의 단순화가 컴파일러 최적화와 하드웨어 파이프라인 성능 향상으로 이어지는 메커니즘을 명시해야 한다.

---

## Ⅰ. 개요 및 필요성

- 정의: 하드웨어 의존도를 높여 복잡성을 감당하는 CISC와, 명령어 단순화로 파이프라인 효율을 극대화하는 RISC ISA 비교
- 배경: 제한된 메모리와 컴파일러 한계로 CISC가 주도했으나, 80/20 법칙 발견과 VLSI 기술 발전으로 RISC가 부상
- 필요성: 모바일/서버 환경의 전력 효율(Performance per Watt)과 클럭 주파수 한계 돌파를 위한 ISA 선택 기준

---

## Ⅱ. 구조 및 구성요소

```text
[ISA 처리 철학 구조]
- CISC: 고급 언어 -> (단순한 컴파일러) -> 복잡한 가변 명령어(메모리 직접 연산) -> 하드웨어 직접 해석
- RISC: 고급 언어 -> (복잡한 컴파일러) -> 단순 고정 명령어(Load-Store 전용) -> 고속 파이프라인
```

| 구성요소 | CISC 접근 방식 | RISC 접근 방식 |
|:---|:---|:---|
| 명령어 길이 | 가변 길이 (1~15바이트) | 고정 길이 (주로 32비트) |
| 메모리 접근 | 모든 명령어가 메모리 직접 연산 가능 | Load, Store 명령어만 메모리 접근 가능 |
| 레지스터 수 | 상대적으로 적음 (메모리 중심 연산) | 매우 많음 (메모리 접근 최소화) |
| 하드웨어 제어 | 마이크로 프로그래밍(ROM) 복잡 제어 | 하드와이어드(Hardwired) 제어로 단순/고속화 |

> 요약: CISC는 명령어 수가 적어 메모리 사용량이 적고, RISC는 메모리 접근을 Load-Store로 제한하여 하드웨어를 단순화했다.

---

## Ⅲ. 동작원리 및 흐름도

```text
[CISC vs RISC 덧셈 연산 처리 흐름 비교]
- CISC 처리: 메모리 1번지와 2번지 값을 더해 메모리 3번지에 저장 (1개 명령어)
  `ADD [Mem3], [Mem1], [Mem2]` -> 디코딩 병목 발생

- RISC 처리: Load -> Load -> 연산 -> Store (4개 명령어)
  `LOAD R1, [Mem1]` -> `LOAD R2, [Mem2]` -> `ADD R3, R1, R2` -> `STORE [Mem3], R3` -> 파이프라인 최적화
```

| 단계 | CISC 처리 흐름 (마이크로코드 기반) | RISC 처리 흐름 (하드와이어드 기반) |
|:---:|:---|:---|
| 1 | 길이가 다른 명령어 인출 (IF 지연 발생) | 고정 길이 명령어 고속 인출 |
| 2 | 복잡한 마이크로코드 해독 (디코더 복잡) | 단순 하드와이어드 즉시 해독 |
| 3 | 메모리 피연산자 직접 인출하여 연산 | 레지스터 데이터만 ALU에서 1사이클 내 연산 |
| 4 | 연산 결과를 메모리에 직접 저장 (클럭 가변) | 결과를 우선 레지스터에 저장 후 비동기 Store |

> 요약: CISC는 메모리 의존성이 높아 사이클(CPI) 예측이 어렵고, RISC는 메모리를 분리하여 1사이클 실행(CPI=1)을 목표로 한다.

## Ⅳ. 심화 비교: CISC vs RISC

| 비교 축 | CISC (Complex Instruction Set) | RISC (Reduced Instruction Set) | 판단 포인트 |
|:---|:---|:---|:---|
| 파이프라이닝 | 명령어 길이가 다르고 복잡해 비효율적 | 고정 길이 및 1사이클 실행으로 최고 효율 | 처리량(Throughput) 극대화 |
| 코드 크기 | 복합 명령어로 실행 파일 크기 작음 | 명령어 개수가 많아 파일 크기 팽창 | 메모리 병목 시대의 선택 |
| 전력 소모 | 복잡한 트랜지스터 디코딩 회로로 높음 | 단순 회로로 저전력 고효율 (Performance/Watt) | 폼팩터(모바일/서버) 적합성 |
| 대표 아키텍처 | Intel x86, AMD64 | ARM, RISC-V, MIPS | 하위 호환성 vs 신규 생태계 |

> 요약: RISC의 단순함은 모바일 전력 효율과 고속 파이프라이닝에서 압도적 우위를 점하여 현대 ISA의 주류가 되었다.

---

## Ⅴ. 현대적 적용 판단: 하이브리드 아키텍처 (CRISC)

| 해결 과제 | 전통적 ISA의 한계 | 현대 CPU의 융합 전략 (CRISC) |
|:---|:---|:---|
| 하위 호환성 (CISC 한계) | x86은 과거 S/W 호환성 때문에 ISA 변경 불가 | 외부 ISA는 CISC로 유지 (호환성 보장) |
| 파이프라인 한계 (CISC 한계) | 복잡한 디코딩으로 인한 파이프라인 정체 | 내부 하드웨어에 Micro-Op 디코더 탑재 |
| 실행 최적화 (RISC 장점 수용) | CISC 명령의 비효율적 실행 주기 | 해독된 쪼개진 명령을 RISC 코어(OoO)에서 고속 실행 |

> 요약: 현대 인텔/AMD 프로세서는 외부적으로 CISC ISA를 쓰지만, 내부는 RISC 스타일의 마이크로 오퍼레이션으로 쪼개어 비순차 실행(OoO)하는 융합(CRISC) 아키텍처다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 디코딩 지연 | 마이크로 오퍼레이션 캐시(uOP Cache) 적중률 90% | 성능 카운터 분석 |
| 파이프라인 CPI | 평균 1.0~1.2 수준 통제 | 사이클 시뮬레이터 |
| 전력 당 성능 | 와트당 명령어 처리율 최적화 | 전력 프로파일링(TDP) |

> 요약: 융합 구조는 마이크로 오퍼레이션 캐시 등을 통해 디코딩 오버헤드를 줄이고 전력 효율을 높인다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. ARM 모바일/클라우드 전환: 모바일 생태계(Apple M시리즈)와 AWS Graviton 등 클라우드 서버에 전력 효율이 높은 RISC 기반 ARM 아키텍처 도입 확산
2. 오픈소스 ISA 적용: IoT, 임베디드, 커스텀 가속기 칩 설계 시 로열티가 없는 RISC-V 개방형 아키텍처를 도입하여 원가 절감 및 커스터마이징 수행
3. 컴파일러 고도화 적용: RISC 환경에서는 명령어 재배치, 루프 언롤링 등을 통한 컴파일러의 스케줄링(Instruction Scheduling) 역량이 성능의 핵심이므로 LLVM 등 최적화 체인 구축

**결론 (2줄):**
- 기술사 판단: 순수 CISC와 RISC의 경계는 무너졌으며, 레거시 호환이 중요한 PC 시장은 CRISC로, 전력과 커스텀 효율이 중요한 모바일·클라우드 시장은 ARM/RISC-V 계열로 양분되었다.
- 향후 방향: 앞으로의 아키텍처는 ISA 차이보다는 NPU 통합, HBM(고대역폭 메모리) 적용, 칩렛(Chiplet) 패키징 등 데이터 전송 병목을 푸는 시스템 레벨 설계로 무게중심이 이동하고 있다.
