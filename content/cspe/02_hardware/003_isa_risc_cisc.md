# 📖 【암기용】 개념 완전 이해

> 목적: RISC와 CISC가 갈린 역사적 이유(80/20 관찰)와 실제 명령어 인코딩·CPI 수치 차이를 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: **명령어 집합 구조(ISA, Instruction Set Architecture)**는 소프트웨어와 하드웨어를 잇는 인터페이스 규약이며, 이를 복잡한 명령어로 설계하는 **CISC(Complex Instruction Set Computer)**와 단순한 명령어로 설계하는 **RISC(Reduced Instruction Set Computer)**로 나뉜다.
- **왜 필요한가**: 1970년대에는 메모리가 비싸 코드를 짧게 만드는 CISC가 유리했지만, 실측 결과 복잡한 명령어의 대부분이 거의 안 쓰인다는 사실이 드러나면서 "자주 쓰는 것만 하드웨어로, 나머지는 소프트웨어 조합으로" 처리하는 RISC 철학이 등장했다.
- **핵심 직관**: CISC는 "한 버튼에 다 해주는 복합 기능"이 많은 리모컨이고, RISC는 "기본 버튼 몇 개를 조합"해서 쓰는 단순한 리모컨이다.

## 핵심 용어 정리

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| ISA(명령어 집합 구조) | CPU가 이해하는 명령어의 종류·형식·인코딩 전체 — 소프트웨어가 하드웨어를 부르는 약속 | 리모컨의 버튼 배치와 기능표 |
| CISC | 명령어 1개가 복잡한 동작(메모리 직접 연산 등)까지 처리하도록 설계한 ISA | 복합 기능 버튼이 많은 리모컨 |
| RISC | 명령어를 단순·고정 길이로 줄이고, 복잡한 동작은 명령어 여러 개 조합으로 처리하는 ISA | 기본 버튼만 있는 리모컨 |
| Load-Store 구조 | 연산은 레지스터끼리만 하고, 메모리 접근은 Load(읽기)·Store(쓰기) 명령어로만 하는 RISC 원칙 | 재료(메모리)는 냉장고에서 꺼내(Load)와야 요리(연산)할 수 있음 |
| 마이크로코드(Microcode) | 복잡한 CISC 명령어 1개를 내부적으로 여러 단계 제어 신호로 풀어주는 ROM 기반 제어 방식 | 복합 버튼을 누르면 내부에서 순서대로 여러 동작을 실행하는 매뉴얼 |
| 하드와이어드 제어(Hardwired Control) | 제어 신호를 회로로 직접 구현해 마이크로코드 해석 없이 즉시 실행하는 방식(RISC가 선호) | 버튼을 누르면 바로 반응하는 물리 스위치 |
| CPI(Cycles Per Instruction) | 명령어 1개를 처리하는 데 드는 평균 클럭 수 | 제품 1개를 만드는 데 걸리는 평균 공정 수 |
| 마이크로 오퍼레이션(Micro-op, μop) | 현대 CISC(x86) 내부에서 복잡한 명령어를 잘게 쪼갠 RISC 스타일 실행 단위 | 세트 메뉴를 주방에서 단품 조리 단계로 다시 쪼갠 것 |

## 깊이 이해

### 80/20 관찰 — RISC가 등장한 실제 이유
- 1970년대 IBM 801 프로젝트(John Cocke, 1975년경)와 이후 여러 연구에서 실제 컴파일된 프로그램을 분석한 결과, CISC가 제공하는 수백 개의 명령어 중 소수의 단순 명령어(load, store, add, branch 등)가 전체 실행 시간의 대부분을 차지하고, 복잡한 주소지정 방식이나 특수 명령어는 컴파일러가 거의 쓰지 않는다는 사실이 드러났다.
- 즉 "명령어 종류를 늘려 코드를 짧게 만드는 것"보다 "자주 쓰는 소수의 명령어를 하드웨어에서 최대한 빠르게 도는 것"이 전체 성능에 더 이득이라는 결론이었고, 이 관찰이 1980년 UC 버클리(Patterson)·스탠퍼드(Hennessy)의 RISC 연구로 이어졌다.

### 명령어 길이와 코드 밀도 — 수치로 비교
- CISC(x86)는 명령어 길이가 1바이트~15바이트로 가변적이다(접두사·오퍼랜드 수에 따라 달라짐). RISC(RISC-V, ARM)는 기본적으로 명령어 길이가 32비트(4바이트)로 고정이다.
- **워크드 예제**: 메모리 주소 A, B의 값을 더해 C에 저장하는 연산(`C = A + B`)을 각각 구현하면:
  - CISC(x86 스타일, 레지스터-메모리 연산 지원): `MOV EAX, [A]` → `ADD EAX, [B]` → `MOV [C], EAX` — 명령어 3개, 각 2~6바이트로 총 약 10바이트 안팎.
  - RISC(RV32I): `LW x1, 0(x10)` → `LW x2, 0(x11)` → `ADD x3, x1, x2` → `SW x3, 0(x12)` — 명령어 4개, 고정 4바이트씩 총 16바이트.
  - CISC가 바이트 수는 더 작지만(코드 밀도 우위), RISC는 모든 명령어가 고정 길이·레지스터 간 연산이라 파이프라인 각 단계가 항상 1클럭으로 끝나 처리 속도(CPI)에서 우위를 가진다.

### CPI로 보는 RISC의 설계 목표
- CISC는 명령어 1개가 메모리 접근·복잡한 주소 계산까지 포함해 마이크로코드로 여러 단계를 거치므로, 명령어별 CPI가 명령어 종류에 따라 크게 흔들린다(단순 명령어는 1~2클럭, 복잡한 명령어는 여러 클럭에서 십수 클럭까지).
- RISC는 모든 명령어를 "레지스터 대 레지스터" 연산 + 고정 길이로 제한해, 하드와이어드 제어로 이상적인 CPI를 1에 최대한 근접시키는 것을 설계 목표로 삼는다. 메모리 접근은 오직 Load/Store 명령어에만 있어, 그 외 연산 명령어는 메모리 지연을 기다릴 필요가 없다.

### 현대 CPU의 융합 — CISC 겉모습, RISC 속모습
- 현대 x86(Intel/AMD) CPU는 하위 호환성 때문에 겉으로 보이는 ISA는 여전히 CISC지만, 내부 디코더가 복잡한 CISC 명령어를 여러 개의 단순한 마이크로 오퍼레이션(μop)으로 즉시 쪼갠 뒤, 그 μop들을 RISC 스타일의 비순차 실행(Out-of-Order) 파이프라인에서 처리한다.
- 이 방식(흔히 CRISC라 부름) 덕분에 x86은 기존 소프트웨어 호환성을 유지하면서도, 실제 실행 엔진 내부에서는 RISC가 얻는 파이프라인 이점을 대부분 확보한다.

### 흔한 오해
- "x86은 CISC라서 느리다" — 틀렸다. 내부 실행 엔진이 RISC화돼 있어 성능 차이는 ISA 자체보다 마이크로아키텍처(코어 설계)·공정 미세화·전력 예산에서 더 크게 갈린다.
- "RISC는 명령어가 적어서 할 수 있는 게 적다" — 틀렸다. 복잡한 동작은 단순 명령어 여러 개의 조합(컴파일러가 자동 생성)으로 똑같이 구현되며, 다만 그 조합·최적화 책임이 하드웨어에서 컴파일러로 넘어간 것이다.

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: RISC와 CISC는 프로세서가 제공하는 명령어 집합(ISA)의 복잡도와 하드웨어-소프트웨어 간 역할 분담을 결정하는 아키텍처 설계 철학이다.
> 2. **가치**: CISC는 컴파일러의 부담과 코드 길이를 줄였고, RISC는 고정 길이 단순 명령어로 하드웨어 파이프라이닝과 고클럭 달성에 기여했다.
> 3. **판단 포인트**: 현대 프로세서는 순수 CISC나 RISC가 존재하지 않으며, CISC 명령어 외부 인터페이스에 RISC 내부 실행 엔진을 결합한 하이브리드(CRISC) 구조로 수렴했다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 프로세서 명령어 아키텍처 발전 흐름 이해 | Load-Store 구조(RISC), 80/20 법칙, 파이프라인 친화성, CRISC 융합 | 단순히 명령어 개수 차이만 적고 Load-Store 메모리 접근 방식의 차이를 누락 |

> 요약: RISC의 단순화가 컴파일러 최적화와 하드웨어 파이프라인 성능 향상으로 이어지는 메커니즘을 명시해야 한다.

## Ⅰ. 개요 및 필요성

- 정의: 하드웨어 의존도를 높여 복잡성을 감당하는 CISC와, 명령어 단순화로 파이프라인 효율을 극대화하는 RISC ISA 비교
- 배경: 제한된 메모리와 컴파일러 한계로 CISC가 주도했으나, 80/20 법칙 발견과 VLSI 기술 발전으로 RISC가 부상
- 필요성: 모바일/서버 환경의 전력 효율(Performance per Watt)과 클럭 주파수 한계 돌파를 위한 ISA 선택 기준

## Ⅱ. 구조 및 구성요소

```text
[ISA 처리 철학 구조]
- CISC: 고급 언어 -> (단순한 컴파일러) -> 복잡한 가변 명령어(메모리 직접 연산) -> 하드웨어 직접 해석
- RISC: 고급 언어 -> (복잡한 컴파일러) -> 단순 고정 명령어(Load-Store 전용) -> 고속 파이프라인
```

| 구성요소 | CISC 접근 방식 | RISC 접근 방식 |
|:---|:---|:---|
| 명령어 길이 | 가변 길이 (1~15바이트) | 고정 길이 (주로 32비트) |
| 메모리 접근 | 모든 명령어가 메모리 직접 연산 가능 | Load, Store 명령어만 메모리 접근 가능 |
| 레지스터 수 | 상대적으로 적음 (메모리 중심 연산) | 매우 많음 (메모리 접근 최소화) |
| 하드웨어 제어 | 마이크로 프로그래밍(ROM) 복잡 제어 | 하드와이어드(Hardwired) 제어로 단순/고속화 |

> 요약: CISC는 명령어 수가 적어 메모리 사용량이 적고, RISC는 메모리 접근을 Load-Store로 제한하여 하드웨어를 단순화했다.

## Ⅲ. 동작원리 및 흐름도

```text
[CISC vs RISC 덧셈 연산 처리 흐름 비교]
- CISC 처리: 메모리 1번지와 2번지 값을 더해 메모리 3번지에 저장 (1개 명령어)
  `ADD [Mem3], [Mem1], [Mem2]` -> 디코딩 병목 발생

- RISC 처리: Load -> Load -> 연산 -> Store (4개 명령어)
  `LOAD R1, [Mem1]` -> `LOAD R2, [Mem2]` -> `ADD R3, R1, R2` -> `STORE [Mem3], R3` -> 파이프라인 최적화
```

| 단계 | CISC 처리 흐름 (마이크로코드 기반) | RISC 처리 흐름 (하드와이어드 기반) |
|:---:|:---|:---|
| 1 | 길이가 다른 명령어 인출 (IF 지연 발생) | 고정 길이 명령어 고속 인출 |
| 2 | 복잡한 마이크로코드 해독 (디코더 복잡) | 단순 하드와이어드 즉시 해독 |
| 3 | 메모리 피연산자 직접 인출하여 연산 | 레지스터 데이터만 ALU에서 1사이클 내 연산 |
| 4 | 연산 결과를 메모리에 직접 저장 (클럭 가변) | 결과를 우선 레지스터에 저장 후 비동기 Store |

> 요약: CISC는 메모리 의존성이 높아 사이클(CPI) 예측이 어렵고, RISC는 메모리를 분리하여 1사이클 실행(CPI=1)을 목표로 한다.

## Ⅳ. 심화 비교: CISC vs RISC

| 구분 | CISC (Complex Instruction Set) | RISC (Reduced Instruction Set) | 판단 포인트 |
|:---|:---|:---|:---|
| 파이프라이닝 | 명령어 길이가 다르고 복잡해 비효율적 | 고정 길이 및 1사이클 실행으로 최고 효율 | 처리량(Throughput) 극대화 |
| 코드 크기 | 복합 명령어로 실행 파일 크기 작음 | 명령어 개수가 많아 파일 크기 팽창 | 메모리 병목 시대의 선택 |
| 전력 소모 | 복잡한 트랜지스터 디코딩 회로로 높음 | 단순 회로로 저전력 고효율 (Performance/Watt) | 폼팩터(모바일/서버) 적합성 |
| 대표 아키텍처 | Intel x86, AMD64 | ARM, RISC-V, MIPS | 하위 호환성 vs 신규 생태계 |

> 요약: RISC의 단순함은 모바일 전력 효율과 고속 파이프라이닝에서 압도적 우위를 점하여 현대 ISA의 주류가 되었다.

## Ⅴ. 현대적 적용 판단: 하이브리드 아키텍처 (CRISC)

| 해결 과제 | 전통적 ISA의 한계 | 현대 CPU의 융합 전략 (CRISC) |
|:---|:---|:---|
| 하위 호환성 (CISC 한계) | x86은 과거 S/W 호환성 때문에 ISA 변경 불가 | 외부 ISA는 CISC로 유지 (호환성 보장) |
| 파이프라인 한계 (CISC 한계) | 복잡한 디코딩으로 인한 파이프라인 정체 | 내부 하드웨어에 Micro-Op 디코더 탑재 |
| 실행 최적화 (RISC 장점 수용) | CISC 명령의 비효율적 실행 주기 | 해독된 쪼개진 명령을 RISC 코어(OoO)에서 고속 실행 |

> 요약: 현대 인텔/AMD 프로세서는 외부적으로 CISC ISA를 쓰지만, 내부는 RISC 스타일의 마이크로 오퍼레이션으로 쪼개어 비순차 실행(OoO)하는 융합(CRISC) 아키텍처다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 디코딩 지연 | 마이크로 오퍼레이션 캐시(uOP Cache) 적중률 90% | 성능 카운터 분석 |
| 파이프라인 CPI | 평균 1.0~1.2 수준 통제 | 사이클 시뮬레이터 |
| 전력 당 성능 | 와트당 명령어 처리율 최적화 | 전력 프로파일링(TDP) |

> 요약: 융합 구조는 마이크로 오퍼레이션 캐시 등을 통해 디코딩 오버헤드를 줄이고 전력 효율을 높인다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. ARM 모바일/클라우드 전환: 모바일 생태계(Apple M시리즈)와 AWS Graviton 등 클라우드 서버에 전력 효율이 높은 RISC 기반 ARM 아키텍처 도입 확산
2. 오픈소스 ISA 적용: IoT, 임베디드, 커스텀 가속기 칩 설계 시 로열티가 없는 RISC-V 개방형 아키텍처를 도입하여 원가 절감 및 커스터마이징 수행
3. 컴파일러 고도화 적용: RISC 환경에서는 명령어 재배치, 루프 언롤링 등을 통한 컴파일러의 스케줄링(Instruction Scheduling) 역량이 성능의 핵심이므로 LLVM 등 최적화 체인 구축

**결론 (2줄):**
- 기술사 판단: 순수 CISC와 RISC의 경계는 무너졌으며, 레거시 호환이 중요한 PC 시장은 CRISC로, 전력과 커스텀 효율이 중요한 모바일·클라우드 시장은 ARM/RISC-V 계열로 양분되었다.
- 향후 방향: 앞으로의 아키텍처는 ISA 차이보다는 NPU 통합, HBM(고대역폭 메모리) 적용, 칩렛(Chiplet) 패키징 등 데이터 전송 병목을 푸는 시스템 레벨 설계로 무게중심이 이동하고 있다.
