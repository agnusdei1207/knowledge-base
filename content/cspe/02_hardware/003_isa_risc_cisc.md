# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: **명령어 집합 구조(ISA)**의 두 설계 철학으로, 명령어 하나의 복잡성을 하드웨어(CISC)가 감당하느냐 소프트웨어·컴파일러(RISC)가 감당하느냐로 갈린다.
- **왜 필요한가**: 기계어의 길이·메모리 접근 규약이 CPU의 디코딩 복잡도, 파이프라인 병렬 처리 한계, 전력 효율을 결정하기 때문이다.
- **핵심 직관**: CISC는 "이것들 전부 곱해서 저기에 저장해"라는 길고 복잡한 한 문장이고, RISC는 "읽어와 / 곱해 / 저장해"를 짧은 세 문장으로 쪼개 빠르게 지시하는 방식이다.

## 핵심 용어 정리 (내부에 등장하는 것들)
CU·레지스터·파이프라인 등 CPU 내부 배경은 002·007에서 다뤘으므로, 여기서는 ISA 설계 용어를 중심으로 정리한다. 맨 위 세 줄이 상위 핵심 키워드다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| **ISA (명령어 집합 구조)** | CPU 하드웨어가 이해·실행하는 명령어의 표준 명세(하드웨어-소프트웨어 계약) | 건물을 짓기 위한 공용 설계 규약 |
| **CISC (Complex)** | 명령어 1개가 메모리 접근+연산까지 포함하는 가변 길이 복합 구조 | 스위스 아미 나이프(다기능 복합 도구) |
| **RISC (Reduced)** | 단순·고정 길이 명령어만 두고 복잡한 일은 조합으로 해결하는 구조 | 단순 레고 블록 |
| **가변 길이 / 고정 길이** | 명령어 바이트 수가 제각각(CISC 1~15B)인지 일정(RISC 4B)인지 | 문장 길이가 들쭉날쭉 vs 항상 같음 |
| **Load-Store 아키텍처** | 연산은 레지스터로만 하고, 메모리는 오직 Load/Store 명령으로만 접근 | 창고에서 꺼내 작업대에서만 가공하고 다시 넣음 |
| **하드와이어드 / 마이크로코드** | 논리회로로 즉시 해독(하드와이어드) vs ROM의 다단 절차로 해독(마이크로코드) | 반사적 동작 vs 두꺼운 매뉴얼을 넘겨보며 실행 |
| **마이크로 오퍼레이션 (Micro-ops)** | CISC 명령어를 내부에서 잘게 쪼갠 RISC형 저수준 명령 | 긴 요리법을 손동작 단위로 쪼갠 지시서 |
| **파이프라인 / CPI** | 명령어를 겹쳐 흘리는 기법(007 참조), 명령어당 사이클 수(CPI) | 컨베이어 라인, 접시 하나당 시간 |
| **ILP / 슈퍼스칼라** | 명령어 수준 병렬성, 이를 위해 한 사이클에 여러 명령을 발급하는 구조 | 여러 라인을 동시에 가동 |
| **코드 밀도 (Code Density)** | 같은 기능을 담는 데 필요한 바이너리 크기(작을수록 밀도 높음) | 짐을 얼마나 압축해 실었나 |
| **전성비 (Perf/Watt)** | 소비 전력 대비 성능 | 연비(같은 기름으로 얼마나 가나) |

## 깊이 이해
- **배경·문제의식**: 1970년대엔 메모리가 비싸고 컴파일러가 약했다. 그래서 어셈블리 한 줄이 메모리 연산까지 다 해내는(코드 밀도 높은) CISC(x86)가 주류였다. 그러나 1980년대 파이프라이닝이 등장하자 "명령어 길이가 제각각이면 다음 명령어가 어디서 시작하는지 몰라 겹쳐 실행이 막힌다"는 치명적 문제가 드러났다. 이를 피하려 "자주 쓰는 단순 명령만 고정 길이로 하드웨어에 넣고, 복잡한 일은 레지스터 안에서 빠르게 조합하자"는 RISC(ARM·MIPS) 철학이 나왔다.
- **작동 원리 (어떻게+왜)**:
  - **CISC**: 명령어가 1~15바이트로 가변적이고, 한 줄을 수십 클럭짜리 마이크로코드로 해석해 메모리를 직접 오간다. 디코더가 무거워 칩 면적을 크게 차지한다.
  - **RISC**: 명령어 폭이 고정(예: 32비트)이라 하드와이어드 로직으로 1클럭에 해독된다. 메모리는 Load/Store로만 접근하고 연산은 레지스터 안에서만 해서(Load-Store) 파이프라인 충돌이 적다.
- **비유**: CISC 드럼세탁기는 버튼 하나로 "세탁-탈수-건조"가 다 되지만 내부 기계가 무겁고 복잡하다. RISC는 세탁기·탈수기·건조기를 따로 둬 사용자가 순서대로 넣어야 하지만(컴파일러 부담↑), 각 기계가 가벼워 줄지어(파이프라인) 처리하기 매우 빠르다.
- **구체 예시**: 메모리 변수 A에 B를 곱할 때, CISC는 `MULT MemA, MemB` 한 줄이지만 내부에서 메모리를 오가며 지연된다. RISC는 `LOAD R1,MemA` / `LOAD R2,MemB` / `MULT R1,R2` / `STORE MemA,R1` 네 줄이지만 레지스터에서 즉시 수행해 파이프라인·ILP 효율이 높다.
- **흔한 오해·주의점**: RISC와 CISC를 지금도 대립하는 흑백논리로 보면 안 된다. 현대 x86(CISC)은 겉으론 호환성을 위해 CISC 기계어를 받지만, 칩 내부 디코더가 이를 Micro-ops(RISC형)로 쪼개 실행한다. ARM(RISC)도 명령어를 늘리며 덩치가 커져, 양 진영은 "최적화"라는 이름 아래 사실상 수렴(Convergence)하는 중이다.

## 연결 개념
- 002. CPU 구성 (CU가 이 명령어를 해독함) / 007. 파이프라이닝 (RISC가 최적화하는 대상)
- 004. RISC-V 오픈 ISA (RISC 철학의 개방형 구현)
- 010. 슈퍼스칼라 (한 클럭에 여러 명령을 발급하는 ILP 확장)

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 명령어 처리의 무게 중심을 하드웨어 제어 복잡도(CISC)에 둘지 컴파일러 스케줄링(RISC)에 둘지 정하는 ISA 설계 철학
> 2. **가치**: RISC의 고정 길이 Load-Store 구조는 1클럭 해독과 디코더 경량화로 모바일·클라우드 전성비 시장을 석권
> 3. **판단 포인트**: 현대 범용 CPU는 x86 호환성을 유지하되 내부는 Micro-ops로 쪼개 RISC 파이프라인 효율을 취하는 하이브리드로 진화

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 명령어 설계 철학과 파이프라인 적합성 차이 판단 확인 | 가변/고정 길이 디코딩 차이, Load-Store 접근 원리 | PC/모바일 이분법 나열 후 구조적 차이 누락 |
| 현대 마이크로아키텍처의 융합 구조 이해 확인 | CISC의 RISC화(Micro-ops 변환), 하이브리드 수렴 | 둘이 여전히 완전 별개로 독자 발전한다는 단정 |

> 요약: RISC·CISC의 구조 차이(가변/고정, 디코더 무게)를 대조하고, 현대 설계가 파이프라인 대역폭을 위해 어떻게 수렴하는지 제시함.

---

## Ⅰ. 개요 및 필요성

- 개요: ISA는 하드웨어-소프트웨어 간 명령어 규약이며, RISC는 축소·고정, CISC는 복합·가변 명령어를 채택
- 배경: 초기엔 메모리 절약을 위해 코드 밀도 높은 CISC가 주류였으나, 파이프라이닝 등장 시 가변 길이의 해독 지연 병목이 표면화
- 필요성: 매 클럭 1명령어 인출·해독(CPI 1.0 접근)과 슈퍼스칼라 다중 발급을 위해 제어를 단순화한 RISC 도입 대두

---

## Ⅱ. 구조 및 구성요소

```text
[CISC] 가변길이 명령어 -> 마이크로코드 ROM -> 멀티사이클 디코더 -> 메모리 직접 연산
[RISC] 고정길이 명령어 -> 하드와이어드 로직 -> 1사이클 해독 -> 레지스터 한정 연산
     / 현대 수렴: CISC 기계어 -> 내부 디코더 -> Micro-ops(RISC형)로 변환 -> 실행
```

| 설계 | 제어(CU) 방식 | 메모리 접근 구조 |
|:---|:---|:---|
| CISC (x86) | 마이크로코드 기반 다단 디코딩 | 명령어에서 메모리 직접 조작(연산+접근 동시) 허용 |
| RISC (ARM·RISC-V) | 하드와이어드 논리회로로 즉시 디코딩 | 연산은 레지스터로 격리, 메모리는 Load/Store로만 |

> 요약: CISC는 무거운 마이크로코드 ROM으로 실리콘을 쓰고, RISC는 풍부한 레지스터와 하드와이어드 로직으로 파이프라인 지연을 방지함.

---

## Ⅲ. 동작원리 및 흐름도

```text
[RISC Load-Store 파이프라인 흐름]
컴파일러 분해 -> 고정 명령어 인출 -> 1클럭 하드와이어 해독 -> 레지스터 한정 연산 -> Store로 메모리 반영
```

- 1단계 [코드 분해]: 컴파일러가 복합 연산을 다수의 단순 Load·ALU·Store로 쪼개고 데이터 해저드를 우회 스케줄링
- 2단계 [인출·해독]: 폭이 고정된 명령어(예: 32비트)를 인출해 복잡한 해석 없이 1클럭에 하드와이어드 해독
- 3단계 [실행]: 메모리 지연을 배제하고 CPU 내부 범용 레지스터 값만으로 산술·논리 연산을 1사이클에 완료
- 4단계 [기록]: 결과를 레지스터에 쓰거나 별도 Store 명령으로 메모리에 전송해 접근 지연을 격리

> 요약: RISC는 메모리 접근을 Load/Store로 격리하고 연산을 1사이클에 끝내 파이프라인 불확실성을 통제함.

---

## Ⅳ. 특징 (설계 트레이드오프)

- 코드 밀도: CISC는 복합 지시로 바이너리가 작고, RISC는 단순 명령을 나열해 코드·I-Cache를 20~30% 더 차지함
- 디코딩 대역폭: CISC 가변 길이는 다음 명령어 위치 예측이 어려워 슈퍼스칼라 확장 시 디코더 면적·발열이 급증함(디코더 병목)
- 전성비(Perf/Watt): RISC는 마이크로코드 ROM을 걷어내 다이 크기를 줄이고 모바일의 누설 전력·발열을 극소화함(ARM 장악)

---

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | CISC (Intel x86) | RISC (ARM·RISC-V) | 선택·도입 기준 |
|:---|:---|:---|:---|
| 명령어 길이 | 가변(1~15B) | 고정(기본 4B) | 파이프라인 프론트엔드 폭 확장 용이성 |
| 파이프라인 | 디코딩 지연 발생 | 단일 클럭 해독 용이 | 슈퍼스칼라 ILP 확보 임계치 |
| 최적화 무게 중심 | 하드웨어(마이크로코드) | 소프트웨어(컴파일러) | 자체 컴파일러 튜닝 권한·생태계 통제 |

> 요약: 방대한 데스크톱 호환성이 필요한 곳은 CISC를, 전력 제약이 심한 모바일·대규모 클라우드는 RISC를 도입함.

**리스크·대응:**
- [CISC 슈퍼스칼라 병목]: 가변 길이 해독으로 다중 발급 정체 → 디코딩 후단에 Micro-ops 변환기 탑재(지표: 디코더 유발 스톨 사이클 %)
- [RISC 코드 팽창]: 명령어 단순화로 코드 라인·I-Cache 점유 증가 → Thumb-2·RISC-V C(압축) 명령어 셋 지원(지표: I-Cache 미스율 5% 이내)

**도입 후 점검 지표:**
- 분기 예측 적중률: 95% 이상 유지 — SPECint 분기 트레이스 분석
- CPI: 목표 workload에서 1.0 근접 여부 — 성능 카운터 측정

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 하이브리드 전환(x86 진화): 데스크톱은 겉을 CISC 기계어로 유지해 하위 호환성을 수용하고, 내부는 Micro-ops 쪼개기로 RISC 파이프라인을 구성해 병목 회피
2. 클라우드 전력 최적화(AWS Graviton): 하이퍼스케일러가 전성비 높은 ARM 커스텀 칩을 도입해 동일 랙에서 연산 밀도를 높이고 TCO 절감
3. 오픈 ISA 커스텀(RISC-V): 로열티 없는 개방형 ISA의 모듈 구조로 IoT 컨트롤러·AI 가속기 명령어를 자체 정의해 라이선스 비용 제거

**결론 (2줄):**
- 기술사 판단: 순수 CISC는 디코더 복잡도로 한계에 도달했고, 현재 설계는 해독부를 가볍게 해 그 실리콘 여유를 캐시·ALU에 투자하는 방향으로 수렴 중
- 향후 방향: 오픈 ISA(RISC-V) 성숙과 컴파일러 발전으로, 범용 ISA보다 클라우드·AI 도메인 특화 아키텍처(DSA)에 커스텀 명령어를 더하는 추세가 가속될 전망
