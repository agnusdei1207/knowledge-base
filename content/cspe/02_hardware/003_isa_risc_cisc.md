## Ⅰ. 개요
- **정의**: CPU가 인식·실행할 수 있는 명령어 집합(ISA) 설계 철학의 두 갈래
- **배경/필요성**: 컴파일러 기술이 발전하면서 복잡한 하드웨어 명령어 대신 단순 명령어를 조합하는 것이 파이프라인 효율에 유리해짐
- **비유**: CISC는 만능 스위스 칼(기능 많으나 무거움), RISC는 전용 공구 세트(각 도구가 단순하나 조합이 빠름)

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 두 철학의 설계 트레이드오프 비교 | RISC의 고정 길이·로드/스토어 분리가 파이프라인을 균등 분할함 | 현대 CISC(x86)도 내부에서 micro-op으로 디코딩하여 RISC적 실행을 한다는 점 누락 시 감점 |

> 요약: RISC는 단순·균일 명령어로 파이프라인을 극대화하고, CISC는 복합 명령어로 코드 밀도를 높이되 현대에는 두 방식이 수렴함

## Ⅱ. 구성요소
```text
[ISA 설계 스펙트럼]

RISC                          CISC
 |-- 고정 길이 명령어           |-- 가변 길이 명령어
 |-- 로드/스토어 구조           |-- 메모리-레지스터 연산 허용
 |-- 레지스터 수 많음(32+)      |-- 레지스터 수 적음(8~16)
 |-- 단순 주소 지정 방식         |-- 복합 주소 지정 방식
 |-- 하드와이어드 제어           |-- 마이크로프로그래밍 제어
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 명령어 길이 | RISC: 고정(4바이트), CISC: 가변(1~15바이트) | 규격 택배 vs 다양한 크기의 소포 |
| 로드/스토어 분리 | RISC는 메모리 접근 명령과 연산 명령을 분리 | 재료 꺼내기와 요리를 별도 단계로 구분 |
| 레지스터 파일 | RISC: 32개 이상 범용 레지스터, CISC: 8~16개 | 넓은 작업대 vs 좁은 작업대 |
| 제어 방식 | 하드와이어드(조합 논리) vs 마이크로프로그래밍(ROM 기반) | 전용 회로 vs 프로그래밍된 절차표 |
| micro-op 디코딩 | 현대 CISC가 복합 명령어를 RISC 유사 내부 연산으로 분해 | 큰 주문을 주방에서 소분하여 병렬 조리 |

> 요약: 명령어 길이·메모리 접근 방식·레지스터 수·제어 방식이 두 ISA의 구조적 차이를 결정함

## Ⅲ. 절차
```text
[RISC 파이프라인 — 균등 5단계]
IF --> ID --> EX --> MEM --> WB
(각 단계 1클록, 균일)

[CISC 내부 처리]
Fetch --> micro-op 디코딩 --> 스케줄링 --> 실행(RISC적) --> Retire
```
- 1단계: **명령어 인출(IF)** — RISC는 고정 길이이므로 PC+4로 다음 주소 계산이 단순, CISC는 길이 판별이 필요함
- 2단계: **디코딩(ID)** — RISC는 단일 클록에 디코딩 완료, CISC는 micro-op 분해에 추가 클록 소요
- 3단계: **실행(EX)** — ALU 연산 수행. RISC는 로드/스토어 분리로 이 단계에서 메모리 접근이 없음
- 4단계: **기록(WB)** — 결과를 레지스터에 기록. RISC는 파이프라인 해저드가 상대적으로 단순하여 포워딩으로 해소 가능

> 요약: RISC의 균일 단계 분할이 파이프라인 처리량을 높이고, CISC는 내부 micro-op 변환으로 이를 모방함

## Ⅳ. 문제점
- **RISC 코드 크기 증가**: 단순 명령어만 사용 — 동일 작업에 CISC 대비 명령어 수가 많아져 I-Cache 압박 발생
- **CISC 파이프라인 비균등**: 가변 길이·복합 명령어 — 단계별 실행 시간 편차가 커서 파이프라인 스톨 빈도 증가
- **micro-op 변환 오버헤드**: 현대 CISC의 디코더가 복잡 — 전력 소비와 칩 면적이 증가하여 모바일·임베디드 적용에 불리함

> 요약: RISC는 코드 밀도, CISC는 파이프라인 효율·전력에서 각각 약점을 가짐

## Ⅴ. 개선방안
1. **단기**: 압축 명령어 확장(예: RISC-V C 확장) — RISC의 코드 크기를 16비트 명령어 혼합으로 줄임
2. **중기**: 디코더 최적화·퓨전(macro-op fusion) — CISC의 micro-op 변환 단계를 줄여 파이프라인 균등성 확보
3. **장기**: 이기종 ISA 통합(CISC 코어 + RISC 가속기) — 범용 호환성과 전력 효율을 동시에 달성

> 요약: 압축 확장·디코더 퓨전·이기종 통합으로 양 ISA의 약점을 상호 보완함

## Ⅵ. 전망
- **발전 방향**: RISC-V(004 참조), ARM(005 참조) 등 RISC 계열이 서버·데스크톱까지 확장되며 ISA 다양성 증가
- **기술사적 판단**: RISC vs CISC 이분법보다 "내부 실행 방식의 수렴"을 이해하는 것이 핵심 평가 포인트임
- **기술사 제언**: ISA 선택 시 코드 밀도·파이프라인 효율·생태계 성숙도를 종합 평가할 것을 권고함
