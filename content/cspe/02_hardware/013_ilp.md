## Ⅰ. 개요
- 정의: 프로그램 실행 시 한 사이클에 동시에 처리할 수 있는 명령어의 평균 개수
- 배경: 프로세서 성능 향상을 위해 단일 명령어 실행 속도보다 병렬 처리에 집중
- 출제 의도: ILP 한계 요인(의존성)과 이를 극복하기 위한 기법들의 유기적 관계 이해

## Ⅱ. 구성요소
- ASCII 구조도
  +---------------------------------------+
  | Processor Performance (1 / CPI)       |
  |   = ILP (Inst Level Parallelism)      |
  |       |                               |
  |  +----v----+      +----------+        |
  |  | Hardware| <--> | Software |        |
  |  | (Dynamic)|      | (Static) |        |
  |  +---------+      +----------+        |
  +---------------------------------------+

- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 데이터 의존성 | 결과값이 다음 명령의 입력으로 쓰임 (RAW) | 선행 공정 |
| 이름 의존성 | 레지스터 이름만 겹치는 가짜 의존 (WAR/WAW) | 동명이인 |
| 제어 의존성 | 분기문에 의해 실행 여부가 결정됨 | 갈림길 |
> 요약: 명령어 간의 의존성을 끊어낼수록 ILP는 향상됨

## Ⅲ. 절차
- ASCII 흐름도
  (Analyze Program) -> (Break Dependencies) -> (Parallel Issue) -> (Execute)

- 4단계 설명
1. 의존성 분석: 컴파일러나 하드웨어가 명령어 간의 인과 관계 파악
2. 지연 해소: 리네이밍(이름 의존성), 분기 예측(제어 의존성)을 통해 벽을 제거
3. 명령어 스케줄링: 순서를 재배치하여 동시 실행 가능한 묶음 형성
4. 다중 발행: 슈퍼스칼라 구조를 통해 여러 명령어를 동시에 실행 유닛으로 투입
> 요약: 방해 요소를 제거하고 가능한 한 많은 명령어를 동시에 쏟아붓는 과정임

## Ⅳ. 문제점
- ILP Wall: 프로그램 자체의 순차적 특성 때문에 병렬성 향상에 물리적 한계 존재
- 복잡도 비용: ILP를 쥐어짜기 위한 하드웨어 증가가 전력과 면적의 비효율 초래

## Ⅴ. 개선방안
- (단기) 루프 언롤링 (Loop Unrolling): 반복문의 분기를 줄여 ILP 기회 확대
- (중기) 투적 실행 (Speculative): 결과 예측을 통해 의존성 벽을 미리 넘음
- (장기) TLP 전환: ILP 한계를 인정하고 스레드 수준 병렬성(TLP)으로 패러다임 전환

## Ⅵ. 전망
- 로드맵: ILP 극대화보다는 전력당 성능비 최적화를 위해 TLP와 혼용 발전
- CSF: 컴파일러의 고급 최적화 기술과 하드웨어의 동적 스케줄링 간 시너지 극대화
