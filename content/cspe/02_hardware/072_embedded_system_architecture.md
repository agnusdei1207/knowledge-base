## 미리 알고가기

- 임베디드 시스템은 장치 안에서 특정 기능을 수행하도록 만든 전용 컴퓨팅 구조임
- MCU·SoC, 메모리, 펌웨어, 센서·통신 인터페이스가 핵심 구성임
- 전력·메모리·시간 제약 안에서 목표 기능을 완료하는 것이 본질임
- HIL 시험은 실제 제어 대상을 모사한 장비로 제어기의 입출력과 타이밍을 검증함
- A/B OTA는 두 펌웨어 파티션을 번갈아 갱신해 실패 시 이전 버전으로 복구함

## 작성 근거(검토용)

- 임베디드 시스템은 프로세서, 메모리, 센서, 액추에이터, 통신, 펌웨어를 핵심 축으로 설명함
- 비교표는 MCU 기반과 SoC·MPU 기반 구조의 용도, 소프트웨어, 자원 제약을 대비함
- 실무 판단은 데드라인 미스율, 복구 시간, 업데이트 성공률, 부팅 무결성 실패 수로 구체화함

## Ⅰ. 개요

- **정의/개념**: 임베디드 시스템은 장치 기능에 맞춰 프로세서·메모리·센서·액추에이터·통신·펌웨어를 자원 한도 안에 통합한 구조임
- **배경/필요성**: 장치별 시간·메모리·전력 한도 안에서 센서 입력과 제어 출력을 반복 처리하기 위해 기능 중심의 전용 구조가 필요함

## Ⅱ. 특징

- 정해진 기능을 메모리·전력·응답시간 한도 안에서 수행하도록 자원을 고정 배치함
- 센서 입력과 물리 제어가 결합돼 하드웨어와 펌웨어를 함께 설계해야 함
- 보안 부팅과 업데이트와 고장 복구까지 초기 구조에 포함해야 함
- 자원 여유가 작아 메모리·통신·전력 설계가 제품 한계를 결정함

## Ⅲ. 종류 및 비교

| 판단 기준 | MCU 기반 구조 | SoC·MPU 기반 구조 |
|:---|:---|:---|
| 주 용도 | 센서 제어와 상태 기계를 짧은 주기로 실행함 | HMI·네트워크·멀티미디어 기능을 함께 실행함 |
| 소프트웨어 구조 | bare-metal이나 RTOS에서 제한된 태스크를 실행함 | Linux나 고기능 OS에서 서비스와 UI를 함께 실행함 |
| 자원과 전력 | 온칩 메모리와 주변장치를 사용해 외부 부품과 소비전력을 줄임 | 외부 DRAM과 고성능 코어 사용으로 전력·열 관리가 필요함 |
| 운영 조건 | 메모리 한도·최악 응답시간 검증 | 보안 업데이트·저장공간 수명 관리 |

> 요약: MCU 기반은 센서 상태 기계를 짧은 주기로 실행하고 SoC·MPU 기반은 HMI·네트워크·멀티미디어 서비스를 함께 실행함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 센서·입력 계층 | 물리 세계 신호를 읽어 디지털 제어의 시작점을 만듦 |
| 연산 코어 | MCU나 SoC가 제어 로직과 통신 처리와 인터럽트를 수행함 |
| 메모리·펌웨어 | 코드와 설정과 로그를 저장하며 자원 한계가 기능 범위를 결정함 |
| 액추에이터·통신 계층 | 모터·릴레이를 제어하고 CAN·UART·이더넷으로 외부 시스템과 데이터를 교환함 |

> 요약: 임베디드 구조는 센서 입력, 연산 코어, 메모리·펌웨어, 액추에이터·통신 계층이 연결됨.

## Ⅴ. 원리 및 절차 흐름도

1. **센서 입력 수집**: 센서와 통신 인터페이스가 물리 상태를 디지털 값으로 전달함
2. **인터럽트·상태 판정**: MCU가 이벤트를 받고 상태 기계로 제어 조건을 판정함
3. **액추에이터 제어**: 펌웨어가 모터·릴레이 등에 제어 출력을 전달함
4. **상태 피드백**: 동작 결과를 다시 수집해 다음 제어 주기의 입력으로 사용함

> 요약: 센서 입력을 상태 기계로 판정해 액추에이터를 제어하고 결과를 다음 주기에 반영함.

## Ⅵ. 실무 사례

1. 산업 제어기는 HIL 시험과 Watchdog 복구를 적용하고 데드라인 미스율·복구 시간을 확인함
2. IoT 게이트웨이는 보안 부팅과 A/B OTA를 적용하고 업데이트 성공률·부팅 무결성 실패 수를 확인함

## Ⅶ. 결론

임베디드 시스템은 기능별 시간·메모리·전력 한도에 맞춰 하드웨어와 펌웨어의 처리 범위를 결정해야 함.
