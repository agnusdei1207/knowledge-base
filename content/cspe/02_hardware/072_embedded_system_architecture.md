## 미리 알고가기

- 임베디드 시스템은 장치 안에서 특정 기능을 수행하도록 만든 전용 컴퓨팅 구조임
- MCU나 SoC와 펌웨어와 센서와 통신 인터페이스가 핵심 구성임
- 전력과 메모리와 시간 제약 안에서 목표 기능을 끝내는 것이 본질임

## Ⅰ. 개요

- **정의/개념**: 임베디드 시스템 구조는 특정 장치 기능을 수행하도록 프로세서와 메모리와 센서와 액추에이터와 통신 모듈과 펌웨어를 제한된 자원 안에 통합한 전용 하드웨어·소프트웨어 구조임
- **배경/필요성**: 자동차와 의료기기와 산업 제어 장치는 범용 PC처럼 넉넉한 자원을 쓰기 어렵고 현장에서 정해진 동작을 반복해야 하므로, 기능에 맞춘 구조 설계가 필요함

## Ⅱ. 특징

- 범용성보다 기능 적합성과 실시간성과 전력 효율을 우선함
- 센서 입력과 물리 제어가 결합돼 하드웨어와 펌웨어를 함께 설계해야 함
- 보안 부팅과 업데이트와 고장 복구까지 초기 구조에 포함해야 함
- 자원 여유가 작아 메모리와 통신과 전력 설계가 곧 제품 한계가 됨

## Ⅲ. 종류 및 비교

| 판단 기준 | MCU 기반 구조 | SoC·MPU 기반 구조 |
|:---|:---|:---|
| 주 용도 | 센서 제어와 상태 기계처럼 짧은 주기 제어에 잘 맞음 | HMI와 네트워크와 멀티미디어처럼 기능이 많은 장치에 잘 맞음 |
| 소프트웨어 구조 | bare-metal이나 RTOS로 단순하고 예측 가능한 구성이 많음 | Linux나 고기능 OS를 써 복잡한 서비스와 UI를 함께 처리함 |
| 자원과 전력 | 메모리와 소비전력이 작아 배터리 장치에 유리함 | 자원 여유는 크지만 전력과 열 관리 부담이 커짐 |
| 운영 유의점 | 자원 부족과 실시간 검증이 핵심 과제가 됨 | 보안 업데이트와 저장공간 관리가 핵심 과제가 됨 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 센서·입력 계층 | 물리 세계 신호를 읽어 디지털 제어의 시작점을 만듦 |
| 연산 코어 | MCU나 SoC가 제어 로직과 통신 처리와 인터럽트를 수행함 |
| 메모리·펌웨어 | 코드와 설정과 로그를 저장하며 자원 한계가 기능 범위를 결정함 |
| 액추에이터·통신 계층 | 모터와 릴레이와 CAN, UART, Ethernet 같은 외부 동작과 연결을 담당함 |

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 기능 요구 정의  | --> | HW·SW 분할   | --> | 제어·통신 설계  | --> | 현장 검증·운영  |
+-------------+     +-------------+     +-------------+     +-------------+
```

## Ⅴ. 원리 및 절차 흐름도

1. **기능 요구 정의**: 제어 대상과 응답 시간과 전력 조건을 먼저 정함
2. **HW·SW 분할**: 어떤 기능을 센서·하드웨어로 처리하고 어떤 기능을 펌웨어로 처리할지 나눔
3. **제어·통신 설계**: 인터럽트와 상태 기계와 버스 통신 구조를 구체화함
4. **현장 검증·운영**: 실제 온도와 진동과 전원 이상 조건에서 동작을 시험함

## Ⅵ. 실무 적용 및 유의점

1. 자동차나 산업 제어기처럼 짧은 주기 응답이 필요한 장치는 MCU와 RTOS 기반 구조가 적합하지만 센서·액추에이터 타이밍이 어긋나면 제어 실패로 이어질 수 있으므로 HIL 시험과 감시 타이머 복구를 함께 두고 데드라인 미스율과 장애 복구 시간과 전력 예산으로 확인함
2. 연결 기능이 많은 HMI나 IoT 장치는 SoC 기반 구조가 유리하지만 업데이트와 보안 기능이 플래시 공간을 빠르게 잠식할 수 있으므로 보안 부팅과 A/B OTA 설계를 같이 두고 업데이트 성공률과 부팅 무결성 통과율과 메모리 여유율로 확인함

## Ⅶ. 결론

임베디드 시스템 구조의 핵심은 작은 컴퓨터를 만드는 일이 아니라 제한된 자원 안에서 필요한 기능을 시간 안에 안정적으로 끝내는 데 있음.
