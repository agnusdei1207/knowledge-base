## 미리 알고가기

- 임베디드 시스템은 장치 안에서 특정 기능을 수행하도록 만든 전용 컴퓨팅 구조임
- MCU나 SoC와 펌웨어와 센서와 통신 인터페이스가 핵심 구성임
- 전력·메모리·시간 제약 안에서 목표 기능을 완료하는 것이 본질임

## Ⅰ. 개요

- **정의/개념**: 임베디드 시스템 구조는 특정 장치 기능을 수행하도록 프로세서, 메모리, 센서, 액추에이터, 통신 모듈, 펌웨어를 제한된 자원 안에 통합한 전용 HW/SW 구조임
- **배경/필요성**: 자동차와 의료기기와 산업 제어 장치는 범용 PC처럼 넉넉한 자원을 쓰기 어렵고 현장에서 정해진 동작을 반복해야 하므로, 기능에 맞춘 구조 설계가 필요함

## Ⅱ. 특징

- 범용성보다 기능 적합성과 실시간성과 전력 효율을 우선함
- 센서 입력과 물리 제어가 결합돼 하드웨어와 펌웨어를 함께 설계해야 함
- 보안 부팅과 업데이트와 고장 복구까지 초기 구조에 포함해야 함
- 자원 여유가 작아 메모리·통신·전력 설계가 제품 한계를 결정함

## Ⅲ. 종류 및 비교

| 판단 기준 | MCU 기반 구조 | SoC·MPU 기반 구조 |
|:---|:---|:---|
| 주 용도 | 센서 제어와 상태 기계를 짧은 주기로 실행함 | HMI·네트워크·멀티미디어 기능을 함께 실행함 |
| 소프트웨어 구조 | bare-metal이나 RTOS에서 제한된 태스크를 실행함 | Linux나 고기능 OS에서 서비스와 UI를 함께 실행함 |
| 자원과 전력 | 온칩 메모리와 주변장치를 사용해 외부 부품과 소비전력을 줄임 | 외부 DRAM과 고성능 코어 사용으로 전력·열 관리가 필요함 |
| 운영 유의점 | 자원 부족과 실시간 검증이 핵심 과제가 됨 | 보안 업데이트와 저장공간 관리가 핵심 과제가 됨 |

> 요약: MCU 기반은 짧은 주기 제어, SoC·MPU 기반은 HMI·네트워크·멀티미디어 기능에 맞음.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 센서·입력 계층 | 물리 세계 신호를 읽어 디지털 제어의 시작점을 만듦 |
| 연산 코어 | MCU나 SoC가 제어 로직과 통신 처리와 인터럽트를 수행함 |
| 메모리·펌웨어 | 코드와 설정과 로그를 저장하며 자원 한계가 기능 범위를 결정함 |
| 액추에이터·통신 계층 | 모터와 릴레이와 CAN, UART, Ethernet 같은 외부 동작과 연결을 담당함 |

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 기능 요구 정의  | --> | HW·SW 분할   | --> | 제어·통신 설계  | --> | 현장 검증·운영  |
+-------------+     +-------------+     +-------------+     +-------------+
```

> 요약: 임베디드 구조는 센서 입력, 연산 코어, 메모리·펌웨어, 액추에이터·통신 계층이 연결됨.

## Ⅴ. 원리 및 절차 흐름도

1. **기능 요구 정의**: 제어 대상과 응답 시간과 전력 조건을 먼저 정함
2. **HW·SW 분할**: 어떤 기능을 센서·하드웨어로 처리하고 어떤 기능을 펌웨어로 처리할지 나눔
3. **제어·통신 설계**: 인터럽트와 상태 기계와 버스 통신 구조를 구체화함
4. **현장 검증·운영**: 실제 온도와 진동과 전원 이상 조건에서 동작을 시험함

> 요약: 기능 요구와 제약을 정한 뒤 HW/SW 분할, 제어·통신 설계, 현장 검증으로 이어짐.

## Ⅵ. 실무 적용 및 유의점

1. 자동차·산업 제어기는 MCU·RTOS 구조가 맞지만 센서·액추에이터 타이밍이 어긋나면 제어 실패로 이어지므로 HIL 시험과 watchdog 복구를 두고 deadline miss rate, recovery time, power budget으로 확인함
2. HMI·IoT 장치는 업데이트와 보안 기능이 flash 공간을 잠식할 수 있으므로 secure boot와 A/B OTA를 두고 update success rate, boot integrity pass rate, memory margin으로 확인함

## Ⅶ. 결론

임베디드 시스템 구조의 핵심은 작은 컴퓨터가 아니라 제한된 자원 안에서 필요한 기능을 정해진 시간 안에 끝내는 데 있음.

## 작성 근거(검토용)

- 임베디드 시스템은 프로세서, 메모리, 센서, 액추에이터, 통신, 펌웨어를 핵심 축으로 설명함
- 비교표는 MCU 기반과 SoC·MPU 기반 구조의 용도, 소프트웨어, 자원 제약을 대비함
- 실무 판단은 deadline miss rate, recovery time, update success rate, memory margin으로 검증 가능하게 작성함
