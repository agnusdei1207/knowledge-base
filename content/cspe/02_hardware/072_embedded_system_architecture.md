## 미리 알고가기

- 임베디드 시스템: 제품이나 장치 내부에 들어가 특정 기능을 수행하는 전용 컴퓨팅 시스템임
- MCU: CPU, 메모리, 주변장치가 한 칩에 통합된 소형 제어용 마이크로컨트롤러임
- 펌웨어: 하드웨어와 밀접하게 결합되어 장치 기능을 직접 제어하는 소프트웨어임
- 실시간성: 정해진 시간 안에 입력을 처리하고 출력을 내야 하는 시간 제약 특성임
- 주변장치: 센서, 액추에이터, 통신 모듈, 타이머, ADC/DAC처럼 외부 세계와 연결되는 장치임

## Ⅰ. 개요

- **정의**: 임베디드 시스템 구조는 특정 장치 기능을 수행하기 위해 프로세서, 메모리, 센서, 액추에이터, 펌웨어, 통신 인터페이스를 제한된 자원 안에 통합한 하드웨어·소프트웨어 아키텍처임. 실시간성, 전력, 비용, 신뢰성, 장치 수명주기를 기준으로 제품 기능을 안정적으로 구현하기 위해 사용함
- **배경/필요성**: 자동차, 의료기기, 가전, 산업 제어 장치는 범용 컴퓨터보다 작은 전력과 비용으로 정해진 동작을 반복 수행해야 함. 센서 입력과 물리 제어가 결합되므로 하드웨어와 소프트웨어를 함께 설계해야 함
- **비유**: 건물 전체 컴퓨터가 아니라 엘리베이터 안에 들어가 버튼, 모터, 문 센서를 정해진 시간 안에 제어하는 전용 두뇌와 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 임베디드 구조 설계 설명 | MCU/SoC, 센서, 액추에이터, 펌웨어, RTOS | 단순 소형 컴퓨터로만 설명 |
| 제약 조건 기반 선택 | 실시간성, 전력, 비용, 신뢰성, 수명주기 | 서버 아키텍처 기준을 그대로 적용 |

> 요약: 임베디드 시스템은 제한된 자원에서 특정 장치 기능을 실시간·저전력·고신뢰로 수행하도록 구성한 전용 컴퓨팅 구조임.

## Ⅱ. 특징/비교

| 판단 기준 | 범용 컴퓨터 | 임베디드 시스템 |
|:---|:---|:---|
| 목적 | 다양한 응용을 실행하는 범용 처리 | 특정 장치 기능을 반복적·안정적으로 수행 |
| 자원 조건 | 메모리, 전력, 저장공간 확장이 비교적 쉬움 | 비용, 전력, 크기, 열, 배터리 제약이 큼 |
| 시간 요구 | 평균 응답성과 처리량을 중시함 | 데드라인, 인터럽트 지연, 결정성을 중시함 |
| 운영 방식 | 사용자와 OS 중심으로 업데이트가 잦음 | 펌웨어 중심이며 긴 수명주기와 현장 업데이트가 중요함 |

> 요약: 임베디드 시스템은 범용성보다 기능 적합성, 시간 제약, 자원 효율, 현장 신뢰성을 우선해 설계함.

- **하드웨어 기준**: MCU, SoC, FPGA, 센서 인터페이스는 성능보다 전력·원가·주변장치 요구에 맞춰 선택함
- **소프트웨어 기준**: bare-metal, RTOS, 임베디드 Linux 중 실시간성과 기능 복잡도에 맞는 실행 환경을 고름
- **운영 기준**: OTA 업데이트, 보안 부팅, 진단 로그, 장기 부품 공급을 설계 초기부터 반영해야 함

## Ⅲ. 구성요소

```text
+----------+      +----------+      +----------+
| Sensor   | ---> | MCU/SoC  | ---> | Actuator |
+----------+      +----+-----+      +----------+
                         |
          +--------------+--------------+
          v                             v
    +----------+                  +----------+
    | Firmware |                  | Comm I/F |
    +----------+                  +----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 센서 입력 | 온도, 압력, 위치, 영상 등 물리 상태를 디지털 또는 아날로그 신호로 수집함 | 감각 기관 |
| MCU/SoC | 명령 실행, 주변장치 제어, 인터럽트 처리를 수행하는 핵심 연산 장치임 | 작은 두뇌 |
| 메모리 | 펌웨어, 설정값, 로그, 실행 데이터를 저장하는 Flash, SRAM, EEPROM 영역임 | 작업 노트 |
| 펌웨어·RTOS | 장치 제어 로직, 태스크 스케줄링, 드라이버, 예외 처리를 수행함 | 운전 규칙 |
| 액추에이터·통신 | 모터, 릴레이, 표시장치, CAN, UART, SPI, Ethernet 등 외부와 상호작용함 | 손발과 통로 |

> 요약: 임베디드 구조는 센서 입력을 MCU/SoC와 펌웨어가 해석해 액추에이터와 통신 출력으로 바꾸는 제어 구조임.

## Ⅳ. 절차

```text
+----------+      +----------+      +----------+      +----------+
| Require  | ---> | Partition| ---> | Implement| ---> | Validate |
| Control  |      | HW/SW    |      | Firmware |      | Field    |
+----------+      +----------+      +----------+      +----------+
```

1. **요구사항 분석**: 제어 기능, 데드라인, 전력, 비용, 안전 등급, 통신 요구를 정의함
2. **HW/SW 분할**: 센서, MCU, 메모리, 주변장치와 펌웨어·RTOS 역할을 분리해 설계함
3. **펌웨어 구현**: 드라이버, 인터럽트, 태스크, 상태 머신, 오류 처리, 업데이트 기능을 구현함
4. **검증·운영**: 실시간 응답, 전력, 환경 조건, 안전 동작, 현장 업데이트를 시험하고 운영함

> 요약: 임베디드 설계는 장치 요구를 하드웨어와 펌웨어 역할로 나누고 현장 조건에서 검증하는 과정임.

## Ⅴ. 문제점

- **P1 자원 제약**: 메모리와 전력이 작아 기능 추가, 암호화, 로그 저장, 업데이트 여유가 부족할 수 있음
- **P2 실시간·안전 결함**: 인터럽트 지연이나 태스크 우선순위 오류가 물리 장치 오동작으로 이어질 수 있음
- **P3 장기 운영과 보안 취약**: 현장 배포 후 업데이트가 어렵고 부품 수명주기가 길어 알려진 취약점이 오래 남을 수 있음

> 요약: 임베디드 시스템은 작은 자원, 물리 제어, 긴 현장 수명주기 때문에 기능 결함이 운영 위험으로 확대됨.

## Ⅵ. 개선방안

1. **단기**: 메모리 사용량, CPU 부하, 인터럽트 지연, 전력 프로파일을 측정해 병목을 확인함
2. **중기**: RTOS 태스크 설계, 전원 관리, 보안 부팅, OTA 업데이트 구조를 표준화함
3. **장기**: 제품군 공통 플랫폼과 장기 유지보수 정책을 수립해 재사용성과 보안성을 높임

- **P1 대응**: 메모리 예산, 저전력 모드, 기능 우선순위, 로그 압축을 적용함 (확인: RAM/Flash 여유율, 평균 전류)
- **P2 대응**: WCET 분석, 우선순위 설계, 상태 머신 검증, 안전 정지 로직을 적용함 (확인: 최대 응답시간, 안전 시험)
- **P3 대응**: 서명 업데이트, SBOM, 취약점 대응 절차, 부품 수명 관리를 도입함 (확인: 패치 성공률, 지원 기간)

> 요약: 임베디드 개선은 자원 예산, 실시간 검증, 장기 보안 업데이트 체계를 함께 갖춰야 함.

## Ⅶ. 전망

- **발전 방향**: 임베디드 시스템은 MCU, NPU, wireless module, secure element, RTOS/Linux를 조합한 온디바이스 지능형 구조로 확대됨
- **기술사적 판단**: 전력 예산, worst-case latency, BOM cost, sensor interface, memory footprint, OTA 요구사항을 기준으로 MCU·SoC·OS 구성을 선택함; boot time, interrupt latency, sleep current, thermal envelope, firmware rollback, EMC/환경 시험 결과를 제품 조건에서 확인함
- **기술사 제언**: 임베디드 아키텍처는 최고 성능보다 실시간성, 전력, 안전, 업데이트 가능성, 공급망 지속성을 기준으로 판단해야 함
