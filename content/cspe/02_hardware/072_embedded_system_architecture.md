## Ⅰ. 개요
- **정의**: 특정 기능 수행을 목적으로 하드웨어와 소프트웨어가 일체화된 전용 컴퓨팅 시스템
- **배경/필요성**: 범용 PC로는 크기·전력·비용 제약을 충족할 수 없어, 목적에 최적화된 전용 시스템이 필요함
- **비유**: 범용 PC가 만능 공구 세트라면, 임베디드 시스템은 한 가지 일만 하는 전동 드라이버임

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 범용 시스템과의 차이·설계 제약 이해 | 실시간성·저전력·전용 목적 3대 특성 | RTOS(073 참조)와 혼동하지 말 것, 시스템 아키텍처 관점으로 서술 |

> 요약: 임베디드 시스템은 특정 기능에 최적화된 전용 HW/SW 통합 시스템임

## Ⅱ. 구성요소
```text
+--------------------------------------------------+
|              Embedded System                      |
|                                                   |
|  Processor ---+--- Memory ---+--- I/O Interface   |
|  (MCU/MPU)    |  (ROM/RAM)   |   (Sensor/Actuator)|
|               |              |                     |
|               +--- Bus ------+                     |
|                                                   |
|  Firmware / RTOS / Application SW                 |
+--------------------------------------------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 프로세서(MCU/MPU) | 연산·제어를 담당하며 주변장치 컨트롤러를 내장한 칩 | 사람의 두뇌 |
| 메모리(ROM/RAM) | 펌웨어를 저장하는 비휘발 메모리와 실행 데이터용 휘발 메모리 | 교과서(ROM)와 메모장(RAM) |
| I/O 인터페이스 | 센서·액추에이터 등 외부 장치와 데이터를 주고받는 통로 | 손과 눈 같은 감각 기관 |
| 펌웨어/RTOS | 하드웨어를 제어하고 태스크를 스케줄링하는 시스템 소프트웨어 | 운전자의 운전 습관·규칙 |

> 요약: 프로세서·메모리·I/O·펌웨어가 하나의 보드에 통합되어 전용 기능을 수행함

## Ⅲ. 절차
```text
Step1 Requirements --> Step2 HW/SW Partition --> Step3 Co-Development --> Step4 Integration
  Define constraints    Decide HW vs SW          Parallel build          Test + Deploy
```
- 1단계: 요구사항 분석 — 응답시간·전력·크기 등 비기능 제약을 정량화함
- 2단계: HW/SW 분할 — 성능이 요구되는 기능은 HW로, 유연성이 필요한 기능은 SW로 배분함 (077 참조)
- 3단계: 병행 개발 — 하드웨어 보드 설계와 펌웨어 개발을 동시에 진행함
- 4단계: 통합 시험 — 크로스 컴파일된 바이너리를 타깃 보드에 탑재하고 기능·타이밍을 검증함

> 요약: 요구사항 → HW/SW 분할 → 병행 개발 → 통합 시험의 4단계로 임베디드 시스템을 구축함

## Ⅳ. 문제점
- 자원 제약에 따른 기능 제한: MCU의 클럭·메모리 한계로 복잡한 알고리즘 탑재가 어려움
- 디버깅 난이도 상승: 타깃 보드 의존적이어서 호스트 환경에서의 재현이 어렵고, JTAG 등 전용 장비가 필요함
- 긴 개발 주기: HW 시제품 제작과 SW 개발이 상호 의존하여 병렬화에 한계가 있음

> 요약: 자원 제약·디버깅 난이도·개발 주기 지연이 임베디드 시스템의 주요 문제임

## Ⅴ. 개선방안
1. 단기: 에뮬레이터·시뮬레이터 기반 가상 타깃 환경을 구축하여 기능 검증 속도를 높임
2. 중기: JTAG 대신 원격 디버깅 프레임워크(OpenOCD 등)를 도입하여 디버깅 접근성을 개선함
3. 장기: SoC 플랫폼(078 참조)을 활용하여 HW 재설계 없이 IP 블록 교체로 기능을 확장함

> 요약: 가상 타깃 → 원격 디버깅 → SoC 플랫폼화 순으로 개발 효율을 개선함

## Ⅵ. 전망
- 발전 방향: AIoT 확산에 따라 엣지 추론 가속기가 내장된 임베디드 SoC가 보편화될 전망임
- 기술사적 판단: 전력·크기·실시간성 3대 제약을 동시에 만족하는 설계 역량이 경쟁력의 핵심이 될 것임
- 기술사 제언: HW/SW 공동설계(077 참조) 프로세스를 조기에 확립하여 개발 리스크를 줄일 필요
