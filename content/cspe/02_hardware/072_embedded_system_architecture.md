## 미리 알고가기

- 임베디드 시스템은 장치 내부에서 특정 기능을 수행하는 전용 컴퓨팅 구조임
- MCU, SoC, 펌웨어, 센서, 액추에이터, 통신 인터페이스가 핵심 구성임
- 제한된 전력과 비용과 실시간 요구를 함께 만족해야 함

## Ⅰ. 개요

- **정의/개념**: 임베디드 시스템 구조는 특정 장치 기능을 수행하도록 프로세서와 메모리와 센서와 액추에이터와 통신 모듈과 펌웨어를 제한된 자원 안에 통합한 전용 하드웨어, 소프트웨어 아키텍처임
- **배경/필요성**: 자동차와 의료기기와 산업 제어 장치는 범용 컴퓨터보다 작은 전력과 비용으로 정해진 동작을 안정적으로 반복해야 하므로, 기능 특화 구조가 필요함

## Ⅱ. 특징

- 범용성보다 기능 적합성과 실시간성과 자원 효율을 우선함
- 센서 입력과 물리 제어가 결합돼 하드웨어와 소프트웨어 co-design이 중요함
- OTA와 보안 부팅과 장기 유지보수까지 초기 설계에 포함해야 함
- 자원 한계 때문에 메모리와 전력과 통신 설계가 곧 시스템 한계가 됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 범용 컴퓨터 | 임베디드 시스템 |
|:---|:---|:---|
| 목적 | 다양한 응용 실행 | 특정 기능 반복 수행 |
| 자원 여유 | 높음 | 낮음 |
| 시간 요구 | 평균 성능 중심 | 데드라인과 결정성 중심 |
| 운영 방식 | 사용자 중심 업데이트 | 펌웨어와 현장 운영 중심 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Sensor, Input Layer | 물리 세계 신호를 받아 디지털 제어의 시작점을 제공함 |
| MCU, SoC | 연산과 인터럽트와 주변장치 제어를 담당하는 핵심 두뇌임 |
| Memory, Firmware | 코드와 설정과 로그를 저장하며 자원 한계가 기능 확장성을 제어함 |
| Actuator, Communication | 모터와 릴레이와 CAN, UART, Ethernet 같은 외부 상호작용 경로를 제공함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 요구 기능 정의   | --> | HW, SW 분할   | --> | 제어 로직 구현  | --> | 현장 검증/운영  |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **요구 기능 정의**: 제어 대상과 데드라인과 전력 조건을 정함
2. **HW, SW 분할**: MCU와 센서와 펌웨어 책임을 나눔
3. **제어 로직 구현**: 드라이버와 상태 기계와 인터럽트 로직을 구현함
4. **현장 검증 및 운영**: 환경 조건과 안전 동작과 업데이트 절차를 시험함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 메모리와 전력 자원이 작으면 보안 기능과 로그와 OTA까지 넣는 과정에서 기능 충돌이 발생할 수 있음
   - 해결방안: 자원 예산을 초기부터 분리하고 memory headroom과 power budget으로 검증함
2. 문제: 센서와 액추에이터와 펌웨어 타이밍이 어긋나면 물리 제어 실패와 오동작이 발생할 수 있음
   - 해결방안: timing analysis와 HIL 검증을 수행하고 deadline miss rate와 control jitter로 검증함
3. 문제: 장기 수명 제품은 부품 단종과 현장 업데이트 실패가 운영 리스크로 누적될 수 있음
   - 해결방안: lifecycle planning과 fail-safe OTA를 설계하고 component availability와 update success rate로 검증함

## Ⅶ. 적용 사례

- 자동차 제어 ECU에서는 센서와 액추에이터와 CAN 통신을 통합하고 확인 지표는 control latency와 fault tolerance임
- 의료 웨어러블에서는 저전력 MCU 기반 구조를 사용하고 확인 지표는 battery life와 alarm reliability임
- 산업 PLC 보조 제어기에서는 실시간 입력 처리를 구현하고 확인 지표는 deadline miss rate와 uptime임

## Ⅷ. 결론

임베디드 시스템 구조의 핵심은 작은 컴퓨터를 만드는 것이 아니라 제한된 자원 안에서 특정 장치 기능을 시간 안에 안정적으로 끝내는 데 있음.
