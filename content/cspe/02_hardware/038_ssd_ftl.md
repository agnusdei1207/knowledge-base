## 미리 알고가기

- FTL은 호스트가 보는 LBA를 NAND 실제 위치인 PBA로 바꾸는 계층임
- NAND는 덮어쓰기가 불가능하고 페이지 단위 쓰기와 블록 단위 삭제가 분리되어 있음
- 가비지 컬렉션과 마모도 평준화 품질이 SSD 성능과 수명을 좌우함
- TRIM: 운영체제가 더 이상 유효하지 않은 블록을 SSD에 알려 가비지 컬렉션 부담을 줄이는 명령임

## 작성 근거(검토용)

- FTL은 주소 변환·새 위치 쓰기·가비지 컬렉션·마모도 평준화·메타데이터 보호로 설명함
- 매핑 방식은 매핑 단위·임의 쓰기, 매핑 테이블 크기, 병합·GC 범위를 핵심 비교축 3개로 대응시킴
- FTL의 쓰기 증폭·지연·메타데이터 복구를 SSD 선택 기준으로 정리함

## Ⅰ. 개요

- **정의/개념**: FTL은 SSD 컨트롤러에서 논리 블록 주소를 NAND 물리 주소로 매핑하고, 새 위치 쓰기·가비지 컬렉션·마모도 평준화로 NAND의 물리 제약을 숨기는 제어 계층임
- **배경/필요성**: NAND의 덮어쓰기 제한·셀 수명·오류 축적을 관리하기 위해 논리 주소와 물리 위치를 분리하는 변환 계층이 필요함

### 쉽게 이해하기 (학습용)
- 책 내용을 고칠 때 원래 페이지를 지우지 못해 새 페이지에 다시 쓰고, 목차(FTL)만 새 페이지 번호로 바꿔주는 것과 같음
- 헌 페이지 정리와 낡은 페이지 관리도 목차가 뒤에서 함께 처리함

## Ⅱ. 특징

- 호스트는 일반 블록 장치처럼 접근하지만 내부에서는 새 위치 쓰기와 재매핑이 수행됨
- 매핑 단위에 따라 DRAM 사용량과 임의 쓰기 성능이 달라짐
- 가비지 컬렉션과 마모도 평준화의 배경 쓰기량이 p99 쓰기 지연과 쓰기 증폭을 결정함
- 전원 장애 시 매핑 메타데이터 보호가 안 되면 데이터 무결성 문제가 커질 수 있음

### 쉽게 이해하기 (학습용)
- 겉에서 보면 그냥 책장이지만 속에서는 계속 새 페이지에 옮겨 쓰고 목차를 갱신하는 작업이 벌어짐
- 목차를 얼마나 세밀하게 관리하느냐가 찾는 속도(성능)와 책장 정리 부담(쓰기 증폭)을 가르고, 정전 시 목차 자체가 망가지지 않게 지켜야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 페이지 매핑 | 블록 매핑 | 하이브리드 매핑 |
|:---|:---|:---|:---|
| 매핑 단위·임의 쓰기 | 페이지 단위로 관리하며 페이지별 새 위치를 바로 할당함 | 블록 단위로 관리하며 임의 쓰기 시 블록 내 페이지 병합이 필요함 | 핫 데이터는 페이지, 대량 데이터는 블록 경로로 쓰기 패턴에 따라 선택함 |
| 매핑 테이블 크기 | 페이지 수만큼 엔트리 필요 | 블록 수만큼 엔트리 필요 | 페이지·블록 엔트리 혼합 |
| 병합·GC 범위 | 무효 페이지가 많은 블록 정리 | 갱신 블록과 원본 블록 병합 | 로그 블록과 데이터 블록 병합 |

> 요약: 페이지 매핑은 세밀한 대신 매핑 테이블이 크고, 블록 매핑은 테이블은 작지만 임의 쓰기마다 블록 병합이 필요하며, 하이브리드 매핑은 두 경로를 혼합해 절충함.

### 쉽게 이해하기 (학습용)
- 페이지 매핑은 문장 하나하나마다 색인 카드를 만드는 것(정밀하지만 카드가 많음)이고, 블록 매핑은 챕터 단위로만 색인을 두는 것(카드는 적지만 한 문장 고칠 때 챕터 전체를 다시 씀)과 같음
- 하이브리드 매핑은 자주 고치는 챕터는 문장 단위로, 나머지는 챕터 단위로 색인하는 절충안임

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 주소 매핑 테이블 | LBA와 PBA 관계를 저장해 논리 주소를 실제 NAND 위치로 변환함 |
| 가비지 컬렉터 | 무효 페이지를 정리해 빈 블록을 확보하고 배경 쓰기 부하를 조절함 |
| 마모도 평준화 엔진 | 특정 블록에 쓰기가 몰리지 않게 분산해 SSD 수명을 늘림 |
| 메타데이터 보호·버퍼 | DRAM 캐시·저널링·전원 손실 보호로 매핑 정보를 안전하게 유지함 |

```text
+-------------+     +------------------+     +------------------+
| 호스트 LBA   | --> | FTL 매핑          | --> | NAND 블록         |
+-------------+     +------------------+     +------------------+
                         |         |
                         v         v
                    +--------+ +--------+
                    | 가비지 수집 | | 마모도 평준화 |
                    +--------+ +--------+
```

> 요약: FTL은 LBA-PBA 매핑·가비지 컬렉션·마모도 평준화·메타데이터 보호를 수행함.

### 쉽게 이해하기 (학습용)
- 목차(주소 매핑 테이블)가 페이지 위치를 알려주고, 청소부(가비지 컬렉터)가 빈 페이지를 확보하며, 관리인(마모도 평준화 엔진)이 특정 페이지만 닳지 않게 순환시키고, 금고(메타데이터 보호)가 목차 자체를 지킴

## Ⅴ. 원리 및 절차 흐름도

```text
+--------+    +--------+    +--------+    +--------+    +--------+    +--------+
| 쓰기요청 | --> | 새페이지 | --> | 매핑갱신 | --> | 페이지  | --> | 가비지  | --> | 마모도  |
| 수신    |    | 할당    |    |        |    | 무효화  |    | 컬렉션  |    | 평준화  |
+--------+    +--------+    +--------+    +--------+    +--------+    +--------+
```

1. **쓰기 요청 수신**: 호스트가 특정 LBA에 데이터를 기록하려고 함
2. **새 페이지 할당**: FTL이 비어 있는 물리 페이지를 새로 선택함
3. **매핑 테이블 갱신**: LBA가 새 PBA를 가리키도록 바꿈
4. **기존 페이지 무효화**: 이전 위치 데이터는 무효 상태로 남김
5. **가비지 컬렉션**: 무효 페이지 비율이 높은 블록을 지워 빈 블록을 회복함
6. **마모도 평준화**: 삭제 횟수가 적은 블록을 회수 대상에 포함해 블록별 삭제 횟수를 분산함

> 요약: FTL은 새 페이지에 쓰고 매핑을 갱신한 뒤 가비지 컬렉션으로 빈 블록을 회복하고 마모도 평준화로 삭제 횟수를 분산함.

### 쉽게 이해하기 (학습용)
- 수정할 문장이 생기면 빈 페이지에 새로 쓰고 목차를 그 페이지로 바꾼 뒤, 옛 페이지는 못 쓰는 페이지로 표시해두고, 못 쓰는 페이지가 쌓인 챕터만 통째로 정리해 다시 빈 페이지로 되돌림

## Ⅵ. 실무 사례

1. 엔터프라이즈 SSD는 여유 공간과 TRIM을 적용하고 쓰기 증폭 계수와 빈 블록 비율을 확인함
2. 전원 손실 보호 SSD는 메타데이터 저널링을 적용하고 매핑 복구시간과 비정상 종료 데이터 손실률을 확인함

### 쉽게 이해하기 (학습용)
- 정리할 페이지 여유를 넉넉히 남겨두는 것(여유 공간)과 필요 없는 페이지를 바로 알려주는 것(TRIM)으로 청소 부담을 줄이고, 정전에도 목차가 살아남게 목차 사본(저널링)을 남겨둠

## Ⅶ. 결론

- FTL은 LBA를 새 물리 위치에 쓰고 매핑을 갱신해 NAND의 덮어쓰기 제약을 숨기며, 가비지 컬렉션과 마모도 평준화로 SSD의 성능과 수명을 함께 좌우함
- 매핑 단위는 임의 쓰기 패턴과 DRAM 여유에 맞춰 선택하고, 여유 공간·TRIM·메타데이터 저널링으로 쓰기 증폭과 전원 손실 복구를 통제해야 함

### 쉽게 이해하기 (학습용)
- 책을 고칠 때마다 새 페이지에 옮겨 쓰고 목차로 관리하는 방식이며, 목차 관리 방식과 청소 주기를 어떻게 설정하느냐가 책장의 수명과 복구 가능성을 가름
