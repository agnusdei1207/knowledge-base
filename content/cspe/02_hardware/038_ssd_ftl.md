## 미리 알고가기

- FTL은 호스트가 보는 LBA를 NAND 실제 위치인 PBA로 바꾸는 계층임
- NAND는 덮어쓰기가 불가능하고 페이지 단위 쓰기와 블록 단위 삭제가 분리되어 있음
- 가비지 컬렉션과 마모도 평준화 품질이 SSD 성능과 수명을 좌우함

## Ⅰ. 개요

- **정의/개념**: FTL은 SSD 컨트롤러에서 논리 블록 주소를 NAND 물리 주소로 매핑하고, 새 위치 쓰기·가비지 컬렉션·마모도 평준화로 NAND의 물리 제약을 숨기는 제어 계층임
- **배경/필요성**: NAND의 덮어쓰기 제한·셀 수명·오류 축적을 관리하기 위해 논리 주소와 물리 위치를 분리하는 변환 계층이 필요함

## Ⅱ. 특징

- 호스트는 일반 블록 장치처럼 접근하지만 내부에서는 새 위치 쓰기와 재매핑이 수행됨
- 매핑 단위에 따라 DRAM 사용량과 임의 쓰기 성능이 달라짐
- 가비지 컬렉션과 마모도 평준화가 동시에 동작하므로 장기 지연 안정성이 핵심 품질 지표임
- 전원 장애 시 매핑 메타데이터 보호가 안 되면 데이터 무결성 문제가 커질 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 페이지 매핑 | 블록 매핑 | 하이브리드 매핑 |
|:---|:---|:---|:---|
| 매핑 단위 | 세밀한 페이지 단위로 관리함 | 큰 블록 단위로 관리함 | 핫 데이터는 페이지, 대량 데이터는 블록 단위로 혼합함 |
| 장점 | 임의 쓰기 성능과 유연성이 높음 | 매핑 테이블 메모리가 작음 | 성능과 메모리 사용의 균형을 잡기 쉬움 |
| 한계 | DRAM 메타데이터 비용이 큼 | 병합 비용과 쓰기 증폭이 커질 수 있음 | 정책이 복잡하고 조정 난도가 높음 |
| 적합 환경 | 고성능 엔터프라이즈 SSD | 저가형 단순 장치 | 범용 SSD |

> 요약: 페이지 매핑은 성능, 블록 매핑은 메모리 절감, 하이브리드 매핑은 균형에 초점이 있음.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 주소 매핑 테이블 | LBA와 PBA 관계를 저장해 논리 주소를 실제 NAND 위치로 변환함 |
| 가비지 컬렉터 | 무효 페이지를 정리해 빈 블록을 확보하고 배경 쓰기 부하를 조절함 |
| 마모도 평준화 엔진 | 특정 블록에 쓰기가 몰리지 않게 분산해 SSD 수명을 늘림 |
| 메타데이터 보호·버퍼 | DRAM 캐시·저널링·전원 손실 보호로 매핑 정보를 안전하게 유지함 |

```text
+-------------+     +------------------+     +------------------+
| Host LBA    | --> | FTL Mapping      | --> | NAND Blocks      |
+-------------+     +------------------+     +------------------+
                         |         |
                         v         v
                    +--------+ +--------+
                    | GC     | | WL     |
                    +--------+ +--------+
```

> 요약: FTL은 LBA-PBA 매핑, GC, wear leveling, 메타데이터 보호로 NAND 제약을 숨김.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+     +-------------+
| 쓰기 요청 수신   | --> | 새 페이지 할당   | --> | 매핑 테이블 갱신   | --> | 기존 페이지 무효화 | --> | 배경 GC 수행    |
+-------------+     +-------------+     +-------------+     +-------------+     +-------------+
```

1. **쓰기 요청 수신**: 호스트가 특정 LBA에 데이터를 기록하려고 함
2. **새 페이지 할당**: FTL이 비어 있는 물리 페이지를 새로 선택함
3. **매핑 테이블 갱신**: LBA가 새 PBA를 가리키도록 바꿈
4. **기존 페이지 무효화**: 이전 위치 데이터는 무효 상태로 남김
5. **배경 GC 수행**: 무효 페이지가 많은 블록을 정리해 여유 공간을 회복함

> 요약: FTL은 새 페이지에 쓰고 매핑을 갱신한 뒤 무효 페이지를 GC로 정리함.

## Ⅵ. 실무 적용 및 유의점

1. GC와 병합 작업이 많아지면 쓰기 증폭이 커지므로 여유 공간 할당과 TRIM을 활용하고 write amplification factor, free block ratio로 확인함
2. 배경 정리 작업이 사용자 I/O와 겹치면 tail latency가 악화되므로 idle-time GC와 QoS-aware scheduling을 적용하고 p99 latency, steady-state IOPS로 확인함
3. 전원 장애 시 매핑 메타데이터가 손상되면 namespace 가시성이 깨질 수 있으므로 PLP와 metadata journaling을 적용하고 metadata recovery time, unsafe shutdown loss rate로 확인함

## Ⅶ. 결론

FTL은 SSD 내부 번역기를 넘어 성능, 수명, 무결성을 함께 조정하는 제어 계층이며, SSD 판단은 NAND 종류보다 FTL 정책 품질에 좌우됨.

## 작성 근거(검토용)

- FTL은 주소 변환뿐 아니라 out-of-place update, GC, wear leveling, 메타데이터 보호로 설명함
- 모호한 표현은 write amplification factor, p99 latency, metadata recovery time으로 구체화함
- 결론은 NAND 종류보다 FTL 정책 품질로 정리함
