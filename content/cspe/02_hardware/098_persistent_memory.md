# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 퍼시스턴트 메모리(Persistent Memory, PMEM)는 '메모리처럼 빠르고(바이트 단위 접근)' + '디스크처럼 전원을 꺼도 지워지지 않는(비휘발성)' 두 가지 장점을 융합한 차세대 저장 계층이다.
- **왜 필요한가**: 컴퓨터 구조는 오랫동안 DRAM(빠름/휘발성)과 디스크(느림/비휘발성)의 극단적 이분법으로 나뉘어 있었다. 이 둘 사이의 엄청난 속도 격차를 메우는 중간 다리가 필요해졌다.
- **핵심 직관**: 작업대(RAM)와 창고(디스크) 사이에, 끄지 않아도 날아가지 않는 아주 큰 '서랍장(PMEM)'을 책상 바로 밑에 달아놓은 것과 같다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| SCM (Storage Class Memory) | 스토리지의 비휘발성과 메모리의 속도를 갖춘 융합 계층 | 하이브리드 자동차 |
| Byte-addressable | 블록(수 KB) 단위가 아닌 1바이트 단위로 데이터를 덮어쓰고 읽는 속성 | 단어 하나만 수정하기 |
| DAX (Direct Access) | OS의 페이지 캐시를 거치지 않고 애플리케이션이 직접 PMEM에 접근하는 기능 | 중간 상인(OS) 없이 직거래 |
| PMDK | 퍼시스턴트 메모리를 활용하기 위한 인텔의 오픈소스 개발 키트 | 서랍장 활용 전용 설명서 |

## 깊이 이해
- **배경·문제의식**: 기존 스토리지는 PCIe나 SATA 인터페이스를 거치고, 파일 시스템을 통해 블록 단위로 쪼개야 하므로 아무리 빠른 SSD도 병목(Overhead)이 컸다. 메모리 버스(DDR)에 직결되면서도 비휘발성인 매체가 요구되었다.
- **작동 원리**: PMEM은 메모리 슬롯(DIMM)에 장착된다. 애플리케이션이 OS의 커널과 버퍼 캐시를 거치지 않고, CPU 캐시 라인(Cache-line) 단위로 메모리에 직접 접근(DAX)한다. 따라서 I/O 지연 시간이 디스크의 마이크로초(µs)에서 나노초(ns) 수준으로 떨어진다.
- **비유**: 예전엔 물건(데이터)을 찾으려면 밖의 창고(SSD)에 가서 상자 단위(블록)로 가져와야 했다면, 이제는 책상(CPU) 바로 옆에 영구 보존되는 서랍장(PMEM)이 있어서 필요한 서류 한 장(바이트)만 즉시 꺼낼 수 있다.
- **구체 예시**: 인텔의 Optane DC Persistent Memory (3D XPoint 기술). 최대 512GB의 용량을 메모리 슬롯에 꽂아 TB급 메모리 풀을 구축할 수 있다.
- **흔한 오해·주의점**: NVDIMM과 혼동하기 쉽다. NVDIMM은 물리적 모듈(DRAM+Flash 백업)이고, 퍼시스턴트 메모리는 MRAM, PRAM, 3D XPoint 등 신소재를 포함하는 더 넓은 개념의 **아키텍처/계층**이다.

## 연결 개념
- NVDIMM — 퍼시스턴트 메모리를 가장 먼저 상용화한 하이브리드 램 모듈
- 인메모리 데이터베이스 (IMDB) — 퍼시스턴트 메모리의 수혜를 가장 크게 받는 워크로드 (예: SAP HANA)
- CXL (Compute Express Link) — 인텔 Optane 단종 이후, PMEM의 사상을 네트워크 레벨로 확장하여 계승하는 차세대 인터페이스

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 퍼시스턴트 메모리(PMEM)는 DRAM의 속도·바이트 단위 접근(Byte-addressability) 특성과 NAND의 비휘발성(Non-volatility)을 동시에 제공하는 신개념 메모리-스토리지 융합 계층이다.
> 2. **가치**: OS의 블록 파일 시스템(버퍼 캐시)과 I/O 스택 병목을 우회하는 DAX(Direct Access)를 통해, 애플리케이션의 I/O 지연시간을 획기적으로 단축한다.
> 3. **판단 포인트**: 신소재(3D XPoint 등) 기반의 물리적 모듈 자체보다, PMDK 및 DAX 지원 파일 시스템 적용 등 애플리케이션 계층의 아키텍처 개편이 성능의 핵심이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 메모리 계층 구조의 병목 해결 방안 이해 | Storage Class Memory(SCM), Byte-addressable, DAX | PMEM을 단순히 '빠른 SSD'로 블록 장치 취급 |
| 기존 I/O 스택과의 차이점 분석 | 커널 버퍼/페이지 캐시 우회(Zero-copy), 문맥 교환 최소화 | 물리적 매체(MRAM 등) 이름만 나열하고 S/W 구조 변화 누락 |

> 요약: 하드웨어의 특성(DRAM 슬롯 장착, 비휘발성)뿐 아니라, OS의 I/O 스택(DAX)을 우회하는 소프트웨어 메커니즘을 강조한다.

## Ⅰ. 개요 및 필요성

- 개요: 퍼시스턴트 메모리(Persistent Memory)는 메모리 버스에 장착되어 바이트 단위 접근이 가능하면서도 전원이 꺼져도 데이터를 유지하는 중간 저장 계층이다.
- 배경: DRAM은 용량 확장 비용이 비싸고 휘발성이며, NAND SSD는 I/O 스택(블록 변환, 문맥 교환) 오버헤드로 인해 지연시간(Latency) 병목이 발생함
- 필요성: 초대형 AI 데이터셋과 인메모리 DB 워크로드에서, 재부팅 시 수 TB 데이터 로딩 지연을 막고 극단적인 I/O 가속을 제공하기 위해 필요함

---

## Ⅱ. 구조 및 구성요소

```text
Application ---> PMDK (User Space)
                   |
[ DAX File System ]  <--- (버퍼 캐시 우회 / Zero-copy)
                   |
Memory Bus (DDR) ---> NVDIMM / 3D XPoint (Persistent Memory)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| DAX (Direct Access) | OS 페이지 캐시를 생략하고 메모리 맵(mmap) 지원 | 블록 변환(Block Translation) 병목 제거 |
| PMDK (PM Dev Kit) | 애플리케이션이 PMEM을 쉽게 다룰 수 있게 돕는 라이브러리 | 원자성(Atomicity), 동기화 등 트랜잭션 보장 |
| App Direct Mode | 스토리지가 아닌 메모리 주소(Byte 단위)로 직접 할당 | 최상의 성능 (기존 코드 수정 필요) |
| Memory Mode | PMEM을 거대 DRAM처럼 취급 (DRAM은 캐시 역할) | 코드 수정 없이 대용량 확보 (휘발성 모드) |

> 요약: 하드웨어를 메모리 슬롯에 장착하는 것에 더해, DAX와 PMDK를 통한 소프트웨어 스택 최적화가 필수적이다.

---

## Ⅲ. 동작원리 및 흐름도

```text
App 데이터 쓰기 -> DAX 인터페이스 호출 -> CPU Cache Line 단위 전송 -> PMEM 즉각 반영
```

- 1단계 [접근 요청]: 애플리케이션이 파일 API 대신 메모리 맵핑(mmap)을 통해 할당된 주소 공간 요청
- 2단계 [커널 우회]: OS 커널의 인터럽트나 컨텍스트 스위칭 없이, CPU가 Load/Store 명령어로 직접 접근
- 3단계 [바이트 단위 기록]: 블록(4KB)이 아닌 캐시 라인(64Byte) 단위로 데이터가 PMEM에 쓰여짐
- 4단계 [영속성 보장]: 플러시(clflush) 명령어를 통해 CPU 캐시의 데이터가 PMEM 하드웨어로 확정(Commit)

> 요약: 전통적 디스크 쓰기(블록 변환, 인터럽트 발생, 디스크 기록) 과정을 Load/Store 명령어 단 두 줄로 압축한다.

---

## Ⅳ. 특징
- 지연시간 혁신: NVMe SSD(수십 µs) 대비 수백 ns 수준으로 지연시간 감축, 시스템 전체 응답성 개선
- TCO 절감: 비싼 고용량 DRAM을 대체하여 대용량 메모리 노드(Scale-up) 구축 시 비용 효율성 확보
- 재시동(Warm-up) 제로: 인메모리 DB 서버 재부팅 시 데이터를 디스크에서 메모리로 적재할 필요 없이 즉시 서비스 투입

> 요약: 용량은 DRAM을 압도하고, 속도는 SSD를 압도하여 두 매체의 치명적 약점(비용, 지연시간)을 융합적으로 해결한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 메인 메모리 (DRAM) | 퍼시스턴트 메모리 (PMEM) | 고성능 스토리지 (NVMe SSD) |
|:---|:---|:---|:---|
| 데이터 영속성 | 휘발성 | 비휘발성 | 비휘발성 |
| 접근 단위 | 바이트 (Byte) | 바이트 (Byte) | 블록 (Block, 4KB~) |
| 지연시간 | 10~50 ns | 100~300 ns | 10~100 µs |
| I/O 경로 | CPU Load/Store | CPU Load/Store (DAX) | OS File System, PCIe |

> 요약: PMEM은 DRAM보다는 약간 느리지만, SSD와 비교 불가능한 바이트 접근 및 Zero-copy 특성을 지닌다.

**PMEM 도입 리스크·대응:**
- [레거시 호환성]: 기존 소프트웨어는 블록 디스크(파일 입출력)로만 작동하여 PMEM의 바이트 접근 이점 상실 → [대응 방안] Memory Mode 적용으로 단순 용량 확장 후, 장기적으로 App Direct Mode(코드 리팩토링)로 전환
- [벤더 독점 단종]: 인텔 Optane 사업 철수 등 특정 매체 단종 리스크 → [대응 방안] CXL(Compute Express Link) 기반 표준 메모리 풀링 아키텍처로 벤더 종속 탈피 (지표: 표준 CXL 장치 수급률)

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. DBMS 성능 가속화: Oracle, Redis 등 인메모리 환경에서 Redo Log 및 주요 테이블을 PMEM에 맵핑하여 병목이었던 디스크 쓰기 지연 원천 제거
2. 대용량 AI 인퍼런스 서버: 딥러닝 모델 크기가 수백 GB에 달할 때, DRAM 대신 PMEM Memory Mode를 적용해 비용 효율적인 고용량 인퍼런스 서버 구축
3. 가상화 하이퍼바이저 캐시: vSAN 등 하이퍼컨버지드 인프라(HCI) 환경에서 Write Buffer로 PMEM을 구성하여 전체 VM의 I/O 성능 극대화

**결론 (2줄):**
- 기술사 판단: PMEM은 하드웨어 성능보다 DAX 기반 I/O 스택의 혁신이 본질이다. 레거시를 단순히 얹는 것(Memory Mode)을 넘어 앱 레벨 최적화(App Direct)를 해야 투자 효과를 본다.
- 향후 방향: 모듈 형태의 SCM은 단종 추세이나, 그 철학과 스택은 PCIe 기반 CXL 메모리 확장 장치로 이식되어 데이터센터 랙 단위의 메모리 공유 시대로 발전하고 있다.
