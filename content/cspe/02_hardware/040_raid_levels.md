# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 여러 개의 물리적 디스크를 묶어 하나의 논리적 디스크처럼 관리하여, 속도를 높이거나(성능) 데이터 손실을 막는(가용성) 스토리지 기술
- **왜 필요한가**: 디스크 하나는 속도도 느리고 고장 나면 데이터가 다 날아간다. 여러 개를 묶어 동시 작업(빠름)과 복제본(안전)을 만들고 싶다.
- **핵심 직관**: "짐(데이터)을 여러 트럭(디스크)에 쪼개서 한 번에 보내면 빠르고(스트라이핑), 똑같은 짐을 다른 트럭에 복사해 보내면 하나가 사고 나도 안전하다(미러링/패리티)."

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| Striping (스트라이핑) | 데이터를 여러 조각(스트라이프)으로 나누어 여러 디스크에 동시 분산 기록 (성능 목적) | "책 100권을 트럭 2대에 50권씩 동시에 싣기" |
| Mirroring (미러링) | 똑같은 데이터를 다른 디스크에 복사본으로 남김 (안전 목적) | "A 트럭 짐과 똑같은 짐을 B 트럭에 하나 더 싣기" |
| Parity (패리티) | 디스크 하나가 고장 났을 때, 나머지 데이터들을 역산하여 깨진 데이터를 복구하는 수학적 정보 | "A+B=C에서, B가 지워져도 A와 C(패리티)를 알면 B를 복원" |
| Write Penalty | 데이터를 쓸 때 패리티를 계산하고 기존 정보를 갱신하느라 디스크 I/O가 여러 번 추가로 발생하는 현상 | "물건 하나 넣을 때마다 전체 장부 총합을 다시 계산하는 수고" |

## 깊이 이해
- **배경·문제의식**: 업무 시스템에서는 디스크 고장으로 인한 서비스 중단이 치명적이다. 단순히 백업만 하면 복구에 시간이 오래 걸리므로, 디스크 1~2개가 죽어도 서비스는 즉각 정상 동작하는 실시간 무중단 환경(Redundancy)이 필요하다.
- **작동 원리 (레벨별 핵심)**:
  - **RAID 0 (스트라이핑)**: 무조건 조각내서 분산 기록. 엄청 빠르지만 디스크 1개만 죽어도 전체 데이터 증발. (안전도 0)
  - **RAID 1 (미러링)**: 무조건 똑같이 2개 복사. 안전하지만 디스크 2개 사서 1개 용량밖에 못 씀. (비용 극악)
  - **RAID 5 (스트라이핑 + 패리티 분산)**: 최소 3개 디스크. 조각내서 쓰되, 복구용 암호(패리티)를 디스크마다 골고루 섞어 둠. 1개 죽어도 복구 가능. (성능+안전+용량 가성비 타협)
  - **RAID 6 (패리티 2개)**: 최소 4개 디스크. RAID 5와 같지만 패리티를 2개 둬서 디스크 2개가 동시에 죽어도 버팀. (요즘 대용량 디스크 환경 필수)
  - **RAID 10 (1+0 구조)**: 디스크들을 2개씩 짝지어 미러링(안전)한 뒤, 그 덩어리들을 스트라이핑(속도)으로 묶음. 최소 4개 디스크. 패리티 계산이 없어서 성능 최상이나 비용 비쌈. (DB용 필수)
- **비유**: 
  - RAID 0: 팀 과제를 N명이 나눠서 함 (빠르지만 1명 잠수타면 과제 망함)
  - RAID 1: 팀 과제를 2명이 똑같이 풀로 다 함 (안전하지만 비효율적)
  - RAID 5: N명이 나눠서 하되, 각자 다른 사람 작업 요약본을 들고 있음 (1명 잠수타도 복구 가능)
- **구체 예시**: 20TB 디스크 5개로 RAID 5를 묶으면 총 80TB를 쓴다(20TB는 패리티 공간). 디스크 1개가 고장 나도 멈추지 않는다.
- **흔한 오해·주의점**: "RAID를 구성했으니 백업은 안 해도 된다?" 절대 안 된다. 파일 삭제 명령이나 랜섬웨어가 돌면 RAID 1(거울)은 똑같이 빛의 속도로 양쪽 디스크에서 데이터를 다 지워버린다. 기계 고장만 막을 뿐 논리적 오류 방어는 못 한다.

## 연결 개념
- MTTDL (Mean Time To Data Loss) — 디스크 배열에서 데이터가 완전히 소실되기까지의 평균 시간
- Erasure Coding (이레이저 코딩) — 클라우드 분산 스토리지에서 RAID를 소프트웨어적으로 대체하는 고급 패리티 분산 알고리즘
- Rebuild Time (리빌드 시간) — 디스크 교체 후 패리티를 연산해 데이터를 원래대로 되살리는 시간 (대용량 디스크일수록 리빌드 중 추가 고장 위험 큰)

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: RAID는 여러 물리 디스크를 묶어 논리적 단일 볼륨으로 구성, 스트라이핑(성능)·미러링(가용성)·패리티(복구력) 기법을 조합하는 스토리지 계층 구조다.
> 2. **가치**: 디스크 장애 시에도 서비스를 무중단 지속(Fault Tolerance)하며, 병렬 I/O를 통해 스토리지 병목 현상을 해소한다.
> 3. **판단 포인트**: 레벨별(0,1,5,6,10) 동작 원리를 도식화하고, 워크로드(DB, 백업, 스트리밍)에 맞는 레벨 선택 기준과 'Write Penalty' 오버헤드를 반드시 연계해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 데이터 가용성 및 보호 메커니즘 이해 | 스트라이핑, 미러링, 패리티 연산 | 레벨 이름만 나열하고 작동 원리(패리티 등) 누락 |
| 워크로드 맞춤형 인프라 설계 역량 | R/W 트랜잭션 비율에 따른 성능(RAID 10) vs 가용성(RAID 6) 판단 기준 | 무조건 숫자가 높을수록 좋다고 서술 |
| 디스크 대용량화에 따른 리스크 인지 | 리빌드 타임 증가, Write Penalty, 이중 장애 대응(RAID 6) | 백업(Backup)과 RAID(HA)의 목적 혼동 |

> 요약: RAID 문제는 각 레벨 구조를 암기하는 데 그치지 않고, "DB 서버에는 왜 RAID 5 대신 10을 쓰는가?" 같은 성능(Write Penalty) 트레이드오프를 설명해야 득점한다.

## Ⅰ. 개요 및 필요성

- 개요: 다수의 저렴한 물리 디스크를 배열로 묶어 하나의 고성능·고가용성 논리 볼륨으로 제공하는 스토리지 가상화 기술
- 배경: 단일 디스크 드라이브의 느린 I/O 속도 한계와 장애 발생 시 즉각적인 데이터 손실(SPOF) 리스크
- 필요성: 성능 향상(스트라이핑)과 데이터 무결성 보호(미러링 및 패리티 연산)를 시스템 중단 없이 동시 달성하기 위한 구조 필수

---

## Ⅱ. 구조 및 구성요소 (핵심 기법 3가지)

```text
Host I/O Request -> [ RAID Controller / SW Layer ]
                      |
        +-------------+-------------+
  스트라이핑(성능) / 미러링(복제) / 패리티(오류복원) 적용
        |             |             |
   [Disk 1]      [Disk 2]      [Disk N]
```

| 구성요소 | 메커니즘 | 적용 특징 |
|:---|:---|:---|
| 스트라이핑 (Striping) | 데이터를 청크 단위로 분할하여 다수 디스크에 동시 병렬 기록 | I/O 대역폭 및 성능 선형 증가 (용량 100% 활용) |
| 미러링 (Mirroring) | 원본 데이터와 100% 동일한 복제본을 쌍(Pair) 디스크에 동시 기록 | 성능 저하 없이 최고 가용성 보장 (용량 50% 효율) |
| 패리티 (Parity) | 디스크 간 배타적 논리합(XOR) 연산을 통해 복구용 메타데이터 분산 저장 | 최소한의 용량 손실(N-1)로 디스크 1~2개 장애 복원 |

> 요약: RAID의 모든 레벨은 위 세 가지 요소(나누기, 똑같이 베끼기, 역산용 수식 남기기)의 배합으로 결정된다.

---

## Ⅲ. 동작원리 및 흐름도 (레벨별 비교)

```text
RAID 0 : 데이터 분산 -> A1(D1), A2(D2), A3(D3) ... (패리티 없음, 최고 속도)
RAID 1 : 데이터 복제 -> A1(D1), A1(D2) ... (1:1 거울, 안전 최우선)
RAID 5 : 분산 + 패리티 1개 -> A1(D1), A2(D2), Parity_A(D3) ... (가성비 균형)
RAID 6 : 분산 + 패리티 2개 -> A1(D1), A2(D2), P_A(D3), Q_A(D4) ... (이중 장애 대비)
RAID 10 : 미러링 후 분산 -> [D1=D2](미러링), [D3=D4](미러링) 구조 위에 스트라이핑
```

| 레벨 | 필요 디스크 | 공간 효율성 | 가용성(허용 장애) | 쓰기 성능 오버헤드 |
|:---:|:---:|:---:|:---:|:---:|
| 0 | 최소 2개 | 100% (N) | 0개 (위험) | 없음 (최상) |
| 1 | 최소 2개 | 50% (N/2) | 1개 (쌍 중 1개) | 없음 (우수) |
| 5 | 최소 3개 | N-1 | 1개 | 패리티 연산 (Write Penalty 4) |
| 6 | 최소 4개 | N-2 | 2개 | 이중 패리티 연산 (Write Penalty 6) |
| 10 | 최소 4개 | 50% (N/2) | 1 Array당 1개 | 미러링 동시 기록 (우수, 패리티 없음) |

> 요약: RAID 레벨 번호는 단순히 버전이 아니라, 비용·성능·가용성 사이의 비중을 어떻게 타협했는지를 보여주는 코드다.

---

## Ⅳ. 특징

- [Write Penalty (쓰기 패널티) 존재]: RAID 5와 6은 데이터 갱신 시 `기존 데이터 읽기 -> 기존 패리티 읽기 -> 새 패리티 XOR 계산 -> 새 데이터 쓰기 -> 새 패리티 쓰기`의 과정이 필요하여 Random 쓰기 부하가 극심함
- [용량 대비 가용성 균형]: 고용량 단일 볼륨이 필요한 파일 서버는 용량 손실을 1~2 디스크로 방어하는 RAID 5, 6 구조가 TCO 측면에서 압도적으로 유리
- [복합 레벨 지원]: Nested RAID(0+1, 1+0, 50 등)를 통해 미러링의 가용성과 스트라이핑의 속도를 물리 계층에서 동시 확보 가능

> 요약: 성능을 위해 패리티를 배제할지(RAID 10), 비용 효율을 위해 패리티 부하를 감수할지(RAID 5/6)의 트레이드오프가 핵심이다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | OLTP DB 서버 (Random Write 잦음) | 백업/아카이빙 스토리지 | 대규모 파일 공유 서버 | 선택 기준 |
|:---|:---|:---|:---|:---|
| 최적 RAID 레벨 | RAID 10 | RAID 6 | RAID 5 또는 6 | I/O 패턴 및 용량 민감도 |
| 성능 판단 요인 | 패리티 연산 부재로 쓰기 성능 최적 | 쓰기 속도보다 데이터 장기 안전성 | 읽기 대역폭 중시 (스트라이핑) | Write Penalty 회피 여부 |
| 리스크 통제 | 디스크 비용(50% 손실) 투자 감수 | 디스크 2개 동시 장애(이중 장애) 방어 | 단일 노드 용량 극대화 | TCO vs 업무 중단 손실 |

> 요약: 데이터베이스는 무조건 쓰기 패널티가 없는 RAID 10을 쓰며, 단순 저장용 공간은 용량 가성비가 높은 RAID 5/6을 배정한다.

**리스크·대응:**
- URE (Unrecoverable Read Error) 및 리빌드 장기화: 테라바이트급 디스크 고장 후 RAID 5 복구(Rebuild) 중 다른 디스크에 숨은 불량(URE)이 발현되면 어레이 전체 파괴 → 고용량 4TB 이상 환경에서는 RAID 5를 폐기하고 RAID 6 강제 적용
- 배터리 방전 시 패리티 훼손(Write Hole): 컨트롤러 정전 시 패리티 갱신이 중단되어 파일시스템 붕괴 → 컨트롤러 캐시 BBU(Battery Backup Unit) 장착 및 비휘발성 캐시(NVRAM) 적용

**도입 후 점검 지표:**
- Rebuild Performance: 디스크 강제 오프라인 후 리빌드 진행 시 호스트 I/O 성능 저하 방어율(백그라운드 리빌드 큐 우선순위 조절)
- 상태 모니터링: 핫스페어(Hot-Spare) 디스크 활성화 테스트 및 컨트롤러 배터리 헬스 체크

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. Mission Critical DB 이중화: 금융 결제 등 지연에 민감한 RDBMS 스토리지 영역(Data 및 Redo Log)을 완벽하게 분리하여 RAID 10으로 구성해 IOPS 한계 돌파
2. 가상화 통합 스토리지: 다수 VM이 섞여 Random I/O가 빗발치는 스토리지에 SSD 캐싱(Tiering)과 결합한 RAID 6를 적용하여 용량 낭비를 줄이고 안전성 확보
3. 클라우드 오브젝트 스토리지 전환: 단일 시스템 내 하드웨어 RAID 한계를 넘기 위해 클러스터 노드 간 분산 저장하는 Erasure Coding(이레이저 코딩) 방식으로 전환

**결론 (2줄):**
- 기술사 판단: RAID는 단일 디스크의 한계를 극복하는 완벽한 가용성 계층이나, 기계적 장애 방어 수단일 뿐 랜섬웨어나 논리적 데이터 삭제를 방어하는 백업(Backup)을 대체할 수 없다.
- 향후 방향: 전통적인 하드웨어 컨트롤러 기반 RAID 5/6은 대용량 드라이브 리빌드 병목으로 인해 점차 쇠퇴하고, vSAN, Ceph 등 소프트웨어 정의 스토리지(SDS) 및 이레이저 코딩으로 주도권이 넘어갈 것이다.
