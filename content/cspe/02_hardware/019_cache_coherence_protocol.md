## 미리 알고가기

- 캐시 일관성은 여러 코어가 같은 데이터의 최신성을 맞추는 규칙임
- MESI는 Modified·Exclusive·Shared·Invalid 4개 상태를, MOESI는 Owned 상태를 더한 5개 상태를 사용함
- 프로토콜 비용은 공유 패턴과 무효화 메시지 수에 좌우됨
- dirty 데이터: 캐시에만 반영되고 메모리에는 아직 쓰이지 않은 최신 값임
- 거짓 공유(False Sharing): 서로 다른 변수가 같은 캐시 라인에 있어 무관한 쓰기로도 캐시 라인이 무효화되는 현상임
- 스누프 필터: 불필요한 스누프 트래픽을 줄이기 위해 캐시 라인 보유 여부를 요약해두는 하드웨어 구조임

## 작성 근거(검토용)

- MESI·MOESI를 상태 이름 나열보다 소유권·무효화·dirty 데이터 전달 규칙으로 설명함
- MESI와 MOESI를 상태 구성·dirty 데이터 공급·반영 비용으로 비교함
- 읽기·쓰기 요청의 상태 전이와 MOESI Owned 상태의 공급 책임을 별도 흐름으로 설명함

## Ⅰ. 개요

- **정의/개념**: 캐시 일관성 프로토콜은 멀티코어 환경에서 각 코어 캐시에 존재하는 동일 주소 데이터의 상태를 관리해 모든 코어가 논리적으로 일관된 값을 보도록 하는 하드웨어 통신 규약임
- **배경/필요성**: 코어별 전용 캐시에 저장된 동일 데이터의 최신성을 맞추기 위해 상태 전이와 무효화 규칙이 필요함

### 쉽게 이해하기 (학습용)
- 여러 사람이 같은 문서를 각자 책상에 복사해 두고 쓸 때, 누군가 고치면 나머지 사본도 최신 내용으로 맞춰야 하는 것과 같음

## Ⅱ. 특징

- MESI는 M/E/S/I 상태로 캐시 라인의 수정·독점·공유·무효 상태를 구분함
- MOESI는 Owned 상태를 추가해 dirty 데이터를 메모리에 먼저 기록하지 않고 다른 캐시에 공급함
- 일관성 유지를 위한 무효화·스누프 메시지가 인터커넥트 대역폭을 사용함
- 거짓 공유가 발생하면 서로 다른 변수를 쓰는 코어 사이에서도 캐시 라인이 반복 무효화됨

### 쉽게 이해하기 (학습용)
- 캐시 라인 상태는 문서 사본에 붙이는 "내가 고치는 중/나만 봄/다같이 봄/버림" 표식과 같음
- MOESI의 Owned는 그 표식을 단 사람이 원본 서랍에 넣기 전에 옆 사람에게 바로 복사해주는 것과 같음
- 거짓 공유는 서로 다른 항목이 같은 페이지에 있다는 이유만으로 무관한 수정에도 페이지 전체를 다시 받아야 하는 낭비임

## Ⅲ. 종류 및 비교

| 판단 기준 | MESI | MOESI |
|:---|:---|:---|
| 상태 구성 | M/E/S/I 4개 상태 | Owned를 더한 5개 상태 |
| dirty 데이터 공급 | Modified 소유자가 메모리에 반영한 뒤 Shared로 전환함 | Owned 캐시가 메모리 반영 없이 다른 캐시에 직접 공급함 |
| 반영 비용 | dirty 공유 전에 write-back이 필요할 수 있고 4개 상태 전이를 검증함 | Owned 라인 교체 전까지 반영을 지연할 수 있고 5개 상태 전이를 검증함 |

> 요약: MESI는 Modified·Exclusive·Shared·Invalid 상태를 사용하고, MOESI는 Owned 상태를 추가해 수정 데이터를 메모리 기록 전 공유함.

### 쉽게 이해하기 (학습용)
- MESI는 고친 내용을 원본 금고(메모리)에 넣고 나서야 남에게 보여주고, MOESI는 금고에 넣기 전에 옆 사람에게 바로 보여줌

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 캐시 라인 상태 | M/E/S/I/O 상태가 현재 데이터 소유와 공유 수준을 나타냄 |
| 스누프·디렉터리 신호 | 다른 코어의 접근을 통지해 상태 전이를 시작함 |
| 무효화 로직 | 쓰기 권한을 요청한 코어가 다른 캐시의 사본을 무효화함 |
| 데이터 전달 경로 | 캐시 간 또는 메모리와 캐시 간 최신 데이터를 전달함 |

```text
+------------------+     +--------------------+     +--------------------+
| 캐시 라인 상태    | --> | 무효화 로직          | --> | 데이터 전달 경로      |
+------------------+     +--------------------+     +--------------------+
            |
            v
   +----------------------+
   | 스누프·디렉터리 신호   |
   +----------------------+
```

> 요약: 캐시 라인 상태, 무효화, 데이터 전달 경로가 최신 데이터 공유 방식을 결정함.

### 쉽게 이해하기 (학습용)
- 상태표(캐시 라인 상태), 옆방 소식통(스누프·디렉터리 신호), 회수 담당(무효화 로직), 배달원(데이터 전달 경로)이 각자 역할을 맡아 최신 데이터를 옮김

## Ⅴ. 원리 및 절차 흐름도

```text
[읽기 미스] 소유자 조회 -> 최신 데이터 전달 -> 요청 캐시 Exclusive 또는 Shared 전환
[쓰기 요청] 공유자 조회 -> 다른 사본 Invalid 전환 -> 요청 캐시 Modified 전환
[MOESI]     Modified 소유자의 dirty 데이터 전달 -> Owned + Shared 전환
```

1. **읽기 미스**: 다른 캐시나 메모리에서 최신 데이터를 받고, 공유 사본이 없으면 Exclusive로, 있으면 Shared로 전환함
2. **쓰기 요청**: Exclusive 상태면 즉시, Shared 상태면 다른 공유 사본을 무효화한 뒤 쓰기 코어가 Modified 소유권을 얻음
3. **MOESI dirty 공유**: Modified 소유자가 데이터를 직접 전달하고 Owned 상태로 공급 책임을 유지함

> 요약: 일관성 프로토콜은 공유 상태를 확인하고 상태 전이, 무효화, 데이터 전달로 최신성을 맞춤.

### 쉽게 이해하기 (학습용)
- 책을 빌리러 가면 누가 갖고 있는지 물어 최신본을 받고, 내가 고쳐 쓰려면 다른 사람 사본부터 회수한 뒤 쓰고, 이미 고친 사람이 있으면 금고에 넣지 않고 바로 옆 사람에게 빌려주는 절차와 같음

## Ⅵ. 실무 사례

1. 멀티코어 CPU는 스누프 필터를 적용하고 일관성 메시지 비율과 인터커넥트 이용률을 확인함
2. 병렬 응용은 공유 변수 사이에 캐시 라인 패딩을 적용하고, 거짓 공유 실패율과 쓰기 무효화율을 확인함

### 쉽게 이해하기 (학습용)
- 소식통 명단을 요약해두면 불필요한 질문이 줄듯 스누프 필터가 트래픽을 줄이고, 서로 다른 물건을 같은 상자에 담지 않게 간격을 두면 거짓 공유가 줄어듦

## Ⅶ. 결론

- 캐시 일관성 프로토콜은 상태 전이와 무효화 규칙으로 여러 코어 캐시에 흩어진 동일 데이터를 논리적으로 일치시키는 하드웨어 통신 규약임
- dirty 데이터를 메모리에 반영한 뒤 공유할지 반영 전에 직접 공급할지를 기준으로 MESI와 MOESI를 선택하고, 거짓 공유로 인한 무효화 트래픽을 줄여야 함

### 쉽게 이해하기 (학습용)
- 누가 최신본을 갖고 언제 원본에 반영할지를 기준으로 두 방식 중 하나를 고르고, 상태 전환과 트래픽을 함께 관리해야 함
