## Ⅰ. 개요
- **정의**: SoC 내부 IP 간 통신을 패킷 기반 네트워크 토폴로지로 구현하는 온칩 통신 구조임
- **배경/필요성**: 공유 버스(079 참조)는 IP 수 증가 시 대역폭 병목이 발생하므로, 네트워크 방식으로 병렬 전송 경로를 확보할 필요가 있음
- **비유**: 단일 복도 대신 건물 전체에 엘리베이터·통로 망을 설치하는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 버스 대비 NoC의 구조적 장점 | 토폴로지·라우팅·흐름제어 메커니즘 | AMBA(079 참조) 대비 면적 오버헤드를 반드시 언급할 것 |

> 요약: 패킷 스위칭 기반 온칩 네트워크로 다수 IP의 병렬 통신을 지원하는 구조임

## Ⅱ. 구성요소
```text
[IP]-NI--+--Router--+--Router--+--NI-[IP]
         |          |          |
[IP]-NI--+--Router--+--Router--+--NI-[IP]
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Router | 패킷을 목적지 방향으로 전달하는 스위칭 노드임 | 도로 교차로의 신호등 |
| Network Interface(NI) | IP의 데이터를 패킷으로 변환/역변환하는 어댑터임 | 우체국 접수 창구 |
| Link | 라우터 간 물리적 배선 채널임 | 도로 자체 |

> 요약: Router-NI-Link 세 요소가 메시 형태의 온칩 네트워크를 구성함

## Ⅲ. 절차
```text
패킷화(NI) --> 라우팅(Router) --> 스위칭/전달 --> 역패킷화(NI)
```
- 1단계: 송신 NI가 IP의 트랜잭션을 헤더·페이로드 플릿으로 패킷화함
- 2단계: Router가 라우팅 알고리즘(XY 등)으로 출력 포트를 결정함
- 3단계: 가상 채널·웜홀 방식으로 플릿을 다음 Router로 전달함
- 4단계: 수신 NI가 플릿을 재조립하여 대상 IP에 트랜잭션을 전달함

> 요약: 패킷화-라우팅-스위칭-역패킷화의 4단계로 온칩 데이터가 전달됨

## Ⅳ. 문제점
- 면적 오버헤드: Router·NI 로직이 IP마다 추가되어 칩 면적이 증가함
- 레이턴시 비결정성: 네트워크 혼잡 시 패킷 대기로 실시간 보장이 어려움
- 데드락 위험: 순환 의존 경로가 생기면 패킷이 영구 대기 상태에 빠짐

> 요약: 면적 증가, 레이턴시 비결정성, 데드락이 NoC의 주요 과제임

## Ⅴ. 개선방안
1. 단기: 경량 라우터 설계(버퍼 축소·포트 공유)로 면적 오버헤드를 감소시킴
2. 중기: QoS 우선순위 가상 채널을 할당하여 실시간 트래픽의 레이턴시 상한을 보장함
3. 장기: 데드락-프리 라우팅(Turn Model 등)과 적응형 알고리즘을 적용하여 순환 의존을 원천 차단함

> 요약: 경량 라우터, QoS 채널, 데드락-프리 라우팅으로 NoC 한계를 극복함

## Ⅵ. 전망
- 발전 방향: 3D 적층 칩에서 수직 TSV 링크를 활용한 3D-NoC가 확산될 것임
- 기술사적 판단: 수백 코어 시대에 NoC는 SoC 인터커넥트의 기본 구조로 자리잡음
- 기술사 제언: 워크로드 특성에 따른 토폴로지 선택 가이드라인 수립이 필요함
