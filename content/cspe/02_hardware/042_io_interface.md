## Ⅰ. 개요
- **정의**: CPU와 주변 장치 간 데이터·제어·상태 신호를 중계하는 하드웨어 회로
- **배경/필요성**: CPU와 주변 장치는 동작 속도·데이터 폭·신호 형식이 상이하여 이를 변환·동기화하는 중간 계층이 필요함
- **비유**: 서로 다른 언어를 쓰는 두 사람 사이의 통역사와 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| I/O 인터페이스의 기능 분류와 데이터 전송 방식 | 데이터 버퍼링, 프로토콜 변환, 주소 디코딩 | Memory-Mapped I/O와 Isolated I/O 차이 혼동 금지 |

> 요약: 속도·형식이 다른 CPU와 주변 장치 사이를 중계하는 하드웨어 계층임

## Ⅱ. 구성요소
```text
  +------+     +--------------------+     +-----------+
  | CPU  |<--->| I/O 인터페이스      |<--->| 주변 장치  |
  +------+     |                    |     +-----------+
               | - 데이터 레지스터   |
               | - 상태 레지스터     |
               | - 제어 레지스터     |
               | - 주소 디코더       |
               +--------------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 데이터 레지스터 | CPU-장치 간 전송 데이터를 임시 보관하여 속도 차이를 흡수함 | 택배 보관함 |
| 상태 레지스터 | 장치의 준비(Ready)·완료(Done)·오류(Error) 상태를 비트 플래그로 보고함 | 신호등 표시판 |
| 제어 레지스터 | CPU가 장치에 내리는 명령(읽기·쓰기·리셋 등)을 전달함 | 작업 지시서 |
| 주소 디코더 | 버스 주소를 해석하여 해당 I/O 포트가 선택되었는지 판별함 | 우편번호 분류기 |

> 요약: 데이터·상태·제어 레지스터와 주소 디코더로 CPU-장치 간 통신을 중재함

## Ⅲ. 절차
```text
CPU 명령 발행 -> 주소 디코딩 -> 제어 신호 전달 -> 데이터 전송 -> 상태 반환
```
- 1단계: **명령 발행** — CPU가 I/O 명령을 실행하고, 버스에 장치 주소와 제어 신호를 올림
- 2단계: **주소 디코딩** — 인터페이스의 주소 디코더가 자신의 포트 주소와 비교하여 선택 여부를 판별함
- 3단계: **데이터 전송** — 데이터 레지스터를 경유하여 CPU → 장치(출력) 또는 장치 → CPU(입력) 방향으로 데이터를 이동함
- 4단계: **상태 반환** — 전송 완료·오류 발생 등 결과를 상태 레지스터에 기록하고 CPU가 이를 확인함

> 요약: 주소 선택 → 제어 전달 → 데이터 이동 → 상태 확인의 4단계 핸드셰이크임

## Ⅳ. 문제점
- **폴링 오버헤드**: 프로그램 제어 I/O 방식은 CPU가 상태 레지스터를 반복 확인하므로 CPU 사이클이 낭비됨
- **속도 불일치**: 고속 CPU와 저속 장치 간 데이터 레이트 차이가 크면 버퍼 언더런/오버런이 발생함
- **주소 공간 충돌**: 다수 장치가 동일 I/O 주소 범위에 매핑되면 디코딩 오류로 데이터 손실이 발생함

> 요약: 폴링 낭비, 속도 격차, 주소 충돌이 I/O 인터페이스의 주요 병목임

## Ⅴ. 개선방안
1. 단기: 인터럽트 구동 I/O로 전환하여 폴링 오버헤드를 제거함 (043 참조)
2. 중기: FIFO 버퍼 및 DMA 컨트롤러를 도입하여 CPU 개입 없이 블록 단위 전송으로 속도 불일치를 해소함 (044 참조)
3. 장기: 자동 주소 할당(PnP, PCIe Enumeration) 메커니즘을 적용하여 주소 충돌을 원천 방지함

> 요약: 인터럽트·DMA·자동 주소 할당으로 폴링·속도·충돌 문제를 단계적으로 해소함

## Ⅵ. 전망
- 발전 방향: PCIe Gen 6·CXL 등 고대역 직렬 인터페이스로 전환되어 CPU-장치 간 대역폭이 지속 확장됨
- 기술사적 판단: 인터페이스 표준화가 장치 호환성과 생태계 확장의 핵심 요소로 유지됨
- 기술사 제언: 차세대 인터커넥트 도입 시 레거시 장치 호환 계층을 함께 설계할 필요
