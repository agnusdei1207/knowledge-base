## 미리 알고가기

- I/O 인터페이스는 CPU와 주변장치 사이의 제어와 데이터 이동 방식을 정의하는 계층임
- 대표 제어 방식은 폴링, 인터럽트, DMA, 채널 I/O임
- 선택 기준은 CPU 개입 정도, 데이터 크기, 응답성, 장치 속도임
- ISR(인터럽트 서비스 루틴): 인터럽트 발생 시 실행되는 처리 코드임
- IOPS: 초당 입출력 처리 횟수를 나타내는 처리량 지표임
- 디바운싱: 짧은 시간에 중복 발생하는 신호를 걸러 하나의 이벤트로 처리하는 기법임

## 작성 근거(검토용)

- I/O 인터페이스는 CPU 역할, 전송 단위, 완료 확인을 비교 기준으로 정리함
- 구성요소는 장치 컨트롤러, 레지스터, DMA, 버스·인터럽트 라인으로 연결함
- 실무 판단은 전송량, CPU 사용률, 인터럽트 지연으로 구체화함

## Ⅰ. 개요

- **정의/개념**: I/O 인터페이스는 CPU·메모리·주변장치 사이에서 상태, 제어 신호, 데이터 경로를 조정해 입출력을 처리하는 하드웨어·제어 방식임
- **배경/필요성**: CPU가 모든 장치의 상태 조회와 데이터 복사를 맡으면 명령 실행 시간이 입출력에 사용되므로 장치별 제어 방식 분리가 필요함

## Ⅱ. 특징

- 데이터량과 응답 시간 요구에 따라 제어 방식 선택이 달라짐
- CPU의 상태 확인과 데이터 복사 역할을 전용 제어기로 옮기면 CPU 가용 시간은 늘지만 별도 제어 하드웨어가 필요함
- 상태 변화가 드문 장치는 인터럽트로 알리고, 연속 블록은 DMA로 전송하며, 여러 장치의 I/O 명령은 채널 I/O로 분리함
- 인터럽트 부하, 버퍼 관리, 버스 점유율이 운영 성능을 좌우함

## Ⅲ. 종류 및 비교

| 판단 기준 | 폴링 | 인터럽트 | DMA | 채널 I/O |
|:---|:---|:---|:---|:---|
| CPU 역할 | 상태 레지스터 반복 조회·데이터 이동 | ISR에서 상태 확인·데이터 처리 | 전송 조건 설정·완료 처리 | 채널 프로그램 작성·완료 처리 |
| 전송 단위 | 레지스터·소량 데이터 | 이벤트·소량 데이터 | 메모리 블록 | 여러 I/O 명령과 데이터 블록 |
| 완료 확인 | 상태 레지스터 조회 | 장치 인터럽트 | DMA 완료 인터럽트 | 채널 상태 보고 |

> 요약: 폴링은 CPU가 상태를 반복 조회하고, 인터럽트는 장치가 상태 변화를 알리며, DMA·채널 I/O는 데이터 이동을 CPU에서 분리함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 장치 컨트롤러 | 주변장치 상태 레지스터와 데이터 버퍼를 제공해 CPU가 장치를 제어할 수 있게 함 |
| 상태·제어 레지스터 | 준비·동작·오류 상태와 시작 명령을 교환하며 폴링과 인터럽트의 판정 기준이 됨 |
| DMA 엔진 | 메모리와 장치 사이 대량 전송을 CPU 대신 수행해 복사 오버헤드를 줄임 |
| 버스·인터럽트 라인 | 데이터 이동 경로와 비동기 알림 경로를 제공하며 충돌과 우선순위 관리가 필요함 |

```text
+-------------+     +----------------+     +------------------+     +-------------+
| CPU         | <-> | 장치 제어      | <-> | DMA·버스 경로    | <-> | 주변장치    |
+-------------+     +----------------+     +------------------+     +-------------+
         ^
         |
     인터럽트선
```

> 요약: 장치 컨트롤러와 레지스터가 상태를 노출하고 DMA와 버스가 대량 이동을 분담함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-----------------+     +----------------+     +-------------+
| I/O 요청 발생 | --> | 제어 방식 판단   | --> | 데이터 이동 수행 | --> | 완료 확인·처리 |
+-------------+     +-----------------+     +----------------+     +-------------+
```

1. **I/O 요청 발생**: 프로세스가 장치 접근을 요청함
2. **제어 방식 판단**: 데이터량과 응답성 요구에 따라 폴링, 인터럽트, DMA, 채널 I/O 중 하나를 선택함
3. **데이터 이동 수행**: 선택한 방식에 따라 CPU 또는 전용 하드웨어가 데이터를 이동함
4. **완료 확인 및 처리**: 상태 레지스터 조회 또는 인터럽트로 완료를 확인하고 후속 처리를 진행함

> 요약: I/O 요청은 데이터량과 응답성에 맞는 제어 방식을 거쳐 완료 확인 후 후속 처리로 이어짐.

## Ⅵ. 실무 사례

1. NVMe 장치는 DMA로 데이터 블록을 전송하고 IOPS·CPU 사용률을 확인함
2. 센서 이벤트는 인터럽트로 통지하고 디바운싱 후 인터럽트 지연·중복 이벤트 수를 확인함

## Ⅶ. 결론

I/O 방식은 CPU가 맡을 상태 확인·데이터 이동 범위를 기준으로 선택하며 이벤트 통지는 인터럽트, 블록 전송은 DMA, 복합 명령은 채널 I/O로 분리함.
