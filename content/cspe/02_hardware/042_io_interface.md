## 미리 알고가기

- I/O 인터페이스는 CPU와 주변장치 사이의 제어와 데이터 이동 방식을 정의하는 계층임
- 대표 제어 방식은 폴링, 인터럽트, DMA, 채널 I/O임
- 선택 기준은 CPU 개입 정도, 데이터 크기, 응답성, 장치 속도임

## Ⅰ. 개요

- **정의/개념**: I/O 인터페이스는 CPU와 메모리와 주변장치 사이에서 상태 확인과 제어 신호와 데이터 전송 경로를 조정해 입출력 처리를 수행하는 하드웨어 및 제어 방식의 집합임
- **배경/필요성**: 프로세서와 장치의 속도 차이가 크기 때문에 모든 입출력을 CPU가 직접 처리하면 연산 자원이 낭비되어, 장치 특성에 맞는 제어 방식 분리가 필요함

## Ⅱ. 특징

- 데이터량과 응답 시간 요구에 따라 제어 방식 선택이 달라짐
- CPU 개입이 줄수록 처리량은 올라가지만 하드웨어 구조는 복잡해짐
- 저속 장치는 인터럽트가, 대용량 전송은 DMA가, 대규모 시스템은 채널 I/O가 유리함
- 운영 성능은 인터럽트 부하와 버퍼 관리와 버스 점유 효율에 좌우됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 폴링 | 인터럽트 | DMA | 채널 I/O |
|:---|:---|:---|:---|:---|
| CPU 개입 | 매우 높음 | 중간 | 낮음 | 매우 낮음 |
| 적합 데이터 크기 | 소량 | 소량~중간 | 중간~대량 | 대량, 복합 I/O |
| 응답성 | 단순하나 비효율적 | 높음 | 높음 | 높음 |
| 대표 환경 | 단순 MCU | 일반 OS 장치 | 디스크, NIC | 메인프레임 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 장치 컨트롤러 | 주변장치 상태 레지스터와 데이터 버퍼를 제공해 CPU가 장치를 제어할 수 있게 함 |
| 상태, 제어 레지스터 | ready, busy, error 같은 장치 상태와 시작 명령을 교환하는 접점으로 폴링과 인터럽트의 기준점이 됨 |
| DMA 엔진 | 메모리와 장치 사이 대량 전송을 CPU 대신 수행해 복사 오버헤드를 줄임 |
| 버스, 인터럽트 라인 | 데이터 이동 경로와 비동기 알림 경로를 제공하며 충돌과 우선순위 관리가 필요함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 장치 요청 발생 | --> | 제어 방식 선택 | --> | 데이터 전송 수행 | --> | 완료 통지/후처리 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **장치 요청 발생**: 장치가 읽기 또는 쓰기 요구를 생성함
2. **제어 방식 선택**: 폴링, 인터럽트, DMA, 채널 I/O 중 적합한 방법을 사용함
3. **데이터 전송 수행**: CPU 또는 전용 하드웨어가 실제 전송을 처리함
4. **완료 통지 및 후처리**: 인터럽트나 상태 갱신으로 완료를 알리고 상위 계층이 후속 처리를 함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 폴링 기반 제어를 고속 장치에 적용하면 CPU가 상태 확인에 시간을 소모해 전체 처리량이 급감할 수 있음
   - 해결방안: 이벤트 중심 장치는 인터럽트나 DMA로 전환하고 CPU utilization과 device service time으로 효율을 검증함
2. 문제: 고속 네트워크 장치에서 인터럽트가 과도하게 발생하면 문맥 전환 비용 때문에 시스템 지연이 커질 수 있음
   - 해결방안: interrupt coalescing이나 adaptive polling을 적용하고 interrupt rate와 softirq time으로 개선 효과를 검증함
3. 문제: DMA 전송은 CPU 부하를 줄이지만 캐시 일관성과 버스 점유 충돌을 함께 유발할 수 있음
   - 해결방안: cache coherence 정책과 burst scheduling을 조정하고 DMA throughput과 cache miss impact로 안정성을 검증함

## Ⅶ. 적용 사례

- NVMe SSD 경로에서는 대용량 블록 전송에 DMA를 적용하고 확인 지표는 IOPS와 average latency임
- 임베디드 센서 제어에서는 저속 이벤트에 인터럽트를 적용하고 확인 지표는 interrupt latency와 CPU idle ratio임
- 메인프레임 입출력 경로에서는 채널 I/O로 복합 장치 작업을 오프로딩하고 확인 지표는 CPU offload ratio와 throughput임

## Ⅷ. 결론

I/O 인터페이스의 핵심은 장치 성격에 맞게 CPU 개입 수준을 조절하는 데 있으므로, 소량 제어는 인터럽트로 대량 전송은 DMA나 채널 I/O로 분리 설계해야 함.
