## 미리 알고가기

- I/O 인터페이스는 CPU와 주변장치 사이의 제어와 데이터 이동 방식을 정의하는 계층임
- 대표 제어 방식은 폴링, 인터럽트, DMA, 채널 I/O임
- 선택 기준은 CPU 개입 정도, 데이터 크기, 응답성, 장치 속도임

## Ⅰ. 개요

- **정의/개념**: I/O 인터페이스는 CPU·메모리·주변장치 사이에서 상태, 제어 신호, 데이터 경로를 조정해 입출력을 처리하는 하드웨어·제어 방식임
- **배경/필요성**: 프로세서와 장치의 속도 차이가 크기 때문에 모든 입출력을 CPU가 직접 처리하면 CPU 시간이 낭비되므로 장치별 제어 방식 분리가 필요함

## Ⅱ. 특징

- 데이터량과 응답 시간 요구에 따라 제어 방식 선택이 달라짐
- CPU 개입이 줄수록 처리량은 늘지만 하드웨어 구조는 복잡해짐
- 상태 변화가 드문 장치는 인터럽트로 알리고, 연속 블록은 DMA로 전송하며, 여러 장치의 I/O 명령은 채널 I/O로 분리함
- 인터럽트 부하, 버퍼 관리, 버스 점유율이 운영 성능을 좌우함

## Ⅲ. 종류 및 비교

| 판단 기준 | 폴링 | 인터럽트 | DMA | 채널 I/O |
|:---|:---|:---|:---|:---|
| CPU 개입 | 최대 | 중간 | 낮음 | 거의 없음 |
| 적합 데이터 크기 | 소량 | 소량~중간 | 중간~대량 | 대량, 복합 I/O |
| 응답성 | 대기 반복으로 낮음 | 이벤트 즉시 처리 | 전송 완료 통지 | 채널 단위 처리 |
| 대표 환경 | 단순 MCU | 일반 OS 장치 | 디스크, NIC | 메인프레임 |

> 요약: 폴링은 CPU가 상태를 반복 조회하고, 인터럽트는 장치가 상태 변화를 알리며, DMA·채널 I/O는 데이터 이동을 CPU에서 분리함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 장치 컨트롤러 | 주변장치 상태 레지스터와 데이터 버퍼를 제공해 CPU가 장치를 제어할 수 있게 함 |
| 상태·제어 레지스터 | ready, busy, error 같은 장치 상태와 시작 명령을 교환하는 접점으로 폴링과 인터럽트의 기준점이 됨 |
| DMA 엔진 | 메모리와 장치 사이 대량 전송을 CPU 대신 수행해 복사 오버헤드를 줄임 |
| 버스·인터럽트 라인 | 데이터 이동 경로와 비동기 알림 경로를 제공하며 충돌과 우선순위 관리가 필요함 |

```text
+-------------+     +----------------+     +------------------+     +-------------+
| CPU         | <-> | Device Control | <-> | DMA / Bus Path   | <-> | Device      |
+-------------+     +----------------+     +------------------+     +-------------+
         ^
         |
   Interrupt Line
```

> 요약: 장치 컨트롤러와 레지스터가 상태를 노출하고 DMA와 버스가 대량 이동을 분담함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 장치 요청 발생 | --> | 제어 방식 선택 | --> | 데이터 전송 수행 | --> | 완료 통지/후처리 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **장치 요청 발생**: 장치가 읽기 또는 쓰기 요구를 생성함
2. **제어 방식 선택**: 폴링, 인터럽트, DMA, 채널 I/O 중 적합한 방법을 사용함
3. **데이터 전송 수행**: CPU 또는 전용 하드웨어가 실제 전송을 처리함
4. **완료 통지 및 후처리**: 인터럽트나 상태 갱신으로 완료를 알리고 상위 계층이 후속 처리를 함

> 요약: I/O 처리는 장치 요청의 크기와 응답성에 맞춰 CPU 개입 수준을 조정함.

## Ⅵ. 실무 적용 및 유의점

1. NVMe·고속 NIC는 DMA·채널 I/O가 맞지만 인터럽트 폭주와 캐시 일관성을 관리해야 하므로 coalescing, IOMMU를 적용하고 IOPS, CPU utilization, interrupt rate로 확인함
2. 센서·제어 신호는 인터럽트가 맞지만 이벤트가 잦으면 CPU가 바빠지므로 debounce, buffering, adaptive polling을 적용하고 interrupt latency, CPU idle ratio로 확인함

## Ⅶ. 결론

I/O 인터페이스는 장치 속도와 데이터 크기에 맞춰 CPU 개입을 줄이는 구조이므로 소량 제어는 인터럽트, 대량 전송은 DMA·채널 I/O로 나눠 설계함.

## 작성 근거(검토용)

- I/O 인터페이스는 CPU 개입 수준, 데이터 크기, 응답성을 비교 기준으로 정리함
- 구성요소는 장치 컨트롤러, 레지스터, DMA, 버스·인터럽트 라인으로 연결함
- 실무 판단은 인터럽트 폭주, 캐시 일관성, 지연 지표를 중심으로 구체화함
