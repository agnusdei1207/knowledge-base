## 미리 알고가기

- DMA는 대량 데이터 전송을 CPU 대신 전용 컨트롤러가 수행하는 방식임
- CPU는 시작 주소와 길이와 방향만 설정하고 완료 시점에 통지받음
- 디스크, 네트워크, 오디오 스트리밍처럼 지속 전송 장치에 핵심적임

## Ⅰ. 개요

- **정의/개념**: DMA는 전용 컨트롤러가 버스 마스터로 동작해 주변장치와 메모리 사이의 데이터를 CPU 개입 없이 직접 전송하는 입출력 가속 기법임
- **배경/필요성**: 대량 블록 전송을 CPU가 직접 복사하면 계산 자원이 낭비되고 처리량이 떨어지므로, 복사 작업을 하드웨어에 위임할 필요가 있음

## Ⅱ. 특징

- CPU 부하를 크게 줄여 연산과 입출력을 병행하기 좋음
- 블록 전송과 스트리밍 처리에서 인터럽트 기반 방식보다 효율적임
- 버스 점유와 캐시 일관성 관리가 함께 필요함
- burst 전송, scatter-gather 같은 확장 기능으로 실제 장치 활용성이 높음

## Ⅲ. 종류 및 비교

| 판단 기준 | Programmed I/O | Interrupt-driven I/O | DMA |
|:---|:---|:---|:---|
| CPU 개입 | 매우 높음 | 중간 | 낮음 |
| 대용량 전송 적합성 | 낮음 | 중간 | 높음 |
| 구현 복잡도 | 낮음 | 중간 | 높음 |
| 대표 용도 | 단순 장치 | 일반 이벤트 장치 | SSD, NIC, 오디오 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| DMA 컨트롤러 | 전송 시작 주소와 길이와 방향을 받아 실제 메모리 이동을 수행함 |
| 버스 인터페이스 | DMA가 버스를 획득해 메모리와 장치 사이 데이터를 이동시키는 경로임 |
| 메모리 버퍼 | 데이터가 저장되는 대상 공간으로 정렬과 보호 설정이 중요함 |
| 완료 인터럽트 | 전송 종료 후 CPU에 결과를 알려 후속 처리를 이어가게 함 |

```text
+-------------+     +----------------+     +----------------+     +-------------+
| CPU Setup   | --> | DMA Controller | <-> | Memory Buffer  | <-> | Device      |
+-------------+     +----------------+     +----------------+     +-------------+
         ^
         |
   Completion IRQ
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| CPU 설정       | --> | 버스 획득      | --> | 장치-메모리 전송 | --> | 완료 인터럽트  |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **CPU 설정**: 전송 주소와 길이와 방향을 DMA에 기록함
2. **버스 획득**: DMA가 버스 마스터 권한을 얻음
3. **장치와 메모리 전송**: 데이터를 직접 복사함
4. **완료 인터럽트**: 종료를 CPU에 알리고 후속 처리를 넘김

## Ⅵ. 문제점 및 해결 방안

1. 문제: DMA가 버스를 장시간 점유하면 CPU와 다른 장치의 메모리 접근 지연이 커질 수 있음
   - 해결방안: burst 크기와 arbitration 정책을 조정하고 bus utilization과 memory latency로 영향을 검증함
2. 문제: DMA가 메모리를 갱신해도 CPU 캐시에 이전 데이터가 남아 있으면 잘못된 값을 읽을 수 있음
   - 해결방안: cache coherence 지원이나 flush, invalidate 절차를 적용하고 data consistency error와 cache miss impact로 검증함
3. 문제: 잘못된 DMA 매핑은 임의 메모리 접근으로 이어져 안정성과 보안 문제를 유발할 수 있음
   - 해결방안: IOMMU와 보호된 descriptor 검증을 적용하고 DMA fault count와 isolation test로 안전성을 검증함

## Ⅶ. 적용 사례

- NVMe 스토리지 경로에서는 블록 데이터 전송을 DMA로 처리하고 확인 지표는 IOPS와 CPU offload ratio임
- 오디오 재생 장치에서는 주기적 샘플 스트림을 DMA로 공급하고 확인 지표는 buffer underrun rate와 jitter임
- 고속 네트워크 카드에서는 패킷 버퍼 전송을 DMA로 수행하고 확인 지표는 throughput과 packet loss rate임

## Ⅷ. 결론

DMA는 대량 데이터 전송에서 CPU를 해방시키는 핵심 메커니즘이지만, 성능 이득은 버스 중재와 캐시 일관성과 주소 보호를 함께 설계할 때만 안정적으로 확보됨.
