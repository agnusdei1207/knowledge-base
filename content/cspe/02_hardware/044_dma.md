## 미리 알고가기

- DMA는 대량 데이터 전송을 CPU 대신 전용 컨트롤러가 수행하는 방식임
- CPU는 시작 주소와 길이와 방향만 설정하고 완료 시점에 통지받음
- 디스크, 네트워크, 오디오 스트리밍처럼 지속 전송 장치에 핵심적임

## Ⅰ. 개요

- **정의/개념**: DMA는 전용 컨트롤러가 버스 마스터로 동작해 주변장치와 메모리 사이 데이터를 CPU 개입 없이 직접 전송하는 입출력 기법임
- **배경/필요성**: 대량 블록 전송을 CPU가 직접 복사하면 계산 자원이 낭비되고 처리량이 떨어지므로, 복사 작업을 하드웨어에 위임할 필요가 있음

## Ⅱ. 특징

- CPU 부하를 줄여 연산과 입출력을 병행하기 쉬움
- 블록 전송과 스트리밍 처리에서 인터럽트 기반 방식보다 CPU 개입이 적음
- 버스 점유와 캐시 일관성 관리가 함께 필요함
- burst 전송, scatter-gather 같은 확장 기능으로 장치별 전송 패턴을 지원함

## Ⅲ. 종류 및 비교

| 판단 기준 | Programmed I/O | Interrupt-driven I/O | DMA |
|:---|:---|:---|:---|
| CPU 개입 | 최대 | 중간 | 낮음 |
| 대용량 전송 적합성 | 낮음 | 중간 | 높음 |
| 구현 복잡도 | 낮음 | 중간 | 높음 |
| 대표 용도 | 단순 장치 | 일반 이벤트 장치 | SSD, NIC, 오디오 |

> 요약: DMA는 CPU 복사를 줄이고 대량·지속 전송을 하드웨어가 맡는 방식임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| DMA 컨트롤러 | 전송 시작 주소와 길이와 방향을 받아 실제 메모리 이동을 수행함 |
| 버스 인터페이스 | DMA가 버스를 획득해 메모리와 장치 사이 데이터를 이동시키는 경로임 |
| 메모리 버퍼 | 데이터가 저장되는 대상 공간으로 정렬과 보호 설정이 중요함 |
| 완료 인터럽트 | 전송 종료 후 CPU에 결과를 알려 후속 처리를 이어가게 함 |

```text
+-------------+     +----------------+     +----------------+     +-------------+
| CPU Setup   | --> | DMA Controller | <-> | Memory Buffer  | <-> | Device      |
+-------------+     +----------------+     +----------------+     +-------------+
         ^
         |
   Completion IRQ
```

> 요약: CPU는 전송 조건만 설정하고 DMA가 버스와 버퍼를 사용해 데이터를 이동함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| CPU 설정       | --> | 버스 획득      | --> | 장치-메모리 전송 | --> | 완료 인터럽트  |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **CPU 설정**: 전송 주소와 길이와 방향을 DMA에 기록함
2. **버스 획득**: DMA가 버스 마스터 권한을 얻음
3. **장치와 메모리 전송**: 데이터를 직접 복사함
4. **완료 인터럽트**: 종료를 CPU에 알리고 후속 처리를 넘김

> 요약: DMA는 설정, 버스 획득, 직접 전송, 완료 통지 순서로 CPU 개입을 줄임.

## Ⅵ. 실무 적용 및 유의점

1. NVMe·고속 NIC는 DMA가 맞지만 캐시 불일치와 주소 매핑 오류가 치명적이므로 cache invalidate와 IOMMU를 적용하고 throughput, CPU offload ratio, DMA fault count로 확인함
2. 오디오·비디오 스트리밍은 DMA로 지속 전송을 맡기되 underrun·overrun을 줄이도록 ring buffer와 completion pacing을 적용하고 buffer underrun rate, jitter로 확인함

## Ⅶ. 결론

DMA는 대량 전송에서 CPU 복사를 줄이지만 버스 중재, 캐시 일관성, 주소 보호를 함께 맞춰야 효과가 유지됨.

## 작성 근거(검토용)

- DMA는 CPU 개입 감소, 버스 마스터, 장치-메모리 직접 전송을 중심으로 설명함
- 비교 기준은 CPU 개입, 대용량 전송 적합성, 구현 복잡도로 제한함
- 실무 판단은 cache invalidate, IOMMU, DMA fault count로 검증 가능하게 작성함
