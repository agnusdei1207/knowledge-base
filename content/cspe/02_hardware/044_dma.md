# DMA 직접 메모리 접근 (Direct Memory Access)

## 미리 알고가기

- DMA: 직접 메모리 접근(Direct Memory Access, DMA)은 장치와 메모리 사이의 블록 데이터를 CPU가 직접 복사하지 않고 전송하는 방식임
- Bus master: 장치나 DMA 컨트롤러가 버스 제어권을 얻어 직접 메모리에 접근하는 주체임
- Scatter-gather: 흩어진 여러 메모리 버퍼를 목록으로 지정해 한 번에 전송하는 방식임
- IOMMU: 입출력 메모리 관리 장치(Input-Output Memory Management Unit, IOMMU)는 장치 DMA 주소를 변환·보호하는 하드웨어임
- Cache coherency: CPU 캐시와 메모리의 데이터 값이 일치하도록 유지하는 성질임

## 1. 개요

- **정의/개념**: DMA는 CPU가 전송할 주소, 길이, 방향, 장치 정보를 설정하면 DMA 컨트롤러나 bus master 장치가 메모리와 I/O 장치 사이의 데이터를 직접 이동해 CPU 복사 부담을 줄이는 전송 방식임.
- **배경/필요성**: 디스크, 네트워크, 그래픽 장치처럼 대용량 데이터를 자주 주고받는 장치를 CPU가 직접 복사하면 연산 자원이 낭비되고 처리량이 제한됨. DMA는 데이터 이동을 전용 하드웨어에 위임해 CPU가 계산과 스케줄링에 집중하게 함.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 대용량 I/O 전송의 CPU 오프로딩 구조를 설명하는 역량 확인 | DMA controller, bus master, source/destination, interrupt, cache coherency, IOMMU | CPU가 완전히 불필요하다고 설명, 캐시 일관성 누락, 보호 문제 누락 |

> 요약: DMA는 CPU가 전송을 설정하고 전용 하드웨어가 실제 데이터 이동을 수행하는 I/O 오프로딩 구조임.

## 2. 특징 및 비교

| 판단 기준 | Programmed I/O | DMA |
|:---|:---|:---|
| 데이터 이동 주체 | CPU가 장치 레지스터와 메모리 사이를 직접 복사함 | DMA 엔진 또는 장치가 메모리에 직접 접근함 |
| CPU 부담 | 전송량에 비례해 CPU 점유율 증가 | 설정·완료 처리만 CPU가 담당함 |
| 성능 효과 | 소량·단순 전송에는 구현이 쉬움 | 대용량·고속 I/O에서 처리량 향상 |
| 주요 리스크 | CPU 낭비와 지연 증가 | 캐시 일관성, 주소 보호, 버스 경합 |

DMA는 모든 전송을 빠르게 만드는 마법이 아니라, 전송 설정 비용보다 데이터 복사 비용이 큰 경우 효과가 큼. 따라서 소량 제어 메시지는 programmed I/O가 단순하고, 대용량 블록·패킷·프레임 전송은 DMA가 적합함.

## 3. 구성요소/구조

```text
+----------+      setup       +------------+
| CPU      | ---------------> | DMA Engine |
+----------+                  +------------+
      |                              |
      | interrupt                    | bus master
      v                              v
+----------+ <----------------> +----------+
| Driver   |                    | Memory   |
+----------+                    +----------+
                                     ^
                                     |
                              +-------------+
                              | I/O Device  |
                              +-------------+
```

| 구성요소 | 설명 | 핵심 포인트 |
|:---|:---|:---|
| CPU/드라이버 | DMA 버퍼, 주소, 길이, 방향을 설정하고 완료 인터럽트를 처리함 | 제어와 완료 처리 |
| DMA 컨트롤러 | 버스 제어권을 얻어 메모리와 장치 사이 데이터를 이동함 | 데이터 전송 주체 |
| 장치 컨트롤러 | 네트워크 카드, 디스크, GPU처럼 데이터를 생산·소비함 | 고속 I/O |
| DMA 버퍼 | 장치가 접근 가능한 메모리 영역임 | 정렬, pinning, 매핑 |
| IOMMU | 장치 주소 변환과 접근 권한 검사를 수행함 | 보호와 격리 |

### 원리/흐름도

```text
+---------+      +---------+      +----------+      +-----------+      +----------+
| Map Buf | ---> | Program | ---> | Transfer | ---> | Interrupt | ---> | Unmap    |
+---------+      +---------+      +----------+      +-----------+      +----------+
```

CPU는 DMA 가능한 버퍼를 준비하고 장치에 전송 조건을 설정함. 이후 DMA 엔진이 버스 마스터가 되어 데이터를 이동하고, 완료 또는 오류를 인터럽트로 알려 CPU가 후처리함.

## 4. 문제점 및 개선방안

1. **캐시 일관성 문제**: CPU가 캐시에 가진 값과 DMA가 메모리에 쓴 값이 달라 데이터 불일치가 발생할 수 있음.
   - **개선방안**: coherent DMA 영역, cache flush/invalidate, DMA mapping API를 사용함. (확인: 데이터 검증 오류)
2. **메모리 보호 문제**: 장치가 잘못된 주소로 DMA를 수행하면 커널 메모리나 다른 프로세스 데이터를 훼손할 수 있음.
   - **개선방안**: IOMMU와 장치별 DMA domain을 적용해 접근 범위를 제한함. (확인: IOMMU fault, 권한 위반 로그)
3. **버스 경합과 지연**: DMA가 대량 전송으로 버스를 점유하면 CPU와 다른 장치의 메모리 접근 지연이 증가함.
   - **개선방안**: burst 크기, QoS, 전송 큐 우선순위를 조정하고 대역폭을 모니터링함. (확인: 메모리 대역폭 사용률, p99 I/O 지연)

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| NVMe 스토리지 | 명령 큐와 DMA 버퍼를 매핑해 블록 데이터를 메모리로 직접 전송함 | IOPS, p99 지연, CPU 사용률 |
| 고속 네트워크 | NIC가 수신 패킷을 ring buffer에 DMA로 적재하고 드라이버가 완료 큐를 처리함 | 패킷 드롭률, IRQ rate, DMA fault |
| GPU 연산 | CPU-GPU 간 입력·출력 데이터를 DMA로 전송하고 pinned memory와 stream으로 복사와 연산을 겹침 | 전송 시간, GPU idle time, end-to-end 지연 |

## 6. 결론

DMA는 대용량 I/O에서 CPU 복사를 제거해 처리량을 높이는 핵심 하드웨어 기능임. 그러나 장치가 메모리에 직접 접근하므로 캐시 일관성, 주소 보호, 버스 경합을 함께 설계하지 않으면 성능 이득이 데이터 오류나 보안 문제로 바뀔 수 있음. 따라서 DMA 적용은 전송량뿐 아니라 버퍼 관리, IOMMU, 완료 처리 지표까지 포함해 판단해야 함.
