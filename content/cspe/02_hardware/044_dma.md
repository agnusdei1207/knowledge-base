## 미리 알고가기

- DMA는 대량 데이터 전송을 CPU 대신 전용 컨트롤러가 수행하는 방식임
- CPU는 시작 주소·길이·방향만 설정하고 완료 시점에 통지받음
- 디스크·네트워크·영상 스트리밍처럼 지속 전송이 필요한 장치에 적용함
- IOMMU: 장치가 접근할 메모리 주소를 변환·검증하는 입출력 메모리 관리 장치임
- 버퍼 언더런·오버런: 버퍼에 데이터가 제때 채워지지 않거나 넘쳐 손실이 발생하는 상태임
- 지터(Jitter): 전송 간격이 일정하지 않고 흔들리는 정도임

## 작성 근거(검토용)

- DMA는 CPU 개입 감소, 버스 마스터, 장치-메모리 직접 전송을 중심으로 설명함
- 비교표는 CPU 역할, 전송 단위, 완료 확인을 기준으로 정리함
- 실무 판단은 IOMMU 오류, CPU 사용률, 버퍼 언더런·오버런으로 구체화함

## Ⅰ. 개요

- **정의/개념**: DMA는 전용 컨트롤러가 버스 마스터로 동작해 주변장치와 메모리 사이 데이터를 CPU 개입 없이 직접 전송하는 입출력 기법임
- **배경/필요성**: 대량 블록을 CPU가 직접 복사하면 명령 실행 시간이 전송에 사용되므로 복사 작업을 하드웨어에 위임할 필요가 있음

## Ⅱ. 특징

- CPU는 전송 조건 설정과 완료 처리만 맡아 전송 중 다른 명령을 실행할 수 있음
- 블록 전송과 스트리밍 처리에서 인터럽트 기반 방식보다 CPU 개입이 적음
- 버스 점유와 캐시 일관성 관리가 함께 필요함
- 버스트(Burst) 전송과 분산-수집(Scatter-Gather)으로 연속·분산 메모리 블록을 처리함

## Ⅲ. 종류 및 비교

| 판단 기준 | 프로그램 I/O | 인터럽트 I/O | DMA |
|:---|:---|:---|:---|
| CPU 역할 | 상태 확인과 데이터 이동 | ISR에서 데이터 이동 | 시작 주소·길이 설정과 완료 처리 |
| 전송 단위 | 레지스터·바이트 | 인터럽트당 소량 데이터 | 연속·분산 메모리 블록 |
| 완료 확인 | 상태 레지스터 조회 | 장치 인터럽트 | DMA 완료 인터럽트 |

> 요약: DMA는 CPU 복사를 줄이고 대량·지속 전송을 하드웨어가 맡는 방식임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| DMA 컨트롤러 | 전송 시작 주소·길이·방향을 받아 실제 메모리 이동을 수행함 |
| 버스 인터페이스 | DMA가 버스를 획득해 메모리와 장치 사이 데이터를 이동시키는 경로임 |
| 메모리 버퍼 | 전송 데이터를 저장하며 정렬 설정이 전송 오류 발생 여부를, 접근 보호 설정이 메모리 격리 범위를 결정함 |
| 완료 인터럽트 | 전송 종료 후 CPU에 결과를 알려 후속 처리를 이어가게 함 |

```text
+-------------+     +----------------+     +----------------+     +-------------+
| CPU 설정    | --> | DMA 컨트롤러   | <-> | 메모리 버퍼   | <-> | 주변장치    |
+-------------+     +----------------+     +----------------+     +-------------+
         ^
         |
     완료 IRQ
```

> 요약: CPU는 전송 조건만 설정하고 DMA가 버스와 버퍼를 사용해 데이터를 이동함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| CPU 설정       | --> | 버스 획득      | --> | 장치-메모리 전송 | --> | 완료 인터럽트  |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **CPU 설정**: 전송 주소·길이·방향을 DMA에 기록함
2. **버스 획득**: DMA가 버스 마스터 권한을 얻음
3. **장치와 메모리 전송**: 데이터를 직접 복사함
4. **완료 인터럽트**: 종료를 CPU에 알리고 후속 처리를 넘김

> 요약: DMA는 설정, 버스 획득, 직접 전송, 완료 통지 순서로 CPU 개입을 줄임.

## Ⅵ. 실무 사례

1. NVMe 장치는 DMA 버퍼와 IOMMU 주소 범위를 설정하고 IOMMU 오류 수·CPU 사용률을 확인함
2. 영상 스트리밍은 링 버퍼와 완료 통지 주기를 조정하고 버퍼 언더런·오버런 비율과 지터를 확인함

## Ⅶ. 결론

DMA는 대량 전송에서 CPU 복사를 줄이지만 버스 중재, 캐시 일관성, 주소 보호를 함께 설계해야 함.
