# 📖 【암기용】 개념 완전 이해
> 목적: DMA가 실제로 어떤 순서(레지스터 셋팅 → 버스 요청/승인 → 전송 → 완료 인터럽트)로 데이터를 움직이는지, 전송 모드 3종과 IOMMU 보안이 이 시퀀스의 어느 지점에 개입하는지 단계별로 완벽히 이해하게 만든다.

## 한눈에
- **개요**: DMA는 버스 마스터링(Bus Mastering) 프로토콜에 따라 "레지스터 셋팅 → Bus Request/Grant → 데이터 전송 → 완료 인터럽트"라는 정해진 시퀀스로 동작하는 I/O 전송 절차다.
- **왜 필요한가**: interrupt-driven I/O는 워드 하나마다 ISR(인터럽트 서비스 루틴)이 CPU를 깨워 레지스터-메모리 간 복사를 시킨다. 전송량이 크면 ISR 호출 자체의 오버헤드(문맥 저장·복귀)가 누적돼 CPU를 갉아먹는다. DMA는 이 반복 절차를 하드웨어 시퀀스 하나로 압축한다.
- **핵심 직관**: 택배 기사가 "출발 신고 → 도로 진입 허가 → 배송 → 도착 신고"라는 고정된 절차를 따르듯, DMA도 4단계 프로토콜을 매 전송마다 정확히 반복한다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 버스 마스터링 프로토콜 | "셋팅→BR/BG→전송→인터럽트"로 이어지는 DMA의 표준 동작 절차 — 이 문서가 다루는 **상위 흐름** | 택배 배송의 표준 절차 |
| DMAC(DMA Controller) | 이 절차를 실행하는 하드웨어 주체 | 절차를 따르는 택배 기사 |
| Address/Count/Control Register | 절차 1단계(셋팅)에서 CPU가 채워 넣는 3개 레지스터 | 배송지·수량·방향이 적힌 전표 |
| Bus Request(BR) | DMAC가 CPU에 버스 사용을 요청하는 신호 — 절차 2단계 | "도로 좀 쓸게요" |
| Bus Grant(BG) | CPU가 현재 명령어를 마치고 버스를 넘겨주는 응답 신호 | "그래, 써" |
| Cycle Stealing | 매 버스 사이클마다 CPU와 번갈아 쓰며 전송하는 모드 — 절차 3단계의 한 방식 | 복도를 번갈아 쓰기 |
| Burst(Block) Mode | 블록 전체를 끝낼 때까지 버스를 독점하는 모드 | 복도를 통째로 빌리기 |
| Transparent Mode | CPU가 버스를 안 쓰는 사이클에만 골라 전송하는 모드 | 아무도 안 볼 때만 몰래 옮기기 |
| Descriptor / Scatter-Gather | 비연속 메모리 조각들의 주소를 리스트로 엮어 한 번의 DMA 요청으로 처리하게 하는 구조 | 여러 박스 주소를 적은 배송 목록 |
| Descriptor Ring | NVMe·NIC 등이 다수의 전송 작업(디스크립터)을 순환 큐에 쌓아 DMAC가 순차 소비하게 하는 구조 | 배송 대기표가 쌓인 컨베이어 벨트 |
| IOMMU | 절차 3단계에서 DMAC가 접근하려는 메모리 주소를 변환·검사해 허가되지 않은 영역 접근을 차단하는 하드웨어 | 배송 기사의 출입증 검사대 |
| 완료 인터럽트 | 절차 4단계, Count Register가 0이 되었을 때 1회 발생 | "배송 완료" 최종 보고 |

## 깊이 이해

### 4단계 시퀀스를 수치로 따라가기
- 예: 4KB(4,096바이트) 블록을 32비트(4바이트) 워드 단위로 전송한다고 하면 워드 수는 4,096 ÷ 4 = **1,024워드**다.
- **1단계 셋팅**: CPU가 Address(시작 주소), Count(1,024), Control(Read/Write)을 레지스터에 쓴다 — 3회의 레지스터 쓰기, 수십 ns 이내에 끝난다.
- **2단계 BR/BG**: DMAC가 BR을 보내면 CPU는 실행 중이던 명령어(보통 1사이클)를 마친 뒤 BG로 응답한다. 이 지연은 통상 수 클럭 이내로, 인터럽트 방식이 ISR 진입에 걸리는 수백 클럭보다 훨씬 짧다.
- **3단계 전송**: 버스트 모드라면 1,024워드를 연속 사이클로 밀어 넣어, 사이클당 10ns 가정 시 약 **10.24μs**에 끝난다. 사이클 스틸링이면 CPU와 절반씩 나눠 쓰므로 대략 2배인 **20.48μs**가 걸리지만 CPU는 그동안 자기 사이클을 절반은 계속 쓸 수 있다.
- **4단계 완료**: Count Register가 0에 도달하는 순간 DMAC가 CPU에 인터럽트 1회를 건다. CPU는 이때 한 번만 문맥을 전환해 후처리(버퍼 확인 등)를 하면 된다.

### 전송 모드 3종의 시퀀스상 위치
- 세 모드(Cycle Stealing·Burst·Transparent) 모두 "1단계 셋팅"과 "2단계 BR/BG"는 동일하게 거친다. 차이는 오직 **3단계(전송)에서 버스를 누구와 어떻게 나눠 쓰는가**뿐이다.
- Cycle Stealing은 CPU와 1사이클씩 교대해 전송 시간은 늘지만 CPU 체감 지연은 작고, Burst는 CPU를 완전히 밀어내고 최단 시간에 끝내며, Transparent는 CPU가 쉬는 사이클만 골라 써 CPU 성능 저하는 0에 가깝지만 전송 완료까지 가장 오래 걸린다(CPU 유휴 사이클이 드물면 실제로는 지연이 크게 늘어날 수 있어 구현이 까다롭다).

### Scatter-Gather와 Descriptor Ring — 다중 전송의 시퀀스
- 파일 하나가 디스크 상에서 여러 조각(파편)으로 흩어져 있으면, 단순 DMA는 조각 수만큼 "셋팅→BR/BG→전송→인터럽트" 4단계를 반복해야 한다. 조각이 100개면 셋팅·인터럽트 오버헤드도 100번 반복된다.
- Scatter-Gather DMA는 100개 조각의 주소·길이를 디스크립터 리스트 하나로 묶어 DMAC에 한 번만 전달한다. DMAC는 리스트를 순회하며 100개 조각을 알아서 이어 붙여 전송하고, CPU에는 전체 완료 시 인터럽트 1번만 보낸다 — 셋팅·인터럽트 오버헤드가 100번에서 1번으로 준다.
- NVMe는 이를 더 확장해 Descriptor Ring(순환 큐)에 수천 개의 전송 요청을 미리 쌓아두고 DMAC가 순차적으로 소비하게 해, 다중 I/O 요청을 인터럽트 폭주 없이 처리한다.

### IOMMU가 시퀀스에 끼어드는 지점과 이유
- DMA는 메모리를 직접 건드리므로, 3단계(전송) 직전에 DMAC가 요청한 주소가 그 장치에게 허용된 범위인지 확인하는 절차가 필요하다. 이를 생략하면 악성 장치(예: Thunderbolt로 연결된 외장 기기)가 임의의 메모리 주소를 읽거나 써서 데이터를 훔치거나 코드를 주입할 수 있다(DMA 공격).
- IOMMU는 DMAC가 사용하는 주소(장치 관점의 가상 주소)를 실제 물리 주소로 변환하면서, 그 장치에 허가된 영역 밖이면 요청 자체를 차단한다. 즉 3단계 전송 직전에 "출입증 검사"를 끼워 넣는 하드웨어다.

## 연결 개념
- I/O 인터페이스(폴링·인터럽트·DMA·채널 I/O) — DMA가 속한 상위 I/O 제어 방식 분류
- 버스 중재(Bus Arbitration) — 2단계(BR/BG)에서 여러 DMAC가 동시에 요청할 때 누구를 먼저 승인할지 정하는 절차
- IOMMU — DMA 공격을 막는 주소 변환·권한 검사 하드웨어


# 📝 【답안용】 시험 답안 템플릿
> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: DMA 답안은 버스 마스터 획득 절차, cycle stealing·burst·transparent 3가지 전송 모드 차이, IOMMU 기반 보안 통제를 함께 제시한다.

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: DMA는 DMA 컨트롤러가 버스 마스터 권한을 얻어 device와 memory 사이 데이터를 CPU 개입 없이 블록 단위로 직접 전송하는 방식이다.
> 2. **가치**: CPU는 전송 설정과 완료 처리만 담당해 대용량 전송에서도 다른 작업을 병행할 수 있다.
> 3. **판단 포인트**: cycle stealing·burst·transparent 모드는 전송 속도와 CPU 버스 점유 허용 범위의 트레이드오프로 선택하고, IOMMU로 DMA 보안을 통제한다.

## 출제 의도 및 답안 포인트
| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| DMA 동작 절차 이해 확인 | 레지스터 설정, bus request/grant, 완료 인터럽트 | DMA가 CPU 개입이 전혀 없다고 단정 |
| 전송 모드 트레이드오프 판단 확인 | cycle stealing vs burst vs transparent 속도·CPU 점유 차이 | burst mode를 무조건 최선으로 서술 |
| DMA 보안 리스크 인식 확인 | DMA 공격 원리와 IOMMU 주소 변환·권한 검사 | IOMMU 역할 누락 |

> 요약: 이 문제는 DMA 개념 나열이 아니라 전송 모드별 트레이드오프와 보안 통제 방안을 보여야 한다.


## Ⅰ. 개요 및 필요성
- 개요: DMA 컨트롤러가 버스 마스터 권한으로 device-memory 간 데이터를 CPU 개입 없이 블록 전송하는 방식
- 배경: interrupt-driven I/O의 word 단위 CPU 전송은 대용량 데이터에서 CPU 점유율을 크게 높임
- 필요성: 대용량 순차 전송을 CPU 부하 없이 처리하려면 DMA 기반 block 전송과 보안 통제(IOMMU)가 필요함


## Ⅱ. 구조 및 구성요소
```text
CPU Setup(Address/Count/Control Reg)
  -> DMAC Bus Request -> CPU Bus Grant
  -> DMAC Master: Device <-> Memory Block Transfer
  -> Transfer Complete -> Interrupt to CPU
  -> IOMMU: Address Translation/Permission Check
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Address Register | 전송 시작 메모리 주소 저장 | CPU가 setup 시 기록 |
| Count Register | 전송할 데이터 길이 저장 | 0이 되면 전송 완료 |
| Control Register | 전송 방향(read/write), 모드 지정 | cycle stealing/burst/transparent |
| IOMMU | device 접근 주소 변환·권한 검사 | DMA 공격 차단 |

> 요약: DMA는 주소·카운트·제어 레지스터로 전송을 정의하고 IOMMU로 접근 범위를 통제한다.


## Ⅲ. 동작원리 및 흐름도
```text
CPU가 DMAC 레지스터 설정 -> DMAC가 Bus Request
  -> CPU Bus Grant -> DMAC가 버스 마스터로 전송 수행
  -> Count Register 0 도달 -> 전송 완료 인터럽트 -> CPU가 후처리
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | CPU가 주소·카운트·방향 레지스터 설정 | 설정값 정확성 |
| 2 | DMAC가 버스 요청, CPU가 버스 승인 | bus grant latency |
| 3 | 전송 모드(cycle stealing/burst/transparent)에 따라 블록 전송 | 전송 완료 시간, CPU 점유율 |
| 4 | 카운트 소진 시 완료 인터럽트로 CPU에 통지 | 인터럽트 지연 |

> 요약: DMA는 CPU 설정 이후 버스 마스터 권한을 얻어 블록을 전송하고 완료 시 인터럽트로 CPU에 알린다.


## Ⅳ. 특징
| 구분 | Cycle Stealing | Burst(Block) Mode | Transparent Mode |
|:---|:---|:---|:---|
| 버스 점유 방식 | 매 사이클 CPU와 교대 | 블록 전체 독점 | CPU 미사용 사이클만 사용 |
| 전송 완료 속도 | 중간 | 가장 빠름 | 가장 느림 |
| CPU 성능 영향 | 소폭 지연 | 전송 중 CPU 버스 접근 불가 | 영향 없음 |
| 적합 상황 | 균형 잡힌 일반 전송 | 완료 시간이 중요한 대용량 전송 | 실시간성이 중요한 시스템 |

> 요약: burst mode는 전송 속도, transparent mode는 CPU 성능 보존, cycle stealing은 그 중간 균형을 제공한다.


## Ⅴ. 심화 비교 및 적용 판단
| 구분 | Interrupt-driven I/O | DMA | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | CPU가 word 단위 직접 전송 | DMAC가 block 단위 전송 | 전송량이 크면 DMA |
| 비용/성능 | 소규모 전송에 적합, 대용량 시 CPU 점유율 급증 | 초기 설정 비용은 있으나 대용량에서 CPU 부하 낮음 | 전송 데이터량과 CPU 여유 자원으로 판단 |
| 운영/위험 | 별도 하드웨어 불필요 | DMA 공격 위험, IOMMU 필요 | 보안 요구 수준에 따라 IOMMU 적용 여부 결정 |

> 요약: 대용량·반복 전송은 DMA를 사용하되 IOMMU로 DMA 공격 위험을 함께 통제해야 한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| DMA 공격 | 악성 device가 임의 메모리 접근 | IOMMU 주소 변환·권한 검사 적용 | 비인가 접근 차단 로그 |
| 버스 경쟁 지연 | burst mode 사용 중 CPU 버스 접근 불가 | 실시간 요구 구간은 cycle stealing/transparent 선택 | CPU stall cycle 비율 |
| 전송 오류 | count/address 레지스터 오설정 | 전송 후 체크섬·재시도 로직 적용 | 전송 오류율 |

> 요약: DMA 운영 리스크는 보안(DMA 공격)과 버스 경쟁이며 IOMMU 로그와 stall 비율로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 전송 처리량 | 목표 MB/s 충족 | I/O 벤치마크 |
| CPU 점유율 | DMA 사용 시 CPU 부하 목표치 이내 | 성능 카운터 |
| 보안 통제 | IOMMU 활성화율 100% | 시스템 구성 점검 |

> 요약: 도입 성공 여부는 전송 처리량, CPU 점유율, IOMMU 활성화 여부로 판단한다.


## Ⅵ. 실무 적용 및 결론
**적용 방안 3개:**
1. 대용량 순차 전송이 필요한 디스크·네트워크 장치는 burst mode DMA를 적용해 전송 완료 시간을 단축함
2. 실시간성이 중요한 제어 시스템은 transparent mode 또는 cycle stealing으로 CPU 성능 영향을 최소화함
3. 외부 포트(Thunderbolt 등)를 통한 DMA 공격을 막기 위해 IOMMU를 기본 활성화하고 device 접근 범위를 제한함

**결론 (2줄):**
- 기술사 판단: 전송 완료 속도가 우선이면 burst mode, CPU 실시간성이 우선이면 transparent mode를 선택하며 보안이 필요하면 IOMMU를 병행함
- 향후 방향: NVMe·스마트 NIC 환경에서는 scatter-gather DMA와 descriptor ring을 확장해 다중 큐 기반 고속 전송과 IOMMU 기반 격리를 함께 강화해야 함
