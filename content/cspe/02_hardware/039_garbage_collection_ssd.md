## 핵심 인사이트 (3줄 요약)
- 가비지 컬렉션(GC)은 SSD가 새 데이터를 쓸 '빈 공간(Free Block)'을 확보하기 위해, 무효화된 찌꺼기 데이터가 섞인 블록들을 모아 쓸모있는 데이터만 옮기고 블록 전체를 삭제(Erase)하는 내부 정리 작업이다.
- 플래시 메모리는 쓰기(Write)는 '페이지' 단위로, 지우기(Erase)는 더 큰 '블록' 단위로 수행해야 하는 비대칭성 때문에 이런 복잡한 청소 과정이 필연적으로 발생한다.
- GC 작업 중에는 SSD 내부 대역폭과 자원을 크게 소모하므로 호스트의 I/O 응답 속도가 일시적으로 느려질 수 있으며, 이를 백그라운드에서 얼마나 눈에 띄지 않게 처리하느냐가 펌웨어 기술력의 핵심이다.
---
## Ⅰ. 개요 및 필요성
- **개념:** FTL(Flash Translation Layer)이 수행하는 핵심 백그라운드 기능으로, 더 이상 쓰이지 않는 쓰레기(Invalid) 페이지가 섞여 있는 블록들을 정리하여 재사용 가능한 완전히 비어있는 블록(Free Block)을 만들어내는 과정.
- **필요성:**
  - **덮어쓰기 불가(Erase-before-Write):** 플래시 메모리는 덮어쓰기가 불가능하여 데이터 갱신 시 계속 새로운 빈 공간을 찾아 쓰게 됨(Out-of-place Write). 계속 쓰다 보면 빈 공간이 고갈됨.
  - **재활용 공간 확보:** 빈 공간이 고갈되기 전, 더럽혀진 블록들을 비워 지속적인 쓰기 작업이 가능하도록 물리적 공간을 환수해야 함.
---
## Ⅱ. 아키텍처 및 핵심 원리
### 1. 가비지 컬렉션 동작 원리 도식
```text
[ GC 수행 전: 블록 A와 블록 B의 상태 ]
┌── 블록 A (Victim) ──┐      ┌── 블록 B (Victim) ──┐
│ ■ 유효 (Valid) 1    │      │ □ 쓰레기(Invalid)   │
│ □ 쓰레기(Invalid)   │      │ ■ 유효 (Valid) 2    │
│ □ 쓰레기(Invalid)   │      │ ■ 유효 (Valid) 3    │
└─────────────────────┘      └─────────────────────┘
          │ (1. 유효 데이터만 읽기)
          ▼
    [ FTL 컨트롤러 버퍼 ]  => Valid 1, Valid 2, Valid 3 만 수집
          │ (2. 새로운 빈 블록에 복사)
          ▼
┌── 블록 C (새로운 빈 블록) ──┐  (3. 기존 블록 A, B 전체 삭제 Erase!)
│ ■ 유효 (Valid) 1        │      ┌── 블록 A ──┐ ┌── 블록 B ──┐
│ ■ 유효 (Valid) 2        │      │ 빈 공간(O) │ │ 빈 공간(O) │
│ ■ 유효 (Valid) 3        │      │ 빈 공간(O) │ │ 빈 공간(O) │
│ 빈 공간 (이후 쓰기 가능)│      │ 빈 공간(O) │ │ 빈 공간(O) │
└─────────────────────────┘      └────────────┘ └────────────┘
```

### 2. 핵심 동작 3단계
1. **희생 블록(Victim Block) 선정:** 쓰레기(Invalid) 페이지가 가장 많이 포함되어 삭제 효율이 높은 더러운 블록을 청소 대상으로 선정.
2. **유효 데이터 마이그레이션(Copy):** 해당 블록에서 아직 살아있는 진짜 데이터(Valid Page)들만 읽어내어, 완전히 비어있는 새로운 블록(Target Block)에 차곡차곡 옮겨 적음.
3. **블록 소거 (Block Erase):** 찌꺼기만 남은 희생 블록 전체에 고전압을 가해 데이터를 완전히 지우고(Erase), 언제든 새 데이터를 쓸 수 있는 깨끗한 빈 블록(Free Block) 리스트로 반환.

## Ⅲ. 비교 및 연결
- **TRIM 명령어와의 연결**
| 구분 | 가비지 컬렉션 (GC) | TRIM 명령어 (OS 지원) |
|---|---|---|
| 주체 | SSD 내부 컨트롤러 (FTL) | 운영체제 (Windows, Linux 등) |
| 역할 | 빈 공간을 만들기 위해 데이터 이동 및 물리적 소거 수행 | OS에서 파일 삭제 시, 해당 LBA가 "쓰레기"임을 SSD에게 미리 알려줌 |
| 상호작용 | TRIM이 없으면 OS가 지운 파일을 SSD는 아직 유효한 줄 알고 GC 때 헛고생(복사)을 함. TRIM 덕분에 GC 효율이 극대화됨. |
---
## Ⅳ. 실무 적용 및 기술사 판단
- **쓰기 증폭(Write Amplification) 현상 주의:** 사용자가 1MB 데이터를 기록하려 할 때, 마침 빈 공간이 없어 GC가 발동하면 유효 데이터를 옮기고 지우는 과정 때문에 실제 낸드 칩에는 수 MB의 쓰기 작업이 일어남. 이는 SSD 수명 단축과 심각한 지연(Latency Spike)을 유발함.
- **Over-Provisioning(OP) 확보 전략:** 엔터프라이즈 스토리지 아키텍트는 GC가 여유롭게 동작할 수 있도록 SSD 전체 용량의 일정 부분(예: 20%)을 할당 금지 영역(OP)으로 남겨두어, 쓰기 폭주 시 성능이 급락하는 클리프(Cliff) 현상을 방지해야 함.
---
## Ⅴ. 기대효과 및 결론
- 가비지 컬렉션은 SSD가 영구적인 속도 저하 없이 오랫동안 쾌적하게 동작하도록 돕는 보이지 않는 청소부입니다.
- 현대의 SSD는 사용자가 컴퓨터를 조작하지 않는 유휴 시간(Idle Time)을 틈타 백그라운드에서 똑똑하게 GC를 미리 수행함으로써, 실제 사용자가 체감하는 성능 저하를 완벽하게 방어하고 있습니다.

### 📈 관련 키워드 및 발전 흐름도
Erase-before-Write 특성 ➔ 찌꺼기 누적으로 성능 저하 (과거 SSD) ➔ **[가비지 컬렉션 / TRIM 명령어 도입 (성능 유지)]** ➔ [백그라운드 지능형 GC 및 펌웨어 최적화]

### 👶 어린이를 위한 3줄 비유 설명
1. 장난감 상자(블록) 안에 고장 난 장난감(쓰레기 데이터)과 멀쩡한 장난감이 뒤섞여서 꽉 차버리면 새 장난감을 넣을 수가 없어요.
2. 그래서 엄마(FTL)가 멀쩡한 장난감만 골라서 새 상자에 예쁘게 옮겨 담아줘요 (유효 데이터 복사).
3. 그런 다음 원래 있던 헌 상자를 통째로 확 비워버리면(Erase), 나중에 새 장난감을 넣을 수 있는 아주 깨끗한 빈 상자가 생기는 거랍니다!
