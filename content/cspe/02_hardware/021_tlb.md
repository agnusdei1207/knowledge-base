## 미리 알고가기

- TLB는 가상 페이지 번호를 물리 프레임 번호로 바꾸는 최근 변환 결과를 담는 캐시임
- TLB 미스가 나면 다단계 페이지 테이블 순회가 발생함
- 큰 페이지를 쓰면 TLB 엔트리 하나가 덮는 메모리 범위가 넓어짐
- ASID(Address Space Identifier): 프로세스별 주소 공간을 구분해 문맥 전환 후에도 TLB 엔트리를 재사용하게 하는 식별자임

## 작성 근거(검토용)

- TLB를 페이지 테이블 순회 회피와 접근 권한 검사를 함께 수행하는 변환 캐시로 설명함
- 페이지 테이블과 TLB를 보관 범위·조회 방식·미스 처리로 비교함
- 구성요소와 적중·미스 흐름의 중복을 피하기 위해 절차형 구조 도식을 삭제함

## Ⅰ. 개요

- **정의/개념**: TLB는 MMU 내부에서 가상 페이지 번호와 물리 프레임 번호·접근 권한의 최근 변환 결과를 연관 검색하는 전용 캐시임
- **배경/필요성**: 다단계 페이지 테이블 순회에 따른 주소 변환 지연을 줄이기 위해 최근 변환 결과를 저장하는 전용 캐시가 필요함

### 쉽게 이해하기 (학습용)
- 서가 전체를 뒤지지 않고 최근 찾은 책 위치를 책상 위 메모장에 적어두고 바로 꺼내 보는 것과 같음

## Ⅱ. 특징

- 주소 변환 경로를 CPU 가까이에 두어 평균 메모리 접근 시간을 줄임
- 연관 검색으로 조회 속도를 높이고 ASID·권한 비트로 보호 기능을 함께 제공함
- 적중률은 지역성과 페이지 크기에 좌우되며 작업 집합이 커지면 성능 변동이 커질 수 있음
- 가상화 환경에서는 게스트와 호스트 변환이 겹쳐 TLB 미스 비용이 더 커짐

### 쉽게 이해하기 (학습용)
- 메모장을 손 닿는 자리에 두고 이름표를 붙여 여러 사람이 같이 써도 헷갈리지 않게 하되, 자주 보는 페이지가 자꾸 바뀌면 메모장이 잘 맞지 않게 됨
- 두 사람 몫을 겹쳐 확인해야 하면 메모장을 다시 채우는 일이 두 배로 늘어남

## Ⅲ. 종류 및 비교

| 판단 기준 | 페이지 테이블 | TLB |
|:---|:---|:---|
| 보관 범위 | 주기억장치에 저장된 전체 가상 페이지 매핑 | MMU 내부에 캐시된 최근 매핑 일부 |
| 조회 방식 | 가상 주소의 단계별 인덱스로 탐색함 | 가상 페이지 번호·ASID를 연관 검색함 |
| 미스 처리 | 유효 엔트리가 없으면 페이지 폴트로 처리함 | 페이지 테이블 순회 후 엔트리를 재채움 |

> 요약: 페이지 테이블은 전체 매핑을 보관하고, TLB는 최근 변환을 캐시해 페이지 테이블 순회를 줄임.

### 쉽게 이해하기 (학습용)
- 서가 전체 목록이 페이지 테이블이라면, 책상 위 메모장은 TLB임. 메모장에 없으면 서가로 가서 다시 찾아 적어둠

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 가상 페이지 태그 | 가상 페이지 번호를 보관하고 입력 주소와 비교해 적중 여부를 결정함 |
| 물리 프레임 엔트리 | 대응되는 물리 프레임 번호를 제공해 최종 물리 주소를 생성함 |
| ASID·권한 비트 | 주소 공간 식별자와 읽기·쓰기·실행 권한을 저장해 문맥 전환과 보호 검사를 지원함 |
| 페이지 순회 인터페이스 | TLB 미스 시 페이지 테이블 탐색을 요청하고 새 변환 결과를 채움 |

> 요약: TLB는 가상 페이지 번호, 물리 프레임 번호, ASID, 권한 비트로 주소 변환과 보호 검사를 함께 처리함.

### 쉽게 이해하기 (학습용)
- 메모장 한 줄에는 책 제목(태그), 꽂힌 서가 위치(프레임 번호), 빌린 사람 이름표와 대출 권한(ASID·권한 비트)이 함께 적혀 있고, 없으면 서가 담당자에게 다시 물어봄

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 주소 분해        | --> | TLB 검색        | --> | 페이지 순회 여부 판단 | --> | 변환 결과 반영   |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **주소 분해**: 가상 주소를 가상 페이지 번호와 오프셋으로 나눔
2. **TLB 검색**: 가상 페이지 번호와 ASID를 기준으로 엔트리를 병렬 비교함
3. **페이지 순회 여부 판단**: 적중이면 물리 프레임 번호를 사용하고 미스면 페이지 테이블을 탐색함
4. **변환 결과 반영**: 최종 물리 주소를 만들고 필요하면 새 엔트리를 TLB에 채움

> 요약: TLB 적중 시 저장된 물리 프레임 번호를 사용하고, 미스 시 페이지 테이블을 탐색한 뒤 변환 결과를 채움.

### 쉽게 이해하기 (학습용)
- 책 번지수를 먼저 두 부분으로 나누고, 메모장부터 훑어본 뒤 있으면 바로 꺼내고 없으면 서가에서 찾아 메모장에 새로 적음

## Ⅵ. 실무 사례

1. 문맥 전환이 잦은 서버는 ASID로 주소 공간을 구분하고 전환 직후 TLB 적중률과 p99 응답시간을 확인함
2. 대용량 데이터베이스는 대형 페이지를 적용하고 TLB 변환 범위와 페이지 테이블 순회율을 확인함

### 쉽게 이해하기 (학습용)
- 근무자가 자주 바뀌는 창구는 이름표로 메모장을 구분해 다시 쓰지 않게 하고, 큰 자료를 다루는 곳은 한 줄이 넓은 범위를 담게 함

## Ⅶ. 결론

- TLB는 최근 주소 변환 결과를 MMU 내부에 캐시해 다단계 페이지 테이블 순회를 줄이는 전용 캐시임
- 엔트리 수·페이지 크기로 정해지는 변환 범위와 페이지 테이블 순회 빈도·지연을 함께 측정해 ASID 재사용이나 대형 페이지 적용 여부를 정해야 함

### 쉽게 이해하기 (학습용)
- 메모장 크기와 한 줄이 담는 범위, 그리고 메모장에 없어서 서가를 다시 뒤지는 빈도를 함께 살펴야 함
