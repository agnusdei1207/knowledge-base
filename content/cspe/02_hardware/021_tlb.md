## 미리 알고가기

- TLB는 가상 페이지 번호를 물리 프레임 번호로 바꾸는 최근 변환 결과를 담는 캐시임
- TLB 미스가 나면 페이지 테이블을 단계적으로 탐색하는 순회가 발생함
- 큰 페이지를 쓰면 TLB 엔트리 하나가 덮는 메모리 범위가 넓어짐

## Ⅰ. 개요

- **정의/개념**: TLB는 MMU 내부에서 가상 페이지 번호와 물리 프레임 번호·접근 권한의 최근 변환 결과를 연관 검색하는 전용 캐시임
- **배경/필요성**: 다단계 페이지 테이블 순회에 따른 주소 변환 지연을 줄이기 위해 최근 변환 결과를 저장하는 전용 캐시가 필요함

## Ⅱ. 특징

- 주소 변환 경로를 CPU 가까이에 두어 평균 메모리 접근 시간을 줄임
- 연관 검색과 ASID, 권한 비트를 함께 사용해 속도와 보호 기능을 동시에 처리함
- 적중률은 지역성과 페이지 크기에 좌우되며 작업 집합이 커지면 성능 변동이 커질 수 있음
- 가상화 환경에서는 게스트와 호스트 변환이 겹쳐 TLB 미스 비용이 더 커짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 페이지 테이블 | TLB |
|:---|:---|:---|
| 위치 | 주기억장치에 계층적으로 저장됨 | MMU 내부의 소용량 고속 캐시에 저장됨 |
| 조회 방식 | 인덱스 기반으로 단계별 탐색함 | 연관 검색으로 즉시 후보를 찾음 |
| 장점 | 전체 주소 공간을 완전하게 표현함 | 적중 시 page walk를 생략해 변환 지연을 줄임 |
| 한계 | 메모리 접근 전에 추가 참조가 필요함 | 용량이 작아 작업 집합이 크면 미스가 늘어남 |

> 요약: 페이지 테이블은 전체 매핑을 보관하고, TLB는 최근 변환을 캐시해 page walk를 줄임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| VPN Tag | 가상 페이지 번호를 보관하며 입력 주소와 병렬 비교되어 적중 여부를 결정함 |
| PFN Entry | 대응되는 물리 프레임 번호를 제공해 최종 물리 주소를 생성함 |
| ASID and Permission Bits | 프로세스 식별자와 읽기·쓰기·실행 권한을 함께 저장해 flush를 줄이고 보호 검사도 즉시 수행함 |
| Page Walker Interface | TLB 미스 시 페이지 테이블 탐색을 요청하고 새 변환 결과를 다시 채워 넣는 연결점임 |

```text
+------------------+     +----------------------+     +------------------+
| Virtual Address  | --> | TLB Lookup           | --> | Physical Address |
+------------------+     +----------------------+     +------------------+
         |                         |
         | miss                    | hit
         v                         v
+------------------+     +----------------------+
| Page Table Walk  | --> | TLB Refill           |
+------------------+     +----------------------+
```

> 요약: TLB는 VPN, PFN, ASID, 권한 비트로 주소 변환과 보호 검사를 함께 처리함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 주소 분해        | --> | TLB 검색        | --> | page walk 여부 판단 | --> | 변환 결과 반영   |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **주소 분해**: 가상 주소를 VPN과 offset으로 나눔
2. **TLB 검색**: VPN과 ASID를 기준으로 엔트리를 병렬 비교함
3. **page walk 여부 판단**: 적중이면 저장된 PFN을 사용하고 미스면 페이지 테이블을 탐색함
4. **변환 결과 반영**: 최종 물리 주소를 만들고 필요하면 새 엔트리를 TLB에 채움

> 요약: TLB 적중 시 저장된 물리 프레임 번호를 사용하고, 미스 시 페이지 테이블을 탐색한 뒤 변환 결과를 채움.

## Ⅵ. 실무 적용 및 유의점

1. 문맥 전환이 잦은 서버는 기존 변환이 자주 무효화되므로 ASID나 PCID로 주소 공간을 구분하고 context switch 직후 TLB hit rate, tail latency로 확인함
2. 대용량 메모리 작업은 TLB coverage를 넘기 쉬우므로 huge page와 multi-level TLB를 적용하고 TLB coverage, page walk rate로 확인함
3. 가상화 환경은 guest·host 2단계 변환이 겹치므로 nested translation cache와 EPT 최적화를 적용하고 nested miss penalty, VM memory access latency로 확인함

## Ⅶ. 결론

TLB는 주소 변환 지연을 줄여 CPU 파이프라인 연속성을 지키는 장치이며, 핵심 판단은 용량보다 miss penalty 통제에 있음.

## 작성 근거(검토용)

- TLB는 단순 캐시가 아니라 page walk 회피와 접근 권한 검사를 함께 수행하는 구조로 설명함
- 모호한 표현은 TLB coverage, page walk rate, nested miss penalty처럼 검증 가능한 지표로 좁힘
- 결론은 용량보다 변환 지연과 CPU 파이프라인 연속성을 기준으로 정리함
