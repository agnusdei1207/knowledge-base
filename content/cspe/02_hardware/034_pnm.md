## 미리 알고가기

- PNM은 메모리 셀 내부가 아니라 메모리 바로 옆의 로직 다이, 버퍼, 인터포저 부근에서 연산하는 구조임
- PIM보다 구현 자유도가 높고 기존 메모리 공정을 덜 건드리지만 데이터 이동을 완전히 없애지는 못함
- 메모리와 프로세서 사이 중간 지점에서 데이터 이동과 범용성의 균형을 잡는 접근임

## Ⅰ. 개요

- **정의/개념**: PNM은 메모리 컨트롤러와 버퍼 칩과 로직 다이와 인터포저 같은 메모리 인접 위치에 연산 기능을 두어, 메인 프로세서까지 데이터를 멀리 보내기 전에 가까운 곳에서 일부 처리를 수행하는 근접형 메모리 컴퓨팅 구조임
- **배경/필요성**: 메모리 내부 로직 통합은 공정 제약이 크고 범용성이 제한되므로, 데이터 이동을 줄이면서도 로직 설계 자유도와 소프트웨어 적응성을 더 확보할 수 있는 중간 해법이 필요함

## Ⅱ. 특징

- PIM보다 로직 설계 자유도가 높아 더 복잡한 연산과 제어를 담기 쉬움
- 메모리 인접 위치에서 처리해 CPU나 GPU까지 가는 데이터 양을 줄일 수 있음
- 메모리 내부가 아니므로 완전한 현장 처리보다 이동 비용 절감 폭은 작을 수 있음
- HBM base die, DIMM buffer, CXL memory device 같은 다양한 폼팩터에 적용 가능함

## Ⅲ. 종류 및 비교

| 판단 기준 | PIM | PNM |
|:---|:---|:---|
| 연산 위치 | 메모리 셀 또는 뱅크 내부에 가까움 | 메모리 바로 옆의 버퍼나 로직 다이에 가까움 |
| 장점 | 데이터 이동 최소화 효과가 큼 | 구현 유연성과 로직 복잡도 수용력이 더 높음 |
| 한계 | 메모리 공정 제약과 범용성 제한이 큼 | 이동 경로가 일부 남아 있어 절감 효과가 상대적으로 작을 수 있음 |
| 적합 업무 | 단순 반복적 메모리 중심 연산 | 전처리, 압축, 필터링, near-data acceleration |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Memory Device | 대용량 데이터를 저장하며 근접 연산의 원천 데이터를 제공함 |
| Near-Memory Logic | 메모리 버퍼나 base die나 인터포저에 위치해 전처리와 집계와 필터링을 수행함 |
| Host Interface | CPU나 GPU가 near-memory 연산을 지시하고 결과를 수신하는 연결 경로임 |
| Offload Runtime | 어떤 작업을 PNM으로 보내고 어떤 작업을 호스트에 남길지 결정해 이득을 최적화함 |

```text
+-------------+     +------------------+     +------------------+
| Host CPU/GPU | --> | Near-Memory Logic| --> | Memory Device    |
+-------------+     +------------------+     +------------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 작업 분류        | --> | PNM 오프로딩    | --> | 근접 위치 전처리   | --> | 축약 결과 전달   |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **작업 분류**: 데이터 이동이 큰 작업과 제어 중심 작업을 나눔
2. **PNM 오프로딩**: 전처리와 집계 후보를 메모리 인접 로직으로 넘김
3. **근접 위치 전처리**: 필터링과 압축과 단순 연산을 가까운 위치에서 수행함
4. **축약 결과 전달**: 줄어든 데이터만 호스트로 보내 후속 연산을 이어감

## Ⅵ. 문제점 및 해결 방안

1. 문제: PNM 장치가 메모리와 가속기 사이에 추가되면 인터페이스와 프로그래밍 모델이 복잡해질 수 있음
   - 해결방안: 표준 오프로딩 API와 장치 추상화를 적용하고 software integration effort와 offload latency로 검증함
2. 문제: 데이터를 충분히 축약하지 못하면 근접 처리 이득보다 추가 홉 비용이 더 커질 수 있음
   - 해결방안: high reduction ratio 작업만 선별하고 bytes reduced per task와 end-to-end latency로 검증함
3. 문제: 메모리와 근접 로직과 호스트 사이 일관성 및 오류 경로가 늘어나면 운영 복잡도가 커짐
   - 해결방안: RAS 정책과 상태 추적을 강화하고 error recovery time과 device fault isolation rate로 검증함

## Ⅶ. 적용 사례

- HBM 기반 AI 가속기는 base die 근처 전처리를 활용해 메모리 왕복을 줄이고, bytes reduced per task와 accelerator utilization로 결과를 확인함
- 데이터 분석 장비는 압축과 필터링을 PNM으로 보내 CPU 부담을 낮추고, query latency와 host CPU utilization로 결과를 확인함
- CXL 메모리 장치는 near-memory 연산으로 공유 메모리 접근량을 줄이고, fabric bandwidth savings와 end-to-end latency로 결과를 확인함

## Ⅷ. 결론

PNM은 메모리 안으로 들어가기 어려운 연산을 메모리 바로 옆으로 끌어와 데이터 이동과 구현 유연성 사이의 현실적인 균형점을 만드는 기술임.
