## 미리 알고가기

- **Near-Memory Computing**: 메모리 소자 내부가 아닌, 메모리 컨트롤러나 인터포저, 로직 다이 등 메모리와 물리적으로 매우 인접한 위치에서 연산을 수행하는 방식
- **데이터 이동 오버헤드**: 데이터를 연산 장치($CPU$, $GPU$)로 옮기는 과정에서 발생하는 에너지 소모 및 지연 시간 ($Latency$)
- **실리콘 인터포저**: $HBM$과 $GPU$를 연결하는 중간 기판으로, $PNM$의 핵심 하드웨어 배치 장소 중 하나임
- **오프로딩 ($Offloading$)**: 주 프로세서가 수행할 부하가 큰 작업을 주변의 특화된 처리 장치에 넘겨 처리하는 기법

## Ⅰ. 개요

- **정의/개념**: 메모리 근접 처리(Processing Near Memory, $PNM$)는 메모리 칩 내부($PIM$)보다는 상위에 위치하지만, 메인 프로세서보다는 훨씬 가까운 메모리 컨트롤러나 로직 다이 등에 연산 기능을 배치하여 데이터 이동 경로를 단축하는 컴퓨팅 구조임
- **배경/필요성**: 메모리 공정 내부에 복잡한 로직을 넣어야 하는 $PIM$은 제조 공정상의 한계와 수율 문제가 큼. 반면 $PNM$은 표준 로직 공정을 활용하면서도 데이터 이동 거리를 획기적으로 줄일 수 있어, $AI$ 학습 및 빅데이터 분석 환경에서 현실적인 '메모리 벽' 해결책으로 주목받고 있음

## Ⅱ. 특징 및 비교

### 가. $PIM$과 $PNM$의 기술적 특성 비교

| 구분 | $PIM$ (In-Memory) | $PNM$ (Near-Memory) |
|:---|:---|:---|
| 연산 위치 | 메모리 뱅크($Bank$) 또는 셀($Cell$) 내부 | 메모리 컨트롤러, 로직 다이, 인터포저 |
| 구현 공정 | $DRAM$ 공정 (로직 구현 제약 큼) | 표준 로직 공정 (설계 유연성 높음) |
| 데이터 이동 거리 | 극소 ($Cell \leftrightarrow PCU$) | 짧음 ($Bank \leftrightarrow Near\ Engine$) |
| 연산 복잡도 | 단순 연산 ($ADD$, $MUL$, $Bitwise$) | 복잡한 연산 ($Reduction$, $Filtering$, $Sort$) |
| 상용화 난이도 | 매우 높음 (수율 및 공정 간섭) | 상대적으로 낮음 (기존 패키징 활용) |
| 에너지 효율 | 최상 (이동 거의 없음) | 우수 (기존 방식 대비 $10 \sim 100$배 개선) |

> 요약: $PIM$은 극한의 효율을, $PNM$은 구현의 현실성과 연산의 유연성을 지향함

### 나. $PNM$의 주요 장점
- **설계 유연성**: 메모리 소자와 별개의 로직 다이에 구현되므로 $RISC-V$나 가속기 코어를 자유롭게 배치 가능
- **데이터 축소**: 대량의 데이터를 $PNM$에서 먼저 필터링하여 호스트 프로세서로 가는 트래픽을 $O(1/n)$ 수준으로 감축

## Ⅲ. 구성요소/구조

### 가. $HBM$ 및 $CXL$ 기반의 $PNM$ 배치 아키텍처

```text
[ Host CPU ] <--- (제한된 채널) --- [ PNM Controller ]
                                          |
      +-----------------------------------+-------------------+
      | [ Near-Memory Engine ]  <- 연산 수행 (Filtering 등)   |
      +-----------------------------------+-------------------+
                                          |
                        [ High-speed Interconnect / TSV ]
                                          |
                        [ Memory Dies / Storage ]
```

### 나. 주요 구성 요소 및 역할

| 구성요소 | 역할 및 설명 | 핵심 포인트 |
|:---|:---|:---|
| 로직 베이스 다이 | $HBM$ 하단에서 주소 변환 및 근접 연산 수행 | $TSV$를 통한 고속 데이터 스캔 |
| $PNM$ 컨트롤러 | 호스트의 요청을 해석하고 근접 연산기 제어 | $DRAM$ 타이밍과 연산 주기 동기화 |
| $Near-Memory\ Engine$ | 필터링, 정렬, 압축 등의 특정 알고리즘 가속 | 하드웨어 로직($ASIC$) 또는 $FPGA$ 형태 |
| 공유 가상 메모리 | $CPU$와 $PNM$이 동일한 주소 체계를 공유 | 프로그래밍 복잡도 완화 ($SVM$ 등) |

> 요약: 메모리의 입구 또는 통로에 '지능형 필터'를 달아 필요한 정보만 골라내는 구조임

## Ⅳ. 문제점 및 개선방안

1. **캐시 일관성($Coherence$) 유지**: $PNM$이 직접 메모리 값을 수정할 경우 $CPU$ 캐시에 저장된 값과 불일치 발생
   - **개선방안**: $PNM$ 전용 메모리 영역을 설정하여 캐싱을 제한하거나, $CXL$($Compute\ Express\ Link$) 프로토콜을 활용해 하드웨어 수준의 일관성을 보장함

2. **오프로딩 비용 ($Offloading\ Cost$)**: $PNM$으로 작업을 넘기고 결과를 받는 오버헤드가 실제 연산 이득보다 클 수 있음
   - **개선방안**: 데이터 이동량이 연산량보다 압도적으로 많은 $Memory-bound$ 워크로드를 선별하여 적용하고, 일괄 처리($Batching$)를 통해 호출 횟수를 줄임

3. **열 관리 문제**: 메모리 인근에 고성능 로직이 위치하여 열 밀도가 급증하고 $DRAM$의 리프레시 주기에 악영향을 줌
   - **개선방안**: 저전력 $ASIC$ 설계를 적용하고, 고효율 방열 구조(액침 냉각 등)와 연계하여 패키지 온도를 $\pm \Delta T$ 범위 내로 제어함

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| $Smart\ SSD$ 분석 | $SSD$ 내부 컨트롤러 인근에서 데이터 검색 및 통계 추출 후 결과만 전송 | $PCIe$ 트래픽 감소량, $Query\ Speed$ |
| $CXL$ 메모리 풀링 | $CXL$ 컨트롤러 내부에 전처리 엔진을 두어 호스트의 메모리 접근 부하 분산 | $CPU\ Utilization$, $Memory\ Access\ Latency$ |
| 유전체 분석 (Genomics) | 수십억 개의 염기서열 매칭 작업을 메모리 근처에서 병렬 처리 | $Execution\ Time$, $Energy\ Consumption$ |

> 요약: 데이터의 양이 너무 방대하여 '전수 조사'가 필요한 분야에서 $PNM$의 성능 향상이 두드러짐

## Ⅵ. 결론

$PNM$은 $PIM$의 이상적인 목표와 현재 반도체 제조 공정의 현실 사이에서 가장 합리적인 접점을 제시하는 기술임. 단순히 전송 속도를 높이는 전통적 방식에서 벗어나, 데이터가 흐르는 길목에 지능을 부여함으로써 시스템 전체의 효율성을 재정의함.

기술사는 $PNM$이 $CXL$이나 $HBM4$와 같은 차세대 인터페이스 기술과 결합하여 어떻게 데이터 중심 컴퓨팅($Data-centric\ Computing$)을 완성해 가는지에 대한 통찰력을 갖추어야 함. 또한 소프트웨어 스택에서의 투명성 확보와 캐시 일관성 문제 해결이 $PNM$의 대중화를 결정짓는 마지막 열쇠임을 이해하고 관련 표준화 동향을 주시해야 함.
