## 미리 알고가기

- near-memory: 메모리 셀 내부가 아니라 메모리 컨트롤러, 로직 다이, 스토리지 컨트롤러 등 가까운 위치에서 처리하는 방식임
- logic layer: 적층 메모리 하단이나 패키지 내부에서 제어·연산 로직을 담는 계층임
- offload: 중앙처리장치(Central Processing Unit, CPU)가 수행하던 일부 작업을 전용 장치나 가까운 처리기로 넘기는 방식임
- reduction: 여러 데이터 값을 합계, 최대값, 필터 결과처럼 작은 결과로 줄이는 연산임

## Ⅰ. 개요

- **정의**: 메모리 근접 처리(Processing Near Memory, PNM)는 메모리 셀 안이 아니라 메모리 컨트롤러, 로직 계층, 스토리지 컨트롤러처럼 데이터 저장 위치와 가까운 곳에 연산 기능을 배치해 CPU와 메모리 사이의 데이터 이동을 줄이는 근접 처리 구조임
- **배경/필요성**: 완전한 메모리 내 처리(Processing-in-Memory, PIM)는 메모리 공정과 일관성 제약 때문에 구현 범위가 제한될 수 있음. PNM은 더 많은 로직을 메모리 근처에 배치해 구현 유연성과 데이터 이동 절감 효과를 절충함
- **비유**: 창고 선반 안에서 계산하지는 않지만 창고 입구에 작업대를 두어 본사로 보내기 전에 분류와 집계를 끝내는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| PIM과 PNM의 위치·구현 차이를 데이터 이동 관점에서 설명하는 역량 확인 | near-memory, logic layer, offload, bandwidth, coherence | PIM과 동일시, CPU 대체로 설명, 소프트웨어 경로 누락 |

> 요약: PNM은 메모리 내부보다 구현이 유연한 근접 위치에서 데이터 이동을 줄이는 처리 구조임.

## Ⅱ. 특징/비교

| 판단 기준 | PIM | PNM |
|:---|:---|:---|
| 연산 위치 | 메모리 배열 내부 또는 매우 가까운 셀 주변 | 메모리 컨트롤러, 로직 다이, 패키지 내부 |
| 구현 유연성 | 메모리 공정 제약이 큼 | 로직 설계 자유도가 상대적으로 큼 |
| 데이터 이동 절감 | 가장 강하게 줄일 수 있음 | CPU 왕복 이동을 줄이되 내부 이동은 일부 존재 |
| 적용 범위 | 제한된 단순 연산 중심 | 필터링, 압축, 집계, 전처리 등 확장 가능 |

> 요약: PNM은 PIM보다 연산 위치가 데이터에서 상대적으로 멀지만 로직 구현과 확장성에서 현실적인 절충안을 제공함.

- PNM은 고대역폭 메모리(High Bandwidth Memory, HBM) 로직 다이, 컴퓨트 익스프레스 링크(Compute Express Link, CXL) 메모리 장치, 스마트 솔리드 스테이트 드라이브(Solid State Drive, SSD), 메모리 컨트롤러 가속 형태로 구현될 수 있음
- CPU는 제어와 복잡한 분기를 담당하고 PNM은 반복적 전처리와 데이터 축소를 맡는 분업이 적합함
- 실효 이득은 offload 비용보다 줄어든 데이터 이동 비용이 클 때 발생함

## Ⅲ. 구성요소

```text
+-----------+      +-----------+      +-----------+
| Host CPU  | <--> | Near Mem  | <--> | Memory    |
| Control   |      | Engine    |      | Banks     |
+-----------+      +-----------+      +-----------+
                        |
                        v
                  +-----------+
                  | Runtime   |
                  +-----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 호스트 CPU | 작업 지시, 예외 처리, 복잡한 제어 흐름을 담당함 | 본사 관리자 |
| 근접 처리 엔진 | 메모리 근처에서 필터, 압축, 집계, 변환을 수행함 | 창고 입구 작업대 |
| 메모리 컨트롤러 | 주소 변환, 명령 큐, 데이터 이동과 근접 연산 실행을 조정함 | 입출고 배차 담당자 |
| 런타임 API | 응용 프로그래밍 인터페이스(Application Programming Interface, API)로 PNM에 넘길 작업과 데이터 범위를 표현하고 완료를 동기화함 | 작업 의뢰서 |

> 요약: PNM은 호스트 CPU가 제어하고 메모리 근처 엔진이 반복 데이터 처리를 수행하는 분업 구조임.

## Ⅳ. 절차

```text
+-----------+      +--------------+      +-----------+      +-----------+
| Select    | ---> | Offload    | ---> | Execute   | ---> | Return    |
+-----------+      +--------------+      +-----------+      +-----------+
```

1. **후보 식별**: 데이터 이동량이 크고 반복적 전처리가 가능한 연산을 찾음
2. **작업 오프로딩**: CPU가 대상 주소, 연산 종류, 결과 위치를 근접 처리 엔진에 전달함
3. **근접 처리 실행**: 메모리 근처에서 필터링, 압축, 집계, 변환을 수행해 데이터량을 줄임
4. **결과 반환과 검증**: 축소된 결과를 CPU로 돌려주고 동기화, 오류, 성능 지표를 확인함

> 요약: PNM은 CPU가 반복 데이터 작업을 메모리 근처로 넘기고 축소된 결과만 회수하는 흐름임.

## Ⅴ. 문제점 및 개선방안

- **P1 offload 오버헤드**: 작업 설정과 동기화 비용이 크면 근접 처리 이득이 상쇄됨
- **P1 대응**: 충분히 큰 데이터 블록과 반복 작업에만 offload를 허용함 (확인: offload latency 대비 절감 시간)
- **P2 메모리 일관성 관리**: CPU 캐시, DMA, PNM 엔진이 같은 데이터를 접근할 때 최신 값 보장이 어려움
- **P2 대응**: ownership, cache flush, invalidate, 직접 메모리 접근(Direct Memory Access, DMA) barrier 정책을 명확히 함 (확인: 일관성 오류 건수와 재처리 건수)
- **P3 표준화 부족**: 장치별 API와 프로그래밍 모델이 달라 이식성과 운영 자동화가 낮을 수 있음
- **P3 대응**: 공통 라이브러리와 추상 API로 장치별 명령·상태 차이를 감춤 (확인: 포팅 수정 범위와 자동화 적용률)

> 요약: PNM 개선은 큰 데이터 작업을 선별하고 일관성·API를 표준화해 실효 이득을 안정화하는 방향임.

## Ⅵ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| CXL 메모리 장치 전처리 | CXL 메모리 근처 엔진이 scan/filter를 수행해 호스트 CPU로 이동하는 cold data 양을 줄임 | host memory traffic, offload latency, CXL bandwidth 사용률 |
| 스마트 SSD 분석 | 로그·이벤트 데이터를 SSD 컨트롤러 근처에서 압축·필터링한 뒤 축소 결과만 호스트로 반환함 | PCIe 전송량, query latency, SSD controller utilization |
| HBM 로직 다이 가속 | 고대역폭 메모리(High Bandwidth Memory, HBM)의 logic layer에서 reduction과 format conversion을 수행하되 데이터 블록 크기 기준으로 offload 여부를 결정함 | 이동 데이터량 감소, PNM engine utilization, 동기화 지연 |

> 요약: PNM은 장치 근처에서 데이터량을 줄이는 작업에 적용하고 offload 비용·일관성 오류·포팅 범위로 효과를 확인해야 함.

## Ⅶ. 전망

- **발전 방향**: CXL 메모리와 스마트 네트워크 인터페이스 카드(Smart Network Interface Card, SmartNIC), 스마트SSD가 확산되면 PNM은 데이터가 있는 장치 근처에서 전처리하는 구조로 확대될 수 있음
- **기술사적 판단**: 인공지능(Artificial Intelligence, AI) 데이터 전처리와 데이터베이스 scan/filter 같은 작업은 CPU 왕복을 줄이는 PNM 후보가 될 가능성이 큼
- **기술사 제언**: 기술사는 PNM을 PIM의 하위 개념으로 단순화하지 말고 위치, 구현 자유도, offload 경제성 기준으로 구분해야 함
