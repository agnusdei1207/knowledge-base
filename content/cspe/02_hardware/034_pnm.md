## 미리 알고가기

- PNM은 메모리 셀 내부가 아니라 메모리 바로 옆의 로직 다이, 버퍼, 인터포저 부근에서 연산하는 구조임
- PIM보다 구현 자유도가 높고 기존 메모리 공정을 덜 건드리지만 데이터 이동을 완전히 없애지는 못함
- 메모리와 프로세서 사이 중간 지점에서 데이터 이동과 범용성의 균형을 잡는 접근임

## Ⅰ. 개요

- **정의/개념**: PNM은 메모리 컨트롤러, 버퍼 칩, 로직 다이, 인터포저 같은 메모리 인접 위치에 연산 기능을 두어, 메인 프로세서까지 데이터를 보내기 전에 가까운 곳에서 일부 처리를 수행하는 근접형 메모리 컴퓨팅 구조임
- **배경/필요성**: 메모리 공정 변경 없이 데이터 이동을 줄이고 로직 설계 자유도를 확보하기 위해 메모리 인접 연산 구조가 필요함

## Ⅱ. 특징

- PIM보다 로직 설계 자유도가 높아 더 복잡한 연산과 제어를 담기 쉬움
- 메모리 인접 위치에서 처리해 CPU나 GPU까지 가는 데이터 양을 줄일 수 있음
- 메모리 내부가 아니므로 완전한 현장 처리보다 이동 비용 절감 폭은 작을 수 있음
- HBM 베이스 다이, DIMM 버퍼, CXL 메모리 장치 같은 다양한 폼팩터에 적용 가능함

## Ⅲ. 종류 및 비교

| 판단 기준 | PIM | PNM |
|:---|:---|:---|
| 연산 위치 | 메모리 셀 또는 뱅크 내부에 가까움 | 메모리 바로 옆의 버퍼나 로직 다이에 가까움 |
| 장점 | 데이터 이동 최소화 효과가 큼 | 구현 유연성과 로직 복잡도 수용력이 더 높음 |
| 한계 | 메모리 공정 제약과 범용성 제한이 큼 | 이동 경로가 일부 남아 있어 절감 효과가 상대적으로 작을 수 있음 |
| 적합 업무 | 단순 반복적 메모리 중심 연산 | 전처리·압축·필터링·인접 데이터 가속 |

> 요약: PIM은 이동량 절감 폭이 크고, PNM은 로직 자유도와 구현 유연성이 큼.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 메모리 장치 | 대용량 데이터를 저장하며 근접 연산의 원천 데이터를 제공함 |
| 메모리 인접 로직 | 메모리 버퍼·베이스 다이·인터포저에서 전처리·집계·필터링을 수행함 |
| 호스트 인터페이스 | CPU나 GPU가 메모리 인접 연산을 지시하고 결과를 수신하는 경로임 |
| 작업 이관 실행환경 | PNM으로 보낼 작업과 호스트에 남길 작업을 결정해 이득을 최적화함 |

```text
+-------------+     +------------------+     +------------------+
| Host CPU/GPU | --> | Near-Memory Logic| --> | Memory Device    |
+-------------+     +------------------+     +------------------+
```

> 요약: PNM은 메모리 인접 로직에서 전처리·집계·필터링을 수행해 호스트 왕복 데이터를 줄임.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 작업 분류        | --> | PNM 오프로딩    | --> | 근접 위치 전처리   | --> | 축약 결과 전달   |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **작업 분류**: 데이터 이동이 큰 작업과 제어 중심 작업을 나눔
2. **PNM 오프로딩**: 전처리와 집계 후보를 메모리 인접 로직으로 넘김
3. **근접 위치 전처리**: 필터링·압축·단순 연산을 가까운 위치에서 수행함
4. **축약 결과 전달**: 줄어든 데이터만 호스트로 보내 후속 연산을 이어감

> 요약: PNM은 이동량이 큰 작업을 메모리 인접 위치에서 축약한 뒤 호스트로 결과만 보냄.

## Ⅵ. 실무 적용 및 유의점

1. PNM 장치가 중간 경로에 추가되면 프로그래밍 모델이 복잡해지므로 표준 작업 이관 API와 장치 추상화를 적용하고 software integration effort, offload latency로 확인함
2. 데이터를 충분히 축약하지 못하면 추가 경유 비용이 이득을 넘어서므로 축약률이 높은 작업만 선별하고 bytes reduced per task, end-to-end latency로 확인함
3. 메모리·근접 로직·호스트 사이 오류 경로가 늘어나므로 RAS 정책과 상태 추적을 강화하고 error recovery time, device fault isolation rate로 확인함

## Ⅶ. 결론

PNM은 메모리 내부에 넣기 어려운 연산을 메모리 옆으로 옮겨 데이터 이동 절감과 구현 유연성의 균형을 잡는 기술임.

## 작성 근거(검토용)

- PNM은 PIM과 달리 메모리 인접 로직에서 처리하는 위치 차이를 중심으로 설명함
- 모호한 표현은 bytes reduced per task, offload latency, device fault isolation rate로 구체화함
- 결론은 데이터 이동 절감과 로직 구현 유연성의 균형으로 정리함
