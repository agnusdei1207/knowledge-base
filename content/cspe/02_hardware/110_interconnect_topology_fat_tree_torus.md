# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 대규모 병렬 컴퓨터나 데이터센터에서 수천 대의 컴퓨팅 노드를 연결할 때, 통신 병목을 막고 최적의 경로를 보장하기 위해 설계하는 물리적 스위칭 배선망(네트워크 구조)
- **왜 필요한가**: 컴퓨터가 10대면 아무 스위치에나 꽂아도 되지만, 10,000대면 한쪽 끝에서 반대쪽 끝으로 갈 때 엄청난 스위치 병목(교통체증)이 발생함. 구조를 수학적으로 잘 짜야 길이 안 막힘.
- **핵심 직관**: 명절 고속도로가 안 막히게 하려면 IC 진입로보다 고속도로 본선의 차선을 훨씬 넓게 파야 한다(팻트리). 아예 이웃집끼리는 담벼락을 허물고 샛길로 다니자(토러스).

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 토폴로지 (Topology) | 스위치와 노드들이 연결된 물리적, 논리적 기하학적 형태 | 도로망 지도 |
| 팻트리 (Fat-Tree) | 위(코어)로 올라갈수록 링크 대역폭(선 굵기)이 뚱뚱(Fat)해지는 트리 구조 | 동네 골목 → 왕복 2차선 → 16차선 고속도로 |
| 토러스 (Torus) | 2D/3D 격자 구조에서 양 끝 노드를 원통형으로 서로 연결한 순환형 구조 | 팩맨(Pac-Man) 게임 화면 (오른쪽으로 나가면 왼쪽으로 나옴) |

## 깊이 이해
- **배경·문제의식**: 기존의 단순 트리(Tree)형 네트워크는 말단 노드 통신은 괜찮지만, 트리의 뿌리(Core) 쪽으로 갈수록 트래픽이 몰려 엄청난 병목이 생김. 슈퍼컴퓨터에서 노드 간 연산 결과를 주고받아야 하는데 여기서 막히면 CPU가 아무리 빨라도 소용이 없음.
- **작동 원리 (팻트리)**: 상위 계층으로 갈수록 물리적 선을 더 많이 깔거나 대역폭이 넓은 장비를 배치함. 즉, 하위 노드에서 올라오는 대역폭 총합과 상위 스위치의 처리 대역폭 총합을 1:1로 맞추어(Non-blocking) 어디서든 병목 없이 통신하게 함.
- **작동 원리 (토러스)**: 중앙 스위치를 거치지 않고, 각 노드가 상하좌우(및 전후) 이웃 노드와 직접 연결됨(Mesh). 여기에 끝과 끝을 다시 이어(Torus) 가장자리에 있는 노드가 반대편 끝으로 갈 때 전체를 관통할 필요 없이 한 칸만 이동하게 만든 원형 링 입체 구조.
- **구체 예시**: 최신 클라우드 데이터센터(Leaf-Spine 아키텍처)는 사실상 팻트리의 변형형인 클로스(Clos) 네트워크 구조임. 슈퍼컴퓨터 후가쿠(Fugaku)는 Tofu라는 6차원 토러스 네트워크를 씀.
- **흔한 오해·주의점**: 팻트리는 말단 노드가 "무작위의 멀리 있는 상대"와 통신(All-to-All)할 때 좋고, 토러스는 물리적으로 가까운 "이웃 데이터"를 쪼개서 연산(Stencil 패턴)할 때 극도로 빠름.

## 연결 개념
- Leaf-Spine 아키텍처
- 광 인터커넥트 (Optical Interconnect)
- MPI (Message Passing Interface) 분산 연산

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 인터커넥트 토폴로지는 대규모 병렬 노드 간 통신 병목을 해소하기 위한 수학적 스위칭 배선망 설계다.
> 2. **가치**: 팻트리(Fat-Tree)는 네트워크 상위 계층의 대역폭을 확장하여 무병목(Non-blocking)을 보장하고, 토러스(Torus)는 이웃 노드 간 다이렉트 패스로 평균 홉(Hop) 수를 줄인다.
> 3. **판단 포인트**: 클라우드 기반 웹 서비스 환경은 동서(East-West) 트래픽 처리에 유리한 팻트리(Clos)가 지배적이며, 물리 시뮬레이션 등 슈퍼컴퓨팅 환경은 토러스가 강력하다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 대규모 클러스터 스위칭 병목 극복 원리 파악 | Bisection Bandwidth(양단면 대역폭), Non-blocking 개념 | 토폴로지 그림만 그리고 정량적(대역폭) 차이를 서술하지 못함 |
| 워크로드 특성에 따른 네트워크 설계 판단 | 팻트리(범용 All-to-All) vs 토러스(인접 노드 통신) 트레이드오프 | "팻트리가 토러스보다 무조건 좋다"식 단정 |

> 요약: 노드 수가 10만 개 단위로 확장될 때, 트래픽 폭증을 방어하기 위한 계층적 설계(팻트리)와 인접 통신 설계(토러스)의 차이를 묻는 문제다.

---

## Ⅰ. 개요 및 필요성

- 개요: 대규모 병렬 컴퓨터나 데이터센터에서 컴퓨팅 노드들을 연결하여 통신 병목을 방지하는 물리적 스위칭 네트워크 배선 구조임
- 배경: 기존 일반 트리(Tree) 구조는 상위 코어 스위치로 트래픽이 집중될 때 오버서브스크립션(Oversubscription)으로 인한 병목 극심
- 필요성: AI 훈련 등 수만 대의 GPU가 쉴 새 없이 동서(East-West) 통신을 주고받는 환경에서 예측 가능한 지연율 보장 설계 필수

---

## Ⅱ. 구조 및 구성요소

```text
[ Fat-Tree (팻트리) ]                         [ 2D Torus (토러스) ]
     [ Core Switch ] (초광대역)                 N --- N --- N ---+ (Wrap-around)
       /         \                              |     |     |    |
[ Aggregation ] [ Aggregation ]                 N --- N --- N ---+
   /      \        /      \                     |     |     |    |
 Edge    Edge    Edge    Edge                   +-----+-----+----+
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 팻트리 상위 링크 | 계층이 올라갈수록 링크 개수 또는 대역폭을 비례 확장 | 하위 트래픽 총합 = 상위 링크 대역폭 총합 (1:1) |
| 토러스 랩어라운드 | 격자 끝단의 노드를 반대편 끝 노드와 직결 연결 | 직경(Diameter)을 절반으로 줄여 지연 최소화 |
| 라우팅 알고리즘 | 목적지까지 충돌 없는 최적 경로 탐색 | 팻트리는 상향/하향, 토러스는 차원별 라우팅 |

> 요약: 팻트리는 중앙 통제식 거대 고속도로 인프라를 구축하고, 토러스는 개별 집들을 거미줄처럼 이어 우회로를 만든 구조다.

---

## Ⅲ. 동작원리 및 흐름도

```text
노드 트래픽 발생 -> 토폴로지 라우팅 결정 -> 노드/스위치 통과(Hop) -> 목적지 수신
```

- 1단계 [팻트리 상향]: 송신 노드가 Edge 스위치로 패킷 전송, 목적지가 다른 Edge 밑에 있으면 팻트리 구조를 따라 Aggregation/Core로 상향(Up)
- 2단계 [팻트리 하향]: Core 스위치가 여유 대역폭(Fat)을 활용해 병목 없이 목적지 Edge 쪽으로 패킷 하향(Down) 스위칭
- 3단계 [토러스 수평이동]: 토러스 구조에서는 Core 스위치 없이 목적지 좌표(X, Y, Z)와 현재 좌표를 비교해 인접 노드로 패킷 넘겨주기 반복
- 4단계 [토러스 순환이동]: 목적지가 반대편 끝일 경우 랩어라운드(Wrap-around) 링크를 타서 단 1~2 홉(Hop)만에 반대편으로 건너뜀

> 요약: 팻트리는 패킷이 "올라갔다 내려오는" 트리를 그리며, 토러스는 "이웃을 거치며 최단 거리를 찾아가는" 기하학적 흐름을 가진다.

---

## Ⅳ. 특징
- Bisection Bandwidth(양단면 대역폭): 네트워크를 임의로 반으로 잘랐을 때 양단 간 유지되는 대역폭. 팻트리는 이 값이 최대(Non-blocking)를 보장
- 비용 및 선박 밀도: 팻트리는 중앙 대형 스위치 장비 및 막대한 케이블 배선 비용 발생, 토러스는 짧은 인접 케이블 위주라 구축 및 증설 용이성 우수
- 결함 허용성(Fault Tolerance): 특정 스위치/링크 고장 시, 두 토폴로지 모두 풍부한 다중 경로(Multipath)를 통해 라우팅 우회 가능

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | Fat-Tree (Clos Network 변형) | 3D Torus | 선택 기준 |
|:---|:---|:---|:---|
| 통신 패턴 강점 | 무작위 All-to-All 통신 | 인접 노드 간 근거리 통신 | 애플리케이션 워크로드 특성 |
| 최대 홉(Hop) 수 | 고정 (계층×2) | 네트워크 크기에 비례 증가 | 레이턴시 일관성 요구도 |
| 확장성 | 스위치 포트 수 한계로 계단식 확장 | 노드 추가만으로 무한 선형 확장 | 인프라 예산 및 증설 유연성 |

> 요약: 예측 불가능한 잡다한 트래픽이 섞이는 퍼블릭 클라우드는 팻트리가 유리하고, 일사불란하게 인접 데이터를 나누어 푸는 물리 연산은 토러스가 압도적이다.

- 케이블 배선 복잡도 리스크: 팻트리는 규모 확장 시 수만 가닥의 광케이블 엉킴으로 유지보수 불가 → 스파인-리프(Spine-Leaf) 2계층 단순화 및 광 인터커넥트(CPO) 도입
- 토러스 데드락(Deadlock) 리스크: 순환 고리 형태로 패킷 교착 상태 발생 가능 → 가상 채널(Virtual Channel) 분리 라우팅 기법으로 구조적 교착 예방

- Bisection Bandwidth: 클러스터 이분할 간 이론적 최대 전송량(Tbps) — 네트워크 설계 보증 지표
- Average Hop Count: 패킷이 목적지 도달까지 거치는 평균 스위치/노드 수 — 지연(Latency) 통제 지표

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 클라우드 Spine-Leaf 전환: 레거시 3-Tier 트리를 팻트리 개념을 차용한 Spine-Leaf 구조로 평탄화(Flatten)하여, VM 간 동서 트래픽 병목을 제거하고 Oversubscription 비율을 3:1 이하로 통제
2. 슈퍼컴퓨팅 6D 토러스 적용: 기상 예보, 분자 동역학 등 격자 단위 계산 시뮬레이션 환경 구축 시 후가쿠(Fugaku) 사례처럼 다차원 토러스망을 채택하여 인접 노드 대역폭 극대화
3. 차세대 AI 패브릭 구축: 엔비디아 NVSwitch 기반 아키텍처에 팻트리 토폴로지를 적용한 Infiniband 랙 스케일 통신망을 구축하여 수천 개 GPU 간 All-to-All 집단 통신(Collective) 지연 최소화

**결론 (2줄):**
- 기술사 판단: 네트워크 장비 투자비(CAPEX)가 충분하다면 무결점 통신을 보장하는 팻트리가 정답이나, 특정 HPC 연산 패턴이 확실하다면 토러스가 가성비 높은 극강의 성능을 낸다.
- 향후 방향: 최근 AI 훈련의 트래픽 패턴이 All-to-All 통신을 극도로 요구함에 따라, 차세대 데이터센터는 팻트리 기반의 무손실 400G/800G 이더넷(RoCE)으로 천하통일되는 추세다.
