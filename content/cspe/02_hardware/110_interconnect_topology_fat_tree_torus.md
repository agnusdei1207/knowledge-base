# 📖 【암기용】 개념 완전 이해

> 목적: 팻트리와 토러스를 처음 봐도 데이터센터와 슈퍼컴퓨터가 왜 서로 다른 네트워크 모양을 쓰는지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 대규모 클러스터의 **네트워크 토폴로지(Interconnect Topology)** 설계에서 대역폭과 비용을 트레이드오프하는 두 대표 구조로, 팻트리(Fat-Tree)는 루트로 갈수록 링크가 굵어지는 계층형 구조이고 토러스(Torus)는 격자 노드를 순환 연결한 구조다.
- **왜 필요한가**: 노드 수가 늘어날수록 모든 노드가 서로 빠르게 통신하게 하려면 스위치·케이블 비용과 대역폭·지연 사이에서 절충이 필요하다. 팻트리와 토러스는 이 절충을 서로 다른 방식으로 푼다.
- **핵심 직관**: 팻트리는 위로 갈수록 도로가 넓어지는 고속도로 진입 구조이고, 토러스는 도넛처럼 끝과 끝이 이어진 바둑판 도로망이다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 네트워크 토폴로지 | 노드들을 어떤 링크 구조로 연결할지 정하는 설계 — 팻트리·토러스가 속하는 상위 개념 | 도시의 도로망 설계도 |
| 이분 대역폭(Bisection Bandwidth) | 네트워크를 절반으로 잘랐을 때 양쪽을 잇는 링크들의 총 대역폭 — 최악 트래픽 상황의 성능 지표 | 도시를 반으로 갈랐을 때 다리 몇 개가 연결하는가 |
| 네트워크 지름(Diameter) | 가장 먼 두 노드 사이의 최소 홉(hop) 수 | 가장 먼 두 동네 사이 최소 정류장 수 |
| Clos 구조/리프-스파인 | 하위(Leaf) 스위치와 상위(Spine) 스위치를 다중 경로로 완전 연결하는 팻트리의 구현 방식 | 모든 지점(Leaf)이 모든 환승역(Spine)과 직결된 지하철망 |
| ECMP(Equal-Cost Multi-Path) | 비용이 같은 여러 경로에 트래픽을 해시로 분산하는 라우팅 기법 | 같은 거리의 여러 다리에 차량을 고르게 분산 |
| 오버서브스크립션(Oversubscription) | 상위 계층 대역폭이 하위 계층 합보다 적어 병목이 생기는 비율 | 진입로는 4차선인데 본선은 2차선인 것 |
| Wraparound(순환 연결) | 격자의 양 끝을 연결해 도넛 모양으로 만드는 토러스의 핵심 구조 | 화면 오른쪽 끝에서 나가면 왼쪽에서 등장하는 것 |
| 스텐실 연산(Stencil Computation) | 각 노드가 바로 이웃 노드하고만 데이터를 주고받는 HPC 연산 패턴 | 옆자리 사람하고만 쪽지를 주고받는 게임 |

## 깊이 이해

### 이분 대역폭으로 두 구조를 숫자로 비교
- 완전 이분 대역폭을 목표로 설계한 팻트리는, 네트워크를 절반으로 잘라도 양쪽 사이 대역폭이 절반 노드가 동시에 전속력으로 통신할 수 있는 만큼 확보된다. 예를 들어 노드 1,000개가 각각 10Gbps 링크를 갖는다면, 완전 이분 대역폭 설계는 절반(500개) 대 절반 사이에 5Tbps 가까운 대역폭을 목표로 스파인 계층을 설계한다.
- 반면 2D 토러스는 노드가 늘어날수록 격자를 가로지르는 "허리 부분"의 링크 수가 노드 수의 제곱근 수준에 그쳐, 이분 대역폭이 노드 수 대비 상대적으로 낮아진다 — all-to-all 트래픽에서는 이 허리 링크들이 먼저 포화된다.

### 네트워크 지름 — 홉 수로 비교
- 2계층 리프-스파인 팻트리는 어느 두 서버 사이든 "리프→스파인→리프"로 항상 몇 홉 이내로 고정된다. 노드가 수만 개로 늘어도 계층을 하나 더 추가하면 되므로 지름이 크게 늘지 않는다.
- k×k 2D 토러스는 지름이 대략 한 변의 노드 수 k에 비례해 늘어난다. 예를 들어 한 변이 10개 노드인 2D 토러스(총 100노드)는 순환 연결 덕분에 최악 지름이 약 5홉(k/2 수준)이지만, 한 변이 100개(총 1만 노드)로 커지면 최악 지름도 약 50홉까지 늘어난다. 즉 토러스는 노드가 늘수록 원거리 통신이 점점 더 느려진다.

### Clos/리프-스파인 구조와 ECMP 판별 원리
- 리프 스위치 각각이 모든 스파인 스위치와 1개씩 링크를 갖는 완전 연결 구조를 취하면, 리프 A에서 리프 B로 가는 경로가 스파인 개수만큼(예: 스파인 4대면 4개 경로) 동시에 존재한다. ECMP는 패킷의 5-tuple(출발지·목적지 IP·포트 등)을 해시해 이 여러 경로 중 하나로 균등 분산한다.
- 오버서브스크립션 비율(예: 3:1)은 "리프 하위 서버 링크 합이 리프-스파인 상위 링크 합의 3배"라는 뜻이며, 비율이 1:1(논블로킹)에 가까울수록 비용은 커지지만 전 서버가 동시에 통신해도 병목이 없다.

### 토러스의 wraparound과 스텐실 연산 최적화
- 2D 토러스에서 노드(0,0)과 노드(0,9)(같은 행의 반대쪽 끝)는 순환 연결 덕분에 직접 1홉으로 연결되어, 순환 연결이 없는 단순 격자(메시)보다 최악 지름이 절반 수준으로 줄어든다.
- HPC의 유체역학·기상 시뮬레이션 같은 스텐실 연산은 각 노드가 바로 인접한 이웃 노드(3D 토러스 기준 상하좌우전후 6개)하고만 통신한다. 이 패턴은 토러스의 물리적 인접 연결 구조와 정확히 일치해, 적은 케이블로도 필요한 대역폭을 거의 다 채워 쓸 수 있다.

### 판별 원리 — 언제 팻트리, 언제 토러스
- 트래픽 패턴이 all-to-all(예: 클라우드 마이크로서비스 east-west 트래픽)이면 이분 대역폭이 높은 팻트리가 유리하다.
- 트래픽 패턴이 인접 노드 위주(스텐실 연산)면 같은 비용으로 더 많은 링크를 인접 연결에 쓸 수 있는 토러스가 유리하다.

### 비유와 흔한 오해
- **비유**: 팻트리는 어느 매장(노드)에서든 본사(루트)까지 넓은 도로로 바로 연결되는 프랜차이즈 물류망이고, 토러스는 이웃 마을끼리만 도로가 있지만 도로가 도넛처럼 순환해 먼 마을도 몇 단계만 거치면 도달하는 마을 네트워크다.
- **오해**: 토러스가 팻트리보다 무조건 저렴하거나 무조건 느리다고 단정하면 안 된다 — 트래픽 패턴에 따라 우열이 뒤바뀐다. 실제로 후지쯔 K computer 등 일부 슈퍼컴퓨터는 6D 토러스·메시 계열 인터커넥트로 인접 통신 패턴에 최적화했다.

## 연결 개념
- 멀티소켓 서버·SMP — 단일 서버 내부 인터커넥트가 확장되어 랙·클러스터 토폴로지로 이어지는 개념
- NVLink·InfiniBand — 팻트리·토러스 토폴로지를 물리적으로 구현하는 링크 계층 기술
- 광 인터커넥트 — 대규모 팻트리·토러스에서 장거리 구간의 대역폭·전력 효율을 개선하는 물리 계층 기술

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 팻트리·토러스 답안은 구조 원리, 이분 대역폭·지름·비용 트레이드오프, 데이터센터 vs HPC 적용 맥락을 함께 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 팻트리는 루트로 갈수록 링크가 굵어지는 계층형 토폴로지이고, 토러스는 격자 노드를 순환 연결한 인접 기반 토폴로지다.
> 2. **가치**: 팻트리는 완전 이분 대역폭에 가까운 데이터센터 트래픽 처리를, 토러스는 적은 케이블로 인접 노드 간 저지연 통신을 각각 최적화한다.
> 3. **판단 포인트**: 트래픽 패턴이 all-to-all이면 팻트리, 인접 노드 위주(스텐실 연산)면 토러스가 비용 대비 유리하다는 기준으로 판단해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 토폴로지 구조 원리 이해 확인 | 팻트리의 leaf-spine·Clos 구조, 토러스의 격자·순환 연결 | 팻트리와 토러스를 단순 "트리 vs 격자"로만 서술 |
| 성능 지표 이해 확인 | 이분 대역폭, 네트워크 지름(diameter), 홉 수 | 이분 대역폭·지름 수치 없이 우열만 서술 |
| 적용 맥락 판단 확인 | 데이터센터(all-to-all) vs HPC(인접 통신) 선택 기준 | 두 토폴로지를 우열로만 서술하고 트래픽 패턴 고려 누락 |

> 요약: 이 문제는 이분 대역폭·지름이라는 정량 지표로 두 토폴로지의 트레이드오프와 적용 맥락을 설명하는지를 본다.

## Ⅰ. 개요 및 필요성

- 개요: 팻트리는 루트 방향 링크 대역폭이 증가하는 계층형 네트워크 토폴로지, 토러스는 격자 노드를 순환 연결한 네트워크 토폴로지
- 배경: 노드 수 증가에 따른 트래픽 병목과 케이블·스위치 비용 사이의 절충 필요성에서 두 토폴로지가 각각 발전
- 필요성: 데이터센터의 all-to-all 트래픽과 HPC의 인접 노드 통신 패턴은 요구하는 대역폭 특성이 달라 토폴로지 선택이 성능·비용을 좌우함

---

## Ⅱ. 구조 및 구성요소

```text
Fat-Tree(Leaf-Spine/Clos)
  Leaf Switch(서버 접속) -> Spine Switch(상위 계층, 대역폭 확장)
  Leaf 여러 대가 모든 Spine과 연결 -> 논블로킹에 가까운 경로 다중화

Torus(2D 예시)
  Node(0,0) -- Node(0,1) -- Node(0,2) -- (wraparound) -- Node(0,0)
     |            |            |
  Node(1,0) -- Node(1,1) -- Node(1,2) -- (wraparound)
     (행·열 모두 양 끝이 순환 연결)
```

| 구성요소 | Fat-Tree | Torus |
|:---|:---|:---|
| 계층 구조 | Leaf-Spine 2~3계층 Clos | 계층 없음, 격자 노드 직접 연결 |
| 대역폭 확장 방식 | 상위 계층 링크·스위치 수 증가 | 노드당 인접 링크 수(차원) 증가 |
| 경로 다중화 | ECMP로 다중 경로 분산 | 다차원 라우팅으로 다중 경로 |
| 대표 활용 | 클라우드·데이터센터 리프-스파인 | HPC 슈퍼컴퓨터(스텐실 연산) |

> 요약: 팻트리는 계층을 늘려 대역폭을 확장하고, 토러스는 노드당 연결 차원을 늘려 인접 대역폭을 확보한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
Fat-Tree 라우팅
  서버 -> Leaf Switch -> ECMP로 Spine 다중 경로 분산 -> 목적 Leaf -> 목적 서버

Torus 라우팅
  Node A -> 인접 축 방향 홉 이동 -> 목적 좌표까지 순차 이동(필요 시 wraparound 경유)
  -> Node B 도착
```

| 단계 | Fat-Tree 처리 | Torus 처리 |
|:---:|:---|:---|
| 1 | 서버가 Leaf Switch로 패킷 송신 | 노드가 인접 노드로 패킷 송신 |
| 2 | ECMP 해시로 Spine 경로 선택 | 목적 좌표 방향으로 축별 라우팅 |
| 3 | Spine을 거쳐 목적 Leaf로 전달 | 필요 시 wraparound 링크로 최단 경로 선택 |
| 4 | 목적 Leaf가 목적 서버로 전달 | 목적 노드 도착까지 다중 홉 반복 |

> 요약: 팻트리는 ECMP 기반 다중 경로로 대역폭을 분산하고, 토러스는 격자 좌표를 따라 다중 홉으로 라우팅한다.

## Ⅳ. 특징

| 구분 | Fat-Tree | Torus | 수치·표준 포인트 |
|:---|:---|:---|:---|
| 이분 대역폭 | 설계에 따라 완전 이분 대역폭 확보 가능 | 노드 수 증가 시 상대적으로 낮아짐 | bisection bandwidth |
| 네트워크 지름 | 계층 수에 비례해 비교적 일정 | 노드 수·차원에 따라 증가 | 홉 수(diameter) |
| 케이블·스위치 비용 | 완전 이분 대역폭 목표 시 비용 급증 | 인접 연결만 필요해 상대적으로 저비용 | 스위치·포트 수 |
| 적합 트래픽 패턴 | all-to-all, east-west 트래픽 | 인접 노드 위주(스텐실 연산) | 통신 패턴 국소성 |

> 요약: 팻트리는 이분 대역폭에서, 토러스는 케이블 비용과 인접 통신 효율에서 각각 강점을 가진다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | Fat-Tree | Torus | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 계층형 Clos, ECMP 다중 경로 | 격자형 순환 연결, 축별 라우팅 | all-to-all 트래픽이면 Fat-Tree |
| 비용/성능 | 완전 이분 대역폭 확보 시 스위치·케이블 비용 큼 | 동일 노드 수 대비 케이블 수 적음 | 예산과 요구 대역폭으로 판단 |
| 운영/위험 | 대규모 확장 시 배선·스위치 관리 복잡 | 특정 트래픽 패턴 외에는 hotspot 발생 가능 | 워크로드 통신 패턴 사전 분석 필요 |

> 요약: 데이터센터형 all-to-all 트래픽은 Fat-Tree, HPC 인접 연산 패턴은 Torus를 선택하는 것이 일반적 기준이다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| Fat-Tree 오버서브스크립션 | 상위 계층 링크 수 부족 설계 | Spine 계층 대역폭 증설, 오버서브스크립션 비율 관리 | 실측 bisection bandwidth |
| Torus hotspot | all-to-all 패턴 유입 시 특정 링크 과부하 | 트래픽 패턴 사전 분석, adaptive routing | 링크별 트래픽 사용률 |
| 확장성 한계 | 노드 수 증가에 따른 지름·비용 급증 | 토폴로지 재설계(dragonfly 등 대안 검토) | 노드 증가 대비 평균 지연 증가율 |

> 요약: 토폴로지 리스크는 이분 대역폭 부족, 특정 패턴에서의 hotspot, 확장 시 비용·지연 급증으로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 이분 대역폭 | 설계 목표 대비 실측치 90% 이상 | 네트워크 벤치마크(all-to-all 테스트) |
| 평균 지연 | 워크로드 SLA 목표 이내 | 트레이스 기반 지연 측정 |
| 링크 사용률 | 특정 링크 과부하 없이 균등 분산 | SNMP/텔레메트리 모니터링 |

> 요약: 도입 성공 여부는 실측 이분 대역폭, 평균 지연, 링크 사용률 균등성으로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 클라우드·데이터센터 east-west 트래픽 처리는 리프-스파인 Fat-Tree로 설계하고 목표 이분 대역폭을 정의함
2. HPC 스텐실 연산 클러스터는 Torus 토폴로지로 케이블·스위치 비용을 절감하고 인접 통신 지연을 최소화함
3. 트래픽 패턴이 혼재된 환경은 사전 통신 패턴 분석 후 토폴로지를 선택하거나 dragonfly 같은 절충형 대안을 검토함

**결론 (2줄):**
- 기술사 판단: all-to-all 트래픽이 지배적이면 Fat-Tree, 인접 노드 위주 연산이면 Torus를 선택 기준으로 삼음
- 향후 방향: AI 학습 클러스터 확산으로 대역폭 요구가 커지며 Fat-Tree·Torus의 절충점인 Dragonfly류 토폴로지와 광 인터커넥트 결합이 확대될 전망
