## 미리 알고가기

- 팻트리는 상위 계층으로 갈수록 더 넓은 대역폭을 제공하는 계층형 구조임
- 토러스는 격자 노드(Node, 정점)의 양 끝을 연결해 순환 경로를 만드는 구조임
- 양분 대역폭(bisection bandwidth)은 네트워크를 반으로 나눴을 때 양쪽을 잇는 총 대역폭임
- All-Reduce는 여러 노드의 값을 집계하고 다시 전체 노드에 배포하는 집단 통신임
- 과가입은 하위 링크의 합산 요구 대역폭이 상위 링크 대역폭을 넘는 상태임
- 스텐실(stencil)은 격자에서 인접 노드의 값을 반복 참조하는 연산임

## 작성 근거(검토용)

- 팻트리·토러스는 연결 구조, 양분 대역폭, 홉 수, 통신 패턴, 장애 우회를 핵심 축으로 설명함
- 비교표는 두 토폴로지의 연결·확장 구조, 통신 경로·양분 대역폭, 적합 통신을 대비함
- 실무 판단은 과가입 비율·집단 통신 지연과 평균 홉 수·장애 우회 시간으로 검증함

## Ⅰ. 개요

- **정의/개념**: 인터커넥트 토폴로지는 서버와 스위치와 가속기 노드가 어떤 링크 구조로 연결되는지를 뜻하며, 팻트리와 토러스는 각각 전역 대역폭과 규칙적 근접 통신을 중시하는 대표 토폴로지임
- **배경/필요성**: 클러스터의 전역·근접 통신 지연과 혼잡을 줄이기 위해 워크로드 통신 패턴에 맞는 토폴로지 선택이 필요함

### 쉽게 이해하기 (학습용)
- 팻트리는 위층으로 갈수록 계단이 넓어지는 건물처럼 누구나 멀리 오갈 수 있게 하고, 토러스는 옆집·앞집끼리 지름길로 바로 연결된 원형 동네와 같음

## Ⅱ. 특징

- 팻트리는 상위 계층의 링크 수·속도를 늘려 네트워크 양분 구간의 대역폭을 확보함
- 토러스는 각 노드를 차원별 이웃과 연결해 인접 통신을 1홉 경로로 구성함
- 팻트리는 포트 수와 케이블 비용이 커질 수 있고 토러스는 전역 통신 홉 수가 늘 수 있음
- 토폴로지 가치는 모양 자체보다 실제 통신 패턴과 장애 우회 능력에서 결정됨

### 쉽게 이해하기 (학습용)
- 팻트리는 위층 계단을 넓힐수록 편리하지만 그만큼 계단 공사비가 커지고, 토러스는 옆집은 가깝지만 건너편 집까지는 여러 집을 거쳐야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 팻트리 | 토러스 |
|:---|:---|:---|
| 연결·확장 구조 | 계층형 스위치 트리, 계층별 스위치 포트·케이블을 증설함 | 2D·3D 순환 격자, 노드마다 차원별 이웃 링크를 구성함 |
| 통신 경로·양분 대역폭 | 상위 계층 경유, 과가입 비율과 상위 계층 링크 수·속도로 대역폭이 제한됨 | 이웃 링크 경유, 격자 절단면 링크 수·속도로 대역폭이 결정되고 평균 홉 수가 증가함 |
| 적합 통신 | All-Reduce·All-to-All 전역 통신 | 스텐실·격자 기반 인접 노드 통신 |

> 요약: 팻트리는 상위 계층 대역폭으로 전역 통신을 처리하고, 토러스는 차원별 이웃 링크로 근접 통신을 처리함.

### 쉽게 이해하기 (학습용)
- 모두가 모두와 자주 이야기해야 하는 전체 회의(All-Reduce)는 넓은 복도(팻트리)가 유리하고, 옆자리끼리만 자료를 주고받는 작업(스텐실)은 자리 배치가 촘촘한 원탁(토러스)이 유리함

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 연산 노드 | 서버와 GPU 노드가 실제 계산과 통신의 말단이 되어 트래픽 패턴을 형성함 |
| 링크 | 노드와 스위치를 잇는 물리 경로로 지연과 혼잡과 장애 우회 능력을 결정함 |
| 스위치·라우터 | 패킷을 적절한 경로로 전달하며 팻트리에서는 계층 대역폭 구조를 형성함 |
| 라우팅 정책 | 경로 선택과 부하 분산과 장애 우회를 담당해 같은 토폴로지도 성능 차이를 만듦 |

> 요약: 연산 노드의 트래픽을 링크와 스위치·라우터가 전달하고 라우팅 정책이 부하 분산·장애 우회 경로를 선택함.

### 쉽게 이해하기 (학습용)
- 각 집(연산 노드)에서 나온 편지를 도로(링크)를 따라 우체국(스위치·라우터)이 배달하고, 배달원(라우팅 정책)이 막힌 길이나 끊긴 길을 피해 다른 길로 돌아감

## Ⅴ. 원리 및 절차 흐름도

1. **패킷 발신**: 연산 노드가 목적지 노드로 향하는 패킷을 생성함
2. **경로 선택**: 팻트리는 상위 계층 스위치를 경유할 홉을 선택하고, 토러스는 차원별로 목적지에 가까워지는 이웃 링크를 선택함
3. **혼잡·장애 회피**: 적응형 라우팅이 혼잡 링크나 장애 링크를 피해 대체 경로로 전환함
4. **목적지 도달**: 패킷이 목적지 노드에 도착해 통신을 완료함

> 요약: 팻트리는 상위 계층 경유 경로를, 토러스는 차원별 이웃 경로를 선택해 혼잡·장애를 우회하며 목적지에 도달함.

### 쉽게 이해하기 (학습용)
- 편지를 보내고(패킷 발신), 큰길로 갈지 옆집을 거쳐 갈지 정하고(경로 선택), 막힌 길을 피해 돌아가며(혼잡·장애 회피), 결국 상대 집에 도착하는(목적지 도달) 순서와 같음

## Ⅵ. 실무 사례

1. AI 학습 클러스터는 팻트리의 과가입 비율과 증설 단위를 정하고 집단 통신 지연·양분 대역폭 활용률을 확인함
2. HPC 스텐실 연산은 토러스 인지 스케줄링과 적응형 라우팅을 적용하고 평균 홉 수·장애 우회 시간을 확인함

### 쉽게 이해하기 (학습용)
- AI 학습 클러스터는 전체 회의가 잦으니 복도를 얼마나 넓혀둘지 미리 정하고, HPC 스텐실 연산은 옆자리끼리 오가는 지름길이 막히지 않는지를 챙김

## Ⅶ. 결론

- 팻트리는 상위 계층 대역폭을 늘려 전역 통신에, 토러스는 차원별 이웃 링크로 근접 통신에 유리하도록 설계된 서로 다른 토폴로지임
- All-Reduce처럼 전역 통신이 잦은 워크로드는 팻트리의 과가입 비율을, 스텐실처럼 인접 통신이 잦은 워크로드는 토러스의 평균 홉 수·장애 우회 시간을 기준으로 선택해야 함

### 쉽게 이해하기 (학습용)
- 전체 회의가 잦은 조직은 넓은 복도(팻트리)를, 옆자리끼리만 일하는 조직은 촘촘한 원탁(토러스)을 고르되, 실제 통행량과 우회로까지 확인하고 정해야 함
