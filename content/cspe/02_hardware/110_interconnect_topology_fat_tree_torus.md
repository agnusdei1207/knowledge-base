## 미리 알고가기

- 팻트리는 상위 계층으로 갈수록 더 넓은 대역폭을 제공하는 계층형 구조임
- 토러스는 격자 노드(Node, 정점)의 양 끝을 연결해 순환 경로를 만드는 구조임
- 양분 대역폭(bisection bandwidth)은 네트워크를 반으로 나눴을 때 양쪽을 잇는 총 대역폭임
- All-Reduce는 여러 노드의 값을 집계하고 다시 전체 노드에 배포하는 집단 통신임
- 과가입은 하위 링크의 합산 요구 대역폭이 상위 링크 대역폭을 넘는 상태임
- 스텐실(stencil)은 격자에서 인접 노드의 값을 반복 참조하는 연산임

## 작성 근거(검토용)

- 팻트리·토러스는 연결 구조, 양분 대역폭, 홉 수, 통신 패턴, 장애 우회를 핵심 축으로 설명함
- 비교표는 두 토폴로지의 경로 구조, 대역폭, 링크 비용, 대표 통신을 대비함
- 실무 판단은 과가입 비율·집단 통신 지연과 평균 홉 수·장애 우회 시간으로 검증함

## Ⅰ. 개요

- **정의/개념**: 인터커넥트 토폴로지는 서버와 스위치와 가속기 노드가 어떤 링크 구조로 연결되는지를 뜻하며, 팻트리와 토러스는 각각 전역 대역폭과 규칙적 근접 통신을 중시하는 대표 토폴로지임
- **배경/필요성**: 클러스터의 전역·근접 통신 지연과 혼잡을 줄이기 위해 워크로드 통신 패턴에 맞는 토폴로지 선택이 필요함

## Ⅱ. 특징

- 팻트리는 상위 계층의 링크 수·속도를 늘려 네트워크 양분 구간의 대역폭을 확보함
- 토러스는 각 노드를 차원별 이웃과 연결해 인접 통신을 1홉 경로로 구성함
- 팻트리는 포트 수와 케이블 비용이 커질 수 있고 토러스는 전역 통신 홉 수가 늘 수 있음
- 토폴로지 가치는 모양 자체보다 실제 통신 패턴과 장애 우회 능력에서 결정됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 팻트리 | 토러스 |
|:---|:---|:---|
| 연결 구조 | 계층형 스위치 트리로 상위 구간 대역폭을 넓힘 | 2D·3D 순환 격자로 차원별 이웃을 연결함 |
| 전역 통신 경로 | 트래픽이 상위 계층을 경유하며 과가입 비율이 경로 대역폭을 제한함 | 트래픽이 여러 이웃 링크를 경유하며 격자 크기에 따라 평균 홉 수가 증가함 |
| 양분 대역폭 | 상위 계층의 링크 수·속도로 결정됨 | 격자 절단면을 지나는 링크 수·속도로 결정됨 |
| 확장 자원 | 계층별 스위치 포트와 케이블을 증설함 | 노드마다 차원별 이웃 링크를 구성함 |
| 적합 통신 | All-Reduce·All-to-All 전역 통신 | 스텐실·격자 기반 인접 노드 통신 |

> 요약: 팻트리는 상위 계층 대역폭으로 전역 통신을 처리하고, 토러스는 차원별 이웃 링크로 근접 통신을 처리함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 연산 노드 | 서버와 GPU 노드가 실제 계산과 통신의 말단이 되어 트래픽 패턴을 형성함 |
| 링크 | 노드와 스위치를 잇는 물리 경로로 지연과 혼잡과 장애 우회 능력을 결정함 |
| 스위치·라우터 | 패킷을 적절한 경로로 전달하며 팻트리에서는 계층 대역폭 구조를 형성함 |
| 라우팅 정책 | 경로 선택과 부하 분산과 장애 우회를 담당해 같은 토폴로지도 성능 차이를 만듦 |

> 요약: 연산 노드의 트래픽을 링크와 스위치·라우터가 전달하고 라우팅 정책이 부하 분산·장애 우회 경로를 선택함.

## Ⅵ. 실무 사례

1. AI 학습 클러스터는 팻트리의 과가입 비율과 증설 단위를 정하고 집단 통신 지연·양분 대역폭 활용률을 확인함
2. HPC 스텐실 연산은 토러스 인지 스케줄링과 적응형 라우팅을 적용하고 평균 홉 수·장애 우회 시간을 확인함

## Ⅶ. 결론

- 인터커넥트는 전역·근접 통신 비율에 따라 팻트리·토러스를 선택하고 양분 대역폭·홉 수·과가입·장애 우회를 검증해야 함
