## 미리 알고가기

- 캐시 매핑은 메모리 블록이 캐시 어디에 들어갈지를 정하는 규칙임
- 직접, 완전 연관, 집합 연관은 접근 지연과 충돌 미스의 트레이드오프 구조임
- 태그, 인덱스, 오프셋 분할이 주소 해석 기준임

## Ⅰ. 개요

- **정의/개념**: 캐시 메모리 매핑은 주기억장치 블록을 제한된 캐시 라인에 어떤 규칙으로 배치하고 탐색할지 정하는 주소 변환 구조임
- **배경/필요성**: 캐시는 빠르지만 용량이 작기 때문에, 어느 위치에 어떻게 저장할지 잘못 설계하면 메모리 병목을 줄이기보다 충돌 미스와 전력 비용을 키울 수 있음

## Ⅱ. 특징

- 직접 매핑은 단순하고 빠르지만 충돌 미스에 취약함
- 완전 연관 매핑은 유연하지만 비교 회로 비용이 큼
- 집합 연관 매핑은 둘의 절충으로 현대 CPU에서 가장 널리 쓰임
- 연관도가 높아질수록 hit rate는 높아질 수 있지만 지연과 전력이 증가함

## Ⅲ. 종류 및 비교

| 판단 기준 | 직접 매핑 | 완전 연관 | 집합 연관 |
|:---|:---|:---|:---|
| 저장 위치 | 한 라인 고정 | 임의 라인 가능 | 한 집합 내부 선택 |
| 강점 | 단순·저지연 | 충돌 미스 최소화 | 균형형 구조 |
| 한계 | conflict miss 큼 | 비교 회로 비용 큼 | 중간 수준 비교 비용 |
| 대표 활용 | 소형 캐시 | TLB 등 | 일반 CPU 캐시 |

> 요약: 직접 매핑은 빠르고, 완전 연관은 충돌을 줄이며, 집합 연관은 지연과 충돌 미스의 균형을 잡음.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Tag | 해당 캐시 라인이 원래 어떤 메모리 블록인지 식별해 hit 여부를 판단함 |
| Index or Set Index | 직접 매핑과 집합 연관에서 접근할 라인 또는 집합을 인덱스로 고정함 |
| Offset | 캐시 라인 내부 바이트 위치를 정해 실제 데이터 바이트를 찾음 |
| Comparator | 태그 비교 회로로 연관도가 높아질수록 병렬 비교 비용이 증가함 |

```text
+--------------+     +-------------+     +---------+
| Address Bits | --> | Tag/Index   | --> | Offset  |
+--------------+     +-------------+     +---------+
                           |
                           v
                     +------------+
                     | Comparator |
                     +------------+
```

> 요약: 주소를 tag, index, offset으로 나누고 태그 비교로 hit 여부를 판단함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 주소 분해       | --> | 집합/라인 선택   | --> | 태그 비교       | --> | hit/miss 판정 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **주소 분해**: 주소를 태그·인덱스·오프셋으로 나눔
2. **집합 또는 라인 선택**: 접근할 후보 위치를 좁힘
3. **태그 비교**: 저장된 태그와 요청 태그를 비교함
4. **hit 또는 miss 판정**: 데이터 사용 또는 교체 절차로 넘어감

> 요약: 캐시는 주소 분해, 후보 위치 선택, 태그 비교를 거쳐 hit 또는 miss를 판단함.

## Ⅵ. 실무 적용 및 유의점

1. 직접 매핑에서 특정 주소가 같은 라인에 몰리면 conflict miss가 반복되므로 set associativity나 address coloring을 적용하고 conflict miss ratio, hit rate로 확인함
2. 연관도를 과도하게 높이면 태그 비교 지연과 전력 비용이 커지므로 workload-driven cache tuning으로 associativity를 정하고 cache access time, power per access, MPKI로 확인함

## Ⅶ. 결론

캐시 매핑은 hit rate만 높이는 문제가 아니라 충돌 미스, 접근 지연, 전력 비용의 균형점을 정하는 설계 기준임.

## 작성 근거(검토용)

- 캐시 매핑은 속도 일반론이 아니라 주소 분해, 후보 라인 선택, 태그 비교 절차로 설명함
- 모호한 표현은 접근 지연, 충돌 미스, 비교 회로 비용으로 바꿈
- 결론은 hit rate 하나가 아니라 접근 지연과 전력까지 포함한 매핑 선택 기준으로 정리함
