## 미리 알고가기

- 캐시 매핑은 메모리 블록이 캐시 어디에 들어갈지를 정하는 규칙임
- 직접, 완전 연관, 집합 연관은 속도와 충돌 미스의 trade-off 구조임
- 태그, 인덱스, 오프셋 분할이 핵심 계산 기준임

## Ⅰ. 개요

- **정의/개념**: 캐시 메모리 매핑은 주기억장치의 블록을 제한된 캐시 라인에 어떤 규칙으로 배치하고 탐색할지 정하는 주소 변환 구조로, 검색 속도와 충돌 미스 빈도를 함께 좌우하는 핵심 설계 요소임
- **배경/필요성**: 캐시는 빠르지만 용량이 작기 때문에, 어느 위치에 어떻게 저장할지 잘못 설계하면 메모리 병목을 줄이기보다 충돌 미스와 전력 비용을 키울 수 있음

## Ⅱ. 특징

- 직접 매핑은 단순하고 빠르지만 충돌 미스에 취약함
- 완전 연관 매핑은 유연하지만 비교 회로 비용이 큼
- 집합 연관 매핑은 둘의 절충으로 현대 CPU에서 가장 널리 쓰임
- 연관도가 높아질수록 hit rate는 좋아질 수 있지만 지연과 전력이 증가함

## Ⅲ. 종류 및 비교

| 판단 기준 | 직접 매핑 | 완전 연관 | 집합 연관 |
|:---|:---|:---|:---|
| 저장 위치 | 한 라인 고정 | 어느 라인 가능 | 한 집합 내부 선택 |
| 강점 | 단순·저지연 | 충돌 미스 최소화 | 균형형 구조 |
| 한계 | conflict miss 큼 | 회로 복잡도 큼 | 중간 수준 복잡도 |
| 대표 활용 | 소형 캐시 | TLB 등 | 일반 CPU 캐시 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Tag | 해당 캐시 라인이 원래 어떤 메모리 블록인지 식별해 hit 여부를 판단함 |
| Index or Set Index | 직접 매핑과 집합 연관에서 접근할 라인 또는 집합을 빠르게 고정함 |
| Offset | 캐시 라인 내부 바이트 위치를 정해 실제 데이터 바이트를 찾음 |
| Comparator | 태그 비교 회로로 연관도가 높아질수록 병렬 비교 비용이 증가함 |

```text
+--------------+     +-------------+     +---------+
| Address Bits | --> | Tag/Index   | --> | Offset  |
+--------------+     +-------------+     +---------+
                           |
                           v
                     +------------+
                     | Comparator |
                     +------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 주소 분해       | --> | 집합/라인 선택   | --> | 태그 비교       | --> | hit/miss 판정 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **주소 분해**: 주소를 태그와 인덱스와 오프셋으로 나눔
2. **집합 또는 라인 선택**: 접근할 후보 위치를 좁힘
3. **태그 비교**: 저장된 태그와 요청 태그를 비교함
4. **hit 또는 miss 판정**: 데이터 사용 또는 교체 절차로 넘어감

## Ⅵ. 문제점 및 해결 방안

1. 문제: 직접 매핑에서는 특정 주소들이 같은 라인에 몰려 conflict miss가 반복될 수 있음
   - 해결방안: set associativity를 높이거나 address coloring을 적용하고 conflict miss ratio와 hit rate로 검증함
2. 문제: 연관도를 과도하게 높이면 태그 비교 회로가 커져 접근 지연과 전력 비용이 증가할 수 있음
   - 해결방안: target latency에 맞는 associativity를 선택하고 cache access time과 power per access로 검증함
3. 문제: 워크로드별 접근 패턴을 보지 않고 고정 구조를 쓰면 실제 병목에 맞지 않는 캐시가 될 수 있음
   - 해결방안: workload-driven cache tuning을 수행하고 MPKI와 area efficiency로 검증함

## Ⅶ. 적용 사례

- 서버 캐시 설계에서는 연관도를 조정하고 확인 지표는 conflict miss ratio와 hit rate임
- 저전력 코어에서는 접근 지연을 관리하고 확인 지표는 cache access time과 power per access임
- 워크로드 튜닝에서는 구조를 최적화하고 확인 지표는 MPKI와 area efficiency임

## Ⅷ. 결론

캐시 매핑의 핵심은 hit rate만 높이는 데 있지 않고 접근 지연과 충돌 미스와 전력 비용 사이의 균형점을 찾는 데 있음.
