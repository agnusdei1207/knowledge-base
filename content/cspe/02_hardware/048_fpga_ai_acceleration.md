# 📖 【암기용】 개념 완전 이해

> 목적: FPGA AI 가속을 처음 봐도 왜 "재구성 가능"이 핵심 가치인지, ASIC과 무엇이 다른지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: FPGA(Field-Programmable Gate Array)의 재구성 가능한 로직 자원을 비트스트림으로 프로그래밍해 AI 연산을 가속하는 방식
- **왜 필요한가**: AI 모델 구조와 양자화 방식은 빠르게 바뀌는데, ASIC은 제작 후 회로가 고정돼 새로운 연산 패턴에 대응하기 어렵다. FPGA는 비트스트림 재프로그래밍만으로 회로 자체를 바꿀 수 있다.
- **핵심 직관**: 레고 블록으로 만든 구조물처럼, 완성 후에도 다시 분해해 다른 모양(알고리즘)으로 재조립할 수 있다.

## 깊이 이해
- **배경·문제의식**: 데이터센터·엣지의 AI 모델은 CNN, Transformer 등으로 구조가 계속 바뀌고 int8·int4 같은 양자화 방식도 자주 바뀐다.
- **배경·문제의식**: ASIC은 tape-out 이후 회로가 고정되어 신규 모델 구조나 양자화 방식에 유연하게 대응하기 어렵다.
- **작동 원리**: FPGA는 LUT(Look-Up Table), CLB(Configurable Logic Block), 프로그래머블 인터커넥트, DSP 슬라이스, on-chip BRAM으로 구성된다.
- **작동 원리**: 비트스트림을 로드하면 이 자원들의 배선과 논리 기능이 재구성되어 원하는 하드웨어 회로(예: systolic array, 커스텀 dataflow)가 만들어진다.
- **장점**: 알고리즘이 바뀌면 물리적 재제작 없이 회로 재설계와 비트스트림 재프로그래밍만으로 대응할 수 있다.
- **장점**: 마스크 제작이 필요 없어 NRE(Non-Recurring Engineering) 비용이 낮고 time-to-market이 빠르다.
- **장점**: 파이프라인 구조를 워크로드에 맞춰 커스터마이징해 특정 연산의 지연을 낮출 수 있다.
- **단점**: LUT 기반 범용 재구성 로직으로 구현하기 때문에 동일 기능을 만들었을 때 ASIC 대비 면적과 전력 효율이 낮다.
- **단점**: 대량 생산 시 칩당 단가가 ASIC보다 높아 볼륨이 커질수록 총소유비용(TCO)에서 불리해진다.
- **단점**: 비트스트림 로드에 재구성 시간(reconfiguration time)이 소요되어 실시간 전환에는 오버헤드가 있다.
- **비유**: FPGA는 조립식 가구와 같아 필요에 따라 다시 조립할 수 있지만, 완전히 맞춤 제작된 고정 가구(ASIC)만큼 공간 효율이 최적화되지는 않는다.
- **구체 예시**: Microsoft의 Project Catapult·Brainwave는 Azure 데이터센터에서 Intel FPGA를 사용해 Bing 검색 랭킹과 DNN 추론을 가속하며, 재구성성 덕분에 새로운 모델 아키텍처에 빠르게 대응했다.
- **흔한 오해·주의점**: "FPGA가 ASIC보다 항상 빠르다"는 틀렸다. 동일 공정·설계 최적화 수준에서는 ASIC이 클럭 주파수와 전력 효율 면에서 우위에 있다.
- **흔한 오해·주의점**: "FPGA는 소프트웨어다"는 틀렸다. 비트스트림은 실제 하드웨어 로직 게이트와 배선 구성을 결정하는 것이지 소프트웨어 명령어를 순차 실행하는 것이 아니다.

## 연결 개념
- ASIC AI 가속 — 재구성성 대신 고정 회로로 최고 성능/전력 효율을 노리는 대안
- SoC(System on Chip) — FPGA가 하나의 통합 SoC 내 가속 블록으로 포함될 수 있음(예: Xilinx Zynq)
- GPU SIMT — 유연한 소프트웨어 프로그래밍 모델을 갖는 또 다른 AI 가속 대안

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: FPGA AI 가속은 LUT·CLB·DSP 슬라이스 등 재구성 가능한 로직 자원을 비트스트림으로 프로그래밍해 AI 연산 회로를 구성하는 방식이다.
> 2. **가치**: 물리적 재제작 없이 비트스트림 재프로그래밍만으로 알고리즘 변화에 대응해 NRE가 낮고 time-to-market이 빠르다.
> 3. **판단 포인트**: 재구성성과 낮은 NRE는 ASIC 대비 면적·전력 효율 열위, 대량 생산 단가 불리라는 트레이드오프를 동반한다.

## Ⅰ. 개요 및 필요성

- 개요: 재구성 가능한 로직 자원을 비트스트림으로 프로그래밍해 AI 연산을 가속하는 반도체
- 배경: AI 모델 구조와 양자화 방식이 빠르게 변화해 고정 회로(ASIC)로는 신속한 대응이 어려움
- 필요성: 물리적 재제작 없이 알고리즘 변화에 대응할 재구성 가능한 가속기가 필요함

---

## Ⅱ. 구조 및 구성요소

```text
Bitstream Load -> Configurable Logic Block(LUT)
  -> Programmable Interconnect -> DSP Slice(연산)
  -> On-chip BRAM(가중치/중간값 버퍼)
  -> Custom Dataflow(Systolic Array 등) -> AI 연산 결과
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| LUT/CLB | 임의 논리 기능 구현 | 비트스트림으로 기능 재구성 |
| Programmable Interconnect | 블록 간 배선 재구성 | 알고리즘별 dataflow 구성 |
| DSP Slice | 곱셈-누산(MAC) 연산 전담 | AI 행렬 연산의 핵심 자원 |
| On-chip BRAM | 가중치·중간 결과 버퍼링 | 오프칩 메모리 접근 감소 |

> 요약: FPGA는 LUT·인터커넥트·DSP·BRAM을 비트스트림으로 재구성해 원하는 AI 연산 회로를 만든다.

---

## Ⅲ. 동작원리 및 흐름도

```text
AI 모델/알고리즘 확정 -> HDL/HLS로 가속 회로 설계
  -> 비트스트림 생성 -> FPGA에 로드(재구성)
  -> 입력 데이터 스트리밍 -> DSP Slice 연산 수행
  -> 결과 출력 -> 모델 변경 시 비트스트림만 재생성
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | AI 연산 패턴을 HDL/HLS로 설계 | 목표 처리량·지연 |
| 2 | 비트스트림 생성 및 FPGA 로드 | 재구성 시간 |
| 3 | 데이터 스트리밍과 DSP 연산 수행 | 처리량, 전력 효율 |
| 4 | 모델 변경 시 비트스트림만 재생성해 재배포 | 재배포 소요 시간 |

> 요약: FPGA AI 가속은 회로 설계 후 비트스트림을 로드하는 절차를 반복해 모델 변화에 대응한다.

## Ⅳ. 특징

| 구분 | FPGA | ASIC(비교 참고) |
|:---|:---|:---|
| 회로 형태 | 재구성 가능(비트스트림 재로드) | 제작 후 고정 |
| NRE 비용 | 낮음(마스크 제작 불필요) | 높음(마스크·tape-out 비용) |
| 대량 생산 단가 | ASIC 대비 높음 | 대량 생산 시 낮음 |
| 면적/전력 효율 | LUT 기반이라 상대적으로 낮음 | 동일 기능 대비 최적화되어 높음 |

> 요약: FPGA는 재구성성과 낮은 NRE가 강점이고, 대량 생산 단가와 전력 효율에서는 ASIC에 열위다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | ASIC | FPGA | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 고정 회로, 최적 배치 | 재구성 가능 로직, 범용 배치 | 알고리즘 변경 빈도가 높으면 FPGA |
| 비용/성능 | 높은 NRE, 대량 생산 시 최저 단가 | 낮은 NRE, 소량·다품종에 유리 | 생산 물량과 모델 변경 주기로 판단 |
| 운영/위험 | 설계 오류 시 재작업 비용 막대 | 재구성 시간 오버헤드, LUT 효율 열위 | 실시간 전환 요구 시 재구성 지연 고려 |

> 요약: 물량이 크고 알고리즘이 안정되면 ASIC, 물량이 작고 알고리즘이 자주 바뀌면 FPGA를 선택한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 전력 효율 열위 | LUT 기반 범용 로직 구조 | DSP 슬라이스 활용 극대화, 저정밀 양자화 적용 | GFLOPS/W |
| 재구성 오버헤드 | 비트스트림 로드 시간 | partial reconfiguration으로 일부 영역만 재구성 | 재구성 소요 시간 |
| 설계 검증 부담 | HDL/HLS 설계 복잡도 | HLS 툴체인, 시뮬레이션 자동화 | 검증 커버리지 |

> 요약: FPGA 리스크는 전력 효율 열위와 재구성 오버헤드이며 GFLOPS/W와 재구성 시간으로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 처리량 | 목표 추론 처리량(inference/s) 충족 | 벤치마크 워크로드 실행 |
| 전력 효율 | GFLOPS/W 목표치 이상 | 전력 측정 장비 |
| 재구성 속도 | 모델 교체 시 재배포 시간 목표치 이내 | 배포 파이프라인 로그 |

> 요약: 도입 성공 여부는 처리량, 전력 효율, 모델 교체 시 재배포 속도로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 모델 구조·양자화 방식이 자주 바뀌는 초기 서비스 단계는 FPGA로 빠르게 대응하고 물량 확정 후 ASIC 전환을 검토함
2. 데이터센터 추론 가속은 partial reconfiguration을 적용해 모델 교체 시 재구성 시간을 단축함
3. DSP 슬라이스와 저정밀 양자화(int8 등)를 활용해 FPGA의 전력 효율 열위를 일부 상쇄함

**결론 (2줄):**
- 기술사 판단: 알고리즘 변경 빈도가 높고 물량이 적으면 FPGA, 알고리즘이 안정되고 물량이 크면 ASIC을 선택함
- 향후 방향: FPGA와 ASIC의 장점을 결합한 Chiplet 기반 이종 통합, Adaptive SoC(예: Versal)로 재구성성과 전력 효율을 동시에 개선하는 추세임
