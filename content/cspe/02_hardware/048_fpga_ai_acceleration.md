## 미리 알고가기

- **$FPGA$ (Field Programmable Gate Array)**: 제조된 후에도 사용자가 내부 논리 회로의 연결을 소프트웨어적으로 재구성할 수 있는 반도체
- **데이터플로우 ($Dataflow$) 아키텍처**: 명령어를 순차적으로 실행하는 대신, 데이터가 준비되는 대로 연산 유닛을 거치며 흐르도록 설계된 구조
- **$LUT$ (Look-Up Table)**: $FPGA$ 내부에서 임의의 논리 함수를 구현하기 위해 사용되는 핵심 구성 요소
- **$DSP$ 블록**: 고속 곱셈 및 누산($MAC$) 연산을 전담하는 하드웨어 가속 블록
- **양자화 ($Quantization$)**: $AI$ 모델의 가중치를 낮은 비트(예: $FP16 \rightarrow INT8$)로 변환하여 연산량과 메모리 사용량을 줄이는 기법

## Ⅰ. 개요

- **정의/개념**: $FPGA\ AI$ 가속은 딥러닝 알고리즘의 핵심인 행렬 연산과 컨볼루션을 $FPGA$ 내부의 재구성 가능한 논리 자원($LUT, DSP, BRAM$)에 최적화된 하드웨어 파이프라인으로 매핑하여, 초저지연($Ultra-low\ Latency$)과 높은 에너지 효율로 처리하는 기술임
- **배경/필요성**: $GPU$는 처리량($Throughput$)은 높지만 지연 시간이 길고 전력 소모가 큼. 또한 $AI$ 알고리즘의 진화 속도가 $ASIC$ 개발 속도보다 빠르기 때문에, 하드웨어 구조를 유연하게 변경하면서도 전용 칩에 가까운 성능을 낼 수 있는 $FPGA$가 엣지 컴퓨팅 및 실시간 제어 분야에서 각광받음

## Ⅱ. 특징 및 비교

### 가. $CPU, GPU, FPGA, ASIC$의 $AI$ 가속 특성 대비

| 구분 | $CPU$ (범용) | $GPU$ (병렬) | $FPGA$ (재구성) | $ASIC$ (전용) |
|:---|:---|:---|:---|:---|
| **유연성** | 최고 | 높음 | 중간 | 낮음 |
| **지연 시간 ($Latency$)** | 높음 | 중간 (배치 처리 필수) | **매우 낮음** | 매우 낮음 |
| **에너지 효율** | 낮음 | 중간 | **높음** | 최고 |
| **개발 기간** | 매우 짧음 | 짧음 | 중간 (HLS 등 필요) | 매우 김 |
| **적합 단계** | 소규모 추론 | 대규모 학습 | 실시간 추론, 엣지 | 대량 양산 추론 |

> 요약: $FPGA$는 '실시간성'과 '에너지 효율', '유연성'의 최적 접점에 위치함

### 나. $FPGA$ 가속의 핵심 차별점
- **비정형 연산 지원**: 표준적인 행렬 연산 외에 사용자 정의 비트 연산이나 복잡한 전처리를 하드웨어 수준에서 통합 처리 가능
- **확정적 지연 시간**: $OS$ 스케줄링 등의 간섭 없이 하드웨어 클록 단위로 정확한 응답 시간 보장

## Ⅲ. 구성요소/구조

### 가. $FPGA$ 기반 $AI$ 엔진의 내부 아키텍처

```text
[ Data In ] ---> [ Pre-processing Logic ] ---> [ Pipelined AI Engine ] ---> [ Post-proc ]
                        |                          |                      |
                 [ LUT / FF Array ]        [ DSP Slice (MAC) ]     [ Interface ]
                        |                          |                      |
                 [ Block RAM (Weight) ] <---> [ Distributed RAM ] <---> [ DDR/HBM ]
```

### 나. 주요 구성 요소 및 역할

| 구성요소 | 역할 및 설명 | 핵심 포인트 |
|:---|:---|:---|
| $LUT$ / 플립플롭 | 제어 로직 및 사용자 정의 연산기 구성 | 재구성의 핵심 단위 |
| $DSP$ 슬라이스 | 정밀한 행렬 곱셈 및 덧셈($MAC$) 연산 가속 | $INT8, FP16$ 등 지원 |
| $BRAM$ / $URAM$ | 모델의 가중치나 중간 결과를 칩 내부에 저장 | 외부 메모리 접근 병목 제거 |
| $HLS$ ($High-Level\ Synthesis$) | $C/C++$ 코드를 하드웨어 설계 언어($HDL$)로 변환 | 개발 생산성 향상 |
| 비트스트림 ($Bitstream$) | $FPGA$ 내부 연결 상태를 정의하는 설정 데이터 | 모델 변경 시 업데이트 대상 |

> 요약: 칩 내부의 자원을 $AI$ 모델의 연산 흐름($Graph$)에 맞춰 최적의 '전용 선로'로 재배열하는 구조임

## Ⅳ. 문제점 및 개선방안

1. **높은 개발 난이도**: $HDL$ 설계와 타이밍 클로저($Timing\ Closure$) 과정이 소프트웨어 개발보다 훨씬 복잡함
   - **개선방안**: **$Vitis$ $AI$**와 같은 전용 컴파일러나 프레임워크를 도입하여 $PyTorch/TensorFlow$ 모델을 자동으로 $FPGA$로 변환함

2. **메모리 대역폭 한계**: 칩 내부 자원은 충분해도 외부 $DRAM$에서 가중치를 가져오는 속도가 병목이 됨
   - **개선방안**: **$HBM$**이 통합된 $FPGA$를 사용하거나, 가중치 프루닝($Pruning$) 및 압축 기술을 적용하여 데이터 전송량 최소화함

3. **모델 크기 제약**: 대규모 언어 모델($LLM$) 등을 단일 $FPGA$에 담기에 온칩 메모리 용량이 부족함
   - **개선방안**: 여러 대의 $FPGA$를 고속 인터커넥트로 연결하는 **멀티 $FPGA$ 클러스터** 구성 및 모델 파티셔닝 기술 적용함

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| **실시간 영상 분석** | 자율주행차나 드론에서 카메라 입력을 지연 없이 분석하여 장애물 회피 제어 수행 | $Frame\ Latency$ ($< 10ms$) |
| **금융 고빈도 매매 ($HFT$)** | 시장 데이터를 분석해 $AI$ 기반으로 수 마이크로초($\mu s$) 내에 주문 체결 여부 결정 | $Tick-to-Trade\ Time$ |
| **스마트 $NIC$ ($DPU$)** | 데이터센터의 네트워크 패킷을 $CPU$ 대신 $FPGA$에서 직접 암호화 및 분류 처리 | $Line-rate\ Processing$, $CPU\ Offload$ |

> 요약: '응답 속도'가 곧 '수익'이나 '생명'과 직결되는 극한의 실시간 환경에서 독보적임

## Ⅵ. 결론

$FPGA\ AI$ 가속은 알고리즘의 유연성과 하드웨어의 고성능을 동시에 확보할 수 있는 전략적 선택지임. 특히 $AI$ 기술이 파편화되고 모델 최적화가 중요해지는 엣지 컴퓨팅 시대에 $FPGA$의 재구성성은 매우 강력한 무기가 됨.

기술사는 단순히 $FPGA$의 물리적 구조를 넘어, $AI$ 프레임워크와의 연동성($Compiler$ 기술)과 전력 대비 성능($TOPS/W$) 관점에서의 최적화 전략을 제시할 수 있어야 함. 또한, 미래에는 $FPGA$ 논리와 전용 $AI$ 엔진이 결합된 **적응형 컴퓨팅 플랫폼($ACAP$)**으로의 진화 방향에 대해서도 깊은 통찰력을 갖추어야 함.
