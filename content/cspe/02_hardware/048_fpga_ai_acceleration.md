# FPGA AI 가속 (FPGA AI Acceleration)

## 미리 알고가기

- FPGA: 필드 프로그래머블 게이트 어레이(Field Programmable Gate Array, FPGA)는 LUT, 플립플롭, DSP, BRAM을 사용자가 재구성할 수 있는 반도체임
- AI 가속: 신경망의 행렬 연산, 컨볼루션, 전처리 등을 전용 하드웨어 구조로 빠르게 처리하는 방식임
- 데이터플로우: 연산 단계를 파이프라인으로 연결해 데이터가 흐르며 처리되게 하는 방식임
- HLS: 고수준 합성(High-Level Synthesis, HLS)은 C/C++ 같은 언어를 RTL 회로로 변환하는 설계 방식임
- 양자화: 모델 가중치와 활성값의 비트 수를 줄여 연산량과 메모리 사용량을 줄이는 기법임

## Ⅰ. 개요

- **정의/개념**: FPGA AI 가속은 신경망의 행렬 연산, 컨볼루션, 전처리 연산을 FPGA의 재구성 가능한 논리, DSP, 온칩 메모리에 매핑해 지연시간과 전력 효율을 최적화하는 AI 처리 방식임.
- **배경/필요성**: AI 모델은 빠르게 바뀌고 엣지·통신 장비는 낮은 지연과 제한된 전력을 요구함. FPGA는 모델 변화에 맞춰 회로를 다시 구성하면서 특정 연산 흐름에 맞춘 병렬 파이프라인을 제공함.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 재구성 하드웨어 기반 AI 가속 선택 기준 설명 | LUT, DSP, BRAM, pipeline, reconfigurable, latency | GPU와 동일 병렬처리로 단순화, 재구성성 누락 |

> 요약: FPGA AI 가속은 모델과 지연 요구에 맞춰 회로 구조 자체를 재구성하는 AI 처리 방식임.

## Ⅱ. 특징 및 비교

| 판단 기준 | GPU | FPGA | ASIC |
|:---|:---|:---|:---|
| 유연성 | 소프트웨어 커널로 변경 쉬움 | 하드웨어 구조 재구성 가능 | 설계 후 변경 어려움 |
| 지연시간 | 처리량 중심, 배치 효과 큼 | 파이프라인으로 낮은 지연 구현 가능 | 목표 연산에 최적화 가능 |
| 전력 효율 | 높은 처리량이나 전력 소모 큼 | 맞춤 데이터패스로 전력 효율 우수 | 대량 생산 시 가장 우수 |
| 개발 난이도 | CUDA 등 생태계 성숙 | RTL/HLS, timing closure 부담 | 설계·검증·제조 비용 큼 |

FPGA는 GPU보다 범용 생태계는 약하지만, 입력이 연속적으로 흐르고 낮은 지연이 중요한 추론·전처리·네트워크 장비에서 강점이 있음. 반대로 모델이 매우 크고 메모리 대역폭 의존이 높으면 GPU나 전용 ASIC이 더 적합할 수 있음.

## Ⅲ. 구성요소/구조

```text
+----------+      +-----------+      +------------+      +----------+
| Sensor/  | ---> | FPGA I/O  | ---> | AI Pipeline| ---> | Output   |
| Packet   |      |           |      | DSP/BRAM   |      |          |
+----------+      +-----------+      +------------+      +----------+
                                      |
                                      v
                               +-------------+
                               | Reconfig    |
                               | Bitstream   |
                               +-------------+
```

| 구성요소 | 설명 | 핵심 포인트 |
|:---|:---|:---|
| LUT/FF | 사용자 논리와 제어 회로를 구성함 | 재구성성 |
| DSP 블록 | 곱셈·누산 같은 수치 연산을 가속함 | MAC 처리 |
| BRAM/URAM | 중간 feature map과 가중치를 칩 내부에 저장함 | 데이터 재사용 |
| I/O 인터페이스 | 센서, 네트워크, 메모리와 스트림 데이터를 주고받음 | 낮은 지연 |
| Bitstream | FPGA 회로 구성을 정의하는 파일임 | 모델별 재구성 |

### 원리/흐름도

```text
+----------+      +-----------+      +------------+      +----------+
| Quantize | ---> | Map Logic | ---> | Pipeline   | ---> | Deploy   |
+----------+      +-----------+      +------------+      +----------+
```

모델은 양자화와 연산 그래프 변환을 거쳐 DSP와 온칩 메모리에 배치됨. 이후 파이프라인 단계가 데이터 스트림을 연속 처리하므로, FPGA 성능은 연산량보다 데이터 재사용과 타이밍 클로저에 크게 좌우됨.

## Ⅳ. 문제점 및 개선방안

1. **개발 난이도와 생산성 한계**: RTL 설계와 timing closure는 소프트웨어 개발보다 진입 장벽이 높음.
   - **개선방안**: HLS, 검증 가능한 IP, reference design을 활용하고 critical path를 단계적으로 최적화함. (확인: timing violation, 개발 기간)
2. **자원 제약**: DSP, BRAM, routing 자원이 제한되어 큰 모델을 그대로 배치하기 어려움.
   - **개선방안**: 양자화, pruning, tiling, off-chip memory scheduling을 적용함. (확인: resource utilization, throughput)
3. **모델 변경 비용**: 모델 구조가 자주 바뀌면 bitstream 재생성과 검증 시간이 운영 부담이 됨.
   - **개선방안**: 가변 파라미터 구조, 부분 재구성, 공통 연산 IP를 표준화함. (확인: bitstream build time, 배포 실패율)

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 엣지 영상 추론 | 카메라 입력을 FPGA 파이프라인에서 전처리·추론까지 연속 처리함 | end-to-end 지연, 프레임 유실률, 전력 |
| 통신 장비 AI 처리 | 패킷 분류나 이상 탐지를 네트워크 데이터 경로에 직접 삽입함 | line-rate 처리, packet latency |
| AI 모델 프로토타이핑 | ASIC 제작 전 데이터패스와 메모리 구조를 FPGA로 검증함 | 자원 사용률, 기능 검증률, 성능 추정 |

## Ⅵ. 결론

FPGA AI 가속은 GPU와 ASIC 사이에서 재구성성과 낮은 지연을 제공하는 선택지임. 특히 스트리밍 입력, 고정 지연, 제한 전력 조건에서는 회로 수준 파이프라인의 이점이 큼. 다만 개발 난이도와 자원 제약이 명확하므로 모델 특성, 지연 요구, 변경 빈도, 검증 비용을 함께 판단해야 함.
