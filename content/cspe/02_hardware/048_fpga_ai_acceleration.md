## Ⅰ. 개요
- **정의**: LUT·FF·DSP 블록을 재구성하여 AI 연산을 하드웨어 수준에서 가속하는 프로그래머블 반도체
- **배경/필요성**: AI 모델이 다양하고 빠르게 변화하므로, 고정 하드웨어(ASIC)만으로는 새로운 연산 구조에 대응하기 어려움
- **비유**: 레고 블록처럼 회로를 조립·해체·재조립할 수 있는 반도체임

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| ASIC(049)·GPU(050) 대비 FPGA의 포지셔닝 | 재구성 가능성(Reconfigurability)과 전력 효율의 균형 | FPGA가 GPU보다 처리량이 높다고 오인하지 말 것 |

> 요약: 재구성 가능한 로직으로 AI 추론 파이프라인을 전용 회로화하여 전력 대비 처리량을 높이는 방식임

## Ⅱ. 구성요소
```text
Configuration Memory
        |
        v
+---[LUT]---[FF]---[Routing]---+
|                               |
+---[DSP Block]---[BRAM]-------+
|                               |
+---[I/O Block]---[SerDes]-----+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| LUT(Look-Up Table) | 임의의 N-입력 논리함수를 테이블로 구현하는 기본 로직 셀 | 레고 1x1 블록 |
| FF(Flip-Flop) | 클록 에지에 데이터를 래치하여 파이프라인 스테이지를 형성함 | 컨베이어 벨트 칸막이 |
| DSP Block | 곱셈-누산(MAC) 연산 전용 하드 매크로, INT8/FP16 지원 | 내장 계산기 |
| BRAM(Block RAM) | 칩 내부 분산 메모리, 가중치·활성값 버퍼로 사용됨 | 작업대 선반 |
| Routing Fabric | LUT·DSP·BRAM 간 신호를 연결하는 프로그래머블 배선 | 레고 연결 핀 |
| Configuration Memory | 비트스트림을 저장하여 로직·배선 구성을 결정함 | 조립 설명서 |

> 요약: LUT·DSP·BRAM이 프로그래머블 배선으로 연결되며, 비트스트림으로 회로를 정의함

## Ⅲ. 절차
```text
모델 분석 --> HLS/RTL 설계 --> 배치·배선(P&R) --> 비트스트림 로드·실행
```
- 1단계: AI 모델의 레이어 구조·데이터 타입·처리량 요구를 분석하여 병렬화 전략을 수립함
- 2단계: HLS(C/C++) 또는 RTL(Verilog/VHDL)로 MAC 어레이·데이터 흐름 파이프라인을 설계함
- 3단계: 합성(Synthesis) 후 FPGA 칩의 LUT·DSP·BRAM에 배치하고 배선을 최적화함
- 4단계: 생성된 비트스트림을 FPGA에 로드하여 AI 추론을 실행함

> 요약: 모델 분석 → HLS/RTL 설계 → 배치·배선 → 비트스트림 배포 순으로 가속기를 구현함

## Ⅳ. 문제점
- 개발 생산성 저하: RTL 수준 개발은 소프트웨어 대비 10~100배 긴 개발 주기를 요구함 — HLS 도구의 추상화 수준이 아직 GPU 프레임워크(CUDA 등)에 미치지 못함
- 절대 처리량 한계: DSP 블록 수가 수천 개 수준으로, 수만 코어를 가진 GPU(050 참조) 대비 피크 TOPS가 낮음 — 대규모 학습에는 부적합함
- 비트스트림 이식성 부재: 벤더(Xilinx/Intel)·제품군 간 비트스트림 호환이 불가하여 플랫폼 전환 시 재설계가 필요함

> 요약: 긴 개발 주기, 피크 처리량 한계, 벤더 종속이 FPGA AI 가속의 주요 제약임

## Ⅴ. 개선방안
1. 단기: Vitis AI·oneAPI 등 고수준 컴파일러 도입으로 모델-투-비트스트림 자동 변환 생산성을 확보함
2. 중기: 칩렛 패키징으로 FPGA+HBM 통합 대역폭을 확대하여 추론 처리량 상한을 높임
3. 장기: OpenCL/SYCL 기반 이식성 프레임워크와 표준 비트스트림 포맷 정립으로 벤더 종속을 완화함

> 요약: 고수준 도구, 칩렛 대역폭 확장, 표준 프레임워크 정립으로 FPGA AI 가속 한계를 극복함

## Ⅵ. 전망
- 발전 방향: Versal(ACAP) 등 CPU+FPGA+AI Engine 통합 아키텍처가 등장하여 적응형 컴퓨팅 플랫폼으로 진화 중임
- 기술사적 판단: 소량·다품종 에지 추론, 네트워크 인라인 가속(SmartNIC) 영역에서 ASIC(049 참조) 대비 경쟁력을 유지함
- 기술사 제언: FPGA는 프로토타이핑과 소량 에지 배포에 적합하며, 대규모 학습은 GPU(050 참조), 대량 양산 추론은 ASIC(049 참조)와 역할을 분담할 것을 권고함
