## Ⅰ. 개요
- 정의: 프로그램의 명령어 순서에 얽매이지 않고 준비된 명령어부터 먼저 실행하는 기술
- 배경: 데이터 의존성(RAW)이나 자원 부족으로 인한 파이프라인 정체(Stall) 해소 필요
- 출제 의도: 가짜 의존성(WAR, WAW) 제거 기술과 동적 스케줄링의 원리 이해

## Ⅱ. 구성요소
- ASCII 구조도
  +-------------------------------------------------+
  | [In-order Front-end] -> [Rename] -> [Issue]     |
  |                            |          |         |
  | [Reorder Buffer] <---------+    [Reservation    |
  | (Commitment)    <----------+     Station]       |
  |                            |          |         |
  | [In-order Retirement] <----+    [OoO Execution] |
  +-------------------------------------------------+

- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| RAT (Rename Table) | 논리 레지스터를 물리 레지스터로 매핑 | 닉네임 사용 |
| Reservation Station | 명령어와 데이터가 준비될 때까지 대기하는 곳 | 대기실 |
| Reorder Buffer (ROB) | 실행 결과를 순서대로 재정렬하여 반영하는 버퍼 | 순서표 |
> 요약: 가짜 의존성을 리네이밍으로 풀고, 비순차로 실행 후 다시 순서대로 정리함

## Ⅲ. 절차
- ASCII 흐름도
  (Decode) -> (Rename) -> (Dispatch) -> (Issue) -> (Execute) -> (Writeback) -> (Commit)

- 4단계 설명
1. Register Renaming: 한정된 논리 레지스터를 넓은 물리 레지스터 풀에 매핑하여 가짜 의존성 제거
2. Dispatch: 명령어를 예약 스테이션으로 보내고 ROB에 엔트리 할당
3. OoO Execution: 피연산자(Operand)가 준비된 명령어부터 순서 관계없이 즉시 실행
4. Retirement (Commit): 실행 완료된 결과를 ROB 순서대로 실제 상태에 반영(In-order)
> 요약: 실행은 마음대로 하되, 결과 반영은 원래 순서를 지켜 예외 처리를 보장함

## Ⅳ. 문제점
- 하드웨어 복잡도: 대규모 ROB 및 복잡한 스케줄링 로직으로 인한 트랜지스터 소모
- 전력 효율 저하: 준비 여부를 매 사이클 체크하고 데이터를 이동시키는 데 전력 과다 사용

## Ⅴ. 개선방안
- (단기) 물리 레지스터 파일(PRF) 확장: 리네이밍 가능한 자원 확보
- (중기) 분산 예약 스테이션: 스케줄링 부하를 분산시켜 병목 지점 해소
- (장기) 체크포인트 기반 복구: 예외 발생 시 신속한 상태 복원을 위한 하드웨어 지원

## Ⅵ. 전망
- 로드맵: 단일 스레드 성능 향상을 위해 더욱 깊은 ROB(512개 이상)를 가진 구조로 진화
- CSF: 전력 한계(Power Wall) 내에서 명령어 윈도우 크기를 극대화하는 스케줄링 효율
