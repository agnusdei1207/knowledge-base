## Ⅰ. 개요
- **정의**: x86 ISA를 64비트 주소·레지스터로 확장한 CISC 프로세서 아키텍처
- **배경/필요성**: 32비트 주소 공간(4 GB)이 메모리 집약 워크로드를 수용하지 못하면서 64비트 확장이 요구됨
- **비유**: 4자리 우편번호가 부족해져 기존 체계를 유지하면서 자릿수를 8자리로 늘린 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| CISC 아키텍처의 64비트 확장 원리 | 동작 모드 3종과 레지스터 확장 구조 | 내부 micro-op 분해 메커니즘 누락 주의 |

> 요약: x86 호환성을 유지하면서 주소·레지스터를 64비트로 확장한 CISC 아키텍처임

## Ⅱ. 구성요소
```text
+------------------+
| Long Mode (64b)  |
+------------------+
        |
+------------------+     +---------------------+
| Protected (32b)  |---->| Compatibility Sub   |
+------------------+     +---------------------+
        |
+------------------+
| Real Mode (16b)  |
+------------------+

Register File:
RAX..RDX (64b) --+-- R8..R15 (신규 범용)
RIP (64b)        +-- XMM0..XMM15 (SIMD)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 동작 모드 | Real/Protected/Long 3종으로 하위 ISA 호환 실행 | 다국어 지원 OS처럼 구세대 앱도 실행 가능 |
| 범용 레지스터 | RAX~RDX 64비트 확장 + R8~R15 8개 추가, 총 16개 | 서랍 8개짜리 책상을 16개짜리로 교체 |
| RIP 상대 주소 | 명령어 포인터 기준 상대 주소 지정으로 위치 독립 코드 생성 | 현재 위치 기준 안내판으로 이동 |
| micro-op 분해 | CISC 명령을 내부 RISC형 micro-op으로 변환 후 파이프라인 실행 | 복잡한 주문서를 단순 작업 카드로 분할 |

> 요약: 3종 동작 모드, 16개 범용 레지스터, micro-op 변환 엔진이 핵심 구성임

## Ⅲ. 절차
```text
CISC 명령 Fetch --> Decode(micro-op 분해) --> Rename --> Dispatch --> Execute --> Retire
```
- 1단계: **Fetch/Decode** — 가변 길이 CISC 명령을 해독하고 1~4개 micro-op으로 분해함
- 2단계: **Register Rename** — WAR/WAW 해저드 제거를 위해 물리 레지스터에 재매핑함
- 3단계: **Dispatch/Execute** — 준비된 micro-op을 기능 유닛에 비순차 발행하여 병렬 실행함
- 4단계: **Retire** — 프로그램 순서대로 결과를 커밋하여 정확한 예외 처리를 보장함

> 요약: CISC 명령을 micro-op으로 분해한 뒤 비순차 실행하고 순차 커밋하는 4단계 흐름임

## Ⅳ. 문제점
- **디코더 복잡도 증가**: 가변 길이 명령 해석에 트랜지스터가 집중 소모됨 — 칩 면적 및 소비 전력 증가
- **호환 모드 전환 오버헤드**: Real/Protected/Long 간 모드 전환 시 파이프라인 플러시가 발생함 — 가상화·레거시 전환 시 지연 증가
- **micro-op 캐시 미스 패널티**: 복잡 명령 비율이 높으면 micro-op 캐시 적중률이 하락함 — 디코더 재실행으로 IPC 저하

> 요약: 디코더 복잡도, 모드 전환 오버헤드, micro-op 캐시 미스가 성능·전력 병목임

## Ⅴ. 개선방안
1. 단기: 디코더 폭 확장 및 micro-op 캐시 용량 증설로 디코더 병목 완화
2. 중기: 하드웨어 가상화 확장(VT-x 개선)으로 모드 전환 시 파이프라인 플러시 최소화
3. 장기: macro-fusion·micro-fusion 범위 확대로 micro-op 수 자체를 축소하여 캐시 압박 경감

> 요약: 디코더 확장 → 가상화 최적화 → fusion 확대 순서로 개선함

## Ⅵ. 전망
- **발전 방향**: APX 확장(32개 범용 레지스터), AVX-512 후속 SIMD 확장으로 데이터 병렬성 강화
- **기술사적 판단**: ARM 서버·RISC-V 확산에도 데스크톱·서버 레거시 생태계가 거대하여 당분간 주류 유지
- **기술사 제언**: CISC 외피-RISC 내부 구조 이해를 바탕으로 ARM/RISC-V와 ISA 수준 비교 역량 확보 필요
