## Ⅰ. 개요
- **정의**: 32비트 x86 명령어 집합을 64비트 주소·레지스터로 확장한 CISC ISA
- **배경/필요성**: 4GB 물리 메모리 한계를 넘어 대규모 데이터 처리와 가상 주소 공간 확보가 요구됨
- **비유**: 4차선 도로(32비트)를 8차선(64비트)으로 확장해 교통 처리량을 늘리는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 32비트 대비 구조 변화 이해 | 범용 레지스터 16개, 가상주소 48비트 | 호환 모드와 Long 모드 구분 누락 |

> 요약: x86 ISA를 64비트로 확장하여 메모리·레지스터 폭을 넓힌 아키텍처임

## Ⅱ. 구성요소
```text
  +---------------------------+
  |      Operating Mode       |
  |  Long / Compat / Legacy   |
  +-------------+-------------+
                |
    +-----------+-----------+
    |                       |
    v                       v
  +----------+       +------------+
  | Register |       |  Address   |
  | (16 GPR) |       | (48b virt) |
  +----------+       +------------+
    |                       |
    v                       v
  +----------+       +------------+
  | SIMD Ext |       |  Paging    |
  | SSE/AVX  |       |  4-Level   |
  +----------+       +------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Long Mode | 64비트 코드 실행 모드, 하위 호환 서브모드 포함 | 고속도로 본선 차로 |
| 범용 레지스터 | RAX~R15 총 16개, 각 64비트 폭 | 작업대 위 서랍 16칸 |
| 가상 주소 체계 | 48비트 가상주소, 4단계 페이지 테이블로 변환 | 우편번호 체계 확장 |
| SIMD 확장 | SSE/AVX 레지스터로 벡터 연산 수행 | 여러 택배를 한 트럭에 적재 |

> 요약: 동작 모드·확장 레지스터·4단계 페이징·SIMD가 핵심 구성요소임

## Ⅲ. 절차
```text
  명령어 인출       디코딩          실행           결과 저장
  (Fetch)         (Decode)       (Execute)      (Write-back)
   |               |               |               |
   +---버스 64b--->+---마이크로옵-->+---ALU 64b---->+
  RIP 갱신       가변길이 해석    레지스터 연산    GPR/메모리
```
- 1단계: RIP(64비트 명령어 포인터)가 가리키는 주소에서 가변 길이 명령어를 인출함
- 2단계: 복잡한 CISC 명령어를 내부 마이크로옵(micro-op)으로 분해·디코딩함
- 3단계: 64비트 ALU에서 마이크로옵 단위로 연산을 수행함
- 4단계: 연산 결과를 64비트 GPR 또는 메모리에 기록함

> 요약: 인출-디코딩-실행-저장의 4단계로 64비트 명령어를 처리함

## Ⅳ. 문제점
- 가변 길이 디코딩 복잡도: CISC 특성상 명령어 길이가 1~15바이트로 가변 — 디코더 하드웨어 면적과 전력 소모가 증가함
- 호환 모드 오버헤드: 32비트 레거시 코드를 Long Mode 내에서 실행 시 모드 전환 비용 발생 — 혼합 환경에서 성능 저하 요인임
- 메모리 사용량 증가: 포인터 크기가 4바이트에서 8바이트로 확대 — 동일 자료구조의 메모리 점유량이 증가함

> 요약: 디코딩 복잡도·호환 오버헤드·포인터 크기 증가가 주요 문제임

## Ⅴ. 개선방안
1. 단기: 마이크로옵 캐시(Decoded Stream Buffer) 도입으로 반복 디코딩 비용을 절감함
2. 중기: 하드웨어 모드 전환 최적화 및 커널 수준 컨텍스트 스위치 비용 감소 설계 적용
3. 장기: 포인터 압축(Compressed Oops) 기법과 태그 기반 주소 지정으로 메모리 효율을 개선함

> 요약: 마이크로옵 캐시·모드전환 최적화·포인터 압축으로 각 문제를 해결함

## Ⅵ. 전망
- 발전 방향: AVX-512 이후 차세대 SIMD 확장과 5단계 페이징(57비트 가상주소)으로 확장 중임
- 기술사적 판단: RISC-V 등 경쟁 ISA 대비 레거시 호환성이 강점이나 전력 효율 개선이 과제임
- 기술사 제언: 클라우드·AI 워크로드에 맞춘 명령어 확장과 에너지 비례 설계를 병행할 필요
