## Ⅰ. 개요
- **정의**: 클럭 상승·하강 양 에지에서 데이터를 전송하는 동기식 DRAM이며, 주기적 갱신(Refresh)으로 데이터를 유지함
- **배경/필요성**: CPU 버스 클럭이 증가해도 DRAM 내부 속도는 따라가지 못하므로, 프리페치 폭과 전송 에지를 확장하여 외부 대역폭을 높일 필요
- **비유**: 도로 폭(프리페치)을 넓히고 양방향(양 에지) 차선을 모두 쓰면 같은 신호등 주기(클럭)에 차량 처리량이 2배 되는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| DDR 세대별 대역폭·전압 추이 | 프리페치 비트 수 변화와 대역폭 계산 | Auto Refresh vs Self Refresh 차이 누락 주의 |

> 요약: 양 에지 전송과 프리페치 확장으로 DRAM 외부 대역폭을 세대별로 배가하는 구조임

## Ⅱ. 구성요소
```text
         CLK
          |  |
   Rising-+  +-Falling
          |  |
    +-----+--+-----+
    | DDR SDRAM     |
    | +-----------+ |
    | | Bank 0..N | |
    | | Row/Col   | |
    | +-----------+ |
    | Prefetch Buffer|
    +-------+-------+
            |
       Data Bus (x4/x8/x16)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 뱅크(Bank) | 독립적으로 행 활성화 가능한 메모리 블록, 뱅크 인터리빙으로 병렬 접근 | 창고 내 독립 구역 |
| 프리페치 버퍼 | 한 번 접근에 n비트를 미리 꺼내 외부 클럭에 맞춰 순차 전송 | 미리 꺼낸 택배 묶음 |
| 리프레시 카운터 | 주기적으로 행 주소를 순회하며 재충전 대상 행을 지정 | 순번표 |
| 클럭 동기 인터페이스 | 외부 클럭 상승+하강 에지에서 데이터를 송수신 | 양방향 컨베이어 |

> 요약: 뱅크·프리페치 버퍼·리프레시 카운터·클럭 동기 인터페이스가 DDR의 핵심 구성임

## Ⅲ. 절차
```text
명령 발행 --> 행 활성화(RAS) --> 열 선택(CAS)
   --> 프리페치 버퍼 적재 --> 양 에지 전송 --> 프리차지
                                  |
                          (리프레시 주기 도달 시)
                                  |
                          Auto/Self Refresh 수행
```
- 1단계: 메모리 컨트롤러가 RAS 명령으로 대상 뱅크의 행을 활성화
- 2단계: CAS 명령으로 열 주소를 지정하여 프리페치 폭만큼 데이터를 버퍼에 적재
- 3단계: 클럭 상승·하강 양 에지마다 버퍼 데이터를 데이터 버스로 순차 전송
- 4단계: 리프레시 주기(64 ms 내 전 행) 도달 시 Auto Refresh(컨트롤러 주도) 또는 Self Refresh(전력 절감 모드) 수행

> 요약: 행 활성→열 선택→양 에지 전송→주기적 리프레시 순으로 데이터를 읽고 유지함

## Ⅳ. 문제점
- 리프레시 대역폭 소모: 용량 증가 시 리프레시 대상 행이 비례 증가하여 유효 대역폭 감소
- 전압·발열 제약: 동작 주파수 상승에 따라 전력 소모와 신호 무결성 확보가 어려워짐
- 지연 정체: 내부 코어 속도(tRCD, tCL)는 세대 간 소폭 개선에 그쳐 지연 개선 한계 존재

> 요약: 리프레시 부담, 전력·발열, 내부 지연 정체가 DDR 세대 진화의 핵심 병목임

## Ⅴ. 개선방안
1. 단기: 리프레시 관리 최적화(Fine Granularity Refresh, DDR5의 Same-Bank Refresh)로 유효 대역폭 확보
2. 중기: 동작 전압 인하(DDR5 1.1V)와 온다이 ECC 적용으로 전력·신호 무결성 동시 개선
3. 장기: HBM(030 참조) 등 3D 적층 구조로 내부 버스 폭을 1024-bit 이상 확장하여 지연 대비 대역폭 극대화

> 요약: 리프레시 세분화 → 전압 인하·ECC → 3D 적층 대역폭 확장 순으로 DDR 한계를 극복함

## Ⅵ. 전망
- 발전 방향: DDR5 보급 확대와 DDR6(LPDDR6) 표준화로 채널당 대역폭이 지속 확대됨
- 기술사적 판단: AI·HPC 워크로드 증가로 DDR 단독 대역폭으로는 부족하여 HBM·CXL과 병용이 일반화됨
- 기술사 제언: DDR 세대별 대역폭·전력·지연 트레이드오프를 정량적으로 비교 분석하는 역량 필요
