# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: DDR SDRAM은 시스템 클럭에 동기화(Synchronous)되어, 클럭의 **상승 에지와 하강 에지 양쪽**에서 데이터를 전송하고, 내부 **병렬 프리패치(Prefetch)** 아키텍처를 결합하여 대역폭을 배가시키는 메인 메모리 규격임.
- **왜 필요한가**: CPU 클럭은 GHz로 급증하는데 메인보드 버스 클럭은 물리적 한계로 수백 MHz에 머물러, 버스 클럭을 높이지 않고도 전송률(Data Rate)을 2배 이상 확장하는 인터페이스 혁신이 필요했음.
- **핵심 직관**: 드럼 비트에 맞춰 춤을 추는데, 기존(SDR)은 '쿵' 할 때만 스텝을 밟았다면, DDR은 '쿵'과 '짝' 모두에 스텝을 밟아 2배 빠르게 동작하는 것임.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 메인 메모리 (상위 키워드) | 활성 프로세스의 작업 공간(DRAM 기반, 027 참조) | "책상 서랍" |
| SDRAM (Synchronous) | CPU 클럭에 동기화된 DRAM | "지휘자 지휘봉에 맞춰 연주" |
| DDR (Double Data Rate) | 클럭의 상승(↑)·하강(↓) 에지 양쪽에서 데이터 전송 | "'쿵'과 '짝' 모두에 동작" |
| Prefetch | 내부 셀 어레이에서 여러 비트(2n~16n)를 병렬 인출하는 기술 | "서빙 전 쟁반에 8접시 미리 담기" |
| Refresh (갱신) | DRAM 커패시터의 전하 누설을 보완하는 주기적 재충전 | "새는 양동이에 물 다시 채움" |
| tREFI | Refresh 명령 발행 간격(통상 7.8µs) | "물 채우는 알림 주기" |
| tRFC | Refresh 1회 소요 시간(DDR5: 295~350ns) | "물 채우는 데 걸리는 시간" |
| Bank Interleaving | 여러 뱅크를 번갈아 접근하여 대기시간을 은닉 | "여러 창구 번갈아 이용" |

## 깊이 이해
- **배경·문제의식**: DRAM 내부 코어의 동작 속도(셀 어레이 접근 시간)는 물리적으로 크게 빨라지지 않음. 그래서 내부에서 한 번 읽을 때 2비트(DDR)→4비트(DDR2)→8비트(DDR3/4)→16비트(DDR5)를 병렬로 미리 인출(Prefetch)하고, I/O 핀에서 상승/하강 에지에 나누어 전송하는 인터페이스 혁신으로 대역폭을 확장해 옴.
- **작동 원리**:
  - **Double Pumping**: 외부 클럭의 양 에지를 모두 활용하여 같은 클럭 주파수에서 데이터 전송률을 2배로 달성함.
  - **Prefetch Architecture**: DDR4는 8n(한 번에 8비트 병렬 인출), DDR5는 16n으로 내부 코어 속도 한계를 우회함.
  - **Bank Interleaving**: 여러 뱅크를 교차 접근하여 RAS/CAS Latency 대기를 겹쳐서 실효 대기시간을 은닉함.
- **Refresh 동작**: 1T1C 구조의 커패시터 전하 누설로 JEDEC 표준 64ms 내에 모든 셀을 재충전해야 함. Refresh 중 해당 뱅크는 접근 불가(Stall)이므로 성능 오버헤드가 발생함.
- **구체 예시**: DDR4-3200의 실제 내부 클럭은 400MHz이나, 8n Prefetch와 Double Pumping(×2)을 통해 400×8×2 / 8 = 3200MT/s의 전송률을 달성함.
- **흔한 오해·주의점**: DDR 세대가 진화할수록 전송률(MT/s)은 2배씩 증가하나, 실제 메모리 응답 시간(Absolute Latency, 약 10~15ns)은 물리적 한계로 크게 줄지 않음. 대역폭은 늘었으나 지연(Latency)은 정체되어 있는 것이 DDR의 근본적 한계임.

## 연결 개념
- **028 DRAM vs SRAM**: 1T1C 셀의 물리적 한계가 Refresh를 유발하는 근본 원인.
- **030 HBM**: DDR의 핀 수 한계를 TSV(실리콘 관통 전극) 수직 적층으로 돌파한 차세대 메모리.
- **027 메모리 계층 구조**: DDR SDRAM이 위치하는 메인 메모리 계층.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: DDR SDRAM은 클럭의 양 에지 전송(Double Pumping)과 내부 병렬 프리패치(n-bit Prefetch)를 결합하여 대역폭을 세대마다 2배씩 확장하는 동기식 메인 메모리 규격임.
> 2. **가치**: 버스 클럭 주파수를 높이지 않고도 전송률을 기하급수적으로 확장하여 CPU-메모리 대역폭 격차(Memory Wall)를 완화함.
> 3. **판단 포인트**: DDR 세대가 진화해도 절대 지연(Latency)은 정체되며, Refresh 오버헤드와 Row Hammer 취약점 등 1T1C 구조의 물리적 한계 관리가 핵심임.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 대역폭 확장 메커니즘 이해 | Double Pumping + Prefetch(2n~16n) 이중 구조 | 버스 클럭 자체가 2배 빨라졌다고 오기 |
| Refresh 병목과 관리 방안 | 누설 전류, tREFI/tRFC, Auto/Self Refresh | Refresh를 캐시 교체 알고리즘으로 오해 |
| DDR 세대 진화 방향 파악 | DDR4→5 비교(16n Prefetch, On-Die ECC, 저전력) | 단순히 "속도가 빨라졌다"로만 서술 |

> 요약: 외부 핀의 Double Pumping과 내부의 n-bit Prefetch 이중 구조를 명시하고, Refresh 병목 방어법을 함께 제시해야 함.

## Ⅰ. 개요 및 필요성

- 개요: 시스템 클럭에 동기화되어 양 에지 전송과 병렬 프리패치로 대역폭을 배가시키는 메인 메모리 규격임.
- 배경: CPU 클럭 급증에 비해 버스 클럭은 물리적 한계로 수백 MHz에 머물러 메모리 대역폭 병목이 시스템 성능을 제약함.
- 필요성: 버스 주파수의 물리적 한계를 우회하여 클럭당 전송량을 극대화하고, Bank Interleaving으로 응답 지연을 은닉해야 함.

---

## Ⅱ. 구조 및 구성요소

```text
DRAM 내부 Core Array --(병렬 n-bit Prefetch)--> I/O 버퍼 --(직렬 2배속 전송)--> CPU
  (내부 클럭 속도 유지)                          상승 에지(↑) 데이터 전송
                                                하강 에지(↓) 데이터 전송
```

| 핵심 기술 | 원리 | 대역폭 효과 |
|:---|:---|:---|
| Double Pumping | 클럭의 상승·하강 에지 양쪽에서 전송 | 외부 클럭 고정 상태에서 전송률 2배 |
| Prefetch(n-bit) | 내부 셀 어레이에서 n비트를 병렬 인출 | DDR5: 16n으로 내부 코어 속도 한계 우회 |
| Bank Interleaving | 여러 뱅크를 교차 접근 | RAS/CAS Latency 대기를 겹쳐 은닉 |

> 요약: DDR은 내부 코어를 빠르게 한 것이 아니라, 병렬 인출(Prefetch) + 양 에지 전송(Double Pumping)의 인터페이스 혁신으로 대역폭을 확장함.

---

## Ⅲ. Refresh 방식 및 흐름도

```text
시간 경과(전하 누설) -> Refresh Timer(tREFI ≈ 7.8µs) 만료 -> CPU 접근 일시 정지(Stall)
  -> 전체 셀 순차 읽기+증폭 복원(tRFC) -> 접근 재개
```

- 1단계 [RAS Only Refresh]: Row 주소만 제공하고 내부 Sense Amp가 전압을 감지·재충전하는 초기 방식.
- 2단계 [CBR (CAS before RAS)]: DRAM 내부 카운터로 외부 주소 없이 자동으로 다음 Row를 재충전하는 방식.
- 3단계 [Auto Refresh]: 현대 PC/서버의 주력 방식. 메모리 컨트롤러가 tREFI마다 Refresh 커맨드를 발행하여 자동 재충전함.
- 4단계 [Self Refresh]: 모바일 슬립 시 시스템 클럭을 끄고 DRAM 내부 발진기로 최소 전력 독립 갱신을 유지함.

> 요약: OS 구동 중에는 Auto Refresh, 대기 모드에서는 Self Refresh로 전환하여 전력과 성능 타격을 통제함.

---

## Ⅳ. 특징
- 대역폭 확장의 이면: DDR 세대마다 전송률(MT/s)은 2배씩 증가하나, 절대 지연(Absolute Latency ≈ 10~15ns)은 물리적 한계로 정체되어 지연 민감 워크로드에는 한계가 있음
- Refresh 오버헤드: tRFC(DDR5: 295~350ns) 동안 해당 뱅크 접근이 불가하여, 서버 워크로드에서 전체 시간의 5~10%가 Refresh에 소모될 수 있음
- Row Hammer 취약점: 미세 공정에서 특정 Row 반복 접근 시 인접 Row 전하가 누설되어 비트 플립이 발생하는 하드웨어 보안 취약점(TRR로 완화)

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | DDR4 | DDR5 | 선택 기준 |
|:---|:---|:---|:---|
| Prefetch | 8n | 16n | 대역폭 요구 수준 |
| 전송률(MT/s) | 2133~3200 | 4800~8400+ | 대역폭 집약 워크로드 여부 |
| 뱅크 구조 | 16 Bank(4 Group) | 32 Bank(8 Group) | 멀티스레드 동시 접근 밀도 |
| 아키텍처 변화 | 1.2V | On-Die ECC, 1.1V 저전력 | 신뢰성·전력 효율 요구 |

> 요약: DDR5는 16n Prefetch와 32 Bank로 대역폭과 동시 접근 밀도를 대폭 향상시켰으나, 절대 지연은 여전히 정체됨.

**리스크·대응:**
- Row Hammer Attack: 미세 공정에서 인접 Row 전하 누설에 의한 비트 플립 → TRR(Target Row Refresh) 로직을 메모리 컨트롤러에 탑재하여 인접 Row를 선제적 Refresh (지표: 비트 에러율)
- Soft Error 증가: 공정 미세화로 방사선에 의한 소프트 에러 빈도 증가 → DDR5부터 On-Die ECC를 칩 내부에 기본 탑재하여 1비트 에러 자동 정정 (지표: DIMM별 Corrected/Uncorrected Error Count)

**점검 지표:**
- 성능: 메모리 대역폭 사용률(Intel PCM/AMD μProf), Refresh Stall 비율
- 운영: EDAC(Error Detection and Correction) 로그의 CE/UE 카운트

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 서버 대역폭 확보: 대규모 DB 서버에 DDR5의 32 Bank 아키텍처를 활용하여 멀티스레드 병렬 트랜잭션의 메모리 동시 접근 지연을 최소화함.
2. 저전력 에지 컴퓨팅: IoT·모바일 단말에 LPDDR5의 Self Refresh 모드를 튜닝하여 대기 전력 소모를 최소화하고 배터리 수명을 극대화함.
3. 고가용성 메모리 구성: 미션 크리티컬 환경에서 On-Die ECC + 시스템 레벨 Side-band ECC를 이중화하여 멀티비트 에러에 의한 시스템 정지(Kernel Panic)를 방지함.

**결론:**
- 기술사 판단: DDR SDRAM은 Prefetch+Interleaving으로 대역폭을 확장했으나, 셀 자체의 지연(Latency)과 Refresh 오버헤드라는 1T1C 구조의 물리적 한계에 봉착하여, 지연 민감 워크로드에는 보완 설계가 필수임.
- 향후 방향: 평면적 핀 수 확장의 한계를 돌파하기 위해, GPU·AI 가속기에는 TSV 수직 적층 기반 HBM(030 참조)이 DDR을 대체하는 표준으로 자리잡음.
