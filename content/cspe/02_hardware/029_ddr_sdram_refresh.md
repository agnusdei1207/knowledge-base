## 미리 알고가기

- DDR은 클록의 상승과 하강 에지 모두에서 데이터를 전송하는 방식임
- SDRAM은 클록에 동기화되어 동작하는 DRAM이며 뱅크 구조와 행 버퍼를 가짐
- 리프레시는 커패시터 전하 누설로 인한 데이터 손실을 방지하기 위해 필수임
- RowHammer: 특정 행을 반복 접근해 인접 행의 데이터를 손상시키는 DRAM 하드웨어 결함임
- 프리페치(Prefetch): 클록 한 번에 여러 비트를 미리 읽어 내부적으로 준비해 두는 DDR 동작 방식임

## 작성 근거(검토용)

- DDR SDRAM은 전송률뿐 아니라 뱅크·행 버퍼·리프레시 스케줄의 제어 관계로 설명함
- 갱신 방식은 제어 주체·갱신 범위·갱신 중 접근으로 비교함
- 읽기·쓰기와 리프레시 일정 이후의 유효 대역폭을 최종 판단 기준으로 정리함

## Ⅰ. 개요

- **정의/개념**: DDR SDRAM은 동기식 DRAM에 양 에지 전송 방식을 적용해 같은 기본 클록에서 더 높은 대역폭을 내는 메모리이고, 리프레시는 저장 전하를 주기적으로 복원해 데이터 무결성을 유지하는 제어 메커니즘임
- **배경/필요성**: DRAM의 고속 전송과 누설 전하에 따른 데이터 보존을 함께 만족하기 위해 전송·갱신 제어가 필요함

### 쉽게 이해하기 (학습용)
- 컨베이어 벨트가 오갈 때마다 짐을 실어 나르듯 신호가 오르내릴 때마다 데이터를 보내고, 물이 새는 물통이라 틈틈이 다시 채워야 함

## Ⅱ. 특징

- 양 에지 전송과 프리페치 구조로 기본 클록 대비 높은 실효 대역폭을 제공함
- 뱅크와 행 버퍼를 활용해 병렬성을 키우지만 접근 패턴에 따라 충돌 지연이 생길 수 있음
- 리프레시는 필수라서 용량과 온도가 높아질수록 성능 손실과 전력 부담이 증가함
- 리프레시 일정과 뱅크 이용률이 유효 메모리 대역폭을 결정함

### 쉽게 이해하기 (학습용)
- 벨트가 왕복할 때마다 짐을 나르고, 미리 여러 개를 챙겨두면(프리페치) 한 번에 더 많이 나를 수 있음
- 여러 창고 칸(뱅크)을 동시에 쓰면 빠르지만, 같은 칸을 서로 쓰려 하면 기다려야 함
- 물통을 채우는 동안(리프레시)에는 짐을 나르지 못하니, 물통을 얼마나 자주 채우느냐가 실제 운반량을 좌우함

## Ⅲ. 종류 및 비교

| 판단 기준 | 자동 리프레시 | 뱅크별 리프레시 | 자체 리프레시 |
|:---|:---|:---|:---|
| 제어 주체 | 메모리 컨트롤러 | 메모리 컨트롤러 | DRAM 내부 로직 |
| 갱신 범위 | 전체 뱅크 단위 | 선택한 뱅크 단위 | DRAM 내부 일정에 따른 전체 행 |
| 갱신 중 접근 | 갱신 구간에 일반 접근이 중단됨 | 다른 뱅크는 접근 가능함 | 일반 읽기·쓰기가 중단됨 |

> 요약: 자동 리프레시는 전체 뱅크를 갱신하고, 뱅크별 리프레시는 선택한 뱅크만 갱신하며, 자체 리프레시는 DRAM 내부 로직이 전체 행을 갱신함.

### 쉽게 이해하기 (학습용)
- 자동 리프레시는 창고 전체를 한 번에 점검하고, 뱅크별 리프레시는 칸을 나눠 순서대로 점검하며, 자체 리프레시는 창고가 스스로 알아서 전체를 점검함

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| DDR 채널·클록 | 명령과 데이터 전송을 동기화하고 양 에지에서 데이터를 전송함 |
| 뱅크·행 버퍼 | 여러 뱅크의 요청을 나누고 열린 행의 데이터를 보관함 |
| 메모리 컨트롤러 | 읽기·쓰기·리프레시 명령을 타이밍 규칙에 맞춰 배치함 |
| 리프레시 스케줄러 | 모든 행이 보존 시간 안에 갱신되도록 시점과 대상 뱅크를 정함 |

```text
+----------------+     +------------------+     +------------------+
| 메모리 요청      | --> | 메모리 컨트롤러    | --> | 뱅크/행 버퍼       |
+----------------+     +------------------+     +------------------+
                                |
                                v
                        +------------------+
                        | 리프레시 스케줄러   |
                        +------------------+
```

> 요약: DDR 컨트롤러는 뱅크·행 접근과 리프레시 시점을 함께 배치함.

### 쉽게 이해하기 (학습용)
- 벨트와 신호(채널·클록), 짐을 나누어 담는 여러 창고 칸(뱅크·행 버퍼), 반입·반출 순서를 정하는 관리자(메모리 컨트롤러), 물통 채우는 시점을 정하는 담당자(리프레시 스케줄러)가 함께 움직임

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+     +-------------+
| 접근 요청 수신  | --> | 뱅크 상태 확인   | --> | 읽기·쓰기·리프레시 | --> | 데이터 전송      | --> | 다음 주기 예약   |
+-------------+     +-------------+     +-------------+     +-------------+     +-------------+
```

1. **접근 요청 수신**: 컨트롤러가 CPU나 DMA의 메모리 요청을 받음
2. **뱅크 상태 확인**: 대상 행과 뱅크 점유 상태를 판단함
3. **읽기·쓰기·리프레시 수행**: 우선순위와 타이밍 규칙에 맞게 명령을 배치함
4. **데이터 전송**: DDR 방식으로 양 에지에서 데이터를 송수신함
5. **다음 주기 예약**: 다음 리프레시 시점과 뱅크 사용 순서를 계산함

> 요약: DDR SDRAM은 접근 요청과 리프레시를 뱅크 상태와 타이밍 규칙에 맞춰 배치함.

### 쉽게 이해하기 (학습용)
- 요청이 들어오면 해당 창고 칸이 비었는지 먼저 보고, 순서 규칙대로 반입·반출이나 물통 채우기를 진행한 뒤 벨트로 짐을 보내고 다음 채울 시점을 예약함

## Ⅵ. 실무 사례

1. 대용량 서버 메모리는 뱅크별 리프레시를 적용하고 리프레시 대기율과 유효 대역폭을 확인함
2. 서버 메모리 컨트롤러는 RowHammer 방어를 위해 대상 행 리프레시를 적용하고 행 활성화율과 교정 오류 건수를 확인함

### 쉽게 이해하기 (학습용)
- 창고가 크면 칸을 나눠 순서대로 점검해 전체를 한 번에 멈추지 않게 하고, 특정 칸을 너무 자주 여닫으면 옆 칸까지 흔들릴 수 있어 그 칸을 따로 더 점검함

## Ⅶ. 결론

- DDR SDRAM은 클록 양 에지에서 데이터를 전송해 대역폭을 높이는 대신, 커패시터 전하 누설을 막을 주기적 리프레시가 반드시 필요한 메모리임
- 읽기·쓰기 요청과 리프레시 일정을 뱅크 상태에 맞춰 조정해 유효 대역폭을 확보하고, 용량이 크거나 RowHammer 위험이 있으면 뱅크별·대상 행 리프레시로 전환해야 함

### 쉽게 이해하기 (학습용)
- 짐을 나르는 시간과 물통을 채우는 시간이 겹치지 않게 잘 짜야 실제로 나를 수 있는 짐의 양이 늘어남
