## Ⅰ. 개요
- Google이 텐서플로우(TensorFlow) 가속을 위해 자체 개발한 ASIC
- 대규모 머신러닝 학습 및 추론을 위한 하드웨어 인프라 핵심

| 구분 | 내용 |
| --- | --- |
| 정의 | 텐서 연산에 최적화된 구글의 AI 전용 가속기 |
| 배경 | 데이터센터 급의 고성능 딥러닝 연산 효율 증대 필요 |
| 출제의도 | Systolic Array 구조 및 TPU의 세대별 발전 특징 이해 |

## Ⅱ. 구성요소
```
+---------------------------------------+
|  [ TPU Core ]                         |
| +-----------------------------------+ |
| | Matrix Multiply Unit (Systolic)   | |
| +-----------------------------------+ |
| | Unified Buffer | Activation Unit  | |
| +----------------+------------------+ |
+---------------------------------------+
```
| 구성요소 | 설명 | 비유 |
| --- | --- | --- |
| Systolic Array | 데이터가 격자 구조를 타고 흐르며 연산 수행 | 컨베이어 벨트 |
| Unified Buffer | 연산 중간 데이터 저장을 위한 대용량 SRAM | 부품 창고 |
| HBM | 고대역폭 메모리를 탑재하여 데이터 공급 원활화 | 초고속 파이프 |
> 요약: 시스톨릭 어레이 구조로 메모리 접근 최소화 및 연산 극대화함.

## Ⅲ. 절차
```
[TF Graph] -> [XLA Compile] -> [Weight Load] -> [Systolic Exec]
```
1. TF Graph 구성: 텐서플로우로 연산 그래프 및 데이터 흐름 정의함.
2. XLA Compile: TPU 하드웨어에 최적화된 명령어로 그래프 컴파일함.
3. Weight Load: 대규모 가중치를 HBM 메모리에 로드하여 준비함.
4. Systolic Exec: 클락마다 데이터를 인접 셀로 전달하며 행렬곱 수행함.
> 요약: 컴파일된 그래프에 따라 전용 하드웨어에서 병렬 처리함.

## Ⅳ. 문제점
- 특정 에코시스템 종속: 텐서플로우 프레임워크 외 활용 제약 존재함.
- 폐쇄적 가용성: 주로 Google Cloud Platform(GCP)에서만 사용 가능함.

## Ⅴ. 개선방안
- 멀티 프레임워크 지원: PyTorch 등 타 프레임워크 호환성 지속 확대함.
- 엣지용 TPU 보급: Coral 브랜드 등 소형 하드웨어로 사용 접점 확대함.

## Ⅵ. 전망
- TPU v5/v6 로드맵 기반의 멀티 포드(Pod) 클러스터링 확장성 강화됨.
- LLM(거대언어모델) 학습 효율 극대화가 하드웨어 설계의 핵심 성공 요인임.
