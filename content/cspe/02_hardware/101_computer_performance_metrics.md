## Ⅰ. 개요
- **정의**: 컴퓨터 시스템의 처리 능력을 정량적으로 측정하는 기준 집합
- **배경/필요성**: 시스템 설계·구매·튜닝 시 객관적 비교 근거가 없으면 의사결정이 주관에 의존하게 되므로 표준화된 측정 체계가 필요함
- **비유**: 자동차의 최고속도·연비·가속시간처럼, 컴퓨터도 여러 관점의 수치로 성능을 판단함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 다양한 지표 간 관계와 적용 맥락 이해 | MIPS·FLOPS·CPI·처리량·응답시간 구분 | 단일 지표만으로 전체 성능을 대표할 수 없음을 명시 |

> 요약: 컴퓨터 성능 지표는 처리 능력을 정량화하여 객관적 비교·최적화를 가능하게 하는 측정 체계임

## Ⅱ. 구성요소
```text
+------------------+     +------------------+     +------------------+
| 시간 기반 지표    |     | 속도 기반 지표    |     | 효율 기반 지표    |
| - 응답시간       |---->| - MIPS           |---->| - CPI            |
| - 처리량         |     | - FLOPS          |     | - IPC            |
+------------------+     +------------------+     +------------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 응답시간(Latency) | 작업 요청부터 완료까지 걸리는 경과 시간 | 주문 후 음식이 나오기까지의 대기 시간 |
| 처리량(Throughput) | 단위 시간당 완료하는 작업 수 | 식당이 1시간에 처리하는 총 주문 건수 |
| MIPS | 초당 수백만 명령어 실행 횟수 | 1초에 읽는 책 페이지 수 |
| FLOPS | 초당 부동소수점 연산 횟수, 과학 연산 성능 지표 | 1초에 풀 수 있는 수학 문제 수 |
| CPI | 명령어 1개 실행에 소요되는 평균 클럭 사이클 수 | 한 문제를 풀 때 필요한 평균 풀이 단계 수 |
| IPC | 클럭 사이클당 실행하는 명령어 수, CPI의 역수 | 한 단계에서 동시에 푸는 문제 수 |

> 요약: 시간·속도·효율 세 축의 지표를 조합해야 시스템 성능을 다면적으로 평가할 수 있음

## Ⅲ. 절차
```text
측정 목표 설정 --> 벤치마크 선정 --> 실행/데이터 수집 --> 분석/비교
```
- 1단계: 측정 목표 설정 — 평가 대상(CPU·GPU·I/O)과 워크로드 유형을 명확히 정의함
- 2단계: 벤치마크 선정 — 목표에 맞는 표준 벤치마크(SPEC CPU, LINPACK 등)를 선택함
- 3단계: 실행/데이터 수집 — 동일 조건에서 반복 측정하여 MIPS·FLOPS·응답시간 등 원시 데이터를 확보함
- 4단계: 분석/비교 — 수집 데이터를 정규화하고 기하평균 등으로 종합 점수를 산출하여 시스템 간 비교함

> 요약: 목표 설정부터 정규화 비교까지 체계적 절차를 거쳐야 신뢰할 수 있는 성능 평가가 가능함

## Ⅳ. 문제점
- MIPS 함정: 명령어 복잡도를 무시하여 ISA가 다른 시스템 간 비교 시 오해를 유발함
- 단일 지표 편향: 하나의 수치만 강조하면 실제 워크로드 성능과 괴리가 발생함
- 벤치마크 최적화: 특정 벤치마크 점수를 높이도록 튜닝하면 범용 성능 저하가 은폐됨

> 요약: 단일 지표 의존과 벤치마크 편향이 성능 평가의 신뢰성을 저해함

## Ⅴ. 개선방안
1. 단기: 복합 지표(CPI+FLOPS+처리량)를 병행 측정하여 MIPS 함정을 회피함
2. 중기: 실제 애플리케이션 기반 벤치마크 스위트를 도입하여 단일 지표 편향을 완화함
3. 장기: 워크로드 프로파일링 자동화 도구를 통해 벤치마크 최적화 왜곡을 탐지함

> 요약: 복합 측정, 실 워크로드 벤치마크, 자동 프로파일링으로 평가 신뢰성을 확보함

## Ⅵ. 전망
- 발전 방향: AI 추론·훈련 워크로드 전용 지표(TOPS, Token/s)가 기존 FLOPS 체계를 보완하는 추세임
- 기술사적 판단: 이기종 컴퓨팅(CPU+GPU+NPU) 환경에서 통합 성능 지표 프레임워크가 요구됨
- 기술사 제언: 에너지 효율(FLOPS/W)을 성능 지표에 포함하여 TCO 관점의 평가 체계를 수립할 필요
