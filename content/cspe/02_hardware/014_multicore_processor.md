# 📖 【암기용】 개념 완전 이해

> 목적: 멀티코어를 처음 봐도 왜 한 칩 안에 코어를 여러 개 넣는 방향으로 설계가 바뀌었는지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 하나의 다이(die) 또는 패키지 안에 독립적으로 명령어를 실행할 수 있는 프로세서 코어를 여러 개 통합한 구조
- **왜 필요한가**: 단일 코어의 클럭 주파수·ILP 확장은 전력·발열·설계 복잡도 한계에 부딪혔고, Pollack의 법칙에 따르면 코어 하나를 더 복잡하게 키우는 것보다 단순한 코어를 여러 개 병렬 배치하는 편이 면적당 처리량이 유리하다
- **핵심 직관**: 일꾼 한 명을 무리해서 더 빨리 뛰게 만드는 대신, 적당한 속도의 일꾼을 여러 명 투입해 전체 작업량을 늘리는 방식이다

## 깊이 이해
- **배경·문제의식**: 2000년대 중반 단일 코어의 클럭 주파수 경쟁이 전력 밀도(전력/면적) 한계에 부딪히면서, 성능 향상 축이 클럭 상승에서 코어 수 증가로 이동했다.
- **작동 원리**: 각 코어는 독립된 파이프라인, 레지스터 파일, L1/L2 캐시(사적 캐시)를 가지며, 여러 코어가 L3 캐시나 마지막 단계 캐시(LLC)를 공유하는 구성이 일반적이다.
- **작동 원리 - 동질·이질 멀티코어**: 동질(homogeneous) 멀티코어는 동일한 마이크로아키텍처 코어를 여러 개 배치하고, 이질(heterogeneous) 멀티코어(예: big.LITTLE 계열 구조)는 고성능 코어와 저전력 코어를 함께 배치해 워크로드에 따라 스케줄링한다.
- **작동 원리 - 상호 연결망**: 코어 수가 늘어날수록 코어 간 통신·캐시 일관성 트래픽을 처리하기 위한 상호 연결망이 필요하며, 소규모는 공유 버스, 중대규모는 링(ring) 또는 메시(mesh) 토폴로지를 사용하는 것이 일반적이다.
- **작동 원리 - 캐시 일관성 필요성**: 각 코어가 사적 캐시에 동일한 메모리 주소의 복사본을 가질 수 있으므로, 한 코어가 값을 갱신하면 다른 코어의 사본을 무효화하거나 갱신하는 캐시 일관성 프로토콜이 반드시 필요하다.
- **비유**: 단일 코어를 계속 키우는 것은 트럭 한 대를 점점 더 크게 만드는 것이고, 멀티코어는 적당한 크기의 트럭 여러 대를 동시에 굴리는 것과 같아서 전체 물류량(처리량) 대비 투입 자원 비율을 낮춘다.
- **흔한 오해·주의점**: 코어 수를 늘리면 성능이 코어 수에 비례해 증가한다고 단정하면 안 된다. 프로그램의 병렬화 가능 비율에 따라 실제 성능 향상은 암달의 법칙(Amdahl's Law)에 의해 제한된다.
- **흔한 오해·주의점**: 멀티코어는 단일 스레드 성능을 자동으로 높여주지 않는다. 병렬화되지 않은 순차 코드 구간은 코어 수와 무관하게 한 코어의 단일 스레드 성능에 좌우된다.

## 연결 개념
- 폴락의 법칙(Pollack's Rule) — 코어 면적 대비 성능 이득이 제곱근에 그친다는 근거로 멀티코어 채택을 뒷받침
- 캐시 일관성 프로토콜(MESI·MOESI) — 코어 간 사적 캐시 데이터 정합성을 보장하는 필수 메커니즘
- 하이퍼스레딩·SMT — 코어를 늘리지 않고 한 코어 내부 자원 활용률을 높이는 대안·보완 기법

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 클럭 확장의 한계와 멀티코어 등장 배경, 사적·공유 캐시 계층 구조, 동질·이질 코어 구성, 캐시 일관성 필요성, 암달의 법칙에 따른 병렬화 한계를 함께 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 멀티코어 프로세서는 독립적으로 실행 가능한 코어를 한 칩에 여러 개 통합해 처리량을 확장하는 구조이다.
> 2. **가치**: 클럭 주파수를 올리지 않고도 병렬 워크로드의 전체 처리량을 늘릴 수 있으며, 코어 단순화로 면적 대비 효율을 높인다.
> 3. **판단 포인트**: 성능 향상은 코어 수에 비례하지 않고 프로그램의 병렬화 비율(암달의 법칙)과 캐시 일관성 오버헤드에 좌우된다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 단일 코어 확장 한계 이해 확인 | 전력 밀도·발열 한계, Pollack의 법칙 근거 | 클럭 상승 한계를 언급하지 않고 코어 수 증가만 서술 |
| 구조 이해 확인 | 사적 L1/L2, 공유 LLC, 상호 연결망(버스·링·메시) | 캐시 계층 구조를 언급하지 않고 코어만 나열 |
| 성능 한계 판단 확인 | 암달의 법칙에 따른 병렬화 비율 제한 | 코어 수와 성능을 비례 관계로 단정 |

> 요약: 이 문제는 코어 개수 나열이 아니라 왜 멀티코어가 채택됐는지의 근거와 실제 성능 확장의 한계를 함께 요구한다.

## Ⅰ. 개요 및 필요성

- 개요: 독립적으로 명령어를 실행하는 프로세서 코어를 한 다이 또는 패키지에 여러 개 통합한 구조
- 배경: 단일 코어의 클럭 주파수·복잡도 확장이 전력 밀도와 발열 한계에 부딪히며 성능 확장 축이 코어 수 증가로 이동함
- 필요성: 병렬 워크로드 처리량을 늘리면서도 코어당 면적·전력을 억제하려면 사적 캐시·공유 캐시·상호 연결망·캐시 일관성을 포함한 멀티코어 설계가 필요함

---

## Ⅱ. 구조 및 구성요소

```text
Core 0 (Pipeline/L1/L2) --\
Core 1 (Pipeline/L1/L2) ---+-- Interconnect(Bus/Ring/Mesh) -- Shared LLC(L3) -- Memory Controller -- DRAM
Core N (Pipeline/L1/L2) --/
                                 |
                                 +-- Cache Coherence Protocol(MESI/MOESI)
```

| 구성요소 | 역할 | 산출물 |
|:---|:---|:---|
| 코어(Core) | 독립적 파이프라인·레지스터로 명령어 실행 | 스레드/프로세스별 실행 결과 |
| 사적 캐시(L1/L2) | 코어별 지역성 데이터 저장 | 접근 지연 단축 |
| 공유 캐시(LLC) | 여러 코어가 공유하는 마지막 단계 캐시 | 코어 간 데이터 공유 효율화 |
| 상호 연결망 | 코어·캐시 간 데이터 및 일관성 트래픽 전달 | 대역폭·지연 특성 결정 |
| 캐시 일관성 로직 | 사적 캐시 간 데이터 정합성 유지 | 무효화·갱신 트랜잭션 |

> 요약: 멀티코어는 코어별 사적 캐시와 공유 LLC를 상호 연결망으로 묶고, 캐시 일관성 로직으로 정합성을 유지하는 구조다.

---

## Ⅲ. 동작원리 및 흐름도

```text
스레드/프로세스 스케줄링 -> 코어 배정
  -> 코어별 독립 실행(파이프라인, 사적 캐시 접근)
  -> 사적 캐시 미스 -> 공유 LLC 조회
  -> 다른 코어가 동일 라인 보유 시 캐시 일관성 프로토콜 동작
  -> 상호 연결망을 통한 데이터 전달 -> 실행 결과 반영
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | OS 스케줄러가 스레드를 코어에 배정 | core affinity, load balancing |
| 2 | 코어가 사적 캐시에서 데이터 접근 시도 | L1/L2 hit rate |
| 3 | 캐시 미스 시 LLC 및 다른 코어 캐시 조회 | 캐시 일관성 프로토콜 상태 전이 |
| 4 | 상호 연결망을 통해 데이터 전달 후 실행 계속 | 코어 간 통신 지연(cross-core latency) |

> 요약: 멀티코어 동작은 코어별 독립 실행을 기본으로 하되, 캐시 미스와 데이터 공유 시점에 일관성 프로토콜과 상호 연결망이 개입한다.

## Ⅳ. 특징

| 구분 | 동질(Homogeneous) 멀티코어 | 이질(Heterogeneous) 멀티코어 | 수치·표준 포인트 |
|:---|:---|:---|:---|
| 코어 구성 | 동일 마이크로아키텍처 코어 다수 | 고성능·저전력 코어 혼합 배치 | 워크로드별 코어 선택 스케줄링 |
| 설계 복잡도 | 상대적으로 단순 | 스케줄러·코어 간 마이그레이션 로직 필요 | 이기종 코어 간 성능 편차 관리 |
| 전력 효율 | 균일한 전력 특성 | 경부하 시 저전력 코어로 전력 절감 | 코어별 DVFS(Dynamic Voltage Frequency Scaling) |
| 적용처 | 서버·데스크톱 범용 처리 | 모바일·전력 민감 클라이언트 기기 | 배터리 수명, 발열 목표 |

> 요약: 동질 멀티코어는 설계가 단순하고, 이질 멀티코어는 전력 효율을 위해 코어 간 워크로드 배분 복잡도를 감수한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 단일 코어 확장 | 멀티코어 확장 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 클럭·ILP 확대 중심 | 코어 수 확대 중심 | 병렬화 가능 워크로드 비중으로 결정 |
| 비용/성능 | 면적 대비 성능 이득이 제곱근에 그침(Pollack의 법칙) | 단순 코어 다수 배치로 면적당 처리량 유리 | 처리량 목표와 전력 예산 대비 판단 |
| 운영/위험 | 단일 스레드 병목에 취약하지 않음 | 병렬화 실패 구간은 암달의 법칙으로 이득 제한 | 순차 구간 비율 사전 분석 |

> 요약: 병렬화 가능 비율이 높은 워크로드는 멀티코어가 유리하고, 순차 의존이 큰 워크로드는 단일 코어 성능이 판단 기준으로 남는다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 병렬화 이득 제한 | 순차 코드 비율이 높은 워크로드 | 알고리즘 병렬화 재설계, 파이프라인 병렬 처리 | 암달의 법칙 기반 이론 상한 대비 실측 성능 |
| 캐시 일관성 오버헤드 | 코어 수 증가에 따른 무효화·브로드캐스트 트래픽 증가 | 디렉터리 기반 일관성, NUMA 최적화 | 코어 간 캐시 트래픽량, 원격 접근 지연 |
| 코어 간 부하 불균형 | 스케줄링 정책 미흡 | 코어 친화도·이기종 스케줄링 정책 적용 | 코어별 사용률 편차 |

> 요약: 멀티코어 리스크는 순차 구간 병목과 코어 간 일관성·부하 불균형이며, 병렬화 설계와 일관성 프로토콜 선택으로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 처리량 | 코어 수 대비 실측 성능 향상 비율 | 벤치마크(병렬 워크로드) |
| 캐시 일관성 오버헤드 | 코어 간 무효화 트래픽 비율 목표치 이내 | 성능 카운터, 인터커넥트 트레이스 |
| 전력 효율 | 코어당 전력 대비 처리량 목표 충족 | 전력 측정, DVFS 로그 |

> 요약: 도입 효과는 병렬 처리량 향상 비율, 캐시 일관성 오버헤드, 전력 효율 세 지표로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 서버·데이터센터 워크로드는 동질 멀티코어와 디렉터리 기반 캐시 일관성을 채택해 코어 수 확장에 따른 일관성 오버헤드를 관리함
2. 모바일·클라이언트 기기는 이질 멀티코어(big.LITTLE 계열)로 경부하 작업을 저전력 코어에 배정해 배터리 수명을 확보함
3. 병렬화 비율이 낮은 워크로드는 코어 수 확장보다 단일 코어 IPC·ILP 개선(비순서 실행, 캐시 계층 최적화)을 우선 검토함

**결론 (2줄):**
- 기술사 판단: 코어 수 확장은 병렬화 가능 비율이 높은 워크로드에서만 효과적이며, 순차 구간이 큰 워크로드는 단일 코어 성능 개선이 병행되어야 함
- 향후 방향: 코어 수 증가에 따른 일관성·인터커넥트 복잡도 상승에 대응해 NUMA 최적화, 디렉터리 기반 일관성, 이질 코어 스케줄링 고도화가 함께 진행되고 있음
