## Ⅰ. 개요
- 정의: 하나의 다이(Die) 또는 패키지 안에 두 개 이상의 독립적인 코어를 집적한 프로세서
- 배경: 클록 주파수 향상의 한계(Power Wall) 및 ILP 한계 극복을 위한 TLP 활용
- 출제 의도: 멀티코어의 이점, 구조적 분류, 병렬 처리 효율(Amdahl's Law) 이해

## Ⅱ. 구성요소
- ASCII 구조도
  +---------------------------------------+
  |              Processor                |
  |  +----------+          +----------+   |
  |  | Core 0   |          | Core 1   |   |
  |  | [L1/L2]  |          | [L1/L2]  |   |
  |  +-----+----+          +-----+----+   |
  |        |                     |        |
  |  +-----+---------------------+----+   |
  |  |        Shared L3 Cache         |   |
  |  +--------------------------------+   |
  +---------------------------------------+

- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 개별 코어 | ALU, CU, 레지스터를 갖춘 독립 연산 단위 | 개별 작업자 |
| 인터커넥트 | 코어 간 데이터 교환 및 공유 메모리 통로 | 사내 메신저 |
| 공유 캐시 | 모든 코어가 공동으로 사용하는 데이터 저장소 | 공용 탕비실 |
> 요약: 독립된 작업자(코어)들이 자원을 공유하며 병렬로 업무를 처리함

## Ⅲ. 절차
- ASCII 흐름도
  (App Launch) -> (Task Decomposition) -> (Core Scheduling) -> (Parallel Exec)
                                                                    |
                       +---------<-----------<-----------<----------+
                       v
                (Sync/Barrier) -> (Result Aggregate)

- 4단계 설명
1. 작업 분할: 큰 업무를 여러 개의 스레드나 프로세스로 쪼갬 (Divide)
2. 스케줄링: OS가 각 작업을 가용한 코어에 할당
3. 병렬 실행: 각 코어가 할당된 코드를 동시에 독립적으로 수행
4. 동기화: 공유 데이터 접근 제어 및 최종 결과 취합 (Conquer)
> 요약: 분할 정복(Divide & Conquer) 원리에 기반하여 전체 처리 성능을 높임

## Ⅳ. 문제점
- 소프트웨어 병렬화: 순차적 실행 부분이 전체 성능 향상의 발목을 잡음 (암달의 법칙)
- 캐시 일관성: 여러 코어가 동일 데이터를 가질 때 불일치 발생 가능성

## Ⅴ. 개선방안
- (단기) 병렬 프로그래밍: OpenMP, Pthreads 등을 통한 효율적 코드 작성
- (중기) 하이브리드 코어: 부하에 따라 빅 코어와 리틀 코어를 선택적으로 사용
- (장기) 매니코어(Many-core): 수백 개 이상의 코어를 배치한 가속기 구조 고도화

## Ⅵ. 전망
- 로드맵: 단일 칩 내 코어 수 경쟁을 넘어 도메인 특화(DSA) 코어 통합으로 진화
- CSF: 코어 간 통신 지연(Latency) 최소화 및 메모리 대역폭(Bandwidth) 확보
