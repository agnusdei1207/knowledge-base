# 014. 멀티코어 프로세서 (Multicore Processor) [출제:132회]

## 미리 알고가기

- **코어 (Core)**: 독자적으로 명령어를 실행할 수 있는 CPU 내부의 최소 단위임
- **TLP (Thread Level Parallelism)**: 여러 개의 스레드를 동시에 실행하여 시스템 전체의 처리량을 높이는 병렬성임
- **암달의 법칙 (Amdahl's Law)**: 프로그램의 병렬화되지 않는 부분에 의해 전체 성능 향상이 제한된다는 법칙임

## Ⅰ. 개요

- **정의/개념**: 멀티코어 프로세서는 하나의 물리적인 반도체 칩(Die) 내에 두 개 이상의 독립적인 코어를 탑재하여 스레드 단위의 병렬 처리를 수행하는 CPU 아키텍처임
- **배경/필요성**: 단일 코어의 클록을 높이는 방식은 전력 소모와 발열(Power Wall) 문제로 한계에 직면함. 이를 해결하기 위해 주파수를 낮추는 대신 코어 수를 늘려 전력 효율을 높이면서 전체 처리량을 증대시키는 방향으로 진화함

## Ⅱ. 특징 및 비교

멀티코어는 동일한 코어를 배치하거나 용도에 맞게 서로 다른 코어를 섞어서 구성함.

| 비교 항목 | 동종 멀티코어 (Homogeneous) | 이종 멀티코어 (Heterogeneous) |
|:---|:---|:---|
| **코어 구성** | 모두 동일한 성능/구조의 코어 | 성능/전력 특성이 다른 코어 조합 |
| **대표 기술** | 일반적인 서버/데스크톱 CPU | **ARM big.LITTLE, Intel Hybrid** |
| **스케줄링** | 단순함 (어느 코어나 동일 성능) | 복잡함 (작업 부하에 따라 코어 선택) |
| **장점** | 설계 및 소프트웨어 최적화 용이 | **전력 대비 성능(Perf/Watt) 극대화** |
| **주요 활용** | 병렬 연산, 서버 가상화 | 스마트폰 AP, 저전력 노트북 |

> 요약: 성능 일관성이 중요하면 동종, 전력 효율이 중요하면 이종 멀티코어를 선택함.

## Ⅲ. 구성요소/구조

멀티코어는 각 코어의 독립성과 공유 자원(L3 캐시, 메모리 버스) 간의 조화가 중요함.

- **구성요소**:
  - **Individual Core**: Fetch/Decode/Execute 유닛을 갖춘 독립 실행체
  - **Private Cache (L1, L2)**: 각 코어만 접근하는 고속 캐시로 데이터 지연 최소화
  - **Shared Cache (L3/LLC)**: 모든 코어가 공유하며 코어 간 데이터 교환 및 중복 방지
  - **Interconnect**: 코어와 메모리 컨트롤러를 연결하는 내부 통로 (Bus, Ring, Mesh 등)
  - **Coherence Engine**: 여러 코어의 캐시 데이터가 일치하도록 관리 (MESI 프로토콜 등)

- **아키텍처 구조도 (ASCII)**:

```text
+-------------------------------------------+
|          Multi-Core Processor             |
| +-----------+ +-----------+ +-----------+ |
| |  Core 0   | |  Core 1   | |  Core N   | |
| | +-------+ | | +-------+ | | +-------+ | |
| | |L1/L2 C| | | |L1/L2 C| | | |L1/L2 C| | |
| | +-------+ | | +-------+ | | +-------+ | |
| +-----+-----+ +-----+-----+ +-----+-----+ |
|       |             |             |       |
| +-----v-------------v-------------v-----+ |
| |        Shared L3 Cache / LLC          | |
| +-------------------+-------------------+ |
|                     |                     |
|          +----------v----------+          |
|          | Memory Controller   |          |
|          +---------------------+          |
+-------------------------------------------+
```

1. **독립성**: 각 코어는 자신만의 L1/L2 캐시를 가져 서로 간섭 없이 연산 수행
2. **협력**: L3 캐시를 통해 코어 간 데이터를 공유하고 메모리 접근 횟수를 줄임

## Ⅳ. 문제점 및 개선방안

1. **메모리 대역폭 병목 (Memory Wall)**: 코어 수는 늘어나는데 메모리로 가는 통로가 좁으면 코어들이 데이터를 기다리느라 멈춤
   - **개선방안**: **DDR5, HBM(고대역폭 메모리)** 등 고속 메모리를 도입하고, 메모리 컨트롤러를 다중화(Multi-channel)함 (확인: 메모리 대기 시간 및 대역폭 점유율)

2. **캐시 일관성(Cache Coherence) 부하**: 코어가 많아질수록 서로의 캐시를 감시하고 수정 정보를 전달하는 트래픽이 기하급수적으로 늘어남
   - **개선방안**: **디렉터리 기반(Directory-based)** 일관성 유지 기법이나 효율적인 스누핑(Snooping) 프로토콜을 적용함 (확인: 코어 간 일관성 트래픽 비중)

3. **소프트웨어 병렬화 한계 (Amdahl's Law)**: 아무리 코어가 많아도 프로그램의 10%가 직렬로 동작한다면 성능 향상은 최대 10배를 넘지 못함
   - **개선방안**: **병렬 프로그래밍 모델(OpenMP, Pthreads)**을 고도화하고, 직렬 구간은 클록이 높은 고성능 코어가 처리하게 하는 하이브리드 전략을 사용함 (확인: 코어 수 대비 성능 향상 곡선)

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 클라우드 가상화 | 수십 개의 코어를 가상 머신(VM)에 할당하여 다수의 사용자가 독립적인 환경에서 동시 작업 수행 | 서버 수용량 (Density), 자원 격리 수준 |
| 모바일 기기 (AP) | 웹 서핑은 저전력 코어로, 고사양 게임은 고성능 코어로 처리하여 배터리 효율 극대화 | 배터리 지속 시간, 온도 제어(Throttling) |
| 빅데이터 분석 | 데이터를 쪼개어 수많은 코어에 분산 배치하고 동시에 집계 연산 수행 (MapReduce 등) | 전체 데이터 처리 시간, 선형 확장성 |

> 요약: 작업의 독립성이 높을수록 멀티코어의 도입 효과가 극대화됨.

## Ⅵ. 결론

멀티코어 프로세서는 단일 성능의 한계를 '규모의 경제'로 극복한 현대 컴퓨팅의 표준 구조임. 기술사는 단순히 코어 개수를 늘리는 것보다, 늘어난 코어들이 메모리와 캐시라는 공유 자원을 얼마나 효율적으로 나누어 쓰고, 소프트웨어가 이 병렬성을 얼마나 잘 활용하는지가 성능의 실질적 핵심임을 이해해야 함.

향후 멀티코어는 칩렛(Chiplet) 기술을 통해 수백 개의 코어를 하나의 패키지에 담는 방향으로 진화할 것이며, 동시에 AI 연산 등을 위한 특수 코어를 포함하는 이종 구성이 더욱 가속화될 것임. 결국 최적의 멀티코어 시스템은 하드웨어의 병렬성과 소프트웨어의 알고리즘이 완벽히 조화될 때 완성됨.
