## Ⅰ. 개요
- **정의**: 하나의 칩 위에 독립적으로 명령어를 실행하는 다수의 프로세서 코어를 집적한 구조
- **배경/필요성**: 단일 코어의 클럭 향상이 전력 벽·ILP 벽(013 참조)에 도달하면서, 처리량 확장을 위해 코어 수를 늘리는 접근이 필요해짐
- **비유**: 한 명의 숙련 요리사를 더 빠르게 만드는 대신, 여러 요리사를 주방에 배치하여 동시 조리량을 늘리는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 멀티코어 전환의 근거와 설계 트레이드오프 | 폴락의 법칙(015 참조) 기반 면적 효율 논거 | 암달의 법칙에 의한 병렬화 한계 명시 |

> 요약: 전력·ILP 한계를 우회하여 칩 면적당 처리량을 높이는 병렬 프로세서 구조임

## Ⅱ. 구성요소
```text
  +-------+  +-------+  +-------+  +-------+
  | Core0 |  | Core1 |  | Core2 |  | Core3 |
  | L1 I$ |  | L1 I$ |  | L1 I$ |  | L1 I$ |
  | L1 D$ |  | L1 D$ |  | L1 D$ |  | L1 D$ |
  +---+---+  +---+---+  +---+---+  +---+---+
      |          |           |          |
      +-----+----+-----+----+-----+----+
            |          |          |
       +----+----+  +--+--+  +---+---+
       | L2 (공유)|  | Bus |  | Mem   |
       | 또는 전용|  |     |  | Ctrl  |
       +---------+  +-----+  +-------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 프로세서 코어 | 독립 파이프라인·레지스터 파일을 갖춘 실행 단위 | 개별 조리 동선을 가진 요리사 |
| 캐시 계층 | L1은 코어 전용, L2/L3는 공유하여 데이터 접근 지연을 줄임 | 개인 냉장고(L1)와 공용 창고(L2/L3) |
| 인터커넥트 | 코어 간·캐시 간 데이터를 전달하는 버스 또는 NoC(Network-on-Chip) | 주방 내 식재료 이동 통로 |
| 캐시 일관성 프로토콜 | MESI 등으로 공유 데이터의 일관성을 보장함 | 모든 요리사가 같은 레시피 버전을 보도록 동기화하는 규칙 |

> 요약: 독립 코어·계층 캐시·인터커넥트·일관성 프로토콜이 멀티코어의 핵심 구성임

## Ⅲ. 절차
```text
  태스크 분할      스레드 배정      병렬 실행        결과 합산
  (병렬 식별)     (코어 매핑)     (동시 처리)      (동기화)
     |               |               |               |
     +---태스크--->   +---스레드--->   +---코어별--->   +
  순차/병렬       OS 스케줄러     캐시 일관성     배리어/락
  영역 구분       부하 균등 배치   프로토콜 동작    최종 결과 병합
```
- 1단계: 프로그램을 순차 영역과 병렬 가능 영역으로 분할하여 태스크를 식별함
- 2단계: OS 스케줄러가 스레드를 가용 코어에 부하 균등하게 배정함
- 3단계: 각 코어가 할당된 스레드를 동시에 실행하며, 캐시 일관성 프로토콜이 공유 데이터를 관리함
- 4단계: 배리어·락 등 동기화 메커니즘으로 부분 결과를 합산하여 최종 결과를 산출함

> 요약: 분할 → 배정 → 병렬 실행 → 동기화 합산의 흐름으로 다중 코어를 활용함

## Ⅳ. 문제점
- 암달의 법칙 제약: 순차 영역 비율 `s`가 존재하면 최대 속도향상이 `1/s`로 제한됨 — 코어 수를 늘려도 성능이 수렴함
- 캐시 일관성 오버헤드: 코어 수 증가 시 일관성 트래픽이 `O(N^2)`으로 증가함 — 인터커넥트 대역폭이 병목이 됨
- 병렬 프로그래밍 난이도: 데드락·레이스 컨디션 등 동시성 버그 발생 확률이 코어 수에 비례하여 증가함 — 개발·디버깅 비용 상승

> 요약: 순차 영역 한계·일관성 트래픽·동시성 버그가 멀티코어 확장의 주요 장벽임

## Ⅴ. 개선방안
1. 단기: 병렬화 라이브러리(OpenMP, TBB) 및 자동 병렬화 컴파일러 지원으로 순차 영역을 축소
2. 중기: 디렉터리 기반 일관성 프로토콜 도입으로 트래픽을 `O(N)`으로 줄이고 계층 NoC 적용
3. 장기: 트랜잭셔널 메모리(TM) 및 Actor 모델 등 높은 수준의 동시성 추상화로 프로그래밍 복잡도 감소

> 요약: 자동 병렬화·디렉터리 프로토콜·TM 도입으로 멀티코어 확장성을 강화함

## Ⅵ. 전망
- 발전 방향: 이종 멀티코어(big.LITTLE, CPU+GPU+NPU)로 워크로드별 최적 코어를 선택하는 구조가 확산됨
- 기술사적 판단: 폴락의 법칙(015 참조)에 따라 소형 코어 다수 배치가 면적 효율에서 유리하며, 칩렛(chiplet) 기반 확장이 가속 중임
- 기술사 제언: 멀티코어 확장 시 소프트웨어 병렬화 역량이 하드웨어 투자 대비 성능 실현의 핵심이므로, 아키텍처와 SW 생태계를 함께 고려할 필요가 있음
