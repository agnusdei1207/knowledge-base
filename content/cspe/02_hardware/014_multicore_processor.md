## 미리 알고가기

- Core: 명령어 fetch, decode, execute가 가능한 독립 실행 단위임
- Shared cache: 여러 코어가 함께 사용하는 LLC 같은 캐시 계층임
- Coherence: 여러 캐시의 같은 주소 데이터가 모순되지 않도록 유지하는 규칙임
- Amdahl's Law: 직렬 구간이 전체 병렬 성능 향상을 제한한다는 법칙임

## Ⅰ. 개요

- **정의**: 멀티코어 프로세서는 하나의 칩 또는 패키지 안에 여러 CPU 코어를 배치해 여러 스레드나 프로세스를 병렬 실행하는 프로세서 구조임. 병렬화 가능성, 캐시 일관성, 메모리 대역폭, 전력 예산을 기준으로 성능 확장성을 판단함.
- **배경/필요성**: 클록 주파수와 단일 코어 복잡도 증가는 전력과 발열 한계에 부딪힘. 멀티코어는 작업을 여러 코어에 나누어 처리량을 높이고 전력 대비 성능을 개선하기 위한 주류 설계가 됨.
- **비유**: 한 명의 고성능 작업자에게 모든 일을 몰아주는 대신 여러 작업자가 각자 일을 나눠 처리하는 작업장임.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 코어 수 증가와 병렬 성능 한계 판단 | shared cache, coherence, synchronization, Amdahl | 코어 수가 곧 성능 배수라는 설명 |

> 요약: 멀티코어 성능은 코어 수보다 병렬화율, 공유 자원, 동기화 비용에 의해 결정됨.

## Ⅱ. 특징/비교

| 판단 기준 | 단일 고성능 코어 | 멀티코어 |
|:---|:---|:---|
| 성능 확장 | 클록, OoO, cache 확대로 단일 스레드 성능을 높임 | thread/task 병렬성으로 전체 처리량을 높임 |
| 한계 요인 | 전력 밀도, 복잡도, ILP 부족 | 직렬 구간, 동기화, 메모리 대역폭, coherency |
| 소프트웨어 조건 | 기존 순차 프로그램 성능 개선에 유리함 | 병렬 알고리즘, thread scheduling, lock 설계가 필요함 |
| 적용 기준 | latency-critical 단일 작업 | 서버, 모바일 SoC, 병렬 서비스, batch 처리 |

> 요약: 단일 지연시간은 큰 코어, 전체 처리량은 멀티코어가 유리하지만 소프트웨어 병렬화가 전제임.

## Ⅲ. 구성요소

```text
+------------------------------------------------+
|                Multicore Processor             |
| +------+  +------+  +------+  +------+         |
| |Core0 |  |Core1 |  |Core2 |  |Core3 |         |
| +--+---+  +--+---+  +--+---+  +--+---+         |
|    |         |         |         |              |
| +--v---------v---------v---------v--+           |
| | Shared LLC / Coherence / NoC      |           |
| +----------------+------------------+           |
|                  v                              |
|          +---------------+                      |
|          | Memory Ctrl   |                      |
|          +---------------+                      |
+------------------------------------------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| CPU 코어 | 독립적으로 thread를 실행하는 처리 단위임 | 작업자 |
| private cache | 각 코어 가까이에 둔 L1/L2 캐시로 지연시간을 줄임 | 개인 책상 |
| shared LLC | 코어 간 데이터 공유와 DRAM 접근 완화를 담당함 | 공용 창고 |
| NoC/인터커넥트 | 코어, 캐시, 메모리 컨트롤러 사이 요청을 전달함 | 내부 도로 |
| Coherence logic | 같은 데이터 사본의 상태를 일관되게 유지함 | 재고 관리자 |

> 요약: 멀티코어는 독립 코어와 공유 메모리 계층을 일관성 프로토콜로 묶은 구조임.

## Ⅳ. 절차

```text
+----------+     +----------+     +----------+     +----------+
| Split    | --> | Schedule | --> | Execute  | --> | Sync     |
+----------+     +----------+     +----------+     +----------+
 task/thread      core assign      cache/coherency  merge result
```

1. **작업 분할** - 애플리케이션을 thread, process, task 단위로 나누고 공유 데이터를 식별함
2. **코어 배치** - OS scheduler가 우선순위, affinity, 부하에 따라 코어를 할당함
3. **병렬 실행** - 각 코어가 private cache를 활용하며 필요한 경우 shared cache와 메모리에 접근함
4. **동기화와 병합** - lock, barrier, atomic 연산으로 결과 순서와 공유 상태를 맞춤

> 요약: 멀티코어 성능은 작업 분할, 코어 배치, 캐시 활용, 동기화 비용의 합으로 결정됨.

## Ⅴ. 문제점

- **P1 병렬화 한계**: 직렬 구간과 lock 경합이 남으면 코어 수 증가만큼 성능이 늘지 않음
- **P2 캐시 일관성 비용**: 공유 데이터 쓰기와 false sharing이 invalidate 트래픽을 증가시켜 지연을 키움
- **P3 전력·열 밀도**: 모든 코어를 동시에 고클록으로 동작시키면 thermal throttling과 전력 예산 초과가 발생함

> 요약: 멀티코어 확장은 소프트웨어 병렬성, 공유 데이터, 전력 예산의 세 조건을 만족해야 효과가 있음.

## Ⅵ. 개선방안

- **P1 대응**: lock-free 구조, 작업 큐, 병렬 알고리즘 재설계, Amdahl 분석을 적용함 (확인: speedup, lock wait)
- **P2 대응**: cache line padding, read-mostly 분리, NUMA/cache affinity, coherence-friendly data layout을 적용함 (확인: invalidation, LLC miss)
- **P3 대응**: DVFS, core parking, big.LITTLE, workload consolidation으로 전력과 온도를 제어함 (확인: throttling, perf/W)

> 요약: 멀티코어 개선은 코어 증설보다 병렬 소프트웨어와 공유 자원 관리가 핵심임.

## Ⅶ. 전망

- **발전 방향**: 멀티코어는 heterogeneous core, chiplet, GPU/NPU, CXL 메모리와 결합해 단일 칩 내부 병렬성을 패키지·노드 수준 병렬성으로 확장함
- **기술사적 판단**: 코어 수는 메모리 대역폭, LLC 크기, coherence 방식, 전력/발열, 소프트웨어 병렬화율과 함께 결정해야 함; scaling curve, lock contention, cache miss, coherence traffic, NUMA remote access 비율을 측정해 코어 증가가 실제 처리량 증가로 이어지는지 확인함
- **기술사 제언**: Amdahl 한계, cache coherence 비용, 메모리 대역폭 병목을 포함해 "코어 수 증가=성능 증가" 오류를 피해야 함
