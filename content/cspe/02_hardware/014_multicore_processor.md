## Ⅰ. 개요
- **정의**: 단일 칩 내에 독립적인 실행 코어를 복수 개 집적하여 스레드 수준 병렬성(TLP)을 활용하는 프로세서
- **배경/필요성**: ILP(013 참조)만으로는 성능 향상에 한계가 있고, 클럭 상승은 전력 벽에 부딪힘. 코어를 늘려 TLP로 처리량을 확보하는 방향이 필요함
- **비유**: 혼자서 빨리 달리는 데 한계가 있으므로, 여러 주자가 릴레이 코스를 나누어 동시에 달리는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 멀티코어 등장 배경 | ILP 벽 + 전력 벽 | 클럭 주파수 한계와 암달의 법칙 모두 언급 |
| 코어 간 일관성 | 캐시 코히어런스 프로토콜(019 참조) | MESI 등 구체적 프로토콜명 포함 필요 |
| 면적 대비 성능 | 폴락의 법칙(015 참조) | 코어 면적 vs 성능의 비선형 관계를 수식으로 제시 |

> 요약: ILP 한계를 넘어 복수 코어로 TLP를 활용하며, 캐시 일관성과 면적 효율이 핵심 과제임

## Ⅱ. 구성요소
```text
+-----------------------------------------------------+
|                    Single Chip                       |
|  +--------+  +--------+  +--------+  +--------+     |
|  | Core 0 |  | Core 1 |  | Core 2 |  | Core 3 |     |
|  | L1 I/D |  | L1 I/D |  | L1 I/D |  | L1 I/D |     |
|  +---+----+  +---+----+  +---+----+  +---+----+     |
|      |           |           |           |           |
|  +---+---+   +---+---+   +---+---+   +---+---+      |
|  |  L2   |   |  L2   |   |  L2   |   |  L2   |      |
|  +---+---+   +---+---+   +---+---+   +---+---+      |
|      +-------+---+-------+---+-------+               |
|                  |                                    |
|           +------+------+                             |
|           | Shared L3   |                             |
|           +------+------+                             |
|                  |                                    |
|         +--------+--------+                           |
|         | Interconnect    |                           |
|         | (Ring/Mesh Bus) |                           |
|         +-----------------+                           |
+-----------------------------------------------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 코어(Core) | 독립 파이프라인·레지스터·L1 캐시를 갖는 실행 단위 | 독립 조리대와 개인 재료함을 가진 각 요리사 |
| 공유 L3 캐시 | 전 코어가 접근하는 공유 캐시로 메모리 접근 지연을 줄임 | 모든 요리사가 공용으로 쓰는 대형 냉장고 |
| 인터커넥트 | 코어·캐시·메모리 컨트롤러를 연결하는 온칩 네트워크 | 각 조리대를 연결하는 주방 내 통로 |
| 코히어런스 컨트롤러 | MESI 등 프로토콜로 캐시 간 데이터 일관성을 유지함(019 참조) | 재료 변경 시 다른 요리사에게 알리는 전달 체계 |

> 요약: 독립 코어가 L1/L2를 갖고, 공유 L3와 인터커넥트로 연결되며, 코히어런스가 일관성을 보장함

## Ⅲ. 절차
```text
Task --> OS Scheduler --> Thread Assign --> Parallel Exec --> Sync/Coherence --> Result Merge
```
- 1단계: **스레드 할당** — OS 스케줄러가 태스크를 스레드로 분할하여 각 코어에 배정함
- 2단계: **병렬 실행** — 각 코어가 독립적으로 할당된 스레드를 실행함
- 3단계: **동기화·일관성 유지** — 공유 데이터 접근 시 캐시 코히어런스 프로토콜과 동기화 프리미티브(락·배리어)를 적용함
- 4단계: **결과 병합** — 각 코어의 실행 결과를 합산하여 최종 출력을 생성함

> 요약: OS가 스레드를 코어에 분배하고, 코히어런스와 동기화를 거쳐 결과를 병합함

## Ⅳ. 문제점
- **암달의 법칙 한계**: 순차 실행 비율이 존재하면 코어 수를 늘려도 속도 향상이 `1/s`로 수렴하여 코어 활용률이 저하됨
- **캐시 코히어런스 오버헤드**: 코어 수 증가 시 코히어런스 트래픽이 O(N^2)로 증가하여 인터커넥트 대역폭이 병목이 됨
- **소프트웨어 병렬화 난이도**: 기존 순차 프로그램을 멀티스레드로 변환하는 데 데이터 레이스·데드락 등 동시성 버그가 발생함

> 요약: 순차 비율 수렴, 코히어런스 트래픽, 병렬 프로그래밍 난이도가 주요 문제임

## Ⅴ. 개선방안
1. 단기: **태스크 병렬 프레임워크** — OpenMP·TBB 등으로 순차 코드를 점진적으로 병렬화하여 순차 비율을 줄임
2. 중기: **디렉터리 기반 코히어런스** — 스누핑 대신 디렉터리 프로토콜을 적용하여 코히어런스 트래픽을 O(N)으로 축소함
3. 장기: **트랜잭셔널 메모리** — 락 없는 원자적 코드 블록으로 데이터 레이스·데드락 위험을 구조적으로 제거함

> 요약: 병렬 프레임워크, 디렉터리 코히어런스, 트랜잭셔널 메모리로 단계적으로 개선함

## Ⅵ. 전망
- **발전 방향**: 이기종 멀티코어(big.LITTLE, CPU+GPU+NPU)로 워크로드별 최적 코어를 동적 할당하는 구조로 진화함
- **기술사적 판단**: 폴락의 법칙(015 참조)에 따라 소형 코어 다수 배치가 면적 대비 처리량에서 유리하며, 전력 효율이 핵심 지표로 부상함
- **기술사 제언**: 워크로드의 병렬화 가능 비율을 사전 분석하고, 코어 수·크기·이기종 구성을 최적화하는 설계 방법론이 필요함
