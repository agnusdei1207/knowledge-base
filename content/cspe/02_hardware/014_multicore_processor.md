# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 멀티코어 프로세서는 단일 반도체 다이(Die) 안에 2개 이상의 독립 연산 코어를 집적하여, 스레드 수준 병렬성(TLP)으로 처리량을 배가하는 아키텍처다.
- **왜 필요한가**: 클럭 상향은 전력·발열(Power Wall)에 막혔고 단일 코어 ILP 확장도 수확 체감(015 폴락의 법칙)에 봉착했으므로, 클럭을 낮추더라도 코어 수를 늘려 전체 처리량을 키우는 방향으로 전환했다.
- **핵심 직관**: 지친 슈퍼맨 한 명(고클럭 단일 코어)에게 다 시키는 대신, 보통 사람 여럿(멀티코어)에게 일을 나눠 전체 속도를 높이는 것과 같다.

## 핵심 용어 정리 (내부에 등장하는 것들)

먼저 답안에 나오는 용어를 비유와 함께 풀어 둔다. 최상위 키워드는 멀티코어(TLP)다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| TLP (스레드 수준 병렬성) | 여러 스레드를 동시에 실행하는 병렬성 | "여러 사람이 각자 일을 동시에" |
| 코어 (Core) | 자체 ALU·레지스터·L1 캐시를 가진 독립 연산 단위 | "독립 직원 1명" |
| 공유 L3 캐시 (LLC) | 여러 코어가 공유하는 최하위 캐시, DRAM 접근 지연 은닉 | "직원 공용 자료실" |
| 캐시 일관성 (Coherence) | 코어별 캐시가 같은 주소 값을 동일하게 유지하는 규약 | "직원 간 최신 서류 동기화" |
| MESI 프로토콜 | 캐시 라인을 M/E/S/I 4상태로 관리하는 대표 일관성 규약(019 참조) | "서류에 상태 스탬프" |
| 인터커넥트 | 코어·캐시·메모리 컨트롤러를 잇는 칩 내부 고속망 | 링 버스 / 메시(Mesh) |
| 암달의 법칙 | 직렬 코드 비율 때문에 코어를 늘려도 성능 향상에 상한이 있다는 법칙(06 참조) | "도장 찍는 사람은 1명뿐" |
| TDP | 칩이 소모·방출 가능한 최대 열 설계 전력 예산 | "냉각이 감당하는 상한" |

## 깊이 이해
- **배경·문제의식**: 2000년대 초 클럭을 4GHz 이상 올리려 했으나 전력이 클럭의 3제곱에 비례해 발열 한계에 부딪혔다. "클럭을 20% 낮추고 코어를 2배로 늘리면 전력은 비슷하되 처리량은 최대 1.7배 오른다"는 계산이 멀티코어 전환의 근거가 됐다.
- **작동 원리(어떻게+왜)**: 한 칩 안에 L1/L2를 가진 다수 코어가 통합되고, OS는 이를 여러 논리 CPU로 인식해 각 코어에 독립 스레드를 할당한다. 코어들은 공유 L3로 데이터를 교환하며, MESI 등 일관성 규약으로 캐시 간 불일치를 막는다. 이는 외부 버스로 통신하는 다중 프로세서(SMP)와 달리 칩 내부 인터커넥트로 통신해 지연이 훨씬 낮다.
- **비유**: 4차선을 시속 200km로 달리는 대신 8차선을 150km로 달리면, 단위 시간당 더 많은 차를 보내면서 사고(발열) 위험도 낮다.
- **구체 예시**: 웹 서버는 수천 독립 요청을 처리하므로 8코어에서 약 7~8배 향상되지만, 단일 스레드 엑셀 계산은 코어 1개만 일해 향상이 거의 없다.
- **흔한 오해**: "코어 2배면 성능 2배"는 틀렸다. 암달의 법칙상 소프트웨어가 병렬화돼 있지 않으면 코어 증가는 무의미하고, 코어가 늘수록 메모리 대역폭 병목(Memory Wall)이 새 병목이 된다.

## 연결 개념
- **013 ILP**: 단일 코어 명령어 병렬성. 멀티코어는 그 한계를 TLP로 우회함.
- **015 폴락의 법칙**: 단일 코어 확장이 비효율적이라는 수학적 근거.
- **019 캐시 일관성**: 멀티코어 설계의 최대 난제.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 멀티코어는 클럭 중심 발전이 Power Wall에 막히자 다수 독립 코어를 집적해 TLP로 처리량을 배가하는 아키텍처임.
> 2. **가치**: 낮은 클럭으로 작동해 전력(클럭³ 비례)을 낮추면서 다중 워크로드 전체 스루풋을 선형에 가깝게 향상시킴.
> 3. **판단**: 코어 증가 시 캐시 일관성 오버헤드와 Memory Wall이 심화되어, 공유 L3 최적화·칩렛 구조로의 발전이 필수임.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 멀티코어 등장 배경·병렬성 전환 이해 | Power Wall, ILP에서 TLP로의 전환 | 코어 수만 언급, 전력 효율·TLP 누락 |
| 멀티코어 설계의 구조적 제약 파악 | 캐시 일관성, 암달의 법칙, Memory Wall | 다중 프로세서(SMP)와 혼동해 외부 버스로 서술 |

> 요약: 성능 척도가 클럭(Hz)에서 코어 수·병렬성(TLP)으로 이동한 설계 패러다임 변화와, 칩 내부 공유 자원 통제 문제를 함께 짚어야 함.

---

## Ⅰ. 개요 및 필요성

- 개요: 멀티코어 프로세서는 단일 다이 내 2개 이상 독립 코어를 집적해 TLP를 제공하는 아키텍처임.
- 배경: 누설 전류·발열에 의한 클럭 상한(Power Wall)과 단일 코어 복잡도 수확 체감(폴락의 법칙)이 겹침.
- 필요성: TDP 예산을 지키면서 서버·클라우드 다중 워크로드의 총 처리량을 극대화하기 위한 구조 전환 필요함.

---

## Ⅱ. 구조 및 구성요소

```text
CPU 소켓 (단일 Die)
  Core0(L1/L2) / Core1(L1/L2) / Core2(L1/L2) / Core3(L1/L2)
    -> 내부 인터커넥트 (Ring / Mesh)
    -> 공유 L3 캐시 (LLC) -> 일관성 컨트롤러 (MESI / Directory)
    -> 메모리 컨트롤러 -> DRAM (DDR5 / HBM)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 독립 연산 코어 | 개별 파이프라인·ALU·L1/L2 보유, 독립 스레드 실행 | 코어별 OoO 등 ILP는 013 위임 |
| 공유 L3 캐시(LLC) | 코어 간 데이터 공유·메인 메모리 지연 은닉 | 대용량 Last Level Cache |
| 일관성 컨트롤러 | 코어 캐시 간 불일치(Stale Data) 방지 | MESI(소규모)·디렉터리(대규모) |
| 내부 인터커넥트 | 코어·캐시·메모리 컨트롤러 고속 연결 | 링 버스 또는 Mesh 토폴로지 |

> 요약: 멀티코어는 코어의 단순 집합이 아니라, 칩 내부 고속 인터커넥트와 공유 L3로 병목을 조율하는 유기적 시스템임.

---

## Ⅲ. 동작원리 및 흐름도

```text
OS 스레드 스케줄링 -> 코어별 분배 -> 병렬 연산·L1/L2 적재 -> L3 공유·일관성 유지
```

- 1단계 [스레드 분배]: OS의 SMP 스케줄러가 활성 스레드를 각 코어에 로드 밸런싱함.
- 2단계 [독립 병렬 실행]: 각 코어가 자신의 L1 캐시에서 명령어를 인출해 독립적으로 연산함.
- 3단계 [일관성 유지]: 한 코어가 공유 주소를 쓰면(Write) 인터커넥트가 타 코어의 해당 캐시 라인을 무효화함.
- 4단계 [공유 자원 동기화]: L3 미스 시 메모리 컨트롤러가 DRAM에 접근해 데이터를 반환함.

> 요약: OS 입장에선 논리적 다중 CPU로 보이고, 하드웨어는 보이지 않게 캐시 일관성과 메모리 접근을 중재함.

---

## Ⅳ. 특징
- 전력 효율 우위: 클럭을 낮춘 다수 코어가 고클럭 단일 코어보다 Perf/Watt에서 유리함.
- 암달의 법칙 종속: 프로그램의 직렬 코드 비율에 따라 코어를 늘려도 성능 향상이 조기 포화됨.
- 메모리 대역폭 병목: 다수 코어 동시 접근 시 Memory Wall이 심화되어 DDR5·HBM 등 고대역폭 메모리 결합이 필요함.

> 요약: 멀티코어는 만능이 아니며, 소프트웨어 병렬화 수준과 메모리 병목 해결이 전체 성능을 좌우함.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 단일 코어 (고클럭) | 멀티코어 (저클럭 다수) |
|:---|:---|:---|
| 성능 타겟 | 단일 스레드 응답 시간(Latency) 최소화 | 다중 스레드 처리량(Throughput) 극대화 |
| 발열·전력 | 클럭 3제곱 비례로 매우 높음 | 클럭 저하로 전압·발열 통제 용이 |
| S/W 의존도 | 기존 순차 코드 수정 불필요 | 스레드 분리·동기화(Lock) 재설계 필요 |
| 확장 한계 | Power Wall·폴락 수확 체감 | 암달 법칙·Memory Wall |

> 요약: 렌더링·DB·웹 서버는 멀티코어가 압도적이나, 실시간 응답이 중요한 구형 단일 스레드 앱은 고클럭 단일 코어가 여전히 유리함.

**리스크·대응 (기본은 불릿):**
- Noisy Neighbor(L3 공유 간섭) — 한 스레드가 공유 L3를 독점해 타 코어 성능 저하 — Intel CAT 등 캐시 파티셔닝·QoS로 격리(지표: 대상 스레드 캐시 미스율 10% 이하)
- 일관성 트래픽 폭증 — 코어 증가로 스누핑 버스 대역폭 포화 — 16코어 이상은 디렉터리 기반 일관성·Mesh 적용(지표: 코어 간 통신 지연)

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. Big.LITTLE 이기종 설계: 모바일 AP에서 고성능 P-코어(OoO)와 저전력 E-코어(In-Order)를 혼합해 배터리 효율을 극대화함.
2. 서버 가상화 밀도 집적: AMD EPYC 등 64~128코어로 단일 소켓 내 VM·컨테이너를 다수 수용해 클라우드 TCO를 절감함.
3. 코어 피닝(Affinity): DPDK 패킷 처리·금융 트랜잭션에서 특정 코어에 프로세스를 고정해 L1/L2 적중률을 높임.

**결론 (2줄):**
- 기술사 판단: 병렬화 가능한 다중 워크로드면 코어 수 확장이 정답이나, 병렬화가 어려운 직렬 워크로드는 암달 법칙상 소수 고성능 코어가 유리함.
- 향후 방향: 단일 다이 코어 수 한계(수율·면적)를 넘기 위해 여러 작은 코어 다이를 UCIe로 잇는 칩렛 기반 멀티코어로 진화 중임.
