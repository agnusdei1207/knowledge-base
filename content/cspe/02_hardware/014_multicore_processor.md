## 미리 알고가기

- TLP(Thread-Level Parallelism): 여러 스레드를 서로 다른 코어에 동시에 배치해 실행하는 병렬성임
- 동종 멀티코어와 이종 멀티코어로 나뉨
- 코어 수 증가만으로 성능이 선형 상승하지는 않음
- 인터커넥트: 코어·캐시·메모리 컨트롤러 사이에서 요청과 데이터를 전달하는 연결 통로임

## 작성 근거(검토용)

- 멀티코어 판단 기준을 코어 수가 아니라 TLP·공유 캐시·메모리 대역폭·동기화 비용으로 설정함
- 동종·이종 멀티코어를 코어 구성·스케줄링·주요 제약으로 비교함
- 병렬화 가능 구간과 공유 캐시·메모리 경합을 코어 수 결정 기준으로 정리함
- 멀티코어는 코어 배치라는 정적 구조가 핵심이고 상태가 단계별로 전이하는 절차가 없어 별도 Ⅴ절 없이 Ⅳ 구조로 설명함

## Ⅰ. 개요

- **정의/개념**: 멀티코어 프로세서는 하나의 반도체 칩 안에 둘 이상의 독립 코어를 배치해 스레드 수준 병렬성을 활용하는 CPU 구조임
- **배경/필요성**: 전력·발열 장벽을 넘지 않고 처리량을 높이기 위해 여러 코어에 병렬 스레드를 배치하는 구조가 필요함

### 쉽게 이해하기 (학습용)
- 사무실 하나에 일꾼 한 명 대신 여러 명을 넣어, 한 명의 속도를 무리하게 올리지 않고도 전체 처리량을 늘리는 것과 같음

## Ⅱ. 특징

- 병렬 스레드가 충분하면 전체 처리량을 높일 수 있음
- 동종 코어는 같은 성능 모델로 스레드를 배치하고 이종 코어는 성능·전력 요구에 따라 코어 유형을 선택함
- 코어가 공유 캐시와 메모리 대역폭을 경쟁하면 코어 추가에 따른 처리량 증가가 줄어듦
- 소프트웨어 병렬화가 부족하면 코어 추가 효과가 제한됨

### 쉽게 이해하기 (학습용)
- 일꾼 수를 늘려도 나눠줄 일감이 부족하거나 다 같이 쓰는 공용 복사기(공유 캐시·메모리 대역폭)에 줄이 길어지면, 사람을 더 넣은 만큼 일이 빨라지지 않음

## Ⅲ. 종류 및 비교

| 판단 기준 | 동종 멀티코어 | 이종 멀티코어 |
|:---|:---|:---|
| 코어 구성 | 동일 성능·구조 | 성능·전력 특성이 다름 |
| 스케줄링 | 코어별 처리 능력을 동일하게 간주해 배치함 | 코어 유형별 성능·전력을 반영해 배치하며 이동 시 처리량·전력이 달라짐 |
| 주요 제약 | 공유 캐시·메모리 대역폭 경쟁 | 작업 분류 오류와 코어 유형 간 이동 비용 |

> 요약: 동종 코어는 같은 처리 능력을 전제로 배치하고, 이종 코어는 작업의 성능·전력 요구에 따라 코어 유형을 선택함.

### 쉽게 이해하기 (학습용)
- 실력이 똑같은 일꾼들로만 팀을 짜면 동종형이고, 빠른 일꾼과 절전형 일꾼을 섞어 업무 성격에 맞게 배정하면 이종형임

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 복수 코어 | 각 코어가 독립된 명령어 흐름을 실행해 여러 스레드를 병렬 처리함 |
| 공유 캐시 | 코어 간 데이터를 공유하며 캐시 용량과 대역폭 경합을 발생시킬 수 있음 |
| 인터커넥트 | 코어·캐시·메모리 컨트롤러를 연결하며 요청 전달 대역폭을 제공함 |
| 메모리 컨트롤러 | 외부 메모리 요청을 중재하고 코어가 사용할 메모리 대역폭을 제공함 |

```text
+--------+   +--------+   +--------+
| Core 1 |   | Core 2 |   | Core N |
+--------+   +--------+   +--------+
     \           |           /
      \          |          /
       +-------------------+
       | 공유 캐시          |
       +-------------------+
                |
                v
       +-------------------+
       | 인터커넥트/메모리 제어기 |
       +-------------------+
```

> 요약: 멀티코어 성능은 코어 수뿐 아니라 공유 캐시, 인터커넥트, 메모리 대역폭에 좌우됨.

### 쉽게 이해하기 (학습용)
- 각자 자리에서 일하는 일꾼들(복수 코어), 다 같이 쓰는 공용 서류함(공유 캐시), 서류함과 창고를 잇는 복도(인터커넥트)와 반출입 담당자(메모리 컨트롤러)가 함께 있어야 팀이 돌아감

## Ⅵ. 실무 사례

1. 멀티스레드 응용은 순차 실행 비중이 큰 구간을 병렬화하고, 병렬화 비율과 가속 효율로 검증함
2. 서버 CPU는 코어 간 공유 캐시 경합을 줄이기 위해 캐시 파티셔닝을 적용하고, 최종 캐시 경합률과 메모리 대역폭 이용률로 검증함

### 쉽게 이해하기 (학습용)
- 여러 사람이 나눠 할 수 있는 일감은 실제로 나눠 맡기고, 그래도 복사기 앞에 줄이 길면 사용 구역을 나눠 정리하는 것과 같음

## Ⅶ. 결론

- 멀티코어는 전력·발열 장벽을 넘지 않으면서 여러 코어에 병렬 스레드를 배치해 처리량을 높이는 구조임
- 병렬화 가능 구간과 공유 캐시·메모리 대역폭 경합을 측정해 코어 수와 동종·이종 배치 정책을 정해야 함

### 쉽게 이해하기 (학습용)
- 사람만 늘린다고 일이 항상 빨리 끝나지 않으므로, 실제로 나눌 수 있는 일감과 공용 자원 정체를 먼저 재본 뒤 인원과 배치를 정하는 것과 같음
