## Ⅰ. 개요
- 특정 영역(Domain)의 문제 해결을 위해 최적화된 컴퓨터 아키텍처
- 무어의 법칙 한계 및 데나드 스케일링 종료에 따른 대안 기술

| 구분 | 내용 |
| --- | --- |
| 정의 | 특정 작업(AI, 보안, 네트워크 등)에 특화된 하드웨어 설계 |
| 배경 | 범용 프로세서의 효율 정체 및 전용 가속기 수요 증가 |
| 출제의도 | 아키텍처 패러다임 변화 및 PPA 최적화 전략 이해 |

## Ⅱ. 구성요소
```
+------------------------------------------+
|  [ Domain-Specific Architecture ]        |
| +------------+ +------------+ +--------+ |
| | Custom ISA | | Specialized| | Local  | |
| | (VLIW 등)  | | Datapath   | | Memory | |
| +------------+ +------------+ +--------+ |
| [ Domain-Specific Language (DSL) ]       |
+------------------------------------------+
```
| 구성요소 | 설명 | 비유 |
| --- | --- | --- |
| Custom ISA | 도메인 전용 명령어 집합 체계 | 특수 목적 언어 |
| Datapath | 특정 연산 흐름에 최적화된 데이터 통로 | 전용 고속도로 |
| Compiler | DSL을 하드웨어 명령어로 변환하는 가교 | 전문 번역가 |
> 요약: 명령어와 데이터 경로를 특정 용도에만 맞춰 극도로 단순화함.

## Ⅲ. 절차
```
[워크로드 분석] -> [핵심 연산 추출] -> [하드웨어 가속 설계] -> [SW 스택 구축]
```
1. 워크로드 분석: 대상 도메인의 데이터 처리 특성 및 병목 지점 파악함.
2. 핵심 연산 추출: 반복적으로 발생하는 핵심 알고리즘(커널) 식별함.
3. 하드웨어 설계: 해당 연산을 물리적으로 처리할 가속기 구조 설계함.
4. SW 스택 구축: 개발자가 쉽게 사용할 수 있는 라이브러리 및 툴체인 제공함.
> 요약: 도메인 특성 분석을 기반으로 맞춤형 하드웨어를 구현함.

## Ⅳ. 문제점
- 유지보수 어려움: 도메인 알고리즘 변경 시 하드웨어 호용성 급감함.
- 생태계 파편화: 각 도메인별로 다른 아키텍처 사용으로 개발 비용 증가함.

## Ⅴ. 개선방안
- 유연한 가속기: 일부 회로를 프로그래밍 가능하게 설계하여 범용성 확보함.
- 표준 중간 표현(IR): MLIR 등을 통해 다양한 하드웨어 백엔드 통합함.

## Ⅵ. 전망
- AI, 자율주행, 게놈 분석 등 고부가가치 도메인 중심의 채택 가속화됨.
- 하드웨어와 소프트웨어의 공동 설계(Co-design) 역량이 CSF로 부각됨.
