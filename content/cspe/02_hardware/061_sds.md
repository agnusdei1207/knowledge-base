## Ⅰ. 개요
- 스토리지 하드웨어와 제어 소프트웨어를 분리하여 가상화하는 기술
- 하드웨어 종속성 탈피 및 유연한 자원 관리를 위한 데이터센터 혁신

| 구분 | 내용 |
| --- | --- |
| 정의 | 소프트웨어로 스토리지 자원을 추상화하고 정책 기반 관리 수행 |
| 배경 | 데이터 가용성 요구 증대 및 벤더 종속(Lock-in) 탈피 필요 |
| 출제의도 | 제어부/데이터부 분리 구조 및 스케일 아웃 확장성 이해 |

## Ⅱ. 구성요소
```
+------------------------------------------+
|  [ SDS Controller (Software) ]           |
|  - Provisioning / Snapshot / Replication |
+------------------------------------------+
|  [ Virtual Storage Pool ]                |
+------------------------------------------+
| +--------+  +--------+  +--------------+ |
| | x86    |  | Cloud  |  | Legacy       | |
| | Server |  | Storage|  | Array        | |
| +--------+  +--------+  +--------------+ |
+------------------------------------------+
```
| 구성요소 | 설명 | 비유 |
| --- | --- | --- |
| Control Plane | 관리 및 정책 설정을 담당하는 논리 계층 | 관제탑 |
| Data Plane | 실제 데이터 읽기/쓰기가 일어나는 계층 | 활주로 |
| Abstraction | 이종 HW를 단일 풀(Pool)로 만드는 추상화 | 가상화 마법 |
> 요약: 물리 스토리지를 하나의 거대한 가상 풀로 통합 관리함.

## Ⅲ. 절차
```
[HW 풀링] -> [정책 정의] -> [가상 볼륨 할당] -> [동적 확장]
```
1. 풀링: 서로 다른 벤더의 서버/디스크 자원을 SDS 노드로 연결함.
2. 정의: 성능(IOPS), 가용성(복제본 수), 보존 정책 등을 설정함.
3. 할당: 애플리케이션 요구에 맞춰 가상 스토리지를 즉시 프로비저닝함.
4. 확장: 용량 부족 시 새로운 노드를 추가하여 무중단 스케일 아웃함.
> 요약: 정책에 따라 자원을 유연하게 배분하고 자동 관리함.

## Ⅳ. 문제점
- 성능 오버헤드: 소프트웨어 계층의 연산으로 인해 물리 장비 대비 지연 발생함.
- 호환성 이슈: 특정 SDS 소프트웨어와 하드웨어 간 드라이버 충돌 우려됨.

## Ⅴ. 개선방안
- 고속 네트워크: RDMA(Remote Direct Memory Access)로 지연 최소화함.
- 검증된 노드: 하드웨어 인증(Certified Node) 모델 사용 권장함.

## Ⅵ. 전망
- 하이퍼컨버지드 인프라(HCI)의 핵심 요소로 성장이 가속화될 것임.
- AI 기반 자동 계층화(Auto Tiering) 기술이 관리 효율의 핵심임.
