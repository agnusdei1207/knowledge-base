## 미리 알고가기

- CAN: 컨트롤러 영역 네트워크(Controller Area Network, CAN)는 자동차와 산업 제어에서 쓰이는 다중 마스터 직렬 버스임
- ECU: 전자 제어 장치(Electronic Control Unit, ECU)는 차량의 센서·액추에이터·제어 기능을 담당하는 임베디드 제어 장치임
- Arbitration ID: 중재 식별자(Arbitration Identifier, Arbitration ID)는 프레임 우선순위와 메시지 의미를 나타내는 식별자임
- 차동 신호: 두 선의 전압 차이로 신호를 표현해 노이즈 내성을 높이는 방식임
- CAN FD: CAN 가변 데이터 전송률(CAN Flexible Data-rate, CAN FD)은 데이터 필드와 전송률을 확장한 방식임
- Error Confinement: 오류 제한(Error Confinement)은 오류가 많은 노드를 버스에서 단계적으로 제한하는 CAN 오류 관리 기능임

## Ⅰ. 개요

- **정의**: CAN 버스는 여러 제어 노드가 차동 2선 공유 버스에서 메시지 ID 기반 우선순위 중재와 오류 검출로 실시간 제어 데이터를 교환하고 노이즈 내성·버스 부하·메시지 지연 기준으로 분산 제어 장치를 연결하는 통신 방식임
- **배경/필요성**: 자동차와 산업 설비는 ECU, 센서, 액추에이터가 많아 각 장치를 개별 배선으로 연결하면 비용과 복잡도가 커짐. 공통 버스와 우선순위 기반 메시지 통신이 필요해 CAN이 널리 사용됨
- **비유**: 여러 부서가 하나의 무전 채널을 쓰되 더 긴급한 호출 ID가 먼저 말하고, 충돌이 나도 규칙에 따라 다시 말하는 통신망과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| CAN 통신 원리 설명 | 다중 마스터, ID 중재, 차동 신호, 오류 검출 | 단순 범용 비동기 송수신기 통신으로 설명 |
| 차량 네트워크 적용 판단 | 실시간성, 버스 부하, CAN FD, 보안 한계 | 노드 주소 기반 통신으로 오해 |

> 요약: CAN은 노드 주소보다 메시지 ID와 우선순위를 중심으로 동작하는 강건한 제어용 공유 버스임.

## Ⅱ. 특징/비교

| 판단 기준 | CAN | Ethernet | 범용 비동기 송수신기(Universal Asynchronous Receiver/Transmitter, UART) |
|:---|:---|:---|:---|
| 통신 구조 | 공유 버스, 다중 마스터, 메시지 ID 기반 | 스위치 기반 고속 패킷 네트워크 | 점대점 또는 단순 직렬 연결 |
| 실시간 중재 | 낮은 ID가 우선권을 갖는 비파괴 중재 | 서비스 품질(Quality of Service, QoS) 설계가 필요하며 기본은 경쟁·스위칭 기반 | 중재 기능이 없음 |
| 신뢰성 | 순환 중복 검사(Cyclic Redundancy Check, CRC), 수신 확인(Acknowledgement, ACK), 오류 프레임, error confinement 제공 | 상위 프로토콜과 스위치 품질에 의존 | 단순 오류 검출 수준 |
| 적합 영역 | 자동차 ECU, 산업 제어, 센서 네트워크 | 대용량 데이터, 백본, 카메라 | 디버그, 저속 주변장치 연결 |

> 요약: CAN은 대용량 전송보다 노이즈 환경에서 제어 메시지를 우선순위대로 안정적으로 전달하는 데 강점이 있음.

- **우선순위 기준**: ID 값이 낮은 메시지가 중재에서 이기므로 안전·제어 메시지 ID 설계가 중요함
- **부하 기준**: 버스 사용률이 높으면 낮은 우선순위 메시지 지연이 커져 실시간성이 악화됨
- **보안 기준**: 기본 CAN은 인증과 암호화를 제공하지 않으므로 차량 보안 게이트웨이와 침입 탐지가 필요함

## Ⅲ. 구성요소

```text
+----------+      +----------+      +----------+
| ECU Node | ---> | CAN      | ---> | ECU Node |
| Sensor   |      | Bus      |      | Actuator |
+----+-----+      +----+-----+      +----+-----+
     |                 |                 |
     v                 v                 v
+----------+      +----------+      +----------+
| CAN Ctrl |      | Twisted  |      | CAN Ctrl |
| Transcvr |      | Pair     |      | Transcvr |
+----------+      +----------+      +----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| CAN 노드 | ECU, 센서, 액추에이터처럼 메시지를 송수신하는 장치임 | 통신 참여자 |
| CAN 컨트롤러 | 프레임 생성, 중재, CRC, 오류 처리를 담당하는 논리 장치임 | 통신 규칙 담당 |
| 트랜시버 | 컨트롤러 신호를 차동 버스 전기 신호로 변환함 | 무전기 송수신기 |
| 버스 배선 | 종단 저항이 있는 차동 2선 매체로 여러 노드가 공유함 | 공동 도로 |
| 프레임·ID | 데이터, 식별자, CRC, ACK, 오류 정보를 담는 통신 단위임 | 우선순위가 붙은 봉투 |

> 요약: CAN은 노드, 컨트롤러, 트랜시버, 차동 버스, 메시지 프레임이 결합해 분산 제어 통신을 수행함.

## Ⅳ. 절차

```text
+----------+      +----------+      +----------+      +----------+
| Prepare  | ---> | Arbitrate| ---> | Transmit | ---> | Check    |
| Frame    |      | ID       |      | Data     |      | Error    |
+----------+      +----------+      +----------+      +----------+
```

1. **프레임 준비**: 노드가 메시지 ID, 데이터 길이 코드(Data Length Code, DLC), 데이터, CRC 정보를 포함한 CAN 프레임을 구성함
2. **버스 중재**: 여러 노드가 동시에 송신하면 ID 비트 중재로 우선순위가 높은 메시지가 버스를 점유함
3. **데이터 전송**: 차동 신호로 프레임을 전송하고 수신 노드는 ID 필터로 필요한 메시지를 처리함
4. **오류 검출·복구**: CRC, ACK, bit monitoring으로 오류를 감지하고 오류 카운터로 노드 상태를 관리함

> 요약: CAN 통신은 프레임 구성, ID 기반 중재, 데이터 전송, 오류 검출·복구 순서로 동작함.

## Ⅴ. 문제점 및 개선방안

- **P1 버스 부하에 따른 지연**: 메시지가 많아지면 낮은 우선순위 프레임의 대기 시간이 커지고 데드라인을 놓칠 수 있음
- **P1 대응**: 메시지 주기와 ID 우선순위를 재배치하고 버스 사용률 상한을 관리함 (확인: 최악 메시지 지연)
- **P2 기본 보안 부재**: CAN 프레임은 인증·암호화가 없어 공격자가 버스에 접근하면 위조 메시지를 주입할 수 있음
- **P2 대응**: 보안 게이트웨이, 메시지 화이트리스트, 이상 탐지, 메시지 인증 코드(Message Authentication Code, MAC) 적용을 검토함 (확인: 위조 프레임 탐지율)
- **P3 물리 배선·노이즈 문제**: 종단 저항 오류, 배선 길이, 접지 문제, 전자파 간섭이 통신 오류를 증가시킴
- **P3 대응**: 종단 저항, 차폐, 접지, 배선 길이, 트랜시버 상태를 검증함 (확인: 오류 프레임 수, bus-off 발생)

> 요약: CAN 개선은 버스 부하 제어, 보안 게이트웨이, 물리 계층 품질 관리가 함께 이루어져야 함.

## Ⅵ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 차량 바디 제어망 | 도어, 조명, 공조 ECU를 CAN으로 연결하고 안전 관련 메시지 ID에 높은 우선순위를 부여함 | 버스 사용률, 최악 메시지 지연, 오류 프레임 수 |
| 산업 장비 센서망 | 차동 2선 버스와 종단 저항을 적용해 노이즈 환경에서 센서·액추에이터를 연결함 | bus-off 발생, CRC 오류 수, 배선 진단 결과 |
| 차량 보안 게이트웨이 | 외부 진단 포트와 내부 CAN 세그먼트 사이에서 메시지 필터링과 이상 탐지를 수행함 | 위조 프레임 탐지율, 차단 로그, 게이트웨이 지연 |

> 요약: CAN 적용은 공유 버스 지연, 물리 계층 품질, 보안 게이트웨이 효과를 함께 확인해야 함.

## Ⅶ. 전망

- **발전 방향**: CAN은 차량 Ethernet과 구역형 아키텍처가 확산되어도 저비용 제어 말단망으로 남고 CAN FD/CAN eXtra Large(CAN XL)로 payload와 속도 한계를 보완함
- **기술사적 판단**: 버스 부하, arbitration ID 우선순위, 케이블 길이, 종단 저항, 오류 제한, 게이트웨이 지연을 기준으로 네트워크 세그먼트를 설계함; 버스 사용률, 오류 프레임 수, 중재 지연, 최악 메시지 지연, 오류 제한 동작을 실제 배선 조건에서 측정함
- **기술사 제언**: CAN은 저속 버스가 아니라 ID 중재, 오류 관리, 보안 한계를 가진 제어망으로 설명하고 Ethernet과 역할 분담을 제시함
