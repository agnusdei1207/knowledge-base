## 미리 알고가기

- CAN은 자동차와 산업 제어에서 널리 쓰는 다중 마스터 직렬 버스임
- 메시지 ID 기반 비파괴 중재와 오류 격리가 핵심 메커니즘임
- 노드 주소보다 메시지 우선순위가 더 중요한 통신 방식임
- CAN 컨트롤러는 프레임·중재·CRC·오류 처리를 담당하고 트랜시버는 논리 신호를 차동 신호로 변환함

## 작성 근거(검토용)

- CAN은 메시지 ID 중재, 차동 신호, CRC·ACK, 오류 카운터를 핵심 축으로 설명함
- 비교표는 CAN·CAN FD·Automotive Ethernet의 전송 방식, 대표 용도, 유의점을 대비함
- 실무 판단은 버스 사용률·최악 메시지 지연과 비인가 프레임 탐지율·차단 건수로 검증함

## Ⅰ. 개요

- **정의/개념**: CAN 버스는 여러 제어 노드가 차동 2선 공유 버스에서 메시지 ID 우선순위와 오류 검출 규칙에 따라 데이터를 교환하는 실시간 분산 제어 통신 방식임
- **배경/필요성**: 여러 ECU·센서·액추에이터를 적은 배선으로 연결하기 위해 우선순위 중재와 오류 격리를 제공하는 제어 버스가 필요함

### 쉽게 이해하기 (학습용)
- 여러 사람이 같은 무전기 채널을 쓰되, 번호표(메시지 ID)가 낮을수록 먼저 말할 권리를 갖는 회의실과 같음
- 배선을 줄이면서도 여러 장치를 연결하려면 이런 순서 규칙과 오류 감지가 필요함

## Ⅱ. 특징

- 낮은 ID가 우선권을 갖는 비파괴 중재로 제어 메시지 지연을 줄임
- 차동 신호로 공통 모드 잡음을 억제하고 CRC·error confinement로 전송 오류를 검출·격리함
- 짧고 중요한 제어 메시지를 주고받는 데 적합함
- 기본 CAN 프레임에는 송신자 인증과 암호화 필드가 없어 외부 연결 구간에 별도 보안 통제가 필요함

### 쉽게 이해하기 (학습용)
- 먼저 말하고 싶은 사람이 번호표를 들면 자동으로 순서가 정해지는 회의실과 같아 급한 안건이 먼저 전달됨
- 다만 이 회의실은 발언자가 누구인지 확인하는 절차가 없어, 외부와 연결되는 문에는 별도 경비가 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | CAN | CAN FD | Automotive Ethernet |
|:---|:---|:---|:---|
| 전송 방식 | 최대 8바이트 페이로드를 메시지 ID 기반 비파괴 중재로 전송함 | 같은 ID 중재 후 데이터 구간 비트율을 높여 최대 64바이트 페이로드를 전송함 | 프레임 기반 대용량 데이터를 스위치 큐·QoS 정책으로 전송함 |
| 대표 용도 | ECU·바디 제어에 적용함 | 진단 데이터·확장 제어에 적용함 | ADAS 센서·중앙 컴퓨팅 백본에 적용함 |
| 유의점 | 버스 부하와 프레임 인증을 관리함 | 기존 CAN 노드 호환성과 비트 타이밍을 검증함 | 스위치 QoS와 종단 보안을 설계함 |

> 요약: CAN은 ID 중재로 짧은 제어 메시지, CAN FD는 확장 페이로드, Automotive Ethernet은 QoS 기반 대용량 백본 통신에 맞음.

### 쉽게 이해하기 (학습용)
- CAN은 짧은 쪽지만 주고받는 회의실, CAN FD는 조금 더 긴 쪽지도 허용하는 회의실, Automotive Ethernet은 아예 택배 상자를 주고받는 물류 창고와 같음

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| ECU 노드 | 센서와 액추에이터를 포함한 통신 참여자로 메시지를 보내고 받음 |
| CAN 컨트롤러 | 프레임 생성·중재·CRC·오류 처리를 담당함 |
| 트랜시버 | CAN 논리 신호를 차동 전기 신호로 변환함 |
| 버스 선로·종단 저항 | 공유 매체의 반사를 억제하고 차동 신호 품질을 유지함 |

> 요약: CAN 컨트롤러가 프레임·오류를 처리하고 트랜시버와 종단 저항이 차동 신호 경로를 구성함.

### 쉽게 이해하기 (학습용)
- 회의 참석자(ECU 노드), 발언 순서와 오류를 관리하는 사회자(CAN 컨트롤러), 목소리를 신호로 바꾸는 변환기(트랜시버), 소리가 울리지 않게 잡아주는 방음벽(종단 저항)이 있음

## Ⅴ. 원리 및 절차 흐름도

1. **프레임 준비**: 메시지 ID와 데이터와 CRC를 구성함
2. **ID 중재**: 여러 노드가 동시에 송신하면 우선순위가 높은 ID가 버스를 점유함
3. **데이터 전송**: 수신 노드는 필요한 메시지만 필터링해 처리함
4. **오류 검출·격리**: CRC와 ACK와 오류 카운터로 이상 노드를 제한함

> 요약: CAN은 ID 중재로 송신 우선순위를 정하고 CRC·ACK·오류 카운터로 이상 노드를 격리함.

### 쉽게 이해하기 (학습용)
- 할 말을 쪽지에 적고, 여러 명이 동시에 말하면 번호표가 낮은 사람이 이기고, 필요한 사람만 알아듣고, 이상한 발언을 하는 사람은 회의에서 제외함

## Ⅵ. 실무 사례

1. 차체 제어 CAN은 메시지 ID 우선순위와 버스 부하를 조정하고 버스 사용률·최악 메시지 지연을 확인함
2. OTA 게이트웨이는 프레임 필터링과 IDS를 적용하고 비인가 프레임 탐지율·차단 건수를 확인함

### 쉽게 이해하기 (학습용)
- 차체 제어 CAN은 안건별 발언 순서를 조정하는 사회자와 같고, OTA 게이트웨이는 수상한 발언을 걸러내는 문지기 역할을 함

## Ⅶ. 결론

- CAN은 메시지 ID 기반 비파괴 중재로 적은 배선에서도 우선순위가 높은 제어 메시지를 먼저 전달하지만, 프레임 자체에는 송신자 인증이 없어 신뢰는 버스 참여자 범위 안에서만 성립함
- 차체 제어처럼 폐쇄된 버스는 메시지 ID별 최악 지연 시간과 버스 사용률을 산정해 여유를 관리하고, OTA 게이트웨이 같은 외부 연결 구간은 프레임 필터링·IDS로 별도 인증을 보강해야 함

### 쉽게 이해하기 (학습용)
- 번호표로 순서를 정하는 편리함 뒤에는 발언자를 확인하지 못하는 약점이 있어 외부 연결 구간은 별도로 지켜야 함
