## 미리 알고가기

- CAN은 자동차와 산업 제어에서 널리 쓰는 다중 마스터 직렬 버스임
- 메시지 ID 기반 비파괴 중재와 오류 격리가 핵심 메커니즘임
- 노드 주소보다 메시지 우선순위가 더 중요한 통신 방식임

## Ⅰ. 개요

- **정의/개념**: CAN 버스는 여러 제어 노드가 차동 2선 공유 버스에서 메시지 ID 우선순위와 오류 검출 규칙에 따라 데이터를 교환하는 실시간 분산 제어 통신 방식임
- **배경/필요성**: 차량과 산업 설비는 많은 ECU와 센서와 액추에이터를 적은 배선으로 안정적으로 연결해야 하므로, 노이즈와 충돌에 강한 제어용 네트워크가 필요함

## Ⅱ. 특징

- 낮은 ID가 우선권을 갖는 비파괴 중재로 실시간성이 좋음
- 차동 신호와 CRC와 error confinement로 노이즈 환경에 강함
- 짧고 중요한 제어 메시지를 주고받는 데 적합함
- 기본적으로 인증과 암호화가 약해 외부 연결 환경에서는 보강이 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | CAN | CAN FD | Automotive Ethernet |
|:---|:---|:---|:---|
| 데이터 전송 특성 | 짧은 제어 메시지를 안정적으로 주고받는 데 적합함 | 더 큰 payload를 실어 진단과 확장 제어에 유리함 | 대용량 데이터와 백본 통신에 적합함 |
| 중재 방식 | 메시지 ID 기반 우선순위 중재를 사용함 | 같은 방식의 ID 중재를 유지하면서 효율을 높임 | 스위치 기반 전달이라 별도 QoS 설계가 필요함 |
| 대표 용도 | 전통 ECU 제어와 바디 네트워크에 널리 씀 | 진단 데이터와 확장 제어 네트워크에 많이 씀 | ADAS 센서와 중앙 컴퓨팅 백본에 많이 씀 |
| 유의점 | 버스 부하와 보안 한계를 함께 관리해야 함 | 호환성과 타이밍 분석을 다시 점검해야 함 | 대역폭은 크지만 구조와 비용이 더 복잡해짐 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| ECU·노드 | 센서와 액추에이터를 포함한 통신 참여자로 메시지를 보내고 받음 |
| CAN Controller | 프레임 생성과 중재와 CRC와 오류 처리를 담당하는 핵심 논리 계층임 |
| Transceiver | CAN 신호를 차동 전기 신호로 바꿔 물리 계층을 형성함 |
| Bus Line·Termination | 공유 매체와 종단 저항이 신호 품질과 노이즈 내성을 좌우함 |

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 프레임 준비    | --> | ID 중재       | --> | 데이터 전송    | --> | 오류 검출·격리 |
+-------------+     +-------------+     +-------------+     +-------------+
```

## Ⅴ. 원리 및 절차 흐름도

1. **프레임 준비**: 메시지 ID와 데이터와 CRC를 구성함
2. **ID 중재**: 여러 노드가 동시에 송신하면 우선순위가 높은 ID가 버스를 점유함
3. **데이터 전송**: 수신 노드는 필요한 메시지만 필터링해 처리함
4. **오류 검출·격리**: CRC와 ACK와 오류 카운터로 이상 노드를 제한함

## Ⅵ. 실무 적용 및 유의점

1. 차체 제어나 산업 설비 제어선은 CAN이 예측 가능한 통신을 제공하지만 버스 사용률이 높아지면 낮은 우선순위 메시지가 반복 지연될 수 있으므로 ID 설계와 부하 분석을 함께 수행하고 버스 사용률과 최악 메시지 지연시간과 오류 프레임 건수로 확인함
2. 외부 진단기나 OTA 게이트웨이와 연결되는 차량 네트워크는 기본 CAN만으로는 악성 프레임 삽입을 막기 어려우므로 게이트웨이 필터링과 IDS 또는 인증 보강을 적용하고 비인가 프레임 탐지율과 차단 건수와 진단 지연시간으로 확인함

## Ⅶ. 결론

CAN의 강점은 빠른 전송 속도보다 예측 가능한 우선순위 중재와 강건한 오류 처리에 있음.
