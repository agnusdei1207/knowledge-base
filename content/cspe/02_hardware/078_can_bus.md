## 미리 알고가기

- CAN은 자동차와 산업 제어에서 널리 쓰이는 다중 마스터 직렬 버스임
- 메시지 ID 기반 비파괴 중재와 오류 격리가 핵심 메커니즘임
- 주소 중심이 아니라 메시지 중심 통신이라는 점이 중요함

## Ⅰ. 개요

- **정의/개념**: CAN 버스는 여러 제어 노드가 차동 2선 공유 버스에서 메시지 ID 우선순위와 오류 검출 규칙에 따라 데이터를 교환하는 실시간 분산 제어 통신 방식임
- **배경/필요성**: 차량과 산업 설비는 많은 ECU와 센서와 액추에이터를 안정적으로 연결해야 하므로, 배선 수를 줄이면서 노이즈와 충돌에 강한 제어용 네트워크가 필요함

## Ⅱ. 특징

- 낮은 ID가 우선권을 가지는 비파괴 중재로 실시간성이 좋음
- 차동 신호와 CRC와 error confinement로 노이즈 환경에 강함
- 대용량 데이터보다는 짧고 중요한 제어 메시지 전달에 적합함
- 기본 보안 기능이 약해 현대 차량 네트워크에는 추가 보호가 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | CAN | CAN FD | Ethernet |
|:---|:---|:---|:---|
| 데이터 크기 | 작음 | 확대됨 | 큼 |
| 우선순위 중재 | ID 기반 | ID 기반 | 별도 QoS 필요 |
| 적합 용도 | 전통 ECU 제어 | 확장 제어, 진단 | 백본, 대용량 데이터 |
| 신뢰성 초점 | 오류 검출, 격리 | 오류 검출 + 확장성 | 스위치 기반 네트워킹 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| CAN Node, ECU | 센서와 액추에이터를 포함한 통신 참여자로 메시지 생성과 소비를 수행함 |
| CAN Controller | 프레임 생성과 중재와 CRC와 오류 처리를 담당하는 핵심 논리 계층임 |
| Transceiver | 차동 전기 신호로 변환해 버스 물리 계층을 형성함 |
| Bus Line, Termination | 공유 매체와 종단 저항이 신호 품질과 노이즈 내성을 좌우함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 프레임 준비    | --> | ID 중재       | --> | 데이터 전송    | --> | 오류 검출/격리 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **프레임 준비**: 메시지 ID와 데이터와 CRC를 구성함
2. **ID 중재**: 동시에 송신 시 우선순위가 높은 ID가 버스를 점유함
3. **데이터 전송**: 수신 노드가 필요한 메시지만 필터링해 처리함
4. **오류 검출 및 격리**: CRC와 ACK와 오류 카운터로 이상 노드를 제한함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 버스 사용률이 높아지면 낮은 우선순위 메시지가 반복적으로 지연돼 실시간성이 악화될 수 있음
   - 해결방안: ID 설계와 버스 부하 관리를 최적화하고 bus utilization과 message latency로 검증함
2. 문제: 기본 CAN은 인증과 암호화가 없어 악성 메시지 삽입과 재생 공격에 취약할 수 있음
   - 해결방안: gateway filtering과 IDS와 secure CAN 계층을 적용하고 unauthorized frame detection rate와 attack block rate로 검증함
3. 문제: 배선 길이와 종단 처리와 노이즈 환경이 맞지 않으면 bit error와 재전송이 급증할 수 있음
   - 해결방안: physical layer guideline을 준수하고 error frame count와 bus stability로 검증함

## Ⅶ. 적용 사례

- 자동차 차체 제어 네트워크에서는 ECU 간 제어 메시지를 교환하고, bus utilization과 message latency로 결과를 확인함
- 산업 장비 제어선에서는 센서와 액추에이터를 CAN으로 연결하고, error frame count와 uptime로 결과를 확인함
- 차량 진단망에서는 CAN FD를 활용해 진단 데이터를 확장 전송하고, payload efficiency와 diagnostic response time로 결과를 확인함

## Ⅷ. 결론

CAN의 강점은 빠른 네트워크가 아니라 예측 가능한 우선순위 중재와 강건한 오류 처리에 있으므로, 메시지 설계와 보안 보강이 품질을 좌우함.
