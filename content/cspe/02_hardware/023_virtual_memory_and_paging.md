## Ⅰ. 개요
- 정의: 물리 메모리보다 큰 프로세스를 실행하기 위해 보조기억장치를 활용하는 기법
- 배경: 한정된 RAM 용량 극복 및 프로세스 간 메모리 보호/격리 필요성
- 출제 의도
| 구분 | 내용 |
| --- | --- |
| 핵심 | 주소 사상(Mapping), 페이지 테이블, 단편화 해결 |

## Ⅱ. 구성요소
```
[ CPU ] -> [ MMU ] -> [ Page Table ] -> [ RAM / Disk ]
  (VA)       (PA)         (Mapping)
```
| 구성요소 | 설명 | 비유 |
| --- | --- | --- |
| 가상 주소(VA) | 프로세스가 참조하는 논리적 주소 | 가상의 번지수 |
| 페이지 테이블 | VA와 PA의 매핑 정보를 저장하는 자료구조 | 주소록 |
| MMU | 가상 주소를 물리 주소로 변환하는 하드웨어 장치 | 주소 변환기 |
> 요약: MMU가 페이지 테이블을 참조하여 논리적 가상 주소를 실제 물리 주소로 변환함

## Ⅲ. 절차
```
CPU 요청 -> MMU 변환 -> 테이블 참조 -> (Hit) RAM 접근 / (Miss) Page Fault
```
1. 가상 주소 발생: CPU가 실행 중인 인스트럭션의 논리 주소 참조
2. 페이지 테이블 조회: MMU가 메모리 내 페이지 테이블에서 유효 비트 확인
3. 주소 사상: 페이지 프레임 번호(PFN)를 찾아 물리 주소 생성
4. 데이터 접근: 생성된 물리 주소를 통해 실제 RAM의 데이터 로드
> 요약: 주소 변환 절차를 통해 투명한 메모리 확장 및 연속된 가상 공간 제공함

## Ⅳ. 문제점
- 매핑 정보 저장을 위한 페이지 테이블 자체가 RAM 공간을 점유하는 오버헤드 발생

## Ⅴ. 개선방안
- 계층적 페이징(Multi-level Paging) 또는 역 페이지 테이블(Inverted Page Table) 활용함

## Ⅵ. 전망
- 클라우드 가상화 가속을 위해 하드웨어 기반의 중첩 페이징(Nested Paging) 최적화가 필수적임
- 대용량 데이터 처리를 위한 Huge Pages 기술의 범용적 적용 및 최적화가 CSF임
