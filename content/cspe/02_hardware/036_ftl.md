## Ⅰ. 개요
- 정의: 낸드 플래시의 물리적 한계를 극복하기 위해 논리 주소를 물리 주소로 변환하는 펌웨어
- 배경: 지우기 전 쓰기 불가, 블록 단위 삭제 등 낸드 특성을 기존 OS에 투명하게 제공
- 출제 의도
| 구분 | 내용 |
| --- | --- |
| 핵심 | 주소 사상(Mapping), 가비지 컬렉션, 웨어 레벨링, 배드 블록 관리 |

## Ⅱ. 구성요소
```
[ File System ] -> [ LBA ] -> [ FTL ] -> [ PBA ] -> [ NAND ]
                               Mapping Table
```
| 구성요소 | 설명 | 비유 |
| --- | --- | --- |
| 매핑 테이블 | 논리 주소(LBA)와 물리 주소(PBA)의 짝을 기록한 표 | 변환 장부 |
| 가비지 컬렉션 | 유효하지 않은 데이터 블록을 정리하여 빈 공간 확보 | 청소부 |
| 웨어 레벨링 | 특정 블록의 마모를 방지하기 위해 쓰기 횟수 균등 분산 | 타이어 위치 교환 |
> 요약: SSD 컨트롤러 내부에서 돌아가는 핵심 운영체제 역할을 수행함

## Ⅲ. 절차
1. 쓰기 요청: 호스트가 논리 주소(LBA) 기반의 쓰기 명령 전송
2. 빈 페이지 탐색: FTL이 비어있는 물리 페이지(Free Page) 검색 및 선택
3. 매핑 업데이트: 실제 기록 후 매핑 테이블에 새로운 PBA 정보 갱신
4. 배경 처리: 유휴 시간에 무효 페이지들을 정리하여 쓰기 가용성 유지
> 요약: 논리적 연속성을 유지하면서 물리적으로는 최적의 위치에 분산 저장함

## Ⅳ. 문제점
- 잦은 주소 변환 및 가비지 컬렉션 수행으로 인한 쓰기 증폭(WAF) 발생함

## Ⅴ. 개선방안
- 호스트-기기 간 협력 모델(Open Channel SSD/ZNS)로 FTL 오버헤드 최소화함

## Ⅵ. 전망
- QLC/PLC 등 고밀도 낸드 제어를 위해 머신러닝 기반의 정교한 FTL 알고리즘 도입 예상
- NVMe 규격 고도화와 함께 FTL의 연산 오프로딩 기능 강화가 차세대 로드맵임
