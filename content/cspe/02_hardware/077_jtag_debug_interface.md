# 📖 【암기용】 개념 완전 이해

> 목적: JTAG을 처음 봐도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: **바운더리 스캔(Boundary Scan)** 기반의 **IEEE 1149.1 표준 인터페이스**다 — 칩 핀에 물리적으로 탐침을 대지 않고도, 칩 내부에 미리 심어둔 스캔 회로를 통해 핀 상태를 소프트웨어적으로 읽고 쓴다.
- **왜 필요한가**: BGA(Ball Grid Array)처럼 핀이 칩 바닥에 숨는 패키징이 보편화되면서, 탐침을 직접 대는 재래식 검사(Bed of Nails)가 물리적으로 불가능해졌다. "탐침 대신 칩 안에 검사 전용 회로를 심어두자"는 발상에서 1990년 IEEE 1149.1로 표준화됐다.
- **핵심 직관**: 칩 둘레의 모든 핀 옆에 작은 스위치(스캔 셀)를 달아 한 줄로 이어놓고, 이 줄에 값을 직렬로 밀어 넣고(Shift-in) 빼내는(Shift-out) 것만으로 칩 내부 상태 전체를 검사·제어한다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 바운더리 스캔 (Boundary Scan) | 칩 둘레(Boundary) 핀들을 스캔 회로로 감싸 검사하는 기법 — JTAG이 표현하려는 **대상** | 건물 외벽 전체에 감지선을 두른 것 |
| IEEE 1149.1 | 바운더리 스캔·TAP을 정의한 국제 표준 규격 | JTAG의 규격 문서 |
| TAP (Test Access Port) | JTAG 신호가 드나드는 표준 포트, 4~5개 핀으로 구성 | 검사 전용 출입구 |
| TCK (Test Clock) | 모든 동작의 박자를 맞추는 클록 신호 | 박자를 세는 시계 |
| TMS (Test Mode Select) | TAP 컨트롤러의 상태를 바꾸는 제어선 | 상태 전환 스위치 |
| TDI (Test Data In) | 칩 내부로 데이터를 직렬 입력하는 핀 | 입구 |
| TDO (Test Data Out) | 칩 내부에서 데이터를 직렬 출력하는 핀 | 출구 |
| TRST (Test Reset) | TAP 로직을 초기화하는 선택적 5번째 핀 | 리셋 버튼 |
| TAP 컨트롤러 | TMS 신호에 따라 16개 상태를 오가는 유한 상태 머신(FSM) | 신호등이 있는 교차로 |
| IR/DR 레지스터 | 명령어(IR)와 데이터(DR, 바운더리 스캔 레지스터 포함)를 담는 레지스터 | 명령서함과 서류함 |
| BSDL | 칩의 스캔 체인 구조를 기술한 언어(자동 검사 장비가 읽음) | 배선 설명서 |

## 깊이 이해

### 스캔 셀과 시프트 레지스터 (수치로 이해)
- 칩의 입출력 핀 하나마다 스캔 셀이 1개(양방향 핀은 2~3개) 붙는다. 예를 들어 핀이 200개인 칩이면 바운더리 스캔 레지스터의 길이는 약 200비트다.
- TDI로 200비트를 순서대로 밀어 넣고 한 클록마다 1비트씩 이동하므로, TCK가 10MHz(주기 100ns)라면 전체 체인을 한 바퀴 도는 데 200 × 100ns = 20µs가 걸린다. 물리 탐침으로 200개 핀을 하나씩 찍는 것보다 훨씬 빠르고 자동화도 가능하다.

### TAP 컨트롤러 16-상태 유한 상태 머신
- TMS 신호(0/1)에 따라 Test-Logic-Reset → Run-Test/Idle → Select-DR-Scan → Capture-DR → Shift-DR → Exit1-DR → Update-DR 등 정확히 16개 상태를 오간다.
- 예: DR(데이터 레지스터)에 값을 쓰려면 Select-DR-Scan → Capture-DR(현재 핀 값을 스캔 셀에 캡처) → Shift-DR(TDI로 새 값을 밀어 넣으며 이전 값을 TDO로 밀어냄) → Update-DR(캡처한 값을 실제 핀에 반영) 순서를 거친다.

### 명령어별 동작 — 무엇을 테스트하는가
- **EXTEST**: 칩 외부 핀에 강제로 값을 출력해 옆 칩이 그 값을 제대로 받는지 확인한다 — 기판 위 배선의 단선(Open)·쇼트(Short) 검사에 쓴다.
- **SAMPLE/PRELOAD**: 칩이 정상 동작하는 도중 핀 상태를 스냅샷처럼 캡처만 한다 — 동작을 방해하지 않는 모니터링.
- **INTEST**: 외부 핀은 무시하고 칩 내부 코어 로직에 직접 테스트 데이터를 주입한다 — 칩 자체의 논리 기능 검사.
- **BYPASS**: 해당 칩을 건너뛰고 TDI를 TDO로 1비트 만에 바로 흘려보낸다 — 데이지 체인에서 특정 칩만 검사하고 나머지는 우회시킬 때 쓴다.

### 비유와 흔한 오해
- **비유**: 건물 벽면을 따라 모든 방(핀)의 창문 상태를 확인할 수 있는 복도(스캔 체인)를 만들어, 관리실(TAP 컨트롤러)에서 창문을 하나하나 열고 닫아보며 이상 유무를 점검하는 것과 같다.
- **오해**: JTAG을 "디버깅 툴"로만 알기 쉽지만, 원래 목적은 제조 후 기판 불량 검사(Boundary Scan Test)다. 디버깅·펌웨어 다운로드는 이 강력한 핀 제어권을 나중에 응용한 것이다(디버깅 관점의 심화는 자매 문서 참고).

## 연결 개념
- TAP (Test Access Port) — JTAG 신호가 드나드는 표준 포트(위에서 다룸)
- ICT (In-Circuit Test) — 바운더리 스캔을 활용한 자동화 양산 검사 공정
- SWD (Serial Wire Debug) — JTAG보다 핀 수를 줄인 ARM 전용 디버그 인터페이스(2핀)
- JTAG 디버깅 인터페이스(077_jtag_debugging_interface.md) — 같은 JTAG을 디버깅·보안 관점에서 다룬 자매 문서

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 4대 핵심 신호(TMS, TCK, TDI, TDO), 바운더리 스캔 원리, 그리고 테스트 및 디버깅 활용을 중심으로 서술한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: JTAG(IEEE 1149.1)은 고밀도 PCB 상의 집적 회로를 테스트하기 위해 칩의 물리적 핀을 소프트웨어적으로 제어하는 바운더리 스캔(Boundary Scan) 기반 표준 인터페이스이다.
> 2. **가치**: 물리적 접촉 없이 복잡한 회로의 단선/쇼트 검사 및 칩 내부 레지스터/메모리 접근을 통한 실시간 하드웨어 디버깅을 가능하게 한다.
> 3. **판단 포인트**: 양산 단계의 품질 보증(QA)과 개발 단계의 디버깅 효율성을 동시에 제공하나, 보안 취약점이 될 수 있으므로 시큐어 JTAG 등 보호 대책이 병행되어야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| JTAG 인터페이스 신호 이해도 | 4대 필수 신호 (TMS, TCK, TDI, TDO) | 신호 명칭 및 역할 누락 |
| 바운더리 스캔 메커니즘 파악 | Scan Cell, Daisy Chain 구조 | 단순 "연결 포트"로만 설명 |
| 활용 범위 및 보안 대응 | Boundary Scan Test, In-circuit Debug, 보안 퓨즈 | 디버깅 용도로만 한정 서술 |

> 요약: 하드웨어 테스트 표준으로서의 본질과 시스템 디버깅/보안 관점의 활용도를 균형 있게 다룬다.

## Ⅰ. 개요 및 필요성

- 정의: 집적 회로(IC) 내부의 테스트 및 디버깅을 위해 IEEE 1149.1 표준으로 정의된 직렬 통신 인터페이스 및 바운더리 스캔 기술
- 배경: SMT 기술 발달로 인한 칩 핀의 고밀도화 및 물리적 테스트 프로브 접근 한계(BGA 패키지 등) 극복 필요
- 필요성: 하드웨어 제조 불량 검사 시간 단축, 칩 내부 가시성(Visibility) 확보를 통한 신속한 오류 수정

---

## Ⅱ. 구조 및 구성요소

### 1. JTAG 핵심 신호 (4+1 PIN)
| 신호 | 명칭 | 역할 |
|:---|:---|:---|
| **TCK** | Test Clock | 통신 동기화를 위한 클록 신호 (Master 제어) |
| **TMS** | Test Mode Select | TAP 컨트롤러의 상태 천이를 결정하는 제어 신호 |
| **TDI** | Test Data In | 칩 내부로 테스트 데이터를 직렬 입력하는 핀 |
| **TDO** | Test Data Out | 칩 내부에서 테스트 데이터를 직렬 출력하는 핀 |
| **TRST** | Test Reset | (선택) JTAG 로직을 초기화하는 리셋 신호 |

### 2. 바운더리 스캔 (Boundary Scan) 구조

```text
[ Controller ] --(TDI)--> [ Chip A (Cell-Cell-Cell) ] --+
                                                        |
               <--(TDO)-- [ Chip B (Cell-Cell-Cell) ] <-+ (Daisy Chain)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Scan Cell | 각 핀과 코어 사이에 위치한 스위치 | 입력/출력/방향 제어 |
| TAP Controller | TMS 신호에 따라 16개 상태로 변화하는 FSM | JTAG 명령 및 데이터 제어 |
| IR/DR Register | 명령어(IR) 및 데이터(DR) 저장 레지스터 | IDCODE, Boundary Scan Data 등 |

---

## Ⅲ. 동작원리 및 활용 방식

```text
Instruction Load (IR) -> Data Load (DR) -> Boundary Scan 실행 -> Result Shift-out
```

| 방식 | 설명 | 주요 용도 |
|:---:|:---|:---|
| Sample/Preload | 실행 중인 핀의 상태를 스냅샷 촬영하듯 읽기 | 동작 중 모니터링 |
| Extest | 칩 외부 핀에 특정 값을 출력하여 연결 상태 확인 | 기판 단선/쇼트 테스트 |
| Intest | 칩 내부 코어 로직에 테스트 데이터를 입력 | 칩 자체 기능 테스트 |
| 디버깅 모드 | CPU의 PC(Program Counter) 제어 및 메모리 접근 | 펌웨어 다운로드, 중단점 설정 |

> 요약: 데이터 비트를 직렬로 밀어 넣고(Shift-in) 결과를 뽑아내는(Shift-out) 과정을 반복하여 전체 기판 상태를 파악한다.

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 표준성 | IEEE 1149.1~7 등 다양한 확장 표준 존재 | 이기종 칩 간 데이지 체인 가능 |
| 비파괴 검사 | 물리적 손상 없이 회로 검증 가능 | 양산 검사 자동화(ICT) 가능 |

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | JTAG (IEEE 1149.1) | SWD (Serial Wire Debug) | 선택 기준 |
|:---|:---|:---|:---|
| 핀 수 | 최소 4핀 (보통 10~20핀 커넥터) | 2핀 (Clock, Data) | 보드 면적 및 핀 여유 |
| 호환성 | 범용 (FPGA, CPU, DSP 등) | ARM Cortex 시리즈 전용 | 타겟 칩 종류 |
| 복잡도 | 데이지 체인으로 여러 칩 제어 | 1:1 디버깅 중심 | 시스템 아키텍처 |

> 요약: 복잡한 보드 테스트에는 JTAG을, 소형 IoT 기기의 ARM 디버깅에는 SWD를 선호한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 펌웨어 탈취 | JTAG 포트를 통한 메모리 덤프 | JTAG 락(Lock), eFuse 절단 | JTAG 접근 권한 차단 여부 |
| 신호 간섭 | TCK 클록의 오버슈트 또는 노이즈 | 종단 저항 배치, 차폐 설계 | 신호 무결성 (Eye Diagram) |
| 연결 오류 | 데이지 체인 중 한 칩의 전원 불량 | 바이패스(Bypass) 모드 확인 | IDCODE 인식 성공률 |

> 요약: 개발 완료 후 양산 시에는 JTAG 포트를 하드웨어/소프트웨어적으로 비활성화하는 '시큐어 JTAG' 설계가 필수다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 인식 속도 | TCK 주파수 10~50MHz 확보 | 통신 대역폭 측정 |
| 테스트 커버리지 | 핀 연결 검사율 95% 이상 | BSDL 파일 기반 고장 진단 |
| 보안 강도 | 권한 없는 접근 차단 (Auth) | 침투 테스트 및 퓨즈 상태 확인 |

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 제조 공정 최적화: BSDL(Boundary Scan Description Language) 파일을 활용한 자동화 검사(ICT) 도입으로 PCB 불량 검출률 98% 달성
2. 고난도 디버깅: OS 부팅 이전 단계(Bootloader 등)의 하드웨어 초기화 오류를 JTAG 하드웨어 브레이크 포인트를 사용하여 해결
3. 보안 강화: 양산 시 칩 내부의 보안 퓨즈(Secure Fuse)를 프로그래밍하여 JTAG 접근을 영구 차단, 역공학(Reverse Engineering) 방지

**결론 (2줄):**
- 기술사 판단: JTAG은 현대 하드웨어 개발과 생산의 '눈'과 같은 존재이나, 보안 관점에서는 가장 위험한 '뒷문'이므로 생애주기별(개발-생산-운영) 관리 전략이 수반되어야 한다.
- 향후 방향: 핀 수를 더욱 줄인 cJTAG(IEEE 1149.7) 및 내부 시스템 가시성을 높이는 On-chip Instrumentation 기술로 발전하고 있다.
