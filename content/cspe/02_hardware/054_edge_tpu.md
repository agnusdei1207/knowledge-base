## 미리 알고가기

- Edge AI: 데이터를 클라우드로 보내지 않고 단말 또는 현장 장비에서 AI 추론을 수행하는 방식임
- TFLite: 모바일·임베디드 환경에서 가볍게 실행하기 위한 TensorFlow Lite 모델 형식임
- INT8 모델: Edge TPU 같은 저전력 추론 가속기가 주로 사용하는 8비트 정수 모델임
- Host CPU: Edge TPU에 입력을 준비하고 후처리를 수행하는 제어 프로세서임

## Ⅰ. 개요

- **정의**: Edge TPU는 엣지 장치에서 TensorFlow Lite 기반 신경망 추론을 낮은 전력과 짧은 지연으로 수행하도록 설계된 전용 AI ASIC임. 지원 연산자, INT8 정밀도, 모델 크기, 실시간 응답 기준으로 현장 추론을 수행하기 위해 사용함.
- **배경/필요성**: 영상, 음성, 센서 데이터는 현장에서 즉시 판단해야 하며 클라우드 전송은 지연, 비용, 개인정보 문제가 있음. Edge TPU는 제한된 전력과 네트워크 조건에서도 추론 서비스를 지속하게 함.
- **비유**: 본사 서버에 매번 묻지 않고 현장 직원이 작은 전용 계산기로 즉시 판단하는 것과 같음.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 엣지 AI 전용 가속기의 구조와 제약 설명 | 저전력, TFLite, INT8, Host CPU, 현장 추론 | 클라우드 TPU와 혼동 |

> 요약: Edge TPU는 엣지 환경의 전력·지연 제약 안에서 신경망 추론을 수행하는 전용 ASIC임.

## Ⅱ. 특징/비교

| 판단 기준 | Cloud TPU | Edge TPU |
|:---|:---|:---|
| 배치 위치 | 데이터센터에서 대규모 학습·추론을 처리함 | 단말, 게이트웨이, 카메라 등 현장 장비에 배치됨 |
| 최적화 목표 | 클러스터 처리량과 대규모 텐서 연산 | 저전력, 낮은 지연, 오프라인 추론 |
| 적용 기준 | 대량 데이터와 중앙 집중 운영에 적합함 | 개인정보, 지연, 네트워크 비용 제약이 큰 서비스에 적합함 |

> 요약: Edge TPU는 대규모 처리량보다 현장성, 전력 효율, 즉시 응답을 우선하는 가속기임.

## Ⅲ. 구성요소

```text
+----------+     +----------+     +----------+
| Sensor   | --> | Host CPU | --> | Edge TPU |
+----------+     +----------+     +----------+
      |                                |
      v                                v
+----------+                   +-------------+
| Pre/Post |                   | TFLite Model|
+----------+                   +-------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Host CPU | 입력 전처리, 모델 로딩, Edge TPU 호출, 후처리를 담당함 | 현장 관리자 |
| Edge TPU ASIC | 지원되는 INT8 신경망 연산을 저전력으로 수행함 | 전용 계산기 |
| TFLite 모델 | Edge TPU 컴파일러로 변환된 실행 가능한 모델 그래프임 | 작업 카드 |
| 센서/I/O | 카메라, 마이크, 산업 센서 입력과 결과 제어를 연결함 | 현장 관측 창구 |

> 요약: Edge TPU 시스템은 센서 입력을 Host CPU가 준비하고 전용 ASIC이 추론한 뒤 현장 동작으로 연결함.

## Ⅳ. 절차

```text
+----------+     +----------+     +----------+     +----------+
| 모델준비 | --> | 입력전처리| --> | TPU추론  | --> | 현장조치 |
+----------+     +----------+     +----------+     +----------+
```

1. **모델 준비**: 학습 모델을 INT8로 양자화하고 Edge TPU 지원 형식으로 컴파일함
2. **입력 전처리**: Host CPU가 센서 데이터를 정규화, 크기 조정, 버퍼링함
3. **TPU 추론**: Edge TPU가 지원 연산자를 실행하고 중간 텐서를 내부적으로 처리함
4. **현장 조치**: Host CPU가 결과를 해석해 알림, 제어, 저장, 네트워크 전송을 수행함

> 요약: Edge TPU 적용은 모델을 제약에 맞게 준비하고 현장 입력을 즉시 추론으로 연결하는 흐름임.

## Ⅴ. 문제점

- **P1 모델 제약**: 지원되지 않는 연산자, 동적 shape, 비INT8 구간은 컴파일 실패나 CPU fallback을 유발함
- **P2 메모리 한계**: 큰 모델이나 고해상도 입력은 Edge TPU 메모리와 대역폭을 초과해 지연을 증가시킴
- **P3 현장 운영 보안**: 물리적으로 노출된 장치에서 모델 탈취, 펌웨어 변조, 비인가 업데이트 위험이 존재함

> 요약: Edge TPU의 문제는 모델 호환성, 제한된 자원, 현장 장치 보안에서 발생함.

## Ⅵ. 개선방안

- **P1 대응**: 지원 연산자 사전 점검, 양자화 인지 학습, 그래프 단순화를 수행함 (확인: 컴파일 성공률)
- **P2 대응**: 모델 pruning, 입력 해상도 조정, 스트리밍 추론, batch 1 최적화를 적용함 (확인: p95 추론 지연)
- **P3 대응**: Secure Boot, 서명된 OTA, 모델 암호화, 장치 인증을 적용함 (확인: 업데이트 검증 실패 차단률)

> 요약: 개선은 모델을 하드웨어 제약에 맞추고 현장 보안 통제를 함께 설계하는 방향임.

## Ⅶ. 전망

- **발전 방향**: Edge TPU 계열은 스마트 카메라, 산업 IoT, 로봇, 리테일 분석에서 현장 추론용 저전력 NPU와 경쟁·융합함
- **기술사적 판단**: Edge TPU 선택은 모델 호환성, 전력 예산, 현장 보안, 네트워크 비용 절감 효과를 함께 평가해야 함
- **기술사 제언**: 답안에서는 Edge TPU를 클라우드 TPU의 축소판이 아니라 엣지 제약을 해결하는 전용 추론 ASIC으로 설명해야 함
