# Edge TPU (Edge TPU)

## 미리 알고가기

- Edge AI: 데이터를 클라우드로 보내지 않고 단말 또는 현장 장비에서 AI 추론을 수행하는 방식임
- Edge TPU: 엣지 장치용 저전력 텐서 추론 가속기임
- TFLite: TensorFlow Lite는 모바일·임베디드 환경에서 가볍게 실행하기 위한 모델 형식임
- INT8 모델: Edge TPU 같은 저전력 추론 가속기가 주로 사용하는 정밀도 형식임
- Host CPU: Edge TPU에 입력을 준비하고 후처리를 수행하는 제어 프로세서임

## 1. 개요

- **정의/개념**: Edge TPU는 엣지 장치에서 지원 연산자, INT8 정밀도, 모델 크기, 실시간 응답 기준에 맞춘 TensorFlow Lite 기반 신경망 추론을 낮은 전력과 짧은 지연으로 수행하는 전용 AI ASIC임.
- **배경/필요성**: 영상, 음성, 센서 데이터는 현장에서 즉시 판단해야 하며 클라우드 전송은 지연, 비용, 개인정보 문제를 유발함. Edge TPU는 제한된 전력과 네트워크 조건에서도 추론 서비스를 지속하게 함.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 엣지 AI 전용 가속기의 구조와 제약 설명 | low power, TFLite, INT8, Host CPU, supported op | Cloud TPU와 혼동, 모델 제약 누락 |

> 요약: Edge TPU는 엣지 환경의 전력·지연 제약 안에서 신경망 추론을 수행하는 전용 ASIC임.

## 2. 특징 및 비교

| 판단 기준 | Cloud TPU | Edge TPU |
|:---|:---|:---|
| 배치 위치 | 데이터센터에서 대규모 학습·추론 처리 | 단말, 게이트웨이, 카메라 등 현장 장비 |
| 최적화 목표 | 클러스터 처리량과 대규모 텐서 연산 | 저전력, 낮은 지연, 오프라인 추론 |
| 모델 조건 | 큰 모델과 대규모 배치에 유리 | 작고 최적화된 INT8 모델에 적합 |
| 운영 기준 | 중앙 집중 운영과 고속 네트워크 전제 | 전력, 온도, 네트워크 단절 허용성 중시 |

Edge TPU는 엣지에서 모든 AI 모델을 실행하는 장치가 아니라, 지원 연산자와 모델 크기 조건을 만족하는 추론을 저전력으로 처리하는 장치임. 따라서 클라우드 회피 효과와 모델 제약을 함께 설명해야 함.

## 3. 구성요소/구조

```text
+----------+      +-----------+      +-----------+      +----------+
| Sensor   | ---> | Host CPU  | ---> | Edge TPU  | ---> | Action   |
+----------+      +-----------+      +-----------+      +----------+
                         |                 ^
                         v                 |
                  +-------------+    +-------------+
                  | TFLite/INT8 |    | Runtime     |
                  +-------------+    +-------------+
```

| 구성요소 | 설명 | 핵심 포인트 |
|:---|:---|:---|
| 센서/입력 | 영상, 음성, 산업 센서 데이터를 생성함 | 현장성 |
| Host CPU | 전처리, 모델 호출, 후처리, 비지원 연산을 수행함 | 전체 지연 |
| Edge TPU 코어 | 지원 연산자를 INT8 기반으로 가속함 | 저전력 추론 |
| TFLite 모델 | Edge TPU 컴파일러가 처리 가능한 모델 형식임 | 모델 제약 |
| 런타임 | 입력 텐서 전달, 장치 실행, 결과 회수를 관리함 | 통합 운영 |

### 원리/흐름도

```text
+----------+      +----------+      +----------+      +----------+
| Convert  | ---> | Compile  | ---> | Infer    | ---> | Actuate  |
+----------+      +----------+      +----------+      +----------+
```

학습된 모델은 TFLite와 INT8 형태로 변환되고 Edge TPU 컴파일러가 지원 연산자 범위를 확인함. 실행 시 Host CPU가 입력을 준비하고 Edge TPU가 추론을 수행한 뒤 후처리 결과로 현장 동작을 결정함.

## 4. 문제점 및 개선방안

1. **지원 모델 제약**: 비지원 연산자나 큰 모델은 Edge TPU에서 실행되지 않거나 Host CPU fallback으로 지연이 증가함.
   - **개선방안**: 모델 설계 단계부터 지원 연산자, 텐서 크기, INT8 조건을 반영함. (확인: Edge TPU compile report)
2. **양자화에 따른 정확도 손실**: INT8 변환 과정에서 작은 객체나 민감한 분류 정확도가 낮아질 수 있음.
   - **개선방안**: 대표 데이터셋 calibration, quantization-aware training, 후처리 threshold 조정을 적용함. (확인: 정확도 차이)
3. **엣지 운영 제약**: 현장 장비는 온도, 전원, 네트워크 단절, 원격 업데이트 실패에 취약함.
   - **개선방안**: thermal budget, OTA rollback, 로컬 로그, watchdog을 설계함. (확인: 장치 온도, 업데이트 실패율)

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 스마트 카메라 | 객체 탐지 모델을 현장 장비에서 실행해 영상 원본 전송을 줄임 | FPS/W, 네트워크 전송량 |
| 산업 현장 이상 탐지 | 센서 데이터를 게이트웨이에서 즉시 추론해 장비 정지를 빠르게 판단함 | 탐지 지연, false alarm |
| 오프라인 AI 단말 | 네트워크가 불안정한 환경에서 음성·이미지 분류를 로컬 처리함 | 오프라인 성공률, 배터리 시간 |

## 6. 결론

Edge TPU는 클라우드 의존을 줄이고 현장 추론의 지연과 전력을 낮추는 장치임. 그러나 모델 형식, INT8 정밀도, 지원 연산자 제약이 명확하므로 적용 전 컴파일 가능성과 정확도 유지 여부를 확인해야 함. 실무 판단은 가속기 성능보다 현장 지연, 전력, 개인정보, 운영 안정성까지 포함해야 함.
