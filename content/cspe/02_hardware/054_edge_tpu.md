# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 구글이 IoT 및 엣지 디바이스 환경에서 딥러닝 추론(Inference)을 고속·저전력으로 수행하기 위해 만든 특수 목적 ASIC 칩
- **왜 필요한가**: 데이터센터용 빵빵한 TPU(Cloud TPU)는 강력하지만 전기를 수백 와트(W) 먹고 크기도 크다. 카메라, 드론, 센서 같은 말단 기기(Edge)에서는 배터리로 돌아갈 작고 전력 소모가 극히 적은 가속기가 필요했다.
- **핵심 직관**: Cloud TPU가 수백 명의 요리사가 있는 대형 뷔페 식당이라면, Edge TPU는 라면 끓이기에만 최적화된 2와트(W)짜리 1인용 소형 라면 조리기다. 정밀도를 낮추고 추론만 한다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| Edge Computing (엣지 컴퓨팅) | 데이터를 중앙 클라우드로 보내지 않고 발생한 단말 근처에서 처리 | 본사에 서류를 보내지 않고 지사에서 즉결 처리 |
| INT8 Quantization (양자화) | 모델 파라미터를 32비트 소수점에서 8비트 정수로 압축 | 고화질 사진을 256색 GIF로 용량 압축 (의미는 유지) |
| Inference (추론) | 이미 학습된 모델에 새 데이터를 넣어 결과를 뽑아내는 과정 | 완성된 시험 공부 지식(모델)으로 실제 시험 문제(추론) 풀기 |

## 깊이 이해
- **배경·문제의식**: 모든 센서 데이터를 클라우드로 보내어 AI 처리하면 통신 지연시간(Latency), 대역폭 비용, 개인정보 유출 문제가 발생한다. 로컬 기기 내에서 즉시 판단할 지능이 요구되었다.
- **작동 원리**: 사전에 클라우드에서 학습된 모델(TensorFlow Lite 형태)을 8비트 정수(INT8)로 변환(양자화)하여 Edge TPU에 컴파일해 넣는다. USB나 PCIe로 연결된 이 칩은 저정밀도의 대규모 행렬 곱셈을 2W 이하의 전력으로 순식간에 수행한다.
- **비유**: 보안 카메라가 사람을 인식할 때, 예전에는 사진을 클라우드로 보내 확인을 받았지만(지연 발생), Edge TPU를 달면 카메라 내부의 소형 칩이 직접 사람 여부를 판단하고 결과 텍스트만 서버로 보낸다.
- **구체 예시**: 구글 코랄(Coral) USB 가속기는 엄지손가락만 한 크기로, 라즈베리 파이 같은 초소형 컴퓨터에 꽂아 4 TOPS(초당 4조 번) 연산을 단 2와트(W) 전력으로 수행한다.
- **흔한 오해·주의점**: Edge TPU에서는 모델 "학습"이 불가능하다. 오직 "추론" 전용이다. 또한 32비트 부동소수점(FP32) 모델은 그대로 돌릴 수 없고 반드시 INT8 변환 과정을 거쳐야 한다.

## 연결 개념
- TPU (Tensor Processing Unit - 클라우드 버전)
- NPU (Neural Processing Unit)
- TensorFlow Lite (모바일/임베디드용 딥러닝 프레임워크)

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Edge TPU는 엣지 컴퓨팅 환경의 SWAP(Size, Weight, And Power) 제약을 극복하고 실시간 머신러닝 추론을 수행하기 위한 구글의 초소형·초저전력 ASIC 가속기다.
> 2. **가치**: 모델 파라미터를 8비트 정수(INT8)로 양자화(Quantization)하여 연산 로직과 메모리 요구량을 극적으로 줄여, 2W 수준의 전력으로 고성능 실시간 비전 처리가 가능하다.
> 3. **판단 포인트**: 클라우드 기반 AI와 대비하여 프라이버시 보호, 통신 지연 제거, 네트워크 단절 시 독립 구동의 장점이 있으나 제한된 메모리로 인해 소규모 특정 모델 구동으로 용도가 한정된다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 온디바이스 AI 트렌드 및 엣지 가속기 이해 | 클라우드 오프로딩의 한계(지연, 대역폭, 보안), 엣지 추론 모델 | Edge TPU에서 모델 학습이 가능하다고 서술 |
| 리소스 제약 환경의 최적화 기술 파악 | INT8 양자화(Quantization), TensorFlow Lite, TOPS/W | 성능을 단순 FLOPS 중심(FP32)으로 비교 평가 |
| 아키텍처 특성 파악 | 초저전력(2W 내외), 소형 폼팩터(M.2, USB), 호스트 인터페이스 | Cloud TPU의 HBM, 광스위치 연결 등과 혼동 |

> 요약: 성능의 절댓값보다 '와트당 처리량(TOPS/W)'과 '통신 지연 없는 실시간성'이라는 엣지 환경 특유의 요구사항을 어떻게 하드웨어적으로 해결했는지가 핵심이다.

## Ⅰ. 개요 및 필요성

- 개요: 구글이 IoT, 로보틱스, 산업용 장비 등 엣지 디바이스에서의 고속 AI 추론(Inference)을 위해 특화 설계한 초저전력 ASIC 가속기
- 배경: 자율주행, 스마트팩토리 등에서 밀리초(ms) 단위의 반응성이 필요하나 클라우드 통신은 네트워크 지연(Latency)과 보안 리스크 유발
- 필요성: 네트워크가 단절된 오프라인 상태에서도 디바이스 자체적으로 데이터를 처리(온디바이스 AI)할 수 있는 고효율 추론 하드웨어 필수

---

## Ⅱ. 구조 및 구성요소

```text
IoT Device (Host) <--- PCIe / USB ---> [Edge TPU 칩]
                                         |-- Control Block (TF Lite 명령어)
[Sensor/Camera] -> Data Input            |-- On-chip SRAM (Weight/Data)
                                         +-> INT8 MAC Array (추론 전용)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| INT8 MAC Array | 양자화된 8비트 정수 기반의 행렬 곱셈-누적 병렬 처리 블록 | 부동소수점(FP) 연산기 배제 (면적/전력 최소화) |
| On-chip SRAM | 가중치와 활성화 값을 임시 저장하는 내장 메모리 | 외부 DRAM 접근 억제로 전력 절감 |
| Host Interface | 라즈베리 파이, 산업용 PC 등과 연결되는 I/O 버스 | USB 3.0, PCIe (M.2/Mini PCIe) 형태 지원 |
| Edge TPU Compiler | 사전에 학습된 TF Lite 모델을 칩 전용 명령어로 변환 | 미지원 연산은 Host CPU로 분리 실행 |

> 요약: 범용성을 과감히 버리고 INT8 텐서 연산에만 칩 면적을 할애하여, 코인 크기의 패키지로 수 테라 연산을 지원하는 구조다.

---

## Ⅲ. 동작원리 및 흐름도

```text
클라우드 학습 -> 모델 양자화/컴파일 -> 디바이스 배포 -> 실시간 센서 입력 -> 엣지 추론/결과
(TensorFlow)    (Edge TPU Compiler)    (Edge Device)    (카메라/마이크)     (Edge TPU)
```

- 1단계 [학습 및 변환]: 강력한 Cloud 환경에서 모델 학습 후, 파라미터를 INT8로 양자화(Post-Training Quantization)
- 2단계 [오프라인 컴파일]: Edge TPU 컴파일러를 통해 연산 그래프를 분석하고 가속기 전용 기계어로 변환
- 3단계 [디바이스 구동]: 엣지 디바이스가 센서(카메라 등) 데이터를 수집하여 USB/PCIe를 통해 칩으로 입력
- 4단계 [실시간 추론]: 칩 내부에서 외부 통신 없이 수 ms 이내에 추론을 완료하고 결과값(라벨, 좌표 등) 반환

> 요약: 무거운 연산(학습 및 양자화)은 클라우드가 전담하고, Edge TPU는 가벼워진 모델로 현장에서 데이터를 즉시 소비하는 역할 분담이다.

---

## Ⅳ. 특징
- 극강의 전성비: 연산당 전력 소모를 나타내는 에너지 효율이 매우 높아 최대 부하 시에도 약 2W만 소모 (방열판 없이 쿨링 가능)
- 통신 대역폭 절감: 원본 영상/음성을 서버로 보내지 않고 추론 결과 메타데이터(예: "침입자 발생")만 전송하여 망 부하 최소화
- 강력한 프라이버시: 민감한 생체 정보나 산업 기밀 데이터가 기기 외부로 유출되지 않아 물리적 보안 확보 용이

> 요약: 절대적인 컴퓨팅 파워는 낮지만 지연(Latency), 프라이버시(Privacy), 대역폭(Bandwidth) 등 엣지 컴퓨팅의 3대 과제를 하드웨어로 해결한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | Cloud TPU | Edge TPU | 선택 기준 |
|:---|:---|:---|:---|
| 주요 임무 | 대규모 학습 (Training) 및 추론 | 초저지연 오프라인 추론 (Inference) | 적용 워크로드 단계 |
| 지원 정밀도 | Bfloat16, FP32 | INT8 단일 정밀도 | 정확도 vs 경량화 수용도 |
| 네트워크 의존 | 고속망(인터넷/데이터센터망) 필수 | 네트워크 단절(Air-gapped) 환경 구동 | 실시간성 및 보안 요구사항 |

> 요약: 모델 생성과 고도화는 Cloud TPU로, 모델 배포와 실시간 실행은 Edge TPU로 분담하는 하이브리드 전략이 표준이다.

**리스크·대응 (기본 불릿):**
- 연산 정밀도 손실: 32비트를 8비트로 압축하면서 모델 정확도(Accuracy) 하락 발생 → Quantization-Aware Training(학습 중 양자화 모의) 적용으로 정확도 손실 1% 이내 방어 (지표: mAP, Top-1 Accuracy)
- 미지원 연산자 바운스 백: Edge TPU가 지원하지 않는 최신 연산(Op)은 Host CPU에서 처리되어 지연 발생 → 컴파일러 경고 기반 모델 아키텍처 재설계(예: MobileNet V2 최적화) (지표: 가속기 처리 비율)
- 제한된 온칩 메모리: 고해상도 이미지 동시 처리 불가 → 이미지 패치 분할 타일링(Tiling) 입력 및 프레임 드롭 로직 구현 (지표: 프레임 처리량 FPS)

**도입 후 점검 지표:**
- 추론 지연시간: ms (인퍼런스 레이턴시) — 목표 응답 시간 준수 여부
- 기기 소비 전력: Watt — 전체 시스템 전력 예산(TDP) 초과 여부

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 스마트팩토리 불량 탐지: 컨베이어 벨트 카메라에 Coral 가속기를 결합하여, 네트워크 지연 없이 초당 30프레임(30fps) 이상으로 실시간 외관 불량 판별
2. 프라이버시 보존형 스마트홈: 가정 내 홈캠에서 캡처된 영상을 서버 송출 없이 Edge TPU 내에서 사람 쓰러짐(Fall Detection) 여부만 판별 후 알림 발송
3. 자율 비행 드론 장애물 회피: 제한된 배터리(페이로드) 환경에서 초경량(수 그램) Edge TPU 모듈을 장착해 딥러닝 기반 실시간 객체 인식 및 회피 기동 수행

**결론 (2줄):**
- 기술사 판단: Edge TPU 도입은 단순히 칩을 끼우는 것이 아니라, 거대 모델을 INT8 환경에 맞게 경량화하는 MLOps 파이프라인(TF Lite 양자화) 구성 역량이 필수적이다.
- 향후 방향: IoT 센서와 가속기가 하나의 패키지로 통합된 형태(AI in Sensor)로 발전하며, NPU 기술의 보편화에 따라 엣지 AI 칩 생태계의 표준화 경쟁이 가속될 것이다.
