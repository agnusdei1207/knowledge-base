# 📖 【암기용】 개념 완전 이해

> 목적: Edge TPU를 처음 봐도 클라우드 TPU·NPU와 무엇이 다른지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: Google이 systolic array 기반 TPU 아키텍처를 소형·저전력으로 축소해 만든 엣지 추론 전용 ASIC
- **왜 필요한가**: 데이터센터 TPU Pod는 킬로와트급 전력을 쓰지만, 카메라·센서·IoT 기기는 수 와트 이하 전력 예산만 허용한다. Edge TPU는 동일한 systolic array 원리를 초소형·초저전력으로 재설계해 이 격차를 메운다.
- **핵심 직관**: 발전소(클라우드 TPU Pod)를 그대로 축소한 휴대용 소형 발전기.

## 깊이 이해
- **배경·문제의식**: Google은 Coral 브랜드로 Edge TPU를 USB 액세서리, M.2/PCIe 모듈, SoC 내장형으로 출시해 카메라·드론·산업 IoT 기기에서 TensorFlow Lite 모델을 오프라인 추론하도록 지원한다.
- **작동 원리**: 클라우드 TPU와 동일하게 systolic array 기반 MAC 연산을 쓰되, 온칩 메모리 용량과 클럭·전력을 크게 낮추고 INT8 양자화 모델 실행에 특화했다.
- **비유**: 대형 인쇄 공장(클라우드 TPU)의 인쇄 원리를 그대로 가져와 손바닥만 한 라벨 프린터(Edge TPU)로 축소한 셈이다.
- **구체 예시**: Coral USB Accelerator는 공개 자료 기준 약 4 TOPS(int8), 약 2W 수준의 전력으로 동작한다고 알려져 있으며, 정확한 세대별 수치는 제품 스펙에 따라 달라질 수 있어 설계 시 최신 공식 스펙 확인이 필요하다.
- **흔한 오해·주의점**: Edge TPU는 "작은 TPU Pod"가 아니다. 학습 기능이 없는 추론 전용 칩이며, 지원 연산자(op) 집합이 제한적이라 TensorFlow Lite 모델을 Edge TPU 컴파일러로 변환·양자화하는 과정이 반드시 필요하다.

## 연결 개념
- TPU(클라우드) — Edge TPU의 원형이 된 데이터센터용 systolic array ASIC(052번 키워드 참고)
- NPU — 모바일 SoC 내장형 추론 가속기와 유사한 포지션이지만 제조사·생태계가 다름(053번 키워드 참고)
- TensorFlow Lite — Edge TPU가 실행하는 경량 추론 프레임워크
- INT8 양자화 — Edge TPU 실행을 위한 필수 모델 변환 과정

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: Edge TPU 답안은 클라우드 TPU와의 축소 관계, 추론 전용 제약, 양자화·컴파일 파이프라인을 함께 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Edge TPU는 클라우드 TPU의 systolic array 원리를 저전력·소형 폼팩터로 축소한 Google의 엣지 추론 전용 ASIC이다.
> 2. **가치**: 수 와트급 전력으로 INT8 양자화 모델을 오프라인 실시간 추론해 네트워크 연결 없는 IoT·카메라 기기에 AI를 배치한다.
> 3. **판단 포인트**: 학습·대규모 추론은 클라우드 TPU, 저전력 오프라인 단일 모델 추론은 Edge TPU라는 배치 위치로 구분해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 클라우드 TPU와의 관계 이해 확인 | systolic array 원리 공유, 규모·전력만 축소 | Edge TPU를 클라우드 TPU Pod의 축소 복제품으로 단순화 |
| 추론 전용 제약 이해 확인 | 학습 미지원, 제한된 연산자 집합, 컴파일러 변환 필수 | Edge TPU에서 모델 학습이 가능하다고 오기술 |
| NPU와의 포지션 차이 인식 확인 | Google 생태계(TFLite, Coral) vs 범용 SoC NPU(모바일 제조사별) | Edge TPU와 NPU를 동일 제품군으로 혼동 |

> 요약: 이 문제는 Edge TPU를 클라우드 TPU의 원리 축소판이자 추론 전용 엣지 ASIC으로 정확히 구분해 보여야 한다.

## Ⅰ. 개요 및 필요성

- 개요: systolic array 기반 TPU 아키텍처를 저전력·소형으로 축소한 Google의 엣지 추론 전용 ASIC
- 배경: IoT·카메라·드론 등은 전력 예산이 수 와트 이하로 제한되어 클라우드 TPU를 그대로 적용할 수 없음
- 필요성: 오프라인·저지연·저전력 추론이 필요한 엣지 환경에서 양자화 모델을 실행할 전용 하드웨어가 필요함

---

## Ⅱ. 구조 및 구성요소

```text
개발 단계: TensorFlow 모델 학습(클라우드/서버)
  -> INT8 양자화 -> Edge TPU Compiler 변환
배포 단계: 기기(Edge TPU 탑재)
  -> USB/M.2/PCIe/SoC 내장 인터페이스
  -> Systolic Array(축소형) -> On-chip Buffer
  -> 추론 결과 반환
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Edge TPU Compiler | TFLite 모델을 Edge TPU 실행 형식으로 변환 | 지원되지 않는 연산자는 CPU로 폴백(fallback) |
| Systolic Array(축소형) | 클라우드 TPU와 동일 원리의 소형 MAC 격자 | 전력·면적을 수 와트급으로 축소 |
| 인터페이스 | USB Accelerator, M.2/PCIe 모듈, SoC 내장 | 폼팩터에 따라 배포 대상 기기가 다름 |
| 호스트 인터페이스 | 호스트 CPU와 Edge TPU 간 명령·데이터 전달 | 호스트-가속기 간 전송 오버헤드 존재 |

> 요약: Edge TPU는 클라우드 TPU와 같은 systolic array 원리를 쓰되, 컴파일러 변환과 소형 인터페이스로 엣지 배포에 맞춘다.

---

## Ⅲ. 동작원리 및 흐름도

```text
서버에서 모델 학습 -> INT8 양자화 -> Edge TPU Compiler 변환
  -> 기기에 배포 -> 입력 데이터 수신(카메라/센서)
  -> Systolic Array 추론 실행 -> 결과를 로컬 애플리케이션에 반환
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 서버에서 모델 학습 후 INT8 양자화 | 양자화 후 정확도 손실률 |
| 2 | Edge TPU Compiler로 지원 연산자 매핑 | 미지원 연산자 CPU 폴백 비율 |
| 3 | 기기 배포 후 입력 데이터 수신 | 입력 전처리 지연 |
| 4 | systolic array 추론 실행 및 결과 반환 | 추론 지연(ms), 전력 소모(W) |

> 요약: Edge TPU는 서버 학습·양자화·컴파일 결과물을 받아 기기 내에서만 추론을 수행하는 배포 종단이다.

## Ⅳ. 특징

| 구분 | Edge TPU | 클라우드 TPU | 수치·표준 포인트 |
|:---|:---|:---|:---|
| 배치 위치 | 카메라·IoT·드론 등 엣지 기기 | 데이터센터 서버 랙 | 폼팩터와 전력 예산이 근본적으로 다름 |
| 기능 범위 | 추론(inference) 전용 | 학습(training) + 대규모 추론 | Edge TPU는 학습 미지원 |
| 전력 규모 | 공개 자료 기준 수 와트급(예: 약 2W 내외) | 칩당 수백 와트 이상, Pod 단위 대규모 전력 | 정확한 수치는 세대·제품 스펙에 따라 상이 |
| 연산자 지원 | 제한된 op 집합, 미지원 시 CPU 폴백 | 폭넓은 op 지원 | 모델 설계 시 지원 연산자 사전 확인 필요 |

> 요약: Edge TPU는 클라우드 TPU와 동일 원리를 쓰되 전력·기능 범위를 대폭 축소한 추론 전용 엣지 칩이다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 클라우드 TPU | Edge TPU | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 대규모 systolic array + ICI Pod 확장 | 소형 systolic array 단일 칩 | 학습 필요 여부, 배포 위치(서버 vs 기기) |
| 비용/성능 | 대규모 학습·배치 추론 처리량 우수 | 저전력·저비용 단일 모델 실시간 추론 | 전력·비용 예산과 처리량 요구 수준 |
| 운영/위험 | 클라우드 종속, 네트워크 필요 | 제한된 연산자, 재학습 시 서버 필요 | 오프라인 요구와 모델 갱신 주기 |

> 요약: 학습·대규모 추론은 클라우드 TPU, 저전력 오프라인 단일 모델 실시간 추론은 Edge TPU를 선택한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 연산자 미지원 | 모델 구조가 Edge TPU 컴파일러 지원 범위를 벗어남 | 지원 연산자 기준으로 모델 재설계, CPU 폴백 최소화 | CPU 폴백 발생 비율 |
| 정확도 손실 | INT8 양자화로 인한 표현력 저하 | 양자화 인식 학습(quantization-aware training) 적용 | 양자화 전후 정확도 차이 |
| 모델 갱신 지연 | Edge TPU 자체 재학습 불가로 서버 왕복 필요 | OTA(Over-The-Air) 모델 배포 파이프라인 구축 | 모델 갱신 주기, 배포 성공률 |

> 요약: Edge TPU 운영 리스크는 연산자 미지원, 양자화 정확도 손실, 모델 갱신 지연이며 컴파일러 검증과 OTA 파이프라인으로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 추론 지연 | 목표 응답시간(예: 실시간 프레임률) 충족 | 온디바이스 벤치마크 |
| 전력 소모 | 기기 전력 예산 이내 | 전력 측정 장비 |
| 정확도 | 양자화 후 정확도 손실 허용치 이내 | 검증 데이터셋 비교 |

> 요약: 도입 성과는 추론 지연, 전력 소모, 양자화 후 정확도로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 카메라·드론·산업 IoT의 오프라인 실시간 추론에는 Edge TPU를 적용하고 CPU 폴백 비율을 사전 점검함
2. 모델 학습과 대규모 배치 추론은 클라우드 TPU에서 수행하고, INT8 양자화·컴파일러 변환 후 Edge TPU로 배포함
3. 모델 갱신이 필요한 경우 OTA 배포 파이프라인을 구축해 서버 재학습 결과를 주기적으로 반영함

**결론 (2줄):**
- 기술사 판단: 학습·대규모 추론은 클라우드 TPU, 저전력·오프라인·실시간 단일 모델 추론은 Edge TPU로 역할을 분담함
- 향후 방향: TensorFlow Lite·컴파일러 지원 연산자 확대와 온디바이스 재학습(온디바이스 fine-tuning) 지원 강화로 발전함

| 유형 | 문제 신호어 | Ⅲ 강조 | Ⅳ 강조 |

| 비교형 | "Edge TPU와 NPU를 비교하시오" | 생태계·컴파일 흐름 차이 | 제조사·플랫폼 종속성 차이 |
