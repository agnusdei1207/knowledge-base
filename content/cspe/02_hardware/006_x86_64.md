## Ⅰ. 개요
- 정의: 인텔 8086에서 시작된 32비트 IA-32를 64비트로 확장한 CISC 기반 아키텍처
- 배경: 대용량 메모리 주소 할당(64비트) 필요성 및 하위 호환성 유지 목적
- 출제 의도: CISC의 복잡성을 내부 RISC 연산으로 극복하는 구조적 특성 이해

## Ⅱ. 구성요소
- ASCII 구조도
  +---------------------------------------+
  |  Front-end (CISC Decode)              |
  |  +------------+    +---------------+  |
  |  | Macro-ops  | -> | u-op Converter|  |
  +--+------------+----+---------------+--+
             | u-ops (RISC-like)
  +----------v----------------------------+
  |  Back-end (Execution Engine)          |
  |  +------------+    +---------------+  |
  |  | Scheduler  | -> | Execution Unit|  |
  +--+------------+----+---------------+--+

- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| Macro-op | 가변 길이의 복합 x86 명령어 | 뭉치 짐 |
| u-op | 내부적으로 처리되는 고정 길이 마이크로 연산 | 낱개 포장 |
| Out-of-Order | 명령어 순서와 관계없이 실행하는 엔진 | 병렬 처리 |
> 요약: 겉은 CISC(호환성), 속은 RISC(성능)인 하이브리드 구조임

## Ⅲ. 절차
- ASCII 흐름도
  (CISC Fetch) -> (u-op Gen) -> (Rename/Alloc) -> (Execute) -> (Retire)

- 4단계 설명
1. Fetch/Decode: 가변 길이 명령어를 가져와 마이크로 연산(u-ops)으로 변환
2. Dispatch: 변환된 u-ops를 실행 유닛의 예약 스테이션으로 분배
3. Execution: 데이터 준비가 완료된 순서대로 비순차(OoO) 실행
4. Retirement: 실행 완료된 결과를 원래 프로그램 순서대로 재정렬하여 반영
> 요약: 하위 호환성을 유지하면서 동적 실행 기술을 통해 성능을 극대화함

## Ⅳ. 문제점
- 전력 소모: 복잡한 디코더 및 비순차 실행 엔진으로 인한 높은 TDP
- 보안 취약점: 분기 예측 및 투적 실행 과정에서의 사이드 채널 공격(Spectre 등)

## Ⅴ. 개선방안
- (단기) 하이브리드 코어: 고성능(P) 코어와 고효율(E) 코어의 결합 (Alder Lake)
- (중기) AVX-512/AMX: AI 및 벡터 연산 전용 가속 명령어 확장
- (장기) 칩렛(Chiplet) 아키텍처: 공정 미세화 한계 극복을 위한 모듈형 패키징

## Ⅵ. 전망
- 로드맵: 단일 다이 구조에서 탈피하여 3D 패키징 기반의 다층 구조로 진화
- CSF: 전력 효율 개선을 통한 데이터센터 TCO 절감 및 보안 취약점의 근본적 차단
