## Ⅰ. 개요
- 정의: 과도한 페이징으로 CPU가 실제 실행보다 페이지 교체에 더 많은 시간을 쓰는 상태
- 배경: 다중 프로그래밍 정도(Degree of MP) 과다 시 시스템 성능 급락 현상 방지 필요
- 출제 의도
| 구분 | 내용 |
| --- | --- |
| 핵심 | 성능 임계점, 지역성(Locality), Working Set, PFF 기법 |

## Ⅱ. 구성요소
```
CPU Util ^
         |      / \  <- Thrashing Point
         |    /     \
         +--------------> Degree of MP
```
| 구성요소 | 설명 | 비유 |
| --- | --- | --- |
| 작업 집합(WS) | 특정 시간 동안 프로세스가 빈번히 참조하는 페이지 집합 | 필수 장비 |
| 윈도우 크기(Δ) | 작업 집합을 결정하기 위한 시간 간격 파라미터 | 관찰 시간 |
| PFF | 페이지 부재 빈도를 기준으로 프레임 할당량을 조절하는 기법 | 속도 조절기 |
> 요약: 프로세스의 지역성을 기반으로 필수 프레임을 보장하여 스래싱을 방지함

## Ⅲ. 절차
1. 지역성 발생: 프로세스가 특정 기간 동안 한정된 범위의 메모리 집중 참조
2. 작업 집합 추적: 윈도우 크기 내에서 참조된 페이지들을 Working Set으로 정의
3. 프레임 할당: 각 프로세스의 Working Set 크기만큼 물리 메모리 프레임 할당
4. 실행 및 조절: 전체 프로세스의 WS 합이 가용 메모리 초과 시 일부 프로세스 중단
> 요약: 메모리 수급 상태를 실시간 감시하여 시스템의 처리량(Throughput)을 유지함

## Ⅳ. 문제점
- 작업 집합 모델 구현 시 윈도우 크기(Δ) 결정의 모호함 및 오버헤드 발생함

## Ⅴ. 개선방안
- 페이지 부재 빈도(PFF)를 측정하여 상/하한선 기반으로 프레임을 유연하게 재할당함

## Ⅵ. 전망
- 컨테이너 및 서버리스 환경에서 콜드 스타트와 스래싱 방지를 위한 예측 모델 도입이 활발함
- AI 기반 자원 오케스트레이션을 통해 실시간 워크로드 패턴 분석 후 동적 할당 최적화가 목표임
