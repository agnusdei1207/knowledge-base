# 📖 【암기용】 개념 완전 이해

> 목적: NPU를 처음 봐도 TPU·GPU와 무엇이 다른지, 왜 스마트폰·노트북에 들어가는지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 모바일·엣지 기기 SoC(System on Chip)에 내장되어 저전력으로 신경망 추론을 수행하는 전용 가속기
- **왜 필요한가**: 스마트폰·노트북은 배터리 용량이 제한적이라 GPU/CPU로 신경망 추론을 돌리면 전력 소모가 크다. NPU는 저정밀(INT8/INT4) 행렬-벡터 연산에 특화된 회로로 동일 추론을 훨씬 적은 전력으로 처리한다.
- **핵심 직관**: 데이터센터의 대형 발전소(TPU/GPU 클러스터) 대신, 집 안에 놓는 소형 저전력 가전기기.

## 깊이 이해
- **배경·문제의식**: 카메라 화질 보정, 음성인식, on-device LLM 요약 같은 기능이 늘면서, 클라우드 왕복 지연과 개인정보 전송 없이 기기 내에서 즉시 추론해야 할 필요가 커졌다.
- **작동 원리**: NPU는 MAC(Multiply-Accumulate) 배열과 저정밀 양자화(INT8·INT4) 지원 유닛으로 구성되며, 처리 능력을 TOPS(Tera Operations Per Second)로 표기한다.
- **비유**: 공장 전체(TPU Pod)가 아니라, 집 안 냉장고처럼 항상 켜져 있으면서 적은 전력으로 정해진 일만 반복하는 전용 가전.
- **구체 예시**: Apple의 Neural Engine, Qualcomm Snapdragon의 Hexagon NPU, Samsung Exynos NPU, Intel/AMD의 Copilot+ PC용 NPU(40+ TOPS급, 공개 마케팅 수치 기준)가 카메라 처리, 음성 인식, on-device 소형 LLM 추론에 쓰인다.
- **흔한 오해·주의점**: NPU는 대규모 모델 학습(training)용이 아니다. 대부분 추론(inference) 전용으로 설계되며, 학습은 여전히 GPU/TPU 데이터센터에서 수행한 뒤 양자화된 모델을 NPU에 배포하는 구조다.

## 연결 개념
- TOPS(Tera Operations Per Second) — NPU 성능 표기 단위
- 양자화(Quantization, INT8/INT4) — NPU 저전력 추론의 핵심 전제
- Edge TPU — Google의 엣지 전용 추론 ASIC(054번 키워드 참고)
- On-Device AI — NPU가 지원하는 대표 응용 분야

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: NPU 답안은 저전력 추론 특화 목적, TOPS/양자화 지표, TPU·GPU와의 배치(deployment) 위치 차이를 함께 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: NPU (Neural Processing Unit)는 모바일·엣지 SoC에 내장되어 저정밀 신경망 추론을 저전력으로 처리하는 전용 가속기이다.
> 2. **가치**: INT8/INT4 양자화 MAC 연산으로 클라우드 왕복 없이 온디바이스 추론을 수행해 지연과 개인정보 전송 위험을 낮춘다.
> 3. **판단 포인트**: 학습은 GPU/TPU 데이터센터, 추론 배포는 전력·지연 제약이 있는 엣지에서는 NPU라는 역할 분담을 기준으로 판단한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 온디바이스 AI 구조 이해 확인 | SoC 내장 위치, MAC 배열, TOPS 지표 | NPU를 TPU·GPU와 동일한 데이터센터 가속기로 서술 |
| 학습·추론 역할 분담 판단 확인 | 학습=GPU/TPU, 추론 배포=NPU | NPU가 대규모 모델 학습까지 담당한다고 오기술 |
| 저전력·양자화 트레이드오프 이해 확인 | INT8/INT4 양자화, 정확도 손실, TOPS/W | 양자화로 인한 정확도 저하 리스크 누락 |

> 요약: 이 문제는 NPU를 TPU·GPU와 뭉뚱그리지 않고, 엣지 저전력 추론이라는 역할과 양자화 트레이드오프를 보여야 한다.

---

## Ⅰ. 개요 및 필요성

- 정의: 모바일·엣지 SoC에 내장되어 저전력 신경망 추론을 전담하는 하드웨어 가속기
- 배경: 카메라·음성·on-device LLM 기능 확산으로 클라우드 왕복 지연과 개인정보 전송 없는 추론 요구가 증가함
- 필요성: 배터리 제약 기기에서 GPU/CPU 추론은 전력 소모가 크므로, 저정밀 MAC 연산 전용 회로로 TOPS/W 효율을 높여야 함

---

## Ⅱ. 구조 및 구성요소

```text
SoC(System on Chip)
  -> CPU Core / GPU Core / NPU Core 통합
  -> NPU: MAC Array (INT8/INT4)
    -> On-chip SRAM Buffer
  -> 양자화된 모델 로드 -> 추론 실행 -> 결과를 CPU/앱으로 반환
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| MAC Array | 저정밀 행렬-벡터 곱셈 누적 연산 | INT8/INT4 위주, 일부 FP16 지원 |
| On-chip SRAM | 가중치·활성값 임시 저장 | DRAM 접근 최소화로 전력 절감 |
| 양자화 엔진 | FP32 모델을 INT8/INT4로 변환 | 정확도 손실과 속도 향상의 트레이드오프 |
| Runtime(NNAPI 등) | 앱-NPU 간 추론 요청 중개 | OS/프레임워크별 API 상이(Core ML, NNAPI, ONNX Runtime) |

> 요약: NPU는 저정밀 MAC 배열과 온칩 버퍼로 양자화된 모델을 저전력 추론하며, OS 런타임이 앱과 하드웨어를 중개한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
클라우드/서버 GPU·TPU에서 모델 학습(FP32/BF16)
  -> 양자화(INT8/INT4)로 모델 경량화
  -> 기기에 배포 -> NPU Runtime이 추론 요청 수신
  -> MAC Array 연산 -> 결과를 앱에 반환
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 데이터센터에서 FP32/BF16으로 모델 학습 | 학습 정확도, loss 수렴 |
| 2 | 양자화(post-training 또는 quantization-aware)로 경량화 | INT8 변환 후 정확도 손실률 |
| 3 | 기기 배포 후 NPU가 추론 요청 수신 | 추론 지연(ms), 배터리 소모 |
| 4 | 결과를 앱/OS로 반환 | TOPS/W, 초당 추론 처리량 |

> 요약: NPU는 서버에서 학습·양자화된 모델을 받아 기기 내 저전력 추론만 담당하는 배포 종단(inference endpoint)이다.

---

## Ⅳ. 특징

| 구분 | NPU | GPU/TPU(데이터센터) | 수치·표준 포인트 |
|:---|:---|:---|:---|
| 배치 위치 | 모바일·노트북·엣지 SoC 내장 | 데이터센터 서버·클라우드 | 온디바이스 vs 클라우드 |
| 주 용도 | 추론(inference) 전용 | 학습(training) + 대규모 추론 | 역할 분담이 핵심 판단축 |
| 정밀도 | INT8/INT4 위주 저정밀 | FP32/FP16/BF16/INT8 등 폭넓음 | 정밀도 폭이 다름 |
| 전력·성능 지표 | TOPS/W(전력당 처리량) 중심 | FLOPS, 처리량(throughput) 중심 | 지표 자체가 다른 목적을 반영 |

> 요약: NPU는 온디바이스 저전력 추론, 데이터센터 GPU/TPU는 학습과 대규모 추론을 담당하는 역할 분담 구조다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 클라우드 추론(GPU/TPU) | 온디바이스 추론(NPU) | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 서버 팜, 고전력·고성능 | SoC 내장, 저전력·제한된 메모리 | 지연·개인정보 요구 수준 |
| 비용/성능 | 대규모 배치 처리 유리 | 배터리·발열 제약 내 실시간 처리 | 실시간성과 오프라인 동작 필요 여부 |
| 운영/위험 | 네트워크 장애 시 서비스 중단 | 양자화로 인한 정확도 손실 | 네트워크 의존성 vs 정확도 손실 허용 범위 |

> 요약: 실시간·오프라인·개인정보 민감 기능은 NPU, 대규모 배치·고정밀 연산은 클라우드 GPU/TPU를 선택한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 정확도 손실 | INT8/INT4 양자화로 인한 표현력 저하 | quantization-aware training, mixed precision 적용 | 양자화 전후 정확도 차이(%p) |
| 파편화 | 제조사별 NPU API·런타임 상이(Core ML, NNAPI 등) | ONNX 등 프레임워크 중립 포맷 활용 | 모델 이식 소요 시간 |
| 열·전력 제약 | 지속 추론 시 발열로 인한 throttling | 추론 배치 주기 조정, 저전력 모드 설계 | 온도, TOPS/W 실측치 |

> 요약: NPU 운영 리스크는 정확도 손실, 플랫폼 파편화, 발열 제약이며 양자화 검증과 표준 포맷으로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 추론 지연 | 목표 응답시간(예: 100ms 이내) 충족 여부 | 온디바이스 벤치마크 |
| 정확도 | 양자화 후 정확도 손실 허용치 이내 | 검증 데이터셋 비교 |
| 전력 효율 | TOPS/W 목표치 달성 | 전력 측정 장비, 벤더 벤치마크 |

> 요약: 도입 성과는 추론 지연, 양자화 후 정확도, TOPS/W 전력 효율로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 실시간·오프라인·개인정보 민감 기능(카메라 보정, 음성인식, on-device 요약)은 NPU 추론 경로로 배치함
2. 대규모 학습과 고정밀 배치 추론은 데이터센터 GPU/TPU에서 수행하고, 양자화된 경량 모델만 NPU로 배포함
3. 제조사별 NPU 파편화에 대응해 ONNX 등 프레임워크 중립 포맷으로 모델을 관리하고 양자화 정확도 손실을 사전 검증함

**결론 (2줄):**
- 기술사 판단: 학습·대규모 배치 추론은 GPU/TPU, 저전력·저지연·오프라인 추론은 NPU라는 역할 분담을 기준으로 아키텍처를 설계함
- 향후 방향: on-device LLM 확대에 따라 NPU의 메모리 대역폭과 INT4/혼합정밀 지원이 강화되는 방향으로 발전함
