## 미리 알고가기

- NPU: 신경망 추론 또는 학습 일부를 전용 데이터패스로 처리하는 프로세서임
- INT8/INT4: 낮은 비트 정밀도로 연산량과 메모리 사용량을 줄이는 표현 방식임
- Graph Partitioning: 모델 그래프를 NPU와 CPU/GPU 실행 구간으로 나누는 과정임
- TOPS: 초당 테라 연산 수로 NPU 성능을 표현할 때 자주 쓰는 지표임

## Ⅰ. 개요

- **정의**: NPU는 신경망의 MAC, 활성화, 정규화, 메모리 이동을 전용 연산 배열과 온칩 메모리로 처리하는 AI 특화 프로세서임. 지연시간, 전력, 지원 연산자, 정밀도를 기준으로 엣지·모바일·서버 AI 추론을 효율화하기 위해 사용함.
- **배경/필요성**: 온디바이스 AI는 네트워크 지연과 개인정보 전송을 줄이면서 제한된 배터리와 열 조건을 만족해야 함. NPU는 CPU보다 낮은 전력으로 신경망 연산을 처리하고 GPU보다 작은 폼팩터에 통합되기 쉬움.
- **비유**: 일반 직원이 모든 일을 처리하는 대신 반복적인 신경망 계산만 맡는 전담 계산팀과 같음.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| AI 전용 프로세서의 구조와 적용 조건 설명 | MAC 배열, 온칩 메모리, 양자화, 런타임 | TOPS 수치만 나열 |

> 요약: NPU는 신경망 연산을 낮은 전력과 짧은 지연으로 실행하도록 설계된 전용 프로세서임.

## Ⅱ. 특징/비교

| 판단 기준 | GPU | NPU |
|:---|:---|:---|
| 실행 목적 | 그래픽과 범용 병렬 연산을 넓게 처리함 | 신경망 연산자와 텐서 흐름에 특화됨 |
| 전력/열 | 고성능 처리량은 높지만 전력 소모가 큼 | 모바일·엣지 환경에서 전력당 추론 성능이 높음 |
| 적용 기준 | 다양한 커널과 학습 워크로드에 적합함 | 고정된 추론 모델, 실시간 응답, 배터리 제약에 적합함 |

> 요약: NPU는 범용성보다 신경망 추론의 전력당 성능과 지연시간을 우선할 때 선택됨.

## Ⅲ. 구성요소

```text
+----------+     +-----------+     +----------+
| AI Model | --> | NPU Driver| --> | NPU Core |
+----------+     +-----------+     +----------+
                                      |
                     +----------------+----------------+
                     v                                 v
              +-------------+                   +-------------+
              | MAC Array   |                   | SRAM/DMA    |
              +-------------+                   +-------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| MAC 배열 | 컨볼루션, 행렬 곱, fully connected 연산을 병렬 수행함 | 계산 작업대 |
| 온칩 SRAM | 가중치와 활성값을 가까운 곳에 저장해 외부 메모리 접근을 줄임 | 부품 선반 |
| DMA/메모리 제어 | 텐서를 NPU 내부와 외부 메모리 사이에 이동시킴 | 물류 담당 |
| 컴파일러/드라이버 | 모델을 지원 연산자로 변환하고 실행 순서를 관리함 | 작업 배정표 |

> 요약: NPU 구조는 전용 연산 배열과 가까운 메모리, 텐서 이동 제어, 소프트웨어 런타임으로 구성됨.

## Ⅳ. 절차

```text
+----------+     +----------+     +----------+     +----------+
| 모델변환 | --> | 그래프분할| --> | NPU실행  | --> | 결과반환 |
+----------+     +----------+     +----------+     +----------+
```

1. **모델 변환**: 학습된 모델을 NPU 런타임 형식으로 변환하고 정밀도를 조정함
2. **그래프 분할**: 지원 연산자는 NPU에 배치하고 미지원 연산자는 CPU/GPU로 분리함
3. **NPU 실행**: 런타임이 텐서 이동과 MAC 연산을 스케줄링해 추론을 수행함
4. **결과 반환**: 후처리와 애플리케이션 로직에 출력 텐서를 전달하고 성능을 기록함

> 요약: NPU 적용은 모델을 지원 연산자 중심으로 변환하고 런타임이 텐서 흐름을 실행하는 과정임.

## Ⅴ. 문제점

- **P1 미지원 연산자 fallback**: NPU가 처리하지 못하는 연산이 CPU로 넘어가면 데이터 이동과 지연이 증가함
- **P2 양자화 정확도 손실**: 낮은 비트 정밀도 적용 시 모델 정확도가 요구 수준 아래로 떨어질 수 있음
- **P3 메모리 대역폭 한계**: 큰 모델과 고해상도 입력은 온칩 메모리를 초과해 외부 메모리 병목을 유발함

> 요약: NPU 운영 문제는 지원 연산자, 정밀도, 메모리 크기가 모델 요구와 맞지 않을 때 발생함.

## Ⅵ. 개선방안

- **P1 대응**: 연산자 호환성 분석, 그래프 rewrite, 런타임 프로파일링으로 fallback 구간을 줄임 (확인: NPU 실행 비율)
- **P2 대응**: 양자화 인지 학습, calibration dataset, mixed precision을 적용함 (확인: 기준 정확도 대비 손실률)
- **P3 대응**: 타일링, 프루닝, 가중치 압축, 메모리 reuse 스케줄을 적용함 (확인: 외부 메모리 대역폭)

> 요약: 개선은 모델 변환 품질과 NPU 자원 배치를 함께 최적화하는 방향으로 수행함.

## Ⅶ. 전망

- **발전 방향**: NPU는 스마트폰, PC, 차량, IoT에서 온디바이스 생성형 AI와 센서 융합 추론을 담당하는 기본 IP로 확산됨
- **기술사적 판단**: NPU 성능은 TOPS보다 실제 모델의 지원 연산자, 메모리, 전력 제한에서 검증해야 함
- **기술사 제언**: 답안에서는 NPU를 AI 전용 하드웨어로 정의하고 양자화와 fallback 문제까지 함께 제시해야 함
