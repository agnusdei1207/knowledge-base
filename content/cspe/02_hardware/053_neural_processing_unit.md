# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 딥러닝 신경망 모델의 연산을 효율적으로 처리하기 위해 설계된 AI 전용 하드웨어 가속기
- **왜 필요한가**: CPU는 순차 처리에, GPU는 그래픽 처리에 범용성이 맞춰져 있어 인공신경망의 고유한 단순·반복·병렬 행렬 연산에 불필요한 전력과 공간을 낭비했다.
- **핵심 직관**: 뇌의 뉴런과 시냅스가 병렬로 연결되어 효율적으로 작동하듯, NPU는 딥러닝 모델의 뉴런(노드) 계층 간 행렬 연산을 전용 칩셋 수준에서 직접 구현하여 극도의 효율을 낸다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| MAC (Multiply-Accumulate) | 곱셈 후 누적 덧셈(A = A + B*C)을 한 번에 처리하는 연산기 | 신경망의 '가중치 × 입력 + 편향' 연산을 처리하는 단위 블록 |
| PE (Processing Element) | MAC 연산기와 로컬 메모리를 포함한 기본 처리 단위 | 딥러닝 연산을 수행하는 공장 작업자 |
| Data Reuse (데이터 재사용) | 온칩 메모리(SRAM)를 활용해 메모리 접근 횟수를 줄이는 기법 | 한 번 가져온 부품을 여러 작업자가 돌려쓰는 것 |
| Dataflow Architecture | 명령어 순서가 아닌 데이터의 흐름과 가용성에 따라 연산이 구동되는 구조 | 컨베이어 벨트 위의 부품 도착에 맞춰 작업이 진행되는 방식 |

## 깊이 이해
- **배경·문제의식**: 스마트폰, IoT 등 엣지 디바이스와 클라우드 서버 모두에서 AI 추론 수요가 급증했다. 배터리와 발열 제약이 큰 환경에서 GPU의 높은 전력 소모는 치명적인 한계(Power Wall)였다.
- **작동 원리**: 수많은 PE가 2차원 배열로 구성되어 있다. 외부 메모리(DRAM)에서 데이터를 한 번 읽어오면, 칩 내부의 데이터 경로(Dataflow)를 따라 이웃한 PE들로 가중치와 입력값을 넘겨주며 반복 연산한다.
- **비유**: GPU가 일반 택배 차량이라면 NPU는 특정 물품(행렬)만 나르는 파이프라인이다. 길(메모리 대역폭)을 여러 번 오가지 않고 한 번 펌프로 밀어 넣어 끝단에서 결과를 얻어낸다.
- **구체 예시**: 스마트폰의 AP(애플 Bionic, 퀄컴 스냅드래곤)에 내장된 NPU는 얼굴 인식, 사진 화질 개선 등 실시간 AI 추론을 밀리와트(mW) 단위의 초저전력으로 수행한다.
- **흔한 오해·주의점**: NPU는 TPU를 포함하는 더 넓은 개념이다. TPU는 구글이 만든 특정 NPU 상표 및 ASIC 모델이며, NPU는 신경망 처리를 위한 모든 전용 하드웨어(IP 블록 포함)를 통칭한다.

## 연결 개념
- AI 가속기 (AI Accelerator)
- SoC (System on Chip)
- Edge AI (온디바이스 AI)

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: NPU(신경망 처리 장치)는 딥러닝 신경망 모델의 핵심인 다차원 행렬 곱셈-누적(MAC) 연산에 최적화된 도메인 특화 아키텍처(DSA) 기반 AI 가속기이다.
> 2. **가치**: 범용 제어 로직을 최소화하고 데이터 재사용성(Data Reuse)을 극대화하여, GPU 대비 전력 소모(Power Wall)와 메모리 병목(Memory Wall) 문제를 효과적으로 해결한다.
> 3. **판단 포인트**: 클라우드 환경에서는 성능과 처리량 확장이 중요하고, 온디바이스(Edge) 환경에서는 극소 면적과 초저전력 구동 등 적용 환경에 따른 최적화 스펙을 평가해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 차세대 하드웨어 발전 방향 이해 | 폰 노이만 구조 한계, 행렬 병렬 연산 특화(MAC 배열) | 폰 노이만 구조를 대체한다고 단정 (가속기로서 공존함) |
| NPU의 아키텍처 특징 설명 | 데이터플로우 구조, 계층적 온칩 메모리, 데이터 재사용 | CPU 멀티코어와 유사한 단순 코어 확장으로 서술 |
| 디바이스 적용 환경별 차이 파악 | 클라우드 NPU(고성능) vs 온디바이스 NPU(저전력, SoC) | 둘의 제약사항(전력, 면적, 메모리) 차이를 무시 |

> 요약: 신경망 연산의 특성인 고도의 데이터 병렬성을 처리하기 위해 제어 복잡성을 낮추고 연산기(PE) 밀도를 높인 하드웨어 최적화 원리를 제시해야 한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 인간의 뇌 신경망(Neuron/Synapse)을 모방한 딥러닝 알고리즘의 대규모 MAC 연산을 하드웨어적으로 구현한 특수 목적 프로세서
- 배경: AI 모델 파라미터 규모가 급증하면서, 기존 폰 노이만 아키텍처 기반의 CPU/GPU로는 메모리 전송 지연과 발열 통제가 한계에 직면함
- 필요성: 모바일, 자율주행 등 전력·면적 제약이 엄격한 환경(SWAP 제약)에서 실시간 추론을 수행하기 위한 극강의 전성비 확보 필수

---

## Ⅱ. 구조 및 구성요소

```text
Host CPU -> NPU Control Unit -> Global Buffer (SRAM)
                                  |
                                  +-> PE Array (MAC 단위 구조)
                                  |     PE <-> PE (Dataflow)
                                  +-> Activation/Pooling Unit
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| PE Array | 다수의 Processing Element(MAC+로컬메모리) 집합 | 2차원 배열 형태로 병렬 연산 수행 |
| Global Buffer | DRAM 접근을 최소화하기 위한 칩 내부 대용량 SRAM | 데이터 재사용(Data Reuse) 핵심 |
| Dataflow Network | PE 간, 또는 버퍼와 PE 간 데이터를 전달하는 인터커넥트 | Weight Stationary 등 데이터 흐름 최적화 |
| Activation Unit | ReLU, Sigmoid 등 비선형 함수 적용 하드웨어 블록 | 행렬 연산 직후 오프로딩 처리 |

> 요약: 거대한 글로벌 버퍼에서 입력/가중치를 읽어 수많은 PE 배열에 분배하고, PE 간 직접 통신으로 메모리 I/O를 우회하는 데이터플로우 구조다.

---

## Ⅲ. 동작원리 및 흐름도

```text
가중치/입력 적재 -> 데이터 라우팅 -> MAC 어레이 병렬 처리 -> 활성화 적용 -> 결과 산출
Off-chip DRAM      Global Buffer   PE Array (Multiply-Add)   Activation Unit
```

- 1단계 [명령/데이터 인출]: CPU가 NPU에 연산 명령을 내리고, 외부 메모리의 모델 가중치를 온칩 버퍼로 로드
- 2단계 [데이터플로우 매핑]: 컴파일러가 최적화한 데이터 경로에 따라 가중치와 입력값을 PE 배열로 라우팅
- 3단계 [병렬 MAC 연산]: 각 PE가 곱셈-누적 연산을 수행하며, 결과를 인접 PE로 전달하여 재사용 극대화
- 4단계 [후처리 및 반환]: 누적된 결과에 활성화 함수 및 풀링(Pooling)을 적용하고 최종 피처맵을 메모리에 기록

> 요약: 메모리 인출은 최소 1회로 제한하고, 연산기 내부망을 통해 데이터를 순환시키며 MAC 연산을 동시다발적으로 처리한다.

---

## Ⅳ. 특징
- 고밀도 연산 효율: 캐시 코히런시, 복잡한 분기 예측 로직을 제거하여 칩 면적의 대부분을 순수 연산기(MAC)로 채움
- 저정밀도 양자화 지원: FP32 대신 FP16, INT8, 심지어 INT4 수준의 양자화(Quantization)를 기본 지원하여 전력 소모 대폭 절감
- 아키텍처 파편화: 표준화된 x86이나 CUDA 모델과 달리 제조사별(애플, 퀄컴, 스타트업 등)로 명령어 세트와 구조가 상이함

> 요약: 특정 연산에 대한 와트당 성능(TOPS/W)은 극도로 높지만, 컴파일러 최적화와 범용 소프트웨어 생태계 성숙도 부족이 장벽이다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | GPU | NPU | 선택 기준 |
|:---|:---|:---|:---|
| 아키텍처 목적 | 범용 병렬 처리 (그래픽+연산) | 도메인 특화 처리 (신경망 연산) | 워크로드 범용성 |
| 메모리 모델 | 대역폭 중심 (GDDR, HBM) | 데이터 재사용 중심 (대규모 온칩 SRAM) | 병목 형태 (대역폭 vs 통신) |
| 도입 환경 | 모델 학습, 대규모 클라우드 | 스마트폰, 자율주행, 실시간 추론 | 전력 제약(TDP) 수준 |

> 요약: 모델 아키텍처가 유동적인 학습(Training) 환경은 GPU가 적합하며, 구조가 고정되고 레이턴시에 민감한 추론(Inference) 환경은 NPU가 최적이다.

**리스크·대응 (기본 불릿):**
- 소프트웨어 스택 성숙도 부족: 하드웨어 성능을 온전히 이끌어낼 NPU 전용 컴파일러 역량 부족 → TVM, ONNX, MLIR 등 범용 중간 표현(IR) 컴파일러 인프라 도입 (지표: 모델 변환 성공률)
- 알고리즘 진화 대응 지연: 트랜스포머(Transformer) 등 새로운 연산 구조 출현 시 하드웨어 최적화 무력화 → 제어 유연성을 더한 CGRA(Coarse-Grained Reconfigurable Architecture) 적용 (지표: 신규 레이어 지원 수)
- 온디바이스 메모리 한계: LLM 같은 거대 모델 탑재 불가 → 모델 양자화(Quantization), 가지치기(Pruning) 적용 및 모바일용 PIM(Processing In Memory) 병행 도입 (지표: 메모리 풋프린트)

**도입 후 점검 지표:**
- 추론 지연시간(Latency): ms (밀리초 단위) — 자율주행 등에서 실시간 처리 기준(예: 30ms 이하) 충족 여부
- 전성비(Energy Efficiency): TOPS/W — 단위 전력당 연산 성능 (배터리 수명 직결)

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 온디바이스 AI 탑재: 모바일 AP 내부의 SoC 블록으로 NPU를 통합 설계하여, 개인정보가 클라우드로 나가지 않는 기기 내 실시간 음성·비전 추론 환경 구축
2. 데이터플로우 맵핑 최적화: 가중치를 PE 내에 고정시키는 Weight Stationary(WS) 방식으로 메모리 접근 전력을 GPU 대비 90% 절감
3. 하이브리드 가속 환경 구축: 데이터센터에서 범용 전처리는 CPU/GPU로, 확정된 거대 모델의 서빙(Serving)은 NPU 블레이드로 오프로딩하여 TCO 최적화

**결론 (2줄):**
- 기술사 판단: NPU 설계의 핵심은 코어 수를 늘리는 것이 아니라, 연산기 사이를 연결하는 데이터 통신 비용(Data Movement Cost)을 얼마나 줄이느냐에 있다.
- 향후 방향: 클라우드형 초대형 NPU(예: 텐스토렌트)와 엣지형 마이크로 NPU로 세분화되며, 장기적으로 인간의 뇌신경 모방을 극한으로 끌어올린 뉴로모픽 반도체(SNN)로 진화할 것이다.
