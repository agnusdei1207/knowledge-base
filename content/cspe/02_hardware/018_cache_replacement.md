## Ⅰ. 개요
- 정의: 캐시가 가득 찼을 때 새로운 데이터를 넣기 위해 기존 데이터 중 무엇을 뺄지 결정하는 전략
- 배경: 한정된 캐시 공간 내에서 미래에 다시 쓰일 가능성이 낮은 데이터를 제거해야 함
- 출제 의도: 지역성(Locality) 원리에 기반한 각 알고리즘의 장단점 및 구현 복잡도 비교

## Ⅱ. 구성요소
- ASCII 구조도
  +------------------+
  |  Cache Set (N-way)|
  | [L0][L1][L2][L3] |
  +--------+---------+
           | (Selection Logic)
           v
  +------------------+
  | Victim Selection |
  | (Based on Policy)|
  +------------------+

- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| LRU | 가장 오랫동안 사용되지 않은 데이터를 교체 | 중고 장터 |
| LFU | 참조 횟수가 가장 적은 데이터를 교체 | 비인기 상품 |
| FIFO | 가장 먼저 들어온 데이터를 교체 | 선착순 퇴장 |
> 요약: 과거의 사용 시점(LRU)이나 빈도(LFU)를 기준으로 미래를 예측함

## Ⅲ. 절차
- ASCII 흐름도
  (Cache Miss) -> (Is Cache Full?) --(Yes)--> (Select Victim via Algorithm)
                                |                  |
                                +-------<----------+
                                v
                (Evict Victim) -> (Load New Data) -> (Update Metadata)

- 4단계 설명
1. 미스 발생: 요청 데이터가 캐시에 없어 메모리에서 가져와야 함을 인식
2. 후보 탐색: 교체 정책에 따라 관리되는 메타데이터(카운터, 스택 등) 확인
3. 희생자 결정: 알고리즘 기준(예: 가장 낮은 카운터 값)에 부합하는 라인 선택
4. 정보 갱신: 새로운 데이터를 적재하고 교체 정책 유지를 위한 메타데이터 업데이트
> 요약: 교체 기준에 따라 희생자를 정하고 새로운 데이터로 교체 후 이력을 갱신함

## Ⅳ. 문제점
- LRU 오버헤드: 데이터 접근 시마다 시간 정보를 갱신해야 하므로 하드웨어 부하 발생
- LFU 초기 집중: 초기에만 많이 쓰인 데이터가 계속 상주하여 새로운 데이터를 방해

## Ⅴ. 개선방안
- (단기) Pseudo-LRU: 비트 트리 등을 활용하여 LRU와 유사한 성능을 저비용으로 구현
- (중기) RRIP (Re-Reference Interval Prediction): 데이터의 재참조 거리를 예측하여 관리
- (장기) ML 기반 교체: 프로그램의 접근 패턴을 학습하여 최적의 희생자를 동적으로 판단

## Ⅵ. 전망
- 로드맵: 고정된 알고리즘 대신 실행 환경에 따라 변하는 적응형(Adaptive) 구조로 발전
- CSF: 대용량 공유 캐시(LLC)에서의 스레드 간 공정성(Fairness)을 고려한 교체 기법 확보
