## Ⅰ. 개요
- **정의**: 멀티프로세서 환경에서 각 코어의 캐시 라인 상태를 4가지로 관리하여 데이터 일관성을 보장하는 프로토콜
- **배경/필요성**: 다중 코어가 동일 메모리 주소를 캐싱하면 갱신 시점 차이로 불일치가 발생하므로, 상태 전이 규칙이 필요함
- **비유**: 여러 사람이 같은 문서 사본을 가지고 있을 때, 누가 편집 중인지 표시하여 최신본을 공유하는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| MESI 4상태 전이와 일관성 보장 원리 | M/E/S/I 각 상태의 의미와 전이 조건 | Exclusive와 Shared의 차이를 명확히 구분할 것 |

> 요약: MESI는 캐시 라인 상태 4종으로 멀티코어 데이터 일관성을 유지하는 프로토콜임

## Ⅱ. 구성요소
```text
        Core 0           Core 1
          |                 |
     +--------+       +--------+
     | Cache  |       | Cache  |
     | (MESI) |       | (MESI) |
     +--------+       +--------+
          |                 |
          +--------+--------+
                   |
              Shared Bus
                   |
            +------------+
            | Main Memory|
            +------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Modified(M) | 해당 캐시만 최신 데이터를 보유하며 메모리와 불일치 상태 | 원본을 혼자 수정하여 아직 공유 안 한 상태 |
| Exclusive(E) | 해당 캐시만 데이터를 보유하며 메모리와 일치하는 상태 | 사본이 하나뿐이고 원본과 동일한 상태 |
| Shared(S) | 둘 이상의 캐시가 동일 데이터를 보유하며 메모리와 일치하는 상태 | 여러 사람이 같은 최신 인쇄본을 들고 있는 상태 |
| Invalid(I) | 캐시 라인이 유효하지 않아 사용 불가한 상태 | 폐기된 구버전 문서 |

> 요약: M/E/S/I 네 상태로 캐시 라인의 소유권과 유효성을 추적함

## Ⅲ. 절차
```text
1. 캐시 미스 발생 / 읽기-쓰기 요청
          |
          v
2. 버스 스누핑으로 타 코어 캐시 상태 확인
          |
          v
3. 상태 전이 규칙 적용
          |
          v
4. 데이터 공급 및 상태 갱신 완료
```
- 1단계: 코어가 읽기 또는 쓰기 요청을 발행하고, 캐시 미스이면 버스 트랜잭션을 생성함
- 2단계: 버스 스누핑을 통해 다른 코어의 캐시가 해당 라인을 보유하는지, 어떤 상태인지 확인함
- 3단계: 읽기 시 타 캐시에 없으면 E, 있으면 S로 전이하고, 쓰기 시 타 캐시를 I로 무효화 후 M으로 전이함
- 4단계: 데이터가 요청 코어에 공급되고, 관련 캐시 라인 상태가 갱신 완료됨

> 요약: 버스 스누핑 기반으로 요청 유형에 따라 상태를 전이하여 일관성을 유지함

## Ⅳ. 문제점
- 버스 대역폭 포화: 코어 수 증가 시 스누핑 트래픽이 공유 버스 대역폭을 초과 — 확장성 한계 발생함
- 쓰기 무효화 오버헤드: 쓰기마다 타 코어 캐시를 I로 전이시키는 브로드캐스트 비용 — 쓰기 빈번 시 지연 증가함
- False Sharing: 서로 다른 변수가 동일 캐시 라인에 위치하면 불필요한 무효화 반복 — 실제 공유 없이도 성능 저하됨

> 요약: 버스 포화·무효화 비용·False Sharing이 MESI 프로토콜의 확장성을 제한함

## Ⅴ. 개선방안
1. 단기: 캐시 라인 패딩으로 False Sharing 방지, 핫 변수를 별도 라인에 배치
2. 중기: MOESI/MESIF 확장 프로토콜 도입으로 Dirty Sharing 허용, 메모리 쓰기백 트래픽 감소
3. 장기: 디렉터리 기반 프로토콜로 전환하여 브로드캐스트 제거, 코어 수 확장에 비례한 대역폭 유지 (020 참조)

> 요약: 라인 패딩·확장 프로토콜·디렉터리 방식으로 단계적 확장성을 확보함

## Ⅵ. 전망
- 발전 방향: CXL(035 참조) 등 이기종 인터커넥트 환경에서 캐시 일관성 범위가 CPU-GPU-가속기로 확장되는 추세임
- 기술사적 판단: 코어 수가 수십 개를 초과하면 스누핑 기반 MESI 단독 운용은 비현실적이며, 계층적 일관성 설계가 필수임
- 기술사 제언: 소프트웨어 수준의 데이터 배치 최적화와 하드웨어 프로토콜을 함께 고려하여 일관성 비용을 최소화할 필요
