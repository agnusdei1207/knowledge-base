## Ⅰ. 개요
- **정의**: PCIe 물리 계층 위에서 CPU·가속기·메모리 간 캐시 일관성과 메모리 공유를 지원하는 개방형 인터커넥트 규격
- **배경/필요성**: GPU·FPGA 등 가속기가 CPU 메모리에 일관성 있게 접근하려면, PCIe의 I/O 모델만으로는 소프트웨어 복사 오버헤드가 발생함
- **비유**: PCIe가 택배(데이터 복사) 방식이라면, CXL은 같은 사무실(공유 메모리)에서 서류를 직접 열람하는 방식

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| CXL 3개 프로토콜 구분과 메모리 풀링 개념 | CXL.io / CXL.cache / CXL.mem 역할 | CXL이 PCIe 대체가 아닌 PCIe 위 상위 프로토콜임을 명시할 것 |

> 요약: CXL은 PCIe 기반으로 캐시 일관성과 메모리 공유를 실현하는 인터커넥트 규격임

## Ⅱ. 구성요소
```text
+-----------+     +-----------+     +-------------+
|   CPU     |     | Accelerator|    | Memory      |
|           |     | (GPU/FPGA)|    | Expander    |
+-----+-----+     +-----+-----+    +------+------+
      |                 |                  |
      +--------+--------+---------+--------+
               |                  |
          CXL.cache          CXL.mem
          CXL.io
               |
        PCIe PHY Layer
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| CXL.io | PCIe와 동일한 I/O 프로토콜로 디바이스 발견·설정·DMA를 수행함 | 택배 배송(기존 I/O 방식) |
| CXL.cache | 디바이스가 호스트 CPU 메모리를 캐시 일관성 있게 접근하는 프로토콜 | 가속기가 CPU 책상 위 서류를 직접 열람하는 것 |
| CXL.mem | 호스트 CPU가 디바이스 부착 메모리를 로드/스토어로 접근하는 프로토콜 | CPU가 외부 서랍장을 자기 책상처럼 사용하는 것 |
| CXL 스위치 | 다수 디바이스와 호스트를 연결하여 메모리 풀링과 패브릭을 구성하는 네트워크 요소 | 여러 방을 연결하는 복도와 출입문 |

> 요약: CXL.io·CXL.cache·CXL.mem 세 프로토콜과 스위치가 이기종 자원을 통합함

## Ⅲ. 절차
```text
1. 디바이스 열거 및 CXL 유형 식별
          |
          v
2. CXL.io로 초기화 및 BAR 할당
          |
          v
3. CXL.cache / CXL.mem 링크 활성화
          |
          v
4. 캐시 일관성 유지하며 메모리 공유 운용
```
- 1단계: 부팅 시 PCIe 열거 과정에서 CXL 디바이스를 식별하고, Type 1/2/3 유형을 판별함
- 2단계: CXL.io를 통해 디바이스를 초기화하고, 메모리 영역(BAR/HDM)을 할당함
- 3단계: 유형에 따라 CXL.cache(Type 2), CXL.mem(Type 3) 프로토콜 링크를 활성화함
- 4단계: 호스트와 디바이스가 캐시 일관성을 유지하며 공유 메모리 영역을 로드/스토어로 접근함

> 요약: PCIe 열거 → 초기화 → 프로토콜 활성화 → 일관성 기반 메모리 공유 순서로 동작함

## Ⅳ. 문제점
- 메모리 접근 지연 불균일: CXL 부착 메모리는 로컬 DRAM 대비 추가 링크 지연이 존재 — NUMA 유사 성능 편차 발생함
- 보안 격리 복잡성: 다수 호스트가 메모리 풀을 공유하면 접근 권한 경계 관리가 복잡 — 데이터 유출 위험 증가함
- 생태계 미성숙: CXL 3.x 스위치·팹릭 장비의 상용화 초기 단계 — 호환성 검증 부담이 큼

> 요약: 지연 불균일·보안 격리·생태계 미성숙이 CXL 확산의 주요 과제임

## Ⅴ. 개선방안
1. 단기: OS 수준 NUMA 정책(티어드 메모리)으로 핫 데이터를 로컬 DRAM에 배치, CXL 메모리는 콜드 데이터 전용으로 운용
2. 중기: CXL IDE(Integrity and Data Encryption) 기능으로 링크 구간 암호화 적용, 풀 내 접근 권한을 하드웨어 수준에서 격리
3. 장기: CXL 컨소시엄 주도 CTS(Compliance Test Suite) 확대 및 다중 벤더 상호운용성 검증 체계 확립

> 요약: 티어드 메모리·링크 암호화·상호운용성 검증으로 CXL 도입 장벽을 낮춤

## Ⅵ. 전망
- 발전 방향: CXL 3.x 패브릭을 통한 랙 스케일 메모리 풀링이 데이터센터 메모리 활용률을 높이는 핵심 기술로 부상함
- 기술사적 판단: CPU-가속기-메모리 간 일관성 도메인 통합은 이기종 컴퓨팅 아키텍처의 필수 기반임
- 기술사 제언: CXL 메모리 티어링 정책과 기존 NUMA 최적화를 통합 설계하여 워크로드별 지연·대역폭 요구를 충족할 필요
