## 미리 알고가기

- 캐시 쓰기 정책은 수정 데이터를 언제 메모리에 반영할지 정하는 규칙임
- Write-Through는 즉시 반영, Write-Back은 교체 시 반영 구조임
- 더티 비트(Dirty Bit): 캐시 라인이 메모리보다 최신 값으로 수정되어 아직 반영되지 않았음을 표시하는 상태 비트임
- 쓰기 버퍼(Write Buffer): 메모리 쓰기 요청을 임시로 쌓아 CPU가 완료를 기다리지 않고 다음 명령을 진행하게 하는 대기 공간임
- Write Miss: 쓰기 대상 주소의 데이터가 캐시에 없어 캐시 라인을 먼저 채워야 하는 상황임
- 플러시(Flush): 더티 라인의 값을 메모리에 강제로 반영해 캐시와 메모리 값을 맞추는 동작임

## 작성 근거(검토용)

- 쓰기 정책을 빠름·느림이 아니라 메모리 반영 시점·더티 비트·쓰기 버퍼·교체 동작으로 설명함
- Write-Through와 Write-Back을 반영 시점·메모리 트래픽·장애·DMA 조건으로 비교함
- 두 정책의 쓰기 요청과 메모리 반영 경로를 별도 흐름으로 분리함

## Ⅰ. 개요

- **정의/개념**: 캐시 쓰기 정책은 CPU가 캐시에 데이터를 갱신할 때 변경된 내용을 메모리에 즉시 반영할지, 캐시에만 유지하다가 추후 교체 시점에 반영할지 결정하는 캐시 제어 규칙임
- **배경/필요성**: 캐시와 메모리의 최신성·쓰기 지연·트래픽을 조절하기 위해 데이터 반영 시점 규칙이 필요함

### 쉽게 이해하기 (학습용)
- 메모지에 적은 수정 내용을 원본 서류철에 바로 옮겨 적을지, 나중에 한꺼번에 옮길지 정하는 규칙과 같음

## Ⅱ. 특징

- Write-Through는 캐시 쓰기마다 메모리 쓰기도 요청해 두 계층의 값을 함께 갱신함
- Write-Back은 같은 라인의 반복 쓰기를 모아 메모리 트래픽을 줄임
- Write-Back은 더티 비트와 교체 관리가 필수임
- write miss 처리와 DMA 일관성 요구에 따라 정책 적합성이 달라짐

### 쉽게 이해하기 (학습용)
- Write-Through는 메모할 때마다 바로 원본에도 옮겨 적어 항상 최신 상태를 유지함
- Write-Back은 메모지에 여러 번 고쳐 쓴 뒤 치울 때 한 번만 원본에 옮겨 손이 덜 감
- 대신 어떤 메모지가 아직 안 옮겨졌는지 딱지(더티 비트)로 표시해둬야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | Write-Through | Write-Back |
|:---|:---|:---|
| 메모리 반영 시점 | 캐시 쓰기 즉시 메모리에도 반영함 | 캐시에서 갱신하고 더티 비트로 표시한 뒤 교체 시점에 반영함 |
| 메모리 트래픽 | 캐시 쓰기마다 발생함 | 같은 라인의 반복 쓰기를 교체 시 한 번에 반영해 줄어듦 |
| 장애·DMA 조건 | 쓰기 버퍼의 완료 상태만 확인함 | 플러시로 캐시와 메모리 값을 맞춘 뒤 접근해야 함 |

> 요약: Write-Through는 캐시와 메모리에 동시에 기록하고, Write-Back은 수정 라인이 교체될 때 메모리에 반영함.

### 쉽게 이해하기 (학습용)
- Write-Through는 적을 때마다 바로 원본도 고치고, Write-Back은 메모지를 치울 때만 원본을 고침

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 캐시 라인 | 수정 대상 데이터가 저장되는 기본 단위임 |
| 더티 비트 | Write-Back에서 메모리에 반영되지 않은 변경 여부를 표시함 |
| 쓰기 버퍼 | Write-Through 요청을 보관하고 메모리 쓰기 지연 동안 CPU 진행을 지원함 |
| 교체 로직 | Write-Back 캐시 라인을 교체할 때 메모리 반영 여부를 결정함 |

```text
+------------+     +-----------+     +--------------+
| 캐시 라인   | --> | 더티 비트  | --> | 교체 로직      |
+------------+     +-----------+     +--------------+
      |
      v
+--------------+
| 쓰기 버퍼     |
+--------------+
```

> 요약: 더티 비트·쓰기 버퍼·교체 로직이 메모리 반영 시점과 쓰기 대기를 제어함.

### 쉽게 이해하기 (학습용)
- 메모지(캐시 라인)에 안 옮겼다는 딱지(더티 비트)를 붙이고, 옮겨적기 요청은 대기 명단(쓰기 버퍼)에 쌓아둠
- 메모지를 치울 때(교체 로직) 원본에 옮길지 결정함

## Ⅴ. 원리 및 절차 흐름도

```text
[Write-Through] 쓰기 요청 -> 캐시 갱신 -> 쓰기 버퍼 -> 메모리 반영
[Write-Back]    쓰기 요청 -> 캐시 갱신·더티 비트 설정 -> 라인 교체 -> 메모리 반영
```

1. **Write-Through**: 캐시 라인을 갱신하고 쓰기 버퍼를 거쳐 메모리에도 쓰기를 전달함
2. **Write-Back**: 캐시 라인만 갱신하고 더티 비트로 표시한 뒤 해당 라인이 교체될 때 메모리에 기록함

> 요약: Write-Through는 쓰기마다 메모리에 반영하고, Write-Back은 더티 라인의 교체 시점에 반영함.

### 쉽게 이해하기 (학습용)
- Write-Through는 메모하자마자 대기 명단을 거쳐 바로 원본에 옮기고, Write-Back은 딱지만 붙였다가 메모지를 치우는 순간 원본에 옮김

## Ⅵ. 실무 사례

1. Write-Through 캐시는 쓰기 버퍼에서 연속 요청을 병합하고, 버퍼 포화율과 메모리 쓰기 트래픽을 확인함
2. DMA 장치와 Write-Back 캐시를 함께 사용하는 시스템은 캐시 플러시를 적용하고, 오래된 값 읽기 건수와 플러시 지연을 확인함

### 쉽게 이해하기 (학습용)
- 연속으로 고쳐 쓴 메모는 대기 명단에서 한 번에 정리해 옮기는 양을 줄임
- 다른 사람(DMA 장치)이 원본을 보기 전에는 딱지 붙은 메모부터 먼저 옮겨 최신 상태를 맞춤

## Ⅶ. 결론

- 캐시 쓰기 정책은 수정 데이터를 메모리에 즉시 반영할지 교체 시점까지 모아 반영할지를 정하는 규칙으로, 반영 시점에 따라 최신성과 메모리 트래픽이 상충됨
- 반복 쓰기 비중과 DMA·장애 시 플러시 조건을 기준으로 Write-Through와 Write-Back을 선택해야 함

### 쉽게 이해하기 (학습용)
- 얼마나 자주 고쳐 쓰는지와 원본을 누가 언제 보는지에 따라 즉시 옮길지 모아서 옮길지를 고름
