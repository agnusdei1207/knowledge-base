## Ⅰ. 개요
- **정의**: CPU가 캐시에 데이터를 기록할 때 메인 메모리 갱신 시점을 결정하는 정책임
- **배경/필요성**: 캐시와 메모리 간 쓰기 데이터의 일관성을 유지하면서 버스 대역폭 소모를 최소화해야 하므로 쓰기 시점 정책이 필요함
- **비유**: 수첩에 메모할 때 매번 원본 노트에도 옮겨 적는 것(WT)과, 수첩 페이지를 넘길 때만 한꺼번에 정리하는 것(WB)의 차이임

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| WT·WB 구조 차이와 적용 상황 판단 | Dirty Bit 유무, 버스 트래픽 차이 | Write Miss 시 Write-Allocate/No-Write-Allocate 조합 설명 필요 |

> 요약: 캐시 쓰기 시 메모리 반영 시점을 WT(즉시)와 WB(지연)로 구분하는 정책임

## Ⅱ. 구성요소
```text
        CPU 쓰기 요청
             |
     +-------+-------+
     |               |
  Write-Through    Write-Back
     |               |
  캐시+메모리       캐시만 갱신
  동시 갱신        (Dirty Bit=1)
     |               |
  버스 즉시사용    축출 시 메모리 반영
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Write-Through(WT) | 캐시 기록과 동시에 메모리에도 기록하여 항상 일관성 유지 | 칠판에 쓰면서 교무수첩에도 즉시 기록 |
| Write-Back(WB) | 캐시에만 기록하고 축출 시 메모리에 반영, Dirty Bit로 수정 여부 추적 | 수첩에만 적고 페이지 넘길 때 정리 |
| Dirty Bit | WB에서 해당 캐시 라인이 수정되었는지 표시하는 1비트 플래그 | 수첩 페이지의 수정 표시 스티커 |
| Write Buffer | WT의 메모리 쓰기 지연을 완화하기 위한 FIFO 버퍼 | 우체통 — 모아서 일괄 발송 |

> 요약: WT는 즉시 반영으로 일관성 확보, WB는 Dirty Bit 기반 지연 반영으로 대역폭 절감함

## Ⅲ. 절차
```text
  쓰기요청          적중판정          정책적용          메모리반영
  (Write Req)      (Hit/Miss)       (Policy)         (Mem Update)
   |                 |                 |                 |
   +--주소비교----->+--WT/WB분기---->+--시점결정----->+
  CPU발행          태그매치확인     WT:즉시/WB:지연   WT:매번/WB:축출시
```
- 1단계: CPU가 쓰기 요청을 발행하고 캐시에 주소를 전달함
- 2단계: 태그 비교를 통해 캐시 적중(Write Hit) 또는 미스(Write Miss)를 판정함
- 3단계: 적중 시 WT는 캐시와 메모리에 동시 기록하고, WB는 캐시만 갱신 후 Dirty Bit를 설정함
- 4단계: 미스 시 Write-Allocate(블록 적재 후 캐시 기록) 또는 No-Write-Allocate(메모리에 직접 기록)를 수행함

> 요약: 쓰기 요청 → 적중 판정 → 정책 분기 → 메모리 반영/할당의 4단계로 처리됨

## Ⅳ. 문제점
- 버스 대역폭 소모(WT): 모든 쓰기가 메모리 버스를 사용하므로 쓰기 빈도가 높은 워크로드에서 병목 발생 — 멀티코어 환경에서 버스 포화 가능
- 일관성 복잡도(WB): 캐시와 메모리 값이 불일치하는 구간 존재 — 멀티프로세서에서 캐시 일관성 프로토콜(019 참조) 필수
- 축출 시 지연(WB): Dirty 라인 축출 시 메모리 쓰기가 선행되어야 하므로 미스 페널티 증가 — 연속 축출 시 스톨 발생

> 요약: WT의 대역폭 낭비, WB의 일관성 복잡도·축출 지연이 주요 한계임

## Ⅴ. 개선방안
1. 단기: Write Buffer 도입(4~8 엔트리)으로 WT의 메모리 쓰기 지연을 CPU와 비동기화하여 버스 병목 완화
2. 중기: WB + MESI 프로토콜(019 참조) 결합으로 일관성 복잡도를 하드웨어 수준에서 자동 관리
3. 장기: Victim Cache·Write Coalescing Buffer 적용으로 Dirty 라인 축출 시 연속 쓰기를 병합하여 미스 페널티 감소

> 요약: Write Buffer, 일관성 프로토콜 결합, 쓰기 병합으로 단계적 개선함

## Ⅵ. 전망
- 발전 방향: 비휘발성 메모리(NVRAM) 환경에서 WB 정책의 영속성 보장 문제 해결을 위한 Persistent Write-Back 연구가 확산 중임
- 기술사적 판단: 워크로드의 읽기/쓰기 비율과 멀티코어 구성에 따라 WT·WB를 계층별로 차등 적용하는 설계 역량이 필요함
- 기술사 제언: L1은 WB로 지연 최소화, L2/L3는 일관성 프로토콜과 연계한 WB를 기본으로 설계할 것을 제언함
