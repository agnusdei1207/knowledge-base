## Ⅰ. 개요
- 정의: 최근에 참조된 페이지 테이블 항목을 저장하는 특수 고속 하드웨어 캐시
- 배경: 가상 주소 변환 시 메모리 내 페이지 테이블에 두 번 접근하는 성능 저하 해결
- 출제 의도
| 구분 | 내용 |
| --- | --- |
| 핵심 | 주소 변환 가속, 연관 메모리(Associative Memory), Hit Ratio |

## Ⅱ. 구성요소
```
[ CPU ] -> [ TLB ] --(Hit)--> [ Physical Addr ]
             |
          (Miss) -> [ Page Table in RAM ]
```
| 구성요소 | 설명 | 비유 |
| --- | --- | --- |
| 태그(Tag) | 가상 페이지 번호(VPN)를 저장하여 비교 대상으로 사용 | 이름표 |
| 데이터(Data) | 실제 물리 프레임 번호(PFN) 및 상태 정보 포함 | 실제 주소 |
| 유효 비트 | 해당 엔트리가 현재 유효한지 나타내는 지시자 | 유효 도장 |
> 요약: CPU 근처에 위치한 고속 SRAM 기반 버퍼로 주소 변환 시간을 획기적으로 단축함

## Ⅲ. 절차
1. 주소 참조: CPU가 가상 주소 발생 시 TLB 내 VPN 존재 여부 확인
2. TLB 조회: 하드웨어가 병렬적으로 모든 엔트리를 검색(Parallel Search)
3. TLB Hit: 일치하는 항목 발견 시 즉시 물리 주소 생성 및 데이터 접근
4. TLB Miss: 실패 시 RAM의 페이지 테이블 참조 및 TLB에 결과 업데이트
> 요약: 높은 지역성(Locality)을 기반으로 대부분의 주소 변환을 TLB 내부에서 처리함

## Ⅳ. 문제점
- 컨텍스트 스위칭 발생 시 이전 프로세스의 TLB 정보가 무효화되어 성능이 급감함

## Ⅴ. 개선방안
- ASID(Address Space Identifier)를 도입하여 프로세스별 TLB 구분 및 유지함

## Ⅵ. 전망
- 가상화 환경 가속을 위한 2단계 주소 변환용 TLB(Shadow TLB) 하드웨어 지원이 강화됨
- 기계 학습 기반의 프리페칭(Prefetching)을 통한 TLB Miss 최소화 기술이 CSF로 대두됨
