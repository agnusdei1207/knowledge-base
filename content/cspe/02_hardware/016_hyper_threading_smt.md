## Ⅰ. 개요
- **정의**: 하나의 물리 코어가 복수의 논리 스레드를 동시에 실행하는 기술임
- **배경/필요성**: 파이프라인 버블·캐시 미스 대기 시 유휴 실행 유닛이 낭비되므로, 유휴 자원을 다른 스레드에 할당하여 처리량을 높일 필요가 있음
- **비유**: 요리사 한 명이 파스타 물 끓는 동안 샐러드를 준비하는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 논리 코어와 물리 코어 구분 이해 | 실행 유닛 공유 구조와 IPC 향상 원리 | CMP(멀티코어)와 혼동 금지, 보안 부채널 문제 언급 필요 |

> 요약: 유휴 실행 유닛을 다른 스레드에 할당해 처리량을 높이는 하드웨어 기법임

## Ⅱ. 구성요소
```text
        +--- 물리 코어 ---+
        |                  |
  +-----+------+    +-----+------+
  | 논리스레드0 |    | 논리스레드1 |
  | (고유 PC,  |    | (고유 PC,  |
  |  레지스터) |    |  레지스터) |
  +-----+------+    +-----+------+
        |                  |
        +----> 공유 자원 <----+
          ALU / FPU / 캐시
          분기예측기 / TLB
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 아키텍처 상태(AS) | 스레드별 독립 PC·레지스터 세트 | 요리사별 개인 레시피 메모 |
| 실행 유닛(EU) | ALU·FPU 등 연산 자원, 스레드 간 공유 | 공용 주방 도구 |
| 스레드 스케줄러 | 매 사이클 유휴 EU에 대기 명령어 배정 | 주방장이 빈 도구에 작업 할당 |
| 공유 캐시·TLB | L1/L2 캐시와 TLB를 스레드가 분할 사용 | 냉장고 칸을 나눠 쓰는 구조 |

> 요약: 아키텍처 상태만 복제하고 실행 유닛은 공유하여 트랜지스터 증가 5% 이내로 처리량을 높임

## Ⅲ. 절차
```text
  명령어인출      디코드/배정     실행            커밋
  (Fetch)        (Dispatch)     (Execute)       (Commit)
   |               |               |               |
   +--스레드선택-->+--유휴EU탐색-->+--결과생성---->+
  스레드0/1교대   이슈큐삽입     공유ALU/FPU    ROB기록
```
- 1단계: 인출 — 라운드로빈 또는 우선순위 기반으로 스레드 0/1의 명령어를 번갈아 가져옴
- 2단계: 디코드/배정 — 명령어를 마이크로옵으로 분해하고, 이슈 큐에 삽입함
- 3단계: 실행 — 유휴 상태인 ALU·FPU에 대기 마이크로옵을 배정하여 연산 수행함
- 4단계: 커밋 — 실행 완료된 결과를 스레드별 재정렬 버퍼(ROB)에 기록하고 아키텍처 상태에 반영함

> 요약: 매 사이클 유휴 실행 유닛에 다른 스레드 명령어를 채워 파이프라인 이용률을 높이는 흐름임

## Ⅳ. 문제점
- 캐시 경합: 두 스레드가 L1/L2를 공유하므로 워킹셋이 크면 캐시 미스율이 증가함 — 단일 스레드 대비 오히려 성능 저하 가능
- 부채널 공격: 공유 캐시 타이밍을 관측하여 다른 스레드의 데이터를 추론 가능함 — Spectre 계열 취약점의 공격 표면 확대
- 전력·열 증가: 유휴 유닛 활용으로 동시 스위칭 트랜지스터가 늘어남 — 열 밀도 상승으로 스로틀링 유발 가능

> 요약: 캐시 경합, 보안 부채널, 전력 증가가 SMT의 주요 한계임

## Ⅴ. 개선방안
1. 단기: 캐시 파티셔닝(Way Partitioning) 적용으로 스레드 간 캐시 경합 완화
2. 중기: 마이크로코드 수준 격리 및 하드웨어 가드(코어 스케줄링) 도입으로 부채널 공격 표면 축소
3. 장기: 이종 코어 구조(big.LITTLE)와 결합하여 부하 특성별 SMT 활성/비활성 동적 제어로 전력 최적화

> 요약: 캐시 분리, 보안 격리, 이종 코어 연계를 통해 SMT의 한계를 단계적으로 해소함

## Ⅵ. 전망
- 발전 방향: 코어당 논리 스레드 수가 4~8개로 확장되고, AI 워크로드에 특화된 SMT 스케줄링 정책이 등장할 전망임
- 기술사적 판단: 보안과 성능의 트레이드오프를 정량적으로 분석하여 워크로드별 SMT 활성화 정책을 수립하는 역량이 필요함
- 기술사 제언: 서버 환경에서는 보안 격리 기반 SMT, 클라이언트 환경에서는 전력 효율 기반 SMT 전략을 구분 적용할 것을 제언함
