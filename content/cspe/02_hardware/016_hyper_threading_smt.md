# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 동시 멀티스레딩(SMT)은 하나의 물리 코어 안에 스레드 문맥(PC·레지스터)만 2벌 이상 복제해 두고, 매 클럭 여러 스레드의 명령어를 섞어 공유 실행 유닛에 동시 배분하는 스레드 병렬 처리 기술임(인텔 상표명이 하이퍼스레딩).
- **왜 필요한가**: 단일 스레드는 캐시 미스·의존성으로 실행 유닛을 다 못 채워 평균 40~50%가 놀므로, 그 빈 슬롯을 독립 스레드 명령어로 메워 코어 가동률을 끌어올리기 위해 필요함.
- **핵심 직관**: 화구 4개짜리 가스레인지에서 요리 1개(단일 스레드)만 하면 2개가 논다. 주문을 2개(2 스레드) 동시에 받아 남는 화구에 다른 요리를 채워 가동률을 높이는 방식임.

## 핵심 용어 정리 (내부에 등장하는 것들)

먼저 답안에 나오는 용어를 비유와 함께 풀어 둔다. 최상위 키워드는 SMT다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| SMT | 물리 코어 1개가 다수 스레드 명령어를 같은 클럭에 섞어 실행하는 기술 | "화구 공유하며 요리 2개 동시" |
| 물리 코어 (Physical Core) | 실제 ALU·FPU·캐시를 가진 반도체 연산 코어 | "실제 요리사와 화구 세트" |
| 논리 코어 (Logical Core) | OS가 CPU로 인식하는 단위. SMT 켜면 물리 코어당 2개로 노출 | "주문 접수처 2곳" |
| 스레드 문맥 (Architectural State) | 스레드 고유 상태(PC·범용 레지스터). SMT는 이것만 복제 | "레시피·도마만 2벌" |
| 파이프라인 버블 (Bubble) | 의존성·미스로 실행 유닛이 연산 못 하고 노는 빈 슬롯 | "물 끓을 때까지 노는 화구" |
| TLP (스레드 수준 병렬성) | 여러 스레드를 동시 실행하는 병렬성(013·014 참조) | ILP 상위 병렬성 |
| IPC (Instructions Per Clock) | 한 클럭에 완료되는 평균 명령어 수, 가동률 척도 | IPC 2 = 1클럭 2개 완료 |

## 깊이 이해
- **배경·문제의식**: 비순서 실행(012)·멀티코어(014)로도 단일 스레드 내 ILP 한계(013 참조) 때문에 실행 유닛 평균 40~50%가 유휴 상태로 남았음. 이 유휴 슬롯(수직·수평 낭비)을 어떻게 채울지가 SMT의 출발점임.
- **작동 원리(어떻게+왜)**: 덩치 큰 실행 유닛(ALU·FPU)과 캐시는 1세트만 두고, 명령어를 담는 문맥(PC·레지스터)만 2벌로 복제함. OS는 논리 코어 2개로 인식해 스레드 2개를 할당하고, 하드웨어 스케줄러가 매 클럭 두 스레드 명령어를 섞어 빈 유닛에 끼워 넣음. 문맥만 복제하므로 추가 면적이 다이의 약 5%로 작음.
- **비유**: 2차선 도로(실행 유닛)를 버스 1대(스레드1)가 혼자 쓰면 옆 차선이 빈다. 승용차(스레드2)를 진입시켜 두 차선을 모두 채워 달리게 함.
- **구체 예시**: 스레드 A가 메모리 로드로 100클럭 스톨하면, 예전에는 코어 전체가 멈췄음. SMT에서는 즉시 스레드 B의 ALU 명령어를 빈 유닛에 실행해 파이프라인을 멈추지 않음. 전형적 스루풋 향상은 15~30%임.
- **흔한 오해**: 4코어 8스레드가 8코어급 2배 성능이라는 건 오해임. 실행 유닛을 공유하므로 향상은 15~30% 선이고, 두 스레드가 같은 유닛(FPU)이나 L1을 두고 경합하면 오히려 단일 스레드보다 느려지는 역전(캐시 쓰래싱)도 발생함.

## 연결 개념
- **013 ILP / 014 멀티코어**: SMT는 ILP가 남긴 유휴 자원을 TLP로 채우는 브릿지 기술임.
- **019 캐시 일관성 / 캐시 쓰래싱**: 두 스레드가 L1을 공유해 서로 데이터를 밀어내는 부작용의 배경임.
- **부채널 공격(Spectre)**: 분기 예측기·L1 공유가 스레드 간 정보 유출 경로가 됨.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: SMT는 단일 물리 코어 내 스레드 문맥을 복제해 매 클럭 다수 스레드 명령어를 공유 실행 유닛에 동시 배분하는 마이크로아키텍처 기술임.
> 2. **가치**: 캐시 미스·의존성으로 비는 파이프라인 버블을 독립 스레드 명령어로 채워, 약 5% 면적 추가로 코어 가동률을 15~30% 높임.
> 3. **판단**: 실행 유닛·L1/L2를 공유하므로 스루풋은 오르나 자원 경합·캐시 오염으로 단일 스레드 지연(Latency)은 악화될 수 있음.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 유휴 실행 유닛 극복 원리 이해 | 문맥(PC·레지스터) 복제, 실행 유닛·캐시 공유 | SMT를 물리 코어 복제(멀티코어)로 혼동 |
| SMT 성능 트레이드오프 파악 | 스루풋 상승 vs 단일 스레드 지연 악화 | 코어 2배분 성능 향상 단정 |

> 요약: SMT는 코어를 복제한 것이 아니라 문맥 대기열만 늘려 노는 실행 유닛을 채우는 최적화임을 명시해야 함.

---

## Ⅰ. 개요 및 필요성

- 개요: SMT는 물리 코어 1개에 다수 스레드 문맥을 복제하고 매 클럭 여러 스레드 명령어를 혼합 실행하는 아키텍처임.
- 배경: 비순서 실행 코어의 명령어 윈도우 한계와 메모리 지연(Memory Wall)으로 실행 유닛 유휴 슬롯이 상시 발생함.
- 필요성: 코어를 물리적으로 2배 늘리지 않고 약 5% 면적 추가만으로 TLP 처리량을 15~30% 확보하기 위해 필요함.

---

## Ⅱ. 구조 및 구성요소

```text
스레드0 문맥(PC·Reg) / 스레드1 문맥(PC·Reg)
  -> 공유 명령어 스케줄러(RS·ROB, 두 스레드 명령어 혼합)
  -> 공유 실행 유닛(ALU·FPU, 빈 슬롯에 동시 배분)
  -> 공유 L1/L2 캐시
```

| 구성요소 | 분리/공유 | 역할 |
|:---|:---|:---|
| 스레드 문맥(PC·레지스터) | 스레드별 복제 | 각 스레드 고유 상태 유지, 논리 코어로 노출 |
| 예약소(RS)·ROB | 파티셔닝/공유 | 두 스레드 명령어를 섞어 비순서 스케줄링 |
| 실행 유닛(ALU·FPU) | 완전 공유 | 혼합된 명령어를 실제 연산, 유휴 슬롯 최소화 |
| L1/L2 캐시 | 완전 공유 | 두 스레드 데이터 공존, 용량 압박(쓰래싱) 유발 |

> 요약: 작은 문맥은 2벌로 복제해 독립성을 주고, 덩치 큰 연산기·캐시는 1개를 공유해 면적 대비 효율을 얻는 구조임.

---

## Ⅲ. 동작원리 및 흐름도

```text
OS 논리 코어 인식 -> 스레드별 명령어 인출 -> 공유 윈도우 혼합 스케줄링 -> 유휴 실행 유닛 동시 점유·커밋
```

- 1단계 [문맥 인출]: OS가 논리 코어 2개로 인식해 스레드 A·B를 할당하고, 하드웨어가 두 PC에서 번갈아 명령어를 인출함.
- 2단계 [의존성 해체]: 스레드별 독립 레지스터 리네이밍으로 스레드 간 충돌 없이 공유 예약소(RS)에 진입함.
- 3단계 [혼합 이슈]: 스레드 A가 캐시 미스로 로드 유닛에 정체되면, 스케줄러가 스레드 B의 ALU 명령어를 빈 유닛에 배분함.
- 4단계 [실행·커밋]: 서로 다른 스레드 명령어가 같은 클럭에 병렬 연산되고, 각자의 ROB 포인터로 독립 커밋됨.

> 요약: 두 스레드 명령어를 하나의 스케줄링 풀에 부어 유닛이 비는 곳마다 채워 넣는 동적 스케줄링임.

---

## Ⅳ. 특징
- 가동률 극대화: 단일 스레드의 수직·수평 낭비 슬롯을 타 스레드 연산으로 은닉해 실행 유닛 활용률을 높임.
- 낮은 면적 비용: 문맥 복제에 필요한 실리콘이 다이의 약 5%에 불과하나 스루풋은 평균 15~30% 향상됨.
- 자원 경합 리스크: 두 스레드가 동일 유닛(FPU)이나 L1을 집중 요구하면 스톨이 가중되어 단일 스레드보다 느려지는 역전 발생함.

> 요약: 트랜지스터 대비 효율이 높은 병렬화이나, 물리 코어 증설 같은 선형 성능 향상은 구조적으로 불가함.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 멀티코어(CMP) | SMT | 선택 기준 |
|:---|:---|:---|:---|
| 병렬화 방식 | 물리 코어 물리적 분리 | 문맥 복제·실행 유닛 공유 | 면적·전력 예산 |
| 자원 간섭 | L3 외 독립(간섭 적음) | 실행 유닛·L1/L2 전반 공유 | 성능 일관성(QoS) 요구 |
| 성능 증가폭 | 코어 수 비례(암달 법칙 내) | 평균 15~30%(자원 한계 종속) | 워크로드 스레드 성향 |

> 요약: 멀티코어는 면적을 2배로 늘려 확실한 처리량을 얻고, SMT는 남는 자원을 채워 면적 대비 스루풋을 얻는 기법임.

**리스크·대응 (기본은 불릿):**
- 캐시 쓰래싱 리스크 — 원인: 두 스레드의 L1 상호 밀어내기 — 대응: OS 스케줄러 코어 어피니티 분리 또는 BIOS에서 SMT 비활성화(지표: 스레드 믹스 캐시 미스율).
- 부채널 유출 리스크 — 원인: L1·분기 예측기 공유로 Spectre류 노출 — 대응: 클라우드에서 코어 단위 격리·캐시 파티셔닝(Intel CAT) 강제(지표: 코어 격리 보장율).

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 엔터프라이즈 RDBMS: I/O 대기가 잦고 트랜잭션이 많은 DB 서버는 SMT를 활성화해 트랜잭션 스루풋을 극대화함.
2. 클라우드 vCPU 매핑: AWS·GCP 등은 물리 코어의 SMT 스레드 각각을 vCPU 1개로 판매해 서버 밀도·활용률을 높임.
3. HFT·HPC 튜닝: 응답 지연 편차가 없어야 하는 금융 고빈도 매매나 HPC는 역으로 SMT를 비활성화해 L1을 단일 스레드가 독점하게 함.

**결론 (2줄):**
- 기술사 판단: 처리량이 핵심인 서버·클라우드면 SMT 활성화가 유리하고, 지연 일관성·보안 격리가 핵심인 HFT·멀티테넌트면 SMT 비활성화 또는 코어 격리를 선택해야 함.
- 향후 방향: 스레드만 섞는 SMT를 넘어 코어 내부 자원(L2·대역폭)을 하드웨어로 파티셔닝하는 QoS 기술(Intel RDT)이 필수 결합되는 추세임.

| 유형 | 문제 신호어 | Ⅱ·Ⅲ 강조 | Ⅴ·Ⅵ 강조 |
|:---|:---|:---|:---|
| 포괄형 | "동시 멀티스레딩(SMT)을 설명하시오" | 문맥 복제·실행 유닛 공유 도식 | 면적 대비 효율 vs 캐시 오염·보안 리스크 |
| 요구사항 명시형 | "멀티코어와 SMT를 비교·적용하시오" | 물리 분리(CMP)와 논리 분리(SMT) 차이 | 클라우드 vCPU(활성) vs HPC·보안(비활성) 기준 |

> 요약: 포괄형은 복제·공유 구조 도식과 트레이드오프를, 명시형은 CMP 대비 차이와 활성·비활성 판단 기준을 축으로 잡아야 함.
