# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 하나의 물리적 코어 내에 2개 이상의 독립적인 하드웨어 스레드 문맥(PC, 레지스터 등)을 복제해 두고, 사이클마다 여러 스레드의 명령어를 섞어서 실행 유닛(ALU 등)에 동시 배분하는 동적 병렬 처리 기술이다. (인텔 상표명: 하이퍼스레딩)
- **왜 필요한가**: 메모리 지연이나 데이터 의존성 때문에 단일 스레드가 실행 유닛을 다 쓰지 못하고 놀릴 때, 그 빈칸을 다른 스레드의 명령어로 채워 하드웨어 가동률을 극대화하기 위해 필요하다.
- **핵심 직관**: 요리사 1명이 가스레인지 화구를 4개 쓸 수 있는데 한 가지 요리(단일 스레드)만 하면 보통 2개는 놀게 된다. 그래서 요리 주문을 2개(2 스레드) 동시에 받아서, 남는 화구에 다른 요리를 동시에 진행시켜 화구(실행 유닛) 가동률을 100%로 끌어올리는 방식이다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 물리 코어 (Physical Core) | 실제 존재하는 반도체 연산 코어 | "실제 요리사 1명과 화구 4개" |
| 논리 코어 (Logical Core) | OS가 인식하는 CPU 개수. SMT를 켜면 물리 코어의 2배로 인식됨 | "주문 접수처 2곳" |
| 파이프라인 버블 (Bubble) | 의존성이나 캐시 미스로 인해 실행 유닛이 연산을 못 하고 쉬는 상태 | "물이 끓을 때까지 화구를 놀리는 시간" |
| 문맥 복제 (Context Duplication) | 스레드 고유 상태(PC, 범용 레지스터)만 하드웨어적으로 여러 벌 복제 | "요리 레시피와 도마를 2벌 준비" |

## 깊이 이해
- **배경·문제의식**: 비순서 실행(OoO)과 멀티코어 기술이 발전했지만, 단일 스레드 내의 ILP 한계 때문에 연산 유닛(ALU 4개 등) 중 평균 40~50%는 항상 놀고 있었다. 이 낭비되는 유휴 자원(Vertical/Horizontal Waste)을 어떻게 활용할 것인가?
- **작동 원리**: 코어 안의 '실행 유닛(ALU, FPU)'은 1세트만 둔 채로, '명령어를 가져오고 저장하는 부분(PC, 레지스터 세트)'만 2벌(또는 4벌)로 늘린다. OS는 이를 2개의 코어로 인식해 2개의 스레드를 할당한다. 하드웨어 스케줄러는 매 사이클마다 두 스레드의 명령어를 섞어 빈 실행 유닛에 끼워 넣는다.
- **비유**: 2차선 도로(실행 유닛)를 버스(스레드 1) 1대가 혼자 쓰면 옆 차선이 빈다. 이때 승용차(스레드 2)를 진입시켜 2차선 모두 꽉 차게 달리게 하는 것이다.
- **구체 예시**: 스레드 A가 메모리에서 데이터를 가져오느라 100사이클 동안 멈춰(Stall) 있으면, 예전에는 CPU 전체가 멈췄다. 하지만 SMT 환경에서는 즉시 스레드 B의 명령어를 가져와 남는 유닛에서 실행하므로 파이프라인이 멈추지 않는다. 
- **흔한 오해·주의점**: SMT를 켜서 4코어 8스레드가 되었다고 성능이 2배(8코어급)가 되는 것이 절대 아니다! 실행 유닛은 결국 공유하기 때문에 전체 성능 향상은 보통 15~30% 수준이다. 심지어 두 스레드가 동일한 자원(예: FPU)을 두고 서로 싸우면(경합) 오히려 싱글 코어일 때보다 성능이 깎이는 현상(Cache Thrashing 등)도 발생할 수 있다.

## 연결 개념
- **013 ILP & 014 멀티코어**: SMT는 ILP의 유휴 자원을 활용하여 TLP(스레드 병렬성)를 극대화하는 브릿지 기술이다.
- **캐시 쓰레싱 (Cache Thrashing)**: 두 스레드가 L1 캐시를 공유하므로 서로의 데이터를 밀어내어 캐시 미스가 폭증하는 부작용.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 동시 멀티스레딩(SMT)은 단일 물리 코어 내에 다수의 구조적 문맥(Architectural State)을 복제하여, 매 사이클마다 여러 스레드의 명령어를 단일 실행 유닛 군에 동시 배분하는 기술이다.
> 2. **가치**: 캐시 미스나 제어 의존성으로 인해 발생하는 파이프라인 유휴 자원(Bubble)을 타 스레드의 독립적 명령어로 채워 넣음으로써 코어의 활용률(Utilization)을 극대화한다.
> 3. **판단 포인트**: 실행 유닛과 L1/L2 캐시를 공유하므로 15~30%의 스루풋 향상을 얻지만, 자원 경합 및 캐시 오염으로 인해 단일 스레드의 응답 시간(Latency)은 오히려 저하될 수 있다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 파이프라인 유휴 자원 극복 원리 분석 | 구조적 상태 복제(레지스터, PC), 실행 유닛 공유 | SMT를 멀티코어(물리적 분할)로 혼동하여 서술 |
| SMT로 인한 성능 트레이드오프 파악 | 가동률(Throughput) 상승 vs 단일 스레드 지연(Latency) | 성능이 2배(코어 2개 분량)로 오른다고 단정하는 오류 |

> 요약: SMT는 "코어를 2개로 복제한 것"이 아니라 "논리적 대기열만 2개로 늘려 놀고 있는 연산 유닛을 쥐어짜는 최적화"임을 명시해야 한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 동시 멀티스레딩(Simultaneous Multithreading, SMT)은 하나의 물리적 프로세서 내에 여러 스레드의 문맥을 복제하고 매 사이클 다수의 스레드 명령어를 혼합 실행하는 아키텍처이다.
- 배경: 비순서 실행(OoO) 코어의 명령어 윈도우 한계 및 메모리 지연(Memory Wall)으로 인해 실행 유닛의 유휴(Waste) 공간 지속 발생
- 필요성: 물리적 트랜지스터(코어)를 두 배로 늘리지 않고도 약간의 면적(약 5%) 추가만으로 스레드 수준 병렬성(TLP) 처리량을 최대 30% 향상시키기 위해 필수

---

## Ⅱ. 구조 및 구성요소 (SMT 복제 및 공유 요소)

```text
[ 스레드 0 문맥 (PC, Reg) ] \
                             -> [ 명령어 스케줄러 (명령어 혼합/이슈) ] -> [ 공유된 다수의 실행 유닛 (ALU, FPU) ]
[ 스레드 1 문맥 (PC, Reg) ] /                                     -> [ 공유 L1/L2 캐시 ]
```

| 구성요소 | 분리/공유 여부 | 역할 및 특이사항 |
|:---|:---|:---|
| 아키텍처 문맥 (PC, 레지스터) | 스레드별 개별 복제 | 각 스레드의 고유 상태 유지, OS에게 논리 코어로 노출 |
| 예약소 (RS) 및 ROB | 스레드 간 파티셔닝 / 공유 | 여러 스레드의 명령어를 섞어서 유지 및 비순서 스케줄링 |
| 실행 유닛 (ALU, FPU) | 완전 공유 | 섞인 명령어들을 실제 연산 (유휴 사이클 최소화) |
| L1 / L2 캐시 | 완전 공유 | 두 스레드의 데이터가 섞이므로 캐시 용량 압박(Thrashing) 발생 |

> 요약: 상태 저장소(문맥)는 2개로 쪼개어 독립성을 보장하고, 덩치가 큰 연산기와 캐시는 1개를 공유하여 가성비를 높인 구조이다.

---

## Ⅲ. 동작원리 및 흐름도

```text
OS 논리코어 인식 -> 독립 명령어 인출 -> SMT 스케줄링(공유 윈도우) -> 유휴 실행 유닛 동시 점유
```

- 1단계 [문맥 인출]: OS는 2개의 논리 코어로 인식하여 스레드 A와 B를 할당하며, 하드웨어는 두 PC에서 번갈아 명령어를 Fetch
- 2단계 [가성 의존성 제거]: 각각 독립적인 레지스터 리네이밍(Renaming)을 거쳐 스레드 간 충돌 없이 단일 예약소(RS)에 진입
- 3단계 [명령어 혼합 이슈]: 스레드 A가 캐시 미스로 특정 유닛(예: 메모리 Load)에 정체되어 있을 때, 스케줄러가 스레드 B의 ALU 명령어를 빈 유닛에 배분
- 4단계 [실행 및 커밋]: 서로 다른 스레드의 명령어가 동일 사이클 내에 병렬 연산되며, 각자의 ROB 포인터를 통해 독립적으로 최종 커밋

> 요약: 두 스레드의 명령어를 하나의 커다란 스케줄링 풀(Pool)에 부어 넣고, 유닛이 비는 곳마다 테트리스를 맞추듯 채워 넣는 동적 스케줄링이다.

---

## Ⅳ. 특징
- 실효 가동률(Utilization) 극대화: 단일 스레드의 수직적/수평적 낭비(Vertical/Horizontal Waste) 사이클을 완전히 타 스레드 연산으로 덮어버림(Hide)
- 낮은 면적 비용: 스레드 문맥 복제에 필요한 실리콘 면적은 전체 다이의 약 5%에 불과하나, 전체 스루풋은 평균 15~30% 향상 (고효율)
- 자원 경합 및 캐시 오염: 두 스레드가 부동소수점 연산 등 동일 유닛을 집중 요구하거나 L1 캐시를 두고 경쟁할 경우, 스톨이 가중되어 성능 역전(Degradation) 발생

> 요약: 트랜지스터 대비 가성비가 가장 뛰어난 병렬화 기술이나, 깡코어(물리 코어) 증가와 같은 선형적 성능 향상은 불가능하다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 멀티코어 프로세서 (CMP) | SMT (동시 멀티스레딩) | 선택 기준 |
|:---|:---|:---|:---|
| 병렬성 수준 | 물리적 코어 분리 | 논리적 문맥 복제 및 연산기 공유 | 실리콘 면적 / 전력 예산 |
| 자원 간섭 | L3 캐시 제외 독립성 보장 (간섭 적음) | 실행유닛, L1/L2 등 내부 로직 전반 공유 | 성능 일관성(QoS) 요구치 |
| 성능 증가폭 | 코어 비례 선형적 (암달의 법칙 내) | 평균 15~30% 향상 (자원 한계 종속) | 애플리케이션 스레드 성향 |

> 요약: 멀티코어는 면적을 두 배로 늘려 확실한 두 배의 성능을 얻는 것이고, SMT는 남는 자원을 쥐어짜서 가성비 스루풋을 얻는 최적화 기법이다.

**리스크·대응 (기본은 불릿):**
- 캐시 쓰래싱 및 성능 저하 리스크: 특정 워크로드(예: 캐시를 많이 쓰는 HPC 앱)에서 스레드 간 L1 캐시 밀어내기로 성능 저하 발생 → OS 스케줄러에서 SMT 논리 코어를 분리(Affinity)하거나 SMT 비활성화 옵션(BIOS) 제공 (지표: 스레드 믹스 캐시 미스율)
- 부채널 공격(Side-Channel Attack) 보안 위협: L1 캐시와 분기 예측기를 물리적으로 공유하여 스레드 간 데이터 유출(Spectre 등) 위험 노출 → 클라우드 환경에서는 코어 단위 격리(Core-level isolation) 및 캐시 파티셔닝 강제 (지표: 격리 보장율 제로 트러스트)

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 엔터프라이즈 데이터베이스 스케줄링: IO 대기가 빈번하고 많은 수의 트랜잭션 처리가 필요한 RDBMS 환경에서는 SMT를 활성화하여 트랜잭션 스루풋 극대화
2. 클라우드 인프라 (vCPU 할당): AWS, GCP 등 클라우드 벤더는 물리 코어의 SMT 스레드를 각각 1개의 vCPU로 매핑/판매하여 서버 밀도와 리소스 활용률 향상
3. HPC / 실시간 시스템 SMT 튜닝: 응답 시간(Latency) 편차가 없어야 하는 금융 HFT(고빈도 매매)나 HPC 환경에서는 역으로 SMT를 비활성화하여 L1 캐시를 단일 스레드가 독점하도록 튜닝

**결론 (2줄):**
- 기술사 판단: SMT는 ILP의 물리적 한계로 발생한 비효율을 TLP로 보완한 매우 우수한 아키텍처 최적화 기술이나, 자원 공유에 따른 보안 취약점과 캐시 간섭이라는 태생적 리스크를 지닌다.
- 향후 방향: 보안 민감 워크로드와 고성능 클라우드 환경이 부상함에 따라, 단순히 스레드만 섞는 SMT에서 벗어나 코어 내부 자원(L1/L2, 대역폭)을 하드웨어적으로 파티셔닝하는 기능(Intel RDT 등)이 필수적으로 결합되고 있다.
