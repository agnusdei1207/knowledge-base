# 022. 가상 메모리 — 페이징·세그멘테이션 (Virtual Memory Paging Segmentation) [출제:120,123,124,128,131,134,135회]

## 미리 알고가기

- **MMU (Memory Management Unit)**: 가상 주소를 물리 주소로 변환하고 메모리 보호를 수행하는 CPU 내 하드웨어 장치임
- **페이지 폴트 (Page Fault)**: 프로세스가 접근하려는 페이지가 현재 물리 메모리에 없을 때 발생하는 트랩(Trap)임
- **스와핑 (Swapping)**: 메모리의 프로세스나 페이지를 보조저장장치의 스왑 영역으로 옮기거나 가져오는 과정임

## Ⅰ. 개요

- **정의/개념**: 가상 메모리는 실제 물리 메모리의 크기와 상관없이 프로세스마다 독립적인 가상의 주소 공간을 제공하는 메모리 관리 기법이며, 이를 구현하는 방식에 따라 페이징과 세그멘테이션으로 나뉨
  - **가상 메모리**: 주소 공간을 추상화하여 메모리 보호, 공유, 효율적 할당을 가능케 함
  - **페이징 (Paging)**: 메모리를 고정된 크기의 블록(Page)으로 나누어 관리하여 외부 단편화를 해결함
  - **세그멘테이션 (Segmentation)**: 메모리를 논리적 의미 단위(Code, Data, Stack)인 세그먼트로 나누어 관리함
- **배경/필요성**: 한정된 물리 메모리보다 큰 프로그램을 실행하거나, 멀티태스킹 환경에서 프로세스 간 메모리 간섭을 완벽히 차단하기 위해 필수적임

## Ⅱ. 특징 및 비교

페이징은 '물리적 효율'에, 세그멘테이션은 '논리적 보호'에 강점이 있음.

| 구분 | 페이징 (Paging) | 세그멘테이션 (Segmentation) |
|:---|:---|:---|
| **관리 단위** | **고정 크기** (Page, Frame) | **가변 크기** (Logical Unit) |
| **단편화** | 내부 단편화 발생 가능 | **외부 단편화** 발생 가능 |
| **주소 구조** | $Page\ Number + Offset$ | $Segment\ Number + Offset$ |
| **장점** | 외부 단편화 없음, 할당 단순 | 공유 및 보호가 논리적으로 용이 |
| **주요 목적** | 물리 메모리 활용 극대화 | 프로그램의 논리적 구조 보호 |

> 요약: 현대 OS는 대부분 페이징을 기본으로 하되, 논리적 보호를 위해 세그멘테이션 개념을 혼합하여 사용함.

## Ⅲ. 구성요소/구조

가상 메모리는 하드웨어(MMU)와 소프트웨어(OS)의 협력을 통해 동작함.

- **구성요소**:
  - **Page Table**: 가상 페이지와 물리 프레임의 매핑 정보를 담은 자료구조
  - **TLB**: 페이지 테이블의 일부를 캐싱하는 고속 버퍼
  - **Swap Space**: 메모리 부족 시 보조저장장치에 마련하는 확장 공간
  - **Valid/Invalid Bit**: 해당 데이터가 실제 메모리에 있는지 표시하는 상태 비트

- **가상 메모리 시스템 구조도 (ASCII)**:

```text
[ Process A (V.A) ]    [ Process B (V.A) ]
       |                      |
 +-----v----------------------v-----+
 |         Page Table (OS)          |
 +-----+----------------------+-----+
       | (Hit)                | (Miss)
 +-----v-----+          +-----v-----+
 | Physical  |          | Disk Swap |
 | Memory    |          | Space     |
 +-----------+          +-----------+
```

1. **주소 변환**: CPU가 가상 주소를 내면 MMU가 페이지 테이블을 참조해 물리 주소로 바꿈
2. **부재 처리**: 메모리에 데이터가 없으면(Page Fault), OS가 디스크에서 데이터를 가져와 메모리에 적재함

## Ⅳ. 문제점 및 개선방안

1. **내부 및 외부 단편화**: 페이징은 페이지 끝자리가 남는 내부 단편화가, 세그멘테이션은 빈 공간이 조각나는 외부 단편화가 발생함
   - **개선방안**: 페이징과 세그멘테이션을 결합(Paged Segmentation)하거나, 가상 메모리 압축 기술을 적용함 (확인: 단편화에 따른 메모리 낭비율)

2. **쓰레싱 (Thrashing)**: 빈번한 페이지 폴트로 인해 CPU가 실제 연산보다 페이지 교체에 더 많은 시간을 쓰는 현상임
   - **개선방안**: 워킹 셋(Working Set) 모델을 사용하여 프로세스별로 필요한 최소 프레임을 보장함 (확인: $Page\ Fault$ 빈도와 CPU 이용률의 상관관계)

3. **주소 변환 오버헤드**: 다단계 페이지 테이블을 거치느라 메모리 접근 횟수가 늘어남
   - **개선방안**: **TLB** 적중률을 높이고, 계층형 페이지 테이블 구조를 최적화함 (확인: 주소 변환에 소요되는 평균 $Cycles$)

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 데이터베이스 (DB) | 대량의 메모리 조회가 잦은 DB 서버에 Huge Page를 설정하여 페이지 테이블 관리 부담 감소 | $TLB\ Miss\ Rate$, 쿼리 성능 |
| 가상화 (VM) | 가상 머신 간의 완벽한 격리를 위해 하드웨어 지원 페이징(EPT) 기술 사용 | $VM\ Exit$ 빈도, 가상화 오버헤드 |
| Linux 서버 운영 | `swapness` 값을 조절하여 물리 메모리가 꽉 차기 전 미리 스와핑을 수행하도록 설정 | $Swap\ Usage$, $Memory\ Pressure$ |

> 요약: 시스템 튜닝 시 'Major Page Fault'와 'Swap 사용량'은 메모리 부족을 판단하는 가장 중요한 지표임.

## Ⅵ. 결론

가상 메모리는 '물리적 한계'를 '논리적 무한함'으로 바꾼 현대 컴퓨팅의 가장 위대한 추상화 중 하나임. 기술사는 단순히 주소 변환 과정을 넘어, 페이징과 세그멘테이션이 어떻게 상호 보완하며 시스템의 안정성과 보안을 책임지는지 통찰해야 함.

향후에는 메모리 풀링(Pooling)이나 CXL과 같은 신기술을 통해, 가상 메모리의 범위가 단일 칩을 넘어 데이터 센터 전체로 확장될 것임. 결국 효율적인 가상 메모리 관리는 컴퓨팅 자원의 활용도를 극대화하는 시스템 아키텍처의 핵심임.
