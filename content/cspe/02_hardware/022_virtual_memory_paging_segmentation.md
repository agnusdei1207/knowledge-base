## 미리 알고가기

- 가상 메모리는 프로세스마다 독립적인 주소 공간을 제공하는 추상화임
- 페이징은 고정 크기 단위로, 세그멘테이션은 논리 단위의 가변 크기로 메모리를 관리함
- 페이지 폴트가 발생하면 운영체제가 보조기억장치에서 필요한 내용을 적재함
- 쓰레싱(Thrashing): 페이지 폴트가 과도해 실제 연산보다 페이지 교체에 더 많은 시간을 쓰는 현상임

## 작성 근거(검토용)

- 가상 메모리를 주소 공간 확대가 아니라 격리·공유·요구 적재·변환 비용으로 설명함
- 페이징과 세그멘테이션을 관리 단위·단편화·보호 경계로 비교함
- 페이지 폴트 비용과 변환 메타데이터를 가상 메모리 관리 기준으로 정리함

## Ⅰ. 개요

- **정의/개념**: 가상 메모리는 프로세스가 보는 주소 공간과 실제 물리 메모리를 분리해 보호·공유·확장을 가능하게 하는 구조이며, 구현 방식은 고정 크기 페이지를 쓰는 페이징과 논리 단위 세그먼트를 쓰는 세그멘테이션으로 나뉨
- **배경/필요성**: 한정된 물리 메모리에서 여러 프로그램을 안전하게 실행하기 위해 주소 격리와 요구 기반 적재 기법이 필요함

## Ⅱ. 특징

- 프로세스별 페이지 테이블과 접근 권한으로 서로 다른 주소 공간을 격리함
- 물리 메모리보다 큰 작업 집합도 필요한 시점에 나눠 적재해 실행할 수 있음
- 공유 라이브러리와 메모리 매핑 파일의 같은 물리 페이지를 여러 주소 공간에 연결함
- 페이지 폴트와 교체 정책이 잘못 맞물리면 쓰레싱으로 전체 처리량이 급락할 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 페이징 | 세그멘테이션 |
|:---|:---|:---|
| 관리 단위 | 고정 크기 페이지·프레임으로 관리함 | 코드·데이터·스택 같은 논리 단위 세그먼트로 관리함 |
| 단편화 | 마지막 페이지의 내부 단편화 발생 | 가변 크기 배치의 외부 단편화 발생 |
| 보호·공유 경계 | 고정 크기 페이지 단위로 설정함 | 코드·데이터·스택 같은 논리 영역 단위로 설정함 |

> 요약: 페이징은 같은 크기의 프레임에 배치하고, 세그멘테이션은 코드·데이터·스택을 보호 경계로 사용함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 가상 주소 공간 | 프로세스별 주소 범위를 제공해 같은 주소를 서로 다른 물리 위치에 매핑함 |
| 페이지·세그먼트 테이블 | 가상 단위를 물리 위치와 연결하고 유효성·권한 정보를 관리함 |
| MMU·TLB | 주소를 변환하고 최근 변환 결과를 캐시함 |
| 물리 메모리·스왑 영역 | 사용 중인 데이터는 DRAM에 두고 나머지는 보조기억장치에 저장함 |

```text
+----------------------+     +----------------------+     +------------------+
| 프로세스 가상 주소 공간  | --> | MMU / TLB            | --> | 물리 메모리        |
+----------------------+     +----------------------+     +------------------+
                                      |
                                      v
                              +------------------+
                              | 디스크 스왑 영역    |
                              +------------------+
```

> 요약: 가상 주소 공간은 MMU와 TLB를 거쳐 물리 메모리나 스왑 영역에 연결됨.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+     +-------------+
| 주소 접근        | --> | 변환 엔트리 조회   | --> | 메모리 존재 확인   | --> | 페이지 폴트 처리   | --> | 실행 재개      |
+-------------+     +-------------+     +-------------+     +-------------+     +-------------+
```

1. **주소 접근**: CPU가 가상 주소로 메모리 참조를 요청함
2. **변환 엔트리 조회**: MMU가 페이지 또는 세그먼트 매핑 정보를 확인함
3. **메모리 존재 확인**: 유효 엔트리면 물리 주소를 만들고 없으면 예외를 발생시킴
4. **페이지 폴트 처리**: 운영체제가 디스크에서 필요한 내용을 적재하고 엔트리를 갱신함
5. **실행 재개**: 동일 명령을 다시 수행해 정상 접근을 완료함

> 요약: 가상 메모리는 변환 엔트리를 확인하고 물리 메모리에 없으면 페이지 폴트로 데이터를 적재함.

## Ⅵ. 실무 사례

1. 메모리 과할당 서버는 작업 집합에 따라 실행 작업 수를 제한하고 주요 페이지 폴트율과 CPU 이용률을 확인함
2. 대용량 데이터베이스는 대형 페이지를 적용하고 페이지 테이블 메모리 비율과 TLB 실패율을 확인함

## Ⅶ. 결론

- 가상 메모리는 주소 격리·공유·요구 적재를 제공하므로 페이지 폴트 빈도·저장장치 지연·페이지 테이블 크기를 함께 관리해야 함
