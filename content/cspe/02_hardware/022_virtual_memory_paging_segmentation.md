## 미리 알고가기

- 가상 메모리는 프로세스마다 독립적인 주소 공간을 제공하는 추상화임
- 페이징은 고정 크기 단위로, 세그멘테이션은 논리 단위의 가변 크기로 메모리를 관리함
- 페이지 폴트가 발생하면 운영체제가 보조기억장치에서 필요한 내용을 적재함

## Ⅰ. 개요

- **정의/개념**: 가상 메모리는 프로세스가 보는 주소 공간과 실제 물리 메모리를 분리해 보호·공유·확장을 가능하게 하는 구조이며, 구현 방식은 고정 크기 페이지를 쓰는 페이징과 논리 단위 세그먼트를 쓰는 세그멘테이션으로 나뉨
- **배경/필요성**: 한정된 물리 메모리에서 여러 프로그램을 안전하게 실행하기 위해 주소 격리와 요구 기반 적재 기법이 필요함

## Ⅱ. 특징

- 프로세스마다 독립 주소 공간을 제공해 메모리 보호와 격리를 쉽게 함
- 물리 메모리보다 큰 작업 집합도 필요한 시점에 나눠 적재해 실행할 수 있음
- 공유 라이브러리와 메모리 매핑 파일처럼 공통 데이터를 효율적으로 재사용할 수 있음
- 페이지 폴트와 교체 정책이 잘못 맞물리면 쓰레싱으로 전체 처리량이 급락할 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 페이징 | 세그멘테이션 |
|:---|:---|:---|
| 관리 단위 | 고정 크기 페이지와 프레임으로 관리함 | 코드·데이터·스택 같은 논리 단위 세그먼트로 관리함 |
| 장점 | 외부 단편화 없이 배치와 교체가 단순함 | 보호와 공유를 논리 경계에 맞춰 적용하기 쉬움 |
| 한계 | 내부 단편화와 페이지 테이블 오버헤드가 생김 | 외부 단편화와 compaction 부담이 생김 |
| 현대 활용 | 대부분의 범용 OS 기본 메커니즘임 | 제한된 보호 모델이나 특수 목적 구조로 보조 활용됨 |

> 요약: 페이징은 배치와 교체가 단순하고, 세그멘테이션은 논리 보호 경계가 명확함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Virtual Address Space | 프로세스별로 독립된 주소 범위를 제공해 같은 주소라도 서로 다른 물리 위치로 매핑되게 함 |
| Page or Segment Table | 각 가상 단위를 물리 위치와 연결하고 유효성 및 권한 정보를 함께 관리함 |
| MMU and TLB | 주소 변환을 하드웨어로 수행하며 최근 변환 결과를 캐시해 지연을 줄임 |
| Physical Memory and Swap Area | 자주 쓰는 데이터는 DRAM에 두고 부족한 영역은 보조기억장치로 넘겨 전체 주소 공간을 확장함 |

```text
+----------------------+     +----------------------+     +------------------+
| Process Virtual Space | --> | MMU / TLB            | --> | Physical Memory  |
+----------------------+     +----------------------+     +------------------+
                                      |
                                      v
                              +------------------+
                              | Disk Swap Area   |
                              +------------------+
```

> 요약: 가상 주소 공간은 MMU와 TLB를 거쳐 물리 메모리나 swap 영역에 연결됨.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+     +-------------+
| 주소 접근        | --> | 변환 엔트리 조회   | --> | 메모리 존재 확인   | --> | 필요 시 page fault | --> | 실행 재개      |
+-------------+     +-------------+     +-------------+     +-------------+     +-------------+
```

1. **주소 접근**: CPU가 가상 주소로 메모리 참조를 요청함
2. **변환 엔트리 조회**: MMU가 페이지 또는 세그먼트 매핑 정보를 확인함
3. **메모리 존재 확인**: 유효 엔트리면 물리 주소를 만들고 없으면 예외를 발생시킴
4. **필요 시 page fault 처리**: 운영체제가 디스크에서 필요한 내용을 적재하고 엔트리를 갱신함
5. **실행 재개**: 동일 명령을 다시 수행해 정상 접근을 완료함

> 요약: 가상 메모리는 변환 엔트리 확인 후 없으면 page fault로 필요한 데이터를 적재함.

## Ⅵ. 실무 적용 및 유의점

1. 작업 집합이 물리 메모리를 넘으면 쓰레싱이 발생하므로 working set과 admission control을 적용하고 page fault frequency, CPU utilization으로 확인함
2. 페이지 테이블이 커지면 메타데이터와 TLB 미스 비용이 늘어나므로 multi-level page table과 huge page를 조합하고 page table memory overhead, TLB miss rate로 확인함
3. 세그멘테이션 기반 가변 크기 배치는 외부 단편화를 키우므로 paging 결합 구조나 compaction 정책을 적용하고 fragmentation ratio, relocation time으로 확인함

## Ⅶ. 결론

가상 메모리는 큰 주소 공간보다 보호·공유·적재 시점 분리로 물리 메모리를 안전하게 쓰는 구조이며, 핵심은 page fault 비용과 메타데이터 오버헤드 통제임.

## 작성 근거(검토용)

- 가상 메모리는 주소 공간 확대가 아니라 보호, 공유, demand paging, 변환 비용을 중심으로 설명함
- 모호한 표현은 page fault frequency, CPU utilization, TLB miss rate, fragmentation ratio로 구체화함
- 결론은 큰 주소 공간보다 page fault 비용과 메타데이터 오버헤드 관리로 정리함
