## Ⅰ. 개요
- **정의**: 프로세스의 논리 주소 공간을 물리 메모리와 분리하여 RAM보다 큰 프로그램 실행과 프로세스 간 격리를 가능하게 하는 메모리 관리 기법임
- **배경/필요성**: 물리 메모리를 프로세스가 직접 접근하면 메모리 침범과 용량 한계가 동시에 발생하므로 논리-물리 주소 분리가 필수적임
- **비유**: 신용카드와 같음. 통장 잔고(물리 메모리)보다 큰 결제가 가능하며, 필요할 때만 현금을 융통(스왑)하여 처리함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 페이징과 세그멘테이션 비교 | 고정 크기 vs 가변 크기, 내부 단편화 vs 외부 단편화 | 둘 중 하나만 서술하고 비교 축 누락 금지 |
| 다단계 페이징 구조 이해 | 64비트 환경의 4단계 페이지 테이블 구조 | 단일 레벨 페이지 테이블만 설명 금지 |
| 현대 OS 결합 구조 | Paged Segmentation 방식의 장점 결합 | 페이징만 현대 표준이라 단정 금지 |

> 요약: 논리-물리 주소 분리를 통해 용량 확장과 프로세스 격리를 동시에 달성하는 기법임

## Ⅱ. 구성요소
```text
프로세스 VA --> +------+     +--------------+     +----------+
               | MMU  |<--->| Page Table   |     | RAM      |
               |      |<--->| (다단계)      |     | (Frame)  |
               +------+     +--------------+     +----------+
                  |                                    ^
                  | TLB Hit 시 직접 변환                |
                  +------------------------------------+
                                             Miss 시 스왑 영역(디스크) 참조
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 페이지/프레임 | 가상 주소 공간을 고정 크기(4KB)로 분할한 페이지와 물리 메모리의 동일 크기 프레임 쌍 | 규격화된 택배 상자 |
| 페이지 테이블 | VPN을 PFN으로 매핑하는 변환 표. 64비트 환경에서 4단계 계층 구조로 관리됨 | 층별 안내 데스크 |
| 세그먼트 테이블 | 논리 단위(코드/데이터/스택)별 Base+Limit 쌍을 관리하는 변환 표 | 건물 동별 출입 명부 |
| 스왑 영역 | RAM 부족 시 페이지를 임시 저장하는 디스크 공간 | 창고에 보관 중인 짐 |

> 요약: 페이지/프레임, 페이지 테이블, 세그먼트 테이블, 스왑 영역으로 주소 변환과 용량 확장을 수행함

## Ⅲ. 절차
```text
CPU VA 발행 --> VPN 추출 --> 페이지 테이블 조회 --> Valid? --Yes--> PFN+Offset 결합 --> 물리 주소
                                                    |
                                                   No
                                                    |
                                                    v
                                             Page Fault --> OS 개입 --> 디스크에서 적재 --> 재실행
```
- 1단계: CPU가 가상 주소를 발행하면 MMU(025 참조)가 VPN과 Offset으로 분리함
- 2단계: TLB(021 참조)를 먼저 검색하고, Miss 시 다단계 페이지 테이블을 순회하여 해당 엔트리를 조회함
- 3단계: Valid 비트가 0이면 Page Fault가 발생하여 OS가 디스크 스왑 영역에서 해당 페이지를 RAM에 적재함
- 4단계: PFN과 Offset을 결합하여 물리 주소를 생성하고, 권한 비트(R/W/X)를 검증한 뒤 메모리 접근을 허용함

> 요약: VPN 분리 -> 테이블 조회 -> 부재 시 디스크 적재 -> 물리 주소 생성의 흐름으로 동작함

## Ⅳ. 문제점
- 내부 단편화(페이징): 고정 4KB 페이지에 실제 데이터가 일부만 차면 나머지 공간이 낭비됨
- 외부 단편화(세그멘테이션): 가변 크기 세그먼트의 할당/해제가 반복되면 연속 빈 공간이 조각나 큰 세그먼트 할당이 실패함
- 페이지 테이블 비대화: 64비트 주소 공간에서 단일 레벨 페이지 테이블은 수백 GB 크기가 되므로 메모리 자체를 과도하게 소비함

> 요약: 페이징의 내부 단편화, 세그멘테이션의 외부 단편화, 대규모 주소 공간의 테이블 비대화가 핵심 문제임

## Ⅴ. 개선방안
1. 단기: Huge Page(2MB/1GB) 적용으로 페이지 수를 줄여 내부 단편화 총량과 TLB Miss를 동시에 감소시킴
2. 중기: Paged Segmentation 적용으로 세그먼트를 다시 페이지 단위로 분할하여 외부 단편화를 원천 제거함
3. 장기: 다단계(4~5레벨) 페이지 테이블과 역 페이지 테이블(Inverted Page Table) 도입으로 테이블 크기를 물리 메모리 비례로 제한함

> 요약: Huge Page, Paged Segmentation, 다단계/역 페이지 테이블로 각 단편화 및 비대화 문제를 해소함

## Ⅵ. 전망
- 발전 방향: CXL 메모리 확장 환경에서 원격 메모리를 가상 주소 공간에 통합하는 메모리 풀링 기술이 확산됨
- 기술사적 판단: 가상화 환경의 이중 주소 변환(EPT/NPT) 오버헤드 관리가 클라우드 인프라 설계의 핵심 고려사항임
- 기술사 제언: Demand Paging과 Working Set 모니터링을 결합하여 Thrashing 임계점을 사전 감지하는 운영 체계를 권고함
