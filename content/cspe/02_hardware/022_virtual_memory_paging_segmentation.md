# 📖 【암기용】 개념 완전 이해

> 목적: 가상 메모리를 처음 봐도 프로세스가 실제 물리 메모리보다 큰 주소공간을 어떻게 쓰는지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 프로세스마다 독립된 가상주소 공간을 부여하고, OS와 MMU가 이를 물리 메모리·보조기억장치로 매핑하는 메모리 관리 기법
- **왜 필요한가**: 물리 메모리는 유한하고 여러 프로세스가 동시에 실행되므로, 가상 메모리 없이는 프로세스 간 주소 충돌과 메모리 부족 문제를 피할 수 없다.
- **핵심 직관**: 아파트 단지의 각 세대(프로세스)가 자기만의 우편함 번호(가상주소)를 갖고, 관리사무소(OS/MMU)가 실제 창고 위치(물리주소)로 연결해주는 구조다.

## 깊이 이해
- **배경·문제의식**: 초기 시스템은 프로그램을 물리주소에 직접 적재해 여러 프로그램을 동시에 실행할 때 주소 충돌과 보호 문제가 발생했다.
- **작동 원리(페이징)**: 페이징은 가상주소 공간과 물리주소 공간을 고정 크기 블록(페이지·프레임, 예시로 4KB)으로 나누고, 페이지 테이블로 페이지 번호를 프레임 번호에 매핑한다.
- **작동 원리(세그멘테이션)**: 세그멘테이션은 주소 공간을 코드·데이터·스택 같은 논리적 단위(세그먼트)로 나누고, 세그먼트마다 base(시작 주소)와 limit(길이)를 세그먼트 테이블에 저장한다.
- **작동 원리(차이)**: 페이징은 물리적으로 균일한 고정 크기 블록 단위 관리이고, 세그멘테이션은 프로그램의 논리적 구조를 반영한 가변 크기 블록 단위 관리다.
- **작동 원리(결합)**: 일부 아키텍처는 세그먼트 내부를 다시 페이지로 나누는 세그멘테이션+페이징 결합 방식을 사용해, 논리적 보호와 고정 크기 배치 효율을 동시에 노린다.
- **비유**: 페이징은 이삿짐을 모두 같은 크기 상자에 담는 방식이고, 세그멘테이션은 옷장·책장·냉장고처럼 원래 크기 그대로 옮기는 방식이다.
- **구체 예시**: 페이지 크기가 4KB인 시스템에서 프로세스가 10KB 배열을 요청하면 페이지 3개(12KB)를 할당하고 남는 2KB는 내부 단편화로 낭비된다.
- **구체 예시**: 세그멘테이션에서 코드 세그먼트(읽기·실행)와 데이터 세그먼트(읽기·쓰기)를 분리하면, 코드 영역에 대한 쓰기 시도를 세그먼트 보호 비트로 차단할 수 있다.
- **흔한 오해·주의점**: 페이징의 "내부 단편화"와 세그멘테이션의 "외부 단편화"는 서로 다른 문제이며, 페이징이 외부 단편화를 없애는 대신 내부 단편화를 감수하는 트레이드오프임을 혼동하지 않아야 한다.
- **흔한 오해·주의점**: 가상 메모리가 크다고 해서 물리 메모리 부족 문제가 사라지는 것은 아니며, 실제 사용되지 않는 페이지만 디스크로 스왑되어 공간을 확보하는 것이다.

## 연결 개념
- 페이지 테이블(Page Table)·TLB — 페이징 주소 변환의 실체
- 페이지 교체 알고리즘(OPT/FIFO/LRU/LFU) — 물리 프레임 부족 시 교체 대상 선정
- MMU(Memory Management Unit) — 페이징·세그멘테이션 변환을 수행하는 하드웨어
- 단편화(Fragmentation) — 내부(페이징)·외부(세그멘테이션) 단편화 문제

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 페이징과 세그멘테이션을 단순 나열하지 않고, 고정/가변 크기 차이와 단편화 유형 차이를 비교축으로 명확히 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 가상 메모리(Virtual Memory)는 프로세스마다 독립된 주소 공간을 부여하고 물리 메모리·보조기억장치로 매핑하는 기법이며, 페이징과 세그멘테이션은 그 매핑 단위가 다르다.
> 2. **가치**: 페이징은 고정 크기 블록으로 외부 단편화를 없애고, 세그멘테이션은 논리적 단위 보호와 공유를 가능하게 한다.
> 3. **판단 포인트**: 내부 단편화(페이징) vs 외부 단편화(세그멘테이션)라는 트레이드오프를 기준으로 설계를 선택해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 페이징·세그멘테이션 구조 차이 확인 | 고정 크기 vs 가변 크기, 페이지 테이블 vs 세그먼트 테이블 | 두 기법을 "메모리 나누는 방식"으로만 뭉뚱그림 |
| 단편화 유형 구분 역량 확인 | 내부 단편화(페이징) vs 외부 단편화(세그멘테이션) | 단편화 종류를 서로 바꿔서 서술 |
| 결합 구조 이해 확인 | 세그멘테이션+페이징 결합 방식의 목적 | 결합 방식을 언급하지 않고 단일 기법만 서술 |

> 요약: 이 문제는 페이징·세그멘테이션 정의 나열이 아니라 단편화 유형과 결합 구조의 목적을 구분했는지를 확인한다.

## Ⅰ. 개요 및 필요성

- 정의: 프로세스마다 독립된 가상주소 공간을 부여하고 물리 메모리·보조기억장치로 매핑하는 메모리 관리 기법
- 배경: 물리 메모리 직접 적재 방식은 프로세스 간 주소 충돌과 물리 메모리 초과 요구 문제를 유발함
- 필요성: 페이징(고정 크기)과 세그멘테이션(가변 크기·논리 단위)은 서로 다른 단편화 문제를 감수하며 주소공간을 관리함

---

## Ⅱ. 구조 및 구성요소

```text
Process Virtual Address Space
  / Paging: Page Table (Page Number -> Frame Number)
  / Segmentation: Segment Table (Segment Number -> Base+Limit)
Virtual Address -> MMU Translation -> Physical Address
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Page Table | 페이지 번호를 프레임 번호로 매핑 | 다단계 구조로 큰 주소공간 지원 |
| Segment Table | 세그먼트 번호를 base+limit으로 매핑 | offset이 limit 초과 시 세그먼트 폴트 |
| Frame(물리 프레임) | 페이징에서 실제 물리 메모리 고정 블록 | 페이지와 동일 크기 |
| Segment | 논리적 단위(코드·데이터·스택) | 세그먼트별 보호 비트 상이 |

> 요약: 페이징은 페이지-프레임 매핑, 세그멘테이션은 세그먼트-base/limit 매핑으로 서로 다른 테이블 구조를 사용한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
Virtual Address 발생
  / Paging: Page Number 추출 -> Page Table 조회 -> Frame Number 획득 -> Offset 결합
  / Segmentation: Segment Number 추출 -> Segment Table 조회 -> Base+Offset 계산 -> Limit 검사
  -> Physical Address 확정 -> Memory Access
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 가상주소를 페이지/세그먼트 번호와 offset으로 분리 | 주소 비트 분할 정확성 |
| 2 | 페이지 테이블 또는 세그먼트 테이블 조회 | 유효 비트(valid bit) 확인 |
| 3 | 세그멘테이션의 경우 offset이 limit 이내인지 검사 | limit 초과 시 세그먼트 폴트 |
| 4 | 물리주소 확정 및 메모리 접근 수행 | 물리주소 범위 유효성 |

> 요약: 페이징은 고정 크기 매핑 후 결합만 하면 되지만, 세그멘테이션은 limit 검사 단계가 추가로 필요하다.

---

## Ⅳ. 특징

| 구분 | 페이징(Paging) | 세그멘테이션(Segmentation) | 수치·표준 포인트 |
|:---|:---|:---|:---|
| 분할 단위 | 고정 크기 블록 | 가변 크기 논리 단위 | 페이지 크기 예시 4KB, huge page 2MB/1GB |
| 단편화 유형 | 내부 단편화 발생 | 외부 단편화 발생 | 압축(compaction)으로 외부 단편화 완화 |
| 테이블 구조 | Page Table(다단계) | Segment Table(base+limit) | 다단계 페이지 테이블은 TLB miss 시 비용 증가 |
| 보호·공유 | 프레임 단위 보호 | 논리 단위(코드/데이터) 보호에 유리 | 세그먼트별 읽기/쓰기/실행 권한 분리 |

> 요약: 페이징은 내부 단편화, 세그멘테이션은 외부 단편화라는 서로 다른 트레이드오프를 갖는다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 페이징 | 세그멘테이션 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 고정 크기, 물리적 배치 단순 | 가변 크기, 논리적 구조 반영 | 단순 배치 효율 우선 시 페이징 |
| 비용/성능 | 내부 단편화로 일부 공간 낭비 | 압축 필요로 CPU 오버헤드 발생 가능 | 대용량 연속 배열은 페이징이 유리 |
| 운영/위험 | 페이지 테이블 크기 관리 필요 | 외부 단편화 누적 관리 필요 | 보호·공유 요구가 크면 세그멘테이션 결합 고려 |

> 요약: 균일한 배치 효율이 필요하면 페이징, 논리적 보호·공유가 중요하면 세그멘테이션 결합 구조를 선택한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 내부 단편화 누적 | 페이지 크기보다 작은 요청 반복 | huge page 선택적 적용, 페이지 크기 조정 | 프로세스당 낭비 메모리 비율 |
| 외부 단편화 심화 | 세그먼트 할당·해제 반복 | 압축(compaction), 세그먼트 재배치 | 가용 공간 단편 개수 |
| 세그먼트 폴트 | offset이 limit 초과 | 경계 검사 로직 및 예외 처리 강화 | 세그먼트 폴트 발생 빈도 |

> 요약: 페이징은 단편화 누적, 세그멘테이션은 외부 단편화 심화를 각각 다른 방식으로 통제해야 한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 메모리 낭비율 | 내부/외부 단편화 비율 최소화 목표 설정 | OS 메모리 통계, `/proc/meminfo` 등 |
| 폴트 발생률 | 페이지 폴트·세그먼트 폴트 빈도 확인 | 커널 트레이싱, 성능 카운터 |
| 압축 오버헤드 | compaction 소요 시간 확인 | 벤치마크, 시스템 로그 |

> 요약: 도입 효과는 단편화 비율, 폴트 발생률, 압축 오버헤드로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 대용량 연속 데이터 처리 워크로드는 페이징 기반 구조에 huge page를 결합해 내부 단편화와 TLB miss를 함께 관리함
2. 코드·데이터·스택 보호가 중요한 환경은 세그먼트 단위 권한 분리를 적용해 코드 영역 쓰기 시도를 차단함
3. 외부 단편화가 누적되는 세그멘테이션 환경은 주기적 압축 또는 세그먼트+페이징 결합 구조로 전환함

**결론 (2줄):**
- 기술사 판단: 물리적 배치 효율이 우선이면 페이징, 논리적 보호·공유가 우선이면 세그멘테이션 결합 구조를 선택함
- 향후 방향: 현대 OS는 대부분 페이징을 기본으로 하고 세그멘테이션은 보호 링·권한 분리 목적으로 제한적으로 결합해 사용하는 추세임
