# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 실제 물리 메모리(RAM)보다 큰 프로그램을 실행하기 위해, 디스크 공간을 메모리처럼 속여 프로세스에게 연속된 거대한 주소 공간을 제공하는 기법
- **왜 필요한가**: 과거에는 RAM 용량보다 큰 프로그램을 돌릴 수 없었고, 여러 프로그램을 띄우면 주소가 겹쳐 충돌했다. 이를 하드웨어와 OS가 중간에서 가짜 주소로 속여 해결한다.
- **핵심 직관**: 100평짜리 창고(RAM)를 쓰는 회사에서, 직원(프로세스)마다 "너 혼자 1,000평 창고(가상 메모리) 다 써라"고 가짜 장부를 주고, 실제 물건은 필요할 때만 진짜 창고에 조금씩 옮겨두는(Paging) 마법.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 페이징 (Paging) | 메모리를 4KB 같은 고정 크기로 깍둑썰기하는 방식 | A4 용지 규격으로 문서를 쪼개서 철하기 |
| 세그멘테이션 (Segmentation) | 메모리를 '코드', '데이터' 등 논리적 의미 단위로 자르는 방식 | 장, 절, 문단 단위로 문서를 나누기 |
| 페이지 (Page) | 가상 메모리 공간에서의 고정 분할 단위 | 가상 장부의 한 칸 |
| 프레임 (Frame) | 물리 메모리(RAM) 공간에서의 고정 분할 단위 (페이지와 크기 동일) | 실제 창고의 한 칸 |
| Swap In / Out | 디스크에서 필요한 데이터를 램으로 가져오고, 안 쓰는 걸 쫓아내는 과정 | 창고 정리 (안 쓰는 짐은 임시 창고로 뺌) |

## 깊이 이해
- **배경·문제의식**: 다중 프로그래밍 환경에서는 프로세스들이 물리 메모리를 두고 경합한다. 프로그램 크기가 물리 메모리보다 크면 실행이 불가능했고(오버레이 기법 등 한계), 주소 충돌로 보안 문제가 빈번했다.
- **작동 원리**: OS는 각 프로세스에게 0번지부터 시작하는 거대한 가상 주소(Virtual Address) 공간을 준다. CPU는 이 가상 주소로 접근하고, 하드웨어(MMU)가 중간에서 몰래 페이지 테이블을 보고 실제 물리 주소(Physical Address)로 변환해준다. 필요한 페이지가 RAM에 없으면 OS가 개입해 디스크에서 퍼온다(Page Fault).
- **비유**: 통역사(MMU)가 있어서, 한국어(가상 주소)로 말하면 상대방에 맞춰 영어(물리 주소)로 바꿔 전달해주는 것.
- **구체 예시**: 32비트 OS는 각 프로세스당 최대 4GB의 가상 메모리를 제공하지만, 실제 꽂혀 있는 RAM은 1GB여도 수십 개의 프로그램이 정상 동작한다.
- **흔한 오해·주의점**: 페이징은 크기가 일정해 메모리 관리는 편하지만 마지막 조각에서 남는 공간(내부 단편화)이 생기고, 세그멘테이션은 의미 단위라 관리는 좋지만 크기가 들쭉날쭉해 중간중간 빈틈(외부 단편화)이 생겨 램 효율이 박살난다. 현재 대부분의 OS는 두 장점을 섞은 Paged Segmentation(세그먼트를 다시 페이지로 쪼갬)을 쓴다.

## 연결 개념
- TLB (Translation Lookaside Buffer) — (021 TLB 참조) 주소 변환을 초고속으로 해주는 캐시
- 페이지 교체 알고리즘 (Page Replacement) — 램이 꽉 찼을 때 누구를 디스크로 쫓아낼지 결정
- MMU (Memory Management Unit) — 가상 주소를 물리 주소로 바꿔주는 핵심 하드웨어

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 가상 메모리는 주소 공간의 논리적 분리(Virtual)와 물리적 적재(Physical)를 디커플링하여, 프로세스 간 메모리 격리와 용량 한계를 극복하는 기법이다.
> 2. **가치**: 불연속적 메모리 할당을 통해 물리 메모리의 단편화 문제를 해결하고, 다중 프로그래밍의 효율성을 극대화한다.
> 3. **판단 포인트**: 현대 OS는 페이징(고정 크기, 내부 단편화)과 세그멘테이션(가변 크기, 외부 단편화)의 단점을 보완하기 위해 두 기법을 결합한 Paged Segmentation 방식을 표준으로 채택한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 메모리 관리 기법의 한계 극복 원리 확인 | 고정 분할(페이징) vs 가변 분할(세그멘테이션) 메커니즘 차이 | 가상 메모리를 단순히 "디스크를 메모리처럼 쓰는 것"으로만 한정 |
| 단편화 문제와 해결 방안 도출 | 내부 단편화(Internal Fragmentation)와 외부 단편화(External Fragmentation) | 페이징과 세그멘테이션의 단편화 종류 혼동 |

> 요약: 주소 변환 메커니즘의 차이(크기 고정 여부)가 단편화의 종류(내부/외부)를 결정짓는 핵심 인과관계를 명시해야 한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 프로세스의 논리적 주소 공간을 물리적 주소 공간과 분리하여, 주 기억장치보다 큰 프로세스의 실행을 지원하고 메모리를 보호하는 기법
- 배경: 프로그램 대형화 및 멀티태스킹 환경에서 물리 메모리 용량 부족과 프로세스 간 메모리 침범 문제가 심화됨
- 필요성: 불연속적인 메모리 적재를 통해 단편화를 최소화하고, MMU 기반 권한 제어로 악의적 접근을 하드웨어 레벨에서 차단 필요

---

## Ⅱ. 구조 및 구성요소

```text
Process A 가상 주소 -> MMU (주소 변환/권한 체크) -> 물리 메모리 (Frame 적재)
                                            |
                                            +-> 디스크 (Swap Area, Page Fault 시 활용)
```

| 기법 | 분할 단위 | 주소 변환 테이블 |
|:---|:---|:---|
| 페이징 (Paging) | Page (고정 크기, 예: 4KB) | Page Table (VPN -> PFN) |
| 세그멘테이션 (Segmentation) | Segment (논리적 의미 기반 가변 크기) | Segment Table (Segment # -> Base, Limit) |
| Paged Segmentation | 논리적 분할 후 다시 고정 크기로 분할 | Segment Table 참조 후 Page Table 이중 참조 |

> 요약: 페이징은 물리적 크기 기준으로 분할하여 관리를 단순화하고, 세그멘테이션은 코드·데이터 등 논리적 단위로 분할하여 보호와 공유를 용이하게 한다.

---

## Ⅲ. 동작원리 및 흐름도 (페이징 기준)

```text
CPU 가상 주소 요청 -> MMU 변환 시도 -> [유효] 물리 주소 산출 및 메모리 접근
                                     |
                                     +-> [무효] Page Fault 발생 -> OS 개입 -> Swap In -> 테이블 갱신
```

- 1단계 [주소 요청]: CPU가 프로세스의 가상 주소(Page Number + Offset)를 MMU로 전송
- 2단계 [테이블 검사]: MMU가 해당 페이지 테이블 엔트리의 Valid Bit를 확인하여 메모리 적재 여부 판정
- 3단계 [Page Fault 처리]: Valid가 0일 경우, OS가 인터럽트를 걸어 디스크에서 해당 페이지를 찾아 빈 Frame에 적재
- 4단계 [주소 변환]: 적재 완료 후 CPU에 재실행을 지시하고, PFN과 Offset을 더해 물리 주소 접근

> 요약: 주소 변환은 하드웨어(MMU)가 고속으로 처리하며, 부재(Fault) 시에만 소프트웨어(OS)가 개입하여 오버헤드를 최소화한다.

---

## Ⅳ. 특징
- 페이징: 고정 크기로 분할하여 외부 단편화가 발생하지 않으나, 마지막 페이지에 할당되지 않은 남는 공간(내부 단편화)이 발생함
- 세그멘테이션: 크기가 제각각이므로 메모리에 올리고 내리는 과정에서 조각난 빈 공간(외부 단편화)이 발생하나, 내부 단편화는 없음
- 보호와 공유: 세그멘테이션은 '코드(Read-Only)', '데이터(Read/Write)' 등 의미 단위로 나뉘어 접근 통제 및 라이브러리 공유가 매우 직관적임

> 요약: 페이징은 메모리 활용의 물리적 효율성을, 세그멘테이션은 프로세스의 논리적 보호 및 공유를 극대화한다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 페이징 (Paging) | 세그멘테이션 (Segmentation) | Paged Segmentation (대안) |
|:---|:---|:---|:---|
| 단편화 문제 | 내부 단편화 발생 (마지막 페이지) | 외부 단편화 발생 (빈틈 조각) | 외부 단편화 제거, 내부 단편화 미미 |
| 테이블 구조 | 1차원 Page Table | 2차원 Segment Table (Base, Limit) | 세그먼트 당 페이지 테이블 유지 |
| 오버헤드 | Page Table 크기가 방대함 | 메모리 컴팩션(압축) 비용 높음 | 이중 테이블 참조로 인한 속도 지연 |

> 요약: 현대 x86 등 대부분의 아키텍처는 보호가 용이한 세그멘테이션으로 먼저 나누고, 다시 페이징으로 잘게 쪼개어 외부 단편화를 근본적으로 없애는 복합 방식을 채택한다.

**리스크·대응 (가상 메모리 성능 병목):**
- [Thrashing]: 프로세스 수가 과도하여 Swap In/Out이 CPU 연산보다 많아지는 현상 → Working Set 모델, PFF(Page Fault Frequency) 조절 (지표: CPU Utilization 하락, I/O Wait 폭증)
- [변환 오버헤드]: Paged Segmentation의 이중/다중 테이블 참조로 인한 지연 → TLB 하드웨어 캐시 확충 및 최적화 (지표: TLB Hit Ratio 99% 유지)

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 메모리 집약적 워크로드 최적화: JVM, RDBMS 운영 시 OS 레벨에서 Huge Page(2MB)를 설정하여 페이지 테이블 크기를 줄이고 변환 속도를 극대화
2. 컨테이너 메모리 격리: cgroups를 활용하여 컨테이너별 메모리 사용량 상한(Limit)과 스왑(Swap) 영역을 통제하여 특정 파드의 Thrashing 전파 차단
3. 동적 페이지 회수 튜닝: 리눅스 커널의 swappiness 값을 0~10으로 낮춰, 불필요한 스와핑을 지연시키고 물리 메모리(Page Cache) 활용도 향상

**결론 (2줄):**
- 기술사 판단: 가상 메모리는 다중 프로그래밍의 근간이나, Thrashing과 변환 지연이라는 트레이드오프가 있으므로 작업 특성에 맞춘 페이징 튜닝이 필수적이다.
- 향후 방향: 클라우드 환경에서 하이퍼바이저와 게스트 OS가 각각 페이지 테이블을 갖는 이중 변환 구조(Shadow Paging)의 부하를 줄이기 위해, NPT/EPT 하드웨어 지원 기술이 핵심 통제 요소로 부각된다.
