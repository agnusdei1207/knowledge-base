# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 가상 메모리는 **메모리 관리 기법**으로, 프로세스의 논리적 주소 공간(가상 주소)을 물리적 주소 공간(RAM)과 분리하여 메모리 보호·격리·용량 확장을 제공하는 OS+하드웨어 협업 기술임.
- **왜 필요한가**: 물리 RAM 용량보다 큰 프로그램 실행이 불가능하고, 여러 프로세스가 동일 물리 주소를 침범하는 보안 문제가 있었음. 가상 메모리는 각 프로세스에 독립된 연속 주소 공간을 제공하여 이를 해결함.
- **핵심 직관**: 100평 창고(RAM)를 쓰는 회사에서, 각 직원(프로세스)에게 "1,000평 전용 창고(가상 메모리)를 써라"고 가짜 장부를 주고, 실제 물건은 필요할 때만 진짜 창고에 옮겨두는(Demand Paging) 방식임.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 메모리 관리 (상위 키워드) | OS가 물리 메모리를 프로세스에 할당·보호·회수하는 체계 | "창고 관리 시스템" |
| 가상 주소 (VA) | 프로세스가 바라보는 논리적 연속 주소 | "가짜 장부의 주소" |
| 물리 주소 (PA) | 실제 RAM 칩의 하드웨어적 위치 | "실제 창고 칸 번호" |
| 페이지 (Page) | 가상 주소 공간의 고정 크기 분할 단위(통상 4KB) | "규격화된 A4 용지" |
| 프레임 (Frame) | 물리 메모리의 고정 크기 분할 단위(Page와 동일 크기) | "창고의 규격 칸" |
| 세그먼트 (Segment) | 코드·데이터·스택 등 논리적 의미 단위의 가변 크기 블록 | "장, 절, 문단 단위" |
| Page Table | VPN→PFN 전체 매핑을 저장한 DRAM 상의 테이블 | "주소 변환 장부" |
| Page Fault | 접근한 페이지가 RAM에 없어 디스크에서 적재해야 하는 상황 | "창고에 물건이 없어 임시 창고에서 가져옴" |
| Swap In/Out | 디스크↔RAM 간 페이지를 이동시키는 과정 | "창고 정리(안 쓰는 짐은 밖으로)" |

## 깊이 이해
- **배경·문제의식**: 다중 프로그래밍 환경에서 각 프로세스가 물리 메모리를 직접 접근하면 ① 타 프로세스 메모리 침범, ② RAM 용량 초과 시 실행 불가, ③ 메모리 단편화로 연속 공간 확보 곤란이라는 세 가지 문제가 발생함. 과거의 오버레이(Overlay) 기법은 프로그래머가 수동으로 메모리를 분할해야 해 비실용적이었음.
- **작동 원리**:
  - **페이징**: 가상 주소 공간과 물리 메모리를 동일한 고정 크기(4KB)로 나눔. CPU가 가상 주소(VPN+Offset)를 발행하면 MMU가 Page Table을 참조하여 PFN으로 변환함. 해당 페이지가 RAM에 없으면 Page Fault가 발생하여 OS가 디스크에서 적재함.
  - **세그멘테이션**: 프로세스를 코드·데이터·스택 등 논리적 의미 단위로 분할함. Segment Table이 각 세그먼트의 시작 주소(Base)와 길이(Limit)를 관리하며, Limit 초과 접근을 하드웨어가 차단함.
  - **Paged Segmentation**: 세그먼트를 먼저 나누고, 각 세그먼트를 다시 페이지로 쪼갬. 세그멘테이션의 논리적 보호 + 페이징의 단편화 제거를 결합한 방식으로 현대 OS가 채택함.
- **비유**: 통역사(MMU)가 한국어(가상 주소)를 영어(물리 주소)로 실시간 변환해 주는 것. 프로세스는 한국어만 알면 되고, RAM과의 통신은 통역사가 전담함.
- **구체 예시**: 32비트 OS는 프로세스당 4GB 가상 공간을 제공함. RAM이 1GB여도 20개 프로세스가 정상 동작하는 이유는, 각 프로세스가 실제 사용하는 Working Set(수십~수백 MB)만 RAM에 적재하고 나머지는 디스크에 보관하기 때문임.
- **흔한 오해·주의점**: 가상 메모리 = "디스크를 메모리처럼 쓰는 것"이라는 이해는 절반만 맞음. 핵심은 **주소 공간의 논리적 분리와 보호**이며, 디스크 활용(Swap)은 용량 확장의 부수 효과임. 또한 페이징은 외부 단편화가 없으나 내부 단편화(마지막 페이지의 잔여 공간)가 있고, 세그멘테이션은 내부 단편화가 없으나 외부 단편화(가변 크기에 의한 빈틈)가 있음.

## 연결 개념
- **021 TLB**: Page Table 참조의 2회 메모리 접근 병목을 해소하는 하드웨어 캐시.
- **023 페이지 교체 알고리즘**: RAM이 가득 찼을 때 어떤 페이지를 Swap Out할지 결정하는 정책.
- **025 MMU**: 가상→물리 주소 변환을 수행하는 하드웨어이며, 권한 위반 시 Segmentation Fault를 발생시킴.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 가상 메모리는 프로세스의 논리적 주소 공간과 물리적 적재를 분리(디커플링)하여 메모리 보호·격리·용량 확장을 제공하는 OS+하드웨어 협업 기법임.
> 2. **가치**: 불연속적 메모리 적재로 단편화를 최소화하고, MMU 기반 권한 제어로 프로세스 간 메모리 침범을 하드웨어 레벨에서 차단함.
> 3. **판단 포인트**: 페이징(내부 단편화)과 세그멘테이션(외부 단편화)의 트레이드오프를 결합한 Paged Segmentation이 현대 OS의 표준이며, Thrashing 방지를 위한 Working Set 관리가 핵심임.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 메모리 관리 기법의 원리·한계 이해 | 페이징(고정)·세그멘테이션(가변) 메커니즘 차이 | "디스크를 메모리처럼 쓰는 것"으로만 한정 |
| 단편화 문제와 해결 구조 도출 | 내부 단편화(페이징)·외부 단편화(세그멘테이션) 인과 | 페이징·세그멘테이션의 단편화 종류 혼동 |

> 요약: 분할 단위(고정/가변)가 단편화 종류(내부/외부)를 결정하는 인과관계를 명시하고, 결합 방식(Paged Segmentation)으로 수렴하는 논리를 전개해야 함.

---

## Ⅰ. 개요 및 필요성

- 개요: 프로세스의 논리적 주소 공간을 물리 메모리와 분리하여 보호·격리·용량 확장을 제공하는 메모리 관리 기법임.
- 배경: 프로그램 대형화·멀티태스킹 환경에서 물리 메모리 용량 부족과 프로세스 간 주소 충돌이 심화됨.
- 필요성: 불연속 적재로 단편화를 최소화하고, MMU 기반 하드웨어 권한 제어로 메모리 침범을 원천 차단해야 함.

---

## Ⅱ. 구조 및 구성요소

```text
프로세스 가상 주소(VA) -> MMU(주소 변환+권한 검증) -> 물리 메모리(Frame 적재)
                                                  |
                                                  +-> 디스크(Swap Area, Page Fault 시 활용)
```

| 기법 | 분할 단위 | 주소 변환 테이블 | 단편화 |
|:---|:---|:---|:---|
| 페이징 | Page(고정, 4KB) | Page Table(VPN→PFN) | 내부 단편화 |
| 세그멘테이션 | Segment(가변, 논리 단위) | Segment Table(Base, Limit) | 외부 단편화 |
| Paged Segmentation | 세그먼트 내부를 다시 Page로 분할 | Segment Table + Page Table 이중 참조 | 내부 단편화만(미미) |

> 요약: 페이징은 고정 크기로 외부 단편화를 제거하고, 세그멘테이션은 논리 단위로 보호·공유를 용이하게 하며, 현대 OS는 두 기법을 결합한 Paged Segmentation을 채택함.

---

## Ⅲ. 동작원리 및 흐름도 (페이징 기준)

```text
CPU 가상 주소 발행 -> MMU: VPN 추출 -> Page Table 검색 -> Valid Bit 확인
  유효 -> PFN+Offset 결합 -> 물리 주소 -> 데이터 접근
  무효 -> Page Fault 발생 -> OS: 디스크에서 Swap In -> Frame 적재 -> 테이블 갱신 -> 재실행
```

- 1단계 [주소 분할]: CPU가 가상 주소를 VPN(Page Number)과 Offset으로 분리하여 MMU에 전달함.
- 2단계 [테이블 검사]: MMU가 Page Table 엔트리의 Valid Bit를 확인하여 메모리 적재 여부를 판정함.
- 3단계 [Page Fault 처리]: Valid=0이면 OS가 인터럽트를 발생시켜 디스크에서 해당 페이지를 빈 Frame에 적재함(RAM이 가득 차면 교체 알고리즘 작동).
- 4단계 [주소 변환 완료]: PFN과 Offset을 결합하여 물리 주소를 생성하고, 데이터에 접근함.

> 요약: 주소 변환은 하드웨어(MMU)가 고속 처리하며, 부재(Page Fault) 시에만 OS가 개입하여 오버헤드를 최소화함.

---

## Ⅳ. 특징
- 페이징의 단편화: 고정 크기 분할로 외부 단편화가 발생하지 않으나, 마지막 페이지에 할당되지 않은 잔여 공간(내부 단편화)이 평균 페이지 크기의 절반(4KB 페이지 시 평균 2KB) 발생
- 세그멘테이션의 보호: 코드(Read-Only)·데이터(Read/Write)·스택 등 의미 단위로 분할되어 접근 권한 통제와 라이브러리 공유가 직관적이나, 가변 크기에 의한 외부 단편화와 Compaction 비용이 발생
- Demand Paging: 프로세스 전체를 한꺼번에 적재하지 않고 접근 시점에 필요한 페이지만 적재하여 초기 적재 시간을 단축하고 메모리 활용률을 향상시킴.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 페이징 | 세그멘테이션 | Paged Segmentation |
|:---|:---|:---|:---|
| 분할 기준 | 고정 크기(4KB) | 논리적 의미 단위(가변) | 논리 분할 후 고정 분할 |
| 단편화 | 내부 단편화 | 외부 단편화 | 내부 단편화만(미미) |
| 보호·공유 | 페이지 단위 보호(세분화 곤란) | 세그먼트 단위 보호·공유 용이 | 세그먼트 보호 + 페이지 관리 |
| 테이블 오버헤드 | 방대한 Page Table(멀티레벨로 해결) | Segment Table은 소규모 | 이중 테이블 참조(TLB로 완화) |

> 요약: 현대 x86-64는 세그멘테이션을 최소화(Flat Segment)하고 4단계 멀티레벨 페이징을 주력으로 사용하며, TLB와 Huge Page로 변환 오버헤드를 제어함.

**리스크·대응:**
- Thrashing: 프로세스 수 과다로 Swap In/Out이 CPU 연산보다 많아져 CPU 활용률이 급락 → Working Set 모델 적용, PFF(Page Fault Frequency) 모니터링으로 메모리 부족 프로세스를 조기 식별 (지표: CPU Utilization 급락 + I/O Wait 급증)
- Page Table 크기 폭증: 64비트 주소 공간에서 단일 Page Table은 수 TB → 멀티레벨 Page Table(x86-64: 4단계)로 계층화하고 미사용 영역은 테이블을 생성하지 않음

**점검 지표:**
- 성능: Page Fault Rate(vmstat의 si/so 컬럼), TLB Miss Rate(perf stat)
- 운영: Swap 사용률(free -m), 프로세스별 RSS vs VSZ 비교

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. Huge Page 적용: JVM·RDBMS 등 메모리 집약 워크로드에서 4KB 대신 2MB/1GB Huge Page를 설정하여 Page Table 크기와 TLB Miss를 동시 절감
2. 컨테이너 메모리 격리: cgroups v2의 memory.max를 설정하여 컨테이너별 메모리 상한을 통제하고, memory.swap.max=0으로 Swap을 차단하여 Thrashing 전파 방지
3. 커널 swappiness 튜닝: DB 서버에서 vm.swappiness=10으로 설정하여 불필요한 Swap Out을 억제하고 Page Cache 활용도를 향상시킴

**결론:**
- 기술사 판단: 가상 메모리는 다중 프로그래밍의 근간이며, 작업 특성에 따라 Huge Page 적용·Swap 정책·Working Set 크기를 조율하여 Thrashing을 사전 방지해야 함.
- 향후 방향: 하이퍼바이저·컨테이너의 이중/삼중 주소 변환 오버헤드가 확대되면서, EPT/NPT 하드웨어 지원과 CXL 기반 메모리 풀링이 가상 메모리 아키텍처의 핵심 진화 방향임.
