## Ⅰ. 개요
- **정의**: 물리 메모리보다 큰 주소 공간을 프로세스에 제공하는 메모리 추상화 기법임
- **배경/필요성**: 다수 프로세스가 제한된 물리 메모리를 공유해야 하므로 격리와 확장을 동시에 지원하는 주소 공간 관리가 필요함
- **비유**: 도서관의 서가(물리 메모리)는 한정되지만, 대출 카드(가상 주소)를 통해 무한한 장서 목록을 제공하는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 페이징과 세그멘테이션의 비교·혼합 구조 이해 | 고정 크기 vs 가변 크기 분할의 트레이드오프 | 페이징의 내부 단편화, 세그멘테이션의 외부 단편화를 혼동하지 말 것 |

> 요약: 가상 메모리는 물리 메모리를 추상화하여 프로세스 격리와 주소 공간 확장을 제공함

## Ⅱ. 구성요소
```text
  +------------------+
  | 가상 주소 공간   |
  |  (프로세스별)    |
  +--------+---------+
           |
     +-----+------+
     |             |
     v             v
  페이징        세그멘테이션
  (고정 블록)   (논리 단위)
     |             |
     v             v
  +------------------+
  | 물리 메모리      |
  | (프레임/영역)    |
  +------------------+
           |
           v
  +------------------+
  | 디스크 스왑 영역 |
  +------------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 가상 주소 공간 | 프로세스마다 독립적으로 부여되는 연속 주소 범위임 | 각자의 사서함 번호 체계 |
| 페이지 테이블 | 가상 페이지 → 물리 프레임 매핑을 저장하는 자료구조임 | 대출 카드 → 서가 위치 색인표 |
| 프레임 | 물리 메모리를 고정 크기(4KB 등)로 분할한 단위임 | 규격화된 서가 칸 |
| 세그먼트 | 코드·데이터·스택 등 논리적 의미 단위로 분할한 가변 크기 블록임 | 장르별로 구분된 서가 구역 |
| 스왑 영역 | 물리 메모리 부족 시 페이지를 임시 저장하는 디스크 공간임 | 도서관 외부 창고 |

> 요약: 가상 주소 공간, 매핑 테이블, 프레임/세그먼트, 스왑 영역으로 구성됨

## Ⅲ. 절차
```text
  주소 생성         매핑 조회         적재 확인         물리 접근
  (가상주소)       (테이블 참조)    (Present Bit)     (프레임 접근)
   |                |                |                 |
   +---가상주소---->+---매핑 결과--->+---적재됨------->+
                                     |                 ^
                                     +---미적재        |
                                         Page Fault    |
                                         스왑에서 적재-+
```
- 1단계: CPU가 가상 주소를 생성하고 페이지 번호와 오프셋으로 분리함
- 2단계: 페이지 테이블(또는 세그먼트 테이블)을 참조하여 물리 주소 매핑을 조회함
- 3단계: Present Bit를 확인하여 메모리 적재 여부를 판정하고, 미적재 시 Page Fault를 발생시킴
- 4단계: 적재된 프레임의 물리 주소에 오프셋을 결합하여 데이터에 접근함

> 요약: 가상주소 분리 → 테이블 조회 → 적재 판정 → 물리 접근의 4단계로 동작함

## Ⅳ. 문제점
- 내부 단편화(페이징): 고정 크기 페이지에 데이터가 미달하면 페이지 내 잔여 공간이 낭비됨
- 외부 단편화(세그멘테이션): 가변 크기 세그먼트 할당·해제가 반복되면 연속 빈 공간이 부족해짐
- 다단계 테이블 오버헤드: 주소 공간이 커질수록 페이지 테이블 단계가 증가하여 변환 지연이 누적됨

> 요약: 페이징의 내부 단편화, 세그멘테이션의 외부 단편화, 테이블 계층 오버헤드가 주요 문제임

## Ⅴ. 개선방안
1. 단기: 슈퍼페이지(2MB/1GB)를 활용하여 내부 단편화 비율을 상대적으로 축소함
2. 중기: 세그멘테이션에 페이징을 결합한 세그먼트-페이지 혼합 기법으로 외부 단편화를 제거함
3. 장기: 역 페이지 테이블(Inverted Page Table) 또는 해시 기반 구조로 테이블 크기와 조회 단계를 감축함

> 요약: 슈퍼페이지, 혼합 기법, 역 페이지 테이블로 단편화·오버헤드를 해소함

## Ⅵ. 전망
- 발전 방향: CXL 기반 메모리 풀링 환경에서 노드 간 가상 메모리 통합 관리 기술이 확대됨
- 기술사적 판단: 컨테이너·서버리스 환경에서 경량화된 주소 공간 관리가 핵심 과제임
- 기술사 제언: 워크로드별 페이지 크기 혼합 정책과 NUMA-aware 배치 전략을 설계할 필요
