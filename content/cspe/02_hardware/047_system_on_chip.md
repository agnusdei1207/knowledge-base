## Ⅰ. 개요
- **정의**: CPU, 메모리, 주변장치를 하나의 칩에 집적한 단일 반도체 시스템임
- **배경/필요성**: 모바일·IoT 기기에서 면적·전력·비용을 동시에 줄이려면 보드 수준 부품을 칩 내부로 통합해야 함
- **비유**: 주방·침실·욕실이 한 건물 안에 있는 원룸과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 칩 수준 통합 설계 이해 | IP 블록 재사용과 온칩 인터커넥트 | SoC와 MCU 차이: SoC는 AP급 범용 OS 구동 가능 |

> 요약: SoC는 이종 IP 블록을 하나의 다이에 통합하여 면적·전력·지연을 절감하는 설계 방식임

## Ⅱ. 구성요소
```text
+--------------------------------------------------+
|                     SoC Die                       |
|                                                   |
|  CPU Core  <--+                                   |
|               |--- On-Chip Bus (AXI/NoC) ---+     |
|  GPU Core  <--+                             |     |
|               |                             v     |
|  DSP / NPU <--+                        Memory     |
|               |                        Controller |
|  I/O Ctrl  <--+                          |        |
|                                       DRAM I/F    |
+--------------------------------------------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| CPU Core | 범용 연산을 수행하는 프로세서 코어 | 원룸의 거실(범용 공간) |
| GPU / DSP / NPU | 그래픽·신호처리·AI 추론용 가속 코어 | 전용 작업실 |
| On-Chip Bus | AXI, NoC 등 IP 블록 간 데이터 전달 경로 | 건물 내부 복도 |
| Memory Controller | DRAM 접근을 중재하는 인터페이스 블록 | 건물 출입구 관리인 |
| I/O Controller | UART, SPI, USB 등 외부 통신을 처리하는 블록 | 건물 우편함·전화기 |

> 요약: CPU·가속기·버스·메모리컨트롤러·I/O가 하나의 다이에 통합되어 동작함

## Ⅲ. 절차
```text
요구사항 정의 --> IP 선정/라이선스 --> 통합 설계 --> 검증/테이프아웃
      |                 |                 |                |
      v                 v                 v                v
  스펙 확정        IP 블록 확보       RTL 통합·합성      Si 검증
```
- 1단계: 목표 성능·전력·면적(PPA) 및 인터페이스 사양을 확정함
- 2단계: 자체 개발 또는 써드파티 IP(CPU, PHY 등)를 라이선스하여 확보함
- 3단계: RTL 통합, 합성, P&R(배치배선)을 수행하고 타이밍·전력을 검증함
- 4단계: 테이프아웃 후 시뮬레이션·FPGA 에뮬레이션·실리콘 테스트를 진행함

> 요약: PPA 스펙 정의 → IP 확보 → RTL 통합·합성 → 테이프아웃·검증 순서로 SoC를 개발함

## Ⅳ. 문제점
- 설계 복잡도 폭증: IP 블록 수 증가에 따라 인터커넥트·클록 트리 설계가 기하급수적으로 복잡해짐 — 설계 기간 및 비용 상승
- 전력 밀도 집중: 동일 다이에 이종 코어가 밀집하여 핫스팟 발생 — 열 관리 실패 시 스로틀링으로 성능 저하
- IP 통합 호환성: 서로 다른 벤더의 IP가 버스 프로토콜·전압 레벨에서 불일치할 수 있음 — 통합 검증 비용 증가

> 요약: 설계 복잡도, 전력 밀도, IP 호환성이 SoC의 핵심 과제임

## Ⅴ. 개선방안
1. 단기: 표준 버스 프로토콜(AMBA AXI) 준수 및 IP 인터페이스 래퍼 표준화로 호환성 문제를 완화함
2. 중기: 칩릿(Chiplet) 기반 이종 집적으로 단일 다이 면적·전력 밀도 부담을 분산함
3. 장기: EDA 자동화·AI 기반 설계 탐색(Design Space Exploration)으로 설계 복잡도를 관리함

> 요약: 인터페이스 표준화, 칩릿 분산, AI 기반 설계 자동화로 SoC 과제를 해결함

## Ⅵ. 전망
- 발전 방향: 칩릿·UCIe 표준 기반의 모듈형 SoC가 확산되며, 도메인 특화 가속기(NPU, DPU 등) 통합이 가속됨
- 기술사적 판단: FPGA(048 참조)·ASIC(049 참조)과의 트레이드오프를 설계 초기에 판단하는 능력이 중요함
- 기술사 제언: PPA 최적화와 IP 재사용 전략을 종합적으로 수립할 필요
