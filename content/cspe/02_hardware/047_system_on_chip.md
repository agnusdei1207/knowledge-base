## Ⅰ. 개요
- **정의**: CPU·GPU·NPU·메모리 컨트롤러·I/O를 단일 반도체 칩에 통합한 시스템
- **배경/필요성**: 모바일·IoT 기기는 면적과 전력 예산이 극히 제한적이므로, 개별 칩을 보드에 배치하는 방식으로는 요구를 충족할 수 없음
- **비유**: 주방·침실·욕실을 한 건물에 합친 원룸과 같음 — 공간은 줄지만 동선(내부 배선)이 짧아짐

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 칩 통합 설계의 장단점과 IP 코어 재사용 구조 | 온칩 버스(AMBA 등)로 IP 간 통신 | SoC와 MCU 차이(범용 OS 탑재 가능 여부) 구분 |

> 요약: 이종 IP 코어를 단일 다이에 통합하여 면적·전력·지연을 줄이는 설계 방식임

## Ⅱ. 구성요소
```text
+-----------------------------------------------+
|                    SoC Die                     |
|  CPU -- On-Chip Bus(AMBA) -- GPU               |
|           |          |                         |
|          NPU    Mem Controller -- DDR I/F      |
|           |          |                         |
|         DSP     I/O Controller -- USB/PCIe     |
+-----------------------------------------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| CPU 코어 | 범용 연산 처리, ARMv9/RISC-V ISA 기반 | 원룸의 작업 데스크 |
| GPU 코어 | 그래픽·병렬 연산 처리 블록 | 대형 모니터 |
| NPU/DSP | AI 추론·신호 처리 전용 가속기 | 전용 계산기 |
| 메모리 컨트롤러 | LPDDR5/HBM 인터페이스를 관리하여 대역폭을 제공함 | 냉장고(데이터 저장고) |
| 온칩 버스(AMBA) | AXI/AHB/APB 계층으로 IP 간 데이터를 전달함 | 복도·통로 |
| I/O 컨트롤러 | USB·PCIe·MIPI 등 외부 인터페이스를 제어함 | 현관문 |

> 요약: CPU·GPU·NPU 등 IP 코어가 온칩 버스를 통해 단일 다이 위에서 상호 연결됨

## Ⅲ. 절차
```text
사양 정의 --> IP 코어 선정/설계 --> 통합·검증 --> 테이프아웃·양산
```
- 1단계: 타깃 응용(모바일 AP, 차량 등)에 따라 필요 IP 종류·성능·전력 예산을 정의함
- 2단계: 자체 설계 또는 라이선스 IP(ARM Cortex, Mali 등)를 선정하고 RTL을 확보함
- 3단계: 온칩 버스로 IP를 연결한 뒤 기능·타이밍·전력 시뮬레이션으로 검증함
- 4단계: 파운드리(TSMC, Samsung 등)에 GDS 전달(Tape-out) 후 웨이퍼 제조·패키징·양산함

> 요약: 사양 정의 → IP 확보 → 통합 검증 → 테이프아웃 순으로 SoC를 개발함

## Ⅳ. 문제점
- 설계 복잡도 폭증: IP 수 증가 시 버스 대역폭·클록 도메인 교차(CDC) 검증 항목이 기하급수적으로 늘어남 — 검증 기간이 전체 개발 비용의 60~70 %를 차지함
- 열 밀도 집중: 이종 IP가 동일 다이에 밀집하여 핫스팟 발생 — 서멀 스로틀링으로 피크 성능 유지가 어려움
- IP 벤더 종속: 핵심 IP(CPU·GPU) 라이선스 의존 시 로열티 부담과 커스터마이징 제약이 발생함

> 요약: 검증 복잡도, 열 밀도, IP 벤더 종속이 SoC 설계의 주요 병목임

## Ⅴ. 개선방안
1. 단기: UVM 기반 자동화 검증 환경과 형식 검증(Formal Verification)을 병행하여 검증 커버리지를 확보함
2. 중기: 칩렛(Chiplet) 분리 패키징으로 다이별 열 분산 및 공정 최적화를 수행함
3. 장기: RISC-V 등 오픈 ISA 기반 자체 IP 확보로 벤더 종속을 탈피함

> 요약: 자동 검증, 칩렛 패키징, 오픈 ISA 전환으로 SoC 설계 한계를 극복함

## Ⅵ. 전망
- 발전 방향: 2.5D/3D 칩렛 통합(UCIe 표준)으로 단일 다이 한계를 넘어 멀티다이 SoC로 진화 중임
- 기술사적 판단: AI 가속(NPU)·보안(TEE)·통신(5G 모뎀) 블록이 필수 IP로 편입되며 SoC 규모가 지속 확대됨
- 기술사 제언: FPGA(048 참조) 프로토타이핑과 칩렛 전략을 결합하여 설계 리스크와 양산 비용을 동시에 관리할 것을 권고함
