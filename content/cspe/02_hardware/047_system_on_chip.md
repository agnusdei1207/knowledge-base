## 미리 알고가기

- SoC는 CPU, 메모리 인터페이스, I/O, 가속기 등을 하나의 칩에 통합한 집적 시스템임
- 성능뿐 아니라 전력, 면적, 인터커넥트 효율이 설계 핵심임
- 모바일·임베디드·온디바이스 AI 플랫폼의 기본 형태임

## Ⅰ. 개요

- **정의/개념**: SoC는 프로세서 코어, 메모리 제어기, 주변장치 인터페이스, 전용 가속기를 하나의 반도체 다이에 통합해 시스템 기능을 칩 내부에서 수행하는 집적 아키텍처임
- **배경/필요성**: 보드 수준 분산 설계는 전력, 공간, 배선 비용이 커지므로 모바일·임베디드 환경에서는 기능 통합을 통한 소형화와 저전력화가 필요함

## Ⅱ. 특징

- 칩 내부 통합으로 전력 소모와 지연을 줄임
- 기능 추가와 검증 복잡도가 함께 증가해 설계 난도가 높음
- CPU, GPU, NPU, ISP 같은 이기종 블록 공존이 일반적임
- CPU·메모리 제어기·주변장치를 한 칩에 통합해 외부 칩 수와 보드 배선을 줄임

## Ⅲ. 종류 및 비교

| 판단 기준 | SoC | MPU 기반 보드 | SiP |
|:---|:---|:---|:---|
| 통합 수준 | 칩 단위 통합 | 낮음 | 패키지 단위 통합 |
| 전력 효율 | 높음 | 중간 | 중간 |
| 설계 유연성 | 낮음 | 높음 | 중간 |
| 대표 용도 | 모바일, 임베디드 | 산업, 범용 제어 | 고밀도 패키징 |

> 요약: SoC는 칩 단위 통합으로 전력·면적을 줄이고, MPU 보드는 설계 유연성을 남김.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Compute Cluster | CPU·GPU·NPU가 연산 성격별로 역할을 분담하며 전체 성능 상한을 결정함 |
| On-chip Interconnect | AMBA NoC 등이 블록 간 데이터를 전달하며 병목과 QoS를 좌우함 |
| Memory, Cache Subsystem | DRAM 인터페이스, 캐시, SRAM이 데이터 공급 효율과 전력 사용량을 결정함 |
| Peripheral, Power Management | USB, PCIe, Display, PMIC 제어가 시스템 연결성과 배터리 지속시간을 함께 좌우함 |

```text
+------------------+
| Compute Cluster  |
+------------------+
         |
         v
+------------------+
| On-chip NoC      |
+------------------+
      |       |
      v       v
+-----------+ +------------------+
| Memory    | | Peripheral / PM  |
+-----------+ +------------------+
```

> 요약: SoC 성능은 compute cluster만 아니라 NoC, 메모리, 전력 관리가 함께 결정함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 기능 통합 설계 | --> | 블록 간 연결 구성 | --> | 전력/클록 제어 | --> | 시스템 기능 제공 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **기능 통합 설계**: 필요한 연산과 I/O 기능을 칩에 배치함
2. **블록 간 연결 구성**: interconnect와 메모리 계층을 연결함
3. **전력과 클록 제어**: 블록별 DVFS와 power gating을 적용함
4. **시스템 기능 제공**: 칩 단위로 완결된 플랫폼 동작을 수행함

> 요약: SoC는 기능 통합 뒤 블록 연결과 전력 제어를 맞춰 칩 단위 플랫폼을 제공함.

## Ⅵ. 실무 적용 및 유의점

1. 스마트폰·AI SoC는 CPU·GPU·NPU 통합으로 전력 효율을 확보하지만 NoC·메모리 병목이 성능을 제한하므로 DVFS·QoS 제어를 적용하고 performance per watt, memory bandwidth utilization으로 확인함
2. 자동차·산업 SoC는 수명 주기가 길고 재설계 비용이 크므로 검증된 IP 재사용과 단계적 검증 계획을 적용하고 verification coverage, first-pass success rate로 확인함

## Ⅶ. 결론

SoC는 기능 수보다 연산·메모리·전력 균형이 핵심이므로 통합 이익과 병목 비용을 함께 판단해야 함.

## 작성 근거(검토용)

- SoC는 통합 수준, 전력·면적, NoC·메모리 병목을 핵심 축으로 설명함
- 구성요소는 compute cluster, on-chip interconnect, memory/cache, peripheral/power로 정리함
- 실무 판단은 DVFS, QoS, verification coverage로 검증 가능하게 작성함
