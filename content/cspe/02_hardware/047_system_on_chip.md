# SoC 시스템온칩 (System on Chip)

## 미리 알고가기

- SoC: 시스템 온 칩(System on Chip, SoC)은 시스템 기능을 하나의 반도체 칩 안에 통합한 구조임
- IP 코어: CPU, GPU, 메모리 컨트롤러처럼 재사용 가능한 반도체 설계 블록임
- NoC/버스: 네트워크 온 칩(Network-on-Chip, NoC)과 버스는 SoC 내부 구성요소 사이의 데이터 이동 경로임
- PPA: 전력·성능·면적(Power, Performance, Area, PPA)은 칩 설계의 핵심 평가 기준임
- Tape-out: 검증된 반도체 설계를 제조용 마스크 데이터로 넘기는 단계임

## 1. 개요

- **정의/개념**: SoC는 CPU, 메모리 컨트롤러, I/O, 가속기, 보안·전원 관리 블록을 하나의 칩에 통합해 지연시간, 전력, 비용, 폼팩터를 기준으로 보드 단위 시스템을 소형화하는 시스템 수준 반도체임.
- **배경/필요성**: 모바일, 임베디드, 온디바이스 AI는 작은 공간에서 높은 성능과 낮은 전력을 동시에 요구함. 개별 칩 조합은 인터페이스 지연, 전력 손실, 보드 복잡도가 커지므로 단일 칩 통합이 필요함.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 시스템 통합 반도체 구조와 장단점 판단 | IP 통합, 내부 인터커넥트, PPA, 검증, 전원 관리 | 단순 CPU 칩으로 축소, 소프트웨어 플랫폼 영향 누락 |

> 요약: SoC는 시스템 구성요소를 칩 내부로 통합해 전력, 지연, 비용을 줄이는 하드웨어 플랫폼임.

## 2. 특징 및 비교

| 판단 기준 | 개별 칩 기반 시스템 | SoC |
|:---|:---|:---|
| 통합 수준 | CPU, 메모리, I/O, 가속기가 보드에서 연결됨 | 주요 기능이 단일 칩 내부에 통합됨 |
| 성능·전력 | 외부 버스 지연과 I/O 전력 부담이 큼 | 내부 인터커넥트로 지연과 전력 감소 |
| 유연성 | 부품 교체와 확장이 상대적으로 쉬움 | 설계 변경 비용과 검증 부담이 큼 |
| 적용 기준 | 범용 서버, 확장 카드, 모듈형 장비 | 모바일, IoT, 차량, 엣지 AI |

SoC의 선택 기준은 PPA뿐 아니라 IP 재사용성, 검증 난이도, 소프트웨어 지원, 제조 비용임. 기능을 많이 넣을수록 보드는 단순해지지만 칩 내부 검증과 열 설계는 더 어려워짐.

## 3. 구성요소/구조

```text
+--------------------------------------------------+
|                     SoC                          |
| +-----+  +-----+  +----------+  +--------------+ |
| | CPU |  | GPU |  | AI Accel |  | Memory Ctrl  | |
| +-----+  +-----+  +----------+  +--------------+ |
|    \        \          |              /           |
|     +--------------------------------+            |
|              Bus / NoC / Fabric                   |
|     +-----------+  +----------+  +-------------+  |
|     | I/O Ctrl  |  | Security |  | Power Mgmt  |  |
|     +-----------+  +----------+  +-------------+  |
+--------------------------------------------------+
```

| 구성요소 | 설명 | 핵심 포인트 |
|:---|:---|:---|
| CPU 코어 | 운영체제와 제어 로직을 실행함 | 범용 제어 |
| GPU/NPU/가속기 | 그래픽, AI, 영상 처리 같은 병렬 연산을 가속함 | 전용 처리량 |
| 메모리 컨트롤러 | DRAM, SRAM, 캐시 접근을 제어함 | 대역폭과 지연 |
| 내부 인터커넥트 | IP 블록 사이 데이터 이동과 QoS를 관리함 | 병목 제어 |
| 보안·전원 관리 블록 | secure boot, key storage, clock/power gating을 담당함 | 신뢰성과 전력 |

### 원리/흐름도

```text
+---------+      +---------+      +----------+      +----------+
| IP 설계 | ---> | 통합    | ---> | 검증     | ---> | 제조/운영|
+---------+      +---------+      +----------+      +----------+
```

SoC 설계는 검증된 IP를 선택하고 내부 버스·메모리·전원 도메인으로 통합한 뒤 기능 검증과 물리 검증을 거쳐 제조됨. 통합도가 높을수록 시스템 성능은 좋아지지만 변경 비용은 커짐.

## 4. 문제점 및 개선방안

1. **검증 복잡도 증가**: 여러 IP와 전원·클록 도메인이 결합되면 기능 오류와 타이밍 오류를 찾기 어려움.
   - **개선방안**: IP별 검증, UVM 기반 검증, formal verification, emulation을 단계적으로 적용함. (확인: coverage, escape defect)
2. **열과 전력 제약**: 작은 칩 면적에 고성능 블록이 집중되면 발열과 전력 피크가 커짐.
   - **개선방안**: DVFS, power gating, thermal throttling, workload scheduling을 설계함. (확인: TDP, thermal violation)
3. **IP 통합과 공급망 리스크**: 외부 IP의 보안 취약점, 라이선스, 호환성 문제가 전체 SoC 품질에 영향을 줌.
   - **개선방안**: IP 보안 검증, 라이선스 관리, 인터페이스 표준화, SBOM/HBOM 관리를 수행함. (확인: IP 취약점, 통합 결함)

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 스마트폰 AP | CPU, GPU, NPU, ISP, 모뎀 인터페이스를 통합해 성능과 배터리 시간을 동시에 관리함 | 전력당 성능, 발열, 앱 지연 |
| 차량용 제어 SoC | 실시간 제어, 영상 처리, 보안 부팅, 안전 격리 블록을 통합함 | 기능안전 진단율, worst-case latency |
| 엣지 AI 장치 | 센서 입력, AI 추론, 네트워크 I/O를 하나의 칩에서 처리해 지연과 전력을 줄임 | 추론 지연, 전력 소모, 온도 |

## 6. 결론

SoC는 부품을 한 칩에 모으는 수준이 아니라 시스템 요구를 PPA, 검증, 소프트웨어 생태계까지 포함해 칩 구조로 바꾸는 설계 방식임. 모바일·임베디드·엣지 환경에서는 지연과 전력을 줄이는 강점이 크지만, 검증과 열 관리 실패는 제품 전체 리스크로 이어짐. 따라서 SoC 판단은 통합 효과와 변경 비용, 운영 신뢰성을 함께 보는 관점이 필요함.
