## Ⅰ. 개요
- **정의**: 하나의 프로그램 내에서 동시에 실행할 수 있는 명령어의 수를 나타내는 병렬성 척도
- **배경/필요성**: 클럭 주파수 향상만으로는 성능 한계가 있으므로, 한 사이클에 복수 명령어를 처리하여 처리량을 높일 필요가 있음
- **비유**: 한 줄로 된 계산 문제지에서 서로 무관한 문제를 여러 명이 동시에 풀 수 있는 정도를 나타냄

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| ILP 활용 기법 열거 | 파이프라이닝(007)+슈퍼스칼라(010)+OoO(012) | VLIW(011)도 ILP 활용 기법임을 포함 |
| ILP 한계 | 데이터/제어 의존성이 ILP 상한을 결정함 | 암달의 법칙에 의한 병렬화 한계도 언급 필요 |

> 요약: 프로그램 내 동시 실행 가능 명령어 수이며, 의존성에 의해 상한이 결정됨

## Ⅱ. 구성요소
```text
                    +--- Pipelining (007)
                    |
ILP Exploitation ---+--- Superscalar (010)
                    |
                    +--- OoO Execution (012)
                    |
                    +--- VLIW (011)

ILP Limitation ---- Data Dependency (RAW/WAR/WAW)
                |
                +-- Control Dependency (Branch)
                |
                +-- Amdahl's Law (Serial Fraction)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 데이터 의존성 | RAW·WAR·WAW 해저드로 인해 명령어 간 실행 순서가 강제됨 | 앞 공정 결과물이 있어야 다음 공정을 시작할 수 있는 조립 라인 |
| 제어 의존성 | 분기 명령어의 결과가 확정될 때까지 후속 명령어를 확정할 수 없음 | 갈림길에서 방향이 정해져야 다음 경로를 걸을 수 있는 것 |
| 슈퍼스칼라/OoO | 하드웨어가 런타임에 ILP를 탐색하여 복수 명령어를 동시 발행함(010, 012 참조) | 여러 창구를 열어 동시에 손님을 처리하는 은행 |
| 암달의 법칙 | 순차 실행 비율 `s`가 존재하면 병렬화 속도 향상은 `1/(s+(1-s)/N)`으로 수렴함 | 고속도로를 넓혀도 병목 톨게이트 용량이 전체 통행량을 제한함 |

> 요약: 의존성과 순차 비율이 ILP 상한을 결정하며, 파이프라이닝·슈퍼스칼라·OoO·VLIW가 ILP를 활용함

## Ⅲ. 절차
```text
Program --> Dependency Graph --> ILP Window --> Parallel Issue --> Result Commit
```
- 1단계: **의존성 그래프 구성** — 명령어 간 RAW/WAR/WAW 및 제어 의존 관계를 분석함
- 2단계: **ILP 윈도 설정** — 동시에 검사할 명령어 범위(instruction window)를 결정함
- 3단계: **병렬 발행** — 윈도 내 의존성이 없는 명령어를 복수 FU에 동시 디스패치함
- 4단계: **결과 커밋** — 실행 완료된 명령어를 프로그램 순서로 아키텍처 상태에 반영함(012 참조)

> 요약: 의존성 그래프에서 병렬 가능 명령어를 추출하여 동시 발행하고 순서대로 커밋함

## Ⅳ. 문제점
- **데이터 의존 벽**: RAW 의존이 많은 코드는 ILP가 1에 수렴하여 병렬화 효과가 사라짐
- **분기 예측 실패**: 제어 의존에서 예측 실패 시 파이프라인 플러시로 수십 사이클 낭비가 발생함
- **윈도 크기 한계**: 하드웨어 ILP 윈도를 넓히면 비교 회로가 O(N^2)로 증가하여 전력·면적 비용이 급증함

> 요약: 데이터 의존, 분기 실패, 윈도 확장 비용이 ILP 활용의 주요 한계임

## Ⅴ. 개선방안
1. 단기: **소프트웨어 파이프라이닝** — 컴파일러가 루프 반복 간 명령어를 재배치하여 RAW 의존 대기를 감소시킴
2. 중기: **고정밀 분기 예측기** — TAGE 등 다단계 예측기로 분기 예측 정확도를 99% 이상으로 향상함
3. 장기: **TLP 전환** — ILP 한계 지점에서 멀티코어(014 참조)·SMT로 스레드 수준 병렬성을 활용함

> 요약: 컴파일러 최적화, 고정밀 예측기, TLP 전환으로 ILP 한계를 단계적으로 극복함

## Ⅵ. 전망
- **발전 방향**: 단일 스레드 ILP 개선폭이 줄어들며, 멀티코어(014 참조)·가속기와 결합한 하이브리드 병렬 구조로 이동함
- **기술사적 판단**: ILP는 프로세서 성능 향상의 기본 축이며, TLP·DLP와 계층적으로 결합되어 활용됨
- **기술사 제언**: 워크로드의 ILP 상한을 분석한 후, ILP·TLP·DLP 비율을 설계에 반영하는 체계적 접근이 필요함
