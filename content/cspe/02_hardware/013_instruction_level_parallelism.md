## 미리 알고가기

- ILP는 하나의 스레드 내부에서 동시에 실행 가능한 명령어의 잠재 병렬성임
- 파이프라이닝·슈퍼스칼라·OoO가 ILP 활용 기술임
- RAW(Read-After-Write): 앞 명령의 쓰기 결과를 뒤 명령이 읽어야 하는 실제 데이터 의존성임
- 데이터·제어·자원 의존성이 ILP 상한을 제한함

## 작성 근거(검토용)

- ILP를 속도 일반론이 아니라 단일 명령어 흐름에서 독립 명령을 찾는 정도로 정의함
- ILP·TLP·DLP를 병렬 단위·대표 기술·주요 제약으로 구분함
- ILP는 명령어 의존 관계로 병렬 실행 범위가 정해지므로 일반 분석 절차 흐름도는 삭제함

## Ⅰ. 개요

- **정의/개념**: 명령어 수준 병렬성 ILP는 하나의 명령어 흐름 안에서 서로 독립적인 연산을 찾아 동시에 실행할 수 있는 정도를 뜻함
- **배경/필요성**: 클록 주파수 증가 없이 단일 스레드 처리량을 높이기 위해 독립 명령어의 병렬 실행이 필요함

## Ⅱ. 특징

- 단일 스레드에서 IPC를 높일 수 있는 병렬 실행 여지를 나타냄
- 파이프라인·슈퍼스칼라·OoO가 대표 활용 수단임
- RAW와 분기 의존성이 높을수록 ILP를 찾기 어려워짐
- 하드웨어 비용을 늘려도 코드 구조상 병렬성이 없으면 효과가 제한됨

## Ⅲ. 종류 및 비교

| 판단 기준 | ILP | TLP | DLP |
|:---|:---|:---|:---|
| 병렬 단위 | 명령어 | 스레드 | 데이터 |
| 대표 기술 | 파이프라인·비순서 실행 | 멀티코어·SMT | SIMD·GPU |
| 주요 제약 | 데이터·제어 의존성 | 동기화·공유 자원 경쟁 | 동일 연산을 적용할 데이터 배열 필요 |

> 요약: ILP는 한 스레드 안의 명령어를, TLP는 스레드를, DLP는 데이터를 병렬화함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 의존성 그래프 | 명령어 간 의존성을 표현해 병렬 실행 가능 범위를 결정함 |
| 명령어 창 | 동시에 관찰할 명령어 범위를 정해 독립 명령 탐색 범위를 결정함 |
| 컴파일러 최적화 | 루프 펼치기와 명령어 배치로 정적 ILP를 늘림 |
| 하드웨어 스케줄러 | 실행 준비가 끝난 명령 조합을 찾아 병렬 실행함 |

```text
+------------------+     +-------------------+     +--------------------+
| 의존성 그래프      | --> | 명령어 창          | --> | 하드웨어 스케줄러    |
+------------------+     +-------------------+     +--------------------+
             |
             v
      +------------------+
      | 컴파일러 최적화    |
      +------------------+
```

> 요약: 의존성 그래프와 명령어 윈도우가 병렬 실행 가능한 명령 범위를 결정함.

## Ⅵ. 실무 사례

1. 단일 스레드 수치 연산은 독립 명령을 늘리기 위해 루프 펼치기와 명령어 재배치를 적용하고, 의존성 대기율과 IPC로 검증함
2. 처리량 중심 서버 CPU는 ILP 증가가 포화되면 코어 수와 벡터 유닛에 면적을 배분하고, 면적당 처리량과 와트당 처리량으로 검증함

## Ⅶ. 결론

- ILP는 단일 스레드의 데이터·제어 의존성을 분석하고 IPC 증가량이 명령 윈도·발행 회로 비용을 상쇄하는 범위에서 활용해야 함
