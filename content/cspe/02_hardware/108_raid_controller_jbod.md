## 미리 알고가기

- RAID 컨트롤러는 여러 디스크를 논리 볼륨으로 묶어 보호와 캐시 기능을 제공함
- JBOD는 디스크를 개별 장치로 그대로 노출해 상위 소프트웨어가 직접 관리하게 함
- BBU나 supercap은 RAID write-back cache의 정전 시 데이터 보호 장치임

## Ⅰ. 개요

- **정의/개념**: RAID 컨트롤러는 디스크 집합을 논리 RAID 볼륨으로 구성해 미러링과 패리티와 캐시와 재구성을 하드웨어에서 처리하는 장치이고, JBOD는 디스크를 개별 장치로 그대로 노출하는 구성 방식임
- **배경/필요성**: 단일 서버는 단순한 보호와 부팅 구성이 필요할 수 있지만 분산 스토리지는 상위 소프트웨어가 복제와 장애 배치를 직접 통제해야 하므로, 데이터 보호 책임 위치를 구분해 선택해야 함

## Ⅱ. 특징

- RAID 컨트롤러는 OS 관점에서 단순한 볼륨 제공과 캐시 가속이 가능함
- JBOD는 디스크 가시성이 높아 SDS와 분산 스토리지에 유리함
- RAID는 컨트롤러 장애와 메타데이터 종속 위험이 있고 JBOD는 운영 소프트웨어 책임이 커짐
- 선택 기준은 성능보다 복구 절차와 장애 도메인과 운영 자동화 수준임

## Ⅲ. 종류 및 비교

| 판단 기준 | RAID 컨트롤러 | JBOD |
|:---|:---|:---|
| 디스크 노출 | 여러 디스크를 하나 이상의 논리 볼륨으로 묶어 노출함 | 디스크를 개별 물리 장치로 그대로 노출함 |
| 보호 기능 | 미러링과 패리티와 rebuild와 캐시를 하드웨어가 제공함 | 상위 파일시스템이나 분산 스토리지가 직접 수행함 |
| 장점 | 부트 볼륨과 단일 서버 운영을 단순하게 만들기 좋음 | 디스크 가시성과 유연성이 높아 분산 스토리지에 잘 맞음 |
| 유의점 | 컨트롤러 장애와 메타데이터 종속을 관리해야 함 | 복제와 재배치와 장애 정책을 상위 소프트웨어가 책임져야 함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| RAID 엔진 | stripe와 mirror와 parity 계산을 수행해 디스크 집합을 논리 저장장치처럼 보이게 함 |
| 캐시·전원 보호 | write-back 성능을 높이되 정전 시 데이터 무결성을 지키는 핵심 보호 장치가 됨 |
| HBA·JBOD 경로 | 디스크를 가공 없이 노출해 상위 소프트웨어가 복제와 배치를 직접 결정하게 함 |
| 상위 스토리지 소프트웨어 | JBOD 환경에서 복제와 scrub과 재배치를 담당해 실제 보호 수준을 결정함 |

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 디스크 인식    | --> | 구성 방식 선택 | --> | 볼륨·디스크 노출 | --> | 장애 복구      |
+-------------+     +-------------+     +-------------+     +-------------+
```

## Ⅴ. 원리 및 절차 흐름도

1. **디스크 인식**: 컨트롤러나 HBA가 연결된 디스크 상태를 파악함
2. **구성 방식 선택**: RAID 레벨 또는 JBOD 노출 정책을 정함
3. **볼륨·디스크 노출**: RAID는 논리 볼륨을, JBOD는 개별 디스크를 OS에 제공함
4. **장애 복구**: rebuild나 재복제나 spare 정책으로 장애 후 복구를 수행함

## Ⅵ. 실무 적용 및 유의점

1. 단일 서버 부트 볼륨과 중소 규모 데이터 저장은 RAID 컨트롤러가 편하지만 컨트롤러 장애와 write-back cache 보호 부재가 복구 지연과 손실로 이어질 수 있으므로 이중화와 BBU 상태 감시를 함께 두고 컨트롤러 절체 성공률과 정합성 검사 통과율과 재구성 시간으로 확인함
2. 분산 스토리지 노드는 JBOD가 디스크 가시성과 유연성에 유리하지만 상위 소프트웨어의 복제 정책이 약하면 디스크 장애가 바로 서비스 손실로 번지므로 장애 영역 정책과 자동 재복제를 함께 운영하고 성능 저하 상태의 복구 시간과 복제본 정상률과 디스크 가시성 점검률로 확인함

## Ⅶ. 결론

RAID 컨트롤러와 JBOD의 선택은 디스크를 어떻게 묶느냐보다 데이터 보호와 복구 책임을 어느 계층에 둘지 정하는 문제임.
