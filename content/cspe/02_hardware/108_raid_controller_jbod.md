## 미리 알고가기

- RAID 컨트롤러는 여러 디스크를 논리 볼륨으로 묶어 보호와 캐시 기능을 제공함
- JBOD는 디스크를 개별 장치로 그대로 노출해 상위 소프트웨어가 직접 관리하게 함
- BBU·슈퍼커패시터(supercap)는 RAID 라이트백(Write-back) 캐시의 정전 시 데이터 보호 장치임
- HBA는 서버와 디스크를 연결하되 RAID 기능 없이 디스크를 그대로 상위 계층에 전달하는 컨트롤러임
- SDS는 소프트웨어가 스토리지의 복제·배치·장애 정책을 관리하는 방식임

## 작성 근거(검토용)

- RAID·JBOD는 디스크 노출 단위, 보호·캐시 기능, 관리 주체, 장애 복구 책임을 핵심 축으로 설명함
- 비교표는 논리 볼륨과 개별 디스크 노출, 보호·관리 책임과 장애 리스크, 적합 환경을 대비함
- 실무 판단은 컨트롤러 절체·재구성 시간과 재복제 시간·복제본 정상률로 검증함

## Ⅰ. 개요

- **정의/개념**: RAID 컨트롤러는 디스크 집합을 논리 RAID 볼륨으로 구성해 미러링과 패리티와 캐시와 재구성을 하드웨어에서 처리하는 장치이고, JBOD는 디스크를 개별 장치로 그대로 노출하는 구성 방식임
- **배경/필요성**: 서버 로컬 볼륨과 분산 스토리지의 데이터 보호 책임을 구분하기 위해 RAID 컨트롤러와 JBOD의 선택 기준이 필요함

### 쉽게 이해하기 (학습용)
- RAID 컨트롤러는 여러 서랍을 하나의 큰 금고처럼 묶어 관리인이 보호해주는 것이고, JBOD는 서랍을 각각 그대로 두고 주인이 직접 정리·백업을 책임지는 것과 같음

## Ⅱ. 특징

- RAID 컨트롤러는 여러 디스크를 논리 볼륨으로 노출하고 라이트백 캐시를 제공함
- JBOD는 개별 디스크의 상태와 오류를 상위 SDS·분산 스토리지에 노출함
- RAID는 컨트롤러 장애와 메타데이터 종속 위험이 있고 JBOD는 운영 소프트웨어 책임이 커짐
- 선택 기준은 성능보다 복구 절차와 장애 도메인과 운영 자동화 수준임

### 쉽게 이해하기 (학습용)
- 금고 관리인(RAID 컨트롤러)이 다치면 금고 전체가 문제가 되고, 서랍 주인들(JBOD 상위 소프트웨어)이 각자 챙기면 그만큼 각자의 관리 부담이 커짐

## Ⅲ. 종류 및 비교

| 판단 기준 | RAID 컨트롤러 | JBOD |
|:---|:---|:---|
| 디스크 노출 | 여러 디스크를 하나 이상의 논리 볼륨으로 묶어 노출함 | 디스크를 개별 물리 장치로 그대로 노출함 |
| 보호·관리 책임 | 컨트롤러가 미러링·패리티·캐시·재구성을 관리하며 컨트롤러 장애·메타데이터 종속을 감수함 | 상위 소프트웨어가 디스크·복제·재배치를 관리하며 복제·장애 정책 책임을 감수함 |
| 적합 환경 | 단일 서버의 부트·로컬 데이터 볼륨 | SDS·분산 스토리지의 데이터 노드 |

> 요약: RAID는 컨트롤러가 보호·캐시·재구성을 담당하고 JBOD는 개별 디스크를 상위 소프트웨어에 노출함.

### 쉽게 이해하기 (학습용)
- 여러 서랍을 하나의 금고로 묶어 파는 매장(RAID)과, 서랍을 각각 낱개로 진열해두고 손님이 골라 담게 하는 매장(JBOD)의 차이와 같음

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| RAID 엔진 | 스트라이핑·미러링·패리티 계산을 수행해 디스크 집합을 논리 저장장치로 제공함 |
| 캐시·전원 보호 | 라이트백 캐시와 BBU가 정전 시 미반영 데이터를 보존함 |
| HBA·JBOD 경로 | 디스크를 가공 없이 노출해 상위 소프트웨어가 복제와 배치를 직접 결정하게 함 |
| 상위 스토리지 소프트웨어 | JBOD 환경에서 복제·스크럽·재배치를 담당해 데이터 보호 수준을 결정함 |

> 요약: RAID는 컨트롤러의 논리 볼륨·캐시 경로를 사용하고 JBOD는 HBA를 통해 개별 디스크를 상위 소프트웨어에 노출함.

### 쉽게 이해하기 (학습용)
- RAID 엔진은 여러 서랍을 하나로 묶는 조립공이고, 캐시·전원 보호는 정전에도 방금 넣은 물건이 사라지지 않게 하는 완충장치이며, JBOD 경로는 서랍을 그대로 전달해 위층 관리자(상위 소프트웨어)가 배치를 정하게 함

## Ⅴ. 원리 및 절차 흐름도

1. **디스크 인식**: 컨트롤러나 HBA가 연결된 디스크 상태를 파악함
2. **구성 방식 선택**: RAID 레벨 또는 JBOD 노출 정책을 정함
3. **볼륨·디스크 노출**: RAID는 논리 볼륨을, JBOD는 개별 디스크를 OS에 제공함
4. **장애 복구**: 재구성·재복제·예비 디스크 정책으로 장애 후 복구를 수행함

> 요약: RAID는 논리 볼륨 구성과 재구성을, JBOD는 디스크 노출과 재복제를 각각 컨트롤러와 상위 소프트웨어가 수행함.

### 쉽게 이해하기 (학습용)
- 서랍을 먼저 확인하고(디스크 인식), 금고로 묶을지 낱개로 둘지 정한 뒤(구성 방식 선택) 그대로 내보이고(노출), 하나가 고장 나면 정해둔 방식대로 채워 넣는(장애 복구) 순서와 같음

## Ⅵ. 실무 사례

1. 서버 부트 볼륨은 RAID 컨트롤러 이중화와 BBU 상태 감시를 적용하고 컨트롤러 절체 성공률·재구성 시간을 확인함
2. 분산 스토리지 노드는 JBOD와 자동 재복제를 적용하고 재복제 시간·복제본 정상률을 확인함

### 쉽게 이해하기 (학습용)
- 서버 한 대의 부팅용 서랍은 금고 관리인의 이중화로 지키고, 여러 노드에 흩어진 분산 저장소는 서랍을 낱개로 두되 사본을 자동으로 다시 채워 넣는 방식으로 지킴

## Ⅶ. 결론

- RAID 컨트롤러는 여러 디스크를 논리 볼륨으로 묶어 미러링·패리티·캐시·재구성을 하드웨어가 대신 처리하고, JBOD는 디스크를 그대로 노출해 상위 소프트웨어가 보호 책임을 짐
- 단일 서버의 부트·로컬 볼륨은 RAID 컨트롤러 이중화로, SDS·분산 스토리지 노드는 JBOD와 자동 재복제로 장애 복구 책임을 나눠야 함

### 쉽게 이해하기 (학습용)
- 금고 관리인에게 맡길지, 서랍 주인이 직접 지킬지는 결국 누가 그 책임을 지는 게 더 안전하고 효율적인지의 문제임
