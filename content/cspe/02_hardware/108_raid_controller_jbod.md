## 미리 알고가기

- RAID 컨트롤러는 여러 디스크를 논리 볼륨으로 묶어 보호와 캐시 기능을 제공함
- JBOD는 디스크를 개별 장치로 그대로 노출해 상위 소프트웨어가 직접 관리하게 함
- BBU·슈퍼커패시터(supercap)는 RAID Write-back 캐시의 정전 시 데이터 보호 장치임

## 작성 근거(검토용)

- RAID·JBOD는 디스크 노출 단위, 보호·캐시 기능, 관리 주체, 장애 복구 책임을 핵심 축으로 설명함
- 비교표는 논리 볼륨과 개별 디스크 노출, 하드웨어·소프트웨어 보호, 장애 조건을 대비함
- 실무 판단은 컨트롤러 절체·재구성 시간과 재복제 시간·복제본 정상률로 검증함

## Ⅰ. 개요

- **정의/개념**: RAID 컨트롤러는 디스크 집합을 논리 RAID 볼륨으로 구성해 미러링과 패리티와 캐시와 재구성을 하드웨어에서 처리하는 장치이고, JBOD는 디스크를 개별 장치로 그대로 노출하는 구성 방식임
- **배경/필요성**: 서버 로컬 볼륨과 분산 스토리지의 데이터 보호 책임을 구분하기 위해 RAID 컨트롤러와 JBOD의 선택 기준이 필요함

## Ⅱ. 특징

- RAID 컨트롤러는 여러 디스크를 논리 볼륨으로 노출하고 Write-back 캐시를 제공함
- JBOD는 개별 디스크의 상태와 오류를 상위 SDS·분산 스토리지에 노출함
- RAID는 컨트롤러 장애와 메타데이터 종속 위험이 있고 JBOD는 운영 소프트웨어 책임이 커짐
- 선택 기준은 성능보다 복구 절차와 장애 도메인과 운영 자동화 수준임

## Ⅲ. 종류 및 비교

| 판단 기준 | RAID 컨트롤러 | JBOD |
|:---|:---|:---|
| 디스크 노출 | 여러 디스크를 하나 이상의 논리 볼륨으로 묶어 노출함 | 디스크를 개별 물리 장치로 그대로 노출함 |
| 보호·관리 책임 | 컨트롤러가 미러링·패리티·캐시·재구성을 관리함 | 상위 소프트웨어가 디스크·복제·재배치를 관리함 |
| 적합 환경 | 단일 서버의 부트·로컬 데이터 볼륨 | SDS·분산 스토리지의 데이터 노드 |
| 유의점 | 컨트롤러 장애와 메타데이터 종속을 관리해야 함 | 복제와 재배치와 장애 정책을 상위 소프트웨어가 책임져야 함 |

> 요약: RAID는 컨트롤러가 보호·캐시·재구성을 담당하고 JBOD는 개별 디스크를 상위 소프트웨어에 노출함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| RAID 엔진 | 스트라이핑·미러링·패리티 계산을 수행해 디스크 집합을 논리 저장장치로 제공함 |
| 캐시·전원 보호 | Write-back 캐시와 BBU가 정전 시 미반영 데이터를 보존함 |
| HBA·JBOD 경로 | 디스크를 가공 없이 노출해 상위 소프트웨어가 복제와 배치를 직접 결정하게 함 |
| 상위 스토리지 소프트웨어 | JBOD 환경에서 복제·스크럽·재배치를 담당해 데이터 보호 수준을 결정함 |

> 요약: RAID는 컨트롤러의 논리 볼륨·캐시 경로를 사용하고 JBOD는 HBA를 통해 개별 디스크를 상위 소프트웨어에 노출함.

## Ⅴ. 원리 및 절차 흐름도

1. **디스크 인식**: 컨트롤러나 HBA가 연결된 디스크 상태를 파악함
2. **구성 방식 선택**: RAID 레벨 또는 JBOD 노출 정책을 정함
3. **볼륨·디스크 노출**: RAID는 논리 볼륨을, JBOD는 개별 디스크를 OS에 제공함
4. **장애 복구**: 재구성·재복제·예비 디스크 정책으로 장애 후 복구를 수행함

> 요약: RAID는 논리 볼륨과 재구성을 컨트롤러가, JBOD는 디스크 노출과 재복제를 상위 소프트웨어가 수행함.

## Ⅵ. 실무 사례

1. 서버 부트 볼륨은 RAID 컨트롤러 이중화와 BBU 상태 감시를 적용하고 컨트롤러 절체 성공률·재구성 시간을 확인함
2. 분산 스토리지 노드는 JBOD와 자동 재복제를 적용하고 재복제 시간·복제본 정상률을 확인함

## Ⅶ. 결론

- RAID 컨트롤러와 JBOD는 데이터 보호·캐시·장애 복구 책임을 하드웨어와 상위 소프트웨어 중 어디에 둘지에 따라 선택해야 함
