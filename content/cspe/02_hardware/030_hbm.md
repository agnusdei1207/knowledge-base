## 미리 알고가기

- HBM은 여러 DRAM 다이를 TSV로 수직 적층해 넓은 I/O 폭을 제공하는 메모리임
- 인터포저는 GPU나 가속기와 HBM 스택을 근거리에서 고밀도로 연결하는 기판임
- 메모리 장벽은 연산 성능 증가 속도를 메모리 대역폭이 따라가지 못하는 병목을 뜻함

## Ⅰ. 개요

- **정의/개념**: HBM은 다수의 DRAM 다이를 TSV와 마이크로 범프로 적층하고 프로세서 옆에 넓은 병렬 인터페이스로 연결해 높은 대역폭과 비트당 전력 효율을 제공하는 3D 메모리 구조임
- **배경/필요성**: AI·HPC의 메모리 대역폭 병목을 줄이기 위해 신호 거리를 줄이고 입출력 폭을 넓힌 적층 메모리가 필요함

## Ⅱ. 특징

- 넓은 버스 폭으로 GDDR보다 높은 총 대역폭을 제공함
- 프로세서와 인터포저로 근접 연결해 배선 길이와 비트당 전송 에너지를 줄임
- TSV 적층과 인터포저 패키징이 필요해 제조 비용과 수율 부담이 큼
- 고대역폭을 제공하는 대신 열 밀도와 용량 확장 한계가 운영 리스크로 남음

## Ⅲ. 종류 및 비교

| 판단 기준 | GDDR | HBM |
|:---|:---|:---|
| 배치 구조 | 보드 위 여러 칩을 수평 배치함 | 패키지 내부에서 여러 다이를 수직 적층함 |
| 대역폭 확보 방식 | 핀당 속도를 높여 대역폭을 늘림 | I/O 폭을 넓혀 총 대역폭을 늘림 |
| 강점 | 표준 DIMM 증설과 용량 확장이 가능함 | 넓은 I/O로 대역폭을 확보하고 비트당 전송 에너지를 줄임 |
| 한계 | 긴 배선과 전력 소모가 커짐 | 패키징 복잡도와 수율·열 관리 부담이 큼 |

> 요약: GDDR은 보드 확장성이 높고, HBM은 패키지 내부에서 넓은 I/O로 대역폭을 확보함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| DRAM Stack | 여러 메모리 다이를 쌓아 같은 면적에서 더 많은 bank·용량·대역폭을 제공함 |
| TSV and Micro-Bump | 적층 다이와 인터포저 사이를 짧은 전기 경로로 연결해 넓은 병렬 I/O를 구현함 |
| Base Logic Die | 스택 하단에서 채널 제어·테스트·신호 정렬을 담당함 |
| Silicon Interposer | 프로세서와 여러 HBM 스택을 고밀도 배선으로 연결해 패키지 내부 초고속 통신을 지원함 |

```text
      +-------------+
      | DRAM Die    |
      +-------------+
      | DRAM Die    |
      +-------------+
      | DRAM Die    |
      +-------------+
      | Base Logic  |
      +-------------+
            |
            v
      +-------------+
      | Interposer  |
      +-------------+
            |
            v
      +-------------+
      | GPU / NPU   |
      +-------------+
```

> 요약: HBM은 적층 DRAM, TSV, base die, 인터포저를 묶어 프로세서 근처에 대역폭을 배치함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 가속기 메모리 요청 | --> | base die 채널 분배 | --> | 다중 bank 병렬 접근 | --> | 넓은 I/O로 데이터 반환 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **가속기 메모리 요청**: GPU나 NPU가 대량의 tensor 또는 벡터 데이터를 요구함
2. **base die 채널 분배**: 요청을 여러 채널과 bank에 나눠 병렬 접근을 준비함
3. **다중 bank 병렬 접근**: 적층된 DRAM 내부에서 동시에 데이터를 읽거나 씀
4. **넓은 I/O로 데이터 반환**: 인터포저 경로를 통해 프로세서에 대량 데이터를 짧은 거리로 전달함

> 요약: HBM은 요청을 여러 채널과 bank로 분산해 짧은 인터포저 경로로 대량 데이터를 반환함.

## Ⅵ. 실무 적용 및 유의점

1. TSV 적층과 인터포저 결합은 불량 민감도가 높으므로 known good die 선별과 hybrid bonding 검증을 강화하고 package yield, cost per GB로 확인함
2. 프로세서와 메모리가 밀집되면 열 밀도가 높아지므로 고성능 냉각과 열 분산 패키지를 적용하고 junction temperature, thermal throttling rate로 확인함
3. 패키지 내부 적층 수와 면적은 용량 확장을 제한하므로 HBM과 외부 CXL memory tier를 결합하고 hot data residency, capacity overflow latency로 확인함

## Ⅶ. 결론

HBM은 메모리 속도 자체보다 연산기 가까이에 대역폭을 배치해 memory wall을 완화하는 패키지 설계임.

## 작성 근거(검토용)

- HBM은 메모리 이름보다 TSV, base die, 인터포저, 넓은 I/O의 패키지 구조로 설명함
- 모호한 표현은 package yield, junction temperature, hot data residency로 구체화함
- 결론은 메모리 속도 우열보다 memory wall 완화와 워크로드 대역폭 활용으로 정리함
