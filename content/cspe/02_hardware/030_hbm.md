## 미리 알고가기

- HBM은 여러 DRAM 다이를 TSV로 수직 적층해 넓은 I/O 폭을 제공하는 메모리임
- 인터포저는 GPU나 가속기와 HBM 스택을 근거리에서 고밀도로 연결하는 기판임
- 메모리 wall은 연산 성능 증가 속도를 메모리 대역폭이 따라가지 못하는 병목을 뜻함

## Ⅰ. 개요

- **정의/개념**: HBM은 다수의 DRAM 다이를 TSV와 micro-bump로 적층하고 프로세서 옆에 넓은 병렬 인터페이스로 연결해 매우 높은 대역폭과 우수한 bit당 전력 효율을 제공하는 3D 메모리 구조임
- **배경/필요성**: AI 학습과 HPC는 연산기 수가 빠르게 늘어나지만 외부 메모리 대역폭이 따라오지 못해 memory wall이 심해지므로, 신호 거리를 줄이고 I/O 폭을 크게 늘린 패키지 수준 혁신이 필요함

## Ⅱ. 특징

- 매우 넓은 버스 폭으로 GDDR보다 높은 총 대역폭을 제공함
- 프로세서와 근접 배치되어 bit당 에너지 효율이 좋고 신호 무결성에도 유리함
- TSV 적층과 인터포저 패키징이 필요해 제조 비용과 수율 부담이 큼
- 고대역폭을 제공하는 대신 열 밀도와 용량 확장 한계가 운영 리스크로 남음

## Ⅲ. 종류 및 비교

| 판단 기준 | GDDR | HBM |
|:---|:---|:---|
| 배치 구조 | 보드 위 여러 칩을 수평 배치함 | 패키지 내부에서 여러 다이를 수직 적층함 |
| 대역폭 확보 방식 | 핀당 속도를 높여 대역폭을 늘림 | I/O 폭을 크게 넓혀 총 대역폭을 늘림 |
| 강점 | 비용과 확장성이 상대적으로 유리함 | 대역폭과 bit당 전력 효율이 우수함 |
| 한계 | 긴 배선과 전력 소모가 커짐 | 패키징 복잡도와 수율과 열 관리 부담이 큼 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| DRAM Stack | 여러 메모리 다이를 쌓아 같은 면적에서 더 많은 bank와 용량과 대역폭을 제공함 |
| TSV and Micro-Bump | 적층 다이와 인터포저 사이를 짧은 전기 경로로 연결해 넓은 병렬 I/O를 구현함 |
| Base Logic Die | 스택 하단에서 채널 제어와 테스트와 신호 정렬을 담당함 |
| Silicon Interposer | 프로세서와 여러 HBM 스택을 고밀도 배선으로 연결해 패키지 내부 초고속 통신을 지원함 |

```text
      +-------------+
      | DRAM Die    |
      +-------------+
      | DRAM Die    |
      +-------------+
      | DRAM Die    |
      +-------------+
      | Base Logic  |
      +-------------+
            |
            v
      +-------------+
      | Interposer  |
      +-------------+
            |
            v
      +-------------+
      | GPU / NPU   |
      +-------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 가속기 메모리 요청 | --> | base die 채널 분배 | --> | 다중 bank 병렬 접근 | --> | 넓은 I/O로 데이터 반환 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **가속기 메모리 요청**: GPU나 NPU가 대량의 tensor 또는 벡터 데이터를 요구함
2. **base die 채널 분배**: 요청을 여러 채널과 bank에 나눠 병렬 접근을 준비함
3. **다중 bank 병렬 접근**: 적층된 DRAM 내부에서 동시에 데이터를 읽거나 씀
4. **넓은 I/O로 데이터 반환**: 인터포저 경로를 통해 프로세서에 대량 데이터를 짧은 거리로 전달함

## Ⅵ. 문제점 및 해결 방안

1. 문제: TSV 적층과 인터포저 결합 공정은 불량 민감도가 높아 제조 수율과 원가 부담을 크게 키움
   - 해결방안: known good die 선별과 hybrid bonding 검증을 강화하고 package yield와 cost per GB로 검증함
2. 문제: 프로세서와 메모리가 밀집 배치되면 열 밀도가 높아져 성능 저하와 신뢰성 문제가 발생할 수 있음
   - 해결방안: 고성능 냉각과 열 분산 패키지 구조를 적용하고 junction temperature와 thermal throttling rate로 검증함
3. 문제: 패키지 내부 적층 수와 면적 제약 때문에 용량 확장이 필요한 워크로드에서는 한계가 드러날 수 있음
   - 해결방안: HBM과 외부 CXL 메모리 tier를 결합하고 hot data residency와 capacity overflow latency로 검증함

## Ⅶ. 적용 사례

- 대형 AI 학습 GPU는 HBM을 사용해 tensor 공급 병목을 줄이고 확인 지표는 memory bandwidth utilization과 accelerator idle ratio임
- 슈퍼컴퓨터 노드는 HBM 기반 가속기로 수치해석 throughput을 높이고 확인 지표는 flops efficiency와 memory stall ratio임
- 고성능 네트워크 스위치는 대용량 버퍼와 룩업 경로를 HBM에 배치해 패킷 처리를 가속하고 확인 지표는 packets per second와 lookup latency임

## Ⅷ. 결론

HBM의 본질은 메모리 속도 자체보다 연산기 옆으로 대역폭을 끌어와 memory wall을 패키지 수준에서 해결하는 데 있으므로, 설계 판단은 GB당 비용보다 필요한 워크로드가 그 대역폭을 실제로 활용하는지에 맞춰야 함.
