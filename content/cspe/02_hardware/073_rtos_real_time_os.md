## Ⅰ. 개요
- **정의**: 태스크의 실행 완료 시점을 보장하는 결정론적 스케줄링 기반 운영체제
- **배경/필요성**: 범용 OS는 처리량 최적화를 우선하여 응답 시간을 보장하지 못하므로, 시간 제약이 있는 제어 시스템에 전용 OS가 필요함
- **비유**: 범용 OS가 뷔페 식당(처리량 우선)이라면, RTOS는 응급실(마감 시한 우선)임

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 실시간 스케줄링 원리 이해 | 결정론적 응답 + 선점형 우선순위 스케줄링 | Hard/Soft 구분(074 참조)과 혼동 말 것, RTOS 자체는 커널 구조 |

> 요약: RTOS는 데드라인 준수를 최우선으로 설계된 결정론적 운영체제임

## Ⅱ. 구성요소
```text
Application Tasks
       |
  +----v-----+
  | Scheduler |--- Priority Queue
  +----+------+
       |
  +----v-----+       +------------+
  |  Kernel   |<----->| Timer/ISR  |
  +----+------+       +------------+
       |
  +----v-----+
  | HAL/BSP  |
  +----------+
       |
    Hardware
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 스케줄러 | 우선순위 기반으로 태스크 실행 순서를 결정하는 핵심 모듈 | 응급실 트리아지 간호사 |
| 커널 | 태스크 생성·동기화·IPC 등 OS 핵심 서비스를 제공함 | 병원의 중앙 관리 시스템 |
| 타이머/ISR | 주기적 틱 인터럽트와 외부 이벤트를 처리하여 스케줄러에 전달함 | 호출 벨과 응급 알람 |
| HAL/BSP | 하드웨어 추상화 계층으로 보드별 차이를 커널에서 분리함 | 통역사(HW 언어를 SW 언어로 변환) |

> 요약: 스케줄러·커널·타이머·HAL이 계층적으로 결합하여 결정론적 실행을 보장함

## Ⅲ. 절차
```text
Step1 Init --> Step2 Task Create --> Step3 Schedule --> Step4 Dispatch
  HW/BSP       Register tasks        Select highest      Context switch
  setup        + set priority         priority task       + execute
```
- 1단계: 초기화 — BSP가 클럭·인터럽트 벡터·주변장치를 설정함
- 2단계: 태스크 생성 — 각 태스크를 우선순위와 함께 레디 큐에 등록함
- 3단계: 스케줄링 — 틱 인터럽트 또는 이벤트 발생 시 가장 높은 우선순위 태스크를 선택함
- 4단계: 디스패치 — 컨텍스트 스위칭을 수행하고 선택된 태스크를 CPU에서 실행함

> 요약: 초기화 → 태스크 등록 → 우선순위 선택 → 컨텍스트 스위칭의 4단계 루프로 동작함

## Ⅳ. 문제점
- 우선순위 역전: 저우선순위 태스크가 점유한 자원을 고우선순위 태스크가 대기하여 데드라인을 위반함 (075 참조)
- 인터럽트 지연: ISR 중첩·비활성화 구간이 길어지면 응답 시간이 증가하여 실시간성이 훼손됨 (075 참조)
- 메모리 단편화: 동적 할당 반복 시 힙 단편화로 할당 실패가 발생하여 태스크 생성이 불가해짐

> 요약: 우선순위 역전·인터럽트 지연·메모리 단편화가 RTOS 운용의 주요 위험 요소임

## Ⅴ. 개선방안
1. 단기: 우선순위 상속(Priority Inheritance) 프로토콜을 적용하여 역전 구간을 최소화함
2. 중기: 인터럽트 처리를 지연 처리(Deferred Procedure) 방식으로 전환하여 ISR 실행 시간을 단축함
3. 장기: 정적 메모리 풀 할당 정책을 채택하여 힙 단편화를 원천 차단함

> 요약: 우선순위 상속 → 지연 처리 → 정적 메모리 풀 순으로 RTOS 안정성을 확보함

## Ⅵ. 전망
- 발전 방향: 안전 인증(IEC 61508, DO-178C) 내장형 RTOS가 자율주행·의료기기 분야에서 확대될 전망임
- 기술사적 판단: POSIX 호환 RTOS와 마이크로커널 구조가 이식성과 보안을 동시에 충족하는 표준이 될 것임
- 기술사 제언: RTOS 선정 시 스케줄링 정책·인증 등급·HAL 지원 범위를 함께 평가할 필요
