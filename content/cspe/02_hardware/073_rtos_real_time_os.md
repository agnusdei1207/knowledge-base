## Ⅰ. 개요
- **정의**: 주어진 데드라인 내에 태스크 응답을 보장하는 운영체제임
- **배경/필요성**: 자동차·의료·산업제어 등 미션크리티컬 시스템에서 응답 지연이 인명·재산 피해로 직결됨
- **비유**: 응급실 트리아지처럼 긴급도에 따라 처리 순서를 결정하는 체계임

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| Hard/Soft RT 구분과 스케줄링 | 결정론적 응답 보장 메커니즘 | GPOS와의 차이를 명확히 서술할 것 |

> 요약: 데드라인 준수를 보장하여 미션크리티컬 환경의 신뢰성을 확보하는 OS임

## Ⅱ. 구성요소
```text
Application Tasks
       |
  +----+----+
  |         |
Scheduler  IPC
  |         |
  +----+----+
       |
   RT Kernel --> HAL --> Hardware
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| RT Kernel | 선점형 스케줄링·인터럽트 지연 최소화를 담당하는 핵심 계층 | 교통 관제탑의 우선순위 배정 |
| Scheduler | 우선순위 기반(Rate Monotonic, EDF 등)으로 태스크 실행 순서를 결정함 | 트리아지 간호사의 환자 분류 |
| HAL | 하드웨어 추상화 계층으로 타이머·GPIO 등을 표준 API로 제공함 | 만국 공통 콘센트 어댑터 |

> 요약: RT 커널·스케줄러·HAL로 결정론적 태스크 실행 환경을 구성함

## Ⅲ. 절차
```text
인터럽트 발생 --> 컨텍스트 저장 --> 스케줄링 --> 태스크 실행
      |               |               |              |
      v               v               v              v
   ISR진입        레지스터보존    우선순위비교     데드라인내완료
```
- 1단계: 하드웨어 인터럽트 발생 시 ISR이 즉시 진입함
- 2단계: 현재 태스크의 레지스터·스택을 컨텍스트에 저장함
- 3단계: 스케줄러가 우선순위를 비교하여 다음 실행 태스크를 선택함
- 4단계: 선택된 태스크가 데드라인 내에 실행을 완료함

> 요약: 인터럽트-저장-스케줄링-실행 4단계로 결정론적 응답을 보장함

## Ⅳ. 문제점
- 우선순위 역전: 저우선순위 태스크가 공유 자원을 점유하여 고우선순위 태스크가 대기함
- 최악 실행시간 분석 난이도: WCET 산출이 복잡하여 데드라인 보장 검증이 어려움
- 제한된 범용성: 메모리 보호·파일시스템 등 GPOS 기능이 축소되어 개발 편의성이 낮음

> 요약: 우선순위 역전·WCET 분석·범용성 부족이 RTOS의 주요 과제임

## Ⅴ. 개선방안
1. 단기: Priority Inheritance Protocol 적용으로 우선순위 역전을 방지함
2. 중기: 정적 분석 도구(aiT 등)를 활용하여 WCET 산출 정확도를 향상함
3. 장기: RTOS 위에 POSIX 호환 계층을 제공하여 범용 개발 환경과의 호환성을 확보함

> 요약: 프로토콜·분석도구·호환계층으로 RTOS 한계를 단계적으로 보완함

## Ⅵ. 전망
- 발전 방향: 자율주행·스마트팩토리 확산으로 멀티코어 RTOS 수요가 증가함
- 기술사적 판단: Safety 인증(ISO 26262, IEC 62304)과 RTOS 연동이 표준화될 전망임
- 기술사 제언: 안전등급별 RTOS 선정 기준과 WCET 검증 체계를 사전에 수립할 필요가 있음
