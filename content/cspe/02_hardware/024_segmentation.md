## 미리 알고가기

- 세그먼트는 코드, 데이터, 스택처럼 의미가 다른 주소 영역을 말함
- 세그먼트 테이블은 각 영역의 시작 주소, 길이, 권한을 관리함
- 가변 크기 할당이라 외부 단편화가 생길 수 있음
- 메모리 압축(Compaction): 외부 단편화를 줄이기 위해 세그먼트를 재배치해 빈 공간을 하나로 모으는 작업임

## 작성 근거(검토용)

- 세그멘테이션은 물리 배치보다 논리 단위, 기준 주소·길이, 권한 검사를 중심으로 설명함
- 세그멘테이션과 페이징을 관리 단위·배치 방식·단편화로 비교함
- 논리 영역별 보호 요구와 외부 단편화 비용을 적용 판단으로 정리함

## Ⅰ. 개요

- **정의/개념**: 세그멘테이션은 프로세스 주소 공간을 논리 단위별 가변 크기 세그먼트로 나누고, 각 세그먼트의 기준 주소·길이·보호 속성을 관리하는 메모리 구조임
- **배경/필요성**: 코드·데이터·스택의 서로 다른 크기와 보호 요구를 반영하기 위해 논리 구조별 보호·공유 단위가 필요함

## Ⅱ. 특징

- 프로그램 논리 구조에 맞춰 영역을 나누고 세그먼트별 보호·공유 정책을 설정함
- 세그먼트별 크기와 성장 방향을 따로 설정해 스택과 힙을 관리함
- 세그먼트 권한으로 코드 실행 영역과 데이터 수정 영역을 분리함
- 가변 크기 할당 특성상 외부 단편화와 메모리 압축 부담이 커질 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 세그멘테이션 | 페이징 |
|:---|:---|:---|
| 관리 단위 | 논리 영역별 가변 크기 세그먼트 | 고정 크기 페이지·프레임 |
| 배치 방식 | 세그먼트별 연속 영역에 배치함 | 같은 크기의 임의 프레임에 배치함 |
| 단편화 | 세그먼트 사이 외부 단편화가 발생함 | 마지막 페이지의 내부 단편화가 발생함 |

> 요약: 세그멘테이션은 논리 단위로 유연하게 배치하지만 외부 단편화가 발생하고, 페이징은 고정 크기로 단순하게 배치하지만 내부 단편화가 발생함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 세그먼트 번호·오프셋 | 논리 주소를 세그먼트 식별자와 내부 위치로 나눔 |
| 세그먼트 테이블 | 각 세그먼트의 기준 주소·길이·권한을 기록함 |
| 범위·권한 검사기 | 오프셋의 길이 초과 여부와 읽기·쓰기·실행 권한을 검사함 |
| 물리 할당 영역 | 세그먼트별 연속 저장 공간을 제공함 |

```text
+-------------------+     +-------------------+     +------------------+
| 세그먼트 번호/오프셋 | --> | 세그먼트 테이블      | --> | 기준 주소+오프셋   |
+-------------------+     +-------------------+     +------------------+
                                   |
                                   v
                           +-------------------+
                           | 길이/권한 검사      |
                           +-------------------+
```

> 요약: 세그먼트 번호와 오프셋은 기준 주소·길이·권한 검사를 거쳐 물리 주소 또는 보호 예외로 이어짐.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 논리 주소 입력   | --> | 세그먼트 엔트리 조회 | --> | 범위·권한 검사   | --> | 물리 주소 생성   |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **논리 주소 입력**: CPU가 세그먼트 번호와 오프셋을 가진 주소를 전달함
2. **세그먼트 엔트리 조회**: 해당 세그먼트의 기준 주소·길이·권한을 읽음
3. **범위와 권한 검사**: 오프셋이 길이를 넘거나 권한이 없으면 예외를 발생시킴
4. **물리 주소 생성**: 조건을 만족하면 기준 주소와 오프셋을 더해 최종 주소를 만듦

> 요약: 세그먼트 접근은 논리 주소를 조회하고 범위·권한을 통과해야 물리 주소가 됨.

## Ⅵ. 실무 사례

1. 가변 세그먼트 메모리 관리기는 페이징 결합 구조를 적용하고 외부 단편화율과 할당 실패율을 확인함
2. 보호 영역을 분리하는 런타임은 세그먼트별 실행·쓰기 권한을 설정하고 권한 위반 예외 건수와 주소 변환 지연을 확인함

## Ⅶ. 결론

- 세그멘테이션은 논리 영역별 보호·공유 요구와 외부 단편화 비용을 비교해 적용해야 함
