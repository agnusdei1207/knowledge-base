## 미리 알고가기

- **세그먼트(Segment)**: 프로그램의 주소 공간을 논리적 단위(코드, 데이터, 스택 등)로 나눈 가변 크기의 메모리 블록
- **세그먼트 테이블(Segment Table)**: 각 세그먼트의 시작 주소(Base)와 크기(Limit) 정보를 저장하는 매핑 테이블
- **외부 단편화(External Fragmentation)**: 메모리 할당과 해제가 반복되면서 중간중간 작은 빈 공간이 생겨 실제 가용 공간은 충분하나 큰 세그먼트를 할당하지 못하는 현상
- **보호(Protection)**: 세그먼트별로 읽기, 쓰기, 실행 권한을 다르게 부여하여 메모리 안전성을 확보하는 기능

## Ⅰ. 개요

- **정의/개념**: 세그멘테이션(Segmentation)은 프로세스의 주소 공간을 고정된 크기가 아닌, 프로그램의 논리적 의미 단위(함수, 객체, 라이브러리 등)로 나누어 관리하는 메모리 관리 기법임
- **배경/필요성**: 페이징은 물리적 효율이 높지만, 하나의 함수가 여러 페이지에 걸치거나 코드와 데이터가 섞여 있어 권한 관리나 공유가 복잡함. 세그멘테이션은 프로그래머가 바라보는 논리적 구조와 실제 메모리 배치를 일치시켜 모듈별 보안과 공유를 직관적으로 처리하기 위해 도입됨

## Ⅱ. 특징 및 비교

### 가. 세그멘테이션과 페이징의 핵심 대비

| 구분 | 세그멘테이션 (Segmentation) | 페이징 (Paging) |
|:---|:---|:---|
| 분할 기준 | 논리적 단위 (의미 중심) | 물리적 단위 (크기 중심) |
| 단위 크기 | 가변 크기 | 고정 크기 (4KB 등) |
| 주소 구성 | 세그먼트 번호 + 오프셋 | 페이지 번호 + 오프셋 |
| 관리 테이블 | 세그먼트 테이블 (Base, Limit) | 페이지 테이블 (Frame Number) |
| 단편화 문제 | 외부 단편화 발생 가능 | 내부 단편화 발생 가능 |
| 주요 강점 | 보호 및 공유 관리가 직관적임 | 메모리 교체 및 할당이 단순함 |

> 요약: 세그멘테이션은 '의미'를 중시하고, 페이징은 '공간 활용'을 중시함

### 나. 세그멘테이션의 주요 장점
- **논리적 보호**: 코드 영역은 읽기/실행 전용, 데이터 영역은 읽기/쓰기 전용으로 명확히 구분 가능
- **코드 공유**: 공유 라이브러리를 하나의 세그먼트로 등록하여 여러 프로세스가 동일한 주소로 참조 가능
- **동적 확장**: 스택이나 힙 세그먼트의 크기를 프로그램 실행 중에 유연하게 조절 가능

## Ⅲ. 구성요소/구조

### 가. 세그멘테이션 주소 변환 아키텍처

```text
[논리 주소 (s, d)] -> [세그먼트 테이블 조회] -> [한계값(Limit) 체크] -> [물리 주소 계산]
   s: 세그먼트 번호          |                           |                  (Base + d)
   d: 변위 (Offset)          v                           v
                      [Base 주소 획득]          (d > Limit 이면 Trap)
```

### 나. 주요 구성 요소 및 역할

| 구성요소 | 역할 및 설명 | 핵심 포인트 |
|:---|:---|:---|
| 세그먼트 번호 (s) | 프로세스 내에서 특정 세그먼트를 지칭하는 인덱스 | 테이블 조회의 키값 |
| 변위 (d, Offset) | 세그먼트 시작점에서 얼마나 떨어졌는지 나타내는 값 | 0 ~ (Limit-1) 범위여야 함 |
| 기준 (Base) | 세그먼트가 물리 메모리에서 시작하는 실제 위치 | 실제 주소 계산의 시작점 |
| 한계 (Limit) | 세그먼트의 실제 크기 | 메모리 침범 방지의 기준선 |
| 보호 비트 (Rights) | 읽기(R), 쓰기(W), 실행(X) 권한 정보 | 권한 없는 접근 시 Segmentation Fault 유발 |

> 요약: 세그먼트 테이블은 각 구역의 '시작 주소'와 '길이'를 관리하여 안전한 주소 변환을 보장함

## Ⅳ. 문제점 및 개선방안

1. **외부 단편화(External Fragmentation)**: 가변 크기 세그먼트의 할당/해제 반복으로 메모리 중간에 조각난 빈 공간이 발생하여 공간 낭비 초래
   - **개선방안**: 메모리 압축(Compaction)을 통해 빈 공간을 한데 모으거나, **페이징 기법과 결합(Paged Segmentation)**하여 외부 단편화 문제를 해결함

2. **메모리 할당 알고리즘의 복잡도**: 세그먼트 적재 시 가용 공간 중 어디에 넣을지 결정하는 연산 필요
   - **개선방안**: 최초 적합(First-fit), 최적 적합(Best-fit), 최악 적합(Worst-fit) 등의 전략을 상황에 맞게 적용하여 탐색 시간을 최적화함

3. **관련 하드웨어 지원의 한계**: 현대 CPU(x86-64 등)는 페이징 위주로 최적화되어 순수 세그멘테이션 성능이 낮을 수 있음
   - **개선방안**: 세그먼트 경계 검사(Boundary Check)를 하드웨어 레벨에서 가속화하거나, 논리적 보호는 세그먼트 개념으로, 물리적 배치는 페이징으로 처리하는 혼합 방식을 사용함

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| x86 아키텍처 (GDT/LDT) | 글로벌/로컬 디스크립터 테이블을 통해 커널, 유저, 데이터 세그먼트를 분리 관리 | Privileged Level, Seg Violation |
| 공유 라이브러리 (Shared Lib) | 여러 프로세스가 동일한 세그먼트 번호를 통해 공유 라이브러리 코드를 참조 | 공유 메모리 절감량, 로딩 속도 |
| 보안 솔루션 (Sandbox) | 특정 프로그램이 지정된 세그먼트(샌드박스) 영역 밖을 보지 못하도록 한계(Limit) 값 설정 | 비인가 접근 차단 횟수, Crash 로그 |

> 요약: 순수 세그멘테이션은 드물지만, 코드와 데이터를 격리하는 '세그먼트 보호' 철학은 모든 현대 OS에 내재됨

## Ⅵ. 결론

세그멘테이션은 컴퓨터 시스템이 프로그램의 '의미'를 이해하고 메모리를 관리하게 해주는 핵심적인 논리적 틀임. 비록 외부 단편화 문제로 인해 물리적 관리의 주도권을 페이징에 내주었지만, 권한 분리와 모듈 공유라는 측면에서의 효율성은 대체 불가능한 가치를 지님.

기술사는 세그멘테이션과 페이징의 트레이드오프 관계를 명확히 파악하고, 두 기법의 장점을 결합한 'Paged Segmentation'이 왜 현대 운영체제의 정석이 되었는지 설명할 수 있어야 함. 또한, 소프트웨어 보안의 기본인 'Segmentation Fault'가 하드웨어 수준에서 어떻게 감지되는지에 대한 깊은 이해를 바탕으로 안전한 시스템 설계 방안을 제시할 수 있어야 함.
