## Ⅰ. 개요
- **정의**: 메모리를 코드/데이터/스택 등 논리적 의미 단위(세그먼트)로 가변 크기 분할하여 관리하는 메모리 관리 기법임
- **배경/필요성**: 고정 크기 페이징(022 참조)만으로는 논리 단위별 접근 권한 설정과 코드 공유가 어려우므로 의미 기반 분할이 요구됨
- **비유**: 책을 100쪽 단위로 기계적으로 나누지 않고, 서론/본론/결론 등 내용 단위로 장(Chapter)을 나누는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 페이징과의 비교 분석 | 고정/가변 크기, 내부/외부 단편화 트레이드오프 | 세그멘테이션만 단독 서술하고 페이징 비교 누락 금지 |
| 주소 변환 메커니즘 | 세그먼트 테이블의 Base+Limit 검증 과정 | Limit 범위 검증(보호 기능) 서술 누락 금지 |
| 현대 OS 결합 구조 | Paged Segmentation과 Flat Memory Model | 현대 OS가 세그멘테이션만 사용한다고 서술 금지 |

> 요약: 논리적 의미 단위로 메모리를 분할하여 접근 권한 제어와 코드 공유를 용이하게 하는 기법임

## Ⅱ. 구성요소
```text
가상 주소 (s, d)
     |
     +-- s(세그먼트 번호) --> 세그먼트 테이블 조회
     |                          |
     |                    Base / Limit / 권한 비트
     |                          |
     +-- d(Offset) ----------->+ d < Limit? --No--> Segmentation Fault
                                |
                               Yes
                                |
                                v
                          Base + d = 물리 주소
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 세그먼트 | 코드/데이터/스택/힙 등 논리적 의미를 갖는 가변 크기 메모리 블록 | 건물의 용도별 구역(사무실/창고/식당) |
| 세그먼트 테이블 | 각 세그먼트의 Base(시작 주소), Limit(길이), 권한 비트(R/W/X)를 저장하는 매핑 표 | 건물 층별 출입 명부 |
| Base 레지스터 | 해당 세그먼트가 물리 메모리에서 시작하는 절대 주소를 보관하는 필드 | 건물의 시작 층수 |
| Limit 레지스터 | 세그먼트의 최대 크기를 지정하여 범위 초과 접근을 차단하는 필드 | 건물의 총 층수(초과 시 출입 거부) |

> 요약: 세그먼트, 세그먼트 테이블, Base, Limit로 구성되어 논리 단위별 주소 변환과 보호를 수행함

## Ⅲ. 절차
```text
CPU 주소 (s, d) --> 세그먼트 테이블에서 s번 조회 --> d < Limit? --> Base+d 계산 --> 물리 주소
                                                      |
                                                   d >= Limit
                                                      |
                                                      v
                                               Segmentation Fault (트랩)
```
- 1단계: CPU가 가상 주소를 세그먼트 번호 `s`와 변위 `d`로 분리하여 MMU(025 참조)에 전달함
- 2단계: MMU가 세그먼트 테이블에서 `s`번 엔트리를 조회하여 Base, Limit, 권한 비트를 획득함
- 3단계: 변위 `d`가 Limit 이상이면 범위 초과로 Segmentation Fault 트랩을 발생시키고, 권한 비트도 현재 CPU 모드와 대조하여 위반 시 차단함
- 4단계: 검증 통과 시 Base + `d`를 계산하여 물리 주소를 생성하고 메모리 접근을 허용함

> 요약: 세그먼트 번호 조회 -> Limit 범위 검증 -> 권한 대조 -> Base+Offset 물리 주소 생성의 4단계임

## Ⅳ. 문제점
- 외부 단편화: 가변 크기 세그먼트의 할당/해제가 반복되면 빈 공간이 흩어져 총량은 충분해도 연속 공간 확보에 실패함
- Compaction 오버헤드: 외부 단편화 해소를 위해 메모리 조각 모음을 수행하면 전체 세그먼트 재배치로 시스템이 일시 정지함
- Flat Model 비호환: x86-64 아키텍처가 Base=0, Limit=최대로 고정하는 Flat Memory Model을 채택하여 하드웨어 세그멘테이션의 물리 분할 기능이 사실상 비활성화됨

> 요약: 외부 단편화, Compaction 부하, 현대 아키텍처의 Flat Model 전환이 주요 한계임

## Ⅴ. 개선방안
1. 단기: Paged Segmentation 적용으로 세그먼트를 다시 고정 크기 페이지로 분할하여 외부 단편화를 원천 제거함
2. 중기: Demand Segmentation과 지연 할당(Lazy Allocation)을 결합하여 Compaction 빈도를 감소시키고 재배치 범위를 최소화함
3. 장기: 세그먼트의 물리 분할 대신 페이지 테이블 권한 비트(NX/W^X)와 Protection Key(MPK)로 논리적 보호 기능을 대체하여 Flat Model 환경에서도 세그먼트 수준 격리를 유지함

> 요약: Paged Segmentation, 지연 할당, 페이지 권한 기반 보호로 각 한계를 해소함

## Ⅵ. 전망
- 발전 방향: 하드웨어 세그멘테이션의 물리 분할 기능은 축소되나, 논리적 보호/공유 개념은 MPK, Intel CET 등 새 메커니즘으로 계승됨
- 기술사적 판단: 세그멘테이션의 본질적 가치는 보호와 공유의 논리적 단위 제공에 있으며, 이 철학이 컨테이너/VM 격리 설계에도 적용됨
- 기술사 제언: Flat Model 환경에서도 세그먼트 개념을 소프트웨어 레벨(ELF 섹션, 링커 스크립트)로 유지하여 메모리 보호 정책 설계에 활용할 것을 권고함
