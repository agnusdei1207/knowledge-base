## 미리 알고가기

- 세그먼트는 코드, 데이터, 스택처럼 의미가 다른 주소 영역을 말함
- 세그먼트 테이블은 각 영역의 시작 주소, 길이, 권한을 관리함
- 가변 크기 할당이라 외부 단편화가 생길 수 있음

## Ⅰ. 개요

- **정의/개념**: 세그멘테이션은 프로세스 주소 공간을 논리 단위별 가변 크기 세그먼트로 나누고, 각 세그먼트의 기준 주소·길이·보호 속성을 관리하는 메모리 구조임
- **배경/필요성**: 코드·데이터·스택의 서로 다른 크기와 보호 요구를 반영하기 위해 논리 구조별 보호·공유 단위가 필요함

## Ⅱ. 특징

- 프로그램 논리 구조에 맞춰 영역을 나누므로 보호와 공유 정책을 직관적으로 적용하기 쉬움
- 세그먼트별 크기와 성장 방향을 다르게 둘 수 있어 스택과 힙 관리에 유연함
- 권한 검사를 세그먼트 단위로 수행해 코드 실행 영역과 데이터 수정 영역을 분리하기 쉬움
- 가변 크기 할당 특성상 외부 단편화와 메모리 압축 부담이 커질 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 세그멘테이션 | 페이징 |
|:---|:---|:---|
| 관리 관점 | 논리 단위 중심으로 메모리를 다룸 | 물리 효율 중심으로 고정 크기 블록을 다룸 |
| 장점 | 보호와 공유를 의미 단위로 설정하기 쉽음 | 외부 단편화 없이 배치와 교체가 단순함 |
| 한계 | 외부 단편화와 재배치 비용이 큼 | 내부 단편화와 메타데이터 오버헤드가 생김 |
| 활용 방향 | 보호 모델과 특수 하드웨어에서 보조적으로 쓰임 | 현대 범용 OS의 기본 메커니즘임 |

> 요약: 세그멘테이션은 논리 보호 경계가 명확하고, 페이징은 물리 배치와 교체가 단순함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Segment Number and Offset | 논리 주소를 세그먼트 식별자와 내부 위치로 나눠 서로 다른 보호 경계를 갖게 함 |
| Segment Table | 각 세그먼트의 base, limit, privilege를 기록해 물리 위치와 접근 가능 범위를 결정함 |
| Bounds and Permission Checker | offset이 limit를 넘는지와 읽기·쓰기·실행 권한을 동시에 검사해 보호 예외를 발생시킴 |
| Physical Allocation Region | 세그먼트별 실제 저장 위치를 따로 배치해 크기 변화와 공유 요구를 반영함 |

```text
+-------------------+     +-------------------+     +------------------+
| Segment No/Offset | --> | Segment Table     | --> | Base + Offset    |
+-------------------+     +-------------------+     +------------------+
                                   |
                                   v
                           +-------------------+
                           | Limit / Permission|
                           +-------------------+
```

> 요약: 세그먼트 번호와 offset은 base, limit, 권한 검사로 물리 주소와 보호 예외를 결정함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 논리 주소 입력   | --> | 세그먼트 엔트리 조회 | --> | 범위·권한 검사   | --> | 물리 주소 생성   |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **논리 주소 입력**: CPU가 세그먼트 번호와 offset을 가진 주소를 전달함
2. **세그먼트 엔트리 조회**: 해당 세그먼트의 base, limit, 권한을 읽음
3. **범위와 권한 검사**: offset 초과나 금지된 접근이면 예외를 발생시킴
4. **물리 주소 생성**: 조건을 만족하면 base와 offset을 더해 최종 주소를 만듦

> 요약: 세그먼트 접근은 논리 주소를 조회하고 범위·권한을 통과해야 물리 주소가 됨.

## Ⅵ. 실무 적용 및 유의점

1. 세그먼트 크기가 제각각이면 외부 단편화로 큰 영역 배치가 어려워지므로 paged segmentation이나 compaction을 적용하고 fragmentation ratio, allocation failure rate로 확인함
2. 큰 세그먼트 이동이 잦으면 compaction이 서비스 지연을 만들 수 있으므로 free list 분리와 buddy allocation을 병행하고 relocation time, allocation latency로 확인함
3. 현대 시스템은 페이징 중심이므로 세그멘테이션은 보호가 필요한 논리 경계에 제한적으로 적용하고 protection fault accuracy, management complexity로 확인함

## Ⅶ. 결론

세그멘테이션은 물리 효율보다 논리 경계에 맞는 보호와 공유를 제공하는 구조이므로, 단편화 비용보다 보호 이점이 큰지로 판단해야 함.

## 작성 근거(검토용)

- 세그멘테이션은 물리 배치보다 논리 단위, base·limit, 권한 검사를 중심으로 설명함
- 모호한 표현은 fragmentation ratio, allocation failure rate, protection fault accuracy로 구체화함
- 결론은 페이징 대비 우열이 아니라 단편화 비용과 보호 이점의 판단으로 정리함
