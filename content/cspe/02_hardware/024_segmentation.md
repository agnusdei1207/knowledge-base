## 미리 알고가기

- 세그먼트: 코드, 데이터, 스택처럼 의미가 같은 주소 범위를 가변 길이 단위로 나눈 논리 메모리 단위임
- 기준 주소: 세그먼트가 물리 메모리에서 시작되는 주소임
- 한계 값: 세그먼트 내부 오프셋이 넘으면 안 되는 최대 크기임
- 외부 단편화: 가변 크기 할당과 해제로 빈 공간이 흩어져 큰 세그먼트를 배치하지 못하는 현상임

## Ⅰ. 개요

- **정의**: 세그멘테이션은 프로세스 주소 공간을 코드, 데이터, 스택 같은 논리적 의미 단위의 가변 길이 세그먼트로 나누고 기준 주소와 한계 값으로 변환·보호해 프로그램 구조와 메모리 관리를 일치시키는 기법임
- **배경/필요성**: 페이징은 고정 크기라 할당은 쉽지만 프로그램 모듈의 의미, 공유, 보호 경계를 직접 표현하기 어려움. 세그멘테이션은 논리 단위별 접근 권한과 공유를 관리하기 위해 필요함
- **비유**: 건물을 층과 방의 용도별 구역으로 나누고 각 구역마다 출입 권한과 면적 제한을 두는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 논리 주소 관리와 보호 메커니즘을 페이징과 비교하는 역량 확인 | 세그먼트 번호, 오프셋, 기준/한계 레지스터, 외부 단편화 | 페이지와 세그먼트 크기 혼동, 보호 기능 누락, 단편화 유형 오류 |

> 요약: 세그멘테이션은 프로그램의 논리 구조를 기준으로 주소 변환과 보호를 수행하는 가변 크기 메모리 관리 방식임.

## Ⅱ. 특징/비교

| 판단 기준 | 페이징 | 세그멘테이션 |
|:---|:---|:---|
| 분할 기준 | 고정 크기 페이지·프레임 | 코드·데이터·스택 등 논리 단위 |
| 주소 형식 | 페이지 번호와 오프셋 | 세그먼트 번호와 오프셋 |
| 단편화 | 내부 단편화 가능 | 외부 단편화 가능 |
| 보호·공유 | 페이지 단위 권한 관리 | 의미 단위별 권한·공유 표현 용이 |

> 요약: 페이징은 고정 프레임 단위 할당으로 외부 단편화가 없는 것이 강점이고 세그멘테이션은 논리적 보호와 공유 표현이 강점임.

- 세그먼트는 가변 길이이므로 모듈 크기 변화에 유연하지만 빈 공간 관리와 압축 비용이 발생함
- 세그먼트 테이블은 각 세그먼트의 기준 주소, 길이, 권한 비트를 저장해 불법 접근을 차단함
- 현대 시스템은 순수 세그멘테이션보다 페이징과 결합하거나 제한적으로 사용해 단편화 부담을 줄임

## Ⅲ. 구성요소

```text
+-------------+      +-------------+      +-------------+
| 논리주소    | ---> | 세그먼트표  | ---> | 물리주소    |
| seg, offset |      | base,limit  |      | base+offset |
+-------------+      +-------------+      +-------------+
        |                    |
        v                    v
+-------------+      +-------------+
| 권한요구    |      | 한계검사    |
+-------------+      +-------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 세그먼트 번호 | 접근하려는 코드, 데이터, 스택 같은 논리 구역을 식별함 | 건물의 구역 번호 |
| 오프셋 | 선택한 세그먼트 시작점에서 떨어진 상대 위치를 나타냄 | 방 안에서의 좌표 |
| 세그먼트 테이블 | 기준 주소, 길이, 권한, 존재 여부를 저장해 변환과 보호를 지원함 | 구역별 출입 대장 |
| 기준·한계 검사 | 오프셋이 세그먼트 크기 안에 있는지 확인하고 물리 주소를 계산함 | 출입문에서 면적과 권한 확인 |

> 요약: 세그멘테이션은 논리 주소의 세그먼트 번호로 테이블을 찾고 오프셋의 범위와 권한을 검증해 물리 주소를 만듦.

## Ⅳ. 절차

```text
+-----------+      +------------+      +---------------+      +----------+
| 주소분해  | ---> | 테이블조회 | ---> | 범위/권한검사 | ---> | 주소생성 |
+-----------+      +------------+      +---------------+      +----------+
```

1. **주소 분해**: CPU가 생성한 논리 주소를 세그먼트 번호와 오프셋으로 나눔
2. **세그먼트 테이블 조회**: 세그먼트 번호로 기준 주소, 길이, 권한 정보를 읽음
3. **범위와 권한 검증**: 오프셋이 한계 값 이내이고 접근 모드가 허용되는지 확인함
4. **물리 주소 생성**: 기준 주소에 오프셋을 더해 실제 메모리 주소를 만들고 접근함

> 요약: 세그멘테이션은 논리 구역 식별, 테이블 조회, 범위 검증, 주소 계산 순서로 메모리 접근을 통제함.

## Ⅴ. 문제점

- **P1 외부 단편화**: 세그먼트 크기가 가변이어서 할당과 해제를 반복하면 작은 빈 공간이 흩어짐
- **P2 세그먼트 배치 비용**: 큰 세그먼트를 적재하려면 적절한 연속 공간 탐색이나 메모리 압축이 필요함
- **P3 보호 정책 복잡도**: 세그먼트 공유와 권한 변경이 많아지면 테이블 관리와 예외 처리가 복잡해짐

> 요약: 세그멘테이션은 논리적 표현력이 높지만 가변 크기 관리와 권한 운영 비용이 커질 수 있음.

## Ⅵ. 개선방안

1. **단기**: 세그먼트 크기, 빈 공간 분포, 보호 예외 발생 건수를 점검해 병목을 식별함
2. **중기**: 페이징과 결합해 세그먼트 내부를 페이지로 나누고 연속 물리 공간 요구를 줄임
3. **장기**: 모듈 경계, 공유 정책, 권한 모델을 표준화해 주소 공간 설계 기준으로 관리함

- **P1 대응**: 세그먼트-페이징 결합으로 외부 단편화를 내부 페이지 관리로 흡수함 (확인: 연속 공간 부족 건수)
- **P2 대응**: best-fit, compaction, 사전 크기 산정 기준을 적용함 (확인: 적재 실패율과 압축 시간)
- **P3 대응**: 코드·데이터·스택 권한 템플릿과 공유 세그먼트 승인 절차를 분리함 (확인: 보호 예외 로그)

> 요약: 세그멘테이션은 순수 방식보다 페이징 결합과 권한 표준화로 실무 적용성을 높임.

## Ⅶ. 전망

- **발전 방향**: 현대 범용 OS는 순수 세그멘테이션보다 페이징 중심 구조를 쓰지만, 논리 보호 경계 개념은 권한 분리와 샌드박싱에 계속 남음
- **기술사적 판단**: 보안 실행 환경과 런타임 격리에서는 코드, 데이터, 스택 경계를 명확히 하는 주소 공간 설계가 더 중요해짐
- **기술사 제언**: 기술사는 세그멘테이션을 단순 옛 기술로 보지 말고 논리 단위 보호와 단편화 트레이드오프의 사례로 설명해야 함
