## Ⅰ. 개요
- **정의**: 프로세스의 주소 공간을 논리적 의미 단위(세그먼트)로 분할하여 관리하는 메모리 기법임
- **배경/필요성**: 코드·데이터·스택 등 용도가 다른 영역을 하나의 연속 공간으로 취급하면 보호·공유가 어려우므로 논리 단위 분리가 필요함
- **비유**: 서류를 내용별(계약서·영수증·보고서)로 다른 폴더에 분류하여 보관하는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 세그멘테이션의 논리적 분할 원리와 페이징과의 차이 | 세그먼트 테이블 구조(Base/Limit)와 보호 비트 | 외부 단편화 문제를 페이징의 내부 단편화와 혼동하지 말 것 |

> 요약: 세그멘테이션은 논리적 의미 단위로 주소 공간을 분할하여 보호·공유를 지원하는 기법임

## Ⅱ. 구성요소
```text
  논리 주소
  (세그먼트 번호 + 오프셋)
   |
   v
  +---------------------+
  | 세그먼트 테이블     |
  |  [번호] -> Base,    |
  |            Limit,   |
  |            권한     |
  +----------+----------+
             |
     +-------+-------+
     |       |       |
     v       v       v
   Code    Data    Stack
   세그먼트 세그먼트 세그먼트
     |       |       |
     v       v       v
  +-------------------------+
  |     물리 메모리         |
  +-------------------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 세그먼트 번호 | 논리 주소의 상위 비트로 세그먼트를 식별하는 인덱스임 | 폴더의 라벨 번호 |
| Base 레지스터 | 해당 세그먼트의 물리 메모리 시작 주소를 저장함 | 폴더가 놓인 서랍 위치 |
| Limit 레지스터 | 세그먼트의 크기 상한을 지정하여 경계 검사에 사용함 | 폴더에 넣을 수 있는 최대 서류 수 |
| 보호 비트 | 읽기/쓰기/실행 권한을 세그먼트 단위로 제어함 | 폴더별 열람 권한 스티커 |
| 세그먼트 테이블 | 세그먼트 번호 → Base/Limit/권한 매핑을 저장하는 자료구조임 | 폴더 위치·권한 목록표 |

> 요약: 세그먼트 번호, Base/Limit, 보호 비트, 세그먼트 테이블로 구성됨

## Ⅲ. 절차
```text
  논리주소 분리      테이블 조회       경계 검사         물리주소 생성
  (번호+오프셋)    (Base/Limit)    (오프셋 < Limit)  (Base+오프셋)
   |                |                |                 |
   +---번호 전달--->+---Base,Limit-->+---유효하면----->+
                                     |
                                     +---초과 시
                                         Trap 발생
```
- 1단계: 논리 주소에서 세그먼트 번호와 오프셋을 분리함
- 2단계: 세그먼트 번호로 세그먼트 테이블을 인덱싱하여 Base, Limit, 권한을 조회함
- 3단계: 오프셋이 Limit을 초과하거나 권한이 위반되면 Segmentation Fault(Trap)를 발생시킴
- 4단계: 검증 통과 시 Base + 오프셋을 계산하여 물리 주소를 생성함

> 요약: 주소 분리 → 테이블 조회 → 경계·권한 검사 → 물리 주소 계산의 4단계로 동작함

## Ⅳ. 문제점
- 외부 단편화: 가변 크기 세그먼트의 할당·해제가 반복되면 빈 공간이 조각나 대형 세그먼트 할당이 실패함
- 메모리 압축 비용: 외부 단편화 해소를 위한 Compaction 수행 시 세그먼트 이동과 테이블 갱신에 높은 CPU 비용이 소요됨
- 테이블 크기 증가: 세그먼트 수가 많은 프로세스에서 테이블 자체의 메모리 점유가 증가함

> 요약: 외부 단편화, Compaction 비용, 테이블 크기가 세그멘테이션의 주요 문제임

## Ⅴ. 개선방안
1. 단기: Best-Fit/Buddy System 등 할당 알고리즘을 최적화하여 외부 단편화 발생 빈도를 감소시킴
2. 중기: 세그먼트-페이지 혼합 기법(Segmentation with Paging)을 적용하여 세그먼트 내부를 페이지 단위로 관리하면 Compaction 필요성이 제거됨
3. 장기: 페이징 기반 세그먼트 에뮬레이션(x86-64 플랫 모델)으로 전환하여 테이블 구조를 단순화함

> 요약: 할당 알고리즘 최적화, 혼합 기법, 플랫 모델 전환으로 세그멘테이션 문제를 해소함

## Ⅵ. 전망
- 발전 방향: 현대 OS는 페이징 중심으로 수렴하였으나 MPK(Memory Protection Keys) 등으로 세그먼트 수준의 보호 기능이 부활함
- 기술사적 판단: 논리적 보호 단위 개념은 보안·격리 요구 증가에 따라 지속적으로 활용됨
- 기술사 제언: 마이크로서비스 환경에서 프로세스 내 메모리 격리 수준 설계 시 세그멘테이션 개념을 응용할 필요
