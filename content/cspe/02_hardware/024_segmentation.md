# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 가상 메모리를 고정 크기가 아닌, 코드·데이터·스택 등 논리적인 의미 단위(세그먼트)로 잘라서 관리하는 기법
- **왜 필요한가**: 페이징처럼 메모리를 기계적으로 4KB씩 뚝뚝 자르면 관리하기는 편하지만, 하나의 함수나 데이터 덩어리가 여러 페이지에 찢어져 들어간다. 이러면 "이 함수만 읽기 전용으로 보호하자" 같은 의미 기반 제어가 매우 까다로워진다.
- **핵심 직관**: 책을 보관할 때, 무조건 100쪽 단위로 뜯어서(페이징) 보관하는 게 아니라, 1단원(서론), 2단원(본론)처럼 장(Chapter) 단위로 나누어(세그멘테이션) 꽂는 방식.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 세그먼트 (Segment) | 논리적으로 연관된 정보의 집합 (가변 크기) | 메인 함수, 배열 데이터 등 |
| Segment Table | 각 세그먼트가 메모리 어디에 있는지, 크기가 얼마인지 기록한 표 | 목차 (1단원은 10쪽부터 총 15쪽 분량) |
| Base | 세그먼트가 실제 물리 메모리에서 시작하는 번지 | 장이 시작되는 실제 페이지 번호 |
| Limit | 해당 세그먼트의 전체 길이 (접근 범위를 제한) | 그 장의 총 페이지 수 |

## 깊이 이해
- **배경·문제의식**: 사용자는 메모리를 바이트의 연속된 덩어리가 아니라, 여러 개의 독립된 객체(Code, Data, Heap, Stack)의 모음으로 바라본다. 이 논리적 관점을 하드웨어 관리에도 그대로 반영하려는 시도에서 출발했다.
- **작동 원리**: CPU는 `[세그먼트 번호(s), 오프셋(d)]` 형태의 2차원 주소를 낸다. MMU는 세그먼트 테이블에서 `s`번 세그먼트를 찾고, 오프셋 `d`가 그 세그먼트의 총 길이(`Limit`)를 넘지 않는지 검사한다. 넘으면 강제로 에러(Trap)를 내고, 정상적이면 시작 위치(`Base`)에 `d`를 더해 실제 주소를 만든다.
- **비유**: 호텔 구조. "3번 세미나실, 입구에서 5미터 앞"으로 가려는데, 3번 세미나실 크기(Limit)가 4미터뿐이라면 "벽 밖으로 나간다"며 경호원이 막아선다.
- **구체 예시**: 공유 라이브러리(`libc.so`)를 여러 프로세스가 쓸 때, 페이징 환경에서는 해당 라이브러리가 여러 페이지에 걸쳐 흩어질 수 있어 공유가 복잡하지만, 세그멘테이션에서는 '라이브러리 세그먼트 1개'만 가리키게 세팅하면 완벽히 공유된다.
- **흔한 오해·주의점**: 세그멘테이션은 내부 단편화가 없다(필요한 만큼만 자르니까). 하지만 가변 크기 덩어리들이 램에 들어갔다 나왔다 하면, 중간중간 20KB, 50KB씩 쓸모없는 빈틈(외부 단편화)이 생겨 램 효율이 박살난다.

## 연결 개념
- 가상 메모리 (Virtual Memory) — (022 참조)
- 페이징 (Paging) — 크기 기반 분할. 세그멘테이션과 반대되는 특징을 가짐
- 외부 단편화 (External Fragmentation) — 총 빈 공간은 충분한데 쪼개져 있어서 새 세그먼트를 넣지 못하는 현상

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 세그멘테이션은 가상 주소 공간을 크기가 아닌 의미(Code, Data, Stack) 단위의 가변 길이 블록으로 분할하여 매핑하는 메모리 관리 기법이다.
> 2. **가치**: 논리적 단위가 유지되므로 읽기 전용/실행 전용 등 세그먼트별 접근 제어(보호)와 동적 라이브러리 공유가 페이징 대비 직관적이고 강력하다.
> 3. **판단 포인트**: 단일 세그멘테이션은 치명적인 외부 단편화를 유발하므로, 현대 아키텍처(x86 등)는 세그먼트로 논리적 보호를 한 뒤 다시 페이징으로 잘게 쪼개는 Paged Segmentation을 채택한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 사용자/컴파일러 관점의 메모리 관리 이해 | 가변 분할, Base/Limit, 보호(Protection) 및 공유(Sharing) 강점 | 페이징의 특징(고정 분할)과 혼동 |
| 세그멘테이션의 한계 원리 확인 | 외부 단편화(External Fragmentation) 발생 메커니즘 | 내부 단편화가 발생한다고 잘못 기재 |
| 현대 시스템 적용 방식 확인 | 페이징과의 결합 (Paged Segmentation) | 세그멘테이션 단독으로 사용된다고 단정 |

> 요약: 왜 페이징을 두고 세그멘테이션이 필요한가(보호·공유)와, 왜 단독으로 못 쓰는가(외부 단편화)를 트레이드오프로 명확히 제시해야 한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 프로세스의 가상 주소 공간을 사용자 관점의 논리적 의미 단위(함수, 배열, 스택 등)로 가변 분할하여 물리 메모리에 적재하는 기법
- 배경: 페이징 기법은 고정 크기로 잘라 물리적 관리 효율은 높이나, 하나의 논리적 객체가 여러 페이지에 찢어져 보호와 공유의 복잡성이 큼
- 필요성: 모듈 단위의 메모리 접근 권한 제어와 공유 라이브러리의 효율적 운영을 위해 논리 구조를 유지하는 가상화 기법 필수

---

## Ⅱ. 구조 및 구성요소

```text
CPU 요청 -> 가상 주소 (Segment #, Offset)
               |
               +-> Segment Table -> [Limit 검사 통과] -> Base + Offset -> 물리 주소
                                 -> [Limit 초과 시] -> Trap (보호 오류)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Segment 번호 (s) | 프로세스 내 논리적 분할 단위의 식별자 | 테이블 검색의 인덱스 역할 |
| Offset (d) | 세그먼트 시작점(Base)으로부터의 변위 | 세그먼트 길이(Limit)보다 작아야 함 |
| Segment Table | 각 세그먼트의 Base 번지, Limit 크기 보관 | MMU 내부 레지스터(STBR) 참조 |
| 권한 비트 | Read, Write, Execute 등의 제어 상태 플래그 | 논리 단위와 1:1 매핑되어 강력한 보호 |

> 요약: 세그멘테이션 하드웨어는 단순히 주소만 더하는(Base+Offset) 것이 아니라, 반드시 길이 한계(Limit)를 교차 검증하여 침범을 하드웨어로 차단한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
주소 발생 (s, d) -> 테이블 탐색 -> Limit 검증 -> 권한 체크 -> 변환 주소 산출 (Base + d)
```

- 1단계 [주소 분리]: CPU가 생성한 2차원 논리 주소를 세그먼트 번호(s)와 변위(d)로 분리
- 2단계 [한계 검증]: 세그먼트 테이블에서 `s`에 해당하는 항목을 찾아, 변위 `d`가 해당 세그먼트의 `Limit` 범위를 벗어나는지 하드웨어 검증
- 3단계 [권한 검사 및 예외]: 범위 이탈 또는 접근 권한(예: Read-Only에 Write 시도) 오류 시 트랩(Addressing Error) 발생
- 4단계 [물리 주소 생성]: 검증 통과 시 해당 세그먼트의 시작 주소(`Base`)에 변위(`d`)를 산술 덧셈하여 최종 물리 주소 완성

> 요약: 주소 변환 과정에서 Limit 검증이라는 샌드박스 메커니즘이 강제되어 보안 위협을 선제적으로 튕겨낸다.

---

## Ⅳ. 비교 (vs 페이징 기법)

| 비교 축 | 세그멘테이션 (Segmentation) | 페이징 (Paging) | 판단 기준 |
|:---|:---|:---|:---|
| 분할 기준 | 의미 기반 논리 단위 (가변 크기) | 프레임 기반 물리 단위 (고정 크기) | 보호 및 공유 우선 / 할당 편의성 우선 |
| 단편화 종류 | 외부 단편화 발생 (중간에 생기는 빈틈) | 내부 단편화 발생 (마지막 페이지 남는 공간) | 가변 분배 vs 정량 분배의 차이 |
| 테이블 크기 | 작음 (세그먼트 개수가 적음) | 매우 큼 (수천~수백만 개 엔트리) | 메모리 오버헤드 통제 관점 |
| 적용 장점 | 강력한 보안(보호) 및 동적 링킹(공유) 유리 | 메모리 적재 및 디스크 스왑 효율 극대화 | 현대 시스템은 두 장점을 결합 |

> 요약: 관리의 직관성과 논리적 보안은 세그멘테이션이 압도적이나, 물리적 램(RAM)의 조각화(외부 단편화) 문제로 인해 단독 구동에는 치명적 한계가 있다.

---

## Ⅴ. 심화 판단: 단편화 리스크와 하이브리드 대안

**리스크·대응 (가변 분할의 한계):**
- [외부 단편화 심화]: 프로세스 생성/종료 반복 시, 총 빈 공간은 100MB여도 연속된 공간이 10MB씩 조각나 50MB 세그먼트 적재 불가 → 주기적인 메모리 압축(Compaction) 수행, 단 압축 중 시스템 정지 지연 발생 (지표: 메모리 조각화율)
- [Paged Segmentation 대안]: 논리적 보호를 위해 먼저 세그먼트로 나누고, 램 할당의 조각화 방지를 위해 그 세그먼트를 다시 고정 크기 페이지로 분할 → 외부 단편화를 근본적으로 차단

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. x86 아키텍처 적용: Intel x86 계열은 하드웨어 레벨에서 Global/Local Descriptor Table(GDT/LDT)을 이용해 세그멘테이션 보호 링(Ring 0~3)을 설정한 후, 하단에서 페이징을 구동하는 Paged Segmentation 채택
2. 코드 재사용 극대화: C/C++ 공유 라이브러리(.so, .dll) 로드 시, 해당 라이브러리를 단일 세그먼트로 지정하여 여러 프로세스 페이지 테이블이 동일한 Base를 가리키도록 설정, 메모리 중복 복사 방지
3. 버퍼 오버플로우 하드웨어 방어: 스택 세그먼트의 실행 권한 비트(NX/XD bit)를 해제하고, 배열 접근 시 Limit 초과를 MMU 트랩으로 튕겨내어 ROP 등 메모리 침해 공격 차단

**결론 (2줄):**
- 기술사 판단: 순수 세그멘테이션은 메모리 단편화 문제로 사장되었으나, 논리적 보호(Protection)의 개념적 가치는 현대 OS 보안 모델의 뼈대로 살아남았다.
- 향후 방향: 64비트 아키텍처(x86-64)에서는 세그멘테이션의 물리적 분할 역할을 축소하고(Base=0, Limit=Max 평면 메모리 모델), 보호 권한 기능만 페이징과 결합하여 오버헤드를 줄이는 방향으로 최적화되었다.
