# PUF 물리적 복제 불가 함수 (Physical Unclonable Function)

## 미리 알고가기

- PUF(Physical Unclonable Function): 제조 공정 미세 편차에서 장치마다 다른 응답을 생성하는 물리적 복제 불가 함수임
- CRP(Challenge-Response Pair): 입력 challenge와 그에 대한 고유 response의 쌍임
- SRAM(Static Random Access Memory) PUF: 전원 인가 시 SRAM 셀이 0 또는 1로 초기화되는 편향을 활용하는 PUF 방식임
- Fuzzy Extractor: 잡음이 있는 PUF 응답에서 안정적인 키를 재구성하는 오류 보정 기법임
- Helper Data: 키 복원을 돕기 위해 저장하는 공개 보조 데이터로 원본 키를 직접 드러내지 않아야 함

## 1. 개요

- **정의/개념**: PUF는 반도체 제조 공정의 미세한 물리적 편차를 이용해 같은 설계의 칩이라도 서로 다른 응답이나 키를 생성하게 하는 하드웨어 보안 기술로, 고유성, 재현성, 예측 불가능성, 환경 안정성을 기준으로 장치 인증과 키 보호에 사용함
- **배경/필요성**: 장치 내부에 고정 키를 저장하면 추출, 복제, 유출 위험이 존재함. PUF는 키를 저장하기보다 필요할 때 장치 물리 특성에서 재구성해 복제와 추출을 어렵게 만들 수 있음
- **비유**: 같은 도면으로 만든 자물쇠라도 금속 표면의 미세한 결 때문에 각 자물쇠가 고유한 지문을 갖는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 하드웨어 고유성 기반 보안 설명 | 제조 편차, challenge-response, fuzzy extractor, helper data | 단순 난수 발생기로 설명 |
| 장치 인증과 키 보호 판단 | 고유성, 재현성, 환경 안정성, 모델링 공격 | PUF 응답이 항상 동일하다고 단정 |

> 요약: PUF는 저장된 비밀이 아니라 장치의 물리적 편차에서 고유 응답을 재구성해 인증과 키 보호에 활용하는 기술임.

## 2. 특징 및 비교

| 판단 기준 | 저장형 키 | PUF 기반 키 |
|:---|:---|:---|
| 비밀 보관 | Flash, fuse, EEPROM(Electrically Erasable Programmable Read-Only Memory) 등에 키 값을 저장함 | 물리 특성에서 키를 재구성하고 평상시 저장하지 않음 |
| 복제 저항 | 저장 매체가 복사되면 키도 복제될 수 있음 | 공정 편차 복제가 어려워 동일 응답 재현이 어려움 |
| 안정성 요구 | 저장값은 환경 변화에 비교적 안정적임 | 온도, 전압, 노화에 따른 응답 흔들림 보정이 필요함 |
| 운영 부담 | 키 주입과 보관 절차가 중요함 | 등록, helper data, 오류 보정, 재현성 시험이 중요함 |

> 요약: PUF는 키 저장 공격을 줄이는 대신 응답 안정화와 모델링 공격 방어를 설계해야 함.

- **고유성 기준**: 서로 다른 칩의 응답 간 해밍 거리가 충분히 커야 장치 식별이 가능함
- **재현성 기준**: 같은 칩이 온도, 전압, 노화 조건에서도 같은 키를 복원할 수 있어야 함
- **보안 기준**: challenge-response를 많이 노출하면 공격자가 모델을 학습할 수 있으므로 사용 범위를 통제해야 함

## 3. 구성요소/구조

```text
+----------+      +----------+      +----------+
| Challenge| ---> | Physical | ---> | Response |
| Input    |      | Entropy  |      | Noisy    |
+----------+      +----+-----+      +----+-----+
                         |                 |
                         v                 v
                   +----------+      +----------+
                   | Fuzzy    | ---> | Key/Auth |
                   | Extract  |      | Output   |
                   +----------+      +----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Challenge | PUF 회로에 입력되어 특정 물리 경로 또는 셀 응답을 선택하는 값임 | 질문지 |
| 물리 엔트로피 | 지연, SRAM 초기값, 링 오실레이터 편차처럼 제조 공정 차이에서 생기는 특성임 | 지문 무늬 |
| Response | challenge에 대해 장치가 생성하는 고유하지만 잡음이 포함된 출력임 | 지문 판독 결과 |
| 오류 보정·Helper Data | 응답 흔들림을 보정해 안정적인 키를 만들도록 돕는 정보와 알고리즘임 | 흐린 지문 보정 |
| 인증·키 출력 | 장치 식별, 세션 키 생성, 암호 연산에 쓰이는 최종 결과임 | 신분 확인서 |

> 요약: PUF는 입력 challenge가 물리 엔트로피를 거쳐 잡음 있는 응답을 만들고, 오류 보정으로 인증 또는 키 결과를 생성함.

### 원리/흐름도

```text
+----------+      +----------+      +----------+      +----------+
| Enroll   | ---> | Challenge| ---> | Rebuild  | ---> | Verify   |
| Device   |      | Measure  |      | Key      |      | Identity |
+----------+      +----------+      +----------+      +----------+
```

1. **등록 단계**: 제조 또는 초기 설정 시 PUF 응답을 측정하고 helper data와 기준 정보를 생성함
2. **응답 측정**: 인증 시 challenge를 입력해 현재 환경에서 PUF response를 다시 얻음
3. **키 재구성**: fuzzy extractor와 오류 보정으로 잡음 있는 응답에서 안정적인 키를 복원함
4. **인증·사용**: 복원된 키나 응답을 서버 검증, 세션 키, 암호 연산에 사용하고 원시 응답 노출을 제한함

> 요약: PUF 사용은 등록, 응답 측정, 오류 보정, 인증·키 사용의 절차로 장치 고유성을 활용함.

## 4. 문제점 및 개선방안

- **P1 환경 민감성**: 온도, 전압, 노화 변화가 PUF 응답을 흔들어 키 재구성 실패를 만들 수 있음
- **P1 대응**: fuzzy extractor, 온도 보정, 안정 셀 선택, 재시도 정책을 적용함 (확인: 키 재구성 실패율, 환경별 비트 오류율)
- **P2 모델링 공격**: 강한 PUF에서 challenge-response가 많이 노출되면 공격자가 응답 함수를 학습할 수 있음
- **P2 대응**: CRP 노출을 제한하고 난독화, 락아웃, 인증된 challenge 절차를 도입함 (확인: 모델링 공격 성공률)
- **P3 Helper Data 관리 위험**: 보조 데이터가 부실하게 설계되면 원시 응답 정보가 새거나 재구성 실패가 증가할 수 있음
- **P3 대응**: helper data 보안 분석과 무결성 보호를 수행함 (확인: 정보 누출 평가, 변조 차단 시험)

> 요약: PUF 개선은 응답 안정화, challenge 노출 통제, helper data 안전성을 동시에 확보해야 함.

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| IoT 장치 등록 | 제조 단계에서 PUF 응답을 등록하고 서비스 접속 시 challenge-response로 장치 신원을 확인함 | 인증 성공률, CRP 노출 건수 |
| FPGA 키 보호 | SRAM PUF로 구성 비트스트림 복호화 키를 재구성하고 평상시 키 저장을 피함 | 키 재구성 실패율, 비트스트림 복호화 성공률 |
| 공급망 위조 방지 | 칩별 고유 응답을 인증서 발급과 연계해 위조 부품을 식별함 | 고유성 해밍 거리, 복제 탐지율 |

> 요약: 실무에서는 PUF의 고유성뿐 아니라 환경별 재현성과 응답 노출 통제를 지표로 확인해야 함.

## 6. 결론

- **발전 방향**: PUF는 IoT(Internet of Things), 차량, FPGA(Field-Programmable Gate Array), 공급망 인증에서 키 주입 부담을 줄이는 하드웨어 루트 신뢰 후보로 확대됨
- **기술사적 판단**: 엔트로피 원천, helper data, 오류 보정, 등록 절차, 온도·전압 변화 범위를 기준으로 PUF 구조를 선택함. 고유성, 재현성, 비트 오류율, 노화 편차, CRP 모델링 공격 저항성을 샘플 수와 환경 조건별로 측정함
- **기술사 제언**: PUF는 복제 불가 표어보다 고유성, 재현성, 오류 보정, 모델링 공격 방어 지표로 평가해야 함
