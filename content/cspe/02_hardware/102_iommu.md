## 미리 알고가기

- DMA는 장치가 CPU 개입 없이 메모리에 직접 접근하는 방식임
- IOVA는 장치가 보는 I/O 가상 주소임
- interrupt remapping은 장치 인터럽트를 올바른 VM이나 커널로 안전하게 전달하는 기능임
- IOTLB는 IOMMU 주소 변환 결과를 캐시해 DMA 지연을 줄이는 버퍼임
- SR-IOV는 하나의 물리 장치를 여러 가상 기능으로 나눠 VM에 직접 할당하는 기술임

## Ⅰ. 개요

- **정의/개념**: IOMMU는 장치 DMA가 사용하는 IOVA를 실제 물리 주소로 변환하고 장치별 접근 권한을 검사해 메모리 격리와 장치 직접 할당을 지원하는 하드웨어 메모리 관리 장치임
- **배경/필요성**: DMA 장치는 CPU MMU를 우회해 메모리에 접근하므로, 장치 오류나 악성 장치가 임의 메모리를 손상시키지 않게 하려면 장치 전용 주소 변환과 권한 제어 계층이 필요함

## Ⅱ. 특징

- 장치 DMA 경로에 별도의 주소 변환과 접근 통제를 추가함
- 장치 직접 할당과 SR-IOV 같은 가상화 시나리오의 기본 보호 장치가 됨
- 장치별 domain 단위로 메모리 접근 범위를 세밀하게 나눌 수 있음
- IOTLB miss와 잦은 매핑 변경이 성능 저하 요인이 될 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | IOMMU 미사용 | IOMMU 사용 |
|:---|:---|:---|
| DMA 주소 사용 | 장치가 물리 주소를 직접 사용함 | 장치가 IOVA를 쓰고 IOMMU가 실제 주소로 변환함 |
| 보안 격리 | 장치 오동작이 전체 메모리 손상으로 번질 수 있음 | 장치별 접근 범위를 제한하고 위반 요청을 차단할 수 있음 |
| 가상화 지원 | 안전한 장치 직접 할당이 어렵거나 제한적임 | VM별 장치 직접 할당과 DMA 격리가 쉬워짐 |
| 성능 특성 | 변환 오버헤드는 적지만 통제 수단이 약함 | IOTLB와 매핑 관리 비용이 추가되지만 보호 수준이 높음 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| DMA 장치 | NIC와 GPU와 NVMe처럼 직접 메모리 접근 요청을 생성하는 주체임 |
| IOMMU 엔진 | 주소 변환과 권한 검사를 수행해 허용된 DMA만 메모리로 전달함 |
| I/O 페이지 테이블 | 장치별 IOVA와 물리 주소 매핑을 저장해 접근 범위와 권한 정책을 결정함 |
| IOTLB | 자주 쓰는 변환 결과를 캐시해 고속 I/O의 지연을 줄임 |

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 매핑 설정      | --> | DMA 요청 발생  | --> | 변환·권한 검사 | --> | 접근 허용·차단 |
+-------------+     +-------------+     +-------------+     +-------------+
```

## Ⅴ. 원리 및 절차 흐름도

1. **매핑 설정**: OS나 하이퍼바이저가 장치 domain과 IOVA 매핑을 구성함
2. **DMA 요청 발생**: 장치가 IOVA 기반 읽기나 쓰기 요청을 보냄
3. **변환·권한 검사**: IOMMU가 IOTLB 또는 페이지 테이블로 주소와 권한을 확인함
4. **접근 허용·차단**: 허용 요청은 메모리로 전달하고 위반 요청은 fault로 보고함

## Ⅵ. 실무 적용 및 유의점

1. GPU 직접 할당이나 SR-IOV NIC를 쓰는 가상화 호스트는 IOMMU가 필수지만 IOTLB miss와 잦은 map·unmap이 지연을 키울 수 있으므로 대용량 페이지와 일괄 매핑 전략을 함께 적용하고 IOTLB miss 비율과 패킷 p99 지연시간과 DMA fault 건수로 확인함
2. 외부 PCIe 확장이나 Thunderbolt 같은 포트는 DMA 공격 경로가 될 수 있으므로 IOMMU와 인터럽트 재매핑과 장치 승인 정책을 함께 활성화하고 비인가 DMA 차단율과 장치 격리 검증 결과와 포트 정책 준수율로 확인함

## Ⅶ. 결론

IOMMU는 성능 최적화 장치가 아니라 DMA 경계를 통제하는 기본 보안 장치이므로, 장치 직접 할당 환경에서는 사실상 필수임.
