# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: I/O 장치가 직접 메모리에 접근할 때 가상 주소를 물리 주소로 변환하고 접근 권한을 통제하는 메모리 관리 하드웨어 장치
- **왜 필요한가**: 가상머신(VM)에 물리적 네트워크 카드(NIC)를 직접 할당(Passthrough)하려면, 장치가 요청하는 메모리 주소를 호스트의 물리 주소로 안전하게 변환해 주어야 한다.
- **핵심 직관**: CPU를 위한 번역기가 MMU라면, 주변장치(I/O)를 위한 번역기이자 검문소가 IOMMU다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| MMU (Memory Management Unit) | CPU가 요청한 가상 주소를 물리 주소로 변환하는 장치 | 내국인 전용 출입국 심사대 |
| DMA (Direct Memory Access) | CPU 개입 없이 I/O 장치가 메모리와 직접 데이터를 주고받는 기능 | 장치들의 직거래 |
| PCI Passthrough | 하이퍼바이저를 거치지 않고 가상머신에 물리 장치를 직접 매핑하는 기술 | 직통 차선 배정 |

## 깊이 이해
- **배경·문제의식**: 고성능 네트워크나 스토리지 장치는 성능을 위해 CPU를 거치지 않고 메모리에 직접 접근(DMA)함. 하지만 가상화 환경에서는 VM이 자신의 메모리 주소(가상 주소)로 장치에 DMA를 요청하면, 장치는 그게 실제 물리 메모리의 어디인지 모름. 하이퍼바이저가 중간에 개입해서 매번 변환해 주면 성능이 바닥을 침.
- **작동 원리**: 칩셋 내부에 IOMMU(Intel VT-d, AMD-Vi)를 배치. I/O 장치가 DMA를 시도하면, IOMMU가 하드웨어 페이지 테이블을 뒤져 장치가 보낸 주소를 물리 메모리 주소로 고속 변환해 줌. 동시에 이 장치가 접근해서는 안 되는 다른 VM의 메모리 영역을 건드리지 못하게 접근을 차단(격리)함.
- **비유**: 외국인(I/O 장치)이 건물(메모리)에 들어가려 할 때, 경비원(IOMMU)이 초청장(페이지 테이블)을 확인하고 정확한 층수(물리 주소)로 안내하며 남의 방에는 못 들어가게 막는 것.
- **구체 예시**: SR-IOV 기능이 있는 10Gbps NIC를 가상머신 10개에 나눠 줄 때, IOMMU가 있어야 각 VM이 물리 NIC의 대역폭을 하이퍼바이저 오버헤드 없이 쓸 수 있음.
- **흔한 오해·주의점**: IOMMU는 CPU 내부에 있는 것이 아니라 주로 칩셋(Northbridge/PCIe Root Complex) 측에 위치하여 I/O 버스와 메모리 사이를 중재함.

## 연결 개념
- 하드웨어 가상화 (VT-x, AMD-V)
- SR-IOV (Single Root I/O Virtualization)
- DMA (Direct Memory Access)

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: IOMMU는 I/O 장치의 DMA 요청 시 가상 주소를 물리 주소로 변환하고 접근 권한을 통제하는 하드웨어 장치이다.
> 2. **가치**: 하이퍼바이저의 소프트웨어 에뮬레이션 없이 가상머신에 물리적 장치를 직접 할당(PCI Passthrough)하여 I/O 오버헤드를 극복한다.
> 3. **판단 포인트**: 고대역폭 네트워크(10Gbps 이상)나 스토리지(NVMe) 가상화에서 SR-IOV와 IOMMU 결합은 선택이 아닌 필수 설계 요소다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| IOMMU의 역할과 위치 이해 확인 | 주소 변환(Translation) 및 메모리 격리(Isolation) | MMU와의 차이를 명시하지 못함 |
| 가상화 I/O 성능 개선 원리 파악 | PCI Passthrough, SR-IOV, DMA 연계 흐름 | 단순히 'I/O 속도 향상'으로 추상화 |

> 요약: 가상머신에서 주변장치를 에뮬레이션 없이 네이티브 속도로 사용하기 위한 하드웨어 주소 변환 체계를 묻는 문제다.

---

## Ⅰ. 개요 및 필요성

- 개요: 주변장치(I/O)가 직접 메모리에 접근할 때 가상 주소를 물리 주소로 변환하고 메모리 접근 권한을 통제하는 하드웨어 장치임
- 배경: 소프트웨어 I/O 에뮬레이션은 네트워크 패킷 처리 시 잦은 VM Exit을 유발하여 병목 발생
- 필요성: 클라우드 환경에서 가상머신이 GPU, NVMe 등 고성능 PCIe 장치의 처리량을 하이퍼바이저 지연 없이 100% 활용하기 위해 필수적임

---

## Ⅱ. 구조 및 구성요소

```text
CPU -> MMU -> RAM <- [ Memory Controller ] <- IOMMU <- PCIe Bus <- I/O Device
                                                          |
                                                    DMA Request (Virtual Address)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Translation Buffer (IOTLB) | IOMMU용 페이지 테이블 캐시 | 변환 속도 가속, 캐시 미스 시 지연 |
| Page Table Directory | 장치별로 할당된 물리 메모리 매핑 정보 | 하이퍼바이저가 메모리에 생성 및 관리 |
| Access Control Logic | 승인되지 않은 메모리 접근 차단 | DMA 공격(DMA Attack) 방지 및 VM 격리 |

> 요약: IOMMU는 CPU용 MMU와 별도로 I/O 버스 측에 위치하며, IOTLB를 통해 DMA 주소를 고속으로 변환하고 격리한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
VM의 장치 사용 -> Device DMA 요청 -> IOMMU 테이블 조회 -> 권한 검증 -> 메모리 접근 완료
```

- 1단계 [DMA 요청]: 가상머신 내부에서 I/O 장치(예: NIC)로 가상 주소 기반 DMA 요청 발생
- 2단계 [주소 변환]: IOMMU가 IOTLB 또는 페이지 테이블을 조회하여 게스트 물리 주소를 호스트 물리 주소로 변환
- 3단계 [권한 검증]: 해당 장치가 요청한 메모리 영역에 접근(Read/Write)할 권한이 있는지 통제 로직 확인
- 4단계 [물리 메모리 접근]: 검증 통과 시 호스트 물리 메모리에 직접 데이터를 읽고 쓰며 작업 완료

> 요약: I/O 장치의 DMA 트래픽은 반드시 IOMMU를 거쳐 주소 변환과 격리 검증을 통과해야 실제 물리 메모리에 도달한다.

---

## Ⅳ. 특징
- PCI Passthrough 지원: 가상머신에 물리적 하드웨어를 직접 맵핑하여 네이티브 수준의 I/O 처리량 확보
- DMA 공격 방어: 장치가 임의의 커널 메모리 영역을 덮어쓰는 행위(예: FireWire DMA Attack)를 하드웨어적으로 원천 차단
- 변환 오버헤드 존재: IOTLB 미스 시 메인 메모리의 페이지 테이블을 걷는(Page Walk) 추가 지연 시간(Latency) 발생

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | MMU (Memory Management Unit) | IOMMU (I/O MMU) |
|:---|:---|:---|
| 요청 주체 | CPU (프로세서) | I/O 주변 장치 (NIC, GPU 등) |
| 변환 방향 | CPU 가상 주소 -> 물리 주소 | 장치 가상 주소 -> 호스트 물리 주소 |
| 보안 목적 | 프로세스 간 메모리 격리 | VM 간 장치 격리 및 DMA 권한 통제 |

> 요약: MMU가 OS 커널을 악성 프로세스로부터 보호한다면, IOMMU는 물리 서버를 악성 I/O 장치나 훼손된 VM으로부터 보호한다.

- IOTLB 병목 리스크: 과도한 소규모 패킷 DMA는 IOTLB 스래싱 유발 → 거대 페이지(Huge Pages)를 VM에 할당하여 IOTLB 엔트리 효율 극대화
- 이기종 환경 호환성 리스크: 인텔(VT-d)과 AMD(AMD-Vi) 간 하드웨어 구현 종속성 → 리눅스 커널의 공통 VFIO 프레임워크로 추상화 통제

- I/O 처리량: PCI Passthrough 활성화 전후의 초당 패킷 처리량(PPS) — iperf, pktgen 측정
- 지연 시간: IOMMU Page Walk로 인한 DMA 응답 지연(us) — 커널 트레이싱(ftrace)

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. BIOS 및 부트로더 설정: 서버 BIOS에서 VT-d/AMD-Vi를 활성화하고, 커널 부트 파라미터(`iommu=on`)를 통해 OS 레벨 IOMMU 활성화
2. SR-IOV 연계 아키텍처: 100Gbps 이상 NIC 도입 시 IOMMU와 SR-IOV를 동시 적용하여 물리 포트 하나를 수십 개의 가상 기능(VF)으로 분할, VM에 직접 매핑
3. VFIO 드라이버 적용: KVM/QEMU 환경에서 기존 드라이버 대신 VFIO(Virtual Function I/O) 프레임워크를 사용해 안전하고 빠른 유저스페이스 DMA 구현

**결론 (2줄):**
- 기술사 판단: 클라우드 인프라에서 AI 훈련(GPU)이나 고속 네트워크(SmartNIC)를 지연 없이 서비스하려면 IOMMU 기반의 Passthrough 아키텍처가 필수적임
- 향후 방향: PCIe 트래픽 증가에 따라 IOMMU의 주소 변환 오버헤드조차 병목이 되고 있어, CXL 기반 메모리 확장 구조를 고려한 차세대 캐시 일관성 연계가 요구됨
