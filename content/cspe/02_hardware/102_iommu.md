## 미리 알고가기

- DMA는 장치가 CPU 개입 없이 메모리에 직접 접근하는 방식임
- IOVA는 장치가 보는 I/O 가상 주소임
- 인터럽트 재매핑(interrupt remapping)은 장치 인터럽트를 지정한 VM이나 커널로 전달하는 기능임
- IOTLB는 IOMMU 주소 변환 결과를 캐시해 DMA 지연을 줄이는 버퍼임
- SR-IOV는 하나의 물리 장치를 여러 가상 기능으로 나눠 VM에 직접 할당하는 기술임

## 작성 근거(검토용)

- IOMMU는 IOVA 변환, 장치 도메인, I/O 페이지 테이블, IOTLB, DMA 권한 검사를 핵심 축으로 설명함
- 비교표는 미사용·사용 구조의 주소, 격리, 가상화, 변환 경로를 대비함
- 실무 판단은 IOTLB 미스율·패킷 지연과 비인가 DMA 차단률·격리 시험 통과율로 검증함

## Ⅰ. 개요

- **정의/개념**: IOMMU는 장치 DMA가 사용하는 IOVA를 실제 물리 주소로 변환하고 장치별 접근 권한을 검사해 메모리 격리와 장치 직접 할당을 지원하는 하드웨어 메모리 관리 장치임
- **배경/필요성**: DMA 장치의 임의 메모리 접근을 제한하기 위해 장치 전용 주소 변환과 권한 제어 계층이 필요함

## Ⅱ. 특징

- 장치 DMA 경로에 별도의 주소 변환과 접근 통제를 추가함
- 장치 직접 할당과 SR-IOV 같은 가상화 시나리오의 기본 보호 장치가 됨
- 장치별 도메인(domain) 단위로 메모리 접근 범위를 나눌 수 있음
- IOTLB 미스와 잦은 매핑 변경은 DMA 주소 변환 지연을 늘림

## Ⅲ. 종류 및 비교

| 판단 기준 | IOMMU 미사용 | IOMMU 사용 |
|:---|:---|:---|
| DMA 주소 사용 | 장치가 물리 주소를 직접 사용함 | 장치가 IOVA를 쓰고 IOMMU가 실제 주소로 변환함 |
| 보안 격리 | 장치 오동작이 전체 메모리 손상으로 번질 수 있음 | 장치별 접근 범위를 제한하고 위반 요청을 차단할 수 있음 |
| 가상화 지원 | 장치 DMA 주소를 VM별로 분리하지 못함 | VM별 DMA 주소 공간과 장치 매핑을 분리함 |

> 요약: IOMMU는 장치가 사용하는 IOVA를 물리 주소로 변환하고 장치 도메인별 DMA 권한을 검사함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| DMA 장치 | NIC와 GPU와 NVMe처럼 직접 메모리 접근 요청을 생성하는 주체임 |
| IOMMU 엔진 | 주소 변환과 권한 검사를 수행해 허용된 DMA만 메모리로 전달함 |
| I/O 페이지 테이블 | 장치별 IOVA와 물리 주소 매핑을 저장해 접근 범위와 권한 정책을 결정함 |
| IOTLB | 자주 쓰는 변환 결과를 캐시해 고속 I/O의 지연을 줄임 |

> 요약: I/O 페이지 테이블과 IOTLB가 장치별 IOVA를 물리 주소로 변환하고 IOMMU 엔진이 DMA 권한을 검사함.

## Ⅴ. 원리 및 절차 흐름도

1. **매핑 설정**: OS나 하이퍼바이저가 장치 도메인과 IOVA 매핑을 구성함
2. **DMA 요청 발생**: 장치가 IOVA 기반 읽기나 쓰기 요청을 보냄
3. **변환·권한 검사**: IOMMU가 IOTLB 또는 페이지 테이블로 주소와 권한을 확인함
4. **접근 허용·차단**: 허용 요청은 메모리로 전달하고 위반 요청은 fault로 보고함

> 요약: OS가 장치 도메인과 IOVA 매핑을 설정하면 IOMMU가 DMA마다 주소와 권한을 검사함.

## Ⅵ. 실무 사례

1. SR-IOV NIC 가상화 호스트는 대용량 페이지와 일괄 매핑을 적용하고 IOTLB 미스율·p99 패킷 지연을 확인함
2. Thunderbolt 포트는 IOMMU·인터럽트 재매핑과 장치 승인을 적용하고 비인가 DMA 차단률·격리 시험 통과율을 확인함

## Ⅶ. 결론

- IOMMU는 장치 직접 할당 전에 장치 도메인·IOVA 범위·인터럽트 재매핑을 설정하고 DMA 오류·격리 시험으로 검증해야 함
