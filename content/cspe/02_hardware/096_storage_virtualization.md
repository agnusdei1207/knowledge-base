## 미리 알고가기

- 논리 볼륨은 여러 물리 저장장치를 추상화해 제공하는 저장 단위임
- storage pool은 여러 장치의 용량과 성능을 하나의 자원 집합으로 묶은 구조임
- thin provisioning은 실제 사용 시점까지 물리 용량 할당을 늦추는 방식임

## Ⅰ. 개요

- **정의/개념**: 스토리지 가상화는 물리 디스크와 어레이와 LUN을 논리 볼륨과 스토리지 풀로 추상화해 위치와 장치 차이를 숨기고 정책 중심으로 저장 자원을 제공하는 기술임
- **배경/필요성**: 물리 장치 단위 운영은 용량 단편화와 벤더 종속과 무중단 이전의 어려움을 키우므로, 운영 유연성과 자원 활용률을 높이려면 가상화 계층이 필요함

## Ⅱ. 특징

- 물리 장치와 서비스 제공 단위를 분리해 풀링과 논리 볼륨 구성이 쉬움
- snapshot과 replication과 migration 같은 데이터 서비스를 중앙 정책으로 제공할 수 있음
- thin provisioning으로 초기 증설 비용을 줄일 수 있지만 과할당 위험이 생김
- 가상화 엔진 자체가 성능 경로이자 장애 도메인이 됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 물리 직접 운영 | 스토리지 가상화 |
|:---|:---|:---|
| 자원 관리 | 장치별로 개별 할당과 수작업 운영이 많음 | pool 기반으로 중앙 할당과 재배치가 쉬움 |
| 데이터 이동 | 장치 교체나 이전 시 중단과 수작업 부담이 큼 | 논리 매핑 변경으로 migration과 확장이 쉬움 |
| 운영 기능 | 장비별 도구에 의존하는 경우가 많음 | snapshot과 clone과 replication을 통합해 제공함 |
| 유의점 | 구조는 단순하지만 자원 활용률이 떨어질 수 있음 | 매핑 계층 병목과 장애 범위를 함께 관리해야 함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 호스트 인터페이스 | 서버에 논리 볼륨을 제공해 애플리케이션이 물리 위치를 직접 알지 않게 함 |
| 가상화 엔진 | 논리 주소를 물리 위치에 매핑하고 thin provisioning과 migration 정책을 집행함 |
| 스토리지 풀 | 성능과 보호 수준이 다른 저장장치를 묶어 용량 활용률과 확장성을 높임 |
| 데이터 서비스 계층 | snapshot과 clone과 replication을 제공해 복구와 운영 자동화를 지원함 |

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 풀 구성        | --> | 논리 볼륨 할당 | --> | 주소 매핑      | --> | 정책 운영      |
+-------------+     +-------------+     +-------------+     +-------------+
```

## Ⅴ. 원리 및 절차 흐름도

1. **풀 구성**: 물리 저장장치를 성능과 보호 수준별 자원 풀로 등록함
2. **논리 볼륨 할당**: 업무 요구에 맞는 논리 볼륨과 용량 정책을 설정함
3. **주소 매핑**: 논리 블록 주소를 실제 디스크와 RAID 배치에 연결함
4. **정책 운영**: snapshot과 복제와 migration과 임계치 관리를 수행함

## Ⅵ. 실무 적용 및 유의점

1. 통합 스토리지 운영은 가상화로 자원 활용률을 높이기 좋지만 메타데이터 경로가 병목이 되면 전체 지연이 올라가므로 엔진 이중화와 캐시·메타데이터 분리를 함께 두고 가상화 지연 오버헤드와 캐시 적중률과 절체 시간으로 확인함
2. thin provisioning은 초기 비용 절감에 유리하지만 물리 용량 고갈이 한 번에 대규모 쓰기 실패로 번질 수 있으므로 임계치 기반 증설과 할당량을 운영하고 물리 여유 용량과 임계치 초과 건수와 과할당 비율로 확인함

## Ⅶ. 결론

스토리지 가상화의 가치는 추상화 자체보다 성능 오버헤드와 과할당과 장애 범위를 통제하면서 운영 유연성을 얻는 데 있음.
