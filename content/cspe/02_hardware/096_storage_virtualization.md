## 미리 알고가기

- 논리 볼륨은 여러 물리 저장장치를 추상화해 제공하는 저장 단위임
- 스토리지 풀(storage pool)은 여러 장치의 용량과 성능을 하나의 자원 집합으로 묶은 구조임
- 씬 프로비저닝(thin provisioning)은 실제 사용 시점까지 물리 용량 할당을 늦추는 방식임

## 작성 근거(검토용)

- 스토리지 가상화는 논리·물리 주소 매핑, 자원 풀, 씬 프로비저닝, 데이터 서비스를 핵심 축으로 설명함
- 비교표는 직접 운영과 가상화의 할당, 이동, 데이터 서비스, 장애 조건을 대비함
- 실무 판단은 가상화 지연·절체 시간과 물리 여유 용량·과할당 비율로 검증함

## Ⅰ. 개요

- **정의/개념**: 스토리지 가상화는 물리 디스크와 어레이와 LUN을 논리 볼륨과 스토리지 풀로 추상화해 위치와 장치 차이를 숨기고 정책 중심으로 저장 자원을 제공하는 기술임
- **배경/필요성**: 여러 저장장치의 여유 용량을 공유하고 데이터 위치를 이관하기 위해 장치를 논리 풀로 묶는 가상화 계층이 필요함

## Ⅱ. 특징

- 물리 장치 위치와 호스트에 제공하는 논리 볼륨을 분리해 풀 단위로 할당함
- 스냅샷·복제·이관 같은 데이터 서비스를 중앙 정책으로 제공할 수 있음
- 씬 프로비저닝은 초기 물리 할당량을 줄이지만 과할당 위험이 생김
- 가상화 엔진 자체가 성능 경로이자 장애 도메인이 됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 물리 직접 운영 | 스토리지 가상화 |
|:---|:---|:---|
| 자원 관리 | 장치별 용량·볼륨을 개별 할당함 | 풀에서 논리 볼륨과 정책을 중앙 할당함 |
| 데이터 이동 | 호스트 경로와 장치별 볼륨을 직접 변경함 | 논리 매핑을 유지하며 물리 블록을 이전함 |
| 운영 기능 | 장비별 도구에 의존하는 경우가 많음 | 스냅샷·복제·클론을 통합해 제공함 |
| 유의점 | 구조는 단순하지만 자원 활용률이 떨어질 수 있음 | 매핑 계층 병목과 장애 범위를 함께 관리해야 함 |

> 요약: 스토리지 가상화는 논리 주소와 물리 장치를 분리해 할당·이동·복제 정책을 중앙에서 적용함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 호스트 인터페이스 | 서버에 논리 볼륨을 제공해 애플리케이션이 물리 위치를 직접 알지 않게 함 |
| 가상화 엔진 | 논리 주소를 물리 위치에 매핑하고 씬 프로비저닝과 이관 정책을 집행함 |
| 스토리지 풀 | 성능과 보호 수준이 다른 저장장치를 묶어 용량 활용률과 확장성을 높임 |
| 데이터 서비스 계층 | 스냅샷·클론·복제를 제공해 복구와 운영 자동화를 지원함 |

> 요약: 가상화 엔진이 논리 볼륨을 물리 블록에 매핑하고 스토리지 풀의 할당·복제·이관 정책을 집행함.

## Ⅴ. 원리 및 절차 흐름도

1. **풀 구성**: 물리 저장장치를 성능과 보호 수준별 자원 풀로 등록함
2. **논리 볼륨 할당**: 업무 요구에 맞는 논리 볼륨과 용량 정책을 설정함
3. **주소 매핑**: 논리 블록 주소를 실제 디스크와 RAID 배치에 연결함
4. **정책 운영**: 스냅샷·복제·이관과 용량 임계치 관리를 수행함

> 요약: 물리 장치를 풀로 등록하고 논리 볼륨의 주소를 매핑한 뒤 복제·이동·용량 정책을 적용함.

## Ⅵ. 실무 사례

1. 통합 스토리지 컨트롤러는 가상화 엔진을 이중화하고 가상화 지연·절체 시간을 확인함
2. 가상화 서버의 스토리지 풀은 씬 프로비저닝 임계치와 할당량을 설정하고 물리 여유 용량·과할당 비율을 확인함

## Ⅶ. 결론

- 스토리지 가상화는 논리·물리 매핑 지연과 장애 범위를 통제하고 씬 프로비저닝의 물리 용량 임계치를 관리해야 함
