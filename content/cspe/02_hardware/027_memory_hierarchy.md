## 미리 알고가기

- 메모리 계층은 속도·용량·비용이 다른 저장 자원을 층으로 배치한 구조임
- 상위 계층일수록 빠르지만 비싸고 작으며 하위 계층일수록 느리지만 크고 저렴함
- 지역성은 계층 구조가 평균 접근 시간을 낮출 수 있게 하는 전제임

## 작성 근거(검토용)

- 메모리 계층은 장치 나열보다 적중·실패와 상하위 계층 이동을 중심으로 설명함
- 상위·하위 계층을 지연·용량·비트당 비용·관리 정책으로 비교함
- 접근 빈도와 계층별 지연·용량을 데이터 배치 기준으로 정리함

## Ⅰ. 개요

- **정의/개념**: 메모리 계층 구조는 레지스터·캐시·주기억장치·보조저장장치를 속도·용량·비용 특성에 따라 계층화하고, 자주 쓰는 데이터를 상위 층에 유지해 평균 접근 시간을 최소화하는 시스템 설계 원리임
- **배경/필요성**: 속도·용량·비용 요구를 함께 만족하기 위해 서로 다른 저장 자원을 결합한 지역성 기반 계층 구조가 필요함

## Ⅱ. 특징

- 상위 계층은 낮은 지연과 작은 용량을, 하위 계층은 높은 용량과 낮은 비용을 담당함
- 데이터 이동 정책과 지역성 활용 수준이 평균 접근 시간과 처리량을 좌우함
- 상위 계층에서 데이터가 없으면 하위 계층의 추가 접근 지연이 발생함
- 최근에는 HBM·CXL·SSD 계층이 추가되어 단일 서버 안에서도 계층이 복잡해짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 상위 계층 | 하위 계층 |
|:---|:---|:---|
| 대표 자원 | 레지스터, L1/L2/L3 캐시 | DRAM, SSD, HDD, 원격 메모리 |
| 접근 지연 | 짧음 | 상위 계층보다 김 |
| 용량 | 작음 | 상위 계층보다 큼 |
| 비트당 비용 | 높음 | 상위 계층보다 낮음 |
| 관리 전략 | 라인 교체·사전 인출로 상위 계층 적중률 조정 | 배치·압축·캐싱·계층 이동으로 하위 계층 접근량 조정 |

> 요약: 상위 계층은 지연을 줄이고, 하위 계층은 용량과 비용을 담당함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 레지스터 | 현재 명령이 사용하는 피연산자와 중간 결과를 저장함 |
| 캐시 계층 | L1·L2·L3가 최근 사용한 데이터를 보관해 DRAM 접근 횟수를 줄임 |
| 주기억장치 | 실행 중인 작업 집합을 보관하고 캐시 실패 시 데이터를 공급함 |
| 보조·확장 메모리 | SSD·원격 메모리·CXL 풀이 주기억장치보다 큰 용량을 제공함 |

```text
+-----------+
| 레지스터  |
+-----------+
      |
      v
+-----------+
| L1 / L2   |
+-----------+
      |
      v
+-----------+
| L3 캐시    |
+-----------+
      |
      v
+-----------+
| DRAM      |
+-----------+
      |
      v
+-----------+
| SSD / CXL |
+-----------+
```

> 요약: 레지스터, 캐시, DRAM, SSD/CXL은 용량과 지연을 나눠 맡아 평균 접근 시간을 낮춤.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+     +-------------+
| CPU 요청 발생   | --> | 상위 계층 조회   | --> | 실패 시 하위 계층 조회 | --> | 데이터 상위 적재   | --> | 다음 요청 처리   |
+-------------+     +-------------+     +-------------+     +-------------+     +-------------+
```

1. **CPU 요청 발생**: 명령이 필요한 데이터를 우선 상위 계층에서 찾음
2. **상위 계층 조회**: 레지스터와 캐시에서 적중 여부를 판단함
3. **실패 시 하위 계층 조회**: 없으면 DRAM이나 저장장치에서 데이터를 찾음
4. **데이터 상위 적재**: 찾은 데이터를 상위 계층에 적재함
5. **다음 요청 처리**: 재참조되면 적재된 상위 계층에서 데이터를 제공함

> 요약: 요청은 상위 계층부터 조회하고 없으면 하위 계층에서 가져와 상위 계층에 적재함.

## Ⅵ. 실무 사례

1. 수치 계산 응용은 캐시 블로킹을 적용하고 캐시 실패율과 메모리 대기 사이클 비율을 확인함
2. CXL 확장 메모리 서버는 사용 빈도 기반 계층 배치를 적용하고 상위 계층 적중률과 종단 메모리 지연을 확인함

## Ⅶ. 결론

- 메모리 계층은 데이터의 접근 빈도와 계층별 지연·용량을 기준으로 저장 위치를 정해야 함
