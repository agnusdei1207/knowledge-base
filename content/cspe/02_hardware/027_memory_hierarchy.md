## 미리 알고가기

- 참조 지역성: 시간적으로 최근 사용한 데이터와 공간적으로 가까운 데이터가 다시 사용될 가능성이 높은 성질임
- 캐시 라인: 캐시와 하위 메모리 사이에서 이동하는 고정 크기 데이터 블록임
- 지연시간: 요청 후 첫 데이터가 도착할 때까지 걸리는 시간임
- 대역폭: 단위 시간에 전송 가능한 데이터량임
- DRAM/SSD: 동적 램(Dynamic Random Access Memory, DRAM)은 주기억장치, 솔리드 스테이트 드라이브(Solid State Drive, SSD)는 보조기억장치 계층의 대표 매체임

## Ⅰ. 개요

- **정의**: 메모리 계층 구조는 레지스터, 캐시, 주기억장치, 보조기억장치를 속도·용량·비용 기준으로 계층화하고 참조 지역성을 이용해 자주 쓰는 데이터를 상위 계층에 배치하는 컴퓨터 저장 구조임
- **배경/필요성**: 중앙처리장치(Central Processing Unit, CPU) 속도는 메모리 접근 속도보다 빠르게 증가해 단일 메모리만으로는 처리 성능을 맞추기 어려움. 계층 구조는 작은 고속 메모리와 큰 저속 메모리를 조합해 비용과 성능을 균형화함
- **비유**: 자주 쓰는 도구는 손에 들고, 덜 쓰는 도구는 책상, 창고, 외부 보관소에 두는 작업 공간 배치와 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 저장장치 선택을 지연·용량·비용·지역성 관점에서 설명하는 역량 확인 | 레지스터, 캐시, DRAM, SSD, locality, hit/miss | 단순 속도 순서 나열, 캐시 원리 누락, 비용 기준 누락 |

> 요약: 메모리 계층은 지역성을 이용해 작은 고속 저장소가 큰 저속 저장소를 보완하게 만드는 구조임.

## Ⅱ. 특징/비교

| 판단 기준 | 상위 계층 | 하위 계층 |
|:---|:---|:---|
| 속도와 지연 | 빠르고 CPU에 가까움 | 접근 지연이 크고 CPU와 멀리 있음 |
| 용량과 비용 | 작고 비트당 비용이 높음 | 크고 비트당 비용이 낮음 |
| 관리 단위 | 레지스터, 캐시 라인처럼 작음 | 페이지, 블록, 파일처럼 큼 |
| 설계 질문 | 적중률을 어떻게 높일 것인가 | 용량과 지속성을 어떻게 확보할 것인가 |

> 요약: 계층 구조는 속도와 비용이 반대로 움직이는 저장장치를 지역성으로 연결하는 설계임.

- 시간 지역성은 최근 사용한 데이터를 캐시에 유지하는 교체 정책의 근거가 됨
- 공간 지역성은 인접 데이터를 캐시 라인 단위로 함께 가져오는 전송 정책의 근거가 됨
- 계층 간 miss가 누적되면 CPU stall, 페이지 폴트, 스토리지 입출력(Input/Output, I/O) 지연으로 확대됨

## Ⅲ. 구성요소

```text
+-----------+ -> +-----------+ -> +-----------+ -> +-----------+
| Register  |    | Cache     |    | DRAM      |    | SSD/HDD   |
+-----------+    +-----------+    +-----------+    +-----------+
   fastest          low latency       large             persistent
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 레지스터 | CPU 내부에서 명령 실행에 직접 쓰는 가장 빠르고 작은 저장소임 | 손에 쥔 도구 |
| 캐시 | 자주 쓰는 메모리 블록을 저장해 DRAM 접근을 줄이는 고속 저장소임 | 책상 위 도구함 |
| 주기억장치 | 실행 중인 프로그램과 데이터를 담는 DRAM 기반 작업 공간임 | 작업실 |
| 보조기억장치 | 전원이 꺼져도 데이터를 유지하는 SSD, 하드 디스크 드라이브(Hard Disk Drive, HDD) 등 대용량 저장소임 | 창고 |

> 요약: 메모리 계층은 CPU에 가까울수록 빠르고 작으며 멀수록 느리지만 크고 저렴한 저장소로 구성됨.

## Ⅳ. 절차

```text
+-----------+      +-----------+      +-----------+      +------------+
| Request   | ---> | Upper Hit | ---> | Miss Fill | ---> | Return Data|
+-----------+      +-----------+      +-----------+      +------------+
```

1. **주소 요청**: CPU가 명령어 또는 데이터 접근을 요청함
2. **상위 계층 조회**: 레지스터, L1/L2/L3 캐시처럼 가까운 계층부터 적중 여부를 확인함
3. **miss 처리**: 적중하지 않으면 하위 계층에서 블록을 가져와 상위 계층에 배치함
4. **데이터 반환**: 요청 데이터를 CPU에 전달하고 교체·쓰기 정책에 따라 상태를 갱신함

> 요약: 메모리 접근은 가까운 계층부터 확인하고 실패할 때마다 아래 계층으로 내려가 데이터를 가져오는 흐름임.

## Ⅴ. 문제점 및 개선방안

- **P1 계층 간 속도 격차**: CPU와 DRAM, DRAM과 SSD의 지연 차이가 커 miss 비용이 성능을 지배할 수 있음
- **P1 대응**: locality를 높이는 자료구조와 prefetch 정책을 적용함 (확인: 최종 레벨 캐시(Last-Level Cache, LLC) miss와 stall cycles)
- **P2 캐시 오염과 충돌**: 재사용 가능성이 낮은 데이터가 캐시에 들어오거나 같은 세트에 몰리면 유효 적중률이 낮아짐
- **P2 대응**: 캐시 친화적 접근 순서와 교체·우회 정책을 적용함 (확인: cache hit ratio)
- **P3 일관성 관리 비용**: 멀티코어와 직접 메모리 접근(Direct Memory Access, DMA) 장치가 같은 데이터를 접근하면 캐시 일관성과 동기화 비용이 발생함
- **P3 대응**: 공유 데이터 최소화와 일관성 프로토콜 영향 분석을 수행함 (확인: coherence traffic)

> 요약: 계층 구조 개선은 상위 적중률을 높이고 하위 접근의 지연을 숨기는 방향으로 진행함.

## Ⅵ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 데이터 분석 엔진 | columnar scan, cache blocking, prefetch로 공간 지역성과 순차 접근을 높임 | LLC miss, memory bandwidth, query time |
| 온라인 트랜잭션 처리(Online Transaction Processing, OLTP) 서버 | hot index는 DRAM과 cache 친화 구조에 두고 cold data는 SSD 계층으로 분리함 | buffer hit ratio, page fault, p99 latency |
| 멀티코어 장치 드라이버 | DMA buffer와 공유 queue의 cache line padding, flush, invalidate 정책을 명확히 함 | coherence traffic, false sharing count |

> 요약: 실무 메모리 계층 설계는 hot data 위치, 접근 순서, 일관성 비용을 계층별 지표로 확인함.

## Ⅶ. 전망

- **발전 방향**: 고대역폭 메모리(High Bandwidth Memory, HBM), 컴퓨트 익스프레스 링크(Compute Express Link, CXL) 메모리, 비휘발성 램(Non-Volatile Random Access Memory, NVRAM)이 결합되며 DRAM 중심 계층에서 대역폭형·용량형 메모리의 혼합 계층으로 확장됨
- **기술사적 판단**: 인공지능(Artificial Intelligence, AI)과 데이터 분석 워크로드는 연산 성능보다 메모리 대역폭과 데이터 이동 비용이 병목이 되는 경우가 늘어남
- **기술사 제언**: 기술사는 저장장치를 빠른 순서로 나열하는 데서 그치지 않고 요구 대역폭, 지연, 용량, 비용을 기준으로 계층을 설계해야 함
