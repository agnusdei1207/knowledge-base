## Ⅰ. 개요
- **정의**: 속도·용량·비용이 다른 저장 매체를 계층적으로 배치하여 성능과 용량을 동시에 확보하는 구조
- **배경/필요성**: CPU 처리 속도와 메모리 접근 속도 간 격차가 매 세대 확대되므로, 빠르고 작은 메모리를 CPU 가까이 두어 격차를 완화할 필요가 있음
- **비유**: 책상 위 메모지(레지스터)→ 서랍(캐시)→ 책장(RAM)→ 창고(디스크) 순으로 멀어질수록 많이 담지만 꺼내기 느린 구조와 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 계층별 속도-용량 트레이드오프 이해 | 지역성 원리(시간·공간) 기반 설계 | 단순 나열이 아닌 지역성 원리와 연계하여 설명할 것 |

> 요약: 속도-용량 트레이드오프를 지역성 원리로 극복하는 다층 저장 구조임

## Ⅱ. 구성요소
```text
        +-------------+
        |  Register   |  <-- 가장 빠름, 수 B
        +-------------+
        |  L1 Cache   |  ~1ns, 수십 KB
        +-------------+
        |  L2 Cache   |  ~3-10ns, 수백 KB
        +-------------+
        |  L3 Cache   |  ~10-30ns, 수~수십 MB
        +-------------+
        |  Main Mem   |  ~50-100ns, 수~수백 GB
        +-------------+
        |  Storage    |  ~us-ms, 수 TB
        +-------------+
        (위로 갈수록 빠르고 작음)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 레지스터 | CPU 내부 연산용 저장소, 1사이클 접근 | 손에 쥔 메모지 |
| L1/L2/L3 캐시 | SRAM 기반, CPU와 메인 메모리 간 속도 격차를 흡수함 | 책상 서랍(L1)~옆 선반(L3) |
| 메인 메모리 | DRAM 기반, 실행 중인 프로그램과 데이터를 적재함 | 사무실 책장 |
| 보조 저장장치 | SSD/HDD, 비휘발성으로 대용량 데이터를 영구 보관함 | 별도 창고 |

> 요약: 레지스터→캐시→메인 메모리→보조 저장장치 순으로 용량 증가·속도 감소하는 4계층 구조임

## Ⅲ. 절차
```text
CPU 데이터 요청 --> L1 Hit? --Yes--> 데이터 반환
                      |
                      No
                      v
                   L2 Hit? --Yes--> L1에 적재 후 반환
                      |
                      No
                      v
                   L3 Hit? --Yes--> L2/L1에 적재 후 반환
                      |
                      No
                      v
                  Main Mem 접근 --> 캐시 라인 적재 후 반환
```
- 1단계: CPU가 L1 캐시에서 데이터를 탐색하며, 히트 시 1~2사이클 내 반환함
- 2단계: L1 미스 시 L2→L3 순으로 탐색하며, 히트한 계층에서 상위 캐시로 데이터를 적재함
- 3단계: 모든 캐시 미스 시 메인 메모리에 접근하여 캐시 라인 단위로 데이터를 가져옴
- 4단계: 메인 메모리에도 없으면 페이지 폴트가 발생하여 보조 저장장치에서 페이지를 스왑인함

> 요약: 상위 계층부터 순차 탐색하여 히트하면 반환, 미스 시 하위 계층으로 내려가는 절차임

## Ⅳ. 문제점
- 캐시 미스 누적: 작업 세트가 캐시 용량을 초과하면 미스율이 급증하여 메인 메모리 접근 빈도가 높아짐
- 일관성 유지 부담: 멀티코어 환경에서 동일 데이터를 여러 캐시가 보유하면 일관성 프로토콜(MESI 등) 오버헤드가 증가함
- 계층 간 대역폭 병목: 상위 계층이 포화되면 하위 계층 접근이 집중되어 버스·인터커넥트 대역폭이 한계에 도달함

> 요약: 캐시 미스·일관성 오버헤드·대역폭 병목이 계층 구조의 주요 한계임

## Ⅴ. 개선방안
1. 단기: 프리페치·캐시 라인 최적화로 캐시 히트율을 높여 미스 누적을 완화함
2. 중기: 스누프 필터·디렉토리 기반 프로토콜로 일관성 트래픽을 감소시킴
3. 장기: HBM·CXL 메모리 풀 도입으로 계층 간 대역폭 격차를 축소함

> 요약: 히트율 향상·일관성 최적화·차세대 메모리로 계층 구조 한계를 개선함

## Ⅵ. 전망
- 발전 방향: 3D 적층·Processing-in-Memory 기술로 계층 간 물리적 거리가 줄어드는 추세임
- 기술사적 판단: AI 워크로드의 대용량 모델 파라미터 접근 패턴으로 메모리 계층 최적화 중요성이 증가함
- 기술사 제언: 소프트웨어 설계 시 데이터 지역성을 고려한 자료구조·알고리즘 선택이 필요함
