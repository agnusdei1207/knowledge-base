## Ⅰ. 개요
- **정의**: 속도·용량·비용이 다른 저장 장치를 계층적으로 배치하여 성능과 비용을 균형시키는 구조임
- **배경/필요성**: CPU 연산 속도와 메모리 접근 속도 격차(Memory Wall)가 계속 벌어지므로, 빈번히 사용하는 데이터를 빠른 계층에 유지하여 평균 접근 시간을 줄일 필요
- **비유**: 책상 위 자주 쓰는 문서(레지스터) → 책장(캐시) → 창고(DRAM) → 외부 보관소(SSD/HDD) 순으로 멀어질수록 꺼내기 느린 구조와 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 계층별 속도·용량 트레이드오프 이해 | 지역성(temporal/spatial) 원리 | 캐시 히트율과 평균 접근 시간 계산식 누락 주의 |

> 요약: 속도-용량-비용 트레이드오프를 지역성 원리로 극복하는 계층적 저장 구조임

## Ⅱ. 구성요소
```text
        +-------------+
        | Register    |  <-- 가장 빠름, 가장 작음
        +------+------+
               |
        +------+------+
        | L1 Cache    |
        +------+------+
               |
        +------+------+
        | L2 Cache    |
        +------+------+
               |
        +------+------+
        | L3 Cache    |
        +------+------+
               |
        +------+------+
        | DRAM        |
        +------+------+
               |
        +------+------+
        | SSD / HDD   |  <-- 가장 느림, 가장 큼
        +-------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 레지스터 | CPU 내부 저장소, 1 사이클 접근, 수 KB | 손에 쥔 메모지 |
| L1 캐시 | 코어 전용, 1~4 사이클, 32~64 KB | 책상 위 바인더 |
| L2 캐시 | 코어 전용/공유, 4~12 사이클, 256 KB~1 MB | 책상 서랍 |
| L3 캐시 | 코어 간 공유, 20~40 사이클, 수~수십 MB | 사무실 책장 |
| DRAM | 주기억장치, 60~100 ns, 수 GB~수 TB | 건물 내 창고 |
| SSD/HDD | 보조기억장치, us~ms 단위, 수 TB | 외부 보관 창고 |

> 요약: 레지스터에서 보조기억장치까지 속도는 감소하고 용량은 증가하는 6단 계층으로 구성됨

## Ⅲ. 절차
```text
CPU 데이터 요청 --> L1 확인 --HIT--> 반환
                       |
                      MISS
                       v
                   L2 확인 --HIT--> L1 적재 후 반환
                       |
                      MISS
                       v
                   L3 --> DRAM --> SSD/HDD (순차 탐색)
                       |
                       v
                   상위 계층에 적재 후 반환
```
- 1단계: CPU가 데이터 요청 시 L1 캐시에서 태그 비교로 히트 여부 판별
- 2단계: L1 미스 시 L2 → L3 순으로 탐색하며, 히트되면 상위 계층에 적재
- 3단계: 모든 캐시 미스 시 DRAM에서 캐시 라인 단위로 데이터를 가져와 적재
- 4단계: DRAM에도 없으면(페이지 폴트) SSD/HDD에서 페이지 단위로 DRAM에 적재 후 반환

> 요약: 상위 계층부터 순차 탐색하여 히트 시 반환, 미스 시 하위 계층으로 내려가며 적재함

## Ⅳ. 문제점
- Memory Wall: CPU 클럭은 매 세대 향상되나 DRAM 지연은 상대적으로 느리게 개선 — CPU 유휴 사이클 증가
- 캐시 오염: 일회성 대량 데이터가 캐시를 점유하면 자주 쓰는 데이터가 축출 — 히트율 급락
- 계층 간 대역폭 병목: 캐시-DRAM 간 버스 대역폭이 다수 코어의 동시 요청을 감당 못함 — 큐잉 지연 발생

> 요약: CPU-메모리 속도 격차, 캐시 오염, 대역폭 병목이 계층 구조의 주요 한계임

## Ⅴ. 개선방안
1. 단기: L3 캐시 용량 확대(3D V-Cache 등)와 프리페치 알고리즘 개선으로 DRAM 접근 빈도 감소
2. 중기: 캐시 파티셔닝(Intel CAT 등)으로 워크로드별 캐시 영역을 격리하여 오염 방지
3. 장기: HBM(030 참조)·CXL(035 참조) 도입으로 DRAM 대역폭을 수배 확장하여 병목 해소

> 요약: 캐시 확대 → 파티셔닝 → HBM/CXL 대역폭 확장 순으로 Memory Wall을 완화함

## Ⅵ. 전망
- 발전 방향: PIM(033 참조)으로 연산을 메모리 근처로 이동시켜 계층 간 데이터 이동 자체를 감소
- 기술사적 판단: AI 모델 파라미터 증가로 메모리 대역폭 요구가 급증하여 계층 구조 재설계 압력 가중됨
- 기술사 제언: 워크로드별 메모리 접근 패턴 프로파일링을 기반으로 계층 구성 최적화 설계 필요
