## Ⅰ. 개요
- 정의: 초고성능 컴퓨터의 연산 능력을 정량적으로 측정하고 비교하기 위한 척도
- 배경: 글로벌 슈퍼컴퓨터 순위(TOP500) 산정 및 시스템 객관적 평가 필요
- 출제 의도: 이론적 성능(Rpeak)과 실측 성능(Rmax)의 차이 및 측정 도구 이해

## Ⅱ. 구성요소
- ASCII 구조도
  +-------------------------------------------------+
  |  Performance Metrics                            |
  |  - Rpeak: 이론적 최대치 (Clock * Cores * IPC)    |
  |  - Rmax : LINPACK 실측 최대치                   |
  |  - Efficiency: Rmax / Rpeak                     |
  +-------------------------------------------------+

- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| FLOPS | 초당 수행 가능한 부동소수점 연산 횟수 | 자동차 속도 |
| LINPACK | 선형 대수 방정식 풀이를 통한 벤치마크 SW | 주행 테스트 |
| Top500 | 전 세계 슈퍼컴퓨터의 성능 순위 리스트 | F1 랭킹 |

- > 요약: FLOPS는 절대 성능을, LINPACK은 실질 연산 효율을 나타냄

## Ⅲ. 절차
- ASCII 흐름도
  [HW 사양 확인] -> [HPL 설정] -> [행렬 연산 수행] -> [결과(FLOPS) 산출]

1. 파라미터 설정: 시스템 규모에 맞는 N(행렬 크기), NB(블록 크기) 결정
2. 병렬 환경 구성: MPI 및 수학 라이브러리(MKL 등) 최적화
3. 연산 실행: LU 분해법을 사용하여 고밀도 선형 시스템 풀이
4. 성능 집계: 소요 시간 대비 연산량을 계산하여 TFLOPS/PFLOPS 단위 출력

- > 요약: 고부하 행렬 연산을 통해 시스템의 한계 성능을 도출함

## Ⅳ. 문제점
- 실무 괴리: LINPACK 점수가 높다고 모든 실제 애플리케이션 성능이 높지 않음
- 데이터 병목: CPU 연산력 대비 메모리/네트워크 대역폭 한계 반영 미흡

## Ⅴ. 개선방안
- HPCG 도입: 실제 애플리케이션 특성을 반영한 새로운 벤치마크 병행 사용
- 전력 효율 고려: Green500을 통한 전력당 성능(FLOPS/W) 지표 강화

## Ⅵ. 전망
- 로드맵: AI 연산 특화 지표(HPL-MxP) 등 혼합 정밀도 측정 방식 확산
- 제어: 단순 연산 속도를 넘어 데이터 이동 효율성을 중시하는 지표로 진화
