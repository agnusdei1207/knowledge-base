## 미리 알고가기

- ISA는 하드웨어와 소프트웨어 사이의 실행 계약임
- RISC는 단순한 고정 길이 명령어를, CISC는 복합 가변 길이 명령어를 지향함
- 현대 CPU는 외부 ISA와 내부 실행 구조가 완전히 일치하지 않을 수 있음
- 로드/스토어 구조(Load/Store Architecture): 연산은 레지스터에서만 수행하고 메모리 접근은 load·store 명령으로 분리하는 방식임
- 마이크로연산(Micro-op): 복합 명령어를 내부적으로 쪼갠 단순 실행 단위임

## 작성 근거(검토용)

- RISC와 CISC를 속도 우열이 아니라 명령어 형식·해독 방식, 코드 밀도, 소프트웨어 호환성의 선택 문제로 정리함
- 현대 CPU는 외부 ISA와 내부 u-op 실행이 다를 수 있으므로 해독과 실행 경로를 분리함
- 파이프라인 구성과 소프트웨어 호환성을 ISA 선택 기준으로 정리함

## Ⅰ. 개요

- **정의/개념**: RISC와 CISC는 명령어 집합 구조를 나누는 방식으로, RISC는 단순 명령어와 규칙적 실행을, CISC는 복합 명령어와 높은 코드 밀도를 중시함
- **배경/필요성**: 워크로드에 맞는 ISA를 선택하기 위해 명령어 복잡도·코드 밀도·해독 비용의 비교 기준이 필요함

### 쉽게 이해하기 (학습용)
- 라면을 물 끓이기·면 넣기·스프 넣기로 나눠 하나씩 하는 방식(RISC)과, 즉석조리 버튼 하나로 한 번에 끝내는 방식(CISC)의 차이와 같음

## Ⅱ. 특징

- RISC는 고정 길이 명령어와 load/store 구조를 사용함
- CISC는 한 명령어에서 메모리 접근과 연산을 함께 표현할 수 있음
- RISC는 명령어 필드를 일정하게 구성해 해독 단계와 파이프라인 경로를 규칙화함
- CISC는 해독 복잡도와 내부 마이크로오퍼레이션 분해 비용이 큼

### 쉽게 이해하기 (학습용)
- 정해진 규격 상자만 취급해 분류가 빠른 택배(RISC)와, 크기가 제각각이라 그때그때 재서 처리해야 하는 소포(CISC)의 차이와 같음

## Ⅲ. 종류 및 비교

| 판단 기준 | RISC | CISC |
|:---|:---|:---|
| 명령어 형식·해독 | 고정 길이, load/store 분리, 고정 필드 해독 | 가변 길이, 메모리 직접 연산, 명령 길이 판정 후 u-op 분해 |
| 코드 밀도 | 명령 수 증가로 코드 크기 확대 | 복합 명령으로 코드 크기 축소 |
| 소프트웨어 호환성 | 대상 ISA 재컴파일·포팅 필요 | 기존 x86 바이너리·운영체제 호환 유지 |

> 요약: RISC는 해독을 단순화하는 대신 코드 크기가 늘고, CISC는 해독이 복잡한 대신 코드 밀도와 기존 바이너리 호환성을 얻음.

### 쉽게 이해하기 (학습용)
- 재료를 미리 손질해두고 빨리 볶지만 그릇을 여러 개 쓰는 식당(RISC)과, 손질부터 한 그릇에 담아내지만 시간이 오래 걸리는 셰프(CISC)의 차이와 같음
- 기존 레시피(바이너리)를 그대로 쓸 수 있는지는 셰프(CISC)가 더 유리함

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 명령어 형식 | 명령 길이와 필드 배치를 정해 해독 방식을 결정함 |
| 레지스터 모델 | 피연산자 사용 방식과 컴파일러의 명령어 배치 범위를 결정함 |
| 해독 로직 | 명령어를 내부 실행 단위로 바꾸며 CISC에서는 명령 길이 판정과 마이크로연산 분해를 수행함 |
| 실행 경로 | 파이프라인과 마이크로연산 처리 구조가 실행 지연과 전력 소모를 결정함 |

```text
+-----------+     +-------------+     +---------------+
| 명령어 형식  | --> | 해독 로직      | --> | 실행 경로        |
+-----------+     +-------------+     +---------------+
      |
      v
+---------------+
| 레지스터 모델   |
+---------------+
```

> 요약: ISA 형식은 해독 로직과 실행 경로를 거쳐 실제 마이크로아키텍처 비용으로 이어짐.

### 쉽게 이해하기 (학습용)
- 주문서 양식(명령어 형식)을 정하고, 주방이 그 주문서를 조리 단위로 바꾼 뒤(해독 로직), 실제로 조리하는(실행 경로) 순서와 같음

## Ⅴ. 원리 및 절차 흐름도

```text
[RISC] 고정 길이 인출 -> 고정 필드 해독 -> 실행
[CISC] 가변 길이 인출 -> 명령 길이 판정 -> 마이크로연산 분해 -> 실행
```

1. **RISC 실행**: 고정 길이 명령어의 필드를 해독해 실행 유닛으로 전달함
2. **CISC 실행**: 가변 길이를 판정하고 복합 명령을 마이크로연산으로 분해해 실행 유닛으로 전달함

> 요약: 현대 CPU는 외부 ISA 철학과 내부 실행 방식이 다를 수 있으므로 해독 비용과 실행 경로를 함께 판단해야 함.

### 쉽게 이해하기 (학습용)
- 정해진 크기 상자(RISC)는 바로 꺼내 쓰지만, 크기가 제각각인 소포(CISC)는 먼저 크기를 재고 여러 조각으로 나눠야 처리할 수 있음

## Ⅵ. 실무 사례

1. x86 서버 CPU는 가변 길이 해독 대기를 줄이기 위해 마이크로연산 캐시를 적용하고, 해독 대역폭과 마이크로연산 캐시 적중률로 검증함
2. RISC 기반 임베디드 시스템은 명령어 캐시 사용량을 줄이기 위해 압축 명령어 확장을 적용하고, 실행 파일 크기와 명령어 캐시 실패율로 검증함

### 쉽게 이해하기 (학습용)
- 자주 나가는 복잡한 주문을 미리 조각내 담아둔 반조리 서랍(마이크로연산 캐시)과, 짐을 줄이려 압축 포장하는 택배(압축 명령어)의 차이와 같음

## Ⅶ. 결론

- RISC와 CISC는 해독 경로, 코드 밀도, 기존 바이너리 호환성을 기준으로 선택해야 함
- 신규 임베디드 설계는 RISC 계열로 해독을 단순화하고, 기존 x86 소프트웨어 자산을 유지해야 하는 서버는 CISC 계열의 마이크로연산 캐시로 해독 비용을 관리해야 함

### 쉽게 이해하기 (학습용)
- 새 주방을 짓는지 기존 주방 설비를 그대로 쓰는지에 따라 조리 방식을 고르는 것과 같음
