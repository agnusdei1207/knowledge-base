# 📖 【암기용】 개념 완전 이해

> 목적: 버스 중재 방식을 처음 봐도 여러 버스 마스터 중 누가 버스를 쓸지 어떻게 정하는지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: CPU, DMA 컨트롤러, 채널 프로세서 등 여러 버스 마스터가 공유 버스 사용권을 요청할 때 충돌 없이 하나에게만 권한을 주는 절차
- **왜 필요한가**: 버스는 공유 자원이라 동시에 여러 마스터가 접근하면 신호 충돌과 데이터 손상이 발생하므로 중재가 반드시 필요하다.
- **핵심 직관**: 회의 사회자가 발언권을 한 사람씩 배정하듯, 버스 중재기는 여러 요청 중 하나에게만 버스 사용권을 넘긴다.

## 깊이 이해
- **배경·문제의식**: CPU 외에도 DMA 컨트롤러, 채널 프로세서 등 여러 장치가 버스 마스터가 될 수 있는 시스템에서는 우선순위와 공정성 문제가 발생한다.
- **작동 원리 — 중앙집중식(Centralized, Independent Request)**: 각 마스터가 독립적인 BR(Bus Request) 라인으로 중재기(arbiter)에 요청을 보낸다.
- **작동 원리 — 중앙집중식**: 중재기는 우선순위 인코더로 요청 중 하나를 선택해 해당 마스터에만 BG(Bus Grant) 신호를 준다.
- **작동 원리 — 중앙집중식**: 확장성은 좋지만 마스터 수만큼 BR/BG 신호선 쌍이 필요해 배선이 늘어난다.
- **작동 원리 — 데이지체인(Daisy-chain)**: 중재기의 BG 신호가 마스터들을 순차로 통과하는 하나의 라인으로 전달된다.
- **작동 원리 — 데이지체인**: 요청한 마스터가 BG 신호를 가로채고 이후 마스터로 전달하지 않아, 체인에서 앞쪽(중재기에 가까운) 마스터가 항상 우선순위가 높다.
- **작동 원리 — 데이지체인**: 배선은 단순하지만 우선순위가 고정되어 공정성이 낮고, 체인이 길어지면 신호 전파 지연이 누적된다.
- **작동 원리 — 분산식(Distributed, Self-Selection)**: 각 마스터가 자신의 고유 arbitration number를 버스에 실어 서로 비교한다.
- **작동 원리 — 분산식**: 가장 높은(또는 낮은) 번호를 가진 마스터가 중앙 중재기 없이 스스로 승자임을 판정한다.
- **버스 프로토콜 절차**: Bus Request(BR) 발행 -> Bus Grant(BG) 수신 -> Bus Busy(BB) 신호로 점유 표시 -> 전송 수행 -> 버스 반환(release) 순서로 진행된다.
- **비유**: 중앙집중식은 사회자에게 손을 들어 발언권을 받는 방식, 데이지체인은 앞사람부터 순서대로 마이크를 넘기는 방식, 분산식은 참가자끼리 번호표를 비교해 스스로 순서를 정하는 방식이다.
- **구체 예시**: PCI 버스는 장치별 REQ#/GNT# 핀 쌍을 사용하는 중앙집중식 중재를 채택한다.
- **구체 예시**: VMEbus는 데이지체인 방식의 버스 중재를 지원한다.
- **구체 예시**: NuBus는 분산식 self-selection 방식으로 중앙 중재기 없이 마스터를 결정한다.
- **흔한 오해·주의점**: "데이지체인 버스 중재는 소프트웨어가 우선순위를 배정한다"는 틀렸다. 물리적 배선 위치가 우선순위를 고정적으로 결정한다.
- **흔한 오해·주의점**: "중앙집중식이 항상 더 빠르다"는 틀렸다. 마스터 수가 많아지면 회선 수와 중재기 복잡도가 커져 오히려 확장성이 떨어질 수 있다.

## 연결 개념
- DMA(Direct Memory Access) — 버스 마스터 권한 획득 후 실제 전송을 수행하는 주체
- 인터럽트 처리 방식(벡터·데이지체인) — 데이지체인 우선순위 개념이 유사하지만 서비스 요청 우선순위와 데이터 전송 권한 우선순위로 목적이 다름
- 채널 I/O — 버스 마스터가 될 수 있는 또 다른 전용 프로세서

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 버스 중재 답안은 BR/BG/BB 프로토콜 절차와 중앙집중·데이지체인·분산식 3가지 방식의 배선 복잡도·공정성 트레이드오프를 함께 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 버스 중재는 여러 버스 마스터의 사용 요청 중 하나에게만 버스 권한을 부여하는 절차이며 중앙집중·데이지체인·분산식으로 구현된다.
> 2. **가치**: 중재 방식 선택은 배선 복잡도, 우선순위 공정성, 확장성을 좌우해 시스템 규모에 맞는 버스 설계를 가능하게 한다.
> 3. **판단 포인트**: 마스터 수, 우선순위 공정성 요구, 배선 제약에 따라 중앙집중·데이지체인·분산식 중 하나를 선택한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 버스 중재 프로토콜 이해 확인 | BR/BG/BB 신호 절차 | 중재 절차 없이 결과(승자)만 서술 |
| 중재 방식별 트레이드오프 판단 확인 | 중앙집중(배선多)·데이지체인(공정성↓)·분산식(중재기 불필요) 차이 | 데이지체인 우선순위를 소프트웨어 설정으로 오인 |
| 실제 버스 표준 적용 이해 확인 | PCI 중앙집중, VMEbus 데이지체인, NuBus 분산식 사례 | 방식명과 사례를 연결하지 않고 나열만 |

> 요약: 이 문제는 중재 방식 명칭 암기가 아니라 배선 복잡도·공정성·확장성 트레이드오프 판단을 보여야 한다.

## Ⅰ. 개요 및 필요성

- 개요: 여러 버스 마스터의 요청 중 하나에게만 버스 사용권을 부여하는 절차
- 배경: CPU 외 DMA 컨트롤러·채널 프로세서 등 다중 버스 마스터 환경에서 신호 충돌 방지가 필요함
- 필요성: 배선 복잡도, 우선순위 공정성, 확장성을 고려한 중재 방식 선택이 시스템 성능과 비용에 직결됨

---

## Ⅱ. 구조 및 구성요소

```text
Bus Masters(CPU/DMAC/Channel) -> Bus Request(BR)
  -> Centralized: Arbiter Priority Encoder -> Bus Grant(BG)
  -> Daisy-chain: BG Pass-through Chain -> 요청 마스터가 가로챔
  -> Distributed: Arbitration Number 비교 -> Self-Selection
  -> Bus Busy(BB) -> Transfer -> Release
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Bus Request(BR) | 마스터의 버스 사용 요청 신호 | 중앙집중식은 마스터별 독립 라인 |
| Arbiter | 중앙집중식에서 우선순위 판별 | 우선순위 인코더 내장 |
| BG Chain | 데이지체인에서 순차 전달되는 승인 신호 | 배선 위치가 우선순위 결정 |
| Arbitration Number | 분산식에서 마스터 식별·비교용 고유값 | 중앙 중재기 불필요 |

> 요약: 버스 중재는 요청·승인 신호를 중앙집중, 데이지체인, 분산식 중 하나의 방식으로 처리해 버스 마스터를 확정한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
버스 마스터 요청 발생 -> 중재 방식 판별
  -> 중앙집중: Arbiter가 우선순위 인코딩 -> BG 발급
  -> 데이지체인: BG가 체인 순서로 전달 -> 요청 마스터가 가로챔
  -> 분산식: Arbitration Number 비교 -> 승자 자체 판정
  -> Bus Busy 설정 -> 전송 수행 -> 버스 반환
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 마스터가 버스 요청 발행 | 요청 신호 검출 |
| 2 | 중재 방식에 따라 승자 결정 | 방식별 결정 지연시간 |
| 3 | Bus Busy 신호로 점유 표시 | 충돌 없는 단일 점유 |
| 4 | 전송 완료 후 버스 반환 | 반환 지연, 다음 요청 처리 |

> 요약: 버스 중재는 요청 발생 후 방식별 절차로 승자를 정하고 점유·전송·반환 순서로 마무리된다.

---

## Ⅳ. 특징

| 구분 | 중앙집중식(Centralized) | 데이지체인(Daisy-chain) | 분산식(Distributed) |
|:---|:---|:---|:---|
| 배선 복잡도 | 마스터 수만큼 BR/BG 쌍 필요 | BG 라인 1개로 단순 | 중재기 불필요, 비교 로직 필요 |
| 우선순위 공정성 | 인코더 설정에 따라 유연 | 체인 위치로 고정, 낮음 | 번호 비교로 상대적 공정 |
| 확장성 | 마스터 증가 시 회선 증가 | 체인 재배선 필요, 지연 누적 | 마스터 추가 용이 |
| 대표 사례 | PCI 버스 | VMEbus | NuBus |

> 요약: 중앙집중식은 유연성, 데이지체인은 배선 단순성, 분산식은 중재기 없는 확장성이 강점이다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 데이지체인 | 중앙집중·분산식 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 고정 우선순위 체인 | 인코더 기반 또는 번호 비교 기반 | 우선순위 변경 필요 시 중앙집중·분산식 |
| 비용/성능 | 배선 단순, 지연 누적 가능 | 배선 또는 비교 로직 비용 존재 | 마스터 수와 배선 제약으로 판단 |
| 운영/위험 | 체인 단선 시 하위 마스터 영향 | 중재기 장애 또는 비교 로직 오류 | 장애 격리 요구 수준으로 판단 |

> 요약: 마스터 수가 적고 배선 단순성이 중요하면 데이지체인, 유연한 우선순위와 확장성이 필요하면 중앙집중·분산식을 선택한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 우선순위 기아(starvation) | 데이지체인 하위 마스터가 지속 차단 | 라운드로빈 결합, 타임아웃 강제 승인 | 마스터별 대기시간 편차 |
| 중재기 병목 | 중앙집중식 요청 폭증 | 중재기 이중화, 계층적 중재 구조 | 중재 지연시간 |
| 체인 단선 | 데이지체인 배선 손상·장치 제거 | 체인 무결성 점검, 핫플러그 재구성 | 체인 연속성 테스트 결과 |

> 요약: 버스 중재 리스크는 우선순위 기아와 중재기 병목이며 대기시간 편차와 지연시간으로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 중재 지연 | 목표 지연시간 이내 | 버스 트레이스 분석 |
| 공정성 | 마스터별 대기시간 편차 목표치 이내 | 로그 기반 통계 분석 |
| 확장성 | 신규 마스터 추가 시 재구성 시간 목표치 이내 | 구성 변경 테스트 |

> 요약: 도입 성공 여부는 중재 지연, 대기시간 공정성, 확장 시 재구성 시간으로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 마스터 수가 적고 배선 단순성이 중요한 임베디드 버스는 데이지체인 방식을 적용함
2. 우선순위 조정이 잦은 시스템 버스는 중앙집중식 중재기와 인코더 설정으로 유연성을 확보함
3. 대규모 확장이 예상되는 버스는 분산식 self-selection으로 중재기 병목을 제거함

**결론 (2줄):**
- 기술사 판단: 배선 단순성이 우선이면 데이지체인, 우선순위 유연성과 확장성이 우선이면 중앙집중·분산식을 선택함
- 향후 방향: PCIe·NVMe 같은 고속 직렬 버스는 point-to-point 스위칭 구조로 전환해 전통적 중재 개념 대신 스위치 기반 경로 할당으로 발전하고 있음
