# 버스 중재 방식 (Bus Arbitration)

## 미리 알고가기

- 버스 마스터: CPU, DMA, I/O 컨트롤러처럼 버스 사용을 요청하는 주체임
- 버스 슬레이브: 메모리나 장치 레지스터처럼 요청을 받아 응답하는 대상임
- BR/BG: 버스 요청(Bus Request, BR)과 버스 허가(Bus Grant, BG)는 사용 요청과 허가 신호임
- 공정성: 특정 마스터가 계속 대기하지 않도록 중재 기회를 분배하는 기준임

## 1. 개요

- **정의/개념**: 버스 중재는 여러 버스 마스터가 하나의 공유 버스를 동시에 사용하려 할 때 우선순위, 순환 순서, 요청 상태를 기준으로 한 번에 하나의 마스터에게 사용권을 부여해 충돌과 기아를 통제하는 제어 방식임.
- **배경/필요성**: CPU, DMA, 고속 I/O가 병행 동작하면 단일 버스에서 전기적 충돌과 데이터 무결성 문제가 발생함. 시스템은 성능 요구, 실시간성, 공정성을 함께 만족하도록 버스 사용권을 결정해야 함.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 공유 버스 제어 방식과 선택 기준 설명 | 중앙집중식, 분산식, 우선순위, 공정성, 기아 | 장치 충돌 원인 누락, 우선순위와 공정성 혼동 |

> 요약: 버스 중재는 공유 전송로의 사용권을 정책적으로 배정해 충돌 없이 데이터 전송을 완료하게 하는 구조임.

## 2. 특징 및 비교

| 방식 | 동작 원리 | 장점 | 한계 | 적합 조건 |
|:---|:---|:---|:---|:---|
| 중앙집중식 중재 | 하나의 arbiter가 모든 요청을 받아 허가함 | 제어 단순, 우선순위 정책 명확 | arbiter 장애와 병목 가능 | 단일 보드, 소규모 시스템 |
| 데이지체인 | 허가 신호가 장치 순서대로 전달됨 | 회로 단순, 비용 낮음 | 앞쪽 장치 우선, 뒤쪽 기아 가능 | 장치 수가 적고 우선순위 고정 |
| 분산식 중재 | 각 마스터가 중재 로직을 갖고 버스 사용을 판단함 | 병목 감소, 확장성 향상 | 설계 복잡도 증가 | 다중 마스터 고성능 시스템 |
| 라운드로빈 | 요청 장치에 순환 순서로 기회를 부여함 | 공정성 높음 | 긴급 장치 지연 가능 | 공정성이 중요한 일반 I/O |

버스 중재의 선택 기준은 최악 지연시간, 처리량, 우선순위 정책, 회로 복잡도임. 실시간 장치는 고정 우선순위가 유리할 수 있지만, 일반 I/O가 섞인 시스템에서는 기아 방지를 위해 공정성 정책이 필요함.

## 3. 구성요소/구조

```text
+----------+       BR        +----------+       BG        +----------+
| Master A | --------------> | Arbiter  | --------------> | Bus      |
+----------+                 +----------+                 +----------+
+----------+       BR              ^                            |
| Master B | ----------------------+                            v
+----------+                                             +----------+
+----------+                                             | Memory/  |
| Master C |                                             | Device   |
+----------+                                             +----------+
```

| 구성요소 | 설명 | 핵심 포인트 |
|:---|:---|:---|
| 버스 마스터 | 버스 사용을 요청하고 데이터 전송을 시작함 | CPU, DMA, I/O |
| 중재기 | 요청을 수집하고 정책에 따라 허가 신호를 부여함 | 우선순위와 공정성 |
| 공유 버스 | 주소, 데이터, 제어 신호가 이동하는 공통 경로임 | 단일 사용 원칙 |
| 우선순위 정책 | fixed, rotating, round-robin 등으로 허가 순서를 결정함 | 지연과 기아 통제 |
| 타임아웃/에러 처리 | 버스 점유 실패나 응답 지연을 감지함 | 장애 격리 |

### 원리/흐름도

```text
+---------+      +----------+      +--------+      +----------+
| Request | ---> | Arbitrate| ---> | Grant  | ---> | Transfer |
+---------+      +----------+      +--------+      +----------+
```

마스터는 버스 요청을 발생시키고 중재기는 현재 사용 상태와 정책을 기준으로 하나의 마스터를 선택함. 허가받은 마스터만 주소·데이터·제어 신호를 구동하므로 버스 컨텐션을 피할 수 있음.

## 4. 문제점 및 개선방안

1. **기아 상태**: 고정 우선순위 방식은 낮은 우선순위 장치가 장기간 버스를 얻지 못할 수 있음.
   - **개선방안**: aging, round-robin, 우선순위 회전 정책을 적용함. (확인: 장치별 최대 대기 시간)
2. **실시간 지연 증가**: 공정성만 강조하면 긴급 장치의 최악 응답시간이 커질 수 있음.
   - **개선방안**: 실시간 장치에는 우선순위 상한과 예약 대역폭을 부여함. (확인: deadline miss, worst-case latency)
3. **중재기 병목과 단일 장애점**: 중앙집중식 arbiter 장애는 전체 버스 사용 불가로 이어질 수 있음.
   - **개선방안**: 이중화, 분산 중재, 타임아웃 기반 회복 절차를 적용함. (확인: arbiter fault, bus hang 복구 시간)

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| SoC 내부 버스 | CPU, DMA, 가속기 요청을 AXI arbiter가 QoS와 우선순위 기준으로 중재함 | 대역폭 사용률, worst-case latency |
| 임베디드 제어 시스템 | 실시간 센서·제어 장치에는 높은 우선순위를 주고 일반 I/O는 순환 방식으로 처리함 | deadline miss, 장치별 대기 시간 |
| 스토리지 컨트롤러 | 여러 DMA 채널의 메모리 접근을 우선순위와 큐 깊이 기준으로 조정함 | I/O 처리량, p99 지연 |

## 6. 결론

버스 중재는 공유 버스의 충돌 방지뿐 아니라 시스템 전체 지연과 공정성을 결정하는 제어 정책임. 고정 우선순위는 긴급 처리를 보장하지만 기아 위험이 있고, 라운드로빈은 공정하지만 실시간성 보장이 약할 수 있음. 따라서 시스템 요구에 맞춰 우선순위, 예약 대역폭, 기아 방지 기준을 함께 설계해야 함.
