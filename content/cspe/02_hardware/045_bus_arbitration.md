## 미리 알고가기

- 버스 마스터: 중앙처리장치(Central Processing Unit, CPU), 직접 메모리 접근(Direct Memory Access, DMA), 입출력(Input/Output, I/O) 컨트롤러처럼 버스 사용을 요청하는 주체임
- 버스 슬레이브: 메모리나 장치 레지스터처럼 요청을 받아 응답하는 대상임
- BR/BG: 버스 요청(Bus Request, BR)과 버스 허가(Bus Grant, BG)로, 사용 요청과 허가 신호를 의미함
- 공정성: 특정 마스터가 계속 대기하지 않도록 중재 기회를 분배하는 기준임

## Ⅰ. 개요

- **정의**: 버스 중재는 여러 버스 마스터가 하나의 공유 버스를 동시에 사용하려 할 때 우선순위, 순환 순서, 요청 상태를 기준으로 한 번에 하나의 마스터에게 사용권을 부여해 충돌, 지연, 기아 상태를 통제하는 제어 방식임
- **배경/필요성**: CPU와 DMA, 고속 I/O가 병행 동작하면 단일 버스에서 전기적 충돌과 데이터 무결성 문제가 발생함. 따라서 시스템은 성능 요구와 실시간성을 함께 만족하는 중재 정책이 필요함
- **비유**: 여러 차량이 한 차로 교차로에 진입할 때 신호등이나 우선순위 규칙으로 한 대씩 통과시키는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 공유 버스 제어 방식 설명과 선택 | 중앙집중식, 분산식, 우선순위, 공정성 | 장치 충돌 원인 누락 |

> 요약: 버스 중재는 공유 버스 사용권을 정책적으로 배정해 충돌 없이 전송을 완료하게 하는 제어 메커니즘임.

## Ⅱ. 특징/비교

| 판단 기준 | 고정 우선순위 중재 | 라운드로빈 중재 |
|:---|:---|:---|
| 선택 기준 | 실시간 장치나 DMA처럼 빠른 응답이 필요한 마스터에 유리함 | 여러 마스터의 평균 대기시간과 공정성을 중시할 때 유리함 |
| 주요 위험 | 낮은 우선순위 장치의 기아 상태가 발생할 수 있음 | 긴급 요청의 응답 지연이 커질 수 있음 |
| 구현 복잡도 | 비교적 단순하나 정책 변경이 제한적임 | 포인터, 큐, 타임아웃 관리가 필요함 |

> 요약: 버스 중재 방식은 응답성, 공정성, 구현 복잡도 중 어떤 요구사항을 우선할지에 따라 선택함.

## Ⅲ. 구성요소

```text
+-----------+     BR      +-----------+     BG      +-----------+
| Master(s) | ----------> |  Arbiter  | ----------> | Shared Bus |
+-----------+             +-----------+             +-----------+
      |                         |
      | status                  v
      +------------------+--------------+
                         | Policy/Timer |
                         +--------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 버스 마스터 | CPU, DMA, I/O 컨트롤러가 전송 필요 시 버스 요청 신호를 보냄 | 교차로 진입 차량 |
| 중재기 | 요청 상태와 정책을 비교해 하나의 마스터에 버스 허가를 내림 | 신호 제어기 |
| 공유 버스 | 주소, 데이터, 제어 신호를 운반하며 동시에 하나의 전송만 허용함 | 단일 차선 |
| 정책/타이머 | 우선순위, 순환 순서, 대기시간을 관리해 기아와 독점을 줄임 | 통행 규칙표 |

> 요약: 버스 중재 구조는 요청 수집, 정책 판단, 사용권 부여, 상태 감시 요소로 충돌 없는 전송을 보장함.

## Ⅳ. 절차

```text
+----------+     +----------+     +----------+     +----------+
| Detect   | --> | Decide   | --> | Grant    | --> | Release  |
+----------+     +----------+     +----------+     +----------+
```

1. **요청 감지**: 각 마스터의 BR 신호, 버스 사용 상태, 잠금 상태를 확인함
2. **우선순위 판단**: 고정 우선순위, 데이지체인, 라운드로빈 등 정책으로 후보를 선택함
3. **권한 부여**: 선택된 마스터에 BG 신호를 보내고 나머지 요청은 대기시킴
4. **전송 해제 감시**: 전송 완료, 타임아웃, 오류 상태를 확인해 버스를 해제함

> 요약: 요청이 정책 판단과 권한 부여를 거쳐 전송 완료 후 다음 요청으로 넘어가는 순환 제어임.

## Ⅴ. 문제점 및 개선방안

- **P1 기아 상태**: 고정 우선순위에서 상위 장치 요청이 반복되면 하위 장치의 대기시간이 무한히 늘 수 있음
- **P1 대응**: 에이징, 순환 우선순위, 최대 대기시간 제한을 적용함 (확인: 마스터별 최대 대기 사이클)
- **P2 전송 지연 변동**: 다중 마스터와 긴 버스트 전송이 겹치면 실시간 장치의 최악 지연시간을 예측하기 어려움
- **P2 대응**: 버스트 길이 제한, 서비스 품질(Quality of Service, QoS) 등급, 실시간 장치 전용 우선 경로를 설계함 (확인: 최악 응답시간)
- **P3 버스 독점 오류**: 마스터가 해제 신호를 내지 못하거나 잠금 전송이 길어지면 전체 시스템 전송이 막힘
- **P3 대응**: 타임아웃, 버스 리셋, 잠금 전송 감사 로그를 둬 독점 상태를 해제함 (확인: 타임아웃 복구 성공률)

> 요약: 중재 개선은 우선순위 보정, 지연 상한 설정, 장애 해제 장치로 문제 원인에 대응함.

## Ⅵ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 임베디드 제어 버스 | 실시간 센서와 직접 메모리 접근(Direct Memory Access, DMA) 전송에 우선순위를 주되 에이징으로 저우선 장치 기아를 방지함 | 마스터별 최대 대기 사이클, 마감시간 위반 건수 |
| 시스템온칩(System on Chip, SoC) 내부 버스 | 고급 확장형 인터페이스(Advanced eXtensible Interface, AXI) 중재기에 서비스 품질(Quality of Service, QoS) 등급과 버스트 길이 제한을 적용함 | 평균/최악 응답시간, 버스 사용률 |
| 장애 복구 설계 | 잠금 전송과 미해제 마스터에 타임아웃과 버스 리셋 정책을 적용함 | 타임아웃 복구 성공률, 독점 지속 시간 |

> 요약: 버스 중재는 응답성, 공정성, 장애 해제 조건을 동시에 만족하는 정책으로 검증해야 함.

## Ⅶ. 전망

- **발전 방향**: 단일 병렬 버스보다 네트워크 온 칩(Network-on-Chip, NoC), 주변 장치 상호연결 익스프레스(Peripheral Component Interconnect Express, PCIe) 스위치, 컴퓨트 익스프레스 링크(Compute Express Link, CXL) 패브릭처럼 패킷 기반 중재 구조가 확대됨
- **기술사적 판단**: 실시간 제어는 지연 상한을, 일반 서버는 처리량과 공정성을 우선해 중재 정책을 선택해야 함
- **기술사 제언**: 중재 방식 설명 시 회로 방식보다 요청-판단-허가-해제 흐름과 기아 방지 기준을 함께 제시해야 함
