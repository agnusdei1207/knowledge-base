# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: DAS, NAS, SAN은 스토리지를 서버에 어떻게 연결할 것인가(직접 연결, 네트워크 공유 등)를 정의하는 스토리지 아키텍처 3대장이다.
- **왜 필요한가**: 데이터가 적을 때는 서버에 하드디스크를 꽂으면 되지만(DAS), 데이터가 폭증하고 서버가 많아지면 스토리지를 따로 분리해서 네트워크로 공유하고 통합 관리해야 하기 때문(NAS/SAN)이다.
- **핵심 직관**: DAS는 내 PC의 외장하드, NAS는 회사의 공유 폴더(IP 네트워크), SAN은 데이터센터 전용 광케이블로 연결된 거대한 블록 스토리지 망이다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| DAS (Direct Attached Storage) | 서버에 직접 케이블로 연결된 스토리지 | 내 컴퓨터에 꽂힌 USB 외장하드 |
| NAS (Network Attached Storage) | 기존 LAN 망(TCP/IP)을 통해 '파일' 단위로 공유하는 스토리지 | 구글 드라이브나 윈도우 네트워크 공유 |
| SAN (Storage Area Network) | 스토리지 전용 고속 망(FC/iSCSI)을 통해 '블록' 단위로 접근 | 나만의 전용 지하 터널로 연결된 대형 금고 |
| 블록(Block) vs 파일(File) | 블록은 포맷 안 된 생(raw) 공간, 파일은 OS가 관리하는 문서 단위 | 블록=빈 창고, 파일=서류 캐비닛에 분류된 폴더 |

## 깊이 이해
- **배경·문제의식**: 예전에는 서버마다 DAS로 디스크를 달았다. 하지만 서버 A는 용량이 남고 서버 B는 꽉 차는 불균형이 생겼다. 이를 해결하기 위해 스토리지를 네트워크로 분리하여 한곳에 모으는(NAS, SAN) 기술이 발전했다.
- **작동 원리**:
  - **DAS**: 서버 내장 컨트롤러가 SCSI/SATA 케이블로 디스크를 직접 제어한다. 빠르지만 다른 서버와 공유 불가.
  - **NAS**: 스토리지가 자체 OS를 갖고 이더넷(LAN)에 붙는다. 클라이언트는 NFS, SMB 프로토콜로 '파일'을 요청하고 NAS가 디스크에 접근해 파일을 준다.
  - **SAN**: LAN과 분리된 스토리지 전용 광통신망(Fibre Channel)을 깐다. 서버 입장에서는 SAN 스토리지 볼륨이 마치 자기 본체에 직접 꽂힌 로컬 하드디스크(블록 장치)처럼 보인다.
- **비유**: DAS는 내 책상 서랍. NAS는 공용 도서관(사서에게 책 이름(파일)을 말하면 찾아줌). SAN은 개인 전용 지하 창고(직접 내려가서 박스(블록)를 가져옴, 엄청 빠름).
- **구체 예시**: 고성능 DB(Oracle)는 엄청난 속도의 블록 I/O가 필요하므로 SAN을 쓴다. 반면, 팀원 간 문서 공유나 영상 스트리밍은 파일 단위 접근이 편하므로 NAS를 쓴다.
- **흔한 오해·주의점**: NAS는 느리고 SAN은 빠르다는 것은 과거 이야기다. 요즘은 10G/40G 이더넷 기반의 All-Flash NAS도 매우 빠르다. 속도보다는 '파일 단위 공유'냐 '블록 단위 독점'이냐의 용도 차이가 핵심이다.

## 연결 개념
- 파일 시스템(File System) — 블록 스토리지(DAS, SAN) 위에 폴더와 파일 구조를 만드는 주체 (NAS는 자체 파일 시스템 사용)
- iSCSI (Internet Small Computer System Interface) — 값비싼 FC망 대신 일반 이더넷(IP)망 위에서 SAN(블록 전송)을 구현하는 프로토콜
- 스토리지 가상화 — 수많은 이기종 스토리지를 논리적인 하나의 풀로 묶는 기술

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 스토리지는 서버 연결 방식과 데이터 엑세스 단위(File vs Block)에 따라 DAS(직접/블록), NAS(LAN/파일), SAN(전용망/블록)으로 분류된다.
> 2. **가치**: 스토리지 시스템을 독립시킴으로써 자원 활용도를 높이고, 이기종 서버 간 데이터 공유 및 데이터센터의 확장성·가용성을 보장한다.
> 3. **판단 포인트**: 데이터 정합성과 고성능 I/O가 필요한 DB 환경은 SAN을, 다수 사용자 간 비정형 파일 공유가 필요한 환경은 NAS를 선택하는 것이 아키텍처의 핵심이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 스토리지 아키텍처 특성 구분 역량 확인 | 연결 방식(직접/LAN/FC망), 프로토콜, 접근 단위(Block/File) | NAS와 SAN의 차이를 단순히 '속도 차이'로만 뭉뚱그려 서술 |
| 워크로드에 맞는 스토리지 설계 판단 | DB는 SAN(블록), 공유 폴더는 NAS(파일) 매핑 | 파일 시스템의 관리 주체(Client vs NAS) 누락 |

> 요약: 각 아키텍처의 프로토콜과 접근 단위를 명확히 대조하고, 적용 대상 워크로드를 정확히 매핑한다.

## Ⅰ. 개요 및 필요성

- 개요: DAS, NAS, SAN은 스토리지와 서버를 연결하는 네트워크 방식과 데이터를 처리하는 단위(Block/File)에 따른 엔터프라이즈 스토리지 아키텍처 분류이다.
- 배경: 서버 내장 스토리지(DAS)의 용량 고립화(Silo) 문제와 자원 활용 불균형으로 인해 네트워크 기반 스토리지 공유 기술이 발전함
- 필요성: 급증하는 데이터를 통합 관리하고 고가용성 및 확장성을 확보하기 위해 용도(DB, 파일 공유)에 맞는 스토리지 계층 설계가 필수적임

---

## Ⅱ. 구조 및 구성요소

```text
[DAS] Server ---(SCSI/SAS)--- Disk Array
[NAS] Server ---(LAN/TCP/IP)--- NAS Head (File System) --- Disk
[SAN] Server ---(FC/iSCSI 망)--- SAN Switch --- Storage Array
```

| 구성요소 | 연결망 (Network) | 프로토콜 (Protocol) | 데이터 접근 단위 |
|:---|:---|:---|:---|
| DAS | 케이블 직접 연결 | SCSI, SAS, NVMe | 블록 (Block) |
| NAS | 기존 LAN 망 | NFS, SMB/CIFS, FTP | 파일 (File) |
| SAN | 스토리지 전용 망 | Fibre Channel (FC), iSCSI | 블록 (Block) |

> 요약: 스토리지는 네트워크의 종류(LAN vs FC)와 데이터 접근의 추상화 수준(File vs Block)에 따라 아키텍처가 완전히 달라진다.

---

## Ⅲ. 동작원리 및 흐름도

```text
[NAS 흐름] Client 요청(파일명) -> TCP/IP LAN -> NAS 자체 파일시스템 해독 -> 디스크 I/O
[SAN 흐름] Server OS 파일시스템 해독 -> 블록 주소 요청 -> FC Switch -> 스토리지 I/O
```

- 1단계 [DAS 처리]: 서버 OS의 파일 시스템이 직접 SCSI 명령어를 생성하여 로컬 디스크의 블록을 읽고 씀
- 2단계 [NAS 처리]: 클라이언트가 파일 I/O를 요청하면, 네트워크를 거쳐 NAS 내부의 자체 OS/파일 시스템이 블록 I/O로 변환
- 3단계 [SAN 처리]: 서버 측 OS가 파일 시스템을 관리하며, SAN 망을 통해 블록(LUN) 수준의 읽기/쓰기 명령(FC)만 전송
- 4단계 [결과 반환]: 각 스토리지 컨트롤러가 디스크에서 데이터를 가져와 역순으로 반환

> 요약: 파일 시스템의 위치가 서버에 있으면 DAS/SAN이고, 스토리지 자체에 있으면 NAS이다.

---

## Ⅳ. 특징
- DAS: 전용선으로 연결되어 속도가 빠르고 구축이 저렴하나, 타 서버와 스토리지 자원 공유가 불가능함
- NAS: 이더넷을 이용해 구축이 쉽고 이기종 OS 간 파일 공유에 최적화되었으나, 프로토콜 오버헤드로 인한 트래픽 병목 가능성 존재
- SAN: 전용 광통신망을 사용하여 고속·무중단 I/O와 무한에 가까운 확장이 가능하나, 구축 및 유지보수 비용(FC 스위치, HBA 등)이 높음

> 요약: DAS는 고립된 고성능, NAS는 광범위한 파일 공유, SAN은 확장 가능한 고성능 블록 스토리지의 특성을 갖는다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | DAS | NAS | SAN | 선택 기준 |
|:---|:---|:---|:---|:---|
| 관리 주체(파일시스템) | 각 서버 OS | NAS 장비 내부 OS | 각 서버 OS (볼륨 할당) | 공유 방식 |
| 확장성/공유 | 불가능 (고립) | 파일 단위 쉬운 공유 | 블록 단위 볼륨 할당 (확장 우수) | 데이터센터 규모 |
| 주요 적용처 | 소규모 서버, 로컬 임시저장 | 부서 공유 폴더, 미디어 스트리밍 | 대규모 DBMS, 가상화 인프라 | I/O 트랜잭션 빈도 |

> 요약: 비정형 데이터 공유는 NAS, 정형 데이터 고속 트랜잭션(DB)은 SAN을 선택하는 것이 정석이다.

**스토리지 아키텍처 리스크·대응:**
- [FC-SAN 비용 한계]: 전용 스위치와 HBA 카드로 인한 높은 TCO → [대응 방안] 기존 이더넷 인프라를 활용하는 IP-SAN(iSCSI) 도입 검토 (지표: 인프라 구축 TCO)
- [NAS 트래픽 병목]: 대규모 파일 요청 시 LAN 대역폭 고갈 → [대응 방안] 이더넷 본딩(Bonding) 및 10G/40G 네트워크 업그레이드 (지표: 네트워크 패킷 지연 10ms 이하)

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 엔터프라이즈 아키텍처 매핑: 미션 크리티컬한 Oracle DBMS와 ERP 시스템은 FC-SAN으로 구성하여 트랜잭션 안정성을 확보
2. 비정형 데이터 통합: 텍스트, 이미지 등 비정형 데이터는 스케일아웃 NAS를 도입하여 용량 유연성 및 부서 간 원활한 공유 구현
3. 하이퍼컨버지드 인프라(HCI) 전환: 최근에는 DAS의 스토리지들을 소프트웨어 정의 스토리지(SDS)로 묶어 SAN처럼 활용하는 HCI 도입 가속

**결론 (2줄):**
- 기술사 판단: 스토리지 선택 시 단일 기술 고집보다 데이터의 특성(정형/비정형)과 I/O 요구사항을 분석하여 NAS와 SAN을 혼용하는 계층화 전략이 타당하다.
- 향후 방향: NVMe-oF(NVMe over Fabrics) 기술의 발전으로, 네트워크를 통해서도 로컬 DAS 수준의 초저지연을 제공하는 차세대 SAN 아키텍처로 진화 중이다.
