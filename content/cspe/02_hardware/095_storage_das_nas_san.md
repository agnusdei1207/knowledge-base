## 미리 알고가기

- DAS는 서버에 직접 붙는 블록 스토리지임
- NAS는 네트워크를 통해 파일 단위로 공유하는 스토리지임
- SAN은 전용 네트워크로 블록 장치를 제공하는 스토리지 구조임

## 작성 근거(검토용)

- DAS·NAS·SAN은 연결 경로, 접근 단위, 공유 주체, 장애 경로를 핵심 축으로 설명함
- 비교표는 세 구조의 연결·접근·관리 방식과 대표 업무를 대비함
- 실무 판단은 파일 연산 지연·동시 사용자 수와 다중 경로 절체 시간·복구 성공률로 검증함

## Ⅰ. 개요

- **정의/개념**: DAS와 NAS와 SAN은 서버와 저장장치를 연결하는 위치와 프로토콜과 접근 단위를 기준으로 구분하는 대표적인 스토리지 계층 구조임
- **배경/필요성**: 업무별 접근 단위·공유 범위·장애 경로를 충족하기 위해 DAS·NAS·SAN의 선택 기준이 필요함

## Ⅱ. 특징

- DAS는 서버가 블록 장치를 직접 소유해 네트워크 홉 없이 접근함
- NAS는 파일시스템·권한 관리를 스토리지에서 제공하고 IP 네트워크를 공유함
- SAN은 전용 패브릭에서 블록 장치와 다중 경로를 제공함
- 선택 기준은 용량보다 접근 단위와 지연과 장애 범위와 관리 방식임

## Ⅲ. 종류 및 비교

| 판단 기준 | DAS | NAS | SAN |
|:---|:---|:---|:---|
| 연결 방식 | 서버 내부 또는 외부 포트에 직접 연결됨 | IP 네트워크를 통해 파일 공유로 연결됨 | 전용 스토리지 네트워크를 통해 블록 장치를 노출함 |
| 접근 단위 | 블록 단위로 직접 접근함 | 파일 단위로 공유함 | 블록 단위로 공유함 |
| 공유·관리 방식 | 서버가 장치를 직접 소유·관리함 | 파일시스템과 권한을 NAS가 관리함 | LUN과 경로를 스토리지 패브릭에서 관리함 |
| 대표 적용 | 단일 서버 DB·부트 디스크 | 문서 공유·파일 백업 | 가상화 데이터스토어·이중 경로 DB 볼륨 |

> 요약: DAS는 직접 블록 접근, NAS는 네트워크 파일 공유, SAN은 전용 패브릭의 블록 공유에 사용함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 호스트 서버 | 애플리케이션이 파일시스템 또는 블록 장치로 I/O를 발생시킴 |
| 연결 패브릭 | SATA와 Ethernet과 FC 같은 경로가 지연과 가용성을 결정함 |
| 스토리지 컨트롤러 | RAID와 캐시와 LUN과 파일 공유 기능을 제공해 성능과 보호 수준을 좌우함 |
| 관리 계층 | 권한과 백업과 복구와 용량 정책을 통합 관리해 운영 난도를 결정함 |

> 요약: 호스트 I/O는 DAS의 직접 경로, NAS의 파일 공유 경로, SAN의 블록 패브릭 경로 중 하나를 거쳐 스토리지에 전달됨.

## Ⅵ. 실무 사례

1. 문서 협업 플랫폼은 NAS의 파일 권한·공유 기능을 적용하고 p99 파일 연산 지연·동시 사용자 수를 확인함
2. 가상화 클러스터는 SAN 다중 경로와 장애 조치를 적용하고 경로 절체 시간·복구 성공률을 확인함

## Ⅶ. 결론

- 스토리지는 접근 단위·공유 범위·지연 한도·장애 경로에 따라 DAS·NAS·SAN을 선택하고 백업·절체 책임을 명확히 해야 함
