# 📖 【암기용】 개념 완전 이해

> 목적: DAS·NAS·SAN을 절대 헷갈리지 않도록 접근 단위(block/file)와 네트워크 유무 기준으로 확실히 구분하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 서버와 저장장치를 연결하는 방식을 네트워크 유무와 접근 단위(블록/파일) 기준으로 나눈 세 가지 스토리지 구성
- **왜 필요한가**: "저장장치를 어떻게 연결하느냐"에 따라 성능·확장성·공유 방식이 완전히 달라지므로, 세 방식을 혼동하면 설계 자체가 틀어진다.
- **핵심 직관**: DAS는 내 방 서랍(직접 연결), NAS는 사무실 공유 파일 캐비닛(네트워크 너머 파일 단위 공유), SAN은 전용 물류창고 전용도로(네트워크 너머지만 블록 단위로 마치 내 디스크처럼 접근)에 비유된다.

## 깊이 이해
- **배경·문제의식**: 서버 한 대에 저장장치를 직접 붙이는 방식은 단순하지만 다른 서버와 공유가 안 되고, 여러 서버가 파일을 공유하려면 네트워크가 필요하며, 네트워크를 거치면서도 로컬 디스크 수준의 성능을 원하는 요구가 각각 다른 스토리지 방식을 만들었다.
- **작동 원리 — DAS(Directly Attached Storage)**: 서버에 SCSI·SAS·USB 같은 케이블로 저장장치를 직접 연결하며, 네트워크를 전혀 거치지 않고 서버가 파일시스템을 직접 소유한다.
- **작동 원리 — NAS(Network Attached Storage)**: 저장장치 자체가 자체 OS와 파일시스템을 가진 독립 장치로 일반 IP 네트워크(Ethernet)에 연결되며, 클라이언트는 NFS·SMB/CIFS 같은 파일 공유 프로토콜로 파일 단위(file-level)로 접근한다.
- **작동 원리 — SAN(Storage Area Network)**: 서버와 저장장치를 Fibre Channel 또는 iSCSI 같은 전용 고속 네트워크(패브릭)로 연결하며, 클라이언트(서버)는 마치 로컬 디스크처럼 블록 단위(block-level)로 저장장치에 접근한다.
- **비유**: DAS는 내 컴퓨터에 꽂힌 외장하드, NAS는 사무실 공용 파일 서버(네트워크 드라이브), SAN은 전용 전용선으로 연결된 원격 하드디스크(운영체제 입장에서는 로컬 디스크처럼 보임)에 비유된다.
- **구체 예시**: DAS 예시 — 서버 섀시 내부 SAS 백플레인에 직결된 디스크. NAS 예시 — `\\fileserver\share` 형태로 여러 사용자가 폴더를 공유하는 파일 서버. SAN 예시 — Fibre Channel 스위치를 통해 여러 서버가 하나의 스토리지 배열에서 각자 전용 LUN(Logical Unit Number)을 블록 단위로 할당받는 구성.
- **흔한 오해·주의점**: NAS와 SAN 모두 "네트워크를 거친다"는 공통점 때문에 헷갈리기 쉬우나, NAS는 파일 단위(file-level) 접근, SAN은 블록 단위(block-level) 접근이라는 접근 계층 자체가 다르다.
- **흔한 오해·주의점 보충**: iSCSI는 일반 이더넷 위에서 동작하지만 SCSI 블록 명령을 캡슐화해 전달하므로 접근 단위는 SAN과 동일한 블록 단위이며, 이를 NAS로 오분류하면 안 된다.

## 연결 개념
- RAID 레벨 0·1·5·6·10 비교 — DAS·SAN 내부 디스크 배열 구성 기법
- 스토리지 가상화 — DAS·NAS·SAN 이질적 자원을 논리 풀로 통합하는 상위 개념
- NVMe·PCIe 인터페이스 — DAS 연결에 쓰이는 최신 고속 인터페이스

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: DAS·NAS·SAN을 "네트워크 유무"와 "접근 단위(블록/파일)"라는 두 축으로 명확히 구분해 답안 전체를 구성한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: DAS는 네트워크 없이 직접 연결, NAS는 일반 IP 네트워크 위에서 파일 단위(file-level) 접근, SAN은 전용 패브릭(FC/iSCSI) 위에서 블록 단위(block-level) 접근이라는 점이 세 방식을 구분하는 핵심 축이다.
> 2. **가치**: DAS는 단순·저지연, NAS는 파일 공유와 관리 용이성, SAN은 네트워크를 거치면서도 로컬 디스크 수준의 블록 성능과 확장성을 제공한다.
> 3. **판단 포인트**: 파일 공유가 목적이면 NAS, 데이터베이스처럼 블록 단위 고성능·저지연이 목적이면 SAN, 단일 서버 전용이면 DAS를 선택 기준으로 삼는다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 접근 단위(block/file) 구분 확인 | NAS=file-level, SAN=block-level, DAS=네트워크 없음 | NAS·SAN을 둘 다 "네트워크 스토리지"로 뭉뚱그림 |
| 프로토콜·네트워크 구분 확인 | NAS=NFS/SMB over 일반 IP, SAN=FC/iSCSI 전용 패브릭 | iSCSI를 파일 단위 접근으로 오분류 |
| 적용 판단 역량 확인 | 파일 공유 vs DB 블록 성능 요구에 따른 선택 기준 | 세 방식을 나열만 하고 선택 기준 누락 |

> 요약: 이 문제는 DAS·NAS·SAN 정의 나열이 아니라 접근 단위(block/file)와 네트워크 구조 차이를 근거로 선택 기준을 제시해야 한다.

## Ⅰ. 개요 및 필요성

- 정의: 서버-저장장치 연결 방식을 네트워크 유무와 접근 단위(블록/파일)로 구분한 세 가지 스토리지 구성 방식
- 배경: 단일 서버 전용 저장(DAS)만으로는 다중 서버 파일 공유나 대규모 블록 스토리지 확장 요구를 충족할 수 없어 NAS·SAN이 등장함
- 필요성: 파일 공유 요구는 NAS의 file-level 접근으로, 데이터베이스 등 고성능 블록 접근 요구는 SAN의 block-level 접근으로 구분해 설계해야 함

---

## Ⅱ. 구조 및 구성요소

```text
Server -> DAS: SAS/SCSI 케이블 직결(네트워크 없음, block-level)
Server -> IP Network(Ethernet) -> NAS Head(자체 OS/FS) -> NFS/SMB(file-level)
Server -> SAN Fabric(FC Switch 또는 iSCSI over Ethernet) -> Storage Array -> LUN(block-level)
```

| 구성요소 | 역할 | 접근 단위 |
|:---|:---|:---|
| DAS | 서버에 직결된 저장장치, 서버가 파일시스템 소유 | block-level(서버 로컬) |
| NAS Head/Filer | 자체 OS·파일시스템을 가진 독립 파일 서버 | file-level(NFS, SMB/CIFS) |
| SAN Fabric | FC 스위치 또는 iSCSI 네트워크로 구성된 전용 패브릭 | block-level(FC, iSCSI) |
| LUN(Logical Unit Number) | SAN에서 서버에 할당되는 논리 블록 장치 단위 | block-level |

> 요약: DAS는 네트워크 없이 서버가 직접 블록을 소유하고, NAS는 일반 IP망 위에서 파일 단위로, SAN은 전용 패브릭 위에서 블록 단위로 접근한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
[DAS] 애플리케이션 -> 서버 OS 파일시스템 -> SAS/SCSI 드라이버 -> 디스크(직결)
[NAS] 애플리케이션 -> NFS/SMB 클라이언트 -> IP 네트워크 -> NAS Head 파일시스템 -> 디스크
[SAN] 애플리케이션 -> 서버 OS 파일시스템 -> FC/iSCSI HBA -> SAN Fabric -> Storage Array LUN
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 연결 방식 식별(직결/일반 IP망/전용 패브릭) | 네트워크 경유 여부 |
| 2 | 접근 프로토콜 확인(SCSI 직결, NFS/SMB, FC/iSCSI) | 접근 단위(block/file) 일치 |
| 3 | 파일시스템 소유 주체 확인(서버 자체 vs NAS Head) | 파일시스템 위치 |
| 4 | 성능·지연 특성 확인 | IOPS, 지연시간, 대역폭 |

> 요약: 세 방식은 연결 경로(직결/일반망/전용패브릭)와 접근 단위(block/file)가 다르므로 요구사항에 맞춰 프로토콜을 선택해야 한다.

## Ⅳ. 특징

| 구분 | DAS | NAS | SAN | 수치·표준 포인트 |
|:---|:---|:---|:---|:---|
| 접근 단위 | block-level(서버 로컬) | file-level | block-level | NFS/SMB=file, FC/iSCSI=block |
| 네트워크 | 없음(직결) | 일반 IP 네트워크(Ethernet) | 전용 패브릭(FC) 또는 iSCSI over Ethernet | FC는 보통 8/16/32Gbps 전용 스위치 |
| 파일시스템 위치 | 서버가 직접 소유 | NAS 장치(Filer)가 소유 | 서버(또는 클러스터 FS)가 소유 | SAN은 서버별 LUN 할당, 공유 시 클러스터 FS 필요 |
| 공유 범위 | 단일 서버 전용 | 다중 클라이언트 파일 공유 용이 | 서버 간 블록 공유는 클러스터링 필요 | SAN은 파일 공유가 목적이 아님 |
| 대표 프로토콜 | SCSI, SAS, NVMe | NFS, SMB/CIFS | Fibre Channel, iSCSI, FCoE | iSCSI는 SCSI 명령을 IP로 캡슐화 |

> 요약: DAS는 네트워크 없는 서버 전용 블록 저장, NAS는 IP망 위 파일 단위 공유, SAN은 전용 패브릭 위 블록 단위 접근이라는 점이 세 방식을 구분하는 핵심이다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | NAS | SAN | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 일반 IP망, 자체 파일시스템 보유 장치 | 전용 패브릭, 서버가 블록 장치처럼 인식 | 파일 공유가 목적이면 NAS, DB 블록 I/O 요구면 SAN |
| 비용/성능 | 상대적 저비용, 파일 프로토콜 오버헤드 존재 | 전용 패브릭 구축 비용, 낮은 지연·높은 IOPS | 지연시간 민감 애플리케이션(DB, 가상화)은 SAN 우선 |
| 운영/위험 | 파일 권한·공유 관리가 상대적으로 단순 | LUN 마스킹, 조닝(zoning) 등 전용 관리 필요 | 관리 인력·전용 네트워크 운영 역량 확보 여부로 판단 |

> 요약: 다중 사용자 파일 공유는 NAS, 데이터베이스·가상화 등 블록 단위 고성능·저지연 요구는 SAN을 선택 기준으로 삼는다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 접근 단위 혼동 설계 | NAS에 블록 워크로드(DB) 배치 | 워크로드 요구사항 사전 분석 후 SAN/NAS 재배치 | 애플리케이션 IOPS·지연 요구 대비 실측치 |
| SAN 조닝 오류 | Fibre Channel 조닝·LUN 마스킹 설정 실수 | 조닝 정책 표준화, 변경 전 검증 절차 도입 | 잘못된 LUN 노출 건수 |
| NAS 단일 장애점 | NAS Head 이중화 미비 | 클러스터형 NAS 또는 페일오버 구성 | NAS 장애 시 RTO |

> 요약: 스토리지 방식 선택 오류와 SAN 조닝 실수가 핵심 리스크이며, 워크로드 분석과 조닝 표준화·이중화로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 접근 지연 | SAN block I/O 지연이 DAS 대비 허용 범위 이내 | 스토리지 벤치마크(IOPS, latency) |
| 파일 공유 성능 | NAS 동시 접속자 수 대비 처리량 목표치 유지 | NFS/SMB 처리량 모니터링 |
| 가용성 | SAN 패브릭·NAS Head 이중화로 단일 장애점 제거 | 페일오버 테스트, RTO/RPO 측정 |

> 요약: DAS·NAS·SAN 도입 효과는 접근 지연, 파일 공유 처리량, 이중화 기반 가용성 지표로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 다중 사용자 파일 공유가 목적인 업무는 NAS를 적용하고 NFS/SMB 동시 접속자 처리량을 정기 점검함
2. 데이터베이스·가상화처럼 블록 단위 저지연·고IOPS가 필요한 업무는 SAN(FC 또는 iSCSI)을 적용하고 LUN 마스킹·조닝을 표준화함
3. 단일 서버 전용 워크로드는 DAS로 단순화하되, 향후 확장·공유 가능성을 고려해 NAS/SAN 전환 여지를 설계에 반영함

**결론 (2줄):**
- 기술사 판단: 스토리지 방식 선택은 접근 단위(파일 vs 블록)와 네트워크 구조(없음/일반IP/전용패브릭)를 기준으로 결정해야 하며, 세 방식을 혼동하면 워크로드 성능 요구를 충족할 수 없음
- 향후 방향: NVMe-oF(NVMe over Fabrics) 확산으로 SAN이 FC 전용 구조를 넘어 이더넷 기반 저지연 블록 스토리지로 진화하는 추세임
