## 미리 알고가기

- DAS는 서버에 직접 붙는 블록 스토리지임
- NAS는 네트워크를 통해 파일 단위로 공유하는 스토리지임
- SAN은 전용 네트워크로 블록 장치를 제공하는 스토리지 구조임

## Ⅰ. 개요

- **정의/개념**: DAS와 NAS와 SAN은 서버와 저장장치를 연결하는 위치와 프로토콜과 접근 단위를 기준으로 구분하는 대표적인 스토리지 계층 구조임
- **배경/필요성**: 로컬 고성능 I/O와 다중 사용자 파일 공유와 대규모 블록 저장은 요구 특성이 다르므로, 업무 성격에 맞는 저장 계층을 골라야 성능과 운영성과 복구 체계를 함께 맞출 수 있음

## Ⅱ. 특징

- DAS는 지연이 짧고 구조가 단순하지만 공유성과 중앙 관리성이 낮음
- NAS는 파일 공유와 권한 관리가 쉽지만 네트워크와 파일 프로토콜 영향을 크게 받음
- SAN은 고성능 블록 공유와 이중화에 유리하지만 구축과 운영이 복잡함
- 선택 기준은 용량보다 접근 단위와 지연과 장애 범위와 관리 방식임

## Ⅲ. 종류 및 비교

| 판단 기준 | DAS | NAS | SAN |
|:---|:---|:---|:---|
| 연결 방식 | 서버 내부 또는 직접 연결로 붙음 | IP 네트워크를 통해 파일 공유로 연결됨 | 전용 스토리지 네트워크를 통해 블록 장치를 노출함 |
| 접근 단위 | 블록 단위로 직접 접근함 | 파일 단위로 공유함 | 블록 단위로 고성능 공유를 제공함 |
| 공유·관리 방식 | 서버가 장치를 직접 소유·관리 | 파일시스템과 권한을 NAS가 관리 | LUN과 경로를 스토리지 패브릭에서 관리 |
| 대표 적용 | 단일 서버 DB·부트 디스크 | 문서 공유·파일 백업 | 가상화 데이터스토어·이중 경로 DB 볼륨 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 호스트 서버 | 애플리케이션이 파일시스템 또는 블록 장치로 I/O를 발생시킴 |
| 연결 패브릭 | SATA와 Ethernet과 FC 같은 경로가 지연과 가용성을 결정함 |
| 스토리지 컨트롤러 | RAID와 캐시와 LUN과 파일 공유 기능을 제공해 성능과 보호 수준을 좌우함 |
| 관리 계층 | 권한과 백업과 복구와 용량 정책을 통합 관리해 운영 난도를 결정함 |

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 요구 분석      | --> | 계층 선택      | --> | 경로 구성      | --> | 운영 검증      |
+-------------+     +-------------+     +-------------+     +-------------+
```

## Ⅴ. 원리 및 절차 흐름도

1. **요구 분석**: IOPS와 지연과 공유 사용자 수와 복구 기준을 정리함
2. **계층 선택**: 로컬성은 DAS, 파일 공유는 NAS, 고성능 블록 공유는 SAN을 우선 검토함
3. **경로 구성**: 볼륨과 export와 multipath와 권한을 설정함
4. **운영 검증**: 용량과 성능과 백업과 장애 조치 지표를 지속 점검함

## Ⅵ. 실무 적용 및 유의점

1. 파일 공유 중심 업무에 DAS를 쓰거나 트랜잭션 DB에 부적절한 NAS를 쓰면 구조 자체가 맞지 않으므로 워크로드별 I/O 특성을 먼저 맞추고 p99 지연시간과 처리량과 동시 사용자 적합성으로 확인함
2. SAN과 NAS는 저장장치보다 네트워크와 다중 경로 품질이 성능과 가용성을 더 크게 좌우하므로 전용 경로와 장애 조치 시험을 함께 운영하고 경로 사용률과 절체 복구 시간과 복구 성공률로 확인함

## Ⅶ. 결론

스토리지 계층 선택의 핵심은 장비 이름이 아니라 접근 단위와 지연 특성과 운영 책임 범위를 맞추는 데 있음.
