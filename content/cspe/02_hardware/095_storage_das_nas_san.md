## Ⅰ. 개요
- **정의**: 서버-스토리지 연결 방식에 따라 분류한 DAS·NAS·SAN 세 가지 스토리지 아키텍처
- **배경/필요성**: 데이터 규모와 공유 요구가 다양화되면서 접속 방식별 특성에 맞는 스토리지 선택이 요구됨
- **비유**: 개인 서랍(DAS), 공유 파일 캐비닛(NAS), 전용 창고 네트워크(SAN)

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 세 아키텍처의 접속 방식·프로토콜 차이 | 블록 I/O(DAS·SAN) vs 파일 I/O(NAS) | NAS는 파일 수준, SAN은 블록 수준 공유임 |

> 요약: DAS·NAS·SAN은 접속 범위와 I/O 단위로 구분되는 스토리지 아키텍처임

## Ⅱ. 구성요소
```text
DAS:  Server ---[SCSI/SATA]--- Disk

NAS:  Client --[LAN/TCP]-- NAS Head --[FS]-- Disk

SAN:  Server --[FC/iSCSI]-- SAN Fabric -- Storage Array
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| DAS(Direct Attached Storage) | 서버에 로컬 인터페이스(SATA/SAS)로 직결된 저장장치 | 책상 서랍 |
| NAS(Network Attached Storage) | LAN을 통해 파일 단위(NFS/SMB)로 접근하는 공유 스토리지 | 사무실 공유 캐비닛 |
| SAN(Storage Area Network) | FC/iSCSI 전용 네트워크로 블록 단위 I/O를 제공하는 스토리지 패브릭 | 전용 물류 창고 네트워크 |
| SAN 스위치(FC Switch) | SAN 패브릭 내 서버-스토리지 간 블록 트래픽을 라우팅하는 장비 | 물류 배송 허브 |

> 요약: DAS는 직결, NAS는 파일 공유, SAN은 블록 공유로 각각 접속 방식이 구분됨

## Ⅲ. 절차
```text
요구 분석 --> 아키텍처 선정 --> 인프라 구성 --> 운영/확장
     |              |                |              |
     v              v                v              v
 용량/공유 요건   DAS/NAS/SAN 결정  네트워크 배치   모니터링/증설
```
- 1단계: 요구 분석 — 용량·IOPS·공유 범위·가용성 요건을 식별함
- 2단계: 아키텍처 선정 — 단일 서버 전용이면 DAS, 파일 공유면 NAS, 블록 수준 고성능 공유면 SAN을 선택함
- 3단계: 인프라 구성 — 선정된 아키텍처에 맞는 네트워크(LAN/FC)·스토리지 컨트롤러·디스크 배치를 수행함
- 4단계: 운영/확장 — 성능 모니터링 후 용량 증설·티어링 정책을 적용하여 확장함

> 요약: 요구 분석 → 아키텍처 선정 → 구성 → 운영의 순서로 스토리지를 도입함

## Ⅳ. 문제점
- DAS 공유 불가: 서버 간 스토리지 공유가 불가능하여 데이터 사일로와 용량 낭비가 발생함
- NAS 성능 제약: LAN 경유 파일 프로토콜 오버헤드로 블록 수준 저지연이 어려움
- SAN 비용 부담: FC 스위치·HBA·전용 케이블 등 인프라 구축·운영 비용이 높음

> 요약: DAS의 공유 한계, NAS의 성능 제약, SAN의 비용 부담이 각각의 문제임

## Ⅴ. 개선방안
1. 단기: 클러스터 공유 디스크(Shared DAS) 또는 JBOD 확장으로 DAS 공유 한계를 완화함
2. 중기: RDMA(RoCE/iWARP) 기반 NAS 프로토콜 도입으로 파일 I/O 레이턴시를 마이크로초 수준으로 단축함
3. 장기: NVMe-oF(NVMe over Fabrics)로 SAN 패브릭을 이더넷 기반으로 통합하여 FC 전용 비용을 제거함

> 요약: 공유 확장·RDMA 가속·NVMe-oF 통합으로 각 아키텍처의 약점을 보완함

## Ⅵ. 전망
- 발전 방향: 소프트웨어 정의 스토리지(SDS)가 DAS·NAS·SAN 경계를 통합하는 방향으로 수렴 중임
- 기술사적 판단: 워크로드별 I/O 특성(블록/파일/오브젝트)에 따른 아키텍처 선택 역량이 핵심임
- 기술사 제언: NVMe-oF와 SDS 동향을 반영한 스토리지 아키텍처 설계 역량 확보가 필요
