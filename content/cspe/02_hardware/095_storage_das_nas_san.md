## 미리 알고가기

- DAS는 서버에 직접 연결된 블록 스토리지임
- NAS는 네트워크를 통해 파일 단위로 공유하는 스토리지임
- SAN은 전용 네트워크로 블록 장치를 제공하는 스토리지 구조임

## Ⅰ. 개요

- **정의/개념**: DAS와 NAS와 SAN은 서버와 저장장치를 연결하는 위치와 프로토콜과 접근 단위를 기준으로 구분하는 대표적인 스토리지 계층 구조임
- **배경/필요성**: 로컬 고성능 I/O와 다중 사용자 파일 공유와 대규모 블록 저장은 요구 특성이 다르므로, 업무 성격에 맞는 저장 계층을 선택해야 성능과 운영성과 복구 체계를 함께 맞출 수 있음

## Ⅱ. 특징

- DAS는 지연이 짧고 구조가 단순하지만 공유성과 중앙 관리성이 낮음
- NAS는 파일 공유가 쉽고 관리가 편리하지만 네트워크와 파일 프로토콜 영향을 크게 받음
- SAN은 고성능 블록 공유와 고가용성에 유리하지만 구축과 운영 복잡도가 높음
- 선택 기준은 용량보다 접근 단위와 지연과 장애 범위와 관리 방식임

## Ⅲ. 종류 및 비교

| 판단 기준 | DAS | NAS | SAN |
|:---|:---|:---|:---|
| 연결 위치 | 서버 내부 또는 직접 연결 | IP 네트워크 기반 파일 공유 | 전용 스토리지 네트워크 |
| 접근 단위 | 블록 | 파일 | 블록 |
| 장점 | 낮은 지연과 단순한 구성 | 공유와 권한 관리 편의 | 고성능과 집중 관리와 이중화 |
| 대표 업무 | 단일 서버 DB, 부트 디스크 | 문서 공유, 백업, 로그 저장 | DB, 가상화, 미션 크리티컬 업무 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Host Server | 애플리케이션이 파일시스템 또는 블록 장치로 I/O를 발생시키며 요구 성능과 공유 방식이 계층 선택의 출발점이 됨 |
| Connection Fabric | SATA와 Ethernet과 FC 같은 연결 경로가 지연과 가용성과 멀티패스 전략을 결정함 |
| Storage Controller | RAID와 캐시와 LUN과 파일 공유 기능을 제공해 성능과 보호 수준을 동시에 좌우함 |
| Management Layer | 권한과 백업과 복구와 용량 정책을 통합 관리해 운영 난도와 장애 대응 속도를 결정함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 요구 분석      | --> | 계층 선택      | --> | 경로 구성      | --> | 운영 검증      |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **요구 분석**: IOPS와 latency와 공유 사용자 수와 복구 기준을 정리함
2. **계층 선택**: 로컬성은 DAS, 파일 공유는 NAS, 고성능 블록 공유는 SAN을 우선 검토함
3. **경로 구성**: 볼륨과 export와 multipath와 권한을 설정함
4. **운영 검증**: 용량과 성능과 백업과 장애 조치 지표를 지속 점검함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 파일 공유 업무에 DAS를 쓰거나 트랜잭션 DB에 부적절한 NAS를 쓰면 성능과 운영성이 함께 나빠질 수 있음
   - 해결방안: workload별 I/O profile을 근거로 접근 단위를 재선정하고 p99 latency와 user concurrency fit으로 검증함
2. 문제: NAS와 SAN은 저장장치보다 네트워크와 multipath 설정이 병목이 되어 예상 성능이 나오지 않을 수 있음
   - 해결방안: 전용 경로와 multipath 튜닝을 적용하고 path utilization과 failover recovery time으로 검증함
3. 문제: DAS가 분산 확장되면 서버별 백업과 용량 관리가 흩어져 운영 비용이 급증할 수 있음
   - 해결방안: 중앙 백업 정책과 용량 표준화를 추진하고 storage admin effort와 backup compliance rate로 검증함

## Ⅶ. 적용 사례

- 트랜잭션 DB 설계에서는 SAN과 NVMe DAS를 비교해 지연 요구에 맞는 계층을 선택하고 확인 지표는 p99 latency와 IOPS임
- 부서 파일 공유 환경에서는 NAS에 권한과 스냅샷 정책을 적용하고 확인 지표는 throughput과 restore success rate임
- 전사 스토리지 표준화에서는 분산 DAS를 통합 관리 체계로 묶고 확인 지표는 capacity utilization과 backup compliance rate임

## Ⅷ. 결론

스토리지 계층 선택은 장비 유행보다 접근 단위와 지연 특성과 운영 책임 범위를 맞추는 구조 판단이 핵심임.
