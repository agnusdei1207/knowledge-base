## Ⅰ. 개요
- 시스템의 단일 장애점(SPOF)을 제거하여 서비스 연속성을 확보하는 설계
- 장애 발생 시에도 무중단 서비스를 제공하기 위한 가용성 극대화 기술

| 구분 | 내용 |
| --- | --- |
| 정의 | 주요 자원을 복수 구성하여 결함 허용(Fault Tolerance) 구현함 |
| 목표 | 고가용성(High Availability, 99.9% 이상) 달성 및 RTO/RPO 단축 |
| 출제의도 | Active-Active, Active-Standby 구조 및 가용성 지표 이해 |

## Ⅱ. 구성요소
```
[ Redundancy Architectures ]
(A-A Mode)                  (A-S Mode)
+-------+   +-------+       +-------+   +-------+
| Active|   | Active|       | Active|   |Standby|
+-------+   +-------+       +-------+   +-------+
  (Load Balancing)            (Failover)
```
| 구성요소 | 설명 | 비유 |
| --- | --- | --- |
| Load Balancer | 부하를 여러 자원으로 분산하여 처리 효율 증대 | 교통 경찰 |
| Failover | 장애 발생 시 백업 장비로 서비스를 자동 전환 | 대역 투입 |
| Heartbeat | 장비 간 생존 확인을 위한 주기적인 신호 교환 | 맥박 확인 |
> 요약: 부하 분산(A-A) 또는 예비 대기(A-S)를 통해 서비스 지속함.

## Ⅲ. 절차
```
[장애 감지] -> [판단/의사결정] -> [트래픽 전환] -> [데이터 동기화]
```
1. 감지: 헬스 체크를 통해 서버나 네트워크의 이상 유무 실시간 파악함.
2. 판단: 설정된 임계치 초과 시 장애로 간주하고 백업 가동 결정함.
3. 전환: 가상 IP(VIP) 이동 등을 통해 클라이언트 접속 경로 변경함.
4. 동기화: 주 장비와 백업 장비 간 데이터 일관성을 실시간 유지함.
> 요약: 장애 발생 시 이를 감지하고 정상 자원으로 업무를 즉시 인계함.

## Ⅳ. 문제점
- 비용 증가: 동일 장비를 두 배 이상 구축함에 따라 인프라 비용 폭증함.
- 데이터 불일치: 전환 시점의 데이터 유실이나 정합성 오류 발생 가능함.

## Ⅴ. 개선방안
- 클라우드 활용: 사용한 만큼 지불하는 클라우드 기반 가용 영역(AZ) 활용함.
- 실시간 복제: 동기(Synchronous) 복제 방식을 통해 데이터 유실 차단함.

## Ⅵ. 전망
- 마이크로서비스(MSA)와 컨테이너 기반의 자가 치유(Self-healing)가 대세임.
- 인공지능 기반의 장애 예측 및 선제적 조치(AIOps) 도입이 핵심 CSF임.
