## Ⅰ. 개요
- 정의: 속도, 용량, 가격이 다른 저장 장치들을 계층적으로 배치하여 최적의 가성비를 도출하는 구조
- 배경: 프로세서와 메모리 간의 속도 차이(Memory Wall)를 극복하기 위한 설계 전략
- 출제 의도: 지역성(Locality)의 원리와 계층 간 데이터 이동 최적화 기술 이해

## Ⅱ. 구성요소
- ASCII 구조도
  Fast/Small/Pricey    +------------+  (Registers)
          ^            |   L1/L2    |  (Cache)
          |            +------------+
          |            |    DRAM    |  (Main Memory)
          |            +------------+
          v            |  SSD/HDD   |  (Storage)
  Slow/Large/Cheap     +------------+

- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 레지스터 | CPU 내부의 초고속 소량 저장소 | 주머니 소지품 |
| 캐시 (SRAM) | 자주 사용되는 데이터를 임시 보관 | 책상 위 서류 |
| 메인메모리(DRAM)| 실행 중인 프로그램과 데이터 상주 | 책꽂이 |
> 요약: 상위 계층은 속도에, 하위 계층은 용량에 집중함

## Ⅲ. 절차
- ASCII 흐름도
  (CPU Req) -> (L1 Search) --(Miss)--> (L2 Search) --(Miss)--> (DRAM)
                  |                       |                     |
                  +-----------(Hit)-------+----------(Hit)------+
                                          v
                                   (Return Data)

- 4단계 설명
1. 지역성 활용: 최근 접근한 데이터나 인접 데이터를 상위 계층에 미리 배치
2. 수직적 탐색: CPU 요청 시 상위(L1)부터 하위(DRAM) 순서로 데이터 존재 확인
3. 계층적 이동: 데이터 발견 시 하위에서 상위로 블록 단위로 복사(Staging)
4. 일관성 유지: 데이터 수정 시 하위 계층과의 일치 여부 관리(Write Policy)
> 요약: 필요한 데이터가 빠른 상위 계층에 있을 확률(Hit Rate)을 높이는 과정임

## Ⅳ. 문제점
- 메모리 벽: CPU 속도는 급격히 향상되었으나 DRAM 속도는 상대적으로 지체됨
- 용량 병목: 데이터 폭증으로 인해 계층 간 데이터 전송(IO) 부하가 성능의 병목이 됨

## Ⅴ. 개선방안
- (단기) 대용량 캐시(L3): LLC 사이즈를 키워 외부 메모리 접근 횟수 최소화
- (중기) HBM (High Bandwidth Memory): 적층 구조를 통해 DRAM 대역폭 혁신
- (장기) PIM (Processing In Memory): 메모리 내에서 직접 연산하여 데이터 이동 제거

## Ⅵ. 전망
- 로드맵: CXL(Compute Express Link) 등을 통한 메모리 풀링 및 자원 공유 가속화
- CSF: 비휘발성 메모리(PRAM 등)를 활용한 스토리지와 메모리 계층 간 경계 붕괴 대응
