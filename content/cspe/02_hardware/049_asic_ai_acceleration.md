## 미리 알고가기

- ASIC: 주문형 반도체(Application-Specific Integrated Circuit, ASIC)는 특정 용도를 위해 맞춤 설계하고 제조하는 반도체임
- AI: 인공지능(Artificial Intelligence, AI)은 데이터 기반 모델로 추론·분류·생성 작업을 수행하는 기술 영역임
- MAC: 곱셈-누산(Multiply-Accumulate, MAC)은 신경망 행렬 연산의 핵심 연산임
- NRE: 비반복 엔지니어링(Non-Recurring Engineering, NRE)은 설계와 마스크 제작에 드는 일회성 비용임
- 데이터 재사용: 같은 가중치나 활성값을 여러 연산에 반복 사용해 메모리 접근을 줄이는 전략임

## Ⅰ. 개요

- **정의**: ASIC AI 가속은 신경망의 MAC, 행렬 곱, 컨볼루션, 어텐션 연산을 특정 데이터패스와 메모리 구조로 고정 설계해 성능, 전력, 면적, 단가를 기준으로 대량 AI 워크로드를 최적화하는 주문형 반도체 가속 방식임
- **배경/필요성**: 범용 중앙처리장치(Central Processing Unit, CPU)와 그래픽 처리 장치(Graphics Processing Unit, GPU)는 다양한 작업을 처리하지만 특정 AI 연산에는 불필요한 제어와 데이터 이동 비용이 존재함. 대규모 서비스와 온디바이스 AI는 전력당 처리량을 높이기 위해 전용 하드웨어가 필요함
- **비유**: 범용 공구상자가 아니라 한 제품을 대량 생산하도록 설계된 전용 생산라인과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 전용 AI 반도체의 선택 근거와 한계 설명 | MAC 배열, 메모리 계층, NRE, 유연성 | ASIC을 단순 고성능 칩으로 설명 |

> 요약: ASIC AI 가속은 특정 AI 연산을 칩 구조에 고정해 전력당 성능을 극대화하는 방식임.

## Ⅱ. 특징/비교

| 판단 기준 | 필드 프로그래머블 게이트 어레이(Field Programmable Gate Array, FPGA) AI 가속 | ASIC AI 가속 |
|:---|:---|:---|
| 변경 가능성 | 비트스트림 재구성으로 구조 변경이 가능함 | 제조 후 데이터패스 변경이 제한적임 |
| 성능/전력 | 재구성 오버헤드 때문에 최고 효율은 제한됨 | 전용 회로로 높은 처리량과 낮은 전력을 달성함 |
| 적용 기준 | 모델 변화가 크고 물량이 제한적일 때 적합함 | 워크로드가 안정적이고 대량 생산일 때 적합함 |

> 요약: ASIC은 유연성을 비용으로 지불하고 전력당 성능과 단가를 얻는 선택임.

## Ⅲ. 구성요소

```text
+----------+     +----------+     +----------+
| Compiler | --> | Scheduler| --> | MAC Array|
+----------+     +----------+     +----------+
      |                               |
      v                               v
+----------+                   +-------------+
| Runtime  | <---------------- | SRAM/HBM    |
+----------+                   +-------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| MAC 배열 | 행렬 곱과 컨볼루션을 병렬로 수행하는 핵심 연산부임 | 전용 생산 기계 |
| 온칩 SRAM | 가중치와 활성값을 가까이 저장해 데이터 재사용률을 높임 | 생산라인 옆 부품함 |
| DMA/NoC | 직접 메모리 접근(Direct Memory Access, DMA)과 네트워크 온 칩(Network-on-Chip, NoC)이 외부 메모리와 연산부 사이의 텐서 이동을 스케줄링함 | 물류 컨베이어 |
| 컴파일러/런타임 | 모델 그래프를 하드웨어 명령과 메모리 배치로 변환함 | 작업 지시서 |

> 요약: ASIC AI 가속기는 전용 연산 배열과 가까운 메모리, 데이터 이동 제어, 컴파일러가 함께 성능을 만듦.

## Ⅳ. 절차

```text
+----------+     +----------+     +----------+     +----------+
| Workload | --> | Arch     | --> | RTLCheck | --> | Deploy   |
+----------+     +----------+     +----------+     +----------+
```

1. **워크로드 고정**: 목표 모델, 연산자, 정밀도, 배치 크기, 지연 요구를 정의함
2. **구조 설계**: MAC 배열, 메모리 계층, NoC, DMA, 명령 세트를 전력·성능·면적(Power, Performance, Area, PPA) 기준으로 설계함
3. **RTL 검증**: 레지스터 전송 수준(Register Transfer Level, RTL) 기능 검증, 성능 시뮬레이션, 전력 분석, 테스트 용이 설계(Design for Test, DFT)를 수행함
4. **양산/운영**: 제조, bring-up, 드라이버와 컴파일러 배포 후 실제 모델 성능을 측정함

> 요약: ASIC AI 가속은 안정된 워크로드를 기준으로 칩 구조를 고정하고 검증·양산하는 과정임.

## Ⅴ. 문제점

- **P1 모델 변화 대응 한계**: 새로운 연산자나 정밀도가 등장하면 고정 데이터패스가 성능을 내지 못할 수 있음
- **P2 높은 NRE와 일정 위험**: 설계 오류가 제조 후 발견되면 마스크 재제작과 출시 지연 비용이 큼
- **P3 메모리·열 병목**: 연산 배열이 커질수록 데이터 공급과 발열 제어가 전체 성능을 제한함

> 요약: ASIC AI 가속의 위험은 고정 구조, 선투자 비용, 데이터 이동·열 제약에서 발생함.

## Ⅵ. 개선방안

1. **단기**: 신규 연산자 요구, tape-out 전 결함, 대역폭·온도 병목을 점검함
2. **중기**: 프로토타입 검증, 확장 명령, 메모리 계층 최적화를 설계에 반영함
3. **장기**: 모델 로드맵과 양산 물량을 기준으로 ASIC 투자 거버넌스를 운영함

- **P1 대응**: 프로그래머블 제어부, 확장 명령, 소프트웨어 fallback 경로를 설계함 (확인: 신규 연산자 지원률)
- **P2 대응**: FPGA 프로토타입, 에뮬레이션, 형식 검증, 단계별 tape-out 기준을 적용함 (확인: tape-out 전 결함 제거율)
- **P3 대응**: 정적 램(Static Random Access Memory, SRAM) 용량 최적화, 고대역폭 메모리(High Bandwidth Memory, HBM)/칩렛 연계, 동적 전압 주파수 조정(Dynamic Voltage and Frequency Scaling, DVFS)과 열 throttling을 적용함 (확인: 대역폭 사용률과 접합 온도)

> 요약: 개선은 하드웨어 확장 여지, 제조 전 검증, 메모리·열 공동 설계로 리스크를 낮춤.

## Ⅶ. 전망

- **발전 방향**: AI ASIC은 신경망 처리 장치(Neural Processing Unit, NPU), 텐서 처리 장치(Tensor Processing Unit, TPU), 도메인 특화 아키텍처(Domain-Specific Architecture, DSA), 칩렛 기반 가속기 형태로 분화하고 메모리 근접 구조와 결합함
- **기술사적 판단**: 물량, 모델 안정성, 전력 예산, 소프트웨어 생태계를 함께 비교해 ASIC 투자 여부를 결정해야 함
- **기술사 제언**: 답안에서는 ASIC을 빠른 칩으로만 쓰지 말고 NRE와 유연성 비용까지 포함해 판단해야 함
