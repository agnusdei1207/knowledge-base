# ASIC AI 가속 (ASIC AI Acceleration)

## 미리 알고가기

- ASIC: 주문형 반도체(Application-Specific Integrated Circuit, ASIC)는 특정 용도를 위해 맞춤 설계하고 제조하는 반도체임
- AI 가속: 신경망의 행렬 곱, 컨볼루션, 어텐션, 전처리 연산을 하드웨어로 빠르게 처리하는 방식임
- MAC: 곱셈-누산(Multiply-Accumulate, MAC)은 신경망 행렬 연산의 핵심 연산임
- NRE: 비반복 엔지니어링(Non-Recurring Engineering, NRE)은 설계와 마스크 제작에 드는 일회성 비용임
- 데이터 재사용: 같은 가중치나 활성값을 여러 연산에 반복 사용해 메모리 접근을 줄이는 전략임

## 1. 개요

- **정의/개념**: ASIC AI 가속은 신경망의 MAC, 행렬 곱, 컨볼루션, 어텐션 연산을 특정 데이터패스와 메모리 구조로 고정 설계해 성능, 전력, 면적, 단가를 기준으로 대량 AI 워크로드를 최적화하는 주문형 반도체 가속 방식임.
- **배경/필요성**: 범용 CPU와 GPU는 다양한 작업을 처리하지만 특정 AI 연산에는 불필요한 제어와 데이터 이동 비용이 존재함. 대규모 서비스와 온디바이스 AI는 전력당 처리량을 높이기 위해 전용 하드웨어가 필요함.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 전용 AI 반도체의 선택 근거와 한계 설명 | MAC array, memory hierarchy, dataflow, NRE, flexibility | ASIC을 단순 고성능 칩으로 설명, 변경 불가 리스크 누락 |

> 요약: ASIC AI 가속은 특정 AI 연산을 칩 구조에 고정해 전력당 성능과 단가를 극대화하는 방식임.

## 2. 특징 및 비교

| 판단 기준 | GPU | FPGA | ASIC AI 가속기 |
|:---|:---|:---|:---|
| 구조 유연성 | 소프트웨어로 커널 변경 가능 | bitstream으로 회로 재구성 가능 | 제조 후 구조 변경 어려움 |
| 성능·전력 | 높은 처리량, 높은 전력 소모 | 낮은 지연과 중간 수준 유연성 | 목표 연산에서 전력당 성능 우수 |
| 비용 구조 | 장비 단가 중심 | 장치 단가와 개발 비용 중간 | NRE 높고 대량 생산 시 단가 유리 |
| 적용 조건 | 다양한 모델과 연구 환경 | 변화 있는 엣지·네트워크 처리 | 안정된 대량 워크로드 |

ASIC은 높은 NRE를 감수할 만큼 연산 패턴과 시장 규모가 명확할 때 적합함. 모델과 알고리즘이 자주 바뀌는 단계에서는 GPU·FPGA가 유리하고, 대량 추론·모바일 SoC처럼 전력과 단가가 핵심이면 ASIC이 강점을 가짐.

## 3. 구성요소/구조

```text
+----------+      +-------------+      +-------------+      +----------+
| Input    | ---> | On-chip Mem | ---> | MAC Array   | ---> | Output   |
+----------+      +-------------+      +-------------+      +----------+
                         ^                    |
                         |                    v
                  +-------------+      +-------------+
                  | DMA/NoC     |      | Accumulate  |
                  +-------------+      +-------------+
```

| 구성요소 | 설명 | 핵심 포인트 |
|:---|:---|:---|
| MAC 배열 | 행렬 곱과 컨볼루션의 곱셈·누산을 병렬 수행함 | 처리량 |
| 온칩 메모리 | 가중치, 활성값, 중간 결과를 저장해 외부 메모리 접근을 줄임 | 데이터 재사용 |
| 데이터플로우 제어 | weight-stationary, output-stationary 등 연산 배치를 결정함 | 메모리 병목 완화 |
| NoC/DMA | 칩 내부와 외부 메모리 사이 데이터 이동을 관리함 | 대역폭 |
| 컴파일러/런타임 | 모델 그래프를 하드웨어 실행 단위로 매핑함 | 소프트웨어 생태계 |

### 원리/흐름도

```text
+----------+      +----------+      +-----------+      +----------+
| Model Map| ---> | Dataflow | ---> | Execute   | ---> | Return   |
+----------+      +----------+      +-----------+      +----------+
```

모델 그래프는 지원 연산자와 메모리 제약에 맞게 분할되고, 런타임은 입력 데이터를 온칩 메모리와 MAC 배열로 공급함. ASIC의 성능은 연산기 수보다 외부 메모리 접근을 얼마나 줄이는지에 크게 좌우됨.

## 4. 문제점 및 개선방안

1. **높은 NRE와 시장 리스크**: 설계·검증·마스크 비용이 높아 수요 예측이 빗나가면 회수가 어려움.
   - **개선방안**: 목표 워크로드, 생산량, 제품 수명, 공정 비용을 사업성 모델로 검증함. (확인: 손익분기 생산량)
2. **알고리즘 변화 대응 한계**: 제조 후 지원 연산자와 데이터패스가 고정되어 새 모델을 효율적으로 실행하지 못할 수 있음.
   - **개선방안**: programmable engine, microcode, compiler fallback, 이종 가속기 조합을 설계함. (확인: 지원 연산자 커버리지)
3. **메모리 병목**: MAC 배열이 충분해도 외부 메모리 대역폭이 부족하면 연산기가 idle 상태가 됨.
   - **개선방안**: 온칩 SRAM 확대, tiling, sparsity 활용, HBM/NoC 대역폭 설계를 적용함. (확인: MAC utilization, memory bandwidth)

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 데이터센터 AI 추론 | 반복되는 대규모 추론 워크로드를 전용 가속기로 처리해 전력당 처리량을 높임 | QPS/W, p99 지연, MAC utilization |
| 모바일 SoC NPU | 카메라, 음성, 온디바이스 모델을 저전력으로 실행하도록 SoC 내부에 통합함 | 배터리 소모, 추론 지연, 발열 |
| 스마트 카메라·산업 장비 | 제한 전력에서 특정 비전 모델을 지속 실행하도록 고정 기능 가속기를 적용함 | FPS/W, 온도, 모델 정확도 |

## 6. 결론

ASIC AI 가속은 특정 AI 워크로드가 충분히 안정되고 대량 처리될 때 전력당 성능과 단가를 극대화함. 그러나 높은 NRE, 알고리즘 변화, 메모리 병목이 핵심 리스크이므로 단순히 “전용 칩이라 빠르다”로 설명하면 부족함. 기술 선택은 목표 모델의 안정성, 생산 규모, 연산자 커버리지, 메모리 구조를 함께 검토해야 함.
