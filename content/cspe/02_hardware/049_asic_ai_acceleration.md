## 미리 알고가기

- ASIC은 특정 목적을 위해 고정 기능으로 설계한 주문형 반도체임
- AI 가속에서는 MAC 배열, SRAM, 데이터 재사용 구조로 연산당 전력 소모를 줄임
- 초기 NRE 비용은 크지만 대량 배포 시 성능과 전력 이점이 큼

## Ⅰ. 개요

- **정의/개념**: ASIC AI 가속은 특정 신경망 연산 패턴에 맞게 데이터 경로, 메모리 구조, 제어 로직을 고정 설계해 높은 처리량과 전력 효율을 제공하는 전용 AI 반도체 방식임
- **배경/필요성**: 대규모 서비스와 온디바이스 AI는 범용 가속기의 전력 낭비를 감당하기 어려워, 반복되는 연산 패턴에 특화한 전용 하드웨어가 필요함

## Ⅱ. 특징

- 불필요한 범용 로직을 제거해 성능 대비 전력 효율이 가장 높음
- 모델 변화가 적은 서비스에서는 대량 배포 시 총비용 경쟁력이 커짐
- 설계 후 기능 변경이 어렵기 때문에 모델 변화 대응력은 낮음
- 메모리 구조와 데이터 이동 최적화가 처리량과 전력 소모를 좌우함

## Ⅲ. 종류 및 비교

| 판단 기준 | GPU | FPGA | ASIC |
|:---|:---|:---|:---|
| 기능 변경 | 소프트웨어 교체 | 비트스트림 재작성 | 회로 재설계·재제작 |
| 연산 경로 | 범용 명령 실행 | 재구성 논리로 구현 | 고정 데이터플로우로 구현 |
| 초기 비용 | 기존 프로세서와 개발 도구 사용 | FPGA 장치와 설계 도구 필요 | 회로 설계·검증·마스크 비용 발생 |
| 생산 수량 영향 | 칩당 가격 변화가 작음 | FPGA 장치 단가가 반복됨 | 생산량 증가 시 칩당 NRE 부담 감소 |

> 요약: ASIC은 회로 변경이 어렵지만 동일 연산을 대량 처리할 때 연산당 전력과 생산 단가를 낮춤.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| PE Array, MAC Engine | 반복적인 행렬 연산을 병렬로 수행하며 ASIC 처리량의 중심이 됨 |
| On-chip SRAM | 활성값과 가중치를 가까이 저장해 DRAM 접근과 에너지 소비를 줄임 |
| Dataflow, Scheduler | weight-stationary나 output-stationary 같은 전략으로 데이터 이동 병목을 줄임 |
| Host Interface, NoC | CPU와 메모리와의 연결 경로를 담당하며 시스템 통합성과 확장성을 결정함 |

```text
+-------------+     +-------------+     +-------------+     +-------------+
| Host Input  | --> | Dataflow     | --> | PE Array    | --> | On-chip SRAM|
+-------------+     +-------------+     +-------------+     +-------------+
```

> 요약: ASIC AI 가속은 PE 배열, SRAM, dataflow를 고정해 데이터 이동 에너지를 줄임.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 모델 고정화    | --> | 데이터플로우 설계 | --> | 전용 연산 수행 | --> | 대량 배포 운영 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **모델 고정화**: 주요 연산 패턴과 비트폭을 확정함
2. **데이터플로우 설계**: 연산 배열과 메모리 이동 구조를 최적화함
3. **전용 연산 수행**: 지정된 모델 경로를 고효율로 실행함
4. **대량 배포 운영**: 변화가 적은 워크로드에 반복 적용함

> 요약: 모델 연산을 고정하면 전용 데이터플로우를 적용할 수 있고, 생산 수량이 늘면 칩당 NRE 부담이 감소함.

## Ⅵ. 실무 적용 및 유의점

1. 클라우드 추론·스마트폰 전용 엔진은 ASIC 전력 효율이 높지만 모델 변화가 수명 주기 리스크를 키우므로 프로그래머블 제어층과 소프트웨어 추상화를 남기고 throughput per watt, model portability로 확인함
2. 대량 배포용 전용 칩은 NRE와 재테이프아웃 비용이 크므로 칩렛 재사용과 단계적 검증을 적용하고 first-pass success rate, NRE recovery period로 확인함

## Ⅶ. 결론

ASIC AI 가속은 변화가 적은 워크로드와 대량 배포가 전제일 때 맞으므로 유연성 손실보다 전력·비용 이익이 큰지 먼저 판단해야 함.

## 작성 근거(검토용)

- ASIC AI 가속은 고정 데이터 경로, PE 배열, SRAM, dataflow를 핵심으로 설명함
- 비교표는 유연성, 전력 효율, 초기 비용, 대량 배포 적합성으로 판단축을 제한함
- 실무 판단은 throughput per watt, model portability, NRE recovery period로 검증 가능하게 작성함
