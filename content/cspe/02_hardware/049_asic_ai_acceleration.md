## Ⅰ. 개요
- **정의**: 특정 AI 연산(매트릭스 곱셈·합성곱 등)에 최적화된 전용 설계 반도체
- **배경/필요성**: AI 워크로드가 대규모화되면서 범용 프로세서로는 전력 대비 처리량 요구를 충족할 수 없으므로, 연산 경로를 고정하여 에너지를 극한까지 절감할 수단이 필요함
- **비유**: 모든 요리를 하는 만능 주방이 아니라, 한 메뉴만 대량 생산하는 전용 생산 라인과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| FPGA(048)·GPU(050) 대비 ASIC의 장단점 비교 | 고정 회로에 의한 TOPS/W 극대화 | ASIC=재구성 불가라는 한계를 반드시 언급할 것 |

> 요약: 연산 경로를 실리콘에 고정하여 특정 AI 연산의 TOPS/W를 극대화하는 전용 칩임

## Ⅱ. 구성요소
```text
Host CPU <--PCIe/CXL--> ASIC Accelerator
                            |
              +--------------+--------------+
              |              |              |
         MAC Array     On-Chip SRAM    Control Unit
              |              |              |
              +---------Interconnect--------+
                             |
                          HBM/DDR
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| MAC Array | 수천~수만 개 곱셈-누산 유닛을 격자형으로 배치한 시스톨릭/메시 어레이 | 대량 생산 컨베이어 벨트 |
| On-Chip SRAM | 가중치·활성값을 재사용하여 외부 메모리 접근을 줄이는 스크래치패드 | 작업대 위 재료 트레이 |
| Control Unit | 데이터 흐름 스케줄링·타일링·DMA 제어를 수행함 | 공장 관리자 |
| HBM/DDR 인터페이스 | 대용량 모델 파라미터를 적재하는 외부 메모리 경로 | 원재료 창고 |
| Host 인터페이스 | PCIe/CXL을 통해 호스트 CPU와 명령·데이터를 교환함 | 납품 트럭 |

> 요약: MAC Array가 핵심 연산을 수행하고, On-Chip SRAM이 데이터 재사용률을 높여 외부 대역폭 병목을 완화함

## Ⅲ. 절차
```text
워크로드 프로파일링 --> 아키텍처 설계 --> RTL 구현·검증 --> 테이프아웃·양산
```
- 1단계: 타깃 모델(Transformer, CNN 등)의 연산 패턴·데이터 타입·처리량 요구를 프로파일링함
- 2단계: MAC 어레이 크기·데이터 흐름(WS/OS/RS)·메모리 계층을 결정하는 마이크로아키텍처를 설계함
- 3단계: RTL 구현 후 기능·타이밍·전력 시뮬레이션과 FPGA(048 참조) 프로토타이핑으로 검증함
- 4단계: 파운드리에 GDS를 전달(Tape-out)하고 패키징·테스트·양산을 수행함

> 요약: 워크로드 분석 → 아키텍처 설계 → RTL 검증 → 테이프아웃 순으로 전용 가속기를 개발함

## Ⅳ. 문제점
- 재구성 불가: 실리콘 확정 후 연산 구조 변경이 불가하므로 모델 구조가 바뀌면 가속 효율이 급감함 — FPGA(048 참조) 대비 유연성이 낮음
- 높은 NRE 비용: 선단 공정(3 nm 이하) 마스크·설계·검증 비용이 수억 달러에 달함 — 소량 생산 시 칩당 단가가 비현실적으로 상승함
- 긴 개발 주기: 설계부터 양산까지 18~24개월이 소요되어 AI 모델 진화 속도를 따라가기 어려움

> 요약: 재구성 불가, 높은 초기 비용, 긴 개발 주기가 ASIC AI 가속의 주요 제약임

## Ⅴ. 개선방안
1. 단기: 프로그래머블 데이터 흐름 엔진(예: 가변 타일링)을 내장하여 다양한 모델 구조에 대한 적응력을 확보함
2. 중기: 칩렛 기반 모듈화로 MAC 타일 수를 조절하고 NRE를 분산시킴
3. 장기: AI 컴파일러(XLA, TVM 등)와 공동 최적화(HW-SW Co-design)하여 아키텍처 진화 주기를 단축함

> 요약: 적응형 데이터 흐름, 칩렛 모듈화, HW-SW 공동 설계로 ASIC의 경직성을 완화함

## Ⅵ. 전망
- 발전 방향: TPU(052 참조)·NPU(053 참조) 등 ASIC 기반 AI 가속기가 데이터센터·단말 양쪽에서 확산 중임
- 기술사적 판단: LLM 추론 수요 폭증으로 TOPS/W 경쟁이 심화되며, ASIC이 대량 배포 구간의 핵심 선택지로 자리잡음
- 기술사 제언: 프로토타이핑은 FPGA(048 참조), 학습은 GPU(050 참조), 대량 추론은 ASIC으로 역할을 분담하는 이종 가속 전략을 권고함
