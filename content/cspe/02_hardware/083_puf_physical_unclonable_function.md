# 📖 【암기용】 개념 완전 이해

> 목적: PUF를 "물리적 편차가 있다"는 절만 알고 넘어가지 않게, CRP 인증 프로토콜의 실제 절차·오류 보정 수학·모델링 공격까지 끝까지 파고들어 이해하게 만든다. (083_puf.md가 PUF의 키 없는 철학과 Arbiter 레이싱 구조를 다뤘다면, 이 문서는 CRP를 이용한 인증 프로토콜 자체와 그 약점·보정 기법에 집중한다.)

## 한눈에
- **개요**: PUF는 하드웨어 보안 프리미티브(hardware security primitive)이자 물리적 인증 메커니즘으로, 반도체 공정 편차(process variation)를 challenge-response 쌍(CRP)으로 바꿔 디바이스 인증이나 암호키 유도에 쓴다.
- **왜 필요한가**: 인증 프로토콜은 "서버가 어떻게 상대가 진짜 그 칩인지 확인하는가"가 핵심인데, CRP는 그 확인을 물리적으로 재현 불가능한 값으로 수행하게 해준다. 다만 원시 응답은 노이즈가 섞여 있어 오류 보정 없이는 인증에 못 쓴다.
- **핵심 직관**: 지문 인식기가 "동일한 손가락이면 항상 같은 지문 이미지"를 요구하듯, PUF도 같은 challenge를 넣었을 때 항상 같은 response가 나와야 인증에 쓸 수 있다 — 그런데 실제로는 손가락이 젖거나 각도가 틀어지듯 온도·전압에 따라 몇 비트가 흔들린다. 그 흔들림을 수학적으로 다림질하는 것이 fuzzy extractor다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 하드웨어 보안 프리미티브 | 암호 알고리즘이 아니라, 그 위에 알고리즘이 올라타는 물리적 기반 부품 | 자물쇠 몸체(PUF)와 열쇠를 깎는 규칙(암호 알고리즘)의 관계 |
| Challenge (챌린지) | PUF 회로에 넣는 입력 벡터(예: 64비트 비트열) | 질문 카드 한 장 |
| Response (리스폰스) | 그 challenge에 대해 칩이 물리적 편차로 만들어내는 출력 | 그 카드에 대한 이 사람만의 답 |
| CRP (Challenge-Response Pair) | challenge와 response의 짝. 등록 시 서버가 미리 수집해 두는 검증 기준 | 본인 확인용으로 미리 받아둔 질문-답 세트 |
| Weak PUF | challenge 공간이 매우 좁아 CRP가 사실상 1~소수 개(예: SRAM 전체 셀 패턴 자체가 응답) — 외부에 노출하지 않고 내부 키 유도에만 사용 | 평생 안 바뀌는 지문 1장만 있는 사람 |
| Strong PUF | challenge 공간이 지수적으로 커서 CRP가 사실상 무한(예: Arbiter, 64비트 challenge → 2⁶⁴개) — 매번 새 CRP로 인증에 직접 사용 가능 | 질문을 아무리 많이 바꿔 물어도 매번 다른 고유한 답을 내놓는 사람 |
| Fuzzy Extractor | 노이즈 섞인 원시 response에서 안정된 키를 뽑아내는 두 단계 알고리즘(Gen/Rep) | 흔들린 사진에서 원본 얼굴을 복원하는 보정 필터 |
| Helper Data | Fuzzy Extractor가 등록 시 만들어 공개 저장해도 안전한 보조 정보 | 흔들린 사진을 원본으로 복원할 때 쓰는 보정값 메모(그 자체로는 원본 얼굴을 안 보여줌) |
| BER (Bit Error Rate) | 같은 challenge를 반복 인가했을 때 원시 response 비트가 등록값과 달라지는 비율 | 지문 스캐너가 같은 손가락인데도 오독하는 비율 |
| 모델링 공격 (Modeling Attack) | 다수의 CRP를 수집해 머신러닝으로 PUF의 입출력 함수를 근사·예측하는 공격 | 문제 유형을 충분히 많이 풀어보고 답 패턴을 외워 시험을 예측하는 것 |

## 깊이 이해

### CRP 공간의 크기로 Weak/Strong을 가른다
- challenge가 n비트면 이론상 CRP는 최대 2ⁿ개까지 존재할 수 있다. 예: 64비트 challenge → 2⁶⁴ ≈ 1.8×10¹⁹개. Arbiter PUF처럼 challenge 비트마다 신호 지연 경로가 달라지는 구조는 이 지수 공간을 실제로 활용해 매번 다른 CRP를 뽑아 쓸 수 있다 → Strong PUF.
- 반면 SRAM PUF는 "전원을 켰을 때 셀이 정착하는 값" 하나뿐이라 challenge라 부를 입력조차 없고, 응답은 사실상 고정된 비트열 1세트다 → Weak PUF. 그래서 SRAM PUF는 인증용 CRP 교환이 아니라 내부 암호키 유도(재현 가능한 시드)로만 쓴다.
- 판별 원리: "이 PUF에 서로 다른 challenge를 수천 개 넣었을 때 서로 다른 response가 나오는가?"가 Weak/Strong을 가르는 기준이다.

### 등록(Enrollment)과 인증(Authentication) — CRP를 소모품처럼 쓴다
- 등록 단계: 제조 직후 안전한 환경(공장)에서 서버가 무작위 challenge를 예로 1,000개 인가해 CRP 1,000쌍을 수집하고 서버 DB에 저장한다. 이 시점 이후 칩은 다시 열어보지 않아도 된다.
- 인증 단계: 매 인증 요청마다 DB에서 "아직 안 쓴" CRP 1개를 골라 challenge만 칩에 보낸다. 칩이 response를 재생성해 돌려보내면 서버가 등록값과 비교한다. 사용한 CRP는 즉시 폐기(재사용 금지)한다.
- 왜 재사용을 금지하는가: 같은 challenge를 반복 사용하면 공격자가 통신을 도청해 response를 그대로 재생(replay attack)할 수 있다. CRP 1,000쌍을 다 쓰면 재등록이 필요하므로, Strong PUF의 거대한 CRP 공간이 실전에서 "고갈되지 않는 인증 재료"로서 의미를 가진다.

### Fuzzy Extractor — 노이즈를 수치로 이해한다
- SRAM PUF 원시 response의 BER은 상온·정격 전압에서 통상 2~5% 수준이고, 온도·전압이 정격을 벗어나거나 칩이 노화되면 10~15%까지 올라간다. 즉 128비트 response 중 실온에서도 평균 3~6비트, 극한 환경에서는 13~19비트가 등록값과 달라질 수 있다.
- 이 오류를 그대로 키로 쓰면 AES 등 대칭키 암호는 1비트만 달라도 완전히 다른 결과를 내므로 무용지물이 된다. Fuzzy Extractor는 등록 시(Gen) 원시 response와 오류정정부호(예: 최대 10비트까지 정정 가능한 BCH(127,64,10))를 결합해 Helper Data를 만들어 공개 저장하고, 인증 시(Rep) 새로 뽑은 노이즈 섞인 response에 Helper Data를 결합해 원래의 128비트 키를 정확히 복원한다.
- Helper Data는 공개돼도 안전하도록 설계된다 — Helper Data만 봐서는 원본 response의 엔트로피를 거의 알아낼 수 없게(entropy loss 최소화) 부호를 고른다. 그래서 이름이 "helper"이지 "secret"이 아니다.

### 모델링 공격 — Strong PUF의 약점
- Arbiter PUF는 각 스테이지의 신호 지연 차이를 더하고 빼는 선형식으로 근사할 수 있는 구조라서, 공격자가 CRP를 수천~수만 개 수집해 로지스틱 회귀나 SVM 같은 머신러닝 모델을 학습시키면 실제 문헌에서 90%대 후반의 예측 정확도가 보고되었다(수집 CRP 수가 많을수록 정확도 상승).
- 대응책: 여러 개의 Arbiter 체인 출력을 XOR로 묶는 XOR Arbiter PUF는 비선형성을 높여 같은 정확도를 얻으려면 필요한 CRP 수와 계산량을 지수적으로 늘려 모델링을 어렵게 만든다. 다만 XOR 체인이 많아질수록 자체 BER도 함께 증가하는 트레이드오프가 있다.

### PUF와 디바이스 DNA의 관계 — 과정과 결과물
- PUF는 "물리적 편차를 읽어 노이즈 섞인 원시 response를 만들어내는 회로/과정"이고, 디바이스 DNA는 그 원시 response를 Fuzzy Extractor로 안정화해 얻은 "고정된 최종 식별자/키"라는 결과물이다. 같은 대상을 가리키는 것처럼 혼용되지만 엄밀히는 도구와 산출물의 관계다.

## 연결 개념
- 083_puf.md — 같은 PUF를 "저장하지 않는 철학"과 Arbiter 레이싱 구조 관점에서 다룬 자매 문서
- 디바이스 DNA — PUF+Fuzzy Extractor를 거쳐 안정화된 결과물
- HSM — PUF로 유도한 키를 관리하는 상위 키 관리 장치

- Secure Boot — PUF 유도 키로 부트로더 서명을 검증하는 응용
- XOR PUF, Lightweight PUF — 모델링 공격에 대응하는 비선형 강화 구조

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: PUF 답안은 원리(공정 편차), CRP 구조, fuzzy extractor 보정 과정, 디바이스 DNA와의 차이를 함께 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: PUF는 반도체 제조 공정 편차를 이용해 칩마다 고유하고 복제 불가능한 challenge-response 쌍을 생성하는 하드웨어 primitive이다.
> 2. **가치**: 키를 영구 저장하지 않고 필요 시 물리적 특성으로 재생성하므로 프로빙·리버스 엔지니어링에 의한 키 추출 위험을 낮춘다.
> 3. **판단 포인트**: PUF 원시 응답은 노이즈가 있어 fuzzy extractor·helper data로 오류를 보정해야 안정적인 키로 쓸 수 있다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 물리적 원리 이해 확인 | 공정 편차, SRAM/Ring Oscillator/Arbiter PUF 유형 | PUF를 암호화 알고리즘으로 서술 |
| CRP·오류 보정 구조 이해 확인 | challenge-response, fuzzy extractor, helper data | 원시 응답을 그대로 키로 사용한다고 서술 |
| 유사 개념과 구분 역량 확인 | 디바이스 DNA(고정 ID)와의 차이 | PUF와 디바이스 DNA를 동일 개념으로 혼용 |

> 요약: 이 문제는 PUF가 암호화 기법이 아니라 물리적 편차 기반 식별·키 유도 primitive임을 정확히 구분해 설명해야 한다.

## Ⅰ. 개요 및 필요성

- 개요: 반도체 제조 공정 편차로 칩마다 고유한 challenge-response를 생성하는 하드웨어 보안 primitive
- 배경: 영구 메모리에 저장된 키는 물리 프로빙·리버스 엔지니어링으로 추출될 위험이 있음
- 필요성: 저장하지 않고 필요 시 재생성하는 키 유도 방식이 위조 방지·디바이스 인증에 요구됨

---

## Ⅱ. 구조 및 구성요소

```text
Challenge 입력 -> PUF 회로(SRAM/Ring Oscillator/Arbiter)
  -> 공정 편차 기반 원시 Response 생성
  -> Fuzzy Extractor + Helper Data
  -> 안정화된 암호 키 출력
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| SRAM PUF | 전원 인가 시 셀 초기값 편향 이용 | 별도 회로 추가 없이 기존 SRAM 재활용 가능 |
| Ring Oscillator PUF | 발진기 간 주파수 편차 비교 | 온도 변화에 상대적으로 강건 |
| Arbiter PUF | 두 신호 경로 지연 차이 비교 | 머신러닝 모델링 공격에 취약점 보고됨 |
| Fuzzy Extractor | 원시 응답의 노이즈 비트를 보정 | Helper Data는 공개해도 키 복원 불가 설계 |
| CRP 데이터베이스 | 인증 시 사용할 challenge-response 목록 | 발급 시 제한된 수량만 사전 등록 |

> 요약: PUF는 물리적 편차로 원시 응답을 만들고, fuzzy extractor로 노이즈를 보정해 안정적 키로 변환한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
등록(Enrollment) 단계: Challenge 다수 인가 -> Response 수집 -> CRP DB 저장
인증(Authentication) 단계: 동일 Challenge 인가
  -> 칩이 Response 재생성 -> Helper Data로 오류 보정
  -> 저장된 Response와 비교 -> 인증 성공/실패 판정
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 제조 후 등록 단계에서 challenge별 response 수집 | CRP 수량, 수집 환경(온도·전압) |
| 2 | 인증 요청 시 동일 challenge 인가 | challenge 재사용 방지 정책 |
| 3 | 원시 response에 fuzzy extractor 적용 | bit error rate 보정 범위 |
| 4 | 보정된 response와 등록값 비교 판정 | 오인증률(false accept), 오거부율(false reject) |

> 요약: PUF 인증은 등록 시 저장한 CRP와 인증 시 재생성한 response를 오류 보정 후 비교하는 흐름이다.

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 장점 | 키를 영구 저장하지 않아 물리적 추출 위험이 낮음 | 칩 파괴·프로빙 공격에도 응답 재현 어려움 |
| 한계 | 온도·전압·노화에 따라 원시 응답이 흔들려 오류 보정 오버헤드 발생 | fuzzy extractor 설계 복잡도 |
| 비교 포인트 | PUF(물리적 노이즈 기반 응답) vs 디바이스 DNA(공장 고정 프로그래밍 ID) | 키 재생성이 필요하면 PUF, 고정 식별자면 디바이스 DNA |

> 요약: PUF는 노이즈가 있는 대신 저장 없이 재생성 가능하고, 디바이스 DNA는 고정 값이라 재생성 개념이 없다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 영구 메모리(NVM, Fuse)에 키 저장 | 물리적 편차 기반 즉시 재생성 | 물리 공격 위협이 크면 PUF 선택 |
| 비용/성능 | 별도 저장 회로 필요 | SRAM PUF는 기존 회로 재활용 가능 | 저비용 위조 방지가 목표면 SRAM PUF 우선 |
| 운영/위험 | 저장 키 유출 시 전체 폐기 | fuzzy extractor 설계 오류 시 인증 실패율 증가 | 오인증·오거부율 목표치 사전 정의 필요 |

> 요약: 저장 키 유출 위험이 클수록 PUF를 선택하되, 오류 보정 설계 품질이 실효성을 좌우한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 모델링 공격 | Arbiter PUF의 CRP 다수 수집 후 머신러닝 예측 | Strong PUF 대신 CRP 노출 제한, XOR PUF 구조 | 모델링 공격 성공률 |
| 응답 불안정 | 온도·전압·노화로 bit error 증가 | fuzzy extractor 오류정정부호(BCH 등) 강화 | bit error rate 목표치 |
| CRP 재사용 | 동일 challenge 반복 노출 | challenge 일회성 또는 제한 사용 정책 | challenge 재사용 탐지 로그 |

> 요약: PUF 리스크는 CRP 노출에 의한 모델링 공격과 환경 변화에 의한 응답 불안정에서 발생한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 인증 정확도 | 오인증률·오거부율 사전 목표치 이내 | CRP 검증 테스트셋 |
| 응답 안정성 | 온도·전압 변화 시 bit error rate 허용치 이내 | 환경 스트레스 테스트 |
| 모델링 내성 | CRP 노출량 제한 정책 준수 | CRP 사용 로그 감사 |

> 요약: 도입 효과는 인증 정확도, 응답 안정성, 모델링 공격 내성으로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 단기: 디바이스 인증·라이선스 위조 방지가 필요한 칩에 SRAM PUF 또는 Ring Oscillator PUF를 적용함
2. 중기: fuzzy extractor와 helper data 설계를 검증해 환경 변화에도 인증 성공률을 확보함
3. 장기: CRP 노출을 제한하는 정책과 XOR PUF 등 모델링 공격 내성 구조를 함께 적용함

**결론 (2줄):**
- 기술사 판단: 키 저장 자체를 없애야 하는 고위협 환경은 PUF, 단순 고정 식별이 목적이면 디바이스 DNA를 선택함
- 향후 방향: IoT·엣지 디바이스 확산에 따라 저비용 SRAM PUF 기반 디바이스 인증이 확대되는 방향으로 발전함
