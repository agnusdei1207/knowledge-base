## Ⅰ. 개요
- **정의**: CPU·메모리·I/O 등 시스템 구성요소를 단일 칩에 집적하는 설계 방식임
- **배경/필요성**: 다수 칩 조합은 보드 면적·전력·신호 지연을 증가시키므로, 단일 칩 통합으로 소형화·저전력·고속화를 달성할 필요가 있음
- **비유**: 여러 가전을 한 건물에 합쳐 놓은 복합 시설과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| SoC 구조와 설계 흐름 이해 | IP 재사용, 온칩 버스, 검증 방법 | HW/SW 공동설계(077 참조)와 연계하여 설명할 것 |

> 요약: 시스템 전체를 단일 칩에 집적하여 면적·전력·성능을 동시에 최적화하는 설계임

## Ⅱ. 구성요소
```text
+--------+--------+--------+--------+
| CPU    | GPU    | DSP    | NPU    |
+--------+--------+--------+--------+
         |  On-Chip Bus (AMBA)  |
+--------+--------+--------+--------+
| SRAM   | DMA    | I/O    | PLL    |
+--------+--------+--------+--------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| IP Core | 사전 검증된 재사용 가능 설계 블록(CPU, GPU 등)임 | 규격화된 레고 블록 |
| On-Chip Bus | IP 간 데이터 전송 경로(079 참조)임 | 건물 내부 복도 |
| 메모리 서브시스템 | SRAM·캐시·DMA로 구성된 온칩 데이터 저장/이동 계층임 | 건물 내 창고와 엘리베이터 |

> 요약: IP Core, 온칩 버스, 메모리 서브시스템이 SoC의 3대 구성축임

## Ⅲ. 절차
```text
요구정의 --> IP선정/설계 --> 통합/버스연결 --> 검증/제조
```
- 1단계: 시스템 사양을 정의하고 HW/SW 분할을 수행함(077 참조)
- 2단계: 자체 설계 또는 라이선스 IP를 선정하여 RTL을 확보함
- 3단계: 온칩 버스로 IP를 연결하고 클럭·리셋 트리를 구성함
- 4단계: 시뮬레이션·FPGA 에뮬레이션·DFT 삽입 후 파운드리에 테이프아웃함

> 요약: 사양정의-IP확보-버스통합-검증/제조의 4단계로 SoC를 구현함

## Ⅳ. 문제점
- IP 호환성 부족: 서로 다른 벤더 IP의 인터페이스·타이밍 규격이 불일치하여 통합 지연이 발생함
- 검증 비용 급증: 게이트 수 증가에 따라 시뮬레이션 시간이 기하급수적으로 늘어남
- 열 집적 문제: 단일 칩에 고성능 IP가 밀집되어 열 밀도가 한계를 초과함

> 요약: IP 호환성, 검증 비용, 열 밀도가 SoC 설계의 주요 병목임

## Ⅴ. 개선방안
1. 단기: 표준 인터페이스(AMBA AXI 등)와 IP-XACT 메타데이터로 IP 호환성을 확보함
2. 중기: FPGA 에뮬레이션·형식 검증 병행으로 검증 커버리지를 높이면서 시간을 단축함
3. 장기: 칩렛(Chiplet) 기반 이기종 집적으로 열 밀도를 분산하고 수율을 개선함

> 요약: 표준 인터페이스, 에뮬레이션 검증, 칩렛 아키텍처로 SoC 한계를 극복함

## Ⅵ. 전망
- 발전 방향: 칩렛·UCIe 표준 기반 모듈형 SoC가 확산될 것임
- 기술사적 판단: AI·자율주행 등 도메인 특화 SoC 수요가 범용 칩을 대체하는 추세임
- 기술사 제언: IP 재사용 전략과 플랫폼 기반 설계 방법론 확립이 필요함
