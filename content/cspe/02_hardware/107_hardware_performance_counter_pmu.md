## 미리 알고가기

- PMU는 CPU 내부 이벤트를 계측하는 하드웨어 블록임
- IPC는 클럭 한 번당 처리한 명령 수이고, CPI는 명령 하나당 필요한 클럭 수임
- 캐시 미스·분기 예측 실패·TLB 미스는 병목 원인 분석에 사용하는 하드웨어 이벤트임
- 샘플링은 카운터가 설정한 값에 도달할 때만 실행 상태를 기록해 계측 오버헤드를 줄이는 방식임
- 오버플로는 카운터 값이 설정한 임계값을 넘어 인터럽트를 발생시키는 상태임

## 작성 근거(검토용)

- PMU는 이벤트 원천, 카운터 선택, 샘플링, IPC·CPI·미스율을 핵심 축으로 설명함
- 비교표는 소프트웨어 프로파일링과 PMU의 관측 대상, 위치 식별, 하드웨어 원인, 제약을 대비함
- 실무 판단은 캐시 미스율·CPI와 실행 간 편차·측정 오버헤드로 검증함

## Ⅰ. 개요

- **정의/개념**: 하드웨어 성능 카운터와 PMU는 CPU의 사이클·명령·캐시 미스·분기 예측 실패를 계측해 마이크로아키텍처 병목 원인을 분석하는 기능임
- **배경/필요성**: 총 실행 시간만으로 구분할 수 없는 파이프라인·캐시·분기 병목을 찾기 위해 CPU 내부 이벤트 계측이 필요함

### 쉽게 이해하기 (학습용)
- 자동차가 목적지에 늦게 도착한 이유를 계기판 속도만으로는 알 수 없듯, 엔진 회전수·연료 소모량 같은 세부 계기(PMU)를 봐야 무엇이 늦어졌는지 알 수 있음

## Ⅱ. 특징

- 함수별 실행 시간을 보여 주는 소프트웨어 프로파일러와 달리 CPU 내부 이벤트 횟수를 제공함
- 샘플링 주기마다 카운터 오버플로를 기록해 모든 이벤트를 추적하는 비용을 줄임
- CPU 세대별 이벤트 의미와 정확도를 이해해야 해석 오류를 줄일 수 있음
- 단일 카운터만으로 병목을 단정하지 않고 IPC·CPI·미스율을 함께 해석함

### 쉽게 이해하기 (학습용)
- 매초 걸음 수를 세는 만보기(소프트웨어 프로파일러)와 달리, 숨이 찬 횟수·발을 헛디딘 횟수까지 세는 정밀 센서(PMU)와 같으며, 기종마다 센서 위치가 달라 해석에 주의가 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 소프트웨어 프로파일링 | PMU 계측 |
|:---|:---|:---|
| 관측 결과 | 함수·호출 경로별 시간 분포를 보여 줌 | 사이클·캐시·분기·TLB 이벤트 비율을 보여 줌 |
| 제약 | 샘플 주기와 계측 코드가 실행 흐름에 영향을 줌 | CPU 세대별 이벤트 정의와 동시 카운터 수가 다름 |
| 주요 활용 | 함수·호출 경로별 실행 시간 분포를 확인함 | 명령·사이클·캐시·분기 이벤트로 병목 가설을 검증함 |

> 요약: 소프트웨어 프로파일링은 느린 코드 위치를, PMU는 파이프라인·캐시·분기·TLB 병목 근거를 제공함.

### 쉽게 이해하기 (학습용)
- 소프트웨어 프로파일링은 어느 구간에서 늦었는지 구간 기록만 보여주고, PMU는 그 구간에서 숨이 왜 찼는지(캐시 미스, 예측 실패) 원인까지 알려주는 정밀 센서에 가까움

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 이벤트 원천 | 파이프라인·캐시·분기 예측기에서 계측 대상 이벤트를 생성함 |
| PMU 제어기 | 계측할 이벤트와 카운터를 지정하고 오버플로 샘플링을 제어함 |
| 하드웨어 카운터 | 선택된 이벤트 횟수와 사이클을 누적해 정량 분석 데이터를 제공함 |
| 분석 도구 | `perf` 같은 도구가 카운터를 수집하고 IPC·미스율로 병목 가설을 검증함 |

> 요약: 이벤트 원천의 발생 횟수를 PMU 카운터가 누적하고 분석 도구가 IPC·CPI·미스율로 변환함.

### 쉽게 이해하기 (학습용)
- 여러 부서(파이프라인·캐시·분기 예측기)에서 발생한 사건을 계기(하드웨어 카운터)가 세고, 관제실 담당자(PMU 제어기)가 어떤 계기를 켤지 정하며, 분석가(분석 도구)가 그 숫자를 비율로 풀어 읽음

## Ⅴ. 원리 및 절차 흐름도

1. **이벤트 선정**: 사이클·명령·미스 계열 중 분석 목표에 맞는 이벤트를 고름
2. **카운터 설정**: 샘플링 주기와 코어 바인딩과 권한 범위를 정함
3. **실행·수집**: 워크로드를 실행하며 카운터 값과 샘플 스택을 수집함
4. **비율 해석**: IPC·CPI·미스율을 계산해 병목 원인을 판단함

> 요약: 분석 가설에 맞는 이벤트와 샘플링 조건을 고정해 수집하고 IPC·CPI·미스율로 병목을 검증함.

### 쉽게 이해하기 (학습용)
- 무엇을 잴지 정하고(이벤트 선정), 측정 간격과 담당 구간을 정한 뒤(카운터 설정), 실제로 뛰면서 기록하고(실행·수집), 마지막에 기록을 비율로 계산해 원인을 짚어내는(비율 해석) 순서와 같음

## Ⅵ. 실무 사례

1. API 서버는 CPU 세대별 PMU 이벤트 매핑을 검증하고 캐시 미스율·CPI를 확인함
2. 운영 서버는 CPU 고정과 이벤트 분할 수집을 적용하고 실행 간 편차·측정 오버헤드를 확인함

### 쉽게 이해하기 (학습용)
- API 서버는 기종별로 계기판 눈금이 다른지부터 확인하고, 운영 서버는 같은 자리에서 재도록 좌석을 고정하고 측정 도구 자체가 부담을 주지 않는지도 함께 살핌

## Ⅶ. 결론

- PMU는 함수별 실행 시간만 보여주는 소프트웨어 프로파일러와 달리 사이클·캐시 미스·분기 예측 실패 같은 CPU 내부 이벤트를 계측해 마이크로아키텍처 병목 원인을 찾음
- CPU 세대마다 이벤트 정의와 정확도가 달라 단일 카운터로 병목을 단정할 수 없으므로, 코어·샘플링 조건을 고정하고 IPC·CPI·미스율을 함께 해석해야 함

### 쉽게 이해하기 (학습용)
- 계기판 하나만 보고 차 상태를 단정하지 않듯, PMU 수치도 기종·측정 조건을 맞추고 여러 지표를 같이 봐야 진짜 원인을 알 수 있음
