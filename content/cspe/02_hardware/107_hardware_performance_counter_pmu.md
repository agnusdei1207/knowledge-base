## 미리 알고가기

- PMU는 CPU 내부 이벤트를 계측하는 하드웨어 블록임
- IPC는 클럭 한 번당 처리한 명령 수이고, CPI는 명령 하나당 필요한 클럭 수임
- cache miss와 branch miss와 TLB miss는 병목 원인 분석에 자주 쓰는 이벤트임

## Ⅰ. 개요

- **정의/개념**: 하드웨어 성능 카운터와 PMU는 CPU 내부에서 발생하는 cycle과 instruction과 cache miss와 branch miss 같은 이벤트를 낮은 오버헤드로 측정해 마이크로아키텍처 병목 원인을 분석하는 계측 기능임
- **배경/필요성**: wall-clock 시간만으로는 코드가 왜 느린지 알기 어려우므로, 성능 최적화와 용량 기준선 수립에는 CPU 내부 이벤트를 직접 관측하는 수단이 필요함

## Ⅱ. 특징

- 소프트웨어 프로파일러보다 하드웨어 병목 원인을 더 직접적으로 보여줌
- sampling 기반으로 운영 환경에서도 비교적 낮은 오버헤드로 사용할 수 있음
- CPU 세대별 이벤트 의미와 정확도를 이해해야 해석 오류를 줄일 수 있음
- 단일 카운터보다 IPC와 CPI와 miss rate를 함께 읽어야 의미가 생김

## Ⅲ. 종류 및 비교

| 판단 기준 | 소프트웨어 프로파일링 | PMU 계측 |
|:---|:---|:---|
| 관측 대상 | 함수 시간과 호출 경로 중심으로 보여 줌 | cycle과 cache와 branch와 TLB 이벤트를 직접 보여 줌 |
| 강점 | 코드 위치를 찾기 쉬움 | 병목 원인을 더 정밀하게 가늠할 수 있음 |
| 한계 | 하드웨어 원인 해석이 약함 | 이벤트 의미와 카운터 수 제한을 이해해야 함 |
| 주 용도 | 최적화 출발점을 찾는 데 적합함 | 가설 검증과 기준선 수립에 적합함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 이벤트 원천 | pipeline과 cache와 branch predictor에서 계측 대상 이벤트를 생성함 |
| PMU 제어기 | 어떤 이벤트를 어떤 카운터로 셀지 정하고 overflow sampling을 제어함 |
| 하드웨어 카운터 | 선택된 이벤트 횟수와 cycle을 누적해 정량 분석의 기반 데이터를 제공함 |
| 분석 도구 | `perf` 같은 도구가 카운터를 수집하고 IPC와 miss rate 해석으로 병목을 드러냄 |

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 이벤트 선정    | --> | 카운터 설정    | --> | 실행·수집      | --> | 비율 해석      |
+-------------+     +-------------+     +-------------+     +-------------+
```

## Ⅴ. 원리 및 절차 흐름도

1. **이벤트 선정**: cycle과 instruction과 miss 계열 중 분석 목표에 맞는 이벤트를 고름
2. **카운터 설정**: sampling 주기와 코어 바인딩과 권한 범위를 정함
3. **실행·수집**: workload를 돌리며 카운터 값과 샘플 스택을 수집함
4. **비율 해석**: IPC와 CPI와 miss rate를 계산해 병목 원인을 판단함

## Ⅵ. 실무 적용 및 유의점

1. 서비스 지연 분석은 PMU가 병목 원인을 직접 보여 주지만 CPU 세대별 이벤트 정의 차이를 무시하면 해석이 어긋나므로 벤더 이벤트 가이드와 기준선을 함께 관리하고 이벤트 매핑 정확도와 캐시 미스율과 CPI로 확인함
2. 운영 환경 측정은 카운터 수 제한과 스케줄링 이동 때문에 잡음이 커질 수 있으므로 CPU 고정과 반복 실행과 이벤트 분할 수집을 함께 적용하고 실행 간 편차와 카운터 보정 오차와 기준선 변동폭으로 확인함

## Ⅶ. 결론

PMU는 성능 수치를 나열하는 도구가 아니라 병목 원인을 검증하는 도구이므로, 이벤트 선택과 측정 조건 통제가 해석 품질을 좌우함.
