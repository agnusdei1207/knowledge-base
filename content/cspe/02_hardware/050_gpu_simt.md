# 📖 【암기용】 개념 완전 이해
> 목적: GPU의 SIMT 실행 모델을 처음 봐도 SIMD와 무엇이 다른지, 분기 발산이 왜 성능에 치명적인지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: GPU가 스레드 그룹(warp·wavefront)에 동일 명령어를 lockstep으로 실행하되 스레드마다 다른 데이터를 처리하는 병렬 실행 모델
- **왜 필요한가**: AI·그래픽 연산은 동일 연산을 대량의 독립 데이터에 반복 적용하는 데이터 병렬성이 크다. SIMT는 프로그래머가 스칼라 코드 하나만 작성해도 하드웨어가 대규모 병렬 실행으로 확장해준다.
- **핵심 직관**: 한 지휘자의 구령에 맞춰 수십 명의 무용수가 동시에 같은 동작을 하되 각자 다른 소품(데이터)을 다루는 군무와 같다.

## 깊이 이해
- **배경·문제의식**: SIMD(Single Instruction Multiple Data)는 하나의 명령어가 고정 폭 벡터 레지스터(예: 256비트에 float 8개)를 명시적으로 동시 처리하는 모델이라 프로그래머·컴파일러가 벡터 폭을 인지해야 한다.
- **작동 원리 — SIMT(Single Instruction Multiple Thread)**: NVIDIA가 CUDA에서 도입한 모델로, 프로그래머는 스칼라 스레드 하나의 코드(커널)만 작성한다.
- **작동 원리 — SIMT**: 하드웨어가 이 스칼라 스레드들을 NVIDIA 기준 warp(32개 스레드), AMD 기준 wavefront(64개 스레드) 단위로 묶어 동일 명령어를 lockstep으로 실행한다.
- **SIMD와의 차이**: SIMD는 벡터 폭이 명시적이며 컴파일러가 벡터화를 수행하지만, SIMT는 벡터 폭(warp size)이 하드웨어 내부에 숨겨져 있고 프로그래머는 스칼라 스레드 코드만 작성한다.
- **분기 발산(Branch Divergence)**: warp 내 스레드들이 조건문에서 서로 다른 경로를 타면, 하드웨어는 각 경로를 순차적으로 실행하고 해당 경로에 속하지 않는 스레드는 마스킹(비활성화)한다.
- **분기 발산**: 두 경로가 모두 실행되므로 각 경로 실행 시간의 합만큼 시간이 걸려 사실상 직렬화된다.
- **GPU 아키텍처 계층**: SM(Streaming Multiprocessor, NVIDIA) 또는 CU(Compute Unit, AMD)가 다수의 CUDA 코어·스트림 프로세서와 warp scheduler를 포함한다.
- **GPU 아키텍처 계층**: 각 스레드는 자체 레지스터를 가지며, 같은 SM 내 스레드들은 shared memory·L1 캐시를 공유하고, 여러 SM은 L2 캐시를 공유하며 최종적으로 HBM·GDDR 글로벌 메모리에 접근한다.
- **비유**: SIMD는 한 사람이 양손에 정확히 8개씩 물건을 쥐고 동시에 같은 동작을 하는 것(고정 폭 벡터)이고, SIMT는 32명이 각자 하나씩 물건을 들고 지휘자의 구령에 맞춰 동일 동작을 수행하는 것(스칼라 코드처럼 보이지만 집단 lockstep 실행)이다.
- **구체 예시**: `if (threadIdx.x % 2 == 0)` 같은 조건 분기가 warp 내에서 발산하면, 짝수 스레드 경로 실행과 홀수 스레드 경로 실행이 순차적으로 이뤄져 분기 없는 코드 대비 최대 2배의 실행 시간이 걸릴 수 있다.
- **흔한 오해·주의점**: "SIMT는 SIMD와 동일하다"는 틀렸다. SIMT는 스레드 단위의 독립적 제어 흐름을 갖는 것처럼 프로그래밍되지만 하드웨어가 warp 단위로 마스킹·직렬화해 벡터 실행을 흉내 내는 것이고, SIMD는 애초에 벡터 레지스터 자체가 명시적이다.
- **흔한 오해·주의점**: "GPU 코어 수가 많으면 무조건 처리량이 증가한다"는 틀렸다. 분기 발산, 메모리 대역폭 병목, warp occupancy(SM당 활성 warp 비율)가 실제 성능을 좌우한다.

## 연결 개념
- CUDA 병렬 컴퓨팅 — SIMT 실행 모델을 프로그래밍하는 NVIDIA의 소프트웨어 플랫폼
- Flynn's Taxonomy(SIMD·MIMD) — GPU SIMT가 SIMD와 어떻게 다른 실행 모델인지 분류하는 상위 체계
- TPU·NPU — GPU와 다른 방식(systolic array 등)으로 AI 연산을 가속하는 대안 아키텍처

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: GPU SIMT는 warp·wavefront 단위로 묶인 스레드 그룹이 동일 명령어를 lockstep으로 실행하되 스레드별로 다른 데이터를 처리하는 실행 모델이다.
> 2. **가치**: 스칼라 스레드 코드로 프로그래밍하면서도 하드웨어가 대규모 데이터 병렬성을 자동으로 활용해 AI·그래픽 연산 처리량을 극대화한다.
> 3. **판단 포인트**: SIMD와 달리 벡터 폭(warp size)이 하드웨어에 숨겨져 있고, 분기 발산 시 warp 내 경로가 순차 직렬화되므로 워크로드의 분기 패턴과 warp occupancy를 함께 고려해야 한다.

## 출제 의도 및 답안 포인트

|:---|:---|:---|
| SIMT 실행 모델 이해 확인 | warp/wavefront 단위 lockstep 실행 원리 | SIMT를 SIMD와 동일한 개념으로 서술 |
| 분기 발산 성능 영향 판단 확인 | 조건 분기 시 경로별 순차 실행과 스레드 마스킹 | 분기 발산이 성능에 미치는 영향 누락 |
| GPU 메모리 계층 이해 확인 | 레지스터-shared memory/L1-L2-HBM/GDDR 계층 구조 | 코어 수만으로 성능을 단정 |

> 요약: 이 문제는 GPU 코어 수 나열이 아니라 SIMT 실행 원리와 분기 발산·메모리 계층이 성능에 미치는 영향을 보여야 한다.


## Ⅰ. 개요 및 필요성
- 개요: warp/wavefront 단위 스레드 그룹이 동일 명령어를 lockstep 실행하되 스레드별로 다른 데이터를 처리하는 모델
- 배경: SIMD는 벡터 폭이 명시적이라 프로그래밍이 번거로웠고, 대규모 데이터 병렬 워크로드에는 스칼라 코드 기반 병렬화가 필요했음
- 필요성: AI·그래픽 연산의 데이터 병렬성을 스칼라 코드로 단순하게 표현하면서 하드웨어가 대규모 병렬 실행으로 확장할 방법이 필요함


## Ⅱ. 구조 및 구성요소
```text
Kernel(Scalar Thread Code) -> Thread Grouping
  -> Warp(32, NVIDIA) / Wavefront(64, AMD)
  -> SM/CU: Warp Scheduler -> CUDA Core/Stream Processor
  -> Register(Thread) -> Shared Memory/L1(SM 내 공유)
  -> L2 Cache(SM 간 공유) -> HBM/GDDR(Global Memory)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Warp/Wavefront | lockstep 실행 단위 | NVIDIA 32스레드, AMD 64스레드 |
| Warp Scheduler | 다음 실행할 warp 선택 | 지연 은닉을 위한 다중 warp 스위칭 |
| Register File | 스레드별 개별 레지스터 | 스레드 문맥 저장 |
| Shared Memory/L1 | SM 내 스레드 간 공유 저장소 | 저지연 블록 내 데이터 공유 |
| HBM/GDDR | 전역 메모리 | 대역폭 병목 발생 지점 |

> 요약: GPU는 스칼라 커널 코드를 warp 단위로 묶어 SM의 warp scheduler와 메모리 계층을 통해 대규모 병렬 실행을 수행한다.


## Ⅲ. 동작원리 및 흐름도
```text
커널 실행 요청 -> 스레드를 Warp/Wavefront로 그룹화
  -> Warp Scheduler가 실행할 Warp 선택
  -> 동일 명령어를 Warp 내 전 스레드에 lockstep 발행
  -> 분기 발생 시: 경로별 스레드 마스킹 -> 순차 실행
  -> 메모리 접근(Shared/L1 -> L2 -> HBM) -> 결과 저장
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 커널의 스레드를 warp/wavefront 단위로 그룹화 | warp occupancy |
| 2 | warp scheduler가 실행 가능한 warp 선택 | 지연 은닉 효율 |
| 3 | 동일 명령어를 warp 내 스레드에 lockstep 실행 | 분기 발산 여부 |
| 4 | 메모리 계층을 거쳐 결과 저장 | 대역폭 활용률 |

> 요약: GPU는 warp 단위로 명령어를 lockstep 실행하되 분기 발생 시 경로별로 순차 처리하며 메모리 계층을 통해 결과를 저장한다.


## Ⅳ. 특징
| 구분 | SIMD | SIMT(GPU) |
|:---|:---|:---|
| 프로그래밍 모델 | 명시적 벡터 폭 인지 필요 | 스칼라 스레드 코드 작성 |
| 실행 단위 | 고정 폭 벡터 레지스터 | warp/wavefront(32/64 스레드) |
| 분기 처리 | 컴파일러가 벡터 마스크 생성 | 하드웨어가 warp 내 스레드 마스킹·순차 실행 |
| 성능 결정 요인 | 벡터화 가능 비율 | warp occupancy, 분기 발산, 메모리 대역폭 |

> 요약: SIMD는 벡터 폭을 프로그래머가 관리하고, SIMT는 하드웨어가 스칼라 코드를 warp 단위로 묶어 벡터처럼 실행한다.


## Ⅴ. 심화 비교 및 적용 판단
| 비교 축 | SIMD(CPU 벡터 유닛) | SIMT(GPU) | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 고정 폭 벡터 레지스터, 명시적 벡터화 | warp 단위 대규모 스레드 병렬 | 대규모 데이터 병렬성이면 GPU SIMT |
| 비용/성능 | 소규모 벡터 연산에 효율적 | 대량 스레드로 처리량 극대화, 분기 발산에 취약 | 분기 많은 워크로드는 CPU SIMD 병행 고려 |
| 운영/위험 | 벡터화 실패 시 성능 저하 | 분기 발산, 메모리 대역폭 병목 | occupancy·분기 패턴 프로파일링 필요 |

> 요약: 분기가 적고 데이터 병렬성이 큰 대량 연산은 GPU SIMT, 분기가 많거나 소규모 벡터 연산은 CPU SIMD가 유리하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 분기 발산 성능 저하 | warp 내 조건 분기로 경로 직렬화 | 분기 없는 알고리즘 재구성, warp 정렬 | warp 실행 효율(SM efficiency) |
| 낮은 warp occupancy | 레지스터·shared memory 과다 사용 | 레지스터 사용량 최적화, 블록 크기 조정 | SM당 활성 warp 비율 |
| 메모리 대역폭 병목 | HBM/GDDR 접근 집중 | 메모리 코얼레싱, 캐시 활용 최적화 | 메모리 대역폭 활용률 |

> 요약: GPU SIMT 리스크는 분기 발산과 낮은 occupancy이며 SM efficiency와 활성 warp 비율로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| SM 효율 | 목표 SM efficiency 이상 | 프로파일러(Nsight 등) |
| Warp Occupancy | SM당 활성 warp 비율 목표치 이상 | 프로파일러 지표 |
| 메모리 대역폭 활용률 | 이론 대역폭 대비 목표 비율 이상 | 메모리 벤치마크 |

> 요약: 도입 성공 여부는 SM 효율, warp occupancy, 메모리 대역폭 활용률로 판단한다.


## Ⅵ. 실무 적용 및 결론
**적용 방안 3개:**
1. 대량 데이터 병렬 연산(행렬곱, 컨볼루션)은 GPU SIMT로 처리해 처리량을 극대화함
2. 조건 분기가 많은 코드는 알고리즘을 재구성하거나 warp 정렬로 분기 발산을 최소화함
3. 프로파일링 도구로 warp occupancy와 메모리 대역폭 활용률을 측정해 커널 최적화를 반복함

**결론 (2줄):**
- 기술사 판단: 분기가 적고 데이터 병렬성이 큰 워크로드는 GPU SIMT, 분기가 많거나 소규모 연산은 CPU SIMD·전용 가속기를 선택함
- 향후 방향: Tensor Core·행렬 연산 전용 유닛과 결합해 SIMT의 범용성과 ASIC 수준 행렬 연산 효율을 함께 확보하는 방향으로 GPU 아키텍처가 발전하고 있음
