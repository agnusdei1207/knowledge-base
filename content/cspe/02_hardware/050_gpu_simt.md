## 미리 알고가기

- GPU는 많은 경량 코어로 처리량 중심 병렬 연산을 수행하는 프로세서임
- SIMT는 단일 명령을 다수 스레드가 각자 데이터에 적용하는 실행 모델임
- 워프(Warp)는 함께 명령을 실행하는 스레드 묶음이며 분기 발산과 메모리 병합 접근이 실행 효율을 좌우함
- 텐서 코어(Tensor Core): 행렬 곱셈·누산을 전용 회로로 가속하는 GPU 연산 유닛임
- 병합 접근(Coalesced Access): 인접 스레드가 연속 주소에 접근해 하나의 메모리 트랜잭션으로 처리되는 방식임
- 레인(Lane): SIMD 명령에서 각 데이터 요소를 처리하는 개별 연산 경로임

## 작성 근거(검토용)

- GPU SIMT는 워프, 분기 발산, 메모리 병합 접근을 핵심 용어로 반영함
- 비교표는 CPU 스레드, CPU SIMD, GPU SIMT의 실행 단위와 분기·지연 처리 차이를 대비함
- 실무 판단은 워프 실행 효율, 분기 발산률, 전역 메모리 적재 효율로 구체화함

## Ⅰ. 개요

- **정의/개념**: GPU 아키텍처와 SIMT 모델은 여러 스레드를 워프로 묶어 같은 명령을 실행하고, 실행 가능한 워프를 교체해 데이터 병렬 연산의 처리량을 높이는 구조임
- **배경/필요성**: 그래픽 렌더링과 AI 학습처럼 동일 연산을 방대한 데이터에 반복 적용하는 작업은 CPU보다 대량 병렬 실행 구조가 필요함

### 쉽게 이해하기 (학습용)
- 같은 동작을 한 번에 여러 명이 조를 짜서 함께 수행하고, 한 조가 쉬는 동안 다른 조를 투입하는 것과 같음

## Ⅱ. 특징

- 개별 코어 지연보다 전체 처리량 중심으로 설계됨
- 워프 스케줄링으로 메모리 대기 중 다른 워프를 실행함
- 분기 발산과 비연속 메모리 접근이 성능 저하의 대표 원인임
- AI 연산에서는 텐서 코어 처리량과 HBM 대역폭이 성능 상한을 좌우함

### 쉽게 이해하기 (학습용)
- 한 사람의 속도보다 줄 전체의 진행 속도가 중요하고, 조원들이 서로 다른 길로 흩어지면(분기 발산) 다시 모일 때까지 기다려야 하는 것과 같음

## Ⅲ. 종류 및 비교

| 판단 기준 | CPU 스레드 | CPU SIMD | GPU SIMT |
|:---|:---|:---|:---|
| 명령 실행 단위 | 개별 코어의 스레드 | 한 명령의 벡터 레인 | 한 명령을 실행하는 워프 |
| 분기 처리 | 스레드별 제어 흐름 | 마스크로 레인 선택 | 워프 내 분기 경로를 나누어 실행 |
| 지연 은닉 | 캐시·비순차 실행 | 벡터 파이프라인 | 실행 가능한 워프로 교체 |

> 요약: GPU SIMT는 워프 단위로 같은 명령을 실행하고 준비된 워프로 교체해 메모리 지연을 숨김.

### 쉽게 이해하기 (학습용)
- 한 명씩 따로 일하기(CPU 스레드), 한 사람이 여러 도구를 한 번에 휘두르기(CPU SIMD), 여러 명이 조를 짜서 같은 동작을 동시에 하기(GPU SIMT)의 차이와 같음

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 스트리밍 멀티프로세서(SM) | 워프 스케줄러·연산 코어·공유 메모리를 묶은 실행 단위임 |
| 워프 스케줄러 | 실행 가능한 워프를 선택해 메모리 대기 중 다른 워프를 실행함 |
| 레지스터·공유 메모리 | 스레드 상태와 블록 내부 공유 데이터를 저장해 전역 메모리 접근을 줄임 |
| 전역 메모리 | 모든 스레드가 접근하며 병합 여부가 메모리 트랜잭션 수와 대역폭 사용률을 결정함 |

```text
+-------------+     +----------------------+     +-------------------+     +-------------+
| 커널 그리드 | --> | 스트리밍 멀티프로세서 | --> | 워프 스케줄러     | --> | 전역 메모리  |
+-------------+     +----------------------+     +-------------------+     +-------------+
                          |
                          v
                    +-------------+
                    | 공유 메모리 |
                    +-------------+
```

> 요약: SM은 워프 스케줄러로 실행 대상을 바꾸고 레지스터·공유 메모리로 전역 메모리 접근을 줄임.

### 쉽게 이해하기 (학습용)
- 작업장(SM), 다음 투입 조를 정하는 반장(워프 스케줄러), 손 닿는 작업대(레지스터·공유 메모리), 멀리 있는 창고(전역 메모리)가 함께 있는 공장과 같음

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 커널 실행 요청 | --> | 워프 단위 배치  | --> | 병렬 명령 실행 | --> | 결과 저장·복귀 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **커널 실행 요청**: 호스트가 GPU에 병렬 커널을 전달함
2. **워프 단위 배치**: 스레드를 블록과 워프로 그룹화해 SM에 할당함
3. **병렬 명령 실행**: 동일 명령을 다수 스레드가 각자 데이터에 적용함
4. **결과 저장 및 복귀**: 계산 결과를 메모리에 기록하고 호스트로 반환함

> 요약: GPU 커널은 스레드를 워프로 그룹화해 동일 명령을 다수 데이터에 적용함.

### 쉽게 이해하기 (학습용)
- 작업 지시가 내려오면 조를 짜고, 다같이 같은 동작을 수행한 뒤, 결과물을 창고에 넣고 보고하는 순서와 같음

## Ⅵ. 실무 사례

1. 합성곱 커널은 같은 분기 경로의 데이터를 한 워프에 배치하고 워프 실행 효율·분기 발산률을 확인함
2. 행렬 커널은 연속 주소를 한 워프에 배치하고 전역 메모리 적재 효율·메모리 처리량을 확인함

### 쉽게 이해하기 (학습용)
- 같은 방향으로 갈 사람끼리 한 조로 묶거나, 옆 칸 물건끼리 한 번에 실어나르도록 배치하는 것과 같음

## Ⅶ. 결론

- GPU SIMT는 스레드를 워프로 묶어 같은 명령을 동시 실행하고 지연 워프를 교체해 처리량을 높이는 구조이며, 분기 발산과 비연속 메모리 접근이 성능을 좌우함
- 분기 경로가 갈리는 연산은 같은 경로의 데이터를 한 워프에 배치하고, 메모리 접근이 잦은 연산은 연속 주소로 병합 접근되게 배치해야 함

### 쉽게 이해하기 (학습용)
- 일꾼 수보다 조 편성과 동선 낭비 여부가 전체 작업 속도를 좌우하는 것과 같음
