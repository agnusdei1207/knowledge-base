## Ⅰ. 개요
- **정의**: 수천~수만 개 경량 코어로 동일 명령을 다수 스레드에 동시 적용하는 대규모 병렬 처리 아키텍처
- **배경/필요성**: AI 학습·추론에서 매트릭스 곱셈·합성곱 등 데이터 병렬성이 높은 연산이 지배적이므로, 단일 스레드 성능보다 처리량 극대화가 필요함
- **비유**: 한 명의 지휘자(명령)가 수천 명의 악단원(스레드)에게 같은 악보를 동시에 연주시키는 오케스트라와 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| SIMT와 SIMD 차이, GPU가 AI 학습에 적합한 구조적 이유 | 워프(Warp) 단위 실행·SM 내부 자원 공유 | SIMT ≠ SIMD: 스레드별 PC를 가지며 분기 처리 가능 |

> 요약: SIMT 실행 모델로 워프 단위 수천 스레드를 동시 실행하여 데이터 병렬 연산을 가속하는 아키텍처임

## Ⅱ. 구성요소
```text
GPU Chip
  |
  +-- SM (Streaming Multiprocessor) x N
  |     |-- CUDA Cores (INT/FP)
  |     |-- Tensor Cores (Matrix)
  |     |-- Warp Scheduler
  |     |-- Register File
  |     +-- Shared Memory / L1 Cache
  |
  +-- L2 Cache
  +-- Memory Controller -- HBM/GDDR
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| SM(Streaming Multiprocessor) | CUDA/Tensor 코어·레지스터·공유 메모리를 묶은 실행 단위 | 오케스트라 섹션(현악·관악) |
| CUDA Core | INT/FP 스칼라 연산을 수행하는 기본 실행 유닛 | 개별 악단원 |
| Tensor Core | FP16/INT8/FP8 매트릭스 곱셈-누산을 1사이클에 처리하는 전용 유닛 | 화음 전문 연주자 |
| Warp Scheduler | 32개 스레드 묶음(워프)을 SM 내 실행 유닛에 디스패치함 | 지휘자 |
| Register File | 스레드당 레지스터를 할당하여 중간 결과를 보관함 | 악보 거치대 |
| Shared Memory/L1 | SM 내 스레드 간 데이터를 공유하는 저지연 온칩 메모리 | 섹션 공용 악보함 |
| HBM/GDDR | 대용량 모델 파라미터·배치 데이터를 저장하는 외부 메모리 | 악보 창고 |

> 요약: SM 내부에 다수 코어·스케줄러·공유 메모리가 배치되어 워프 단위로 병렬 실행됨

## Ⅲ. 절차
```text
커널 디스패치 --> 스레드블록 할당 --> 워프 스케줄링·실행 --> 결과 Write-back
```
- 1단계: 호스트 CPU가 GPU 커널을 호출하고, 그리드(Grid) 내 스레드블록(Block) 수를 지정함
- 2단계: GigaThread 엔진이 스레드블록을 가용 SM에 할당하고, 레지스터·공유 메모리를 배분함
- 3단계: 워프 스케줄러가 32스레드 워프를 선택하여 CUDA/Tensor 코어에 명령을 발행하고, 메모리 대기 시 다른 워프로 전환(Latency Hiding)함
- 4단계: 연산 결과를 L2 캐시·HBM에 기록하고, 호스트에 완료를 통보함

> 요약: 커널 호출 → 블록 할당 → 워프 실행(지연 은닉) → 결과 기록 순으로 대규모 병렬 연산을 수행함

## Ⅳ. 문제점
- 분기 발산(Branch Divergence): 워프 내 스레드가 서로 다른 분기를 타면 순차 실행으로 전환됨 — 워프 활용률이 50 % 이하로 저하될 수 있음
- 메모리 대역폭 병목: Tensor Core의 피크 연산량 대비 HBM 대역폭이 부족하면 연산 유닛이 유휴 상태가 됨 — 산술 강도(AI)가 낮은 연산에서 두드러짐
- 높은 전력 소비: 대규모 병렬 코어 가동 시 TDP 300~700 W 수준 — 데이터센터 냉각·전력 비용이 지배적 운영 부담이 됨

> 요약: 분기 발산, 메모리 대역폭 병목, 높은 전력 소비가 GPU 가속의 주요 제약임

## Ⅴ. 개선방안
1. 단기: 워프 내 분기를 최소화하는 커널 설계 패턴(Predication, 데이터 정렬)을 적용함
2. 중기: HBM4·캐시 계층 확장으로 Byte/FLOP 비율을 개선하여 메모리 바운드 구간을 축소함
3. 장기: 칩렛 분리·액침 냉각·광 인터커넥트 도입으로 전력·발열 한계를 구조적으로 완화함

> 요약: 분기 최소화, 메모리 대역폭 확장, 전력·냉각 혁신으로 GPU 가속 한계를 극복함

## Ⅵ. 전망
- 발전 방향: Transformer 학습에 특화된 Tensor Core 세대별 진화(FP8·FP4)와 NVLink/NVSwitch 기반 멀티 GPU 스케일아웃이 가속됨
- 기술사적 판단: AI 학습 영역에서는 GPU가 사실상 표준이며, 추론 영역에서 ASIC(049 참조)·FPGA(048 참조)와 역할을 분담하는 구도가 지속됨
- 기술사 제언: CUDA(051 참조) 생태계 의존도를 인식하고, SYCL·Triton 등 이식성 프레임워크 병행 도입으로 벤더 다변화를 준비할 것을 권고함
