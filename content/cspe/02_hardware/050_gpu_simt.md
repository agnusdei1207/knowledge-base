## 미리 알고가기

- **$GPU$ (Graphics Processing Unit)**: 수천 개의 단순한 연산 코어를 사용하여 대규모 병렬 처리에 특화된 프로세서
- **$SIMT$ (Single Instruction Multiple Threads)**: 하나의 명령어가 여러 스레드에 동시에 적용되어 각기 다른 데이터를 처리하는 병렬 실행 모델
- **워프 ($Warp$)**: $GPU$가 한 번에 스케줄링하고 실행하는 스레드 집합 ($NVIDIA$ 기준 $32$개 스레드)
- **분기 발산 ($Branch\ Divergence$)**: 같은 워프 내의 스레드들이 서로 다른 조건문에 진입할 때 실행이 순차적으로 일어나 성능이 저하되는 현상
- **$SM$ (Streaming Multiprocessor)**: $GPU$ 내부의 독립적인 연산 단위로, 다수의 코어와 공유 메모리, 스케줄러를 포함함

## Ⅰ. 개요

- **정의/개념**: $GPU$ 아키텍처와 $SIMT$ 모델은 대규모 데이터 병렬성을 처리하기 위한 하드웨어 구조 및 실행 원리임
  - **$GPU$ 아키텍처**: 수많은 연산 유닛($ALU$)과 고대역폭 메모리($HBM$)를 배치하여 처리량($Throughput$)을 극대화한 구조임
  - **$SIMT$ 모델**: 단일 명령어를 다수의 스레드가 각자의 데이터에 적용하도록 하는 $NVIDIA$의 병렬 프로그래밍 모델로, $SIMD$보다 유연한 스레드 제어를 지원함
- **배경/필요성**: $CPU$는 복잡한 제어 흐름과 낮은 지연 시간($Latency$)에 최적화되어 있으나, 딥러닝이나 그래픽 처리와 같은 대규모 단순 반복 연산에서는 효율이 급감함. 이를 보완하기 위해 연산 유닛의 밀도를 높이고 지연 시간을 병렬성으로 숨기는($Latency\ Hiding$) 방식이 필요하게 됨

## Ⅱ. 특징 및 비교

### 가. $CPU$ ($SISD/MIMD$)와 $GPU$ ($SIMT$)의 실행 모델 비교

| 구분 | $CPU$ 아키텍처 | $GPU$ ($SIMT$) 아키텍처 |
|:---|:---|:---|
| **설계 목표** | 단일 스레드 지연 시간 최소화 | 전체 시스템 처리량($Throughput$) 극대화 |
| **코어 구성** | 소수의 복잡하고 강력한 코어 | 수천 개의 단순하고 가벼운 코어 |
| **제어 로직** | 크고 복잡함 (분기 예측, 비순서 실행) | 작고 단순함 (스레드 간 공유) |
| **캐시 메모리** | 대용량 캐시 (데이터 접근 지연 감소용) | 소량 캐시 (대역폭 증폭 및 데이터 공유용) |
| **병렬화 방식** | 멀티코어, 하이퍼스레딩 | 수만 개의 활성 스레드 동시 실행 |

> 요약: $CPU$가 '정교한 스포츠카'라면 $GPU$는 '대용량 화물 열차'와 같음

### 나. $SIMD$ vs $SIMT$
- **$SIMD$ (Single Instruction Multiple Data)**: 하드웨어 벡터 레지스터 폭에 맞춰 고정된 데이터 묶음을 처리 (엄격한 정렬 필요)
- **$SIMT$**: 개별 스레드 단위로 논리적 실행을 정의하며, 하드웨어가 이를 워프 단위로 묶어 실행 (보다 유연한 프로그래밍 가능)

## Ⅲ. 구성요소/구조

### 가. $GPU$ 하드웨어 계층 및 $SIMT$ 실행 구조

```text
[ GPU Device ]
  |-- [ Global Memory (HBM / GDDR) ]
  |-- [ L2 Cache ]
  |-- [ Streaming Multiprocessors (SM) x N ]
        |-- [ Warp Scheduler ]
        |-- [ Register File ]
        |-- [ Shared Memory / L1 Cache ]
        |-- [ CUDA Cores (ALU) ]
        |-- [ Tensor Cores (Matrix Ops) ]
```

### 나. 주요 구성 요소 및 역할

| 구성요소 | 역할 및 설명 | 핵심 포인트 |
|:---|:---|:---|
| 스트리밍 멀티프로세서 ($SM$) | $GPU$의 핵심 연산 유닛 블록 | $Thread\ Block$이 할당되는 단위 |
| 워프 스케줄러 | 실행 준비가 된 워프를 선택해 연산기에 할당 | 지연 시간 은닉($Latency\ Hiding$) 수행 |
| 공유 메모리 | $SM$ 내부 스레드들이 데이터를 공유하는 고속 공간 | 유저 제어 가능 ($Scratchpad\ Memory$) |
| 레지스터 파일 | 수만 개의 스레드 상태를 즉각 저장하는 대규모 공간 | 문맥 전환 오버헤드 거의 없음 |
| 텐서 코어 ($Tensor\ Core$) | 딥러닝용 $4 \times 4$ 행렬 곱셈 전용 가속기 | $AI$ 성능의 핵심 요소 |

> 요약: 코어를 수천 개 깔고, 메모리 대기 시간 동안 다른 일을 하도록 스케줄링하는 '벌떼 연산' 구조임

## Ⅳ. 문제점 및 개선방안

1. **분기 발산 ($Branch\ Divergence$)**: $if-else$ 문에서 스레드들이 갈라질 때, 모든 경로를 순차 실행하여 성능이 절반 이하로 하락
   - **개선방안**: 데이터를 미리 정렬하여 워프 단위로 분기 경로를 일치시키거나, 조건부 실행($Predication$) 기술을 활용함

2. **메모리 병합 ($Memory\ Coalescing$) 실패**: 인접 스레드가 서로 멀리 떨어진 주소를 읽을 때 메모리 대역폭 낭비 발생
   - **개선방안**: 메모리 접근 주소를 연속된 영역으로 정렬하여 한 번의 버스 사이클로 여러 데이터를 가져오도록 최적화함

3. **호스트-디바이스 통신 병목**: $PCIe$ 버스를 통한 $CPU-GPU$ 간 데이터 전송 시간이 연산 시간보다 길어지는 현상
   - **개선방안**: **$NVLink$**와 같은 고속 인터커넥트를 도입하거나, **$Unified\ Memory$**를 통해 불필요한 데이터 복사를 최소화함

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| **딥러닝 학습/추론** | $SIMT$ 구조를 활용해 수조 개의 파라미터를 가진 신경망 행렬 연산을 병렬 처리 | $TFLOPS$, $Throughput$ |
| **기상 예측 / 시뮬레이션** | 지구 격자 데이터를 수만 개의 스레드에 분산하여 유체 역학 방정식 계산 | $Simulation\ Time$, $Node\ Scalability$ |
| **암호화폐 채굴** | 단순 반복적인 해시($Hash$) 연산을 대규모 병렬 코어로 수행하여 초당 해시량 극대화 | $Hash\ Rate$, $Power\ Efficiency$ |

> 요약: 데이터의 양은 방대하지만 연산 과정이 독립적이고 정형화된 모든 분야의 표준으로 자리 잡음

## Ⅵ. 결론

$GPU$ 아키텍처와 $SIMT$ 모델은 현대 인공지능 혁명의 하드웨어적 토대임. '지연 시간을 줄이는 대신 병렬성으로 덮는다'는 설계 철학은 $AI$ 모델의 크기가 폭발적으로 증가하는 현 시점에서 가장 유효한 전략으로 입증되었음.

기술사는 단순히 코어 개수가 많다는 점을 넘어, **워프 스케줄링**을 통한 지연 은닉 원리와 **메모리 병합**의 중요성을 명확히 설명할 수 있어야 함. 또한, $HBM3/4$와 같은 차세대 메모리와 $CXL$ 기반의 가속기 연동 기술이 향후 $GPU$ 중심의 데이터센터 아키텍처를 어떻게 변화시킬지 전망할 수 있어야 함.
