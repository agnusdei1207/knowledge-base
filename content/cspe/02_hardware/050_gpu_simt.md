## 미리 알고가기

- GPU: 그래픽 처리 장치(Graphics Processing Unit, GPU)는 많은 연산 유닛으로 처리량 중심 병렬 연산을 수행하는 프로세서임
- SIMT: 단일 명령 다중 스레드(Single Instruction Multiple Threads, SIMT)는 여러 스레드가 같은 명령 흐름을 병렬 실행하는 모델임
- Warp/Wavefront: GPU가 함께 스케줄링하는 스레드 묶음임
- SM/CU: 스트리밍 멀티프로세서(Streaming Multiprocessor, SM) 또는 컴퓨트 유닛(Compute Unit, CU)은 GPU 내부에서 워프를 실행하는 연산 블록임
- Coalescing: 인접 스레드의 메모리 접근을 묶어 대역폭 효율을 높이는 기법임

## Ⅰ. 개요

- **정의**: GPU SIMT 모델은 수천 개의 경량 스레드를 워프 단위로 묶어 같은 명령을 서로 다른 데이터에 적용함으로써 그래픽, 과학 계산, AI처럼 데이터 병렬성이 큰 연산의 처리량을 높이는 병렬 실행 구조임
- **배경/필요성**: 중앙처리장치(Central Processing Unit, CPU)는 낮은 지연과 복잡한 제어 흐름에 강하지만 대규모 동일 연산을 처리할 때 코어 수와 메모리 대역폭이 제한됨. GPU는 많은 연산 유닛과 고대역폭 메모리로 처리량 중심 워크로드를 가속함
- **비유**: 한 감독이 같은 지시를 여러 작업자에게 내리고 각 작업자가 서로 다른 부품을 동시에 처리하는 공장과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| GPU 병렬 실행 구조와 CPU와의 차이 설명 | SIMT, 워프, 메모리 계층, 분기 발산 | 단순 코어 수 비교 |

> 요약: GPU SIMT는 같은 명령을 많은 스레드에 적용해 데이터 병렬 처리량을 높이는 구조임.

## Ⅱ. 특징/비교

| 판단 기준 | CPU 중심 실행 | GPU SIMT 실행 |
|:---|:---|:---|
| 최적화 목표 | 낮은 단일 스레드 지연과 복잡한 제어 흐름 처리 | 높은 처리량과 대규모 데이터 병렬성 처리 |
| 실행 단위 | 소수의 강한 코어와 깊은 캐시 계층 | 다수의 연산 유닛, 워프 스케줄러, 고대역폭 메모리 |
| 적용 기준 | 분기와 의존성이 많은 일반 제어 로직에 적합함 | 동일 연산을 많은 데이터에 반복하는 연산에 적합함 |

> 요약: GPU는 지연시간보다 처리량이 중요한 데이터 병렬 문제에서 CPU보다 유리함.

## Ⅲ. 구성요소

```text
+----------+     +----------+     +----------+
| Host CPU | --> | Kernel   | --> | SM/CU    |
+----------+     +----------+     +----------+
                                      |
                     +----------------+----------------+
                     v                                 v
              +-------------+                   +-------------+
              | Warp Sched  |                   | HBM/GDDR    |
              +-------------+                   +-------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| SM/CU | 워프를 실행하고 ALU, 레지스터, 공유 메모리를 포함함 | 작업 구역 |
| 워프 스케줄러 | 준비된 워프를 선택해 실행 유닛에 명령을 공급함 | 현장 반장 |
| 메모리 계층 | 레지스터, 공유 메모리, 2단계 캐시(Level 2 Cache, L2), 고대역폭 메모리(High Bandwidth Memory, HBM)/그래픽 더블 데이터 레이트(Graphics Double Data Rate, GDDR)로 데이터 접근 지연을 관리함 | 부품 창고 |
| 호스트/런타임 | CPU가 커널 실행과 데이터 전송을 지시함 | 작업 관리자 |

> 요약: GPU 구조는 호스트가 커널을 실행시키고 SM이 워프 단위로 대량 연산을 수행하는 형태임.

## Ⅳ. 절차

```text
+----------+     +----------+     +----------+     +----------+
| Kernel   | --> | ThreadMap| --> | WarpRun  | --> | Collect  |
+----------+     +----------+     +----------+     +----------+
```

1. **커널 작성**: 데이터 병렬로 수행할 연산을 GPU 커널로 정의함
2. **스레드 배치**: 그리드, 블록, 스레드 구조로 데이터 범위를 분할함
3. **워프 실행**: 스케줄러가 워프를 선택하고 메모리 접근과 산술 논리 장치(Arithmetic Logic Unit, ALU) 연산을 병렬 수행함
4. **결과 회수**: 전역 메모리에 결과를 기록하고 CPU가 동기화 후 후속 처리를 수행함

> 요약: GPU 실행은 커널을 스레드 격자로 펼친 뒤 워프 단위로 스케줄링해 결과를 모음.

## Ⅴ. 문제점 및 개선방안

- **P1 분기 발산**: 같은 워프 안의 스레드가 서로 다른 분기 경로를 타면 경로를 순차 실행해 병렬 효율이 떨어짐
- **P1 대응**: 워프 단위 분기 정렬, predication, 데이터 재배치로 발산을 줄임 (확인: branch efficiency)
- **P2 메모리 접근 비효율**: 비연속 접근과 낮은 데이터 재사용은 고대역폭 메모리(High Bandwidth Memory, HBM)에서도 병목을 만듦
- **P2 대응**: coalescing, shared memory tiling, prefetch로 메모리 접근 패턴을 정렬함 (확인: 메모리 처리량)
- **P3 점유율 불균형**: 레지스터와 공유 메모리 사용량이 크면 동시에 실행 가능한 워프 수가 줄어 지연 숨김이 어려움
- **P3 대응**: 레지스터 사용량 조정, 블록 크기 튜닝, occupancy 분석을 수행함 (확인: achieved occupancy)

> 요약: GPU 최적화는 워프 흐름을 맞추고 메모리 접근과 자원 사용량을 균형화하는 작업임.

## Ⅵ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 인공지능(Artificial Intelligence, AI) 학습 행렬 연산 | 그래픽 처리 장치(Graphics Processing Unit, GPU) 커널을 단일 명령 다중 스레드(Single Instruction Multiple Threads, SIMT) 구조에 맞춰 타일링하고 tensor core 사용 조건을 맞춤 | 처리량, 고대역폭 메모리(High Bandwidth Memory, HBM) 대역폭 사용률, achieved occupancy |
| 영상·과학 계산 | 동일 연산이 반복되는 픽셀·격자 데이터를 워프 단위로 배치하고 분기 조건을 데이터 전처리로 정렬함 | branch efficiency, 커널 실행시간, 메모리 coalescing 효율 |
| 호스트-가속기 혼합 서비스 | 중앙처리장치(Central Processing Unit, CPU)는 제어와 전처리를 담당하고 GPU는 대량 병렬 커널만 수행하도록 데이터 이동 비용을 측정함 | 주변 장치 상호연결 익스프레스(Peripheral Component Interconnect Express, PCIe) 전송 시간, end-to-end 지연, GPU 사용률 |

> 요약: GPU SIMT 적용은 병렬화 가능성, 메모리 접근 패턴, CPU-GPU 전송 비용이 지표로 확인될 때 효과가 큼.

## Ⅶ. 전망

- **발전 방향**: GPU는 인공지능(Artificial Intelligence, AI) 학습, 고성능 컴퓨팅(High Performance Computing, HPC), 디지털 트윈에서 NVLink, HBM, 텐서 코어와 결합해 처리량 중심 플랫폼으로 확장됨
- **기술사적 판단**: GPU 도입은 병렬화 가능성, 메모리 대역폭, 데이터 이동 비용을 측정한 뒤 결정해야 함
- **기술사 제언**: 답안에서는 SIMT 실행 모델과 분기·메모리 병목을 함께 제시해 GPU 선택 근거를 구조적으로 설명해야 함
