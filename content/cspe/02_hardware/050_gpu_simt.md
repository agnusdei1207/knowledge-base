# 📖 【암기용】 개념 완전 이해

> 목적: 이 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: **SIMT**(Single Instruction Multiple Threads)는 GPU가 수천 개의 **스레드**를 32개 단위인 **Warp**로 묶어 하나의 명령어로 동시에 실행하는 NVIDIA의 병렬 실행 모델이다.
- **왜 필요한가**: 화면 하나를 채우는 픽셀 수, 딥러닝 행렬의 원소 수는 수백만~수십억 단위인데 각 원소에 대한 연산 자체는 덧셈·곱셈처럼 단순하다. CPU처럼 소수의 강력한 코어로 이런 데이터를 하나씩 순차 처리하면 시간이 감당되지 않는다. 그래서 코어 하나의 성능(지능)을 낮추는 대신 코어 개수를 극단적으로 늘려, 같은 연산을 데이터만 바꿔가며 동시에 수행하는 구조가 필요했다.
- **핵심 직관**: CPU는 복잡한 지시를 알아서 판단해 각자 다른 일을 처리하는 소수의 전문가(MIMD)이고, GPU는 "전체 차렷, 앞으로 갓" 하나의 구령에 수천 명이 동시에 똑같이 움직이는 열병식 부대다. 다만 병사(스레드)마다 손에 든 총알(데이터)만 다르다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 표기/용어 | 의미 | 비유 |
|:---|:---|:---|
| SIMT (Single Instruction Multiple Threads) | 1개 명령어를 다수의 독립적 스레드가 동시에 실행하는 GPU 실행 모델 — 이 개념의 핵심 키워드 | 구령 하나에 수천 명이 동시 동작하되, 각자 총알(데이터)은 다름 |
| SP (Streaming Processor / CUDA Core) | 실제 연산(덧셈·곱셈)을 수행하는 GPU의 최소 실행 단위 코어 | 병사 1명 |
| Warp (워프) | 32개의 스레드를 묶어 항상 같은 명령어를 함께 받는 스케줄링 단위 | 32명으로 구성된 분대 |
| SM (Streaming Multiprocessor) | 여러 Warp, 레지스터 파일, 공유 메모리, L1 캐시를 묶은 실행 블록 | 여러 분대를 지휘하는 중대 |
| Global Memory | 칩 외부의 대용량·고대역폭 메모리(VRAM, HBM/GDDR) | 부대 전체가 함께 쓰지만 멀리 떨어진 보급 창고 |
| SIMD (Single Instruction Multiple Data) | 1개 명령어로 레지스터에 실린 여러 데이터를 통째로 처리하는 벡터 연산 방식 | 여러 발을 한 탄창에 넣어 한 번에 발사 — 탄창 전체가 하나로 묶여 개별 조작 불가 |
| Warp Divergence (분기 발산) | 하나의 Warp 안에서 조건문(if-else)에 따라 스레드들이 서로 다른 경로로 갈라지는 현상 | 분대 안에서 절반은 좌회전, 절반은 우회전 명령을 받은 상황 |
| Masking (마스킹) | 분기 발생 시 해당 경로에 속하지 않는 스레드를 일시적으로 비활성화(대기)시키는 하드웨어 기법 | 지금 명령을 받지 않는 병사는 잠깐 '쉬어' 자세로 대기 |

## 깊이 이해

### 왜 이런 구조가 필요했나 — 규모를 숫자로 보기
- 화면 해상도 FHD(1920×1080)는 1,920 × 1,080 = 2,073,600개의 픽셀로 이루어진다. 4K(3840×2160)는 이 4배인 약 829만 개다. 화면을 초당 60번(60fps) 갱신한다면 FHD 기준으로도 초당 1억 2천만 회가 넘는 픽셀 연산이 필요하다.
- 딥러닝 행렬 곱셈도 마찬가지다. 4096×4096 크기 행렬 곱셈 한 번에는 약 4096³ ≈ 687억 번의 곱셈-덧셈 연산이 들어간다.
- 이런 연산은 개별적으로는 "덧셈 한 번, 곱셈 한 번" 수준으로 단순하지만 개수가 압도적으로 많다. 반면 CPU가 잘하는 것은 정반대다 — 복잡한 분기와 순서 의존적 로직을 소수의 코어가 빠르게(낮은 지연시간, Low Latency) 처리하는 것이다. "단순 연산 × 수백만 개"라는 문제에는 코어 하나의 지능을 낮추더라도 코어 수를 늘려 총 처리량(Throughput)을 극대화하는 별도의 칩이 필요해졌다 — 이것이 GPU다.

### CPU와 GPU의 트랜지스터 면적 할당 철학 차이
- 같은 크기의 칩(Die) 면적을 CPU와 GPU는 서로 다른 곳에 쓴다.
- CPU: 분기 예측(Branch Prediction), 비순차 실행(Out-of-Order Execution), 거대한 L2/L3 캐시에 면적 대부분을 할당한다. 목적은 "명령어 하나하나를 최대한 빨리, 최대한 안 기다리고" 처리하는 것 — 즉 지연시간(Latency) 최소화다. 그 결과 실제 연산기(ALU)가 차지하는 면적은 작다.
- GPU: 분기 예측이나 대형 캐시 같은 "똑똑해지기 위한" 회로를 최소화하고, 그 자리에 ALU를 수천 개 채운다. 스레드 하나가 느리게 처리되어도 상관없다 — 동시에 처리하는 스레드 수(처리량)를 극대화하는 것이 목적이기 때문이다.
- 판별 기준: "하나를 얼마나 빨리 끝내는가(지연시간)"가 중요한가, "전체를 얼마나 빨리 다 끝내는가(처리량)"가 중요한가로 CPU와 GPU의 설계 철학이 갈린다.

### 왜 하필 32개 단위(Warp)인가
- Warp 크기 32는 물리 법칙이 아니라 NVIDIA의 하드웨어 설계 관례(Convention)다. 명령어를 스레드들에 실어 나르는 페치/디코드 유닛의 처리 폭과 SP를 묶는 클럭 사이클 배수 등을 고려해 정해진 값으로, NVIDIA GPU 세대를 거치며 32로 굳어졌다. 참고로 AMD GPU는 대응 단위를 Wavefront라 부르며 크기가 64인 경우가 많다 — 즉 "몇 개를 하나로 묶어 동시에 통제할 것인가"는 벤더마다 다른 설계 선택이다.
- 이 숫자가 스케줄링의 기본 단위이므로, 스레드 개수가 32의 배수가 아니면 마지막 Warp에는 빈자리가 생긴다. 예: 스레드 100개를 실행하면 32+32+32+4로 나뉘어, 마지막 Warp는 32자리 중 4자리만 쓰고 28자리는 비활성 상태로 낭비된다.

### SIMD와 SIMT의 차이 — 왜 SIMT가 더 유연한가
- SIMD(Single Instruction Multiple Data)는 벡터 레지스터 하나에 여러 데이터를 실어놓고 명령어 하나로 통째로 처리한다. x86의 AVX가 대표적이다. 문제는 벡터 안의 원소 하나가 다른 원소와 다른 경로(if-else)로 가야 할 때다 — 벡터는 원자적으로 통째로 움직이므로 개별 원소만 따로 분기시킬 하드웨어 지원이 없고, 프로그래머가 비트 마스크 연산으로 억지로 흉내 내야 한다.
- SIMT는 겉으로는 "명령어 하나로 여러 데이터를 처리"하는 게 SIMD와 똑같아 보이지만, 내부적으로는 32개의 독립된 스레드로 관리한다. 각 스레드가 자신만의 레지스터와 활성/비활성 상태를 갖기 때문에, 조건문을 만나면 하드웨어가 스레드별로 마스킹을 걸어 개별적으로 분기를 처리할 수 있다.
- 판별 기준: 데이터 전체가 항상 같은 연산만 받는가(SIMD로 충분) 아니면 데이터별로 조건에 따라 다른 경로를 타야 하는가(SIMT가 필요) — 이 차이가 벡터 연산의 단순 확장이 아닌 별도의 스레드 기반 모델(SIMT)이 만들어진 이유다.

### Warp Divergence가 실제로 얼마나 느려지는가 — 수치 예제
- 32개 스레드로 이루어진 Warp가 `if (x > 0) A(); else B();` 코드를 실행한다고 하자. A()와 B()가 각각 정확히 10클럭이 걸리는 연산이라 가정한다.
- 32개 전부가 조건을 같은 방향으로 통과하면(발산 없음): A() 10클럭만 실행하고 끝난다 — 총 10클럭.
- 16개는 참, 16개는 거짓으로 반씩 갈리면: 하드웨어는 먼저 참인 16개만 활성화해 A()를 10클럭 동안 실행하고(이때 거짓인 16개는 마스킹되어 대기), 그다음 거짓인 16개를 활성화해 B()를 10클럭 동안 실행한다(이때 참인 16개가 대기). 결과적으로 Warp 전체는 10 + 10 = 20클럭을 써야 끝난다.
- 즉 실제 유효 연산량은 그대로인데 걸리는 시간은 2배가 된다 — Warp 하나는 항상 "그 안에서 갈라진 모든 경로의 실행 시간 합"만큼 시간을 쓰기 때문이다. 32개가 32갈래로 전부 다른 경로를 탄다면 이론상 최악의 경우 32배까지 느려질 수 있다.
- 그래서 GPGPU 튜닝의 핵심 원칙 하나가 "실행 경로가 갈릴 데이터는 미리 정렬해서, 같은 경로를 타는 스레드끼리 같은 Warp 안에 모아 넣어라"는 것이다 — 그러면 Warp 단위로는 발산이 사라진다.

### 메모리 계층과 SM의 역할 — 왜 SM으로 묶는가
- SP(코어) 하나는 스스로 명령어를 가져오거나 판단할 능력이 없다. 명령어 페치/디코드, 레지스터 파일, 공유 메모리, L1 캐시 같은 자원은 여러 SP를 묶은 SM 단위로 공유한다.
- Global Memory(VRAM)는 SM 외부, 칩 바깥의 대용량 메모리라 접근 지연이 SM 내부 공유 메모리보다 수십~수백 배 크다. 그래서 데이터를 SM 내부 공유 메모리에 올려놓고 그 안에서 여러 스레드가 재사용하도록 설계하는 것이 GPU 성능 튜닝의 또 다른 축이다.
- 또한 SM은 하나의 Warp가 Global Memory 접근으로 대기(Stall)하는 동안 놀지 않고, 곧바로 다른 Warp를 교체 투입한다(지연시간 은닉, Latency Hiding). 이것이 GPU가 캐시를 줄이고도 메모리 지연을 버티는 방법이다 — 기다리는 스레드를 캐시로 감싸는 대신, 기다리지 않는 다른 스레드로 그 시간을 채운다.

### 비유로 정리
- CPU는 각자 다른 복잡한 업무를 처리하는 소수의 전문가 사무실이고, GPU는 동일한 단순 작업(예: 서류에 도장 찍기)을 수천 명이 한 구령에 맞춰 동시에 반복하는 공장 라인이다. 라인에서 누군가 다른 작업(도장 대신 서명)을 해야 하는 예외가 생기면, 그 사람만 잠깐 세워두고(마스킹) 나머지가 끝난 뒤 처리해야 하므로 라인 전체 속도가 떨어진다 — 이것이 Warp Divergence다.

### 흔한 오해
- "GPU 코어가 CPU보다 훨씬 많으니 무조건 더 빠르다"는 틀렸다. 코어 하나의 성능(클럭, 분기 처리 능력)은 CPU가 훨씬 높다. GPU가 이기는 영역은 "같은 단순 연산을 대량의 독립적인 데이터에 반복 적용"하는 경우로 한정된다. 순서 의존적이거나 분기가 많은 로직(운영체제 스케줄러, 일반 애플리케이션)은 오히려 GPU에서 더 느려질 수 있다.
- "SIMT가 SIMD를 대체했다"는 것도 정확하지 않다. 둘은 공존한다 — 오늘날 GPU도 Warp 안의 32개 스레드가 물리적으로는 같은 명령어 페치/디코드 자원을 공유하는 SIMD와 유사한 하드웨어 위에서 동작하되, 그 위에 스레드별 독립 상태와 마스킹이라는 레이어를 얹어 유연성을 확보한 것이다.

## 연결 개념
- GPGPU (General-Purpose computing on GPU) — SIMT라는 실행 모델을 그래픽 렌더링이 아닌 범용 연산에 활용하는 상위 패러다임
- CUDA — SIMT 하드웨어를 C/C++ 수준의 언어로 프로그래밍할 수 있게 해주는 NVIDIA의 소프트웨어 플랫폼
- SIMD (AVX 등) — SIMT 이전부터 존재한 벡터 연산 방식, SIMT와의 비교 대상
- Amdahl의 법칙 — 병렬화 가능한 부분과 순차 처리가 필수인 부분의 비율이 전체 속도 향상의 상한을 결정 (SIMT로 병렬화해도 순차 구간이 병목이 될 수 있음)

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: GPU 아키텍처는 제어 로직과 캐시를 최소화하는 대신 ALU(연산기)를 극대화한 초병렬 처리(Throughput-Oriented) 프로세서이며, 이를 통제하기 위해 NVIDIA가 고안한 하드웨어 스레드 스케줄링 모델이 SIMT다.
> 2. **가치**: 1개의 명령어로 32개의 스레드 그룹(Warp)을 일괄 통제하면서도, 각 스레드가 고유의 레지스터와 로컬 메모리를 가짐으로써 전통적인 SIMD의 경직된 벡터 연산 한계를 탈피하고 분기 처리(Branching)의 유연성을 확보했다.
> 3. **판단 포인트**: SIMT 모델 하에서는 스레드 간 실행 경로가 엇갈리는 분기 발산(Warp Divergence) 발생 시 성능이 급감하므로, 제어 흐름(Control Flow)을 단순화하고 데이터 병렬성을 극대화하는 GPGPU 커널 알고리즘 최적화가 필수적이다.

## 출제 의도 및 답안 포인트
| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| CPU(Latency 지향)와 GPU(Throughput 지향)의 근본적 아키텍처 철학 차이 대조 | 트랜지스터 할당 비율 (Control/Cache vs ALU) | GPU 코어와 CPU 코어를 1:1로 성능 비교(클럭 등)하는 무의미한 서술 방지 |
| 고전적 SIMD 방식 대비 현대 GPU의 SIMT 모델의 우위성 분석 | 하드웨어 스레드 독립성, Warp 단위 스케줄링 | SIMT와 SIMD를 완벽히 똑같은 개념으로 뭉뚱그려 서술하는 치명적 오류 (유연성 차이 필수) |

> 요약: GPU의 SIMT는 "SIMD의 멍청한 군대식 획일성에, 각 병사(Thread)에게 약간의 자율성(개별 레지스터와 마스킹 분기)을 부여하여 범용 프로그래밍(GPGPU)을 가능케 한 엔비디아의 신의 한 수"임을 명확히 서술해야 한다.


## Ⅰ. 개요 및 필요성

- 정의: 그래픽 처리 및 대규모 병렬 수치 연산을 가속하기 위해 수천 개의 스트리밍 프로세서(SP)를 집적한 칩(GPU)과, 이를 32개의 스레드 단위(Warp)로 묶어 단일 명령어로 다중 스레드를 동시에 구동하는 실행 아키텍처(SIMT)
- 배경: CPU의 파이프라이닝 및 비순차 실행(OoO) 등 복잡한 제어 로직은 순차적 명령어의 지연시간(Latency)을 줄이는 데는 한계에 도달했으며, 수백만 개의 독립된 픽셀이나 텐서(행렬) 데이터를 처리하는 데는 절대적인 코어 수가 부족함
- 필요성: 칩 면적(Die)을 낭비하는 거대한 캐시와 제어 회로를 걷어내고 산술논리연산장치(ALU)를 수천 개 밀어 넣어, 막대한 대역폭(Throughput) 기반의 데이터 수준 병렬성(Data Level Parallelism)을 극대화할 아키텍처 요구


## Ⅱ. 구조 및 구성요소 (GPU 트랜지스터 면적 할당 철학)

```text
[폰 노이만 CPU 아키텍처 vs GPU 스트리밍 다중 프로세서(SM) 다이 면적 비교]

      [ 범용 CPU (Latency-Oriented) ]             [ 범용 GPU (Throughput-Oriented) ]
+------------------------------------------+    +------------------------------------------+
|  [Control] [Control]  |   거 대 한        |    | [Control] [ALU][ALU][ALU][ALU][ALU][ALU] |
|  [  ALU  ] [  ALU  ]  |   L2 / L3        |    | [Control] [ALU][ALU][ALU][ALU][ALU][ALU] |
|  [Cache]   [Cache]    |   Cache (캐시)   |    | [Cache]   [ALU][ALU][ALU][ALU][ALU][ALU] |
+------------------------------------------+    +------------------------------------------+
  -> 복잡한 분기 예측 및 컨텍스트 스위칭 최적화      -> 제어/캐시 버리고 무식할 정도로 계산기만 채움
```

| 핵심 구성요소 (NVIDIA 기준) | 매핑 구조 및 역할 | 통제 특징 |
|:---|:---|:---|
| SP (Streaming Processor) | 실제 연산을 수행하는 1개의 코어 (일꾼 1명) | 스스로 명령어를 가져오지 못하고 하달받음 |
| Warp (워프) | SIMT 스케줄링의 기본 단위 (병사 32명 소대) | **32개의 스레드가 무조건 동일한 명령을 공유** |
| SM (Streaming Multiprocessor)| 다수의 Warp와 공유 메모리를 묶은 중대 (코어 그룹)| L1 캐시와 레지스터 파일을 그룹 내 공유 |
| Global Memory (VRAM) | 칩 외부에 탑재된 초고대역폭 메모리 (HBM, GDDR) | 수천 개 스레드가 동시에 쏟아붓는 I/O 수용 |

> 요약: GPU 설계 철학은 "어차피 몇 놈은 메모리 기다리느라 쉴 텐데, 캐시로 막지 말고 차라리 대기병력(스레드)을 10배 더 뽑아서 쉬는 놈 빼고 딴 놈을 투입시키자(Thread Hiding)"는 물량 공세다.


## Ⅲ. 동작원리 및 SIMT 워프 분기 발산(Warp Divergence) 마이크로 흐름

32명의 스레드(1개 Warp)가 똑같은 코드를 돌리다, `if-else` 문을 만나 16명은 A로, 16명은 B로 찢어져야 할 때 GPU의 대처법을 보여준다.

```text
[SIMT 구조에서 조건문(If-Else) 발생 시 마스킹(Masking) 제어 흐름]
(명령: if (x > 0) 실행_A(); else 실행_B();)

1. [분기 직면]: Warp 내 32개 스레드 중 16개는 조건 참(True), 16개는 거짓(False) 판별
2. [경로 찢어짐]: 하드웨어는 2개의 명령어를 동시에 내릴 수 없음 (Single Instruction 위배 위기)
3. [마스킹 1] : False인 16개 스레드를 '비활성화(Mask-off/쉬어)'시키고, True인 16개만 '실행_A()' 구동
4. [마스킹 2] : A가 끝나면, 반대로 True 16개를 재우고(Mask-off), False 16개를 깨워 '실행_B()' 구동
5. [병합 완료]: 32개 스레드가 다시 같은 실행 선상으로 모여(Re-converge) 다음 명령어 동시 수행
```

| 실행 조건 | SIMT 하드웨어 처리 결과 | 연산 효율 (클럭 낭비도) |
|:---:|:---|:---|
| 모든 스레드가 같은 조건 (if) | 32개 스레드가 마스킹 없이 한 번에 통과 | **100% 효율 (속도 최상)** |
| 1개 스레드만 다른 조건 (else)| 31개 실행(1개 대기) -> 1개 실행(31개 대기) | **효율 극감** (똑같은 시간을 2번 소모) |

> 요약: SIMT 모델은 유연성을 대가로 끔찍한 비효율(Warp Divergence) 리스크를 품고 있다. 따라서 GPGPU 프로그래밍의 핵심은 "코드 안에 제발 if-else 문을 쓰지 않거나, 32개 단위로 운명이 통일되게 데이터를 묶어주는 것"이다.


## Ⅳ. 심화 비교: 고전적 SIMD vs 진화된 SIMT 대조표

똑같이 "하나의 명령으로 여러 데이터를 처리"하지만, x86 CPU의 AVX(SIMD)와 엔비디아의 SIMT는 프로그래머가 체감하는 유연성에서 천지차이다.

| 구분 | SIMD (Single Instruction Multiple Data) | SIMT (Single Instruction Multiple Threads) | GPGPU 진화의 핵심 |
|:---|:---|:---|:---|
| 제어 대상의 최소 단위| 거대한 1개의 긴 레지스터(Vector) 통째로 제어 | **각각 독립적인 32개의 스레드(Thread)** | 하드웨어적 유연성 확보 |
| 데이터 접근 방식 | 데이터가 메모리에 반드시 연속적(연달아)이어야 함 | 32개 스레드가 **제각각 다른 메모리 주소(흩어짐) 참조 가능** | 메모리 Gather/Scatter 지원 |
| 조건문(분기) 처리 | H/W 지원 없음. 프로그래머가 비트 연산으로 억지 구현 | **H/W 레벨 마스킹(Masking)**으로 스레드별 개별 분기 허용 | 복잡한 일반 범용 알고리즘 이식 가능 |
| 개발자 체감 (코딩) | 벡터 패킹(Packing) 등 기계어 수준 튜닝 고통 | 각 스레드가 독립적인 것처럼 C언어 1줄로 편하게 짬 (환상) | CUDA 생태계 폭발적 확장 기반 |

> 요약: SIMT는 프로그래머에게 "네가 수천 개의 독립된 CPU를 굴리고 있다"는 환상(Abstraction)을 심어주어, 개발 장벽을 무너뜨리고 딥러닝 붐(Boom)의 인프라를 깔아버린 1등 공신이다.


## Ⅴ. 제약 사항 및 SIMT 한계 돌파 기술 (메모리 병목 타파)

| 리스크 | 발생 원인 | 아키텍처 및 CUDA 대응 방안 | 극복 원리 및 효과 |
|:---|:---|:---|:---|
| 글로벌 메모리 병목 | 수천 개의 스레드가 동시에 VRAM(외부 메모리)에서 데이터를 퍼가려다 엄청난 지연(Memory Wall) 발생 | **공유 메모리 (Shared Memory)** | SM(중대) 내부에 스레드들이 빛의 속도로 공유할 수 있는 L1 캐시급 스크래치패드를 배치. 메인 VRAM 접속을 최소화하고 중대원들끼리 데이터 돌려쓰기 |
| 분기 발산 (Divergence)| 알고리즘 특성상 if-else를 피할 수 없어 Warp 내 스레드들이 찢어져 칩 성능이 1/32로 추락 | Warp Re-convergence 최적화 / 정렬 | CUDA 튜닝 시, 애초에 조건을 물어보기 전에 데이터 배열을 비슷한 놈(참/거짓)들끼리 32개씩 미리 정렬(Sort)해두어 마스킹 오버헤드 원천 제거 |
| PCIe 전송 지연 오버헤드| CPU 램에서 GPU VRAM으로 10GB 데이터를 옮기는 시간(PCIe 통과)이, GPU가 계산하는 시간보다 훨씬 김 | **NVLink 및 통합 메모리 (Unified Memory)** | CPU-GPU 간 병목인 PCIe를 버리고 초고속 전용망(NVLink)을 깔거나, 포인터 주소를 통합하여 복사(Copy) 없이 서로의 메모리를 즉각 참조 |

> 요약: GPU에 아무리 코어를 수만 개 때려 박아도, "먹이(데이터)를 입에 넣어주는 속도"가 느리면 수만 명이 그냥 굶어 죽는다(Idle). GPU 최적화는 사실상 '메모리 병목과의 전쟁'이다.


## Ⅵ. 실무 적용 및 결론
**적용 방안 3개:**
1. 대규모 생성형 AI(LLM) 파운데이션 모델 학습 인프라 구축: 수천억 개의 파라미터를 가진 Transformer 모델의 Q, K, V 행렬 곱셈을 처리하기 위해, 수천 대의 NVIDIA H100 GPU 클러스터에 데이터를 텐서(Tensor) 코어로 분산(Data Parallelism)하여 SIMT 연산 효율을 95% 이상으로 유지하는 초거대 훈련망 가동
2. 생명공학 분자 역학(Molecular Dynamics) 시뮬레이션 가속: 수백만 개의 원자 상호작용(N-body Problem)을 계산할 때 분기(if-else)를 최소화하도록 수식을 단일 수학적 매핑으로 정규화(Normalization)하여, Warp Divergence 없이 SIMT 스트림을 100% 점유하는 단백질 접힘(Folding) 시뮬레이터 구축
3. 자율주행 컴퓨터 비전(CNN) 엣지 실시간 처리 파이프라인: 테슬라 등 카메라 영상에서 객체를 식별할 때, CPU가 이미지 전처리를 하고 GPU로 넘기는 PCIe 병목을 없애기 위해 SoC 내부에 통합된 통합 메모리(UMA) 환경에서 Zero-Copy로 영상 버퍼를 즉각 SIMT 스레드에 던지는 파이프라인 설계

**결론 (2줄):**
- 기술사 판단: GPU의 SIMT 모델은 복잡한 제어 로직을 걷어내고 ALU 밀도를 극한으로 높인 아키텍처 결단으로, 데이터 병렬성이 지배하는 현대 딥러닝과 빅데이터 연산의 표준(De-facto) 하드웨어로 등극했다.
- 향후 방향: 단순 스레드 제어(SIMT)를 넘어, 딥러닝 행렬 곱셈 자체를 하드웨어적으로 한 클럭에 끝내버리는 텐서 코어(Tensor Core)의 도입으로 '소프트웨어 병렬'에서 '물리적 회로 병렬'로 가속 패러다임이 한 단계 더 진화하고 있다.
