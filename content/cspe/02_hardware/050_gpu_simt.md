# GPU 아키텍처·SIMT 모델 (GPU SIMT)

## 미리 알고가기

- GPU: 그래픽 처리 장치(Graphics Processing Unit, GPU)는 많은 연산 유닛으로 처리량 중심 병렬 연산을 수행하는 프로세서임
- SIMT: 단일 명령 다중 스레드(Single Instruction Multiple Threads, SIMT)는 여러 스레드가 같은 명령 흐름을 병렬 실행하는 모델임
- Warp/Wavefront: GPU가 함께 스케줄링하는 스레드 묶음임
- SM/CU: 스트리밍 멀티프로세서(Streaming Multiprocessor, SM) 또는 컴퓨트 유닛(Compute Unit, CU)은 GPU 내부에서 워프를 실행하는 연산 블록임
- Coalescing: 인접 스레드의 메모리 접근을 묶어 대역폭 효율을 높이는 기법임

## 1. 개요

- **정의/개념**: GPU SIMT 모델은 수천 개의 경량 스레드를 워프 단위로 묶어 같은 명령을 서로 다른 데이터에 적용함으로써 그래픽, 과학 계산, AI처럼 데이터 병렬성이 큰 연산의 처리량을 높이는 병렬 실행 구조임.
- **배경/필요성**: CPU는 낮은 지연과 복잡한 제어 흐름에 강하지만 대규모 동일 연산에서는 코어 수와 메모리 대역폭이 제한됨. GPU는 많은 연산 유닛과 고대역폭 메모리로 처리량 중심 워크로드를 가속함.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| GPU 병렬 실행 구조와 CPU와의 차이 설명 | SIMT, warp, SM/CU, memory hierarchy, branch divergence | 단순 코어 수 비교, 분기·메모리 병목 누락 |

> 요약: GPU SIMT는 같은 명령을 많은 스레드에 적용해 데이터 병렬 처리량을 높이는 구조임.

## 2. 특징 및 비교

| 판단 기준 | CPU 중심 실행 | GPU SIMT 실행 |
|:---|:---|:---|
| 최적화 목표 | 낮은 단일 스레드 지연과 복잡한 제어 흐름 처리 | 높은 처리량과 대규모 데이터 병렬성 처리 |
| 실행 단위 | 소수의 강한 코어와 깊은 캐시 계층 | 다수의 SM/CU, 워프 스케줄러, 고대역폭 메모리 |
| 제어 흐름 | 분기와 예외 처리에 강함 | 같은 워프의 분기 발산에 취약함 |
| 메모리 관점 | 캐시가 접근 지연을 숨김 | coalescing과 공유 메모리 활용이 중요함 |

GPU는 지연시간보다 처리량이 중요한 데이터 병렬 문제에서 유리함. 반면 분기가 많고 데이터 의존성이 강한 작업, CPU-GPU 전송 비용이 큰 작업은 GPU를 사용해도 end-to-end 성능이 낮아질 수 있음.

## 3. 구성요소/구조

```text
+----------+      +----------+      +-------------+
| Host CPU | ---> | Kernel   | ---> | GPU SM/CU   |
+----------+      +----------+      +-------------+
                                      |
                       +--------------+--------------+
                       v                             v
                +-------------+               +-------------+
                | Warp Sched  |               | HBM/GDDR    |
                +-------------+               +-------------+
                       |
                       v
                +-------------+
                | ALU/Tensor  |
                +-------------+
```

| 구성요소 | 설명 | 핵심 포인트 |
|:---|:---|:---|
| SM/CU | 워프를 실행하고 ALU, 레지스터, 공유 메모리를 포함함 | 병렬 실행 단위 |
| 워프 스케줄러 | 준비된 워프를 선택해 실행 유닛에 명령을 공급함 | 지연 숨김 |
| 메모리 계층 | 레지스터, 공유 메모리, 캐시, HBM/GDDR로 데이터 접근을 계층화함 | 대역폭 활용 |
| 호스트/런타임 | CPU가 커널 실행과 데이터 전송을 지시함 | 제어와 동기화 |
| 특수 연산 유닛 | Tensor Core 등 특정 행렬 연산을 가속함 | AI 처리량 |

### 원리/흐름도

```text
+----------+      +-----------+      +---------+      +----------+
| Kernel   | ---> | ThreadMap | ---> | WarpRun | ---> | Collect  |
+----------+      +-----------+      +---------+      +----------+
```

CPU는 병렬 커널을 실행하고 GPU는 그리드·블록·스레드로 작업을 펼침. 워프 스케줄러는 메모리 대기 중인 워프 대신 준비된 워프를 실행해 지연을 숨기며, 결과는 전역 메모리에 기록된 뒤 CPU나 다음 커널이 사용함.

## 4. 문제점 및 개선방안

1. **분기 발산**: 같은 워프 안의 스레드가 서로 다른 분기 경로를 타면 경로를 순차 실행해 병렬 효율이 떨어짐.
   - **개선방안**: 워프 단위 분기 정렬, predication, 데이터 재배치로 발산을 줄임. (확인: branch efficiency)
2. **메모리 접근 비효율**: 비연속 접근과 낮은 데이터 재사용은 고대역폭 메모리에서도 병목을 만듦.
   - **개선방안**: coalescing, shared memory tiling, prefetch로 접근 패턴을 정렬함. (확인: memory throughput, cache hit rate)
3. **점유율 불균형**: 레지스터와 공유 메모리 사용량이 크면 동시에 실행 가능한 워프 수가 줄어 지연 숨김이 어려움.
   - **개선방안**: 레지스터 사용량, 블록 크기, 공유 메모리 사용량을 튜닝함. (확인: achieved occupancy)

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| AI 학습 행렬 연산 | 행렬 곱을 타일링하고 tensor core 사용 조건에 맞춰 데이터 타입과 배치를 조정함 | 처리량, HBM 대역폭, achieved occupancy |
| 영상·과학 계산 | 픽셀·격자 데이터를 워프 단위로 배치하고 분기 조건을 전처리로 정렬함 | branch efficiency, 커널 실행시간 |
| 호스트-가속기 혼합 서비스 | CPU는 제어와 전처리, GPU는 대량 병렬 커널을 담당하게 분리함 | PCIe/NVLink 전송 시간, end-to-end 지연 |

## 6. 결론

GPU SIMT는 많은 스레드가 같은 명령을 다른 데이터에 적용할 때 강력한 처리량을 제공함. 그러나 분기 발산, 메모리 접근 패턴, CPU-GPU 데이터 이동을 통제하지 않으면 코어 수가 많아도 실효 성능은 낮아짐. 따라서 GPU 선택은 병렬화 가능성, 메모리 대역폭, 전송 비용, 점유율 지표를 함께 확인하는 설계 판단이어야 함.
