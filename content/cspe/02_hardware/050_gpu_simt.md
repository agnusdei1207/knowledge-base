# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 수천 개의 단순 연산 코어(Core)를 배치하고, 하나의 명령어로 수십 개의 스레드 묶음(Warp)을 동시에 실행하는 GPU의 핵심 병렬 처리 아키텍처
- **왜 필요한가**: 그래픽 픽셀 처리나 딥러닝 행렬 곱셈은 "엄청나게 많은 데이터에 동일한 연산"을 적용하는 작업이다. 똑똑하고 복잡한 CPU 코어 몇 개보다, 단순한 수학 연산기 수천 개가 군대처럼 일제히 움직이는 것이 압도적으로 빠르다.
- **핵심 직관**: CPU가 박사급 인재 4명이 각자 복잡한 논문을 쓰는 '연구소'라면, GPU 아키텍처(SIMT)는 단순 노동자 4천 명이 교관의 "삽질해!"라는 구령 하나에 맞춰 동시에 땅을 파는 '대규모 훈련소'다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| SM (Streaming Multiprocessor) | 수십~수백 개의 코어와 스케줄러, 레지스터를 묶은 GPU 내부의 독립적 작업 반장 조직 | "작업 반장 1명과 노동자 32명이 있는 소대" |
| SIMT (Single Instruction, Multiple Threads) | 하나의 명령어로 여러 스레드가 동시에 각자의 데이터를 처리하는 실행 모델 | "하나의 구령(명령)에 32명의 군인이 각자 자기 앞의 흙(데이터)을 파는 것" |
| 워프 (Warp) | GPU 스케줄러가 한 번에 명령을 내리는 최소 스레드 그룹 (NVIDIA 기준 32개) | "명령을 같이 받는 한 소대(32명)" |
| 워프 다이버전스 (Warp Divergence) | 32명 중 일부는 IF로, 일부는 ELSE로 조건 분기하여 동시에 일을 못 하고 대기하는 현상 | "삽질파와 곡괭이파가 나뉘어, 반장이 한쪽 명령 내릴 때 다른 쪽은 놀고 있는 비효율" |

## 깊이 이해
- **배경·문제의식**: 고전적인 SIMD(Single Instruction Multiple Data) 구조는 여러 데이터를 배열 하나로 묶어 처리해야 해서 프로그래밍이 너무 어려웠다. 스레드 단위로 자유롭게 코딩하면서도 내부적으로는 SIMD처럼 묶어서 실행해 주는 모델이 필요했다.
- **작동 원리**: 
  - 개발자는 마치 CPU 코딩하듯 개별 스레드 1개의 동작만 프로그래밍한다 (CUDA).
  - 하드웨어(GPU SM 스케줄러)가 알아서 이 스레드 32개를 묶어 하나의 '워프(Warp)'로 만든다.
  - SM은 한 클럭에 1개의 명령어를 패치하여 32개의 코어에 쫙 뿌린다. 32개 코어는 동시에 똑같은 명령(예: 덧셈)을 각자의 데이터(레지스터)에 수행한다.
- **비유**: 32대의 로봇 청소기(스레드)가 있다. 조종기 하나(Single Instruction)로 "직진!"을 누르면 32대가 일제히 각자 서 있는 위치(데이터)에서 직진한다.
- **구체 예시**: 딥러닝 행렬 곱셈 $C = A \times B$. 이 연산은 원소 간 독립적인 곱셈과 덧셈의 반복이다. GPU의 SIMT 모델은 32개의 곱셈을 한 번의 사이클에 동시 처리하여 CPU 대비 수백 배의 TFLOPS를 뽑아낸다.
- **흔한 오해·주의점**: SIMT는 SIMD와 다르다. SIMD는 명령어 레벨에서 256bit 묶음 레지스터를 다뤄야 하지만(하드웨어 종속), SIMT는 각 스레드가 고유한 상태(레지스터, PC)를 가져 분기문(if-else) 실행이 가능하다(단, 다이버전스 페널티 발생).

## 연결 개념
- CUDA (Compute Unified Device Architecture) — SIMT 하드웨어에 스레드 그리드/블록 개념을 얹어 범용 연산(GPGPU)을 가능케 한 엔비디아의 S/W 플랫폼
- 텐서 코어 (Tensor Core) — 최근 GPU에 추가된, 4x4 행렬 덧셈·곱셈(MAC)을 한 번의 클럭에 통째로 뭉개버리는 딥러닝 전용 가속 유닛

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: GPU의 SIMT 모델은 단일 명령어 처리기(Fetch/Decode)가 동일 명령을 수십 개의 스레드 묶음(Warp)에 동시 하달하여, 수천 개의 단순 코어 연산을 병렬 구동하는 GPGPU 아키텍처이다.
> 2. **가치**: 캐시와 분기 예측 등 제어 로직에 쓰이던 트랜지스터 면적을 산술논리연산장치(ALU)로 전환 배치하여, 데이터 레벨 병렬성(Data-Level Parallelism)이 높은 AI 행렬 연산 처리량을 극대화한다.
> 3. **판단 포인트**: SIMT의 성능은 조건문 분기로 인한 워프 다이버전스(Warp Divergence)를 어떻게 소프트웨어적으로 회피하고, 잦은 메모리 I/O 지연을 스레드 문맥 교환으로 가리느냐(Latency Hiding)에 달려있다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| CPU와 GPU 구조의 근본적 차이 이해 | ALU 밀집도 차이, 제어/캐시 회로 축소, 스레드 은닉 | 추상적으로 "GPU는 코어가 많아 빠르다" 수준의 나열식 서술 |
| SIMT와 SIMD의 구조적 차이 비교 | 레지스터 개별 소유, 스레드 단위 분기(if-else) 가능 | SIMT를 SIMD와 완전히 똑같은 개념으로 오서술 |
| GPU 성능 최적화(병목 회피) 메커니즘 | 워프(Warp) 개념, 워프 다이버전스, 멀티스레딩 지연 은닉 | 하드웨어 구조만 나열하고 분기문 비효율 문제(약점) 누락 |

> 요약: SIMT는 프로그래밍의 유연성(개별 스레드)을 주면서도 하드웨어 효율성(SIMD식 묶음 실행)을 챙긴 천재적 타협안임을 명확히 서술해야 한다.

## Ⅰ. 개요 및 필요성

- 개요: SIMT(Single Instruction, Multiple Threads)는 하나의 명령어로 독립적인 상태(레지스터)를 가진 다수 스레드(Warp)를 동시 실행하는 GPU 기반 대규모 병렬 처리 아키텍처이다.
- 배경: 그래픽 렌더링, 딥러닝 행렬 연산 등은 방대한 데이터에 동일 연산(Data-Parallel)이 반복되나, CPU의 복잡한 명령어 제어 구조로는 처리량(Throughput) 확보에 한계가 있음
- 필요성: 제어 회로를 극소화하고 트랜지스터 대부분을 ALU에 할당하여, 수천 개의 스레드를 한 번에 밀어내는 초고밀도 병렬 연산을 구현하기 위해 필수적임

---

## Ⅱ. 구조 및 구성요소 (Streaming Multiprocessor)

```text
+----------------------- GPU 내부 SM (Streaming Multiprocessor) ------------------------+
| [ Instruction Fetch / Decode (1개 공용) ]  [ Warp Scheduler & Dispatcher ]          |
|-------------------------------------------------------------------------------------|
| [ 레지스터 파일 (수만 개 용량) - 스레드별 개별 할당 ]                                   |
|-------------------------------------------------------------------------------------|
|  +-------+  +-------+  +-------+  +-------+         +---------------+               |
|  | ALU 1 |  | ALU 2 |  | ALU 3 |  | ALU32 | ...     | Tensor Core   | (행렬 가속)   |
|  +-------+  +-------+  +-------+  +-------+         +---------------+               |
|  <------ 1개의 Warp (32 스레드) 동시 연산 ------->                                    |
|-------------------------------------------------------------------------------------|
| [ Shared Memory (L1 캐시) - 블록 내 스레드 간 데이터 공유 ]                             |
+-------------------------------------------------------------------------------------+
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| SM (Streaming Multiprocessor) | 스케줄러, 레지스터, 다수 코어를 포함하는 GPU 연산의 기본 조직 | GPU 하나에 수십~수백 개 탑재 |
| 워프 스케줄러 (Warp Scheduler) | 32개 스레드를 1개 워프 단위로 묶어 명령어(Instruction) 하달 | I/O 대기 워프 발생 시 즉각 타 워프로 교체 |
| ALU (CUDA Core) | 실제 부동소수점/정수 연산을 수행하는 단순 실행 유닛 | 제어 분기 예측 기능 없음 |
| 대용량 레지스터 파일 | 수천 개 스레드의 문맥(Context)을 칩 내부에 상시 유지 | Context Switching 오버헤드 제로(0) |

> 요약: 똑똑한 관리자(제어 회로)를 줄이고, 대용량 사물함(레지스터)과 수백 명의 단순 노동자(ALU)를 배치해 32명(워프) 단위로 명령을 일괄 하달한다.

## Ⅲ. 동작원리 및 지연 은닉 (Latency Hiding) 흐름

```text
Warp 1 메모리 로드 요청 -> (수백 클럭 지연 대기) -> 스케줄러 즉시 Warp 2 실행 (Zero-Overhead)
-> Warp 2 연산 -> Warp 3 실행 ... -> Warp 1 데이터 도착 시 연산 재개
```

- 1단계 [워프 편성]: 소프트웨어(CUDA)에서 생성한 수만 개의 스레드를 하드웨어가 32개 단위의 '워프(Warp)'로 분할하여 SM에 할당한다.
- 2단계 [동시 실행 (SIMT)]: 스케줄러가 하나의 명령어를 가져오면(Fetch), 워프 내 32개 코어가 각자의 레지스터 데이터를 꺼내 동시에 연산한다.
- 3단계 [지연 은닉 (Zero-Overhead Switch)]: 특정 워프가 글로벌 메모리에 접근하느라 수백 클럭의 대기(Stall)가 발생하면, 방대한 레지스터에 대기 중이던 다른 워프의 명령어를 지연 없이 즉시 실행하여 ALU 유휴 상태를 막는다.
- 4단계 [메모리 병합 (Coalescing)]: 32개 스레드가 인접한 메모리 주소에 동시 접근 시, 하드웨어가 이를 1개의 거대한 메모리 트랜잭션으로 병합해 대역폭을 극대화한다.

> 요약: 스레드 전환 시 레지스터를 뺐다 꼈다(Context Switch) 할 필요가 없으므로, I/O 지연을 다른 수많은 스레드 연산으로 빈틈없이 메우는 구조다.

## Ⅳ. 특징

- [스레드 레벨 유연성]: 기존 SIMD는 벡터 레지스터 하나로 데이터 묶음을 강제하나, SIMT는 스레드별 개별 PC(Program Counter)와 레지스터를 가져 프로그래밍이 용이함
- [워프 다이버전스 (Warp Divergence) 리스크]: 32개 스레드 중 조건문(if-else)으로 흐름이 갈리면, 분기된 경로를 '순차적'으로 각각 실행(나머지는 Masking 대기)하므로 효율이 최대 1/32로 폭락함
- [방대한 메모리 대역폭 의존]: 연산기(ALU)가 너무 많아 데이터를 제때 공급하지 못하면 굶주림(Starvation) 발생. HBM(High Bandwidth Memory) 결합이 필수적임
- [Throughput 지향]: 단일 스레드의 처리 속도(Latency)는 CPU보다 훨씬 느리지만, 단위 시간당 총 처리량(Throughput)은 수백 배 높음

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | CPU 아키텍처 (SISD/MIMD) | 고전적 SIMD (AVX 등) | GPU SIMT 아키텍처 |
|:---|:---|:---|:---|
| 최적화 목표 | 단일 스레드 최단시간 처리 (Low Latency) | 데이터 블록의 일괄 연산 | 동시 수만 스레드 총 처리량 (High Throughput) |
| 제어 로직 비중 | 매우 높음 (분기 예측, Out-of-Order) | 중간 (CPU 확장 명령어) | 최소화 (면적 대부분을 ALU에 올인) |
| 문맥 교환 | 캐시 및 레지스터 덤프 (오버헤드 매우 큼) | (해당 없음) | 하드웨어 레지스터 상주 (오버헤드 0) |

> 요약: CPU가 "복잡한 미로를 가장 빨리 푸는 소수의 천재"라면, SIMT는 "단순한 계산을 수만 명이 분담해 한 번에 끝내는 대군"이다.

**리스크·대응:**
- [분기 다이버전스에 의한 코어 낭비]: 워프 내 스레드들의 if-else 조건이 엇갈림 → [대응] CUDA 설계 시 같은 워프 내 스레드는 무조건 동일한 실행 분기를 타도록 조건문 배치 정렬 (지표: 워프 실행 효율 90% 이상 유지)
- [글로벌 메모리 병목]: GPU 외부 VRAM 접근 시 극심한 지연 → [대응] SM 내부의 Shared Memory(소프트웨어 제어 L1 캐시)를 활용하여 타일(Tile) 단위 행렬 스레드 간 데이터 재사용 (지표: 글로벌 메모리 히트율 향상)

**도입 후 점검 지표:**
- SM Occupancy (활성도): GPU의 전체 슬롯 중 현재 활성화된 워프의 비율 — 레지스터나 Shared Memory 초과 사용 시 워프 생성 제한 여부 파악
- TFLOPS (Tera Floating-point Operations Per Second): 초당 부동소수점 연산 횟수 — 병렬 처리의 궁극적 스루풋 검증

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. LLM 딥러닝 트레이닝: 트랜스포머 모델의 거대한 Attention 행렬 곱을 단일 명령어(SIMT)와 텐서 코어(MMA 연산)에 분배하여 수십억 파라미터 학습 시간을 단축
2. GPGPU 기반 과학 계산 (HPC): 분자 동역학, 기상 예측 등에서 공간 그리드 데이터를 스레드 블록에 매핑하여, 독립적인 편미분 방정식 갱신을 동시 병렬 실행
3. CUDA Shared Memory 최적화 기법: 행렬 곱셈 시, 반복 참조되는 A행렬과 B행렬의 부분(Tile)을 글로벌 메모리 대신 초고속 Shared Memory에 올려 스레드 간 공유로 I/O 병목 돌파

**결론 (2줄):**
- 기술사 판단: SIMT는 트랜지스터를 제어가 아닌 연산에 올인하는 설계 철학으로, 다이버전스(분기)가 적고 데이터 독립성이 강한 AI 및 HPC 워크로드에서 대체 불가한 최적의 아키텍처임
- 향후 방향: 최근 Nvidia Hopper 등은 단순 SIMT를 넘어, SM 간 비동기 데이터 통신(Asynchronous TMA)과 동적 워프 재구성을 지원하여 병렬성을 한 차원 더 끌어올리고 있음
