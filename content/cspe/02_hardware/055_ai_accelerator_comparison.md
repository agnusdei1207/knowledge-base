# 055. AI 가속기 비교 — CPU·GPU·NPU·FPGA·ASIC (AI Accelerator Comparison) [출제: 126, 134, 136, 137회]

## Ⅰ. 개요

- **정의/개념**: 인공지능 알고리즘의 핵심인 행렬 연산과 데이터 처리를 가속하기 위해 각기 다른 아키텍처 특성을 가진 $CPU, GPU, NPU, FPGA, ASIC$ 하드웨어 자원을 성능, 전력, 비용 관점에서 비교 평가하는 것임
  - **$CPU$**: 제어 흐름과 범용 연산에 최적화된 프로세서임
  - **$GPU$**: 수천 개의 코어로 대규모 병렬 연산을 처리하는 가속기임
  - **$NPU$**: 신경망 연산(MAC 등)에 특화된 전용 프로세서임
  - **$FPGA$**: 회로 수준에서 연산 경로를 재구성할 수 있는 반도체임
  - **$ASIC$**: 특정 모델이나 워크로드를 위해 고정 설계된 주문형 반도체임
- **배경/필요성**: $AI$ 모델의 규모가 거대해지고 적용 도메인이 클라우드에서 엣지까지 다변화됨에 따라, 특정 하드웨어가 모든 상황에서 최적일 수 없으므로 서비스 요구사항($SLA$)에 맞는 가속기 선택이 중요함

## Ⅱ. 특징 및 비교

| 분류 | $CPU$ | $GPU$ | $NPU$ ($ASIC$) | $FPGA$ |
|:---|:---|:---|:---|:---|
| **설계 구조** | 폰 노이만 (범용) | $SIMT$ (병렬) | $Systolic/Array$ | 가변 논리 회로 |
| **유연성** | 매우 높음 | 높음 | 낮음 | 중간 (재구성) |
| **에너지 효율** | 낮음 ($1 \times$) | 중간 ($10 \times$) | 매우 높음 ($100 \times$) | 높음 ($50 \times$) |
| **지연 시간** | 높음 | 중간 (배치 중심) | 낮음 (최적화) | 매우 낮음 (하드웨어) |
| **주요 용도** | 제어, 전처리 | 학습, 범용 가속 | 전용 추론, 모바일 | 저지연, 프로토타입 |

> 요약: $CPU$는 제어, $GPU$는 학습, $NPU$는 추론, $FPGA$는 특수 목적 및 저지연 영역에 강점이 있음

## Ⅲ. 구성요소/구조

- **평가 및 선택 지표**:
  - **Performance ($TOPS/TFLOPS$)**: 초당 연산 횟수로 하드웨어의 절대적 연산 능력을 나타냄
  - **Energy Efficiency ($TOPS/W$)**: 전력당 성능으로 모바일 및 데이터센터 운영 비용에 직접적 영향 줌
  - **Latency vs Throughput**: 단일 요청의 응답 속도와 단위 시간당 처리량 사이의 균형($Trade-off$)임
  - **Precision Support**: $FP32, FP16, INT8, INT4$ 등 모델이 요구하는 수치 정밀도 지원 여부임
  - **Software Ecosystem**: $SDK$, 컴파일러, 프레임워크($PyTorch, TensorFlow$) 지원 수준임

- **가속기 선택 가이드라인 구조**:
```text
[ 요구사항 분석 ] -> [ 워크로드 분류 ] -> [ 하드웨어 매핑 ] -> [ TCO 평가 ]
       |                  |                   |                |
(Latency/Power)      (Train/Infer)       (GPU/NPU/FPGA)     (Capex/Opex)
```

## Ⅳ. 문제점 및 개선방안

1. **[메모리 벽 (Memory Wall)]**: 연산 유닛의 비약적 발전에도 불구하고 외부 메모리($DRAM$) 대역폭이 병목이 되어 실효 성능이 저하됨
   - **개선방안**: $HBM$($High\ Bandwidth\ Memory$) 도입, $PIM$($Processing-In-Memory$) 기술 적용, 또는 가중치 압축 기법을 활용함 (확인: 메모리 대역폭 활용률)
2. **[소프트웨어 최적화 격차]**: 하드웨어 성능은 뛰어나나 전용 컴파일러나 $SDK$의 미성숙으로 인해 모델 이식이 어렵거나 성능이 안 나옴
   - **개선방안**: $ONNX$ 등 표준 모델 포맷을 준수하고, $TVM$이나 $MLIR$ 같은 오픈소스 컴파일러 생태계에 참여함 (확인: 모델 이식 성공률)
3. **[높은 초기 도입 비용]**: 전용 $ASIC/NPU$ 개발에는 막대한 $NRE$ 비용이 발생하며, $GPU$ 클러스터 구축에는 거액의 자본 투입($CAPEX$) 필요
   - **개선방안**: 초기에는 클라우드 인스턴스를 활용해 검증하고, 서비스 규모 확장 시 전용 칩 도입이나 장기 대여 계약을 통해 비용을 최적화함 (확인: $TCO$ 분석)

## Ⅴ. 실무 적용 사례

| 적용 영역 | 추천 가속기 | 선정 사유 |
|:---|:---|:---|
| **초거대 AI 학습 (LLM)** | $GPU$ ($H100$) / $TPU$ | 방대한 파라미터 업데이트를 위한 고대역폭 통신 및 범용 병렬 연산 필요 |
| **자율주행 온보드** | $ASIC$ / $NPU$ | 제한된 전력 내에서 수십 개의 센서 데이터를 실시간으로 동시 추론해야 함 |
| **금융 알고리즘 거래** | $FPGA$ | 마이크로초($\mu s$) 단위의 결정론적 저지연($Deterministic\ Latency$) 보장 필수 |

## Ⅵ. 결론

$AI$ 가속기 비교는 단순히 '누가 더 빠른가'의 문제를 넘어, 비즈니스 목적과 기술적 제약 사이에서 최적의 균형점을 찾는 아키텍처 의사결정임. 현재는 $NVIDIA$ $GPU$가 시장을 독점하고 있으나, 향후 특정 도메인에 특화된 $DSA$($Domain\ Specific\ Architecture$) 기반의 $NPU$와 칩렛 기술을 통한 맞춤형 가속기 시장이 더욱 커질 것임. 기술사는 하드웨어 구조뿐만 아니라 소프트웨어 스택과 비용 구조를 종합적으로 고려한 전략적 선택안을 제시할 수 있어야 함.
