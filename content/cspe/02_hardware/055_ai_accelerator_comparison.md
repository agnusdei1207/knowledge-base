## 미리 알고가기

- AI 가속기: 신경망의 행렬·텐서 연산을 CPU보다 빠르거나 적은 전력으로 처리하는 하드웨어임
- 산술 강도: 메모리에서 가져온 데이터 1바이트당 수행하는 연산량임
- 지연시간/처리량: 단일 요청 응답 시간과 단위 시간 처리 건수를 구분하는 성능 기준임
- TCO: 장비, 전력, 냉각, 개발, 운영 비용을 합친 총소유비용임

## Ⅰ. 개요

- **정의**: AI 가속기 비교는 CPU, GPU, NPU, FPGA, ASIC을 워크로드 특성, 지연시간, 처리량, 전력, 유연성, 생태계 기준으로 평가해 적합한 하드웨어를 선택하는 과정임. AI 서비스의 성능과 비용을 요구사항에 맞게 설계하기 위해 사용함.
- **배경/필요성**: AI 모델은 크기, 연산자, 배치, 배치 위치가 다양해 하나의 하드웨어가 모든 조건에서 최적일 수 없음. 잘못된 가속기 선택은 비용 과다, 지연 증가, 운영 종속성으로 이어짐.
- **비유**: 같은 이동이라도 도보, 승용차, 트럭, 기차를 거리와 짐의 양에 따라 고르는 것과 같음.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| AI 하드웨어 선택 기준 비교 | 워크로드, 유연성, 전력, 지연, TCO | TOPS 기준 단독 판단 |

> 요약: AI 가속기 비교는 모델과 운영 요구에 맞춰 성능, 전력, 유연성, 비용을 함께 보는 선택 문제임.

## Ⅱ. 특징/비교

| 판단 기준 | CPU/GPU | NPU/FPGA/ASIC |
|:---|:---|:---|
| 유연성 | CPU는 제어 흐름, GPU는 다양한 병렬 커널에 강함 | NPU·ASIC은 지원 연산자에, FPGA는 재구성 설계에 의존함 |
| 전력 효율 | 범용성이 높을수록 불필요한 제어와 데이터 이동 비용이 큼 | 전용 데이터패스와 온칩 메모리로 전력당 성능을 높임 |
| 적용 기준 | 연구, 혼합 워크로드, 소프트웨어 생태계가 중요한 경우 | 대량 추론, 엣지 저전력, 고정 워크로드에 유리함 |

> 요약: AI 가속기는 범용성과 효율성 사이의 트레이드오프를 요구사항별로 판단해야 함.

## Ⅲ. 구성요소

```text
+----------+     +----------+     +------------+
| Workload | --> | Criteria | --> | Accelerator|
+----------+     +----------+     +------------+
      |               |                 |
      v               v                 v
+----------+     +----------+     +------------+
| Model    |     | TCO/PPA  |     | Runtime    |
+----------+     +----------+     +------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 워크로드 프로파일 | 모델 크기, 연산자, 배치, 지연 목표, 데이터 위치를 정의함 | 운송할 짐 |
| 평가 기준 | 성능, 전력, 비용, 유연성, 공급망, 운영성을 수치와 조건으로 비교함 | 선택 체크리스트 |
| 후보 가속기 | CPU, GPU, NPU, FPGA, ASIC 등 가능한 하드웨어 대안을 구성함 | 이동 수단 후보 |
| 소프트웨어 스택 | 프레임워크, 컴파일러, 드라이버, 런타임이 실제 성능을 결정함 | 운전 면허와 도로 |

> 요약: AI 가속기 선택 구조는 워크로드, 평가 기준, 하드웨어 후보, 소프트웨어 스택을 함께 묶어 판단함.

## Ⅳ. 절차

```text
+----------+     +----------+     +----------+     +----------+
| 요구정의 | --> | 후보선정 | --> | 벤치마크 | --> | 운영선택 |
+----------+     +----------+     +----------+     +----------+
```

1. **요구 정의**: 모델, p95 지연, 처리량, 전력, 비용, 배포 위치를 명확히 함
2. **후보 선정**: CPU, GPU, NPU, FPGA, ASIC 중 요구에 맞는 후보와 소프트웨어 스택을 선정함
3. **벤치마크**: 실제 입력 분포, 배치 크기, 정밀도, 데이터 이동을 포함해 측정함
4. **운영 선택**: 성능 결과와 TCO, 공급 안정성, 개발 역량을 반영해 도입 대안을 확정함

> 요약: AI 가속기 비교는 카탈로그 수치가 아니라 대표 워크로드 기반 실측으로 결론을 내려야 함.

## Ⅴ. 문제점

- **P1 벤치마크 불일치**: 공개 TOPS나 합성 벤치마크가 실제 모델 지연과 운영 비용을 대변하지 못함
- **P2 생태계 종속**: 특정 컴파일러, 드라이버, 클라우드, 모델 형식에 묶이면 전환 비용이 커짐
- **P3 전력·냉각 과소평가**: 데이터센터와 엣지 모두에서 전력 피크와 발열이 성능 유지 시간을 제한함

> 요약: 비교 오류는 실제 워크로드 검증 부족, 소프트웨어 종속, 운영 인프라 비용 누락에서 발생함.

## Ⅵ. 개선방안

- **P1 대응**: 대표 trace, 실제 입력 크기, 목표 정밀도, end-to-end 지연 기준으로 벤치마크함 (확인: 운영 지표와 벤치마크 편차)
- **P2 대응**: 모델 중립 포맷, 추상화 계층, 이중 벤더 전략, exit plan을 수립함 (확인: 대체 실행 경로)
- **P3 대응**: 랙 전력, 냉각 여유, throttling, 배치 스케줄링을 포함해 TCO를 계산함 (확인: 지속 성능과 전력당 처리량)

> 요약: 개선은 실측 기반 비교, 종속성 관리, 전력·냉각 포함 비용 모델링으로 수행함.

## Ⅶ. 전망

- **발전 방향**: AI 가속기는 GPU 중심 학습, NPU 중심 온디바이스 추론, ASIC·칩렛 중심 대규모 서비스로 역할이 분화됨
- **기술사적 판단**: 선택 기준은 TOPS가 아니라 모델 적합성, 데이터 이동, 소프트웨어 성숙도, 운영 비용이어야 함
- **기술사 제언**: 답안에서는 하드웨어 목록보다 선택 기준과 트레이드오프를 먼저 제시해야 고득점 구조가 됨
