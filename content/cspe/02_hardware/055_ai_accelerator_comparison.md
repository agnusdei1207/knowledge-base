## 미리 알고가기

- CPU·GPU·NPU·FPGA·ASIC은 같은 AI 연산도 목표와 제약이 다름
- 선택 기준은 유연성, 지연, 전력, 배포 규모, 개발 시간임
- 공개 연산량과 실제 모델의 지원 연산·데이터 이동·운영비를 구분해 평가해야 함
- SIMT(Single Instruction Multiple Thread): 같은 명령을 다수 스레드가 서로 다른 데이터에 동시 적용하는 GPU 실행 모델임
- 비트스트림(Bitstream): FPGA의 논리 회로 구성을 정의해 재구성 가능한 하드웨어에 적재하는 설정 파일임
- RTL·HLS: RTL(Register Transfer Level)은 레지스터 단위 회로 동작을 기술하는 설계 언어이고 HLS(High-Level Synthesis)는 고수준 코드를 회로로 자동 변환하는 도구임
- MAC(Multiply-Accumulate) 연산: 곱셈과 누산을 한 번에 수행하는 연산으로 신경망 행렬 연산의 기본 단위임
- 폴백(Fallback): 컴파일러가 지원하지 않는 연산을 만나면 다른 처리 장치로 실행을 넘기는 동작임

## 작성 근거(검토용)

- AI 가속기는 연산 구조, 대표 역할, 변경·개발 부담을 기준으로 비교함
- 구성요소는 범용 연산 경로, 전용 연산 배열, 메모리·인터커넥트, 컴파일러·런타임으로 정리함
- 원리는 요구사항 정의부터 배치 결정까지 선정 절차로 설명함
- 실무 판단은 학습 처리량, 장치 사용률, p95 추론 지연, 추론당 소비 전력으로 구체화함

## Ⅰ. 개요

- **정의/개념**: AI 가속기 비교는 신경망 처리 하드웨어를 연산 구조, 전력 효율, 유연성, 운영 목적 기준으로 구분해 적합한 배치 위치를 결정하는 작업임
- **배경/필요성**: 학습, 서버 추론, 온디바이스 추론은 지원 연산·전력·지연·배포 수량이 달라 같은 기준으로 가속기를 선택할 수 없음

### 쉽게 이해하기 (학습용)
- 이사할 때 짐 종류와 목적지 거리에 따라 트럭·오토바이·손수레 중 무엇을 쓸지 고르는 것과 같음

## Ⅱ. 특징

- CPU는 범용 명령과 분기를 처리하고 AI 파이프라인의 제어·전후처리를 담당함
- GPU는 SIMT 커널과 텐서 연산기를 사용해 학습과 서버 추론을 처리함
- NPU와 ASIC은 지원 신경망 연산을 전용 배열에 배치하며 비지원 연산은 다른 장치에서 실행함
- FPGA는 비트스트림으로 연산 경로를 바꿀 수 있지만 합성·배치배선·타이밍 검증이 필요함

### 쉽게 이해하기 (학습용)
- 잡무를 처리하는 총괄 직원(CPU), 같은 작업을 여러 명이 동시에 하는 작업조(GPU), 정해진 일만 하는 전담 기계(NPU·ASIC), 배선을 다시 깔아야 하는 조립식 라인(FPGA)의 차이임

## Ⅲ. 종류 및 비교

| 판단 기준 | CPU | GPU | NPU | FPGA | ASIC |
|:---|:---|:---|:---|:---|:---|
| 연산 구조 | 범용 명령 실행 | SIMT 병렬 실행 | 신경망 전용 배열 실행 | 재구성 논리 실행 | 고정 데이터플로우 실행 |
| 대표 역할 | 제어·전후처리 | AI 학습·서버 추론 | 온디바이스 추론 | 지연 상한이 있는 추론 | 설계 범위의 학습·추론 |
| 변경·개발 부담 | 코드 작성·컴파일 | 커널 작성·컴파일 | 지원 범위 안에서 모델 변환·컴파일 | 비트스트림 재작성·RTL·HLS 재검증 | 회로 재설계·재검증·재제작 |

> 요약: GPU는 학습·서버 추론, NPU는 온디바이스 추론, FPGA는 재구성 추론, ASIC은 설계 범위가 고정된 학습·추론에 적용함.

### 쉽게 이해하기 (학습용)
- 도보, 오토바이, 트럭, 개조 가능한 컨테이너, 전용 화물기 다섯 운송수단이 각각 어디에 어울리는지 고르는 것과 같음

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 범용 연산 경로 | CPU·GPU의 명령 제어 구조가 다양한 연산과 분기를 처리함 |
| 전용 연산 배열 | NPU·ASIC의 MAC 배열과 저정밀 연산기가 반복 신경망 연산을 처리함 |
| 메모리·인터커넥트 | HBM·SRAM·PCIe·NVLink가 연산기에 데이터를 공급하고 장치 간 결과를 교환함 |
| 컴파일러·런타임 | 모델을 지원 연산에 매핑하고 비지원 연산의 폴백 경로를 관리함 |

> 요약: 연산 구조와 메모리·인터커넥트가 처리 경로를 정하고 컴파일러·런타임이 지원 연산과 폴백을 배치함.

### 쉽게 이해하기 (학습용)
- 여러 일을 다 하는 도로(범용 연산 경로), 한 가지 물건만 빠르게 나르는 전용 컨베이어(전용 연산 배열), 물건을 공급하는 파이프라인(메모리·인터커넥트), 배차를 정하는 관제실(컴파일러·런타임)이 함께 동작함

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 요구사항 정의  | --> | 후보 압축      | --> | 벤치마크 검증  | --> | 배치 결정      |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **요구사항 정의**: 워크로드의 연산 형태, 지연 목표, 전력 한도를 정의함
2. **후보 압축**: 지원 연산 범위와 개발 기간 제약으로 CPU·GPU·NPU·FPGA·ASIC 후보를 좁힘
3. **벤치마크 검증**: 실제 모델로 처리량, 추론 지연, 소비 전력을 측정함
4. **배치 결정**: 측정 결과를 기준으로 학습, 서버 추론, 온디바이스 추론 위치를 정함

> 요약: 워크로드 요구사항으로 후보를 좁히고 벤치마크 측정 결과로 배치 위치를 결정함.

### 쉽게 이해하기 (학습용)

## Ⅵ. 실무 사례

1. 대규모 학습 클러스터는 GPU 간 통신 링크와 병렬화 방식을 함께 구성하고 학습 처리량과 장치 사용률을 확인함
2. 스마트 카메라는 실제 모델을 NPU·FPGA 후보에서 실행해 p95 추론 지연·추론당 소비 전력을 비교함

### 쉽게 이해하기 (학습용)
- 대량 화물은 트럭 여러 대를 연결해 옮기고, 소형 배송은 오토바이와 자전거 중 더 빠른 쪽을 실제로 비교해 고름

## Ⅶ. 결론

- AI 가속기는 연산 구조·전력 효율·유연성·운영 목적에 따라 CPU·GPU·NPU·FPGA·ASIC으로 나뉘며, 같은 신경망 연산도 배치 위치에 따라 적합한 장치가 다름
- 학습·서버 추론·온디바이스 추론처럼 목적이 다르면 지원 연산, 전력·지연 한도, 배포 수량을 벤치마크로 검증해 장치를 선택해야 함

### 쉽게 이해하기 (학습용)
- 운송수단을 고를 때 짐 종류뿐 아니라 연료, 도로 폭, 대수까지 함께 따져야 하는 것과 같음
