# 📖 【암기용】 개념 완전 이해

> 목적: 5가지 AI 가속기를 처음 봐도 왜 서로 다른 용도로 쓰이는지 한 축으로 비교해 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: AI 연산을 처리하는 다섯 하드웨어(CPU·GPU·NPU·FPGA·ASIC)를 유연성-전력효율 축 위에 배치해 비교하는 관점
- **왜 필요한가**: "빠른 하드웨어를 쓰면 된다"는 식의 판단은 시험에서 감점이다. 각 하드웨어는 유연성·개발비용·전력효율의 트레이드오프가 다르므로 워크로드 특성에 맞춰 선택해야 한다.
- **핵심 직관**: 만능 공구(CPU) -> 다목적 전동공구(GPU) -> 리모델링 가능한 전용 라인(FPGA) -> 못 하나만 박는 고정 자동화 라인(ASIC/NPU)까지, 유연성을 버릴수록 전력효율이 오른다.

## 깊이 이해
- **배경·문제의식**: 동일한 딥러닝 연산이라도 데이터센터 학습, 데이터센터 추론, 엣지 추론, 실시간 신호처리는 요구 지연·전력·개발주기가 전혀 다르다.
- **작동 원리**: CPU는 범용 스칼라+SIMD 명령어로 제어흐름이 복잡한 코드에 강하다. GPU는 SIMT로 수천 스레드를 동시 실행해 데이터 병렬 연산(행렬곱 포함)에 강하다. NPU는 모바일 SoC에 내장된 저전력 추론 전용 회로다(053번 키워드 참고). FPGA는 논리 게이트를 재구성 가능한 회로(reconfigurable logic)로, 커스텀 파이프라인을 하드웨어 수준에서 다시 구성할 수 있다. ASIC은 특정 연산만을 위해 설계를 굳힌 고정 회로로 TPU가 대표적 사례다(052번 키워드 참고).
- **비유**: CPU=만능 스위스 아미 나이프, GPU=다목적 전동드릴, FPGA=배선을 다시 꽂을 수 있는 조립식 회로판, ASIC=한 번 찍어낸 전용 금형.
- **구체 예시**: 동일한 이미지 분류 추론을 서버에서는 GPU/TPU로, 스마트폰에서는 NPU로, 통신 장비 실시간 신호처리는 FPGA로, 대량 양산 IoT 센서는 커스텀 ASIC으로 각각 배치한다.
- **흔한 오해·주의점**: "ASIC이 항상 가장 빠르다"는 조건부로만 맞다. ASIC은 설계를 굳힌 특정 연산에서만 최고 효율을 내고, 알고리즘이 바뀌면 재설계(수개월~수년, 높은 NRE(Non-Recurring Engineering) 비용)가 필요해 유연성이 0에 가깝다.

## 연결 개념
- GPU SIMT(050번 키워드) — 범용 병렬 연산 구조
- TPU(052번), NPU(053번) — ASIC 계열의 대표 특화 사례
- FPGA AI 가속(048번), ASIC AI 가속(049번) — 개별 상세 키워드
- NRE(Non-Recurring Engineering) 비용 — ASIC 설계 시 발생하는 일회성 개발비

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 5종 가속기 답안은 유연성-전력효율 스펙트럼, 개발비용(NRE), 워크로드별 배치 기준을 함께 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: CPU·GPU·NPU·FPGA·ASIC은 유연성과 전력효율이 반비례하는 스펙트럼 위에서 서로 다른 위치를 차지하는 AI 연산 하드웨어군이다.
> 2. **가치**: 워크로드의 정형성(algorithm 고정 여부)과 전력·지연 제약에 맞춰 하드웨어를 선택하면 동일 전력에서 처리량을 극대화할 수 있다.
> 3. **판단 포인트**: 범용성이 필요하면 CPU/GPU, 특화 효율이 필요하면 NPU/ASIC, 그 중간의 재구성 가능성이 필요하면 FPGA를 선택 기준으로 삼는다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 5종 가속기 특성 분류 역량 확인 | 유연성·전력효율·개발비용(NRE) 축 비교 | 5종을 성능 서열로만 나열(예: GPU>CPU) |
| 워크로드-하드웨어 매칭 판단 확인 | 학습/추론/엣지/실시간 신호처리별 적합 하드웨어 | 워크로드 특성 없이 하드웨어 이름만 나열 |
| 트레이드오프 이해 확인 | ASIC 고효율 vs 재설계 비용, FPGA 재구성성 vs 상대적 저효율 | "ASIC이 항상 최선"처럼 조건 없는 단정 |

> 요약: 이 문제는 하드웨어 나열이 아니라 유연성-전력효율 트레이드오프와 워크로드 매칭 기준을 요구한다.

## Ⅰ. 개요 및 필요성

- 정의: AI 연산 하드웨어를 유연성과 전력효율의 트레이드오프 관점에서 CPU·GPU·NPU·FPGA·ASIC 다섯 갈래로 비교하는 체계
- 배경: 동일 딥러닝 연산도 학습·데이터센터 추론·엣지 추론·실시간 신호처리마다 지연·전력·개발주기 요구가 다름
- 필요성: 하드웨어 선택 오류는 과도한 전력 소모나 과도한 개발비용(NRE)으로 이어지므로 워크로드 특성 기반 선택 기준이 필요함

---

## Ⅱ. 구조 및 구성요소

```text
유연성 高 -----------------------------------------> 전력효율 高
CPU(범용 스칼라+SIMD)
  -> GPU(SIMT 대규모 병렬)
    -> FPGA(재구성 가능 로직)
      -> NPU(엣지 추론 특화 ASIC 계열)
        -> ASIC(단일 연산 고정 회로, 예: TPU)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| CPU | 범용 제어흐름·순차 연산 처리 | 분기·조건문이 많은 코드에 유리 |
| GPU | SIMT 기반 대규모 데이터 병렬 연산 | 학습·대규모 추론, CUDA/OpenCL 생태계 |
| NPU | 모바일·엣지 SoC 내장 저전력 추론 | INT8/INT4 양자화, TOPS/W 지표 |
| FPGA | 재구성 가능한 로직으로 커스텀 파이프라인 구현 | 재프로그래밍 가능, ASIC보다 개발기간 짧음 |
| ASIC | 특정 연산 전용 고정 회로 | 최고 전력효율, 높은 NRE 비용과 긴 개발기간 |

> 요약: 다섯 하드웨어는 유연성을 버릴수록 전력효율이 오르는 스펙트럼 위에 배치되며 개발비용도 함께 증가한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
워크로드 특성 분석(정형성/전력제약/지연요구)
  -> 정형 반복 연산 + 대량 양산 -> ASIC/NPU 검토
  -> 알고리즘 변경 가능성 존재 -> FPGA 검토
  -> 범용성·개발생산성 우선 -> GPU/CPU 검토
  -> 하드웨어 선정 -> 개발비용(NRE)·전력·성능 지표 확정
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 워크로드의 정형성·전력·지연 요구 분석 | 알고리즘 변경 빈도, 전력 예산 |
| 2 | 재구성 필요성 판단(FPGA 여부) | 알고리즘 업데이트 주기 |
| 3 | 양산 규모·전력효율 요구 판단(ASIC/NPU 여부) | 생산 수량, TOPS/W 목표 |
| 4 | 범용성·개발생산성 요구 판단(CPU/GPU 여부) | 개발기간, 프레임워크 지원 |

> 요약: 하드웨어 선택은 워크로드의 정형성과 전력·지연 제약을 먼저 분석한 뒤 유연성-효율 스펙트럼에서 위치를 정하는 순서로 진행한다.

## Ⅳ. 특징

| 구분 | CPU | GPU | NPU | FPGA | ASIC |
|:---|:---|:---|:---|:---|:---|
| 유연성 | 최고(범용 명령어) | 높음(프로그래밍 가능 SIMT) | 낮음(고정 추론 파이프라인) | 중간(재구성 가능 로직) | 최저(설계 고정) |
| 전력효율 | 낮음 | 중간 | 높음(TOPS/W 특화) | 중간~높음 | 최고(특정 연산 한정) |
| 개발비용·기간 | 낮음(기존 코드 재사용) | 낮음~중간(CUDA/OpenCL) | 중간(양자화·컴파일 필요) | 중간(HDL/HLS 설계) | 최고(마스크 제작, 수개월~수년) |
| 대표 사례 | 범용 서버·PC 연산 | 학습·대규모 추론(050번) | 모바일 추론(053번) | 통신 신호처리, 재구성 가속(048번) | TPU(052번), 전용 추론 칩 |

> 요약: 유연성은 CPU가, 전력효율은 ASIC이 극단을 차지하며 GPU·FPGA·NPU는 그 사이에서 각기 다른 절충점을 갖는다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 범용형(CPU/GPU) | 특화형(NPU/ASIC) | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 프로그래밍 가능, 알고리즘 변경 용이 | 고정 회로, 특정 연산만 최적화 | 알고리즘 변경 빈도가 높으면 범용형 |
| 비용/성능 | 초기 개발비 낮음, 전력효율 상대적으로 낮음 | 초기 NRE 높음, 대량 양산 시 단가·전력효율 우수 | 생산 수량과 전력 예산으로 손익분기 판단 |
| 운영/위험 | 유연한 업데이트 가능 | 설계 오류 시 재설계 비용 막대 | FPGA를 중간 검증 단계로 활용하는 전략 검토 |

> 요약: 알고리즘이 안정화되고 대량 양산이 확정된 경우에만 ASIC/NPU 전환을 검토하고, 그 전까지는 GPU/FPGA로 검증한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| ASIC 설계 오류 | 테이프아웃 이후 알고리즘 결함 발견 | FPGA 프로토타이핑으로 사전 검증 | 검증 커버리지, 시뮬레이션 일치율 |
| 하드웨어 과투자 | 워크로드 규모 대비 과도한 특화 하드웨어 도입 | 워크로드 프로파일링 후 단계적 도입 | ROI, 가동률(utilization) |
| 벤더 종속 | 특정 생태계(CUDA 등)에 종속된 개발 | 프레임워크 추상화 계층 유지 | 이식 소요 시간 |

> 요약: 특화 하드웨어 도입 리스크는 설계 검증 부족과 과투자이며 FPGA 프로토타이핑과 단계적 도입으로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 성능 | 목표 처리량(TOPS/FLOPS) 달성 여부 | 벤치마크, 프로파일러 |
| 전력효율 | TOPS/W 또는 FLOPS/W 목표치 달성 | 전력 측정 장비 |
| 개발 ROI | NRE 대비 양산 단가 절감 손익분기 | 원가 분석, 생산 수량 시뮬레이션 |

> 요약: 도입 성과는 처리량, 전력효율, NRE 대비 ROI 세 지표로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 알고리즘이 자주 바뀌는 R&D·범용 서비스는 CPU/GPU로 개발 생산성을 우선 확보함
2. 대량 양산·전력 제약이 뚜렷한 엣지 추론은 NPU를, 알고리즘이 고정된 대규모 정형 연산은 ASIC(TPU 등)을 검토함
3. 알고리즘이 완전히 고정되지 않았지만 커스텀 파이프라인이 필요한 경우 FPGA로 프로토타이핑 후 ASIC 전환 여부를 판단함

**결론 (2줄):**
- 기술사 판단: 유연성이 필요하면 CPU/GPU, 전력효율이 필요하면 NPU/ASIC, 중간 단계 검증에는 FPGA를 선택 기준으로 삼음
- 향후 방향: 칩렛(058번)·UCIe(059번) 기반 이종 통합으로 하나의 패키지 안에 CPU·GPU·NPU·ASIC 다이를 혼합 배치하는 방향으로 발전함
