## 미리 알고가기

- SoC는 CPU와 GPU와 NPU와 메모리와 I/O를 하나의 칩에 통합한 구조임
- 온디바이스 AI는 클라우드로 보내지 않고 단말 내부에서 추론을 수행하는 방식임
- TOPS는 연산량 지표일 뿐 실제 성능은 메모리와 발열과 모델 호환성이 더 크게 좌우함

## Ⅰ. 개요

- **정의/개념**: SoC AI 온디바이스 칩은 CPU와 GPU와 NPU와 메모리 서브시스템과 보안 블록을 단일 칩에 통합해 단말 내부에서 AI 추론을 수행하도록 설계한 시스템 반도체임
- **배경/필요성**: 모바일과 차량과 IoT 단말은 지연과 네트워크 비용과 개인정보 문제 때문에 클라우드 의존을 줄여야 하므로, 제한된 전력과 열 예산 안에서 AI 추론을 처리할 수 있는 칩 구성이 필요함

## Ⅱ. 특징

- NPU 중심으로 추론을 오프로딩해 CPU 대비 전력 효율을 높임
- 메모리 대역폭과 on-chip buffer 구조가 실제 지연을 크게 좌우함
- 연산자 호환성과 양자화 지원 수준이 활용 가능한 모델 범위를 결정함
- secure boot와 모델 보호와 OTA 업데이트 체계가 제품 수명주기 품질을 좌우함

## Ⅲ. 종류 및 비교

| 판단 기준 | 클라우드 AI 처리 | 온디바이스 AI SoC |
|:---|:---|:---|
| 지연 경로 | 단말·네트워크·서버 왕복과 서버 대기 포함 | 단말의 NPU·메모리·CPU 처리 시간 포함 |
| 개인정보 | 원본 데이터 외부 전송 부담이 큼 | 로컬 처리로 데이터 노출 범위를 줄일 수 있음 |
| 자원 제약 | 서버 자원을 유연하게 확장할 수 있음 | 전력과 열과 메모리 제약 안에서 모델을 맞춰야 함 |
| 운영 포인트 | 서버 확장과 비용 관리가 중요함 | 모델 경량화와 칩 호환성과 업데이트 관리가 중요함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| CPU·GPU | 전처리와 후처리와 범용 제어를 맡아 NPU가 처리하지 않는 작업을 보완함 |
| NPU | CNN과 Transformer 연산을 높은 전력 효율로 처리하는 중심 연산기임 |
| 메모리 서브시스템 | 가중치와 activation 공급을 담당하며 실제 병목이 되기 쉬운 경로임 |
| 보안·전력 블록 | 모델 무결성 검증과 DVFS 제어를 담당해 보안성과 배터리 수명을 좌우함 |

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 모델 준비      | --> | 칩 맞춤 최적화 | --> | 추론 실행      | --> | 결과·업데이트  |
+-------------+     +-------------+     +-------------+     +-------------+
```

## Ⅴ. 원리 및 절차 흐름도

1. **모델 준비**: 목표 정확도와 입력 크기와 지연 요구에 맞는 모델을 선정함
2. **칩 맞춤 최적화**: 양자화와 연산자 매핑으로 모델을 NPU 형식에 맞춤 변환함
3. **추론 실행**: NPU와 메모리와 DMA와 CPU가 협력해 추론 파이프라인을 수행함
4. **결과·업데이트**: 후처리와 보안 검증과 OTA 모델 갱신을 운영함

## Ⅵ. 실무 적용 및 유의점

1. 스마트폰과 엣지 카메라는 단말 NPU에서 추론해 네트워크 왕복을 제거하되, NPU 미지원 연산자는 CPU 우회 처리 비율을 높이므로 타깃 NPU에 맞춘 모델 설계와 양자화를 적용하고 NPU 처리 비율과 우회 처리 비율과 추론 지연시간으로 확인함
2. 차량과 모바일 단말은 높은 TOPS보다 메모리 이동과 발열과 모델 보호가 더 큰 문제이므로 버퍼 재사용과 DVFS와 보안 부팅 기반 모델 보호를 함께 운영하고 전력당 추론 횟수와 열 쓰로틀링 발생률과 모델 변조 탐지율로 확인함

## Ⅶ. 결론

온디바이스 AI SoC의 실질 가치는 TOPS 숫자보다 모델 호환성과 메모리 경로와 전력·보안 체계를 얼마나 균형 있게 통합했는지에 있음.
