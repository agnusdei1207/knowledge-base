# 📖 【암기용】 개념 완전 이해

> 목적: FTL을 처음 봐도 SSD가 왜 HDD처럼 그냥 덮어쓰지 못하고 이런 소프트웨어 계층이 필요한지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: SSD 컨트롤러 펌웨어에서 호스트의 논리 주소(LBA)를 NAND 플래시의 물리 주소로 변환하고, 마모도·불량 블록·가비지 컬렉션을 관리하는 계층
- **왜 필요한가**: NAND 플래시는 페이지 단위로만 쓰고 블록 단위로만 지울 수 있어 HDD처럼 임의 위치를 바로 덮어쓸 수 없는데, FTL이 이 제약을 감추고 호스트에는 일반 블록 장치처럼 보이게 한다
- **핵심 직관**: 이미 글씨가 쓰인 페이지에 새 글을 쓰려면 페이지를 통째로 지우개로 지워야 하는 노트에서, 비서가 항상 빈 페이지를 찾아 대신 써주고 다 쓴 페이지는 몰래 정리해주는 것과 같다

## 깊이 이해
- **배경·문제의식**: NAND 플래시는 쓰기는 페이지(수KB) 단위, 지우기는 블록(수백 페이지 묶음) 단위로만 가능하고 이미 쓰인 페이지에 바로 덮어쓸 수 없어(erase-before-write), 호스트가 이 특성을 그대로 다루면 파일시스템 설계가 매우 복잡해진다.
- **작동 원리**: FTL은 호스트가 보내는 LBA(Logical Block Address)를 물리 페이지 주소로 매핑하는 주소 변환 테이블을 유지하고, 데이터를 수정할 때는 원래 페이지를 지우지 않고 새 빈 페이지에 써넣은 뒤 매핑을 갱신하며, 이전 페이지는 무효(invalid)로 표시한다.
- **가비지 컬렉션(GC)**: 무효 페이지가 쌓인 블록은 유효한 페이지만 다른 블록으로 복사한 뒤 원래 블록 전체를 지워 재사용 가능한 빈 블록으로 만드는 과정을 거치며, 이 과정에서 실제 NAND에 쓰이는 데이터량이 호스트가 요청한 양보다 늘어나는 쓰기 증폭(Write Amplification)이 발생한다.
- **마모도 평준화(Wear Leveling)**: NAND 셀은 P/E 사이클(Program/Erase Cycle) 한계가 있어(SLC 약 10만 회, MLC 약 3천~1만 회, TLC 약 1천~3천 회, QLC 약 수백~1천 회 수준으로 알려짐) FTL은 특정 블록에 쓰기가 몰리지 않도록 전체 블록에 걸쳐 쓰기 횟수를 고르게 분산시킨다.
- **불량 블록 관리(Bad Block Management)**: 출하 시 또는 사용 중 발생하는 불량 블록을 감지해 예비 블록(Spare/Over-Provisioning 영역)으로 대체하는 것도 FTL의 책임이다.
- **비유**: FTL은 "이미 쓰인 페이지는 지우개로 지우지 않고 새 페이지에 옮겨 쓰며, 오래된 페이지들이 쌓이면 밤사이 몰래 정리(GC)하고, 특정 페이지만 닳지 않도록 사용 페이지를 순환(마모도 평준화)시키는" 비서 역할을 한다.
- **흔한 오해·주의점**: "SSD는 파일을 삭제하면 즉시 물리적으로 지워진다"는 오해가 있으나, 실제로는 TRIM 명령으로 무효 페이지임을 FTL에 알려줄 뿐이고 실제 물리적 삭제(블록 단위 erase)는 가비지 컬렉션 시점에 이뤄진다는 점을 구분해야 한다.

## 연결 개념
- NAND Flash·3D V-NAND — FTL이 관리하는 물리 저장 매체
- Wear Leveling·Garbage Collection — FTL의 핵심 책임 기능
- 쓰기 증폭(Write Amplification) — FTL 설계 품질을 나타내는 지표
- TRIM 명령 — 호스트가 무효 데이터를 FTL에 알리는 인터페이스

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: FTL은 기능 나열이 아니라, NAND의 erase-before-write 제약이 만드는 문제와 이를 해결하는 매핑·GC·마모도 평준화의 인과관계를 축으로 답안을 구성한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: FTL은 NAND 플래시의 페이지 쓰기·블록 지우기 제약을 감추고 호스트에 일반 블록 장치처럼 보이게 하는 SSD 컨트롤러의 소프트웨어 계층이다.
> 2. **가치**: 주소 변환·가비지 컬렉션·마모도 평준화·불량 블록 관리로 SSD의 수명과 성능을 동시에 확보한다.
> 3. **판단 포인트**: FTL 설계 품질은 쓰기 증폭 계수(WAF)로 정량 평가되며, 매핑 방식(페이지/블록/하이브리드)과 오버프로비저닝 비율이 이를 좌우한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| NAND 제약과 FTL 필요성 인과관계 확인 | erase-before-write 제약 → 주소 변환 필요성 | FTL을 단순 "관리 계층"으로만 추상 서술 |
| 핵심 기능 이해 확인 | 가비지 컬렉션, 마모도 평준화, 불량 블록 관리 3대 책임 | 기능 중 일부 누락 또는 혼동 |
| 성능 지표 이해 확인 | 쓰기 증폭 계수(WAF), 오버프로비저닝 | GC를 성능 저하 원인으로만 서술하고 필요성 누락 |

> 요약: 이 문제는 FTL 명칭 암기가 아니라 NAND 제약-FTL 대응-성능 지표(WAF)로 이어지는 인과관계를 확인한다.

## Ⅰ. 개요 및 필요성

- 정의: SSD 컨트롤러 펌웨어에서 논리 주소를 NAND 물리 주소로 변환하고 GC·마모도 평준화·불량 블록 관리를 수행하는 계층
- 배경: NAND는 페이지 쓰기·블록 지우기 단위가 달라 기존 위치에 바로 덮어쓸 수 없는 erase-before-write 제약이 있음
- 필요성: 이 제약을 호스트로부터 감추고 SSD 수명(P/E 사이클)과 성능을 동시에 확보하기 위해 FTL이 필수

---

## Ⅱ. 구조 및 구성요소

```text
Host: LBA 기반 Read/Write 요청
  -> FTL
       / 주소 변환 테이블(Page/Block/Hybrid Mapping)
       / Garbage Collection 엔진
       / Wear Leveling 엔진
       / Bad Block Manager
  -> NAND Flash Array (Page 쓰기 / Block 지우기)
```

| 구성요소 | 역할 | 산출물 |
|:---|:---|:---|
| 주소 변환 테이블 | LBA를 물리 페이지 주소로 매핑 | 매핑 갱신 이력 |
| Garbage Collection 엔진 | 무효 페이지 회수, 블록 재사용 | 재사용 가능 빈 블록 |
| Wear Leveling 엔진 | 블록별 P/E 사이클 균등 분산 | 블록별 사용 횟수 통계 |
| Bad Block Manager | 불량 블록 감지·대체 | 예비 블록 매핑 |

> 요약: FTL은 주소 변환을 중심으로 GC·마모도 평준화·불량 블록 관리를 결합해 NAND 제약을 감춘다.

---

## Ⅲ. 동작원리 및 흐름도

```text
Host Write(LBA) -> FTL 주소 변환 테이블 조회
  -> 기존 페이지 무효화 표시
  -> 새 빈 페이지에 데이터 기록, 매핑 갱신
  -> 무효 페이지 비율 임계치 초과 블록 탐지
  -> Garbage Collection: 유효 페이지 이동 -> 원블록 Erase
  -> Wear Leveling: 사용 횟수 낮은 블록으로 배치 유도
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | Host 쓰기 요청 시 LBA를 새 물리 페이지에 매핑 | 매핑 갱신 정확성 |
| 2 | 기존 페이지를 무효(invalid)로 표시 | TRIM 반영 여부 |
| 3 | 무효 페이지 비율 임계치 초과 블록에서 GC 수행 | 쓰기 증폭 계수(WAF) |
| 4 | 마모도 평준화로 블록별 P/E 사이클 분산 | 블록 간 사용 횟수 편차 |

> 요약: FTL은 매핑-무효화-GC-마모도 평준화 사이클을 반복하며 NAND 제약 속에서 논리적 덮어쓰기를 구현한다.

## Ⅳ. 특징

| 구분 | 페이지 매핑 | 블록 매핑 | 하이브리드 매핑 |
|:---|:---|:---|:---|
| 매핑 단위 | 페이지 단위 세밀 매핑 | 블록 단위 매핑 | 로그 블록 + 블록 매핑 혼합 |
| DRAM 사용량 | 매핑 테이블 크기 커서 DRAM 요구량 높음 | 상대적으로 낮음 | 중간 수준 |
| GC 효율 | 세밀한 회수로 WAF 낮음 | 블록 단위 재기록으로 WAF 높음 | 균형점 지향 |
| 대표 적용 | 고성능 엔터프라이즈 SSD | 초기 저비용 SSD | 과거 세대 절충형 SSD |

> 요약: 매핑 방식은 DRAM 사용량과 쓰기 증폭 사이의 트레이드오프이며, 현대 SSD는 대체로 세밀한 페이지 매핑 기반을 채택한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | HDD(단순 덮어쓰기) | SSD + FTL | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 임의 위치 직접 덮어쓰기 | 새 페이지 기록 + 매핑 갱신 | 랜덤 쓰기 성능 요구 수준 |
| 비용/성능 | 기계적 탐색 지연 존재 | 낮은 지연, GC로 인한 순간 성능 저하 가능 | 지속 쓰기 워크로드 여부 |
| 운영/위험 | 기계적 고장(헤드·모터) | P/E 사이클 소진, WAF 관리 필요 | 쓰기 집약도, 오버프로비저닝 비율 |

> 요약: 랜덤 I/O·저지연이 중요한 워크로드는 SSD+FTL이 유리하나, WAF와 P/E 사이클 소진을 함께 관리해야 한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 쓰기 증폭 심화 | 무효 페이지 비율 증가, 낮은 오버프로비저닝 | 오버프로비저닝 확대, TRIM 적극 활용 | 쓰기 증폭 계수(WAF) |
| 마모 편중 | 특정 블록에 쓰기 집중 | Wear Leveling 정책 강화 | 블록별 P/E 사이클 편차 |
| 불량 블록 증가 | 셀 열화, 미세공정 신뢰성 저하 | 예비 블록 확보, ECC 강화 | 불량 블록 발생률, ECC 정정률 |

> 요약: FTL 운영 리스크는 쓰기 증폭, 마모 편중, 불량 블록 증가이며 오버프로비저닝과 ECC로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 쓰기 증폭 계수 | 목표 WAF 낮게 유지 | SMART 로그, 컨트롤러 통계 |
| 수명 소모율 | P/E 사이클 잔여율 관리 | SMART Media Wearout Indicator |
| 지연시간 | GC 발생 시에도 p99 지연 목표 준수 | 스토리지 성능 모니터링 |

> 요약: 도입 후 성공 여부는 쓰기 증폭 계수, P/E 사이클 잔여율, GC 발생 시 지연시간으로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 쓰기 집약적 워크로드는 오버프로비저닝 비율을 높여 쓰기 증폭 계수를 낮추고 SSD 수명을 확보함
2. 파일 삭제 시 TRIM 명령이 파일시스템·OS 계층까지 전달되도록 구성해 GC 효율을 높임
3. SMART 지표(WAF, Media Wearout, 불량 블록 수)를 상시 모니터링해 교체 시점을 사전 판단함

**결론 (2줄):**
- 기술사 판단: FTL은 NAND의 물리적 제약을 감추는 필수 계층이며, 매핑 방식과 오버프로비저닝 비율 선택이 성능·수명의 핵심 트레이드오프임
- 향후 방향: QLC·PLC 등 셀당 비트 수 증가로 P/E 사이클이 줄어드는 추세에 맞춰 FTL의 GC·마모도 평준화 알고리즘 정교화가 더 중요해질 전망임
