## 미리 알고가기

- **휘발성 메모리(Volatile Memory)**: 전원 공급이 중단되면 저장된 데이터가 사라지는 메모리 (RAM의 공통적 특성)
- **커패시터(Capacitor)**: 전하를 저장하는 장치. DRAM에서 데이터를 보관하는 핵심 요소이나 시간이 지나면 전하가 누설됨
- **리프레시(Refresh)**: DRAM의 커패시터에서 누설되는 전하를 보충하기 위해 주기적으로 데이터를 다시 읽고 써주는 과정
- **플립플롭(Flip-Flop)**: 두 개의 안정된 상태 중 하나를 유지하는 논리 회로. SRAM에서 데이터를 보존하는 방식

## Ⅰ. 개요

- **정의/개념**: DRAM(Dynamic RAM)은 커패시터에 전하를 저장하여 비트를 표현하며 주기적인 리프레시가 필요한 고집적 메모리이고, SRAM(Static RAM)은 플립플롭 회로를 통해 전원이 공급되는 동안 리프레시 없이 데이터를 유지하는 고속 메모리임
- **배경/필요성**: 컴퓨터 시스템은 방대한 데이터를 담을 저렴한 공간(DRAM)과 CPU의 연산 속도를 보조할 극도로 빠른 공간(SRAM)을 동시에 필요로 함. 두 메모리는 구조적 차이에 따른 상보적 특성을 가지며, 메모리 계층 구조의 서로 다른 층위를 담당하여 시스템 전체의 효율성을 최적화함

## Ⅱ. 특징 및 비교

### 가. DRAM과 SRAM의 핵심 하드웨어 특성 비교

| 구분 | DRAM (Dynamic RAM) | SRAM (Static RAM) |
|:---|:---|:---|
| 저장 원리 | 커패시터(Capacitor) 전하 축적 | 플립플롭(Flip-Flop) 논리 상태 유지 |
| 셀 구조 | 1개 트랜지스터 + 1개 커패시터 (1T1C) | 6개 트랜지스터 (6T) |
| 리프레시 | 주기적으로 반드시 필요함 | 필요 없음 |
| 속도 (지연) | 상대적으로 느림 (수십 ns) | 매우 빠름 (수 ns) |
| 집적도 | 매우 높음 (대용량화 용이) | 낮음 (면적을 많이 차지함) |
| 소비 전력 | 동작 시 낮으나 리프레시 전력 소모 | 동작 시 높으나 대기 시 낮음 |
| 가격 (비용) | 저렴함 | 매우 비쌈 |
| 주요 용도 | 주기억장치 (Main Memory) | 캐시 메모리 (L1, L2, L3) |

> 요약: DRAM은 '용량과 경제성'에, SRAM은 '속도와 안정성'에 최적화된 설계임

### 나. 리프레시(Refresh)의 영향
- **DRAM**: 전하가 자연 누설되므로 수 밀리초(ms)마다 데이터를 재충전해야 하며, 이 동안에는 데이터 접근이 제한되어 성능 손실이 발생함
- **SRAM**: 전원이 켜져 있는 동안은 상태가 고정되므로 별도의 충전 시간이 필요 없어 즉각적인 데이터 응답이 가능함

## Ⅲ. 구성요소/구조

### 가. 메모리 계층에서의 배치 구조

```text
[CPU Core] <--- (L1/L2 Cache: SRAM) --- (L3 Cache: SRAM) --- (Main Mem: DRAM)

1. CPU 연산: 레지스터와 SRAM 캐시를 통해 즉각적인 피연산자 획득
2. 데이터 적재: 캐시 Miss 시 DRAM에서 블록 단위로 데이터를 SRAM으로 전송
3. 상호 보완: SRAM의 속도로 CPU를 돌리고, DRAM의 용량으로 데이터를 보관함
```

### 나. 주요 구성 요소 및 역할

| 구성요소 | 역할 및 설명 | 핵심 포인트 |
|:---|:---|:---|
| 1T1C 셀 (DRAM) | 데이터를 담는 가장 작은 물리적 단위 | 커패시터의 크기가 작아질수록 공정 난이도 급증 |
| 6T 셀 (SRAM) | 6개의 트랜지스터로 구성된 안정된 회로 | 면적 효율보다는 속도 응답성에 올인한 구조 |
| 메모리 컨트롤러 | CPU의 요청을 받아 DRAM 행/열 제어 및 리프레시 수행 | 리프레시 오버헤드 관리가 성능의 핵심 |
| 감지 증폭기 (SA) | DRAM 커패시터의 미세한 전하 차이를 읽어내는 증폭기 | 읽기 동작 후 데이터를 재기록(Precharge)하는 역할 |

> 요약: SRAM은 회로 자체의 논리로, DRAM은 전하라는 물리적 양으로 정보를 유지하는 차이가 있음

## Ⅳ. 문제점 및 개선방안

1. **DRAM의 성능 한계 (Memory Wall)**: CPU 대비 느린 응답 속도와 리프레시 지연이 전체 성능의 병목이 됨
   - **개선방안**: 데이터를 수직으로 쌓아 대역폭을 극대화한 **HBM(고대역폭 메모리)** 기술을 적용하거나, 리프레시 간격을 동적으로 조절함

2. **SRAM의 면적 및 전력 비용**: 캐시 용량을 늘리고 싶어도 칩 면적을 너무 많이 차지하고 누설 전류가 발생함
   - **개선방안**: 3D 적층 기술을 통해 CPU 위에 SRAM을 쌓거나(V-Cache), 저전력 SRAM 설계를 통해 누설 전류를 제어함

3. **용도 한계와 트레이드오프**: 모든 메모리를 SRAM으로 만들면 가격이 수천 배로 치솟고, DRAM만 쓰면 시스템이 너무 느려짐
   - **개선방안**: L1(SRAM) - L2(SRAM) - L3(SRAM) - Main(DRAM)의 촘촘한 계층 구조를 설계하여 통계적으로 평균 접근 속도를 최적화함

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 고성능 서버 (HPC) | 수백 MB급의 L3 캐시(SRAM)를 탑재하여 메모리 접근 지연 최소화 | Cache Hit Rate, CPI (Cycles Per Instruction) |
| 그래픽 카드 (VGA) | GDDR 또는 HBM(DRAM 기반)을 사용하여 대규모 텍스처 데이터를 고속 전송 | Memory Bandwidth (GB/s) |
| 저전력 임베디드 | 리프레시 회로가 필요 없는 SRAM을 메인 메모리로 사용하여 시스템 단순화 및 전력 절감 | Standby Current, Boot Time |

> 요약: 속도가 생명인 AI/HPC는 SRAM 비중을, 데이터가 방대한 분석 장비는 DRAM 대역폭과 용량을 중시함

## Ⅵ. 결론

DRAM과 SRAM은 현대 반도체 기술이 도달한 최고의 효율성을 보여주는 상호 보완적 한 쌍임. 고집적을 위해 리프레시라는 단점을 안고 가는 DRAM과, 속도를 위해 면적 효율을 포기한 SRAM의 조합은 컴퓨터 공학의 지혜로운 타협 결과임.

기술사는 단순히 두 기술의 스펙 비교에 그치지 않고, 시스템 아키텍처 관점에서 '왜 이 위치에 이 메모리가 쓰이는가'에 대한 확고한 논리를 갖추어야 함. 특히 최근 HBM과 PIM(Processing-In-Memory)의 등장으로 DRAM의 한계를 돌파하려는 시도와, SRAM의 대안으로 떠오르는 차세대 메모리(MRAM 등)의 동향을 주시하여 미래 메모리 계층 변화에 대비해야 함.
