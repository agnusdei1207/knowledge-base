## 미리 알고가기

- DRAM: 동적 램(Dynamic Random Access Memory, DRAM)은 커패시터에 전하를 저장해 비트를 표현하며 주기적 refresh가 필요한 메모리임
- SRAM: 정적 램(Static Random Access Memory, SRAM)은 플립플롭 회로로 비트를 유지하며 전원이 공급되는 동안 refresh 없이 값을 보존하는 메모리임
- 집적도: 같은 칩 면적에 넣을 수 있는 메모리 셀 수를 의미함
- 접근 지연: 주소 요청 후 데이터가 안정적으로 읽히기까지의 시간임
- HBM: 고대역폭 메모리(High Bandwidth Memory, HBM)는 적층 DRAM으로 높은 대역폭을 제공하는 메모리 계층임

## Ⅰ. 개요

- **정의**: DRAM과 SRAM은 휘발성 반도체 메모리로, DRAM은 커패시터 기반 고집적·저비용 저장을 위해 주기적 refresh를 사용하고 SRAM은 플립플롭 기반 고속 접근을 위해 더 큰 셀 면적과 비용을 감수하는 메모리 방식임
- **배경/필요성**: 컴퓨터는 큰 용량의 작업 메모리와 매우 빠른 중앙처리장치(Central Processing Unit, CPU) 근접 저장소를 동시에 필요로 함. 두 메모리는 속도, 용량, 비용, 전력 특성이 달라 주기억장치와 캐시에 각각 배치됨
- **비유**: DRAM은 넓고 저렴하지만 계속 점검해야 하는 창고이고, SRAM은 작고 비싸지만 즉시 꺼내 쓰는 책상 서랍과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 반도체 메모리 선택 기준을 구조와 계층 관점에서 비교하는 역량 확인 | 커패시터, 플립플롭, refresh, 집적도, 캐시/주기억장치 | 단순 빠름/느림 표현, refresh 원인 누락, 용도 혼동 |

> 요약: DRAM은 용량과 비용, SRAM은 속도와 단순 접근성이 강점인 휘발성 메모리임.

## Ⅱ. 특징/비교

| 판단 기준 | DRAM | SRAM |
|:---|:---|:---|
| 저장 셀 | 트랜지스터와 커패시터 기반 | 여러 트랜지스터 플립플롭 기반 |
| 속도 | SRAM보다 느리며 행/열 접근과 refresh 영향 존재 | refresh 없이 셀 상태를 바로 읽어 접근 지연이 낮음 |
| 집적도·비용 | 고집적, 비트당 비용 낮음 | 저집적, 비트당 비용 높음 |
| 대표 용도 | 주기억장치, 그래픽 메모리, HBM | L1/L2/L3 캐시, 레지스터 파일 일부 |

> 요약: DRAM과 SRAM의 선택 기준은 셀 구조가 만드는 속도, 면적, refresh 필요성의 차이임.

- DRAM은 값이 누설되므로 refresh 회로와 타이밍 제어가 필수임
- SRAM은 refresh가 없고 지연이 낮지만 셀 면적이 커 대용량 주기억장치로 쓰기 어려움
- CPU 성능은 SRAM 캐시 적중률과 DRAM 대역폭·지연의 조합에 크게 영향을 받음

## Ⅲ. 구성요소

```text
+-----------+      +-----------+      +-----------+
| CPU       | ---> | SRAM Cache| ---> | DRAM Main |
+-----------+      +-----------+      +-----------+
                         |                 |
                         v                 v
                   +------------+    +-----------+
                   | low latency|    | high cap. |
                   +------------+    +-----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| DRAM 셀 | 전하 저장과 감지를 통해 비트를 표현하며 주기적 refresh가 필요함 | 물이 조금씩 새는 양동이 |
| SRAM 셀 | 안정된 회로 상태로 비트를 유지해 빠른 읽기·쓰기를 지원함 | 잠금장치가 있는 서랍 |
| 메모리 컨트롤러 | DRAM의 행/열 선택, refresh, 타이밍을 제어함 | 창고 입출고 관리자 |
| 캐시 컨트롤러 | SRAM 캐시의 태그 조회, 적중 판단, 교체를 수행함 | 책상 서랍 정리 담당자 |

> 요약: DRAM과 SRAM은 저장 셀 구조와 제어 방식 차이 때문에 메모리 계층에서 서로 다른 위치를 담당함.

## Ⅳ. 절차

```text
+-----------+      +-----------+      +-----------+      +-----------+
| Request   | ---> | Cache Hit | ---> | DRAM Read | ---> | Return    |
+-----------+      +-----------+      +-----------+      +-----------+
```

1. **접근 요청**: CPU가 명령어나 데이터 주소를 요청함
2. **SRAM 캐시 확인**: 캐시 태그를 조회해 적중하면 낮은 지연으로 데이터를 반환함
3. **DRAM 접근 수행**: 캐시 miss 시 메모리 컨트롤러가 DRAM 행/열을 활성화해 데이터를 읽음
4. **계층 상태 갱신**: 가져온 캐시 라인을 SRAM에 배치하고 교체·쓰기 정책을 반영함

> 요약: 실제 시스템은 SRAM 캐시로 빠른 접근을 제공하고 miss 시 DRAM의 큰 용량을 활용하는 흐름으로 동작함.

## Ⅴ. 문제점 및 개선방안

- **P1 DRAM 지연 병목**: 캐시 miss가 많으면 DRAM 접근 지연과 대역폭 한계가 CPU 성능을 제한함
- **P1 대응**: locality 개선과 메모리 병렬성을 높여 DRAM 접근을 줄임 (확인: 최종 레벨 캐시(Last-Level Cache, LLC) miss와 memory stall)
- **P2 refresh 전력·가용성 부담**: DRAM은 refresh로 전력과 시간 자원을 사용하며 고밀도 환경에서 영향이 커짐
- **P2 대응**: refresh 스케줄 최적화와 저전력 DRAM 모드를 적용함 (확인: refresh overhead와 전력)
- **P3 SRAM 면적 비용**: 캐시 용량을 크게 늘리면 칩 면적, 누설 전력, 수율 비용이 증가함
- **P3 대응**: 캐시 용량보다 적중률 개선 효과가 큰 구조를 우선 선택함 (확인: 성능 대비 면적 비용)

> 요약: 두 메모리의 한계는 계층 설계와 접근 패턴 최적화로 완화해야 함.

## Ⅵ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| CPU 캐시 설계 | L1/L2/L3는 SRAM으로 구성하고 용량 증설보다 hit rate 대비 면적 증가를 기준으로 계층을 정함 | cache hit ratio, access latency, die area |
| 서버 주기억장치 | 대용량 working set은 DRAM 채널·rank 병렬성과 비균등 메모리 접근(Non-Uniform Memory Access, NUMA) 배치로 대역폭을 확보함 | memory bandwidth, LLC miss, p99 latency |
| 인공지능(Artificial Intelligence, AI) 가속기 메모리 계층 | SRAM scratchpad에는 재사용 타일을 두고 DRAM/HBM에는 대량 tensor를 배치함 | on-chip reuse ratio, DRAM traffic, accelerator utilization |

> 요약: 실무 선택은 SRAM의 저지연과 DRAM의 대용량을 계층별 비용·성능 지표로 배치하는 것임.

## Ⅶ. 전망

- **발전 방향**: CPU와 가속기 성능이 높아질수록 DRAM 대역폭 병목이 커져 HBM과 온패키지 메모리의 활용이 확대됨
- **기술사적 판단**: SRAM은 대용량화보다 계층 세분화, 전력 절감, 특화 캐시 구조를 통해 접근 지연을 개선하는 방향으로 발전함
- **기술사 제언**: 기술사는 DRAM과 SRAM을 단순 암기 비교가 아니라 메모리 계층에서 비용과 지연을 배치하는 설계 문제로 설명해야 함
