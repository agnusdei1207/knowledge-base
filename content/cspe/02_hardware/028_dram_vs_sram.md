# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: DRAM과 SRAM은 **셀 구조 차이(1T1C vs 6T)**에 의해 속도·밀도·비용·리프레시 필요 여부가 결정되는 두 가지 **휘발성 메모리 소자**이며, 메모리 계층 구조(027 참조)에서 각각 주기억장치와 캐시로 역할이 분담됨.
- **왜 필요한가**: 단일 메모리 소자만 사용하면 "빠르지만 비싸서 용량 부족(SRAM)" 또는 "싸고 크지만 느려서 CPU 유휴(DRAM)" 중 하나에 몰림. 두 소자를 역할 분담시켜야 속도와 용량·비용을 동시에 충족함.
- **핵심 직관**: SRAM은 사람이 계속 잡고 있는 저울(전원만 있으면 상태 유지, 부품이 많아 비쌈), DRAM은 물이 새는 양동이(놔두면 새므로 주기적 보충 필요하지만 구조가 단순해 대량 생산 가능)임.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 메모리 계층 구조 (상위 키워드) | 속도·용량·비용이 다른 매체를 피라미드로 배치하는 설계(027 참조) | "사무실 책상-서랍-창고" |
| 1T1C (DRAM Cell) | 트랜지스터 1개 + 커패시터 1개로 1비트 저장 | "수도꼭지 하나 + 물통 하나" |
| 6T (SRAM Cell) | 트랜지스터 6개로 구성된 플립플롭으로 1비트 저장 | "부품 6개짜리 자물쇠" |
| 밀도 (Density) | 같은 면적에 저장 가능한 비트 수 — 셀 부품 수가 적을수록 높음 | "같은 방에 서랍을 몇 개 넣을 수 있나" |
| 리프레시 (Refresh) | DRAM 커패시터의 전하 누설을 보완하기 위한 주기적 재충전 | "새는 양동이에 물 다시 채움" |
| Sense Amplifier | DRAM 읽기 시 미세 전하 신호를 증폭하는 회로 | "속삭임을 마이크로 키움" |
| Self-Refresh | 시스템 대기 시 메모리 컨트롤러 없이 DRAM 자체가 최소 전력으로 리프레시 | "자동 급수기" |
| TCM (Tightly Coupled Memory) | 실시간 시스템에서 확정적 응답을 위해 SRAM으로 구성한 전용 메모리 | "리프레시 없는 개인 금고" |

## 깊이 이해
- **배경·문제의식**: 메모리 계층 구조(027)에서 캐시에 SRAM, 주기억장치에 DRAM을 사용하는 근본 이유는 셀 구조에서 비롯됨. SRAM의 6T 셀은 트랜지스터 6개로 플립플롭을 구성하여 전원만 유지되면 상태를 보존하나, DRAM의 1T1C 셀은 커패시터의 전하로 데이터를 저장하므로 시간이 지나면 전하가 누설되어 리프레시가 필수임.
- **셀 구조 → 밀도 → 비용 인과 사슬**: SRAM 6T 셀은 DRAM 1T1C 대비 부품 수가 6배 이상이므로 같은 면적에 담을 수 있는 비트 수가 현저히 적음. 반도체 제조 원가는 웨이퍼 면적에 비례하므로, SRAM의 비트당 비용은 DRAM 대비 수십 배 높음. 이 때문에 L3 캐시는 수십 MB에 머무는 반면, DRAM 모듈 1개는 수십 GB를 구성함.
- **비유**: SRAM은 벽돌 6개로 쌓은 튼튼한 금고(유지비 높으나 안정), DRAM은 벽돌 1개+물통으로 만든 간이 보관함(싸고 많이 만들 수 있으나 주기적 관리 필요)임.
- **구체 예시(실시간 시스템)**: 자동차 ECU(엔진 제어 유닛)에서 1ms 미만의 확정적 응답이 요구될 때, DRAM의 리프레시가 예측 불가 시점에 접근을 지연시킬 수 있어 치명적임. 이에 인터럽트 핸들러·핵심 제어 코드를 SRAM 기반 TCM에 배치하여 확정적 응답 시간을 보장함.
- **흔한 오해·주의점**: ① "SRAM이 무조건 더 좋다"는 틀림. 비트당 비용이 높아 대용량 구성이 비현실적이므로, 용도에 맞는 소자를 선택하는 것이 핵심임. ② DRAM의 리프레시는 "고장 대응"이 아니라 커패시터의 물리적 전하 누설을 보완하는 정상 동작임.

## 연결 개념
- **027 메모리 계층 구조**: SRAM(캐시)과 DRAM(주기억장치)이 배치되는 상위 피라미드.
- **029 DDR SDRAM·리프레시**: Auto/Self Refresh와 tREFI/tRFC 타이밍이 구체적으로 다뤄짐.
- **030 HBM**: DRAM을 수직 적층하여 대역폭을 극대화한 차세대 메모리.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: DRAM은 커패시터 기반(1T1C), SRAM은 플립플롭 기반(6T) 휘발성 메모리로, 셀 구조 차이가 속도·밀도·리프레시 필요 여부를 결정함.
> 2. **가치**: DRAM은 고밀도·저비용으로 대용량 주기억장치를, SRAM은 고속·무리프레시로 CPU 캐시를 담당하여 메모리 계층의 경제적 최적화를 실현함.
> 3. **판단 포인트**: 대용량이 필요하면 DRAM, 저지연·확정적 응답이 필요하면 SRAM을 선택하며, 두 소자는 대체 관계가 아니라 역할 분담 관계임.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 셀 구조 차이 이해 | 1T1C vs 6T, 구조→밀도→비용 인과 | 구조 설명 없이 "DRAM이 느리다"로만 서술 |
| 리프레시 필요성 이해 | 커패시터 전하 누설과 리프레시의 인과관계 | 리프레시를 SRAM에도 적용되는 것처럼 서술 |
| 용도별 선택 기준 파악 | 캐시는 SRAM, 주기억장치는 DRAM | 두 소자를 용도 구분 없이 대체 가능하게 서술 |

> 요약: 셀 구조 차이(1T1C vs 6T)가 리프레시 필요성과 용도 선택으로 이어지는 인과관계를 명확히 제시해야 함.

## Ⅰ. 개요 및 필요성

- 개요: DRAM은 커패시터 기반(1T1C), SRAM은 플립플롭 기반(6T) 휘발성 메모리 소자로, 셀 구조 차이에 의해 속도·밀도·리프레시 필요 여부가 결정됨.
- 배경: 단일 소자로 속도와 대용량을 동시에 충족할 수 없어, 메모리 계층 구조에서 역할을 분담해야 함.
- 필요성: 용도(캐시 vs 주기억장치)에 따라 적합한 소자를 선택하여 시스템 비용과 성능의 균형을 달성해야 함.

---

## Ⅱ. 구조 및 구성요소

```text
DRAM Cell: Transistor 1개 + Capacitor 1개(1T1C) -> 전하 유무로 0/1 저장 -> Refresh 필요
SRAM Cell: Flip-Flop(6 Transistor, 6T) -> 전원 공급 중 상태 유지 -> Refresh 불필요
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| DRAM Cell(1T1C) | 커패시터 전하로 데이터 저장 | 전하 누설로 리프레시 필수 |
| Refresh Controller | DRAM 셀의 주기적 재충전 수행 | JEDEC 표준 주기(tREFI) 준수 |
| SRAM Cell(6T) | 플립플롭으로 데이터 저장 | 전원 유지 시 리프레시 불필요 |
| Sense Amplifier | DRAM 읽기 시 미세 전하 신호 증폭 | DRAM 읽기 지연의 주요 요인 |

> 요약: DRAM은 커패시터+리프레시 컨트롤러 조합, SRAM은 플립플롭만으로 구성되어 유지 로직 자체가 상이함.

---

## Ⅲ. 동작원리 및 흐름도

```text
DRAM 읽기: Row 활성화 -> Sense Amp 증폭 -> 데이터 출력 -> 파괴적 읽기로 재기록
DRAM 유지: 주기적 Refresh 명령 -> 전체 Row 순차 재충전 -> 전하 누설 보완
SRAM 읽기: 플립플롭 상태 감지 -> 즉시 데이터 출력(재기록 불필요)
SRAM 유지: 전원 공급 지속 -> 상태 유지(별도 재충전 없음)
```

- 1단계 [DRAM 읽기]: Row를 활성화한 후 커패시터의 미세 전하를 Sense Amplifier로 증폭하여 데이터를 출력함. 읽기 과정에서 전하가 파괴(Destructive Read)되므로 즉시 재기록이 필요함.
- 2단계 [DRAM 리프레시]: 메모리 컨트롤러가 JEDEC 표준 주기(tREFI ≈ 7.8µs)마다 Refresh 명령을 발행하여 전체 Row를 순차 재충전함. 리프레시 중 해당 뱅크는 접근 불가(Stall)됨.
- 3단계 [SRAM 읽기]: 플립플롭의 전기적 상태를 즉시 감지하여 데이터를 출력하며, 비파괴적 읽기이므로 재기록이 불필요함.
- 4단계 [SRAM 유지]: 전원이 공급되는 한 플립플롭 상태가 자동 유지되므로 별도 리프레시 로직이 존재하지 않음.

> 요약: DRAM은 읽기마다 재기록 + 주기적 리프레시가 필요하나, SRAM은 전원만 유지되면 별도 관리 없이 상태를 보존함.

---

## Ⅳ. 특징
- 밀도·비용 격차: DRAM 1T1C 셀은 SRAM 6T 대비 면적 효율이 6배 이상 높아 비트당 비용이 수십 배 저렴하므로, 대용량 주기억장치(수십~수백 GB)에 적합함
- 속도 격차: SRAM은 플립플롭 기반으로 1~2ns 접근이 가능하나, DRAM은 Row 활성화+Sense Amp 증폭으로 60~100ns가 소요되어 캐시(고속)와 주기억장치(대용량)로 역할이 분리됨
- 리프레시 확정성 문제: DRAM 리프레시 중 해당 뱅크 접근이 불가하여 실시간 시스템에서 최악 응답 시간(WCET) 보장이 어려우므로, 확정적 응답이 필요한 영역에는 SRAM 기반 TCM을 사용함

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | DRAM | SRAM | 선택 기준 |
|:---|:---|:---|:---|
| 셀 구조 | 1T1C(커패시터) | 6T(플립플롭) | 밀도 vs 속도 |
| 밀도/비용 | 고밀도, 비트당 비용 낮음 | 저밀도, 비트당 비용 높음 | 대용량 필요 시 DRAM |
| 접근 속도 | 60~100ns | 1~2ns | 저지연 필요 시 SRAM |
| 리프레시 | 필수(전하 누설) | 불필요(전원 유지) | 확정적 응답 필요 시 SRAM |
| 대표 용도 | 주기억장치(메인 메모리) | CPU 캐시(L1/L2/L3) | 메모리 계층 내 위치 |

> 요약: 용량과 비용이 우선이면 DRAM, 속도와 확정성이 우선이면 SRAM을 선택하며, 실제 시스템은 계층별로 양쪽 모두 사용함.

**리스크·대응:**
- Refresh 오버헤드: DRAM 리프레시 중 해당 뱅크 접근 제한 → Self-Refresh 모드 활용, Refresh 스케줄링 최적화(Targeted Refresh)로 Stall 최소화 (지표: 리프레시 소요 시간 비율 tRFC/tREFI)
- SRAM 면적·비용 과다: 6T 구조의 낮은 밀도로 대용량 캐시 구성 곤란 → 워크로드 프로파일링으로 적정 캐시 크기 결정, 3D V-Cache 적층으로 면적 제약 완화 (지표: 캐시 면적 대비 Miss Rate)

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. CPU 캐시 SRAM 구성: L1/L2/L3 캐시를 SRAM으로 구성하여 CPU 클럭에 맞는 1~15ns 저지연 접근을 확보하고, 3D V-Cache 적층으로 캐시 용량을 확대함.
2. 주기억장치 DRAM 구성: 메인 메모리를 DDR5 DRAM으로 구성하여 대용량(수십~수백 GB)을 낮은 비트당 비용으로 확보하고, Refresh 스케줄링을 최적화하여 Stall을 최소화함.
3. 실시간 시스템 TCM 적용: 자동차 ECU·산업용 PLC 등에서 인터럽트 핸들러와 핵심 제어 코드를 SRAM 기반 TCM에 배치하여 리프레시 Stall 없는 확정적 응답 시간(WCET)을 보장함.

**결론:**
- 기술사 판단: DRAM과 SRAM은 대체 관계가 아니라 셀 구조 차이(1T1C vs 6T)에 따른 역할 분담 관계이며, 용도에 맞는 소자 선택이 시스템 비용·성능 최적화의 핵심임.
- 향후 방향: HBM(DRAM 적층, 대역폭 극대화)과 3D V-Cache(SRAM 적층, 캐시 용량 확대)가 각 소자의 물리적 한계를 패키징 혁신으로 돌파하는 방향으로 동시 진화 중임.
