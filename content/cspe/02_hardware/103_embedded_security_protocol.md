## Ⅰ. 개요
- 자원이 제한된 임베디드 장치 간 안전한 통신을 위해 설계된 경량 보안 규약.
- 기기 인증, 데이터 무결성, 기밀성을 보장하면서 연산 및 전력 소모를 최소화함.
| 구분 | 내용 | 비고 |
|---|---|---|
| 정의 | 임베디드 환경에 최적화된 경량 암호 및 통신 보안 규약 | Lightweight |
| 의도 | 제약 사항 하의 효율적 보안 통신 메커니즘 설계 역량 측정 | 에너지 효율 |

## Ⅱ. 구성요소
[ Embedded Device ] --(CoAP/MQTT + DTLS)--> [ Gateway/Cloud ]
| 구성요소 | 설명 | 비유 |
|---|---|---|
| 경량 암호 | LEA, SIMON, SPECK 등 적은 자원으로 구동되는 알고리즘 | 작은 열쇠 |
| DTLS | UDP 기반 환경에서 신뢰성 있는 보안 채널 제공 프로토콜 | 간이 터널 |
| 인증 메커니즘 | 인증서 대신 대칭키 기반의 PSK(Pre-Shared Key) 활용 | 암구호 |
> 요약: 경량 암호 알고리즘, 전송 보안(DTLS), 간소화된 인증 체계임.

## Ⅲ. 절차
(1) Handshake -> (2) Session Key -> (3) Encrypted Comm -> (4) Termination
1. Handshake: 상호 인증을 수행하고 지원 가능한 암호 리스트(Cipher Suite) 협상.
2. Session Key: ECDH 등 경량 키 교환 방식을 통해 이번 세션에 쓸 키 생성.
3. Encrypted Comm: AEAD(인증된 암호화) 방식을 써서 기밀성과 무결성 동시 확보.
4. Termination: 세션 종료 후 사용된 임시 키를 파기하여 Forward Secrecy 보장.
> 요약: 핸드쉐이크, 키 생성, 암호 통신, 종료의 단계를 거침.

## Ⅳ. 문제점
- 연산 부하: 복잡한 공개키 연산 시 배터리 소모 급증 및 응답 시간 지연.
- 패킷 오버헤드: 보안 헤더 추가로 인한 패킷 크기 증가로 네트워크 대역폭 낭비.

## Ⅴ. 개선방안
- 하드웨어 가속: 암호 연산을 전용 하드웨어 가속기(Crypto Engine)에 위임.
- 헤더 압축: 6LoWPAN 환경 등에서 보안 헤더를 압축하는 기술(NHC) 적용.

## Ⅵ. 전망
- 제로 터치 온보딩: 기기가 네트워크에 최초 접속 시 자동 보안 설정 기술(FIDO 등) 확산.
- 양자 내성 보안: 임베디드 환경에서도 구동 가능한 경량 양자 내성 암호(PQC) 프로토콜 연구.
