# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: ARM 프로세서 내부에 하드웨어적으로 일반 실행 구역과 보안 실행 구역을 완벽히 분리하는 보안 격리 기술
- **왜 필요한가**: 안드로이드나 iOS 같은 일반 OS가 해킹당하더라도, 은행 앱의 비밀번호나 생체인증 데이터만큼은 물리적으로 접근 불가능한 안전지대에 두기 위해 필요하다.
- **핵심 직관**: "스마트폰 안의 금고 방. 일반 방(OS)이 털려도 금고 방(TrustZone) 문은 열리지 않는다."

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| REE (Rich Execution Environment) | 일반 OS(안드로이드 등)와 앱이 실행되는 구역 (보안성 낮음) | "스마트폰의 평범한 거실" |
| TEE (Trusted Execution Environment) | 보안 OS와 신뢰할 수 있는 앱(생체인증 등)만 실행되는 구역 | "스마트폰 안의 숨겨진 금고 방" |
| TrustZone 보안 모니터 | REE와 TEE 사이의 문지기 역할을 하는 하드웨어 인터럽트 제어기 | "금고 방의 철통 경비원" |
| SMC (Secure Monitor Call) | 일반 구역에서 보안 구역으로 서비스를 요청하는 특별한 명령어 | "경비원에게 신분증 확인을 요청하는 쪽지" |

## 깊이 이해
- **배경·문제의식**: 소프트웨어 방식의 백신이나 암호화는 OS 자체 권한(Root)이 탈취되면 쉽게 무력화된다. 따라서 소프트웨어적 방어를 넘어 CPU 레벨에서 메모리와 주변 장치 접근 권한을 하드웨어적으로 쪼개버리는 하드웨어 기반 보안 계층(Hardware Root of Trust)이 필요해졌다.
- **작동 원리**: ARM 코어는 NS(Non-Secure) 비트를 추가하여 물리적으로 상태를 구분한다. NS=1이면 일반 세계(REE), NS=0이면 보안 세계(TEE)다. 일반 OS는 보안 메모리 영역을 물리적으로 볼 수도, 읽을 수도 없다. 은행 앱에서 지문 인식을 요청하면 CPU가 SMC를 통해 TEE로 잠시 들어가 지문을 판독하고 '맞다/틀리다' 결과만 REE로 던져준다.
- **비유**: 은행에 갔을 때, 고객 대기실(REE)에 강도가 들어도 금고실(TEE)의 두꺼운 철문은 물리적으로 열 수 없다. 고객 대기실에서 대출 심사를 신청하면, 금고실 안의 직원이 작은 창구(SMC)로 결과만 알려주는 식이다.
- **구체 예시**: 삼성 페이(Samsung Pay)나 애플의 Face ID 인증 처리. 안드로이드가 루팅되어도 결제 정보는 TEE 안에서만 해독되고 서명되므로 안전하다.
- **흔한 오해·주의점**: "TrustZone은 칩이 두 개(듀얼 코어)라서 분리된 것이다"는 틀린 설명이다. 단일 코어(Single Core) 안에서 시간을 쪼개어 보안 세계와 일반 세계를 번갈아 실행하는 하드웨어 문맥(Context) 격리 방식이다. (단, 최신 시스템은 멀티코어 전반에 적용됨)

## 연결 개념
- TEE (Trusted Execution Environment)
- 하드웨어 신뢰 근원 (Hardware Root of Trust)
- 보안 부팅 (Secure Boot)

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: ARM TrustZone은 프로세서의 상태를 물리적 비트(NS Bit)로 분할하여, 단일 코어 상에서 일반 구역(REE)과 보안 구역(TEE)을 하드웨어적으로 격리하는 기술이다.
> 2. **가치**: 일반 OS(Android, Linux 등)가 커널 수준(Root)으로 침해당하더라도 암호 키, 생체 정보, 결제 트랜잭션 등 핵심 데이터의 유출 및 위변조를 원천 차단한다.
> 3. **판단 포인트**: TrustZone은 단순 메모리 암호화가 아니라 CPU 버스(AMBA), 인터럽트(GIC), 주변장치까지 전체 시스템을 두 세계(Two Worlds)로 분리하는 시스템 레벨 아키텍처임이 핵심이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 하드웨어 기반 격리(Hardware-backed Isolation) 원리 이해 | NS(Non-Secure) 비트, Normal World / Secure World | 소프트웨어 기반 가상머신(Hypervisor)으로 혼동하여 서술 |
| 모바일/IoT 보안 프레임워크(TEE) 아키텍처 이해 | REE, TEE, Secure Monitor Call(SMC) 흐름도 | TEE 개념을 ARM에 국한하지 않은 범용으로만 풀고 TrustZone 핵심(SMC) 누락 |
| TrustZone 적용의 실무적 의의 및 확대 적용 사례 | 모바일 생체 인증, DRM, IoT 엣지 보안 결합 | "데이터를 단순히 암호화해서 저장한다" 수준의 얕은 서술 |

> 요약: 소프트웨어(OS)의 취약점을 하드웨어 아키텍처(Two Worlds)로 방어한다는 패러다임 전환과 SMC를 통한 제한적 통신 구조를 설명해야 한다.

---

## Ⅰ. 개요 및 필요성

- 개요: ARM TrustZone은 단일 시스템(SoC) 내부에 논리적인 하드웨어 상태 비트를 두어, 일반 실행 환경(REE)과 신뢰 실행 환경(TEE)을 완벽히 분리하는 보안 아키텍처
- 배경: 모바일 운영체제의 권한 탈취(Rooting) 및 악성코드 감염 시, 소프트웨어 백신만으로는 커널 메모리 해킹을 막을 수 없는 한계 도달
- 필요성: 모바일 결제, 생체 인증, 기업용 DRM 보안을 위해 메인 OS가 붕괴되어도 영향을 받지 않는 칩 레벨의 신뢰 실행 구역(Root of Trust) 구축 필요

---

## Ⅱ. 구조 및 구성요소

```text
       [ Normal World (REE) ]          [ Secure World (TEE) ]
      Rich OS (Android/Linux)           Trusted OS (Kinibi 등)
                |           +---------+           |
  NS Bit = 1    +---------> | Monitor | <---------+    NS Bit = 0
                (SMC 호출)  +---------+  (결과 반환)
------------------------------------------------------------------
                 Hardware (AMBA Bus, Memory, Peripherals)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Normal World (REE) | 사용자 애플리케이션 및 범용 OS가 동작하는 비보안 구역 | Secure World 자원에 물리적 접근 불가 |
| Secure World (TEE) | 보안 부팅, 암호 키 연산, 생체인증 등을 수행하는 신뢰 구역 | Normal World 자원에 양방향 접근 가능 |
| Secure Monitor | 두 세계 간의 문맥 교환(Context Switch)을 통제하는 게이트웨이 | SMC(Secure Monitor Call) 명령어로만 진입 가능 |
| AMBA Bus / GIC | 시스템 버스와 인터럽트 컨트롤러에 보안 속성 부여 | 특정 메모리 블록과 주변장치(센서)를 Secure 전용으로 할당 |

> 요약: TrustZone 아키텍처는 코어뿐만 아니라 버스(AMBA), 메모리 보호 장치(TZASC), 인터럽트(GIC)까지 하드웨어 전반을 두 구역으로 분리한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
사용자 인증 요청 -> REE에서 SMC 명령어 실행 -> Monitor 진입 및 상태 전환 -> TEE에서 안전한 검증 수행 -> Monitor 복귀 및 REE로 결과 전달
```

- 1단계 [보안 요청]: Normal World의 결제 앱이 지문 인증 등 보안 처리가 필요할 때 OS를 통해 SMC(Secure Monitor Call) 호출
- 2단계 [세계 전환]: 프로세서가 예외(Exception)를 발생시키고 Secure Monitor 모드로 진입하여 NS 비트를 0으로 변경 (문맥 저장)
- 3단계 [보안 연산]: Secure World의 Trusted OS가 지문 센서(Secure 주변장치)를 단독 제어하여 서명 및 인증 로직 수행
- 4단계 [결과 반환]: 인증 결과(True/False 등)만 레지스터에 담아 다시 Monitor를 거쳐 Normal World로 안전하게 반환

> 요약: 일반 세계는 보안 세계의 메모리를 훔쳐볼 수 없으며, 오직 규격화된 SMC 호출을 통해서만 제한된 보안 서비스를 '요청'하고 '결과'만 받을 수 있다.

---

## Ⅳ. 특징

- 물리적 리소스 공유: 칩을 2개 쓰는 듀얼 코어가 아니라 단일 코어에서 시분할과 권한 분리를 통해 구현되므로 BOM(부품단가)과 전력 소모 증가 억제
- 비대칭적 접근 통제: Secure World는 Normal World의 메모리를 읽고 쓸 수 있지만, 역방향 접근은 하드웨어 수준에서 차단됨
- 에코시스템 독립성: 메인 OS(Android)의 커널 패닉이나 악성코드 감염 등 시스템 붕괴 상황에서도 TEE의 신뢰 연산은 독립적으로 안전하게 생존함

> 요약: 하드웨어 추가 비용을 최소화하면서도 완벽한 물리적 차단벽을 생성하여, 스마트폰의 보안 수준을 하드웨어 금고(Smart Card) 급으로 끌어올린다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 소프트웨어 가상화 (Hypervisor) | ARM TrustZone (하드웨어 TEE) | 선택 기준 |
|:---|:---|:---|:---|
| 격리 메커니즘 | VMM에 의한 가상 주소 매핑 및 메모리 파티셔닝 | CPU 상태 비트(NS) 버스 레벨의 물리적 차단 | 격리의 물리적 강력함 여부 |
| OS 해킹 시 취약성 | 하이퍼바이저 취약점 공격 시 뚫릴 우려 있음 | OS나 하이퍼바이저가 뚫려도 하드웨어 접근 불가로 안전 | 보안 최상위 계층 (Root of Trust) |
| 적용 환경 | 클라우드 서버, 다중 OS 구동 (무거운 리소스) | 모바일 기기, IoT 엣지 디바이스 (제한된 리소스) | 디바이스의 컴퓨팅 파워 및 폼팩터 |

> 요약: 서버급 다중 인스턴스 격리에는 가상화가 적합하지만, 모바일/IoT 단일 칩에서의 생체/금융 데이터 원천 보호에는 TrustZone 물리 격리가 필수적이다.

**리스크·대응:**
- Trusted OS(TEE) 자체 취약점 리스크: TEE 안의 보안 앱(Trustlet)에 버퍼 오버플로우 등 결함이 있으면 시스템 전체 권한이 탈취됨 → TEE 내부 코드 베이스 최소화 및 정형 검증(Formal Verification) 기반 엄격한 배포 통제 (지표: TEE 앱 대상 침투 테스트 취약점 0건)
- 사이드 채널 공격(Side Channel Attack) 리스크: 전력 소모량이나 캐시 접근 시간 패턴을 분석해 TEE 내부 암호키를 유추함 → 캐시 플러싱(Cache Flushing) 의무화 및 암호 연산 시 난수 지연(Dummy Cycle) 삽입 방어 (지표: DPA/SPA 공격 저항성 인증 획득)

**도입 후 점검 지표:**
- 하드웨어 격리 보장성: 일반 구역(REE) 커널에서 보안 메모리 물리 주소 직접 접근 시 하드웨어 Exception(Abort) 정상 발생 여부 검증
- 보안 부팅 체인: 전원 인가 시 Boot ROM부터 TEE 활성화, REE 로드까지 단계별 전자서명 검증 체인(Chain of Trust) 단절 여부

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. FIDO 생체 인증 연동: 지문/안면 인식 센서 제어권을 AMBA 시스템 버스 설정으로 Secure World에만 독점 할당하여, 인증 템플릿의 외부 유출 원천 차단 설계
2. DRM 미디어 파이프라인 보호: 넷플릭스 등 고화질 4K 스트리밍 복호화 키 및 디코딩된 순수 영상(Raw) 프레임을 TEE 내 메모리에만 상주시켜 화면 캡처 해킹(Screen Scraping) 방어
3. IoT 보안 부팅 및 원격 검증: Cortex-M 시리즈 기반 초소형 IoT 기기(TrustZone for ARMv8-M)에 적용하여, 펌웨어 업데이트(OTA) 시 무결성을 자체 검증하는 엣지 보안 노드 구축

**결론 (2줄):**
- 기술사 판단: 애플리케이션 계층 방어는 뚫릴 수밖에 없다는 'Zero Trust' 관점에서, TrustZone은 하드웨어를 신뢰의 뿌리(Root of Trust)로 삼아 최후 방어선을 구축하는 필수 아키텍처다.
- 향후 방향: 모바일을 넘어 자동차 전장(자율주행 ECU) 및 데이터센터 서버급 시스템 환경(Confidential Computing)까지 하드웨어 물리 격리 아키텍처 적용이 표준으로 자리잡을 것이다.
