## 미리 알고가기

- TrustZone은 하나의 ARM 시스템 안에서 보안 영역과 일반 영역을 나누는 하드웨어 보안 확장임
- 보안 영역(Secure World)과 일반 영역(Normal World)은 서로 다른 신뢰 경계를 구성함
- 보안 모니터(Secure Monitor)는 두 영역의 전환과 컨텍스트 저장을 담당함
- Secure Boot는 보안 영역의 초기 코드를 검증하고 TEE는 보안 영역에서 신뢰 서비스를 실행함
- 신뢰 컴퓨팅 기반(TCB)은 보안 기능을 제공하기 위해 신뢰해야 하는 코드·하드웨어의 집합임

## 작성 근거(검토용)

- ARM TrustZone은 Secure·Normal World, Secure Monitor, 자원 보안 속성, TEE를 핵심 축으로 설명함
- 비교표는 소프트웨어 격리와 TrustZone의 경계 강제·키 보호·실행 범위를 대비함
- 실무 판단은 보안 영역 코드 크기·호출 지연과 비인가 접근 차단률·격리 시험 통과율로 검증함

## Ⅰ. 개요

- **정의/개념**: ARM TrustZone은 ARM 기반 SoC를 보안 영역과 일반 영역으로 분리해 키·인증·민감 서비스를 보안 영역에서 실행하는 하드웨어 보안 아키텍처임
- **배경/필요성**: 운영체제 침해 뒤에도 핵심 자산을 보호하기 위해 일반 기능과 보안 기능을 분리할 하드웨어 경계가 필요함

## Ⅱ. 특징

- 하나의 프로세서 안에서 두 개의 신뢰 수준을 분리할 수 있음
- 메모리·인터럽트·주변장치 접근을 보안 속성으로 통제함
- TEE와 결합해 결제·인증서·기기 비밀값을 보안 영역에서 처리함
- 보안 영역 코드가 늘어나면 공격면과 유지보수 부담도 증가함

## Ⅲ. 종류 및 비교

| 판단 기준 | 소프트웨어 격리만 사용하는 구조 | TrustZone 기반 구조 |
|:---|:---|:---|
| 격리 방식 | 운영체제 권한과 프로세스 분리에 주로 의존함 | 하드웨어가 보안 영역과 일반 영역을 나눠 경계를 강제함 |
| 키 보호 | 운영체제가 침해되면 민감 정보가 함께 노출될 수 있음 | 보안 영역에 키와 민감 서비스를 격리해 노출 위험을 줄일 수 있음 |
| 활용 범위 | 운영체제의 프로세스·권한으로 앱을 분리함 | TEE·Secure Boot·기기 인증을 보안 영역에서 실행함 |
| 유의점 | 운영체제 침해 시 같은 권한 경계의 자산이 노출될 수 있음 | 영역 전환과 메모리·주변장치 보안 속성 오류를 관리해야 함 |

> 요약: TrustZone은 소프트웨어 격리와 달리 하드웨어 경계를 제공하며 메모리·주변장치의 보안 속성 설정이 필요함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 보안·일반 영역 | 민감 기능과 일반 기능을 분리해 서로 다른 신뢰 경계를 만듦 |
| 보안 모니터 | 영역 전환과 컨텍스트 저장을 담당해 경계 진입 통로를 통제함 |
| 메모리·주변장치 접근 제어 | 보안 속성으로 RAM·인터럽트·장치를 구분해 접근 범위를 제한함 |
| TEE·보안 서비스 | 키 저장과 기기 인증과 결제 같은 민감 기능을 보안 영역에서 제공함 |

> 요약: TrustZone은 보안·일반 영역, 보안 모니터, 접근 제어, TEE 서비스로 경계를 구성함.

## Ⅴ. 원리 및 절차 흐름도

1. **보안 부팅 시작**: 신뢰된 초기 코드가 먼저 보안 영역을 준비함
2. **보안 속성 설정**: 메모리와 주변장치 접근 범위를 보안 영역과 일반 영역으로 나눔
3. **보안 서비스 실행**: 키 관리와 인증 같은 민감 기능을 보안 영역에서 처리함
4. **일반 영역 연계**: 일반 OS가 보안 모니터를 통해 보안 서비스를 호출함

> 요약: 보안 부팅으로 경계를 만든 뒤 보안 서비스를 실행하고 보안 모니터로 일반 영역과 연계함.

## Ⅵ. 실무 사례

1. IoT 게이트웨이는 보안 영역의 TCB를 최소화하고 보안 영역 코드 크기·보안 호출 지연을 확인함
2. 자동차 도메인 컨트롤러는 메모리·주변장치 보안 속성을 검증하고 비인가 접근 차단률·격리 시험 통과율을 확인함

## Ⅶ. 결론

- TrustZone은 보안 영역의 TCB를 줄이고 메모리·주변장치 보안 속성과 영역 전환 경로를 검증해야 함
