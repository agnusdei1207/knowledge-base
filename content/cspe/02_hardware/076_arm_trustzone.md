## 미리 알고가기

- TrustZone은 하나의 ARM 시스템 안에서 보안 영역과 일반 영역을 나누는 하드웨어 보안 확장임
- secure monitor와 메모리·주변장치 접근 제어가 핵심 구성임
- secure boot와 TEE와 함께 써야 격리 효과가 증가함

## Ⅰ. 개요

- **정의/개념**: ARM TrustZone은 ARM 기반 SoC를 보안 영역과 일반 영역으로 논리 분리해 키 저장과 인증과 민감 서비스를 보안 영역에서 격리 실행하게 하는 하드웨어 보안 아키텍처임
- **배경/필요성**: 모바일과 임베디드 장치는 일반 애플리케이션과 보안 기능을 한 칩에서 함께 돌리므로, 운영체제가 침해돼도 핵심 자산을 보호할 하드웨어 경계가 필요함

## Ⅱ. 특징

- 하나의 프로세서 안에서 두 개의 신뢰 수준을 분리할 수 있음
- 메모리와 인터럽트와 주변장치 접근을 보안 속성으로 통제함
- TEE와 결합하면 결제와 인증서와 기기 비밀값 보호에 적합함
- 보안 영역 코드가 늘어나면 공격면과 유지보수 부담도 증가함

## Ⅲ. 종류 및 비교

| 판단 기준 | 소프트웨어 격리만 사용하는 구조 | TrustZone 기반 구조 |
|:---|:---|:---|
| 격리 방식 | 운영체제 권한과 프로세스 분리에 주로 의존함 | 하드웨어가 보안 영역과 일반 영역을 나눠 경계를 강제함 |
| 키 보호 | 운영체제가 침해되면 민감 정보가 함께 노출될 수 있음 | 보안 영역에 키와 민감 서비스를 격리해 노출 위험을 줄일 수 있음 |
| 활용 범위 | 일반 앱 보호와 권한 분리에 적합함 | TEE와 secure boot와 기기 인증 같은 민감 기능에 적합함 |
| 유의점 | 구현은 단순하지만 운영체제 전체 신뢰에 의존함 | 보안 경계는 강하지만 world 전환과 속성 설정 오류를 엄격히 관리해야 함 |

> 요약: TrustZone은 SW 격리보다 하드웨어 경계를 제공하지만 보안 속성 설정 오류를 엄격히 관리해야 함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Secure·Normal World | 민감 기능과 일반 기능을 분리해 서로 다른 신뢰 경계를 만듦 |
| Secure Monitor | world 전환과 컨텍스트 저장을 담당해 경계 진입 통로를 통제함 |
| 메모리·주변장치 접근 제어 | secure 속성으로 RAM과 인터럽트와 장치를 구분해 접근 범위를 제한함 |
| TEE·보안 서비스 | 키 저장과 기기 인증과 결제 같은 민감 기능을 보안 영역에서 제공함 |

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 보안 부팅 시작 | --> | 보안 속성 설정  | --> | 보안 서비스 실행  | --> | 일반 영역 연계  |
+-------------+     +-------------+     +-------------+     +-------------+
```

> 요약: TrustZone은 secure/normal world, secure monitor, 접근 제어, TEE 서비스로 경계를 구성함.

## Ⅴ. 원리 및 절차 흐름도

1. **보안 부팅 시작**: 신뢰된 초기 코드가 먼저 보안 영역을 준비함
2. **보안 속성 설정**: 메모리와 주변장치 접근 범위를 보안 영역과 일반 영역으로 나눔
3. **secure 서비스 실행**: 키 관리와 인증 같은 민감 기능을 보안 영역에서 처리함
4. **일반 영역 연계**: 일반 OS가 필요한 경우 monitor를 통해 보안 서비스를 호출함

> 요약: 보안 부팅으로 경계를 만든 뒤 secure service를 실행하고 monitor로 일반 영역과 연계함.

## Ⅵ. 실무 적용 및 유의점

1. 모바일 결제·IoT 게이트웨이는 보안 영역 코드가 늘면 공격면이 넓어지므로 TCB 최소화와 인터페이스 감사를 적용하고 secure code size, vulnerability count, secure call latency로 확인함
2. 자동차·산업 엣지는 속성 설정 오류 시 일반 영역이 민감 자원에 접근할 수 있으므로 부팅 정책 검증과 격리 시험을 자동화하고 unauthorized access, isolation pass rate, boot integrity pass rate로 확인함

## Ⅶ. 결론

TrustZone의 가치는 한 칩 안에 보안 경계를 만드는 데 있으므로, 보안 영역을 작게 유지하고 자원 속성 설정을 정확히 관리해야 함.

## 작성 근거(검토용)

- ARM TrustZone은 secure/normal world, secure monitor, 메모리·주변장치 속성, TEE를 핵심 축으로 설명함
- 비교표는 SW 격리와 TrustZone 기반 구조의 키 보호와 경계 강제 차이를 대비함
- 실무 판단은 secure code size, secure call latency, isolation pass rate, boot integrity pass rate로 검증 가능하게 작성함
