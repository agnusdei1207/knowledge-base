## 미리 알고가기

- 메모리 인터리빙은 연속 주소를 여러 메모리 뱅크에 나눠 배치하는 기법임
- 뱅크 충돌(bank conflict)은 여러 요청이 같은 뱅크에 몰려 병렬성이 줄어드는 현상임
- 스트라이드(stride) 접근은 일정한 간격으로 주소를 건너뛰며 읽는 패턴임
- NUMA(Non-Uniform Memory Access)는 소켓별로 로컬·원격 메모리 접근 지연이 다른 멀티소켓 구조임

## 작성 근거(검토용)

- 메모리 인터리빙은 주소 매핑, 뱅크 병렬성, 뱅크 충돌, 스트라이드를 핵심 축으로 설명함
- 비교표는 단일 뱅크·워드·블록 인터리빙의 연속 주소 배치, 충돌 조건, 적합 조건을 대비함
- 실무 판단은 뱅크 충돌률·지속 대역폭과 원격 메모리 접근률·소켓별 대역폭으로 검증함

## Ⅰ. 개요

- **정의/개념**: 메모리 인터리빙은 주소 공간을 여러 메모리 뱅크에 분산해 연속 또는 규칙적 접근 시 여러 뱅크를 겹쳐 사용하도록 만드는 메모리 대역폭 확장 기법임
- **배경/필요성**: CPU·DMA·벡터 처리기의 메모리 대역폭 요구를 충족하기 위해 연속 주소를 여러 뱅크로 분산해야 함

## Ⅱ. 특징

- 연속 주소를 서로 다른 뱅크에 배치하면 뱅크 접근 주기를 겹쳐 처리함
- 스트라이드와 뱅크 수가 공약수를 가지면 같은 뱅크에 요청이 집중될 수 있음
- 캐시 미스 이후 하위 메모리 병목을 완화하는 데 자주 쓰임

## Ⅲ. 종류 및 비교

| 판단 기준 | 단일 뱅크 | 워드 인터리빙 | 블록 인터리빙 |
|:---|:---|:---|:---|
| 연속 주소 배치 | 같은 뱅크에서 순차 처리함 | 인접 주소를 서로 다른 뱅크에 배치함 | 같은 블록은 한 뱅크에 배치함 |
| 충돌 조건 | 모든 요청이 단일 뱅크에서 대기함 | 스트라이드와 뱅크 수가 공약수를 가지면 같은 뱅크에 집중됨 | 같은 블록 요청이 한 뱅크에 집중됨 |
| 적합 조건 | 동시 요청이 적은 저대역폭 시스템 | 벡터·연속 스트림 접근 | 블록 지역성을 이용하는 캐시·페이지 배치 |

> 요약: 워드 인터리빙은 인접 주소를 여러 뱅크에 분산하고, 블록 인터리빙은 같은 블록을 한 뱅크에 배치함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 요청 발생원 | CPU, DMA, 가속기가 메모리 접근 패턴을 만들어 냄 |
| 주소 매퍼 | 주소 비트 규칙으로 요청을 특정 뱅크에 분산시킴 |
| 메모리 뱅크 집합 | 독립 접근 가능한 여러 뱅크가 실제 병렬 처리 기반이 됨 |
| 스케줄러·반환 경로 | 충돌 시 순서를 조정하고 결과를 원래 요청자에게 돌려줌 |

> 요약: 인터리빙 구조는 주소 매퍼가 요청을 여러 뱅크에 분산하고 충돌 시 스케줄러가 순서를 조정함.

## Ⅴ. 원리 및 절차 흐름도

1. **주소 요청 생성**: CPU나 DMA가 연속 또는 스트라이드 요청을 발행함
2. **뱅크 매핑**: 주소 규칙에 따라 각 요청을 뱅크에 배정함
3. **병렬 또는 대기 처리**: 다른 뱅크 요청은 병렬 처리하고 같은 뱅크 요청은 대기시킴
4. **데이터 반환**: 처리 결과를 요청 순서에 맞춰 반환함

> 요약: 메모리 인터리빙은 주소를 뱅크에 나누고 충돌 없는 요청을 병렬 처리해 대역폭을 높임.

## Ⅵ. 실무 사례

1. 벡터 프로세서는 주소 해싱과 데이터 패딩을 적용하고 뱅크 충돌률·지속 대역폭을 확인함
2. NUMA 서버는 인터리빙 범위를 소켓 내부로 제한하고 페이지 배치를 맞춰 원격 메모리 접근률·소켓별 대역폭을 확인함

## Ⅶ. 결론

- 메모리 인터리빙은 뱅크 수와 주소 매핑을 접근 스트라이드에 맞추고 충돌률·지속 대역폭으로 효과를 검증해야 함
