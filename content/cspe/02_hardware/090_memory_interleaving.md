## Ⅰ. 개요
- **정의**: 연속 메모리 주소를 복수의 메모리 뱅크에 교차 배치하여 접근 지연을 중첩시키는 기법임
- **배경/필요성**: CPU와 메모리 간 속도 격차가 확대되면서 단일 뱅크의 접근 지연을 숨기기 위한 병렬화가 필요함
- **비유**: 계산대가 여러 개인 마트에서 고객을 번갈아 배정하여 대기 시간을 줄이는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 인터리빙 방식별 주소 배분 원리 | 하위 비트(Low-order) vs 상위 비트(High-order) 인터리빙 차이 | 뱅크 충돌(Bank Conflict) 발생 조건 명시 필요 |

> 요약: 주소를 뱅크에 교차 배분하여 메모리 접근 대역폭을 향상하는 기법임

## Ⅱ. 구성요소
```text
  CPU --> 주소 버스 --> 뱅크 선택 로직
                          |
            +------+------+------+------+
            |Bank0 |Bank1 |Bank2 |Bank3 |
            |Addr0 |Addr1 |Addr2 |Addr3 |
            |Addr4 |Addr5 |Addr6 |Addr7 |
            +------+------+------+------+
                          |
                       데이터 버스
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 메모리 뱅크 | 독립적으로 접근 가능한 메모리 모듈 단위임 | 마트의 개별 계산대 |
| 뱅크 선택 로직 | 주소 비트를 기준으로 접근할 뱅크를 결정하는 하드웨어임 | 고객 배정 안내원 |
| 하위 비트 인터리빙 | 주소 하위 비트로 뱅크를 선택하여 연속 주소가 다른 뱅크에 분산됨 | 순번대로 줄 서기 |
| 상위 비트 인터리빙 | 주소 상위 비트로 뱅크를 선택하여 연속 주소가 같은 뱅크에 집중됨 | 블록별로 줄 서기 |

> 요약: 뱅크·선택 로직·인터리빙 방식이 메모리 병렬 접근의 핵심 구성요소임

## Ⅲ. 절차
```text
주소 발행 --> 뱅크 번호 결정 --> 병렬 접근 --> 데이터 병합
```
- 1단계: **주소 발행** — CPU가 연속된 메모리 주소를 순차적으로 요청함
- 2단계: **뱅크 번호 결정** — 주소의 하위(또는 상위) 비트로 대상 뱅크를 선택함
- 3단계: **병렬 접근** — 서로 다른 뱅크에 대한 요청이 동시에 처리되어 접근 지연이 중첩됨
- 4단계: **데이터 병합** — 각 뱅크의 응답 데이터를 순서대로 조합하여 CPU에 전달함

> 요약: 주소 발행-뱅크 선택-병렬 접근-병합의 4단계로 메모리 대역폭을 확대함

## Ⅳ. 문제점
- 뱅크 충돌: 연속 접근 패턴의 보폭(Stride)이 뱅크 수의 배수이면 동일 뱅크에 집중되어 지연이 발생함
- 설계 복잡도 증가: 뱅크 수 증가 시 선택 로직·데이터 정렬 회로의 면적과 전력이 증가함
- 비순차 응답 처리: 뱅크별 응답 시간 차이로 데이터 순서 재정렬 오버헤드가 발생함

> 요약: 뱅크 충돌·설계 복잡도·재정렬 오버헤드가 인터리빙의 3대 한계임

## Ⅴ. 개선방안
1. 단기: 소수(Prime) 개수 뱅크 구성으로 보폭 기반 뱅크 충돌 확률을 저감함
2. 중기: 뱅크 그룹핑과 독립 버스 구조로 선택 로직의 복잡도를 분산함
3. 장기: 적응형 뱅크 할당(XOR 해싱 등)으로 접근 패턴에 따른 동적 분산과 순서 보장을 구현함

> 요약: 소수 뱅크·그룹핑·적응형 해싱으로 인터리빙의 한계를 극복함

## Ⅵ. 전망
- 발전 방향: HBM·DDR5에서 뱅크 그룹 수가 증가하며 인터리빙의 병렬도가 지속 확대되는 추세임
- 기술사적 판단: CXL 기반 메모리 풀링 환경에서 뱅크 인터리빙의 설계 중요성이 재부상할 전망임
- 기술사 제언: 인터리빙 방식·뱅크 수·접근 패턴 간 상관관계를 정량적으로 분석하는 역량이 필요함
