# 메모리 인터리빙 (Memory Interleaving)

## 미리 알고가기

- 메모리 뱅크: 독립적으로 접근 가능한 메모리 하위 묶음임
- CPU(Central Processing Unit): 메모리 요청을 생성하는 중앙처리장치임
- DMA(Direct Memory Access): CPU 개입을 줄이고 장치가 메모리에 직접 접근하는 방식임
- 워드 인터리빙: 연속 주소를 서로 다른 뱅크에 번갈아 배치하는 방식임
- 블록 인터리빙: 일정 주소 블록 단위로 뱅크를 나누어 배치하는 방식임
- 뱅크 충돌: 동시에 필요한 주소가 같은 뱅크에 몰려 병렬 접근이 막히는 현상임

## Ⅰ. 개요

- **정의/개념**: 메모리 인터리빙은 연속 주소 공간을 여러 메모리 뱅크에 분산 배치해 접근 지연과 대역폭 병목을 뱅크 병렬성 기준으로 완화하는 메모리 구성 방식으로, CPU, DMA, 벡터 처리기가 연속 데이터를 읽을 때 메모리 사이클을 겹쳐 처리하기 위해 사용함
- **배경/필요성**: 프로세서 속도는 빠르게 증가했지만 단일 메모리 뱅크의 접근 시간은 제한적이어서 메모리 병목이 발생함. 여러 뱅크를 병렬로 동작시키면 한 뱅크가 응답하는 동안 다른 뱅크 요청을 시작할 수 있음
- **비유**: 한 계산대에 줄을 세우는 대신 손님을 여러 계산대에 번갈아 보내 대기 시간을 줄이는 방식임

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 메모리 대역폭 개선 구조 설명 | 뱅크 분산, 주소 매핑, 충돌, 병렬 접근 | 캐시와 동일 개념 취급 |

> 요약: 메모리 인터리빙은 여러 뱅크를 주소 매핑으로 병렬화해 순차 접근 대역폭을 높이는 기법임.

## Ⅱ. 특징 및 비교

| 판단 기준 | 단일 뱅크 구성 | 메모리 인터리빙 |
|:---|:---|:---|
| 접근 병렬성 | 한 번에 한 뱅크 사이클에 의존함 | 여러 뱅크 사이클을 겹쳐 처리함 |
| 효과가 큰 패턴 | 무작위 접근에서는 병목이 직접 노출됨 | 연속·스트라이드 접근에서 대역폭이 증가함 |
| 설계 변수 | 메모리 속도와 버스 폭 중심 | 뱅크 수, 주소 매핑, 뱅크 충돌률 중심 |
| 한계 | 구조가 단순하나 확장성이 낮음 | 충돌 패턴이 맞지 않으면 성능 개선이 제한됨 |

> 요약: 인터리빙 선택은 단순 용량 확장이 아니라 접근 패턴과 뱅크 충돌률을 기준으로 판단함.

- **적용 조건**: 연속 접근이나 예측 가능한 stride 접근이 많은 워크로드에서 효과가 큼
- **선택 지표**: 뱅크 충돌률과 지속 대역폭을 함께 확인해야 함

## Ⅲ. 구성요소/구조

```text
+-----------+      +---------------+      +----------+
| CPU/DMA   | ---> | Address mapper| ---> | Bank 0   |
+-----------+      +---------------+      +----------+
                         |           ---> | Bank 1   |
                         |           ---> | Bank 2   |
                         v           ---> | Bank 3   |
                    +-----------+
                    | Scheduler |
                    +-----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 요청 발생기 | CPU, DMA, 가속기가 메모리 읽기·쓰기 주소를 생성함 | 주문을 내는 손님 |
| 주소 매퍼 | 하위 비트 또는 블록 번호로 요청을 특정 뱅크에 배정함 | 줄을 나누는 안내원 |
| 메모리 뱅크 | 독립 사이클로 데이터를 읽고 쓰는 물리 메모리 묶음임 | 여러 계산대 |
| 스케줄러 | 뱅크 상태와 충돌을 고려해 요청 순서를 조정함 | 대기열 관리자 |

> 요약: 인터리빙 구조는 주소 매핑과 뱅크 스케줄링으로 메모리 요청을 병렬 처리함.

### 원리/흐름도

```text
+----------+      +----------+      +----------+      +----------+
| Address  | ---> | Bank Map | ---> | Parallel | ---> | Return   |
+----------+      +----------+      +----------+      +----------+
```

1. **주소 생성**: 프로세서나 DMA가 연속 또는 스트라이드 메모리 주소를 요청함
2. **뱅크 선택**: 주소 하위 비트, 모듈로 연산, 블록 범위로 대상 뱅크를 결정함
3. **병렬 접근**: 서로 다른 뱅크 요청은 겹쳐 실행하고 같은 뱅크 요청은 대기시킴
4. **데이터 조립**: 반환 데이터를 버스 폭과 요청 순서에 맞춰 프로세서에 전달함

> 요약: 주소가 뱅크에 고르게 분산될수록 메모리 접근 사이클이 중첩되어 유효 대역폭이 증가함.

## Ⅳ. 문제점 및 개선방안

- **P1 뱅크 충돌**: 스트라이드가 뱅크 수와 맞물리면 요청이 같은 뱅크에 집중되어 병렬성이 사라짐
- **P1 대응**: XOR(Exclusive OR) 기반 뱅크 해싱, 패딩, stride-aware 배치로 충돌 스트라이드를 분산함 (확인: 뱅크 충돌률)
- **P2 매핑 복잡도**: 캐시 라인, 페이지, NUMA(Non-Uniform Memory Access) 배치와 주소 매핑이 충돌하면 예측하기 어려운 지연이 생김
- **P2 대응**: 캐시 라인·페이지 크기·NUMA 정책과 인터리빙 단위를 함께 설계함 (확인: 소켓당 지속 메모리 대역폭)
- **P3 쓰기 일관성 부담**: 병렬 쓰기와 재정렬이 결합되면 순서 보장과 ECC(Error-Correcting Code) 처리 경로가 복잡해짐
- **P3 대응**: 메모리 컨트롤러의 쓰기 버퍼, 순서 보장 fence, ECC 경로 검증을 분리해 관리함 (확인: 쓰기 지연 분산)

> 요약: 인터리빙은 주소 해싱과 계층별 매핑을 함께 조정해야 지속적인 대역폭 개선을 얻음.

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| HPC 메모리 대역폭 튜닝 | 배열 stride와 페이지 배치를 조정해 채널·뱅크 접근을 고르게 분산함 | sustained bandwidth, bank conflict rate |
| 데이터베이스·분석 서버 | NUMA 노드와 메모리 채널 인터리빙 정책을 워크로드별로 분리해 p99 지연을 관리함 | p99 memory latency, socket bandwidth, remote access ratio |
| HBM·CXL 메모리 설계 | 스택, 채널, 장치 단위 인터리빙을 주소 해싱과 함께 설계해 hot bank를 줄임 | channel utilization, hotspot count, write latency variance |

> 요약: 실무에서는 인터리빙을 켜는 것보다 주소 패턴과 계층별 배치 정책을 측정해 병목 뱅크를 줄이는 것이 핵심임.

## Ⅵ. 결론

- **발전 방향**: HBM(High Bandwidth Memory), CXL(Compute Express Link) 메모리 풀, 다채널 DDR(Double Data Rate)에서는 뱅크뿐 아니라 채널·스택·장치 단위 인터리빙이 함께 중요해짐
- **기술사적 판단**: 메모리 성능 평가는 최대 대역폭보다 실제 워크로드의 스트라이드, 지역성, 경합 기준으로 수행해야 함
- **기술사 제언**: 하드웨어 설계와 시스템 소프트웨어에서 주소 배치 정책을 함께 관리해 뱅크 충돌을 관측 가능한 지표로 운영해야 함
