## 미리 알고가기

- 메모리 인터리빙은 연속 주소를 여러 뱅크에 분산해 병렬 접근을 높이는 기법임
- 효과는 메모리 뱅크 수와 주소 매핑과 접근 패턴에 크게 좌우됨
- 캐시와는 다른 계층의 대역폭 확장 방법임

## Ⅰ. 개요

- **정의/개념**: 메모리 인터리빙은 주소 공간을 여러 메모리 뱅크에 분산 배치해 연속 또는 규칙적 접근 시 여러 뱅크를 겹쳐 사용하도록 만드는 메모리 대역폭 확장 기법임
- **배경/필요성**: 단일 뱅크 메모리는 한 번에 처리할 수 있는 요청 수가 제한적이므로, 프로세서와 DMA와 벡터 처리기의 대역폭 요구를 맞추기 위해 뱅크 병렬성이 필요함

## Ⅱ. 특징

- 연속 접근과 규칙적 stride 접근에서 대역폭 향상 효과가 큼
- 주소 매핑이 좋으면 메모리 사이클을 겹쳐 처리할 수 있음
- 잘못된 stride와 뱅크 수 조합은 bank conflict를 늘려 효과를 상쇄함
- 캐시 미스 후 메모리 병목을 줄이는 하위 계층 최적화 수단임

## Ⅲ. 종류 및 비교

| 판단 기준 | 단일 뱅크 | 워드 인터리빙 | 블록 인터리빙 |
|:---|:---|:---|:---|
| 병렬성 | 낮음 | 높음 | 중간 |
| 연속 접근 성능 | 낮음 | 높음 | 중간 |
| 지역성 유지 | 중간 | 낮음 | 높음 |
| bank conflict 민감도 | 낮음 | 높음 | 중간 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Request Source | CPU와 DMA와 가속기가 메모리 요청 패턴을 생성함 |
| Address Mapper | 주소 비트와 모듈로 규칙으로 요청을 특정 뱅크에 분산시킴 |
| Memory Bank Set | 독립 접근 가능한 뱅크들이 병렬 처리 능력의 실제 기반이 됨 |
| Scheduler, Return Logic | 충돌 시 순서를 조정하고 결과를 원래 요청 순서에 맞춰 반환함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 주소 요청 생성   | --> | 뱅크 매핑      | --> | 병렬 또는 대기 처리 | --> | 데이터 반환      |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **주소 요청 생성**: CPU나 DMA가 연속 또는 stride 요청을 발행함
2. **뱅크 매핑**: 주소 규칙에 따라 요청을 각 뱅크에 배정함
3. **병렬 또는 대기 처리**: 다른 뱅크는 병렬 처리하고 같은 뱅크는 대기시킴
4. **데이터 반환**: 스케줄러가 결과를 조합해 요청자에 전달함

## Ⅵ. 문제점 및 해결 방안

1. 문제: stride 패턴이 뱅크 수와 맞물리면 요청이 특정 뱅크에 몰려 인터리빙 효과가 거의 사라질 수 있다
   - 해결방안: XOR 기반 뱅크 해싱과 데이터 패딩을 적용하고 bank conflict rate와 sustained bandwidth로 검증함
2. 문제: 캐시 라인과 페이지 매핑과 인터리빙 규칙이 어긋나면 예상하기 어려운 지연이 발생할 수 있다
   - 해결방안: cache line과 NUMA 정책을 함께 설계하고 latency variance와 socket bandwidth로 검증함
3. 문제: 병렬 쓰기와 ECC 처리 경로가 복잡해지면 데이터 정합성과 순서 보장 비용이 커질 수 있다
   - 해결방안: write ordering 정책과 ECC path 검증을 강화하고 write stall time과 ECC correction overhead로 검증함

## Ⅶ. 적용 사례

- 벡터 연산 시스템에서는 연속 배열 접근을 인터리빙 메모리에 배치하고, sustained bandwidth와 vector stall reduction로 결과를 확인함
- DMA 기반 스토리지 경로에서는 다중 뱅크 병렬 접근을 활용하고, transfer throughput과 bank conflict rate로 결과를 확인함
- NUMA 서버 메모리 구성에서는 인터리빙 정책을 조정하고, socket memory bandwidth와 latency variance로 결과를 확인함

## Ⅷ. 결론

메모리 인터리빙의 핵심은 뱅크 수보다 주소 패턴을 얼마나 고르게 분산시키느냐에 있으므로, 워크로드 접근 패턴을 먼저 보고 설계해야 함.
