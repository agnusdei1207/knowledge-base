## 미리 알고가기

- 3-상태 버퍼는 출력이 0, 1뿐 아니라 high-impedance 상태를 가질 수 있는 버퍼임
- 다수 장치가 하나의 버스를 공유할 때 비선택 장치를 전기적으로 분리하는 데 사용함
- enable 신호 제어가 잘못되면 bus contention이 발생함

## Ⅰ. 개요

- **정의/개념**: 3-상태 버퍼는 입력 신호를 전달하되 enable 상태에 따라 출력선을 0, 1 또는 고임피던스 Z 상태로 만들어 공유 버스 접속 여부를 제어하는 디지털 회로임
- **배경/필요성**: 여러 회로 블록이 하나의 데이터 버스를 함께 쓸 때 비선택 회로가 계속 출력을 걸면 충돌이 생기므로, 전기적 분리를 위한 출력 차단 메커니즘이 필요함

## Ⅱ. 특징

- 선택된 회로만 버스를 구동하고 나머지는 Z 상태로 분리할 수 있음
- 멀티플렉서보다 버스 공유 구조에 자연스럽게 맞음
- enable 제어 타이밍이 어긋나면 단락성 충돌과 전력 낭비가 생길 수 있음
- 현대 SoC 내부에서는 전용 interconnect와 mux 구조가 늘면서 사용 범위가 제한되기도 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 3-상태 버퍼 | 멀티플렉서 | 오픈드레인 |
|:---|:---|:---|:---|
| 버스 공유 적합성 | 높음 | 중간 | 중간 |
| 출력 제어 방식 | enable로 Z 상태 생성 | 선택선으로 단일 입력 선택 | 풀업 저항 기반 |
| 충돌 위험 | enable 오류 시 높음 | 구조적으로 낮음 | 속도 낮음 |
| 대표 용도 | 데이터 버스 | 선택 회로 | I2C 등 공통선 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 입력 신호선 | 버퍼가 전달할 논리값이 들어오는 경로임 |
| Enable 제어 | 출력 활성화 여부를 결정하며 bus contention 방지의 핵심 조건임 |
| Output Driver | enable이 켜지면 실제 버스를 구동하고 꺼지면 Z 상태로 전환함 |
| 공유 버스 | 여러 버퍼 출력이 연결되는 공통선으로 동시 활성화 방지가 필수임 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 입력 신호 준비 | --> | enable 판정    | --> | 출력 또는 Z 전환 | --> | 공유 버스 전달 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **입력 신호 준비**: 전달할 논리값을 버퍼 입력에 둠
2. **Enable 판정**: 선택된 회로인지 확인함
3. **출력 또는 Z 전환**: 선택되면 값을 출력하고 아니면 Z 상태로 둠
4. **공유 버스 전달**: 활성 버퍼만 버스를 구동함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 두 개 이상의 버퍼가 동시에 활성화되면 버스 충돌로 과전류와 데이터 오류가 발생할 수 있음
   - 해결방안: one-hot enable 제어와 타이밍 검증을 적용하고 bus contention count와 peak current로 안전성을 검증함
2. 문제: enable 전환 타이밍이 겹치면 짧은 순간의 glitch나 불안정한 논리값이 발생할 수 있음
   - 해결방안: non-overlap timing과 register synchronization을 적용하고 glitch rate와 setup-hold violation으로 검증함
3. 문제: 긴 버스와 다수 부하가 연결되면 신호 무결성과 전파 지연이 악화될 수 있음
   - 해결방안: 버퍼 분할과 배선 길이 최적화를 적용하고 signal integrity와 propagation delay로 검증함

## Ⅶ. 적용 사례

- 마이크로프로세서 외부 데이터 버스에서는 선택된 메모리만 선을 구동하게 하고 확인 지표는 bus contention count와 read stability임
- FPGA 기반 보드 설계에서는 GPIO 공유선 제어에 사용하고 확인 지표는 output enable timing과 error rate임
- 레거시 시스템 인터페이스에서는 멀티디바이스 버스 분리를 구현하고 확인 지표는 signal integrity와 power noise임

## Ⅷ. 결론

3-상태 버퍼의 핵심은 논리 연산 자체보다 공유 버스를 안전하게 분리하는 데 있으므로, enable 제어의 상호배제와 타이밍 검증이 설계 성패를 가름함.
