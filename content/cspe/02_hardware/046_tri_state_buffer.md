## Ⅰ. 개요
- **정의**: 출력이 0, 1, Hi-Z 세 가지 상태를 갖는 버퍼 회로임
- **배경/필요성**: 다수 장치가 하나의 공유 버스에 연결될 때 전기적 충돌 없이 한 장치만 버스를 구동해야 하므로 필요함
- **비유**: 여러 사람이 하나의 마이크를 공유할 때, 발언권 없는 사람은 마이크 스위치를 꺼 두는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 공유 버스 구동 원리 이해 | Hi-Z 상태의 의미와 역할 | Hi-Z는 "연결 끊김"이지 논리 0이 아님을 구분 |

> 요약: 3상태 버퍼는 Enable 신호로 출력을 Hi-Z 상태로 전환하여 공유 버스의 전기적 충돌을 방지하는 회로임

## Ⅱ. 구성요소
```text
          Enable
            |
            v
Input ---> [Buffer] ---> Output (0 / 1 / Hi-Z)
            |
            +--- Enable=1 : Input 값 그대로 출력
            +--- Enable=0 : Hi-Z (고임피던스, 회로 분리)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Input | 버퍼에 인가되는 논리 입력 신호 | 발언할 내용 |
| Enable | 출력 활성화 여부를 결정하는 제어 신호 | 마이크 스위치 |
| Output | 0, 1, Hi-Z 중 하나의 상태를 갖는 출력 단자 | 스피커로 나가는 음성 |
| Hi-Z 상태 | 출력 단자가 전기적으로 분리된 고임피던스 상태 | 마이크가 꺼진 상태 |

> 요약: Enable 신호가 출력의 활성·비활성을 결정하며, 비활성 시 Hi-Z로 버스에서 전기적으로 분리됨

## Ⅲ. 절차
```text
버스 접근 요청 --> 버스 중재기 판정 --> Enable 활성화 --> 데이터 전송
      |                  |                  |                |
      v                  v                  v                v
  장치 요청          우선순위 결정      해당 버퍼 개방      버스 구동
```
- 1단계: 장치가 버스 사용을 요청하며, 나머지 장치는 Hi-Z 상태를 유지함
- 2단계: 버스 중재기(Bus Arbiter)가 우선순위에 따라 구동 장치를 선정함
- 3단계: 선정된 장치의 3상태 버퍼 Enable 신호를 활성화하여 출력 경로를 개방함
- 4단계: 해당 장치가 버스를 구동하여 데이터를 전송하고, 완료 후 Enable을 비활성화함

> 요약: 버스 중재기가 한 장치만 Enable하여 충돌 없이 공유 버스를 시분할 사용하는 절차임

## Ⅳ. 문제점
- 버스 경합(Bus Contention): 두 버퍼가 동시에 Enable되면 출력 충돌로 과전류 발생 — 회로 손상 위험이 있음
- 전파 지연 증가: 버퍼를 경유하므로 직접 연결 대비 ns 단위 지연이 추가됨 — 고속 버스에서 타이밍 마진 감소
- 부유 상태 노이즈: Hi-Z 구간에서 버스 라인이 부유(Floating)하여 노이즈에 취약함 — 오동작 유발 가능

> 요약: 동시 Enable에 의한 버스 경합, 전파 지연, Hi-Z 구간의 노이즈가 주요 문제임

## Ⅴ. 개선방안
1. 단기: Break-Before-Make 제어 로직 적용으로 두 버퍼가 동시 Enable되는 시간 구간을 제거함
2. 중기: 저지연 CMOS 버퍼 채택 및 버스 클록 대비 타이밍 검증(STA)을 수행함
3. 장기: 풀업/풀다운 저항(Bus Keeper) 또는 차동 시그널링 방식 도입으로 부유 상태를 제거함

> 요약: 동시 Enable 방지, 저지연 버퍼 채택, Bus Keeper 도입 순으로 문제를 해결함

## Ⅵ. 전망
- 발전 방향: 포인트-투-포인트 직렬 인터커넥트(PCIe 등) 확산으로 공유 버스 사용이 감소하나, MCU 내부 APB/AHB 버스에서는 여전히 활용됨
- 기술사적 판단: SoC 내부 온칩 버스 설계 시 3상태 버퍼와 멀티플렉싱 방식의 트레이드오프를 이해해야 함
- 기술사 제언: 공유 자원 접근 제어의 기본 원리로서 버스 중재·Hi-Z 개념을 숙지할 필요
