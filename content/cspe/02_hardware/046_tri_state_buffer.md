## 미리 알고가기

- 3-상태 버퍼는 출력이 0, 1뿐 아니라 고임피던스(high-impedance) 상태를 가질 수 있는 버퍼임
- 다수 장치가 하나의 버스를 공유할 때 비선택 장치를 전기적으로 분리하는 데 사용함
- enable 신호 제어가 잘못되면 bus contention이 발생함

## Ⅰ. 개요

- **정의/개념**: 3-상태 버퍼는 enable 상태에 따라 입력을 0·1로 전달하거나 출력선을 고임피던스 Z 상태로 분리해 공유 버스 접속을 제어하는 디지털 회로임
- **배경/필요성**: 여러 회로 블록이 하나의 데이터 버스를 함께 쓸 때 비선택 회로가 출력을 유지하면 충돌이 생기므로 전기적 분리를 위한 출력 차단 메커니즘이 필요함

## Ⅱ. 특징

- 선택된 회로만 버스를 구동하고 나머지는 Z 상태로 분리할 수 있음
- 멀티플렉서보다 공유 버스 구조에 적합함
- enable 제어 타이밍이 어긋나면 단락 전류와 데이터 오류가 생길 수 있음
- 현대 SoC 내부에서는 전용 interconnect와 mux 구조가 늘면서 사용 범위가 줄어듦

## Ⅲ. 종류 및 비교

| 판단 기준 | 3-상태 버퍼 | 멀티플렉서 | 오픈드레인 |
|:---|:---|:---|:---|
| 버스 공유 적합성 | 높음 | 중간 | 중간 |
| 출력 제어 방식 | enable로 Z 상태 생성 | 선택선으로 단일 입력 선택 | 풀업 저항 기반 |
| 충돌 위험 | enable 오류 시 높음 | 구조적으로 낮음 | 낮음 |
| 대표 용도 | 데이터 버스 | 선택 회로 | I2C 등 공통선 |

> 요약: 3-상태 버퍼는 enable로 버스를 분리하고, 멀티플렉서는 선택선으로 입력을 고정 선택함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 입력 신호선 | 버퍼가 전달할 논리값이 들어오는 경로임 |
| Enable 제어 신호 | 출력 활성화 여부를 결정하며 bus contention 방지의 핵심 조건임 |
| Output Driver | enable이 켜지면 실제 버스를 구동하고 꺼지면 Z 상태로 전환함 |
| 공유 버스 | 여러 버퍼 출력이 연결되는 공통선으로 동시 활성화 방지가 필수임 |

```text
+-------------+     +-------------+     +-------------+     +-------------+
| Input Signal| --> | Enable Ctrl | --> | Output Driver| --> | Shared Bus  |
+-------------+     +-------------+     +-------------+     +-------------+
                                        |
                                        v
                                      Z State
```

> 요약: enable이 켜진 버퍼만 공유 버스를 구동하고 나머지는 Z 상태로 분리됨.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 입력 신호 준비 | --> | enable 판정    | --> | 출력 또는 Z 전환 | --> | 공유 버스 전달 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **입력 신호 준비**: 전달할 논리값을 버퍼 입력에 둠
2. **Enable 판정**: 선택된 회로인지 확인함
3. **출력 또는 Z 전환**: 선택되면 값을 출력하고 아니면 Z 상태로 둠
4. **공유 버스 전달**: 활성 버퍼만 버스를 구동함

> 요약: 입력값은 enable 판정 뒤 출력 또는 Z 상태로 갈라져 버스 충돌을 방지함.

## Ⅵ. 실무 적용 및 유의점

1. 외부 메모리·공유 데이터 버스는 동시 enable이 과전류와 데이터 오류를 만들 수 있으므로 one-hot 제어와 non-overlap timing을 적용하고 bus contention count, peak current로 확인함
2. FPGA 보드·레거시 인터페이스처럼 배선이 길면 Z 전환 글리치와 신호 열화가 생기므로 버퍼 분할과 타이밍 동기화를 적용하고 glitch rate, propagation delay로 확인함

## Ⅶ. 결론

3-상태 버퍼는 공유 버스를 전기적으로 분리하는 회로이므로 enable 상호배제와 전환 타이밍이 보장될 때만 안전하게 적용함.

## 작성 근거(검토용)

- 3-상태 버퍼는 0, 1, Z 상태와 enable 제어를 중심으로 설명함
- 비교표는 버스 공유 방식, 출력 제어, 충돌 위험을 기준으로 정리함
- 실무 판단은 bus contention, non-overlap timing, peak current로 검증 가능하게 작성함
