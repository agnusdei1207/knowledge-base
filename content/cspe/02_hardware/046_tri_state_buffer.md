# 3-상태 버퍼·트라이스테이트 (Tri-State Buffer)

## 미리 알고가기

- 논리 상태: 디지털 출력은 일반적으로 `0` 또는 `1` 전압 레벨을 가짐
- Hi-Z: 고임피던스(High Impedance, Hi-Z)는 회로가 버스에서 전기적으로 분리된 상태임
- Enable: 버퍼가 신호를 버스로 내보낼지 차단할지 결정하는 제어 입력임
- 버스 컨텐션: 두 출력이 서로 다른 값을 동시에 구동해 과전류와 오동작이 발생하는 상태임

## Ⅰ. 개요

- **정의/개념**: 3-상태 버퍼는 입력 값을 `0`, `1`, `Hi-Z` 중 하나의 출력 상태로 제어하는 디지털 버퍼이며, Enable 신호를 기준으로 선택된 장치만 공유 버스를 구동하게 해 전기적 충돌을 방지함.
- **배경/필요성**: 메모리, I/O 장치, 프로세서가 같은 데이터 버스를 공유할 때 선택되지 않은 장치는 신호를 밀어내지 않아야 함. 트라이스테이트는 배선 수를 줄이면서 다수 장치의 버스 공유를 가능하게 함.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 공유 버스 전기적 제어 원리 설명 | 0, 1, Hi-Z, Enable, bus contention | Hi-Z 의미 누락, 단순 논리 게이트로만 설명 |

> 요약: 트라이스테이트는 선택된 회로만 공유 버스를 구동하고 나머지는 Hi-Z로 분리하는 버스 공유용 출력 제어 방식임.

## Ⅱ. 특징 및 비교

| 판단 기준 | 일반 버퍼 | 3-상태 버퍼 |
|:---|:---|:---|
| 출력 상태 | `0` 또는 `1`만 출력함 | `0`, `1`, `Hi-Z`를 출력함 |
| 제어 입력 | 입력 값이 곧 출력 값이 됨 | Enable 신호가 출력 연결 여부를 결정함 |
| 공유 버스 적합성 | 여러 출력 연결 시 충돌 가능 | 선택 출력만 버스를 구동해 공유 가능 |
| 설계 주의점 | 논리값 전달 중심 | Enable 타이밍, floating bus, 컨텐션 방지 중요 |

트라이스테이트의 핵심은 `Hi-Z`가 논리값이 아니라 전기적으로 버스에서 빠지는 상태라는 점임. 따라서 논리 설계뿐 아니라 Enable 신호의 타이밍, 풀업·풀다운, 버스 점유 규칙이 함께 설계되어야 함.

## Ⅲ. 구성요소/구조

```text
             Enable A
                |
+----------+    v
| Device A | -> [3-State] ----+
+----------+                  |
                              +---- Shared Bus
+----------+                  |
| Device B | -> [3-State] ----+
+----------+    ^
                |
             Enable B
```

| 구성요소 | 설명 | 핵심 포인트 |
|:---|:---|:---|
| 입력 신호 | 버스에 전달할 `0` 또는 `1` 데이터임 | 데이터 값 |
| Enable 신호 | 버퍼 출력 활성화 여부를 결정함 | 선택 제어 |
| 출력 드라이버 | 활성화 시 버스에 전압 레벨을 구동함 | 전류 구동 능력 |
| Hi-Z 상태 | 비활성화 시 회로가 버스에서 분리됨 | 충돌 방지 |
| 공유 버스 | 여러 장치가 번갈아 사용하는 데이터 경로임 | 단일 구동 원칙 |

### 원리/흐름도

```text
+--------------+      +--------------+      +-------------+
| Select Device| ---> | Enable Output| ---> | Drive Bus   |
+--------------+      +--------------+      +-------------+
        |                      |
        v                      v
  Others Hi-Z           Contention Check
```

버스 제어 로직은 하나의 장치 Enable만 활성화하고 나머지 장치는 Hi-Z로 둠. 이 규칙이 깨지면 두 출력이 서로 다른 전압을 동시에 구동해 컨텐션과 과전류가 발생함.

## Ⅳ. 문제점 및 개선방안

1. **버스 컨텐션**: 두 개 이상의 버퍼가 동시에 활성화되면 서로 다른 논리값을 강제로 구동해 회로 손상과 데이터 오류가 발생함.
   - **개선방안**: one-hot enable, 상호 배타 제어, 타이밍 검증을 적용함. (확인: contention 검출, enable overlap)
2. **부유 버스(floating bus)**: 모든 장치가 Hi-Z이면 버스 전압이 불안정해 임의 값으로 인식될 수 있음.
   - **개선방안**: pull-up/pull-down, bus keeper, 명시적 idle 값을 사용함. (확인: idle 전압 안정성)
3. **고속 설계 한계**: 긴 공유 버스와 큰 부하는 신호 무결성, 지연, 전력 문제를 키움.
   - **개선방안**: point-to-point 인터커넥트, 멀티플렉서, NoC 구조로 전환함. (확인: setup/hold violation, 신호 무결성 측정)

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 메모리 데이터 버스 | 읽기 사이클에서 선택된 메모리 칩만 데이터 버스를 구동하고 나머지는 Hi-Z 상태로 둠 | enable timing, bus contention |
| 마이크로컨트롤러 GPIO | 입출력 방향 전환 시 출력 enable을 제어해 외부 회로와 충돌을 피함 | GPIO 방향 설정 오류, 전류 이상 |
| 보드 레벨 공유 신호 | 여러 주변장치가 같은 데이터선을 사용할 때 chip select와 enable을 조합함 | 신호 무결성, idle 전압 |

## Ⅵ. 결론

3-상태 버퍼는 `0/1` 논리값 전달보다 `Hi-Z`를 통한 버스 분리가 핵심인 회로임. 공유 버스를 단순하게 만들 수 있지만 Enable 타이밍이 잘못되면 컨텐션이나 floating bus가 발생함. 따라서 실제 설계에서는 데이터 값보다 선택 제어, idle 상태, 신호 무결성을 중심으로 검증해야 함.
