## 미리 알고가기

- 논리 상태: 디지털 출력은 일반적으로 `0` 또는 `1` 전압 레벨을 가짐
- Hi-Z: 고임피던스(High Impedance, Hi-Z)는 회로가 버스에서 전기적으로 분리된 상태임
- Enable: 버퍼가 신호를 버스로 내보낼지 차단할지 결정하는 제어 입력임
- 버스 컨텐션: 두 출력이 서로 다른 값을 동시에 구동해 과전류가 발생하는 상태임

## Ⅰ. 개요

- **정의**: 3-상태 버퍼는 입력 값을 `0`, `1`, `Hi-Z` 중 하나의 출력 상태로 제어하는 디지털 버퍼로, 여러 장치가 같은 배선을 공유할 때 Enable 신호를 기준으로 선택 장치만 버스를 구동하게 해 전기적 충돌을 방지함
- **배경/필요성**: 메모리, I/O 장치, 프로세서가 같은 데이터 버스를 공유하면 선택되지 않은 장치가 신호를 밀어내지 않아야 함. 트라이스테이트는 선택 장치만 버스를 구동하게 해 회로 수와 배선을 줄임
- **비유**: 한 마이크 라인에 여러 발표자가 연결되어 있지만 말할 사람만 스위치를 켜는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 공유 버스 전기적 제어 원리 설명 | 0, 1, Hi-Z, Enable, 버스 충돌 | Hi-Z 의미 누락 |

> 요약: 트라이스테이트는 선택된 회로만 공유 버스를 구동하게 하는 버스 공유용 출력 제어 방식임.

## Ⅱ. 특징/비교

| 판단 기준 | 일반 푸시풀 출력 | 3-상태 버퍼 |
|:---|:---|:---|
| 공유 버스 적합성 | 항상 0 또는 1을 구동하므로 다중 출력 연결에 부적합함 | 비선택 시 Hi-Z로 분리되어 다중 장치 공유가 가능함 |
| 제어 기준 | 출력 값만 제어함 | 출력 값과 버스 연결 여부를 함께 제어함 |
| 주요 위험 | 서로 다른 출력 연결 시 단락 전류가 발생함 | Enable 타이밍 오류 시 일시적 버스 컨텐션이 발생함 |

> 요약: 3-상태 버퍼의 차별점은 논리값 전달보다 버스 연결과 분리를 제어한다는 점임.

## Ⅲ. 구성요소

```text
+-------+      +---------+      +------------+
| Input | ---> | Buffer  | ---> | Shared Bus |
+-------+      +---------+      +------------+
                    ^
                    |
              +------------+
              | Enable Ctrl|
              +------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 입력 신호 | 버스로 전달할 원래 논리값을 제공함 | 발표 내용 |
| Enable 제어 | 장치 선택 신호를 받아 출력 구동 여부를 결정함 | 마이크 스위치 |
| 출력 드라이버 | Enable이 활성일 때 입력을 버스 전압으로 구동함 | 음성 증폭기 |
| 공유 버스 | 여러 출력이 연결되지만 한 시점에는 하나의 구동만 허용함 | 공용 방송선 |

> 요약: 트라이스테이트 구조는 데이터 입력, 출력 드라이버, Enable 제어, 공유 버스로 구성됨.

## Ⅳ. 절차

```text
+----------+     +----------+     +----------+     +----------+
| Select   | --> | Enable   | --> | Drive    | --> | HiZ      |
+----------+     +----------+     +----------+     +----------+
```

1. **장치 선택**: 주소 디코더나 칩 선택 신호가 버스를 사용할 장치를 결정함
2. **Enable 활성화**: 선택된 장치의 버퍼만 출력 구동 상태가 되며 나머지는 Hi-Z가 됨
3. **신호 구동**: 출력 드라이버가 입력 값을 공유 버스에 전달하고 수신 장치가 샘플링함
4. **Hi-Z 복귀**: 전송 완료 후 Enable을 비활성화해 다음 장치가 버스를 사용할 수 있게 함

> 요약: 선택된 장치만 Enable을 켜고 전송 후 즉시 Hi-Z로 복귀하는 순서가 핵심임.

## Ⅴ. 문제점 및 개선방안

- **P1 버스 컨텐션**: 두 장치의 Enable이 겹치면 서로 다른 전압을 동시에 구동해 과전류와 데이터 오류가 발생함
- **P1 대응**: 원핫 디코딩, 상호배제 로직, 버스 컨텐션 검출 회로를 적용함 (확인: 동시 Enable 검출 건수)
- **P2 플로팅 버스**: 모든 장치가 고임피던스(High Impedance, Hi-Z)일 때 버스 전압이 떠서 노이즈에 민감한 불확정 상태가 될 수 있음
- **P2 대응**: 풀업, 풀다운, 버스 홀더를 배치해 비구동 상태의 기본 전압을 보정함 (확인: 유휴 버스 전압 범위)
- **P3 타이밍 글리치**: Enable 전환 순간의 지연 차이로 짧은 펄스나 잘못된 샘플링이 발생할 수 있음
- **P3 대응**: Enable 설정/해제 시간을 타이밍 제약에 반영하고 샘플링 여유를 둠 (확인: setup/hold 위반 수)

> 요약: 개선은 선택 신호의 배타성 보장과 유휴 상태 전압 안정화, 타이밍 검증으로 이루어짐.

## Ⅵ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 메모리 데이터 버스 | 주소 디코더가 선택한 메모리 칩만 Enable을 활성화하고 나머지는 고임피던스(High Impedance, Hi-Z)로 분리함 | 동시 Enable 검출 건수, 버스 컨텐션 전류 |
| 마이크로컨트롤러 주변장치 공유 | 여러 주변장치가 같은 데이터 라인을 공유할 때 칩 선택 신호와 샘플링 시간을 제약함 | setup/hold 위반 수, 전송 오류율 |
| 테스트·디버그 포트 | 유휴 구간에는 버스 홀더나 풀업을 둬 플로팅 상태를 방지함 | 유휴 버스 전압 범위, 노이즈 오검출 건수 |

> 요약: 트라이스테이트 적용은 선택 신호의 배타성, 유휴 전압, 전환 타이밍을 계측할 수 있어야 함.

## Ⅶ. 전망

- **발전 방향**: 칩 내부에서는 멀티플렉서와 네트워크 온 칩(Network-on-Chip, NoC)이 늘고, 외부 병렬 버스에서는 여전히 공유 신호 제어 원리로 활용됨
- **기술사적 판단**: 트라이스테이트는 회로 소자 설명보다 공유 버스에서 충돌을 막는 조건을 중심으로 설명해야 함
- **기술사 제언**: Enable 신호, Hi-Z, 버스 컨텐션을 함께 제시하면 버스 구조와 전기적 안전성을 동시에 보여줄 수 있음
