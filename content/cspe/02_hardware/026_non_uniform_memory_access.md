## Ⅰ. 개요
- **정의**: 프로세서가 자기 노드 로컬 메모리와 타 노드 리모트 메모리에 접근할 때 지연 시간이 다른 메모리 구조임
- **배경/필요성**: 코어 수가 증가하면 단일 메모리 버스(UMA)에 병목이 집중되어 확장이 불가하므로, 노드별 로컬 메모리를 분산 배치하여 대역폭을 확보할 필요
- **비유**: 자기 책상 서랍(로컬)은 바로 꺼내지만, 옆 사무실 서랍(리모트)은 걸어가야 하므로 느린 구조와 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| UMA 대비 NUMA 차이 이해 | 로컬 vs 리모트 지연 비율(1:3~1:10) | 디렉터리 일관성 프로토콜(020 참조) 누락 주의 |

> 요약: 코어별 로컬/리모트 메모리 접근 지연 차이를 갖는 분산 메모리 아키텍처임

## Ⅱ. 구성요소
```text
+----------+    Interconnect    +----------+
| Node 0   |<----------------->| Node 1   |
| CPU+L3   |                   | CPU+L3   |
| Local    |                   | Local    |
| DRAM     |                   | DRAM     |
+----------+                   +----------+
      |                              |
      v                              v
  Local Access                 Remote Access
  (low latency)               (high latency)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 노드(Node) | CPU·로컬 DRAM·캐시가 묶인 단위로, 독립적 메모리 컨트롤러 보유 | 자기 책상 + 서랍 한 세트 |
| 인터커넥트 | 노드 간 데이터 전송 경로(QPI, UPI, Infinity Fabric 등) | 사무실 간 복도 |
| 로컬 메모리 | 해당 노드 CPU가 직접 제어하는 DRAM 영역 | 자기 서랍 |
| 리모트 메모리 | 타 노드에 물리적으로 부착된 DRAM 영역 | 옆 사무실 서랍 |
| 디렉터리 캐시 | 원격 캐시라인 위치를 추적하여 일관성 유지(020 참조) | 서류 위치 대장 |

> 요약: 노드·인터커넥트·로컬/리모트 메모리·디렉터리로 구성되며, 노드 내 접근이 핵심 성능 결정 요소임

## Ⅲ. 절차
```text
CPU 메모리 요청 --> 주소 확인 --> 로컬? --YES--> 로컬 DRAM 접근
                                    |
                                   NO
                                    |
                                    v
                           인터커넥트 통해 리모트 노드 접근
                                    |
                                    v
                           디렉터리 일관성 검증 --> 데이터 반환
```
- 1단계: CPU가 가상 주소를 물리 주소로 변환하여 메모리 접근 요청 발행
- 2단계: 메모리 컨트롤러가 물리 주소의 노드 소속을 판별(로컬/리모트 결정)
- 3단계: 리모트인 경우 인터커넥트를 통해 원격 노드의 메모리 컨트롤러로 요청 전달
- 4단계: 디렉터리 프로토콜로 캐시 일관성 검증 후 데이터를 요청 노드에 반환

> 요약: 주소 기반 노드 판별 후 로컬이면 직접, 리모트이면 인터커넥트 경유로 접근함

## Ⅳ. 문제점
- 리모트 접근 지연: 인터커넥트 홉 수에 비례하여 지연이 증가 — 로컬 대비 3~10배 느려 성능 편차 발생
- NUMA 비인지 스케줄링: OS가 노드 친화성 무시 시 스레드와 데이터가 다른 노드에 배치 — 리모트 접근 비율 급증
- 메모리 불균형: 특정 노드에 메모리 할당이 편중되면 해당 노드 DRAM 부족 — OOM 또는 스왑 발생

> 요약: 리모트 지연, 비인지 스케줄링, 메모리 편중이 NUMA 환경의 주요 성능 저하 원인임

## Ⅴ. 개선방안
1. 단기: `numactl`, `mbind()` 등으로 프로세스·메모리를 특정 노드에 명시적 바인딩하여 리모트 접근 비율 감소
2. 중기: OS 스케줄러에 NUMA 친화성(affinity) 정책 적용하여 스레드를 데이터 소재 노드에 배치
3. 장기: CXL(035 참조) 기반 메모리 풀링으로 노드 간 메모리 용량을 동적 재분배하여 편중 해소

> 요약: 명시적 바인딩 → NUMA 친화 스케줄링 → CXL 풀링 순으로 리모트 접근·편중 문제를 해소함

## Ⅵ. 전망
- 발전 방향: CXL 3.0 메모리 공유·풀링이 NUMA 경계를 유연화하여 접근 지연 격차 축소
- 기술사적 판단: 코어 수 증가와 AI 워크로드 확대로 NUMA 최적화는 서버 설계의 기본 요건으로 고착됨
- 기술사 제언: NUMA 토폴로지 분석 도구(`lstopo`, `numastat`)를 활용한 성능 프로파일링 역량 확보 필요
