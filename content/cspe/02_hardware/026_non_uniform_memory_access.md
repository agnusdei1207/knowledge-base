## Ⅰ. 개요
- **정의**: 프로세서마다 로컬 메모리를 두고, 원격 메모리 접근 시 지연이 달라지는 공유 메모리 구조
- **배경/필요성**: 멀티소켓 시스템에서 단일 메모리 버스는 병목이 되므로, 각 소켓에 로컬 메모리를 배치하여 대역폭을 분산할 필요가 있음
- **비유**: 각 팀이 자기 책상 서랍(로컬 메모리)을 갖되, 다른 팀 서랍(원격 메모리)도 열 수 있지만 걸어가야 하는 사무실 배치와 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| UMA와 NUMA의 구조적 차이 이해 | 로컬/원격 접근 지연 비대칭 | UMA와 혼동하지 말 것, NUMA ratio 개념 언급 필요 |

> 요약: 프로세서별 로컬 메모리를 두어 접근 지연이 비균일한 공유 메모리 아키텍처임

## Ⅱ. 구성요소
```text
+----------+    Interconnect    +----------+
| CPU Node |<------------------>| CPU Node |
|  +-----+ |                    |  +-----+ |
|  | CPU  | |                    |  | CPU  | |
|  +-----+ |                    |  +-----+ |
|  +-----+ |                    |  +-----+ |
|  | Local| |                    |  | Local| |
|  | Mem  | |                    |  | Mem  | |
|  +-----+ |                    |  +-----+ |
+----------+                    +----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| NUMA 노드 | CPU와 로컬 메모리를 묶은 단위, 소켓 단위로 구성됨 | 자기 서랍이 있는 개인 책상 |
| 로컬 메모리 | 해당 노드 CPU가 저지연으로 접근하는 메모리 영역 | 팔 뻗으면 닿는 서랍 |
| 원격 메모리 | 다른 노드에 속한 메모리, 인터커넥트를 경유하여 접근함 | 복도 건너 다른 팀 서랍 |
| 인터커넥트 | 노드 간 데이터를 전달하는 고속 연결망(QPI, UPI 등) | 팀 간 복도 |

> 요약: CPU·로컬 메모리·인터커넥트로 구성된 노드 단위 아키텍처임

## Ⅲ. 절차
```text
CPU 메모리 요청 --> 주소 확인 --> 로컬 여부 판별
       |                              |
       |          +--------------------+----+
       |          | Yes                     | No
       v          v                         v
   로컬 메모리 접근              인터커넥트 경유 원격 접근
       |                              |
       +----------> 데이터 반환 <------+
```
- 1단계: CPU가 가상 주소로 메모리 접근을 요청함
- 2단계: 메모리 컨트롤러가 물리 주소를 확인하여 로컬 노드 소속 여부를 판별함
- 3단계: 로컬이면 저지연 접근, 원격이면 인터커넥트를 경유하여 해당 노드 메모리에 접근함
- 4단계: 데이터를 요청 CPU에 반환하며, 원격 접근 시 로컬 대비 1.5~3배 지연이 발생함

> 요약: 주소 기반으로 로컬/원격을 판별한 뒤 경로에 따라 지연이 달라지는 접근 절차임

## Ⅳ. 문제점
- 원격 접근 지연: 인터커넥트 홉 경유 — 로컬 대비 수배의 지연이 발생하여 처리량이 저하됨
- 메모리 편중: OS가 NUMA를 인식하지 못하면 특정 노드에 할당이 집중되어 로컬 메모리가 고갈됨
- 스레드 마이그레이션: 스케줄러가 스레드를 다른 노드로 이동시키면 기존 할당 메모리가 원격이 되어 성능이 급락함

> 요약: 원격 지연·메모리 편중·스레드 이동이 NUMA 환경의 주요 성능 저하 원인임

## Ⅴ. 개선방안
1. 단기: NUMA-aware 메모리 할당 정책 적용(리눅스 `numactl`, `mbind` 등)으로 로컬 할당 비율을 높임
2. 중기: NUMA-aware 스케줄러 도입으로 스레드를 할당 메모리가 속한 노드에 고정(CPU affinity)함
3. 장기: CXL 등 차세대 인터커넥트로 원격 접근 지연을 로컬 수준에 근접시킴

> 요약: 로컬 할당 최적화·스레드 고정·차세대 인터커넥트로 비균일 지연을 완화함

## Ⅵ. 전망
- 발전 방향: CXL 메모리 풀링으로 NUMA 경계가 유연해지며, 원격 접근 지연 격차가 축소되는 추세임
- 기술사적 판단: 멀티소켓·멀티칩렛 구조 확산으로 NUMA 인식 소프트웨어 설계가 필수 역량이 됨
- 기술사 제언: OS·미들웨어·애플리케이션 전 계층에서 NUMA 토폴로지를 반영한 설계가 필요함
