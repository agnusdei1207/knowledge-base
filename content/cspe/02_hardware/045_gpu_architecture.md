## Ⅰ. 개요
- 대규모 병렬 처리를 위해 수천 개의 코어를 탑재한 연산 장치
- AI 학습 및 고성능 연산을 위한 가속기 핵심 기술

| 구분 | 내용 |
| --- | --- |
| 정의 | 수치 연산 집약적 작업을 위한 다중 코어 기반 병렬 처리 장치 |
| 배경 | 딥러닝 연산량 폭증 및 그래픽 처리 성능 고도화 요구 |
| 출제의도 | SIMT 구조 및 AI 특화 텐서 코어 메커니즘 이해 확인 |

## Ⅱ. 구성요소
```
+------------------------------------------+
|  [ GPU Architecture ]                    |
| +----------+ +----------+ +----------+   |
| |  SM 0    | |  SM 1    | |  SM n    |   |
| | +------+ | | +------+ | | +------+ |   |
| | | CUDA | | | |Tensor| | | | L1   | |   |
| | | Core | | | | Core | | | |Cache | |   |
| | +------+ | | +------+ | | +------+ |   |
| +----------+ +----------+ +----------+   |
| [      L2 Cache / Memory Controller     ] |
+------------------------------------------+
```
| 구성요소 | 설명 | 비유 |
| --- | --- | --- |
| SM | Streaming Multiprocessor; GPU의 기본 실행 단위 | 작업반 |
| CUDA Core | 정수 및 부동소수점 연산을 수행하는 범용 코어 | 일반 작업자 |
| Tensor Core | 행렬 연산 가속을 위한 전용 하드웨어 유닛 | 계산기 숙련공 |
> 요약: 다수 SM 내 CUDA/Tensor 코어가 병렬 연산 수행함.

## Ⅲ. 절차
```
[Data Copy HtoD] -> [Kernel Launch] -> [Parallel Exec] -> [Data Copy DtoH]
```
1. Host to Device: CPU 메모리에서 GPU 전역 메모리로 데이터 복사함.
2. Kernel Launch: CPU가 GPU에 연산 명령(Kernel)을 전달함.
3. Parallel Execution: 수천 개의 스레드가 SM에서 병렬로 연산을 수행함.
4. Device to Host: 연산 완료된 결과를 다시 CPU 메모리로 전달함.
> 요약: 데이터 전송 후 대규모 병렬 연산 수행 및 결과 반환함.

## Ⅳ. 문제점
- 데이터 전송 병목: CPU-GPU 간 PCIe 대역폭 한계로 지연 발생함.
- 높은 전력 소모: 고밀도 코어 집적으로 인한 발열 및 전력 관리 어려움.

## Ⅴ. 개선방안
- NVLink 적용: 고속 상호 연결 기술을 통한 데이터 전송 대역폭 확장함.
- 동적 전력 관리: 연산 부하에 따른 전압/주파수 스케일링(DVFS) 적용함.

## Ⅵ. 전망
- HBM4 탑재 로드맵을 통한 메모리 병목 극복 및 칩렛 아키텍처 도입 가속화됨.
- 저전력·고효율 AI 추론 전용 아키텍처 최적화가 시장 주도권의 핵심(CSF)임.
