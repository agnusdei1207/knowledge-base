# 📖 【암기용】 개념 완전 이해

> 목적: DRAM과 SRAM이 회로 수준에서 무엇이 다르길래 속도·밀도·리프레시 필요성이 극과 극으로 갈리는지, 트랜지스터 개수와 전하 물리학 관점에서 완벽히 이해하게 만든다.

## 한눈에
- **개요**: **셀 회로 구조**가 서로 다른 두 가지 **휘발성 반도체 메모리**로, SRAM은 트랜지스터 여러 개로 만든 **플립플롭(래치)** 회로로 상태를 유지하고, DRAM은 트랜지스터 1개와 **커패시터** 1개로 전하 유무를 저장한다.
- **왜 필요한가**: 컴퓨터는 "빛처럼 빠르지만 비싼 메모리(캐시)"와 "적당히 빠르고 용량이 엄청난 메모리(메인 메모리)"가 모두 필요하다. 하나의 회로 기술로는 두 요구를 동시에 만족할 수 없어, 물리적으로 다른 두 소자를 각자의 자리에 쓴다.
- **핵심 직관**: SRAM은 스위치 여러 개가 서로 꽉 맞물려(플립플롭) 전기가 끊기기 전까지 절대 풀리지 않는 자물쇠다. DRAM은 밑 빠진 독에 물을 채운 것과 같아서, 가만두면 새어 나가므로 주기적으로 다시 채워야(Refresh) 한다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 휘발성 반도체 메모리 | 전원이 끊기면 저장된 데이터가 사라지는 메모리 — SRAM·DRAM이 공통으로 속한 **상위 개념** | 전기가 나가면 지워지는 화이트보드 |
| 셀(Cell) | 메모리에서 1비트를 저장하는 최소 회로 단위 | 서랍 한 칸 |
| SRAM (Static RAM) | 플립플롭 회로로 전원이 있는 한 리프레시 없이 상태를 유지하는 메모리 | 손을 놓아도 안 풀리는 매듭 |
| 6T 구조 | SRAM 셀 1개를 구성하는 통상 6개의 트랜지스터(스위치 2개 + 인버터 쌍 4개) | 자물쇠를 이루는 부품 6개 |
| 플립플롭(Flip-Flop) | 인버터 2개를 서로 마주보게 교차 결합해, 한쪽이 1이면 다른 쪽은 0을 유지하도록 스스로 고정되는 회로 | 시소 양쪽에 추를 걸어 한쪽으로 고정 |
| DRAM (Dynamic RAM) | 커패시터의 전하 유무로 데이터를 저장하고, 전하가 새므로 주기적 재충전이 필요한 메모리 | 물이 새는 물통 |
| 1T1C 구조 | DRAM 셀 1개 = 트랜지스터 1개(스위치) + 커패시터 1개(전하 저장소) | 수도꼭지(스위치) + 물통(저장소) |
| 전하 누설(Leakage) | 커패시터에 저장된 전자가 시간이 지나며 저절로 빠져나가는 현상 — DRAM이 리프레시가 필요한 근본 원인 | 물통 바닥의 미세한 구멍으로 물이 샘 |
| 파괴적 읽기(Destructive Read) | DRAM은 읽을 때 커패시터의 전하를 다 쏟아내며 읽으므로, 읽자마자 즉시 재기록해야 값이 보존됨 | 컵의 물을 다 부어 측정한 뒤 다시 채워 넣어야 함 |
| 센스 앰프(Sense Amplifier) | 커패시터의 미세한 전하 신호를 증폭해 0/1로 판별하는 보조 회로 | 희미한 신호를 키우는 확성기 |

## 깊이 이해

### 트랜지스터 개수 차이가 만드는 밀도 격차 — 수치로 이해
- SRAM 셀 1개 = 트랜지스터 약 6개. DRAM 셀 1개 = 트랜지스터 1개 + 커패시터 1개. 부품 수만 비교해도 SRAM이 DRAM보다 6배 이상 많은 소자를 써서 1비트를 저장한다.
- 반도체에서 면적은 곧 비용이다. 같은 웨이퍼 면적에 DRAM은 SRAM보다 훨씬 많은 비트를 욱여넣을 수 있어서, 예를 들어 CPU 내장 L3 캐시는 수십 MB 수준에 그치지만 DRAM 칩 하나는 수십 Gb(기가비트) 용량을 흔히 만든다 — 자릿수 차이가 나는 이유가 바로 이 셀 구조 차이다.

### SRAM이 리프레시 없이 버티는 원리 (플립플롭)
- 인버터(입력을 반전시키는 논리 게이트) 2개를 서로의 출력이 서로의 입력이 되도록 교차 연결하면, 한쪽이 1을 출력하는 순간 다른 쪽은 0을 출력하고, 그 0이 다시 첫 번째 인버터의 입력이 되어 1을 유지시킨다. 이 자기 강화 루프가 플립플롭이다.
- 전원이 공급되는 한 이 루프는 외부 개입 없이 스스로 상태를 유지한다. 그래서 SRAM은 리프레시가 근본적으로 불필요하다 — "상태를 유지하려고 뭔가 더 할 필요가 없는" 구조이기 때문이다.

### DRAM이 리프레시를 해야만 하는 원리 (커패시터)
- 커패시터는 전극 사이에 전자를 모아두는 그릇일 뿐, 그 자체로 전자를 계속 붙잡아 둘 능동적인 힘이 없다. 절연체를 통해 미세하게 전자가 새어 나가고(누설 전류), 시간이 지나면 전압이 임계값 아래로 떨어져 1인지 0인지 구분이 안 되게 된다.
- JEDEC 표준은 이 누설을 보완하기 위해 통상 64ms 안에 모든 셀을 재충전(Refresh)하도록 규정한다. 리프레시 명령을 몇 µs마다 내려야 하는지, 한 번에 얼마나 걸리는지(tREFI·tRFC)의 구체적 계산은 029(DDR SDRAM·갱신 방식)에서 다룬다 — 여기서는 "왜 새는가"라는 물리적 원인에 집중한다.
- 게다가 DRAM은 읽을 때도 커패시터의 전하를 센스 앰프로 쏟아내며 읽는 파괴적 읽기 방식이라, 읽은 직후 같은 값을 즉시 재기록해줘야 한다 — 리프레시가 "가끔 하는 청소"가 아니라 읽기 동작 자체에도 내장된 근본 특성이라는 뜻이다.

### 속도 차이가 나는 이유
- SRAM은 플립플롭 상태를 그냥 전선으로 읽어내면 되므로 접근 시간이 1~10ns 수준으로 짧다.
- DRAM은 행(Row)을 활성화하고, 미세한 전하 신호가 비트라인에 나타나길 기다리고, 센스 앰프로 증폭하는 여러 단계를 거쳐야 하므로 40~100ns 수준으로 SRAM보다 느리다. "DRAM이 더 신기술이라 더 빠르다"는 흔한 오해이며, 실제로는 회로 단계 수 자체가 DRAM이 더 많아 근본적으로 느리다.

### 비유로 정리
- SRAM: 다이얼 금고. 한 번 맞춰두면 누가 건드리지 않는 한 영원히 유지된다(크고 비쌈).
- DRAM: 밑 빠진 독에 물 붓기. 1(물 채움)과 0(물 없음)을 표시하는데, 물이 계속 새므로 종업원(리프레시 컨트롤러)이 끊임없이 다시 채워야 한다(싸고 좁은 공간에 많이 담을 수 있음).

## 연결 개념
- 메모리 계층 구조(027) — 속도가 생명인 최상위(캐시)는 SRAM, 용량이 생명인 중간층(메인 메모리)은 DRAM이 맡는 배치 근거
- DDR SDRAM·리프레시(029) — 이 문서의 리프레시 원리가 실제 표준(tREFI, tRFC)으로 구체화되는 항목
- 028_dram_vs_sram — 같은 소자를 회로 물리 관점이 아니라 시스템 설계·용도 선택 관점으로 다룬 항목

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: SRAM과 DRAM은 휘발성 반도체 메모리(RAM)의 양대 산맥으로, 각각 플립플롭(Flip-Flop) 논리 회로와 커패시터(Capacitor) 전하 저장 방식을 근간으로 한다.
> 2. **가치**: SRAM은 고속 동작에 유리하여 프로세서 내부의 캐시 메모리로, DRAM은 셀 면적이 작아 고집적 대용량 구성에 유리하여 메인 메모리로 이원화 배치된다.
> 3. **판단 포인트**: DRAM의 태생적 한계인 전하 누설(Leakage)을 극복하기 위한 동적 리프레시(Refresh) 오버헤드와, 이를 보완하려는 DDR 동기화 및 eDRAM 융합 기술이 시스템 설계의 핵심 고려 사항이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 기억장치 소자의 물리적 구조와 특성 차이 이해 | SRAM(플립플롭, 6T), DRAM(커패시터, 1T1C) 회로 대조 | "SRAM은 빠르고 비싸다"는 현상만 적고 그 근본 물리 구조(트랜지스터 개수)를 누락 |
| 아키텍처 상의 역할 분담과 리프레시(Refresh) 부하 파악 | DRAM의 전하 누설과 재충전(Refresh) 지연 사이클 발생 원리 | DRAM의 리프레시가 소프트웨어(OS)에 의해 수행된다고 헷갈림 (메모리 컨트롤러 H/W가 수행함) |

> 요약: 성능(Speed)과 집적도(Density) 간의 철저한 트레이드오프가 회로 소자의 구성(6T vs 1T1C)에서 파생됨을 논리적으로 연결해야 한다.

## Ⅰ. 개요 및 필요성

- 정의: 프로세서 내외부에서 데이터를 임시 보관하는 랜덤 액세스 메모리로, 트랜지스터 래치 기반의 정적(Static) RAM과 커패시터 기반의 동적(Dynamic) RAM
- 배경: CPU 클럭이 GHz 단위로 치솟음에 따라 즉시 응답 가능한 고속 버퍼(SRAM)와, 기가바이트 단위의 OS/앱을 상주시켜야 할 거대 공간(DRAM)의 동시 요구
- 필요성: 시스템 단가를 낮추면서도 폰 노이만 아키텍처의 메모리 병목을 은닉하기 위해, 두 소자의 물리적 강점을 분리하여 메모리 계층(Hierarchy) 구조를 완성

## Ⅱ. 구조 및 구성요소 (물리적 Cell 회로도)

```text
[메모리 1비트(Bit)를 저장하기 위한 최소 단위 Cell 구조]
1. SRAM Cell (6T 구조)
   (Word Line) ---> [ 트랜지스터 스위치 ] <==> [ 인버터 2개 교차 결합 (Latch) ]
   * 플립플롭 구조로 무한 루프 형성 (전원 차단 전까지 상태 유지)

2. DRAM Cell (1T 1C 구조)
   (Word Line) ---> [ 1개 트랜지스터 스위치 ] ---> [ 1개 커패시터 (전하 저장소) ]
   * 매우 단순. 전자가 커패시터 밖으로 계속 누설(Leakage)됨
```

| 구분 | 소자 구성 (1 Bit 기준) | 상태 유지 원리 | 셀 면적 및 집적도 |
|:---|:---|:---|:---|
| SRAM | 트랜지스터 4~6개 (6T) | 쌍안정 논리 게이트(플립플롭)로 전압 락킹(Locking) | 면적이 커서 집적도 낮음 (수십 MB 수준 한계) |
| DRAM | 트랜지스터 1개 + 축전기 1개 (1T1C) | 축전기(Capacitor) 내의 전하량 유무 (1 또는 0) | 극단적으로 작아 고집적 가능 (수십 GB 구현) |

> 요약: 1비트를 기록하는 데 필요한 부피 차이가 6배 이상 나기 때문에, 동일한 웨이퍼 면적에서 DRAM이 압도적인 용량 우위를 점한다.

## Ⅲ. 동작원리 및 메커니즘 흐름도 (상태 유지 및 읽기)

```text
[DRAM의 전하 누설과 Refresh 제어 마이크로 흐름]
1. CPU가 DRAM에 데이터 1 쓰기 -> 커패시터에 전자 충전
2. (시간 경과, 수십 ms) -> 미세한 전자 누설(Leakage) 발생 -> 전압 하강
3. [ 메모리 컨트롤러 개입 ] -> JEDEC 표준 64ms 주기 도래
4. 컨트롤러가 해당 Row 전체 읽기(Read) -> 증폭기(Sense Amp)를 거쳐 다시 원래 전압으로 [ 재충전 (Refresh) ]
```

| 동작 단계 | SRAM (정적 작동) | DRAM (동적 작동) |
|:---:|:---|:---|
| 기록(Write) | 플립플롭 상태를 즉시 반전 | 커패시터에 전압을 가해 전하를 충전 (지연 발생) |
| 유지(Hold) | 전원 공급 시 영구 유지 | 방치 시 방전되어 데이터 유실 |
| 재생(Refresh)| **불필요 (오버헤드 제로)** | 컨트롤러가 주기적으로(약 64ms) 전체 셀 재기록 수행 |
| 인출(Read) | 워드라인 활성화 시 즉시 출력 | 읽을 때 커패시터 전하가 쏟아져 나와(파괴적 읽기) 다시 채워야 함 |

> 요약: DRAM은 가만히 둬도 새고(Leakage), 읽어봐도 쏟아지는(Destructive Read) 불완전한 소자이므로 주변의 강력한 보조 회로(Sense Amp, Refresh H/W)가 필수적이다.

## Ⅳ. 심화 비교: DRAM vs SRAM 핵심 대조표

| 구분 | SRAM (Static RAM) | DRAM (Dynamic RAM) | 시스템 아키텍처 판단 기준 |
|:---|:---|:---|:---|
| 속도 (접근 시간)| 매우 빠름 (1~10ns 이내) | 상대적으로 느림 (40~100ns) | 프로세서와 동기화 레이턴시 |
| 소비 전력 | 대기 시 전력 소모 거의 없음 | Refresh 동작으로 인한 지속적 대기 전력 소모 | 모바일 기기의 배터리 수명 |
| 비트당 단가 | 매우 높음 (웨이퍼 면적 과다) | 매우 낮음 (경제적 대량 생산) | 대규모 메인 메모리 구성 여부 |
| 적용 위치 | CPU 내부 L1, L2, L3 캐시 메모리 | PC/서버의 메인 메모리, 그래픽 메모리(GDDR) | 계층 구조(Hierarchy) 내 티어 |
| 패키징 방식 | CPU 다이(Die) 내부에 통합 (SoC) | 외부 슬롯(DIMM) 형태로 분리 장착 | H/W 마더보드 설계의 복잡도 |

> 요약: 비싸고 빠른 SRAM은 CPU 품속(캐시)으로 들어갔고, 싸고 넓은 DRAM은 마더보드의 메인 램 슬롯(DIMM)을 차지하며 완벽한 공생을 이루었다.

## Ⅴ. 제약 사항 및 차세대 메모리 기술 융합

두 소자의 물리적 한계를 극복하기 위해, 현대 반도체는 구조를 변형하거나 이종 결합을 시도하고 있다.

| 리스크 | 발생 원인 | 아키텍처 대응 방안 (융합 기술) | 극복 효과 |
|:---|:---|:---|:---|
| DRAM 병목(속도)| 커패시터 충전 지연과 Refresh 오버헤드로 인한 성능 한계점 노출 | **eDRAM (Embedded DRAM)**: DRAM을 SRAM처럼 CPU 내부 캐시(L4)로 직접 박아넣어 버스 지연 최소화 | IBM 파워 프로세서 및 인텔 Iris 그래픽에서 대용량 L4 캐시 역할 수행 |
| 핀 대역폭 포화 | DRAM 칩 외부와 CPU를 잇는 핀(Pin) 개수의 물리적 한계 | **HBM (High Bandwidth Memory)**: DRAM 칩에 구멍(TSV)을 뚫어 수직으로 쌓고 인터포저로 CPU(GPU)와 직접 결합 | 테라바이트급 대역폭 확보로 AI/GPU 병목 원천 해소 |
| 휘발성 공통 한계 | 전원 차단 시 SRAM/DRAM 모두 데이터가 즉각 유실됨 (부팅 지연) | **SCM (NVM, STT-MRAM)**: 자성(자기저항) 상태로 데이터를 보존해 SRAM급 속도와 디스크급 비휘발성 동시 달성 | 전원 차단 시에도 즉각적인 시스템 재개(Instant-On) 보장 |

> 요약: DRAM은 속도를 높이기 위해 패키징을 혁신(HBM)하고 있으며, 궁극적으로는 두 소자의 장점만 합친 차세대 비휘발성 메모리(MRAM, ReRAM)로의 진화가 연구되고 있다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 실시간 시스템(RTOS)의 SRAM 할당 제어: 1ms 미만의 확정적 응답이 생명인 자동차 엔진 제어(ECU) MCU 개발 시, DRAM의 비결정적인 Refresh 딜레이를 회피하기 위해 인터럽트 핸들러와 핵심 코드를 칩셋 내부의 TCM(Tightly Coupled Memory, 순수 SRAM) 영역에 강제 링키지(Linkage) 배치
2. 인메모리 DB의 NUMA/DRAM 인터리빙: SAP HANA, Redis 등 방대한 메인 메모리를 구동하는 대형 서버에서, 여러 개의 DRAM 뱅크(Bank)에 데이터를 라운드 로빈으로 흩뿌리는 인터리빙(Interleaving) 설정을 켜서, 특정 DRAM 뱅크의 Refresh 대기 시간(tRFC) 패널티를 다른 뱅크 접근으로 은닉
3. 시스템 전력 최적화 (Self-Refresh): 모바일 기기(AP)나 슬립 모드(S3/S4) 진입 시, CPU 개입 없이 메모리 컨트롤러 스스로 최저 전력만 써서 DRAM의 데이터 증발만 막는 Self-Refresh 모드로 진입시켜 배터리 소모 극단적 억제

**결론 (2줄):**
- 기술사 판단: SRAM의 플립플롭 로직과 DRAM의 1T1C 커패시터 구조는 속도와 용량이라는 서로 양립할 수 없는 반도체 경제학의 한계를 이원화 전략으로 완벽히 분할 통치(Divide and Rule)한 걸작이다.
- 향후 방향: 최근 AI 연산 폭증으로 CPU-DRAM 간 버스 병목이 임계점에 달함에 따라, 단순히 DRAM 용량을 키우는 것을 넘어 DRAM 내부에 연산 코어를 삽입하는 PIM(Processing-In-Memory) 아키텍처로 진화하고 있다.
