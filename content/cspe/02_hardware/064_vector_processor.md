## 미리 알고가기

- 벡터 프로세서는 배열형 데이터를 벡터 명령으로 처리하는 구조임
- 벡터 레지스터와 벡터 연산기와 stride, mask가 핵심 개념임
- 목적은 스칼라 반복 제어를 줄여 수치 연산 처리량을 늘리는 데 있음

## Ⅰ. 개요

- **정의/개념**: 벡터 프로세서는 동일 연산을 대량 데이터 배열에 반복 적용할 때, 원소별 스칼라 명령 대신 벡터 명령과 벡터 레지스터를 사용해 긴 데이터 흐름을 연속 처리하는 프로세서 구조임
- **배경/필요성**: 과학 계산, 신호 처리, 행렬 연산은 같은 연산을 긴 배열에 반복하므로, 벡터 명령 기반 구조가 스칼라 코어의 제어 오버헤드를 줄이고 파이프라인 활용도를 늘릴 수 있음

## Ⅱ. 특징

- 하나의 벡터 명령으로 여러 원소를 처리해 명령 효율과 파이프라인 활용도를 늘림
- 긴 벡터와 연속 메모리 접근에서 강하며 계산 규칙성이 높을수록 이점이 뚜렷함
- stride와 mask를 통해 일부 비연속 접근과 조건부 실행도 다룰 수 있지만 불규칙 분기에는 약함
- 코어 자체보다 메모리 공급과 벡터 길이가 성능의 상한을 정함

## Ⅲ. 종류 및 비교

| 판단 기준 | 스칼라 프로세서 | 벡터 프로세서 | SIMD 확장 |
|:---|:---|:---|:---|
| 명령 단위 | 원소 하나씩 처리함 | 긴 데이터 집합을 벡터 단위로 처리함 | 비교적 짧은 벡터를 CPU 명령 확장으로 처리함 |
| 제어 오버헤드 | 반복이 길수록 루프 제어 부담이 늘어남 | 같은 연산 반복에서 제어 부담이 작음 | 범용 CPU 안에서 중간 수준의 벡터화를 제공함 |
| 잘 맞는 작업 | 분기 많은 일반 제어에 맞음 | 대규모 수치 계산과 반복 배열 처리에 맞음 | 범용 프로그램의 부분 벡터화에 맞음 |
| 주요 병목 | 명령 수와 분기 비용이 병목임 | 메모리 대역폭과 벡터 길이 활용률이 병목임 | 레지스터 폭과 데이터 정렬 제약이 남음 |

> 요약: 벡터 프로세서는 긴 반복 배열 처리에 강하고, SIMD 확장은 범용 CPU 안에서 그 특성을 부분적으로 제공함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 벡터 레지스터 파일 | 여러 원소를 한 번에 저장해 반복 load와 store를 줄이는 저장 공간임 |
| 벡터 연산기 | 덧셈, 곱셈, 논리 연산을 파이프라인으로 처리해 처리량을 늘리는 핵심 유닛임 |
| 로드·스토어 유닛 | stride와 gather 성격의 접근을 처리하며 메모리 공급 능력이 전체 효율을 좌우함 |
| 마스크와 제어 로직 | 조건부 실행과 실제 벡터 길이 제어를 담당해 불필요한 연산을 줄임 |

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 벡터 데이터 적재 | --> | 벡터 명령 발행 | --> | 벡터 파이프라인 | --> | 결과 저장      |
+-------------+     +-------------+     +-------------+     +-------------+
```

> 요약: 데이터를 벡터 레지스터에 적재하고 벡터 명령으로 파이프라인 연산을 수행한 뒤 결과를 저장함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 데이터 정렬    | --> | 벡터 적재      | --> | 연속 원소 연산   | --> | 결과 기록      |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **데이터 정렬**: 벡터화에 맞게 배열과 stride를 준비함
2. **벡터 적재**: 데이터를 벡터 레지스터에 읽어 옴
3. **연속 원소 연산**: 하나의 벡터 명령으로 여러 원소를 파이프라인 처리함
4. **결과 기록**: 메모리나 다음 벡터 연산 단계로 결과를 넘김

> 요약: 데이터 정렬 뒤 벡터 레지스터에 적재하고 연속 원소를 파이프라인으로 처리함.

## Ⅵ. 실무 적용 및 유의점

1. 기상 계산·영상 필터링은 간격 접근과 분산 읽기가 많으면 메모리 효율이 떨어지므로 데이터 재배치와 블록 분할을 적용하고 compute throughput, BW utilization, vectorized runtime으로 확인함
2. 벡터 길이가 짧거나 분기가 많은 코드는 초기화 비용이 이점을 넘을 수 있으므로 임계 길이와 mask 사용 비율을 먼저 분석하고 vector length utilization, mask ratio, runtime으로 확인함

## Ⅶ. 결론

벡터 프로세서의 성능은 코어 수보다 긴 배열을 얼마나 끊김 없이 흘려보내느냐에 달려 있으므로, 데이터 정렬과 메모리 공급이 설계의 중심임.

## 작성 근거(검토용)

- 벡터 프로세서는 벡터 명령, 벡터 레지스터, stride, mask, 메모리 대역폭을 핵심 축으로 설명함
- 비교표는 스칼라 프로세서, 벡터 프로세서, SIMD 확장의 명령 단위와 병목을 대비함
- 실무 판단은 memory bandwidth utilization, vectorized runtime, vector length utilization으로 확인하게 작성함
