## 미리 알고가기

- 벡터 프로세서는 배열형 데이터를 벡터 명령으로 처리하는 구조임
- 벡터 레지스터·벡터 연산기·보폭(Stride)·마스크가 핵심 개념임
- 수집(Gather)·분산(Scatter): 비연속 주소의 데이터를 모아 읽거나 흩어 쓰는 벡터 메모리 접근 방식임
- 목적은 스칼라 반복 제어를 줄여 수치 연산 처리량을 늘리는 데 있음

## 작성 근거(검토용)

- 벡터 프로세서는 벡터 명령, 벡터 레지스터, 보폭, 마스크, 메모리 대역폭을 핵심 축으로 설명함
- 비교표는 스칼라 프로세서, 벡터 프로세서, SIMD 확장의 명령 단위·제어 오버헤드와 병목을 대비함
- 실무 판단은 메모리 대역폭 사용률, 벡터화 구간 실행 시간, 벡터 길이 사용률로 구체화함

## Ⅰ. 개요

- **정의/개념**: 벡터 프로세서는 원소별 스칼라 명령 대신 벡터 명령과 레지스터로 배열의 여러 원소를 연속 처리하는 구조임
- **배경/필요성**: 과학 계산·신호 처리·행렬 연산의 반복 명령 수를 줄이기 위해 배열을 벡터 단위로 처리하는 구조가 필요함

### 쉽게 이해하기 (학습용)
- 옷을 한 벌씩 빠는 대신 세탁망에 여러 벌을 한꺼번에 넣어 한 번에 돌리는 대형 세탁기와 같음

## Ⅱ. 특징

- 하나의 벡터 명령으로 여러 원소를 처리해 명령 효율과 파이프라인 활용도를 늘림
- 긴 벡터와 연속 메모리 접근에서 파이프라인의 유휴 구간이 줄어듦
- 보폭과 마스크로 비연속 접근·조건부 실행을 처리하며 불규칙 분기에서는 비활성 레인이 늘어남
- 코어 자체보다 메모리 공급과 벡터 길이가 성능의 상한을 정함

### 쉽게 이해하기 (학습용)
- 세탁물이 가지런히 쌓여 있을수록 세탁기가 쉬지 않고 돌지만, 색깔별로 골라내야 하는 옷이 섞이면 일부 자리를 비워둬야 함
- 세탁기 성능보다 세탁물을 얼마나 빨리 채워 넣을 수 있는지가 더 중요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 스칼라 프로세서 | 벡터 프로세서 | SIMD 확장 |
|:---|:---|:---|:---|
| 명령 단위·제어 오버헤드 | 원소 하나씩 처리하며 반복이 길수록 루프 제어 부담이 늘어남 | 긴 데이터 집합을 벡터 단위로 처리해 같은 연산 반복의 제어 부담이 작음 | CPU 명령 집합의 고정 폭 벡터로 반복을 줄이되 레지스터 폭만큼만 처리함 |
| 대표 적용 사례 | 분기가 많은 일반 제어 | 수치 계산·반복 배열 처리 | 범용 프로그램의 부분 벡터화 |
| 주요 병목 | 명령 수와 분기 비용이 병목임 | 메모리 대역폭과 벡터 길이 활용률이 병목임 | 레지스터 폭과 데이터 정렬 제약이 남음 |

> 요약: 벡터 프로세서는 벡터 레지스터의 여러 원소를 한 명령으로 처리하고, SIMD 확장은 범용 CPU 명령 집합에 벡터 연산을 추가함.

### 쉽게 이해하기 (학습용)
- 옷을 한 벌씩 손빨래하면 스칼라, 세탁망 가득 채워 한 번에 돌리면 벡터 프로세서, 가정용 세탁기의 정해진 통 크기만큼만 채워 돌리면 SIMD 확장임

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 벡터 레지스터 파일 | 여러 원소를 한 번에 저장해 반복 적재·저장 명령을 줄임 |
| 벡터 연산기 | 덧셈, 곱셈, 논리 연산을 파이프라인으로 처리해 처리량을 늘리는 핵심 유닛임 |
| 로드·스토어 유닛 | 보폭·수집(Gather) 접근을 처리하며 메모리 공급률이 벡터 연산기 사용률을 좌우함 |
| 마스크와 제어 로직 | 조건부 실행과 실제 벡터 길이 제어를 담당해 불필요한 연산을 줄임 |

> 요약: 데이터를 벡터 레지스터에 적재하고 벡터 명령으로 파이프라인 연산을 수행한 뒤 결과를 저장함.

### 쉽게 이해하기 (학습용)
- 세탁망(벡터 레지스터 파일)에 옷을 담고, 세탁기 모터(벡터 연산기)가 돌리며, 넣고 꺼내는 문(로드·스토어 유닛)과 얼룩진 옷만 골라내는 표시(마스크)가 함께 있음

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 데이터 정렬    | --> | 벡터 적재      | --> | 연속 원소 연산   | --> | 결과 기록      |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **데이터 정렬**: 벡터화에 맞게 배열과 보폭을 준비함
2. **벡터 적재**: 데이터를 벡터 레지스터에 읽어 옴
3. **연속 원소 연산**: 하나의 벡터 명령으로 여러 원소를 파이프라인 처리함
4. **결과 기록**: 메모리나 다음 벡터 연산 단계로 결과를 넘김

> 요약: 데이터 정렬 뒤 벡터 레지스터에 적재하고 연속 원소를 파이프라인으로 처리함.

### 쉽게 이해하기 (학습용)
- 빨랫감을 종류별로 정리하고, 세탁망에 담아, 한 번에 돌리고, 다 마르면 옷장에 넣는 순서와 같음

## Ⅵ. 실무 사례

1. 과학 계산 배열은 데이터를 연속 배치하고 메모리 대역폭 사용률·벡터화 구간 실행 시간을 확인함
2. 분기가 많은 코드는 벡터 길이 사용률·스칼라 실행 대비 시간을 비교함

### 쉽게 이해하기 (학습용)
- 많은 실험 데이터를 세탁기에 한꺼번에 돌리듯 처리하는 계산과, 옷 종류가 뒤섞여 손빨래가 늘어나듯 분기가 많아 세탁기 효율이 떨어지는 코드의 차이임

## Ⅶ. 결론

- 벡터 프로세서는 벡터 명령과 레지스터로 배열의 여러 원소를 한 번에 처리해 반복 명령 수를 줄이는 구조임
- 처리량은 벡터 길이 사용률과 연속 메모리 공급이 좌우하므로, 벡터화 구간에서는 데이터 배치와 메모리 대역폭을 함께 설계해야 함

### 쉽게 이해하기 (학습용)
- 세탁기를 얼마나 꽉 채워 돌리고 세탁물을 끊김 없이 공급하느냐가 관건이며, 정리와 공급 속도를 함께 설계해야 함
