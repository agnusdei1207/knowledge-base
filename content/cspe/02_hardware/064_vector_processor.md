## Ⅰ. 개요
- **정의**: 하나의 명령어로 벡터(1차원 배열) 단위 데이터를 일괄 처리하는 SIMD 기반 프로세서임
- **배경/필요성**: 과학·공학 연산에서 대규모 배열 연산이 반복되어 스칼라 프로세서의 루프 오버헤드를 제거할 필요가 있음
- **비유**: 편지 한 통씩 봉투에 넣는 대신, 자동 봉입기로 수백 통을 한 번에 처리하는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 벡터 연산의 원리와 스칼라 대비 이점 | 벡터 레지스터 + 파이프라인 체이닝 + 메모리 스트라이드 | SIMD(063 참조)와의 관계 명시 필요 |

> 요약: 벡터 단위 일괄 처리로 스칼라 루프 오버헤드를 제거하는 데이터 병렬 프로세서임

## Ⅱ. 구성요소
```text
+------------------+     +------------------+     +------------------+
|  Vector          | --> |  Vector          | --> |  Vector          |
|  Register File   |     |  Functional Unit |     |  Load/Store Unit |
+------------------+     +------------------+     +------------------+
       ^                        |
       |                        v
       +--- Pipeline Chaining --+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Vector Register File | 64~512개 원소를 보유하는 벡터 전용 레지스터 집합임 | 자동 봉입기의 다열 트레이 |
| Vector Functional Unit | 덧셈·곱셈 등 벡터 연산을 파이프라인으로 수행하는 연산 장치임 | 봉입기의 연속 처리 라인 |
| Vector Load/Store Unit | 메모리에서 벡터 데이터를 스트라이드·인덱스 방식으로 적재/저장함 | 창고에서 트레이 단위로 재료를 운반 |
| Pipeline Chaining | 앞 연산의 결과를 레지스터 파일 경유 없이 다음 연산에 직접 전달함 | 컨베이어 벨트 간 직결 연결 |

> 요약: 벡터 레지스터, 벡터 연산 유닛, 적재/저장 유닛, 파이프라인 체이닝으로 구성됨

## Ⅲ. 절차
```text
Vectorization --> Vector Load --> Pipeline Execution --> Vector Store
      |                |                  |                    |
      v                v                  v                    v
  루프 -> 벡터      메모리 -> VR       Chained FU 연산      VR -> 메모리
  명령 변환         스트라이드 적재     파이프라인 처리       결과 저장
```
- 1단계: **Vectorization** — 컴파일러가 스칼라 루프를 벡터 명령어로 변환하며, 의존성 분석을 수행함
- 2단계: **Vector Load** — 메모리에서 벡터 레지스터로 데이터를 스트라이드 또는 인덱스 방식으로 적재함
- 3단계: **Pipeline Execution** — 벡터 연산 유닛이 파이프라인·체이닝으로 원소별 연산을 연속 처리함
- 4단계: **Vector Store** — 연산 결과를 벡터 레지스터에서 메모리로 일괄 저장함

> 요약: 벡터화 → 벡터 적재 → 파이프라인 실행 → 벡터 저장의 4단계로 동작함

## Ⅳ. 문제점
- **벡터화 불가 루프**: 데이터 의존성이 있는 루프는 벡터 명령으로 변환이 불가하여 스칼라 모드로 폴백됨
- **메모리 대역폭 병목**: 벡터 연산 처리량 대비 메모리 공급 속도가 부족하면 파이프라인이 스톨됨
- **스트라이드 접근 비효율**: 비연속 메모리 접근 시 캐시 적중률이 하락하여 유효 대역폭이 감소함

> 요약: 벡터화 불가 루프, 메모리 대역폭 병목, 비연속 접근 비효율이 주요 제약임

## Ⅴ. 개선방안
1. 단기: 컴파일러 힌트(`#pragma`, 내장 함수)로 벡터화율을 향상시켜 스칼라 폴백 감소
2. 중기: HBM·인터리빙 등 고대역폭 메모리 기술로 벡터 유닛의 데이터 공급 병목 해소
3. 장기: 가변 길이 벡터(SVE, RVV) ISA 도입으로 하드웨어 독립적 벡터화와 스트라이드 최적화를 지원

> 요약: 컴파일러 최적화, 고대역폭 메모리, 가변 길이 벡터 ISA로 단계적 개선함

## Ⅵ. 전망
- 발전 방향: ARM SVE·RISC-V V 확장 등 가변 길이 벡터 ISA가 범용 프로세서에도 확산 중임
- 기술사적 판단: AI 행렬 연산과 과학 계산 수요가 지속되어 벡터 처리 기능은 프로세서 핵심 요소로 유지될 전망임
- 기술사 제언: 워크로드의 벡터화 가능 비율을 사전 측정하고, 벡터 길이·메모리 대역폭 균형을 설계에 반영할 필요
