# 📖 【암기용】 개념 완전 이해

> 목적: 벡터 프로세서를 처음 봐도 SIMD 명령어와 어떻게 다른지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 벡터(배열) 전체를 하나의 명령어로 파이프라인 처리하는 프로세서 구조
- **왜 필요한가**: 스칼라 프로세서는 배열 원소마다 반복문으로 명령어를 인출·해독해야 하므로, 대량 배열 연산에서 명령어 오버헤드와 메모리 지연이 누적된다.
- **핵심 직관**: 컨베이어 벨트에 원소들을 한 줄로 흘려보내며 한 번의 지시로 전체를 순차 가공하는 구조다.

## 깊이 이해
- **배경·문제의식**: 1970년대 Cray-1이 과학기술 계산(행렬·유체역학)의 대량 반복 연산을 가속하기 위해 벡터 레지스터와 파이프라인 연산 유닛을 도입했다.
- **작동 원리**: 벡터 프로세서는 벡터 레지스터(Vector Register)에 배열 전체를 적재하고, 벡터 명령어 하나가 벡터 길이 레지스터(Vector Length Register)만큼 원소를 파이프라인 연산 유닛에 순차 투입한다.
- **작동 원리**: 체이닝(Chaining)은 한 벡터 연산의 첫 결과가 나오는 즉시 다음 벡터 연산 유닛에 바로 전달해, 전체 연산 완료를 기다리지 않고 파이프라인을 이어 붙이는 기법이다.
- **작동 원리**: 벡터 마스크 레지스터(Vector Mask Register)는 조건에 맞는 원소만 연산에 참여시켜 분기 없는 조건 처리를 지원한다.
- **비유**: 스칼라 프로세서가 접시를 하나씩 나르는 웨이터라면, 벡터 프로세서는 트레이 하나에 여러 접시를 한 번에 싣고 나르는 웨이터다.
- **구체 예시**: 길이 1000인 배열 두 개를 더하는 연산에서, 스칼라 프로세서는 1000번의 개별 ADD 명령을 반복하지만 벡터 프로세서는 벡터 ADD 명령 1개로 벡터 레지스터 전체를 파이프라인 처리한다.
- **구체 예시**: ARM SVE(Scalable Vector Extension)와 RISC-V V 확장은 벡터 길이를 하드웨어 구현마다 다르게(128비트~2048비트) 설정할 수 있는 가변 길이 벡터 명령어 집합이다.
- **흔한 오해·주의점**: 벡터 프로세서와 SIMD 명령어(AVX)는 같은 데이터 병렬 원리를 쓰지만, AVX 계열은 레지스터 폭이 고정(256/512비트)인 반면 전통적 벡터 프로세서와 SVE·RISC-V V는 벡터 길이를 가변적으로 다룰 수 있다는 점에서 구분된다.
- **흔한 오해·주의점**: 벡터화가 항상 유리한 것은 아니다. 원소 간 의존성이 있거나 배열 접근이 불규칙(스캐터·개더)하면 파이프라인 이득이 줄어든다.

## 연결 개념
- SIMD·MIMD 프로세서 — 벡터 프로세서가 속한 데이터 병렬 처리 계열
- Flynn 분류 — 벡터 프로세서는 SIMD 범주로 분류
- GPU SIMT — 벡터 개념을 스레드 단위로 확장한 병렬 모델

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 벡터 프로세서 답안은 벡터 레지스터·체이닝 구조, SIMD 고정폭 명령어와의 차이, 적용 워크로드를 함께 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 벡터 프로세서는 배열 전체를 벡터 레지스터에 적재해 하나의 명령어로 파이프라인 처리하는 구조다.
> 2. **가치**: 명령어 인출·해독 반복 없이 체이닝으로 파이프라인을 연결해 대량 배열 연산의 처리량을 높인다.
> 3. **판단 포인트**: 원소 간 의존성이 없고 접근 패턴이 규칙적인 배열 연산일수록 벡터화 이득이 크다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 벡터 프로세서 구조 이해 확인 | 벡터 레지스터, 체이닝, 마스크 레지스터 | 단순히 "배열을 빠르게 처리"라고만 서술 |
| SIMD와의 차이 확인 | 가변 길이(SVE·RISC-V V) vs 고정 폭(AVX) | 벡터 프로세서와 SIMD 명령어를 동일 개념으로 혼동 |
| 적용 한계 이해 확인 | 의존성·불규칙 접근 시 이득 감소 | 벡터화가 항상 유리하다고 단정 |

> 요약: 이 문제는 배열 가속 효과보다 체이닝 구조와 SIMD와의 구분 근거를 보여야 한다.

## Ⅰ. 개요 및 필요성

- 개요: 배열 전체를 벡터 레지스터에 적재해 단일 명령어로 파이프라인 처리하는 프로세서
- 배경: 스칼라 반복문은 배열 원소마다 명령어 인출·해독을 반복해 대량 연산에서 오버헤드가 누적됨
- 필요성: 과학기술 계산·신호처리·행렬 연산처럼 규칙적 대량 배열 연산은 벡터 명령어로 처리량을 높여야 목표 연산 시간을 만족함

---

## Ⅱ. 구조 및 구성요소

```text
Scalar Register -> Vector Register(배열 적재)
  -> Vector Length Register(처리 원소 수 지정)
  -> Vector Functional Unit(파이프라인 연산)
  -> Chaining(다음 연산 유닛으로 결과 즉시 전달)
  -> Vector Mask Register(조건부 원소 선택)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Vector Register | 배열 원소 전체를 레지스터에 적재 | 폭에 따라 처리 가능 원소 수 결정 |
| Vector Length Register | 실제 처리할 원소 수 지정 | 배열 길이가 레지스터 폭보다 작을 때 사용 |
| Vector Functional Unit | 파이프라인 방식으로 원소 순차 연산 | 첫 결과가 나오는 지연 후 매 클럭 결과 산출 |
| Chaining | 한 연산 결과를 다음 연산에 즉시 전달 | 전체 완료 대기 없이 파이프라인 연결 |
| Vector Mask Register | 조건에 맞는 원소만 연산 참여 | 분기 없는 조건 처리 |

> 요약: 벡터 프로세서는 벡터 레지스터·체이닝·마스크 레지스터 조합으로 배열 연산을 파이프라인화한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
배열 적재(Vector Register) -> 벡터 명령어 디코드 1회
  -> Functional Unit 파이프라인 순차 연산
  -> Chaining으로 후속 연산 유닛 연계
  -> 결과 벡터 레지스터 저장
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 배열을 벡터 레지스터에 적재 | 벡터 길이, 레지스터 폭 |
| 2 | 벡터 명령어 1회 디코드로 전체 원소 처리 지시 | 명령어 인출 횟수 감소율 |
| 3 | 파이프라인 연산 유닛이 원소를 순차 처리 | 파이프라인 startup latency, throughput |
| 4 | 체이닝으로 다음 연산 유닛에 결과 즉시 전달 | 체이닝 적용 시 총 사이클 감소량 |

> 요약: 벡터 프로세서는 배열을 한 번에 적재한 뒤 파이프라인 연산과 체이닝으로 순차 처리해 처리량을 높인다.

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 장점 | 명령어 인출·해독 반복 제거로 대량 배열 연산 처리량 향상 | 배열 길이 대비 명령어 수 감소율 |
| 한계 | 원소 간 의존성, 불규칙 접근(scatter/gather) 시 이득 감소 | 의존성 분석, 접근 패턴 규칙성 |
| 비교 포인트 | SIMD(AVX)는 고정 폭, 전통 벡터·SVE·RISC-V V는 가변 길이 | 하드웨어 구현별 레지스터 폭 |

> 요약: 벡터 프로세서의 이득은 배열 규칙성과 의존성 여부에 좌우된다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 스칼라 프로세서 | 벡터 프로세서 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 원소별 반복 명령어 실행 | 벡터 레지스터 + 파이프라인 연산 | 배열 길이와 반복 횟수 |
| 비용/성능 | 명령어 오버헤드 누적 | 체이닝으로 처리량 향상 | 목표 연산 시간(FLOPS) |
| 운영/위험 | 구현 단순, 이식성 높음 | 의존성·불규칙 접근 시 이득 제한 | 데이터 의존성 분석 필요 |

> 요약: 배열이 크고 원소 간 의존성이 없을수록 벡터 프로세서 선택이 유리하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 벡터화 실패 | 원소 간 데이터 의존성 존재 | 의존성 분석 후 루프 재구성 | 벡터화 가능 루프 비율 |
| 접근 불규칙 | scatter/gather 패턴 | 데이터 레이아웃 재정렬(AoS->SoA) | 캐시 미스율 |
| 마스크 오버헤드 | 조건부 원소 비율 낮음 | 마스크 활용률 프로파일링 후 재판단 | 유효 lane 비율 |

> 요약: 벡터 프로세서 운영은 의존성 분석과 데이터 레이아웃 정렬로 벡터화 실패 리스크를 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 처리량 | FLOPS 목표치 이상 | 벤치마크(HPL 등) |
| 벡터화율 | 루프 벡터화 비율 목표치 이상 | 컴파일러 벡터화 리포트 |
| 자원 사용률 | 벡터 유닛 활용률 목표치 이상 | 성능 카운터 |

> 요약: 도입 후 성공 여부는 FLOPS, 벡터화율, 벡터 유닛 활용률로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 행렬·신호처리·과학계산처럼 규칙적 배열 연산은 벡터 명령어(SVE, RISC-V V)로 벡터화함
2. 원소 간 의존성이 있는 루프는 의존성 분석 후 재구성해 벡터화 가능 비율을 높임
3. 불규칙 메모리 접근은 데이터 레이아웃을 AoS에서 SoA로 재정렬해 벡터화 이득을 확보함

**결론 (2줄):**
- 기술사 판단: 배열 규모가 크고 의존성이 없는 연산은 벡터 프로세서를, 이질적 제어 흐름이 많은 연산은 스칼라·MIMD를 선택함
- 향후 방향: ARM SVE·RISC-V V 같은 가변 길이 벡터 확장이 확대되며 하드웨어별 이식성이 개선되는 방향으로 발전함
