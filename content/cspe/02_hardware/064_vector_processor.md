## 미리 알고가기

- 벡터 프로세서는 배열형 데이터를 벡터 명령으로 연속 처리하는 프로세서임
- vector register와 vector functional unit과 stride, mask가 핵심 개념임
- 스칼라 반복 제어를 줄여 수치 연산 처리량을 높이는 데 목적이 있음

## Ⅰ. 개요

- **정의/개념**: 벡터 프로세서는 동일한 연산을 수행하는 긴 데이터 배열을 벡터 명령과 벡터 레지스터와 파이프라인 연산기로 처리해 루프 제어 오버헤드와 원소별 명령 실행 비용을 줄이는 구조임
- **배경/필요성**: 과학 계산과 신호 처리와 행렬 연산은 동일 연산을 대량 데이터에 반복 적용하므로, 스칼라 코어보다 벡터 명령 기반 처리가 더 높은 효율을 낼 수 있음

## Ⅱ. 특징

- 하나의 벡터 명령이 여러 원소를 연속 처리해 명령 효율이 높음
- 긴 벡터와 규칙적 메모리 접근에서 파이프라인 활용도가 높음
- stride와 mask를 지원해 비연속 접근과 조건부 실행을 일부 다룰 수 있음
- 메모리 대역폭과 벡터 길이 의존성이 커서 비정형 작업에는 불리함

## Ⅲ. 종류 및 비교

| 판단 기준 | 스칼라 프로세서 | 벡터 프로세서 | SIMD 확장 |
|:---|:---|:---|:---|
| 명령 단위 | 원소 단위 | 벡터 단위 | 짧은 벡터 단위 |
| 제어 오버헤드 | 큼 | 작음 | 중간 |
| 적합 연산 | 일반 제어 | 대규모 수치 계산 | 범용 CPU 내 데이터 병렬 |
| 메모리 의존성 | 중간 | 높음 | 높음 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Vector Register File | 여러 데이터 원소를 한 번에 보관해 반복 load, store를 줄임 |
| Vector Functional Unit | 덧셈과 곱셈과 논리 연산을 파이프라인으로 처리해 처리량을 높임 |
| Load, Store Unit | stride와 gather 계열 접근을 처리하며 메모리 대역폭 병목과 직접 연결됨 |
| Mask, Control Logic | 조건부 실행과 벡터 길이 제어를 담당해 분기 비용을 줄임 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 벡터 데이터 적재 | --> | 벡터 명령 발행 | --> | 파이프라인 연산 | --> | 결과 저장      |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **벡터 데이터 적재**: 배열 데이터를 벡터 레지스터에 읽어옴
2. **벡터 명령 발행**: 하나의 명령으로 여러 원소를 지정함
3. **파이프라인 연산**: 기능 유닛이 연속적으로 원소를 처리함
4. **결과 저장**: 연산 결과를 메모리나 다음 벡터 연산에 전달함

## Ⅵ. 문제점 및 해결 방안

1. 문제: stride가 크거나 gather 형태 접근이 많으면 메모리 대역폭 효율이 나빠져 벡터화 이득이 줄어들 수 있음
   - 해결방안: 데이터 재배치와 blocking을 적용하고 memory bandwidth efficiency와 vector speedup으로 검증함
2. 문제: 짧은 벡터나 반복 횟수가 적은 작업은 벡터 초기화 비용이 더 커질 수 있음
   - 해결방안: 벡터화 임계 길이를 설정하고 vector length utilization과 execution time으로 적합성을 검증함
3. 문제: 조건 분기가 많은 알고리즘은 mask 사용이 늘어도 lane 활용률이 떨어질 수 있음
   - 해결방안: 데이터 재정렬과 분기 분리를 적용하고 mask utilization과 branch overhead로 검증함

## Ⅶ. 적용 사례

- 기상 수치 해석에서는 대형 배열 연산을 벡터화하고 확인 지표는 FLOPS와 memory bandwidth utilization임
- 영상 필터링에서는 연속 픽셀 계산을 벡터 명령으로 처리하고 확인 지표는 pixels per second와 vector efficiency임
- 신호 처리 DSP 코드에서는 반복 MAC 연산을 벡터화하고 확인 지표는 throughput과 latency reduction임

## Ⅷ. 결론

벡터 프로세서의 성능은 코어 수보다 긴 배열을 얼마나 연속적으로 흘려보내느냐에 달려 있으므로, 데이터 정렬과 메모리 공급이 설계의 핵심임.
