# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 벡터 프로세서는 스칼라(단일 숫자) 대신 **벡터(1차원 배열) 데이터를 하나의 기계어 명령어로 통째로 처리**하도록 설계된 SIMD 기반의 파이프라인 프로세서다.
- **왜 필요한가**: 과학 계산, 3D 그래픽, AI 연산 등은 방대한 배열 데이터에 동일한 연산을 수없이 반복한다. 이를 일반 CPU로 루프(for문)를 돌리면 명령어 인출/해독 오버헤드가 너무 커져 비효율적이다.
- **핵심 직관**: 사과 64개를 자를 때 칼(명령어)을 한 번씩 64번 내리치는 것(스칼라)이 아니라, 날이 64개 달린 특수 작두(벡터 명령어)로 한 번에 내리치는 것이다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 스칼라 (Scalar) | 크기만 있는 단일 값 하나 | 일반적인 숫자 1개 |
| 벡터 (Vector) | 같은 데이터 타입이 일렬로 나열된 1차원 배열 | 숫자 64개의 묶음(배열) |
| 벡터 레지스터 (Vector Register) | 다수의 데이터(예: 64개)를 한 번에 담을 수 있는 거대한 레지스터 | "64칸짜리 계란판" |
| 메모리 인터리빙 (Memory Interleaving) | 연속된 벡터 데이터를 한 번에 가져오기 위해 메모리를 여러 뱅크로 나눠 동시 접근하는 기술 | "여러 개의 출입문으로 동시에 입장" |

## 깊이 이해
- **배경·문제의식**: 구형 슈퍼컴퓨터 시절 기상 예측이나 유체 역학 시뮬레이션은 어마어마한 행렬 계산이 필요했다. 일반 프로세서(스칼라)는 `for(i=0; i<64; i++) c[i] = a[i] + b[i];`를 실행하려면 '명령어 인출-디코딩-덧셈-인덱스증가-분기판단'을 64번 반복해야 했다. 덧셈 외의 제어 오버헤드가 성능을 갉아먹었다.
- **작동 원리**: 벡터 프로세서는 `VADD V1, V2, V3` (벡터 레지스터 V2와 V3를 더해 V1에 넣어라) 단 한 줄의 명령어로 이 루프를 끝낸다. 명령어를 한 번만 읽으므로(인출/해독 오버헤드 1/64), 나머지 시간은 거대한 벡터 파이프라인에서 데이터 연산에만 쏟아붓는다.
- **비유**: 엑셀에서 C열(C1~C64) 값을 구할 때, A1+B1을 계산하고 그걸 밑으로 주욱 드래그하는 작업이 벡터 연산이다. 셀 하나씩 수식을 일일이 치는 것은 스칼라 연산이다.
- **구체 예시**: 인텔의 AVX-512 명령어 셋. 512비트 레지스터 하나에 32비트짜리 실수 16개를 욱여넣고 단 한 번의 클럭 사이클(파이프라인)에 16개 덧셈을 동시 수행한다.
- **흔한 오해·주의점**: 벡터 프로세서와 GPU는 유사하지만 차이가 있다. 정통 벡터 프로세서는 거대한 다중 파이프라인으로 벡터 데이터를 쭉쭉 흘려보내는 구조고, GPU는 수천 개의 단순 스칼라 코어를 떼지어 병렬 실행시키는 SIMT(스레드 기반) 방식에 가깝다. 현재는 범용 CPU에 내장된 벡터 확장(SIMD)이 대세다.

## 연결 개념
- SIMD (단일 명령어 다중 데이터) — 벡터 프로세서를 설명하는 플린 분류체계 (063 참조)
- 루프 언롤링 (Loop Unrolling) — 스칼라 프로세서에서 반복문 오버헤드를 줄이는 소프트웨어 기법
- 텐서 처리 장치 (TPU) — 벡터(1차원)를 넘어 2차원 행렬 연산(MAC)을 한 번에 처리하는 가속기

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 벡터 프로세서는 단일 기계어 명령(SIMD)으로 1차원 데이터 배열(벡터) 전체를 깊은 파이프라인을 통해 연속 처리하는 고성능 연산 아키텍처다.
> 2. **가치**: 반복문 제어 명령어(루프 인덱스 증가, 분기 판단)의 인출·해독 오버헤드를 제거하고, 메모리 대역폭 한계 내에서 연산 처리량(Throughput)을 극대화한다.
> 3. **판단 포인트**: 순수 하드웨어 벡터 프로세서는 크레이(Cray) 시리즈 이후 GPU로 대체되었으나, 현재는 멀티코어 CPU 내부의 SIMD 확장(AVX, ARM SVE, RISC-V V-Ext) 형태로 소프트웨어 최적화의 핵심 기준이 되었다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 벡터 프로세싱의 성능 이점 원리 파악 | SIMD 구조, 반복문 제어 오버헤드 제거, 벡터 레지스터 | 다수 프로세서가 처리하는 MIMD 구조로 오답 기재 |
| 아키텍처 구성 요소 이해 | 벡터 파이프라인, 거대 레지스터, 메모리 인터리빙 | 단순 명령어 파이프라이닝(스칼라)과 혼동 |

> 요약: 스칼라 루프 연산 대비 명령어 페치 횟수 급감과 병렬 파이프라인 극대화라는 본질적 이점을 수치적 비교로 제시해야 한다.

## Ⅰ. 개요 및 필요성

- 개요: 플린의 분류 중 SIMD(Single Instruction Multiple Data) 구조를 기반으로, 1차원 배열 형태의 다중 데이터를 단일 명령어로 일괄 처리하는 프로세서
- 배경: 그래픽 렌더링, 시뮬레이션, 인공지능 등 행렬·벡터 단위 대량 연산에서 스칼라 방식의 반복문 제어 오버헤드(Loop Overhead) 극심화
- 필요성: 매 요소마다 명령어를 페치/디코드하는 사이클 낭비를 없애고, 거대한 단위 데이터를 한 번에 가져와 파이프라인에 밀어 넣어 연산 처리량(Throughput)을 수십 배 향상

## Ⅱ. 구조 및 구성요소

```text
[스칼라 프로세서]                [벡터 프로세서]
Inst -> Fetch 64번               Inst(VADD) -> Fetch 1번
Inst -> Decode 64번              Inst(VADD) -> Decode 1번
Data -> ALU [ A+B ] (64번 반복)  Data Array -> [V_ALU 1~16] 파이프라인 (연속 처리)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 벡터 레지스터 (Vector Register) | 배열 요소 다수(예: 64개~512비트 폭)를 한 번에 저장하는 거대 저장소 | N개의 요소가 순차/병렬로 출력됨 |
| 벡터 연산 유닛 (Vector ALU) | 여러 개의 독립된 파이프라인 ALU로 구성되어 배열 연산 동시 수행 | 벡터 가산기, 곱셈기 분리 |
| 벡터 체이닝 (Vector Chaining) | 앞선 벡터 연산 결과가 레지스터에 다 기록되기 전에 다음 연산에 포워딩 | `D = A * B + C`의 MAC 연산 가속 |
| 다중 뱅크 메모리 (Interleaved Mem) | 거대 벡터 데이터를 병목 없이 인출하기 위한 물리적 분산 접근 구조 | 스트라이드(Stride) 단위 로딩 |

> 요약: 거대한 레지스터 세트와 깊은 ALU 파이프라인, 그리고 이를 뒷받침할 메모리 인터리빙 대역폭이 벡터 아키텍처의 3대 핵심이다.

---

## Ⅲ. 동작원리 및 흐름도

```text
Host 프로그램 -> 스칼라 분기/제어 처리 -> 벡터 명령 인출 (VADD V1, V2, V3) 
  -> 벡터 레지스터 2개 동시 읽기 -> 벡터 파이프라인 ALU 유입 -> 체이닝/결과 벡터 쓰기
```

- 1단계 [명령어 인출]: 스칼라 제어부가 단 하나의 벡터 명령어(예: 벡터 덧셈)를 페치 및 디코딩
- 2단계 [오퍼랜드 인출]: 메모리 인터리빙을 통해 연속된 배열 데이터를 1클럭당 다수 뱅크에서 읽어 벡터 레지스터에 적재
- 3단계 [파이프라인 실행]: 다중 벡터 ALU가 레지스터의 요소들을 클럭마다 순차적·병렬적으로 처리
- 4단계 [체이닝 통제]: 의존성이 있는 후속 벡터 명령어(예: 곱셈 직후 덧셈)에 중간 산출물을 즉시 바이패스하여 겹쳐 실행

> 요약: 단 1회의 명령어 디코딩 이후에는 제어 개입 없이, 데이터 스트림만 파이프라인을 타고 흐르는(Streaming) 데이터 주도적 동작이다.

---

## Ⅳ. 특징

- [루프 오버헤드 제거]: N번 반복되는 루프의 분기 검사, 인덱스 증가, 명령어 인출 과정을 생략하여 스칼라 대비 제어 사이클을 95% 이상 감축한다.
- [메모리 대역폭 의존성]: 벡터 연산기가 아무리 많아도 메모리에서 배열을 퍼오는 속도가 느리면 병목(Memory Wall)이 발생하므로 광대역 인터리빙/HBM이 필수적이다.
- [암달의 법칙 한계]: 프로그램 내에 벡터화가 불가능한 스칼라 분기(If-Else 조건문) 비율이 높을수록 벡터 유닛이 유휴 상태가 되어 전체 효율이 급감한다.

> 요약: 벡터 연산은 "결과 독립성"이 보장되는 정형화된 데이터 배열(Data Parallelism)에서만 기하급수적 성능 향상을 입증한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 스칼라 루프 연산 | 벡터 SIMD 연산 | 실무 선택 기준 |
|:---|:---|:---|:---|
| 명령어 처리 횟수 | 배열 크기(N) 만큼 페치/디코드 | 단 1회 페치/디코드 | 명령어 페치 대역폭 포화도 |
| 조건 분기(If) 처리 | 분기 예측기 활용 유연 처리 | 마스킹(Masking)에 의한 ALU 유휴 | 알고리즘 내 조건문 포함 비율 |
| 메모리 접근 패턴 | 캐시 중심의 무작위 접근(랜덤) | 일정 간격(Stride)의 순차 블록 로드 | 데이터 레이아웃(AOS vs SOA) 구조 |

> 요약: 스칼라 아키텍처는 유연한 제어(제어 종속성)에, 벡터 아키텍처는 데이터 정형성(데이터 독립성)에 투자한 설계다.

**도입 및 최적화 점검 지표:**
- 벡터화 비율 (Vectorization Ratio): 프로파일러로 컴파일된 코드 내 SIMD 명령어 점유율 측정 (지표: 타겟 루프 내 벡터화율 80% 이상)
- 데이터 정렬 및 캐시 히트율: 비정렬(Unaligned) 메모리 접근 시 벡터 로딩 페널티 폭증 → 데이터 구조체 메모리 얼라인먼트 점검 (지표: 캐시 라인 경계 준수율 100%)

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 컴파일러 자동 벡터화(Auto-vectorization): C/C++ 개발 시 `-O3`, `-mavx2` 등 최적화 플래그를 적용하여, 코드 내 명시적 `#pragma omp simd` 선언 없이도 단순 for문을 벡터 명령어로 자동 변환
2. 데이터 구조의 SOA(Struct of Arrays) 변환: 객체 단위 배열(AOS)을 속성 단위 배열(SOA)로 재설계하여, 메모리상 연속 배치된 벡터를 한 번의 SIMD 명령으로 로딩하도록 애플리케이션 리팩토링
3. 유연한 벡터 길이(SVE/RVV) 아키텍처 채택: ARM SVE나 RISC-V V-Extension(Vector)을 적용, 하드웨어 벡터 레지스터 길이에 상관없이 바이너리를 한 번만 컴파일해도 하드웨어 스펙에 맞게 가변 폭 연산 가속

**결론 (2줄):**
- 기술사 판단: 순수 독립 하드웨어로서의 전통적 벡터 프로세서는 쇠퇴했으나, 벡터 프로세싱 '사상'은 x86 AVX, ARM NEON, RISC-V V 등 CPU 내부의 필수 가속 엔진으로 내재화되었다.
- 향후 방향: 1차원 벡터 연산을 넘어, 딥러닝 트랜스포머 가속을 위해 2차원 행렬 타일(Tile) 전체를 단일 명령으로 처리하는 AMX(Advanced Matrix Extensions) 및 TPU/NPU 구조로 발전하고 있다.
