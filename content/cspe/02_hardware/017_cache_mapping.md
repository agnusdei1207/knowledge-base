# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 캐시 매핑은 방대한 메인 메모리의 블록을 훨씬 작은 캐시의 어느 라인(슬롯)에 적재·탐색할지 결정하는 하드웨어 규칙으로, 직접·완전 연관·집합 연관 3방식으로 나뉨.
- **왜 필요한가**: CPU가 캐시 전체를 순차 탐색하면 캐시 도입 이유가 무색해지므로, 메모리 주소만 보고 "몇 번째 칸에 있는지"를 즉시 계산하는 규칙이 필요함.
- **핵심 직관**: 책 1만 권(메모리)을 10칸 책꽂이(캐시)에 꽂을 때 — 끝자리로 정해진 칸에만 꽂으면 직접 매핑, 아무 빈칸에나 꽂고 찾을 때 전체를 훑으면 완전 연관, 10칸을 5조로 나눠 조를 정한 뒤 조 안 2칸 중 빈 곳에 꽂으면 집합 연관임.

## 핵심 용어 정리 (내부에 등장하는 것들)

먼저 답안에 나오는 용어를 비유와 함께 풀어 둔다. 최상위 키워드는 캐시 매핑이다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 지역성 (Locality) | 최근·인접 참조 주소를 곧 다시 쓴다는 성질. 캐시 존재 근거 | 시간적(방금 본 책 또 봄)·공간적(옆 책도 봄) |
| 캐시 히트/미스 (Hit/Miss) | 찾는 데이터가 캐시에 있음/없어 메모리까지 가야 함 | "책꽂이에 있음 / 서고까지 다녀옴" |
| 라인·블록 (Line/Block) | 메모리에서 캐시로 한 번에 옮기는 전송 기본 단위(예: 64B) | "권 단위가 아닌 박스 단위" |
| 태그 (Tag) | 저장된 데이터가 메모리 어느 원본인지 식별하는 상위 주소 | "책 겉면 청구기호" |
| 인덱스 (Index) | 어느 캐시 슬롯(세트)에 넣을지 지정하는 색인 | "책꽂이 칸 번호" |
| 오프셋 (Offset) | 블록 안에서 특정 바이트 위치 | "박스 안 몇 번째 책" |
| Way (n-Way) | 한 세트 안에 든 라인(빈칸) 개수. 세트 수가 아님 | "A구역 주차면 4칸 = 4-Way" |
| 충돌 미스 (Conflict Miss) | 빈칸이 있어도 같은 인덱스 경합으로 쫓겨나 생기는 미스 | "내 지정석에 남이 와서 차 뺌" |

## 깊이 이해
- **배경·문제의식**: CPU-메모리 속도 격차를 지역성으로 메우려 캐시를 뒀으나, 캐시는 메모리보다 수백 배 작아 매핑 규칙에 따라 상충이 갈림 — 탐색이 빠르면 충돌이 심하고(직접), 충돌을 없애면 탐색이 느리고 회로가 비쌈(완전 연관).
- **작동 원리**: 물리 주소를 `[Tag | Index | Offset]`로 쪼갬. ① 직접 매핑은 `블록번호 MOD 라인수`로 정한 딱 1칸에만 적재 — 같은 인덱스가 오면 빈칸이 남아도 기존을 축출(충돌 미스). ② 완전 연관은 Index를 없애고 Tag만 둬 아무 빈칸에나 적재 — 충돌은 없으나 탐색 시 전 라인 태그를 동시 비교하는 CAM 회로가 비쌈. ③ 집합 연관은 캐시를 세트로 나눠 세트당 n개 Way를 두고, `블록번호 MOD 세트수`로 세트를 찾은 뒤 세트 내 n개 태그만 병렬 비교함.
- **비유**: 직접 매핑은 지정 주차석(빠르나 남 오면 차 뺌), 완전 연관은 자율 주차(빈자리 쉬우나 내 차 찾기 어려움), n-Way 집합 연관은 구역별 배정 주차(A구역 n칸 중 아무 데나, 찾을 땐 A구역만 뒤짐)임.
- **구체 예시**: 32비트 주소·64B 블록·256세트면 Offset 6비트, Index 8비트, Tag 18비트로 분할됨. 4-Way면 인덱스가 4번 겹쳐도 축출되지 않고 버팀.
- **흔한 오해·주의점**: n-Way의 'n'은 세트 개수가 아니라 한 세트 안 라인(빈칸) 개수임. 4-Way는 한 세트에 4자리가 있어 인덱스가 4번 겹칠 때까지 축출되지 않는다는 뜻임.

## 연결 개념
- **지역성 (Locality)**: 시간·공간 지역성이 캐시와 매핑이 성립하는 근본 전제임.
- **018 캐시 쓰기 정책·교체 알고리즘**: 세트가 꽉 차 축출할 대상 선정(LRU 등)과 변경분 반영 시점을 다룸.
- **021 TLB**: 항목이 적고 극한 적중률이 필요해 예외적으로 완전 연관을 채택함.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 캐시 매핑은 메모리 블록 주소를 한정된 캐시 라인 주소로 변환해 적재·탐색 위치를 결정하는 하드웨어 규칙임.
> 2. **가치**: 탐색 속도(Hit Time)와 공간 활용(Hit Rate)의 상충을 조율해 미스 페널티를 최소화함.
> 3. **판단**: 충돌이 심한 직접 매핑과 회로가 비싼 완전 연관을 절충한 n-Way 집합 연관이 현대 L1/L2의 표준임.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 주소 해석·매핑 원리 이해 | 주소 3분할(Tag·Index·Offset)과 방식별 차이 | 방식별 주소 포맷 차이 누락 |
| 매핑 방식 트레이드오프 파악 | 직접(충돌↑)·완전(회로↑)·집합(절충) 비교 | Way 의미를 세트 수로 반대 해석 |

> 요약: 주소 분할 포맷 차이가 태그 비교 회로 복잡도와 충돌 미스율을 어떻게 바꾸는지 증명해야 함.

---

## Ⅰ. 개요 및 필요성

- 개요: 캐시 매핑은 큰 메인 메모리 블록을 작은 캐시 라인 중 어디에 적재·탐색할지 정하는 규칙임.
- 배경: 캐시를 순차 탐색(O(N))하면 메모리 지연 극복이라는 캐시 본연의 목적이 상실됨.
- 필요성: 히트 시 저지연 반환을 보장하면서 주소 겹침에 의한 충돌 미스를 최소화하는 하드웨어 절충이 필요함.

---

## Ⅱ. 구조 및 구성요소

```text
물리 주소(예: 32비트) 3분할
  Tag(상위, 라인 식별) / Index(중위, 적재 세트) / Offset(하위, 블록 내 바이트)
  -> Index로 세트 지정 -> 세트 내 Tag 병렬 비교 -> 일치 시 Hit, 불일치 시 Miss
```

| 구성요소 | 크기 결정 기준 | 역할 |
|:---|:---|:---|
| Offset | 블록 크기(예: 64B) | 라인 내 특정 바이트 위치 식별 |
| Index | 캐시 세트 개수 | 데이터를 적재·탐색할 세트 지정 |
| Tag | 남은 상위 비트 | 적재 데이터가 요청 원본과 일치하는지 검증 |

> 요약: 주소를 비트로 쪼개 Index로 위치를 빠르게 찾고 Tag로 내 데이터인지 확인하는 이중 장치임.

---

## Ⅲ. 동작원리 및 흐름도 (3가지 매핑 방식)

```text
CPU 주소 -> Index로 세트 선택 -> 세트 내 Tag 비교 -> Hit면 반환 / Miss면 메모리 적재·교체
  직접: 세트당 1라인 / 집합: 세트당 n라인 / 완전: 세트 1개(전 라인 후보)
```

- 1단계 [직접 매핑]: `블록번호 MOD 라인수`로 정한 1칸에만 적재하고 태그 1개만 비교함(회로 최소, 충돌 미스 잦음).
- 2단계 [완전 연관 매핑]: Index를 없애고 빈칸 아무 곳에나 적재하며 전 라인 태그를 동시 비교함(충돌 미스 없음, CAM 회로 고비용).
- 3단계 [n-Way 집합 연관 매핑]: `블록번호 MOD 세트수`로 세트를 찾고 세트 내 n개 라인 중 빈 곳에 적재, n개 태그만 병렬 비교함.
- 4단계 [교체 결정]: 세트가 꽉 차면 LRU·Random 등으로 축출 대상을 정하고 새 블록으로 교체함(018 참조).

> 요약: 세트를 인덱스로 빠르게 찾고 세트 내에서만 유연하게 배치하는 n-Way가 직접의 단순함과 완전 연관의 유연성을 결합함.

---

## Ⅳ. 특징
- 충돌 완화의 한계: n-Way라도 행렬 곱·루프처럼 참조가 특정 세트에 몰리면 용량 부족·잦은 교체(Thrashing)가 발생함.
- 하드웨어 복잡도 상승: Way가 늘수록 태그 비교기·다입력 MUX가 늘어 Hit Time이 길어짐.
- 교체 정책 필수 결합: 세트가 찼을 때 축출 대상을 정하는 LRU·Random 회로가 반드시 함께 필요함.

> 요약: Way를 늘려 적중률을 올리면 탐색 지연(Hit Time)이 길어지는 명확한 트레이드오프가 있음.

---

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 직접 매핑 | n-Way 집합 연관 | 완전 연관 |
|:---|:---|:---|:---|
| 주소 포맷 | Tag+Index+Offset | Tag+Set Index+Offset | Tag+Offset(Index 없음) |
| 태그 동시 비교 수 | 1개(회로 최소) | n개(Way 수) | 전 라인 수(회로 최대) |
| 충돌 미스 | 매우 높음(단일 슬롯) | 중간(n번 초과 겹침 시) | 없음(빈칸 소진 시에만 미스) |
| 대표 적용 | 단순 L1(과거) | 현대 L1(4~8W)·L3(16W↑) | TLB 등 소용량 |

> 요약: L1은 반응 속도 위해 4~8-Way, L3은 적중률 위해 16-Way 이상, 소용량 TLB는 완전 연관을 적용함.

**리스크·대응 (기본은 불릿):**
- 특정 세트 오염 리스크 — 원인: 재사용 없는 스트리밍 복사가 유용 데이터 축출 — 대응: 캐시 바이패스·Non-temporal Store 명령어 적용(지표: 핵심 워크로드 캐시 생존율).
- 직접 매핑 속도·적중률 동시 요구 — 원인: 단일 슬롯 충돌 — 대응: 해시 인덱싱 기반 Skewed Associative Cache 도입(지표: 적중률·Hit Time 동시 보존).

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 계층별 비대칭 매핑: 클럭 직결 L1은 4~8-Way로 Hit Time을 줄이고, 백스토어 L3은 16-Way로 미스를 최소화함.
2. TLB 완전 연관 설계: 항목이 적고 극한 적중률이 필요한 TLB는 예외적으로 완전 연관 위주로 구성함.
3. 캐시 어웨어 프로그래밍: 구조체 패딩·배열 정렬을 64B 라인·세트 충돌 주기에 맞춰 False Sharing·충돌 미스를 차단함.

**결론 (2줄):**
- 기술사 판단: 지연이 핵심인 L1은 저Way로 Hit Time을, 용량이 핵심인 L3은 고Way로 적중률을 우선해 계층별로 매핑을 달리해야 함.
- 향후 방향: 대용량 캐시(AMD 3D V-Cache)가 확산되며 단순 인덱스 분할을 넘어 접근 패턴 예측 기반 동적 라인 할당으로 진화 중임.
