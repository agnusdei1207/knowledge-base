## Ⅰ. 개요
- 정의: CPU와 외부 장치 간의 데이터 교환을 제어하는 다양한 하드웨어/소프트웨어 기법
- 배경: 저속의 I/O 장치와 고속의 CPU 간 속도 차이에 의한 성능 병목 극복 필요
- 출제 의도
| 구분 | 내용 |
| --- | --- |
| 핵심 | 폴링(Polling) vs 인터럽트, CPU 개입도, 응답 속도 |

## Ⅱ. 구성요소
```
[ CPU ] <--- (Status/Data/Control Bus) ---> [ I/O Module ]
  |                                            |
  +---- (Interrupt Line / Polling Loop) -------+
```
| 구성요소 | 설명 | 비유 |
| --- | --- | --- |
| Programmed I/O | CPU가 장치의 상태 비트를 주기적으로 확인 (Polling) | 무한 대기 |
| Interrupt-driven | 장치가 준비되었을 때 CPU에 신호를 보냄 | 벨 알람 |
| I/O 채널(IOP) | 입출력 전용 프로세서가 독립적으로 I/O 수행 | 전문 비서 |
> 요약: 제어 주체와 알림 방식에 따라 효율성과 하드웨어 비용이 달라짐

## Ⅲ. 절차
1. 상태 확인: (PIO) CPU가 반복 체크 / (인터럽트) CPU는 다른 작업 수행
2. 장치 준비: 입출력 장치가 데이터 처리를 완료하고 상태 레지스터 갱신
3. 신호 전달: (인터럽트) 장치가 CPU에 인터럽트 요청 신호(IRQ) 발송
4. 데이터 전송: 준비된 데이터를 버스를 통해 메모리나 레지스터로 이동
> 요약: 인터럽트 방식은 CPU 유휴 시간을 줄여 시스템 가용성을 극대화함

## Ⅳ. 문제점
- 인터럽트 방식은 잦은 컨텍스트 스위칭으로 인한 오버헤드가 발생할 수 있음

## Ⅴ. 개선방안
- 인터럽트 병합(Coalescing) 기술 및 고성능 DMA/채널 방식 도입함

## Ⅵ. 전망
- 데이터 센터 규모에서는 CPU 개입을 0으로 만드는 가속 인터페이스(RDMA)가 필수적임
- OS 커널을 거치지 않는 유저 레벨 I/O(DPDK/SPDK) 기술로의 진화가 로드맵임
