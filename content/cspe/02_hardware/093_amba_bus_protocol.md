## 미리 알고가기

- AMBA는 Arm 계열 SoC 내부 IP를 연결하는 온칩 버스 표준임
- AXI는 고성능 데이터 경로, AHB는 범용 시스템 경로, APB는 저속 제어 경로에 주로 씀
- interconnect는 주소 해석과 중재와 라우팅을 담당하는 연결 계층임

## Ⅰ. 개요

- **정의/개념**: AMBA 버스 프로토콜은 CPU와 DMA와 메모리와 주변장치 IP를 공통 트랜잭션 규칙으로 연결해 SoC 내부 통신을 표준화하는 온칩 버스 아키텍처임
- **배경/필요성**: SoC는 다양한 공급자의 IP를 한 칩 안에 통합하므로, 고성능 데이터 경로와 저속 제어 경로를 구분한 표준 버스가 있어야 재사용성과 검증 효율을 확보할 수 있음

## Ⅱ. 특징

- 성능 등급에 따라 AXI와 AHB와 APB로 역할을 분리함
- 주소와 데이터와 응답 규칙이 정해져 IP 재사용성이 높음
- 다수 master와 slave를 interconnect로 묶어 복잡한 내부 통신을 관리함
- QoS와 브리지와 클럭 도메인 설계가 실제 지연과 검증 난도를 좌우함

## Ⅲ. 종류 및 비교

| 판단 기준 | AXI | AHB | APB |
|:---|:---|:---|:---|
| 주요 용도 | 메모리·가속기 데이터 경로 | CPU·DMA의 공유 시스템 버스 | UART·timer의 제어 레지스터 경로 |
| 구조 특성 | 주소·데이터 채널 분리와 다중 outstanding 전송 | 단일 주소·데이터 파이프라인 전송 | setup·access 두 단계 전송 |
| 처리 방식 | 여러 요청과 응답을 겹쳐 처리 | 한 버스에서 파이프라인 처리 | 요청 하나를 완료한 뒤 다음 요청 처리 |
| 설계 포인트 | 대역폭과 지연과 QoS를 함께 조정해야 함 | 면적과 성능의 균형이 중요함 | 저전력과 단순 제어가 중요함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| master IP | CPU와 DMA처럼 요청을 발생시키며 대역폭 요구의 출발점이 됨 |
| interconnect | 주소 디코딩과 중재와 라우팅을 수행해 병목 위치를 결정함 |
| slave IP | 메모리와 주변장치처럼 요청을 처리하며 응답 지연이 전체 성능에 반영됨 |
| bridge | AXI와 AHB와 APB 사이 속도와 프로토콜 차이를 흡수해 경로를 연결함 |

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 요청 발행      | --> | 주소 해석      | --> | 데이터 전송    | --> | 응답 반환      |
+-------------+     +-------------+     +-------------+     +-------------+
```

## Ⅴ. 원리 및 절차 흐름도

1. **요청 발행**: master가 주소와 속성과 burst 정보를 포함한 트랜잭션을 생성함
2. **주소 해석**: interconnect가 목적지 slave와 우선순위를 결정함
3. **데이터 전송**: 프로토콜 규칙과 핸드셰이크에 따라 데이터를 이동함
4. **응답 반환**: slave가 완료나 오류 상태를 master에 돌려줌

## Ⅵ. 실무 적용 및 유의점

1. 모바일 SoC나 MCU 플랫폼은 고성능 AXI 경로와 저속 APB 경로를 섞어 쓰는데 마스터가 같은 메모리 구간에 몰리면 버스 병목이 심해지므로 트래픽 모델 기반 크기 산정과 QoS 조정을 함께 수행하고 버스 사용률과 기아 발생 건수와 최악 지연시간으로 확인함
2. 서로 다른 클럭 도메인의 IP를 연결하는 구간은 프로토콜보다 CDC 품질이 더 중요하므로 표준 브리지와 비동기 FIFO와 CDC 검증을 같이 적용하고 CDC 위반 건수와 타이밍 수렴율과 프레임 손실률로 확인함

## Ⅶ. 결론

AMBA 선택의 핵심은 버스 이름이 아니라 각 IP의 대역폭과 지연과 검증 복잡도에 맞는 경로를 나누는 데 있음.
