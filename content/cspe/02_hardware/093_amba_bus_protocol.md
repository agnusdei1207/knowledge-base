## 미리 알고가기

- AMBA는 Arm 계열 SoC 내부 IP를 연결하는 온칩 버스 표준임
- AXI는 고성능 데이터 경로, AHB는 범용 시스템 경로, APB는 저속 제어 경로에 주로 씀
- 인터커넥트(interconnect)는 주소 해석·중재·라우팅을 담당하는 연결 계층임
- 마스터(master)는 요청을 발행하고 슬레이브(slave)는 요청을 처리해 응답하는 AMBA의 통신 주체임

## 작성 근거(검토용)

- AMBA는 AXI·AHB·APB의 채널 구조, 동시 처리, 적용 IP, 브리지 연결을 핵심 축으로 설명함
- 비교표는 세 프로토콜의 용도, 구조·처리 방식, 설계 조건을 대비함
- 실무 판단은 버스 사용률·최악 지연과 CDC 위반 건수·전송 오류율로 검증함

## Ⅰ. 개요

- **정의/개념**: AMBA 버스 프로토콜은 CPU와 DMA와 메모리와 주변장치 IP를 공통 트랜잭션 규칙으로 연결해 SoC 내부 통신을 표준화하는 온칩 버스 아키텍처임
- **배경/필요성**: 서로 다른 IP를 한 SoC에 통합하기 위해 데이터 처리량과 제어 빈도에 맞춘 표준 버스·인터페이스가 필요함

### 쉽게 이해하기 (학습용)
- 여러 회사가 만든 가전제품을 한 집에 꽂아 쓸 수 있게 만든 공통 콘센트 규격과 같음

## Ⅱ. 특징

- 성능 등급에 따라 AXI와 AHB와 APB로 역할을 분리함
- 주소와 데이터와 응답 규칙이 정해져 IP 재사용성이 높음
- 다수 마스터와 슬레이브를 인터커넥트로 연결해 주소 해석과 중재를 수행함
- QoS와 브리지와 클럭 도메인 설계가 실제 지연과 검증 난도를 좌우함

### 쉽게 이해하기 (학습용)
- 고속도로(AXI)·시내도로(AHB)·골목길(APB)로 등급을 나누고, 교차로에서 신호 우선순위와 진입 규칙까지 미리 정해둔 도로망과 같음

## Ⅲ. 종류 및 비교

| 판단 기준 | AXI | AHB | APB |
|:---|:---|:---|:---|
| 주요 용도 | 메모리·가속기 데이터 경로에 사용함 | CPU·DMA의 공유 시스템 버스에 사용함 | UART·타이머의 제어 레지스터 경로에 사용함 |
| 구조·처리 방식 | 주소·데이터 채널 분리와 다중 Outstanding 전송으로 여러 요청·응답을 겹쳐 처리함 | 단일 주소·데이터 파이프라인으로 한 버스에서 순차 처리함 | Setup·Access 두 단계로 요청을 하나씩 완료한 뒤 처리함 |
| 설계 조건 | Outstanding 수·버스트·QoS를 조정함 | 중재·파이프라인·버스 점유를 조정함 | 클럭 게이팅·Setup·Access 대기 상태를 조정함 |

> 요약: AXI는 다중 채널·Outstanding 전송, AHB는 파이프라인 공유 버스, APB는 Setup·Access 순차 전송에 사용함.

### 쉽게 이해하기 (학습용)
- AXI는 여러 차로에서 여러 차량을 동시에 보내는 고속도로, AHB는 한 줄로 순서대로 지나가는 시내도로, APB는 신호 대기 후 한 대씩 통과하는 골목길과 같음

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 마스터 IP | CPU와 DMA처럼 요청을 발생시키며 대역폭 요구의 출발점이 됨 |
| 인터커넥트 | 주소 디코딩·중재·라우팅을 수행해 병목 위치를 결정함 |
| 슬레이브 IP | 메모리와 주변장치처럼 요청을 처리하며 응답 지연이 전체 성능에 반영됨 |
| 브리지 | AXI와 AHB와 APB 사이 속도와 프로토콜 차이를 흡수해 경로를 연결함 |

> 요약: 마스터 요청은 인터커넥트와 브리지를 거쳐 해당 슬레이브에 전달되고 응답은 반대 경로로 반환됨.

### 쉽게 이해하기 (학습용)
- 요청을 보내는 발신자(마스터), 길을 찾아주는 교차로(인터커넥트), 요청을 처리하는 수신자(슬레이브), 등급이 다른 도로를 잇는 나들목(브리지)이 하나의 통신망을 이룸

## Ⅴ. 원리 및 절차 흐름도

1. **요청 발행**: 마스터가 주소·속성·버스트 정보를 포함한 트랜잭션을 생성함
2. **주소 해석**: 인터커넥트가 목적지 슬레이브와 우선순위를 결정함
3. **데이터 전송**: 프로토콜 규칙과 핸드셰이크에 따라 데이터를 이동함
4. **응답 반환**: 슬레이브가 완료나 오류 상태를 마스터에 돌려줌

> 요약: 마스터 요청을 인터커넥트가 주소·우선순위로 라우팅하고 슬레이브 응답을 원 요청자에게 반환함.

### 쉽게 이해하기 (학습용)
- 발신자가 주소를 적어 보내면, 교차로가 목적지와 우선순위를 정해 길을 안내하고, 규칙대로 짐을 옮긴 뒤, 처리 결과를 발신자에게 돌려주는 택배 절차와 같음

## Ⅵ. 실무 사례

1. 모바일 SoC는 AXI 트래픽 모델과 QoS 중재를 적용하고 버스 사용률·최악 요청 지연을 확인함
2. 클럭 도메인이 다른 IP 경로는 비동기 브리지와 CDC 검증을 적용하고 CDC 위반 건수·전송 오류율을 확인함

### 쉽게 이해하기 (학습용)
- 모바일 SoC는 혼잡한 교차로에 신호 우선순위를 매겨 정체를 줄이고, 속도가 다른 두 도로를 잇는 구간은 나들목에서 충돌이 없는지 따로 점검하는 것과 같음

## Ⅶ. 결론

- AMBA는 IP별 대역폭·동시 요청·제어 빈도에 따라 AXI·AHB·APB 경로를 분리해 통신 등급을 맞추는 표준임
- 고성능 데이터 경로는 QoS·Outstanding 조정을, 클럭 도메인이 다른 저속 경로는 브리지·CDC 검증을 우선해 지연과 오류를 통제해야 함

### 쉽게 이해하기 (학습용)
- 도로 등급을 나눠 쓰는 것만으로 끝나지 않고, 혼잡한 교차로엔 신호 우선순위를, 속도 다른 도로가 만나는 나들목엔 충돌 점검을 따로 해줘야 함
