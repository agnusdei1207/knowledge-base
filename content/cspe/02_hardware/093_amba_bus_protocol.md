# 📖 【암기용】 개념 완전 이해

> 목적: AMBA가 SoC 내부에서 왜 여러 종류의 버스를 나눠 쓰는지 처음 봐도 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: ARM이 정의한 SoC 내부 온칩 인터커넥트(on-chip interconnect) 표준 규격군
- **왜 필요한가**: 하나의 칩 안에 CPU, GPU, DMA, 메모리 컨트롤러, 저속 주변장치가 함께 있는데, 이들의 성능·속도 요구가 서로 다르므로 용도별로 다른 버스 프로토콜이 필요하다.
- **핵심 직관**: 건물 안에서 고속 화물 엘리베이터(AXI), 일반 승객 엘리베이터(AHB), 각 층 복도(APB)를 용도에 맞게 나눠 쓰는 것과 같다.

## 깊이 이해
- **배경·문제의식**: SoC 내부에는 고성능 CPU/GPU/DMA와 저속 UART/GPIO/타이머가 함께 있어, 하나의 버스로 모두 연결하면 저속 장치가 고속 버스 대역폭을 낭비하거나 고속 장치가 저속 버스에 발목 잡힌다.
- **작동 원리**: AMBA는 계층별 버스를 정의한다. APB(Advanced Peripheral Bus)는 저속·저전력 주변장치 레지스터 접근용이고, AHB(Advanced High-performance Bus)는 파이프라인 구조의 중간 성능 버스이며, AXI(Advanced eXtensible Interface)는 분리된 5개 채널과 아웃스탠딩 트랜잭션을 지원하는 고성능 버스다.
- **작동 원리 보충**: AXI는 Read Address(AR), Read Data(R), Write Address(AW), Write Data(W), Write Response(B) 5개 독립 채널로 구성돼 읽기·쓰기를 동시에 처리할 수 있다.
- **작동 원리 보충2**: AXI는 트랜잭션마다 ID 태그를 부여해 여러 트랜잭션을 순서와 무관하게 동시에 진행(out-of-order completion)할 수 있다.
- **비유**: APB는 사내 우편함(느리지만 단순), AHB는 사내 셔틀버스(정해진 노선을 파이프라인처럼 순환), AXI는 여러 화물이 동시에 오가는 물류 허브(주소·데이터·응답 채널 분리)에 비유된다.
- **구체 예시**: CPU가 AXI로 DDR 컨트롤러에 접근하고, AHB-APB 브리지를 거쳐 UART·타이머 같은 저속 주변장치는 APB로 접근하는 계층 구조가 전형적이다.
- **흔한 오해·주의점**: AMBA는 특정 칩이 아니라 ARM이 공개한 인터페이스 규격이므로, ARM 코어가 아닌 IP도 AXI/AHB/APB 인터페이스만 맞추면 SoC에 통합할 수 있다.
- **흔한 오해·주의점 보충**: AXI-Lite는 AXI의 저사양 버전(버스트 미지원, 단일 비트 전송)이고, AXI-Stream은 주소 채널 자체가 없는 순수 데이터 스트리밍 프로토콜로 AXI 풀 버전과 혼동하면 안 된다.

## 연결 개념
- SOC 시스템온칩 — AMBA가 내부 인터커넥트로 쓰이는 상위 개념
- PCIe 스위칭 아키텍처 — 칩 간(off-chip) 인터커넥트로서의 대응 개념
- Chiplet — 다이 간 인터커넥트에서 AMBA CHI 등 코히런트 프로토콜과의 연결

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: AMBA를 하나의 버스로 뭉뚱그리지 않고 APB·AHB·AXI 계층 구조와 AXI 5채널·아웃스탠딩 트랜잭션 구조로 답안을 구성한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: AMBA(Advanced Microcontroller Bus Architecture)는 SoC 내부에서 성능·전력 요구가 다른 블록을 계층별로 연결하는 ARM 온칩 인터커넥트 표준이다.
> 2. **가치**: APB·AHB·AXI로 계층을 나눠 저속 주변장치가 고속 버스 대역폭을 낭비하지 않고, 고속 블록은 AXI의 분리 채널과 아웃스탠딩 트랜잭션으로 성능을 극대화한다.
> 3. **판단 포인트**: 제어 레지스터 접근은 APB, 중간 성능 IP는 AHB, CPU·GPU·메모리 컨트롤러 등 고성능 블록은 AXI(또는 AXI-Stream)를 선택 기준으로 삼는다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| SoC 인터커넥트 계층 구조 이해 확인 | APB·AHB·AXI 성능·용도 차이 | AMBA를 단일 프로토콜로 서술 |
| AXI 고성능 구조 이해 확인 | 5채널 분리, ID 기반 아웃스탠딩·비순차 완료 | 채널 구성과 비순차 처리 특성 누락 |
| 변형 프로토콜 구분 확인 | AXI-Lite(단순 제어)와 AXI-Stream(주소 없는 스트리밍) 차이 | AXI-Lite와 AXI-Stream을 AXI 풀 버전과 혼동 |

> 요약: 이 문제는 AMBA를 하나의 버스로 나열하지 않고, 계층별 용도 구분과 AXI의 채널·트랜잭션 구조를 근거로 답해야 한다.

## Ⅰ. 개요 및 필요성

- 개요: ARM이 정의한 SoC 내부 블록 간 연결용 온칩 인터커넥트 표준 규격군
- 배경: SoC 내부에 성능·전력 요구가 다른 CPU, GPU, DMA, 저속 주변장치가 공존해 단일 버스로는 효율적 연결이 어려움
- 필요성: 저속 제어 접근은 APB, 중간 성능은 AHB, 고성능·고대역폭 블록 연결은 AXI로 계층화해야 전체 SoC 성능과 전력 효율을 동시에 확보함

---

## Ⅱ. 구조 및 구성요소

```text
SoC Interconnect(AMBA)
  CPU/GPU/DMA/Memory Controller -> AXI(고성능, 5채널, 아웃스탠딩)
  중간 성능 IP -> AHB(파이프라인, 단일 버스 중재)
  AHB-APB Bridge -> APB(저속 주변장치: UART/GPIO/Timer)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| AXI(Advanced eXtensible Interface) | 고성능 블록 간 점대점 연결 | AR/R/AW/W/B 5채널, ID 기반 비순차 완료 |
| AHB(Advanced High-performance Bus) | 중간 성능 블록 연결 | 파이프라인 구조, 단일 버스 중재 방식 |
| APB(Advanced Peripheral Bus) | 저속·저전력 주변장치 레지스터 접근 | 비파이프라인, 단순 프로토콜, 낮은 전력 |
| AXI-Lite / AXI-Stream | AXI의 경량화·스트리밍 변형 | AXI-Lite는 버스트 미지원, AXI-Stream은 주소 채널 없음 |

> 요약: AMBA는 AXI(고성능)-AHB(중간)-APB(저속) 3계층으로 블록 성능 특성에 맞춰 인터커넥트를 배치한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
Master(CPU 등) -> AXI Address Channel(AR/AW)로 트랜잭션 ID 부여 요청
  -> Slave가 Data Channel(R/W)로 데이터 응답
  -> Write는 Response Channel(B)로 완료 통지
  -> 여러 ID의 트랜잭션이 동시에 진행(out-of-order 허용)
  -> AHB-APB Bridge를 거쳐 저속 주변장치는 순차적으로 접근
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | Master가 AR/AW 채널로 주소와 트랜잭션 ID 전송 | ID 중복 여부, 버스트 길이 유효성 |
| 2 | Slave가 R/W 채널로 데이터 전송 | 채널별 handshake(VALID/READY) 정합성 |
| 3 | Write 트랜잭션은 B 채널로 완료 응답 | 완료 통지와 원 트랜잭션 ID 일치 |
| 4 | 서로 다른 ID의 트랜잭션이 비순차로 동시 진행 | 아웃스탠딩 트랜잭션 수, 처리량 |
| 5 | 저속 접근은 AHB-APB Bridge를 거쳐 순차 처리 | 브리지 지연, APB 사이클 수 |

> 요약: AXI는 주소·데이터·응답 채널을 분리하고 ID로 트랜잭션을 구분해 여러 요청을 비순차·동시에 처리한다.

## Ⅳ. 특징

| 구분 | APB | AHB | AXI | 수치·표준 포인트 |
|:---|:---|:---|:---|:---|
| 성능 특성 | 저속, 저전력, 단순 | 중간 성능, 파이프라인 | 고성능, 분리 채널, 아웃스탠딩 | AXI4 기준 5채널(AR/R/AW/W/B) |
| 중재 방식 | 브리지를 통해 접근 | 단일 버스, 중재기 기반 | 점대점(point-to-point), ID 기반 병렬 처리 | AHB는 동시에 하나의 마스터만 버스 점유 |
| 대표 용도 | UART, GPIO, Timer 레지스터 접근 | 중간 대역폭 IP 연결 | CPU, GPU, DMA, 메모리 컨트롤러 | AXI-Lite는 제어 레지스터, AXI-Stream은 DSP 데이터 파이프라인 |
| 후속 표준 | - | AHB-Lite로 단순화 | ACE(캐시 코히런시 확장), CHI(다중 코어 코히런트 메쉬) | AMBA 5에서 CHI로 대규모 코어 확장 지원 |

> 요약: APB는 저속 제어, AHB는 중간 성능, AXI는 고성능·비순차 트랜잭션 처리를 담당하며 AMBA 5의 CHI는 다중 코어 코히런시까지 확장한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | AHB | AXI | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 단일 공유 버스, 중재 필요 | 점대점 연결, 채널 분리 | 다중 마스터 고대역폭 요구 시 AXI 우선 |
| 비용/성능 | 게이트 수 적음, 대역폭 제한 | 채널·ID 관리로 게이트 수 증가, 고대역폭 확보 | 저속 IP는 AHB로 면적·전력 절감 |
| 운영/위험 | 버스 점유 대기(중재 지연) 발생 | 트랜잭션 순서 관리·검증 복잡도 증가 | 검증 리소스와 성능 요구 균형으로 판단 |

> 요약: 단순·저비용 연결은 AHB, 고대역폭·다중 마스터 병렬 처리가 필요하면 AXI를 선택한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 채널 데드락 | AXI 채널 간 handshake 순서 오류 | 프로토콜 컴플라이언스 검증(VIP), assertion 기반 검증 | 채널별 VALID/READY 데드락 발생률 |
| 트랜잭션 순서 오류 | ID 매칭 오류로 응답이 잘못된 요청과 연결 | ID 유일성 검증, 스코어보드 기반 시뮬레이션 | ID 매칭 오류 건수 |
| 브리지 병목 | AHB-APB 브리지에서 저속 접근 지연 누적 | 저속 주변장치 접근 빈도 분리, 배치 재설계 | 브리지 평균 응답 지연 |

> 요약: AMBA 설계 리스크는 채널 데드락과 트랜잭션 순서 오류이며, VIP 기반 프로토콜 검증과 ID 매칭 스코어보드로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 트랜잭션 처리량 | 아웃스탠딩 트랜잭션 수 목표치 이상 유지 | RTL 시뮬레이션, 성능 카운터 |
| 프로토콜 준수 | AXI VALID/READY handshake 100% 규격 준수 | UVM/VIP 기반 컴플라이언스 테스트 |
| 브리지 지연 | AHB-APB 브리지 왕복 지연 목표치 이내 | 파형 분석, 사이클 정확 시뮬레이션 |

> 요약: AMBA 설계 성공 여부는 트랜잭션 처리량, 프로토콜 준수율, 브리지 지연으로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. CPU·GPU·메모리 컨트롤러 등 고대역폭 블록은 AXI로 연결하고 ID 기반 아웃스탠딩 트랜잭션으로 병렬 처리량을 확보함
2. UART·GPIO·Timer 등 저속 주변장치는 APB로 연결해 면적·전력을 절감하고 AHB-APB 브리지 지연을 별도로 점검함
3. 다중 코어 캐시 코히런시가 필요한 대규모 SoC는 AMBA 5 CHI로 확장해 코어 간 데이터 일관성을 유지함

**결론 (2줄):**
- 기술사 판단: SoC 인터커넥트는 단일 버스가 아니라 APB·AHB·AXI 계층 구조로 설계해야 성능과 전력을 동시에 만족함
- 향후 방향: 멀티코어·칩렛 시대에는 AXI를 넘어 ACE·CHI 같은 코히런트 인터커넥트로 확장하는 추세임
