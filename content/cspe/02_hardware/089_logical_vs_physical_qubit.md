## 미리 알고가기

- 물리 큐비트는 실제 소자 위에 구현된 양자 비트임
- 논리 큐비트는 여러 물리 큐비트를 오류 정정 코드로 묶어 만든 계산 단위임
- 코드 거리(code distance)는 오류 정정 강도를 나타내는 대표 지표임
- 오류 증후군과 디코더는 물리 오류의 징후를 측정하고 보정 방향을 계산하는 오류 정정 계층임

## 작성 근거(검토용)

- 물리·논리 큐비트는 소자, 오류 정정 코드, 논리 오류율, 실행 깊이를 핵심 축으로 설명함
- 비교표는 정의·판단 대상, 대표 지표, 자원 비용을 대비함
- 실무 판단은 논리 큐비트 수·논리 오류율과 물리 큐비트 오버헤드·디코딩 지연으로 검증함

## Ⅰ. 개요

- **정의/개념**: 물리 큐비트는 양자 상태를 구현한 하드웨어 소자이고, 논리 큐비트는 여러 물리 큐비트를 오류 정정 코드로 묶어 논리 오류율을 낮춘 계산 단위임
- **배경/필요성**: 오류 정정 후 실행 가능한 계산 규모를 판단하기 위해 물리 큐비트 수와 논리 큐비트 수를 구분해야 함

### 쉽게 이해하기 (학습용)
- 가수 한 명의 목소리(물리 큐비트)는 흔들리기 쉽지만, 여러 명이 화음을 맞춰 만든 하나의 화음선(논리 큐비트)은 서로의 실수를 상쇄해 더 안정적임

## Ⅱ. 특징

- 물리 큐비트는 하드웨어 구현 규모와 제어 품질을 보여 줌
- 논리 큐비트는 실제 알고리즘 실행 가능성을 보여 줌
- 코드 거리와 물리 오류율이 논리 오류율을 결정함
- 물리 큐비트가 많아도 오류 정정이 약하면 실용성은 낮을 수 있음

### 쉽게 이해하기 (학습용)
- 가수 수만 늘려도 화음 규칙 없이 부르면 불협화음이 나듯, 물리 큐비트가 많아도 오류 정정이 약하면 논리 큐비트의 신뢰도는 낮음
- 화음 규칙(코드 거리)과 개별 음정 오차(물리 오류율)가 최종 화음의 정확도를 정함

## Ⅲ. 종류 및 비교

| 판단 기준 | 물리 큐비트 | 논리 큐비트 |
|:---|:---|:---|
| 정의·판단 대상 | 하드웨어 소자 자체이며 소자·제어 계층의 품질을 판단함 | 오류 정정으로 보호된 계산 단위이며 알고리즘 실행 가능성을 판단함 |
| 대표 지표 | 결맞음 시간·게이트 충실도·판독 오류율을 측정함 | 논리 오류율·코드 거리·실행 가능 깊이를 측정함 |
| 자원 비용 | 소자·제어·판독 회로를 큐비트마다 구성함 | 다수 물리 큐비트·측정 회로·디코더를 논리 큐비트마다 구성함 |

> 요약: 물리 큐비트는 소자·제어 계층의 품질을, 논리 큐비트는 오류 정정 뒤의 계산 가능성을 보여 줌.

### 쉽게 이해하기 (학습용)
- 가수 한 명의 음정 정확도를 볼지(물리 큐비트), 파트 전체가 만든 화음의 완성도를 볼지(논리 큐비트)에 따라 평가 기준과 필요한 인원이 달라짐

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 물리 큐비트 | 양자 상태를 저장하고 게이트와 측정을 수행하는 실제 장치임 |
| 오류 정정 코드 블록 | 여러 물리 큐비트를 묶어 하나의 논리 상태를 보호함 |
| 오류 증후군·디코더 | 오류 징후를 해석해 논리 오류를 낮추는 보정 경로를 제공함 |
| 논리 연산 계층 | 보호된 코드 공간 위에서 알고리즘 게이트를 실행함 |

> 요약: 논리 큐비트는 물리 큐비트, 오류 정정 코드, 오류 증후군·디코더, 논리 연산 계층으로 구성됨.

### 쉽게 이해하기 (학습용)
- 가수들(물리 큐비트), 화음 규칙(오류 정정 코드 블록), 음이탈을 잡아내는 지휘자(오류 증후군·디코더), 완성된 곡을 실제로 부르는 무대(논리 연산 계층)가 함께 있어야 공연이 완성됨

## Ⅴ. 원리 및 절차 흐름도

1. **물리 큐비트 준비**: 실제 소자와 제어 상태를 초기화함
2. **오류 정정 인코딩**: 여러 물리 큐비트에 논리 상태를 분산함
3. **오류 증후군·디코딩**: 오류 징후를 읽고 보정 방향을 계산함
4. **논리 연산 실행**: 보호된 상태에서 목표 알고리즘을 수행함

> 요약: 물리 큐비트에 논리 상태를 분산하고 오류 증후군을 해석한 뒤 보호된 상태에서 논리 연산을 수행함.

### 쉽게 이해하기 (학습용)
- 가수들이 자리를 잡고(준비), 화음 규칙대로 배치된 뒤(인코딩), 지휘자가 음 이탈을 감지해 교정 신호를 주고(디코딩), 그 위에서 실제 곡을 연주함(논리 연산)

## Ⅵ. 실무 사례

1. 양자 프로세서는 물리 큐비트 수와 논리 큐비트 목표를 함께 산정하고 논리 큐비트 수·논리 오류율을 확인함
2. 표면 코드 프로세서는 물리 오류율과 코드 거리를 함께 조정하고 물리 큐비트 오버헤드·디코딩 지연을 확인함

### 쉽게 이해하기 (학습용)
- 공연 기획자가 필요한 화음 완성도(논리 큐비트 수·논리 오류율)를 먼저 정하면 그만큼 가수 수(물리 큐비트)와 지휘 부담(디코딩 지연)이 늘어남을 미리 계산함

## Ⅶ. 결론

- 물리 큐비트는 소자·제어 품질을 보여주고 논리 큐비트는 오류 정정으로 보호된 뒤의 실제 알고리즘 실행 가능성을 보여주므로, 물리 큐비트 수가 많아도 오류 정정이 약하면 실용성은 낮음
- 양자 시스템의 규모는 물리 큐비트 수가 아니라 코드 거리·물리 오류율로 정해지는 논리 큐비트 수와 논리 오류율로 환산해 평가해야 함

### 쉽게 이해하기 (학습용)
- 무대에 세운 가수 수만으로 공연 품질을 판단하지 않고, 화음이 실제로 얼마나 정확한지로 최종 평가하는 것과 같음
