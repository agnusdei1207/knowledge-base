## 미리 알고가기

- 물리 큐비트는 실제 소자에 구현된 불안정한 양자 비트임
- 논리 큐비트는 여러 물리 큐비트를 묶어 오류 정정으로 보호한 추상 큐비트임
- 실용 양자컴퓨팅 규모는 물리 큐비트 수보다 논리 큐비트 품질로 판단해야 함

## Ⅰ. 개요

- **정의/개념**: 물리 큐비트는 실제 하드웨어 상의 양자 소자 하나를 의미하고, 논리 큐비트는 오류 정정 코드를 통해 여러 물리 큐비트를 묶어 안정적으로 사용할 수 있게 만든 계산 단위임
- **배경/필요성**: 물리 큐비트는 오류가 많아 긴 알고리즘을 직접 수행하기 어렵기 때문에, 실제 문제 해결 능력은 얼마나 많은 논리 큐비트를 확보했는지로 평가해야 함

## Ⅱ. 특징

- 물리 큐비트는 구현 가능성과 제어 난도를 보여줌
- 논리 큐비트는 실질적인 알고리즘 실행 가능성을 보여줌
- 코드 거리와 물리 오류율이 논리 오류율을 결정함
- 물리 큐비트 수 증가는 필요 조건일 뿐 충분 조건은 아님

## Ⅲ. 종류 및 비교

| 판단 기준 | 물리 큐비트 | 논리 큐비트 |
|:---|:---|:---|
| 구현 대상 | 실제 양자 소자 | 오류 정정된 추상 단위 |
| 주요 지표 | coherence, gate fidelity | logical error rate, code distance |
| 비용 구조 | 소자 제작과 제어 | 물리 큐비트 오버헤드와 디코딩 비용 |
| 의미 | 하드웨어 규모 | 실제 계산 규모 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Physical Qubit | 양자 상태를 저장하고 게이트와 측정을 수행하는 실제 장치임 |
| QEC Code Block | 여러 물리 큐비트를 묶어 하나의 논리 상태를 보호함 |
| Syndrome, Decoder | 오류 징후를 읽고 논리 오류를 줄이기 위한 추정과 보정을 수행함 |
| Logical Operation Layer | 보호된 코드 공간 위에서 실제 알고리즘 게이트를 실행함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 물리 큐비트 준비 | --> | 오류 정정 인코딩 | --> | syndrome/디코딩 | --> | 논리 연산 실행  |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **물리 큐비트 준비**: 실제 소자와 제어 상태를 초기화함
2. **오류 정정 인코딩**: 여러 물리 큐비트에 논리 상태를 분산함
3. **Syndrome 및 디코딩**: 오류 징후를 해석해 안정성을 유지함
4. **논리 연산 실행**: 목표 알고리즘을 보호된 상태에서 수행함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 물리 큐비트 수만 많은 시스템은 논리 오류율이 높으면 실제 문제 해결 능력이 거의 없을 수 있다
   - 해결방안: logical qubit 기준 평가를 적용하고 logical error rate와 algorithm depth capacity로 검증함
2. 문제: 코드 거리 증가에 따른 물리 큐비트와 제어 비용 증가가 확장성 한계를 빠르게 드러낼 수 있다
   - 해결방안: 물리 오류율 개선과 모듈화 설계를 병행하고 physical qubit overhead와 scaling efficiency로 검증함
3. 문제: 디코더 지연과 상관 오류가 커지면 논리 큐비트 품질 예측이 실제보다 낙관적으로 보일 수 있다
   - 해결방안: real-time decoder와 noise-aware model을 적용하고 decoder latency와 correlated error impact로 검증함

## Ⅶ. 적용 사례

- 양자 하드웨어 로드맵 평가에서는 논리 큐비트 목표를 기준으로 잡고 확인 지표는 logical qubit count와 target algorithm feasibility임
- 오류 정정 실험에서는 물리 대비 논리 성능 향상을 측정하고 확인 지표는 logical error suppression과 code distance scaling임
- 투자와 기술 비교 보고서에서는 물리 수 대신 논리 품질을 비교하고 확인 지표는 logical gate fidelity와 overhead ratio임

## Ⅷ. 결론

논리 큐비트와 물리 큐비트의 차이는 이름 차이가 아니라 실용성과 구현성의 차이이므로, 양자 컴퓨터 평가는 반드시 논리 오류율 기준으로 봐야 함.
