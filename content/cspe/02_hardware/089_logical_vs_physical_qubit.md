## 미리 알고가기

- 물리 큐비트는 실제 소자 위에 구현된 양자 비트임
- 논리 큐비트는 여러 물리 큐비트를 오류 정정 코드로 묶어 만든 계산 단위임
- code distance는 오류 정정 강도를 나타내는 대표 지표임

## Ⅰ. 개요

- **정의/개념**: 물리 큐비트는 실제 하드웨어 소자 하나를 뜻하고, 논리 큐비트는 여러 물리 큐비트를 오류 정정 코드로 묶어 더 안정적으로 쓸 수 있게 만든 추상 계산 단위임
- **배경/필요성**: 물리 큐비트는 오류가 많아 긴 알고리즘을 직접 수행하기 어렵기 때문에, 실제 문제 해결 능력은 물리 수보다 얼마나 쓸 만한 논리 큐비트를 확보했는지로 판단해야 함

## Ⅱ. 특징

- 물리 큐비트는 하드웨어 구현 규모와 제어 품질을 보여 줌
- 논리 큐비트는 실제 알고리즘 실행 가능성을 보여 줌
- 코드 거리와 물리 오류율이 논리 오류율을 결정함
- 물리 큐비트가 많아도 오류 정정이 약하면 실용성은 낮을 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 물리 큐비트 | 논리 큐비트 |
|:---|:---|:---|
| 의미 | 실제 회로나 이온 같은 하드웨어 소자 자체를 뜻함 | 오류 정정으로 보호된 계산 단위를 뜻함 |
| 대표 지표 | coherence time과 gate fidelity와 readout error가 중요함 | logical error rate와 code distance와 usable depth가 중요함 |
| 비용 구조 | 소자 제작과 제어 회로 확장이 핵심 비용임 | 많은 물리 큐비트와 decoder와 제어 오버헤드가 필요함 |
| 실무 판단 | 하드웨어 성숙도를 가늠하는 기준이 됨 | 실제 알고리즘 실행 가능성을 가늠하는 기준이 됨 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 물리 큐비트 | 양자 상태를 저장하고 게이트와 측정을 수행하는 실제 장치임 |
| 오류 정정 코드 블록 | 여러 물리 큐비트를 묶어 하나의 논리 상태를 보호함 |
| syndrome·decoder | 오류 징후를 해석해 논리 오류를 낮추는 보정 경로를 제공함 |
| 논리 연산 계층 | 보호된 코드 공간 위에서 알고리즘 게이트를 실행함 |

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 물리 큐비트 준비 | --> | 오류 정정 인코딩 | --> | syndrome·디코딩 | --> | 논리 연산 실행  |
+-------------+     +-------------+     +-------------+     +-------------+
```

## Ⅴ. 원리 및 절차 흐름도

1. **물리 큐비트 준비**: 실제 소자와 제어 상태를 초기화함
2. **오류 정정 인코딩**: 여러 물리 큐비트에 논리 상태를 분산함
3. **syndrome·디코딩**: 오류 징후를 읽고 보정 방향을 계산함
4. **논리 연산 실행**: 보호된 상태에서 목표 알고리즘을 수행함

## Ⅵ. 실무 적용 및 유의점

1. 양자 하드웨어 로드맵 평가는 물리 큐비트 수만 강조하면 실제 계산 가능성을 과대평가하기 쉬우므로 논리 큐비트 기준 목표를 함께 두고 논리 큐비트 수와 논리 오류율과 알고리즘 실행 깊이로 확인함
2. 코드 거리만 늘리는 확장 전략은 제어와 복호 비용이 급격히 커질 수 있으므로 물리 오류율 개선과 모듈화 설계를 병행하고 물리 큐비트 오버헤드와 확장 효율과 복호 지연시간으로 확인함

## Ⅶ. 결론

논리 큐비트와 물리 큐비트의 차이는 이름 차이가 아니라 실용성과 구현성의 차이이므로 평가 기준도 달라야 함.
