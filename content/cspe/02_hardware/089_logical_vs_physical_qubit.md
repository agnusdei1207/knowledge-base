## Ⅰ. 개요
- **정의**: 물리 큐비트는 하드웨어에 구현된 개별 양자 비트이고, 논리 큐비트는 오류정정 코드로 다수의 물리 큐비트를 묶어 만든 오류 허용 연산 단위임
- **배경/필요성**: 물리 큐비트의 오류율이 10^-3 수준이므로 실용 알고리즘 실행을 위해 오류가 억제된 논리 큐비트 추상화가 필요함
- **비유**: 물리 큐비트는 개별 선수, 논리 큐비트는 팀 전체의 합산 점수와 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 두 개념의 계층적 관계 이해 | 논리 큐비트 1개 = 수백~수천 물리 큐비트 | 오류정정 코드(088 참조)와의 연결 명시 필요 |

> 요약: 물리 큐비트를 오류정정으로 묶어 논리 큐비트를 구성하는 계층 구조임

## Ⅱ. 구성요소
```text
  +-- 논리 큐비트 ---------------------+
  |  +--------+ +--------+ +--------+ |
  |  |물리 Q1 | |물리 Q2 | |물리 Qn | |
  |  +--------+ +--------+ +--------+ |
  |       |          |          |      |
  |  +--- 오류정정 코드(인코딩) ---+   |
  +------------------------------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 물리 큐비트 | 초전도·이온트랩 등으로 구현된 단일 양자 비트임 (086 참조) | 팀의 개별 선수 |
| 논리 큐비트 | 오류정정 부호로 인코딩된 오류 허용 연산 단위임 | 팀 전체의 합산 성적 |
| 오류정정 코드 | 물리 큐비트 간 중복성을 부여하여 오류를 검출·정정하는 부호임 (088 참조) | 다수결 투표 규칙 |
| 보조 큐비트 | 신드롬 측정 전용으로 사용되며 논리 정보를 담지 않음 | 심판 역할 |

> 요약: 물리 큐비트·오류정정 코드·보조 큐비트가 논리 큐비트를 구성하는 핵심 요소임

## Ⅲ. 절차
```text
물리 큐비트 배치 --> 코드 인코딩 --> 신드롬 측정 --> 논리 게이트 실행
```
- 1단계: **물리 큐비트 배치** — 격자 구조에 데이터·보조 큐비트를 물리적으로 배치함
- 2단계: **코드 인코딩** — 표면 코드 등으로 물리 큐비트를 논리 큐비트에 매핑함
- 3단계: **신드롬 측정** — 보조 큐비트로 패리티를 반복 측정하여 오류를 검출함
- 4단계: **논리 게이트 실행** — 횡단(Transversal) 게이트 또는 매직 상태 증류로 논리 연산을 수행함

> 요약: 배치-인코딩-측정-논리 연산의 4단계로 오류 허용 양자 연산을 수행함

## Ⅳ. 문제점
- 자원 비율 과다: 논리 큐비트 1개에 1,000개 이상 물리 큐비트가 필요하여 하드웨어 규모가 방대함
- 논리 게이트 제한: 횡단 게이트로 구현 가능한 게이트 집합이 범용적이지 않음
- 오류 전파 위험: 보조 큐비트의 측정 오류가 디코딩 실패로 이어질 수 있음

> 요약: 자원 비율·게이트 제한·오류 전파가 논리 큐비트 실용화의 3대 장벽임

## Ⅴ. 개선방안
1. 단기: qLDPC 등 고비율 코드로 물리 큐비트 대 논리 큐비트 비율을 절감함
2. 중기: 매직 상태 증류(Magic State Distillation) 최적화로 범용 게이트 집합을 확보함
3. 장기: 플래그 큐비트(Flag Qubit) 기법으로 보조 큐비트 오류 전파를 차단함

> 요약: 고비율 코드·매직 상태 증류·플래그 큐비트로 논리 큐비트의 실용성을 확보함

## Ⅵ. 전망
- 발전 방향: 물리 큐비트 품질 향상과 고효율 코드 발전으로 오버헤드 비율이 지속 감소하는 추세임
- 기술사적 판단: 논리 큐비트 수십 개를 안정적으로 운용하는 시점이 양자 실용화의 전환점임
- 기술사 제언: 물리 오류율·코드 거리·논리 오류율 간 관계를 정량적으로 분석하는 역량이 필요함
