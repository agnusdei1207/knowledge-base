## Ⅰ. 개요
- 정의: 유효하지 않은 데이터가 포함된 블록을 정리하여 가용 빈 블록을 확보하는 과정
- 배경: 낸드 플래시의 "블록 단위 삭제" 및 "페이지 단위 쓰기" 특성 차이 극복
- 출제 의도
| 구분 | 내용 |
| --- | --- |
| 핵심 | 유효 페이지 복사, 블록 삭제, 쓰기 증폭(WAF), 성능 저하 해결 |

## Ⅱ. 구성요소
```
[ Block A ] (Mixed) -> [ Valid Pages ] -> [ Block B ] (New)
 [ Invalid ]             [ Clean up ]   -> [ Block A ] (Erased)
```
| 구성요소 | 설명 | 비유 |
| --- | --- | --- |
| 유효 페이지 | 호스트가 여전히 사용 중인 최신 데이터 상태 | 살릴 물건 |
| 무효 페이지 | 덮어쓰기 등으로 인해 더 이상 필요 없는 데이터 | 버릴 쓰레기 |
| 프리 블록 | 데이터 기록이 가능한 완전히 비워진 블록 상태 | 빈 박스 |
> 요약: 조각난 유효 데이터를 모아 새로운 블록에 쓰고 기존 블록은 비움

## Ⅲ. 절차
1. 대상 선정: 무효 페이지가 많아 효율이 높은 Victim 블록 선택
2. 데이터 복사: 선정된 블록 내의 "유효 페이지"만 읽어 다른 빈 블록에 기록
3. 매핑 갱신: 복사된 페이지들의 새로운 물리 주소를 매핑 테이블에 반영
4. 블록 삭제: 유효 데이터가 모두 빠져나간 원본 블록을 한꺼번에 삭제
> 요약: 쓰기 공간 부족 시 발생하는 필수 작업으로 SSD 성능 유지의 핵심임

## Ⅳ. 문제점
- GC 실행 중 호스트 I/O 요청이 대기하게 되어 응답 속도가 튀는 현상 발생함

## Ⅴ. 개선방안
- 오버 프로비저닝(OP) 영역 확대 및 TRIM 명령을 통한 조기 무효화 처리함

## Ⅵ. 전망
- 호스트가 데이터의 성격(Hot/Cold)을 지정하는 멀티 스트림 기술과의 연계 강화됨
- AI 기반으로 GC 시점을 최적화하여 꼬리 지연 시간(Tail Latency)을 극소화하는 것이 목표임
