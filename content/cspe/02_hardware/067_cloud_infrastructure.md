## Ⅰ. 개요
- 정의: 클라우드 서비스를 제공하기 위한 물리적 자원(HW) 및 이를 효율화하는 기술적 기반
- 배경: 자원 이용률 극대화(가상화) 및 고성능 요구(베어메탈)의 병존
- 출제 의도: 물리 서버와 가상 서버의 구조적 차이 및 활용 시나리오 비교 역량 측정

## Ⅱ. 구성요소
- ASCII 구조도
  +------------------+     +------------------+
  |    App / DB      |     |  VM  |  VM  |  VM |
  +------------------+     +------------------+
  |    OS (Linux)    |     |    Guest OS      |
  +------------------+     +------------------+
  |   Bare Metal HW  |     |   Hypervisor     |
  +------------------+     +------------------+
  | [Bare Metal]     |     | [Virtualization] |
  +------------------+     +------------------+

- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| Bare Metal | OS가 HW에 직접 설치되어 자원을 독점적으로 사용 | 단독 주택 |
| Hypervisor | 물리 자원을 논리적으로 분할하여 VM에 할당 | 아파트 관리실 |
| Guest OS | 하이퍼바이저 위에서 구동되는 독립된 OS | 아파트 입주 세대 |

- > 요약: 베어메탈은 성능 최적화, 가상화는 유연성과 효율성에 초점

## Ⅲ. 절차
- ASCII 흐름도
  (요청) -> [관리 SW] -> [자원 할당] -> [인스턴스 생성] -> (서비스)

1. 리소스 프로비저닝: 가상/물리 서버 자원 할당 계획 수립
2. 하이퍼바이저/OS 설치: 하드웨어 위에 제어 계층 구성
3. 논리적 격리: 네트워크, 스토리지, 컴퓨팅 자원 독립화
4. 오케스트레이션: 자동화 도구를 통한 전체 인프라 생명주기 관리

- > 요약: 하드웨어 추상화를 통해 유연한 자원 공급 체계 구축

## Ⅳ. 문제점
- 가상화 Overload: 하이퍼바이저 계층의 연산 개입으로 인한 성능 손실 발생
- Noisy Neighbor: 가상화 환경에서 타 VM의 자원 점유로 인한 간섭 현상

## Ⅴ. 개선방안
- Bare Metal Cloud: 하이퍼바이저 없이 클라우드의 자동화 이점만 수용
- HW Offloading: SmartNIC 등을 활용하여 가상화 오버헤드를 하드웨어로 전가

## Ⅵ. 전망
- 로드맵: SDDC(Software Defined Data Center) 고도화 및 Full-Stack 자동화 지향
- 제어: AI 기반 인프라(AIOps)를 통한 자동 장애 탐지 및 자원 최적 배치 필수
