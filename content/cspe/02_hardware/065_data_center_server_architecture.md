# 데이터 센터 서버 아키텍처 (Data Center Server Architecture)

## 미리 알고가기

- Scale-up: 한 서버의 중앙처리장치(Central Processing Unit, CPU), 메모리, 입출력(Input/Output, I/O) 용량을 키워 성능을 높이는 방식임
- Scale-out: 여러 서버를 수평으로 늘려 처리량과 가용성을 높이는 방식임
- GPU/NPU: 그래픽 처리 장치(Graphics Processing Unit, GPU)와 신경망 처리 장치(Neural Processing Unit, NPU)는 AI 서버의 대표 가속기 자원임
- BMC: 베이스보드 관리 컨트롤러(Baseboard Management Controller, BMC)는 서버 전원, 센서, 원격 관리를 담당함
- Failure Domain: 한 장애가 동시에 영향을 미치는 서버, 랙, 전원, 네트워크 범위임

## 1. 개요

- **정의/개념**: 데이터 센터 서버 아키텍처는 대규모 서비스의 성능, 가용성, 확장성, 전력, 운영 자동화 요구를 만족하도록 컴퓨트, 메모리, 스토리지, 네트워크, 전원·냉각, 관리 기능을 배치한 서버 시스템 구조임.
- **배경/필요성**: 클라우드, 인공지능(Artificial Intelligence, AI), 대규모 웹 서비스는 단일 서버 성능보다 많은 서버의 조합과 운영 효율이 중요함. 서버 아키텍처는 장애 격리와 자원 효율, 배포 속도를 좌우하므로 초기 설계가 핵심임.
- **비유**: 한 건물 안에 사무실, 창고, 통신실, 전력실, 관제실을 업무 흐름에 맞게 배치하는 것과 같음.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 데이터센터 서버 구성과 설계 기준 설명 | 컴퓨트, 메모리, 네트워크, BMC, 가용성 | 데이터센터 시설과 서버 구조 혼동 |

> 요약: 데이터 센터 서버 아키텍처는 대규모 서비스를 위한 서버 자원 배치와 운영 관리 구조임.

## 2. 특징 및 비교

| 판단 기준 | Scale-up 서버 | Scale-out 서버 |
|:---|:---|:---|
| 확장 방식 | 중앙처리장치(Central Processing Unit, CPU), 메모리, 입출력(Input/Output, I/O)을 한 서버 안에서 증설함 | 여러 서버 노드를 추가해 수평 확장함 |
| 장애 영향 | 단일 서버 장애 영향이 크고 고가 부품 의존도가 높음 | 노드 장애를 분산 처리하나 분산 시스템 복잡도가 큼 |
| 적용 기준 | 대용량 데이터베이스(Database, DB), 메모리 집약, 라이선스 제약 업무에 적합함 | 웹, 클라우드, 빅데이터, AI 클러스터에 적합함 |

> 요약: 서버 아키텍처는 워크로드가 수직 확장에 맞는지 수평 분산에 맞는지에 따라 달라짐.

## 3. 구성요소/구조

```text
+----------+     +----------+     +----------+
| Compute  | --- | Network  | --- | Storage  |
+----------+     +----------+     +----------+
      |                |               |
      v                v               v
+----------+     +----------+     +----------+
| Memory   |     | BMC/Mgmt |     | Power/Fan|
+----------+     +----------+     +----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 컴퓨트 노드 | CPU, 그래픽 처리 장치(Graphics Processing Unit, GPU), 신경망 처리 장치(Neural Processing Unit, NPU)가 애플리케이션과 데이터 처리를 수행함 | 작업실 |
| 메모리/스토리지 | 동적 램(Dynamic Random Access Memory, DRAM), 솔리드 스테이트 드라이브(Solid State Drive, SSD), 비휘발성 메모리 익스프레스(Non-Volatile Memory Express, NVMe), 외부 스토리지가 상태와 데이터를 저장함 | 자료실과 창고 |
| 네트워크 | 네트워크 인터페이스 카드(Network Interface Card, NIC), 스위치, 인터커넥트가 서버 간 통신과 외부 접속을 제공함 | 도로망 |
| 관리/전원·냉각 | BMC, 전원 공급 장치(Power Supply Unit, PSU), 팬, 센서가 원격 관리와 운영 안정성을 지원함 | 관제실과 설비팀 |

> 요약: 데이터센터 서버는 계산 자원뿐 아니라 네트워크, 저장장치, 관리, 전원·냉각이 통합된 운영 단위임.

### 원리/흐름도

```text
+----------+     +----------+     +----------+     +----------+
| Req      | --> | Node     | --> | Rack     | --> | Operate  |
+----------+     +----------+     +----------+     +----------+
```

1. **요구 정의**: 서비스 수준 협약(Service Level Agreement, SLA), 처리량, 지연, 데이터 크기, 전력 한계, 장애 허용 수준을 정의함
2. **노드 설계**: CPU, 메모리, 가속기, SSD, NIC, BMC 사양을 워크로드에 맞게 선택함
3. **랙 통합**: 전원, 냉각, 네트워크 초과 가입 비율, 장애 도메인을 고려해 배치함
4. **운영 관리**: 프로비저닝, 모니터링, 펌웨어 업데이트, 용량 계획을 자동화함

> 요약: 서버 아키텍처 설계는 서비스 요구를 노드 사양과 랙 운영 구조로 변환하는 과정임.

## 4. 문제점 및 개선방안

- **P1 자원 불균형**: CPU, 메모리, 스토리지, 네트워크 중 하나가 병목이면 나머지 자원이 유휴 상태가 됨
- **P1 대응**: 워크로드별 병목 측정, right-sizing, 자원 풀링, 비균일 메모리 접근(Non-Uniform Memory Access, NUMA)-aware 배치를 적용함 (확인: 자원 사용률 균형)
- **P2 장애 도메인 확대**: 같은 랙, 전원, 스위치에 의존한 배치가 장애 영향을 여러 서비스로 확산시킴
- **P2 대응**: 랙·전원·스위치 기준 anti-affinity와 이중화 배치를 설계함 (확인: 장애 도메인별 서비스 분산도)
- **P3 전력·열 제약**: 고밀도 CPU/GPU 서버는 랙 전력과 냉각 한계를 초과해 성능 throttling을 유발함
- **P3 대응**: 랙 전력 예산, airflow 관리, 액체냉각 검토, 온도 기반 스케줄링을 적용함 (확인: throttling 발생률)

> 요약: 데이터센터 서버 개선은 자원 균형화, 장애 도메인 분리, 전력·열 기반 운영 정책으로 수행함.

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 클라우드 컴퓨트 풀 | CPU·메모리 사용률을 기준으로 인스턴스 타입과 NUMA 배치를 조정함 | 자원 사용률 균형, p95 지연 |
| AI 학습 클러스터 | GPU 서버를 고대역 네트워크와 고전력 랙에 배치하고 냉각 용량을 선검증함 | GPU utilization, east-west bandwidth, throttling률 |
| 핵심 서비스 배치 | 랙·전원·스위치 fault domain을 분리해 복제본을 anti-affinity로 배치함 | 장애 도메인별 복제본 수, failover time |

> 요약: 실무에서는 서버 사양보다 워크로드 병목, 장애 도메인, 전력·냉각 한계를 지표로 확인함.

## 6. 결론

- **발전 방향**: 데이터센터 서버는 가속기 집적 노드, 메모리 풀링, 네트워크·스토리지 오프로딩, 액체냉각, 조합형 인프라를 결합한 자원 풀 구조로 이동함
- **기술사적 판단**: SLA, fault domain, 랙 전력 밀도, 주변 장치 상호연결 익스프레스(Peripheral Component Interconnect Express, PCIe) lane 예산, 냉각 방식, 관리망 이중화를 기준으로 CPU/GPU/메모리/네트워크 구성을 결정함; burn-in, firmware compliance, thermal throttling, failover time, east-west bandwidth를 표준 부하에서 측정함
- **기술사 제언**: 데이터센터 서버는 부품 사양 나열보다 전력·냉각·장애 격리·운영 자동화를 포함한 서비스 단위 설계로 제시함
