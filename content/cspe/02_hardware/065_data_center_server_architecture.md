## 미리 알고가기

- 데이터센터 서버는 CPU, 메모리, 스토리지, 네트워크, 전력 경로가 서비스용으로 최적화된 시스템임
- 핵심 목표는 확장성, 가용성, 관리성, 전력 효율임
- 단일 서버 성능보다 랙과 클러스터 단위 운영성이 중요함

## Ⅰ. 개요

- **정의/개념**: 데이터센터 서버 아키텍처는 대규모 서비스와 가상화와 AI 워크로드를 안정적으로 수용하기 위해 연산과 메모리와 스토리지와 네트워크와 전원 이중화를 조합한 서버 시스템 구조임
- **배경/필요성**: 클라우드와 엔터프라이즈 서비스는 단일 장비 장애가 곧 서비스 장애로 이어질 수 있으므로, 성능뿐 아니라 교체 용이성과 원격 관리와 에너지 효율이 함께 필요함

## Ⅱ. 특징

- 멀티소켓 CPU와 대용량 메모리와 고속 NIC를 조합해 범용 워크로드를 수용함
- 전원과 팬과 스토리지 경로의 이중화가 일반적임
- BMC와 원격 관리 기능으로 무인 운영과 자동 복구를 지원함
- 랙 단위 밀도와 전력과 냉각 제약을 함께 고려해야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 범용 데이터센터 서버 | AI, HPC 서버 |
|:---|:---|:---|
| 연산 중심 | CPU 중심 | GPU, 가속기 중심 |
| 메모리 구성 | 대용량 DRAM, NVMe | HBM, 고대역폭 NIC 추가 |
| 네트워크 요구 | 일반 이더넷 | 고속 RDMA, NVLink, InfiniBand |
| 전력 밀도 | 중간 | 높음 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Compute Node | CPU와 가속기가 실제 연산을 담당하며 워크로드 유형에 따라 구성이 달라짐 |
| Memory, Storage Path | DRAM과 NVMe와 RAID가 데이터 접근 성능과 장애 대응성을 결정함 |
| Network Interface | 다중 NIC와 고속 인터커넥트가 서비스 트래픽과 클러스터 통신 병목을 좌우함 |
| Power, Management Layer | 이중 PSU와 BMC와 센서가 무중단 운영과 원격 관리를 가능하게 함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 워크로드 요구 정의 | --> | 서버 자원 구성  | --> | 이중화/관리 설계 | --> | 랙 운영 최적화  |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **워크로드 요구 정의**: CPU, 메모리, 스토리지, 네트워크 요구량을 산정함
2. **서버 자원 구성**: 소켓 수와 DIMM과 NVMe와 NIC 구성을 정함
3. **이중화 및 관리 설계**: PSU와 팬과 관리 채널을 중복 구성함
4. **랙 운영 최적화**: 전력과 냉각과 배선 구조를 조정함

## Ⅵ. 문제점 및 해결 방안

1. 문제: CPU와 메모리와 네트워크 자원을 균형 없이 확장하면 특정 계층 병목 때문에 서버 투자 대비 성능이 낮아질 수 있음
   - 해결방안: workload profiling을 기반으로 자원을 구성하고 CPU utilization과 memory bandwidth와 NIC throughput으로 검증함
2. 문제: 고밀도 서버는 랙 전력과 냉각 한계를 빠르게 넘겨 thermal throttling과 장애 확률이 커질 수 있음
   - 해결방안: rack power budget과 냉각 용량을 함께 설계하고 inlet temperature와 power headroom으로 검증함
3. 문제: 원격 관리와 펌웨어 계층이 부실하면 장애 대응 시간이 길어져 운영 가용성이 떨어질 수 있음
   - 해결방안: BMC 표준화와 펌웨어 관리 절차를 적용하고 MTTR와 remote recovery success rate로 검증함

## Ⅶ. 적용 사례

- 가상화 클러스터 서버에서는 멀티소켓과 대용량 메모리를 구성하고 확인 지표는 VM density와 host utilization임
- AI 추론 서버에서는 GPU와 고속 NIC를 통합하고 확인 지표는 inference throughput과 rack power density임
- 스토리지 노드 서버에서는 NVMe와 이중 전원을 강화하고 확인 지표는 IOPS와 failover success rate임

## Ⅷ. 결론

데이터센터 서버 아키텍처는 단일 부품 성능보다 랙과 운영 체계 안에서 얼마나 균형 있게 확장되고 관리되는지가 핵심임.
