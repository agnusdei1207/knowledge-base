## 미리 알고가기

- 데이터센터 서버는 CPU, 메모리, 스토리지, 네트워크, 전원 경로를 서비스 운영 기준으로 묶은 시스템임
- 핵심 목표는 확장성, 가용성, 관리성, 전력 효율임
- 서버 자원 구성은 랙 전력·냉각과 클러스터 장애 범위 안에서 판단함

## 작성 근거(검토용)

- 데이터센터 서버는 연산, 메모리, 스토리지, 네트워크, 전원·관리 계층을 핵심 축으로 설명함
- 비교표는 범용 서버와 AI·HPC 서버의 연산 구성, 데이터 경로, 네트워크, 운영 제약을 대비함
- 실무 판단은 CPU 준비 시간, 스토리지 지연, 랙 입력 전력, 열 조절 횟수로 구체화함

## Ⅰ. 개요

- **정의/개념**: 데이터센터 서버 아키텍처는 서비스 워크로드와 장애 격리 요구에 맞춰 연산, 메모리, 스토리지, 네트워크, 전원·관리 경로를 조합한 서버 시스템 구조임
- **배경/필요성**: 서버 고장·교체 중 서비스 중단을 줄이기 위해 원격 관리, 부품 교체, 장애 격리, 전원 경로를 함께 설계할 필요가 있음

## Ⅱ. 특징

- CPU·메모리·스토리지·NIC 비율을 워크로드의 연산량과 I/O 요구량에 맞춰 배치함
- PSU·팬·스토리지 경로 이중화와 BMC 원격 관리를 장애 격리 구조에 포함함
- 범용 가상화 서버와 AI 가속 서버는 전력 밀도와 인터커넥트 요구가 다름
- 서버 소비전력과 발열량이 랙 전력·냉각 용량을 넘으면 열 조절로 처리량이 제한됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 범용 데이터센터 서버 | AI·HPC 서버 |
|:---|:---|:---|
| 연산 중심 | CPU·DRAM으로 범용 서비스와 VM을 처리함 | GPU·NPU로 행렬·텐서 연산을 처리함 |
| 메모리와 스토리지 | DRAM과 NVMe를 서비스 부하에 맞춰 배치함 | HBM·고속 로컬 스토리지로 가속기에 데이터를 공급함 |
| 네트워크 요구 | 서비스 이더넷과 관리망을 분리함 | RDMA·InfiniBand·NVLink로 가속기 데이터를 교환함 |
| 운영 제약 | VM 밀도·부품 교체 시간 | 랙 전력·냉각 용량·인터커넥트 병목 |

> 요약: 범용 서버는 CPU·메모리·스토리지를 서비스 부하에 배분하고, AI·HPC 서버는 가속기 전력 밀도와 인터커넥트에 맞춰 랙과 냉각을 구성함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 연산 노드 | CPU·가속기가 워크로드의 명령과 병렬 연산을 처리함 |
| 메모리·스토리지 경로 | DRAM·NVMe·RAID가 데이터 공급 지연과 저장장치 장애 범위를 결정함 |
| 네트워크 인터페이스 | 서비스 요청과 클러스터 통신을 분리하고 링크별 처리량을 제공함 |
| 전원·관리 계층 | 이중 PSU·BMC·센서가 전원 장애 격리와 원격 복구를 담당함 |

> 요약: 연산·메모리·I/O 경로가 워크로드를 처리하고 전원·관리 계층이 장애를 격리해 원격 복구를 수행함.

## Ⅵ. 실무 사례

1. 가상화 클러스터는 CPU·메모리·스토리지 경로를 배치하고 CPU 준비 시간·스토리지 p95 지연을 확인함
2. GPU 서버는 랙 전력·냉각 한도에 맞춰 가속기 수를 정하고 랙 입력 전력·열 조절 횟수를 확인함

## Ⅶ. 결론

데이터센터 서버는 워크로드별 연산·메모리·I/O 수요와 랙 전력·냉각 한도를 기준으로 자원 구성을 결정해야 함.
