## Ⅰ. 개요
- 정의: UC 버클리에서 개발한 오픈 소스 기반의 5세대 RISC 명령어 집합 구조
- 배경: 상용 ISA(ARM, x86)의 높은 라이선스 비용 및 폐쇄성 탈피 필요성
- 출제 의도: 모듈형 구조, 확장성, 오픈 소스 하드웨어 생태계의 기술적 가치 이해

## Ⅱ. 구성요소
- ASCII 구조도
  +---------------------------------------+
  |  RISC-V Ecosystem                     |
  |  +-----------+  +------------------+  |
  |  | Base ISA  |  | Standard Ext.    |  |
  |  | (RV32/64I)|  | (M, A, F, D, C)  |  |
  |  +-----------+  +------------------+  |
  |       |                  |            |
  |  +----v------------------v----------+  |
  |  |      Custom Extensions (P, V)    |  |
  |  +----------------------------------+  |
  +---------------------------------------+

- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| Base ISA | 필수적인 기본 정수 연산 집합 | 건물의 뼈대 |
| Extensions | 곱셈(M), 부동소수점(F) 등 선택적 모듈 | 옵션 가구 |
| Privilege | 사용자/시스템 모드 등 보안 실행 계층 | 접근 권한 |
> 요약: 최소한의 Base와 필요한 Extension을 조합하는 모듈형 설계임

## Ⅲ. 절차
- ASCII 흐름도
  (Design) -> (Select Extensions) -> (Implementation) -> (Verification)
      ^                                                     |
      +----------------- (Community Feedback) --------------+

- 4단계 설명
1. Spec 선택: 하드웨어 용도에 맞는 RV32/64/128I 등 기본 사양 결정
2. 확장 모듈 추가: 응용 분야(AI, 보안)에 따라 특화된 익스텐션 결합
3. 커스텀 설계: 오픈 소스 소스코드를 수정하여 독자적인 IP 구현
4. 컴파일러 최적화: GCC, LLVM 등 오픈 소스 툴체인을 통한 성능 튜닝
> 요약: 누구나 자유롭게 설계에 참여하고 최적화할 수 있는 개방형 절차임

## Ⅳ. 문제점
- 파편화: 업체별 커스텀 확장으로 인한 호환성 결여 및 생태계 분절 위험
- 검증 도구 부족: 상용 ISA 대비 성숙도가 낮은 검증 프레임워크 및 툴

## Ⅴ. 개선방안
- (단기) 프로파일(Profile) 표준화: 호환성 보장을 위한 표준 사양 그룹 정의
- (중기) 오픈 소스 검증 툴킷: 공통 검증 플랫폼(OpenHW Group 등) 강화
- (장기) 리눅스 재단 협업: OS 레벨의 표준 드라이버 및 미들웨어 지원 확대

## Ⅵ. 전망
- 로드맵: IoT 기기에서 시작하여 데이터센터 AI 가속기 및 차량용 반도체로 확산
- CSF: 글로벌 빅테크의 참여 유도 및 소프트웨어 생태계의 완전한 성숙이 관건임
