## Ⅰ. 개요
- **정의**: DRAM 적층 밀도와 핀당 속도를 극대화한 5세대 고대역폭 메모리
- **배경/필요성**: AI 모델 파라미터가 수천억 개 규모로 증가하면서 GPU 연산 속도를 메모리 대역폭이 따라가지 못하는 Memory Wall이 심화됨. 기존 HBM3(030 참조) 대비 인터페이스 폭(1024-bit)을 유지하면서 핀당 전송률을 높여 대역폭을 끌어올리는 접근이 요구됨
- **비유**: 차선 수(1024-bit)는 그대로 두되 제한속도를 최고로 올려 화물 처리량을 늘린 고속도로

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| HBM 세대 간 차이 구분 | 핀당 속도 향상(9.6Gbps)이 대역폭 1.18TB/s 달성의 핵심 수단임 | HBM3과 I/O 폭은 동일(1024-bit), HBM4(032 참조)의 2048-bit과 혼동 금지 |

> 요약: HBM3E는 1024-bit 인터페이스를 유지하면서 핀당 속도를 극한까지 올려 1.18TB/s 대역폭을 달성한 메모리임

## Ⅱ. 구성요소
```text
+------------------+                    +---------------------+
|  GPU / AI 가속기  | <-- 1024-bit --> |    HBM3E Stack       |
+------------------+   인터포저 연결    | +---+ +---+ +---+   |
                                        | |Die| |Die| |Die|   |
                                        | +---+ +---+ +---+   |
                                        |  ... 12단 TSV 적층   |
                                        | +------------------+ |
                                        | | Base Logic Die   | |
                                        | +------------------+ |
                                        +---------------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| DRAM Die 12단 적층 | 백그라인딩으로 얇게 연마한 다이를 TSV로 수직 관통하여 12층 적재, 36GB 용량 확보 | 얇은 팬케이크 12장을 꼬치로 관통시켜 쌓은 구조 |
| Base Logic Die | PHY 인터페이스와 ECC, 온도 센서 등 제어 회로를 집적한 최하단 칩 | 건물 1층의 관리 사무소 |
| 2.5D 인터포저 | GPU와 HBM3E 스택을 실리콘 기판 위에 수평 배치하여 1024-bit 배선으로 연결 | 두 건물을 잇는 지하 연결통로 |
| MR-MUF 방열 소재 | 다이 사이 빈틈에 고열전도성 언더필을 주입하여 발열을 기판 방향으로 배출 | 층간 사이에 끼운 냉각 시트 |

> 요약: 12단 DRAM을 TSV로 수직 적층하고 인터포저 위에서 GPU와 1024-bit 병렬 연결하는 구조임

## Ⅲ. 절차
```text
웨이퍼 가공 -> KGD 선별 -> TSV 적층 -> MR-MUF 충진 -> 인터포저 접합 -> 패키지 테스트
```
- 1단계: 웨이퍼를 백그라인딩하여 다이 두께를 40um 이하로 연마하고, TSV 비아를 형성함
- 2단계: 다이 단위 사전 테스트(KGD)를 수행하여 양품만 선별함 — 12단 중 1개라도 불량이면 전체 스택 폐기이므로 수율 관리가 핵심임
- 3단계: 양품 다이를 마이크로 범프로 12단 적층한 뒤 MR-MUF 언더필을 주입하여 방열 경로를 확보함
- 4단계: 완성된 HBM3E 스택을 인터포저 위에 접합하고 GPU와 함께 2.5D 패키지로 통합 테스트함

> 요약: 얇은 다이 가공 -> 양품 선별 -> 12단 적층 및 방열 처리 -> 인터포저 통합 순서로 제조함

## Ⅳ. 문제점
- TSV 수율 한계: 수만 개 TSV 비아 중 하나라도 단선·단락 시 전체 스택 폐기 — 적층 수가 12단으로 증가하며 누적 불량률이 상승함
- 발열 집중: 핀당 속도를 9.6Gbps까지 올리며 단위 면적당 발열 밀도가 증가 — MR-MUF만으로 방열 한계에 근접함
- 대역폭 천장: I/O 폭이 1024-bit로 고정되어 핀당 속도 증가만으로는 2TB/s 이상 도달이 곤란함

> 요약: TSV 수율·발열 밀도·고정 I/O 폭이 HBM3E의 물리적 한계를 규정함

## Ⅴ. 개선방안
1. 단기: AI 비전 기반 TSV 검사 자동화 도입으로 KGD 선별 정확도를 높여 수율 손실을 축소함
2. 중기: 하이브리드 본딩(범프리스) 공정으로 전환하여 다이 간 열 저항을 낮추고 발열 밀도 문제를 완화함
3. 장기: I/O 폭을 2048-bit로 확장한 HBM4(032 참조)로 세대 전환하여 대역폭 천장을 근본 해소함

> 요약: 검사 자동화 -> 본딩 공정 혁신 -> 차세대 규격 전환 순으로 한계를 극복함

## Ⅵ. 전망
- 발전 방향: HBM3E는 1024-bit 규격의 완성형이며, 이후 HBM4(032 참조)의 2048-bit 아키텍처로 패러다임이 전환됨
- 기술사적 판단: AI 학습/추론 가속기 설계 시 메모리 대역폭 산정 기준으로 HBM3E의 1.18TB/s를 벤치마크로 활용 가능함
- 기술사 제언: GPU 가동률 저하 원인이 메모리 대역폭인지 용량인지를 구분하여 HBM3E 도입 여부를 판단할 필요
