## 미리 알고가기

- HBM3E는 HBM3를 확장한 고대역폭 메모리 세대로 AI 가속기에 집중 적용되는 흐름임
- TSV 적층과 인터포저 연결 구조는 유지하되 속도와 용량과 전력 효율을 함께 끌어올리는 방향이 핵심임
- 고단 적층이 늘수록 열과 수율과 신호 무결성 관리가 더 중요해짐

## Ⅰ. 개요

- **정의/개념**: HBM3E는 HBM3 아키텍처를 기반으로 핀 속도와 스택 용량과 전력 효율을 개선해 대형 AI 학습과 추론에 필요한 데이터 공급 능력을 높인 확장형 고대역폭 메모리 세대임
- **배경/필요성**: 대형 모델은 연산기 성능보다 메모리 대역폭과 용량이 먼저 병목이 되므로, 기존 HBM3보다 더 높은 실효 대역폭과 더 큰 온패키지 메모리 구성이 필요해짐

## Ⅱ. 특징

- HBM3와 동일한 적층 철학을 유지하면서도 스택당 대역폭과 용량을 실질적으로 확장함
- AI 가속기 워크로드에 맞춰 bit당 전력 효율을 높여 동일 전력 범위에서 더 많은 데이터를 공급함
- 고단 적층과 고속 신호 조건이 겹쳐 열 관리와 패키지 신뢰성이 설계 성패를 좌우함
- 시스템 경쟁력은 단일 칩 성능보다 가속기와 냉각과 패키지 수율을 함께 맞추는 통합 능력에 달려 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | HBM3 | HBM3E |
|:---|:---|:---|
| 지향점 | 표준 고대역폭 메모리 세대로 폭넓은 적용 기반을 마련함 | AI 중심 워크로드에 맞춰 속도와 용량과 효율을 더 끌어올림 |
| 대역폭 | 이미 매우 높지만 차세대 AI에는 부족해질 수 있음 | 스택당 대역폭을 더 높여 대형 모델 데이터 공급을 강화함 |
| 용량 구성 | 고성능 가속기 기본 용량 수준을 제공함 | 더 큰 스택 용량으로 모델 탑재 여유를 늘림 |
| 설계 부담 | 고대역폭 패키징 난도가 높음 | 더 높은 열 밀도와 수율 민감도로 통합 난도가 더 큼 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| High-Speed DRAM Dies | 적층된 메모리 다이가 더 높은 핀 속도와 용량 구성을 지원해 스택 처리량을 끌어올림 |
| TSV and Micro-Bump Interconnect | 짧은 전기 경로를 유지해 초고속 병렬 전송과 bit당 전력 효율을 동시에 확보함 |
| Base Logic Die | 채널 제어와 테스트와 신호 조정을 담당하며 고속 동작 안정성을 좌우함 |
| Thermal and Package Stack | 고단 적층 구조의 열 방출과 기계적 안정성을 관리해 실제 제품 수율과 지속 성능을 결정함 |

```text

      | DRAM Die    |
      +-------------+
      | DRAM Die    |
      +-------------+
      | DRAM Die    |
      +-------------+
      | Base Logic  |
      +-------------+
            |
            v
      +-------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 가속기 요청 발생 | --> | 채널·bank 분산   | --> | 적층 메모리 병렬 접근 | --> | 넓은 I/O로 데이터 반환 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **가속기 요청 발생**: GPU나 NPU가 대량의 파라미터와 activation을 요구함
2. **채널과 bank 분산**: base logic die가 요청을 여러 채널로 나눠 병렬성을 확보함
3. **적층 메모리 병렬 접근**: DRAM 다이가 동시에 읽기와 쓰기를 수행함
4. **넓은 I/O로 데이터 반환**: 인터포저를 통해 프로세서로 대량 데이터를 빠르게 전달함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 고단 적층과 고속 동작이 겹치면 스택 내부 열이 누적되어 지속 성능과 신뢰성이 흔들릴 수 있음
   - 해결방안: 고성능 냉각과 열 분산 패키지 설계를 적용하고 junction temperature와 thermal throttling rate로 검증함
2. 문제: 스택 높이와 신호 속도가 올라갈수록 패키지 수율과 인터커넥트 불량 민감도가 커짐
   - 해결방안: known good die 선별과 공정 검증을 강화하고 package yield와 field failure rate로 검증함
3. 문제: 높은 대역폭을 제공해도 소프트웨어가 메모리 접근을 정렬하지 못하면 실효 이득이 제한될 수 있음
   - 해결방안: tensor 배치와 메모리 스케줄 최적화를 병행하고 bandwidth utilization과 accelerator idle ratio로 검증함

## Ⅶ. 적용 사례

- 대형 AI 학습 GPU는 HBM3E를 사용해 모델 데이터 공급 병목을 줄이고, bandwidth utilization과 accelerator idle ratio로 결과를 확인함
- 추론 전용 가속기는 더 큰 온패키지 용량을 활용해 오프로딩 빈도를 줄이고, tokens per second와 capacity overflow latency로 결과를 확인함
- HPC 연산 노드는 고대역폭 메모리로 sparse와 dense 계산을 가속하고, flops efficiency와 memory stall ratio로 결과를 확인함

## Ⅷ. 결론

HBM3E의 가치는 단순 세대 상승이 아니라 AI 가속기의 유휴 시간을 줄일 만큼 충분한 대역폭과 용량을 패키지 안에서 안정적으로 제공하는 데 있음.
