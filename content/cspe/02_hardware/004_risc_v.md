# 📖 【암기용】 개념 완전 이해

> 목적: RISC-V가 003의 RISC 철학을 실제로 어떻게 오픈소스 ISA로 구현했는지, 명령어 구성·인코딩까지 처음 봐도 완벽히 이해하게 만든다.

## 한눈에
- **개요**: **RISC-V**는 003에서 다루는 **RISC(Reduced Instruction Set Computer)** 설계 철학을 따르는 **오픈소스·로열티 프리 명령어 집합 구조(Open ISA)**다.
- **왜 필요한가**: ARM·x86 같은 기존 ISA를 쓰려면 막대한 라이선스 비용을 내야 하고 명령어를 마음대로 확장할 수도 없었다. IoT·AI 가속기처럼 "이 워크로드에만 맞는 맞춤형 칩"을 싸게 만들고 싶은 수요가 이 장벽과 부딪히면서 개방형 ISA가 필요해졌다.
- **핵심 직관**: ARM이 로열티를 내야 하는 프랜차이즈 레시피라면, RISC-V는 누구나 가져다 쓰고 자기만의 재료(커스텀 명령어)를 더해도 되는 오픈소스 레시피다.

## 핵심 용어 정리

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| RISC(상위 개념) | 명령어를 단순·고정 길이로 설계하는 ISA 철학(003 참조) — RISC-V가 실제로 구현한 대상 | 리모컨 설계 철학 |
| ISA(상위 개념) | 하드웨어가 이해하는 명령어의 종류·형식 전체 규약 | 리모컨 버튼 기능표 |
| Base ISA(RV32I/RV64I) | 시스템 구동에 필요한 최소 필수 정수 명령어 집합 — 분기·정수 연산·Load/Store만 포함 | 자동차의 기본 뼈대(섀시) |
| Standard Extension | 표준 재단이 정의한 선택적 기능 모듈(M·A·F·D·C·V 등) | 옵션으로 다는 순정 부품 |
| Custom Extension | 설계자가 특정 목적을 위해 독자로 정의하는 명령어 | 차주가 직접 개조한 부품 |
| x0 레지스터 | 항상 0을 반환하고, 쓰기는 버려지는 하드와이어드 0번 레지스터 | 아무리 넣어도 항상 비어 있는 상자 |
| 명령어 인코딩 포맷(R/I/S/B/U/J-type) | 32비트 고정 길이 명령어를 필드별로 나누는 6가지 형식 | 양식 종류별로 칸이 정해진 서식지 |
| 특권 모드(M/S/U) | Machine/Supervisor/User 3단계 실행 권한 계층 — OS·하이퍼바이저 지원용 | 관리자/부서장/사원의 권한 등급 |
| C 확장(Compressed) | 자주 쓰는 명령어를 16비트로 압축해 코드 크기를 줄이는 확장 | 자주 쓰는 문구를 줄임말로 쓰는 것 |

## 깊이 이해

### 이름의 유래와 등장 배경
- UC 버클리는 1980년대부터 RISC 계열 ISA를 설계해왔다(RISC-I, RISC-II, SOAR, SPUR에 이은 다섯 번째 설계) — "V"는 영어 "5(five)"가 아니라 로마 숫자 5를 뜻한다.
- 2010년 Krste Asanović 교수 연구팀이 시작했고, 기존 ARM·x86처럼 명령어 추가에 로열티나 특허 승인이 필요 없는 완전 개방형 ISA로 설계해, "하드웨어계의 리눅스"를 지향했다.

### Base + Extension 조립식 구조 — 표기명 해독
- RV32I는 정수 연산·분기·Load/Store만 담은 최소 뼈대로, 공식 스펙 기준 47개의 명령어로 구성된다 — CPU가 이 Base ISA만 구현해도 최소한의 소프트웨어(부트로더 수준)를 돌릴 수 있다.
- 표기명은 Base + Extension 알파벳을 이어 붙인 것이다. 예: **RV32IMAC** = RV32I(32비트 기본) + M(정수 곱셈/나눗셈) + A(원자적 연산, 락 없는 동시성 제어) + C(16비트 압축 명령어).
- 흔히 M+A+F+D(단정도·배정도 부동소수점)를 묶어 "G"(General)로 줄여 쓴다 — 예: RV64GC = RV64I+M+A+F+D+C.

### 레지스터 구조와 x0의 설계 트릭 — 수치로 이해
- RISC-V는 범용 레지스터 32개(x0~x31)를 갖는다(003에서 다룬 RISC 원칙대로 레지스터가 많아 메모리 접근을 최소화). 이 중 x0는 하드웨어적으로 항상 0을 반환하고 쓰기는 버려진다.
- 이 x0 덕분에 별도의 NOP(아무 동작 안 함) 명령어 없이 `ADDI x0, x0, 0`(0에 0을 더해 0에 저장)으로 NOP을 표현할 수 있고, `ADD x3, x1, x0`(x1+0)만으로 레지스터 복사(MOVE)를 표현할 수 있다 — 명령어 종류를 늘리지 않고 x0 하나로 여러 의사(疑似) 명령어를 만드는 RISC-V 특유의 설계다.

### 32비트 고정 인코딩 — 워크드 예제
- 모든 표준 RISC-V 명령어는 32비트이며, 하위 7비트(비트 6:0)가 opcode다. 예를 들어 R-type(레지스터-레지스터 연산) 포맷은 `funct7(7비트) | rs2(5비트) | rs1(5비트) | funct3(3비트) | rd(5비트) | opcode(7비트)`로 32비트를 채운다.
- 이렇게 필드 위치가 모든 R-type 명령어에서 동일해, 디코더가 명령어 종류를 먼저 안 따져도 각 필드를 병렬로 바로 잘라낼 수 있다 — CISC(x86)의 가변 길이 명령어가 "어디까지가 이 명령어인지"부터 순차적으로 알아내야 하는 것과 대비된다(003 참조).

### 압축 확장(C)의 효과 — 코드 크기
- C 확장은 자주 쓰이는 명령어(스택 포인터 사용, 소수 레지스터 사용 등)를 16비트로 압축해 표현한다. 32비트 명령어와 16비트 압축 명령어가 섞여도 디코더가 처음 2비트로 구분할 수 있게 설계돼 있다.
- 압축 확장을 켜면(RV32IC) 실행 파일의 코드 크기가 순수 32비트 고정 명령어만 쓸 때보다 약 25~30% 줄어든다고 알려져 있다 — RISC가 포기했던 코드 밀도를 다시 회복하는 절충 장치다.

### 실제 사례와 흔한 오해
- Western Digital은 SSD·HDD 컨트롤러 코어를 ARM에서 RISC-V로 전환해 코어당 로열티 지불을 없앴고, SiFive는 상용 RISC-V 코어 IP를 유료로 판매한다.
- **오해**: "RISC-V 코어는 공짜다" — 반만 맞다. ISA 스펙(문서·규칙)은 무료지만, 이를 검증된 실리콘으로 구현한 상용 코어 설계(IP)는 SiFive 등에서 유료로 판매한다. 직접 RTL을 설계해 만들면 로열티 없이 제작할 수 있다.

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: RISC-V는 UC 버클리에서 개발된 BSD 라이선스 기반의 개방형 명령어 집합 구조(Open ISA)로, 하드웨어 생태계의 민주화를 이끄는 표준이다.
> 2. **가치**: 불필요한 레거시 명령어를 제거한 40여 개의 베이스 모듈 위에, 벡터·부동소수점 등 확장을 모듈화하여 라이선스 비용 없이 도메인 특화 아키텍처(DSA)를 설계할 수 있다.
> 3. **판단 포인트**: RISC-V의 성공 여부는 단순히 무료라는 장점을 넘어, 소프트웨어 컴파일러 체인과 검증된 상용 IP 생태계(에코시스템)의 성숙도에 달려있다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |

## Ⅰ. 개요 및 필요성

- 정의: 라이선스 비용과 설계 제약 없이 누구나 사용, 수정, 배포 가능한 개방형 RISC 명령어 집합 구조
- 배경: ARM/x86의 독점적 고비용 라이선스와 폐쇄적 설계 규약으로 인한 특정 도메인(IoT, AI) 칩 개발의 장벽
- 필요성: 불필요한 레거시 명령어를 덜어내고, 도메인 특화 아키텍처(DSA)에 최적화된 맞춤형 커스텀 명령어 도입 필요

## Ⅱ. 구조 및 구성요소 (모듈형 아키텍처)

```text
[RISC-V 모듈형 명령어 구성 흐름도]
[Base Integer ISA] 필수 뼈대 (RV32I, 40여 개 명령어)
       |
       +-> [Standard Extension] 선택 블록 (M, A, F, D, V 등)
       |
       +-> [Custom Extension] 사용자 독자 명령어 (도메인 특화)
```

| 구성요소 | 핵심 역할 | 세부 하위 요소 / 특징 |
|:---|:---|:---|
| Base Integer ISA | 시스템 구동을 위한 최소 필수 명령어 집합 | RV32I(32비트), RV64I(64비트) / 분기, 정수, Load/Store |
| Standard Extension | 표준 재단에서 정의한 선택적 기능 모듈 | M(곱셈/나눗셈), A(원자적 연산), F/D(부동소수점), V(벡터) |
| Custom Extension | 설계자가 특정 목적을 위해 독자 정의한 명령어 | AI 행렬 연산, 암호화, IoT 최적화 가속 (라이선스 제약 없음) |

> 요약: RISC-V 칩셋 표기명(예: RV32IMAC)은 베이스 모듈과 추가된 표준 확장 모듈의 알파벳 조합으로 아키텍처 능력을 직관적으로 나타낸다.

## Ⅲ. 동작원리 및 흐름도

```text
[Custom Extension 기반 도메인 특화 칩(DSA) 설계 흐름도]
AI 워크로드 분석 -> 병목 연산 식별 (행렬 곱) -> 커스텀 명령어(Custom ISA) 정의
-> GCC/LLVM 컴파일러 수정 -> RISC-V RTL 설계 반영 -> NPU 통합 SoC 제작
```

| 단계 | 처리 주체 | 처리 내용 (생태계 워크플로우) |
|:---:|:---|:---|
| 1 | 프로파일링 | 타겟 애플리케이션(예: 딥러닝)의 연산 병목 프로파일링 및 최적 명령어 도출 |
| 2 | ISA 확장 | RISC-V 예약 공간에 도메인 특화 사용자 정의 명령어(Custom Extension) 할당 |
| 3 | 툴체인 수정 | 새로운 ISA를 지원하도록 오픈소스 컴파일러(GCC, LLVM) 백엔드 업데이트 |
| 4 | H/W 설계·검증 | Chisel/Verilog 기반 하드웨어 구현 및 오픈소스 검증 프레임워크로 RTL 검증 |

> 요약: 소프트웨어(LLVM)와 하드웨어(RTL) 양쪽을 자유롭게 수정 가능하여 애플리케이션에 완벽히 피팅된 SoC를 설계할 수 있다.

## Ⅳ. 심화 비교: RISC-V vs ARM

| 비교 축 | ARM 아키텍처 | RISC-V 아키텍처 | 선택 기준 |
|:---|:---|:---|:---|
| 라이선스 모델 | 고비용 상용 라이선스 (폐쇄적) | 완전 무료, BSD 라이선스 (개방형) | 초기 투자비 및 TCO 절감 |
| ISA 확장성 | 사용자 임의 명령어 추가 불가 | 사용자 커스텀 명령어 자유 추가 가능 | 도메인 특화(DSA) 최적화 여부 |
| 명령어 레거시 | 30년 누적으로 비대화된 명령어 셋 | 과거 레거시를 배제한 초경량 베이스 | 임베디드 폼팩터의 극단적 경량화 |
| 생태계 (Eco) | 모바일/AP 시장 압도적 점유 (성숙) | IoT 가속기 중심에서 차량/서버로 확장 중 | 서드파티 툴체인 및 상용 IP 검증도 |

> 요약: ARM은 안정된 툴체인과 성능이 필요한 스마트폰/서버 AP에, RISC-V는 맞춤형 가속기와 라이선스 자유도가 필수적인 IoT/칩렛에 적합하다.

## Ⅴ. 생태계 리스크 및 적용 판단

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 파편화 (Fragmentation) | 자유로운 커스텀 확장으로 인한 호환성 상실 우려 | RISC-V Foundation의 프로파일 표준화(RVA22 등) 준수 인증 | 표준 리눅스 부팅 호환성 |
| 소프트웨어 툴체인 부족 | ARM 대비 상용 디버거/컴파일러 성숙도 부족 | SiFive 등 선도기업 툴 및 오픈소스(LLVM) 기여 확대 | 커스텀 명령어 빌드 자동화율 |
| 상용 IP 검증 미흡 | 오픈소스 코어의 엣지 케이스 버그 위험성 | 상용 수준의 검증이 완료된 검증 IP(VIP) 및 코어 도입 | RTL 검증 커버리지 100% |

> 요약: 개방성으로 인한 "파편화"가 최대 리스크이므로, OS(리눅스) 레벨 호환성을 보장하는 베이스라인 프로파일 준수가 필수적이다.

**적용 방안 3개:**
1. IoT/엣지 디바이스 전환: 저장장치 컨트롤러(SSD), 스마트 워치 등 저전력 제어형 SoC에 ARM Cortex-M 대신 RISC-V 코어를 적용하여 라이선스 비용 제로화
2. AI 도메인 특화 가속기(DSA): 자율주행, 딥러닝 칩 내부의 마이크로 컨트롤러에 벡터(V) 확장과 텐서 커스텀 명령어를 결합한 RISC-V 탑재
3. 보안 엔클레이브 분리: CPU 주 코어 옆에 격리된 RISC-V 코어를 보안 루트 오브 트러스트(RoT) 프로세서로 배치하여 펌웨어 변조 방지 및 암호화 전담

**결론 (2줄):**
- 기술사 판단: RISC-V는 하드웨어 분야의 리눅스(Linux) 혁명을 이끌고 있으며, 초기 IoT 시장을 넘어 벡터 확장(RVV)을 통해 고성능 AI 및 데이터센터 시장으로 상승 진입하고 있다.
- 향후 방향: 앞으로는 반도체 미세공정 한계를 넘기 위해 여러 기능을 타일로 묶는 칩렛(Chiplet) 생태계와 결합하여, 다양한 벤더의 RISC-V 타일이 자유롭게 집적되는 방향으로 발전할 것이다.
