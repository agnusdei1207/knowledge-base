## Ⅰ. 개요
- **정의**: 로열티 없이 누구나 구현·확장할 수 있는 개방형 RISC 명령어 집합 아키텍처임
- **배경/필요성**: 상용 ISA의 라이선스 비용과 확장 제약이 칩 설계 진입장벽을 높이므로, 개방형 ISA가 필요함
- **비유**: x86·ARM이 프랜차이즈 식당이라면, RISC-V는 레시피가 공개된 오픈소스 요리책임

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 개방형 ISA의 의의와 생태계 이해 | 모듈식 확장(Base+Extension) 구조 | ISA 공개 ≠ 구현체 공개, 코어 설계는 별도 IP임을 구분 |

> 요약: 라이선스 비용 없는 모듈식 ISA로 칩 설계 진입장벽을 낮추는 것이 핵심임

## Ⅱ. 구성요소
```text
  +-------------- RISC-V ISA ---------------+
  |                                         |
  |  Base ISA (필수)                        |
  |  +------+  +------+  +------+  +------+ |
  |  | RV32I|  | RV64I|  |RV32E |  |RV128I| |
  |  +------+  +------+  +------+  +------+ |
  |                                         |
  |  Standard Extensions (선택)             |
  |  +---+ +---+ +---+ +---+ +---+ +---+   |
  |  | M | | A | | F | | D | | C | | V |   |
  |  +---+ +---+ +---+ +---+ +---+ +---+   |
  |                                         |
  |  Custom Extensions (사용자 정의)        |
  +------------------------------------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Base ISA | RV32I/RV64I 등 정수 연산 기본 명령어 47개로 구성된 필수 기반임 | 요리의 기본 레시피 |
| Standard Extension | M(곱셈), A(원자적), F/D(부동소수), C(압축), V(벡터) 등 공식 확장임 | 선택 토핑 메뉴 |
| Custom Extension | 특정 도메인(AI 가속, 암호 등)에 맞춰 사용자가 정의하는 비표준 확장임 | 시그니처 레시피 |
| 특권 모드 | Machine/Supervisor/User 3단계 실행 권한 계층임 | 건물 보안 등급(관리자/직원/방문객) |

> 요약: Base + 표준 확장 + 사용자 확장의 모듈 구조가 RISC-V 유연성의 근간임

## Ⅲ. 절차
```text
  ISA 기반 선택      확장 조합         코어 구현         검증/테이프아웃
  (Base Select)     (Ext Config)     (RTL Design)     (Verify/Tape-out)
    |                  |                |                  |
    +--요구사항 분석-->+--프로파일링--->+--시뮬레이션----->+
  RV32I/RV64I 결정  M,A,F,D,C,V 선택  오픈/상용 코어    FPGA/ASIC 양산
```
- 1단계: 대상 시스템의 비트 폭·용도에 따라 RV32I 또는 RV64I 등 Base ISA를 선택함
- 2단계: 워크로드를 프로파일링하여 필요한 표준 확장(M, F, V 등)을 조합함
- 3단계: 오픈소스 코어(BOOM, Rocket 등) 또는 상용 IP를 기반으로 RTL을 구현함
- 4단계: 시뮬레이션·FPGA 검증 후 ASIC 테이프아웃으로 칩을 양산함

> 요약: Base 선택 → 확장 조합 → 코어 구현 → 검증 순서로 칩 설계가 진행됨

## Ⅳ. 문제점
- [소프트웨어 생태계 미성숙]: 컴파일러·OS·라이브러리 최적화 부족 — x86/ARM 대비 바이너리 호환 소프트웨어가 제한적임
- [파편화 위험]: 무제한 커스텀 확장 — 벤더별 비표준 확장이 난립하면 바이너리 이식성이 훼손됨
- [고성능 코어 부재]: 상용 수준 OoO 코어 제한 — 서버·데스크톱급 싱글 스레드 성능이 ARM/x86에 미달함

> 요약: 생태계·파편화·고성능 코어 부족이 RISC-V 확산의 3대 과제임

## Ⅴ. 개선방안
1. 단기: 주요 리눅스 배포판·툴체인(GCC, LLVM)의 RISC-V 지원을 Tier-1으로 격상하여 생태계를 확충함
2. 중기: RISC-V International의 프로파일 표준(RVA23 등)을 통해 호환성 기준선을 정의하여 파편화를 억제함
3. 장기: 멀티코어 OoO 설계 IP를 공개·상용화하여 서버급 싱글 스레드 성능 격차를 축소함

> 요약: 생태계 강화 → 프로파일 표준화 → 고성능 코어 IP 확보 순으로 과제를 해소함

## Ⅵ. 전망
- 발전 방향: IoT·에지 AI 칩에서 RISC-V 채택이 가속되며, 데이터센터 진출 시도가 본격화됨
- 기술사적 판단: ISA 개방은 칩 설계 민주화를 의미하며, 반도체 공급망 다변화 전략과 맞물림
- 기술사 제언: RISC-V 도입 시 표준 프로파일 준수 여부와 장기 생태계 로드맵을 평가해야 함
