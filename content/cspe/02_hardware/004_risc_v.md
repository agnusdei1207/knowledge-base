## Ⅰ. 개요
- **정의**: 라이선스 비용 없이 사용·수정·확장 가능한 개방형 RISC 명령어 집합 아키텍처
- **배경/필요성**: 상용 ISA(x86, ARM)의 라이선스 비용과 설계 자유도 제한이 IoT·AI 가속기 등 다양한 도메인에서 걸림돌이 됨
- **비유**: x86/ARM이 프랜차이즈 가맹점(로열티 지불, 규격 준수)이라면, RISC-V는 오픈소스 레시피(자유 변형, 비용 무료)

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 개방형 ISA의 구조적 장점과 생태계 확장성 | 모듈러 확장(I+M/A/F/D/C) 구조, 라이선스 프리 | 기본 정수 명령어(RV32I/RV64I)와 확장의 구분을 명확히 해야 함 |

> 요약: RISC-V는 라이선스 프리·모듈러 확장 구조로 도메인별 맞춤 프로세서 설계를 가능하게 하는 개방형 ISA임

## Ⅱ. 구성요소
```text
[RISC-V 모듈러 구조]

Base ISA (필수)
  |-- RV32I / RV64I / RV128I (정수 연산, 고정 32비트 명령어)
  |
Extensions (선택)
  |-- M : 곱셈/나눗셈
  |-- A : 원자적 연산(Atomic)
  |-- F : 단정밀도 부동소수점
  |-- D : 배정밀도 부동소수점
  |-- C : 압축 명령어(16비트)
  |-- V : 벡터 연산
  |-- 커스텀 확장 : 도메인 특화 명령어
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Base ISA(RV32I/64I) | 정수 연산·분기·로드/스토어를 포함하는 최소 필수 명령어 세트 | 기본 블록 — 모든 건물의 토대 |
| M 확장 | 하드웨어 곱셈·나눗셈 지원으로 소프트웨어 에뮬레이션 대비 처리량 향상 | 전동 공구 추가 — 수작업 대비 속도 증가 |
| A 확장 | 멀티코어 환경에서 원자적 read-modify-write 연산 제공 | 공유 칠판에 잠금 마커를 붙여 동시 수정 방지 |
| C 확장 | 빈번 명령어를 16비트로 압축하여 코드 밀도 향상(003 코드 크기 문제 해결) | 자주 쓰는 단어를 약어로 줄임 |
| V 확장 | 가변 길이 벡터 레지스터로 데이터 병렬 처리 지원 | 한 번에 여러 접시를 나르는 트레이 |
| 커스텀 확장 | 사용자가 비표준 명령어를 예약 opcode 영역에 정의 | 레시피에 자기만의 비법 단계를 추가 |

> 요약: 필수 Base ISA 위에 도메인별 확장을 조합하여 최소 면적·최대 효율의 프로세서를 설계함

## Ⅲ. 절차
```text
요구분석 --> Base ISA 선택 --> 확장 조합 --> RTL 설계/검증 --> 칩 제조/배포
              (RV32I/64I)    (M,A,F,D,C,V)   (오픈소스 코어)
```
- 1단계: **요구분석** — 대상 도메인(IoT, AI, 서버)의 연산·전력·면적 요구사항을 정의함
- 2단계: **Base ISA·확장 선택** — RV32I 또는 RV64I를 기반으로 필요한 확장(M/A/F/D/C/V)을 조합함
- 3단계: **RTL 설계·검증** — 오픈소스 코어(BOOM, Rocket 등)를 활용하거나 자체 설계 후 시뮬레이션 검증 수행
- 4단계: **제조·배포** — 파운드리를 통해 칩을 제조하고, 소프트웨어 툴체인(GCC, LLVM)과 함께 배포함

> 요약: 요구분석→ISA 조합→설계 검증→제조의 흐름으로 도메인 맞춤 프로세서를 구현함

## Ⅳ. 문제점
- **소프트웨어 생태계 미성숙**: x86/ARM 대비 OS·라이브러리·드라이버 지원이 부족 — 범용 컴퓨팅 즉시 적용이 어려움
- **확장 파편화 위험**: 커스텀 확장 남용 시 바이너리 호환성 상실 — 서로 다른 RISC-V 칩 간 소프트웨어 이식이 불가해짐
- **고성능 구현 검증 부족**: 서버급 고클록 설계의 상용 검증 사례가 제한적 — 성능 예측 신뢰도가 낮음

> 요약: 생태계·호환성·고성능 검증의 세 가지 성숙도 과제가 RISC-V 확산의 주요 장벽임

## Ⅴ. 개선방안
1. **단기**: 주요 OS(Linux, Android) 포팅 강화와 툴체인 안정화 — 소프트웨어 생태계 진입 장벽 완화
2. **중기**: RISC-V International의 프로파일 표준(RVA23 등) 정의 — 확장 조합을 표준화하여 파편화 방지
3. **장기**: 대규모 SoC 레퍼런스 설계 공개와 벤치마크 축적 — 서버급 고성능 구현의 검증 기반 확보

> 요약: 생태계 확충·프로파일 표준화·레퍼런스 설계로 성숙도 과제를 단계적으로 해소함

## Ⅵ. 전망
- **발전 방향**: AI 가속기·자동차 MCU·위성 프로세서 등 도메인 특화 칩에서 채택이 가속되며, 서버 시장 진입도 진행 중
- **기술사적 판단**: 개방형 ISA는 벤더 종속 탈피와 공급망 다변화 측면에서 전략적 가치가 높음
- **기술사 제언**: RISC-V 도입 시 생태계 성숙도·호환성 프로파일·보안 확장(Crypto 등) 지원 여부를 사전 평가할 것을 권고함
