## 미리 알고가기

- RISC-V는 로열티 없는 개방형 ISA 표준임
- Base ISA와 표준 확장 모듈을 조합하는 구조임
- 하드웨어 자율성은 크지만 소프트웨어 생태계 성숙도가 선택 변수임

## Ⅰ. 개요

- **정의/개념**: RISC-V는 기본 정수 명령어 집합에 표준 확장을 모듈식으로 결합할 수 있도록 정의된 개방형 RISC ISA이며, 특정 벤더 종속 없이 프로세서를 설계할 수 있게 하는 표준 구조임
- **배경/필요성**: ISA의 라이선스 비용과 확장 제약을 줄이기 위해 개방형·모듈식 명령어 표준이 필요함

## Ⅱ. 특징

- 기본 ISA와 확장 모듈이 분리되어 설계 유연성이 큼
- 공개 표준이라 교육·연구·국산 SoC 검토에서 라이선스 부담이 작음
- 벡터·압축·원자성 등 확장을 구현 범위에 맞춰 단계적으로 채택함
- 상용 툴체인과 검증 자산의 성숙도는 도입 전 확인해야 할 조건임

## Ⅲ. 종류 및 비교

| 판단 기준 | RISC-V | ARM |
|:---|:---|:---|
| 라이선스 | 개방형 표준 | 벤더 라이선스 |
| 확장 유연성 | 모듈식 확장 높음 | 성숙한 표준 생태계 |
| 강점 | 자율 설계·비용 절감 | 검증된 IP·소프트웨어 |
| 한계 | 생태계 성숙도 편차 | 비용과 종속성 |

> 요약: RISC-V는 개방형 기본 ISA와 선택 확장으로 명령어 구성을 설계할 수 있지만 적합성 검증과 툴체인 준비가 필요함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Base ISA | RV32I와 RV64I 같은 최소 실행 규격으로 모든 구현의 공통 기반이 됨 |
| Standard Extension | M, A, F, D, C, V 등 기능 확장을 제공해 용도별 ISA 구성을 가능하게 함 |
| Privileged Spec | 예외 처리와 인터럽트와 권한 모드를 정의해 OS 구동 기반을 만듦 |
| Toolchain and Ecosystem | 컴파일러와 디버거와 OS 지원 수준이 실제 도입 가능성을 좌우함 |

```text
+-----------+     +------------------+     +-----------------+
| Base ISA  | --> | Standard Extension | --> | Privileged Spec |
+-----------+     +------------------+     +-----------------+
      |
      v
+----------------------+
| Toolchain/Ecosystem  |
+----------------------+
```

> 요약: RISC-V 도입 가능성은 Base ISA, 확장, 권한 명세, 툴체인 준비도가 함께 결정함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 기본 ISA 선택    | --> | 확장 모듈 선택    | --> | 권한/예외 설계   | --> | 툴체인 검증     |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **기본 ISA 선택**: RV32I 또는 RV64I를 선택함
2. **확장 모듈 선택**: 용도에 맞는 M/A/F/C/V 등을 조합함
3. **권한과 예외 설계**: OS 또는 RTOS 구동 규칙을 정함
4. **툴체인 검증**: 컴파일러와 디버거와 OS 지원을 확인함

> 요약: RISC-V 설계는 필요한 ISA 조합을 정한 뒤 권한 구조와 소프트웨어 지원을 검증하는 순서로 진행됨.

## Ⅵ. 실무 적용 및 유의점

1. 상용 SoC는 검증 자산과 구현 품질 편차가 리스크이므로 compliance test와 formal verification을 병행하고 conformance pass rate와 silicon bug count로 검증함
2. 확장 조합이 많거나 신규 플랫폼을 포팅할 때는 profile 기반 표준 구성과 toolchain readiness를 먼저 평가하고 binary compatibility rate, porting lead time, debug turnaround time으로 확인함

## Ⅶ. 결론

- RISC-V의 판단 기준은 무료 ISA 자체보다 필요한 기능만 조합해 자율적으로 설계하되 검증과 생태계 책임도 함께 감당할 수 있는지에 있음

## 작성 근거(검토용)

- RISC-V의 판단 기준을 무료 여부가 아니라 base ISA, 확장, privileged spec, toolchain 준비도로 설정함
- 범위가 넓은 표현은 라이선스 부담, 적합성 검증, 포팅 시간처럼 확인 가능한 항목으로 구체화함
- 결론은 오픈 ISA의 장점과 구현 책임이 동시에 존재한다는 구조로 정리함
