# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: RISC-V는 로열티 없이 누구나 자유롭게 사용·구현·확장할 수 있는 **개방형(Open) 표준 ISA**로, 최소한의 **기본 명령어 집합(Base ISA)**에 필요한 **확장(Extension)** 모듈만 골라 조립하는 **모듈러(modular)** 구조가 핵심이다.
- **왜 필요한가**: (003 RISC/CISC 참조) 기존 ARM·x86은 상용 라이선스라 로열티 부담과 명령어 커스터마이징 제약이 있어, IoT 컨트롤러부터 AI 가속기까지 도메인별로 명령어를 자유롭게 정의·검증할 수 있는 개방·중립 표준이 필요했다.
- **핵심 직관**: 레고처럼 정수 연산이라는 최소 받침판(Base)만 고정해 두고, 곱셈기·부동소수점·벡터 같은 필요한 블록(Extension)만 끼워 맞춰 그 칩에 딱 맞는 명령어 세트를 만든다.

## 핵심 용어 정리 (내부에 등장하는 것들)
RISC 일반론(고정 길이·Load-Store)은 003이 다뤘으므로, 여기서는 RISC-V만의 '개방·모듈러' 용어를 세운다. 맨 위 두 줄이 상위 핵심 키워드다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| **개방형 ISA (상위 키워드)** | 특허·로열티 없이 공개된 명령어 표준 명세, 특정 기업 소유 아님 | 사용료 없는 공용 도로 표준 |
| **모듈러 확장 (상위 키워드)** | 기본셋 + 필요한 확장만 조립하는 설계 | 레고 받침판 + 선택 블록 |
| **Base ISA (RV32I/RV64I)** | 반드시 있어야 하는 정수 명령 최소셋(RV32I는 명령 47개), 32비트/64비트 주소 폭 구분 | 문법의 기초 뼈대(주어·동사) |
| **확장(Extension) M/A/F/D/C/V** | 곱셈·나눗셈(M), 원자연산(A), 단정도 부동소수(F), 배정도(D), 압축(C), 벡터(V) | 필요할 때 끼우는 부가 기능 팩 |
| **G (General)** | 범용 조합 = IMAFD + Zicsr/Zifencei를 묶은 약칭(RV64GC = G+C) | 자주 쓰는 세트를 묶은 '기본 패키지' |
| **프로즌(frozen) 기본셋** | 한번 비준된 Base·확장 스펙은 영구 동결해 하위 호환 보장 | 한번 정한 표준 규격은 안 바꿈 |
| **커스텀 opcode 공간** | 표준이 비워 둔 명령 코드 영역, 벤더가 자체 명령 정의 가능 | 공식 서식의 '기타' 빈칸 |
| **특권 모드 (M/S/U)** | Machine(펌웨어)·Supervisor(OS)·User(앱)의 3단 실행 권한 계층 | 관리자·운영자·일반사용자 등급 |
| **RISC-V International** | 표준을 관리하는 비영리 국제 재단(스위스 소재), 회원 합의로 스펙 비준 | 표준을 중립 관리하는 협회 |
| **소프트 코어 / 하드 코어** | HDL로 배포돼 FPGA에 올리는 구현 vs 실리콘으로 굳힌 구현 | 설계도 배포 vs 완제품 |

## 깊이 이해
- **배경·문제의식**: RISC-V는 2010년 UC 버클리에서 교육·연구용으로 시작됐다. 당시 상용 ISA(ARM·x86)는 라이선스 계약·NDA·건당 로열티가 필요해, 대학이 자유롭게 프로세서를 만들어 논문·수업에 쓰기 어려웠다. "명령어 집합만큼은 특정 회사가 소유하지 않는 개방 표준이어야 한다"는 문제의식에서 출발해, TCP/IP·리눅스처럼 ISA를 공공 인프라로 만들자는 움직임으로 커졌다.
- **작동 원리 (어떻게+왜)**:
  - **Base + Extension 분리**: 반드시 있어야 하는 것은 정수 연산 최소셋(RV32I) 하나뿐이다. 곱셈이 필요하면 M, 부동소수점이 필요하면 F/D, 코드 크기를 줄이려면 압축 명령 C, AI·과학연산이면 벡터 V를 '추가'한다. 그래서 초소형 MCU는 RV32IMC처럼 가볍게, 서버는 RV64GC처럼 풍부하게 같은 표준 위에서 조립된다.
  - **왜 이렇게 하나**: 안 쓰는 명령어까지 다 넣으면 디코더·게이트가 낭비된다. 필요한 확장만 넣으면 IoT는 최소 실리콘으로, 가속기는 도메인 명령으로 최적화된다. 표준이 커스텀 opcode 영역을 비워 둬, 벤더는 표준을 깨지 않고 자체 명령(예: 암호·DSP 가속)을 그 빈칸에 정의한다.
  - **프로즌 원칙**: 한번 비준된 스펙은 동결한다. 그래야 오늘 컴파일한 바이너리가 미래 코어에서도 돈다 — 개방형인데도 파편화를 막는 장치다.
- **비유**: 스마트폰 앱을 표준 OS 위에 골라 까는 것과 같다. OS(Base ISA)는 공통이고, 카메라 앱(F 확장)·게임(V 확장)은 필요한 기기만 설치한다. 앱스토어 사용료(로열티)가 없고, 개발사가 자체 앱(커스텀 명령)도 올릴 수 있다는 점이 다르다.
- **구체 예시**: RV32I 기본 정수 ISA는 명령이 47개뿐이라 교재 한 장에 다 들어간다(x86은 수천 개). 실제 채택으로 SiFive의 응용 코어, 웨스턴디지털의 SweRV(스토리지 컨트롤러), 구글·NVIDIA가 관리용 마이크로컨트롤러에 RISC-V를 쓴다. 유럽·인도는 특정국 ISA 의존을 줄이려는 설계 주권(sovereignty) 목적으로도 채택한다.
- **흔한 오해·주의점**: "RISC-V = 오픈소스 CPU"가 아니다. RISC-V는 **명령어 표준(설계 규약)만 개방**한 것이고, 그것을 구현한 실제 칩은 SiFive처럼 상용·비공개일 수 있다. 리눅스가 무료여도 특정 배포판·서버는 유료인 것과 같다. 또 개방형이라 성능이 낮은 게 아니라, 서버·AI용 고성능 코어도 활발히 개발 중이다.

## 연결 개념
- **003. ISA RISC/CISC**: RISC-V는 RISC 철학의 개방형 구현체 — 003이 '왜 RISC인가'를, 004가 '개방·모듈러라는 차별점'을 담당.
- **048/049. FPGA·ASIC 가속기**: 커스텀 확장으로 도메인 특화 명령을 얹기 좋은 대상.
- **076. TrustZone / 특권 모드**: RISC-V의 M/S/U 3단 권한 모델은 보안 격리의 하드웨어 토대.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: RISC-V는 특정 기업이 소유하지 않는 개방형 표준 ISA로, 정수 Base에 M/A/F/D/C/V 확장을 조립하는 모듈러 구조임
> 2. **가치**: 로열티 제거와 커스텀 opcode 개방으로 IoT부터 AI 가속기까지 도메인 특화 명령을 자유 정의, 프로즌 원칙으로 파편화 방지
> 3. **판단 포인트**: 성숙한 생태계·툴체인이 강점인 ARM 대비, RISC-V는 라이선스 비용·설계 주권이 필요한 커스텀 SoC에서 우위임

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 개방형·모듈러 ISA 구조 이해 확인 | Base ISA + 확장(Extension) 조립, 커스텀 opcode 개방 | 단순 "무료 RISC"로 축약, 모듈성 누락 |
| 상용 ISA 대비 도입 가치 판단 확인 | 로열티 제거, 설계 주권, 도메인 특화 명령 | 오픈소스 CPU와 오픈 표준 ISA 혼동 |
| 개방형의 파편화 리스크 관리 이해 | 프로즌 기본셋, 프로파일 표준화로 호환성 확보 | 개방=자유라는 이유로 호환성 위험 무시 |

> 요약: 모듈러 구조와 개방성이라는 차별점을 세우고, 로열티·주권 가치와 파편화 관리 방안까지 연결해야 함.

## Ⅰ. 개요 및 필요성

- 개요: 로열티 없이 확장 가능한 개방형 표준 ISA로, 정수 Base에 필요한 확장만 조립하는 모듈러 명령어 집합임
- 위치: (003 RISC 철학의 개방형 구현) 003이 정립한 고정 길이·Load-Store RISC 원리를 특정 기업 소유가 아닌 공용 표준으로 개방한 형태임
- 필요성: 상용 ISA의 건당 로열티와 커스터마이징 제약을 제거해, 도메인별로 명령어를 자체 정의할 개방·중립 표준 확보가 필요함

## Ⅱ. 구조 및 구성요소

선형 구조도 (조립 구조):

    Base ISA (RV32I/RV64I 정수 최소셋, 프로즌) -> 표준 확장 선택(M·A·F·D·C·V) -> 커스텀 opcode 확장(벤더 자체 명령)
                                                            / 특권 모드 계층: M(펌웨어) -> S(OS) -> U(앱)

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Base ISA (RV32I/64I) | 반드시 포함하는 정수 명령 최소셋 | RV32I는 47개 명령, 영구 동결로 하위 호환 보장 |
| 표준 확장(M/A/F/D/C/V) | 곱셈·원자연산·부동소수·압축·벡터 등 선택 기능 | RV64GC 등 조합 약칭, 안 쓰면 게이트 절감 |
| 커스텀 opcode 공간 | 표준이 비운 코드 영역에 벤더 자체 명령 정의 | 표준 불변 유지하며 도메인 특화 가능 |
| 특권 모드(M/S/U) | 펌웨어·OS·앱의 3단 실행 권한 격리 | 보안·가상화의 하드웨어 토대 |

> 요약: 동결된 정수 Base 위에 표준·커스텀 확장을 얹고 M/S/U 권한으로 격리하는 조립형 구조임.

## Ⅲ. 동작원리 및 흐름도

선형 흐름도:

    타깃 도메인 정의 -> Base+확장 프로파일 선택 -> (필요시)커스텀 명령 정의 -> 툴체인 컴파일 -> 코어 구현·검증

1. [프로파일 선택]: IoT는 RV32IMC, 서버·AI는 RV64GCV처럼 도메인에 맞는 Base와 확장 조합을 확정함
2. [커스텀 정의]: 표준으로 부족한 가속 연산은 비워 둔 opcode 공간에 자체 명령을 추가해 표준 호환을 유지함
3. [컴파일]: GCC·LLVM 등 개방 툴체인이 선택한 확장에 맞춰 바이너리를 생성함
4. [구현·검증]: 소프트 코어로 FPGA 검증 후 실리콘화하며, 프로즌 스펙 준수로 미래 호환성을 확보함

> 요약: 도메인에 맞춰 확장을 고르고 커스텀 명령을 더한 뒤, 표준 툴체인으로 컴파일해 파편화 없이 구현함.

## Ⅳ. 특징

- 로열티 제로: 상용 ISA의 건당 라이선스·로열티가 없어 대량 출하 시 단가·설계 비용을 절감함
- 모듈러 확장성: 안 쓰는 명령을 빼 IoT는 최소 실리콘으로, AI는 벡터 확장으로 도메인 최적화가 가능함
- 설계 주권: 특정 기업·국가에 종속되지 않는 중립 표준이라 공급망·규제 리스크에 강함
- 커스텀 명령 개방: 표준을 깨지 않고 비워 둔 opcode에 자체 가속 명령을 정의할 수 있음

## Ⅴ. 심화 비교 및 적용 판단

RISC-V와 상용 RISC 대표인 ARM은 둘 다 RISC이지만 '개방성·라이선스·커스터마이징' 축에서 갈리므로 대조함.

| 구분 | RISC-V | ARM |
|:---|:---|:---|
| 라이선스 | 개방 표준, 로열티 없음 | 상용 라이선스 + 건당 로열티 |
| 명령어 커스터마이징 | 커스텀 opcode로 자유 정의 | 표준 준수 강제, 커스텀 제약(고가 라이선스만 일부) |
| 생태계 성숙도 | 성장 중(툴·SW·검증 IP 상대 부족) | 성숙(방대한 툴체인·소프트웨어·레퍼런스) |
| 소유·거버넌스 | RISC-V International 중립 관리 | Arm社 단일 소유 |

> 요약: 성숙한 생태계·즉시 양산이 필요하면 ARM, 로열티 제거·명령어 커스터마이징·설계 주권이 핵심이면 RISC-V를 선택함.

**리스크·대응:**
- 생태계 파편화: 확장 조합이 제각각이면 SW 호환성 저하 → RVA 프로파일 표준으로 확장 조합을 등급화(지표: 표준 프로파일 준수율)
- 툴·검증 IP 부족: 상용 대비 성숙도 격차로 개발 지연 → LLVM·GCC 업스트림 기여, 상용 검증 IP 확보(지표: 컴파일러 최적화 벤치 격차 %)

**점검 지표:**
- 성능: 동일 워크로드 대비 IPC·전성비 — SPEC·EEMBC 벤치 실측
- 호환: 표준 프로파일 준수 여부 — RISC-V compliance 테스트 통과율

## Ⅵ. 실무 적용 및 결론

**적용 방안:**
1. 도메인 특화 가속기 설계: AI·스토리지 컨트롤러에 커스텀 벡터·암호 명령을 얹어 전용 ASIC의 로열티·면적 비용을 절감함
2. 공급망 주권 확보: 특정 벤더 ISA 종속을 피해야 하는 공공·국방·산업 SoC에 중립 표준으로 채택함
3. 엣지 MCU 최소화: RV32IMC처럼 최소 확장만 조립해 저전력 IoT 컨트롤러의 게이트·전력을 최소화함

**결론:**
- 기술사 판단: RISC-V의 본질 가치는 '무료'가 아니라 모듈성과 커스텀 개방으로, 도메인 특화 시대에 명령어를 자산화할 수 있다는 점임
- 향후 방향: 프로파일 표준화와 툴체인 성숙으로 서버·AI 영역까지 확산되며, 상용 ISA와 성능이 아닌 개방·커스터마이징 축에서 경쟁이 심화될 전망임
