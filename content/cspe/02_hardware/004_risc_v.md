## 미리 알고가기

- Base ISA: 프로세서 구현이 반드시 갖춰야 하는 최소 정수 명령어 집합임
- 표준 확장(M, A, F, D, C, V): 곱셈·나눗셈, 원자 연산, 부동소수점, 압축 명령, 벡터 연산처럼 용도별로 선택 추가하는 명령어 그룹임
- 권한 명세(Privileged Specification): 예외 처리·인터럽트·권한 모드를 정의해 운영체제 구동 기반을 규정하는 규격임
- ISA 프로파일: 특정 확장 조합을 표준으로 묶어 구현 간 호환 범위를 정하는 구성 단위임
- ABI(Application Binary Interface): 레지스터 사용 규칙과 함수 호출 규약을 정의해 컴파일된 바이너리 간 호환을 보장하는 인터페이스임
- 적합성 시험(Conformance Test): 구현체가 ISA 명세와 일치하는지 표준 테스트 스위트로 검증하는 절차임

## 작성 근거(검토용)

- RISC-V 판단 기준을 무료 여부가 아니라 Base ISA·표준 확장·권한 명세·프로파일·툴체인 준비도로 설정함
- RISC-V와 ARM을 라이선스·확장 방식, 호환 단위, 도입·생태계 리스크로 비교함
- 개방형 ISA의 설계 자율성과 구현 조직의 적합성 검증 책임을 함께 정리함

## Ⅰ. 개요

- **정의/개념**: RISC-V는 기본 정수 명령어 집합에 표준 확장을 조합해 프로세서를 구현하는 개방형 RISC ISA임
- **배경/필요성**: ISA의 라이선스 비용과 확장 제약을 줄이기 위해 개방형·모듈식 명령어 표준이 필요함

### 쉽게 이해하기 (학습용)
- 기본 레시피(Base ISA)에 원하는 토핑(확장)만 얹어 요리를 완성하는 오픈소스 레시피북과 같으며, 누구나 로열티 없이 가져다 씀

## Ⅱ. 특징

- 기본 ISA와 확장 모듈이 분리되어 구현할 명령어 범위를 선택할 수 있음
- 공개 표준을 사용하므로 ISA 사용료 없이 프로세서 구현을 검토할 수 있음
- 벡터·압축·원자성 등 확장을 구현 범위에 맞춰 단계적으로 채택함
- 상용 툴체인과 검증 자산의 성숙도는 도입 전 확인해야 할 조건임

### 쉽게 이해하기 (학습용)
- 레고 기본 블록에 필요한 세트만 골라 조립하듯 확장 범위를 선택하지만, 완성품을 뒷받침할 조립 설명서(툴체인)가 충분한지는 따로 확인해야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | RISC-V | ARM |
|:---|:---|:---|
| 라이선스·확장 방식 | 개방형 표준, Base ISA에 표준 확장을 조합 | 벤더 라이선스, 아키텍처 버전과 벤더 IP 범위에서 확장 |
| 호환 단위 | ISA 프로파일·확장 조합을 맞춰야 함 | 아키텍처 프로파일과 ABI를 맞춰야 함 |
| 도입·생태계 리스크 | 구현체별 검증 자산과 툴체인 지원을 도입 조직이 확인해야 함 | 벤더 IP·도구·운영체제 지원 범위와 라이선스 조건을 관리해야 함 |

> 요약: RISC-V는 개방형 기본 ISA와 선택 확장으로 명령어 구성을 설계할 수 있지만 적합성 검증과 툴체인 준비가 필요함.

### 쉽게 이해하기 (학습용)
- RISC-V는 오픈 레시피를 각자 조합해 쓰고 ARM은 정해진 프랜차이즈 레시피를 사용료 내고 쓰는 것과 같아, 재료(확장) 조합이 다르면 같은 이름이어도 서로 호환되지 않을 수 있음

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 기본 ISA | RV32I와 RV64I 같은 최소 실행 규격으로 구현의 공통 기반이 됨 |
| 표준 확장 | M, A, F, D, C, V 등 기능 확장을 제공해 용도별 ISA 구성을 지원함 |
| 권한 명세 | 예외 처리·인터럽트·권한 모드를 정의해 운영체제 구동 기반을 제공함 |
| 툴체인·생태계 | 컴파일러·디버거·운영체제의 지원 범위가 도입 가능성을 결정함 |

```text
+-----------+     +------------------+     +-----------------+
| 기본 ISA    | --> | 표준 확장             | --> | 권한 명세          |
+-----------+     +------------------+     +-----------------+
      |
      v
+----------------------+
| 툴체인·생태계          |
+----------------------+
```

> 요약: RISC-V 도입 가능성은 Base ISA, 확장, 권한 명세, 툴체인 준비도가 함께 결정함.

### 쉽게 이해하기 (학습용)
- 뼈대(기본 ISA)에 기능(표준 확장)을 붙이고 관리자 권한(권한 명세)을 정한 뒤, 이를 다룰 도구 상자(툴체인)가 갖춰져야 실제로 조립·운전할 수 있음

## Ⅵ. 실무 사례

1. 상용 RISC-V SoC는 구현체의 표준 준수 여부를 확인하기 위해 적합성 시험과 형식 검증을 수행하고, 적합성 시험 통과율과 실리콘 결함 건수로 검증함
2. RISC-V 운영체제 플랫폼은 확장 조합 차이로 생기는 호환 문제를 줄이기 위해 표준 프로파일을 적용하고, 바이너리 호환률과 포팅 소요시간으로 검증함

### 쉽게 이해하기 (학습용)
- 새로 만든 부품이 표준 규격에 맞는지 검사소에서 검증받고, 여러 제조사 부품이 서로 맞물리도록 정해진 규격(프로파일)대로 만드는 것과 같음

## Ⅶ. 결론

- RISC-V는 필요한 확장 조합과 프로파일을 정하고 적합성 검증·툴체인·운영체제 지원이 확보된 경우 선택함
- 검증 자산과 상용 툴체인이 부족한 초기 도입 단계에서는 표준 프로파일 준수와 적합성 시험 통과율부터 확인하고, 미달하면 성숙한 ARM 생태계와 병행 검토해야 함

### 쉽게 이해하기 (학습용)
- 필요한 옵션(확장)을 고르고 그 조합이 인증받았는지, 다룰 도구와 운영 지원이 준비됐는지 확인한 뒤 오픈 레시피를 채택하는 것과 같음
