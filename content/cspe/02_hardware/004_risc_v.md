# 📖 【암기용】 개념 완전 이해

> 목적: RISC-V를 처음 봐도 왜 "오픈소스 CPU 설계도"라 불리는지, 확장 명령어 체계가 어떻게 조립되는지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: UC Berkeley에서 시작된 로열티 프리(royalty-free) 오픈 ISA로, 기본 정수 명령어 집합에 필요한 확장을 모듈처럼 조합해 프로세서를 설계할 수 있다.
- **왜 필요한가**: ARM·x86은 라이선스 비용과 사용 제약이 있어 커스텀 반도체 설계가 어려운데, RISC-V는 사양이 공개되어 있어 라이선스 없이 코어를 설계·수정할 수 있다.
- **핵심 직관**: 레고 블록처럼 "기본 세트(정수 연산)"에 "확장 블록(곱셈, 부동소수점, 벡터 등)"을 필요한 만큼만 끼워 맞추는 명령어 집합이다.

## 깊이 이해
- **배경·문제의식**: 2010년 UC Berkeley의 Krste Asanović 연구팀이 교육·연구용으로 설계를 시작했고, 이후 RISC-V International(스위스 소재 비영리 단체)이 표준을 관리하며 로열티 없이 누구나 구현할 수 있도록 사양을 공개했다.
- 기존 ARM은 코어 설계나 아키텍처 라이선스에 비용이 발생하고 명령어 집합을 자유롭게 변형하기 어려운데, RISC-V는 사양 자체가 오픈소스라 커스텀 명령어 확장과 자체 코어 설계가 가능하다.
- **작동 원리 — 기본 ISA**: 기본 정수 명령어 집합은 RV32I(32비트), RV64I(64비트), RV128I(128비트)로 나뉘며 각각 32개의 정수 레지스터(x0~x31)를 가진다.
- x0 레지스터는 항상 값 0으로 하드와이어드되어 있어 별도의 zero 레지스터 전용 명령어 없이 상수 0 표현이나 no-op 구현에 활용된다.
- **작동 원리 — 확장 명령어**: M 확장은 정수 곱셈·나눗셈, A 확장은 원자적 연산(atomic read-modify-write), F/D 확장은 각각 단정도·배정도 부동소수점, C 확장은 16비트 압축 명령어를 추가한다.
- G는 IMAFD(정수+곱셈+원자+단정도+배정도)를 묶어 부르는 축약 표기이며, V 확장(2021년 표준 승인)은 벡터 연산을, B 확장은 비트 조작 명령어를 추가한다.
- 명령어 인코딩은 기본적으로 32비트 고정 길이이지만, C 확장을 적용하면 16비트 압축 명령어와 32비트 명령어가 혼합되어 코드 크기를 줄인다.
- **작동 원리 — 특권 모드**: RISC-V 특권 아키텍처는 M-모드(Machine, 필수), S-모드(Supervisor, OS 커널용), U-모드(User, 응용 프로그램용) 3단계를 기본으로 정의하고, 가상화가 필요하면 선택적인 H 확장(Hypervisor)을 추가한다.
- **비유**: 기본 정수 명령어는 "필수 공구함"이고, M·A·F·D·V 확장은 필요할 때만 추가하는 "옵션 공구"이며, 압축 확장(C)은 같은 공구를 더 작은 케이스에 담는 것과 같다.
- **구체 예시**: SiFive의 임베디드 코어는 RV32IMC(정수+곱셈나눗셈+압축)를 조합해 코드 크기와 면적을 줄이고, 서버급 코어는 RV64GC(정수+곱셈+원자+부동소수점+압축)를 조합해 범용 연산 능력을 확보하는 식으로 워크로드에 맞춰 확장을 선택한다.
- **흔한 오해·주의점**: "RISC-V는 특정 회사의 프로세서 제품명"이 아니다. RISC-V는 사양(ISA)이며, 이를 구현한 실제 코어는 SiFive, Western Digital, Alibaba(XuanTie) 등 여러 업체가 각자 설계한다.
- "오픈소스이므로 무조건 저렴하다"도 성립하지 않는다. ISA 사양은 무료이지만 실제 코어 설계·검증·툴체인 구축에는 별도 비용과 인력이 필요하다.

## 연결 개념
- 명령어 집합 RISC vs CISC — RISC-V는 RISC 설계 철학을 오픈소스로 구현한 사례
- ARM 아키텍처 — 라이선스 기반 RISC ISA로 RISC-V와 경쟁·비교 대상
- SoC 시스템온칩 — RISC-V 코어가 커스텀 SoC에 내장되는 대표 적용처
- FPGA/ASIC AI 가속 — RISC-V 제어 코어와 결합한 온디바이스 AI 칩 설계 사례

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: RISC-V를 "오픈소스"라는 단어로만 답하지 않고, 기본 ISA·확장 모듈·특권 모드 구조와 ARM 대비 선택 기준을 함께 제시한다. (127회 기출 대응)

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: RISC-V는 RV32I/RV64I/RV128I 기본 정수 명령어에 M·A·F·D·C·V 등 확장을 모듈식으로 조합하는 로열티 프리 오픈 ISA다.
> 2. **가치**: 라이선스 비용 없이 명령어 확장과 커스텀 코어 설계가 가능해 반도체 주권 확보와 도메인 특화 가속기 설계에 유리하다.
> 3. **판단 포인트**: 커스텀 명령어·라이선스 자유가 필요하면 RISC-V, 성숙한 생태계·소프트웨어 자산이 우선이면 ARM을 선택 기준으로 삼는다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 오픈 ISA 구조 이해 확인 | 기본 ISA(RV32I/RV64I)와 확장(M/A/F/D/C/V) 조합 방식 | "오픈소스 CPU"라는 표현만 쓰고 명령어 구조 누락 |
| 특권 모드·시스템 설계 이해 확인 | M/S/U 3단계 특권 모드와 선택적 H 확장 | 특권 모드 없이 명령어 확장만 설명 |
| ARM 대비 선택 기준 판단 확인 | 라이선스·커스텀 확장 자유 vs 생태계 성숙도 | RISC-V가 무조건 우월하다는 절대화된 서술 |

> 요약: 이 문제는 RISC-V를 오픈소스 구호로 답하지 않고 모듈형 ISA 구조와 ARM 대비 선택 기준을 요구한다.

## Ⅰ. 개요 및 필요성

- 개요: 로열티 프리로 공개된 모듈형 RISC ISA로, 기본 정수 명령어에 확장을 조합해 프로세서를 설계
- 배경: 2010년 UC Berkeley에서 시작해 RISC-V International이 표준을 관리하며 사양을 공개 유지
- 필요성: ARM·x86의 라이선스 제약 없이 커스텀 명령어·도메인 특화 가속기를 설계해야 하는 반도체 주권·비용 요구에 대응

---

## Ⅱ. 구조 및 구성요소

```text
Base ISA: RV32I / RV64I / RV128I (정수 레지스터 x0~x31, x0=0 고정)
  + M(곱셈/나눗셈) + A(원자연산) + F/D(부동소수점) + C(압축 16비트) + V(벡터)
Privilege Modes: M-mode(필수) -> S-mode(OS) -> U-mode(응용), 선택적 H(가상화)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 기본 정수 ISA | 산술·분기·load/store 기본 명령어 | RV32I/RV64I/RV128I, 32개 레지스터(x0 고정 0) |
| 표준 확장(M/A/F/D) | 곱셈나눗셈·원자연산·부동소수점 지원 | G = IMAFD 축약 표기 |
| 압축 확장(C) | 16비트 명령어로 코드 크기 축소 | 32비트 명령어와 혼합 인코딩 |
| 특권 모드 | 시스템 권한 계층 구분 | M/S/U 3단계, H는 선택 확장 |

> 요약: RISC-V는 기본 정수 ISA에 필요한 확장만 조합하고, 특권 모드로 시스템 권한을 계층화한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
Fetch(32비트 또는 C 확장 16비트 혼합) -> Decode(base+extension opcode map)
  -> Execute(정수 ALU 또는 M/A/F/D/V 실행 유닛 분기)
  -> Privilege Check(M/S/U 모드에 따른 접근 제어) -> Writeback
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 명령어 인출 시 압축(16비트) 여부 판별 | 명령어 정렬·경계 정합성 |
| 2 | 확장 opcode map으로 실행 유닛 결정 | M/A/F/D/V 유닛 라우팅 정확성 |
| 3 | 특권 모드 확인 후 CSR(Control Status Register) 접근 통제 | 모드별 접근 위반 트랩 발생 |
| 4 | 실행 결과를 레지스터·메모리에 반영 | writeback 정합성 |

> 요약: 명령어는 기본/압축 인출 후 확장별 실행 유닛으로 분기하며, 특권 모드가 CSR 접근을 통제한다.

## Ⅳ. 특징

| 구분 | RISC-V | ARM(비교 참고) | 수치·표준 포인트 |
|:---|:---|:---|:---|
| 라이선스 | 로열티 프리, 사양 공개 | 코어·아키텍처 라이선스 비용 발생 | RISC-V International 관리 |
| 명령어 구성 | 기본 ISA + 모듈형 확장(M/A/F/D/C/V) | 벤더가 사전 정의한 확장 집합 | RV32I 기본 레지스터 32개 |
| 커스텀 확장 | 사용자 정의 opcode 공간 허용 | 벤더 승인 필요 | 도메인 특화 가속기 설계 용이 |
| 생태계 성숙도 | 툴체인·OS 포팅이 상대적으로 신생 | 수십 년간 축적된 소프트웨어 자산 | 서버·모바일 상용 검증 이력 |

> 요약: RISC-V는 라이선스 자유와 커스텀 확장에 강점이 있고, ARM은 생태계 성숙도에서 강점이 있다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | RISC-V | ARM | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 모듈형 확장 조합, 커스텀 opcode 허용 | 벤더 정의 확장, 검증된 코어 라인업 | 커스텀 명령어 필요 여부로 판단 |
| 비용/성능 | 로열티 없음, 검증·툴체인 자체 구축 비용 | 라이선스 비용, 검증된 성능·전력 특성 | 물량·라이선스 총비용(TCO) 비교 |
| 운영/위험 | 생태계·OS 포팅 자체 확보 필요 | 성숙한 컴파일러·OS·보안 생태계 | 소프트웨어 이식성과 개발 인력 확보 여부 |

> 요약: 반도체 주권과 커스텀 가속기가 목적이면 RISC-V, 검증된 생태계와 신속한 상용화가 우선이면 ARM을 선택한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 툴체인 미성숙 | 특정 확장 조합에 대한 컴파일러·디버거 지원 부족 | 표준 확장 우선 채택, 커뮤니티 툴체인 검증 | 컴파일러 지원 확장 목록 |
| 파편화 | 벤더별 커스텀 확장 남용으로 호환성 저하 | 표준 확장(G, C, V) 우선 사용, 프로파일 준수 | 표준 프로파일 준수율 |
| 검증 부담 | 오픈 ISA 특성상 코어 검증을 자체 수행 | 공개 테스트 스위트(RISC-V compliance test) 활용 | compliance test 통과율 |

> 요약: RISC-V 도입 리스크는 툴체인 성숙도, 확장 파편화, 자체 검증 부담이 핵심이다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 표준 준수 | RISC-V compliance test 통과 여부 | 공식 테스트 스위트 실행 |
| 코드 밀도 | C 확장 적용 시 코드 크기 감소율 | 바이너리 크기 비교(비압축 대비) |
| 생태계 지원 | 주요 OS·컴파일러 포팅 완료 여부 | Linux 커널·GCC/LLVM 지원 버전 확인 |

> 요약: 도입 효과는 표준 준수율, 코드 밀도, OS·툴체인 포팅 완료 여부로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 임베디드·IoT 코어는 RV32IMC 조합으로 코드 밀도와 저전력을 확보하고 compliance test로 표준 준수를 검증함
2. 서버·AI 가속기 제어 코어는 RV64GCV 조합으로 벡터 확장을 활용해 도메인 특화 연산을 지원함
3. 커스텀 명령어가 필요한 도메인은 표준 opcode 공간을 침범하지 않는 예약 영역에 확장을 정의하고 문서화함

**결론 (2줄):**
- 기술사 판단: 라이선스 자유와 커스텀 확장이 우선이면 RISC-V, 생태계 성숙도와 신속한 상용화가 우선이면 ARM을 선택함
- 향후 방향: 반도체 공급망 자립 요구가 커지며 RISC-V 기반 서버·AI 가속기 채택이 늘고 있어 표준 확장(V, B) 성숙도를 지속 점검해야 함
