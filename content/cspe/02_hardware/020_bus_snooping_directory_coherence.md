## 미리 알고가기

- 버스 스누핑은 모든 캐시가 공용 버스를 감시하는 방식임
- 디렉터리 방식은 중앙 또는 분산 디렉터리가 캐시 상태를 관리함
- 스누핑은 모든 캐시가 요청을 감시하고, 디렉터리는 소유자·공유자에게만 메시지를 보냄
- 스누프 필터: 불필요한 스누프 질의를 줄이기 위해 캐시 라인 보유 여부를 요약해두는 하드웨어 구조임
- 희소 디렉터리(Sparse Directory): 전체 캐시 라인이 아니라 실제 공유되는 라인만 추적해 저장량을 줄이는 방식임
- NUMA: 코어별로 메모리 접근 지연이 달라지는 다중 소켓 구조임

## 작성 근거(검토용)

- 스누핑과 디렉터리를 방송 감시와 소유자·공유자 조회라는 통신 구조 차이로 설명함
- 스누핑과 디렉터리를 통신 방식·저장 비용·확장 제약으로 비교함
- Ⅳ는 정적 구성요소와 연결 관계를, Ⅴ는 방송·조회부터 응답까지 상태가 바뀌는 순서를 담당하도록 정적 구조와 동적 절차를 분리해 설명함

## Ⅰ. 개요

- **정의/개념**: 버스 스누핑과 디렉터리 기반 일관성은 캐시 일관성 프로토콜을 실제 하드웨어 통신 구조로 구현하는 두 방식으로, 스누핑은 모든 캐시가 방송 메시지를 직접 감시하고 디렉터리는 소유자·공유자와 상태를 추적함
- **배경/필요성**: 코어 수에 따라 일관성 메시지 지연과 방송 트래픽을 줄이기 위해 확장 가능한 통신 구조가 필요함

### 쉽게 이해하기 (학습용)
- 한 회의실에서 크게 물어 모두가 듣는 방식(스누핑)과, 안내 데스크에 물어 필요한 사람에게만 쪽지를 전하는 방식(디렉터리)의 차이와 같음

## Ⅱ. 특징

- 스누핑은 별도 디렉터리 없이 모든 캐시가 공용 버스의 일관성 요청을 감시함
- 디렉터리는 필요한 노드에만 메시지를 보내 방송 트래픽을 줄임
- 스누핑은 코어 수가 늘면 방송 메시지가 공용 버스 대역폭을 더 많이 사용함
- 디렉터리는 상태 메타데이터와 조회 지연이 추가됨

### 쉽게 이해하기 (학습용)
- 스누핑은 회의실 참석자가 늘수록 매번 방송을 듣느라 시끄러워지고, 디렉터리는 안내 데스크에 명단을 만들어두는 수고와 조회 시간이 듦

## Ⅲ. 종류 및 비교

| 판단 기준 | 버스 스누핑 | 디렉터리 방식 |
|:---|:---|:---|
| 통신 방식 | 모든 캐시가 버스를 감시하고 방송으로 요청을 전달함 | 디렉터리 엔트리가 소유자·공유자를 기록하고 조회 후 대상에만 전달함 |
| 저장 비용 | 캐시별 스누프 로직 | 라인별 디렉터리 메타데이터 |
| 확장 제약 | 코어가 늘면 방송 트래픽이 공용 버스 대역폭을 초과함 | 디렉터리 용량과 조회 지연이 늘지만 many-core·NUMA의 대상 지정에 적합함 |

> 요약: 스누핑은 모든 캐시가 버스를 감시하고, 디렉터리는 필요한 캐시에만 메시지를 보냄.

### 쉽게 이해하기 (학습용)
- 스누핑은 모두에게 소리쳐 묻고, 디렉터리는 안내 데스크 명단을 먼저 확인한 뒤 필요한 사람에게만 쪽지를 보냄

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 공용 버스·패브릭 | 스누핑에서 모든 코어가 감시하는 공용 통신 경로임 |
| 스누프 로직 | 각 캐시가 버스 주소를 비교해 자신의 상태를 갱신함 |
| 디렉터리 엔트리 | 캐시 라인의 소유자와 공유자 목록을 기록함 |
| 인터커넥트 메시지 경로 | 디렉터리가 지정한 코어에 무효화·데이터 메시지를 전달함 |

```text
+---------------+     +-------------+     +-------------------+
| 공용 버스      | --> | 스누프 로직    | --> | 캐시 상태 갱신       |
+---------------+     +-------------+     +-------------------+

+----------------+     +---------------------+     +----------------------+
| 디렉터리 엔트리  | --> | 인터커넥트 메시지      | --> | 대상 캐시 갱신       |
+----------------+     +---------------------+     +----------------------+
```

> 요약: 스누핑은 공용 버스 감시로, 디렉터리는 소유자·공유자 목록 조회로 일관성을 유지함.

### 쉽게 이해하기 (학습용)
- 공용 버스는 모두가 듣는 방송 채널, 스누프 로직은 각자의 귀, 디렉터리 엔트리는 안내 데스크 명단, 인터커넥트 메시지 경로는 쪽지 배달 경로에 해당함

## Ⅴ. 원리 및 절차 흐름도

```text
[버스 스누핑] 요청 코어가 버스에 방송 -> 각 캐시가 주소 비교·스누프 -> 보유 캐시가 데이터 공급 또는 무효화 응답
[디렉터리]   요청 코어가 홈 디렉터리에 요청 -> 소유자·공유자 목록 조회 -> 대상 캐시에만 무효화·데이터 메시지 전송 -> 응답 수신 후 디렉터리 갱신
```

1. **스누핑 방송**: 요청 코어가 읽기·쓰기 요청을 공용 버스에 방송함
2. **스누프 응답**: 각 캐시가 자신의 상태와 주소를 비교해 데이터를 공급하거나 해당 라인을 무효화함
3. **디렉터리 조회**: 요청이 홈 디렉터리에 도달하면 디렉터리가 소유자·공유자 목록에서 전달 대상을 확인함
4. **대상 지정 전달**: 디렉터리가 조회된 대상에만 무효화·데이터 메시지를 보내고 응답을 모아 소유자·공유자 목록을 갱신함

> 요약: 스누핑은 방송으로 모든 캐시가 즉시 응답하고, 디렉터리는 조회 후 대상 캐시에만 메시지를 보내 상태를 갱신함.

### 쉽게 이해하기 (학습용)
- 스누핑은 방송으로 묻고 들은 사람이 바로 답하며, 디렉터리는 안내 데스크에 먼저 물어 명단에 있는 사람에게만 쪽지를 전달하는 순서로 진행됨

## Ⅵ. 실무 사례

1. 소규모 멀티코어는 스누프 필터를 적용하고 방송 트래픽 비율과 버스 대역폭 이용률을 확인함
2. NUMA 시스템은 분산 희소 디렉터리를 적용하고 메타데이터 비율과 디렉터리 조회 지연을 확인함

### 쉽게 이해하기 (학습용)
- 참석자가 적은 회의실에서는 다 같이 들어도 되지만, 참석자가 아주 많아지면 안내 데스크 명단 방식이 더 유리해짐

## Ⅶ. 결론

- 버스 스누핑과 디렉터리 방식은 캐시 일관성 프로토콜을 실제 통신 구조로 구현하는 방법으로, 모든 캐시에 방송할지 소유자·공유자에게만 메시지를 보낼지로 갈림
- 코어 수가 적어 방송 트래픽이 버스 대역폭 안에 들면 스누핑을, 코어 수가 늘어 디렉터리 저장량·조회 지연을 감수할 만하면 디렉터리 방식을 선택해야 함

### 쉽게 이해하기 (학습용)
- 참석자 수(코어 수)가 적으면 다 같이 듣는 방식이 간단하고, 많아지면 안내 데스크 명단 방식이 방송 트래픽을 줄여줌
