## 미리 알고가기

- 버스 스누핑은 모든 캐시가 공용 버스를 감시하는 방식임
- 디렉터리 방식은 중앙 또는 분산 디렉터리가 캐시 상태를 관리함
- 코어 수가 적으면 스누핑 지연이 짧고, 많아지면 디렉터리가 방송 메시지를 줄임

## Ⅰ. 개요

- **정의/개념**: 버스 스누핑과 디렉터리 기반 일관성은 캐시 일관성 프로토콜을 실제 하드웨어 통신 구조로 구현하는 두 방식으로, 스누핑은 모든 캐시가 방송 메시지를 직접 감시하고 디렉터리는 소유자·공유자와 상태를 추적함
- **배경/필요성**: 코어 수에 따라 일관성 메시지 지연과 방송 트래픽을 줄이기 위해 확장 가능한 통신 구조가 필요함

## Ⅱ. 특징

- 스누핑은 구현이 단순하고 짧은 지연에 유리함
- 디렉터리는 필요한 노드에만 메시지를 보내 방송 트래픽을 줄임
- 스누핑은 코어 수 증가 시 버스 병목이 심해짐
- 디렉터리는 상태 메타데이터와 조회 지연이 추가됨

## Ⅲ. 종류 및 비교

| 판단 기준 | 버스 스누핑 | 디렉터리 방식 |
|:---|:---|:---|
| 통신 방식 | 방송 메시지 | 대상 지정 메시지 |
| 장점 | 단순성과 짧은 지연 | 방송 메시지 감소 |
| 한계 | 대규모 확장 취약 | 메타데이터와 조회 비용 |
| 적합 환경 | 소규모 칩 내 코어 | 대규모 many-core·NUMA |

> 요약: 스누핑은 모든 캐시가 버스를 감시하고, 디렉터리는 필요한 캐시에만 메시지를 보냄.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Shared Bus or Fabric | 스누핑에서는 모든 코어가 감시하는 공용 통신 경로가 됨 |
| Snoop Logic | 각 캐시가 버스 주소를 비교해 자신의 상태를 갱신함 |
| Directory Entry | 특정 라인의 소유자와 공유자 목록을 기록해 대상 지정 무효화를 가능하게 함 |
| Interconnect Message Path | 디렉터리 구조에서 필요한 코어에만 invalidate와 data 메시지를 전달함 |

```text
+---------------+     +-------------+     +-------------------+
| Shared Bus    | --> | Snoop Logic | --> | Cache State Update |
+---------------+     +-------------+     +-------------------+

+----------------+     +---------------------+     +----------------------+
| Directory Entry | --> | Interconnect Message | --> | Target Cache Update |
+----------------+     +---------------------+     +----------------------+
```

> 요약: 스누핑은 공용 버스 감시로, 디렉터리는 소유자·공유자 목록 조회로 일관성을 유지함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 접근 요청 발생   | --> | 소유자/공유자 확인 | --> | 방송 또는 대상 지정 | --> | 상태 갱신      |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **접근 요청 발생**: 한 코어가 읽기 또는 쓰기를 요청함
2. **소유자와 공유자 확인**: 버스 감시 또는 디렉터리 조회를 수행함
3. **방송 또는 대상 지정 메시지 전송**: invalidate와 data 전달을 처리함
4. **상태 갱신**: 관련 캐시를 최신 상태로 맞춤

> 요약: 요청 발생 후 공유 상태를 확인하고 방송 또는 대상 지정 메시지로 캐시 상태를 갱신함.

## Ⅵ. 실무 적용 및 유의점

1. 소규모 멀티코어는 스누핑이 단순하지만 코어 수가 늘면 방송 메시지가 대역폭을 소모하므로 snoop filter와 계층형 버스를 적용하고 broadcast traffic ratio, effective bus bandwidth로 확인함
2. NUMA·칩렛 시스템은 디렉터리가 방송을 줄이지만 메타데이터와 조회 지연이 커지므로 sparse directory, compression, distributed directory, local caching을 적용하고 directory overhead ratio, lookup latency로 확인함

## Ⅶ. 결론

스누핑·디렉터리 선택은 방식의 우열이 아니라 코어 수와 통신 비용에 맞춰 최신성 유지 비용을 줄이는 설계 판단임.

## 작성 근거(검토용)

- 스누핑과 디렉터리는 프로토콜 이름이 아니라 방송 감시와 디렉터리 조회라는 통신 절차 차이로 설명함
- 모호한 표현은 broadcast traffic ratio, directory overhead, lookup latency로 검증 가능한 표현으로 바꿈
- 결론은 고급/저급 구분이 아니라 코어 수와 통신 비용에 맞춘 일관성 구현 선택으로 정리함
