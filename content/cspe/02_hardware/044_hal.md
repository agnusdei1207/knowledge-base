## Ⅰ. 개요
- 정의: 운영체제 커널과 하드웨어 사이에서 장치 종속적인 부분을 처리하는 인터페이스 계층
- 배경: 다양한 하드웨어 사양에 관계없이 동일한 커널 코드를 유지하려는 이식성 확보
- 출제 의도
| 구분 | 내용 |
| --- | --- |
| 핵심 | 이식성(Portability), 모듈화, 커널 독립성, 표준 API 제공 |

## Ⅱ. 구성요소
```
[ Application ]
      |
[ OS Kernel ]
      |
[   HAL     ] <- (Generic API for Kernel)
      |
[ Hardware  ] <- (Specific Driver/Register)
```
| 구성요소 | 설명 | 비유 |
| --- | --- | --- |
| 추상화 API | 커널이 하드웨어에 접근할 때 사용하는 공통 함수군 | 표준 콘센트 |
| 장치 드라이버 | HAL 하단에서 실제 물리 장치와 통신하는 저수준 코드 | 가전 전용 플러그 |
| 레지스터 맵 | 하드웨어별 특유의 메모리/포트 주소 매핑 정보 | 장치 매뉴얼 |
> 요약: 하드웨어의 복잡함을 숨기고 커널에게 일관된 뷰(View)를 제공함

## Ⅲ. 절차
1. 커널 호출: OS 커널이 I/O 수행을 위해 HAL의 공통 API 호출
2. 하드웨어 식별: HAL이 현재 시스템에 탑재된 물리 장치 종류 판별
3. 하위 구동: 특정 하드웨어에 맞는 드라이버나 명령어로 변환하여 실행
4. 결과 반환: 장치로부터 온 응답을 커널이 이해할 수 있는 규격으로 가공
> 요약: "쓰기"라는 공통 명령을 각 장치에 맞는 "신호"로 변환하는 중계자임

## Ⅳ. 문제점
- 추가적인 소프트웨어 계층을 거침으로써 발생하는 미세한 성능 오버헤드 존재함

## Ⅴ. 개선방안
- 인라인 함수 최적화 및 하드웨어 가속 기능을 직접 노출하는 통로(Passthrough) 제공함

## Ⅵ. 전망
- 임베디드 및 IoT 기기의 파편화 해결을 위한 표준 HAL 규격(예: Project Treble) 확산
- 클라우드 가상화용 VirtIO 등 가상 HAL 기술이 서버 자원 효율화의 핵심 로드맵임
