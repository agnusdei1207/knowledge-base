## 미리 알고가기

- Interconnect: 중앙처리장치(Central Processing Unit, CPU), 그래픽 처리 장치(Graphics Processing Unit, GPU), 메모리, 스위치 사이를 연결하는 고속 통신 경로임
- Peer-to-Peer: 피어 간 직접 통신(Peer-to-Peer, P2P)은 GPU가 CPU 메모리 복사 없이 다른 GPU 메모리에 직접 접근하는 방식임
- NVSwitch: 여러 GPU의 NVLink 연결을 스위칭해 대규모 GPU 패브릭을 구성하는 장치임
- Collective: AllReduce처럼 여러 GPU가 텐서를 집계하는 병렬 통신 연산임

## Ⅰ. 개요

- **정의**: NVLink는 GPU와 GPU, 일부 플랫폼의 GPU와 CPU 사이를 고대역폭·저지연으로 연결해 주변 장치 상호연결 익스프레스(Peripheral Component Interconnect Express, PCIe) 대비 높은 대역폭, GPU 메모리 접근, 다중 GPU 통신 효율 기준으로 AI 학습과 고성능 컴퓨팅(High Performance Computing, HPC) 워크로드를 가속하는 NVIDIA 고속 인터커넥트임.
- **배경/필요성**: 대규모 AI 모델은 하나의 GPU 메모리와 연산 성능을 초과하므로 여러 GPU 간 텐서와 gradient 교환이 필수임. PCIe만으로는 통신 병목이 커져 GPU 유휴 시간이 증가하므로 전용 고속 연결이 필요함.
- **비유**: 여러 공장 사이에 일반 도로 대신 전용 고속 물류 터널을 만든 것과 같음.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| GPU 클러스터 내부 고속 연결 구조 설명 | 대역폭, P2P, NVSwitch, 토폴로지 | PCIe의 단순 이름 대체로 설명 |

> 요약: NVLink는 다중 GPU 시스템에서 GPU 간 데이터 이동 병목을 줄이는 전용 고속 인터커넥트임.

## Ⅱ. 특징/비교

| 판단 기준 | PCIe 중심 연결 | NVLink 연결 |
|:---|:---|:---|
| 통신 경로 | 범용 I/O 버스로 CPU 루트 복합체와 스위치를 중심으로 연결됨 | GPU 간 직접 연결과 NVSwitch 패브릭을 구성할 수 있음 |
| 최적화 목표 | 호환성, 범용 주변장치 연결, 표준 생태계 | GPU 메모리 접근, collective 통신, 낮은 통신 지연 |
| 적용 기준 | 일반 서버와 다양한 장치 연결에 적합함 | AI 학습, HPC, 대규모 GPU 노드에 적합함 |

> 요약: NVLink는 범용성보다 GPU 간 대역폭과 토폴로지 효율이 중요한 시스템에서 선택됨.

## Ⅲ. 구성요소

```text
+-------+      +---------+      +-------+
| GPU 0 | <--> | NVSwitch| <--> | GPU 1 |
+-------+      +---------+      +-------+
    |               |               |
    v               v               v
+-------+      +---------+      +-------+
| GPU 2 | <--> | Fabric  | <--> | GPU 3 |
+-------+      +---------+      +-------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| NVLink 포트 | GPU와 인접 장치 사이에 고속 직렬 링크를 제공함 | 전용 터널 입구 |
| NVSwitch | 여러 NVLink를 스위칭해 GPU 간 완전 연결에 가까운 경로를 제공함 | 물류 분기 허브 |
| GPU 메모리 | P2P 접근과 collective 통신의 대상이 되는 고대역폭 메모리(High Bandwidth Memory, HBM) 영역임 | 공장별 창고 |
| 통신 라이브러리 | NVIDIA 집합 통신 라이브러리(NVIDIA Collective Communications Library, NCCL) 같은 계층이 토폴로지에 맞춰 AllReduce, Broadcast를 수행함 | 배차 시스템 |

> 요약: NVLink 구조는 GPU 링크, 스위치 패브릭, 메모리 접근, 통신 라이브러리의 결합으로 동작함.

## Ⅳ. 절차

```text
+----------+     +----------+     +----------+     +----------+
| Topology | --> | Route    | --> | Transfer | --> | Monitor  |
+----------+     +----------+     +----------+     +----------+
```

1. **토폴로지 식별**: GPU 간 링크 수, NVSwitch 연결, 비균일 메모리 접근(Non-Uniform Memory Access, NUMA) 위치, PCIe 경로를 확인함
2. **경로 설정**: P2P 접근 가능 여부와 통신 라이브러리의 ring/tree 경로를 결정함
3. **데이터 전송**: 텐서, gradient, activation을 링크 대역폭에 맞춰 전송하고 연산과 겹침 처리함
4. **성능 감시**: 링크 활용률, collective 지연, GPU 유휴 시간을 모니터링함

> 요약: NVLink 운영은 토폴로지를 인식한 통신 경로 설정과 링크 활용률 관리가 핵심임.

## Ⅴ. 문제점

- **P1 토폴로지 병목**: GPU 배치와 통신 패턴이 링크 구조와 맞지 않으면 특정 링크나 스위치에 트래픽이 집중됨
- **P2 플랫폼 종속성**: NVIDIA GPU와 지원 플랫폼에 의존해 장비 선택과 확장 전략이 제한될 수 있음
- **P3 열·장애 영향**: 고밀도 GPU 노드에서 링크·스위치 장애와 발열이 전체 학습 작업을 중단시킬 수 있음

> 요약: NVLink의 성능은 링크 존재보다 토폴로지 매핑, 플랫폼 전략, 고밀도 운영 안정성에 좌우됨.

## Ⅵ. 개선방안

- **P1 대응**: 토폴로지 인식 rank 배치, 통신-연산 overlap, 병렬화 전략 조정을 적용함 (확인: collective p95 지연)
- **P2 대응**: 워크로드별 대체 PCIe/RDMA over Converged Ethernet(RoCE) 구성과 비용 기준을 함께 보유함 (확인: 대체 구성 성능비)
- **P3 대응**: 링크 헬스체크, 온도 기반 스케줄링, 장애 GPU 격리와 체크포인트를 운영함 (확인: 작업 재시작 시간)

> 요약: 개선은 토폴로지 최적화, 벤더 종속 관리, 링크·열 장애 대응 체계를 통해 수행함.

## Ⅶ. 전망

- **발전 방향**: NVLink 계열 고속 연결은 스위치 패브릭, 메모리 공유, 호스트 연결 기술과 결합해 노드 내부 GPU 통신 병목을 줄이는 방향으로 발전함
- **기술사적 판단**: GPU 배치, all-reduce 트래픽, PCIe fallback 경로, 링크 전력 예산을 함께 산정해 모델 병렬화 병목이 링크로 이동하지 않게 설계함; P2P 대역폭, collective p95 지연, 링크 오류 카운터, GPU 유휴율을 워크로드별로 측정해 포트 속도와 실효 처리량을 분리함
- **기술사 제언**: NVLink는 PCIe 대비 수치 비교보다 통신 패턴, 장애 도메인, 운영 계측을 함께 제시해 AI 서버 패브릭 선택 근거로 설명함
