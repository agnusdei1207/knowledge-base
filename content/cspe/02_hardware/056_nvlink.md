# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: NVIDIA가 개발한 GPU 간, 또는 CPU-GPU 간 초고속 점대점(Point-to-Point) 인터커넥트 기술
- **왜 필요한가**: 딥러닝 모델 학습 시 GPU 여러 대를 묶어 써야 하는데, 이들을 이어주는 기존 PCIe 버스 대역폭이 너무 좁아 데이터 전송 병목이 심각했다.
- **핵심 직관**: 여러 대의 GPU가 거대한 하나의 칩처럼 행동하려면 엄청난 속도의 직통 도로가 필요하다. NVLink는 기존 왕복 2차선(PCIe)을 왕복 16차선(NVLink) 고속도로로 넓혀준 전용망이다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| PCIe (Peripheral Component Interconnect Express) | 범용 PC/서버의 표준 주변기기 연결 버스 | 누구나 쓰는 일반 국도 (막힘 현상 심함) |
| NVLink | NVIDIA의 GPU 전용 고속 직통 연결 기술 | GPU 전용 톨게이트 없는 고속도로 |
| NVSwitch | 수십 대의 GPU를 풀 메시(Full-mesh)로 묶어주는 전용 스위치 칩 | 고속도로들이 만나는 거대한 입체 교차로 |
| Unified Memory | 여러 GPU의 메모리를 마치 하나의 거대한 메모리처럼 다루는 기술 | 각자 창고를 터서 하나의 거대 물류센터로 만듦 |

## 깊이 이해
- **배경·문제의식**: LLM 등 파라미터가 수백억 개 이상인 거대 모델은 단일 GPU 메모리(80GB)에 담을 수 없어 여러 GPU에 쪼개어 올려야 한다(모델/텐서 병렬화). 이때 GPU 간 가중치를 교환하는 통신 시간이 연산 시간보다 길어지는 주객전도가 발생했다.
- **작동 원리**: CPU를 거치지 않고 GPU 메모리 간 직접 데이터 읽기/쓰기(P2P)를 허용한다. 4세대 NVLink(Hopper 아키텍처)의 경우 GPU당 초당 900GB의 양방향 대역폭을 제공하여 PCIe 5.0(64GB/s) 대비 14배 이상 빠르다.
- **비유**: 옆 부서(GPU B) 자료가 필요할 때, 예전에는 본부장(CPU)을 통해 결재선(PCIe)을 타고 받아야 했다면, NVLink는 부서 간 벽을 허물고 옆자리 동료에게 바로 자료를 넘겨받는 식이다.
- **구체 예시**: 8대의 H100 GPU를 단일 서버(DGX H100)로 묶을 때, NVSwitch를 통해 모든 GPU가 서로 900GB/s 대역폭으로 통신하여 마치 640GB(80GBx8) 메모리를 가진 1대의 괴물 GPU처럼 동작한다.
- **흔한 오해·주의점**: NVLink는 서버 내부(또는 인접 랙) 통신망이다. 멀리 떨어진 서버 노드 간의 통신(네트워크)은 여전히 InfiniBand나 이더넷 기반의 RDMA(RoCE)가 담당한다.

## 연결 개념
- Tensor Parallelism (텐서 병렬화)
- InfiniBand (노드 간 네트워크)
- CXL (Compute Express Link - 범용 대안 표준)

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: NVLink는 GPU 상호 간 및 CPU-GPU 간 데이터 병목을 해소하기 위해 NVIDIA가 독자 개발한 초고속, 고대역폭 직렬 인터커넥트 인터페이스다.
> 2. **가치**: PCIe의 대역폭 한계(64GB/s)를 우회하여 초당 900GB(4세대 기준)의 직통 경로를 제공, 다중 GPU 클러스터의 확장성(Scalability) 한계를 돌파했다.
> 3. **판단 포인트**: 거대 언어 모델(LLM) 학습을 위한 텐서/파이프라인 병렬화 시 노드 내(Intra-node) 통신은 NVLink가 전담하고, 노드 간(Inter-node) 통신은 InfiniBand로 계층화하는 설계가 필수적이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| AI 클러스터 통신 병목 해결 역량 | PCIe 대역폭 한계, GPU Direct P2P 통신 | NVLink를 범용 이더넷 네트워크 기술과 혼동 |
| 멀티 GPU 스케일업 아키텍처 이해 | NVLink와 NVSwitch를 통한 풀 메시(Full-mesh) 구성 | NVSwitch 없이 단순 링크 연결로 스케일업을 설명 |
| 개방형 생태계와의 비교 판단 | 벤더 종속성(Lock-in), 개방형 표준(CXL, UCIe)과의 대조 | 통신 규격이므로 연산 성능 척도(TOPS) 위주 설명 지양 |

> 요약: 단일 GPU 연산 속도가 아무리 빨라도 데이터를 공급받지 못하면 유휴 상태(Starvation)에 빠진다. NVLink는 이 데이터 공급 파이프라인의 핵심이다.

## Ⅰ. 개요 및 필요성

- 개요: 딥러닝 모델의 다중 GPU 분산 학습 시 발생하는 PCIe 버스 대역폭 한계를 극복하기 위한 NVIDIA의 초고속 점대점(P2P) 인터페이스
- 배경: LLM(거대언어모델) 등장으로 파라미터 크기가 수백 기가바이트(GB)를 초과하며, 모델 병렬화에 따른 GPU 간 가중치 교환 오버헤드 급증
- 필요성: 시스템 메모리(Host CPU)를 거치지 않고 GPU 간 VRAM을 직접 액세스하는 초광대역(Ultra-bandwidth) 직통 채널 확보 필수

---

## Ⅱ. 구조 및 구성요소

```text
[ GPU 1 ] <--- NVLink (최대 900GB/s) ---> [ GPU 2 ]
    |                                         |
    +-----> [ NVSwitch (Full-Mesh 라우팅) ] <----+
                  |               |
             [ GPU 3 ]         [ GPU 4 ]
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| NVLink Link | GPU 다이 외곽에 배치된 고속 직렬 I/O 인터페이스 통로 | 4세대(H100) 기준 1개 GPU당 18개 링크 집적 |
| NVSwitch | 다중 GPU 간의 트래픽을 차단(Blocking) 없이 라우팅하는 스위치 칩 | 8개 이상의 GPU를 단일 노드처럼 묶어줌 |
| NVLink Network | 여러 랙(Rack) 단위의 서버 노드를 스위치로 연결하는 확장망 | 단일 서버를 넘어선 슈퍼팟(SuperPOD) 구성 |
| GPU Direct P2P | CPU 개입 없이 GPU 메모리 공간을 직접 매핑하고 전송하는 SW/HW 스택 | PCIe 병목 및 CPU 컨텍스트 스위칭 제거 |

> 요약: 개별 NVLink 통로가 NVSwitch를 통해 풀 메시 톨로지(Full-mesh Topology)로 묶여, 서버 내 모든 GPU가 동일한 최대 대역폭으로 통신한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
CPU 할당 우회 -> 가상 메모리 공간 통합 매핑 -> GPU 간 직접 데이터 요청 -> 고속 직렬 전송
Memory Mapped I/O   Unified Memory Space      Direct RDMA-like Transfer  SerDes PHY Layer
```

- 1단계 [통신 초기화]: 드라이버 레벨에서 각 GPU의 VRAM 물리 주소를 다른 GPU가 접근할 수 있도록 통합 매핑
- 2단계 [오프로딩 수행]: GPU 1의 텐서 연산 결과(활성화 맵)가 GPU 2의 연산에 즉시 필요함 (데이터 의존성)
- 3단계 [CPU 우회 직통]: GPU 1이 PCIe Root Complex를 거치지 않고 NVLink를 통해 GPU 2의 메모리에 직접 쓰기(Write) 수행
- 4단계 [논블로킹 전송]: 다중 GPU 간 동시다발적인 요청도 NVSwitch가 병목 없이 고속 라우팅 처리

> 요약: PCIe를 통과하는 기존의 `GPU1 -> CPU RAM -> GPU2` 경로를 우회하여, VRAM 간 직접 전송으로 지연 시간을 나노초(ns) 수준으로 낮춘다.

---

## Ⅳ. 특징
- 초광대역 전송: PCIe Gen5(양방향 128GB/s) 대비 약 7배 넓은 900GB/s 대역폭을 제공하여 통신 의존적인 집단 연산(All-Reduce) 성능 극대화
- 통합 메모리 가상화: 물리적으로 분리된 여러 GPU의 메모리를 개발자 관점에서 단일 포인터로 접근 가능하게 하여 프로그래밍 복잡도 경감
- 강한 벤더 종속성: NVIDIA 자사 GPU 및 특정 CPU(Grace) 등 폐쇄적인 생태계에만 호환되어 인프라 유연성 저해

> 요약: 멀티 GPU 스케일업 성능은 타의 추종을 불허하지만, 폐쇄형 생태계에 종속되는 강력한 락인(Lock-in) 효과를 수반한다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | PCIe (표준) | NVLink (NVIDIA 독자) | 선택 기준 |
|:---|:---|:---|:---|
| 아키텍처 | 트리(Tree)형 확장 구조 | NVSwitch 기반 풀 메시 구조 | GPU 장착 대수 및 통신 밀도 |
| 대역폭 / 지연 | 128GB/s (Gen5 양방향) | 900GB/s (4세대) | 데이터 병렬화 vs 텐서 병렬화 |
| 생태계 개방성 | 모든 제조사 범용 호환 | NVIDIA 제품군 전용 | TCO 및 특정 하드웨어 종속 수용 |

> 요약: 4대 이하의 GPU나 데이터 통신이 적은 워크로드는 범용 PCIe로 충분하나, 8대 이상의 초대형 LLM 분산 학습 환경은 NVLink 도입이 필수적이다.

**리스크·대응 (기본 불릿):**
- 벤더 종속 비용 폭증: 전용 스위치(NVSwitch)와 케이블링으로 단일 노드 구축 비용 급상승 → 개방형 인터커넥트 표준인 CXL(Compute Express Link) 생태계 병행 검토 (지표: 인프라 TCO 대비 성능 이득)
- 노드 내 스케일업 한계: NVSwitch로 묶을 수 있는 칩 수가 물리적 한계(발열·핀 수)에 봉착 → NVLink는 노드 내(Scale-up)로 한정하고 노드 간 통신(Scale-out)은 400G InfiniBand로 분리하는 계층화 설계 (지표: 네트워크 통신 계층 대역폭)
- 물리적 발열 제약: 초고속 직렬 통신(SerDes) 칩의 극심한 발열 유발 → 공랭 한계 돌파를 위한 Direct-to-Chip 수랭(Liquid Cooling) 도입 (지표: PUE 및 랙 단위 전력 밀도)

**도입 후 점검 지표:**
- 노드 내 통신 대역폭: GB/s — NCCL(NVIDIA Collective Communications Library) 벤치마크 툴로 All-Reduce 실측 대역폭 확인
- 학습 선형 확장성: Scale-up Efficiency — GPU 1대 대비 8대 사용 시 성능 향상률(이상적으로 8배에 얼마나 근접하는가)

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. LLM 텐서 병렬화(Tensor Parallelism) 분산: 거대 행렬 곱셈을 8장의 GPU로 쪼개어 연산할 때, 빈번한 중간 결과 교환(All-Gather) 병목을 NVLink로 제거하여 통신 지연시간 은닉
2. Grace Hopper 슈퍼칩(GH200) 통합: CPU(Grace)와 GPU(Hopper)를 NVLink-C2C 칩렛 기술로 연결해, 별도의 메인보드 전송 없이 900GB/s로 메모리 캐시 일관성(Coherency) 확보
3. NCCL 최적화 라우팅: 집단 통신 라이브러리(NCCL)를 적용하여 데이터의 물리적 위치(NVLink 연결망 위상)를 파악, 링(Ring) 또는 트리(Tree) 최단 경로 전송 자동화

**결론 (2줄):**
- 기술사 판단: 단일 칩의 무어의 법칙이 종료된 현재, AI 성능 확장은 코어 연산력 개선보다 NVLink와 같은 다중 다이(Die) 간 인터커넥트 패키징 기술이 좌우한다.
- 향후 방향: NVIDIA의 폐쇄적 고대역폭 생태계에 대항하여, 인텔/AMD/ARM 등 연합군 중심의 UALink(Ultra Accelerator Link) 및 UCIe 표준이 부상하며 규격 경쟁이 심화될 것이다.
