## Ⅰ. 개요
- **정의**: GPU 간 및 GPU-CPU 간 고대역폭 직접 연결을 제공하는 점대점 인터커넥트 기술임
- **배경/필요성**: AI/HPC 워크로드에서 GPU 메모리 간 데이터 이동량이 PCIe 대역폭을 초과하여, 전용 고속 링크가 필요함
- **비유**: 고속도로(PCIe)가 정체될 때 GPU끼리 전용 지하 터널을 뚫어 데이터를 주고받는 구조임

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| GPU 인터커넥트 대역폭 비교 | PCIe 대비 대역폭 수치 차이 | NVSwitch와 NVLink 혼동 금지 |

> 요약: GPU 간 PCIe 병목을 해소하는 전용 고대역폭 점대점 링크임

## Ⅱ. 구성요소
```text
GPU-A --[NVLink Lane x18]--> NVSwitch --[NVLink Lane x18]--> GPU-B
  |                            |
  +--- Unified Memory Fabric --+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| NVLink Lane | 차동 신호 쌍으로 구성된 단방향 고속 직렬 링크 | 고속도로의 차선 1개 |
| NVLink Brick | 복수 Lane을 묶은 양방향 서브링크 단위 | 왕복 차선 묶음 |
| NVSwitch | 다수 GPU를 All-to-All로 연결하는 스위치 칩 | 교차로 신호등 없는 고가 IC |
| Unified Memory Fabric | GPU 간 메모리를 단일 주소 공간으로 노출하는 메커니즘 | 여러 창고를 하나의 주소로 관리 |

> 요약: Lane-Brick-NVSwitch 계층으로 다대다 GPU 메모리 패브릭을 구성함

## Ⅲ. 절차
```text
요구분석 -> 토폴로지 설계 -> NVLink 물리 연결 -> 메모리 패브릭 설정
```
- 1단계: **요구분석** — 워크로드별 GPU 간 통신량과 지연 요구사항을 산정함
- 2단계: **토폴로지 설계** — GPU 수에 따라 NVSwitch 기반 All-to-All 또는 점대점 링 토폴로지를 선택함
- 3단계: **NVLink 물리 연결** — Brick 수를 할당하고 GPU 보드 간 물리 배선을 구성함
- 4단계: **메모리 패브릭 설정** — Unified Memory 모드를 활성화하여 GPU 간 직접 메모리 접근을 허용함

> 요약: 통신량 산정-토폴로지 선택-물리 배선-메모리 통합 순서로 구축함

## Ⅳ. 문제점
- **GPU 수 확장 한계**: NVSwitch 포트 수가 고정되어 노드 내 GPU 수가 제한됨 — 단일 노드 확장에 물리적 상한 존재
- **열 밀도 집중**: 고대역폭 직렬 링크가 좁은 면적에 집중되어 냉각 부하가 증가함 — 열 설계 전력(TDP) 초과 위험
- **노드 간 미지원**: NVLink는 노드 내부 연결 전용이므로 다중 서버 간 통신에는 InfiniBand(057 참조) 등 별도 네트워크가 필요함

> 요약: 포트 한계·열 밀도·노드 간 미지원이 확장성의 3대 제약임

## Ⅴ. 개선방안
1. 단기: NVSwitch 세대 업그레이드로 포트당 대역폭 및 포트 수를 확대하여 GPU 수 확장 한계 완화
2. 중기: 액체 냉각·침수 냉각 도입으로 NVLink 영역의 열 밀도 집중 문제를 해소
3. 장기: NVLink-C2C 등 칩 간 패키지 레벨 링크로 노드 간 NVLink 확장을 통해 별도 네트워크 의존 감소

> 요약: 포트 확장-냉각 혁신-패키지 레벨 확장 순으로 개선함

## Ⅵ. 전망
- 발전 방향: 세대별 대역폭이 2배씩 증가하며 GPU 클러스터의 기본 패브릭으로 정착하는 추세임
- 기술사적 판단: AI 대규모 학습 인프라에서 NVLink 유무가 학습 처리량을 결정하는 핵심 변수임
- 기술사 제언: NVLink 토폴로지 설계 시 워크로드 통신 패턴 분석을 선행하고, InfiniBand(057 참조)와의 계층적 연동 구조를 수립할 필요
