# TPU 텐서 처리 장치 (Tensor Processing Unit)

## 미리 알고가기

- Tensor: 딥러닝에서 벡터, 행렬, 다차원 배열을 일반화한 데이터 단위임
- TPU: 텐서 처리 장치(Tensor Processing Unit, TPU)는 텐서 연산을 전용 데이터패스로 처리하는 가속기임
- Systolic Array: 데이터가 배열 내부를 박동처럼 이동하며 MAC 연산을 반복하는 구조임
- MXU: 행렬 연산 유닛(Matrix Multiply Unit, MXU)은 대규모 행렬 곱을 처리하는 핵심 블록임
- XLA: 모델 그래프를 하드웨어 실행에 맞게 최적화하는 컴파일러 계층임

## Ⅰ. 개요

- **정의/개념**: TPU는 딥러닝 모델의 텐서 연산을 대규모 MAC 배열과 고대역폭 메모리에 매핑해 행렬 연산 비중, 모델 그래프, 배치 처리량 기준으로 학습·추론 효율을 높이는 전용 프로세서임.
- **배경/필요성**: 대형 신경망은 행렬 곱과 컨볼루션이 연산량 대부분을 차지하며 CPU와 범용 GPU만으로는 비용과 전력 부담이 커짐. TPU는 텐서 연산 경로를 전용화해 대규모 AI 서비스의 전력당 처리량을 높임.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 텐서 연산 전용 하드웨어 구조 설명 | Systolic Array, MXU, HBM, compiler, model constraint | GPU와 같은 범용 병렬처리로 설명, 컴파일러 제약 누락 |

> 요약: TPU는 딥러닝 텐서 연산을 전용 하드웨어와 컴파일러로 실행해 전력당 처리량을 높이는 장치임.

## Ⅱ. 특징 및 비교

| 판단 기준 | GPU AI 가속 | TPU 텐서 처리 |
|:---|:---|:---|
| 실행 구조 | SIMT 코어와 tensor core를 조합해 범용 병렬성을 제공함 | 텐서 그래프를 전용 행렬 배열과 메모리 흐름에 맞춤 |
| 유연성 | 다양한 커널과 프레임워크 지원이 넓음 | 지원 연산자와 컴파일러 최적화 범위에 성능 의존 |
| 적용 기준 | 다양한 모델 실험과 혼합 워크로드에 유리함 | 큰 배치, 규칙적 텐서 연산, 클러스터 학습에 유리함 |
| 병목 요인 | 커널 효율, 메모리 접근, GPU 간 통신 | 그래프 컴파일, HBM 대역폭, collective 통신 |

TPU는 특정 벤치마크 수치보다 모델 그래프가 전용 배열에 잘 매핑되는지가 중요함. 지원되지 않는 연산자가 많거나 배치가 작으면 CPU/GPU fallback과 통신 비용 때문에 기대 성능이 낮아질 수 있음.

## Ⅲ. 구성요소/구조

```text
+----------+      +-----------+      +-----------+      +----------+
| Model    | ---> | XLA/Graph | ---> | MXU Array | ---> | Output   |
+----------+      +-----------+      +-----------+      +----------+
                                      |
                                      v
                               +-------------+
                               | HBM / SRAM  |
                               +-------------+
```

| 구성요소 | 설명 | 핵심 포인트 |
|:---|:---|:---|
| MXU/Systolic Array | 행렬 곱을 대규모 MAC 배열로 반복 처리함 | 텐서 처리량 |
| HBM/온칩 메모리 | 가중치와 활성값을 공급하고 중간 결과를 저장함 | 대역폭 |
| XLA 컴파일러 | 모델 그래프를 하드웨어 실행 형태로 변환·최적화함 | 그래프 최적화 |
| Collective 통신 | 다중 TPU 간 gradient와 tensor를 집계함 | 클러스터 확장 |
| 런타임 | 모델 실행, 메모리 배치, 장치 동기화를 관리함 | 운영 제어 |

### 원리/흐름도

```text
+----------+      +----------+      +----------+      +-----------+
| Compile  | ---> | Place    | ---> | Execute  | ---> | Collective|
+----------+      +----------+      +----------+      +-----------+
```

모델 그래프는 XLA를 통해 연산자 융합과 배치 최적화를 거친 뒤 MXU와 메모리에 배치됨. 다중 TPU에서는 연산 속도만큼 gradient 집계와 장치 간 통신이 전체 처리량을 결정함.

## Ⅳ. 문제점 및 개선방안

1. **연산자 지원 제약**: 모델에 TPU 최적화가 어려운 연산자가 많으면 fallback과 그래프 분할로 지연이 증가함.
   - **개선방안**: 지원 연산자 중심으로 모델을 변환하고 연산자 융합·그래프 재작성 기준을 적용함. (확인: unsupported op, compile warning)
2. **메모리·통신 병목**: MXU가 충분해도 HBM 공급과 TPU 간 collective가 느리면 연산기가 idle 상태가 됨.
   - **개선방안**: batch size, sharding, data/model parallel 전략, 통신 overlap을 조정함. (확인: MXU utilization, step time)
3. **생태계 종속성**: 프레임워크, 클라우드, 컴파일러 스택에 성능과 운영이 의존함.
   - **개선방안**: 모델 이식성, GPU 대안, 비용 모델을 사전에 비교함. (확인: TCO, 이식 테스트 성공률)

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 대규모 모델 학습 | 텐서 병렬·데이터 병렬을 조합하고 collective 통신을 최적화함 | step time, MXU utilization |
| 대량 추론 서비스 | 배치와 모델 컴파일을 고정해 반복 텐서 연산의 처리량을 높임 | QPS/W, p99 지연 |
| 연구 모델 운영화 | GPU에서 검증한 모델을 TPU 지원 연산자와 XLA 그래프에 맞게 변환함 | unsupported op 수, 정확도 변화 |

## Ⅵ. 결론

TPU는 텐서 연산 중심 워크로드에서 전용 배열과 컴파일러 최적화로 높은 전력당 처리량을 제공함. 그러나 성능은 모델 그래프, 지원 연산자, 메모리·통신 구조에 크게 좌우됨. 따라서 TPU 선택은 “전용 AI 칩”이라는 이름보다 모델 매핑 가능성, 배치 특성, 클러스터 통신 지표를 기준으로 판단해야 함.
