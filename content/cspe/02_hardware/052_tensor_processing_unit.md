# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: Google이 자체 개발한 딥러닝 기계학습 전용 맞춤형 집적회로(ASIC) 가속기
- **왜 필요한가**: GPU는 범용성이 높지만 전력 소모가 크고 행렬 연산 외의 불필요한 로직이 많다. 딥러닝의 핵심인 '행렬 곱셈'에만 자원을 몰아넣어 가성비와 전성비를 극대화할 필요가 있었다.
- **핵심 직관**: GPU가 다용도 스위스 아미 나이프라면, TPU는 오직 채소를 써는 데 최적화된 거대한 작두다. 행렬 데이터를 한 번 넣으면 내부에서 심장 박동처럼(Systolic) 데이터를 밀어내며 연산을 끝낸다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| MXU (Matrix Multiply Unit) | 행렬 곱셈을 수행하는 거대한 산술논리연산장치 배열 | 수만 개의 곱셈기가 바둑판처럼 배열된 심장부 |
| Systolic Array (시스톨릭 배열) | 데이터가 프로세서 배열을 통과하며 연속적으로 연산되는 구조 | 공장 컨베이어 벨트에 부품이 지나가며 조립되는 과정 |
| Bfloat16 | 딥러닝에 최적화된 16비트 부동소수점 포맷 | 정밀도 일부를 포기하고 표현 범위(지수부)를 유지한 경량 숫자 포맷 |
| CISC 기반 명령어 | TPU가 사용하는 복잡한 명령어 집합 | "이 행렬 전체를 곱해라"라는 큰 덩어리의 명령 |

## 깊이 이해
- **배경·문제의식**: 딥러닝 추론/학습 워크로드는 행렬 곱셈(MAC 연산)이 90% 이상을 차지한다. 폰 노이만 구조나 기존 GPU는 연산마다 메모리(레지스터)에서 데이터를 읽고 쓰는 오버헤드가 너무 컸다.
- **작동 원리**: 시스톨릭 배열 구조를 사용하여, 데이터가 한 연산기(ALU)에서 연산된 후 메모리로 가지 않고 바로 옆 연산기로 전달된다. 메모리 접근을 극단적으로 줄이고 연산 밀도를 높였다.
- **비유**: 100명이 릴레이 계산을 할 때, 계산할 때마다 중앙 칠판(메모리)에 적고 다음 사람이 읽어가는 대신(GPU), 옆 사람에게 바로 쪽지를 넘기며(TPU 시스톨릭 배열) 연속 계산한다.
- **구체 예시**: TPU v1은 65,536(256x256)개의 8비트 MAC 연산기를 내장하여 클럭당 65,536회의 연산을 수행하며, GPU 대비 와트당 성능이 30배 높았다.
- **흔한 오해·주의점**: TPU가 무조건 빠른 것은 아니다. 대규모 행렬 곱셈(Dense Matrix)이 아닌, 분기가 많거나 순차적 로직이 필요한 일반 연산에서는 오히려 느리거나 동작하지 않는다.

## 연결 개념
- ASIC (Application-Specific Integrated Circuit)
- MAC (Multiply-Accumulate) 연산
- NPU (Neural Processing Unit)

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: TPU는 딥러닝 모델의 행렬 곱셈(Matrix Multiplication) 가속에 특화된 구글의 AI 전용 ASIC(주문형 반도체)이다.
> 2. **가치**: 시스톨릭 배열(Systolic Array) 아키텍처를 통해 메모리 접근 횟수를 최소화하여, 단위 전력당 연산량(TOPS/W)을 획기적으로 개선했다.
> 3. **판단 포인트**: 범용성(CPU, GPU)과 특수성(TPU, ASIC)의 트레이드오프 관계에서, 대규모 텐서 연산의 오프로딩 효율성 확보가 선택 기준이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| AI 전용 가속기의 등장 배경 이해 | 폰 노이만 병목, 행렬 곱셈 중심의 워크로드 특성 | 일반 그래픽 처리 기능과 혼동 |
| TPU 핵심 아키텍처의 구조적 특성 파악 | Systolic Array, MXU, Bfloat16, 대용량 온칩 버퍼 | 단순 코어 수 증가로 성능 향상 설명 단정 |
| 이기종 가속기 비교 판단 | GPU 대비 높은 전성비, 낮은 범용성, CISC 기반 접근 | 적용 불가능한 범용 로직에 도입 방안 제시 |

> 요약: 딥러닝 워크로드의 특성에 맞춰 메모리 대역폭 한계(Memory Wall)를 극복하기 위한 시스톨릭 데이터 흐름과 저정밀도 포맷이 TPU의 핵심이다.

---

## Ⅰ. 개요 및 필요성

- 개요: 구글이 텐서플로우(TensorFlow) 기반의 딥러닝 모델 학습 및 추론 가속을 위해 자체 개발한 텐서 처리 전용 ASIC 가속기
- 배경: AI 모델 크기가 지수적으로 증가하면서 기존 범용 CPU 및 GPU로는 발열과 전력 소비, 데이터 병목을 감당할 수 없음
- 필요성: 단순 반복적인 대규모 MAC(Multiply-Accumulate) 연산 효율을 극대화하여 데이터센터의 TCO(총소유비용) 최적화 필요

---

## Ⅱ. 구조 및 구성요소

```text
Host -> PCIe -> [TPU Chip]
                   |-- Control Unit (CISC Instruction)
                   |-- Unified Buffer (SRAM, Weight/Activation 저장)
                   +-> MXU (Systolic Array) -> Activation Unit
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| MXU (Matrix Multiply Unit) | 거대한 MAC 연산기 배열(Systolic Array)로 행렬 곱셈 수행 | 레지스터 접근 없이 데이터 파이프라이닝 |
| Unified Buffer | 가중치(Weight)와 활성화(Activation) 데이터를 담는 온칩 메모리 | 수십 MB의 고속 SRAM 적용 |
| Activation Unit | ReLU, Sigmoid 등 비선형 활성화 함수 하드웨어 처리 | MAC 연산 후 즉각 적용 |
| Control Unit | 호스트로부터 전달된 CISC 명령어를 디코딩하여 제어 | "Read, Multiply, Write"를 단일 명령으로 처리 |

> 요약: 대규모 통합 버퍼에서 데이터를 읽어 MXU의 시스톨릭 배열로 밀어넣어 메모리 접근 없이 연속으로 연산하는 구조다.

---

## Ⅲ. 동작원리 및 흐름도

```text
호스트 명령 수신 -> 가중치 버퍼 로드 -> 데이터 스트리밍(시스톨릭) -> 활성화 함수 적용 -> 결과 저장
Host             Unified Buffer    MXU (MAC Array)            Activation Unit  Unified Buffer
```

- 1단계 [명령어 인출]: Host CPU가 PCIe를 통해 복합 명령어(CISC 형태)를 TPU Control Unit으로 전송
- 2단계 [가중치 로드]: 오프칩 메모리(DDR/HBM)에서 가중치 데이터를 온칩 Unified Buffer로 선적재
- 3단계 [시스톨릭 연산]: 입력 데이터가 MXU 배열의 행과 열을 따라 흐르며 곱셈-누적(MAC) 연산을 연속 수행
- 4단계 [활성화 및 반환]: 연산 결과를 Activation Unit에 통과시킨 후 통합 버퍼를 거쳐 Host로 반환

> 요약: 가중치를 고정하고 입력 데이터가 연산기 배열을 물결처럼 통과하는 구조로, 레지스터 병목을 제거하고 처리량을 극대화한다.

---

## Ⅳ. 특징
- 고전성비 아키텍처: 분기 예측, 캐시 계층 등 범용 제어 로직을 제거하고 트랜지스터의 90% 이상을 산술 연산에 할당
- 저정밀도 포맷 적용: 딥러닝의 내결함성(Fault-tolerance)을 활용해 8비트 정수(INT8) 또는 16비트 부동소수점(Bfloat16) 연산으로 메모리 효율 향상
- 특정 프레임워크 종속성: TensorFlow, JAX 등 구글 주도 생태계에 최적화되어 있어 타 프레임워크 이식성이 다소 낮음

> 요약: 극단적인 연산 밀도와 와트당 성능을 얻은 대신, 프로그래밍 유연성과 범용 워크로드 처리 능력은 포기한 트레이드오프를 갖는다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | GPU | TPU | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 다수 코어의 SIMT 구조 | 시스톨릭 배열 기반 ASIC | 연산의 규칙성 |
| 비용/성능 | 범용성 높음, 전력 소모 높음 | AI 전용, 와트당 성능 압도적 우위 | 전성비 및 구축 규모 |
| 운영/위험 | PyTorch 등 다양한 생태계 지원 | TensorFlow 중심, 구글 클라우드 종속 | 클라우드 환경 벤더 락인 |

> 요약: 다양한 모델 R&D 목적이라면 범용적인 GPU가 유리하며, 확정된 거대 모델의 대규모 서비스라면 전력 효율이 높은 TPU가 유리하다.

**리스크·대응 (기본 불릿):**
- 클라우드 벤더 종속성: 구글 클라우드(GCP) 환경에 강하게 결속됨 → ONNX 등 범용 모델 포맷 변환 및 컨테이너 기반 하이브리드 아키텍처 준비 (지표: 프레임워크 마이그레이션 소요 시간)
- 모델 범용성 부족: 희소 행렬(Sparse Matrix)이나 순차적 RNN 모델에서는 성능 저하 → 대규모 밀집 행렬 연산(Dense Matrix, CNN, Transformer)으로 타겟 워크로드 한정 (지표: MXU 활용률)
- 메모리 대역폭 한계(Memory Wall): 모델 파라미터 급증 시 HBM 대역폭 포화 → Pod 단위의 광학 인터커넥트 연결 및 모델 병렬화 분산 처리 (지표: 통신 대비 연산 시간 비율)

**도입 후 점검 지표:**
- 처리량(Throughput): TOPS (초당 테라 연산 횟수) — 초당 처리 가능한 추론 이미지 수 또는 토큰 수 측정
- 전력 효율: TOPS/W (와트당 처리량) — 데이터센터 단위 전력 소모량 모니터링

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. LLM 학습 클러스터 구축: 수천 개의 TPU 칩을 OCS(광 회선 스위치)로 연결한 TPU Pod를 구성하여 GPT 등 거대 모델의 학습 시간을 수개월에서 수주 단위로 단축
2. Bfloat16 양자화 적용: 모델 파라터를 32비트(FP32)에서 Bfloat16으로 변환하여 메모리 대역폭 요구량을 절반으로 줄이고 정확도 저하 없이 학습 가속
3. TensorFlow 기반 MLOps 파이프라인: XLA(Accelerated Linear Algebra) 컴파일러를 적용하여 고수준 연산 그래프를 TPU 기계어로 자동 최적화

**결론 (2줄):**
- 기술사 판단: TPU는 대규모 언어 모델(LLM)과 같이 밀집 행렬 연산이 주를 이루는 환경에서 에너지 효율과 처리 비용을 극대화하는 최적의 솔루션이다.
- 향후 방향: 클라우드용 고성능 TPU와 디바이스단 추론용 Edge TPU로 양극화되며, 차세대 메모리(HBM3E) 및 광학 스위칭(OCS) 도입으로 시스템 스케일 확장에 주력할 것이다.
