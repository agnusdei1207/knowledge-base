## 미리 알고가기

- TPU는 텐서 연산을 전용 데이터패스로 처리하는 AI 가속기임
- MXU·시스톨릭 배열(Systolic Array)·HBM이 핵심 하드웨어 구성임
- XLA는 지원 연산을 융합하고 행렬 연산을 MXU 실행 형태로 변환함
- MAC(Multiply-Accumulate) 연산: 곱셈과 누산을 한 번에 수행하는 연산으로 행렬 곱의 기본 단위임
- 폴백(Fallback): 컴파일러가 지원하지 않는 연산을 만나면 다른 처리 장치로 실행을 넘기는 동작임

## 작성 근거(검토용)

- TPU는 MXU, 시스톨릭 배열, XLA, 집단 통신망을 핵심 구성으로 설명함
- 비교표는 GPU, TPU, NPU의 배치 처리 구조, 생태계 의존성, 실행 환경을 대비함
- 실무 판단은 비지원 연산 수, 학습 단계 시간, MXU 사용률, 전체 합산 통신 시간으로 구체화함

## Ⅰ. 개요

- **정의/개념**: TPU는 딥러닝의 행렬 곱과 텐서 연산을 전용 배열과 메모리 구조에 매핑해 학습과 추론을 수행하는 AI 전용 프로세서임
- **배경/필요성**: 반복 텐서 연산의 명령 제어 부담과 데이터 이동량을 줄이기 위해 전용 배열과 컴파일러 최적화가 필요함

### 쉽게 이해하기 (학습용)
- 곱셈표를 계산하는 전용 계산판(시스톨릭 배열)에 숫자를 흘려보내 한 번에 대량 곱셈을 처리하는 것과 같음

## Ⅱ. 특징

- 행렬 곱을 시스톨릭 배열에 배치해 MAC 연산을 반복 처리함
- 프레임워크의 그래프 구성과 XLA 연산 융합이 MXU 사용률을 좌우함
- 비지원 연산이 많으면 다른 장치로 전환하는 폴백 시간이 늘어남
- 다중 TPU의 집단 통신 시간이 학습 단계 시간을 좌우함

### 쉽게 이해하기 (학습용)
- 컨베이어 벨트(시스톨릭 배열)에 숫자가 흐르며 곱하고 더하는 일을 반복하고, 작업을 미리 묶어주는 재단사(XLA)가 있어야 벨트가 쉬지 않으며, 벨트가 못 다루는 작업은 다른 곳(폴백)으로 보냄

## Ⅲ. 종류 및 비교

| 판단 기준 | GPU | TPU | NPU |
|:---|:---|:---|:---|
| 배치 처리 구조 | 다수 스레드가 그래픽·과학·AI 커널을 병렬 처리 | MXU에 텐서를 묶어 배치 실행 | 전용 배열에서 지원 신경망 연산을 처리 |
| 생태계 의존성 | CUDA 중심 | XLA, 프레임워크 중심 | 벤더 런타임 중심 |
| 실행 환경 | 서버·워크스테이션 | 클라우드 AI 클러스터 | 모바일·PC·엣지 |

> 요약: TPU는 텐서를 MXU에 묶어 실행하고 GPU는 다수 스레드로 커널을 병렬 실행하며 생태계와 실행 환경이 다름.

### 쉽게 이해하기 (학습용)
- 여러 일감을 동시에 처리하는 다목적 공장(GPU), 곱셈만 전문으로 하는 전용 라인(TPU), 손안에서 돌아가는 소형 작업대(NPU)의 차이임

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| MXU·시스톨릭 배열 | MAC 연산을 반복 수행해 TPU의 행렬 연산 처리량을 결정함 |
| HBM·온칩 메모리 | 텐서 데이터를 공급하며 대역폭이 MXU 사용률을 결정함 |
| XLA 컴파일러 | 모델 그래프를 연산 융합과 배치 최적화를 거쳐 TPU 실행 형태로 변환함 |
| 집단 통신망 | 다중 TPU 사이의 그래디언트·활성값을 교환해 동기화 시간을 결정함 |

> 요약: XLA가 모델 그래프를 MXU·메모리 경로에 배치하고 집단 통신망이 다중 TPU 결과를 동기화함.

### 쉽게 이해하기 (학습용)
- 계산판(MXU), 계산판에 재료를 빠르게 공급하는 파이프(HBM), 작업 순서를 짜는 관리자(XLA), 여러 계산판끼리 진행 상황을 맞추는 무전기(집단 통신망)가 함께 동작함

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 모델 그래프 준비 | --> | 컴파일·배치 최적화 | --> | MXU 연산 실행  | --> | 결과 집계·동기화 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **모델 그래프 준비**: 텐서 연산 그래프를 프레임워크에서 정의함
2. **컴파일 및 배치 최적화**: XLA가 연산 융합과 배치를 조정함
3. **MXU 연산 실행**: 텐서 연산을 배열 구조에서 병렬 실행함
4. **결과 집계 및 동기화**: 다중 장치 환경에서는 집단 통신을 수행함

> 요약: 모델 그래프는 XLA 최적화 뒤 MXU에서 실행되고 다중 장치에서는 동기화됨.

### 쉽게 이해하기 (학습용)
- 설계도를 그리고(그래프 준비), 작업 순서를 재배치한 뒤(컴파일 최적화), 계산판에서 찍어내고(MXU 실행), 여러 라인의 결과를 한데 모으는(집계·동기화) 공정과 같음

## Ⅵ. 실무 사례

1. 언어 모델 학습은 XLA 비지원 연산을 대체·융합하고 비지원 연산 수·학습 단계 시간을 확인함
2. TPU 클러스터는 계산과 집단 통신을 중첩하고 MXU 사용률·전체 합산 통신 시간을 확인함

### 쉽게 이해하기 (학습용)
- 번역 공장은 표준 라인이 못 다루는 작업을 미리 손봐두고, 여러 공장이 함께 일할 땐 계산과 연락을 동시에 진행해 대기 시간을 줄임

## Ⅶ. 결론

- TPU는 행렬·텐서 연산을 시스톨릭 배열에 매핑해 MAC 연산을 반복 처리함으로써 명령 제어 부담과 데이터 이동량을 줄이는 전용 프로세서임
- 행렬 연산 비중이 높은 AI 워크로드에 적용하되, XLA 비지원 연산 비율과 다중 TPU의 집단 통신 시간을 판단해 폴백·동기화 지연을 통제해야 함

### 쉽게 이해하기 (학습용)
- 곱셈이 많은 일감일수록 전용 라인이 유리하지만, 라인이 못 다루는 작업 비율과 여러 라인 간 연락 시간까지 함께 따져야 함
