# 📖 【암기용】 개념 완전 이해

> 목적: 이 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: **TPU(Tensor Processing Unit)**는 구글이 자체 설계한 **AI 전용 ASIC**로, **시스톨릭 어레이(Systolic Array)** 구조의 **MXU(Matrix Multiply Unit)**를 이용해 행렬 곱셈-누산(MAC) 연산을 하드웨어 배선 수준에서 가속하는 도메인 특화 아키텍처(DSA, Domain-Specific Architecture)다.
- **왜 필요한가**: 딥러닝 연산의 대부분(수십~수백억 회)은 A×B+C 형태의 단순한 MAC 연산인데, 범용 CPU/GPU는 연산 하나마다 레지스터·캐시·메모리를 오가며 데이터를 주고받는다. 문제는 이 "데이터를 가져오는 행위" 자체가 실제 곱셈·덧셈보다 훨씬 큰 에너지·시간을 잡아먹는다는 점이다(메모리 벽, Memory Wall) — 논문 수치로는 메모리 접근이 연산 자체보다 수십~수백 배 비싸다고 알려져 있다. 구글은 그래픽 렌더링용 회로, 분기 예측, 범용 캐시 계층 같은 TPU에 불필요한 회로를 전부 걷어내고, 오직 "메모리를 최소한으로 건드리며 행렬 곱셈만 미친 듯이 반복하는" 전용 배선을 ASIC으로 구웠다.
- **핵심 직관**: 일반 프로세서는 택배 상하차와 같다 — 물건(데이터) 하나를 내릴 때마다 창고(메모리)에 다녀와 장부(레지스터)에 적고 다시 온다. TPU의 시스톨릭 어레이는 컨베이어 벨트다 — 메모리에서 물건(가중치)을 딱 한 번만 꺼내 작업대(연산기) 위에 고정해 놓고, 데이터가 벨트를 타고 흘러 들어오면 심장 박동(Systolic)처럼 옆 칸·아래 칸으로 계속 전달되며 중간 저장 없이 곱셈-누산이 폭포처럼 끝난다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 표기/용어 | 의미 | 비유 |
|:---|:---|:---|
| TPU | 구글이 텐서 연산 가속만을 위해 만든 AI 전용 ASIC 칩 — 이 블록 전체의 상위 키워드 | 행렬 곱셈만 하는 전용 공장 |
| ASIC | 특정 용도로만 동작하도록 회로를 물리적으로 고정 제작한 반도체 | 범용 맥가이버 칼이 아니라 전용 드라이버 하나 |
| DSA (도메인 특화 아키텍처) | 특정 연산 도메인(여기선 행렬 연산)에 맞춰 설계를 최적화한 아키텍처 계열 | 요리 전용 부엌 vs 만능 작업실 |
| MXU (Matrix Multiply Unit) | TPU 내부의 핵심 행렬 곱셈 연산 블록. 256×256 크기의 연산기 격자 | TPU의 심장, 65,536칸짜리 바둑판 |
| 시스톨릭 어레이 (Systolic Array) | 연산기(PE)들을 격자로 배치하고, 클럭마다 데이터를 이웃 연산기로 넘겨가며 처리하는 하드웨어 데이터 흐름 구조 | 심장 박동처럼 규칙적으로 데이터를 밀어내는 컨베이어 벨트 |
| PE (Processing Element) | 시스톨릭 어레이를 구성하는 하나의 최소 연산 단위, 보통 MAC 1개를 담당 | 컨베이어 벨트 위 작업자 한 명 |
| MAC (Multiply-Accumulate) | 곱하고(Multiply) 그 결과를 누적(Accumulate)하는 A×B+C 형태의 기본 연산 | 곱해서 더하기를 한 번에 하는 계산기 버튼 |
| 가중치 고정(Weight-stationary) | 가중치 값을 PE 내부 레지스터에 한 번 로드해 고정해두고, 활성화값(입력)만 흘려보내며 재사용하는 데이터 흐름 방식 | 작업대에 부품(가중치)을 미리 고정해두고 원자재(입력)만 계속 흘려보냄 |
| Unified Buffer | MXU 앞뒤에 붙은 대용량 온칩 SRAM. 활성화값을 담아두고 외부 DRAM 왕복을 줄임 | 작업장 바로 옆 원자재 창고 |
| SRAM / HBM | SRAM은 칩 내부의 빠른 소용량 메모리, HBM(High Bandwidth Memory)은 칩 옆에 적층된 고대역폭 외부 메모리 | SRAM=책상 서랍, HBM=바로 옆방 대형 서고 |
| FP32 | 부호 1비트 + 지수 8비트 + 가수 23비트 = 32비트 부동소수점. 정밀하지만 무거움 | 소수점 8자리까지 정밀한 저울 |
| FP16 | 부호 1비트 + 지수 5비트 + 가수 10비트 = 16비트. 가볍지만 표현 범위(지수)가 좁음 | 눈금은 세밀한데 저울 자체가 작아 큰/작은 무게는 못 잼 |
| Bfloat16 (BF16) | 부호 1비트 + 지수 8비트 + 가수 7비트 = 16비트. 구글이 TPU 학습용으로 만든 포맷 | 눈금(정밀도)은 성기게, 저울 범위(지수)는 FP32와 동일하게 유지 |
| INT8 양자화 | 부동소수점 값을 8비트 정수 범위(예: -128~127)로 스케일 변환해 표현하는 기법. 추론 전용 | 소수점 저울을 버리고 눈금 256개짜리 정수 저울로 바꿈 |
| TPU Pod | 수천 개의 TPU 칩을 전용 인터커넥트로 직결해 하나의 슈퍼컴퓨터처럼 묶은 클러스터 | TPU 칩들을 광케이블로 이어 붙인 초대형 공장 단지 |
| Torus Network | Pod 내부 칩들을 도넛(토러스) 형태의 격자로 직접 연결하는 네트워크 토폴로지 | 칩들이 원형 컨베이어처럼 서로 순환 연결됨 |
| XLA | 텐서플로우/JAX/PyTorch 코드를 TPU가 이해하는 저수준 명령으로 번역하는 컴파일러 | 사람 언어를 TPU 전용 기계어로 통역하는 통역사 |
| Edge TPU | 클라우드 TPU를 극도로 축소해 저전력(수 W급)으로 만든 INT8 추론 전용 소형 칩 | TPU 공장을 손톱만 하게 축소한 휴대용 버전 |

## 깊이 이해

### 왜 시스톨릭 어레이가 메모리 접근을 줄이는가 — 수치로 확인
- 일반적인(비-시스톨릭) 방식으로 256×256 행렬 곱셈을 한다고 하자. 출력 하나를 계산할 때마다 필요한 가중치 값을 매번 메모리에서 다시 읽어온다면, 가중치 원소 수(256×256=65,536개)를 서로 다른 입력 벡터 256개에 대해 매번 다시 읽어야 하므로 총 가중치 읽기 횟수는 65,536 × 256 = 16,777,216회에 달한다.
- 반면 TPU MXU는 **가중치 고정(Weight-stationary)** 방식을 쓴다. 가중치 65,536개를 SRAM에서 MXU의 각 PE 레지스터로 **딱 한 번만** 로드해 그대로 고정시켜 놓는다. 이후 입력 활성화값들이 클럭마다 배열의 왼쪽/위에서 흘러 들어와 각 PE를 통과하면서 이미 고정된 가중치와 곱해지고, 그 결과(부분합)는 레지스터에 다시 쓰지 않고 바로 옆/아래 PE로 넘겨져(Pass) 누적된다. 이 경우 가중치 읽기는 65,536회로 끝나고, 256개의 서로 다른 입력을 처리해도 추가 가중치 재읽기가 없다 — 위 비교에서 메모리 접근이 약 256배 줄어드는 셈이다.
- 이것이 "시스톨릭(Systolic, 심장 박동)"이라는 이름의 이유다. 심장이 한 번 박동할 때마다 혈액이 혈관을 따라 규칙적으로 밀려나가듯, 클럭 한 번마다 데이터가 배열의 한 칸씩 이웃으로 밀려나가며 중간에 메모리(레지스터 파일)에 다시 쓰이지 않는다.

### MXU 256×256이 의미하는 연산 규모
- MXU는 256행 × 256열, 즉 65,536개의 PE(각 PE는 MAC 1개)로 구성된 격자다. 시스톨릭 파이프라인이 가득 차면 **매 클럭 사이클마다 최대 65,536개의 MAC(곱셈+누산) 연산**이 동시에 진행된다.
- 실제 TPU v1은 약 700MHz 클럭으로 동작했고, MAC 하나는 곱셈 1회 + 덧셈 1회로 2개의 연산(Op)으로 친다. 이론상 최대 처리량은 65,536(MAC) × 2(Op/MAC) × 700,000,000(Hz) ≈ 92조 회/초, 즉 약 92 TOPS(Tera-Operations Per Second, INT8 기준)에 이른다. 이는 구글이 공개한 TPU v1 논문(Jouppi et al., 2017)의 피크 성능 수치와 일치한다.
- Unified Buffer는 이 거대한 연산기 배열이 "굶지 않도록" 활성화값을 미리 담아두는 대용량 온칩 SRAM(TPU v1 기준 24MB)이다. MXU가 65,536개의 MAC을 동시에 돌리려면 그만큼 빠르게 데이터를 공급해야 하는데, 매번 외부 DRAM까지 왕복하면 병목이 생기므로 칩 내부에 큰 버퍼를 둔 것이다.

### 데이터 포맷: FP32 vs FP16 vs BF16 — 비트 구조를 정확히 뜯어보기
- 부동소수점은 [부호][지수][가수] 세 부분으로 이루어진다. 지수부는 표현 가능한 값의 **범위**(얼마나 크거나 작은 수까지 표현하는가)를 결정하고, 가수부는 **정밀도**(소수점 아래 몇 자리까지 세밀하게 구분하는가)를 결정한다.
  - **FP32**: 부호 1비트 + 지수 8비트 + 가수 23비트 = 32비트. 범위도 넓고 정밀도도 높지만 그만큼 메모리와 대역폭을 많이 먹는다.
  - **FP16**: 부호 1비트 + 지수 5비트 + 가수 10비트 = 16비트. 절반 크기지만 지수가 5비트뿐이라 표현 범위가 좁다 — 딥러닝 학습 중 그래디언트 값이 아주 작아지면(예: 10^-8 수준) 이 좁은 범위를 벗어나 0으로 뭉개지는 언더플로우(Underflow)가 발생하기 쉽다.
  - **BF16(Bfloat16)**: 부호 1비트 + 지수 8비트 + 가수 7비트 = 16비트. 크기는 FP16과 같은 16비트지만, 지수부를 FP32와 똑같이 8비트로 유지하고 대신 가수부만 23비트에서 7비트로 잘라냈다.
- **판별 기준**: 지수부가 같다는 것은 표현 가능한 수의 최대/최소 범위(대략 2^-126 ~ 2^127)가 FP32와 동일하다는 뜻이다. 그래서 FP32로 학습하던 모델의 가중치를 BF16으로 바꿀 때 지수를 다시 스케일링할 필요 없이 가수부만 잘라내면 되고(단순 절삭 변환), 언더플로우/오버플로우 위험 없이 메모리 사용량과 대역폭을 절반으로 줄일 수 있다. 이 때문에 구글은 TPU v2부터 학습(Training)에 BF16을 표준으로 채택했다.
- **INT8 양자화**는 아예 부동소수점을 버리고 정수로 바꾸는 방식이다. 예를 들어 가중치의 실제 범위가 [-2.0, 2.0]이라면 스케일 factor = 4.0/255 ≈ 0.0157로 잡고, 각 값을 `round(값/scale)`로 -128~127 정수에 매핑한다. FP32(4바이트) 대비 INT8(1바이트)은 메모리 용량 1/4, 연산기 회로 면적도 크게 줄어(정수 곱셈기는 부동소수점 곱셈기보다 훨씬 단순) 속도와 전력 효율이 동시에 오른다. 다만 오차가 커서 이미 학습이 끝난 모델의 추론(Inference) 단계에만 주로 쓴다.

### 학습(Training)과 추론(Inference)에서 포맷을 다르게 쓰는 이유 — 판별 기준
- 학습은 역전파 과정에서 아주 작은 그래디언트 값을 다뤄야 하므로 넓은 표현 범위가 필수다 → BF16(또는 FP32와 섞어 쓰는 혼합 정밀도)을 쓴다.
- 추론은 이미 학습이 끝난 고정된 가중치로 정방향 계산만 하면 되고, 결과가 "대략 맞으면" 충분하다(예: 개·고양이 분류에서 소수점 7자리 오차는 결과를 바꾸지 않는다) → 정밀도를 과감히 버리고 INT8로 압축해 속도를 극대화한다.
- 이 기준에 따라 TPU v1은 추론 전용으로 INT8 MXU를 채택했고, TPU v2 이후는 학습까지 지원하며 BF16 MXU를 함께 갖췄다.

### TPU Pod와 Torus Network — 칩 하나를 넘어서는 확장
- MXU 하나가 아무리 빨라도 조 단위 파라미터를 가진 LLM은 칩 한 개로 학습할 수 없다. 구글은 수천 개의 TPU 칩을 전용 광 인터커넥트로 직접 연결해 하나의 거대한 연산 자원처럼 묶는데, 이 연결 토폴로지가 **토러스(Torus)** 형태다 — 격자의 양 끝을 서로 이어붙여 도넛처럼 순환하는 구조로, 특정 칩에서 다른 칩으로 가는 평균 경로 길이를 줄이고 특정 링크에 트래픽이 몰리는 병목을 완화한다.
- 이렇게 묶인 클러스터 전체를 **TPU Pod**라 부른다. 파이프라인 병렬화 등 분산 학습 기법과 결합하면, 개별 칩의 MXU 연산 속도뿐 아니라 칩 간 통신 지연이 전체 학습 속도를 좌우하게 되므로 인터커넥트 설계가 MXU 설계만큼 중요하다.

### 비유와 흔한 오해
- **비유**: 시스톨릭 어레이는 심장이다. 심장이 박동할 때마다 혈액(데이터)이 혈관(배선)을 따라 정해진 방향으로 규칙적으로 밀려나가고, 중간에 혈액을 따로 퍼서 저장했다가 다시 흘리는 낭비가 없다.
- **오해 1**: "TPU는 GPU보다 무조건 빠르다." 틀렸다 — TPU는 오직 행렬 MAC 연산에서만 압도적이고, 범용 연산이나 분기가 많은 워크로드에서는 아예 실행조차 못 하거나 비효율적이다. 유연성을 버린 대신 좁은 영역의 효율을 극대화한 것이다.
- **오해 2**: "BF16은 FP16보다 더 정밀하다." 틀렸다 — 오히려 가수부가 7비트로 FP16(10비트)보다 더 적어 정밀도는 낮다. BF16의 장점은 정밀도가 아니라 FP32와 동일한 넓은 표현 범위(지수부)를 유지한다는 점이다.
- **오해 3**: "MXU 256×256은 한 번에 256×256 행렬 곱셈 전체를 끝낸다." 정확히는 매 클럭 65,536개의 MAC이 동시에 진행되는 것이고, 더 큰 행렬은 이 MXU 크기 단위로 잘라(타일링) 여러 클럭에 걸쳐 흘려보낸다.

## 연결 개념
- 049 ASIC/AI 가속기 일반론 (상위 개념 — TPU는 그중 구글이 만든 구체적 제품이며, 이 문서는 MXU 규모·데이터 포맷 같은 TPU 고유의 아키텍처 디테일에 집중한다)
- 텐서(Tensor) — 다차원 데이터 덩어리. TPU의 "T"가 가리키는 연산 대상
- 양자화(Quantization) — INT8처럼 부동소수점을 저비트 정수로 압축하는 일반 기법. TPU는 이를 하드웨어로 구현한 대표 사례
- 폰 노이만 병목 / 메모리 벽 — 시스톨릭 어레이가 근본적으로 해결하려는 상위 문제

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: TPU(Tensor Processing Unit)는 구글이 텐서플로우 프레임워크의 다차원 행렬 곱셈-누산(MAC) 연산을 극단적으로 가속하기 위해, 시스톨릭 어레이(Systolic Array) 기반으로 자체 설계(In-house)한 맞춤형 반도체(ASIC)다.

> 3. **판단 포인트**: 범용성(유연성)은 제로에 수렴하지만, 클라우드(GCP) 환경의 TPU Pod 클러스터링을 통해 초거대 LLM 학습(Training)과 Edge TPU를 통한 온디바이스 추론(Inference) 양단에서 수직 계열화된 독점적 효율성을 제공한다.

## Ⅰ. 개요 및 필요성

- 정의: 클라우드 기반 딥러닝 인프라의 폭발적인 연산량(MAC)을 감당하기 위해, 구글이 오직 텐서(Tensor) 연산 최적화를 목적으로 개발한 도메인 특화 아키텍처(DSA) 기반 ASIC 가속기
- 배경: 머신러닝 워크로드에 범용 GPU(NVIDIA)를 사용할 경우, 필요 없는 그래픽 제어 회로 및 복잡한 부동소수점(FP32) 연산 로직으로 인해 데이터센터의 전력(TCO) 및 냉각 한계 봉착
- 필요성: 캐시나 분기 예측(Branch Prediction) 같은 잉여 기능을 완벽히 제거하고, 행렬 데이터가 유입되면 파이프라인을 따라 중간 저장 없이 끝단까지 흘러가는 물리적 하드웨어 배선(Hard-wired)을 통한 극한의 효율성 확보

## Ⅱ. 구조 및 구성요소 (시스톨릭 어레이 아키텍처)

TPU가 폰 노이만의 메모리 병목을 피하는 꼼수는 "레지스터를 안 쓰고 값을 옆 사람한테 던지는 것(Passing)"이다.

```text
[TPU 핵심 연산 엔진: MXU (Matrix Multiply Unit) 시스톨릭 어레이 흐름]
+========================================================================+
| [ 대규모 온칩 메모리 (SRAM, 24MB) ]  ====> (가중치 Weight 데이터 1회 로드) |
|          ||                                                            |
|          \/ (맥박: 클럭 사이클마다 데이터가 우측/하단으로 파도처럼 밀려감) |
| +--------------------------------------------------------------------+ |
| | [ ALU(MAC) ] -> [ ALU(MAC) ] -> [ ALU(MAC) ]  (256 x 256 바둑판 배열) |
| |       |               |               |                              |
| | [ ALU(MAC) ] -> [ ALU(MAC) ] -> [ ALU(MAC) ]  (단일 사이클에 65,536개 MAC)|
| +--------------------------------------------------------------------+ |
|          \/ (어레이를 완전히 관통할 때까지 중간 메모리 저장 없음)          |
| [ Activation 유닛 (ReLU, Sigmoid 연산 전담 회로) ] -> 최종 결과 출력      |
+========================================================================+
```

| 핵심 구성요소 | 주요 역할 | CPU/GPU와의 차별점 |
|:---|:---|:---|
| MXU (Matrix Unit) | 시스톨릭 어레이 기반의 거대 행렬 곱셈기 | 연산 결과를 레지스터에 쓰지 않고, 인접한 다음 연산기(ALU)의 입력으로 즉각 패스(Pass) |
| Unified Buffer | 칩 내부 온다이(On-die) 거대 SRAM 캐시 | 느린 외부 DRAM과의 통신 I/O를 원천 차단하기 위해 칩 면적의 상당 부분을 할당 |
| Bfloat16 (BF16) 포맷 | AI 학습을 위해 구글이 만든 부동소수점 | FP32와 지수부(8비트)는 똑같이 두어 오차 폭발은 막고, 가수부(23->7비트)를 잘라 대역폭을 2배 이득 봄 |
| HBM & Torus Network | 외부 데이터 공급망 및 칩 간 스케일아웃 | 메모리 대역폭 한계를 HBM 3D 적층으로 돌파하고, 수천 개의 칩을 광링크 토러스 링망으로 직결(TPU Pod) |

> 요약: 일반 칩이 밥(데이터)을 한 숟갈 먹고 창고(메모리)에 다녀온다면, TPU의 시스톨릭 어레이는 컨베이어 벨트를 깔아놓고 입구를 열어 밥을 폭포수처럼 들이붓는 구조다.

## Ⅲ. 동작원리 및 Bfloat16을 통한 메모리 압축 마이크로 흐름

AI 모델 학습 시 엔비디아의 FP32(32비트)를 사용하면 정확하지만 메모리가 터져나간다. 구글은 AI의 허점을 노렸다.

```text
[부동소수점 데이터 표현 형식의 재정의: FP32 vs FP16 vs Bfloat16]
* FP32 (표준)   : [부호 1] + [지수 8] + [가수 23] = 32비트 (가장 정밀하나 무거움)
* FP16 (표준)   : [부호 1] + [지수 5] + [가수 10] = 16비트 (가볍지만 표현 범위가 좁아 AI 학습 시 Underflow 에러로 폭망)
* BF16 (구글형) : [부호 1] + [지수 8] + [가수 7]  = 16비트 (무게는 반으로 줄이고, 표현 범위는 FP32와 동일하게 유지!)
```

| 처리 방식 | 장점 및 H/W 임팩트 | 적용된 TPU 버전 모델 |
|:---:|:---|:---|
| INT8 양자화 (추론용) | 32비트 실수를 8비트 정수로 강제 반올림 변환. 연산기 크기가 1/16로 작아짐 | TPU v1, Edge TPU |
| BF16 포맷 (학습용) | 메모리 대역폭(I/O) 50% 절감, 곱셈기 회로(ALU) 면적 50% 축소 | TPU v2, v3, v4, v5e |

> 요약: 구글은 "AI는 강아지 사진을 고양이로 헷갈리는 게 문제지, 소수점 7자리 숫자가 조금 틀리는 건 대세에 지장 없다"는 사실을 간파하고 과감하게 정밀도(가수부)를 잘라버려 H/W 효율을 폭발시켰다.

## Ⅳ. 심화 비교: 엔비디아 텐서 코어(Tensor Core) vs 구글 TPU

TPU의 엄청난 성공에 기겁한 NVIDIA는 범용 GPU 내부에 '미니 TPU' 격인 텐서 코어(Tensor Core) 블록을 강제로 박아 넣기 시작했다.

| 구분 | NVIDIA GPU (Tensor Core 탑재) | Google TPU (ASIC 전용) | 아키텍처 선택 기준 |
|:---|:---|:---|:---|
| 하드웨어 정체성 | 범용 SIMT 기반 + 부분적 행렬 가속 회로 | **오직 행렬 텐서 연산만을 위한 시스톨릭 고정 회로** | 유연성(NVIDIA) vs 전성비(Google) |
| 가용 프레임워크 | CUDA 기반 모든 S/W (PyTorch 등 생태계 100%) | **TensorFlow, JAX 중심** (코드 호환성 제약 존재) | 개발 편의 및 벤더 종속성(Lock-in) |
| 클러스터 확장망 | InfiniBand, NVLink 스위치 기반 | **칩 자체 내장 라우터로 3D Torus Direct 연결 (Pod)** | 초거대 트랜스포머 분산 학습 효율 |
| 판매 및 접근 모델| 그래픽 카드를 돈 주고 직접 사서 온프레미스 구축 | 칩을 절대 안 팖. 오직 **Google Cloud(GCP) 임대만 가능** | 인프라 내재화 여부 (CAPEX vs OPEX) |

> 요약: 엔비디아가 다용도 SUV 짐칸에 스포츠카 엔진을 얹었다면, 구글 TPU는 애초에 의자도 에어컨도 다 빼고 오직 F1 서킷만 돌게 만든 뼈대뿐인 레이싱카다.

## Ⅴ. 제약 사항 및 TPU 종속성(Lock-in) 한계 극복 기술

| 리스크 | 발생 원인 | 생태계 대응 방안 및 아키텍처 진화 | 극복 원리 및 효과 |
|:---|:---|:---|:---|
| 극심한 S/W 락인 | TPU를 쓰려면 오직 구글 텐서플로우 컴파일러(XLA)를 거쳐야만 동작하므로, 연구계 대세인 파이토치(PyTorch) 코드 이식 시 성능 폭락 및 에러 발생 | **PyTorch / XLA 프로젝트 통합** | 메타(Meta)와 구글이 협력하여, PyTorch 스크립트를 TPU의 중간 언어(XLA)로 즉각 번역/컴파일해주는 드라이버 레이어 고도화로 생태계 이탈 방어 |
| 알고리즘 경직성 | CNN(비전) 기반 행렬 최적화로 구워놨더니, LLM 시대의 트랜스포머(Attention) 희소 행렬(Sparse Matrix) 연산에서 바둑판(MXU)의 연산 유닛들이 공회전(Idle) | **Sparse (희소) 행렬 가속 회로 도입** | TPU v4부터 행렬 안에 '0'이 많은 데이터(희소성)가 들어오면 0 연산을 건너뛰거나(Skip), 압축하여 MXU에 쑤셔 넣는 분기 예측 펌웨어/회로 추가 내장 |
| 엣지 확장 실패 | 데이터센터 TPU는 수냉식이 필요할 만큼 거대하여 자율주행차나 IoT 센서 같은 오프라인 엣지 환경 이식이 불가능함 | **Coral Edge TPU 다이 분리형 아키텍처** | 동전보다 작은 사이즈(수십 mW)로 양자화(INT8) 전용 TPU 코어를 떼어내어 USB나 PCIe 형태로 판매. Raspberry Pi 등 모바일 로봇 디바이스에 AI 오프로딩 장착 |

> 요약: 맞춤형 칩(ASIC)의 숙명은 "알고리즘 트렌드가 바뀌면 칩을 버려야 한다"는 공포다. 구글은 XLA 컴파일러(소프트웨어)의 마법으로 칩의 물리적 경직성을 억지로 무마하며 생명 연장을 거듭하고 있다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. LLM(대규모 언어 모델) 초거대 분산 학습을 위한 TPU Pod 구축: Gemini 등 조 단위 파라미터 모델 훈련 시, 4096개의 TPU v4 칩을 3D Torus 광케이블 네트워크로 직결한 거대 클러스터(Pod)에 파이프라인 병렬화(Pipeline Parallelism) 기법을 적용하여 엔비디아 NVLink 랙 스케일을 초과하는 선형적 스케일아웃 달성
2. 검색/광고 추천 시스템(DLRM) 초저지연 추론 클러스터 도입: 구글 검색 및 유튜브 추천 알고리즘의 유저 반응 속도를 보장하기 위해, 범용 GPU 렌탈 비용 대신 추론 전용 칩인 TPU v5e 인스턴스를 스팟(Spot)으로 프로비저닝하여, 초당 수백만 건의 임베딩 룩업 및 MAC 연산을 기존 대비 TCO 50% 수준으로 컷다운
3. 제조 현장 스마트 팩토리 Edge TPU 비전 인스펙션: 컨베이어 벨트를 훑는 불량 판정 카메라(IoT)에 무거운 x86+GPU PC를 설치하는 대신, 2W 전력만 먹는 USB 타입의 Coral Edge TPU 가속기를 장착하고, MobileNet V2 모델을 INT8 양자화로 배포하여 클라우드 전송 지연(Network Latency) 없이 밀리초(ms) 단위 로컬 불량 검출 시현

**결론 (2줄):**
- 기술사 판단: TPU는 폰 노이만 메모리 병목을 시스톨릭 어레이 하드웨어 구조로 돌파한 도메인 특화 아키텍처(DSA)의 정수이자, 소프트웨어 기업(구글)이 실리콘 반도체를 직접 깎는 실리콘 내재화(In-house)의 신호탄이다.
- 향후 방향: 엔비디아가 GPU 내부에 TPU 기능을(Tensor Core) 모방 흡수하고 역공하는 가운데, 차세대 TPU는 단일 칩의 연산력을 넘어 수만 개의 칩을 광(Optical) 스위치로 완벽히 묶어내는 스케일아웃(Scale-out) 인터커넥트 네트워킹(OCI) 전쟁으로 확전되고 있다.
