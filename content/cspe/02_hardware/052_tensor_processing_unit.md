## 미리 알고가기

- Tensor: 딥러닝에서 벡터, 행렬, 다차원 배열을 일반화한 데이터 단위임
- TPU: 텐서 처리 장치(Tensor Processing Unit, TPU)는 텐서 연산을 전용 데이터패스로 처리하는 가속기임
- Systolic Array: 데이터가 배열 내부를 박동처럼 이동하며 곱셈-누산(Multiply-Accumulate, MAC) 연산을 반복하는 구조임
- XLA: 가속 선형 대수(Accelerated Linear Algebra, XLA)는 모델 그래프를 하드웨어 실행에 맞게 최적화하는 컴파일러 계층임
- Collective 통신: 여러 가속기 간 gradient나 tensor를 집계하는 통신 연산임

## Ⅰ. 개요

- **정의**: TPU는 딥러닝 모델의 텐서 연산을 대규모 MAC 배열과 고대역폭 메모리(High Bandwidth Memory, HBM)에 매핑해 행렬 연산 비중, 모델 그래프, 배치 처리량 기준으로 학습·추론 처리 효율을 높이는 전용 프로세서임.
- **배경/필요성**: 대형 신경망은 행렬 곱과 컨볼루션이 연산량 대부분을 차지하며 중앙처리장치(Central Processing Unit, CPU)와 범용 그래픽 처리 장치(Graphics Processing Unit, GPU)만으로는 비용과 전력 부담이 커짐. TPU는 텐서 연산 경로를 전용화해 대규모 인공지능(Artificial Intelligence, AI) 서비스의 처리 효율을 높임.
- **비유**: 일반 계산기가 아니라 행렬 계산만 빠르게 처리하도록 만든 전용 계산 공장과 같음.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 텐서 연산 전용 하드웨어 구조 설명 | Systolic Array, HBM, 컴파일러, 모델 제약 | GPU와 같은 범용 병렬처리로 설명 |

> 요약: TPU는 딥러닝 텐서 연산을 전용 하드웨어와 컴파일러로 실행해 전력당 처리량을 높이는 장치임.

## Ⅱ. 특징/비교

| 판단 기준 | GPU AI 가속 | TPU 텐서 처리 |
|:---|:---|:---|
| 실행 구조 | 단일 명령 다중 스레드(Single Instruction Multiple Threads, SIMT) 코어와 텐서 코어를 조합해 범용 병렬성을 제공함 | 텐서 그래프를 전용 행렬 배열과 메모리 흐름에 맞춤 |
| 유연성 | 다양한 커널과 프레임워크 지원이 넓음 | 지원 연산자와 컴파일러 최적화 범위에 성능이 의존함 |
| 적용 기준 | 다양한 모델 실험과 혼합 워크로드에 유리함 | 큰 배치, 규칙적 텐서 연산, 클러스터 학습에 유리함 |

> 요약: TPU는 범용성보다 텐서 연산 효율과 클러스터 처리량이 중요한 환경에서 선택됨.

## Ⅲ. 구성요소

```text
+----------+     +----------+     +-------------+
| AI Graph | --> | Compiler | --> | Systolic MXU|
+----------+     +----------+     +-------------+
                                      |
                     +----------------+----------------+
                     v                                 v
              +-------------+                   +-------------+
              | HBM/SRAM    |                   | Interconnect|
              +-------------+                   +-------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 행렬 연산 유닛 | 수축기식 행렬 연산 유닛(Matrix Multiply Unit, MXU)이 MAC 연산을 대량 병렬로 수행함 | 행렬 전용 생산라인 |
| 메모리 계층 | HBM과 정적 램(Static Random Access Memory, SRAM) 기반 온칩 버퍼가 텐서와 가중치를 공급함 | 원자재 창고 |
| 컴파일러 | 모델 그래프를 분할, 배치, fusion해 하드웨어 명령으로 변환함 | 공정 설계자 |
| 인터커넥트 | 여러 TPU 사이의 텐서 집계와 동기화를 지원함 | 공장 간 물류망 |

> 요약: TPU는 행렬 배열, 메모리, 컴파일러, 클러스터 인터커넥트가 함께 텐서 처리량을 만듦.

## Ⅳ. 절차

```text
+----------+     +----------+     +----------+     +----------+
| Compile  | --> | Tile     | --> | MAC Run  | --> | Reduce   |
+----------+     +----------+     +----------+     +----------+
```

1. **그래프 컴파일**: 모델 연산자를 TPU가 지원하는 텐서 연산과 정밀도로 변환함
2. **텐서 배치**: 텐서와 가중치를 HBM, SRAM, 연산 배열에 맞게 타일링함
3. **배열 연산**: Systolic Array가 데이터 흐름에 맞춰 MAC 연산을 반복 수행함
4. **집계/반환**: 다중 장치 결과를 collective 통신으로 동기화하고 출력 텐서를 반환함

> 요약: TPU 실행은 모델 그래프를 컴파일해 텐서 흐름과 행렬 배열에 맞춰 처리하는 과정임.

## Ⅴ. 문제점

- **P1 연산자 제약**: 지원되지 않는 연산자나 동적 제어 흐름은 CPU/GPU fallback을 유발해 성능이 낮아짐
- **P2 입력 파이프라인 병목**: 데이터 로딩과 전처리가 느리면 연산 배열이 유휴 상태가 됨
- **P3 플랫폼 의존성**: 특정 클라우드, 런타임, 컴파일러에 의존하면 이전 경로와 운영 선택지가 제한됨

> 요약: TPU 성능은 전용 하드웨어보다 모델 호환성, 데이터 공급, 플랫폼 운영성에 의해 제한될 수 있음.

## Ⅵ. 개선방안

- **P1 대응**: XLA 지원 연산자 확인, 모델 graph rewrite, fallback 구간 측정을 수행함 (확인: TPU 실행 연산 비율)
- **P2 대응**: 데이터 캐시, 병렬 전처리, prefetch, 입력 sharding을 적용함 (확인: accelerator utilization)
- **P3 대응**: 모델 export 경로, 비용 기준, 대체 GPU 실행 계획을 함께 설계함 (확인: 이전 가능한 모델 수)

> 요약: 개선은 모델-컴파일러 적합성 검증과 데이터 공급 최적화, 운영 종속성 관리로 이루어짐.

## Ⅶ. 전망

- **발전 방향**: TPU류 가속기는 대규모 언어 모델(Large Language Model, LLM), 추천, 멀티모달 모델을 위해 대규모 메모리와 고속 인터커넥트 중심으로 진화함
- **기술사적 판단**: TPU 선택은 모델 연산 패턴, 배치 크기, 데이터 파이프라인, 클라우드 비용을 함께 비교해야 함
- **기술사 제언**: 답안에서는 텐서 전용 구조와 컴파일러 제약을 함께 제시해 전용 가속기의 장단을 균형 있게 설명해야 함
