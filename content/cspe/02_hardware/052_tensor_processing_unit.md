# 📖 【암기용】 개념 완전 이해

> 목적: TPU를 처음 봐도 GPU와 무엇이 다른지, 왜 행렬곱에 특화됐는지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: Google이 설계한 딥러닝 행렬곱 연산 전용 ASIC(Application-Specific Integrated Circuit)
- **왜 필요한가**: 딥러닝 연산의 대부분은 행렬곱-누산(MAC, Multiply-Accumulate)이다. TPU는 이 연산만 극도로 효율화한 전용 회로(systolic array)로 GPU 대비 동일 전력에서 더 높은 행렬곱 처리량을 노린다.
- **핵심 직관**: 범용 공구함(GPU) 대신 특정 나사 규격 하나만 초고속으로 조이는 전용 자동화 라인.

## 깊이 이해
- **배경·문제의식**: 2015년 Google은 자사 데이터센터의 추론 연산(검색·번역·이미지 인식) 전력 비용을 줄이기 위해 TPU v1(추론 전용, INT8)을 자체 개발했다.
- **작동 원리**: 핵심은 systolic array 구조로, 수백~수천 개의 MAC 유닛이 격자로 배치되어 데이터가 유닛 사이를 흐르며(streaming) 행렬곱을 누적한다. 별도 레지스터 접근 없이 인접 유닛 간 전달만으로 연산해 메모리 접근 오버헤드를 줄인다.
- **비유**: 컨베이어 벨트 위에서 부품(데이터)이 흐르며 각 스테이션(MAC 유닛)이 순서대로 곱셈·누적만 수행하는 조립 라인.
- **구체 예시**: TPU v1은 추론 전용 INT8 연산만 지원했고, TPU v2부터 학습까지 지원하며 bfloat16(BF16, Google이 딥러닝용으로 정의한 16비트 부동소수점 포맷) 연산을 도입했다. 이후 세대는 ICI(Inter-Chip Interconnect)로 다수 칩을 묶어 TPU Pod을 구성한다.
- **흔한 오해·주의점**: TPU가 GPU를 완전히 대체하는 범용 가속기는 아니다. TPU는 행렬곱 중심의 정형화된 텐서 연산에 최적화된 것이고, 비정형 제어 흐름이나 그래픽 렌더링, 범용 병렬 연산은 GPU가 더 유연하다.

## 연결 개념
- Systolic Array — TPU 연산 코어의 핵심 데이터플로 구조
- bfloat16(BF16) — TPU 학습에 쓰이는 저정밀 부동소수점 포맷
- ICI(Inter-Chip Interconnect)·TPU Pod — 다중 TPU 칩을 묶는 확장 구조
- GPU SIMT — 범용 병렬 처리 대안 아키텍처(050번 키워드 참고)

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: TPU 답안은 systolic array 구조, GPU와의 목적·유연성 차이, ICI 기반 Pod 확장을 함께 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: TPU (Tensor Processing Unit)는 systolic array 기반 MAC 연산에 특화된 Google의 딥러닝 전용 ASIC이다.
> 2. **가치**: 행렬곱-누산 연산만을 위한 고정 회로로 GPU의 범용 SIMT 구조 대비 동일 전력에서 텐서 연산 처리량을 높인다.
> 3. **판단 포인트**: 정형화된 대규모 행렬곱 workload는 TPU, 비정형 제어·그래픽·범용 병렬 연산은 GPU를 선택 기준으로 삼는다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| ASIC 특화 구조 이해 확인 | systolic array, MAC 유닛, 데이터플로 연산 | TPU를 "GPU의 상위 호환"으로 단순 서술 |
| GPU와의 목적 차이 판단 확인 | TPU=행렬곱 특화 ASIC vs GPU=범용 SIMT 병렬 | 두 아키텍처를 동일 목적의 가속기로 혼동 |
| 확장성·생태계 이해 확인 | ICI, TPU Pod, bfloat16, Google Cloud 종속 | 클라우드 벤더 종속성과 이식성 제약 누락 |

> 요약: 이 문제는 TPU를 GPU의 대체재로 뭉뚱그리지 않고, systolic array 특화 구조와 적용 한계를 구분해 보여야 한다.

## Ⅰ. 개요 및 필요성

- 개요: 딥러닝 행렬곱-누산 연산에 특화된 Google 설계 ASIC
- 배경: 데이터센터 추론 연산의 전력·비용 부담을 줄이기 위해 범용 프로세서 대신 전용 회로를 설계함
- 필요성: 대규모 행렬곱 workload는 범용 명령어 해석 오버헤드 없이 고정 데이터플로 연산이 전력 효율 확보에 유리함

---

## Ⅱ. 구조 및 구성요소

```text
Host -> TPU Chip
  -> Systolic Array (MAC Unit 격자)
  -> On-chip Memory (Weight/Activation Buffer)
  -> HBM (High Bandwidth Memory)
  -> ICI(Inter-Chip Interconnect) -> 다른 TPU 칩
  -> TPU Pod (다중 칩 묶음)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Systolic Array | MAC 유닛 격자에서 데이터가 흐르며 행렬곱 누적 | 인접 유닛 간 전달만으로 연산, 레지스터 접근 최소화 |
| On-chip Buffer | 가중치·활성값 임시 저장 | HBM 접근 빈도를 줄여 지연 감소 |
| HBM | 대용량 고대역폭 메모리 | 대규모 모델 파라미터·활성값 저장 |
| ICI | 칩 간 직접 연결 인터커넥트 | 다중 TPU를 묶어 Pod 단위 학습 확장 |

> 요약: TPU는 systolic array와 온칩 버퍼로 행렬곱을 처리하고, ICI로 여러 칩을 묶어 대규모 학습을 확장한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
모델 가중치·입력 로드 -> On-chip Buffer 적재
  -> Systolic Array에서 MAC 연산 스트리밍 수행
  -> 활성값 다음 레이어로 전달 -> HBM/Buffer 갱신
  -> 다중 칩이면 ICI로 파라미터·그래디언트 교환
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 가중치·입력을 온칩 버퍼에 적재 | 버퍼 적중률, HBM 접근 횟수 |
| 2 | systolic array에서 MAC 연산 스트리밍 수행 | MAC 유닛 활용률(utilization) |
| 3 | 레이어 간 활성값 전달 및 갱신 | 레이어별 처리 지연 |
| 4 | (Pod 구성 시) ICI로 그래디언트 동기화 | all-reduce 시간, 통신 대비 연산 비율 |

> 요약: TPU는 데이터를 systolic array에 흘려 MAC 연산을 수행하고, 다중 칩 학습은 ICI 동기화 효율로 성능이 좌우된다.

## Ⅳ. 특징

| 구분 | TPU | GPU | 수치·표준 포인트 |
|:---|:---|:---|:---|
| 목적 | 딥러닝 행렬곱-누산 특화 | 범용 SIMT 병렬 연산(그래픽·과학계산·딥러닝 포함) | TPU는 워크로드 특화, GPU는 범용성 우위 |
| 연산 구조 | Systolic Array 고정 데이터플로 | 수천 개 CUDA 코어 + Tensor Core SIMT | 유연성은 GPU, 특화 효율은 TPU |
| 정밀도 | INT8(v1, 추론), BF16 등(v2 이후, 학습) | FP32/FP16/INT8/FP8 등 폭넓은 지원 | 워크로드별 정밀도 선택 폭은 GPU가 넓음 |
| 확장 | ICI 기반 TPU Pod | NVLink/InfiniBand 기반 GPU 클러스터(056·057 참고) | 확장 인터커넥트 종류가 다름 |
| 생태계 | Google Cloud, TensorFlow/JAX 최적화 | CUDA 생태계, 범용 프레임워크 폭넓게 지원 | TPU는 클라우드·프레임워크 종속성 존재 |

> 요약: TPU는 행렬곱 특화 효율, GPU는 범용성과 생태계 폭에서 각각 우위를 가진다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | GPU | TPU | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 범용 SIMT + Tensor Core | 행렬곱 전용 systolic array | 워크로드가 정형 행렬곱 중심이면 TPU 우선 |
| 비용/성능 | 다양한 워크로드 대응, 클라우드/온프레미스 선택 폭 넓음 | 대규모 정형 학습에서 전력당 처리량 우수 | 온프레미스 필요 여부와 클라우드 종속 허용도 |
| 운영/위험 | 범용 프레임워크·툴체인 성숙 | Google Cloud 종속, 커스텀 연산 유연성 제한 | 벤더 종속 리스크와 이식성 요구 수준 |

> 요약: 정형 행렬곱 대규모 학습은 TPU, 범용성·이식성이 필요한 환경은 GPU를 선택한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 벤더·클라우드 종속 | TPU가 Google Cloud 중심 서비스로 제공 | 멀티클라우드 전략, 프레임워크 추상화(JAX/XLA) 유지 | 이식 소요 시간, 대체 하드웨어 가용성 |
| 워크로드 부적합 | 비정형 제어·희소 연산에 systolic array 비효율 | 워크로드 프로파일링 후 GPU/TPU 혼합 배치 | MAC 유닛 활용률, idle cycle 비율 |
| Pod 확장 병목 | ICI 대역폭 대비 통신량 과다 | 데이터/모델 병렬화 전략 재설계 | all-reduce 시간, 통신-연산 오버랩 비율 |

> 요약: TPU 운영 리스크는 벤더 종속, 워크로드 부적합, Pod 통신 병목이며 각각 이식성·프로파일링·병렬화 전략으로 통제한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 연산 효율 | MAC 유닛 활용률 목표치 이상 유지 | 프로파일러(XLA profiler) |
| 학습 처리량 | step time, samples/sec 목표 대비 달성 여부 | 학습 로그, 벤치마크 |
| 확장 효율 | Pod 규모 증가 대비 처리량 선형성 | scaling efficiency 측정 |

> 요약: 도입 성과는 MAC 활용률, 학습 처리량, Pod 확장 선형성으로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 대규모 정형 행렬곱 중심 학습(대형 언어모델·이미지 모델)은 TPU Pod를 적용하고 all-reduce 통신 비율을 점검함
2. 비정형 연산·다양한 프레임워크 지원이 필요한 R&D 환경은 GPU 클러스터를 유지하고 워크로드별 프로파일링으로 배치를 결정함
3. 벤더 종속 완화를 위해 XLA·JAX 같은 컴파일러 추상화 계층을 유지해 TPU/GPU 간 이식 비용을 낮춤

**결론 (2줄):**
- 기술사 판단: 정형 대규모 행렬곱 학습은 TPU, 범용성·이식성·다양한 워크로드는 GPU를 선택 기준으로 삼음
- 향후 방향: TPU 세대별 ICI 대역폭 확장과 BF16/INT8 등 저정밀 연산 지원 강화로 학습·추론 효율을 지속 개선하는 방향으로 발전함
