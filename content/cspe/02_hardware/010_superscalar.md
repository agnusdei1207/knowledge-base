## 미리 알고가기

- 슈퍼스칼라는 한 클록에 여러 명령어를 발행하는 구조임
- ILP를 하드웨어가 동적으로 찾아 병렬 실행함
- 비순서 실행과 ROB가 함께 동작하는 경우가 많음

## 작성 근거(검토용)

- 슈퍼스칼라는 실행 유닛 수보다 동적 의존성 분석과 발행 폭의 제약을 설명하도록 구성함
- 스칼라·슈퍼스칼라·VLIW를 동시 발행·병렬성 탐지·바이너리 조건·하드웨어 부담으로 비교함
- 실제 코드가 채우는 발행 슬롯과 동적 탐지 회로 비용을 확장 기준으로 정리함

## Ⅰ. 개요

- **정의/개념**: 슈퍼스칼라는 한 클록 주기에 여러 명령어를 발행하고 복수 실행 유닛에서 병렬 처리하는 명령어 수준 병렬화 구조임
- **배경/필요성**: 클록당 명령어 처리량을 높이기 위해 독립 명령어를 동적으로 찾아 병렬 발행하는 구조가 필요함

## Ⅱ. 특징

- 동적 의존성 분석으로 여러 명령어를 동시에 실행함
- 소프트웨어 수정 없이 기존 바이너리에서 ILP를 활용함
- 발행 폭과 명령 윈도 크기가 늘면 동시에 비교할 의존 관계와 레지스터 파일 포트 수가 증가함
- 분기 실패와 실행 유닛 유휴 슬롯이 성능 상한을 제한함

## Ⅲ. 종류 및 비교

| 판단 기준 | Scalar | Superscalar | VLIW |
|:---|:---|:---|:---|
| 동시 발행·병렬성 탐지 | 1개, 탐지 없음 | N개, 하드웨어 동적 탐지 | N개, 컴파일러 정적 탐지 |
| 바이너리 조건 | 순차 명령어 사용 | 기존 순차 바이너리에서 동적 탐지 | 병렬 슬롯을 포함한 전용 바이너리 필요 |
| 하드웨어 부담·제약 | 단일 발행 제어, 발행 수 제한 | 다중 해독·의존성 검사·ROB, 데이터 의존·분기 실패·빈 슬롯 | 동적 검사 회로 축소, 컴파일러 스케줄과 구현 폭 호환성 필요 |

> 요약: 슈퍼스칼라는 하드웨어가 독립 명령을 동적으로 찾아 한 클록에 여러 명령을 발행하는 구조임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 다중 명령 프런트엔드 | 여러 명령어를 동시에 인출·해독해 발행 대역폭을 제공함 |
| 의존성 검사기 | 데이터·자원 의존성을 판정해 병렬 발행 가능 여부를 결정함 |
| 복수 실행 유닛 | 정수·부동소수점·로드스토어 유닛이 명령어를 병렬 실행함 |
| 재정렬 버퍼 | 비순서로 끝난 결과를 프로그램 순서대로 확정해 상태 일관성을 유지함 |

```text
+----------------+     +-----------------+     +----------------------+
| 다중 명령 프런트엔드 | --> | 의존성 검사기      | --> | 복수 실행 유닛           |
+----------------+     +-----------------+     +----------------------+
                                                |
                                                v
                                         +---------------+
                                         | 재정렬 버퍼      |
                                         +---------------+
```

> 요약: 슈퍼스칼라는 넓은 front-end, 의존성 검사, 복수 실행 유닛, ROB로 병렬 실행과 순차 확정을 함께 처리함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 다중 인출       | --> | 의존성 분석      | --> | 병렬 발행       | --> | 순차 확정      |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **다중 인출**: 한 번에 여러 명령어를 가져옴
2. **의존성 분석**: 병렬 실행 가능한 조합을 찾음
3. **병렬 발행**: 실행 유닛에 동시에 배치함
4. **순차 확정**: 결과를 프로그램 순서대로 반영함

> 요약: 슈퍼스칼라는 발행 폭보다 실제 코드의 독립 명령어와 의존성 검사 비용이 성능을 좌우함.

## Ⅵ. 실무 사례

1. 서버 CPU는 데이터 의존으로 생기는 빈 발행 슬롯을 줄이기 위해 비순서 실행 창을 조정하고, 발행 슬롯 이용률과 IPC로 검증함
2. 모바일 CPU는 전력 예산에 맞게 발행 폭을 조정하고, 와트당 처리량과 발행 슬롯 이용률로 검증함

## Ⅶ. 결론

- 슈퍼스칼라는 발행 폭보다 실제 코드의 독립 명령 수, 발행 슬롯 이용률, 의존성 검사 비용을 기준으로 확장 폭을 정해야 함
