## Ⅰ. 개요
- 정의: 매 사이클마다 여러 개의 명령어를 동시에 발행(Issue)하여 병렬 처리하는 기술
- 배경: 단일 파이프라인의 CPI=1 한계를 극복하고 IPC > 1 달성 필요
- 출제 의도: 다중 실행 유닛(Multiple Functional Units)을 통한 병렬성 확보 전략 이해

## Ⅱ. 구성요소
- ASCII 구조도 (Dual-Issue)
  Cycle:   1       2       3       4
  Inst1: [IF][ID][EX1][MEM][WB]
  Inst2: [IF][ID][EX2][MEM][WB] (동시 발행)
  Inst3:     [IF][ID][EX1][MEM][WB]
  Inst4:     [IF][ID][EX2][MEM][WB]

- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| Issue Unit | 의존성 없는 명령어를 선택하여 동시 발송 | 배차 관리자 |
| Execution Units | 정수, 부동소수점, 로드/스토어 등 다수 유닛 | 여러 개 차선 |
| Dispatcher | 각 명령어를 적절한 실행 유닛으로 할당 | 창구 직원 |
> 요약: 하드웨어적으로 여러 명령어를 동시에 가져와 병렬로 실행함

## Ⅲ. 절차
- ASCII 흐름도
  (Multi-Fetch) -> (Parallel Decode) -> (Dependency Check) -> (Issue)
                                                                 |
                                       +---------<---------<-----+
                                       v
                                (Parallel Execute) -> (Reorder/WB)

- 4단계 설명
1. Multi-Fetch: 한 사이클에 여러 개의 명령어를 명령어 캐시에서 인출
2. 분석: 명령어 간 데이터 및 제어 의존성을 하드웨어가 동적으로 분석
3. Issue: 의존성이 없는 명령어 조합을 실행 유닛으로 동시 전송
4. 병렬 실행: 할당된 다수의 유닛에서 각 명령어를 동시에 수행 및 결과 정리
> 요약: 하드웨어가 런타임에 병렬성을 찾아내어 실행 유닛을 가동시킴

## Ⅳ. 문제점
- 하드웨어 복잡성: 명령어 수가 증가할수록 의존성 체크 로직이 기하급수적으로 복잡
- 자원 활용 불균형: 특정 유닛만 사용되고 나머지는 유휴 상태가 될 가능성 존재

## Ⅴ. 개선방안
- (단기) 정적 스케줄링: 컴파일러가 미리 명령어 순서를 최적화하여 하드웨어 부담 경감
- (중기) 비순차 실행(OoO): 순서와 상관없이 실행 가능한 명령을 먼저 처리
- (장기) SMT(Hyper-threading): 다중 스레드를 활용하여 실행 유닛 점유율 극대화

## Ⅵ. 전망
- 로드맵: 단일 코어의 Wide-Issue(8~16 way) 경쟁에서 전력 효율 중심 설계로 전환
- CSF: 정교한 스케줄링 알고리즘 및 캐시 대역폭 확장을 통한 실행 유닛 가동률 확보
