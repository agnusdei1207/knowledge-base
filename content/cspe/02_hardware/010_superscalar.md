## 미리 알고가기

- ILP(Instruction-Level Parallelism): 서로 의존하지 않아 동시에 실행할 수 있는 명령어 집합임
- 발행 폭(Issue Width): 한 클록에 동시에 발행할 수 있는 명령어 개수임
- 명령 윈도: 발행 대상을 고르기 위해 동시에 살펴보는 명령어 범위임
- 비순서 실행(Out-of-Order Execution): 프로그램 순서와 다르게 준비된 명령어부터 먼저 실행하는 방식임
- 재정렬 버퍼(ROB, Reorder Buffer): 비순서로 끝난 실행 결과를 프로그램 순서대로 확정하는 저장 구조임
- VLIW(Very Long Instruction Word): 컴파일러가 병렬 실행할 명령어 묶음을 미리 정해 하나의 긴 명령어로 인코딩하는 방식임
- IPC(Instructions Per Cycle): 클록 한 주기당 완료하는 명령어 수를 나타내는 처리량 지표임

## 작성 근거(검토용)

- 슈퍼스칼라는 실행 유닛 수보다 동적 의존성 분석과 발행 폭의 제약을 설명하도록 구성함
- 스칼라·슈퍼스칼라·VLIW를 동시 발행·병렬성 탐지·바이너리 조건·하드웨어 부담으로 비교함
- 실제 코드가 채우는 발행 슬롯과 동적 탐지 회로 비용을 확장 기준으로 정리함

## Ⅰ. 개요

- **정의/개념**: 슈퍼스칼라는 한 클록 주기에 여러 명령어를 발행하고 복수 실행 유닛에서 병렬 처리하는 명령어 수준 병렬화 구조임
- **배경/필요성**: 클록당 명령어 처리량을 높이기 위해 독립 명령어를 동적으로 찾아 병렬 발행하는 구조가 필요함

### 쉽게 이해하기 (학습용)
- 계산대 여러 개를 둔 마트에서 줄 선 손님 중 서로 관계없는 손님들을 동시에 여러 계산대로 보내 처리 속도를 높이는 것과 같음

## Ⅱ. 특징

- 동적 의존성 분석으로 여러 명령어를 동시에 실행함
- 소프트웨어 수정 없이 기존 바이너리에서 ILP를 활용함
- 발행 폭과 명령 윈도 크기가 늘면 동시에 비교할 의존 관계와 레지스터 파일 포트 수가 증가함
- 분기 실패와 실행 유닛 유휴 슬롯이 성능 상한을 제한함

### 쉽게 이해하기 (학습용)
- 계산원들이 그 자리에서 손님 관계를 살펴 동시에 처리할 손님을 즉석 판단하며, 대기표(코드)를 바꾸지 않아도 됨
- 계산대를 늘릴수록 손님 조합을 확인할 경우의 수와 필요한 창구도 함께 늘어남
- 안내를 잘못하거나 손님이 안 오면 계산대가 비어 처리 속도가 한계에 부딪힘

## Ⅲ. 종류 및 비교

| 판단 기준 | Scalar | Superscalar | VLIW |
|:---|:---|:---|:---|
| 동시 발행·병렬성 탐지 | 1개, 탐지 없음 | N개, 하드웨어 동적 탐지 | N개, 컴파일러 정적 탐지 |
| 바이너리 조건 | 순차 명령어 사용 | 기존 순차 바이너리에서 동적 탐지 | 병렬 슬롯을 포함한 전용 바이너리 필요 |
| 하드웨어 부담·제약 | 단일 발행 제어, 발행 수 제한 | 다중 해독·의존성 검사·ROB, 데이터 의존·분기 실패·빈 슬롯 | 동적 검사 회로 축소, 컴파일러 스케줄과 구현 폭 호환성 필요 |

> 요약: 슈퍼스칼라는 하드웨어가 독립 명령을 동적으로 찾아 한 클록에 여러 명령을 발행하는 구조임.

### 쉽게 이해하기 (학습용)
- 계산대 한 개로 한 손님씩 받는 매장(Scalar), 계산원이 즉석에서 같이 처리할 손님을 정하는 매장(Superscalar), 본사가 미리 짜준 손님 조합표대로만 움직이는 매장(VLIW)에 비유할 수 있음

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 다중 명령 프런트엔드 | 여러 명령어를 동시에 인출·해독해 발행 대역폭을 제공함 |
| 의존성 검사기 | 데이터·자원 의존성을 판정해 병렬 발행 가능 여부를 결정함 |
| 복수 실행 유닛 | 정수·부동소수점·로드스토어 유닛이 명령어를 병렬 실행함 |
| 재정렬 버퍼 | 비순서로 끝난 결과를 프로그램 순서대로 확정해 상태 일관성을 유지함 |

```text
+----------------+     +-----------------+     +----------------------+
| 다중 명령 프런트엔드 | --> | 의존성 검사기      | --> | 복수 실행 유닛           |
+----------------+     +-----------------+     +----------------------+
                                                |
                                                v
                                         +---------------+
                                         | 재정렬 버퍼      |
                                         +---------------+
```

> 요약: 슈퍼스칼라는 넓은 front-end, 의존성 검사, 복수 실행 유닛, ROB로 병렬 실행과 순차 확정을 함께 처리함.

### 쉽게 이해하기 (학습용)
- 동시에 여러 손님을 접수하는 창구(프런트엔드), 같이 처리 가능한 손님을 가려내는 안내원(의존성 검사기), 실제로 계산하는 여러 계산대(실행 유닛), 계산이 끝난 순서가 뒤섞여도 원래 줄 순서대로 영수증을 내주는 정리대(ROB)가 함께 움직임

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 다중 인출       | --> | 의존성 분석      | --> | 병렬 발행       | --> | 순차 확정      |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **다중 인출**: 한 번에 여러 명령어를 가져옴
2. **의존성 분석**: 병렬 실행 가능한 조합을 찾음
3. **병렬 발행**: 실행 유닛에 동시에 배치함
4. **순차 확정**: 결과를 프로그램 순서대로 반영함

> 요약: 슈퍼스칼라는 발행 폭보다 실제 코드의 독립 명령어와 의존성 검사 비용이 성능을 좌우함.

### 쉽게 이해하기 (학습용)
- 손님을 한꺼번에 여러 명 불러들이고(다중 인출), 서로 안 겹치는 손님을 골라(의존성 분석), 여러 계산대로 동시에 보낸 뒤(병렬 발행), 영수증만은 원래 줄 순서대로 정리해 내어줌(순차 확정)

## Ⅵ. 실무 사례

1. 서버 CPU는 데이터 의존으로 생기는 빈 발행 슬롯을 줄이기 위해 비순서 실행 창을 조정하고, 발행 슬롯 이용률과 IPC로 검증함
2. 모바일 CPU는 전력 예산에 맞게 발행 폭을 조정하고, 와트당 처리량과 발행 슬롯 이용률로 검증함

### 쉽게 이해하기 (학습용)
- 손님 많은 대형 매장은 빈 계산대가 안 생기게 대기줄 관리 폭을 조정하고, 손님 적은 소형 매장은 전기료에 맞춰 여는 계산대 수 자체를 줄이는 것과 같음

## Ⅶ. 결론

- 슈퍼스칼라는 프로그램 순서와 무관하게 독립 명령어를 동적으로 찾아 한 클록에 여러 개를 발행해 클록당 처리량을 높이는 구조임
- 슈퍼스칼라는 발행 폭보다 실제 코드의 독립 명령 수, 발행 슬롯 이용률, 의존성 검사 비용을 기준으로 확장 폭을 정해야 함

### 쉽게 이해하기 (학습용)
- 계산대를 무작정 늘리기보다 실제로 동시에 처리할 손님이 얼마나 되는지, 계산대가 얼마나 놀고 있는지를 보고 몇 개를 열지 정해야 함
