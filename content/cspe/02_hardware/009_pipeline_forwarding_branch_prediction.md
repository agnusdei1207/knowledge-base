## 미리 알고가기

- 포워딩은 데이터 해저드를 줄이는 우회 전달 기법임
- 분기 예측은 제어 해저드를 줄이기 위한 경로 추정 기법임
- 둘 다 CPI를 낮추지만 실패 비용과 구현 난도가 다름

## 작성 근거(검토용)

- 포워딩은 RAW 값 대기, 분기 예측은 제어 흐름 대기라는 서로 다른 해저드 대응으로 분리함
- 포워딩과 분기 예측을 해결 대상·동작 원리·판정 입력·실패 형태로 비교함
- 두 기법을 하나의 공통 흐름으로 묶지 않고 각각의 고유 판정과 복구 흐름으로 나눔

## Ⅰ. 개요

- **정의/개념**: 포워딩은 연산 결과를 레지스터 기록 전에 다음 명령어로 직접 우회 전달해 데이터 대기를 줄이는 기법이고, 분기 예측은 분기 결과가 확정되기 전에 다음 실행 경로를 추정해 파이프라인 정지를 줄이는 기법임
- **배경/필요성**: 깊은 파이프라인의 데이터·분기 대기를 줄이기 위해 우회 전달과 경로 예측 장치가 필요함

## Ⅱ. 특징

- 포워딩은 연산 결과를 레지스터 기록 전 실행 단계로 우회 전달해 RAW 대기를 줄임
- 분기 예측은 추측 실행을 기반으로 제어 해저드를 줄임
- 포워딩은 load-use 상황처럼 완전히 없애지 못하는 대기가 남을 수 있음
- 분기 예측은 실패 시 flush 패널티가 발생함

## Ⅲ. 종류 및 비교

| 판단 기준 | 포워딩 | 분기 예측 |
|:---|:---|:---|
| 해결 대상·동작 원리 | 데이터 해저드, 우회 경로 전달 | 제어 해저드, 다음 경로 추정 |
| 판정 입력 | 생산·소비 레지스터 번호와 결과 준비 단계 | 분기 주소·과거 이력·목표 주소 |
| 실패 형태·검증 지표 | 잔여 정체 발생, 적재-사용 대기율로 검증 | 잘못 인출한 명령 폐기, 분기 예측 정확도로 검증 |

> 요약: 포워딩은 값 대기를 줄이고, 분기 예측은 경로 대기를 줄이는 해저드 대응 기법임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 포워딩 장치 | 생산 레지스터와 소비 레지스터를 비교해 우회 여부를 결정함 |
| 우회 선택기 | 레지스터 값 대신 전달된 결과를 선택해 ALU 입력으로 보냄 |
| 분기 예측기 | 과거 분기 이력이나 패턴을 기반으로 다음 경로를 추정함 |
| 복구 로직 | 예측 실패 시 잘못 인출한 명령을 폐기하고 올바른 경로로 복귀함 |

```text
[포워딩] 생산·소비 레지스터 비교 -> 우회 선택기 -> 실행 단계 입력

[분기 예측] 분기 이력·주소 -> 분기 예측기 -> 예측 경로
                                       -> 실패 시 복구 로직
```

> 요약: 포워딩은 우회 경로를, 분기 예측은 예측기와 복구 로직을 통해 파이프라인 정지를 줄임.

## Ⅴ. 원리 및 절차 흐름도

```text
[포워딩] RAW 비교 -> 결과 준비 단계 확인 -> 우회 선택 -> load-use이면 stall
[분기 예측] 이력 조회 -> 경로·목표 예측 -> 실제 결과 비교 -> 실패 시 flush·재인출
```

1. **포워딩**: 생산 명령의 결과가 준비됐으면 ALU 입력으로 우회하고, 메모리 값이 준비되지 않은 load-use 상황이면 대기함
2. **분기 예측**: 예측 경로를 먼저 인출하고 실제 분기 결과와 다르면 후속 명령을 폐기한 뒤 올바른 경로에서 다시 인출함

> 요약: 포워딩·분기 예측은 파이프라인 진행을 유지하지만 값 준비 지연과 예측 실패는 별도 복구 비용을 남김.

## Ⅵ. 실무 사례

1. 적재-사용 의존이 많은 CPU는 포워딩 후 남는 대기를 줄이기 위해 독립 명령을 사이에 배치하고, 적재-사용 대기율과 CPI로 검증함
2. 분기 명령 비중이 높은 서버 CPU는 워크로드에 맞게 분기 예측기 크기를 조정하고, 분기 예측 정확도와 천 명령당 분기 실패 수로 검증함

## Ⅶ. 결론

- 포워딩은 load-use 잔여 대기를, 분기 예측은 오예측 폐기 비용을 각각 측정해 CPI 감소량이 추가 배선·테이블 비용을 상쇄하는지 판단해야 함
