## Ⅰ. 개요
- **정의**: 데이터 해저드를 바이패스 경로로, 제어 해저드를 분기 결과 예측으로 해소하는 기법
- **배경/필요성**: 파이프라인 해저드(008 참조)가 스톨·버블을 유발하여 처리량이 저하되므로 하드웨어 수준 해소책이 필요함
- **비유**: 조립 라인에서 부품을 창고에 넣었다 꺼내는 대신 옆 사람에게 바로 건네고(포워딩), 갈림길에서 과거 경험으로 방향을 미리 추측하는(분기 예측) 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 해저드 해소의 하드웨어 기법 | 포워딩 경로 위치, 정적/동적 분기 예측 차이 | Spectre 취약점과 투기 실행 연결 누락 주의 |

> 요약: 포워딩은 데이터 해저드, 분기 예측은 제어 해저드를 각각 하드웨어로 해소하는 기법임

## Ⅱ. 구성요소
```text
[EX/MEM Reg]---+                     +---[BTB]
               |  forwarding mux     |   (Branch Target Buffer)
               v                     v
ALU input <---MUX              IF stage <--- predicted PC
               ^                     ^
               |                     |
[MEM/WB Reg]---+              [BHT / PHT]
                              (Branch History Table)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 포워딩 MUX | EX/MEM·MEM/WB 출력을 ALU 입력으로 바이패스하는 멀티플렉서 | 완성품을 창고 거치지 않고 옆 라인에 직접 전달 |
| 해저드 검출 유닛 | 소스·목적 레지스터 번호 비교로 포워딩 필요 여부를 판별함 | 부품 번호표를 대조하는 검수원 |
| BHT (Branch History Table) | 분기 명령 주소별 Taken/Not-Taken 이력을 기록하는 카운터 테이블 | 매일 출퇴근 경로를 기록한 일지 |
| BTB (Branch Target Buffer) | 분기 목적지 주소를 캐싱하여 IF 단계에서 즉시 PC를 갱신함 | 자주 가는 목적지를 즐겨찾기에 저장 |
| 투기 실행 (Speculative Exec) | 예측 결과에 따라 명령을 미리 실행하고, 오예측 시 결과를 폐기함 | 주문이 올 것을 예상하고 미리 조리 시작 |

> 요약: 포워딩 MUX·해저드 검출·BHT·BTB·투기 실행이 핵심 구성요소임

## Ⅲ. 절차
```text
ID(의존성 검출) --> 포워딩 경로 선택 --> ALU 입력 바이패스 --> 스톨 회피
IF(분기 인식)   --> BHT/BTB 조회    --> 예측 PC로 인출     --> 오예측 시 플러시
```
- 1단계: **의존성 검출** — ID 단계에서 선행 명령의 목적 레지스터와 후행 명령의 소스 레지스터를 비교함
- 2단계: **포워딩 적용** — EX/MEM 또는 MEM/WB 결과를 MUX를 통해 ALU 입력에 바이패스함
- 3단계: **분기 예측** — IF 단계에서 BHT 카운터를 조회하고 BTB에서 목적지 주소를 인출함
- 4단계: **오예측 복구** — EX 단계에서 예측이 틀린 경우 파이프라인 플러시 후 올바른 PC로 재인출함

> 요약: 의존성 검출 → 포워딩 → 분기 예측 → 오예측 복구의 4단계로 해저드를 해소함

## Ⅳ. 문제점
- **Load-Use 해저드 미해소**: Load 결과는 MEM 단계 이후에야 가용하여 1클럭 스톨이 불가피함 — 포워딩만으로 완전 해소 불가
- **오예측 패널티**: 파이프라인 깊이만큼의 클럭이 플러시로 낭비됨 — 깊은 파이프라인일수록 패널티가 증가
- **투기 실행 보안 취약**: Spectre 계열 공격이 투기 실행 중 캐시 사이드 채널로 비밀 데이터를 추출함 — 마이크로아키텍처 수준 정보 누출

> 요약: Load-Use 스톨, 오예측 패널티, Spectre 취약점이 핵심 한계임

## Ⅴ. 개선방안
1. 단기: 컴파일러 명령어 스케줄링으로 Load-Use 간 독립 명령을 삽입하여 스톨 은폐
2. 중기: TAGE 등 다단계 예측기 도입으로 오예측률을 3 % 이하로 저감
3. 장기: 투기 실행 결과의 캐시 반영을 커밋 시점까지 지연하는 하드웨어 격리 기법으로 Spectre 완화

> 요약: 스케줄링 → 고급 예측기 → 투기 실행 격리 순서로 3대 문제를 각각 해소함

## Ⅵ. 전망
- **발전 방향**: 뉴럴 분기 예측기(퍼셉트론 기반)로 예측 정확도 향상 추세
- **기술사적 판단**: 포워딩·분기 예측은 파이프라인 문제와 세트로 출제되며, Spectre는 보안 토픽과 교차 출제 가능
- **기술사 제언**: 해저드 유형(008)→해소 기법(009)→슈퍼스칼라(010)의 연결 흐름을 답안에서 체계적으로 구성할 필요
