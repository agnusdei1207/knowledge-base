# 📖 【암기용】 개념 완전 이해

> 목적: 현대 CPU가 어떻게 파이프라인 해저드로 인한 스톨(Stall)을 제로에 가깝게 만드는지 직관적으로 이해하게 만든다.

## 한눈에
- **개요**: 데이터 충돌(의존성)을 해결하는 '새치기(포워딩)'와 분기 충돌을 해결하는 '미래 예측(분기 예측)' 기술
- **왜 필요한가**: 5단 파이프라인은 앞 명령이 끝나야 뒤 명령이 실행될 수 있는 의존성 문제(RAW)와, 다음 명령이 무엇인지 모르는 분기(If-Else) 문제 때문에 시도 때도 없이 멈춘다. 멈추면 성능이 수직 낙하하므로, 하드웨어적 꼼수가 필요하다.
- **핵심 직관**: 포워딩은 요리 완성(WB)을 기다리지 않고 프라이팬에서 고기(EX 결과)를 바로 덜어 쓰는 것이고, 분기 예측은 손님이 메뉴를 고민할 때 늘 먹던 메뉴를 미리 요리하기 시작하는 눈치 게임이다.

## 깊이 이해
- **작동 원리 (포워딩 - Data Hazard 해소)**: 
  - `ADD R1, R2, R3` 직후 `SUB R4, R1, R5`가 실행되면, SUB는 R1이 필요하다. 원칙대로면 ADD가 WB(5단계)를 끝내야 SUB가 EX(3단계)를 할 수 있어 2클럭을 쉰다(Stall).
  - **포워딩(Bypass)**: ADD의 EX 연산이 끝나자마자(3단계), 결과값을 레지스터를 안 거치고 즉시 SUB의 EX 단계 입력선으로 쏴준다. 2클럭 쉴 것을 0클럭으로 없애버린다.
- **작동 원리 (분기 예측 - Control Hazard 해소)**: 
  - `if (a > b)` 같은 분기문은 EX 단계에서야 조건이 판별되므로, 그때까지 다음 명령어를 인출(IF)할 수 없다. (예측 안 하면 2~3클럭 대기)
  - **분기 예측**: 과거의 패턴(BHT)을 보고 "얘는 주로 참이었어!" 하고 찍어서 미리 IF를 진행한다(투기적 실행). 맞으면 대박(0클럭 낭비), 틀리면 그동안 진행한 걸 싹 다 쓰레기통에 버려야 한다(Flush 페널티).
- **비유**: 
  - 포워딩: 직원이 월급(WB)을 은행에 넣고 다시 찾는 대신, 현찰(ALU 출력)을 바로 받아서 물건을 사는 것.
  - 분기 예측: 기상청이 비 올 확률을 예측해 우산을 미리 챙기는 것. 맞으면 안 젖지만, 틀리면 짐만 무겁다.
- **구체 예시**: 반복문 `for (i=0; i<100; i++)`의 경우, 분기문은 99번은 돌아가고 1번만 빠져나온다. 동적 분기 예측기(2비트 카운터)는 이런 패턴을 파악해 98% 이상의 적중률을 달성한다.

## 연결 개념
- 투기적 실행 (Speculative Execution) — 분기 예측을 믿고 미리 명령어를 실행하는 기술로, 보안 취약점(Meltdown/Spectre)의 원인
- 비순차 실행 (Out of Order) — 분기 예측과 포워딩으로도 안 풀리는 의존성을 명령어 순서를 섞어서 해결하는 기법


# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 데이터 포워딩과 분기 예측은 파이프라인의 데이터 의존성(RAW)과 제어 불확실성을 해소하여 IPC(명령어 처리량) 저하를 방어하는 하드웨어 최적화 회로다.
> 2. **가치**: 포워딩은 EX 단계의 결과를 즉각 재사용하여 2사이클 스톨을 0사이클로 없애며, 분기 예측은 BHT/BTB를 통해 제어 해저드 플러시(Flush) 빈도를 5% 미만으로 통제한다.
> 3. **판단 포인트**: 단(Stage) 수가 깊은 현대 슈퍼파이프라인 구조일수록 분기 예측 실패 페널티(10~20 사이클)가 치명적이므로, 다단 동적 분기 예측기의 정교함이 코어 성능을 좌우한다.

## 출제 의도 및 답안 포인트
| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 파이프라인 해저드의 원인과 하드웨어적 해결 메커니즘 이해 | 데이터 해저드(RAW) -> 포워딩 경로 회로 (EX/MEM, MEM/WB), 제어 해저드 -> BTB, BHT 기반 동적 예측 | 포워딩으로 Load-Use 해저드까지 0사이클로 없앨 수 있다고 적는 오류 (Load는 최소 1사이클 필요) |

> 요약: 스톨(Stall)을 줄이는 포워딩의 데이터 경로 추가와, 버블(Bubble)을 줄이는 분기 예측의 캐시(BTB) 메커니즘을 구체적으로 대조 서술해야 한다.


## Ⅰ. 개요 및 필요성

- 정의: 파이프라인 처리 중 발생하는 데이터 해저드를 해결하는 **포워딩**과, 제어 해저드를 완화하는 **분기 예측** 메커니즘
- 배경: 명령어 간 의존성으로 인해 발생하는 멈춤 현상(Stall, Flush)이 깊은 파이프라인 구조에서 심각한 CPI 손실을 유발
- 필요성: 클럭 주파수를 낭비하지 않고 이상적 CPI인 1.0에 근접하기 위한 필수 하드웨어 보상 회로 요구


## Ⅱ. 데이터 해저드 극복: 포워딩 (Forwarding/Bypass)

```text
[데이터 포워딩 회로 개념도 (RAW 의존성 해결)]
명령 1: [ IF ] -> [ ID ] -> [ EX (결과생성) ] -> [ MEM ] -> [ WB ]
                               |               |
                               +--->(EX/MEM)---+---> [ EX ] (명령 2 재사용)
                               |
                               +--->(MEM/WB)-------> [ EX ] (명령 3 재사용)
```

| 포워딩 회로 | 대상 해저드 조건 | 적용 방법 (마이크로 오퍼레이션) |
|:---|:---|:---|
| EX/MEM 포워딩 | 직전 명령의 ALU 결과를 현재 명령의 ALU 입력으로 필요 시 | ALU 연산 완료 즉시 다음 클럭의 ALU 입력 MUX로 결과값 패스 |
| MEM/WB 포워딩 | 전전 명령의 결과를 현재 명령의 ALU 입력으로 필요 시 | 메모리 접근/WB 단계의 레지스터 기록 전 데이터를 ALU로 패스 |
| Load-Use 한계 | Load 직후 해당 데이터를 ALU 연산에 쓸 경우 | 데이터 인출은 MEM에서 끝나므로 포워딩을 써도 최소 1사이클 스톨 발생 |

> 요약: 포워딩은 WB 단계를 기다리지 않고 내부 데이터 버스(Bypass)를 열어 스톨(Stall)을 0사이클로 차단한다.


## Ⅲ. 제어 해저드 극복: 분기 예측 (Branch Prediction)

```text
[동적 분기 예측 동작 흐름도 (IF 단계)]
PC 인출 -> BTB 검색 (분기문 여부 및 타겟 주소 확인)
  -> BHT 참조 (2-Bit 예측기) -> [ Taken(분기) ] 판단 시 Target 주소로 IF 
  -> [ EX 단계 실제 결과 ] -> 예측 실패 시 Flush 및 BHT 상태 업데이트
```

| 구성요소 | 핵심 역할 | 상세 하위 요소 / 특징 |
|:---|:---|:---|
| BTB (Branch Target Buffer) | 분기 목적지 주소 캐싱 | IF 단계에서 명령어가 분기문인지 판별하고 목표 주소 제공 |
| BHT (Branch History Table) | 분기 여부(Taken/Not Taken) 예측 | 과거 실행 결과를 저장하는 포화 카운터(Saturating Counter) |
| 정적 예측 (Static) | 컴파일러 기반의 하드코딩 규칙 | 후방 분기는 루프로 판단해 무조건 Taken 처리 |
| 동적 예측 (Dynamic) | 런타임 과거 이력 기반 H/W 예측 | 1-bit, 2-bit 예측기, 글로벌 예측기, TAGE 예측기 |

> 요약: BTB로 "어디로 갈지"를 캐싱하고, BHT로 "갈지 말지"를 예측하여 IF 단계의 지연(제어 해저드)을 완전히 은닉한다.


## Ⅳ. 심화 비교 및 성능 지표 판단

| 비교 축 | 데이터 포워딩 (Data Hazard) | 동적 분기 예측 (Control Hazard) | 판단 포인트 |
|:---|:---|:---|:---|
| 지연 원인 | RAW 데이터 의존성 (의존 레지스터 대기) | 분기 조건 및 목적지 계산 지연 (PC 불확실) | 어떤 해저드를 방어하는가 |
| 적용 단계 | EX 단계 (ALU 입력 시점) | IF 단계 (다음 명령어 반입 시점) | 마이크로 아키텍처 개입 위치 |
| 실패 패널티 | 포워딩 불가 시 1~2사이클 지연(Stall) | 예측 실패 시 파이프라인 전체 비우기(Flush) | 깊은 파이프라인일수록 분기 패널티 치명적 |
| 구현 복잡도 | ALU 입력 MUX 추가 등 비교적 단순 | 다단 카운터, 글로벌 히스토리 테이블 등 고비용 회로 | 면적 대비 성능 한계 효용 |

> 요약: 데이터 포워딩은 1~2사이클의 확실한 보완재이나, 분기 예측 실패는 수십 사이클의 붕괴(Flush)를 초래하므로 최신 CPU 트랜지스터의 상당수가 분기 예측에 투자된다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 분기 예측 정확도 | BHT + 글로벌 이력 조합으로 95% 이상 적중 | SPECint 벤치마크 분기 추적 |
| 브랜치 미스 패널티 | Flush 사이클(파이프라인 깊이) 통제 | 성능 모니터링 카운터(PMU) 분석 |
| Load-Use 스톨 발생률 | 전체 사이클의 5% 이하 (컴파일러 협력) | 명령어 재배치 코드 프로파일링 |

> 요약: 하드웨어 포워딩과 예측기로 95%의 해저드를 막고, 남은 한계(Load-Use)는 컴파일러 스케줄링으로 방어해야 한다.


## Ⅵ. 실무 적용 및 결론
**적용 방안 3개:**
1. 컴파일러 명령어 스케줄링 연계: Load 명령어 직후 곧바로 해당 레지스터를 사용하는 코드를 지연시키기 위해, 서로 무관한 명령어를 끼워 넣어(Instruction Scheduling) Load-Use 스톨 잔여 1사이클 방어
2. 다단 동적 분기 예측기 채택: 고성능 서버(ARM Neoverse, AMD EPYC) 프로세서 설계 시 2-Bit 카운터를 넘어 패턴 히스토리(TAGE, Perceptron) 기반의 인공신경망 예측기를 도입해 적중률 99% 달성
3. 투기적 실행 보안 격리: 분기 예측을 믿고 미리 메모리를 읽어두는 투기적 실행(Speculative Execution)이 유발하는 캐시 부채널 공격(Spectre) 방어를 위해, 예측 실패 시 캐시 상태 롤백(Rollback) 및 IBRS 보안 격리 적용

**결론 (2줄):**
- 기술사 판단: 파이프라인의 성능(IPC)은 클럭 속도가 아니라 "포워딩 회로의 정교함"과 "분기 예측 실패 빈도(Flush Penalty)"를 억제하는 아키텍처 역량에 달려있다.
- 향후 방향: 분기 예측의 패널티 리스크를 넘기 위해 AI 기반 분기 예측기가 도입되고 있으며, 최후의 보루로 명령어 순서를 뒤집는 비순차 실행(Out-of-Order Execution) 기법이 병행 확산되고 있다.
