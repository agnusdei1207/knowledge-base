## Ⅰ. 개요
- **정의**: 데이터 해저드를 우회 경로로, 제어 해저드를 분기 결과 예측으로 해소하는 기법
- **배경/필요성**: 파이프라인 해저드(008 참조)로 인한 스톨과 플러시를 줄여 CPI를 1에 근접시킬 필요가 있음
- **비유**: 조립 라인에서 완성 전 중간 결과물을 바로 다음 공정에 전달(포워딩)하고, 갈림길에서 과거 경험으로 방향을 미리 결정(분기예측)하는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 해저드 해소 기법의 동작 원리 | 포워딩 경로 위치, 예측기 구조(BHT/BTB) | 포워딩으로 해결 불가한 Load-Use 케이스 누락 |

> 요약: 포워딩과 분기예측으로 파이프라인 스톨·플러시를 최소화하는 기법임

## Ⅱ. 구성요소
```text
  +------------+          +------------------+
  |  Forwarding |          | Branch Prediction|
  +------+-----+          +--------+---------+
         |                         |
    +----+----+              +-----+-----+
    |         |              |           |
    v         v              v           v
  EX-EX    MEM-EX         BHT         BTB
  우회      우회         분기이력     분기목적지
  경로      경로         테이블       버퍼
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| EX-EX 포워딩 | EX 단계 출력을 다음 명령어의 EX 입력으로 전달함 | 요리 중간 결과를 옆 조리대에 즉시 전달 |
| MEM-EX 포워딩 | MEM 단계 출력을 후속 명령어의 EX 입력으로 전달함 | 포장 직후 결과물을 조리대로 회송 |
| BHT (Branch History Table) | 분기 명령어의 과거 taken/not-taken 이력을 기록하여 방향을 예측함 | 매일 출퇴근 경로 패턴 기억 |
| BTB (Branch Target Buffer) | 분기 목적지 주소를 캐싱하여 IF 단계에서 즉시 인출 주소를 결정함 | 자주 가는 목적지 내비 즐겨찾기 |

> 요약: 포워딩 경로 2종과 예측 테이블 2종이 핵심 구성요소임

## Ⅲ. 절차
```text
  의존성 검출      포워딩 판정      분기 예측        검증/복구
  (Detect)        (Forward)       (Predict)        (Verify)
   |               |               |               |
   +--ID 비교----->+--MUX 선택---->+--BHT/BTB----->+
  소스/목적지     EX/MEM 출력     예측 주소로      오예측 시
  레지스터 비교   을 입력에 연결   IF 수행         플러시+재인출
```
- 1단계: ID 단계에서 소스 레지스터와 선행 명령어의 목적 레지스터를 비교하여 데이터 의존성을 검출함
- 2단계: 의존성이 존재하면 MUX를 통해 EX 또는 MEM 단계의 출력을 현재 명령어의 ALU 입력으로 선택함
- 3단계: 분기 명령어 인출 시 BHT로 방향을, BTB로 목적지 주소를 예측하여 다음 IF를 수행함
- 4단계: EX 단계에서 실제 분기 결과를 확인하고, 오예측 시 파이프라인을 플러시한 뒤 올바른 경로를 재인출함

> 요약: 검출-포워딩-예측-검증의 4단계로 해저드를 최소 비용으로 해소함

## Ⅳ. 문제점
- Load-Use 스톨: `LW` 직후 결과를 사용하는 명령어는 MEM 완료 전 포워딩이 불가함 — 1클럭 스톨이 불가피함
- 오예측 페널티: 분기예측이 틀리면 잘못 인출된 명령어를 폐기해야 함 — 파이프라인 깊이에 비례하여 페널티 클럭이 증가함
- 하드웨어 복잡도: 포워딩 MUX와 예측 테이블이 추가됨 — 제어 로직 면적과 전력 소모가 증가함

> 요약: Load-Use 스톨·오예측 페널티·하드웨어 복잡도가 잔존 과제임

## Ⅴ. 개선방안
1. 단기: 컴파일러가 Load 명령어 뒤에 독립 명령어를 스케줄링(지연 슬롯)하여 Load-Use 스톨을 회피함
2. 중기: 2비트 포화 카운터, 상관 예측기, 토너먼트 예측기 등으로 예측 정확도를 98% 이상으로 향상시킴
3. 장기: 비순차 실행 엔진과 결합하여 포워딩·예측 로직을 통합 최적화하고 전력 대비 성능을 개선함

> 요약: 명령어 스케줄링·고급 예측기·OoO 통합으로 각 문제를 해결함

## Ⅵ. 전망
- 발전 방향: 뉴럴 분기예측기(퍼셉트론 기반)와 TAGE 예측기로 복잡한 분기 패턴 학습이 진행 중임
- 기술사적 판단: 포워딩은 기본 전제, 분기예측 정확도가 고성능 프로세서 IPC의 핵심 결정 요소임
- 기술사 제언: 예측기 복잡도와 전력 소모 간 균형점을 워크로드 특성별로 분석·제시할 필요
