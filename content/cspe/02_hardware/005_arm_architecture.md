## Ⅰ. 개요
- **정의**: 저전력 RISC 기반의 라이선스형 프로세서 아키텍처로, 모바일·임베디드 시장의 지배적 ISA임
- **배경/필요성**: 배터리 구동 기기에서 와트당 연산 성능이 핵심 지표이므로, 전력 효율 중심 설계가 필요함
- **비유**: ARM은 설계 도면만 파는 건축 설계사무소이고, 실제 시공(칩 제조)은 라이선시가 수행함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| ARM 라이선스 모델과 아키텍처 특징 | IP 라이선스 vs 아키텍처 라이선스 구분 | ARM은 ISA 이름이자 회사명이며, 칩 제조사가 아닌 IP 설계사라는 점 명시 |

> 요약: 저전력 RISC 설계를 IP 라이선스 형태로 공급하는 것이 ARM의 핵심 모델임

## Ⅱ. 구성요소
```text
  +-------------- ARM 생태계 ----------------+
  |                                          |
  |  ISA 계층                                |
  |  +--------+  +--------+  +--------+     |
  |  | ARMv8  |  | ARMv9  |  | 프로파일|     |
  |  | AArch64|  | SVE2   |  | A/R/M  |     |
  |  +--------+  +--------+  +--------+     |
  |                                          |
  |  코어 IP 계층                            |
  |  +----------+  +--------+  +---------+  |
  |  | Cortex-A |  |Cortex-R |  |Cortex-M |  |
  |  | (고성능) |  | (실시간)|  | (저전력)|  |
  |  +----------+  +--------+  +---------+  |
  |                                          |
  |  라이선스 모델                           |
  |  +----------+  +-----------+             |
  |  | IP 라이선스|  |아키텍처 LIC|            |
  |  | (코어 그대로)|  |(자체 설계) |           |
  |  +----------+  +-----------+             |
  +------------------------------------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 프로파일(A/R/M) | A(Application), R(Real-time), M(Microcontroller)로 용도별 기능 범위를 정의함 | 승용차/트럭/오토바이 등급 |
| Cortex 코어 IP | ARM이 설계한 마이크로아키텍처 구현체로, 라이선시가 SoC에 통합함 | 완성된 엔진 모듈 |
| big.LITTLE / DynamIQ | 고성능 코어와 저전력 코어를 클러스터로 조합하여 부하에 따라 전환함 | 고속 엔진과 경제형 엔진의 하이브리드 차량 |
| TrustZone | 하드웨어 수준에서 Secure/Normal 월드를 격리하는 보안 확장임 | 건물 내 보안 구역과 일반 구역 분리 |

> 요약: 프로파일·코어 IP·이종 클러스터·보안 확장이 ARM 생태계의 4대 축임

## Ⅲ. 절차
```text
  ISA 선정          코어 라이선스      SoC 통합          검증/양산
  (ARMv8/v9)       (Cortex 선택)     (IP Integration)  (Tape-out)
    |                  |                |                  |
    +--프로파일 결정-->+--IP 계약------>+--버스 연결------->+
  A/R/M 프로파일    IP/아키텍처 LIC   AMBA/AXI 인터커넥트  파운드리 위탁
```
- 1단계: 대상 기기의 용도(모바일/차량/MCU)에 따라 프로파일과 ISA 버전을 선정함
- 2단계: IP 라이선스(코어 RTL 그대로 사용) 또는 아키텍처 라이선스(자체 코어 설계)를 계약함
- 3단계: AMBA/AXI 버스로 코어·GPU·NPU·메모리 컨트롤러를 SoC에 통합함
- 4단계: 시뮬레이션·FPGA 검증 후 파운드리에 위탁하여 양산함

> 요약: 프로파일 선정 → 라이선스 계약 → SoC 통합 → 양산의 4단계로 칩이 만들어짐

## Ⅳ. 문제점
- [라이선스 비용]: 로열티·선급금 구조 — 저가 IoT 칩에서는 라이선스 비용이 BOM 대비 과대해짐
- [서버급 성능 격차]: 싱글 스레드 IPC 제한 — x86 대비 범용 서버 워크로드에서 코어당 성능이 열위함
- [생태계 종속]: 단일 IP 공급사 — ARM의 라이선스 정책 변경이 전체 공급망에 파급됨

> 요약: 라이선스 비용·서버 성능·공급사 종속이 ARM 확산의 3대 리스크임

## Ⅴ. 개선방안
1. 단기: Flexible Access(소량 선급금) 모델 도입으로 중소 설계사의 라이선스 비용 부담을 경감함
2. 중기: ARMv9 + SVE2 벡터 확장과 고성능 OoO 코어(Cortex-X 시리즈)로 서버급 IPC를 향상함
3. 장기: RISC-V 등 대안 ISA와 경쟁 체제를 형성하여 라이선스 정책의 투명성·예측 가능성을 확보함 (004 참조)

> 요약: 유연 라이선스 → 고성능 코어 강화 → 경쟁 생태계 조성 순으로 리스크를 완화함

## Ⅵ. 전망
- 발전 방향: 클라우드 네이티브 서버(AWS Graviton 등)와 AI 에지 디바이스에서 ARM 채택이 확대됨
- 기술사적 판단: ARM과 RISC-V의 경쟁이 ISA 라이선스 시장의 가격·개방성을 개선하는 촉매가 됨
- 기술사 제언: SoC 설계 시 ARM과 RISC-V의 TCO(라이선스+생태계+전환비용)를 정량 비교해야 함
