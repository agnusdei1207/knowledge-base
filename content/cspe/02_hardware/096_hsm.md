## Ⅰ. 개요
- 암호화 키 생성, 저장 및 암호 연산을 수행하는 독립적인 하드웨어 장치.
- 중요 정보를 소프트웨어가 아닌 물리적으로 격리된 공간에서 처리하여 유출 차단.
| 구분 | 내용 | 비고 |
|---|---|---|
| 정의 | 암호 키 생애주기 관리 및 연산 전용 물리적 보안 장치 | FIPS 140-2 |
| 의도 | 키 관리의 물리적 보안성 및 침입 탐지 메커니즘 이해 측정 | 고신뢰 암호 |

## Ⅱ. 구성요소
[ User App ] <--> [ PKCS#11 API ] <--> [ HSM Device ]
                                     | Crypto Engine |
                                     | Key Storage   |
                                     | Anti-Tamper   |
| 구성요소 | 설명 | 비유 |
|---|---|---|
| 암호 엔진 | 대칭/비대칭키 알고리즘 고속 연산 처리 장치 | 금고 속 계산기 |
| 보안 저장소 | 외부 노출 없이 키를 보관하는 내부 메모리 | 비밀 수첩 |
| Anti-Tamper | 물리적 분해 시 데이터 자폭 및 무력화 회로 | 함정 장치 |
> 요약: 연산 엔진, 격리 저장소, 물리적 침입 탐지 회로로 구성됨.

## Ⅲ. 절차
(1) Key Gen -> (2) Request -> (3) Internal Process -> (4) Response
1. Key Gen: HSM 내부에서 난수 생성기(TRNG)를 이용해 암호 키를 직접 생성함.
2. Request: 외부 앱이 API를 통해 데이터 암호화/전자서명을 요청함.
3. Internal Process: 키는 HSM 밖으로 나가지 않고 내부 엔진에서 연산 수행.
4. Response: 연산 결과값만 외부로 전달하며, 키는 안전하게 보관됨.
> 요약: 키 생성, 요청 수신, 내부 연산, 결과 반환 순으로 키를 은닉함.

## Ⅳ. 문제점
- 도입 비용: 전용 하드웨어 구축 비용이 높고 관리가 복잡함.
- 병목 현상: 대량의 트랜잭션 처리 시 HSM 연산 속도가 전체 성능 제약 요인이 됨.

## Ⅴ. 개선방안
- 클라우드 HSM: 서비스형 HSM(CloudHSM) 도입으로 초기 비용 절감 및 유연성 확보.
- 성능 가속: 멀티코어 기반 HSM 도입 및 클러스터링을 통한 부하 분산.

## Ⅵ. 전망
- 포스트 양자 암호(PQC): 양자 컴퓨팅 위협에 대응하는 PQC 알고리즘 탑재 HSM 확산.
- IoT 전용 HSM: 초소형/저전력 칩 형태 HSM이 스마트 기기에 내장되어 End-to-End 보안.
