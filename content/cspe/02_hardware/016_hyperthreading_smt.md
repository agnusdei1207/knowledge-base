## 미리 알고가기

- SMT는 하나의 물리 코어에서 여러 스레드를 동시에 실행하는 기술임
- 하이퍼스레딩은 Intel의 SMT 구현 브랜드임
- 실행 유닛과 캐시는 공유하고 PC·레지스터 상태는 스레드별로 유지함

## Ⅰ. 개요

- **정의/개념**: SMT는 하나의 물리 코어 내부에서 여러 스레드의 아키텍처 상태를 유지하고, 각 스레드의 명령어를 동시에 발행해 공유 실행 자원의 유휴 슬롯을 줄이는 마이크로아키텍처 기법임
- **배경/필요성**: 단일 스레드에서는 메모리 대기와 분기 지연으로 실행 유닛이 자주 비므로, 다른 스레드의 명령을 같은 코어에 함께 투입해 처리량을 높이려는 목적에서 도입됨

## Ⅱ. 특징

- 유휴 실행 슬롯을 다른 스레드로 채워 처리량을 높임
- 멀티코어보다 면적 증가가 작고 구현 비용이 상대적으로 낮음
- L1 캐시와 실행 유닛을 공유하므로 간섭이 발생하기 쉬움
- 단일 요청 지연 단축보다 전체 처리량 증가에 더 적합함

## Ⅲ. 종류 및 비교

| 판단 기준 | 멀티코어 | SMT |
|:---|:---|:---|
| 물리 자원 | 코어 분리 | 실행 유닛·캐시 공유 |
| 장점 | 독립 자원으로 간섭 감소 | 낮은 면적 비용의 처리량 증가 |
| 한계 | 면적 증가 큼 | 자원 간섭과 성능 변동 |
| 적합 환경 | 병렬 독립 작업 | 대기 시간이 긴 워크로드 |

> 요약: SMT는 코어를 추가하지 않고 공유 실행 자원의 빈 슬롯을 다른 스레드로 채움.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Thread Context | 각 스레드의 PC와 레지스터 상태를 별도로 보관해 독립 실행처럼 보이게 함 |
| Shared Execution Units | ALU, FPU, load/store 유닛을 여러 스레드가 함께 사용함 |
| Shared Cache | L1/L2 캐시 경쟁이 SMT 간섭과 처리량 변동의 원인이 됨 |
| Scheduler | 어떤 스레드의 명령을 먼저 발행할지 정해 공정성과 처리량을 조절함 |

```text
+------------------+   +------------------+
| Thread Context 1 |   | Thread Context 2 |
+------------------+   +------------------+
          \                    /
           \                  /
        +----------------------+
        | Scheduler            |
        +----------------------+
                  |
                  v
        +----------------------+
        | Shared Exec/Cache    |
        +----------------------+
```

> 요약: SMT는 스레드별 상태를 분리하되 실행 유닛과 캐시는 공유해 처리량을 높임.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 스레드 상태 유지  | --> | 발행 후보 선택    | --> | 공유 자원 실행    | --> | 결과 반영      |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **스레드 상태 유지**: 논리 프로세서별 상태를 저장함
2. **발행 후보 선택**: 준비된 스레드 명령 중 우선순위를 정함
3. **공유 자원 실행**: 실행 유닛과 캐시를 함께 사용함
4. **결과 반영**: 각 스레드 상태에 결과를 반영함

> 요약: SMT는 준비된 스레드 명령을 선택해 공유 자원에서 실행하고 결과를 각 스레드 상태에 반영함.

## Ⅵ. 실무 적용 및 유의점

1. 서버 스케줄러에서 실행 유닛·캐시 경쟁이 크면 처리량 이득보다 간섭이 커지므로 SMT-aware scheduling을 적용하고 resource contention ratio와 throughput gain으로 확인함
2. 멀티테넌트나 지연 민감 서비스는 코어 공유로 side-channel과 p99 지연이 커질 수 있으므로 workload isolation과 SMT on/off 정책을 적용하고 leakage risk score, p99 latency, core utilization으로 확인함

## Ⅶ. 결론

SMT는 코어를 늘리지 않고 처리량을 높이지만, 공유 자원 간섭과 보안 노출을 함께 통제할 때 효과가 있음.

## 작성 근거(검토용)

- SMT는 물리 코어 추가가 아니라 아키텍처 상태 복제와 실행 자원 공유라는 구조 차이를 기준으로 설명함
- 모호한 표현은 공유 자원, 처리량 증가, p99 latency, resource contention으로 치환함
- 결론은 처리량 이득과 자원 간섭·보안 노출을 동시에 판단해야 한다는 운영 기준으로 정리함
