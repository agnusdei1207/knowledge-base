## 미리 알고가기

- SMT는 하나의 물리 코어에서 여러 스레드를 동시에 실행하는 기술임
- 하이퍼스레딩은 Intel의 SMT 구현 브랜드임
- 실행 유닛과 캐시는 공유하고 PC·레지스터 상태는 스레드별로 유지함

## 작성 근거(검토용)

- SMT를 물리 코어 추가가 아니라 스레드별 상태 복제와 실행 자원 공유라는 구조로 설명함
- 멀티코어와 SMT를 물리 자원·처리량 조건·자원 간섭·격리로 비교함
- 처리량 증가와 공유 자원 간섭·격리 조건을 SMT 사용 판단으로 정리함

## Ⅰ. 개요

- **정의/개념**: SMT는 하나의 물리 코어 내부에서 여러 스레드의 아키텍처 상태를 유지하고, 각 스레드의 명령어를 동시에 발행해 공유 실행 자원의 유휴 슬롯을 줄이는 마이크로아키텍처 기법임
- **배경/필요성**: 메모리·분기 대기 중인 실행 유닛의 활용률을 높이기 위해 여러 스레드를 동시에 발행하는 구조가 필요함

## Ⅱ. 특징

- 유휴 실행 슬롯을 다른 스레드로 채워 처리량을 높임
- 코어 전체가 아니라 스레드별 PC·레지스터 상태를 추가하고 실행 유닛과 캐시는 공유함
- L1 캐시와 실행 유닛을 공유하므로 간섭이 발생하기 쉬움
- 한 스레드의 대기 슬롯을 다른 스레드가 사용하므로 단일 스레드 지연보다 코어 전체 처리량을 대상으로 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 멀티코어 | SMT |
|:---|:---|:---|
| 물리 자원 | 코어와 상태를 완전히 분리 | 실행 유닛·캐시는 공유하고 스레드별 PC·레지스터만 분리 |
| 처리량 조건 | 코어별 독립 스레드가 필요 | 한 스레드의 실행 슬롯이 비는 구간이 필요 |
| 자원 간섭·격리 | 공유 LLC·메모리에서 간섭이 발생하며 격리 단위는 물리 코어임 | 실행 유닛·L1 캐시부터 간섭이 발생하며 격리 단위는 논리 프로세서임 |

> 요약: SMT는 코어를 추가하지 않고 공유 실행 자원의 빈 슬롯을 다른 스레드로 채움.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 스레드 문맥 | 각 스레드의 PC와 레지스터 상태를 별도로 보관함 |
| 공유 실행 유닛 | ALU·FPU·로드스토어 유닛을 여러 스레드가 함께 사용함 |
| 공유 캐시 | L1·L2 캐시 경쟁이 SMT 간섭과 처리량 변동을 발생시킴 |
| 스케줄러 | 준비된 스레드 중 어떤 명령을 먼저 발행할지 결정함 |

```text
+------------------+   +------------------+
| 스레드 문맥 1      |   | 스레드 문맥 2      |
+------------------+   +------------------+
          \                    /
           \                  /
        +----------------------+
        | 스케줄러              |
        +----------------------+
                  |
                  v
        +----------------------+
        | 공유 실행 유닛·캐시     |
        +----------------------+
```

> 요약: SMT는 스레드별 상태를 분리하되 실행 유닛과 캐시는 공유해 처리량을 높임.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 스레드 상태 유지  | --> | 발행 후보 선택    | --> | 공유 자원 실행    | --> | 결과 반영      |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **스레드 상태 유지**: 논리 프로세서별 상태를 저장함
2. **발행 후보 선택**: 준비된 스레드 명령 중 우선순위를 정함
3. **공유 자원 실행**: 실행 유닛과 캐시를 함께 사용함
4. **결과 반영**: 각 스레드 상태에 결과를 반영함

> 요약: SMT는 준비된 스레드 명령을 선택해 공유 자원에서 실행하고 결과를 각 스레드 상태에 반영함.

## Ⅵ. 실무 사례

1. 서버 운영체제는 같은 코어의 실행 유닛·캐시 경합을 줄이기 위해 SMT 인지 스케줄링을 적용하고, 자원 경합률과 처리량 증가율로 검증함
2. 지연시간 민감 서비스는 논리 프로세서 간 간섭을 줄이기 위해 SMT를 비활성화하고, p99 응답시간과 처리량으로 검증함

## Ⅶ. 결론

- SMT는 유휴 실행 슬롯 감소로 얻는 처리량 증가량과 실행 유닛·캐시 간섭, p99 지연, 격리 위험을 함께 측정해 사용 여부를 정해야 함
