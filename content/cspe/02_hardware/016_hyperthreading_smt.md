## Ⅰ. 개요
- 정의: 하나의 물리 코어가 두 개 이상의 논리 코어처럼 동작하게 하여 자원 활용도를 높이는 기술
- 배경: 비순차 실행 시 발생하는 유휴 자원(Execution Unit)을 다른 스레드가 사용하게 함
- 출제 의도: SMT(Simultaneous Multithreading)의 원리와 멀티코어와의 차이점 이해

## Ⅱ. 구성요소
- ASCII 구조도
  +---------------------------------------+
  |              Physical Core            |
  |  +----------+          +----------+   |
  |  | Logical  |          | Logical  |   |
  |  | Core 0   |          | Core 1   |   |
  |  +-----+----+          +-----+----+   |
  |        | (Reg, PC 분리)      |         |
  |  +-----+---------------------+----+   |
  |  |     Shared Execution Units     |   |
  |  +--------------------------------+   |
  +---------------------------------------+

- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 논리 프로세서 | 아키텍처 상태(PC, 레지스터)를 유지하는 가상 코어 | 서류 접수처 |
| 공유 실행 유닛 | 실제 연산을 수행하는 ALU, FPU 등 하드웨어 | 실제 처리 공장 |
| 스레드 스케줄러 | 어떤 스레드의 명령을 실행 유닛에 넣을지 결정 | 공정 관리자 |
> 요약: 서류함(PC/Reg)은 두 개지만, 일꾼(ALU)은 하나를 나눠 쓰는 구조임

## Ⅲ. 절차
- ASCII 흐름도
  (Inst Fetch T1) --\     (Decode)     (Shared Issue)     (Execute)
                     +-->          -->                -->
  (Inst Fetch T2) --/   (Rename)      (Buffer/Queue)     (Shared)

- 4단계 설명
1. 상태 복제: 각 스레드별로 독립적인 레지스터 세트와 PC(Program Counter) 유지
2. 명령어 인출: 두 스레드에서 동시에 명령어를 가져와 디코딩 및 리네이밍 수행
3. 자원 경합: 하나의 실행 유닛을 두고 두 스레드의 명령어가 준비되는 대로 투입
4. 병렬 처리: 한 스레드가 메모리 대기(Stall) 중일 때 다른 스레드가 실행 유닛 점유
> 요약: 명령어 수준에서 자원을 공유하여 단일 코어의 처리량(Throughput)을 증대함

## Ⅳ. 문제점
- 성능 간섭: 두 스레드가 동일 자원(예: 캐시, 특정 ALU)을 집중 사용 시 성능 하락
- 보안 취약점: 캐시 공유를 통한 정보 유출(L1TF, PortSmash 등) 가능성 존재

## Ⅴ. 개선방안
- (단기) 스레드 격리: 보안 민감 작업 시 하이퍼스레딩 비활성화 또는 코어 격리
- (중기) 자원 할당 제어: 하드웨어적으로 스레드 간 자원 점유율(Quota) 강제 조정
- (장기) 동적 SMT: 부하 상황에 따라 SMT 모드와 단일 고성능 모드를 자동 전환

## Ⅵ. 전망
- 로드맵: 전력 효율 중심의 E-코어에서는 제외하고 고성능 P-코어 위주로 선별 적용
- CSF: 스레드 간 컨텍스트 스위칭 오버헤드 최소화 및 공유 자원 경합 해결 로직 고도화
