## Ⅰ. 개요
- 정의: 물리적 하드웨어 자원을 논리적으로 분리하여 여러 독립된 환경을 구축하는 기술
- 배경: 서버 자원 낭비 방지, 신속한 서비스 배포 및 격리된 실행 환경 필요
- 출제 의도: 하이퍼바이저와 컨테이너의 구조적 차이 및 장단점 비교 역량 측정

## Ⅱ. 구성요소
- ASCII 구조도
  [ VM (Virtual Machine) ]      [ Container ]
  +----------------------+      +--------------+
  | App | Library        |      | App | Lib    |
  +----------------------+      +--------------+
  | Guest OS             |      | Docker/CRI   |
  +----------------------+      +--------------+
  | Hypervisor           |      | Host OS      |
  +----------------------+      +--------------+
  | Host HW              |      | Host HW      |
  +----------------------+      +--------------+

- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| Hypervisor | 하드웨어를 가상화하여 독립된 OS 구동 지원 | 가상 PC 빌더 |
| Container | 커널을 공유하며 프로세스 단위로 자원 격리 | 경량 포장 박스 |
| Guest OS | VM 내부에서 동작하는 완전한 운영체제 | 입주 가구용 가전 |

- > 요약: 하이퍼바이저는 HW 가상화, 컨테이너는 OS 레벨 가상화 지향

## Ⅲ. 절차
- ASCII 흐름도
  [Image 생성] -> [Registry 등록] -> [Instantiating] -> [Runtime 관리]

1. 자원 격리: Namespace(이름 공간), Cgroups(자원 제한) 설정
2. 이미지 스냅샷: 실행에 필요한 파일 시스템과 환경 설정을 패키징
3. 동적 할당: 실행 시점에 필요한 CPU, 메모리 자원을 논리적으로 할당
4. 생명주기 관리: 복제, 이동(Migration), 소멸 등의 작업을 자동화

- > 요약: 추상화 계층을 통해 물리적 제약 없는 서비스 배포 환경 구현

## Ⅳ. 문제점
- VM 성능 손실: Guest OS와 하이퍼바이저의 중복 계층으로 인한 오버헤드
- 컨테이너 보안: 커널 공유로 인한 취약점 전이 및 완전한 격리의 어려움

## Ⅴ. 개선방안
- MicroVM: 경량화된 하이퍼바이저(Firecracker 등)로 성능과 보안 동시 확보
- 커널 격리 강화: gVisor, Kata Container 등을 통한 컨테이너 보안성 증대

## Ⅵ. 전망
- 로드맵: 서버리스(Serverless) 인프라의 핵심 기반 기술로 자리매김
- CSF: 가상화 오버헤드를 제로에 가깝게 구현하는 HW 가속(VT-x 등) 연계 필수
