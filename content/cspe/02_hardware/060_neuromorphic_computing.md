## 미리 알고가기

- SNN: Spiking Neural Network로 신호를 연속값 대신 spike 이벤트로 표현하는 신경망임
- Event-driven: 이벤트가 발생한 시점에만 연산과 통신을 수행하는 방식임
- Synapse: 뉴런 사이의 연결 가중치이며 뉴로모픽 칩에서는 메모리와 연산 역할을 함께 가짐
- Plasticity: 입력 패턴에 따라 연결 강도가 변하는 학습 특성임

## Ⅰ. 개요

- **정의**: 뉴로모픽 컴퓨팅은 생물학적 신경계의 spike, synapse, event-driven 처리 방식을 회로와 아키텍처로 모사해 낮은 전력으로 감각·패턴 인식 문제를 처리하는 컴퓨팅 방식임. 이벤트 희소성, 시간 정보, 전력 효율을 기준으로 엣지 지능형 처리를 구현하기 위해 사용함.
- **배경/필요성**: 기존 폰 노이만 구조는 메모리와 연산 장치 사이 데이터 이동 비용이 크고, 항상 클록에 맞춰 동작해 희소 이벤트 처리에 비효율적임. 뉴로모픽은 데이터가 발생할 때만 계산해 초저전력 지능형 센서 처리 가능성을 제공함.
- **비유**: 계속 켜진 공장 조명이 아니라 움직임이 감지된 구역의 조명만 켜지는 자동 조명 시스템과 같음.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 뇌 모사 하드웨어의 구조와 적용 한계 설명 | SNN, spike, event-driven, synaptic memory | 일반 딥러닝 가속기로 설명 |

> 요약: 뉴로모픽 컴퓨팅은 spike 이벤트와 근접 메모리 연산으로 희소 신호를 저전력 처리하는 방식임.

## Ⅱ. 특징/비교

| 판단 기준 | 폰 노이만 AI 처리 | 뉴로모픽 컴퓨팅 |
|:---|:---|:---|
| 데이터 표현 | 연속 텐서 값을 메모리에서 읽어 연산기로 이동함 | spike 이벤트와 시간 정보를 기반으로 처리함 |
| 동작 방식 | 클록 기반으로 주기적 연산을 수행함 | 이벤트 발생 시 연산·통신하는 비동기 구조가 가능함 |
| 적용 기준 | 대규모 행렬 연산과 표준 딥러닝 모델에 적합함 | 센서 이벤트, 저전력 패턴 인식, 적응형 제어에 적합함 |

> 요약: 뉴로모픽은 밀집 텐서 처리보다 희소 이벤트와 전력 제약이 큰 문제에 적합함.

## Ⅲ. 구성요소

```text
+----------+     +----------+     +----------+
| Sensor   | --> | Encoder  | --> | SNN Core |
+----------+     +----------+     +----------+
                                      |
                     +----------------+----------------+
                     v                                 v
              +-------------+                   +-------------+
              | Synapse Mem |                   | Event Router|
              +-------------+                   +-------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Spike 뉴런 | 입력 이벤트를 누적하고 임계값을 넘으면 spike를 발생시킴 | 알람 센서 |
| Synapse 메모리 | 연결 가중치를 저장하고 입력 spike에 따른 영향을 계산함 | 연결 강도 표 |
| Event Router | spike 이벤트를 목적 뉴런으로 전달하고 희소 통신을 관리함 | 신호 배달망 |
| 인코더/디코더 | 실제 센서 값을 spike로 바꾸고 결과 spike를 의미 있는 출력으로 해석함 | 번역기 |

> 요약: 뉴로모픽 구조는 이벤트 인코딩, spike 뉴런, synapse 메모리, 이벤트 라우팅으로 구성됨.

## Ⅳ. 절차

```text
+----------+     +----------+     +----------+     +----------+
| 이벤트변환| --> | Spike전파| --> | 가중치갱신| --> | 결과해석 |
+----------+     +----------+     +----------+     +----------+
```

1. **이벤트 변환**: 센서 입력이나 텐서 값을 시간 기반 spike 이벤트로 인코딩함
2. **Spike 전파**: 이벤트 라우터가 spike를 관련 뉴런과 synapse로 전달함
3. **가중치 갱신**: 학습 규칙이나 사전 학습 가중치에 따라 synapse 영향을 반영함
4. **결과 해석**: spike 빈도, 시간, 패턴을 분류 결과나 제어 신호로 디코딩함

> 요약: 뉴로모픽 처리는 값을 계속 계산하는 대신 이벤트를 전달하고 시간 패턴을 해석하는 흐름임.

## Ⅴ. 문제점

- **P1 프로그래밍 모델 미성숙**: SNN 모델링, 학습, 디버깅 도구가 표준 딥러닝 생태계보다 제한적임
- **P2 벤치마크 불일치**: 기존 AI 성능 지표가 spike 시간, 전력, 희소 이벤트 처리 가치를 충분히 반영하지 못함
- **P3 정확도·학습 격차**: ANN을 SNN으로 변환하거나 온칩 학습을 수행할 때 정확도와 안정성이 떨어질 수 있음

> 요약: 뉴로모픽의 어려움은 하드웨어보다 모델 개발 방법과 평가 기준의 성숙도 부족에서 크게 발생함.

## Ⅵ. 개선방안

- **P1 대응**: SNN 프레임워크, 시뮬레이터, 하드웨어 추상화 API를 표준 개발 흐름에 통합함 (확인: 모델 배포 성공률)
- **P2 대응**: 이벤트 기반 지연, 에너지 per inference, spike sparsity를 포함한 벤치마크를 사용함 (확인: 작업별 에너지)
- **P3 대응**: ANN-SNN 변환 보정, surrogate gradient 학습, 하이브리드 ANN/SNN 구조를 적용함 (확인: 기준 정확도 대비 차이)

> 요약: 개선은 개발 도구, 평가 지표, 학습 방법을 뉴로모픽 특성에 맞게 재정의하는 것임.

## Ⅶ. 전망

- **발전 방향**: 뉴로모픽 컴퓨팅은 event camera, robot control, wearable sensor, edge inference와 결합해 spike 기반 저전력 처리 영역을 넓힘
- **기술사적 판단**: 입력 이벤트 희소성, synapse memory 위치, on-chip learning 필요성, 배터리 전력 예산을 기준으로 기존 NPU와 역할을 나눔; energy per spike, inference latency, 정확도 손실률, noise 내성, spike sparsity를 동일 데이터셋과 센서 조건에서 측정함
- **기술사 제언**: 뉴로모픽은 범용 AI 대체가 아니라 데이터 표현과 전력 제약이 맞을 때 선택하는 특화 아키텍처로 설명함
