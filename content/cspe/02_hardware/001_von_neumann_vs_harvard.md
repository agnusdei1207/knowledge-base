# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: **컴퓨터 구조**(Computer Architecture)의 근간으로, 프로그램 명령어를 데이터와 통합하여 관리하는가(폰 노이만) 또는 물리적으로 분리하는가(하버드)에 따른 설계 모델이다.
- **왜 필요한가**: 명령어와 데이터의 접근 경로 설계에 따라 CPU의 처리량(Throughput)과 파이프라인 병목(Stall) 발생 여부가 결정되기 때문이다.
- **핵심 직관**: 창고(메모리)에서 물건(명령어와 데이터)을 가져올 때, 출입문과 통로가 하나인가(폰 노이만) 두 개인가(하버드)의 차이다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| **저장 프로그램 방식** | 명령어를 데이터처럼 메모리에 저장하고 CPU가 이를 읽어 실행하는 방식 | 레시피를 종이에 적어두고 순서대로 요리함 |
| **폰 노이만 병목** | 명령어와 데이터가 단일 버스를 공유하여 발생하는 구조적 속도 지연 | 1차선 도로에 우편차와 택배차가 겹쳐 정체됨 |
| **버스 (Bus)** | CPU, 메모리, I/O 간에 데이터나 제어 신호를 주고받는 물리적 전로 | 물건을 실어나르는 컨베이어 벨트 |
| **NX Bit** | 데이터 영역의 실행을 하드웨어적으로 차단하여 보안을 강화하는 기술 | 택배 상자(데이터)는 열어보되 먹지(실행) 못하게 함 |

## 깊이 이해
- **배경·문제의식**: 최초의 컴퓨터 ENIAC은 프로그램을 바꿀 때마다 전선을 다시 꽂아야 했다. 존 폰 노이만은 "명령어를 데이터처럼 메모리에 넣어두자"는 아이디어를 냈으나(폰 노이만 구조), 단일 버스로 인해 명령어 인출과 데이터 접근을 동시에 할 수 없는 한계에 부딪혔다. 하버드 대학의 Mark I은 이를 해결하고자 물리적 경로를 처음부터 분리했다.
- **작동 원리**:
  - **폰 노이만**: 단일 주소/데이터 버스를 사용하여 회로가 단순하고 메모리 활용이 유연하지만, 매 사이클마다 명령어 인출(Fetch)과 데이터 읽기 중 하나만 수행 가능하다.
  - **하버드**: 명령어 전용과 데이터 전용 버스를 각각 배치하여, 다음 명령어를 읽어오는 동시에 현재 명령어의 연산 데이터를 메모리에서 가져올 수 있다.
- **비유**: 요리사가 요리할 때, 레시피 북과 식재료가 같은 상자에 있으면(폰 노이만) 하나를 꺼낸 뒤에야 다른 걸 꺼낼 수 있다. 하지만 레시피 전용 선반과 식재료 전용 냉장고가 따로 있으면(하버드) 양손을 써서 동시에 준비할 수 있다.
- **구체 예시**: 5단 파이프라인 CPU에서 1번 명령어의 데이터 메모리 접근(MEM)과 4번 명령어의 인출(IF)이 겹칠 때, 폰 노이만은 버스 경합으로 1사이클 정지(Stall)가 생기지만 하버드는 병렬 처리가 가능하다.
- **흔한 오해·주의점**: "현대 PC는 폰 노이만이다"라고 단정하면 안 된다. 현대 CPU는 칩 내부의 L1 캐시만 명령어(I-Cache)와 데이터(D-Cache)로 분리(하버드)하고, 칩 밖의 메인 메모리는 통합(폰 노이만)하여 사용하는 **변형된 하버드(Modified Harvard)** 구조를 쓴다.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 명령어와 데이터의 메모리 공간 및 버스 경로를 통합(폰 노이만) 또는 물리적 분할(하버드)한 아키텍처 설계
> 2. **가치**: 명령어 인출과 데이터 접근의 병행 처리를 통해 파이프라인의 구조적 해저드를 제거하고 IPC(처리량)를 극대화
> 3. **판단 포인트**: 범용 시스템은 유연성을 위해 변형된 하버드(Modified)를, 실시간 신호처리는 확정적 대역폭을 위해 순수 하버드를 적용

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| CPU 처리 병목 원인 진단 및 아키텍처 분기 이해 | 폰 노이만 병목, 파이프라인 IF/MEM 구조적 해저드 | 역사적 사실 나열에 그침 |
| 현대 프로세서의 구조적 타협점(Trade-off) 파악 | L1 분리 캐시(Modified Harvard) 구조 및 효익 | 현대 CPU를 단일 아키텍처로 오해 |

> 요약: 폰 노이만 병목의 원인을 파이프라인 구조적 해저드 관점에서 진단하고, 현대 프로세서의 계층적 혼합 구조(Modified Harvard)를 제시한다.

---

## Ⅰ. 개요 및 필요성

- 개요: 프로그램 내장 방식에서 명령어와 데이터의 물리적 저장 위치 및 CPU 접근 경로를 정의하는 논리적 설계 체계
- 배경: 단일 버스 공유 시 명령어 인출과 데이터 접근 간 경합으로 인한 폰 노이만 병목(Bottleneck) 현상 발생
- 필요성: 고속 파이프라인에서 IF(인출)와 MEM(데이터) 단계의 충돌(구조적 해저드)을 방지하여 처리 성능(IPC) 향상 필요

---

## Ⅱ. 구조 및 구성요소

```text
[폰 노이만 구조] CPU <-> 공용 버스 <-> 통합 메모리 (명령어 + 데이터)

[하버드 구조]   CPU <-> 명령어 버스 <-> 명령어 메모리
                     <-> 데이터 버스   <-> 데이터 메모리
```

| 구분 | 폰 노이만 구조 | 하버드 구조 | 비고 |
|:---|:---|:---|:---|
| 메모리 공간 | 단일 통합 주소 공간 | 명령어/데이터 물리적 분리 | 메모리 활용성 차이 |
| 버스 구성 | 단일 주소/데이터 버스 | 이중(분리) 버스 구성 | 하드웨어 복잡도 |
| 주요 특징 | 단순한 설계, 유연한 할당 | 병렬 접근, 고속 처리 가능 | 트레이드 오프 |

> 요약: 폰 노이만은 단일 버스로 설계가 단순하고, 하버드는 이중 버스로 명령어와 데이터의 동시 병렬 접근을 보장한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
[변형된 하버드(Modified Harvard)의 처리 흐름]
CPU -> [L1 I-Cache 인출] -> [디코딩/실행] -> [L1 D-Cache 데이터 접근]
    -> [L1 미스 시] -> [통합 메인 메모리(RAM) 접근]
```

- 1단계 [명령어 인출]: PC가 지시한 주소의 명령어를 독립된 명령어 전용 버스(또는 I-Cache)를 통해 인출
- 2단계 [해독 및 실행]: CU가 명령어를 해석하고 ALU를 통해 산술·논리 연산 수행
- 3단계 [데이터 접근]: 연산 결과 저장 또는 피연산자 로드 시 데이터 전용 버스(또는 D-Cache)를 통해 동시 접근
- 4단계 [상태 업데이트]: 연산 완료 후 레지스터 상태를 갱신하며, 캐시 미스 시 통합 메모리 영역에서 데이터 동기화

> 요약: 코어 내부는 하버드 방식으로 분리 접근하여 성능을 확보하고, 외부는 폰 노이만 방식으로 설계 효율을 높인다.

---

## Ⅳ. 특징
- 폰 노이만 한계: CPU 클럭 대비 메모리 대역폭 정체로 인한 병목 현상이 전체 시스템 성능의 하한선을 결정함
- 하버드 설계 부담: 버스와 핀(Pin) 수가 두 배로 증가하여 칩 면적(Die size) 및 제조 단가가 상승하는 트레이드오프 존재
- 보안 및 유연성: 폰 노이만은 자기수정코드(JIT) 구현에 유리하나, 코드 인젝션 공격에 취약하여 NX Bit 등의 보호 기재가 필수

> 요약: 하버드 구조는 성능(대역폭)이 우수하나 설계 비용이 높으며, 폰 노이만은 유연성이 높으나 병목과 보안 리스크가 존재한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 항목 | 폰 노이만 아키텍처 | 순수 하버드 아키텍처 | 변형된 하버드(현대) |
|:---|:---|:---|:---|
| 버스 경합 | 구조적 해저드 빈발 | 경합 없음 (물리 분리) | L1 적중 시 경합 제거 |
| 설계 복잡도 | 낮음 (단일 인터페이스) | 높음 (이중 인터페이스) | 중간 (계층형 설계) |
| 동적 할당 | 우수 (공유 영역 활용) | 불가능 (영역 크기 고정) | 우수 (L2 이하 통합) |

> 요약: 범용 컴퓨팅은 유연성이 높은 변형된 하버드를, 임베디드 및 DSP는 확정적 성능을 위해 순수 하버드를 선택한다.

**리스크·대응 (기본은 불릿):**
- [보안 취약점]: 데이터 영역의 악성 코드 실행 위험 → [대응] NX Bit(No-Execute) 하드웨어 설정 및 OS DEP 적용
- [캐시 불일치]: Modified Harvard에서 I/D-Cache 간 데이터 불일치 → [대응] Self-modifying code 실행 전 Cache Flush/Invalidate 수행
- [공간 낭비]: 하버드 구조에서 한쪽 메모리 잔여 시 교차 활용 불가 → [대응] 주기억장치를 통합하는 계층형 메모리 구조 설계

**도입 후 점검 지표:**
- 처리량: 목표 IPC(Instructions Per Cycle) 1.0~1.3 근접 여부 확인 — PMU 활용
- 캐시 적중률: L1 I-Cache 및 D-Cache 미스율 5% 미만 유지 — 성능 카운터 분석

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 범용 프로세서(x86, ARM): L1 캐시를 I/D로 철저히 분리하여 명령어 인출과 데이터 로드 간 간섭을 제거하고 파이프라인 효율 극대화
2. 특수 목적 가속기(DSP): 영상/음성 처리 등 루프 연산이 잦은 환경에서 사이클 손실을 막기 위해 명령어와 데이터 메모리를 완전히 분리한 순수 하버드 채택
3. 시스템 보안 강화: 데이터 영역에 실행 권한을 배제하는 NX(Never Execute) 설정을 통해 폰 노이만 구조의 코드 인젝션 취약점을 하드웨어 수준에서 방어

**결론 (2줄):**
- 기술사 판단: 워크로드의 병렬성 요구치와 칩 면적 비용을 고려하여, 코어 내부(L1)와 외부(L2/L3)의 버스 분리 지점을 최적으로 설계해야 한다.
- 향후 방향: 최근에는 데이터 이동 병목을 해결하기 위해 메모리 내부에서 연산을 수행하는 PIM(Processing-In-Memory) 구조가 차세대 대안으로 부상하고 있다.
