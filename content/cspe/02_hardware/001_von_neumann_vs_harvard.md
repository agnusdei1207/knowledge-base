# 001. 컴퓨터 구조 개요 — 폰 노이만 vs 하버드 아키텍처 (Von Neumann vs Harvard Architecture)

## 미리 알고가기

- **프로그램 내장 방식 (Stored Program)**: 명령어와 데이터를 메모리에 저장하고 CPU가 이를 읽어 처리하는 방식임
- **버스 (Bus)**: CPU, 메모리, 입출력 장치 간에 데이터를 주고받는 물리적/논리적 통로임
- **병목 (Bottleneck)**: 시스템의 특정 구성요소 성능이 낮아 전체 처리량이 제한되는 현상임

## 1. 개요

- **정의/개념**: 컴퓨터 구조는 CPU, 메모리, I/O 장치의 연결 방식과 동작 원리를 정의한 기본 설계이며, 특히 폰 노이만과 하버드 구조는 명령어와 데이터의 저장 및 전송 통로 분리 여부에 따른 분류임
- **배경/필요성**: 초기 컴퓨터는 범용성을 위해 통합 메모리 방식을 채택했으나, CPU 속도가 빨라지면서 단일 통로(Bus)를 공유하는 데 따른 지연이 발생함. 이를 해결하기 위해 명령어와 데이터를 병렬로 처리할 수 있는 구조적 개선이 요구됨

## 2. 특징 및 비교

두 구조의 핵심 차이는 '명령어와 데이터가 같은 길을 쓰느냐'에 있으며, 이는 비용과 성능의 트레이드오프로 이어짐.

| 비교 항목 | 폰 노이만 구조 (Von Neumann) | 하버드 구조 (Harvard) |
|:---|:---|:---|
| **메모리 구성** | 명령어와 데이터를 **동일한 공간**에 저장 | 명령어와 데이터 **저장 공간 분리** |
| **버스 구성** | 단일 버스 (버스 병목 발생 가능) | **독립 버스** (명령어/데이터 병렬 접근) |
| **구현 비용** | 구조가 단순하여 설계 및 제조비 저렴 | 버스와 메모리 인터페이스 중복으로 고비용 |
| **유연성** | 메모리 주소 할당이 유연함 | 고정된 공간 할당으로 유연성 낮음 |
| **주요 용도** | 범용 컴퓨터, PC, 서버 | **임베디드, DSP, CPU 내부 캐시** |

> 요약: 범용성과 저비용이 목적이면 폰 노이만, 병렬 접근을 통한 고성능이 목적이면 하버드 구조를 선택함.

## 3. 구성요소/구조

컴퓨터 아키텍처는 제어, 연산, 저장, 통신 유닛의 상호작용으로 구성됨.

- **구성요소**:
  - **CPU (Central Processing Unit)**: 제어장치(CU)와 연산장치(ALU)를 포함하는 실행 주체
  - **Memory**: 명령어(Instruction)와 데이터(Data)가 상주하는 저장소
  - **Bus**: 주소(Address), 데이터(Data), 제어(Control) 신호가 흐르는 통로

- **구조도 (ASCII)**:

```text
[Von Neumann Structure]              [Harvard Structure]
+-------+      +----------+        +-------+      +----------+
|       | Bus  | Unified  |        |       | Bus1 | Inst Mem |
|  CPU  |<---->| Memory   |        |  CPU  |<---->+----------+
|       |      +----------+        |       | Bus2 | Data Mem |
+-------+                          +-------+      +----------+
```

1. **폰 노이만**: 하나의 버스에서 명령어 인출(Fetch)과 데이터 읽기/쓰기가 번갈아 일어나야 하므로 지연이 발생함
2. **하버드**: 명령어 버스와 데이터 버스가 분리되어 있어, 현재 명령어를 실행하면서 다음 명령어를 동시에 가져올 수 있음

## 4. 문제점 및 개선방안

1. **폰 노이만 병목 (Von Neumann Bottleneck)**: CPU와 메모리 사이의 단일 통로가 데이터 전송량을 따라가지 못해 CPU가 유휴 상태에 빠지는 문제임
   - **개선방안**: CPU 내부에 명령어 캐시(I-Cache)와 데이터 캐시(D-Cache)를 분리하여 하버드 구조의 장점을 취한 **수정 하버드 구조(Modified Harvard Architecture)**를 적용함 (확인: CPI 및 Stall 사이클 감소율)

2. **하버드 구조의 자원 낭비**: 명령어 메모리는 남는데 데이터 메모리가 부족한 경우처럼, 물리적으로 고정된 분리 공간이 자원 효율성을 떨어뜨림
   - **개선방안**: 외부 주소 공간은 하나로 통합하되, CPU 내부 파이프라인에서만 독립된 캐시를 사용하는 계층적 메모리 설계를 수행함 (확인: 메모리 활용률 및 캐시 적중률)

3. **데이터 일관성 문제**: 명령어와 데이터 공간이 분리되면 자가 수정 코드(Self-modifying code)나 동적 로딩 시 일관성 오류가 발생할 수 있음
   - **개선방안**: 메모리 배리어(Memory Barrier) 명령어를 사용하거나 일관성 프로토콜을 통해 캐시와 메인 메모리 상태를 동기화함 (확인: 일관성 오류 발생 여부)

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 현대 범용 CPU | 외부 RAM은 통합(폰 노이만)하고, L1 캐시 레벨에서 I-Cache/D-Cache를 분리(하버드)하여 성능 최적화 | L1 캐시 적중률, 파이프라인 효율(IPC) |
| DSP (신호처리) | 오디오/비디오 처리 시 대량의 데이터를 실시간으로 읽어야 하므로 하버드 구조를 채택해 처리 지연 최소화 | 실시간 응답 시간(Latency), 처리량 |
| 임베디드 MCU | 펌웨어(Flash)와 변수 저장 공간(SRAM)을 물리적으로 분리하여 시스템 안정성과 속도 확보 | 인터럽트 응답 시간, 버스 점유율 |

> 요약: 대부분의 현대 프로세서는 외부는 폰 노이만, 내부는 하버드 구조를 섞은 '하이브리드' 방식을 채택함.

## 6. 결론

컴퓨터 구조는 '범용적 유연성'과 '특수적 고성능' 사이의 균형을 맞추는 설계 철학의 산물임. 기술사는 단순히 구조의 명칭을 외우는 것을 넘어, 현대의 시스템이 왜 외부 통합-내부 분리라는 하이브리드 구조로 진화했는지 이해하고, 시스템 설계 시 발생할 수 있는 메모리 병목 지점을 정확히 진단할 수 있어야 함.

특히 칩렛(Chiplet)이나 CXL과 같은 새로운 인터커넥트 기술이 등장함에 따라, 명령어와 데이터의 전송 효율을 극대화하기 위한 구조적 선택은 더욱 세분화될 것임. 결국 구조의 이해는 하드웨어의 한계를 소프트웨어 최적화로 극복하는 출발점임.
