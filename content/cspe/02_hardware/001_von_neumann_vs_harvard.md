## 미리 알고가기

- 폰 노이만 구조는 명령어와 데이터를 같은 메모리와 버스로 다룸
- 하버드 구조는 명령어와 데이터를 분리해 병렬 접근을 노림
- 현대 CPU는 외부는 통합하고 내부는 분리하는 수정 하버드 구조를 많이 씀

## Ⅰ. 개요

- **정의/개념**: 폰 노이만 구조는 명령어와 데이터를 하나의 주소 공간과 전송 경로로 처리하는 범용 컴퓨터 구조이고, 하버드 구조는 두 자원을 분리해 명령 인출과 데이터 접근을 병렬화하는 구조임
- **배경/필요성**: CPU와 메모리 속도 차이가 커지면 단일 버스 병목이 커지므로, 범용성과 병렬 접근 중 줄일 병목을 먼저 정해야 함

## Ⅱ. 특징

- 폰 노이만 구조는 설계가 단순하고 메모리 활용이 유연함
- 하버드 구조는 명령어와 데이터 경로를 분리해 병렬 접근이 가능함
- 폰 노이만 구조는 단일 버스 병목에 취약함
- 하버드 구조는 분리 자원 관리와 일관성 처리 비용이 커짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 폰 노이만 구조 | 하버드 구조 |
|:---|:---|:---|
| 메모리 구성 | 명령어·데이터 통합 | 명령어·데이터 분리 |
| 버스 구성 | 단일 경로 | 독립 경로 |
| 장점 | 통합 주소 공간과 단순 제어 | 명령·데이터 동시 접근 |
| 적합 환경 | 범용 시스템 | DSP·MCU·캐시 내부 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| CPU | 명령어를 해독하고 연산을 수행하며 메모리 접근 방식의 병목을 직접 체감하는 실행 주체임 |
| Instruction Path | 명령어를 가져오는 경로로 하버드 구조에서는 데이터 경로와 분리되어 인출 지연을 줄임 |
| Data Path | 피연산자 읽기와 결과 쓰기를 담당하며 폰 노이만 구조에서는 명령 인출과 버스를 공유함 |
| Main Memory | 프로그램과 데이터를 저장하며 구조 선택에 따라 주소 공간 통합 또는 분리 방식이 달라짐 |

```text
+---------+     +------------------+     +-------------+
| CPU     | --> | Instruction Path | --> | Main Memory |
+---------+     +------------------+     +-------------+
     |
     v
+---------+     +------------------+
| CPU     | --> | Data Path        |
+---------+     +------------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 명령어 인출     | --> | 명령어 해독     | --> | 데이터 접근     | --> | 결과 기록      |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **명령어 인출**: 메모리에서 다음 명령어를 읽음
2. **명령어 해독**: 제어 장치가 실행 동작을 결정함
3. **데이터 접근**: 필요한 피연산자를 가져오거나 저장함
4. **결과 기록**: 연산 결과를 레지스터나 메모리에 반영함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 폰 노이만 구조에서는 명령 인출과 데이터 접근이 같은 경로를 공유하여 버스 병목이 커짐
   - 해결방안: 명령어 캐시와 데이터 캐시를 분리한 수정 하버드 구조를 적용하고 stall cycle ratio와 cache hit rate로 검증함
2. 문제: 하버드 구조에서는 명령어·데이터 공간이 고정 분리되어 한쪽 공간이 남아도 다른 쪽에서 쓰기 어려울 수 있음
   - 해결방안: 외부 주소 공간은 통합하고 내부 경로만 분리하며 memory utilization과 bandwidth efficiency로 검증함
3. 문제: 분리 경로 환경에서 코드 변경이나 동적 로딩 시 명령어와 데이터 일관성 오류가 생길 수 있음
   - 해결방안: cache invalidation과 memory barrier를 함께 적용하고 coherence error count와 deployment failure rate로 검증함

## Ⅶ. 적용 사례

- 범용 서버 CPU에서는 수정 하버드 구조를 적용하고, stall cycle ratio와 cache hit rate로 검증함
- DSP 기반 신호처리 장치에서는 분리 경로를 사용하고, bandwidth efficiency와 throughput per cycle로 검증함
- 펌웨어 갱신이 많은 임베디드 장치에서는 일관성 절차를 운영하고, coherence error count와 deployment failure rate로 검증함

## Ⅷ. 결론

폰 노이만과 하버드 구조의 선택 기준은 어느 구조가 더 우월한지가 아니라 범용성·유연성과 병렬 접근 성능 중 어떤 병목을 더 줄여야 하는지에 있음.

## 작성 근거(검토용)

- 비교 축을 메모리·버스 분리 여부로 고정해 구조 차이가 병목 차이로 이어지게 구성함
- 범위가 넓은 표현은 고정 분리로 인한 남는 공간 문제와 검증 지표로 구체화함
- 결론은 우열 판단이 아니라 단일 버스 병목과 병렬 접근 병목 중 무엇을 줄일지로 정리함
