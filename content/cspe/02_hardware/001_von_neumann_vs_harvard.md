## 미리 알고가기

- 폰 노이만 구조는 명령어와 데이터를 같은 메모리와 버스로 다룸
- 하버드 구조는 명령어와 데이터를 분리해 두 자원에 동시에 접근함
- 현대 CPU는 외부는 통합하고 내부는 분리하는 수정 하버드 구조를 주로 사용함
- 주소 공간(Address Space): CPU가 명령어·데이터를 식별하는 데 쓰는 메모리 위치 범위임
- 캐시(Cache): 자주 쓰는 명령어·데이터를 저장해 접근 속도를 높이는 임시 저장 장치임
- MCU(Microcontroller Unit): 저전력 임베디드 제어에 쓰이는 소형 마이크로컨트롤러임

## 작성 근거(검토용)

- 메모리·버스 분리 여부가 명령어 인출과 데이터 접근의 경합을 결정하도록 구성함
- 고정 분리로 인한 공간 활용 제약과 일관성 처리 조건을 실무 검증 항목으로 연결함
- 주소 공간 공유와 명령어·데이터 동시 접근 요구를 최종 선택 조건으로 정리함

## Ⅰ. 개요

- **정의/개념**: 폰 노이만 구조는 명령어와 데이터를 하나의 주소 공간과 전송 경로로 처리하는 범용 컴퓨터 구조이고, 하버드 구조는 두 자원을 분리해 명령 인출과 데이터 접근을 병렬화하는 구조임
- **배경/필요성**: 명령어 인출과 데이터 접근의 전송 대기를 줄이기 위해 메모리와 버스 구성 기준이 필요함

### 쉽게 이해하기 (학습용)
- 부품과 완제품을 같은 컨베이어 벨트로 나르면(폰 노이만) 서로 길을 막고, 벨트를 부품용과 완제품용으로 나누면(하버드) 동시에 옮길 수 있음

## Ⅱ. 특징

- 폰 노이만 구조는 명령어와 데이터가 주소 공간을 공유해 용도별 메모리 크기를 고정하지 않음
- 하버드 구조는 명령어와 데이터 경로를 분리해 병렬 접근이 가능함
- 폰 노이만 구조는 명령어 인출과 데이터 접근이 단일 버스에서 경합함
- 하버드 구조는 명령어·데이터 공간의 크기와 일관성을 각각 관리해야 함

### 쉽게 이해하기 (학습용)
- 벨트를 하나로 합치면 부품·완제품 비율을 필요할 때마다 자유롭게 조절할 수 있지만 두 화물이 같은 벨트를 다투며 지나감
- 벨트를 나누면 부품과 완제품을 동시에 옮길 수 있는 대신, 각 벨트의 용량과 재고를 서로 안 어긋나게 따로 관리해야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | 폰 노이만 구조 | 하버드 구조 |
|:---|:---|:---|
| 메모리·버스 구성 | 명령어·데이터 통합, 단일 경로 | 명령어·데이터 분리, 독립 경로 |
| 인출·접근 병목 | 명령 인출과 데이터 접근이 같은 경로에서 경합 | 각 경로에서 동시 접근 가능 |
| 확장·일관성 관리 | 단일 공간이라 일관성 문제 없이 용도별 크기를 유동적으로 조정 가능 | 두 주소 공간의 크기·일관성을 각각 관리 |

> 요약: 폰 노이만은 단일 경로에서 명령어와 데이터가 경합하고, 하버드는 경로를 분리해 동시 접근을 얻는 대신 두 공간을 각각 관리함.

### 쉽게 이해하기 (학습용)
- 벨트가 하나면 부품과 완제품이 한 줄에서 순서를 다투고, 벨트가 둘이면 각자 길을 가는 대신 두 벨트의 재고를 따로 챙겨야 함

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| CPU | 명령어를 인출·해독하고 데이터 연산과 메모리 접근을 수행함 |
| 명령어 경로 | 명령어를 가져오는 경로이며 하버드 구조에서는 데이터 경로와 분리되어 인출 지연을 줄임 |
| 데이터 경로 | 피연산자 읽기와 결과 쓰기를 담당하며 폰 노이만 구조에서는 명령 인출과 버스를 공유함 |
| 주기억장치 | 프로그램과 데이터를 저장하며 구조 선택에 따라 주소 공간 통합 또는 분리 방식이 달라짐 |

```text
[폰 노이만] CPU <-> 공용 버스 <-> 명령어·데이터 메모리

[하버드]   CPU <-> 명령어 버스 <-> 명령어 메모리
             +-> 데이터 버스   <-> 데이터 메모리
```

> 요약: 두 구조의 차이는 명령어 경로와 데이터 경로를 같은 자원으로 볼지 분리 자원으로 볼지에 있음.

### 쉽게 이해하기 (학습용)
- 작업자(CPU)가 부품과 완제품을 나르는데, 창고(주기억장치)와 통로를 하나만 쓰면 통로가 하나뿐이고, 부품·완제품 창고와 통로를 따로 두면 두 벌이 됨

## Ⅵ. 실무 사례

1. 범용 CPU는 L1 명령어·데이터 캐시를 분리하고 메모리 대기 사이클 비율·캐시 적중률을 확인함
2. 임베디드 MCU는 프로그램·데이터 메모리 용량을 조정하고 각 메모리 사용률을 확인함

### 쉽게 이해하기 (학습용)
- 큰 공장은 부품 창고와 완제품 창고를 실제로 나눠 두고 통로 대기시간과 창고 적중률을 점검하며, 작은 공장은 두 창고를 각각 얼마나 채웠는지만 확인함

## Ⅶ. 결론

- 폰 노이만과 하버드 구조는 주소 공간 공유 필요성과 명령·데이터 동시 접근 필요성을 기준으로 선택함
- 범용 CPU는 외부 메모리를 통합하고 내부 캐시만 분리하는 수정 하버드 구조로 절충하며, 임베디드 MCU는 프로그램·데이터 메모리 용량을 고정한 순수 하버드 구조를 적용함

### 쉽게 이해하기 (학습용)
- 창고를 하나로 합쳐 재고를 유연하게 쓸지, 창고를 나눠 동시에 꺼내 쓸지를 필요에 따라 고름
