## 미리 알고가기

- 폰 노이만 구조는 명령어와 데이터를 같은 메모리와 버스로 다룸
- 하버드 구조는 명령어와 데이터를 분리해 병렬 접근을 노림
- 현대 CPU는 외부는 통합하고 내부는 분리하는 수정 하버드 구조를 주로 사용함

## Ⅰ. 개요

- **정의/개념**: 폰 노이만 구조는 명령어와 데이터를 하나의 주소 공간과 전송 경로로 처리하는 범용 컴퓨터 구조이고, 하버드 구조는 두 자원을 분리해 명령 인출과 데이터 접근을 병렬화하는 구조임
- **배경/필요성**: CPU와 메모리의 속도 차이로 생기는 전송 병목을 줄이기 위해 메모리와 버스 구성 기준이 필요함

## Ⅱ. 특징

- 폰 노이만 구조는 설계가 단순하고 메모리 활용이 유연함
- 하버드 구조는 명령어와 데이터 경로를 분리해 병렬 접근이 가능함
- 폰 노이만 구조는 단일 버스 병목에 취약함
- 하버드 구조는 분리 자원 관리와 일관성 처리 비용이 커짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 폰 노이만 구조 | 하버드 구조 |
|:---|:---|:---|
| 메모리 구성 | 명령어·데이터 통합 | 명령어·데이터 분리 |
| 버스 구성 | 단일 경로 | 독립 경로 |
| 장점 | 통합 주소 공간과 단순 제어 | 명령·데이터 동시 접근 |
| 적합 환경 | 범용 시스템 | DSP·MCU·캐시 내부 |

> 요약: 폰 노이만은 통합 구조의 범용성, 하버드는 분리 경로의 병렬 접근이 선택 기준임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| CPU | 명령어를 해독하고 연산을 수행하며 메모리 접근 방식의 병목을 직접 체감하는 실행 주체임 |
| 명령어 경로 | 명령어를 가져오는 경로이며 하버드 구조에서는 데이터 경로와 분리되어 인출 지연을 줄임 |
| 데이터 경로 | 피연산자 읽기와 결과 쓰기를 담당하며 폰 노이만 구조에서는 명령 인출과 버스를 공유함 |
| 주기억장치 | 프로그램과 데이터를 저장하며 구조 선택에 따라 주소 공간 통합 또는 분리 방식이 달라짐 |

```text
+---------+     +------------------+     +-------------+
| CPU     | --> | Instruction Path | --> | Main Memory |
+---------+     +------------------+     +-------------+
     |
     v
+---------+     +------------------+
| CPU     | --> | Data Path        |
+---------+     +------------------+
```

> 요약: 두 구조의 차이는 명령어 경로와 데이터 경로를 같은 자원으로 볼지 분리 자원으로 볼지에 있음.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 명령어 인출     | --> | 명령어 해독     | --> | 데이터 접근     | --> | 결과 기록      |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **명령어 인출**: 메모리에서 다음 명령어를 읽음
2. **명령어 해독**: 제어 장치가 실행 동작을 결정함
3. **데이터 접근**: 필요한 피연산자를 가져오거나 저장함
4. **결과 기록**: 연산 결과를 레지스터나 메모리에 반영함

> 요약: 명령어 인출과 데이터 접근이 같은 경로를 쓰면 병목이 커지고, 분리하면 병렬성은 커지지만 관리 비용이 늘어남.

## Ⅵ. 실무 적용 및 유의점

1. 범용 CPU는 단일 버스 병목을 줄이기 위해 명령어 캐시와 데이터 캐시를 분리한 수정 하버드 구조를 적용하고 stall cycle ratio와 cache hit rate로 검증함
2. 임베디드·동적 로딩 환경은 공간 활용률과 일관성 문제가 생길 수 있으므로 외부 주소 공간은 통합하고 cache invalidation과 memory barrier를 적용해 memory utilization과 coherence error count로 확인함

## Ⅶ. 결론

- 폰 노이만과 하버드 구조의 선택 기준은 우열이 아니라 범용성·유연성과 병렬 접근 성능 중 어떤 병목을 줄일지에 있음

## 작성 근거(검토용)

- 비교 기준을 메모리·버스 분리 여부로 고정해 구조 차이가 병목 차이로 이어지게 구성함
- 범위가 넓은 표현은 고정 분리로 인한 공간 활용 문제와 검증 지표로 구체화함
- 결론은 우열 판단이 아니라 단일 버스 병목과 병렬 접근 병목 중 무엇을 줄일지로 정리함
