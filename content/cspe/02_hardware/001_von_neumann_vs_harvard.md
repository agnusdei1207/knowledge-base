## 미리 알고가기

- 명령어 집합 구조(Instruction Set Architecture, ISA): 소프트웨어가 중앙처리장치(Central Processing Unit, CPU)에 요구할 수 있는 명령어와 동작 규칙임
- 마이크로아키텍처: ISA를 실제 회로와 파이프라인으로 구현한 내부 구조임
- 프로그램 내장 방식: 명령어와 데이터를 메모리에 함께 저장하고 순차적으로 실행하는 방식임
- 병목: 처리 요소 중 가장 느린 자원이 전체 처리량을 제한하는 현상임

## Ⅰ. 개요

- **정의**: 컴퓨터 구조는 CPU, 메모리, 입출력장치가 명령어와 데이터를 어떤 통로와 저장 공간으로 주고받는지 정한 기본 설계 기준임. 폰 노이만 구조와 하버드 구조는 명령어 메모리와 데이터 메모리를 통합할지 분리할지에 따라 성능, 비용, 구현 복잡도를 판단하는 대표 분류임.
- **배경/필요성**: 프로그램 내장 방식은 범용 컴퓨터 구현을 단순화했지만 명령어와 데이터가 같은 버스를 공유해 CPU 대기 시간이 발생함. 임베디드, DSP, 고성능 CPU에서는 접근 병목을 줄이기 위해 분리 캐시나 하버드식 내부 구조를 선택함.
- **비유**: 폰 노이만은 사람과 물건이 같은 출입문을 쓰는 건물이고, 하버드는 사람용 문과 물류용 문을 나눈 건물임.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 구조 차이와 적용 조건 판단 | 저장 공간 분리 여부, 버스 병목, 수정 하버드 구조 | 단순 속도 우열로만 설명 |

> 요약: 메모리와 버스 분리 여부가 컴퓨터 구조의 성능, 비용, 적용 영역을 결정함.

## Ⅱ. 특징/비교

| 판단 기준 | 폰 노이만 구조 | 하버드 구조 |
|:---|:---|:---|
| 메모리 구성 | 명령어와 데이터를 하나의 주소 공간에 저장함 | 명령어와 데이터를 별도 공간에 저장함 |
| 접근 경로 | 하나의 버스를 공유해 동시 접근이 제한됨 | 명령어 fetch와 데이터 접근을 병렬화할 수 있음 |
| 구현 비용 | 범용 OS와 프로그램 적재가 단순함 | 버스와 메모리 제어가 복잡하고 비용이 증가함 |
| 적용 기준 | 범용 컴퓨터, 유연한 프로그램 실행에 적합함 | MCU, DSP, L1 I/D 캐시 분리 구조에 적합함 |

> 요약: 유연성이 우선이면 폰 노이만, 명령어·데이터 병렬 접근이 우선이면 하버드 계열을 선택함.

## Ⅲ. 구성요소

```text
+------------------+        +------------------+
| Von Neumann      |        | Harvard          |
| +-----+          |        | +-----+          |
| | CPU |          |        | | CPU |          |
| +--+--+          |        | +-+-+-+          |
|    | inst/data   |        |   | | inst/data  |
| +--v-----------+ |        | +-v+ +-v------+  |
| | Unified Mem  | |        | |I | |D Mem   |  |
| +--------------+ |        | +--+ +--------+  |
+------------------+        +------------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| CPU | 명령어를 해석하고 데이터 연산을 수행하는 처리 주체임 | 작업자 |
| 명령어 메모리 | 실행할 프로그램 코드를 저장하거나 캐시하는 공간임 | 작업 지시서함 |
| 데이터 메모리 | 연산 대상과 결과 데이터를 저장하는 공간임 | 자재 창고 |
| 버스/인터커넥트 | CPU와 메모리 사이의 주소, 데이터, 제어 신호를 전달함 | 출입 통로 |

> 요약: 명령어와 데이터의 저장 위치와 이동 통로를 어떻게 나누는지가 구조 차이를 만듦.

## Ⅳ. 절차

```text
+----------+     +----------+     +----------+     +----------+
| Fetch    | --> | Decode   | --> | Execute  | --> | Writeback|
+----------+     +----------+     +----------+     +----------+
      |                 |                |                |
      +---- memory/bus access decision --+----------------+
```

1. **명령어 인출** - PC가 가리키는 주소에서 명령어를 가져오며, 통합 또는 분리 경로를 사용함
2. **명령어 해석** - 제어장치가 opcode와 operand를 해석하고 필요한 데이터 접근을 결정함
3. **연산 수행** - ALU나 실행 유닛이 레지스터와 메모리 데이터를 이용해 연산함
4. **결과 반영** - 결과를 레지스터나 메모리에 기록하고 다음 명령어 주소로 진행함

> 요약: 실행 절차는 동일하지만 명령어와 데이터 접근 경로 분리가 병렬성의 차이를 만듦.

## Ⅴ. 문제점 및 개선방안

- **P1 폰 노이만 병목**: 명령어 fetch와 데이터 접근이 같은 버스를 사용해 CPU가 메모리 응답을 기다리는 시간이 증가함
- **P1 대응**: L1 명령 캐시(Instruction Cache, I-Cache)와 데이터 캐시(Data Cache, D-Cache) 분리, prefetch, 넓은 메모리 버스로 명령어와 데이터 접근 충돌을 줄임 (확인: 캐시 miss rate, IPC)
- **P2 하버드 경직성**: 코드와 데이터 주소 공간이 분리되면 자기수정 코드, 동적 로딩, 범용 OS 메모리 관리가 복잡해짐
- **P2 대응**: 통합 주소 공간을 유지하되 내부 캐시만 분리하는 수정 하버드 구조를 적용함 (확인: 코드 적재 호환성, 캐시 일관성 오류)
- **P3 계층 혼합 복잡도**: 현대 CPU는 외부는 통합 메모리, 내부는 I/D 캐시 분리라 일관성, 예외, 캐시 무효화 처리가 필요함
- **P3 대응**: 캐시 flush/invalidate 규칙, 직접 메모리 접근(Direct Memory Access, DMA) coherency, 메모리 장벽 명령을 표준화함 (확인: 드라이버 검증, 일관성 테스트)

> 요약: 외부 호환성은 유지하고 내부 병렬성을 키우는 수정 하버드 방식이 현실적 개선책임.

## Ⅵ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 범용 서버 CPU | 외부는 통합 주소 공간을 유지하고 내부 L1 I-Cache/D-Cache 분리로 명령어 fetch와 데이터 접근 충돌을 줄임 | instruction fetch stall, data cache miss, IPC |
| 실시간 마이크로컨트롤러(Microcontroller Unit, MCU) | 명령 메모리와 데이터 메모리를 분리해 예측 가능한 접근 지연을 확보하고 인터럽트 응답성을 검증함 | worst-case latency, flash wait state, SRAM access time |
| DMA 기반 장치 드라이버 | 수정 하버드 구조에서 캐시 무효화와 메모리 장벽을 명시해 CPU 캐시와 장치 메모리 관측값을 일치시킴 | coherency test, DMA 오류율, 드라이버 회귀 테스트 |

> 요약: 구조 선택은 명령·데이터 접근 충돌, 실시간 지연, 캐시 일관성을 실제 지표로 검증할 때 의미가 있음.

## Ⅶ. 전망

- **발전 방향**: CPU 내부는 명령/데이터 분리 캐시와 통합 메모리 공간을 결합한 수정 하버드 구조로 유지되고, 칩렛·CXL 환경에서는 접근 경로와 대역폭 계층이 더 세분화됨
- **기술사적 판단**: 범용성은 통합 주소 공간, 실시간성은 명령 fetch와 데이터 load/store 충돌 방지, 전력은 포트 수와 캐시 크기 기준으로 선택함; `CPI`, instruction fetch stall, data cache miss, 메모리 버스 점유율을 함께 측정해 구조 분리 효과가 실제 병목 감소로 이어졌는지 확인함
- **기술사 제언**: 구조 명칭보다 메모리 병목, 분리 캐시 효과, 현대 CPU의 수정 하버드 구현을 성능·검증 기준으로 연결해 판단해야 함
