## Ⅰ. 개요
- **정의**: 명령어와 데이터의 메모리 배치 방식에 따른 컴퓨터 구조 분류
- **배경/필요성**: 프로그램 내장 방식으로 범용성을 확보하되, 명령어·데이터 동시 접근 요구가 커지면서 메모리 경로 분리 필요성 대두
- **비유**: 한 줄 창구(VN)는 모든 업무를 한 곳에서 처리하여 줄이 길어지고, 두 줄 창구(Harvard)는 업무별 전용 창구로 대기 시간을 줄임

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 두 구조의 근본 차이와 트레이드오프 이해 | VN 병목 원인(단일 버스 경합), Harvard의 하드웨어 비용 증가 | Modified Harvard를 누락하면 현대 CPU 설명 불가 |

> 요약: 메모리 경로 공유 여부가 두 구조의 핵심 차이이며, 현대 CPU는 Modified Harvard로 절충함

## Ⅱ. 구성요소
```text
[Von Neumann]
CPU --<단일 버스>-- 통합 메모리(명령어+데이터)

[Harvard]
CPU --<명령어 버스>-- 명령어 메모리
    --<데이터 버스>-- 데이터 메모리

[Modified Harvard]
CPU -- L1I Cache(명령어) / L1D Cache(데이터) -- 통합 L2/L3 -- 주메모리
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 통합 메모리(VN) | 명령어와 데이터가 동일 주소 공간에 저장, 단일 버스로 접근 | 한 권의 노트에 문제와 답을 번갈아 기록 |
| 분리 메모리(Harvard) | 명령어 메모리와 데이터 메모리가 물리적으로 분리, 독립 버스 사용 | 문제지와 답안지를 별도로 들고 동시에 읽음 |
| L1 캐시 분리(Modified Harvard) | CPU 내부에서 I-Cache와 D-Cache를 분리하되, 하위 계층은 통합 | 책상 위에는 참고서와 연습장을 따로 두되, 서랍은 공유 |
| 버스 | 주소·데이터·제어 신호 전달 경로 | 도로 차선 — 차선이 많을수록 동시 통행량 증가 |

> 요약: VN은 단일 버스·통합 메모리, Harvard는 이중 버스·분리 메모리, Modified Harvard는 캐시 수준에서 분리하여 절충함

## Ⅲ. 절차
```text
Fetch(명령어 인출) --> Decode(해석) --> Execute(연산) --> Writeback(결과 저장)
       |                                                       |
       +--- VN: 같은 버스로 명령어·데이터 순차 접근 (경합) -----+
       +--- Harvard: 명령어 버스와 데이터 버스 동시 접근 -------+
```
- 1단계: **Fetch** — PC가 가리키는 주소에서 명령어를 인출하며, VN 구조에서는 데이터 접근과 버스를 공유함
- 2단계: **Decode** — 인출된 명령어를 해석하여 연산 종류와 오퍼랜드를 결정함
- 3단계: **Execute** — ALU가 연산을 수행하며, 데이터 메모리 접근이 필요하면 VN에서는 버스 경합 발생
- 4단계: **Writeback** — 연산 결과를 레지스터 또는 메모리에 저장하며, Harvard에서는 데이터 전용 버스를 사용함

> 요약: 명령어 사이클 전 구간에서 VN은 단일 버스 경합이 발생하고, Harvard는 이를 이중 버스로 해소함

## Ⅳ. 문제점
- **VN 병목(Von Neumann Bottleneck)**: 명령어와 데이터가 단일 버스를 공유 — CPU 처리 속도 대비 메모리 대역폭이 병목이 됨
- **Harvard 하드웨어 비용 증가**: 메모리·버스를 이중으로 배치 — 회로 면적과 설계 복잡도가 증가하여 범용 시스템 적용이 어려움
- **메모리 활용 비효율**: Harvard에서 명령어·데이터 메모리 크기가 고정 — 한쪽이 남아도 다른 쪽에 재할당할 수 없어 낭비 발생

> 요약: VN은 대역폭 병목, Harvard는 비용·유연성 문제를 가지며 둘 다 단독으로는 한계가 있음

## Ⅴ. 개선방안
1. **단기**: 캐시 계층 분리(L1I/L1D) — VN 병목을 CPU 내부에서 완화하는 Modified Harvard 적용
2. **중기**: 메모리 인터리빙·멀티채널 — Harvard 수준의 대역폭을 통합 메모리에서 확보하여 비용 절감
3. **장기**: Processing-in-Memory(PIM) — 연산을 메모리 근처로 이동시켜 버스 병목 자체를 제거

> 요약: 캐시 분리로 당장의 병목을 완화하고, 장기적으로는 연산-메모리 간 거리를 줄이는 방향으로 발전함

## Ⅵ. 전망
- **발전 방향**: CXL 기반 메모리 풀링과 PIM이 보편화되면 VN/Harvard 이분법이 약화될 전망
- **기술사적 판단**: 현대 CPU는 Modified Harvard가 사실상 표준이며, 시험에서는 세 가지 구조의 트레이드오프를 정확히 비교하는 능력이 평가됨
- **기술사 제언**: 구조 선택 시 대역폭·비용·유연성 세 축의 균형을 정량적으로 분석할 것을 권고함
