# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: **컴퓨터 아키텍처**(Computer Architecture)의 두 원형으로, **저장 프로그램 방식**에서 명령어와 데이터를 하나의 메모리·버스로 통합하느냐(폰 노이만) 물리적으로 분리하느냐(하버드)를 가르는 설계 모델이다.
- **왜 필요한가**: 명령어와 데이터가 CPU로 들어오는 경로(버스)를 어떻게 놓느냐가, CPU가 한 사이클에 "명령어 인출"과 "데이터 접근"을 동시에 할 수 있는지를 결정하기 때문이다.
- **핵심 직관**: 창고(메모리)에서 레시피(명령어)와 재료(데이터)를 꺼낼 때, 통로가 하나면(폰 노이만) 번갈아 꺼내야 하고 둘이면(하버드) 양손으로 동시에 꺼낸다.

## 핵심 용어 정리 (내부에 등장하는 것들)
아래 표는 답안(Ⅰ~Ⅵ)에 등장하는 모든 용어를 비유와 함께 먼저 풀어둔 것이다. 맨 위 두 줄이 이 키워드의 상위 핵심 키워드다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| **컴퓨터 아키텍처** | CPU·메모리·버스를 어떻게 연결하고 명령어를 어떻게 처리할지 정한 하드웨어 골격 | 건물의 배관·전선 배치도 |
| **저장 프로그램 방식** | 명령어를 데이터처럼 메모리에 넣어두고 CPU가 순서대로 읽어 실행하는 방식 | 레시피를 종이에 적어두고 위에서부터 읽어 요리 |
| **버스 (Bus)** | CPU·메모리·I/O 사이에서 신호를 나르는 공용 전선 묶음. 주소(어디)·데이터(무엇)·제어(어떻게) 3종 | 물건을 실어 나르는 컨베이어 벨트 |
| **폰 노이만 병목** | 명령어와 데이터가 단일 버스를 공유해 한 번에 하나만 지나가며 생기는 구조적 지연 | 1차선 도로에 우편차와 택배차가 겹쳐 정체 |
| **명령어 인출 (Fetch)** | 메모리에서 다음 실행할 명령어를 CPU로 읽어오는 동작 | 요리사가 다음 조리 단계를 레시피에서 읽음 |
| **파이프라인** | 명령어의 인출·해독·실행 단계를 겹쳐 흘려보내 처리량을 높이는 기법 | 컨베이어에서 여러 요리를 단계별로 동시에 진행 |
| **구조적 해저드** | 두 명령어가 같은 자원(버스·메모리 포트)을 동시에 요구해 하나가 멈추는 충돌 | 칼 하나를 두 요리사가 동시에 잡으려 함 |
| **IPC / Throughput** | 한 사이클에 완료하는 명령어 수(IPC) 및 단위 시간 처리량 | 시간당 완성 접시 수 |
| **변형된 하버드 (Modified Harvard)** | 코어 안 L1 캐시만 명령어/데이터로 분리하고 바깥 메인 메모리는 통합한 현대 절충 구조 | 조리대 위 선반만 재료/레시피로 나누고 창고는 공용 |
| **I-Cache / D-Cache** | 명령어 전용(I)·데이터 전용(D)으로 나눈 L1 캐시 | 레시피 전용 선반, 재료 전용 냉장고 |
| **NX Bit / DEP** | 데이터 영역의 실행을 하드웨어로 차단하는 보안 비트(및 OS 정책 DEP) | 택배 상자(데이터)는 열되 먹지(실행) 못하게 함 |

## 깊이 이해
- **배경·문제의식**: 최초 컴퓨터 ENIAC은 프로그램을 바꿀 때마다 수천 개 전선을 다시 꽂아야 했다. 존 폰 노이만은 "명령어도 데이터처럼 메모리에 저장하자"(저장 프로그램)는 착상을 냈고, 이것이 오늘날 모든 범용 컴퓨터의 뿌리가 됐다. 그러나 단일 버스로 명령어와 데이터를 함께 나르니, 명령어를 읽는 순간에는 데이터를 못 읽는 한계(병목)가 드러났다. 하버드 대학의 Mark I은 처음부터 두 경로를 물리적으로 나눠 이 병목을 없앴다.
- **작동 원리 (어떻게+왜)**:
  - **폰 노이만**: 주소·데이터 버스가 하나뿐이라 회로가 단순하고 메모리를 명령어/데이터 구분 없이 유연하게 쓴다. 대신 매 사이클 인출(Fetch)과 데이터 접근 중 하나만 가능해, 둘이 겹치면 1사이클 멈춘다.
  - **하버드**: 명령어 전용 버스와 데이터 전용 버스를 따로 둔다. 다음 명령어를 읽어오는 동시에 현재 명령어의 피연산자를 메모리에서 가져올 수 있어, 파이프라인이 멈추지 않는다. 대신 버스·핀(Pin) 수가 두 배라 칩 면적과 단가가 오른다.
- **비유**: 요리사가 레시피 북과 식재료를 같은 상자에 두면(폰 노이만) 하나를 꺼낸 뒤에야 다른 걸 꺼낸다. 레시피 전용 선반과 식재료 전용 냉장고가 따로 있으면(하버드) 양손으로 동시에 준비한다.
- **구체 예시**: 5단 파이프라인에서 1번 명령어가 데이터 메모리에 접근(MEM)하는 사이클과 4번 명령어를 인출(IF)하는 사이클이 겹칠 때, 폰 노이만은 버스 경합으로 1사이클 정지(Stall)가 생기지만, 하버드는 IF와 MEM이 서로 다른 버스를 써서 병렬 진행된다.
- **흔한 오해·주의점**: "현대 PC는 폰 노이만이다"라고 단정하면 안 된다. 현대 CPU는 코어 안 L1만 I-Cache/D-Cache로 분리(하버드)하고, 코어 밖 L2·L3·메인 메모리는 통합(폰 노이만)해 쓰는 **변형된 하버드**다. 순수/폰 노이만 이분법이 아니라 계층별 혼합이 정답이다.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 명령어와 데이터의 메모리 공간·버스 경로를 통합(폰 노이만)하느냐 물리 분리(하버드)하느냐를 정하는 컴퓨터 아키텍처 설계 원형
> 2. **가치**: 인출과 데이터 접근을 병행 처리해 파이프라인 구조적 해저드를 제거하고 IPC를 높이는 것이 하버드 계열의 이점
> 3. **판단 포인트**: 범용 시스템은 유연성을 위해 변형된 하버드를, 실시간 신호처리는 확정적 대역폭을 위해 순수 하버드를 채택

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| CPU 병목 원인 진단과 아키텍처 분기 이해 확인 | 폰 노이만 병목, 파이프라인 IF/MEM 구조적 해저드 | 역사적 사실 나열에 그침 |
| 현대 프로세서의 구조적 절충 파악 확인 | L1 분리 캐시(Modified Harvard) 구조와 효익 | 현대 CPU를 단일 아키텍처로 단정 |

> 요약: 폰 노이만 병목을 파이프라인 구조적 해저드 관점으로 진단하고, 현대 프로세서의 계층적 혼합(Modified Harvard)을 제시함.

## Ⅰ. 개요 및 필요성

- 개요: 저장 프로그램 방식에서 명령어·데이터의 저장 위치와 CPU 접근 경로를 정의하는 논리적 설계 체계
- 배경: 단일 버스 공유 시 인출과 데이터 접근이 경합하는 폰 노이만 병목 발생
- 필요성: 고속 파이프라인에서 IF(인출)와 MEM(데이터) 단계 충돌(구조적 해저드)을 막아 IPC를 확보할 필요

---

## Ⅱ. 구조 및 구성요소

```text
[폰 노이만] CPU -> 공용 버스 -> 통합 메모리(명령어 + 데이터)

[하버드]   CPU -> 명령어 버스 -> 명령어 메모리
              -> 데이터 버스   -> 데이터 메모리

[변형 하버드] CPU -> L1 I-Cache / L1 D-Cache (분리)
                  -> L2 이하 -> 통합 메인 메모리
```

| 구분 | 폰 노이만 | 하버드 | 특이사항 |
|:---|:---|:---|:---|
| 메모리 공간 | 단일 통합 주소 공간 | 명령어/데이터 물리 분리 | 공간 활용 유연성 차이 |
| 버스 구성 | 단일 주소·데이터 버스 | 이중(분리) 버스 | 하버드는 핀 수·면적 2배 |
| 병렬 접근 | 인출·데이터 택일 | 인출·데이터 동시 | 하버드가 구조적 해저드 제거 |

> 요약: 폰 노이만은 단일 버스로 단순·유연하고, 하버드는 이중 버스로 명령어·데이터 동시 접근을 보장함.

---

## Ⅲ. 동작원리 및 흐름도

```text
[변형된 하버드 처리 흐름]
PC 지정 주소 -> L1 I-Cache 인출 -> CU 해독 -> ALU 실행 -> L1 D-Cache 데이터 접근
            -> L1 미스 시 -> 통합 L2/메인 메모리 접근
```

- 1단계 [인출]: PC가 지정한 주소의 명령어를 명령어 전용 버스(또는 I-Cache)로 인출
- 2단계 [해독·실행]: CU가 명령어를 해석하고 ALU가 산술·논리 연산 수행
- 3단계 [데이터 접근]: 피연산자 로드·결과 저장 시 데이터 전용 버스(또는 D-Cache)로 동시 접근
- 4단계 [갱신·동기화]: 레지스터 상태 갱신, L1 미스 시 통합 메모리에서 데이터 동기화

> 요약: 코어 내부는 하버드로 분리 접근해 성능을, 외부는 폰 노이만으로 통합해 유연성을 확보함.

---

## Ⅳ. 특징

- 폰 노이만 병목: CPU 클럭 대비 단일 버스 대역폭이 시스템 성능의 하한을 결정함
- 하버드 설계 부담: 버스·핀 수가 2배로 늘어 칩 면적(Die size)과 제조 단가 상승의 트레이드오프 존재
- 보안·유연성 상충: 폰 노이만은 자기수정코드(JIT) 구현에 유리하나 코드 인젝션에 취약해 NX Bit 보호가 필수임

---

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 폰 노이만 | 순수 하버드 | 변형된 하버드(현대) |
|:---|:---|:---|:---|
| 버스 경합 | 구조적 해저드 빈발 | 물리 분리로 경합 없음 | L1 적중 시 경합 제거 |
| 설계 복잡도 | 낮음(단일 인터페이스) | 높음(이중 인터페이스) | 중간(계층형) |
| 동적 할당 | 우수(공유 영역) | 불가(영역 고정) | 우수(L2 이하 통합) |

> 요약: 범용 컴퓨팅은 유연한 변형된 하버드를, 임베디드·DSP는 확정적 성능을 위해 순수 하버드를 선택함.

**리스크·대응:**
- [코드 인젝션]: 데이터 영역의 악성 코드 실행 위험 → NX Bit 및 OS DEP로 실행 권한 차단
- [캐시 불일치]: Modified Harvard에서 자기수정코드 실행 시 I-Cache와 D-Cache 내용 불일치 → 실행 전 Cache Flush/Invalidate 수행
- [공간 낭비]: 순수 하버드에서 한쪽 메모리 잔여분을 반대 용도로 못 씀 → 주기억을 통합하는 계층형 구조 채택

**도입 후 점검 지표:**
- IPC: 목표 1.0~1.3 근접 여부 — PMU(성능 카운터)로 측정
- L1 미스율: I-Cache·D-Cache 각 5% 미만 유지 — 성능 카운터 분석

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 범용 프로세서(x86·ARM): L1을 I/D로 분리해 인출·로드 간섭을 없애고 파이프라인 효율 확보
2. 신호처리 가속기(DSP·TI C6000): 루프 연산 사이클 손실을 막기 위해 명령어·데이터 메모리를 완전 분리한 순수 하버드 채택
3. 보안 강화: 데이터 영역에 NX 설정을 걸어 폰 노이만 구조의 코드 인젝션 취약점을 하드웨어 수준에서 차단

**결론 (2줄):**
- 기술사 판단: 워크로드 병렬성 요구와 칩 면적 비용을 저울질해, 코어 내부(L1)와 외부(L2/L3)의 버스 분리 지점을 최적 설계해야 함
- 향후 방향: 데이터 이동 병목을 근본 해결하려 메모리 내부에서 연산하는 PIM(Processing-In-Memory)이 차세대 대안으로 부상 중
