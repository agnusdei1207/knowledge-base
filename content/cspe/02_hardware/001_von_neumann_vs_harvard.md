## Ⅰ. 개요
- 정의: 프로그램 메모리와 데이터 메모리가 구분되었는지에 따른 컴퓨터 아키텍처 분류
- 배경: 프로그램 내장 방식(Stored-Program)의 구현과 병목 현상 해결 필요성
- 출제 의도: 두 구조의 차이점, 병목 현상(Bus Bottleneck) 및 현대적 혼용 방식 이해

## Ⅱ. 구성요소
- ASCII 구조도
  [Von Neumann]          [Harvard]
  +-----------+          +-----------+
  |    CPU    |          |    CPU    |
  +-----+-----+          +--+-----+--+
        | Bus               |     |
  +-----+-----+        Inst |     | Data
  | Mem (I+D) |        +----+  +----+
  +-----------+        |Inst|  |Data|
                       +----+  +----+

- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| 공통 버스 | 폰 노이만 구조에서 명령어/데이터 공유 통로 | 단선 도로 |
| 분리 버스 | 하바드 구조에서 명령어/데이터 개별 통로 | 복선 도로 |
| 통합 메모리 | 폰 노이만: 코드와 데이터가 같은 공간 존재 | 한 수첩에 기록 |
> 요약: 폰 노이만은 구조적 단순성, 하바드는 성능 최적화에 중점을 둠

## Ⅲ. 절차
- ASCII 흐름도
  (Fetch) -> (Decode) -> (Execute) -> (Store)
      ^                                |
      +--------------------------------+

- 4단계 설명
1. Fetch: 메모리에서 명령어를 읽어 CPU로 가져옴
2. Decode: 명령어의 의미를 해석하고 제어 신호 생성
3. Execute: ALU를 통해 연산을 수행하거나 데이터 이동
4. Write-back: 연산 결과를 메모리나 레지스터에 기록
> 요약: 순차적 실행 구조를 가지며, 하바드는 1단계를 병렬화 가능함

## Ⅳ. 문제점
- 폰 노이만 병목: 동일 버스 사용으로 명령어/데이터 동시 접근 불가
- 하바드 복잡성: 버스 라인 증가로 인한 하드웨어 설계 비용 상승

## Ⅴ. 개선방안
- (단기) 수정된 하바드 구조: CPU 내부는 분리, 외부는 통합 메모리 사용
- (중기) 캐시 메모리 L1 분리: L1 캐시를 I-Cache, D-Cache로 구분하여 병목 해소
- (장기) 메모리 중심 컴퓨팅(PIM): 메모리 내 연산으로 데이터 이동 최소화

## Ⅵ. 전망
- 로드맵: 고성능 서버는 계층적 캐시를 통한 하바드형 적용, 저전력 MCU는 폰 노이만 유지
- CSF: 온칩 버스 대역폭 극대화 및 고속 캐시 정합성 제어 기술 확보가 핵심임
