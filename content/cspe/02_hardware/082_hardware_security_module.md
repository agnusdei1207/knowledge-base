## 미리 알고가기

- HSM은 암호키를 장치 내부에서 생성, 저장, 사용하는 전용 보안 장치임
- tamper resistance는 물리 변조를 감지하거나 차단하는 보호 기능임
- key ceremony는 키 생성, 백업, 권한 분리를 공식 절차로 관리하는 운영 방식임

## Ⅰ. 개요

- **정의/개념**: HSM은 암호키를 서버 메모리나 파일에 노출하지 않고 변조 방지 하드웨어 내부에서 생성, 저장, 연산하게 하는 전용 키 보호 장치임
- **배경/필요성**: 암호 시스템의 안전성은 키 보호 수준에 직접 좌우되므로 결제, PKI, 코드 서명처럼 침해 비용이 큰 환경에서는 소프트웨어 키 저장소만으로 부족함

## Ⅱ. 특징

- 키를 장치 경계 안에 가둬 평문 추출 위험을 낮춤
- 역할 분리, 승인 절차, 감사 로그로 운영 통제를 강화함
- PKI와 결제처럼 대량 서명 업무를 처리할 수 있게 성능형 장비로 확장 가능함
- 장비 장애와 연동 지연이 전체 인증 경로의 병목이 될 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 소프트웨어 키 저장소 | TPM | HSM |
|:---|:---|:---|:---|
| 보호 경계 | 운영체제와 파일 보호에 주로 의존함 | 장치 무결성과 부팅 보호에 초점이 맞음 | 키 생성부터 사용까지 전용 하드웨어 경계로 보호함 |
| 대표 용도 | 일반 응용의 비밀값 보관에 적합함 | 기기 신뢰 부팅과 장치 인증에 적합함 | CA 키와 결제 키와 코드 서명 키 보호에 적합함 |
| 처리 성능 | 간단한 업무에는 충분하지만 대량 서명에는 한계가 있음 | 처리량보다 신뢰 루트 기능이 중요함 | 대량 암호 연산과 감사 통제를 함께 처리하기에 적합함 |
| 운영 난도 | 가장 낮지만 보호 강도도 낮음 | 플랫폼 종속 관리가 필요함 | 백업과 이중화와 권한 분리를 엄격히 설계해야 함 |

> 요약: HSM은 소프트웨어 저장소나 TPM보다 키 사용 경계를 강하게 통제하지만 운영 절차가 무거움.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 보안 키 저장소 | 키를 외부 평문 노출 없이 저장하며 수명주기 정책의 기준점이 됨 |
| 암호 연산 엔진 | 서명, 암복호, 난수 생성을 내부에서 수행해 키 노출을 차단함 |
| 정책·접근 통제 | 역할 분리와 승인 절차를 강제해 내부 오남용을 줄임 |
| 감사·변조 대응 | 사용 기록과 변조 감지를 제공해 사고 대응과 규제 준수를 지원함 |

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 키 생성·반입   | --> | 정책 설정      | --> | HSM 내부 연산   | --> | 감사·교체 운영  |
+-------------+     +-------------+     +-------------+     +-------------+
```

> 요약: HSM 구조는 키 저장소, 내부 연산, 접근 통제, 감사 기능이 결합된 키 보호 경계임.

## Ⅴ. 원리 및 절차 흐름도

1. **키 생성·반입**: HSM 내부 생성 또는 승인된 절차로 키를 준비함
2. **정책 설정**: 사용 권한, 용도, 만료, 승인 조건을 정함
3. **HSM 내부 연산**: 응용 시스템이 API로 요청하면 장치 내부에서만 암호 연산을 수행함
4. **감사·교체 운영**: 로그 검토, 키 회전, 백업 복구 절차를 운영함

> 요약: HSM은 키 준비, 정책 설정, 내부 연산, 감사·교체가 끊기지 않아야 안전함.

## Ⅵ. 실무 적용 및 유의점

1. 루트 CA나 코드 서명 환경은 키 유출 비용이 크므로 HSM이 필요하지만 장비 장애가 서명 경로를 중단시킬 수 있어 이중화와 key ceremony를 운영하고 서명 지연시간, 복구 성공률, 권한 작업 감사 범위로 확인함
2. 결제 승인이나 대량 TLS 종료는 HSM이 키 보호에 유리하지만 요청이 몰리면 병목이 생기므로 클러스터링과 요청 배치를 적용하고 초당 처리 건수, HSM 사용률, 비인가 작업 차단율로 확인함

## Ⅶ. 결론

HSM의 가치는 암호 연산 속도보다 키를 밖으로 내보내지 않는 통제력에 있으므로, 장비 도입보다 키 수명주기와 운영 절차 설계가 먼저임.

## 작성 근거(검토용)

- HSM은 키 비노출, 변조 방지 경계, 역할 분리, 감사 추적을 핵심 키워드로 선정함
- 비교표는 소프트웨어 키 저장소, TPM, HSM의 보호 경계와 운영 난도를 대비함
- 실무 판단은 서명 지연시간, 복구 성공률, HSM 사용률, 비인가 작업 차단율로 검증 가능하게 작성함
