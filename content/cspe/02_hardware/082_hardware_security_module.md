## 미리 알고가기

- HSM(Hardware Security Module): 암호키 생성, 저장, 사용을 변조 방지 하드웨어 내부에서 수행하는 보안 장치임
- 키 수명주기: 키 생성, 배포, 사용, 보관, 교체, 폐기까지의 관리 절차임
- Tamper Resistance: 물리적 침입이나 변조 시 키 삭제 또는 동작 차단을 수행하는 보호 특성임
- PKCS#11: 응용이 암호 토큰과 연동할 때 사용하는 대표 API(Application Programming Interface) 표준임
- Key Ceremony: 중요 키 생성과 활성화를 다수 승인자와 감사 절차로 수행하는 공식 절차임

## Ⅰ. 개요

- **정의**: HSM은 암호키를 소프트웨어 메모리에 노출하지 않고 안전한 하드웨어 내부에서 생성·저장·암호 연산을 수행하게 하는 전용 보안 모듈로, 키 보호 수준, 처리 성능, 접근 통제, 감사, 규제 준수 기준으로 인증, 결제, 전자서명, 인증서 인프라의 신뢰 기반을 확보하기 위해 사용함
- **배경/필요성**: 암호 시스템의 안전성은 알고리즘보다 키가 어떻게 보관되고 사용되는지에 크게 좌우됨. 서버 메모리나 파일에 저장된 키는 권한 탈취, 백업 유출, 악성코드로 노출될 수 있어 하드웨어 기반 키 보호가 필요함
- **비유**: 중요한 계약서 도장을 책상 서랍에 두지 않고, 금고 안에서만 찍히게 하고 누가 언제 사용했는지 기록하는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 하드웨어 키 보호 구조 설명 | 키 생성·저장·연산, tamper resistance, API, 감사 | 단순 암호화 장비로만 설명 |
| 적용 영역과 한계 판단 | PKI(Public Key Infrastructure), 결제, 인증, 성능, HA(High Availability), 키 백업 | HSM이 모든 데이터 유출을 막는다는 단정 |

> 요약: HSM은 키를 하드웨어 경계 밖으로 내보내지 않고 암호 연산과 감사 통제를 제공하는 키 보호 장치임.

## Ⅱ. 특징/비교

| 판단 기준 | 소프트웨어 키 저장소 | TPM(Trusted Platform Module) | HSM |
|:---|:---|:---|:---|
| 보호 수준 | 파일·메모리 접근 통제에 의존 | 단말 또는 서버의 플랫폼 신뢰 보호 | 전용 보안 장치 내부 키 보호와 고성능 암호 연산 |
| 주요 용도 | 일반 애플리케이션 키 관리 | 장치 무결성, 디스크 암호화, 원격 증명 | PKI, 결제, 코드서명, 대량 TLS(Transport Layer Security) 키 연산 |
| 확장성 | 구축은 쉽지만 중앙 통제와 감사가 약함 | 장치 단위에 적합함 | 중앙 또는 클러스터 기반 키 서비스를 제공함 |
| 운영 부담 | 낮음 | 중간 | 키 행사, HA, 백업, 접근 통제 운영이 복잡함 |

> 요약: HSM은 단순 저장소보다 높은 키 보호와 감사 능력을 제공하지만 운영 절차와 가용성 설계가 필수임.

- **보안 기준**: 키가 HSM 밖으로 평문 노출되지 않고 정책에 허용된 연산만 수행되어야 함
- **성능 기준**: 전자서명, TLS, 결제 승인처럼 암호 연산량이 많은 업무는 처리량과 지연을 검토해야 함
- **운영 기준**: 키 백업, 이중화, 관리자 역할 분리, 감사 로그가 없으면 HSM 장애가 서비스 장애로 이어짐

## Ⅲ. 구성요소

```text
+----------+      +----------+      +----------+
| Client   | ---> | HSM      | ---> | Crypto   |
| Request  |      | Policy   |      | Engine   |
+----------+      +----+-----+      +----+-----+
                         |                 |
                         v                 v
                   +----------+      +----------+
                   | Key Store|      | Audit    |
                   | Tamper   |      | Log      |
                   +----------+      +----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 클라이언트 API | PKCS#11, KMIP(Key Management Interoperability Protocol), 전용 SDK(Software Development Kit)로 응용이 HSM 기능을 호출하는 인터페이스임 | 금고 접수 창구 |
| 보안 정책 | 키 사용 권한, 관리자 역할, 승인 조건, 연산 제한을 정의함 | 출입 규칙 |
| 키 저장소 | 키를 하드웨어 내부 보안 영역에 저장하고 외부 평문 추출을 제한함 | 금고 내부 |
| 암호 엔진 | 서명, 암복호화, 난수 생성, 키 생성 같은 연산을 수행함 | 도장 작업대 |
| 감사·변조 방지 | 로그, 알람, tamper detection, 키 삭제 기능으로 오남용을 추적하고 보호함 | CCTV와 비상 잠금 |

> 요약: HSM은 API, 정책, 키 저장소, 암호 엔진, 감사·변조 방지 기능으로 키 사용을 통제함.

## Ⅳ. 절차

```text
+----------+      +----------+      +----------+      +----------+
| Create   | ---> | Protect  | ---> | Use Key  | ---> | Audit    |
| Key      |      | Policy   |      | In HSM   |      | Rotate   |
+----------+      +----------+      +----------+      +----------+
```

1. **키 생성·반입**: HSM 내부 난수 생성기로 키를 만들거나 승인된 절차로 외부 키를 안전하게 반입함
2. **정책 설정**: 키 용도, 접근 권한, 관리자 분리, 백업, 만료, 폐기 조건을 정의함
3. **암호 연산 수행**: 응용은 API로 요청하고 HSM은 키를 외부로 내보내지 않은 채 서명·복호화 등을 수행함
4. **감사·교체**: 사용 로그를 검토하고 만료 또는 침해 의심 시 키를 교체·폐기함

> 요약: HSM 운영은 키 생성, 정책 보호, 내부 연산, 감사·교체의 키 수명주기 절차로 진행됨.

## Ⅴ. 문제점 및 개선방안

- **P1 통합 지연과 병목**: 모든 암호 연산이 HSM을 거치면 네트워크 지연과 장비 처리량이 인증·서명 서비스의 p95 지연을 제한할 수 있음
- **P1 대응**: 업무별 암호 연산량을 산정하고 HSM 클러스터, 세션 풀, 제한된 캐싱 정책을 적용함 (확인: 서명 TPS(Transactions Per Second), p95 지연)
- **P2 가용성·백업 위험**: HSM 장애나 키 백업 실패는 인증서 발급, 결제, 코드서명 서비스를 중단시킬 수 있음
- **P2 대응**: 고가용성(High Availability, HA) 이중화, 보안 백업, 복구 훈련, 지역 분산을 구성함 (확인: 장애 전환 시간, 복구 성공률)
- **P3 운영 절차 오류**: 관리자 권한 집중, key ceremony 부실, 감사 로그 미검토는 HSM의 키 보호 효과를 약화시킴
- **P3 대응**: 관리자 역할 분리, 다중 승인, 정기 감사 로그 검토를 운영함 (확인: 권한 리뷰, key ceremony 기록)

> 요약: HSM 개선은 키 보호 수준뿐 아니라 성능, 가용성, 운영 감사 절차를 동시에 설계해야 함.

## Ⅵ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| PKI 인증기관 | 루트·중간 인증기관 키를 HSM 내부에서 생성하고 서명 연산과 key ceremony를 감사함 | 서명 감사 로그, 키 반출 차단 여부 |
| 결제 승인 시스템 | 결제 키를 HSM 클러스터에 분산하고 피크 시간 서명·검증 처리량을 용량 기준으로 관리함 | 승인 TPS, p95 지연, 장애 전환 시간 |
| 코드서명 파이프라인 | 빌드 산출물 서명을 HSM 정책과 다중 승인에 연결하고 서명 키 사용 기록을 보존함 | 승인 누락 건수, 서명 이력 무결성 |

> 요약: 실무에서는 HSM을 키 금고가 아니라 암호 연산 성능, 가용성, 감사 절차가 결합된 키 수명주기 통제로 운영함.

## Ⅶ. 전망

- **발전 방향**: HSM은 클라우드 HSM, KMS(Key Management Service), 코드서명, 결제 HSM, PQC(Post-Quantum Cryptography) 전환과 결합해 키 수명주기 플랫폼으로 확대됨
- **기술사적 판단**: FIPS(Federal Information Processing Standards), Common Criteria, 키 행사, 정족수 승인, 처리량, 지연, HA 클러스터, 백업 토큰 보관 방식을 기준으로 구조를 선택함. 키 내보내기 제한, 변조 대응, 감사 로그 무결성, 서명 TPS, 장애 전환, PQC 알고리즘 지원을 운영 조건에서 확인함
- **기술사 제언**: HSM은 암호 연산 가속기가 아니라 키 수명주기와 감사 통제를 하드웨어 경계 안에서 수행하는 신뢰 기반으로 설명함
