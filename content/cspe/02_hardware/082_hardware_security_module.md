## 미리 알고가기

- HSM은 암호키를 장치 내부에서 생성, 저장, 사용하는 전용 보안 장치임
- TPM(Trusted Platform Module)은 부팅 무결성 측정과 제한된 키 보호 기능을 제공하는 저비용 보안 칩임
- 변조 저항성(tamper resistance)은 물리 변조를 감지하거나 차단하는 보호 기능임
- 키 의식(key ceremony)은 키 생성·백업·권한 분리를 공식 절차로 관리하는 운영 방식임

## 작성 근거(검토용)

- HSM은 키 비노출, 변조 대응, 역할 분리, 감사 추적을 핵심 축으로 설명함
- 비교표는 소프트웨어 키 저장소·TPM·HSM의 보호·처리 구조, 용도, 운영 조건을 대비함
- 실무 판단은 서명 지연·복구 성공률과 서명 처리량·장치 사용률로 검증함

## Ⅰ. 개요

- **정의/개념**: HSM은 암호키를 서버 메모리나 파일에 노출하지 않고 변조 대응 하드웨어 내부에서 생성·저장·연산하는 전용 키 보호 장치임
- **배경/필요성**: 결제·PKI·코드 서명 키의 평문 노출을 방지하기 위해 키 생성과 연산을 장치 내부로 제한하는 보호 경계가 필요함

## Ⅱ. 특징

- 키를 장치 경계 안에 가둬 평문 추출 위험을 낮춤
- 역할 분리·다중 승인·감사 로그로 키 사용 권한을 통제함
- 클러스터와 전용 암호 연산기로 서명 요청을 분산 처리함
- 장비 장애와 연동 지연이 전체 인증 경로의 병목이 될 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 소프트웨어 키 저장소 | TPM | HSM |
|:---|:---|:---|:---|
| 보호·처리 구조 | 호스트 CPU가 파일·OS 보호에 의존해 암호 연산을 수행함 | 장치 무결성·부팅 보호에 초점을 두고 제한된 키 연산을 수행함 | 키 생성부터 연산까지 전용 하드웨어 경계에서 처리함 |
| 대표 용도 | 응용 비밀값을 파일·키 저장소에 보관함 | 부팅 측정값과 장치 인증 키를 보호함 | CA·결제·코드 서명 키를 전용 장비에서 사용함 |
| 운영 조건 | OS 권한·파일 백업·비밀 배포를 관리함 | 플랫폼별 소유권·봉인 정책을 관리함 | 키 의식을 수행하고 이중화·권한 분리·감사 체계를 운영함 |

> 요약: HSM은 키 생성·저장·사용을 전용 하드웨어 내부로 제한하고 역할 분리와 감사 기록을 적용함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 보안 키 저장소 | 키를 외부 평문 노출 없이 저장하며 수명주기 정책의 기준점이 됨 |
| 암호 연산 엔진 | 서명, 암복호, 난수 생성을 내부에서 수행해 키 노출을 차단함 |
| 정책·접근 통제 | 역할 분리와 승인 절차를 강제해 내부 오남용을 줄임 |
| 감사·변조 대응 | 사용 기록과 변조 감지를 제공해 사고 대응과 규제 준수를 지원함 |

> 요약: HSM 구조는 키 저장소, 내부 연산, 접근 통제, 감사 기능이 결합된 키 보호 경계임.

## Ⅴ. 원리 및 절차 흐름도

1. **키 생성·반입**: HSM 내부 생성 또는 승인된 절차로 키를 준비함
2. **정책 설정**: 사용 권한, 용도, 만료, 승인 조건을 정함
3. **HSM 내부 연산**: 응용 시스템이 API로 요청하면 장치 내부에서만 암호 연산을 수행함
4. **감사·교체 운영**: 로그 검토, 키 회전, 백업 복구 절차를 운영함

> 요약: HSM에서 키를 준비하고 사용 정책을 설정한 뒤 내부 연산 기록을 감사하고 키를 교체함.

## Ⅵ. 실무 사례

1. 코드 서명 시스템은 HSM 이중화와 키 의식을 운영하고 서명 지연·장애 복구 성공률을 확인함
2. 대량 TLS 종단 서버는 HSM 클러스터링과 요청 배치를 적용하고 초당 서명 처리량·장치 사용률을 확인함

## Ⅶ. 결론

- HSM은 키를 장치 밖에 평문으로 노출하지 않고 생성·사용·백업·폐기 전 과정에 역할 분리와 감사를 적용해야 함
