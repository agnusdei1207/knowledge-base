## 미리 알고가기

- HSM은 암호키를 안전한 하드웨어 내부에서 생성, 저장, 사용하게 하는 보안 장치임
- tamper resistance와 key ceremony와 감사 로그가 핵심 운영 개념임
- PKI, 결제, 코드 서명, 대량 TLS 키 보호에 주로 사용됨

## Ⅰ. 개요

- **정의/개념**: HSM은 암호키를 소프트웨어 메모리에 노출하지 않고 변조 방지 하드웨어 내부에서 생성과 저장과 서명과 복호 연산을 수행하게 하는 전용 키 보호 장치임
- **배경/필요성**: 암호 시스템의 안전성은 알고리즘보다 키 보호 수준에 좌우되므로, 서버 파일과 메모리에 키를 보관하는 방식보다 더 강한 신뢰 경계가 필요함

## Ⅱ. 특징

- 키를 장치 내부 경계에 가둬 평문 추출 위험을 낮춤
- 관리자 역할 분리와 감사 로그로 운영 통제를 강화함
- 대량 서명과 인증 업무에 필요한 성능형 장비로 확장 가능함
- 장비 장애와 통합 지연이 서비스 병목으로 이어질 수 있어 가용성 설계가 중요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 소프트웨어 키 저장소 | TPM | HSM |
|:---|:---|:---|:---|
| 보호 수준 | 낮음 | 플랫폼 보호 중심 | 매우 높음 |
| 주요 용도 | 일반 앱 키 보관 | 장치 무결성, 부팅 | PKI, 결제, 코드서명 |
| 처리 성능 | 중간 | 낮음 | 중간~높음 |
| 운영 복잡도 | 낮음 | 중간 | 높음 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Secure Key Store | 키를 외부 평문 노출 없이 저장하며 생명주기 정책의 중심이 됨 |
| Crypto Engine | 서명과 암복호와 난수 생성 같은 연산을 실제로 수행함 |
| Policy, Access Control | 역할 분리와 승인 절차와 사용 조건을 강제함 |
| Audit, Tamper Protection | 사용 기록과 변조 감지로 보안 사고 대응과 규제 준수를 지원함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 키 생성/반입   | --> | 정책 설정      | --> | HSM 내부 연산   | --> | 감사/교체 운영  |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **키 생성 및 반입**: HSM 내부 또는 승인 절차로 키를 준비함
2. **정책 설정**: 사용 권한과 용도와 만료 조건을 정의함
3. **HSM 내부 연산**: 응용이 API로 요청하면 장치 내부에서만 암호 연산을 수행함
4. **감사 및 교체 운영**: 로그 검토와 회전과 폐기를 수행함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 모든 인증과 서명 요청이 HSM을 거치면 처리량 한계와 네트워크 지연이 서비스 병목이 될 수 있음
   - 해결방안: HSM cluster와 request batching을 적용하고 p95 signing latency와 TPS로 검증함
2. 문제: 키 백업과 관리자 역할 분리가 부실하면 장비 장애 시 복구 실패나 내부 오남용 위험이 커질 수 있음
   - 해결방안: key ceremony와 HA backup 절차를 운영하고 recovery success rate와 privileged action auditability로 검증함
3. 문제: HSM만 도입하고 응용 연동 정책이 느슨하면 키 사용 오남용은 계속 발생할 수 있음
   - 해결방안: fine-grained access control과 API policy를 적용하고 unauthorized operation rate와 policy violation count로 검증함

## Ⅶ. 적용 사례

- 전자서명 PKI에서는 루트와 중간 CA 키를 HSM에 저장하고 확인 지표는 signing latency와 audit compliance임
- 결제 승인 시스템에서는 카드 키 연산을 HSM에서 수행하고 확인 지표는 TPS와 tamper event count임
- 코드 서명 인프라에서는 배포 키를 보호하고 확인 지표는 signing workflow integrity와 key exposure count임

## Ⅷ. 결론

HSM의 가치는 암호 연산 속도보다 키를 밖으로 내보내지 않는 통제력에 있으므로, 장비 자체보다 키 수명주기와 운영 절차를 함께 설계해야 함.
