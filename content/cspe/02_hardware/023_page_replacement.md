## 미리 알고가기

- 페이지 폴트: 참조한 가상 페이지가 물리 메모리에 없어 보조기억장치에서 적재해야 하는 상황임
- 프레임: 물리 메모리를 페이지와 같은 크기로 나눈 고정 크기 저장 단위임
- 참조 지역성: 프로그램이 최근 사용한 주소나 그 주변 주소를 다시 사용할 가능성이 높은 성질임
- 스택 알고리즘: 프레임 수가 늘어도 기존 프레임 집합이 포함 관계를 유지해 Belady 이상을 피하는 교체 방식임

## Ⅰ. 개요

- **정의**: 페이지 교체 알고리즘은 가상 메모리에서 페이지 폴트가 발생했을 때 제한된 물리 프레임 중 어떤 페이지를 내보낼지 참조 가능성, 적재 시점, 사용 빈도 기준으로 결정해 메모리 활용률과 응답시간을 조정하는 정책임
- **배경/필요성**: 물리 메모리는 전체 가상 주소 공간보다 작고, 잘못된 교체는 디스크 I/O와 스래싱을 증가시킴. 따라서 워크로드의 참조 패턴에 맞는 교체 기준을 선택해야 함
- **비유**: 책상 공간이 부족할 때 다시 볼 가능성이 낮은 자료부터 서랍에 넣어 작업 흐름을 유지하는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 가상 메모리 성능을 페이지 폴트와 지역성 관점에서 설명하는 역량 확인 | OPT, FIFO, LRU, LFU, Belady 이상, 참조 지역성 | 단순 암기 나열, 페이지와 프레임 혼동, 디스크 I/O 비용 누락 |

> 요약: 페이지 교체는 한정된 프레임에서 페이지 폴트를 최소화하기 위한 희생 페이지 선택 정책임.

## Ⅱ. 특징/비교

| 판단 기준 | FIFO | LRU | LFU | OPT |
|:---|:---|:---|:---|:---|
| 선택 기준 | 가장 먼저 들어온 페이지 제거 | 가장 오래 참조되지 않은 페이지 제거 | 참조 횟수가 가장 낮은 페이지 제거 | 앞으로 가장 늦게 쓰일 페이지 제거 |
| 구현 비용 | 큐로 단순 구현 | 시간 정보·하드웨어 보조 필요 | 카운터와 노화 처리 필요 | 미래 참조를 알아야 하므로 실구현 불가 |
| 적합 조건 | 단순 시스템, 비용 우선 | 시간 지역성이 강한 워크로드 | 반복 빈도가 의미 있는 워크로드 | 알고리즘 성능 상한 비교 기준 |

> 요약: 교체 알고리즘은 구현 비용과 참조 패턴 예측 정확도 사이의 트레이드오프로 선택함.

- FIFO는 구현은 쉽지만 오래 상주한 핵심 페이지도 제거해 Belady 이상이 발생할 수 있음
- LRU는 최근성이 미래 참조 가능성을 잘 대변할 때 페이지 폴트를 줄이나 정확한 순서 유지 비용이 큼
- LFU는 장기 반복 참조를 반영하지만 과거에 자주 쓰였던 페이지가 계속 남는 캐시 오염을 만들 수 있음

## Ⅲ. 구성요소

```text
+-----------+      +-----------+      +-----------+
| 참조열    | ---> | 교체정책  | ---> | 희생페이지|
+-----------+      +-----------+      +-----------+
      |                  |
      v                  v
+-----------+      +-----------+
| 프레임상태|      | 참조정보  |
+-----------+      +-----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 참조열 | 프로세스가 접근하는 페이지 번호의 시간 순서이며 폴트 계산의 입력임 | 이용자가 찾는 책 목록 |
| 프레임 상태 | 현재 물리 메모리에 올라온 페이지 집합과 빈 프레임 여부를 나타냄 | 책상 위 자리 배치 |
| 교체 정책 | FIFO, LRU, LFU처럼 희생 페이지를 선택하는 판단 규칙임 | 정리 담당자의 치우는 기준 |
| 참조 정보 | 적재 시각, 최근 사용 시각, 참조 횟수, 참조 비트 등 정책 실행에 필요한 메타데이터임 | 자료에 붙인 사용 기록표 |

> 요약: 페이지 교체 구조는 참조열과 프레임 상태를 관찰해 정책별 참조 정보를 갱신하고 희생 페이지를 결정함.

## Ⅳ. 절차

```text
+-----------+      +-----------+      +-----------+      +-----------+
| 페이지참조| ---> | 적중검사  | ---> | 희생선정  | ---> | 적재/갱신 |
+-----------+      +-----------+      +-----------+      +-----------+
```

1. **페이지 참조 식별**: CPU가 생성한 가상 주소에서 페이지 번호를 추출하고 페이지 테이블을 조회함
2. **메모리 적중 검사**: 유효 비트로 페이지 존재 여부를 판단하고 적중 시 참조 정보를 갱신함
3. **희생 페이지 선정**: 폴트와 프레임 부족이 발생하면 정책 기준으로 제거할 페이지를 고름
4. **적재와 메타데이터 갱신**: 필요한 쓰기 반영 후 새 페이지를 적재하고 큐, 시간, 카운터 정보를 갱신함

> 요약: 페이지 교체는 참조마다 적중 여부를 확인하고 폴트 시 정책 기준으로 교체 후 상태 정보를 갱신하는 과정임.

## Ⅴ. 문제점

- **P1 참조 패턴 불일치**: FIFO, LFU처럼 단순 기준은 실제 지역성과 맞지 않을 때 페이지 폴트를 증가시킴
- **P2 정확한 LRU 구현 비용**: 모든 참조 순서를 정밀하게 유지하면 하드웨어 비트, 타이머, 리스트 관리 오버헤드가 커짐
- **P3 스래싱 위험**: 프로세스 워킹셋보다 프레임이 부족하면 교체가 계속 발생해 CPU보다 I/O 대기가 지배적이 됨

> 요약: 페이지 교체의 핵심 문제는 예측 오류, 추적 비용, 프레임 부족이 결합될 때 유효 접근시간이 급증하는 점임.

## Ⅵ. 개선방안

1. **단기**: 페이지 폴트율, 프레임 사용률, 디스크 I/O 대기를 측정해 교체 정책의 병목을 확인함
2. **중기**: Clock, Aging, WSClock처럼 참조 비트 기반 근사 LRU와 워킹셋 기반 제어를 적용함
3. **장기**: 워크로드별 메모리 상한, NUMA 배치, 캐시·TLB 영향까지 포함한 메모리 운영 기준을 수립함

- **P1 대응**: 참조 지역성에 맞는 LRU 계열 또는 워크로드별 정책을 선택함 (확인: 페이지 폴트율 감소)
- **P2 대응**: 정확 LRU 대신 참조 비트와 주기적 노화 기반 근사 정책을 사용함 (확인: 정책 관리 오버헤드)
- **P3 대응**: 워킹셋 크기 기반으로 프레임을 재배분하고 과다 다중프로그래밍을 제한함 (확인: I/O 대기율)

> 요약: 교체 정책은 이론적 적중률뿐 아니라 추적 비용과 워킹셋 보장을 함께 관리해야 함.

## Ⅶ. 전망

- **발전 방향**: 대용량 메모리와 계층형 스토리지가 결합되면서 DRAM, CXL 메모리, SSD 사이의 다계층 페이지 배치가 중요해짐
- **기술사적 판단**: 운영체제는 단일 LRU보다 애플리케이션 힌트, 메모리 압축, NUMA locality를 반영한 적응형 정책으로 발전함
- **기술사 제언**: 기술사는 알고리즘 명칭보다 페이지 폴트율, 구현 비용, 워킹셋 보장 여부를 기준으로 교체 정책을 설명해야 함
