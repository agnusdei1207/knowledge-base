# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 페이지 교체 알고리즘은 **가상 메모리**의 Demand Paging 환경에서 물리 프레임이 가득 찬 상태에서 새 페이지를 적재하기 위해 **희생 페이지(Victim)**를 선정하는 정책임.
- **왜 필요한가**: Page Fault 발생 시 디스크 I/O(10⁶ 사이클 이상)가 동반되므로, 무엇을 교체하느냐에 따라 이후 Page Fault 횟수가 크게 달라짐. 미래에 다시 참조될 가능성이 가장 낮은 페이지를 선별하는 규칙이 전체 시스템 성능을 좌우함.
- **핵심 직관**: 냉장고(프레임)가 가득 찼을 때 무엇을 버릴지 정하는 규칙 — 가장 오래 안 먹을 것(OPT), 가장 먼저 넣은 것(FIFO), 가장 오래 안 꺼낸 것(LRU), 가장 적게 꺼낸 것(LFU) 중 하나를 선택함.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| 요구 페이징 (상위 키워드) | 필요한 페이지만 실행 시점에 적재하는 가상 메모리 기법 | "필요한 책만 그때그때 책상에 올림" |
| Page Fault | 참조한 페이지가 프레임에 없어 디스크에서 적재해야 하는 상황 | "책상에 없는 책을 서고에서 가져옴" |
| Victim Page | 교체 알고리즘에 의해 디스크로 방출될 페이지 | "냉장고에서 버려지는 재료" |
| OPT (Optimal) | 미래에 가장 늦게 참조될 페이지를 교체 — 이론적 최적, 구현 불가 | "미래를 아는 신의 선택" |
| FIFO | 가장 먼저 적재된 페이지부터 교체 — 큐 구현 | "선입선출 대기줄" |
| LRU (Least Recently Used) | 가장 오랫동안 참조되지 않은 페이지를 교체 — 타임스탬프/스택 필요 | "가장 오래 안 편 책부터 정리" |
| LFU (Least Frequently Used) | 참조 횟수가 가장 적은 페이지를 교체 — 카운터 필요 | "가장 적게 읽은 책부터 정리" |
| Belady's Anomaly | 프레임 수를 늘렸는데 오히려 Page Fault가 증가하는 역설(FIFO 등 비스택 알고리즘에서 발생) | "방을 넓혔는데 이삿짐이 더 자주 나감" |
| Stack Algorithm | n개 프레임의 적재 집합이 n+1개 프레임 집합의 부분집합인 성질(LRU·OPT 해당) | "큰 서랍이 작은 서랍의 내용을 항상 포함" |
| Clock (NUR/Second Chance) | Reference Bit 1개와 원형 포인터로 LRU를 근사하는 실무 알고리즘 | "시계 바늘이 돌며 안 쓴 페이지를 찾아냄" |

## 깊이 이해
- **배경·문제의식**: 가상 메모리(022 참조) 환경에서 Page Fault 처리에는 디스크 I/O가 수반되므로 CPU 연산 대비 수백만 배 느려짐. 따라서 Page Fault 횟수를 최소화하는 교체 전략이 시스템 성능의 핵심 변수임.
- **작동 원리**: OS는 참조열(Reference String)의 패턴을 활용하여 희생 페이지를 선정함.
  - **OPT**: 미래에 가장 늦게 참조될 페이지를 교체. 이론적 최적이나 미래 참조를 예측할 수 없어 구현 불가. 다른 알고리즘의 성능 평가 기준선으로 활용.
  - **FIFO**: 가장 먼저 적재된 페이지를 큐에서 제거. 구현이 단순하나 자주 쓰이는 페이지도 오래되면 교체되는 문제(Belady's Anomaly 발생 가능).
  - **LRU**: 가장 오래 참조되지 않은 페이지를 교체. 시간적 지역성 반영이 우수하나 매 참조마다 타임스탬프 갱신이 필요하여 오버헤드가 큼.
  - **LFU**: 참조 횟수가 가장 적은 페이지를 교체. 집중 참조 패턴에 적합하나, 초기에 반짝 사용된 페이지가 높은 카운트 때문에 잔존하는 Cache Pollution 문제 발생.
- **Belady's Anomaly 수치 검증**: 참조열 `1,2,3,4,1,2,5,1,2,3,4,5`(12회) 적용 시 — FIFO 3프레임: 9회 폴트, FIFO 4프레임: 10회 폴트. 프레임을 늘렸는데 폴트가 증가함. 동일 참조열에 LRU 적용 시 3프레임: 10회, 4프레임: 8회로 정상 감소(Stack Property).
- **실무 근사(Clock 알고리즘)**: 순수 LRU의 타임스탬프 오버헤드가 크므로, 실제 OS(Linux 등)는 하드웨어 Reference Bit 1개만 사용하는 Clock 알고리즘을 적용함. 원형 큐를 포인터가 순회하며 bit=1이면 0으로 초기화하고 지나가고, bit=0인 페이지를 만나면 교체함.
- **흔한 오해·주의점**: ① "LRU가 항상 FIFO보다 우수하다"는 특정 참조열에서만 성립하며 절대적 우열은 참조열에 의존함. ② "프레임을 늘리면 무조건 폴트가 준다"는 Stack Algorithm(LRU, OPT)에서만 보장되며, FIFO에서는 Belady's Anomaly로 역전 가능함.

## 연결 개념
- **022 가상 메모리·페이징**: 페이지 교체가 발생하는 상위 환경.
- **Thrashing**: 프레임 부족으로 교체만 반복되어 CPU 활용률이 급락하는 현상. Working Set 모델로 방지함.
- **021 TLB**: Page Fault 처리 후 TLB를 갱신하여 이후 변환을 캐싱함.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 페이지 교체 알고리즘은 물리 프레임 부족 시 Page Fault 횟수를 최소화하기 위해 희생 페이지를 선정하는 정책임.
> 2. **가치**: 참조 지역성을 활용하여 미래 Page Fault 확률을 최소화하고, 디스크 I/O에 의한 CPU 유휴 시간을 절감함.
> 3. **판단 포인트**: OPT는 구현 불가(기준선), FIFO는 Belady's Anomaly 위험, LRU는 오버헤드로 인해 Clock(NUR)으로 근사 구현하는 것이 실무 표준임.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 알고리즘별 동작 원리 차이 이해 | OPT·FIFO·LRU·LFU의 Victim 선정 기준 | 네 알고리즘을 "오래된 것을 버린다"로 뭉뚱그림 |
| Belady's Anomaly 발생 조건 파악 | FIFO(비스택)에서 발생, LRU(스택)에서 미발생 | 모든 알고리즘에서 발생한다고 서술 |
| 실무 구현 가능성 판단 | OPT 구현 불가, LRU→Clock 근사 | OPT를 실제 OS가 사용한다고 서술 |

> 요약: 이 문제는 알고리즘 이름 암기가 아니라 구현 가능성·Belady's Anomaly 발생 여부·근사 구현 방식을 구분할 수 있는지를 확인함.

---

## Ⅰ. 개요 및 필요성

- 개요: 물리 프레임 부족 시 교체할 페이지를 선정하여 Page Fault 횟수를 최소화하는 메모리 관리 정책임.
- 배경: Page Fault 처리 시 디스크 I/O(10⁶ CPU 사이클 이상)가 발생하여 시스템 성능이 급격히 저하됨.
- 필요성: 참조 지역성에 기반한 교체 정책으로 Thrashing을 방지하고 CPU의 유효 연산 시간을 확보해야 함.

---

## Ⅱ. 구조 및 구성요소

```text
CPU 참조 -> Page Fault 발생 -> 빈 프레임 확인
  있음 -> 즉시 적재
  없음 -> 교체 알고리즘 적용(OPT/FIFO/LRU/LFU/Clock)
       -> Victim 선정 -> Dirty 시 디스크 Write-Back -> 새 페이지 적재
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 참조열 (Reference String) | 교체 성능 평가를 위한 페이지 접근 순서 | 지역성 패턴 분석의 기준 |
| Victim 선정 로직 | 알고리즘별 기준(순서/최근성/빈도)으로 교체 대상 결정 | OPT/FIFO/LRU/LFU/Clock 별 상이 |
| Reference Bit | 최근 참조 여부를 표시하는 하드웨어 1비트 플래그 | Clock 알고리즘의 판단 근거 |
| Dirty Bit | 페이지 수정 여부, 교체 시 디스크 Write-Back 필요 판단 | Dirty=1이면 I/O 비용 추가 |

> 요약: OS는 하드웨어가 제공하는 Reference/Dirty Bit를 조합하여, I/O 비용이 낮고 향후 참조 확률이 낮은 페이지를 Victim으로 선정함.

---

## Ⅲ. 동작원리 및 흐름도

```text
Page Fault -> 교체 큐/리스트 탐색 -> 전략별 Victim 확정 -> 상태 비트 초기화 -> 큐 갱신
```

- 1단계 [OPT]: 미래 참조열에서 가장 늦게 등장하는 페이지를 교체함(구현 불가, 성능 하한선 역할).
- 2단계 [FIFO]: 가장 먼저 적재된 페이지를 큐에서 제거함(단순하나 자주 쓰이는 페이지도 교체 가능).
- 3단계 [LRU]: 최근에 가장 오랫동안 참조되지 않은 페이지를 교체함(시간 지역성 반영 우수, 갱신 오버헤드 큼).
- 4단계 [Clock/NUR]: Reference Bit=0인 페이지를 찾을 때까지 원형 큐를 순회하며 bit=1→0으로 초기화함(LRU의 실무적 근사).

> 요약: 이론적 이상(OPT)을 향해 과거 참조 이력(LRU)을 추적하되, 오버헤드를 줄이기 위해 1비트 상태(Clock)로 근사함.

---

## Ⅳ. 특징
- Belady's Anomaly: FIFO는 비스택 알고리즘이라 프레임 수를 늘려도 Page Fault가 증가할 수 있음(참조열 `1,2,3,4,1,2,5,1,2,3,4,5` 시 3프레임 9회→4프레임 10회)
- Stack Property: LRU·OPT는 n프레임 적재 집합이 n+1프레임의 부분집합이므로 프레임 증가 시 폴트가 단조 감소함
- LFU의 Cache Pollution: 초기에 반짝 사용된 페이지가 높은 참조 카운트로 잔존하는 문제가 있어 시간 감쇠(Aging)를 병행해야 함

---

## Ⅴ. 심화 비교 및 적용 판단

| 알고리즘 | Victim 선정 기준 | 구현 가능성 | Belady's Anomaly |
|:---|:---|:---|:---|
| OPT | 미래 참조까지 가장 먼 페이지 | 구현 불가(이론적 기준선) | 해당 없음(최적해) |
| FIFO | 가장 먼저 적재된 페이지 | 큐로 단순 구현 | 발생 가능(비스택) |
| LRU | 가장 오래 참조되지 않은 페이지 | 타임스탬프/스택 필요(Clock으로 근사) | 미발생(스택 알고리즘) |
| LFU | 참조 횟수 가장 적은 페이지 | 카운터 구현, Aging 보정 필요 | 별도 분석 필요 |

> 요약: 구현 가능성과 Belady's Anomaly 면역 여부를 기준으로 판단하면, LRU의 Clock 근사가 범용 OS의 실무 표준임.

**리스크·대응:**
- Sequential Scan 오염: DB 풀 스캔 시 1회성 데이터가 LRU 큐의 유용한 캐시를 밀어내는 현상 → LRU-K(N회 이상 참조 시 주 큐 승격) 또는 Midpoint Insertion 적용 (지표: 버퍼풀 히트율)
- Dirty Page I/O 지연: Victim이 Dirty=1이면 즉시 디스크 기록 필요 → 백그라운드 데몬(kswapd/pdflush)이 비동기적으로 Dirty Page를 선제 플러시 (지표: Dirty Page 비율)

**점검 지표:**
- 성능: Page Fault Rate(vmstat의 si/so), 버퍼풀 히트율
- 운영: CPU Utilization vs I/O Wait 비율(Thrashing 징후 감시)

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. RDBMS 버퍼풀 관리: MySQL InnoDB의 Midpoint Insertion(LRU 리스트의 3/8 지점에 신규 페이지 삽입)으로 풀스캔에 의한 캐시 오염을 방어함.
2. 커널 페이지 회수 튜닝: Linux의 min_free_kbytes 워터마크를 설정하여 여유 메모리 고갈 전에 kswapd가 비동기 회수(Clock 변형)를 시작하도록 유도함.
3. 애플리케이션 힌트 적용: madvise(MADV_SEQUENTIAL) API로 순차 접근 후 즉시 해제할 페이지를 OS에 명시하여 불필요한 LRU 큐 진입을 방지함.

**결론:**
- 기술사 판단: 이론적 최적(OPT)은 구현 불가하며, 실무는 워크로드 특성(순차/랜덤)에 맞춰 Clock 기반 LRU 근사 + Scan 오염 방어(LRU-K) 조합을 선택해야 함.
- 향후 방향: CXL 메모리 풀링·NVDIMM 계층화로 단일 디스크 Swap 대신 중간 계층(Tiering) 메모리로 페이지를 마이그레이션하는 지능형 티어링 알고리즘이 확산 중임.
