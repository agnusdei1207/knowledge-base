# 023. 페이지 교체 알고리즘 — LRU·LFU·NUR·FIFO (Page Replacement Algorithm) [출제:120,123,124,128,131,134,135회]

## 미리 알고가기

- **페이지 폴트 (Page Fault)**: 접근하려는 페이지가 메모리에 없어 디스크로부터 읽어와야 하는 상황임
- **참조 지역성 (Locality)**: 프로그램이 특정 시간에 메모리의 좁은 범위를 집중 참조하는 성질(시간/공간)임
- **희생 페이지 (Victim Page)**: 새로운 페이지를 위해 메모리에서 쫓겨나기로 결정된 페이지임

## Ⅰ. 개요

- **정의/개념**: 페이지 교체 알고리즘은 페이지 폴트 발생 시 메모리에 빈 프레임이 없을 경우, 현재 적재된 페이지 중 어떤 것을 교체할지 결정하는 관리 전략임
  - **FIFO (First-In First-Out)**: 메모리에 가장 먼저 들어온 페이지를 가장 먼저 교체함
  - **LRU (Least Recently Used)**: 가장 오랫동안 사용되지 않은 페이지를 교체하여 시간 지역성을 활용함
  - **LFU (Least Frequently Used)**: 과거 참조 횟수가 가장 적은 페이지를 교체함
  - **NUR (Not Used Recently)**: 최근에 참조되거나 수정되지 않은 페이지를 우선 교체함 (Clock 알고리즘 등)
- **배경/필요성**: 물리 메모리의 한계를 극복하고 페이지 적중률을 높여 디스크 $I/O$를 최소화하기 위해 필수적임

## Ⅱ. 특징 및 비교

알고리즘마다 구현 복잡도와 성능(적중률) 사이의 트레이드오프가 존재함.

| 알고리즘 | 결정 기준 | 장점 | 단점 |
|:---|:---|:---|:---|
| **FIFO** | 적재 시간 순서 | 구현이 매우 단순함 | **Belady's Anomaly** 발생 가능 |
| **LRU** | 마지막 참조 시각 | **지역성 반영, 성능 우수** | 오버헤드(시간 기록) 발생 |
| **LFU** | 누적 참조 횟수 | 집중 사용 페이지 보존 | 초반 집중 사용 시 정체 현상 |
| **NUR** | 참조/수정 비트 | **LRU 근사, 효율적** | 정교한 시각 기록은 아님 |
| **OPT** | 미래 참조 시각 | 이론적 최적 성능 | **실현 불가능** (미래 예측) |

> 요약: 실무에서는 성능이 우수하면서도 비용이 저렴한 **LRU 근사(NUR/Clock)** 방식을 선호함.

## Ⅲ. 구성요소/구조

페이지 교체는 하드웨어의 상태 비트와 운영체제의 정책이 결합되어 수행됨.

- **구성요소**:
  - **Reference Bit**: 페이지가 참조되었을 때 하드웨어가 $1$로 설정하는 비트
  - **Modified (Dirty) Bit**: 페이지 내용이 수정되었음을 표시하는 비트 (교체 시 디스크 쓰기 필요 여부 결정)
  - **Counter/Timer**: $LRU$나 $LFU$를 구현하기 위해 사용하는 추가 정보
  - **Page Tables**: 각 페이지의 메모리 존재 여부 및 상태 비트를 포함

- **LRU (Clock) 알고리즘 동작 원리 (ASCII)**:

```text
[ Current Pointer ]
       |
  +----v----+       (If Ref Bit == 1)      +---------+
  | Page A  | ---------------------------> | Set to 0|
  | Ref: 1  |       (Give 2nd Chance)      | Move Ptr|
  +---------+                              +---------+
       |
  +----v----+       (If Ref Bit == 0)      +---------+
  | Page B  | ---------------------------> | Replace |
  | Ref: 0  |       (Found Victim!)        | This!   |
  +---------+                              +---------+
```

1. **검사**: 포인터가 가리키는 페이지의 $Reference\ Bit$를 확인
2. **기회**: $1$이면 $0$으로 바꾸고 다음으로 이동(2차 기회), $0$이면 해당 페이지를 교체

## Ⅳ. 문제점 및 개선방안

1. **벨레이디의 모순 (Belady's Anomaly)**: FIFO에서 프레임 수를 늘렸는데 오히려 페이지 폴트가 늘어나는 현상임
   - **개선방안**: 스택 알고리즘 성질을 가진 **LRU** 등을 사용하여 프레임 증가가 항상 성능 향상으로 이어지게 함 (확인: 프레임 수 대비 적중률 곡선)

2. **LRU의 높은 하드웨어 비용**: 매 참조마다 시각을 기록하거나 스택을 재배치하는 것은 부하가 큼
   - **개선방안**: 참조 비트 하나만 사용하는 **Clock 알고리즘(NUR)**으로 LRU를 근사화하여 구현함 (확인: 주소 변환 지연 시간)

3. **LFU의 과거 집착**: 초반에만 쓰이고 안 쓰이는 페이지가 높은 횟수 때문에 메모리를 계속 차지함
   - **개선방안**: 일정 주기로 참조 횟수를 줄이는 **Aging(노화)** 기법을 도입하여 최근의 경향성을 강조함 (확인: 페이지 교체 후 재참조 간격)

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 리눅스 커널 | LRU의 근사 형태인 '2차 기회(Second Chance)' 알고리즘을 기본으로 활용 | $Major\ Page\ Fault$ 발생 빈도 |
| 데이터베이스 (Buffer Pool) | 쿼리 성능 극대화를 위해 메모리 내 버퍼 교체 정책으로 LRU 변형 알고리즘 적용 | $Buffer\ Cache\ Hit\ Ratio$ |
| 가상화/하이퍼바이저 | 호스트 메모리 부족 시 게스트의 페이지를 회수하는 전략으로 상태 비트 활용 | $Swap\ Out\ Rate$, $I/O\ Wait$ |

> 요약: 실제 시스템은 순수 알고리즘보다 관리 비용과 성능의 균형을 맞춘 '근사 알고리즘'을 사용함.

## Ⅵ. 결론

페이지 교체 알고리즘은 가상 메모리의 유연성을 뒷받침하는 핵심 지능임. 기술사는 단순히 방식별 차이를 암기하는 것을 넘어, 프로그램의 '참조 지역성'이라는 본질을 어떻게 알고리즘에 녹여내어 비싼 디스크 $I/O$를 회피할 것인지에 대한 설계적 통찰력을 갖춰야 함.

향후 시스템은 고성능 $SSD$와 $NVM$, $CXL$ 메모리 등의 등장으로 인해 메모리 계층이 복잡해짐에 따라, 단일 교체 정책보다는 데이터의 성격과 계층별 지연시간을 고려한 지능형·적응형 교체 전략으로 진화할 것임. 결국 최적의 시스템 응답성은 데이터의 미래를 얼마나 잘 예측하는가에 달려 있음.
