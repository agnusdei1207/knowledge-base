## Ⅰ. 개요
- **정의**: 물리 메모리가 가득 찼을 때 새 페이지를 적재하기 위해 어떤 기존 페이지를 희생(Victim)할지 결정하는 OS의 메모리 관리 정책임
- **배경/필요성**: Page Fault 1회 발생 시 디스크 I/O로 수백만 CPU 사이클이 소모되므로, 재사용 가능성이 낮은 페이지를 선별하여 폴트 횟수를 최소화해야 함
- **비유**: 꽉 찬 냉장고에서 새 식재료를 넣기 위해 가장 안 먹을 것을 골라 버리는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 4대 알고리즘 비교 분석 | OPT/FIFO/LRU/LFU의 Victim 선정 기준 차이 | OPT가 구현 가능하다고 서술 금지 |
| Belady 이상 현상 이해 | FIFO에서 프레임 증가 시 폴트 증가 가능 | 모든 알고리즘에 적용된다고 오해 금지 |
| 실무 근사 구현 | Clock(Second Chance) 알고리즘의 LRU 근사 원리 | LRU의 HW 구현 비용 언급 누락 금지 |

> 요약: 페이지 폴트 비용을 최소화하기 위해 최적 희생 페이지를 선별하는 교체 정책임

## Ⅱ. 구성요소
```text
OPT ---- 미래 참조 거리 기준 ---- 이론적 최적(구현 불가)
  |
FIFO --- 적재 순서 기준 --------- 단순 큐 구조(Belady 이상 위험)
  |
LRU ---- 최근 사용 시점 기준 ---- 지역성 활용(실무 표준)
  |
LFU ---- 사용 빈도 기준 --------- 빈도 카운터 관리(초기 편향 문제)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| OPT(Optimal) | 미래에 가장 오래 사용되지 않을 페이지를 교체함. 미래 예측이 필요하여 실제 구현 불가하지만 성능 하한 기준으로 활용됨 | 미래를 아는 예언자 |
| FIFO(First-In First-Out) | 가장 먼저 적재된 페이지를 교체함. 큐 하나로 구현이 단순하나 자주 쓰는 페이지도 오래되면 제거됨 | 선입선출 편의점 진열대 |
| LRU(Least Recently Used) | 가장 오랫동안 참조되지 않은 페이지를 교체함. 시간적 지역성을 활용하여 OPT에 근접한 성능을 보임 | 가장 오래 안 꺼낸 옷 정리 |
| LFU(Least Frequently Used) | 참조 횟수가 가장 적은 페이지를 교체함. 초기에만 집중 사용된 페이지가 카운터 누적으로 잔류하는 문제가 있음 | 최소 판매 상품 할인 코너 |

> 요약: OPT(이론 기준), FIFO(순서 기준), LRU(최근성 기준), LFU(빈도 기준)의 4가지 정책으로 구분됨

## Ⅲ. 절차
```text
Page Fault 발생 --> 빈 프레임 존재? --Yes--> 즉시 적재
                        |
                       No
                        |
                        v
                 교체 알고리즘으로 Victim 선정 --> Dirty? --Yes--> 디스크 Write-back
                                                    |
                                                   No
                                                    |
                                                    v
                                              Victim 프레임에 신규 페이지 적재 --> 테이블 갱신
```
- 1단계: 가상 주소 참조 시 해당 페이지가 RAM에 없으면 Page Fault 인터럽트가 발생하여 OS로 제어권이 전환됨
- 2단계: OS가 빈 프레임을 탐색하고, 없으면 교체 알고리즘(OPT/FIFO/LRU/LFU)으로 Victim 페이지를 선정함
- 3단계: Victim 페이지의 Dirty 비트가 1이면 변경 내용을 디스크에 Write-back한 뒤 프레임을 해제함
- 4단계: 디스크에서 요청 페이지를 빈 프레임에 적재하고, 페이지 테이블의 Valid 비트와 PFN을 갱신함

> 요약: Page Fault -> Victim 선정 -> Dirty Write-back -> 신규 적재/테이블 갱신의 4단계로 수행됨

## Ⅳ. 문제점
- Belady 이상 현상: FIFO에서 프레임 수를 3개에서 4개로 늘려도 폴트가 9회에서 10회로 증가하는 반직관적 현상이 발생함. 적재 순서만 고려하고 참조 빈도를 무시하기 때문임
- LRU 하드웨어 구현 비용: 매 메모리 참조마다 타임스탬프를 기록하거나 스택을 갱신해야 하므로 하드웨어 오버헤드가 과도함
- 캐시 오염(Cache Pollution): 대용량 순차 스캔(Full Table Scan) 시 1회성 페이지가 LRU 리스트 상위를 점유하여 Hot 데이터가 밀려남

> 요약: FIFO의 Belady 이상, LRU의 HW 비용, 순차 스캔에 의한 캐시 오염이 주요 문제임

## Ⅴ. 개선방안
1. 단기: 스택 알고리즘 특성을 갖는 LRU 계열로 전환하여 프레임 증가 시 폴트가 감소하지 않는 Belady 이상을 원천 방지함
2. 중기: Reference Bit 기반 Clock(Second Chance) 알고리즘으로 LRU를 근사 구현하여 1비트 검사만으로 타임스탬프 기록 부하를 제거함
3. 장기: Midpoint Insertion(MySQL InnoDB 방식) 또는 LRU-K/ARC 등 다중 리스트 정책을 도입하여 1회성 스캔 페이지를 Cold 영역에 격리함

> 요약: LRU 전환, Clock 근사, 다중 리스트 정책으로 각 문제를 단계적으로 해결함

## Ⅵ. 전망
- 발전 방향: DRAM/CXL/SSD 다계층 메모리 환경에서 계층 간 데이터 이동을 관리하는 Multi-Tier 교체 정책이 부상함
- 기술사적 판단: 단일 알고리즘 비교를 넘어 워크로드 특성(랜덤/순차/혼합)에 따른 적응형(Adaptive) 교체 전략 설계가 필수적임
- 기술사 제언: 페이지 폴트율과 Dirty Write-back 빈도를 연계 모니터링하여 교체 정책과 메모리 증설 시점을 정량 판단할 것을 권고함
