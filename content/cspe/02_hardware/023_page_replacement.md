## 미리 알고가기

- 페이지 교체는 빈 프레임이 없을 때 어떤 페이지를 내보낼지 정하는 정책임
- 참조 지역성은 최근 또는 자주 쓰인 페이지가 다시 쓰일 가능성이 높다는 성질임
- 수정 페이지는 교체 전에 저장장치에 다시 기록해야 하므로 비용이 더 큼

## 작성 근거(검토용)

- 페이지 교체를 page fault·희생 페이지·dirty write-back 흐름으로 설명함
- FIFO·LRU·LFU·OPT를 희생 기준·메타데이터·지역성 반영·실패 조건·활용 역할로 비교함
- 구성요소 도식과 교체 절차의 중복을 피하기 위해 절차형 구조 도식을 삭제함

## Ⅰ. 개요

- **정의/개념**: 페이지 교체 알고리즘은 페이지 폴트 발생 시 빈 프레임이 없으면 적재된 페이지 중 희생 대상을 선택해 전체 교체 비용을 줄이는 운영체제 정책임
- **배경/필요성**: 제한된 물리 메모리에서 디스크 입출력과 응답 지연을 줄이기 위해 페이지 유지·교체 기준이 필요함

## Ⅱ. 특징

- 지역성을 반영하면 재참조 가능성이 낮은 페이지를 선택해 페이지 폴트를 줄일 수 있음
- 이상적인 성능은 미래 참조를 아는 OPT가 주지만 실제 시스템은 근사 알고리즘으로 구현함
- LRU는 접근 시각, LFU는 참조 횟수처럼 희생 기준에 필요한 메타데이터를 매 참조마다 갱신함
- 교체 비용은 페이지 폴트 횟수뿐 아니라 수정 데이터 기록과 긴 꼬리 지연까지 함께 봐야 함

## Ⅲ. 종류 및 비교

| 판단 기준 | FIFO | LRU | LFU | OPT |
|:---|:---|:---|:---|:---|
| 선택 기준 | 가장 먼저 들어온 페이지를 교체함 | 가장 오래 쓰지 않은 페이지를 교체함 | 가장 적게 참조된 페이지를 교체함 | 가장 나중에 다시 쓰일 페이지를 교체함 |
| 필요 메타데이터 | 도착 순서 큐 | 최근 접근 순서·참조 비트 | 참조 횟수·aging 정보 | 미래 참조 순서 |
| 지역성 반영 | 최근성·빈도 미반영 | 최근성 반영 | 누적 빈도 반영 | 전체 미래 참조 반영 |
| 한계 | 벨라디 이상이 발생할 수 있음 | 정확한 접근 순서 추적 비용이 큼 | 오래된 참조 이력이 남아 현재 빈도를 왜곡할 수 있음 | 미래 정보를 몰라 실제 구현이 불가능함 |
| 활용 역할 | 순서 기반 기준선 | Clock·Second-Chance의 근사 대상 | 에이징을 결합한 빈도 기반 정책 | 다른 정책의 최소 페이지 폴트 기준 |

> 요약: FIFO는 도착 순서, LRU는 최근성, LFU는 누적 빈도, OPT는 미래 재참조 시점을 희생 기준으로 사용함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 프레임 목록 | 현재 메모리에 올라온 페이지 집합을 보관해 교체 후보를 구성함 |
| 참조·더티 비트 | 최근 참조 여부와 수정 여부를 기록함 |
| 교체 메타데이터 | 시간 스탬프·카운터·원형 포인터로 정책의 선택 기준을 유지함 |
| 스왑·후면 저장소 관리자 | 더티 희생 페이지를 저장하고 새 페이지를 적재함 |

> 요약: 교체 정책은 참조 비트, dirty 상태, 메타데이터를 이용해 희생 페이지를 선택함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+     +-------------+
| 페이지 폴트 발생  | --> | 빈 프레임 확인   | --> | 희생 페이지 선정   | --> | 더티 페이지 기록   | --> | 새 페이지 적재   |
+-------------+     +-------------+     +-------------+     +-------------+     +-------------+
```

1. **페이지 폴트 발생**: 참조한 페이지가 메모리에 없음을 확인함
2. **빈 프레임 확인**: 여유 프레임이 있으면 적재하고 없으면 교체로 넘어감
3. **희생 페이지 선정**: 정책에 따라 재사용 가능성이 낮은 페이지를 선택함
4. **더티 페이지 기록**: 희생 페이지가 수정된 경우 후면 저장소에 먼저 기록함
5. **새 페이지 적재**: 요청한 페이지를 프레임에 올리고 메타데이터를 갱신함

> 요약: 페이지 폴트 시 빈 프레임이 없으면 재사용 가능성과 더티 페이지 기록 비용을 보고 희생 페이지를 정함.

## Ⅵ. 실무 사례

1. 범용 운영체제는 LRU를 Clock으로 근사하고 교체 처리시간과 주요 페이지 폴트율을 확인함
2. 메모리 제약 서버는 프레임 수별 페이지 폴트 곡선으로 작업 집합을 조정하고 페이지 폴트율과 p99 응답시간을 확인함

## Ⅶ. 결론

- 페이지 교체는 작업 집합의 재참조 패턴에 맞는 희생 기준을 선택하고 페이지 폴트·더티 페이지 기록·메타데이터 갱신 비용을 측정해야 함
