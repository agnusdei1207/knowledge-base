## 미리 알고가기

- **페이지 폴트(Page Fault)**: 프로세스가 요청한 페이지가 현재 물리 메모리에 없어 디스크로부터 적재해야 하는 상태
- **참조 지역성(Locality of Reference)**: 프로그램이 특정 시간에 메모리의 좁은 범위를 집중적으로 참조하는 특성(시간/공간 지역성)
- **벨레이디의 모순(Belady's Anomaly)**: 프레임 수를 늘렸음에도 불구하고 페이지 폴트가 오히려 증가하는 기현상(FIFO에서 발생)
- **희생 페이지(Victim Page)**: 새로운 페이지를 올리기 위해 메모리에서 쫓겨나기로 결정된 페이지

## Ⅰ. 개요

- **정의/개념**: 페이지 교체 알고리즘은 가상 메모리 관리 기법 중 하나로, 페이지 폴트 발생 시 빈 프레임이 없다면 현재 메모리에 적재된 페이지 중 어떤 것을 디스크로 내보내고(Swap-out) 새로운 페이지를 들여올지(Swap-in) 결정하는 규칙임
- **배경/필요성**: 물리 메모리는 가상 메모리보다 훨씬 작기 때문에 한정된 프레임을 효율적으로 운영해야 함. 부적절한 페이지 교체는 빈번한 디스크 I/O를 유발하여 시스템 전체가 페이지 교체에만 매달리는 쓰레싱(Thrashing) 현상을 일으키므로, 페이지 적중률을 극대화할 수 있는 지능적인 선택 전략이 필수적임

## Ⅱ. 특징 및 비교

### 가. 주요 페이지 교체 알고리즘 상세 비교

| 구분 | OPT (Optimal) | FIFO (First-In First-Out) | LRU (Least Recently Used) | LFU (Least Frequently Used) |
|:---|:---|:---|:---|:---|
| 핵심 원리 | 미래에 가장 늦게 사용될 페이지 교체 | 가장 먼저 들어온 페이지 교체 | 가장 오랫동안 사용되지 않은 페이지 교체 | 참조 횟수가 가장 적은 페이지 교체 |
| 구현 가능성 | 불가능 (미래 예측 불가) | 매우 쉬움 (큐 활용) | 가능 (스택/카운터 활용) | 가능 (참조 횟수 기록) |
| 성능 수준 | 최상 (이론적 한계치) | 낮음 (모순 발생 가능) | 우수 (지역성 활용) | 중간 (집중 참조 시 왜곡) |
| 주요 특징 | 알고리즘 성능의 기준점 | Belady의 모순 발생 | 시간 지역성 원리 기반 | 참조 빈도 중심 관리 |

> 요약: 이론적으로는 OPT가 최고이나 실무적으로는 참조 지역성을 가장 잘 반영하는 LRU 계열이 표준으로 쓰임

### 나. 알고리즘 선택 시 고려사항
- **오버헤드**: 페이지 참조마다 정보를 갱신해야 하므로 하드웨어 지원이 없으면 성능 저하 유발
- **정밀도 vs 비용**: 정교한 LRU를 위해 스택을 관리할 것인지, 단순하게 참조 비트(Reference Bit)만 쓸 것인지의 트레이드오프

## Ⅲ. 구성요소/구조

### 가. 페이지 교체 메커니즘 및 데이터 흐름

```text
[페이지 참조] -> [Hit 검사] --(No)--> [빈 프레임 탐색] --(No)--> [교체 알고리즘 실행]
                                                                    |
                                                            [희생 페이지 선정]
                                                                    |
[참조 정보 갱신] <------------------------------------------ [Swap-in/out 수행]
```

### 나. 주요 구성 요소 및 역할

| 구성요소 | 역할 및 설명 | 핵심 포인트 |
|:---|:---|:---|
| 참조열 (Ref. String) | 페이지 접근 순서를 기록한 비트열 | 알고리즘의 입력 데이터 |
| 프레임 (Frame) | 페이지가 상주하는 물리 메모리 공간 | 가용 프레임 수에 따라 성능 변화 |
| 수정 비트 (Dirty Bit) | 해당 페이지의 내용이 변경되었는지 표시 | 1일 경우 디스크 쓰기 수행 후 교체 |
| 참조 비트 (Ref. Bit) | 최근에 해당 페이지가 접근되었는지 표시 | LRU 근사 알고리즘(Clock)의 핵심 |
| 카운터 / 타이머 | 페이지가 들어온 시각이나 사용 횟수 기록 | LFU, FIFO 등의 판단 근거 |

> 요약: 하드웨어의 상태 비트(Dirty/Ref Bit)와 운영체제의 관리 정책이 결합되어 최적의 희생자를 찾아냄

## Ⅳ. 문제점 및 개선방안

1. **LRU의 하드웨어 구현 비용**: 매 참조마다 시간이나 순서를 완벽히 기록하는 것은 CPU 오버헤드가 너무 큼
   - **개선방안**: **클록 알고리즘(Clock Algorithm)**과 같이 참조 비트 하나만 사용하여 원형 큐를 도는 방식으로 LRU를 근사화(Approximation)함

2. **LFU의 과거 집착 문제**: 초반에 집중적으로 사용된 페이지가 나중에는 전혀 안 쓰임에도 높은 참조 횟수 때문에 메모리를 계속 점유함
   - **개선방안**: 일정 시간마다 참조 횟수를 반으로 줄이는 **노화(Aging)** 기법을 도입하여 최근의 경향성을 더 강하게 반영함

3. **쓰레싱(Thrashing) 발생**: 프로세스가 늘어나 프레임이 부족해지면 교체 작업 자체가 시스템 성능을 지배함
   - **개선방안**: 프로세스당 최소 프레임 수를 보장하고, **워킹셋(Working Set)** 모델을 적용하여 활발하게 참조되는 페이지 묶음이 한꺼번에 메모리에 올라오도록 관리함

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 리눅스 커널 | 2차 기회(Second Chance) 알고리즘인 클록 방식을 기본으로 사용 | Major Page Fault Count |
| 데이터베이스 (DB) | 자체 버퍼 풀 관리 시 데이터의 특성에 따라 LRU 또는 MRU(최근 사용 교체) 등 변형 적용 | Buffer Cache Hit Ratio |
| 가상화 환경 (Hypervisor) | 게스트 OS 간 메모리 경합 시 Ballooning 기술과 연계하여 페이지 회수 전략 수립 | Swap Out Rate, Latency |

> 요약: 실제 운영체제는 순수 LRU보다 관리 비용이 저렴한 'Second Chance' 계열의 근사 알고리즘을 선호함

## Ⅵ. 결론

페이지 교체 알고리즘은 가상 메모리 성능의 최후 보루임. 단순히 어떤 페이지를 뺄 것인가의 문제를 넘어, 프로그램의 참조 지역성을 얼마나 정확히 예측하여 디스크 I/O라는 값비싼 비용을 회피하느냐가 시스템 응답성을 결정함.

기술사는 각종 알고리즘의 동작 원리와 더불어 벨레이디의 모순, 쓰레싱과 같은 부작용을 명확히 이해해야 함. 특히 최근 고속 SSD와 CXL 기반 원격 메모리 등 메모리 계층 구조가 다변화됨에 따라, 단일 교체 정책보다는 워크로드의 특성을 동적으로 반영하는 적응형 페이지 교체 전략에 대한 깊은 통찰이 요구됨.
