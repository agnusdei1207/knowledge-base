## 미리 알고가기

- 페이지 교체는 빈 프레임이 없을 때 어떤 페이지를 내보낼지 정하는 정책임
- 참조 지역성은 최근 또는 자주 쓰인 페이지가 다시 쓰일 가능성이 높다는 성질임
- 수정 페이지는 교체 전에 저장장치에 다시 기록해야 하므로 비용이 더 큼
- 벨라디 이상(Belady's Anomaly): 프레임 수를 늘렸는데도 페이지 폴트가 오히려 증가하는 현상임

## 작성 근거(검토용)

- 페이지 교체를 페이지 폴트·희생 페이지·더티 페이지 기록 흐름으로 설명함
- FIFO·LRU·LFU·OPT를 선택 기준·지역성 반영·한계로 비교함
- 구성요소 도식과 교체 절차의 중복을 피하기 위해 절차형 구조 도식을 삭제함

## Ⅰ. 개요

- **정의/개념**: 페이지 교체 알고리즘은 페이지 폴트 발생 시 빈 프레임이 없으면 적재된 페이지 중 희생 대상을 선택해 전체 교체 비용을 줄이는 운영체제 정책임
- **배경/필요성**: 제한된 물리 메모리에서 디스크 입출력과 응답 지연을 줄이기 위해 페이지 유지·교체 기준이 필요함

### 쉽게 이해하기 (학습용)
- 냉장고 칸이 다 차면 새 반찬을 넣기 전에 어떤 반찬을 먼저 꺼낼지 정하는 규칙과 같음

## Ⅱ. 특징

- 지역성을 반영하면 재참조 가능성이 낮은 페이지를 선택해 페이지 폴트를 줄일 수 있음
- 미래 참조를 아는 OPT가 이상적인 성능을 내지만 실제 시스템은 근사 알고리즘으로 구현함
- LRU는 접근 시각, LFU는 참조 횟수처럼 희생 기준에 필요한 메타데이터를 매 참조마다 갱신함
- 교체 비용은 페이지 폴트 횟수뿐 아니라 수정 데이터 기록과 긴 꼬리 지연까지 함께 봐야 함

### 쉽게 이해하기 (학습용)
- 최근에 먹은 반찬은 또 먹을 가능성이 높으니 남겨두고, 미래를 다 아는 사람이라면 가장 늦게 먹을 반찬을 완벽히 골라낼 수 있음
- 실제로는 미래를 모르니 언제 꺼냈는지, 몇 번 먹었는지 같은 기록을 계속 갱신해야 함
- 손댄 반찬은 그릇을 다시 씻어야 하니 버릴 때 손이 더 감

## Ⅲ. 종류 및 비교

| 판단 기준 | FIFO | LRU | LFU | OPT |
|:---|:---|:---|:---|:---|
| 선택 기준 | 도착 순서 큐 기준으로 가장 먼저 들어온 페이지를 교체함 | 접근 시각 기준으로 가장 오래 쓰지 않은 페이지를 교체함 | 참조 횟수 기준으로 가장 적게 쓰인 페이지를 교체함 | 미래 참조 시점 기준으로 가장 나중에 다시 쓰일 페이지를 교체함 |
| 지역성 반영 | 최근성·빈도 미반영 | 최근성 반영 | 누적 빈도 반영 | 전체 미래 참조 반영 |
| 한계 | 벨라디 이상이 발생할 수 있음 | 정확한 접근 순서 추적 비용이 큼 | 오래된 참조 이력이 남아 현재 빈도를 왜곡할 수 있음 | 미래 정보를 몰라 실제 구현이 불가능함 |

> 요약: FIFO는 도착 순서, LRU는 최근성, LFU는 누적 빈도, OPT는 미래 재참조 시점을 희생 기준으로 사용함.

### 쉽게 이해하기 (학습용)
- FIFO는 먼저 넣은 반찬부터 꺼내고, LRU는 가장 오래 안 먹은 반찬을 꺼내며, LFU는 가장 적게 먹은 반찬을 꺼냄. OPT는 앞으로 안 먹을 반찬을 미리 알고 꺼냄

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 프레임 목록 | 현재 메모리에 올라온 페이지 집합을 보관해 교체 후보를 구성함 |
| 참조·더티 비트 | 최근 참조 여부와 수정 여부를 기록함 |
| 교체 메타데이터 | 시간 스탬프·카운터·원형 포인터로 정책의 선택 기준을 유지함 |
| 스왑·후면 저장소 관리자 | 더티 희생 페이지를 저장하고 새 페이지를 적재함 |

> 요약: 교체 정책은 참조 비트, 더티 상태, 메타데이터를 이용해 희생 페이지를 선택함.

### 쉽게 이해하기 (학습용)
- 냉장고 안 반찬 목록(프레임 목록), 최근에 먹었는지·손댔는지 표시하는 스티커(참조·더티 비트), 언제 넣었는지 적은 메모(교체 메타데이터), 버릴 반찬을 내놓고 새 반찬을 채우는 손(저장소 관리자)이 함께 동작함

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+     +-------------+
| 페이지 폴트 발생  | --> | 빈 프레임 확인   | --> | 희생 페이지 선정   | --> | 더티 페이지 기록   | --> | 새 페이지 적재   |
+-------------+     +-------------+     +-------------+     +-------------+     +-------------+
```

1. **페이지 폴트 발생**: 참조한 페이지가 메모리에 없음을 확인함
2. **빈 프레임 확인**: 여유 프레임이 있으면 적재하고 없으면 교체로 넘어감
3. **희생 페이지 선정**: 정책에 따라 재사용 가능성이 낮은 페이지를 선택함
4. **더티 페이지 기록**: 희생 페이지가 수정된 경우 후면 저장소에 먼저 기록함
5. **새 페이지 적재**: 요청한 페이지를 프레임에 올리고 메타데이터를 갱신함

> 요약: 페이지 폴트 시 빈 프레임이 없으면 재사용 가능성과 더티 페이지 기록 비용을 보고 희생 페이지를 정함.

### 쉽게 이해하기 (학습용)
- 새 반찬을 찾는데 냉장고에 없으면(폴트), 빈 칸이 있는지 먼저 보고 없으면 규칙대로 반찬을 하나 골라 손댄 그릇은 먼저 씻어 치운 뒤 새 반찬을 넣음

## Ⅵ. 실무 사례

1. 범용 운영체제는 LRU를 Clock으로 근사하고 교체 처리시간과 주요 페이지 폴트율을 확인함
2. 메모리 제약 서버는 프레임 수별 페이지 폴트 곡선으로 작업 집합을 조정하고 페이지 폴트율과 p99 응답시간을 확인함

### 쉽게 이해하기 (학습용)
- 정확한 기록 대신 대략적인 표시만으로 오래 안 먹은 반찬을 찾고, 냉장고 칸 수를 늘렸을 때 오히려 반찬을 더 자주 새로 사오는지도 확인함

## Ⅶ. 결론

- 페이지 교체는 빈 프레임이 없을 때 재참조 가능성이 낮은 페이지를 희생시켜 페이지 폴트 비용을 줄이는 정책임
- 작업 집합의 재참조 패턴에 맞춰 FIFO·LRU·LFU·OPT 근사 기준을 선택하고, 더티 페이지 기록과 메타데이터 갱신 비용을 함께 측정해야 함

### 쉽게 이해하기 (학습용)
- 어떤 반찬을 먼저 꺼낼지 정하는 규칙을 식사 습관에 맞게 고르되, 반찬을 다시 채워 넣는 빈도와 손댄 그릇 씻는 수고까지 함께 재야 함
