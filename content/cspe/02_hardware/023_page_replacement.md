## Ⅰ. 개요
- **정의**: 물리 메모리가 가득 찼을 때 교체 대상 페이지를 선택하는 알고리즘임
- **배경/필요성**: 물리 프레임 수가 가상 페이지 수보다 적으므로 Page Fault 발생 시 어떤 페이지를 내보낼지 결정하는 정책이 필요함
- **비유**: 책꽂이가 가득 찼을 때 어떤 책을 창고로 보낼지 고르는 전략과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 교체 알고리즘별 특성 비교와 최적 기준 이해 | OPT·LRU·FIFO·Clock의 동작 원리 차이 | Belady의 이상현상(FIFO)과 LRU 근사의 구분을 명확히 할 것 |

> 요약: 페이지 교체 알고리즘은 제한된 프레임에서 Page Fault를 최소화하는 교체 대상 선택 정책임

## Ⅱ. 구성요소
```text
  Page Fault 발생
   |
   v
  +------------------+
  | 교체 대상 선택   |
  |  알고리즘 적용   |
  +--------+---------+
           |
   +-------+-------+-------+
   |       |       |       |
   v       v       v       v
  OPT    LRU    FIFO   Clock
  (최적) (최근) (선입) (근사)
           |
           v
  +------------------+
  | Victim 페이지    |
  | Swap-Out 수행    |
  +------------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| OPT (Optimal) | 가장 오랫동안 사용되지 않을 페이지를 교체함 (구현 불가, 비교 기준) | 미래를 아는 사서가 고르는 책 |
| LRU (Least Recently Used) | 가장 오래 전에 참조된 페이지를 교체함 | 가장 오래 손대지 않은 책을 빼는 방식 |
| FIFO (First In First Out) | 가장 먼저 적재된 페이지를 교체함 | 책꽂이에 먼저 꽂힌 책부터 빼는 방식 |
| Clock (Second Chance) | 참조 비트를 활용하여 LRU를 근사하는 순환 큐 방식임 | 시계 바늘이 돌며 안 읽힌 책을 골라내는 방식 |
| Reference/Dirty Bit | 참조 여부와 수정 여부를 기록하여 교체 판단에 활용함 | 책 위의 먼지 유무와 메모 낙서 여부 |

> 요약: OPT를 이론 기준으로 LRU·FIFO·Clock 등이 실용적 교체 정책을 구현함

## Ⅲ. 절차
```text
  Page Fault        Victim 선택      Swap-Out          새 페이지 적재
  (프레임 부족)    (알고리즘 적용)  (Dirty면 기록)    (프레임 할당)
   |                |                |                 |
   +---교체 요청--->+---Victim 결정->+---디스크 기록-->+
                                     |                 ^
                                     +---Clean이면     |
                                         기록 생략-----+
```
- 1단계: 새 페이지 요청 시 빈 프레임이 없으면 Page Fault 인터럽트가 발생함
- 2단계: 교체 알고리즘(LRU, Clock 등)이 Victim 페이지를 선택함
- 3단계: Victim의 Dirty Bit가 설정되어 있으면 디스크(스왑)에 기록하고, Clean이면 기록을 생략함
- 4단계: 해제된 프레임에 새 페이지를 적재하고 페이지 테이블을 갱신함

> 요약: Page Fault → Victim 선택 → 조건부 Swap-Out → 새 페이지 적재의 4단계임

## Ⅳ. 문제점
- Belady 이상현상: FIFO에서 프레임 수를 늘려도 Page Fault가 증가하는 반직관적 현상이 발생함
- LRU 구현 비용: 정확한 LRU는 매 참조마다 타임스탬프 갱신 또는 스택 유지가 필요하여 하드웨어 비용이 높음
- Thrashing: 작업 세트가 프레임 수를 초과하면 교체가 반복되어 CPU 이용률이 급락함

> 요약: Belady 이상현상, LRU 구현 비용, Thrashing이 페이지 교체의 핵심 문제임

## Ⅴ. 개선방안
1. 단기: LRU 근사 알고리즘(Clock, Enhanced Clock)을 적용하여 스택 알고리즘 특성을 유지하면서 구현 비용을 절감함
2. 중기: 참조 비트 노화(Aging) 기법으로 LRU 정밀도를 높여 구현 비용 대비 Fault율을 개선함
3. 장기: 작업 세트 모델(Working Set) 기반 프레임 할당 정책으로 프로세스별 적정 프레임 수를 보장하여 Thrashing을 방지함

> 요약: Clock 근사, Aging 기법, 작업 세트 기반 할당으로 교체 문제를 해소함

## Ⅵ. 전망
- 발전 방향: 머신러닝 기반 접근 패턴 예측으로 OPT에 근접하는 적응형 교체 정책이 연구됨
- 기술사적 판단: NVM(비휘발성 메모리) 계층 추가 시 Swap-Out 비용 모델이 재정립될 필요
- 기술사 제언: 워크로드 프로파일링 기반 동적 교체 정책 전환 메커니즘을 설계할 필요
