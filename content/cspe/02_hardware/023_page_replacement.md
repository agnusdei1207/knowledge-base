## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 페이지 교체 알고리즘은 물리 메모리(RAM)가 가득 찼을 때, 새로 필요한 페이지를 올리기 위해 **어떤 기존 페이지를 디스크로 쫓아낼지(Victim)** 결정하는 OS의 자원 관리 정책이다.
> 2. **가치**: 한 번의 페이지 부재(Page Fault)는 수백만 사이클의 디스크 I/O를 유발하므로, 향후 다시 쓰일 확률이 가장 낮은 페이지를 골라내어 **페이지 부재 횟수를 최소화**하는 것이 전체 시스템 성능의 핵심이다.
> 3. **판단 포인트**: 기술사는 이론적 최적인 **OPT**(구현 불가), 단순한 **FIFO**(성능 불안정), 지역성을 활용한 **LRU**(실무 표준)의 차이를 이해하고, 특히 프레임이 늘어도 성능이 떨어질 수 있는 **Belady's Anomaly**를 경계해야 한다.

---

## Ⅰ. 개요 및 필요성

냉장고(RAM)는 작고 넣어야 할 음식(페이지)은 많다. 음식을 새로 사 왔는데 냉장고가 꽉 찼다면, 하나를 버려야 한다. 이때 "가장 유통기한이 많이 남은 것"을 버릴지, "가장 먼저 산 것"을 버릴지 정하는 규칙이 페이지 교체 알고리즘이다.

잘못된 걸 버리면(예: 저녁에 먹을 고기를 버림), 다시 마트(디스크)에 다녀오느라 요리 시간(CPU 연산)이 엄청나게 지연된다. 따라서 "가장 나중에 먹을 것"을 기가 막히게 골라 버리는 것이 중요하다.

- **📢 섹션 요약 비유**: 페이지 교체는 **'책상 정리'**와 같다. 책상이 좁아 책 한 권을 치워야 할 때, 곧 다시 읽을 책을 치워버리면 서고까지 다시 다녀와야 하는 수고(Page Fault)를 겪게 된다.

## Ⅱ. 4대 핵심 교체 알고리즘 비교

| 알고리즘 | 선정 기준 (Victim) | 특징 및 한계 |
|:---|:---|:---|
| **OPT (Optimal)** | 앞으로 **가장 오랫동안** 안 쓰일 것 | 이론적 최적(폴트 최소). 미래를 알아야 하므로 **구현 불가**. |
| **FIFO (First-In)** | 가장 **먼저 들어온** 것 | 구현이 매우 쉬움. 자주 쓰는 페이지도 오래되면 버려짐. |
| **LRU (Least Recently Used)** | 가장 **오랫동안 안 쓴** 것 | 과거의 이력이 미래를 결정한다는 **지역성** 활용. 실무적 최선. |
| **LFU (Least Frequently)** | 가장 **적게 사용된** 것 | 사용 횟수가 적은 것을 버림. 초기에만 반짝 쓴 페이지가 남는 문제. |

## Ⅲ. 동작 원리: 벨레이디의 역설 (Belady's Anomaly)

일반적으로 "메모리(프레임)를 늘리면 성능이 좋아지겠지?"라고 생각하지만, **FIFO** 방식에서는 반대 현상이 일어날 수 있다.

```text
[ 벨레이디의 역설 검증 (참조열: 1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5) ]

1. 프레임 3개 사용 시: 페이지 폴트 9회 발생
2. 프레임 4개 사용 시: 페이지 폴트 10회 발생 (오히려 늘어남!)

* 원인: FIFO는 페이지의 '중요도'를 무시하고 순서만 따지기 때문에, 프레임이 늘어나도 효율적인 배치가 깨질 수 있음.
* 해결: LRU와 같은 '스택 알고리즘'을 쓰면 프레임이 늘어날 때 폴트가 절대 늘어나지 않음.
```

## Ⅳ. 실무 적용 및 기술사 판단

### 실무 시나리오: 리눅스 커널의 교체 전략 (Clock 알고리즘)
- **상황**: LRU가 가장 좋지만, 매번 페이지 접근 시간을 기록하려니 CPU 오버헤드가 너무 큼.
- **판단**: 완벽한 LRU 대신 1비트의 **'Reference Bit'**만 사용하는 **Clock 알고리즘(Second Chance)**으로 근사 구현해야 한다.
- **대응**: 시계 바늘(포인터)이 돌면서 최근에 쓴 페이지(Bit=1)는 0으로 바꾸고 기회를 한 번 더 주며, 이미 0인 페이지를 만나면 즉시 교체한다. 적은 비용으로 LRU와 비슷한 효과를 낸다.

### 안티패턴: 데이터베이스 풀 스캔(Full Scan) 시의 LRU 오염
- **문제**: 대용량 테이블을 한 번 쓱 훑는 쿼리가 실행되면, 평소 자주 쓰던 데이터(Hot Data)들이 다 쫓겨나고 1회성 데이터로 캐시가 가득 찬다. (**Cache Pollution**)
- **교훈**: MySQL 같은 DB는 **'Midpoint Insertion'** 기술을 써서, 처음 들어온 페이지는 리스트의 중간에 넣고 여러 번 불려야만 상위권(Hot 영역)으로 승격시키는 전략을 쓴다.

## Ⅴ. 기대효과 및 결론

페이지 교체 알고리즘은 **'과거를 통해 미래를 예측하는 기술'**이다. 완벽한 예측(OPT)은 불가능하지만, 지역성이라는 인간의 행동 패턴을 이용해 90% 이상의 효율을 낸다.

기술사는 단순히 알고리즘 수식을 넘어서, **'쓰기(Dirty) 비트'**가 있는 페이지를 버릴 때 디스크 쓰기 비용이 추가된다는 점, 그리고 **'CXL'** 같은 차세대 메모리 계층에서 교체 주기가 어떻게 변하는지까지 시야를 확장해야 한다.

### 📈 관련 키워드 및 발전 흐름도

```text
FIFO - 단순한 순서 기반 (Belady's Anomaly 위험)
    |
    v
LRU - 최근성 기반 (지역성 활용, 실무 표준)
    |
    v
Clock (NUR) - LRU의 오버헤드를 줄인 실무적 근사 방식
    |
    v
LRU-K / ARC - 단순 최근성을 넘어 빈도와 패턴을 결합한 지능형 교체
    |
    v
Multi-Tiering - DRAM/CXL/SSD 계층 사이에서 데이터를 옮기는 최신 흐름
```

### 👶 어린이를 위한 3줄 비유 설명

1. 페이지 교체는 **'좁은 책상 정리하기'**와 같아요. 새 책을 올리려면 하나를 치워야 하죠.
2. "가장 옛날에 본 책"을 치우는 게 보통은 제일 똑똑한 방법(LRU)이에요.
3. 하지만 치운 책을 바로 다시 찾게 되면, 서고(디스크)까지 멀리 다녀와야 해서 공부가 늦어진답니다!
