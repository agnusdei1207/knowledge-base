# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 물리 메모리가 꽉 찼을 때, 디스크에서 새로운 페이지를 가져오기 위해 기존 페이지 중 무엇을 버릴지(Swap Out) 결정하는 알고리즘
- **왜 필요한가**: 가상 메모리는 디스크를 활용해 메모리 용량을 속이지만, 결국 자주 쓰는 데이터는 램(RAM)에 있어야 빠르다. 램 공간이 한정되어 있으니 "가장 안 쓸 것 같은 데이터"를 똑똑하게 골라 버려야 램의 효율을 극대화할 수 있다.
- **핵심 직관**: 책상(RAM)에 더 이상 새 서류를 놓을 자리가 없을 때, 앞으로 제일 안 볼 서류를 서랍(디스크)에 넣어야 다시 꺼내는 수고(Page Fault)를 덜 수 있다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| Page Fault (페이지 부재) | CPU가 요청한 페이지가 현재 램(Frame)에 없는 상태 | 책상에 찾는 서류가 없어 서랍을 뒤져야 하는 상황 |
| 희생 페이지 (Victim Page) | 교체 알고리즘에 의해 디스크로 쫓겨나기로 결정된 페이지 | 책상에서 치워질 서류 1순위 |
| 참조열 (Reference String) | CPU가 접근하는 페이지 번호들의 순서 배열 | "1번 서류, 3번 서류, 1번 서류..." 접근 순서 |
| 참조 비트 (Reference Bit) | 이 페이지를 최근에 읽었는지(1) 안 읽었는지(0) 표시하는 하드웨어 플래그 | 서류에 찍힌 "최근 열람" 도장 |

## 깊이 이해
- **배경·문제의식**: Page Fault가 발생하면 OS가 개입해 디스크 I/O를 수행하므로 CPU 사이클 기준 수백만 배 느려진다. 따라서 Page Fault 횟수를 최소화하는 교체 전략이 전체 시스템 성능을 좌우한다.
- **작동 원리**: OS는 참조열의 패턴을 예측하여 희생 페이지를 고른다. 이론상 가장 먼 미래에 사용될 페이지를 버리는 게 최적(OPT)이지만 미래를 알 수 없으므로, "가장 오래 전에 들어온 것(FIFO)", "최근에 안 쓴 것(LRU)", "사용 빈도가 낮은 것(LFU)" 등의 경험적 방식을 쓴다.
- **비유**: 냉장고(RAM) 안의 식재료 관리. FIFO는 무조건 오래된 것부터 버리기(어제 산 파를 계속 쓰는데도 버림), LRU는 최근에 안 먹은 것부터 버리기(합리적임).
- **구체 예시**: 3칸짜리 메모리에 참조열 `1, 2, 3, 1, 4`가 들어올 때, FIFO는 `1`을 버리고 `4`를 넣지만, LRU는 방금 `1`을 썼으므로 가장 오래 안 쓴 `2`를 버리고 `4`를 넣는다.
- **흔한 오해·주의점**: 순수 LRU는 모든 페이지 접근마다 타임스탬프를 갱신해야 해서 하드웨어/OS 오버헤드가 너무 크다. 그래서 실무(Linux 등)에서는 타이머 대신 하드웨어가 찍어주는 '참조 비트' 하나만 보고 원형 큐를 도는 Clock(NUR) 알고리즘을 변형해 쓴다.

## 연결 개념
- 가상 메모리 (Virtual Memory) — (022 참조) 페이징 기법의 기반 환경
- Thrashing (스래싱) — 교체 알고리즘이 실패하거나 메모리가 너무 부족해 계속 교체만 일어나는 상태
- 지역성 (Locality) — 최근 쓴 걸 또 쓰고(시간), 근처를 쓴다(공간)는 원리. LRU가 성립하는 근거.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 페이지 교체 알고리즘은 물리 메모리의 한계를 극복하기 위해, Page Fault 발생 시 디스크로 방출할 희생 페이지(Victim)를 선정하는 최적화 전략이다.
> 2. **가치**: 프로그램의 시간적·공간적 참조 지역성(Locality)을 활용하여 미래의 Page Fault 확률을 최소화하고, CPU의 유효 연산 시간을 극대화한다.
> 3. **판단 포인트**: 이론적 최적해(OPT)나 순수 LRU는 오버헤드로 인해 구현이 불가하며, 실무에서는 하드웨어 참조 비트를 활용한 근사 알고리즘인 Clock(NUR/Second Chance)을 튜닝하여 사용한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 메모리 교체 비용 통제 원리 이해 | Page Fault 오버헤드, 참조 지역성 매핑 | 페이지 부재(Fault)와 캐시 미스(Miss) 혼용 |
| 알고리즘 간 차이와 실무적 한계 인지 | OPT, FIFO, LRU, LFU 비교 및 Belady의 모순 | 순수 LRU를 실제 OS가 그대로 쓴다고 단정 |
| 실무 적용 가능성 확인 | Clock (NUR / 2nd Chance) 알고리즘, LRU-K 등 변형 | 특정 알고리즘 하나만 길게 설명 |

> 요약: 이론적 알고리즘(LRU)의 오버헤드 한계를 명시하고, 이를 보완하는 하드웨어 비트 기반 근사 알고리즘(Clock/NUR)의 실무 적용성을 강조해야 한다.

## Ⅰ. 개요 및 필요성

- 개요: 페이징 기법에서 물리 메모리(Frame)가 모두 할당된 상태일 때, 새로운 페이지를 적재하기 위해 제거할 희생 페이지를 결정하는 알고리즘
- 배경: Page Fault 처리 시 디스크 I/O가 발생하여 CPU 연산 대비 극심한 지연(10^6 사이클 이상)이 발생하므로 부재율 최소화가 요구됨
- 필요성: 제한된 물리 메모리 환경에서 프로세스 실행 연속성을 보장하고 Thrashing을 방지하기 위해, 지역성에 기반한 똑똑한 페이지 교체 필수

---

## Ⅱ. 구조 및 구성요소

```text
CPU 참조 요청 -> [Page Fault] -> 빈 Frame 존재 검사 -> [없음] 페이지 교체 알고리즘 동작
                                                        |
                                                        +-> Victim 선정 -> Swap Out -> 새 페이지 Swap In
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 참조열 (Reference String) | 교체 성능 평가를 위한 페이지 접근 순서열 | 지역성 패턴 분석의 기준 |
| 희생 페이지 (Victim Page) | 교체 알고리즘에 의해 스왑 아웃 대상이 된 페이지 | Dirty Bit가 1이면 디스크 쓰기 필요 |
| 하드웨어 지원 비트 | 참조 비트(Reference Bit), 수정 비트(Dirty Bit) | OS의 교체 판단(NUR 등) 근거 |

> 요약: OS는 하드웨어가 제공하는 참조/수정 상태 비트를 조합하여, I/O 비용이 가장 낮고 향후 참조 확률이 낮은 페이지를 희생양으로 삼는다.

---

## Ⅲ. 주요 교체 알고리즘의 동작원리 (흐름)

```text
Page Fault 발생 -> 교체 큐(리스트) 탐색 -> 전략별 희생 대상 확정 -> 상태 비트 초기화 및 큐 갱신
```

- 1단계 [OPT - 이론적 한계]: "앞으로 가장 오랫동안 사용되지 않을" 페이지 교체 (미래 예측 불가로 구현 불가, 성능 평가 기준치 역할)
- 2단계 [FIFO - 시간 기반]: "가장 먼저 램에 들어온" 페이지 교체 (구현이 쉬우나 빈번히 쓰이는 초기 페이지도 버림)
- 3단계 [LRU - 과거 기반]: "가장 오랫동안 사용되지 않은" 페이지 교체 (시간 지역성 반영 우수, 큐/타임스탬프 갱신 오버헤드 큼)
- 4단계 [Clock/NUR - 근사 기반]: 참조 비트가 0인 페이지를 찾을 때까지 원형 큐를 순회하며 1을 0으로 바꿈 (LRU의 실무적 근사치)

> 요약: 이론적 이상(OPT)을 향해 과거 데이터를(LRU) 추적하되, 현실적인 오버헤드를 줄이기 위해 1비트 상태(NUR)로 근사한다.

---

## Ⅳ. 특징 (FIFO의 한계)
- Belady의 모순 (Belady's Anomaly): 일반적으로 할당된 프레임(Frame) 수가 증가하면 Page Fault가 감소해야 하나, FIFO 알고리즘에서는 프레임 수를 늘렸음에도 오히려 부재율이 증가하는 기현상이 발생함
- 원인: FIFO는 페이지의 '사용 빈도'나 '최근성'을 전혀 고려하지 않고 오직 큐에 들어온 시간만 따지기 때문에, 지역성(Locality)을 반영하는 스택(Stack) 속성을 갖추지 못함
- LRU/OPT 스택 알고리즘: LRU나 OPT는 N개 프레임에 있는 페이지들이 항상 N+1개 프레임의 부분집합이 되는 특성(Stack Property)을 가져 모순이 발생하지 않음

> 요약: 지역성을 무시하는 단순 큐 구조는 자원을 늘려도 성능이 하락할 수 있어, 반드시 참조 이력을 반영하는 알고리즘 구조가 필요하다.

## Ⅴ. 심화 비교 및 적용 판단

| 알고리즘 | 선정 기준 (희생 페이지) | 장점 및 특징 | 한계점 (선택 배제 기준) |
|:---|:---|:---|:---|
| FIFO | 가장 먼저 메모리에 적재된 페이지 | 구현 단순, 오버헤드 최소 | Belady 모순, 빈번한 페이지도 교체 |
| LRU | 최근에 가장 오랫동안 참조되지 않은 페이지 | OPT에 가장 근접, 지역성 반영 우수 | 모든 노드의 갱신 오버헤드 (실구현 어려움) |
| LFU | 참조 횟수가 가장 적은 페이지 | 집중 참조 패턴에 적합 | 초기에 반짝 쓰인 페이지가 계속 잔존 |
| NUR(Clock) | 참조 비트=0, 수정 비트=0 인 페이지 우선 | LRU의 효과를 적은 오버헤드로 근사 구현 | 순환 탐색 시간(Worst Case) 발생 |

> 요약: 범용 OS는 속도와 오버헤드의 균형을 맞춘 NUR(Clock, Second Chance) 계열을 표준으로 채택한다.

**리스크·대응 (알고리즘 오동작 리스크):**
- [Sequential Scan 오염]: DB 전체 풀 스캔 시 대량의 1회성 데이터가 들어와 LRU 큐의 유용한 캐시를 밀어내는 현상 → LRU-K 또는 2Q 알고리즘으로 N번 이상 참조된 경우에만 주 큐로 승격 (지표: 캐시 히트율)
- [Dirty Page I/O 지연]: 교체 대상이 수정 비트(Dirty)=1이면 즉시 디스크 기록이 필요해 응답 지연 발생 → 백그라운드 데몬(pdflush)이 비동기적으로 Dirty Page를 미리 디스크에 동기화

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. RDBMS 버퍼풀 관리: MySQL/Oracle 버퍼풀에서 단일 LRU 대신 미드포인트 인서션(Midpoint Insertion)이나 LRU-K(2회 이상 참조)를 적용해 풀스캔으로 인한 캐시 오염 방어
2. 페이지 회수 임계치 설정: 리눅스 커널의 워터마크(min_free_kbytes) 파라미터를 튜닝하여, 여유 메모리가 고갈되기 전에 kswapd 데몬이 비동기적으로 페이지 회수(Clock 변형)를 시작하도록 유도
3. 응용 힌트 기반 선제 제어: `madvise()` API를 통해 애플리케이션이 OS에게 "이 페이지는 순차 접근 후 버릴 것(MADV_SEQUENTIAL)"이라는 힌트를 주어 불필요한 LRU 적재 방지

**결론 (2줄):**
- 기술사 판단: 완벽한 교체 알고리즘은 없으며, 하드웨어 비용 한계(NUR 근사)와 워크로드 특성(풀스캔 오염)을 보완하는 시스템 아키텍처적 방어 기제가 실무의 핵심이다.
- 향후 방향: CXL 기반 메모리 풀링 및 NVDIMM 계층화가 도입되면서, 단일 디스크로 쫓아내는 것이 아니라 중간 계층(Tiering) 메모리로 페이지를 마이그레이션하는 인텔리전트 티어링(Intelligent Tiering) 알고리즘으로 진화하고 있다.
