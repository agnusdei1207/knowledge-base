## Ⅰ. 개요
- 네트워크를 통해 스토리지 자원을 공유하는 두 가지 대표적 방식
- 데이터 공유의 편의성과 고성능 전송 사이의 기술적 선택

| 구분 | 내용 |
| --- | --- |
| NAS | IP 네트워크 기반 파일 단위 공유 저장소 |
| SAN | 전용 고속 네트워크 기반 블록 단위 공유 저장소 |
| 출제의도 | 전송 단위, 프로토콜, 성능 및 확장성 관점의 비교 역량 확인 |

## Ⅱ. 구성요소
```
[ NAS: File Level ]           [ SAN: Block Level ]
+------+    (Ethernet)        +------+    (FC Switch)
| Host | <------------> [NAS] | Host | <------------> [SAN]
+------+      (NFS/SMB)       +------+      (FC/iSCSI)
      ^                             ^
      | [ File System ]             | [ Local File System ]
```
| 항목 | NAS | SAN |
| --- | --- | --- |
| 접속 방식 | 일반 이더넷 (TCP/IP) | 전용 FC 또는 iSCSI 네트워크 |
| 데이터 단위 | 파일 (File) | 블록 (Block) |
| 장점 | 설치 용이, 파일 공유 최적 | 고성능, 낮은 지연, 서버 부담 적음 |
> 요약: NAS는 공유 폴더 느낌, SAN은 내장 하드디스크 느낌임.

## Ⅲ. 절차
```
[연결 설정] -> [권한/LUN 할당] -> [마운트] -> [데이터 입출력]
```
1. 연결: 이더넷(NAS) 또는 광케이블/HBA(SAN)를 물리적으로 구성함.
2. 할당: 공유 폴더 생성(NAS) 또는 LUN(Logical Unit Number) 생성함.
3. 마운트: 클라이언트에서 네트워크 드라이브나 로컬 디스크로 인식시킴.
4. 입출력: 파일 시스템 요청 처리(NAS) 또는 블록 I/O 직접 수행함.
> 요약: 네트워크 경로를 통해 스토리지를 가상화하여 서버에 제공함.

## Ⅳ. 문제점
- NAS: 네트워크 트래픽 증가 시 성능 병목 및 지연 시간 가변적임.
- SAN: 고가의 장비(FC 스위치, HBA)와 전문 관리 인력 필수적임.

## Ⅴ. 개선방안
- IP-SAN 도입: iSCSI를 통해 기존 이더넷 인프라에서 SAN 기능 구현함.
- 올플래시 적용: SSD 기반 스토리지로 물리적 I/O 한계 돌파함.

## Ⅵ. 전망
- NVMe-over-Fabrics(NVMe-oF) 기술을 통한 SAN 성능의 비약적 향상됨.
- 하이브리드 클라우드 환경의 데이터 이동성 보장이 핵심 성공 요인임.
