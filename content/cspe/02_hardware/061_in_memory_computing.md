## Ⅰ. 개요
- **정의**: 데이터를 주메모리(DRAM)에 상주시킨 채 연산하여 저장장치 I/O를 제거하는 컴퓨팅 방식
- **배경/필요성**: 디스크 기반 처리는 I/O 지연이 전체 응답시간의 대부분을 차지하므로, 데이터를 메모리에 유지하면 지연을 수십~수백 배 줄일 수 있음
- **비유**: 책장에서 책을 꺼내 읽는 대신, 자주 보는 책을 책상 위에 펼쳐 놓고 바로 읽는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 메모리 기반 처리의 원리와 한계 이해 | 디스크 I/O 제거 원리, PIM(033 참조)과의 차이 | 휘발성 한계와 영속성 보장 기법 언급 필요 |

> 요약: 데이터를 메모리에 적재하여 저장장치 접근 없이 연산하는 기법임

## Ⅱ. 구성요소
```text
+------------------+     +------------------+     +------------------+
| 대용량 DRAM      | --> | 인메모리 엔진    | --> | 분산 클러스터    |
| (데이터 상주)    |     | (연산 수행)      |     | (수평 확장)      |
+------------------+     +------------------+     +------------------+
         |                        |
         v                        v
+------------------+     +------------------+
| 영속성 계층      |     | 직렬화/역직렬화  |
| (스냅샷/WAL)     |     | (데이터 교환)    |
+------------------+     +------------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 대용량 DRAM | 수백 GB~TB급 메모리에 전체 작업 데이터를 상주시킴 | 넓은 책상 위에 모든 자료를 펼쳐 놓는 것 |
| 인메모리 엔진 | 메모리 상 데이터를 대상으로 질의·연산을 수행하는 처리기 | 책상 위 자료를 바로 읽고 계산하는 사람 |
| 분산 클러스터 | 여러 노드의 메모리를 합산하여 용량을 수평 확장함 | 여러 책상을 이어 붙여 작업 공간을 넓히는 것 |
| 영속성 계층 | 스냅샷·WAL로 메모리 데이터를 디스크에 주기적으로 기록함 | 작업 중간에 복사본을 서랍에 보관하는 것 |
| 직렬화/역직렬화 | 객체를 바이트 스트림으로 변환하여 노드 간 전송함 | 편지를 봉투에 넣어 보내고 받는 쪽에서 꺼내 읽는 것 |

> 요약: DRAM 상주 데이터, 인메모리 엔진, 분산 클러스터, 영속성 계층으로 구성됨

## Ⅲ. 절차
```text
데이터 로딩 --> 메모리 파티셔닝 --> 인메모리 연산 --> 결과 반환/영속화
```
- 1단계: **데이터 로딩** — 디스크·외부 소스의 데이터를 DRAM으로 적재함
- 2단계: **메모리 파티셔닝** — 데이터를 노드별·파티션별로 분할 배치하여 병렬 접근을 준비함
- 3단계: **인메모리 연산** — 메모리 상에서 질의·집계·조인 등을 수행하여 디스크 I/O 없이 처리함
- 4단계: **결과 반환/영속화** — 연산 결과를 반환하고, 필요시 스냅샷·WAL로 디스크에 기록함

> 요약: 데이터를 메모리에 적재한 뒤 파티셔닝·연산·영속화 순서로 처리함

## Ⅳ. 문제점
- **휘발성 데이터 손실**: 전원 장애 시 DRAM 데이터가 소멸 — 영속성 미보장으로 장애 복구가 어려움
- **메모리 용량 제약**: 데이터가 메모리 총량을 초과하면 디스크 스왑 발생 — 응답시간이 급격히 증가함
- **높은 비용**: DRAM 가격이 SSD 대비 10배 이상 — 대용량 데이터 유지 시 인프라 비용이 급증함

> 요약: 휘발성·용량 한계·높은 비용이 주요 제약 요인임

## Ⅴ. 개선방안
1. 단기: WAL·체크포인트 주기를 최적화하여 휘발성 데이터 손실 위험을 최소화함
2. 중기: 비휘발성 메모리(NVDIMM, CXL 메모리)를 혼용하여 메모리 용량 상한을 확장함
3. 장기: PIM(033 참조) 기반 근메모리 연산으로 데이터 이동과 DRAM 의존도를 동시에 절감함

> 요약: 영속성 강화 → 비휘발성 메모리 혼용 → PIM 전환 순서로 개선함

## Ⅵ. 전망
- 발전 방향: CXL 메모리 풀링으로 노드 간 메모리 공유가 확대되어 용량 제약이 완화될 것임
- 기술사적 판단: 실시간 분석·AI 추론 워크로드 증가로 인메모리 처리 수요가 지속 확대될 것임
- 기술사 제언: 데이터 영속성 계층 설계와 메모리 티어링 전략을 비용 대비 성능 관점에서 수립할 필요
