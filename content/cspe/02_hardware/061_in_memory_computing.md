## Ⅰ. 개요
- **정의**: 데이터를 메인 메모리(DRAM)에 상주시켜 디스크 I/O 없이 처리하는 컴퓨팅 방식임
- **배경/필요성**: 대규모 실시간 분석 워크로드에서 디스크 기반 처리의 지연이 병목이 되어 메모리 직접 처리 필요
- **비유**: 서류를 매번 창고에서 꺼내지 않고, 책상 위에 펼쳐 놓고 즉시 작업하는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 디스크 I/O 제거를 통한 처리 속도 개선 원리 이해 | 메모리 상주 + 컬럼 스토어 + 병렬 처리 조합 | 단순 캐싱과 인메모리 컴퓨팅의 차이 구분 필요 |

> 요약: 메모리에 데이터를 상주시켜 디스크 I/O 지연을 제거하는 고속 처리 패러다임임

## Ⅱ. 구성요소
```text
+------------------+     +------------------+     +------------------+
|  Application     | --> |  In-Memory       | --> |  Persistence     |
|  Layer           |     |  Engine          |     |  Layer           |
+------------------+     +------------------+     +------------------+
                              |
                              v
                    +------------------+
                    |  Distributed     |
                    |  Memory Pool     |
                    +------------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| In-Memory Engine | 데이터를 DRAM에 적재하고 연산을 수행하는 핵심 처리 엔진임 | 책상 위 작업 공간 |
| Distributed Memory Pool | 여러 노드의 메모리를 논리적으로 통합한 공유 메모리 풀임 | 여러 책상을 연결한 대형 작업대 |
| Persistence Layer | 장애 복구를 위해 메모리 데이터를 비휘발성 매체에 주기적 저장함 | 작업 중간 결과를 금고에 백업 |
| Column Store | 컬럼 단위로 데이터를 메모리에 배치하여 분석 질의 성능을 높임 | 항목별로 분류된 서류 바인더 |

> 요약: 메모리 엔진, 분산 메모리 풀, 영속 계층, 컬럼 스토어로 고속 처리 구조를 형성함

## Ⅲ. 절차
```text
Data Ingestion --> Memory Loading --> Parallel Processing --> Result Return
     |                  |                    |                     |
     v                  v                    v                     v
  Source DB        Column Format        Multi-Thread           Response
  / Stream         Compression          Execution              + Persist
```
- 1단계: **Data Ingestion** — 원천 DB·스트림에서 대상 데이터를 추출하여 메모리 엔진으로 전달함
- 2단계: **Memory Loading** — 컬럼 포맷으로 압축·인코딩하여 DRAM에 적재함
- 3단계: **Parallel Processing** — 멀티스레드·SIMD 연산으로 메모리 상 데이터를 병렬 처리함
- 4단계: **Result Return** — 처리 결과를 애플리케이션에 반환하고 영속 계층에 체크포인트 기록함

> 요약: 데이터 수집 후 메모리 적재, 병렬 처리, 결과 반환·영속화의 4단계로 동작함

## Ⅳ. 문제점
- **메모리 용량 한계**: DRAM 단가가 디스크 대비 10배 이상 높아 대용량 데이터 전체 상주가 비용 부담임
- **휘발성 리스크**: 정전·장애 시 메모리 데이터가 소실되어 데이터 무결성 훼손 가능함
- **GC 지연**: 대용량 힙을 사용하는 JVM 기반 구현에서 GC pause가 응답 지연을 유발함

> 요약: 메모리 비용, 휘발성, GC 지연이 인메모리 컴퓨팅의 주요 제약임

## Ⅴ. 개선방안
1. 단기: Hot/Cold 데이터 티어링으로 자주 접근하는 데이터만 메모리에 상주시켜 비용 절감
2. 중기: NVDIMM·CXL 메모리 풀링으로 비휘발성 + 대용량 메모리 계층 확보
3. 장기: PIM(Processing-In-Memory) 기술 도입으로 메모리 내부에서 연산을 수행하여 GC·데이터 이동 오버헤드 제거

> 요약: 티어링, 비휘발 메모리 확장, PIM 기술 순으로 비용·안정성·성능 문제를 단계적 해소함

## Ⅵ. 전망
- 발전 방향: CXL 기반 메모리 패브릭이 노드 간 메모리 공유를 표준화하여 분산 인메모리 풀 확장이 가속됨
- 기술사적 판단: 실시간 AI 추론·스트림 분석 수요 증가로 인메모리 컴퓨팅은 데이터 플랫폼의 기본 계층으로 정착할 전망임
- 기술사 제언: 메모리 계층(DRAM-NVDIMM-CXL) 설계와 장애 복구 전략을 함께 수립할 필요
