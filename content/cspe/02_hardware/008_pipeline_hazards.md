## 미리 알고가기

- 해저드는 다음 파이프라인 단계의 진행을 지연시키는 충돌 상황임
- 구조적·데이터·제어 해저드로 나뉨
- 포워딩·분기 예측·자원 분리는 대표 대응 수단임
- CPI(Cycles Per Instruction): 명령어 한 개 처리에 필요한 평균 클록 사이클 수임
- RAW(Read After Write): 앞 명령어의 쓰기가 끝나기 전에 뒤 명령어가 같은 값을 읽으려는 데이터 의존 상황임
- 정체(Stall): 해저드가 풀릴 때까지 파이프라인 진행을 멈추는 대응임
- 파이프라인 초기화(Flush): 분기 예측이 틀렸을 때 이미 인출한 명령어를 무효화하는 동작임

## 작성 근거(검토용)

- 해저드를 구조적·데이터·제어 원인으로 나누고 각 원인에 자원 분리·포워딩·분기 예측을 연결함
- 구조적·데이터·제어 해저드를 원인·대응·검증 지표로 구분함
- 해저드 유형마다 감지·대응 방식이 달라 하나의 공통 절차로 뭉친 기존 Ⅴ절은 삭제함

## Ⅰ. 개요

- **정의/개념**: 파이프라인 해저드는 여러 명령어가 단계별로 중첩 실행될 때 자원 충돌·데이터 의존·분기 불확실성으로 다음 단계 진행이 지연되는 상태임
- **배경/필요성**: 파이프라인 충돌에 따른 정체와 초기화 손실을 줄이기 위해 해저드 유형별 대응이 필요함

### 쉽게 이해하기 (학습용)
- 여러 사람이 한 줄로 조립 작업을 하다가 도구가 부족하거나, 앞사람 결과물을 기다리거나, 다음에 뭘 조립할지 몰라 줄이 멈추는 상황과 같음

## Ⅱ. 특징

- 구조적 해저드는 동일 자원 경쟁에서 발생함
- 데이터 해저드는 결과가 준비되기 전에 다음 명령이 값을 필요로 할 때 생김
- 제어 해저드는 분기 결과 미확정으로 다음 경로가 불분명할 때 발생함
- 해저드 대응 회로는 CPI, 전력, 면적 비용을 함께 변화시킴

### 쉽게 이해하기 (학습용)
- 같은 도구를 서로 쓰려다 부딪히면 구조적 해저드, 앞사람 결과물을 기다리면 데이터 해저드, 갈림길에서 방향을 모르면 제어 해저드임
- 이런 대응 장치를 달수록 처리 속도·전력·부품 비용이 함께 바뀜

## Ⅲ. 종류 및 비교

| 판단 기준 | 구조적 해저드 | 데이터 해저드 | 제어 해저드 |
|:---|:---|:---|:---|
| 원인·대표 사례 | 자원 충돌(단일 메모리 포트 경쟁) | 값 의존성(읽기 후 쓰기, RAW) | 분기 불확실성(분기·점프 명령) |
| 대표 대응 | 자원 분리·증설 | 포워딩·정체 | 분기 예측 |
| 검증 지표 | 자원 충돌률 | 데이터 대기율 | 분기 예측 실패율 |

> 요약: 구조적 해저드는 자원, 데이터 해저드는 값 의존성, 제어 해저드는 분기 경로가 원인임.

### 쉽게 이해하기 (학습용)
- 화장실 하나를 두고 줄서면 구조적 해저드, 화장실을 늘리는 게 대응임
- 앞사람 반제품을 못 받아 기다리면 데이터 해저드, 바로 건네주는 게 대응임
- 갈림길 표지판이 없어 멈추면 제어 해저드, 미리 예측해서 가보는 게 대응임

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 해저드 감지 장치 | 명령어 간 충돌을 감지해 정체 또는 우회 전달 여부를 결정함 |
| 포워딩 경로 | 준비된 결과를 우회 전달해 데이터 대기를 줄임 |
| 공유 자원 | 메모리 포트와 실행 유닛 수가 구조적 해저드 발생 빈도를 결정함 |
| 분기 제어 | 분기 예측과 파이프라인 초기화가 제어 해저드 손실을 결정함 |

```text
+----------------------+     +----------------+     +----------------+
| 해저드 감지 장치       | --> | 포워딩 경로      | --> | 실행 흐름        |
+----------------------+     +----------------+     +----------------+
            |
            +--> 공유 자원
            |
            +--> 분기 제어
```

> 요약: 해저드 감지 장치는 충돌 유형에 따라 정체·우회 전달·분기 초기화 여부를 결정함.

### 쉽게 이해하기 (학습용)
- 감시원(해저드 감지 장치)이 충돌을 알아채면, 반제품을 바로 옆으로 넘기거나(포워딩 경로) 공용 도구를 늘리거나(공유 자원) 갈림길 안내판을 세워두는(분기 제어) 방식으로 대응함

## Ⅵ. 실무 사례

1. 데이터 의존성이 많은 CPU는 결과 대기를 줄이기 위해 포워딩 경로를 적용하고, 데이터 대기율과 CPI로 검증함
2. 분기 명령 비중이 높은 CPU는 잘못 인출한 명령을 줄이기 위해 동적 분기 예측기를 적용하고, 분기 예측 실패율과 파이프라인 초기화 사이클로 검증함

### 쉽게 이해하기 (학습용)
- 반제품을 자주 기다리는 라인은 옆으로 바로 건네주는 길을 놓고, 갈림길이 잦은 라인은 자주 가는 방향을 미리 예측해 걸어가 봄

## Ⅶ. 결론

- 파이프라인 해저드는 자원 충돌·데이터 의존·분기 불확실성을 구분하고, 유형별 대기 감소와 하드웨어 비용을 검증해야 함
- 데이터 의존이 지배적인 워크로드는 포워딩 경로를 우선 확장하고, 분기 비중이 높으면 예측기 정교화를, 자원 충돌이 잦으면 공유 자원 증설을 우선해야 함

### 쉽게 이해하기 (학습용)
- 충돌 원인을 자원·데이터·분기로 나눠 찾아내고, 대응 장치를 달 때 줄어드는 대기 시간과 늘어나는 비용을 함께 따져야 함
