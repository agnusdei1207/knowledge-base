## Ⅰ. 개요
- 정의: 파이프라인에서 다음 명령어가 예정된 사이클에 실행되지 못하는 방해 현상
- 종류: 구조적(Structural), 데이터(Data), 제어(Control) 해저드
- 출제 의도: 각 해저드의 발생 원인과 파이프라인 성능 저하 요인 분석 능력 평가

## Ⅱ. 구성요소
- ASCII 구조도 (Hazard Stall)
  Cycle:  1     2     3     4     5     6
  Inst1: [IF]--[ID]--[EX]--[MEM]-[WB]
  Inst2:       [IF]--[ID]--[STALL]-[EX]--[MEM]-[WB]
                            (Bubble)

- 구성요소 표
| 구성요소 | 발생 원인 | 해결 비유 |
| :--- | :--- | :--- |
| 구조적 해저드 | 동일 자원(메모리 등) 동시 접근 시도 | 설비 증설 |
| 데이터 해저드 | 이전 명령의 결과가 아직 준비 안 됨 | 지인 찬스(포워딩) |
| 제어 해저드 | 조건 분기 결과 미결정으로 다음 명령 모름 | 미리 찍기 |
> 요약: 자원 충돌, 데이터 의존성, 분기 결정 지연이 주된 원인임

## Ⅲ. 절차
- ASCII 흐름도
  (Detect Hazard) -> (Insert Bubble/Stall) -> (Resolve) -> (Resume)

- 4단계 설명
1. 감지(Detection): 하드웨어 로직이 파이프라인 단계 간 의존성이나 충돌 감지
2. 지연(Stalling): 충돌이 해결될 때까지 후속 명령어의 진행을 멈춤(Bubble 삽입)
3. 해결(Resolution): 자원 확보, 데이터 포워딩, 혹은 분기 결과 확정 대기
4. 재개(Resumption): 해저드 원인이 사라지면 파이프라인을 다시 가동
> 요약: 문제 감지 시 버블을 삽입하여 안전을 확보한 후 순차적으로 해결함

## Ⅳ. 문제점
- 성능 저하: Stall 발생 시 CPI(Cycles Per Instruction)가 증가하여 실제 성능 하락
- 복잡성: 모든 의존성을 체크하기 위한 하드웨어 인터록(Interlock) 회로 증가

## Ⅴ. 개선방안
- (단기) 하드웨어 분리: 명령어 메모리와 데이터 메모리 분리 (구조적 해저드 방지)
- (중기) 데이터 포워딩: ALU 결과를 메모리 쓰기 전 다음 연산에 직접 전달
- (장기) 동적 스케줄링: 비순차 실행(OoO)을 통해 의존성 없는 명령 먼저 수행

## Ⅵ. 전망
- 로드맵: 컴파일러의 정적 최적화와 하드웨어의 동적 해저드 방지 기술의 결합
- CSF: 정교한 분기 예측 알고리즘(TAGE 등)을 통한 제어 해저드 최소화가 관건
