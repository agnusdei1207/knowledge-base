## Ⅰ. 개요
- **정의**: 파이프라인에서 다음 명령어를 예정 클럭에 실행하지 못하게 만드는 의존성 충돌
- **배경/필요성**: 파이프라이닝(007 참조)은 명령어 간 독립성을 가정하나, 실제로는 의존성이 존재하여 스톨이 발생함
- **비유**: 조립 라인에서 앞 공정의 부품이 아직 완성되지 않아 뒷 공정이 대기하는 상황과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 3가지 해저드 유형 구분 | 데이터·제어·구조 해저드의 원인과 해결 | RAW/WAR/WAW 세부 구분 누락 |

> 요약: 데이터·제어·구조 의존성이 파이프라인 스톨을 유발하는 현상임

## Ⅱ. 구성요소
```text
                  +------------------+
                  | Pipeline Hazards |
                  +--------+---------+
                           |
           +---------------+---------------+
           |               |               |
           v               v               v
     +-----------+   +-----------+   +-----------+
     |   Data    |   |  Control  |   | Structural|
     |  Hazard   |   |  Hazard   |   |  Hazard   |
     +-----+-----+   +-----------+   +-----------+
           |
     +-----+-----+
     |     |     |
     v     v     v
    RAW   WAR   WAW
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 데이터 해저드 | 이전 명령어의 결과를 후속 명령어가 필요로 하여 대기 발생 | 앞 요리 소스가 나와야 다음 요리 시작 가능 |
| 제어 해저드 | 분기 명령어의 결과 확정 전까지 다음 인출 주소를 알 수 없음 | 갈림길에서 방향 결정까지 정지 |
| 구조 해저드 | 두 명령어가 동일 하드웨어 자원을 같은 클럭에 요구함 | 한 대의 프린터를 두 사람이 동시에 사용 시도 |

> 요약: 데이터·제어·구조 해저드가 파이프라인 중첩 실행을 방해함

## Ⅲ. 절차
```text
  명령어 투입      의존성 검출      스톨/우회 판정    해소 후 재개
  (Issue)         (Detect)        (Resolve)        (Resume)
   |               |               |               |
   +--파이프진입-->+--비교로직----->+--NOP/포워딩--->+
  IF 단계        ID 단계에서      하드웨어 제어    정상 흐름
               레지스터 비교      신호 생성        복귀
```
- 1단계: 새 명령어가 IF를 거쳐 ID 단계에 진입함
- 2단계: ID 단계에서 선행 명령어의 목적 레지스터와 현재 명령어의 소스 레지스터를 비교하여 의존성을 검출함
- 3단계: 의존성이 존재하면 스톨(버블 삽입) 또는 포워딩(009 참조)으로 충돌을 해소함
- 4단계: 해저드가 해소된 후 파이프라인이 정상 흐름으로 복귀함

> 요약: 투입-검출-해소-재개 4단계로 해저드를 처리함

## Ⅳ. 문제점
- 데이터 해저드 스톨: RAW 의존성이 연속 명령어에 빈번히 발생함 — 평균 CPI가 1보다 커져 처리율이 저하됨
- 제어 해저드 페널티: 분기 결과가 EX 이후에 확정됨 — 오예측 시 2~3클럭의 파이프라인 플러시가 발생함
- 구조 해저드 경합: 단일 포트 메모리에서 IF와 MEM이 동시 접근을 요구함 — 한쪽이 1클럭 지연됨

> 요약: 스톨·플러시·자원 경합이 파이프라인 처리율을 감소시킴

## Ⅴ. 개선방안
1. 단기: 포워딩 경로를 추가하여 RAW 스톨을 1~2클럭에서 0클럭으로 감소시킴 (009 참조)
2. 중기: 분기예측기(BHT, BTB)를 도입하여 제어 해저드 페널티를 오예측 시에만 한정함 (009 참조)
3. 장기: 명령어 메모리와 데이터 메모리를 분리(하버드 구조)하여 구조 해저드를 원천 제거함

> 요약: 포워딩·분기예측·메모리 분리로 각 해저드를 해결함

## Ⅵ. 전망
- 발전 방향: 비순차 실행(OoO)과 레지스터 리네이밍으로 WAR/WAW 해저드를 하드웨어 수준에서 제거하는 추세임
- 기술사적 판단: 해저드 유형 분류와 해결 기법은 파이프라인 관련 문제에서 필수 서술 항목임
- 기술사 제언: 해저드 해소 기법의 하드웨어 비용 대비 성능 개선 비율을 정량적으로 비교·제시할 필요
