## Ⅰ. 개요
- 정의: 서로 다른 프로토콜의 IoT 기기들을 연결하고 클라우드 전송 전 데이터를 처리하는 장치
- 배경: 센서 노드의 통신 거리 한계 극복 및 대규모 데이터의 실시간 응답성 확보 필요
- 출제 의도: 프로토콜 변환, 데이터 필터링 및 에지 컴퓨팅 역할 이해

## Ⅱ. 구성요소
- ASCII 구조도
  [ End Devices ] --(ZigBee/BLE)--+
  [ (Sensors)   ] --(WiFi/NFC)----+--> [ IoT Gateway ] --(LTE/5G)--> [ Cloud ]
                                       [ Edge Proc  ]

- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| Protocol Bridge | 이종 네트워크 규격 간의 데이터를 변환/중계 | 통역사 |
| Data Aggregator | 다수의 센서 데이터를 수집 및 병합 | 집하장 |
| Edge Engine | 클라우드 전송 전 현장에서 즉시 판단 및 제어 | 지휘소 |

- > 요약: 로컬 네트워크의 허브이자 클라우드 부하를 줄이는 전초 기지

## Ⅲ. 절차
- ASCII 흐름도
  [Scanning] -> [Connecting] -> [Data Filtering] -> [Routing]

1. 장치 탐색: 주변의 활성화된 IoT 노드들을 식별하고 페어링 수행
2. 데이터 수집: 주기적으로 각 노드로부터 환경/상태 정보 획득
3. 에지 처리: 의미 없는 중복 데이터 제거 및 이상 징후 발생 시 즉각 제어 신호 송출
4. 업링크 전송: 가공된 데이터를 표준 규격(MQTT, HTTP)으로 클라우드에 전달

- > 요약: 필터링과 판단을 통해 네트워크 대역폭과 클라우드 비용 최적화

## Ⅳ. 문제점
- 보안 취약성: 수많은 기기가 연결되는 접점으로 해킹 및 DDoS 공격의 통로가 됨
- 가용성 이슈: 게이트웨이 장애 시 하부의 모든 IoT 서비스가 중단되는 단일 실패점

## Ⅴ. 개선방안
- 하드웨어 보안: TPM(Trusted Platform Module) 및 보안 부트(Secure Boot) 적용
- 이중화 구성: 다중 게이트웨이 클러스터링을 통한 자동 장애 복구 기술 도입

## Ⅵ. 전망
- 로드맵: 단순 중계를 넘어 로컬 AI 모델을 실행하는 'AI Edge Gateway'로 진화
- CSF: 저지연(Low Latency) 보장을 위한 실시간 OS(RTOS) 및 전용 가속기 탑재 필수
