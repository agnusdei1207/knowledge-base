## Ⅰ. 개요
- **정의**: CPU 개입 없이 I/O 장치와 메모리 간 데이터를 직접 전송하는 하드웨어 기법임
- **배경/필요성**: CPU가 바이트 단위로 I/O를 처리하면 대용량 전송 시 CPU 사이클 대부분이 데이터 복사에 소비됨
- **비유**: 사장(CPU)이 서류를 직접 나르는 대신 비서(DMA 컨트롤러)가 캐비닛↔책상 간 서류를 옮기는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| DMA 동작 원리와 버스트/사이클 스틸 비교 | CPU는 시작·종료만 관여하고 전송은 DMA 컨트롤러가 수행함 | 버스트 = 연속 전송, 사이클 스틸 = 버스 사이클 1개씩 양보 구분 |

> 요약: DMA는 CPU 바이패스로 블록 단위 I/O 전송 효율을 극대화하는 기법임

## Ⅱ. 구성요소
```text
CPU ---+--- System Bus ---+--- Memory
       |                   |
       +--- DMA Ctrl ------+
                |
            I/O Device
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| DMA 컨트롤러 | 소스/목적 주소·전송 크기를 레지스터에 설정받아 자율 전송을 수행하는 하드웨어 | 이사업체 담당자 |
| 주소 레지스터(MAR) | 현재 전송 중인 메모리 주소를 보관함 | 짐을 놓을 방 번호 |
| 카운트 레지스터(WC) | 남은 전송 바이트/워드 수를 추적함 | 남은 짐 박스 수 |
| 버스 요청/승인(BR/BG) | DMA가 버스 사용권을 CPU에 요청하고 허가받는 신호 쌍(045 참조) | 도로 통행권 요청·허가 |

> 요약: DMA 컨트롤러가 주소·카운트 레지스터와 버스 중재 신호로 자율 전송을 수행함

## Ⅲ. 절차
```text
CPU 설정 -> 버스 요청 -> 데이터 전송 -> 완료 인터럽트
   (1)         (2)          (3)            (4)
```
- 1단계: **CPU 초기 설정** — CPU가 DMA 컨트롤러에 소스 주소·목적 주소·전송 크기·전송 방향을 기록함
- 2단계: **버스 요청** — DMA 컨트롤러가 BR 신호로 시스템 버스 사용권을 CPU에 요청하고 BG를 수신함
- 3단계: **데이터 전송** — 버스트 모드(연속 점유) 또는 사이클 스틸 모드(1사이클씩 양보)로 전송함
- 4단계: **완료 인터럽트** — 카운트 레지스터가 0이 되면 DMA가 CPU에 인터럽트를 발생시켜 종료를 알림(043 참조)

> 요약: CPU 설정 → 버스 확보 → 자율 전송 → 인터럽트 완료 순으로 DMA가 동작함

## Ⅳ. 문제점
- **버스 경합**: 버스트 모드 사용 시 DMA가 버스를 장시간 점유하여 CPU 메모리 접근이 지연됨
- **캐시 비일관성**: DMA가 메모리를 갱신해도 CPU 캐시에 이전 값이 남아 데이터 불일치가 발생함
- **주소 공간 제한**: 구형 DMA 컨트롤러는 24비트 주소만 지원하여 16MB 이상 메모리에 접근 불가함

> 요약: 버스 경합·캐시 비일관성·주소 공간 제한이 DMA의 주요 문제임

## Ⅴ. 개선방안
1. 단기: 사이클 스틸 모드 적용으로 CPU와 DMA의 버스 사용을 인터리빙하여 지연을 분산함
2. 중기: 캐시 스누핑(Snooping) 또는 소프트웨어 캐시 플러시로 일관성을 보장함
3. 장기: IOMMU 도입으로 DMA가 가상 주소를 사용하여 전체 물리 메모리에 접근 가능하게 함

> 요약: 사이클 스틸 → 캐시 스누핑 → IOMMU 순으로 DMA 한계를 해소함

## Ⅵ. 전망
- 발전 방향: GPU·NIC 등 고대역 장치에서 RDMA·P2P DMA가 표준화되는 추세임
- 기술사적 판단: 이기종 가속기 시스템에서 DMA 경로 최적화가 전체 처리량을 좌우함
- 기술사 제언: IOMMU 정책과 캐시 일관성 프로토콜을 설계 단계에서 함께 검토할 필요
