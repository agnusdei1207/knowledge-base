## 미리 알고가기

- Type 1은 물리 하드웨어 위에서 직접 동작하는 하이퍼바이저임
- Type 2는 호스트 OS 위에서 애플리케이션처럼 동작하는 하이퍼바이저임
- 자원 과할당(overcommit)은 물리 자원보다 많은 가상 자원을 할당하는 운영 방식임
- 스냅샷은 VM 디스크와 상태를 특정 시점 기준으로 보존하는 기능임

## 작성 근거(검토용)

- Type 1·2는 하이퍼바이저 위치, 호스트 OS 의존성, 장애 경계, 운영 환경을 핵심 축으로 설명함
- 비교표는 실행 계층, 경유 경로, 적용 환경, 장애 전파 범위를 대비함
- 실무 판단은 CPU 준비 대기·p99 I/O 지연과 VM 준비 시간·호스트 메모리 사용률로 검증함

## Ⅰ. 개요

- **정의/개념**: Type 1과 Type 2 하이퍼바이저는 가상머신을 관리하는 계층이 물리 하드웨어에 직접 위치하는지, 호스트 OS 위에 위치하는지를 기준으로 구분하는 서버 가상화 구조임
- **배경/필요성**: 운영 서버와 개발 호스트의 OS 의존성·장애 범위·장치 연동 요구를 충족하기 위해 하이퍼바이저 위치별 선택 기준이 필요함

## Ⅱ. 특징

- Type 1은 하드웨어 위에서 VM과 장치 자원을 직접 관리함
- Type 2는 호스트 OS의 드라이버와 프로세스 위에서 VM을 실행함
- Type 1은 운영 서버·클라우드, Type 2는 개발·시험용 호스트에 배치함
- 장애 범위와 보안 경계가 하이퍼바이저 위치에 따라 달라짐

## Ⅲ. 종류 및 비교

| 판단 기준 | Type 1 하이퍼바이저 | Type 2 하이퍼바이저 |
|:---|:---|:---|
| 위치 | 하드웨어 위에서 직접 실행됨 | 호스트 OS 위에서 실행됨 |
| 실행 경로 | 하이퍼바이저가 CPU·메모리·I/O를 직접 관리함 | 호스트 OS의 스케줄러·드라이버·파일시스템을 경유함 |
| 대표 환경 | 데이터센터·클라우드 운영 서버에 적용함 | 개발 노트북·시험 환경에 적용함 |
| 장애 영향 | 하이퍼바이저·관리 도메인 장애가 호스트 VM에 영향을 줌 | 호스트 OS 장애가 해당 호스트의 VM에 영향을 줌 |

> 요약: Type 1은 하드웨어 위에서 VM 자원을 직접 관리하고 Type 2는 호스트 OS의 자원·드라이버를 경유함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 가상머신 | 게스트 OS와 애플리케이션이 실행되는 논리 서버로 자원 격리 대상이 됨 |
| 하이퍼바이저 코어 | vCPU와 메모리와 I/O를 가상화하며 성능과 격리 수준을 직접 결정함 |
| 호스트 OS | Type 2에서 장치 드라이버와 파일시스템 기반을 제공하지만 추가 장애 경로가 됨 |
| 관리 계층 | 이미지 배포와 snapshot과 migration과 정책 제어를 담당해 운영 자동화 수준을 좌우함 |

> 요약: 가상머신은 하이퍼바이저 코어의 자원을 사용하고 Type 2는 호스트 OS 계층을 추가로 경유하며 관리 계층이 이미지·스냅샷을 제어함.

## Ⅵ. 실무 사례

1. 프라이빗 클라우드 호스트는 준가상화 드라이버와 자원 과할당 한도를 적용하고 CPU 준비 대기·p99 I/O 지연을 확인함
2. 개발 노트북은 Type 2 VM의 스냅샷과 호스트 자원 한도를 관리하고 VM 준비 시간·호스트 메모리 사용률을 확인함

## Ⅶ. 결론

- 운영 서버는 Type 1의 직접 자원 관리와 HA를, 개발 환경은 Type 2의 호스트 연동을 기준으로 선택하고 장애 전파 범위를 검증해야 함
