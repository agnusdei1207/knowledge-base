# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 멀티프로세서 환경에서 각 CPU가 자신에게 직접 연결된 로컬 메모리는 빠르게, 다른 노드의 원격 메모리는 인터커넥트를 거쳐 느리게 접근하는 **비대칭적 메모리 아키텍처**.
- **왜 필요한가**: 모든 CPU가 단일 버스를 공유하는 UMA(Uniform Memory Access) 구조는 코어 수가 늘어날수록 메모리 컨트롤러 병목으로 인해 시스템 확장성이 급격히 저하됨. 이를 해결하기 위해 메모리 컨트롤러를 소켓별로 분산 배치함.
- **핵심 직관**: **"층별 자료실 시스템"** — 내 층(노드) 자료실 서류는 손만 뻗으면 닿지만(로컬), 다른 층 서류를 가져오려면 엘리베이터(인터커넥트)를 타고 이동해야 하므로 시간이 더 걸림.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| **NUMA Node** | CPU 코어 + 로컬 메모리 컨트롤러 + DRAM이 하나로 묶인 단위 | "부서별 독립 사무실" |
| **Interconnect** | 노드 간 데이터를 중계하는 고속 통로 (Intel UPI, AMD Infinity Fabric) | "층간 고속 엘리베이터" |
| **NUMA Ratio** | 로컬 대비 원격 접근 지연의 배수 (통상 1.5~2.5배) | "엘리베이터 이동에 소요되는 추가 시간 배율" |
| **First-Touch** | 메모리를 처음 실제로 사용하는(Write) 스레드의 노드에 물리 페이지를 할당하는 정책 | "서류를 처음 꺼낸 사람 책상 근처에 보관함 배치" |

## 깊이 이해
- **배경·문제의식**: 서버의 성능을 높이기 위해 CPU 소켓을 2개, 4개로 늘리면 모든 CPU가 하나의 '메모리 고속도로'로 몰려듦. 차가 막혀(Bus Contention) 속도가 떨어지는 문제를 해결하기 위해, 고속도로를 여러 구역으로 나누고 구역마다 전용 주차장(메모리)을 만든 것이 NUMA임.
- **작동 원리 (ccNUMA)**:
  1. 물리적으로는 메모리가 나뉘어 있으나, 하드웨어(ccNUMA)가 전체를 **하나의 거대한 주소 공간**으로 보이게 관리함.
  2. CPU가 메모리 주소를 요청하면 하드웨어는 해당 주소가 내 노드인지(Local) 타 노드인지(Remote) 판별함.
  3. 타 노드 주소일 경우 인터커넥트를 통해 원격 노드의 메모리 컨트롤러에 요청을 전달하고 데이터를 받아옴.
- **비유**: 한 사무실에 100명이 공용 프린터 1대를 쓰는 게 UMA라면, 10개 부서마다 프린터를 1대씩 두고 자기 부서 걸 우선 쓰되 급하면 옆 부서 걸 빌려 쓰는 게 NUMA임.
- **구체 예시 (성능 하락 사례)**: 스레드는 0번 노드에서 도는데, 처리할 데이터가 1번 노드에 몰려있으면 매번 인터커넥트를 타야 하므로 CPU 점유율은 100%인데 처리량(Throughput)은 반토막 나는 'NUMA 미스매치' 현상이 발생함.
- **흔한 오해/주의점**: "NUMA는 메모리 공유가 안 된다"는 오해임. 공유는 완벽히 되지만 **"비용(Latency)"**이 다를 뿐임. 이를 무시하고 코딩하면 멀티코어의 이득을 전혀 못 볼 수 있음.

## 연결 개념
- **090 메모리 인터리빙**: 단일 노드 내에서 대역폭을 높이는 기술 (NUMA는 노드 간 배치 기술).
- **035 CXL**: NUMA의 지연 문제를 극복하고 장치 간 메모리 풀링을 가능케 하는 차세대 인터페이스.
- **019 캐시 일관성(MESI)**: 노드 간 데이터 불일치를 막기 위한 기본 프로토콜.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 메모리 컨트롤러를 CPU 소켓별로 분산하여 로컬/원격 접근 지연 차이를 발생시키는 확장형 멀티프로세서 아키텍처임.
> 2. **가치**: 단일 공유 버스(UMA)의 병목을 제거하여 수십~수백 코어 규모의 서버 확장성을 보장함.
> 3. **판단 포인트**: 성능 최적화를 위해 **First-Touch 정책**과 **CPU/Memory Pinning**을 통한 데이터 지역성(Locality) 확보가 운영의 핵심임.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| UMA 대비 차별점 이해 | 버스 경합(Contention) 해소와 확장성 | 단순히 "메모리가 여러 개인 구조"로 서술 금지 |
| 지연(Latency) 특성 분석 | 로컬 vs 원격 접근 경로 및 NUMA Ratio | 인터커넥트(UPI/Infinity Fabric) 언급 누락 금지 |
| 소프트웨어 최적화 연계 | OS 스케줄링 및 메모리 배치 정책(First-touch) | 하드웨어 구조만 서술하고 운영 전략 누락 금지 |

## Ⅰ. 개요 및 필요성

- **정의**: 멀티소켓 시스템에서 메모리를 노드별로 분산 배치하여, 접근 위치에 따라 지연 시간이 달라지는 비균등 메모리 접근(Non-Uniform Memory Access) 아키텍처.
- **배경**: 코어 수 증가에 따른 단일 공유 메모리 버스의 대역폭 한계와 중재(Arbitration) 오버헤드 급증.
- **필요성**: 소켓별 독립적 메모리 대역폭 확보를 통해 시스템 전체의 확장성(Scalability) 및 처리량 극대화.

---

## Ⅱ. 구조 및 구성요소

```text
 [ NUMA Node 0 ]                     [ NUMA Node 1 ]
 +-------------+                     +-------------+
 |  CPU Cores  | <--- Interconnect ---> |  CPU Cores  |
 |     +-------+     (UPI/IF)        |     +-------+
 |  MC | Local |                     |  MC | Local |
 +-----+ Memory|                     +-----+ Memory|
       +-------+                           +-------+
```

| 구성요소 | 역할 | 기술적 특징 |
|:---|:---|:---|
| **NUMA Node** | 연산과 저장의 최소 단위 | CPU 소켓 + 메모리 컨트롤러(MC) + DRAM |
| **Interconnect** | 노드 간 통신 경로 | Intel UPI(Ultra Path), AMD Infinity Fabric |
| **Local Memory** | 동일 노드 내 DRAM | 최저 지연(90~100ns), 최대 대역폭 |
| **Remote Memory** | 타 노드 소속 DRAM | 인터커넥트 경유 지연 증가 (1.5x~2.0x) |

---

## Ⅲ. 동작 메커니즘 및 지연 분석

- **동작 경로**:
  1. **로컬 접근**: CPU → 내부 MC → 로컬 DRAM (Direct Path)
  2. **원격 접근**: CPU → 내부 MC → Interconnect → 타 노드 MC → 타 노드 DRAM (Indirect Path)
- **지연 시간(Latency) 모델**:
  - $T_{access} = T_{local} + (Hop \times T_{interconnect})$
  - Hop 수가 늘어날수록(예: 4소켓 서버의 대각선 노드 접근) 지연 시간은 선형적으로 증가함.

---

## Ⅳ. 주요 특징 및 소프트웨어 대응 전략

- **하드웨어 특징**:
  - **ccNUMA**: 캐시 일관성 하드웨어가 지원되어 소프트웨어는 단일 메모리 공간으로 인식.
  - **확장성**: 버스 경합이 분산되어 CPU 추가에 따른 성능 선형 증가 유도.
- **OS 및 SW 대응**:
  - **First-Touch Policy**: 메모리 페이지를 처음 건드리는 CPU가 속한 노드에 물리 프레임 할당.
  - **NUMA-aware Scheduling**: 프로세스를 특정 노드에 고정하여 원격 접근 발생 원천 차단.
  - **Numactl/Libnuma**: 관리자가 명시적으로 메모리 할당 위치와 CPU 선호도 지정.

## Ⅴ. 심화 비교: UMA vs NUMA

| 비교 항목 | UMA (Uniform Memory Access) | NUMA (Non-Uniform Memory Access) |
|:---|:---|:---|
| **메모리 접근** | 모든 위치에서 지연 시간 동일 | 위치(로컬/원격)에 따라 지연 차등 |
| **확장성** | 소켓 증가 시 성능 저하(병목) | 소켓 증가 시 선형적 성능 향상 |
| **하드웨어 복잡도** | 낮음 (단일 버스 구조) | 높음 (인터커넥트 및 일관성 제어) |
| **최적화 난이도** | 쉬움 (고려 불필요) | 어려움 (Locality 인식 필수) |
| **주요 대상** | 단일 소켓 PC, 엔트리급 서버 | 엔터프라이즈 서버, 고성능 컴퓨팅(HPC) |

## Ⅵ. 실무 적용 및 기술적 통찰

- **DB 성능 최적화**: Oracle, MySQL 등 대형 DB는 NUMA 환경에서 스레드와 메모리가 꼬일 경우 성능이 급락하므로, `numactl --interleave` 등을 통해 모든 노드에 골고루 분산하거나 특정 노드에 고정하는 튜닝이 필수적임.
- **가상화 환경(VM)**: 하이퍼바이저는 가상 머신(VM)의 CPU와 메모리를 동일한 물리 NUMA 노드에 배치(vNUMA)하여 원격 접근 오버헤드를 최소화함.
- **기술사 의견**: 현대 하드웨어는 코어 밀도가 높아져 단일 칩 내에서도 NUMA 특성(Sub-NUMA Clustering)이 나타나고 있음. 따라서 인프라 설계자는 단순히 소켓 단위를 넘어 다이(Die) 간의 지연 특성까지 고려한 정교한 최적화가 필요함.
