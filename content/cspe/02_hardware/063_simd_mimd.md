## 미리 알고가기

- SIMD: 단일 명령 다중 데이터(Single Instruction Multiple Data, SIMD)는 하나의 명령어가 여러 데이터 요소에 동시에 적용되는 데이터 병렬 실행 방식임
- MIMD: 다중 명령 다중 데이터(Multiple Instruction Multiple Data, MIMD)는 여러 처리기가 서로 다른 명령어를 독립적으로 실행하는 병렬 실행 방식임
- Vector Lane: SIMD 명령이 동시에 처리하는 데이터 요소별 실행 경로임
- Synchronization: MIMD에서 여러 스레드나 프로세스의 실행 순서를 맞추는 제어임

## Ⅰ. 개요

- **정의**: SIMD와 MIMD 프로세서는 병렬 실행을 하나의 명령이 여러 데이터에 적용되는 데이터 병렬 구조로 묶을지, 여러 처리기가 독립 명령을 수행하는 작업 병렬 구조로 나눌지 판단하는 병렬 처리 구조임.
- **배경/필요성**: 영상, 행렬, 신호처리처럼 같은 연산을 반복하는 작업과 서버, 시뮬레이션처럼 독립 작업이 많은 문제는 최적 구조가 다름. SIMD와 MIMD 비교는 병렬화 전략을 하드웨어 특성에 맞추게 함.
- **비유**: SIMD는 한 구령에 맞춰 여러 사람이 같은 동작을 하는 것이고, MIMD는 여러 팀이 각자 다른 작업을 동시에 수행하는 것과 같음.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 데이터 병렬과 작업 병렬 구조의 차이 설명 | 명령 흐름, 데이터 흐름, 분기, 동기화 | 단순 빠르다/느리다 비교 |

> 요약: SIMD와 MIMD는 병렬성을 같은 명령의 반복 처리로 볼지 독립 작업의 동시 처리로 볼지 나누는 기준임.

## Ⅱ. 특징/비교

| 판단 기준 | SIMD | MIMD |
|:---|:---|:---|
| 병렬화 대상 | 같은 연산을 여러 데이터 요소에 적용함 | 서로 다른 작업이나 스레드를 여러 처리기가 실행함 |
| 강점 | 제어 오버헤드가 작고 벡터·행렬 연산 처리량이 높음 | 분기와 불규칙 작업을 독립적으로 처리할 수 있음 |
| 적용 기준 | 데이터 정렬, 규칙적 반복, 낮은 분기 발산이 중요함 | 동기화, 통신, 부하분산 비용 관리가 중요함 |

> 요약: SIMD는 규칙적 데이터 병렬성, MIMD는 독립 작업 병렬성에 적합함.

## Ⅲ. 구성요소

```text
+--------------+        +---------------+
| SIMD Control | -----> | Lane 0..N     |
+--------------+        +---------------+

+----------+   +----------+   +----------+
| Core 0   |   | Core 1   |   | Core N   |
+----------+   +----------+   +----------+
      \              |              /
       +-------- Shared/Network ---+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| SIMD 제어부 | 하나의 명령을 여러 lane에 동시에 배포함 | 단일 구령자 |
| Vector lane | 각 데이터 요소를 병렬로 계산하는 실행 경로임 | 같은 동작을 하는 작업자 |
| MIMD 코어 | 각 코어가 독립 명령 흐름과 상태를 가지고 실행함 | 독립 팀 |
| 공유 메모리/네트워크 | MIMD 코어 간 데이터 교환과 동기화를 지원함 | 회의실과 연락망 |

> 요약: SIMD는 하나의 제어와 여러 lane, MIMD는 여러 독립 코어와 통신 구조로 구성됨.

## Ⅳ. 절차

```text
+----------+     +----------+     +----------+     +----------+
| Split    | --> | Select   | --> | Execute  | --> | Merge    |
+----------+     +----------+     +----------+     +----------+
```

1. **작업 분해**: 반복 연산, 데이터 의존성, 분기 패턴, 독립 작업 단위를 분석함
2. **구조 선택**: 규칙적 데이터 병렬은 SIMD, 독립 작업 병렬은 MIMD에 매핑함
3. **병렬 실행**: SIMD는 lane 단위로, MIMD는 코어와 스레드 단위로 실행함
4. **결과 통합**: reduction, barrier, message passing으로 결과를 합치고 정합성을 확인함

> 요약: SIMD/MIMD 적용은 작업 특성을 분석해 적합한 병렬 구조에 매핑하고 결과를 통합하는 과정임.

## Ⅴ. 문제점 및 개선방안

- **P1 SIMD 분기·정렬 제약**: lane별 조건이 다르거나 데이터가 비연속이면 lane 유휴와 메모리 비효율이 발생함
- **P1 대응**: 데이터 정렬, predication, mask 연산, gather/scatter 최소화를 적용함 (확인: lane utilization)
- **P2 MIMD 동기화 오버헤드**: 공유 자원 잠금, barrier, 메시지 교환이 많으면 병렬 이득이 줄어듦
- **P2 대응**: 작업 분할, lock-free 구조, work stealing, 메시지 batch 처리를 적용함 (확인: 동기화 대기시간)
- **P3 메모리 경합**: SIMD와 MIMD 모두 많은 처리 요소가 같은 메모리 계층을 사용하면 대역폭 병목이 발생함
- **P3 대응**: 비균일 메모리 접근(Non-Uniform Memory Access, NUMA)-aware 배치, 캐시 blocking, prefetch, 메모리 대역폭 측정을 수행함 (확인: bandwidth utilization)

> 요약: SIMD/MIMD 개선은 실행 구조보다 데이터 배치, 분기 제어, 동기화 비용을 먼저 최적화해야 효과가 큼.

## Ⅵ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 영상·신호 처리 | 픽셀·샘플 배열을 SIMD lane에 정렬하고 mask 연산으로 조건 처리를 최소화함 | lane utilization, 처리 프레임 수 |
| 웹·서버 처리 | 요청 단위를 MIMD 스레드나 프로세스로 분산하고 공유 상태 접근을 줄임 | p95 지연, lock wait, 처리량 |
| 과학 계산 | 벡터 연산은 SIMD로, 도메인 분할은 MIMD로 병행 적용함 | speedup, cache miss rate, 통신 비율 |

> 요약: 실무에서는 규칙적 반복은 SIMD, 독립 작업과 도메인 분할은 MIMD로 나누어 병렬 이득을 검증함.

## Ⅶ. 전망

- **발전 방향**: SIMD/MIMD는 중앙처리장치(Central Processing Unit, CPU) vector extension, 그래픽 처리 장치(Graphics Processing Unit, GPU) 단일 명령 다중 스레드(Single Instruction Multiple Threads, SIMT), many-core 신경망 처리 장치(Neural Processing Unit, NPU)가 결합된 heterogeneous parallelism의 기본 판단 기준으로 남음
- **기술사적 판단**: 데이터 규칙성, 분기 비율, 작업 독립성, 공유 메모리 경합, 스케줄러 비용을 기준으로 SIMD와 MIMD 영역을 나눔; vector lane utilization, branch divergence, thread imbalance, cache miss rate, synchronization wait를 같은 입력 규모에서 측정해 병렬화 효과를 검증함
- **기술사 제언**: SIMD/MIMD 답안은 Flynn 분류에 머물지 말고 알고리즘 특성과 측정 지표로 병렬 구조 선택을 설명해야 함
