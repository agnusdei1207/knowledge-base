## 미리 알고가기

- SIMD는 같은 명령을 여러 데이터에 동시에 적용하는 구조임
- MIMD는 여러 처리기가 서로 다른 명령을 독립적으로 수행하는 구조임
- 분기 발산(Branch Divergence): SIMD 레인이 조건문에서 서로 다른 경로로 갈라져 일부 레인이 비활성 상태로 대기하는 현상임
- 선택 기준은 데이터 규칙성, 분기 패턴, 동기화 비용임

## 작성 근거(검토용)

- SIMD·MIMD는 명령 흐름과 데이터 흐름의 차이, 레인 활용률, 동기화 비용을 중심으로 설명함
- 비교표는 제어 구조, 대표 구현·적용, 주요 병목을 기준으로 정리함
- 실무 판단은 레인 사용률, 분기 효율, 처리량, 동기화 대기 시간으로 구체화함

## Ⅰ. 개요

- **정의/개념**: SIMD와 MIMD는 명령·데이터 흐름으로 병렬 실행 구조를 구분하며 SIMD는 한 명령을 여러 데이터에 적용하고 MIMD는 코어별 독립 명령을 병렬 실행함
- **배경/필요성**: 행렬 연산처럼 규칙적인 작업과 웹 서버 요청처럼 독립적인 작업은 병렬화 방식이 다르므로, 데이터 특성과 제어 특성에 맞는 구조 선택이 필요함

### 쉽게 이해하기 (학습용)
- SIMD는 프레스 기계 하나가 같은 틀로 여러 부품을 한 번에 찍어내는 것과 같고, MIMD는 노동자 여럿이 각자 다른 작업을 동시에 하는 것과 같음

## Ⅱ. 특징

- SIMD는 하나의 제어 흐름을 여러 레인이 공유해 반복 명령 수를 줄임
- MIMD는 처리 요소마다 다른 명령을 실행해 독립 태스크와 분기 경로를 병렬 처리함
- SIMD는 분기 발산·비연속 메모리 접근에서 레인 유휴가 발생하고 MIMD는 동기화·락 경합에서 코어가 대기함
- 두 구조 모두 메모리 대역폭과 작업 분할 방식이 처리량과 코어 유휴 시간을 좌우함

### 쉽게 이해하기 (학습용)
- 프레스(SIMD)는 같은 틀을 반복 사용해 지시를 줄이지만 부품 모양이 갈리면 일부 자리를 비워둬야 함
- 노동자들(MIMD)은 각자 다른 작업을 하다 서로 자재를 기다리며 멈추기도 함

## Ⅲ. 종류 및 비교

| 판단 기준 | SIMD | MIMD |
|:---|:---|:---|
| 제어 구조 | 하나의 명령 흐름이 여러 레인에 동시에 적용됨 | 각 코어가 독립 명령 흐름과 상태를 가짐 |
| 대표 구현·적용 | 벡터 유닛·GPU 레인에서 벡터·영상·행렬의 반복 연산을 처리함 | 멀티코어 CPU·클러스터에서 서버 요청·시뮬레이션 같은 독립 태스크를 병렬 처리함 |
| 주요 병목 | 분기 발산·레인 유휴·불규칙 메모리 접근 | 락 경합·배리어 대기·부하 불균형 |

> 요약: SIMD는 같은 연산을 여러 데이터에 반복 적용하고, MIMD는 다른 작업을 독립적으로 나누는 구조임.

### 쉽게 이해하기 (학습용)
- 프레스 기계 하나가 여러 부품을 같은 틀로 찍는 것이 SIMD, 노동자 여럿이 각자 다른 작업대에서 다른 일을 하는 것이 MIMD임
- 프레스는 부품 모양이 갈리면 일부를 쉬게 하고, 노동자들은 자재 대기나 순서 다툼으로 멈춤

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| SIMD 제어기·레인 | 하나의 제어기가 같은 명령을 여러 레인에 배포하며 레인 사용률이 처리량을 좌우함 |
| MIMD 코어 | 각 코어가 독립 명령을 실행하며 작업 불균형이 코어 유휴 시간을 결정함 |
| 메모리와 인터커넥트 | 두 구조 모두 데이터를 공급하고 교환하는 경로이며 병목이 생기기 쉬운 지점임 |
| 동기화 기법 | 배리어·락·메시지 전달이 결과 정합성과 코어 대기 시간을 결정함 |

> 요약: 작업 특성을 먼저 보고 구조를 선택한 뒤 실행과 동기화 비용을 함께 관리해야 함.

### 쉽게 이해하기 (학습용)
- 프레스를 돌리는 제어반(SIMD 제어기·레인), 각자 일하는 노동자들(MIMD 코어), 부품을 나르는 컨베이어(메모리·인터커넥트), 순서를 맞추는 신호등(동기화 기법)이 함께 있음

## Ⅵ. 실무 사례

1. 이미지 처리 커널은 데이터를 연속 배치하고 분기 마스크를 조정해 레인 사용률·분기 효율을 확인함
2. 멀티코어 웹 서버는 작업 크기와 락 범위를 조정하고 처리량·동기화 대기 시간을 확인함

### 쉽게 이해하기 (학습용)
- 사진 보정처럼 같은 필터를 모든 픽셀에 찍어내는 작업은 프레스 방식으로, 여러 손님 주문을 각자 처리하는 서버는 노동자 방식으로 다룸

## Ⅶ. 결론

- SIMD는 하나의 명령 흐름을 여러 레인에 공유해 반복 명령을 줄이고, MIMD는 처리 요소마다 독립 명령을 실행해 독립 태스크를 병렬 처리함
- 구조 선택은 코어 수가 아니라 데이터 규칙성과 태스크 독립성·분기 패턴·동기화 비용을 기준으로 판단해야 함

### 쉽게 이해하기 (학습용)
- 기계나 노동자 수가 아니라, 작업이 같은 틀의 반복인지 서로 다른 독립 작업인지를 보고 방식을 골라야 함
