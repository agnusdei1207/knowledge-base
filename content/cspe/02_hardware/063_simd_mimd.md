## Ⅰ. 개요
- **정의**: 하나의 명령어로 다수 데이터를 처리하는 SIMD와, 다수 명령어가 다수 데이터를 독립 처리하는 MIMD 아키텍처임
- **배경/필요성**: 데이터 병렬과 태스크 병렬의 구분이 워크로드별 최적 프로세서 선정에 핵심적임
- **비유**: SIMD는 체조 단체 연기(같은 동작, 다른 선수), MIMD는 오케스트라(다른 악기, 다른 악보)와 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 데이터 병렬과 태스크 병렬의 구조적 차이 | SIMD: 동일 명령 다수 데이터, MIMD: 독립 명령 독립 데이터 | Flynn 분류(062 참조) 전체 틀 속에서 위치 명시 필요 |

> 요약: SIMD는 데이터 병렬, MIMD는 태스크 병렬을 구현하는 두 가지 병렬 아키텍처 유형임

## Ⅱ. 구성요소
```text
  SIMD                              MIMD
  +------------+                    +------------+  +------------+
  | Controller | --Instruction-->   | Processor1 |  | Processor2 |
  +------------+                    | + Local    |  | + Local    |
       |                            | Memory     |  | Memory     |
       v                            +------------+  +------------+
  +----+----+----+                       |               |
  | PE | PE | PE |                       v               v
  +----+----+----+                  Interconnect Network
  (동일 연산, 다른 데이터)           (독립 연산, 독립 데이터)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| SIMD Controller | 단일 명령어를 발행하여 모든 PE에 동시 전달하는 제어 장치임 | 체조 감독이 구령을 내림 |
| Processing Element (PE) | SIMD에서 동일 명령을 각자의 데이터에 적용하는 연산 유닛임 | 구령에 맞춰 동작하는 각 선수 |
| MIMD Processor | 독립된 명령어 스트림을 가진 자율 프로세서로, 고유 프로그램 카운터를 보유함 | 개별 악보를 연주하는 각 연주자 |
| Interconnect Network | MIMD 프로세서 간 데이터 교환과 동기화를 수행하는 통신 경로임 | 연주자 간 호흡을 맞추는 지휘 신호 |

> 요약: SIMD는 중앙 컨트롤러+다수 PE, MIMD는 독립 프로세서+인터커넥트로 구성됨

## Ⅲ. 절차
```text
Workload Analysis --> Parallelism Mapping --> Execution --> Synchronization
       |                     |                   |                |
       v                     v                   v                v
  데이터/태스크          SIMD or MIMD         병렬 연산          결과 수집
  병렬성 식별            구조 매핑            수행               + 동기화
```
- 1단계: **Workload Analysis** — 대상 연산이 동일 연산의 반복(데이터 병렬)인지 이질 연산의 조합(태스크 병렬)인지 분석함
- 2단계: **Parallelism Mapping** — 데이터 병렬이면 SIMD, 태스크 병렬이면 MIMD 구조에 매핑함
- 3단계: **Execution** — SIMD는 컨트롤러가 단일 명령을 PE에 브로드캐스트하고, MIMD는 각 프로세서가 독립 실행함
- 4단계: **Synchronization** — SIMD는 락스텝으로 암묵적 동기화되고, MIMD는 배리어·메시지 패싱으로 명시적 동기화함

> 요약: 병렬성 분석 → 구조 매핑 → 병렬 실행 → 동기화의 4단계로 수행됨

## Ⅳ. 문제점
- **SIMD 분기 페널티**: 조건 분기 발생 시 일부 PE가 유휴 상태가 되어 활용률이 저하됨
- **MIMD 동기화 오버헤드**: 프로세서 간 동기화·통신 비용이 프로세서 수 증가에 따라 비선형적으로 증가함
- **프로그래밍 복잡성**: MIMD는 경쟁 조건·교착 상태 등 병렬 프로그래밍 난이도가 높아 개발 비용이 증가함

> 요약: SIMD의 분기 페널티, MIMD의 동기화 비용과 프로그래밍 복잡성이 주요 제약임

## Ⅴ. 개선방안
1. 단기: 프레디케이션(predication) 기법으로 SIMD 분기 페널티를 마스킹하여 PE 유휴 시간 감소
2. 중기: 하드웨어 기반 배리어·원자 연산 지원으로 MIMD 동기화 오버헤드를 축소
3. 장기: SPMD 프로그래밍 모델(OpenCL, SYCL)을 통해 SIMD/MIMD 추상화를 통합하여 프로그래밍 복잡성 완화

> 요약: 프레디케이션, 하드웨어 동기화, 통합 프로그래밍 모델로 각 문제를 단계적 해소함

## Ⅵ. 전망
- 발전 방향: GPU의 SIMT(Single Instruction Multiple Threads) 모델이 SIMD와 MIMD의 경계를 융합하는 방향으로 진화 중임
- 기술사적 판단: AI·HPC 워크로드에서 데이터 병렬(SIMD)과 태스크 병렬(MIMD)의 혼합 활용이 표준이 될 전망임
- 기술사 제언: 워크로드의 병렬 특성을 사전 분석하고, SIMD/MIMD/SIMT 중 적합한 실행 모델을 선정할 필요
