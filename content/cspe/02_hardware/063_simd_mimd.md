# 📖 【암기용】 개념 완전 이해

> 목적: SIMD와 MIMD가 플린의 분류(Flynn's Taxonomy)라는 더 큰 틀 안에서 어떤 자리를 차지하는지, 그리고 왜 하드웨어가 이 두 방식으로 병렬 처리를 나누어 구현하는지 처음부터 이해하게 만든다.

## 한눈에
- **개요**: SIMD와 MIMD는 **플린의 분류(Flynn's Taxonomy)** 중 병렬 컴퓨터를 가리키는 두 유형이다 — 명령어 스트림 수와 데이터 스트림 수의 조합으로 컴퓨터 구조를 4가지로 나눈 체계에서, "명령어 1개·데이터 여럿"이 SIMD, "명령어 여럿·데이터 여럿"이 MIMD다.
- **왜 필요한가**: 같은 연산을 수백만 번 반복하는 작업(영상 필터링, 행렬 곱)과, 서로 다른 작업을 동시에 처리해야 하는 상황(웹 서버의 동시 접속자 처리)은 요구되는 하드웨어 구조가 다르다. 하나의 제어 장치로 여러 데이터를 밀어붙일지, 제어 장치 자체를 여러 개 두어 독립적으로 돌릴지를 구분해야 자원을 낭비하지 않는다.
- **핵심 직관**: SIMD는 지휘자 1명이 손을 들면 오케스트라 전원이 같은 음을 동시에 연주하는 것이고, MIMD는 단원들이 각자 다른 악보를 들고 자기 파트를 알아서 연주하는 것이다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 표기/용어 | 의미 | 비유 |
|:---|:---|:---|
| 플린의 분류 (Flynn's Taxonomy) | 명령어 스트림 수 × 데이터 스트림 수로 컴퓨터 구조를 SISD·SIMD·MISD·MIMD 4가지로 나눈 1966년 분류 체계 | 병렬 컴퓨터를 부르는 이름표의 사전 |
| SISD | 명령어 1개, 데이터 1개 — 순차 처리하는 일반 단일 코어 | 요리사 1명이 재료 1개씩 순서대로 손질 |
| SIMD | 명령어 1개, 데이터 여럿 — 같은 연산을 여러 데이터에 동시 적용 | 지휘자 1명, 오케스트라 전원 같은 음 |
| MISD | 명령어 여럿, 데이터 1개 — 같은 데이터를 여러 방식으로 동시 검증(실사용 사례 희귀) | 재료 1개를 검사관 여럿이 각자 다른 기준으로 동시 검사 |
| MIMD | 명령어 여럿, 데이터 여럿 — 독립된 제어 장치들이 각자 다른 명령·데이터 처리 | 단원마다 다른 악보를 든 합주 |
| 제어 장치 (CU, Control Unit) | 명령어를 해석해 연산 장치에 지시를 내리는 부분 | 지휘자 |
| 처리 장치 (PU/ALU) | 실제 덧셈·곱셈 등을 수행하는 회로 | 연주자 |
| Lock-step | 모든 처리 장치가 같은 클럭에 같은 명령을 동시 수행하는 동기 방식(SIMD의 특징) | 전원이 같은 박자로 발맞춰 행진 |

- SIMD·MIMD는 대등한 대안이 아니라 **워크로드 성격(데이터 병렬 vs 작업 병렬)**에 따라 선택하는 상호 보완 관계다. 실제 CPU(MIMD)는 내부에 SIMD 실행 유닛을 함께 갖는 경우가 대부분이다(063_simd_mimd_processor에서 상세).

## 깊이 이해

### 플린의 분류가 나온 배경
- 1966년 스탠퍼드의 마이클 플린(Michael Flynn)이 "명령어를 몇 갈래로 흘려보내는가"와 "데이터를 몇 갈래로 흘려보내는가"를 각각 1개/여러 개로 나누어 2×2=4개 조합(SISD·SIMD·MISD·MIMD)을 제시했다. 지금까지도 병렬 아키텍처를 분류하는 표준 어휘로 쓰인다.
- 4개 중 실제로 널리 쓰이는 것은 SISD(전통적 단일 코어)·SIMD(벡터/GPU)·MIMD(멀티코어/클러스터) 셋이고, MISD는 극히 드물다(항공우주용 다중 검증 시스템 정도).

### SIMD의 동작 원리 — 수치로 확인
- 구조: 제어 장치(CU) 1개가 여러 연산 장치(PU)에 동일한 명령을 동시에 내린다. 예를 들어 AVX-512는 레지스터 폭이 512비트이므로, 32비트 정수 1개당 16개(512÷32)를 한 명령어로 동시에 처리한다.
- 효과: 100만 개 원소를 더하는 반복문을 스칼라(1개씩)로 처리하면 100만 번의 덧셈 명령이 필요하지만, 16-way SIMD로 처리하면 62,500번(100만÷16)의 명령으로 끝난다 — 명령어 인출·해석 횟수가 1/16로 줄어든다.
- 한계: 조건 분기(if-else)를 만나면 문제가 생긴다. 16개 레인 중 8개는 조건이 참, 8개는 거짓이면 CU는 명령을 1개만 내릴 수 있으므로, 참인 8개를 먼저 처리하는 동안 거짓인 8개는 놀고(Idle), 그다음 반대로 처리한다. 결과적으로 실질 처리 효율이 50%로 떨어진다.

### MIMD의 동작 원리 — 수치로 확인
- 구조: 제어 장치와 연산 장치의 쌍이 여러 개 독립적으로 존재한다. 24코어 CPU라면 24개의 독립된 CU-PU 쌍이 각자 다른 프로그램 카운터·다른 명령·다른 데이터를 갖는다.
- 효과: 24개의 서로 무관한 작업(예: 웹 요청 24건)을 동시에 처리할 수 있어 응답 지연(Latency)이 짧다.
- 한계: 여러 코어가 같은 메모리 주소를 동시에 읽고 쓰면 값이 꼬인다. 이를 막는 동기화(락, 세마포어)에 시간이 들고, 코어 수를 늘려도 동기화 대기 시간 때문에 성능이 코어 수만큼 정비례로 늘지 않는다(암달의 법칙과 연결).

### 왜 인프라 설계에서 구분이 중요한가
- 데이터 병렬 작업(이미지 1000만 픽셀에 같은 밝기 보정)에 MIMD(범용 멀티코어)를 쓰면, 코어마다 제어 로직을 따로 두는 오버헤드 때문에 SIMD 전용 회로보다 비효율적이다.
- 반대로 작업 병렬 상황(수만 명의 서로 다른 API 요청)에 SIMD를 쓰면 애초에 "같은 명령을 여럿에게"라는 전제가 성립하지 않아 처리 자체가 불가능하다.
- 그래서 실무에서는 그래픽/AI 연산은 SIMD(GPU), 범용 서버 로직은 MIMD(CPU)로 역할을 나눈다.

## 연결 개념
- 063_simd_mimd_processor — 같은 SIMD/MIMD를 프로세서 마이크로아키텍처(AVX, 워프 발산, 캐시 일관성) 관점에서 더 깊이 다룬 파일
- SIMT (Single Instruction, Multiple Threads) — GPU가 SIMD의 분기 문제를 완화하려고 고안한 변형
- 벡터 프로세서 — SIMD를 하드웨어로 구현한 고전적 형태(064에서 상세)
- 암달의 법칙(Amdahl's Law) — MIMD로 코어를 늘려도 순차 구간 때문에 성능이 무한정 늘지 않는 이유를 수식으로 설명

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: SIMD와 MIMD의 구조적 차이를 도식화하고, 병렬 처리 효율과 유연성 간의 트레이드오프를 논리적으로 설명한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: SIMD는 단일 제어로 다수 데이터를 동시 처리하는 효율 중심 구조이며, MIMD는 독립 제어로 다수 작업을 동시 처리하는 유연성 중심 구조이다.
> 2. **가치**: 대량 정형 데이터 연산(SIMD)과 복잡 독립 태스크 수행(MIMD)을 구분하여 시스템 처리량(Throughput)을 최적화한다.
> 3. **판단 포인트**: 데이터 간 독립성과 연산의 정형성 여부에 따라 하드웨어 가속기(SIMD) 또는 범용 서버(MIMD) 도입을 결정한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 병렬 아키텍처 비교 분석 역량 확인 | 구조 도식(CU-PU 관계), 처리 방식 차이 | 특징만 나열하고 "왜" 그런 차이가 발생하는지 생략 |
| 프로그래밍 및 운영 관점 이해 확인 | 데이터 병렬성 vs 작업 병렬성, 동기화 오버헤드 | 하드웨어 구조에만 매몰되어 소프트웨어적 난이도 간과 |
| 현대 시스템 적용 사례 제시 | AVX/GPU(SIMD) vs 멀티코어/클러스터(MIMD) | 구식 이론에 머물러 최신 명령어 셋(AVX-512 등) 누락 |

> 요약: 이 문제는 두 모델의 구조적 차이가 실제 성능과 프로그래밍 모델에 미치는 영향을 비교 설명해야 한다.

## Ⅰ. 개요 및 필요성

- 정의: 명령어와 데이터의 흐름 수에 따라 구분되는 병렬 컴퓨팅 아키텍처 모델
- 배경: 단일 스레드 성능 향상의 한계(Power Wall)로 인해 하드웨어 레벨의 병렬성 활용이 필수적
- 필요성: 용도에 맞는 병렬성(Data vs Task) 선택으로 하드웨어 자원 활용률과 에너지 효율성 극대화

---

## Ⅱ. 구조 및 구성요소

```text
[SIMD: Shared Control]           [MIMD: Independent Control]
      Instruction                      Inst1   Inst2   Inst3
           |                             |       |       |
      [Control Unit]                [CU1]   [CU2]   [CU3]
      /    |    \                    |       |       |
   [PU1] [PU2] [PU3]                [PU1]   [PU2]   [PU3]
     |     |     |                   |       |       |
   [D1]  [D2]  [D3]                [D1]    [D2]    [D3]
```

| 구성요소 | SIMD 역할 | MIMD 역할 |
|:---|:---|:---|
| 제어 유닛 (CU) | 1개가 모든 PU에 동일 명령 하달 | 각 PU마다 전용 CU가 독립 명령 하달 |
| 처리 유닛 (PU) | 동일 명령으로 서로 다른 데이터 연산 | 각자 다른 명령으로 각자 데이터 연산 |
| 메모리 (Memory) | 정렬된 벡터 데이터 공급 위주 | 독립적인 스택/힙 영역 관리 위주 |

> 요약: SIMD는 제어 로직을 공유하여 연산 밀도를 높이고, MIMD는 제어 로직을 분산하여 독립성을 확보한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
[SIMD Flow: Lock-step]
Fetch(Inst) -> Broadcast -> Parallel Execute(D1~Dn) -> Sync Store

[MIMD Flow: Asynchronous]
Thread1: Fetch -> Execute -> Store -> Sync/Wait
Thread2: Fetch -> Execute -> Store -> Sync/Wait
```

| 단계 | SIMD 처리 내용 | MIMD 처리 내용 |
|:---:|:---|:---|
| 1 | 단일 명령어 인출 및 해석 | 다수 명령어 독립 인출 및 해석 |
| 2 | 모든 연산 장치에 명령어 전송 | 각 연산 장치별 명령어 실행 |
| 3 | 동일 클럭 내 병렬 연산 (Lock-step) | 비동기적 각자 연산 (Asynchronous) |
| 4 | 결과 통합 및 메모리 쓰기 | 세마포어/뮤텍스 기반 결과 동기화 |

> 요약: SIMD는 모든 유닛이 발맞춰 움직이는 '동기적' 흐름이며, MIMD는 각자 움직이는 '비동기적' 흐름이다.

## Ⅳ. 특징

| 구분 | SIMD (Data Parallel) | MIMD (Task Parallel) |
|:---|:---|:---|:---|
| 제어 방식 | 동기식 (Lock-step) | 비동기식 (Asynchronous) |
| 효율성 | 높음 (적은 제어 오버헤드) | 낮음 (CU 중복 및 동기화 비용) |
| 유연성 | 낮음 (분기 시 성능 저하) | 높음 (다양한 작업 동시 수행) |
| 프로그래밍 | 컴파일러/라이브러리 의존 | OS 스케줄링/스레드 관리 의존 |

> 요약: SIMD는 대량의 단순 반복 작업에, MIMD는 복잡하고 다양한 작업의 병렬 처리에 유리하다.

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 데이터 병렬성 (SIMD) | 작업 병렬성 (MIMD) | 선택 기준 |
|:---|:---|:---|:---|
| 입성 (Granularity) | 미세 입성 (Word 단위) | 거대 입성 (Task 단위) | 데이터 처리 단위 크기 |
| 확장성 | 매우 우수 (만 단위 코어) | 우수 (수천 단위 노드) | 제어 복잡도 감수 능력 |
| 하드웨어 설계 | 처리량(Throughput) 중심 | 응답성(Latency) 중심 | 주요 성능 지표(KPI) |

> 요약: 동일 연산이 반복되는 행렬 처리 등은 SIMD, 독립된 유저 요청 처리는 MIMD가 적합하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 분기 불일치 (SIMD) | If-Else 등 조건문 발생 | Predicated Execution, Masking | 연산 유효성 (Effective FLOPs) |
| 동기화 지연 (MIMD) | 공유 자원 경합 (Lock) | Lock-free, 메시지 패싱 | CPU Wait Time / Lock Wait |
| 데이터 전송 병목 | 연산 속도 대비 낮은 대역폭 | HBM 도입, 캐시 최적화 | 메모리 대역폭 점유율 |

> 요약: SIMD는 코드의 정형화를 통해, MIMD는 정교한 스케줄링과 자원 격리를 통해 리스크를 관리한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 병렬화 효율 | 자원 증가 대비 선형 성능 향상 | 가속도 측정 (Speedup / N) |
| 명령어 대역폭 | 초당 실행 명령어 수 (MIPS/GFLOPS) | 성능 카운터 (PMU) 측정 |
| 에너지 효율 | 전력 대비 성능 (Performance per Watt) | 소비 전력 모니터링 |

> 요약: 도입 효과는 가속도와 에너지 효율성 지표를 통해 정량적으로 검증한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 영상/이미지 처리: 픽셀 단위의 동일 연산이 반복되는 필터링, 인코딩 작업에 SIMD(AVX, GPU)를 적용하여 처리 속도 10배 이상 향상
2. 실시간 트래픽 처리: 수만 명의 동시 접속자가 각자 다른 요청을 보내는 웹 서버 환경에 MIMD(멀티코어, K8s 클러스터)를 적용하여 서비스 가용성 확보
3. 하이브리드 설계: 최신 CPU 아키텍처에서 MIMD 코어 내부에 SIMD 유닛(벡터 엔진)을 배치하여 범용성과 특수 연산 성능을 동시 만족

**결론 (2줄):**
- 기술사 판단: 향후 병렬 처리는 SIMD의 고효율과 MIMD의 고유연성을 결합한 이기종 컴퓨팅(Heterogeneous Computing)이 주류가 될 것이며, 이를 연결하는 인터커넥트 성능이 핵심이 될 것임
- 향후 방향: CXL 등을 통해 메모리 벽을 허물고, 소프트웨어 레벨에서 SIMD/MIMD를 자동 구분하여 할당하는 컴파일러 기술이 발전할 것으로 전망됨
