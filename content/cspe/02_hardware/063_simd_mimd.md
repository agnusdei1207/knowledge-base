# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: SIMD와 MIMD는 플린 분류(Flynn's Taxonomy)의 핵심으로, 각각 데이터 수준 병렬성(DLP)과 스레드 수준 병렬성(TLP)을 극대화한 **현대 병렬 프로세서 아키텍처의 양대 산맥**이다.
- **왜 필요한가**: 그래픽 처리나 AI 연산처럼 '단순 반복 배열 연산'이 많은 워크로드와, 웹 서버처럼 '각기 다른 독립적 요청'을 처리해야 하는 워크로드는 요구하는 병렬성 종류가 다르기 때문에 맞춤형 하드웨어가 필요하다.
- **핵심 직관**: SIMD는 군대에서 소대장이 "전진!" 하면 모든 병사가 동시에 한 걸음 내딛는 집단행동 방식이고, MIMD는 각 팀원이 각자의 업무 매뉴얼을 들고 알아서 일하는 사무실 방식이다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| SIMD (Single Instruction, Multiple Data) | 1개의 명령어로 다수의 데이터를 한꺼번에 처리하는 프로세서 구조 | "도장 하나로 여러 문서에 한 번에 찍기" (GPU, AVX) |
| MIMD (Multiple Instruction, Multiple Data) | 다수의 프로세서가 각기 다른 명령어와 데이터를 독립적으로 처리하는 구조 | "여러 직원이 각자 다른 서류 결재하기" (멀티코어 CPU) |
| DLP (Data Level Parallelism) | 동일한 연산이 큰 배열 구조의 여러 데이터 요소에 동시 적용되는 병렬성 | 벡터 덧셈, 픽셀 렌더링 |
| TLP (Thread Level Parallelism) | 서로 독립적인 흐름(스레드)이 동시에 병렬로 실행되는 특성 | 다중 클라이언트의 HTTP 요청 처리 |

## 깊이 이해
- **배경·문제의식**: CPU 클럭 속도를 높이는 방식(단일 코어 성능 향상)이 전력 벽(Power Wall)에 부딪히면서, 병렬 처리를 통해 성능을 높이는 방향으로 전환되었다. 이때 연산의 특성에 따라 '명령어를 통일해 연산기만 늘릴지(SIMD)', '제어부까지 통째로 늘릴지(MIMD)' 선택이 필요해졌다.
- **작동 원리**:
  - **SIMD**: 1개의 CU(Control Unit)가 여러 개의 ALU(연산기)를 제어한다. 벡터 A와 B를 더할 때, `A[0]+B[0]`부터 `A[3]+B[3]`까지 4개의 연산기가 1클럭에 동시에 더블 수행한다. 단, 조건문(If/Else)에서 분기가 엇갈리면 일부 ALU는 쉬어야 하는 마스킹(Masking) 비효율이 발생한다.
  - **MIMD**: 코어마다 독립된 CU와 ALU, 캐시를 가진다. 1번 코어는 영상 압축을, 2번 코어는 웹 브라우저를 렌더링한다. 매우 유연하지만, 데이터를 공유할 때 캐시 일관성 프로토콜(MESI 등)로 인한 통신 오버헤드가 발생한다.
- **비유**: SIMD는 관광버스(명령어 1개에 승객 40명 이동), MIMD는 택시 40대(명령어 40개에 승객 각 1명씩 각자 목적지 이동).
- **구체 예시**:
  - SIMD: x86 CPU 내부의 AVX-512 명령어(512비트 레지스터 하나로 32비트 정수 16개를 한 번에 연산), 엔비디아 GPU 아키텍처.
  - MIMD: 인텔 코어 i9, AMD 라이젠 등 현대의 범용 멀티코어 CPU, 데이터센터 서버 클러스터.

## 연결 개념
- 플린 분류 (Flynn's Taxonomy) — SIMD와 MIMD를 정의하는 상위 이론 (062 참조)
- GPU 아키텍처 (SIMT) — SIMD를 스레드 개념과 결합해 유연하게 만든 확장 모델
- 캐시 일관성 프로토콜 — MIMD 환경에서 필연적으로 발생하는 데이터 동기화 문제 해결책

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: SIMD는 단일 제어 흐름으로 다중 데이터 배열을 동시 처리하여 DLP(데이터 병렬성)를, MIMD는 다중 제어 흐름으로 독립 태스크를 비동기 처리하여 TLP(스레드 병렬성)를 극대화한 프로세서 구조다.
> 2. **가치**: SIMD는 하드웨어 제어 유닛을 최소화하여 면적당 연산량(MAC 밀도)을 높이고, MIMD는 복잡한 조건 분기와 범용 비즈니스 로직 처리의 유연성을 보장한다.
> 3. **판단 포인트**: 클라우드·AI 환경에서는 어느 하나만으로 최적화가 불가능하며, 노드 간은 MIMD로, 코어 내부는 SIMD 확장 명령어(AVX)나 GPU(SIMT)로 구성하는 계층적 하이브리드 아키텍처를 설계해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 아키텍처별 병렬성(DLP vs TLP) 차이 이해 | SIMD-데이터/배열 특화, MIMD-스레드/독립제어 특화 매핑 | 구조만 그리고 목표하는 병렬성 종류(DLP/TLP) 누락 |
| 장단점 및 트레이드오프 분석 역량 | SIMD 제어 분기 오버헤드, MIMD 캐시 일관성/동기화 비용 | 어느 한쪽이 무조건 우수하다고 단정하는 서술 |
| 현대 시스템 적용 방식 인지 | CPU 멀티코어 내 AVX, GPGPU 모델, 분산 클러스터 하이브리드 | SIMD/MIMD가 완전히 분리된 별도 칩으로만 존재한다고 오해 |

> 요약: SIMD와 MIMD는 대립 개념이 아니라 단위 면적당 연산량(Throughput)과 제어 유연성(Latency/Branch)을 상호 보완하는 핵심 툴셋이다.

## Ⅰ. 개요 및 필요성

- 개요: 플린 분류법에 따라 데이터 병렬성(DLP) 중심의 단일 명령어 다중 데이터 처리 구조(SIMD)와 스레드 병렬성(TLP) 중심의 다중 명령어 독립 제어 구조(MIMD)
- 배경: 단일 코어의 클럭 향상에 따른 전력 장벽(Power Wall) 도달로, 용도에 맞는 병렬화로 성능 한계 돌파 요구
- 필요성: AI 파라미터 계산, 그래픽 등 규칙적 대량 연산과 웹 트랜잭션 등 불규칙적 범용 로직 연산을 칩 면적 효율과 전력 범위 내에서 최적 처리하기 위해 두 아키텍처의 분리 및 통합 필수

---

## Ⅱ. 구조 및 구성요소

```text
[SIMD 아키텍처]                        [MIMD 아키텍처]
 CU (단일 제어)                         CU 1       CU 2       CU N
  |-> 브로드캐스트                        |          |          |
 [ ALU 1 ][ ALU 2 ][ ALU N ]          [ALU 1]    [ALU 2]    [ALU N]
  | Data 1 | Data 2 | Data N           | D 1      | D 2      | D N
```

| 구성요소 비교 | SIMD (데이터 병렬성) | MIMD (스레드 병렬성) |
|:---|:---|:---|
| 제어 유닛 (CU) | 단일 (Single) — 모든 연산기가 같은 명령 수신 | 다수 (Multiple) — 코어별 독립 제어 |
| 연산 유닛 (ALU) | 배열/벡터 형태 다수 집적 (고밀도) | 스칼라 및 슈퍼스칼라 파이프라인 |
| 데이터 메모리 | 병렬 로드를 위한 인터리빙/벡터 메모리 | 코어별 독립 L1/L2 캐시 및 공유 L3 |
| 핵심 활용 기술 | GPU, AVX/NEON 명령어 셋 확장 | 멀티코어 CPU, SMP, 멀티소켓 서버 |

> 요약: SIMD는 CU 비중을 줄여 ALU 집적도를 높인 구조고, MIMD는 완결된 CU+ALU+Cache 세트(코어)를 다수 배치한 구조다.

---

## Ⅲ. 동작원리 및 흐름도

```text
[SIMD 동작: 벡터 덧셈]                 [MIMD 동작: 분산 트랜잭션]
명령 1: Load Vector A (4개 요소 동시)  코어 1: DB 조회 (Inst A -> Data A)
명령 2: Load Vector B (4개 요소 동시)  코어 2: 로그 쓰기 (Inst B -> Data B)
명령 3: Add Vector A, B (4개 ALU 동시) 코어 3: 통신 암호화 (Inst C -> Data C)
```

- SIMD 1단계 [단일 인출]: 1개의 제어장치가 벡터 덧셈 명령어 인출 및 디코딩
- SIMD 2단계 [다중 실행]: 다수의 연산 유닛이 각자의 데이터 레인(Lane)에서 벡터 요소를 동시 연산 (동기화 불필요)
- MIMD 1단계 [독립 인출]: N개의 코어가 각자의 PC(Program Counter)로 서로 다른 프로그램/스레드 인출
- MIMD 2단계 [비동기 실행]: 각 코어가 각자 속도로 독립 처리하며, 필요시 락(Lock)이나 캐시 일관성 메시지로 통신

> 요약: SIMD는 락스텝(Lock-step)으로 동기화되어 움직이며 제어 오버헤드가 없고, MIMD는 비동기적으로 움직이며 스레드 간 상태 동기화가 필요하다.

---

## Ⅳ. 특징 (트레이드오프)

- [전력/면적 효율]: SIMD는 칩 면적의 대부분을 ALU에 할당하여 MAC 연산 전력비(TOPS/W)가 압도적으로 높으나, MIMD는 캐시와 제어부 비중이 커 연산 효율이 낮다.
- [분기문(Branch) 제약]: SIMD는 조건문(If-Else) 발생 시 조건이 다른 데이터 레인은 연산을 멈추고 대기해야 하는 마스킹(Masking/Divergence) 오버헤드가 크다.
- [캐시 일관성 트래픽]: MIMD는 코어 수가 늘어날수록 스누핑(Snooping) 프로토콜 등에 의한 공유 버스 트래픽이 기하급수적으로 증가해 스케일업 한계가 존재한다.

> 요약: SIMD는 분기문 없는 단순 수학 연산의 극한 효율을, MIMD는 캐시 일관성 오버헤드를 지불하더라도 높은 범용성을 담보한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | SIMD 기반 가속기 (GPU) | MIMD 기반 서버 (SMP) | 설계 및 적용 기준 |
|:---|:---|:---|:---|
| 프로그래밍 | 명시적 벡터화, CUDA/OpenCL | 멀티스레드, Pthread, OpenMP | 컴파일러 자동 벡터화 지원 여부 판단 |
| 오버헤드 요인 | 분기 이탈 (Divergence Penalty) | 컨텍스트 스위칭, 락 경합 | 코드 내 조건문 비율 vs 공유 자원 경합률 |
| 스케일링 | 수천 개 코어 집적 용이 | 수십~수백 개 코어 집적 한계 | 대규모 데이터 처리량 vs 단일 지연시간 요건 |

> 요약: 분기가 적고 데이터 배열이 방대한 딥러닝/렌더링은 SIMD로 오프로딩하고, 복잡한 상태 천이와 사용자 제어는 MIMD에 남겨둔다.

**리스크·대응:**
- MIMD의 메모리 병목 및 False Sharing: 다중 코어가 동일 캐시라인 접근 시 무효화 트래픽 폭증 → 데이터 패딩(Padding) 및 스레드 로컬 메모리 활용 (지표: 캐시라인 무효화율 5% 이하)
- SIMD의 메모리 로드 비효율: 연속되지 않은 데이터(Gather/Scatter) 접근 시 병렬 로드 불가 → SOA(Struct of Arrays) 방식의 메모리 데이터 레이아웃 재설계 (지표: 메모리 대역폭 활용률 80% 이상)

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. CPU 내 SIMD 명령어 확장 (AVX-512): MIMD 기반 인텔/AMD 프로세서 내부에 512비트 폭의 SIMD 레지스터 및 연산기를 내장하여 암호화·영상 디코딩 시 소프트웨어 벡터화로 8~16배 성능 향상
2. 이기종 컴퓨팅 아키텍처 설계: 호스트 통제 및 스케줄링은 범용 MIMD(CPU)가 담당하고, PCIe로 연결된 극단적 SIMD 장치(GPU/NPU)로 데이터 병렬 연산을 오프로딩하는 클라우드 인스턴스 구성
3. SPMD (Single Program Multiple Data) 패턴 적용: 프로그래밍 논리 복잡성을 낮추기 위해, MIMD 클러스터(MPI 환경) 위에서 사실상 동일한 프로그램을 데이터만 쪼개서 실행하는 하이브리드 소프트웨어 모델 채택

**결론 (2줄):**
- 기술사 판단: 클럭 주파수 상승이 멈춘 현재, 시스템 아키텍트는 맹목적 코어 수 확장이 아닌 애플리케이션의 DLP/TLP 특성을 식별하여 SIMD/MIMD 할당을 결정해야 정답이다.
- 향후 방향: SIMD의 경직성을 극복하기 위해 엔비디아의 SIMT(명령어는 단일하되 스레드별 개별 제어 허용) 모델처럼 두 아키텍처의 장점을 결합하는 방향으로 구조가 진화할 것이다.
