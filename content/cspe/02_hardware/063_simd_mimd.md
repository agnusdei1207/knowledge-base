## 미리 알고가기

- SIMD는 같은 명령을 여러 데이터에 동시에 적용하는 구조임
- MIMD는 여러 처리기가 서로 다른 명령을 독립적으로 수행하는 구조임
- 선택 기준은 데이터 규칙성, 분기 패턴, 동기화 비용임

## Ⅰ. 개요

- **정의/개념**: SIMD와 MIMD는 병렬 처리를 어떤 모양으로 구현하는지 보여 주는 구조로, SIMD는 하나의 명령을 여러 데이터에 뿌리고 MIMD는 여러 코어가 서로 다른 명령 흐름을 병렬로 수행하는 방식임
- **배경/필요성**: 행렬 연산처럼 규칙적인 작업과 웹 서버 요청처럼 독립적인 작업은 병렬화 방식이 다르므로, 데이터 특성과 제어 특성에 맞는 구조 선택이 필요함

## Ⅱ. 특징

- SIMD는 제어 오버헤드가 작아 규칙적인 데이터 병렬에서 높은 처리량을 얻기 좋음
- MIMD는 분기와 태스크 독립성이 큰 작업을 자연스럽게 처리할 수 있음
- SIMD는 분기 발산과 비연속 메모리 접근에 약하고, MIMD는 동기화와 락 경합이 병목이 되기 쉬움
- 두 구조 모두 코어 수보다 메모리 대역폭과 작업 분할 방식이 실제 성능을 좌우함

## Ⅲ. 종류 및 비교

| 판단 기준 | SIMD | MIMD |
|:---|:---|:---|
| 제어 구조 | 하나의 명령 흐름이 여러 lane에 동시에 적용됨 | 각 코어가 독립 명령 흐름과 상태를 가짐 |
| 잘 맞는 작업 | 벡터, 영상, 행렬처럼 반복 규칙이 뚜렷한 작업에 맞음 | 서버 처리, 시뮬레이션, 태스크 병렬에 맞음 |
| 주요 병목 | 분기 발산, lane 유휴, 불규칙 메모리 접근이 문제임 | 락 경합, barrier 대기, 부하 불균형이 문제임 |
| 대표 구현 | 벡터 유닛, GPU 내부 실행 모델에 가깝음 | 멀티코어 CPU, 멀티프로세서, 클러스터에 가깝음 |

> 요약: SIMD는 같은 연산을 많이 뿌리는 구조이고, MIMD는 다른 작업을 독립적으로 나누는 구조임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| SIMD 제어기와 lane | 하나의 제어기가 같은 명령을 여러 lane에 배포하며 lane 활용률이 성능을 좌우함 |
| MIMD 코어 | 각 코어가 독립적으로 명령을 가져와 실행하며 작업 분할 품질이 중요함 |
| 메모리와 인터커넥트 | 두 구조 모두 데이터를 공급하고 교환하는 경로이며 병목이 생기기 쉬운 지점임 |
| 동기화 기법 | barrier, lock, message passing이 결과 정합성과 대기 시간을 결정함 |

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 작업 특성 분석 | --> | SIMD/MIMD 선택 | --> | 병렬 실행      | --> | 결과 병합/동기화 |
+-------------+     +-------------+     +-------------+     +-------------+
```

> 요약: 작업 특성을 먼저 보고 구조를 고른 뒤, 실행과 동기화 비용을 함께 관리해야 함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 데이터/분기 분석 | --> | 구조 선택      | --> | lane 또는 코어 실행 | --> | 병합과 대기 제어 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **데이터와 분기 분석**: 규칙적 반복인지 독립 작업인지 확인함
2. **구조 선택**: 같은 연산 반복이면 SIMD를, 독립 태스크면 MIMD를 우선 검토함
3. **lane 또는 코어 실행**: 선택한 구조에 맞춰 병렬 실행함
4. **병합과 대기 제어**: reduction, barrier, message passing으로 결과를 정리함

## Ⅵ. 실무 적용 및 유의점

1. 이미지 처리나 AI 커널처럼 반복 규칙이 뚜렷한 작업은 SIMD가 유리하지만 분기와 메모리 접근이 흐트러지면 유휴 실행선이 늘어나므로 데이터 정렬과 조건부 실행을 함께 적용하고 실행선 활용률과 분기 효율과 메모리 대기 시간으로 확인함
2. 멀티코어 웹 서버나 시뮬레이션처럼 독립 태스크가 많은 작업은 MIMD가 맞지만 락과 동기화 장벽이 많아지면 병렬 이득이 줄어드므로 작업 분할과 락 없는 구조를 함께 검토하고 처리량과 동기화 대기 시간과 가속 비율로 확인함

## Ⅶ. 결론

SIMD와 MIMD의 차이는 코어 수가 아니라 병렬성의 모양에 있으므로, 데이터 규칙성과 동기화 비용을 먼저 보고 구조를 골라야 함.
