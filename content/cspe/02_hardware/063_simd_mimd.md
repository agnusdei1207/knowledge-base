# 📖 【암기용】 개념 완전 이해

> 목적: SIMD·MIMD 프로세서를 처음 봐도 실제 하드웨어에서 어떻게 구현되는지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: Flynn 분류의 실제 구현체로, SIMD는 단일 명령어로 다중 데이터를 동시 처리하고 MIMD는 다중 프로세서가 각자 다른 명령어·데이터를 동시 처리하는 구조
- **왜 필요한가**: 규칙적인 대량 데이터 연산(이미지·행렬)과 이질적인 다중 작업(웹 서버 다중 요청)은 요구되는 병렬화 방식이 다르므로, 워크로드 특성에 맞는 프로세서 구조 선택이 필요하다.
- **핵심 직관**: SIMD는 하나의 도장으로 여러 문서에 동시에 찍는 것이고, MIMD는 여러 직원이 각자 다른 서류를 각자 다른 방식으로 처리하는 것이다.

## 깊이 이해
- **배경·문제의식**: 스칼라 프로세서는 데이터 하나당 명령어 하나를 소비해 대량 반복 연산에서 명령어 인출·해독 오버헤드가 누적된다.
- **작동 원리**: SIMD 프로세서는 하나의 제어장치가 명령어를 해독하고 그 결과를 여러 실행 유닛(lane)에 동시에 broadcast해 서로 다른 데이터에 같은 연산을 적용한다.
- **작동 원리**: MIMD 프로세서는 각 코어 또는 노드가 독립적인 제어장치와 프로그램 카운터를 가져 서로 다른 명령어 스트림을 동시에 실행한다.
- **작동 원리**: MIMD는 메모리 접근 방식에 따라 공유 메모리 MIMD(SMP·NUMA)와 분산 메모리 MIMD(클러스터·MPP)로 다시 나뉜다.
- **비유**: SIMD는 공장 컨베이어에서 같은 프레스 기계가 여러 부품에 동시에 같은 모양을 찍어내는 것이다.
- **비유**: MIMD는 여러 독립 작업대에서 각 작업자가 자기 도면과 재료로 각자 다른 제품을 동시에 만드는 것이다.
- **구체 예시**: SIMD 예시 — x86 AVX-512 명령어 하나가 512비트 레지스터의 16개 32비트 값을 한 번에 더한다.
- **구체 예시**: MIMD 예시 — 64코어 서버에서 각 코어가 서로 다른 컨테이너의 서로 다른 프로세스를 동시에 실행한다.
- **흔한 오해·주의점**: SIMD는 분기(if-else)가 있는 코드에서 비효율적이다. 조건이 lane마다 다르면 마스킹으로 양쪽 분기를 모두 실행 후 결과만 선택해 실질 처리량이 줄어든다.
- **흔한 오해·주의점**: MIMD가 항상 SIMD보다 빠른 것은 아니다. 규칙적 데이터 병렬 작업에서는 SIMD가 명령어 오버헤드를 줄여 단위 전력당 처리량이 더 높다.

## 연결 개념
- Flynn 분류 — SIMD·MIMD가 속한 상위 분류 체계
- 벡터 프로세서 — SIMD 원리를 가변 길이로 확장한 구현
- GPU SIMT — SIMD와 MIMD 요소를 결합한 하이브리드 실행 모델

# 📝 【답안용】 시험 답안 템플릿

> 핵심: SIMD·MIMD 답안은 실행 유닛 구조 차이, 대표 하드웨어, 워크로드 적합성을 함께 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: SIMD는 단일 제어장치가 다중 데이터에 동일 연산을 적용하고, MIMD는 다중 제어장치가 각자 다른 명령어·데이터를 처리하는 프로세서 구조다.
> 2. **가치**: SIMD는 데이터 병렬 워크로드의 처리량을 높이고, MIMD는 이질적 태스크를 동시에 독립 처리해 범용성을 확보한다.
> 3. **판단 포인트**: 워크로드의 규칙성과 분기 빈도, 메모리 공유 여부가 SIMD·MIMD 선택 기준이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 실행 구조 차이 확인 | 제어장치 개수, lane 구조 | 두 구조를 명령어 개수 차이로만 설명 |
| 대표 하드웨어 이해 확인 | AVX·GPU(SIMD), 멀티코어·클러스터(MIMD) | 사례 없이 정의만 서술 |
| 워크로드 적합성 판단 확인 | 데이터 병렬 vs 태스크 병렬 | 항상 MIMD가 우수하다는 식의 단정 |

> 요약: 이 문제는 정의 나열보다 워크로드 특성에 따른 SIMD·MIMD 선택 근거를 보여야 한다.

## Ⅰ. 개요 및 필요성

- 정의: SIMD는 단일 명령어로 다중 데이터를 동시 처리, MIMD는 다중 명령어로 다중 데이터를 독립 처리하는 프로세서 구조
- 배경: 스칼라 프로세서의 명령어 인출·해독 오버헤드 누적 문제와, 이질적 다중 작업 동시 처리 요구가 각각 SIMD·MIMD 발전을 이끔
- 필요성: 이미지·행렬 연산처럼 규칙적인 대량 데이터 처리와, 서버 다중 요청처럼 이질적 작업 처리는 서로 다른 병렬 구조 선택이 필요함

---

## Ⅱ. 구조 및 구성요소

```text
SIMD: Control Unit -> Decode 1회 -> Lane1/Lane2/.../LaneN 동시 실행
MIMD: Core1(PC1,Decode1) / Core2(PC2,Decode2) / ... 각자 독립 실행
  -> Shared Memory(SMP/NUMA) 또는 Distributed Memory(Cluster)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| SIMD Control Unit | 명령어 1회 해독 후 전체 lane에 broadcast | AVX-512, ARM NEON/SVE |
| SIMD Lane | 동일 연산을 서로 다른 데이터에 적용하는 실행 유닛 | 분기 시 마스킹으로 효율 저하 |
| MIMD Core | 독립 PC·Decode로 서로 다른 명령어 실행 | 멀티코어 CPU |
| Shared Memory MIMD | 코어 간 메모리 주소 공간 공유 | SMP, NUMA |
| Distributed Memory MIMD | 노드 간 메시지 패싱으로 통신 | 클러스터, MPP |

> 요약: SIMD는 단일 제어·다중 실행 유닛, MIMD는 다중 제어·독립 실행 유닛으로 병렬성을 구현한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
SIMD: 명령어 인출/해독 1회 -> 다중 lane에 동일 연산 전파 -> 결과 벡터 반환
MIMD: 각 코어가 독립 인출/해독 -> 각자 다른 연산 수행 -> 동기화 지점에서 결과 취합
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | SIMD는 명령어 1회 해독 후 lane 수만큼 broadcast | lane 활용률 |
| 2 | MIMD는 코어별 독립 명령어 인출·해독 | 코어별 명령어 처리율 |
| 3 | SIMD는 마스킹으로 분기 조건 처리 | 마스킹 오버헤드 |
| 4 | MIMD는 동기화 지점(barrier·lock)에서 결과 취합 | 동기화 대기 시간 |

> 요약: SIMD는 단일 명령어를 여러 데이터에 병렬 적용하고, MIMD는 독립 실행 후 동기화 지점에서 결과를 모은다.

---

## Ⅳ. 특징

| 구분 | SIMD | MIMD | 수치·표준 포인트 |
|:---|:---|:---|:---|
| 처리 기준 | 단일 명령어, 다중 데이터 | 다중 명령어, 다중 데이터 | AVX-512 16-lane, 멀티코어 N개 |
| 정책 범위 | 규칙적 데이터 병렬 연산 | 이질적 태스크 병렬 처리 | 벡터 연산, 스레드 스케줄링 |
| 지연 요인 | 조건 분기 시 마스킹 오버헤드 | 코어 간 동기화·락 경합 | lane 유휴율, 락 대기시간 |
| 확장 방식 | lane 폭 확대(256->512bit) | 코어·노드 수 증가 | SIMD 폭, 코어 수 |

> 요약: SIMD는 lane 폭 확장으로, MIMD는 코어·노드 수 확장으로 성능을 높인다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | SIMD | MIMD | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 단일 제어 + 다중 lane | 다중 제어 + 다중 코어/노드 | 작업 동질성 여부 |
| 비용/성능 | 단위 전력당 처리량 높음(규칙적 작업) | 이질적 작업 유연성 높음 | 워크로드 분기 빈도 |
| 운영/위험 | 분기 많으면 lane 유휴로 효율 저하 | 동기화·통신 오버헤드 증가 | 분기율, 통신 지연 |

> 요약: 분기 없는 규칙적 대량 연산은 SIMD, 분기 많고 이질적인 작업은 MIMD를 선택한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| SIMD 효율 저하 | 조건 분기로 마스킹 발생 | 분기 없는 데이터 배치, 조건부 연산 최소화 | lane 활용률 |
| MIMD 동기화 병목 | 락 경합, barrier 대기 | lock-free 자료구조, 메시지 패싱 도입 | 락 대기 시간 |
| 확장 한계 | NUMA 원격 접근 지연 | 데이터 지역성 배치, NUMA-aware 스케줄링 | 원격 메모리 접근 비율 |

> 요약: SIMD는 분기 관리, MIMD는 동기화·NUMA 지연 관리가 핵심 리스크다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| SIMD 효율 | lane 활용률 목표치 이상 | 프로파일러, 벡터화 리포트 |
| MIMD 확장성 | 코어 수 증가 대비 처리량 선형 근접 | 스케일링 벤치마크 |
| 자원 사용률 | CPU·메모리 사용률 임계치 이하 | 모니터링 지표 |

> 요약: 도입 후 성공 여부는 SIMD lane 활용률과 MIMD 스케일링 선형성으로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 이미지·행렬·신호처리처럼 규칙적 데이터 병렬 연산은 SIMD 명령어(AVX, NEON)로 벡터화함
2. 웹 서버·마이크로서비스처럼 이질적 다중 요청 처리는 MIMD 멀티코어·클러스터로 스케줄링함
3. 분기가 많은 벡터화 후보 코드는 마스킹 오버헤드를 프로파일링해 SIMD 적용 여부를 재판단함

**결론 (2줄):**
- 기술사 판단: 워크로드 규칙성과 분기율을 기준으로 SIMD와 MIMD를 선택하거나 병행 적용함
- 향후 방향: GPU SIMT처럼 SIMD·MIMD 요소를 결합한 하이브리드 가속기 구조로 발전함
