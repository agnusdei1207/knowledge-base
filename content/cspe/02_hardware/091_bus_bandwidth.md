## 미리 알고가기

- 대역폭은 단위 시간당 전송 가능한 최대 데이터량임
- 전송률은 프로토콜 오버헤드와 대기시간을 반영한 실제 유효 데이터량임
- 계산 시 bit와 Byte와 Hz와 MT/s와 단방향 및 양방향을 구분해야 함

## Ⅰ. 개요

- **정의/개념**: 버스 대역폭·전송률 계산은 버스 폭과 전송 주파수와 전송 배수와 채널 수를 기준으로 이론 최대 전송량과 실제 유효 처리량을 산정해 시스템 병목을 판단하는 성능 분석 방법임
- **배경/필요성**: CPU와 메모리와 PCIe 장치 성능이 높아져도 연결 버스가 필요한 데이터를 공급하지 못하면 전체 처리량이 제한되므로, 인터페이스 선택과 병목 분석에는 스펙 수치보다 정확한 대역폭 계산이 필요함

## Ⅱ. 특징

- 계산 기준이 버스 폭과 클럭뿐 아니라 DDR 여부와 레인 수와 방향성까지 함께 반영됨
- 이론 대역폭과 유효 전송률을 구분해야 실제 성능 기대치를 올바르게 해석할 수 있음
- 프로토콜 인코딩과 헤더와 흐름 제어와 재전송이 유효 처리량을 감소시킴
- 메모리와 I/O와 스토리지 인터페이스의 병목을 공통 수치 체계로 비교할 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 이론 대역폭 | 유효 전송률 |
|:---|:---|:---|
| 계산 기준 | 폭, 전송 속도, 채널 수 중심 | 이론치에 효율과 대기시간을 반영 |
| 활용 목적 | 인터페이스 상한 비교 | 실제 병목 판단과 용량 계획 |
| 오차 요인 | 단위 변환 실수 | 패킷 크기와 혼잡도 변동 |
| 대표 의미 | 스펙 상 최고치 | 운영 중 체감 처리량 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Bus Width | 한 번의 전송에서 이동하는 비트 수를 뜻하며 병렬 처리량 상한을 결정함 |
| Transfer Rate | 클럭과 DDR 여부와 MT/s가 초당 전송 기회를 결정해 시간당 데이터량 계산의 기준이 됨 |
| Channel or Lane | 독립 경로 수가 늘수록 총 대역폭이 커지지만 상위 링크 공유 구조에서는 병목이 다시 생길 수 있음 |
| Protocol Overhead | 인코딩과 헤더와 흐름 제어와 재전송이 실제 페이로드 비율을 떨어뜨려 유효 전송률을 결정함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 단위 정리      | --> | 이론치 계산    | --> | 효율 보정      | --> | 병목 비교      |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **단위 정리**: bit와 Byte와 Hz와 MT/s와 단방향 및 양방향을 구분함
2. **이론치 계산**: 버스 폭과 전송 속도와 채널 수로 최대 전송량을 산출함
3. **효율 보정**: 인코딩과 헤더와 대기시간을 반영해 유효 전송률을 계산함
4. **병목 비교**: 장치 요구 대역폭과 실측치를 대조해 제한 구간을 찾음

## Ⅵ. 문제점 및 해결 방안

1. 문제: bit와 Byte와 MHz와 MT/s를 혼동하면 계산 결과가 크게 왜곡되어 장비 선정이 잘못될 수 있음
   - 해결방안: 계산식마다 단위를 명시한 표준 템플릿을 사용하고 unit mismatch count와 review defect rate로 검증함
2. 문제: 이론 대역폭만 보고 설계하면 프로토콜 오버헤드와 대기시간이 빠져 실제 처리량 부족이 발생할 수 있음
   - 해결방안: payload efficiency와 p99 latency를 함께 반영한 유효 전송률 모델을 사용하고 measured throughput gap으로 검증함
3. 문제: 특정 버스만 증설하면 메모리 컨트롤러나 DMA 엔진이 새 병목이 되어 전체 성능 개선이 제한될 수 있음
   - 해결방안: end-to-end 경로별 utilization 분석을 수행하고 component bottleneck ratio와 saturation point로 검증함

## Ⅶ. 적용 사례

- GPU 서버 슬롯 설계에서는 PCIe 세대와 레인 수를 계산해 장치별 요구 대역폭을 비교하고, oversubscription ratio와 p99 transfer latency로 결과를 확인함
- 메모리 채널 증설 검토에서는 채널 수 증가에 따른 이론 대역폭과 실측 처리량을 대조하고, bandwidth scaling efficiency와 memory stall rate로 결과를 확인함
- 스토리지 성능 분석에서는 NVMe 링크 상한과 실제 I/O 처리량을 비교하고, payload efficiency와 measured throughput으로 결과를 확인함

## Ⅷ. 결론

버스 대역폭 평가는 스펙 수치 자체보다 단위 일관성, 오버헤드 반영, 경로 전체 병목 비교를 함께 수행할 때 설계 판단력이 생김.
