# 📖 【암기용】 개념 완전 이해

> 목적: 데이터 센터가 얼마나 튼튼하고 안전한지 나누는 글로벌 기준인 'Tier' 등급을 이해하고, 등급별 차이를 파악하게 만든다.

## 한눈에
- **개요**: 데이터 센터 Tier 등급은 데이터센터의 **가용성(Availability)** 과 **이중화(Redundancy)** 수준을 기준으로 나눈 국제 표준 등급 체계(TIA-942 등)로, 1등급부터 4등급까지 정전·장애 상황에서 서비스가 얼마나 버티는지를 나타낸다.
- **왜 필요한가**: "우리 센터는 안전해요"라는 말보다 "우리 센터는 Tier 4 인증을 받았어요"라는 말이 훨씬 신뢰를 준다. 등급에 따라 정전 시 견디는 시간, 장비 점검 중에도 서비스가 유지되는지 등이 명확히 갈린다.
- **핵심 직관**: 
  - Tier 1: 원룸 (정전 나면 끝, 수리하려면 전기 꺼야 함)
  - Tier 4: 요새 (모든 선이 두 개씩, 하나 터져도 아무 일 없음)

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 가용성 (Availability) | 1년 중 서비스가 멈추지 않고 유지되는 시간의 비율(%) — 이 개념 전체가 등급을 매기는 기준 | 학교 출석률 |
| 이중화 (Redundancy) | 장비나 경로를 예비로 더 두어 하나가 고장 나도 버티게 하는 설계 | 예비 타이어 |
| N / N+1 / 2N | N=딱 필요한 만큼, N+1=필요량+예비 1대, 2N=필요한 세트 전체를 통째로 2벌 | 필요 3대 / 예비 포함 4대 / 통째로 2세트인 6대 |
| 경로 (Path) | 전력·냉각수가 장비까지 전달되는 배선·배관 통로 | 수도관 라인 |
| 동시 유지보수 (Concurrent Maintainability) | 서비스를 끄지 않고도 장비 점검·교체가 가능한 능력 — Tier 3의 기준 | 비행 중 정비 |
| 결함 허용 (Fault Tolerant) | 예상치 못한 고장이 나도 자동으로 반대편이 즉시 대체하는 능력 — Tier 4의 기준 | 엔진 하나 꺼져도 계속 나는 비행기 |
| SPOF (Single Point of Failure, 단일 장애점) | 여기 하나가 끊기면 시스템 전체가 죽는 지점 | 시스템의 아킬레스건 |

## 깊이 이해

### 배경·문제의식
- 서비스의 중요도에 따라 필요한 안정성 수준이 다르다. 모든 센터를 최고급(Tier 4)으로 짓기엔 돈이 너무 많이 들고, 그렇다고 대충 짓기엔 위험하다. 그래서 객관적으로 비교 가능한 '표준 등급'이 필요해졌다.

### N/N+1/2N을 수치로 이해 — 등급을 가르는 실제 설계 차이
- 냉각기(CRAC) 3대가 필요한 시설이라고 하자. Tier 1은 딱 3대(N)만 두어 1대만 고장 나도 냉각 용량이 부족해진다. Tier 2는 3대+예비 1대(N+1=4대)를 두어 1대 고장까지는 버틴다. Tier 4는 3대 세트를 통째로 2벌(2N=6대), 그것도 물리적으로 분리된 전력 계통에 두어 한쪽 계통 전체가 화재로 전소해도 반대쪽 3대만으로 정상 가동한다.

### 등급별 가용성 수치와 핵심 차이
- **Tier 1 (기본)**: 이중화 없음(N). 부품 하나 고장 나거나 정기 점검하면 서비스 중단. 가용성 99.671%(연간 정지 약 28.8시간).
- **Tier 2 (부분 이중화)**: 예비 발전기나 냉각기는 있음(N+1). 하지만 전선(경로)은 하나라서 그 전선을 수리할 때는 꺼야 함. 가용성 99.741%(연간 정지 약 22.0시간).
- **Tier 3 (동시 유지보수 가능)**: 경로가 2개라 하나를 막고 점검해도 반대편으로 서비스가 유지된다. 단, 평소엔 경로 하나만 상시 사용(Active-Standby). 가용성 99.982%(연간 정지 약 1.6시간).
- **Tier 4 (결함 허용, Fault Tolerant)**: 모든 시스템이 완전히 독립된 2세트(2N)로 두 경로 모두 항상 가동(Active-Active). 한쪽이 통째로 날아가도 서비스에 지장 없음. 가용성 99.995%(연간 정지 약 26분).

### Tier 3과 Tier 4를 가르는 진짜 기준 — 계획된 점검 vs 예기치 못한 사고
- Tier 3의 "동시 유지보수"는 **미리 계획한** 점검·교체 작업 중에는 서비스가 안 끊긴다는 뜻이다. 하지만 포클레인이 갑자기 전선을 끊거나 발전기실에 불이 나는 등 **예상치 못한 단일 고장(SPOF)** 이 터지면 Tier 3도 다운될 수 있다.
- Tier 4는 이런 계획되지 않은 사고까지 방어한다. 경로 2개가 항상 동시에 살아 있고(Active-Active) 물리적으로 완전히 분리되어 있어, 한쪽이 갑자기 죽어도 반대쪽이 즉시(0초 지연) 전체 부하를 떠안는다.

### 비유와 구체 예시
- Tier 1은 외발자전거(넘어지면 끝), Tier 3은 바퀴가 4개인 자동차(타이어 하나 펑크 나도 교체하며 갈 수 있음), Tier 4는 엔진이 두 개인 비행기(엔진 하나 꺼져도 계속 날아감)에 비유된다.
- 일반 기업의 전산실은 Tier 1~2 수준이고, 네이버·카카오·금융권 데이터 센터는 Tier 3~4 수준으로 짓는다.

## 연결 개념
- 가용성 (Availability) — 99.9...% 숫자로 나타내는 서비스 유지 시간
- BCP/DR — 재해 시 서비스 연속성을 유지하기 위한 상위 계획
- PUE — 등급이 안정성 지표라면, PUE는 효율성 지표

## Ⅰ. 개요 및 필요성

- 정의: 데이터 센터의 전력, 냉각, 통신 등 인프라의 가용성과 유지보수 능력을 기준으로 분류한 등급 체계 (TIA-942 표준)
- 배경: 비즈니스 연속성(BCP)에 대한 요구 증대 및 센터 간 객관적인 안정성 비교를 위한 표준 인증 필요
- 필요성: 서비스 중요도에 따른 구축 비용 최적화 및 장애 발생 시 피해 규모를 예측하기 위한 정량적 기준 제공

## Ⅱ. 구조 및 구성요소

```text
[Data Center Tier Architecture Concept]
Tier 1/2: Single Path (SPOF 존재)
  - Utility -> [UPS] -> [PDU] -> Server

Tier 3: Multiple Path (Active-Passive)
  - Path A: Utility -> [UPS] -> [PDU] -> Server (Active)
  - Path B: Utility -> [ATS] -> [PDU] -> Server (Standby/Maintenable)

Tier 4: Multiple Path (Active-Active, Fault Tolerant)
  - Path A: Utility A -> [UPS A] -> [PDU A] -> Server
  - Path B: Utility B -> [UPS B] -> [PDU B] -> Server
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 구성 장치 (Component) | 전력, 냉각, 발전기 등 실제 부품 | N+1, N+2 등의 중복성 확보 |
| 배분 경로 (Path) | 전력 및 냉각수가 전달되는 통로 | 경로 이중화 여부가 등급의 결정적 요소 |
| 동시 유지보수 | 운영 중 시스템 정지 없이 수리 가능 여부 | Tier 3 이상의 필수 요건 |
| 결함 허용 | 장애 발생 시 자동 복구 및 영향 차단 | Tier 4의 핵심 철학 |

> 요약: 장비의 개별 이중화를 넘어 공급 경로의 독립성 확보 수준이 등급을 결정한다.

## Ⅲ. 동작원리 및 흐름도

```text
[Maintenance Flow: Tier 3 vs Tier 2]
Tier 2: Stop Service -> Maintenance -> Start Service (Downtime 발생)
Tier 3: Switch to Path B -> Maintenance Path A -> Back to Path A (No Downtime)

[Failure Flow: Tier 4]
Failure Path A -> Auto Detection -> Instant Switch to Path B -> No Impact
```

| 단계 | 처리 내용 | 확인 기준 |
|:---:|:---|:---|
| 1 | 장애 또는 점검 상황 발생 | 시스템 감시 및 경보 |
| 2 | 예비 장비 또는 예비 경로로 절체 (Switching) | 무순단/무중단 여부 |
| 3 | 상시 운영 환경의 유지보수 수행 | 운영 중 작업 가능 여부 (Tier 3+) |
| 4 | 장애 복구 및 정상 계통으로 원복 | 데이터 유실 및 서비스 영향 0 |

> 요약: 상위 등급일수록 점검과 장애 상황이 사용자 서비스에 미치는 영향을 물리적으로 격리하여 동작한다.

## Ⅳ. 특징

| 구분 | Tier 1 (Basic) | Tier 2 (Redundant) | Tier 3 (Maintenable) | Tier 4 (Fault Tolerant) |
|:---|:---|:---|:---|:---|
| 가용성 | 99.671% | 99.741% | 99.982% | 99.995% |
| 연간 장애 시간 | 28.8시간 | 22.0시간 | 1.6시간 | 0.4시간 (26분) |
| 배분 경로 | 단일 경로 | 단일 경로 | 다중 경로 (1 Active) | 다중 경로 (2 Active) |
| 이중화 수준 | N (없음) | N+1 | N+1 | 2(N+1) 또는 S+S |
| 특징 | 최저 비용 | 부분적 이중화 | 중단 없는 유지보수 | 최강의 결함 허용 |

> 요약: Tier 3은 "수리 중에도 안 꺼짐", Tier 4는 "망가져도 안 꺼짐"으로 요약 가능하다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | Tier 3 (동시 유지보수) | Tier 4 (결함 허용) | 선택 기준 |
|:---|:---|:---|:---|
| 설계 철학 | 점검 중 가용성 확보 | 모든 장애 시 가용성 확보 | 서비스 중단 리스크 감내 수준 |
| 비용 구조 | 표준적인 대규모 센터 수준 | 매우 고가 (장비 및 부지 2배) | ROI 및 비즈니스 임팩트 |
| 리스크 대응 | 계획된 작업(Work) 대응 | 계획되지 않은 사고(Incident) 대응 | 정전 및 화재 등 재난 대비 수준 |

> 요약: 일반 클라우드 서비스는 Tier 3으로 충분하며, 금융 결제나 국가 기간망은 Tier 4가 필수적이다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 가용성 수치 맹신 | 설계는 Tier 4이나 운영 미숙으로 장애 | 운영 숙련도 향상, 매뉴얼 표준화 | 실제 가동 시간 (Uptime) |
| 과잉 설계 (Over-Spec) | 필요 이상의 등급으로 인한 TCO 낭비 | 워크로드별 등급 차등 적용 | 가용성당 비용 (Cost per 9s) |
| 경로 교차 (Crossover) | 이중화된 경로가 한 지점에서 만남 | 물리적 이격 거리 확보, 관로 분리 | SPOF 유무 분석 (Single Point) |

> 요약: 물리적 등급(Tier)만큼이나 운영 관리 체계(Standard Operating Procedure)가 가용성 유지에 중요하다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 동시 유지보수성 | 핵심 계통 차단 시 서비스 유지 확인 | 실운영 환경 절체 테스트 |
| 전력/냉각 용량 | N+1 부하 시 목표 온도 유지 | 부하 테스트 (Load Bank Test) |
| 장애 복구 시간 | RTO 0분, RPO 0분 달성 | 모의 장애 훈련 결과 분석 |

> 요약: 도입 효과는 실제 점검 및 장애 상황 발생 시 서비스에 미치는 영향도로 검증한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 중요도별 인프라 배치: 핵심 DB 및 결제 시스템은 Tier 4 센터에, 일반 웹 서비스 및 배치 작업은 Tier 3 이하 센터에 분산 배치하여 비용 효율화
2. 동시 유지보수 훈련: 6개월마다 전력 계통의 한 축을 인위적으로 차단하고 반대축으로 서비스가 유지되는지 점검하여 Tier 3 요건 상시 확인
3. 경로 독립성 검증: 설계 도면상 독립된 경로가 실제 시공 과정에서 동일한 케이블 트레이를 사용하거나 인접해 있는지 실사하여 물리적 SPOF 제거

**결론 (2줄):**
- 기술사 판단: 인프라의 Tier 등급은 안정성을 위한 물리적 토대이나, 최근에는 멀티 리전(Multi-Region) 구성을 통해 소프트웨어 레벨에서 하드웨어 등급의 한계를 보완하는 방향으로 발전함
- 향후 방향: 탄소 중립 요구에 따라 고가용성을 유지하면서도 에너지 효율(PUE)을 동시에 만족하는 Green Tier-Standard 정립이 가속화될 것으로 전망됨
