## 미리 알고가기

- 펌웨어는 장치 초기화와 부팅과 하드웨어 제어를 담당하는 저수준 코드임
- UEFI와 BMC와 Boot ROM과 OTA 경로는 대표적인 펌웨어 공격면임
- Secure Boot는 승인된 부트 체인만 실행하게 하는 검증 체계임

## Ⅰ. 개요

- **정의/개념**: 펌웨어 보안 취약점은 부팅과 초기화와 장치 제어와 업데이트를 담당하는 저수준 코드와 설정에 결함이 있어 공격자가 높은 권한을 얻거나 장치에 지속적으로 남을 수 있게 만드는 보안 문제임
- **배경/필요성**: 펌웨어는 운영체제보다 먼저 실행되고 하드웨어에 가까운 권한을 가지므로 이 계층이 침해되면 상위 보안 기능이 쉽게 우회돼, 일반 소프트웨어보다 먼저 통제해야 함

## Ⅱ. 특징

- 부팅 전 계층이라 탐지와 포렌식이 어렵고 침해가 오래 숨기 쉬움
- 업데이트 실패가 곧 부팅 불가나 현장 장애로 이어질 수 있음
- 디버그 포트 노출과 서명 검증 누락과 하드코딩 비밀이 자주 문제됨
- 공급망과 장치 수명주기가 길어 취약 버전이 오래 남기 쉬움

## Ⅲ. 종류 및 비교

| 판단 기준 | 애플리케이션 취약점 | 펌웨어 취약점 |
|:---|:---|:---|
| 실행 위치 | 운영체제와 응용 계층에서 주로 나타남 | 부트 체인과 장치 제어 계층에서 나타남 |
| 공격 영향 | 계정 탈취나 서비스 장애에 머무는 경우가 많음 | 부팅 장악과 영구 지속성 확보로 이어지기 쉬움 |
| 수정 방식 | 배포와 패치가 비교적 단순함 | 장치 호환성과 복구 절차까지 함께 관리해야 함 |
| 핵심 대응 | 권한 분리와 신속한 패치가 중요함 | Secure Boot와 서명 업데이트와 디버그 잠금이 중요함 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 부트 체인 | ROM과 부트로더와 장치 펌웨어가 초기 신뢰 경계를 이루며 검증 누락 시 전체 보안이 흔들림 |
| 업데이트 경로 | OTA와 서비스 포트와 저장 매체 경로가 안전하지 않으면 변조 이미지가 유입될 수 있음 |
| 비밀·키 저장소 | 하드코딩 비밀과 평문 키는 침해 후 장기간 악용되는 출발점이 됨 |
| 관리·디버그 인터페이스 | JTAG와 UART와 BMC는 유지보수 통로이면서 동시에 가장 위험한 공격면이 됨 |

```text
+-------------+     +-------------+     +-------------+     +-------------+
```

## Ⅴ. 원리 및 절차 흐름도

1. **자산 식별**: 부트로더와 BMC와 디버그 포트와 배포 경로를 목록화함
2. **취약점 점검**: 서명 검증과 키 저장과 버전 관리와 공개 취약점을 확인함
3. **보호 정책 적용**: Secure Boot와 서명 업데이트와 접근 통제를 설정함
4. **안전 업데이트 운영**: 원격 배포와 롤백 차단과 자산 추적을 함께 운영함

## Ⅵ. 실무 적용 및 유의점

1. 서버와 네트워크 장비처럼 UEFI와 BMC가 함께 있는 환경은 운영체제 점검만으로는 높은 권한 공격면을 놓치기 쉬우므로 펌웨어 구성 목록과 정기 자산 점검을 함께 운영하고 미관리 펌웨어 수와 패치 소요 시간과 부팅 무결성 통과율로 확인함
2. IoT나 차량 ECU처럼 OTA를 쓰는 장치는 서명 검증과 복구 경로가 약하면 변조 이미지나 실패 업데이트로 현장 장애가 날 수 있으므로 서명된 업데이트와 A/B 복구 절차를 같이 두고 비서명 이미지 차단률과 업데이트 성공률과 복구 성공률로 확인함

## Ⅶ. 결론

펌웨어 보안의 핵심은 코드 취약점 자체보다 부트 체인과 업데이트 경로와 디버그 접근을 먼저 통제하는 데 있음.
