## 미리 알고가기

- 펌웨어는 장치 초기화, 부팅, 하드웨어 제어를 담당하는 저수준 코드임
- UEFI, BMC, Boot ROM, OTA 경로는 대표적인 펌웨어 공격면임
- BMC(Baseboard Management Controller)는 서버 하드웨어를 원격으로 관리하는 별도 프로세서임
- Secure Boot는 승인된 부트 체인만 실행하게 하는 검증 체계임

## 작성 근거(검토용)

- 펌웨어 보안은 부트 체인, 업데이트 경로, 비밀 저장소, 디버그 인터페이스를 핵심 축으로 설명함
- 비교표는 애플리케이션과 펌웨어 취약점의 실행 위치, 공격 영향, 대응 통제를 대비함
- 실무 판단은 미관리 펌웨어 수·패치 소요 시간과 업데이트·복구 성공률로 검증함

## Ⅰ. 개요

- **정의/개념**: 펌웨어 보안 취약점은 부팅·초기화·장치 제어·업데이트 코드의 결함으로 공격자가 펌웨어 권한이나 재부팅 후 지속성을 얻는 보안 문제임
- **배경/필요성**: 운영체제보다 먼저 실행되는 코드의 변조를 방지하기 위해 부트 체인과 펌웨어 업데이트 경로의 통제가 필요함

## Ⅱ. 특징

- 운영체제보다 먼저 실행돼 OS 기반 탐지·포렌식에서 누락될 수 있음
- 업데이트 실패가 곧 부팅 불가나 현장 장애로 이어질 수 있음
- 디버그 포트 노출, 서명 검증 누락, 하드코딩 비밀이 자주 문제됨
- 공급망과 장치 수명주기가 길어 취약 버전이 오래 남기 쉬움

## Ⅲ. 종류 및 비교

| 판단 기준 | 애플리케이션 취약점 | 펌웨어 취약점 |
|:---|:---|:---|
| 실행 위치 | 운영체제와 응용 계층에서 주로 나타남 | 부트 체인과 장치 제어 계층에서 나타남 |
| 공격 영향 | 응용 권한 범위의 계정·데이터·서비스에 영향을 줌 | 부팅 코드·장치 제어 권한과 재부팅 후 지속성에 영향을 줌 |
| 대응 통제 | 권한 분리와 애플리케이션 패치를 적용함 | Secure Boot·서명 업데이트·디버그 잠금을 적용하고 이미지 호환성·복구 절차를 검증함 |

> 요약: 펌웨어 취약점은 부트 체인·장치 제어 계층에 영향을 주므로 서명 업데이트와 디버그 잠금이 필요함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 부트 체인 | ROM, 부트로더, 장치 펌웨어가 초기 신뢰 경계를 이루며 검증 누락 시 전체 보안이 흔들림 |
| 업데이트 경로 | OTA와 서비스 포트와 저장 매체 경로가 안전하지 않으면 변조 이미지가 유입될 수 있음 |
| 비밀·키 저장소 | 하드코딩 비밀과 평문 키는 침해 후 장기간 악용되는 출발점이 됨 |
| 관리·디버그 인터페이스 | JTAG·UART·BMC 노출 시 메모리 접근, 콘솔 명령, 원격 관리 권한이 공격 경로가 됨 |

> 요약: 펌웨어 공격면은 부트 체인·업데이트 경로·키 저장소·디버그 인터페이스에서 형성됨.

## Ⅴ. 원리 및 절차 흐름도

1. **자산 식별**: 부트로더, BMC, 디버그 포트, 배포 경로를 목록화함
2. **취약점 점검**: 서명 검증, 키 저장, 버전 관리, 공개 취약점을 확인함
3. **보호 정책 적용**: Secure Boot, 서명 업데이트, 접근 통제를 설정함
4. **안전 업데이트 운영**: 원격 배포, 롤백 차단, 자산 추적을 함께 운영함

> 요약: 펌웨어 자산과 배포 경로를 식별하고 서명 검증·접근 통제를 적용하며 업데이트를 안전하게 운영함.

## Ⅵ. 실무 사례

1. 서버 BMC는 펌웨어 자산 목록과 서명 검증을 운영하고 미관리 펌웨어 수·패치 소요 시간을 확인함
2. IoT 장치는 서명 업데이트와 A/B 복구를 적용하고 업데이트 성공률·복구 성공률을 확인함

## Ⅶ. 결론

- 펌웨어 보안은 부트 체인의 코드·키·버전을 검증하고 업데이트·디버그 경로를 장치 수명주기 동안 통제해야 함
