## Ⅰ. 개요
- **정의**: 하드웨어에 내장된 펌웨어의 무결성과 기밀성을 보장하는 보안 기법
- **배경/필요성**: 펌웨어는 OS보다 낮은 권한 수준에서 동작하므로, 변조 시 상위 소프트웨어 보안 체계 전체가 무력화됨
- **비유**: 건물의 기초 콘크리트에 독을 섞으면 모든 층이 오염되듯, 펌웨어 변조는 시스템 전체를 위협함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 부트 체인 신뢰 구조 이해 | Secure Boot, Measured Boot 차이 | Root of Trust 개념 누락 시 감점 |

> 요약: 펌웨어는 시스템 최하위 계층이므로 변조 방지가 전체 보안의 전제 조건임

## Ⅱ. 구성요소
```text
+------------------+
| Application      |
+------------------+
        |
+------------------+
| OS Kernel        |
+------------------+
        |
+------------------+
| Bootloader       |
+------------------+
        |
+------------------+
| Firmware (UEFI)  |
+------------------+
        |
+------------------+
| Root of Trust    |
+------------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Root of Trust | 변경 불가능한 하드웨어 기반 신뢰 시작점 | 건물 기초의 검증 마크 |
| Secure Boot | 부팅 단계마다 서명을 검증하여 변조 코드 실행 차단 | 출입문마다 신분증 확인 |
| Measured Boot | 각 부팅 단계의 해시를 TPM에 기록하여 사후 검증 가능하게 함 | CCTV 녹화 후 감사 |
| Firmware Update Engine | 서명된 업데이트만 수용하는 펌웨어 갱신 모듈 | 봉인된 택배만 수령하는 경비실 |
| TPM (Trusted Platform Module) | 해시·키 저장 전용 보안 칩 (082 참조) | 금고 속 열쇠 보관함 |

> 요약: Root of Trust에서 시작해 부팅 체인 전체를 서명·해시로 검증하는 계층 구조임

## Ⅲ. 절차
```text
Power On --> ROM 코드 실행 --> 1차 서명 검증
  --> Bootloader 로드 --> 2차 서명 검증
    --> OS Kernel 로드 --> 3차 서명 검증
      --> 정상 부팅 완료 / 검증 실패 시 부팅 차단
```
- 1단계: ROM에 저장된 Root of Trust 코드가 Bootloader 이미지의 디지털 서명을 검증함
- 2단계: Bootloader가 OS 커널 이미지의 서명을 검증하고, 해시 값을 TPM PCR에 기록함
- 3단계: OS 커널이 드라이버·모듈의 서명을 검증하여 무결성 확인 후 로드함
- 4단계: 원격 검증 서버가 TPM에 저장된 PCR 값을 조회하여 부팅 체인 전체의 무결성을 사후 확인함

> 요약: 전원 인가부터 OS 로드까지 각 단계에서 서명을 검증하는 Chain of Trust 절차임

## Ⅳ. 문제점
- 롤백 공격: 구버전 펌웨어 재설치를 차단하는 버전 관리 부재 — 패치된 취약점이 재노출됨
- 공급망 변조: 제조·유통 과정에서 펌웨어에 백도어 삽입 가능 — 출하 전 검증 체계 미흡
- 업데이트 지연: 펌웨어 업데이트 시 재부팅 필수 — 가용성 요구가 높은 환경에서 패치 적용이 지연됨

> 요약: 롤백, 공급망 변조, 업데이트 지연이 펌웨어 보안의 주요 위협임

## Ⅴ. 개선방안
1. 단기: 안티롤백 카운터(Anti-Rollback Counter)를 OTP 퓨즈에 기록하여 구버전 복원 차단
2. 중기: SBOM(Software Bill of Materials) 기반 공급망 투명성 확보 및 제조 단계 서명 검증 의무화
3. 장기: A/B 파티션 기반 무중단 펌웨어 업데이트(Seamless Update) 적용으로 가용성 유지

> 요약: 안티롤백, 공급망 SBOM, 무중단 업데이트로 펌웨어 보안 취약점 해소 가능함

## Ⅵ. 전망
- 발전 방향: NIST SP 800-193 기반 플랫폼 펌웨어 복원력(Resiliency) 표준 채택 확대
- 기술사적 판단: 하드웨어 Root of Trust와 원격 증명(Remote Attestation) 결합이 표준 아키텍처로 정착 중임
- 기술사 제언: 펌웨어 보안은 Zero Trust 아키텍처의 최하위 계층으로, 설계 단계부터 Secure-by-Design 원칙 적용 필요
