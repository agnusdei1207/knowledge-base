## 미리 알고가기

- 펌웨어는 장치 초기화, 부팅, 하드웨어 제어를 담당하는 저수준 코드임
- UEFI, BMC, Boot ROM, OTA 경로는 대표적인 펌웨어 공격면임
- Secure Boot는 승인된 부트 체인만 실행하게 하는 검증 체계임

## Ⅰ. 개요

- **정의/개념**: 펌웨어 보안 취약점은 부팅, 초기화, 장치 제어, 업데이트 코드의 결함으로 공격자가 높은 권한이나 장기 지속성을 얻는 보안 문제임
- **배경/필요성**: 펌웨어는 운영체제보다 먼저 실행되고 하드웨어 권한에 가까우므로 이 계층이 침해되면 상위 보안 기능이 쉽게 우회되어 우선 통제해야 함

## Ⅱ. 특징

- 부팅 전 계층이라 탐지와 포렌식이 어렵고 침해가 오래 숨기 쉬움
- 업데이트 실패가 곧 부팅 불가나 현장 장애로 이어질 수 있음
- 디버그 포트 노출, 서명 검증 누락, 하드코딩 비밀이 자주 문제됨
- 공급망과 장치 수명주기가 길어 취약 버전이 오래 남기 쉬움

## Ⅲ. 종류 및 비교

| 판단 기준 | 애플리케이션 취약점 | 펌웨어 취약점 |
|:---|:---|:---|
| 실행 위치 | 운영체제와 응용 계층에서 주로 나타남 | 부트 체인과 장치 제어 계층에서 나타남 |
| 공격 영향 | 계정 탈취나 서비스 장애에 머무는 경우가 많음 | 부팅 장악과 영구 지속성 확보로 이어지기 쉬움 |
| 수정 방식 | 애플리케이션 패키지를 배포·교체함 | 장치별 이미지 호환성·서명·실패 복구 절차를 검증함 |
| 핵심 대응 | 권한 분리와 신속한 패치가 중요함 | Secure Boot, 서명 업데이트, 디버그 잠금이 중요함 |

> 요약: 펌웨어 취약점은 실행 위치가 낮아 수정보다 부트 체인 검증과 업데이트 통제가 먼저 필요함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 부트 체인 | ROM, 부트로더, 장치 펌웨어가 초기 신뢰 경계를 이루며 검증 누락 시 전체 보안이 흔들림 |
| 업데이트 경로 | OTA와 서비스 포트와 저장 매체 경로가 안전하지 않으면 변조 이미지가 유입될 수 있음 |
| 비밀·키 저장소 | 하드코딩 비밀과 평문 키는 침해 후 장기간 악용되는 출발점이 됨 |
| 관리·디버그 인터페이스 | JTAG·UART·BMC 노출 시 메모리 접근, 콘솔 명령, 원격 관리 권한이 공격 경로가 됨 |

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 자산 식별      | --> | 취약점 점검    | --> | 보호 정책 적용  | --> | 안전 업데이트 운영 |
+-------------+     +-------------+     +-------------+     +-------------+
```

> 요약: 자산 식별, 취약점 점검, 보호 정책, 안전 업데이트가 이어져야 펌웨어 공격면을 통제할 수 있음.

## Ⅴ. 원리 및 절차 흐름도

1. **자산 식별**: 부트로더, BMC, 디버그 포트, 배포 경로를 목록화함
2. **취약점 점검**: 서명 검증, 키 저장, 버전 관리, 공개 취약점을 확인함
3. **보호 정책 적용**: Secure Boot, 서명 업데이트, 접근 통제를 설정함
4. **안전 업데이트 운영**: 원격 배포, 롤백 차단, 자산 추적을 함께 운영함

> 요약: 펌웨어 보안은 숨은 자산을 찾고 검증 정책과 안전 업데이트를 계속 운영하는 절차임.

## Ⅵ. 실무 적용 및 유의점

1. UEFI와 BMC가 있는 서버·네트워크 장비는 운영체제 점검만으로 공격면을 놓치기 쉬우므로 펌웨어 목록과 정기 점검을 운영하고 미관리 펌웨어 수, 패치 소요 시간, 부팅 무결성 통과율로 확인함
2. OTA 기반 IoT·차량 ECU는 서명 검증과 복구 경로가 약하면 변조 이미지가 현장 장애로 이어지므로 서명 업데이트와 A/B 복구를 두고 비서명 이미지 차단률, 업데이트 성공률, 복구 성공률로 확인함

## Ⅶ. 결론

펌웨어 보안의 핵심은 코드 취약점 자체보다 부트 체인과 업데이트 경로와 디버그 접근을 먼저 통제하는 데 있음.

## 작성 근거(검토용)

- 펌웨어 보안은 부트 체인, 업데이트 경로, 디버그 인터페이스, 장기 지속성을 핵심 판단축으로 선정함
- 비교표는 애플리케이션 취약점과 펌웨어 취약점의 실행 위치, 공격 영향, 수정 방식을 대비함
- 실무 판단은 미관리 펌웨어 수, 패치 소요 시간, 부팅 무결성 통과율, 복구 성공률로 검증 가능하게 작성함
