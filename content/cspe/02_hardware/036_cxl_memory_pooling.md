## Ⅰ. 개요
- **정의**: CXL 인터커넥트를 통해 다수 호스트가 공유 메모리 자원을 동적으로 할당·반환하는 기술임
- **배경/필요성**: 서버별 DRAM 고정 장착 방식은 유휴 메모리 낭비와 과부하 시 부족 문제를 동시에 발생시키므로, 풀 단위 공유로 활용률을 높일 필요가 있음
- **비유**: 각 사무실에 개별 프린터를 두는 대신, 공용 인쇄실을 만들어 필요할 때만 프린터를 배정받는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| CXL 프로토콜 계층과 메모리 풀링 동작 원리 이해 | CXL.mem 프로토콜, Type 3 디바이스, 동적 할당 메커니즘 | CXL 1.1/2.0/3.0 간 풀링 지원 범위 차이 혼동 주의 |

> 요약: CXL 메모리 풀링은 공유 메모리 자원의 동적 배분으로 DRAM 활용률을 극대화하는 기술임

## Ⅱ. 구성요소
```text
Host CPU 1 --+                         +-- Memory Device A
             |   +------------------+  |
Host CPU 2 --+---| CXL Switch/FM   |--+-- Memory Device B
             |   +------------------+  |
Host CPU 3 --+                         +-- Memory Device C
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| CXL Type 3 Device | 호스트에 메모리만 제공하는 CXL 디바이스, HDM(Host-managed Device Memory) 영역 보유 | 공용 인쇄실의 프린터 한 대 |
| CXL Switch | 다수 호스트와 다수 메모리 디바이스를 연결하는 PCIe 기반 패브릭 스위치 | 공용 인쇄실의 배전반 |
| Fabric Manager (FM) | 메모리 영역을 호스트에 동적 할당·회수하는 관리 소프트웨어 | 인쇄실 관리자 |
| CXL.mem 프로토콜 | 호스트-디바이스 간 load/store 수준 메모리 접근을 지원하는 트랜잭션 계층 | 프린터와 PC를 잇는 전용 케이블 |
| HDM (Host-managed Device Memory) | 호스트 물리 주소 공간에 매핑되는 디바이스 측 메모리 영역 | 프린터에 장착된 용지함 |

> 요약: CXL 스위치와 FM이 Type 3 디바이스의 HDM 영역을 호스트에 동적 매핑하여 풀링을 구현함

## Ⅲ. 절차
```text
Host 요청 --> FM 수신 --> HDM 영역 할당 --> 주소 매핑 --> 메모리 접근
    |                                                        |
    +------------------ 반환 요청 시 회수 <------------------+
```
- 1단계: 호스트가 FM에 메모리 용량 할당을 요청함
- 2단계: FM이 가용 디바이스의 HDM 영역을 선택하고 호스트 물리 주소 공간에 매핑함
- 3단계: 호스트가 CXL.mem 프로토콜로 할당된 영역에 load/store 접근을 수행함
- 4단계: 워크로드 종료 시 호스트가 FM에 반환을 요청하고, FM이 해당 영역을 풀로 회수함

> 요약: FM 주도의 할당-매핑-접근-회수 4단계 순환으로 메모리 자원을 동적 관리함

## Ⅳ. 문제점
- 접근 지연 증가: CXL 링크와 스위치 홉을 경유하므로 로컬 DRAM 대비 50~100ns 추가 레이턴시가 발생함
- 장애 전파 위험: 스위치 또는 FM 단일 장애 시 다수 호스트의 메모리 접근이 동시에 중단될 수 있음
- 보안 격리 복잡성: 다수 호스트가 동일 물리 디바이스를 공유하므로, 메모리 영역 간 격리 실패 시 데이터 유출 가능성이 존재함

> 요약: 레이턴시 증가, 단일 장애점, 보안 격리가 풀링 환경의 주요 과제임

## Ⅴ. 개선방안
1. 단기: NUMA-aware 메모리 배치 정책을 적용하여 핫 데이터를 로컬 DRAM에 유지하고 콜드 데이터만 풀링 영역에 배치함
2. 중기: FM 이중화 및 스위치 다중 경로 구성으로 단일 장애점을 제거함
3. 장기: CXL 3.0 하드웨어 기반 메모리 태깅과 암호화를 적용하여 호스트 간 물리 메모리 격리를 하드웨어 수준에서 보장함

> 요약: 배치 최적화, 이중화, 하드웨어 격리를 단계적으로 적용하여 풀링의 안정성과 성능을 확보함

## Ⅵ. 전망
- 발전 방향: CXL 3.0의 멀티레벨 스위칭과 Global Fabric Attached Memory(GFAM)로 랙·포드 단위 메모리 풀링이 확산될 전망임
- 기술사적 판단: AI/ML 학습 클러스터처럼 메모리 수요 편차가 큰 환경에서 TCO 절감 효과가 검증되면 데이터센터 표준 아키텍처로 정착할 가능성이 높음
- 기술사 제언: CXL 메모리 풀링 도입 시 워크로드 프로파일링을 선행하여 로컬/풀 메모리 비율을 산정하고, FM 이중화 설계를 필수로 포함할 필요가 있음
