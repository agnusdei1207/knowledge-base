## 미리 알고가기

- NVMe는 비휘발성 메모리용으로 설계된 명령 집합과 레지스터 인터페이스 표준임
- PCIe는 NVMe가 주로 사용하는 고속 직렬 전송 버스임
- NVMe는 다중 제출·완료 큐로 CPU 코어의 I/O 요청을 SSD 내부 채널에 병렬 전달함
- 도어벨(Doorbell): 호스트가 큐에 새 명령을 등록했음을 컨트롤러에 알리는 레지스터 쓰기 신호임

## 작성 근거(검토용)

- NVMe·PCIe는 장치 속도보다 제출·완료 큐, 도어벨, PCIe 전달 경로로 설명함
- SATA/AHCI와 NVMe/PCIe는 전송 인터페이스·큐·명령 처리·적용 환경을 핵심 비교축 3개로 비교함
- SSD 내부 병렬성을 호스트 큐와 PCIe 경로로 연결하는 구조로 정리함

## Ⅰ. 개요

- **정의/개념**: NVMe는 비휘발성 메모리 장치에 다중 명령 큐를 제공하는 스토리지 프로토콜이며, PCIe는 NVMe 명령과 데이터를 직렬 레인으로 전달하는 인터페이스임
- **배경/필요성**: SSD의 병렬성과 낮은 지연을 활용하기 위해 다중 큐 기반 저장장치 프로토콜과 고속 버스가 필요함

## Ⅱ. 특징

- CPU 코어별 제출 큐와 완료 큐를 두어 잠금 경합과 단일 큐 대기를 줄임
- PCIe 링크와 다중 큐를 통해 SSD 내부 채널에 여러 명령을 전달함
- 메모리 매핑 레지스터와 도어벨 기반 동작으로 소프트웨어 경로 지연을 줄임
- 성능은 SSD 자체 NAND 특성뿐 아니라 큐 깊이·CPU 인터럽트 처리·NUMA 배치에 영향을 받음

## Ⅲ. 종류 및 비교

| 판단 기준 | SATA/AHCI | NVMe/PCIe |
|:---|:---|:---|
| 전송 인터페이스 | SATA 직렬 링크 | PCIe 직렬 레인 |
| 큐·명령 처리 | 단일 명령 큐에서 AHCI 레지스터로 순서대로 처리 | 코어별 다중 제출·완료 큐와 도어벨로 동시 처리 |
| 적용 환경 | HDD·SATA SSD | 클라이언트·서버·데이터센터 NVMe SSD |

> 요약: SATA/AHCI는 HDD 시대 구조이고, NVMe/PCIe는 SSD 병렬성과 낮은 지연에 맞춘 구조임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 호스트 드라이버 | I/O 요청을 NVMe 명령으로 바꾸고 큐를 관리해 장치와 운영체제를 연결함 |
| 제출·완료 큐 | 명령 제출과 완료 통지를 분리하고 코어별 큐에서 I/O를 처리함 |
| NVMe 컨트롤러 | 명령 해석·DMA·네임스페이스 관리로 SSD 동작을 제어함 |
| PCIe 링크 | 호스트와 장치 사이 데이터와 명령을 저지연으로 전송함 |

```text
+-------------+     +-------------------+     +------------------+     +-------------+
| 호스트 드라이버 | --> | 제출 큐             | --> | NVMe 컨트롤러     | --> | NAND/매체   |
+-------------+     +-------------------+     +------------------+     +-------------+
        ^                         |
        |                         v
        +------------------ 완료 큐 ----------------------------------+
```

> 요약: NVMe는 호스트 드라이버·제출 큐·완료 큐·컨트롤러·PCIe 링크로 병렬 I/O를 처리함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+     +-------------+
| I/O 요청 생성   | --> | 제출 큐 등록    | --> | PCIe로 장치 전달   | --> | 컨트롤러 수행    | --> | 완료 큐 통지    |
+-------------+     +-------------+     +-------------+     +-------------+     +-------------+
```

1. **I/O 요청 생성**: 파일시스템이나 애플리케이션이 읽기와 쓰기를 요청함
2. **제출 큐 등록**: 드라이버가 제출 큐에 명령과 버퍼 정보를 기록함
3. **PCIe로 장치 전달**: 도어벨을 통해 컨트롤러에 새 명령을 알림
4. **컨트롤러 수행**: SSD가 NAND 접근과 DMA를 수행함
5. **완료 큐 통지**: 완료 큐에 결과를 기록하고 호스트가 완료를 회수함

> 요약: 호스트는 제출 큐에 명령을 넣고 컨트롤러가 PCIe로 처리한 뒤 완료 큐로 결과를 돌려줌.

## Ⅵ. 실무 사례

1. 데이터베이스 서버는 CPU 코어별 NVMe 큐와 인터럽트 친화도를 설정하고 IOPS당 CPU 사이클과 p99 지연을 확인함
2. NUMA 서버는 NVMe 큐와 PCIe 장치를 같은 노드에 배치하고 소켓 간 트래픽과 처리량을 확인함

## Ⅶ. 결론

- NVMe·PCIe는 제출·완료 큐와 PCIe 링크로 호스트의 병렬 I/O를 SSD 내부 채널에 전달함
