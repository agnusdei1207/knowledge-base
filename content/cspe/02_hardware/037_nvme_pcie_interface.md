## 미리 알고가기

- NVMe는 비휘발성 메모리용으로 설계된 명령 집합과 레지스터 인터페이스 표준임
- PCIe는 NVMe가 주로 사용하는 고속 직렬 전송 버스임
- 핵심 개선점은 병렬 큐 구조와 낮은 소프트웨어 오버헤드로 SSD 내부 병렬성을 드러내는 데 있음

## Ⅰ. 개요

- **정의/개념**: NVMe는 SSD 같은 비휘발성 메모리 장치를 위해 설계된 고성능 스토리지 프로토콜이며, PCIe는 그 명령과 데이터를 저지연으로 전달하는 고속 직렬 인터페이스로서 둘이 결합해 현대 SSD의 기본 경로를 형성함
- **배경/필요성**: SSD의 병렬성과 낮은 지연을 활용하기 위해 다중 큐 기반 저장장치 프로토콜과 고속 버스가 필요함

## Ⅱ. 특징

- 다수의 제출 큐와 완료 큐를 사용해 높은 병렬 I/O를 효율적으로 처리함
- PCIe 대역폭과 낮은 프로토콜 오버헤드를 활용해 SSD 내부 병렬성을 드러내기 쉬움
- 메모리 매핑 레지스터와 doorbell 기반 동작으로 소프트웨어 경로 지연을 줄임
- 성능은 SSD 자체 NAND 특성뿐 아니라 큐 깊이·CPU 인터럽트 처리·NUMA 배치에 영향을 받음

## Ⅲ. 종류 및 비교

| 판단 기준 | SATA/AHCI | NVMe/PCIe |
|:---|:---|:---|
| 설계 배경 | HDD 중심 구조로 큐와 명령 경로가 단순함 | SSD 중심 구조로 대량 병렬 큐를 전제로 설계됨 |
| 성능 특성 | 병렬성과 지연 최적화 한계가 큼 | 낮은 지연과 높은 IOPS 확장이 가능함 |
| 큐 구조 | 제한된 명령 큐를 제공함 | 다수의 제출·완료 큐를 제공함 |
| 적합 환경 | 범용 저가 저장장치 | 고성능 서버, 클라이언트 SSD, 데이터센터 스토리지 |

> 요약: SATA/AHCI는 HDD 시대 구조이고, NVMe/PCIe는 SSD 병렬성과 낮은 지연에 맞춘 구조임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 호스트 드라이버 | I/O 요청을 NVMe 명령으로 바꾸고 큐를 관리해 장치와 운영체제를 연결함 |
| 제출·완료 큐 | 명령 제출과 완료 통지를 분리해 병렬 I/O를 효율적으로 처리함 |
| NVMe 컨트롤러 | 명령 해석·DMA·네임스페이스 관리로 SSD 동작을 제어함 |
| PCIe 링크 | 호스트와 장치 사이 데이터와 명령을 저지연으로 전송함 |

```text
+-------------+     +-------------------+     +------------------+     +-------------+
| Host Driver | --> | Submission Queue  | --> | NVMe Controller  | --> | NAND / Media|
+-------------+     +-------------------+     +------------------+     +-------------+
        ^                         |
        |                         v
        +------------------ Completion Queue --------------------------+
```

> 요약: NVMe는 호스트 드라이버·제출 큐·완료 큐·컨트롤러·PCIe 링크로 병렬 I/O를 처리함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+     +-------------+
| I/O 요청 생성   | --> | SQ에 명령 등록   | --> | PCIe로 장치 전달   | --> | 컨트롤러 수행    | --> | CQ 완료 통지    |
+-------------+     +-------------+     +-------------+     +-------------+     +-------------+
```

1. **I/O 요청 생성**: 파일시스템이나 애플리케이션이 읽기와 쓰기를 요청함
2. **SQ에 명령 등록**: 드라이버가 제출 큐에 명령과 버퍼 정보를 기록함
3. **PCIe로 장치 전달**: 도어벨을 통해 컨트롤러에 새 명령을 알림
4. **컨트롤러 수행**: SSD가 NAND 접근과 DMA를 수행함
5. **CQ 완료 통지**: 완료 큐에 결과를 기록하고 호스트가 완료를 회수함

> 요약: 호스트는 SQ에 명령을 넣고 컨트롤러가 PCIe로 처리한 뒤 CQ로 완료를 돌려줌.

## Ⅵ. 실무 적용 및 유의점

1. 인터럽트와 큐 처리 경로가 비효율적이면 CPU 오버헤드가 병목이 되므로 polling, interrupt steering, multi-queue tuning을 적용하고 CPU cycles per IOPS, p99 latency로 확인함
2. NUMA를 무시한 큐와 PCIe 슬롯 배치는 실효 성능을 낮추므로 queue affinity와 NUMA-local placement를 적용하고 cross-socket traffic, throughput stability로 확인함
3. 높은 병렬성은 GC와 write amplification을 자극할 수 있으므로 queue depth cap과 over-provisioning을 조정하고 tail latency, steady-state IOPS로 확인함

## Ⅶ. 결론

NVMe와 PCIe의 결합은 SSD 병렬성을 소프트웨어 큐와 버스 구조가 제대로 드러내게 만든 전환점임.

## 작성 근거(검토용)

- NVMe·PCIe는 장치 속도보다 큐 구조, 도어벨, 완료 경로, PCIe 전달 흐름으로 설명함
- 모호한 표현은 CPU cycles per IOPS, p99 latency, steady-state IOPS로 구체화함
- 결론은 저장장치 속도보다 SSD 병렬성을 드러내는 소프트웨어·버스 구조로 정리함
