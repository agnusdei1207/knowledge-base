## 미리 알고가기

- 인터럽트 레이턴시: 외부 이벤트 발생부터 인터럽트 서비스 루틴(Interrupt Service Routine, ISR) 또는 관련 태스크가 실제 실행되기까지 걸리는 시간임
- 우선순위 역전: 높은 우선순위 태스크가 낮은 우선순위 태스크가 보유한 자원 때문에 대기하는 현상임
- 우선순위 상속: 자원을 가진 낮은 우선순위 태스크의 우선순위를 일시적으로 올려 역전을 줄이는 기법임
- 블로킹 시간: 태스크가 자원 대기, 인터럽트 마스킹, 임계 구역 때문에 실행되지 못하는 시간임
- RTOS: 실시간 운영체제(Real-Time Operating System, RTOS)는 우선순위와 태스크 상태를 기준으로 실행 순서를 제어하는 운영체제임

## Ⅰ. 개요

- **정의**: 인터럽트 레이턴시와 우선순위 역전은 실시간 시스템에서 높은 중요도의 이벤트나 태스크가 인터럽트 경로·스케줄러·공유 자원 때문에 즉시 처리되지 못해 데드라인 위반을 유발하는 시간 지연 문제임
- **배경/필요성**: 임베디드 제어 시스템은 센서 이벤트와 제어 태스크가 정해진 시간 안에 처리되어야 함. 인터럽트가 늦거나 높은 우선순위 태스크가 공유 자원 때문에 막히면 평균 성능이 좋아도 실제 장치는 오동작할 수 있음
- **비유**: 구급차가 신호를 받아도 출동 지시가 늦거나, 출동로를 일반 차량이 막고 있어 더 중요한 차량이 움직이지 못하는 상황과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 실시간 지연 원인 설명 | 인터럽트 레이턴시, ISR, 블로킹, 우선순위 역전 | 단순 CPU 성능 부족으로만 설명 |
| 대응 기법 판단 | 우선순위 상속, 짧은 ISR, 임계 구역 축소 | 문제와 해결책 연결 누락 |

> 요약: 인터럽트 레이턴시와 우선순위 역전은 실시간 시스템에서 데드라인 보장을 깨는 대표적인 시간 예측성 문제임.

## Ⅱ. 특징/비교

| 판단 기준 | 인터럽트 레이턴시 | 우선순위 역전 |
|:---|:---|:---|
| 발생 지점 | 이벤트 발생부터 ISR 또는 태스크 실행 전까지의 경로 | 공유 자원 잠금과 스케줄링 경합 지점 |
| 주요 원인 | 인터럽트 마스킹, 긴 ISR, 커널 임계 구역, 높은 부하 | 낮은 우선순위 태스크의 mutex 보유, 중간 우선순위 태스크 선점 |
| 영향 | 센서 입력 누락, 제어 지연, 주기 태스크 지터 | 높은 우선순위 태스크의 데드라인 미스 |
| 대응 기준 | 최대 레이턴시 측정과 ISR 최소화 | 블로킹 시간 상한과 우선순위 상속 적용 |

> 요약: 인터럽트 레이턴시는 이벤트 진입 지연이고, 우선순위 역전은 공유 자원 때문에 높은 우선순위 작업이 막히는 지연임.

- **측정 기준**: 평균 지연보다 최대 지연, p99 지연, 최악 조건에서의 데드라인 미스 여부가 중요함
- **설계 기준**: ISR은 최소 작업만 수행하고 긴 처리는 태스크로 넘겨야 실시간성이 안정됨
- **운영 기준**: 부하가 낮을 때 보이지 않던 지연이 통신 폭주, 센서 노이즈, 로그 증가 상황에서 드러날 수 있음

## Ⅲ. 구성요소

```text
+----------+      +----------+      +----------+
| Event    | ---> | Interrupt| ---> | ISR      |
| Source   |      | Control  |      | Handler  |
+----------+      +----+-----+      +----+-----+
                         |                 |
                         v                 v
                   +----------+      +----------+
                   | Scheduler| ---> | Task/Lock|
                   +----------+      +----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 이벤트 소스 | 센서, 타이머, 통신 장치처럼 처리를 요구하는 외부·내부 이벤트임 | 호출 벨 |
| 인터럽트 컨트롤러 | 인터럽트 우선순위, 마스킹, 벡터 전달을 담당하는 하드웨어임 | 교환대 |
| ISR | 이벤트 원인을 확인하고 최소 처리를 수행한 뒤 태스크에 신호를 넘김 | 긴급 접수원 |
| 스케줄러 | 우선순위와 준비 상태에 따라 다음 실행 태스크를 선택함 | 배차 담당 |
| 공유 자원 잠금 | mutex, 세마포어, 임계 구역으로 자원 접근을 보호하지만 블로킹을 만들 수 있음 | 잠긴 공용 창고 |

> 요약: 실시간 지연은 이벤트 소스, 인터럽트 컨트롤러, ISR, 스케줄러, 공유 자원 잠금의 경로에서 누적됨.

## Ⅳ. 절차

```text
+----------+      +----------+      +----------+      +----------+
| Event    | ---> | ISR      | ---> | Schedule | ---> | Complete |
| Arrive   |      | Minimal  |      | Task     |      | Deadline |
+----------+      +----------+      +----------+      +----------+
```

1. **이벤트 발생**: 센서나 장치가 인터럽트를 발생시키고 컨트롤러가 우선순위와 마스크 상태를 확인함
2. **ISR 진입**: 프로세서가 현재 문맥을 저장하고 벡터로 이동해 원인 확인과 최소 처리를 수행함
3. **태스크 스케줄링**: ISR이 세마포어 또는 큐로 작업을 넘기면 RTOS가 우선순위에 따라 태스크를 실행함
4. **자원 접근·완료**: 태스크가 공유 자원을 사용하고 데드라인 안에 제어 출력이나 결과를 생성함

> 요약: 인터럽트 처리는 이벤트 진입, 최소 ISR, 태스크 스케줄링, 공유 자원 접근을 거쳐 데드라인 완료로 이어짐.

## Ⅴ. 문제점 및 개선방안

- **P1 무제한 인터럽트 지연**: 긴 임계 구역이나 인터럽트 마스킹이 누적되면 이벤트가 발생해도 ISR 진입이 늦어짐
- **P1 대응**: 인터럽트 마스킹 구간을 줄이고 긴 처리를 지연 처리 태스크로 분리함 (확인: 최대 ISR 진입 지연)
- **P2 무제한 우선순위 역전**: 낮은 우선순위 태스크가 잠금을 보유하고 중간 우선순위 태스크가 계속 실행되면 높은 우선순위 태스크가 장시간 대기함
- **P2 대응**: 우선순위 상속 또는 우선순위 천장 프로토콜을 적용함 (확인: 최대 블로킹 시간)
- **P3 계측 사각지대**: 평균 중앙처리장치(Central Processing Unit, CPU) 사용률만 보면 드문 최악 지연, 지터, 블로킹 시간이 드러나지 않음
- **P3 대응**: 범용 입출력(General-Purpose Input/Output, GPIO) 토글, trace hook, RTOS 통계로 p99·최대 지연을 수집함 (확인: 데드라인 미스율, 지터)

> 요약: 개선은 평균 부하 최적화가 아니라 최악 지연의 원인을 계측하고 상한을 만드는 방향이어야 함.

## Ⅵ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 모터 보호 제어 | 과전류 인터럽트의 마스킹 시간을 제한하고 보호 태스크의 공유 자원 블로킹을 상한화함 | 최대 ISR 진입 지연, 보호 동작 시간, 데드라인 미스율 |
| 차량 통신 게이트웨이 | 통신 폭주 시 ISR은 수신 확인만 수행하고 큐 처리 태스크로 넘겨 지터를 낮춤 | p99 지연, 큐 포화율, 오류 프레임 수 |
| 안전 센서 펌웨어 | 높은 우선순위 센서 태스크에 우선순위 상속 mutex를 적용하고 잠금 보유 시간을 계측함 | 최대 블로킹 시간, mutex 보유 시간, 지터 |

> 요약: 인터럽트 지연과 우선순위 역전은 실제 이벤트 경로에서 최대 지연과 블로킹 상한을 확인해야 함.

## Ⅶ. 전망

- **발전 방향**: 멀티코어 마이크로컨트롤러 유닛(Microcontroller Unit, MCU)과 이기종 시스템 온 칩(System on Chip, SoC) 확산으로 인터럽트 라우팅, 공유 캐시, 메모리 버스 경합까지 지연 분석 범위가 확대됨
- **기술사적 판단**: ISR 길이, 인터럽트 우선순위, 잠금 프로토콜, 직접 메모리 접근(Direct Memory Access, DMA) 우선순위, 코어 고정, 임계 구역 시간을 기준으로 최악 응답시간을 산정함; 최대 인터럽트 지연, 지터, 우선순위 역전 재현 조건, 뮤텍스 보유 시간, 중첩 인터럽트 깊이를 추적으로 확인함
- **기술사 제언**: 인터럽트 지연과 우선순위 역전은 평균 처리량이 아니라 최악 응답시간과 공유 자원 통제 기준으로 설명해야 함
