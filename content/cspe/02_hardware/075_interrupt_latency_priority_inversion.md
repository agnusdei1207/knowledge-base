## Ⅰ. 개요
- **정의**: 인터럽트 지연은 인터럽트 발생부터 ISR 실행까지의 시간이며, 우선순위 역전은 저우선순위 태스크가 고우선순위 태스크의 실행을 간접적으로 차단하는 현상
- **배경/필요성**: 두 현상 모두 RTOS(073 참조)의 실시간성을 훼손하므로, 원인과 해결 메커니즘을 정확히 이해할 필요가 있음
- **비유**: 인터럽트 지연은 119 전화를 받기까지의 대기 시간, 우선순위 역전은 신입 직원이 회의실을 잡고 있어 임원이 회의를 못 하는 상황임

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 실시간 장애 원인 분석 능력 | 인터럽트 지연 구성(HW+SW) + 우선순위 역전 3-태스크 시나리오 | 역전 해결책(상속 vs 천장)을 혼동하지 말 것 |

> 요약: 인터럽트 지연과 우선순위 역전은 RTOS 데드라인 위반의 대표적 원인임

## Ⅱ. 구성요소
```text
[Interrupt Latency]
  IRQ Signal --> HW Latency --> SW Latency --> ISR Start
                (pipeline      (context save
                 flush)         + vector jump)

[Priority Inversion]
  Task H(high) --wait--> Lock held by Task L(low)
                              |
                Task M(mid) --preempts--> Task L
                (H is blocked while M runs)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| HW 지연 | 파이프라인 플러시·인터럽트 인식까지의 하드웨어 소요 시간 | 전화벨이 울린 후 수화기를 드는 시간 |
| SW 지연 | 레지스터 저장·벡터 테이블 점프 등 소프트웨어 오버헤드 | 메모를 내려놓고 전화 내용을 기록할 준비 시간 |
| 우선순위 역전 | 중간 우선순위 태스크(M)가 자원 보유 태스크(L)를 선점하여 고우선순위(H)가 무한 대기하는 현상 | 택배 기사(M)가 문 앞을 막아 소방관(H)이 진입 못하는 상황 |
| 임계 구간 | 공유 자원 접근 시 인터럽트를 비활성화하는 코드 영역, 길어지면 지연이 증가함 | 통행 차단 구간 |

> 요약: HW/SW 지연 요소와 우선순위 역전 3-태스크 구조가 핵심 구성요소임

## Ⅲ. 절차
```text
Step1 Detect --> Step2 Measure --> Step3 Mitigate --> Step4 Validate
  Identify        Profile IRQ       Apply protocol    Stress test
  symptoms        + task timing     (inherit/ceiling)  under load
```
- 1단계: 탐지 — 데드라인 위반 로그를 분석하여 지연 또는 역전 발생 여부를 식별함
- 2단계: 측정 — 오실로스코프·트레이스 도구로 인터럽트 지연 시간과 태스크 블로킹 시간을 프로파일링함
- 3단계: 완화 — 인터럽트 지연은 ISR 최소화, 역전은 우선순위 상속 또는 천장 프로토콜을 적용함
- 4단계: 검증 — 최대 부하 조건에서 스트레스 테스트를 수행하여 데드라인 준수를 확인함

> 요약: 탐지 → 측정 → 프로토콜 적용 → 부하 검증의 4단계로 실시간 장애를 해결함

## Ⅳ. 문제점
- ISR 비대화: ISR 내부에 과도한 처리 로직이 포함되면 인터럽트 비활성화 시간이 길어져 후속 인터럽트가 유실됨
- 비제한적 역전(Unbounded Inversion): 중간 우선순위 태스크가 다수일 경우 역전 시간이 예측 불가능하게 증가함
- 데드락 위험: 다수 자원에 천장 프로토콜을 적용할 때 천장 값 설정 오류로 데드락이 발생할 수 있음

> 요약: ISR 비대화·비제한적 역전·데드락 위험이 실시간 장애 해결의 2차 문제임

## Ⅴ. 개선방안
1. 단기: ISR을 최소화하고 하반부(Bottom Half)를 태스크로 분리하여 인터럽트 비활성화 시간을 줄임
2. 중기: 우선순위 천장 프로토콜(PCP)을 도입하여 역전 시간의 상한을 결정론적으로 제한함
3. 장기: Lock-Free 자료구조를 채택하여 공유 자원 경합 자체를 제거하고 데드락 가능성을 원천 차단함

> 요약: ISR 분리 → PCP 도입 → Lock-Free 전환 순으로 실시간 안정성을 확보함

## Ⅵ. 전망
- 발전 방향: 멀티코어 RTOS에서 코어 간 인터럽트 라우팅·자원 격리 기술이 중요해질 전망임
- 기술사적 판단: 인터럽트 지연과 우선순위 역전 분석은 안전 필수 시스템 인증의 필수 항목이 될 것임
- 기술사 제언: 설계 단계에서 WCET와 블로킹 시간을 정량적으로 분석하여 역전 시나리오를 사전에 차단할 필요
