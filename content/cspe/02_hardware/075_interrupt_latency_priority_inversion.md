## 미리 알고가기

- 인터럽트 레이턴시는 인터럽트 요청부터 ISR이 실제로 시작될 때까지의 지연 시간임
- 우선순위 역전은 높은 우선순위 태스크가 낮은 우선순위 태스크가 잡은 자원 때문에 기다리는 현상임
- 두 문제 모두 실시간 시스템의 데드라인 미스를 직접 일으킬 수 있음

## 작성 근거(검토용)

- 인터럽트 레이턴시·우선순위 역전은 IRQ·ISR 경로, 락 경합, 최악 지연시간을 중심으로 설명함
- 비교표는 발생 위치, 직접 원인, 영향 대상, 대표 대응을 기준으로 정리함
- 실무 판단은 최대 인터럽트 지연, 제어 지터, 태스크 대기 시간, 락 점유 시간으로 구체화함

## Ⅰ. 개요

- **정의/개념**: 인터럽트 레이턴시는 IRQ부터 ISR 시작까지의 지연이며 우선순위 역전은 높은 우선순위 태스크가 낮은 우선순위 태스크의 락 해제를 기다리는 현상임
- **배경/필요성**: 인터럽트 지연과 공유 자원 대기가 응답시간 상한을 넘으면 센서 처리와 제어 태스크가 데드라인을 놓칠 수 있음

## Ⅱ. 특징

- 인터럽트 레이턴시는 마스킹 구간과 ISR 길이에 따라 증가함
- 우선순위 역전은 뮤텍스·공유 버퍼의 락 경합 구간에서 발생함
- 두 문제는 평균 성능보다 최악 지연시간을 늘림
- 스케줄러 정책, 락 점유 시간, ISR 실행 시간을 함께 분석해야 원인을 분리할 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 인터럽트 레이턴시 문제 | 우선순위 역전 문제 |
|:---|:---|:---|
| 발생 위치 | IRQ와 ISR 경로에서 인터럽트가 늦게 처리될 때 나타남 | 태스크가 공유 자원을 기다리는 동기화 경로에서 나타남 |
| 직접 원인 | 긴 인터럽트 마스킹·ISR·비결정적 커널 구간 | 낮은 우선순위 태스크의 장시간 락 점유 |
| 영향 대상 | 센서 입력·외부 이벤트의 ISR 시작 지연 | 높은 우선순위 제어 태스크의 실행 지연 |
| 대표 대응 | ISR 최소화·후속 작업 지연 처리 | 우선순위 상속·우선순위 천장 기법 |

> 요약: 인터럽트 레이턴시는 IRQ·ISR 경로 지연이고, 우선순위 역전은 공유 자원 대기 지연임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| IRQ·ISR 경로 | 인터럽트 요청에서 서비스 루틴까지의 경로가 응답 상한을 결정함 |
| 스케줄러·우선순위 큐 | 태스크 실행 순서를 정해 지연 전파 범위를 결정함 |
| 뮤텍스·공유 자원 | 보호 방식에 따라 우선순위 역전 발생 여부와 지속 시간이 달라짐 |
| 추적·계측 도구 | 지연 시간과 차단 시간을 수집해 인터럽트·락 경합 원인 분리에 사용됨 |

> 요약: IRQ·ISR 경로와 스케줄러 지연은 인터럽트 응답시간으로, 뮤텍스 경합은 우선순위별 대기 시간으로 측정함.

## Ⅵ. 실무 사례

1. 모터 제어기는 ISR에 상태 확인만 남기고 후속 처리를 지연 태스크로 넘겨 최대 인터럽트 지연·제어 지터를 확인함
2. 장치 드라이버 뮤텍스는 우선순위 상속을 적용하고 태스크 대기 시간·락 점유 시간을 확인함

## Ⅶ. 결론

실시간 시스템은 인터럽트 지연 상한과 공유 자원 대기 시간을 함께 제한해야 데드라인을 준수할 수 있음.
