## 미리 알고가기

- **UMA (Uniform Memory Access)**: 모든 CPU가 공유 버스를 통해 메모리에 접근하며, 물리적 거리에 상관없이 동일한 지연 시간(Latency)을 갖는 대칭형 구조
- **로컬 메모리 (Local Memory)**: 특정 CPU 소켓에 직접 연결되어 있어 가장 빠르게 접근할 수 있는 메모리 영역
- **원격 메모리 (Remote Memory)**: 다른 CPU 소켓에 연결되어 있어 인터커넥트(QPI, UPI 등)를 거쳐야 접근할 수 있는 메모리 영역
- **피닝 (Pinning)**: 특정 프로세스나 스레드를 특정 CPU 코어에 고정하여 실행되도록 강제하는 설정

## Ⅰ. 개요

- **정의/개념**: NUMA(Non-Uniform Memory Access)는 멀티소켓 서버 아키텍처에서 각 CPU가 자신에게 직접 연결된 로컬 메모리에는 낮은 지연으로 접근하고, 다른 CPU에 연결된 원격 메모리에는 더 높은 지연으로 접근하는 비균등 메모리 제어 방식임
- **배경/필요성**: CPU 코어 수가 급격히 늘어남에 따라 단일 버스를 공유하는 UMA 방식은 대역폭 병목과 버스 경합 문제로 인해 확장이 불가능해짐. CPU별로 독립된 메모리 채널을 할당하는 NUMA 구조를 통해 전체 시스템의 메모리 대역폭을 획기적으로 늘리고 확장성을 확보하기 위해 도입됨

## Ⅱ. 특징 및 비교

### 가. UMA와 NUMA 아키텍처의 비교

| 구분 | UMA (대칭형) | NUMA (비균등형) |
|:---|:---|:---|
| 메모리 접근 지연 | 위치와 무관하게 균일함 | 로컬/원격 위치에 따라 다름 |
| 확장성 | 소켓 수 증가 시 대역폭 병목 발생 | 소켓마다 메모리 채널 분산으로 우수함 |
| 상호연결망 | 단일 시스템 버스 중심 | 노드 간 포인트-투-포인트 인터커넥트 |
| 관리 복잡도 | 운영체제가 신경 쓸 필요 없음 | 스레드 및 메모리 배치(Locality) 최적화 필수 |
| 적합 환경 | 저사양 서버, 임베디드, 초기 멀티코어 | 고성능 서버, 데이터베이스, 가상화 서버 |

> 요약: UMA는 단순하지만 병목이 있고, NUMA는 복잡하지만 고성능 확장이 가능함

### 나. NUMA의 주요 성능 결정 요인
- **Local Access Ratio**: 전체 메모리 요청 중 로컬 메모리에서 처리된 비율. 이 비율이 높을수록 성능이 우수함
- **Interconnect Bandwidth**: 노드 간 데이터를 주고받는 통로(Intel UPI, AMD Infinity Fabric 등)의 속도와 대역폭

## Ⅲ. 구성요소/구조

### 가. NUMA 노드 구조 및 상호연결 메커니즘

```text
[NUMA Node 0]                [Interconnect]               [NUMA Node 1]
+------------+               (UPI / QPI)                +------------+
|  CPU 0     | <--------------------------------------> |  CPU 1     |
| (Local Mem)|                                          | (Local Mem)|
+------------+                                          +------------+
```

### 나. 주요 구성 요소 및 역할

| 구성요소 | 역할 및 설명 | 핵심 포인트 |
|:---|:---|:---|
| NUMA 노드 | CPU와 메모리가 하나의 묶음으로 구성된 최소 성능 단위 | 노드 간의 물리적 거리가 지연 시간 결정 |
| 로컬 메모리 | 해당 노드 CPU가 직접 관리하는 메모리 채널 | 가장 높은 대역폭과 낮은 지연 제공 |
| 인터커넥트 | 노드 간 데이터 및 캐시 일관성 메시지를 전달하는 통로 | 원격 메모리 접근 시의 병목 지점 |
| 커널 스케줄러 | 스레드를 어느 CPU에 배치할지 결정하는 관리자 | NUMA 토폴로지를 인식(Aware)해야 함 |
| 메모리 할당 정책 | 데이터를 어느 노드 메모리에 배치할지 결정하는 규칙 | First-touch, Interleave 정책 등 |

> 요약: CPU와 메모리가 짝을 이루는 '노드'들이 고속망으로 연결된 분산-공유 메모리 구조임

## Ⅳ. 문제점 및 개선방안

1. **원격 메모리 접근(Remote Access) 지연**: 프로세스가 실행되는 CPU와 데이터가 위치한 메모리 노드가 다를 경우 심각한 성능 저하 발생
   - **개선방안**: **스레드 피닝(Thread Pinning)**으로 실행 위치를 고정하고, **First-touch 정책**을 활용하여 실제 데이터를 사용하는 CPU 근처에 메모리를 할당함

2. **메모리 단편화 및 불균형**: 특정 노드의 메모리는 꽉 차 있는데 다른 노드는 여유로운 상황에서 성능 불균형 발생
   - **개선방안**: **numactl**과 같은 도구로 메모리를 노드 전체에 골고루 분산하는 **인터리빙(Interleaving)** 정책을 적용하거나, 동적으로 페이지를 이동(Auto-NUMA Balancing)함

3. **I/O 장치와의 거리 문제**: NIC나 GPU가 특정 소켓에만 연결되어 있어 다른 소켓의 CPU가 I/O 처리 시 오버헤드 발생
   - **개선방안**: I/O 장치가 연결된 노드(Locality)를 확인하여, 해당 장치를 제어하는 인터럽트 서비스 루틴(ISR)과 스레드를 같은 노드에 배치함

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 인메모리 DB (SAP HANA 등) | NUMA 토폴로지를 직접 관리하여 데이터와 처리 스레드를 동일 소켓에 강제 배치 | Remote Memory Ratio, TPS |
| 가상화 호스트 (VMware, KVM) | VM 생성 시 vCPU와 할당 메모리가 단일 NUMA 노드 내에서 해결되도록 배치(NUMA Alignment) | VM Exit Count, p99 Latency |
| AI 가속 학습 | GPU가 연결된 PCIe 슬롯의 NUMA 노드와 CPU 학습 스레드를 일치시켜 데이터 전송 병목 제거 | GPU Util, Bus Bandwidth |

> 요약: 실제 서버 성능 이슈 해결 시 'Remote Access' 비율을 확인하여 NUMA 불일치 여부를 진단함

## Ⅵ. 결론

NUMA는 현대 서버 아키텍처에서 고성능을 뽑아내기 위한 필수적인 메모리 관리 기법임. 단순히 하드웨어의 연결 방식에 그치지 않고, 운영체제의 스케줄링과 애플리케이션의 데이터 배치가 유기적으로 결합되어야 비로소 진가를 발휘함.

기술사는 서버 인프라 설계 시 하드웨어 토폴로지를 명확히 이해해야 하며, 특히 최근 CXL(Compute Express Link)의 도입으로 인한 메모리 풀링 환경에서도 '메모리 근접성(Memory Locality)'이라는 NUMA의 핵심 가치는 더욱 정교한 관리가 요구될 것임을 인지해야 함. 또한 컨테이너 환경에서 NUMA 정렬을 자동화하는 오케스트레이션 최적화 방안에 대해서도 통찰력이 필요함.
