## 미리 알고가기

- NUMA는 코어가 어느 메모리에 접근하느냐에 따라 지연 시간이 달라지는 구조임
- 로컬 메모리는 같은 소켓에 연결된 메모리이고 원격 메모리는 다른 소켓의 메모리임
- 최초 접근 정책은 처음 접근한 코어 근처에 페이지를 배치하는 방식임
- NUMA 노드: 로컬 메모리와 연결된 CPU 소켓 단위이며, 이 문서에서 소켓과 같은 대상을 가리킴

## 작성 근거(검토용)

- NUMA는 소켓 수보다 로컬·원격 접근 지연과 스레드·페이지 배치를 중심으로 설명함
- UMA와 NUMA는 메모리 지연·메모리 경로·배치 요구를 같은 수준으로 비교함
- 계산 스레드와 데이터를 같은 노드에 배치하는 기준으로 정리함

## Ⅰ. 개요

- **정의/개념**: NUMA는 여러 CPU 소켓이 각자 로컬 메모리를 가지면서도 전체 주소 공간은 공유하되, 접근 위치에 따라 메모리 지연 시간과 대역폭이 달라지는 멀티프로세서 구조임
- **배경/필요성**: 다중 소켓의 공유 메모리 요청 경합을 줄이기 위해 메모리 제어기와 접근 경로를 분산하는 구조가 필요함

### 쉽게 이해하기 (학습용)
- 여러 사무실 지점이 각자 서고를 갖고 있지만 전체 회사 문서 목록은 공유하며, 내 지점 서고는 빨리 찾고 다른 지점 서고는 택배로 받아야 하는 것과 같음

## Ⅱ. 특징

- 소켓을 추가하면 로컬 메모리 컨트롤러와 메모리 채널도 늘어나 전체 메모리 대역폭이 증가함
- 같은 주소 공간을 유지해 공유 메모리 프로그래밍 모델을 제공함
- 원격 접근은 인터커넥트 경유로 로컬 접근보다 지연이 크고 변동성도 커짐
- 성능은 하드웨어보다 스레드 배치와 메모리 배치 정책에 좌우됨

### 쉽게 이해하기 (학습용)
- 지점을 늘리면 각 지점 서고와 통로도 늘어 전체 보관량은 커지고, 회사 전체 문서 번호 체계는 그대로 유지됨
- 다른 지점 서고는 택배(인터커넥트)를 거쳐야 해서 시간이 더 걸리고 배송이 밀리면 더 늦어짐. 결국 직원과 문서를 같은 지점에 배치하는 배치 계획이 속도를 좌우함

## Ⅲ. 종류 및 비교

| 판단 기준 | UMA | NUMA |
|:---|:---|:---|
| 메모리 지연 | 코어 위치와 무관하게 같은 메모리 경로를 사용함 | 로컬·원격 메모리 경로에 따라 지연 차이가 발생함 |
| 메모리 경로 | 모든 코어가 공용 메모리 경로를 사용함 | 소켓별 메모리 제어기와 채널을 사용함 |
| 배치 요구 | 코어·페이지 위치를 구분하지 않음 | 스레드와 페이지의 노드 위치를 함께 관리함 |

> 요약: UMA는 접근 지연이 균일하고, NUMA는 확장성을 얻는 대신 지역성 관리가 필요함.

### 쉽게 이해하기 (학습용)
- UMA는 회사 전체가 중앙 서고 하나를 함께 쓰는 방식이라 누구나 걸리는 시간이 같고, NUMA는 지점별 서고를 두어 규모는 커지지만 내 지점 서고를 우선 쓰도록 관리해야 함

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| CPU 소켓 | 연산 코어와 최종 캐시를 포함하며 로컬 메모리 제어기에 연결됨 |
| 로컬 메모리 제어기 | 소켓에 연결된 DRAM 요청을 처리함 |
| 소켓 간 인터커넥트 | 다른 소켓 메모리의 요청과 응답을 전달함 |
| NUMA 인지 운영체제 스케줄러 | 스레드와 페이지를 같은 노드에 배치해 원격 접근을 줄임 |

```text
+------------+      +------------------+      +------------+
| CPU 소켓 0  | <--> | 인터커넥트         | <--> | CPU 소켓 1  |
+------------+      +------------------+      +------------+
      |                                              |
      v                                              v
+------------+                                +------------+
| 로컬 DRAM 0 |                                | 로컬 DRAM 1 |
+------------+                                +------------+
```

> 요약: NUMA는 소켓별 메모리 채널을 사용하고 원격 메모리 요청은 인터커넥트를 거침.

### 쉽게 이해하기 (학습용)
- 각 지점(CPU 소켓)에는 전담 직원(로컬 메모리 제어기)이 있고, 지점 사이에는 택배 노선(인터커넥트)이 연결되어 있으며, 배치 담당자(NUMA 인지 스케줄러)가 직원과 서류를 같은 지점에 두려고 함

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 스레드 배치 결정  | --> | 페이지 초기 배치   | --> | 로컬·원격 접근 판정 | --> | 필요 시 재배치   |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **스레드 배치 결정**: 운영체제가 실행 스레드를 특정 NUMA 노드에 배치함
2. **페이지 초기 배치**: 최초 접근 정책이나 지정 정책으로 메모리를 노드에 할당함
3. **로컬 또는 원격 접근**: 같은 노드의 메모리는 직접 접근하고 다른 노드는 인터커넥트를 거침
4. **필요 시 재배치**: 원격 접근 비율이 높으면 페이지나 스레드를 다른 노드로 옮김

> 요약: NUMA는 스레드와 페이지를 같은 노드에 배치해 원격 메모리 접근을 줄임.

### 쉽게 이해하기 (학습용)
- 직원을 먼저 특정 지점에 배치하고, 그 직원이 처음 찾는 서류도 같은 지점 서고에 두며, 이후 같은 지점 서고면 바로 쓰고 다른 지점이면 택배를 거침. 택배가 잦아지면 직원이나 서류를 옮김

## Ⅵ. 실무 사례

1. 인메모리 데이터베이스는 작업 스레드와 최초 접근 페이지를 같은 노드에 배치하고, 원격 메모리 접근률과 메모리 지연을 확인함
2. 운영체제의 자동 NUMA 균형 기능은 자주 쓰는 페이지만 이동하고, 페이지 이동량과 로컬 접근률을 확인함

### 쉽게 이해하기 (학습용)
- 직원과 자주 찾는 서류를 같은 지점에 두어 택배를 줄이고, 시스템이 자주 쓰는 서류만 골라 지점을 옮겨줌

## Ⅶ. 결론

- NUMA는 여러 소켓이 각자 로컬 메모리를 가지면서도 하나의 주소 공간을 공유해, 접근 위치에 따라 지연이 달라지는 멀티프로세서 구조임
- 계산 스레드와 자주 쓰는 페이지를 같은 노드에 배치해 원격 접근을 줄이고, 원격 접근 비율이 높아지면 자동 균형 기능으로 페이지나 스레드를 재배치해야 함

### 쉽게 이해하기 (학습용)
- 일하는 직원과 그 직원이 쓸 서류를 같은 지점에 모아두면 택배로 오가는 시간을 줄일 수 있음
