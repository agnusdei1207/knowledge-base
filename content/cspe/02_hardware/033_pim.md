## 미리 알고가기

- PIM은 메모리 내부에 연산 기능을 넣어 데이터 이동을 줄이려는 구조임
- PIM은 반복 연산을 메모리 내부로 이관해 호스트와 메모리 사이의 데이터 전송량을 줄임
- 범용 CPU 대체가 아니라 반복적이고 병렬적인 연산을 메모리로 이관하는 접근임

## 작성 근거(검토용)

- PIM은 범용 CPU 대체가 아니라 메모리 왕복 데이터가 큰 반복 연산의 이관 구조로 설명함
- CPU·GPU 중심 처리와 PIM을 연산 위치·지원 연산·데이터 경로·실행 제어·물리 제약으로 비교함
- 외부 전송량과 연산당 에너지 감소를 PIM 작업 이관 기준으로 정리함

## Ⅰ. 개요

- **정의/개념**: PIM은 DRAM이나 HBM 같은 메모리 내부에 경량 연산 로직을 통합해 데이터를 외부 프로세서로 대량 이동시키지 않고 저장 위치 근처에서 직접 처리하는 메모리 중심 컴퓨팅 구조임
- **배경/필요성**: AI·빅데이터의 데이터 이동 에너지와 지연을 줄이기 위해 저장 위치 근처의 연산 기능이 필요함

## Ⅱ. 특징

- 데이터 이동량을 줄여 에너지 효율과 실효 처리량을 동시에 개선할 수 있음
- 메모리 뱅크별 연산 유닛이 단순 반복 연산을 병렬 처리함
- 분기 제어가 적은 MAC·축약·필터 연산을 메모리 내부로 이관함
- 캐시 일관성·프로그래밍 모델·메모리 공정 제약이 상용화 속도를 좌우함

## Ⅲ. 종류 및 비교

| 판단 기준 | CPU/GPU 중심 처리 | PIM |
|:---|:---|:---|
| 연산 위치 | 외부 프로세서 코어에서 수행함 | 메모리 내부 로직에서 수행함 |
| 지원 연산 | 범용 명령·분기 제어 | 반복 벡터·누산·필터 연산 |
| 데이터 경로 | 메모리와 프로세서 사이 왕복 | 메모리 내부 처리 후 결과만 외부 전송 |
| 실행 제어 | CPU·GPU 명령 스케줄러 | 호스트 작업 이관과 PIM 실행환경 |
| 물리 제약 | 메모리 인터페이스 대역폭 | 메모리 공정의 로직 면적·열 |

> 요약: CPU·GPU는 범용 명령을 실행하고, PIM은 반복 연산을 메모리 내부에서 처리해 외부 전송량을 줄임.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 메모리 배열 | 원본 데이터를 저장하며 대용량 병렬 접근의 기반이 됨 |
| 메모리 내 연산 유닛 | 메모리 내부의 경량 연산 로직으로 벡터 연산이나 누산 같은 반복 작업을 수행함 |
| 명령·작업 이관 인터페이스 | 호스트가 처리할 데이터와 연산을 지시해 CPU와 PIM의 역할을 분리함 |
| 실행환경·데이터 배치 정책 | 이관 대상과 데이터 위치를 조정해 내부 병렬성을 실제 성능으로 연결함 |

```text
+-------------+     +----------------------+     +------------------+
| 호스트 CPU/GPU | --> | PIM 명령 인터페이스   | --> | 메모리 내 연산      |
+-------------+     +----------------------+     +------------------+
                                               |
                                               v
                                       +------------------+
                                       | 메모리 배열        |
                                       +------------------+
```

> 요약: PIM은 메모리 배열 가까이에 연산 로직과 오프로딩 인터페이스를 두어 이동량을 줄임.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+     +-------------+
| 작업 후보 식별   | --> | PIM 오프로딩 결정 | --> | 메모리 내부 병렬 처리 | --> | 결과 축약 반환   | --> | 후속 연산 연계   |
+-------------+     +-------------+     +-------------+     +-------------+     +-------------+
```

1. **작업 후보 식별**: 반복적이고 데이터 이동 비중이 큰 연산을 선택함
2. **PIM 오프로딩 결정**: 호스트가 명령과 대상 데이터를 메모리 쪽에 넘김
3. **메모리 내부 병렬 처리**: 뱅크 단위 연산 로직이 데이터를 메모리 내부에서 처리함
4. **결과 축약 반환**: 전체 데이터를 보내는 대신 필요한 결과만 호스트로 돌려줌
5. **후속 연산 연계**: CPU나 GPU가 제어 중심 작업과 후처리를 계속 수행함

> 요약: PIM은 데이터 이동 비중이 큰 작업만 선별해 메모리 내부에서 처리하고 축약 결과를 반환함.

## Ⅵ. 실무 사례

1. 데이터베이스 스캔은 필터 연산을 PIM으로 이관하고 호스트 전송량과 질의당 에너지를 확인함
2. CPU와 PIM의 공유 데이터는 비캐시 영역에 배치하고 일관성 위반 건수와 작업 이관 지연을 확인함

## Ⅶ. 결론

- PIM은 반복 연산을 메모리 내부로 이관해 외부 전송량과 연산당 에너지를 줄이는 구조임
