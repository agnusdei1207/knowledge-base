## 미리 알고가기

- PIM은 메모리 내부에 연산 기능을 넣어 데이터 이동을 줄이려는 구조임
- 핵심 목표는 연산량보다 데이터 이동 비용이 더 큰 memory-bound 작업을 줄이는 것임
- 범용 CPU 대체가 아니라 반복적이고 병렬적인 연산을 메모리 쪽으로 오프로딩하는 접근임

## Ⅰ. 개요

- **정의/개념**: PIM은 DRAM이나 HBM 같은 메모리 내부에 경량 연산 로직을 통합해 데이터를 외부 프로세서로 대량 이동시키지 않고 저장 위치 근처에서 직접 처리하는 메모리 중심 컴퓨팅 구조임
- **배경/필요성**: AI와 빅데이터 워크로드는 계산보다 데이터 이동 에너지와 지연이 더 큰 병목이 되므로, 폰 노이만 구조의 메모리 wall을 줄이기 위해 연산 위치를 메모리 안으로 당길 필요가 있음

## Ⅱ. 특징

- 데이터 이동량을 크게 줄여 에너지 효율과 실효 처리량을 동시에 개선할 수 있음
- 메모리 뱅크 병렬성을 그대로 활용해 단순 반복 연산을 대량으로 분산 처리하기 좋음
- 복잡한 제어 흐름보다는 MAC, reduce, filter 같은 규칙적 연산에서 효과가 큼
- 캐시 일관성과 프로그래밍 모델과 메모리 공정 제약이 상용화 속도를 좌우함

## Ⅲ. 종류 및 비교

| 판단 기준 | CPU/GPU 중심 처리 | PIM |
|:---|:---|:---|
| 연산 위치 | 외부 프로세서 코어에서 수행함 | 메모리 내부 로직에서 수행함 |
| 데이터 이동 | 메모리와 프로세서 사이 왕복이 큼 | 내부 처리로 왕복을 줄임 |
| 강점 | 범용성, 복잡한 제어, 성숙한 소프트웨어 생태계 | energy efficiency와 memory-bound workload 처리에 유리함 |
| 한계 | memory wall과 이동 전력 부담이 큼 | 범용성 부족과 프로그래밍 모델 성숙도가 낮음 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Memory Array | 원본 데이터를 저장하며 대용량 병렬 접근의 기반이 되는 공간임 |
| In-Memory Compute Unit | 메모리 내부에 배치된 경량 연산 로직으로 벡터 연산이나 누산 같은 반복 작업을 수행함 |
| Command and Offload Interface | 호스트가 어떤 데이터를 어떤 연산으로 처리할지 지시해 CPU와 PIM 사이 역할을 분리함 |
| Runtime and Data Placement Policy | 오프로딩 대상과 데이터 위치를 조정해 내부 병렬성을 실제 성능으로 연결함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+     +-------------+
| 작업 후보 식별   | --> | PIM 오프로딩 결정 | --> | 메모리 내부 병렬 처리 | --> | 결과 축약 반환   | --> | 후속 연산 연계   |
+-------------+     +-------------+     +-------------+     +-------------+     +-------------+
```

1. **작업 후보 식별**: 반복적이고 데이터 이동 비중이 큰 연산을 고름
2. **PIM 오프로딩 결정**: 호스트가 명령과 대상 데이터를 메모리 쪽에 넘김
3. **메모리 내부 병렬 처리**: 뱅크 단위 연산 로직이 데이터를 현장에서 처리함
4. **결과 축약 반환**: 전체 데이터를 보내는 대신 필요한 결과만 호스트로 돌려줌
5. **후속 연산 연계**: CPU나 GPU가 제어 중심 작업과 후처리를 계속 수행함

## Ⅵ. 문제점 및 해결 방안

1. 문제: DRAM 공정은 로직 최적화가 아니어서 복잡한 연산기를 넣을수록 면적과 속도와 수율 부담이 커짐
   - 해결방안: 경량 연산 집합 위주로 설계하고 supported offload ratio와 area overhead로 검증함
2. 문제: CPU 캐시와 PIM이 같은 데이터를 따로 다루면 일관성 관리 비용이 커질 수 있음
   - 해결방안: 비캐시 영역 분리나 일관성 프로토콜 연계를 적용하고 coherence violation count와 offload latency로 검증함
3. 문제: 기존 소프트웨어가 PIM 친화적으로 짜여 있지 않으면 데이터 이동 절감 효과를 실제 성능으로 연결하기 어려움
   - 해결방안: compiler와 runtime 오프로딩 지원을 강화하고 offload hit ratio와 energy per operation으로 검증함

## Ⅶ. 적용 사례

- 추천 시스템은 임베딩 lookup과 reduce를 PIM에 오프로딩해 이동 비용을 줄이고, energy per query와 throughput으로 결과를 확인함
- 대형 언어모델 추론은 메모리 집약 구간을 PIM으로 분산 처리해 가속기 유휴를 줄이고, tokens per second와 accelerator idle ratio로 결과를 확인함
- 대규모 검색과 필터링 엔진은 scan 연산을 메모리 내부에서 수행해 데이터 왕복을 줄이고, scanned bytes reduction과 query latency로 결과를 확인함

## Ⅷ. 결론

PIM의 핵심은 연산을 더 빠르게 만드는 것이 아니라 불필요한 데이터 이동을 줄여 시스템 전체 에너지와 지연 구조를 바꾸는 데 있음.
