## 미리 알고가기

- 데이터 이동 비용: 연산 자체보다 데이터를 중앙처리장치(Central Processing Unit, CPU)나 가속기로 가져오는 데 드는 시간·전력 비용임
- memory-bound: 연산기 성능보다 메모리 대역폭이나 지연이 전체 성능을 제한하는 상태임
- in-memory 연산: 메모리 배열 내부 또는 매우 가까운 위치에서 단순 연산을 수행하는 방식임
- coherence: 여러 처리 장치가 같은 데이터를 볼 때 일관된 값을 유지하는 성질임

## Ⅰ. 개요

- **정의**: 메모리 내 처리(Processing-in-Memory, PIM)는 메모리 칩 내부 또는 메모리 배열과 밀접한 위치에 연산 기능을 넣어 데이터가 저장된 곳에서 필터링, 집계, 벡터 연산 등을 수행함으로써 CPU-메모리 간 데이터 이동과 에너지 소비를 줄이는 컴퓨팅 구조임
- **배경/필요성**: 인공지능(Artificial Intelligence, AI), 그래프 분석, 데이터베이스처럼 대량 데이터를 반복 스캔하는 작업은 연산보다 메모리 대역폭이 병목이 되는 경우가 많음. PIM은 데이터를 멀리 이동시키지 않고 가까운 곳에서 처리해 memory wall을 완화함
- **비유**: 모든 원재료를 본사로 보내 계산하지 않고 창고 안에서 분류와 집계를 먼저 끝내 배송량을 줄이는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 데이터 이동 병목을 메모리 중심 연산 구조로 설명하는 역량 확인 | memory wall, 데이터 이동, 메모리 내 연산, coherence, 프로그래밍 모델 | 단순 캐시 확장으로 설명, 지원 연산 한계 누락, 일관성 문제 누락 |

> 요약: PIM은 데이터를 저장한 메모리 근처에서 직접 처리해 대역폭과 전력 병목을 줄이는 구조임.

## Ⅱ. 특징/비교

| 판단 기준 | CPU 중심 처리 | PIM |
|:---|:---|:---|
| 데이터 흐름 | 메모리에서 CPU로 데이터를 이동한 뒤 연산 | 메모리 내부 또는 근처에서 일부 연산 수행 |
| 적합 작업 | 복잡한 제어 흐름, 범용 연산 | 반복적, 병렬적, 메모리 대역폭 지배 작업 |
| 주요 제약 | 데이터 이동 병목 | 지원 명령, 프로그래밍 모델, coherence 관리 |

> 요약: PIM은 범용 CPU를 대체하기보다 데이터 이동이 지배적인 연산을 메모리 쪽으로 이동시키는 보완 구조임.

- PIM은 단순 산술, 비트 연산, reduction, search처럼 데이터 병렬성이 큰 연산에서 데이터 이동량 절감 효과가 큼
- 메모리 공정은 복잡한 로직에 최적화되어 있지 않아 연산 기능은 제한적으로 설계됨
- 기존 명령어 집합 구조(Instruction Set Architecture, ISA), 컴파일러, 런타임, 운영체제(Operating System, OS)가 PIM 연산을 어떻게 호출하고 동기화할지가 핵심임

## Ⅲ. 구성요소

```text
+-----------+      +-----------+      +-----------+
| Host CPU  | ---> | PIM Ctrl  | ---> | Memory    |
+-----------+      +-----------+      | Array+Op  |
      ^             |                 +-----------+
      |             v
      +------> +-----------+
               | Runtime   |
               +-----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 호스트 프로세서 | 전체 제어 흐름과 복잡한 연산을 수행하며 PIM 작업을 요청함 | 현장 총괄 관리자 |
| PIM 제어기 | 메모리 내부 연산 명령, 주소 범위, 동기화를 관리함 | 창고 작업 지시자 |
| 메모리 연산 유닛 | 메모리 뱅크나 로직 근처에서 단순 병렬 연산을 수행함 | 선반 옆 계산대 |
| 런타임·컴파일러 | 어떤 연산을 PIM으로 보낼지 결정하고 결과를 동기화함 | 작업 분배표 |

> 요약: PIM은 호스트가 제어하고 메모리 내부 연산 유닛이 데이터 근처에서 반복 연산을 수행하는 구조임.

## Ⅳ. 절차

```text
+-----------+      +-------------+      +-----------+      +------------+
| Select    | ---> | PIM Cmd     | ---> | Execute   | ---> | Sync       |
+-----------+      +-------------+      +-----------+      +------------+
```

1. **연산 선별**: 데이터 이동 비용이 큰 반복·병렬 연산을 PIM 후보로 식별함
2. **명령과 주소 생성**: 런타임이 대상 주소 범위와 연산 종류를 PIM 제어기에 전달함
3. **메모리 내 처리**: 메모리 뱅크 근처 연산 유닛이 필터링, 집계, 벡터 연산을 수행함
4. **결과 동기화**: 결과를 호스트와 공유하고 캐시 일관성, 예외, 완료 상태를 정리함

> 요약: PIM은 적합 연산을 선별해 메모리 쪽으로 보내고 결과만 동기화해 데이터 이동량을 줄임.

## Ⅴ. 문제점 및 개선방안

- **P1 프로그래밍 모델 미성숙**: 개발자가 어떤 연산을 PIM으로 내릴지 표현하고 디버깅하는 도구가 부족할 수 있음
- **P1 대응**: 반복 패턴별 PIM 라이브러리와 성능 모델을 제공해 offload 대상을 명확히 선택하게 함 (확인: 커널 offload 비율과 개발 수정 범위)
- **P2 일관성·동기화 부담**: CPU 캐시와 PIM이 같은 데이터를 접근하면 최신 값 보장과 순서 제어가 어려움
- **P2 대응**: PIM 대상 메모리 영역의 cache flush, invalidate, ownership 규칙을 명확히 함 (확인: 데이터 불일치 오류와 동기화 대기 시간)
- **P3 연산 기능 제한**: 메모리 공정과 전력 제약 때문에 복잡한 제어 흐름이나 큰 로직을 넣기 어려움
- **P3 대응**: 필터, reduce, bitwise 등 효과가 검증된 제한 연산부터 적용함 (확인: 이동 데이터량 감소와 전력당 처리량)

> 요약: PIM은 범용화보다 memory-bound 커널을 좁게 잡고 소프트웨어 경로를 표준화할 때 데이터 이동량 절감 효과가 큼.

## Ⅵ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 데이터베이스 스캔 가속 | column scan, predicate filter, simple aggregation을 PIM으로 내려 호스트로 돌아오는 tuple 수를 줄임 | 메모리 버스 트래픽, query latency, offload 성공률 |
| 추천·그래프 분석 | embedding lookup, neighbor filtering, bitset 연산처럼 random access와 reduction이 많은 커널만 PIM 후보로 분리함 | 이동 데이터량 감소, cache miss 감소, energy per query |
| AI 추론 보조 연산 | 대규모 벡터 reduce와 activation 전처리를 메모리 근처에서 수행하되 CPU와 GPU의 cache ownership 규칙을 고정함 | PIM kernel utilization, 동기화 오류, end-to-end latency |

> 요약: PIM 적용은 데이터 이동 절감량이 호출·동기화 비용보다 큰 반복 병렬 커널을 선별하고 일관성 지표로 검증해야 함.

## Ⅶ. 전망

- **발전 방향**: AI 추론, 추천, 그래프, 데이터베이스 스캔처럼 데이터 이동이 지배적인 영역에서 PIM 활용 가능성이 확대됨
- **기술사적 판단**: 고대역폭 메모리(High Bandwidth Memory, HBM)와 PIM 결합은 높은 내부 대역폭을 활용해 가속기 외부 데이터 이동을 더 줄이는 방향으로 발전할 수 있음
- **기술사 제언**: 기술사는 PIM을 CPU 대체 기술이 아니라 데이터 이동 비용을 줄이는 메모리 중심 가속 전략으로 설명해야 함
