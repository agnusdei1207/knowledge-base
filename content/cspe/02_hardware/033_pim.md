## 미리 알고가기

- **폰 노이만 병목(Von Neumann Bottleneck)**: 연산 장치(CPU)와 저장 장치(Memory)가 분리되어 있어, 데이터를 주고받는 통로의 속도가 전체 성능을 제한하는 현상
- **데이터 이동 비용**: 연산 자체에 드는 에너지보다 데이터를 메모리에서 CPU로 가져오는 과정에서 발생하는 전력 및 시간 손실
- **메모리 뱅크(Memory Bank)**: 독립적인 읽기/쓰기가 가능한 메모리 내부의 단위 구역
- **Near-Memory Computing**: 메모리 칩 바로 옆 또는 패키지 내부에 연산기를 배치하는 넓은 의미의 PIM 개념

## Ⅰ. 개요

- **정의/개념**: 메모리 내 처리(Processing-in-Memory, PIM)는 데이터를 저장하는 메모리 반도체 내부에 직접 연산 기능을 통합하여, 데이터를 외부 프로세서(CPU/GPU)로 옮기지 않고 현장에서 직접 처리하는 지능형 메모리 기술임
- **배경/필요성**: AI 모델의 거대화로 인해 연산량보다 데이터 전송량이 기하급수적으로 증가하며 '메모리 벽' 문제가 심화됨. 데이터 이동 거리를 획기적으로 줄여 지연 시간을 단축하고 전력 효율을 극대화함으로써 폰 노이만 아키텍처의 근본적인 한계를 극복하기 위해 필요함

## Ⅱ. 특징 및 비교

### 가. 전통적 컴퓨팅과 PIM 아키텍처의 비교

| 구분 | 프로세서 중심 (CPU/GPU) | 메모리 중심 (PIM) |
|:---|:---|:---|
| 데이터 흐름 | 메모리 → 버스 → 프로세서 (왕복) | 메모리 내부에서 즉시 처리 (Local) |
| 연산 위치 | CPU/GPU 내 ALU/Core | 메모리 뱅크 내 연산 유닛 (PCU) |
| 주요 병목 | 데이터 전송 대역폭 및 지연 | 메모리 내부 연산 성능 및 열 관리 |
| 전력 효율 | 낮음 (이동 중 에너지 소모 큼) | 높음 (데이터 이동 최소화) |
| 적합 작업 | 복잡한 제어 흐름, 범용 연산 | 단순 반복 대량 연산, 병렬 작업 |
| 프로그래밍 | 표준 C/C++, Python 활용 | 전용 라이브러리 및 명령셋 필요 |

> 요약: PIM은 '데이터가 있는 곳으로 연산기를 가져가는' 역발상적 구조임

### 나. PIM의 핵심 가치
- **에너지 절감**: 데이터 이동에 소비되는 전력을 최대 70~80% 이상 절감 가능
- **대역폭 극대화**: 메모리 내부의 방대한 뱅크 병렬성을 그대로 연산에 활용

## Ⅲ. 구성요소/구조

### 가. PIM의 메모리 뱅크 내 연산 유닛 배치 구조

```text
[ Processor ] <--- (기존 버스: 소량 결과값만 전송) --- [ PIM Module ]
                                                        |
      +-------------------------------------------------+
      | [ Bank 0 ] [ Bank 1 ] [ Bank 2 ] [ Bank 3 ]     |
      |     |          |          |          |          |
      | [ PCU 0 ]  [ PCU 1 ]  [ PCU 2 ]  [ PCU 3 ]      | <- 연산기 통합
      +-------------------------------------------------+
```

### 나. 주요 구성 요소 및 역할

| 구성요소 | 역할 및 설명 | 핵심 포인트 |
|:---|:---|:---|
| PCU (PIM Control Unit) | 메모리 뱅크별로 배치된 단순 연산 로직 | 덧셈, 곱셈, 비트 연산 위주 수행 |
| 명령 인터페이스 | 호스트(CPU)로부터 PIM 연산 명령을 수신 | 기존 DRAM 프로토콜과의 호환성 유지 |
| 데이터 버퍼 (SR) | 연산 중간 결과나 피연산자를 임시 저장 | 뱅크 내부 데이터 재사용성 향상 |
| 런타임/컴파일러 | 어떤 연산을 PIM으로 보낼지 결정(Offloading) | 소프트웨어 수준의 지능적 연산 분배 |

> 요약: 메모리 뱅크마다 '작은 계산기'를 달아주어 동시다발적인 처리를 지원하는 구조임

## Ⅳ. 문제점 및 개선방안

1. **메모리 공정의 로직 제약**: DRAM 공정은 트랜지스터 속도보다 고집적도와 저비용에 맞춰져 있어 고성능 연산기 구현이 어려움
   - **개선방안**: 복잡한 제어 로직은 최소화하고, AI 연산의 핵심인 **MAC(Multiply-Accumulate)** 연산에 최적화된 경량화 구조를 채택함

2. **프로그래밍 모델 및 호환성 부족**: 기존 소프트웨어를 PIM에서 돌리려면 코드 수정이나 전용 컴파일러가 필요함
   - **개선방안**: 표준 라이브러리(PyTorch, TensorFlow 등)와 연동되는 PIM 전용 가속 라이브러리를 보급하고, **JEDEC 표준화**를 통해 하드웨어 파편화 방지함

3. **캐시 일관성(Cache Coherence) 문제**: CPU 캐시에 있는 데이터와 PIM이 수정한 메모리 데이터가 불일치할 수 있음
   - **개선방안**: PIM 연산 영역을 비캐시(Non-cacheable) 구역으로 설정하거나, 하드웨어 수준의 일관성 유지 프로토콜을 보강함

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 거대언어모델 (LLM) | 가중치 데이터 이동이 많은 추론 단계에서 PIM을 활용해 에너지 효율 개선 | Energy per Token, Latency |
| 추천 시스템 (Recommendation) | 임베딩 벡터의 단순 합산(Summation) 연산을 메모리 내에서 처리 | TCO (Total Cost of Ownership) |
| 빅데이터 검색/필터링 | 수십억 개의 레코드 중 특정 조건 필터링을 메모리 내부에서 수행 | Data Transfer Reduction, Search Time |

> 요약: 데이터가 너무 커서 CPU로 옮기는 것 자체가 손해인 'Memory-bound' 작업에 특효약임

## Ⅵ. 결론

PIM은 70여 년간 유지되어 온 폰 노이만 아키텍처의 패러다임을 송두리째 바꾸는 파괴적 혁신임. 단순히 메모리를 똑똑하게 만드는 것을 넘어, 컴퓨팅 시스템의 중심축을 '연산'에서 '데이터'로 이동시키는 데이터 중심 컴퓨팅(Data-centric Computing)의 핵심 기술임.

기술사는 PIM을 단순히 '성능 좋은 부품'으로 보지 말고, 시스템 전체의 에너지 소모와 대역폭 갈증을 해결하는 아키텍처 관점에서 설명해야 함. 특히 최근 HBM-PIM이나 CXL-PIM과 같은 하이브리드 기술의 동향을 파악하고, 소프트웨어 생태계(컴파일러, 런타임)와의 정렬이 PIM 대중화의 가장 큰 숙제임을 인식해야 함.
