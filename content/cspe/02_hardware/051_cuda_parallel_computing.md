# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: NVIDIA가 개발한 GPU 기반 병렬 컴퓨팅 플랫폼 및 프로그래밍 모델(API)
- **왜 필요한가**: 그래픽 처리에만 쓰이던 GPU의 막대한 병렬 연산 자원을 일반 목적의 연산(GPGPU)에 활용하기 위해 직관적인 C/C++ 기반 환경이 필요했다.
- **핵심 직관**: CPU가 전체 작업의 흐름을 지휘하는 '감독'이라면, GPU는 수천 명의 '단순 노동자'다. CUDA는 감독이 노동자들에게 동시에 같은 명령을 내리고 결과를 취합하는 통신 규약이다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| Host | 메인 시스템 (CPU와 시스템 메모리) | 작업 지시를 내리는 중앙 통제실 |
| Device | 병렬 연산 장치 (GPU와 비디오 메모리) | 수천 대의 기계가 있는 생산 공장 |
| Kernel (커널) | GPU에서 병렬로 실행되는 함수 | 모든 노동자에게 전달되는 단일 작업 지시서 |
| Thread (스레드) | 병렬 실행의 최소 단위 | 각각의 노동자 1명 |
| Block (블록) | 스레드의 묶음 (공유 메모리 사용 가능) | 같은 작업반 (서로 소통 가능) |
| Grid (그리드) | 블록의 묶음 (전체 문제 공간) | 전체 공장 라인 |

## 깊이 이해
- **배경·문제의식**: 과거에는 GPU를 범용 계산에 쓰려면 그래픽 API(OpenGL 등)로 연산을 위장해야 하는 셰이더 프로그래밍의 극심한 복잡성이 존재했다.
- **작동 원리**: CPU(Host)가 입력 데이터를 GPU(Device) 메모리로 복사한다. CPU가 커널을 호출하면, GPU는 수천 개의 스레드를 생성해 데이터를 병렬로 연산한다. 연산이 끝나면 결과를 다시 CPU 메모리로 복사한다.
- **비유**: 100만 픽셀의 이미지 밝기를 조절할 때, CPU는 한 픽셀씩 100만 번 반복문(for)을 돌린다. CUDA는 100만 명의 노동자(스레드)를 동원해 각자 1픽셀씩 동시에 밝기를 조절하게 한다.
- **구체 예시**: `cudaMemcpy()`로 데이터를 이동하고, `addKernel<<<numBlocks, threadsPerBlock>>>(A, B, C)` 형태로 수만 개의 덧셈을 동시 실행한다.
- **흔한 오해·주의점**: 무조건 스레드를 많이 띄운다고 빠르지 않다. 호스트-디바이스 간 데이터 전송 지연(PCIe 병목)이 커서, 연산량이 전송 시간보다 압도적으로 많을 때만 효과가 있다.

## 연결 개념
- GPGPU (General-Purpose computing on Graphics Processing Units)
- SIMT (Single Instruction, Multiple Threads)
- OpenCL (개방형 이기종 컴퓨팅 프레임워크)

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: CUDA는 NVIDIA GPU의 병렬 연산 자원을 범용 연산(GPGPU)에 활용하기 위해 추상화된 병렬 컴퓨팅 아키텍처 및 프로그래밍 모델이다.
> 2. **가치**: SIMT 구조를 통해 수천 개의 스레드를 동시에 제어하며, 딥러닝·과학 연산 등 행렬/벡터 중심 데이터 병렬 워크로드의 처리량을 극대화한다.
> 3. **판단 포인트**: 이기종 컴퓨팅에서 Host-Device 간 PCIe 대역폭 병목을 최소화하고, 워프 다이버전스(Warp Divergence)를 피하는 메모리 계층 설계가 핵심이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 병렬 컴퓨팅 프로그래밍 모델 이해 | Host/Device 구조, Kernel, Grid/Block/Thread 계층 | 단순히 그래픽 카드의 성능 향상 기술로 단정 |
| 데이터 전송 및 실행 흐름 분석 | `cudaMemcpy` 병목, SIMT 동작, Unified Memory | 스레드 생성과 실행을 CPU 멀티스레딩과 혼동 |
| 병목 요인 통제 역량 | PCIe 대역폭 한계, 메모리 합침(Coalescing), 워프 다이버전스 | 메모리 복사 오버헤드를 누락 |

> 요약: CUDA의 성능은 연산 코어 수뿐만 아니라 메모리 전송 지연을 은닉하는 계층적 스레드 관리와 메모리 접근 패턴 최적화에 달려 있다.

---

## Ⅰ. 개요 및 필요성

- 개요: NVIDIA GPU의 SIMT(Single Instruction Multiple Threads) 아키텍처를 C/C++ 기반으로 제어하는 이기종(Heterogeneous) 병렬 컴퓨팅 플랫폼
- 배경: 과학 연산과 인공지능 분야에서 대규모 행렬 곱셈 등 데이터 병렬성(Data Parallelism)이 높은 워크로드가 급증함
- 필요성: CPU의 수십 개 코어로는 테라플롭스(TFLOPS) 단위의 연산량을 감당 불가하여, 수천 개 코어를 가진 GPU 오프로딩 필수

---

## Ⅱ. 구조 및 구성요소

```text
Host (CPU/RAM) -> PCIe Bus -> Device (GPU/VRAM)
[Application]                   [Grid]
      |                           |-- Block 0 (Shared Memory)
      +--- Kernel Launch ---->    |     |-- Thread 0, Thread 1...
      |                           |-- Block 1 (Shared Memory)
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Host | 메인 제어, 디바이스 메모리 할당 및 데이터 전송 명령 | CPU 및 시스템 메인 메모리 |
| Device | 병렬 커널 함수 실행, 대용량 스레드 컨텍스트 유지 | GPU 코어(SM) 및 GDDR 메모리 |
| Kernel | Host가 호출하고 Device에서 실행되는 병렬 함수 단위 | `__global__` 한정자 사용 |
| Grid/Block/Thread | 스레드 실행 공간을 3차원으로 분할하는 계층 구조 | 워프(Warp) 단위로 스케줄링 |

> 요약: Host가 제어 흐름과 메모리 복사를 담당하고, Device는 Grid-Block-Thread 계층에 맞춰 Kernel을 SIMT 방식으로 병렬 실행한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
데이터 준비 -> 디바이스 메모리 복사 -> 커널 실행 (병렬 연산) -> 결과 호스트 복사 -> 메모리 해제
Host(CPU)       PCIe (Host->Device)    Device(GPU/SM)          PCIe (Device->Host)   Host(CPU)
```

- 1단계 [메모리 복사]: Host 메모리의 입력 데이터를 `cudaMemcpy`를 통해 Device 메모리로 이동
- 2단계 [커널 론치]: CPU가 병렬 스레드 수(Grid, Block 크기)를 지정하여 GPU Kernel 함수 호출
- 3단계 [SIMT 실행]: GPU의 스트리밍 멀티프로세서(SM)가 32개 스레드 묶음(Warp) 단위로 동일 명령어 병렬 처리
- 4단계 [결과 회수]: 연산 완료 후 Device 메모리의 결과를 Host 메모리로 다시 복사

> 요약: Host-Device 간 데이터 전송 후 GPU 내부에서 대량의 스레드가 커널을 동시에 실행하고 결과를 반환하는 오프로딩 구조다.

---

## Ⅳ. 특징
- 병렬성 극대화: 단일 명령어 스트림으로 수천 개의 데이터 요소를 동시 처리하는 데이터 병렬성 제공
- 계층적 메모리: Global(느림, 대용량), Shared(빠름, 블록 공유), Local/Register(가장 빠름)로 구성되어 접근 지연 은닉
- Unified Memory 지원: CUDA 6.0 이후 Host와 Device 메모리를 단일 포인터로 접근 가능하여 개발 복잡도 완화

> 요약: 고도의 데이터 병렬 처리에 유리하지만, 호스트 간 메모리 전송 지연과 스레드 동기화 오버헤드라는 한계가 존재한다.

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | CUDA (NVIDIA) | OpenCL (Khronos) | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 벤더 종속 프로그래밍 모델 | 개방형 범용 프로그래밍 모델 | 대상 하드웨어 이기종성 |
| 비용/성능 | NVIDIA GPU 최적화 성능 최고 | CPU/GPU/FPGA 교차 지원이나 성능 저하 | 성능 극대화 vs 이식성 |
| 운영/위험 | 풍부한 라이브러리(cuDNN 등) 지원 | 벤더별 드라이버 최적화 파편화 | 딥러닝 생태계 종속 여부 |

> 요약: 성능과 생태계 측면에서 AI 연산은 CUDA가 압도적 우위이나, 하드웨어 독립성이 필요한 엣지 환경은 OpenCL을 고려한다.

**리스크·대응 (기본 불릿):**
- 워프 다이버전스(Warp Divergence): 분기문(if-else)으로 인해 워프 내 스레드 유휴 발생 → 분기 조건을 통일하거나 최소화 (지표: 워프 실행 효율)
- 메모리 전송 병목: PCIe 대역폭 한계로 연산보다 전송 지연이 큼 → 비동기 스트림(Stream) 복사와 연산 중첩 (지표: PCIe 대역폭 활용률)
- 비합침 메모리 접근: 연속되지 않은 글로벌 메모리 접근 시 지연 → Shared Memory 캐싱을 통한 병합(Coalesced) 접근 유도 (지표: 메모리 트랜잭션 수)

**도입 후 점검 지표:**
- 연산 처리량: TFLOPS (초당 부동소수점 연산 횟수) — nvprof 등 프로파일러로 측정
- 메모리 대역폭: GB/s (초당 전송 기가바이트) — 글로벌 메모리 접근 효율 측정

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 딥러닝 프레임워크 연동: PyTorch, TensorFlow의 백엔드로 cuDNN을 적용하여 행렬 곱셈(GEMM) 연산 시간을 1/10 수준으로 단축
2. 비동기 스트리밍 적용: 메모리 복사(`cudaMemcpyAsync`)와 커널 실행을 CUDA Stream으로 겹쳐(Overlap) 전체 파이프라인 유휴 시간 최소화
3. 메모리 계층 최적화: 자주 접근하는 배열 데이터는 글로벌 메모리 대신 블록 내 공유 메모리(Shared Memory)에 적재하여 메모리 지연 10배 이상 개선

**결론 (2줄):**
- 기술사 판단: CUDA는 데이터 독립성이 높은 워크로드에서 최적이나, 반복적인 Host-Device 통신이 필요한 로직은 오히려 오버헤드가 크므로 연산 오프로딩 단위를 크게 설계해야 한다.
- 향후 방향: PCIe 병목 극복을 위해 NVLink 적용 및 CPU-GPU 간 캐시 일관성을 유지하는 통합 메모리(Unified Memory) 아키텍처로 진화 중이다.
