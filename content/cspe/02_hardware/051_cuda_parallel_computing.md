## 미리 알고가기

- **$CUDA$ (Compute Unified Device Architecture)**: $NVIDIA$ $GPU$에서 범용 병렬 연산을 수행하기 위해 개발된 프로그래밍 모델 및 소프트웨어 플랫폼
- **커널 ($Kernel$)**: $GPU$에서 병렬로 실행되는 함수의 단위로, 수만 개의 스레드가 동일한 코드를 각기 다른 데이터에 대해 실행함
- **호스트 ($Host$)와 디바이스 ($Device$)**: 연산을 제어하는 $CPU$($Host$)와 실제 병렬 연산을 수행하는 $GPU$($Device$)의 관계
- **그리드·블록·스레드**: $CUDA$에서 병렬 작업을 관리하는 계층적 구조 ($Grid \supset Block \supset Thread$)
- **공유 메모리 ($Shared\ Memory$)**: 같은 블록 내의 스레드들이 데이터를 매우 빠르게 공유할 수 있는 $SM$ 내부의 메모리 공간

## Ⅰ. 개요

- **정의/개념**: $CUDA$ 병렬 컴퓨팅은 $NVIDIA$ $GPU$의 $SIMT$($Single\ Instruction\ Multiple\ Threads$) 아키텍처를 $C/C++$ 등의 고수준 언어로 제어하여, 대규모 데이터 병렬 워크로드를 수만 개의 스레드로 나누어 동시에 처리하는 병렬 프로그래밍 아키텍처임
- **배경/필요성**: 딥러닝, 기상 예측, 암호 해독 등 현대의 복잡한 연산은 데이터 간 의존성이 낮고 단순 반복이 많은 특성을 가짐. $CPU$의 순차 처리 한계를 극복하고, $GPU$의 수천 개 코어를 범용 연산($GPGPU$)에 활용하기 위해 개발됨

## Ⅱ. 특징 및 비교

### 가. $CPU$ 멀티스레딩과 $CUDA$ 병렬 컴퓨팅의 비교

| 구분 | $CPU$ 병렬 (멀티스레딩) | $CUDA$ 병렬 컴퓨팅 |
|:---|:---|:---|
| **스레드 수** | 수십 개 이내 (무거움) | 수만 개 이상 (매우 가벼움) |
| **병렬 모델** | $MIMD$ (서로 다른 명령 가능) | $SIMT$ (동일 명령, 다른 데이터) |
| **메모리 구조** | 자동 캐시 계층 중심 | 명시적 메모리 계층 관리 필요 |
| **문맥 전환** | 오버헤드 큼 (소프트웨어적) | 오버헤드 거의 없음 (하드웨어적) |
| **주요 용도** | 복잡한 제어, 순차적 의존성 | 단순 반복 연산, 대량 데이터 처리 |

> 요약: $CPU$는 '숙련된 장인 소수'가 정교한 일을 하는 구조라면, $CUDA$는 '수만 명의 단순 노동자'가 동시에 달려드는 구조임

### 나. $CUDA$의 핵심 프로그래밍 가치
- **추상화**: 복잡한 $GPU$ 하드웨어 파이프라인을 몰라도 $C$ 언어 기반의 커널 작성으로 병렬성 구현 가능
- **성능**: 하드웨어 계층(레지스터, 공유 메모리)에 직접 접근하여 극한의 최적화 가능

## Ⅲ. 구성요소/구조

### 가. $CUDA$의 스레드 및 메모리 계층 구조

```text
[ Grid ]
  |-- [ Block (0,0) ]
  |      |-- [ Shared Memory ]
  |      |-- [ Thread (0,0,0) ] ... [ Thread (n,n,n) ]
  |-- [ Block (n,n) ]
------------------------------------------------------
[ Memory Hierarchy ]
  |-- Local Memory (Thread 전용)
  |-- Shared Memory (Block 공유, L1급 속도)
  |-- Global Memory (HBM/GDDR, 모든 Thread 접근)
```

### 나. 주요 구성 요소 및 역할

| 구성요소 | 역할 및 설명 | 핵심 포인트 |
|:---|:---|:---|
| 호스트 ($CPU$) | 데이터 전송 명령 및 커널 실행 스케줄링 | 전체 워크플로우 제어 |
| 디바이스 ($GPU$) | 하달받은 커널을 수만 개의 스레드로 병렬 실행 | 실제 연산 수행 주체 |
| 스레드 블록 | $SM$에 할당되는 스레드들의 묶음 | 블록 내 스레드 간 동기화 가능 |
| 스트림 ($Stream$) | 커널 실행과 데이터 전송을 비동기적으로 수행하는 큐 | $Task$ 간 병렬성 확보 |
| $JIT$ 컴파일러 | 커널 코드를 $GPU$ 하드웨어용 기계어($PTX$)로 변환 | 런타임 최적화 |

> 요약: 계층화된 스레드 구조가 데이터를 '나눠 갖고', 계층화된 메모리 구조가 데이터를 '빨리 공급'하는 구조임

## Ⅳ. 문제점 및 개선방안

1. **데이터 전송 오버헤드**: $PCIe$ 버스를 통한 $CPU-GPU$ 간 데이터 복사 시간이 실제 연산 시간보다 길어지는 현상
   - **개선방안**: **통합 메모리($Unified\ Memory$)**를 사용하여 불필요한 복사를 줄이고, **$Stream$**을 통해 전송과 연산을 오버랩($Overlap$)함

2. **메모리 접근 정렬 ($Coalescing$) 실패**: 인접 스레드가 흩어진 메모리 주소를 읽을 때 대역폭이 낭비됨
   - **개선방안**: 데이터를 연속된 주소로 재배치하여 한 번의 메모리 트랜잭션으로 최대한 많은 데이터를 가져오도록 튜닝함

3. **벤더 종속성 ($Lock-in$)**: $CUDA$는 오직 $NVIDIA$ $GPU$에서만 동작하여 하드웨어 선택권이 제한됨
   - **개선방안**: **$OpenCL$**이나 **$SYCL$**, 또는 $AMD$의 **$HIP$**과 같은 오픈 소스/이식성 도구를 사용하여 코드 범용성을 확보함

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| **딥러닝 학습 ($LLM$)** | $cuBLAS, cuDNN$ 등 $CUDA$ 가속 라이브러리를 통해 수 조개의 파라미터 업데이트 | $TFLOPS$, $Step\ Time$ |
| **영상 편집 (랜더링)** | 수백만 개의 픽셀에 대한 효과 및 레이어 합성 처리를 각 스레드에 분산 | $Render\ Time$, $FPS$ |
| **의료 영상 분석** | $MRI/CT$ 데이터를 3차원 그리드 구조로 나누어 암 세포 탐지 및 복원 연산 수행 | $Processing\ Accuracy$, $Latency$ |

> 요약: '데이터의 개수'가 많을수록 $CUDA$의 성능 이점은 지수적으로 증가함

## Ⅵ. 결론

$CUDA$ 병렬 컴퓨팅은 소프트웨어가 하드웨어의 병렬성을 어떻게 제어해야 하는지에 대한 표준을 제시했음. 단순히 빠른 라이브러리를 넘어, 인공지능 시대의 '새로운 프로그래밍 패러다임'으로 자리 잡았음.

기술사는 $CUDA$의 문법적 이해를 넘어, **메모리 계층 간 데이터 이동 비용**과 **워프 단위의 실행 원리**를 깊이 있게 분석할 수 있어야 함. 또한, 향후 $NVLink$와 같은 차세대 인터커넥트가 $CUDA$의 메모리 모델을 어떻게 확장시키고 있는지, 그리고 $AI$ 반도체 경쟁 속에서 $CUDA$ 생태계의 소프트웨어 파급력이 가지는 전략적 의미를 이해해야 함.
