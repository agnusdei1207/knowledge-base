## 미리 알고가기

- CUDA는 NVIDIA GPU용 병렬 프로그래밍 모델과 실행 플랫폼임
- 병렬 구조는 그리드(Grid), 블록(Block), 스레드(Thread), 메모리 계층으로 구성됨
- 성능 핵심은 점유율, 메모리 병합 접근, 스트림 중첩임
- SM(Streaming Multiprocessor): 워프 단위로 스레드를 실행하는 GPU 연산 코어 묶음임
- 점유율(Occupancy): SM이 지원하는 최대 워프 수 대비 실제 배정된 워프 비율임
- 워프(Warp): SM이 같은 명령을 동시에 실행하는 스레드 32개 묶음임
- SIMT(Single Instruction Multiple Thread): 같은 명령을 다수 스레드가 서로 다른 데이터에 동시 적용하는 실행 모델임

## 작성 근거(검토용)

- CUDA는 SIMT 실행, 그리드·블록·스레드, 메모리 계층, 스트림을 핵심 축으로 설명함
- 비교표는 실행 계층, 메모리 제어, 코드 이식 조건을 기준으로 정리함
- 실무 판단은 메모리 적재 효율, GPU 사용률, PCIe 전송 시간으로 구체화함

## Ⅰ. 개요

- **정의/개념**: CUDA는 NVIDIA GPU의 그리드·블록·스레드와 메모리 계층을 제어해 SIMT 데이터 병렬 연산을 실행하는 프로그래밍 플랫폼임
- **배경/필요성**: AI 학습·과학 계산의 반복 연산을 GPU 스레드와 메모리에 배치하기 위해 병렬 프로그래밍 계층이 필요함

### 쉽게 이해하기 (학습용)
- 작업 계획표(그리드·블록)와 창고 배치(메모리 계층)를 미리 짜서 같은 작업을 수많은 일꾼이 동시에 처리하게 하는 것과 같음

## Ⅱ. 특징

- 작업을 그리드·블록·스레드로 나눠 GPU의 SM과 워프에 배치함
- 공유 메모리는 블록 내 데이터를 재사용하고 스트림은 커널 실행과 메모리 복사를 중첩함
- 메모리 접근이 연속되지 않거나 워프 분기가 갈리면 메모리 트랜잭션과 실행 경로가 늘어남
- CUDA 커널과 라이브러리는 NVIDIA GPU 실행 환경을 전제로 함

### 쉽게 이해하기 (학습용)
- 여러 작업조(블록)가 같은 작업대(공유 메모리)를 나눠 쓰고 운반과 조립을 동시에 진행하지만(스트림), 작업자들이 서로 다른 길로 흩어지면(워프 분기) 대열이 흐트러져 시간이 더 걸림

## Ⅲ. 종류 및 비교

| 판단 기준 | CPU 멀티스레딩 | CUDA 병렬 컴퓨팅 | OpenCL, SYCL 계열 |
|:---|:---|:---|:---|
| 실행 계층 | 프로세스·스레드 | 그리드·블록·스레드 | API의 작업 그룹·작업 항목 |
| 메모리 제어 | 캐시·NUMA 배치 | 전역·공유·레지스터 메모리 배치 | 공통 메모리 모델 범위 |
| 코드 이식 조건 | 대상 CPU용 재컴파일 | CUDA 지원 GPU 필요 | 장치별 백엔드·커널 검증 필요 |

> 요약: CUDA는 그리드·블록·스레드로 NVIDIA GPU 전용 커널을 실행하고 OpenCL·SYCL은 벤더별 백엔드 검증이 필요한 다중 장치 커널을 실행함.

### 쉽게 이해하기 (학습용)
- 회사원이 알아서 일하는 방식(CPU 스레드)과, 한 회사 전용 조직표로 움직이는 방식(CUDA), 여러 회사에서 통용되는 표준 매뉴얼로 움직이는 방식(OpenCL·SYCL)의 차이임

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 그리드·블록·스레드 | 작업을 계층적으로 분할해 SM에 배치하며 블록이 동기화와 메모리 공유 범위를 결정함 |
| 전역·공유·레지스터 메모리 | 데이터 재사용 범위에 맞춰 배치하며 전역 메모리 접근 횟수가 전송 시간을 결정함 |
| 워프 스케줄러 | 준비된 워프를 교차 실행해 메모리 대기 중 SM 유휴 시간을 줄임 |
| 스트림·런타임 API | 커널 실행과 메모리 복사를 비동기로 중첩해 전송 대기 시간을 줄임 |

> 요약: 그리드·블록이 스레드 배치와 공유 범위를 정하고 워프 스케줄러·스트림이 실행과 전송 대기를 중첩함.

### 쉽게 이해하기 (학습용)
- 작업 조직표(그리드·블록·스레드), 창고 등급(전역·공유·레지스터 메모리), 대기 없이 다음 조를 투입하는 반장(워프 스케줄러), 운반과 작업을 동시에 진행하는 물류(스트림)가 함께 돌아감

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 데이터 준비    | --> | 커널 배치      | --> | GPU 병렬 실행  | --> | 결과 회수·후처리 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **데이터 준비**: 호스트가 GPU 메모리와 커널 인자를 준비함
2. **커널 배치**: 그리드와 블록 크기를 정해 커널을 실행함
3. **GPU 병렬 실행**: 워프 단위로 스레드가 같은 명령을 병렬 처리함
4. **결과 회수 및 후처리**: 출력 데이터를 회수하고 상위 로직에 반영함

> 요약: 호스트가 데이터와 커널을 준비하면 GPU가 워프 단위로 병렬 실행하고 결과를 반환함.

### 쉽게 이해하기 (학습용)
- 재료를 창고로 옮기고(데이터 준비), 작업 조를 배정한 뒤(커널 배치), 여러 조가 동시에 같은 작업을 수행하고(병렬 실행), 완성품을 다시 모아오는(결과 회수) 공정과 같음

## Ⅵ. 실무 사례

1. 영상 추론 커널은 연속 메모리 접근과 공유 메모리 재사용을 적용하고 메모리 적재 효율·GPU 사용률을 확인함
2. 호스트-GPU 복사가 반복되는 파이프라인은 고정 메모리와 스트림 중첩을 적용하고 PCIe 전송 시간과 전체 지연을 확인함

### 쉽게 이해하기 (학습용)
- 사진 인식 라인은 같은 작업대를 반복 사용해 재료 낭비를 줄이고, 자재 운반이 잦은 라인은 트럭이 쉬지 않고 왕복하도록 일정을 겹쳐 짬

## Ⅶ. 결론

- CUDA는 그리드·블록·스레드로 작업을 나눠 GPU의 SM·워프에 배치하고 메모리 계층을 활용해 병렬 처리량을 높이는 플랫폼임
- 메모리 접근이 잦은 커널은 공유 메모리 재사용과 연속 접근으로 최적화하고, 호스트-GPU 복사가 반복되면 스트림 중첩으로 전송 대기 시간을 줄여야 함

### 쉽게 이해하기 (학습용)
- 일꾼 수를 늘리는 것보다 창고 배치와 작업 조 편성을 잘 짜야 전체 생산 속도가 빨라지는 공장과 같음
