# CUDA 병렬 컴퓨팅 (CUDA Parallel Computing)

## 미리 알고가기

- CUDA: NVIDIA GPU에서 범용 병렬 연산을 수행하기 위한 프로그래밍 모델과 런타임임
- Host/Device: CPU는 host로서 제어를 담당하고 GPU는 device로서 커널을 실행함
- Kernel: GPU에서 병렬 실행되는 함수이며 많은 스레드가 같은 코드를 실행함
- Grid/Block/Thread: CUDA가 병렬 작업을 계층적으로 배치하는 실행 단위임
- Stream: 커널 실행과 메모리 복사를 비동기로 겹치게 하는 실행 큐임

## 1. 개요

- **정의/개념**: CUDA 병렬 컴퓨팅은 CPU가 호스트로 작업을 지시하고 NVIDIA GPU가 디바이스로 커널을 실행하도록 스레드 계층, 메모리 계층, 런타임 API를 제공해 데이터 병렬 작업의 처리량을 높이는 병렬 프로그래밍 모델임.
- **배경/필요성**: AI, 영상처리, 과학계산은 같은 연산을 대량 데이터에 반복 적용하므로 CPU만으로는 처리량과 전력 효율이 부족함. CUDA는 GPU 하드웨어 구조를 소프트웨어가 직접 활용하게 해 병렬 구현과 최적화를 체계화함.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| GPU 프로그래밍 모델과 실행 구조 설명 | Host/Device, Grid/Block/Thread, 메모리 계층, stream | CUDA를 단순 라이브러리로 설명, 데이터 이동 비용 누락 |

> 요약: CUDA는 GPU SIMT 구조를 프로그래밍 모델로 노출해 대량 데이터 병렬 연산을 실행하게 하는 기술임.

## 2. 특징 및 비교

| 판단 기준 | CPU 스레드 병렬 | CUDA 병렬 컴퓨팅 |
|:---|:---|:---|
| 실행 단위 | OS 스레드와 코어 중심의 비교적 큰 작업 병렬화 | grid, block, thread 단위의 대량 경량 스레드 |
| 메모리 관점 | 캐시와 가상 메모리 추상화가 강함 | global, shared, register memory 배치가 성능 좌우 |
| 적용 기준 | 분기와 순차 의존성이 큰 작업에 적합함 | 규칙적 데이터 병렬성과 높은 산술 강도에 적합함 |
| 병목 요인 | 락, 문맥 전환, 캐시 미스 | 전송 비용, 분기 발산, 메모리 coalescing 실패 |

CUDA는 병렬 작업을 많이 만들수록 항상 빨라지는 모델이 아님. 커널 계산량이 충분하고 메모리 접근이 정렬되며 CPU-GPU 전송 비용을 상쇄할 때 실효 성능이 커짐.

## 3. 구성요소/구조

```text
+----------+      +----------+      +-------------+
| Host CPU | ---> | CUDA API | ---> | GPU Kernel  |
+----------+      +----------+      +-------------+
      |                                  |
      v                                  v
+----------+                      +-------------+
| Host Mem | <------------------> | Device Mem  |
+----------+                      +-------------+
```

| 구성요소 | 설명 | 핵심 포인트 |
|:---|:---|:---|
| Host 코드 | 데이터 준비, 메모리 복사, 커널 실행, 동기화를 제어함 | 제어 흐름 |
| Kernel | GPU 스레드가 실행하는 병렬 함수임 | 실제 연산 |
| 실행 계층 | Grid, Block, Thread, Warp가 작업 범위와 스케줄링 단위를 정함 | 병렬도 |
| 메모리 계층 | global, shared, constant, register memory가 접근 비용과 재사용성을 결정함 | 대역폭 |
| Stream/Event | 커널과 복사를 비동기로 조합하고 완료 시점을 동기화함 | overlap |

### 원리/흐름도

```text
+----------+      +----------+      +----------+      +----------+
| DataPrep | ---> | Launch   | ---> | GPU Work | ---> | Sync     |
+----------+      +----------+      +----------+      +----------+
```

CPU는 입력을 GPU 메모리에 준비하고 그리드·블록 크기를 지정해 커널을 실행함. GPU는 워프 단위로 스레드를 스케줄링하고, 완료 후 CPU는 결과를 회수하거나 다음 커널로 넘김.

## 4. 문제점 및 개선방안

1. **데이터 전송 병목**: CPU-GPU 복사 비용이 커널 계산 이득보다 크면 전체 성능이 낮아짐.
   - **개선방안**: pinned memory, stream overlap, unified memory prefetch, kernel fusion으로 전송과 동기화를 줄임. (확인: PCIe/NVLink 전송 시간)
2. **동시성 오류**: 공유 메모리, 원자 연산, 동기화 지점이 잘못되면 경쟁 상태와 비결정적 결과가 발생함.
   - **개선방안**: sanitizer, racecheck, block-level synchronization 규칙을 적용함. (확인: 동시성 결함 재현 건수)
3. **플랫폼 종속성**: CUDA는 NVIDIA 생태계에 강하게 결합되어 하드웨어 선택과 이식성이 제한됨.
   - **개선방안**: 알고리즘 계층과 CUDA 커널 계층을 분리하고 HIP, OpenCL, 표준 라이브러리 대안을 검토함. (확인: 이식 대상 수)

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 영상 분석 배치 | 동일 필터·행렬 연산을 CUDA 커널로 분할하고 shared memory로 재사용함 | 커널 실행 시간, GPU 점유율 |
| 과학계산 시뮬레이션 | 격자 계산을 GPU로 이전하고 stream으로 전송과 계산을 겹침 | 전송 대비 계산 시간, 수치 오차 |
| LLM 추론 | matmul, attention, sampling 병목을 프로파일링하고 kernel fusion과 batch 크기를 조정함 | 토큰당 지연, 초당 토큰 수 |

## 6. 결론

CUDA는 GPU의 대량 병렬 구조를 활용하는 실무적 프로그래밍 모델이지만, 성능은 커널 작성보다 데이터 이동과 메모리 배치에서 결정되는 경우가 많음. 따라서 CUDA 적용 여부는 병렬화 가능성, 산술 강도, CPU-GPU 전송 비용, 벤더 종속성을 함께 판단해야 함.
