## 미리 알고가기

- VT-x와 AMD-V는 x86 CPU가 가상머신 실행을 직접 지원하는 하드웨어 확장임
- VM Exit은 게스트 실행 중 하이퍼바이저 개입이 필요해 CPU가 제어를 넘기는 사건임
- EPT와 NPT는 게스트 주소를 실제 물리 주소로 바꾸는 2단계 주소 변환 구조임
- 준가상화 드라이버는 에뮬레이션 대신 하이퍼바이저에 맞춘 경량 I/O 경로를 쓰는 드라이버임
- TLB는 최근 가상주소와 물리주소의 변환 결과를 저장해 페이지 테이블 조회 횟수를 줄이는 캐시임

## 작성 근거(검토용)

- 하드웨어 가상화는 VM 실행 모드, VM Exit, EPT·NPT, 인터럽트·I/O 경로를 핵심 축으로 설명함
- 비교표는 소프트웨어와 하드웨어 가상화의 특권 명령·게스트 실행, 메모리 가상화, 대표 병목을 대비함
- 실무 판단은 VM Exit 비율·I/O 지연과 EPT 미스율·원격 메모리 접근률로 검증함

## Ⅰ. 개요

- **정의/개념**: 하드웨어 가상화는 CPU의 VM 실행 모드·특권 명령 제어·2단계 주소 변환으로 수정하지 않은 게스트 OS를 격리해 실행하는 기술임
- **배경/필요성**: 특권 명령 변환과 메모리 매핑 비용을 줄이면서 게스트 호환성을 유지하기 위해 CPU 수준의 가상화 지원이 필요함

### 쉽게 이해하기 (학습용)
- 대리인을 거치지 않고 본인이 직접 창구 업무를 보되, 은행 도장이 필요한 순간에만 직원을 부르는 것과 같음

## Ⅱ. 특징

- CPU 가상화 모드에서 게스트 OS의 특권 명령을 VM Exit 조건으로 통제함
- EPT와 NPT가 게스트 물리 주소를 호스트 물리 주소로 2단계 변환함
- 특권 이벤트가 잦으면 VM Exit와 I/O 가상화 경로의 처리 시간이 증가함

### 쉽게 이해하기 (학습용)
- 직원 호출 창구(VM Exit)가 따로 있어 평소엔 셀프로 처리하지만, 호출이 잦아지면 그만큼 대기 줄이 길어짐

## Ⅲ. 종류 및 비교

| 판단 기준 | 소프트웨어 가상화 | 하드웨어 가상화 |
|:---|:---|:---|
| 특권 명령·게스트 실행 | 변환·에뮬레이션으로 특권 명령을 처리하고 게스트 수정이 필요함 | CPU가 VM 실행 모드에서 VM Exit로 통제하고 게스트를 수정 없이 실행함 |
| 메모리 가상화 | 소프트웨어가 게스트·호스트 주소 변환 테이블을 관리함 | EPT와 NPT로 2단계 주소 변환을 하드웨어가 수행함 |
| 대표 병목 | 명령 변환 비용이 큼 | VM Exit와 I/O 경로와 TLB 관련 비용이 큼 |

> 요약: 하드웨어 가상화는 CPU 실행 모드와 2단계 주소 변환을 사용하고 VM Exit·I/O·TLB 비용을 추가함.

### 쉽게 이해하기 (학습용)
- 통역사가 매 문장을 옮겨주는 방식(소프트웨어)과, 두 사람이 각자 언어로 말해도 창구 장치가 자동으로 알아듣게 하는 방식(하드웨어)의 차이와 같음

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| VM 실행 모드 | 게스트와 하이퍼바이저 실행 권한을 분리해 직접 실행과 안전한 제어를 함께 가능하게 함 |
| 제어 구조체 | 게스트 상태와 VM Exit 조건과 제어 비트를 저장해 전환 정책과 비용의 기준이 됨 |
| EPT·NPT | 게스트 물리 주소를 호스트 물리 주소로 변환해 메모리 격리와 성능을 함께 좌우함 |
| 인터럽트·I/O 가상화 | 장치 접근과 인터럽트 전달을 가상화해 실제 운영 성능과 격리 수준을 결정함 |

> 요약: VM 실행 모드와 제어 구조체가 게스트 전환을 관리하고 EPT·NPT와 I/O 가상화가 메모리·장치 접근을 중재함.

### 쉽게 이해하기 (학습용)
- 투숙객 층과 관리자 층을 나누고(VM 실행 모드), 프런트 장부에 투숙 상태를 적어두며(제어 구조체), 방 번호를 실제 건물 호수로 바꿔주는 안내판(EPT·NPT)과 벨소리를 정확히 전달하는 교환대(인터럽트·I/O)가 함께 작동함

## Ⅴ. 원리 및 절차 흐름도

1. **VM 설정**: 하이퍼바이저가 vCPU 상태와 메모리 매핑과 제어 구조를 초기화함
2. **게스트 직접 실행**: CPU가 가상머신 실행 모드에서 게스트 명령을 직접 수행함
3. **VM Exit 처리**: 특권 명령 실행, I/O 요청, 인터럽트 발생 시 하이퍼바이저로 전환함
4. **재진입 실행**: 이벤트 처리 후 게스트 상태를 갱신하고 다시 실행함

> 요약: 게스트를 CPU에서 직접 실행하고 특권 이벤트가 발생할 때만 VM Exit로 전환한 뒤 처리 후 재진입함.

### 쉽게 이해하기 (학습용)
- 대리 기사가 차 열쇠를 받아 직접 운전하다가 톨게이트에서만 차주에게 잠깐 넘기고, 통과 후 다시 운전을 이어받는 것과 같음

## Ⅵ. 실무 사례

1. 클라우드 VM 호스트는 준가상화 드라이버와 인터럽트 묶음 처리를 적용하고 VM Exit 비율·p99 I/O 지연을 확인함
2. 메모리 집약 VM은 대용량 페이지와 NUMA 배치를 적용하고 EPT 미스율·원격 메모리 접근률을 확인함

### 쉽게 이해하기 (학습용)
- 자주 오가는 우편물은 묶어 한 번에 배달하고(인터럽트 묶음), 큰 짐은 가까운 창고에서 큰 상자 단위로 꺼내 쓰는 것(대용량 페이지·NUMA)과 같음

## Ⅶ. 결론

- 하드웨어 가상화는 CPU의 VM 실행 모드와 2단계 주소 변환으로 게스트 OS를 수정 없이 직접 실행하고, 특권 이벤트가 발생할 때만 VM Exit로 하이퍼바이저에 제어를 넘김
- 특권 이벤트가 잦은 워크로드는 VM Exit 빈도·I/O 지연·EPT 미스율을 함께 측정해 준가상화 드라이버나 대용량 페이지 같은 최적화 적용 여부를 판단해야 함

### 쉽게 이해하기 (학습용)
- 자동차를 고를 때 최고속도만 보지 않고 연비·제동·소음을 함께 재듯, 하드웨어 가상화도 여러 지표를 같이 재야 실제 효과를 알 수 있음
