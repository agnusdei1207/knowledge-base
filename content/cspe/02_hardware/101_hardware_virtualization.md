## 미리 알고가기

- VT-x와 AMD-V는 x86 CPU가 가상머신 실행을 직접 지원하는 하드웨어 확장임
- VM exit은 게스트 실행 중 하이퍼바이저 개입이 필요해 CPU가 제어를 넘기는 사건임
- EPT와 NPT는 게스트 주소를 실제 물리 주소로 바꾸는 2단계 주소 변환 구조임
- 준가상화 드라이버는 에뮬레이션 대신 하이퍼바이저에 맞춘 경량 I/O 경로를 쓰는 드라이버임
- TLB는 최근 주소 변환 결과를 저장해 메모리 접근을 빠르게 하는 캐시임

## Ⅰ. 개요

- **정의/개념**: 하드웨어 가상화는 CPU가 가상머신 실행 모드와 특권 명령 제어와 2단계 메모리 주소 변환을 직접 제공해 하이퍼바이저가 게스트 OS를 높은 호환성과 격리 수준으로 실행하게 하는 기술임
- **배경/필요성**: 순수 소프트웨어 가상화는 특권 명령 변환과 메모리 매핑 비용이 커 성능과 호환성 한계가 있었으므로, 서버 통합과 클라우드 운영을 위해 CPU 수준 지원이 필요함

## Ⅱ. 특징

- 게스트 OS를 수정하지 않고도 일반 운영체제를 그대로 실행하기 좋음
- 특권 명령과 인터럽트와 I/O 접근을 CPU가 trap과 exit로 통제함
- EPT와 NPT가 소프트웨어 주소 변환 테이블 관리 부담을 줄여 메모리 가상화 효율을 높임
- 실제 병목은 직접 실행보다 VM exit 빈도와 I/O 가상화 경로에서 자주 생김

## Ⅲ. 종류 및 비교

| 판단 기준 | 소프트웨어 가상화 | 하드웨어 가상화 |
|:---|:---|:---|
| 특권 명령 처리 | 변환이나 에뮬레이션을 많이 써 오버헤드가 큼 | CPU가 VM 실행 모드와 exit를 직접 지원함 |
| 게스트 호환성 | 수정된 게스트나 우회 기법이 필요할 수 있음 | 일반 게스트 OS를 높은 호환성으로 실행하기 쉬움 |
| 메모리 가상화 | 소프트웨어가 주소 변환 테이블을 크게 관리해야 해 부담이 큼 | EPT와 NPT로 2단계 변환을 하드웨어가 지원함 |
| 대표 병목 | 명령 변환 비용이 큼 | VM exit와 I/O 경로와 TLB 관련 비용이 큼 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| VM 실행 모드 | 게스트와 하이퍼바이저 실행 권한을 분리해 직접 실행과 안전한 제어를 함께 가능하게 함 |
| 제어 구조체 | 게스트 상태와 exit 조건과 제어 비트를 저장해 전환 정책과 비용의 기준이 됨 |
| EPT·NPT | 게스트 물리 주소를 호스트 물리 주소로 변환해 메모리 격리와 성능을 함께 좌우함 |
| 인터럽트·I/O 가상화 | 장치 접근과 인터럽트 전달을 가상화해 실제 운영 성능과 격리 수준을 결정함 |

```text
+-------------+     +-------------+     +-------------+     +-------------+
| VM 설정        | --> | 게스트 직접 실행 | --> | VM exit 처리   | --> | 재진입 실행    |
+-------------+     +-------------+     +-------------+     +-------------+
```

## Ⅴ. 원리 및 절차 흐름도

1. **VM 설정**: 하이퍼바이저가 vCPU 상태와 메모리 매핑과 제어 구조를 초기화함
2. **게스트 직접 실행**: CPU가 가상머신 실행 모드에서 게스트 명령을 직접 수행함
3. **VM exit 처리**: 특권 명령과 I/O와 인터럽트 발생 시 하이퍼바이저로 전환함
4. **재진입 실행**: 이벤트 처리 후 게스트 상태를 갱신하고 다시 실행함

## Ⅵ. 실무 적용 및 유의점

1. 클라우드 VM 호스트는 하드웨어 가상화가 기본이지만 특권 명령과 타이머와 I/O가 많으면 VM exit가 급증하므로 준가상화 드라이버와 인터럽트 묶음 처리를 함께 적용하고 VM exit 비율과 CPU 대기 시간과 p99 지연시간으로 확인함
2. 메모리 집약 VM 환경은 2단계 주소 변환 비용과 TLB miss가 누적되기 쉬우므로 대용량 페이지와 NUMA 배치를 함께 조정하고 EPT miss 비율과 p99 메모리 지연시간과 원격 메모리 접근 비율로 확인함

## Ⅶ. 결론

하드웨어 가상화의 가치는 가상머신을 직접 실행하는 데 있으므로, 평가는 코어 수보다 exit 비용과 주소 변환 효율과 격리 수준을 함께 봐야 함.
