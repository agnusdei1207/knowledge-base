# 📖 【암기용】 개념 완전 이해

> 목적: 디바이스 DNA를 처음 봐도 PUF와 무엇이 다른 "고정 지문"인지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 제조 단계에서 칩마다 공장이 직접 새겨 넣는 고유하고 변경 불가능한 읽기 전용 식별자(예: FPGA의 96비트 Device DNA)
- **왜 필요한가**: 소프트웨어로 부여한 시리얼 번호는 복제·변조가 가능하다. 실리콘 제조 단계에 새긴 식별자는 공장 밖에서 재프로그래밍할 수 없어 위조 방지·라이선싱 근거가 된다.
- **핵심 직관**: 자동차 차대번호(VIN)처럼 출고 시 프레임에 각인돼 이후 누구도 바꿀 수 없는 고정 번호다.

## 깊이 이해
- **배경·문제의식**: FPGA 비트스트림 복제나 IP 무단 사용을 막으려면 칩 개별 단위로 구분되는 변경 불가능한 식별자가 필요했고, 제조사가 이를 팹 단계에서 직접 퓨즈·ROM에 프로그래밍했다.
- **작동 원리**: 제조 시 공장이 각 칩에 고유 값을 1회성 프로그래밍(예: eFuse, 마스크 ROM)으로 기록하며, 이후 JTAG 등 전용 포트로만 읽기 전용 접근이 가능하고 재기록은 불가능하다.
- **비유**: 신분증 뒷면의 일련번호는 발급 시점에 인쇄돼 이후 소유자가 절대 바꿀 수 없는 것과 같다.
- **구체 예시**: Xilinx(AMD) 7시리즈·UltraScale FPGA는 제조 시 96비트(또는 57비트) Device DNA를 내장하며, DNA_PORT 프리미티브로 비트스트림 암호화 키 유도나 라이선스 바인딩에 활용한다.
- **흔한 오해·주의점**: "디바이스 DNA도 PUF의 일종이다"는 흔한 오해다. 디바이스 DNA는 공장이 고정값을 프로그래밍한 결정론적(deterministic) ID이고, PUF는 제조 편차라는 물리적 노이즈에서 매번 유도되는 확률적 응답이다. 둘은 값의 발생 원리와 안정성 특성이 근본적으로 다르다.

## 연결 개념
- PUF — 물리적 노이즈 기반 응답 생성(디바이스 DNA와 대비되는 개념)
- FPGA AI 가속 — Device DNA로 비트스트림 암호화·라이선스를 결합하는 실제 적용처
- Secure Boot — 고정 식별자를 부팅 체인 인증 요소로 활용
- HSM — Device DNA 기반 라이선스 키를 상위에서 관리

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 디바이스 DNA 답안은 프로그래밍 시점, 읽기 전용 특성, PUF와의 발생 원리 차이를 함께 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 디바이스 DNA는 제조 단계에서 팹이 직접 새긴, 변경 불가능한 칩 고유 읽기 전용 식별자이다.
> 2. **가치**: 비트스트림 암호화 키 유도와 라이선스 바인딩의 근거가 되어 IP 무단 복제·불법 클로닝을 방지한다.
> 3. **판단 포인트**: 값이 결정론적으로 고정되는지(디바이스 DNA), 물리적 노이즈에서 확률적으로 유도되는지(PUF)로 두 개념을 구분해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 고정 식별자 원리 이해 확인 | 팹 단계 1회성 프로그래밍, JTAG 읽기 전용 접근 | 소프트웨어 시리얼 번호와 동일 개념으로 서술 |
| PUF와의 차이 구분 역량 확인 | 결정론적 고정값 vs 물리적 노이즈 기반 확률값 | 디바이스 DNA를 PUF의 하위 개념으로 혼동 |
| 실제 적용 사례 이해 확인 | FPGA 비트스트림 암호화, 라이선스 바인딩 | 적용 사례 없이 개념만 나열 |

> 요약: 이 문제는 디바이스 DNA가 PUF와 달리 결정론적 고정 식별자임을 정확히 구분해 설명해야 한다.

## Ⅰ. 개요 및 필요성

- 정의: 제조 단계에서 칩에 고정 프로그래밍된 변경 불가능한 읽기 전용 고유 식별자
- 배경: 소프트웨어 시리얼 번호는 복제·변조가 가능해 FPGA IP·비트스트림 위조 방지에 한계가 있음
- 필요성: 팹 단계에 새긴 고정값은 재프로그래밍이 불가능해 라이선스 바인딩과 위조 방지 근거로 필요함

---

## Ⅱ. 구조 및 구성요소

```text
제조(Fab) 단계 -> eFuse/마스크 ROM에 고유값 1회 프로그래밍
  -> JTAG/DNA_PORT 읽기 전용 접근
  -> 비트스트림 암호화 키 유도 / 라이선스 바인딩
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| eFuse/마스크 ROM | 고유값 저장 매체 | 1회 프로그래밍 후 재기록 불가 |
| DNA_PORT(FPGA 예시) | 칩 내부 고유값 읽기 전용 포트 | Xilinx 7시리즈 96비트 |
| JTAG 접근 경로 | 외부에서 값 조회 | 읽기만 가능, 쓰기 차단 |
| 라이선스 관리 로직 | Device DNA와 라이선스 파일 매칭 | 불일치 시 비트스트림 로드 거부 |

> 요약: 디바이스 DNA는 팹 단계 고정값을 읽기 전용 포트로만 조회해 라이선스·암호화 키 유도에 사용한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
칩 제조 -> eFuse에 고유값 기록(공장 1회)
  -> 출하 후 JTAG로 Device DNA 조회
  -> 비트스트림 암호화 키와 조합 또는 라이선스 파일과 매칭
  -> 일치 시 정상 동작, 불일치 시 로드 거부
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 팹이 제조 중 고유값을 eFuse에 기록 | 값 재기록 시도 시 물리적 차단 |
| 2 | 사용자가 JTAG로 Device DNA 조회 | 읽기 전용 권한만 허용 |
| 3 | 비트스트림 암호화 키 유도 또는 라이선스 매칭 | 값 불일치 시 로드 거부 |
| 4 | 위조 칩 여부 판별 | 등록된 DNA 목록과 대조 |

> 요약: 디바이스 DNA는 제조 시 고정된 값을 조회해 라이선스·암호화 매칭에 사용하는 단방향 흐름이다.

---

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 장점 | 팹 단계 고정값이라 소프트웨어 조작으로 변경 불가 | 위조 칩 식별에 명확한 기준 제공 |
| 한계 | 값이 노출되면 그 자체로는 영구히 고정돼 키 갱신이 불가능 | 유출 시 별도 폐기·블랙리스트 정책 필요 |
| 비교 포인트 | 디바이스 DNA(결정론적 고정값) vs PUF(물리적 노이즈 기반 확률값) | 재발급이 필요하면 PUF, 고정 식별이 목적이면 디바이스 DNA |

> 요약: 디바이스 DNA는 고정 불변이라 식별용으로 강하지만, 유출 시 대체가 불가능하다는 한계가 있다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 기존/대안 | 본 키워드 | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 소프트웨어 시리얼 번호 | 팹 단계 하드웨어 고정 식별자 | 위조 방지 신뢰도가 중요하면 디바이스 DNA |
| 비용/성능 | 별도 하드웨어 불필요 | 제조 공정에 eFuse 회로 추가 필요 | 대량 생산 IP 보호 목적이면 비용 감수 |
| 운영/위험 | 값 변경·재발급 용이 | 유출 시 재발급 불가, 블랙리스트로만 대응 | 유출 대응 절차 사전 수립 필수 |

> 요약: 위조 방지 신뢰도가 중요한 대량 생산 IP 보호에는 디바이스 DNA가 적합하되 유출 대응 절차가 필수다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 값 유출 후 재발급 불가 | 고정값 특성상 갱신 메커니즘 부재 | 블랙리스트 등록, 라이선스 서버 측 무효화 | 유출 값 블랙리스트 반영 시간 |
| 사이드채널 노출 | JTAG 접근 통제 미흡 | JTAG 잠금(Disable), 접근 인증 강화 | JTAG 접근 시도 로그 |
| 라이선스 매칭 우회 | 소프트웨어 매칭 로직 취약점 | 매칭 로직을 HSM/보안 영역에서 처리 | 매칭 실패·우회 시도 탐지 건수 |

> 요약: 디바이스 DNA 리스크는 값 유출 시 대체 불가라는 근본 한계에서 비롯되며 접근통제로 완화한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 위조 방지 효과 | 등록되지 않은 DNA 값 검출률 100% | 라이선스 서버 매칭 로그 |
| 접근 통제 | JTAG 무단 접근 시도 0건 | JTAG 접근 로그 감사 |
| 라이선스 정합성 | DNA-라이선스 매칭 오류율 0% | 배포 전 검증 테스트 |

> 요약: 도입 효과는 위조 검출률, JTAG 접근 통제 수준, 라이선스 매칭 정합성으로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 단기: FPGA 비트스트림 암호화 키를 Device DNA와 결합해 위조 칩에서의 무단 로드를 차단함
2. 중기: 라이선스 매칭 로직을 보안 영역(HSM 또는 TrustZone)에서 처리해 소프트웨어 우회를 방지함
3. 장기: JTAG 접근 통제와 유출 값 블랙리스트 체계를 라이선스 서버에 상시 반영함

**결론 (2줄):**
- 기술사 판단: 고정 식별과 위조 방지가 목적이면 디바이스 DNA, 저장 없이 재생성 가능한 키가 목적이면 PUF를 선택함
- 향후 방향: FPGA 기반 AI 가속기 확산에 따라 IP 보호를 위한 Device DNA 기반 라이선싱이 함께 확대되는 방향으로 발전함
