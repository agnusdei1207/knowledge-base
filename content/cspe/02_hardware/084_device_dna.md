## 미리 알고가기

- Device DNA는 장치마다 다른 하드웨어 고유 식별 정보를 뜻함
- fuse 값, secure ID, PUF 응답이 구현 수단이 될 수 있음
- attestation은 장치가 자신이 진짜임을 원격으로 증명하는 절차임

## Ⅰ. 개요

- **정의/개념**: Device DNA는 칩이나 장치의 고유 식별 정보와 물리 특성으로 장치 신원을 확인하고 위조와 복제를 막는 하드웨어 기반 식별 체계임
- **배경/필요성**: IoT, 차량, 산업 장비처럼 대량 배포되는 장치는 소프트웨어 시리얼 번호만으로 복제와 위조를 차단하기 어려워 장치 본체에 뿌리 둔 신원 수단이 필요함

## Ⅱ. 특징

- 장치 고유성을 바탕으로 공급망 추적과 원격 인증에 활용할 수 있음
- 단순 문자열보다 위조 저항성이 높지만 읽기 노출만으로는 보안이 완성되지 않음
- 인증서 바인딩과 attestation을 함께 설계해야 실제 신뢰 체계가 됨
- 장치 추적 오남용이 생기면 프라이버시 문제가 생길 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | 소프트웨어 시리얼 번호 | Device DNA |
|:---|:---|:---|
| 생성 기반 | 파일이나 설정에 기록한 논리 식별자에 의존함 | 칩 내부 고유 식별값이나 물리 특성에 의존함 |
| 복제 조건 | 저장된 식별자 값을 복사해 재사용 가능 | 칩 고유값을 복제하거나 인증 응답을 위조해야 함 |
| 운영 방식 | 식별자를 발급하고 데이터베이스에서 관리함 | provisioning·인증서 바인딩·attestation을 수행함 |
| 주의점 | 신뢰 수준이 낮아 보안 판단에 한계가 있음 | 읽기 노출과 추적 오남용을 함께 통제해야 함 |

> 요약: Device DNA는 논리 식별자보다 복제 저항성이 높지만 인증서 바인딩과 노출 통제가 필요함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 고유 하드웨어 ID | fuse 값, secure ID, PUF 응답이 식별의 원천이 됨 |
| provisioning 시스템 | 생산 단계에서 장치 ID, 키, 인증서를 묶어 초기 신뢰를 만듦 |
| attestation 서비스 | 장치가 원격으로 실제 자신임을 증명하도록 검증 경로를 제공함 |
| 접근·프라이버시 정책 | 누가 식별자를 읽고 어떤 서비스와 연결할지 통제해 오남용을 차단함 |

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 고유 ID 확보   | --> | 등록·인증서 바인딩 | --> | 장치 인증 요청  | --> | 신원 검증·권한 부여 |
+-------------+     +-------------+     +-------------+     +-------------+
```

> 요약: Device DNA는 고유 ID를 등록, 인증서 바인딩, 원격 증명으로 연결할 때 신뢰 수단이 됨.

## Ⅴ. 원리 및 절차 흐름도

1. **고유 ID 확보**: 제조 단계에서 장치 고유 식별 원천을 읽거나 생성함
2. **등록·인증서 바인딩**: 서비스와 연결할 키와 인증서를 고유 ID에 묶음
3. **장치 인증 요청**: 운영 중 서비스가 장치 신원 증명을 요구함
4. **신원 검증·권한 부여**: 위조 여부를 판단해 연결과 권한을 결정함

> 요약: Device DNA 절차는 고유 ID를 서비스 신뢰 체계에 묶고 운영 중 신원 증명으로 확인하는 흐름임.

## Ⅵ. 실무 적용 및 유의점

1. IoT 플랫폼이나 정품 인증 체계는 Device DNA가 복제 장치 판별에 유리하지만 읽기 가능한 ID만 노출하면 재사용 공격이 가능하므로 질의-응답 증명과 인증서 바인딩을 두고 증명 성공률, 복제 장치 탐지율, 식별자 결합 정확도로 확인함
2. 장치 추적 가능성이 민감한 환경은 고유 식별자 오남용이 규제 이슈로 번질 수 있으므로 가명 식별자와 접근 권한 분리를 적용하고 식별자 노출 건수, 개인정보 감사 결과, 비인가 조회 건수로 확인함

## Ⅶ. 결론

Device DNA의 가치는 ID 문자열 자체가 아니라 그 ID를 신뢰 체계와 어떻게 묶어 운영하느냐에 있음.
