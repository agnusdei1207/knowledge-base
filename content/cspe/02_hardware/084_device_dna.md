## Ⅰ. 개요
- **정의**: FPGA·SoC 내부의 SRAM PUF 기반 고유 식별자를 활용한 칩 인증 기술
- **배경/필요성**: 소프트웨어 기반 시리얼 넘버는 복제 가능하므로, 칩 물리 특성에 기반한 위변조 불가능한 식별 체계가 필요함
- **비유**: 생물의 DNA가 개체마다 고유하듯, 반도체 공정 편차가 칩마다 고유한 식별 정보를 생성함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| PUF 기반 칩 고유 식별 응용 | PUF(083)과의 관계·차이 | Device DNA는 PUF의 상용 구현체임을 명시 |

> 요약: Device DNA는 PUF 기술을 상용 FPGA에 적용하여 칩 수준의 고유 인증을 제공하는 기술임

## Ⅱ. 구성요소
```text
+------ FPGA/SoC Chip ------+
|                            |
|  +--------+  +----------+ |
|  | SRAM   |->| Device   | |
|  | PUF    |  | DNA Block| |
|  +--------+  +----------+ |
|                  |         |
|           +------v------+  |
|           | Key Derivation| |
|           | Function     | |
|           +------+------+  |
|                  |         |
|           +------v------+  |
|           | Crypto Core  | |
|           +--------------+ |
+----------------------------+
        |
   Encrypted Bitstream
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| SRAM PUF | 전원 인가 시 SRAM 셀의 초기 상태 편차로 고유 비트열 생성 | 신생아의 지문 |
| Device DNA Block | SRAM PUF 출력을 안정화하여 256비트 고유 ID로 변환 | 지문에서 추출한 특징점 벡터 |
| Key Derivation Function | Device DNA 값에서 암호 키를 파생 | 지문으로 금고 비밀번호 생성 |
| Crypto Core | 파생된 키로 비트스트림 복호화·인증 수행 | 비밀번호로 금고를 여는 동작 |
| Encrypted Bitstream | Device DNA 키로 암호화된 FPGA 설계 데이터 | 특정 금고에서만 열리는 봉인 문서 |

> 요약: SRAM PUF에서 고유 ID를 추출하고, 이를 키로 파생하여 비트스트림을 암호화 보호하는 구조임

## Ⅲ. 절차
```text
전원 인가 --> SRAM PUF 초기 상태 수집
  --> Device DNA 256-bit ID 생성
    --> KDF로 암호 키 파생
      --> 비트스트림 복호화 및 FPGA 구성
```
- 1단계: 전원 인가 시 SRAM 셀이 공정 편차에 따라 0 또는 1로 초기화되며 PUF 원시 데이터 수집
- 2단계: Fuzzy Extractor(083 참조)가 노이즈를 보정하여 256비트 고유 Device DNA 값 생성
- 3단계: KDF(Key Derivation Function)가 Device DNA 값을 입력으로 비트스트림 복호화용 AES 키 파생
- 4단계: 파생된 키로 암호화된 비트스트림을 복호화하여 FPGA 로직을 구성하고, 키 불일치 시 구성 거부

> 요약: 전원 인가 → PUF ID 생성 → 키 파생 → 비트스트림 복호화의 흐름으로 칩 바인딩을 실현함

## Ⅳ. 문제점
- 노화 열화: 장기 사용 시 SRAM 셀 특성 변화로 Device DNA 값이 드리프트 — 인증 실패 가능성 증가
- 칩 종속 잠금: 특정 칩에 바인딩된 비트스트림은 해당 칩 고장 시 복구 불가 — 유지보수 유연성 저하
- 벤더 종속: Device DNA 구현이 FPGA 벤더별 독자 규격 — 멀티벤더 환경에서 호환성 부재

> 요약: 노화 드리프트, 칩 종속 잠금, 벤더 종속이 Device DNA 운영의 주요 제약임

## Ⅴ. 개선방안
1. 단기: ECC 기반 Helper Data 주기적 재등록으로 노화에 따른 비트 드리프트 보상
2. 중기: 키 에스크로(Key Escrow) 체계 도입으로 칩 고장 시 대체 칩에 비트스트림 재바인딩 가능하게 함
3. 장기: IEEE 또는 ISO 표준 기반 PUF 인터페이스 규격 통일로 멀티벤더 호환성 확보

> 요약: Helper Data 갱신, 키 에스크로, 표준화로 운영 안정성과 호환성을 확보함

## Ⅵ. 전망
- 발전 방향: 자동차·의료기기 등 안전 필수 시스템에서 위조 부품 탐지 수단으로 확대 적용
- 기술사적 판단: Device DNA와 PUF(083)의 결합이 IoT 디바이스 Root of Trust 표준으로 정착 중임
- 기술사 제언: 설계 단계에서 Device DNA 노화 마진과 키 복구 정책을 수립하는 것이 필요
