## 미리 알고가기

- Device DNA: DNA(Deoxyribonucleic Acid)의 비유를 차용해 장치마다 다른 하드웨어 고유 식별 정보를 이용하는 개념 또는 기능임
- Unique ID(Identifier): 제조 시 부여되거나 칩 내부 특성에서 도출되는 장치 고유 식별자임
- Provisioning: 제조·등록 단계에서 장치 ID, 키, 인증서를 서비스와 연결하는 절차임
- Attestation: 장치가 자신의 신원과 상태를 원격 검증자에게 증명하는 과정임
- Anti-Cloning: 동일한 ID나 기능을 가진 위조 장치를 만들기 어렵게 하는 보호 특성임

## Ⅰ. 개요

- **정의**: Device DNA는 칩이나 장치가 가진 고유 식별 정보, PUF(Physical Unclonable Function) 응답, fuse 값, 보안 저장소의 ID를 활용해 장치 신원을 구분하고 복제 여부를 판단하는 하드웨어 기반 식별 체계로, 고유성, 변경 불가성, 읽기 권한, 인증서 바인딩, 개인정보 영향을 기준으로 장치 등록과 위조 방지에 사용함
- **배경/필요성**: IoT(Internet of Things), 차량, 산업 장비는 대량 배포되며 위조 장치, 복제 펌웨어, 불법 수리 부품을 식별해야 함. 소프트웨어 시리얼 번호만으로는 복사와 조작이 쉬워 하드웨어에 뿌리 둔 식별 값이 필요함
- **비유**: 제품 박스에 붙은 스티커 번호가 아니라 제품 재료 자체에 새겨진 고유 지문을 서비스 등록과 보증 확인에 쓰는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 하드웨어 기반 장치 식별 설명 | Unique ID, PUF, provisioning, attestation | MAC(Media Access Control) 주소나 시리얼 번호만으로 축소 |
| 위조 방지와 개인정보 판단 | 복제 저항, 인증서 바인딩, 추적 위험 | 고유 ID 공개의 프라이버시 위험 누락 |

> 요약: Device DNA는 장치 고유성을 보안 서비스와 연결해 위조 방지, 등록, 원격 신원 확인에 활용하는 식별 체계임.

## Ⅱ. 특징/비교

| 판단 기준 | 소프트웨어 시리얼 | PUF | Device DNA |
|:---|:---|:---|:---|
| 생성 기준 | 파일, 설정, 펌웨어에 저장된 값 | 제조 편차에서 생성되는 응답 | 칩 고유 ID, PUF, fuse, 인증서 바인딩의 조합 |
| 복제 저항 | 복사가 쉬워 위조에 취약함 | 물리 복제가 어려움 | 저장형 ID와 물리 특성을 정책으로 결합함 |
| 활용 목적 | 자산 관리, 표시용 식별 | 키 생성, 강한 장치 인증 | 제품 등록, 라이선스, attestation, 위조 부품 탐지 |
| 운영 이슈 | 변경·조작 가능성 | 환경 안정성 필요 | 개인정보, ID 노출, 프로비저닝 품질 관리 필요 |

> 요약: Device DNA는 단일 값이 아니라 장치 고유 식별 정보를 보안 프로비저닝과 검증 절차에 연결하는 운영 체계임.

- **식별 기준**: ID가 장치마다 충분히 달라야 하고 제조 중복이나 재사용이 없어야 함
- **보호 기준**: 고유 ID가 평문으로 노출되면 추적과 복제 시도가 가능하므로 인증된 접근이 필요함
- **연계 기준**: 장치 ID는 인증서, 키, 제조 이력, 서비스 권한과 안전하게 바인딩되어야 함

## Ⅲ. 구성요소

```text
+----------+      +----------+      +----------+
| Unique   | ---> | Secure   | ---> | Provision|
| Source   |      | Read     |      | Identity |
+----------+      +----+-----+      +----+-----+
                         |                 |
                         v                 v
                   +----------+      +----------+
                   | Cert/Key | ---> | Attest   |
                   | Binding  |      | Service  |
                   +----------+      +----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 고유 ID 원천 | fuse, eFuse, ROM(Read-Only Memory) ID, PUF, 보안 요소처럼 장치마다 다른 값을 제공함 | 지문 원판 |
| 보안 읽기 로직 | 고유값 접근 권한과 읽기 조건을 제어해 무단 추출을 막음 | 신분증 발급 창구 |
| 프로비저닝 시스템 | 제조 단계에서 ID를 인증서, 키, 제품 이력과 연결함 | 주민등록 절차 |
| 인증서·키 바인딩 | 장치 ID를 암호학적 신원으로 변환해 원격 검증에 사용함 | 공인 신분증 |
| 검증 서비스 | 장치 등록, 라이선스 확인, 위조 탐지, 원격 attestation을 수행함 | 출입 심사대 |

> 요약: Device DNA는 고유 ID 원천을 안전하게 읽고 인증서·키·서비스 등록 정보와 결합해 장치 신원을 증명함.

## Ⅳ. 절차

```text
+----------+      +----------+      +----------+      +----------+
| Manufacture| -->| Provision| ---> | Present  | ---> | Verify   |
| Device     |    | Identity |      | Proof    |      | Service  |
+----------+      +----------+      +----------+      +----------+
```

1. **고유값 생성·읽기**: 제조된 칩에서 fuse ID, PUF 응답, 보안 요소 ID 같은 장치 고유값을 확보함
2. **프로비저닝**: 고유값을 인증서, 키, 제품 이력, 권한 정보와 안전하게 바인딩함
3. **신원 제시**: 장치가 서비스 접속이나 부팅 검증 시 고유 ID 자체가 아닌 서명된 증명을 제출함
4. **검증·운영**: 서버가 인증서 체인, 제조 이력, 폐기 상태, 위조 여부를 확인하고 권한을 부여함

> 요약: Device DNA 활용은 제조 고유값을 보안 신원으로 등록하고 서비스 시 암호학적으로 검증하는 절차임.

## Ⅴ. 문제점

- **P1 단순 ID 복제**: 고유 ID를 평문으로 읽을 수 있으면 공격자가 값을 복사해 위조 장치에 심을 수 있음
- **P2 개인정보·추적 위험**: 변하지 않는 장치 ID가 외부에 반복 노출되면 사용자와 장치 이동 경로를 추적할 수 있음
- **P3 프로비저닝 오류**: 제조 단계에서 ID, 인증서, 키, 제품 이력이 잘못 매핑되면 정품 장치도 인증 실패하거나 위조 탐지가 약해짐

> 요약: Device DNA는 고유성만으로 충분하지 않으며 ID 보호, 프라이버시, 제조 등록 품질이 함께 보장되어야 함.

## Ⅵ. 개선방안

1. **단기**: ID 읽기 권한, 인증서 바인딩, 제조 등록 데이터의 중복·오류를 점검함
2. **중기**: PUF 기반 키, 보안 요소, challenge-response 인증, 가명 식별자를 적용함
3. **장기**: 제품 수명주기 전반의 장치 신원 관리와 폐기·이전 정책을 서비스 거버넌스로 운영함

- **P1 대응**: 고유 ID 직접 노출 대신 서명 기반 challenge-response와 보안 저장소를 사용함 (확인: ID 평문 노출 차단)
- **P2 대응**: 서비스별 가명 ID, 회전 식별자, 최소 공개 원칙을 적용함 (확인: 외부 추적 가능성 평가)
- **P3 대응**: 프로비저닝 자동 검증, 인증서 폐기 목록, 제조 이력 감사 로그를 운영함 (확인: 등록 오류율, 인증 실패 분석)

> 요약: Device DNA 개선은 고유 ID를 숨기고 암호학적 증명으로 전환하며 프로비저닝 품질을 관리하는 방향이어야 함.

## Ⅶ. 전망

- **발전 방향**: Device DNA는 PUF, 보안 부팅, 원격 증명, 제조 이력 추적과 결합해 칩에서 클라우드까지 이어지는 장치 신원 체계로 확대됨
- **기술사적 판단**: 고유값 생성 방식, 개인정보 영향, 프로비저닝 절차, 클라우드 바인딩, 폐기·교체, RMA(Return Merchandise Authorization) 정책을 함께 설계함. 충돌률, 읽기 안정성, 등록 성공률, 복제 탐지율, 원격 증명 바인딩, 개인정보 노출 가능성을 생산 배치별로 확인함
- **기술사 제언**: Device DNA는 단순 고유번호가 아니라 보안 프로비저닝, 권한 관리, 개인정보 보호를 함께 다루는 장치 신원 기준으로 설명함
