## 미리 알고가기

- Device DNA는 장치마다 다른 하드웨어 고유 식별 정보를 뜻함
- 퓨즈 값·보안 ID·PUF 응답이 하드웨어 식별값의 구현 수단이 됨
- 원격 증명(attestation)은 장치가 자신이 진짜임을 원격으로 증명하는 절차임
- 프로비저닝(provisioning)은 생산 단계에서 장치 ID·키·인증서를 등록하는 절차임

## 작성 근거(검토용)

- 디바이스 DNA는 하드웨어 ID, 프로비저닝, 인증서 바인딩, 원격 증명을 핵심 축으로 설명함
- 비교표는 소프트웨어 시리얼 번호와 하드웨어 ID의 생성 기반, 복제 조건, 운영·주의사항을 대비함
- 실무 판단은 증명 성공률·복제 장치 탐지율과 식별자 노출·비인가 조회 건수로 검증함

## Ⅰ. 개요

- **정의/개념**: 디바이스 DNA는 칩의 고유 식별값이나 물리 특성을 키·인증서와 결합해 장치 신원을 확인하는 하드웨어 기반 식별 체계임
- **배경/필요성**: 소프트웨어 시리얼 번호의 복제·위조를 식별하기 위해 하드웨어 고유값에 기반한 장치 신원 수단이 필요함

### 쉽게 이해하기 (학습용)
- 차대번호처럼 차체에 새겨진 고유번호를 등록증·열쇠와 묶어 진짜 차량임을 확인하는 것과 같음
- 종이에 적힌 번호는 베끼기 쉽지만 차체에 새겨진 번호는 위조하기 어려움

## Ⅱ. 특징

- 장치 고유성을 바탕으로 공급망 추적과 원격 인증에 활용할 수 있음
- 단순 문자열보다 위조 저항성이 높지만 읽기 노출만으로는 보안이 완성되지 않음
- 인증서 바인딩과 원격 증명을 함께 설계해야 실제 신뢰 체계가 됨
- 장치 추적 오남용이 생기면 프라이버시 문제가 생길 수 있음

### 쉽게 이해하기 (학습용)
- 차대번호로 부품 이력을 추적하고 원격으로도 진품 여부를 확인할 수 있음
- 번호만 보여준다고 끝이 아니라 등록증과 실제 검증 절차가 있어야 진짜로 믿을 수 있음
- 번호를 너무 자주 조회하면 소유자의 이동 경로가 드러나는 문제도 생김

## Ⅲ. 종류 및 비교

| 판단 기준 | 소프트웨어 시리얼 번호 | Device DNA |
|:---|:---|:---|
| 생성 기반 | 파일이나 설정에 기록한 논리 식별자에 의존함 | 칩 내부 고유 식별값이나 물리 특성에 의존함 |
| 복제 조건 | 저장된 식별자 값을 복사해 재사용 가능 | 칩 고유값을 복제하거나 인증 응답을 위조해야 함 |
| 운영·주의사항 | 식별자를 발급·관리하지만 그 자체로 진위를 증명할 수 없음 | 프로비저닝·인증서 바인딩·원격 증명을 수행하고 읽기 노출·추적 오남용을 통제함 |

> 요약: Device DNA는 논리 식별자보다 복제 저항성이 높지만 인증서 바인딩과 노출 통제가 필요함.

### 쉽게 이해하기 (학습용)
- 소프트웨어 일련번호는 종이에 적은 번호라 그대로 베끼면 복제됨
- Device DNA는 차체에 새겨진 번호라 차체 자체를 통째로 복제해야 흉내 낼 수 있음

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 고유 하드웨어 ID | 퓨즈 값·보안 ID·PUF 응답이 식별의 원천이 됨 |
| 프로비저닝 시스템 | 생산 단계에서 장치 ID·키·인증서를 묶어 초기 신뢰를 만듦 |
| 원격 증명 서비스 | 장치가 원격으로 실제 자신임을 증명하도록 검증 경로를 제공함 |
| 접근·프라이버시 정책 | 누가 식별자를 읽고 어떤 서비스와 연결할지 통제해 오남용을 차단함 |

> 요약: Device DNA는 고유 ID를 등록, 인증서 바인딩, 원격 증명으로 연결할 때 신뢰 수단이 됨.

### 쉽게 이해하기 (학습용)
- 차체에 새겨진 번호(고유 하드웨어 ID)를 출고할 때 등록증·열쇠와 묶고(프로비저닝)
- 이후 진짜 차량인지 원격으로 확인하며(원격 증명), 누가 번호를 조회할 수 있는지도 통제함(접근·프라이버시 정책)

## Ⅴ. 원리 및 절차 흐름도

1. **고유 ID 확보**: 제조 단계에서 장치 고유 식별 원천을 읽거나 생성함
2. **등록·인증서 바인딩**: 서비스와 연결할 키와 인증서를 고유 ID에 묶음
3. **장치 인증 요청**: 운영 중 서비스가 장치 신원 증명을 요구함
4. **신원 검증·권한 부여**: 위조 여부를 판단해 연결과 권한을 결정함

> 요약: Device DNA 절차는 고유 ID를 서비스 신뢰 체계에 묶고 운영 중 신원 증명으로 확인하는 흐름임.

### 쉽게 이해하기 (학습용)
- 출고 시 차대번호를 확인해 등록증에 묶어두고, 운행 중에는 검문소가 그 번호를 조회함
- 등록된 번호와 일치하면 통행을 허가하는 흐름과 같음

## Ⅵ. 실무 사례

1. IoT 장치 플랫폼은 질의-응답 증명을 수행하고 인증서 바인딩을 적용하며 증명 성공률·복제 장치 탐지율을 확인함
2. 사내 장비 관리 플랫폼은 가명 식별자를 부여하고 접근 권한을 분리해 식별자 노출 건수·비인가 조회 건수를 확인함

### 쉽게 이해하기 (학습용)
- IoT 기기는 진품 확인 절차를 거쳐 가짜 기기가 섞여 있는지 걸러냄
- 사내 장비는 실제 번호 대신 가명표를 붙여 아무나 원래 번호를 못 보게 함

## Ⅶ. 결론

- 디바이스 DNA는 칩 고유 식별값을 키·인증서와 결합해 소프트웨어 시리얼 번호보다 위조·복제가 어려운 장치 신원을 만들되, 식별값을 보여주는 것만으로는 진위를 증명하지 못함
- 공급망 추적과 원격 인증에는 프로비저닝·인증서 바인딩·질의응답 증명을 함께 운영하고, 식별자 조회 권한을 제한해 추적 오남용을 막아야 함

### 쉽게 이해하기 (학습용)
- 차체 번호를 등록증과 묶어두는 것만으로는 부족함
- 진품 확인 절차와 번호 열람 권한 관리까지 함께 운영해야 진짜 신뢰를 얻음
