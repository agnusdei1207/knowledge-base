# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: CPU가 주변 장치의 긴급 요청을 식별하고 우선순위를 판별해 적절한 처리 루틴(ISR)으로 분기하는 하드웨어적 메커니즘
- **왜 필요한가**: 수많은 주변 장치(키보드, 마우스, 타이머, 디스크)가 동시에 인터럽트를 요청할 때, "누가 불렀는지", "누구부터 처리할지"를 빠르고 정확하게 결정해야 시스템이 꼬이지 않는다.
- **핵심 직관**: 교실에서 여러 학생(장치)이 동시에 질문(인터럽트)할 때, 선생님(CPU)이 앞줄부터 차례로 묻거나(데이지 체인), 학생 고유번호를 보고 즉시 해당 답변 매뉴얼(벡터)을 펴는 방식이다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| ISR (Interrupt Service Routine) | 특정 인터럽트 발생 시 실행할 코드(함수) 주소 | "질문 번호에 맞는 답변 매뉴얼" |
| 데이지 체인 (Daisy Chain) | 장치들을 직렬(선 하나)로 연결해 우선순위 순으로 묻는 하드웨어 폴링 | "앞줄부터 차례로 질문표를 넘기는 방식" |
| 벡터 인터럽트 (Vectored Interrupt) | 장치가 자신의 고유 번호(벡터)를 버스에 실어 보내는 방식 | "질문표에 학생 번호가 적혀 있어 바로 식별" |
| PIC (Programmable Interrupt Controller) | 여러 장치의 인터럽트를 모아 우선순위를 조정하고 CPU에 전달하는 칩 | "선생님 대신 질문을 걷어 중요도순으로 정리해주는 반장" |

## 깊이 이해
- **배경·문제의식**: 장치가 한두 개일 때는 CPU가 장치들을 하나씩 검사(소프트웨어 폴링)하면 됐다. 하지만 장치가 수십 개로 늘어나자 검사 시간만으로 지연이 너무 커졌다. 장치가 자신을 즉시 증명하는 방법이 필요해졌다.
- **작동 원리**:
  - **소프트웨어 폴링**: CPU가 INTR 신호를 받으면, 인터럽트를 요청한 장치를 찾을 때까지 모든 장치의 상태 레지스터를 S/W로 확인한다. 느리다.
  - **데이지 체인**: INTA(인터럽트 확인) 신호가 장치들을 직렬 회로로 통과한다. 신호를 처음 받은 장치(보통 CPU와 가까움)가 우선순위가 높고 요청자면 멈춘다. 속도는 중간.
  - **벡터 인터럽트**: 장치가 고유 ID(벡터)를 데이터 버스에 올린다. CPU는 이 벡터를 인덱스로 삼아 메모리의 인터럽트 벡터 테이블(IVT)에서 ISR 주소를 즉시 찾아 실행한다. 매우 빠르다.
- **비유**: 식당에서 콜벨이 울렸을 때, 알바생이 모든 테이블을 돌아보며 찾는 것(소프트웨어 폴링), 1번 테이블부터 순서대로 쳐다보는 것(데이지 체인), 벨 화면에 '5번 테이블'이라 바로 뜨는 것(벡터)의 차이다.
- **구체 예시**: x86 구조에서는 APIC(Advanced PIC)가 최대 255개의 벡터를 관리하며, 타이머는 벡터 32, 키보드는 벡터 33 번호로 CPU에 신호를 보낸다.
- **흔한 오해·주의점**: "폴링은 무조건 S/W 기법이다"는 오해다. 데이지 체인은 하드웨어 신호 선을 이용한 하드웨어적 폴링 기법이다.

## 연결 개념
- 문맥 교환 (Context Switching) — 인터럽트 처리 전 현재 CPU 레지스터 상태를 스택에 백업하는 과정
- 우선순위 역전 (Priority Inversion) — 우선순위가 높은 인터럽트가 낮은 우선순위 락에 막혀 대기하는 현상

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 인터럽트 처리는 다중 입출력 장치의 비동기적 요청을 식별하고, 우선순위를 중재하여 정확한 서비스 루틴(ISR) 주소로 분기하는 식별 메커니즘이다.
> 2. **가치**: 소프트웨어적 확인 절차를 하드웨어(데이지체인, 벡터, PIC)로 대체함으로써 식별 지연(Latency)을 최소화하고 실시간 처리성을 보장한다.
> 3. **판단 포인트**: 장치 수와 요구 응답 속도에 따라 회로 복잡도(비용)와 식별 속도 간의 트레이드오프를 고려해 S/W 폴링, 하드웨어 데이지체인, 벡터 방식을 선택해야 한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 다중 인터럽트 식별/중재 메커니즘 이해 | S/W 폴링, 데이지체인, 벡터 인터럽트 비교, 우선순위 | 인터럽트 자체의 정의만 쓰고 다중 장치 식별 원리를 누락 |
| 하드웨어 비용과 성능의 트레이드오프 | 벡터 버스 회로망 복잡성, 데이지체인 직렬 지연 | 방식 간 비교 없이 나열식 서술에 그침 |
| 인터럽트 처리 세부 절차 파악 | 백업(Context Save) -> 원인 식별 -> ISR 주소 계산 -> 복원 | 식별 단계(Vector Table)를 건너뛰고 바로 실행으로 서술 |

> 요약: 인터럽트 발생 자체보다, "여러 장치 중 누가 불렀는가(원인 식별)"와 "어떤 코드(ISR)를 실행할 것인가(주소 매핑)"를 빠르고 충돌 없이 찾아내는 구조에 초점을 맞춰야 한다.

## Ⅰ. 개요 및 필요성

- 개요: 인터럽트 처리 방식은 복수의 주변 장치가 CPU에 처리를 요청할 때, 요청 소스를 식별하고 우선순위를 중재하여 ISR(Interrupt Service Routine)을 실행하는 메커니즘이다.
- 배경: 시스템 내 주변 장치 개수가 증가함에 따라 소프트웨어 루프 기반 장치 식별 방식은 CPU 오버헤드와 응답 지연을 초래함
- 필요성: 실시간 응답이 요구되는 I/O 처리에서, 하드웨어 회로를 통해 식별 시간을 O(1) 수준으로 단축하고 병목을 제거하기 위해 필수적임

---

## Ⅱ. 구조 및 구성요소

```text
Devices(1~N) -> Interrupt Request(INTR) -> [ 식별/중재기 (PIC/Daisy/S/W) ]
                    |
                    +-> Vector Generation -> CPU -> IVT(Interrupt Vector Table) -> ISR 실행
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| 인터럽트 컨트롤러 (PIC) | 다중 INTR 선을 수렴해 우선순위 중재 후 단일 CPU 신호로 변환 | IRQ 마스킹 및 우선순위 프로그래밍 지원 |
| 인터럽트 벡터 테이블 (IVT) | 고유 번호(Vector)와 해당 ISR 시작 주소를 매핑한 메모리 테이블 | 커널 메모리 영역에 고정적으로 유지 |
| 데이지 체인 회로 | 장치들을 직렬 릴레이로 연결해 S/W 개입 없이 하드웨어적 식별 | CPU에 가까울수록 하드웨어 우선순위 높음 |
| 시스템 버스 | 식별된 인터럽트 벡터 번호를 CPU의 데이터 버스로 전송 | 장치와 CPU 간 고속 신호 전달 |

> 요약: 중재기를 통해 장치의 요청을 정리하고, 벡터 테이블을 통해 실행할 주소를 즉시 매핑하는 구조이다.

---

## Ⅲ. 동작원리 및 흐름도

```text
장치 INTR 발생 -> CPU INTA 응답 -> 원인 식별(데이지/벡터) -> 문맥 저장
-> 벡터 기반 ISR 주소 분기 -> ISR 실행 -> 문맥 복원 및 복귀(IRET)
```

- 1단계 [요청 및 확인]: 장치가 INTR 신호를 보내면 CPU가 현재 명령어 사이클 종료 후 INTA 신호로 응답한다.
- 2단계 [원인 식별]: S/W 폴링, 데이지체인, 또는 벡터 버스를 통해 요청 장치의 ID(벡터 번호)를 획득한다.
- 3단계 [문맥 저장 및 분기]: 현재 상태(PC, 레지스터)를 스택에 푸시하고, 획득한 벡터로 IVT를 조회해 ISR 주소로 점프한다.
- 4단계 [실행 및 복귀]: ISR 완료 후 IRET 명령을 통해 스택에서 상태를 팝하여 원래 흐름으로 복귀한다.

> 요약: 현재 작업을 안전하게 백업한 후, 식별된 벡터 번호로 해당 ISR을 즉시 찾아 실행하고 복귀하는 일련의 과정이다.

---

## Ⅳ. 특징

- [소프트웨어 폴링]: 하드웨어 추가 비용(선로, 컨트롤러)이 0에 가깝지만, 장치가 많을수록 O(N)의 식별 지연(Latency)이 발생함
- [데이지 체인 (Daisy Chain)]: S/W 개입 없이 INTA 신호의 물리적 도달 순서로 자동 식별하므로 중간 속도와 회로 절감을 달성함
- [벡터 인터럽트 (Vectored)]: 데이터 버스로 고유 번호를 직접 전송하여 O(1) 시간에 즉시 분기 가능하나, 병렬 회로 복잡도가 큼
- [유연성]: PIC와 결합된 최신 벡터 방식은 S/W 레벨에서 우선순위를 동적 재할당(Masking)할 수 있어 실시간 운영체제(RTOS)에 적합함

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 소프트웨어 폴링 | 데이지 체인 | 벡터 인터럽트 | 선택 기준 |
|:---|:---|:---|:---|:---|
| 식별 원리 | ISR 내 소프트웨어 루프 검사 | INTA 신호 직렬 통과 검사 | 데이터 버스로 고유 ID 전송 | 하드웨어 지원 여부 |
| 식별 속도 / 지연 | 매우 느림 / 장치 수에 비례 | 중간 / 후순위 장치 지연 | 매우 빠름 / 상수 시간(즉시) | 실시간 응답 요구 사항 |
| 구현 비용 | 회로 불필요 | 단일 직렬 제어 선 추가 | 병렬 버스 및 벡터 논리 회로 | 설계 예산 및 면적 제약 |

> 요약: 비용이 극한으로 제약된 초소형 임베디드는 폴링이나 데이지체인을, 성능이 중요한 범용 컴퓨팅이나 RTOS는 벡터 방식을 선택한다.

**리스크·대응:**
- [우선순위 역전]: 하위 인터럽트가 락을 선점해 상위 인터럽트가 지연됨 → [대응] 우선순위 상속(Priority Inheritance) 프로토콜 적용 (지표: 마감시간 준수율)
- [식별 신호 충돌]: 여러 장치가 동시 벡터 전송 시 버스 충돌 → [대응] APIC(Advanced PIC) 기반 정교한 우선순위 중재망 설계 (지표: 버스 오류 발생률 0건)

**도입 후 점검 지표:**
- 인터럽트 레이턴시: 하드웨어 요청부터 첫 ISR 명령어 실행까지의 시간(μs) — 실시간 제약 조건 충족 여부 확인
- 오버헤드 비율: 총 CPU 사이클 중 ISR 및 문맥 교환이 차지하는 비율 — 5% 미만 유지 설계

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. RTOS 기반 임베디드 설계: 마이크로컨트롤러 내부에 중첩형 벡터 인터럽트 컨트롤러(NVIC)를 채택하여 꼬리 물기(Tail-chaining) 방식으로 문맥 교환 지연 최소화
2. 멀티코어 최적화: SMP 환경에서 IOAPIC(I/O Advanced PIC)를 구성하여 코어 간 인터럽트 부하(Affinity)를 분산 매핑
3. PCIe MSI-X 도입: 최신 고속 버스에서는 물리 선로 대신 메모리 쓰기 메시지(Message Signaled Interrupts) 기반 가상 벡터로 회로 제약 없이 수천 개 인터럽트 수용

**결론 (2줄):**
- 기술사 판단: 인터럽트 식별 성능은 시스템 전체 레이턴시의 핵심 병목이므로, 고성능 시스템일수록 H/W 기반의 벡터 처리와 MSI-X 전환이 필수적임
- 향후 방향: 가상화 환경에서는 하이퍼바이저 개입으로 인한 가상 인터럽트 지연이 크므로, VT-d 및 하드웨어 패스스루 기반의 인터럽트 직접 주입 기술이 요구됨
