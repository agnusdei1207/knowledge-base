## 미리 알고가기

- 인터럽트는 비동기 이벤트가 발생했을 때 CPU 실행 흐름을 잠시 바꾸는 메커니즘임
- 벡터 방식은 인터럽트 번호로 ISR 주소를 조회하고, 데이지체인은 장치 연결 순서로 우선순위를 정함
- 핵심 지표는 인터럽트 지연, 우선순위 판정 시간, ISR 실행 시간임
- ISR(인터럽트 서비스 루틴): 인터럽트 발생 시 실행되는 처리 코드임
- IRQ(인터럽트 요청): 장치가 CPU 또는 컨트롤러에 서비스를 요청하는 신호임
- 마스킹: 특정 인터럽트의 수신을 일시적으로 차단하는 제어임
- 에지·레벨 트리거: 신호가 바뀌는 순간(에지) 또는 신호가 유지되는 상태(레벨)로 인터럽트 발생을 감지하는 방식임

## 작성 근거(검토용)

- 인터럽트 처리는 원인 식별, 우선순위, ISR 길이를 핵심 판단축으로 삼음
- 벡터와 데이지체인은 요청 식별·우선순위 판정, 우선순위 변경, 장치 증가 영향을 기준으로 비교함
- 실무 판단은 최악 인터럽트 지연, ISR 실행 시간, 장치별 서비스 지연으로 구체화함

## Ⅰ. 개요

- **정의/개념**: 인터럽트 처리 방식은 장치·예외의 서비스 요청을 식별하고 우선순위를 정한 뒤 ISR로 분기해 원래 작업으로 복귀시키는 제어 구조임
- **배경/필요성**: 폴링만으로는 비동기 장치 이벤트를 적시에 처리하기 어렵기 때문에 응답성과 CPU 활용률을 확보하는 비동기 제어 방식이 필요함

### 쉽게 이해하기 (학습용)
- 일하다가 벨소리가 나면 하던 일을 잠시 멈추고 누가 왔는지 확인한 뒤 응대하고, 끝나면 원래 하던 일로 돌아가는 것과 같음

## Ⅱ. 특징

- CPU가 인터럽트를 수락하면 현재 명령을 마친 뒤 ISR로 분기함
- 인터럽트 컨트롤러와 벡터 테이블 설계에 따라 식별 속도와 확장성이 달라짐
- 우선순위와 마스킹 정책이 실시간성에 직접 영향을 줌
- ISR이 길어지면 전체 시스템 지연과 중첩 처리 부담이 증가함

### 쉽게 이해하기 (학습용)
- 지금 하던 응대가 끝나야 다음 벨을 받고, 응대 중엔 다른 벨소리를 잠시 무시(마스킹)하며, 응대 시간이 길어지면 뒤에 대기하는 손님들이 밀림

## Ⅲ. 종류 및 비교

| 판단 기준 | 벡터 인터럽트 | 데이지체인 |
|:---|:---|:---|
| 요청 식별·우선순위 판정 | 벡터 번호로 ISR 조회 후 컨트롤러가 우선순위 판정 | 체인 앞쪽 장치부터 승인 신호로 응답 |
| 우선순위 변경 | 컨트롤러 레지스터·소프트웨어로 설정 | 장치 연결 순서 변경 필요 |
| 장치 증가 영향 | 벡터·컨트롤러 입력 확장 | 승인 신호 전파 단계 증가 |

> 요약: 벡터 인터럽트는 번호로 ISR을 선택하고, 데이지체인은 앞 장치부터 승인 신호를 전달해 뒤 장치의 대기 시간이 누적됨.

### 쉽게 이해하기 (학습용)
- 번호표를 뽑아 바로 담당 창구를 찾아가는 방식(벡터)과, 줄을 서서 앞사람이 넘겨줘야 다음 사람 차례가 오는 방식(데이지체인)의 차이와 같음

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| IRQ 라인 | 장치의 요청 신호 경로이며 에지·레벨 트리거 방식이 요청 유지와 중복 처리 조건을 결정함 |
| 인터럽트 컨트롤러 | 다수 요청을 수집하고 마스킹과 우선순위 결정을 수행해 CPU 부담을 줄임 |
| 벡터 테이블 | 인터럽트 번호와 ISR 주소를 매핑해 주소 탐색 단계를 줄임 |
| ISR·복귀 메커니즘 | 문맥을 저장하고 서비스를 실행한 뒤 복귀하며 ISR 길이가 시스템 응답성을 좌우함 |

```text
+-------------+     +----------------------+     +----------------+     +-------------+
| IRQ 발생원  | --> | 인터럽트 컨트롤러     | --> | 벡터·ISR       | --> | CPU 복귀    |
+-------------+     +----------------------+     +----------------+     +-------------+
```

> 요약: IRQ 요청은 컨트롤러와 벡터 테이블을 거쳐 짧은 ISR로 처리될 때 지연이 줄어듦.

### 쉽게 이해하기 (학습용)
- 초인종(IRQ 라인), 접수 담당자(인터럽트 컨트롤러), 담당자 명부(벡터 테이블), 응대 후 원래 자리로 돌아가는 절차(ISR·복귀)가 함께 있는 사무실과 같음

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| IRQ 발생       | --> | 원인·우선순위 판정 | --> | ISR 실행      | --> | 문맥 복귀      |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **IRQ 발생**: 장치가 CPU 또는 컨트롤러에 인터럽트 요청을 보냄
2. **원인 및 우선순위 판정**: 벡터 또는 체인 구조로 서비스 대상을 결정함
3. **ISR 실행**: 문맥 저장 후 서비스 루틴을 처리함
4. **문맥 복귀**: 상태를 복원하고 원래 프로그램 흐름으로 돌아감

> 요약: 인터럽트는 요청, 원인 판정, ISR 실행, 문맥 복귀 순서로 CPU 흐름을 일시 전환함.

### 쉽게 이해하기 (학습용)
- 벨이 울리면 누가 먼저인지 정하고, 응대한 뒤, 하던 일로 되돌아가는 순서와 같음

## Ⅵ. 실무 사례

1. NVMe 컨트롤러는 벡터 번호로 요청을 구분하고 ISR에는 상태 확인만 남겨 최악 인터럽트 지연·ISR 실행 시간을 확인함
2. 데이지체인은 뒤쪽 장치까지 승인 신호 전파 단계가 누적되므로 장치 수와 연결 순서를 제한하고 장치별 서비스 지연을 측정함

### 쉽게 이해하기 (학습용)
- 접수번호로 바로 담당자를 찾아가게 하거나, 줄서기 방식의 인원을 제한해 뒷사람 대기 시간을 줄이는 것과 같음

## Ⅶ. 결론

- 인터럽트 처리는 요청 식별과 우선순위 판정을 거쳐 ISR로 분기했다가 원래 흐름으로 복귀시키는 구조이며, 우선순위·마스킹 정책과 ISR 길이가 응답성을 좌우함
- 다장치·실시간 시스템은 벡터 번호로 ISR을 바로 찾아 식별 지연을 줄이고, 장치 수가 적고 우선순위 변경이 드물 때만 데이지체인을 선택해야 함

### 쉽게 이해하기 (학습용)
- 급한 손님은 번호표로 바로 응대하고 나머지 서류 작업은 나중에 처리해 전체 대기 시간을 줄이는 것과 같음
