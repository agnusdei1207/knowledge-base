## 미리 알고가기

- 인터럽트는 비동기 이벤트가 발생했을 때 CPU 실행 흐름을 잠시 바꾸는 메커니즘임
- 벡터 방식은 인터럽트 번호로 ISR 주소를 조회하고, 데이지체인은 장치 연결 순서로 우선순위를 정함
- 핵심 지표는 interrupt latency, prioritization, ISR overhead임

## Ⅰ. 개요

- **정의/개념**: 인터럽트 처리 방식은 장치·예외의 서비스 요청을 식별하고 우선순위를 정한 뒤 ISR로 분기해 원래 작업으로 복귀시키는 제어 구조임
- **배경/필요성**: 폴링만으로는 비동기 장치 이벤트를 적시에 처리하기 어렵기 때문에 응답성과 CPU 활용률을 확보하는 비동기 제어 방식이 필요함

## Ⅱ. 특징

- 비동기 이벤트를 즉시 처리해 응답성이 높음
- 인터럽트 컨트롤러와 벡터 테이블 설계에 따라 식별 속도와 확장성이 달라짐
- 우선순위와 마스킹 정책이 실시간성에 직접 영향을 줌
- ISR이 길어지면 전체 시스템 지연과 중첩 처리 부담이 증가함

## Ⅲ. 종류 및 비교

| 판단 기준 | 벡터 인터럽트 | 데이지체인 |
|:---|:---|:---|
| 원인 식별 | 벡터 번호로 즉시 식별 | 승인 신호를 순차 전달하며 식별 |
| 응답 속도 | 빠름 | 상대적으로 느림 |
| 확장성 | 높음 | 낮음 |
| 우선순위 방식 | 컨트롤러 또는 테이블 기반 | 물리적 연결 순서 기반 |

> 요약: 벡터 인터럽트는 번호로 ISR을 선택하고, 데이지체인은 앞 장치부터 승인 신호를 전달해 뒤 장치의 대기 시간이 누적됨.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| IRQ 라인 | 장치가 인터럽트 요청을 발생시키는 신호 경로로 트리거 방식 선택이 중요함 |
| 인터럽트 컨트롤러 | 다수 요청을 수집하고 마스킹과 우선순위 결정을 수행해 CPU 부담을 줄임 |
| 벡터 테이블 | 인터럽트 번호와 ISR 주소를 매핑해 빠른 분기를 가능하게 함 |
| ISR·복귀 메커니즘 | 문맥 저장, 서비스 수행, 복귀를 처리하며 ISR 길이가 시스템 응답성을 좌우함 |

```text
+-------------+     +----------------------+     +----------------+     +-------------+
| IRQ Sources | --> | Interrupt Controller | --> | Vector / ISR   | --> | CPU Return  |
+-------------+     +----------------------+     +----------------+     +-------------+
```

> 요약: IRQ 요청은 컨트롤러와 벡터 테이블을 거쳐 짧은 ISR로 처리될 때 지연이 줄어듦.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| IRQ 발생       | --> | 원인/우선순위 판정 | --> | ISR 실행      | --> | 문맥 복귀      |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **IRQ 발생**: 장치가 CPU 또는 컨트롤러에 인터럽트 요청을 보냄
2. **원인 및 우선순위 판정**: 벡터 또는 체인 구조로 서비스 대상을 결정함
3. **ISR 실행**: 문맥 저장 후 서비스 루틴을 처리함
4. **문맥 복귀**: 상태를 복원하고 원래 프로그램 흐름으로 돌아감

> 요약: 인터럽트는 요청, 원인 판정, ISR 실행, 문맥 복귀 순서로 CPU 흐름을 일시 전환함.

## Ⅵ. 실무 적용 및 유의점

1. 네트워크 카드·스토리지는 동시 요청이 많아 벡터 인터럽트가 맞지만 ISR이 길면 지연이 커지므로 deferred handler로 후속 작업을 넘기고 worst-case interrupt latency, jitter로 확인함
2. 단순 임베디드 보드의 데이지체인은 구현은 쉽지만 하위 장치 지연이 누적되므로 장치 수·우선순위를 제한하거나 벡터 구조로 전환하고 service latency, fairness index로 확인함

## Ⅶ. 결론

인터럽트 처리 방식은 원인 식별과 우선순위 제어가 핵심이므로 다장치·실시간 환경에서는 벡터 번호로 ISR을 선택하고 긴 작업을 지연 처리기로 넘겨 ISR 시간을 줄여야 함.

## 작성 근거(검토용)

- 인터럽트 처리는 원인 식별, 우선순위, ISR 길이를 핵심 판단축으로 삼음
- 벡터와 데이지체인은 식별 속도, 확장성, 물리적 우선순위 차이로 비교함
- 실무 유의점은 deferred handler, latency, jitter로 검증 가능하게 정리함
