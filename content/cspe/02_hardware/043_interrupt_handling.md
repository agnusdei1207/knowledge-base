# 📖 【암기용】 개념 완전 이해

> 목적: 여러 주변기기가 동시에 "나 좀 봐줘!"라고 비명을 지를 때, CPU가 패닉에 빠지지 않고 누구 비명부터 어떻게 멱살 잡고 처리하는지(우선순위 판별 및 벡터링) 그 내부 H/W 로직을 완벽히 이해하게 만든다.

## 한눈에
- **개요**: CPU가 메인 프로그램을 실행하는 도중에 발생한 예외 상황이나 외부 H/W의 긴급 요청(Interrupt)을 인지하고, 수많은 장치 중 '누가 불렀는지(식별)'와 '어떤 프로그램으로 처리할지(분기)'를 결정하는 하드웨어적/소프트웨어적 메커니즘
- **왜 필요한가**: 키보드, 마우스, 랜카드, 하드디스크가 동시에 CPU에게 "일 끝났어!"라고 신호를 보낼 수 있다. CPU에는 인터럽트 선(Pin)이 몇 개 없는데, 10개의 장치가 동시에 불을 켜면 CPU는 "누구지? 누구부터 처리해야 하지?" 멘붕에 빠진다. 이때 폴링(S/W로 다 물어보기), 데이지 체인(H/W 직렬 연결), 병렬 우선순위(H/W 병렬) 방식을 통해 0.1초 만에 최적의 루틴으로 점프해야 한다.
- **핵심 직관**: 
  - **폴링(S/W)**: 선생님(CPU)이 "지금 누구 떠들었어?" 하고 1번 학생부터 30번 학생까지 순서대로 다 물어봄. (느림, 유연함)
  - **데이지 체인(H/W 직렬)**: 1번~30번 학생을 한 줄로 세워놓고 선생님이 맨 앞 학생한테 "너야?" 찌름. 아니면 걔가 뒷사람한테 "너야?" 넘김. 줄 앞쪽에 설수록 VIP(우선순위 높음). (선이 적게 듦, 뒤로 갈수록 느림)
  - **병렬 우선순위(H/W 병렬)**: 30명 학생 책상에 전부 개별 직통 벨을 깔아놓음. 벨이 울리면 인터럽트 컨트롤러(PIC)가 "어 너 3번! 우선순위 제일 높네" 하고 즉각 반응. (선이 많이 듦, 가장 빠름)

## 깊이 이해
- **배경·문제의식**: 인터럽트가 걸리면 CPU는 하던 일을 멈추고 **ISR (인터럽트 서비스 루틴)** 이라는 구급차 프로그램으로 점프해야 한다. 점프하려면 구급차가 어딨는지 주소(Address)를 알아야 한다. 장치가 "나는 키보드야, 내 구급차 주소는 0x55번지야"라고 주소(Vector)를 하드웨어 버스에 직접 실어 보내주는 방식을 **벡터 인터럽트(Vectored Interrupt)** 라고 한다.
- **작동 원리 (누가 불렀나 찾기 레이스)**: 
  - **데이지 체인 (Daisy Chain)**: 기기들을 꼬리에 꼬리를 무는 직렬 와이어(Interrupt Acknowledge 선)로 엮는다. CPU가 확인 신호(ACK)를 쏘면 1번 기기가 받는다. 1번 기기가 요청한 게 맞으면 자신의 벡터(주소)를 버스에 띄우고 신호를 끊어버린다. 아니면 2번 기기로 신호를 패스(Pass)한다. 가장 앞단에 연결된 기기가 절대적 하드웨어 우선권을 갖는다.
  - **소프트웨어 폴링 (Polling)**: CPU에 인터럽트 선은 딱 1개다. 신호가 오면, CPU는 범용 인터럽트 루틴으로 점프해서 `if (키보드 플래그==1) ... else if (마우스 플래그==1)` 코드를 실행해 범인을 찾는다. 주소(벡터)를 기기가 쏴주지 않으므로 비벡터(Non-Vectored) 방식이다.
- **인터럽트 벡터(Vector)**: 장치가 CPU에게 "나 3번 장치야!"라고 번호를 던져주면, CPU는 메모리에 있는 [인터럽트 벡터 테이블]에서 3번 칸을 찾아가 ISR 코드가 있는 주소를 단숨에 획득한다. 
- **흔한 오해·주의점**: "인터럽트는 소프트웨어(OS)가 발생시킨다"는 반만 맞다. 인터럽트는 기계가 핀(Pin)에 전기를 쏴서 거는 **하드웨어 인터럽트**(마우스 클릭)와, 프로그램이 0으로 나누기 오류나 `INT` 명령어로 고의로 거는 **소프트웨어 인터럽트(Trap)** 로 나뉜다.

## 연결 개념
- 문맥 교환 (Context Switching) — 인터럽트가 걸렸을 때 CPU가 하던 작업(PC, 레지스터 값)을 스택(Stack)에 긴급 대피시키는 오버헤드 작업.
- ISR (Interrupt Service Routine) — 인터럽트의 요청을 실제로 해결해 주는 OS 내부의 119 구급대원 코드 (예: 키보드 입력값을 메모리에 복사).
- 마스커블(Maskable) / 넌마스커블(NMI) — 바쁠 때 "무시해도 되는" 인터럽트와, 전원이 뽑히는 등 "무조건 즉각 처리해야 하는" 절대 인터럽트의 차이.

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 인터럽트 처리는 다수의 디바이스에서 발생하는 비동기적 요청에 대해 식별(Identification), 우선순위 판별(Priority), 그리고 처리 루틴(ISR)으로의 분기(Branching)를 수행하는 시스템 제어 매커니즘이다.
> 2. **가치**: 데이지 체인과 병렬 우선순위(PIC) 같은 하드웨어 벡터링(Vectoring) 방식을 통해, S/W 폴링 시 소모되는 탐색 오버헤드와 분기 지연 시간(Latency)을 최소화하여 실시간성(Real-time)을 보장한다.
> 3. **판단 포인트**: 장치 개수가 증가할수록 S/W 폴링과 데이지 체인은 응답 지연이 선형적으로 폭증하므로, 현대 아키텍처에서는 인터럽트 제어기(APIC)를 통한 병렬 하드웨어 벡터 방식이 필수적이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 다중 인터럽트 발생 시 장치 식별 및 우선순위 중재 메커니즘 차이 분석 | 폴링(S/W) vs 데이지 체인(직렬 H/W) vs 병렬 우선순위(PIC) | 데이지 체인을 네트워크 토폴로지로 착각하여 서술하는 오류 (여기선 H/W ACK 선의 릴레이 구조임) |
| 벡터(Vectored) 방식과 분기 처리(ISR) 아키텍처 연계 | 장치가 고유 번호(Vector)를 데이터 버스에 싣는 행위 | 장치가 주소를 쏜다(Vector)는 핵심을 빼놓고 단순 우선순위 판별법으로만 서술하는 것 |

> 요약: 인터럽트 방식의 3대 구분은 "누가 범인인가를 S/W 코드(if문)로 찾을래(폴링), 직렬 전깃줄로 찾을래(데이지체인), 전담 칩(PIC)에 맡길래(병렬)?"의 트레이드오프다.

## Ⅰ. 개요 및 필요성

- 정의: CPU가 다중 프로그래밍 또는 I/O 작업을 수행할 때, 동시다발적으로 발생하는 외부 요청(Interrupt)을 인지하여 장치를 식별하고 해당 인터럽트 서비스 루틴(ISR)으로 제어권을 넘기는 일련의 과정
- 배경: 여러 개의 주변기기(디스크, 네트워크, 타이머)가 제한된 CPU 핀(INTR)을 공유하므로, 인터럽트 경합 시 어떤 장치의 요청을 먼저 처리할지 결정하는 중재(Arbitration) 불가피
- 필요성: 시스템의 실시간(Real-time) 반응성을 위해 장치 식별에 걸리는 지연 시간(Latency)을 마이크로초 이하로 단축하고, 처리 중인 기존 문맥(Context)을 안전하게 보호/복원할 뼈대 확립

## Ⅱ. 인터럽트 처리 마이크로 흐름 및 문맥 교환

인터럽트 발생 시 CPU 내부에서는 하드웨어적으로 기존 작업을 멈추고 구급대(ISR)를 부르는 숨 가쁜 릴레이가 일어난다.

```text
[인터럽트 수신 및 ISR 분기(Branch) 마이크로 제어 흐름]
1. [인지] : INTR 핀 신호 수신 (현재 실행 중인 명령어 1개는 끝까지 완료함)
2. [저장] : 현재의 Program Counter(PC)와 상태 레지스터(PSR)를 메모리 Stack에 Push (문맥 보호)
3. [확인] : INTA(인터럽트 승인) 신호를 버스로 쏘아 "준비됐다, 번호 대라!" 장치에 통보
4. [식별] : 장치 식별 (폴링 / 데이지체인 / 병렬 PIC 기반 탐색) -> 장치가 벡터(Vector) 반환
5. [분기] : 벡터 테이블을 참조해 해당 ISR(디바이스 드라이버) 주소로 PC 점프
6. [복귀] : ISR 종료 후(RETI 명령어), Stack에서 기존 PC를 Pop하여 중단점부터 재실행
```

| 처리 요소 | 수행 주체 | 핵심 역할 및 페널티 |
|:---|:---|:---|
| Context Saving | H/W (CPU 로직) | CPU 레지스터 대피. 무거운 운영체제일수록 대피할 레지스터가 많아 인터럽트 오버헤드 가중 |
| Vector Table | OS (메모리 로드) | 인터럽트 고유 번호(0~255)와 해당 ISR 시작 주소를 매핑해둔 일종의 '전화번호부' |
| ISR (서비스 루틴) | OS (커널 모드) | 실제 요건 처리. ISR 코드가 길면 다른 기기의 인터럽트가 막히므로 무조건 짧고 빨라야 함 |

> 요약: 인터럽트는 절대 공짜가 아니다. 한 번 걸릴 때마다 하던 일을 멈추고 서류(레지스터)를 서랍(스택)에 다 집어넣고 빼는 '문맥 교환 패널티'를 지불해야 한다.

## Ⅲ. 동작원리 및 장치 식별 3대 방식 구조

누가 인터럽트를 걸었는지(식별) 찾아내는 구조에 따라 소프트웨어와 하드웨어 방식으로 나뉜다.

```text
[1. S/W 폴링 (Polling)]
[CPU] -----> ISR 코드 진입: if (Device_A_Flag) 실행_A; else if (Device_B_Flag) 실행_B;
             (장점: 유연함, H/W 수정 없음 / 단점: B 장치는 앞선 비교 때문에 무조건 응답 느림)

[2. 데이지 체인 (Daisy Chain - 직렬 H/W)]
[CPU (INTA)] ----> [장치 1 (우선순위 1위)] --(Pass)--> [장치 2] --(Pass)--> [장치 3]
             (원리: 가장 가까운 장치가 ACK를 가로채고 버스에 자기 벡터(Vector)를 실어 보냄)

[3. 병렬 우선순위 (PIC - 병렬 H/W)]
[장치 1] ---선1--\     +----------------+
[장치 2] ---선2--->    | PIC (중재 칩)   | ----> [CPU]
[장치 3] ---선3--/     +----------------+
             (원리: 전담 칩(PIC)이 하드웨어 마스크 레지스터를 비교해 최고 순위 장치의 벡터를 쏴줌)
```

> 요약: 현대 컴퓨터는 수십 개의 장치가 물리려 하므로 S/W 폴링이나 데이지 체인은 속도 터져서 못 쓴다. 무조건 메인보드에 컨트롤러 칩(PIC, APIC)을 박아서 병렬로 처리한다.

## Ⅳ. 심화 비교: 폴링 vs 데이지 체인 vs 병렬 우선순위 대조표

| 비교 축 | 소프트웨어 폴링 (Polling) | 데이지 체인 (Daisy Chain) | 병렬 우선순위 (PIC / APIC) |
|:---|:---|:---|:---|
| 구현 계층 | 소프트웨어 (ISR 내부 로직) | 하드웨어 (직렬 INTA 와이어 릴레이)| 하드웨어 (별도 통제 칩셋 박음) |
| 처리 속도 | 가장 느림 (IF 조건문 순차 실행) | 보통 (뒤로 갈수록 릴레이 지연 발생) | **가장 빠름 (즉시 판별)** |
| 장치 식별(Vector)| 비벡터(Non-Vectored) 방식 | **Vectored 방식 (장치가 버스에 쏨)** | **Vectored 방식 (PIC가 버스에 쏨)** |
| 확장성 / 유연성 | S/W 수정만으로 우선순위 자유 변경 | 물리적 선로 연결 순서가 우선순위 고정 | 레지스터 셋팅으로 동적 우선순위 변경 |
| 적용 아키텍처 | 초저가 임베디드, 초기 마이크로컴퓨터| 시스템 버스 확장 슬롯, 구형 SCSI | 현대 x86 PC, 멀티코어 서버 (APIC) |

> 요약: 데이지 체인은 하드웨어로 벡터(번호)를 받아내어 S/W 폴링의 무식함을 극복했으나, 장비가 10개로 늘어나면 10번째 장치는 신호가 도달할 때까지 굶어 죽는(Starvation) 약점이 있다.

## Ⅴ. 제약 사항 및 다중 인터럽트 중첩(Nesting) 한계 극복

| 리스크 | 발생 원인 | 아키텍처 및 OS 대응 방안 | 극복 원리 및 효과 |
|:---|:---|:---|:---|
| 다중 인터럽트 붕괴 | 낮은 순위의 키보드 ISR을 처리하는 도중, 치명적인 하드디스크 장애 인터럽트가 들어오면 무시당할 위기 | **다중 인터럽트 허용 (Nesting / 중첩)** | ISR 처리 도중에도 전역 인터럽트 플래그(IF)를 활성화시켜, 자신보다 우선순위가 높은 놈이 들어오면 ISR 위에서 또 ISR로 점프(스택 다중 누적) 허용 |
| 마스킹(Masking) 마비 | 너무 빈번한 네트워크 패킷이 들어올 때 중요한 OS 타이머가 밀려 시스템 시간이 느려짐 | 하드웨어 인터럽트 마스크 레지스터(IMR) | PIC 내부에 마스크(Mask) 비트를 두어, 특정 장치의 인터럽트 신호를 H/W 단에서 무시(Disable)하게 통제 |
| 멀티 코어 병목 | CPU 코어가 64개인데 모든 인터럽트가 0번 코어(Core 0)에만 쏟아져 0번 코어 마비 | **APIC (Advanced PIC) 라우팅 분산** | 메인보드의 I/O APIC가 들어온 인터럽트를 로드 밸런싱하여 64개 코어의 Local APIC에 공평하게 찢어 분산 송출 (SMP 환경 필수) |

> 요약: 우선순위는 정해져 있다(하드웨어 에러 > 타이머 > 디스크 > 마우스). 중요한 구급대(ISR)가 일할 땐 안 중요한 구급차를 막고(Masking), 치명적 에러(NMI)는 모든 걸 뚫고 들어오게 설계된다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. RTOS(실시간 운영체제) 기반 자율주행 제어기 설계: 자동차 충돌 방지 레이더 신호와 에어컨 버튼 신호가 동시에 들어올 때, 레이더 센서 핀을 PIC의 최상위 우선순위(IRQ 0)에 물리적으로 배선(Hard-wired)하고 선점형(Preemptive) ISR로 점프시켜 0.01초 내 제동 제어 보장
2. 멀티코어 데이터베이스 서버 IRQ Affinity (SMP Affinity) 튜닝: 리눅스 서버에서 10Gbps 랜카드의 RX(수신) 인터럽트가 0번 코어에 몰려 드롭(Drop)되는 현상을 막기 위해, `/proc/irq/` 파일의 마스크 값을 수정하여 각 랜카드 큐(Queue)의 인터럽트를 특정 유휴 CPU 코어로 수동 바인딩(Pinning)하여 처리량 2배 폭증
3. Top-Half / Bottom-Half (Tasklet) 구조 분리: ISR이 길어지면 시스템 전체가 멈추므로, 리눅스 커널 개발 시 키보드 입력값을 메모리에 적는 핵심 작업(Top-Half)만 ISR에서 긴급 처리한 뒤 인터럽트를 켜고, 나머지 화면에 출력하는 무거운 작업(Bottom-Half)은 나중에 백그라운드로 스케줄링하여 인터럽트 차단 시간 최소화

**결론 (2줄):**
- 기술사 판단: 인터럽트 처리 매커니즘은 장치 식별을 위해 낭비되던 폴링(CPU 유휴 주기)을 하드웨어 데이지체인 및 APIC(벡터링)로 우회함으로써 다중 프로그래밍의 응답성을 보장한 척추다.
- 향후 방향: 현대 초고속 네트워크(100GbE)와 NVMe 스토리지에서는 역설적으로 초당 백만 번의 인터럽트 패널티가 커널을 마비시키고 있어, 다시 인터럽트를 끄고 NAPI나 DPDK 같은 S/W 폴링(Polling)으로 회귀하는 나선형 발전(Spiral Evolution)이 진행 중이다.
