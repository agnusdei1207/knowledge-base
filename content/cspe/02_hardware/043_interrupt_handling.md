## Ⅰ. 개요
- 정의: 예외 상황이나 장치 요청 발생 시 CPU의 정상 실행을 일시 중단하고 처리하는 매커니즘
- 배경: 긴급 상황의 즉각 대응 및 비동기적 이벤트 처리를 위한 필수 하드웨어 기능
- 출제 의도
| 구분 | 내용 |
| --- | --- |
| 핵심 | ISR, 벡터 테이블, 문맥 보존(Context Save), 우선순위 제어 |

## Ⅱ. 구성요소
```
[ Interrupt Source ] -> [ PIC/APIC ] -> [ CPU (INTR) ]
                                          |
                                    [ Vector Table ] -> [ ISR ]
```
| 구성요소 | 설명 | 비유 |
| --- | --- | --- |
| 인터럽트 벡터 | 처리 서비스 루틴(ISR)의 시작 주소를 담고 있는 테이블 | 119 출동 주소록 |
| ISR | 인터럽트가 발생했을 때 실제로 실행되는 코드 블록 | 현장 조치 매뉴얼 |
| 문맥(Context) | 인터럽트 직전의 레지스터, PC 값 등 프로그램 상태 정보 | 하던 일 메모 |
> 요약: 하드웨어 신호와 소프트웨어 루틴의 유기적 결합으로 예외 처리함

## Ⅲ. 절차
1. 요청 및 인지: 장치가 신호 발생, CPU는 현재 인스트럭션 종료 후 인지
2. 문맥 보존: 현재 실행 중인 프로그램의 상태(PC, PSR 등)를 스택에 저장
3. 루틴 실행: 벡터 테이블에서 주소를 찾아 해당 ISR로 점프 및 실행
4. 복구 및 재개: 처리가 끝나면 저장된 문맥을 복원하고 원래 위치로 복귀
> 요약: 투명한 문맥 전환을 통해 다중 작업을 중단 없이 처리하는 느낌을 줌

## Ⅳ. 문제점
- 중첩 인터럽트 발생 시 우선순위 관리가 부적절하면 시스템 데드락 위험함

## Ⅴ. 개선방안
- 다중 레벨 인터럽트 우선순위(Priority) 설정 및 마스킹 기법 적용함

## Ⅵ. 전망
- 멀티코어 환경 최적화를 위한 APIC(Advanced PIC) 및 MSI-X 기술 보편화됨
- 인터럽트 지연(Latency)을 최소화하기 위한 실시간 OS(RTOS)의 하드웨어 가속이 CSF임
