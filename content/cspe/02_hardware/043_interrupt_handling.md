## 핵심 인사이트 (3줄 요약)
- 인터럽트(Interrupt)는 CPU가 프로그램을 순차적으로 실행하는 도중에 예기치 않은 이벤트(입출력 완료, 타이머, 예외 상황 등)가 발생했음을 하드웨어적으로 알려주는 메커니즘이다.
- 인터럽트가 발생하면 CPU는 즉시 현재 하던 일(문맥)을 메모리에 안전하게 백업하고, 정해진 인터럽트 서비스 루틴(ISR)을 실행한 뒤 다시 원래 작업으로 복귀한다.
- 다수의 장치가 동시에 인터럽트를 걸 때 누구를 먼저 처리할지 결정하는 '데이지 체인', '폴링', '벡터 인터럽트' 방식의 우선순위 판별 및 처리 아키텍처가 시스템 응답성을 좌우한다.

## Ⅰ. 개요 및 필요성
- **개념:** 마이크로프로세서가 정상적인 기계어 명령 실행 흐름을 일시 중단하고, 더 급하고 중요한 외부(Hardware) 또는 내부(Software)의 이벤트를 먼저 처리하도록 흐름을 바꾸는 기능.
- **필요성:** 
  - **비동기적 이벤트 대응:** 사용자의 키보드 입력이나 네트워크 패킷 도착처럼 언제 발생할지 모르는 사건에 즉각적으로 반응하기 위함.
  - **CPU 효율 극대화:** CPU가 장치 상태를 무한 대기하며 묻는 폴링(Polling)의 자원 낭비를 없애고 다중 프로그래밍(Multi-programming)을 가능하게 함.

## Ⅱ. 아키텍처 및 핵심 원리
### 1. 인터럽트 발생 및 처리 사이클 도식
```text
[ 메인 프로그램 실행 중 ]
   명령어 1
   명령어 2  <---- ⚡ 인터럽트 발생! (키보드 입력 등)
   (명령어 2 완료 직후)
      │
      ▼
 1) 현재 상태 저장 (PC, 레지스터 값 등을 스택에 Push)
 2) 인터럽트 원인 파악 및 벡터 테이블 참조 (어디로 점프할까?)
      │
      ▼
[ ISR (Interrupt Service Routine) 실행 ]  <-- 해당 장치를 위한 처리 코드 (예: 버퍼에 키보드 값 저장)
   ISR 명령 1
   ISR 명령 2
      │
      ▼
 3) 상태 복원 (스택에서 Pop 하여 복구) 및 IRET (인터럽트 복귀 명령)
      │
      ▼
[ 메인 프로그램 복귀 ]
   명령어 3  <---- 아무 일 없었다는 듯 이어서 실행
```

### 2. 다중 인터럽트 판별 방식 (누가 불렀는지 찾기)
- **소프트웨어 폴링 방식:** 인터럽트가 걸리면 OS가 모든 장치의 상태 레지스터를 하나하나 검사하여 요청자를 찾음. 회로는 단순하나 속도가 느림.
- **데이지 체인 (Daisy Chain):** 장치들을 인터럽트 우선순위에 따라 직렬 회로로 줄을 세움. CPU가 '인터럽트 확인 신호'를 보내면 앞쪽 장치부터 판단하므로 최상위 우선순위 처리가 명확함.
- **벡터 인터럽트 (Vectored Interrupt):** 장치가 인터럽트 요청과 함께 자신의 고유 번호(Vector)를 데이터 버스로 보냄. CPU는 이 번호가 가리키는 메모리 주소(Vector Table)로 직행하여 ISR을 즉시 실행. 응답 속도가 가장 빨라 현대 아키텍처의 기본이 됨.

## Ⅲ. 비교 및 연결
- **인터럽트의 종류 분류**
| 분류 | 원인 및 특징 | 대표적 예시 |
|---|---|---|
| **외부 (하드웨어) 인터럽트** | I/O 장치나 타이머 등 CPU 외부 핀 신호에 의해 비동기적으로 발생 | I/O 완료 통보, 전원 이상, 타이머 만료(Context Switch용) |
| **내부 인터럽트 (Exception)** | CPU 내부에서 명령어 실행 중 발생한 예외 상황. 동기적 발생 | 0으로 나누기, 존재하지 않는 페이지(Page Fault) 접근 |
| **소프트웨어 인터럽트 (SVC)** | 사용자 프로그램이 운영체제의 권한이 필요할 때 코드로 의도적 발생 | 시스템 콜(System Call - `int 0x80`), 파일 읽기/쓰기 |
---
## Ⅳ. 실무 적용 및 기술사 판단
- **인터럽트 지연(Latency)과 실시간 시스템(RTOS):** 자동차 제어나 미사일 유도 같은 하드 리얼타임 OS에서는 인터럽트 발생부터 ISR 첫 코드가 실행될 때까지의 시간(Interrupt Latency)이 극도로 짧고 예측 가능해야 함. 인터럽트를 중첩(Nested) 허용하여 고순위 인터럽트가 저순위 ISR을 끊고 들어갈 수 있게 설계함.
- **Bottom-Half(태스크릿/워크큐) 설계:** 네트워크 패킷이 쏟아질 때 ISR에서 복잡한 로직을 다 처리하면 CPU가 멈춰버림. 실무 커널 프로그래밍에서는 ISR(Top-half)에서는 패킷만 잽싸게 큐에 복사하고 인터럽트를 끝낸 뒤, 여유가 될 때 나머지 처리(Bottom-half)를 수행하여 시스템 반응성을 사수함.
---
## Ⅴ. 기대효과 및 결론
- 인터럽트는 하나의 CPU가 수많은 외부 장치와 동시에 소통하며 현대적인 멀티태스킹 운영체제를 구동할 수 있게 해주는 중추 신경계입니다.
- H/W 기반의 빠른 벡터 인터럽트 감지와 S/W 기반의 정교한 Top-half / Bottom-half 분할 처리 메커니즘을 완벽히 이해하는 것은, 고성능 임베디드 시스템 및 서버 커널 아키텍처 설계의 가장 기본적이고 치명적인 역량입니다.

### 📌 관련 개념 맵
- 인터럽트 벡터 테이블 (IVT) ─ 인터럽트 서비스 루틴 (ISR)
- 우선순위: 데이지 체인 (Hardware) ─ 소프트웨어 폴링
- 컨텍스트 스위칭 (Context Switching) ─ 시스템 콜 (System Call)

### 👶 어린이를 위한 3줄 비유 설명
1. CPU가 방에서 집중해서 책(메인 프로그램)을 읽고 있는데, 갑자기 초인종 소리(인터럽트)가 울렸어요!
2. CPU는 읽던 페이지에 책갈피를 꽂아두고(상태 저장), 달려 나가서 택배 아저씨의 택배를 받아 방에 놓아요(ISR 실행).
3. 일이 끝나면 다시 돌아와서 아까 책갈피를 꽂아둔 곳부터 아무 일 없었다는 듯이 계속 책을 읽는답니다.
