## Ⅰ. 개요
- **정의**: 가상 주소→물리 주소 변환 결과를 캐싱하는 고속 연관 메모리임
- **배경/필요성**: 페이지 테이블이 메인 메모리에 존재하므로 매 주소 변환마다 메모리 접근이 이중으로 발생하여 CPU 성능이 저하됨
- **비유**: 자주 가는 식당 전화번호를 전화번호부 대신 포스트잇에 적어두는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 주소 변환 성능 최적화 원리 이해 | Hit/Miss 시 동작 흐름과 ASID 역할 | 문맥 전환 시 TLB Flush 문제를 누락하지 말 것 |

> 요약: TLB는 페이지 테이블 조회 비용을 줄이기 위한 주소 변환 캐시임

## Ⅱ. 구성요소
```text
  CPU
   |
   v
  +--------+     Hit      +------------+
  | 가상   |------------->| 물리 주소  |
  | 주소   |              | 출력       |
  +--------+              +------------+
   |  Miss                     ^
   v                           |
  +-------------+    변환 결과 |
  | 페이지      |-------------+
  | 테이블 조회 |
  +-------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Tag (VPN) | 가상 페이지 번호를 저장하여 비교 키로 사용함 | 전화번호부의 이름 항목 |
| Data (PFN) | 대응하는 물리 프레임 번호를 저장함 | 전화번호부의 번호 항목 |
| Valid Bit | 해당 엔트리가 유효한 매핑인지 표시함 | 포스트잇의 사용 가능 표시 |
| ASID | 프로세스별 주소 공간을 구분하는 식별자임 | 여러 사람의 포스트잇을 구분하는 이름표 |
| Dirty Bit | 해당 페이지가 수정되었는지 기록함 | 메모 내용 변경 여부 표시 |

> 요약: TLB는 VPN-PFN 쌍과 제어 비트로 구성된 연관 캐시 구조임

## Ⅲ. 절차
```text
  가상주소 입력     TLB 검색        Hit/Miss 판정     물리주소 출력
  (VPN 추출)      (병렬 비교)     (결과 분기)       (PFN+Offset)
   |                |                |                 |
   +---VPN 전달---->+---비교 결과--->+---Hit 경로----->+
                                     |                 ^
                                     +---Miss 경로     |
                                         페이지 테이블 |
                                         조회 후 갱신--+
```
- 1단계: CPU가 가상 주소에서 VPN(가상 페이지 번호)과 Offset을 분리함
- 2단계: TLB 내 모든 엔트리와 VPN을 병렬로 비교(CAM 방식)함
- 3단계: Hit이면 PFN을 즉시 반환하고, Miss이면 페이지 테이블을 조회하여 PFN을 획득함
- 4단계: Miss 시 조회된 VPN-PFN 쌍을 TLB에 적재하고 물리 주소(PFN + Offset)를 출력함

> 요약: VPN 추출 → 병렬 비교 → Hit/Miss 분기 → 물리 주소 생성의 4단계로 동작함

## Ⅳ. 문제점
- TLB Miss 지연: 페이지 테이블이 다단계 구조일 경우 Miss 시 2~4회 메모리 접근이 발생하여 지연이 증가함
- 문맥 전환 비용: 프로세스 전환 시 TLB 전체 Flush가 필요하여 전환 직후 Miss율이 급증함
- 용량 한계: 엔트리 수가 수십~수백 개로 제한되어 작업 세트가 큰 프로세스에서 Hit율이 하락함

> 요약: Miss 지연, 문맥 전환 Flush, 제한된 용량이 TLB의 주요 병목임

## Ⅴ. 개선방안
1. 단기: 다단계 TLB(L1/L2) 구성으로 Miss 지연을 계층적으로 흡수함
2. 중기: ASID 태그를 활용하여 문맥 전환 시 선택적 무효화로 Flush 범위를 축소함
3. 장기: 슈퍼페이지(2MB/1GB) 매핑을 지원하여 단일 엔트리 커버리지를 확대함

> 요약: 계층화, ASID 활용, 슈퍼페이지 지원으로 TLB 효율을 개선함

## Ⅵ. 전망
- 발전 방향: 이기종 메모리(CXL, HBM) 환경에서 다중 주소 공간을 관리하는 확장형 TLB 구조가 연구됨
- 기술사적 판단: 메모리 가상화가 확대될수록 TLB 설계의 중요성이 증가함
- 기술사 제언: 워크로드 특성에 따른 TLB 크기·정책 튜닝 역량을 확보할 필요
