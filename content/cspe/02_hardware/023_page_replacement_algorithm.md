# 📖 【암기용】 개념 완전 이해
> 목적: 페이지 교체 알고리즘을 처음 봐도 물리 프레임이 가득 찼을 때 어떤 페이지를 내보내는지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 물리 프레임이 부족할 때 어떤 페이지를 디스크로 내보낼지 결정하는 규칙
- **왜 필요한가**: 요구 페이징(demand paging) 환경에서 새 페이지를 적재하려는데 빈 프레임이 없으면, 기존 페이지 중 하나를 교체해야 하며 이 선택이 페이지 폴트 빈도를 좌우한다.
- **핵심 직관**: 냉장고가 가득 찼을 때 무엇을 버릴지 정하는 규칙과 같다. 가장 오래 안 먹을 것 같은 것(OPT), 가장 먼저 넣은 것(FIFO), 가장 오래 안 꺼낸 것(LRU), 가장 적게 꺼낸 것(LFU) 중 하나를 기준으로 정한다.

## 깊이 이해
- **배경·문제의식**: 페이지 교체 알고리즘의 목표는 향후 페이지 폴트 횟수를 최소화하는 것이며, 어떤 페이지가 미래에 다시 쓰일지 예측하는 정확도가 알고리즘 성능을 가른다.
- **작동 원리(OPT)**: OPT(Optimal, Belady's Optimal)는 앞으로 가장 오랫동안 참조되지 않을 페이지를 교체 대상으로 선택하며, 이론적으로 페이지 폴트 수가 최소임이 증명되어 있다.
- **작동 원리(OPT 한계)**: OPT는 미래의 참조 순서를 미리 알아야 하므로 실제 운영체제에서 실시간으로 구현할 수 없고, 다른 알고리즘의 성능을 비교하는 이론적 기준선으로만 사용된다.
- **작동 원리(FIFO)**: FIFO(First-In First-Out)는 가장 먼저 적재된 페이지를 교체하며, 큐(queue) 구조로 간단하게 구현할 수 있다.
- **작동 원리(FIFO 한계)**: FIFO는 프레임 수를 늘렸는데 오히려 페이지 폴트가 늘어나는 Belady's Anomaly가 발생할 수 있는 대표적인 비스택(non-stack) 알고리즘이다.
- **작동 원리(LRU)**: LRU(Least Recently Used)는 가장 오랫동안 참조되지 않은 페이지를 교체하며, 참조 시각을 기록하는 카운터나 스택 구조로 구현한다.
- **작동 원리(LRU 성질)**: LRU는 스택 알고리즘(stack algorithm)에 속하므로 프레임 수를 늘리면 페이지 폴트가 절대 늘어나지 않는다는 성질을 가지며, Belady's Anomaly가 발생하지 않는다.
- **작동 원리(LFU)**: LFU(Least Frequently Used)는 참조 횟수가 가장 적은 페이지를 교체하며, 프로세스 초기에 자주 쓰였지만 이후 쓰이지 않는 페이지가 높은 참조 횟수 때문에 계속 남는 문제(cache pollution)가 있다.
- **작동 원리(근사 구현)**: 실제 OS는 순수 LRU 구현 비용이 커서, reference bit과 원형 포인터를 쓰는 Clock(Second-Chance) 알고리즘으로 LRU를 근사한다.
- **비유**: OPT는 미래를 아는 신이 고르는 방식이고, FIFO는 선입선출 대기줄, LRU는 최근에 안 쓴 것부터 버리는 방식, LFU는 누적 사용 횟수가 적은 것부터 버리는 방식이다.
- **구체 예시**: 참조열 1,2,3,4,1,2,5,1,2,3,4,5에서 프레임 3개일 때 FIFO는 특정 조건에서 프레임을 4개로 늘려도 폴트가 늘어나는 사례(Belady's Anomaly)가 보고된 대표 예시열로 자주 인용된다.
- **흔한 오해·주의점**: "LRU가 항상 FIFO보다 폴트가 적다"는 일반적인 경향일 뿐이며, 특정 참조열에서는 두 알고리즘의 우열이 뒤집힐 수 있어 절대적으로 단정할 수 없다.
- **흔한 오해·주의점**: OPT는 "가장 좋은 알고리즘"이 아니라 "구현 불가능한 이론적 상한선"이라는 점을 혼동하면 안 된다.

## 연결 개념
- 가상 메모리·요구 페이징(Demand Paging) — 페이지 교체가 발생하는 배경
- Belady's Anomaly — FIFO 계열에서 나타나는 비직관적 현상
- Clock(Second-Chance) 알고리즘 — LRU의 실용적 근사 구현
- Working Set 모델 — 교체 정책과 스래싱(Thrashing) 방지의 연결점

## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 페이지 교체 알고리즘은 물리 프레임 부족 시 어떤 페이지를 디스크로 내보낼지 결정하는 정책이다.
> 2. **가치**: OPT는 이론적 최적 기준선, FIFO는 단순 구현, LRU는 실질적 근사 최적, LFU는 참조 빈도 기반 정책으로 각각 다른 목적을 갖는다.
> 3. **판단 포인트**: 구현 가능성(OPT 불가), Belady's Anomaly 발생 여부(FIFO 발생, LRU 미발생), 근사 구현 비용(Clock 알고리즘)을 함께 판단해야 한다.

| Belady's Anomaly 이해 확인 | FIFO에서 발생 가능, LRU는 스택 알고리즘이라 미발생 | 모든 알고리즘에서 발생한다고 서술 |
| 실무 구현 가능성 판단 확인 | OPT는 구현 불가, LRU는 Clock 알고리즘으로 근사 | OPT를 실제 OS가 쓰는 알고리즘처럼 서술 |

## Ⅰ. 개요 및 필요성
- 개요: 물리 프레임이 부족할 때 교체할 페이지를 선정하는 정책
- 배경: 요구 페이징 환경에서 빈 프레임이 없으면 반드시 기존 페이지 하나를 내보내야 페이지 폴트를 처리할 수 있음
- 필요성: 교체 정책의 선택이 페이지 폴트 빈도와 시스템 응답 지연을 좌우하므로 이론적 기준(OPT)과 실용적 근사(LRU·Clock)를 구분해 이해해야 함


## Ⅱ. 구조 및 구성요소
```text
Page Fault 발생 -> 빈 프레임 확인
  -> 있음: 즉시 적재
  -> 없음: 교체 알고리즘 적용
       / OPT: 미래 참조까지 고려(이론적)
       / FIFO: 적재 순서 큐 참조
       / LRU: 최근 참조 시각 참조
       / LFU: 참조 횟수 카운터 참조
  -> 희생 페이지(victim) 선정 -> 디스크 기록(dirty 시) -> 신규 페이지 적재
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Victim 선정 로직 | 교체 대상 페이지 결정 | 알고리즘별 기준 상이 |
| Reference Bit/Counter | LRU·LFU·Clock의 판단 근거 | 하드웨어 또는 소프트웨어로 갱신 |
| FIFO Queue | 적재 순서 기록 | 참조 여부와 무관하게 순서만 관리 |
| Dirty Bit | 교체 시 디스크 기록 필요 여부 판단 | dirty면 write-back 필요 |

> 요약: 교체 알고리즘은 victim 선정 기준(순서·최근성·빈도)에 따라 별도의 자료구조(큐·카운터·비트)를 사용한다.


## Ⅲ. 동작원리 및 흐름도
```text
참조열 입력 -> 프레임 상태 확인
  -> Hit: 페이지 폴트 없음
  -> Miss: 프레임 여유 확인
       -> 여유 있음: 즉시 적재
       -> 여유 없음: 알고리즘별 victim 선정 -> 교체 수행
  -> 폴트 카운트 갱신
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 참조 페이지가 프레임에 있는지 확인 | hit/miss 판정 |
| 2 | miss 시 프레임 여유 확인 | 빈 프레임 존재 여부 |
| 3 | 여유 없으면 알고리즘 기준으로 victim 선정 | OPT/FIFO/LRU/LFU 기준 적용 |
| 4 | victim 교체 후 폴트 카운트·상태 갱신 | 누적 페이지 폴트 수 |

> 요약: 알고리즘 차이는 3단계 victim 선정 기준에서만 갈리며, 나머지 흐름은 동일하다.


## Ⅳ. 특징
| 구분 | OPT | FIFO | LRU | LFU |
|:---|:---|:---|:---|:---|
| 선정 기준 | 미래 참조까지 가장 먼 페이지 | 가장 먼저 적재된 페이지 | 가장 오래 참조 안 된 페이지 | 참조 횟수 가장 적은 페이지 |
| 구현 가능성 | 구현 불가(이론적 기준선) | 큐로 간단히 구현 | 카운터·스택·Clock 근사 구현 | 참조 카운터 구현, 갱신 비용 존재 |
| Belady's Anomaly | 해당 없음(이론적 최적) | 발생 가능 | 미발생(스택 알고리즘) | 알고리즘 특성상 별도 분석 필요 |
| 대표 한계 | 실시간 구현 불가능 | 오래됐다고 무조건 안 쓰인다는 보장 없음 | 참조 시각 기록 비용 | 초기 고빈도 페이지의 cache pollution |

> 요약: OPT는 이론적 상한선, FIFO는 단순하지만 Anomaly 위험, LRU는 근사 구현으로 실질적 최선, LFU는 빈도 편향 문제를 갖는다.


## Ⅴ. 심화 비교 및 적용 판단
| 비교 축 | FIFO | LRU | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 단순 큐, 구현 비용 낮음 | 참조 시각 추적 필요, 구현 비용 높음 | 구현 단순성 우선 시 FIFO |
| 비용/성능 | Belady's Anomaly 위험 존재 | 스택 알고리즘으로 안정적 성능 | 안정적 폴트율 필요 시 LRU 근사(Clock) |
| 운영/위험 | 오래된 페이지가 실제로 자주 쓰일 수 있음 | 참조 이력 관리 오버헤드 | 참조 지역성이 강한 워크로드는 LRU 유리 |

> 요약: 구현 단순성은 FIFO, 폴트율 안정성은 LRU(Clock 근사)가 유리하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| Belady's Anomaly | FIFO의 비스택 알고리즘 특성 | LRU 또는 스택 알고리즘 계열로 전환 | 프레임 수 증가 시 폴트 수 변화 추이 |
| Cache Pollution | LFU가 과거 고빈도 페이지를 계속 보유 | 참조 횟수 시간 감쇠(aging) 적용 | 오래된 고빈도 페이지 잔존 비율 |
| 스래싱(Thrashing) | 프레임 수 대비 워킹셋 과다 | Working Set 모델 기반 프레임 할당 조정 | 페이지 폴트율 대비 CPU 이용률 |

> 요약: FIFO는 Anomaly, LFU는 편향 문제를 각각 다른 보정 기법으로 통제해야 한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 페이지 폴트율 | 워크로드 기준 목표 폴트율 설정 | OS 페이지 폴트 카운터 |
| 프레임 증가 대비 폴트 변화 | 스택 알고리즘 여부 검증 | 참조열 시뮬레이션 |
| 참조 지역성 | temporal/spatial locality 정도 확인 | 참조 패턴 분석 도구 |

> 요약: 도입 효과는 페이지 폴트율, 프레임 증가에 따른 폴트 변화, 참조 지역성 세 지표로 판단한다.


## Ⅵ. 실무 적용 및 결론
**적용 방안 3개:**
1. 이론 비교나 신규 알고리즘 평가 시에는 OPT를 기준선으로 두어 실제 알고리즘의 폴트율 격차를 측정함
2. 범용 운영체제는 순수 LRU 대신 Clock(Second-Chance) 알고리즘으로 근사 구현해 참조 이력 관리 비용을 낮춤
3. 특정 페이지가 초기에만 자주 쓰이는 워크로드는 LFU에 시간 감쇠를 적용해 cache pollution을 완화함

**결론 (2줄):**
- 기술사 판단: OPT는 이론적 상한선으로만 활용하고, 실무는 구현 가능성과 폴트율 안정성을 고려해 LRU 근사(Clock) 알고리즘을 우선 선택함
- 향후 방향: 워킹셋 크기가 급변하는 클라우드·컨테이너 환경에서는 고정 알고리즘보다 적응형 교체 정책 연구가 확대되는 추세임
