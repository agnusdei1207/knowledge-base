# 📖 【암기용】 개념 완전 이해
> 목적: 페이지 교체 알고리즘 각각이 정확히 어떤 규칙으로 희생 페이지를 고르는지, 그리고 그 규칙이 프레임 수를 바꿀 때 어떤 수치 결과를 낳는지(Belady's Anomaly 포함)를 실제 계산으로 이해하게 만든다.

## 한눈에
- **개요**: 페이지 교체 알고리즘은 **가상 메모리**의 **요구 페이징(Demand Paging)** 환경에서 물리 프레임이 가득 찼을 때 어떤 페이지를 디스크로 내보낼지 정하는 **victim 선정 정책**이다.
- **왜 필요한가**: 프레임이 다 찬 상태에서 새 페이지를 올리려면 반드시 기존 페이지 하나를 비워야 한다. 무엇을 비우느냐에 따라 이후 페이지 폴트 횟수가 크게 달라지므로, "미래에 다시 쓰일 가능성이 가장 낮은 페이지"를 골라내는 규칙이 필요하다.
- **핵심 직관**: 냉장고(프레임)가 가득 찼을 때 무엇을 버릴지 정하는 규칙과 같다 — 가장 오래 안 먹을 것(OPT), 가장 먼저 넣은 것(FIFO), 가장 오래 안 꺼낸 것(LRU), 가장 적게 꺼낸 것(LFU) 중 한 기준으로 고른다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 가상 메모리 / 요구 페이징 | 프로그램을 필요한 페이지만 그때그때 물리 메모리에 올리는 상위 기법 — 교체 알고리즘이 동작하는 무대 | 필요한 책만 그때그때 책상에 올리는 방식 |
| 페이지 폴트(Page Fault) | 참조한 페이지가 물리 프레임에 없어 디스크에서 가져와야 하는 상황 | 책상에 없는 책을 서고에서 다시 찾아옴 |
| Victim | 교체 대상으로 선정되어 내쫓기는 페이지 | 냉장고에서 버려지는 재료 |
| OPT(Optimal, Belady's Optimal) | 앞으로 가장 오랫동안 참조되지 않을 페이지를 교체 — 이론상 폴트 수 최소가 증명됨, 미래를 알아야 해서 구현 불가 | 미래를 아는 신의 선택 |
| FIFO(First-In First-Out) | 가장 먼저 적재된 페이지부터 교체 — 큐로 구현 | 선입선출 대기줄 |
| LRU(Least Recently Used) | 가장 오랫동안 참조되지 않은 페이지를 교체 — 참조 시각 기록 필요 | 가장 오래 안 편 책부터 정리 |
| LFU(Least Frequently Used) | 참조 횟수가 가장 적은 페이지를 교체 | 가장 적게 읽은 책부터 정리 |
| Belady's Anomaly | 프레임을 늘렸는데 오히려 페이지 폴트가 느는 역설 — FIFO 등 일부 알고리즘에서 발생 | 방을 넓혔는데 이삿짐이 더 자주 나가는 상황 |
| Stack Algorithm | n개 프레임의 적재 페이지 집합이 n+1개 프레임 집합의 부분집합이 되는 성질 — 이 성질이 있으면 Belady's Anomaly가 생기지 않음 | 큰 서랍이 작은 서랍의 내용을 항상 포함 |
| Clock(Second-Chance, NUR) | reference bit 1개와 원형 포인터로 LRU를 근사하는 실무 구현 | 시계 바늘이 돌며 최근에 안 쓴 페이지만 솎아냄 |

## 깊이 이해

### 왜 순수 LRU를 안 쓰고 근사하는가
- 진짜 LRU는 페이지마다 "마지막 참조 시각"을 매 참조마다 갱신해야 해서 오버헤드가 크다. 그래서 실제 OS는 페이지마다 reference bit 1개만 두고 Clock 알고리즘으로 근사한다: 원형으로 늘어선 페이지들을 포인터가 돌면서 bit가 1이면 0으로 바꾸고 지나가고, 이미 0인 페이지를 만나면 그 페이지를 교체한다.

### Belady's Anomaly를 수치로 확인하기 — FIFO
- 참조열 1,2,3,4,1,2,5,1,2,3,4,5(총 12회 참조)에 FIFO를 적용한다.
- **프레임 3개**: 1,2,3,4(1제거→[2,3,4]),1(2제거→[3,4,1]),2(3제거→[4,1,2]),5(4제거→[1,2,5])까지 7회 연속 폴트. 이어서 1,2는 [1,2,5] 안에 있어 히트. 3(1제거→[2,5,3]) 폴트, 4(2제거→[5,3,4]) 폴트, 5는 [5,3,4] 안에 있어 히트. 총 폴트 = **9회**.
- **프레임 4개**: 1,2,3,4를 순서대로 채워 [1,2,3,4]까지 4회 폴트. 1,2는 히트. 5(1제거→[2,3,4,5]) 폴트, 1(2제거→[3,4,5,1]) 폴트, 2(3제거→[4,5,1,2]) 폴트, 3(4제거→[5,1,2,3]) 폴트, 4(5제거→[1,2,3,4]) 폴트, 5(1제거→[2,3,4,5]) 폴트. 총 폴트 = **10회**.
- 프레임을 3개에서 4개로 **늘렸는데 폴트가 9회→10회로 오히려 증가**했다 — 이것이 Belady's Anomaly다. FIFO는 적재 순서만 보고 참조 패턴(최근성)을 반영하지 않는 비스택(non-stack) 알고리즘이라 이런 역설이 생긴다.

### 같은 참조열에 LRU를 적용하면
- **프레임 3개**: 1,2,3,4(1제거→[2,3,4]),1(2제거→[3,4,1]),2(3제거→[4,1,2]),5(4제거→[1,2,5])까지 7회 폴트. 1,2는 히트(참조 순서를 [2,5,1]→[5,1,2]로 갱신). 3(5제거→[1,2,3]) 폴트, 4(1제거→[2,3,4]) 폴트, 5(2제거→[3,4,5]) 폴트. 총 폴트 = **10회**.
- **프레임 4개**: 1,2,3,4를 채워 [1,2,3,4]까지 4회 폴트. 1,2 히트(참조 순서 갱신). 5(가장 오래 안 쓴 3 제거→[4,1,2,5]) 폴트. 1,2 다시 히트. 3(4 제거→[5,1,2,3]) 폴트, 4(5 제거→[1,2,3,4]) 폴트, 5(1 제거→[2,3,4,5]) 폴트. 총 폴트 = **8회**.
- LRU는 프레임을 3개→4개로 늘리자 폴트가 10회→**8회로 정상적으로 감소**했다. LRU는 스택 알고리즘이라 프레임이 늘수록 폴트가 절대 늘지 않는다는 성질(스택 속성)이 이 계산으로 확인된다.

### OPT는 왜 기준선으로만 쓰이나
- OPT는 "앞으로 가장 늦게 다시 쓰일 페이지"를 미리 알아야 고를 수 있다. 실행 중인 프로그램의 미래 참조를 미리 알 방법이 없으므로 실시간 구현이 불가능하고, 다른 알고리즘의 폴트 수를 비교하는 이론적 하한선으로만 쓰인다.

### LFU의 함정(cache pollution)
- LFU는 누적 참조 횟수만 보므로, 프로그램 초기에 반짝 자주 쓰이고 이후 전혀 안 쓰이는 페이지가 높은 카운트 때문에 계속 살아남는 문제가 있다. 이를 완화하려면 참조 횟수를 시간이 지날수록 줄이는 시간 감쇠(aging)를 함께 적용해야 한다.

### 비유와 흔한 오해
- **비유**: OPT는 미래를 아는 신, FIFO는 선입선출 대기줄, LRU는 가장 오래 안 편 책부터 정리하는 방식, LFU는 누적 대출 횟수가 적은 책부터 정리하는 방식이다.
- **오해 1**: "LRU가 항상 FIFO보다 폴트가 적다"는 일반적 경향일 뿐이다. 위 계산은 같은 참조열에서 3프레임 기준 FIFO=9회, LRU=10회로 오히려 FIFO가 더 적은 경우도 있음을 보여준다 — 절대적 우열은 참조열마다 다르다.
- **오해 2**: "프레임을 늘리면 무조건 폴트가 준다"는 FIFO에는 성립하지 않는다(Belady's Anomaly). LRU 등 스택 알고리즘에서만 항상 성립한다.

## 연결 개념
- 가상 메모리·요구 페이징(Demand Paging) — 페이지 교체가 발생하는 배경
- Working Set 모델·스래싱(Thrashing) — 교체 정책이 아무리 좋아도 프레임 자체가 부족하면 무력화되는 상위 문제
- MMU — reference bit·dirty bit를 하드웨어에서 갱신해 교체 알고리즘이 참조하게 해주는 주체
- 동일 알고리즘군을 스래싱·워킹셋 관점에서 다루는 자매 문서 — 본 문서는 알고리즘 자체의 계산 절차(Belady's Anomaly 수치 검증)에 집중

> 2. **가치**: OPT는 이론적 최적 기준선, FIFO는 단순 구현, LRU는 실질적 근사 최적, LFU는 참조 빈도 기반 정책으로 각각 다른 목적을 갖는다.

## Ⅰ. 개요 및 필요성
- 개요: 물리 프레임이 부족할 때 교체할 페이지를 선정하는 정책
- 배경: 요구 페이징 환경에서 빈 프레임이 없으면 반드시 기존 페이지 하나를 내보내야 페이지 폴트를 처리할 수 있음
- 필요성: 교체 정책의 선택이 페이지 폴트 빈도와 시스템 응답 지연을 좌우하므로 이론적 기준(OPT)과 실용적 근사(LRU·Clock)를 구분해 이해해야 함


## Ⅱ. 구조 및 구성요소
```text
Page Fault 발생 -> 빈 프레임 확인
  -> 있음: 즉시 적재
  -> 없음: 교체 알고리즘 적용
       / OPT: 미래 참조까지 고려(이론적)
       / FIFO: 적재 순서 큐 참조
       / LRU: 최근 참조 시각 참조
       / LFU: 참조 횟수 카운터 참조
  -> 희생 페이지(victim) 선정 -> 디스크 기록(dirty 시) -> 신규 페이지 적재
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Victim 선정 로직 | 교체 대상 페이지 결정 | 알고리즘별 기준 상이 |
| Reference Bit/Counter | LRU·LFU·Clock의 판단 근거 | 하드웨어 또는 소프트웨어로 갱신 |
| FIFO Queue | 적재 순서 기록 | 참조 여부와 무관하게 순서만 관리 |
| Dirty Bit | 교체 시 디스크 기록 필요 여부 판단 | dirty면 write-back 필요 |

> 요약: 교체 알고리즘은 victim 선정 기준(순서·최근성·빈도)에 따라 별도의 자료구조(큐·카운터·비트)를 사용한다.


## Ⅲ. 동작원리 및 흐름도
```text
참조열 입력 -> 프레임 상태 확인
  -> Hit: 페이지 폴트 없음
  -> Miss: 프레임 여유 확인
       -> 여유 있음: 즉시 적재
       -> 여유 없음: 알고리즘별 victim 선정 -> 교체 수행
  -> 폴트 카운트 갱신
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 참조 페이지가 프레임에 있는지 확인 | hit/miss 판정 |
| 2 | miss 시 프레임 여유 확인 | 빈 프레임 존재 여부 |
| 3 | 여유 없으면 알고리즘 기준으로 victim 선정 | OPT/FIFO/LRU/LFU 기준 적용 |
| 4 | victim 교체 후 폴트 카운트·상태 갱신 | 누적 페이지 폴트 수 |

> 요약: 알고리즘 차이는 3단계 victim 선정 기준에서만 갈리며, 나머지 흐름은 동일하다.


## Ⅳ. 특징
| 구분 | OPT | FIFO | LRU | LFU |
|:---|:---|:---|:---|:---|
| 선정 기준 | 미래 참조까지 가장 먼 페이지 | 가장 먼저 적재된 페이지 | 가장 오래 참조 안 된 페이지 | 참조 횟수 가장 적은 페이지 |
| 구현 가능성 | 구현 불가(이론적 기준선) | 큐로 간단히 구현 | 카운터·스택·Clock 근사 구현 | 참조 카운터 구현, 갱신 비용 존재 |
| Belady's Anomaly | 해당 없음(이론적 최적) | 발생 가능 | 미발생(스택 알고리즘) | 알고리즘 특성상 별도 분석 필요 |
| 대표 한계 | 실시간 구현 불가능 | 오래됐다고 무조건 안 쓰인다는 보장 없음 | 참조 시각 기록 비용 | 초기 고빈도 페이지의 cache pollution |

> 요약: OPT는 이론적 상한선, FIFO는 단순하지만 Anomaly 위험, LRU는 근사 구현으로 실질적 최선, LFU는 빈도 편향 문제를 갖는다.


## Ⅴ. 심화 비교 및 적용 판단
| 비교 축 | FIFO | LRU | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 단순 큐, 구현 비용 낮음 | 참조 시각 추적 필요, 구현 비용 높음 | 구현 단순성 우선 시 FIFO |
| 비용/성능 | Belady's Anomaly 위험 존재 | 스택 알고리즘으로 안정적 성능 | 안정적 폴트율 필요 시 LRU 근사(Clock) |
| 운영/위험 | 오래된 페이지가 실제로 자주 쓰일 수 있음 | 참조 이력 관리 오버헤드 | 참조 지역성이 강한 워크로드는 LRU 유리 |

> 요약: 구현 단순성은 FIFO, 폴트율 안정성은 LRU(Clock 근사)가 유리하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| Belady's Anomaly | FIFO의 비스택 알고리즘 특성 | LRU 또는 스택 알고리즘 계열로 전환 | 프레임 수 증가 시 폴트 수 변화 추이 |
| Cache Pollution | LFU가 과거 고빈도 페이지를 계속 보유 | 참조 횟수 시간 감쇠(aging) 적용 | 오래된 고빈도 페이지 잔존 비율 |
| 스래싱(Thrashing) | 프레임 수 대비 워킹셋 과다 | Working Set 모델 기반 프레임 할당 조정 | 페이지 폴트율 대비 CPU 이용률 |

> 요약: FIFO는 Anomaly, LFU는 편향 문제를 각각 다른 보정 기법으로 통제해야 한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 페이지 폴트율 | 워크로드 기준 목표 폴트율 설정 | OS 페이지 폴트 카운터 |
| 프레임 증가 대비 폴트 변화 | 스택 알고리즘 여부 검증 | 참조열 시뮬레이션 |
| 참조 지역성 | temporal/spatial locality 정도 확인 | 참조 패턴 분석 도구 |

> 요약: 도입 효과는 페이지 폴트율, 프레임 증가에 따른 폴트 변화, 참조 지역성 세 지표로 판단한다.


## Ⅵ. 실무 적용 및 결론
**적용 방안 3개:**
1. 이론 비교나 신규 알고리즘 평가 시에는 OPT를 기준선으로 두어 실제 알고리즘의 폴트율 격차를 측정함
2. 범용 운영체제는 순수 LRU 대신 Clock(Second-Chance) 알고리즘으로 근사 구현해 참조 이력 관리 비용을 낮춤
3. 특정 페이지가 초기에만 자주 쓰이는 워크로드는 LFU에 시간 감쇠를 적용해 cache pollution을 완화함

**결론 (2줄):**
- 기술사 판단: OPT는 이론적 상한선으로만 활용하고, 실무는 구현 가능성과 폴트율 안정성을 고려해 LRU 근사(Clock) 알고리즘을 우선 선택함
- 향후 방향: 워킹셋 크기가 급변하는 클라우드·컨테이너 환경에서는 고정 알고리즘보다 적응형 교체 정책 연구가 확대되는 추세임
