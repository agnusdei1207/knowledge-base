## Ⅰ. 개요
- 병렬 컴퓨팅에서 프로세서 수 증가에 따른 성능 향상(Speedup)의 한계를 설명하는 법칙.
- 자원 투입 대비 효율성을 판단하고 병렬화 전략을 수립하는 이론적 근거임.
| 구분 | 내용 | 비고 |
|---|---|---|
| 정의 | 병렬화 가능 부분과 순차 부분에 따른 성능 향상 계산식 | Speedup 이론 |
| 의도 | 시스템 규모 확장 시의 성능 한계 및 관점 차이 이해 측정 | 확장성 분석 |

## Ⅱ. 구성요소
| 구분 | 암달의 법칙 (Amdahl) | 구스타프슨의 법칙 (Gustafson) |
|---|---|---|---|
| 관점 | 고정된 문제 크기 (Fixed Size) | 고정된 실행 시간 (Fixed Time) |
| 수식 | S = 1 / ( (1-P) + P/N ) | S = (1-P) + P*N |
| 의미 | 순차 비중(1-P)이 전체 성능 제한 | 코어 늘리면 더 큰 문제 해결 가능 |
| 비유 | 한 그릇 빨리 먹기 | 시간 내에 많이 먹기 |
> 요약: 암달은 속도 한계에 집중, 구스타프슨은 작업량 확장에 집중함.

## Ⅲ. 절차
(1) Identify P -> (2) Analyze Constraint -> (3) Scalability Test -> (4) Decision
1. Identify P: 프로그램 코드 중 병렬화 가능한 부분(P)의 비율을 산출함.
2. Analyze Constraint: 암달을 통해 코어를 무한히 늘려도 도달 못할 상한선을 파악함.
3. Scalability Test: 구스타프슨 관점에서 자원 증설 시 처리 가능한 데이터 규모 예측.
4. Decision: 순차 코드 최적화에 집중할지, 자원을 늘려 대용량 처리를 할지 결정함.
> 요약: 병렬 비중 파악, 한계 분석, 확장성 테스트, 전략 수립 순임.

## Ⅳ. 문제점
- 오버헤드 무시: 통신 지연이나 동기화 비용 등 실제 병렬화 시 발생하는 손실을 배제함.
- 비현실적 가정: 실제 작업 환경에서 순차 부분과 병렬 부분이 명확히 나뉘지 않음.

## Ⅴ. 개선방안
- 현실적 모델링: 통신 오버헤드 계수를 포함한 수정된 암달의 법칙(LogP 모델 등) 적용.
- 동적 분석: 실행 환경에 따라 변하는 병렬성(P)을 실시간으로 측정하여 자원 할당 최적화.

## Ⅵ. 전망
- 슈퍼컴퓨팅 지표: 엑사스케일 컴퓨팅 설계 시 구스타프슨 관점의 대규모 데이터 처리 강조.
- 서버리스 최적화: 클라우드 오토스케일링 시 비용 대비 효율성 판단의 핵심 이론으로 재부각.
