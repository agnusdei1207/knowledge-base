# 📖 【암기용】 개념 완전 이해

> 목적: PNM 중에서도 특히 "CXL 모듈에 연산기를 얹어 메모리 용량 한계(Capacity Wall)를 풀어낸다"는 관점을 파고들어, 왜 이 구조가 용량과 수율을 동시에 지키는지 완전히 이해하게 만든다.

## 한눈에
- **개요**: PNM(Processing Near Memory)은 초거대 AI 모델의 **메모리 용량 한계(Capacity Wall)**를 풀기 위해, 연산 로직을 메모리 다이가 아니라 **CXL 모듈 기판(PCB)**이나 메모리 컨트롤러에 결합하는 근접 처리(Near-Memory Computing) 아키텍처다.
- **왜 필요한가**: LLM 같은 초거대 모델은 파라미터가 수백 GB~수 TB에 달해, CPU 메인보드의 램 슬롯 개수만으로는 다 담을 수 없다(용량 벽). 그렇다고 PIM처럼 D램 칩 내부에 연산기를 박으면 셀 면적을 깎아 먹어 용량(Density)이 오히려 줄어든다. PNM은 D램 칩은 그대로 두고 기판 위에 연산 칩을 따로 붙여, 용량도 지키고 CPU까지 가는 데이터양도 줄인다.
- **핵심 직관**: 도서관 본관(D램 칩)의 서가는 그대로 두고, 분관 입구(모듈 기판)에 요약 복사기(연산 칩)를 하나 세워두는 것. 책(데이터) 자체는 건드리지 않으니 서가 용량은 그대로면서, 필요한 요약본만 빠르게 받을 수 있다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| Capacity Wall (용량 병목) | 파라미터 양이 시스템 램 용량(슬롯 수)을 초과해 못 담는 현상 — PNM이 풀려는 **상위 문제** | 창고가 작아서 재고를 다 못 쌓는 것 |
| 근접 처리 (Near-Memory Computing) | 메모리 '내부'가 아니라 '근처'에서 데이터를 처리 — 이 기술이 속한 **상위 범주** | 창고 안이 아니라 창고 앞마당에서 처리 |
| PNM 컨트롤러 | MAC(곱셈-누산) 유닛과 CXL 인터페이스를 함께 내장한 연산 전담 ASIC | 창고 앞 검수·계산 담당 직원 |
| 모듈 기판 (PCB) | D램 칩과 PNM 컨트롤러를 함께 얹는 회로 기판 — 구조 혁신의 무대 | 창고 여러 칸을 한 층에 배치한 건물 배치도 |
| Density (용량 밀도) | 칩 하나가 담을 수 있는 데이터 양 — PIM은 연산기가 셀 자리를 차지해 감소, PNM은 그대로 유지 | 창고 선반 한 칸에 들어가는 상자 수 |
| Embedding Lookup | 추천 시스템·LLM에서 방대한 파라미터 표를 뒤져 필요한 값만 꺼내는 연산 — PNM이 대신 처리 | 두꺼운 사전에서 필요한 단어 하나만 찾아오기 |
| CXL.cache | CXL의 캐시 일관성 서브 프로토콜 — PNM과 CPU가 계산한 값이 서로 어긋나지 않게 보장(035에서 상세) | 두 사람이 같은 장부를 실시간으로 동기화하는 규칙 |

## 깊이 이해

### 용량(Density)을 지키면서 데이터 이동을 줄이는 원리
- PIM은 D램 셀 사이사이에 연산기(PCU)를 심다 보니, 그 자리만큼 저장할 수 있는 셀 수가 줄어든다 — 즉 용량과 연산 능력을 맞바꾼다.
- PNM은 D램 칩 자체는 순정 그대로 찍어내고, 연산 칩을 기판 위 별도 위치(로직 다이)에 붙인다. 그래서 답안 Ⅳ에서처럼 메모리 용량(Density)은 100% 보존되면서도, 연산은 근처에서 처리해 데이터 이동량은 확 줄어든다 — "저장은 저장답게, 계산은 계산답게" 역할을 분리한 결과다.

### 임베딩 룩업 예시로 보는 트래픽 감소 — 수치로 이해
- 추천 시스템이나 LLM은 수백 GB짜리 임베딩 테이블 중 극히 일부(요청마다 수백~수천 개 벡터)만 필요로 한다. 기존 방식은 이 큰 테이블 전체를 다 CPU 쪽으로 옮길 수 없어 CPU가 필요한 조각을 하나씩 요청해 가져와야 했다.
- PNM 컨트롤러가 모듈 위에서 직접 필요한 벡터를 찾아 곱셈·누산까지 끝내고 나면, 답안 Ⅲ에서 보듯 원래 옮겨야 했던 데이터(예: 100GB 단위)가 아니라 계산이 끝난 결과값(수 MB 단위)만 CXL 버스를 탄다 — 버스에 실리는 트래픽이 사실상 99% 가까이 줄어드는 셈이다.
- 그 결과 답안 Ⅵ의 적용 사례처럼 응답 속도가 약 2배 개선되는 효과로 이어진다.

### 왜 하필 CXL 위에 얹나 — 캐시 일관성 문제
- PNM 컨트롤러가 자기 마음대로 계산해 값을 바꿔버리면, CPU 캐시에 남아있는 옛날 값과 실제 메모리 값이 어긋나는 캐시 불일치가 생길 수 있다.
- CXL의 CXL.cache 프로토콜이 하드웨어 차원에서 PNM 모듈이 CPU 캐시 상태를 스누핑(엿보기)하도록 지원해, 이 불일치를 자동으로 막아준다. CXL 없이 PNM만 있으면 이 정합성 문제를 소프트웨어로 일일이 처리해야 해서 실용성이 떨어진다.

### 판별 원리 — 용량 벽 vs 대역폭 벽
- 병목이 "메모리에 다 담을 수 없다(용량 부족)"는 Capacity Wall이면 CXL 기반 PNM처럼 용량을 지키며 확장하는 방식이 답이다.
- 반대로 병목이 "이미 담겨 있는데 옮기는 속도가 느리다(대역폭 부족)"는 Bandwidth Wall이면, 뱅크 내부에서 초고속으로 처리하는 PIM이 더 유리하다. 즉 문제의 종류(용량 vs 속도)에 따라 PNM과 PIM의 선택이 갈린다.

## 연결 개념
- Capacity Wall (메모리 용량 병목) — 이 기술이 직접 해소하는 상위 문제
- PIM (Processing In Memory) — 용량 대신 속도를 극대화하는 대응 개념(033에서 상세)
- CXL (Compute Express Link), 특히 CXL.cache — PNM 모듈과 CPU 간 캐시 일관성을 보장하는 필수 인프라(035에서 상세)
- Density (메모리 용량 밀도) — PIM과 PNM을 가르는 핵심 트레이드오프 축

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: PNM(Processing Near Memory)은 연산 유닛(Accelerator)을 메모리 다이(Die) 내부가 아닌 메모리 모듈 기판(DIMM)이나 CXL 컨트롤러 단에 인접 배치하는 아키텍처다.
> 2. **가치**: 메모리 칩 내부를 뜯어고쳐야 하는 PIM의 공정 수율 저하와 용량(Density) 손실 문제를 완벽히 회피하면서도, 호스트 CPU로의 데이터 이동(Memory Wall)은 획기적으로 차단한다.
> 3. **판단 포인트**: 초거대 AI의 메모리 용량 한계(Capacity Wall) 극복을 위해 CXL 인터페이스 기반 메모리 확장이 대세가 되면서, CXL 컨트롤러에 연산 로직을 심는 CXL-PNM 폼팩터가 데이터센터의 현실적 주력으로 부상했다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 폰 노이만 병목 해결을 위한 PIM과 PNM의 설계 철학적 차이 이해 | 메모리 '내부(다이)' vs 메모리 '근처(기판/컨트롤러)' | PIM과 PNM을 동일한 기술로 취급하거나 혼용하여 서술 |
| PNM이 부상하게 된 하드웨어적 공정 제약 및 현실적 한계 파악 | PIM의 수율/발열/용량 침해 문제 극복, 기존 DRAM 칩 재사용(원가 절감) | PNM이 PIM보다 무조건 속도가 빠르다고 서술하는 오류 (속도는 PIM이 더 빠름) |

> 요약: PIM이 "성능 극대화"를 위한 반도체 공학의 이상(Ideal)이라면, PNM은 "용량 확보와 수율 안정"을 노린 시스템 패키징의 현실(Reality)이라는 트레이드오프를 명확히 해야 한다.

## Ⅰ. 개요 및 필요성

- 정의: 데이터 연산 기능(Accelerator)을 메모리 칩 내부가 아닌, 메모리 모듈 기판(PCB)이나 메모리 컨트롤러 칩렛(Chiplet)에 인접하여 통합 설계하는 차세대 메모리 시스템
- 배경: PIM(In-Memory) 설계 시 메모리 공정과 로직 공정의 차이로 인한 수율 하락, 셀 면적(Density) 잠식으로 인한 칩당 메모리 용량 급감의 치명적 한계 직면
- 필요성: 범용 메모리(DRAM) 칩 공정을 전혀 건드리지 않고 그대로 재사용하면서, 호스트(CPU)와의 데이터 전송 트래픽은 획기적으로 줄여 전력과 성능 효율(TCO)을 높이는 타협점 요구

## Ⅱ. 구조 및 구성요소 (메모리 모듈 기반 분리 구조)

```text
[CXL 기반 PNM 아키텍처의 물리적/논리적 배치도]
+-------------------------------------------------------------+
|  [ 범용 DRAM 칩 ] [ 범용 DRAM 칩 ] [ 범용 DRAM 칩 ] (기존 공정) |
+-------------------------------------------------------------+
|    || 버스 통신           || 버스 통신          || 버스 통신   |
+=============================================================+
| [ PNM 연산 컨트롤러 (MAC 유닛 + CXL 인터페이스 내장 ASIC) ] | <- 기판에 장착
+=============================================================+
                           || (CXL 프로토콜)
                 [ 호스트 CPU / GPU 다이 ]
```

| 구성요소 | 핵심 역할 | 소재 및 공정 특성 |
|:---|:---|:---|
| 범용 DRAM 칩 | 순수 데이터 저장 (연산 기능 0) | 표준 D램 미세 공정으로 찍어내어 용량(Density) 100% 보존 |
| PNM 컨트롤러 | 메모리 I/O 및 데이터 자체 연산 가속 | 로직 파운드리 공정으로 제조된 ASIC 칩. 기판에 칩렛 형태로 결합 |
| 모듈 기판 (PCB)| 칩과 컨트롤러를 묶는 베이스보드 | E3.S 등 대형 CXL 폼팩터 규격을 채택하여 쿨링 및 전력 공급 |
| CXL 인터페이스 | 호스트(CPU)와의 초고속 캐시 통신 | 연산된 콤팩트한 결과값만 전송하여 기존 PCIe 병목 원천 차단 |

> 요약: PNM은 반도체 "칩(Die) 설계"의 혁신이 아니라, 기판 위에 칩을 배치하는 "시스템 폼팩터(Form Factor)"의 혁신이다.

## Ⅲ. 동작원리 및 아키텍처 흐름도 (임베딩 룩업 오프로딩)

초거대 언어 모델(LLM)이나 추천 시스템에서 방대한 파라미터를 찾는 작업(Embedding Lookup)을 CPU 대신 PNM이 수행한다.

```text
[PNM 모듈의 연산 오프로딩(Off-loading) 마이크로 흐름]
1. CPU (추론 요청) -> 전체 임베딩 데이터 100GB 로딩을 포기하고, PNM 모듈에 [ 특정 특징 추출 연산 명령 ] 송신
2. PNM 컨트롤러 수신 -> 모듈 위에 꽂힌 수십 개의 DRAM 칩에서 필요한 데이터를 집중적으로 긁어모음 (내부 버스 활용)
3. PNM 내부 MAC 연산기 -> 데이터를 벡터 곱셈 등 축소 연산 수행
4. 완료된 연산 결과(수 MB 스칼라 값)만 CXL 버스를 태워 CPU로 반환
```

| 비교 지표 | 폰 노이만 (CPU 주도) | PNM 아키텍처 | 동작 효과 판단 |
|:---:|:---|:---|:---|
| 메모리 버스 점유율 | 데이터 100GB 전체가 메인보드 횡단 | 결과값 수 MB만 메인보드 횡단 | 폰 노이만 트래픽 병목 99% 해소 |
| CPU 점유 (Stall) | 데이터 올 때까지 파이프라인 멈춤 | CPU는 다른 작업 수행 (비동기) | 호스트 코어 유휴 자원 확보 |
| 메모리 용량 한계 | 시스템 램 슬롯 개수에 종속됨 | CXL 스위치로 수 TB까지 무한 증설 | 파라미터 용량 병목(Capacity Wall) 타파 |

> 요약: 창고(메모리)에서 수만 개의 상자를 본사(CPU)로 보내지 않고, 창고 앞 소장(PNM 컨트롤러)이 상자를 열어 정답만 찾아서 본사에 팩스 1장으로 보고하는 꼴이다.

## Ⅳ. 심화 비교: PIM vs PNM 대조표 (반도체 전략 차이)

| 구분 | PIM (Processing In Memory) | PNM (Processing Near Memory) | 아키텍처 선택 기준 |
|:---|:---|:---|:---|
| 연산기 위치 | DRAM 셀 **내부 (다이)** | 메모리 모듈 **기판** (컨트롤러) | 칩 내부 vs 칩 외부 |
| 최고 대역폭(성능)| 압도적 1위 (다이 내부 초병렬 통신) | 2위 (DRAM과 컨트롤러 간 통신 병목 존재) | 성능 극대화 vs 비용 최적화 |
| 메모리 용량(Density)| 감소함 (연산기가 셀 면적 차지) | **100% 보존** (DRAM 구조 안 건드림) | 초대형 LLM (수백 GB 필요) 적합성 |
| 수율 및 제조 단가 | 극악 (DRAM + 로직 공정 혼합) | **매우 우수** (기존 D램 칩 기성품 조립) | 양산성(Mass Production) 및 범용성 |
| 대표적 폼팩터 | HBM-PIM (삼성), LPDDR-PIM | **CXL-PNM**, NVDIMM 가속기 | HBM (비쌈) vs CXL 모듈 (확장성) |

> 요약: PIM은 칩셋 한계 성능을 극한으로 끌어올리는 HBM(AI 훈련) 시장에 적합하고, PNM은 대용량 가성비 확장이 필수적인 CXL(AI 추론/서버) 시장을 장악하고 있다.

## Ⅴ. 제약 사항 및 CXL 폼팩터 기술 한계

| 리스크 | 발생 원인 | 아키텍처 대응 방안 (CXL 결합) | 극복 원리 및 효과 |
|:---|:---|:---|:---|
| 메모리 용량 병목 | 파라미터가 1조 개를 넘어가면서 메인보드에 램 슬롯(DIMM)을 꽂을 물리적 공간 부족 | **CXL E3.S 폼팩터 도입** | PCIe 슬롯에 꽂는 SSD처럼, 대용량 메모리 모듈(PNM)을 서버 전면 베이에 수십 개 꽂아 수 TB 확보 |
| CPU-PNM 일관성 | CPU 캐시와 PNM 모듈이 각자 계산하다가 데이터 정합성이 깨지는 캐시 불일치 발생 | **CXL.cache 프로토콜 하드웨어 지원** | PNM 모듈이 CPU 캐시 상태를 스누핑(Snooping)하여 메모리 일관성을 H/W 로직으로 완벽 보장 |
| 소프트웨어 추상화 | PIM/PNM 연산 가속기를 OS 커널이 인식하지 못하고 그냥 디스크(블록 기기)로 오인함 | **메모리 시맨틱(Memory Semantics) 드라이버** | PNM 모듈을 Byte 접근이 가능한 투명한 논리적 메모리 공간으로 매핑시켜 프로그래머 진입장벽 철폐 |

> 요약: PNM 아키텍처의 화룡점정은 CXL(Compute Express Link) 프로토콜과의 결합이다. CXL 없이는 호스트와 PNM 간의 캐시 일관성 붕괴로 실사용이 불가능하다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 추천 시스템(Recommendation System) 인프라 전환: 메타(Meta) DLRM 등 수백 GB의 임베딩 테이블을 무작위 추출(Sparse Access)하는 서비스 환경에서, 기존 DDR5 서버를 삼성 CXL-PNM 메모리 확장 서버로 교체하여 CPU-메모리 병목을 제거하고 응답 속도를 2배 개선
2. CXL 스위치 기반 분리형 아키텍처(Disaggregated) 구축: 클라우드 데이터센터 설계 시, CPU 랙과 메모리 랙을 CXL 스위치 네트워크로 분리하고, 메모리 랙 전단에 PNM 컨트롤러 풀(Pool)을 두어 연산 부하에 따라 PNM 자원을 동적으로 소프트웨어 할당(SDDC)
3. 온프레미스 LLM 추론 가속: 기업 내부망(On-prem)에서 Llama3 등 70B 파라미터 모델을 서비스할 때 초고가의 엔비디아 H100 GPU 8대를 사는 대신, 고용량 CXL-PNM 모듈을 일반 서버에 다중 장착하여 '용량 부족(OOM)'과 '메모리 대역폭 한계'를 동시에 저비용으로 해결

**결론 (2줄):**
- 기술사 판단: PNM 아키텍처는 PIM의 이상적 공학 목표를 반도체 수율과 기판 단위 패키징이라는 현실적 시스템 비즈니스로 우회 달성한 뛰어난 엔지니어링 타협이다.
- 향후 방향: HBM의 가격 폭등과 용량 한계가 극에 달함에 따라, AI 추론(Inference) 서버 시장의 주도권은 막대한 메모리를 욱여넣고 스스로 연산까지 수행하는 CXL 기반 PNM 폼팩터로 빠르게 재편될 것이다.
