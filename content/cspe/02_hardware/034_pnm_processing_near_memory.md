# 📖 【암기용】 개념 완전 이해

> 목적: "왜 연산기를 메모리 칩 안(PIM)이 아니라 밖(PNM)에 두는가"라는 선택의 이유를, 표준 메모리를 그대로 쓸 수 있다는 경제성 관점에서 완전히 이해하게 만든다.

## 한눈에
- **개요**: PNM(Processing Near Memory)은 **폰 노이만 병목(Memory Wall)**을 완화하는 **근접 처리(Near-Memory Computing)** 기술 중 하나로, 메모리 칩 **내부**가 아니라 칩과 **인접한 로직 영역**(모듈 버퍼, 메모리 컨트롤러 등)에 연산기를 배치하는 방식이다.
- **왜 필요한가**: PIM처럼 메모리 칩 자체(D램 공정)를 바꿔서 연산기를 심으면 이상적이지만, D램 공정과 로직(연산기) 공정은 성질이 달라 같이 만들면 수율이 떨어지고 비용이 오른다. PNM은 표준 D램 칩은 손대지 않고 그 옆(컨트롤러·모듈)에 연산기를 따로 붙여, 공정 리스크 없이 데이터 이동 거리만 줄이는 현실적 타협이다.
- **핵심 직관**: 방(메모리 칩) 안을 뜯어고쳐 미니 주방을 넣는 대신(PIM), 방 바로 문 앞 복도(모듈/컨트롤러)에 간이 조리대를 놓는 것(PNM). 방 내부는 원래 그대로 쓸 수 있어 공사(공정 변경)가 필요 없다.

## 핵심 용어 정리 (내부에 등장하는 것들)

| 용어 | 의미 | 비유 |
|:---|:---|:---|
| 폰 노이만 병목 (Memory Wall) | CPU-메모리 간 데이터 이동이 성능·전력을 잡아먹는 현상 — PNM이 풀려는 **상위 문제** | 창고-사무실 복도의 상시 정체 |
| 근접 처리 (Near-Memory Computing) | 메모리 '내부'가 아니라 '근처'에서 데이터를 처리하는 접근 계열 — PNM이 속한 **상위 범주** | 창고 안이 아니라 창고 문 앞에서 처리 |
| PIM (Processing-in-Memory) | 메모리 칩 **내부**(뱅크)에 연산기를 넣는 방식 — PNM과 항상 비교되는 상대 개념 | 창고 칸 안에 계산기를 박아 넣음 |
| Near-Memory Processor | PNM에서 실제 연산을 담당하는 유닛(NPU, FPGA 등) | 창고 문 앞에 세운 계산 담당 알바생 |
| Memory Buffer/Controller | 메모리 접근을 중계하고 연산을 제어하는 로직 칩 | 창고 입출고를 관리하는 감독관 |
| Standard Memory (Legacy DRAM) | 공정을 바꾸지 않은 기존 표준 D램 칩 | 원래 그대로 쓰는 창고 선반 |
| High-speed Interconnect | 근접 연산기와 메모리 사이를 잇는 고속 배선 | 창고 선반과 문 앞 조리대를 잇는 짧은 통로 |
| 로직 공정 vs 메모리 공정 | 연산기(로직)를 만드는 공정과 D램 셀을 만드는 공정 — 성격이 달라 한 칩에 섞기 어려움 | 정밀 시계 공장과 대량 벽돌 공장을 한 라인에 합치는 것 |

## 깊이 이해

### 왜 굳이 메모리 칩 밖에 연산기를 두나 — 공정·수율 관점
- D램 공정은 셀 하나하나를 극도로 작고 촘촘하게 찍어내는 데 최적화돼 있고, 로직(연산기) 공정은 트랜지스터를 빠르게 동작시키는 데 최적화돼 있다. 이 둘을 한 칩(PIM)에 섞으면 두 공정의 장점을 다 살리기 어렵고 불량률(수율 저하)이 올라간다.
- PNM은 D램 칩은 기존 공정 그대로 찍어내고, 연산기만 별도의 로직 공정(칩)으로 만들어 컨트롤러나 모듈 기판에 붙인다. 그 결과 답안 Ⅳ에서 보듯 도입 비용(TCO)이 PIM 대비 약 30% 이상 저렴해지고, 상용화 장벽도 훨씬 낮다(모듈/컨트롤러 설계 수준이라 칩 재설계가 불필요).

### 데이터가 얼마나 덜 움직이나 — 수치로 이해
- Near-Memory Processor는 CPU와 메모리 사이, 데이터 이동 경로의 '중간 지점'에 위치한다. 예를 들어 필터링·집계 같은 연산을 이 지점에서 미리 끝내면, 원래 CPU까지 가야 했던 데이터의 상당 부분이 시스템 버스에 오르지 않고 사라진다.
- 답안 Ⅴ의 점검 항목대로, 이렇게 근접 연산기가 미리 처리하고 나면 시스템 버스 점유율이 기존 대비 40% 이상 줄고, 그만큼 CPU가 처리할 수 있는 추론 처리량(TPS)이 약 1.5배 이상 늘어나는 식으로 성능에 반영된다. 대역폭이 아니라 "버스에 실리는 데이터 총량"을 줄인 결과라는 점이 핵심이다.

### 언제 PIM 대신 PNM을 고르나 — 판별 원리
- ① 메모리 공정을 바꿀 수 없거나 빠른 상용화가 필요할 때(표준 D램 칩을 그대로 재고로 쓸 수 있어야 함), ② 복잡한 연산기(고성능 로직)를 넣어야 할 때(로직 공정이라 미세 공정 적용이 쉬움), ③ 이미 구축된 CXL 같은 표준 인터페이스에 얹어 확장하고 싶을 때 — 이 세 조건에서는 PIM보다 PNM이 현실적이다.
- 반대로 극한의 전력 절감·대역폭이 최우선이면(뱅크 내부 초고속 경로가 필요하면) PIM이 더 유리하다 — 즉 "성능 최댓값은 PIM, 구현 용이성·경제성은 PNM"이라는 트레이드오프로 정리된다.

### 비유와 흔한 오해
- **비유**: 아파트(메모리 칩) 내부 구조를 바꿔 각 세대에 미니 주방을 넣는 대신(PIM), 아파트는 그대로 두고 1층 로비(컨트롤러/모듈)에 공용 주방을 하나 크게 만드는 것(PNM). 공사 범위가 훨씬 작다.
- **오해**: "PNM은 PIM보다 무조건 하급 기술"이라는 생각은 틀렸다. PNM은 로직 공정을 그대로 쓸 수 있어 오히려 더 복잡하고 강력한 연산기를 넣기 유리하다 — 위치가 다를 뿐 우열 관계가 아니다.

## 연결 개념
- PIM (Processing In Memory) — 메모리 칩 '내부'에서 연산하는 대응 개념(033에서 상세)
- CXL (Compute Express Link) — PNM 연산기를 표준 인터페이스로 연결·확장하는 핵심 프로토콜(035에서 상세)
- Memory Wall (폰 노이만 병목) — PIM·PNM이 공통으로 해소하려는 상위 문제
- AXDIMM — PNM 개념이 실제 제품화된 대표 사례

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: PNM은 구현 용이성(Legacy Memory 활용)과 연산 유연성(Logic Process) 관점에서 PIM과 차별화하여 기술한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: PNM은 메모리 칩 외부의 근접 영역(DIMM, Base Die, Controller)에 연산 유닛을 배치하여 데이터 이동 경로를 단축하는 기술이다.
> 2. **가치**: 표준 메모리 칩을 그대로 사용하여 제조 비용을 절감하면서도, 폰 노이만 병목을 완화하고 복잡한 연산 로직 통합이 용이하다.
> 3. **판단 포인트**: 메모리 공정 변경 없이 빠른 상용화가 필요하거나, 고성능 로직 공정 기반의 연산 능력이 필요할 때 PNM이 유리하다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| PIM vs PNM 아키텍처 구분 역량 | 연산 위치(Near Memory), 표준 메모리 재사용성 | PIM과 동일하게 '칩 내부'로 서술 |
| 구현 현실성 및 경제성 판단 | 로직 공정 활용 가능, 수율 및 비용 우위 | 기술적 우위만 나열하고 비용 측면 누락 |
| 최신 인터페이스(CXL) 시너지 이해 | CXL 기반 메모리 확장 및 가속기 결합 | 인터페이스 표준과의 관계 누락 |

> 요약: 기존 메모리 생태계를 파괴하지 않으면서 성능을 개선하는 '현실적 데이터 중심 컴퓨팅'임을 강조한다.

## Ⅰ. 개요 및 필요성

- 정의: 메모리 칩(DRAM)과 인접한 로직 영역(모듈 버퍼, 컨트롤러 등)에 연산기를 배치하여 데이터 이동 거리를 최소화하는 기술
- 배경: PIM의 메모리 공정 변경에 따른 고비용/저수율 문제 극복 및 고성능 연산기(NPU 등) 통합 필요성 대두
- 필요성: 시스템 대역폭 절약(60% 이상), 에너지 효율 향상, 기존 DDR/HBM 생태계 호환성 유지

## Ⅱ. 구조 및 구성요소

```text
Host CPU/GPU <-> CXL/Memory Bus <-> PNM Controller (Processor Near Memory)
                                             |
                                             +-- Standard Memory Chip 1 (DRAM)
                                             +-- Standard Memory Chip 2 (DRAM)
                                             ...
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Near-Memory Processor | 실제 연산 수행 (NPU, FPGA 등) | 로직 공정(5nm 등) 적용 가능 |
| Memory Buffer/Controller | 메모리 접근 및 연산 제어 | CXL 2.0/3.0 기반 확장 용이 |
| Standard Memory | 데이터 저장 (Legacy DRAM) | 칩 내부 수정 없이 그대로 사용 |
| High-speed Interconnect | 연산기와 메모리 간 통로 | 모듈 내 초고속 배선 또는 TSV |

> 요약: 표준 메모리 칩은 그대로 두고, 그 입구(Controller/Buffer)에 강력한 연산 성능을 갖춘 로직 칩을 결합하는 구조다.

---

## Ⅲ. 동작원리 및 흐름도

```text
호스트 연산 요청 -> PNM 컨트롤러 수신 -> 인접 메모리에서 데이터 인출(Short Path)
                                             |
                                             +-- PNM 내 연산기에서 처리
                                             |
호스트 결과 반환 <- 가공된 결과값 임시 저장 <- 연산 완료
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 데이터 처리 명령 오프로드 | 호스트-PNM 간 명령어 세트 호환성 |
| 2 | 메모리 칩 데이터 병렬 인출 | 로컬 인터페이스 대역폭 활용률 |
| 3 | 근접 연산기(NMP) 처리 | 연산기 성능(TOPS) 및 대기시간 |
| 4 | 최종 결과 데이터 요약/반환 | 시스템 버스 트래픽 감소량(%) |

> 요약: 데이터가 시스템 버스를 타고 CPU로 가기 전, 메모리 입구에 있는 전용 연산기가 이를 가공하여 시스템 부하를 줄이는 흐름이다.

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | PIM (In-Memory) | PNM (Near-Memory) | 선택 기준 |
|:---|:---|:---|:---|
| 연산 위치 | 메모리 뱅크 내부 (Cell 근처) | 메모리 칩 외부 (Controller/DIMM) | 연산 유닛의 크기/성능 요구치 |
| 공정 | 메모리 공정 (DRAM) | 로직 공정 (TSMC/삼성 파운드리) | 제조 원가 및 연산 복잡도 |
| 상용화 장벽 | 높음 (칩 재설계 필수) | 낮음 (모듈/컨트롤러 설계) | 시장 출시 시점 (Time-to-Market) |

> 요약: 극도의 전력 절감이 목표면 PIM, 복잡한 연산 가속과 빠른 도입이 목표면 PNM을 선택한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 병목 현상 | 컨트롤러-메모리 간 대역폭 한계 | 인터페이스 대역폭 확장 (CXL 3.0 등) | Local Bandwidth (GB/s) |
| 소프트웨어 스택 | 전용 드라이버 및 런타임 필요 | 표준 CXL Fabric Manager 활용 | 소프트웨어 호환성 리스트 |
| 전력 밀도 | 연산기 탑재로 인한 모듈 발열 | 능동 냉각 및 전력 제한 기술 | 모듈 온도 (Case Temp) |

> 요약: 연산기와 메모리 사이의 로컬 병목을 해결하고, 표준화된 소프트웨어 환경을 구축하는 것이 관건이다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 시스템 버스 점유율 | 기존 대비 40% 이상 감소 | 성능 카운터 (Bus Utilization) |
| 추론 처리량 (TPS) | 기존 시스템 대비 1.5배 이상 | End-to-End AI 벤치마크 |
| 도입 비용 (TCO) | PIM 대비 30% 이상 저렴 | 부품 단가 및 운용 비용 산출 |

> 요약: 도입 성공은 시스템 전체 트래픽 감소량과 가성비(성능/비용) 지표로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. CXL 메모리 확장기: CXL 기반 메모리 풀에 PNM 기능을 결합하여 데이터 검색(Filtering)이나 정렬을 가속
2. 스마트 스토리지/DIMM: AXDIMM과 같은 솔루션을 기존 서버에 장착하여 코드 수정 최소화 기반 AI 성능 향상
3. 데이터 전처리 가속: 빅데이터 분석 시 필터링, 집계(Aggregation) 연산을 PNM으로 오프로드하여 CPU 부하 경감

**결론 (2줄):**
- 기술사 판단: PNM은 PIM의 현실적인 대안이자 보완재이며, 특히 CXL 생태계 확산에 따라 기업용 서버 시장에서 가장 먼저 주류가 될 가능성이 높다.
- 향후 방향: 3D 적층 기술을 통해 로직 다이와 메모리 다이를 수직 결합한 하이브리드 형태(HBM4 등)로 PIM과 PNM의 경계가 허물어지며 발전할 전망이다.
