# 📖 【암기용】 개념 완전 이해

> 목적: PNM을 처음 봐도 PIM과 무엇이 다르고 왜 쓰는지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 메모리 칩 내부(Inside)가 아닌, 메모리 칩과 매우 가까운 위치(모듈, 컨트롤러, 로직 다이 등)에 연산기를 배치하여 데이터를 처리하는 기술
- **왜 필요한가**: PIM(칩 내부)은 메모리 칩 공정 자체를 바꿔야 해서 수율과 비용 부담이 큼. PNM은 메모리 칩은 그대로 두고 그 주변(예: CXL 컨트롤러)에 연산기를 넣음으로써 현실적인 타협점을 제공함.
- **핵심 직관**: 창고(메모리) 안에 가스레인지를 넣는 게 아니라(PIM), 창고 바로 옆에 간이 주방(PNM)을 만들어 데이터를 조금만 이동시켜 처리하는 것.

## 깊이 이해
- **배경·문제의식**: 데이터 이동 병목은 줄여야겠는데, 메모리 칩(DRAM)은 극도의 미세 공정과 대량 양산 체제라 내부 구조를 바꾸기가 매우 힘듦. 메모리 칩은 그대로 쓰면서도 데이터 이동 거리를 획기적으로 줄일 방법이 필요해짐.
- **작동 원리**: 메모리 모듈(DIMM) 상의 버퍼 칩, HBM의 베이스 다이(Base Die), 또는 CXL 메모리 컨트롤러 내부에 연산기(NPU 등)를 배치함. 데이터가 CPU까지 가기 전에 이 '근접 연산기'에서 먼저 처리됨.
- **비유**: 대형 도서관 서가마다 알바생을 두는 대신(PIM), 각 층 복도 입구(PNM)에 복사기와 알바생을 두어 층 밖으로 책이 나가지 않게 처리하는 것.
- **구체 예시**: 삼성전자의 AXDIMM(가속 DIMM). 메모리 모듈에 AI 가속기를 탑재하여 CPU 성능을 돕고 에너지를 절감함. 최근엔 CXL 기반 PNM 솔루션이 활발히 연구됨.
- **흔한 오해·주의점**: PNM이 PIM보다 무조건 하급 기술인 것은 아님. PNM은 더 복잡한 연산기를 넣기에 유리하고(로직 공정 활용), 기존 표준 메모리 칩을 그대로 쓸 수 있다는 강력한 경제적 장점이 있음.

## 연결 개념
- PIM (Processing In Memory) — 메모리 칩 '내부' 연산
- CXL (Compute Express Link) — PNM을 구현하기 위한 핵심 인터페이스
- AXDIMM — PNM 기술이 적용된 메모리 모듈 사례
- Memory Wall — PNM이 해결하려는 시스템 병목

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: PNM은 구현 용이성(Legacy Memory 활용)과 연산 유연성(Logic Process) 관점에서 PIM과 차별화하여 기술한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: PNM은 메모리 칩 외부의 근접 영역(DIMM, Base Die, Controller)에 연산 유닛을 배치하여 데이터 이동 경로를 단축하는 기술이다.
> 2. **가치**: 표준 메모리 칩을 그대로 사용하여 제조 비용을 절감하면서도, 폰 노이만 병목을 완화하고 복잡한 연산 로직 통합이 용이하다.
> 3. **판단 포인트**: 메모리 공정 변경 없이 빠른 상용화가 필요하거나, 고성능 로직 공정 기반의 연산 능력이 필요할 때 PNM이 유리하다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| PIM vs PNM 아키텍처 구분 역량 | 연산 위치(Near Memory), 표준 메모리 재사용성 | PIM과 동일하게 '칩 내부'로 서술 |
| 구현 현실성 및 경제성 판단 | 로직 공정 활용 가능, 수율 및 비용 우위 | 기술적 우위만 나열하고 비용 측면 누락 |
| 최신 인터페이스(CXL) 시너지 이해 | CXL 기반 메모리 확장 및 가속기 결합 | 인터페이스 표준과의 관계 누락 |

> 요약: 기존 메모리 생태계를 파괴하지 않으면서 성능을 개선하는 '현실적 데이터 중심 컴퓨팅'임을 강조한다.

---

## Ⅰ. 개요 및 필요성

- 정의: 메모리 칩(DRAM)과 인접한 로직 영역(모듈 버퍼, 컨트롤러 등)에 연산기를 배치하여 데이터 이동 거리를 최소화하는 기술
- 배경: PIM의 메모리 공정 변경에 따른 고비용/저수율 문제 극복 및 고성능 연산기(NPU 등) 통합 필요성 대두
- 필요성: 시스템 대역폭 절약(60% 이상), 에너지 효율 향상, 기존 DDR/HBM 생태계 호환성 유지

---

## Ⅱ. 구조 및 구성요소

```text
Host CPU/GPU <-> CXL/Memory Bus <-> PNM Controller (Processor Near Memory)
                                             |
                                             +-- Standard Memory Chip 1 (DRAM)
                                             +-- Standard Memory Chip 2 (DRAM)
                                             ...
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Near-Memory Processor | 실제 연산 수행 (NPU, FPGA 등) | 로직 공정(5nm 등) 적용 가능 |
| Memory Buffer/Controller | 메모리 접근 및 연산 제어 | CXL 2.0/3.0 기반 확장 용이 |
| Standard Memory | 데이터 저장 (Legacy DRAM) | 칩 내부 수정 없이 그대로 사용 |
| High-speed Interconnect | 연산기와 메모리 간 통로 | 모듈 내 초고속 배선 또는 TSV |

> 요약: 표준 메모리 칩은 그대로 두고, 그 입구(Controller/Buffer)에 강력한 연산 성능을 갖춘 로직 칩을 결합하는 구조다.

---

## Ⅲ. 동작원리 및 흐름도

```text
호스트 연산 요청 -> PNM 컨트롤러 수신 -> 인접 메모리에서 데이터 인출(Short Path)
                                             |
                                             +-- PNM 내 연산기에서 처리
                                             |
호스트 결과 반환 <- 가공된 결과값 임시 저장 <- 연산 완료
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 데이터 처리 명령 오프로드 | 호스트-PNM 간 명령어 세트 호환성 |
| 2 | 메모리 칩 데이터 병렬 인출 | 로컬 인터페이스 대역폭 활용률 |
| 3 | 근접 연산기(NMP) 처리 | 연산기 성능(TOPS) 및 대기시간 |
| 4 | 최종 결과 데이터 요약/반환 | 시스템 버스 트래픽 감소량(%) |

> 요약: 데이터가 시스템 버스를 타고 CPU로 가기 전, 메모리 입구에 있는 전용 연산기가 이를 가공하여 시스템 부하를 줄이는 흐름이다.

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 구현 난이도 | 상대적으로 낮음 | 표준 메모리 활용, 공정 변경 불필요 |
| 연산 능력 | 고성능 로직 통합 가능 | 5nm 이하 미세 공정 연산기 탑재 용이 |
| 경제성 | 우수 (Cost-effective) | 메모리 수율에 영향 없음, 기존 설비 활용 |
| 호환성 | 우수 | CXL 등 표준 인터페이스와 결합 용이 |

> 요약: PIM보다 강력한 연산 유닛을 저렴하고 빠르게 구현할 수 있으며, 시스템 유연성이 높은 것이 특징이다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | PIM (In-Memory) | PNM (Near-Memory) | 선택 기준 |
|:---|:---|:---|:---|
| 연산 위치 | 메모리 뱅크 내부 (Cell 근처) | 메모리 칩 외부 (Controller/DIMM) | 연산 유닛의 크기/성능 요구치 |
| 공정 | 메모리 공정 (DRAM) | 로직 공정 (TSMC/삼성 파운드리) | 제조 원가 및 연산 복잡도 |
| 상용화 장벽 | 높음 (칩 재설계 필수) | 낮음 (모듈/컨트롤러 설계) | 시장 출시 시점 (Time-to-Market) |

> 요약: 극도의 전력 절감이 목표면 PIM, 복잡한 연산 가속과 빠른 도입이 목표면 PNM을 선택한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 병목 현상 | 컨트롤러-메모리 간 대역폭 한계 | 인터페이스 대역폭 확장 (CXL 3.0 등) | Local Bandwidth (GB/s) |
| 소프트웨어 스택 | 전용 드라이버 및 런타임 필요 | 표준 CXL Fabric Manager 활용 | 소프트웨어 호환성 리스트 |
| 전력 밀도 | 연산기 탑재로 인한 모듈 발열 | 능동 냉각 및 전력 제한 기술 | 모듈 온도 (Case Temp) |

> 요약: 연산기와 메모리 사이의 로컬 병목을 해결하고, 표준화된 소프트웨어 환경을 구축하는 것이 관건이다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 시스템 버스 점유율 | 기존 대비 40% 이상 감소 | 성능 카운터 (Bus Utilization) |
| 추론 처리량 (TPS) | 기존 시스템 대비 1.5배 이상 | End-to-End AI 벤치마크 |
| 도입 비용 (TCO) | PIM 대비 30% 이상 저렴 | 부품 단가 및 운용 비용 산출 |

> 요약: 도입 성공은 시스템 전체 트래픽 감소량과 가성비(성능/비용) 지표로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. CXL 메모리 확장기: CXL 기반 메모리 풀에 PNM 기능을 결합하여 데이터 검색(Filtering)이나 정렬을 가속
2. 스마트 스토리지/DIMM: AXDIMM과 같은 솔루션을 기존 서버에 장착하여 코드 수정 최소화 기반 AI 성능 향상
3. 데이터 전처리 가속: 빅데이터 분석 시 필터링, 집계(Aggregation) 연산을 PNM으로 오프로드하여 CPU 부하 경감

**결론 (2줄):**
- 기술사 판단: PNM은 PIM의 현실적인 대안이자 보완재이며, 특히 CXL 생태계 확산에 따라 기업용 서버 시장에서 가장 먼저 주류가 될 가능성이 높다.
- 향후 방향: 3D 적층 기술을 통해 로직 다이와 메모리 다이를 수직 결합한 하이브리드 형태(HBM4 등)로 PIM과 PNM의 경계가 허물어지며 발전할 전망이다.
