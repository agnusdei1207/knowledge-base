# 📖 【암기용】 개념 완전 이해

> 목적: PNM을 처음 봐도 PIM과 어떻게 다른지, 왜 연산 로직을 메모리 다이 밖에 두는지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 연산 로직을 DRAM 다이 내부가 아니라 메모리와 물리적으로 가까운 별도 다이(베이스 다이·버퍼 칩·컨트롤러)에 배치해 데이터 이동 거리를 줄이는 방식
- **왜 필요한가**: PIM은 DRAM 공정 제약으로 연산 성능이 낮은데, PNM은 로직 공정으로 만든 별도 다이에 연산기를 둬 DRAM 공정 제약 없이 더 복잡한 연산을 근접 위치에서 수행할 수 있다
- **핵심 직관**: 창고 안에 소형 설비를 넣는 대신(PIM), 창고 바로 옆 사무실에 정식 가공 설비를 두고 물건을 조금만 옮겨 가공하는 것이다

## 깊이 이해
- **배경·문제의식**: PIM은 연산 로직이 DRAM 다이 자체에 붙어 있어 DRAM 공정(고성능 로직에 불리한 공정)의 제약을 그대로 받는데, AI 워크로드 중 일부는 MAC보다 복잡한 연산(활성화 함수, 정렬, 필터링)을 요구한다.
- **작동 원리**: PNM은 HBM 스택의 베이스 다이, DIMM의 버퍼 칩, 또는 CXL 메모리 확장 모듈의 컨트롤러 다이처럼 DRAM 다이와는 별도의 로직 공정 다이에 연산 유닛을 배치해, TSV나 인터커넥트로 메모리와 짧은 거리에서 데이터를 주고받으며 연산한다.
- **대표 구현 예시**: 삼성전자의 AXDIMM(Acceleration DIMM)은 DIMM 버퍼 칩 위치에 FPGA 기반 연산 유닛을 배치해 추천 시스템 임베딩 연산을 메모리 근접 위치에서 처리하도록 설계되었고, CXL 기반 메모리 확장 장치의 컨트롤러 다이에 연산 로직을 넣는 방식도 PNM 범주에 속한다(제조사 공개 자료 기준).
- **비유**: PNM은 재료 창고 바로 옆 사무실에 정식 조립 라인을 두어, 창고에서 몇 걸음만 옮기면 전문 설비로 가공할 수 있게 하는 것과 같다.
- **구체 예시**: HBM 스택에서 DRAM Die가 아닌 Base Die(로직 공정)에 벡터 연산 유닛을 추가하는 구조는 다이 자체는 DRAM이 아니므로 PIM이 아니라 PNM으로 분류된다.
- **흔한 오해·주의점**: "메모리 가까이 있으면 모두 PIM"이라는 오해가 흔하지만, 분류 기준은 물리적 거리가 아니라 연산 로직이 DRAM 다이 내부(PIM)인지 별도 로직 다이(PNM)인지이므로 이 기준으로 구분해야 한다.

## 연결 개념
- PIM(Processing-in-Memory) — 연산 로직이 DRAM 다이 내부에 있는 대비 개념
- HBM Base Die — PNM 연산 로직이 흔히 위치하는 다이
- CXL(Compute Express Link) — PNM 컨트롤러 다이 연산이 결합되는 인터커넥트
- AXDIMM — 삼성전자의 DIMM 버퍼 칩 기반 PNM 구현 사례

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: PNM은 근접 위치라는 표면적 특징보다, 연산 로직이 별도 로직 다이에 있다는 구조적 차이와 PIM 대비 성능·적용 범위 차이를 중심으로 답안을 구성한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: PNM은 연산 로직을 DRAM 다이가 아닌 별도 로직 공정 다이(베이스 다이·버퍼 칩·컨트롤러)에 배치해 메모리 근접 위치에서 연산하는 구조다.
> 2. **가치**: DRAM 공정 제약 없이 로직 공정 성능을 활용해 PIM보다 복잡한 연산을 근접 위치에서 처리할 수 있다.
> 3. **판단 포인트**: PIM과 PNM 선택은 데이터 이동 거리 최소화(PIM)와 연산 복잡도·성능(PNM) 중 어느 쪽이 우선인지로 판단한다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| PIM vs PNM 위치·공정 구분 확인 | DRAM 다이 내부(PIM) vs 별도 로직 다이(PNM) | 물리적 거리만으로 PIM/PNM을 구분 |
| 연산 성능·복잡도 이해 확인 | 로직 공정 활용으로 확보하는 연산 성능 이점 | PNM을 PIM의 하위 개념으로 단정 |
| 적용 사례 이해 확인 | AXDIMM, HBM Base Die, CXL 컨트롤러 연산 | 대표 사례 없이 개념만 서술 |

> 요약: 이 문제는 PNM 명칭 암기가 아니라 PIM과의 다이·공정 구분과 적용 사례를 연결하는 판단력을 확인한다.

## Ⅰ. 개요 및 필요성

- 정의: 연산 로직을 DRAM 다이가 아닌 별도 로직 다이에 배치해 메모리와 근접한 위치에서 연산을 수행하는 구조
- 배경: PIM은 DRAM 공정 제약으로 복잡한 연산 처리에 한계가 있어 로직 공정 기반 근접 연산이 대안으로 등장
- 필요성: 데이터 이동 거리를 짧게 유지하면서도 로직 공정의 연산 성능을 확보해 PIM보다 넓은 연산 범위를 지원

---

## Ⅱ. 구조 및 구성요소

```text
Host CPU/GPU
  -> 짧은 인터커넥트(TSV/버스)
  -> Logic Die (Base Die / Buffer Chip / CXL Controller)
       연산 유닛(FPGA/ASIC 등, 로직 공정)
  -> DRAM Die/DIMM (별도 다이, 데이터 저장 전용)
  -> 연산 결과 Host로 반환
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| Logic Die(Base Die/버퍼 칩) | 연산 유닛 탑재, DRAM과 근접 배치 | 로직 공정 사용으로 성능 우위 |
| DRAM Die/DIMM | 순수 데이터 저장 | Logic Die와 별도 다이로 분리 |
| 인터커넥트(TSV/버스) | Logic Die와 DRAM 간 짧은 데이터 경로 | 거리 짧아 지연·전력 이득 |
| 연산 유닛(FPGA/ASIC) | 벡터 연산, 필터링 등 복잡 연산 수행 | PIM 대비 넓은 연산 범위 지원 |

> 요약: PNM은 DRAM과 물리적으로 가까운 별도 로직 다이에 연산 유닛을 두어 공정 제약 없이 근접 연산을 수행한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
Host: 연산 요청 및 데이터 참조 전달
  -> Logic Die가 근접 인터커넥트로 DRAM 접근
  -> Logic Die 내 연산 유닛이 데이터 처리(필터링/집계/벡터 연산)
  -> 처리 결과를 Host로 반환
  -> 원본 데이터는 Host-Logic Die 구간만 이동, 장거리 버스 이동 없음
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | Host가 연산 요청과 대상 주소를 Logic Die로 전달 | 명령 매핑 정확성 |
| 2 | Logic Die가 근접 인터커넥트로 DRAM 데이터 접근 | 접근 지연시간 |
| 3 | Logic Die 내 연산 유닛이 처리 수행 | 연산 정확도, 처리 지연 |
| 4 | 결과를 Host로 반환 | 데이터 이동 거리 대비 개선율 |

> 요약: PNM은 Logic Die가 근접 인터커넥트로 데이터를 가져와 처리한 뒤 결과만 Host로 반환한다.

---

## Ⅳ. 특징

| 구분 | PIM | PNM | 수치·포인트 |
|:---|:---|:---|:---|
| 연산 로직 위치 | DRAM 다이 내부/뱅크 | 별도 로직 다이(베이스 다이·버퍼 칩) | 다이 구분이 핵심 기준 |
| 공정 제약 | DRAM 공정, 로직 성능 낮음 | 로직 공정, 상대적 고성능 | 복잡 연산 지원 가능 여부 |
| 데이터 이동 거리 | 사실상 0(뱅크 내부) | 짧지만 다이 간 이동 존재 | PIM이 이동 거리는 더 짧음 |
| 대표 구현 | HBM-PIM, GDDR6-AiM | AXDIMM, HBM Base Die 연산, CXL 컨트롤러 연산 | 제조사 공개 자료 기준 |

> 요약: PIM은 다이 내부 연산으로 이동 거리가 가장 짧고, PNM은 별도 로직 다이의 성능 이점을 활용한다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | PIM | PNM | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | DRAM 다이 내부 연산 유닛 | 별도 로직 다이 연산 유닛 | 연산 복잡도 요구 수준 |
| 비용/성능 | 낮은 연산 성능, 최소 이동 거리 | 높은 연산 성능, 약간의 이동 거리 | 데이터 이동 최소화 vs 연산 성능 |
| 운영/위험 | DRAM 공정 검증 체계 재사용 제한 | 로직 공정 다이 별도 검증 필요 | 설계·검증 인력·비용 |

> 요약: 단순·반복 연산은 PIM, 필터링·집계 등 복잡 연산은 PNM이 유리하다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| 다이 간 인터커넥트 병목 | Logic Die-DRAM 간 대역폭 제한 | 고속 인터커넥트·TSV 설계 최적화 | 다이 간 대역폭 실측치 |
| 개념 혼동 | PIM/PNM 구분 기준 오적용 | 연산 로직 위치(다이 내부 vs 별도) 기준 문서화 | 설계 문서 검증 |
| 소프트웨어 연동 | 근접 연산 API·프레임워크 미성숙 | 벤더 SDK 연동 검증 | API 호출 성공률 |

> 요약: PNM 리스크는 다이 간 인터커넥트 병목과 개념 혼동이며, 위치 기준을 명확히 문서화해 통제해야 한다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 연산 처리량 | Host 단독 처리 대비 처리량 개선 | 벤치마크 비교 |
| 다이 간 지연 | 목표 지연시간 이내 | 인터커넥트 지연 측정 |
| 정확도 | Host 연산 결과와 오차 허용 범위 이내 | 결과 비교 테스트 |

> 요약: 도입 성공 여부는 처리량 개선, 다이 간 지연, 연산 정확도로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 추천 시스템 임베딩 조회·집계 연산은 AXDIMM류 PNM 장치로 오프로드해 Host CPU 부하를 줄임
2. HBM Base Die 연산과 CXL 컨트롤러 연산을 결합한 이종 근접 연산 아키텍처를 단계적으로 검토함
3. PIM/PNM 구분 기준을 설계 문서에 명시해 아키텍처 검토 시 혼동을 방지함

**결론 (2줄):**
- 기술사 판단: 데이터 이동 최소화가 최우선이면 PIM, 복잡 연산과 로직 성능이 필요하면 PNM을 선택함
- 향후 방향: PNM은 CXL 메모리 풀링과 결합해 다중 호스트가 공유하는 근접 연산 자원으로 확장될 전망임
