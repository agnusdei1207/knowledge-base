## Ⅰ. 개요
- **정의**: 메모리 칩 외부의 버퍼 다이 또는 모듈 기판에 연산 로직을 배치하여 데이터 근접 처리하는 아키텍처
- **배경/필요성**: PIM(033 참조)은 메모리 다이 내부에 로직을 혼재시키므로 공정 난이도와 수율 문제가 발생함. 기존 DRAM 다이를 수정 없이 사용하면서도 데이터 이동을 축소하는 현실적 대안이 요구됨
- **비유**: 창고(메모리) 내부를 개조하지 않고, 창고 바로 앞마당에 작업장을 설치하여 물건을 짧은 거리만 옮겨 가공하는 방식

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| PIM과 PNM의 차이 구분 | 연산기 위치가 다이 외부(모듈 기판/버퍼 다이)임 | PIM(033 참조)은 다이 내부 뱅크에 연산기 배치, PNM은 외부 배치 — 위치가 핵심 차이 |

> 요약: PNM은 기존 DRAM을 수정 없이 유지하면서 모듈 기판의 가속기로 데이터 근접 처리하는 실용적 아키텍처임

## Ⅱ. 구성요소
```text
+---------------------------------------------------+
|              PNM Memory Module (PCB)               |
|                                                    |
|  +--------+ +--------+ +--------+ +--------+      |
|  | DRAM   | | DRAM   | | DRAM   | | DRAM   |      |
|  | (표준) | | (표준) | | (표준) | | (표준) |       |
|  +--------+ +--------+ +--------+ +--------+      |
|       |          |          |          |            |
|       +----------+----------+----------+            |
|                  | 로컬 버스                        |
|            +-----v------+                           |
|            | PNM 가속기 |                           |
|            | (FPGA/ASIC)|                           |
|            +-----+------+                           |
+---------------------------------------------------+
                   | CXL / PCIe 버스
             +-----v------+
             | Host CPU   |
             +------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 표준 DRAM 다이 | 기존 공정으로 제조한 범용 DRAM, 수정 없이 대용량 탑재 가능 | 기성품 선반을 그대로 쓰는 창고 |
| PNM 가속기 | 모듈 기판 위에 별도 탑재한 FPGA 또는 ASIC, 임베딩 검색·MAC 연산 등을 오프로드 | 창고 앞마당의 전용 작업대 |
| 로컬 버스 | DRAM과 PNM 가속기를 모듈 내부에서 연결하는 고속 배선 | 창고에서 앞마당까지의 짧은 컨베이어 |
| CXL/PCIe 인터페이스 | 호스트 CPU와 PNM 모듈 간 명령 전달 및 결과 반환 경로, CXL(035 참조) 활용 시 캐시 일관성 지원 | 본사와 창고를 잇는 택배 노선 |

> 요약: 표준 DRAM·모듈 기판 가속기·로컬 버스·CXL 인터페이스로 구성됨

## Ⅲ. 절차
```text
호스트 오프로드 요청 -> 가속기 데이터 로컬 접근 -> 근접 연산 수행 -> 결과 반환
```
- 1단계: 호스트 CPU가 CXL/PCIe를 통해 연산 작업을 PNM 모듈의 가속기로 오프로드 요청함
- 2단계: PNM 가속기가 로컬 버스를 통해 모듈 내 DRAM에서 대상 데이터를 읽어들임 — 외부 시스템 버스를 경유하지 않음
- 3단계: 가속기가 임베딩 벡터 검색, 필터링, MAC 연산 등을 로컬에서 수행함
- 4단계: 처리 완료된 소량의 결과값만 CXL 버스를 통해 호스트로 반환함 — 원본 데이터 이동량 대비 수백 분의 1 수준임

> 요약: 오프로드 요청 -> 로컬 데이터 접근 -> 근접 연산 -> 경량 결과 반환 순서로 동작함

## Ⅳ. 문제점
- 인터페이스 대역폭 제한: 가속기와 DRAM 사이 로컬 버스 대역폭이 PIM의 뱅크 내부 대역폭에 미치지 못함 — 초고속 연산에는 병목이 됨
- 모듈 전력·면적 증가: 가속기 칩을 별도 탑재하므로 모듈당 소비 전력과 물리적 면적이 증가함 — 서버 랙 밀도에 영향을 줌
- 가속기 프로그래밍 파편화: 벤더마다 FPGA/ASIC 아키텍처가 상이하여 통합 개발 환경이 부재함 — 솔루션 이식성이 낮음

> 요약: 로컬 버스 대역폭·모듈 전력/면적·프로그래밍 파편화가 PNM의 주요 제약임

## Ⅴ. 개선방안
1. 단기: 로컬 버스를 온-인터포저 고속 배선으로 교체(2.5D 패키징)하여 가속기-DRAM 간 대역폭을 확대함
2. 중기: 가속기를 저전력 ASIC으로 특화 설계하고 DRAM 다이와 3D 적층하여 전력·면적 오버헤드를 축소함
3. 장기: CXL 컨소시엄 주도의 표준 오프로드 API를 수립하여 벤더 간 가속기 프로그래밍 호환성을 확보함

> 요약: 고속 배선 전환 -> 저전력 ASIC 적층 -> 표준 API 수립 순으로 제약을 해소함

## Ⅵ. 전망
- 발전 방향: CXL(035 참조) 메모리 풀링과 결합하여 대용량 분산 메모리에 연산을 오프로드하는 구조로 확장됨
- 기술사적 판단: PIM 기술 성숙 전까지 PNM이 대용량 추천 시스템·인메모리 DB 워크로드에서 현실적 가속 수단임
- 기술사 제언: 워크로드 특성에 따라 PIM(초고속·소용량)과 PNM(중속·대용량)을 혼합 배치하는 계층적 설계를 검토할 필요
