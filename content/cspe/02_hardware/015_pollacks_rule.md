## 미리 알고가기

- 폴락의 법칙은 코어 성능이 면적의 제곱근 정도로 증가한다는 경험 법칙임
- 큰 코어 하나보다 작은 코어 여러 개가 처리량에서 유리한 조건을 설명함
- PPA(Power·Performance·Area): 전력·성능·면적을 함께 따지는 설계 균형 기준이며, 이 균형에서 멀티코어 전환 논리가 나옴
- 순차 구간: 병렬화할 수 없어 한 스레드가 순서대로 처리해야 하는 코드 구간임
- p99 응답시간: 전체 요청 중 99%가 이 시간 안에 처리됨을 나타내는 지연 지표임

## 작성 근거(검토용)

- 폴락의 법칙을 공식 암기가 아니라 면적 증가 대비 단일 코어 성능의 수익 체감으로 설명함
- 큰 코어와 작은 코어 다수를 면적 배분·적용 대상·주요 제약으로 비교함
- 경험 법칙은 실행 절차가 아니므로 설계 업무 순서를 그린 기존 Ⅴ절을 삭제함

## Ⅰ. 개요

- **정의/개념**: 폴락의 법칙은 프로세서 코어 성능이 코어 면적 증가에 선형으로 비례하지 않고 대략 제곱근 수준으로 증가한다는 경험적 관찰로, 단일 코어 복잡도 확대의 수익 체감을 설명하는 법칙임
- **배경/필요성**: 제한된 칩 면적에서 처리량을 높이기 위해 대형 코어와 다수 소형 코어의 배분 기준이 필요함

### 쉽게 이해하기 (학습용)
- 코어 면적을 두 배로 늘려도 성능은 대략 1.4배 정도만 늘어나는 것과 같음
- 한정된 칩 면적을 큰 코어 하나에 몰아줄지 작은 코어 여럿에 나눌지 정해야 함

## Ⅱ. 특징

- 면적 투입 대비 성능 이득이 점차 줄어드는 현상을 설명함
- 병렬화 가능한 워크로드에서는 같은 면적을 여러 코어에 배분하는 근거가 됨
- 엄밀한 물리 법칙보다 설계 경험에 기반한 법칙임
- 단일 스레드 지연시간을 우선하는 영역에서는 여전히 큰 코어가 필요함

### 쉽게 이해하기 (학습용)
- 면적을 더 넣을수록 늘어나는 성능 폭이 점점 작아짐(수익 체감)
- 여러 사람이 나눠 할 수 있는 작업이면 작은 코어 여럿으로 쪼개 쓰는 게 이득임
- 혼자 순서대로 처리해야 하는 작업이면 큰 코어 하나가 여전히 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 큰 단일 코어 | 다수의 작은 코어 |
|:---|:---|:---|
| 면적 배분 | 실행 유닛·캐시·제어 로직을 한 코어에 집중 | 같은 면적을 여러 코어로 분할 |
| 적용 대상 | 순차 구간이 크고 지연 시간이 우선인 작업 | 병렬 스레드로 분할 가능하고 처리량이 우선인 작업 |
| 주요 제약 | 면적 증가 대비 단일 코어 성능 수익 체감 | 동기화·메모리 대역폭·순차 구간 |

> 요약: 큰 코어는 단일 스레드 지연을 줄이고, 작은 코어 다수는 같은 면적에서 병렬 처리량을 늘림.

### 쉽게 이해하기 (학습용)
- 일 잘하는 직원 한 명에게 자리를 넓혀줄지, 같은 넓이를 여러 직원에게 나눠줄지 고르는 것과 같음
- 혼자 순서대로 처리할 일이 많으면 큰 자리(큰 코어)가 유리하고, 동시에 나눠 할 일이 많으면 작은 자리 여럿(작은 코어)이 유리함

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 코어 면적 | 캐시·실행 유닛·제어 로직이 차지하는 하드웨어 자원 총량임 |
| 성능 이득 | 면적 증가로 얻는 단일 코어 성능이며 면적의 제곱근 수준으로 증가함 |
| 전력·열 비용 | 추가 회로가 소비하는 전력과 단위 면적에서 발생하는 열을 나타냄 |
| 아키텍처 선택 | 큰 코어와 다수의 작은 코어 중 어디에 면적을 배분할지 결정함 |

```text
+-------+     +----------------+     +-------------+
| 코어 면적 | --> | 성능 이득          | --> | 구조 선택     |
+-------+     +----------------+     +-------------+
    |
    v
+-----------+
| 전력·열 비용 |
+-----------+
```

> 요약: 폴락의 법칙은 면적 증가, 성능 이득, 전력 비용을 함께 보는 설계 판단 기준임.

### 쉽게 이해하기 (학습용)
- 면적을 넣으면(입력) 성능이 늘고 전력·열도 함께 늘어나며, 이 셋을 보고 구조를 고름
- 면적, 성능, 전력이라는 세 저울을 동시에 보고 큰 코어와 작은 코어 중 하나를 선택하는 과정임

## Ⅵ. 실무 사례

1. 지연시간 중심 CPU는 칩 면적을 큰 코어에 배분하고, 단일 스레드 성능과 p99 응답시간으로 검증함
2. 처리량 중심 서버 CPU는 같은 면적을 여러 코어에 배분하고, 면적당 처리량과 병렬 효율로 검증함

### 쉽게 이해하기 (학습용)
- 응답 속도가 중요한 서버는 넓은 자리(큰 코어)를 주고 개인 응답 시간을 재서 확인함
- 동시에 많은 요청을 처리해야 하는 서버는 자리를 여럿으로 쪼개고 전체 처리량을 재서 확인함

## Ⅶ. 결론

- 폴락의 법칙은 면적 증가 대비 단일 코어 성능 이득이 제곱근 수준으로 체감하므로, 순차 구간과 병렬화 가능 구간을 구분해 면적을 배분해야 함
- 순차 구간이 큰 워크로드는 큰 코어에 면적을 집중하고, 병렬화 가능한 워크로드는 다수의 작은 코어로 전환하되 동기화·메모리 대역폭 제약을 함께 통제해야 함

### 쉽게 이해하기 (학습용)
- 지연이 중요한 일과 동시에 처리할 일을 구분해 면적을 어디에 쓸지 판단해야 함
- 면적을 늘린 만큼 성능이 늘어나는지, 전력은 얼마나 늘어나는지 함께 재보고 결정함
