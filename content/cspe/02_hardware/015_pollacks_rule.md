## 미리 알고가기

- 폴락의 법칙은 코어 성능이 면적의 제곱근 정도로 증가한다는 경험 법칙임
- 큰 코어 하나보다 작은 코어 여러 개가 처리량에서 유리한 조건을 설명함
- PPA 균형과 멀티코어 전환 논리의 근거로 자주 쓰임

## Ⅰ. 개요

- **정의/개념**: 폴락의 법칙은 프로세서 코어 성능이 코어 면적 증가에 선형으로 비례하지 않고 대략 제곱근 수준으로 증가한다는 경험적 관찰로, 단일 코어 복잡도 확대의 수익 체감을 설명하는 법칙임
- **배경/필요성**: 코어를 계속 크게 만들수록 면적과 전력은 크게 늘지만 성능 상승 폭은 둔화되므로, big core와 multicore의 면적 배분을 비교해야 함

## Ⅱ. 특징

- 면적 투입 대비 성능 이득이 점차 줄어드는 현상을 설명함
- 단일 코어 대형화보다 다코어 분산이 유리한 배경이 됨
- 엄밀한 물리 법칙보다 설계 경험에 기반한 법칙임
- 단일 스레드 지연시간을 우선하는 영역에서는 여전히 큰 코어가 필요함

## Ⅲ. 종류 및 비교

| 판단 기준 | 큰 단일 코어 | 다수의 작은 코어 |
|:---|:---|:---|
| 면적 투자 효과 | 수익 체감 큼 | 처리량 확장에 유리 |
| 장점 | 단일 스레드 지연 단축 | 병렬 처리량 확대 |
| 한계 | 전력·복잡도 급증 | 병렬화 의존성 |
| 적용 판단 | latency 우선 | parallel workload 우선 |

## Ⅳ. 구성요소 및 구조

|:---|:---|

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 면적 증가 가정    | --> | 성능 이득 추정    | --> | 전력 비용 비교    | --> | 구조 선택      |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **면적 증가 가정**: 코어 복잡도와 캐시를 확대하는 시나리오를 정함
2. **성능 이득 추정**: 체감 성능 상승 폭을 계산함
3. **전력 비용 비교**: PPA 기준으로 손익을 비교함
4. **구조 선택**: big core 또는 multicore 방향을 정함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 폴락의 법칙만 기계적으로 적용하면 단일 스레드 응답을 우선하는 워크로드 요구를 과소평가함
   - 해결방안: latency-critical workload를 별도 평가하고 single-thread gain과 tail latency로 검증함
2. 문제: 면적 대비 성능만 보고 전력과 열 밀도를 함께 보지 않으면 실제 칩 설계가 비현실적일 수 있음
   - 해결방안: PPA를 함께 조정하고 perf per watt와 thermal density로 검증함
3. 문제: 멀티코어 선택 후 소프트웨어 병렬화가 부족하면 기대 처리량 이득이 나오지 않을 수 있음
   - 해결방안: software scalability review를 병행하고 parallel efficiency와 core utilization으로 검증함

## Ⅶ. 적용 사례

- CPU 아키텍처 검토에서는 단일 스레드 요구를 분리하고, single-thread gain과 tail latency로 검증함
- 반도체 설계 팀에서는 PPA 균형을 맞추고, perf per watt와 thermal density로 검증함
- 서버 플랫폼 계획에서는 병렬 확장성을 검토하고, parallel efficiency와 core utilization으로 검증함

## Ⅷ. 결론

폴락의 법칙은 큰 코어를 무조건 키우는 방식의 한계를 보여주며, 면적을 어디에 배분할지 판단하게 함.

## 작성 근거(검토용)

- 폴락의 법칙은 엄밀 공식 암기가 아니라 면적 증가 대비 성능 체감이라는 설계 판단으로 설명함
- 넓은 표현은 면적 배분, PPA, tail latency처럼 비교 가능한 기준으로 바꿈
- 결론은 큰 코어와 작은 코어의 우열이 아니라 워크로드별 면적 배분 문제로 정리함
