## Ⅰ. 개요
- **정의**: 프로세서 코어의 면적(트랜지스터 수)을 2배로 늘리면 단일 스레드 성능은 약 $\sqrt{2}$배만 향상된다는 경험 법칙
- **배경/필요성**: 코어를 크게 만들수록 OoO 로직·캐시 등이 면적을 차지하지만 성능 향상은 둔화됨. 같은 면적을 소형 코어 여러 개에 투자하는 것이 총 처리량 측면에서 유리할 수 있음
- **비유**: 사무실을 2배로 넓혀도 한 사람의 업무 속도는 1.4배 정도만 빨라지므로, 같은 공간에 책상 2개를 놓고 2명이 일하는 편이 총 산출량이 높은 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 수식 해석 | 성능 $\approx \sqrt{\text{Area}}$ | 면적-성능 관계가 선형이 아님을 명시 |
| 멀티코어 설계 근거 | 소형 코어 N개가 대형 코어 1개보다 총 처리량 우위 | 단일 스레드 성능은 대형 코어가 여전히 우위임을 함께 언급 |
| big.LITTLE 연계 | 이기종 코어 조합의 이론적 근거 | 전력 효율 관점도 포함 필요 |

> 요약: 코어 면적 대비 성능이 제곱근으로 둔화되므로, 소형 코어 다수 배치가 총 처리량에서 유리함

## Ⅱ. 구성요소
```text
              Area = A          Area = 2A
            +---------+      +-------------+
            | Small   |      |   Large     |
            | Core    |      |   Core      |
            | Perf: 1 |      | Perf: ~1.4  |
            +---------+      +-------------+

  Same total area (2A):
  +---------+---------+      +-------------+
  | Small   | Small   |      |   Large     |
  | Core    | Core    |      |   Core      |
  | Perf: 1 | Perf: 1 |      | Perf: ~1.4  |
  +---------+---------+      +-------------+
  Total throughput: 2         Total throughput: ~1.4
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 코어 면적(A) | 트랜지스터 수로 측정되는 코어의 물리적 크기 | 사무실 바닥 면적 |
| 단일 스레드 성능 | $\sqrt{A}$에 비례하여 증가하는 코어 1개의 처리 속도 | 넓은 사무실에서 한 사람이 일하는 속도 |
| 총 처리량 | 코어 수 $\times$ 코어당 성능으로 산출되는 칩 전체 산출량 | 사무실 전체에서 동시에 처리하는 업무 총량 |
| 면적 효율 | 단위 면적당 처리량, 소형 코어가 대형 코어 대비 높음 | 좁은 책상 여러 개가 넓은 책상 하나보다 총 생산성이 높음 |

> 요약: 면적·성능·처리량·면적 효율의 4요소가 코어 설계 트레이드오프를 결정함

## Ⅲ. 절차
```text
Workload Analysis --> Core Size Decision --> Area Allocation --> Performance Estimation
```
- 1단계: **워크로드 분석** — 대상 애플리케이션의 단일 스레드 의존도와 병렬화 비율을 측정함
- 2단계: **코어 크기 결정** — 폴락의 법칙에 따라 대형/소형 코어의 성능 대 면적 비율을 비교함
- 3단계: **면적 배분** — 주어진 총 칩 면적을 대형 코어와 소형 코어에 배분하여 이기종 구성을 설계함
- 4단계: **성능 추정** — 총 처리량 = 코어 수 $\times$ $\sqrt{A_i}$로 설계안의 이론적 성능을 검증함

> 요약: 워크로드를 분석하고 면적-성능 트레이드오프에 따라 코어 구성을 결정함

## Ⅳ. 문제점
- **단일 스레드 성능 희생**: 소형 코어 위주 설계 시 순차 실행 구간의 성능이 저하되어 암달의 법칙 한계가 심화됨
- **워크로드 편차**: 병렬화율이 낮은 애플리케이션에서는 소형 코어 다수가 유휴 상태로 남아 면적이 낭비됨
- **전력·열 불균형**: 대형 코어와 소형 코어 혼합 시 전력 밀도가 불균일하여 열 관리 복잡도가 증가함

> 요약: 단일 스레드 성능 저하, 워크로드 편차, 전력 불균형이 주요 문제임

## Ⅴ. 개선방안
1. 단기: **big.LITTLE 동적 전환** — 순차 구간에서 대형 코어를 활성화하여 단일 스레드 성능 저하를 보완함
2. 중기: **이기종 코어 스케줄러** — 워크로드 특성을 런타임에 감지하여 최적 코어에 태스크를 배치하고 유휴 코어를 줄임
3. 장기: **칩렛 기반 모듈러 설계** — 코어 타일을 칩렛으로 분리·조합하여 워크로드별 최적 면적 배분과 열 분산을 동시에 달성함

> 요약: big.LITTLE 전환, 이기종 스케줄링, 칩렛 설계로 단계적으로 개선함

## Ⅵ. 전망
- **발전 방향**: CPU·GPU·NPU 등 이기종 코어를 단일 칩에 집적하는 구조에서 폴락의 법칙이 코어 크기 결정의 기본 지침으로 활용됨
- **기술사적 판단**: 멀티코어(014 참조) 설계의 이론적 근거이며, 전력 효율(perf/watt)이 면적 효율과 함께 핵심 설계 지표로 부상함
- **기술사 제언**: 폴락의 법칙과 암달의 법칙을 결합하여 워크로드별 최적 코어 수·크기를 정량적으로 도출하는 설계 방법론이 필요함
