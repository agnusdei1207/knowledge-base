# 📖 【암기용】 개념 완전 이해

> 목적: Flynn 분류를 처음 봐도 왜 명령어 흐름과 데이터 흐름 두 축으로 컴퓨터를 나누는지 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 명령어 스트림 수와 데이터 스트림 수의 조합으로 컴퓨터 구조를 4가지로 나눈 분류 체계
- **왜 필요한가**: 병렬 컴퓨터 구조를 논할 때 "무엇이 병렬화되는가"(명령어인가 데이터인가)를 구분하지 않으면 SIMD와 MIMD, GPU와 클러스터를 같은 범주로 혼동하게 된다.
- **핵심 직관**: 한 사람이 한 가지 지시로 여러 재료를 동시에 써는가(SIMD), 여러 사람이 각자 다른 지시로 각자 다른 재료를 다루는가(MIMD)를 구분하는 틀이다.

## 깊이 이해
- **배경·문제의식**: 1966년 Michael Flynn이 컴퓨터 구조를 명령어 스트림(Instruction Stream)과 데이터 스트림(Data Stream)의 단일·다중 여부로 분류하는 체계를 제안했다.
- **작동 원리**: 분류 축은 두 개다. 하나는 동시에 실행되는 명령어 스트림이 하나(Single)인지 여럿(Multiple)인지이고, 다른 하나는 동시에 처리되는 데이터 스트림이 하나(Single)인지 여럿(Multiple)인지이다.
- **작동 원리**: SISD는 단일 명령어·단일 데이터로 전통적 폰 노이만 단일 프로세서 구조이다.
- **작동 원리**: SIMD는 단일 명령어·다중 데이터로 하나의 제어장치가 같은 연산을 여러 데이터에 동시 적용하는 구조이다.
- **작동 원리**: MISD는 다중 명령어·단일 데이터로 같은 데이터에 여러 명령어가 동시 적용되는 구조이며 상용 사례가 극히 드물다.
- **작동 원리**: MIMD는 다중 명령어·다중 데이터로 여러 프로세서가 각자 다른 명령어로 각자 다른 데이터를 처리하는 구조이다.
- **비유**: SISD는 요리사 한 명이 한 재료를 순서대로 손질하는 것이고, SIMD는 요리사 한 명이 "썰어라"는 지시 하나로 여러 채칼이 동시에 여러 재료를 써는 것이다.
- **비유**: MIMD는 요리사 여러 명이 각자 다른 레시피로 각자 다른 재료를 동시에 조리하는 것이다.
- **구체 예시**: SIMD 예시 — AVX-512 명령어 하나로 16개 32비트 정수를 동시에 더한다. MIMD 예시 — 8코어 CPU에서 각 코어가 서로 다른 스레드의 서로 다른 명령어를 동시에 실행한다.
- **흔한 오해·주의점**: GPU는 SIMD로 단순 분류되기보다 SIMT(Single Instruction Multiple Thread)로 별도 명명되며, 워프(warp) 단위로 SIMD 실행하되 스레드별 분기를 부분 지원하는 하이브리드 구조다.
- **흔한 오해·주의점**: MISD는 이론적 분류이며 실제 상용 프로세서 사례가 거의 없다는 점을 "존재하지 않는다"로 단정하면 오답이다. 극소수 결함 허용(fault-tolerant) 연구용 시스템 사례로만 언급된 구조다.

## 연결 개념
- SIMD·MIMD 프로세서 — Flynn 분류의 실제 구현 형태
- 벡터 프로세서 — SIMD 계열의 대표 구현
- GPU SIMT — SIMD를 확장한 스레드 기반 병렬 모델

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: Flynn 분류 답안은 4분류 정의, 분류 축 2개, 각 분류의 대표 구현 사례를 함께 제시한다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Flynn 분류는 명령어 스트림 수와 데이터 스트림 수를 축으로 컴퓨터 구조를 SISD·SIMD·MISD·MIMD 4가지로 나눈 체계이다.
> 2. **가치**: 병렬 처리 대상이 명령어인지 데이터인지 구분해 GPU, 벡터 프로세서, 멀티코어, 클러스터를 서로 다른 병렬화 전략으로 설명할 수 있다.
> 3. **판단 포인트**: SIMD는 규칙적 데이터 병렬 작업에, MIMD는 이질적 작업을 동시 처리하는 범용 병렬 구조에 적합하다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 분류 축 이해 확인 | 명령어 스트림 수 x 데이터 스트림 수 | 4분류 이름만 나열하고 분류 기준 누락 |
| 대표 구현 사례 이해 확인 | SIMD-AVX/GPU, MIMD-멀티코어/클러스터 | 이론적 정의만 쓰고 실제 사례 누락 |
| 예외 구조 이해 확인 | MISD의 희소성, GPU의 SIMT 하이브리드 | MISD가 흔하다고 서술하거나 GPU를 단순 SIMD로만 서술 |

> 요약: 이 문제는 분류 이름 암기보다 두 축의 조합 논리와 대표 사례 매칭 능력을 보여야 한다.

## Ⅰ. 개요 및 필요성

- 개요: 명령어 스트림과 데이터 스트림의 단일·다중 조합으로 컴퓨터 구조를 나눈 분류 체계
- 배경: 1966년 Michael Flynn이 병렬 처리 방식을 논의하기 위해 제안한 고전적 분류 체계
- 필요성: 병렬 컴퓨터 설계 시 무엇을 병렬화할지(명령어 또는 데이터)를 먼저 구분해야 SIMD 가속기와 MIMD 멀티프로세서 설계 방향이 갈림

---

## Ⅱ. 구조 및 구성요소

```text
분류 축1: Instruction Stream (Single/Multiple)
분류 축2: Data Stream (Single/Multiple)
  -> SISD: Single/Single
  -> SIMD: Single/Multiple
  -> MISD: Multiple/Single
  -> MIMD: Multiple/Multiple
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| SISD | 단일 명령어, 단일 데이터 처리 | 전통 단일 프로세서 |
| SIMD | 단일 명령어, 다중 데이터 동시 처리 | 벡터 프로세서, AVX |
| MISD | 다중 명령어, 단일 데이터 처리 | 상용 사례 극히 드묾 |
| MIMD | 다중 명령어, 다중 데이터 처리 | 멀티코어, 클러스터 |

> 요약: Flynn 분류는 명령어·데이터 스트림 수의 4가지 조합으로 병렬 구조를 구분한다.

---

## Ⅲ. 동작원리 및 흐름도

```text
Instruction Stream 판단(단일/다중) -> Data Stream 판단(단일/다중)
  -> 4분류 매핑 -> 해당 하드웨어 구현 선택
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 명령어 스트림이 하나인지 여럿인지 판별 | 제어장치(Control Unit) 개수 |
| 2 | 데이터 스트림이 하나인지 여럿인지 판별 | 동시 처리 데이터 개수 |
| 3 | 두 축 조합으로 4분류 중 하나에 매핑 | 축 조합 일치 여부 |
| 4 | 분류에 맞는 실제 하드웨어 사례 연결 | AVX, GPU, 멀티코어, 클러스터 매칭 |

> 요약: Flynn 분류는 명령어·데이터 축을 순서대로 판별한 뒤 4분류 중 하나로 매핑하는 절차다.

## Ⅳ. 특징

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 장점 | 병렬 처리 전략을 명령어·데이터 축으로 명확히 구분 | 설계 초기 병렬화 대상 식별 |
| 한계 | 현대 하이브리드 구조(SIMT, 이기종 가속기)는 4분류만으로 설명 어려움 | GPU를 SIMD로만 단순화하면 부정확 |
| 비교 포인트 | SIMD는 데이터 병렬, MIMD는 태스크 병렬 | 워크로드 규칙성 여부 |

> 요약: Flynn 분류는 기본 병렬 구조 이해에 유용하지만 SIMT 같은 하이브리드 구조는 추가 설명이 필요하다.

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | SIMD | MIMD | 선택 기준 |
|:---|:---|:---|:---|
| 구조 | 단일 제어장치 + 다중 연산유닛 | 다중 제어장치 + 다중 연산유닛 | 작업 동질성 여부 |
| 비용/성능 | 동일 연산 반복 시 처리량 극대화 | 이질적 작업 동시 처리에 유연 | 워크로드가 규칙적 데이터 병렬인지 |
| 운영/위험 | 분기 발생 시 lane 유휴로 효율 저하 | 태스크 스케줄링·동기화 복잡도 증가 | 분기 빈도, 동기화 오버헤드 |

> 요약: 규칙적 데이터 병렬 작업은 SIMD, 이질적 태스크 병렬 작업은 MIMD를 선택한다.

| 리스크 | 원인 | 대응 방안 | 확인 지표 |
|:---|:---|:---|:---|
| SIMD 효율 저하 | 조건 분기로 lane 일부 유휴 | 분기 최소화, 마스킹 연산 활용 | lane 활용률 |
| MIMD 동기화 오버헤드 | 다중 코어 간 락 경합 | lock-free 구조, 메시지 패싱 도입 | 락 대기 시간 |
| 분류 오적용 | GPU를 단순 SIMD로 오분류 | SIMT 별도 정의 사용 | 아키텍처 문서 검증 |

> 요약: SIMD는 분기 최소화, MIMD는 동기화 오버헤드 관리가 핵심 운영 리스크다.

| 점검 항목 | 목표 기준 | 측정 방법 |
|:---|:---|:---|
| 처리량 | SIMD lane 활용률 목표치 이상 | 프로파일러, 성능 카운터 |
| 확장성 | MIMD 코어 수 증가 대비 처리량 선형성 | 벤치마크 스케일링 테스트 |
| 정확성 | 분류-사례 매칭 오류 0건 | 아키텍처 문서 대조 |

> 요약: 도입 후 성공 여부는 SIMD lane 활용률과 MIMD 스케일링 선형성으로 판단한다.

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개 (필수 — 단계별 또는 항목별):**
1. 이미지·행렬 연산처럼 규칙적 데이터 병렬 워크로드는 SIMD·벡터 프로세서·GPU로 매핑함
2. 이질적 마이크로서비스·분산 작업은 MIMD 멀티코어·클러스터 구조로 매핑함
3. GPU 같은 하이브리드 구조는 SIMT로 별도 명명해 Flynn 4분류의 단순 적용 오류를 방지함

**결론 (2줄):**
- 기술사 판단: 데이터 병렬성이 높은 작업은 SIMD, 태스크 병렬성이 높은 작업은 MIMD를 기본 축으로 선택함
- 향후 방향: SIMT, 이기종 가속기 결합 구조가 늘며 Flynn 4분류를 확장 해석하는 방향으로 발전함
