# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: 여러 개의 물리적 CPU 소켓이 하나의 메인보드에 실장되어 시스템 메모리와 I/O를 공유하며, 단일 운영체제 이미지로 제어되는 대칭형 다중 처리 아키텍처
- **왜 필요한가**: CPU 코어 수십 개가 들어간 칩 하나만으로는 대규모 데이터베이스 연산력을 감당할 수 없다. 칩(소켓) 2개, 4개를 한 보드에 박아서 하나의 거대한 슈퍼 컴퓨터처럼 쓰고 싶다.
- **핵심 직관**: 공장에 똑같은 권한을 가진 공장장 4명(CPU)을 두고, 하나의 창고(공유 메모리)와 하나의 작업반장(단일 OS) 밑에서 협동하게 만드는 것.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| SMP (Symmetric Multiprocessing) | 모든 CPU가 동등한 권한으로 단일 메모리에 접근하는 대칭형 처리 | 평등한 권한의 동업자들 |
| Multi-Socket | 물리적 CPU 칩이 꽂히는 슬롯(소켓)이 보드에 2개 이상 존재하는 서버 | 쌍발/4발 엔진 항공기 (2-way, 4-way) |
| NUMA (Non-Uniform Memory Access) | 소켓마다 각자 메모리를 쥐고 있으면서도 하나처럼 공유하는 최신 SMP 구조 | 자기 앞 접시와 옆 사람 접시가 다 있는 식탁 |

## 깊이 이해
- **배경·문제의식**: 시스템 성능을 키우는 방법엔 두 가지가 있음. 컴퓨터를 여러 대 사서 네트워크로 묶는 것(Scale-out, 클러스터), 아니면 한 컴퓨터에 엄청나게 좋은 CPU를 여러 개 박는 것(Scale-up, 멀티소켓). 거대 RDBMS 같은 놈들은 데이터를 쪼개기 어려워 한 대의 거대한 컴퓨터(SMP)가 필요함.
- **작동 원리**: 2-way(CPU 2개) 서버에서 윈도우나 리눅스를 깔면, OS는 "아, 내 밑에 CPU가 2개구나"라고 알고(단일 OS), 프로세스를 1번 CPU나 2번 CPU에 자유롭게 할당함. 두 CPU는 서로 고속 버스(Intel UPI, AMD xGMI)로 연결되어 남의 메모리 데이터를 서로 훔쳐볼(Snooping) 수 있음.
- **비유**: 회의실에 CEO 2명이 앉아 있음. 책상(메모리)은 하나고 문(I/O)도 하나임. 누구든 똑같이 책상의 서류를 볼 수 있고(Symmetric), 서류를 고치면 즉각 반대편 CEO도 알게 됨(캐시 일관성).
- **구체 예시**: 흔히 전산실에서 보는 "2U 2소켓 서버"가 전형적인 SMP 구조임. 인텔 제온이나 AMD 에픽 CPU 2개를 끼워서 코어 128개짜리 몬스터를 만듦.
- **흔한 오해·주의점**: 멀티소켓 = NUMA 구조임. 예전에는 진짜 중앙 메모리를 하나 뒀지만(UMA), 지금은 각 CPU에 메모리를 반반씩 달아주고 서로 연결함. 따라서 내 CPU 쪽에 달린 메모리를 읽을 땐 빠르고, 남의 CPU에 달린 걸 읽을 땐 느림(Non-Uniform).

## 연결 개념
- NUMA (Non-Uniform Memory Access)
- 캐시 일관성 프로토콜 (MESI, MOESI)
- 버스 스누핑 / 디렉터리 기반 일관성

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 멀티소켓 SMP는 다수의 물리적 CPU를 단일 메인보드에 결합하고 단일 OS 이미지로 제어하여 공유 메모리 기반의 Scale-up 성능을 제공하는 아키텍처다.
> 2. **가치**: 대규모 RDBMS나 인메모리 DB(SAP HANA 등)처럼 노드 분할(Sharding)이 어려운 거대 워크로드에 무결성 높은 단일 연산 자원을 제공한다.
> 3. **판단 포인트**: 소켓 간 고속 인터커넥트(UPI)를 통한 캐시 일관성(Cache Coherence) 유지와 NUMA 아키텍처로 인한 메모리 접근 비대칭성 최적화가 필수적이다.

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 시스템 스케일업 아키텍처 이해 | 대칭성(Symmetric), 단일 OS 이미지, 공유 메모리 | 단순히 코어 수가 많은 '멀티코어'와 소켓 구분을 못 함 |
| 멀티소켓의 물리적 병목 포인트 파악 | 인터커넥트 대역폭 한계, NUMA 트래픽, 캐시 스누핑 | 분산 클러스터(MPP) 방식의 특징을 SMP에 혼용 서술 |

> 요약: 서버 내부에 CPU를 2개 이상 장착했을 때 겪는 통신 지연 원인과 단일 운영체제 제어의 장단점을 명확히 묻는 문제다.

---

## Ⅰ. 개요 및 필요성

- 개요: 2개 이상의 물리적 CPU 소켓이 시스템 버스와 메모리를 공유하며 단일 운영체제 이미지로 제어되는 대칭형 다중 프로세서 아키텍처임
- 배경: 단일 칩(싱글 소켓) 멀티코어만으로는 엔터프라이즈 데이터베이스 및 대규모 가상화 집적도(Consolidation)를 감당하기 부족함
- 필요성: 노드 간 네트워크 통신 지연을 감내하기 힘든 강결합성 워크로드(Tightly Coupled Workload)에 고성능 단일 논리 서버(Scale-up) 제공 필요

---

## Ⅱ. 구조 및 구성요소

```text
[ CPU Socket 0 ] <====== ( 고속 인터커넥트: UPI ) ======> [ CPU Socket 1 ]
      |                                                        |
[ Local Memory ]          단일 OS 통합 스케줄링             [ Local Memory ]
```

| 구성요소 | 역할 | 특이사항 |
|:---|:---|:---|
| CPU 소켓 (Processor) | 물리적 독립 칩 단위, 서로 동등한 인터럽트 및 메모리 접근 권한 부여 | 통상 2-way, 4-way, 8-way로 실장 |
| 고속 인터커넥트 | 소켓 간 메모리 및 캐시 스누핑 트래픽 전송 (Intel UPI, AMD xGMI) | 대역폭 병목 및 NUMA 지연의 핵심 |
| 단일 OS 이미지 | 하나의 커널이 전체 소켓의 코어와 메모리를 파악하여 통합 스케줄링 | 운영 관리 포인트 단일화 |

> 요약: 모든 소켓은 권한이 평등(Symmetric)하며 하나의 OS로 제어되지만, 물리적 칩의 분리로 인해 칩 간 통신 고속도로(UPI)가 필수적이다.

---

## Ⅲ. 동작원리 및 흐름도

```text
스레드 생성 -> OS 통합 스케줄러 할당 -> 로컬/원격 메모리 I/O -> 캐시 일관성 프로토콜 작동
```

- 1단계 [단일 풀 인지]: OS 부팅 시 전체 소켓의 코어 수와 메모리 뱅크를 하나의 거대한 자원 풀(NUMA 노드 집합)로 스캔 및 인식
- 2단계 [스레드 분배]: 애플리케이션 프로세스 생성 시 OS 스케줄러가 부하 분산(Load Balancing)을 위해 유휴 소켓/코어로 스레드 할당
- 3단계 [메모리 접근]: 스레드가 자신의 소켓에 직결된 로컬 메모리를 읽거나(고속), 인터커넥트를 건너 원격 메모리를 읽음(저속, NUMA)
- 4단계 [일관성 유지]: 한 소켓이 메모리를 수정하면 인터커넥트를 통해 다른 소켓의 L3 캐시를 무효화(Snoop)하여 정합성 보장

> 요약: 프로그래머 입장에서는 거대한 하나의 컴퓨터처럼 보이지만, 하드웨어 단에서는 인터커넥트를 통한 치열한 동기화 트래픽이 오간다.

---

## Ⅳ. 특징
- 소프트웨어 투명성: 애플리케이션 코드를 분산 아키텍처용(MPI 등)으로 재작성할 필요 없이 레거시 코드를 그대로 올려 성능 스케일업 가능
- NUMA 아키텍처 필연성: 소켓이 각자의 메모리 컨트롤러를 가지므로, 원격 메모리 접근 시 지연(Latency)이 상승하는 비대칭성 동반
- 스누핑 한계: 소켓 수가 8-way 이상 늘어나면 캐시 일관성을 맞추기 위한 브로드캐스트 트래픽이 연산 대역폭을 잠식하여 확장 한계 봉착

---

## Ⅴ. 심화 비교 및 적용 판단

| 비교 축 | 단일 소켓 (Single-Socket) | 멀티소켓 SMP (Scale-up) | MPP 클러스터 (Scale-out) |
|:---|:---|:---|:---|
| 메모리 아키텍처 | UMA (균일 접근) | NUMA (비균일 공유 메모리) | Shared-Nothing (독립 메모리) |
| 노드 간 연결 | 칩 내부 링/메시 버스 | 보드 위 고속 인터커넥트 (UPI) | 외부 네트워크 스위치 (이더넷, IB) |
| 적합 워크로드 | 웹/앱 컨테이너 노드 | 대규모 단일 RDBMS, 인메모리 DB | 분산 데이터 처리 (Hadoop, AI) |

> 요약: SMP는 코딩이 쉽고 관리가 편한 단일 컴퓨터의 한계를 2배~8배로 강제로 밀어 올린 '헤비급' 단독 장비다.

- NUMA Ping-Pong 리스크: 스레드가 소켓 0과 1을 번갈아 이동하며 원격 메모리 접근 지연을 반복 유발 → OS 레벨 CPU Pinning(친화도 고정) 및 NUMA-Aware 애플리케이션 설계로 억제
- 라이선스 비용 폭증 리스크: 오라클, MS SQL 등 상용 SW는 물리 코어/소켓 단위로 과금되어 비용 인플레이션 → 가상화(VM Pinning)를 통한 라이선스 통제 영역 격리

- 메모리 로컬리티(Locality): 전체 메모리 접근 중 원격 노드 접근 비율 — `numastat` 도구 모니터링
- 인터커넥트 활용률: UPI 버스의 병목 여부 트래픽 분석(%) — 하드웨어 PMU 측정

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. RDBMS 서버 스케일업: 대용량 트랜잭션이 발생하는 금융권 메인 원장 DB에 4-way x86 SMP 서버를 도입하여 Sharding 없이 논리적 정합성과 단일 처리량 동시 확보
2. NUMA 튜닝 정책 강제: 가상화 하이퍼바이저 설정 시 vCPU와 할당 메모리가 물리적으로 동일한 NUMA 노드에 배치되도록 강제 설정(NUMA Affinity)하여 지연 최소화
3. 서버 콘솔리데이션(Consolidation): 방치된 구형 1소켓 서버 수십 대를 2소켓 고성능 랙 서버 2~3대로 가상화 마이그레이션하여 상면 및 소프트웨어 라이선스 비용 최적화

**결론 (2줄):**
- 기술사 판단: 멀티소켓 SMP는 분산 불가능한 코어 워크로드의 구원투수이나, NUMA 지연과 캐시 일관성 트래픽 한계로 인해 통상 4소켓 이상 확장은 비용 대비 효율이 떨어진다.
- 향후 방향: 최근 단일 CPU 칩 안에 코어가 128개씩 들어가는 칩렛(Chiplet) 아키텍처가 발전하면서, 비싼 멀티소켓 보드 대신 고밀도 1소켓 서버로 회귀하는 현상도 뚜렷하다.
