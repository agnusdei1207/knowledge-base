## 미리 알고가기

- SMP는 여러 CPU가 하나의 OS와 공유 메모리 공간을 사용하는 구조임
- 멀티소켓 서버는 소켓별 로컬 메모리와 소켓 간 링크를 가짐
- NUMA는 소켓마다 메모리 접근 지연이 달라지는 특성임

## Ⅰ. 개요

- **정의/개념**: 멀티소켓 서버와 SMP는 둘 이상의 CPU 소켓이 하나의 시스템 이미지와 공유 메모리 공간을 구성해 코어 수와 메모리 용량과 I/O 자원을 확장하는 서버 구조임
- **배경/필요성**: 대형 데이터베이스와 가상화 호스트와 메모리 집약 워크로드는 단일 소켓의 코어 수와 메모리 채널 한계를 넘기 쉬우므로, 한 노드 안에서 수직 확장할 구조가 필요함

## Ⅱ. 특징

- 여러 CPU 소켓의 코어·메모리 채널·I/O 레인을 하나의 OS 이미지에 결합함
- 소켓별 로컬 메모리와 원격 메모리 지연 차이가 성능에 직접 반영됨
- 캐시 일관성과 소켓 간 트래픽이 공유 데이터 많은 워크로드에서 병목이 됨
- scale-up 장점이 크지만 라이선스와 전력과 냉각 비용도 함께 증가함

## Ⅲ. 종류 및 비교

| 판단 기준 | 단일소켓 서버 | 멀티소켓 SMP |
|:---|:---|:---|
| 자원 규모 | 단일 CPU 범위 안에서만 확장 가능함 | 여러 소켓 자원을 한 노드에 결합할 수 있음 |
| 메모리 지연 | 비교적 균일한 메모리 접근을 기대할 수 있음 | NUMA 때문에 로컬과 원격 접근 차이가 생김 |
| 튜닝 난도 | 상대적으로 낮음 | NUMA 배치와 일관성 트래픽 관리가 필요함 |
| 대표 업무 | 단일 소켓 자원 안에서 처리되는 일반 서비스 | 단일 소켓의 코어·메모리 용량을 넘는 DB·가상화·메모리 집약 처리 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| CPU 소켓 | 코어와 캐시와 메모리 컨트롤러를 포함해 하나의 NUMA 노드 기반이 됨 |
| 소켓 간 링크 | 소켓 간 데이터 이동과 캐시 일관성을 처리해 원격 접근 비용을 결정함 |
| 로컬 메모리 | 해당 소켓의 메모리 컨트롤러에 직접 연결돼 소켓 간 링크를 거치지 않음 |
| OS 스케줄러 | 스레드와 메모리와 장치를 적절한 NUMA 노드에 배치해 성능 차이를 조정함 |

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 토폴로지 인식   | --> | NUMA 배치      | --> | 병렬 실행      | --> | 원격 접근 조정 |
+-------------+     +-------------+     +-------------+     +-------------+
```

## Ⅴ. 원리 및 절차 흐름도

1. **토폴로지 인식**: BIOS와 OS가 소켓과 메모리와 링크 구조를 파악함
2. **NUMA 배치**: 스레드와 메모리와 장치를 같은 소켓 주변에 우선 배치함
3. **병렬 실행**: 여러 소켓 코어가 공유 주소 공간에서 작업을 수행함
4. **원격 접근 조정**: 원격 메모리 비중과 일관성 트래픽을 관찰하며 튜닝함

## Ⅵ. 실무 적용 및 유의점

1. 대형 DB와 가상화 호스트는 여러 소켓의 코어와 메모리를 사용하되, 스레드와 메모리가 다른 소켓에 놓이면 원격 접근 비용이 커지므로 NUMA 인지 스케줄링과 메모리 바인딩을 적용하고 원격 메모리 접근 비율과 p99 지연시간과 CPU 대기 시간으로 확인함
2. 공유 데이터와 락 경합이 많은 워크로드는 소켓 간 일관성 트래픽이 병목이 되기 쉬우므로 소켓별 데이터 구조와 락 분할을 적용하고 소켓 간 대역폭과 락 대기 시간과 트랜잭션당 비용으로 확인함

## Ⅶ. 결론

멀티소켓 SMP는 여러 소켓의 자원을 한 노드에 결합하므로, 확장된 자원량과 NUMA·캐시 일관성 비용을 함께 평가해야 함.
