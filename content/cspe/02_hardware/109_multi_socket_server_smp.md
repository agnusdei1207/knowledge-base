## 미리 알고가기

- SMP는 여러 CPU가 하나의 OS와 공유 메모리 공간을 사용하는 구조임
- 멀티소켓 서버는 소켓별 로컬 메모리와 소켓 간 링크를 가짐
- NUMA 노드(Node)는 CPU 소켓과 로컬 메모리로 구성되며 다른 노드의 메모리는 소켓 간 링크로 접근함
- 소켓 간 링크는 서로 다른 CPU 소켓의 코어가 상대 소켓의 메모리·캐시에 접근하도록 잇는 전용 링크임

## 작성 근거(검토용)

- 멀티소켓 SMP는 소켓·로컬 메모리·소켓 간 링크·캐시 일관성·NUMA 배치를 핵심 축으로 설명함
- 비교표는 단일·멀티소켓의 자원 규모·메모리 지연, 공유 데이터 비용, 적용 업무를 대비함
- 실무 판단은 원격 메모리 접근률·p99 질의 지연과 소켓 간 대역폭·락 대기 시간으로 검증함

## Ⅰ. 개요

- **정의/개념**: 멀티소켓 서버와 SMP는 둘 이상의 CPU 소켓이 하나의 시스템 이미지와 공유 메모리 공간을 구성해 코어 수와 메모리 용량과 I/O 자원을 확장하는 서버 구조임
- **배경/필요성**: 단일 소켓의 코어·메모리 채널 한도를 넘는 워크로드를 한 서버에서 처리하기 위해 멀티소켓 수직 확장 구조가 필요함

## Ⅱ. 특징

- 여러 CPU 소켓의 코어·메모리 채널·I/O 레인을 하나의 OS 이미지에 결합함
- 소켓별 로컬 메모리와 원격 메모리 지연 차이가 성능에 직접 반영됨
- 캐시 일관성과 소켓 간 트래픽이 공유 데이터 많은 워크로드에서 병목이 됨
- 소켓 수에 따라 코어·메모리 채널과 함께 소켓 라이선스·전력·냉각 비용이 증가함

## Ⅲ. 종류 및 비교

| 판단 기준 | 단일소켓 서버 | 멀티소켓 SMP |
|:---|:---|:---|
| 자원 규모·메모리 지연 | 단일 CPU 범위 내 자원, 한 소켓의 메모리 컨트롤러 경로만 사용함 | 여러 소켓 자원을 결합하되 NUMA로 로컬·원격 접근 지연 차이가 생김 |
| 공유 데이터 비용 | 한 소켓의 캐시 계층에서 일관성을 유지함 | 소켓 간 링크로 캐시 일관성 트래픽을 전달함 |
| 대표 업무 | 단일 소켓 자원 안에서 처리되는 서비스 | 단일 소켓의 코어·메모리 용량을 넘는 DB·가상화·메모리 집약 처리 |

> 요약: 멀티소켓은 코어·메모리·I/O를 확장하지만 원격 메모리와 캐시 일관성 트래픽을 추가함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| CPU 소켓 | 코어와 캐시와 메모리 컨트롤러를 포함해 하나의 NUMA 노드 기반이 됨 |
| 소켓 간 링크 | 소켓 간 데이터 이동과 캐시 일관성을 처리해 원격 접근 비용을 결정함 |
| 로컬 메모리 | 해당 소켓의 메모리 컨트롤러에 직접 연결돼 소켓 간 링크를 거치지 않음 |
| OS 스케줄러 | 스레드와 메모리와 장치를 적절한 NUMA 노드에 배치해 성능 차이를 조정함 |

> 요약: 각 CPU 소켓은 로컬 메모리와 NUMA 노드를 구성하고 소켓 간 링크가 원격 메모리·캐시 일관성 트래픽을 전달함.

## Ⅴ. 원리 및 절차 흐름도

1. **토폴로지 인식**: BIOS와 OS가 소켓과 메모리와 링크 구조를 파악함
2. **NUMA 배치**: 스레드와 메모리와 장치를 같은 소켓 주변에 우선 배치함
3. **병렬 실행**: 여러 소켓 코어가 공유 주소 공간에서 작업을 수행함
4. **원격 접근 조정**: 원격 메모리 비중과 일관성 트래픽을 관찰하며 튜닝함

> 요약: OS가 소켓 토폴로지를 인식해 스레드·메모리·I/O를 배치하고 원격 접근과 일관성 트래픽을 조정함.

## Ⅵ. 실무 사례

1. 대형 데이터베이스는 NUMA 인지 스케줄링과 메모리 바인딩을 적용하고 원격 메모리 접근률·p99 질의 지연을 확인함
2. 공유 메모리 분석 엔진은 소켓별 데이터 구조와 락 분할을 적용하고 소켓 간 대역폭·락 대기 시간을 확인함

## Ⅶ. 결론

- 멀티소켓 SMP는 추가 코어·메모리 채널과 원격 메모리·캐시 일관성 비용을 함께 측정해 확장 효과를 판단해야 함
