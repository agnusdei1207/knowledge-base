## 미리 알고가기

- SMP는 여러 CPU가 하나의 OS와 공유 메모리 공간을 사용하는 구조임
- 멀티소켓 서버는 소켓별 로컬 메모리와 소켓 간 링크를 가짐
- NUMA는 소켓마다 메모리 접근 지연이 달라지는 특성임

## Ⅰ. 개요

- **정의/개념**: 멀티소켓 서버와 SMP는 둘 이상의 CPU 소켓이 하나의 시스템 이미지와 공유 메모리 공간을 구성해 코어 수와 메모리 용량과 I/O 자원을 확장하는 서버 구조임
- **배경/필요성**: 대형 데이터베이스와 가상화 호스트와 메모리 집약 워크로드는 단일 소켓의 코어 수와 메모리 채널 한계를 넘기 쉬우므로, 수직 확장을 위해 멀티소켓 구성이 필요함

## Ⅱ. 특징

- 코어 수와 메모리 용량과 I/O 레인을 한 노드 안에서 크게 확장할 수 있음
- 소켓별 로컬 메모리와 원격 메모리 지연 차이가 성능에 직접 반영됨
- 캐시 일관성과 inter-socket 트래픽이 공유 데이터 많은 워크로드에서 병목이 됨
- scale-up 장점이 크지만 라이선스와 전력과 냉각 비용도 함께 증가함

## Ⅲ. 종류 및 비교

| 판단 기준 | 단일소켓 서버 | 멀티소켓 SMP |
|:---|:---|:---|
| 자원 규모 | 단일 CPU 범위에 제한 | 여러 소켓 자원 결합 가능 |
| 메모리 지연 | 비교적 균일 | NUMA로 로컬과 원격 차이 존재 |
| 튜닝 난도 | 낮음 | NUMA 배치와 일관성 트래픽 관리 필요 |
| 적합 업무 | 일반 서비스 | 대형 DB, 가상화, 메모리 집약 처리 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| CPU Socket | 코어와 캐시와 메모리 컨트롤러를 포함해 하나의 NUMA 노드 기반이 됨 |
| Inter-socket Link | 소켓 간 데이터 이동과 캐시 일관성을 처리해 원격 접근 비용을 결정함 |
| Local Memory | 각 소켓에 직접 연결된 메모리로 가장 낮은 접근 지연을 제공함 |
| OS Scheduler | 스레드와 메모리와 장치를 적절한 NUMA 노드에 배치해 성능 차이를 조정함 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 토폴로지 인식   | --> | NUMA 배치      | --> | 병렬 실행      | --> | 원격 접근 조정 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **토폴로지 인식**: BIOS와 OS가 소켓과 메모리와 링크 구조를 파악함
2. **NUMA 배치**: 스레드와 메모리와 장치를 같은 소켓 주변에 우선 배치함
3. **병렬 실행**: 여러 소켓 코어가 공유 주소 공간에서 작업을 수행함
4. **원격 접근 조정**: 원격 메모리 비중과 일관성 트래픽을 관찰하며 튜닝함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 스레드와 메모리가 다른 소켓에 배치되면 원격 메모리 접근으로 지연이 크게 증가할 수 있음
   - 해결방안: NUMA-aware scheduling과 memory binding을 적용하고 remote memory access ratio와 p99 latency로 검증함
2. 문제: 공유 데이터와 lock 경합이 많으면 inter-socket coherence traffic이 급증해 처리량이 떨어질 수 있음
   - 해결방안: per-socket 데이터 구조와 lock sharding을 적용하고 inter-socket bandwidth와 lock wait time으로 검증함
3. 문제: 소켓 수가 늘수록 라이선스와 전력과 냉각 비용이 비선형으로 증가할 수 있음
   - 해결방안: scale-up과 scale-out TCO를 비교하고 cost per transaction과 power draw로 검증함

## Ⅶ. 적용 사례

- 대형 DB 서버에서는 프로세스와 버퍼 풀을 NUMA 노드별로 배치하고, remote memory access ratio와 p99 latency로 결과를 확인함
- 가상화 호스트에서는 VM과 PCIe 장치를 같은 소켓에 묶어 배치하고, CPU ready time과 inter-socket bandwidth로 결과를 확인함
- 상용 플랫폼 용량 계획에서는 소켓 수 증가 전후를 비교하고, cost per transaction과 power draw로 결과를 확인함

## Ⅷ. 결론

멀티소켓 SMP는 코어 확장 기술이 아니라 NUMA와 일관성 비용을 감당할 수 있는 워크로드에서만 유효한 scale-up 구조임.
