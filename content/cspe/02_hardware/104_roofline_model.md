## Ⅰ. 개요
- 연산 성능과 메모리 대역폭 사이의 상관관계를 시각화하여 성능 병목 지점을 찾는 모델.
- 산술 강도(Arithmetic Intensity)를 기준으로 프로그램이 어느 성능 한계에 걸리는지 분석함.
| 구분 | 내용 | 비고 |
|---|---|---|
| 정의 | 컴퓨터 성능의 한계를 연산 능력과 대역폭으로 표현한 분석 모델 | 성능 시각화 |
| 의도 | 하드웨어 자원 최적화 및 소프트웨어 병목 구간 판별 능력 측정 | 최적 지점 도달 |

## Ⅱ. 구성요소
Performance (GFLOPS)
^   +----------------- (Peak Floating Point Performance)
|  /
| / (Memory Bandwidth Limited)
|/
+----------------------> Operational Intensity (FLOPs/Byte)
| 구성요소 | 설명 | 비유 |
|---|---|---|
| 산술 강도 | 메모리 1바이트 이동당 수행되는 부동 소수점 연산 수 | 작업 밀도 |
| 연산 루프 | 프로세서가 제공할 수 있는 최대 이론 성능 한계선 | 지붕 |
| 메모리 루프 | 메모리 대역폭에 의해 제한되는 성능 한계선 (경사면) | 오르막길 |
> 요약: 산술 강도, 연산 한계, 대역폭 한계로 구성된 성능 지도임.

## Ⅲ. 절차
(1) Profile -> (2) Plotting -> (3) Identify -> (4) Optimization
1. Profile: 프로그램의 전체 연산량(FLOPs)과 데이터 이동량(Bytes)을 측정함.
2. Plotting: 루프라인 그래프 위에 해당 프로그램의 위치(산술 강도 대비 성능)를 점찍음.
3. Identify: 점이 경사면에 있으면 'Memory Bound', 수평선에 있으면 'Compute Bound'로 판별.
4. Optimization: 병목에 맞춰 알고리즘 개선(캐시 최적화 또는 연산 병렬화) 수행.
> 요약: 프로파일링, 그래프 타점, 병목 식별, 최적화 적용 순임.

## Ⅳ. 문제점
- 단순화 오류: 캐시 계층 구조나 인스트럭션 파이프라인의 복잡성을 완벽히 반영 못함.
- 측정 난이도: 실제 HW에서의 정확한 데이터 이동량을 측정하기 위해 정밀한 도구 필요.

## Ⅴ. 개선방안
- 계층적 모델: L1, L2, L3 캐시 대역폭별로 여러 개의 루프라인을 그려 분석 고도화.
- 자동화 툴: Intel Advisor 등 자동 프로파일링 툴을 활용하여 분석 정밀도 제고.

## Ⅵ. 전망
- AI 가속기 최적화: NPU 성능 분석 시 산술 강도 최적화를 통한 전력 효율 극대화 지표로 활용.
- 맞춤형 HW 설계: 특정 도메인 알고리즘에 최적화된 메모리-연산 밸런스 설계 가이드라인 제공.
