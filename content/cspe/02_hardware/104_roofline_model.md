## Ⅰ. 개요
- **정의**: 연산 강도 대비 달성 가능 성능 상한을 시각화하는 성능 분석 모델
- **배경/필요성**: 프로세서의 연산 처리량과 메모리 대역폭 중 어느 쪽이 병목인지 정량적으로 판별할 수단이 필요함
- **비유**: 도로(대역폭)와 공장(연산)의 관계에서, 자재 운송이 느리면 공장이 쉬고 공장이 느리면 자재가 쌓이는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 메모리·연산 병목 분석 능력 확인 | 연산 강도(OI) 기준 경계점 도출 | 단순 그래프 설명이 아닌 병목 판별 논리 서술 필요 |

> 요약: 연산 강도를 축으로 메모리 병목과 연산 병목 영역을 구분하는 성능 상한 모델임

## Ⅱ. 구성요소
```text
  Performance (FLOPS)
       |        _______________  <-- Peak Compute (연산 상한)
       |       /
       |      /
       |     /  <-- Memory Bandwidth Slope
       |    /
       |   /
       +--/------------------------> Operational Intensity (FLOP/Byte)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 연산 상한 (Peak Compute) | 프로세서가 이론적으로 달성 가능한 최대 FLOPS 값 | 공장의 최대 생산 능력 |
| 메모리 대역폭 경사 | `대역폭 x 연산강도`로 결정되는 메모리 제한 영역의 기울기 | 자재 운송 속도에 비례하는 생산량 |
| 연산 강도 (OI) | 바이트당 부동소수점 연산 횟수(FLOP/Byte)로 워크로드 특성을 나타냄 | 자재 1톤당 만드는 제품 수 |
| 경계점 (Ridge Point) | 메모리 병목에서 연산 병목으로 전환되는 OI 임계값 | 자재 공급과 생산 속도가 균형을 이루는 지점 |

> 요약: 연산 상한·대역폭 경사·경계점 세 요소로 워크로드의 병목 유형을 판별함

## Ⅲ. 절차
```text
HW 스펙 수집 --> OI 계산 --> 루프라인 배치 --> 병목 판별/최적화
```
- 1단계: 대상 프로세서의 Peak FLOPS와 메모리 대역폭(GB/s) 수집
- 2단계: 커널별 총 연산량과 총 메모리 접근량으로 연산 강도(OI) 산출
- 3단계: 루프라인 그래프 위에 각 커널을 OI-성능 좌표로 배치
- 4단계: 경계점 대비 위치로 메모리 병목 또는 연산 병목을 판별하고 최적화 방향 결정

> 요약: HW 스펙과 커널 프로파일링을 결합하여 병목 유형별 최적화 방향을 도출함

## Ⅳ. 문제점
- 캐시 계층 미반영: 단일 대역폭만 가정하여 L1/L2 캐시 히트 시 실제 성능과 괴리가 발생함
- 다중 병목 미표현: 연산·메모리 외 네트워크·동기화 등 복합 병목을 표현하지 못함
- 정적 분석 한계: 분기 예측·파이프라인 스톨 등 런타임 동적 요인을 반영하지 못함

> 요약: 캐시 계층·복합 병목·동적 요인 미반영으로 실측과 괴리가 발생할 수 있음

## Ⅴ. 개선방안
1. 단기: 캐시 인지 루프라인(Cache-Aware Roofline) 적용으로 계층별 대역폭 반영
2. 중기: 네트워크·동기화 축을 추가한 다차원 루프라인 모델 확장
3. 장기: 런타임 프로파일러 연동으로 동적 병목을 실시간 시각화하는 도구 구축

> 요약: 캐시 인지·다차원 확장·런타임 연동 순으로 모델 정밀도를 높여 나감

## Ⅵ. 전망
- 발전 방향: AI 가속기(NPU·TPU)에 특화된 루프라인 변형 모델 확산 예상
- 기술사적 판단: 이기종 컴퓨팅 환경에서 워크로드 배치 최적화의 기본 도구로 자리잡음
- 기술사 제언: HW 선정·커널 최적화 시 루프라인 분석을 표준 절차로 포함할 필요
