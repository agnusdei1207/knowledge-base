## Ⅰ. 개요
- **정의**: 연산 강도 대비 달성 가능 성능 상한을 시각화하는 성능 분석 모델임
- **배경/필요성**: 프로세서 성능이 연산 또는 메모리 중 어디에 병목되는지 정량 판별이 필요함
- **비유**: 수도관(대역폭)과 물탱크(연산력) 중 좁은 쪽이 수돗물 유량을 결정하는 것과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 성능 병목 분석 능력 확인 | 연산 강도(OI) 기준 경계점 설명 | peak FLOPS와 대역폭 두 축 모두 명시 필요 |

> 요약: 연산 강도를 기준으로 compute-bound와 memory-bound를 구분하는 성능 상한 모델임

## Ⅱ. 구성요소
```text
Performance(GFLOPS)
  |         ____________________  <-- Peak Compute
  |        /
  |       / Ridge Point
  |      /
  |     / <-- Memory Bandwidth Slope
  |    /
  +--/-------------------------------> Operational Intensity (FLOP/Byte)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Peak Compute | 프로세서가 달성 가능한 최대 연산 처리량(GFLOPS) | 공장 최대 생산 능력 |
| Memory Bandwidth | 메모리에서 데이터를 공급하는 최대 속도(GB/s) | 원자재 운송 도로 폭 |
| Operational Intensity | 바이트당 수행 연산 수(FLOP/Byte)로 커널 특성 표현 | 원자재 1톤당 생산 제품 수 |
| Ridge Point | compute-bound와 memory-bound의 경계 지점 | 도로와 공장 능력이 균형인 지점 |

> 요약: 연산 상한, 대역폭 기울기, 연산 강도 세 요소로 성능 천장을 결정함

## Ⅲ. 절차
```text
HW 스펙 수집 --> OI 산출 --> 루프라인 도식화 --> 병목 판별
```
- 1단계: 대상 프로세서의 peak FLOPS와 메모리 대역폭을 측정함
- 2단계: 분석 대상 커널의 연산 강도(FLOP/Byte)를 프로파일링으로 산출함
- 3단계: 두 축 로그 스케일 그래프에 성능 상한선(루프라인)을 도식화함
- 4단계: 커널 좌표가 기울기 구간이면 memory-bound, 수평 구간이면 compute-bound로 판별함

> 요약: HW 스펙과 커널 OI를 대조하여 병목 유형을 판별하는 4단계 절차임

## Ⅳ. 문제점
- 캐시 계층 미반영: 단일 대역폭만 가정하여 L1/L2 히트 시 실제 성능과 괴리 발생함
- 다중 병목 미표현: 연산-메모리 외 네트워크, 동기화 등 추가 병목을 표현 불가함
- 정적 분석 한계: 런타임 동적 스케줄링·분기 예측 영향을 반영하지 못함

> 요약: 캐시 계층·다중 병목·동적 거동을 반영하지 못하는 정적 모델의 한계가 있음

## Ⅴ. 개선방안
1. 단기: Cache-Aware Roofline으로 L1/L2/L3 각 계층별 대역폭 상한선을 추가함
2. 중기: 네트워크·동기화 비용을 별도 축으로 확장한 다차원 루프라인 모델 적용함
3. 장기: 프로파일러 연동 자동 계측으로 런타임 OI 변화를 실시간 추적함

> 요약: 캐시 계층 세분화, 다차원 확장, 런타임 자동 계측 순으로 정밀도를 높임

## Ⅵ. 전망
- 발전 방향: AI 가속기(GPU, NPU) 전용 루프라인이 표준 벤치마크로 확산 중임
- 기술사적 판단: HW-SW 최적화 의사결정에 정량 근거를 제공하는 도구로 중요성 증가함
- 기술사 제언: 이기종 컴퓨팅 환경에서 디바이스별 루프라인 비교 분석 역량 확보가 필요함
