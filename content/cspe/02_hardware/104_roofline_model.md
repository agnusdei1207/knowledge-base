## Ⅰ. 개요
- **정의**: 연산 강도 대비 달성 가능 성능 상한을 시각화하는 성능 분석 모델
- **배경/필요성**: 프로세서 성능이 연산·메모리 중 어디에 병목되는지 정량 판별이 필요함
- **비유**: 달리기 선수의 체력(연산)과 산소공급(메모리 대역폭) 중 먼저 한계에 도달하는 쪽이 기록을 결정하는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 성능 병목 분석 능력 확인 | 연산 강도(OI)와 두 영역 경계 | 피크 성능·대역폭 수치 없이 개념만 서술하면 감점 |

> 요약: 연산 강도 기준으로 메모리·연산 병목 영역을 구분하는 성능 상한 모델임

## Ⅱ. 구성요소
```text
Performance(FLOPS)
  |         ___________  <-- Peak Compute
  |        /
  |       / Memory-bound
  |      /    region
  |     /         Compute-bound region
  |    /
  +--/--------------------> OI (FLOP/Byte)
       ^
       Ridge Point
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 피크 연산 성능 | 프로세서가 낼 수 있는 최대 FLOPS | 엔진 최대 출력 |
| 메모리 대역폭 | 초당 전송 가능한 데이터량(GB/s) | 연료 공급 파이프 굵기 |
| 연산 강도(OI) | 바이트당 수행하는 부동소수점 연산 수 | 연료 1L당 주행 거리 |
| 릿지 포인트 | 메모리·연산 병목 경계가 되는 OI 값 | 출력과 연료공급이 균형인 회전수 |

> 요약: 피크 성능, 대역폭, OI, 릿지 포인트가 병목 영역을 결정함

## Ⅲ. 절차
```text
HW 스펙 수집 --> OI 산출 --> 루프라인 그래프 작성 --> 병목 판별/최적화
```
- 1단계: 대상 HW의 피크 FLOPS와 메모리 대역폭을 측정함
- 2단계: 커널별 연산량과 데이터 이동량으로 OI를 산출함
- 3단계: 로그-로그 그래프에 천장선과 커널 위치를 표시함
- 4단계: 릿지 포인트 대비 위치로 메모리/연산 병목을 판별하고 최적화 방향을 결정함

> 요약: HW 스펙 수집 → OI 산출 → 그래프 매핑 → 병목 판별 순서로 진행함

## Ⅳ. 문제점
- 단일 계층 가정: 캐시 계층을 무시하여 실제 메모리 접근 패턴을 반영하지 못함
- 동시 병목 미반영: 연산·메모리가 동시에 병목인 혼합 워크로드 분석이 부정확함
- 비정형 연산 한계: 분기·정수 연산 위주 워크로드에 FLOPS 기반 모델이 부적합함

> 요약: 캐시 계층, 혼합 병목, 비정형 연산에 대한 모델 정확도가 한계임

## Ⅴ. 개선방안
1. 단기: 캐시 인지 루프라인(CARM)으로 L1/L2/L3 계층별 천장선을 추가함
2. 중기: 연산·메모리 동시 병목을 표현하는 다차원 루프라인 확장을 적용함
3. 장기: 정수·분기·통신 병목까지 통합하는 범용 성능 모델로 발전시킴

> 요약: 캐시 계층 반영 → 다차원 확장 → 범용 모델 순으로 개선함

## Ⅵ. 전망
- 발전 방향: AI 가속기(GPU, NPU)의 Tensor 연산 특성을 반영한 변형 모델이 확산 중임
- 기술사적 판단: HW-SW 공동 최적화의 출발점으로 성능 분석 역량의 핵심 도구임
- 기술사 제언: 워크로드별 OI 프로파일링을 자동화하여 설계 초기 단계에서 병목을 예측할 필요가 있음
