## Ⅰ. 개요
- 데이터 저장 방식 및 관리 단위에 따른 3가지 핵심 스토리지 모델
- 용도와 성능 요구사항에 맞는 최적의 데이터 저장 구조 선택

| 구분 | 내용 |
| --- | --- |
| 정의 | 데이터를 블록, 파일, 또는 객체 단위로 관리하는 기술 |
| 필요성 | 비정형 데이터 폭증 및 고성능 연산 데이터 처리 필요 |
| 출제의도 | 각 스토리지의 구조적 차이, 장단점, 활용 사례 비교 |

## Ⅱ. 구성요소
```
[ Block ]         [ File ]         [ Object ]
+-------+      +-----------+     +------------+
| Block |      | Hierarchy |     | Flat Space |
| ID    |      | (Folders) |     | (ID+Meta)  |
+-------+      +-----------+     +------------+
(Low Latency)  (User Friendly)   (Scalability)
```
| 유형 | 설명 | 비유 |
| --- | --- | --- |
| Block | 데이터를 고정 크기 블록으로 쪼개어 저장(SAN) | 주차장 칸 |
| File | 계층적 폴더 구조로 파일 단위 저장(NAS) | 서류 캐비닛 |
| Object | 데이터+메타데이터+ID를 묶어 평면 저장(Cloud) | 창고 보관함 |
> 요약: 블록은 성능, 파일은 편의성, 객체는 확장성에 최적화됨.

## Ⅲ. 절차
```
[데이터 발생] -> [유형 판별] -> [프로토콜 할당] -> [저장/인덱싱]
```
1. 발생: 시스템이나 사용자로부터 저장 요청 데이터 수신함.
2. 판별: 성능 위주(DB), 공유 위주(문서), 대규모(미디어) 등 구분함.
3. 할당: iSCSI/FC(Block), NFS/SMB(File), HTTP/S3(Object) 적용함.
4. 인덱싱: 각 방식의 관리 체계에 따라 메타데이터 기록 및 저장함.
> 요약: 데이터 성격에 맞는 프로토콜을 통해 저장소에 기록함.

## Ⅳ. 문제점
- 블록: 네트워크 경계 너머 확장성 부족 및 관리 복잡성 높음.
- 객체: 데이터 수정(Update) 시 전체를 다시 써야 하므로 지연 발생함.

## Ⅴ. 개선방안
- 통합 스토리지: 블록/파일/객체를 동시에 지원하는 다중 프로토콜 장비 도입함.
- SDS 활용: 하드웨어에 종속되지 않는 소프트웨어 정의 스토리지로 통합함.

## Ⅵ. 전망
- AI 학습용 데이터 레이크 구축을 위한 객체 스토리지 비중 급증함.
- 데이터의 가치를 높이는 지능형 메타데이터 관리 기술이 핵심임.
