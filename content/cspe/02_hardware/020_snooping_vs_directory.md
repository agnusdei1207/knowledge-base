## Ⅰ. 개요
- 정의: 캐시 일관성을 유지하기 위해 정보를 교환하는 두 가지 주요 아키텍처 방식
- 배경: 버스 공유 방식(Snooping)의 확장성 한계를 해결하기 위한 디렉터리 구조 등장
- 출제 의도: 네트워크 구조와 코어 수에 따른 일관성 유지 기법의 적합성 판단

## Ⅱ. 구성요소
- ASCII 구조도
  [Snooping]                     [Directory-based]
  +-------+  Bus (Broadcast)     +-------+    +-----------+
  |Core A | <============>       |Core A |<-->| Directory |
  +-------+                      +-------+    | (Node)    |
  |Core B | <============>       |Core B |<-->|           |
  +-------+                      +-------+    +-----------+

- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| Snoop Control | 버스 트래픽을 감시하여 캐시 상태 갱신 | 공개 방송 청취 |
| Directory Node | 어떤 캐시가 데이터를 가졌는지 중앙 관리 | 도서관 대출대 |
| Presence Bit | 특정 데이터 사본을 가진 코어를 표시하는 비트 | 소지자 명단 |
> 요약: 스누핑은 방송(Broadcast), 디렉터리는 개별 통지(Unicast) 기반임

## Ⅲ. 절차
- ASCII 흐름도 (Directory)
  (Req for Data) -> (Check Directory) -> (Send Invalidate to Sharers)
                                                |
          +---------<------------<--------------+
          v
  (Ack from Sharers) -> (Grant Data to Req) -> (Update Dir)

- 4단계 설명
1. 요청: 코어가 특정 주소에 대한 읽기/쓰기 권한을 중앙 디렉터리에 요청
2. 조회: 디렉터리는 해당 데이터의 현재 소유자 및 공유자 리스트 확인
3. 제어: 쓰기 요청 시 모든 공유자에게 무효화 메시지를 개별적으로 발송
4. 응답: 모든 코어의 완료 보고를 받으면 요청자에게 최종 권한 부여 및 상태 갱신
> 요약: 중앙(또는 분산) 관리자가 중재하여 불필요한 방송 트래픽을 제거함

## Ⅳ. 문제점
- 스누핑 한계: 코어 수가 많아지면 버스 트래픽 급증으로 통신 병목 발생
- 디렉터리 비용: 중앙 관리 정보를 위한 추가적인 메모리 공간 및 제어 로직 복잡성

## Ⅴ. 개선방안
- (단기) 계층적 스누핑: 다이 내부는 스누핑, 다이 간에는 디렉터리 방식 혼용
- (중기) 중복 디렉터리: 접근 속도 향상을 위해 디렉터리를 여러 노드에 분산 배치
- (장기) 예측적 무효화: 접근 패턴을 분석하여 미리 무효화 신호를 보내 지연 시간 단축

## Ⅵ. 전망
- 로드맵: 수백 코어 이상의 Many-core 시스템에서는 디렉터리 기반이 표준으로 정착
- CSF: NoC(Network-on-Chip) 대역폭 활용을 최적화하는 토폴로지 기반 프로토콜 설계
