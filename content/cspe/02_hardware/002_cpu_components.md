# 📖 【암기용】 개념 완전 이해

> 목적: 이 개념을 처음 보는 사람도 완벽히 이해하게 만든다. 시험 답안 양식이 아니라, 이해를 위한 친절한 설명이다.

## 한눈에
- **개요**: 중앙처리장치(CPU)는 컴퓨터의 뇌로서, 프로그램 명령어를 수행하기 위해 연산, 제어, 기억, 전달을 담당하는 핵심 반도체다.
- **왜 필요한가**: 메모리에 적재된 소프트웨어 명령어(0과 1)를 해독하여 하드웨어의 물리적 전기 신호로 변환하고 실제 산술 처리를 수행하기 위함이다.
- **핵심 직관**: 공장(컴퓨터) 안에서 작업반장(CU)이 지시를 내리고, 기술자(ALU)가 물건을 가공하며, 앞 책상(레지스터)에 재료를 올려두고, 수레(버스)로 나른다.

## 핵심 용어 정리

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| **ALU (산술논리연산장치)** | 덧셈, 뺄셈, 비트 시프트, AND/OR 등 실제 데이터 연산을 담당 | "공장의 핵심 기술자" |
| **CU (제어장치)** | 명령어를 해석하고 시스템 각 부품에 제어 신호를 타이밍에 맞춰 발송 | "전체 공정 통제 반장" |
| **레지스터 (Register)** | CPU 내부에 위치한 가장 빠르고 용량이 작은 임시 기억 공간 | "기술자 바로 앞의 작업대" |
| **내부 버스 (Internal Bus)** | CPU 내부 요소 간 데이터와 제어 신호를 나르는 물리적 전선 다발 | "부품 간 컨베이어 벨트" |

## 깊이 이해
- **배경·문제의식**: 연산을 하려면 숫자를 잠시 저장할 공간이 필요하고, 이를 더할 계산기도 필요하며, 이 순서를 맞출 시계와 지시자도 필요하다. 이를 칩 하나에 유기적으로 모아놓지 않으면 데이터가 칩 바깥(메인 메모리)을 오가는 동안 수백 클럭의 지연(Stall)이 발생한다.
- **작동 원리 (명령어 사이클)**: 
  - 외부 메모리에서 명령어를 가져와 내부 레지스터(IR)에 담는다. (Fetch)
  - 제어장치(CU) 내 디코더가 이 명령어가 "더하기"인지 "메모리 읽기"인지 해독하여 활성 신호를 만든다. (Decode)
  - 기술자(ALU)가 레지스터에 놓인 두 숫자를 가져와 회로를 통해 더한다. (Execute)
- **비유**: 요리사(CPU)가 있다. 레시피 북(메모리)에서 조리법을 읽고(CU), 손에 닿는 도마 위(레지스터)에 재료를 꺼낸다. 칼질(ALU)을 직접 하고 다시 도마 위에 결과를 둔다. 부엌 내에서 재료를 나를 때는 카트(내부 버스)를 쓴다.
- **구체 예시**: `ADD R1, R2` (R1 = R1 + R2) 실행 시, CU는 덧셈 신호를 발송한다. 내부 버스는 R1과 R2 레지스터의 값을 ALU의 입력 단자로 나른다. ALU 가산기가 연산한 결과는 다시 내부 버스를 타고 R1 레지스터 위치에 덮어씌워진다.
- **흔한 오해·주의점**: 레지스터는 캐시(L1/L2)와 다르다. 캐시는 메인 메모리의 주소를 그대로 복사해 둔 공간이지만, 레지스터는 명령어(기계어)가 명시적으로 `R1`, `R2`처럼 지목하여 연산 피연산자를 넣는 별개의 전용 공간이다.

## 연결 개념
- 파이프라이닝 (Pipelining) - CPU 동작 단계를 겹쳐 실행
- 슈퍼스칼라 아키텍처 (Superscalar) - 다중 ALU 탑재
- 캐시 메모리 계층 (Memory Hierarchy)

# 📝 【답안용】 시험 답안 템플릿

> 목적: 시험장에서 25분에 그대로 쓰는 답안 양식. 작성방식(추상표현 금지·수치·도식·문제유형 전환)을 엄격히 지킨다.
> 핵심: 이 시험은 정보를 많이 나열하는 시험이 아니라, 문제 신호어에서 출제자 의도를 읽고 핵심 논점을 선별해 쓰는 시험이다.

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 중앙처리장치(CPU)는 연산(ALU), 제어(CU), 기억(Register), 전달(Internal Bus)의 4대 요소로 구성된 마이크로프로세서
> 2. **가치**: 명령어 사이클(Fetch-Decode-Execute)을 고속으로 수행해 소프트웨어의 요구사항을 하드웨어 상태 변화로 변환
> 3. **판단 포인트**: 연산 유닛의 분할·병렬화, 다중 레지스터, 내부 대역폭 확장이 파이프라인의 명령어 수준 병렬성(ILP)을 결정

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 프로세서 기본 동작 흐름과 구조적 요소 파악 | ALU, CU, Register, Internal Bus 간 상호작용 | 기능만 위키식으로 병렬 나열하고 인과 흐름 생략 |
| 폰 노이만 아키텍처 기반의 명령어 실행 과정 이해 | Fetch-Decode-Execute 주기 내의 제어 신호와 데이터 흐름 매핑 | 레지스터와 메모리/캐시의 역할을 혼동 |

> 요약: CPU 4대 구성요소가 흩어진 파편이 아니라 명령어 사이클상에서 어떻게 상호작용하여 처리량(Throughput)을 내는지 기승전결로 제시한다.

## Ⅰ. 개요 및 필요성

- 개요: CPU는 메인 메모리에서 기계어 명령어를 인출 및 해독하여 지정된 산술·논리 연산을 실행하고 상태를 갱신하는 중앙 통제 장치
- 배경: 프로그램 내장 방식(폰 노이만 구조)을 물리적으로 구현하기 위해 데이터와 제어 신호를 동기화 처리할 중앙 집중형 유닛 설계 대두
- 필요성: 시스템 클럭 주기에 맞춰 메모리 계층 및 I/O 기기를 제어하고, 매 클럭당 1개 이상의 연산 처리량(목표 IPC 1.0)을 유지하기 위해 핵심 유닛 집적화 필수

---

## Ⅱ. 구조 및 구성요소

```text
[CPU 내부 구조 상호작용도]
제어 버스 (외부) <-+-> CU (Control Unit)  : 클럭 동기화, 제어 신호 해독 및 발행
데이터 버스 (외부) <-+-> ALU (Arithmetic Logic Unit) : 산술 논리 연산 수행
주소 버스 (외부)   <-+-> Registers (PC, IR, AC 등) : 연산 피연산자 및 상태 임시 기억
                   |
                   +-> Internal Bus : CPU 내부 구성요소 간 데이터 및 통제 신호 이동 경로
```

| 4대 구성요소 | 핵심 역할 | 상세 하위 유닛 |
|:---|:---|:---|
| ALU (연산장치) | 실제 데이터의 연산 가공(덧셈, 비트연산, 시프트) | 가산기(Adder), 보수기(Complemented), 누산기, 시프터 |
| CU (제어장치) | 명령어 해독 및 각 장치 동작 통제용 전기 신호 활성화 | 명령어 해독기(Decoder), 제어 신호 발생기 |
| Register (레지스터) | 사이클 내 즉각 접근(1ns 미만) 가능한 초고속 임시 기억장소 | PC(명령어 주소), IR(명령어), MAR, MBR, 범용 레지스터 |
| Internal Bus (내부 버스) | ALU, CU, 레지스터 상호 간 물리적 전송 버스 계층 | 주소 버스, 데이터 버스, 제어 버스 (단, CPU 내부에 한정) |

> 요약: CU가 통제 신호를 활성화하면 내부 버스를 타고 데이터가 레지스터에서 ALU로 인입되어 물리적 연산이 수행된다.

## Ⅲ. 동작원리 및 흐름도

```text
[명령어 처리 사이클 (Instruction Cycle) 단위 흐름]
PC 확인 -> 메모리 인출 (Fetch) -> 명령어 해독 (Decode) -> 실제 연산 (Execute) -> 상태/데이터 기록 (Write Back)
```

- 1단계 [명령어 인출]: PC(Program Counter)가 가리키는 메모리 주소에서 명령어를 인출해 IR(Instruction Register)에 적재하고 PC 주소 증가
- 2단계 [명령어 해독]: CU 내부의 디코더가 IR의 Op-code를 해석하여 해당 동작 수행에 필요한 ALU 연산 모드와 메모리 통제 신호 발생
- 3단계 [실제 연산]: 내부 버스로 범용 레지스터의 피연산자를 읽어들인 후 ALU 내부 논리 회로를 통해 산술 연산 또는 분기(Branch) 판정 수행
- 4단계 [결과 기록]: ALU 연산 최종 결과값을 타겟 레지스터나 메모리(MBR 경유)에 덮어써 상태 갱신 완료

> 요약: CPU는 매 클럭마다 인출, 해독, 실행, 기록의 물리적 단계를 거치며, 이 순차적 흐름을 공간적으로 겹치는 것이 파이프라이닝의 본질이다.

---

## Ⅳ. 특징 (설계 트레이드오프)
- 초고속 연산 보장: 메인 메모리(수십 ns 지연)를 거치지 않고 내부 레지스터망(1 ns 미만 지연)으로 피연산자를 공급하여 ALU 연산 파이프라인 정지(Stall) 방지
- 제어 타이밍 일원화: 단일 CU가 시스템 클럭 신호에 맞춰 전체 레지스터와 유닛 래치(Latch)를 동기화하므로, 하드웨어 타이밍 충돌 회피 보장
- 대역폭 병목 한계: 단일 내부 버스 폭(32/64비트)의 한계로 인해 1사이클 내 전달 가능한 비트 수가 제한되어 단일 코어의 물리적 연산 처리량 상한 결정

> 요약: 단일 칩 내부 구성으로 초고속 타이밍 동기화가 가능하나, ALU 개수나 내부 버스 물리 대역폭 한계로 1사이클당 확장성에 제약이 있다.

## Ⅴ. 심화 비교 및 적용 판단

| 아키텍처 확장 축 | 기본 CPU 구조 (단일 처리) | 최신 CPU 확장 (슈퍼스칼라/멀티코어) | 도입 판단 기준 |
|:---|:---|:---|:---|
| 연산 (ALU) | 단일 정수 ALU 1개 | 다중 정수 ALU, 부동소수점(FPU), SIMD 유닛 분리 | 행렬 연산 및 벡터 데이터 비율 |
| 제어 (CU) | 단일 명령어 인출/순차 해독 | 다중 명령어 인출, 분기 예측기, 비순차(OoO) 스케줄러 | 파이프라인 예측 실패율(Miss Rate) |
| 기억 (Register) | 기본 레지스터 파일(16~32개) | 레지스터 리네이밍용 물리 레지스터 창(100개 이상) | 명령어 수준 병렬성(ILP) 한계치 |

> 요약: 현대 고성능 CPU는 기본 4대 요소를 버리는 것이 아니라, 병렬 처리를 위해 ALU 종류를 세분화하고 CU의 스케줄링 통제 능력을 고도화한다.

**리스크·대응 (기본은 불릿):**
- [리스크] 구조적 해저드 발생: 다중 명령어가 연산 유닛이나 버스를 동시 경합하여 사이클 유휴 유발 → [대응] 명령어 발행(Issue) 단계에서 스케줄러(Reservation Station) 적용 대기열 분산 (지표: 구조적 스톨 사이클 5% 미만)
- [리스크] ALU 굶주림(Starvation): 메모리 지연으로 ALU가 연산할 데이터를 받지 못함 → [대응] 다단계 분리 캐시 및 하드웨어 메모리 프리패처(Prefetcher) 구동 (지표: ALU 활용률 목표 90%)

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 제어 영역 하드웨어 격리 (ARM TrustZone): CU의 제어 상태를 일반(Normal)과 보안(Secure) 모드로 물리적으로 분리하여, 악성코드가 중요 연산 레지스터망에 접근하는 것을 원천 차단
2. 데이터 연산 유닛 확장 (SIMD/AVX): 단일 연산 한계를 극복하기 위해 ALU 내부에 벡터 처리 유닛 구조를 확장, 한 번의 제어 명령(CU 인출)으로 여러 데이터를 1클럭 내 일괄 가공
3. 성능 프로파일링 지표 수집: 레지스터 사용 빈도와 CU의 캐시/분기 미스율을 하드웨어 카운터(PMU)로 실시간 수집하여, 운영체제(OS)의 스케줄링 배치 최적화에 적용

**결론 (2줄):**
- 기술사 판단: CPU의 성능 향상은 단순히 클럭을 높이는 것에서 벗어나, ALU 자원을 늘리고 그 자원이 놀지 않도록 CU 통제(OoO, 예측)를 최적화하는 아키텍처 재설계로 패러다임이 이동했다.
- 향후 방향: 최근 부하 가중 워크로드(AI 추론) 처리를 위해 CPU 내부에 NPU 특화 블록을 직접 내장하여 전력 소모를 줄이고 이기종 연산을 통제하는 SoC 통합 구조가 주류로 자리잡고 있다.
