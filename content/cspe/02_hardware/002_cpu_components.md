## 미리 알고가기

- ALU: 산술 연산과 논리 연산을 수행하는 실행 장치임
- CU: 명령어를 해석하고 각 장치에 제어 신호를 내보내는 장치임
- 레지스터: CPU 내부에서 operand, 주소, 상태값을 1클록 접근으로 저장하는 저장소임
- 버스: 주소, 데이터, 제어 신호가 이동하는 공통 통로임

## Ⅰ. 개요

- **정의**: CPU 구성은 명령어를 가져와 해석하고 연산 결과를 저장하기 위해 ALU, 제어장치, 레지스터, 내부 버스를 어떻게 배치하는지 설명하는 구조 기준임. 각 요소의 역할과 병목을 기준으로 CPU 성능, 전력, 명령어 처리 가능성을 판단하는 데 쓰임.
- **배경/필요성**: 프로그램 실행은 단순 계산이 아니라 데이터 공급, 제어 흐름, 상태 저장이 함께 맞물리는 절차임. CPU 내부 구성요소를 이해해야 파이프라인, 캐시, 멀티코어, 가속기의 성능 병목을 설명할 수 있음.
- **비유**: CPU는 공장이고 ALU는 가공 설비, 제어장치는 작업반장, 레지스터는 작업대, 버스는 이동 통로임.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| CPU 내부 역할과 명령어 처리 흐름 설명 | ALU, CU, 레지스터, 버스의 상호작용 | 구성요소 명칭만 나열 |

> 요약: CPU는 제어, 연산, 임시 저장, 데이터 이동 요소가 클록 단위로 협력해 명령어를 실행함.

## Ⅱ. 특징/비교

| 판단 기준 | ALU 중심 설계 | 제어장치 중심 설계 | 레지스터/버스 중심 설계 |
|:---|:---|:---|:---|
| 최적화 대상 | 연산 지연, 정수/부동소수점 처리량 | 명령어 해석, 분기, 제어 신호 정확성 | 데이터 공급 지연, 내부 대역폭 |
| 병목 신호 | 실행 유닛 utilization 저하 | 분기 miss, decode stall | register pressure, bus contention |
| 설계 선택 | ALU 복수화, SIMD, 전용 실행기 | hardwired control, microcode, predictor | 레지스터 파일 확장, bypass network |
| 답안 포인트 | 계산 성능을 설명할 때 사용함 | 명령어 흐름을 설명할 때 사용함 | 메모리 벽과 파이프라인 해저드를 설명할 때 사용함 |

> 요약: CPU 성능은 연산기 수보다 제어와 데이터 공급이 균형을 이룰 때 높아짐.

## Ⅲ. 구성요소

```text
+------------------------------------------------+
|                      CPU                       |
|  +-----------+      control       +----------+ |
|  | Control   | -----------------> |   ALU    | |
|  | Unit      |                    +-----+----+ |
|  +-----+-----+                          |      |
|        |                                |      |
|  +-----v-----+      data/address  +-----v----+ |
|  | Register  | <----------------> | Bus/IF   | |
|  | File      |                    +----------+ |
|  +-----------+                                 |
+------------------------------------------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| ALU | 산술·논리 연산을 수행하고 상태 플래그를 갱신함 | 계산 설비 |
| 제어장치 | 명령어를 해석해 ALU, 레지스터, 메모리 접근을 제어함 | 작업 지휘자 |
| 레지스터 | 피연산자, 결과, 주소, 프로그램 상태를 CPU 내부에 보관함 | 작업대 |
| 내부 버스 | 구성요소 사이의 데이터, 주소, 제어 신호를 전달함 | 공장 통로 |

> 요약: CPU 구성요소는 명령어 의미를 제어 신호와 데이터 이동으로 바꾸는 내부 실행 구조임.

## Ⅳ. 절차

```text
+----------+     +----------+     +----------+     +----------+
| Fetch    | --> | Decode   | --> | Execute  | --> | Store    |
+----------+     +----------+     +----------+     +----------+
     |                 |                |                |
     v                 v                v                v
   PC/IR              CU              ALU            Register
```

1. **명령어 인출** - PC가 가리키는 주소에서 명령어를 가져와 IR에 적재함
2. **해석과 제어** - CU가 opcode, addressing mode, operand 위치를 해석해 제어 신호를 생성함
3. **연산과 접근** - ALU가 레지스터 operand를 연산하거나 주소 계산과 메모리 접근을 수행함
4. **결과 저장** - 결과를 레지스터나 메모리에 반영하고 PC와 상태 플래그를 갱신함

> 요약: CPU 실행은 제어 신호가 데이터 경로를 열고 ALU 결과를 상태로 확정하는 과정임.

## Ⅴ. 문제점

- **P1 메모리 벽**: ALU 처리 속도보다 메모리 접근 지연이 커서 실행 유닛이 데이터를 기다리는 시간이 발생함
- **P2 제어 흐름 병목**: 분기와 예외가 많으면 CU와 파이프라인이 다음 명령어 흐름을 확정하지 못함
- **P3 전력·발열 한계**: 레지스터 파일, bypass, 실행 유닛을 키우면 동적 전력과 누설 전력이 증가함

> 요약: CPU 병목은 연산 능력 부족보다 데이터 공급, 제어 예측, 전력 예산에서 자주 발생함.

## Ⅵ. 개선방안

- **P1 대응**: 캐시 계층, prefetch, out-of-order 실행으로 메모리 대기 중 독립 명령을 처리함 (확인: memory stall cycle, IPC)
- **P2 대응**: 분기 예측기, branch target buffer, 예외 처리 경로 검증을 강화함 (확인: branch miss rate, flush 횟수)
- **P3 대응**: clock gating, power gating, DVFS, 실행 유닛 선택적 활성화로 전력 예산을 관리함 (확인: TDP, perf/W)

> 요약: CPU 개선은 연산기 증설보다 병목 지표를 기준으로 제어와 데이터 경로를 함께 조정해야 함.

## Ⅶ. 전망

- **발전 방향**: 범용 CPU는 벡터 유닛, AI 보조 명령, PMU, 보안 실행 기능을 같은 패키지에 통합해 제어·연산·관측 기능을 함께 제공하는 방향으로 확장됨
- **기술사적 판단**: ALU 폭, 레지스터 수, 제어부 복잡도, 캐시 대역폭은 분기 중심·메모리 중심·벡터 중심 workload의 병목 위치에 맞춰 결정해야 함; `IPC`, branch miss, cache miss, register dependency stall, PMU 이벤트를 비교해 구성요소별 병목이 fetch-decode-execute 흐름 중 어디서 발생하는지 확인함
- **기술사 제언**: CPU 구성요소는 명칭 나열보다 명령 처리 단계, 병목 지표, 펌웨어·전력 정책까지 포함한 시스템 관점으로 설명해야 함
