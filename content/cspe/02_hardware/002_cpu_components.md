## 미리 알고가기

- ALU는 연산을, CU는 제어를, 레지스터는 피연산자와 중간 결과 저장을 담당함
- 버스는 CPU 내부와 외부 구성요소를 연결하는 통로임
- CPU 성능은 유닛 개수보다 데이터 공급 지연과 제어 흐름에 좌우됨

## 작성 근거(검토용)

- CPU를 연산·제어·저장·전달 경로로 나누고 각 경로의 대기를 검증 지표와 연결함
- 구성요소별 역할과 대기 원인을 같은 축으로 배열해 실행 유닛 수만으로 성능을 판단하지 않게 함
- 각 구성요소의 대기를 확인할 지표와 대응 구조를 연결함

## Ⅰ. 개요

- **정의/개념**: CPU는 명령어를 인출·해독·실행한 뒤 결과를 기록하는 중앙 처리 장치이며, ALU·CU·레지스터·버스로 명령어 사이클을 수행함
- **배경/필요성**: CPU 처리량을 제한하는 경로를 찾기 위해 연산·제어·저장·전달 경로를 구분하는 구성 체계가 필요함

## Ⅱ. 특징

- ALU는 산술·논리 명령을 실행함
- CU는 명령 해독과 분기 제어로 실행 순서를 결정함
- 레지스터는 피연산자와 중간 결과를 CPU 내부에 저장함
- 버스 대역폭과 제어 충돌은 CPU 전체 처리량을 제한함

## Ⅲ. 종류 및 비교

| 판단 기준 | ALU | CU | 레지스터 | 버스 |
|:---|:---|:---|:---|:---|
| 주요 역할 | 연산 수행 | 제어 신호 생성 | 피연산자·중간 결과 저장 | 데이터 전달 |
| 병목 형태 | 연산 유닛 부족 | 분기·스케줄링 지연 | 저장 공간 부족 | 대역폭 부족 |
| 대표 검증 지표 | 실행 유닛 이용률 | 분기 예측 실패율 | 레지스터 스필 수 | 버스 이용률 |

> 요약: CPU는 연산·제어·저장·전달 경로 중 대기가 발생하는 지점을 구분해 처리량 제한 원인을 찾음.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| ALU | 정수와 논리 연산을 수행하며 실행 유닛 수와 지연 시간이 계산 성능을 좌우함 |
| CU | 명령어를 해독하고 각 유닛에 제어 신호를 보내며 분기와 파이프라인 흐름을 제어함 |
| 레지스터 파일 | 피연산자와 중간 결과를 저장해 메모리 접근 횟수와 스케줄링 대기를 줄임 |
| 내부 버스 | CPU 내부 유닛 간 데이터를 이동시키며 포트 수와 폭이 병렬성을 제한함 |

```text
+---------+     +---------------+     +-------------+
| CU      | --> | 레지스터 파일  | --> | ALU         |
+---------+     +---------------+     +-------------+
     \                |
      \               v
       --> +----------------------+
           | 내부 버스             |
           +----------------------+
```

> 요약: ALU, CU, 레지스터 파일, 내부 버스는 명령어 실행 사이클을 나누어 담당함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 명령어 인출     | --> | 해독 및 제어     | --> | 연산 수행      | --> | 결과 기록      |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **명령어 인출**: 메모리에서 명령어를 읽음
2. **해독 및 제어**: CU가 명령 종류와 자원 사용을 결정함
3. **연산 수행**: ALU가 필요한 산술·논리 연산을 처리함
4. **결과 기록**: 결과를 레지스터나 메모리에 반영함

> 요약: CPU는 명령어 인출, 해독, 연산, 기록을 반복하며 각 단계의 대기가 전체 처리량을 제한함.

## Ⅵ. 실무 사례

1. 서버 CPU는 메모리 공급 대기를 줄이기 위해 캐시 계층과 사전 인출 정책을 조정하고, 캐시 실패율과 메모리 대기 사이클로 검증함
2. 분기 명령 비중이 높은 CPU는 실행 유닛의 유휴 시간을 줄이기 위해 분기 예측기를 조정하고, 분기 예측 실패율과 실행 유닛 이용률로 검증함

## Ⅶ. 결론

- CPU 처리량은 ALU 이용률, 분기 예측 실패, 레지스터 스필, 내부 버스 대기 중 가장 긴 대기를 만드는 경로를 기준으로 개선해야 함
