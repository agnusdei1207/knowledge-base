# 002. CPU 구성 — ALU·CU·레지스터·버스 (CPU Components)

## 미리 알고가기

- **명령어 사이클 (Instruction Cycle)**: CPU가 하나의 명령어를 실행하는 과정(인출, 해독, 실행, 저장)임
- **프로그램 카운터 (PC)**: 다음에 실행할 명령어의 메모리 주소를 가리키는 특수 레지스터임
- **클록 (Clock)**: CPU 내부 구성요소들의 동작 시간을 맞추기 위해 일정 간격으로 발생하는 전기적 신호임

## Ⅰ. 개요

- **정의/개념**: CPU(Central Processing Unit)는 컴퓨터의 두뇌로서 명령어를 해석하고 실행하는 장치이며, 내부적으로 연산(ALU), 제어(CU), 기억(Register), 통신(Bus) 유닛으로 구성됨
- **배경/필요성**: 데이터 처리 속도 향상과 복잡한 제어 흐름 관리를 위해 각 구성요소가 역할별로 최적화되어야 함. CPU 내부 구조를 이해하는 것은 시스템 병목 지점을 파악하고 저전력/고성능 설계를 수행하는 기본 토대가 됨

## Ⅱ. 특징 및 비교

CPU 구성요소는 기능에 따라 실행부, 제어부, 기억부로 나뉘며 각 유닛의 성능이 전체 IPC(Instructions Per Cycle)를 결정함.

| 구성요소 | 주요 역할 | 핵심 판단 기준 | 비유 |
|:---|:---|:---|:---|
| **ALU** (연산 장치) | 산술 연산, 논리 연산 수행 | 정수/부동소수점 처리량, 연산 속도 | 가공 설비 |
| **CU** (제어 장치) | 명령어 해독 및 제어 신호 생성 | 명령어 해독 속도, 분기 예측 정확도 | 작업반장 |
| **Register** (기억 장치) | 피연산자 및 중간 결과 임시 저장 | 접근 속도(L1 캐시보다 빠름), 용량 | 작업대 |
| **Internal Bus** (통로) | 유닛 간 데이터 및 신호 전달 | 대역폭(Bandwidth), 신호 간섭 최소화 | 컨베이어 벨트 |

> 요약: ALU는 '힘(연산)', CU는 '머리(제어)', 레지스터는 '손(기억)', 버스는 '혈관(통로)'의 역할을 수행함.

## Ⅲ. 구성요소/구조

CPU는 내부 버스를 통해 각 유닛이 유기적으로 연결되어 명령어 사이클을 수행함.

- **구성요소**:
  - **ALU (Arithmetic Logic Unit)**: 덧셈, 뺄셈 등 산술 연산과 AND, OR 등 논리 연산 수행
  - **CU (Control Unit)**: 명령어 레지스터(IR)의 내용을 해독하여 각 장치에 제어 신호를 전송
  - **Registers**: PC(다음 주소), IR(현재 명령어), MAR(메모리 주소), MBR(메모리 데이터), AC(누산기) 등
  - **Internal Bus**: CPU 내부 유닛들 사이의 데이터 및 제어 신호 전달 경로

- **내부 구조도 (ASCII)**:

```text
+-------------------------------------------------+
|                      CPU                        |
|  +-----------+      Control       +----------+  |
|  |  Control  | -----------------> |   ALU    |  |
|  |   Unit    |       Signals      +-----+----+  |
|  +-----+-----+                          |       |
|        |                                |       |
|  +-----v-----+      Internal      +-----v----+  |
|  | Register  | <----------------> | Internal |  |
|  |   File    |        Data        |   Bus    |  |
|  +-----------+                    +----------+  |
+-------------------------------------------------+
        ^                                ^
        | Address/Data Bus (to Memory/IO)|
```

1. **CU**가 명령어를 읽어 분석하고 필요한 제어 신호를 발생시킴
2. **Register**에 저장된 데이터를 **ALU**로 보내 연산을 수행함
3. 연산 결과는 다시 **Register**나 외부 메모리로 전송됨

## Ⅳ. 문제점 및 개선방안

1. **메모리 벽 (Memory Wall)**: ALU 연산 속도에 비해 외부 메모리(RAM) 접근 속도가 너무 느려 CPU가 노는 시간이 발생함
   - **개선방안**: CPU 내부에 레지스터와 RAM 사이의 완충 지대인 **캐시 메모리(Cache Memory)**를 계층화하여 데이터 공급 지연을 줄임 (확인: 캐시 적중률 및 대기 사이클)

2. **제어 흐름 병목**: 조건문이나 반복문 등 분기 명령어가 많을 때 CU가 다음 실행할 명령어를 미리 준비하기 어려움
   - **개선방안**: **분기 예측(Branch Prediction)**과 **비순서 실행(Out-of-Order Execution)** 기술을 적용하여 제어 장치의 유휴 시간을 최소화함 (확인: 분기 예측 성공률)

3. **전력 및 발열**: 클록 속도를 높이거나 유닛을 증설하면 전력 소모와 발열이 급증하여 성능 유지가 어려움
   - **개선방안**: 사용하지 않는 유닛의 전원을 차단하는 **파워 게이팅(Power Gating)**과 작업량에 따라 속도를 조절하는 **DVFS**를 적용함 (확인: 전력 효율성(Perf/Watt))

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 서버 성능 튜닝 | PMU(Performance Monitoring Unit)를 통해 ALU 사용률과 레지스터 대기 시간을 분석하여 코드 최적화 | IPC (Instructions Per Cycle), Stall Cycles |
| 임베디드 설계 | 제어 위주의 작업에는 CU 성능에 집중하고, 연산 위주의 작업(DSP)에는 ALU를 보강한 아키텍처 선택 | 최악 실행 시간(WCET), 인터럽트 지연 |
| AI 가속기 개발 | 단순 연산이 반복되는 AI 워크로드를 위해 ALU를 수천 개로 늘린 NPU/GPU 구조 설계 | FLOPS (Floating Point Operations Per Second) |

> 요약: 워크로드 특성에 따라 ALU와 CU의 비중을 조절하여 시스템 효율을 극대화함.

## Ⅵ. 결론

CPU 구성요소는 현대 컴퓨팅의 기초 물리적 구조이며, 각 유닛의 균형 있는 설계가 전체 시스템의 성능을 좌우함. 기술사는 단순한 구성요소 나열을 넘어, 메모리 접근 지연이나 분기 오예측과 같은 물리적 한계를 각 구성요소가 어떤 방식으로 극복하고 있는지 아키텍처 관점에서 설명할 수 있어야 함.

특히 무어의 법칙이 한계에 다다름에 따라, 범용적인 CPU 구성에 특정 목적의 가속기(NPU 등)를 통합하는 방향으로 진화하고 있음. 결국 CPU 구성에 대한 이해는 소프트웨어 최적화와 차세대 하드웨어 설계의 시작점임.
