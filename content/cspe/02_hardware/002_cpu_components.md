# 📖 【암기용】 개념 완전 이해

## 한눈에
- **개요**: **중앙처리장치(CPU)**는 명령어를 인출·해독·실행하는 시스템의 핵심 **마이크로프로세서**로, 연산(ALU)·제어(CU)·기억(레지스터)·전달(버스) 4대 요소로 구성된다.
- **왜 필요한가**: 메모리에 저장된 소프트웨어 명령어(001 저장 프로그램 방식 참조)를 실제 전기 신호와 산술 연산으로 바꿔줄 물리 장치가 있어야 프로그램이 돌기 때문이다.
- **핵심 직관**: 공장에서 작업반장(CU)이 지시하고, 기술자(ALU)가 가공하며, 작업대(레지스터)에 재료를 두고, 카트(내부 버스)로 나르는 구조다.

## 핵심 용어 정리 (내부에 등장하는 것들)
버스·메모리 접근 구조 등 공통 배경은 001에서 설명했으므로, 여기서는 CPU 내부 요소를 중심으로 정리한다. 맨 위 두 줄이 상위 핵심 키워드다.

| 용어/표기 | 의미 | 비유·예 |
|:---|:---|:---|
| **CPU (중앙처리장치)** | 명령어를 인출·해독·실행해 시스템 전체를 통제하는 연산 장치 | 공장 전체를 돌리는 핵심 작업장 |
| **마이크로프로세서** | CPU를 단일 반도체 칩에 집적한 형태 | 손톱만 한 칩에 담긴 공장 |
| **ALU (연산장치)** | 산술(Arithmetic)·논리(Logic) 연산을 실제 수행하는 회로 | 가공을 맡는 기술자 |
| **CU (제어장치)** | 명령어를 해독해 각 유닛에 제어 신호를 뿌리고 흐름을 통제 | 공정을 지시하는 작업반장 |
| **레지스터 (Register)** | CPU 안의 초고속 임시 저장소. 명령어가 R1·PC처럼 직접 지칭 | 손이 바로 닿는 작업대 |
| **PC / IR** | 다음 명령어 주소를 담는 레지스터(PC), 현재 명령어를 담는 레지스터(IR) | 지금 볼 레시피 줄 번호(PC)와 펼친 레시피(IR) |
| **MAR / MBR** | 메모리 접근 주소(MAR)와 오가는 데이터(MBR)를 담는 레지스터 | 창고 선반 번호(MAR)와 실린 물건(MBR) |
| **내부 버스 (Internal Bus)** | CPU 내부 유닛 간 데이터·신호를 나르는 경로 | 작업장 안에서만 도는 카트 |
| **명령어 사이클** | 인출(Fetch)→해독(Decode)→실행(Execute)→기록(Write-back)의 반복 주기 | 레시피 한 줄을 읽고-이해하고-요리하고-담는 반복 |
| **마이크로코드 (Micro-code)** | 복잡한 명령어 하나를 잘게 나눈 내부 저수준 제어 단계 표 | 큰 조리 지시를 세부 손동작으로 쪼갠 매뉴얼 |
| **CPI / IPC** | 명령어당 소요 사이클(CPI), 그 역수인 사이클당 명령어(IPC) | 접시 하나당 걸린 시간(CPI) |
| **슈퍼스칼라 / ILP** | ALU를 여러 개 두어 한 사이클에 여러 명령어를 처리(ILP 활용) | 기술자 여러 명이 동시에 가공 |

## 깊이 이해
- **배경·문제의식**: 연산을 하려면 숫자를 잠깐 둘 곳(레지스터), 계산할 회로(ALU), 순서를 맞출 통제자(CU)가 모두 필요하다. 이들을 한 칩에 유기적으로 집적하지 않으면 데이터가 칩 밖 RAM을 오가는 동안 수백 사이클이 낭비된다. 그래서 자주 쓰는 저장·연산·제어를 CPU 안에 묶어 초고속으로 돌린다.
- **작동 원리 (명령어 사이클)**:
  - **인출(Fetch)**: PC가 가리키는 주소의 명령어를 가져와 IR에 넣고, PC는 다음 주소로 증가한다.
  - **해독(Decode)**: CU가 IR의 Op-code를 해석해 연산 종류·피연산자를 파악하고, 필요한 제어 신호를 만든다(단순 명령은 하드와이어드, 복잡 명령은 마이크로코드로).
  - **실행(Execute)**: 내부 버스가 레지스터 값을 ALU로 보내 연산하고, 결과를 다시 레지스터/메모리에 기록한다.
- **비유**: 요리사(CPU)가 레시피(명령어)를 읽고(CU), 도마(레지스터) 위 재료를 칼질(ALU)한 뒤 접시에 담는다. 주방 안에서 재료를 옮길 땐 전용 카트(내부 버스)를 쓴다.
- **구체 예시**: `ADD R1, R2` 실행 시 CU가 덧셈 제어 신호를 켜고, 내부 버스가 R1·R2 값을 ALU로 보내며, ALU가 더한 결과를 R1에 다시 쓴다. 이 전 과정이 파이프라인 없는 단순 구조에선 여러 사이클, 파이프라인에선 여러 명령어가 겹쳐 사실상 사이클당 1개꼴로 완료된다.
- **흔한 오해·주의점**: 레지스터를 캐시(L1/L2)와 혼동하면 안 된다. 캐시는 메모리 내용을 자동 복사해 두는 완충 공간이라 프로그래머가 주소로 지칭하지만, 레지스터는 명령어가 `R1`·`PC`처럼 이름으로 직접 지정하는 연산 전용 공간이다. 개수도 수십 개(레지스터) vs 수만~수십만 바이트(캐시)로 다르다.

# 📝 【답안용】 시험 답안 템플릿

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 연산(ALU)·제어(CU)·기억(레지스터)·전달(내부 버스) 4대 요소로 명령어 사이클을 수행하는 시스템의 핵심 연산 장치
> 2. **가치**: Fetch-Decode-Execute를 고속 반복해 소프트웨어 명령어를 물리적 상태 변화로 구현
> 3. **판단 포인트**: ALU 병렬화(Superscalar)·레지스터 리네이밍·내부 버스 대역폭이 단일 코어 ILP의 상한을 결정

## 출제 의도 및 답안 포인트

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| CPU 내부 요소 간 상호작용·동작 흐름 파악 확인 | ALU/CU/레지스터/버스 역할과 유기적 연계 | 기능만 나열하고 사이클 흐름 누락 |
| 명령어 사이클 단계별 하드웨어 상태 변화 이해 확인 | Fetch-Decode-Execute 주기의 제어·데이터 흐름 | 레지스터와 캐시(메모리) 역할 혼동 |

> 요약: 4대 구성요소가 명령어 사이클 안에서 어떻게 상호작용해 처리량을 확보하는지 논리적으로 제시함.

## Ⅰ. 개요 및 필요성

- 개요: 메모리의 명령어를 인출·해독해 산술·논리 연산을 실행하고 시스템 흐름을 통제하는 중앙 집중형 연산 장치
- 배경: 저장 프로그램 방식 구현을 위해 데이터 처리와 제어 신호 동기화를 전담할 물리 장치가 필요(001 참조)
- 필요성: 시스템 클럭에 맞춰 자원을 관리하고 사이클당 처리량(IPC)을 유지하기 위해 연산·제어 유닛의 집적 필수

---

## Ⅱ. 구조 및 구성요소

```text
외부 시스템 버스 -> MAR / MBR(메모리 인터페이스 레지스터)
                 -> 내부 버스 -> ALU / CU / 범용 레지스터
                 / 제어 신호: CU -> 전 유닛 방향
```

| 구성요소 | 역할 | 특이사항(하위 유닛) |
|:---|:---|:---|
| ALU | 데이터 산술·논리 연산 수행 | 가산기, 보수기, 시프터, 누산기(AC) |
| CU | 명령어 해독·제어 신호 생성 | 디코더, 순서 제어기, 마이크로코드 |
| 레지스터 | 피연산자·상태 임시 저장 | PC, IR, MAR, MBR, 범용 레지스터 |
| 내부 버스 | 유닛 간 데이터·주소·제어 전송 | 데이터/주소/제어 버스로 구성 |

> 요약: CU 제어 신호에 따라 내부 버스가 레지스터 값을 ALU로 인입해 물리 연산을 수행함.

---

## Ⅲ. 동작원리 및 흐름도

```text
PC 확인 -> 명령어 인출(Fetch) -> 해독(Decode) -> 실행(Execute) -> 결과 기록(Write-back)
       -> PC 증가 -> 다음 사이클 반복
```

- 1단계 [인출]: PC 주소의 명령어를 IR에 적재하고 PC를 다음 주소로 증가
- 2단계 [해독]: CU 디코더가 IR의 Op-code를 해석해 ALU 연산 모드와 제어 신호를 생성
- 3단계 [실행]: 내부 버스로 레지스터 피연산자를 ALU에 전달해 산술·논리·분기 연산 수행
- 4단계 [기록]: 결과를 타깃 레지스터나 메모리(MBR 경유)에 기록하고 상태 갱신 완료

> 요약: 인출-해독-실행-기록을 무한 반복하며, 이 단계를 시간적으로 겹치는 것이 파이프라이닝의 본질임.

---

## Ⅳ. 특징

- 초고속 데이터 공급: 내부 레지스터망으로 ALU에 피연산자를 즉시 공급해 메모리 지연 Stall을 최소화함
- 제어 타이밍 동기화: 단일 CU가 시스템 클럭에 맞춰 전 유닛을 동기화해 자원 충돌·오동작을 회피함
- 확장 한계: 단일 내부 버스 대역폭과 단일 ALU 구조가 사이클당 처리량 확장의 물리적 상한으로 작용함

---

## Ⅴ. 심화 비교 및 적용 판단

| 구분 | 기본 CPU(Single-issue) | 고성능 CPU(Superscalar) | 판단 기준 |
|:---|:---|:---|:---|
| 연산(ALU) | 정수 ALU 1개 | 다중 ALU·FPU·SIMD 유닛 | 연산 복잡도·병렬도 |
| 제어(CU) | 순차 해독·실행 | 분기 예측·비순차 실행(OoO) 스케줄러 | 파이프라인 예측 실패율 |
| 기억(레지스터) | 기본 레지스터 셋 | 리네이밍용 물리 레지스터 창 | ILP(명령어 수준 병렬성) 한계 |

> 요약: 현대 CPU는 4대 요소를 유지하되 ALU를 다변화하고 CU 스케줄링을 고도화해 병렬성을 확장함.

**리스크·대응:**
- [구조적 해저드]: 다중 명령어가 ALU·버스 자원을 동시 경합 → 예약 스테이션(Reservation Station)으로 대기열 분산
- [데이터 공급 정체]: 메모리 지연으로 ALU 유휴(Starvation) → 다단계 캐시 계층과 프리패처 적용
- [전력·발열 한계]: 고클럭 시 전력·발열 급증 → 다중 코어 분산과 DVFS(동적 전압·주파수 조절) 적용

**도입 후 점검 지표:**
- ALU 활용률: 연산 유닛이 실제 연산 중인 사이클 비율 90% 이상 목표 — PMU 측정
- CPI: 명령어당 사이클 수 1.0 미만 목표 — 성능 카운터 분석

---

## Ⅵ. 실무 적용 및 결론

**적용 방안 3개:**
1. 제어 영역 격리(ARM TrustZone): CU 제어 상태를 보안 세계로 분리해 중요 레지스터에 대한 악성 접근 차단
2. 연산 유닛 확장(SIMD/AVX): ALU에 벡터 구조를 더해 한 제어 명령으로 다수 데이터를 동시 처리(데이터 병렬)
3. 성능 모니터링(PMU): 레지스터 사용 빈도·분기 미스율을 수집해 OS 스케줄러의 코어 배치 최적화에 반영

**결론 (2줄):**
- 기술사 판단: 성능 향상의 축이 클럭 주파수 증대에서 ALU 자원 증설과 CU 스케줄링 최적화로 이동함
- 향후 방향: AI 워크로드를 위해 CPU 내부에 NPU 블록을 직접 통합하는 SoC 구조가 전력 효율의 대세로 부상 중
