## Ⅰ. 개요
- **정의**: CPU 내부에서 연산·제어·저장·전송을 담당하는 네 가지 핵심 기능 블록임
- **배경/필요성**: 명령어 실행 과정을 이해하려면 각 블록의 역할과 상호 데이터 흐름 파악이 필요함
- **비유**: 공장에서 ALU는 생산 라인, CU는 공정 관리자, 레지스터는 작업대, 버스는 컨베이어 벨트임

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| CPU 내부 구조와 데이터 흐름 이해 | 각 블록 간 제어·데이터 신호 방향 | 레지스터 종류(범용/특수)를 구분하여 서술할 것 |

> 요약: ALU·CU·레지스터·버스의 협업이 명령어 실행 사이클을 구성함

## Ⅱ. 구성요소
```text
              +------------------+
              |       CPU        |
              |                  |
  +-----+    |  +-----+  +----+ |    +-----------+
  | MEM |<-->|--| REG |--| ALU| |    | I/O장치   |
  +-----+    |  +-----+  +----+ |    +-----------+
     |        |     |       |    |         |
     +--------|-----+-------+----|--------+
              |       BUS        |
              |  +-----+         |
              |  | CU  |---제어-->|--제어 신호
              |  +-----+         |
              +------------------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| ALU (산술논리연산장치) | 덧셈·뺄셈·AND·OR 등 산술·논리 연산을 수행함 | 공장 생산 라인 |
| CU (제어장치) | 명령어를 해독하고 각 블록에 제어 신호를 발생시킴 | 공정 관리자 |
| 레지스터 | CPU 내부의 소용량 고속 저장 공간(PC, IR, ACC, 범용 등)임 | 작업자 앞 작업대 |
| 버스 | 데이터·주소·제어 신호를 전달하는 공유 전송 경로임 | 컨베이어 벨트 |

> 요약: 네 블록이 버스를 매개로 인출-해독-실행-저장 사이클을 반복함

## Ⅲ. 절차
```text
  Fetch           Decode          Execute         Write-back
  (명령 인출)     (명령 해독)     (연산 실행)     (결과 저장)
    |               |               |               |
    +--주소 버스---->+--제어 신호---->+--데이터 버스-->+
  PC->MAR->MEM     CU가 IR 해독    ALU 연산 수행   결과->REG/MEM
```
- 1단계: PC 값을 주소 버스에 올려 메모리에서 명령어를 인출하고 IR에 저장함
- 2단계: CU가 IR의 연산코드를 해독하여 ALU·레지스터·메모리에 제어 신호를 생성함
- 3단계: ALU가 레지스터의 피연산자로 연산을 수행하고 상태 플래그를 갱신함
- 4단계: 연산 결과를 목적 레지스터 또는 메모리에 기록하고 PC를 다음 명령 주소로 갱신함

> 요약: Fetch-Decode-Execute-Writeback 4단계가 CPU 명령어 사이클의 기본 골격임

## Ⅳ. 문제점
- [버스 병목]: 단일 버스 공유 — 다수 블록이 동시에 버스를 요청하면 대기 시간이 증가함
- [레지스터 부족]: 범용 레지스터 수 제한 — 레지스터 스필(spill)이 발생하여 메모리 접근 횟수가 증가함
- [제어 복잡도]: 명령어 종류 증가 — CU의 마이크로코드 또는 하드와이어드 로직 크기가 비례 증가함

> 요약: 버스 경합·레지스터 부족·제어 복잡도가 CPU 성능의 주요 병목임

## Ⅴ. 개선방안
1. 단기: 내부 버스를 데이터·주소·제어 3종으로 분리하고 멀티포트 레지스터 파일을 적용함
2. 중기: 레지스터 리네이밍과 비순차 실행(OoO)으로 논리 레지스터 부족 문제를 하드웨어가 우회함
3. 장기: 마이크로옵 변환(CISC 외부, RISC 내부) 방식으로 CU 복잡도를 디코더 계층에 한정함 (003 참조)

> 요약: 버스 분리 → 레지스터 리네이밍 → 마이크로옵 변환 순으로 병목을 해소함

## Ⅵ. 전망
- 발전 방향: 칩렛 기반 멀티코어에서 코어 내부 구조보다 코어 간 인터커넥트 설계 비중이 증가함
- 기술사적 판단: NPU·GPU 등 가속기에서도 ALU-레지스터-버스 구조는 기본 설계 단위로 유지됨
- 기술사 제언: CPU 내부 구조 이해를 기반으로 파이프라인·캐시 최적화 설계 역량을 확보해야 함
