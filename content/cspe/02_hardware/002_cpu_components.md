## 미리 알고가기

- ALU는 연산을, CU는 제어를, 레지스터는 초고속 저장을 담당함
- 버스는 CPU 내부와 외부 구성요소를 연결하는 통로임
- CPU 성능은 유닛 개수보다 데이터 공급과 제어 효율에 더 크게 좌우됨

## Ⅰ. 개요

- **정의/개념**: CPU는 명령어를 읽고 해독하고 연산한 뒤 결과를 기록하는 중앙 처리 장치이며, 내부적으로 ALU와 CU와 레지스터와 버스로 구성되어 하나의 명령어 사이클을 수행함
- **배경/필요성**: 시스템 병목을 분석하려면 CPU를 하나의 검은 상자로 보지 않고 연산부와 제어부와 저장부와 전달부로 나누어 각각 어디에서 지연이 발생하는지 이해해야 함

## Ⅱ. 특징

- ALU는 산술·논리 연산 처리량을 결정함
- CU는 명령 해독과 분기 제어로 실행 흐름을 지배함
- 레지스터는 메모리보다 훨씬 빠른 임시 저장소로 동작함
- 버스 대역폭과 제어 충돌은 CPU 전체 처리량을 제한할 수 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | ALU | CU | Register | Bus |
|:---|:---|:---|:---|:---|
| 핵심 역할 | 연산 수행 | 제어 신호 생성 | 초고속 임시 저장 | 데이터 전달 |
| 병목 형태 | 연산 유닛 부족 | 분기·스케줄링 지연 | 저장 공간 부족 | 대역폭 부족 |
| 최적화 축 | 병렬 연산기 | 분기 예측·OoO | 레지스터 파일 | 폭·포트 확장 |
| 대표 지표 | IPC 기여도 | branch accuracy | register pressure | bus utilization |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| ALU | 정수와 논리 연산을 수행하며 실행 유닛 수와 지연 시간이 계산 성능을 좌우함 |
| CU | 명령어를 해독하고 각 유닛에 제어 신호를 보내며 분기와 파이프라인 제어의 핵심임 |
| Register File | 피연산자와 중간 결과를 저장해 메모리 접근을 줄이며 스케줄링 효율에 직접 영향을 줌 |
| Internal Bus | CPU 내부 유닛 간 데이터를 이동시키며 포트 수와 폭이 병렬성을 제한함 |

```text
+---------+     +---------------+     +-------------+
| CU      | --> | Register File | --> | ALU         |
+---------+     +---------------+     +-------------+
     \                |
      \               v
       --> +----------------------+
           | Internal Bus         |
           +----------------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 명령어 인출     | --> | 해독 및 제어     | --> | 연산 수행      | --> | 결과 기록      |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **명령어 인출**: 메모리에서 명령어를 읽음
2. **해독 및 제어**: CU가 명령 종류와 자원 사용을 결정함
3. **연산 수행**: ALU가 필요한 산술·논리 연산을 처리함
4. **결과 기록**: 결과를 레지스터나 메모리에 반영함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 메모리 접근 속도가 ALU 처리 속도를 따라가지 못하면 CPU 유휴 시간이 커질 수 있음
   - 해결방안: 캐시 계층과 prefetch를 강화하고 cache miss rate와 memory stall cycle로 검증함
2. 문제: 분기와 명령 해독 부담이 커지면 CU가 실행 유닛을 충분히 활용하지 못할 수 있음
   - 해결방안: branch prediction과 out-of-order execution을 적용하고 branch accuracy와 issue utilization로 검증함
3. 문제: 내부 버스와 레지스터 포트가 부족하면 다수 유닛이 있어도 실제 병렬성이 제한될 수 있음
   - 해결방안: datapath 폭과 port 설계를 조정하고 bus utilization과 register port contention으로 검증함

## Ⅶ. 적용 사례

- 서버 CPU 튜닝에서는 메모리 병목을 줄이고, cache miss rate와 memory stall cycle로 결과를 확인함
- 모바일 AP 설계에서는 제어 효율을 높이고, branch accuracy와 issue utilization로 결과를 확인함
- AI 가속기 설계에서는 데이터 경로를 확장하고, bus utilization과 register port contention로 결과를 확인함

## Ⅷ. 결론

CPU 성능은 단일 클록 수치보다 ALU와 CU와 레지스터와 버스가 얼마나 균형 있게 협력하는지에서 결정됨.
