## Ⅰ. 개요
- 정의: 컴퓨터의 두뇌로서 연산, 제어, 데이터 보관 기능을 수행하는 중앙 처리 장치
- 필요성: 프로그램 명령어 실행 및 하드웨어 자원 관리의 중추적 역할 수행
- 출제 의도: CPU 3대 핵심 구성요소의 역할과 상호작용 프로세스 이해

## Ⅱ. 구성요소
- ASCII 구조도
  +-----------------------------------+
  |               CPU                 |
  |  +----------+       +----------+  |
  |  | Control  | <---> | Register |  |
  |  |  Unit    |       |   File   |  |
  |  +----+-----+       +----+-----+  |
  |       |                  |        |
  |  +----+-----+            |        |
  |  |   ALU    | <----------+        |
  |  +----------+                     |
  +-----------------------------------+

- 구성요소 표
| 구성요소 | 설명 | 비유 |
| :--- | :--- | :--- |
| ALU | 산술 연산(+,-) 및 논리 연산(AND, OR) 수행 | 계산기 |
| 제어장치 | 명령어 해석 및 각 장치에 제어 신호 전달 | 지휘자 |
| 레지스터 | CPU 내부의 초고속 임시 저장 장치 | 작업대 |
> 요약: 연산(ALU), 지시(CU), 보관(Register)이 조화를 이루어 작동함

## Ⅲ. 절차
- ASCII 흐름도
  CU: (Fetch) -> (Decode) -> (Execute)
                    |            |
                    v            v
  Register: (Operand Load) -> (Result Store)

- 4단계 설명
1. Fetch: PC가 가리키는 주소의 명령어를 IR로 로드
2. Decode: 제어장치가 명령어를 해석하여 연산 제어 신호 발생
3. Execute: ALU가 피연산자를 사용하여 실제 연산 수행
4. Store: 결과를 레지스터나 메모리에 저장하고 상태 플래그 갱신
> 요약: 제어장치의 신호에 따라 ALU가 연산하고 레지스터가 데이터를 공급함

## Ⅳ. 문제점
- 연산 속도 격차: CPU 연산 대비 메모리 접근 속도가 현저히 낮음 (Memory Wall)
- 전력 및 발열: 연산 밀집도가 높아짐에 따라 열 방출 문제 심화

## Ⅴ. 개선방안
- (단기) 레지스터 세트 확장: 데이터 전송 오버헤드 감소를 위한 레지스터 최적화
- (중기) 분기 예측 기술: 제어장치의 명령어 대기 시간 최소화
- (장기) 광컴퓨팅/양자 소자: 기존 실린콘 소자의 물리적 한계 돌파 시도
