## 미리 알고가기

- HBM4는 HBM3E 이후 세대로 더 넓은 인터페이스와 더 높은 스택 대역폭을 지향함
- 차세대 구현에서는 2,048-bit급 버스와 고도화된 base die가 핵심 축으로 거론됨
- 메모리만의 진화가 아니라 파운드리, 패키지, 가속기 공동 설계가 함께 커짐

## Ⅰ. 개요

- **정의/개념**: HBM4는 더 넓은 인터페이스와 향상된 base die와 적층 공정 고도화를 통해 HBM3E보다 높은 대역폭과 용량과 시스템 통합성을 제공하려는 차세대 고대역폭 메모리 표준임
- **배경/필요성**: 초대형 AI 모델과 멀티모달 추론은 온패키지 메모리에서 공급해야 하는 데이터 양이 폭증하므로, 핀 속도 증대만으로는 한계가 있어 버스 폭과 패키지 구조 자체를 확장해야 함

## Ⅱ. 특징

- 인터페이스 폭 확대를 통해 더 낮은 신호 부담으로 더 큰 총 대역폭을 확보하려는 방향이 뚜렷함
- base die 기능이 강화되어 메모리 제어와 테스트와 신호 최적화 여지가 커짐
- 하이브리드 본딩 같은 고급 패키징 기술과 결합될수록 두께와 저항과 열 경로를 함께 줄일 수 있음
- 메모리 공급사와 가속기 설계사와 파운드리의 공동 최적화 비중이 크게 높아짐

## Ⅲ. 종류 및 비교

| 판단 기준 | HBM3E | HBM4 |
|:---|:---|:---|
| 인터페이스 방향 | 기존 폭 위에서 속도와 용량을 높이는 확장형임 | 더 넓은 인터페이스로 총 대역폭을 크게 키우는 구조 변화가 큼 |
| 시스템 역할 | 현행 AI 가속기의 주력 메모리임 | 차세대 AI 플랫폼의 메모리 공급 기반으로 확장됨 |
| 패키징 난도 | 이미 매우 높음 | 인터페이스와 적층과 발열 조건이 더 복잡해짐 |
| 설계 포인트 | 성능과 수율의 균형이 중요함 | 메모리와 로직의 공동 설계 비중이 더 커짐 |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Wider I/O Interface | 더 넓은 데이터 통로를 제공해 고속 신호 부담을 분산하면서 총 대역폭을 높임 |
| Advanced Base Die | 제어와 테스트와 신호 보정 기능을 강화해 차세대 가속기 요구에 맞춘 통합성을 높임 |
| High-Layer DRAM Stack | 더 큰 스택 용량과 병렬성을 제공해 모델 탑재 범위를 넓힘 |
| Hybrid Package Path | 인터포저와 본딩 구조를 개선해 전력 손실과 열 집중을 함께 줄이려는 핵심 영역임 |

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 대규모 메모리 요청 | --> | 넓은 채널로 분산  | --> | 고단 스택 병렬 접근 | --> | 프로세서로 고속 전달 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **대규모 메모리 요청**: 가속기가 긴 컨텍스트와 큰 파라미터 집합을 읽음
2. **넓은 채널로 분산**: base die가 요청을 넓은 인터페이스 경로에 분배함
3. **고단 스택 병렬 접근**: 적층 DRAM이 다수 bank와 채널에서 동시에 동작함
4. **프로세서로 고속 전달**: 인터포저와 본딩 경로를 통해 데이터가 짧은 거리로 이동함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 인터페이스 폭 확대와 적층 증가가 겹치면 패키지 배선과 본딩 정밀도 요구가 급격히 높아짐
   - 해결방안: 하이브리드 본딩과 고밀도 인터포저를 적용하고 package yield와 signal integrity margin으로 검증함
2. 문제: 더 큰 대역폭을 지속적으로 쓰는 AI 부하는 열 밀도와 전력 밀도를 빠르게 악화시킬 수 있음
   - 해결방안: 액체 냉각과 전력 분산 설계를 적용하고 junction temperature와 sustained bandwidth로 검증함
3. 문제: 메모리와 가속기 공동 설계 의존도가 커지면 공급망과 검증 일정이 쉽게 병목이 될 수 있음
   - 해결방안: co-design interface와 검증 자동화를 강화하고 bring-up cycle time과 interoperability defect rate로 검증함

## Ⅶ. 적용 사례

- 차세대 AI 학습 플랫폼은 HBM4를 사용해 긴 컨텍스트 모델의 공급 병목을 줄이고, sustained bandwidth와 tokens per second로 결과를 확인함
- 맞춤형 AI ASIC는 강화된 base die 통합을 활용해 메모리 경로를 최적화하고, accelerator utilization과 power efficiency로 결과를 확인함
- 엑사스케일 HPC 노드는 고대역폭 스택으로 과학 계산의 데이터 공급을 개선하고, flops efficiency와 memory stall ratio로 결과를 확인함

## Ⅷ. 결론

HBM4는 메모리의 세대 교체가 아니라 패키지와 로직과 메모리의 공동 설계를 전제로 하는 시스템 아키텍처 변화이므로, 판단 기준은 단순 최고 속도보다 통합 가능한 지속 대역폭임.
