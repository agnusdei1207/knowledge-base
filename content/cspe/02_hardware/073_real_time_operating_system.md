# RTOS 실시간 운영체제 (Real-Time Operating System)

## 미리 알고가기

- RTOS: 실시간 운영체제(Real-Time Operating System, RTOS)는 태스크가 정해진 시간 안에 실행되도록 스케줄링과 동기화를 제공하는 운영체제임
- 데드라인: 특정 태스크가 반드시 완료되어야 하는 시간 한계임
- 지터: 주기 태스크나 인터럽트 응답 시간이 매번 달라지는 변동 폭임
- ISR: 인터럽트 서비스 루틴(Interrupt Service Routine, ISR)은 인터럽트 발생 시 즉시 실행되는 짧은 처리 루틴임
- 우선순위 역전: 낮은 우선순위 태스크가 보유한 자원 때문에 높은 우선순위 태스크가 대기하는 현상임

## Ⅰ. 개요

- **정의/개념**: RTOS는 임베디드·제어 시스템에서 태스크, 인터럽트, 타이머, 동기화 자원을 관리하고 최악 응답시간·지터·데드라인 만족 여부를 기준으로 예측 가능한 실행을 보장하는 운영체제임
- **배경/필요성**: 자동차 제어, 산업 설비, 의료기기처럼 물리 장치를 제어하는 시스템은 응답이 빠른 것보다 늦지 않는 것이 중요함. 범용 운영체제(Operating System, OS)는 처리량과 사용자 편의 중심이라 데드라인 보장에 한계가 있음
- **비유**: 여러 사람이 줄을 서는 은행보다 응급 환자, 수술실, 약품 배송을 정해진 우선순위와 시간표로 처리하는 응급실 운영 방식과 같음

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 실시간 OS 선택 기준 설명 | 결정성, 스케줄러, 인터럽트, 데드라인, 지터 | 빠른 OS로만 설명 |
| 임베디드 제어 안정성 판단 | 우선순위, 동기화, 우선순위 역전 | 일반 OS 기능 나열 |

> 요약: RTOS는 작업을 빨리 실행하는 것보다 늦지 않게 실행하도록 최악 응답시간을 관리하는 운영체제임.

## Ⅱ. 특징 및 비교

| 판단 기준 | 범용 OS | RTOS |
|:---|:---|:---|
| 최우선 목표 | 처리량, 사용자 편의, 자원 활용률 | 데드라인 만족, 결정성, 낮은 지터 |
| 스케줄링 | 공정성, 우선순위, 동적 부하 균형 | 고정·동적 우선순위 기반 실시간 스케줄링 |
| 인터럽트 처리 | 평균 응답성이 중요함 | 인터럽트 레이턴시 상한과 예측 가능성이 중요함 |
| 적용 영역 | 개인용 컴퓨터(Personal Computer, PC), 서버, 모바일 범용 응용 | 자동차, 로봇, 의료, 산업 제어, 사물인터넷(Internet of Things, IoT) 장치 |

> 요약: RTOS는 평균 성능보다 최악 지연을 통제해야 하는 제어 시스템에 적합함.

- **스케줄링 기준**: 비율 단조 스케줄링(Rate Monotonic Scheduling, RMS), 최단 마감 우선(Earliest Deadline First, EDF), 고정 우선순위 등 태스크 특성에 맞춰 선택함
- **동기화 기준**: 세마포어, 뮤텍스, 메시지 큐는 편리성보다 블로킹 시간 예측 가능성이 중요함
- **검증 기준**: 중앙처리장치(Central Processing Unit, CPU) 사용률 평균보다 최악 실행시간, 인터럽트 지연, 데드라인 미스율을 측정해야 함

## Ⅲ. 구성요소/구조

```text
+----------+      +----------+      +----------+
| Interrupt| ---> | RTOS     | ---> | Task     |
| Event    |      | Kernel   |      | Execute  |
+----------+      +----+-----+      +----+-----+
                         |
          +--------------+--------------+
          v                             v
    +----------+                  +----------+
    |Scheduler |                  |IPC/Timer |
    +----+-----+                  +----+-----+
          |                             |
          +--------------+--------------+
                         v
                   +----------+
                   | Output   |
                   | Control  |
                   +----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 커널 | 태스크 상태, 문맥 전환, 시스템 호출을 관리하는 RTOS 핵심임 | 관제 센터 |
| 스케줄러 | 우선순위와 데드라인 기준으로 다음 실행 태스크를 선택함 | 응급실 배정표 |
| 인터럽트 처리기 | 외부 이벤트에 즉시 반응하고 필요한 작업을 태스크로 넘김 | 비상벨 대응팀 |
| 타이머 | 주기 태스크, 타임아웃, 데드라인 감시를 위한 시간 기준을 제공함 | 정확한 시계 |
| IPC·동기화 | 프로세스 간 통신(Inter-Process Communication, IPC), 큐, 세마포어, 뮤텍스로 태스크 간 데이터 전달과 자원 접근을 조정함 | 교통 신호 |

> 요약: RTOS는 커널, 스케줄러, 인터럽트, 타이머, 동기화 기능으로 실시간 태스크 실행 순서를 통제함.

### 원리/흐름도

```text
+----------+      +----------+      +----------+      +----------+
| Task     | ---> | Priority | ---> | Dispatch | ---> | Verify   |
| Model    |      | Assign   |      | Control  |      | Timing   |
+----------+      +----------+      +----------+      +----------+
```

1. **태스크 모델링**: 주기, 실행시간, 데드라인, 공유 자원, 인터럽트 이벤트를 정의함
2. **우선순위 설계**: 태스크 중요도와 주기를 기준으로 우선순위와 스케줄링 정책을 정함
3. **실행·동기화 제어**: ISR, 메시지 큐, 세마포어, 타이머를 통해 태스크 실행과 통신을 제어함
4. **시간 검증**: 최악 실행시간, 인터럽트 지연, 문맥 전환 시간, 데드라인 미스 여부를 측정함

> 요약: RTOS 적용은 태스크 시간 특성을 정의하고 우선순위와 동기화를 설계한 뒤 최악 시간으로 검증하는 과정임.

## Ⅳ. 문제점 및 개선방안

- **P1 우선순위 역전**: 낮은 우선순위 태스크가 공유 자원을 잡고 있으면 높은 우선순위 태스크가 데드라인을 놓칠 수 있음
- **P1 대응**: 우선순위 상속 또는 우선순위 천장 프로토콜을 적용함 (확인: 블로킹 시간 상한)
- **P2 지터와 인터럽트 폭주**: ISR이 길거나 이벤트가 과도하면 주기 태스크의 실행 간격이 불안정해짐
- **P2 대응**: ISR을 최소화하고 지연 처리 태스크로 분리하며 인터럽트 발생률 제한을 적용함 (확인: 지터, 최대 ISR 시간)
- **P3 자원 누수와 교착**: 작은 메모리와 정적 자원 환경에서 큐 포화, 스택 오버플로, 데드락이 장치 오동작으로 이어짐
- **P3 대응**: 정적 할당, 워터마크 측정, 데드락 분석을 적용함 (확인: 스택 여유, 큐 포화율)

> 요약: RTOS 개선은 시간 계측을 기반으로 우선순위, 인터럽트, 메모리 자원 사용을 예측 가능하게 만드는 활동임.

## Ⅴ. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 모터 제어 장치 | 주기 제어 태스크와 보호 인터럽트를 높은 우선순위로 두고 공유 자원 블로킹 시간을 제한함 | 최대 응답시간, 지터, 블로킹 시간 상한 |
| 의료기기 펌웨어 | 센서 수집, 경보, 사용자 표시 태스크를 중요도별로 분리하고 데드라인 미스 시 안전 상태로 전환함 | 데드라인 미스율, 경보 지연, 스택 여유 |
| 산업용 사물인터넷(Internet of Things, IoT) 게이트웨이 | 통신 ISR은 짧게 처리하고 메시지 큐와 작업 태스크로 부하를 분산함 | 최대 ISR 시간, 큐 포화율, 패킷 손실률 |

> 요약: RTOS는 태스크 중요도와 최악 지연을 실제 제어·경보·통신 지표로 검증할 때 선택 근거가 명확해짐.

## Ⅵ. 결론

- **발전 방향**: RTOS는 자율주행, 로봇, 산업 IoT에서 기능 안전, 보안 업데이트, 멀티코어 스케줄링, 혼합 중요도 파티셔닝과 결합함
- **기술사적 판단**: 태스크 우선순위, 최악 실행 시간(Worst-Case Execution Time, WCET), 인터럽트 중첩, 메모리 보호, 타이머 해상도, 스택 크기를 데드라인 요구와 함께 설계함; 최악 응답시간, 지터, 데드라인 미스율, 우선순위 역전 발생 조건, 스택 오버플로를 계측 도구로 측정함
- **기술사 제언**: RTOS는 빠른 OS가 아니라 최악 응답시간과 데드라인 보장을 설계·검증·운영 지표로 관리하는 체계로 설명함
