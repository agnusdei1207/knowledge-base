## 미리 알고가기

- MCU는 CPU와 메모리와 주변장치를 한 칩에 통합한 제어용 반도체임
- MPU는 외부 메모리와 고성능 소프트웨어 스택을 전제로 하는 연산 중심 프로세서임
- RTOS는 짧은 응답시간과 결정성을 중시하는 실시간 운영체제임
- PMIC(Power Management IC)는 전원 변환과 분배를 담당하는 전력 관리 반도체임

## 작성 근거(검토용)

- MCU·MPU는 칩 통합 범위, 메모리, 운영체제, 실시간성, 전력·보드 구성을 핵심 축으로 설명함
- 비교표는 두 구조의 칩·전력 구조, 소프트웨어, 대표 제어·응용 업무를 대비함
- 실무 판단은 대기 전류·메모리 여유율과 데드라인 미스율·보드 전력으로 검증함

## Ⅰ. 개요

- **정의/개념**: 마이크로컨트롤러는 제어 업무에 필요한 CPU와 메모리와 주변장치를 단일 칩에 통합한 구조이고, 마이크로프로세서는 고성능 CPU를 중심으로 외부 메모리와 I/O를 결합해 시스템을 구성하는 구조임
- **배경/필요성**: 실시간 제어와 범용 응용의 데드라인·메모리·전력 요구를 충족하기 위해 MCU와 MPU의 선택 기준이 필요함

## Ⅱ. 특징

- MCU는 CPU·메모리·타이머·GPIO를 한 칩에 통합해 센서·모터 제어 주기를 실행함
- MPU는 외부 DRAM과 범용 운영체제로 UI·네트워크·멀티미디어 응용을 처리함
- MCU는 베어메탈·RTOS, MPU는 Linux·Android 실행 환경을 주로 사용함
- 실시간성 요구와 보드 복잡도와 전력 예산이 선택을 가르는 핵심 축임

## Ⅲ. 종류 및 비교

| 판단 기준 | 마이크로컨트롤러 | 마이크로프로세서 |
|:---|:---|:---|
| 칩·전력 구조 | CPU·Flash·SRAM·주변장치를 칩 안에 통합하고 저전력 모드를 사용함 | CPU 중심이며 외부 DRAM·저장장치·PMIC로 전력·열을 관리함 |
| 소프트웨어 | 베어메탈·RTOS에서 제한된 태스크를 실행함 | Linux·Android에서 프로세스와 서비스를 실행함 |
| 대표 업무 | 센서·모터·계측 주기 제어 | UI·네트워크·멀티미디어·복합 연산 |

> 요약: MCU는 온칩 자원과 실시간 제어, MPU는 외부 메모리와 범용 운영체제 기반 복합 응용에 사용함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| CPU 코어 | MCU는 제어 응답성과 단순성을, MPU는 범용 처리 성능과 확장성을 중시함 |
| 메모리 구조 | MCU는 내장 메모리 중심이라 단순하고 저전력이지만 MPU는 외부 DRAM으로 확장성을 얻음 |
| 주변장치·I/O | MCU는 GPIO·ADC·타이머를 칩 내부에 통합하고 MPU는 고속 인터페이스와 외부 칩을 연결함 |
| 소프트웨어 스택 | MCU는 작은 펌웨어와 RTOS로 예측 가능성을 높이고 MPU는 범용 OS와 풍부한 미들웨어를 활용함 |

> 요약: MCU는 온칩 메모리·주변장치와 RTOS로 제어 경로를 구성하고, MPU는 외부 메모리와 범용 OS로 응용 경로를 구성함.

## Ⅵ. 실무 사례

1. 배터리 센서 노드는 MCU의 메모리·주변장치 예산을 고정하고 대기 전류·메모리 여유율을 확인함
2. MPU 기반 Linux 장치는 실시간 제어 경로를 MCU로 분리하고 데드라인 미스율·보드 전력을 확인함

## Ⅶ. 결론

- MCU와 MPU는 데드라인·메모리·운영체제·전력·보드 비용 요구에 따라 선택하고 실제 제어 지연과 전력 예산으로 검증해야 함
