## Ⅰ. 개요
- **정의**: MCU는 CPU·메모리·주변장치를 단일 칩에 통합한 제어용 프로세서, MPU는 연산 중심의 범용 프로세서임
- **배경/필요성**: IoT·임베디드 시스템 설계 시 제어 목적과 연산 목적에 따라 칩 선택 기준이 상이함
- **비유**: MCU는 다용도 멀티툴, MPU는 전문 공작 기계에 해당함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 구조·용도·성능 관점 비교 | 내장 메모리 유무, OS 탑재 가능 여부 | MCU에도 고성능 제품군 존재함을 인지 |

> 요약: 통합도와 용도에 따라 MCU(제어)와 MPU(연산)를 구분함

## Ⅱ. 구성요소
```text
MCU: +-- CPU Core --+-- Flash/SRAM --+-- GPIO/ADC/Timer --+  (Single Chip)
MPU: +-- CPU Core --+               외부 DRAM / Flash / I/O 칩과 버스 연결
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| CPU 코어 | MCU는 저전력 코어, MPU는 고클럭 다중 코어를 탑재함 | 소형 엔진 vs 대형 엔진 |
| 메모리 | MCU는 KB급 내장 SRAM/Flash, MPU는 외부 GB급 DRAM을 사용함 | 주머니 vs 창고 |
| 주변장치 | MCU는 GPIO·ADC·타이머를 칩 내 통합, MPU는 외부 IC로 확장함 | 내장 공구함 vs 별도 공구대 |

> 요약: MCU는 단일 칩 통합, MPU는 외부 확장 기반 고성능 구조임

## Ⅲ. 절차
```text
요구사항 분석 -> 제어/연산 목적 판별 -> MCU/MPU 선정 -> 펌웨어/OS 설계
```
- 1단계: 대상 시스템의 연산량·전력·비용 요구사항을 분석함
- 2단계: 실시간 제어 중심이면 MCU, 범용 연산·OS 필요 시 MPU로 판별함
- 3단계: 클럭·메모리·주변장치 사양을 기준으로 구체 칩을 선정함
- 4단계: MCU는 베어메탈/RTOS 펌웨어, MPU는 Linux 등 OS 기반으로 설계함

> 요약: 요구사항-목적판별-칩선정-SW설계 순으로 의사결정함

## Ⅳ. 문제점
- MCU 성능 한계: 복잡 연산·멀티태스킹 요구 증가 시 처리 능력이 부족함
- MPU 전력·비용 부담: 외부 메모리·전원 회로 등 BOM 비용과 소비 전력이 높음
- 경계 모호화: 고성능 MCU와 저전력 MPU 스펙이 중첩되어 선정 기준이 불명확함

> 요약: MCU의 성능 천장, MPU의 비용·전력, 양자 경계 모호화가 과제임

## Ⅴ. 개선방안
1. 단기: 하드웨어 가속기(DSP, FPU) 탑재 MCU로 연산 한계를 보완함
2. 중기: SiP(System in Package)로 MPU+메모리 통합하여 BOM을 절감함
3. 장기: RISC-V 기반 커스텀 코어로 제어·연산 비율을 워크로드별 최적화함

> 요약: 가속기·SiP·커스텀 코어로 MCU-MPU 간극을 축소함

## Ⅵ. 전망
- 발전 방향: 온디바이스 AI(100 참조) 요구로 MCU에 NPU 통합이 확산됨
- 기술사적 판단: IoT 엣지 디바이스 증가로 저전력·고집적 MCU 수요가 지속됨
- 기술사 제언: 워크로드 프로파일에 기반한 MCU/MPU 선정 프레임워크 수립이 필요함
