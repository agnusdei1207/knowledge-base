## 미리 알고가기

- 비순서 실행은 준비된 명령부터 먼저 실행하는 구조임
- WAR·WAW: 실제 데이터 흐름이 아니라 레지스터 재사용으로 생기는 가짜 의존성(각각 Write-After-Read, Write-After-Write)이며 레지스터 리네이밍이 이를 제거함
- ILP(Instruction-Level Parallelism): 서로 의존하지 않아 동시에 실행할 수 있는 명령어 병렬 처리량임
- 재정렬 버퍼(Reorder Buffer): 비순서로 실행된 결과를 프로그램 순서대로 커밋하는 저장 구조임
- 결과 확정은 여전히 프로그램 순서를 유지해야 함
- IPC(Instructions Per Cycle): 클록 한 주기당 완료하는 명령어 수를 나타내는 처리량 지표임

## 작성 근거(검토용)

- OoO와 리네이밍을 순서를 없애는 기술이 아니라 가짜 의존성을 제거하고 커밋 순서를 보존하는 구조로 설명함
- 순서 실행과 비순서 실행을 실행/발행 순서·결과 확정·하드웨어 자원으로 비교함
- 명령어 창 크기와 복구·재실행 비용을 비순서 실행의 검증 기준으로 연결함

## Ⅰ. 개요

- **정의/개념**: 비순서 실행은 프로그램 순서와 다르게 준비된 명령어를 먼저 실행해 실행 유닛 유휴 시간을 줄이는 기술이고, 레지스터 리네이밍은 논리 레지스터 이름을 물리 레지스터로 매핑해 가짜 의존성을 제거하는 메커니즘임
- **배경/필요성**: 메모리 대기 중에도 독립 명령어를 실행해 단일 스레드 성능을 높이기 위해 의존성 분석과 순서 재배치가 필요함

### 쉽게 이해하기 (학습용)
- 주방장이 주문 순서와 상관없이 재료가 준비된 요리부터 먼저 만들어 화구가 노는 시간을 줄이는 것과 같음
- 같은 이름의 그릇을 재사용하다 헷갈리지 않도록 매번 새 이름표를 붙이는 것이 리네이밍임

## Ⅱ. 특징

- 준비된 연산을 먼저 실행해 실행 유닛 활용률을 높임
- 리네이밍으로 WAR와 WAW를 제거해 ILP를 확장함
- 결과는 재정렬 버퍼를 통해 프로그램 순서대로 확정되어 정합성을 유지함
- 명령 윈도·물리 레지스터·재정렬 버퍼 항목 수가 늘면 비교 회로와 저장 비트가 증가함

### 쉽게 이해하기 (학습용)
- 준비된 요리부터 바로 만들어 화구를 놀리지 않음
- 그릇 이름표를 새로 붙여 같은 그릇을 다시 쓰다 생기는 혼동을 없앰
- 요리는 순서 없이 완성돼도 서빙 창구에서는 주문 순서대로 내보냄

## Ⅲ. 종류 및 비교

| 판단 기준 | 순서 실행 | 비순서 실행 |
|:---|:---|:---|
| 실행/발행 순서 | 프로그램 순서대로 발행·실행함 | 피연산자가 준비된 명령부터 발행해 대기시간을 줄임 |
| 결과 확정 | 실행 순서와 동일하게 커밋함 | 재정렬 버퍼가 프로그램 순서로 커밋함 |
| 하드웨어 자원 | 파이프라인 레지스터 중심 | 레지스터 별칭 테이블·예약 스테이션·물리 레지스터·재정렬 버퍼 추가 필요 |

> 요약: 순서 실행은 프로그램 순서를 유지하고, 비순서 실행은 준비된 명령을 먼저 처리해 대기 시간을 줄임.

### 쉽게 이해하기 (학습용)
- 순서대로 조리하는 주방은 한 요리씩 차례로 만들어 낸 순서 그대로 서빙하지만, 비순서 주방은 재료가 준비된 요리부터 만들고 서빙 창구에서 순서를 맞춰 냄
- 비순서 방식은 대기 화구·이름표 관리대·서빙 창구 같은 추가 설비가 필요함

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 레지스터 별칭 테이블 | 논리 레지스터를 물리 레지스터로 매핑해 이름 충돌을 제거함 |
| 예약 스테이션 | 피연산자가 준비될 때까지 명령어를 대기시키고 준비되면 발행함 |
| 물리 레지스터 파일 | 리네이밍된 물리 레지스터의 연산 결과를 저장함 |
| 재정렬 버퍼 | 비순서로 끝난 결과를 프로그램 순서대로 확정해 정밀 예외와 상태 일관성을 유지함 |

```text
+---------------------+     +-------------------+     +----------------------+
| 레지스터 별칭 테이블  | --> | 예약 스테이션       | --> | 물리 레지스터 파일        |
+---------------------+     +-------------------+     +----------------------+
                                                     |
                                                     v
                                              +---------------+
                                              | 재정렬 버퍼      |
                                              +---------------+
```

> 요약: 리네이밍과 재정렬 버퍼는 가짜 의존성을 제거하면서 결과 확정 순서는 보존함.

### 쉽게 이해하기 (학습용)
- 그릇 이름표를 새로 붙이는 곳(레지스터 별칭 테이블), 재료 도착을 기다리는 대기 자리(예약 스테이션), 완성 요리를 담아두는 선반(물리 레지스터 파일), 손님 순서대로 다시 정렬해 내보내는 창구(재정렬 버퍼)가 함께 움직임

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 레지스터 리네이밍  | --> | 준비 상태 대기    | --> | 비순서 실행      | --> | 순차 확정      |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **레지스터 리네이밍**: 논리 레지스터를 물리 레지스터에 매핑함
2. **준비 상태 대기**: 피연산자 도착까지 예약 스테이션에서 대기함
3. **비순서 실행**: 준비된 명령부터 실행 유닛에 발행함
4. **순차 확정**: 재정렬 버퍼가 원래 순서대로 결과를 반영함

> 요약: 비순서 실행은 이름 충돌을 없앤 뒤 준비된 명령을 먼저 실행하고 결과는 프로그램 순서대로 확정함.

### 쉽게 이해하기 (학습용)
- 그릇 이름표를 새로 붙이고(리네이밍), 재료가 올 때까지 기다렸다가(준비 상태 대기), 준비된 순서로 요리하고(비순서 실행), 마지막엔 원래 주문 순서로 서빙함(순차 확정)

## Ⅵ. 실무 사례

1. 서버 CPU는 명령어 창을 늘려 독립 명령 탐색 범위를 조정하고, IPC 증가량과 전력 증가량으로 적정 크기를 검증함
2. 메모리 의존성 예측을 사용하는 CPU는 잘못 실행한 명령의 재처리를 줄이기 위해 예측기를 조정하고, 재실행률과 복구 사이클로 검증함

### 쉽게 이해하기 (학습용)
- 화구(명령어 창)를 늘리면 동시에 준비할 수 있는 요리가 늘지만 관리 부담도 커져 적정선을 찾아야 함
- 잘못 예상하고 만든 요리는 버리고 다시 만들어야 하므로 예상이 자주 틀리면 손해가 커짐

## Ⅶ. 결론

- 비순서 실행과 레지스터 리네이밍은 WAR·WAW 같은 가짜 의존성을 제거해 준비된 명령을 먼저 실행하면서도 재정렬 버퍼로 결과를 프로그램 순서대로 확정하는 기술임
- 명령어 창과 물리 레지스터 규모는 IPC 증가량이 검사 회로 비용과 재실행 손실을 상쇄하는 범위에서 정해야 함

### 쉽게 이해하기 (학습용)
- 재료 이름표를 바꿔 헷갈림을 없애고 준비된 요리부터 만들되, 손님에게는 항상 주문한 순서대로 내야 함
