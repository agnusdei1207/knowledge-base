## 미리 알고가기

- CXL은 PCIe 물리 계층 위에서 동작하는 고속 저지연 일관성 인터커넥트임
- 호스트·가속기·메모리 장치 사이에 메모리 접근 의미와 일관성을 제공하는 것이 핵심임
- CXL은 단순 I/O 연결보다 메모리 확장과 풀링과 공유 자원화에 더 직접적인 의미가 있음

## Ⅰ. 개요

- **정의/개념**: CXL은 PCIe 기반 물리 인터페이스를 활용하면서도 호스트 프로세서·가속기·메모리 장치 간에 일관성 있는 메모리 접근과 저지연 데이터 교환을 제공하는 개방형 고속 인터커넥트 표준임
- **배경/필요성**: CPU·GPU·메모리 확장 장치를 일관되게 공유·확장하기 위해 저지연 표준 인터커넥트가 필요함

## Ⅱ. 특징

- PCIe 인프라를 활용하면서도 메모리 일관성과 접근 의미를 제공해 확장성이 높음
- 메모리 확장 장치와 가속기를 긴밀하게 연결해 이기종 시스템 구성을 단순화함
- 스위칭·풀링·패브릭 확장으로 데이터센터 자원 분리를 가속함
- 성능 이득은 프로토콜 자체보다 소프트웨어 스택과 메모리 배치 정책이 얼마나 잘 맞는지에 달려 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | CXL.io | CXL.cache | CXL.mem |
|:---|:---|:---|:---|
| 역할 | 장치 발견·구성·관리 기능을 담당함 | 가속기가 호스트 메모리를 일관성 있게 참조하게 함 | 호스트가 장치 메모리를 메모리처럼 접근하게 함 |
| 강점 | PCIe 호환 관리 경로를 유지함 | 가속기와 CPU 간 캐시 일관성을 지원함 | 메모리 확장과 풀링의 기반을 제공함 |
| 주 사용처 | 초기화와 제어 경로 | 가속기 연결 | 메모리 확장 장치 |
| 설계 포인트 | 호환성과 관리성 | 일관성 처리 지연 | 메모리 지연과 RAS |

> 요약: CXL.io는 관리, CXL.cache는 일관성 참조, CXL.mem은 메모리 확장을 담당함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 호스트 프로세서 | CXL 루트를 제공하며 가속기와 메모리 장치의 일관성 정책 기준점이 됨 |
| CXL 링크 | PCIe 기반 물리 연결에서 CXL.io·CXL.cache·CXL.mem 트래픽을 전달함 |
| 가속기·유형별 장치 | 연산 가속이나 메모리 확장을 수행하며 유형별 캐시·메모리 기능 범위가 다름 |
| 패브릭·스위치 계층 | 다수 장치를 분기 연결하고 메모리 풀링과 공유 토폴로지를 지원함 |

```text
+----------------+     +----------------+     +------------------+
| Host Processor | <-> | CXL Link       | <-> | CXL Device       |
+----------------+     +----------------+     +------------------+
                                 |
                                 v
                         +------------------+
                         | CXL Switch/Fabric|
                         +------------------+
```

> 요약: CXL은 호스트·링크·장치·스위치 패브릭으로 가속기와 메모리를 일관성 있게 연결함.

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 장치 열거        | --> | 링크 협상        | --> | cache/mem 경로 설정 | --> | 데이터 교환 수행 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **장치 열거**: 호스트가 연결된 CXL 장치와 기능 타입을 인식함
2. **링크 협상**: 물리 링크와 프로토콜 기능을 설정함
3. **cache와 mem 경로 설정**: 필요한 일관성 경로와 메모리 매핑을 준비함
4. **데이터 교환 수행**: 가속기 접근이나 메모리 확장을 저지연 경로로 처리함

> 요약: CXL은 장치 인식 후 cache/mem 경로를 설정해 저지연 일관성 접근을 수행함.

## Ⅵ. 실무 적용 및 유의점

1. remote memory를 과도하게 쓰면 지연 민감 작업이 흔들리므로 latency-aware placement와 hot set pinning을 적용하고 CXL memory access latency, local hit ratio로 확인함
2. 호스트·장치·스위치가 늘면 coherency와 RAS 경로가 복잡해지므로 fabric management와 telemetry를 강화하고 fault isolation time, corrected error visibility로 확인함
3. CXL 확장 메모리를 로컬 DRAM처럼 쓰면 성능이 저하될 수 있으므로 계층 인식 할당기와 NUMA 정책을 적용하고 remote access ratio, throughput stability로 확인함

## Ⅶ. 결론

CXL은 새 케이블이 아니라 메모리와 가속기를 필요할 때 묶고 풀 수 있게 만드는 데이터센터 인터커넥트 규약임.

## 작성 근거(검토용)

- CXL은 PCIe 대체가 아니라 CXL.io, CXL.cache, CXL.mem의 역할 분리로 설명함
- 모호한 표현은 CXL memory access latency, local hit ratio, fault isolation time으로 구체화함
- 결론은 케이블·버스가 아니라 데이터센터 자원 연결 규약으로 정리함
