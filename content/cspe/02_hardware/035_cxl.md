## 미리 알고가기

- CXL은 PCIe 물리 계층 위에서 동작하는 고속 저지연 일관성 인터커넥트임
- CXL은 호스트·가속기·메모리 장치 사이에 메모리 접근 의미와 일관성을 제공함
- CXL.mem과 스위치 기능은 메모리 확장·풀링 경로를 구성함

## 작성 근거(검토용)

- CXL은 PCIe 대체가 아니라 CXL.io·CXL.cache·CXL.mem의 역할 분리로 설명함
- CXL.io·CXL.cache·CXL.mem을 접근 주체·전송 의미·사용 경로·관리 조건으로 구분함
- 호스트·가속기·메모리의 접근 규약을 CXL의 중심 역할로 정리함

## Ⅰ. 개요

- **정의/개념**: CXL은 PCIe 기반 물리 인터페이스를 활용하면서도 호스트 프로세서·가속기·메모리 장치 간에 일관성 있는 메모리 접근과 저지연 데이터 교환을 제공하는 개방형 고속 인터커넥트 표준임
- **배경/필요성**: CPU·GPU·메모리 확장 장치를 일관되게 공유·확장하기 위해 저지연 표준 인터커넥트가 필요함

## Ⅱ. 특징

- PCIe 물리 계층을 사용하고 CXL.io·CXL.cache·CXL.mem 프로토콜을 제공함
- 호스트가 장치 메모리에 접근하고 가속기가 호스트 메모리를 일관성 있게 참조할 수 있음
- 스위치와 패브릭 관리 기능으로 메모리 장치의 확장·풀링 경로를 구성함
- 접근 지연은 장치 위치와 운영체제의 메모리 배치 정책에 따라 달라짐

## Ⅲ. 종류 및 비교

| 판단 기준 | CXL.io | CXL.cache | CXL.mem |
|:---|:---|:---|:---|
| 접근 주체 | 호스트 소프트웨어 | 가속기 장치 | 호스트 프로세서 |
| 전송 의미 | 장치 발견·구성·관리 | 호스트 메모리의 일관성 캐시 접근 | 장치 메모리의 읽기·쓰기 접근 |
| 사용 경로 | 초기화·제어·오류 보고 | 가속기의 호스트 메모리 참조 | 메모리 확장·풀링 |
| 관리 조건 | PCIe 호환 설정·열거 | 일관성 지연·캐시 상태 | 메모리 지연·RAS·배치 정책 |

> 요약: CXL.io는 관리, CXL.cache는 일관성 참조, CXL.mem은 메모리 확장을 담당함.

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| 호스트 프로세서 | CXL 루트를 제공하며 가속기와 메모리 장치의 일관성 정책 기준점이 됨 |
| CXL 링크 | PCIe 기반 물리 연결에서 CXL.io·CXL.cache·CXL.mem 트래픽을 전달함 |
| 가속기·유형별 장치 | 연산 가속이나 메모리 확장을 수행하며 유형별 캐시·메모리 기능 범위가 다름 |
| 패브릭·스위치 계층 | 다수 장치를 분기 연결하고 메모리 풀링과 공유 토폴로지를 지원함 |

```text
+----------------+     +----------------+     +------------------+
| 호스트 프로세서   | <-> | CXL 링크       | <-> | CXL 장치          |
+----------------+     +----------------+     +------------------+
                                 |
                                 v
                         +------------------+
                         | CXL 스위치/패브릭 |
                         +------------------+
```

> 요약: CXL은 호스트·링크·장치·스위치 패브릭으로 가속기와 메모리를 일관성 있게 연결함.

## Ⅵ. 실무 사례

1. CXL 메모리 확장 서버는 계층 인식 할당기를 적용하고 로컬 메모리 적중률과 CXL 메모리 접근 지연을 확인함
2. CXL 패브릭은 장치 상태 수집과 오류 격리를 적용하고 장애 격리시간과 교정 오류 누락 건수를 확인함

## Ⅶ. 결론

- CXL은 CXL.io·CXL.cache·CXL.mem으로 호스트·가속기·메모리의 접근 경로를 구성하는 인터커넥트 규약임
