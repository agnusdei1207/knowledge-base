## 미리 알고가기

- CXL은 PCIe 물리 계층 위에서 동작하는 고속 저지연 일관성 인터커넥트임
- 호스트와 가속기와 메모리 장치 사이에 memory semantics와 coherency를 제공하는 것이 핵심임
- CXL은 단순 I/O 연결보다 메모리 확장과 풀링과 공유 자원화에 더 직접적인 의미가 있음

## Ⅰ. 개요

- **정의/개념**: CXL은 PCIe 기반 물리 인터페이스를 활용하면서도 호스트 프로세서와 가속기와 메모리 장치 간에 일관성 있는 메모리 접근과 저지연 데이터 교환을 제공하는 개방형 고속 인터커넥트 표준임
- **배경/필요성**: AI와 데이터센터 시스템은 CPU와 GPU와 메모리 확장 장치를 더 유연하게 묶어야 하므로, 단순 I/O 연결을 넘어 메모리 자원을 효율적으로 공유하고 확장할 수 있는 표준 인터커넥트가 필요함

## Ⅱ. 특징

- PCIe 인프라를 활용하면서도 메모리 coherency와 memory semantics를 제공해 확장성이 높음
- 메모리 확장 장치와 가속기를 더 긴밀하게 연결해 heterogeneous 시스템 구성을 단순화함
- 스위칭과 풀링과 fabric 방향 확장으로 데이터센터 자원 분리를 가속함
- 성능 이득은 프로토콜 자체보다 소프트웨어 스택과 메모리 배치 정책이 얼마나 잘 맞는지에 달려 있음

## Ⅲ. 종류 및 비교

| 판단 기준 | CXL.io | CXL.cache | CXL.mem |
|:---|:---|:---|:---|
| 역할 | 장치 발견과 구성과 관리 기능을 담당함 | 가속기가 호스트 메모리를 일관성 있게 참조하게 함 | 호스트가 장치 메모리를 메모리처럼 접근하게 함 |
| 강점 | PCIe 호환 관리 경로를 유지함 | 가속기와 CPU 간 cache coherency를 지원함 | 메모리 확장과 풀링의 기반을 제공함 |
| 주 사용처 | 초기화와 제어 경로 | accelerator attach | memory expansion device |
| 설계 포인트 | 호환성과 관리성 | coherence latency | memory latency와 RAS |

## Ⅳ. 구성요소 및 구조

| 구성요소 | 설명 |
|:---|:---|
| Host Processor | CXL 루트를 제공하며 가속기와 메모리 장치에 대한 coherency 정책의 기준점이 됨 |
| CXL Link | PCIe 기반 물리 연결 위에서 CXL.io와 CXL.cache와 CXL.mem 트래픽을 전달함 |
| Accelerator or Type Device | 연산 가속이나 메모리 확장 역할을 수행하며 타입별로 cache와 memory 기능 범위가 다름 |
| Fabric or Switch Layer | 다수 장치를 fan-out하고 이후 memory pooling과 공유 토폴로지를 가능하게 함 |

```text
+----------------+     +----------------+     +------------------+
| Host Processor | <-> | CXL Link       | <-> | CXL Device       |
+----------------+     +----------------+     +------------------+
                                 |
                                 v
                         +------------------+
                         | CXL Switch/Fabric|
                         +------------------+
```

## Ⅴ. 원리 및 절차 흐름도

```text
+-------------+     +-------------+     +-------------+     +-------------+
| 장치 열거        | --> | 링크 협상        | --> | cache/mem 경로 설정 | --> | 데이터 교환 수행 |
+-------------+     +-------------+     +-------------+     +-------------+
```

1. **장치 열거**: 호스트가 연결된 CXL 장치와 기능 타입을 인식함
2. **링크 협상**: 물리 링크와 프로토콜 기능을 설정함
3. **cache와 mem 경로 설정**: 필요한 일관성 경로와 메모리 매핑을 준비함
4. **데이터 교환 수행**: 가속기 접근이나 메모리 확장을 저지연 경로로 처리함

## Ⅵ. 문제점 및 해결 방안

1. 문제: 링크 대역폭이 충분해도 실제 워크로드가 remote memory를 과도하게 사용하면 지연 민감 작업이 쉽게 흔들릴 수 있음
   - 해결방안: latency-aware placement와 hot set pinning을 적용하고 CXL memory access latency와 local hit ratio로 검증함
2. 문제: 호스트와 장치와 스위치가 늘수록 coherency와 RAS 경로가 복잡해져 장애 분석이 어려워질 수 있음
   - 해결방안: fabric management와 telemetry를 강화하고 fault isolation time과 corrected error visibility로 검증함
3. 문제: 소프트웨어가 CXL 확장 메모리를 로컬 DRAM처럼 취급하면 기대한 자원 효율보다 성능 저하가 먼저 나타날 수 있음
   - 해결방안: tier-aware allocator와 NUMA 정책을 적용하고 remote access ratio와 throughput stability로 검증함

## Ⅶ. 적용 사례

- AI 서버는 CXL 메모리 장치를 사용해 호스트 메모리 여유를 확장하고, local hit ratio와 accelerator utilization로 결과를 확인함
- 데이터베이스 서버는 메모리 확장 tier를 도입해 대용량 인메모리 집합을 수용하고, query latency와 remote access ratio로 결과를 확인함
- 이기종 가속 플랫폼은 CXL 기반 연결로 CPU와 가속기 경로를 단순화하고, device attach latency와 throughput stability로 결과를 확인함

## Ⅷ. 결론

CXL의 본질은 새로운 케이블이 아니라 메모리와 가속기를 자원화해 필요할 때 묶고 풀 수 있게 만드는 데이터센터 인터커넥트 규약이라는 점에 있음.
