## Ⅰ. 개요
- **정의**: 서버를 표준 랙 또는 전용 섀시에 탑재하는 두 가지 대표 폼팩터임
- **배경/필요성**: 데이터센터 밀도와 관리 효율 요구가 높아져 서버 폼팩터 선택이 TCO에 미치는 영향이 큼
- **비유**: 랙 서버는 서랍장에 독립 서랍을 쌓는 것, 블레이드 서버는 책꽂이에 얇은 책을 꽂는 것과 유사함

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 두 폼팩터의 구조·장단점 비교 | 밀도·전력·관리·확장성 축으로 비교 | 블레이드의 벤더 종속(섀시 호환성) 언급 필요 |

> 요약: 랙 서버와 블레이드 서버는 독립성과 집적도 간 트레이드오프를 가진 서버 폼팩터임

## Ⅱ. 구성요소
```text
  Rack Server                    Blade Server
  +-----------+                  +--Chassis-----------+
  | 1U/2U/4U  |                  | +----+ +----+ +--+ |
  | Server    |                  | | BL | | BL | |BL| |
  | (독립 PSU,|                  | +----+ +----+ +--+ |
  |  NIC, Fan)|                  | Shared PSU/NIC/Fan  |
  +-----------+                  +---------------------+
  | 1U/2U/4U  |
  | Server    |
  +-----------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| Rack Server | 1U~4U 독립 서버로 자체 PSU·NIC·팬을 보유하며, 19인치 랙에 수직 적재됨 | 독립된 서랍(각자 열쇠·손잡이 보유) |
| Blade Server | 얇은 보드 형태의 서버로, 섀시의 공유 전원·냉각·네트워크를 사용함 | 책꽂이의 얇은 책(책꽂이가 구조 지지) |
| Chassis (섀시) | 블레이드를 수용하는 인클로저로, PSU·팬·미드플레인 백본을 공유 제공함 | 여러 책을 담는 책꽂이 틀 |
| Midplane | 섀시 내 블레이드 간 전력·데이터를 연결하는 백플레인 보드임 | 책꽂이 내부의 공유 연결판 |

> 요약: 랙 서버는 독립 구성, 블레이드 서버는 섀시 공유 구성으로 차이가 있음

## Ⅲ. 절차
```text
Requirement Analysis --> Form Factor Selection --> Deployment --> Management
        |                        |                     |              |
        v                        v                     v              v
  워크로드·밀도·            랙 or 블레이드         물리 설치/        통합 관리/
  예산 분석                 폼팩터 결정            케이블링          모니터링
```
- 1단계: **Requirement Analysis** — 워크로드 유형, 집적 밀도, 예산, 벤더 전략을 분석함
- 2단계: **Form Factor Selection** — 독립성·유연성 중시 시 랙 서버, 고밀도·통합 관리 중시 시 블레이드 서버를 선정함
- 3단계: **Deployment** — 랙 서버는 개별 케이블링, 블레이드는 섀시 단위 설치 후 블레이드 슬롯 삽입으로 구축함
- 4단계: **Management** — 랙 서버는 개별 BMC/IPMI, 블레이드는 섀시 관리 모듈(CMM)로 통합 모니터링함

> 요약: 요구분석 → 폼팩터 선정 → 구축 → 관리의 4단계로 도입됨

## Ⅳ. 문제점
- **블레이드 벤더 종속**: 섀시·미드플레인이 벤더 전용 규격이라 타 벤더 블레이드 호환이 불가함
- **랙 서버 케이블 복잡도**: 서버당 독립 전원·네트워크 케이블이 필요하여 고밀도 환경에서 케이블 관리가 복잡해짐
- **블레이드 열 집중**: 고밀도 섀시에서 발열이 집중되어 냉각 부하가 국소적으로 증가함

> 요약: 벤더 종속, 케이블 복잡도, 열 집중이 각 폼팩터의 주요 문제임

## Ⅴ. 개선방안
1. 단기: OCP(Open Compute Project) 등 개방형 표준 섀시 채택으로 블레이드 벤더 종속 완화
2. 중기: 구조화 케이블링(Top-of-Rack 스위치 + 패치 패널)으로 랙 서버 케이블 복잡도 감소
3. 장기: 리어도어 수냉·직접 액냉(DLC) 도입으로 블레이드 섀시의 열 집중 문제 해소 (069 참조)

> 요약: 개방형 표준, 구조화 케이블링, 액냉 도입으로 각 문제를 단계적 해소함

## Ⅵ. 전망
- 발전 방향: 하이퍼컨버지드(HCI) 어플라이언스가 랙·블레이드의 장점을 결합한 제3 폼팩터로 부상 중임
- 기술사적 판단: OCP 기반 개방형 서버 표준이 확산되면서 전통 블레이드 시장은 축소되고 랙/OCP 중심으로 재편될 전망임
- 기술사 제언: 5년 TCO 분석 시 폼팩터별 전력·냉각·관리 비용까지 포함하여 비교 평가할 필요
