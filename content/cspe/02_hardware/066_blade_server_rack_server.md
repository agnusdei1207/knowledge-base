# 블레이드 서버·랙 서버 (Blade Server Rack Server)

## 미리 알고가기

- Rack Unit: 랙 유닛(Rack Unit, U)은 19인치 랙에서 장비 높이를 나타내는 단위이며 `1U`는 약 1.75인치임
- Blade Chassis: 여러 블레이드 서버가 공유하는 전원, 냉각, 네트워크, 관리 섀시임
- Top-of-Rack: 랙 상단 스위치로 같은 랙의 서버 네트워크를 집선하는 방식임
- Hot Swap: 서버나 모듈을 운영 중 교체할 수 있는 특성임

## 1. 개요

- **정의/개념**: 블레이드 서버와 랙 서버는 서버를 공유 섀시 중심의 고밀도 모듈로 구성할지, 독립 섀시 중심의 표준 랙 장비로 구성할지 집적도, 확장 유연성, 장애 범위, 전원·냉각, 벤더 종속성 기준으로 비교하는 서버 폼팩터임.
- **배경/필요성**: 데이터센터는 공간, 전력, 배선, 관리 효율을 높여야 하지만 워크로드와 장애 격리 요구도 함께 만족해야 함. 블레이드와 랙 서버 비교는 물리 배치가 운영성과 가용성에 미치는 영향을 판단하게 함.
- **비유**: 블레이드는 여러 가구가 공용 설비를 쓰는 아파트이고, 랙 서버는 독립 주택을 줄지어 배치한 형태와 같음.

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| 서버 폼팩터별 장단점과 선택 기준 설명 | 섀시 공유, 밀도, 확장성, 장애 도메인 | 블레이드를 단순 소형 서버로 설명 |

> 요약: 블레이드 서버와 랙 서버는 물리 집적도와 독립성 사이의 트레이드오프로 선택함.

## 2. 특징 및 비교

| 판단 기준 | 블레이드 서버 | 랙 서버 |
|:---|:---|:---|
| 집적도/배선 | 공유 섀시로 전원, 냉각, 네트워크 배선을 줄이고 고밀도 구성이 가능함 | 서버별 케이블과 전원이 필요하지만 배치 자유도가 높음 |
| 장애 범위 | 섀시, 백플레인, 공유 전원 장애가 여러 블레이드에 영향을 줄 수 있음 | 서버 단위 장애 격리가 쉽고 부품 교체 경로가 다양함 |
| 적용 기준 | 표준화된 고밀도 컴퓨트와 중앙 관리에 유리함 | 다양한 구성, GPU/스토리지 확장, 벤더 선택 유연성에 유리함 |

> 요약: 블레이드는 밀도와 관리 효율, 랙 서버는 유연성과 장애 격리에 강점이 있음.

## 3. 구성요소/구조

```text

| +------+ +------+ +------+  |
| |Blade | |Blade | |Blade |  |
| +------+ +------+ +------+  |
| Power  Network  Cooling Mgmt|
+-----------------------------+

+--------+  +--------+  +--------+
| Rack 1 |  | Rack 2 |  | Rack N |
+--------+  +--------+  +--------+
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 블레이드 섀시 | 전원, 냉각, 네트워크, 관리 모듈을 여러 서버가 공유함 | 아파트 공용 설비 |
| 서버 블레이드 | 중앙처리장치(Central Processing Unit, CPU), 메모리, 로컬 입출력(Input/Output, I/O)을 가진 얇은 서버 모듈임 | 개별 세대 |
| 랙 서버 | 독립 전원, 냉각, I/O 확장을 가진 표준 랙 장착 서버임 | 독립 주택 |
| 관리 모듈 | 원격 전원, 펌웨어, 상태 감시, 장애 알림을 통합 관리함 | 관리사무소 |

> 요약: 블레이드는 공유 섀시 중심, 랙 서버는 독립 서버 중심으로 물리 구조가 다름.

### 원리/흐름도

```text
+----------+     +----------+     +----------+     +----------+
| Capacity | --> | FormFact | --> | Install  | --> | Operate  |
+----------+     +----------+     +----------+     +----------+
```

1. **용량 산정**: 중앙처리장치(Central Processing Unit, CPU), 메모리, 그래픽 처리 장치(Graphics Processing Unit, GPU), 스토리지, 랙 공간, 전력, 냉각 요구를 계산함
2. **폼팩터 선택**: 밀도, 장애 격리, 확장 카드, 벤더 전략을 기준으로 블레이드와 랙 서버를 비교함
3. **설치/연결**: 전원 이중화, 네트워크 업링크, 관리망, 케이블 경로를 구성함
4. **운영/확장**: 모니터링, 펌웨어 업데이트, 장애 교체, 증설 계획을 표준 절차로 관리함

> 요약: 서버 폼팩터 선택은 용량 요구를 물리 배치와 운영 절차에 맞추는 과정임.

## 4. 문제점 및 개선방안

- **P1 공유 섀시 장애 영향**: 블레이드 섀시의 백플레인, 전원, 관리 모듈 장애가 여러 서버에 동시에 영향을 줄 수 있음
- **P1 대응**: 섀시 전원·팬·관리 모듈 이중화와 서비스 분산 배치를 적용함 (확인: 섀시 장애 시 영향 서비스 수)
- **P2 열 밀도 증가**: 고밀도 블레이드 구성은 랙 단위 발열을 높여 냉각 부족과 throttling을 유발함
- **P2 대응**: 랙 전력 상한, airflow blanking, 고밀도 구역 냉각 개선, 온도 기반 부하 배치를 적용함 (확인: 흡기 온도와 throttling률)
- **P3 벤더 종속성**: 블레이드 섀시, I/O 모듈, 관리 소프트웨어가 특정 벤더 생태계에 묶일 수 있음
- **P3 대응**: 표준 랙 서버 혼합 전략, 계약 exit 조건, 관리 응용 프로그램 인터페이스(Application Programming Interface, API) 연동성을 확보함 (확인: 대체 장비 도입 가능성)

> 요약: 블레이드·랙 서버 개선은 공유 구성 이중화, 열 밀도 관리, 벤더 종속 완화로 폼팩터 리스크에 대응함.

## 5. 실무 적용 사례

| 적용 영역 | 적용 방식 | 확인 지표 |
|:---|:---|:---|
| 가상화 컴퓨트 팜 | 블레이드 섀시로 표준 서버를 고밀도 배치하고 관리 모듈로 펌웨어를 일괄 통제함 | 랙당 노드 수, 섀시 장애 영향 범위 |
| GPU 확장 서버 | 독립 랙 서버에 고전력 GPU와 PCIe 확장 카드를 배치해 냉각과 교체성을 확보함 | GPU 장착 가능 수, 흡기 온도, 정비 시간 |
| 혼합 데이터센터 | 핵심 서비스는 장애 격리가 쉬운 랙 서버, 표준 batch 업무는 블레이드로 분리함 | 서비스별 fault domain, 랙 전력 밀도 |

> 요약: 실무에서는 밀도, 확장 카드, 장애 격리 요구에 따라 블레이드와 랙 서버를 혼합 선택함.

## 6. 결론

- **발전 방향**: 블레이드와 랙 서버는 가속기 모듈, 모듈형 섀시, 개방형 랙 설계, 직접 액체냉각을 반영하며 밀도와 독립 운영 사이에서 세분화됨
- **기술사적 판단**: 공유 전원·팬·관리 모듈의 장애 범위, 주변 장치 상호연결 익스프레스(Peripheral Component Interconnect Express, PCIe) expansion 필요량, 랙당 kW, cable management, 벤더 교체성을 기준으로 폼팩터를 선택함; chassis failover, fan fault thermal margin, GPU 장착 시 공기 흐름, 전력 분배 장치(Power Distribution Unit, PDU) branch load, maintenance access 시간을 실측함
- **기술사 제언**: 폼팩터 선택은 공간 절감만이 아니라 장애 도메인, 열 설계, 확장 카드, 공급망 대체성을 함께 비교해야 함
