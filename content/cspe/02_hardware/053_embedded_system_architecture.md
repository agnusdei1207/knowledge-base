## Ⅰ. 개요
- 특정 목적을 수행하기 위해 장치에 내장된 전용 컴퓨터 시스템
- 하드웨어와 소프트웨어가 밀결합된 실시간 처리(Real-time) 구조

| 구분 | 내용 |
| --- | --- |
| 정의 | 기계나 장치에 포함되어 특정 기능을 수행하는 제어 시스템 |
| 특징 | 고신뢰성, 저전력, 실시간성(Determinism), 자원 제약 |
| 출제의도 | 계층 구조 및 실시간 운영체제(RTOS)의 역할 이해 확인 |

## Ⅱ. 구성요소
```
+------------------------------------------+
|  [ Embedded SW Stack ]                   |
|  +------------------------------------+  |
|  | Application Code (Specific Task)   |  |
|  +------------------------------------+  |
|  | Middleware / RTOS / HAL            |  |
|  +------------------------------------+  |
|  [ Hardware: CPU/MCU, Mem, I/O, Sensor ] |
+------------------------------------------+
```
| 구성요소 | 설명 | 비유 |
| --- | --- | --- |
| MCU | CPU, 메모리, 주변장치가 통합된 마이크로 컨트롤러 | 올인원 가전 |
| RTOS | 작업 우선순위 기반의 실시간 운영체제 | 엄격한 시간표 |
| HAL | 하드웨어 독립적인 추상화 레이어 | 공용 리모컨 |
> 요약: 최소 자원으로 특정 임무를 수행하는 수직적 통합 구조임.

## Ⅲ. 절차
```
[센싱/입력] -> [데이터 처리/연산] -> [제어 출력/액션]
```
1. 센싱: 인터럽트나 폴링 방식으로 외부 신호 및 상태 데이터 획득함.
2. 처리: RTOS의 스케줄링 하에 최우선 순위 태스크를 먼저 실행함.
3. 연산: 정의된 알고리즘에 따라 제어 로직을 계산하고 상태 업데이트함.
4. 액션: GPIO, PWM 등을 통해 모터 구동이나 디스플레이 출력 수행함.
> 요약: 외부 입력을 실시간 처리하여 즉각적인 물리적 피드백 제공함.

## Ⅳ. 문제점
- 하드웨어 종속성: 특정 칩셋에 맞춰 코딩되어 타 장치 이식성 낮음.
- 디버깅 난이도: 화면/입력 수단 부재로 동작 분석 및 오류 수정 어려움.

## Ⅴ. 개선방안
- 표준화된 HAL 적용: 하드웨어 의존도를 낮춰 코드 재사용성 확보함.
- 원격 모니터링: OTA(Over-the-Air) 기술 도입으로 원격 관리 강화함.

## Ⅵ. 전망
- 리눅스 기반 임베디드와 경량 RTOS의 하이브리드 구조 도입 확산됨.
- 보안 내재화(Security by Design)가 가전/자동차 분야의 핵심 성공 요인임.
