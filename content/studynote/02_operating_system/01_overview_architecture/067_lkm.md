## 핵심 인사이트 (3줄 요약)

> 1. **본질**: LKM(Loadable [[022_kernel_role|Kernel]] Modules)은 [[022_kernel_role|커널]]을 재부팅하지 않고 기능을 추가/제거할 수 있게 하는 [[192_module_independence|모듈]] 방식이다.
> 2. **가치**: 드라이버, [[501_file_definition_logical_record|파일]] 시스템, 네트워크 기능을 동적으로 확장할 수 있어 유지보수와 유연성이 높다.
> 3. **판단**: [[022_kernel_role|커널]] 내부이므로 안정성과 보안이 중요하며, [[192_module_independence|모듈]] 서명과 의존성 관리가 필요하다.

---

## Ⅰ. 개요 및 필요성

모든 기능을 [[022_kernel_role|커널]]에 기본 탑재하면 [[022_kernel_role|커널]]이 너무 커진다. 그래서 필요한 것만 나중에 적재하는 LKM이 중요하다.

LKM은 운영 중에도 기능 추가가 가능하므로 장치 지원과 확장성 측면에서 유용하다.

- **📢 섹션 요약 비유**: 벽을 뜯지 않고 필요한 부품만 끼워 넣는 조립식 가구다.

---

## Ⅱ. 아키텍처 및 핵심 원리

```text
Module file
  ↓ insmod/modprobe
Kernel space
  ↓
Registered subsystem
```

| 구성 요소 | 역할 |
| :-- | :-- |
| insmod | [[192_module_independence|모듈]] 적재 |
| modprobe | 의존성 포함 적재 |
| rmmod | [[192_module_independence|모듈]] 제거 |
| symbol | [[022_kernel_role|커널]]과 [[192_module_independence|모듈]]의 연결 지점 |

LKM은 [[022_kernel_role|커널]] 심볼을 통해 기능을 연결한다. 그래서 [[192_module_independence|모듈]] 간 의존성과 [[288_version_ihl_tos_total_length|버전]] 호환성을 잘 관리해야 한다.

- **📢 섹션 요약 비유**: 장난감에 맞는 연결핀을 꽂아 기능을 확장하는 느낌이다.

---

## Ⅲ. 비교 및 연결

| 구분 | Built-in | LKM |
| :-- | :-- | :-- |
| 적재 시점 | 부팅 시 | 런타임 |
| 유연성 | 낮음 | 높음 |
| 안정성 | 상대적으로 높음 | [[192_module_independence|모듈]] 품질에 의존 |

| 관련 개념 | 의미 |
| :-- | :-- |
| [[495_device_driver|Device Driver]] | 하드웨어 지원 |
| Filesystem [[192_module_independence|Module]] | [[501_file_definition_logical_record|파일]] 시스템 확장 |
| Netfilter | 네트워크 기능 확장 |

LKM은 필요할 때만 넣는 방식이라 효율적이지만, [[022_kernel_role|커널]] 내부 코드인 만큼 버그가 치명적일 수 있다.

- **📢 섹션 요약 비유**: 필요할 때만 붙였다 떼는 도구지만, 잘못 끼우면 전체가 흔들린다.

---

## Ⅳ. 실무 적용 및 기술사 판단

### [[435_checklist_based_testing|체크리스트]]

1. [[192_module_independence|모듈]] 의존성과 [[288_version_ihl_tos_total_length|버전]] 호환성을 확인하는가?
2. [[192_module_independence|모듈]] 서명과 보안을 고려하는가?
3. insmod와 modprobe 차이를 아는가?
4. 런타임 적재/제거 영향 범위를 아는가?
5. [[022_kernel_role|커널]] 공간 특성을 이해하는가?

### [[128_water_scrum_fall_anti_pattern|안티패턴]]

- [[395_verification_process_review|검증]] 없이 임의 [[192_module_independence|모듈]]을 적재하는 설계
- 의존성을 무시한 적재 순서
- [[022_kernel_role|커널]] 공간 버그를 과소평가하는 설계
- 운영 환경에서 서명/정책을 무시하는 설계

기술사 관점에서는 LKM을 "[[022_kernel_role|커널]] 확장 메커니즘"으로 보되, 안정성과 보안을 반드시 함께 언급해야 한다.

- **📢 섹션 요약 비유**: 새 부품을 넣을 때는 설명서와 안전장치가 꼭 필요하다.

---

## Ⅴ. 기대효과 및 결론

LKM은 [[022_kernel_role|커널]] 재컴파일 없이 기능을 확장하게 해 운영 효율이 높다. 그래서 드라이버 중심 시스템에서 특히 중요하다.

결론적으로 LKM은 런타임 [[022_kernel_role|커널]] 확장 방식이다.

- **📢 섹션 요약 비유**: 필요한 기능만 나중에 끼워 넣을 수 있는 커다란 장난감 상자다.
