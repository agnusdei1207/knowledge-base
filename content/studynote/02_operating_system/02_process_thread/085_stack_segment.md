## 핵심 인사이트 (3줄 요약)

> **본질**: [[057_stack|스택]]([[057_stack|Stack]]) 영역은 [[294_function_calling_tool_use|함수 호출]] 때 생기는 프레임(Frame)을 쌓아 두는 프로세스 메모리 영역이다.
> **가치**: 지역 변수, 매개변수, 복귀 주소, 저장 레지스터를 빠르게 관리할 수 있어 [[294_function_calling_tool_use|함수 호출]]이 자연스러워진다.
> **판단 포인트**: 깊은 [[014_recursion|재귀]], 큰 지역 [[055_array|배열]], 무분별한 alloca는 [[057_stack|스택]] 오버플로([[095_overflow|Overflow]]) 위험을 키운다.

## Ⅰ. 개요 및 필요성

[[057_stack|스택]] 영역은 [[294_function_calling_tool_use|함수 호출]]과 복귀를 위해 사용하는 LIFO(Last In, First Out) 메모리 구조다. 호출이 중첩될 때마다 새로운 프레임이 올라가고, 함수가 끝나면 마지막에 들어온 프레임부터 내려간다.

이 구조가 필요한 이유는 [[294_function_calling_tool_use|함수 호출]]의 상태를 빠르게 저장하고 복원해야 하기 때문이다. [[015_abi|ABI]] ([[015_abi|Application Binary Interface]])가 호출 규약을 정의하는 이유도, [[057_stack|스택]]을 어떻게 쓰는지 정하지 않으면 다른 함수와 모듈이 서로 맞물리지 않기 때문이다.

- 📢 섹션 요약 비유: 겹겹이 쌓는 작업대

## Ⅱ. 아키텍처 및 핵심 원리

[[057_stack|스택]] 프레임에는 보통 복귀 주소, 이전 프레임 포인터, 지역 변수, 임시 값, 인자가 들어간다. [[166_sp|SP]] ([[057_stack|Stack]] Pointer)는 현재 꼭대기를 가리키고, [[293_fp_function_point|FP]] (Frame Pointer)는 현재 프레임의 기준점을 잡아 디버깅과 접근을 쉽게 만든다. 많은 시스템에서 [[057_stack|스택]]은 높은 주소에서 낮은 주소 방향으로 자란다.

```text
높은 주소
┌──────────────────┐
│ 이전 프레임      │
├──────────────────┤
│ 복귀 주소        │
├──────────────────┤
│ 지역 변수 / 임시값│
├──────────────────┤
│ 현재 SP          │
└──────────────────┘
낮은 주소
```

| 항목 | 역할 |
| --- | --- |
| Return Address | 함수가 끝난 뒤 돌아갈 위치 |
| Local Variables | 함수 내부 임시 [[001_dikw_pyramid|데이터]] |
| Saved Registers | 호출 전 상태 보존 |
| Args | 함수 입력값 보관 |

[[057_stack|스택]]은 빠르지만 크기가 제한되므로, "빠르다"와 "많이 담을 수 있다"는 다른 얘기라는 점이 핵심이다.

- 📢 섹션 요약 비유: 서랍식 호출 기록

## Ⅲ. 비교 및 연결

[[057_stack|스택]]은 힙([[078_heap_datastructure|Heap]])과 자주 비교된다. [[057_stack|스택]]은 자동 관리되고 접근이 빠르지만 수명이 짧고 크기가 제한된다. 힙은 자유도가 높지만 할당/해제가 느리고 단편화가 생길 수 있다. 정적 영역이나 [[083_bss_segment|BSS]] (Block Started by Symbol)는 프로그램 전체 수명 동안 유지되는 [[001_dikw_pyramid|데이터]]에 가깝다.

| 영역 | 특징 | 대표 용도 |
| --- | --- | --- |
| [[057_stack|Stack]] | 빠르고 자동 관리 | 지역 변수, 호출 프레임 |
| [[078_heap_datastructure|Heap]] | 동적이고 유연 | 객체, 큰 버퍼 |
| Static/[[083_bss_segment|BSS]] | 프로그램 전체 수명 | 전역/정적 변수 |

즉 [[057_stack|스택]]은 "[[294_function_calling_tool_use|함수 호출]]을 위한 임시 작업대"이고, 힙은 "장기 보관 창고"로 이해하면 경계가 선명해진다.

- 📢 섹션 요약 비유: 작업대와 창고

## Ⅳ. 실무 적용 및 기술사 판단

실무에서는 큰 [[055_array|배열]]이나 깊은 [[014_recursion|재귀]]를 [[057_stack|스택]]에 올리지 않는 것이 기본이다. 멀티스레드 환경에서는 스레드별 [[057_stack|스택]] 크기가 다르므로, [[336_library_vs_framework|라이브러리]] [[014_recursion|재귀]]나 지역 변수 크기를 조심해야 한다. 또한 주소가 [[057_stack|스택]] 영역인지 힙 영역인지 알고 디버깅해야 원인 분석이 빨라진다.

### [[435_checklist_based_testing|체크리스트]]
1. 지역 [[055_array|배열]]이 지나치게 크지 않은가?
2. [[014_recursion|재귀]] 깊이가 입력에 비례해 커지지 않는가?
3. 프레임 포인터를 기준으로 디버깅 가능한가?

### [[128_water_scrum_fall_anti_pattern|안티패턴]]
- 지역 변수 주소를 밖으로 반환하는 것
- 대형 버퍼를 [[057_stack|스택]]에 무심코 두는 것
- [[014_recursion|재귀]] 종료 조건이 약한 알고리즘을 그대로 쓰는 것

- 📢 섹션 요약 비유: 빨리 쌓고 빨리 치우기

## Ⅴ. 기대효과 및 결론

[[057_stack|스택]] 구조를 이해하면 [[294_function_calling_tool_use|함수 호출]], 예외 처리, [[016_interrupt_mechanism|인터럽트]], 디버깅을 하나의 메모리 모델로 설명할 수 있다. 반면 [[057_stack|스택]]과 힙을 혼동하면 [[282_performance_tactics|성능]] 문제와 메모리 오류를 헷갈리기 쉽다. 그래서 [[057_stack|스택]]은 "자동 정리되는 임시 작업대"로 기억하는 것이 좋다.

결론적으로 [[057_stack|스택]] 영역은 호출 규약과 메모리 안정성의 교차점이다. 기술사 답변에서는 [[166_sp|SP]], [[293_fp_function_point|FP]], 호출 프레임, 오버플로 위험을 함께 설명하면 탄탄하다.
