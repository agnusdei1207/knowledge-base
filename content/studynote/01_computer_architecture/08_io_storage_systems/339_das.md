## 핵심 인사이트 (3줄 요약)

> 1. **본질**: DAS ([Direct](/studynote/01_computer_architecture/04_instruction_set_architecture/176_direct_addressing/) Attached Storage)는 저장장치를 네트워크가 아니라 서버의 로컬 [버스](/studynote/01_computer_architecture/09_system_bus_interconnects/344_bus/)에 직접 붙여, [운영체제](/studynote/02_operating_system/01_overview_architecture/001_operating_system_purpose/) ([Operating System](/studynote/02_operating_system/01_overview_architecture/001_operating_system_purpose/))가 거의 자기 내부 디스크처럼 다루게 만드는 가장 직접적인 스토리지 구조다.
> 2. **가치**: 중간 네트워크 계층이 없으므로 지연시간이 가장 짧고 경로가 단순해, [데이터베이스](/studynote/05_database/01_db_architecture_relational/002_database_definition/) [로그](/studynote/04_software_engineering/09_cloud_native_ai_architecture/568_logs_distributed_logging_elk_fluentd/)·임시 작업공간·고성능 로컬 캐시처럼 “바로 옆에서 빨리 읽고 써야 하는” 워크로드에 강하다.
> 3. **판단 포인트**: DAS는 빠르고 싸지만 공유성과 유연성이 약하다. 여러 서버가 같은 저장공간을 함께 써야 하거나 장애 시 즉시 다른 서버로 넘겨야 한다면 [NAS](/studynote/02_operating_system/08_storage_and_io_systems/492_nas_network_attached_storage/) ([Network Attached Storage](/studynote/02_operating_system/08_storage_and_io_systems/492_nas_network_attached_storage/))나 [SAN](/studynote/02_operating_system/08_storage_and_io_systems/493_san_storage_area_network/) ([Storage Area Network](/studynote/02_operating_system/08_storage_and_io_systems/493_san_storage_area_network/)), 혹은 [SDS](/studynote/01_computer_architecture/15_advanced_topics/632_sds/) (Software-Defined Storage) 계열을 함께 검토해야 한다.

---

## Ⅰ. 개요 및 필요성

DAS ([Direct](/studynote/01_computer_architecture/04_instruction_set_architecture/176_direct_addressing/) Attached Storage)는 서버나 워크스테이션에 저장장치를 직접 연결해 쓰는 구조다. 여기서 “직접”이라는 말의 핵심은 [데이터](/studynote/05_database/01_db_architecture_relational/001_dikw_pyramid/)가 [스위치](/studynote/03_network/05_lan_wan_l2_devices/238_switch_operation_principles/), 라우터, 원격 [파일](/studynote/02_operating_system/09_file_system/501_file_definition_logical_record/) 서버를 거치지 않고 [SATA](/studynote/01_computer_architecture/08_io_storage_systems/341_sata/) ([Serial ATA](/studynote/01_computer_architecture/08_io_storage_systems/341_sata/)), SAS ([Serial Attached SCSI](/studynote/01_computer_architecture/08_io_storage_systems/340_scsi_sas/)), [PCIe](/studynote/01_computer_architecture/09_system_bus_interconnects/356_pcie/) ([Peripheral Component Interconnect](/studynote/01_computer_architecture/09_system_bus_interconnects/355_pci/) Express) 같은 로컬 입출력 경로를 통해 곧바로 이동한다는 뜻이다. 그래서 [운영체제](/studynote/02_operating_system/01_overview_architecture/001_operating_system_purpose/)는 이 장치를 네트워크 공유 폴더가 아니라 로컬 블록 장치로 인식한다.

이 구조가 필요한 이유는 CPU (Central Processing Unit)와 메모리의 속도를 따라가기 위해서다. 특히 [데이터베이스](/studynote/05_database/01_db_architecture_relational/002_database_definition/)의 [로그](/studynote/04_software_engineering/09_cloud_native_ai_architecture/568_logs_distributed_logging_elk_fluentd/) 기록, 분석 작업의 스크래치 디스크, 가상머신의 임시 이미지처럼 짧은 지연시간과 높은 IOPS (Input/Output Operations Per Second)가 필요한 작업은 경로가 짧을수록 유리하다. 네트워크 스토리지는 유연성을 주지만, 패킷 처리·원격 제어·공유 [정책](/studynote/10_ai/02_dl_architecture_new/164_policy/)이라는 추가 비용이 붙는다. DAS는 그 비용을 지우고 “한 대의 서버가 자기 디스크를 가장 빠르게 쓰는 방식”에 집중한 선택이다.

이 그림은 DAS가 왜 빠르지만 동시에 왜 고립되기 쉬운지를 함께 보여준다.

```text
+----------------------------------------------------------------------+
|            DAS의 장점과 한계: 짧은 경로, 강한 종속성               |
+----------------------------------------------------------------------+
|  Server A                                                           |
|  +--------------+       PCIe / SAS / SATA        +---------------+  |
|  | CPU / Memory | ------------------------------> | Local Storage |  |
|  +--------------+                                 +---------------+  |
|          ^                                                   |       |
|          +---- OS가 직접 파일시스템·캐시·스케줄링 제어 -------+       |
|                                                                      |
|  Server B                                                           |
|  +--------------+                                 +---------------+  |
|  | CPU / Memory | ------------------------------> | Local Storage |  |
|  +--------------+                                 +---------------+  |
|                                                                      |
|  핵심: 각 서버는 자기 디스크에는 빠르게 접근하지만, 남의 디스크는     |
|       기본적으로 함께 쓰지 못한다.                                    |
+----------------------------------------------------------------------+
```

다이어그램의 포인트는 단순하다. [데이터](/studynote/05_database/01_db_architecture_relational/001_dikw_pyramid/) 경로가 짧아서 빠른 대신, 스토리지의 소유권이 서버에 강하게 묶인다. 즉 DAS는 “[성능](/studynote/04_software_engineering/05_devops_ci_cd/282_performance_tactics/)을 얻는 대신 공유를 포기하는” 구조에서 출발한다.

- **📢 섹션 요약 비유**: DAS는 내 책상 서랍과 같다. 손만 뻗으면 가장 빨리 꺼낼 수 있지만, 옆자리 동료가 그 서랍을 같이 쓰기는 어렵다.

## Ⅱ. 아키텍처 및 핵심 원리

DAS의 핵심 원리는 <strong>로컬 블록 접근</strong>이다. 애플리케이션이 읽기·쓰기를 요청하면 [운영체제](/studynote/02_operating_system/01_overview_architecture/001_operating_system_purpose/)가 [파일](/studynote/02_operating_system/09_file_system/501_file_definition_logical_record/) 시스템과 블록 계층을 거쳐 로컬 컨트롤러로 명령을 내리고, 저장장치는 그 명령을 즉시 수행한다. NAS처럼 원격 [파일](/studynote/02_operating_system/09_file_system/501_file_definition_logical_record/) [프로토콜](/studynote/03_network/06_network_layer_ip/295_protocol_field_tcp_udp_icmp/)을 번역할 필요도 없고, SAN처럼 별도 패브릭을 거쳐 [LUN](/studynote/01_computer_architecture/15_advanced_topics/685_lun_masking/) ([Logical Unit Number](/studynote/01_computer_architecture/15_advanced_topics/685_lun_masking/))을 매핑받을 필요도 없다. 그래서 경로가 짧고 제어 지점이 적다.

다만 DAS가 무조건 “디스크 한 개 직결”만 뜻하는 것은 아니다. 서버 내부의 [NVMe](/studynote/02_operating_system/08_storage_and_io_systems/482_nvme/) ([Non-Volatile Memory Express](/studynote/02_operating_system/08_storage_and_io_systems/482_nvme/)) [SSD](/studynote/01_computer_architecture/08_io_storage_systems/327_ssd/) ([Solid State Drive](/studynote/01_computer_architecture/08_io_storage_systems/327_ssd/)), [RAID](/studynote/02_operating_system/08_storage_and_io_systems/483_raid_overview/) (Redundant [Array](/studynote/08_algorithm_stats/04_datastructure/055_array/) of Independent Disks) 카드에 묶인 여러 개의 SAS 디스크, 외장 JBOD (Just a Bunch Of Disks) 확장함처럼 물리적으로는 다양한 형태가 가능하다. 중요한 것은 <strong>그 스토리지가 특정 호스트에 직접 귀속되어 있고, 그 호스트가 주된 제어권을 가진다</strong>는 점이다.

| 연결 방식 | 첫 의미 | 강점 | 주의점 |
| :-- | :-- | :-- | :-- |
| [SATA](/studynote/01_computer_architecture/08_io_storage_systems/341_sata/) ([Serial ATA](/studynote/01_computer_architecture/08_io_storage_systems/341_sata/)) | 범용 서버·PC용 직결 인터페이스 | 저렴하고 보급성 높음 | 대역폭과 큐 처리 한계 |
| SAS ([Serial Attached SCSI](/studynote/01_computer_architecture/08_io_storage_systems/340_scsi_sas/)) | 엔터프라이즈용 고신뢰 직결 인터페이스 | [이중 경로](/studynote/02_operating_system/08_storage_and_io_systems/500_multipath_io/), 안정성, 확장성 | 비용 상승 |
| [NVMe](/studynote/02_operating_system/08_storage_and_io_systems/482_nvme/) ([Non-Volatile Memory Express](/studynote/02_operating_system/08_storage_and_io_systems/482_nvme/)) over [PCIe](/studynote/01_computer_architecture/09_system_bus_interconnects/356_pcie/) | [초고속](/studynote/06_ict_convergence/02_iot_mobility/148_5g_embb_urllc_mmtc/) SSD용 저지연 인터페이스 | 낮은 지연시간, 높은 [병렬](/studynote/05_database/07_exam_summary/430_index_fast_full_scan/)성 | 발열·가격·슬롯 자원 고려 |

아래 그림은 DAS의 [데이터](/studynote/05_database/01_db_architecture_relational/001_dikw_pyramid/) 경로가 왜 짧은지, 그리고 병목이 어디서 결정되는지를 보여준다.

```text
+----------------------------------------------------------------------+
|                 DAS 데이터 경로와 병목 지점                          |
+----------------------------------------------------------------------+
|  Application                                                        |
|       |                                                              |
|       v                                                              |
|  File System / Page Cache                                            |
|       |                                                              |
|       v                                                              |
|  Block Layer / I/O Scheduler                                         |
|       |                                                              |
|       v                                                              |
|  HBA (Host Bus Adapter) / RAID Card / NVMe Controller                |
|       |                                                              |
|       v                                                              |
|  Local Media (SSD / HDD)                                             |
|                                                                      |
|  병목 판단:                                                          |
|  · HDD (Hard Disk Drive): 탐색 시간 + 회전 지연                      |
|  · SSD (Solid State Drive): 컨트롤러 병렬성 + 큐 깊이                |
|  · RAID 구성: 쓰기 증폭, 재구성 시간, 캐시 정책                      |
+----------------------------------------------------------------------+
```

이 구조에서 [성능](/studynote/04_software_engineering/05_devops_ci_cd/282_performance_tactics/)은 네트워크가 아니라 [매체](/studynote/03_network/03_physical_layer_media/121_transmission_media_guided_unguided/) 특성과 로컬 컨트롤러 설계가 좌우한다. HDD는 탐색 시간과 회전 지연이, SSD는 [병렬](/studynote/05_database/07_exam_summary/430_index_fast_full_scan/) 큐 처리와 플래시 관리가 [성능](/studynote/04_software_engineering/05_devops_ci_cd/282_performance_tactics/)을 결정한다. 따라서 DAS를 논할 때는 “직결이라 빠르다”에서 멈추지 말고, 어떤 인터페이스와 어떤 [매체](/studynote/03_network/03_physical_layer_media/121_transmission_media_guided_unguided/) 조합인지까지 봐야 한다.

- **📢 섹션 요약 비유**: DAS는 공장 안에 붙어 있는 전용 창고다. 복도만 건너면 되니 빠르지만, 창고 크기와 선반 구조가 곧 작업 속도를 결정한다.

## Ⅲ. 비교 및 연결

DAS를 제대로 이해하려면 NAS와 SAN을 함께 놓고 봐야 한다. 세 기술은 모두 “[데이터](/studynote/05_database/01_db_architecture_relational/001_dikw_pyramid/)를 어디에 두고 어떻게 접근할 것인가”에 답하지만, [성능](/studynote/04_software_engineering/05_devops_ci_cd/282_performance_tactics/)·공유성·운영 복잡도에서 서로 다른 철학을 갖는다. DAS는 가장 단순한 구조로 낮은 지연시간을 얻고, NAS는 [파일](/studynote/02_operating_system/09_file_system/501_file_definition_logical_record/) 공유를 쉽게 하며, SAN은 여러 서버가 원격 블록 장치를 유연하게 쓰게 만든다.

| 항목 | DAS ([Direct](/studynote/01_computer_architecture/04_instruction_set_architecture/176_direct_addressing/) Attached Storage) | [NAS](/studynote/02_operating_system/08_storage_and_io_systems/492_nas_network_attached_storage/) ([Network Attached Storage](/studynote/02_operating_system/08_storage_and_io_systems/492_nas_network_attached_storage/)) | [SAN](/studynote/02_operating_system/08_storage_and_io_systems/493_san_storage_area_network/) ([Storage Area Network](/studynote/02_operating_system/08_storage_and_io_systems/493_san_storage_area_network/)) |
| :-- | :-- | :-- | :-- |
| 접근 단위 | 블록 중심, 로컬 디스크처럼 사용 | [파일](/studynote/02_operating_system/09_file_system/501_file_definition_logical_record/) 단위 공유 | 블록 단위 원격 디스크 |
| 연결 방식 | 서버 로컬 [버스](/studynote/01_computer_architecture/09_system_bus_interconnects/344_bus/) 직결 | 일반 네트워크 | 전용 또는 [논리](/studynote/09_security/04_endpoint_security/369_logic_bomb/) 분리된 스토리지 네트워크 |
| 장점 | 가장 낮은 지연시간, 단순 구성, 낮은 비용 | 협업과 공유에 강함 | 멀티서버 유연성, 중앙 집중 관리 |
| 한계 | 공유성·이동성 약함 | 네트워크 병목, [프로토콜](/studynote/03_network/06_network_layer_ip/295_protocol_field_tcp_udp_icmp/) 오버헤드 | 비용·설계 복잡도 높음 |
| 대표 용도 | 단일 서버 DB, 캐시, 로컬 부트 디스크 | [파일](/studynote/02_operating_system/09_file_system/501_file_definition_logical_record/) 서버, 협업 스토리지 | [가상화](/studynote/13_cloud_architecture/01_virtualization/015_virtualization/) 클러스터, 미션 크리티컬 DB |

이 차이는 시스템 설계 전반으로 이어진다. [운영체제](/studynote/02_operating_system/01_overview_architecture/001_operating_system_purpose/) 관점에서 DAS는 로컬 [파일](/studynote/02_operating_system/09_file_system/501_file_definition_logical_record/) 시스템과 캐시 전략을 가장 단순하게 설계하게 해 주지만, 고가용성 (High [Availability](/studynote/01_computer_architecture/13_reliability_power_management/452_availability/))을 만들려면 별도 [복제](/studynote/14_data_engineering/01_infrastructure/016_replication_factor/)나 [백업](/studynote/02_operating_system/09_file_system/555_backup_and_restore_strategy/)이 필요하다. 반대로 SAN은 장애 조치와 자원 재배치를 쉽게 만들지만, 인프라 비용과 운영 난도가 따라온다. 최근에는 각 서버의 DAS를 소프트웨어로 묶는 [HCI](/studynote/01_computer_architecture/15_advanced_topics/630_hci/) (Hyper-Converged Infrastructure)와 SDS가 등장하면서, “물리적으로는 DAS지만 운영적으로는 공유 풀처럼 보이게” 만드는 방향으로 확장되고 있다.

즉 DAS는 과거 기술이 아니라, 오늘날 [분산](/studynote/08_algorithm_stats/08_stats/136_variance/) 스토리지의 출발점이자 재료다. 현대 클러스터는 여전히 로컬 [NVMe](/studynote/02_operating_system/08_storage_and_io_systems/482_nvme/) SSD를 많이 사용하며, 그 위에 [복제](/studynote/14_data_engineering/01_infrastructure/016_replication_factor/)·[분산](/studynote/08_algorithm_stats/08_stats/136_variance/)·장애복구 로직을 소프트웨어 계층으로 올린다.

- **📢 섹션 요약 비유**: DAS는 개인 자전거, NAS는 동네 공용 창고, SAN은 기업 물류센터에 가깝다. 어느 것이 더 좋다기보다, 얼마나 빨리 꺼내야 하는지와 얼마나 함께 써야 하는지가 선택을 가른다.

## Ⅳ. 실무 적용 및 기술사 판단

실무에서 DAS는 “한 서버가 높은 [성능](/studynote/04_software_engineering/05_devops_ci_cd/282_performance_tactics/)을 독점해야 하는가?”라는 질문에 가장 먼저 연결된다. 예를 들어 [데이터베이스](/studynote/05_database/01_db_architecture_relational/002_database_definition/) [트랜잭션](/studynote/05_database/04_transactions_concurrency/191_transaction_concept_states/) [로그](/studynote/04_software_engineering/09_cloud_native_ai_architecture/568_logs_distributed_logging_elk_fluentd/), 검색엔진 [인덱스](/studynote/05_database/03_relational_model/154_database_index_b_tree_search_optimization/), 대규모 정렬 작업의 임시 공간, [가상화](/studynote/13_cloud_architecture/01_virtualization/015_virtualization/) 호스트의 로컬 캐시 계층은 DAS가 매우 유효하다. 로컬 [NVMe](/studynote/02_operating_system/08_storage_and_io_systems/482_nvme/) SSD를 사용하면 수십 마이크로초 수준의 접근 지연과 매우 높은 IOPS를 기대할 수 있어, 네트워크 왕복이 들어가는 구조보다 유리하다.

반대로 여러 서버가 같은 [데이터](/studynote/05_database/01_db_architecture_relational/001_dikw_pyramid/)를 동시에 읽고 써야 하거나, 한 서버가 죽었을 때 다른 서버가 즉시 스토리지를 승계해야 하면 DAS 단독 구성은 위험하다. 서버 본체와 스토리지가 강하게 결합되어 있기 때문이다. 따라서 기술사 관점에서는 DAS를 채택할 때 <strong>장애 <a href="/studynote/09_security/13_secops_ir_forensics/658_ir_recovery/">복구</a> 방식, <a href="/studynote/02_operating_system/09_file_system/555_backup_and_restore_strategy/">백업</a> 주기, <a href="/studynote/14_data_engineering/01_infrastructure/016_replication_factor/">복제</a> 여부, 용량 확장 방식</strong>을 반드시 함께 제시해야 한다.

### 판단 [체크리스트](/studynote/04_software_engineering/11_testing_validation/435_checklist_based_testing/)

1. **지연시간 우선인가, 공유 우선인가?** 지연시간이 절대 기준이면 DAS가 우세하다.
2. **장애 시 다른 서버로 즉시 넘겨야 하는가?** 그렇다면 DAS 단독보다는 공유 스토리지나 [복제](/studynote/14_data_engineering/01_infrastructure/016_replication_factor/) 설계가 필요하다.
3. **용량 증설이 서버별로 따로 놀아도 괜찮은가?** 그렇지 않으면 장기적으로 [사일로](/studynote/15_devops_sre/01_culture_methodology/002_silo_hyeonhyung/) 문제가 생긴다.
4. <strong><a href="/studynote/02_operating_system/09_file_system/555_backup_and_restore_strategy/">백업</a>과 <a href="/studynote/09_security/13_secops_ir_forensics/658_ir_recovery/">복구</a> 시간을 감당할 수 있는가?</strong> 빠른 로컬 저장이 곧 빠른 [복구](/studynote/09_security/13_secops_ir_forensics/658_ir_recovery/)를 의미하지는 않는다.

### 대표 [안티패턴](/studynote/04_software_engineering/02_requirements_analysis/128_water_scrum_fall_anti_pattern/)

- 단일 중요 [데이터베이스](/studynote/05_database/01_db_architecture_relational/002_database_definition/) ([Database](/studynote/05_database/04_transactions_concurrency/501_database/))를 DAS 한 대에만 두고 장애 조치 설계를 생략하는 구성
- 팀 단위 공유 [데이터](/studynote/05_database/01_db_architecture_relational/001_dikw_pyramid/)를 DAS에 두고 운영자가 수작업 복사로 협업을 해결하려는 구성
- [NVMe](/studynote/02_operating_system/08_storage_and_io_systems/482_nvme/) [성능](/studynote/04_software_engineering/05_devops_ci_cd/282_performance_tactics/)만 보고 도입했지만 발열, 슬롯 수, [RAID](/studynote/02_operating_system/08_storage_and_io_systems/483_raid_overview/) [정책](/studynote/10_ai/02_dl_architecture_new/164_policy/), [백업](/studynote/02_operating_system/09_file_system/555_backup_and_restore_strategy/) 체계를 검토하지 않은 구성

핵심은 DAS가 [성능](/studynote/04_software_engineering/05_devops_ci_cd/282_performance_tactics/) 문제의 만능 해답이 아니라는 점이다. DAS는 <strong>짧은 경로를 사는 기술</strong>이지, <strong>공유·<a href="/studynote/09_security/13_secops_ir_forensics/658_ir_recovery/">복구</a>·이동 문제까지 자동 해결하는 기술</strong>은 아니다.

- **📢 섹션 요약 비유**: DAS는 스포츠카와 같다. 혼자 빠르게 달리기엔 최고지만, 이삿짐 운반과 단체 이동까지 맡기면 금방 한계가 드러난다.

## Ⅴ. 기대효과 및 결론

DAS를 적절히 쓰면 시스템은 단순해지고 예측 가능해진다. [데이터](/studynote/05_database/01_db_architecture_relational/001_dikw_pyramid/) 경로가 짧아 [성능](/studynote/04_software_engineering/05_devops_ci_cd/282_performance_tactics/) 튜닝 포인트가 명확하고, 네트워크 혼잡의 영향을 적게 받아 안정적인 로컬 처리 [성능](/studynote/04_software_engineering/05_devops_ci_cd/282_performance_tactics/)을 확보할 수 있다. 또한 동일 [성능](/studynote/04_software_engineering/05_devops_ci_cd/282_performance_tactics/) 기준으로 비교하면 대체로 구축 비용이 낮아, 고성능 단일 서버나 엣지 장비, 분석 노드에 매우 실용적이다.

하지만 기대효과는 전제조건이 맞을 때만 성립한다. 서버 간 공유가 중요하거나 스토리지를 서비스처럼 재배치해야 하는 환경에서는 DAS의 강점이 약점으로 뒤집힌다. 그래서 현대 아키텍처는 DAS를 버리기보다, DAS 위에 [복제](/studynote/14_data_engineering/01_infrastructure/016_replication_factor/)·[분산 파일 시스템](/studynote/02_operating_system/09_file_system/553_distributed_file_system/)·오케스트레이션을 얹어 한계를 보완하는 방향으로 진화하고 있다.

결론적으로 DAS는 “가장 원초적이지만 여전히 강력한 스토리지 기본형”으로 기억하는 것이 맞다. 스토리지를 서버 가까이에 둘수록 빠르지만, 가까울수록 그 서버와 운명을 같이한다는 사실까지 함께 기억해야 한다.

- **📢 섹션 요약 비유**: DAS는 집 안 금고와 같다. 가장 빨리 열 수 있지만, 가족 전체 자산을 운영하려면 금고만이 아니라 복사본, 보험, 공동 접근 규칙까지 같이 준비해야 한다.

### 📈 관련 키워드 및 발전 흐름도

```text
로컬 디스크 직결
    |
    v
DAS (Direct Attached Storage)
    |
    +- 성능·저지연 강화 --> SAS / NVMe / RAID 고도화
    |
    +- 공유성 요구 확대 --> NAS (파일 공유) / SAN (원격 블록 공유)
    |
    +- 분산 운영 확장 --> SDS / HCI / NVMe-oF (NVMe over Fabrics)
```

이 흐름은 DAS가 끝난 기술이 아니라, 이후 스토리지 아키텍처가 무엇을 보완하려 했는지 보여준다. 출발점은 늘 “로컬은 빠르다”이고, 이후의 발전은 그 빠름을 얼마나 공유 가능하게 만들 것인가에 대한 답변이다.

### 👶 어린이를 위한 3줄 비유 설명

1. DAS는 내 책상에 딱 붙어 있는 개인 서랍이라서 물건을 제일 빨리 꺼낼 수 있어요.
2. 하지만 그 서랍은 내 자리 것이라서 친구랑 같이 쓰거나 멀리서 빌려 쓰기는 어려워요.
3. 그래서 빨리 써야 할 물건은 서랍에 넣고, 같이 써야 할 물건은 공용 보관함에 두는 거예요.
