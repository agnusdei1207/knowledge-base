## 핵심 인사이트 (3줄 요약)

> 1. **본질**: TDI는 기밀 VM이나 신뢰 [도메인](/studynote/05_database/02_modeling_normalization/064_relation_domain/)과 [PCIe](/studynote/01_computer_architecture/09_system_bus_interconnects/356_pcie/)/[CXL](/studynote/01_computer_architecture/12_accelerators_ai_hardware/441_cxl/) 장치 사이의 I/O 경로를 [보호](/studynote/02_operating_system/10_security/571_protection_vs_security/)하기 위해, 장치 [인증](/studynote/04_software_engineering/05_devops_ci_cd/303_authentication_authorization_patterns/)과 링크 암호화를 결합하는 신뢰 [도메인](/studynote/05_database/02_modeling_normalization/064_relation_domain/)용 인터커넥트 개념이다.
> 2. **가치**: CPU와 메모리만 [보호](/studynote/02_operating_system/10_security/571_protection_vs_security/)하는 기밀 컴퓨팅의 한계를 넘어, [GPU](/studynote/01_computer_architecture/12_accelerators_ai_hardware/418_gpu/)·SmartNIC·가속기 쪽으로 신뢰 경계를 확장한다는 점에서 의미가 크다.
> 3. **판단 포인트**: 핵심 판단은 [SR-IOV](/studynote/02_operating_system/08_storage_and_io_systems/497_sr_iov_pcie_mapping/) 같은 [성능](/studynote/04_software_engineering/05_devops_ci_cd/282_performance_tactics/) 지향 가상 I/O에 비해 어떤 보안 가치를 얻는지, 그리고 SPDM·TDISP·IDE 같은 [프로토콜](/studynote/03_network/06_network_layer_ip/295_protocol_field_tcp_udp_icmp/) 복잡도를 감당할지에 있다.

---

## Ⅰ. 개요 및 필요성

기밀 VM이 CPU와 메모리 안에서는 안전해도, 외부 장치와 [데이터](/studynote/05_database/01_db_architecture_relational/001_dikw_pyramid/)를 주고받는 순간 하이퍼바이저나 중간 I/O 경로가 평문을 볼 수 있다면 [보호](/studynote/02_operating_system/10_security/571_protection_vs_security/) 경계는 끊긴다. TDI는 바로 이 끊어진 경계를 다시 잇기 위한 개념이다. 즉 "[보호](/studynote/02_operating_system/10_security/571_protection_vs_security/)된 메모리에서 [보호](/studynote/02_operating_system/10_security/571_protection_vs_security/)된 장치까지" 신뢰를 확장하려는 것이다. [AI](/studynote/04_software_engineering/03_design_architecture/190_ai_llm_requirements_specification/) 가속기와 [CXL](/studynote/01_computer_architecture/12_accelerators_ai_hardware/441_cxl/) 메모리 확장이 늘어나는 환경에서는 이 I/O 경로 보안이 점점 더 중요해진다.

```text
+--------------------------------------------------------------+
|      Trusted domain needs secure path all the way out       |
+--------------------------------------------------------------+
| TD / confidential VM -> host fabric -> device               |
|                 |                       |                    |
|       without TDI: host can inspect     with TDI: protected |
+--------------------------------------------------------------+
```

- **📢 섹션 요약 비유**: 방 안 금고는 튼튼한데, 금고에서 은행 차량으로 옮기는 복도가 뚫려 있으면 의미가 줄어든다. TDI는 그 복도까지 장갑화하는 일이다.

---

## Ⅱ. 아키텍처 및 핵심 원리

TDI를 설명할 때는 보통 SPDM ([Security](/studynote/04_software_engineering/05_devops_ci_cd/283_security_tactics/) [Protocol](/studynote/03_network/06_network_layer_ip/295_protocol_field_tcp_udp_icmp/) and [Data Model](/studynote/05_database/01_db_architecture_relational/014_data_model_components/)) 기반 장치 [인증](/studynote/04_software_engineering/05_devops_ci_cd/303_authentication_authorization_patterns/), TDISP ([TEE](/studynote/01_computer_architecture/14_hardware_security_trends/478_tee/) Device Interface [Security](/studynote/04_software_engineering/05_devops_ci_cd/283_security_tactics/) [Protocol](/studynote/03_network/06_network_layer_ip/295_protocol_field_tcp_udp_icmp/)) 기반 [도메인](/studynote/05_database/02_modeling_normalization/064_relation_domain/)-장치 연결, [PCIe](/studynote/01_computer_architecture/09_system_bus_interconnects/356_pcie/)/[CXL](/studynote/01_computer_architecture/12_accelerators_ai_hardware/441_cxl/) IDE ([Integrity](/studynote/09_security/01_intro_principles/003_integrity/) and [Data](/studynote/05_database/01_db_architecture_relational/001_dikw_pyramid/) Encryption) 기반 링크 [보호](/studynote/02_operating_system/10_security/571_protection_vs_security/)를 함께 본다. 먼저 장치가 신뢰 가능한 펌웨어와 [인증](/studynote/04_software_engineering/05_devops_ci_cd/303_authentication_authorization_patterns/)서를 갖췄는지 [확인](/studynote/04_software_engineering/12_testing_maintenance/396_validation/)하고, 이후 [세션 키](/studynote/09_security/03_network_security/140_session_key/)를 수립한 뒤 링크 계층에서 [데이터](/studynote/05_database/01_db_architecture_relational/001_dikw_pyramid/) [기밀성](/studynote/09_security/01_intro_principles/002_confidentiality/)과 [무결성](/studynote/09_security/01_intro_principles/003_integrity/)을 보장한다. 따라서 TDI의 본질은 하나의 단일 장치가 아니라, "장치 신원 [확인](/studynote/04_software_engineering/12_testing_maintenance/396_validation/) + 링크 암호화 + [도메인](/studynote/05_database/02_modeling_normalization/064_relation_domain/) 할당" 세 단계가 묶인 체계라는 점이다.

| 구성 요소 | 역할 | 설계 포인트 |
| :--- | :--- | :--- |
| SPDM | 장치 [인증](/studynote/04_software_engineering/05_devops_ci_cd/303_authentication_authorization_patterns/)·측정 교환 | [인증](/studynote/04_software_engineering/05_devops_ci_cd/303_authentication_authorization_patterns/)서 체인과 신뢰 루트 관리 |
| TDISP | [도메인](/studynote/05_database/02_modeling_normalization/064_relation_domain/)과 장치 연결 [설정](/studynote/15_devops_sre/01_culture_methodology/009_config/) | 상태 전이와 권한 관리 |
| IDE | [PCIe](/studynote/01_computer_architecture/09_system_bus_interconnects/356_pcie/)/[CXL](/studynote/01_computer_architecture/12_accelerators_ai_hardware/441_cxl/) 링크 암호화·[무결성](/studynote/09_security/01_intro_principles/003_integrity/) | [세션 키](/studynote/09_security/03_network_security/140_session_key/)·재동기화 처리 |
| [IOMMU](/studynote/02_operating_system/10_security/627_iommu_dma_isolation/) / [Domain](/studynote/05_database/02_modeling_normalization/064_relation_domain/) Control | [DMA](/studynote/02_operating_system/11_exam_summary/746_io_direct_memory_access_dma/) 경로 제한 | 메모리 소유권과 [일관성](/studynote/05_database/04_transactions_concurrency/194_consistency_database_integrity/) 유지 |

```text
+--------------------------------------------------------------+
|             Device trust establishment for TDI              |
+--------------------------------------------------------------+
| SPDM auth -> TDISP bind -> IDE secure link -> DMA allowed   |
|                                                              |
| Only authenticated device gets protected path to TD         |
+--------------------------------------------------------------+
```

- **📢 섹션 요약 비유**: VIP 전용 배송차를 [쓰기](/studynote/13_cloud_architecture/05_data_engineering/289_cqrs_db/) 전에 운전기사 신분 [확인](/studynote/04_software_engineering/12_testing_maintenance/396_validation/), 배송 계약 체결, 봉인 테이프 부착을 순서대로 하는 것과 같다. 하나만 빠져도 안전 배송이 아니다.

## Ⅲ. 비교 및 연결

TDI는 전통적 SR-IOV보다 보안 목표가 훨씬 높다. SR-IOV와 VT-d는 주로 [성능](/studynote/04_software_engineering/05_devops_ci_cd/282_performance_tactics/)과 주소 격리에 초점을 두지만, TDI는 하이퍼바이저를 완전히 신뢰하지 않는 모델에서 장치 자체의 신뢰성과 링크 [기밀성](/studynote/09_security/01_intro_principles/002_confidentiality/)까지 요구한다. 따라서 [성능](/studynote/04_software_engineering/05_devops_ci_cd/282_performance_tactics/) 오버헤드는 조금 늘어도, 민감 모델 파라미터나 금융 [데이터](/studynote/05_database/01_db_architecture_relational/001_dikw_pyramid/)가 가속기로 이동하는 환경에서는 얻는 보안 가치가 크다.

| 비교 대상 | 강점 | 대표 한계 |
| :--- | :--- | :--- |
| [SR-IOV](/studynote/02_operating_system/08_storage_and_io_systems/497_sr_iov_pcie_mapping/) / VT-d | [성능](/studynote/04_software_engineering/05_devops_ci_cd/282_performance_tactics/) 좋은 가상 I/O | 평문 I/O 경로 [보호](/studynote/02_operating_system/10_security/571_protection_vs_security/)는 제한적 |
| TDI | 장치 신뢰성과 링크 [보호](/studynote/02_operating_system/10_security/571_protection_vs_security/)까지 확장 | [프로토콜](/studynote/03_network/06_network_layer_ip/295_protocol_field_tcp_udp_icmp/)/운영 복잡도 증가 |
| 전용 외부 [HSM](/studynote/01_computer_architecture/14_hardware_security_trends/475_hsm/) 경유 | 강한 분리 | [데이터](/studynote/05_database/01_db_architecture_relational/001_dikw_pyramid/) 이동 비용과 구조 복잡도 큼 |

- **📢 섹션 요약 비유**: 고속도로 전용 차선은 빠르지만, 귀중품 수송에는 봉인 차량과 신원 [확인](/studynote/04_software_engineering/12_testing_maintenance/396_validation/)이 추가로 필요한 것과 같다.

---

## Ⅳ. 실무 적용 및 기술사 판단

실무에서는 confidential VM이 GPU나 SmartNIC을 사용할 때 TDI 계열 구조가 중요해진다. 기술사 답안에서는 첫째 장치 펌웨어와 [인증](/studynote/04_software_engineering/05_devops_ci_cd/303_authentication_authorization_patterns/)서 체인을 누가 검증하는지, 둘째 링크 [보호](/studynote/02_operating_system/10_security/571_protection_vs_security/)가 재부팅·리셋 후 어떻게 복구되는지, 셋째 장치 공유 모드에서 테넌트 간 [DMA](/studynote/02_operating_system/11_exam_summary/746_io_direct_memory_access_dma/) 간섭이 어떻게 차단되는지를 써야 한다. 또한 TDI는 아직 생태계 성숙도가 완전하지 않으므로, [성능](/studynote/04_software_engineering/05_devops_ci_cd/282_performance_tactics/)과 보안 요구가 모두 큰 구간에 우선 적용하는 전략이 현실적이다.

- **📢 섹션 요약 비유**: 귀중품 수송에 모든 택배차를 장갑차로 바꿀 필요는 없지만, 정말 중요한 물건을 나를 때는 장갑차와 신분 [확인](/studynote/04_software_engineering/12_testing_maintenance/396_validation/) 절차가 꼭 필요하다.

---

## Ⅴ. 기대효과 및 결론

TDI는 기밀 컴퓨팅을 CPU·메모리 울타리 안에 가두지 않고, I/O 장치까지 실제 업무 경계로 확장하는 데 의미가 있다. 이 방향이 자리 잡아야만 [GPU](/studynote/01_computer_architecture/12_accelerators_ai_hardware/418_gpu/) 중심 [AI](/studynote/04_software_engineering/03_design_architecture/190_ai_llm_requirements_specification/), [CXL](/studynote/01_computer_architecture/12_accelerators_ai_hardware/441_cxl/) [메모리 풀](/studynote/02_operating_system/06_memory_management/369_memory_pool/), 스마트 네트워크 가속기 시대에도 "실행 중 [데이터](/studynote/05_database/01_db_architecture_relational/001_dikw_pyramid/) [보호](/studynote/02_operating_system/10_security/571_protection_vs_security/)"가 완성된다. 앞으로는 장치 측 원격 증명과 표준화된 confidential I/O 스택이 더 중요해질 것이다. 결국 TDI는 "[보호](/studynote/02_operating_system/10_security/571_protection_vs_security/)된 [VM](/studynote/01_computer_architecture/15_advanced_topics/598_vm_migration_nic/)"에서 끝나지 않고 "[보호](/studynote/02_operating_system/10_security/571_protection_vs_security/)된 [데이터](/studynote/05_database/01_db_architecture_relational/001_dikw_pyramid/) 경로"까지 완성하려는 다음 단계로 이해하는 것이 좋다.

- **📢 섹션 요약 비유**: 집 안 금고를 지키는 것에서 한 걸음 더 나아가, 금고와 차고 사이의 복도까지 잠그는 보안이라고 생각하면 된다.

### 📈 관련 키워드 및 발전 흐름도

```text
[Device Authentication]
    |
    v
[TDISP Domain Binding]
    |
    v
[IDE Protected Link]
    |
    +---> [Secure DMA Path]
    +---> [Confidential Device Use]
```

이 흐름은 장치 [인증](/studynote/04_software_engineering/05_devops_ci_cd/303_authentication_authorization_patterns/)에서 시작한 신뢰가 [도메인](/studynote/05_database/02_modeling_normalization/064_relation_domain/) 바인딩과 링크 [보호](/studynote/02_operating_system/10_security/571_protection_vs_security/)를 거쳐 안전한 [DMA](/studynote/02_operating_system/11_exam_summary/746_io_direct_memory_access_dma/) 경로로 이어지는 구조를 보여준다. 즉 TDI는 I/O 경로 전체를 하나의 신뢰 사슬로 본다.

### 👶 어린이를 위한 3줄 비유 설명

1. 비밀 짐을 트럭에 싣고 옮길 때, 트럭 기사 [확인](/studynote/04_software_engineering/12_testing_maintenance/396_validation/)도 하고 상자에도 봉인을 붙이는 것과 비슷해요.
2. 컴퓨터도 비밀 자료를 다른 장치로 보낼 때 그냥 보내지 않고, 믿을 수 있는 장치인지 먼저 [확인](/studynote/04_software_engineering/12_testing_maintenance/396_validation/)해요.
3. 그래서 중간 길목에 있는 나쁜 사람이 내용을 훔쳐보기 더 어려워져요.
