> **핵심 인사이트**
> 1. ZTA([Zero Trust Architecture](/knowledge-base/studynote/12_it_management/05_security_compliance/184_zero_trust_architecture/))는 NIST [SP](/knowledge-base/studynote/01_computer_architecture/04_instruction_set_architecture/166_sp/) 800-207이 정의한 구체적 구현 아키텍처 — "[제로 트러스트](/knowledge-base/studynote/02_operating_system/10_security/667_zero_trust_runtime_integrity_measurement/)"가 원칙이라면 ZTA는 [정책](/knowledge-base/studynote/10_ai/02_dl_architecture_new/164_policy/) 결정 지점(PDP), [정책](/knowledge-base/studynote/10_ai/02_dl_architecture_new/164_policy/) 시행 지점(PEP), [정책](/knowledge-base/studynote/10_ai/02_dl_architecture_new/164_policy/) 엔진(PE)의 3요소로 구성된 실제 구현 모델이다.
> 2. ZTA의 핵심은 [정책](/knowledge-base/studynote/10_ai/02_dl_architecture_new/164_policy/) 엔진([Policy](/knowledge-base/studynote/10_ai/02_dl_architecture_new/164_policy/) Engine)의 동적 신뢰 점수 계산 — 사용자 ID, 디바이스 상태, 위치, 시간, 행동 분석을 종합해 매 요청마다 실시간으로 신뢰 점수를 산출하고 접근 여부를 결정하는 지속적 평가(Continuous Evaluation)가 핵심이다.
> 3. ZTA 구현의 7가지 원칙 — NIST는 ① 모든 [데이터](/knowledge-base/studynote/05_database/01_db_architecture_relational/001_dikw_pyramid/) 소스/서비스를 리소스로 간주, ② 통신 보안은 네트워크 위치와 무관, ③ 세션별 접근 허가, ④ 동적 [정책](/knowledge-base/studynote/10_ai/02_dl_architecture_new/164_policy/), ⑤ 모든 자산 모니터링, ⑥ 동적 엄격한 [인증](/knowledge-base/studynote/04_software_engineering/05_devops_ci_cd/303_authentication_authorization_patterns/), ⑦ 현재 상태에서 점진적 개선을 원칙으로 제시한다.

## Ⅱ. 신뢰 점수 계산



<div class="kb-diagram" data-diagram="ascii-converted">
<div class="kb-diagram-flow">
<div class="kb-diagram-note">동적 신뢰 점수 (Dynamic Trust Score):</div>

<div class="kb-diagram-note">디바이스 상태 (Device Health):</div>

<div class="kb-diagram-note">EDR 활성 여부 (+/- 10점)</div>
<div class="kb-diagram-note">디스크 암호화 여부 (+/- 5점)</div>
<div class="kb-diagram-note">알려진 CVE 취약점 (-15점)</div>
<div class="kb-diagram-note">기여 점수: 0~25점</div>
<div class="kb-diagram-note">네트워크/위치 (Network/Location):</div>
<div class="kb-diagram-note">IP 평판 점수</div>
<div class="kb-diagram-note">일반 접속 위치 여부 (+/- 15점)</div>
<div class="kb-diagram-note">VPN 사용 여부</div>
<div class="kb-diagram-note">비정상 국가 (-20점)</div>
<div class="kb-diagram-note">기여 점수: 0~25점</div>
<div class="kb-diagram-note">행동 분석 (Behavior Analytics):</div>
<div class="kb-diagram-note">평소 접속 시간대 여부</div>
<div class="kb-diagram-note">접근 리소스 패턴 일치</div>
<div class="kb-diagram-note">이상 행위 (대량 다운로드, 야간 접속)</div>
<div class="kb-diagram-note">기여 점수: 0~20점</div>
<div class="kb-diagram-note">신뢰 점수 = ID + 디바이스 + 네트워크 + 행동</div>
<div class="kb-diagram-note">범위: 0~100점</div>
<div class="kb-diagram-note">정책:</div>
<div class="kb-diagram-note">70점 이상: 접근 허용</div>
<div class="kb-diagram-note">40~70점: 추가 MFA 요구</div>
<div class="kb-diagram-note">40점 미만: 접근 거부 + 보안팀 알림</div>
<div class="kb-diagram-note">예시:</div>
<div class="kb-diagram-note">MFA OK(30) + 최신 패치(25) + 사무실 IP(20) + 정상(20)</div>
<div class="kb-diagram-note">= 95점 → 즉시 허용</div>
<div class="kb-diagram-note">MFA OK(30) + 취약점 있음(10) + 해외 IP(-5) + 야간(-5)</div>
<div class="kb-diagram-note">= 30점 → 거부 + 알림</div>
</div>
</div>



> 📢 **섹션 요약 비유**: 신뢰 점수는 여행자 신용 점수 — ID(여권), 디바이스(건강 증명서), 위치(일반 경로), 행동(의심스럽지 않음). 70점 이상만 입국!

## Ⅲ. ZTA 구현 배포 모델



<div class="kb-diagram" data-diagram="ascii-converted">
<div class="kb-diagram-flow">
<div class="kb-diagram-note">NIST SP 800-207 배포 모델:</div>
<div class="kb-diagram-note">1. 에이전트 기반 (Agent/Gateway):</div>
<div class="kb-diagram-note">디바이스에 에이전트 설치</div>
<div class="kb-diagram-note">에이전트 ↔ PEP(게이트웨이) ↔ 리소스</div>
<div class="kb-diagram-note">장점: 세밀한 디바이스 제어</div>
<div class="kb-diagram-note">단점: 에이전트 설치 필요 (BYOD 어려움)</div>
<div class="kb-diagram-note">도구: CrowdStrike, Zscaler ZPA</div>
<div class="kb-diagram-note">2. 마이크로세그멘테이션:</div>
<div class="kb-diagram-note">네트워크 내부를 작은 구역으로 분리</div>
<div class="kb-diagram-note">각 구역 간 PEP 배치</div>
<div class="kb-diagram-note">장점: 기존 인프라 재사용</div>
<div class="kb-diagram-note">단점: 네트워크 재설계 필요</div>
<div class="kb-diagram-note">도구: Illumio, VMware NSX</div>
<div class="kb-diagram-note">3. SDP (Software-Defined Perimeter):</div>
<div class="kb-diagram-note">사용자가 리소스 "보기" 전에 인증</div>
<div class="kb-diagram-note">인증 전 리소스 IP 노출 안 함</div>
<div class="kb-diagram-note">Cloud SPA (Single Packet Authorization):</div>
<div class="kb-diagram-note">첫 패킷으로 인증 → 포트 개방</div>
<div class="kb-diagram-note">도구: Cloudflare Access, Appgate SDP</div>
<div class="kb-diagram-note">4. ZTNA (Zero Trust Network Access):</div>
<div class="kb-diagram-note">VPN 대체 솔루션</div>
<div class="kb-diagram-note">사용자 → ZTNA 클라이언트 → ZTNA 서비스 → 앱</div>
<div class="kb-diagram-note">앱별 개별 터널 (VPN과 달리 전체망 X)</div>
<div class="kb-diagram-note">도구: Zscaler Private Access (ZPA)</div>
<div class="kb-diagram-note">Cloudflare WARP, Palo Alto Prisma</div>
<div class="kb-diagram-note">5. CASB (Cloud Access Security Broker):</div>
<div class="kb-diagram-note">SaaS 앱 접근 중간 제어</div>
<div class="kb-diagram-note">Microsoft 365, Salesforce 등</div>
<div class="kb-diagram-note">Shadow IT 탐지</div>
<div class="kb-diagram-note">도구: Netskope, MCAS (Microsoft)</div>
<div class="kb-diagram-note">선택 기준:</div>
<div class="kb-diagram-note">레거시 많은 기업: 마이크로세그멘테이션</div>
<div class="kb-diagram-note">원격 근무 중심: ZTNA</div>
<div class="kb-diagram-note">SaaS 의존: CASB</div>
</div>
</div>



> 📢 **섹션 요약 비유**: ZTA 배포 모델은 경비 시스템 종류 — 에이전트(개인 경호원), 마이크로세그멘테이션(건물 구역 경비), [ZTNA](/knowledge-base/studynote/12_it_management/05_security_compliance/339_ztna/)(개인 통로), [CASB](/knowledge-base/studynote/03_network/14_network_security_threats/741_casb_cloud_access_security_broker/)(외부 건물 [접근 통제](/knowledge-base/studynote/04_software_engineering/06_software_architecture/387_access_control_pattern/)). 상황에 맞는 경비 선택!

> 📢 **섹션 요약 비유**: 연방 ZTA는 정부청사 전체 보안 리모델링 — 모든 출입구(PEP), 생체인식([MFA](/knowledge-base/studynote/09_security/11_iam_access_control/552_mfa/)), 구역별 잠금(마이크로세그멘테이션). 수백 개 청사를 동시에. 7년 대공사!

## 👶 어린이를 위한 3줄 비유 설명

1. ZTA 3요소는 공항 보안 — 보안 시스템(PE: 위험 판단), 직원(PA: 판단 전달), 게이트(PEP: 실제 통과/차단). 매 탑승마다 재검사!
2. 신뢰 점수는 여행자 평점 — ID+디바이스+위치+행동을 합산. 70점 이상만 통과. 나쁜 디바이스(취약점)나 이상한 위치(해외 IP)면 점수 감소!
3. ZTA 성숙도는 무술 단계 — 흰 띠(비밀번호만)에서 검은 띠([AI](/knowledge-base/studynote/04_software_engineering/03_design_architecture/190_ai_llm_requirements_specification/) 지속 [인증](/knowledge-base/studynote/04_software_engineering/05_devops_ci_cd/303_authentication_authorization_patterns/))까지. 한 번에 검은 띠 불가, 단계별 향상!
