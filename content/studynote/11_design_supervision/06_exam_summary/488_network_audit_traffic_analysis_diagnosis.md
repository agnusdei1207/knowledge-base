## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 네트워크 감리 트래픽 분석 진단은 패킷 캡처(PCAP), 플로우 분석(NetFlow/sFlow/IPFIX), SNMP 폴링, 활성 프로빙(Active Probing)의 4대 기법을 결합하여 OSI 2~7계층의 트래픽 정상성·병목·이상행위를 정량·정성적으로 진단하는 종합 기법으로, KPI(throughput, latency, jitter, packet loss, retransmission)와 KT(트래픽) 진단 기준에 부합하는지 감리한다.
> 2. **가치**: 사전 구축 단계에서 설계된 대역폭·QoS·라우팅 정책이 운영 단계에서 SLA(99.9% 가용성, RTT ≤ 50ms, 패킷손실 ≤ 0.1%)를 충족하는지 객관 검증하여, 감리 완료 후 1년 내 평균 35% 이상의 장애 감소 및 MTTR(평균복구시간) 40% 단축 효과를 달성한다.
> 3. **판단 포인트**: 핵심 트레이드오프는 (a) 패킷 캡처의 정밀도 vs. 미러링 비용·저장 부담, (b) 플로우 분석의 확장성 vs. L7 페이로드 가시성 부재, (c) 상시 모니터링 vs. 감리 시점의 스냅샷 검증 사이의 균형이며, 이를 위해 TAP/SPAN 포트 배치, 샘플링 비율(1:1000~1:10000), 분석 도구(Wireshark, nfdump, NTA, NDR) 선정이 결정적 설계 인자이다.

## Ⅰ. 개요 및 필요성

정보통신망법 제46조(감리) 및 동법 시행령 제60조에 의거하여 일정 규모 이상의 정보통신망을 구축하는 사업자는 발주청이 지정하는 감리원의 감리를 받아야 하며, 이때 **트래픽 분석 및 진단**은 감리 3대 영역(설계 적정성, 시공 적정성, 성능 적정성) 중 **성능 적정성**을 입증하는 핵심 절차이다. 감리는 단순한 서류심사가 아니라, 구축된 망이 (1) 설계 시 산정한 트래픽 수용 용량(예: 동시사용자 1,000명, 피크 트래픽 800Mbps)을 실제로 처리할 수 있는지, (2) 응용 계층의 트랜잭션 응답시간이 SLA 기준(예: 웹 페이지 TTFB ≤ 200ms, DB 쿼리 ≤ 50ms)을 충족하는지, (3) 보안 정책(IPS/IDS, DDoS 차단, 비인가 트래픽) 및 QoS 정책(Voice/Video 우선순위)이 정상 동작하는지를 **실측 데이터**로 증명해야 하는 절차이다.

과거(2000년대 초)에는 ping, traceroute, SNMP 단순 폴링에 의존해 가용성·지연만 확인하는 "단순 점검" 수준에 머물렀으나, 클라우드·SaaS·실시간 화상회의(Zoom/Webex)·IoT 트래픽이 폭증하면서, (a) L7 애플리케이션 단위의 가시성(애플리케이션 인지), (b) east-west 데이터센터 내부 트래픽 분석, (c) 암호화(HTTPS/TLS 1.3, QUIC) 트래픽의 메타데이터 기반 분석, (d) 머신러닝 기반 이상행위 탐지가 필수로 부상했다.

```text
        |                  |   | 트래픽 미러링  |   |   +----------+
```

전통적 방법론 대비 현대 감리 트래픽 분석은 **① 시계열 분석**(장기 트렌드), **② 베이스라인 편차 분석**(정상 트래픽 패턴 대비 이상), **③ 시나리오 기반 부하시험**(Stress/Soak/Spike Test), **④ 다차원 상관분석**(대역폭-지연-패킷손실-재전송률의 4대 KPI 상관관계)이라는 4축 분석 체계를 채택한다.

- **📢 섹션 요약 비유**: 네트워크 감리 트래픽 분석은 새로 지은 다리(망)에 트럭을 실제 통과시켜 진동·처짐·하중을 측정하는 "내하력 시험(Load Test)"과 같다. 설계도상 견딜 수 있다고 적혀 있어도, 실제로 40톤 트럭이 지나가는 순간 진동 센서·변위계·스트레인 게이지를 통해 객관 수치를 뽑아내야 비로소 안전하다고 인증할 수 있다.

## Ⅱ. 아키텍처 및 핵심 원리

네트워크 감리 트래픽 분석 진단 시스템은 **수집(Collector) -> 저장(Storage) -> 분석(Analytics) -> 시각화(Visualization) -> 보고(Reporting)**의 5계층 파이프라인으로 구성된다. 각 계층은 독립적으로 스케일링되어야 하며, 감리 시점의 일회성 진단과 상시 운영 모니터링의 이중 목적을 모두 충족해야 한다.

```text
+----------------------------------------------------------------------+
|            트래픽 분석 진단 아키텍처 (5계층 파이프라인)                |
+----------------------------------------------------------------------+

  [1단계: 트래픽 수집]            [2단계: 데이터 저장]
  +--------------------+         +---------------------+
  | +--------------+   |         |  +---------------+  |
  | |TAP(광분배기) |--+----+     |  |  Time-Series  |  |
  | |(인라인 복제) |   |    |     |  |  Database     |  |
  | +--------------+   |    |     |  |  (InfluxDB,   |  |
  | +--------------+   |    |     |  |   Prometheus) |  |
  | |SPAN Port    |--+--+ |     |  +---------------+  |
  | |(스위치 미러) |   |  | |     |  +---------------+  |
  | +--------------+   |  | |     |  |  Flow Storage |  |
  | +--------------+   |  | |     |  |  (nfdump,     |  |
  | |sFlow/NetFlow|--+--+-+-----|->|   PMACCT)     |  |
  | |(라우터 샘플) |   |  | |     |  +---------------+  |
  | +--------------+   |  | |     |  +---------------+  |
  | +--------------+   |  | |     |  |  PCAP Storage |  |
  | |ERSPAN/VXLAN |--+--+-+-----|->|  (RingBuffer, |  |
  | |(원격 미러)   |   |  | |     |  |   NFS, S3)    |  |
  | +--------------+   |  | |     |  +---------------+  |
  +--------------------+  | |     +----------+----------+
                          | |                |
                          | |                v
  [3단계: 분석 엔진]    | |   [4단계: 시각화/대시보드]

  | +---------------+  | | |   | +----------------------+ |
  | | 패킷 분석기   |  | | |   | | Grafana / Kibana     | |
  | | - Wireshark   |<-+-+---+---| (시계열/Top-N/Heatmap)| |
  | | - tcpdump     |  | | |   | +----------------------+ |
  | | - tshark      |  | | |   | +----------------------+ |
  | | (L2~L7 해부)  |  | | |   | | NTA/NDR 대시보드     | |
  | +---------------+  | | |   | | (Darktrace, Vectra,  | |
  | +---------------+  | | |   | |  ExtraHop, Cisco     | |
  | | 플로우 분석기 |<-+-+---+---|  Secure Network      | |
  | | - nfdump/NfSen|  | | |   | |  Analytics)          | |
  | | - SiLK        |  | | |   | +----------------------+ |
  | | (5-Tuple 집계)|  | | |   +--------------------------+ |
  | +---------------+  | | |                |
  | +---------------+  | | |                v
  | | AI/ML 엔진    |  | | |   [5단계: 감리 보고서]
  | | - 베이스라인   |<-+-+---+--->+----------------------+
  | | - 이상탐지     |  | | |   | - KPI 적합성 표      |
  | | - 분류(DPI)   |  | | |   | - 병목 지점 도식     |

  +--------------------+ |                              |
```

| 구성 요소 | 역할 | 핵심 기술 및 동작 방식 |
| :--- | :--- | :--- |
| **TAP (Test Access Point)** | 광/구리 링크의 인라인 트래픽을 비파괴적으로 복제 | 광분배기(Splitter) 방식은 50:50으로 광신호 분기(실패 시 링크 다운되지 않는 passive 안전성), Regeneration TAP는 능동 재생. **장점**: 패킷 손실 0%, 미러링 부하 0%. **단점**: 1Gbps->2개 포트 필요, 10G SR/LR별 별도 모듈. |
| **SPAN (Switched Port Analyzer)** | L2/L3 스위치의 미러 포트 기능(일명 Port Mirroring) | Cisco `monitor session 1 source interface Gi0/1 both`, Juniper `set forwarding-options analyzer`, Arista `monitor session`. **Tx/Rx/Both** 방향 선택 가능. **단점**: ASIC 오버헤드로 대역폭 >70% 시 패킷 드랍 발생, oversubscription 가능. |
| **ERSPAN (Encapsulated Remote SPAN) / GRE** | 데이터센터 내부 원격 미러링 | L3 GRE 터널로 캡슐화하여 원격 분석 장비로 전달. VXLAN 기반 EVPN 환경에서는 `mirror-on-drop` 또는 `packet-trace`(Arista EOS) 활용. |
| **sFlow / NetFlow / IPFIX** | 라우터·L3스위치의 플로우(5-tuple) 샘플링/수집 | **sFlow**: 무작위 1:N 패킷 샘플링(RFC 3176), L2~L7 헤더까지 캡처, **NetFlow v5/v9**: 플로우 단위 집계(7개 필드: SrcIP, DstIP, SrcPort, DstPort, Protocol, ToS, InputIf), **IPFIX**(RFC 7011): NetFlow v9의 IETF 표준화 후속, 가변 길이 템플릿 지원. 샘플링 비율: 일반 1:1000, 정밀 1:100, DDoS 시 1:1(전수). |
| **SNMP Polling / Trap** | 장비 인터페이스 카운터, CPU/메모리, 온도 등 메트릭 수집 | **SNMPv2c/v3** 기반. OID 예: `ifInOctets(1.3.6.1.2.1.2.2.1.10)`, `ifOutErrors`, `ifInDiscards`. 폴링 주기: 5분(표준), 1분(정밀). 5분 간격으로 95th percentile 계산 -> 인터페이스 회선利用率 산출. |
| **Packet Broker (NPB)** | TAP/SPAN 트래픽을 통합·필터링·로드밸런싱하여 분석도구에 분배 | Gigamon, Ixia, cPacket, Garland Technology. 트래픽 필터링(BPF: `tcp port 443 and host 10.0.0.0/8`), L2GRE/VXLAN 터널 종단, 패킷 마스킹(개인정보 비식별화). |
| **Wireshark / tshark** | 패킷 레벨 L2~L7 심층 분석 | tshark CLI: `tshark -i eth0 -Y "tcp.analysis.retransmission" -T fields -e ip.src -e tcp.seq`. 디코더 3,000+ 프로토콜 지원. SSLKEYLOGFILE로 TLS 1.3 평문 복호화. |
| **nfdump / NfSen** | NetFlow 수집·저장·분석 오픈소스 | `nfdump -R /var/netflow/data -c 100 -s record -n 20` (Top 20 통신쌍). NfSen: PHP 기반 웹 프론트엔드. 시계열·산점도·히트맵 시각화. |
| **NTA/NDR (Network Traffic Analysis/Detection-Response)** | AI 기반 이상행위 탐지·위협 헌팅 | ExtraHop Reveal(x), Cisco Secure Network Analytics(구 Stealthwatch), Darktrace, Vectra AI. **기법**: 베이스라인 학습(2~4주) -> LSTM/Autoencoder 이상 점수 -> MITRE ATT&CK 매핑. |
| **부하 생성기 (Traffic Generator)** | 의도적 트래픽 주입으로 SLA 검증 | **iperf3**: `iperf3 -c server -t 60 -P 10
