## 핵심 인사이트 (3줄 요약)

> 1. **본질**: ISP(Information Strategy Planning)는 조직의 **경영전략(BSC, Value Chain) ↔ 업무 프로세스 ↔ 정보시스템 ↔ 기술인프라**를 4계층 아키텍처(BA/DA/AA/TA)로 정렬하고, As-Is·To-Be·Gap 분석을 통해 **최소 3~5년 로드맵**과 ROI 정당화된 투자 우선순위를 도출하는 한국 공공부문 표준 정보화 전략수립 방법론이다.
> 2. **가치**: 국내 정보화 사업의 약 **78%(행안부 2022 통계)**가 ISP 결과 없이 추진되어 평균 **23%의 예산 초과·일정 지연**을 겪는 반면, ISP를 거친 사업은 **TCO 15~30% 절감, 정보화 예산의 중복투자 제거 40% 이상, 현업 요구사항 충족률 85% 이상**의 정량적 효과를 발휘한다.
> 3. **판단 포인트**: ISP 수행 시 가장 큰 의사결정 축은 ①범위(전사 vs. 업무영역 한정) ②기간(단순 전략 vs. ISP+ISMP+EA 통합) ③방법론 선택(자체 vs. McKinsey/Accenture/한국전산원 표준 vs. Agile-ISP) ④BA->DA->AA->TA **연계 정합성** 확보 여부이며, 기술사 시험에서는 **「ISP 단계별 수행착오 시 정보화사업 성과에 미치는 영향」** 식의 트레이드오프형 질문이 핵심 평가 포인트다.

---

## Ⅰ. 개요 및 필요성

ISP(Information Strategy Planning, 정보화 전략수립)는 1980년대 John Zachman의 **프레임워크**와 일본 NTT 데이터의 **NICS(Network-based Integrated Computer System) 방법론**, 그리고 McKinsey·Booz Allen의 컨설팅 방법론이 1990년대 한국에 도입되어 **한국전산원(현 NIA) 표준 방법론**으로 정착된 **Top-down 전략수립 체계**다. 1996년 「정보화촉진기본법」, 2009년 「국가정보화기본법」, 2013년 「클라우드컴퓨팅법」, 2015년 「소프트웨어산업법」 개정 등 일련의 법·제도적 근거를 통해 **국가·공공기관 정보화 사업의 사전 필수 절차**로 자리 잡았다.

정보기술(Information Technology)이 단순 **업무지원(Back-office Automation)** 단계를 넘어 **경영혁신(Strategic Differentiation)**과 **비즈니스 모델 재정의**의 동력이 되면서, IT 투자 의사결정에서 **"왜(Why) -> 무엇을(What) -> 어떻게(How)"**의 3단계 사고가 필수가 되었다. 그러나 한국 공공기관의 정보화 사업은 **①부서별 단위시스템의 스파게티 구조 ②동일 데이터의 중복 입력 ③정보화 예산의 30~40%가 중복투자 ④현업과 IT 부서 간 4~5단계의 커뮤니케이션 갭**이라는 4대 구조적 모순을 안고 있었으며, 이를 해소할 단일 방법론이 필요했다.

```text
[ISP 도입 전: 프로젝트 단위 산발적 IT 투자]
   영업부서 -- (요구) ---> 정보화 담당
       |                      |
       v                      v
   영업관리 SW             ERP 부분구축
   (단독 DB)                  |
       |                      v
       v                재무/회계 모듈
   CRM 도입                    |
   (별도 계약)                 v
                       HR/그룹웨어

   ⚠️ 문제: 같은 고객정보가 3개 DB, 총투자 120억, 1년 6개월 초과
```

```text
[ISP 도입 후: 4-Layer Architecture 기반 통합 전략]
   +---------------------------------------------+
   |  경영전략 (BSC, 4-Perspective KPI)            |
   |  ↕ Alignment                                 |
   |  업무아키텍처 BA (133개 업무, 89개 프로세스)  |
   |  ↕ Mapping                                   |
   |  데이터아키텍처 DA (주요 27개 엔터티, ERD)    |
   |  ↕ Mapping                                   |
   |  애플리케이션아키텍처 AA (32개 시스템, 18개 패키지)|
   |  ↕ Mapping                                   |
   |  기술아키텍처 TA (클라우드/네트워크/보안 표준) |
   +---------------------------------------------+
            v
    [3개년 로드맵 + 23개 세부과제 + 580억 투자계획]
```

**Old vs New Paradigm 비교**

| 시대 | Old Paradigm (1990s 이전) | New Paradigm (ISP 적용) |
|:---|:---|:---|
| 출발점 | 시스템 도입 요청(Hardware-driven) | **경영목표·비전**에서 출발(Strategy-driven) |
| 범위 | 부서/현장 단위 | **전사(End-to-End)** 가치사슬 |
| 분석 방법 | 벤치마크 단순 도입 | **As-Is(현황) -> To-Be(목표) -> Gap(차이)** 3단계 |
| 데이터 | 시스템별 단편 DB | **주엔터티(Master Entity)** 중심 통합 데이터 모델 |
| ROI | "자동화로 인건비 절감" 정성 | **NPV·IRR·Payback Period** 정량 + 정성 효과 |
| 참여 주체 | IT 부서 독주 | **이해관계자(Steering Committee) -> 실무 Task Force** |
| 산출물 | 시스템 설계서 | **ISP 보고서 + 시스템 맵 + 투자우선순위 + 로드맵** |

- **📢 섹션 요약 비유**: ISP는 회사의 **건강검진 + 3년 건강플랜**과 같다. 무작정 헬스장 등록(시스템 도입)하는 게 아니라, 우선 **전신 X-ray·혈액검사(As-Is 분석)**를 통해 어디가 문제인지 정확히 파악한 뒤, **식단·운동·수면·검진 주기(To-Be 로드맵)**를 수립하는 의학적 접근이다.

## Ⅱ. 아키텍처 및 핵심 원리

ISP는 일반적으로 **5단계·9세부활동**으로 구성되며, 각 단계는 4-Architecture(BA/DA/AA/TA) 프레임워크로 수렴된다. 한국전산원 표준 모델은 ①전략수립 추진계획 ②현황분석 ③비전·전략수립 ④실행계획 ⑤결과보고의 5단계이며, **1단계 산출물이 2단계의 입력**이 되는 **Waterfall형**이지만 최근에는 **Agile-ISP(8~12주 스프린트)** 방식이 컨설팅 현장에서 혼용된다.

```text
[ISP 5단계 방법론 상세 흐름도]
+----------------------------------------------------------+
| STEP 1. 전략수립 추진계획 (4~6주)                          |
|   +- 사업범위 정의 (전사 vs. 특정 업무영역)                |
|   +- 수행조직 구성 (추진위, 실무TF, 자문위)                |
|   +- 일정/예산/방법론 확정                                 |
|   +- 산출물: 추진계획서, RFP, 수행체계도                    |
+-------------+--------------------------------------------+
              v
+----------------------------------------------------------+
| STEP 2. 현황분석 및 이슈도출 (8~10주)                       |
|   +- 내부환경 분석: PEST, Five Forces, Value Chain        |
|   +- 업무분석: 133개 업무, 89개 프로세스, RACI 매트릭스     |
|   +- 시스템분석: HW/SW 인벤토리, 시스템간 인터페이스 매트릭스|
|   +- 데이터분석: 27개 주엔터티, 154개 속성                 |
|   +- SWOT/CSF/KPI 도출                                   |
|   +- 산출물: As-Is 보고서, 시스템 맵, 데이터 모델, SWOT    |
+-------------+--------------------------------------------+
              v
+----------------------------------------------------------+
| STEP 3. 정보화 비전·목표·전략수립 (6~8주)                    |
|   +- 미션/비전/핵심가치 정립                                |
|   +- 3대 전략축 (e.g. 고객중심, 협업, 혁신)                |
|   +- To-Be 모델링: BA/DA/AA/TA 각 4-Architecture           |
|   +- 정보화 목표 (BSC 4관점 KPI 30개)                      |
|   +- 핵심과제 23개 도출 (Quick-Win 6 + 중장기 17)          |
|   +- 산출물: To-Be 보고서, 4-Architecture 도면, 목표체계도  |
+-------------+--------------------------------------------+
              v
+----------------------------------------------------------+
| STEP 4. 실행계획 수립 (6~8주)                              |
|   +- 투자우선순위: AHP(Analytic Hierarchy Process) 분석    |
|   +- TCO 5개년 분석: HW/SW/인력/교육/운영비                 |
|   +- ROI 정량화: NPV, IRR, Payback (e.g. NPV 87억, IRR 23%)|
|   +- 3개년 로드맵: Gantt Chart, Milestone                  |
|   +- 위험관리: 23개 위험 식별, RPN(위험우선순위지수) 산정   |
|   +- 성과관리: KPI 모니터링 체계                            |
|   +- 산출물: 실행계획서, 투자계획, 로드맵, 위험대응계획      |
+-------------+--------------------------------------------+
              v
+----------------------------------------------------------+
| STEP 5. 결과보고 및 사후관리 (2~4주)                        |
|   +- ISP 종합보고서 (경영진 보고)                           |
|   +- 이사회/위원회 승인                                    |
|   +- ISMP·EA 연계 계획                                    |
|   +- 차기 ISP 주기 설정 (보통 3~5년)                       |
|   +- 산출물: 최종보고서, 의사결정문, 사후관리방안            |
+----------------------------------------------------------+
```

**4-Architecture 프레임워크의 상호연계 원리**

| 계층 | 핵심 질문 | 산출물 | 사용 방법론/도구 |
|:---|:---|:---|:---|
| **BA (Business Architecture)** | "무엇을(What)" — 어떤 업무를 어떻게 수행하는가? | 업무분장체계, 업무흐름도, RACI | BPMN 2.0, EPC, IDEF0, ARIS |
| **DA (Data Architecture)** | "어떤 정보(Information)" — 데이터의 구조와 흐름은? | 주엔터티 도출, ERD, 데이터 표준화, 메타관리 | IE (Information Engineering), Chen Notation, 데이터 딕셔너리 |
| **AA (Application Architecture)** | "어떤 시스템(With What)" — 어떤 SW로 지원하는가? | 시스템 구성도, 시스템-업무 매트릭스, 인터페이스 정의 | TOGAF, SOA, Microservice, REST/GraphQL |
| **TA (Technology Architecture)** | "어떤 기술(How)" — 어떤 HW/Network/Platform? | H/W 스펙, 네트워크 토폴로지, DBMS, 보안, 클라우드 | AWS Well-Architected, 한국 EA 표준프레임임 |

이 4계층은 **Zachman 2x3 Matrix**의 행(Planner, Owner, Designer, Builder)과 열(What, How, Where, Who, When, Why)이 결합된 개념으로, ISP에서는 보통 **3관점(개념/논리/물리)**으로 단순화하여 활용한다. 핵심은 **BA-DA-AA-TA 간 Traceability(추적성)**를 확보하는 것이다. 즉, **「매출채권 회수 업무(BA) ↔ 매출채권 엔터티(DA) ↔ AR 시스템(AA) ↔ RDBMS + ERP 패키지(TA)」**처럼 한 줄로 이어져야 한다.

**ISP의 정량 분석 도구 — AHP(Analytic Hierarchy Process)**

정보화 투자 우선순위를 결정할 때 Thomas Saaty(1980)가 제안한 **다기준 의사결정(MCDM)** 기법을 활용한다. 예시:

```text
[ISP 투자우선순위 의사결정 트리 (AHP)]
                  [최종 투자우선순위]
          +------------+------------+
       전략적효과    투자규모     실행위험
       (가중치 0.5) (0.3)        (0.2)
       +----+----+                |
   매출증대  고객만족  내부효율    위험비용  ROI  ...
   (0.4)  (0.35)  (0.25)        ...

   -> AHP 일관성 비율(CR) < 0.1 일 때 의사결정 신뢰
   -> 예: 과제 A의 종합점수 0.78 > 과제 B 0.65 > 과제 C 0.42
```

**As-Is -> To-Be -> Gap 분석의 정량화**

| 분석 차원 | As-Is 측정 지표 | To-Be 목표 | Gap (목표-현황) | 해소 전략 |
|:---|:---|:---|:---|:---|
| 업무 효율 | 매출채권 회수 소요일수 평균 47일 | 12일 | -35일 (74% 단축) | ERP 도입 + RPA 자동화 |
| 시스템 통합 | 동일 고객데이터 중복 3.2개소 | 1.0개소 | -2.2개소 | MDM 도입 |
| 정보화 예산 | 매출액 대비 3.8% | 2.5% | -1.3%p | 클라우드 전환(IaaS->SaaS) |
| 현업 만족도 | IT 서비스 만족도 58점/100 | 85점 | +27점 | 데스크레벨 서비스 Desk+ 강화 |

- **📢 섹션 요약 비유**: 4-Architecture는 **서로 다른 언어로 번역된 4권의 사전**이다. BA는 **일상 언어**(업무 매뉴얼), DA는 **데이터 언어**(ERD), AA는 **소프트웨어 언어**(API), TA는 **하드웨어 언어**(서버·네트워크)다. ISP는 이 4개 사전의 **용어집(Glossary)**을 통일하고
