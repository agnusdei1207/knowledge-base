## 핵심 인사이트 (3줄 요약)

> 1. **본질**: ERP 감리 프로세스 적합성 평가는 정보시스템 감리 규정(행정안전부 고시)에 기반하여 ERP 시스템이 **착수-계획-분석-설계-구축-이행-안정화** 전 단계에서 업무 프로세스 재설계(BPR) 결과와 시스템 기능이 고객 요구사항(RFP), 표준 프로세스(Fit-to-Standard), 그리고 업무 적합성 기준에 부합하는지를 **일반감리·상세감리·상주감리** 등 다층적 방법론으로 검증하는 종합적 평가 체계이다.
> 2. **가치**: 적합성 평가를 통해 ERP 구축 실패율(전통적으로 60~70% 수준)을 20%p 이상 감소시키고, 다년간의 미해결 결함 잔존율(Defect Leakage Rate)을 평균 5% 이하로 통제하며, 데이터 마이그레이션 오류율 0.1% 이내, 인터페이스 정합성 99.9% 이상을 보증하여 TCO(총소유비용) 15~25% 절감 및 ROI 극대화를 실현한다.
> 3. **판단 포인트**: 핵심 트레이드오프는 ①**As-Is/To-Base/To-Be Gap 분석의 정밀도 vs 구축 기간** ②**표준 프로세스 준용(Fit-to-Standard) vs 고객 맞춤 Customizing 비율** ③**상주 감리의 리스크 조기 탐지 효과 vs 비용 부담** ④**동시 다발적 모듈 통합 검증 vs 모듈별 단계적 검증** 이며, 기술사는 SAP의 ASAP/SAP Activate, Oracle Unified Method(OUM), MOC(Method of Construction) 등 도입 방법론의 단계별 Gate(검증 게이트) 산출물을 기준으로 의사결정해야 한다.

## Ⅰ. 개요 및 필요성

ERP(Enterprise Resource Planning) 감리는 단순한 SW(소프트웨어) 결함 검출이 아닌, **경영전략-업무프로세스-정보시스템-데이터-인프라-변화관리** 6개 축의 정합성을 평가하는 종합적 적합성 검증 활동이다. 한국정보통신기술협회(TTA) 「정보시스템 감리 안내서」와 행정안전부 「정보시스템 감리 기준」(제2019-44호)에 따르면, 국가·공공기관의 ERP 구축 사업은 예산 5억 원 이상 또는 핵심정보통신기반시설에 해당할 경우 **일반감리 또는 상주감리** 의무 대상이며, 민간도 사내 통제 기준(예: 금융감독원의 전산감리)에 준거하여 감리를 수행한다.

ERP 감리 프로세스 적합성 평가는 다음과 같은 배경에서 필수적이다:

1. **ERP 구축의 본질적 리스크**: 통계적으로 ERP 프로젝트는 평균 예산 30~200% 초과, 기간 40~150% 지연이 빈번하며, 미국 GAO(2020) 보고에 따르면 대형 ERP 도입 실패율 65%, 부분 실패율 25%이다.
2. **업무 프로세스 복잡성**: 단일 조직 평균 1,200~3,000개의 업무 프로세스가 존재하며, 모듈 간 통합(예: FI-CO-MM-SD-PP-HR) 시 인터페이스 포인트가 500~2,000개에 달한다.
3. **컴플라이언스 요구**: K-IFRS, 내부회계관리제도, 개인정보보호법, 전자금융거래법, ESG 공시, 클라우드 데이터 주권 규제 등 다층적 규제 환경의 동시 충족.
4. **데이터 무결성**: 레거시 시스템에서 신규 ERP로 데이터 마이그레이션 시 평균 2~5% 데이터 오류 발생(IBM 연구) -> 정확한 마이그레이션 정합성 평가 필수.

**전통적 패러다임 vs 현대 패러다임**:
- **전통(1990~2000)**: ERP = 단순히 레거시 mainframe(IBM AS/400, Unisys)을 차세대 ERP로 R/2 -> R/3 전환하는 기술적 마이그레이션 관점. 감리는 "코딩 표준 준수", "DB 스키마 적정성" 같은 기술 중심 평가.
- **현대(2010~현재)**: ERP = 디지털 트랜스포메이션 코어. S/4HANA, Oracle Cloud ERP, Microsoft Dynamics 365 등 **Cloud-native + In-memory + AI/ML 임베디드** 환경으로 전환. 감리는 **업무 적합성, 비즈니스 가치 실현, Agile/DevOps, 데이터 거버넌스, 변경 영향도(Change Impact)** 중심으로 확장.
- **미래(2024~)**: Generative AI 기반 ERP(Joule, Copilot, Oracle AI Agents)와 Composable ERP(MSA 기반 모듈 조합) 환경에서 감리는 **AI 모델의 공정성, Explainability, 데이터 lineage 자동 검증** 으로 진화.

- **📢 섹션 요약 비유**: ERP 감리 프로세스 적합성 평가는 마치 **대형 우주선의 발사 전 7단계 체크아웃(Pre-launch Checkout)**과 같습니다. 각 단계별 Gate(검증문)를 통과하지 못하면 다음 단계로 못 가며, 우주선의 부품(모듈), 연료(데이터), 조종 절차(업무프로세스), 통신(인터페이스), 비상탈출(롤백 계획)까지 전부 점검해야 비로소 안전한 발사(이행)가 가능합니다.

## Ⅱ. 아키텍처 및 핵심 원리

ERP 감리 프로세스 적합성 평가는 **ISACA의 ITAF(Information Technology Assurance Framework)**, **COBIT 2019**, **PMBOK 7th**, **ISO/IEC 33000(소프트웨어 프로세스 평가)**, 그리고 **TTA 정보시스템 감리 안내서(2023 개정판)**을 통합한 다층 프레임워크로 수행된다. 감리 대상은 5개 영역(Domain) - 거버넌스, 프로젝트 관리, 시스템 품질, 데이터 품질, 변화관리 - 으로 분류되며, 각 영역별 평가 기준은 **공통평가기준(Common Criteria) + 도메인별 상세기준(Detailed Criteria) + 체크리스트(Checklist) 3계층**으로 구성된다.

| :--- | :--- | :--- | :--- |
| **G0: 착수** | 사업타당성분석서, BPR 추진계획 | 사업 정당성, 이해관계자 합의, 추진조직 적정성 | CCTA ISPL(Information System Procurement Library) |
| **G1: 계획/RFP** | RFP, 기능/비기능 요구사항 정의서, SLA | 요구사항 명확성(완전성·일관성·검증가능성·추적가능성), 평가기준·배점 적정성 | IEEE 830, BABOK v3, NIPA SW사업 관리 가이드 |
| **G2: 분석** | As-Is 프로세스 맵, To-Be 프로세스 맵, Gap 분석표, 현행시스템 인벤토리 | 현행업무 정확도(샘플링 검증), To-Be 효율성(ROI 추정치), 컴플라이언스 매핑 | BPR/BPI 방법론, BPMN 2.0, K-IFRS 업무 흐름도 |
| **G3: 설계** | 시스템 설계서, 데이터 모델, 인터페이스 명세, 보안설계서, 시험계획서 | 아키텍처 원칙(SOLID, 12-Factor App) 준수, ERD 정규화(BCNF), 인터페이스 예외처리 완비 | TOGAF 9.2, ArchiMate 3.1, AWS Well-Architected |
| **G4: 구축** | 단위/통합/시스템/인수시험 결과, 결함관리대장, 코드 리뷰 결과 | 테스트 커버리지(Line≥80%, Branch≥70%), 결함 밀도(KLOC당 ≤0.5건), 성능 시험 동시사용자 목표 | ISTQB, IEEE 829, TMMi 5 Level 3 |
| **G5: 이행** | 컷오버 계획/결과, 데이터 마이그레이션 검증 결과, 교육/매뉴얼, 병행테스트 결과 | 데이터 마이그레이션 정합성(99.9%), 롤백 시나리오 검증, 사용자 수용성(UAT pass rate ≥95%) | ITIL 4, PRINCE2 |

### 적합성 평가 핵심 산식 및 지표

1. **요구사항 추적 매트릭스 커버리지(RTM Coverage)**:
   ```
   RTM_Coverage(%) = (추적 가능한 요구사항 수 / 전체 요구사항 수) × 100
   ※ 적합 임계값: ≥ 95%
   ```

2. **테스트 커버리지(코드)**:
   - Line Coverage: 𝜂_L = (실행된 라인 수 / 전체 라인 수) × 100 ≥ 80%
   - Branch Coverage: 𝜂_B = (실행된 분기 수 / 전체 분기 수) × 100 ≥ 70%
   - MCDC(Modified Condition/Decision Coverage): ≥ 60% (안전 критичный 모듈)

3. **결함 누출률(Defect Leakage Rate, DLR)**:
   ```
   DLR(%) = (운영 단계 결함 수 / 전체 결함 수) × 100
   ※ 적합 임계값: ≤ 5%
   ```

4. **일정 적합성(Schedule Performance Index, SPI)**:
   ```
   SPI = EV(Earned Value) / PV(Planned Value)
   ※ SPI < 0.9 -> Yellow, SPI < 0.8 -> Red
   ```
