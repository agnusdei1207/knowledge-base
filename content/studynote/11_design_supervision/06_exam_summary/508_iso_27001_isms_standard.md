## 핵심 인사이트 (3줄 요약)

> 1. **본질**: ISO/IEC 27001은 조직의 정보보호 위험을 **PDCA(Plan-Do-Check-Act) 사이클 기반 ISMS(Information Security Management System)** 로 체계화하여, 2022년 개정판 기준 **Annex A 4개 영역(Organizational/People/Physical/Technological) 93개 통제 항목**을 통해 위험평가·처리·모니터링을 전사적으로 통합 관리하는 국제 표준이다.
> 2. **가치**: 인증 취득을 통한 고객·규제기관 신뢰 확보, ISMS-P(국내)·GDPR·PCI-DSS 등 다중 컴플라이언스 매핑으로 중복 통제 제거, 보험료 할증 제거(평균 15~30%) 및 보안사고 발생 시 과실 입증 부담 경감 등의 정량적 이점을 제공한다.
> 3. **판단 포인트**: 적용 범위(Scope) 정의의 합리성(전사 vs 특정 부서), 위험평가 방법론 선택(ISO 27005 vs NIST SP 800-30 vs OCTAVE), 통제 적용 판단 기준(SoA에서의 적용/제외 사유), 그리고 인증기관(Accredited CB) 선정 시 IAF MLA 가입 여부 검증이 핵심 의사결정 요소다.

## Ⅰ. 개요 및 필요성

정보보안 침해사고는 2023년 IBM Cost of a Data Breach Report 기준 전 세계 평균 **$4.45M**에 달하며, 국내에서는 2024년 상반기 랜섬웨어 피해 신고만 **245건**으로 전년 대비 약 2배 증가했다(한국인터넷진흥원 KISA). 이러한 환경에서 개별 보안 제품 도입 중심의 **'포인트 솔루션 패러다임'** 은 한계를 드러냈고, 경영 체계 차원에서 정보보호를 관리하는 **'ISMS 패러다임'** 으로 전환이 요구되었다.

ISO 27001은 영국 표준 BS 7799(1995) -> BS 7799-2(2002) -> ISO/IEC 27001(2005) -> 2013 개정 -> **2022년 3세대 개정(ISO/IEC 27001:2022)** 을 거치며 진화해왔다. 2022년 개정의 핵심 변화는 다음과 같다:

- Annex A 통제 항목 **114개 -> 93개**로 통제통합(예: A.6.1.1~5 -> A.5.15~17 Access Control 통합)
- 통제 분류 체계를 **11개 영역 -> 4개 테마**로 단순화
- 11개의 신규 통제 추가(DPI, DLP, Threat Intelligence, ICT Readiness, Physical Security Monitoring 등)
- Annex A 통제와 **ISO 27002:2022** 의 5가지 속성(Preventive/Detective/Corrective, Control of impact, Information security properties, Cybersecurity concepts, Operational capabilities, Security domains) 매핑

```text
[ ISO 27001 도입 배경 및 패러다임 전환 ]

  +----------------------------------------------------------+
  |   1990s                       2000s               2010s~  |
  |  +------+                  +------+           +------+  |
  |  |기술중심| ---- 진화 ----->|정책중심| ---- 진화 --->|경영체계| |
  |  |Firewall|               |ISMS  |           |Risk  |  |
  |  |Anti-Virus|              |인증  |           |Based |  |
  |  +------+                  +------+           +------+  |
  |      |                          |                  |     |
  |  침해 탐지                 위험 식별          전사 거버넌스 |
  |  (Reactive)             (Proactive)        (Predictive) |
  +----------------------------------------------------------+

  [ 기존 패러다임 vs ISMS 패러다임 비교 ]

  +------------------+         +------------------+
  |  포인트 솔루션    |         |   ISMS 체계     |
  |  (Legacy)        |         |   (Modern)       |
  +------------------+         +------------------+
  | • 제품별 독립    |  ----->  | • 위험 기반 통합 |
  | • 사후 대응형    |         | • 예방-탐지-대응 |
  | • IT 부서 한정   |         | • 전사 거버넌스  |
  | • ROI 불명확     |         | • 경영 KPI 연계 |
  | • 컴플라이언스 X  |         | • 다중 인증 연계 |

       실패 확률 ^                    실패 확률 v
```

| 구분 | 포인트 솔루션 | ISMS 패러다임 |
| :--- | :--- | :--- |
| **관리 대상** | 기술 자산(서버, 네트워크) | 정보 자산(데이터) + 프로세스 + 사람 |
| **위험 인식** | 사고 발생 후 인지 | 위험평가·처리 사전 수행 |
| **책임 주체** | CISO/보안팀 | 최고경영자(CEO) -> 전사 |
| **측정 지표** | 가용성, 처리량 | KRI, KPI, KCI(보안 문화 지수) |
| **규제 대응** | 개별 대응 | 통합 매핑(ISMS-P, GDPR, ISO 27701) |
| **지속성** | 인력/예산 변동 시 공백 | PDCA 사이클의 제도적 보장 |

- **📢 섹션 요약 비유**: 포인트 솔루션이 **"감기 증상마다 약을 다르게 먹는 것"** 이라면, ISMS는 **"면역 체계를 만들어서 감기 자체를 예방하는 건강검진 시스템"** 입니다.

## Ⅱ. 아키텍처 및 핵심 원리

ISO 27001:2022의 구조는 **본문(Clauses 4~10) + Annex A 통제 항목** 으로 구성된다. 본문은 **HLS(High Level Structure)** 라고 불리는 ISO 9001, 14001 등 다른 MSS(Management System Standard)와 공통화된 10개 조항으로, PDCA 사이클에 명확히 매핑된다.

```text
[ ISO 27001:2022 PDCA 사이클과 조항 매핑 ]

                          +-----------------+
                          |  Clause 4: 조직의 상황 |
                          |  (Context)        |
                          +--------+--------+
                                   | 이해관계자 요구사항
                                   v
       +---------------------------------------------------+
       | PLAN (계획)                                        |
       |  +-------------+  +--------------+  +----------+ |
       |  | Clause 5:   |  | Clause 6:    |  | Clause 7:| |
       |  | 리더십      |-->| 위 험 평가   |-->| 지원    | |
       |  | (Leadership)|  | (Planning)   |  |(Support)| |
       |  +-------------+  +--------------+  +----------+ |
       |       |                  |                  |     |
       |       v                  v                  v     |
       |  +----------------------------------------------+|
       |  | 위험처리계획(RTP) + Statement of Applicability ||
       |  +----------------------------------------------+|
       +---------------------------+-----------------------+
                                   |
                                   v
       +---------------------------------------------------+
       | DO (실행)                                          |
       |  +----------------------------------------------+|
       |  | Clause 8: 운영 (Operation)                     ||
       |  |  • Annex A 통제 구현 (93개 통제)                ||
       |  |  • 4개 테마: Org(37) / People(8) / Phys(14)    ||
       |  |    / Tech(34)                                 ||
       |  +----------------------------------------------+|
       +---------------------------+-----------------------+
                                   | 운영 데이터
                                   v
       +---------------------------------------------------+
       | CHECK (검증)                                       |
       |  +----------------------------------------------+|
       |  | Clause 9: 성과평가 (Performance Evaluation)    ||
       |  |  9.1 모니터링·측정·분석·평가                   ||
       |  |  9.2 내부감사(Internal Audit) - ISO 19011     ||
       |  |  9.3 경영검토(Mgmt Review) - 분기/반기          ||
       |  +----------------------------------------------+|
       +---------------------------+-----------------------+
                                   | 개선 사항
                                   v
       +---------------------------------------------------+
       | ACT (개선)                                         |
       |  +----------------------------------------------+|
       |  | Clause 10: 개선 (Improvement)                  ||
       |  |  10.1 일반 / 10.2 부적합 및 시정조치            ||
       |  |  10.3 지속적 개선 (Continual Improvement)      ||
       |  +----------------------------------------------+|
       +---------------------------+-----------------------+
                                   |
                                   +---------> 다음 PLAN 사이클
```

| 구성 요소 | 역할 | 핵심 기술 및 동작 방식 |
| :--- | :--- | :--- |
| **Clause 4: 조직의 상황** | ISMS 적용 범위 결정 | **내부/외부 이슈 분석**(SWOT, PESTLE), 이해관계자 요구사항 파악, **Scope Statement** 작성(예: "서울 본사 및 데이터센터의 고객정보 처리 업무") |
| **Clause 5: 리더십** | 최고경영자의 의지 표명 | 정보보안 정책(ISP) 승인, **보안 담당 임원(CISO)** 임명, 역할/책임 매트릭스(RACI) 정의, 조직 내 모든 레벨에 ISMS 통합 지시 |
| **Clause 6: 위험평가 및 처리** | 정보보호 위험의 체계적 관리 | 자산 식별(정보/소프트웨어/물리/서비스/사람) -> 위협 식별(STRIDE, PASTA) -> 취약점 평가(CVSS 4.0) -> **위험도 = 가능성 × 영향도**(정성적 5단계 또는 정량적 Monetary Value) -> 위험처리 옵션 선택(수정/회피/전가/수용) -> **위험처리계획서(RTP)** 작성 |
| **Clause 7: 지원** | ISMS 운영 자원 확보 | 역량·인식·교육·의사소통·문서화된 정보 관리, **역량 매트릭스**(보안 자격증: CISSP/CISA/CIPP/ISO 27001 LA) |
| **Clause 8: 운영** | 통제 구현 및 운영 | **Annex A 93개 통제** 적용, 통제 운영 절차(SOP) 수립, 변경관리, 일정 계획에 따른 통제 운영 |
| **Clause 9: 성과평가** | ISMS 효과성 측정 | KPI(예: 보안사고 수, 패치 SLA 준수율 ≥ 95%), **내부감사 프로그램**(연 1회 이상, ISO 19011:2018 기반), **경영검토 회의**(연 1~2회, 의사결정 로그 기록) |
| **Clause 10: 개선** | 부적합 사항 시정 및 예방 | **8D 보고서**, 근본원인분석(RCA: 5-Why, Fishbone), **시정조치(CA)** 등록/추적, 지속적 개선 활동(Kaizen) |
| **Annex A 통제 (4개 테마)** | 세부 보안 통제 항목 | Org(37): 거버넌스·분류·정책 / People(8): 채용·훈련·퇴직 / Physical(14): 출입통제·환경 / Technological(34): 암호·네트워크·백업·SIEM·DLP |

### 핵심 통제 메커니즘 상세

**위험평가 방법론 (Clause 6.1.2)**:
ISO 27001은 특정 방법론을 강제하지 않지만, 실무에서는 다음을 조합한다:
- **ISO 27005:2022** (위험관리 가이드라인)
- **NIST SP 800-30 Rev.1** (위험평가 수행 가이드)
- **OCTAVE Allegro** (운영 위협/자산/취약점 평가)
- **FAIR**(Factor Analysis of Information Risk) - 정량적 분석 시

**Statement of Applicability (SoA, Clause 6.1.3.d)**:
- Annex A 93개 통제 **전수에 대해** 적용/제외 여부 명시
- 적용/제외 사유 문서화 필수(제외 시 정당화 근거)
- 통제별 구현 상태(구현중/구현완료/부분구현/미구현) 표시
- 통
