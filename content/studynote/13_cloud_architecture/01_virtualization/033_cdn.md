[CDN](/knowledge-base/studynote/03_network/09_application_layer_web_email/506_cdn_content_delivery_network_edge_caching/)(Content Delivery Network)은 전 세계 분산된 엣지 서버에 콘텐츠를 [캐싱](/knowledge-base/studynote/02_operating_system/08_storage_and_io_systems/456_caching/)해 사용자와 가장 가까운 위치에서 콘텐츠를 전달함으로써 레이턴시를 최소화하는 인프라다.
> 2. 정적 [파일](/knowledge-base/studynote/02_operating_system/09_file_system/501_file_definition_logical_record/) [캐싱](/knowledge-base/studynote/02_operating_system/08_storage_and_io_systems/456_caching/)을 넘어 동적 콘텐츠 가속·DDoS [보호](/knowledge-base/studynote/02_operating_system/10_security/571_protection_vs_security/)·[TLS](/knowledge-base/studynote/02_operating_system/11_exam_summary/694_thread_local_storage_tls/) 종단·[API](/knowledge-base/studynote/02_operating_system/01_overview_architecture/014_api_posix/) 게이트웨이 기능으로 진화해 현대 웹 아키텍처의 첫 번째 방어선이자 [성능](/knowledge-base/studynote/04_software_engineering/05_devops_ci_cd/282_performance_tactics/) 레이어가 되었다.
> 3. Cache-Control 헤더·[TTL](/knowledge-base/studynote/03_network/06_network_layer_ip/294_ttl_time_to_live_looping_prevention/) [설정](/knowledge-base/studynote/15_devops_sre/01_culture_methodology/009_config/)·캐시 무효화(Invalidation) [전략](/knowledge-base/studynote/04_software_engineering/04_testing_quality/268_strategy_pattern/)이 [CDN](/knowledge-base/studynote/03_network/09_application_layer_web_email/506_cdn_content_delivery_network_edge_caching/) 활용의 핵심이며, 원본 서버 [보호](/knowledge-base/studynote/02_operating_system/10_security/571_protection_vs_security/)와 [캐시 히트](/knowledge-base/studynote/01_computer_architecture/06_memory_hierarchy_cache/263_cache_hit_miss/)율 최적화의 균형이 중요하다.

## Ⅰ. CDN의 구조와 동작 원리

[CDN](/knowledge-base/studynote/03_network/09_application_layer_web_email/506_cdn_content_delivery_network_edge_caching/)(Content Delivery Network)은 <strong><a href="/knowledge-base/studynote/07_enterprise_systems/02_erp_systems/120_pop_point_of_production/">PoP</a>(Point of Presence, 접속 거점)에 위치한 엣지 서버 네트워크</strong>로, 원본 서버(Origin)의 콘텐츠를 [복제](/knowledge-base/studynote/14_data_engineering/01_infrastructure/016_replication_factor/)·[캐싱](/knowledge-base/studynote/02_operating_system/08_storage_and_io_systems/456_caching/)해 가까운 위치에서 제공한다.

📢 **섹션 요약 비유**: CDN은 편의점 네트워크다 — 물건(콘텐츠)을 멀리 있는 본사 창고(원본 서버) 대신, 동네 편의점(엣지 서버)에서 바로 가져온다.

### Cache-Control 헤더

```http
Cache-Control: public, max-age=86400     # 1일 캐시
Cache-Control: private, no-cache         # 사용자별, 항상 재검증
Cache-Control: public, s-maxage=3600     # CDN 1시간, 브라우저 다름
Cache-Control: immutable, max-age=31536000 # 해시URL: 1년 캐시
```

### 캐시 가능 콘텐츠 [분류](/knowledge-base/studynote/16_bigdata/05_analysis/104_classification_analysis/)

| 콘텐츠 유형    | 캐시 [전략](/knowledge-base/studynote/04_software_engineering/04_testing_quality/268_strategy_pattern/)           | [TTL](/knowledge-base/studynote/03_network/06_network_layer_ip/294_ttl_time_to_live_looping_prevention/)         |
|-------------|-------------------|------------|
| JS/[CSS](/knowledge-base/studynote/06_ict_convergence/02_iot_mobility/110_unlicensed_lpwan_lorawan_sigfox/) (해시) | [immutable](/knowledge-base/studynote/13_cloud_architecture/05_data_engineering/298_immutable/) 캐시    | 1년         |
| 이미지        | public 캐시       | 7일~30일    |
| HTML          | 짧은 [TTL](/knowledge-base/studynote/03_network/06_network_layer_ip/294_ttl_time_to_live_looping_prevention/) + ETag   | 5분~1시간   |
| [API](/knowledge-base/studynote/02_operating_system/01_overview_architecture/014_api_posix/) 응답      | private or no-cache| 없음        |
| 개인화 콘텐츠 | no-store          | 없음        |

📢 **섹션 요약 비유**: Cache-Control은 유통기한 스티커다 — 오래된 빵(HTML)은 매일 새로 받고, 통조림(해시된 JS)은 1년 캐시해도 된다.

### [캐시 히트](/knowledge-base/studynote/01_computer_architecture/06_memory_hierarchy_cache/263_cache_hit_miss/)율 최적화

```
히트율 = 캐시 히트 / 전체 요청

히트율 개선 방법:
  ✅ 적절한 TTL 설정 (너무 짧으면 히트율↓)
  ✅ 쿼리 파라미터 정규화
  ✅ Vary 헤더 최소화
  ✅ 캐시 키 최적화
```

📢 **섹션 요약 비유**: 캐시 무효화는 편의점 재고 교체다 — 유통기한([TTL](/knowledge-base/studynote/03_network/06_network_layer_ip/294_ttl_time_to_live_looping_prevention/))이 지나면 자동 교체(만료), 신제품 즉시 출시(해시 URL), 즉시 강제 교체(Purge [API](/knowledge-base/studynote/02_operating_system/01_overview_architecture/014_api_posix/)).

### Edge Function 예시 (Cloudflare Workers)

```javascript
export default {
  async fetch(request) {
    const url = new URL(request.url);
    // A/B 테스트 쿠키 없으면 랜덤 할당
    if (!request.headers.get('Cookie')?.includes('ab=')) {
      const variant = Math.random() < 0.5 ? 'A' : 'B';
      const response = await fetch(
        `https://origin.example.com${url.pathname}?variant=${variant}`
      );
      return new Response(response.body, {
        headers: { ...response.headers, 'Set-Cookie': `ab=${variant}` }
      });
    }
    return fetch(request);
  }
};
```

📢 **섹션 요약 비유**: Edge Function은 배달 드론이 배달 중에 포장을 변경하는 것이다 — 고객 주소(지역), 취향([쿠키](/knowledge-base/studynote/03_network/09_application_layer_web_email/475_cookie_local_state/))에 따라 본사(원본)에 가지 않고도 맞춤 포장을 한다.

## 👶 어린이를 위한 3줄 비유 설명

1. CDN은 전국 편의점 체인이다 — 음료수(콘텐츠)를 멀리 있는 공장(원본)에서 직접 가져오는 대신, 가까운 편의점(엣지)에서 바로 산다.
2. Cache-Control은 유통기한이다 — 유통기한이 길면(긴 [TTL](/knowledge-base/studynote/03_network/06_network_layer_ip/294_ttl_time_to_live_looping_prevention/)) 자주 들르지 않아도 되고, 짧으면(짧은 [TTL](/knowledge-base/studynote/03_network/06_network_layer_ip/294_ttl_time_to_live_looping_prevention/)) 자주 새로 채워야 한다.
3. Edge Function은 배달 기사가 배달 중에 맞춤 [서비스](/knowledge-base/studynote/13_cloud_architecture/02_iaas_paas_saas/090_service_kubernetes_network_load_balancing/)를 하는 것이다 — 배달 도중에 고객 취향에 맞게 포장을 바꾸거나 선물을 추가한다.
