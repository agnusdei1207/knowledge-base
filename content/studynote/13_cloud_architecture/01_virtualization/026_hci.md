## 핵심 인사이트 (3줄 요약)
> 1. **본질**: [[630_hci|HCI]] (Hyperconverged Infrastructure, [[630_hci|하이퍼컨버지드 인프라]])는 서버 컴퓨팅·스토리지·네트워킹·하이퍼바이저를 단일 어플라이언스 노드로 통합한 인프라 아키텍처로, 소프트웨어 정의 기술([[632_sds|SDS]], [[633_sdn_whitebox|SDN]])을 기반으로 x86 범용 하드웨어 위에 구현된다.
> 2. **가치**: HCI는 [[090_configuration_item|CI]](Converged Infrastructure) 대비 스토리지가 스토리지 어레이에 종속되지 않고 각 노드의 내부 디스크를 소프트웨어로 묶어 사용하므로, 노드 추가만으로 컴퓨팅+스토리지+네트워크 용량이 선형적으로 확장([[202_scale_out_distributed_horizontal_expansion|Scale-out]])된다.
> 3. **판단 포인트**: HCI의 핵심 트레이드오프는 "운영 단순성·확장 유연성 vs. 스토리지와 컴퓨팅의 독립적 [[249_scaling_normalization_standardization|스케일링]] 불가"다. 컴퓨팅 집약적 워크로드([[190_ai_llm_requirements_specification|AI]]/ML)에서는 스토리지 없이 컴퓨팅만 늘릴 수 없어 비효율이 발생한다.

---

## Ⅰ. 개요 및 필요성

```text
┌────────────────────────────────────────────────────────┐
│   전통 3-Tier vs. CI vs. HCI 아키텍처 비교              │
├────────────────────────────────────────────────────────┤
│ 전통:  [서버] + [SAN/NAS] + [L2/L3 스위치] — 3계층      │
│ CI:    [서버+스토리지 어레이+네트워크] 미리 통합된 번들   │
│ HCI:   [소프트웨어로 통합된 x86 노드 클러스터]           │
│        각 노드 = CPU + RAM + NVMe/SSD + HBA + 하이퍼바이저│
│        SDS 레이어가 전체 스토리지 풀 구성                 │
└────────────────────────────────────────────────────────┘
```

- **📢 섹션 요약 비유**: HCI는 레고 블록 [[801_data_center_3_tier_architecture_core_aggregation_access|데이터센터]]다. 블록 하나(노드)에 전기·수도·[[024_gas|가스]]가 모두 들어있어서, 블록을 추가하면 세 가지가 동시에 늘어난다. 기존 [[801_data_center_3_tier_architecture_core_aggregation_access|데이터센터]]는 전기회사, 수도회사, [[024_gas|가스]]회사에 따로 전화해야 했다.

## Ⅱ. 아키텍처 및 핵심 원리

### [[630_hci|HCI]] 소프트웨어 [[057_stack|스택]]

```text
┌────────────────────────────────────────────────────────┐
│               HCI 소프트웨어 레이어                      │
├────────────────────────────────────────────────────────┤
│ VM / 컨테이너 (워크로드)                                  │
├────────────────────────────────────────────────────────┤
│ 하이퍼바이저 (VMware vSphere / AHV / Hyper-V)            │
├────────────────────────────────────────────────────────┤
│ SDS (Software Defined Storage)                          │
│  - 분산 스토리지 엔진 (vSAN / Nutanix DSF / S2D)         │
│  - 데이터 중복 제거, 압축, 이레이저 코딩                  │
├────────────────────────────────────────────────────────┤
│ SDN (Software Defined Networking)                       │
├────────────────────────────────────────────────────────┤
│ x86 하드웨어 (노드별 CPU + RAM + NVMe/SSD)               │
└────────────────────────────────────────────────────────┘
```

### [[202_scale_out_distributed_horizontal_expansion|Scale-out]] vs. [[621_scale_up_system_bus|Scale-up]]

| 비교 | [[630_hci|HCI]] [[202_scale_out_distributed_horizontal_expansion|Scale-out]] | 전통 [[621_scale_up_system_bus|Scale-up]] |
|:---|:---|:---|
| 확장 방법 | 동일 노드 추가 | 더 큰 서버·스토리지로 교체 |
| 비용 | 점진적 투자 가능 | 대규모 선투자 필요 |
| [[452_availability|가용성]] | 노드 장애 시 자동 재배치 | [[454_spof|단일 장애점]] 위험 |
| 독립 스케일 | 불가 (컴퓨팅+스토리지 묶음) | 분리 가능 |

- **📢 섹션 요약 비유**: Scale-out은 직원을 점진적으로 채용하는 것이다. 한 명이 컴퓨팅+스토리지+네트워킹 세 가지를 다 담당하는 멀티플레이어라, 한 명씩 추가하면 세 가지 역량이 동시에 늘어난다.

## Ⅲ. 비교 및 연결

| 비교 | [[630_hci|HCI]] | [[090_configuration_item|CI]] (Converged Infrastructure) | 전통 3-Tier |
|:---|:---|:---|:---|
| 스토리지 | 노드 내장 [[632_sds|SDS]] | 외부 스토리지 어레이 | [[493_san_storage_area_network|SAN]]/[[492_nas_network_attached_storage|NAS]] 별도 |
| 관리 | 단일 관리 콘솔 | 멀티 관리 도구 | 각 계층 별도 관리 |
| 확장성 | 노드 단위 [[202_scale_out_distributed_horizontal_expansion|Scale-out]] | 번들 단위 | 각 계층 독립 |

- **📢 섹션 요약 비유**: 전통 [[801_data_center_3_tier_architecture_core_aggregation_access|데이터센터]]가 주방·거실·침실이 따로 있는 대형 아파트라면, CI는 방 3개가 패키지로 묶인 모델 하우스, HCI는 모든 기능이 하나로 통합된 오피스텔이다.

## Ⅳ. 실무 적용 및 기술사 판단

### [[079_developer_cleanroom_vdi_security|VDI]] 워크로드에서 [[630_hci|HCI]] 우위
- [[079_developer_cleanroom_vdi_security|VDI]] (Virtual Desktop Infrastructure)는 수백~수천 VM이 I/O 집약적이면서 균일한 컴퓨팅+스토리지를 필요로 한다. HCI의 [[136_variance|분산]] 스토리지가 I/O 병목을 [[136_variance|분산]]시키고, 노드 추가로 선형 확장된다.

### [[235_edge_computing_smart_factory|엣지 컴퓨팅]] 활용
- 소형 [[630_hci|HCI]] 어플라이언스(2~3 노드)를 공장·지점·병원에 배치하여 로컬 [[001_dikw_pyramid|데이터]] 처리. 중앙 클라우드와 하이브리드 관리.

- **📢 섹션 요약 비유**: 엣지 HCI는 편의점 무인 키오스크다. 중앙 서버에 의존하지 않고 로컬에서 직접 처리하되, 본사(클라우드)와 주기적으로 동기화한다.

## Ⅴ. 기대효과 및 결론

| 기대효과 | 내용 |
|:---|:---|
| **운영 단순화** | 단일 콘솔로 인프라 전체 관리 |
| **[[016_tco|TCO]] 절감** | 하드웨어 통합, 관리 인력 절감 |
| **민첩성** | 노드 추가 → 용량 확장 수시간 이내 |

[[190_ai_llm_requirements_specification|AI]]/ML 워크로드의 [[418_gpu|GPU]] 집약적 특성으로 인해 [[630_hci|HCI]] 벤더는 [[418_gpu|GPU]] 노드 통합형 [[190_ai_llm_requirements_specification|AI]]-[[630_hci|HCI]] 솔루션을 출시하고, [[205_kubernetes_container_orchestration|Kubernetes]] 기반 [[561_container_based_deployment|컨테이너]] 오케스트레이션을 HCI에 통합하는 방향으로 진화 중이다.

- **📢 섹션 요약 비유**: [[190_ai_llm_requirements_specification|AI]]-HCI는 [[190_ai_llm_requirements_specification|AI]] 연구소가 필요한 모든 장비([[418_gpu|GPU]]·스토리지·네트워크)를 통합 패키지로 제공하는 턴키 [[190_ai_llm_requirements_specification|AI]] 인프라다. 연구자가 인프라 설정에 시간을 쓰지 않고 바로 [[190_ai_llm_requirements_specification|AI]] 모델 학습에 집중할 수 있다.

### 👶 어린이를 위한 3줄 비유 설명

1. HCI는 레고 블록 [[801_data_center_3_tier_architecture_core_aggregation_access|데이터센터]]예요! 블록 하나에 컴퓨터·저장소·네트워크가 모두 들어있고, 블록을 더 붙이면 모든 게 동시에 늘어나요.
2. 전통 [[801_data_center_3_tier_architecture_core_aggregation_access|데이터센터]]는 전기·수도·[[024_gas|가스]] 회사에 따로따로 전화해야 하지만, HCI는 하나의 통합 [[090_service_kubernetes_network_load_balancing|서비스]] 앱에서 한 번에 처리해요!
3. 요즘은 GPU까지 통합해서 [[190_ai_llm_requirements_specification|AI]] 학습을 위한 블록도 추가할 수 있답니다!
