## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 정보관리기술사 445번 시험은 IT 거버넌스·전략·아키텍처·프로젝트·운영·보안·법규를 통합적으로 판단하는 종합 응시 능력 평가이며, COBIT 2019, ISO 38500, TOGAF 10, PMBOK 7th, ITIL 4 프레임워크를 축으로 최신 기술사 답안 논리(Why->What->How->So What)를 구성해야 한다.
> 2. **가치**: 단순 암기형 출제에서 탈피하여 실무 사례 기반의 의사결정·트레이드오프 분석·ROI 산출·리스크 정량화·컴플라이언스 매핑 능력을 검증하며, 합격자는 조직의 CIO/CTO 레벨에서 IT-Business Alignment를 주도할 수 있는 자격을 취득한다.
> 3. **판단 포인트**: 프레임워크 간 중복·충돌(예: Agile vs. Waterfall, DevOps vs. ITIL Change Management, BYOD vs. 정보보호)의 우선순위, 한국 규제 환경(개인정보보호법, 정보통신망법, 클라우드컴퓨팅법, AI기본법) 하에서의 글로벌 표준 적용, 그리고 레거시 현대화·디지털전환(DX)·ESG-IT 간 시너지를 어떻게 설계하느냐가 고득점 결정 변수다.

---

## Ⅰ. 개요 및 필요성

정보관리기술사(445회 기준) 시험은 ①IT 전략·계획 ②정보시스템 구축·관리 ③정보보호 ④IT 운영·거버넌스 ⑤IT 법규·컴플라이언스의 5대 영역을 통합적으로 평가한다. 2020년 이후 출제 트렌드는 클라우드·AI·데이터 거버넌스·제로트러스트·DevSecOps·ESG가 결합된 융합형 사례형 문제(SWOT, ROI, KPI, RACI, BPR, BPMN 도출 요구)로 전환되었으며, 단순 이론 암기형 문항은 10% 미만으로 축소되었다.

**왜 필요한가?** 과거(2010년 이전) 정보관리기술사 시험은 OSI 7계층·DB 정규화·개발 방법론 이론형이 60% 이상이었으나, 현재는 4차 산업혁명·디지털전환(DX)·AI 윤리·데이터 주권·공급망 보안 등 **VUCA 환경**에서 CIO가 즉시 의사결정해야 하는 실무 시나리오가 출제된다. 따라서 단순 지식이 아닌 "**프레임워크 선택->적용->정량적 효과 측정**"의 종합 판단력이 요구된다.

- **📢 섹션 요약 비유**: 정보관리기술사는 "**의료법무의 전문의(MD-JD)**"와 같다. IT라는 환자의 상태(시스템)를 진단(거버넌스)하고, 처방(전략)을 내리고, 수술(구축)을 집도하며, 재활(운영)·보험처리(컴플라이언스)까지 두루 알아야 한다.

## Ⅱ. 아키텍처 및 핵심 원리

정보관리기술사 답안의 **4단계 논리 구조**는 다음과 같이 표준화된다. 이는 어떤 출제 영역이든 동일하게 적용되어야 한다.

```text
+---------------------------------------------------------------------+

+---------------------------------------------------------------------+
|                                                                     |
|  [1] WHY  --►  [2] WHAT  --►  [3] HOW  --►  [4] So What            |
|   문제정의     프레임워크선택   실행계획수립     정량적효과/리스크    |
|                                                                     |
|  +---------+   +---------+   +---------+   +--------------+        |
|  |As-Is    |   |TOGAF ADM|   |WBS/RACI |   |NPV, ROI,    |        |
|  |SWOT/5F  |--►|COBIT 2019|--►|KPI/SLA  |--►|Payback, TCO |        |
|  |CSF/KPI  |   |ISO 38500|   |Budget   |   |Risk Matrix  |        |
|  |Pain Point  |NIST CSF  |   |PMO      |   |ESG Score    |        |
|  +---------+   +---------+   +---------+   +--------------+        |
|       |              |              |              |                |
|       v              v              v              v                |

|   되는가?"         풀 것인가?"     어떻게?"       리스크는?"     |
+---------------------------------------------------------------------+
```

### 답안 작성 시 핵심 파라미터 & 공식

1. **NPV (순현재가치)**: `NPV = Σ [CFt / (1+r)^t] - I0` (CFt: t기 현금흐름, r: 할인율, I0: 초기투자)
2. **ROI**: `ROI = (총이익 - 총비용) / 총비용 × 100%` — IT 사업의 경우 3년 내 150% 이상 권고
3. **TCO (Total Cost of Ownership)**: 직접비(HW/SW) + 간접비(운영·교육·장애·전환) — 일반적으로 5년 TCO = 도입비의 3~5배
4. **Payback Period**: `Σ CFt (1~n) ≥ I0` 되는 n — IT 프로젝트 3~5년 이내 회수가 적정
5. **가용성(Availability)**: `A = MTBF / (MTBF + MTTR) × 100%` — 99.999%(Five-9) = 연 5.26분 장애 허용
6. **RTO/RPO**: 재해복구 목표시간 / 목표데이터복구시점 — Tier1: RTO 4h/RPO 0, Tier4: RTO 96h/RPO 24h
7. **성능지수**: TPS(Transaction Per Sec), 동시사용자수(CCU), 응답시간(Response Time), 처리량(Throughput), Apdex 점수

- **📢 섹션 요약 비유**: 기술사 답안은 "**환자 진료기록부(SOAP)**"와 같다. **S**ubjective(주관적 호소 = WHY), **O**bjective(객관소견 = AS-IS 분석), **A**ssessment(평가 = 프레임워크 매핑), **P**lan(치료계획 = HOW + So What). SOAP 없이 진단하면 오진이 발생하듯, 4-Stage 없이 답안 쓰면 탈락한다.

### 프레임워크 간 비교표 (가장 빈번한 출제)

| :--- | :--- | :--- | :--- | :--- | :--- |
| **주 목적** | IT 거버넌스·관리 | IT 서비스 운영 | 정보보호 관리체계 | 사이버보안 프레임 | EA 구축 방법론 |
| **적용 계층** | 이사회~경영진 | 실무 운영팀 | CISO·보안팀 | 전사 보안전략 | EA 아키텍트 |
| **핵심 구조** | 5도메인, 40목표 | 34실무, SVS | 93통제, 4-theme | 6 Function, Tier1-4 | 8단계 ADM |
| **측정 체계** | 능력수준(M0-M5) | 서비스 KPI | KRI, 감사결과 | TIER 매핑 | ADM 산출물 |
| **법적 연계** | SOX, 內部회계 | ISO 20000 | PIMS, ISMS-P | EO 14028 | 공공 EA(KEAF) |
| **업데이트** | 2019, 5년주기 | 2019, 축약형 | 2022(93통제) | 2024(Govern추가) | 2022(EA4.0연동) |

### 다른 영역과의 연결 매트릭스

- **거버넌스 ↔ 프로젝트관리**: COBIT의 EDM(평가·지시·모니터링) ↔ PMO의 Portfolio/Program/Project 3계층. 프로젝트 단계 종료 시마다 COBIT 목표 달성도 평가 필수.
- **EA ↔ 전략**: TOGAF Phase A(Architecture Vision)에서 BSC, Phase B(비즈니스 아키텍처)에서 BPR/BPMN 매핑. **EA는 전략의 "How"를 구체화한 청사진**.
- **ITIL ↔ DevOps**: 전통적 ITIL Change Management(긴 시간) ↔ DevOps의 CI/CD Pipeline(자동화). 2020년 이후 ITIL 4가 "Value Stream", "SVS"로 DevOps와 통합.
- **정보보호 ↔ 개인정보**: ISO 27701(PIMS)로 확장. 2023년 9월 개인정보보호법 개정(가명정보 도입)으로 PIMS 인증 수요 폭증.
- **AI 거버넌스 ↔ ISO 38500**: EU AI Act(2024), 한국 AI기본법(2026 시행) — IT 거버넌스 원칙을 AI에 확장 적용하는 논리가 신규 출제 포인트.

- **📢 섹션 요약 비유**: 이 프레임워크들은 "**오케스트라 악기**"와 같다. **COBIT**은 지휘자(거버넌스), **TOGAF**는 악보(설계도), **ITIL**은 현악(운영), **ISO27001**은 보안요원(보호), **PMBOK**은 타악기(일정). 한 악기만 연주하면 불협화음, 모두 조화롭게 연주해야 비로소 **가치(So What)**가 창출된다.

## Ⅳ. 실무 적용 및 기술사 판단

### 기술사형 판단 체크리스트

1. **문제 정의 단계 (WHY)**: As-Is 분석 시 5 Forces·SWOT·CSF·Value Chain을 활용했는가? 정량 데이터(매출, 시스템 가용성, 장애시간, NPS)가 포함되었는가?
2. **프레임워크 선택 단계 (WHAT)**: COBIT·TOGAF·ITIL·ISO 표준 중 해당 문제에 가장 적합한 2~3개를 선택했는가? 선정 사유가 "Best Fit"이 아니라 "Why Not Alternative" 논리로 설명되는가?
3. **실행계획 단계 (HOW)**: WBS(Work Breakdown Structure), RACI 매트릭스, 일정(Gantt/Milestone), 예산(Bottom-up Top-down), 리스크 매트릭스(발생확률×영향도)가 포함되었는가?
4. **정량효과 단계 (So What)**: NPV
