## 핵심 인사이트 (3줄 요약)

> 1. **본질**: IT 거버넌스(Information Technology Governance)는 **COBIT 2019**(40개 관리목표·5개 도메인·40개 컴포넌트), **ISO/IEC 38500**(6원칙·5개 모델), **ITIL 4**(34개 실무·SVS), **PMBOK 7th**(8대 성과영역)을 통합한 **Value Governance** 체계로, 이사회·경영진의 **EDM(Evaluate·Direct·Monitor)** 책임을 통해 IT 자원과 비즈니스 전략을 **Align-Plan-Organize** 라이프사이클로 연계하는 통제 프레임워크이다.
> 2. **가치**: ISACA·Gartner 연구에 따르면 COBIT 기반 거버넌스 도입 기업은 **IT 투자 ROI 23% 향상**(McKinsey 2022), **프로젝트 실패율 38%->12% 감소**(PMI 2023 Pulse), **컴플라이언스 비용 45% 절감**, **IT-Biz 정렬도 67%->89% 개선**(Balanced Scorecard 적용 시) 효과를 얻는다.
> 3. **판단 포인트**: 핵심 트레이드오프는 **① 프레임워크 중복성**(COBIT·ITIL·PMBOK 간 중복 영역 30%) vs **② 통합 거버넌스**, **③ 중앙집중 통제 vs 연방형 거버넌스(Federal Governance)**, **④ 성숙도 모델(5단계) 적용 시점**, **⑤ RACI 매트릭스**에서 의사결정 권한의 위임 수준이며, 조직의 **CMMI 성숙도·산업 규제(금융 ISA·의료 HIPAA)·클라우드 전환 단계**에 따라 의사결정 기준이 달라진다.

## Ⅰ. 개요 및 필요성

IT 경영관리(Information Technology Management)는 2000년대 **Section 404 of SOX**(2002), **Enron·WorldCom 사건** 이후 IT 통제(IT General Controls, ITGC)의 재무보고 영향이 부각되면서 단순 "IT 운영"에서 **"Value-Driven IT Governance"**로 패러다임이 전환되었다. 과거 CIO(Chief Information Officer)는 시스템 구축·운영에 집중했으나, **CDO(Chief Data Officer), CISO(Chief Information Security Officer), CRO(Chief Risk Officer)** 등 C-Level 역할이 세분화되며 이사회 수준의 **IT 전략 거버넌스**가 요구된다.

```text
+----------------------------------------------------------------------+
|         IT 거버넌스 패러다임 전환 (Legacy -> Modern)                  |
+----------------------------------------------------------------------+
|                                                                      |
|   [과거: IT 관리 (1980~2000)]         [현재: IT 거버넌스 (2000~)]    |
|   +---------------------+             +---------------------+       |
|   |  • IT 부서 중심     |             |  • 전사 가치 중심    |       |
|   |  • 비용(cost) 중심  |   ------►   |  • 가치(value) 중심  |       |
|   |  • 기술 사일로      |             |  • 전략 정렬(align)  |       |
|   |  • 프로젝트별 관리  |             |  • 포트폴리오 관리   |       |
|   |  • CFO 보고        |             |  • CEO·이사회 보고  |       |
|   |  • CAPEX 일회성    |             |  • OPEX+CAPEX+TBM   |       |
|   +---------------------+             +---------------------+       |
|                                                                      |
|   +------------------------------------------------------+         |
|   | 규제·표준 환경 변화 (Regulatory Drivers)              |         |
|   |  • SOX 404 (2002) - ITGC 통제 필수화                  |         |
|   |  • COSO 2013 Internal Control - Integrated Framework |         |
|   |  • ISO 38500 (2008->2015) - IT Governance Standard    |         |
|   |  • 한국: 전자정부법, 개인정보보호법, ISMS-P (2021)    |         |
|   |  • 금융: 금융감독원 IT검사, ISA(정보시스템감사)기준   |         |
|   +------------------------------------------------------+         |
|                                                                      |
|   +------------------------------------------------------+         |
|   | 한국 IT 거버넌스 진화 단계 (5단계 성숙도)              |         |
|   |  L1: Ad-hoc -> L2: Repeatable -> L3: Defined           |         |
|   |  -> L4: Managed -> L5: Optimized                       |         |
|   |  (한국 대기업 평균: L2.8, 금융권 평균: L4.2)          |         |
|   +------------------------------------------------------+         |
+----------------------------------------------------------------------+
```

**왜 IT 거버넌스가 필요한가?**

1. **IT-Biz 정렬 부재**: McKinsey(2021) 조사 결과 글로벌 기업의 **63%가 IT 투자와 비즈니스 전략의 정렬 실패**를 경험, 이로 인한 손실이 **연간 매출의 4.2%** 에 달함.
2. **프로젝트 실패율**: Standish Group CHAOS Report(2023)에 따르면 IT 프로젝트 **실패율 31.1%, 챌린지 53.1%**, 성공률 15.4%이며, 거버넌스 미비 기업의 실패율은 평균의 **2.3배**.
3. **규제 컴플라이언스**: GDPR 위반 시 글로벌 매출의 **4% 또는 €20M**, 한국 개인정보보호법 위반 시 **누적 과징금 1,000억원** (2023년 기준)까지 부과 가능.
4. **사이버 리스크**: IBM Cost of Data Breach 2023 평균 비용 **$4.45M**, 거버넌스 성숙 기업은 **$3.15M**(29% 절감).
5. **클라우드·AI 전환 가속**: 멀티클라우드·생성형 AI 도입으로 IT 토폴로지가 복잡해지면서 통합 거버넌스 부재 시 **Shadow IT가 IT 예산의 30~40%** 점유하는 현상 발생.

- **📢 섹션 요약 비유**: IT 거버넌스는 마치 **오케스트라의 지휘자**와 같습니다. 첼리스트(개발팀), 바이올리니스트(운영팀), 트럼펫 연주자(보안팀) 각자 실력은 뛰어나지만, **악보(전략)**와 **지휘봉(거버넌스)** 없이는 카오스가 됩니다. COBIT은 악보, ITIL은 각 악기 연주 매뉴얼, ISO 38500은 오케스트라 운영 규칙에 비유할 수 있습니다.

## Ⅱ. 아키텍처 및 핵심 원리

### 1. COBIT 2019 핵심 아키텍처

COBIT 2019는 **2019년 4월 ISACA**에서 발표된 6번째 개정판으로, **40개 관리목표(Management Objectives)**를 **5개 도메인**에 걸쳐 정의하고, 이를 실현하기 위한 **40개 컴포넌트(Components of a Governance System)** 와 **7단계 디자인 팩토리(Design Factors)**를 통해 조직 맞춤형 거버넌스 시스템을 설계한다.

```text
+----------------------------------------------------------------------+
|              COBIT 2019 거버넌스 시스템 아키텍처                      |
+----------------------------------------------------------------------+
|                                                                      |
|                    +---------------------+                           |
|                    |  Stakeholder Needs  |  ◄-- 13개 이해관계자      |
|                    |  (13개 니즈)        |      (이사회, 경영진,     |
|                    +----------+----------+       규제기관, 고객 등)  |
|                               |                                     |
|                               v                                     |
|                    +---------------------+                           |
|                    |   Enterprise Goals  |  ◄-- 13개 목표(AGI)       |
|                    |   (13개 전사목표)   |      재무/고객/내부/     |
|                    +----------+----------+       학습/성장 관점      |
|                               |     (Cascade)                       |
|                               v                                     |
|   +--------------------------------------------------------+        |
|   |  Alignment Goals -> IT 관련 목표 (13개 IT-AG)            |        |
|   +--------------------+-----------------------------------+        |
|                        v                                            |
|   +----------------------------------------------------------+      |
|   |  ★ 5개 도메인 × 40개 관리목표 (Management Objectives) ★  |      |
|   |  +--------------------------------------------------+    |      |
|   |  | EDM: Evaluate·Direct·Monitor (5개)               |    |      |
|   |  |  +- EDM01: 거버넌스 프레임워크 설정·유지          |    |      |
|   |  |  +- EDM02: 혜택 실현(Delivery of Benefits)         |    |      |
|   |  |  +- EDM03: 리스크 최적화(Optimize Risk)            |    |      |
|   |  |  +- EDM04: 자원 최적화(Resource Optimization)      |    |      |
|   |  |  +- EDM05: 이해관계자 투명성 확보                  |    |      |
|   |  +--------------------------------------------------+    |      |
|   |  | APO: Align·Plan·Organize (14개)                   |    |      |
|   |  |  +- APO01~14: IT관리체계, 전략, 아키텍처, 혁신,    |    |      |
|   |  |  |  포트폴리오, 예산, HR, 관계, 서비스 합의,      |    |      |
|   |  |  |  공급자, 품질, 리스크, 보안, 데이터            |    |      |
|   |  +--------------------------------------------------+    |      |
|   |  | BAI: Build·Acquire·Implement (11개)               |    |      |
|   |  |  +- BAI01~11: 프로그램/프로젝트, 요구사항,        |    |      |
|   |  |  |  솔루션, 가용성, 전환, 변경, 수용, 지식, 자산   |    |      |
|   |  +--------------------------------------------------+    |      |
|   |  | DSS: Deliver·Service·Support (6개)                 |    |      |
|   |  |  +- DSS01~06: 운영, 서비스 요청, 인시던트,        |    |      |
|   |  |  |  연속성, 보안 서비스, 비즈니스 통제            |    |      |
|   |  +--------------------------------------------------+    |      |
|   |  | MEA: Monitor·Evaluate·Assess (4개)                 |    |      |
|   |  |  +- MEA01~04: 성능/정합성, 내부통제, 외부요구,    |    |      |
|   |  |  |  이슈/Escalation 관리                          |    |      |
|   |  +--------------------------------------------------+    |      |
|   +----------------------------------------------------------+      |
|                              |                                       |
|                              v                                       |
|   +----------------------------------------------------------+      |
|   | 7개 디자인 팩토리 (조직별 거버넌스 시스템 설계)         |      |
|   |  D1: 전략/목표   D2: 리스크   D3: 이슈/사고              |      |
|   |  D4: 위협/취약점 D5: 규제    D6: 역할/의사결정 모델     |      |
|   |  D7: 기술 도입   + Focus Area (DevOps·Risk·Compliance)  |      |
|   +----------------------------------------------------------+      |
|                              |                                       |
|                              v                                       |
|   +----------------------------------------------------------+      |
|   | 40개 컴포넌트 (Components of Governance System)          |      |
|   |  +- 프로세스(Process) - 40개                              |      |
|   |  +- 조직구조(Organizational Structures) - 17개            |      |
|   |  +- 정보흐름(Information Flows) - 다양한 데이터/보고서    |      |
|   |  +- 사람/역량/기술(People, Skills, Competencies)          |      |
|   |  +- 정책/절차(Principles, Policies, Procedures)           |      |
|   |  +- 문화/윤리/행동(Culture, Ethics, Behavior)             |      |
|   |  +- 서비스/인프라/응용(People, Process, Technology)        |      |
