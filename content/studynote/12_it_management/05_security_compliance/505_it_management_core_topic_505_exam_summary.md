# 📘 기술사 시험 요약 노트 — 505. IT 경영 관리 핵심 토픽

> **시험 대비 관점**: 정보관리기술사 / 컴퓨터시스템응용기술사 필기·면접 통합 대비
> **학습 범위**: IT 거버넌스·전략·조직·성과·디지털 전환·위험관리의 end-to-end 프레임워크

---

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: IT 경영 관리의 핵심은 **"IT-비즈니스 정합(Alignment) -> 가치(Value) 실현 -> 위험(Risk) 통제"**의 3축으로 수렴되며, 이는 COBIT 2019(Governance & Management Objectives 40개), ISO/IEC 38500(6원칙), ITIL 4(SVS 34개实践), PMBOK 7(8성능영역) 등 글로벌 표준의 교집합으로 정의된다.
> 2. **가치**: IT 거버넌스 성숙도 Level 3->5 도달 시 프로젝트 성공률 28%->62% 향상(PMI 2021), EA 기반 투자 포트폴리오 최적화로 TCO 15–25% 절감, BSC 4관점 KPI 운영으로 ROI 측정 가능 영역 40%->85% 확대.
> 3. **판단 포인트**: **표준 채택 vs. 맞춤형 적용(Customization)**, **집중형 거버넌스(Centralized) vs. 분산형(Federated)**, **프로세스 중심 vs. 데이터 중심**, **단기 ROI vs. 장기 역량 구축** — 면접에서는 "왜 이 프레임워크를 선택했는가"의 트레이드오프 논리가 반드시 요구된다.

---

## Ⅰ. 개요 및 필요성

디지털 전환(DX), AI·클라우드·데이터 3대 요소의 폭발적 확산으로 IT는 더 이상 **"지원 기능(Back-office)"이 아닌 "사업의 핵심 동력"**으로 격상되었다. 그러나 한국 기업 71%(KISA 2023)의 IT 투자 대비 성과 측정이 미흡하고, 정보시스템 감사의 중대 지적사항 비율이 38%에 달해, **IT 투자의 정당성·효율성·리스크 관리**를 입증할 수 있는 체계적 경영관리 프레임워크의 도입이 필수적이다.

**기존 패러다임 vs. 신규 패러다임**:

| 구분 | 전통적 IT 경영(1990~2010) | 현대 IT 경영(2020~) |
|---|---|---|
| 관점 | 비용센터(Cost Center) | 가치센터(Value Center) |
| 구조 | 기능별 수직(Silo) | 플랫폼 기반 수평(Platform) |
| 의사결정 | CIO 단독 Top-down | CDO·CCO·CISO 등 C-Level 협업 |
| 성과측정 | Uptime, 응답시간 | NPV, ROIC, Customer Journey 지표 |
| 위험관리 | BCP/DR 중심 | Cyber Resilience + ESG + Privacy |

**왜 필요한가 (3대 배경)**:
1. **규제 강화**: 개인정보보호법(2023 전면개정), 정보통신망법, ISMS-P, AI기본법(2025 시행) 등 컴플라이언스 요건 폭증
2. **투자 규모 확대**: 글로벌 IT 지출 2024년 5.1조 USD(Gartner), 한국 공공 SW사업 12조 원 돌파
3. **사이버 리스크 증대**: 랜섬웨어 피해 연평균 23% 증가, 평균 다운타임 비용 분당 300만 원

- **📢 섹션 요약 비유**: IT 경영 관리는 마치 **"대형 유조선의 키잡이"**와 같다. 거대한 투자·조직·기술이라는 선박의 방향을 거버넌스(키)로, 항해도(전략)로, 기관(프로세스)으로, 엔진(인재)으로, 나침반(성과·리스크)으로 동시에 통제해야 한다.

## Ⅱ. 아키텍처 및 핵심 원리

### 1. IT 거버넌스 3계층 아키텍처

```text
+-----------------------------------------------------------------+
| Tier 1: 의사결정 계층 (Decision Layer)                          |
|  +--------------+  +--------------+  +--------------+           |
|  | 이사회/IT전략 |  |  IT거버넌스위 |  |  사업주도 아키|           |
|  |   위원회     |-> |  원회(ISG)   |-> |  텍처 사빕   |           |
|  +--------------+  +--------------+  +--------------+           |
+-----------------------------------------------------------------+
| Tier 2: 관리 계층 (Management Layer) - COBIT 2019 EDM/Domain   |
|  EDM01 거버넌스프레임워크 | EDM02 가치전달 | EDM03 리스크최적화  |
|  EDM04 자원관리 | EDM05 투명성보장                            |
+-----------------------------------------------------------------+
| Tier 3: 실행 계층 (Execution Layer) - Process/Service          |
|  ITIL 4 (34 Practice) | PMBOK 7 (8 PF) | DevOps (CICD)        |
|  ISO 27001 (114 Control) | TOGAF (ADM) | ISA 315/330 (감사)   |
+-----------------------------------------------------------------+
```

### 2. IT-Business Alignment 성숙도 모델 (Luftman 5단계)

| 단계 | 명칭 | 핵심 특징 | 진단 질문 |
|---|---|---|---|
| Level 1 | Adhoc(임의) | 무계획, 프로젝트별 단발성 | "IT 투자의 ROI 측정이 가능한가?" |
| Level 2 | Committed(약속) | 인식은 있으나 실행력 부족 | "경영진이 IT 전략을 승인했는가?" |
| Level 3 | Established(확립) | 표준 프로세스 적용 중 | "IT-사업 KPI가 연동되어 있는가?" |
| Level 4 | Improved(개선) | 정량 측정·피드백 체계 가동 | "성과 차이가 분석되어 개선되는가?" |
| Level 5 | Optimized(최적화) | 지속적 혁신·예측 가능 | "IT가 사업 모델 혁신을 주도하는가?" |

### 3. 핵심 프레임워크 연동 구조

| 구성 요소 | 역할 | 핵심 기술 및 동작 방식 |
|---|---|---|
| **COBIT 2019** | 거버넌스 메타프레임워크 | 40개 Governance/Management Objective, 7개 컴포넌트(원리/정책/구조/프로세스/정보/문화/인재/서비스), Cascade Goals(기업->IT->Stakeholder) |
| **ISO/IEC 38500** | IT 거버넌스 국제표준 | 6대 원칙(책임/전략/취득/성과/규정/인간행위) + 3계층(지시/평가/모니터링) |
| **ITIL 4** | 서비스 관리 운영체계 | 34개 Practice(일반/서비스/기술) + SVS(Service Value System) + 4D 모델(설계/전환/구축/개선) |
| **PMBOK 7** | 프로젝트 관리 원칙 | 12원칙 + 8성능영역(팀/계획/개발/불확실성/측정/범위/일정/재무) + Tailoring |
| **TOGAF 10** | EA 방법론 | ADM(Architecture Development Method) 9단계 + Content Framework + Capability Framework |
| **BSC(Kaplan-Norton)** | 전략->성과 변환 | 4관점(재무/고객/내부/학습성장) × 5요소(목표/지표/목표값/과제/전략맵) |
| **ISO 31000** | 리스크 관리 | 원칙-프레임워크-프로세스(6단계: 식별->분석->평가->처리->모니터링->커뮤니케이션) |

### 4. 핵심 알고리즘/원리

**(1) Cascade Goals (목표 연쇄) — COBIT 2019**

```
Stakeholder Needs -> Enterprise Goals(13) -> Alignment Goals(13) -> Mgmt Objectives(40)
        v                  v                    v                    v
   가치/리스크         EBITDA 12%^        Portfolio Mgmt 95%   EDM02/APO05
```

**(2) BSC 전략맵 인과관계 (Cause-Effect Chain)**

```
학습성장(역량^) -> 내부프로세스(품질^) -> 고객(만족도^) -> 재무(ROI^)
   (직원훈련)       (오류율v)         (NPS^)          (매출증대)
```

**(3) 위험 = f(자산, 위협, 취약성, 영향)** — ISO 27005

```
Risk = Likelihood(가능성) × Impact(영향도) × Vulnerability(취약성)
     = (Threat × Asset Value) × Control Gap
```

**(4) EA 정합도 분석식**

```
Fit Score = Σ(Wi × Ci) / ΣWi
   - Wi: 영역 가중치(비즈니스 40%, 애플리케이션 25%, 데이터 20%, 기술 15%)
   - Ci: 세부영역별 정합도 점수(0~100)
```

- **📢 섹션 요약 비유**: COBIT는 **"오케스트라의 지휘자"**다. 각 악기(프로세스·기술·인재·데이터)를 개별 연주하게 두지 않고, 하나의 악보(Governance Objective)로 정렬하여 가치를 만들어낸다. ISO 38500은 지휘자의 행동강령, ITIL은 연주 매뉴얼, PMBOK은 파트 연습법이다.

## Ⅲ. 비교 및 연결

### 1. 유사 프레임워크 비교

| 구분 | COBIT 2019 | ITIL 4 | ISO 38500 | PMBOK 7 |
|---|---|---|---|---|
| **주 목적** | 거버넌스·관리 | 서비스 운영 | 거버넌스 원칙 | 프로젝트 관리 |
| **관점** | What(무엇을) + How(어떻게) | How(어떻게) | What(무엇을) 원칙 | How(어떻게) 원칙 |
| **계층** | Strategic/Tactical | Tactical/Operational | Strategic | Project-level |
| **성숙도** | CMMI 5단계 | 5단계 | 평가 없음 | 모델·방법·원칙 |
| **대상** | CIO·이사회·감사 | IT운영자·매니저 | 이사회·경영진 | PM·팀원 |
| **산출물** | Goals Cascade | SVS/Practice | 원칙선언문 | Charter/WBS |
| **연계 프레임워크** | ISO 27001, 20000, 31000 | DevOps, SIAM | COBIT, ISO 31000 | SAFe, Agile, PRINCE2 |
| **강점** | End-to-end 거버넌스, 감사 친화 | 서비스 가치·고객경험 | 원칙 명확, ISO 정합 | 원칙·유연성, Agile 통합 |
| **약점** | 복잡성, 도입비용 | 거버넌스 결여 | 구현 가이드 부재 | 거버넌스·운영 결여 |

### 2. 거버넌스 모델 비교 (Weill-Ross)

| 구분 | Business Monarchy | IT Monarchy | Feudal | Federal | Duopoly |
|---|---|---|---|---|---|
| **의사결정** | 사업부서 독점 | CIO 독점 | 단위별 독자 | 공동 합의 | IT+사업 쌍두 |
| **장점** | 사업 친화 | 기술 우수 | 빠른 의사결정 | 균형·정합 | 전략적 부합 |
| **단점** | 중복·표준 부재 | 사업 괴리 | 사일로·중복 | 의사결정 지연 | 갈등 소지 |
| **적용** | 규제산업, R&D | IT 강호기업 | 다국적·대기업 | 균형 추구 조직 | DX 추진 조직 |

### 5. 프로젝트 관리 방법론 비교 (Predictive vs Adaptive)

| 구분 | Predictive(Waterfall) | Adaptive(Agile) | Hybrid(SAFe/Spotify) |
|---|---|---|---|
| **요구사항** | 초기에 명확 | 점진적 발견 | 부분 명확 |
| **범위 변경** | 엄격 통제 | 유연 수용 | 영역별 분리 |
| **적합** | 대형/규제/건설 | SW/혁신/실험 | 기업 전사(DX) |
| **리스크 관리** | 사전 식별 | 스프린트별 | 다층(PI/Iteration) |
| **측정** | SPI/CPI/EAC | Velocity/Burn-down | PI Objectives |
| **예시** | 공공 SI, ERP | 앱개발, MVP | SAFe, LeSS, Nexus |
