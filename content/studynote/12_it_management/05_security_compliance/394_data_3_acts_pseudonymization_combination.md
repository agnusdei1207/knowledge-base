## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 2020년 2월 4일 시행된 '데이터 3법'(개인정보 보호법, 정보통신망법, 신용정보법) 개정으로 도입된 **가명정보(Pseudonymous Information)** 는 추가 이용·제공·결합이 허용되는 새로운 처리형태로, 개인식별성은 제거하되 결합·분석·상호연계에 필요한 식별자(Linkage Key)는 보존하는 반가역적(Reversible by Trustee) 데이터이다.
> 2. **가치**: 행정안전부·과기정통부·금위위 등 5개 부처 합동 분석에 따르면 가명정보 결합 활용 시 **연간 약 4조 원 이상의 경제적 가치**와 헬스케어·공공데이터·핀테크 등 약 15개 산업군에서 신규 비즈니스 모델 창출이 가능하며, 가명처리·결합통제-안전조치-재식별 위험평가의 3단 게이트를 통해 GDPR Article 89 대비 한국형 Safe Harbor를 구현한다.
> 3. **판단 포인트**: 가명정보 결합의 성패는 **① 결합목적 적법성(Speciality Principle), ② 결합통제기관(개인정보보호위원회) 승인 또는 동의획득 경로, ③ 가명처리 알고리즘(k-익명성, l-다양성, t-근접성, 차등프라이버시 ε), ④ 내부관리계획 수립·이행, ⑤ 재식별 위험의 정기적 재평가**의 5축 균형점에 있으며, 결합상한 30일 룰·가명결합전문기관 지정제·가명정보 결합계약서 표준 양식 등 세부 통제 요건을 모두 충족해야 한다.

## Ⅰ. 개요 및 필요성

한국 사회의 디지털 전환 가속화에 따라 병원·은행·통신사·공공기관이 보유한 데이터는 단순 저장을 넘어 **교차 결합(Cross-Industry Data Federation)** 을 통한 새로운 인사이트 생산의 원천이 되었다. 그러나 종전의 「개인정보 보호법」(2011.9.30 시행, 2013.6.7 전면시행)은 수집·이용·제3자 제공·목적 외 이용 등 모든 단계에서 **정보주체의 동의**를 요구하고, 가명처리 후에는 그 자체로 결합·분석이 사실상 불가능하도록 제한하여 **"데이터 쓰나미(Data Tsunami) vs. 데이터 사막(Data Desert)"** 의 모순을 낳았다.

특히 2018년 1월 개정안 국회 계류 당시, 의료 빅데이터(건보공단-심사평가원-병원 EMR), 핀테크(금융결제원-통신사-카드사), 모빌리티(지자체-렌터카-내비게이션) 등 3대 융합산업에서 데이터 공유가 법적으로 막혀 **OECD가 2018 Digital Economy Outlook에서 한국을 "데이터 활용 최하위권"** 으로 평가하는 사태까지 발생했다. 이 같은 문제를 해결하기 위해 '데이터 3법'(개인정보 보호법, 정보통신망법, 신용정보법)이 2020.1.9 공포·2.4.시행되었고, 핵심 변화는 다음과 같다.

| 기존 패러다임 (Pre-2020) | 신규 패러다임 (Post-2020 데이터 3법) |
| :--- | :--- |
| 가명처리(익명처리 구분) 시 결합·반복 활용 불가 | **가명정보는 결합·통계작성·연구·상호연계 가능** |
| 가명처리 기관 자체 처리 | **가명결합전문기관** 지정(한국정보화진흥원 등) 통한 중앙화 결합 |
| 정보주체 동의 없이는 제3자 제공 차단 | **상대방 가명결합** 시 결합계약서·결합통제기관 승인/신고 |
| 22개 개별법에서 정의 상이 | **'개인정보' 정의 통일**(생존·사망자 정보 포함) |
| 비식별 조치 후 재식별 시 형사처벌 조항 부재 | **재식별 금지 명문화 + 과징금/형사처벌** 동시 적용 |

기술적으로는 "비식별화(De-identification)"라는 용어까지도 「개인정보 보호법」에서 **"가명처리"** 로 명명 변경하여 법적 효력을 분명히 했다. 즉, **가명 = 식별자 가명화 + 추가정보 분리·접근통제** 의 2단계 처리(가명정보 보호위원회 가이드라인 기준)이며, 단순 해시(Hash)나 마스킹(Masking)만으로는 가명정보로 인정되지 않는다.

- **📢 섹션 요약 비유**: 데이터를 도서관의 책에 비유하면, 종전에는 책에 적힌 독자 이름이 보이지 않더라도 책을 대출할 때마다 사서에게 별도 허락을 받아야 했다. 데이터 3법 이후에는 **"이름표만 떼어내고 사물함에 보관하되, 검색 인덱스(연결고리)는 사서가 관리"** 하므로 책(데이터)은 여러 도서관 사이에서 자유롭게 대출·교환되며, 이름표를 다시 붙이려는 시도는 사서가 막는다.

## Ⅱ. 아키텍처 및 핵심 원리

가명정보 결합 활용은 3대 계층(Layer)으로 구현된다. ① 가명정보 **생성** 계층, ② 가명정보 **결합·관리** 계층, ③ 가명정보 **활용·재식별방지** 계층이며, 각 계층은 모두 개인정보보호위원회 고시(제2020-2호 「가명정보 처리 가이드라인」)와 「표준 개인정보 보호 지침」을 따른다.

```text
[가명정보 결합 활용 3계층 아키텍처 + 데이터 흐름]

+---------------------------------------------------------------------+
| LAYER 1. 가명정보 생성 계층 (Data Holder -> Data Trustee)              |
|                                                                     |
|  +----------+  식별자추출  +--------------+  매핑테이블격리  +----+|
|  | 원본 DB  | ------------>|  가명처리모듈  | ---------------->|가명||
|  |(병원/은행|              | ①식별자추출   |  (별도보관함)   |정보||

|         |        가명결합전문기관(KAIT 외)        |                 |
```

| 구성 요소 | 역할 | 핵심 기술 및 동작 방식 |
| :--- | :--- | :--- |
| **데이터 보유기관 (Data Holder)** | 병원·금융사·통신사 등 원본 보유자. 가명처리 후 가명결합전문기관에 결합 요청 | 가명처리 전 **개인정보 영향평가(PIA)** 의무(개인정보보호법 제33조의2), 식별자 12종(성명·주소·전화번호·이메일·IP·MAC·계좌번호·카드번호·생년월일+성별 조합·의료기록번호·CI·DI) 추출 및 **HMAC-SHA256 + 기관별 Salt** 기반 일방향 암호화 |
| **가명결합전문기관 (Data Trustee)** | 한국정보화진흥원(KAIT), 한국데이터산업진흥원 등 공인 결합 중개자. 결합계약서 작성·결합 실행·결합키 관리 | 결합키 생성 시 **양 기관의 가명정보를 동일 알고리즘으로 변환한 후 매칭**, 결합 후 원본 매핑 테이블은 30일 내 파기(결합상한 30일 룰), 결합계약서는 표준양식(개인정보위 고시) 사용 |
| **결합통제기관 (PIPC)** | 가명정보 결합의 안전성 검토·승인·신고 수리·표준양식 보급·연 1회 통합관리체계 평가 | 「가명정보 처리 가이드라인」 제4편 결합편 운영, 결합통제시스템 가이드라인(2022.12), 가명정보 결합시스템 인증(2023~ 시범) |
| **가명정보 활용기관 (Utilizer)** | 연구·통계·상호연계 목적의 최종 사용자 | **내부관리계획 수립 의무**, 가명처리 5대 안전조치(①추가정보 별도 분리·접근통제, ②가명정보 결합 시 결합상한 30일, ③재식별 시도 금지, ④연 1회 가명정보 영향평가, ⑤결합기록 5년 보관) |

### 핵심 알고리즘 및 정량 파라미터

- **k-익명성 (k-Anonymity, Sweeney 2002)**: 동일 속성값(Quasi-Identifier) 집합이 **k개 이상**(개인정보위 가이드라인 권고 k≥5)이어야 재식별 불가. 예) (나이, 성별, 거주지) 트리플렛을 일반화(Generalization)·억제(Suppression) 처리.
- **l-다양성 (l-Diversity, Machanavajjhala 2007)**: 동질 그룹 내 민감속성(Sensitive Attribute) 값이 **l개 이상**으로 분산.
- **t-근접성 (t-Closeness, Li 2007)**: 민감속성 분포가 전체 분포와 거리 ≤ t.
- **차등 프라이버시 (Differential Privacy, Dwork 2006)**: ε-차등프라이버시, 노이즈 캘리브레이션. 한국 통계청 마이크로데이터는 ε≤1.0 적용.
- **HMAC-SHA256 + 기관별 상이 Salt**: 동일 주민번호 입력 시 기관별로 다른 가명식별자 생성 -> **상대방 가명결합 시에도 매핑 실패 -> 세컨더리 가명결합기술 필요**(K-Anon, Bloom Filter, PSNM 등).
- **결합상한 30일 룰**: 매핑 테이블 30일 보존, 이후 자동 파기 (기술적으로는 `cron + shred` 또는 TDE 키 폐기).

### 결합 방식 분류 (기술사 빈출)

1. **일방향 가명결합 (One-way)**: 가명결합전문기관이 결합키 보유, 보유기관은 결합결과만 수령.
2. **상호 가명결합 (Bilateral)**: 양 기관이 동일 가명처리 알고리즘을 적용했으나 Salt가 다를 때, **세컨더리 가명결합(Secondary Pseudonym Matching)** 기법으로 결합.
3. **다자간 가명결합 (Multi-party)**: 3개 이상 기관 참여, 결합전문기관이 가명정보 통합 후 개별 활용기관에 배포.

- **📢 섹션 요약 비유**: 가명정보 결합을 **"색맹안경과 자물쇠"** 에 비유하면, 색맹안경(가명처리)이 색깔(식별자)을 못 보게 하지만 자물쇠 번호(Linkage Key)는 동일하게 유지되어 두 개의 다른 도면(데이터셋)을 정확히 같은 위치끼리 포갤 수 있다. 그런데 두 도면의 자물쇠 번호가 다르면(서로 다른 Salt)에는 **"보조 자물쇠(Secondary Pseudonym)"** 를 써서 번호를 다시 통일시켜야 한다.
