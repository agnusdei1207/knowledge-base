## 핵심 인사이트 (3줄 요약)

> 1. **본질**: IT 경영 관리는 IT 거버넌스(COBIT 2019, ISO 38500), 정보화 사업관리(PMBOK 7th, PRINCE2), 디지털 전환 전략, 정보기술서비스관리(ITIL 4), 사이버보안 거버넌스, 데이터 거버넌스(DAMA-DMBOK) 등 6대 영역을 통합하여 기업 가치를 극대화하는 체계적 프레임워크이다.
> 2. **가치**: 적절한 IT 거버넌스 도입 시 ROI 25~40% 향상, IT 프로젝트 실패율 30%->10% 이하 감소, 정보보안 사고 대응시간 60% 단축, 디지털 전환 성공률 35%->70% 이상 개선의 정량적 효과를 기대할 수 있다.
> 3. **판단 포인트**: 중앙집중형 vs 분산형 거버넌스 모델 선택, Agile vs Plan-driven 방법론, Build vs Buy vs Cloud, Zero Trust vs 경계보안, 스키마온리 vs Lakehouse 아키텍처 등 트레이드오프에서 조직의 성숙도, 규제환경, 산업특성을 종합 판단해야 한다.

---

## Ⅰ. 개요 및 필요성

정보기술이 기업의 핵심 경쟁력이 되면서 IT는 단순한 비용센터(Cost Center)에서 가치창출센터(Value Center)로, 나아가 전략적 파트너(Strategic Partner)로 진화하였다. 4차 산업혁명, 코로나19 이후의 비대면 경제, 생성형 AI의 등장으로 IT 경영 관리의 패러다임은 근본적으로 재편되었고, 전통적인 데이터센터 운영·ERP 구축 차원을 넘어 **디지털 비즈니스 플랫폼, AI 기반 의사결정, ESG-연동 IT, 클라우드 네이티브 아키텍처**로 확장되었다.

기술사 시험에서 다루는 IT 경영 관리는 크게 **① IT 거버넌스 및 전략 기획 ② 정보화 사업 관리 ③ IT 서비스 운영 관리 ④ 정보보안 및 컴플라이언스 ⑤ 데이터 및 AI 거버넌스 ⑥ 디지털 전환과 신기술 도입**의 6대 영역으로 분류된다. 각각의 영역은 COBIT 2019, PMBOK 7th, ITIL 4, ISO 27001/27005, DAMA-DMBOK 2.0, TOGAF 10 등의 글로벌 표준 프레임워크와 연계되며, 기업의 규모·업종·규제환경에 따라 맞춤형으로 적용된다.

과거 IT 관리는 "시스템 안정성"과 "비용 절감"이 최우선이었으나, 현재는 **비즈니스 민첩성(Business Agility)**, **데이터 기반 의사결정(Data-Driven Decision Making)**, **사이버 회복탄력성(Cyber Resilience)**, **ESG 및 지속가능성 IT**, **플랫폼 비즈니스 모델**이라는 5대 핵심 가치로 재정의되었다. 이러한 변화 속에서 기술사는 단순한 기술 도입을 넘어 **경영·기술·사람·프로세스를 아우르는 통합적 판단**을 내려야 한다.

**과거 패러다임 vs 새로운 패러다임 비교:**

| 구분 | 과거 (Legacy IT Management) | 현재 (Digital-First IT Management) |
|:---|:---|:---|
| 조직구조 | IT부서 중심, 계층적 | CDO/CTO/CDSO 등 C-Level, 페어럴렐 |
| 투자관점 | 비용(CapEx), 회계 중심 | 가치(Business Value), 플랫폼 투자 |
| 의사결정 | 경험/직관 기반 Top-Down | 데이터 기반, 옵저버빌리티 기반 |
| 시스템 | 모놀리식, On-Premise | 마이크로서비스, 멀티클라우드 |
| 보안 | 경계기반, Castle & Moat | Zero Trust, SASE/SSE |
| 개발 | Waterfall, 연 1~2회 배포 | Agile/DevOps, 지속적 배포(CD) |
| 거버넌스 | 컴플라이언스 중심 | 비즈니스 임팩트 + 리스크 균형 |
| 데이터 | 데이터웨어하우스, ETL 배치 | Lakehouse, 스트리밍, 데이터 패브릭 |
| 인재 | 기능별 전문가(Silo) | T자형/π자형, Product Owner/SRE |

- **📢 섹션 요약 비유**: IT 경영 관리는 **오케스트라 지휘자**와 같습니다. 바이올린(보안), 첼로(데이터), 트럼펫(서비스), 팀파니(거버넌스) 등 각 악기가 제 역할을 하면서도, 지휘자의 통합적 신호로 하나의 아름다운 음악(기업 가치)을 만들어내야 합니다.

## Ⅱ. 아키텍처 및 핵심 원리

IT 경영 관리의 핵심은 **전략-투자-집행-운영-평가의 Value Loop**를 만드는 것이다. 이를 위해 COBIT 2019의 거버넌스 시스템(Governance System)과 관리 목표(Management Objective)를 기반으로 40개의 거버넌스/관리 목표를 수립하고, 이를 KPI와 직접 연계한다.

**핵심 가치사슬(Value Chain) 동작 원리:**

```text
[IT 거버넌스 가치사슬 및 의사결정 흐름]

  +----------+    +----------+    +----------+    +----------+
  | ① 전략   |---->| ② 투자   |---->| ③ 사업   |---->| ④ 운영   |
  |   기획   |    |   우선   |    |   관리   |    |   관리   |
  |(Plan)    |    |(Priorit.)|    |(Deliver) |    |(Operate) |
  +----------+    +----------+    +----------+    +----------+
       ^                                              |
       |                                              |
       |            +----------+    +----------+       |
       +------------| ⑥ 학습   |<----| ⑤ 성과   |-------+
                   |   개선   |    |   측정   |
                   |(Learn)   |    |(Monitor) |
                   +----------+    +----------+

  [세부 컴포넌트 매핑]

  ① 전략기획 : ISP(Information Strategy Planning) -> EA(Enterprise Architecture)
               -> TOGAF 10 ADM(Architecture Development Method)

  ② 투자우선 : Portfolio Management -> AHP, TOPSIS, BSC
               -> IT Investment Matrix : Risk/Value 2x2

  ③ 사업관리 : PMBOK 7th(8개 Performance Domain) + PRINCE2
               -> Stage Gate Process : Idea->Feasibility->Design->Build->Deploy->Operate

  ④ 운영관리 : ITIL 4 (SVS: Service Value System, 34개 Practice)
               -> DevOps + SRE : DORA 4 Metrics(배포빈도, 리드타임, 변경실패율, MTTR)

  ⑤ 성과측정 : COBIT 2019 (40 Goals) + ISO 38500
               -> KPI Cascade : 전략KPI->프로세스KPI->개인KPI
               -> 인과관계 모델(Kaplan & Norton)

  ⑥ 학습개선 : PDCA + DMAIC + OODA Loop
               -> Knowledge Management : SECI 모델(암묵지↔형식지)
```

**COBIT 2019 거버넌스 시스템 구성요소 (40개 목표 기반):**

| 구성 요소 | 역할 | 핵심 기술 및 동작 방식 |
|:---|:---|:---|
| **Governance Objectives (5개)** | Evaluate, Direct, Monitor (EDM) | 이사회/경영진 관점, 원칙·정책·구조 결정, COBIT 2019 EDM 도메인 (EDM01~05) |
| **Management Objectives (35개)** | Plan, Build, Run, Monitor (PBRM) | Align/Plan/Organize(APO) 14개, Build/Acquire/Implement(BAI) 11개, Deliver/Service(DSS) 6개, Monitor/Evaluate(MEA) 4개 |
| **Components (7가지)** | 거버넌스 시스템 구성 | ① 프로세스 ② 조직구조 ③ 정보흐름 ④ 사람/기술/시설 ⑤ 정책/원칙 ⑥ 문화/윤리/행동 ⑦ 서비스/인프라/애플리케이션 |
| **Design Factors (11개)** | 거버넌스 시스템 맞춤화 | 전략, 목표, 위험, 문제 관련사례, 위협환경, 컴플라이언스, 역할, IT도입 이슈, 기술채택, 조직규모 등 |
| **Focus Area (선택)** | 우선순위 도메인 | DevOps, 사이버보안, 디지털윤리, ESG-IT, 클라우드 거버넌스, AI 거버넌스 등 |
| **Goals Cascade** | 전략-전술-운영 연계 | Stakeholder Needs->Enterprise Goals(13개)->Alignment Goals(13개)->Management Goals(40개) |
