# 668. IT 거버넌스 및 정보화 전략 핵심 토픽 — 시험 요약

---

## 핵심 인사이트 (3줄 요약)

> 1. **본질**: IT 거버넌스(COBIT 2019, ISO 38500)는 **이사회-경영진-IT** 3계층 간 의사결정 권한과 책임(RACI)을 분리하고, **EGM(평가-지침-모니터링)** 사이클로 IT 투자·위험·성과를 통합 관리하는 경영 통제 체계이다.
> 2. **가치**: 체계적 거버넌스 도입 시 IT 투자 ROI 평균 25%^(Gartner 2023), 중복 투자 30~40%v, 핵심 시스템 가용성 99.95% 이상 확보, 컴플라이언스 위반 건수 60%v 효과를 기대할 수 있다.
> 3. **판단 포인트**: **중앙집중형(Federal)** vs **분산형(Federated)** 거버넌스 모델, **계획(Plan) vs 발생(Emergent)** 전략론, **Top-down EA vs Bottom-up BPM** 도입 방식의 trade-off를 조직 역량과 산업 규제 강도에 맞춰 선택해야 한다.

---

## Ⅰ. 개요 및 필요성

### 1.1 배경 및 등장 배경

2010년대 이후 **클라우드·모바일·AI·IoT** 등 4차 산업혁명 기술의 폭발적 확산으로 기업 IT 환경이 **"3V(Volume·Velocity·Variety)"** 특성의 빅데이터 시대로 전환되었다. 한국 정보화진흥원(NIA)의 *2024 정보화白書*에 따르면 국내 500대 기업 평균 **애플리케이션 포트폴리오 320개**, **데이터베이스 480개**, **연간 IT 예산 1,200억원** 수준으로, **시스템 중복(Shadow IT)**, **데이터 사일로(Data Silo)**, **투자 대비 효과 미흡** 문제가 심화되고 있다.

특히 2024년 1월 시행 *공공데이터이용자권리보장제도* 및 EU AI Act 등 규제 강화로 **컴플라이언스·보안·개인정보 통제**가 경영 1차 과제로 부상하면서, 단순 IT 운영을 넘어 **"IT가 어떻게 경영 의사결정에 기여하는가"**에 대한 **거버넌스(Governance)** 프레임워크가 필수 영역이 되었다.

### 1.2 패러다임 변화: IT 관리 -> IT 거버넌스

```text
  +----------------+         +---------------------+
  | 1.0 IT 관리    |         | 2.0 IT 거버넌스      |
  | (1990s)        |   --->   | (2010s~현재)         |
  +----------------+         +---------------------+
  | · 비용중심      |         | · 가치(Value)중심    |
  | · 시스템 단위   |         | · 프로세스·전사 단위 |
  | · CIO 독단 결정 |         | · 이사회 거버넌스위   |
  | · ITIL(운영)   |         | · COBIT+ITIL+ISO    |
  | · CAPEX 일회성 |         | · OPEX+반복 개선     |
  | · 내부 IT부서   |         | · 내부+외부(클라우드) |
  +----------------+         +---------------------+
        |                              |
        v                              v
  "서버가 안 죽어라"             "IT가 매출에 기여하라"
  (안정성)                       (전략적 정렬·가치창출)
```

### 1.3 기술적 과제 4가지

1. **전략 정렬(Strategic Alignment)**: 비즈니스 목표와 IT 투자가 단절, IT가 CFO·CEO 의사결정에서 보이지 않음
2. **가치 전달(Value Delivery)**: IT 프로젝트 70%가 비즈니스 목표 미달적(Standish Group CHAOS Report 2023)
3. **리스크 관리(Risk Management)**: 사이버보안 위협 2023년 전년比 38%^, 랜섬웨어 피해액 평균 5.4억원
4. **자원 관리(Resource Management)**: IT 인력·예산·인프라의 한정 자원을 다수 이해관계자(LOB, B2B, B2C, 규제기관)간 배분

- **📢 섹션 요약 비유**: IT 거버넌스 부재는 마치 **"주방·홀·재무가 각자 다른 레시피로 요리하는 레스토랑"**과 같습니다. 손님(고객)은 음식을, 투자자(이사회)는 수익을, 위생요원(규제기관)은 안전을 요구하는데 **총괄 셰프(거버넌스위원회)**가 없으면 결국 한쪽에서 큰불이 납니다.

## Ⅱ. 아키텍처 및 핵심 원리

### 2.1 IT 거버넌스 3계층 의사결정 구조

```text
  +----------------------------------------------------------+
  |  Tier 1: 이사회 / 거버넌스위원회 (Board / Gov. Committee)|
  |   · 이사 5~9명 중 IT 위원회(1~2명)                       |
  |   · 책임: 방향설정, 승인, 감독                            |
  |   · 산출물: IT Charter, Top-5 리스크 보고서               |
  +----------------------+-----------------------------------+
                         | (의사결정 위임·보고)
                         v
  +----------------------------------------------------------+
  |  Tier 2: 경영진 / IT 전략위원회 (Steering Committee)     |
  |   · CIO + LOB(사업부) 대표 + CFO                         |
  |   · 책임: 우선순위, 예산 배분, 프로젝트 포트폴리오 관리   |
  |   · 산출물: ISP, IT Roadmap, KPI 대시보드                 |
  +----------------------+-----------------------------------+
                         | (집행·운영 위임)
                         v
  +----------------------------------------------------------+
  |  Tier 3: IT 운영조직 (PMO, 서비스데스크, SOC)            |
  |   · 책임: 프로젝트 수행, 서비스 운영, 인시던트 대응       |
  |   · 산출물: SLA 보고서, 변경관리 로그, 보안 모니터링      |
  +----------------------------------------------------------+
        ^                  ^                  ^
        |                  |                  |
   IT위원회           RACI Matrix        감사(Audit)
   (감시)             (책임할당)         (내부·외부)
```

### 2.2 COBIT 2019 핵심 6원칙 & 5도메인

COBIT(Control Objectives for Information and Related Technologies)은 ISACA가 2019년 **6대 거버넌스 시스템 원리**로 재정립한 글로벌 de-facto 표준이다.

| 원칙 | 영문 | 핵심 의미 |
|:---|:---|:---|
| 1 | Stakeholder Needs | 이해관계자 요구를 가치창출 목표로 변환 |
| 2 | End-to-End Coverage | IT 거버넌스를 전사 거버넌스 체계에 통합 |
| 3 | Apply a Single Integrated Framework | COBIT 단일 프레임워크로 중복 제거 |
| 4 | Enabling a Holistic Approach | 7컴포넌트(원리·정책·프로세스·조직·문화·정보·인력) 동시 고려 |
| 5 | Distinguishing Governance & Management | **Governance(평가·지침·모니터링)** vs **Management(계획·구축·운영·모니터링)** 분리 |
| 6 | Tailoring to Enterprise Needs | 위험·역량·규제에 따라 40+ Focus Area로 맞춤 적용 |

**5개 거버넌스 도메인 + 5개 관리 도메인(총 40개 오브젝티브)**:

```text
  Governance Domain (EDM: Evaluate, Direct, Monitor)
  +--------------------------------------------------+
  | EDM01 - 거버넌스 프레임워크 수립                  |
  | EDM02 - 가치 전달 보장                           |
  | EDM03 - 리스크 최적화                            |
  | EDM04 - 자원 최적화                              |
  | EDM05 - 이해관계자 투명성 확보                    |
  +--------------------------------------------------+
                       |
                       v (연결)
  Management Domain (PBRM: Plan, Build, Run, Monitor)
  +--------------------------------------------------+
  | APO(Align, Plan, Organize)  - 14개 목적          |
  | BAI(Build, Acquire, Implement) - 11개 목적        |
  | DSS(Deliver, Service, Support) - 6개 목적         |
  | MEA(Monitor, Evaluate, Assess) - 4개 목적        |
  | (각 도메인 내 5단계: Plan->Acquire->Implement->      |
  |   Deliver->Monitor 활동)                          |
  +--------------------------------------------------+
```

### 2.3 정보화 전략 수립(ISP) 5단계 방법론

한국 **행정안전부 *정보화사업 관리체계(ISM)* v4.0** 기준 정보화 사업은 다음 5단계로 수행된다.

```text
  +------+   +------+   +------+   +------+   +------+
  | 1단계|   | 2단계|   | 3단계|   | 4단계|   | 5단계|
  |ISP수립|--->|분석  |--->|설계  |--->|구축  |--->|운영  |
  |(전략) |   |(As-Is)|  |(To-Be)|  |(구현) |  |(평가) |
  +--+---+   +--+---+   +--+---+   +--+---+   +--+---+
     |          |          |          |          |
     v          v          v          v          v
   ·비전수립   ·현황분석   ·목표아키텍처·시스템개발  ·안정화
   ·과제도출   ·벤치마킹   ·EA(4A)    ·테스트      ·성과측정
   ·로드맵     ·SWOT      ·표준정의   ·이행        ·개선
   ·사업타당성 ·요구분석   ·WBS·RFP   ·교육        ·차기ISP
```

### 2.4 EA(Enterprise Architecture) 4A 프레임워크

| 구성 요소(4A) | 정의 | 산출물 예시 | 핵심 프레임워크 |
|:---|:---|:---|:---|
| **BA** (Business Architecture) | 업무·조직·역할·프로세스 | 비즈니스 캡슐, BPMN 2.0 | Zachman, FEAF |
| **DA** (Data/Information Architecture) | 데이터 모델·마스터·메타 | ERD, 클래스 다이어그램, 데이터 거버넌스 정책 | DAMA-DMBOK, ISO 8000 |
| **AA** (Application Architecture) | 앱 포트폴리오·통합 | 앱 매트릭스, API 카탈로그, TOGAF ADM | TOGAF 10, ArchiMate 3.2 |
| **TA** (Technology Architecture) | 인프라·플랫폼·네트워크 | 서버/네트워크 토폴로지, 기술 표준 | AWS Well-Architected, GCP CAF |

### 2.5 핵심 기법 및 산정 공식

**(1) IT 투자 우선순위 결정: AHP(Analytic Hierarchy Process)**

```
목표: IT 투자 우선순위
+- 기준1: 전략적 가치 (가중치 0.4)
+- 기준2: 위험도 (0.3)
+- 기준3: ROI (0.2)
+- 기준4: 컴플라이언스 (0.1)
     |
     v
쌍대비교 -> 고유벡터 -> 일관성지수(CI) < 0.1 검증
```

**(2) TCO(Total Cost of Ownership) 산정** (Gartner 모델):

```
TCO = Capex + Opex
     = (HW + SW + 구축) + (인력 + 운영 + 교육 + 보안 + 유지보수)
     ≈ 초기투자 × 4~5배 (5년 기준)

예) ERP 100억 도입 -> 5년 TCO 약 480억
```

**(3) BSC(Balanced Score Card) for IT 4관점**:
- 재무관점: IT 예산 준수율, ROI
- 고객관점: 사용자 만족도(NPS), SLA 달성률
- 내부프로세스: 평균복구시간(MTTR), 변경 성공률
- 학습·성장: IT 인력 자격, 지식 자산 활용도

- **📢 섹션 요약 비유**: 거버넌스는 **"비행기의 계기판(COBIT)"** + **"자동조종장치(ISO 38500)"** + **"정비 매뉴얼(TOGAF)"**을 모두 장착하는 것과 같습니다. 파일럿(CIO)만 잘해서는 안 되고, **탑승객(이사회)·관제탑(규제)·지상팀(LOB) 모두가 같은 계기판을 봐야** 안전하게 도착합니다.

### 3.1 주요 IT 거버넌스·관리 프레임워크 비교

| 구분 | COBIT 2019 | ITIL 4 | ISO 38500 | PMBOK 7 | CMMI v2.0 |
|:---|:---|:---|:---|:---|:---|
| **목적** | IT 거버넌스·관리 | IT 서비스 관리 | IT 의사결정 거버넌스 | 프로젝트 관리 | 프로세스 성숙도 |
| **관리 주체** | ISACA | Axelos/PeopleCert | ISO | PMI | ISACA/CMMI Institute |
