## 핵심 인사이트 (3줄 요약)

> 1. **본질**: ISP(Information Strategy Planning)는 경영목표 -> IT 전략 -> 시스템 구축을 연계하는 상위 계층의 정보화 방법론이며, BPR(Business Process Reengineering)은 ISP의 Phase 3(To-Be 설계)에서 As-Is 업무프로세스를 근본적으로 재설계하기 위한 핵심 엔진이다. 5단계(전략기획->현황분석->업무개선->정보화계획->이행계획)로 구성되며, BSC·CSF·KPI·EA·BPMN·IDEF0가 핵심 도구로 활용된다.
> 2. **가치**: 체계적 ISP 수행 시 IT 투자 ROI 20~35% 향상, 업무처리 시간 30~50% 단축, 정보화 사업 실패율(통상 30~60%)을 15% 이하로 축소 가능. 정성적으로는 사일로(Silo) 해체, 핵심역량 집중, 변화관리(Change Management) 기반 확보라는 가치를 제공한다.
> 3. **판단 포인트**: ①BPR의 **혁식적(Radical)** vs **점진적(Incremental)** 접근 선택, ②As-Is 분석의 정밀도(IDEF0 3단 분해 원칙 준수), ③CSF 도출 시 전략-업무-IT 정렬(Alignment) 검증, ④AHP(Analytic Hierarchy Process) 기반 과제 우선순위, ⑤EA·ISP·BPR·BPM·ITIL·COBIT 간 연계 범위 결정이 기술사의 핵심 판단 영역이다.

## Ⅰ. 개요 및 필요성

**ISP(Information Strategy Planning)** 는 1990년대 말 한국 정보화진흥원(현 NIA) 주도로 정립된 한국형 정보화 사업 상위 방법론이다. 정보시스템을 단순 도입·구축하는 것이 아니라, **경영환경 분석 -> 경영전략 -> 정보화 전략 -> 업무/시스템 재설계(BPR) -> 이행**의 연쇄적 과정을 통해 "전략-업무-IT"의 정렬(Strategic Alignment)을 달성하는 것이 본질이다. Zachman EA, Henderson의 SAMM(Strategic Alignment Maturity Model) 등 글로벌 프레임과도 결합되어 활용된다.

**BPR** 은 Hammer & Champy(1993, 『Reengineering the Corporation』)가 제안한 개념으로, "기존 업무를 분업·기능 중심으로 쪼개 사고하지 말고, **프로세스 단위**로 근본적(Radical)이며 비약적(Dramatic)인 성과를 위해 재설계한다"는 경영혁신 방법론이다. TQM·Six Sigma 등 점진적 개선(Continuous Improvement)과 대비되며, BPR의 7원칙 중 핵심은 ①프로세스 중심 사고, ②최대 성과 추구, ③자연스러운 병행처리, ④분권화, ⑤다기능 팀 활용, ⑥다양한 통제 메커니즘, ⑦단일 데이터베이스/공유정보 활용이다.

**필요성**은 세 가지 패러다임 전환에서 기인한다. 첫째, **데이터/시스템 중심 -> 업무/전략 중심**으로 정보화 패러다임이 이동했다. 둘째, **부서별 사일로(Information Silo)** 해체를 통해 End-to-End 프로세스 최적화가 요구된다. 셋째, 4차 산업혁명·DX(Digital Transformation) 환경에서 AI·RPA·클라우드 등 신기술 도입을 위한 비즈니스 모델 재설계가 필수적이다.

기존 정보화 사업은 "시스템이 만들어지면 업무는 저절로 바뀔 것"이라는 **기술 낙관주의(Technological Determinism)** 에 근거해, 시스템 구축 후에도 실제 업무 프로세스는 변하지 않아 투자 회수에 실패하는 사례가 빈번했다(통계적으로 한국 정보화 사업의 30~60%가 정량적 성과 미달). ISP·BPR은 이를 사전에 방지하기 위해 **변화관리(Change Management)** 를 정보화 사업의 일급 시민으로 격상시킨다.

```text
          [기술 낙관주의]                              [전략·업무 중심]
   +-----------------------+                  +-----------------------+
   |  시스템 도입 -> 자동화  |     --전환--->    | 경영목표 -> 전략 -> BPR  |
   |       (하향식)        |                  |   -> 시스템 -> 평가     |
   |                       |                  |       (상향식)         |
   +-----------------------+                  +-----------------------+
       실패율 30~60%                                실패율 15% 이하
                  v
       +-----------------------+
       |   Gap = 30~45%p      |  <- ISP·BPR로 메우는 ROI 손실
       +-----------------------+
```

- **📢 섹션 요약 비유**: ISP는 집을 새로 짓기 전 **설계도**를 그리는 작업이고, BPR는 설계도 안의 **"주방-거실-방이 어떻게 연결되어야 요리가 빨리 나오고 가족이 편할지"** 를 재배치하는 단계입니다. 시스템(벽과 배관)만 보기 시작하면, 사는 사람은 여전히 불편합니다.

## Ⅱ. 아키텍처 및 핵심 원리

ISP는 일반적으로 5단계로 구성되며, 각 단계는 정해진 산출물(Input/Output/Technique) 체계를 가진다. 한국 공공부문(행정안전부, NIA)의 표준 ISP 방법론은 아래와 같다.

```text
+----------------------------------------------------------------------+
|  Phase 1. 전략기획 (Strategy Planning)                               |
|  +--------------+  +--------------+  +--------------+                |
|  |  내부역량    |  |  외부환경    |  |  IT 거버넌스 |                |
|  |  (Value Chain|  | (PEST, 5-   |  | (COBIT, ITIL |                |
|  |   분석)      |  |  Forces)     |  |  Maturity)   |                |
|  +------+-------+  +------+-------+  +------+-------+                |
|         +-----------------+-----------------+                       |
|                            v                                         |
|            SWOT -> CSF 도출 -> BSC -> IT 비전/전략                      |
+----------------------------------------------------------------------+
                                v
+----------------------------------------------------------------------+
|  Phase 2. 현황분석 (As-Is)                                           |
|   • 업무분석: IDEF0 (3단 분해), DFD, AS-IS 업무분장기술서             |
|   • 시스템분석: 시스템 구성도, 데이터 모델(ERD), 인터페이스 분석       |
|   • 데이터분석: 데이터 무결성, 표준화(KS/ISO 11179) 진단               |
|   • 조직/인력: RACI 매트릭스, 인력 역량 Gap                            |
+----------------------------------------------------------------------+
                                v
+----------------------------------------------------------------------+
|  Phase 3. 업무개선 ★ BPR / To-Be 설계  ★  ★  ★  ★  ★              |
|   • 비전·미션 -> To-Be 업무모델                                       |
|   • 핵심프로세스(Core Process) 선정 (CSF ↔ KPI 매핑)                   |
|   • 프로세스 혁신기법: 병행처리(Parallelization), 통합(Integration),  |
|     자동화(Automation), 근본적 사고(Zero-base Thinking)                |
|   • To-Be 산출물: To-Be 업무분장기술서, BPMN 다이어그램, To-Be KPI   |
+----------------------------------------------------------------------+
                                v
+----------------------------------------------------------------------+
|  Phase 4. 정보화 계획 (Information Plan)                              |
|   • 정보화 과제 도출 -> 우선순위 평가(AHP) -> EA 매핑                   |
|   • 시스템 아키텍처(논리/물리), 데이터 아키텍처, 기술 아키텍처         |
|   • 투자계획: TCO, ROI, NPV, IRR (BSG 가이드라인)                     |
+----------------------------------------------------------------------+
                                v
+----------------------------------------------------------------------+
|  Phase 5. 이행 계획 (Implementation)                                  |
|   • 단계별 추진일정 (Master Schedule + WBS)                           |
|   • 리스크 관리(RBS), 의사소통, 변화관리 계획                          |
|   • RFP/사업계획서, 성과지표(KPI) 운영체계                             |
+----------------------------------------------------------------------+
```
