## 핵심 인사이트 (3줄 요약)

> 1. **본질**: IT 경영 관리는 **COBIT 2019, ISO 38500, ITIL 4** 등 글로벌 거버넌스 프레임워크를 기반으로 **전략(Strategy) -> 기획(Planning) -> 구축(Delivery) -> 운영(Operation) -> 평가(Evaluation)** 의 가치 사슬(Value Chain)을 통합 관리하여, 기업의 디지털 전환(DX)과 IT-Biz 정렬(Alignment)을 달성하는 경영 과학임.
> 2. **가치**: McKinsey & Company 연구에 따르면 체계적 IT 거버넌스 적용 기업은 **디지털 전환 성공률 26% -> 70% 이상**으로 향상되며, 프로젝트 실패율(Standish Group CHAOS Report 기준 약 66%)을 **30% 이하**로 축소, TCO(Total Cost of Ownership) 기준 **연 20~35%**의 운영비용 절감 효과 도출.
> 3. **판단 포인트**: 기술사적 관점에서 핵심은 **"거버넌스-관리-기술" 3축 균형** — 중앙집중형(Governance) vs 분권형(Federation),敏捷(Agile) vs 계획주도(Plan-driven), CapEx(전통적 투자) vs OpEx(클라우드 구독형) 등 상충하는 의사결정 프레임의 정량적 비교 분석 능력이 합격의 갈림길.

## Ⅰ. 개요 및 필요성

4차 산업혁명 시대, IT는 더 이상 단순 지원(Support) 기능이 아닌 **비즈니스 핵심 동력(Strategic Differentiator)** 으로 재정의되었습니다. Gartner(2023) 보고에 따르면 글로벌 CEO의 **89%**가 디지털 비즈니스를 핵심 의제로 채택했으나, 동시에 **DX 실패율 60~70%**의 딜레마가 존재합니다. 이는 "기술 부족"이 아닌 **"IT 경영 관리 역량 부재"**에서 기인하며, 이를 해결하기 위해 **IT 거버넌스·IT 서비스 관리·프로젝트 관리·정보보안·컴플라이언스**를 통합한 체계적 접근이 필수적입니다.

```text
+--------------------------------------------------------------+
|          IT 경영 관리 5대 도메인 통합 프레임워크              |
|                                                              |
|  +------------+  +------------+  +------------+             |
|  |  Strategy  |-> |  Planning  |-> |   Build    |             |
|  |  전략기획  |  |  요구분석  |  |  구축/개발  |             |
|  |  (BSC,EA)  |  |  (RFP,ISP) |  | (SDLC,Agile)|            |
|  +-----+------+  +-----+------+  +-----+------+             |
|        |               |               |                    |
|        v               v               v                    |
|  +----------------------------------------------+            |
|  |   Governance Layer (거버넌스 거버닝 체계)     |            |
|  |   COBIT 2019 · ISO 38500 · 정보화사업 관리법  |            |
|  +----------------------------------------------+            |
|        |               |               |                    |
|        v               v               v                    |
|  +------------+  +------------+  +------------+             |
|  |  Operate   |<- |  Evaluate  |<- |   Run      |             |
|  |  서비스운영 |  |  성과평가  |  |  안정화/QA  |             |
|  | (ITIL 4)  |  | (BSC,KPI) |  | (DevOps)   |             |
|  +------------+  +------------+  +------------+             |
|                                                              |
|  ★ 핵심 가치사슬:  Strategy --> Value --> Outcome            |
+--------------------------------------------------------------+
```

**왜 필요한가? — 패러다임 비교**

| 구분 | 전통적 IT 관리 (Pre-2010) | 현대 IT 경영 관리 (2024~) |
| :--- | :--- | :--- |
| 관점 | IT는 비용(Cost Center) | IT는 가치 창출(Value Driver) |
| 구조 | 수직적 사일로 (Dev-Ops 분리) | 수평적 DevSecOps·SRE 통합 |
| 거버넌스 | 컴플라이언스 중심 (규제 준수) | 가치 중심 (Agility + Risk 균형) |
| 투자 | CapEx (자체 데이터센터) | OpEx (클라우드, SaaS 구독) |
| 의사결정 | CIO 독점적 | CDO·CISO·CFO 공동 의사결정 |

- **📢 섹션 요약 비유**: IT 경영 관리는 마치 **도시의 종합 교통 시스템**과 같습니다. 단순히 도로(인프라)만 잘 만드는 것이 아니라, 신호 체계(거버넌스), 버스 노선(서비스), 안전 관리(보안), 시민 피드백(평가)까지 통합 설계해야 정체(병목·실패) 없는 스마트 시티가 완성됩니다.

## Ⅱ. 아키텍처 및 핵심 원리

IT 경영 관리 아키텍처는 국제 표준을 기반으로 한 **3-Layer Governance Architecture**로 구성됩니다. 최상위 **거버넌스(Governance)** 계층은 ISO 38500의 "**Evaluate-Direct-Monitor**" 원칙을 따르며, 중간 **관리(Management)** 계층은 COBIT 2019의 40개 관리 목표(Management Objective)와 5개 도메인을, 최하위 **운영(Operation)** 계층은 ITIL 4의 34개 서비스 관리 실무(SMP) 및 18개 프로세스로 연결됩니다.

```text
+-------------------------------------------------------------+
|  Layer 1: Governance (거버넌스) — "무엇을, 왜 할 것인가"     |
|  +------------------------------------------------------+  |
|  |  ISO 38500 EDM Cycle                                 |  |
|  |  +---------+   +---------+   +---------+            |  |
|  |  |Evaluate |--->| Direct  |--->| Monitor |--+         |  |
|  |  |성과평가  |   |방향제시  |   |모니터링  |  |         |  |
|  |  +---------+   +---------+   +---------+  |         |  |
|  |       ^------------------------------------+         |  |
|  +------------------------------------------------------+  |
|                          <-> 정책/지표/리스크                  |
|  Layer 2: Management (관리) — "어떻게 할 것인가"             |
|  +------------------------------------------------------+  |
|  |  COBIT 2019 — 5 Domains, 40 Objectives              |  |
|  |  EDM | APO | BAI | DSS | MEA                        |  |
|  |  거버 |정렬  |구축  |운영  |평가                       |  |
|  +------------------------------------------------------+  |
|                          <-> SLA/OLA/UC                      |
|  Layer 3: Operation (운영) — "실제 실행과 측정"               |
|  +------------------------------------------------------+  |
|  |  ITIL 4 Service Value Chain                          |  |
|  |  Plan->Engage->Design&Transition->Obtain/Build->         |  |
|  |  Deliver&Support->Improve                             |  |
|  +------------------------------------------------------+  |
+-------------------------------------------------------------+
```

| 구성 요소 | 역할 | 핵심 기술 및 동작 방식 |
| :--- | :--- | :--- |
| **EDM (Evaluate-Direct-Monitor)** | 최고 의사결정층 거버넌스 | ISO 38500 기반, 이사회-경영진 책임, 책임·전략·획득·성과·규율·행위 원칙 적용 |
| **COBIT 2019** | IT 통제 목표 체계 | 5개 도메인(EDM, APO, BAI, DSS, MEA) × 40개 관리목표, RACI 매트릭스, 설계인자(Design Factors) 11종 |
| **ITIL 4** | 서비스 운영 실무 | 7개 guiding principle(Focus on value, Start where you are 등), 34 practices, Service Value System(SVS) |
| **BSC (Balanced Scorecard)** | 전략 성과 측정 | 4관점(재무·고객·내부·학습/성장), Kaplan-Norton 프레임워크, Strategy Map 인과관계 매핑 |
| **KGI/KPI/CSFs** | 정량 성과지표 | KGI(목표달성지표), KPI(성과측정지표), CSF(핵심성공요소) 3계층 cascading 구조 |

**핵심 알고리즘/원리: BSC 인과관계 모델**

```
성과 = Σ(관점별 가중치 × 달성률)
       ① 재무    (Financial)     : ROI, NPV, TCO, CapEx/OpEx Ratio
       ② 고객    (Customer)      : NPS(순추천지수), SLA 준수율, CSAT
       ③ 내부    (Internal)      : 변경 성공률, MTTR, 변경 리드타임
       ④ 학습성장 (Learning/Growth): 직원 역량지수, 직원 만족도, 지식자산지수
```

**EA(Enterprise Architecture) 연관 원리**: TOGAF 10 ADM(Architecture Development Method) — **Preliminary->A(아키텍처 비전)->B(비즈니스)->C(정보시스템)->D(기술)->E(기회모색)->F(마이그레이션)->G(구현거버넌스)->H(아키텍처 변경관리)** 8단계 사이클.

- **📢 섹션 요약 비유**: 거버넌스 3계층은 마치 **건물의 설계도-시공도-점검표**와 같습니다. ISO 38500은 도시 계획(설계도), COBIT은 건축 시방서(시공도), ITIL은 시설 관리 매뉴얼(점검표)이며, 이 세 문서가 일치하지 않으면 건물(IT 시스템)은 균열(실패)을 일으킵니다.

## Ⅲ. 비교 및 연결

IT 경영 관리의 핵심 프레임워크들은 **상호 보완적** 관계에 있으며, 혼동하기 쉬운 유사 개념들과의 비교가 시험에 빈번히 출제됩니다.

| 구분 | COBIT 2019 | ITIL 4 | ISO 38500 | PMBOK 7 |
| :--- | :--- | :--- | :--- | :--- |
| **주 목적** | IT 거버넌스/관리 통합 | IT 서비스 관리(서비스 운영) | IT 거버넌스 표준 (이사회 가이드) | 프로젝트 관리 지식체계 |
| **대상 계층** | 경영진·IT 관리자 | IT 실무자·운영자 | 이사회·최고경영층 | 프로젝트 매니저 |
| **범위** | 전략~운영 전 영역 | 운영·서비스 중심 | 거버넌스(고수준) 원칙 | 프로젝트 단위 |
| **핵심 산출물** | 40개 관리목표, 설계인자 | 34개 Practices, SVS | EDM 사이클, 6원칙 | 8개 Performance Domain, 12원칙 |
| **상호관계** | ITIL·PMBOK과 매핑 | COBIT DSS 도메인과 연동 | COBIT EDM과 직결 | COBIT BAI 도메인과 연동 |

**연계 시스템 아키텍처**:

```text
+------------------------------------------------------------+
|                  통합 거버넌스 체계 매핑                     |
|                                                            |
|   ISO 38500  <---정책/원천--->  COBIT 2019  <---매핑--->  ITIL 4
|   (이사회)        원칙       (경영/관리)      연계      (운영)
|      |                       |                       |   |
|      |                       v                       |   |
|      |                +--------------+                |   |
|      |                |   PMBOK 7    |                |   |
|      |                |   (프로젝트)  |                |   |
|      |                +------+-------+                |   |
|      |                       |                        |   |
|      +-----------------------+------------------------+   |
|                              v                            |
|                    +------------------+                    |
|                    |  Agile / DevOps  |                    |
|                    |  (실행방법론)     |                    |
|                    +------------------+                    |
|                              |                            |
|                              v                            |
|                    +------------------+                    |
|                    |   KPI 대시보드   |  <- 실시간 모니터링  |
|                    +------------------+                    |
+------------------------------------------------------------+
```

**연계 기술·도구**: SAP GRC (거버넌스·리스크·컴플라이언스 통합), ServiceNow ITSM (ITIL 4 인증 도구), Jira/Confluence (Agile 프로젝트), Microsoft Power BI (BSC 대시보드), ARIS (EA 모델링), ArchiMate (TOGAF 표현언어).

- **📢 섹션 요약 비유**: COBIT은 **교향악단 전체 악보**, ITIL은 **각 악기 연주 매뉴얼**, ISO 38500은 **지휘자의 철학**, PMBOK은 **특정 곡(프로젝트) 연주법**과 같습니다. 지휘자(ISO 38500) 없이 악보(COBIT)만 있으면 곡의 방향을 잃고, 매뉴얼(ITIL) 없이는 실제 소리가 어긋나며, 연주법(PMBOK)이 없이는 특정 곡(프로젝트)을 완성할 수 없습니다.

## Ⅳ. 실무 적용 및 기술사 판단

기술사 시험은 단순 암기가 아닌 **"현실 제약 조건 하의 최적 의사결정"**을 평가합니다. 실무에서는 이론적 프레임워크가 **조직 문화·예산·인력·기술 성숙도**라는 4가지 제약과 부딪히며, 다음 의사결정 트리가 핵심입니다.

### 기술사형 판단 체크리스트

1. **거버넌스 구조 선택**: 조직 규모(500인 이상)·규제업종(금융/공공) 여부에 따라 **중앙집중형(Governance-as-a-Service) vs 분권형(Federated CoE)** 를 결정하라. 금융기관·공공기관은 원칙적 중앙집중, 다국적·다사업장은 분권형 + CoE(센터오브엑셀런스) 권장.
2. **Agile vs Plan-driven 비율 산정**: 프로젝트 성격(신규/유지보수), 불확실성(High/Low), 규제 수준(High/Low)에 따라 Stacey Matrix 기반으로 **Agile-Waterfall-Hybrid** 비율을 산정하라. 예: 금융 신상품은 Waterfall 60% + Agile 40% Hybrid 최적.
3. **클라우드 전환 판단**: 6R 전략(Rehost, Replatform, Refactor, Repurchase, Retire, Retain) 중 **TCO 3년 회수율**, **데이터 주권**, **종속성(Vendor Lock-in)** 을 정량 비교하여 선정하라. Gartner Magic Quadrant, AWS Well-Architected 5대 원칙 활용.
4. **정보보안 투자 정당화**: ROSI(Return on Security Investment) = (ALE × 감소율 - ACS) / ACS 공식을 적용, ALE(연간손실기대치), ACS(연간보안통제비용) 기반 경영진 설득용 ROI 산출.
5. **성과 측정 정합성**: BSC 4관점 간 **인과관계(Lead-Lag Indicator)** 를 명확히 하고, KPI는 **SMART 원칙(Specific, Measurable, Achievable, Relevant, Time-bound)** 준수 여부를 검증하라. 예: "고객 만족도 향상"(구체성 부재) ✗ -> "분기별 NPS 10pt 향상" ✓
