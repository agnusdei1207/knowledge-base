## 핵심 인사이트 (3줄 요약)

> 1. **본질**: IT 경영 관리(정보화 사업 관리)는 **ISP(정보화전략계획) → 정보시스템 감리 → 성과평가(BSC·KPI) → 거버넌스(COBIT·ISO 38500)**로 이어지는 V-Model 기반의 전주기(End-to-End) 관리 체계이며, 발주자 관점의 **사업관리(PMO·품질·일정·변경·리스크)**와 통제 관점의 **감리·감사**가 양대축을 이룬다.
> 2. **가치**: 체계적 적용 시 **사업 실패율 약 30%↓, 요구사항 추적성 100% 확보, TCO 20~40% 절감, 감사 적정 판정률 95% 이상**을 달성할 수 있으며, 정량적 KPI(예: 가용성 99.9%, MTTR ≤ 30분, 결함밀도 ≤ 0.5/KLOC)와 정성적 BSC(재무·고객·내부프로세스·학습성장) 균형을 통해 **투자대비성과(ROI) 150~300%**를 기대할 수 있다.
> 3. **판단 포인트**: **자체개발 vs 패키지(ERP) vs SaaS**, **기능중심 vs 데이터중심 아키텍처**, **Waterfall vs Agile(DevOps)** 중哪一个를 선택할지는 조직의 **SI 거버너런스 성숙도(Level 1~5)**, 데이터 표준화 수준, 그리고 **SLA 등급(bronze/silver/gold/platinum)**에 따라 결정하며, 기술사는 **발주자-사업자-감리인** 3자 간 책임·권한·통신(Communication) 프로토콜을 명확히 분리하는 것이 핵심이다.

---

## Ⅰ. 개요 및 필요성

정보화 사업은 **① 막대한 예산(수십억~수천억 원)**, **② 다수 이해관계자(발주청, 사업자, 감리인, 사용자)**, **③ 복잡한 기술 스택(legacy mainframe → cloud-native)**, **④ 장기 운영(10~20년)**이라는 특성으로 인해 **일반 건설사업보다 리스크가 2~3배 높다**. 한국 정보화진흥원(NIA) 통계에 따르면 정보화 사업의 **약 35%가 예산 초과, 25%가 일정 지연, 15%가 사용자 불만족** 상태로 종료된다. 이를 해결하기 위해 **「정보시스템의 효율적 도입 및 운영 등에 관한 법률」(이하 '정보화사업법')**과 **「클라우드컴퓨팅법」** 하에서 **ISP 수립 → 사업 착수 → 감리 → 평가**의 전주기 관리 체계가 의무화되어 있다.

특히 **2020년 이후 메가트렌드**(AI·클라우드·데이터3법·원격근무) 가속화로 **전통적 Waterfall 감리 모델로는 Agile·DevOps 환경의 연속배포(Continuous Delivery)를 통제할 수 없는 문제**가 대두되었고, **2022년 NIA 「정보시스템 감리 안내서」 개정**으로 **Agile 감리 가이드라인**, **클라우드 보안 인증(CSAP)**, **데이터 거버넌스** 항목이 추가되었다.

```text
┌──────────────────────────────────────────────────────────────────────┐

│                                                                      │
│   ┌────────┐    사업발주    ┌──────────┐   ISP승인   ┌──────────┐   │
│   │  발주청 │ ───────────▶ │ 사업자선정 │ ─────────▶ │  ISP수립  │   │

│   │  성과평가 │ ◀──── │  시운전   │ ◀──── │  개발구축 │ ◀──── │  감리인 ││
```

**기존(As-Is) vs 신규(To-Be) 패러다임 비교**
- **As-Is**: 하드웨어 중심(Compute-bound), 문서 중심(MS Word 명세서), 연 1~2회 배포, 감리 시점=완료 후 사후검증, 내부 SI 의존도 80%
- **To-Be**: 클라우드·데이터 중심(Cloud-native, Data-driven), GitOps·IaC(Terraform/Ansible) 기반 **불변 인프라**, **주 1~일 100회 배포(CI/CD)**, **전 과정 상시 감리(Continuous Audit)**, **내부+외부 하이브리드 운영(FinOps·AIOps 도입)**

- **📢 섹션 요약 비유**: IT 경영 관리는 **인테리어 공사의 설계·자재·시공·감리·하자보수** 전 과정을 다루는 것과 같다. 좋은 도면(ISP) 없이 공사를 시작하면 나중에 벽을 뜯어내고 다시 배관하는 것과 같이 **사업 재작업(Re-work) 비용이 전체의 30~50%**를 차지하게 된다.

## Ⅱ. 아키텍처 및 핵심 원리

IT 경영 관리 아키텍처는 크게 **① 의사결정 거버넌스 계층**, **② 사업 관리(PMO) 계층**, **③ 통제·감리 계층**, **④ 기술·운영 계층**의 4-tier로 구성된다. 기술사 시험에서는 이 4계층이 어떻게 **요구사항 → 설계 → 구현 → 검증 → 운영**의 V-Model을 통해 추적성(Traceability)을 유지하는지 설명할 수 있어야 한다.

```text
┌──────────────────────────────────────────────────────────────────────┐
│          IT 경영 관리 4-Tier 아키텍처 (발주자 관점)                   │
├──────────────────────────────────────────────────────────────────────┤
│                                                                      │
│ ┌─────────────────────────────────────────────────────────────────┐ │
│ │ [Tier 1] 의사결정 거버넌스 계층 (Steering Committee)            │ │
│ │  구성: CIO(의장), 사업부장, 법무·재무·감사, 외부자문(Advisory)   │ │
│ │  산출물: IT-Strategy Map, 거버넌스 헌장, 투자우선순위(Portfolio) │ │
│ │  프레임워크: COBIT 2019 EDM(40 Governance Objectives)          │ │
│ └─────────────────────────────────────────────────────────────────┬─┘ │
│                                                                   │   │
│                        ▼ 결정/지시(Decisions)                    │   │
│ ┌─────────────────────────────────────────────────────────────────┴─┐ │

│ │  기능: WBS·일정·예산·품질·리스크·변경·이행·계약·커뮤니케이션   │ │
│ │  방법론: PMBOK 7th(원칙 기반) + PRINCE2(7 Process)              │ │
│ │  도구: MS Project, JIRA, Confluence, OKR Dashboard              │ │
│ │  KPI: SPI(Schedule), CPI(Cost), EAC, ETC, TCPI                │ │
│ └─────────────────────────────────────────────────────────────────┬─┘ │
│                                                                   │   │
│                        ▼ 통제(Control)                            │   │
│ ┌─────────────────────────────────────────────────────────────────┴─┐ │
│ │ [Tier 3] 통제·감리 계층 (Control & Audit)                      │ │
│ │  ·감리: 착수·중간·완료 3단계 (NIA 「감리 안내서」 §4)         │ │

│ │  ·컴플라이언스: 개인정보보호법, 정보통신망법, 클컴법           │ │

│                        ▼ 실행(Execution)                          │   │

│ │ [Tier 4] 기술·운영 계층 (Technical Operations)                 │ │
│ │  ·방법론: SDLC, Agile(Scrum/Kanban), DevOps, MLOps            │ │
│ │  ·아키텍처: MSA(Microservice), EDA(Event-Driven), Serverless   │ │
│ │  ·인프라: K8s, Service Mesh(Istio), Observability(Prometheus)  │ │
│ │  ·데이터: Data Lake(△/▢/λ), 거버넌스·품질·메타관리           │ │
│ └───────────────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────────────┘
```

| 구성 요소 | 역할 | 핵심 기술 및 동작 방식 |
| :--- | :--- | :--- |
| **CIO / 이사회(Steering Committee)** | IT 투자·리스크의 최종 의사결정, 정렬(Alignment) | COBIT 2019 EDM 5개 영역(Governance System 40 Objectives 중 EDM 05), **투자대비성과(ROI/NPV/IRR)** 평가, **EA(Enterprise Architecture) 원칙** 수립 (TOGAF ADM 사이클) |
| **PMO / 사업관리** | WBS·일정·예산·품질·리스크·변경·계약·소통 통합관리 | PMBOK 7th의 **8대 성과영역(Stakeholder, Team, Development Approach, Planning, Project Work, Delivery, Measurement, Uncertainty)**, PRINCE2의 **7 Principle·7 Process·7 Theme**, **임계값 관리(±10% SPI/CPI 시 경보)**, **EVM(Earned Value Management)**: EV=PV×%완성, CV=EV-AC, SV=EV-PV |
| **감리인(제3자 통제)** | 발주자 보호, 사업 품질·법령 적합성 검증 | NIA 「정보시스템 감리 안내서」 **5개 영역**(사업·요구사항·설계·구현·시험) × **3개 관점**(적합성·적정성·효과성), **방법론**: 문서검토+현장실태조사+인터뷰+샘플링, **결함 분류**: 치명/중요/경미/권고 |
| **운영·서비스 관리(ITIL v4)** | 서비스 카탈로그, 인시던트, 변경, 지속적 개선 | **34개 Practice**(중심: Incident, Problem, Change Enablement, Service Desk, SLM), **CSI(Continual Service Improvement)** 모델, **SLA 4등급**: Bronze(99.5%)/Silver(99.9%)/Gold(99.95%)/Platinum(99.99%), **가용성 계산**: `(1 - 다운타임/총시간) × 100%`, **MTTR ≤ 30분, MTBF ≥ 720시간** 권고 |

**핵심 산식·개념**
- **EVM(Earned Value)**: `CPI = EV/AC`, `SPI = EV/PV`, `EAC = BAC/CPI`, `TCPI = (BAC-EV)/(BAC-AC)` (CV<0이면 사업비 초과 확정)
- **가용성(Availability, A)**: `A = MTBF / (MTBF + MTTR) × 100%`. 99.99%(Four Nine) ⇒ 연간 허용 다운타임 52.6분
- **결함밀도(Defect Density)**: `D = 결함수/KLOC`, 일반적 허용치 0.5~1.0/KLOC, 미션 크리티컬 0.1 이하
- **요구사항 추적성 매트릭스(RTM)**: `요구사항ID ↔ 설계ID ↔ 코드ID ↔ 테스트ID` 100% 매핑, 누락 시 감리 부적합
- **BSC 4관점 가중치 예시**: 재무 25% + 고객 25% + 내부프로세스 30% + 학습성장 20%, SMART 원칙(Specific·Measurable·Achievable·Relevant·Time-bound) 적용

- **📢 섹션 요약 비유**: 4-Tier 아키텍처는 **도시계획(거버넌스) → 시공관리(PMO) → 안전감리(감리) → 건축기술(기술운영)**이 층층이 연결된 **건축행정 체계**와 같다. 어느 한 층이 무너지면 건물 전체의 안전이 위협받는다.

## Ⅲ. 비교 및 연결

IT 경영 관리의 핵심 개념들은 서로 경쟁·보완 관계에 있다. 기술사 시험에서는 **무엇이 왜 적합한지 정량적 근거**와 함께 비교 설명할 수 있어야 한다.

| 구분 | **Waterfall(전통적) 감리** | **Agile·DevOps 감리** |
| :--- | :--- | :--- |
| **방법론 기반** | 정보화사업법, NIA 감리 안내서(2014) | NIA 「Agile 감리 가이드」(2022), DevOps Audit Cookbook |
| **배포 주기** | 연 1~2회(Big-Bang Release) | 일 1~수십 회(Continuous Deployment) |
| **감리 시점** | 완료 후 사후검증(Post-audit) | 스프린트 단위 상시검증(Continuous Audit) |
| **산출물** | 문서 80% + SW 20% (문서 중심) | 실행 SW 80% + 테스트/문서 20% (실증 중심) |
| **요구사항 변경** | 변경관리위원회(CCB) 승인 필요, 평균 처리 2~4주 | Backlog 우선순위 재조정, **변경 허용(Embrace Change)** |
