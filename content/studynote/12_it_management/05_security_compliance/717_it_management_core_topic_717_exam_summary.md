## 핵심 인사이트 (3줄 요약)

> 1. **본질**: IT 경영관리는 COBIT 2019·ITIL 4·ISO/IEC 38500 표준체계 하에서 거버넌스-관리-운영 3계층 분리 원칙으로, IT 전략(Strategy)->구조(Structure)->프로세스(Process)->기술(Technology)을 정렬(Value Alignment)하는 경영시스템이다.
> 2. **가치**: 정량적으로는 IT 투자 ROSC(Return on Scope of Capital) 25~40% 개선·정보화사업 실패율 50%->18% 저감(Standish CHAOS 2023 기준), 정성적으로는 전략적 민첩성(Strategic Agility) 확보·이해관계자 신뢰도 제고·디지털 컴플라이언스 자동화를 달성한다.
> 3. **판단 포인트**: ① 거버넌스 표준 중복 vs 통합(COBIT+ITIL 매핑 비용) ② 정량 KPI(ROI/NPV) vs 정성 BSC(전략관점) 비중 ③ 중앙집중(CoE) vs 분권형(BizDevOps) IT조직 모델 ④ Agile/DevOps 도입 시 거버넌스 통제 강도 유지의 균형이 핵심 결정 변수다.

## Ⅰ. 개요 및 필요성

글로벌 디지털 전환(DX) 가속화 속에서 IT는 비용센터(Cost Center)에서 전략자산(Strategic Asset)·플랫폼 비즈니스(Platform Business)·데이터 자산으로 패러다임이 전환되었다. 한국 공공부문 연간 정보화사업 예산은 약 8조 원(2024년 디지털정부 품질관리 시행지침 기준)에 달하며, 민간 D/AX 투자까지 합산하면 GDP 대비 IT 투자의 비중은 약 8.4%(2023년 KISDI 통계)로 OECD 평균 6.1%를 상회한다. 그러나 Standish Group CHAOS Report 2023에 따르면 글로벌 정보화사업 성공률은 약 31.1%(2020년 31.1% -> 2023년 다소 변동)에 불과하며, 한국 정보시스템감사 결과 매년 100여 건의 미흡사항이 지적된다. 이는 ① 사업 타당성 분석 부실 ② 이해관계자 정렬 실패 ③ 성과측정 부재 ④ 사후운영·평가 미흡 ⑤ 거버넌스 공백이 근본 원인으로 작용한다.

IT 경영관리는 이를 해결하기 위해 `전략-투자-수행-운영-평가`의 5단계 가치사슬(Value Chain)을 통합 관리하며, 특히 PDCA(Plan-Do-Check-Act) 사이클을 **거버넌스 수준(Board/Executive)**과 **관리 수준(PMO/Process Owner)**·**운영 수준(DevOps/Service Desk)**로 분리하여 운영하는 것이 핵심이다.

```text
+-----------------------------------------------------------------------------+
|             IT 경영관리 가치사슬 (IT Management Value Chain)                 |
+-----------------------------------------------------------------------------+
|                                                                             |
|  +----------+    +----------+    +----------+    +----------+    +--------+|
|  | ①전략    |---->| ②투자    |---->| ③수행    |---->| ④운영    |---->|⑤평가  ||
|  | Strategy |    | Investment|    |Delivery  |    |Operation |    |Eval   ||
|  +----------+    +----------+    +----------+    +----------+    +--------+|
|       |              |              |              |              |        |
|       v              v              v              v              v        |
|  +---------+    +---------+    +---------+    +---------+    +---------+  |
|  |BSC·CSF |    |TCO·ROI  |    |PMBOK·   |    |ITIL 4·  |    |KPI·    |  |
|  |EA·COBIT|    |NPV·IRR  |    |Agile    |    |SLA·OLA |    |BPM·    |  |
|  |거버넌스 |    |사업성   |    |DevOps   |    |관측성   |    |BSC     |  |
|  +---------+    +---------+    +---------+    +---------+    +---------+  |
|                                                                             |
|   <----- 3계층 거버넌스 체계(Board/Executive -> Management -> Operational) ---> |
|                                                                             |
|   +------------------------------------------------------------------+     |
|   | 외부환경: ISO 38500(거버넌스) · ISO 27001(보안) · ISO 20000(서비스) |     |
|   |          ISMS-P · GDPR · ESG · 전자정부법 · 클라우드컴퓨팅법      |     |
|   +------------------------------------------------------------------+     |
+-----------------------------------------------------------------------------+
```

과거 패러다임(1990~2000년대)은 **기술 중심·프로젝트 단발성·CAPEX 일회성 평가**였다면, 현재 패러다임(2020~현재)은 **가치 중심·포트폴리오·반복적 평가·OPEX/Subscription 모델·데이터 기반 의사결정**으로 전환되었다. 특히 클라우드·AI/ML·Zero Trust·SaaS 기반 구독경제가 보편화되면서, IT 자산의 정의가 하드웨어/소프트웨어에서 데이터·알고리즘·플랫폼·인재(스킬)로 확장되었다.

- **📢 섹션 요약 비유**: IT 경영관리는 마치 **크루즈 선박의 항해 시스템**과 같다. 거버넌스는 나침반(COBIT/ISO 38500)으로 방향을 잡고, 관리는 엔진룸의 제어시스템(PMBOK/Agile)이며, 운영은 실제로 바다를 가르며 나가는 프로펠러와 같다. 어느 한 부분이 작동하지 않으면 배는 표류하거나 침몰한다.

## Ⅱ. 아키텍처 및 핵심 원리

IT 경영관리의 3계층 참조 모델(Three-Layer Reference Model)은 국제 표준과 산업 Best Practice를 정합화한 핵심 아키텍처다.

```text
+----------------------------------------------------------------------------+
|           IT 경영관리 3계층 아키텍처 (IT Management 3-Layer Model)         |
+----------------------------------------------------------------------------+
|                                                                            |
|  +--------------------------------------------------------------------+  |
|  |  Layer 1: 거버넌스 (Governance) — "무엇을(What)·왜(Why)할 것인가"  |  |
|  |  ---------------------------------------------------------------   |  |
|  |   • 의사결정기구: IT전략위원회 / Steering Committee                |  |
|  |   • 책임원칙: RACI 매트릭스 (Responsible/Accountable/Consulted/    |  |
|  |               Informed)                                            |  |
|  |   • 표준: COBIT 2019, ISO/IEC 38500, ISO/IEC 27014                |  |
|  |   • 핵심활동: 전략정렬·위험관리·자원배분·성과감시·이해관계자가치   |  |
|  |   • 입력: 미션·비전·전략·규제 / 출력: 정책·원칙·예산한도·KPI     |  |
|  +--------------------------------------------------------------------+  |
|                              | 위임·정렬(Align)                            |
|                              v                                            |
|  +--------------------------------------------------------------------+  |
|  |  Layer 2: 관리 (Management) — "어떻게(How) 수행할 것인가"          |  |
|  |  ---------------------------------------------------------------   |  |
|  |   • PMO: 프로젝트·프로그램·포트폴리오 오피스                       |  |
|  |   • 표준: PMBOK 7, PRINCE2, ISO 21502, BABOK, BPM CBOK           |  |
|  |   • 핵심프로세스:                                |                  |
|  |     - 기획(ISMS-P 정보화사업 5단계: 계획/분석/설계/구축/운영)      |  |
|  |     - 경제성평가(TA: 기술적·경제적·법률적·정치적 분석)             |  |
|  |     - 조달·계약·공급자관리(SRM)                                   |  |
|  |     - 품질·리스크·변경·이슈·형상관리                              |  |
|  |   • 산출물: 사업계획서·WBS·일정·예산·품질계획·리스크대응책        |  |
|  +--------------------------------------------------------------------+  |
|                              | 실행·운영(Operate)                          |
|                              v                                            |
|  +--------------------------------------------------------------------+  |
|  |  Layer 3: 운영 (Operation) — "일상적(Everyday) 가치를 어떻게"      |  |
|  |  ---------------------------------------------------------------   |  |
|  |   • 서비스운영: IT 서비스 데스크 / SOC / NOC                      |  |
|  |   • 표준: ITIL 4 (34개 Practice), ISO/IEC 20000, DevOps           |  |
|  |   • 핵심영역:                                                     |  |
|  |     - 서비스전략·설계·전환·운영·지속적개선(CSI)                   |  |
|  |     - SLA(서비스수준협약)·OLA(운영수준협약)·UC(Underpinning)      |  |
|  |     - 인시던트·문제·변경·릴리스·구성·지식관리                     |  |
|  |     - AIOps·옵저버빌리티(Prometheus/Grafana/ELK)·SRE              |  |
|  +--------------------------------------------------------------------+  |
|                                                                            |
|  <-> 양방향 피드백: Layer 1 -> KPI/리스크 보고, Layer 3 -> 관측성/사고 보고  |
+----------------------------------------------------------------------------+
```

| 구성 요소 | 역할 | 핵심 기술 및 동작 방식 |
| :--- | :--- | :--- |
| **거버넌스 의사결정기구** (IT Steering Committee) | IT-사업 정렬·최종 승인·예산 의결 | 분기별 운영위원회 / ESM(Enterprise Service Management) 대시보드로 KPI 보고 / 정족수(Quorum) ⅔ 이상 의사결정 |
| **PMO (Project/Program/Portfolio Office)** | 프로젝트 포트폴리오 우선순위·자원배분·리스크 통합관리 | PPMS(Project & Portfolio Management System) — Planview / Clarity PPM / ServiceNow SPM / Microsoft PPM — 사용, EVM(Earned Value Management) 기반 CPI/SPI 측정 |
| **COBIT 2019 거버넌스 체계** | 40개 거버넌스·관리 목표(GOAL) 매핑 | 디자인 팩터 11개(전략·목표·리스크·위험문제·역량·규제·기술·산업·조직·문화·메서드) 기반 맞춤형 Governance System 설계 |
| **ITIL 4 Service Value System (SVS)** | 운영 가치사슬(Value Chain) 통한 가치공급 | 6개 활동(Plan/Improve/Engage/Design&Transition/Obtain&Build/Deliver&Support) + 34개 Practice + 7개 원칙(Guide) |
| **BSC (Balanced Scorecard)** | 4관점 성과측정·전략 실행 | 재무(Financial)/고객(Customer)/내부프로세스(Internal Process)/학습성장(Learning & Growth) — 인과관계도(Strategy Map) 기반 |
| **TCO/ROI 분석 엔진** | 투자대비성과 정량평가 | CAPEX(초기투자) + OPEX(운영비용) + Risk-adjusted Cost — NPV(순현재가치), IRR(내부수익률), Payback Period(투자회수기간), CFROI, EVA, BSC Score |
| **ITSM 도구 스택** | 운영 자동화·관측·품질 | ServiceNow ITSM / Jira Service Management / BMC Remedy / Freshservice + Prometheus + Grafana + ELK + Sentry + PagerDuty |
