## 핵심 인사이트 (3줄 요약)

> 1. **본질**: OWASP Top 10(2021)은 OWASP(Open Worldwide Application Security Project)가 전 세계 수십만 개 애플리케이션의 실제 취약점 데이터를 분석하여 웹 애플리케이션에서 가장 빈번하고 위험한 10가지 보안 위험 범주를 선정한 업계 표준 보안 가이드라인이다.
> 2. **가치**: OWASP Top 10은 개발팀, 보안팀, 경영진이 공통으로 사용하는 '웹 보안의 공통 언어'로, 보안 교육, 코드 리뷰 기준, 취약점 점검 체크리스트, 규정 준수 요건 충족의 기준점으로 활용된다.
> 3. **판단 포인트**: OWASP Top 10을 외우는 것이 목적이 아니라, 각 위험의 근본 원인을 이해하고 내 서비스에 어떤 항목이 가장 적용되는지 맥락적으로 분석하는 능력이 핵심이다.

## Ⅰ. 개요 및 필요성

### OWASP와 Top 10의 역사

OWASP(Open Web Application Security Project)는 2001년 마크 커핀이 설립한 비영리 오픈소스 재단이다. 웹 애플리케이션 보안의 공개 표준과 도구를 개발하는 것을 목적으로 한다. 2003년에 최초의 OWASP Top 10이 발표되었고, 이후 2004, 2007, 2010, 2013, 2017, 2021년에 업데이트되었다.

2021년 버전은 이전과 달리 3가지 새로운 범주가 추가되고, 기존 항목들이 통합·재분류되었다. 특히 데이터 기반 분석(실제 취약점 건수)과 커뮤니티 설문 조사(신흥 위험)를 결합한 방식으로 더욱 현실적인 목록이 완성되었다.

### 왜 OWASP Top 10이 중요한가

웹 애플리케이션 보안 위협은 너무 다양하여 "모든 것을 방어하라"는 전략은 비현실적이다. OWASP Top 10은 "80%의 공격이 20%의 취약점 유형에서 발생한다"는 파레토 원칙을 보안에 적용한 것이다. 이 10가지를 먼저 해결하면 대부분의 일반적인 공격을 방어할 수 있다.

또한 PCI DSS(결제 카드 산업 데이터 보안 표준), SOC 2, ISO 27001 등 주요 보안 규정들이 OWASP Top 10을 구현 요건의 기준으로 참조한다. 한국의 KISA 소프트웨어 개발보안 가이드도 OWASP를 기반으로 한 49가지 취약점 항목을 정의하고 있다.

- **📢 섹션 요약 비유**: 교통사고의 80%가 과속, 음주운전, 신호 위반 등 소수의 원인에서 비롯되듯, 웹 보안 사고의 대부분도 OWASP Top 10이 다루는 소수의 취약점 유형에서 비롯된다.

### 10가지 취약점 범주 상세 설명

| 순위 | 취약점명 | 핵심 문제 | 주요 방어 기법 |
|:---|:---|:---|:---|
| A01 | 취약한 접근 제어 | 인가 로직 부재·우회 | 서버 측 권한 검사, 최소 권한 원칙 |
| A02 | 암호화 오류 | 민감 데이터 평문 전송·저장 | TLS 강제, AES-256, 안전한 해시 |
| A03 | 인젝션 | 신뢰되지 않은 데이터 명령어 삽입 | 파라미터화 쿼리, ORM, 입력 검증 |
| A04 | 안전하지 않은 설계 | 설계 단계 보안 결함 | 위협 모델링, 시큐어 디자인 패턴 |
| A05 | 보안 설정 오류 | 기본값 사용, 불필요한 기능 활성화 | CIS 벤치마크, 구성 자동화 |
| A06 | 취약한 컴포넌트 | 알려진 취약점이 있는 라이브러리 | SCA 도구, SBOM 관리 |
| A07 | 인증 실패 | 약한 비밀번호, 세션 관리 오류 | MFA, 강력한 세션 관리 |
| A08 | 무결성 실패 | 신뢰되지 않은 업데이트·플러그인 | 코드 서명, 공급망 보안 |
| A09 | 로깅·모니터링 실패 | 보안 사고 미탐지 | SIEM, 중앙화 로깅, 알림 |
| A10 | SSRF | 서버가 내부 자원에 위조 요청 | 요청 대상 화이트리스트, 방화벽 |

### 2017 → 2021 변경 사항

| 2017년 순위 | 2021년 순위 | 변경 내용 |
|:---|:---|:---|
| A1. 인젝션 | A3 | 1위에서 3위로 하락 (발생률 감소) |
| A2. 취약한 인증 | A7 | 순위 하락 |
| - | A1. 취약한 접근 제어 | 1위로 신규 등장 |
| - | A4. 안전하지 않은 설계 | 신규 추가 (2021 특이점) |
| - | A8. SW·데이터 무결성 실패 | 공급망 보안 위협 반영 |
| - | A10. SSRF | 클라우드 환경 위협 반영 |

## Ⅲ. 비교 및 연결

### OWASP Top 10 vs CWE Top 25

| 구분 | OWASP Top 10 | CWE Top 25 |
|:---|:---|:---|
| 관리 | OWASP 재단 | MITRE 기관 |
| 대상 | 웹 애플리케이션 | 소프트웨어 일반 |
| 단위 | 취약점 범주(넓음) | 특정 취약점 유형(세밀함) |
| 활용 | 보안 정책·교육 기준 | 개발 코딩 기준 |
| 연계 | OWASP A03(인젝션) = CWE-89(SQL 인젝션) 등 매핑 가능 |

### OWASP Top 10 활용 맥락

| 활용 영역 | 구체적 활용 방법 |
|:---|:---|
| 개발 교육 | 신입 개발자 보안 교육의 필수 커리큘럼 |
| 코드 리뷰 | 리뷰 체크리스트로 활용 |
| 보안 테스트 | 각 항목별 테스트 케이스 작성 기준 |
| 규정 준수 | PCI DSS, KISA 가이드 준수 증거 |
| 아키텍처 검토 | 설계 단계 보안 검토 기준점 |

### 설계 판단 체크리스트

1. **서비스의 특성에 맞는 OWASP 항목을 우선순위화했는가?** - 금융 서비스는 A02(암호화)와 A07(인증)이 최우선, 공공 API는 A01(접근 제어)과 A10(SSRF)이 중요하다.
2. **OWASP Top 10이 KISA 49개 취약점과 어떻게 매핑되는지 확인했는가?** - 전자정부 시스템은 KISA 가이드가 법적 의무이며, OWASP와 겹치는 항목이 많다.
3. **SAST 도구가 OWASP Top 10 항목을 커버하는지 확인했는가?** - 도구마다 커버하는 CWE 목록이 다르다. OWASP와 매핑된 규칙이 활성화되어 있어야 한다.
4. **A04(안전하지 않은 설계)를 위협 모델링으로 대응하는가?** - 이 항목은 SAST/DAST로 탐지하기 어렵다. 설계 단계 위협 모델링이 유일한 효과적 대응이다.
5. **A06(취약한 컴포넌트)을 위한 SCA와 SBOM이 있는가?** - Log4Shell(CVE-2021-44228) 같은 오픈소스 취약점은 SCA 없이는 파악조차 불가능하다.

### 안티패턴

- **Top 10 전부 동시 완벽 대응 추구**: 10가지를 동시에 완벽하게 해결하려다가 아무것도 완성하지 못하는 경우. 서비스 특성에 맞는 2-3개를 먼저 집중 해결하는 것이 현실적이다.
- **Top 10 = 전체 보안이라는 오해**: OWASP Top 10을 모두 충족하면 보안이 완벽하다는 착각. Top 10은 최소 기준선이며, 서비스 특성에 따른 추가 보안 요건이 반드시 있다.
- **개발팀 vs 보안팀 분리**: "OWASP Top 10은 보안팀이 알아야 할 것"으로 인식하는 경우. Top 10의 대부분은 개발자가 코딩 단계에서 예방해야 하며, 보안팀 혼자로는 한계가 있다.
- **버전 업데이트 무시**: 2017년 Top 10을 아직도 기준으로 사용하는 경우. SSRF(A10)와 안전하지 않은 설계(A04) 같은 2021 신규 항목을 놓치게 된다.

- **📢 섹션 요약 비유**: 운전면허 필기시험 문제집이 매년 업데이트되듯, OWASP Top 10도 위협 환경 변화에 따라 갱신된다. 오래된 버전으로 공부하면 현재 위험을 놓친다.

## Ⅴ. 기대효과 및 결론

OWASP Top 10을 체계적으로 적용하는 조직에서 나타나는 효과는 명확하다. 첫째, 보안 논의의 공통 언어가 생긴다. 개발자가 "A01 취약점이 있습니다"라고 말하면 경영진도 그 심각성을 이해할 수 있다. 둘째, 규정 준수 대응이 쉬워진다. PCI DSS 6.3.1조항(OWASP 기반 취약점 점검 요건)처럼 OWASP를 직접 요구하는 규정 준수 증거로 활용된다. 셋째, 신규 개발자의 보안 온보딩이 표준화된다. Top 10을 교육 과정에 포함시키면 빠르게 보안 마인드셋을 형성할 수 있다.

OWASP Top 10은 5년마다 업데이트되지만, 인젝션이나 접근 제어 같은 근본적인 취약점 유형은 수십 년간 반복되고 있다. 이는 역설적으로 "기초가 가장 중요하다"는 사실을 보여준다. 최신 AI 보안 도구나 자동화 솔루션도 OWASP Top 10의 기초가 해결되지 않으면 무의미하다.

결론적으로 OWASP Top 10은 "웹 보안의 알파이자 오메가"다. 처음 보안을 시작하는 팀에게는 시작점이고, 성숙한 보안 조직에게는 기준선이며, 규정 준수를 준비하는 팀에게는 검증 도구가 된다.

- **📢 섹션 요약 비유**: 기초 체력 운동(push-up, squat, plank)이 모든 운동의 기반인 것처럼, OWASP Top 10은 모든 웹 보안의 기초다. 화려한 기술 전에 기초가 탄탄해야 한다.

### 👶 어린이를 위한 3줄 비유 설명

1. OWASP Top 10은 "웹 사이트를 만들 때 가장 많이 실수하는 보안 문제 10가지 목록"이에요. 마치 학교에서 "학생들이 가장 자주 틀리는 수학 문제 유형 10가지"를 모아둔 것과 같아요.
2. 이 10가지만 조심해도 대부분의 나쁜 사람들이 웹 사이트를 공격하는 방법을 막을 수 있어요.
3. 전 세계 많은 회사들이 이 목록을 기준으로 프로그램을 점검하고, 5년마다 새로운 위험이 생기면 목록을 업데이트해요!
