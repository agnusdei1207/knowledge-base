## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 소프트웨어 공학은 시스템 구축 전 과정을 구조화해 품질, 일정, 유지보수성을 통제하는 과목이다.
> 2. **가치**: 요구사항에서 아키텍처, 테스트, 데브옵스(DevOps)까지 연결해야 실전형 답안의 흐름이 완성된다.
> 3. **판단 포인트**: 인공지능(AI) 기반 개발, 데브섹옵스(DevSecOps), 클라우드 네이티브 품질 통제를 함께 설명해야 한다.

## Ⅱ. 왜 시험 핵심인가

- 기술사 답안은 기술 자체보다 "어떻게 개발하고 통제할 것인가"를 묻는 경우가 많아 소프트웨어 공학이 서술의 틀을 제공한다.
- 요구사항 누락, 설계 결함, 테스트 부실, 운영 배포 실패를 하나의 생명주기 관점으로 설명할 수 있어야 한다.
- 조직, 프로세스, 아키텍처, 품질지표를 한 번에 다루므로 고득점형 종합 서술 문제와 궁합이 좋다.
- 최근에는 생성형 인공지능(Generative AI) 활용 개발과 거버넌스까지 포함해 응용 범위가 넓어지고 있다.

## Ⅳ. 단답형 / 서술형 분리 포인트

- 단답형: 생명주기(SDLC), 응집도/결합도, 설계원칙, 테스트 수준, 형상관리 용어를 명확히 구분
- 서술형: 요구사항에서 배포까지의 통제 흐름, 품질 속성 간 상충관계, 아키텍처 의사결정 근거를 단계형으로 설명
- 답안 기준: "요구 → 설계 → 구현 → 검증 → 운영" 축을 유지하면 심사위원이 구조를 즉시 파악할 수 있다.

## Ⅴ. 최신 기술 동향 연결

- 개발 방식: 생성형 인공지능 기반 코딩 보조, 프롬프트 엔지니어링, AI 테스트 자동화
- 운영 품질: 데브섹옵스(DevSecOps), 소프트웨어 공급망 보안(SBOM, SLSA), 지속적 검증
- 아키텍처: 클라우드 네이티브, 서비스 메시(Service Mesh), 이벤트 주도 아키텍처(Event-Driven Architecture)
- 관리 체계: 플랫폼 엔지니어링, 내부 개발자 플랫폼(IDP), 가치 흐름 관리(Value Stream Management)
