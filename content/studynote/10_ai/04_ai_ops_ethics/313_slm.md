## 핵심 인사이트 (3줄 요약)

> 1. **본질**: SLM (Small Language Model, 소형 언어 모델)은 수십억 파라미터 이하의 경량 언어 모델로, [지식 증류](/knowledge-base/studynote/14_data_engineering/05_exam_keywords/252_knowledge_distillation_quantization_edge_slm_diffusion/)·[양자화](/knowledge-base/studynote/01_computer_architecture/12_accelerators_ai_hardware/434_quantization/)·효율적 아키텍처 설계를 통해 클라우드 없이 온디바이스(스마트폰, 엣지 서버, [PC](/knowledge-base/studynote/01_computer_architecture/04_instruction_set_architecture/164_pc/)) 환경에서 실시간 [AI](/knowledge-base/studynote/04_software_engineering/03_design_architecture/190_ai_llm_requirements_specification/) 추론을 수행하는 모델이다.
> 2. **가치**: 네트워크 없는 환경, [데이터](/knowledge-base/studynote/05_database/01_db_architecture_relational/001_dikw_pyramid/) 프라이버시 필수 환경(의료기기, 군사·보안), 낮은 [지연](/knowledge-base/studynote/03_network/01_data_communication/015_지연_데이터_관점/)시간(Low [Latency](/knowledge-base/studynote/01_computer_architecture/03_architecture_basics_performance/141_latency/)) 필수 환경(자율주행, 로봇)에서 LLM이 대체할 수 없는 영역을 담당하며 [AI](/knowledge-base/studynote/04_software_engineering/03_design_architecture/190_ai_llm_requirements_specification/) 활용의 다변화를 이끈다.
> 3. **판단 포인트**: SLM의 [성능](/knowledge-base/studynote/04_software_engineering/05_devops_ci_cd/282_performance_tactics/)은 파라미터 수보다 <strong>학습 <a href="/knowledge-base/studynote/05_database/01_db_architecture_relational/001_dikw_pyramid/">데이터</a>의 품질과 다양성</strong>, <strong>효율적 아키텍처(<a href="/knowledge-base/studynote/09_security/17_framework_compliance/864_phi/">Phi</a>, Mistral 등)</strong>, <strong>특화된 증류 방식</strong>에 더 크게 의존하며, "작지만 강한" SLM이 특정 [태스크](/knowledge-base/studynote/02_operating_system/02_process_thread/150_task/)에서 LLM을 능가하는 사례가 증가하고 있다.

## Ⅰ. 개요 및 필요성

ChatGPT([GPT](/knowledge-base/studynote/10_ai/04_ai_ops_ethics/302_gpt_autoregressive/)-4)는 수조 개의 파라미터를 수백~수천 대의 A100 [GPU](/knowledge-base/studynote/01_computer_architecture/12_accelerators_ai_hardware/418_gpu/) 클러스터에서 실행한다. 스마트폰에서 절대 동작할 수 없다. 그러나 현실에는 클라우드에 연결할 수 없는 수많은 [AI](/knowledge-base/studynote/04_software_engineering/03_design_architecture/190_ai_llm_requirements_specification/) 응용 시나리오가 있다.

- 비행기·지하·해저 환경에서 [AI](/knowledge-base/studynote/04_software_engineering/03_design_architecture/190_ai_llm_requirements_specification/) 번역·요약
- 의료기기에서 환자 [데이터](/knowledge-base/studynote/05_database/01_db_architecture_relational/001_dikw_pyramid/)를 외부 클라우드로 전송 불가 시 로컬 진단
- 자율주행 차량에서 10ms 미만 반응이 필요한 실시간 판단
- 오프라인 작동이 필수인 국방·보안 [AI](/knowledge-base/studynote/04_software_engineering/03_design_architecture/190_ai_llm_requirements_specification/) 시스템

<strong>SLM (Small Language Model)</strong>은 이 요구를 충족하기 위해 1B~7B 파라미터 수준에서 LLM에 근접한 [성능](/knowledge-base/studynote/04_software_engineering/05_devops_ci_cd/282_performance_tactics/)을 달성하도록 설계된 경량 언어 모델이다.

```text
+----------------------------------------------+
| Background Problem -> Need -> Adoption Value   |
+----------------------------------------------+
| Existing limitation | Operational pressure   |
| New requirement     | Design decision point  |
+----------------------------------------------+
```

- **📢 섹션 요약 비유**: LLM이 도심 대형 병원(클라우드, 강력하지만 멀고 느림)이라면, SLM은 동네 의원(온디바이스, 빠르고 가깝지만 전문성 제한)이다. 감기(일상 NLP [태스크](/knowledge-base/studynote/02_operating_system/02_process_thread/150_task/))는 동네 의원으로 충분하고 더 빠르다. 암 수술(복잡한 추론)은 대형 병원이 필요하다. 용도에 맞는 선택이 핵심이다.

## Ⅱ. 아키텍처 및 핵심 원리

```text
+------------------------------------------------------------------+
|         SLM 생태계 주요 모델 비교 (2024 기준)                         |
+------------------------------------------------------------------+
|                                                                  |
|  +---------------------------------------------------------+    |
|  |  모델명      | 파라미터 | 개발사   | 특징                    |    |
|  +---------------------------------------------------------+    |
|  |  Phi-3 Mini  |   3.8B  | Microsoft| 고품질 교과서 데이터 학습  |    |
|  |  Phi-4       |   14B   | Microsoft| 수학·추론 특화            |    |
|  |  Gemma 2B    |    2B   | Google   | 오픈소스, 온디바이스 최적화|    |
|  |  Llama 3.2   |   1~3B  | Meta     | 오픈소스, 멀티모달 지원   |    |
|  |  Mistral 7B  |    7B   | Mistral  | GQA로 추론 가속          |    |
|  |  EXAONE 3.0  |   2.4B  | LG AI    | 한국어 특화 SLM          |    |
|  +---------------------------------------------------------+    |
|                                                                  |
|  SLM 성능 향상 핵심 기법:                                           |
|  ① 고품질 데이터 필터링 (Quality over Quantity)                    |
|     - 인터넷 전체 크롤링 대신 교과서·논문급 고품질 텍스트만 사용           |
|  ② 지식 증류 (Knowledge Distillation)                             |
|     - GPT-4 등 LLM의 출력으로 합성 훈련 데이터 생성                  |
|  ③ GQA (Grouped Query Attention, 그룹 쿼리 어텐션)                |
|     - Key-Value 헤드 수를 줄여 추론 메모리·속도 최적화                |
|  ④ Sliding Window Attention                                     |
|     - 긴 시퀀스에서 모든 위치 대신 슬라이딩 윈도우 내 어텐션만 계산      |
+------------------------------------------------------------------+
```

| 배포 환경 | 권장 SLM 크기 | [양자화](/knowledge-base/studynote/01_computer_architecture/12_accelerators_ai_hardware/434_quantization/) | 사용 기기 |
|:---|:---|:---|:---|
| 스마트폰 (4~8GB RAM) | 1~3B | INT4 | Android/iOS |
| 엣지 서버 (16~32GB) | 7B | INT8 | 산업용 [PC](/knowledge-base/studynote/01_computer_architecture/04_instruction_set_architecture/164_pc/), 의료기기 |
| 고성능 [PC](/knowledge-base/studynote/01_computer_architecture/04_instruction_set_architecture/164_pc/) (32~64GB) | 13~14B | INT8/FP16 | 노트북, 워크스테이션 |
| 자율주행 칩 | 1~3B 특화 | INT4 | NVIDIA Orin, 퀄컴 |

- **📢 섹션 요약 비유**: GQA (Grouped Query Attention)는 회의실 축소 [전략](/knowledge-base/studynote/04_software_engineering/04_testing_quality/268_strategy_pattern/)이다. 일반 MHA([Multi-Head Attention](/knowledge-base/studynote/10_ai/04_ai_ops_ethics/299_multi_head_attention/))는 모든 어텐션 헤드가 개별 [Key](/knowledge-base/studynote/05_database/02_modeling_normalization/067_db_key_uniqueness_minimality/)-Value 방을 가지지만, GQA는 여러 헤드가 [Key](/knowledge-base/studynote/05_database/02_modeling_normalization/067_db_key_uniqueness_minimality/)-Value 방을 공유한다. 개인 사무실(MHA) 대신 공유 오피스(GQA)로 바꿔 공간(메모리)을 절약하면서 업무(어텐션 계산)는 그대로 [진행](/knowledge-base/studynote/02_operating_system/03_cpu_scheduling/216_progress_in_synchronization/)한다.

## Ⅲ. 비교 및 연결

<strong><a href="/knowledge-base/studynote/06_ict_convergence/04_ai_llm/263_llm_large_language_model/">LLM</a> vs SLM 선택 기준</strong>:
| 요구사항 | [LLM](/knowledge-base/studynote/06_ict_convergence/04_ai_llm/263_llm_large_language_model/) | SLM |
|:---|:---|:---|
| 복잡한 다단계 추론 | 우세 | 제한적 |
| 특정 [도메인](/knowledge-base/studynote/05_database/02_modeling_normalization/064_relation_domain/) 특화 | [파인 튜닝](/knowledge-base/studynote/10_ai/04_ai_ops_ethics/304_fine_tuning/) 필요 | [파인 튜닝](/knowledge-base/studynote/10_ai/04_ai_ops_ethics/304_fine_tuning/) 효율적 |
| 온디바이스 배포 | 불가 | 가능 |
| 비용 | 높음 ([API](/knowledge-base/studynote/02_operating_system/01_overview_architecture/014_api_posix/) 과금) | 낮음 (자체 배포) |
| 프라이버시 | [데이터](/knowledge-base/studynote/05_database/01_db_architecture_relational/001_dikw_pyramid/) 외부 전송 | 완전 로컬 처리 |
| [지연](/knowledge-base/studynote/03_network/01_data_communication/015_지연_데이터_관점/)시간 | [네트워크 지연](/knowledge-base/studynote/03_network/20_performance_evaluation_advanced/1002_network_delay_rtt_oneway_delay_components/) 있음 | 즉시 응답 |

- **📢 섹션 요약 비유**: [LLM](/knowledge-base/studynote/06_ict_convergence/04_ai_llm/263_llm_large_language_model/) vs SLM 선택은 데스크톱 vs 스마트폰 선택과 같다. 영상 편집(복잡한 추론)은 데스크톱, 카카오톡(일상 NLP)은 스마트폰이 적합하다. 두 기기가 서로를 대체하는 게 아니라 용도가 다른 것처럼, LLM과 SLM도 상호 보완적 [관계](/knowledge-base/studynote/05_database/02_modeling_normalization/083_relationship_in_er_model/)다.

## Ⅳ. 실무 적용 및 기술사 판단

**SLM 도입 아키텍처 패턴**:
1. **순수 온디바이스**: SLM만 기기에서 실행 (최고 프라이버시, 가장 제한적 [성능](/knowledge-base/studynote/04_software_engineering/05_devops_ci_cd/282_performance_tactics/))
2. **하이브리드 (On-Device + Cloud)**: 단순 [태스크](/knowledge-base/studynote/02_operating_system/02_process_thread/150_task/)는 SLM, 복잡한 [태스크](/knowledge-base/studynote/02_operating_system/02_process_thread/150_task/)는 [LLM](/knowledge-base/studynote/06_ict_convergence/04_ai_llm/263_llm_large_language_model/) [API](/knowledge-base/studynote/02_operating_system/01_overview_architecture/014_api_posix/) [라우팅](/knowledge-base/studynote/03_network/07_network_layer_routing/339_routing_overview_best_path_selection/)
3. **엣지-클라우드 협력**: 엣지 SLM이 1차 처리, 필요 시 클라우드 LLM에 보강 요청

<strong>Microsoft의 <a href="/knowledge-base/studynote/09_security/17_framework_compliance/864_phi/">Phi</a> 시리즈 성공 요인</strong>: "더 많은 [데이터](/knowledge-base/studynote/05_database/01_db_architecture_relational/001_dikw_pyramid/)"가 아닌 "더 좋은 [데이터](/knowledge-base/studynote/05_database/01_db_architecture_relational/001_dikw_pyramid/)"로 작은 모델도 강해질 수 있다는 것을 증명. 교과서·코딩 튜토리얼·수학 문제집처럼 밀도 높은 지식이 담긴 [합성 데이터](/knowledge-base/studynote/09_security/16_data_privacy/818_synthetic_data/)로 학습한 [Phi](/knowledge-base/studynote/09_security/17_framework_compliance/864_phi/)-3 Mini(3.8B)가 7B~13B 모델을 능가하는 [성능](/knowledge-base/studynote/04_software_engineering/05_devops_ci_cd/282_performance_tactics/)을 달성했다.

- **📢 섹션 요약 비유**: 하이브리드 아키텍처는 회사 내 온사이트 팀(SLM)과 외부 컨설팅([LLM](/knowledge-base/studynote/06_ict_convergence/04_ai_llm/263_llm_large_language_model/))의 협업이다. 일상 업무(단순 NLP)는 온사이트 팀이 즉시 처리하고, 전문적 [전략](/knowledge-base/studynote/04_software_engineering/04_testing_quality/268_strategy_pattern/) 결정(복잡한 추론)은 외부 컨설팅에 의뢰한다. 모든 것을 컨설팅에 맡기는 것보다 비용이 1/10로 줄면서 핵심 사안에서 최고 품질을 유지한다.

## Ⅴ. 기대효과 및 결론

SLM은 AI를 클라우드 서버실에서 해방시켜 모든 곳에 AI가 있는([AI](/knowledge-base/studynote/04_software_engineering/03_design_architecture/190_ai_llm_requirements_specification/) Everywhere) 미래를 실현하는 핵심 기술이다. 스마트폰의 [AI](/knowledge-base/studynote/04_software_engineering/03_design_architecture/190_ai_llm_requirements_specification/) 어시스턴트, 자동차의 음성 [AI](/knowledge-base/studynote/04_software_engineering/03_design_architecture/190_ai_llm_requirements_specification/), 병원 의료기기의 진단 [AI](/knowledge-base/studynote/04_software_engineering/03_design_architecture/190_ai_llm_requirements_specification/), 공장 로봇의 자연어 제어 등 오프라인·실시간·프라이버시 필수 환경에서 SLM의 활용도는 LLM과 다른 차원에서 폭발적으로 증가할 것이다.

- **📢 섹션 요약 비유**: SLM의 등장은 AI의 "전기 공급 혁명"이다. 처음 전기는 발전소([LLM](/knowledge-base/studynote/06_ict_convergence/04_ai_llm/263_llm_large_language_model/) 클라우드)에서만 쓸 수 있었지만, 배터리(SLM)가 발명되면서 전기를 들고 다니며 어디서나 쓸 수 있게 됐다. AI도 이제 서버실에서 꺼내어 손 안의 기기로, 자동차 안으로, 수술실 안으로 들어간다.

### 👶 어린이를 위한 3줄 비유 설명

1. <strong>SLM(소형 언어 모델)</strong>은 ChatGPT처럼 똑똑하지만 **스마트폰에서도 돌아갈 만큼 작은** AI예요!
2. 인터넷 없이도, [데이터](/knowledge-base/studynote/05_database/01_db_architecture_relational/001_dikw_pyramid/)를 서버로 보내지 않고도 **기기 안에서 바로** 번역, 요약, 대화를 할 수 있어요.
3. Microsoft의 [Phi](/knowledge-base/studynote/09_security/17_framework_compliance/864_phi/), Google의 Gemma, Meta의 Llama 같은 **작지만 강한 AI들이** 스마트폰·자동차·의료기기를 지능화하고 있어요!
