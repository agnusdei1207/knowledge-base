## Ⅰ. 회선 제어 규약의 개요와 [분류](/studynote/16_bigdata/05_analysis/104_classification_analysis/)

회선 제어 규약(Line Control [Protocol](/studynote/03_network/06_network_layer_ip/295_protocol_field_tcp_udp_icmp/))은 <strong>물리 링크 위에서 <a href="/studynote/05_database/01_db_architecture_relational/001_dikw_pyramid/">데이터</a> 전송을 <a href="/studynote/04_software_engineering/10_trends_pm_quality/642_reliability_mtbf_mttr_mttf_availability/">신뢰성</a> 있게 수행</strong>하기 위한 규약이다. 크게 문자 지향(Character-Oriented)과 [비트](/studynote/01_computer_architecture/02_data_representation_arithmetic/073_bit/) 지향(Bit-Oriented) 방식으로 [분류](/studynote/16_bigdata/05_analysis/104_classification_analysis/)된다.

| [분류](/studynote/16_bigdata/05_analysis/104_classification_analysis/)          | 대표 [프로토콜](/studynote/03_network/06_network_layer_ip/295_protocol_field_tcp_udp_icmp/) | 특징                          |
|-------------|-------------|-------------------------------|
| 문자 지향     | [BSC](/studynote/12_it_management/01_governance_strategy/019_bsc/)         | 제어 문자(STX/ETX) 기반        |
| [비트](/studynote/01_computer_architecture/02_data_representation_arithmetic/073_bit/) 지향     | [HDLC](/studynote/03_network/04_data_link_layer_error/216_hdlc_high_level_data_link_control/), [SDLC](/studynote/12_it_management/04_sdlc_testing/131_sdlc_system_development_life_cycle_waterfall_agile/)  | [플래그](/studynote/03_network/04_data_link_layer_error/186_character_stuffing_dle_stx_etx/)(01111110) 기반 프레임   |
| [바이트 카운트](/studynote/03_network/04_data_link_layer_error/185_byte_counting_framing/) | DDCMP       | 헤더에 [바이트](/studynote/01_computer_architecture/02_data_representation_arithmetic/074_byte/) 수 명시          |

### 회선 제어 5대 기능

1. **회선 접속** — [논리](/studynote/09_security/04_endpoint_security/369_logic_bomb/)적 연결 [설정](/studynote/15_devops_sre/01_culture_methodology/009_config/) (Setup)
2. **동기 제어** — [비트](/studynote/01_computer_architecture/02_data_representation_arithmetic/073_bit/)/문자/프레임 동기 맞춤
3. <strong><a href="/studynote/03_network/04_data_link_layer_error/213_flow_control_buffer_overflow/">흐름 제어</a></strong> — 수신자 버퍼 넘침 방지
4. <strong><a href="/studynote/03_network/04_data_link_layer_error/188_error_control_overview/">오류 제어</a></strong> — [CRC](/studynote/01_computer_architecture/02_data_representation_arithmetic/113_crc/) 검출 + [ARQ](/studynote/03_network/19_frequent_topics_terms/949_arq_automatic_repeat_request_go_back_n_selective/) 재전송
5. **회선 해제** — 전송 완료 후 [논리](/studynote/09_security/04_endpoint_security/369_logic_bomb/) 연결 해제

📢 **섹션 요약 비유**: 회선 제어 규약은 도로 교통 법규와 같다. [신호](/studynote/02_operating_system/02_process_thread/130_signal/)(동기), 차선([흐름 제어](/studynote/03_network/04_data_link_layer_error/213_flow_control_buffer_overflow/)), 사고 처리([오류 제어](/studynote/03_network/04_data_link_layer_error/188_error_control_overview/)), 진입/진출(접속/해제) 규칙이 모두 포함된다.

## Ⅱ. [BSC](/studynote/12_it_management/01_governance_strategy/019_bsc/) (Binary [Synchronous](/studynote/03_network/01_data_communication/010_동기식_비동기식_전송/) Communication)

BSC는 IBM이 1960년대 개발한 <strong>문자 지향 반이중 <a href="/studynote/03_network/06_network_layer_ip/295_protocol_field_tcp_udp_icmp/">프로토콜</a></strong>이다.

```
[STX] [데이터] [ETX] [BCC]
 시작   본문   종료  오류검사
```

| 제어 문자 | 의미                    |
|----------|------------------------|
| STX      | 본문 시작 (Start of Text) |
| ETX      | 본문 종료 (End of Text)  |
| ENQ      | 회선 [확인](/studynote/04_software_engineering/12_testing_maintenance/396_validation/) 요청            |
| ACK      | 긍정 응답                |
| [NAK](/studynote/03_network/04_data_link_layer_error/211_nak_negative_acknowledgement/)      | 부정 응답 (재전송 요청)   |
| SYN      | 동기 문자                |

<strong><a href="/studynote/12_it_management/01_governance_strategy/019_bsc/">BSC</a> 한계</strong>: 반이중, 포인트-투-포인트만, 다중점 제한, 에러 제어 취약

📢 **섹션 요약 비유**: BSC는 무전기 통신이다. "오버"를 외쳐야(ENQ/ACK) 상대가 말할 수 있고, 한 번에 한 방향만 통신된다.

## Ⅲ. [HDLC](/studynote/03_network/04_data_link_layer_error/216_hdlc_high_level_data_link_control/) (High-level [Data](/studynote/05_database/01_db_architecture_relational/001_dikw_pyramid/) Link Control) — 핵심

HDLC는 ISO가 정의한 <strong><a href="/studynote/01_computer_architecture/02_data_representation_arithmetic/073_bit/">비트</a> 지향 전이중 <a href="/studynote/03_network/06_network_layer_ip/295_protocol_field_tcp_udp_icmp/">프로토콜</a></strong>로, X.25·ISDN·PPP의 기반이 된다.

### [HDLC](/studynote/03_network/04_data_link_layer_error/216_hdlc_high_level_data_link_control/) 프레임 구조

```
+--------+----------+------------+----------+--------+
| Flag   | Address  |  Control   |  Data    |  FCS   |
|01111110|  8 bit   |  8/16 bit  | 가변 길이 | 16/32b |
+--------+----------+------------+----------+--------+
```

### 프레임 종류

| 프레임  | 기호 | 기능                            |
|--------|------|---------------------------------|
| [I-Frame](/studynote/03_network/04_data_link_layer_error/220_hdlc_frames_i_s_u/) | 000  | 정보 전송 + 피기백 ACK/[NAK](/studynote/03_network/04_data_link_layer_error/211_nak_negative_acknowledgement/)      |
| S-Frame | 01   | 감시 ([RR](/studynote/03_network/16_data_center_cloud/834_load_balancing_algorithm_round_robin_least_connection/)/RNR/REJ/SREJ)          |
| U-Frame | [11](/studynote/03_network/06_network_layer_ip/308_static_dynamic_nat_pat_port_address_translation/)   | 비번호 ([설정](/studynote/15_devops_sre/01_culture_methodology/009_config/)·해제·초기화)        |

### [HDLC](/studynote/03_network/04_data_link_layer_error/216_hdlc_high_level_data_link_control/) 스테이션 모드

- <strong><a href="/studynote/03_network/04_data_link_layer_error/219_nrm_arm_abm_hdlc_modes/">NRM</a> (Normal Response Mode)</strong>: 마스터-슬레이브, [폴링](/studynote/02_operating_system/08_storage_and_io_systems/448_polling_programmed_io/) 방식
- **ARM (Asynchronous Response Mode)**: 슬레이브 자발 전송 가능
- **ABM (Asynchronous Balanced Mode)**: 양방향 대등 전송 -> LAP-B, [PPP](/studynote/03_network/04_data_link_layer_error/224_ppp_point_to_point_protocol/)

📢 **섹션 요약 비유**: HDLC는 양방향 고속도로다. BSC가 일방통행 국도였다면, HDLC는 차선별로 다른 종류의 [신호](/studynote/02_operating_system/02_process_thread/130_signal/)(I/S/U 프레임)를 동시에 보낼 수 있는 자동차 전용도로다.

## Ⅳ. 슬라이딩 윈도우와 [ARQ](/studynote/03_network/19_frequent_topics_terms/949_arq_automatic_repeat_request_go_back_n_selective/) 제어

### 슬라이딩 윈도우 (Sliding Window) [프로토콜](/studynote/03_network/06_network_layer_ip/295_protocol_field_tcp_udp_icmp/)

```
송신측 윈도우: [ 3 | 4 | 5 | 6 | 7 ]  (미확인 전송 가능 프레임)
수신측:        ACK3 수신 -> 윈도우 이동 -> [ 4 | 5 | 6 | 7 | 8 ]
```

| [ARQ](/studynote/03_network/19_frequent_topics_terms/949_arq_automatic_repeat_request_go_back_n_selective/) 방식    | 재전송 방식            | 효율          |
|------------|----------------------|---------------|
| Stop-and-Wait | 1프레임씩 ACK 대기  | 낮음 (1/[RTT](/studynote/03_network/08_transport_layer/441_rtt_round_trip_time_srtt_smoothed/))  |
| Go-Back-N   | 오류 이후 전부 재전송 | 중간           |
| Selective Repeat | 오류 프레임만 재전송 | 높음 (버퍼^) |

<strong><a href="/studynote/03_network/08_transport_layer/413_tcp_window_size_flow_control_16bit/">윈도우 크기</a></strong>: n비트 순서번호 -> Go-Back-N: 2ⁿ-1, SR: 2ⁿ⁻¹

📢 **섹션 요약 비유**: 슬라이딩 윈도우는 택배 기사가 [확인](/studynote/04_software_engineering/12_testing_maintenance/396_validation/) 전화 없이 여러 집에 미리 배달하는 것과 같다. 반품([NAK](/studynote/03_network/04_data_link_layer_error/211_nak_negative_acknowledgement/))이 오면 Go-Back-N은 그 이후 전부 다시 배달하고, SR은 그 집 것만 다시 배달한다.

## Ⅴ. PPP와 현대 링크 계층 [프로토콜](/studynote/03_network/06_network_layer_ip/295_protocol_field_tcp_udp_icmp/)

### [PPP](/studynote/03_network/04_data_link_layer_error/224_ppp_point_to_point_protocol/) ([Point-to-Point Protocol](/studynote/03_network/04_data_link_layer_error/224_ppp_point_to_point_protocol/))

[HDLC](/studynote/03_network/04_data_link_layer_error/216_hdlc_high_level_data_link_control/) 기반에서 발전한 PPP는 인터넷 다이얼업·DSL·[LCP](/studynote/03_network/04_data_link_layer_error/225_lcp_link_control_protocol/)/[NCP](/studynote/03_network/04_data_link_layer_error/226_ncp_network_control_protocol/) 협상을 지원한다.

```
PPP 연결 설정 과정:
Dead -> Establish (LCP) -> Authenticate -> Network (NCP) -> Open
```

| [프로토콜](/studynote/03_network/06_network_layer_ip/295_protocol_field_tcp_udp_icmp/)    | 계층  | 특징                         |
|------------|------|------------------------------|
| [PPP](/studynote/03_network/04_data_link_layer_error/224_ppp_point_to_point_protocol/)        | L2   | 다중 [프로토콜](/studynote/03_network/06_network_layer_ip/295_protocol_field_tcp_udp_icmp/), [인증](/studynote/04_software_engineering/05_devops_ci_cd/303_authentication_authorization_patterns/)([PAP](/studynote/03_network/04_data_link_layer_error/227_pap_password_authentication_protocol/)/[CHAP](/studynote/03_network/04_data_link_layer_error/228_chap_challenge_handshake_authentication_protocol/)) |
| PPPoE      | L2   | [이더넷](/studynote/03_network/05_lan_wan_l2_devices/230_ethernet_structure_and_principles_ieee_802_3/) 위 [PPP](/studynote/03_network/04_data_link_layer_error/224_ppp_point_to_point_protocol/) (DSL)           |
| MLPPP      | L2   | 다중 링크 묶음                |
| [L2TP](/studynote/03_network/07_network_layer_routing/379_l2tp_layer_2_tunneling_protocol/)       | L2   | [VPN](/studynote/03_network/19_frequent_topics_terms/983_vpn_virtual_private_network/) [터널링](/studynote/03_network/07_network_layer_routing/377_tunneling_mechanism_overview/)                    |

📢 **섹션 요약 비유**: PPP는 표준 전화잭처럼 어떤 기기든 연결되도록 만든 규격이다. 기기 종류([NCP](/studynote/03_network/04_data_link_layer_error/226_ncp_network_control_protocol/))와 연결 [설정](/studynote/15_devops_sre/01_culture_methodology/009_config/)([LCP](/studynote/03_network/04_data_link_layer_error/225_lcp_link_control_protocol/))을 협상 후 [데이터](/studynote/05_database/01_db_architecture_relational/001_dikw_pyramid/)를 전달한다.

## 📌 관련 개념 맵

```
회선 제어 규약
+-- 문자 지향
|   +-- BSC (Binary Synchronous Communication)
|       +-- STX/ETX 프레임
|       +-- ACK/NAK 응답
+-- 비트 지향
|   +-- HDLC (High-level Data Link Control)
|   |   +-- I-Frame / S-Frame / U-Frame
|   |   +-- NRM / ARM / ABM 모드
|   +-- SDLC (IBM 독점 -> HDLC 표준화)
+-- 흐름/오류 제어
|   +-- 슬라이딩 윈도우 (Sliding Window)
|   +-- Go-Back-N ARQ
|   +-- Selective Repeat ARQ
+-- 현대 응용
    +-- PPP / PPPoE
    +-- L2TP
    +-- X.25 / ISDN 링크
```

## 📈 관련 키워드 및 발전 흐름도

```
+-----------------------------------------------------------------+
|             회선 제어 규약 발전 흐름                             |
+--------------+------------------+-------------------------------+
| 1960년대     | BSC (IBM)        | 문자 지향, 반이중, 포인트 간   |
| 1970년대     | SDLC -> HDLC     | 비트 지향, 전이중, ISO 표준화  |
| 1980년대     | X.25 / LAPB      | 패킷 교환망 링크 계층          |
| 1990년대     | PPP / ISDN BRI  | 다중 프로토콜, 다이얼업 인터넷 |
| 2000년대     | PPPoE / L2TP    | DSL 광대역, VPN 터널           |
| 2010~현재    | MPLS / Ethernet | 링크 제어 -> 이더넷 지배        |
+--------------+------------------+-------------------------------+

핵심 키워드 연결:
BSC -> HDLC -> PPP -> L2TP -> IPSec VPN
  v       v       v
문자동기  비트동기  NCP 협상
  v       v
CRC     슬라이딩 윈도우 ARQ
```

## 👶 어린이를 위한 3줄 비유 설명

1. 회선 제어 규약은 편지 배달 규칙이다 — 봉투 형식, 주소 쓰는 법, 반품 처리 방법이 모두 정해져 있다.
2. [HDLC](/studynote/03_network/04_data_link_layer_error/216_hdlc_high_level_data_link_control/) 프레임은 특급 우편 봉투다 — 앞에 보내는 사람 주소, 뒤에 분실 방지 스티커가 붙어있다.
3. 슬라이딩 윈도우는 편의점 배달 앱이다 — [확인](/studynote/04_software_engineering/12_testing_maintenance/396_validation/) 전화 없이 여러 건 미리 배달하고, 반품만 다시 가져간다.
