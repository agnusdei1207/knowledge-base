## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 데이터 거버넌스은 엔터프라이즈 시스템을 단순 구축 대상이 아니라 전략, 프로세스, 데이터, 조직 역량이 결합된 경영 시스템으로 다루는 접근이다.
> 2. **가치**: 정책, 표준, 품질, 메타데이터, 책임 체계로 데이터를 관리함으로써 투자 효과를 설명 가능하게 만들고, 변화 실행 과정의 리스크를 줄인다.
> 3. **판단 포인트**: 핵심은 소유자 지정과 실효성이다. 산출물의 양보다 의사결정과 실행으로 이어지는 추적성이 중요하다.

---

## I. 개요 및 필요성

데이터 거버넌스은 기업 정보시스템이 업무 자동화 수준을 넘어 경영 성과와 직접 연결되면서 중요해졌다. ERP, CRM, 데이터 플랫폼, 클라우드, AI가 개별 시스템으로 흩어져 있으면 투자 대비 효과를 설명하기 어렵고, 부서별 최적화가 전사 병목을 만들 수 있다.

따라서 이 주제는 현황을 진단하고 목표 상태를 정의한 뒤, 투자 우선순위와 실행 로드맵, 성과 지표까지 연결하는 관리 체계로 이해해야 한다. 기술 자체보다 경영 목표와 IT 실행의 연결 구조가 핵심이다.

```text
[Enterprise Management Flow]

Business Goal
     |
     v
Current Assessment -> Target Model -> Roadmap
     |                    |             |
     v                    v             v
Risk/Cost             Architecture     KPI
     |                    |             |
     +---------- Governance -----------+
```

## II. 구성 요소 및 핵심 원리

| 구성 요소 | 설명 | 확인 포인트 |
| :--- | :--- | :--- |
| 현황 진단 | 업무, 시스템, 데이터, 조직 성숙도 파악 | 기준 데이터와 인터뷰 결과의 일치 여부 |
| 목표 모델 | 향후 업무/시스템/데이터 구조 정의 | 경영 목표와 직접 연결되는지 |
| 이행 과제 | 과제를 포트폴리오로 분해 | 의존성, 비용, 위험, 기간 산정 |
| 거버넌스 | 의사결정권과 변경 통제 정의 | 책임자, 승인 기준, 감사 이력 |
| 성과 관리 | KPI와 사후 평가 체계 운영 | 정량 지표와 정성 효과의 균형 |

핵심 원리는 정렬(alignment), 추적성(traceability), 측정 가능성(measurability)이다. 전략 문서의 문장과 실제 프로젝트, 예산, 시스템 변경, 운영 지표가 서로 이어져야 한다.

---

## III. 비교 및 연결

| 구분 | 산출물 중심 접근 | 실행 중심 접근 |
| :--- | :--- | :--- |
| 목적 | 보고서 완성 | 의사결정과 변화 실행 |
| 범위 | 단일 부서/시스템 | 전사 프로세스와 포트폴리오 |
| 지표 | 일정, 문서 수 | 성과, 비용, 위험, 만족도 |
| 리스크 | 형식적 계획 | 변화 저항과 실행 지연 관리 |
| 성공 조건 | 방법론 준수 | 현업 참여와 경영진 후원 |

데이터 거버넌스은 EA, IT 거버넌스, 데이터 거버넌스, 프로젝트 포트폴리오 관리, 변화관리와 연결된다. 특히 시험 답안에서는 개념 설명에서 끝내지 말고 적용 절차와 실패 요인을 함께 제시해야 한다.

## IV. 실무 적용 및 기술사 판단

### 적용 절차

1. 경영 목표와 핵심 문제를 명확히 정의한다.
2. 업무 프로세스, 시스템, 데이터, 조직 역량을 현재 상태로 진단한다.
3. 목표 모델과 원칙을 수립하고 대안을 비교한다.
4. 과제를 가치, 위험, 비용, 시급성 기준으로 우선순위화한다.
5. KPI, 책임자, 일정, 예산, 사후 평가 기준을 확정한다.

### 판단 체크리스트

- 경영 목표와 IT 과제가 1:1로 추적되는가?
- 현업, IT, 보안, 재무 조직의 책임이 명확한가?
- 단기 성과와 장기 아키텍처 일관성이 균형을 이루는가?
- 정량 지표가 실제 행동 변화를 유도하는가?
- 변경관리와 교육 계획이 포함되어 있는가?

### 피해야 할 안티패턴

- 방법론 이름만 나열하고 조직 문제를 다루지 않는 경우
- ROI를 과장하고 운영비, 전환비, 교육비를 누락하는 경우
- 현행 시스템 제약을 무시한 빅뱅 전환
- KPI를 너무 많이 만들어 의사결정에 쓰지 못하는 경우

## V. 기대효과 및 결론

데이터 거버넌스을 제대로 적용하면 IT 투자가 업무 성과와 연결되고, 중복 투자와 운영 위험을 줄일 수 있다. 기술사 답안에서는 정의, 구성 요소, 적용 절차, 비교, 위험 통제를 균형 있게 쓰는 것이 좋다.

### 관련 개념 맵

| 개념 | 연결 포인트 |
| :--- | :--- |
| Enterprise Architecture | 목표 구조와 전환 로드맵 제공 |
| IT Governance | 의사결정권과 통제 체계 정립 |
| Portfolio Management | 투자 우선순위와 자원 배분 |
| Change Management | 현업 수용성과 실행력 확보 |
| KPI Management | 성과 측정과 지속 개선 |
