## 컴퓨터시스템응용기술사 핵심 트랙

- 과목 총 노트 수: 409개

### 왜 핵심인가
- 기업 정보시스템의 설계, 통합, 운영, 혁신을 한 번에 묻기 좋은 과목이라 시스템응용형 문제의 중심축이 된다.
- 단순 제품 지식보다 EA(Enterprise Architecture, 전사 아키텍처), ERP(Enterprise Resource Planning, 전사적 자원관리), MSA(Microservices Architecture, 마이크로서비스 아키텍처) 간 연결 논리를 요구해 변별력이 높다.
- 경영 전략, 프로세스 혁신, 데이터, 클라우드 운영까지 이어져 답안에서 "기술-업무-성과" 3단 구성을 만들기 좋다.
- 실무형 채점에서는 구축 방법론, 전환 리스크, 운영 지표를 함께 쓰는 수험생이 강하므로 핵심 출제 비중이 높다.

### 우선 학습 챕터
- `01_strategy_governance`: EA, IT 거버넌스, ISP/ISMP, KPI
- `02_erp_systems`: ERP, SCM, CRM, MES, PLM
- `03_eai_esb_msa`: EAI, ESB, SOA, API Gateway, Service Mesh
- `04_process_consulting`: BPR, BPM, 프로세스 진단, PI
- `05_data_bi`: DW, ETL, OLAP, 데이터 거버넌스, MDM
- `09_digital_transformation`: DX, 플랫폼, 초자동화, 데이터 기반 혁신
- `10_enterprise_security_governance`: 전사 보안 통제, 컴플라이언스 연계
- `08_cloud_finops`: 클라우드 비용 최적화, 운영 지표, 책임 체계

### 추천 핵심 키워드 목표 수
- 90개

### 단답형 분리 포인트
- 정의형: ERP, SCM, CRM, EAI, ESB, SOA, MSA, BPM 차이
- 구조형: 허브앤스포크, 버스, 이벤트 기반, API 중심 구조
- 지표형: ROI(Return on Investment, 투자수익률), TCO(Total Cost of Ownership, 총소유비용), SLA(Service Level Agreement, 서비스 수준 협약)
- 비교형: 빅뱅 전환 vs 점진 전환, 패키지 도입 vs 자체 개발

### 서술형 분리 포인트
- "배경-문제-아키텍처-전환 전략-기대효과" 5단 구조로 답안을 고정
- 기술 요소만 쓰지 말고 업무 프로세스, 조직 변화, 데이터 표준화까지 같이 기술
- ERP-SCM-MES, EAI-ESB-MSA, DW-BI-거버넌스처럼 상호 연계 축을 잡아 통합 관점으로 서술
- 장애, 벤더 종속, 데이터 품질, 비용 통제 등 실패 요인을 대응 방안과 세트로 제시

### 최신 기술 동향 연결
- Agentic AI(에이전틱 AI)를 BPM, 헬프데스크, 운영 자동화와 연결
- Service Mesh(서비스 메시)와 플랫폼 엔지니어링을 MSA 운영 통제 관점으로 연결
- Composable ERP(컴포저블 ERP), SaaS 통합, 이벤트 기반 아키텍처를 차세대 전사 시스템 전환 축으로 정리
- Supply Chain Resilience(공급망 복원력), FinOps(Financial Operations, 클라우드 재무 운영), ESG(환경·사회·지배구조) 데이터 보고 체계를 경영 성과와 묶어 정리
