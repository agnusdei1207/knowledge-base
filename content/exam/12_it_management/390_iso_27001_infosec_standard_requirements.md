## 핵심 인사이트 (3줄 요약)

> 1. **본질**: ISO/IEC 27001:2022는 Clause 4~10의 **PDCA(Plan-Do-Check-Act) 기반 ISMS(Information Security Management System) 요구사항**과 **93개 통제항목(Annex A)** 으로 구성되며, 조직의 정보자산을 식별·평가·처리·모니터링하기 위한 **위험중심(Risk-based) 경영체계** 표준이다.
> 2. **가치**: 인증 취득을 통해 고객·규제기관·파트너에게 **정보보호 거버넌스의 객관적 증거**를 제공하며, GDPR·PIPC(개인정보보호법)·PCI DSS·SOC 2 등 타 규제로의 **통제 매핑 효율**을 60~80% 수준으로 향상시킨다.
> 3. **판단 포인트**: 핵심은 인증 자체가 아니라 **위험평가 방법론**(자산 식별 -> 위협·취약점 -> 영향도·발생가능성 -> 위험 수준 산정)의 정밀도와 **SoA(Statement of Applicability)** 의 정당성이며, 통제항목의 단순 나열식 적용은 형식적 인증(Compliance Theater)으로 귀결된다.

## Ⅰ. 개요 및 필요성

전통적 정보보안 접근법인 **"방화벽·IDS/IPS·암호화 등 기술 통제" 중심의 제품 배포(Perimeter-based Security)** 만으로는 ① 클라우드·SaaS·제로트러스트 환경에서의 경계 모호화, ② 공급망·내부자 위협 증가, ③ 개인정보보호법·GDPR 등 글로벌 규제 강화, ④ 사이버 보험·공급사 심사 요구 확대라는 새로운 위협 환경에 대응하기 어렵다. ISO/IEC 27001은 2005년 BS 7799 Part 2에서 출발하여 2013년 개정을 거쳐 **2022년 10월 3대 패치**(① Clause 구조 슬림화, ② Annex A 통제 114개->93개 재편성, ③ 신규 통제 11개 추가)가 반영된 현재 버전을 사용한다. 본 표준은 **경영체계(Management System)** 관점에서 정보보안을 정의하므로, ISMS 인증 취득 기업은 평균적으로 보안 사고 발생 시 **복구 비용이 35~48% 낮고**(IBM Cost of a Data Breach Report), 공급사 심사(SIG·CAIQ·VSA) 통과율이 유의미하게 향상된다.

```text
[정보보안 패러다임 전환: 제품중심 -> 경영체계중심]

  +-------------------------+        +--------------------------+
  |  Past (2000s 이전)      |        |  Present (2022 이후)     |
  |  -----------------      |   ->    |  ------------------      |
  |  • 제품/기술 중심       |        |  • 위험/거버넌스 중심    |
  |  • 경계 방어(perimeter) |        |  • 제로트러스트 + ISMS   |
  |  • 일회성 점검          |        |  • 지속적 모니터링(CA)   |
  |  • 정책문서 단순 배포   |        |  • PDCA 순환 + KRI      |
  +-------------------------+        +--------------------------+
                  |                              |
                  +----- ISO/IEC 27001:2022 -----+
                            (경영체계 표준)
```

**왜 필요한가?**
- **규제 준수 매핑(Compliance Mapping)**: ISO 27001 단일 인증으로 PIPC(개인정보보호법) 30조, EU GDPR Art.32, NIS2 Directive, PCI DSS v4.0 통제 다수를 1:N 매핑 가능.
- **위험의 정량화**: 5×5 매트릭스(가능성 × 영향도) 또는 FAIR(Factor Analysis of Information Risk) 등 방법론으로 위험을 화폐가치화하여 경영진 의사결정 지원.
- **공급망 신뢰(Trust Chain)**: Tier 1·Tier 2 OEM·SaaS 협력사 심사 시 ISO 27001 인증은 사실상 디폴트 요구사항(예: AWS MSA, Microsoft DPF, Google Cloud SCC).
- **사고 대응 표준화**: 93개 통제항목 중 A.5.24~A.5.28(정보보안 사고 관리)이 **NIST SP 800-61** Incident Response Lifecycle과 직접 매핑되어 IR 거버넌스 자동화 기반 제공.

- **📢 섹션 요약 비유**: ISO 27001은 **"회사 전체의 보안 건강검진 시스템"** 과 같다. 제품/장비는 당장의 해열제(Anti-virus)·진통제(방화벽)이고, ISMS는 매년 1회 정기 검진을 통해 ① 어디가 약한지(위험평가) ② 무엇을 치료할지(위험처리) ③ 효과를 측정할지(KPI·KRI) 결정하는 종합 건강검진 틀이다.

## Ⅱ. 아키텍처 및 핵심 원리

ISO/IEC 27001:2022는 **두 개의 구조**가 직교(Orthogonal)한다. ① **Clause 4~10**: 모든 경영시스템(ISO 9001·14001·45001 등)에 공통 적용되는 **High-Level Structure(HLS)** 기반 ISMS 요구사항. ② **Annex A**: 93개 정보보안 통제항목의 **참조 통제목록(Reference Control Set)**. 인증 심사는 ①과 ② 모두에 대해 수행된다.

```text
[ISO/IEC 27001:2022 구조 - Clause 4~10 (경영체계) + Annex A (통제항목)]

  +--------------------------------------------------------------+
  |                Clause 4: 조직 상황 (Context)                  |
  |   - 이해관계자 니즈 파악 / ISMS 범위 정의 / 이슈 분석        |
  +------------------------+-------------------------------------+
                           v
  +--------------------------------------------------------------+
  |                Clause 5: 리더십 (Leadership)                  |
  |   - 최상위 경영자 책임 / 정보보안 정책 / 역할·책임(RACI)      |
  +------------------------+-------------------------------------+
                           v
  +--------------------------------------------------------------+
  |                Clause 6: 계획 (Planning)                      |
  |   - 위험평가 방법론 / 위험처리 계획 / SoA / 정보보안 목표    |
  +------------------------+-------------------------------------+
                           v
  +--------------------------------------------------------------+
  |                Clause 7: 지원 (Support)                       |
  |   - 자원 / 역량 / 인식 / 의사소통 / 문서화                    |
  +------------------------+-------------------------------------+
                           v
  +--------------------------------------------------------------+
  |                Clause 8: 운영 (Operation)                     |
  |   - 위험평가 실행 / 위험처리 구현 / ISMS 운영 통제           |
  +------------------------+-------------------------------------+
                           v
  +--------------------------------------------------------------+
  |                Clause 9: 성과평가 (Performance Evaluation)    |
  |   - 모니터링/측정/분석/평가 / 내부감사 / 경영검토            |
  +------------------------+-------------------------------------+
                           v
  +--------------------------------------------------------------+
  |                Clause 10: 개선 (Improvement)                  |
  |   - 부적합 / 시정조치 / 지속적 개선                           |
  +--------------------------------------------------------------+

  +--------------------------------------------------------------+
  |  Annex A: 93개 통제항목 (4개 영역)                            |
  |   A.5 조직적 통제 (37개) - Organizational                    |
  |   A.6 사람적 통제  (8개)  - People                            |
  |   A.7 물리적 통제  (14개) - Physical                          |
  |   A.8 기술적 통제  (34개) - Technological                     |
  |   (총 93개, 2022 개정 전 114개에서 통폐합)                    |
  +--------------------------------------------------------------+
```

| 구성 요소 | 역할 | 핵심 기술 및 동작 방식 |
| :--- | :--- | :--- |
| **Clause 4 - 조직의 상황** | ISMS 적용 범위(Scope) 결정, 내부·외부 이슈 분석 | **SWOT/PESTLE 분석**, 이해관계자 매핑(Stakeholder Map), **Scope Statement** 작성(예: "본사 및 AWS 리전 ap-northeast-2의 SaaS 서비스") |
| **Clause 5 - 리더십** | 경영자Sponsor 지정, 정책 승인, 역할 책임 정의 | **정보보안 정책(High-level Policy)**, **RACI 매트릭스**, ISMS Owner = CISO 또는 CIO 직속 임원 |
| **Clause 6 - 계획** | 위험평가, 위험처리, SoA, 보안 목표 | **5×5 위험 매트릭스** 또는 **FAIR/CVSS** 기반 정량화, SoA 문서에 93개 통제별 **적용(Applicable)/미적용(Excluded)/실적(Justification)** 명시 |
| **Clause 7 - 지원** | 인력 역량, 교육훈련, 문서 관리, 의사소통 | **역량 매트릭스(Competency Matrix)**, 연간 **인식제고 훈련**(Phishing 시뮬레이션·LMS), **문서 라이프사이클 정책**(Draft->Review->Approved->Retired) |
| **Clause 8 - 운영** | 위험평가·위험처리 실행, 운영 통제 | **RTP(Risk Treatment Plan) 실행**, **변경관리(SaaS, Infra-as-Code)**, **통제 운영 증거** 자동 수집(Terraform/Cloud Custodian) |
| **Clause 9 - 성과평가** | KPI/KRI 측정, 내부감사, 경영검토 | **보안 KPI**(MTTD, MTTR, 패치 SLA 준수율), **내부감사 체크리스트**(Annex A 93개 매핑), **경영검토 회의록**(분기/반기) |
| **Clause 10 - 개선** | 부적합 추적, 시정조치, 예방조치 | **CAPA(Corrective and Preventive Action) 프로세스**, **Root Cause Analysis**(5-Why, Fishbone), **KPI 추세 분석** |
| **Annex A - 통제항목** | 93개 통제 적용 및 운영 증거 산출 | 2022 신규 통제: **A.5.7 Threat Intelligence**, **A.5.23 정보보안 클라우드 서비스 사용**, **A.5.30 ICT 준비사업 연속성**, **A.7.4 물리적 보안 모니터링**, **A.8.9 구성관리**, **A.8.10 정보 삭제**, **A.8.11 데이터 마스킹**, **A.8.12 데이터 유출 방지(DLP)**, **A.8.16 모니터링 활동**, **A.8.23 웹 필터링**, **A.8.28 코드 개발 보안(Secure Coding)** |

### 핵심 메커니즘: PDCA + 위험 관리 사이클

```text
[ISO 27001 PDCA + Risk Management 통합 사이클]

          PLAN (Clause 4~7)            DO (Clause 8)
   +---------------------------+   +------------------------+
   | ① Context & Scope        |   | ① 위험처리 실행(RTP)   |
   | ② 위험 식별·평가         |   | ② 통제 구현 및 운영    |
   | ③ 위험처리 계획 수립     |   | ③ 변경관리·릴리즈      |
   | ④ SoA 작성               |   | ④ 사고대응·사업연속성  |
   +------------+--------------+   +-----------+------------+
                |                                |
                |                                |
                v                                v
          ACT (Clause 10)                CHECK (Clause 9)
   +---------------------------+   +------------------------+
   | ① 시정조치(CAPA)         |   | ① KPI/KRI 측정        |
   | ② 예방조치               |   | ② 내부감사(Internal)   |
   | ③ 경영검토 결과 반영     |   | ③ 경영검토(Mgmt Review)|
   | ④ 지속적 개선             |   | ④ 통제 효과성 평가     |
   +---------------------------+   +------------------------+
                |                                |
                +--------------------------------+
                       (위험평가 결과 피드백)
```

### 위험평가 방법론(심화)

- **자산 식별(Asset Inventory)**: CMDB 연동, **주요 자산 분류**(정보자산: PII·영업비밀, SW, HW, 서비스, 사람, 무형자산)
- **위협 식별(Threat)**: **STRIDE 모델**(Spoofing, Tampering, Repudiation, Information Disclosure, DoS, Elevation of Privilege) 또는 **MITRE ATT&CK** 매핑
- **취약점 평가(Vulnerability)**: **CVSS v3.1/4.0** 점수, 취약점 스캔(Tenable Nessus, Qualys, AWS Inspector)
- **영향도(Impact)**: CIA(Confidentiality, Integrity, Availability) + **PII 영향**, 재무적 영향, 평판 영향, 규제 영향
- **발생 가능성(Likelihood)**: 5단계(1:희박 ~ 5:빈번) 또는 정량화(연간 발생 확률)
- **위험도 산정**: Risk = Impact × Likelihood (5×5 매트릭스 시 1~25점)
- **위험처리(Risk Treatment)**: **4R 전략** — Reduce(완화), Avoid(회피), Transfer(전가=보험·아웃소싱), Accept(수용=경영진 승인)

- **📢 섹션 요약 비유**: **Clause 4~10은 "건물의 설계도+시공+유지보수 매뉴얼"** 이고, **Annex A는 "건물에 들어가는 자재 카탈로그"** 이다. 설계도(Clause)가 부실하면 아무리 좋은 자재(Annex A 통제)를 써도 무너지고, 반대로 자재 선정이 잘못되면 설계를 잘 따라도 품질이 낮다. 두 축이 **정합(Alignment)** 되어야 인증이 실효성을 갖는다.

## Ⅲ. 비교 및 연결

| 구분 | **ISO/IEC 27001:2022** | **ISO/IEC 27002:2022** | **NIST CSF 2.0** | **국내 ISMS-P (PIPC)** |
| :--- | :--- | :--- | :--- | :--- |
| **성격** | 인증 가능한 경영체계 표준 (Requirements) | 통제 구현 가이드라인 (Guidance) | 자발적 프레임워크 (Framework) | 법적 의무 인증 체계 (PIPA Art.32) |
| **구조** | Clause 4~10 + Annex A 93개 | 통제별 상세 구현 가이드(목적·속성·지식·기술·메트릭) | Govern + Identify·Protect·Detect·Respond·Recover 6 Function | 인증기준 12개 영역, 80+ 세부산출물 |
| **인증 가능성** | ✅ 제3자 인증 (UKAS·KAB 등) | ❌ 가이드라인, 인증 부적합 | ❌ Self-assessment 기반 | ✅ KISA 지정 인증기관(기간 3년) |
| **위험 관리** | **Risk-based 접근 명시**(6.1.2~6.1.3 필수) | 통제별 위험 연계 설명 | Govern function에 risk 통합 | 위험분석 필수, ISMS-P 인증기준 §3 |
| **통제 수** | 93개 (Annex A) | 93개 (1:1 매핑) | 108개 Subcategory | 80+ 통제 (12개 분야) |
| **PIPC 매핑** | 1:N 매핑 용이 | 27001과 함께 활용 | 부분 매핑 가능 | 직접 매핑 |
| **연결 관계** | 27002는 27001 Annex A의 "구현 지침서" | 27001 통제별 상세 가이드 | 27001과 상호보완적(Governance 통합) | PIPA 개인정보영향평가와 연계 |
