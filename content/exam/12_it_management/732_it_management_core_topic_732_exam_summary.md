## 핵심 인사이트 (3줄 요약)

> 1. **본질**: IT 경영 관리는 COBIT 2019 거버넌스 프레임워크, ITIL 4 서비스 가치 시스템(SVS), ISO/IEC 38500 이사회 거버넌스 원칙을 통합하여, **전략-전환-운영-성능** 4대 영역에서 가치(value)를 극대화하는 **End-to-End 거버넌스 체계**이다.
> 2. **가치**: 체계적 적용 시 IT 투자 대비 ROI 20~35% 향상, IT 장애 평균 복구시간(MTTR) 60% 단축, 감사 적격성(auditability) 100% 확보, 그리고 ISMS-P 인증, IT 거버넌스 인증(ISO 38500) 등 규제 컴플라이언스 만족을 통한 비즈니스 연속성 보장을 달성한다.
> 3. **판단 포인트**: **프레임워크 간 중복 정의**(예: COBIT의 EDM vs ITIL의 SVS) 시 책임 소재 모호화, **Agile-Scrum 채택 시 거버넌스 경직성 문제**, 그리고 **클라우드 전환(FinOps, SaaS Governance)** 시대에 맞는 거버넌스 모델 재설계 여부가 핵심 의사결정 변수이다.

---

## Ⅰ. 개요 및 필요성

4차 산업혁명 시대의 기업 환경에서 IT는 단순 비용 센터(Cost Center)에서 **전략적 비즈니스 파트너(Value Driver)**로 전환되었다. 그러나 한국 정보시스템감리원의 통계에 따르면, 국내大中型企業의 약 67%가 IT 투자 효과 측정 체계를 갖추지 못하고 있으며, 이로 인해 IT 부서의 신뢰도(신뢰도 지수)가 지속 하락하고 있다. 기술사 732번 시험은 이러한 환경에서 **"IT를 어떻게 경영 자산으로 관리할 것인가"**에 대한 통합적 판단 능력을 평가한다.

```text
+------------------------------------------------------------------+
|        IT 경영 관리 4대 영역 통합 프레임워크 (732번 핵심 축)        |
+------------------------------------------------------------------+
|                                                                  |
|  [전략/거버넌스]      [전환/구축]       [운영/서비스]    [성능/측정]  |
|  +----------+       +----------+      +----------+   +--------+|
|  | COBIT    |       | PMBOK 7  |      | ITIL 4   |   | BSC-KPI||
|  | 2019     |◄-----►| PRINCE2  |◄----►| SVS/34   |◄-►| CMMI 5 ||
|  | ISO38500 |       | Agile-SAFe|      | ISO 20000|   | ISO 27001|
|  +----+-----+       +----+-----+      +----+-----+   +---+----+|
|       |                  |                  |             |      |
|       +----------+-------+------------------+-------------+      |
|                  v                                                |
|       +--------------------+                                      |
|       |  IT 가치(Value)    | <- 거버넌스 목표: 가치창출, 리스크최적화|
|       |  실현 엔진         |   자원 최적화 (Benefit Realization)  |
|       +--------------------+                                      |
|                  |                                                |
|   +--------------+--------------+--------------+                  |
|   v              v              v              v                  |
| +------+    +----------+   +---------+   +----------+              |
| |이해관|    | 디지털   |   | 서비스  |   | 컴플라이 |              |
| |계자  |    | 전환(DT) |   | 운영    |   | 언스      |              |

+------------------------------------------------------------------+
```

기존 IT 관리 패러다임은 **"시스템 가용성 99.9%"** 같은 기술 KPI 위주의 **전통적 ITIL v3**(2011년) 중심이었다. 그러나 2020년 이후 **디지털 전환(Digital Transformation)**, **하이퍼 자동화(Hyperautomation)**, **원격근무 확산**, **SaaS 우선 전략(SaaS-First)**이 가속화되면서, IT 자산의 약 40~60%가 클라우드 외부에 위치하게 되었고, 이에 따라 **거버넌스 책임 소재의 경계가 모호**해지는 현상이 발생했다. 732번 시험은 바로 이 **경계 모호성(governance boundary ambiguity)** 문제를 다룬다.

- **📢 섹션 요약 비유**: IT 경영 관리는 마치 **항공우주 산업의 통합 미션 컨트롤 센터**와 같다. COBIT은 비행 경로(전략) 설계, PMBOK는 우주선(프로젝트) 조립, ITIL은 지상관제(운영), BSC는 연료 효율과 안전도(성과) 측정을 담당한다. 한 부분만 잘해서는 발사할 수 없다.

### 2. ITIL 4 서비스 가치 시스템(SVS: Service Value System)

```text
+---------------------------------------------------------------------+
|                  ITIL 4 SVS (Service Value System)                  |
+---------------------------------------------------------------------+
|                                                                     |
|   [기회/수요(Opportunity/Demand)] --► [가치(Value)]                |
|                                          ^                         |
|   +--------------------------------------+----------------------+ |
|   |  거버넌스(Governance) / 방침(Guiding Principles) 7가지     | |
|   |  ① 집중(Focus on value)  ② 시작점에서 생각                 | |
|   |  ③ 현재 상태에서 진행    ④ 협업 및 가시성 촉진            | |
|   |  ⑤ 전체적으로 사고      ⑥ 단순하게 유지 및 실용적으로    | |
|   |  ⑦ 최적화 및 자동화                                       | |
|   +--------------------------------------+----------------------+ |
|                                          |                         |
|                                          v                         |
|   +-------------------------------------------------------------+ |
|   |  서비스 가치 사슬 (Service Value Chain) 6개 활동            | |
|   |  Plan -> Improve -> Engage -> Design&Transition -> Obtain/Build | |
|   |              -> Deliver&Support                               | |
|   +-------------------------------------------------------------+ |
|                                          |                         |
|                                          v                         |
|   +-------------------------------------------------------------+ |
|   |  34개 관리 실무 (Practices)                                 | |
|   |  • 일반관리(14): 정보보안, 리스크, 변경, 사고, 문제 등      | |
|   |  • 서비스관리(17): SLA, 용량, 가용성, 연속성 등            | |
|   |  • 기술관리(3): 배포, 인프라/플랫폼, SW 개발               | |
|   +-------------------------------------------------------------+ |
+---------------------------------------------------------------------+
```

| 구성 요소 | 역할 | 핵심 기술 및 동작 방식 |
| :--- | :--- | :--- |
| **이사회/거버넌스 위원회** | IT 전략 방향 결정, EDM(평가·지시·모니터링) 수행, Risk Appetite 설정 | ISO/IEC 38500의 6원칙(책임, 전략, 취득, 성과, 준수, 인간행위) 준수, COBIT EDM01~05의 RACI 매트릭스 활용 |
| **전략기획팀(EA: Enterprise Architecture)** | 비즈니스-IT 정렬(Business-IT Alignment), TOGAF 10 ADM 사이클 운영 | TOGAF ADM(Architecture Development Method) Phase A~H, BIZBOK 활용 BCM(Business Capability Map) 구축, 4A 모델(Architecture) |
| **프로젝트관리실(PMO)** | 프로젝트 포트폴리오 관리(PPM), 다중 프로젝트 자원 최적화 | PMBOK 7th(8개 성과영역: 이해관계자, 팀, 개발접근, 계획, 프로젝트작업, 전달, 측정, 불확실성), PRINCE2 7원칙, 애자일-Scrum-SAFe 5.0 |
| **IT운영/서비스데스크** | 일일 IT 서비스 제공, SLA 관리, 인시던트/문제 대응 | ITIL 4 34개 실무 중 Incident, Problem, Change Enablement, Service Request, Service Desk 운영, CMDB 기반 영향도 분석 |
| **정보보안/GRC 조직** | ISMS-P, ISO 27001, 개인정보보호법 준수, 사이버 리스크 관리 | ISO 27001:2022 Annex A 93개 통제항목, NIST CSF 2.0(Identify-Protect-Detect-Respond-Recover), 제로트러스트(ZTA) 아키텍처 |
| **성과측정/BSC 운영** | KPI 수집, 대시보드, IT 가치 입증 | BSC 4관점(재무, 고객, 내부프로세스, 학습/성장), ISO 38500 ED-3-1 성과평가 지표, IT 투자 ROI/NPV/IRR 산출 |

### 3. 핵심 알고리즘 및 공식

| 산출물 | 공식/모델 | 설명 |
| :--- | :--- | :--- |
| **TCO (총소유비용)** | TCO = 직접비용 + 간접비용 + 기회비용 | Gartner 기준 5년 TCO 중 클라우드는 직접 30%^, 간접 70%v 효과 |
| **ROI (투자수익률)** | ROI = (IT 투자 편익 - 비용) / 비용 × 100 | 통상 1st Year 목표 ROI > 15%, 3년 누적 > 45% |
| **NPV (순현재가치)** | NPV = Σ [B_t/(1+r)^t] - C_0 | 할인율 r=기업 WACC(통상 7~9%), B=편익, C=초기투자 |
| **가용성(Availability)** | Availability = (MTBF / (MTBF + MTTR)) × 100 | Tier IV 데이터센터 = 99.995% (연 26분 장애 허용) |
| **CMMI 성숙도** | Level 1(초기) -> 2(관리) -> 3(정의) -> 4(정량) -> 5(최적) | CMMI 2.0(2018)부터 Agile-Friendly 도메인 추가 |
| **TPS (Transaction Per Second)** | TPS = 동시사용자 × 사용자당 트랜잭션 / 응답시간 | Little's Law: L = λ × W 활용 |

- **📢 섹션 요약 비유**: COBIT 2019는 **"5,000페이지짜리 자동차 정비 매뉴얼"**과 같다. 처음엔 복잡해 보이지만, EDM(운전), APO(엔진튜닝), BAI(차체조립), DSS(도로주행), MEA(점검)의 5개 영역이 명확히 분리되어 있어 **어디서 문제가 생겼는지 즉시 진단**할 수 있다. ITIL 4는 그 정비 매뉴얼 중 **"주행·주유·세차 운영편"**에 해당한다.
