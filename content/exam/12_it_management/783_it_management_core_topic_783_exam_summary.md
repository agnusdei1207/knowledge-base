## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 정보기술전략(ISP) 수립부터 IT 거버넌스(COBIT 2019), 엔터프라이즈 아키텍처(TOGAF), 서비스 운영(ITIL 4), 디지털 전환(DX)까지를 통합한 IT 경영관리 프레임워크로서, Strategy->Architecture->Execution->Operation->Improvement(SAEOI) 사이클로 조직의 디지털 가치사슬을 관리하는 것이 본질이다.
> 2. **가치**: 체계적 IT 거버넌스 도입 시 IT 투자 대비 ROI를 평균 28% 개선(MIT CISR 2023), IT 프로젝트 성공률 30%->68%로 향상(Standish Group CHAOS Report 2023), 컴플라이언스 위반 비용 60% 절감(IBM Cost of Data Breach 기준), 그리고 의사결정 속도 3~5배 향상을 통한 비즈니스 민첩성 확보가 가능하다.
> 3. **판단 포인트**: COBIT 2019의 40개 Governance/Management 목표 중 조직의 핵심 이슈(Material Issue) 5~7개를 선별하여 집중 관리하고, EA는 TOGAF ADM(Application->Data->Technology->Business Layer)의 4개 도메인 균형을 유지하며, DX는 "기술도입이 아닌 비즈니스 모델 재설계" 관점에서 CFO·CDO·CIO 3자 합의 기반 로드맵을 수립하는 것이 핵심 판단 포인트다.

## Ⅰ. 개요 및 필요성

한국 정보관리기술사(기술사 783번)는 정보시스템의 전략적 기획·구축·운영·폐기 전 생애주기를 다루는 최고 난이도 국가자격 시험이다. 본 토픽은 ①IT 전략(ISP/EA) ②IT 거버넌스(COBIT/ISO 38500) ③프로젝트 관리(PMBOK/PRINCE2) ④서비스 관리(ITIL 4) ⑤정보보안 거버넌스 ⑥DX/AI 전략을 하나의 통합 거버넌스 체계로 이해하는 것을 요구한다. 특히 2020년 이후 클라우드 전환, 생성형 AI 도입, ESG 컴플라이언스 강화로 인해 전통적인 "계획-구축-운영" 3단계 모델은 한계에 도달했으며, **"가설-실험-학습-확산"** 기반의 민첩형(Agile) 거버넌스로 패러다임이 전환되었다.

기존 패러다임(2010년대 이전)은 **계획 중심(Plan-Driven)**, **사일로형(Siloed)**, **연 1회 전략수립**, **IT 부서 독점**이었다. 그러나 디지털 트랜스포메이션 시대에는 **가설 중심(Outcome-Driven)**, **플랫폼 기반(Platform-of-Platforms)**, **연중 지속적 재계획(Continuous Strategy)**, **CDO·CCO·CISO 등 C-Level 합의** 형태로 전환되었다. 기술사 시험에서는 이러한 패러다임 전환을 명확히 인지하고, **"왜(Why) -> 무엇을(What) -> 어떻게(How) -> 어떻게 측정할 것인가(How to Measure)"**의 4단계 논리 구조로 답안을 구성해야 한다.

- **📢 섹션 요약 비유**: IT 경영관리는 마치 **오케스트라의 지휘자**와 같다. 첼로(데이터), 바이올린(애플리케이션), 트럼펫(인프라), 팀파니(보안) 등 다양한 악기(기술영역) 각각이 제 역할을 하되, **지휘자(거버넌스)**가 없으면 소음만 나고, **악보(전략/EA)**가 없으면 방향이 없으며, **객석(CFO/이사회)**이 만족하지 못하면 지속 불가능하다.

## Ⅱ. 아키텍처 및 핵심 원리

IT 경영관리의 핵심은 **COBIT 2019의 40 Governance/Management Objectives**를 5개 도메인(EDM, APO, BAI, DSS, MEA)으로 묶고, 이를 **ISO 38500의 6원칙(Evaluate/Direct/Monitor)**으로 감독하며, **TOGAF ADM**으로 실현하는 3축 통합이다. 본 절에서는 각 계층별 핵심 구성요소의 기술적 동작 원리를 상세히 기술한다.

```text
+----------------------------------------------------------------------+
|           COBIT 2019 Governance/Management 시스템 (40 Objectives)     |
|                                                                      |
|   +--------------------------------------------------------------+   |
|   | EDM (Evaluate, Direct, Monitor) - 5 Objectives                |   |
|   |  +- EDM01: 거버넌스 체계 설정(Framework)                     |   |
|   |  +- EDM02: 혜택 실현(Benefits Delivery)                      |   |
|   |  +- EDM03: 위험 최적화(Risk Optimization)                    |   |
|   |  +- EDM04: 자원 최적화(Resource Optimization)                |   |
|   |  +- EDM05: 이해관계자 투명성(Stakeholder Transparency)        |   |
|   +----------------------+---------------------------------------+   |
|                          |                                           |
|   +----------------------v---------------------------------------+   |
|   | APO (Align, Plan, Organize) - 14 Objectives                   |   |
|   |  +- APO01~02: 관리 프레임워크/전략                           |   |
|   |  +- APO03~05: 조직/혁신/포트폴리오                           |   |
|   |  +- APO06~08: 예산/인력/관계                                 |   |
|   |  +- APO09~11: SLA/공급자/위험                                |   |
|   |  +- APO12~14: 데이터/보안/감시                               |   |
|   +----------------------+---------------------------------------+   |
|                          |                                           |
|   +----------------------v---------------------------------------+   |
|   | BAI (Build, Acquire, Implement) - 11 Objectives               |   |
|   |  +- BAI01~03: 프로그램/요구사항/솔루션                       |   |
|   |  +- BAI04~06: 가용성/전환/변경                               |   |
|   |  +- BAI07~09: 도입/지식/자산                                 |   |
|   |  +- BAI10~11: 구성/장애                                      |   |
|   +----------------------+---------------------------------------+   |
|                          |                                           |
|   +----------------------v---------------------------------------+   |
|   | DSS (Deliver, Service, Support) - 6 Objectives                 |   |
|   |  +- DSS01~03: 운영/서비스/문제                               |   |
|   |  +- DSS04~05: 연속성/보안                                    |   |
|   |  +- DSS06: 비즈니스 통제                                    |   |
|   +----------------------+---------------------------------------+   |
|                          |                                           |
|   +----------------------v---------------------------------------+   |
|   | MEA (Monitor, Evaluate, Assess) - 4 Objectives                |   |
|   |  +- MEA01: 성과/준수 모니터링                                |   |
|   |  +- MEA02: 내부 통제 시스템                                  |   |
|   |  +- MEA03: 외부 요구사항 준수                                |   |
|   |  +- MEA04: 감사(Assurance)                                   |   |
|   +--------------------------------------------------------------+   |
|                                                                      |
|   [각 목표당 7단계 워터폴]                                            |
|   (1) 입력 -> (2) 프로세스 -> (3) 활동 -> (4) 산출물 ->               |
|   (5) RACI -> (6) KPI -> (7) 목표 연계                               |
+----------------------------------------------------------------------+
```

| 구성 요소 | 역할 | 핵심 기술 및 동작 방식 |
| :--- | :--- | :--- |
| **ISP (Information Strategy Planning)** | 비즈니스 전략->IT 전략 정렬(Strategy Alignment) | McFarlan 전략 그리드(Strategic/Operation/Support/Factory), Porter 5 Forces, Value Chain 분석을 통해 **CSF(Critical Success Factor)->KPI->정보시스템**의 3단계 트리(Tree) 도출, 일반 6개월~1년 소요, **MIT 90s 포트폴리오**(Steering Committee + ISP팀 + 실무자) 거버넌스 운영 |
| **EA (Enterprise Architecture)** | 비즈니스·데이터·애플리케이션·기술 4계층 통합 모델 | **TOGAF ADM** 8단계(Phase A Preliminary->A Vision->B~D Architecture->E Opportunities->F Migration->G Implementation->H Change Mgmt->Requirements Management) 순환, **Zachman Framework** 6×6 매트릭스(What/How/Where/Who/When/Why × Planner/Owner/Designer/Builder/Subcontractor/Functioning System), **ArchiMate 3.2** 표준 표기로 계층 간 일관성 확보 |
| **COBIT 2019** | IT 거버넌스/관리 40개 목표 체계 | **Cascade Goals** 메커니즘: Enterprise Goals(13개)->Alignment Goals(13개)->Governance/Management Goals(40개), **Design Factors 11개**(전략, 목표, 위험, 문제, 환경, 역할, 규모, 문화 등)로 시스템 설계 맞춤화, **Performance Mgmt**: Maturity(0~5)과 Capability(0~5) 지표 활용
