## 핵심 인사이트 (3줄 요약)
> 1. **본질**: 데이터 메시(Data Mesh)는 중앙 집중 데이터 팀이 아닌, 비즈니스 도메인 팀이 데이터 제품(Data Product)의 소유권을 갖는 분산형 데이터 아키텍처 패러다임이다.
> 2. **가치**: 조직 규모가 커질수록 중앙 데이터 팀의 병목이 심화되는 문제를 해결하며, 도메인 전문성과 데이터 민첩성을 동시에 확보한다.
> 3. **판단 포인트**: 분산 소유권이 데이터 사일로를 재생산하지 않도록, 연합 거버넌스(Federated Governance)와 셀프서비스 플랫폼이 반드시 동반되어야 한다.

---

## Ⅰ. 개요 및 필요성

데이터 메시는 Zhamak Dehghani(2019)가 제안한 사회기술적(Sociotechnical) 아키텍처로, 중앙 집중형 데이터 레이크·데이터 웨어하우스의 한계를 극복한다.

```text
+--------------------------------------------------+
|        중앙 집중형 vs 데이터 메시 비교             |
+--------------------+-----------------------------+
|  중앙 집중형        |  데이터 메시                  |
|  +----------+      |  +----+ +----+ +----+       |
|  | 중앙 팀   |      |  |주문| |결제| |물류|       |
|  | 전부 관리 |      |  |도메| |도메| |도메|       |
|  +----------+      |  |인팀| |인팀| |인팀|       |
|  병목·지연 발생     |  +--+-+ +--+-+ +--+-+       |
|                     |     +------+------+         |
|                     |     셀프서비스 플랫폼         |
+--------------------+-----------------------------+
```

📢 **섹션 요약 비유**: 중앙 집중형은 모든 부서의 서류를 한 사무실에서 관리하는 것이고, 데이터 메시는 각 부서가 자기 서류를 관리하되 공통 양식과 캐비닛 규격을 따르는 연방제이다.

## Ⅱ. 아키텍처 및 핵심 원리

### 2.1 데이터 메시 4대 원칙

| 원칙 | 설명 | 핵심 질문 |
|:---|:---|:---|
| **도메인 소유권(Domain Ownership)** | 도메인 팀이 분석용 데이터까지 책임 | 누가 데이터를 생산하고 품질을 보증하는가? |
| **데이터를 제품으로(Data as a Product)** | SLA·문서·SLO를 갖춘 데이터 제품 제공 | 소비자 관점에서 발견·이해·신뢰할 수 있는가? |
| **셀프서비스 플랫폼(Self-Serve Platform)** | 도메인 팀의 인프라 부담 제거 | 비전문가도 파이프라인을 구축할 수 있는가? |
| **연합 거버넌스(Federated Governance)** | 전사 상호운용성 표준 수립 | 분산된 데이터 제품 간 일관성이 유지되는가? |

```text
+---------------------------------------------------------+
|              데이터 메시 아키텍처 구조                     |
+---------------------------------------------------------+
|                                                          |
|  +------------+  +------------+  +------------+         |
|  | 도메인 A    |  | 도메인 B    |  | 도메인 C    |         |
|  | Data Product|  | Data Product|  | Data Product|         |
|  | +--------+ |  | +--------+ |  | +--------+ |         |
|  | |Input   | |  | |Input   | |  | |Input   | |         |
|  | |Transform| |  | |Transform| |  | |Transform| |         |
|  | |Output  | |  | |Output  | |  | |Output  | |         |
|  | |SLA/SLO | |  | |SLA/SLO | |  | |SLA/SLO | |         |
|  | +--------+ |  | +--------+ |  | +--------+ |         |
|  +------+-----+  +------+-----+  +------+-----+         |
|         +---------------+---------------+                |
|                         v                                |
|         +--------------------------+                     |
|         | 셀프서비스 데이터 플랫폼   |                     |
|         | (인프라·카탈로그·보안)     |                     |
|         +--------------------------+                     |
|                         v                                |
|         +--------------------------+                     |
|         | 연합 거버넌스 위원회       |                     |
|         | (표준·정책·상호운용성)     |                     |
|         +--------------------------+                     |
+---------------------------------------------------------+
```

📢 **섹션 요약 비유**: 데이터 메시는 프랜차이즈 레스토랑이다. 각 지점(도메인)이 메뉴(데이터 제품)를 직접 만들되, 본사(플랫폼)가 주방 설비를 제공하고, 위생 기준(거버넌스)을 통일한다.

## Ⅲ. 비교 및 연결

| 비교 항목 | 데이터 메시(Data Mesh) | 데이터 패브릭(Data Fabric) |
|:---|:---|:---|
| **접근 방식** | 조직·문화 중심 (사회기술적) | 기술 중심 (자동화) |
| **소유권** | 도메인 팀 분산 소유 | 중앙 플랫폼 통합 관리 |
| **거버넌스** | 연합형 (Federated) | 중앙 집중형 + 자동화 |
| **메타데이터** | 도메인별 자율 관리 | 통합 메타데이터 레이어 자동 |
| **적합 조직** | 대규모·도메인 독립성 높은 조직 | 이기종 데이터 소스 통합 필요 조직 |

📢 **섹션 요약 비유**: 데이터 메시가 연방제 국가라면, 데이터 패브릭은 중앙 정보청이 전국 데이터를 자동 수집·연결하는 시스템이다. 두 접근은 상호 보완적이다.

## Ⅳ. 실무 적용 및 기술사 판단

### 체크리스트
1. 도메인 팀에 데이터 엔지니어가 임베디드 배치되었는가?
2. 데이터 제품의 SLA(가용성·신선도·정확도)가 정의되었는가?
3. 셀프서비스 플랫폼이 파이프라인 템플릿을 제공하는가?
4. 연합 거버넌스 위원회가 주기적으로 상호운용성을 검토하는가?
5. 데이터 제품 카탈로그에서 검색·접근·계보 추적이 가능한가?

### 안티패턴
- 도메인 소유권만 부여하고 플랫폼 없이 방치 -> 데이터 사일로 재생산
- 모든 도메인에 동일 기술 스택 강제 -> 도메인 자율성 훼손
- 거버넌스 없이 분산 -> 메타데이터 불일치, 데이터 품질 하락
- 중앙 팀 역할을 완전 폐지 -> 플랫폼 운영·진화 주체 부재

📢 **섹션 요약 비유**: 메시 도입 실패는 지방 자치를 선언하고 예산·법률 체계 없이 방치하는 것과 같다.

---

## Ⅴ. 기대효과 및 결론

데이터 메시는 조직의 데이터 민첩성과 도메인 전문성을 동시에 극대화하는 패러다임이다. 핵심은 분산과 통합의 균형이며, 셀프서비스 플랫폼과 연합 거버넌스가 그 균형추 역할을 한다.

📢 **섹션 요약 비유**: 잘 운영되는 연방제 국가처럼, 자율과 표준이 공존할 때 전체 국력(데이터 가치)이 극대화된다.

### 📌 관련 개념 맵

| 개념 | 연결 포인트 |
|:---|:---|
| 데이터 패브릭(Data Fabric) | 기술 중심 통합 접근, 메시와 상호 보완 |
| 데이터 프로덕트(Data Product) | 메시의 핵심 산출물, SLA 기반 계약 |
| 도메인 주도 설계(DDD) | 메시의 도메인 분해 원칙의 이론적 기반 |
| 데이터 카탈로그(Data Catalog) | 데이터 제품의 발견·검색 인프라 |
| 데이터 거버넌스(Data Governance) | 연합 거버넌스의 정책·표준 프레임워크 |

### 📈 관련 키워드 및 발전 흐름도

```text
데이터 아키텍처 진화
    +-► EDW(중앙 집중형) -> Data Lake(스키마 온 리드)
    +-► Data Lakehouse(ACID + 레이크) -> Data Mesh(도메인 분산)
    +-► Data Fabric(자동화 메타데이터) ↔ Data Mesh(조직 분산)
    +-► 데이터 제품 -> 데이터 계약 -> 셀프서비스 플랫폼
```

### 👶 어린이를 위한 3줄 비유 설명
1. 데이터 메시는 반마다 급식 당번이 따로 있는 학교예요. 모든 반의 급식을 한 명이 하면 너무 느리잖아요.
2. 각 반이 메뉴를 정하지만, 학교 전체 위생 규칙은 똑같이 지켜야 해요.
3. 급식실 장비(플랫폼)는 학교가 제공하고, 각 반은 자기 반 입맛에 맞게 요리해요.
