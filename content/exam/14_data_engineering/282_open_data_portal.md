## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 행정안전부(국가데이터처)가 운영·관리하는 공공데이터포털(data.go.kr)을 통해 범정부 단일 표준 API 규약(URL+서비스키+요청변수+데이터포맷) 하에 데이터를 개방하는 분산-중앙집중 하이브리드 개방형 데이터 유통 인프라이며, ISO/IEC 11179 메타데이터 표준과 RESTful 아키텍처를 기반으로 한다.
> 2. **가치**: 1,100여 개 기관의 약 8만 건 이상의 데이터셋을 단일 진입점(One-Stop)으로 통합 제공하여 기관별 상이한 인터페이스 학습비용(개발시간 평균 60% 절감)을 해소하고, 데이터 3법(2020.8.5. 시행) 및 정부3.0 정책의 실효성 있는 수단으로 데이터 경제(DT 4.0) 기반을 마련한다.
> 3. **판단 포인트**: (a) 일반 인증키 vs 활용사례 등록 인증키의 보안 트레이드오프, (b) XML/JSON 듀얼 포맷 응답의 호환성 vs 페이로드 크기 문제, (c) 서버/클라이언트 캐싱 및 트래픽 폭주 대응을 위한 API Gateway 배치, (d) LOD·RDF로 확장 시 메타데이터 연계 설계 — 이 네 가지가 실무 설계의 핵심 의사결정 축이다.

## Ⅰ. 개요 및 필요성

### 1. 공공데이터와 개방 데이터의 정의

공공데이터란 **「공공데이터의 제공 및 이용 활성화에 관한 법률」(2020.8.5. 전면 개정, 데이터 3법과 동시 시행)** 제2조 제1호에 따라 "공공기관이 업무를 수행하면서 생성·취득·관리하는 데이터(전자적 형태로 보유·관리되는 것)"를 말한다. 오픈 데이터(Open Data)의 8대 원칙(완전성·원시성·시의성·접근성·기계판독성·비차별성·비독점성·무허가성 — Open Knowledge Foundation 기준)을 충족하려면, 단순 파일 공개가 아닌 **기계가 자동 해석·처리 가능한 표준 API** 형태가 필수적이다.

### 2. 발생 배경: 파편화된 데이터, 통합되지 않은 인터페이스

2013년 「공공데이터의 제공 및 이용 활성화에 관한 법률」 제정 이전, 각 행정기관은 자체 웹페이지, FTP, 심지어 FAX·E-mail을 통해 데이터를 제공했다. 동일 "날씨" 데이터임에도 기상청(동네예보 Open API), 환경부(대기질), 한국환경공단(에어코리아 API) 등 기관별 URL, 인증, 데이터 포맷이 달라 **개발자 1인당 평균 3.2개 기관을 별도 학습**해야 하는 비효율이 존재했다. 정부3.0(2013.6.) 패러다임은 이 문제를 "**표준화 + 단일 포털**"이라는 두 축으로 해결한다.

### 3. 기술적 과제

| 기존(Before) | 표준 API(After) |
| :--- | :--- |
| 기관별 상이한 URL·키·파라미터 | `http://apis.data.go.kr/{기관코드}/{서비스명}/{오퍼레이션}` 단일 패턴 |
| HTML/Excel/XLSX 비정형 제공 | JSON / XML 구조화 응답 |
| 메타데이터 부재로 검색 불가 | DCAT 2.0·ISO 19115 기반 메타데이터 |
| 호출 한도·SLA 불명시 | 일 1,000~10,000건 트래픽 명시 + 응답시간 지표 |

- **📢 섹션 요약 비유**: 공공데이터포털은 마치 **"전국 1,100개 도서관이 각각 다른 대출 규칙을 쓰던 것을, 도서관정보나루(BOOKING)처럼 한 장의 회원증으로 통합한 시스템"**과 같다. 책을 빌리려면 이제 모든 도서관을 따로 배울 필요 없이 한 곳에서 검색·인증·대출(API 호출)·반납(데이터 수신) 규칙만 알면 된다.

## Ⅱ. 아키텍처 및 핵심 원리

### 1. 표준 API 호출 구조 (RESTful 패턴)

공공데이터 표준 API는 **REST(Representational State Transfer)** 의 4대 제약(자원 식별·표현·상태 비저장·통일 인터페이스)을 준수한다. 호출 패턴은 다음과 같이 고정된다.

|  |      ?serviceKey=발급받은_API키                                     |  |
|  |      &pageNo=1                                                    |  |
|  |      &numOfRows=10                                                |  |
|  |      &dataType=JSON                                               |  |

### 2. 핵심 구성 요소

| 구성 요소 | 역할 | 핵심 기술 및 동작 방식 |
| :--- | :--- | :--- |
| **공공데이터포털 (data.go.kr)** | 단일 진입점(One-Stop Portal)·메타 카탈로그·활용신청 관리 | Java/Spring 기반, ElasticSearch(전체 검색), MySQL(메타DB), KOLAS·DBpia 협력 검색 |
| **API Gateway** | 라우팅·인증·트래픽제어·로깅 | NginX + Spring Cloud Gateway, JWT/공공I-PIN 인증, Redis 기반 분산 Rate-Limit(예: 1,000req/day) |
