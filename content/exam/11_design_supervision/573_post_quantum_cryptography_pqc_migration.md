## 핵심 인사이트 (3줄 요약)

> 1. **본질**: Shor 알고리즘으로 위협받는 RSA/ECC를 대체하기 위해 NIST가 표준화한 격자(Lattice), 해시 기반(Hash-based), 다변수(Multivariate), 코드 기반(Code-based) 암호로 전환하는 작업으로, FIPS 203/204/205(FN-DSA 포함) 기반의 양자 내성 알고리즘을 TLS·PKI·HSM·서명 인프라 전반에 적용하는 기술적 패러다임 전환
> 2. **가치**: "Harvest Now, Decrypt Later(HNDL)" 공격으로 이미 유출된 장기 기밀 데이터의 미래 복호화 위험을 차단하고, Mosca의 정리(X+Y>Z)에 따라 양자 컴퓨터 도래 전 migration window 확보로 10~30년 이상의 기밀성을 보장
> 3. **판단 포인트**: PQC 알고리즘의 키/서명 크기 증가(Kyber-768: 1,184Byte, Dilithium3: 2,420Byte)로 인한 TLS 핸드셰이크 페이로드 증가, Hybrid 운용(Classical+PQC)의 호환성·성능 트레이드오프, Crypto-Agility 확보를 위한 추상화 계층 설계가 핵심 의사결정 사항

## Ⅰ. 개요 및 필요성

현재 전 세계가 사용 중인 공개키 암호체계(RSA-2048, ECDSA P-256, DH/ECDH)는 1994년 Peter Shor가 제안한 양자 알고리즘에 의해 다항식 시간 내에 해독 가능하다. 2024년 NIST가 공개한 첫 PQC 표준 3종(FIPS 203/204/205)과 2025년 표준화 예정인 FN-DSA(Falcon, FIPS 206)는 양자 컴퓨터 등장 이후에도 안전한 통신·서명 기반을 제공하기 위한 차세대 암호 패러다임이다.

특히 **"Harvest Now, Decrypt Later"** 위협 모델은 정부·국방·의료·금융 등 장기 기밀성을 요구하는 데이터가 이미 수집·저장되고 있으며, 향후 CRQC(Cryptographically Relevant Quantum Computer)가 등장하는 시점에 일괄 복호화될 수 있음을 경고한다. 2024년 Mosca는 양자 위험 정량화 모델 "Mosca's Theorem: X(데이터 기밀 유지 기간) + Y(전환 소요 시간) > Z(양자 컴퓨터 도달 시점)"을 제시하며, 2025년 현재 X≥10년, Y≥7년, Z≤10년으로 추산되어 즉각적 전환이 필요함을 강조했다.

```text
+------------------------------------------------------------------+
|            양자 컴퓨터 위협과 PQC 전환 필요성 (2025)              |
+------------------------------------------------------------------+
|                                                                  |
|   과거(Pre-Quantum)              현재·미래(Post-Quantum)         |
|   +-----------------+            +---------------------+        |
|   | RSA-2048        |  --X--->   | Kyber-768 (ML-KEM)  |        |
|   | ECDSA P-256     |   Shor    | Dilithium3 (ML-DSA) |        |
|   | DH-2048         |  Algorithm| Falcon-512 (FN-DSA) |        |
|   | AES-128 (Grover)|            | SPHINCS+ (SLH-DSA)  |        |
|   +-----------------+            | HQC (코드기반 KEM)  |        |
|            |                    +---------------------+        |
|            |                              ^                      |
|            v                              |                      |
|   +-----------------------------------------------------+        |
|   |   공격자: HNDL (Harvest Now, Decrypt Later)         |        |
|   |   ① 현재 TLS 트래픽·DB dump 저장                   |        |
|   |   ② 양자 컴퓨터 등장 시 일괄 복호화                |        |
|   |   ③ 정부·군사·의료·금융 등 10~30년 기밀위반         |        |
|   +-----------------------------------------------------+        |
|                                                                  |
|   Mosca's Theorem:  X(10년) + Y(7년) > Z(2030~2033 예상)  ⚠     |
+------------------------------------------------------------------+
```

기존 패러다임은 "충분히 큰 키(RSA-2048, ECC-256)면 안전"이라는 계산 복잡성 가정에 기반했다. 그러나 양자 패러다임은 "수학적 난제 가정(格子最短벡터 문제 LWE/SIS, 해시 충돌 저항성 등)으로 안전성 증명"하며, 양자·고전 컴퓨터 양쪽 모두에 대한 안전성을 제공한다.

- **📢 섹션 요약 비유**: 양자 컴퓨터는 "모든 금고의 마스터키를 공짜로 복제하는 천재 도둑"이고, PQC는 "도둑이 풀 수 없는 새로운 물리법칙 기반의 자물쇠"로 금고를 교체하는 작업

## Ⅱ. 아키텍처 및 핵심 원리

### NIST PQC 표준 알고리즘 (FIPS 203/204/205 + 206)

NIST는 2016년 PQC 표준화 프로젝트를 시작해 2022년 7월 1차 4개 알고리즘을 선정하고, 2024년 8월 13일 FIPS 203/204/205 표준을 최종 확정, 2025년 FN-DSA(Falcon) 표준을 발행한다. 이 5종은 각각 KEM(키 캡슐화)과 Digital Signature(전자서명) 두 영역을 커버한다.

```text
+------------------------------------------------------------------+
|      NIST PQC 표준 알고리즘 패밀리 분류 (5종)                    |
+------------------------------------------------------------------+
|                                                                  |
|  +---------------- KEM (Key Encapsulation) ----------------+     |
|  |  +------------------+    +------------------+           |     |
|  |  | FIPS 203 ML-KEM  |    | FIPS ??? HQC     |           |     |
|  |  | (구 Kyber)       |    | (Hamming QC)     |           |     |
|  |  | - Lattice (MLWE) |    | - Code-based     |           |     |
|  |  | - 3개 파라미터   |    | - KEM 백업용     |           |     |
|  |  |   512/768/1024   |    | - 2025 선정예정  |           |     |
|  |  +------------------+    +------------------+           |     |
|  +--------------------------------------------------------+     |
|                                                                  |
|  +----------- Digital Signature (전자서명) --------------+       |
|  | +--------------+ +--------------+ +--------------+    |       |
|  | |FIPS 204      | |FIPS 206      | |FIPS 205      |    |       |
|  | |ML-DSA        | |FN-DSA        | |SLH-DSA       |    |       |
|  | |(Dilithium)   | |(FALCON)      | |(SPHINCS+)    |    |       |
|  | |- Lattice     | |- Lattice     | |- Hash-based  |    |       |
|  | |- 범용 고속   | |- Compact서명 | |- 보수적 안전 |    |       |
|  | |- 44/65/87    | |- 512/1024    | |- Stateful/   |    |       |
|  | +--------------+ +--------------+ |  Stateless형 |    |       |
|  |                                   +--------------+    |       |
|  +-------------------------------------------------------+       |
+------------------------------------------------------------------+
```

### 핵심 알고리즘별 안전성 근거 및 파라미터

| 구성 요소 | 역할 | 핵심 기술 및 동작 방식 |
|:---|:---|:---|
| **ML-KEM (Kyber)** | KEM | Module-LWE 문제 기반. 공개키 pk∈R_q^q×k (k=2,3,4), CCA 변환(FO transform) 적용. ① Alice가 pk로 32byte 공유키 K와 ciphertext c 생성 ② Bob이 비밀키 sk로 c 복호화. 파라미터: ML-KEM-512(≈AES-128), -768(≈AES-192), -1024(≈AES-256) |
| **ML-DSA (Dilithium)** | 서명 | Module-LWE + Module-SIS 이중 가정. Fiat-Shamir with Aborts. 공개키 1,312Byte, 서명 2,420Byte(Dilithium3). Dilithium2/3/5 등급 |
| **FN-DSA (Falcon)** | 서명 | NTRU 격자 기반, GPV(Gentry-Peikert-Vaikuntanathan) 트랩도어, FFT 고속 푸리에 샘플링. 공개키 897Byte, 서명 666Byte로 가장 compact. **실수연산 부동소수점 -> side-channel 안전 구현 어려움** |
| **SLH-DSA (SPHINCS+)** | 서명 | 해시 함수 충돌/2차프리이미지 저항성만 가정 (가장 보수적). WOTS+ + XMSS + Merkle tree. SHA2/SHAKE, fast/simple, small/fast 변형. 서명 약 7~50KB (크지만 안전성 가정 최소) |
| **HQC (Hamming Quasi-Cyclic)** | KEM | 코드 기반 패리티 검사 행렬의 복호화 난이도. McEliece 대안, ML-KEM 실패 시 백업용. 파라미터 HQC-128/192/256 |

### PQC Hybrid TLS 1.3 핸드셰이크 동작 흐름

현실적 전환 전략은 "Crypto Agility"를 위해 **Hybrid(고전+PQC 병행)** 방식을 채택한다. Chrome(2024 v124), Cloudflare, AWS, Apple iMessage(iOS 17) 등은 X25519+ML-KEM-768 하이브리드를 사용한다.

```text
+----------+                            +----------+
|  Client  |                            |  Server  |
+----+-----+                            +----+-----+
     |  ① ClientHello (key_share:           |
     |     X25519 + ML-KEM-768 pub)         |
     | ------------------------------------>|
     |                                      |
     |  ② ServerHello (key_share 응답)      |
     |     + certificate (ML-DSA/RSA hybrid)|
     |     + certificate_verify             |
     | <------------------------------------|
     |                                      |
     |  ③ Finished                         |
     | ------------------------------------>|
     |                                      |
     |  [KDF로 두 secret 결합]              |
     |  transcript_hash = HKDF-Extract(      |
     |     ECDH_secret || ML-KEM_secret,    |
     |     master_secret)                   |
     |                                      |
     |  +----------------------------------+|
     |  | Hybrid 보안 성질                 ||
     |  | - 둘 다 깨지면 = 전체 안전 X     ||
     |  | - 둘 중 하나만 안전 = 안전       ||
     |  | - 양자 컴퓨터 등장 전 = ECDH     ||
     |  |   안전성으로 호환성 유지         ||
     |  +----------------------------------+|
```

### Mosca의 위험 정량화 모델

```
현재 시점: 2025년
+------------------------------------------------------------+
|                                                            |
|  Z (양자 위협 도달 시점)     2030 ~ 2033 (예상)            |
|  ----------------------------------->                       |
|                                                            |
|  ------+--------+-----------+-----------> 시간              |
|       2025     ?           2030                            |
|        |                                                    |
|        |<--- Y (전환 소요) --->|                             |
|        |    약 5 ~ 7년       |                             |
|        |                     |                             |
|        |<- X (데이터 기밀 유지) ->|                          |
|        |   산업별 10 ~ 30년    |                           |
|        |                       |                           |
|        |   ★ X + Y > Z 이면 위험 ★                         |
+------------------------------------------------------------+
```

- **📢 섹션 요약 비유**: PQC 전환은 "모든 도로 표지판·교량 하중을 한꺼번에 개량하는 30년 국가 프로젝트"와 같아, 정밀한 일정·비용·안전 마진이 필요

## Ⅲ. 비교 및 연결

### PQC 알고리즘 간 비교

| 구분 | ML-KEM (Kyber) | ML-DSA (Dilithium) | FN-DSA (Falcon) | SLH-DSA (SPHINCS+) | HQC |
|:---|:---|:---|:---|:---|:---|
| **수학적 가정** | Module-LWE | Module-LWE+SIS | NTRU 격자 | Hash collision resistance | 코드 디코딩 |
| **용도** | KEM | 서명 | 서명 | 서명 | KEM |
| **공개키 크기** | 800/1,184/1,568 B | 1,312/1,952/2,592 B | 897/1,793 B | 32/48/64 B | 2,249/4,522/7,235 B |
| **서문/ciphertext** | 768/1,088/1,568 B | 2,420/3,309/4,595 B (서명) | 666/1,280 B (서명) | 7,856/16,224 B (서명) | 4,433/8,978/17,469 B |
| **상대 속도** | 매우 빠름 | 빠름 | 빠름(FFT) | 느림 (서명 큼) | 중간 |
| **구현 난이도** | 낮음 (정수연산) | 낮음 (정수연산) | **높음** (부동소수점·side-channel) | 중간 (해시만) | 중간 |
| **보수성** | 중 | 중 | 중 | **최고** (해시만 가정) | 중 |
| **주요 사용처** | TLS, VPN, 메시징 | SW 서명, 인증서 | 블록체인, IoT | 펌웨어·장기 서명 | ML-KEM 백업 |
