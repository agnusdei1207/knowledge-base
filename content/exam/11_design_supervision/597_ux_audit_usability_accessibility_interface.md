## 핵심 인사이트 (3줄 요약)

> 1. **본질**: UX 감리는 ISO 9241-11(사용성: 효과성·효율성·만족도), ISO 25010(소프트웨어 품질), WCAG 2.1/2.2(접근성: 인식성·운용성·이해성·견고성, POUR) 및 한국형 KWCAG 2.1을 기준으로 휴리스틱 평가, 사용자 테스트, 자동화 도구(aXe, WAVE, Lighthouse)를 결합해 인터페이스의 인지적·물리적·환경적 사용성을 정량·정성적으로 진단하는 품질 보증 체계이다.
> 2. **가치**: 전자정부법·장애인차별금지법에 따른 웹접근성 의무 준수, SUS(0~100점, 68 이상 우수), 작업 완료율(85%^), 작업 소요 시간(20~40%v), 오류율 감소, CSAT/NPS 개선(통상 15~30%p), 디지털 소외계층 포용 및 법적 리스크(과태료/입찰제한) 회피라는 ROI를 동시에 창출한다.
> 3. **판단 포인트**: ① 평가 시점(Waterfall 사후감리 vs. Agile/DevOps 임베디드 평가), ② 정량 지표 vs. 정성 인사이트의 가중치, ③ 자동화 커버리지(자동 30~50% vs. 수동 50~70%)와 실제 사용자 그룹 다양성(고령자·장애인·비영어권) 확보, ④ WCAG 2.1 AA/AAA 준수 수준 및 모바일·반응형·다중접근채널(웹/앱/키오스크/음성) 통합 보장 사이의 비용-가치 트레이드오프가 핵심 의사결정 변수다.

---

## Ⅰ. 개요 및 필요성

디지털 서비스 이용자 폭증(2024년 기준 한국 인터넷이용률 96.5%, 65세 이상 75.6%), 초고령사회 진입(2025년 초고령사회), 그리고 「장애인차별금지법」·「전자정부법」에 따른 법적 접근성 의무화에 따라 UX 품질은 단순한 만족도 이슈를 넘어 **공공성·포용성·법적 컴플라이언스**의 핵심 영역으로 격상되었다. SW 품질 감리(한국SW감리인증원, e-Gov 감리) 영역에서도 기능적 결함 위주의 전통적 감리에서 벗어나, 2020년 이후 「UX/UI 품질」 항목이 별도 평가 영역으로 편성되어 10여 개 핵심 항목(IA, 내비게이션, 일관성, 피드백, 접근성, 반응성 등)이 정식 채점된다.

기존 **결함 중심의 사후 검증(Verification)** 패러다임은 실제 사용자의 인지 부하·동작 맥락·환경 제약을 반영하지 못해, 출시 후 사용성 결함으로 CS 비용이 폭증하거나 소송 리스크가 발생하는 한계가 있었다. 반면 현대적 UX 감리는 **사람 중심 설계(HCD, ISO 9241-210)**, **공학적 측정 지표(Usability Metrics)**, **자동화 스캔 + 휴리스틱 + 실사용자 테스트의 3-Layer 검증**을 통합해 ROI를 사전에 정량화한다. Nielsen Norman Group의 연구에 따르면 사용성 개선 1달러당 ROI는 10~100달러 수준으로, 고객지원·교육·수정 비용 절감의 선순환이 입증되었다.

```text
   [사용자(User) Persona: 일반/고령/장애인/다문화]
              |   ^
              |   | (1) 경험 데이터(Eye-tracking, 클릭로그, 설문)
              v   |
   +----------------------------------------------+
   |   2-Layer 평가 프레임워크 (UX Audit)          |
   |  +------------+  +------------+  +---------+ |
   |  | 자동화 스캔 |->| 휴리스틱    |->| 사용자   | |
   |  | (aXe/WAVE) |  | (Nielsen10)|  | 테스트   | |
   |  +------------+  +------------+  +---------+ |
   |   v 결과 통합 -> 정량지표(SUS/NPS) + 정성 이슈 |
   +----------------------------------------------+
              |                |
              v                v
   +--------------+   +------------------+
   | WCAG/ISO 점검 |   | UX 리스크/개선안 |
   | (POUR 4원칙) |   | (Severity/Priority) |
   +--------------+   +------------------+
              |
              v
   [개선 백로그 -> 디자인 시스템/컴포넌트 업데이트]
```

**전통 결함감리 vs. UX 감리 비교**
- *전통적 결함감리*: 명세 기반, 코드/기능 일치성, 사전 정의된 TC, 개발자 관점, 사후적.
- *UX 감리*: 실제 사용 맥락, 시나리오 기반, 휴리스틱 + 측정, 사용자 관점, 예방적·반복적, 정성+정량.

- **📢 섹션 요약 비유**: 기존 감리가 "성적표 채점"이었다면, UX 감리는 "운동선수의 체육관·심리·장비까지 진단하는 스포츠 과학 트레이닝"이다.

## Ⅱ. 아키텍처 및 핵심 원리

UX 감리는 크게 **① 평가 범위 정의(Scoping) -> ② 휴리스틱·표준 점검(Heuristic) -> ③ 자동화 도구 스캔(Automated) -> ④ 사용자 테스트(User Testing) -> ⑤ 정량 지표 산출(Quantitative) -> ⑥ 결과 리포팅·이슈 우선순위화 -> ⑦ 개선안 도출 및 후속 검증**의 7단계로 구성된다. 핵심 표준은 ISO 9241 시리즈(특히 -11, -151, -161, -210), ISO 25010(소프트웨어 제품 품질 8대 특성: 기능적합성·성능·호환성·사용성·신뢰성·보안·유지보수성·이식성), WCAG 2.1(AA/AAA), KWCAG 2.1(한국형, 23개 검사 항목), 그리고 「웹접근성 품질인증 마크(WAQM)」이다.

평가 시 사용되는 인지·심리학적 원리로는 **Fitts's Law**(타겟 도달 시간 = a + b·log₂(D/W+1), D: 거리, W: 폭 -> 버튼/링크 크기와 거리 설계), **Hick's Law**(선택지 수 N에 따라 의사결정 시간 = a + b·log₂(N) -> 메뉴 5~7개 한도), **Miller's Law**(단기 기억 7±2 청크), **Jakob's Law**(사용자는 다른 사이트에서 학습한 패턴을 기대), **Tesler's Law**(복잡성 보존, 시스템이 흡수할 것인가 vs. 사용자에게 떠넘길 것인가), **Von Restorff Effect**(독립적 항목이 기억·주목도가 높음) 등이 UX 의사결정의 물리적 토대를 이룬다.

```text
   [평가 계획 수립]-------------------------------------------+
        | Scope(User Group, Task, Environment, Channel)        |
        v                                                      |
   +----------------+  +----------------+  +----------------+ |
   | Heuristic Eval |  | Auto-Scan      |  | User Testing   | |
   | (Nielsen 10)   |  | (aXe/Lighthouse|  | (Lab/Field)    | |
   | Cognitive Walk |  |  WAVE/Pa11y)   |  | A/B Test       | |
   +--------+-------+  +-------+--------+  +-------+--------+ |
            +----------+-------+---------+----------+          |
                       v                 v                     |
              +----------------+ +----------------+           |
              | 정성 이슈 도출  | | 정량 지표 산출  |           |
              | (Severity 1~4) | | (SUS, NPS, TC%, |           |
              |                | |  Time-on-Task,  |           |
              |                | |  Error Rate)    |           |
              +--------+-------+ +-------+--------+           |
                       +--------+--------+                    |
                                v                             |
                  +-------------------------+                 |
                  | 통합 리포트 + 우선순위화  |                 |
                  | (Impact × Frequency /   |                 |
                  |  Fix Cost, RICE/ICE)    |                 |
                  +--------+----------------+                 |
                           v                                  |
              +-----------------------------+                 |
              | 개선안 -> 디자인시스템 반영    |-----------------+
              |  -> 후속 평가(Iteration)      |
              +-----------------------------+
```

| 구성 요소 | 역할 | 핵심 기술 및 동작 방식 |
| :--- | :--- | :--- |
| **휴리스틱 평가 (Heuristic Evaluation)** | 전문가(3~5명)가 Nielsen 10원칙으로 UI 위반사항 식별 | Nielsen 10 Heuristics(시스템 상태 가시성, 시스템·현실 매칭, 사용자 통제·자유, 일관성·표준, 오류 예방, 인식vs기억, 유연성·효율성, 미니멀·미적 디자인, 오류 인식·진단·회복, 도움말·문서) 기반 Severity 0~4 채점, 독립 평가 후 통합(Voice Voting) |
| **자동화 접근성 스캔 (Automated A11y Scan)** | WCAG/KWCAG 기계 검증(전체 페이지 30~50% 커버) | aXe-core(Deque), WAVE(WebAIM), Lighthouse(Google), Pa11y, SortSite. DOM·ARIA·콘트라스트·대체텍스트·시맨틱·키보드포커스·lang 속성 검사. CI/CD 통합(GitHub Actions, Jenkins) |
| **사용자 테스트 (User Testing)** | 실제 사용자 시나리오 수행 관찰·측정 | 정량(Moderated Lab, Eye-tracking, Mouselab)/정성(Unmoderated Remote, Diary Study). 표본 N=5~7(Nielsen: 5명에서 85% 사용성 이슈 발견), N=20~30 정량 통계 검정 |
| **인지적 작업분석 (CTA/CWA)** | 사용자 정보처리 단계별 인지 부하 분석 | Cognitive Task Analysis: 목표->계획->실행->인지->판단. 시나리오 베이스라인 측정(Baseline Time-on-Task) |
| **표준 적합성 검증** | ISO/WCAG/KWCAG 컴플라이언스 증빙 | WCAG 2.1 Level AA 50개 Success Criteria(1.1.1~4.1.3), KWCAG 23항목(한국형), WAI-ARIA 1.2(landmark, role, state, property), 전자정부 웹접근성 지침 v3.0 |
| **UX 정량지표** | 객관적 비교·추세 관리 | SUS(System Usability Scale, 10문항 5점, 0~100, ≥68 우수), UMUX(4문항), NPS(추천지수), NASA-TLX(인지부하), Task Completion Rate, Time-on-Task, Error Rate, SEQ(Single Ease Question) |
| **리포팅/이슈관리** | 우선순위화 및 개선 추적 | RICE(Reach/Impact/Confidence/Effort), ICE, Heuristic Severity × Frequency 매트릭스. JIRA·Linear·Azure DevOps 연동. 디자인 토큰·컴포넌트 라이브러리(Storybook) 피드백 루프 |

**핵심 매개변수 및 채점 로직**
- SUS 채점: 홀수문항(1,3,5,7,9) = 응답-1, 짝수문항(2,4,6,8,10) = 5-응답, 합산 × 2.5. Sauro-Lewis 정규분포 보정 시 78점 이상 우상위 10%.
- 콘트라스트비(Contrast Ratio): WCAG AA = 4.5:1(일반 텍스트), 3:1(18pt^ 또는 14pt Bold^), AAA = 7:1. WebAIM Contrast Checker로 측정.
- 타겟 크기(Minimum Target Size): WCAG 2.5.5 AAA = 44×44 CSS px, Apple HIG = 44×44pt, Material = 48×48dp.
- 응답시간(Response Time Limit): WCAG 2.2.1 = 20초(긴 작업) 또는 해제 메커니즘, 2.2.2 = 움직임/깜빡임/자동스크롤 제어.
- 200% 확대(Reflow): 320 CSS px width에서 가로 스크롤 없이 1방향 콘텐츠.

- **📢 섹션 요약 비유**: UX 감리는 "영화 제작"에 비유할 수 있다. 각자 다른 렌즈(휴리스틱=감독의 경험, 자동화=현미경, 사용자 테스트=관객 반응)로 같은 작품을 다각도 진단해 "흥행" 가능성을 사전에 가늠하는 작업이다.

## Ⅲ. 비교 및 연결

UX 감리는 SW 품질 감리, UX 리서치, 접근성 감사와 그 영역을 공유하지만, **평가 시점·주체·방법·출력물**에서 명확히 구분된다. 또한 **QA, UAT, 디자인 리뷰**와 상호보완적 관계를 가지며, **DevOps·디자인 시스템·데이터 분석 플랫폼**과 통합될 때 시너지를 극대화한다.

| 구분 | SW 감리 (품질감리) | UX 감리 | 접근성 감리 (웹접근성진단) | UX 리서치 (User Research) |
| :--- | :--- | :--- | :--- | :--- |
| **목적** | 기능/성능/보안 결함 검증 | 사용성·경험 품질 종합 진단 | WCAG/KWCAG 법적 적합성 | 사용자 니즈·행동 탐색 |
| **표준** | ISO 25010, e-Gov 감리지침 | ISO 9241-11/210, Nielsen 10 | WCAG 2.1/2.2, KWCAG 2.1 | 없음(방법론 다양) |
| **주체** | 감리원(개발자 출신) | UX 전문가 + 도메인 전문가 | 접근성 인증기관(한국정보화진흥원 WAQM) | UX 리서처 |
| **방법** | 코드 리뷰, TC 수행, 정적분석 | 휴리스틱 + 자동화 + 사용자 테스트 | 자동화 스캔 + 전문가 검토 + 사용자 평가 | 인터뷰, 관찰, 포커스그룹, 설문 |
| **시점** | 주로 인수·배포 직전 | 주기적(분기/릴리스) | 인증 갱신 시(1~2년) | 기획·개선 사이클 전 과정 |
| **출력** | 결함 리포트, 합격/부적합 | 정량지표 + Severity 이슈 + 개선안 | 인증마
