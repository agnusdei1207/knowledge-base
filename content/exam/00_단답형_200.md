## 작성 방법

- 기출 분석 후 고빈도 키워드부터 채워나가기
- 각 항목: **정의 1줄 + 특징 2~3개** 로 작성
- 손으로 쓸 수 있는지 주 1회 셀프 테스트

---

## 형식

```
### [번호]. [키워드]

**정의**: (한 줄 정의)

**핵심 포인트**:
1. 
2. 
3. 

**관련 키워드**: 
```

## 컴퓨터 구조

### 1. 파이프라이닝 (Pipelining)

**정의**: 명령어 실행을 여러 단계로 분할해 단계별로 중첩 실행하는 병렬 처리 기법

**핵심 포인트**:
1. 단계: IF → ID → EX → MEM → WB
2. 해저드: 구조적(자원 충돌) / 데이터(의존성) / 제어(분기)
3. 처리량 향상, 지연시간은 단축 안 됨

**관련 키워드**: 슈퍼스칼라, 분기 예측, 명령어 재배열

---

### 2. 캐시 메모리 (Cache Memory)

**정의**: CPU와 메인 메모리 사이의 고속 임시 저장소로 지역성 원리 활용

**핵심 포인트**:
1. 지역성: 시간적(최근 접근) / 공간적(인접 주소)
2. 매핑: 직접 / 집합 연관 / 완전 연관
3. 교체 정책: LRU, LFU, FIFO

**관련 키워드**: TLB, 히트율, 쓰기 정책(Write-through/Back)

---

### 3. 가상 메모리 (Virtual Memory)

**정의**: 물리 메모리보다 큰 주소 공간을 제공하는 메모리 관리 기법

**핵심 포인트**:
1. 페이징: 고정 크기 블록, 외부 단편화 없음
2. 세그멘테이션: 가변 크기, 논리적 분할
3. 페이지 교체: LRU, OPT, CLOCK

**관련 키워드**: 페이지 폴트, 스레싱, TLB, MMU

---

## 운영체제

### 4. 교착상태 (Deadlock)

**정의**: 둘 이상의 프로세스가 서로 상대방의 자원을 기다리며 무한 대기하는 상태

**핵심 포인트**:
1. 필요조건: 상호배제 / 점유대기 / 비선점 / 순환대기 (4가지 모두 성립 시 발생)
2. 해결: 예방 / 회피(은행원 알고리즘) / 탐지 / 복구
3. 탐지: 자원 할당 그래프

**관련 키워드**: 기아(Starvation), 라이브락, 뮤텍스, 세마포어

---

### 5. 프로세스 vs 스레드

**정의**: 프로세스는 독립 실행 단위, 스레드는 프로세스 내 실행 흐름

**핵심 포인트**:
1. 프로세스: 독립 메모리, IPC 필요, 오버헤드 큼
2. 스레드: 메모리 공유, 빠른 통신, 동기화 필요
3. 멀티스레드: 반응성 향상, 자원 효율적

**관련 키워드**: 컨텍스트 스위칭, PCB, TCB, 경쟁조건

---

## 소프트웨어 공학

### 6. 애자일 (Agile)

**정의**: 짧은 반복 주기로 동작하는 소프트웨어를 지속 제공하는 개발 방법론

**핵심 포인트**:
1. 스크럼: 스프린트(2~4주) / 백로그 / 데일리 스탠드업
2. vs 워터폴: 유연성↑, 문서↓, 고객 참여↑
3. 적합: 요구사항 변경 잦은 프로젝트

**관련 키워드**: 스크럼, 칸반, XP, CI/CD, 사용자 스토리

---

### 7. 디자인 패턴 (Design Pattern)

**정의**: 반복되는 설계 문제에 대한 재사용 가능한 해결책 템플릿

**핵심 포인트**:
1. 생성: Singleton, Factory, Builder
2. 구조: Adapter, Decorator, Proxy
3. 행위: Observer, Strategy, Command

**관련 키워드**: GOF, SOLID 원칙, 리팩토링

---

## 데이터베이스

### 8. 정규화 (Normalization)

**정의**: 데이터 중복을 제거하고 이상 현상을 방지하기 위한 테이블 분해 과정

**핵심 포인트**:
1. 1NF: 원자값 / 2NF: 부분함수 종속 제거 / 3NF: 이행함수 종속 제거
2. BCNF: 모든 결정자가 후보키
3. 반정규화: 성능 향상 목적의 의도적 역정규화

**관련 키워드**: 함수 종속, 이상 현상(삽입/삭제/갱신), 후보키

---

### 9. 트랜잭션 (Transaction)

**정의**: 데이터베이스의 논리적 작업 단위로 ACID 속성을 보장

**핵심 포인트**:
1. ACID: 원자성 / 일관성 / 격리성 / 지속성
2. 격리 수준: Read Uncommitted → Read Committed → Repeatable Read → Serializable
3. 동시성 제어: 2PL, MVCC, 낙관적 잠금

**관련 키워드**: 롤백, 커밋, 교착상태, 팬텀 리드

---

## 알고리즘

### 10. 시간복잡도 (Time Complexity)

**정의**: 입력 크기 n에 따른 알고리즘 실행 시간의 증가율을 빅오 표기로 나타낸 것

**핵심 포인트**:
1. O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ)
2. 최선/평균/최악 케이스 구분
3. 정렬 비교: 퀵 O(n log n) 평균, 버블 O(n²)

**관련 키워드**: 공간복잡도, 빅오메가, 마스터 정리

## 보안

### 11. 대칭키 vs 비대칭키 암호화

**정의**: 대칭키는 동일 키 사용, 비대칭키는 공개키/개인키 쌍 사용

**핵심 포인트**:
1. 대칭: 속도 빠름, 키 배분 문제 (AES, DES)
2. 비대칭: 키 배분 해결, 속도 느림 (RSA, ECC)
3. 실무: 하이브리드 (대칭키를 비대칭키로 암호화하여 전송)

**관련 키워드**: PKI, 인증서, TLS/SSL, 전자서명

---

### 12. OWASP Top 10 (2021)

**정의**: 웹 애플리케이션의 주요 보안 취약점 10가지를 정리한 국제 표준 가이드

**핵심 포인트**:
1. A01 접근제어 취약점 / A02 암호화 실패 / A03 인젝션
2. A04 불안전한 설계 / A05 보안 설정 오류
3. A07 인증 실패 / A10 SSRF

**관련 키워드**: SQL Injection, XSS, CSRF, Broken Access Control

## AI

### 13. RAG (Retrieval-Augmented Generation)

**정의**: LLM이 외부 지식베이스를 검색하여 응답을 생성하는 아키텍처

**핵심 포인트**:
1. 구성: 검색기(Retriever) + 생성기(Generator)
2. 장점: 할루시네이션 감소, 최신 정보 반영
3. 한계: 검색 품질에 성능 의존, 지연시간 증가

**관련 키워드**: 벡터 DB, 임베딩, 청킹, 하이브리드 검색

---

### 14. Transformer

**정의**: Self-Attention 메커니즘 기반의 시퀀스 처리 신경망 아키텍처

**핵심 포인트**:
1. 핵심: Multi-Head Self-Attention + Position Encoding
2. 병렬 처리 가능 → RNN 대비 학습 속도 향상
3. 기반: BERT(인코더), GPT(디코더), T5(인코더-디코더)

**관련 키워드**: Attention Is All You Need, LLM, Fine-tuning, PEFT

## 클라우드

### 15. 컨테이너 vs 가상머신

**정의**: 컨테이너는 OS 공유 경량 격리, VM은 하드웨어 수준 완전 격리

**핵심 포인트**:
1. 컨테이너: 빠른 시작, 낮은 오버헤드, 커널 공유 (Docker)
2. VM: 완전 격리, 보안↑, 무거움 (KVM, VMware)
3. 실무: 마이크로서비스는 컨테이너, 강한 격리는 VM

**관련 키워드**: Docker, Kubernetes, 오케스트레이션, 네임스페이스
