## 1교시 실제 모범답안

### 1) 스펙트럼 공유 기술

- 정의: 스펙트럼 공유는 동일 주파수 자원을 시간, 공간, 정책 기반으로 복수 사용자 또는 서비스가 공동 활용하는 기술이다.
- 핵심1: `DSA(Dynamic Spectrum Access)`는 사용 현황에 따라 유휴 대역을 동적으로 할당한다.
- 핵심2: `CBRS(Citizens Broadband Radio Service)`처럼 계층형 이용권 모델을 적용할 수 있다.
- 핵심3: 간섭 관리, 정책 엔진, 데이터베이스 정확도가 성능을 좌우한다.
- 적용: 5세대 이동통신(5G) 특화망과 비면허 대역 활용 확대에 적합하다.

```text
[유휴 대역 탐지]
      ↓
[정책 기반 할당]
      ↓
[간섭 최소화 공유]
```

### 2) 비면허 대역 5세대 이동통신 (5G NR-U, New Radio-Unlicensed)

- 정의: `NR-U`는 5세대 이동통신 무선접속 기술을 비면허 대역에 확장 적용하는 방식이다.
- 핵심1: `LBT(Listen Before Talk)`로 기존 무선랜과 공존한다.
- 핵심2: 공장, 물류, 캠퍼스 등에서 추가 용량 확보에 유리하다.
- 핵심3: 간섭 환경이 불안정해 품질 보장형 서비스에는 설계 주의가 필요하다.
- 적용: 사설망에서 면허 대역과 비면허 대역을 혼합해 커버리지와 비용을 최적화할 수 있다.

```text
[면허 대역]
    + 
[비면허 대역 NR-U]
      ↓
[용량 확장·공존]
```

## 선택 추천 실제 모범답안

### 1) AI 네이티브 6세대 이동통신(6G) 네트워크

#### Ⅰ. 개요

- AI 네이티브 6세대 이동통신(6G)은 인공지능을 부가 기능이 아니라 무선, 전송, 코어, 운영 전반의 기본 메커니즘으로 내재화한 네트워크이다.
- 트래픽 예측, 자원 제어, 장애 대응을 실시간으로 수행해야 하므로 기존 5세대 이동통신(5G)보다 데이터 폐쇄루프가 중요하다.

#### Ⅱ. 아키텍처

```text
[서비스/단말]
      ↓
[AI-RAN]
      ↓
[Transport/Edge]
      ↓
[Core/Cloud]
      ↓
[AIOps 폐쇄루프]
```

#### Ⅲ. 핵심 요소

| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 무선 | 빔포밍, 스케줄링, `PHY AI` | 실시간 추론 성능 |
| 코어 | 슬라이스 최적화, 정책 자동화 | 품질과 안정성 |
| 운영 | 장애 예측, 자동 복구 | 오탐 제어 |
| 데이터 | 학습데이터 수집, 거버넌스 | 개인정보·보안 |

#### Ⅳ. 설계 원칙

- 1. 중앙형 모델만이 아니라 `RAN` 현장 추론과 클라우드 학습을 분리한다.
- 2. 학습 정확도보다 서비스 영향 최소화와 롤백 가능성을 우선한다.
- 3. 표준 인터페이스 기반으로 장비사 종속을 줄인다.

#### Ⅴ. 결론

- AI 네이티브 6G는 성능 향상보다 운영 안정성과 설명 가능한 자동화까지 확보해야 상용망 적용 가치가 높다.

### 2) 멀티액세스 엣지 컴퓨팅(Multi-access Edge Computing, MEC)과 클라우드 연계 아키텍처

#### Ⅰ. 개요

- `MEC`는 사용자 인접 구간에서 애플리케이션과 데이터를 처리해 지연을 줄이는 분산 컴퓨팅 구조이다.
- 정보통신기술사 답안에서는 단순 정의보다 백홀 절감, 서비스 연속성, 오케스트레이션까지 연결해야 한다.

#### Ⅱ. 연계 구조

```text
[단말]
   ↓
[기지국/UPF]
   ↓
[MEC]
   ↘
    [Central Cloud]
```

#### Ⅲ. 핵심 비교

| 구분 | MEC | 중앙 클라우드 |
|:---|:---|:---|
| 지연 | 매우 짧음 | 상대적으로 큼 |
| 자원 | 제한적 | 확장성 우수 |
| 적용 | AR/VR, 제어 | 학습, 통합 분석 |
| 한계 | 분산 운영 복잡도 | 실시간성 부족 |

#### Ⅳ. 적용 방안

- 1. 사용자 평면 기능(`UPF`, User Plane Function)을 엣지에 배치해 로컬 브레이크아웃을 구현한다.
- 2. 중앙 클라우드는 모델 학습, 장기 저장, 전사 운영 통합에 사용한다.
- 3. 서비스 이동 시 세션 연속성과 데이터 동기화 체계를 같이 설계한다.

#### Ⅴ. 결론

- `MEC`와 클라우드는 대체 관계가 아니라 지연 민감도와 운영 효율에 따라 역할을 분담하는 상보 구조다.

### 3) O-RAN(Open Radio Access Network) 아키텍처 보안 강화 방안

#### Ⅰ. 개요

- `O-RAN`은 개방형 인터페이스와 멀티벤더 구조로 유연성을 높이지만 공격면이 확대되는 특징이 있다.
- 따라서 무선접속망 기능 분리와 공급망 개방을 고려한 별도 보안 아키텍처가 필요하다.

#### Ⅱ. 보안 구조

```text
[SMO]
  ↓
[Near-RT RIC] ↔ [xApp/rApp]
  ↓
[O-CU/O-DU/O-RU]
```

#### Ⅲ. 보안 통제 항목

| 구분 | 주요 위협 | 강화 방안 |
|:---|:---|:---|
| 인터페이스 | 위변조, 도청 | 상호 인증, 암호화 |
| 앱 생태계 | 악성 xApp | 서명 검증, 샌드박스 |
| 공급망 | 취약 모듈 혼입 | `SBOM(Software Bill of Materials)`, 검증 |
| 운영 | 권한 오남용 | 최소권한, 감사로그 |

#### Ⅳ. 적용 방안

- 1. `RIC(RAN Intelligent Controller)` 앱은 배포 전 코드 서명과 행위 검증을 수행한다.
- 2. 인터페이스별 인증서를 분리해 장애 시 영향 범위를 축소한다.
- 3. 장비사별 취약점 공개 주기와 패치 절차를 계약 수준에서 관리한다.

#### Ⅴ. 결론

- `O-RAN` 보안은 장비 보안이 아니라 인터페이스, 앱, 공급망, 운영권한까지 통합 관리해야 실효성이 확보된다.
