## 1교시 실제 모범답안

### 1) 멀티패스 TCP (Multipath TCP, MPTCP)

- 정의: `MPTCP`는 하나의 전송 연결에서 복수 경로를 동시에 사용해 대역폭 활용도와 회복성을 높이는 확장 전송제어프로토콜이다.
- 핵심1: 단말의 Wi-Fi와 셀룰러 경로를 병행 사용해 세션 연속성을 확보한다.
- 핵심2: 서브플로우 기반으로 경로별 혼잡 상태를 반영한다.
- 핵심3: 중간 장비 호환성, 재정렬 오버헤드, 정책 제어가 고려사항이다.
- 적용: 이동 중인 업무 단말이나 특화망 게이트웨이의 이중접속 품질 향상에 유효하다.

```text
[세션 1개]
   ├→ [Wi-Fi 경로]
   └→ [5G 경로]
```

### 2) 네트워크 슬라이싱 보안

- 정의: 네트워크 슬라이싱 보안은 단일 5세대 이동통신(5G) 인프라를 논리적으로 분리한 슬라이스 간 격리와 신뢰성을 보장하는 보호 체계이다.
- 핵심1: 제어면, 사용자면, 관리면에서 크로스 슬라이스 공격을 막아야 한다.
- 핵심2: 슬라이스별 정책, 인증, 모니터링을 독립 운영해야 한다.
- 핵심3: 공유 자원 기반이므로 완전 물리 격리보다 검증 가능한 논리 격리가 중요하다.
- 적용: 공공안전, 제조, 의료 슬라이스를 동시 제공하는 사업자 망에서 필수다.

```text
[공통 인프라]
   ├→ [공공안전 Slice]
   ├→ [제조 Slice]
   └→ [의료 Slice]
```

## 선택 추천 실제 모범답안

### 1) 생성형 인공지능 서비스 도입 시 통신망 영향 및 대응 방안

#### Ⅰ. 개요

- 생성형 인공지능 서비스는 대규모 업로드, 장시간 세션, 응답형 추론 트래픽을 유발해 기존 동영상 중심 망과 다른 부하 특성을 만든다.
- 따라서 통신망은 단순 증설이 아니라 캐시, 엣지, 전송, 보안, 과금 구조를 함께 재설계해야 한다.

#### Ⅱ. 영향 구조

```text
[이용자 요청]
      ↓
[API/GPU 추론]
      ↓
[대용량 응답/세션 유지]
      ↓
[Access-Backhaul-Core 부하]
```

#### Ⅲ. 주요 영향

| 구분 | 영향 | 대응 포인트 |
|:---|:---|:---|
| 접속망 | 업링크 증가, 세션 장기화 | `QoS`, 트래픽 분산 |
| 전송망 | 동서 트래픽 확대 | 캐시, 경로 최적화 |
| 데이터센터 | GPU 집중 부하 | 엣지 분산 배치 |
| 보안 | 프롬프트 악용, 데이터 유출 | 접근통제, 감사 |

#### Ⅳ. 대응 방안

- 1. 인기 모델은 `MEC` 또는 지역 데이터센터에 배치해 지연과 백홀 부하를 줄인다.
- 2. 응답형 트래픽은 `CDN(Content Delivery Network)`과 API 게이트웨이로 분산한다.
- 3. 기업 고객용은 전용 슬라이스와 보안관제 연계형 상품으로 차별화한다.

#### Ⅴ. 결론

- 생성형 인공지능 트래픽 대응은 용량 증설보다 서비스 위치, 캐시 전략, 보안 통제를 함께 설계하는 것이 핵심이다.

### 2) 양자내성암호(Post-Quantum Cryptography, PQC) 하이브리드 전환

#### Ⅰ. 개요

- `PQC` 하이브리드 전환은 현행 공개키 알고리즘과 양자내성 알고리즘을 병행 적용해 상호운용성과 안전성을 동시에 확보하는 방식이다.
- 통신망은 장비 교체 주기가 길기 때문에 일괄 전환보다 단계적 하이브리드가 현실적이다.

#### Ⅱ. 전환 흐름

```text
[현행 TLS/IPsec]
        ↓
[기존 알고리즘 + PQC]
        ↓
[성능 검증]
        ↓
[PQC 중심 전환]
```

#### Ⅲ. 핵심 비교

| 구분 | 현행 공개키 | PQC 하이브리드 |
|:---|:---|:---|
| 호환성 | 높음 | 중간 |
| 안전성 | 양자환경 취약 | 전환 리스크 완화 |
| 성능 | 안정적 | 키·서명 크기 증가 |
| 적용 | 기존 전 구간 | 중요 구간 우선 |

#### Ⅳ. 적용 방안

- 1. `TLS(Transport Layer Security)`와 `IPsec(Internet Protocol Security)`부터 우선 적용한다.
- 2. 관리망, 백본망, 대외 연동망 순으로 중요도를 나눠 전환한다.
- 3. 인증서 수명, 키관리, 장비 처리량을 함께 검증한다.

#### Ⅴ. 결론

- `PQC` 전환은 알고리즘 선택보다 통신망 자산 분류와 성능 검증 체계를 먼저 세우는 것이 성공 조건이다.

### 3) Open Radio Access Network (Open RAN) 보안 아키텍처

#### Ⅰ. 개요

- `Open RAN`은 무선접속망을 개방형 인터페이스와 분리형 기능으로 구성해 유연성을 높이는 구조이다.
- 그러나 멀티벤더와 소프트웨어화가 확대되면서 인터페이스, 공급망, 운영권한 보안이 핵심 이슈가 된다.

#### Ⅱ. 아키텍처

```text
[SMO]
  ↓
[RIC]
  ↓
[O-CU] - [O-DU] - [O-RU]
```

#### Ⅲ. 보안 요소

| 구분 | 위협 | 대응 |
|:---|:---|:---|
| 개방 인터페이스 | 도청, 위변조 | 인증, 암호화 |
| 가상화 플랫폼 | 취약 이미지 | 무결성 검증 |
| 공급망 | 악성 모듈 유입 | `SBOM`, 서명 검증 |
| 운영 | 권한 남용 | `Zero Trust`, 감사 |

#### Ⅳ. 강화 방안

- 1. `SMO(Service Management and Orchestration)`와 `RIC` 접근은 강한 인증과 세분 권한을 적용한다.
- 2. 소프트웨어 배포는 이미지 서명과 취약점 점검을 거친다.
- 3. 장비사 혼합 환경에서는 상호운용 검증과 패치 책임 범위를 명확히 한다.

#### Ⅴ. 결론

- `Open RAN` 보안은 장비별 기능 보안보다 생태계 전체 신뢰사슬을 관리하는 구조적 접근이 중요하다.
