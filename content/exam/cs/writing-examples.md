# CSPE 답안 작성 예시집

> 작성 원칙과 검수 절차의 정본은 [CSPE 답안 작성법 단일 정본](@/exam/cs/writing-method.md)이다. 이 문서는 정본의 규칙을 실제 문장에 적용하는 수정 전·후 예시를 모은 참조 문서다.

## 0. 예시 누적 및 판단 방법

새로운 문장 교정 사례가 생기면 결과 문장만 추가하지 않고 아래 정보를 함께 기록한다.

전수 검수에서는 모든 문장을 읽되 모든 문장을 고치지 않는다. 기술 정확성·자연스러움·직관성·핵심성·배치 적합성을 이미 만족하면 수정 없이 통과시키고, 실제로 읽을 때 걸리는 문장만 아래 항목으로 판정해 교정한다.

| 기록 항목 | 확인 내용 |
|:---|:---|
| 문제 유형 | 불필요한 말, 과잉 압축, 과잉 설명, 모호한 동사, 부적절한 단어 배치, 잘못된 절 배치, 기술 오류 중 무엇인지 구분함 |
| 문장 위치 | 정의·특징·비교표·구성요소·절차·실무 사례·결론 중 어디에 들어가는지 기록함 |
| 핵심 판단 | 독자가 이 문장에서 반드시 알아야 하는 대상과 선택 기준을 적음 |
| 단어별 근거 | 명사·동사·형용사·부사·수식어가 기술 정의, 비교, 지표, 인과, 순서 중 어떤 근거를 갖는지 기록함 |
| 판정 이유 | 왜 장황한지, 왜 직관적이지 않은지, 무엇이 생략됐는지 설명함 |
| 권장 문장 | 기술 정확성을 유지하면서 처음 읽어도 뜻을 설명할 수 있는 문장을 남김 |

문장 품질은 다음 순서로 판단한다.

1. **기술 정확성**: 사실과 인과관계가 맞는지 확인함
2. **자연스러움**: 기술적으로 맞더라도 평소 한국어 문장으로 읽히지 않으면 폐기하고 다시 씀
3. **문장 완결성**: 주어·조건·목적어·서술어가 하나의 판단으로 닫히고 마지막 동사가 앞 내용을 회수하는지 확인함
4. **직관성**: 처음 읽는 사람이 동작이나 차이를 자신의 말로 설명할 수 있는지 확인함
5. **핵심성**: 출제 의도와 선택 기준에 필요한 정보인지 확인함
6. **문장 내 단어 배치 적합성**: 수식어와 대상, 주어와 서술어, 목적어와 동사가 자연스럽게 연결되는지 확인함
7. **절 배치 적합성**: 정의는 개념, 비교표는 차이, 실무 사례는 적용·위험·대응·지표를 담는지 확인함
8. **간결성**: 앞의 일곱 조건을 훼손하지 않는 범위에서만 줄임

| 실패 유형 | 쓰지 않는 방식 | 권장 방식 |
|:---|:---|:---|
| 불필요한 말 | 이미 드러난 주어·절 제목·메타 설명을 반복함 | 새로운 판단을 추가하는 말만 남김 |
| 과잉 압축 | 적용 대상이나 검증 대상을 삭제해 짧게 만듦 | 대상·조건·판단 기준을 완전한 문장으로 연결함 |
| 과잉 설명 | 첫 이해에 필요 없는 수식·단계·예외를 한 문장에 모두 넣음 | 핵심 동작을 먼저 설명하고 세부 내용은 특징·절차로 내림 |
| 모호한 표현 | 좋음·강함·효율적·안정적처럼 기준 없이 평가함 | 지연·메모리·오류율·복구 시간처럼 확인 대상을 밝힘 |
| 근거 없는 수식어 | 비교 기준 없이 바로·빠르게·쉽게·크게를 붙임 | 비교 대상·측정 지표·실제 순서를 밝히거나 수식어를 삭제함 |
| 부적절한 단어 배치 | 수식어와 대상이 떨어지거나 여러 명사를 한 동사에 억지로 묶음 | 수식어를 대상 가까이에 두고 명사마다 자연스러운 동사를 연결함 |
| 문장 내부 논리 단절 | 관련 조건 사이에 다른 기준을 끼우고 마지막에 새 동작을 추가함 | 관련 조건을 묶어 배치하고 마지막 서술어가 핵심 판단만 회수하게 함 |
| 문장 미완결 | 조건과 명사를 나열한 뒤 목적어와 맞지 않는 동사로 끝냄 | 대상·조건·판단 기준을 연결하고 핵심 선택이나 판단을 서술어로 완성함 |
| 잘못된 절 배치 | 정의에서 구현 세부를 설명하거나 결론에서 새 위험을 만듦 | 각 절의 역할에 맞는 정보만 배치함 |
| 장황한 문장 | 같은 의미를 원인·결과·목적으로 반복함 | 대상과 핵심 동작을 한 번씩만 씀 |

### 핵심 판단 요소와 비교축의 구분

- 핵심 판단 요소는 문제에서 실제로 알고자 하는 2~3개의 질문임
- 비교축은 그 질문에 답하기 위해 두 기술의 차이를 보여주는 5~6개의 관찰 기준임
- 예를 들어 최단 경로의 핵심 판단 요소는 `음수 가중치와 사이클의 존재 여부`, `접근 범위`임
- 이를 설명하는 비교축은 `계산 범위`, `음수 가중치 처리`, `음수 사이클 검증`, `반복 기준`, `적합 조건`, `대표 적용 사례`로 구성할 수 있음
- 비교표에서 선정한 축은 구성요소의 저장 방식, 절차의 반복·검증 단계, 실무 사례의 선택 조건, 결론의 알고리즘 선택 기준으로 끝까지 이어감

## 1. 문장 정밀화 예시

| 구분 | 쓰지 않을 문장 | 권장 문장 | 판정 이유 |
|:---|:---|:---|:---|
| BFS 방문 순서 | BFS는 시작 정점에서 간선 수 기준 거리 0, 1, 2처럼 같은 깊이 레벨의 정점을 먼저 방문한 뒤 다음 레벨로 확장하는 방식임 | BFS는 시작 정점으로부터 가까운 정점을 먼저 모두 방문한 후 멀리 있는 정점을 탐색하는 방식임 | 거리 단계의 수치 나열이 첫 이해에 필요하지 않아 과잉 설명이 됨 |
| DFS 방문 절차 | DFS는 먼 정점까지 먼저 탐색하는 방식임 | DFS는 한 경로의 미방문 인접 정점을 계속 따라가다가 더 진행할 수 없으면 직전 분기점으로 되돌아가는 방식임 | 멀다는 표현만으로 탐색과 복귀 절차를 알 수 없음 |
| BFS 메모리 | BFS에서 폭이 큰 그래프가 메모리를 압박해 동일 레벨 정점이 폭증하면 큐가 커짐 | 같은 거리 후보의 노드가 많을 시 큐 길이가 급격히 늘어날 수 있음 | 원인과 결과를 중복하지 않고 큐 증가 조건을 직접 설명함 |
| DFS 깊이 | DFS 재귀가 깊이 한계를 넘어 편향 그래프에서 호출 깊이가 시스템 제한을 초과할 수 있음 | DFS 재귀 호출이 깊어지면 호출 스택 한도를 초과할 수 있음 | 반복된 깊이 표현을 줄이고 초과 대상을 호출 스택으로 특정함 |
| 불필요한 표현 | 탐색 방식 선택에 따라 얻을 수 있는 결과와 비용이 달라짐 | 삭제 | 결과와 비용이 무엇인지 밝히지 않아 새로운 판단을 제공하지 못함 |
| 단어 배치 | 입력 증가 메모리 사용량 분석 기준이 필요함 | 입력 규모에 따른 메모리 사용량 증가율 분석이 필요함 | 알고리즘 분석 용어인 `입력 규모`를 쓰고 변화 대상을 `증가율`로 특정함. 필요성을 설명하는 자리이므로 `분석이 필요함`을 유지하고 조사 충돌과 명사 나열을 정리함 |
| 자료구조 차이 | 인접 정보는 이웃 정점 목록 또는 행렬이며 자료구조에 따라 상수 비용이 달라짐 | 인접 리스트는 실제 연결만 따라가고, 인접 행렬은 간선 존재 여부를 확인함 | 상수 비용 대신 두 구조의 실제 접근 차이를 보여줌 |
| 근거 없는 수식어 | 인접 행렬은 간선 존재 여부를 바로 확인함 | 인접 행렬은 간선 존재 여부를 확인함 | 확인 순서나 비교 시간이 없으므로 `바로`의 근거가 없음 |
| 배경/필요성 | 그래프 탐색은 정점을 방문하는 알고리즘이므로 필요함 | 네트워크 연결 경로를 찾고 시스템 의존성의 순환을 탐지하기 위해 그래프 탐색이 필요함 | 경로는 `찾고` 순환은 `탐지`하도록 대상별 동사를 구분하고, 정의 반복 대신 해결할 문제를 밝힘 |
| 최단 경로 필요성 | 라우팅·물류·경로 계획은 연결 여부보다 총 비용이 작아야 하므로 가중치 기반 경로 선택 기준이 필요함 | 라우팅 비용 절감을 위해 거리·비용·시간 지연이 가장 작은 경로가 필요함 | 적용 분야를 나열하지 않고 대표 목적과 기준을 연결함 |

### 문장 내부 기승전결과 논리 배치 예시

- 수정 전: `최단 경로는 음수 가중치·계산 범위·음수 사이클 가능성을 기준으로 알고리즘과 검증 절차를 함께 선택해야 함.`
- 수정 후: `최단 경로는 음수 가중치·사이클 존재 여부와 접근 범위를 기준으로 알고리즘을 선택해야 함.`

| 검사 항목 | 수정 전의 문제 | 수정 후의 판단 |
|:---|:---|:---|
| 관련어 묶음 | 음수 가중치와 음수 사이클 사이에 계산 범위가 끼어 논리가 끊김 | 음수 가중치·사이클 존재 여부를 하나의 조건으로 묶음 |
| 용어 정확성 | 계산 범위가 출발·도착 대상의 범위인지 연산량인지 모호함 | 알고리즘이 다루는 출발·도착 범위를 접근 범위로 특정함 |
| 목적어·동사 결합 | 알고리즘과 검증 절차를 모두 선택한다고 표현함 | 선택 대상인 알고리즘만 목적어로 둠 |
| 결론 회수 | 검증 절차라는 새 대상을 문장 끝에 추가함 | 앞의 판단 기준으로 알고리즘을 선택한다는 핵심만 회수함 |
| 문장 흐름 | 조건 나열 뒤 서로 다른 두 동작을 한꺼번에 요구함 | 대상에서 조건과 기준을 거쳐 선택 동작으로 끝남 |

### 근거 없는 수식어 지적 사례

수정 전 문장 `인접 리스트는 실제 연결만 따라가고, 인접 행렬은 간선 존재 여부를 바로 확인함`에서 `바로`는 확인 순서, 시간복잡도, 지연 시간 중 무엇을 뜻하는지 근거가 없다. 따라서 아래처럼 교정한다.

`인접 리스트는 실제 연결만 따라가고, 인접 행렬은 간선 존재 여부를 확인함.`

| 단어 | 근거 | 판정 |
|:---|:---|:---|
| 인접 리스트 | 비교 대상 자료구조 | 유지 |
| 실제 연결 | 저장된 이웃 항목만 순회하는 구조 | 유지 |
| 따라감 | 리스트 순회 동작 | 유지 |
| 인접 행렬 | 비교 대상 자료구조 | 유지 |
| 간선 존재 여부 | 행렬 셀이 나타내는 정보 | 유지 |
| 확인함 | 셀 조회 목적 | 유지 |
| 바로 | 비교 시간·절차 순서 근거 없음 | 삭제 |

이 판정은 모든 문장에 동일하게 적용한다. 단어 하나라도 존재 이유를 설명할 수 없으면 문장을 완료된 것으로 보지 않는다.

### 공유 값과 주제 이탈 예시

- 나쁜 예: `인접 리스트 기준 시간복잡도는 $O(V+E)$임. 희소 그래프는 실제 간선만 확인함.`
- 여전히 나쁜 예: `인접 리스트는 실제 간선만 따라가 시간복잡도가 $O(V+E)$임.`
- 아직 부족한 예: `BFS·DFS는 각 정점과 간선을 한 번씩 처리하므로 시간복잡도가 $O(V+E)$임.`
- 나쁜 예: `BFS·DFS는 시간복잡도가 모두 $O(V+E)$로 같아, 선택 기준은 속도가 아니라 보장 결과임.`
- 좋은 예: `BFS·DFS는 시간복잡도가 모두 $O(V+E)$로 같아, 선택 기준은 속도가 아니라 방문 절차임.`

비교 대상이 공유하는 값은 그 자체로 차별점이 아니다. 같은 값에서 무엇이 달라지는지 문맥에 맞는 기준으로 설명하고, 불필요한 반대 개념을 끌어와 주제를 벗어나지 않는다.

### 시간복잡도 남용 예시

- 나쁜 예: 크루스칼·프림 비교표에 선택 방식, 자료구조, 적용 사례와 함께 시간복잡도 수식을 관성적으로 추가함
- 나쁜 이유: 최소 신장 트리의 선택 절차와 그래프 입력 형태를 묻는 문맥에서 수식이 실제 선택 기준을 대신하지 못하고 표의 중심만 흐림
- 좋은 예: `그래프 입력 형태 | 간선 목록을 정렬해 처리 | 인접 리스트·행렬에서 연결 노드를 확장`
- 좋은 예: `선택 조건 | 간선 목록이 주어지고 연결 요소를 합칠 때 | 시작 지점에서 연결 범위를 확장할 때`

시간복잡도가 주제 자체이거나 입력 규모에 따른 성능 차이가 알고리즘 선택을 직접 가르면 수식을 유지한다. 그렇지 않으면 대표 적용 사례, 입력 형태, 처리 절차, 제약 조건 중 주제에 맞는 축을 사용한다.

### 비교표 행·열 타당성 예시

- 나쁜 행: `장점 | 빠르고 효율적임 | 안정적이고 유연함`
  - 비교 대상의 어떤 구조가 어떤 결과를 만드는지 없고 다른 주제에도 그대로 붙는 일반론임
- 나쁜 셀 대응: `처리 방식 | 간선을 정렬함 | 밀집 그래프에 유리함`
  - 왼쪽은 동작 원리이고 오른쪽은 적용 조건이므로 같은 분석 수준이 아님
- 좋은 셀 대응: `선택 방식 | 전체 간선을 가중치 순으로 선택 | 현재 트리와 외부 노드를 잇는 간선을 선택`
  - 두 셀이 모두 간선 선택 절차를 설명함
- 핵심 누락 예: 크루스칼·프림 표에 시간복잡도와 장점은 있지만 사이클 처리와 입력 형태가 없음
  - 행 수와 관계없이 실제 구현·선택 기준이 빠졌으므로 미완성 표임
- 불필요한 열 예: 알고리즘 열 사이에 `공통점` 열을 추가해 두 알고리즘의 동일한 결과를 반복함
  - 공통점은 표 앞 문장으로 설명하고 비교 열은 독립된 대상만 유지함

표의 모든 요소는 `주제 필요성 -> 비교 차이 -> 뒤 절의 회수`를 설명할 수 있어야 한다. 설명할 수 없는 행·열·셀은 문장이 자연스러워도 유지하지 않는다.

## 2. 내용 선별 예시

`희소 그래프`를 언급할 때 반대인 `밀집 그래프`도 써야 하는지 판단한다. 인접 리스트의 이점을 설명하는 자리라면 밀집 그래프와 한 줄로 대비하지만, 그래프 탐색 자체가 주제라면 밀집 그래프까지 확장하지 않고 해당 언급을 삭제한다.

## 3. 비교표·요약문 예시

| 교정 대상 | 수정 전 | 수정 후 | 교정 기준 |
|:---|:---|:---|:---|
| 선택 기준 | 음수 가중치 여부와 계산 범위를 먼저 보고 최단 경로 알고리즘을 선택함 | 음수 가중치 존재 여부와 접근 범위를 보고 최단 경로 알고리즘을 선택함 | 판단 관계를 자연스럽게 연결함 |
| 검증 조건 | 음수 사이클과 도달 불가능 정점을 결과 해석에 반영함 | 음수 사이클은 계산 실패로, 단절 노드는 경로 없음으로 표시함 | 결과 상태를 직접 밝힘 |
| 경로 기록 | 최단 경로 자체를 복원할 때 직전 정점을 기록함 | 도착 노드까지 실제 이동 경로를 되짚기 위해 각 노드에 바로 앞 노드를 기록함 | 기록 목적과 대상을 밝힘 |
| 구조 요약 | 거리 저장소와 완화 기준이 일치해야 최단 거리와 경로를 함께 산출함 | 거리값과 바로 앞 노드를 함께 기록하면 최단 거리와 실제 이동 경로를 모두 확인할 수 있음 | 추상 조건을 실제 저장 동작으로 바꿈 |
| 절차 요약 | 최단 경로 알고리즘은 처리 대상이 달라도 거리값 갱신과 예외 검증으로 결과를 확정함 | 알고리즘별 반복 기준에 따라 완화를 수행하고, 음수 사이클·단절 노드를 검증하여 최단 경로를 확정함 | 처리 대상과 예외를 구체화함 |
| 명사형 축약 | 음수 사이클·도달 불가·경로 복원 가능성을 확인함 | 음수 사이클·단절 노드·실제 이동 경로 생성 여부를 확인함 | 억지 축약어를 사용하지 않음 |
| 실무 검증 | 라우팅처럼 음수 가중치가 없는 그래프는 다익스트라를 쓰고 p99 탐색 지연과 큐 크기로 검증함 | 음수 가중치가 없는 라우팅은 다익스트라를 적용하며, p99 지연 시간 및 큐 크기 기반으로 성능 임계치를 검증함 | 적용·검증 대상을 생략하지 않음 |
| 결론 | 최단 경로는 음수 가중치·계산 범위·음수 사이클 가능성을 기준으로 알고리즘과 검증 절차를 함께 선택해야 함 | 최단 경로는 음수 가중치·사이클 존재 여부와 접근 범위를 기준으로 알고리즘을 선택해야 함 | 관련 조건을 묶고 정확한 용어를 사용하며 선택 대상만 서술어와 연결함 |

## 4. 실무 사례 예시

| 수정 전 | 수정 후 |
|:---|:---|
| 문제: DFS 재귀가 깊이 한계를 넘어 편향 그래프에서 호출 깊이가 시스템 제한을 초과할 수 있음 | 의존성 순환 검사에는 DFS를 적용하되 재귀 호출이 스택 한도를 초과할 수 있으므로 깊은 입력은 반복 DFS로 전환하고 최대 탐색 깊이와 메모리 사용량을 검증함 |
| 메모리 조회 집중 시스템에서는 AVL로 경로 길이를 짧게 유지함, 확인 지표는 조회 지연시간과 회전 횟수임 | 조회가 많은 메모리 색인은 AVL을 적용하고 p95 조회 지연과 회전 횟수로 탐색 성능과 갱신 비용을 검증함 |

문장을 줄이더라도 적용 대상, 검증 대상, 판단 기준을 삭제하지 않는다. 짧지만 무엇을 검증하는지 알 수 없으면 과잉 압축으로 판정한다.

## 5. 어휘 검수 예시

노트가 누적되면 `안정적`, `막다`, `높이다` 같은 모호어를 문장 단위가 아니라 어휘 단위로 전수 검색하고 판별표로 교정한다.

1. 대상 어휘가 들어간 모든 줄을 파일·줄 번호와 함께 검색함
2. 기술 용어로 의미가 확정됐는지, 근거 없이 문장을 마무리한 모호어인지 판별함
3. 안정 정렬·메타안정성처럼 의미가 고정된 기술 용어는 유지함
4. 모호어는 문맥이 요구하는 구체적인 대상·상태·동작으로 바꿈

| 파일:줄 | 원문 어휘 | 판정 | 교정 |
|:---|:---|:---|:---|
| 028:20 | 안정적으로 반영 | 유지 — 정착 시간($Settling$ $Time$)의 기술적 정의 | - |
| 029:87 | 안정적으로 동작함 | 모호 — 무엇이 안정적인지 불명확 | 오동작 없이 동작함 |
| 046:32 | 안정적인 구간 | 모호 — 안정이 가리키는 지표 불명 | 분산이 작은 구간 |
| 051:52 | 수치 불안정을 막음 | `막다` 금지어 | 수치 불안정을 방지함 |
| 060:16 | 안정적인 결과 | 모호 — 본문이 이미 분산을 정의어로 사용함 | 분산이 낮은 결과 |

## 6. 모호 표현 예시

| 모호한 표현 | 교정 |
|:---|:---|
| 최고차항·상수 제거 | 하위 항과 계수를 제거하고 최고차항만 남김 |
| 암호화·복호화 처리 | 송신 측이 암호화하고 수신 측이 복호화함 |
| 정책과 로그로 통제 | 정책으로 검증하고 결과를 로그로 남김 |
| 중복 삽입을 막음 | 발견 시점 표시로 중복 삽입을 방지함 |
| 경로·순환 판단 | 경로 구조 분석이나 순환 탐지 |

`경로·순환 판단`에서 순환은 존재 여부를 판단하지만 경로는 분석·추적한다. 두 명사를 가운데점으로 묶기 전에 각각 어떤 동사와 자연스럽게 짝지어지는지 확인한다.
