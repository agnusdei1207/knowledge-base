# 컴퓨터시스템응용기술사 통합 학습 전략

> 기출 132~138회(2023~2026) 전수 분석 + 합격후기 기반.

---

## ⛔ 답안 작성 0순위 규칙 — 추상 표현 절대 금지

**"추상 표현은 점수로 이어지지 않는다."**

채점자는 형용사·부사로 끝나는 문장을 읽지 않는다. 아래 패턴이 나오면 즉시 교체한다.

| 금지 (점수 0) | 통과 (점수 인정) |
|:---|:---|
| 성능이 향상된다 | p99 지연 200ms→50ms, 처리량 3,000→10,000 TPS |
| 보안이 강화된다 | AES-256-GCM 암호화, mTLS 상호인증, RBAC 최소권한 |
| 안정성이 높아진다 | RTO 4분 이하, RPO 15분, 가용성 99.9%, MTTR 10분 |
| 효율적으로 처리된다 | CPU 이용률 70%→40%, 배포 시간 45분→8분 |
| 확장이 용이하다 | HPA min 2/max 20, 스케일아웃 트리거 CPU 70% |
| 최신 기술을 적용한다 | 기존 한계(수치) + 신기술 도입 후 개선값(수치) |
| 위협에 대응한다 | MITRE ATT&CK T1190 매핑, Sigma 탐지 규칙, SOAR 플레이북 |

**규칙: 모든 효과 문장은 수치·표준명·기술명·비교값 중 최소 1개로 끝낸다.**

## Ⅰ. 시험 구조 이해

| 교시 | 유형 | 선택 구조 | 시간 | 배점 |
|:---:|:---|:---|:---:|:---:|
| 1교시 | 단답형 | 13문항 중 10선택 | 100분 | 각 10점 |
| 2교시 | 서술형 | 6문항 중 4선택 | 100분 | 각 25점 |
| 3교시 | 서술형 | 6문항 중 4선택 | 100분 | 각 25점 |
| 4교시 | 서술형 | 6문항 중 4선택 | 100분 | 각 25점 |

- 합격 기준: 전 교시 평균 60점 이상 (400점 만점 기준 240점), 과락 없음
- 목표 점수: 1교시 70점 / 2~4교시 각 65점 → 전체 평균 67~70점

> 요약: 400분 동안 1교시 10문항 단답 + 2~4교시 각 4문항 서술. 선택권이 있으므로 쓸 수 있는 문제를 고르는 전략이 핵심.

## Ⅲ. 핵심 원칙 — 3쪽을 채우려면 2~4과목을 엮어야 한다

**서술형 답안 3쪽은 단일 과목 지식으로 채울 수 없다.** 기출 분석 결과, 합격권 문제는 모두 2~4개 과목이 교차한다.

### 실제 기출 교차 패턴

| 문제 (회차) | 교차 과목 | 3쪽 구성 방식 |
|:---|:---|:---|
| AI 에이전트 시스템 설계 (133·138회) | AI + SW공학 + 보안 | 구조(AI) + ReAct 흐름(SW) + 프롬프트 인젝션 대응(보안) |
| 제로트러스트 아키텍처 (135회) | 보안 + 네트워크 + 클라우드 | ZTNA 구조(보안) + 마이크로세그먼트 흐름(네트워크) + SASE 적용(클라우드) |
| MSA 전환 (136회) | SW공학 + 클라우드 + DB | DDD 분해(SW) + Istio 서비스 메시(클라우드) + DB per Service(DB) |
| LLM 파인튜닝 비교 (135·133회) | AI + 컴퓨터구조 + SW공학 | 학습 방식 비교(AI) + GPU/VRAM 구조(하드웨어) + PEFT 배포(SW) |
| 클라우드 보안 공유 책임 (137회) | 클라우드 + 보안 + IT거버넌스 | 서비스 모델별 경계(클라우드) + 통제 매핑(보안) + 감사 체계(거버넌스) |

### 교차 공식 적용법

```text
Ⅰ. 개요 (0.3쪽)
   → 문제의 배경·필요성. 키워드 1개 → 2~3개 과목 연결점 명시

Ⅱ. 구조 및 구성요소 (0.7쪽)
   → ASCII 구조도 + 구성요소 표
   → 구성요소 각각에 과목 레이블 표시 (예: AI층 / 보안층 / 인프라층)

Ⅲ. 동작원리 및 흐름도 (0.7쪽)
   → ASCII 흐름도 + 단계 표
   → 각 단계에서 교차 과목 요소가 어떻게 작동하는지 수치로 명시

Ⅳ. 특징 (0.5쪽)
   → 비교표: 기존 방식 vs 본 기술 (수치 컬럼 필수)
   → 장점·한계 각 2~3줄. 추상 표현 금지.

Ⅴ. 적용방안·결론 (0.3쪽)
   → 단기(PoC)·중기(전환)·장기(운영) 3단계
   → 기술사 판단: 조건A면 X, 조건B면 Y 형식
```

> 요약: Ⅱ 구성요소 표에 과목 레이블을 붙이고, Ⅲ 흐름 단계마다 수치를 넣으면 자연스럽게 3쪽이 채워진다.

## Ⅳ. 답안 작성 규칙 — 구체 표현 강제

### 구성요소 표 작성법

```markdown
| 구성요소 | 역할 | 구체 수치/표준 |
|:---|:---|:---|
| Vector DB (Pinecone) | 임베딩 유사도 검색 | 코사인 유사도 top-k=5, 응답 20ms |
| Reranker (Cross-Encoder) | 검색 결과 재정렬 | MRR@10 0.72→0.89 향상 |
| LLM (GPT-4o) | 답변 생성 | 최대 128K 컨텍스트, 할루시네이션율 12%→3% |
```

❌ 나쁜 예: "벡터 DB가 검색을 담당한다"  
✅ 좋은 예: "Pinecone 벡터 DB가 코사인 유사도 기준 top-k=5 검색, 응답 20ms 이내"

### 특징 표 작성법

```markdown
| 구분 | 기존 방식 | 본 기술 | 판단 기준 |
|:---|:---|:---|:---|
| 최신성 | 학습 데이터 컷오프 고정 | 실시간 문서 검색 반영 | 자주 변하는 도메인 → RAG |
| 구축 비용 | Fine-tuning: GPU 수백 시간 | RAG: 벡터 DB 구축 2~3일 | 빠른 POC → RAG |
| 정확도 | 도메인 특화 고정 | 검색 품질에 의존 | 고정 도메인 심화 → Fine-tuning |
```

### 흐름도 작성법

```text
[요청] → [임베딩 변환 (384차원)] → [Vector DB 검색 (top-5, 20ms)]
       → [Reranker 재정렬 (MRR 0.89)] → [프롬프트 보강 (max 8K 토큰)]
       → [LLM 생성 (GPT-4o, 2s)] → [응답 반환 + 출처 명시]
```

❌ 나쁜 예: `질의 → 검색 → 생성 → 답변`  
✅ 좋은 예: 각 단계에 처리 방식·수치·소요 시간 명시

## Ⅴ. 시간 배분 — 2~4교시 25분 운용

| 시간 | 행동 | 산출물 |
|:---:|:---|:---|
| 0~2분 | 6문제 훑기 → 쓸 수 있는 4문제 선택 | 선택 번호 체크 |
| 2~4분 | Ⅰ 개요 + 과목 교차 구조 스케치 | 목차 키워드 5~7개 |
| 4~7분 | Ⅱ ASCII 구조도 + 구성요소 표 | 구조도 + 3~4행 표 |
| 7~12분 | Ⅲ ASCII 흐름도 + 단계 표 | 흐름도 + 4단계 표 |
| 12~18분 | Ⅳ 특징 비교표 (기존 vs 본 기술) | 3~4행 비교표 |
| 18~23분 | Ⅴ 단기·중기·장기 방안 + 결론 | 3단계 + 기술사 판단 1줄 |
| 23~25분 | 추상 표현 점검 → 수치로 교체 | 최종 검수 |

> **25분 안에 못 쓰면 Ⅴ 결론을 한 줄로 압축하고 넘어간다. 미완성이 빈칸보다 낫다.**

## Ⅵ. 1교시 단답형 전략

1교시 답안은 2~4교시 Ⅰ~Ⅲ의 압축판이다.

```markdown
### [키워드명 (영문명)]

- **정의**: [주어 + 동사 + 목적어, 30자 이내]
- **구성/원리**: [핵심 요소 3개, 기술명 포함]
- **특징**: [장점 1개 + 한계 1개, 수치 포함]
- **미니 흐름**: 입력 → [핵심 처리] → 출력 (3칸)
- **적용 포인트**: [실무 조건 또는 비교 대상 1줄]
```

- 10분/문항 엄수: 6분 작성 + 1분 수치 점검 + 3분 이동
- 추상 표현이 있으면 마지막 1분에 교체

## Ⅶ. 1000 키워드 선정 기준

기존 9,000개 파일은 범위가 지나치게 넓다. 시험 답안 서술이 즉시 가능한 수준의 1,000개를 새로 작성한다.

### 선정 기준

| 기준 | 내용 |
|:---|:---|
| 기출 등장 | 132~138회에 1회 이상 출제된 키워드 |
| 교차 활용 | 2개 이상 문제에서 구성요소·비교 대상으로 등장하는 키워드 |
| 서술 가능 | 구조도 + 구성요소 표 + 특징 표를 25분 안에 완성할 수 있는 수준 |
| 제외 | 전압·저항·BJT 등 물리/전자회로 레벨, 순수 이론 수식 |

### 과목별 목표 키워드 수

| 과목 | 목표 수 | 근거 |
|:---|:---:|:---|
| AI/LLM | 180개 | 매회 28% 비중, 빠른 기술 변화 |
| 보안 | 160개 | 매회 22% 비중, PQC·Zero Trust 심화 |
| 클라우드/인프라 | 140개 | 매회 18% 비중 |
| SW공학 | 130개 | 매회 14% 비중 |
| DB/데이터 | 100개 | 매회 9% 비중 |
| OS/컴퓨터구조 | 100개 | 매회 9% 비중 |
| 네트워크 | 60개 | ★ 단답형 위주 |
| IT거버넌스 | 60개 | ★ 서술형 회피용 최소 확보 |
| **합계** | **930개** | 실질 커버 범위 |

> 요약: 1,000개 키워드는 충분하다. 단, 각 키워드가 구조도+표+수치까지 즉시 서술 가능한 수준이어야 한다. 개념 정의만 아는 것은 1교시 단답형에만 통한다.

## Ⅷ. 학습 타임라인 (2026 기준)

### 7월 — 기반 구축

| 주 | 작업 |
|:---:|:---|
| 1주 | AI/LLM 핵심 30개 키워드 → 구조도+표 완성 |
| 2주 | 보안 핵심 30개 키워드 → 구조도+표 완성 |
| 3주 | 클라우드 핵심 30개 키워드 → 구조도+표 완성 |
| 4주 | SW공학 핵심 30개 키워드 + 25분 타이머 연습 첫 회 |

### 8월 — 교차 훈련

- 주 3회 25분 타이머: 2~4과목 교차 문제 선택 → 3쪽 완성
- 과목 교차 조합 연습: AI+보안, 클라우드+SW공학, DB+OS
- 실전 모의 1회 (4교시 풀세트, 400분)
- 추상 표현 점검 루틴: 작성 후 형용사 동사 검색 → 수치로 교체

### 9월 — 실전 최적화

- 실전 모의 2회
- 약점 과목 집중 보완
- 1교시 단답형 속도 점검: 6분/문항 내 완성

### 10월 직전 — 최종 점검

- 고빈도 50개 최종 회독 (구조도+수치 기억 확인)
- 손 글씨 속도 최종 측정 (3쪽 = 약 750~900자 기준)
- 목차 고정 확인: `Ⅰ개요-Ⅱ구조·구성요소-Ⅲ동작원리·흐름도-Ⅳ특징-Ⅴ적용·결론`
