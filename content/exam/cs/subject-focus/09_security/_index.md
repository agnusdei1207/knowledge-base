> 컴퓨터시스템응용기술사 09 보안 과목 — 시험장에서 바로 옮겨 쓰는 답안 골격 모음. (studynote 키워드 목록과 달리, 정의·표·모범답안 전개를 담은 작성용 문서)
> 과목 총 노트 수: 1049개 (고빈출 과목)

## 핵심 인사이트 (3줄 요약)

1. 본질: 보안은 감점 방지가 아니라 독립 득점 축이다. "자산-위협-취약점-통제-운영" 순서로 쓰면 어떤 문제든 구조가 잡힌다.
2. 가치: 암호·네트워크·애플리케이션·IAM·침해대응을 한 문제에서 엮는 통합형이 늘고 있고, 클라우드·API·AI·공급망으로 출제 무게가 이동 중이다.
3. 판단 포인트: 원리만 적지 말고 적용 위치·성능·키관리·법제도까지 묶어야 기술사 수준 답안이 된다. 제로 트러스트와 공급망 보안은 거의 모든 설계형 문제의 채점 축이다.

## Ⅰ. 과목 개요

- 보안은 컴퓨터시스템응용기술사에서 매 회차 출제되는 최고빈출 과목군이다. 1교시 단답은 정의·분류·절차·공격 4유형으로, 2~4교시 서술은 "설계할 수 있는가"를 묻는 통합형으로 나온다.
- 답안 표준 골격: Ⅰ개요(정의+필요성) → Ⅱ구조/원리(도식 필수) → Ⅲ특징/비교(표 필수) → Ⅳ적용/방안(번호) → Ⅴ결론(기술사적 판단+발전방향).
- 약어는 최초 1회 풀네임 병기. 예: AES(Advanced Encryption Standard), IAM(Identity and Access Management).
- 채점 가산 포인트: 위협 모델링 관점, 계층형 방어(Defense in Depth), 키/인증서 생명주기, 법·제도(개인정보보호법·ISMS-P) 분리 서술.

## Ⅱ. 1교시 단답형 핵심 (앞단위)

핵심 키워드 정의·포인트 표 (각 키워드 10점, ~10분 / 13문제 중 10문제 선택).

| 키워드 | 한줄 정의 | 핵심 3포인트 |
|:---|:---|:---|
| 제로 트러스트(Zero Trust) | "Never Trust, Always Verify" — 위치 무관 모든 접근 검증 (NIST SP 800-207) | ① 신원·디바이스·맥락 지속 검증 ② 마이크로 세그멘테이션·최소권한 ③ PEP/PDP 정책엔진 구조 |
| PKI(Public Key Infrastructure) | 공개키 인증서 발급·관리·폐기 신뢰 체계 | ① CA/RA/저장소 구성 ② X.509 인증서 체인 검증 ③ CRL/OCSP 폐지 확인 |
| IAM(Identity and Access Management) | 신원과 접근권한 통합 생명주기 관리 | ① Joiner/Mover/Leaver 프로비저닝 ② SSO·MFA·페더레이션 ③ RBAC/ABAC 인가 |
| 대칭키 암호(Symmetric) | 동일 키로 암·복호화 (AES 등) | ① 고속·대용량 적합 ② 키 분배 문제 ③ 블록(AES)/스트림(ChaCha20) |
| 비대칭키 암호(Asymmetric) | 공개키/개인키 쌍 (RSA, ECC) | ① 키 분배·전자서명 해결 ② 저속 → 키교환·서명용 ③ 소인수분해/이산로그 기반 |
| 해시 함수(Hash) | 임의 입력 → 고정 길이 단방향 요약 | ① 무결성 검증·MAC ② 충돌·역상 저항성 ③ SHA-2/3, salt·키스트레칭 |
| 전자서명(Digital Signature) | 개인키 서명·공개키 검증으로 무결성·부인방지 | ① 해시 후 개인키 서명 ② 위변조 탐지+부인방지 ③ RSA-PSS·ECDSA·EdDSA |
| 침입탐지(IDS) | 트래픽·로그 분석으로 공격 탐지 | ① 시그니처/이상 탐지 ② 미러링(out-of-band) 배치 ③ 탐지만, 차단은 IPS |
| 방화벽(Firewall) | 정책 기반 네트워크 접근 제어 | ① 패킷필터→상태검사→NGFW ② DMZ·세그멘테이션 ③ L7 앱·사용자 식별 |
| WAF(Web Application Firewall) | HTTP/HTTPS 계층 웹 공격 차단 | ① OWASP CRS 규칙 ② SQLi·XSS 탐지 ③ 가상 패칭 |
| MFA(Multi-Factor Authentication) | 지식·소유·내재 등 2요소 이상 인증 | ① TOTP/HOTP·푸시 ② FIDO2/Passkey 피싱저항 ③ 크리덴셜 스터핑 방어 |
| RBAC/ABAC | 역할 기반 / 속성 기반 접근 제어 | ① RBAC=역할-권한 매핑 ② ABAC=주체·객체·환경 속성 ③ 최소권한·직무분리(SoD) |
| TLS(Transport Layer Security) | 전송계층 기밀성·무결성·인증 | ① 1.3 1-RTT·AEAD 의무 ② ECDHE 전방비밀성(PFS) ③ 인증서 기반 서버인증 |
| SBOM(Software Bill of Materials) | 소프트웨어 구성요소 명세서 | ① 의존성 가시성 ② 취약점(CVE) 추적 ③ SPDX/CycloneDX, VEX 연계 |
| 공급망 보안(Supply Chain) | 빌드·배포·의존성 전반 무결성 보호 | ① 의존성 오염·빌드 변조 ② SBOM·서명·SLSA ③ Log4Shell 교훈 |
| PQC(Post-Quantum Cryptography) | 양자컴퓨터 내성 암호 | ① Shor가 RSA/ECC 위협 ② Kyber(KEM)·Dilithium(서명) ③ Harvest-Now-Decrypt-Later·crypto agility |
| DevSecOps | CI/CD에 보안을 좌측 이동(Shift-Left) 통합 | ① SAST/DAST/SCA 자동화 ② 파이프라인 보안 게이트 ③ IaC·시크릿 스캔 |
| 개인정보보호(Privacy) | 개인정보 수집·이용·파기 보호 | ① 개인정보보호법·ISMS-P ② 가명·익명 비식별화 ③ Privacy by Design |
| MITRE ATT&CK | 공격자 전술·기법·절차(TTP) 지식베이스 | ① 14개 전술 매트릭스 ② 탐지룰·위협헌팅 매핑 ③ Diamond Model·Kill Chain 연계 |
| SIEM/SOAR | 로그 상관분석 / 자동화 대응 | ① SIEM=수집·정규화·상관 ② SOAR=플레이북 자동화 ③ SOC 관제 핵심 |
| DLP(Data Loss Prevention) | 민감데이터 유출 탐지·차단 | ① 콘텐츠·맥락 분석 ② 엔드포인트/네트워크/스토리지 ③ 분류·태깅 기반 정책 |

1교시 답안 공식 1줄: `정의 1줄 → 특징 숫자 3개 → ASCII 도해 3줄 → 미니표 3행 → 적용/비교 1줄` (약어 최초 1회 풀네임 병기).

## Ⅲ. 2~4교시 서술형 확장 (심화)

각 교시 6문제 중 4문제, 문제당 25점·22~24분·3~3.5쪽. 아래 5개 토픽은 출제 빈도 최상위.

### 1. 제로 트러스트 아키텍처(Zero Trust Architecture)

- 정의: 네트워크 위치를 신뢰 근거로 삼지 않고, 모든 접근 요청을 신원·디바이스·맥락 기반으로 매번 검증하는 보안 모델(NIST SP 800-207).

- Ⅰ. 개요: 경계(Perimeter) 붕괴 — 클라우드·재택·BYOD로 내부망 신뢰 가정이 무너짐. "Never Trust, Always Verify".
- Ⅱ. 구조/원리:

```text
[사용자/디바이스] ──요청──> [PEP 정책시행지점]
                                │ 질의
                                ▼
              [PDP 정책결정] ← 신원(IdP)·디바이스·위협TI·맥락 신호
                                │ 허용/거부/조건
                                ▼
                        [보호 대상 자원/워크로드]
   (전 구간 마이크로 세그멘테이션 + 최소권한 + 지속 검증)
```

- Ⅲ. 특징/비교 (경계보안 vs 제로트러스트):

| 구분 | 경계보안(Perimeter) | 제로 트러스트(Zero Trust) |
|:---|:---|:---|
| 신뢰 모델 | 내부=신뢰, 외부=불신 | 위치 무관 항상 검증 |
| 통제 단위 | 네트워크 경계(방화벽) | 신원·세션·워크로드 |
| 측면 이동 | 내부 침투 시 확산 용이 | 마이크로 세그로 차단 |
| 인증 시점 | 최초 1회 | 지속·조건부 |
| 적용 환경 | 온프레미스 | 클라우드·하이브리드 |

- Ⅳ. 적용/방안: ① 신원 중심 — IAM·MFA·디바이스 인증 ② SDP/마이크로 세그멘테이션으로 East-West 통제 ③ 정책엔진(PDP/PEP) 도입 ④ 가시성 — 로그·UEBA·지속 모니터링 ⑤ SASE로 네트워크+보안 통합. 단계적(자산식별→정책→자동화) 로드맵 권장.
- Ⅴ. 결론: 제로 트러스트는 제품이 아니라 전략·여정이며, IAM 성숙도와 가시성 확보가 선행 조건이다.

### 2. 대칭키 vs 비대칭키 암호와 하이브리드 구조

- 정의: 대칭키는 동일 키로 암·복호화, 비대칭키는 공개/개인키 쌍을 쓰며, 실무는 둘을 결합한 하이브리드(KEM/DEM) 구조를 사용한다.

- Ⅰ. 개요: 기밀성·무결성·인증·부인방지 제공. 대칭은 속도, 비대칭은 키분배·서명을 해결.
- Ⅱ. 구조/원리 (하이브리드 암호):

```text
[송신자] ──비대칭(수신자 공개키)로 세션키 암호화──> [수신자]
   │                                                  │ 개인키로 세션키 복호
   └──대칭(세션키)로 대용량 데이터 암호화──────────────> 데이터 복호
   (키교환=비대칭/ECDHE, 데이터=대칭/AES-GCM)
```

- Ⅲ. 특징/비교 (대칭 vs 비대칭):

| 구분 | 대칭키 | 비대칭키 |
|:---|:---|:---|
| 키 | 단일 공유키 | 공개/개인키 쌍 |
| 속도 | 빠름(대용량 적합) | 느림(소량·키교환) |
| 키 분배 | 어려움(사전 공유) | 공개키로 해결 |
| 대표 | AES, ChaCha20 | RSA, ECC, ECDH |
| 용도 | 데이터 암호화 | 키교환·전자서명 |
| 키 수(n자) | n(n-1)/2 | 2n |

- Ⅳ. 적용/방안: ① TLS 1.3 = ECDHE 키교환 + AES-GCM(AEAD) ② 키 생명주기(생성·분배·저장·순환·폐기) HSM/KMS 관리 ③ PQC 전환 대비 crypto agility ④ 전방비밀성(PFS) 보장 위해 Ephemeral 키 사용.
- Ⅴ. 결론: 단일 방식이 아닌 하이브리드가 표준이며, 양자 위협에 대비해 알고리즘 교체 가능한 설계가 핵심이다.

### 3. IDS/IPS와 계층형 침입 대응 + 위협-대응 매핑

- 정의: IDS는 침입을 탐지(경보)하고, IPS는 인라인 배치로 탐지+실시간 차단까지 수행하는 능동 방어체계다.

- Ⅰ. 개요: 단일 방화벽으로는 알려진/미지 공격을 모두 막을 수 없어 탐지·대응 계층이 필요.
- Ⅱ. 구조/원리:

```text
[외부] → [방화벽] → [IPS 인라인 차단] → [내부망/세그먼트]
                          │                    │
                      [IDS 미러링 탐지]    [HIDS/EDR 엔드포인트]
                          ↓
                     [SIEM 상관분석] → [SOAR 자동대응 플레이북]
```

- Ⅲ. 특징/비교 (IDS vs IPS):

| 구분 | IDS | IPS |
|:---|:---|:---|
| 배치 | Out-of-band(미러) | In-line(경로상) |
| 동작 | 탐지·경보 | 탐지·차단 |
| 지연 | 트래픽 영향 없음 | 처리 지연 가능 |
| 오탐 영향 | 경보만 | 정상차단 위험 |
| 탐지 방식 | 시그니처/이상 | 동일 + 능동 차단 |

- Ⅳ. 위협-대응 매핑 표:

| 위협 | 공격 면 | 대응 통제 | 한계/보완 |
|:---|:---|:---|:---|
| DDoS | 네트워크·앱 계층 | Rate Limit·Anycast·Scrubbing | 볼류메트릭은 ISP 협력 필요 |
| SQL Injection | 웹 입력값 | WAF·파라미터 바인딩 | 근본은 시큐어 코딩 |
| 랜섬웨어 | 엔드포인트·측면이동 | EDR·세그멘테이션·백업 | 오프라인 백업 필수 |
| 크리덴셜 탈취 | 인증 | MFA·FIDO2·PAM | 피싱저항 인증 필요 |
| APT 측면이동 | 내부망 | 마이크로 세그·UEBA·위협헌팅 | 가정침투(Assumed Breach) 전제 |

- Ⅴ. 결론: 단일 장비가 아닌 NGFW+IPS+EDR+SIEM/SOAR의 계층형·자동화 대응이 현대 위협 대응의 핵심이다.

### 4. PKI와 전자서명 기반 신뢰 체계

- 정의: PKI는 공개키와 신원을 인증서로 결합해 발급·검증·폐기하는 신뢰 인프라이며, 전자서명·인증·기밀성의 기반이다.

- Ⅰ. 개요: 공개키의 소유자 신뢰 문제를 CA의 보증으로 해결. 인터넷 신뢰(TLS·코드서명·전자문서)의 토대.
- Ⅱ. 구조/원리:

```text
[가입자] →CSR→ [RA 신원검증] → [CA 인증서 발급/서명]
                                      │
              [저장소/CT 로그]    [X.509 인증서]
                   │                  │ 사용
            [CRL / OCSP] ←폐지확인── [검증자: 체인검증 Root→Inter→EE]
```

- Ⅲ. 특징/비교 (CRL vs OCSP):

| 구분 | CRL | OCSP |
|:---|:---|:---|
| 방식 | 폐지목록 일괄 배포 | 실시간 상태 질의 |
| 실시간성 | 낮음(주기 갱신) | 높음 |
| 부하 | 클라이언트 다운로드 | 응답자 부하 |
| 개선 | delta CRL | OCSP Stapling |

- Ⅳ. 적용/방안: ① TLS 서버 인증·mTLS ② 코드 서명(공급망 무결성)·문서 전자서명+TSA(타임스탬프) 부인방지 ③ 인증서 생명주기 자동화(ACME) ④ 키는 HSM 보관, 인증서 핀닝·CAA·CT로 오발급 방어 ⑤ PQC 서명(Dilithium) 전환 대비.
- Ⅴ. 결론: PKI는 신뢰의 출발점이나 키·인증서 관리 실패가 전체 붕괴로 이어지므로 자동화된 생명주기 관리가 관건이다.

### 5. 소프트웨어 공급망 보안과 DevSecOps

- 정의: 개발·빌드·배포·의존성 전 과정의 무결성을 보장하고, 보안을 CI/CD에 통합(Shift-Left)하는 체계.

- Ⅰ. 개요: Log4Shell·SolarWinds처럼 신뢰된 경로를 통한 공격이 급증. 코드 외부 의존성이 공격 표면이 됨.
- Ⅱ. 구조/원리:

```text
[코드] →SAST/시크릿스캔→ [빌드] →SCA/SBOM생성→ [서명/증명]
                                                    │ SLSA·서명검증
                                                    ▼
[레지스트리] →이미지스캔→ [배포] →DAST/런타임보호→ [운영 모니터링]
```

- Ⅲ. 특징/비교 (전통 보안 vs DevSecOps):

| 구분 | 전통(Bolt-on) | DevSecOps |
|:---|:---|:---|
| 시점 | 출시 직전 | 전 단계(Shift-Left) |
| 주체 | 보안팀 분리 | 개발·운영·보안 공동 |
| 방식 | 수동 점검 | SAST/DAST/SCA 자동화 |
| 속도 | 병목 | 파이프라인 통합 |
| 산출물 | 점검 보고서 | SBOM·서명·증명 |

- Ⅳ. 적용/방안: ① SBOM(SPDX/CycloneDX) 생성·관리, VEX로 취약점 적용성 판단 ② 의존성 핀닝·서명 검증으로 의존성 오염 차단 ③ SLSA 빌드 무결성 레벨 ④ 시크릿 관리(Vault)·IaC 스캔 ⑤ CTEM으로 지속적 노출 관리.
- Ⅴ. 결론: 공급망 보안은 SBOM 가시성 + 서명 무결성 + 자동화 게이트의 결합이며, DevSecOps 문화 정착이 전제다.

## Ⅳ. 출제 포인트 & 함정

| 출제유형 | 1교시 단답 포인트 | 2~4교시 서술 포인트 |
|:---|:---|:---|
| 정의형 (AES·RSA·TLS) | 풀네임+키길이/구조 1줄 | 원리+적용위치+성능+키관리 통합 |
| 분류/비교형 (대칭vs비대칭, IDS vs IPS) | 핵심 차이 3행 미니표 | 비교표+선택 기준+적용 상황 |
| 절차형 (인증·키교환·사고대응) | 단계 나열(IR 6단계 등) | 흐름도+각 단계 통제 포인트 |
| 공격형 (SQLi·XSS·SSRF·랜섬웨어) | 원리+대표 대응 1개 | 위협-대응 매핑표+근본 대책 |
| 설계형 (제로트러스트·공급망) | 구성요소 키워드 | 아키텍처 도식+단계적 로드맵 |
| 법제도형 (개인정보·ISMS-P) | 핵심 원칙 1줄 | 기술·관리·물리 통제 분리 서술 |

함정 정리:
- IDS와 IPS 혼동 — IDS는 탐지만(미러링), IPS는 인라인 차단. 배치 위치를 반드시 명시.
- 해시 vs 암호화 vs 인코딩 혼동 — 해시는 단방향(복호 불가), 암호화는 양방향, 인코딩은 보안 아님.
- 전자서명 = 개인키 서명/공개키 검증 (기밀성 암호화와 키 사용 방향 반대). 부인방지+무결성 제공, 기밀성 아님.
- 인증(Authentication) vs 인가(Authorization) 구분, 식별·인증·인가·책임추적 4A.
- "제로 트러스트 = VPN 제거"가 아니라 신뢰 모델 전환. 제품 아닌 전략임을 명시.
- AEAD(GCM)는 암호화+무결성 동시 — ECB 모드·CBC 패딩오라클 취약점 언급 시 가점.
- PQC는 양자내성이지 양자암호(QKD)가 아님. Kyber=KEM, Dilithium=서명 구분.
- SBOM은 취약점 자동 차단이 아니라 가시성 도구 — VEX와 함께 적용성 판단 필요.

## Ⅴ. 결론 및 회독 포인트

- 회독 우선순위: 제로 트러스트 → 대칭/비대칭·하이브리드 → PKI/전자서명 → IDS/IPS·SIEM/SOAR → 공급망/DevSecOps → 개인정보·PQC.
- 답안 공통 골격은 "자산-위협-취약점-통제-운영"으로 고정하고, 비교표 1개+위협대응표 1개+도식 1개를 반드시 포함한다.
- 모든 보안 답안 마무리는 제로 트러스트·공급망·PQC·AI보안 등 최신 흐름과 연결해 기술사적 통찰을 보여줄 것.
