## Ⅰ. 정의
> 데이터링크 계층에서 비트 스트림을 프레임 단위로 구분(프레이밍)하고, 데이터 내에 프레임 경계 플래그와 동일한 패턴이 나타나지 않도록 비트/바이트를 삽입(스터핑)하여 투명 전송을 보장하는 기법이다.

## Ⅱ. 구성요소 / 원리
- 플래그(Flag): 프레임 시작·끝을 표시하는 특수 패턴 01111110(0x7E)
- 비트 스터핑(Bit Stuffing): 데이터 중 연속된 1이 5개면 강제로 0을 1비트 삽입, 수신측은 제거
- 바이트 스터핑(Byte Stuffing): 플래그·이스케이프 문자 출현 시 이스케이프(DLE/0x7D) 삽입
- 프레임 경계 식별: 플래그 검출로 동기 확보, 길이 필드 방식과 병행 가능
- 투명성(Transparency) 보장: 임의의 비트 패턴도 데이터로 전송 가능

## Ⅲ. 흐름도 / 구조
```text
 송신: 데이터 ...111110... → [5개 연속1 뒤 0 삽입] → ...1111100...
 프레임: [Flag 01111110][ Header | 스터핑된 Data | FCS ][Flag]
 수신: 플래그 검출 → 본문에서 1×5 뒤 0 제거 → 원 데이터 복원
```

## Ⅳ. 핵심 특징
| 구분 | 내용 |
|:---|:---|
| 목적 | 프레임 경계를 명확히 하고 데이터-플래그 충돌 없는 투명 전송 보장 |
| 장점 | 임의 비트열 전송 가능, 플래그 기반 자기 동기로 프레임 정렬 용이 |
| 한계 | 스터핑 비트로 오버헤드 증가(가변), 비트 오류 시 경계 오인식 위험 |

## Ⅴ. 기술사적 적용
- HDLC·PPP·SDLC 등 동기식 데이터링크 프로토콜의 핵심 프레이밍 메커니즘
- PPP는 바이트 스터핑(0x7D 이스케이프)으로 비동기 회선 투명성 확보
- 길이 필드·플래그·문자 카운트 방식과 비교해 프레이밍 설계 시 트레이드오프 고려
