## Ⅰ. 정의
> 일정 속도로 생성되는 토큰을 버킷에 축적하고, 패킷 전송 시 토큰을 소비하도록 하여 평균 전송률을 제어하면서 버스트(Burst)를 허용하는 트래픽 셰이핑·폴리싱 알고리즘이다.

## Ⅱ. 구성요소 / 원리
- 토큰 생성률(r): 초당 버킷에 채워지는 토큰 수 = 평균 허용 전송률
- 버킷 크기(b): 최대 누적 토큰 수 = 허용 가능한 최대 버스트 크기
- 토큰 소비: 패킷 전송 시 크기만큼 토큰 차감, 부족 시 대기/폐기
- 버스트 허용: 토큰이 쌓여 있으면 순간적으로 r 초과 전송 가능
- 셰이핑(지연 후 송출) vs 폴리싱(초과분 폐기/마킹)

## Ⅲ. 흐름도 / 구조
```text
 토큰생성(rate r) --> [ 버킷(용량 b) ] (가득차면 토큰버림)
                          |
패킷 도착 -> 토큰 충분? --YES--> 전송(토큰 차감)
                          |
                         NO --> 대기(셰이핑)/폐기(폴리싱)
```

## Ⅳ. 핵심 특징
| 구분 | 내용 |
|:---|:---|
| 목적 | 평균률 제어 + 버스트 허용으로 유연한 트래픽 규제 |
| 장점 | 버스트 수용, 평균/최대율 동시 제어, 구현 간단 |
| 한계 | 파라미터(r,b) 튜닝 필요, 과대 버킷 시 혼잡 유발 가능 |

## Ⅴ. 기술사적 적용
- Leaky Bucket과 비교: Leaky는 일정률 누출(버스트 억제), Token은 버스트 허용
- DiffServ srTCM/trTCM에서 토큰버킷으로 트래픽 색상(녹/황/적) 마킹
- API Rate Limiting, 대역폭 정책(폴리싱)에 광범위 활용
