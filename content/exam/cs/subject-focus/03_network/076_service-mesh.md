## Ⅰ. 정의
> 마이크로서비스 간 통신을 애플리케이션 코드와 분리된 인프라 계층(사이드카 프록시)에서 처리하여 트래픽 관리·보안·관측성을 일괄 제공하는 아키텍처이다.

## Ⅱ. 구성요소 / 원리
- 사이드카(Sidecar): 각 서비스 옆에 배치된 프록시(Envoy)가 통신 가로채기
- 데이터 평면(Data Plane): 사이드카 집합으로 실제 트래픽 처리
- 컨트롤 평면(Control Plane): 정책·설정을 사이드카에 배포·관리
- mTLS(mutual TLS): 서비스 간 상호 인증·암호화
- 트래픽 관리·관측성: 카나리·재시도·서킷브레이커·분산추적

## Ⅲ. 흐름도 / 구조
```text
  [Control Plane] --정책배포-->
  ┌Svc A┐        ┌Svc B┐
  │ +Sidecar│<-mTLS->│Sidecar+ │
  └────────┘        └────────┘
   데이터평면(Envoy 프록시 간 통신)
```

## Ⅳ. 핵심 특징
| 구분 | 내용 |
|:---|:---|
| 목적 | 서비스 간 통신의 보안·제어·관측 일원화 |
| 장점 | 코드 비침투, mTLS·트래픽정책·추적 표준 제공 |
| 한계 | 사이드카 자원·지연 오버헤드, 운영 복잡성 |

## Ⅴ. 기술사적 적용
- Istio·Linkerd 등으로 쿠버네티스 MSA에 적용
- API 게이트웨이(남북)와 메시(동서) 트래픽 역할 분담
- 사이드카리스(Ambient Mesh)로 오버헤드 절감 진화
