## Ⅰ. 정의
> 웹 클라이언트와 서버 간 하이퍼텍스트 자원을 요청·응답 방식으로 전송하는 응용 계층 프로토콜로, 버전 진화를 통해 지연과 다중화 성능을 개선해왔다.

## Ⅱ. 구성요소 / 원리
- HTTP/1.1: Keep-alive(연결 재사용), 파이프라이닝, 텍스트 기반, HOL 블로킹 존재
- HTTP/2: 바이너리 프레이밍, 멀티플렉싱, HPACK(헤더 압축), 서버 푸시
- HTTP/3: QUIC(UDP) 기반으로 TCP HOL 블로킹 완전 해소
- 요청/응답 메시지: 메서드·헤더·바디 구조
- 무상태(Stateless): 쿠키·세션으로 상태 보완

## Ⅲ. 흐름도 / 구조
```text
 1.1 : TCP 단일연결, 텍스트, HOL 블로킹
 2   : TCP+멀티플렉싱+HPACK+서버푸시
 3   : QUIC(UDP)+멀티플렉싱, HOL 완전해소
        └ TLS1.3 내장
```

## Ⅳ. 핵심 특징
| 구분 | 내용 |
|:---|:---|
| 목적 | 웹 자원 전송 표준화 및 지연·다중화 최적화 |
| 장점 | 2의 멀티플렉싱·헤더압축, 3의 전송 HOL 해소 |
| 한계 | 1.1 HOL 블로킹, 2는 TCP 레벨 HOL 잔존 |

## Ⅴ. 기술사적 적용
- HTTP/2는 도메인 샤딩 등 1.1 우회기법 불필요화
- HTTP/3 도입으로 모바일·고지연망 체감 성능 향상
- REST·GraphQL API 전송 기반으로 모든 웹 아키텍처에 내재
