## Ⅰ. 정의
> ARP(Address Resolution Protocol)는 동일 네트워크에서 IP 주소를 MAC(Media Access Control) 주소로 변환하는 프로토콜이며, RARP는 그 반대, GARP는 자신의 매핑을 능동 통지하는 변형이다.

## Ⅱ. 구성요소 / 원리
- ARP Request: 대상 IP에 대한 MAC을 브로드캐스트로 질의(FF:FF:FF:FF:FF:FF)
- ARP Reply: 해당 IP 보유 호스트가 유니캐스트로 MAC 응답
- ARP Cache: 변환 결과를 일정 시간 캐싱하여 재질의 감소
- RARP(Reverse ARP): MAC→IP 조회(디스크리스 단말, 현재는 DHCP로 대체)
- GARP(Gratuitous ARP): 자기 IP를 스스로 질의/통지 → 중복 IP 탐지, 캐시 갱신, 페일오버(VRRP)

## Ⅲ. 흐름도 / 구조
```text
[A: B의 MAC?] ─ ARP Request(브로드캐스트) ─→ 전체 세그먼트
              ←─ ARP Reply(유니캐스트, B의 MAC) ─ [B]
  A의 ARP Cache: B-IP ↔ B-MAC 저장
GARP: [A] "내 IP=내 MAC" 브로드캐스트 → 중복검사/갱신
RARP: [디스크리스] MAC→IP 요청
```

## Ⅳ. 핵심 특징
| 구분 | 내용 |
|:---|:---|
| 목적 | L3 IP 주소와 L2 MAC 주소 간 매핑으로 실제 프레임 전달 가능화 |
| 장점 | 자동 주소 해석, 캐시로 효율화, GARP로 가용성·중복검출 지원 |
| 한계 | 평문 브로드캐스트 기반으로 ARP Spoofing/Poisoning 공격에 취약 |

## Ⅴ. 기술사적 적용
- ARP Spoofing 방어: DAI(Dynamic ARP Inspection), 정적 ARP 바인딩 적용
- VRRP/HSRP 이중화에서 GARP로 가상 IP의 MAC 갱신(페일오버 전환)
- IPv6에서는 ARP 대신 NDP(Neighbor Discovery Protocol)가 역할 수행
