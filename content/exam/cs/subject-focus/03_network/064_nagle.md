## Ⅰ. 정의
> 작은 크기의 데이터를 즉시 보내지 않고 모아서 전송함으로써, 헤더 대비 페이로드가 작은 소형 패킷(tinygram) 남발을 줄여 네트워크 효율을 높이는 TCP 송신 최적화 알고리즘이다.

## Ⅱ. 구성요소 / 원리
- 핵심 규칙: 미확인(ACK 대기) 데이터가 있으면 작은 데이터는 버퍼에 보류
- 전송 조건: MSS만큼 모이거나, 이전 전송분 ACK 수신 시 즉시 송출
- 작은패킷 묶음: 다수의 소형 쓰기를 하나의 세그먼트로 통합
- delayed ACK 상호작용: 수신측 지연 ACK와 겹치면 양측 대기로 지연 유발
- TCP_NODELAY: 소켓 옵션으로 Nagle 비활성화(즉시 전송)

## Ⅲ. 흐름도 / 구조
```text
소량 데이터 쓰기 -> 미확인 데이터 있음?
        |                  |
       NO -> 즉시 전송    YES -> 버퍼에 누적
                            |
        MSS 도달 또는 ACK 수신 -> 묶어서 전송
   (수신 delayed ACK와 겹치면 지연 증가)
```

## Ⅳ. 핵심 특징
| 구분 | 내용 |
|:---|:---|
| 목적 | 소형 패킷 남발 억제로 대역폭·혼잡 효율 개선 |
| 장점 | 헤더 오버헤드 감소, 광역망 효율 향상 |
| 한계 | delayed ACK와 결합 시 지연 발생, 실시간/대화형 부적합 |

## Ⅴ. 기술사적 적용
- 저지연 요구 응용(실시간 게임·금융·SSH 대화형)은 TCP_NODELAY로 비활성화
- delayed ACK(약 40~200ms)와의 교착 회피 위해 쓰기 패턴 일괄화 설계
- Cork(TCP_CORK)와 비교: 명시적 버퍼링으로 풀사이즈 패킷 전송 제어
