## Ⅰ. 정의
> 송신 속도가 수신 처리 속도를 초과해 수신버퍼가 넘치지 않도록 전송량을 조절하는 종단 간 제어 기법.

## Ⅱ. 구성요소 / 원리
- 정지대기(Stop-and-Wait): 한 프레임 전송 후 ACK 수신까지 대기
- 슬라이딩 윈도우(Sliding Window): 윈도우 크기만큼 연속 전송
- 수신 윈도우 광고(Advertised Window): 수신 가용 버퍼량 통지
- 버퍼링·역압(Back-pressure): 처리 한계 시 송신 억제
- ARQ(Automatic Repeat reQuest)와 결합해 오류·흐름 동시 제어

## Ⅲ. 흐름도 / 구조
```text
송신자 ───데이터───▶ 수신자(버퍼)
       ◀──Win=N────  남은버퍼 N 광고
 if N=0 → 송신 중단(Zero Window)
       ◀──Win>0────  버퍼 비면 재개
혼잡제어: 네트워크 내부 과부하 별도 제어
```

## Ⅳ. 핵심 특징
| 구분 | 내용 |
|:---|:---|
| 목적 | 수신단 버퍼 오버플로 방지, 종단 간 속도 정합 |
| 장점 | 데이터 손실 예방, 자원 효율적 사용 |
| 한계 | 윈도우 통지 지연 시 처리율 저하, 혼잡은 별도 대응 필요 |

## Ⅴ. 기술사적 적용
- 흐름제어=수신단 보호 vs 혼잡제어=네트워크 보호로 명확히 구분
- TCP는 rwnd(수신윈도우)와 cwnd(혼잡윈도우) 중 최솟값으로 전송량 결정
- 데이터링크(HDLC)·전송(TCP) 두 계층 모두에서 적용
