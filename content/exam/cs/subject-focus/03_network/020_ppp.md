## Ⅰ. 정의
> 두 노드 간 점대점 직렬 링크에서 멀티프로토콜 데이터그램을 캡슐화·전송하는 데이터링크 계층 표준 프로토콜.

## Ⅱ. 구성요소 / 원리
- LCP(Link Control Protocol): 링크 설정·옵션 협상·유지·종료
- NCP(Network Control Protocol): IPCP 등 상위 네트워크 계층 협상
- 인증(Authentication): PAP/CHAP로 접속 신원 확인
- 프레임 구조: Flag|Address|Control|Protocol|Payload|FCS
- HDLC 프레이밍 기반, 멀티링크·압축·오류검출 지원

## Ⅲ. 흐름도 / 구조
```text
[Dead]→[LCP 설정]→[인증]→[NCP/IPCP]→[Open 데이터]→[종료]
 PAP: 평문 ID/PW 1회 전송(취약)
 CHAP: 챌린지-응답 해시(3-way, 주기검증)
 +----+----+----+--------+---------+----+
 |Flag|Addr|Ctrl|Protocol| Payload |FCS |
 +----+----+----+--------+---------+----+
```

## Ⅳ. 핵심 특징
| 구분 | 내용 |
|:---|:---|
| 목적 | 점대점 링크에서 멀티프로토콜 캡슐화·인증 제공 |
| 장점 | 인증·압축·오류검출 내장, IP 동적 할당 지원 |
| 한계 | 점대점 전용으로 다중접속 불가, PAP 보안 취약 |

## Ⅴ. 기술사적 적용
- PAP(Password Authentication Protocol) 평문 vs CHAP(Challenge-Handshake Authentication Protocol) 해시 비교
- PPPoE(PPP over Ethernet)로 xDSL·FTTH 가입자 인증에 적용
- VPN 터널링(L2TP, PPTP)의 캡슐화 기반으로 활용
