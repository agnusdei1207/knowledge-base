## Ⅰ. 정의
> IP(Internet Protocol) 패킷이 네트워크에서 생존할 수 있는 한계를 나타내는 헤더 필드로, 라우터를 거칠 때마다 1씩 감소하여 0이 되면 폐기되어 무한 루프를 방지하는 메커니즘이다.

## Ⅱ. 구성요소 / 원리
- IPv4 헤더 내 8비트 필드(0~255), 송신 호스트가 초기값 설정(예: Linux 64, Windows 128)
- 라우터(L3 홉)를 통과할 때마다 TTL 값 1 감소(Decrement)
- TTL이 0이 되면 패킷 폐기 후 ICMP(Internet Control Message Protocol) Time Exceeded 메시지를 송신지로 회신
- 라우팅 루프·반복 순환 패킷으로 인한 네트워크 자원 고갈 방지
- IPv6에서는 Hop Limit 필드가 동일 역할 수행

## Ⅲ. 흐름도 / 구조
```text
[Src TTL=64] → R1(TTL=63) → R2(TTL=62) → ... 
   루프 발생 시 TTL 계속 감소
   → Rn(TTL=0) → 패킷 폐기(Drop)
   → ICMP Time Exceeded → [Src]
   traceroute: TTL 1,2,3..로 각 홉 응답 수집
```

## Ⅳ. 핵심 특징
| 구분 | 내용 |
|:---|:---|
| 목적 | 라우팅 루프 방지 및 좀비 패킷의 네트워크 무한 순환 차단 |
| 장점 | 단순한 카운터로 망 안정성 확보, traceroute 등 진단 도구 기반 제공 |
| 한계 | 홉 수 기준이라 실제 지연(시간)과 무관, 비정상 초기값 시 도달 실패 가능 |

## Ⅴ. 기술사적 적용
- traceroute/tracert: TTL을 1부터 증가시켜 Time Exceeded 응답으로 경로상 각 라우터 식별
- DNS·CDN의 캐시 TTL과는 개념이 다름(시간 기반 캐시 유효기간)에 유의해 설계
- 방화벽·IDS에서 TTL 값 분석으로 OS Fingerprinting 및 우회 탐지에 활용
