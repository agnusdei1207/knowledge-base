## Ⅰ. 1교시 핵심 답안

> SDN은 네트워크 장비 내부에 결합되어 있던 제어평면과 데이터평면을 분리하여 중앙 소프트웨어가 정책과 경로를 프로그래밍 방식으로 제어하는 구조이다.

- **핵심 개념**: `Control Plane / Data Plane 분리`
- **구성 요소**: SDN Controller, Southbound API, Northbound API
- **목적**: 자동화, 정책 일관성, 신속한 변경
- **출제 포인트**: 전통 네트워크와의 구조 차이

## Ⅱ. 구조 및 동작 원리

```text
Application
   |
Northbound API
   |
SDN Controller
   |
Southbound API (e.g. OpenFlow)
   |
Switch / Router (Data Plane)
```

- **Controller**: 전역 정책과 경로 로직 관리
- **Data Plane**: 컨트롤러가 배포한 포워딩 규칙 수행
- **Programmability**: 네트워크 기능을 소프트웨어 정책으로 정의
- **Centralized View**: 운영 가시성과 변경 일관성 확보

## Ⅲ. 비교표

| 구분 | 전통 네트워크 | SDN |
|:---|:---|:---|
| 제어 구조 | 장비별 분산 | 논리적 중앙 제어 |
| 변경 방식 | 장비별 수작업 | 정책 기반 자동 배포 |
| 가시성 | 부분적 | 전역적 |
| 확장 방향 | 벤더 종속 경향 | API 기반 유연성 |

## Ⅳ. 기술사 답안 포인트

- **장점**: 자동화, 민첩성, 멀티테넌트 정책 적용
- **한계**: 컨트롤러 가용성, 보안, 전통망 공존 문제
- **연계 주제**: NFV, IBN, Network Slicing, OpenFlow, P4
- **비교 논점**: SDN은 제어 구조, NFV는 기능 가상화라는 점 구분

## Ⅴ. 결론

SDN의 핵심은 장비를 소프트웨어로 바꾼 것이 아니라 `네트워크 제어의 위치와 방식`을 바꾼 데 있다.  
SDN의 본질은 `평면 분리 -> 중앙 제어 -> 자동화 효과`의 흐름에 있다. 제어 평면을 컨트롤러로 집중하면 정책 기반 경로 제어와 네트워크 자동화가 가능하지만, 컨트롤러 가용성과 보안 통제가 핵심 운영 조건이 된다.
