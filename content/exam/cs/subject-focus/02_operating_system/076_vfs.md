## Ⅰ. 정의
> VFS(Virtual File System)는 다양한 파일시스템을 단일한 공통 인터페이스로 추상화하는 커널 계층으로, 응용이 파일시스템 종류와 무관하게 동일한 시스템 콜로 접근하게 한다.

## Ⅱ. 구성요소 / 원리
- 공통 객체 모델: superblock(볼륨), inode(파일), dentry(디렉터리 엔트리), file(열린 파일)
- 추상 연산 인터페이스: open/read/write/close 등을 함수 포인터 테이블로 위임
- 실제 파일시스템(ext4·XFS·NFS 등)이 인터페이스를 각자 구현
- 마운트(Mount): 서로 다른 파일시스템을 단일 디렉터리 트리에 결합
- 디스크·네트워크·가상 파일시스템(/proc) 모두 동일 추상화

## Ⅲ. 흐름도 / 구조
```text
   응용 프로세스 (open/read/write)
            ↓ 시스템 콜
   ┌──────── VFS 계층 ────────┐
   │ superblock/inode/dentry/file │
   └───┬────────┬────────┬─────┘
     ext4      XFS      NFS  (실제 FS 구현)
       ↓        ↓        ↓
     블록장치  블록장치  네트워크
```

## Ⅳ. 핵심 특징
| 구분 | 내용 |
|:---|:---|
| 목적 | 이기종 파일시스템을 통일된 인터페이스로 투명하게 제공 |
| 장점 | 응용 이식성·확장성, 새 파일시스템 플러그인식 추가 용이 |
| 한계 | 추상화 계층 오버헤드, 공통 모델로 인한 고유 기능 제약 |

비교

| 구분 | VFS 없음 | VFS 있음 |
|:---|:---|:---|
| 응용 코드 | FS별 분기 | 단일 인터페이스 |
| 확장성 | 낮음 | 높음 |

## Ⅴ. 기술사적 적용
- 리눅스가 ext4·Btrfs·NFS·FUSE 등을 동시 지원하는 기반
- FUSE로 사용자공간 파일시스템 구현, 컨테이너 오버레이FS 활용
- 네트워크·클라우드 스토리지를 로컬 파일처럼 마운트하는 투명성 제공
