## Ⅰ. 정의
> 프로세스에 특정 이벤트 발생을 비동기적으로 통지하는 소프트웨어 인터럽트로, 커널이나 다른 프로세스가 대상 프로세스의 정상 흐름을 중단시켜 처리하게 하는 IPC(프로세스 간 통신) 기법.

## Ⅱ. 구성요소 / 원리
- 시그널 번호: SIGKILL(강제종료, 무시·차단 불가), SIGTERM(정상종료 요청)
- SIGINT(Ctrl+C 인터럽트), SIGSEGV(메모리 위반), SIGCHLD(자식 상태변화)
- 처리 방식: 기본 동작(default)·무시(ignore)·핸들러(사용자 정의)
- 시그널 핸들러: 발생 시 호출되는 콜백 함수(signal/sigaction 등록)
- 차단(blocking)·대기(pending): 마스크로 일시 보류 가능

## Ⅲ. 흐름도 / 구조
```text
 이벤트(커널/kill) ──생성──> [Pending Signal]
                               |
        마스크 차단? ──예──> 보류
              아니오
                               v
        프로세스 정상흐름 중단 ──> Signal Handler 실행
                               |
        복귀 / 종료 / 무시(기본동작)
```

## Ⅳ. 핵심 특징
| 구분 | 내용 |
|:---|:---|
| 목적 | 비동기 이벤트의 경량 비동기 통지·제어 |
| 장점 | 즉각적 비동기 알림, 프로세스 제어(종료·중단) 간편 |
| 한계 | 정보량 적음(번호만), 재진입·경쟁 위험, SIGKILL 처리불가 |

## Ⅴ. 기술사적 적용
- SIGTERM(우아한 종료) → 미응답 시 SIGKILL(강제) 단계적 종료 정책
- SIGCHLD 핸들러로 좀비 프로세스 회수(wait) 자동화
- 핸들러 내 비동기-시그널-안전(async-signal-safe) 함수만 사용 권고
