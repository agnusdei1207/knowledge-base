## Ⅰ. 정의
> 유닉스 계열 파일시스템에서 파일·디렉터리에 대한 읽기(r)·쓰기(w)·실행(x) 권한을 소유자(owner)·그룹(group)·기타(other) 단위로 부여하는 접근통제 메커니즘이다.

## Ⅱ. 구성요소 / 원리
- 권한 비트: 읽기(r=4)·쓰기(w=2)·실행(x=1), 디렉터리의 x는 진입 권한
- 대상 분류: owner(소유자)·group(그룹)·other(기타), 각 3비트 = 총 9비트
- 8진수 표기: 각 그룹 3비트를 0~7로 표현(예: rwxr-xr-- = 754)
- 특수 권한: SetUID(4000)·SetGID(2000)·Sticky Bit(1000)
- chmod·chown·umask로 권한·소유·기본값 관리

## Ⅲ. 흐름도 / 구조
```text
  - rwx r-x r--
  │  │   │   └ other (r--=4)
  │  │   └──── group (r-x=5)
  │  └──────── owner (rwx=7)  → 754
  └─ 파일유형(-,d,l …)
 접근판정: 소유자→그룹→기타 순으로 매칭 비트 검사
 SetUID: 실행 시 소유자 권한으로 동작
```

## Ⅳ. 핵심 특징
| 구분 | 내용 |
|:---|:---|
| 목적 | 사용자/그룹 단위 임의접근통제(DAC)로 자원 보호 |
| 장점 | 단순·직관적, 8진수로 빠른 설정, 특수권한으로 유연성 |
| 한계 | 3주체로 세분화 부족, 복잡 정책은 ACL/SELinux 필요 |

권한 값 예시

| 8진수 | 표기 | 의미 |
|:---|:---|:---|
| 755 | rwxr-xr-x | 소유자 전체, 그외 읽기·실행 |
| 644 | rw-r--r-- | 소유자 R/W, 그외 읽기 |
| 600 | rw------- | 소유자만 R/W |

## Ⅴ. 기술사적 적용
- 세밀한 제어를 위한 POSIX ACL(Access Control List) 확장 적용
- SetUID 오남용은 권한상승 취약점, 최소권한 원칙으로 관리
- 강제접근통제(MAC)인 SELinux·AppArmor와 결합한 다층 보안
