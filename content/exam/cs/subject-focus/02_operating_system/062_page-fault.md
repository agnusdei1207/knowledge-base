## Ⅰ. 정의
> 페이지부재(Page Fault)는 CPU가 참조한 페이지가 물리메모리에 존재하지 않을 때 발생하는 트랩(Trap)으로, 운영체제가 해당 페이지를 백업저장소에서 적재하는 사건이다.

## Ⅱ. 구성요소 / 원리
- 유효/무효 비트가 무효(Invalid)일 때 부재 트랩 발생
- 부재 처리 루틴: 빈 프레임 확보 → 디스크 입출력 → 페이지테이블 갱신 → 명령 재시작
- 빈 프레임이 없으면 페이지교체(Page Replacement) 알고리즘으로 희생 페이지 선정
- 유효접근시간(EAT)은 부재율(p)에 매우 민감(디스크 접근이 지배적)

## Ⅲ. 흐름도 / 구조
```text
참조 → [유효비트?] ─무효─▶ Trap(OS)
   유효│                    │
   메모리접근          빈 프레임 확보(없으면 교체)
                            ▼
                    디스크→프레임 적재
                            ▼
                    페이지테이블 갱신(유효)
                            ▼
                       명령어 재시작
```

## Ⅳ. 핵심 특징
| 구분 | 내용 |
|:---|:---|
| 목적 | 미적재 페이지를 적재하여 요구페이징 완성 |
| 장점 | 필요 페이지만 동적 적재, 가상메모리 실현 |
| 한계 | 디스크 입출력으로 처리 지연 큼, 빈번 시 스래싱 |

## Ⅴ. 기술사적 적용
- EAT = (1-p)×메모리접근 + p×페이지부재처리시간으로 성능 정량화
- 부재율 관리(워킹셋·PFF), 교체 알고리즘 선택이 시스템 성능 핵심 요인
