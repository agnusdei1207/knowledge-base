## Ⅰ. 정의
> 논리 주소공간을 고정 크기 페이지로, 물리 주소공간을 동일 크기 프레임으로 분할하여 매핑하는 비연속 할당 기법으로, TLB(Translation Lookaside Buffer, 변환참조버퍼)로 주소변환을 가속한다.

## Ⅱ. 구성요소 / 원리
- 논리주소 = 페이지 번호(p) + 오프셋(d), 페이지테이블이 p→프레임 번호(f)로 변환
- 페이지테이블(Page Table): 프로세스별 p→f 매핑 정보 저장
- 다단계 페이지테이블(Multi-level): 테이블을 계층화해 미사용 영역 미할당으로 크기 절감
- TLB: 최근 변환을 캐싱하는 연관기억장치(Associative Memory), 적중 시 메모리 1회 접근 생략
- EAT(Effective Access Time, 유효접근시간): TLB 적중률에 따라 평균 접근시간 결정

## Ⅲ. 흐름도 / 구조
```text
논리주소(p, d) → TLB 조회
        │
   TLB Hit? ──Yes→ 프레임(f) 즉시 획득 → 물리주소(f, d) 접근
        └──No(Miss)→ 페이지테이블 접근 → f 획득 → TLB 갱신 → 물리주소 접근
   EAT = (적중률 × (TLB+메모리)) + (실패율 × (TLB+메모리×2))
```

## Ⅳ. 핵심 특징
| 구분 | 내용 |
|:---|:---|
| 목적 | 비연속 할당으로 외부단편화 제거, TLB로 주소변환 속도 향상 |
| 장점 | 외부단편화 없음, 다단계 테이블로 메모리 절감, TLB 적중 시 EAT 대폭 단축 |
| 한계 | 내부단편화(Internal Fragmentation) 발생, TLB 미스·다단계 시 다중 메모리 접근 |

## Ⅴ. 기술사적 적용
- 다단계 페이지테이블은 페이지 번호를 계층 분할하여 거대한 테이블 크기를 절감(64비트 환경 필수)
- TLB 적중률을 높여 EAT를 단축하는 것이 핵심이며, 문맥교환 시 TLB 플러시 비용(ASID로 완화)을 고려
- 페이지 크기는 내부단편화(작을수록↓)와 페이지테이블 크기·TLB 적중률(클수록↑) 간 트레이드오프로 결정
