## Ⅰ. 정의
> i-node(Index Node)는 유닉스 계열 파일시스템에서 파일의 메타데이터와 데이터 블록 위치 정보를 담는 자료구조로, 파일 하나당 하나의 i-node가 대응된다.

## Ⅱ. 구성요소 / 원리
- 메타데이터: 파일 유형·권한·소유자(UID/GID)·크기·타임스탬프·링크 수
- 직접 블록 포인터(Direct): 데이터 블록을 직접 가리킴(소형 파일에 효율적)
- 단일/이중/삼중 간접 블록(Indirect): 포인터 블록을 거쳐 대용량 파일 주소 지정
- i-node 번호로 파일 식별, 파일명은 디렉터리 엔트리가 i-node에 매핑
- i-node에는 파일명·데이터 자체는 저장하지 않음

## Ⅲ. 흐름도 / 구조
```text
디렉터리(파일명 → i-node번호)
        ↓
   ┌── i-node ──────────────┐
   │ 메타데이터(권한·크기·시간) │
   │ 직접포인터 → [데이터블록]   │
   │ 단일간접 → [포인터블록]→블록 │
   │ 이중간접 → [포인터]→[포인터]→블록 │
   │ 삼중간접 → … (대용량)       │
   └────────────────────────┘
```

## Ⅳ. 핵심 특징
| 구분 | 내용 |
|:---|:---|
| 목적 | 파일 메타데이터·블록 위치를 효율적으로 색인·관리 |
| 장점 | 다단계 간접으로 소형~대용량 파일 모두 효율적 지원, 하드링크 가능 |
| 한계 | i-node 수 고정으로 소형파일 다량 시 고갈, 파일명 미포함 |

비교

| 항목 | 직접 블록 | 간접 블록 |
|:---|:---|:---|
| 접근속도 | 빠름 | 추가 참조 필요 |
| 대상 | 소형 파일 | 대용량 파일 |

## Ⅴ. 기술사적 적용
- ext2/3/4, XFS 등 유닉스 계열 파일시스템 핵심 구조
- 하드링크(같은 i-node 공유) vs 심볼릭링크(경로 참조) 구분 근거
- i-node 고갈 문제 대응 위한 동적 할당·차세대 FS(Btrfs 익스텐트) 설계
