## Ⅰ. 정의
> CPU의 개입 없이 입출력장치(I/O Device)와 주기억장치(Memory) 간에 데이터를 직접 전송하는 기법으로, CPU 부하를 줄이고 I/O 처리량을 향상시킨다.

## Ⅱ. 구성요소 / 원리
- DMA 컨트롤러(DMAC): 전송을 주관하는 전용 하드웨어, 주소·카운트 레지스터 보유
- 사이클 스틸링(Cycle Stealing): 메모리 버스를 잠시 빌려 한 워드씩 전송, CPU와 버스 공유
- 버스트 모드(Burst Mode): 블록 단위로 버스를 점유해 일괄 전송
- 인터럽트(Interrupt): 전송 완료 시 CPU에 통지
- 동작: CPU가 전송 파라미터 설정 → DMAC가 자율 전송 → 완료 인터럽트

## Ⅲ. 흐름도 / 구조
```text
1) CPU → DMAC: 시작주소·전송량·방향 설정
2) DMAC ⇄ I/O장치 ⇄ Memory  (CPU 미개입)
        └ 사이클 스틸링으로 버스 점유 ┘
3) 전송 완료 → DMAC → CPU 인터럽트
  CPU는 그동안 다른 연산 수행(병행성↑)
```

## Ⅳ. 핵심 특징
| 구분 | 내용 |
|:---|:---|
| 목적 | CPU 개입 없는 대량 I/O로 CPU 자원 절약·처리량 향상 |
| 장점 | CPU와 I/O 병행 처리, 인터럽트 빈도 감소(블록 전송) |
| 한계 | 버스 경합으로 CPU 메모리 접근 지연, 추가 하드웨어 필요 |

비교

| 방식 | CPU 개입 | 효율 |
|:---|:---|:---|
| 프로그램 I/O | 전 과정 | 낮음 |
| 인터럽트 I/O | 워드 단위 | 중간 |
| DMA | 시작·완료만 | 높음 |

## Ⅴ. 기술사적 적용
- 디스크·네트워크·GPU 등 고속 대량 전송 장치의 표준 I/O 방식
- 캐시 일관성(Cache Coherence) 유지를 위한 스누핑·플러시 고려 필요
- I/O 채널·IOMMU와 결합해 가상화 환경에서 안전한 직접 전송 구현
