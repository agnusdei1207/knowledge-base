## Ⅰ. 정의
> 실행 중인 프로세스로부터 CPU(Central Processing Unit)를 강제 회수할 수 있는지 여부에 따른 스케줄링 분류로, 선점(Preemptive)은 강제 회수 가능, 비선점(Non-preemptive)은 자발적 반납까지 점유를 보장한다.

## Ⅱ. 구성요소 / 원리
- 선점: 더 높은 우선순위 도착·타이머 인터럽트 발생 시 실행 프로세스를 강제 중단 후 문맥교환
- 비선점: 프로세스가 종료하거나 입출력(I/O) 대기로 전환할 때까지 CPU 보장
- 선점 트리거: 타이머 만료, 인터럽트, 더 짧은 잔여시간/높은 우선순위 도착
- 선점은 잦은 문맥교환 비용, 비선점은 응답성 저하 위험 수반
- 대표 사례: 선점(RR, SRTF, 선점형 우선순위), 비선점(FCFS, SJF, HRN)

## Ⅲ. 흐름도 / 구조
```text
[실행 중 P1] --타이머 만료/우선순위 높은 P2 도착--> 선점
       |                                          |
       v(비선점: 자발 반납까지 점유)               v
   [종료/I/O 전환]                          [P1 → Ready, P2 실행]
```

## Ⅳ. 핵심 특징
| 구분 | 내용 |
|:---|:---|
| 목적 | CPU 회수 정책으로 응답성과 공정성·처리량의 균형 확보 |
| 장점 | 선점=빠른 응답·실시간성, 비선점=문맥교환 적고 구현 단순 |
| 한계 | 선점=오버헤드·임계영역 보호 필요, 비선점=호위효과·응답 지연 |

## Ⅴ. 기술사적 적용
- 선점형은 시분할·실시간 시스템(RR, EDF)에, 비선점형은 배치 처리에 적합
- 선점 시 공유자원 일관성 위해 동기화(뮤텍스·세마포어) 병행 필요
- 리눅스 CFS는 선점형 기반으로 대화형·서버 부하 모두 대응
