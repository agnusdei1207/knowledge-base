## Ⅰ. 정의
> 커널 구조(Kernel Architecture)는 운영체제 핵심 기능(프로세스·메모리·파일·장치 관리)을 커널 공간과 사용자 공간에 어떻게 배치하는가에 따른 설계 방식으로, 성능과 모듈성·안정성의 트레이드오프를 결정한다.

## Ⅱ. 구성요소 / 원리
- **모놀리식 커널(Monolithic Kernel)**: 모든 OS 서비스를 단일 커널 공간에서 실행(Linux)
- **마이크로커널(Microkernel)**: 최소 기능(IPC·스케줄링)만 커널, 나머지는 사용자 공간 서버(Mach)
- **하이브리드 커널(Hybrid Kernel)**: 성능 핵심은 커널, 모듈성은 절충(Windows NT, macOS XNU)
- **IPC(Inter-Process Communication)**: 마이크로커널에서 서버 간 통신 핵심
- **모듈(LKM, Loadable Kernel Module)**: 모놀리식의 동적 확장으로 모듈성 보완

## Ⅲ. 흐름도 / 구조
```text
[모놀리식]              [마이크로커널]
 ┌──────────┐          ┌──────────┐ 사용자공간
 │ 응용     │          │응용 │FS │드라이버│ ← 서버
 ├──────────┤          ├──────────┤
 │ 커널(전체│          │ 커널(IPC·스케줄)│ ← 최소
 │ 서비스)  │          └──────────┘
 └──────────┘          (서버 간 IPC로 통신)
```

## Ⅳ. 핵심 특징
| 구분 | 내용 |
|:---|:---|
| 목적 | OS 서비스 배치를 통한 성능·안정성·확장성 균형 설계 |
| 장점 | 모놀리식=고성능, 마이크로커널=모듈성·내결함성·보안 |
| 한계 | 모놀리식=장애 전파·비대화, 마이크로커널=IPC 오버헤드 |

### 구조 비교표
| 구분 | 모놀리식 | 마이크로커널 | 하이브리드 |
|:---|:---|:---|:---|
| 성능 | 높음 | 낮음(IPC) | 중간 |
| 모듈성·안정성 | 낮음 | 높음 | 중간 |
| 예시 | Linux, Unix | Mach, QNX | Windows NT, XNU |

## Ⅴ. 기술사적 적용
- Linux는 모놀리식에 LKM을 더해 성능과 모듈성을 절충
- 마이크로커널의 격리성은 안전성 요구가 큰 임베디드·차량(QNX)에 적용
- 컨테이너·유니커널 등 경량 OS 트렌드와 커널 설계 선택의 연계
