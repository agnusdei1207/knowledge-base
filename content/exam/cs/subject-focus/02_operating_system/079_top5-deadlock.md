## Ⅰ. 정의
> 둘 이상의 프로세스가 서로 점유한 자원을 무한정 대기하여 어느 것도 진행하지 못하는 상태로, 4가지 필요조건이 동시에 성립할 때 발생한다.

## Ⅱ. 구성요소 / 원리
- 상호배제(Mutual Exclusion): 자원을 한 번에 한 프로세스만 사용
- 점유와 대기(Hold and Wait): 자원을 점유한 채 다른 자원을 추가 요청
- 비선점(No Preemption): 자원을 강제로 빼앗을 수 없음
- 순환대기(Circular Wait): 프로세스들이 환형으로 자원을 대기
- 처리: 예방(Prevention)·회피(Avoidance, 은행원 알고리즘)·탐지(Detection)·복구(Recovery)

## Ⅲ. 흐름도 / 구조
```text
P1 ──요청→ R2(P2 점유)        은행원 알고리즘(Banker's Algorithm):
 ↑                              요청 → [가용자원 시뮬레이션]
 │ 점유                              ↓
 R1 ←요청── P2                  안전순서(Safe Sequence) 존재? ──Yes→ 할당
   (순환대기 = 교착)                  └──No→ 대기(불안전상태 회피)
```

## Ⅳ. 핵심 특징
| 구분 | 내용 |
|:---|:---|
| 목적 | 예방=조건 원천 차단 / 회피=안전상태 유지 / 탐지·복구=발생 후 처리 |
| 장점 | 예방=교착 원천봉쇄, 회피=자원효율↑(은행원), 탐지=정상시 오버헤드 없음 |
| 한계 | 예방=자원이용률 저하, 회피=최대요구량 사전필요, 복구=프로세스 강제종료/롤백 비용 |

## Ⅴ. 기술사적 적용
- 회피 기법은 은행원 알고리즘으로 안전상태(Safe State)일 때만 자원을 할당하여 교착 차단
- 탐지는 자원할당그래프(RAG)를 단순화한 대기그래프(Wait-for Graph)의 사이클 유무로 판단
- 복구는 프로세스 종료(전체/부분) 또는 자원 선점(희생자 선정·롤백·기아 고려)으로 수행
