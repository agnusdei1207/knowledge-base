## Ⅰ. 정의
> 응용 프로세스가 입출력(I/O) 완료를 대기하고 통지받는 방식에 대한 모델로, 블로킹(Blocking)·논블로킹(Non-blocking)·비동기(Asynchronous)로 구분된다.

## Ⅱ. 구성요소 / 원리
- 블로킹(Blocking): I/O 완료까지 호출 스레드가 멈춰 대기
- 논블로킹(Non-blocking): 즉시 반환하고 준비 여부를 반복 확인(폴링)
- I/O 다중화(Multiplexing): select/poll/epoll로 다수 디스크립터를 한 스레드가 감시
- 비동기(Asynchronous): 커널이 I/O 전체를 수행 후 완료를 콜백/시그널로 통지
- 동기/비동기는 통지 주체, 블로킹/논블로킹은 대기 여부 기준으로 구분

## Ⅲ. 흐름도 / 구조
```text
Blocking    : 호출──[대기·블록]──완료 반환
Non-block   : 호출─즉시반환 → 폴링·폴링·…→ 완료
Multiplexing: select/epoll 감시 → 준비된 fd 처리
Async       : 호출─즉시반환 → (커널이 I/O 수행) → 완료 콜백/시그널
```

## Ⅳ. 핵심 특징
| 구분 | 내용 |
|:---|:---|
| 목적 | I/O 대기와 연산을 효율적으로 중첩해 동시성·처리량 확보 |
| 장점 | 비동기·다중화는 적은 스레드로 다수 연결 처리(C10K 대응) |
| 한계 | 논블로킹 폴링은 CPU 낭비, 비동기는 구현 복잡도·디버깅 난이도 |

모델 비교

| 모델 | 호출 반환 | 완료 통지 | 동시성 |
|:---|:---|:---|:---|
| 블로킹 | 완료 후 | 즉시 | 스레드당 1 |
| 논블로킹 | 즉시 | 폴링 | 폴링 부하 |
| 다중화 | 이벤트 시 | 이벤트 | 1스레드 다수 |
| 비동기 | 즉시 | 콜백/시그널 | 높음 |

## Ⅴ. 기술사적 적용
- 고성능 서버는 epoll·io_uring 기반 이벤트 구동(Event-driven)으로 설계
- Node.js·Nginx 등 단일 스레드 비동기 모델로 대규모 연결 처리
- 리액터(Reactor)·프로액터(Proactor) 패턴으로 I/O 모델 추상화
