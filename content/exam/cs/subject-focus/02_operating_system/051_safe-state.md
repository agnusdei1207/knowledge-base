## Ⅰ. 정의
> 모든 프로세스가 교착 없이 완료될 수 있는 자원 할당 순서(안전순열, Safe Sequence)가 하나 이상 존재하는 시스템 상태로, 교착 회피의 판단 기준.

## Ⅱ. 구성요소 / 원리
- 안전순열: <P1,P2,...,Pn> 순서로 모두 완료 가능한 실행 순서
- 자료구조: Available, Max, Allocation, Need(=Max-Allocation)
- 안전상태 ⊃ 교착없음, 불안전상태가 곧 교착은 아님(가능성)
- 은행원 알고리즘(Banker's): 요청 가수락 시 안전성 검사 후 할당
- 안전순열 존재 시에만 할당 승인

## Ⅲ. 흐름도 / 구조
```text
[상태]  안전 ── (안전순열 존재) ── 교착 없음 보장
   │
 불안전 ── 교착 가능성 영역(교착 포함)
[검사] Work=Available; 반복:
   Need_i ≤ Work 인 Pi 찾음 → Work += Allocation_i
   모두 처리되면 → 안전상태
```

## Ⅳ. 핵심 특징
| 구분 | 내용 |
|:---|:---|
| 목적 | 자원할당 전 안전성 검증으로 교착 회피 |
| 장점 | 교착 사전 차단, 자원 일부 활용 가능 |
| 한계 | Max 사전 선언 필요, O(m·n²) 검사 비용, 자원 저활용 |

## Ⅴ. 기술사적 적용
- 은행원 알고리즘 = 안전성 알고리즘 + 자원요청 알고리즘
- 불안전 ≠ 교착: 불안전은 교착 가능성일 뿐
- 동적 자원·미지의 Max 환경에선 적용 곤란 → 실무는 탐지·복구 선호
