## Ⅰ. 정의
> 원격 프로시저 호출(Remote Procedure Call). 다른 주소공간·원격 호스트의 함수를 마치 로컬 함수처럼 호출하도록 네트워크 통신을 숨기는 분산 통신 추상화.

## Ⅱ. 구성요소 / 원리
- 클라이언트 스텁(Stub): 호출을 가로채 인자를 마샬링
- 서버 스텁(스켈레톤): 수신 데이터를 언마샬링 후 실제 함수 호출
- 마샬링/언마샬링: 인자·결과를 전송 가능 형식으로 직렬화·복원
- 전송 계층: 요청·응답 메시지를 네트워크로 전달
- IDL(Interface Definition Language)로 인터페이스 정의·스텁 생성

## Ⅲ. 흐름도 / 구조
```text
Client ─call()─> [Client Stub] ─마샬링─> 네트워크
                                            |
네트워크 ─> [Server Stub] ─언마샬링─> 실제 procedure 실행
                                            |
결과 ─마샬링─> 네트워크 ─> Client Stub ─언마샬링─> 반환
```

## Ⅳ. 핵심 특징
| 구분 | 내용 |
|:---|:---|
| 목적 | 분산 환경 함수호출을 로컬 호출처럼 투명화 |
| 장점 | 통신 세부 은닉, 개발 생산성·분산 모듈화 향상 |
| 한계 | 부분실패·네트워크 지연, 호출 의미론(at-most/least-once) 복잡 |

## Ⅴ. 기술사적 적용
- gRPC·Thrift: IDL 기반 스텁 자동생성·다언어 마이크로서비스 연계
- 멱등성·타임아웃·재시도 설계로 부분실패 대응
- 비교: REST(자원중심) vs RPC(함수중심) 통신 모델 선택
