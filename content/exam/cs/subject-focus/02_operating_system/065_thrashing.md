## Ⅰ. 정의
> 스래싱(Thrashing)은 프로세스가 실제 실행보다 페이지 교체에 더 많은 시간을 소모하여 CPU 이용률이 급격히 떨어지는 과도한 페이징 상태이다.

## Ⅱ. 구성요소 / 원리
- 원인: 다중프로그래밍 정도(Degree) 과다 → 프로세스당 프레임 부족 → 빈번한 페이지부재
- 악순환: 부재 증가 → CPU 유휴 → 스케줄러가 Degree 증가 → 부재 가중
- 해결: 워킹셋(Working Set) 모델로 충분한 프레임 보장
- 해결: PFF(Page Fault Frequency)로 부재율 상·하한 관리하여 프레임 조정

## Ⅲ. 흐름도 / 구조
```text
CPU이용률
  │      ┌──최대점
  │     /        \  ← 스래싱(급락)
  │    /          \____
  └───┴──────────────────▶ 다중프로그래밍 정도
       임계점 초과 시 부재↑ → 디스크 대기 → CPU↓
```

## Ⅳ. 핵심 특징
| 구분 | 내용 |
|:---|:---|
| 목적 | 과도한 페이징으로 인한 성능 붕괴 현상 규명 |
| 장점 | 워킹셋·PFF로 사전 탐지·예방 가능 |
| 한계 | Degree 제어 실패 시 시스템 전체 처리량 급락 |

## Ⅴ. 기술사적 적용
- 워킹셋 모델: 지역성 기반 필요 프레임 확보로 스래싱 방지
- PFF 방식: 부재율 상한 초과 시 프레임 추가, 하한 미만 시 회수
