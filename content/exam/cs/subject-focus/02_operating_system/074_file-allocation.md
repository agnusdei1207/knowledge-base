## Ⅰ. 정의
> 파일의 데이터 블록을 디스크 상에 배치·관리하는 방식으로, 연속 할당·연결 할당·색인 할당으로 구분되며 접근속도와 공간효율을 좌우한다.

## Ⅱ. 구성요소 / 원리
- 연속 할당(Contiguous): 연속된 블록에 저장, 시작주소+길이로 관리
- 연결 할당(Linked): 각 블록이 다음 블록 포인터를 보유, 분산 저장
- 색인 할당(Indexed): 색인 블록(Index Block)에 모든 데이터 블록 주소를 모아 관리
- FAT(File Allocation Table): 연결 할당의 포인터를 별도 테이블로 모은 변형
- 외부단편화·임의접근 지원 여부가 핵심 차이

## Ⅲ. 흐름도 / 구조
```text
연속: [A1][A2][A3]      (인접, 시작+길이)
연결: [A1]→[A3]→[A7]    (포인터 체인)
색인: [색인블록]→A1,A2,A3 (주소 모음)
        ↓
   임의접근: 연속·색인 O / 연결 X
```

## Ⅳ. 핵심 특징
| 구분 | 내용 |
|:---|:---|
| 목적 | 디스크 블록을 효율적으로 배치해 접근성·공간효율 확보 |
| 장점 | 방식별로 임의접근·동적증가·단편화 대응 선택 가능 |
| 한계 | 연속=외부단편화, 연결=임의접근 불가, 색인=색인블록 오버헤드 |

방식 비교

| 방식 | 임의접근 | 단편화 | 비고 |
|:---|:---|:---|:---|
| 연속 | 우수 | 외부단편화 | 시작+길이 |
| 연결 | 불가 | 없음 | 포인터 체인 |
| 색인 | 우수 | 내부(색인) | 색인블록 사용 |

## Ⅴ. 기술사적 적용
- FAT는 연결 할당, 유닉스 i-node는 색인 할당 기반
- 대용량은 다단계 색인·익스텐트(Extent) 방식으로 오버헤드 절감
- 단편화 완화 위한 디스크 조각모음·할당 정책 최적화
