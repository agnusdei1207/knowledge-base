## Ⅰ. 정의
> 운영체제가 프로세스를 관리·식별하기 위해 프로세스별 모든 정보를 담아 커널 영역에 유지하는 자료구조(=Task Control Block).

## Ⅱ. 구성요소 / 원리
- 프로세스 식별자(PID, Process IDentifier) 및 부모 PID
- 프로세스 상태(New/Ready/Running/Waiting/Terminated)
- 프로그램 카운터(PC)와 CPU 레지스터 집합(문맥)
- 메모리 관리 정보(베이스/한계 레지스터, 페이지·세그먼트 테이블 포인터)
- 스케줄링 정보(우선순위, 큐 포인터), 계정·I/O 상태(열린 파일 목록)

## Ⅲ. 흐름도 / 구조
```text
+------- PCB -------+
| PID / Parent PID  |
| State             |
| PC / Registers    |  <-- 문맥교환 시 저장·복원
| Memory Info       |
| Scheduling Info   |
| I/O / File Table  |
+-------------------+
   |  ready queue / waiting queue 에 연결(linked list)
```

## Ⅳ. 핵심 특징
| 구분 | 내용 |
|:---|:---|
| 목적 | 프로세스 식별·상태·문맥의 일원화 관리 |
| 장점 | 문맥교환 시 정확한 상태 저장·복원 보장 |
| 한계 | 프로세스 수 증가 시 PCB 메모리·탐색 오버헤드 |

## Ⅴ. 기술사적 적용
- 문맥교환(Context Switch)은 곧 PCB의 레지스터·PC 저장·복원 과정
- 스케줄러는 PCB를 준비·대기 큐에 연결해 디스패치 수행
- PCB 변조는 권한상승 공격 표적 → 커널 메모리 보호 필요
