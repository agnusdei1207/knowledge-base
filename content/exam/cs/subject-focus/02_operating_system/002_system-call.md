## Ⅰ. 정의
> 시스템콜(System Call)은 사용자모드의 응용 프로그램이 커널모드의 운영체제 서비스를 요청하기 위한 표준 인터페이스로, 트랩(Trap)을 통해 안전하게 모드를 전환하여 특권 자원에 접근한다.

## Ⅱ. 구성요소 / 원리
- **API(Application Programming Interface)**: 응용이 호출하는 라이브러리 함수(예: POSIX `read()`)
- **시스템콜 번호(System Call Number)**: 커널이 서비스를 식별하는 인덱스, 시스템콜 테이블 참조
- **트랩(Trap)**: 소프트웨어 인터럽트로 사용자→커널 모드 전환
- **파라미터 전달**: 레지스터·스택·블록 방식으로 인자 전달
- **분류**: 프로세스 제어, 파일 관리, 장치 관리, 정보 유지, 통신

## Ⅲ. 흐름도 / 구조
```text
[User] 응용프로그램 → API 함수 호출 (read)
            │ 시스템콜 번호 설정 + trap 실행
            ▼  모드 전환 (User→Kernel)
[Kernel] 시스템콜 핸들러 → 시스템콜 테이블 조회
            │ 해당 커널 서비스 루틴 수행
            ▼  결과 반환 + 모드 복귀 (Kernel→User)
[User] 반환값 수신 후 계속 실행
```

## Ⅳ. 핵심 특징
| 구분 | 내용 |
|:---|:---|
| 목적 | 응용에 OS 서비스(자원 접근)를 안전하게 제공하는 게이트웨이 |
| 장점 | 직접 하드웨어 접근 차단, 이식성(API 추상화), 보호·검증 일원화 |
| 한계 | 모드 전환·인자 검증으로 함수 호출 대비 성능 오버헤드 |

## Ⅴ. 기술사적 적용
- 듀얼모드의 사용자→커널 전환을 실현하는 표준 진입점
- 라이브러리 호출(API)과 실제 시스템콜의 분리로 이식성·호환성 확보
- vDSO·시스템콜 일괄 처리(io_uring) 등으로 오버헤드 최소화 기법 발전
