## Ⅰ. 정의
> 컨테이너(Container)는 호스트 운영체제의 커널을 공유하면서 네임스페이스(Namespace)와 cgroups로 프로세스를 격리·자원 제한하는 OS 수준 경량 가상화 기술로, 애플리케이션과 의존성을 이미지로 패키징하여 실행한다.

## Ⅱ. 구성요소 / 원리
- **커널 공유(Shared Kernel)**: 게스트 OS 없이 호스트 커널을 공유해 경량화
- **네임스페이스(Namespace)**: PID·NET·MNT 등 프로세스 가시성 격리
- **cgroups(Control Groups)**: CPU·메모리·I/O 자원 제한·계량
- **이미지(Image)**: 실행에 필요한 파일시스템·의존성을 담은 읽기 전용 템플릿
- **레이어(Layer)**: 이미지를 계층(Union File System)으로 구성, 공유·재사용

## Ⅲ. 흐름도 / 구조
```text
[VM]                        [Container]
 게스트 OS × N               App + Bins/Libs × N
 ─────────────              ───────────────────
 Hypervisor                 Container Engine
 ─────────────              ───────────────────
 Host OS / HW               Host OS(커널 공유) / HW
 (무거움, 강한격리)         (경량, 빠른 기동)
```

## Ⅳ. 핵심 특징
| 구분 | 내용 |
|:---|:---|
| 목적 | 빠른 배포·확장이 가능한 경량·이식성 높은 격리 실행 환경 |
| 장점 | 빠른 기동·고밀도, 적은 자원, 이미지 기반 일관 배포(DevOps) |
| 한계 | 커널 공유로 VM 대비 격리·보안 약함, 호스트 커널 종속 |

### 컨테이너 vs 가상머신 비교표
| 구분 | 컨테이너 | 가상머신(VM) |
|:---|:---|:---|
| 격리 단위 | 프로세스(커널 공유) | 게스트 OS(커널 별도) |
| 기동 속도 | 초 단위 | 분 단위 |
| 자원 오버헤드 | 작음 | 큼 |
| 격리·보안 | 상대적 약함 | 강함 |

## Ⅴ. 기술사적 적용
- 마이크로서비스(MSA)·CI/CD의 표준 배포 단위로 활용
- Kubernetes로 다수 컨테이너 오케스트레이션(스케줄·자동확장)
- 보안 격리 강화를 위해 gVisor·Kata Container 등 샌드박스와 결합
