## Ⅰ. 정의
> 프로세스 내에서 CPU를 점유해 실행되는 최소 단위로, 코드·데이터·파일은 공유하고 스택·레지스터·PC는 독립적으로 갖는 경량 실행 흐름.

## Ⅱ. 구성요소 / 원리
- 공유 자원: 코드·전역 데이터·힙·열린 파일(프로세스 주소공간 공유)
- 독립 자원: 스택, 레지스터, 프로그램 카운터(PC), 스레드 ID
- 사용자 스레드(User Thread): 사용자 라이브러리가 관리, 커널 미인지
- 커널 스레드(Kernel Thread): 커널이 직접 생성·스케줄링
- 동기화 필요: 공유 자원 접근 시 임계구역(Critical Section) 보호

## Ⅲ. 흐름도 / 구조
```text
+--------- Process ---------+
|  Code | Data | Heap | File |  (공유)
|  +------+ +------+ +------+ |
|  |Stack | |Stack | |Stack | | (스레드별 독립)
|  |Regs  | |Regs  | |Regs  | |
|  |PC T1 | |PC T2 | |PC T3 | |
+--------------------------+
```

## Ⅳ. 핵심 특징
| 구분 | 내용 |
|:---|:---|
| 목적 | 경량 병행성으로 응답성·자원공유 효율 향상 |
| 장점 | 생성·문맥교환 비용↓, 데이터 공유 용이(IPC 불필요) |
| 한계 | 한 스레드 오류가 전 프로세스 영향, 동기화 복잡 |

## Ⅴ. 기술사적 적용
- 사용자 스레드: 문맥교환 빠르나 한 스레드 블로킹 시 전체 블로킹
- 커널 스레드: 멀티코어 병렬 실행 가능하나 모드전환 비용 발생
- 웹서버·DBMS의 요청별 스레드 처리 구조 설계에 적용
