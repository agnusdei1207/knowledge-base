## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 배포 전략은 신규 버전을 운영 환경에 반영할 때 무중단·저위험으로 전환하는 방식으로, 카나리(Canary)·블루그린(Blue-Green)·롤링(Rolling) 등으로 트래픽 전환과 롤백 방식을 달리한다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 애자일 실행체계와 DevOps 기반 전달 자동화, 운영 피드백까지 연결하는 출제축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 스크럼, XP, 칸반, MVP, SAFe/LeSS, DevOps, IaC, SRE, GitOps |
| 2~4교시 확장 방향 | 민첩성 요구와 도입 배경, 역할·이벤트·파이프라인 구조, 전통 방식 대비 차이, 지표 기반 운영과 확장 전략 |


- 답안 포인트
  - `배포 전략 (카나리·블루그린·롤링)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 롤링(Rolling): 인스턴스를 순차 교체, 추가 자원 적으나 두 버전 공존·롤백 느림
- 블루그린(Blue-Green): 동일 운영 환경 2벌, 그린으로 일괄 전환·즉시 롤백(자원 2배)
- 카나리(Canary): 소수 사용자(예 5%)에 먼저 노출, 지표 정상 시 점진 확대
- 트래픽 라우팅·헬스체크·자동 롤백, 기능 플래그(Feature Flag)로 코드 분리 제어
- A/B 테스트·섀도(Shadow) 배포로 검증 병행

## Ⅲ. 비교·구조·지표 정리
```text
[Rolling]  v1 v1 v1 → v2 v1 v1 → v2 v2 v1 → v2 v2 v2
[BlueGreen] Blue(v1) ── 전환 ──> Green(v2) (LB 스위치)
[Canary]   v2 5% → 모니터링 OK → 25% → 50% → 100%
                         │ 이상 → 자동 롤백
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 무중단·점진적 전환으로 배포 위험과 영향 최소화 |
| 장점 | 카나리: 위험 격리, 블루그린: 즉시 롤백, 롤링: 자원 효율 |
| 한계 | 블루그린: 자원 2배, 카나리: 모니터링·라우팅 복잡, DB 스키마 호환 |

## Ⅳ. 실무 적용 및 기술사 판단
- CI/CD 파이프라인·GitOps와 결합해 자동화된 점진 배포·자동 롤백 구현
- 옵저버빌리티 지표 기반 카나리 분석(자동 판정), SRE 에러예산과 연계

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 민첩성 요구와 도입 배경 |
| 본론 1 | 역할·이벤트·파이프라인 구조 |
| 본론 2 | 전통 방식 대비 차이 |
| 본론 3 | 지표 기반 운영과 확장 전략 |
| 결론 | 조직 문화 정착 포인트 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
