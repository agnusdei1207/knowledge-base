## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 함수형 프로그래밍(FP, Functional Programming)은 부수효과 없는 순수함수를 1급 객체로 다루고, 상태 변경 대신 값의 변환으로 계산을 표현하는 선언적 패러다임이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 모듈 경계, 아키텍처 스타일, 설계 원칙, 패턴, 품질속성까지 설계 판단을 묻는 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 응집도/결합도, 아키텍처 뷰, MVC, MSA, DDD, SOLID, DI, 코드 품질 메트릭 |
| 2~4교시 확장 방향 | 설계 목표와 품질속성, 구성요소·패턴·원리, 대안 구조 비교, 적용 조건과 안티패턴 |


- 답안 포인트
  - `함수형 프로그래밍 (Functional Programming)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 순수함수(Pure Function): 동일 입력→동일 출력, 부수효과(Side Effect) 없음
- 불변성(Immutability): 데이터 생성 후 변경 불가, 새 값으로 대체
- 고차함수(High-order Function): 함수를 인자·반환값으로 사용(map·filter·reduce)
- 1급 함수(First-class)·참조투명성: 함수를 값처럼 전달, 식을 결과로 치환 가능
- 선언적 표현: "무엇을" 기술, 재귀·합성으로 흐름 구성

## Ⅲ. 비교·구조·지표 정리
```text
입력값(불변)
   │ map(변환)
   ▼
중간값(새 객체)
   │ filter(선별)
   ▼
reduce(누적) → 결과값
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 부수효과 제거로 예측가능·동시성 안전 코드 구현 |
| 장점 | 테스트·디버깅 용이, 병렬처리 적합, 참조투명성 |
| 한계 | 상태 많은 도메인 표현 난해, 재귀 깊이·메모리 부담 |

## Ⅳ. 실무 적용 및 기술사 판단
- 불변성·순수함수는 멀티코어 병렬처리와 동시성 프로그래밍의 핵심 기반
- 스트림 API(Java)·React Hooks 등 현대 언어/프레임워크에 도입
- 객체지향과 혼합(멀티패러다임)하여 도메인별 강점 활용

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 설계 목표와 품질속성 |
| 본론 1 | 구성요소·패턴·원리 |
| 본론 2 | 대안 구조 비교 |
| 본론 3 | 적용 조건과 안티패턴 |

- 전개 순서

  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
