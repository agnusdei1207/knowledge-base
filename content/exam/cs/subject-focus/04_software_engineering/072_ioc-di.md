## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 제어역전(IoC, Inversion of Control)은 객체 생성·생명주기의 제어권을 프레임워크(컨테이너)에 넘기는 원리이며, 의존성주입(DI, Dependency Injection)은 그 구현 기법으로 외부에서 의존 객체를 주입한다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 모듈 경계, 아키텍처 스타일, 설계 원칙, 패턴, 품질속성까지 설계 판단을 묻는 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 응집도/결합도, 아키텍처 뷰, MVC, MSA, DDD, SOLID, DI, 코드 품질 메트릭 |
| 2~4교시 확장 방향 | 설계 목표와 품질속성, 구성요소·패턴·원리, 대안 구조 비교, 적용 조건과 안티패턴 |


- 답안 포인트
  - `제어역전·의존성주입 (IoC·DI)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- IoC 컨테이너: 빈(Bean) 생성·관리·소멸을 담당하는 제어 주체
- 생성자 주입(Constructor): 불변·필수 의존성, 권장 방식
- 세터 주입(Setter): 선택적 의존성, 런타임 변경 가능
- 필드 주입(Field): 간결하나 테스트·결합 측면 비권장
- 원리: "Don't call us, we'll call you"(Hollywood Principle)

## Ⅲ. 비교·구조·지표 정리
```text
[IoC 컨테이너]
   │ 생성·주입
   ▼
ClassA ──의존──> Interface <──구현── ClassB
(주입된 구현체를 런타임에 사용)
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 객체 간 결합도 낮추고 의존성 외부화로 유연성 확보 |
| 장점 | 테스트 용이(Mock 주입), 교체 용이, 관심사 분리 |
| 한계 | 컨테이너 학습비용, 런타임 추적·디버깅 복잡 |

## Ⅳ. 실무 적용 및 기술사 판단
- SOLID의 DIP(의존성역전원칙) 실현 수단으로 DI 활용
- Spring Framework의 핵심 메커니즘, 테스트 더블 주입으로 단위테스트 강화
- 전략패턴·팩토리패턴과 결합해 런타임 구현체 선택

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시
