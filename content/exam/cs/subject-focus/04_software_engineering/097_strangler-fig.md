## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 스트랭글러 피그(Strangler Fig)는 레거시 시스템을 한 번에 교체하지 않고, 기능을 점진적으로 신규 시스템으로 이관하며 레거시를 단계적으로 폐기하는 현대화 패턴이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 컨테이너, 서비스 메시, 분산 트랜잭션, 관측성과 복원력을 포함한 운영형 아키텍처 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | Kubernetes, Service Mesh, API Gateway/BFF, Saga, CQRS, Serverless, MSA 전환 |
| 2~4교시 확장 방향 | 클라우드 네이티브 전환 배경, 런타임 구조와 통신 메커니즘, 모놀리스/분산구조 비교, 운영 복잡도와 대응 패턴 |


- 답안 포인트
  - `스트랭글러 피그 패턴 (Strangler Fig)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 파사드(Facade)/프록시: 요청을 레거시·신규로 분기하는 라우팅 계층
- 점진적 이관: 기능 단위로 신규 시스템 구현·전환
- 병행 운영: 레거시·신규가 일정 기간 공존
- 라우팅 전환: 이관 완료 기능은 신규로 트래픽 이동
- 폐기: 모든 기능 이관 후 레거시 제거

## Ⅲ. 비교·구조·지표 정리
```text
Client → [Facade/Proxy 라우터]
            ├─ 미이관 기능 → Legacy System
            └─ 이관 완료   → New System
   (점진 전환: 비율↑ → 최종 Legacy 폐기)
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 레거시의 안전·점진적 현대화 |
| 장점 | 빅뱅 리스크 회피·롤백 용이·비즈니스 무중단 |
| 한계 | 이관 장기화·중복 유지비·라우팅 계층 복잡 |

## Ⅳ. 실무 적용 및 기술사 판단
- 모놀리스→MSA 전환의 대표 전략(빅뱅 재작성 대비 위험↓)
- 안티커럽션 레이어(ACL)로 레거시·신규 모델 격리
- 모듈러 모놀리스의 경계가 이관 단위 식별을 가속

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 클라우드 네이티브 전환 배경 |
| 본론 1 | 런타임 구조와 통신 메커니즘 |
| 본론 2 | 모놀리스/분산구조 비교 |
| 본론 3 | 운영 복잡도와 대응 패턴 |
| 결론 | 확장성·회복탄력성 결론 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
