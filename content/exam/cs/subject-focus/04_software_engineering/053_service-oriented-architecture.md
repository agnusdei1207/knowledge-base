## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 서비스 지향 아키텍처(SOA, Service-Oriented Architecture)는 비즈니스 기능을 표준 인터페이스를 가진 재사용 가능한 서비스로 구성하고, ESB(Enterprise Service Bus)를 통해 느슨하게 통합·연계하는 아키텍처이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 모듈 경계, 아키텍처 스타일, 설계 원칙, 패턴, 품질속성까지 설계 판단을 묻는 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 응집도/결합도, 아키텍처 뷰, MVC, MSA, DDD, SOLID, DI, 코드 품질 메트릭 |
| 2~4교시 확장 방향 | 설계 목표와 품질속성, 구성요소·패턴·원리, 대안 구조 비교, 적용 조건과 안티패턴 |


- 답안 포인트
  - `서비스 지향 아키텍처 (SOA)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 서비스(Service): 표준 계약(WSDL)으로 노출되는 비즈니스 단위
- ESB(Enterprise Service Bus): 라우팅·변환·중계 통합 버스
- 서비스 레지스트리(UDDI): 서비스 등록·발견
- 표준 프로토콜: SOAP/WS-*, XML 기반 메시지
- 느슨한 결합·재사용·표준 계약·서비스 합성(Orchestration)

## Ⅲ. 비교·구조·지표 정리
```text
[Consumer] → [ESB(라우팅/변환/중계)] → [Service A]
                  │  ↑(레지스트리 조회)  → [Service B]
              [UDDI 레지스트리]          → [Service C]
   ESB 중심 허브-스포크 통합
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 기업 서비스 재사용·표준 통합으로 민첩성 확보 |
| 장점 | 이기종 시스템 연계, 재사용·표준화, 비즈니스 정렬 |
| 한계 | ESB 중앙집중 병목·SPOF, 무거운 WS-* 표준, 거버넌스 복잡 |

## Ⅳ. 실무 적용 및 기술사 판단
- 대기업 레거시 통합(EAI 발전형), 정부·금융 표준 연계 플랫폼
- MSA는 SOA의 ESB 집중을 제거하고 경량 API·분산 거버넌스로 진화한 형태

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 설계 목표와 품질속성 |
| 본론 1 | 구성요소·패턴·원리 |
| 본론 2 | 대안 구조 비교 |
| 본론 3 | 적용 조건과 안티패턴 |
| 결론 | 유지보수성과 확장성 결론 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
