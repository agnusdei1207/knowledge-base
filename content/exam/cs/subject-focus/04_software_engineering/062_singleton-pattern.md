## Ⅰ. 출제 관점 및 1교시 답안 포인트
> GoF(Gang of Four) 디자인패턴의 생성(Creational) 패턴으로, 특정 클래스의 인스턴스를 시스템 전역에 단 1개만 생성·보장하고 이에 대한 전역 접근점(Global Access Point)을 제공하는 패턴.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 모듈 경계, 아키텍처 스타일, 설계 원칙, 패턴, 품질속성까지 설계 판단을 묻는 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 응집도/결합도, 아키텍처 뷰, MVC, MSA, DDD, SOLID, DI, 코드 품질 메트릭 |
| 2~4교시 확장 방향 | 설계 목표와 품질속성, 구성요소·패턴·원리, 대안 구조 비교, 적용 조건과 안티패턴 |


- 답안 포인트
  - `싱글톤 패턴 (Singleton)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- **Singleton 클래스**: 자신의 유일 인스턴스를 보관하는 static 멤버 보유
- **private 생성자**: 외부의 `new` 호출 차단으로 인스턴스 추가 생성 방지
- **getInstance()**: 인스턴스가 없으면 생성, 있으면 기존 것 반환(Lazy/Eager 초기화)
- **전역 접근점**: 클래스 메서드를 통해 어디서든 동일 객체 접근
- **동시성 제어**: 멀티스레드 환경에서 DCL(Double-Checked Locking)·synchronized로 안전 보장

## Ⅲ. 비교·구조·지표 정리
```text
Client ── getInstance() ──> Singleton
                            - static instance
                            - private Singleton()
                            + getInstance(): Singleton
            (instance==null ? new : 기존 반환)
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 인스턴스 1개 보장 + 전역 접근점 제공 |
| 장점 | 자원 공유(설정·로그·커넥션풀), 메모리 절약, 일관된 상태 |
| 한계 | 전역상태로 결합도↑·테스트(Mock) 곤란, 멀티스레드 동기화 비용 |

## Ⅳ. 실무 적용 및 기술사 판단
- 로깅, 환경설정, DB Connection Pool, 캐시 매니저 등 공유 자원 관리에 활용
- DI(의존성 주입) 컨테이너의 Bean Scope=Singleton으로 프레임워크가 대체 관리
- 안티패턴 논란: 과용 시 SRP·테스트성 저하 → DI/Monostate로 보완

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시
