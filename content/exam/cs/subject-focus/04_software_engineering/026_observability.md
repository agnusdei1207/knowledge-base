## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 옵저버빌리티(Observability, 관측가능성)는 시스템의 외부 출력(텔레메트리)만으로 내부 상태를 추론할 수 있는 능력으로, 메트릭(Metrics)·로그(Logs)·트레이스(Traces) 3대 축을 통해 미지의 장애까지 진단하는 운영 역량이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 애자일 실행체계와 DevOps 기반 전달 자동화, 운영 피드백까지 연결하는 출제축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 스크럼, XP, 칸반, MVP, SAFe/LeSS, DevOps, IaC, SRE, GitOps |
| 2~4교시 확장 방향 | 민첩성 요구와 도입 배경, 역할·이벤트·파이프라인 구조, 전통 방식 대비 차이, 지표 기반 운영과 확장 전략 |


- 답안 포인트
  - `옵저버빌리티 (Observability)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 메트릭(Metrics): 수치화된 시계열 지표(CPU·지연·오류율), 집계·알림에 적합
- 로그(Logs): 시점별 이벤트의 구조화 기록, 상세 원인 분석
- 트레이스(Traces): 분산 요청의 전 구간 경로·지연 추적(분산 추적)
- 모니터링과 차이: 알려진 지표 감시(모니터링) vs 미지 문제 탐색(관측가능성)
- 표준: OpenTelemetry로 텔레메트리 수집 표준화, 상관관계 분석

## Ⅲ. 비교·구조·지표 정리
```text
 서비스 ─계측(OpenTelemetry)→ ┌ Metrics ┐
                              ├ Logs    ┼─> 수집·상관분석 ─> 대시보드/알림
                              └ Traces  ┘            │
                                        근본원인(RCA)·MTTR 단축
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 텔레메트리로 내부 상태를 추론해 미지 장애까지 신속 진단 |
| 장점 | RCA·MTTR 단축, 분산 시스템 가시성, 선제적 이상 탐지 |
| 한계 | 데이터 폭증·저장 비용, 계측 표준화·노이즈 관리 부담 |

## Ⅳ. 실무 적용 및 기술사 판단
- SRE의 SLI 측정·에러예산 산정의 데이터 기반, DevOps 측정(M) 실현
- 마이크로서비스·쿠버네티스 환경 분산추적, AIOps 이상탐지와 연계

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 민첩성 요구와 도입 배경 |
| 본론 1 | 역할·이벤트·파이프라인 구조 |
| 본론 2 | 전통 방식 대비 차이 |
| 본론 3 | 지표 기반 운영과 확장 전략 |
| 결론 | 조직 문화 정착 포인트 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
