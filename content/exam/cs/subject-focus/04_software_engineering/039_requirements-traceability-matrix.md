## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 요구사항 추적성 매트릭스(RTM, Requirements Traceability Matrix)는 요구사항이 설계·구현·테스트로 이어지는 연결을 추적·관리하는 표.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 요구 도출부터 우선순위, 명세, 추적성까지 품질 좋은 요구를 만드는 분석 출제축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 요구공학, SRS, RTM, 유스케이스, DFD, QFD, MoSCoW, 스토리맵 |
| 2~4교시 확장 방향 | 문제 상황과 이해관계자 관점, 도출·분석·명세 절차, 도구/기법 비교, 변경 통제와 검증 적용 |


- 답안 포인트
  - `요구사항 추적성 (RTM)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 순방향(Forward) 추적: 요구→설계→코드→테스트케이스 연결
- 역방향(Backward) 추적: 산출물→근거 요구사항 역추적
- 양방향(Bidirectional): 순·역 추적 모두 유지
- 변경영향 분석: 요구 변경 시 영향 범위 식별
- 누락·중복 검출: 미구현·미테스트 요구 식별

## Ⅲ. 비교·구조·지표 정리
```text
요구ID ─순방향→ 설계 → 코드 → 테스트케이스
   ↑__________ 역방향(근거 추적) __________↓
REQ-01 | DSG-03 | MOD-07 | TC-12
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 요구 충족 보장과 변경 영향 통제 |
| 장점 | 누락·과잉 방지, 감사·검증 근거 확보 |
| 한계 | 작성·유지 비용 크고 수작업 시 동기화 어려움 |

## Ⅳ. 실무 적용 및 기술사 판단
- 순방향=요구 누락 방지, 역방향=골드플래팅·범위크리프 방지
- 형상관리 도구(JIRA, DOORS)로 자동 추적
- 변경통제(CCB)와 연계한 영향분석 핵심 자료

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 문제 상황과 이해관계자 관점 |
| 본론 1 | 도출·분석·명세 절차 |
| 본론 2 | 도구/기법 비교 |
| 본론 3 | 변경 통제와 검증 적용 |
| 결론 | 실패 예방 효과 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
