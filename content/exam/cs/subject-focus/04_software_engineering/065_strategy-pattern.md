## Ⅰ. 출제 관점 및 1교시 답안 포인트
> GoF(Gang of Four) 행위(Behavioral) 패턴으로, 동일 목적의 알고리즘군을 각각 캡슐화하여 상호 교환 가능하게 만들고, 클라이언트와 독립적으로 런타임에 알고리즘을 선택·교체할 수 있게 하는 패턴.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 모듈 경계, 아키텍처 스타일, 설계 원칙, 패턴, 품질속성까지 설계 판단을 묻는 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 응집도/결합도, 아키텍처 뷰, MVC, MSA, DDD, SOLID, DI, 코드 품질 메트릭 |
| 2~4교시 확장 방향 | 설계 목표와 품질속성, 구성요소·패턴·원리, 대안 구조 비교, 적용 조건과 안티패턴 |


- 답안 포인트
  - `전략 패턴 (Strategy)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- **Strategy**: 알고리즘 공통 인터페이스(예: execute) 정의
- **ConcreteStrategy**: Strategy를 구현한 각 알고리즘
- **Context**: Strategy 참조를 보유, 클라이언트 요청을 위임 실행
- **Client**: Context에 사용할 ConcreteStrategy를 주입(setStrategy)
- **원리**: 상속 대신 합성(Composition)으로 행위 분리 → 조건분기(if/switch) 제거

## Ⅲ. 비교·구조·지표 정리
```text
Client → Context(strategy) ──execute()──> Strategy
                                            △
                ┌───────────────┬──────────┘
          StrategyA        StrategyB     StrategyC
런타임에 setStrategy()로 알고리즘 교체
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 알고리즘 캡슐화·런타임 교체, 조건문 제거 |
| 장점 | OCP 준수, 알고리즘 독립 확장·테스트, 결합도↓ |
| 한계 | 전략 클래스 수 증가, 클라이언트가 전략 차이 인지 필요 |

## Ⅳ. 실무 적용 및 기술사 판단
- 정렬·압축·암호화·결제수단 등 교체형 알고리즘 선택에 활용
- 상태 패턴(State)과 구조 유사: Strategy는 알고리즘 선택, State는 상태전이 자동화
- 함수형 언어의 고차함수·람다, DI와 결합해 전략 주입 간소화

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |

| 서론 | 설계 목표와 품질속성 |
| 본론 1 | 구성요소·패턴·원리 |

- 전개 순서

  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
