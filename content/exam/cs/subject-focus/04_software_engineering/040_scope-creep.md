## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 공식 변경통제 없이 프로젝트 범위가 점진적·통제 불능으로 확대되어 일정·비용·품질을 악화시키는 현상.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 요구 도출부터 우선순위, 명세, 추적성까지 품질 좋은 요구를 만드는 분석 출제축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 요구공학, SRS, RTM, 유스케이스, DFD, QFD, MoSCoW, 스토리맵 |
| 2~4교시 확장 방향 | 문제 상황과 이해관계자 관점, 도출·분석·명세 절차, 도구/기법 비교, 변경 통제와 검증 적용 |


- 답안 포인트
  - `범위 크리프 (Scope Creep)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 원인: 모호한 범위정의, 잦은 요구 추가, 통제 부재
- 증상: 일정 지연, 예산 초과, 품질 저하
- 통제 수단: 변경통제위원회(CCB), 기준선(Baseline) 관리
- 예방: 명확한 SOW·WBS, 요구사항 동결, 추적성 유지
- 골드플래팅과 구분: 고객 요구 확대(크리프) vs 개발자 자발 추가(골드플래팅)

## Ⅲ. 비교·구조·지표 정리
```text
기준범위 → (소규모 요구 추가)×N → 통제불능 확대
                 ↓ 변경통제 부재
        일정지연·비용초과·품질저하
   [예방] CCB·기준선·추적성으로 차단
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 통제되지 않은 범위 확장 인식·예방 |
| 장점 | 인지 시 변경통제로 위험 관리 가능 |
| 한계 | 잠재적·누적적이라 조기 식별 어려움 |

## Ⅳ. 실무 적용 및 기술사 판단
- 변경통제 프로세스(요청→영향분석→승인→반영)로 관리
- RTM·기준선으로 범위 일탈 감지
- 골드플래팅과 함께 범위관리(Scope Management) 영역의 핵심 위험

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 문제 상황과 이해관계자 관점 |
| 본론 1 | 도출·분석·명세 절차 |
| 본론 2 | 도구/기법 비교 |
| 본론 3 | 변경 통제와 검증 적용 |
| 결론 | 실패 예방 효과 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
