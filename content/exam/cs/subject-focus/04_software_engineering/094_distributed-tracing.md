## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 분산 추적(Distributed Tracing)은 하나의 요청이 여러 마이크로서비스를 거치는 전 경로를 TraceID·SpanID로 연결·시각화하여 지연·병목·장애 지점을 분석하는 관측성 기법이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 컨테이너, 서비스 메시, 분산 트랜잭션, 관측성과 복원력을 포함한 운영형 아키텍처 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | Kubernetes, Service Mesh, API Gateway/BFF, Saga, CQRS, Serverless, MSA 전환 |
| 2~4교시 확장 방향 | 클라우드 네이티브 전환 배경, 런타임 구조와 통신 메커니즘, 모놀리스/분산구조 비교, 운영 복잡도와 대응 패턴 |


- 답안 포인트
  - `분산 추적 (Distributed Tracing)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- Trace: 단일 요청의 전체 호출 경로(여러 Span의 트리)
- Span: 개별 작업 단위(서비스 호출), 시작·종료 시간·메타 포함
- Context Propagation: TraceID·SpanID를 헤더로 서비스 간 전파
- OpenTelemetry(OTel): 추적·메트릭·로그 수집 표준 SDK·프로토콜
- Collector·Backend: Jaeger·Zipkin·Tempo로 저장·시각화

## Ⅲ. 비교·구조·지표 정리
```text
Request(TraceID=T1)
 Span A(svc1) ─┬─ Span B(svc2, parent=A)
               └─ Span C(svc3, parent=A)
[헤더로 traceparent 전파] → Collector → Jaeger 시각화
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 분산 호출 경로의 가시성·근본원인 분석 |
| 장점 | 병목·지연 식별·서비스 의존성 파악·MTTR 단축 |
| 한계 | 계측 오버헤드·샘플링 시 정보 손실·저장 비용 |

## Ⅳ. 실무 적용 및 기술사 판단
- 관측성 3요소(메트릭·로그·추적) 중 추적을 OTel로 표준 통합
- 서비스 메시 사이드카가 자동 계측으로 코드 변경 최소화
- 샘플링(헤드/테일) 전략으로 비용·정보 균형 조정

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시
