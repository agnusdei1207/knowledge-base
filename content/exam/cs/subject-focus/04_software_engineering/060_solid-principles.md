## Ⅰ. 출제 관점 및 1교시 답안 포인트
> SOLID는 로버트 마틴이 정리한 객체지향 설계 5대 원칙(SRP·OCP·LSP·ISP·DIP)으로, 변경에 유연하고 유지보수·확장이 용이한 객체지향 구조를 만들기 위한 지침이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 모듈 경계, 아키텍처 스타일, 설계 원칙, 패턴, 품질속성까지 설계 판단을 묻는 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 응집도/결합도, 아키텍처 뷰, MVC, MSA, DDD, SOLID, DI, 코드 품질 메트릭 |
| 2~4교시 확장 방향 | 설계 목표와 품질속성, 구성요소·패턴·원리, 대안 구조 비교, 적용 조건과 안티패턴 |


- 답안 포인트
  - `SOLID 원칙`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- SRP(단일 책임 원칙): 클래스는 변경 이유가 하나여야 함 — 책임 단일화
- OCP(개방-폐쇄 원칙): 확장에는 열리고 수정에는 닫힘 — 추상화로 확장
- LSP(리스코프 치환 원칙): 자식은 부모 타입으로 치환 가능해야 함 — 계약 준수
- ISP(인터페이스 분리 원칙): 사용하지 않는 인터페이스 의존 강제 금지 — 작은 인터페이스
- DIP(의존성 역전 원칙): 구체가 아닌 추상에 의존 — 고수준·저수준 모두 추상화 의존

## Ⅲ. 비교·구조·지표 정리
```text
[SRP] 책임 분리 ─┐
[OCP] 확장 개방  ─┤
[LSP] 치환 보장  ─┼─> 유연·견고한 객체지향 설계
[ISP] 분리 의존  ─┤
[DIP] 추상 의존  ─┘
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 변경에 유연하고 재사용·테스트 가능한 OO 설계 |
| 장점 | 결합도↓·응집도↑, 확장 용이, 유지보수성 향상 |
| 한계 | 과적용 시 클래스·인터페이스 증가, 복잡도·추상화 비용 |

## Ⅳ. 실무 적용 및 기술사 판단
- DIP는 헥사고날·클린 아키텍처 포트&어댑터의 핵심 원리
- OCP·ISP는 디자인 패턴(전략·어댑터)·플러그인 구조 설계 근거

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 설계 목표와 품질속성 |
| 본론 1 | 구성요소·패턴·원리 |
| 본론 2 | 대안 구조 비교 |
| 본론 3 | 적용 조건과 안티패턴 |
| 결론 | 유지보수성과 확장성 결론 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
