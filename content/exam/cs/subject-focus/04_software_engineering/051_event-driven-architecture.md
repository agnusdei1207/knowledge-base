## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 이벤트 기반 아키텍처(EDA, Event-Driven Architecture)는 상태 변화를 나타내는 이벤트의 생성·발행·구독을 통해 컴포넌트가 비동기·느슨하게 통신하는 아키텍처로, 발행/구독(Pub/Sub) 모델과 이벤트 브로커를 핵심으로 한다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 모듈 경계, 아키텍처 스타일, 설계 원칙, 패턴, 품질속성까지 설계 판단을 묻는 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 응집도/결합도, 아키텍처 뷰, MVC, MSA, DDD, SOLID, DI, 코드 품질 메트릭 |
| 2~4교시 확장 방향 | 설계 목표와 품질속성, 구성요소·패턴·원리, 대안 구조 비교, 적용 조건과 안티패턴 |


- 답안 포인트
  - `이벤트 기반 아키텍처 (EDA)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 이벤트 생산자(Producer)·소비자(Consumer): 발행·구독 주체
- 이벤트 브로커/채널(Broker): Kafka·RabbitMQ 등 메시지 중계
- 처리 토폴로지: 중재자(Mediator) 방식과 브로커(Broker) 방식
- 비동기·느슨한 결합·시간 분리(temporal decoupling)
- 이벤트 = 발생 사실의 불변 메시지

## Ⅲ. 비교·구조·지표 정리
```text
[Producer] --발행--> [Event Broker(Topic)] --구독--> [Consumer A]
                          │                        └--> [Consumer B]
   비동기 전파, 생산자-소비자 상호 무인지(느슨한 결합)
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 비동기 느슨한 결합으로 확장성·실시간 반응성 확보 |
| 장점 | 높은 확장성·탄력성, 컴포넌트 독립 진화, 실시간 처리 |
| 한계 | 흐름 추적·디버깅 곤란, 최종 일관성, 이벤트 순서/중복 처리 |

## Ⅳ. 실무 적용 및 기술사 판단
- MSA 서비스 간 비동기 통신, 사가(Saga)·CQRS·이벤트 소싱의 기반
- IoT·실시간 스트리밍·알림 시스템 등 이벤트 폭주 환경에 적합

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 설계 목표와 품질속성 |
| 본론 1 | 구성요소·패턴·원리 |
| 본론 2 | 대안 구조 비교 |
| 본론 3 | 적용 조건과 안티패턴 |
| 결론 | 유지보수성과 확장성 결론 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
