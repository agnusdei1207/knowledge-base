## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 시크릿 관리는 API 키·비밀번호·인증서·토큰 등 민감 정보를 코드·설정에서 분리해 중앙에서 안전하게 저장·접근통제·순환(Rotation)하는 보안 체계이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 개발생명주기 보안, 위협 모델링, 오픈소스 공급망 통제까지 예방 중심 보안 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | Secure SDLC, STRIDE, SCA, SBOM, Secret Management |
| 2~4교시 확장 방향 | 보안 좌측 이동 배경, 통제 포인트와 자동화 체계, 기존 사후 점검 대비 차이, 규제·감사·운영 적용 |


- 답안 포인트
  - `시크릿 관리 (Secret Management·Vault)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 중앙 저장소: Vault·AWS Secrets Manager가 암호화 저장
- 접근통제: 정책 기반 인가·최소권한·동적 시크릿 발급
- 암호화: 저장(at-rest)·전송(in-transit) 암호화, Seal/Unseal
- 순환(Rotation): 시크릿 주기적 자동 갱신으로 노출 위험 최소화
- 감사: 모든 접근 로깅으로 추적성 확보

## Ⅲ. 비교·구조·지표 정리
```text
App → 인증(Token/IAM) → [Vault]
                         ├ 정책 검증(최소권한)
                         ├ 동적 시크릿 발급(TTL)
                         └ 감사 로깅
   하드코딩 금지: 코드/이미지에 비밀 미포함
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 민감정보 중앙화·노출 차단·자동 순환 |
| 장점 | 하드코딩 제거·동적 시크릿·감사 추적·접근통제 |
| 한계 | SPOF·가용성 의존·초기 구축 복잡·성능 영향 |

## Ⅳ. 실무 적용 및 기술사 판단
- 12-Factor App "설정의 환경 분리" 원칙 구현 수단
- K8s에선 External Secrets Operator로 Vault 연동
- 정적 시크릿 대비 동적 시크릿(짧은 TTL)이 유출 피해 최소화

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 보안 좌측 이동 배경 |
| 본론 1 | 통제 포인트와 자동화 체계 |
| 본론 2 | 기존 사후 점검 대비 차이 |
| 본론 3 | 규제·감사·운영 적용 |
| 결론 | 리스크 저감 효과 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
