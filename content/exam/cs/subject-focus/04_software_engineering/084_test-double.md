## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 테스트 더블(Test Double)은 테스트 대상이 의존하는 실제 객체를 대체하는 모조 객체로, 의존성을 격리해 단위테스트의 독립성·결정성을 확보한다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 검증·확인, 테스트 설계, 커버리지, 회귀/성능까지 품질보증 체계를 묻는 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 테스트 원리, 블랙박스/화이트박스, 테스트 레벨, 회귀, 성능, TDD, 테스트 더블 |
| 2~4교시 확장 방향 | 품질 위험과 테스트 필요성, 기법·절차·커버리지 구조, 정적/동적 또는 기능/비기능 비교, 자동화·회귀 전략 |


- 답안 포인트
  - `테스트 더블 (Mock·Stub·Spy·Fake)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- Stub: 미리 정해진 응답을 반환(상태 기반 검증 지원)
- Mock: 호출 방식·횟수 기대를 검증(행위 기반 검증)
- Spy: 실제 객체 일부 대체+호출 정보 기록
- Fake: 단순화된 동작 구현(예: 인메모리 DB)
- Dummy: 전달만 되고 사용되지 않는 객체

## Ⅲ. 비교·구조·지표 정리
```text
[테스트 대상 SUT]
     │ 의존성 주입
     ▼
[테스트 더블] ── Stub: 응답반환
              ├ Mock: 호출검증
              └ Fake: 경량구현
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 외부 의존성 격리로 빠르고 결정적인 단위테스트 실현 |
| 장점 | 외부자원 불필요, 실행 고속, 예외상황 재현 용이 |
| 한계 | 과용 시 실제 동작과 괴리, 테스트 취약(과결합) |

## Ⅳ. 실무 적용 및 기술사 판단
- DI(의존성주입)로 테스트 더블 주입, 단위테스트 격리 강화
- Mock(행위검증) vs Stub(상태검증) 목적별 구분 적용
- TDD에서 협력객체 미완성 시 더블로 선행 테스트 작성

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 품질 위험과 테스트 필요성 |
| 본론 1 | 기법·절차·커버리지 구조 |
| 본론 2 | 정적/동적 또는 기능/비기능 비교 |
| 본론 3 | 자동화·회귀 전략 |
| 결론 | 품질 지표와 운영 연계 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
