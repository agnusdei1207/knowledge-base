## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 추상화(Abstraction)는 복잡한 대상에서 본질적 속성만 추출해 단순화하는 기법, 정보은닉(Information Hiding)은 모듈 내부 구현·자료를 외부로부터 감추고 인터페이스만 노출하는 설계 원칙이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 모듈 경계, 아키텍처 스타일, 설계 원칙, 패턴, 품질속성까지 설계 판단을 묻는 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 응집도/결합도, 아키텍처 뷰, MVC, MSA, DDD, SOLID, DI, 코드 품질 메트릭 |
| 2~4교시 확장 방향 | 설계 목표와 품질속성, 구성요소·패턴·원리, 대안 구조 비교, 적용 조건과 안티패턴 |


- 답안 포인트
  - `추상화·정보은닉 (Abstraction·Information Hiding)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 추상화 유형: 과정 추상화, 자료 추상화(ADT), 제어 추상화
- 정보은닉: 캡슐화(Encapsulation)로 구현, 접근제어자(private/protected)로 노출 범위 통제
- 인터페이스(계약)와 구현(세부)의 분리 → 변경 격리
- 추상화는 '무엇을', 은닉은 '어떻게'를 감춤
- 모듈 간 결합도 감소·응집도 향상에 기여

## Ⅲ. 비교·구조·지표 정리
```text
[외부 호출자]
     │ (공개 인터페이스만 접근)
     ▼
[모듈 경계 = 추상화 계약]
     │
     ▼
[은닉된 내부 구현·자료구조]  ← 변경되어도 외부 불변
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 복잡도 관리와 변경 격리로 안정적 모듈 설계 |
| 장점 | 내부 변경 자유, 재사용·교체 용이, 오용 방지 |
| 한계 | 과도한 추상화 시 이해 난이도·간접 호출 비용 증가 |

## Ⅳ. 실무 적용 및 기술사 판단
- 객체지향 캡슐화, 헥사고날 아키텍처 포트, MSA API 계약의 기반 원리
- DIP(의존성 역전)와 결합해 인터페이스 기반 느슨한 결합 구조 설계

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 설계 목표와 품질속성 |
| 본론 1 | 구성요소·패턴·원리 |
| 본론 2 | 대안 구조 비교 |
| 본론 3 | 적용 조건과 안티패턴 |
| 결론 | 유지보수성과 확장성 결론 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
