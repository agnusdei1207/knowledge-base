## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 컨테이너는 애플리케이션과 의존성을 OS 커널 공유 기반으로 격리·패키징한 경량 실행 단위이며, 쿠버네티스(K8s)는 이 컨테이너의 배포·확장·운영을 자동화하는 오케스트레이션 플랫폼이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 컨테이너, 서비스 메시, 분산 트랜잭션, 관측성과 복원력을 포함한 운영형 아키텍처 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | Kubernetes, Service Mesh, API Gateway/BFF, Saga, CQRS, Serverless, MSA 전환 |
| 2~4교시 확장 방향 | 클라우드 네이티브 전환 배경, 런타임 구조와 통신 메커니즘, 모놀리스/분산구조 비교, 운영 복잡도와 대응 패턴 |


- 답안 포인트
  - `컨테이너·쿠버네티스 (Container·Kubernetes)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- Pod: 컨테이너의 최소 배포 단위, 동일 네트워크·스토리지 공유
- Service: Pod 집합에 안정적 가상 IP(ClusterIP)·로드밸런싱 제공
- Ingress: 클러스터 외부 HTTP/HTTPS 트래픽의 L7 라우팅 진입점
- Control Plane: API Server·etcd·Scheduler·Controller Manager
- 선언적 모델: 원하는 상태(Desired State)를 YAML로 정의, 자동 수렴

## Ⅲ. 비교·구조·지표 정리
```text
Client → Ingress(L7) → Service(ClusterIP/LB)
                          │
                  ┌───────┴───────┐
                Pod-A           Pod-B  (ReplicaSet)
                  └─ Container ──┘  (kubelet/Node 관리)
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 컨테이너 배포·확장·자가치유 자동화 |
| 장점 | 이식성·선언적 운영·오토스케일(HPA)·롤링 업데이트 |
| 한계 | 운영 복잡도·학습 곡선·상태저장(Stateful) 부담 |

## Ⅳ. 실무 적용 및 기술사 판단
- MSA 런타임 표준: 서비스 단위 컨테이너 배포로 독립 배포성 확보
- VM 대비 부팅 속도·자원 효율 우수, 단 격리 수준은 VM보다 낮음
- 서비스 메시·GitOps(ArgoCD)와 결합해 CI/CD 파이프라인 완성

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시
