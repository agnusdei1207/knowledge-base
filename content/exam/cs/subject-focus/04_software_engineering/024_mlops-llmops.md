## Ⅰ. 출제 관점 및 1교시 답안 포인트
> MLOps(Machine Learning Operations)는 머신러닝 모델의 데이터·학습·배포·모니터링 수명주기를 자동화·표준화하는 운영 체계이며, LLMOps는 대규모 언어모델(LLM)의 프롬프트·파인튜닝·평가·서빙 등 LLM 특화 운영을 다루는 확장 분야이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 애자일 실행체계와 DevOps 기반 전달 자동화, 운영 피드백까지 연결하는 출제축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 스크럼, XP, 칸반, MVP, SAFe/LeSS, DevOps, IaC, SRE, GitOps |
| 2~4교시 확장 방향 | 민첩성 요구와 도입 배경, 역할·이벤트·파이프라인 구조, 전통 방식 대비 차이, 지표 기반 운영과 확장 전략 |


- 답안 포인트
  - `MLOps·LLMOps`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 파이프라인: 데이터 수집·검증 → 학습 → 평가 → 배포(서빙) → 모니터링 → 재학습
- 버전관리: 데이터·모델·코드 3중 버전(재현성), 실험추적·모델 레지스트리
- 모니터링: 데이터 드리프트·모델 성능 저하 감지 후 자동 재학습 트리거(CT, 지속학습)
- LLMOps 특화: 프롬프트 관리, RAG(검색증강생성), 파인튜닝/RLHF, 환각·평가, 토큰비용·가드레일
- CI/CD/CT 통합, 피처스토어·GPU 자원 관리

## Ⅲ. 비교·구조·지표 정리
```text
 Data ─> Train ─> Evaluate ─> Deploy(Serving) ─> Monitor
   ▲                                              │ Drift 감지
   └──────────── Retrain(CT) ←────────────────────┘
 [LLMOps] +Prompt/RAG/Fine-tune/Guardrail/평가
```

| 구분 | 내용 |
|:---|:---|
| 목적 | ML/LLM 수명주기 자동화로 재현성·신뢰성·운영 효율 확보 |
| 장점 | 빠른 배포·재학습, 드리프트 대응, 거버넌스·비용 통제 |
| 한계 | 데이터 품질·GPU 비용, LLM 환각·평가 난이도, 규제·윤리 |

## Ⅳ. 실무 적용 및 기술사 판단
- DevOps에 데이터·모델 차원을 더한 확장(CI/CD/CT), 모델 거버넌스·AI윤리 연계
- LLMOps로 사내 RAG·에이전트 운영, 토큰비용·가드레일·옵저버빌리티 통합

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시
