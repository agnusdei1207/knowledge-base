## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 헥사고날(포트&어댑터)·클린 아키텍처는 도메인 핵심 로직을 중심에 두고, 외부 기술(UI·DB·메시징)을 포트(Port)와 어댑터(Adapter)로 분리하여 의존성이 항상 외부에서 내부 도메인으로 향하도록(의존성 역전) 구성하는 아키텍처이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 모듈 경계, 아키텍처 스타일, 설계 원칙, 패턴, 품질속성까지 설계 판단을 묻는 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 응집도/결합도, 아키텍처 뷰, MVC, MSA, DDD, SOLID, DI, 코드 품질 메트릭 |
| 2~4교시 확장 방향 | 설계 목표와 품질속성, 구성요소·패턴·원리, 대안 구조 비교, 적용 조건과 안티패턴 |


- 답안 포인트
  - `헥사고날·클린 아키텍처 (Hexagonal·Clean)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 도메인/유스케이스 핵심: 기술 비종속 비즈니스 로직(내부 영역)
- 포트(Port): 도메인이 정의한 인터페이스(인바운드·아웃바운드)
- 어댑터(Adapter): 포트 구현체(웹·DB·외부 API)
- 의존성 역전(DIP): 외부→내부 단방향 의존, 도메인은 외부 무인지
- 클린: 엔티티-유스케이스-인터페이스어댑터-프레임워크 동심원 계층

## Ⅲ. 비교·구조·지표 정리
```text
   [Web Adapter] → (Inbound Port)
                        │
                  [Domain Core]
                        │
   (Outbound Port) ← [DB Adapter]
   의존성 방향: 외부 → 내부(도메인), 도메인은 기술 무관
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 도메인 보호와 기술 교체 자유로 변경에 강한 구조 |
| 장점 | 테스트 용이(목 어댑터), 기술 독립, 도메인 순수성 |
| 한계 | 초기 구조·인터페이스 증가, 작은 시스템엔 과설계 |

## Ⅳ. 실무 적용 및 기술사 판단
- DDD 도메인 모델 보호, MSA 서비스 내부 구조의 표준 골격
- 계층형 아키텍처의 DB 종속 한계를 의존성 역전으로 해소

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 설계 목표와 품질속성 |
| 본론 1 | 구성요소·패턴·원리 |
| 본론 2 | 대안 구조 비교 |
| 본론 3 | 적용 조건과 안티패턴 |
| 결론 | 유지보수성과 확장성 결론 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
