## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 번다운 차트(Burndown Chart)는 스프린트·릴리스 기간 동안 남은 작업량(잔여 스토리포인트·시간)을 시간축에 그려, 이상선(Ideal Line)과 실적선을 비교함으로써 진척과 완료 가능성을 시각화하는 추적 도구이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 애자일 실행체계와 DevOps 기반 전달 자동화, 운영 피드백까지 연결하는 출제축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 스크럼, XP, 칸반, MVP, SAFe/LeSS, DevOps, IaC, SRE, GitOps |
| 2~4교시 확장 방향 | 민첩성 요구와 도입 배경, 역할·이벤트·파이프라인 구조, 전통 방식 대비 차이, 지표 기반 운영과 확장 전략 |


- 답안 포인트
  - `번다운 차트 (Burndown Chart)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- X축: 스프린트 일자(시간), Y축: 잔여 작업량(스토리포인트 또는 잔여 시간)
- 이상선: 시작 총량에서 종료일 0까지의 직선(목표 소진 속도)
- 실적선: 매일 갱신되는 실제 잔여량 곡선
- 해석: 실적선이 이상선 위 → 지연, 아래 → 선행, 평탄 구간 → 정체
- 변형: 잔여 대신 완료 누적을 표시하는 번업 차트(Burnup, 범위 변화도 표현)

## Ⅲ. 비교·구조·지표 정리
```text
잔여량
 100 *●
     | ●●  (실적선)
     |   *●●        * : 이상선
     |     *  ●●
   0 +----------*●---→ 일자
     D1   D3   D5  D7
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 잔여 작업과 완료 추세를 시각화해 일정 리스크 조기 감지 |
| 장점 | 직관적, 매일 갱신으로 즉각적 경보, 회고 근거 자료 |
| 한계 | 범위 변경 미반영(번업으로 보완), 추정 부정확 시 신뢰도 저하 |

## Ⅳ. 실무 적용 및 기술사 판단
- 스프린트 번다운(단기)·릴리스 번다운(중기)으로 계층적 진척 관리
- 속도(Velocity) 데이터와 결합해 차기 스프린트 용량 산정 근거로 활용

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 민첩성 요구와 도입 배경 |
| 본론 1 | 역할·이벤트·파이프라인 구조 |
| 본론 2 | 전통 방식 대비 차이 |
| 본론 3 | 지표 기반 운영과 확장 전략 |
| 결론 | 조직 문화 정착 포인트 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
