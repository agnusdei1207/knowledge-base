## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 전통 SW 개발 모델은 SDLC 단계를 수행하는 방식·순서를 규정한 절차 모델로, 프로젝트 특성(요구 명확성·위험·규모)에 따라 폭포수·V-모델·나선형·프로토타입을 선택한다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 생명주기, 프로세스 성숙도, 형상/품질/원가/일정/위험 관리의 통합 판단 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | SDLC, 프로세스 모델, CMMI, 형상관리, 원가·일정·리스크 |
| 2~4교시 확장 방향 | 도입 배경과 관리 필요성, 핵심 절차·지표·산출물, 성숙도/방법론 비교, 프로젝트 통제와 조직 적용 |


- 답안 포인트
  - `전통 SW 개발 모델 (폭포수·V-모델·나선형·프로토타입)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 폭포수(Waterfall): 단계 순차 진행, 이전 단계 완료 후 다음 진행
- V-모델: 개발 단계와 대응되는 시험 단계를 짝지어 검증·확인(V&V) 강화
- 나선형(Spiral): 계획→위험분석→개발→평가를 반복하는 위험분석 중심 모델
- 프로토타입(Prototype): 시제품을 만들어 요구를 조기 구체화·확정

## Ⅲ. 비교·구조·지표 정리
```text
Waterfall : 요구→설계→구현→시험 (직렬)
V-Model  : 요구↔인수시험, 설계↔통합시험 (대칭)
Spiral   : (계획→위험분석→개발→평가) 반복 나선
Prototype: 요구→시제품→평가→정제 반복
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 프로젝트 위험·요구 안정성에 맞는 개발 절차 선정 |
| 장점 | 폭포수(단순·관리용이), V(검증강화), 나선형(위험저감), 프로토타입(요구명확화) |
| 한계 | 폭포수(변경취약), V(경직), 나선형(고비용·전문성), 프로토타입(범위 팽창) |

## Ⅳ. 실무 적용 및 기술사 판단
- 요구 명확·대규모: 폭포수/V-모델, 고위험·대형: 나선형, 요구 불명확: 프로토타입
- 나선형의 위험분석 사상은 애자일 반복(Iteration)·위험관리와 연계

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 도입 배경과 관리 필요성 |
| 본론 1 | 핵심 절차·지표·산출물 |
| 본론 2 | 성숙도/방법론 비교 |
| 본론 3 | 프로젝트 통제와 조직 적용 |
| 결론 | 기대효과와 한계 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
