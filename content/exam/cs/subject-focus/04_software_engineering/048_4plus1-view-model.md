## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 4+1 뷰 모델(Kruchten)은 소프트웨어 아키텍처를 이해관계자별 관점에 따라 논리·프로세스·개발·물리 4개 뷰와 이를 통합하는 시나리오(유스케이스) 뷰로 기술하는 다중 관점 아키텍처 표현 기법이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 모듈 경계, 아키텍처 스타일, 설계 원칙, 패턴, 품질속성까지 설계 판단을 묻는 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 응집도/결합도, 아키텍처 뷰, MVC, MSA, DDD, SOLID, DI, 코드 품질 메트릭 |
| 2~4교시 확장 방향 | 설계 목표와 품질속성, 구성요소·패턴·원리, 대안 구조 비교, 적용 조건과 안티패턴 |


- 답안 포인트
  - `4+1 뷰 아키텍처 모델`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 논리(Logical) 뷰: 기능·클래스·객체 구조, 최종 사용자 관점 (클래스·시퀀스 다이어그램)
- 프로세스(Process) 뷰: 동시성·성능·프로세스/스레드, 시스템 통합자 관점
- 개발(Development) 뷰: 모듈·패키지·계층 구성, 개발자 관점 (컴포넌트 다이어그램)
- 물리(Physical) 뷰: 하드웨어 배치·노드 매핑, 시스템 엔지니어 관점 (배치 다이어그램)
- 시나리오(+1): 유스케이스로 4개 뷰를 검증·통합하는 중심 관점

## Ⅲ. 비교·구조·지표 정리
```text
        [시나리오/유스케이스(+1)]
        ┌─────┼─────┬─────┐
     논리뷰  프로세스뷰 개발뷰  물리뷰
    (기능)   (동시성)  (모듈)  (배치)
        └─────┴─────┴─────┘
        4개 뷰를 시나리오가 검증·통합
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 이해관계자별 관심사 분리로 아키텍처 완전 기술 |
| 장점 | 다관점 일관성 확보, 누락 방지, 의사소통 명확화 |
| 한계 | 문서 작성·동기화 부담, 소규모엔 과도할 수 있음 |

## Ⅳ. 실무 적용 및 기술사 판단
- ISO/IEC 42010 아키텍처 기술 표준의 뷰포인트 개념과 정합
- ATAM 품질속성 시나리오 평가 시 뷰별 트레이드오프 분석 기반 제공

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 설계 목표와 품질속성 |
| 본론 1 | 구성요소·패턴·원리 |
| 본론 2 | 대안 구조 비교 |
| 본론 3 | 적용 조건과 안티패턴 |
| 결론 | 유지보수성과 확장성 결론 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
