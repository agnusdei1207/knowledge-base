## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 코드형 인프라(Infrastructure as Code, IaC)는 서버·네트워크·스토리지 등 인프라를 코드(선언적 정의 파일)로 기술하고 버전 관리·자동 프로비저닝하여, 수작업 없이 일관되고 재현 가능한 환경을 구축하는 기법이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 애자일 실행체계와 DevOps 기반 전달 자동화, 운영 피드백까지 연결하는 출제축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 스크럼, XP, 칸반, MVP, SAFe/LeSS, DevOps, IaC, SRE, GitOps |
| 2~4교시 확장 방향 | 민첩성 요구와 도입 배경, 역할·이벤트·파이프라인 구조, 전통 방식 대비 차이, 지표 기반 운영과 확장 전략 |


- 답안 포인트
  - `코드형 인프라 (IaC)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 선언형(Declarative): 원하는 최종 상태를 기술, 도구가 차이를 계산해 수렴(Terraform)
- 명령형(Imperative): 수행 절차를 순차 기술(Ansible 플레이북 일부)
- 멱등성(Idempotency): 동일 코드를 반복 적용해도 결과 상태가 동일
- 버전관리·코드리뷰: Git으로 인프라 변경 이력·승인 관리
- 도구: Terraform(프로비저닝), Ansible(구성관리), 상태파일(State)·드리프트 탐지

## Ⅲ. 비교·구조·지표 정리
```text
 코드(.tf/.yml) ─Git─> Plan(차이 계산) ──Apply──> 클라우드 인프라
      │                     │                        │
      └── 코드리뷰          └ 멱등성 보장        드리프트 탐지/수렴
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 인프라를 코드로 자동화해 일관성·재현성·속도 확보 |
| 장점 | 환경 표준화, 변경 추적·롤백, 휴먼에러 감소, 대규모 확장 |
| 한계 | 상태관리·도구 학습곡선, 잘못된 코드의 광범위 영향, 비밀정보 관리 |

## Ⅳ. 실무 적용 및 기술사 판단
- CI/CD 파이프라인에 통합해 GitOps의 선언적 인프라 토대 제공
- 멀티클라우드·재해복구(DR) 환경의 신속·반복 가능한 프로비저닝

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 민첩성 요구와 도입 배경 |
| 본론 1 | 역할·이벤트·파이프라인 구조 |
| 본론 2 | 전통 방식 대비 차이 |
| 본론 3 | 지표 기반 운영과 확장 전략 |
| 결론 | 조직 문화 정착 포인트 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
