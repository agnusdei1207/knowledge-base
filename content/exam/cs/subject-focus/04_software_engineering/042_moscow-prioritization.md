## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 요구사항을 Must·Should·Could·Won't 4범주로 분류하여 한정된 자원 내 우선순위와 범위를 합의하는 기법.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 요구 도출부터 우선순위, 명세, 추적성까지 품질 좋은 요구를 만드는 분석 출제축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 요구공학, SRS, RTM, 유스케이스, DFD, QFD, MoSCoW, 스토리맵 |
| 2~4교시 확장 방향 | 문제 상황과 이해관계자 관점, 도출·분석·명세 절차, 도구/기법 비교, 변경 통제와 검증 적용 |


- 답안 포인트
  - `MoSCoW 우선순위 기법`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- Must have: 필수, 없으면 실패(반드시 구현)
- Should have: 중요하나 대안 존재(가능하면 구현)
- Could have: 있으면 좋음(여유 시 구현)
- Won't have(this time): 이번 범위 제외(차기 검토)
- 타임박스: 고정 일정 내 Must 우선 배분

## Ⅲ. 비교·구조·지표 정리
```text
요구목록 → 분류
  Must  ████ 필수
  Should ███ 중요
  Could  ██  선택
  Won't  ─   이번 제외
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 자원 제약 하 범위·우선순위 합의 |
| 장점 | 직관적, 이해관계자 소통 용이 |
| 한계 | 분류 주관성, Must 과다 시 효과 저하 |

## Ⅳ. 실무 적용 및 기술사 판단
- DSDM·애자일에서 타임박스 범위 협상에 활용
- Kano 모델·QFD와 결합해 정량 근거 보강
- Won't 명시로 범위크리프 예방 효과

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 문제 상황과 이해관계자 관점 |
| 본론 1 | 도출·분석·명세 절차 |
| 본론 2 | 도구/기법 비교 |
| 본론 3 | 변경 통제와 검증 적용 |
| 결론 | 실패 예방 효과 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
