## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 칸반(Kanban)은 도요타 생산방식에서 유래한 시각적 작업관리 기법으로, 작업을 보드에 시각화하고 진행 중 작업(WIP)을 제한하여 흐름(Flow)을 최적화하는 풀(Pull) 기반 방법론이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 애자일 실행체계와 DevOps 기반 전달 자동화, 운영 피드백까지 연결하는 출제축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 스크럼, XP, 칸반, MVP, SAFe/LeSS, DevOps, IaC, SRE, GitOps |
| 2~4교시 확장 방향 | 민첩성 요구와 도입 배경, 역할·이벤트·파이프라인 구조, 전통 방식 대비 차이, 지표 기반 운영과 확장 전략 |


- 답안 포인트
  - `칸반 (Kanban)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 시각화: 칸반 보드의 단계별 열(To Do → Doing → Done)과 작업 카드
- WIP 제한(Work In Progress Limit): 단계별 동시 작업 수 상한으로 병목·과부하 통제
- 흐름 관리: 카드의 리드타임(Lead Time)·사이클타임(Cycle Time) 측정·개선
- 풀 시스템: 후공정이 여유 생길 때 작업을 당겨와 처리(밀어내기 금지)
- 명시적 정책·지속적 개선(Kaizen), 누적흐름도(CFD)로 병목 분석

## Ⅲ. 비교·구조·지표 정리
```text
 Backlog │ To Do(3) │ Doing(2) │ Review(2) │ Done
   ●●●●  │  ●●       │  ●●←WIP한 │  ●        │ ●●●
         │           │  계로 Pull│           │
   ←──────── 흐름(Flow), 리드타임 측정 ────────→
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 작업 흐름 가시화와 WIP 제한으로 처리량·예측성 향상 |
| 장점 | 점진적 도입(기존 프로세스 유지), 병목 즉시 노출, 유연한 우선순위 |
| 한계 | 타임박스·역할 부재로 규율 약화 가능, 추정·일정 약속에 부적합 |

## Ⅳ. 실무 적용 및 기술사 판단
- 스크럼과 결합한 스크럼반(Scrumban)으로 반복+흐름 장점 결합
- 운영·유지보수·DevOps 작업 흐름 관리에 적합, CFD로 SLA 예측

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 민첩성 요구와 도입 배경 |
| 본론 1 | 역할·이벤트·파이프라인 구조 |
| 본론 2 | 전통 방식 대비 차이 |
| 본론 3 | 지표 기반 운영과 확장 전략 |
| 결론 | 조직 문화 정착 포인트 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
