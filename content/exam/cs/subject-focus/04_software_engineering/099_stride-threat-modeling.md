## Ⅰ. 출제 관점 및 1교시 답안 포인트
> STRIDE는 마이크로소프트가 제시한 위협 모델링 기법으로, 시스템의 잠재 위협을 6개 범주로 분류·식별하여 설계 단계에서 보안 대책을 수립하는 방법론이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 개발생명주기 보안, 위협 모델링, 오픈소스 공급망 통제까지 예방 중심 보안 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | Secure SDLC, STRIDE, SCA, SBOM, Secret Management |
| 2~4교시 확장 방향 | 보안 좌측 이동 배경, 통제 포인트와 자동화 체계, 기존 사후 점검 대비 차이, 규제·감사·운영 적용 |


- 답안 포인트
  - `STRIDE 위협 모델링 (STRIDE)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- Spoofing(위장): 신원 도용 → 인증(MFA)으로 대응
- Tampering(변조): 데이터 무단 변경 → 무결성(해시·서명)
- Repudiation(부인): 행위 부인 → 감사로그·전자서명
- Information Disclosure(정보 노출): 기밀 유출 → 암호화·접근통제
- Denial of Service(서비스 거부): 가용성 침해 → Rate Limit·이중화
- Elevation of Privilege(권한 상승): 무단 권한 획득 → 최소권한·인가

## Ⅲ. 비교·구조·지표 정리
```text
DFD 작성 → 신뢰경계 식별 → 각 요소에 STRIDE 매핑
 S(인증) T(무결성) R(부인방지)
 I(기밀성) D(가용성) E(인가)
   → 위협 도출 → 완화책 → 검증
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 설계 단계 체계적 위협 식별·대응 |
| 장점 | 구조적 분류·CIA+인증/인가/부인방지 전 범위 포괄 |
| 한계 | 정량적 위험 평가 부재·DFD 의존·전문성 필요 |

## Ⅳ. 실무 적용 및 기술사 판단
- 시큐어 SDLC 설계 단계의 핵심 위협 모델링 도구
- DREAD(위험 정량화)·Attack Tree와 결합해 우선순위 산정
- STRIDE 6범주는 보안 속성(CIA·인증·인가·부인방지)과 1:1 대응

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 보안 좌측 이동 배경 |
| 본론 1 | 통제 포인트와 자동화 체계 |
| 본론 2 | 기존 사후 점검 대비 차이 |
| 본론 3 | 규제·감사·운영 적용 |
| 결론 | 리스크 저감 효과 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
