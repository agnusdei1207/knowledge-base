## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 모듈러 모놀리스는 단일 배포 단위(모놀리스)를 유지하되, 내부를 명확한 경계와 낮은 결합도의 독립 모듈로 분할해 MSA의 모듈성과 모놀리스의 단순성을 절충한 아키텍처이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 컨테이너, 서비스 메시, 분산 트랜잭션, 관측성과 복원력을 포함한 운영형 아키텍처 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | Kubernetes, Service Mesh, API Gateway/BFF, Saga, CQRS, Serverless, MSA 전환 |
| 2~4교시 확장 방향 | 클라우드 네이티브 전환 배경, 런타임 구조와 통신 메커니즘, 모놀리스/분산구조 비교, 운영 복잡도와 대응 패턴 |


- 답안 포인트
  - `모듈러 모놀리스 (Modular Monolith)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 모듈 경계: 도메인(DDD Bounded Context) 기준 분리
- 인터페이스 통신: 모듈 간 공개 API/이벤트로만 상호작용
- 단일 배포·단일 프로세스: 인메모리 호출, 분산 복잡성 배제
- 캡슐화: 내부 구현·DB 스키마 모듈 내 은닉
- 점진적 분해: 필요 모듈을 추후 마이크로서비스로 추출 용이

## Ⅲ. 비교·구조·지표 정리
```text
┌──────── Single Deployment ────────┐
│ [모듈 주문] ↔API↔ [모듈 결제]      │
│ [모듈 배송] ↔API↔ [모듈 회원]      │
│   각 모듈 = 독립 경계·인메모리 호출 │
└────────────────────────────────────┘
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 모듈성 확보+분산 복잡성 회피 |
| 장점 | 단순 배포·트랜잭션 일관성·낮은 운영비·디버깅 용이 |
| 한계 | 독립 배포·기술 이질성·개별 확장 불가 |

## Ⅳ. 실무 적용 및 기술사 판단
- "MSA 우선" 대안: 초기엔 모듈러 모놀리스, 필요 시 점진 분리
- 경계가 명확하면 스트랭글러 패턴으로 MSA 전환 비용 최소화
- 소규모·중규모 팀에서 MSA 과잉 복잡성 회피 전략

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 클라우드 네이티브 전환 배경 |
| 본론 1 | 런타임 구조와 통신 메커니즘 |
| 본론 2 | 모놀리스/분산구조 비교 |
| 본론 3 | 운영 복잡도와 대응 패턴 |
| 결론 | 확장성·회복탄력성 결론 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
