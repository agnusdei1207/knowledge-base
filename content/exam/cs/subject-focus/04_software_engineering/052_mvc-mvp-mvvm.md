## Ⅰ. 출제 관점 및 1교시 답안 포인트
> MVC·MVP·MVVM은 표현(UI) 계층을 모델(Model)·뷰(View)와 중재 객체로 분리해 UI 로직과 비즈니스 로직의 결합을 낮추는 표현 계층 분리 패턴 계열이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 모듈 경계, 아키텍처 스타일, 설계 원칙, 패턴, 품질속성까지 설계 판단을 묻는 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 응집도/결합도, 아키텍처 뷰, MVC, MSA, DDD, SOLID, DI, 코드 품질 메트릭 |
| 2~4교시 확장 방향 | 설계 목표와 품질속성, 구성요소·패턴·원리, 대안 구조 비교, 적용 조건과 안티패턴 |


- 답안 포인트
  - `MVC·MVP·MVVM`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- MVC(Model-View-Controller): 컨트롤러가 입력 받아 모델 갱신, 뷰가 모델 관찰
- MVP(Model-View-Presenter): 프레젠터가 뷰-모델 중재, 뷰는 수동적(Passive View)
- MVVM(Model-View-ViewModel): 뷰모델이 데이터 바인딩으로 뷰 자동 동기화
- 공통 원리: 관심사 분리, 모델은 UI 비종속
- 결합 방향: MVC(뷰↔모델 인지), MVP(1:1 인터페이스), MVVM(바인딩으로 결합 최소)

## Ⅲ. 비교·구조·지표 정리
```text
MVC : View → Controller → Model → View(관찰)
MVP : View ↔ Presenter ↔ Model   (View 수동)
MVVM: View ⇄(데이터바인딩) ViewModel → Model
```

| 구분 | 내용 |
|:---|:---|
| 목적 | UI와 로직 분리로 테스트성·유지보수성 향상 |
| 장점 | 뷰 교체 용이, 모델 재사용, MVVM은 바인딩으로 코드 감소 |
| 한계 | 패턴 오버헤드, MVVM은 바인딩 디버깅·학습 곤란 |

## Ⅳ. 실무 적용 및 기술사 판단
- MVC: Spring/Web, MVP: Android 초기, MVVM: WPF·Vue·React(상태관리)
- 표현계층 복잡도·바인딩 지원 여부에 따라 패턴 선택, 클린 아키텍처와 결합

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시
