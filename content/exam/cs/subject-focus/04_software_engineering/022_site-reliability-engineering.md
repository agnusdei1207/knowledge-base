## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 사이트 신뢰성 엔지니어링(Site Reliability Engineering, SRE)은 구글이 정립한 운영 방식으로, 소프트웨어 엔지니어링 기법을 운영에 적용해 서비스 신뢰성을 정량 목표(SLO)로 관리하고 에러 예산으로 속도와 안정성의 균형을 맞추는 분야이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 애자일 실행체계와 DevOps 기반 전달 자동화, 운영 피드백까지 연결하는 출제축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 스크럼, XP, 칸반, MVP, SAFe/LeSS, DevOps, IaC, SRE, GitOps |
| 2~4교시 확장 방향 | 민첩성 요구와 도입 배경, 역할·이벤트·파이프라인 구조, 전통 방식 대비 차이, 지표 기반 운영과 확장 전략 |


- 답안 포인트
  - `사이트 신뢰성 엔지니어링 (SRE)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- SLI(Service Level Indicator): 가용성·지연 등 신뢰성 측정 지표
- SLO(Objective): SLI의 목표치(예 99.9%), SLA는 고객과의 계약·보상 약정
- 에러 예산(Error Budget): 1−SLO, 허용 장애량. 소진 시 신규 배포 동결·안정화 집중
- Toil(반복 수작업): 자동화 대상, SRE 업무의 상한(예 50%) 관리
- 비난 없는 사후분석(Postmortem), 점진적 변경, 모니터링·온콜

## Ⅲ. 비교·구조·지표 정리
```text
 SLI 측정 ─> SLO 목표 ─> Error Budget(1-SLO)
                              │
        남음 → 빠른 배포      소진 → 배포 동결·신뢰성 작업
                              │
            Toil 자동화 ← Postmortem 피드백
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 신뢰성을 정량 목표로 관리해 개발 속도와 안정성 균형 |
| 장점 | 객관적 의사결정(에러예산), Toil 감소, 데이터 기반 운영 |
| 한계 | SLI/SLO 정의 난이도, 조직 문화·자동화 역량 요구 |

## Ⅳ. 실무 적용 및 기술사 판단
- SLA(계약)·SLO(목표)·SLI(지표) 3계층으로 서비스 품질 관리체계 수립
- DevOps의 측정(M)을 구체화, 옵저버빌리티·온콜 체계와 연계

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 민첩성 요구와 도입 배경 |
| 본론 1 | 역할·이벤트·파이프라인 구조 |
| 본론 2 | 전통 방식 대비 차이 |
| 본론 3 | 지표 기반 운영과 확장 전략 |
| 결론 | 조직 문화 정착 포인트 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
