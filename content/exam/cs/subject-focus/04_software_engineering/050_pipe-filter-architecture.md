## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 파이프-필터 아키텍처는 독립적인 처리 단위인 필터(Filter)가 데이터를 변환하고, 필터 간 데이터 흐름을 파이프(Pipe)가 연결하여 단계적 스트림 처리를 구성하는 데이터 흐름 중심 아키텍처 패턴이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 모듈 경계, 아키텍처 스타일, 설계 원칙, 패턴, 품질속성까지 설계 판단을 묻는 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 응집도/결합도, 아키텍처 뷰, MVC, MSA, DDD, SOLID, DI, 코드 품질 메트릭 |
| 2~4교시 확장 방향 | 설계 목표와 품질속성, 구성요소·패턴·원리, 대안 구조 비교, 적용 조건과 안티패턴 |


- 답안 포인트
  - `파이프-필터 아키텍처 (Pipe-Filter)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 필터(Filter): 입력 데이터를 변환·가공하는 독립 처리 컴포넌트
- 파이프(Pipe): 필터 간 데이터 전달 통로(버퍼·스트림)
- 데이터 소스(Source)와 싱크(Sink): 흐름의 시작·끝
- 필터 간 무상태·독립성 → 재구성·병렬화 용이
- 푸시/풀 방식 데이터 전달

## Ⅲ. 비교·구조·지표 정리
```text
[Source] → [Filter1] → pipe → [Filter2] → pipe → [Filter3] → [Sink]
            (변환)            (필터링)          (집계)
   각 필터 독립·교체 가능, 순차 스트림 처리
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 단계적 데이터 변환의 모듈화·재사용 |
| 장점 | 필터 재배치·재사용, 병렬·동시 처리 용이 |
| 한계 | 상태 공유 어려움, 대화형 처리 부적합, 파이프 오버헤드 |

## Ⅳ. 실무 적용 및 기술사 판단
- 컴파일러, ETL, 스트림 처리(Kafka Streams), Unix 파이프라인의 원형
- CI/CD 파이프라인·이미지 처리 등 배치형 변환 워크플로 설계에 적용

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 설계 목표와 품질속성 |
| 본론 1 | 구성요소·패턴·원리 |
| 본론 2 | 대안 구조 비교 |
| 본론 3 | 적용 조건과 안티패턴 |
| 결론 | 유지보수성과 확장성 결론 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
