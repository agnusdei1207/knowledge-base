## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 관점지향 프로그래밍(AOP, Aspect-Oriented Programming)은 로깅·트랜잭션·보안처럼 여러 모듈에 흩어진 횡단관심사(Cross-cutting Concern)를 분리해 모듈화하는 패러다임이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 모듈 경계, 아키텍처 스타일, 설계 원칙, 패턴, 품질속성까지 설계 판단을 묻는 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 응집도/결합도, 아키텍처 뷰, MVC, MSA, DDD, SOLID, DI, 코드 품질 메트릭 |
| 2~4교시 확장 방향 | 설계 목표와 품질속성, 구성요소·패턴·원리, 대안 구조 비교, 적용 조건과 안티패턴 |


- 답안 포인트
  - `관점지향 프로그래밍 (AOP)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- Aspect: 횡단관심사를 모듈화한 단위(Advice+Pointcut)
- Advice: 실제 실행되는 부가 기능(Before·After·Around)
- Pointcut: Advice를 적용할 지점을 선별하는 표현식
- JoinPoint: Advice가 적용될 수 있는 프로그램 실행 지점(메서드 호출 등)
- Weaving: 핵심 로직에 Aspect를 결합하는 과정(컴파일·로드·런타임)

## Ⅲ. 비교·구조·지표 정리
```text
핵심 로직(메서드 호출) = JoinPoint
        │ Pointcut 매칭
        ▼
   ┌─ Before Advice
   ├─ [핵심 비즈니스 실행]
   └─ After/Around Advice  ← Weaving으로 결합
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 핵심관심사와 횡단관심사 분리로 모듈성·재사용 향상 |
| 장점 | 코드 중복 제거, 비즈니스 로직 순수성 유지, 일괄 변경 용이 |
| 한계 | 실행 흐름 추적 난해, 과용 시 디버깅·이해도 저하 |

## Ⅳ. 실무 적용 및 기술사 판단
- Spring AOP는 프록시 기반으로 트랜잭션·로깅·보안에 적용
- 클린코드의 SRP(단일책임원칙)를 횡단관심사 측면에서 보완
- OOP의 한계(횡단관심사 산재)를 보완하는 상호보완 패러다임

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 설계 목표와 품질속성 |
| 본론 1 | 구성요소·패턴·원리 |
| 본론 2 | 대안 구조 비교 |
| 본론 3 | 적용 조건과 안티패턴 |
| 결론 | 유지보수성과 확장성 결론 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
