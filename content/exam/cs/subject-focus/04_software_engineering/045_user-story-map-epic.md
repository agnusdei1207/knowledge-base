## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 유저스토리는 사용자 관점의 기능 요구를 간결히 표현한 단위이며, 에픽은 큰 스토리 묶음, 스토리 맵은 사용자 활동 흐름을 2차원으로 배치해 릴리스 범위를 시각화한 기법.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 요구 도출부터 우선순위, 명세, 추적성까지 품질 좋은 요구를 만드는 분석 출제축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 요구공학, SRS, RTM, 유스케이스, DFD, QFD, MoSCoW, 스토리맵 |
| 2~4교시 확장 방향 | 문제 상황과 이해관계자 관점, 도출·분석·명세 절차, 도구/기법 비교, 변경 통제와 검증 적용 |


- 답안 포인트
  - `유저스토리 맵·에픽 (User Story Map·Epic)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 유저스토리: "As a <역할>, I want <기능>, so that <가치>" 형식
- 에픽(Epic): 여러 스토리로 분할되는 대규모 요구 단위
- 백본(가로축): 사용자 활동·태스크 순서 흐름
- 우선순위(세로축): 위에서 아래로 중요도·릴리스 배치
- INVEST 원칙·수용기준(Acceptance Criteria)으로 품질 확보

## Ⅲ. 비교·구조·지표 정리
```text
활동:  [가입]→[탐색]→[구매]→[배송]   (백본·가로)
릴1:   회원가입  검색   장바구니 주문조회
릴2:   SNS가입  필터   쿠폰결제 알림
(세로=우선순위/릴리스)
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 사용자 흐름 기반 범위·릴리스 계획 시각화 |
| 장점 | 전체 그림 공유, 점증 릴리스 계획 용이 |
| 한계 | 비기능·상세 명세 부족, 대규모 시 관리 복잡 |

## Ⅳ. 실무 적용 및 기술사 판단
- 에픽→스토리→태스크로 점진 분해(Backlog Refinement)
- MoSCoW로 세로축 우선순위 결정, 릴리스 슬라이스 도출
- 애자일 요구관리에서 SRS를 대체·보완하는 경량 산출물

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 문제 상황과 이해관계자 관점 |
| 본론 1 | 도출·분석·명세 절차 |
| 본론 2 | 도구/기법 비교 |
| 본론 3 | 변경 통제와 검증 적용 |
| 결론 | 실패 예방 효과 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
