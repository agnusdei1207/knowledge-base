## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 웹어셈블리(WebAssembly, WASM)는 브라우저·서버에서 네이티브에 근접한 속도로 실행되는 이식성 높은 저수준 바이너리 명령 포맷으로, 다양한 언어를 컴파일해 샌드박스에서 실행한다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 언어/runtime 혁신과 AI 활용 공학을 기술사 관점에서 실효성과 제약으로 정리하는 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | Virtual Threads, WebAssembly, AI4SE |
| 2~4교시 확장 방향 | 등장 배경과 기술 변화, 핵심 동작 원리, 기존 방식 대비 차이, 적용 시 리스크와 생산성 영향 |


- 답안 포인트
  - `웹어셈블리 (WebAssembly·WASM)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 바이너리 포맷: 스택 기반 가상머신용 컴팩트 명령어(.wasm)
- 다언어 컴파일: C/C++·Rust·Go 등을 WASM으로 컴파일
- 샌드박스: 메모리 격리·기능 기반 보안으로 안전 실행
- WASI(WebAssembly System Interface): 브라우저 밖 시스템 호출 표준
- 이식성: OS·아키텍처 독립, "한 번 빌드 어디서나 실행"

## Ⅲ. 비교·구조·지표 정리
```text
Rust/C++/Go → (컴파일) → .wasm 바이너리
   → 런타임(브라우저 JS엔진 / 서버 Wasmtime)
   → 샌드박스 실행 (메모리 격리)
   서버 측: WASI로 파일/네트워크 접근
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 고성능·이식성·안전한 코드 실행 |
| 장점 | 네이티브급 속도·다언어·강한 격리·빠른 콜드스타트 |
| 한계 | DOM 직접접근 제약·생태계 미성숙·디버깅 난이도 |

## Ⅳ. 실무 적용 및 기술사 판단
- 서버리스 엣지: 컨테이너 대비 초경량·밀리초 콜드스타트로 부상
- 플러그인·멀티테넌트 격리 실행 환경(Envoy WASM 필터)
- 컨테이너 보완재로 엣지 컴퓨팅·CDN 함수 실행에 적용

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시
