## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 클린코드(Clean Code)는 읽기 쉽고 의도가 명확하며 변경이 용이한 코드이며, 코드스멜(Code Smell)은 잠재적 결함·설계 악취를 시사하는 표면적 징후로 리팩토링 대상이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 모듈 경계, 아키텍처 스타일, 설계 원칙, 패턴, 품질속성까지 설계 판단을 묻는 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 응집도/결합도, 아키텍처 뷰, MVC, MSA, DDD, SOLID, DI, 코드 품질 메트릭 |
| 2~4교시 확장 방향 | 설계 목표와 품질속성, 구성요소·패턴·원리, 대안 구조 비교, 적용 조건과 안티패턴 |


- 답안 포인트
  - `클린코드·코드스멜 (Clean Code·Code Smell)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 가독성: 의미 있는 네이밍, 작은 함수, 명확한 흐름
- 단순성(KISS)·중복제거(DRY): 불필요 복잡성·중복 제거
- 대표 코드스멜: 중복코드, 긴 메서드, 큰 클래스, 과도한 매개변수
- 결합/응집: 낮은 결합도·높은 응집도 지향
- 리팩토링: 외부 동작 유지하며 내부 구조 개선

## Ⅲ. 비교·구조·지표 정리
```text
코드 작성 → 코드스멜 탐지(정적분석)
       │
   리팩토링(메서드 추출·이름변경)
       │
   테스트 통과 검증 → 클린코드 유지
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 유지보수성·가독성 향상으로 기술부채 최소화 |
| 장점 | 결함 감소, 협업 효율, 변경 용이성 확보 |
| 한계 | 정량 기준 모호, 단기 생산성 저하, 과도한 추상화 위험 |

## Ⅳ. 실무 적용 및 기술사 판단
- SonarQube 등 정적분석 도구로 코드스멜 자동 탐지·관리
- 리팩토링은 TDD의 Refactor 단계와 결합해 안전하게 수행
- 기술부채(Technical Debt) 관리 지표로 코드 품질 정량화

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 설계 목표와 품질속성 |
| 본론 1 | 구성요소·패턴·원리 |
| 본론 2 | 대안 구조 비교 |
| 본론 3 | 적용 조건과 안티패턴 |
| 결론 | 유지보수성과 확장성 결론 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
