## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 계층형 아키텍처는 시스템을 책임에 따라 표현·업무·영속 등 수평 계층으로 분할하고, 상위 계층이 하위 계층에만 의존하도록 구성하는 관심사 분리 기반 아키텍처 패턴이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 모듈 경계, 아키텍처 스타일, 설계 원칙, 패턴, 품질속성까지 설계 판단을 묻는 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 응집도/결합도, 아키텍처 뷰, MVC, MSA, DDD, SOLID, DI, 코드 품질 메트릭 |
| 2~4교시 확장 방향 | 설계 목표와 품질속성, 구성요소·패턴·원리, 대안 구조 비교, 적용 조건과 안티패턴 |


- 답안 포인트
  - `계층형 아키텍처 (Layered Architecture)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 표현(Presentation) 계층: UI·사용자 입출력 처리
- 업무(Business) 계층: 도메인 로직·트랜잭션 처리
- 영속(Persistence) 계층: 데이터 접근(DAO/Repository)
- 데이터베이스(Database) 계층: 저장소
- 폐쇄 계층(Closed Layer) 원칙: 인접 하위 계층만 호출, 계층 격리(Layer Isolation)

## Ⅲ. 비교·구조·지표 정리
```text
[Presentation]  UI
      │
[Business]      도메인 로직
      │
[Persistence]   데이터 접근
      │
[Database]      저장소
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 관심사 분리로 유지보수성·표준화된 구조 확보 |
| 장점 | 이해 용이, 계층별 교체·테스트, 역할 분담 명확 |
| 한계 | 계층 관통 변경 시 전 계층 수정(Sinkhole), 성능 오버헤드 |

## Ⅳ. 실무 적용 및 기술사 판단
- 전통적 엔터프라이즈(Spring MVC) 표준 구조, 모놀리식 기본 골격
- 헥사고날·클린 아키텍처는 의존성 역전으로 계층형의 DB 종속 한계를 보완

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 설계 목표와 품질속성 |
| 본론 1 | 구성요소·패턴·원리 |
| 본론 2 | 대안 구조 비교 |
| 본론 3 | 적용 조건과 안티패턴 |
| 결론 | 유지보수성과 확장성 결론 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
