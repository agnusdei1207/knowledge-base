## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 데브섹옵스(DevSecOps)는 DevOps 파이프라인 전 단계에 보안(Security)을 내재화하여, 보안을 마지막 관문이 아닌 설계·개발 초기부터 자동화·지속 검증하는 보안 좌측 이동(Shift-Left) 문화·실천이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 애자일 실행체계와 DevOps 기반 전달 자동화, 운영 피드백까지 연결하는 출제축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 스크럼, XP, 칸반, MVP, SAFe/LeSS, DevOps, IaC, SRE, GitOps |
| 2~4교시 확장 방향 | 민첩성 요구와 도입 배경, 역할·이벤트·파이프라인 구조, 전통 방식 대비 차이, 지표 기반 운영과 확장 전략 |


- 답안 포인트
  - `데브섹옵스 (DevSecOps)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- Shift-Left: 보안 검증을 개발 초기·코드 단계로 앞당겨 결함 비용 절감
- 자동 보안 테스트: SAST(정적), DAST(동적), SCA(오픈소스 의존성), IaC 스캔
- 시크릿 관리·정책 코드화(Policy as Code), 컨테이너 이미지 취약점 스캔
- 보안 게이트: 파이프라인 내 품질·보안 임계치 미달 시 차단
- 모두의 보안 책임(Security as Code)·지속적 모니터링·위협 모델링

## Ⅲ. 비교·구조·지표 정리
```text
Plan ─위협모델링→ Code ─SAST/Secret→ Build ─SCA→ Test ─DAST→
                                                         │
   Deploy ─이미지스캔/IaC스캔→ Operate ─런타임보안·모니터링→ 피드백
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 보안을 파이프라인에 내재화해 빠른 인도와 보안을 양립 |
| 장점 | 취약점 조기·저비용 제거, 자동·반복 검증, 규제 대응 |
| 한계 | 도구 통합·오탐(False Positive) 관리, 보안 역량 내재화 필요 |

## Ⅳ. 실무 적용 및 기술사 판단
- CI/CD에 SAST/DAST/SCA 게이트 삽입, 컴플라이언스(개인정보·금융) 자동 증빙
- SBOM·공급망 보안과 연계, SRE·옵저버빌리티로 런타임 위협 탐지

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 민첩성 요구와 도입 배경 |
| 본론 1 | 역할·이벤트·파이프라인 구조 |
| 본론 2 | 전통 방식 대비 차이 |
| 본론 3 | 지표 기반 운영과 확장 전략 |
| 결론 | 조직 문화 정착 포인트 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
