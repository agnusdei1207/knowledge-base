## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 품질기능전개(QFD, Quality Function Deployment)는 고객 요구(VOC)를 기술적 설계특성으로 체계적으로 변환·전개하는 품질기법으로, 핵심 도구는 품질의 집(HoQ).

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 요구 도출부터 우선순위, 명세, 추적성까지 품질 좋은 요구를 만드는 분석 출제축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 요구공학, SRS, RTM, 유스케이스, DFD, QFD, MoSCoW, 스토리맵 |
| 2~4교시 확장 방향 | 문제 상황과 이해관계자 관점, 도출·분석·명세 절차, 도구/기법 비교, 변경 통제와 검증 적용 |


- 답안 포인트
  - `품질기능전개 (QFD)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 고객요구(WHAT): 고객의 소리(VOC)와 중요도
- 기술특성(HOW): 요구를 충족할 설계특성
- 관계행렬: WHAT-HOW 상관강도
- 지붕(상관행렬): 기술특성 간 상호 상관
- 경쟁평가·목표값: 벤치마킹과 설계 목표 설정

## Ⅲ. 비교·구조·지표 정리
```text
        ╱지붕(기술간 상관)╲
        ┌── 기술특성(HOW) ──┐
고객요구│  관계행렬(상관강도) │경쟁
(WHAT)  └────────────────────┘평가
        목표값 / 중요도 가중치
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 고객요구를 설계특성으로 추적가능하게 전개 |
| 장점 | VOC 반영 강화, 부서간 소통·합의 도구 |
| 한계 | 작성 복잡·시간 소요, 정성 평가 주관성 |

## Ⅳ. 실무 적용 및 기술사 판단
- HoQ 출력이 다음 단계(부품·공정) HoQ 입력으로 4단계 전개
- Kano·MoSCoW 결과를 WHAT 중요도에 반영
- 요구사항-설계 추적성(RTM) 확보 수단으로 연계

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 문제 상황과 이해관계자 관점 |
| 본론 1 | 도출·분석·명세 절차 |
| 본론 2 | 도구/기법 비교 |
| 본론 3 | 변경 통제와 검증 적용 |
| 결론 | 실패 예방 효과 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
