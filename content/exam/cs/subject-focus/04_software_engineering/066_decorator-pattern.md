## Ⅰ. 출제 관점 및 1교시 답안 포인트
> GoF(Gang of Four) 구조(Structural) 패턴으로, 객체에 동적으로 책임(기능)을 추가하며, 서브클래싱 대신 래핑(Wrapping) 합성을 통해 기능을 유연하게 확장하는 패턴.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 모듈 경계, 아키텍처 스타일, 설계 원칙, 패턴, 품질속성까지 설계 판단을 묻는 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 응집도/결합도, 아키텍처 뷰, MVC, MSA, DDD, SOLID, DI, 코드 품질 메트릭 |
| 2~4교시 확장 방향 | 설계 목표와 품질속성, 구성요소·패턴·원리, 대안 구조 비교, 적용 조건과 안티패턴 |


- 답안 포인트
  - `데코레이터 패턴 (Decorator)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- **Component**: 핵심 기능과 데코레이터가 공유하는 공통 인터페이스
- **ConcreteComponent**: 기본 기능을 가진 실제 객체
- **Decorator**: Component를 참조·구현하는 추상 래퍼
- **ConcreteDecorator**: 호출 전후로 부가 기능 추가 후 위임(delegation)
- **원리**: 동일 인터페이스로 재귀적 중첩 → 기능 조합을 런타임에 구성

## Ⅲ. 비교·구조·지표 정리
```text
Client → DecoratorB( DecoratorA( ConcreteComponent ) )
          └부가기능┘  └부가기능┘   └핵심기능┘
   operation() 호출 → 각 래퍼가 전후 처리 후 안쪽으로 위임
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 상속 없이 동적 기능 추가, 기능 조합 유연화 |
| 장점 | 단일책임 분리, 조합 폭발 방지, 런타임 확장 |
| 한계 | 래퍼 다층 중첩 시 디버깅·식별 곤란, 잔객체 증가 |

## Ⅳ. 실무 적용 및 기술사 판단
- Java I/O 스트림(BufferedInputStream 등), UI 위젯 장식에 적용
- 상속의 정적 확장 한계 보완 → 클래스 폭발(class explosion) 회피
- Proxy와 비교: Decorator는 기능 추가, Proxy는 접근 제어 목적

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 설계 목표와 품질속성 |
| 본론 1 | 구성요소·패턴·원리 |
| 본론 2 | 대안 구조 비교 |
| 본론 3 | 적용 조건과 안티패턴 |
| 결론 | 유지보수성과 확장성 결론 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
