## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 2단계 커밋(2PC, Two-Phase Commit)은 분산 트랜잭션의 원자성을 위해 코디네이터가 준비(Prepare)·커밋(Commit) 2단계로 모든 참여자의 합의를 도출하는 프로토콜이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 컨테이너, 서비스 메시, 분산 트랜잭션, 관측성과 복원력을 포함한 운영형 아키텍처 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | Kubernetes, Service Mesh, API Gateway/BFF, Saga, CQRS, Serverless, MSA 전환 |
| 2~4교시 확장 방향 | 클라우드 네이티브 전환 배경, 런타임 구조와 통신 메커니즘, 모놀리스/분산구조 비교, 운영 복잡도와 대응 패턴 |


- 답안 포인트
  - `2단계 커밋 한계 (2PC)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 코디네이터(Coordinator): 트랜잭션 전 과정 조율·결정
- 참여자(Participant): 각 자원 관리자(DB)
- 1단계 Prepare: 코디네이터가 커밋 가능 여부 질의, 참여자 Vote
- 2단계 Commit/Abort: 전원 Yes면 커밋, 하나라도 No면 롤백
- 강한 일관성(ACID) 보장, 동기·블로킹 방식

## Ⅲ. 비교·구조·지표 정리
```text
Coordinator →Prepare→ [P1, P2, P3]
            ←Vote(Yes/No)←
  전원 Yes → Commit  ┐
  하나라도 No → Abort┘→ 참여자 반영
  (Prepare~Commit 사이 참여자 락 보유=블로킹)
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 분산 트랜잭션의 원자성·강한 일관성 보장 |
| 장점 | ACID 보장·단순 의미론 |
| 한계 | 블로킹·코디네이터 SPOF·성능 저하·확장성 부족 |

## Ⅳ. 실무 적용 및 기술사 판단
- 코디네이터 장애 시 참여자 락 유지로 가용성 급락 → MSA 부적합
- 대안: 사가 패턴(최종 일관성)·이벤트 소싱으로 대체
- 단일 DB·전통 RDBMS 분산 환경 등 강한 일관성 필수 영역에 한정 적용

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 클라우드 네이티브 전환 배경 |
| 본론 1 | 런타임 구조와 통신 메커니즘 |
| 본론 2 | 모놀리스/분산구조 비교 |
| 본론 3 | 운영 복잡도와 대응 패턴 |
| 결론 | 확장성·회복탄력성 결론 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
