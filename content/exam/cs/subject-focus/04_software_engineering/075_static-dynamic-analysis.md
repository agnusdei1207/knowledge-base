## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 정적분석(Static Analysis)은 프로그램을 실행하지 않고 소스코드·바이트코드를 검사하는 기법이며, 동적분석(Dynamic Analysis)은 실제 실행 중 동작·자원·결함을 관찰하는 기법이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 모듈 경계, 아키텍처 스타일, 설계 원칙, 패턴, 품질속성까지 설계 판단을 묻는 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 응집도/결합도, 아키텍처 뷰, MVC, MSA, DDD, SOLID, DI, 코드 품질 메트릭 |
| 2~4교시 확장 방향 | 설계 목표와 품질속성, 구성요소·패턴·원리, 대안 구조 비교, 적용 조건과 안티패턴 |


- 답안 포인트
  - `정적·동적 분석 (Static·Dynamic Analysis)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 정적분석: 구문·자료흐름·제어흐름 분석, 코딩규칙·취약점 점검
- 동적분석: 실행 추적, 메모리 누수·성능·커버리지 측정
- 정적 도구: SonarQube, PMD, FindBugs, Coverity
- 동적 도구: Valgrind, 프로파일러, 동적 보안진단(DAST)
- 상호보완: 정적은 조기·광범위, 동적은 실제 거동 검증

## Ⅲ. 비교·구조·지표 정리
```text
소스코드 ──> [정적분석] 규칙·취약점 탐지(미실행)
   │
빌드·실행 ──> [동적분석] 메모리·성능·커버리지
   │
결함 리포트 통합 → 품질 개선
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 결함·취약점을 조기 또는 실행시점에 식별해 품질 확보 |
| 장점 | 정적=조기검출·전수, 동적=실거동·런타임 오류 검증 |
| 한계 | 정적=오탐(False Positive), 동적=실행경로 한정·비용 |

## Ⅳ. 실무 적용 및 기술사 판단
- DevSecOps 파이프라인에 SAST(정적)·DAST(동적) 통합 자동화
- 정적분석으로 코드스멜·보안약점 사전제거, 동적분석으로 성능·메모리 검증
- 두 기법 병행으로 검출 사각지대 최소화

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 설계 목표와 품질속성 |
| 본론 1 | 구성요소·패턴·원리 |
| 본론 2 | 대안 구조 비교 |
| 본론 3 | 적용 조건과 안티패턴 |
| 결론 | 유지보수성과 확장성 결론 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
