## Ⅰ. 출제 관점 및 1교시 답안 포인트
> GoF(Gang of Four) 생성(Creational) 패턴으로, 객체 생성을 위한 인터페이스를 정의하되 어떤 클래스의 인스턴스를 만들지는 서브클래스가 결정하도록 위임하여 객체 생성 로직을 캡슐화하는 패턴.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 모듈 경계, 아키텍처 스타일, 설계 원칙, 패턴, 품질속성까지 설계 판단을 묻는 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 응집도/결합도, 아키텍처 뷰, MVC, MSA, DDD, SOLID, DI, 코드 품질 메트릭 |
| 2~4교시 확장 방향 | 설계 목표와 품질속성, 구성요소·패턴·원리, 대안 구조 비교, 적용 조건과 안티패턴 |


- 답안 포인트
  - `팩토리 패턴 (Factory Method)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- **Product**: 생성될 객체의 공통 인터페이스
- **ConcreteProduct**: Product를 구현한 실제 생성 대상 클래스
- **Creator**: 팩토리 메서드(factoryMethod)를 선언하는 추상 생성자
- **ConcreteCreator**: 팩토리 메서드를 오버라이드해 구체 Product 반환
- **원리**: 생성 책임을 서브클래스로 분리 → OCP(개방-폐쇄 원칙) 준수, 결합도 완화

## Ⅲ. 비교·구조·지표 정리
```text
Creator ──factoryMethod()──> Product
   △                            △
   │                            │
ConcreteCreator ──생성──> ConcreteProduct
Client → Creator.factoryMethod() → Product 사용
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 객체 생성 캡슐화, 생성-사용 코드 분리 |
| 장점 | 신규 제품 추가 시 기존 코드 수정 최소(OCP), 결합도↓ |
| 한계 | 제품별 서브클래스 증가로 클래스 수·복잡도 상승 |

## Ⅳ. 실무 적용 및 기술사 판단
- 단순 Factory·Factory Method·Abstract Factory로 확장(제품군 생성)
- JDBC DriverManager, 로그 프레임워크의 LoggerFactory 등에 적용
- 의존성 역전(DIP)·전략 패턴과 결합해 런타임 객체 선택 유연화

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

  5. 확장 방향과 결론으로 마무리
