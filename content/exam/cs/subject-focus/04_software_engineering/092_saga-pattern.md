## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 사가(Saga)는 MSA에서 여러 서비스에 걸친 분산 트랜잭션을, 로컬 트랜잭션의 연쇄와 실패 시 보상 트랜잭션(Compensating Transaction)으로 데이터 일관성을 보장하는 패턴이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 컨테이너, 서비스 메시, 분산 트랜잭션, 관측성과 복원력을 포함한 운영형 아키텍처 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | Kubernetes, Service Mesh, API Gateway/BFF, Saga, CQRS, Serverless, MSA 전환 |
| 2~4교시 확장 방향 | 클라우드 네이티브 전환 배경, 런타임 구조와 통신 메커니즘, 모놀리스/분산구조 비교, 운영 복잡도와 대응 패턴 |


- 답안 포인트
  - `사가 패턴 (Saga)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 로컬 트랜잭션: 각 서비스가 자신의 DB에 대해 독립 커밋
- 보상 트랜잭션: 후속 단계 실패 시 이전 단계를 되돌리는 역연산
- 오케스트레이션: 중앙 오케스트레이터가 각 단계를 명령·조정
- 코레오그래피: 서비스가 이벤트를 발행·구독하며 자율 진행
- 최종 일관성(Eventual Consistency) 기반, 격리성은 직접 미보장

## Ⅲ. 비교·구조·지표 정리
```text
[오케스트레이션]            [코레오그래피]
Orchestrator               SvcA→event→SvcB→event→SvcC
 ├→cmd→ SvcA               실패 시 보상 event 역전파
 ├→cmd→ SvcB (실패)        SvcC─보상→SvcB─보상→SvcA
 └→보상→ SvcA
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 분산 환경에서 2PC 없이 데이터 일관성 확보 |
| 장점 | 느슨한 결합·확장성·장기 트랜잭션 지원 |
| 한계 | 보상 로직 복잡·격리성 부재(중간상태 노출)·디버깅 난이도 |

## Ⅳ. 실무 적용 및 기술사 판단
- 오케스트레이션: 흐름 가시성·중앙통제 우수, 단일 결합점 위험
- 코레오그래피: 결합도 최소, 단 흐름 추적·순환 의존 위험
- 격리성 부재 보완: 시맨틱 락·교환 가능 업데이트 설계

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 클라우드 네이티브 전환 배경 |
| 본론 1 | 런타임 구조와 통신 메커니즘 |

- 전개 순서

  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
