## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 데이터흐름도(DFD)는 데이터의 흐름·처리·저장을 구조적으로 표현하는 모델이며, 자료사전(Data Dictionary)은 그 데이터 항목을 정의·표기하는 메타정보 집합.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 요구 도출부터 우선순위, 명세, 추적성까지 품질 좋은 요구를 만드는 분석 출제축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 요구공학, SRS, RTM, 유스케이스, DFD, QFD, MoSCoW, 스토리맵 |
| 2~4교시 확장 방향 | 문제 상황과 이해관계자 관점, 도출·분석·명세 절차, 도구/기법 비교, 변경 통제와 검증 적용 |


- 답안 포인트
  - `DFD·자료사전 (Data Flow Diagram·Data Dictionary)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- DFD 4요소: 프로세스(○), 데이터흐름(→), 자료저장소(=), 외부엔티티(□)
- 단계화: 배경도(Level 0)→상세화(Level 1,2…)로 분할
- 균형(Balancing): 상위/하위 DFD 입출력 일치 유지
- 자료사전 표기: =(구성), +(and), [|](택일), {}(반복), ()(선택)
- 상호보완: DFD는 흐름, 자료사전은 데이터 구조 정의

## Ⅲ. 비교·구조·지표 정리
```text
[고객]→(주문접수)→주문데이터→(재고확인)
                              ↓
                         =재고DB=
자료사전: 주문 = 고객ID + {상품}1n + (메모)
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 구조적 분석으로 데이터 흐름과 정의를 일관화 |
| 장점 | 직관적 표현, 자료 정의 표준화로 모호성 제거 |
| 한계 | 제어흐름·시간 표현 불가, 객체지향에 부적합 |

## Ⅳ. 실무 적용 및 기술사 판단
- 구조적 분석(Structured Analysis) 기법의 핵심 산출물
- 자료사전은 후속 ERD·DB설계의 입력으로 연계
- 균형 검사로 분할 정합성 검증

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 문제 상황과 이해관계자 관점 |
| 본론 1 | 도출·분석·명세 절차 |
| 본론 2 | 도구/기법 비교 |
| 본론 3 | 변경 통제와 검증 적용 |
| 결론 | 실패 예방 효과 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
