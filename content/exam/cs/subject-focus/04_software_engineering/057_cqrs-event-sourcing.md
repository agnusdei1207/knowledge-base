## Ⅰ. 출제 관점 및 1교시 답안 포인트
> CQRS(Command Query Responsibility Segregation)는 상태를 변경하는 명령(Command)과 조회(Query)의 모델·경로를 분리하는 패턴이고, 이벤트 소싱(Event Sourcing)은 현재 상태 대신 상태 변경 이벤트를 순차 저장하여 재생(Replay)으로 상태를 복원하는 저장 기법이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 모듈 경계, 아키텍처 스타일, 설계 원칙, 패턴, 품질속성까지 설계 판단을 묻는 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 응집도/결합도, 아키텍처 뷰, MVC, MSA, DDD, SOLID, DI, 코드 품질 메트릭 |
| 2~4교시 확장 방향 | 설계 목표와 품질속성, 구성요소·패턴·원리, 대안 구조 비교, 적용 조건과 안티패턴 |


- 답안 포인트
  - `CQRS·이벤트 소싱 (CQRS·Event Sourcing)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 명령 모델(Write Model): 쓰기 최적화, 도메인 검증·일관성 처리
- 조회 모델(Read Model): 읽기 최적화, 비정규화 뷰
- 이벤트 저장소(Event Store): 불변 이벤트 시퀀스 추가 저장(Append-only)
- 프로젝션(Projection): 이벤트로 조회 모델 갱신
- 최종 일관성(Eventual Consistency)·스냅샷으로 재생 비용 절감

## Ⅲ. 비교·구조·지표 정리
```text
[Command] → [Write Model] → [Event Store(이벤트 적재)]
                                   │ (이벤트 발행)
                            [Projection]
                                   ▼
[Query]   ← [Read Model(비정규화 뷰)]
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 읽기/쓰기 독립 최적화와 변경 이력 완전 보존 |
| 장점 | 독립 확장, 감사·추적성, 시점 복원·재생 가능 |
| 한계 | 복잡도·최종 일관성, 이벤트 스키마 진화·중복 처리 부담 |

## Ⅳ. 실무 적용 및 기술사 판단
- MSA·EDA 환경에서 서비스별 읽기/쓰기 분리 확장에 적용
- 금융·감사 요구 시스템의 이력 추적, DDD 도메인 이벤트와 결합

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 설계 목표와 품질속성 |
| 본론 1 | 구성요소·패턴·원리 |

  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
