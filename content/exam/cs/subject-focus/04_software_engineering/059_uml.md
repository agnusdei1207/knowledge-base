## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 통합 모델링 언어(UML, Unified Modeling Language)는 OMG가 표준화한 객체지향 시스템의 구조와 행위를 시각적으로 표현하는 표준 모델링 언어로, 구조(Structural)·행위(Behavioral) 다이어그램으로 구성된다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 모듈 경계, 아키텍처 스타일, 설계 원칙, 패턴, 품질속성까지 설계 판단을 묻는 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 응집도/결합도, 아키텍처 뷰, MVC, MSA, DDD, SOLID, DI, 코드 품질 메트릭 |
| 2~4교시 확장 방향 | 설계 목표와 품질속성, 구성요소·패턴·원리, 대안 구조 비교, 적용 조건과 안티패턴 |


- 답안 포인트
  - `통합 모델링 언어 (UML)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 구조 다이어그램: 클래스·객체·컴포넌트·배치·패키지 (정적 구조)
- 행위 다이어그램: 유스케이스·시퀀스·상태·액티비티·커뮤니케이션 (동적 행위)
- 클래스 다이어그램: 클래스·속성·연관·상속 관계 표현
- 시퀀스 다이어그램: 객체 간 메시지 시간 순서 표현
- 상태/액티비티: 상태 전이·업무 흐름 표현

## Ⅲ. 비교·구조·지표 정리
```text
[UML]
 ├ 구조: 클래스 / 컴포넌트 / 배치 (정적)
 └ 행위: 유스케이스 / 시퀀스 / 상태 / 액티비티 (동적)
      시퀀스: ObjectA →msg→ ObjectB →msg→ ObjectC
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 표준 표기로 설계 의사소통·문서화 일관성 확보 |
| 장점 | 시각화, 이해관계자 공통 언어, 도구·코드 생성 연계 |
| 한계 | 과도한 문서화 부담, 표기 학습 필요, 최신 동기화 곤란 |

## Ⅳ. 실무 적용 및 기술사 판단
- 4+1 뷰의 각 뷰 표현 표기로 활용(논리=클래스, 프로세스=시퀀스)
- DDD 모델·MSA 컴포넌트 설계 및 MDA(모델 기반 개발)의 기반

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 설계 목표와 품질속성 |
| 본론 1 | 구성요소·패턴·원리 |
| 본론 2 | 대안 구조 비교 |
| 본론 3 | 적용 조건과 안티패턴 |
| 결론 | 유지보수성과 확장성 결론 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
