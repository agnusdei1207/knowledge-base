## Ⅰ. 출제 관점 및 1교시 답안 포인트
> DRY·KISS·YAGNI는 소프트웨어 설계·구현의 단순성과 중복 제거를 지향하는 실천 원칙으로, 각각 중복 배제(DRY)·단순함 유지(KISS)·불필요한 기능 배제(YAGNI)를 의미한다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 모듈 경계, 아키텍처 스타일, 설계 원칙, 패턴, 품질속성까지 설계 판단을 묻는 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 응집도/결합도, 아키텍처 뷰, MVC, MSA, DDD, SOLID, DI, 코드 품질 메트릭 |
| 2~4교시 확장 방향 | 설계 목표와 품질속성, 구성요소·패턴·원리, 대안 구조 비교, 적용 조건과 안티패턴 |


- 답안 포인트
  - `DRY·KISS·YAGNI`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- DRY(Don't Repeat Yourself): 지식·로직 중복 제거, 단일 진실 원천(SSOT) 유지
- KISS(Keep It Simple, Stupid): 가능한 한 단순하게, 과도한 복잡성 회피
- YAGNI(You Aren't Gonna Need It): 현재 필요 없는 기능은 미리 만들지 않음
- 공통 지향: 복잡도·유지보수 비용 최소화
- 균형: DRY 과적용 시 과도한 추상화 → KISS와 상충 주의

## Ⅲ. 비교·구조·지표 정리
```text
[설계/구현 결정]
   ├ DRY  : 중복 발견 → 추상화·재사용
   ├ KISS : 복잡 해법 → 가장 단순한 해법 선택
   └ YAGNI: 미래 추측 기능 → 보류(현 요구만)
        ▼  낮은 복잡도·높은 유지보수성
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 단순성·중복 제거로 유지보수 비용·결함 감소 |
| 장점 | 가독성·변경 용이성, 개발 속도, 오버엔지니어링 방지 |
| 한계 | 과한 DRY는 결합 증가, 단순화 판단 주관적 |

## Ⅳ. 실무 적용 및 기술사 판단
- 리팩토링·코드리뷰 기준, 애자일·TDD의 점진적 설계 철학과 정합
- SOLID와 함께 클린 코드 실천, 오버엔지니어링 방지의 의사결정 근거

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

- 전개 순서

  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
