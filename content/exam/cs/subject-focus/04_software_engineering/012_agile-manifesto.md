## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 애자일 선언문(Agile Manifesto)은 2001년 17인의 개발자가 합의한 경량 개발 철학으로, 무겁고 문서 중심적인 전통 개발에 대한 반성에서 출발해 변화 대응과 고객 가치를 우선하는 4대 가치와 12원칙을 제시한 선언이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 애자일 실행체계와 DevOps 기반 전달 자동화, 운영 피드백까지 연결하는 출제축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 스크럼, XP, 칸반, MVP, SAFe/LeSS, DevOps, IaC, SRE, GitOps |
| 2~4교시 확장 방향 | 민첩성 요구와 도입 배경, 역할·이벤트·파이프라인 구조, 전통 방식 대비 차이, 지표 기반 운영과 확장 전략 |


- 답안 포인트
  - `애자일 선언문 (Agile Manifesto)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 4대 가치(좌측 우선): ① 개인과 상호작용 > 프로세스·도구, ② 작동하는 SW > 포괄적 문서
- ③ 고객과의 협력 > 계약 협상, ④ 변화 대응 > 계획 준수 (우측도 가치 있으나 좌측을 더 중시)
- 12원칙: 잦은 인도, 변경 환영, 짧은 주기 릴리스, 비즈니스·개발 협업, 동기부여된 팀
- 대면 소통, 작동 SW가 진척 척도, 지속가능한 개발 속도, 기술적 탁월성, 단순성
- 자기조직화 팀, 정기적 회고(Retrospective)를 통한 조정

## Ⅲ. 비교·구조·지표 정리
```text
[전통 가치] ──반성──> [애자일 4대 가치]
   문서·계획 중심           개인·동작SW·협력·변화대응
        │                        │
        └──> 12원칙(잦은 인도·변경 환영·회고) ──> 고객 가치 극대화
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 변화에 빠르게 대응하여 고객 가치를 지속 인도 |
| 장점 | 짧은 피드백 주기, 변경 수용성, 팀 자율성·동기 향상 |
| 한계 | 가치·원칙 수준의 추상적 지침, 대규모·규제 환경 적용 시 별도 프레임워크 필요 |

## Ⅳ. 실무 적용 및 기술사 판단
- 스크럼(Scrum)·XP·칸반(Kanban)은 애자일 선언을 구현하는 구체적 방법론으로 매핑
- 대규모 적용은 SAFe·LeSS로, 운영 연계는 DevOps로 확장되어 가치 흐름을 완성

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 민첩성 요구와 도입 배경 |
| 본론 1 | 역할·이벤트·파이프라인 구조 |
| 본론 2 | 전통 방식 대비 차이 |
| 본론 3 | 지표 기반 운영과 확장 전략 |
| 결론 | 조직 문화 정착 포인트 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
