## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 스크럼(Scrum)은 복잡한 제품 개발을 짧은 반복(Sprint) 단위로 점진·경험적으로 수행하는 애자일 프레임워크로, 3개 역할·3개 산출물·5개 이벤트와 투명성·점검·적응의 경험주의 3축으로 구성된다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 애자일 실행체계와 DevOps 기반 전달 자동화, 운영 피드백까지 연결하는 출제축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 스크럼, XP, 칸반, MVP, SAFe/LeSS, DevOps, IaC, SRE, GitOps |
| 2~4교시 확장 방향 | 민첩성 요구와 도입 배경, 역할·이벤트·파이프라인 구조, 전통 방식 대비 차이, 지표 기반 운영과 확장 전략 |


- 답안 포인트
  - `스크럼 (Scrum)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 역할(3): 제품책임자(PO, 가치·우선순위), 스크럼마스터(SM, 프로세스 촉진·장애 제거), 개발팀(자기조직화)
- 산출물(3): 제품 백로그(Product Backlog), 스프린트 백로그, 증분(Increment)
- 이벤트: 스프린트(1~4주 컨테이너), 스프린트 계획, 데일리 스크럼, 스프린트 리뷰, 회고
- 추적: 번다운/번업 차트로 잔여 작업 가시화
- 완료 정의(DoD)와 수용 기준으로 품질·완성 합의

## Ⅲ. 비교·구조·지표 정리
```text
Product Backlog ──Sprint Planning──> Sprint Backlog
        │                                  │
        │            ┌── Daily Scrum(24h) ─┘
        ▼            ▼
   PO 우선순위    Sprint(1~4주) ──> Increment ──Review/Retrospective──> 다음 Sprint
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 짧은 반복으로 가치 있는 증분을 지속 인도하고 경험적으로 개선 |
| 장점 | 빠른 피드백, 우선순위 유연성, 역할·책임 명확, 자기조직화 |
| 한계 | 요구 변동·역할 미준수 시 혼란, 대규모 조직엔 스케일링 필요 |

## Ⅳ. 실무 적용 및 기술사 판단
- 4개 핵심 이벤트(계획·데일리·리뷰·회고)와 번다운으로 진척·리스크 관리
- 대규모는 SAFe/LeSS, 흐름 중심 운영은 칸반(Scrumban)과 결합 가능

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 민첩성 요구와 도입 배경 |
| 본론 1 | 역할·이벤트·파이프라인 구조 |
| 본론 2 | 전통 방식 대비 차이 |
| 본론 3 | 지표 기반 운영과 확장 전략 |
| 결론 | 조직 문화 정착 포인트 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
