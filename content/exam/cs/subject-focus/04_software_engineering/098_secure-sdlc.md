## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 시큐어 SDLC(Secure Software Development Life Cycle)는 요구·설계·구현·테스트·운영 등 개발생명주기 전 단계에 보안 활동을 내재화하여 사후 대응이 아닌 사전 예방으로 결함을 제거하는 개발 방법론이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 개발생명주기 보안, 위협 모델링, 오픈소스 공급망 통제까지 예방 중심 보안 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | Secure SDLC, STRIDE, SCA, SBOM, Secret Management |
| 2~4교시 확장 방향 | 보안 좌측 이동 배경, 통제 포인트와 자동화 체계, 기존 사후 점검 대비 차이, 규제·감사·운영 적용 |


- 답안 포인트
  - `시큐어 SDLC (Secure SDLC)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 요구: 보안 요구사항 정의·규제(개인정보보호법) 식별
- 설계: 위협 모델링(STRIDE)·보안 아키텍처 검토
- 구현: 시큐어 코딩 표준·SAST(정적분석)
- 테스트: DAST(동적분석)·모의해킹·SCA(구성분석)
- 운영: 취약점 패치·모니터링·사고 대응

## Ⅲ. 비교·구조·지표 정리
```text
요구 → 설계 → 구현 → 테스트 → 운영
 │보안   │위협   │시큐어   │DAST   │패치
 요구    모델링  코딩/SAST  /SCA    /모니터링
   ── Shift-Left: 결함 조기 발견 ──
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 보안 내재화로 사전 예방·비용 절감 |
| 장점 | 조기 결함 제거·수정비용↓·규제 준수 |
| 한계 | 초기 도입비·문화 정착·개발 속도 부담 |

## Ⅳ. 실무 적용 및 기술사 판단
- Shift-Left 원리: 후반 발견 시 수정비용 기하급수 증가 회피
- DevSecOps로 CI/CD에 보안 자동화(SAST·DAST·SCA) 통합
- 마이크로소프트 SDL·OWASP SAMM·BSIMM 등 성숙도 모델 연계

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 보안 좌측 이동 배경 |
| 본론 1 | 통제 포인트와 자동화 체계 |
| 본론 2 | 기존 사후 점검 대비 차이 |
| 본론 3 | 규제·감사·운영 적용 |
| 결론 | 리스크 저감 효과 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
