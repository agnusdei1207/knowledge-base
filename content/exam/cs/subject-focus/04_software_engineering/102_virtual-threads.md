## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 가상 스레드(Virtual Threads)는 JVM이 관리하는 경량 스레드로, OS 스레드에 1:1 매핑하지 않고 다수를 소수 캐리어 스레드에 다중화하여 고동시성을 저비용으로 구현하는 Java Project Loom의 핵심 기술이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 언어/runtime 혁신과 AI 활용 공학을 기술사 관점에서 실효성과 제약으로 정리하는 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | Virtual Threads, WebAssembly, AI4SE |
| 2~4교시 확장 방향 | 등장 배경과 기술 변화, 핵심 동작 원리, 기존 방식 대비 차이, 적용 시 리스크와 생산성 영향 |


- 답안 포인트
  - `가상 스레드 (Virtual Threads)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 캐리어 스레드(Carrier): 가상 스레드를 실제 실행하는 플랫폼 스레드
- 마운트/언마운트: 블로킹 I/O 시 가상 스레드를 캐리어에서 분리
- M:N 스케줄링: 수백만 가상 스레드를 소수 OS 스레드에 다중화
- 저비용: 스택이 힙에 저장되어 생성·전환 비용 극소
- 동기 코드 유지: 비동기 콜백 없이 블로킹 스타일로 고동시성

## Ⅲ. 비교·구조·지표 정리
```text
수백만 Virtual Thread
        │ (M:N 스케줄)
   ┌────┼────┐
 Carrier  Carrier  (소수 OS 스레드)
   I/O 블로킹 시 → 언마운트 → 캐리어 재사용
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 동기 코드로 대규모 동시성 구현·자원 효율 |
| 장점 | 경량·고처리량·단순 디버깅·스레드풀 불필요 |
| 한계 | CPU 바운드엔 이점 적음·고정(Pinning)·생태계 성숙 진행 |

## Ⅳ. 실무 적용 및 기술사 판단
- 리액티브(WebFlux) 대비 가독성 우수, I/O 바운드 서버에 적합
- "thread-per-request" 모델로 회귀하되 확장성 확보
- synchronized 블록 내 블로킹은 Pinning 유발 → ReentrantLock 권장

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시
