## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 시스템이 '무엇을 하는가'를 규정하는 기능 요구사항과, '얼마나 잘 하는가'를 규정하는 비기능 요구사항(품질속성·제약).

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 요구 도출부터 우선순위, 명세, 추적성까지 품질 좋은 요구를 만드는 분석 출제축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 요구공학, SRS, RTM, 유스케이스, DFD, QFD, MoSCoW, 스토리맵 |
| 2~4교시 확장 방향 | 문제 상황과 이해관계자 관점, 도출·분석·명세 절차, 도구/기법 비교, 변경 통제와 검증 적용 |


- 답안 포인트
  - `기능·비기능 요구사항 (Functional·Non-functional)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 기능 요구사항: 입력·처리·출력, 비즈니스 규칙, 기능 단위 동작
- 비기능 요구사항: 성능·가용성·보안·확장성·유지보수성 등 품질속성
- 제약사항: 법규·표준·플랫폼·예산 등 외부 제약
- 측정가능성: 비기능은 정량 지표(SLA, 응답시간 등)로 명세
- 상호영향: 비기능이 아키텍처(ATAM) 설계를 주도

## Ⅲ. 비교·구조·지표 정리
```text
요구사항
 ├ 기능(FR): "로그인 기능 제공"
 └ 비기능(NFR)
     ├ 성능: 응답 ≤ 2초
     ├ 보안: 암호화 AES-256
     └ 가용성: 99.9%
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 기능 정의와 품질수준을 분리·명확화 |
| 장점 | 검증기준 명확, 아키텍처 의사결정 근거 제공 |
| 한계 | 비기능은 정량화·검증 어려움, 누락 시 후반 재설계 |

## Ⅳ. 실무 적용 및 기술사 판단
- NFR은 ISO/IEC 25010 품질모델로 분류
- 비기능 충돌(성능 vs 보안)은 트레이드오프 분석(ATAM)으로 조정
- FURPS+ 모델로 요구사항 체계화 가능

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 문제 상황과 이해관계자 관점 |
| 본론 1 | 도출·분석·명세 절차 |
| 본론 2 | 도구/기법 비교 |
| 본론 3 | 변경 통제와 검증 적용 |
| 결론 | 실패 예방 효과 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
