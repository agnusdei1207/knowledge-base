## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 익스트림 프로그래밍(eXtreme Programming, XP)은 켄트 벡이 제창한 애자일 방법론으로, 짧은 반복과 엔지니어링 실천을 극단적으로 강조해 변화하는 요구에 고품질로 대응하는 개발 방식이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 애자일 실행체계와 DevOps 기반 전달 자동화, 운영 피드백까지 연결하는 출제축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 스크럼, XP, 칸반, MVP, SAFe/LeSS, DevOps, IaC, SRE, GitOps |
| 2~4교시 확장 방향 | 민첩성 요구와 도입 배경, 역할·이벤트·파이프라인 구조, 전통 방식 대비 차이, 지표 기반 운영과 확장 전략 |


- 답안 포인트
  - `익스트림 프로그래밍 (XP)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 5대 가치: 의사소통, 단순성, 피드백, 용기, 존중
- 짝 프로그래밍(Pair Programming): 2인 1조로 실시간 리뷰·지식 공유
- 테스트 주도 개발(TDD): 실패 테스트 작성 → 구현 → 리팩토링의 Red-Green-Refactor
- 리팩토링: 동작 보존하며 내부 구조 개선, 지속적 통합(CI)으로 잦은 병합·검증
- 작은 릴리스, 공동 코드 소유, 지속 가능한 속도(주 40시간), 고객 상주

## Ⅲ. 비교·구조·지표 정리
```text
User Story ──> Pair Programming
                  │
        ┌──> [Red] 실패 테스트 ──> [Green] 구현 ──> [Refactor]
        │                                            │
        └────────── CI(지속적 통합) ←────────────────┘──> 작은 릴리스
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 엔지니어링 실천으로 변화 대응성과 코드 품질을 동시에 확보 |
| 장점 | 결함 조기 발견, 높은 회귀 안정성, 지식 분산, 빠른 피드백 |
| 한계 | 짝 프로그래밍 인건비·문화 장벽, 고객 상주·테스트 부담 |

## Ⅳ. 실무 적용 및 기술사 판단
- TDD·CI는 CI/CD 파이프라인과 DevOps 자동화의 기술적 토대
- 스크럼(관리)+XP(실천) 결합으로 프로세스와 품질을 상호 보완

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 민첩성 요구와 도입 배경 |
| 본론 1 | 역할·이벤트·파이프라인 구조 |
| 본론 2 | 전통 방식 대비 차이 |
| 본론 3 | 지표 기반 운영과 확장 전략 |
| 결론 | 조직 문화 정착 포인트 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
