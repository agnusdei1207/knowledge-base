## Ⅰ. 출제 관점 및 1교시 답안 포인트
> SCM(Software Configuration Management, 소프트웨어 형상관리)은 SW 산출물(형상항목)의 변경을 식별·통제·기록·감사하여 무결성과 추적성을 보장하는 활동이다. 기준선(Baseline)을 중심으로 변경을 관리한다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 생명주기, 프로세스 성숙도, 형상/품질/원가/일정/위험 관리의 통합 판단 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | SDLC, 프로세스 모델, CMMI, 형상관리, 원가·일정·리스크 |
| 2~4교시 확장 방향 | 도입 배경과 관리 필요성, 핵심 절차·지표·산출물, 성숙도/방법론 비교, 프로젝트 통제와 조직 적용 |


- 답안 포인트
  - `형상관리 (SCM)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 형상식별(Identification): 형상항목 지정 및 버전·라벨 부여
- 형상통제(Control): CCB(Change Control Board, 변경통제위원회) 심의로 변경 승인
- 형상기록(Status Accounting): 변경 이력·상태 기록 및 보고
- 형상감사(Audit): 기능(FCA)·물리(PCA) 감사로 기준선 준수 검증
- 기준선(Baseline): 합의·승인된 형상의 기준 스냅샷

## Ⅲ. 비교·구조·지표 정리
```text
[변경요청] → [CCB 심의] → 승인/반려
   → [형상항목 변경] → [상태기록]
   → [형상감사] → [새 베이스라인 설정]
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 산출물 무결성·추적성 확보, 무단변경 방지 |
| 장점 | 변경 가시성·재현성, 릴리스 품질 안정화 |
| 한계 | 절차 과중 시 민첩성 저하, 도구·운영 부담 |

## Ⅳ. 실무 적용 및 기술사 판단
- Git 등 버전관리·CI/CD와 결합한 자동 형상관리 구현
- CMMI 레벨2 핵심 프로세스, 품질보증(QA)·감리와 연계

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 도입 배경과 관리 필요성 |
| 본론 1 | 핵심 절차·지표·산출물 |
| 본론 2 | 성숙도/방법론 비교 |
| 본론 3 | 프로젝트 통제와 조직 적용 |
| 결론 | 기대효과와 한계 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
