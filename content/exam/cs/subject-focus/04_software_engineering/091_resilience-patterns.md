## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 회복탄력성(Resilience) 패턴은 분산 시스템에서 부분 장애가 전체로 전파(연쇄 장애)되는 것을 차단하고 정상 동작을 유지하기 위한 장애 격리·복구 설계 기법이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 컨테이너, 서비스 메시, 분산 트랜잭션, 관측성과 복원력을 포함한 운영형 아키텍처 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | Kubernetes, Service Mesh, API Gateway/BFF, Saga, CQRS, Serverless, MSA 전환 |
| 2~4교시 확장 방향 | 클라우드 네이티브 전환 배경, 런타임 구조와 통신 메커니즘, 모놀리스/분산구조 비교, 운영 복잡도와 대응 패턴 |


- 답안 포인트
  - `회복탄력성 패턴 (서킷브레이커·벌크헤드·재시도)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 서킷브레이커(Circuit Breaker): 실패율 임계 초과 시 호출 차단(Open), 일정 후 Half-Open 탐색
- 벌크헤드(Bulkhead): 자원(스레드풀·커넥션)을 격리해 장애 영향 국소화
- 재시도(Retry): 일시적 오류에 지수 백오프+지터로 재호출
- 타임아웃: 무한 대기 방지로 자원 고갈 차단
- 폴백(Fallback): 실패 시 대체 응답·캐시 제공

## Ⅲ. 비교·구조·지표 정리
```text
Request → [Timeout] → [Bulkhead 격리]
   │
   ▼  실패율↑
[Circuit: Closed → Open → Half-Open]
   └ Open 시 즉시 Fallback 반환
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 연쇄 장애 차단·시스템 안정성 확보 |
| 장점 | 장애 격리·빠른 실패·자원 보호·우아한 성능저하 |
| 한계 | 임계값 튜닝 난이도·재시도 폭주(Retry Storm) 위험 |

## Ⅳ. 실무 적용 및 기술사 판단
- Resilience4j·Istio로 코드/인프라 레벨 적용, 멱등성 보장 시에만 재시도
- 서킷브레이커는 빠른 실패, 벌크헤드는 격리로 상호 보완
- 카오스 엔지니어링으로 패턴 유효성 사전 검증

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시
