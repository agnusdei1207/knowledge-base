## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 순환복잡도(Cyclomatic Complexity)는 맥케이브(McCabe)가 제안한 척도로, 프로그램 제어흐름그래프의 선형 독립 경로 수를 측정해 코드 복잡도와 테스트 케이스 최소 개수를 정량화한다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 모듈 경계, 아키텍처 스타일, 설계 원칙, 패턴, 품질속성까지 설계 판단을 묻는 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 응집도/결합도, 아키텍처 뷰, MVC, MSA, DDD, SOLID, DI, 코드 품질 메트릭 |
| 2~4교시 확장 방향 | 설계 목표와 품질속성, 구성요소·패턴·원리, 대안 구조 비교, 적용 조건과 안티패턴 |


- 답안 포인트
  - `맥케이브 순환복잡도 (Cyclomatic Complexity)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 제어흐름그래프(CFG): 노드(N)=처리, 엣지(E)=흐름
- 공식: V(G) = E - N + 2 (단일 연결그래프)
- 대안 공식: V(G) = P + 1 (P=판단노드 수)
- 분기(if·while·for·case)마다 복잡도 1 증가
- V(G)는 독립 경로 수 = 최소 테스트 케이스 수

## Ⅲ. 비교·구조·지표 정리
```text
   ●(N1)
   │
  ◇(판단) ── true ── ●
   │ false           │
   ●─────────────────●  E - N + 2 = V(G)
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 코드 복잡도 정량화 및 테스트 충분성 기준 제시 |
| 장점 | 객관적 수치, 위험 모듈 식별, 화이트박스 경로 기준 |
| 한계 | 데이터 복잡도·중첩 깊이 미반영, 가독성 직접측정 불가 |

## Ⅳ. 실무 적용 및 기술사 판단
- 권고치 V(G)≤10 초과 모듈은 리팩토링·분할 대상 선정
- 기본경로테스트(Basis Path Testing)의 경로 수 산정 근거
- 정적분석 도구의 품질지표로 코드스멜·기술부채 관리 연계

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 설계 목표와 품질속성 |
| 본론 1 | 구성요소·패턴·원리 |
| 본론 2 | 대안 구조 비교 |
| 본론 3 | 적용 조건과 안티패턴 |
| 결론 | 유지보수성과 확장성 결론 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
