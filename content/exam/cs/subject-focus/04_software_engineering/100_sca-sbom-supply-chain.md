## Ⅰ. 출제 관점 및 1교시 답안 포인트
> SCA(Software Composition Analysis, 소프트웨어 구성분석)는 오픈소스·서드파티 의존성의 취약점·라이선스를 분석하는 기법이고, SBOM(Software Bill of Materials, 소프트웨어 자재명세서)은 구성요소 목록을 표준화한 명세로 공급망 보안의 기반이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 개발생명주기 보안, 위협 모델링, 오픈소스 공급망 통제까지 예방 중심 보안 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | Secure SDLC, STRIDE, SCA, SBOM, Secret Management |
| 2~4교시 확장 방향 | 보안 좌측 이동 배경, 통제 포인트와 자동화 체계, 기존 사후 점검 대비 차이, 규제·감사·운영 적용 |


- 답안 포인트
  - `SCA·SBOM·공급망 보안 (SCA·SBOM·Supply Chain)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- SCA: 의존성 스캔→알려진 취약점(CVE)·라이선스 위반 탐지
- SBOM: 컴포넌트·버전·라이선스·해시 목록(SPDX·CycloneDX 표준)
- 공급망 위협: 의존성 변조·악성 패키지·빌드 파이프라인 침해
- 무결성 검증: 서명(Sigstore)·프로비넌스(SLSA) 보증
- 지속 모니터링: 신규 CVE 발생 시 영향 컴포넌트 추적

## Ⅲ. 비교·구조·지표 정리
```text
소스+의존성 → [SCA 스캔] → CVE/라이선스 탐지
            → [SBOM 생성] (SPDX/CycloneDX)
            → 서명/프로비넌스(SLSA)
   배포 후: 신규 CVE ↔ SBOM 대조 → 영향 추적
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 의존성 가시성 확보·공급망 위협 차단 |
| 장점 | 취약점 신속 추적·라이선스 준수·투명성 |
| 한계 | 오탐·SBOM 최신성 유지·전이 의존성 깊이 |

## Ⅳ. 실무 적용 및 기술사 판단
- Log4Shell 사례처럼 SBOM이 영향 범위 신속 식별 핵심
- DevSecOps CI/CD에 SCA 자동화 게이트 통합
- 미 행정명령(EO 14028)·SLSA 프레임워크로 공급망 보안 표준화

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 보안 좌측 이동 배경 |
| 본론 1 | 통제 포인트와 자동화 체계 |
| 본론 2 | 기존 사후 점검 대비 차이 |

| 결론 | 리스크 저감 효과 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
