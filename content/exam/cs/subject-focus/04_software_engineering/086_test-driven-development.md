## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 테스트 주도 개발(TDD, Test-Driven Development)은 실패하는 테스트를 먼저 작성한 뒤 이를 통과시키는 최소 코드를 구현하고 리팩토링하는, 테스트가 설계를 견인하는 개발 방법론이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 검증·확인, 테스트 설계, 커버리지, 회귀/성능까지 품질보증 체계를 묻는 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 테스트 원리, 블랙박스/화이트박스, 테스트 레벨, 회귀, 성능, TDD, 테스트 더블 |
| 2~4교시 확장 방향 | 품질 위험과 테스트 필요성, 기법·절차·커버리지 구조, 정적/동적 또는 기능/비기능 비교, 자동화·회귀 전략 |


- 답안 포인트
  - `테스트 주도 개발 (TDD)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- Red: 요구를 표현하는 실패 테스트를 먼저 작성
- Green: 테스트를 통과시키는 최소한의 코드 구현
- Refactor: 동작 유지하며 중복 제거·구조 개선
- 작은 단위 반복(짧은 주기)으로 점진적 진화
- 테스트 우선으로 명세·설계를 코드로 구체화

## Ⅲ. 비교·구조·지표 정리
```text
  ┌──> Red(실패 테스트 작성)
  │         │
  │      Green(최소 구현·통과)
  │         │
  └──── Refactor(구조 개선) ──┘
        (사이클 반복)
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 테스트로 요구·설계를 견인해 결함 적은 코드 점진 구현 |
| 장점 | 높은 커버리지, 회귀안전망, 클린한 설계·즉각 피드백 |
| 한계 | 초기 생산성 저하, 학습곡선, UI·외부연동 적용 난이도 |

## Ⅳ. 실무 적용 및 기술사 판단
- 테스트 더블·DI와 결합해 의존성 격리된 단위테스트 작성
- 리팩토링 단계는 클린코드·코드스멜 제거와 직결
- BDD(행위주도개발)로 확장해 요구추적성·협업 강화, CI에 통합

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 품질 위험과 테스트 필요성 |
| 본론 1 | 기법·절차·커버리지 구조 |
| 본론 2 | 정적/동적 또는 기능/비기능 비교 |
| 본론 3 | 자동화·회귀 전략 |
| 결론 | 품질 지표와 운영 연계 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
