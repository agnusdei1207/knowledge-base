## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 객체지향 프로그래밍(OOP, Object-Oriented Programming)은 데이터와 행위를 객체 단위로 캡슐화하고, 객체 간 메시지로 협력하도록 설계하는 패러다임이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 모듈 경계, 아키텍처 스타일, 설계 원칙, 패턴, 품질속성까지 설계 판단을 묻는 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 응집도/결합도, 아키텍처 뷰, MVC, MSA, DDD, SOLID, DI, 코드 품질 메트릭 |
| 2~4교시 확장 방향 | 설계 목표와 품질속성, 구성요소·패턴·원리, 대안 구조 비교, 적용 조건과 안티패턴 |


- 답안 포인트
  - `객체지향 4대 특징 (OOP)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 캡슐화(Encapsulation): 데이터·메서드를 묶고 내부 구현을 은닉, 접근제어자로 보호
- 상속(Inheritance): 상위 클래스의 속성·행위를 재사용하여 확장, 코드 중복 제거
- 다형성(Polymorphism): 동일 메시지에 객체별로 다른 응답(오버라이딩·오버로딩)
- 추상화(Abstraction): 핵심 개념만 모델링하고 불필요한 세부는 감춤(인터페이스)
- 협력 원리: 객체는 책임을 갖고 메시지를 주고받으며 시스템 동작 구성

## Ⅲ. 비교·구조·지표 정리
```text
[추상화] 인터페이스 정의
   │
[캡슐화] 데이터+메서드 은닉 → 객체
   │
[상속] 부모→자식 확장
   │
[다형성] 동일 메시지 → 다른 구현 실행
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 재사용성·유지보수성·확장성 높은 모듈 구조 확보 |
| 장점 | 정보은닉, 코드 재사용, 변경 영향 국소화, 실세계 모델링 용이 |
| 한계 | 과도한 상속 시 결합도 증가, 설계 난이도·성능 오버헤드 |

## Ⅳ. 실무 적용 및 기술사 판단
- 상속의 강결합 문제는 GoF 디자인패턴의 "상속보다 합성(Composition)" 원칙으로 보완
- SOLID 원칙(특히 LSP·DIP)과 결합하여 유연한 객체 설계 적용
- 다형성은 의존성주입(DI)·전략패턴 구현의 기반

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 설계 목표와 품질속성 |
| 본론 1 | 구성요소·패턴·원리 |
| 본론 2 | 대안 구조 비교 |
| 본론 3 | 적용 조건과 안티패턴 |
| 결론 | 유지보수성과 확장성 결론 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
