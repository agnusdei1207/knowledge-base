## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 회귀 테스트(Regression Testing)는 코드 수정·기능 추가 후 기존에 정상 동작하던 기능이 손상되지 않았음을 재검증하는 테스트로, 변경의 부작용을 방지한다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 검증·확인, 테스트 설계, 커버리지, 회귀/성능까지 품질보증 체계를 묻는 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 테스트 원리, 블랙박스/화이트박스, 테스트 레벨, 회귀, 성능, TDD, 테스트 더블 |
| 2~4교시 확장 방향 | 품질 위험과 테스트 필요성, 기법·절차·커버리지 구조, 정적/동적 또는 기능/비기능 비교, 자동화·회귀 전략 |


- 답안 포인트
  - `회귀 테스트 (Regression Testing)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 변경 영향분석: 수정 코드의 파급 범위 식별
- 테스트 케이스 선정: 전체 재실행 vs 선택적 재실행
- 우선순위화(Prioritization): 위험·빈도 기반 케이스 순서
- 최소화(Minimization): 중복 케이스 제거로 효율화
- 자동화: CI 파이프라인에서 반복 실행

## Ⅲ. 비교·구조·지표 정리
```text
코드 변경 → 영향분석 → 케이스 선정
      │
회귀 스위트 실행(자동화)
      │
실패 시 결함 수정 → 재실행 → 통과
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 변경으로 인한 기존 기능 결함(회귀결함) 방지 |
| 장점 | 안정성 확보, 자동화로 반복 효율, 변경 신뢰성 |
| 한계 | 케이스 누적으로 실행시간·비용 증가, 유지보수 부담 |

## Ⅳ. 실무 적용 및 기술사 판단
- CI/CD 파이프라인에 자동 회귀 스위트 통합(지속적 검증)
- 위험기반 선택·우선순위화로 실행시간 최적화
- 살충제 패러독스 대응 위해 회귀 케이스 주기적 갱신

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 품질 위험과 테스트 필요성 |
| 본론 1 | 기법·절차·커버리지 구조 |
| 본론 2 | 정적/동적 또는 기능/비기능 비교 |
| 본론 3 | 자동화·회귀 전략 |
| 결론 | 품질 지표와 운영 연계 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
