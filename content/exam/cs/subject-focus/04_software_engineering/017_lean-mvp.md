## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 린 스타트업(Lean Startup)은 불확실한 시장에서 최소기능제품(MVP)을 빠르게 만들어 측정·학습하는 반복으로 검증된 학습을 추구하는 방법론이며, MVP(Minimum Viable Product)는 핵심 가설을 최소 비용으로 검증할 수 있는 최소 기능 제품이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 애자일 실행체계와 DevOps 기반 전달 자동화, 운영 피드백까지 연결하는 출제축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 스크럼, XP, 칸반, MVP, SAFe/LeSS, DevOps, IaC, SRE, GitOps |
| 2~4교시 확장 방향 | 민첩성 요구와 도입 배경, 역할·이벤트·파이프라인 구조, 전통 방식 대비 차이, 지표 기반 운영과 확장 전략 |


- 답안 포인트
  - `린·MVP (Lean·MVP)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- Build-Measure-Learn 루프: 아이디어→제품(Build)→데이터(Measure)→학습(Learn)→재반복
- MVP: 핵심 가치 가설 검증용 최소 기능 묶음, 자원 낭비 최소화
- 검증된 학습(Validated Learning): 실제 고객 데이터로 가설 진위 판정
- 피벗(Pivot) vs 인내(Persevere): 학습 결과로 방향 전환 또는 유지 결정
- 혁신 회계(지표 기반), 가치/성장 가설 구분

## Ⅲ. 비교·구조·지표 정리
```text
   아이디어(가설)
       │ Build
       ▼
     MVP(제품) ──Measure──> 데이터
       ▲                     │ Learn
       └──── Pivot/Persevere ┘
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 최소 자원으로 시장 가설을 빠르게 검증해 실패 비용 절감 |
| 장점 | 낭비 제거, 빠른 학습, 시장 적합성(PMF) 조기 확인 |
| 한계 | MVP 범위 오판 시 브랜드 손상, 정량 지표 해석 오류 위험 |

## Ⅳ. 실무 적용 및 기술사 판단
- 애자일·DevOps와 결합해 짧은 릴리스로 BML 루프 가속(A/B 테스트, 기능 플래그)
- 디자인씽킹·MVP로 신사업 PoC, 데이터 기반 의사결정 체계와 연계

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 민첩성 요구와 도입 배경 |
| 본론 1 | 역할·이벤트·파이프라인 구조 |
| 본론 2 | 전통 방식 대비 차이 |
| 본론 3 | 지표 기반 운영과 확장 전략 |
| 결론 | 조직 문화 정착 포인트 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
