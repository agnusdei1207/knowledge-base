## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 깃옵스(GitOps)는 시스템의 원하는 상태를 Git에 선언적으로 정의하고 이를 단일 진실 원천(SSOT, Single Source of Truth)으로 삼아, 에이전트가 실제 상태를 Git 상태로 지속 동기화(Pull 기반)하는 운영 방식이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 애자일 실행체계와 DevOps 기반 전달 자동화, 운영 피드백까지 연결하는 출제축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 스크럼, XP, 칸반, MVP, SAFe/LeSS, DevOps, IaC, SRE, GitOps |
| 2~4교시 확장 방향 | 민첩성 요구와 도입 배경, 역할·이벤트·파이프라인 구조, 전통 방식 대비 차이, 지표 기반 운영과 확장 전략 |


- 답안 포인트
  - `깃옵스 (GitOps)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 선언형(Declarative): 인프라·앱 상태를 매니페스트로 기술해 Git에 저장
- 단일 진실 원천(SSOT): 모든 변경은 Git 커밋·PR을 통해서만 수행(승인·감사 추적)
- 풀(Pull) 기반: 클러스터 내 에이전트가 Git을 폴링해 차이를 자동 수렴(reconcile)
- 드리프트 탐지·자동 교정: 실제 상태가 어긋나면 Git 상태로 복원
- 도구: Argo CD, Flux. 롤백은 Git revert로 단순화

## Ⅲ. 비교·구조·지표 정리
```text
 개발자 ─PR/Merge─> Git(SSOT, 선언적 매니페스트)
                         │ Pull(폴링)
                         ▼
              Agent(Argo CD) ─reconcile→ K8s 클러스터
                         ▲ 드리프트 탐지 → Git 상태로 자동 교정
```

| 구분 | 내용 |
|:---|:---|
| 목적 | Git을 단일 진실 원천으로 선언적·자동 동기화 운영 |
| 장점 | 감사·롤백 용이, 일관성·재현성, 보안(클러스터 외부 접근 최소) |
| 한계 | 선언형·쿠버네티스 종속, 시크릿 관리·다환경 구성 복잡 |

## Ⅳ. 실무 적용 및 기술사 판단
- IaC·CI/CD를 Pull 기반으로 재구성, 변경 거버넌스를 Git 워크플로로 표준화
- 멀티클러스터·플랫폼 엔지니어링의 배포 표준, 카나리 배포 연계

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시
