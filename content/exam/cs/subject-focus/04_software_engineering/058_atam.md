## Ⅰ. 출제 관점 및 1교시 답안 포인트
> ATAM(Architecture Tradeoff Analysis Method)은 SEI가 제안한 아키텍처 평가 기법으로, 품질속성(Quality Attribute) 시나리오를 기반으로 아키텍처 결정이 품질에 미치는 영향과 트레이드오프(Tradeoff)를 식별·분석하는 방법이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 모듈 경계, 아키텍처 스타일, 설계 원칙, 패턴, 품질속성까지 설계 판단을 묻는 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 응집도/결합도, 아키텍처 뷰, MVC, MSA, DDD, SOLID, DI, 코드 품질 메트릭 |
| 2~4교시 확장 방향 | 설계 목표와 품질속성, 구성요소·패턴·원리, 대안 구조 비교, 적용 조건과 안티패턴 |


- 답안 포인트
  - `아키텍처 트레이드오프 분석 (ATAM)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 품질속성: 성능·가용성·보안·변경용이성 등 비기능 요구
- 유틸리티 트리(Utility Tree): 품질속성을 시나리오로 구체화·우선순위화
- 민감점(Sensitivity Point): 품질에 큰 영향을 주는 결정
- 트레이드오프점(Tradeoff Point): 여러 품질에 상충 영향을 주는 결정
- 위험(Risk)·비위험(Non-risk) 식별

## Ⅲ. 비교·구조·지표 정리
```text
[비즈니스 동인] → [아키텍처 제시]
        │
[유틸리티 트리(품질속성 시나리오)]
        │ 분석
[민감점·트레이드오프점·위험 식별] → [결과/개선]
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 품질속성 관점에서 아키텍처 위험·상충 조기 식별 |
| 장점 | 이해관계자 합의, 정량적 근거, 위험 사전 도출 |
| 한계 | 평가 비용·시간·전문가 필요, 정성적 판단 의존 |

## Ⅳ. 실무 적용 및 기술사 판단
- 4+1 뷰·품질속성 시나리오 기반으로 대형 시스템 아키텍처 검증
- SAAM·CBAM과 비교, 설계 의사결정의 트레이드오프 근거 문서화

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 설계 목표와 품질속성 |
| 본론 1 | 구성요소·패턴·원리 |
| 본론 2 | 대안 구조 비교 |
| 본론 3 | 적용 조건과 안티패턴 |
| 결론 | 유지보수성과 확장성 결론 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
