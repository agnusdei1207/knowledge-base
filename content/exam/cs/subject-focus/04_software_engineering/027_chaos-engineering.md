## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 카오스 엔지니어링(Chaos Engineering)은 운영에 가까운 환경에 의도적으로 장애를 주입하는 통제된 실험을 통해 시스템의 약점을 사전에 발견하고 복원력(Resilience)에 대한 확신을 확보하는 분야이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 애자일 실행체계와 DevOps 기반 전달 자동화, 운영 피드백까지 연결하는 출제축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 스크럼, XP, 칸반, MVP, SAFe/LeSS, DevOps, IaC, SRE, GitOps |
| 2~4교시 확장 방향 | 민첩성 요구와 도입 배경, 역할·이벤트·파이프라인 구조, 전통 방식 대비 차이, 지표 기반 운영과 확장 전략 |


- 답안 포인트
  - `카오스 엔지니어링 (Chaos Engineering)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 정상 상태(Steady State) 가설 정의: 정상 시 측정 가능한 지표 기준 설정
- 실제 장애 주입: 서버 종료, 네트워크 지연·단절, 자원 고갈 등 현실적 이벤트
- 통제된 실험: 폭발 반경(Blast Radius) 최소화, 운영 환경 점진 확대
- 자동 중단(Abort): 가설 위반·위험 시 즉시 롤백
- 도구: Chaos Monkey(넷플릭스), 게임데이(Game Day) 훈련

## Ⅲ. 비교·구조·지표 정리
```text
 Steady State 가설 ─> 장애 주입(서버다운/지연)
        │                   │ 폭발반경 제한
        ▼                   ▼
   지표 비교 ── 가설 유지? ──No──> 약점 발견·개선
                  │Yes                │
                  └─ 범위 확대 ←───────┘ (자동 Abort)
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 사전 장애 실험으로 숨은 약점 발견·복원력 검증 |
| 장점 | 실제 장애 전 대비, 복구 절차 검증, 자신감 있는 운영 |
| 한계 | 운영 영향 리스크, 성숙한 모니터링·롤백 체계 전제 |

## Ⅳ. 실무 적용 및 기술사 판단
- SRE 신뢰성 검증·옵저버빌리티와 결합해 가설-측정-개선 루프 운영
- 마이크로서비스·멀티클라우드 장애 격리(서킷브레이커) 효과 실증

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 민첩성 요구와 도입 배경 |
| 본론 1 | 역할·이벤트·파이프라인 구조 |
| 본론 2 | 전통 방식 대비 차이 |
| 본론 3 | 지표 기반 운영과 확장 전략 |
| 결론 | 조직 문화 정착 포인트 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
