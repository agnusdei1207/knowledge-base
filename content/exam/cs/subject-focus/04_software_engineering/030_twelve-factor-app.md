## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 12-Factor App은 Heroku가 제시한 클라우드 네이티브 SaaS 애플리케이션 구축 방법론으로, 이식성·확장성·선언적 구성을 갖춘 견고한 앱을 위한 12가지 설계 원칙이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 애자일 실행체계와 DevOps 기반 전달 자동화, 운영 피드백까지 연결하는 출제축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 스크럼, XP, 칸반, MVP, SAFe/LeSS, DevOps, IaC, SRE, GitOps |
| 2~4교시 확장 방향 | 민첩성 요구와 도입 배경, 역할·이벤트·파이프라인 구조, 전통 방식 대비 차이, 지표 기반 운영과 확장 전략 |


- 답안 포인트
  - `12-Factor App`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 코드베이스(Codebase): 버전관리되는 하나의 코드베이스를 다중 배포
- 의존성(Dependencies): 명시적 선언·격리, 설정(Config)은 환경변수로 코드와 분리
- 백킹 서비스(Backing Services): DB·큐 등을 교체 가능한 연결 리소스로 취급
- 프로세스(Processes): 무상태(Stateless)·공유 비저장, 상태는 백킹 서비스에
- 포트 바인딩·동시성(수평 확장)·폐기가능성(빠른 기동/정상 종료)·개발-운영 환경 일치
- 로그를 이벤트 스트림으로, 관리 프로세스를 일회성 작업으로 실행

## Ⅲ. 비교·구조·지표 정리
```text
 1 Codebase ── N Deploy
   │ Config=환경변수(코드 분리)
   ▼
 무상태 Process ─port bind→ 수평 확장(Concurrency)
   │ 로그=스트림   │ 폐기가능(빠른 기동/종료)
   └ 백킹서비스(DB/큐) = 교체가능 리소스
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 클라우드 환경에서 이식·확장·자동화에 유리한 앱 설계 원칙 제시 |
| 장점 | 환경 일치·수평 확장 용이, CI/CD·컨테이너 친화, 운영 단순화 |
| 한계 | 상태·대용량 데이터 앱엔 제약, 스트리밍 등 일부 시나리오 미흡 |

## Ⅳ. 실무 적용 및 기술사 판단
- 컨테이너(Docker)·쿠버네티스·마이크로서비스 설계의 표준 가이드
- 무상태·환경변수 구성은 CI/CD·오토스케일링·12-factor 확장(15-factor)으로 연계

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 민첩성 요구와 도입 배경 |
| 본론 1 | 역할·이벤트·파이프라인 구조 |
| 본론 2 | 전통 방식 대비 차이 |
| 본론 3 | 지표 기반 운영과 확장 전략 |
| 결론 | 조직 문화 정착 포인트 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
