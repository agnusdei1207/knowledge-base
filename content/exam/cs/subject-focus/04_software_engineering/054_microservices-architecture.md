## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 마이크로서비스 아키텍처(MSA, Microservices Architecture)는 단일 애플리케이션을 비즈니스 능력 단위의 작고 독립적으로 배포 가능한 서비스 집합으로 분해하고, 각 서비스가 자체 데이터베이스(DB per Service)를 소유하며 경량 API로 통신하는 분산 아키텍처이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 모듈 경계, 아키텍처 스타일, 설계 원칙, 패턴, 품질속성까지 설계 판단을 묻는 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 응집도/결합도, 아키텍처 뷰, MVC, MSA, DDD, SOLID, DI, 코드 품질 메트릭 |
| 2~4교시 확장 방향 | 설계 목표와 품질속성, 구성요소·패턴·원리, 대안 구조 비교, 적용 조건과 안티패턴 |


- 답안 포인트
  - `마이크로서비스 아키텍처 (MSA)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 독립 배포·독립 확장: 서비스별 빌드·배포·스케일 단위 분리
- DB per Service: 서비스마다 전용 DB 소유로 자율성·느슨한 결합 확보
- API 게이트웨이: 단일 진입점, 라우팅·인증·집계·Rate Limit
- 서비스 디스커버리·구성서버: 동적 위치 등록/조회
- 분산 트랜잭션은 사가(Saga), 장애 전파 차단은 서킷브레이커(Circuit Breaker)로 대응

## Ⅲ. 비교·구조·지표 정리
```text
[Client] → [API Gateway] → [Service A]─[DB A]
                 │         → [Service B]─[DB B]
                 │            │ (Saga: 보상 트랜잭션)
            [Discovery]     [Circuit Breaker로 장애 격리]
   서비스 간 REST/이벤트 통신, 서비스별 독립 배포·DB
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 독립 배포·확장으로 민첩성·장애 격리·기술 다양성 확보 |
| 장점 | 부분 배포·확장, 장애 국소화, 폴리글랏, 팀 자율성 |
| 한계 | 분산 복잡성, 데이터 일관성(최종 일관성), 운영·관측성 부담 |

## Ⅳ. 실무 적용 및 기술사 판단
- 서킷브레이커(Resilience4j)·사가(오케스트레이션/코레오그래피)·API 게이트웨이(Spring Cloud Gateway)로 안정성 확보
- 컨테이너(Docker)·오케스트레이션(Kubernetes)·서비스 메시(Istio)와 결합, SOA의 ESB 병목 극복
- DDD 바운디드 컨텍스트로 서비스 경계 도출, CQRS·이벤트 소싱과 연계

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 설계 목표와 품질속성 |
| 본론 1 | 구성요소·패턴·원리 |
| 본론 2 | 대안 구조 비교 |
| 본론 3 | 적용 조건과 안티패턴 |
| 결론 | 유지보수성과 확장성 결론 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
