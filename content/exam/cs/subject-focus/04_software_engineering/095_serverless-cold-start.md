## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 서버리스는 인프라 관리 없이 코드를 함수 단위로 실행하는 FaaS(Function as a Service) 모델이며, 콜드스타트는 유휴 함수의 첫 호출 시 런타임 초기화로 발생하는 지연이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 컨테이너, 서비스 메시, 분산 트랜잭션, 관측성과 복원력을 포함한 운영형 아키텍처 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | Kubernetes, Service Mesh, API Gateway/BFF, Saga, CQRS, Serverless, MSA 전환 |
| 2~4교시 확장 방향 | 클라우드 네이티브 전환 배경, 런타임 구조와 통신 메커니즘, 모놀리스/분산구조 비교, 운영 복잡도와 대응 패턴 |


- 답안 포인트
  - `서버리스·콜드스타트 (Serverless·Cold Start)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- FaaS: 이벤트 기반 함수 실행(AWS Lambda·Azure Functions)
- 이벤트 트리거: HTTP·큐·스토리지 이벤트로 함수 기동
- 자동 확장: 요청량에 따라 0→N 인스턴스 탄력 스케일
- 콜드스타트: 컨테이너 할당·런타임 로드·코드 초기화 지연
- 웜스타트: 기존 실행 환경 재사용으로 지연 없음

## Ⅲ. 비교·구조·지표 정리
```text
Event → [함수 인스턴스 有?]
        │No  → 컨테이너 할당+런타임 init = Cold Start(지연)
        │Yes → 즉시 실행 = Warm Start
        실행 후 일정시간 유지 → 유휴 시 소멸
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 인프라 무관리·사용량 기반 과금·자동 확장 |
| 장점 | 운영 부담↓·비용 효율(0 스케일)·빠른 출시 |
| 한계 | 콜드스타트 지연·실행시간 제한·벤더 락인·상태 비저장 |

## Ⅳ. 실무 적용 및 기술사 판단
- 콜드스타트 완화: 프로비저닝드 동시성·경량 런타임·SnapStart
- 이벤트 드리븐 아키텍처·비정형 워크로드(배치·웹훅)에 최적
- 일관 고부하·저지연 요구 영역은 컨테이너가 유리(혼합 설계)

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 클라우드 네이티브 전환 배경 |
| 본론 1 | 런타임 구조와 통신 메커니즘 |
| 본론 2 | 모놀리스/분산구조 비교 |
| 본론 3 | 운영 복잡도와 대응 패턴 |
| 결론 | 확장성·회복탄력성 결론 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
