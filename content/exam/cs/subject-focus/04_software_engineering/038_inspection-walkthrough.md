## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 산출물의 결함을 동료가 검토하여 조기 제거하는 정적 검토 기법으로, 인스펙션은 정형(formal)·역할기반, 워크쓰루는 비정형(informal)·저자주도 검토.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 요구 도출부터 우선순위, 명세, 추적성까지 품질 좋은 요구를 만드는 분석 출제축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 요구공학, SRS, RTM, 유스케이스, DFD, QFD, MoSCoW, 스토리맵 |
| 2~4교시 확장 방향 | 문제 상황과 이해관계자 관점, 도출·분석·명세 절차, 도구/기법 비교, 변경 통제와 검증 적용 |


- 답안 포인트
  - `인스펙션·워크쓰루 (Inspection·Walkthrough)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 인스펙션: 진행자(Moderator)·작성자·검토자·기록자 역할 분담
- 인스펙션 절차: 계획→준비→회의→재작업→후속관리, 체크리스트 사용
- 워크쓰루: 작성자가 동료에게 설명하며 비공식 검토
- 정형성 차이: 인스펙션은 측정·통계 수반, 워크쓰루는 경량
- 공통 목적: 동적 테스트 이전 결함 조기 발견

## Ⅲ. 비교·구조·지표 정리
```text
인스펙션: 계획→준비→[검토회의]→재작업→후속
                       (역할/체크리스트/통계)
워크쓰루: 작성자 설명 →동료 의견 →개선
                       (비공식/저자주도)
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 정적 검토로 결함 조기 제거 및 품질 향상 |
| 장점 | 테스트보다 저비용, 결함 원인 학습 효과 |
| 한계 | 인스펙션은 준비·시간 부담, 워크쓰루는 누락 가능 |

## Ⅳ. 실무 적용 및 기술사 판단
- 정형 검토(인스펙션) vs 비정형 검토(워크쓰루, 피어리뷰) 구분
- Fagan Inspection이 대표적 정형 기법
- 정적분석 도구와 병행 시 검출률 향상

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 문제 상황과 이해관계자 관점 |
| 본론 1 | 도출·분석·명세 절차 |
| 본론 2 | 도구/기법 비교 |
| 본론 3 | 변경 통제와 검증 적용 |
| 결론 | 실패 예방 효과 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
