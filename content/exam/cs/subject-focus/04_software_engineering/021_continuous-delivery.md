## Ⅰ. 출제 관점 및 1교시 답안 포인트
> CI/CD는 코드 변경을 자동으로 통합·검증·전달하는 파이프라인으로, 지속적 통합(CI)은 잦은 병합·자동 빌드/테스트, 지속적 인도(CD, Continuous Delivery)는 언제든 배포 가능한 상태 유지, 지속적 배포(Continuous Deployment)는 운영까지 무인 자동 배포를 의미한다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 애자일 실행체계와 DevOps 기반 전달 자동화, 운영 피드백까지 연결하는 출제축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 스크럼, XP, 칸반, MVP, SAFe/LeSS, DevOps, IaC, SRE, GitOps |
| 2~4교시 확장 방향 | 민첩성 요구와 도입 배경, 역할·이벤트·파이프라인 구조, 전통 방식 대비 차이, 지표 기반 운영과 확장 전략 |


- 답안 포인트
  - `지속적 통합·배포 (CI/CD)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 지속적 통합(CI): 잦은 커밋·병합, 자동 빌드·단위/통합 테스트로 통합 지옥 방지
- 지속적 인도(Continuous Delivery): 릴리스 후보를 항상 배포 가능 상태로 유지, 운영 반영은 수동 승인
- 지속적 배포(Continuous Deployment): 테스트 통과 시 운영까지 사람 개입 없이 자동 릴리스
- 파이프라인 단계: Source→Build→Test→Staging→Approve→Deploy
- 아티팩트 저장소·품질 게이트·자동 롤백

## Ⅲ. 비교·구조·지표 정리
```text
Commit ─> [CI] Build → Test ─> Artifact
                                 │
        [CD-인도] Staging → 승인(수동) → 운영
        [CD-배포] Staging → (자동) ────→ 운영
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 변경의 통합·검증·배포를 자동화해 빠르고 안전한 릴리스 |
| 장점 | 리드타임 단축, 결함 조기 발견, 배포 리스크 분산, 반복성 |
| 한계 | 테스트 자동화 성숙도 의존, 파이프라인 구축·유지 비용 |

## Ⅳ. 실무 적용 및 기술사 판단
- DORA 지표(배포빈도·리드타임) 개선의 핵심 수단, DevOps 자동화 중추
- 카나리·블루그린 배포 전략, 기능 플래그, GitOps와 결합해 무중단 릴리스

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시
