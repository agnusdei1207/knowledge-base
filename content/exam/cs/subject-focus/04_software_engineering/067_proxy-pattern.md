## Ⅰ. 출제 관점 및 1교시 답안 포인트
> GoF(Gang of Four) 구조(Structural) 패턴으로, 실제 객체(RealSubject)에 대한 대리자(Proxy)를 두어 접근을 제어하고, 지연 생성·보안·원격 호출 등 부가 제어를 수행하는 패턴.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 모듈 경계, 아키텍처 스타일, 설계 원칙, 패턴, 품질속성까지 설계 판단을 묻는 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 응집도/결합도, 아키텍처 뷰, MVC, MSA, DDD, SOLID, DI, 코드 품질 메트릭 |
| 2~4교시 확장 방향 | 설계 목표와 품질속성, 구성요소·패턴·원리, 대안 구조 비교, 적용 조건과 안티패턴 |


- 답안 포인트
  - `프록시 패턴 (Proxy)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- **Subject**: RealSubject와 Proxy가 공유하는 공통 인터페이스
- **RealSubject**: 실제 작업을 수행하는 본체 객체
- **Proxy**: RealSubject 참조 보유, 접근 제어 후 요청 위임
- **유형**: 가상(Virtual·지연로딩)·보호(Protection·권한)·원격(Remote)·캐싱 프록시
- **원리**: 클라이언트는 인터페이스만 의존 → 본체 접근을 투명하게 중개

## Ⅲ. 비교·구조·지표 정리
```text
Client → Proxy ──(접근제어/지연/캐싱)──> RealSubject
          │                                │
          └─ 동일 Subject 인터페이스 구현 ──┘
   request() → Proxy 검증 후 RealSubject.request() 위임
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 본체 대리 접근 제어·부가 제어 수행 |
| 장점 | 지연 생성으로 자원 절약, 보안·캐싱·로깅 분리 |
| 한계 | 호출 계층 추가로 응답 지연, 구현 복잡도 증가 |

## Ⅳ. 실무 적용 및 기술사 판단
- ORM 지연로딩, RPC/원격 스텁, AOP 기반 트랜잭션·보안 프록시
- Spring AOP의 동적 프록시(JDK Dynamic/CGLIB)로 횡단관심사 처리
- Decorator와 비교: Proxy는 접근 제어, Decorator는 기능 확장 목적

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 설계 목표와 품질속성 |
| 본론 1 | 구성요소·패턴·원리 |
| 본론 2 | 대안 구조 비교 |
| 본론 3 | 적용 조건과 안티패턴 |
| 결론 | 유지보수성과 확장성 결론 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
