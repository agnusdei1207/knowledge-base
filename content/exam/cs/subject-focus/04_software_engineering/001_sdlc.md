## Ⅰ. 출제 관점 및 1교시 답안 포인트
> SDLC(Software Development Life Cycle, 소프트웨어 개발 생명주기)는 요구분석부터 폐기까지 SW 개발 전 과정을 단계화한 체계적 프레임워크이다. 산출물·품질·일정 관리의 기준선이 된다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 생명주기, 프로세스 성숙도, 형상/품질/원가/일정/위험 관리의 통합 판단 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | SDLC, 프로세스 모델, CMMI, 형상관리, 원가·일정·리스크 |
| 2~4교시 확장 방향 | 도입 배경과 관리 필요성, 핵심 절차·지표·산출물, 성숙도/방법론 비교, 프로젝트 통제와 조직 적용 |


- 답안 포인트
  - `소프트웨어 개발 생명주기 (SDLC)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 타당성 검토(Feasibility): 기술·경제·운영 타당성 평가
- 요구분석(Requirement): 기능·비기능 요구사항 정의 및 명세
- 설계(Design): 아키텍처·상세 설계, 인터페이스 정의
- 구현(Implementation): 코딩·단위 테스트
- 시험/통합(Test): 통합·시스템·인수 테스트
- 운영·유지보수(Maintenance): 결함수정·기능개선, 최종 폐기

## Ⅲ. 비교·구조·지표 정리
```text
[타당성] → [요구분석] → [설계] → [구현]
   → [시험] → [운영/유지보수] → [폐기]
         ↑___________피드백 루프__________│
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 개발 전 과정의 표준화로 품질·일정·비용 예측성 확보 |
| 장점 | 단계별 산출물·검증으로 추적성과 통제 용이 |
| 한계 | 단계 경직 시 변경 대응 지연, 초기 요구 확정 부담 |

## Ⅳ. 실무 적용 및 기술사 판단
- 폭포수·V-모델·나선형·애자일 등 프로세스 모델 선택의 기준 골격
- CMMI 성숙도 향상, 형상관리(SCM)·EVM 적용의 단계 기준선 제공

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 도입 배경과 관리 필요성 |
| 본론 1 | 핵심 절차·지표·산출물 |
| 본론 2 | 성숙도/방법론 비교 |
| 본론 3 | 프로젝트 통제와 조직 적용 |
| 결론 | 기대효과와 한계 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
