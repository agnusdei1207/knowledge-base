## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 검증(Verification)은 '제품을 제대로 만들었는가(명세 부합)', 확인(Validation)은 '맞는 제품을 만들었는가(사용자 요구 충족)'를 평가하는 품질보증 활동.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 요구 도출부터 우선순위, 명세, 추적성까지 품질 좋은 요구를 만드는 분석 출제축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 요구공학, SRS, RTM, 유스케이스, DFD, QFD, MoSCoW, 스토리맵 |
| 2~4교시 확장 방향 | 문제 상황과 이해관계자 관점, 도출·분석·명세 절차, 도구/기법 비교, 변경 통제와 검증 적용 |


- 답안 포인트
  - `검증과 확인 (V&V)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- Verification: 명세·설계 대비 산출물 일치 검사(리뷰·정적분석)
- Validation: 실제 사용 목적·요구 충족 검사(테스트·시연)
- 정적기법: 인스펙션, 워크쓰루, 정적분석
- 동적기법: 단위·통합·시스템·인수 테스트
- 단계별 적용: 각 개발 단계 산출물마다 V&V 수행

## Ⅲ. 비교·구조·지표 정리
```text
명세 → 설계 → 구현 → 제품
  └Verification(단계간 일치 검사)┘
요구 ─────── Validation ─────── 제품
   "올바른 것을 만들었나?"
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 결함 조기 발견과 요구 충족 보증 |
| 장점 | 후반 재작업 비용 절감, 품질 확보 |
| 한계 | 시간·비용 소요, 전수 검증 불가 |

## Ⅳ. 실무 적용 및 기술사 판단
- Verification=Are we building the product right, Validation=Are we building the right product
- V-모델에서 좌측 산출물과 우측 테스트 단계가 V&V로 대응
- IEEE 1012 표준의 IV&V(독립 V&V) 적용 가능

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 문제 상황과 이해관계자 관점 |
| 본론 1 | 도출·분석·명세 절차 |
| 본론 2 | 도구/기법 비교 |
| 본론 3 | 변경 통제와 검증 적용 |
| 결론 | 실패 예방 효과 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
