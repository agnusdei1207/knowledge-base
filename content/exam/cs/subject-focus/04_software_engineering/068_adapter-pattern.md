## Ⅰ. 출제 관점 및 1교시 답안 포인트
> GoF(Gang of Four) 구조(Structural) 패턴으로, 호환되지 않는 인터페이스를 가진 기존 클래스를 클라이언트가 기대하는 인터페이스로 변환(Wrapping)하여 함께 동작하도록 연결하는 패턴.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 모듈 경계, 아키텍처 스타일, 설계 원칙, 패턴, 품질속성까지 설계 판단을 묻는 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 응집도/결합도, 아키텍처 뷰, MVC, MSA, DDD, SOLID, DI, 코드 품질 메트릭 |
| 2~4교시 확장 방향 | 설계 목표와 품질속성, 구성요소·패턴·원리, 대안 구조 비교, 적용 조건과 안티패턴 |


- 답안 포인트
  - `어댑터 패턴 (Adapter)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- **Target**: 클라이언트가 사용하는 기대 인터페이스
- **Adaptee**: 변환 대상이 되는 기존(레거시) 클래스
- **Adapter**: Target을 구현하며 Adaptee 호출로 인터페이스 변환·중개
- **Client**: Target 인터페이스를 통해 Adaptee 기능 사용
- **방식**: 합성 기반 객체 어댑터(권장), 상속 기반 클래스 어댑터(다중상속)

## Ⅲ. 비교·구조·지표 정리
```text
Client → Target ◁── Adapter ──호출──> Adaptee(기존)
                     (변환)            existingMethod()
   request() → Adapter가 Adaptee.existingMethod()로 매핑
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 인터페이스 불일치 해소, 기존 코드 재사용 |
| 장점 | 레거시·외부 라이브러리 통합, 변경 없이 호환 |
| 한계 | 어댑터 계층 추가로 복잡도↑, 과용 시 추적 곤란 |

## Ⅳ. 실무 적용 및 기술사 판단
- 레거시 시스템 연계, 외부 API/서드파티 라이브러리 통합에 활용
- Java의 Arrays.asList, InputStreamReader 등 변환기에 적용
- Facade와 비교: Adapter는 인터페이스 변환, Facade는 통합 단순화 목적

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 설계 목표와 품질속성 |
| 본론 1 | 구성요소·패턴·원리 |
| 본론 2 | 대안 구조 비교 |
| 본론 3 | 적용 조건과 안티패턴 |
| 결론 | 유지보수성과 확장성 결론 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
