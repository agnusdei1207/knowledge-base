## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 화이트박스 커버리지(White-box Coverage)는 프로그램 내부 구조·제어흐름을 기준으로 테스트가 코드를 얼마나 실행했는지 측정하는 구조기반 척도이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 검증·확인, 테스트 설계, 커버리지, 회귀/성능까지 품질보증 체계를 묻는 축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 테스트 원리, 블랙박스/화이트박스, 테스트 레벨, 회귀, 성능, TDD, 테스트 더블 |
| 2~4교시 확장 방향 | 품질 위험과 테스트 필요성, 기법·절차·커버리지 구조, 정적/동적 또는 기능/비기능 비교, 자동화·회귀 전략 |


- 답안 포인트
  - `화이트박스 커버리지 (White-box Coverage)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 구문 커버리지(Statement): 모든 실행문 1회 이상 실행
- 결정 커버리지(Decision/Branch): 모든 분기의 참·거짓 실행
- 조건 커버리지(Condition): 각 개별 조건의 참·거짓 평가
- 조건/결정(C/DC): 조건·결정 모두 만족
- MC/DC: 각 조건이 결정 결과에 독립적으로 영향함을 입증(항공 등 고신뢰)

## Ⅲ. 비교·구조·지표 정리
```text
구문 ⊂ 결정 ⊂ 조건/결정 ⊂ MC/DC (엄격도↑)
   if (A && B)
     ├ A,B 조합별 분기 실행
     └ 각 조건의 독립 영향 검증(MC/DC)
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 내부 경로 실행도를 정량화해 테스트 충분성 확보 |
| 장점 | 미실행 코드·숨은 경로 식별, 객관적 수치 |
| 한계 | 100% 커버해도 결함 부재 보장 불가, 케이스 폭증 |

## Ⅳ. 실무 적용 및 기술사 판단
- DO-178C 등 안전필수 시스템은 MC/DC 100% 요구
- 순환복잡도 V(G)와 연계해 기본경로 테스트 케이스 도출
- 블랙박스 기법과 결합한 하이브리드 테스트로 보완

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 품질 위험과 테스트 필요성 |
| 본론 1 | 기법·절차·커버리지 구조 |
| 본론 2 | 정적/동적 또는 기능/비기능 비교 |
| 본론 3 | 자동화·회귀 전략 |
| 결론 | 품질 지표와 운영 연계 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
