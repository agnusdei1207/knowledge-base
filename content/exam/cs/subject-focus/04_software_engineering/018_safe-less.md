## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 대규모 애자일은 다수 팀·제품을 정렬해 엔터프라이즈 수준에서 애자일을 적용하는 프레임워크로, SAFe(Scaled Agile Framework)는 정렬·계층 중심의 규범적 모델, LeSS(Large-Scale Scrum)는 스크럼을 최소 확장한 경량 모델이다.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 애자일 실행체계와 DevOps 기반 전달 자동화, 운영 피드백까지 연결하는 출제축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 스크럼, XP, 칸반, MVP, SAFe/LeSS, DevOps, IaC, SRE, GitOps |
| 2~4교시 확장 방향 | 민첩성 요구와 도입 배경, 역할·이벤트·파이프라인 구조, 전통 방식 대비 차이, 지표 기반 운영과 확장 전략 |


- 답안 포인트
  - `대규모 애자일 (SAFe·LeSS)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- SAFe: 포트폴리오·라지솔루션·프로그램(ART)·팀의 다계층, ART는 5~12팀을 묶은 애자일 릴리스 트레인
- SAFe 핵심: PI(Program Increment) 계획, 가치흐름(Value Stream), 린-애자일 원칙
- LeSS: 단일 제품 백로그·단일 PO·공통 스프린트로 다팀이 하나처럼 동작
- LeSS Huge: 8팀 초과 시 요구영역(Requirement Area)으로 분할
- 공통: 정렬·투명성·동기화된 반복·전사적 회고

## Ⅲ. 비교·구조·지표 정리
```text
[SAFe]  Portfolio → Large Solution → ART(Program) → Teams
                                   PI Planning 동기화
[LeSS]  단일 Product Backlog ─ 단일 PO
          ├ Team1 ┐
          ├ Team2 ┼ 공통 Sprint → 통합 Increment
          └ Team3 ┘
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 다수 팀의 정렬·동기화로 대규모 가치 인도 |
| 장점 | SAFe: 규범적 가이드·거버넌스, LeSS: 단순성·스크럼 충실 |
| 한계 | SAFe: 무거움·관료화 우려, LeSS: 대규모 조직 적용 난이도 |

## Ⅳ. 실무 적용 및 기술사 판단
- 조직 규모·문화 성숙도에 따라 SAFe(규제·대기업) vs LeSS(단일제품) 선택
- DevOps·가치흐름 매핑과 결합해 엔터프라이즈 애자일 전환 추진

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 민첩성 요구와 도입 배경 |
| 본론 1 | 역할·이벤트·파이프라인 구조 |
| 본론 2 | 전통 방식 대비 차이 |
| 본론 3 | 지표 기반 운영과 확장 전략 |
| 결론 | 조직 문화 정착 포인트 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
