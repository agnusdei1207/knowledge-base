## Ⅰ. 출제 관점 및 1교시 답안 포인트
> 고객이 요청하지 않은 과잉 기능·품질을 개발자가 자발적으로 추가하여 자원을 낭비하고 위험을 늘리는 현상.

| 답안 축 | 정리 포인트 |
|:---|:---|
| 출제 맥락 | 요구 도출부터 우선순위, 명세, 추적성까지 품질 좋은 요구를 만드는 분석 출제축 |
| 1교시 기본 골격 | 정의 -> 목적 -> 핵심 요소/절차 -> 장단점/지표 -> 적용 판단 |
| 함께 묶을 논점 | 요구공학, SRS, RTM, 유스케이스, DFD, QFD, MoSCoW, 스토리맵 |
| 2~4교시 확장 방향 | 문제 상황과 이해관계자 관점, 도출·분석·명세 절차, 도구/기법 비교, 변경 통제와 검증 적용 |


- 답안 포인트
  - `골드 플래팅 (Gold Plating)`가 해결하려는 문제와 목적을 첫 문장에 압축
  - 핵심 구성요소·절차·지표는 3~5개 축으로 정리
  - 비교 개념과 실무 적용 조건을 함께 적시해 확장성 확보

## Ⅱ. 핵심 구조 및 메커니즘
- 원인: 개발자 완벽주의, 기술 과시, 잉여 시간 활용
- 결과: 일정·비용 증가, 복잡도·결함 위험 상승
- 가치 부재: 고객 가치 없이 검증·유지보수 부담만 증가
- 범위크리프와 구분: 자발적 추가(골드플래팅) vs 외부 요구확대(크리프)
- 예방: 요구사항 기준 준수, RTM으로 역방향 추적

## Ⅲ. 비교·구조·지표 정리
```text
요구범위 ┊ + 요청없는 기능(개발자 자발)
          ↓
   비용↑ 복잡도↑ 결함위험↑ (고객가치 0)
   [예방] RTM 역추적·범위준수로 차단
```

| 구분 | 내용 |
|:---|:---|
| 목적 | 요청 없는 과잉 기능의 위험 인식 |
| 장점 | 인식 시 자원 낭비·품질저하 예방 가능 |
| 한계 | 선의의 추가라 통제 동기 약함 |

## Ⅳ. 실무 적용 및 기술사 판단
- RTM 역방향 추적으로 근거 없는 산출물 식별
- 애자일의 YAGNI(You Aren't Gonna Need It) 원칙으로 억제
- 범위크리프와 함께 범위관리 위험요인으로 비교 출제

- 답안 포인트
  - 도입 전제, 운영 리스크, 기대 효과를 한 세트로 기술
  - 조직·프로세스·아키텍처 관점의 판단 기준을 함께 제시

## Ⅴ. 2~4교시 확장 프레임
| 확장 문단 | 서술 포인트 |
|:---|:---|
| 서론 | 문제 상황과 이해관계자 관점 |
| 본론 1 | 도출·분석·명세 절차 |
| 본론 2 | 도구/기법 비교 |
| 본론 3 | 변경 통제와 검증 적용 |
| 결론 | 실패 예방 효과 |


- 전개 순서
  1. 문제 배경과 필요성 제시
  2. 핵심 원리·구성요소·절차 설명
  3. 대안 구조 또는 유사 개념과 비교
  4. 도입 효과, 리스크, 기술사 판단 정리
  5. 확장 방향과 결론으로 마무리
