## 핵심 인사이트 (3줄 요약)

> 1. **본질**: 데이터베이스(Database)는 무결성(Integrity)·동시성(Concurrency)·복구(Recovery)·확장성(Scalability)을 동시에 설계해야 하는 시스템 응용의 핵심 저장 계층이다.
> 2. **가치**: 정규화·인덱스·트랜잭션(ACID)으로 정합성과 성능을 잡고, 샤딩(Sharding)·복제·일관성 모델로 분산 확장까지 설명해야 답안이 단단해진다.
> 3. **판단 포인트**: NoSQL/NewSQL, 벡터 데이터베이스(Vector Database), 레이크하우스(Lakehouse)까지 연결해야 최신성과 기술사 통찰이 확보된다.

## Ⅱ. 1교시 단답형 핵심 (앞단위)

> 1교시 답안 공식 1줄: **정의 1문장 + 핵심 3포인트 + 미니 도해/표 1개 + 비교·적용 1줄** (약어는 최초 1회 풀네임 병기, 10분 내 완성).

| 키워드 | 한줄 정의 | 핵심 3포인트 |
|:---|:---|:---|
| ACID | 트랜잭션이 보장해야 할 4대 성질 | ① 원자성(All-or-Nothing) ② 일관성(무결성 유지) ③ 격리성(병행제어) ④ 영속성(로그/회복) |
| 트랜잭션(Transaction) | 분할 불가한 논리적 작업 단위 | ① 상태전이 Active→Committed/Aborted ② COMMIT/ROLLBACK/SAVEPOINT ③ 원자성·영속성은 회복관리자 보장 |
| 격리수준(Isolation Level) | 동시 트랜잭션 간섭 허용 정도 ANSI 4단계 | ① Read Uncommitted~Serializable ② 단계↑ 일관성↑·동시성↓ ③ Dirty/Non-Repeatable/Phantom Read 차단 범위 |
| 동시성 제어(Concurrency Control) | 병행 수행 시 일관성 유지 기법 | ① Lock(S/X) 2PL ② Timestamp Ordering ③ 낙관/MVCC, 처리량 극대화 목적 |
| MVCC | 다중 버전 동시성 제어, 읽기-쓰기 락 충돌 배제 | ① 스냅샷 읽기 ② Undo 세그먼트로 구버전 유지 ③ 읽기가 쓰기 안 막음(Oracle·PostgreSQL 기본) |
| 정규화(Normalization) | 이상현상 제거 위해 릴레이션 분해 과정 | ① 1NF(원자값)~BCNF(결정자=후보키) ② 삽입·삭제·갱신 이상 제거 ③ 무손실 분해·종속성 보존 |
| 반정규화(De-normalization) | 성능 위해 중복 허용·정규화 의도적 위배 | ① 테이블 병합/분할 ② 중복·파생컬럼 추가 ③ 조인 오버헤드↓ vs 정합성 관리 부담↑ |
| 함수적 종속성(FD) | X값이 Y값을 유일 결정(X→Y) | ① 완전/부분 종속(2NF) ② 이행 종속(3NF) ③ Armstrong 공리(반사·첨가·이행) |
| 인덱스(Index) | 검색 속도 향상 자료구조(별도 공간) | ① B+Tree(범위)·Hash(동등)·Bitmap(저분포) ② 클러스터드/넌클러스터드 ③ DML 시 갱신 오버헤드 |
| 무결성(Integrity) | DB 정확성·일관성 보장 제약조건 | ① 개체(PK NULL불가) ② 참조(FK) ③ 도메인·사용자정의(CHECK) |
| 옵티마이저(Optimizer) | 최적 SQL 실행계획 생성기 | ① CBO(통계 기반 비용) vs RBO(규칙) ② 실행계획·힌트 ③ NL/Sort-Merge/Hash 조인 선택 |
| 조인(Join) | 공통 속성 기준 두 릴레이션 결합 | ① Inner/Outer/Cross/Self ② NL(소량)·Sort-Merge·Hash(대량 동등) ③ 드라이빙/드리븐 순서 |
| 트랜잭션 회복(Recovery) | 장애 전 일관 상태로 DB 복원 | ① WAL(로그 선기록) ② Redo(영속성)/Undo(원자성) ③ Checkpoint·ARIES 알고리즘 |
| 교착상태(Deadlock) | 상호 락 점유로 무한 대기 | ① 예방 Wait-Die/Wound-Wait ② 탐지 Wait-for Graph 사이클 ③ 회피·희생자 롤백 |
| 샤딩(Sharding) | 데이터 수평 분할로 Scale-out | ① 샤드키 설계 ② Hash(균등)/Range(범위, 핫스팟) ③ 일관된 해싱으로 재배치 최소화 |
| NoSQL | Not Only SQL, 스키마리스·수평확장 분산 | ① KV/Document/Column/Graph 4모델 ② BASE·결과적 일관성 ③ 쿼리 주도 모델링 |
| NewSQL | RDB의 ACID + NoSQL 수평확장 결합 | ① Spanner(TrueTime)·CockroachDB·TiDB ② HTAP 지원 ③ 글로벌 분산 강일관성 |
| CAP 정리 | C·A·P 동시 만족 불가(분산 DB 이론) | ① CP(HBase) vs AP(Cassandra) ② 분할 시 택일 ③ PACELC로 지연/일관성 확장 |
| 2PC | 2단계 커밋, 분산 트랜잭션 원자성 보장 | ① Coordinator·Participant ② Prepare→Commit ③ 블로킹 한계→3PC·Saga |
| 벡터 데이터베이스(Vector DB) | 임베딩 벡터 유사도 고속 검색 특화 | ① ANN·HNSW 인덱스 ② 코사인/L2 거리 ③ RAG 연동 환각 방지(Milvus·pgvector) |
| 데이터 웨어하우스(DW) | 의사결정 지원 통합·주제중심·비휘발성 저장소 | ① 주제·통합·시계열·비휘발 4특징 ② ETL/ELT ③ Star/Snowflake 스키마 |

## Ⅲ. 2~4교시 서술형 확장 (심화)

### 1) 트랜잭션 ACID와 동시성 제어

- **정의**: 트랜잭션은 분할 불가한 논리적 작업 단위로 ACID(원자성·일관성·격리성·영속성)를 보장해야 하며, 다중 사용자 환경에서 격리성은 동시성 제어로 구현된다.

- **Ⅰ. 개요**: 병행 수행 시 갱신손실·오손읽기·반복불가읽기·유령읽기가 발생 → 일관성 유지와 처리량 극대화의 균형이 과제.
- **Ⅱ. 구조/원리**:

```text
[트랜잭션 요청]
   ↓
[동시성 제어] → Lock(2PL) / Timestamp / 낙관 / MVCC
   ↓
[직렬가능성 보장] ── 충돌 직렬가능 스케줄
   ↓
[WAL 로그] → Redo/Undo → [Checkpoint·ARIES 회복]
```

- **Ⅲ. 특징/비교**: 아래 낙관/비관 동시성 비교표 참조.
- **Ⅳ. 적용/방안**: OLTP는 Read Committed+MVCC로 블로킹 완화, 정산·재고는 Serializable 또는 명시적 락, 분산은 2PC/Saga.
- **Ⅴ. 결론**: 격리수준은 정합성과 성능의 트레이드오프이며, MVCC 기반 스냅샷 격리가 현대 RDBMS의 기본 선택지로 자리잡았다.

| 구분 | 비관적(Pessimistic, Lock/2PL) | 낙관적(Optimistic)/MVCC |
|:---|:---|:---|
| 가정 | 충돌 빈번 | 충돌 드묾 |
| 시점 | 접근 전 락 획득 | 종료(Validation) 시 검사 / 스냅샷 |
| 장점 | 강한 일관성 보장 | 읽기-쓰기 비차단, 높은 동시성 |
| 단점 | 교착상태·블로킹 | 충돌 시 롤백·재시도, 버전 저장 비용 |
| 적용 | 갱신 충돌 잦은 OLTP | 읽기 위주, 대규모 동시 조회 |

### 2) 정규화와 반정규화

- **정의**: 정규화는 함수적 종속성에 따라 릴레이션을 분해해 이상현상을 제거하는 과정이고, 반정규화는 성능을 위해 의도적으로 중복을 허용하는 역과정이다.

- **Ⅰ. 개요**: 미정규화 시 삽입·삭제·갱신 이상 발생 → 무손실·종속성 보존을 만족하며 분해.
- **Ⅱ. 구조/원리**: 1NF(원자값) → 2NF(부분종속 제거) → 3NF(이행종속 제거) → BCNF(모든 결정자=후보키) → 4NF(다치종속) → 5NF(조인종속).
- **Ⅲ. 특징/비교**: 아래 정규화 vs 반정규화 비교표.
- **Ⅳ. 적용/방안**: 트랜잭션계(OLTP)는 3NF 기준, 조회·분석계(OLAP/DW)는 Star 스키마로 반정규화, 집계컬럼·요약테이블 도입.
- **Ⅴ. 결론**: "정규화로 정합성, 반정규화로 성능"을 워크로드 기준으로 선택하며 과도한 분해는 조인 오버헤드를 키운다.

| 구분 | 정규화 | 반정규화 |
|:---|:---|:---|
| 목적 | 이상현상 제거·정합성 | 조회 성능·조인 감소 |
| 데이터 | 중복 최소 | 중복 허용 |
| 효과 | 무결성↑, 저장공간↓ | 응답속도↑, 관리부담↑ |
| 위험 | 조인 증가로 성능 저하 | 갱신 이상·불일치 가능 |
| 적용 | OLTP 운영계 | OLAP/DW, 대량 조회 |

### 3) 인덱스와 SQL 옵티마이저 튜닝

- **정의**: 인덱스는 검색 속도를 높이는 자료구조이며, 옵티마이저는 통계 기반(CBO)으로 최소 비용 실행계획을 생성한다.

- **Ⅰ. 개요**: 풀스캔과 인덱스 스캔, 조인 기법 선택이 성능을 좌우 → 통계·선택도가 핵심.
- **Ⅱ. 구조/원리**:

```text
[SQL] → [파서] → [옵티마이저(CBO)] → [실행계획]
                      │ 통계/선택도
        ┌─────────────┼──────────────┐
   인덱스 스캔     조인 기법        파티션 프루닝
 (B+Tree/Hash/   (NL/Sort-Merge/   (Range/Hash/List)
   Bitmap)         Hash Join)
```

- **Ⅲ. 특징/비교**: B+Tree(범위·정렬)·Hash(동등)·Bitmap(저분포 컬럼). 결합인덱스는 선행 컬럼 순서가 관건.
- **Ⅳ. 적용/방안**: 선택도 낮은 컬럼 인덱싱, 결합인덱스 순서 최적화, 힌트/바인드 변수로 하드파싱 방지, 대량은 Hash Join.
- **Ⅴ. 결론**: 인덱스는 조회 이득과 DML 오버헤드의 균형 문제이며, 통계 최신화가 옵티마이저 정확도의 전제다.

### 4) 분산 DB · NoSQL · NewSQL과 일관성

- **정의**: 분산 데이터베이스는 단일 시스템처럼 보이는 투명성을 제공하며, NoSQL/NewSQL은 수평 확장과 일관성 모델의 선택으로 대용량을 처리한다.

- **Ⅰ. 개요**: 데이터 증가·글로벌 서비스로 Scale-out 필요 → CAP/PACELC 기반 일관성·가용성 trade-off.
- **Ⅱ. 구조/원리**: 분할(수평/수직)·복제(Master-Slave/Multi-Master)·샤딩(샤드키, 일관된 해싱), 합의(Raft/Paxos)로 리더 선출·로그 복제.
- **Ⅲ. 특징/비교**: 아래 SQL vs NoSQL 비교표.
- **Ⅳ. 적용/방안**: 강일관성 결제는 RDB/NewSQL(Spanner), 대량 쓰기·로그는 Cassandra(AP), 캐시는 Redis, 검색은 Elasticsearch, 폴리글랏 퍼시스턴스로 목적별 혼용.
- **Ⅴ. 결론**: "한 DB로 모두 해결" 대신 워크로드별 최적 저장소 조합과 일관성 수준 합의가 기술사적 판단의 핵심이다.

| 구분 | RDB(SQL) | NoSQL |
|:---|:---|:---|
| 스키마 | 고정(Schema-on-write) | 유연(Schemaless) |
| 확장 | 수직(Scale-up) 중심 | 수평(Scale-out) |
| 일관성 | ACID·강일관성 | BASE·결과적 일관성 |
| 모델 | 테이블·정규화 | KV/Document/Column/Graph |
| 적용 | 트랜잭션·정합성 | 대용량·고가용·유연 스키마 |

## Ⅳ. 출제 포인트 & 함정

| 출제유형 | 1교시 단답 포인트 | 2~4교시 서술 포인트 |
|:---|:---|:---|
| 트랜잭션/격리 | ACID 각 보장 주체, 격리수준 4단계와 이상현상 매핑 | MVCC vs 락 비교, 격리수준별 성능 trade-off 설계 |
| 정규화 | 각 정규형 조건(2NF 부분, 3NF 이행, BCNF 결정자) | 정규화/반정규화 선택 기준, 무손실·종속성 보존 |
| 인덱스/튜닝 | B+Tree vs Hash vs Bitmap, 클러스터드/넌클러스터드 | CBO 실행계획, 조인 3기법 선택, 결합인덱스 순서 |
| 회복/장애 | WAL, Redo/Undo, Checkpoint, ARIES 3단계 | 장애 유형별 복구 절차, 미디어 회복·롤포워드 |
| 분산/일관성 | CAP·PACELC, 2PC/3PC, 샤딩·복제 투명성 | NoSQL 모델 선택, Saga·결과적 일관성 설계 |
| 최신 저장소 | 벡터 DB·HNSW·RAG, 레이크하우스, HTAP | 워크로드별 폴리글랏 아키텍처, AI 연계 검색 |

- **함정 1**: ACID의 일관성(Consistency)과 CAP의 일관성을 혼동 — 전자는 무결성, 후자는 복제본 간 동일성.
- **함정 2**: BCNF는 "모든 결정자가 후보키" — 3NF 만족해도 BCNF 위배 가능(결정자가 후보키 아닐 때).
- **함정 3**: 인덱스가 항상 빠르지 않음 — 분포도 높은 소량 조회만 이득, 대량·저선택도는 풀스캔이 유리하고 DML 오버헤드 발생.
- **함정 4**: MVCC가 모든 이상현상 제거하지 않음 — 스냅샷 격리는 Write Skew 등 일부 이상 잔존, Serializable과 구분.
- **함정 5**: Hash 인덱스/Hash 조인은 동등(=) 조건 전용 — 범위 검색 불가.
- **함정 6**: 약어 풀네임 누락 — ACID·MVCC·CAP·WAL·ETL·OLTP/OLAP는 최초 1회 풀네임 병기.
