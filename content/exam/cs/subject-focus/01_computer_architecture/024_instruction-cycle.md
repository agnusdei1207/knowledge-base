## Ⅰ. 정의
> CPU가 하나의 명령어를 인출(Fetch)·해독(Decode)·실행(Execute)하는 일련의 반복 절차로, 프로그램 수행의 최소 단위 주기이다.

## Ⅱ. 구성요소 / 원리
- 인출(Fetch): PC(Program Counter)가 가리키는 주소의 명령어를 MAR→MBR 경유로 IR(Instruction Register)에 적재
- 해독(Decode): 제어장치가 OP-code를 분석하여 제어신호 생성
- 실행(Execute): ALU 연산·레지스터/메모리 접근 수행
- 간접(Indirect) 사이클: 간접주소지정 시 유효주소 재인출
- 인터럽트(Interrupt) 사이클: 명령 종료 후 인터럽트 요청 점검·처리

## Ⅲ. 흐름도 / 구조
```text
   ┌────────┐   ┌────────┐   ┌────────┐   ┌──────────┐
   │ Fetch  │──▶│ Decode │──▶│Execute │──▶│Interrupt?│
   └────────┘   └────────┘   └────────┘   └────┬─────┘
        ▲                                       │ Y/N
        └───────────────────────────────────────┘
   PC+1 → 다음 명령어 인출 반복
```

## Ⅳ. 핵심 특징
| 구분 | 내용 |
|:---|:---|
| 목적 | 명령어를 정해진 절차로 자동 반복 수행 |
| 장점 | 단순·규칙적 제어, 파이프라이닝의 기본 골격 |
| 한계 | 단일 사이클 직렬 수행 시 클럭당 처리량 저하 |

## Ⅴ. 기술사적 적용
- 각 단계를 분할·중첩하면 명령어 파이프라이닝(IF·ID·EX·MEM·WB)으로 발전
- 인터럽트 사이클은 멀티태스킹·실시간 OS의 컨텍스트 스위칭 기반
