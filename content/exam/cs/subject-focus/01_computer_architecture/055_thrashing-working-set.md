## Ⅰ. 정의
> 스래싱(Thrashing)은 과도한 페이지 폴트로 CPU가 페이지 교체에만 시간을 쓰는 성능 급락 현상이며, 워킹셋(Working Set)은 일정 시간 동안 실제 참조한 페이지 집합으로 스래싱 방지의 기준.

## Ⅱ. 구성요소 / 원리
- 발생 원인: 다중 프로그래밍 과다로 프로세스당 프레임 부족
- 워킹셋 모델: 윈도우 Δ 내 참조 페이지 집합 W(t,Δ) 만큼 프레임 보장
- PFF(Page Fault Frequency): 폴트율 상·하한으로 프레임 동적 조절
- 증상: CPU 이용률↓인데 다중도↑하면 더 악화(역설)
- 대응: 다중 프로그래밍 정도 조절, 스왑아웃, 메모리 증설

## Ⅲ. 흐름도 / 구조
```text
다중도↑ → 프레임 부족 → 폴트 폭증 → CPU 유휴↑
   → (오판)다중도 더↑ → 스래싱 심화 ↘ 성능 붕괴
  대응: WorkingSet 확보 / PFF로 다중도 하향
```

## Ⅳ. 핵심 특징
| 구분 | 내용 |
|:---|:---|
| 목적 | 폴트 폭증에 의한 성능 붕괴 예방·제어 |
| 장점(모델) | 워킹셋·PFF로 적정 다중도 유지, 안정 동작 |
| 한계 | 윈도우 Δ 설정 민감, 워킹셋 추적 오버헤드 |

## Ⅴ. 기술사적 적용
- 비교: 지역성 변화(국면 전환) 시 워킹셋 급변 대응
- 실무: cgroup 메모리 제한, OOM Killer, 스왑 튜닝
- 최신: 메모리 압축·CXL 메모리 확장으로 스래싱 완화
