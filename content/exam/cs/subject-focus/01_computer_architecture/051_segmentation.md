## Ⅰ. 정의
> 메모리를 코드·데이터·스택 등 논리적 의미 단위(세그먼트)의 가변 크기로 분할하여 관리하는 기법으로, 사용자 관점의 논리 구조를 반영한다.

## Ⅱ. 구성요소 / 원리
- 세그먼트: 논리 단위(코드·데이터·스택·힙), 가변 길이
- 주소 = 세그먼트 번호(Segment #) + 변위(Offset)
- 세그먼트 테이블: 기준주소(Base) + 한계(Limit) + 보호비트
- 보호: Limit 검사로 경계 초과 접근 차단, 세그먼트별 권한 부여
- 한계: 가변 크기로 외부 단편화 발생

## Ⅲ. 흐름도 / 구조
```text
주소 = | Seg# | Offset |
         ↓
 Seg Table[Seg#] → Base, Limit
   Offset < Limit ? ─yes→ PA = Base + Offset
                    └no → 보호 위반(Trap)
```

## Ⅳ. 핵심 특징
| 구분 | 내용 |
|:---|:---|
| 목적 | 논리적 의미 단위 관리·보호·공유 용이 |
| 장점 | 모듈별 보호·공유 직관적, 동적 크기 지원 |
| 한계 | 외부 단편화 발생, 가변 길이 관리 복잡 |

## Ⅴ. 기술사적 적용
- 비교: 페이징(외부 단편화 없음)과 결합 → 세그먼트드 페이징
- 실무: x86 보호모드 세그먼트, 현대 OS는 플랫 모델로 단순화
- 최신: 페이징 중심으로 전환, 세그먼트는 보호/스레드 베이스 용도
