## Ⅰ. 정의
> 컴파일러가 병렬 실행 가능한 다수의 연산을 하나의 긴 명령어로 묶어 발행하는 정적 다중발행 구조로, 하드웨어 의존성 검사를 컴파일러로 이관한다.

## Ⅱ. 구성요소 / 원리
- 하나의 명령어 = 여러 연산 슬롯(각 슬롯이 독립 실행 유닛 대응)
- 컴파일러가 ILP 추출·정적 스케줄링·의존성 해소 수행
- 병렬성 부족 슬롯은 NOP으로 채움
- 단순 하드웨어(스케줄링 로직 불필요), 트레이스/소프트웨어 파이프라이닝 활용

## Ⅲ. 흐름도 / 구조
```text
┌──────── 1개의 긴 명령어(VLIW) ────────┐
│ OP1(ALU) │ OP2(FPU) │ OP3(LD) │ NOP   │
└────┬─────────┬──────────┬───────┘
     ▼         ▼          ▼   동시 발행·병렬 실행
```

## Ⅳ. 핵심 특징
| 구분 | 내용 |
|:---|:---|
| 목적 | 컴파일러 기반 정적 ILP로 하드웨어 단순화 |
| 장점 | 제어 간단·저전력, 결정적 스케줄 |
| 한계 | 코드 호환성↓, NOP 코드팽창, 동적 사건(캐시미스) 대응 약 |

## Ⅴ. 기술사적 적용
- 슈퍼스칼라(동적 발행) 대비 컴파일러 의존 정적 발행 방식
- Intel Itanium(EPIC), DSP·GPU 셰이더 등 특수 도메인에 적용
