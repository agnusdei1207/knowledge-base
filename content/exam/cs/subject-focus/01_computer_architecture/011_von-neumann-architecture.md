## Ⅰ. 정의
> 프로그램(명령어)과 데이터를 동일한 메모리에 저장하고 단일 버스로 순차 처리하는 내장 프로그램(Stored Program) 방식 컴퓨터 구조이며, CPU-메모리 간 단일 통로로 인해 발생하는 성능 한계를 폰 노이만 병목현상이라 한다.

## Ⅱ. 구성요소 / 원리
- CPU: 제어장치(CU) + 연산장치(ALU) + 레지스터로 명령어 인출·해독·실행
- 주기억장치(Memory): 명령어와 데이터를 같은 공간에 저장
- 단일 시스템 버스(Address/Data/Control Bus)로 CPU-메모리 연결
- 동작 원리: 내장 프로그램 개념 + Fetch→Decode→Execute 순차 실행
- 병목: CPU 처리속도 ≫ 메모리 대역폭 → 단일 버스가 병목

## Ⅲ. 흐름도 / 구조
```text
 ┌──────CPU──────┐        ┌──── Memory ────┐
 │ CU │ ALU │ Reg│◀──────▶│ 명령어 + 데이터 │
 └───────────────┘ 단일버스 └────────────────┘
        ▲  (Address/Data/Control) — 병목 지점
   Fetch→Decode→Execute (순차)
```

## Ⅳ. 핵심 특징
| 구분 | 내용 |
|:---|:---|
| 목적 | 내장 프로그램으로 범용·유연한 명령 실행 구조 제공 |
| 장점 | 구조 단순, 프로그램 교체 용이, 설계·구현 비용 저렴 |
| 한계 | 단일 버스 병목, 명령어·데이터 동시 접근 불가로 성능 제약 |

## Ⅴ. 기술사적 적용
- 하버드 아키텍처(명령/데이터 버스 분리)로 병목 완화
- 캐시 메모리·파이프라인·멀티코어로 메모리 벽(Memory Wall) 대응
- HBM, PIM(Processing-in-Memory)로 대역폭 한계 극복 시도
