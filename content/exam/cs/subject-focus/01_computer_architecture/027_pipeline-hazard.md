## Ⅰ. 정의
> 파이프라인에서 명령어를 정상 클럭에 진행시키지 못하게 하는 장애 요인으로, 구조적·데이터·제어 해저드로 구분된다.

## Ⅱ. 구성요소 / 원리
- 구조적(Structural) 해저드: 자원 충돌(단일 메모리·포트 부족), 자원 중복·분리로 해소
- 데이터(Data) 해저드: 명령어 간 데이터 의존성(RAW/WAR/WAW), 포워딩·스톨로 해소
- 제어(Control) 해저드: 분기로 인한 PC 불확실, 분기예측·지연분기로 해소
- 해소 미흡 시 스톨(버블) 삽입으로 성능 저하

## Ⅲ. 흐름도 / 구조
```text
        ┌─ 구조적 ─ 자원충돌 ─▶ 자원 추가/분리
Hazard ─┼─ 데이터 ─ 의존성   ─▶ Forwarding / Stall
        └─ 제어   ─ 분기      ─▶ Branch Prediction / Delayed Branch
```

## Ⅳ. 핵심 특징
| 구분 | 내용 |
|:---|:---|
| 목적 | 파이프라인 정확성 보장(해저드 인식·대응) |
| 장점 | 적절 해소 시 처리량 유지 |
| 한계 | 스톨·플러시로 CPI 증가, 성능 저하 |

## Ⅴ. 기술사적 적용
- 데이터 해저드는 포워딩·비순차실행(OoO)으로, 제어 해저드는 동적 분기예측·BTB로 완화
- 컴파일러 명령어 스케줄링(정적)과 하드웨어 기법(동적)의 협업 설계
