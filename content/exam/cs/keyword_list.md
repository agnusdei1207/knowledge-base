## Ⅰ. 개요

- **정의**: 컴퓨터시스템응용기술사 키워드 목록은 16과목 방대한 개념 중 시험 답안으로 바로 전환해야 하는 핵심 주제만 추려, 1교시 단답형과 2~4교시 서술형 관점으로 재구성한 실전용 정리표이다.
- **필요성**: `studynote/`의 9,103개 학습 노트는 개념 이해용 범위가 넓기 때문에, 시험 직전 회독에서는 반복 출제군, 최신 출제군, 비교형 주제를 별도로 압축할 필요가 있다.
- **활용 원칙**:
  1. 1교시는 정의 1문장 + 핵심 3포인트로 전환 가능한 키워드를 우선 본다.
  2. 2~4교시는 구조도, 비교표, 적용 방안으로 확장 가능한 키워드를 우선 본다.
  3. 학습용 상세 개념은 `studynote/`, 시험용 압축 키워드는 `exam/`으로 분리한다.

## Ⅱ. 핵심 출제 구조 및 분류

```text
[16과목 학습 노트]
        ↓
[시험 빈출 키워드 압축]
        ↓
 ┌───────────────┬───────────────┬───────────────┐
 │ 반복 출제군   │ 비교형 주제군 │ 최신 확장군   │
 └───────────────┴───────────────┴───────────────┘
        ↓
[1교시 단답 / 2~4교시 서술형 답안 전환]
```

- **반복 출제군**: 교착상태, 캐시, 정규화, 인덱스, MSA, Zero Trust 같이 정의형과 구조형으로 반복되는 주제
- **비교형 주제군**: VM vs Container, SQL vs NoSQL, Monolith vs MSA, RDB vs NewSQL처럼 선택 기준이 필요한 주제
- **최신 확장군**: LLM, RAG, MLOps, SBOM, PQC, DPU, CXL처럼 최근 기술 이슈와 연결되는 주제

| 클라우드/인프라 | Kubernetes, IaC, Observability, FinOps, Serverless | 운영 자동화, 책임 분담, 비용 최적화 |
| AI/데이터 | LLM, RAG, 벡터DB, MLOps, 데이터 레이크하우스 | 구조도, 학습/추론 분리, 품질과 거버넌스 |

## Ⅳ. 실전 적용 및 기술사적 판단

### 1. 1교시 단답형 우선 키워드

- 정의형: 캐시 메모리, 세마포어, 정규화, CAP 정리, Zero Trust
- 구조형: 파이프라인, TCP 3-way handshake, Kubernetes 구성요소, RAG 구조
- 비교형: 프로세스 vs 스레드, SQL vs NoSQL, VM vs 컨테이너

### 2. 2~4교시 서술형 확장 키워드

| 문제 유형 | 추천 키워드 | 전개 방식 |
|:---|:---|:---|
| 설명형 | MSA, 서비스 메시, 레이크하우스, MLOps | 정의 → 구조도 → 특징 → 적용 |
| 비교형 | Monolith vs MSA, RDB vs NoSQL, VM vs Container | 비교표 + 선택 기준 |
| 방안형 | 공급망 보안 강화, 장애 대응 체계, 데이터 거버넌스 | 문제점 → 원인 → 개선안 |
| 설계형 | 쿠버네티스 기반 플랫폼, Observability 체계, 데이터 파이프라인 | 계층도 + 구성요소 + 운영 절차 |

### 3. 기술사적 판단 포인트

1. 단순 정의보다 성능, 운영 복잡도, 비용, 보안성을 함께 묶어 써야 점수가 올라간다.
2. 최신 기술 키워드는 단독 암기보다 기존 기술과의 비교 기준이 있어야 한다.
3. 기출 반복 키워드는 과목 간 중복이 많으므로 대표 답안 구조 하나로 수렴해야 한다.

## Ⅴ. 결론 및 회독 방향

- 컴퓨터시스템응용기술사 키워드 회독은 `전 범위 학습`과 `시험 답안화`를 분리해서 운영해야 효율이 높다.
- `studynote/`는 개념 이해와 장기 누적 학습, 본 문서는 시험 직전 압축 회독 기준으로 사용한다.
- 향후 AI·클라우드·보안 융합 출제가 강화될수록 반복 출제군에 최신 확장군을 연결하는 방식으로 답안을 진화시켜야 한다.
