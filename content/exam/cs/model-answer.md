## ⛔ 절대 금지 — 추상 표현 (점수 0)

추상 표현은 채점자가 읽지 않는다. 아래 형태가 답안에 나오면 즉시 구체 표현으로 교체한다.

| 쓰면 안 되는 표현 | 반드시 써야 하는 표현 |
|:---|:---|
| 성능이 좋다 / 빠르다 | p99 지연 50ms 이하, 처리량 10,000 TPS, 캐시 적중률 95% |
| 보안이 강화된다 | AES-256 암호화, mTLS 인증, RBAC 접근통제, CVE 스캔 자동화 |
| 안정적이다 / 신뢰성이 높다 | RTO 4분 이하, RPO 15분, 가용성 99.9%, MTTR 10분 |
| 효율적이다 / 최적화된다 | CPU 이용률 70%→40%, 메모리 30% 절감, 배포 시간 45분→8분 |
| 유연하다 / 확장성이 있다 | 수평 스케일아웃, HPA min2/max20, 오토스케일링 30초 반응 |
| 최신 기술이다 | 기존 방식의 구체적 한계 + 신기술이 해결하는 수치 |
| 보안 위협을 대응한다 | MITRE ATT&CK TTP 매핑, 탐지 규칙 ID, 대응 플레이북 |
| 품질이 향상된다 | 결함밀도 2.1→0.8/KLOC, 테스트 커버리지 40%→80% |

**규칙: 형용사·부사로 끝나는 문장은 쓰지 않는다. 반드시 수치·표준명·기술명·비교값으로 끝낸다.**

---

## 사용 원칙

- 첫 줄 1문장 정의 (주어 + 동사 + 목적어, 30자 이내)
- 5초 안에 구조가 보이도록 `정의 → 구조/원리 → 비교/절차 → 결론`
- 1교시는 Ⅰ~Ⅲ까지, 2~4교시는 Ⅰ~Ⅴ 고정
- 약어는 최초 1회 풀네임 병기 (예: RAG(Retrieval-Augmented Generation))

---

## 1교시 단답형 템플릿

1교시 답안은 독립 문서가 아니라, 2~4교시 답안의 앞부분인 `Ⅰ. 개요 + Ⅱ. 구조·동작원리`를 압축해서 먼저 멈춘 형태다.

````markdown
### [키워드]

- **정의**: [개념의 본질 1문장]
- **핵심 1**: [구성요소/원리]
- **핵심 2**: [장점/효과]
- **핵심 3**: [한계/유의점/비교 포인트]
- **미니 구조**: [입력/요구] → [핵심 메커니즘] → [효과/결과]
- **적용/출제 포인트**: [실무 또는 비교 대상]
````

### 1교시 빠른 변형 규칙

| 유형 | 답안 포인트 | 미니 도식 |
|:---|:---|:---|
| 정의형 | 정의 1줄 + 특징 3개 | `입력 → 처리 → 효과` 3칸 |
| 비교형 | 공통점 1개 + 차이점 3개 | `A vs B` 2칸 비교 |
| 구조형 | 구성요소 3개 + 흐름도 | `구성 A → 구성 B → 구성 C` |
| 장단점형 | 장점 2개 + 단점 1개 + 적용처 | `장점 / 한계 / 적용` 3칸 |

## 2~4교시 서술형 템플릿

2~4교시 답안은 같은 답안을 `Ⅰ~Ⅱ`까지 쓴 뒤 `Ⅲ~Ⅴ`의 딥 논의로 이어가는 구조다.
- `Ⅱ. 구조 및 구성요소`: 박스 구성도(ASCII) + 구성요소 표 + 한 줄 요약
- `Ⅲ. 동작원리 및 흐름도`: 흐름도(ASCII) + 단계 표 + 한 줄 요약
- 표를 쓰면 반드시 한 줄 요약(`> 요약:`)을 바로 아래 적는다
- 구조·흐름도는 ASCII 아트와 표 **양쪽 다** 작성한다
- `Ⅳ. 특징` — "핵심특징" 금지, 반드시 "특징"만 사용

````markdown
## [문제명]

### Ⅰ. 개요
- **정의**: [핵심 개념 1문장]
- **배경/필요성**: [출제 배경 2~3]
- **답안 방향**: [이 답안에서 끌고 갈 축 3]

### Ⅱ. 구조 및 구성요소
```text
[ASCII 구조도: 박스 3~5개 + 화살표, 10~15초 안에 그린다]
┌──────────┐   ┌──────────┐   ┌──────────┐
│ 구성 A   │──▶│ 구성 B   │──▶│ 구성 C   │
└──────────┘   └──────────┘   └──────────┘
```

| 구성요소 | 역할 | 산출물 |
|:---|:---|:---|
| 구성 A |  |  |
| 구성 B |  |  |
| 구성 C |  |  |

> 요약: [구성요소가 어떤 역할을 하는지 1문장]

### Ⅲ. 동작원리 및 흐름도
```text
[ASCII 흐름도: 입력 → 처리 → 통제 → 출력]
입력/요구 → 핵심 처리 → 검증/통제 → 결과 출력
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 입력/요구 식별 | 업무 적합성 |
| 2 | 핵심 처리 수행 | 성능·정확성 |
| 3 | 통제·검증 적용 | 안정성·감사성 |
| 4 | 출력·효과 확인 | 지표 충족 여부 |

> 요약: [어떤 순서로 어떻게 동작하는지 1문장]

**※ 여기까지가 1교시 답안 범위 (2/3~1쪽)**
**──────[딥 논의 분기점]──────**

### Ⅳ. 특징
| 구분 | 내용 | 판단 포인트 |
|:---|:---|:---|
| 장점 |  |  |
| 한계 |  |  |
| 비교 포인트 |  |  |

> 요약: [핵심 장단점 또는 비교 포인트 1문장]

### Ⅴ. 적용방안·결론
1. 단기: [현황 진단, PoC, 표준 수립]
2. 중기: [아키텍처 전환, 자동화, 거버넌스]
3. 장기: [운영 고도화, 지표 관리, 지속 개선]

| 리스크 | 원인 | 대응 | 기대효과 |
|:---|:---|:---|:---|
|  |  |  |  |

> 요약: [적용 시 핵심 판단 기준 1문장]

- 기술사적 판단: [조건별 선택 기준]
- 기술사 제언: [실무 적용 시사점 1줄]
- 향후 발전 방향
````

### 서술형 문항 유형별 치환 규칙

| 문제 표현 | Ⅲ에서 강조 | Ⅳ에서 강조 |
|:---|:---|:---|
| 설명하시오 | 구성요소, 원리 | 적용 사례 |
| 비교하시오 | 표 중심 차이점 | 선택 기준 |
| 방안을 제시하시오 | 문제 원인 | 단계별 개선안 |
| 설계하시오 | 아키텍처 | 구성 기준, 운영 절차 |
| 문제점과 대책 | 리스크 | 원인-대책 매핑 |

## 구조도 예시

다음 형태를 손으로 먼저 그린 뒤, 각 박스 아래에 핵심 키워드 1~2개만 덧붙인다.

```text
┌──────────┐   ┌──────────┐   ┌──────────┐
│ 입력/요구 │──▶│ 핵심 처리 │──▶│ 효과/성과 │
└──────────┘   └──────────┘   └──────────┘
```

16과목별 확장 포인트는 [컴퓨터시스템응용기술사 2~4교시 통합 답안 템플릿](@/exam/cs/master-template.md)의 `Ⅲ. 16과목 적용 포인트`를 따른다.

## 16과목 매핑표

| 과목 | 1교시에서 끊기는 앞부분(Ⅰ~Ⅱ) | 2~4교시 딥 논의(Ⅲ~Ⅴ) |
|:---|:---|:---|
| 01 컴퓨터구조 | 계층, 병목, 성능지표, 기본 메커니즘 | 성능 향상 기법 비교, 병목 해소 판단 |

| 03 네트워크 | 계층, 주소, 프로토콜 구조·흐름 | 제어평면/데이터평면 비교, 품질·보안 판단 |

| 07 엔터프라이즈 시스템 | EA, ERP, EAI, BPM 구조 | AS-IS/TO-BE, 통합 전략 판단 |

## 2~4교시 필수 확장 체크

| 항목 | 확인 기준 |
|:---|:---|
| Ⅰ 개요 | 정의-배경-답안 방향이 한 호흡으로 이어지는가 |
| Ⅱ 구조 | 구조(구성요소)와 원리(흐름)가 짝으로 분리되었는가 |
| Ⅲ 비교 | 비교표/특징표가 있는가 |
| Ⅳ 적용 | 단계별 방안 또는 리스크 대응이 있는가 |
| Ⅴ 결론 | 조건별 선택 기준과 기술사 제언이 있는가 |

## 답안 압축 체크리스트

- 정의가 첫 줄에 있는가
- 도해가 1개 이상 있는가
- 서술형은 표가 1개 이상 있는가
- 비교 문제는 선택 기준이 있는가
- 결론에 기술사 제언 또는 본인 의견 한 줄이 있는가
- 결론이 기술사적 판단으로 끝나는가
