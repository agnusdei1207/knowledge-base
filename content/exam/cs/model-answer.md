---

## 사용 원칙

- 첫 줄 1문장 개요 (주어 + 동사 + 목적어, 30자 내외 — 정의 1문장은 짧게, 부연은 별도 불렛으로)
- 5초 안에 구조가 보이도록 `개요 -> 구조/원리 -> 비교/절차 -> 결론`
- 1교시는 Ⅰ~Ⅲ까지, 2~4교시는 Ⅰ~Ⅵ 고정
- 약어는 최초 1회 풀네임 병기 (예: RAG(Retrieval-Augmented Generation))
- 정보 나열 금지: 문제 신호어에서 출제 의도를 읽고, 반드시 짚을 핵심·비교축·감점 회피 포인트를 먼저 고정한다
- 출제 의도 표는 노트·연습용 장치다: 실전 답안지에는 표를 그대로 옮기지 않고, Ⅰ. 개요의 "답안 방향" 불렛에 녹여 쓴다

---

## 1교시 단답형 템플릿

1교시 답안은 독립 문서가 아니라, 2~4교시 답안의 앞부분인 `Ⅰ. 개요 + Ⅱ. 구조 및 구성요소 + Ⅲ. 동작원리 및 흐름도`(Ⅰ~Ⅲ)를 압축해서 먼저 멈춘 형태다.

````markdown
### [키워드]

- **개요**: [개념의 본질 1문장]
- **핵심 1**: [구성요소/원리]
- **핵심 2**: [장점/효과]
- **핵심 3**: [한계/유의점/비교 포인트]
- **미니 구조**: [입력/요구] -> [핵심 메커니즘] -> [효과/결과]
- **적용/출제 포인트**: [실무 또는 비교 대상]
````

### 1교시 빠른 변형 규칙

| 유형 | 답안 포인트 | 미니 도식 |
|:---|:---|:---|
| 설명형 | 개요 1줄 + 특징 3개 | `입력 -> 처리 -> 효과` 3칸 |
| 비교형 | 공통점 1개 + 차이점 3개 | `A vs B` 2칸 비교 |
| 구조형 | 구성요소 3개 + 흐름도 | `구성 A -> 구성 B -> 구성 C` |
| 장단점형 | 장점 2개 + 단점 1개 + 적용처 | `장점 / 한계 / 적용` 3칸 |

## 2~4교시 서술형 템플릿

2~4교시 답안은 1교시의 `Ⅰ~Ⅲ` 압축판을 `Ⅳ~Ⅵ`의 특징·심화 비교·적용·결론으로 확장하는 구조다.
- `Ⅱ. 구조 및 구성요소`: 텍스트 구조도 + 구성요소 표 + 한 줄 요약
- `Ⅲ. 동작원리 및 흐름도`: 텍스트 흐름도 + 단계 표 + 한 줄 요약
- **금지되는 것은 "박스 모양"이 아니라 "유니코드 박스 그리기 문자"다.** `┌ ┐ └ ┘ │(세로선용) ─ ▶ ├ ┤ ┬ ┴ ┼` 같은 특수 유니코드 글리프는 폰트·폭에 따라 웹·모바일에서 깨지므로 금지. 대신 일반 ASCII 문자 `+ - | / \ > < v ^`만 쓴다 — 이 문자들로는 박스(`+---+` / `|  |` / `+---+`)도, 화살표도 전부 안전하게 표현 가능하다.
- **박스 vs 화살표 체인, 둘 다 쓸 수 있다.** Ⅱ.구조 및 구성요소처럼 "이게 무엇으로 구성되는가"를 보여줄 땐 손으로 자를 대고 그리는 실제 답안과 닮은 **ASCII 박스**(`+----+` 테두리)가 오히려 더 실전에 가깝다. Ⅲ.동작원리처럼 "무엇이 무엇으로 이어지는가"를 보여줄 땐 화살표 체인(`A -> B -> C`)이 더 간결하다. 상황에 맞게 고른다(하나로 통일하지 않아도 됨).
- **가로로만 욱여넣지 않는다.** 요소가 4개를 넘거나 가로 폭이 좁아지면 세로 방향(`|`로 잇고 `v`로 화살표머리 표시)으로 바꾼다. 예:
  ```text
  [입력]
    |
    v
  [처리 A] --> [처리 B]
    |
    v
  [출력]
  ```
- **다닥다닥 붙이지 않는다.** 박스·화살표 사이에 최소 1칸 이상 여백을 두고, 요소가 많으면 줄바꿈으로 나눈다. 한 줄에 모든 것을 구겨 넣어 읽기 어렵게 만들지 않는다.
- 표 vs 불릿 선택, `Ⅳ. 특징` 슬롯 판단, 표 아래 `> 요약:` 규칙은 [writing-method.md](@/exam/cs/writing-method.md) `Ⅶ. 표·불릿·구성 판단 규칙`을 따른다 — 아래 골격의 표는 예시일 뿐 개수 하한이 아니다
- `Ⅴ. 심화 비교 및 적용 판단`은 비교·선택 기준, 리스크·대응, 지표·점검을 다루되, 대조 축이 실제로 있을 때만 표로 쓴다
- **절 생략·번호 규칙**: 생략 가능한 절은 Ⅳ뿐이다. Ⅴ·Ⅵ은 생략 금지이며, 절을 생략해도 번호는 당기지 않는다(결론은 항상 `Ⅵ. 실무 적용 및 결론`) — [writing-method.md](@/exam/cs/writing-method.md) Ⅶ `절 생략·번호 규칙`

````markdown
## [문제명]

### Ⅰ. 개요
- **정의**: [핵심 개념 1문장]
- **배경/필요성**: [출제 배경 2~3]
- **출제 의도**: [출제자가 확인하려는 역량: 구조 이해 / 비교 판단 / 설계 방안 / 운영 통제]
- **답안 방향**: [이 답안에서 끌고 갈 축 3]

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| [문제 신호어로 파악한 요구] | [키워드·수치·표준·비교축] | [개념 나열, 요구사항 누락, 추상 표현] |

> 요약: [출제자가 보려는 판단을 1문장으로 고정]

### Ⅱ. 구조 및 구성요소
```text
[텍스트 구조도: 박스 문자 없이 4~6개 요소 + 방향]
입력/요구 -> 구성 A -> 구성 B -> 구성 C -> 산출물
             |           |
             +-> 통제    +-> 관측/검증
```

| 구성요소 | 역할 | 산출물 |
|:---|:---|:---|
| 구성 A |  |  |
| 구성 B |  |  |
| 구성 C |  |  |

> 요약: [구성요소가 어떤 역할을 하는지 1문장]

### Ⅲ. 동작원리 및 흐름도
```text
[텍스트 흐름도: 입력 -> 처리 -> 통제 -> 출력]
입력/요구 -> 핵심 처리 -> 검증/통제 -> 결과 출력
```

- 1단계 [입력/요구 식별]: [무엇을 판정·입력하는지 1줄]
- 2단계 [핵심 처리]: [핵심 연산·변환 1줄]
- 3단계 [검증·통제]: [무엇으로 검증하는지 1줄]
- 4단계 [출력·효과]: [산출물과 확인 지표 1줄]

> 요약: [어떤 순서로 어떻게 동작하는지 1문장]

> ⚠️ 단계는 **순차 과정이므로 기본은 위처럼 번호 불릿**이다. 흐름도가 이미 순서를 보여주므로 같은 단계를 표로 다시 그리지 않는다. 단계마다 '입력·처리·검증'처럼 2개 이상 축의 값이 실제로 모두 채워질 때만 예외로 표를 쓴다 — [writing-method.md](@/exam/cs/writing-method.md) Ⅶ.

**※ 여기까지가 1교시 답안 범위 (2/3~1쪽)**
**[딥 논의 분기점]**

### Ⅳ. 특징
- [장점/특징 1]: [판단 포인트 / 구체적 수치]
- [단점/한계 2]: [판단 포인트 / 제외 조건]
- [특징 3]: [판단 포인트 / 기술명]

> 요약: [특징 한 줄 핵심 — 핵심 장단점 또는 비교 포인트 1문장]

### Ⅴ. 심화 비교 및 적용 판단

| [비교하는 관점의 실제 이름] | [대상 A의 실제 이름] | [대상 B의 실제 이름] | 선택 기준 |
|:---|:---|:---|:---|
| 구조 |  |  |  |
| 비용/성능 |  |  |  |
| 운영/위험 |  |  |  |

> ⚠️ 위 헤더 행의 대괄호 `[ ]` 안은 전부 실제 값으로 교체한다. 특히 첫 칸을 "비교 축"이라는 메타 단어 그대로 쓰지 않는다 — 이 열이 실제로 나열하는 판단 기준의 이름(예: "적재율", "탐색 성능", "구조")을 쓴다. 대괄호 없이 "선택 기준"만 그대로 둔 것은 모든 비교표에 재사용 가능한 고정 라벨이기 때문이다.

> 요약: [어떤 조건에서 무엇을 선택하는지 1문장]

**리스크·대응 (기본은 불릿):**
- [리스크 A]: [원인] → [대응 방안] (지표: [확인 지표])
- [리스크 B]: [원인] → [대응 방안] (지표: [확인 지표])

**도입 후 점검 지표 (기본은 불릿):**
- 성능/효율: [p95·처리량 등 목표 기준] — [측정 방법]
- 품질/운영: [오류율·RTO/RPO 등 목표 기준] — [측정 방법]

> ⚠️ 리스크·지표는 **단일 축 나열이라 기본이 불릿**이다. 리스크가 3개 이상이고 원인·대응·지표가 모두 실질 정보로 채워질 때만 예외로 표를 쓴다 — [writing-method.md](@/exam/cs/writing-method.md) Ⅶ. 반면 위 '비교 축 × 대상' 표는 표가 적합한 자리다.

### Ⅵ. 실무 적용 및 결론
1. 단기: [현황 진단, PoC, 표준 수립]
2. 중기: [아키텍처 전환, 자동화, 거버넌스]
3. 장기: [운영 고도화, 지표 관리, 지속 개선]

- 기술사적 판단: [조건별 선택 기준]
- 기술사 제언: [실무 적용 시사점 1줄]
- 향후 발전 방향
````

### 서술형 문항 유형별 치환 규칙

| 문제 표현 | Ⅱ·Ⅲ에서 강조 | Ⅴ·Ⅵ에서 강조 |
|:---|:---|:---|
| 설명하시오 | 구성요소, 원리 | 적용 사례, 발전 방향 |
| 비교하시오 | 공통 구조·흐름 | 표 중심 차이점, 선택 기준 |
| 방안을 제시하시오 | 문제 원인 구조·영향 흐름 | 단계별 개선안, 우선순위 |
| 설계하시오 | 아키텍처, 처리 흐름 | 구성 기준, 운영 절차 |
| 문제점과 대책 | 원인·영향 구조 | 리스크-원인-대책 매핑 |

## 구조도 예시

화살표 체인 예시 — 흐름·절차를 보여줄 때(요소 사이 여백을 충분히 둔다):

```text
입력/요구 -> 핵심 처리 -> 효과/성과
             |             |
             +-> 통제      +-> 지표 확인
```

박스 예시 — 구성요소·계층을 보여줄 때(유니코드 박스 문자 대신 `+ - |`만 사용):

```text
+------------+       +------------+
|  구성 A    | ----> |  구성 B    |
+------------+       +------------+
      |
      v
+------------+
|  구성 C    |
+------------+
```

가로 폭이 좁거나 요소가 많으면 위처럼 세로(`|`, `v`) 방향으로 바꿔도 된다 — 위 "2~4교시 서술형 템플릿"의 도식 규칙 참조.

공식 8대영역별 확장 포인트는 [컴퓨터시스템응용기술사 2~4교시 통합 답안 템플릿](@/exam/cs/master-template.md)의 `Ⅲ. 공식 8대영역 적용 원칙`을 따른다.

## 공식 8대영역 매핑표

| 대영역 | 1교시에서 끊기는 앞부분(Ⅰ~Ⅲ) | 2~4교시 딥 논의(Ⅳ~Ⅵ) |
|:---|:---|:---|
| 01 컴퓨터 기초이론 | 알고리즘, 자료구조, 통계 개념 | 복잡도, 선택 기준, 정량 비교 |
| 02 하드웨어 시스템 | 구조, 병목, 성능지표 | 병렬화, 메모리, AI 가속기 판단 |
| 03 시스템·응용 SW | OS, SW공학, DB 구조 | 아키텍처, 품질속성, 분산 설계 |
| 04 통신·네트워크 | 계층, 주소, 프로토콜 흐름 | 제어평면/데이터평면, QoS, 보안 |
| 05 시스템 보안 | 자산, 위협, 통제 구조 | 탐지·대응·복구, 규제 대응 |
| 06 시스템 평가 | 성능·신뢰성·품질 지표 | 측정 방법, 감리, 개선 판단 |
| 07 법규·정책·표준 | 법·정책·표준 요구사항 | 거버넌스, 준수 방안, 책임 구조 |
| 08 최신 기술 동향 | AI·클라우드·신기술 개요 | 적용 기준, 위험관리, 발전 방향 |

## 2~4교시 필수 확장 체크

| 항목 | 확인 기준 |
|:---|:---|
| Ⅰ 개요 | 개요-배경-답안 방향이 한 호흡으로 이어지는가 |
| 출제 의도 | 문제 신호어를 읽고 반드시 짚을 핵심·감점 회피 포인트를 먼저 고정했는가 |
| Ⅱ·Ⅲ 구조/원리 | 구조(Ⅱ 구성요소)와 원리(Ⅲ 흐름)가 짝으로 분리되었는가 |
| Ⅳ 특징 | 특징표와 한계 판단이 있는가 |
| Ⅴ 심화 판단 | 비교·선택 기준(표), 리스크·대응·지표(기본 불릿)가 있는가 — 표 남발 금지 |
| Ⅵ 결론 | 조건별 선택 기준과 기술사 제언이 있는가 |

## 답안 압축 체크리스트

- 개요가 첫 줄에 있는가
- 출제 의도와 감점 회피 포인트가 답안 초반에 있는가
- 선형 텍스트 도식이 2개 있는가
- 표는 대조 축이 있는 곳에만 썼는가(개수 채우기용 억지 표 없음 — writing-method.md Ⅶ)
- 비교 문제는 선택 기준이 있는가
- 결론에 기술사 제언 또는 본인 의견 한 줄이 있는가
- 결론이 기술사적 판단으로 끝나는가
