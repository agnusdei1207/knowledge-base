## 사용 원칙

> **2026-07-05 4차 개정**: 골격을 실제 기술사 수험가의 표준 목차 — `정의 → 배경/필요성 → 구성요소 → 절차 → 문제점 → 개선방안 → 전망` — 로 단순화했다. 출제 의도 표·비유는 시험 답안에는 옮기지 않고 **노트에서 이해를 돕는 용도로만 유지**한다(실전 답안지에는 안 옮겨 적어도 되지만, 노트 자체에서는 삭제하지 않는다).

- 첫 줄 1문장 개요 (주어 + 동사 + 목적어, 30자 내외 — 정의 1문장은 짧게, 부연은 별도 불렛으로)
- 5초 안에 구조가 보이도록 `개요 -> 구성요소/절차 -> 문제점/개선방안 -> 전망`
- 1교시는 Ⅰ~Ⅲ까지, 2~4교시는 Ⅰ~Ⅵ 고정
- 약어는 최초 1회 풀네임 병기 (예: RAG(Retrieval-Augmented Generation))
- 정보 나열 금지: 문제 신호어에서 출제 의도를 읽고, 반드시 짚을 핵심·비교축·감점 회피 포인트를 먼저 고정한다
- **출제 의도 표·비유는 노트용 이해 장치다.** 실전 답안지에 그대로 옮기지 않아도 되지만(시간 제약상 생략 가능), 노트에서는 학습자가 "출제자가 뭘 보려는지"와 "직관적으로 뭘 뜻하는지"를 눈으로 확인할 수 있도록 남겨 둔다 — 지우지 않는다.

## 1교시 단답형 템플릿

1교시 답안은 독립 문서가 아니라, 2~4교시 답안의 앞부분인 `Ⅰ. 개요 + Ⅱ. 구성요소 + Ⅲ. 절차`(Ⅰ~Ⅲ)를 압축해서 먼저 멈춘 형태다.

````markdown
### [키워드]

- **개요**: [개념의 본질 1문장]
- **핵심 1**: [구성요소/원리]
- **핵심 2**: [장점/효과]
- **핵심 3**: [한계/유의점/비교 포인트]
- **미니 구조**: [입력/요구] -> [핵심 메커니즘] -> [효과/결과]
- **적용/출제 포인트**: [실무 또는 비교 대상]
````

### 1교시 빠른 변형 규칙

| 유형 | 답안 포인트 | 미니 도식 |
|:---|:---|:---|
| 설명형 | 개요 1줄 + 특징 3개 | `입력 -> 처리 -> 효과` 3칸 |
| 비교형 | 공통점 1개 + 차이점 3개 | `A vs B` 2칸 비교 |
| 구조형 | 구성요소 3개 + 흐름도 | `구성 A -> 구성 B -> 구성 C` |
| 장단점형 | 장점 2개 + 단점 1개 + 적용처 | `장점 / 한계 / 적용` 3칸 |

## 2~4교시 서술형 템플릿

2~4교시 답안은 1교시의 `Ⅰ~Ⅲ` 압축판을 `Ⅳ~Ⅵ`의 문제점·개선방안·전망으로 확장하는 구조다.
- `Ⅱ. 구성요소`: 텍스트 구조도 + 구성요소 표 + 한 줄 요약
- `Ⅲ. 절차`: 텍스트 흐름도 + 단계 불릿 + 한 줄 요약
- **금지되는 것은 "박스 모양"이 아니라 "유니코드 박스 그리기 문자"다.** `┌ ┐ └ ┘ │(세로선용) ─ ▶ ├ ┤ ┬ ┴ ┼` 같은 특수 유니코드 글리프는 폰트·폭에 따라 웹·모바일에서 깨지므로 금지. 대신 일반 ASCII 문자 `+ - | / \ > < v ^`만 쓴다 — 이 문자들로는 박스(`+---+` / `|  |` / `+---+`)도, 화살표도 전부 안전하게 표현 가능하다.
- **박스 vs 화살표 체인, 둘 다 쓸 수 있다.** Ⅱ.구성요소처럼 "이게 무엇으로 구성되는가"를 보여줄 땐 손으로 자를 대고 그리는 실제 답안과 닮은 **ASCII 박스**(`+----+` 테두리)가 오히려 더 실전에 가깝다. Ⅲ.절차처럼 "무엇이 무엇으로 이어지는가"를 보여줄 땐 화살표 체인(`A -> B -> C`)이 더 간결하다. 상황에 맞게 고른다(하나로 통일하지 않아도 됨).
- **가로로만 욱여넣지 않는다.** 요소가 4개를 넘거나 가로 폭이 좁아지면 세로 방향(`|`로 잇고 `v`로 화살표머리 표시)으로 바꾼다. 예:
  ```text
  [입력]
    |
    v
  [처리 A] --> [처리 B]
    |
    v
  [출력]
  ```
- **다닥다닥 붙이지 않는다.** 박스·화살표 사이에 최소 1칸 이상 여백을 두고, 요소가 많으면 줄바꿈으로 나눈다. 한 줄에 모든 것을 구겨 넣어 읽기 어렵게 만들지 않는다.
- 표 vs 불릿 선택, 표 아래 `> 요약:` 규칙은 [writing-method.md](@/exam/cs/writing-method.md) `Ⅶ. 표·불릿·구성 판단 규칙`을 따른다 — 아래 골격의 표는 예시일 뿐 개수 하한이 아니다.
- **비교가 필요하면 별도 절을 만들지 않고 Ⅱ(구성요소가 여러 방식으로 나뉠 때) 또는 Ⅴ(대안끼리 비교해 개선방안을 고를 때) 안에 표로 녹인다.**
- **절 생략·번호 규칙**: 생략 가능한 절은 없다(Ⅰ~Ⅵ 전부 필수). 절 순서와 번호는 고정한다(결론은 항상 `Ⅵ. 전망`) — [writing-method.md](@/exam/cs/writing-method.md) Ⅶ `절 생략·번호 규칙`

````markdown
## [문제명]

### Ⅰ. 개요
- **정의**: [핵심 개념 1문장, 30자 내외]
- **배경/필요성**: [이 개념이 논리적으로 왜 필요한가 1~2문장 — 역사·연도·인명 나열 금지]
- **비유**: [직관적으로 이해를 돕는 비유 1개 — 실제 답안엔 안 옮겨도 되는 노트용]

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| [문제 신호어로 파악한 요구] | [키워드·수치·표준·비교축] | [개념 나열, 요구사항 누락, 추상 표현] |

> ⚠️ 위 출제 의도 표는 **노트에서 이해를 돕는 장치**다. 실전 답안지에 표를 그대로 옮기지 않아도 되지만, 노트에서는 지우지 않는다.

> 요약: [출제자가 보려는 판단을 1문장으로 고정]

### Ⅱ. 구성요소
```text
[텍스트 구조도: 박스 문자 없이 4~6개 요소 + 방향]
입력/요구 -> 구성 A -> 구성 B -> 구성 C -> 산출물
             |           |
             +-> 통제    +-> 관측/검증
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 구성 A |  |  |
| 구성 B |  |  |
| 구성 C |  |  |

> ⚠️ "설명" 열에는 역할과 산출물을 하나로 합쳐 쓴다("무엇을 하고 무엇을 내놓는가"를 한 칸에). "비유" 열은 노트에서 이해를 돕는 용도이며 삭제하지 않는다 — [writing-method.md](@/exam/cs/writing-method.md) Ⅶ.

> 요약: [구성요소가 어떤 역할을 하는지 1문장]

### Ⅲ. 절차
```text
  단계1         단계2         단계3         단계4
  (입력/요구)   (핵심처리)    (검증/통제)   (출력/효과)
   |             |             |             |
   +---데이터--->+---변환------>+---판정------>+
  소스/트리거   엔진/알고리즘  검증기/기준   산출물/지표
```

1. **입력/요구 식별** — [무엇을 판정·입력하는지 1줄]
2. **핵심 처리** — [핵심 연산·변환 1줄]
3. **검증·통제** — [무엇으로 검증하는지 1줄]
4. **출력·효과** — [산출물과 확인 지표 1줄]

> 요약: [어떤 순서로 어떻게 동작하는지 1문장]

> ⚠️ **흐름도는 구성요소 구조도처럼 여러 줄로 깔끔하게 작성한다** — 한 줄에 모든 단계를 우겨넣지 않고, 단계명·설명·연결·하위요소를 행 단위로 정렬한다. 단계는 순차 과정이므로 기본은 번호 불릿이다. 흐름도가 이미 순서를 보여주므로 같은 단계를 표로 다시 그리지 않는다. 단계마다 2개 이상 축의 값이 실제로 모두 채워질 때만 예외로 표를 쓴다 — [writing-method.md](@/exam/cs/writing-method.md) Ⅶ.

**※ 여기까지가 1교시 답안 범위 (2/3~1쪽)**
**[딥 논의 분기점]**

### Ⅳ. 문제점
- [문제/한계 1]: [원인] — [무엇이 왜 문제인지 1줄]
- [문제/한계 2]: [원인] — [무엇이 왜 문제인지 1줄]
- [문제/한계 3]: [원인] — [무엇이 왜 문제인지 1줄]

> ⚠️ 필요하면 대안·방식 비교가 이 절에 들어갈 수 있다(대상 2개↑ × 축 2개↑일 때만 표, 그 외엔 위처럼 불릿).

> 요약: [핵심 문제 1문장]

### Ⅴ. 개선방안
1. 단기: [현황 진단, PoC, 즉시 조치]
2. 중기: [구조 개선, 자동화, 표준 수립]
3. 장기: [운영 고도화, 거버넌스, 지속 개선]

- [리스크 A]: [원인] → [대응 방안] (지표: [확인 지표])
- [리스크 B]: [원인] → [대응 방안] (지표: [확인 지표])

> ⚠️ Ⅳ의 문제 각각에 대응하는 방안을 여기서 짝지어 준다. 대안을 놓고 고르는 판단이면 표(대상 2개↑ × 축 2개↑)로, 그 외 리스크·지표 나열은 기본 불릿 — [writing-method.md](@/exam/cs/writing-method.md) Ⅶ.

> 요약: [무엇을 어떻게 개선하는지 1문장]

### Ⅵ. 전망
- 향후 발전 방향: [기술·표준·생태계가 어디로 가는지 1~2줄]
- 기술사적 판단: [조건별 선택 기준 또는 종합 판단]
- 기술사 제언: [실무 적용 시사점 1줄]
````

### 서술형 문항 유형별 치환 규칙

| 문제 표현 | Ⅱ·Ⅲ에서 강조 | Ⅳ~Ⅵ에서 강조 |
|:---|:---|:---|
| 설명하시오 | 구성요소, 절차 | 한계, 발전 방향 |
| 비교하시오 | 공통 구조·흐름 | Ⅳ/Ⅴ 표 중심 차이점, 선택 기준 |
| 방안을 제시하시오 | 문제 원인 구조·영향 흐름 | Ⅴ 단계별 개선안, 우선순위 |
| 설계하시오 | 아키텍처, 처리 흐름 | Ⅴ 구성 기준, 운영 절차 |
| 문제점과 대책 | 원인·영향 구조 | Ⅳ·Ⅴ가 곧 문제-원인-대책 매핑 |

## 구조도 예시

화살표 체인 예시 — 흐름·절차를 보여줄 때(요소 사이 여백을 충분히 둔다):

```text
입력/요구 -> 핵심 처리 -> 효과/성과
             |             |
             +-> 통제      +-> 지표 확인
```

박스 예시 — 구성요소·계층을 보여줄 때(유니코드 박스 문자 대신 `+ - |`만 사용):

```text
+------------+       +------------+
|  구성 A    | ----> |  구성 B    |
+------------+       +------------+
      |
      v
+------------+
|  구성 C    |
+------------+
```

가로 폭이 좁거나 요소가 많으면 위처럼 세로(`|`, `v`) 방향으로 바꿔도 된다 — 위 "2~4교시 서술형 템플릿"의 도식 규칙 참조.

공식 8대영역별 확장 포인트는 [컴퓨터시스템응용기술사 2~4교시 통합 답안 템플릿](@/exam/cs/master-template.md)의 `Ⅲ. 공식 8대영역 적용 원칙`을 따른다.

## 공식 8대영역 매핑표

| 대영역 | 1교시에서 끊기는 앞부분(Ⅰ~Ⅲ) | 2~4교시 딥 논의(Ⅳ~Ⅵ) |
|:---|:---|:---|
| 01 컴퓨터 기초이론 | 알고리즘, 자료구조, 통계 개념 | 한계, 선택 기준, 개선방안 |
| 02 하드웨어 시스템 | 구조, 병목, 성능지표 | 병렬화, 메모리, AI 가속기 판단 |
| 03 시스템·응용 SW | OS, SW공학, DB 구조 | 아키텍처 한계, 품질속성, 분산 설계 개선 |
| 04 통신·네트워크 | 계층, 주소, 프로토콜 흐름 | 제어평면/데이터평면 한계, QoS, 보안 개선 |
| 05 시스템 보안 | 자산, 위협, 통제 구조 | 탐지·대응·복구, 규제 대응 |
| 06 시스템 평가 | 성능·신뢰성·품질 지표 | 측정 한계, 감리, 개선 판단 |
| 07 법규·정책·표준 | 법·정책·표준 요구사항 | 거버넌스 공백, 준수 방안, 책임 구조 |
| 08 최신 기술 동향 | AI·클라우드·신기술 개요 | 리스크, 적용 기준, 발전 방향 |

## 2~4교시 필수 확장 체크

| 항목 | 확인 기준 |
|:---|:---|
| Ⅰ 개요 | 정의-배경/필요성이 한 호흡으로 이어지는가, 출제 의도 표가 있는가 |
| Ⅱ·Ⅲ 구성요소/절차 | 구성요소(Ⅱ)와 절차(Ⅲ)가 짝으로 분리되었는가 |
| Ⅳ 문제점 | 원인이 명시된 문제/한계가 있는가 |
| Ⅴ 개선방안 | Ⅳ의 문제마다 대응이 짝지어졌는가, 단기/중기/장기 구분이 있는가 |
| Ⅵ 전망 | 발전 방향과 기술사 제언이 있는가 |

## 답안 압축 체크리스트

- 개요가 첫 줄에 있는가
- 출제 의도와 감점 회피 포인트가 답안 초반에 있는가(노트용, 답안지엔 생략 가능)
