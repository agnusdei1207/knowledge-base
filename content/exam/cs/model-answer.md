> **작성법(품질 규칙)은 [writing-method.md](@/exam/cs/writing-method.md)가 정본이다.** 이 문서는 채우는 **골격(양식)**만 제공한다. 추상 표현 치환·의미 반전 방지·핵심 집중·논리 전개·중복 금지·표 vs 불릿 판단은 writing-method.md를 따르고 여기서 되풀이하지 않는다.

---

## 사용 원칙

- 첫 줄 1문장 개요 (주어 + 동사 + 목적어, 30자 내외 — 정의 1문장은 짧게, 부연은 별도 불렛으로)
- 5초 안에 구조가 보이도록 `개요 -> 구조/원리 -> 비교/절차 -> 결론`
- 1교시는 Ⅰ~Ⅲ까지, 2~4교시는 Ⅰ~Ⅵ 고정
- 약어는 최초 1회 풀네임 병기 (예: RAG(Retrieval-Augmented Generation))
- 정보 나열 금지: 문제 신호어에서 출제 의도를 읽고, 반드시 짚을 핵심·비교축·감점 회피 포인트를 먼저 고정한다
- 출제 의도 표는 노트·연습용 장치다: 실전 답안지에는 표를 그대로 옮기지 않고, Ⅰ. 개요의 "답안 방향" 불렛에 녹여 쓴다

---

## 1교시 단답형 템플릿

1교시 답안은 독립 문서가 아니라, 2~4교시 답안의 앞부분인 `Ⅰ. 개요 + Ⅱ. 구조 및 구성요소 + Ⅲ. 동작원리 및 흐름도`(Ⅰ~Ⅲ)를 압축해서 먼저 멈춘 형태다.

````markdown
### [키워드]

- **개요**: [개념의 본질 1문장]
- **핵심 1**: [구성요소/원리]
- **핵심 2**: [장점/효과]
- **핵심 3**: [한계/유의점/비교 포인트]
- **미니 구조**: [입력/요구] -> [핵심 메커니즘] -> [효과/결과]
- **적용/출제 포인트**: [실무 또는 비교 대상]
````

### 1교시 빠른 변형 규칙

| 유형 | 답안 포인트 | 미니 도식 |
|:---|:---|:---|
| 설명형 | 개요 1줄 + 특징 3개 | `입력 -> 처리 -> 효과` 3칸 |
| 비교형 | 공통점 1개 + 차이점 3개 | `A vs B` 2칸 비교 |
| 구조형 | 구성요소 3개 + 흐름도 | `구성 A -> 구성 B -> 구성 C` |
| 장단점형 | 장점 2개 + 단점 1개 + 적용처 | `장점 / 한계 / 적용` 3칸 |

---

## 2~4교시 서술형 템플릿

2~4교시 답안은 1교시의 `Ⅰ~Ⅲ` 압축판을 `Ⅳ~Ⅵ`의 특징·심화 비교·적용·결론으로 확장하는 구조다.
- `Ⅱ. 구조 및 구성요소`: 선형 텍스트 구조도 + 구성요소 표 + 한 줄 요약
- `Ⅲ. 동작원리 및 흐름도`: 선형 텍스트 흐름도 + 단계 표 + 한 줄 요약
- 구조·흐름도는 `A -> B -> C`, 들여쓰기, 번호, `/` 분기만 사용한다. 박스 문자(`┌ ┐ └ ┘ │ ─ ▶`)는 웹 렌더링과 모바일 폭에서 깨지므로 사용하지 않는다
- 표 vs 불릿 선택, `Ⅳ. 특징` 슬롯 판단, 표 아래 `> 요약:` 규칙은 [writing-method.md](@/exam/cs/writing-method.md) `Ⅶ. 표·불릿·구성 판단 규칙`을 따른다 — 아래 골격의 표는 예시일 뿐 개수 하한이 아니다
- `Ⅴ. 심화 비교 및 적용 판단`은 비교·선택 기준, 리스크·대응, 지표·점검을 다루되, 대조 축이 실제로 있을 때만 표로 쓴다
- **절 생략·번호 규칙**: 생략 가능한 절은 Ⅳ뿐이다. Ⅴ·Ⅵ은 생략 금지이며, 절을 생략해도 번호는 당기지 않는다(결론은 항상 `Ⅵ. 실무 적용 및 결론`) — [writing-method.md](@/exam/cs/writing-method.md) Ⅶ `절 생략·번호 규칙`

````markdown
## [문제명]

### Ⅰ. 개요
- **개요**: [핵심 개념 1문장]
- **배경/필요성**: [출제 배경 2~3]
- **출제 의도**: [출제자가 확인하려는 역량: 구조 이해 / 비교 판단 / 설계 방안 / 운영 통제]
- **답안 방향**: [이 답안에서 끌고 갈 축 3]

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| [문제 신호어로 파악한 요구] | [키워드·수치·표준·비교축] | [개념 나열, 요구사항 누락, 추상 표현] |

> 요약: [출제자가 보려는 판단을 1문장으로 고정]

### Ⅱ. 구조 및 구성요소
```text
[텍스트 구조도: 박스 문자 없이 4~6개 요소 + 방향]

             |           |
             +-> 통제    +-> 관측/검증
```

| 구성요소 | 역할 | 산출물 |
|:---|:---|:---|

### Ⅲ. 동작원리 및 흐름도
```text
[텍스트 흐름도: 입력 -> 처리 -> 통제 -> 출력]
입력/요구 -> 핵심 처리 -> 검증/통제 -> 결과 출력
```

| 단계 | 처리 내용 | 검증 기준 |
|:---:|:---|:---|
| 1 | 입력/요구 식별 | 업무 적합성 |
| 2 | 핵심 처리 수행 | 성능·정확성 |
| 3 | 통제·검증 적용 | 안정성·감사성 |
| 4 | 출력·효과 확인 | 지표 충족 여부 |

> 요약: [어떤 순서로 어떻게 동작하는지 1문장]

**※ 여기까지가 1교시 답안 범위 (2/3~1쪽)**
**[딥 논의 분기점]**
````

### 서술형 문항 유형별 치환 규칙

| 문제 표현 | Ⅱ·Ⅲ에서 강조 | Ⅴ·Ⅵ에서 강조 |
|:---|:---|:---|
| 설명하시오 | 구성요소, 원리 | 적용 사례, 발전 방향 |
| 비교하시오 | 공통 구조·흐름 | 표 중심 차이점, 선택 기준 |
| 방안을 제시하시오 | 문제 원인 구조·영향 흐름 | 단계별 개선안, 우선순위 |
| 설계하시오 | 아키텍처, 처리 흐름 | 구성 기준, 운영 절차 |
| 문제점과 대책 | 원인·영향 구조 | 리스크-원인-대책 매핑 |

## 구조도 예시

다음 형태처럼 선형 흐름을 먼저 적고, 각 요소 아래에 핵심 키워드 1~2개만 덧붙인다. 박스 문자 대신 `->`, 들여쓰기, `/` 분기를 사용한다.

```text
입력/요구 -> 핵심 처리 -> 효과/성과
             |             |
             +-> 통제      +-> 지표 확인
```

공식 8대영역별 확장 포인트는 [컴퓨터시스템응용기술사 2~4교시 통합 답안 템플릿](@/exam/cs/master-template.md)의 `Ⅲ. 공식 8대영역 적용 원칙`을 따른다.

## 공식 8대영역 매핑표

| 대영역 | 1교시에서 끊기는 앞부분(Ⅰ~Ⅲ) | 2~4교시 딥 논의(Ⅳ~Ⅵ) |
|:---|:---|:---|
| 01 컴퓨터 기초이론 | 알고리즘, 자료구조, 통계 개념 | 복잡도, 선택 기준, 정량 비교 |
| 02 하드웨어 시스템 | 구조, 병목, 성능지표 | 병렬화, 메모리, AI 가속기 판단 |
| 03 시스템·응용 SW | OS, SW공학, DB 구조 | 아키텍처, 품질속성, 분산 설계 |
| 04 통신·네트워크 | 계층, 주소, 프로토콜 흐름 | 제어평면/데이터평면, QoS, 보안 |
| 05 시스템 보안 | 자산, 위협, 통제 구조 | 탐지·대응·복구, 규제 대응 |
| 06 시스템 평가 | 성능·신뢰성·품질 지표 | 측정 방법, 감리, 개선 판단 |
| 07 법규·정책·표준 | 법·정책·표준 요구사항 | 거버넌스, 준수 방안, 책임 구조 |
| 08 최신 기술 동향 | AI·클라우드·신기술 개요 | 적용 기준, 위험관리, 발전 방향 |

## 2~4교시 필수 확장 체크

| 항목 | 확인 기준 |
|:---|:---|
| Ⅰ 개요 | 개요-배경-답안 방향이 한 호흡으로 이어지는가 |
| 출제 의도 | 문제 신호어를 읽고 반드시 짚을 핵심·감점 회피 포인트를 먼저 고정했는가 |
| Ⅱ·Ⅲ 구조/원리 | 구조(Ⅱ 구성요소)와 원리(Ⅲ 흐름)가 짝으로 분리되었는가 |
| Ⅳ 특징 | 특징표와 한계 판단이 있는가 |
| Ⅴ 심화 판단 | 비교·선택 기준, 리스크·대응, 지표·점검 표가 있는가 |
| Ⅵ 결론 | 조건별 선택 기준과 기술사 제언이 있는가 |

## 답안 압축 체크리스트

- 개요가 첫 줄에 있는가
- 출제 의도와 감점 회피 포인트가 답안 초반에 있는가
- 선형 텍스트 도식이 2개 있는가
- 표는 대조 축이 있는 곳에만 썼는가(개수 채우기용 억지 표 없음 — writing-method.md Ⅶ)
- 비교 문제는 선택 기준이 있는가
- 결론에 기술사 제언 또는 본인 의견 한 줄이 있는가
- 결론이 기술사적 판단으로 끝나는가
