# 합격후기 기반 답안 작성법

컴퓨터시스템응용기술사는 지식량보다 **400분 동안 채점자가 읽을 수 있는 구조를 반복 생산하는 능력**이 더 중요하다. 공개 합격후기와 기술사 답안 작성법을 종합하면, 합격권 답안의 공통점은 다음 네 가지다.

1. 출제기준과 기출을 먼저 큰 가지로 잡는다.
2. 1교시 단답형을 2~4교시 서술형의 재료로 쓴다.
3. 2~4교시는 3쪽 내외를 끝까지 채우는 훈련을 한다.
4. 실전 답안은 표와 짧은 단계 흐름을 기본으로 하고, 연습용 템플릿에서만 ASCII 박스 예시를 참고한다.

## Ⅰ. 취득 후기에서 뽑은 실전 원칙

| 후기/작성법 공통점 | 시험 문서 반영 방식 |
|:---|:---|
| 암기 중심에서 이해·작성·커버리지 중심으로 전환해야 점수가 오른다 | 키워드를 외우는 문서와 서술형 답안 템플릿을 분리 |
| 기출을 출제기준 기간 단위로 묶어 경향을 본다 | 2023~2026 출제기준 축에 AI, 보안, 클라우드, SW, DB를 재배치 |
| 1교시 10문제와 2교시 4문제 분량을 실제 답안지로 채우는 훈련이 필요하다 | 1교시는 `정의 + 핵심 3포인트 + 미니 도식 + 적용 1줄` 기준의 `2/3~1쪽`, 2~4교시는 3쪽 내외 템플릿으로 고정 |
| 답안은 서론-본론-결론이 아니라 채점용 목차·표·도식으로 읽혀야 한다 | Ⅰ~Ⅴ 목차, 구조도 1개, 표 2개, 결론 2줄을 기본값으로 설정 |
| 포괄형 문제와 요구사항 명시형 문제는 목차 구성이 달라야 한다 | 문제 유형별 치환표를 사용 |

## Ⅱ. 1교시가 2~4교시에 포함되는 방식

| 1교시 단답 요소 | 2~4교시에서 쓰는 위치 | 예시 |
|:---|:---|:---|
| 정의 1문장 | Ⅰ. 개요 첫 줄 | "RAG는 검색 결과를 생성형 AI 프롬프트에 결합하는 아키텍처이다" |
| 구성요소 3개 | Ⅱ. 구성요소 표 | Retriever, Vector DB, Generator |
| 장점·한계 | Ⅲ. 비교/특징 표 | 최신성 확보 vs 검색 품질 의존 |
| 적용 포인트 | Ⅳ. 적용 방안 | 권한 필터링, 평가 자동화, Guardrail |
| 향후 방향 | Ⅴ. 결론 | Agentic RAG, 기업 지식 거버넌스 |

즉 1교시 답안은 짧은 독립 답안이고, 2~4교시 답안은 **1교시 템플릿의 확장형**이다. 2~4교시에 1교시 답안을 별도 부록처럼 붙이는 것이 아니라, Ⅰ. 개요와 Ⅱ. 구성요소 안에 정의·핵심요소·장단점·적용 포인트를 내장한다.

2~4교시 정본 골격은 [모범답안 템플릿](@/exam/cs/model-answer.md)의 `Ⅰ. 개요 / Ⅱ. 구조·동작원리 / Ⅲ. 핵심특징·비교 / Ⅳ. 적용방안·리스크 / Ⅴ. 결론`을 따른다.

## Ⅲ. 2~4교시 페이지 구성

| 쪽 | 쓰는 내용 | 실제 행동 |
|:---|:---|:---|
| 1쪽 | Ⅰ 개요 + Ⅱ 구조/원리 | 정의 2줄 후 단계표 또는 짧은 한 줄 흐름 작성 |
| 2쪽 | Ⅱ 구성요소표 + Ⅲ 비교표 | 표 2개로 채점 포인트를 보이게 함 |
| 3쪽 | Ⅳ 적용 방안 + Ⅴ 결론 | 단계별 방안과 조건부 판단으로 마무리 |

### 25분 운용

| 시간 | 작업 |
|:---:|:---|
| 0~2분 | 6문제 중 쓸 4문제 선택, 목차 키워드만 적기 |
| 2~5분 | Ⅰ 개요와 구조도 뼈대 작성 |
| 5~13분 | Ⅱ 구성요소·원리 작성 |
| 13~19분 | Ⅲ 비교표·특징표 작성 |
| 19~23분 | Ⅳ 방안·리스크 대응 작성 |
| 23~25분 | Ⅴ 결론, 빠진 요구사항 보완 |

구조도는 `Ⅰ. 개요` 직후에 박스 3~5개만 먼저 그리고, 자세한 설명은 `Ⅱ. 구조·동작원리` 표에서 채운다.

## Ⅳ. 추상 표현을 줄이는 치환 규칙

| 추상 표현 | 시험 답안 표현 |
|:---|:---|
| 성능이 좋다 | 지연시간 감소, 처리량 증가, 병목 제거, 캐시 적중률 향상 |
| 안정성이 높다 | 장애 격리, 자동 복구, RTO/RPO 단축, SLO 준수 |
| 보안이 강화된다 | 인증·인가, 암호화, 접근통제, 로깅·감사, 위협 탐지 |
| 운영이 편하다 | 자동화, 표준화, 관측성, 배포 롤백, 구성 편류 방지 |
| 비용을 줄인다 | 리소스 우측정, 오토스케일링, 예약/스팟, FinOps 태깅 |
| 최신 기술이다 | 기존 방식의 한계, 도입 구조, 적용 조건, 리스크를 함께 적는다 |
