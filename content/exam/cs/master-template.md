# 컴퓨터시스템응용기술사 2~4교시 통합 답안 템플릿

이 문서는 `1교시 단답형 모음`이 아니라, **하나의 연속 답안을 1교시는 Ⅰ~Ⅲ에서 멈추고, 2~4교시는 Ⅰ~Ⅵ까지 확장하는 방식**으로 정리한 사례집이다.

---

## Ⅰ. 답안 작성 원칙

| 원칙 | 적용 방법 | 피해야 할 형태 |
|:---|:---|:---|
| 문제 요구사항 우선 | 문제 문장의 동사(설명, 비교, 설계, 방안, 문제점)를 목차로 바꾼다 | 외운 목차를 문제와 무관하게 붙임 |
| 출제 의도 고정(노트용) | 답안 초반에 출제 의도·반드시 짚을 핵심·감점 회피 포인트를 표로 먼저 쓴다 — 이해를 돕는 장치이며 실전 답안지엔 생략 가능 | 키워드 설명만 길게 쓰고 문제 의도를 놓침 |
| 정보 나열 금지 | 채점자가 기대하는 비교축·선택 기준·수치 지표를 선별한다 | 아는 내용을 모두 나열해 논점이 흐려짐 |
| 1교시는 Ⅰ~Ⅲ까지 | 개요·구성요소·절차까지 쓰고 문제점·개선방안 딥 논의 직전에서 멈춘다 | 단답형 답안을 길게 늘여 서술형으로 착각 |
| 2~4교시는 판단 | 구조도, 흐름도, 문제점, 개선방안(단기/중기/장기), 전망을 반드시 넣는다 | 개념 설명만 반복 |
| 과목 균형 | 01 컴퓨터구조뿐 아니라 OS, 네트워크, SW, DB, 보안, AI, 클라우드, 경영까지 선택지를 확보한다 | 1과목 지식으로 모든 문제를 해결하려 함 |
| 손글씨 시간 | 25분 안에 3쪽 내외 완성 가능한 목차로 고정한다 | 목차 구상에 시간을 과다 사용 |

## Ⅱ. 2~4교시 기본 골격

2~4교시 골격은 [모범답안 템플릿](@/exam/cs/model-answer.md)의 `2~4교시 서술형 템플릿`을 정본으로 따른다.

| 정본 반영 원칙 | 적용 메모 |
|:---|:---|
| Ⅰ 개요 / Ⅱ 구성요소 / Ⅲ 절차 / Ⅳ 문제점 / Ⅴ 개선방안 / Ⅵ 전망 | 과목별 적용 시 제목과 표 축만 바꾸고 골격은 유지 |
| 출제 의도 표(노트용) | 출제 의도 / 반드시 짚을 핵심 / 감점 회피 포인트를 답안 초반에 배치 — 이해를 돕는 장치, 삭제하지 않음 |
| 1교시는 같은 답안의 앞부분 | Ⅰ~Ⅲ까지 쓰고 멈춘 압축판 |
| 구조도+흐름도 필수 | Ⅱ에 선형 텍스트 구조도+구성요소 표(`구성요소│설명│비유` 3칸), Ⅲ에 선형 텍스트 흐름도+단계 불릿; 각 표 아래 한 줄 요약 |
| Ⅳ 문제점 | 원인이 명시된 문제·한계를 불릿으로 나열(비교가 필요하면 이 절에 표로) |
| Ⅴ 개선방안 | Ⅳ 각 문제에 대응하는 방안을 단기/중기/장기로 짝짓는다. 리스크·지표는 기본 불릿 |
| Ⅵ 전망 | 발전 방향 + 기술사적 판단/제언 |

## Ⅲ. 공식 8대영역 적용 원칙

공식 8대영역 매핑표는 [모범답안 템플릿](@/exam/cs/model-answer.md)의 `공식 8대영역 매핑표`를 정본으로 따른다. 실제 키워드 학습은 [CSPE 키워드 노트](@/cspe/_index.md)를 기준으로 한다.

| 적용 원칙 | 의미 |
|:---|:---|
| 1교시는 Ⅰ~Ⅲ까지 | 개요, 구성요소, 절차에서 멈춘다 |
| 2~4교시는 Ⅳ~Ⅵ로 확장 | 문제점, 개선방안(단기/중기/장기), 전망까지 밀어붙인다 |
| Ⅱ: 구성요소 고정 | 선형 텍스트 구조도 -> 구성요소 표(`구성요소│설명│비유` 3칸) -> 한 줄 요약 순서 |
| Ⅲ: 절차 고정 | 선형 텍스트 흐름도 -> 단계 불릿 -> 한 줄 요약 순서 |
| Ⅳ: 문제점 필수 | 원인이 있는 문제·한계만 쓴다. 비교가 의미 있을 때만 표(억지 표 금지) |
| Ⅴ: 개선방안 필수 | Ⅳ와 1:1로 짝짓는다. 단기/중기/장기 구분, 리스크·지표는 기본 불릿 |
| Ⅵ: 전망 필수 | 발전 방향 + 기술사적 판단으로 마무리 |
| 사례집 활용 방식 | 과목별로 표 축과 흐름 라벨만 바꿔 손답안에 즉시 전개한다 |

### 실제 치환 예시 1: MSA 장애 대응

| 단락 | 바로 쓸 내용 |
|:---|:---|
| Ⅰ 개요 | MSA는 서비스를 도메인 단위로 분리해 독립 배포하는 구조이나, 네트워크 지연·장애 전파·데이터 정합성 문제가 생긴다 |
| Ⅱ 구성요소 | API Gateway -> Service -> DB per Service -> Message Broker -> Observability |
| Ⅲ 절차 | 요청 라우팅 -> 서비스 처리 -> 이벤트 발행/소비 -> DB 커밋 -> 트레이스·메트릭 수집 |
| Ⅳ 문제점 | 서비스 간 호출 실패의 연쇄 전파(장애 전이), 분산 트랜잭션의 데이터 정합성 붕괴, 운영 복잡도 증가 |
| Ⅴ 개선방안 | 단기: Circuit Breaker·Retry/Timeout 도입 / 중기: Bulkhead·Saga 패턴 적용 / 장기: Distributed Tracing 기반 관측성 체계화 |
| Ⅵ 전망 | 단계적 분해(Strangler Fig)와 운영 자동화·관측성 확보가 성공 조건이며, 서비스 메시 표준화로 발전 |

손답안 구조도는 아래처럼 먼저 그린다. 웹과 모바일에서 깨지지 않도록 박스 문자 없이 선형 흐름으로 작성한다.

`Ⅱ. 구성요소` 자리:

```text
Client -> API Gateway -> Service A -> DB per Service
                        |
                        +-> Message Bus -> Observability
```

`Ⅲ. 절차` 자리:

```text
Client Request -> Gateway Routing -> Service Processing
-> Event Publish/Consume -> DB Commit -> Trace/Metric Collect
```

구조도는 `Ⅰ. 개요` 다음에 10~15초 안에 뼈대만 그리고, 설명은 `Ⅱ. 구성요소` 표와 `Ⅲ. 절차` 단계 불릿에서 채운다.

### 실제 치환 예시 2: RAG 도입

| 단락 | 바로 쓸 내용 |
|:---|:---|
| Ⅰ 개요 | RAG는 외부 지식 검색 결과를 LLM 프롬프트에 결합해 최신성·근거성을 높이는 생성형 AI 아키텍처 |
| Ⅱ 구성요소 | Document -> Chunking -> Embedding -> Vector DB -> Retrieval -> Prompt Augmentation -> LLM |
| Ⅲ 절차 | 문서 적재 -> 청크 분할 -> 임베딩 생성 -> 벡터 검색 -> 프롬프트 보강 -> LLM 생성 -> 답변 반환 |
| Ⅳ 문제점 | 검색 품질이 낮으면 근거 없는 응답(Hallucination) 발생, 문서 접근 권한이 검색 단계에서 새는 보안 문제, 최신 문서 반영 지연 |
| Ⅴ 개선방안 | 단기: Hybrid Search·Evaluation 파이프라인 구축 / 중기: 권한 필터링·문서 품질관리 체계화 / 장기: Hallucination Guardrail 자동화 |
| Ⅵ 전망 | 기업 RAG는 모델보다 데이터 거버넌스와 검색 품질이 성패를 좌우하며, Agentic RAG로 발전 |

손답안 구조도는 아래처럼 먼저 그린다. 박스 문자 없이 입력-저장-검색-생성 흐름을 한 줄 단위로 분리한다.

`Ⅱ. 구성요소` 자리:

```text
Document -> Chunking -> Embedding -> Vector DB
                                        |
Query -> Retriever (Vector DB 검색) -> Prompt Augmentation -> LLM -> Answer
```

`Ⅲ. 절차` 자리:

```text
문서 적재 -> 청크 분할 -> 임베딩 생성 -> 벡터 검색
-> 프롬프트 보강 -> LLM 생성 -> 답변 반환
```

구조도는 박스를 예쁘게 그리는 것이 아니라, **입력-저장-검색-생성**의 흐름을 깨지지 않게 보이게 만드는 것이 목적이다.

## Ⅴ. 적용 점검 체크리스트

| 체크 | 기준 |
|:---|:---|
| 골격 일치 | 2~4교시 골격은 [모범답안 템플릿](@/exam/cs/model-answer.md)의 정본을 그대로 따랐는가 |
| 출제 의도 | 문제 신호어에서 요구역량을 읽고 핵심·감점 회피 포인트를 답안 초반에 고정했는가(노트용) |
| 핵심 선별 | 정보 나열이 아니라 비교축·선택 기준·수치 지표 중심으로 답안이 좁혀졌는가 |
| 과목 적용 | 과목 특성에 따라 표 축과 구조도만 교체했는가 |
| 구조도 시점 | `Ⅰ. 개요` 직후 구조도 뼈대를 먼저 그렸는가 |
| 1교시 연결 | 개요·구성요소·절차가 Ⅰ~Ⅲ에 자연스럽게 이어지는가 (1교시는 Ⅲ에서 멈춤) |
| Ⅳ↔Ⅴ 짝짓기 | Ⅳ에서 제기한 문제마다 Ⅴ에 대응 방안이 있는가(누락 없음) |
