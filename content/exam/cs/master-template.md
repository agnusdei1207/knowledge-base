# CSPE 문제 유형 참조

> 작성법의 유일 정본은 [CSPE 답안 작성법 단일 정본](@/exam/cs/writing-method.md)이다. 이 문서는 문제 신호어별 강조점을 확인하는 참조 문서이며, 별도 템플릿이나 구판 작성법을 제공하지 않는다.

| 문제 신호어 | 먼저 볼 요구사항 | 강조할 흐름 |
|:---|:---|:---|
| 설명하시오 | 개념 본질·구성·원리 | 요구사항 -> 구조설계 -> 기술선정 |
| 비교하시오 | 비교 대상·선택 기준 | 기술선정 -> 트레이드오프 -> 판단 |
| 설계하시오 | 요구사항·제약조건 | 요구사항 -> 구조설계 -> 구현전략 |
| 방안을 제시하시오 | 문제 원인·우선순위 | 운영관리 -> 개선 |
| 문제점과 대책 | 대표 실무 판단 1~2개 | 적용 환경 -> 유의점 -> 대응 -> 확인 기준 |
| 운영하시오 | 지표·통제·복구 | 구현전략 -> 운영관리 -> 개선 |
| 보안하시오 | 자산·위협·통제 | 요구사항 -> 기술선정 -> 운영관리 |

> 요약: 어떤 문제 유형이든 최종 답안은 `요구사항 -> 구조설계 -> 기술선정 -> 구현전략 -> 운영관리 -> 개선` 흐름으로 정리한다.

- `문제점과 대책` 유형도 예전처럼 문제와 해결을 따로 늘어놓지 않고, 적용 환경과 유의점, 대응, 확인 기준을 한 문장으로 합쳐 씀
- 나쁜 예: `DFS 재귀가 깊이 한계를 넘어 편향 그래프에서 호출 깊이가 시스템 제한을 초과할 수 있음`
- 좋은 예: `의존성 순환 검사는 DFS가 맞지만 깊이가 계속 깊어지면 시스템 한계를 넘을 수 있으므로 깊은 입력은 반복 DFS로 바꾸고 최대 깊이와 메모리 사용량으로 확인함`
- `구성요소 및 구조` 절은 `구성요소 | 설명` 표를 기본으로 하되, 관계와 계층이 중요하면 표 아래에 ASCII 구조 도식을 보조적으로 추가함
- `Ⅵ. 실무 사례`는 `적용 상황 -> 주의 조건 -> 대응 방식 -> 검증 지표`를 한 문장으로 쓰며, 사례와 유의점을 별도 항목으로 반복하지 않음
- `대규모`처럼 선택 기준을 바꾸지 않는 수식어는 삭제하고, 규모 때문에 알고리즘·복잡도·용량 판단이 달라질 때만 구체적 조건으로 남김
- `작성 근거(검토용)`는 `미리 알고가기` 바로 다음, `Ⅰ. 개요` 앞에 배치해 답안을 읽기 전에 핵심 키워드·판단축·전개 방향을 먼저 확인하게 함
- 기존 노트 다듬기는 개요만 보지 않고 제목·메타데이터→미리 알고가기→작성 근거→Ⅰ~Ⅶ→표·도식·검증 지표 순으로 전수 확인하며, 개요에서 정리한 용어가 뒤 절에서 다시 영문·혼용 표현으로 흔들리지 않게 통일함
- 작업은 10개 파일 단위로 필수 절·근거 위치·정의·필요성 형식을 검사하고 `zola build` 후 해당 10개만 커밋·푸시하며, 마지막 완료 번호와 다음 시작 번호를 인계 정보로 남김
- `보기 쉽게 다듬기`는 새 내용을 더하는 작업보다, 채점자가 첫 호흡에 읽히게 문장 초점을 앞으로 당기는 작업에 가깝다.
- 수정 전: `최단 경로는 가중 그래프에서 출발지와 도착지 사이의 간선 가중치 합이 가장 작은 경로와 거리임`
- 수정 후: `최단 경로는 가중 그래프에서 출발지와 도착지 사이의 경로 비용(가중치) 합이 가장 작은 경로임`
- 위와 같이 `간선 가중치 합`을 `경로 비용(가중치) 합`으로 바꾸면 용어를 덜 기계적으로 느끼게 하면서, 독자가 한 번에 잡는 핵심 명사를 앞쪽에 모을 수 있다.
- 수정 전: `라우팅·물류·경로 계획은 누적 거리·비용·지연이 가장 작은 경로를 찾아야 함`
- 수정 후: `라우팅 비용 절감을 위해 거리·비용·시간 지연이 가장 작은 경로가 필요함`
- 위와 같이 사례 나열을 줄이고 목적을 먼저 두면 문장이 더 짧아지고, 왜 이 기술이 필요한지 바로 읽힌다.
- 실무 사례 수정 전: `라우팅처럼 음수 가중치가 없는 대규모 그래프는 다익스트라를 쓰고 p99 탐색 지연과 큐 크기로 검증함`
- 실무 사례 수정 후: `라우팅처럼 음수 가중치가 없는 그래프는 다익스트라를 쓰고 p99 탐색 지연과 큐 크기로 검증함`
- 위 문장에서 `대규모`는 다익스트라 선택 조건을 바꾸지 않으므로 삭제한다. 수식어는 있어 보이게 만드는 장식이 아니라 실제 선택 기준일 때만 남긴다.
- 배경/필요성은 반드시 `[해결 목적]을 위해 [개념·기준·구조]가 필요함`으로 작성한다. 목적을 앞에 두고 `필요함`으로 끝내야 답안에서 필요 이유와 수단이 한 번에 읽힌다.
- 표는 내용이 같아도 열 폭을 맞춰 정렬하면 시선이 흔들리지 않아 훑어보기 쉬워진다. 즉 `보기 좋게 고친다`는 것은 표현 압축, 초점 전진, 스캔성 개선을 함께 뜻한다.
