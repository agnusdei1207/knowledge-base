# 컴퓨터시스템응용기술사 2~4교시 통합 답안 템플릿

이 문서는 `1교시 단답형 모음`이 아니라, **하나의 연속 답안을 1교시는 Ⅰ~Ⅲ에서 멈추고, 2~4교시는 Ⅰ~Ⅵ까지 확장하는 방식**으로 정리한 사례집이다.

---

## Ⅰ. 답안 작성 원칙

| 원칙 | 적용 방법 | 피해야 할 형태 |
|:---|:---|:---|
| 문제 요구사항 우선 | 문제 문장의 동사(설명, 비교, 설계, 방안, 문제점)를 목차로 바꾼다 | 외운 목차를 문제와 무관하게 붙임 |
| 출제 의도 고정 | 답안 초반에 출제 의도·반드시 짚을 핵심·감점 회피 포인트를 표로 먼저 쓴다 | 키워드 설명만 길게 쓰고 문제 의도를 놓침 |
| 정보 나열 금지 | 채점자가 기대하는 비교축·선택 기준·수치 지표를 선별한다 | 아는 내용을 모두 나열해 논점이 흐려짐 |
| 1교시는 Ⅰ~Ⅲ까지 | 개요·구성요소·동작원리까지 쓰고 특징·적용 딥 논의 직전에서 멈춘다 | 단답형 답안을 길게 늘여 서술형으로 착각 |
| 2~4교시는 판단 | 구조도, 비교표, 선택 기준, 리스크 대응, 점검 지표, 운영 방안을 반드시 넣는다 | 개념 설명만 반복 |
| 과목 균형 | 01 컴퓨터구조뿐 아니라 OS, 네트워크, SW, DB, 보안, AI, 클라우드, 경영까지 선택지를 확보한다 | 1과목 지식으로 모든 문제를 해결하려 함 |
| 손글씨 시간 | 25분 안에 3쪽 내외 완성 가능한 목차로 고정한다 | 목차 구상에 시간을 과다 사용 |

## Ⅱ. 2~4교시 기본 골격

2~4교시 골격은 [모범답안 템플릿](@/exam/cs/model-answer.md)의 `2~4교시 서술형 템플릿`을 정본으로 따른다.

| 정본 반영 원칙 | 적용 메모 |
|:---|:---|
| Ⅰ 개요 / Ⅱ 구조 및 구성요소 / Ⅲ 동작원리 및 흐름도 / Ⅳ 특징 / Ⅴ 심화 비교 및 적용 판단 / Ⅵ 적용방안·결론 | 과목별 적용 시 제목과 표 축만 바꾸고 골격은 유지 |
| 출제 의도 표 필수 | 출제 의도 / 반드시 짚을 핵심 / 감점 회피 포인트를 답안 초반에 배치 |
| 1교시는 같은 답안의 앞부분 | Ⅰ~Ⅲ까지 쓰고 멈춘 압축판 |
| 구조도+흐름도 필수 | Ⅱ에 선형 텍스트 구조도+구성요소 표, Ⅲ에 선형 텍스트 흐름도+단계 표; 각 표 아래 한 줄 요약 |
| Ⅴ 심화 판단 확장 | Ⅴ에서 비교·선택 기준, 리스크·대응, 지표·점검을 다루되, 대조 축이 있을 때만 표로 쓴다(억지 표 금지) |
| Ⅳ "특징" 슬롯 | 기본은 "특징", 고유 특징 없으면 "비교"·"트레이드오프"로 교체·생략 가능. "핵심특징" 금지. 상세 판단은 [writing-method.md](@/exam/cs/writing-method.md) Ⅶ |

## Ⅲ. 공식 8대영역 적용 원칙

공식 8대영역 매핑표는 [모범답안 템플릿](@/exam/cs/model-answer.md)의 `공식 8대영역 매핑표`를 정본으로 따른다. 실제 키워드 학습은 [CSPE 키워드 노트](@/cspe/_index.md)를 기준으로 한다.

| 적용 원칙 | 의미 |
|:---|:---|
| 1교시는 Ⅰ~Ⅲ까지 | 개요, 구조·구성요소, 동작원리·흐름도에서 멈춘다 |
| 2~4교시는 Ⅳ~Ⅵ로 확장 | 특징·비교, 선택 기준, 리스크, 지표, 적용방안, 결론까지 밀어붙인다 |
| Ⅱ: 구조+구성요소 고정 | 선형 텍스트 구조도 -> 구성요소 표 -> 한 줄 요약 순서 |
| Ⅲ: 흐름도+원리 고정 | 선형 텍스트 흐름도 -> 단계 표 -> 한 줄 요약 순서 |
| Ⅳ: "특징" 표기 고정 | "핵심특징" 절대 사용 금지 |
| Ⅴ: 심화 판단 표 고정 | 비교·선택 기준 / 리스크·대응 / 지표·점검 표로 3쪽 분량을 확보한다 |
| 사례집 활용 방식 | 과목별로 표 축과 흐름 라벨만 바꿔 손답안에 즉시 전개한다 |

## Ⅳ. 문제 유형별 치환 템플릿

| 문제 유형 | 출제 의도 | Ⅰ 개요 | Ⅱ 구조·구성요소 | Ⅲ 동작원리·흐름도 | Ⅳ 특징 | Ⅴ 심화 판단 | Ⅵ 적용·결론 |
|:---|:---|:---|:---|:---|:---|:---|:---|
| 설명형 | 개념 본질·구성·원리 확인 | 개요·필요성 | 구성요소 표+선형 구조도 | 흐름 단계 표+선형 흐름도 | 특징표 | 비교·선택 기준, 지표 | 적용 사례·발전 방향 |
| 비교형 | 차이·선택 기준 확인 | 비교 배경 | 공통 구조+선형 구성도 | 공통 흐름+선형 흐름도 | 차이표 | 선택 기준, 리스크·대응 | 조건별 결론 |
| 설계형 | 요구사항을 구조로 바꾸는 역량 확인 | 요구사항 | 아키텍처 구성도+요소 표 | 처리 흐름도+단계 표 | 설계 원칙표 | 지표·점검, 리스크 | 구축 절차·확장 방향 |
| 방안형 | 문제 원인과 실행 대책 확인 | 문제 현황 | 원인 구조도+원인 표 | 영향 흐름도+단계 표 | 문제-원인-대책표 | 우선순위, 확인 지표 | 단·중·장기 대책 |
| 운영형 | 지표 기반 통제 역량 확인 | 운영 목표 | 운영 구성도+구성요소 표 | 운영 프로세스도+단계 표 | 지표표 | SLO·RTO/RPO, 점검표 | 자동화·지속 개선 |
| 보안형 | 위협·통제·탐지·복구 연결 역량 확인 | 위협 개요 | 공격면·자산 구조도+자산 표 | 공격 흐름도+단계 표 | 통제 매핑표 | 탐지·대응·복구 지표 | 규제·감사 대응 |

### 실제 치환 예시 1: MSA 장애 대응

| 단락 | 바로 쓸 내용 |
|:---|:---|
| Ⅰ | MSA는 서비스를 도메인 단위로 분리해 독립 배포하는 구조이나, 네트워크 지연·장애 전파·데이터 정합성 문제가 생긴다 |
| Ⅱ | API Gateway -> Service -> DB per Service -> Message Broker -> Observability |
| Ⅲ | Monolith vs MSA 비교: 배포, 확장, 장애격리, 운영복잡도 |
| Ⅳ | Circuit Breaker, Retry/Timeout, Bulkhead, Saga, Distributed Tracing |
| Ⅴ | MSA는 분해보다 운영 자동화와 관측성 확보가 성공 조건 |

손답안 구조도는 아래처럼 먼저 그린다. 웹과 모바일에서 깨지지 않도록 박스 문자 없이 선형 흐름으로 작성한다.

`Ⅱ. 구조(구성요소)` 자리:

```text
Client -> API Gateway -> Service A -> DB per Service
                        |
                        +-> Message Bus -> Observability
```

`Ⅱ. 동작 원리(흐름)` 자리:

```text
Client Request -> Gateway Routing -> Service Processing
-> Event Publish/Consume -> DB Commit -> Trace/Metric Collect
```

구조도는 `Ⅰ. 개요` 다음에 10~15초 안에 뼈대만 그리고, 설명은 `Ⅱ. 구조` 표와 `Ⅱ. 동작 원리` 단계 표에서 채운다.

### 실제 치환 예시 2: RAG 도입

| 단락 | 바로 쓸 내용 |
|:---|:---|
| Ⅰ | RAG는 외부 지식 검색 결과를 LLM 프롬프트에 결합해 최신성·근거성을 높이는 생성형 AI 아키텍처 |
| Ⅱ | Document -> Chunking -> Embedding -> Vector DB -> Retrieval -> Prompt Augmentation -> LLM |
| Ⅲ | Fine-tuning vs RAG 비교: 목적, 비용, 최신성, 보안, 운영 난이도 |
| Ⅳ | 문서 품질관리, 권한 필터링, Hybrid Search, Evaluation, Hallucination Guardrail |
| Ⅴ | 기업 RAG는 모델보다 데이터 거버넌스와 검색 품질이 성패를 좌우 |

손답안 구조도는 아래처럼 먼저 그린다. 박스 문자 없이 입력-저장-검색-생성 흐름을 한 줄 단위로 분리한다.

`Ⅱ. 구조(구성요소)` 자리:

```text
Document -> Chunking -> Embedding -> Vector DB
                              |
Query -> Retriever -> Prompt Augmentation -> LLM -> Answer
```

`Ⅱ. 동작 원리(흐름)` 자리:

```text
문서 적재 -> 청크 분할 -> 임베딩 생성 -> 벡터 검색
-> 프롬프트 보강 -> LLM 생성 -> 답변 반환
```

구조도는 박스를 예쁘게 그리는 것이 아니라, **입력-저장-검색-생성**의 흐름을 깨지지 않게 보이게 만드는 것이 목적이다.

## Ⅴ. 적용 점검 체크리스트

| 체크 | 기준 |
|:---|:---|
| 골격 일치 | 2~4교시 골격은 [모범답안 템플릿](@/exam/cs/model-answer.md)의 정본을 그대로 따랐는가 |
| 출제 의도 | 문제 신호어에서 요구역량을 읽고 핵심·감점 회피 포인트를 답안 초반에 고정했는가 |
| 핵심 선별 | 정보 나열이 아니라 비교축·선택 기준·수치 지표 중심으로 답안이 좁혀졌는가 |
| 과목 적용 | 과목 특성에 따라 표 축과 구조도만 교체했는가 |
| 구조도 시점 | `Ⅰ. 개요` 직후 구조도 뼈대를 먼저 그렸는가 |
| 1교시 연결 | 개요·핵심요소·동작원리·적용 포인트가 Ⅰ~Ⅳ에 자연스럽게 이어지는가 |
