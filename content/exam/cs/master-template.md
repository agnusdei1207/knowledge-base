# 컴퓨터시스템응용기술사 2~4교시 통합 답안 템플릿

이 문서는 `1교시 단답형 모음`이 아니라, **2~4교시 서술형 답안 안에 1교시 단답형 앞단위를 포함시키는 템플릿**이다.
1교시 키워드는 독립 암기 대상이면서 동시에 서술형의 Ⅰ·Ⅱ 단락 재료가 된다.

---

## Ⅰ. 답안 작성 원칙

| 원칙 | 적용 방법 | 피해야 할 형태 |
|:---|:---|:---|
| 문제 요구사항 우선 | 문제 문장의 동사(설명, 비교, 설계, 방안, 문제점)를 목차로 바꾼다 | 외운 목차를 문제와 무관하게 붙임 |
| 1교시는 앞단위 | 정의·구성요소·장단점 3줄을 2~4교시의 Ⅰ·Ⅱ에 삽입한다 | 단답형 답안을 길게 늘여 서술형으로 착각 |
| 2~4교시는 판단 | 구조도, 비교표, 적용 기준, 한계, 운영 방안을 반드시 넣는다 | 개념 설명만 반복 |
| 과목 균형 | 01 컴퓨터구조뿐 아니라 OS, 네트워크, SW, DB, 보안, AI, 클라우드, 경영까지 선택지를 확보한다 | 1과목 지식으로 모든 문제를 해결하려 함 |
| 손글씨 시간 | 25분 안에 3쪽 내외 완성 가능한 목차로 고정한다 | 목차 구상에 시간을 과다 사용 |

## Ⅱ. 2~4교시 기본 골격

### 1. 표준 25점 답안

### 2. 분량 배분

| 단락 | 목표 분량 | 소요 시간 | 핵심 산출물 |
|:---|:---:|:---:|:---|
| Ⅰ 개요 | 0.5쪽 | 3분 | 정의, 배경, 답안 방향 |
| Ⅱ 구조 | 0.8쪽 | 6분 | 구조도 1개, 구성요소 표 |
| Ⅲ 비교 | 0.7쪽 | 6분 | 비교표 또는 특성표 |
| Ⅳ 방안 | 0.7쪽 | 7분 | 단계별 방안, 리스크 대응 |
| Ⅴ 결론 | 0.3쪽 | 2분 | 판단 기준, 미래 방향 |

## Ⅲ. 문제 유형별 치환 템플릿

| 문제 유형 | Ⅰ | Ⅱ | Ⅲ | Ⅳ | Ⅴ |
|:---|:---|:---|:---|:---|:---|
| 설명형 | 정의·필요성 | 구성요소·원리 | 특징표 | 적용 사례 | 발전 방향 |
| 비교형 | 비교 배경 | 공통 구조 | 차이표 | 선택 기준 | 조건별 결론 |
| 설계형 | 요구사항 | 목표 아키텍처 | 구성요소 역할 | 구축 절차·운영 기준 | 확장 방향 |
| 방안형 | 문제 현황 | 원인 구조 | 문제-원인표 | 단·중·장기 대책 | 기대효과 |
| 운영형 | 운영 목표 | 운영 프로세스 | 지표표 | 자동화·통제 | 지속 개선 |
| 보안형 | 위협 정의 | 공격면·자산 | 통제 매핑 | 탐지·대응·복구 | 제로트러스트/규제 |

### 실제 치환 예시: MSA 장애 대응

| 단락 | 바로 쓸 내용 |
|:---|:---|
| Ⅰ | MSA는 서비스를 도메인 단위로 분리해 독립 배포하는 구조이나, 네트워크 지연·장애 전파·데이터 정합성 문제가 생긴다 |
| Ⅱ | API Gateway → Service → DB per Service → Message Broker → Observability |
| Ⅲ | Monolith vs MSA 비교: 배포, 확장, 장애격리, 운영복잡도 |
| Ⅳ | Circuit Breaker, Retry/Timeout, Bulkhead, Saga, Distributed Tracing |
| Ⅴ | MSA는 분해보다 운영 자동화와 관측성 확보가 성공 조건 |

### 실제 치환 예시: RAG 도입

| 단락 | 바로 쓸 내용 |
|:---|:---|
| Ⅰ | RAG는 외부 지식 검색 결과를 LLM 프롬프트에 결합해 최신성·근거성을 높이는 생성형 AI 아키텍처 |
| Ⅱ | Document → Chunking → Embedding → Vector DB → Retrieval → Prompt Augmentation → LLM |
| Ⅲ | Fine-tuning vs RAG 비교: 목적, 비용, 최신성, 보안, 운영 난이도 |
| Ⅳ | 문서 품질관리, 권한 필터링, Hybrid Search, Evaluation, Hallucination Guardrail |
| Ⅴ | 기업 RAG는 모델보다 데이터 거버넌스와 검색 품질이 성패를 좌우 |

## Ⅳ. 16과목별 2~4교시 대응 포인트

| 과목 | 1교시 앞단위 | 2~4교시 확장 질문 | 반드시 넣을 표/도해 |
|:---|:---|:---|:---|
| 01 컴퓨터구조 | 캐시, 파이프라인, 병렬처리 | 성능 병목 원인과 개선 구조 | 계층도, 병목-대책표 |
| 02 운영체제 | 스케줄링, 동기화, 가상메모리 | 자원관리 알고리즘 비교와 운영 선택 | 알고리즘 비교표, 상태전이도 |
| 03 네트워크 | TCP/IP, 라우팅, QoS | 전송 품질·경로 제어·보안 설계 | 계층도, 프로토콜 비교표 |
| 04 소프트웨어공학 | SDLC, Agile, MSA, 품질 | 방법론·아키텍처·품질보증 방안 | 단계-산출물표, 아키텍처도 |
| 05 데이터베이스 | ACID, 인덱스, 정규화 | 성능·일관성·분산DB 설계 | 트랜잭션 흐름도, CAP 비교 |
| 06 ICT 융합 | 디지털트윈, IoT, V2X | 산업 적용 구조와 리스크 대응 | 물리-가상 폐루프도 |
| 07 엔터프라이즈 시스템 | EA, ERP, EAI, BPM | 업무·데이터·시스템 통합 전략 | AS-IS/TO-BE 표 |
| 08 알고리즘·통계 | 복잡도, 그래프, 추론 | 알고리즘 선택 기준과 분석 근거 | 복잡도 비교표 |
| 09 보안 | CIA, ZTA, PKI, SBOM | 위협 모델링과 통제 체계 | 위협-통제 매핑표 |
| 10 인공지능 | Transformer, LLM, MLOps | AI 서비스 설계·운영·거버넌스 | AI 파이프라인도, 평가표 |
| 11 IT 설계·감리 | 감리, RTM, ATAM | 품질·리스크 점검 절차 | 감리 관점표, 추적성표 |
| 12 IT 경영 | ISP, EA, ITIL, BCP | 거버넌스·투자·서비스관리 | 프레임워크 비교표 |
| 13 클라우드 아키텍처 | K8s, 서버리스, FinOps | 클라우드 전환·운영·비용 최적화 | 책임공유표, 배포도 |
| 14 데이터엔지니어링 | ETL/ELT, CDC, Lakehouse | 데이터 파이프라인·품질·거버넌스 | 메달리온 구조도 |
| 15 DevOps·SRE | CI/CD, SLO, GitOps | 배포 자동화와 신뢰성 운영 | 파이프라인도, SLI/SLO 표 |
| 16 빅데이터 | Hadoop, Spark, Kafka | 분산처리·실시간 분석 아키텍처 | Lambda/Kappa 비교표 |

## Ⅴ. 답안 품질 체크리스트

| 체크 | 기준 |
|:---|:---|
| 문제 요구사항 반영 | 문제에 나온 항목이 목차에 그대로 보이는가 |
| 1교시 포함 | 정의·구성요소·장단점이 Ⅰ~Ⅱ에 들어갔는가 |
| 서술형 확장 | 구조도, 비교표, 적용 방안이 각각 1개 이상 있는가 |
| 과목 편중 방지 | 컴퓨터구조만 쓰지 않고 OS/SW/DB/보안/AI/클라우드 축과 연결했는가 |
| 구체성 | 제품명·표준·지표·운영 절차 중 최소 2개가 있는가 |
| 결론 | 조건별 선택 기준과 향후 방향이 있는가 |
