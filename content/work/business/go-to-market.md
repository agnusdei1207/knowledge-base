상위 문서:
- [business](/knowledge-base/work/business/)

---

## 1. 왜 지금 필요한가

최근 대부분의 조직이 AI 도입을 이야기하지만, 실제로는 문서와 맥락 구조가 준비되지 않아 도입 효과가 제한되는 경우가 많습니다.

우리는 이 문제를 다음처럼 정의합니다.

- AI보다 먼저 문서 구조가 필요하다
- 검색보다 먼저 연결이 필요하다
- 도구보다 먼저 운영 규칙이 필요하다

---

## 2. 초기 제안 패키지

### 패키지 A. 내부 위키 정리 킥오프

- 범위: 기존 문서 구조 진단, 문서 분류 기준 수립, 메인 허브 구성
- 산출물:
  - 문서 구조 맵
  - 핵심 인덱스 문서
  - 운영 가이드 초안

### 패키지 B. AI 협업형 지식베이스 구축

- 범위: Markdown 기반 저장소 구성, Quartz 웹 포털, AI 문서 정리 운영안
- 산출물:
  - Git 기반 지식저장소
  - 배포 자동화
  - Claude Code 작업 규칙

### 패키지 C. 부서별 적용 확장

- 범위: 사업, 개발, 운영, 연구 문서 체계 확장
- 산출물:
  - 부서별 템플릿
  - 온보딩 문서 구조
  - 검색 및 재사용 기준

## 3. 초기 세일즈 메시지

- "문서가 많아도 AI가 못 읽으면 생산성이 안 오릅니다."
- "우리는 위키를 만드는 게 아니라, AI와 사람이 같이 쓰는 지식 운영체계를 만듭니다."
- "정적 웹 배포와 Git 기반 운영이라 자산 통제권이 남습니다."

## 4. 리스크와 대응

### 리스크 1. 비개발자 진입장벽

- 대응:
  - GitHub 웹 편집 링크 제공
  - 템플릿 문서 제공
  - 문서 작성 규칙 최소화

### 리스크 2. 초기 문서 정리 비용

- 대응:
  - AI 초안 정리
  - `inbox -> 정리 문서` 흐름 도입
  - 부서별 핵심 문서부터 단계 적용

### 리스크 3. 너무 기술적인 인상

- 대응:
  - 사업 문서와 운영 문서 예시를 먼저 보여주기
  - 결과 화면 중심 데모 준비
  - [business-pipeline](/knowledge-base/work/business-pipeline/) 사례형 문서 축적
