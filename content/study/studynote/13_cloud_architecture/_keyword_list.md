# [[052_cloud_computing_os|클라우드 컴퓨팅]] 및 아키텍처 (Cloud [[319_architecture|Architecture]]) 키워드 목록 (심화 확장판)

정보관리기술사, 컴퓨터응용시스템기술사 및 클라우드 솔루션 아키텍트([[767_sa_standalone_5g_core_network|SA]])를 위한 [[052_cloud_computing_os|클라우드 컴퓨팅]] 전 영역 핵심/심화 키워드 800선입니다.

[[015_virtualization|가상화]]의 기초부터 [[196_kubernetes_k8s_container_orchestration|쿠버네티스]](K8s) [[073_container_orchestration_tools|오케스트레이션]], [[206_serverless_cold_start|서버리스]], [[213_msa_microservices_architecture|마이크로서비스 아키텍처]]([[619_msa_traffic_hardware|MSA]]), 클라우드 보안([[667_zero_trust_runtime_integrity_measurement|제로 트러스트]]), 멀티/[[009_hybrid_cloud|하이브리드 클라우드]] [[268_strategy_pattern|전략]], [[344_finops|FinOps]], SRE까지 클라우드 엔지니어링의 모든 기술 요소를 포함합니다.

## 1. 클라우드 기초 모델 및 [[015_virtualization|가상화]] ([[190_virtualization_computing_architecture_cloud|Virtualization]]) (60개)
1. [[052_cloud_computing_os|클라우드 컴퓨팅]] ([[052_cloud_computing_os|Cloud Computing]]) 5대 특징 (NIST 기준) - 주문형 셀프 [[090_service_kubernetes_network_load_balancing|서비스]], 광범위한 네트워크 접속, 리소스 [[285_pooling_layer|풀링]], 신속한 [[571_resiliency_fault_tolerance_patterns|탄력성]](Elasticity), 측정 가능한 [[090_service_kubernetes_network_load_balancing|서비스]]
2. [[183_iaas_infrastructure_as_a_service|IaaS]] (Infrastructure [[344_as_autonomous_system_asn|as]] a [[090_service_kubernetes_network_load_balancing|Service]]) - 서버([[598_vm_migration_nic|VM]]), 스토리지, 네트워크 인프라 제공 (AWS EC2, S3)
3. [[184_paas_platform_as_a_service|PaaS]] (Platform [[344_as_autonomous_system_asn|as]] a [[090_service_kubernetes_network_load_balancing|Service]]) - OS, 런타임, 미들웨어, DB가 세팅된 개발/운영 플랫폼 제공 (AWS Elastic Beanstalk, Heroku)
4. [[309_saas|SaaS]] (Software [[344_as_autonomous_system_asn|as]] a [[090_service_kubernetes_network_load_balancing|Service]]) - 브라우저 기반 완제품 소프트웨어 제공 (Google Workspace, Salesforce)
5. [[186_baas_backend_as_a_service_firebase|BaaS]] (Backend [[344_as_autonomous_system_asn|as]] a [[090_service_kubernetes_network_load_balancing|Service]]) - 모바일/웹 앱을 위한 공통 백엔드 [[014_api_posix|API]] ([[303_authentication_authorization_patterns|인증]], 푸시, DB) 제공 (Firebase)
6. [[342_faas|FaaS]] (Function [[344_as_autonomous_system_asn|as]] a [[090_service_kubernetes_network_load_balancing|Service]] / [[206_serverless_cold_start|Serverless]]) - 인프라 관리 없이 함수 코드 조각 단위로 배포/실행 (AWS [[216_lambda_kappa_architecture_batch_realtime|Lambda]])
7. [[007_public_cloud|퍼블릭 클라우드]] ([[007_public_cloud|Public Cloud]]) - 다수의 기업이 공유하는 공용 인프라 (AWS, Azure, GCP)
8. [[008_private_cloud|프라이빗 클라우드]] ([[008_private_cloud|Private Cloud]]) - 단일 기업 전용으로 자체 [[801_data_center_3_tier_architecture_core_aggregation_access|데이터센터]]([[061_on_premise_legacy_infrastructure|On-Premise]]) 내부에 구축된 클라우드 (OpenStack 등)
9. [[009_hybrid_cloud|하이브리드 클라우드]] ([[009_hybrid_cloud|Hybrid Cloud]]) - 퍼블릭과 프라이빗(또는 레거시) 클라우드를 망연계([[983_vpn_virtual_private_network|VPN]], [[266_leased_line_basics_e1_t1_t3|전용선]])하여 혼용하는 모델
[[489_raid_10_hybrid|10]]. [[202_multi_cloud_hybrid_cloud_governance|멀티 클라우드]] ([[202_multi_cloud_hybrid_cloud_governance|Multi-Cloud]]) - 특정 [[051_vendor_lock_in_cloud_computing|벤더 종속]]([[362_lock_in_portability|Lock-in]]) 회피 및 [[452_availability|가용성]] 극대화를 위해 2개 이상의 [[007_public_cloud|퍼블릭 클라우드]](AWS + Azure 등)를 동시 사용
[[308_static_dynamic_nat_pat_port_address_translation|11]]. [[242_distributed_cloud_edge_computing_aws_outposts|분산 클라우드]] ([[242_distributed_cloud_edge_computing_aws_outposts|Distributed Cloud]]) - [[007_public_cloud|퍼블릭 클라우드]] [[090_service_kubernetes_network_load_balancing|서비스]]를 다양한 물리적 위치(엣지, 고객사 [[801_data_center_3_tier_architecture_core_aggregation_access|데이터센터]])에 [[136_variance|분산]] 배포하되, CSP가 일괄 통제
12. [[235_edge_computing_smart_factory|엣지 컴퓨팅]] ([[235_edge_computing_smart_factory|Edge Computing]]) - 클라우드 중앙 서버로 보내지 않고 단말 주변(Edge)에서 [[001_dikw_pyramid|데이터]] 실시간 처리 (저지연, [[140_bandwidth|대역폭]] 절약)
13. [[106_fog_computing_cisco_architecture|포그 컴퓨팅]] ([[106_fog_computing_cisco_architecture|Fog Computing]]) - 엣지와 클라우드 사이의 로컬 네트워크(게이트웨이) 단에서 1차 [[001_dikw_pyramid|데이터]] 처리
14. [[014_multi_tenancy|멀티 테넌시]] ([[014_multi_tenancy|Multi-Tenancy]]) - 하나의 소프트웨어/인스턴스가 여러 고객(Tenant)에게 독립적으로 [[090_service_kubernetes_network_load_balancing|서비스]]되도록 [[369_logic_bomb|논리]]적 분리 보장 (SaaS의 핵심)
15. [[015_virtualization|가상화]] ([[190_virtualization_computing_architecture_cloud|Virtualization]]) - 물리적 하드웨어(CPU, RAM, 디스크)를 [[369_logic_bomb|논리]]적인 여러 개의 자원([[598_vm_migration_nic|Virtual Machine]])으로 분할하는 기술
16. [[054_hypervisor|하이퍼바이저]] ([[054_hypervisor|Hypervisor]] / VMM) - 가상 머신(Guest OS)을 [[087_process_state_transition|생성]]하고 하드웨어를 분배/[[208_schedule_history_transaction_execution_order|스케줄]]링하는 [[015_virtualization|가상화]] [[022_kernel_role|커널]] 소프트웨어
17. Type 1 [[054_hypervisor|하이퍼바이저]] (베어메탈, Bare-metal) - 하드웨어 위에 OS 없이 직접 설치되어 오버헤드가 적고 고성능 (VMware ESXi, Xen, [[713_kvm_over_ip|KVM]])
18. Type 2 [[054_hypervisor|하이퍼바이저]] (호스트형, Hosted) - 호스트 OS 위에서 하나의 애플리케이션처럼 구동 (VMware Workstation, VirtualBox)
19. [[057_full_virtualization|전가상화]] ([[057_full_virtualization|Full Virtualization]]) - 하드웨어 전체를 에뮬레이션, Guest OS 수정 없이 그대로 구동 (Binary Translation 방식 등, 속도 저하)
20. [[058_paravirtualization|반가상화]] ([[192_full_virtualization_vs_para_virtualization|Para-virtualization]]) - Guest OS의 [[022_kernel_role|커널]]을 일부 수정하여 [[054_hypervisor|하이퍼바이저]]와 [[120_direct_communication|직접 통신]](Hypercall), [[057_full_virtualization|전가상화]]보다 오버헤드 적음 (Xen)
21. [[059_hardware_assisted_virtualization|하드웨어 보조 가상화]] ([[021_hardware_assisted_virtualization|Hardware-assisted Virtualization]]) - CPU에 [[015_virtualization|가상화]] 지원 [[158_instruction|명령어]]([[658_intel_vtx|Intel VT-x]], [[659_amd_v|AMD-V]])를 탑재해 [[057_full_virtualization|전가상화]]의 [[282_performance_tactics|성능]] 저하 해결 (현재의 표준)
22. [[497_sr_iov_pcie_mapping|SR-IOV]] (Single Root I/O [[190_virtualization_computing_architecture_cloud|Virtualization]]) - 하나의 물리적 [[356_pcie|PCIe]] 네트워크 카드([[587_nic_offloading|NIC]])를 여러 VM에 [[369_logic_bomb|논리]]적으로 직접 매핑해 [[054_hypervisor|하이퍼바이저]] [[238_switch_operation_principles|스위치]] 오버헤드 우회 ([[148_5g_embb_urllc_mmtc|초고속]] I/O)
23. [[858_sddc_software_defined_data_center_infrastructure|소프트웨어 정의 데이터센터]] ([[631_sddc|SDDC]], Software Defined [[801_data_center_3_tier_architecture_core_aggregation_access|Data Center]]) - 컴퓨팅, 스토리지, 네트워킹을 모두 [[015_virtualization|가상화]](SDC, [[632_sds|SDS]], [[633_sdn_whitebox|SDN]])하여 API로 [[528_provisioning|프로비저닝]]하는 [[801_data_center_3_tier_architecture_core_aggregation_access|데이터센터]]
24. [[633_sdn_whitebox|SDN]] ([[215_sdn_software_defined_networking_openflow|Software Defined Networking]]) - 제어 평면(Control Plane)과 [[001_dikw_pyramid|데이터]] 전송 평면([[001_dikw_pyramid|Data]] Plane)을 분리하여 네트워크 장비를 중앙 집중식으로 프로그래밍 통제
25. [[632_sds|SDS]] ([[632_sds|Software Defined Storage]]) - 범용 x86 서버 하드웨어를 묶어 [[136_variance|분산]]/[[015_virtualization|가상화]] 소프트웨어를 통해 하나의 스토리지 풀로 운영 (Ceph 등)
26. [[630_hci|HCI]] (Hyper-Converged Infrastructure) - 서버, 스토리지, 네트워킹 [[015_virtualization|가상화]] 솔루션을 단일 x86 어플라이언스 노드에 통합 패키징 ([[079_developer_cleanroom_vdi_security|VDI]] 및 [[008_private_cloud|프라이빗 클라우드]] 구축 용이)
27. [[629_bare_metal_cloud|베어메탈 클라우드]] ([[629_bare_metal_cloud|Bare Metal Cloud]]) - [[015_virtualization|가상화]]([[054_hypervisor|하이퍼바이저]]) 없이 고객에게 물리 서버 전체를 통째로 임대하여 극강의 [[282_performance_tactics|성능]]과 보안 분리 제공 (DB 최적화)
28. 가상 [[008_private_cloud|프라이빗 클라우드]] ([[836_vpc_virtual_private_cloud_subnet_isolation|VPC]], [[028_vpc|Virtual Private Cloud]]) - [[007_public_cloud|퍼블릭 클라우드]] 내에 가상의 [[369_logic_bomb|논리]]적 격리 네트워크(서브넷, [[339_routing_overview_best_path_selection|라우팅]], [[690_firewall_generation_evolution|방화벽]])를 구축하는 [[090_service_kubernetes_network_load_balancing|서비스]]
29. [[621_scale_up_system_bus|스케일 업]] ([[621_scale_up_system_bus|Scale-up]] / 수직적 확장) - 서버 자체의 CPU, 메모리 사양을 높임 (DB [[075_kubernetes_k8s_cluster_architecture|마스터 노드]] 등에 적합, 확장 한계 존재)
30. [[202_scale_out_distributed_horizontal_expansion|스케일 아웃]] ([[202_scale_out_distributed_horizontal_expansion|Scale-out]] / 수평적 확장) - 저사양 서버 인스턴스 개수를 [[430_index_fast_full_scan|병렬]]로 여러 대 늘려 부하 [[136_variance|분산]] (웹/WAS 서버에 적합, 무한 확장 가능)
31. 오토 [[249_scaling_normalization_standardization|스케일링]] ([[030_auto_scaling|Auto Scaling]]) - CPU 사용량, 트래픽 등 [[431_ssthresh_slow_start_threshold|임계치]](Threshold)에 따라 서버([[598_vm_migration_nic|VM]]/[[198_pod_kubernetes_minimum_deployment_unit|Pod]]) 개수를 자동으로 늘리고([[202_scale_out_distributed_horizontal_expansion|Scale-out]]) 줄이는(Scale-in) 기능
32. 로드 밸런서 ([[031_load_balancer|Load Balancer]]) - L4(네트워크/전송 계층) 또는 L7(애플리케이션 계층)에서 트래픽을 여러 백엔드 인스턴스로 균등 분배
33. 블록 스토리지 (Block Storage) - 디스크 공간을 블록 단위로 나누어 VM에 직접 [[516_mount_mechanism|마운트]](Attach)하여 사용하는 고성능 스토리지 (OS 설치, DB용 / AWS EBS)
34. [[501_file_definition_logical_record|파일]] 스토리지 ([[501_file_definition_logical_record|File]] Storage) - [[506_directory_structure_symbol_table|디렉터리]] 트리 구조로 [[501_file_definition_logical_record|파일]] 공유 ([[543_nfs_network_file_system|NFS]], SMB [[295_protocol_field_tcp_udp_icmp|프로토콜]] / AWS EFS)
35. [[494_object_storage|오브젝트 스토리지]] ([[494_object_storage|Object Storage]]) - 플랫(Flat)한 [[061_namespace|네임스페이스]]에 객체([[001_dikw_pyramid|데이터]]+[[012_metadata|메타데이터]]) 형태로 저장, [[477_rest_api_architecture|REST API]]([[461_http_stateless_connection_oriented|HTTP]])를 통해 무한한 용량 접근 가능 (이미지, [[555_backup_and_restore_strategy|백업]], 빅데이터 저장 / AWS S3)
36. [[506_cdn_content_delivery_network_edge_caching|CDN]] (Content Delivery Network) - 전 세계 엣지(Edge) 서버에 정적 콘텐츠(이미지, 동영상)를 [[456_caching|캐싱]]하여 사용자에게 가장 가까운 위치에서 [[017_전송_지연|전송 지연]] 단축
37. 온디맨드 인스턴스 (On-Demand) - 필요할 때마다 초/시간 단위로 사용한 만큼만 지불
38. 예약 인스턴스 (Reserved Instance / RI) - 1~3년 장기 약정을 조건으로 대폭 할인받는 요금제 (상시 구동되는 코어 시스템용)
39. [[209_spot_instance_cloud_cost_optimization|스팟 인스턴스]] ([[209_spot_instance_cloud_cost_optimization|Spot Instance]]) - 클라우드 벤더의 남는 잉여 자원을 경매 방식으로 최대 90% 저렴하게 이용, 단 벤더 필요 시 언제든 회수당할 수 있음 (중단 가능한 [[228_batch_processing_hadoop_spark|배치 처리]], [[561_container_based_deployment|컨테이너]] 빅데이터 연산에 최적)
40. 오버프로비저닝 (Over-provisioning) 방지 / Right Sizing (용량 최적화) - [[344_finops|FinOps]] 재무 관리 핵심
41. 마이그레이션 6R (클라우드 전환 [[268_strategy_pattern|전략]])
42. Rehost ([[212_rehost_lift_and_shift_migration_strategy|리호스트]] / [[086_lift_association_rule_marketing|Lift]] and Shift) - [[061_on_premise_legacy_infrastructure|온프레미스]] [[598_vm_migration_nic|VM]]/애플리케이션을 변경 없이 클라우드 IaaS로 그대로 이관 (가장 빠름, 클라우드 이점 부족)
43. Replatform (리플랫폼) - 핵심 아키텍처는 유지하되 OS나 DB 등을 클라우드 관리형(RDS 등) [[090_service_kubernetes_network_load_balancing|서비스]]로 일부 최적화
44. [[213_refactoring_cloud_native_rearchitecture|Refactor]] / Re-architect (리팩터) - [[531_cloud_native_architecture|클라우드 네이티브]] 이점을 얻기 위해 모놀리식 구조를 [[532_microservices_decomposition_patterns|마이크로서비스]]([[619_msa_traffic_hardware|MSA]]) 및 [[206_serverless_cold_start|서버리스]]로 전면 재설계
45. Repurchase (재구매) - 기존 라이선스 소프트웨어를 버리고 클라우드 [[309_saas|SaaS]](Salesforce 등)로 대체
46. Retire (폐기) - 불필요한 시스템 제거 / Retain (유지) - 당장 이관 불가한 시스템 [[061_on_premise_legacy_infrastructure|온프레미스]] 잔류
47. 클라우드 브로커 (CSB, Cloud [[090_service_kubernetes_network_load_balancing|Service]] Brokerage) - 여러 클라우드 [[090_service_kubernetes_network_load_balancing|서비스]]를 중개, 통합, 커스터마이징하여 기업에 제공
48. MSP ([[060_cloud_msp_managed_service_provider|Managed Service Provider]]) - 클라우드 도입 컨설팅, 이관, 운영/관제 대행 전문 기업
49. 섀도우 IT ([[049_shadow_it|Shadow IT]]) - 현업 부서가 IT/보안팀 승인 없이 SaaS를 임의 결제해 사용하는 [[096_risk_non_risk_architecture_evaluation_flaws|리스크]]
50. [[001_dikw_pyramid|데이터]] 그래비티 ([[001_dikw_pyramid|Data]] Gravity) - 대용량 [[001_dikw_pyramid|데이터]]가 모인 곳으로 애플리케이션, [[090_service_kubernetes_network_load_balancing|서비스]]가 끌려가게 되는 현상 (클라우드 락인의 주원인)

## 3. [[213_msa_microservices_architecture|마이크로서비스 아키텍처]] ([[619_msa_traffic_hardware|MSA]]) 및 [[206_serverless_cold_start|서버리스]] (60개)
121. [[121_monolithic_architecture|모놀리식 아키텍처]] ([[121_monolithic_architecture|Monolithic Architecture]]) - 모든 기능 [[192_module_independence|모듈]], UI, DB가 하나의 코드베이스로 강결합(Tightly Coupled)된 전통적 구조 (장점: 디버깅/통합테스트 용이, 단점: 빌드시간 [[015_지연_데이터_관점|지연]], 작은 수정 시 전체 재배포, 단일 기술 [[057_stack|스택]] 종속)
122. [[213_msa_microservices_architecture|마이크로서비스 아키텍처]] ([[619_msa_traffic_hardware|MSA]]) - 애플리케이션을 비즈니스 [[064_relation_domain|도메인]] 중심의 작고 독립적인 [[090_service_kubernetes_network_load_balancing|서비스]]들로 쪼개어(Loosely Coupled), 각기 다른 팀이 자율적으로 선택한 언어/DB로 개발 및 독립 배포하는 구조
123. [[618_soa_hardware|SOA]] vs [[619_msa_traffic_hardware|MSA]] - SOA는 전사 재사용 목적 중앙 집중식 [[146_esb_enterprise_service_bus_architecture|ESB]]([[146_esb_enterprise_service_bus_architecture|Enterprise Service Bus]]) 활용, MSA는 [[064_relation_domain|도메인]] 분리 목적 [[145_message_broker_sync_async|메시지 브로커]] 기반 [[136_variance|분산]] 안무(Choreography) 지향
124. [[014_api_posix|API]] 게이트웨이 ([[542_api_gateway|API Gateway]]) - 클라이언트와 수많은 [[532_microservices_decomposition_patterns|마이크로서비스]]들 사이에 위치하는 단일 진입점 [[264_proxy_pattern_surrogate_access_control|프록시]]

[[014_api_posix|API]] 게이트웨이 주요 기능 - [[341_dynamic_routing_protocol_operation|동적 라우팅]], [[303_authentication_authorization_patterns|인증]]/[[509_authorization_models_rbac_abac|인가]] 통합, 요청 통합(Aggregation), [[295_protocol_field_tcp_udp_icmp|프로토콜]] 변환, 스로틀링(Throttling/[[520_rate_limiting|Rate Limiting]])
126. [[309_bff_backend_for_frontend_pattern|백엔드 포 프론트엔드]] ([[543_bff_backend_for_frontend|BFF]], [[543_bff_backend_for_frontend|Backend For Frontend]]) - 모바일, 웹, 태블릿 등 클라이언트 환경마다 맞춤형 응답을 제공하기 위해 [[014_api_posix|API]] 게이트웨이를 별도 구축하는 패턴
127. [[306_service_discovery_pattern|서비스 디스커버리]] ([[303_service_discovery|Service Discovery]]) - 클라우드 환경에서 오토스케일링으로 동적으로 변하는 [[561_container_based_deployment|컨테이너]]([[090_service_kubernetes_network_load_balancing|서비스]])의 IP와 [[446_port_and_bus|Port]] 위치를 [[235_registry_immutable_tag|레지스트리]]에 등록하고 찾는 매커니즘 (클라이언트 사이드 vs 서버 사이드 탐색)
128. [[307_circuit_breaker_pattern|서킷 브레이커]] ([[304_circuit_breaker|Circuit Breaker]]) 패턴 - 특정 [[090_service_kubernetes_network_load_balancing|서비스]]가 장애/[[573_timeout_retry_backoff_strategy|타임아웃]] 상태일 때, 해당 [[090_service_kubernetes_network_load_balancing|서비스]]로의 호출을 조기에 차단(회로 Open)하여 [[092_thread_lwp|스레드]] 락 등 시스템 전체로 장애가 확산(Cascading Failure)되는 것을 방지하는 [[233_recovery_database_restoration_overview|회복]] [[571_resiliency_fault_tolerance_patterns|탄력성]]([[571_resiliency_fault_tolerance_patterns|Resiliency]]) 기법 (Resilience4j 등)
129. [[171_fallback_resilience_pattern|폴백]] ([[129_fallback|Fallback]]) - 서킷이 Open되었을 때 에러 [[286_page_frame|페이지]] 대신 [[456_caching|캐싱]]된 과거 [[001_dikw_pyramid|데이터]]나 디폴트 안내 화면을 반환하여 [[090_service_kubernetes_network_load_balancing|서비스]] 무중단을 흉내 내는 [[268_strategy_pattern|전략]]
130. [[308_bulkhead_pattern|벌크헤드]] ([[308_bulkhead_pattern|Bulkhead]] / 격벽) 패턴 - 배의 격벽처럼, 특정 [[090_service_kubernetes_network_load_balancing|서비스]] 호출용 [[092_thread_lwp|스레드]] 풀을 격리시켜 하나의 장애가 전체 리소스를 고갈시키지 않게 방어
131. [[311_database_per_service_pattern|데이터베이스 퍼 서비스]] ([[311_database_per_service_pattern|Database per Service]]) - [[532_microservices_decomposition_patterns|마이크로서비스]] 간에 절대 DB 테이블을 직접 공유하지 않고, 오직 API로만 [[001_dikw_pyramid|데이터]]를 교환하여 캡슐화와 기술 독립성([[132_polyglot_persistence|Polyglot Persistence]]) 보장
132. [[308_pgvector|폴리글랏 퍼시스턴스]] ([[132_polyglot_persistence|Polyglot Persistence]]) - 각 [[090_service_kubernetes_network_load_balancing|서비스]]의 트래픽/특성에 맞춰 RDBMS(결제), [[035_nosql|NoSQL]]([[568_logs_distributed_logging_elk_fluentd|로그]]), [[039_graph_db|Graph DB]](추천) 등을 다양하게 혼용
133. [[549_2pc_two_phase_commit_limitations_msa|2PC]] ([[549_2pc_two_phase_commit_limitations_msa|Two-Phase Commit]]) 한계 - [[619_msa_traffic_hardware|MSA]] [[136_variance|분산]] DB 환경에서 [[191_transaction_concept_states|트랜잭션]] [[212_synchronization_mechanisms|동기화]]를 위해 코디네이터가 락([[510_lock|Lock]])을 걸면 [[282_performance_tactics|성능]] 병목(블로킹)이 극심해 클라우드에서 배제됨

135. [[553_choreography_saga_event_driven|코레오그래피 사가]] (Choreography) - 중앙 통제 없이 각 [[090_service_kubernetes_network_load_balancing|서비스]]가 비동기 이벤트를 발생(Publish)하고 구독(Subscribe)하며 자율적으로 댄스하듯 연쇄 [[216_progress_in_synchronization|진행]] (설계 단순, 디버깅 어려움)
136. [[552_orchestration_saga_centralized_control|오케스트레이션 사가]] ([[073_container_orchestration_tools|Orchestration]]) - 중앙 오케스트레이터(지휘자 컨트롤러)가 상태 기계([[272_state_pattern|State]] Machine)를 들고 다음 [[191_transaction_concept_states|트랜잭션]]을 호출하며 흐름을 전면 통제 (복잡한 흐름, [[454_spof|SPOF]] 위험)

[[014_concurrency|동시성]] 문제 파훼 및 완벽 [[606_auditing_linux_auditd|감사]] [[568_logs_distributed_logging_elk_fluentd|로그]] 제공

[[538_event_driven_architecture_eda|이벤트 기반 아키텍처]] ([[064_eda|EDA]], [[140_event_driven_architecture_eda|Event-Driven Architecture]]) - [[619_msa_traffic_hardware|MSA]] 간 통신 시 [[477_rest_api_architecture|REST API]] 동기 통신의 [[195_coupling_levels|결합도]]를 끊기 위해 [[179_kafka_flink_watermark_time_window|카프카]]([[179_kafka_flink_watermark_time_window|Kafka]]) 등 [[389_mesh_topology|메시]]지 큐를 통한 철저한 비동기/[[195_coupling_levels|결합도]] 해소 지향

[[183_microservice_chassis_pattern|마이크로서비스 샤시]] ([[141_microservice_chassis|Microservice Chassis]]) - 로깅, [[342_routing_metric_hop_bandwidth_delay|메트릭]], [[569_distributed_tracing_opentelemetry_jaeger|분산 추적]], [[306_service_discovery_pattern|서비스 디스커버리]] 등록 등 횡단 관심사(Boilerplate) 코드를 템플릿화한 프레임워크 기반 [[090_service_kubernetes_network_load_balancing|서비스]] 뼈대 (Spring Boot Starter 등)
