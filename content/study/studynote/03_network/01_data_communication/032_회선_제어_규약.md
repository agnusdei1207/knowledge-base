> **핵심 인사이트 3줄**
> 1. 회선 제어 규약(Line Control [[295_protocol_field_tcp_udp_icmp|Protocol]])은 [[001_dikw_pyramid|데이터]] 링크 계층에서 회선 접근·[[212_synchronization_mechanisms|동기화]]·[[188_error_control_overview|오류 제어]]·[[213_flow_control_buffer_overflow|흐름 제어]]를 담당하는 [[295_protocol_field_tcp_udp_icmp|프로토콜]] 집합이다.
> 2. 문자 지향([[019_bsc|BSC]])→[[073_bit|비트]] 지향([[216_hdlc_high_level_data_link_control|HDLC]]·[[131_sdlc_system_development_life_cycle_waterfall_agile|SDLC]]) 발전으로 전송 효율과 [[642_reliability_mtbf_mttr_mttf_availability|신뢰성]]이 크게 향상되었다.
> 3. [[216_hdlc_high_level_data_link_control|HDLC]](High-level [[001_dikw_pyramid|Data]] Link Control)는 ISO 표준으로 현재도 ISDN·위성·WAN 링크에서 슬라이딩 윈도우 기반 ARQ를 구현한다.

## Ⅰ. 회선 제어 규약의 개요와 [[104_classification_analysis|분류]]

회선 제어 규약(Line Control [[295_protocol_field_tcp_udp_icmp|Protocol]])은 **물리 링크 위에서 [[001_dikw_pyramid|데이터]] 전송을 [[642_reliability_mtbf_mttr_mttf_availability|신뢰성]] 있게 수행**하기 위한 규약이다. 크게 문자 지향(Character-Oriented)과 [[073_bit|비트]] 지향(Bit-Oriented) 방식으로 [[104_classification_analysis|분류]]된다.

| [[104_classification_analysis|분류]]          | 대표 [[295_protocol_field_tcp_udp_icmp|프로토콜]] | 특징                          |
|-------------|-------------|-------------------------------|
| 문자 지향     | [[019_bsc|BSC]]         | 제어 문자(STX/ETX) 기반        |
| [[073_bit|비트]] 지향     | [[216_hdlc_high_level_data_link_control|HDLC]], [[131_sdlc_system_development_life_cycle_waterfall_agile|SDLC]]  | [[186_character_stuffing_dle_stx_etx|플래그]](01111110) 기반 프레임   |
| [[185_byte_counting_framing|바이트 카운트]] | DDCMP       | 헤더에 [[074_byte|바이트]] 수 명시          |

### 회선 제어 5대 기능

1. **회선 접속** — [[369_logic_bomb|논리]]적 연결 [[009_config|설정]] (Setup)
2. **동기 제어** — [[073_bit|비트]]/문자/프레임 동기 맞춤
3. **[[213_flow_control_buffer_overflow|흐름 제어]]** — 수신자 버퍼 넘침 방지
4. **[[188_error_control_overview|오류 제어]]** — [[113_crc|CRC]] 검출 + [[949_arq_automatic_repeat_request_go_back_n_selective|ARQ]] 재전송
5. **회선 해제** — 전송 완료 후 [[369_logic_bomb|논리]] 연결 해제

📢 **섹션 요약 비유**: 회선 제어 규약은 도로 교통 법규와 같다. [[130_signal|신호]](동기), 차선([[213_flow_control_buffer_overflow|흐름 제어]]), 사고 처리([[188_error_control_overview|오류 제어]]), 진입/진출(접속/해제) 규칙이 모두 포함된다.

## Ⅱ. [[019_bsc|BSC]] (Binary [[010_동기식_비동기식_전송|Synchronous]] Communication)

BSC는 IBM이 1960년대 개발한 **문자 지향 반이중 [[295_protocol_field_tcp_udp_icmp|프로토콜]]**이다.

```
[STX] [데이터] [ETX] [BCC]
 시작   본문   종료  오류검사
```

| 제어 문자 | 의미                    |
|----------|------------------------|
| STX      | 본문 시작 (Start of Text) |
| ETX      | 본문 종료 (End of Text)  |
| ENQ      | 회선 [[396_validation|확인]] 요청            |
| ACK      | 긍정 응답                |
| [[211_nak_negative_acknowledgement|NAK]]      | 부정 응답 (재전송 요청)   |
| SYN      | 동기 문자                |

**[[019_bsc|BSC]] 한계**: 반이중, 포인트-투-포인트만, 다중점 제한, 에러 제어 취약

📢 **섹션 요약 비유**: BSC는 무전기 통신이다. "오버"를 외쳐야(ENQ/ACK) 상대가 말할 수 있고, 한 번에 한 방향만 통신된다.

## Ⅲ. [[216_hdlc_high_level_data_link_control|HDLC]] (High-level [[001_dikw_pyramid|Data]] Link Control) — 핵심

HDLC는 ISO가 정의한 **[[073_bit|비트]] 지향 전이중 [[295_protocol_field_tcp_udp_icmp|프로토콜]]**로, X.25·ISDN·PPP의 기반이 된다.

### [[216_hdlc_high_level_data_link_control|HDLC]] 프레임 구조

```
┌────────┬──────────┬────────────┬──────────┬────────┐
│ Flag   │ Address  │  Control   │  Data    │  FCS   │
│01111110│  8 bit   │  8/16 bit  │ 가변 길이 │ 16/32b │
└────────┴──────────┴────────────┴──────────┴────────┘
```

### 프레임 종류

| 프레임  | 기호 | 기능                            |
|--------|------|---------------------------------|
| [[220_hdlc_frames_i_s_u|I-Frame]] | 000  | 정보 전송 + 피기백 ACK/[[211_nak_negative_acknowledgement|NAK]]      |
| S-Frame | 01   | 감시 ([[834_load_balancing_algorithm_round_robin_least_connection|RR]]/RNR/REJ/SREJ)          |
| U-Frame | [[308_static_dynamic_nat_pat_port_address_translation|11]]   | 비번호 ([[009_config|설정]]·해제·초기화)        |

### [[216_hdlc_high_level_data_link_control|HDLC]] 스테이션 모드

- **[[219_nrm_arm_abm_hdlc_modes|NRM]] (Normal Response Mode)**: 마스터-슬레이브, [[448_polling_programmed_io|폴링]] 방식
- **ARM (Asynchronous Response Mode)**: 슬레이브 자발 전송 가능
- **ABM (Asynchronous Balanced Mode)**: 양방향 대등 전송 → LAP-B, [[224_ppp_point_to_point_protocol|PPP]]

📢 **섹션 요약 비유**: HDLC는 양방향 고속도로다. BSC가 일방통행 국도였다면, HDLC는 차선별로 다른 종류의 [[130_signal|신호]](I/S/U 프레임)를 동시에 보낼 수 있는 자동차 전용도로다.

## Ⅳ. 슬라이딩 윈도우와 [[949_arq_automatic_repeat_request_go_back_n_selective|ARQ]] 제어

### 슬라이딩 윈도우 (Sliding Window) [[295_protocol_field_tcp_udp_icmp|프로토콜]]

```
송신측 윈도우: [ 3 | 4 | 5 | 6 | 7 ]  (미확인 전송 가능 프레임)
수신측:        ACK3 수신 → 윈도우 이동 → [ 4 | 5 | 6 | 7 | 8 ]
```

| [[949_arq_automatic_repeat_request_go_back_n_selective|ARQ]] 방식    | 재전송 방식            | 효율          |
|------------|----------------------|---------------|
| Stop-and-Wait | 1프레임씩 ACK 대기  | 낮음 (1/[[441_rtt_round_trip_time_srtt_smoothed|RTT]])  |
| Go-Back-N   | 오류 이후 전부 재전송 | 중간           |
| Selective Repeat | 오류 프레임만 재전송 | 높음 (버퍼↑) |

**[[413_tcp_window_size_flow_control_16bit|윈도우 크기]]**: n비트 순서번호 → Go-Back-N: 2ⁿ-1, SR: 2ⁿ⁻¹

📢 **섹션 요약 비유**: 슬라이딩 윈도우는 택배 기사가 [[396_validation|확인]] 전화 없이 여러 집에 미리 배달하는 것과 같다. 반품([[211_nak_negative_acknowledgement|NAK]])이 오면 Go-Back-N은 그 이후 전부 다시 배달하고, SR은 그 집 것만 다시 배달한다.

## Ⅴ. PPP와 현대 링크 계층 [[295_protocol_field_tcp_udp_icmp|프로토콜]]

### [[224_ppp_point_to_point_protocol|PPP]] ([[224_ppp_point_to_point_protocol|Point-to-Point Protocol]])

[[216_hdlc_high_level_data_link_control|HDLC]] 기반에서 발전한 PPP는 인터넷 다이얼업·DSL·[[225_lcp_link_control_protocol|LCP]]/[[226_ncp_network_control_protocol|NCP]] 협상을 지원한다.

```
PPP 연결 설정 과정:
Dead → Establish (LCP) → Authenticate → Network (NCP) → Open
```

| [[295_protocol_field_tcp_udp_icmp|프로토콜]]    | 계층  | 특징                         |
|------------|------|------------------------------|
| [[224_ppp_point_to_point_protocol|PPP]]        | L2   | 다중 [[295_protocol_field_tcp_udp_icmp|프로토콜]], [[303_authentication_authorization_patterns|인증]]([[227_pap_password_authentication_protocol|PAP]]/[[228_chap_challenge_handshake_authentication_protocol|CHAP]]) |
| PPPoE      | L2   | [[230_ethernet_structure_and_principles_ieee_802_3|이더넷]] 위 [[224_ppp_point_to_point_protocol|PPP]] (DSL)           |
| MLPPP      | L2   | 다중 링크 묶음                |
| [[379_l2tp_layer_2_tunneling_protocol|L2TP]]       | L2   | [[983_vpn_virtual_private_network|VPN]] [[377_tunneling_mechanism_overview|터널링]]                    |

📢 **섹션 요약 비유**: PPP는 표준 전화잭처럼 어떤 기기든 연결되도록 만든 규격이다. 기기 종류([[226_ncp_network_control_protocol|NCP]])와 연결 [[009_config|설정]]([[225_lcp_link_control_protocol|LCP]])을 협상 후 [[001_dikw_pyramid|데이터]]를 전달한다.

## 📌 관련 개념 맵

```
회선 제어 규약
├── 문자 지향
│   └── BSC (Binary Synchronous Communication)
│       ├── STX/ETX 프레임
│       └── ACK/NAK 응답
├── 비트 지향
│   ├── HDLC (High-level Data Link Control)
│   │   ├── I-Frame / S-Frame / U-Frame
│   │   └── NRM / ARM / ABM 모드
│   └── SDLC (IBM 독점 → HDLC 표준화)
├── 흐름/오류 제어
│   ├── 슬라이딩 윈도우 (Sliding Window)
│   ├── Go-Back-N ARQ
│   └── Selective Repeat ARQ
└── 현대 응용
    ├── PPP / PPPoE
    ├── L2TP
    └── X.25 / ISDN 링크
```

## 👶 어린이를 위한 3줄 비유 설명

1. 회선 제어 규약은 편지 배달 규칙이다 — 봉투 형식, 주소 쓰는 법, 반품 처리 방법이 모두 정해져 있다.
2. [[216_hdlc_high_level_data_link_control|HDLC]] 프레임은 특급 우편 봉투다 — 앞에 보내는 사람 주소, 뒤에 분실 방지 스티커가 붙어있다.
3. 슬라이딩 윈도우는 편의점 배달 앱이다 — [[396_validation|확인]] 전화 없이 여러 건 미리 배달하고, 반품만 다시 가져간다.
