## 핵심 인사이트 (3줄 요약)

> 1. **본질**: [[164_pc|PC]] (Program [[059_counter|Counter]]) 상대 주소 지정 ([[164_pc|PC]]-Relative Addressing)은 목표 주소를 절대 번지가 아니라 [[164_pc|PC]] 기준 변위([[179_displacement_addressing|Displacement]])로 표현해 `목표 = 현재 기준 + 거리` 형태로 계산하는 방식이다.
> 2. **가치**: 프로그램이 메모리 어디에 적재되든 상대 거리만 유지하면 되므로 재배치, [[333_shared_library|공유 라이브러리]], PIC (Position-Independent [[082_process_memory_structure|Code]]) 구현이 쉬워지고 [[158_instruction|명령어]] 길이도 짧아진다.
> 3. **판단 포인트**: 루프·조건 분기처럼 가까운 제어 이동에는 매우 적합하지만, 변위 범위를 넘는 먼 목적지는 long jump, veneer, trampoline 같은 보조 기법이 필요하다.

---

## Ⅰ. 개요 및 필요성

[[164_pc|PC]] 상대 주소 지정은 **"어디로 갈 것인가"를 절대 주소가 아니라 "지금 위치에서 얼마나 떨어졌는가"로 표현하는 [[173_addressing_modes|주소 지정 방식]]**이다. 절대 주소 방식이 `0x8048120으로 점프`라고 말한다면, [[164_pc|PC]] 상대 방식은 `다음 명령어 기준으로 +24바이트 이동`이라고 말한다. 주소 자체보다 **현재 위치와의 차이**를 인코딩한다는 점이 핵심이다.

이 방식이 필요한 이유는 코드가 항상 같은 메모리 번지에 놓이지 않기 때문이다. [[001_operating_system_purpose|운영체제]]의 로더 (Loader)는 실행 파일을 빈 구역에 적재하고, [[374_aslr|ASLR]] (Address Space Layout Randomization)은 보안을 위해 적재 위치를 계속 바꾼다. 분기와 호출이 절대 주소로 박혀 있으면 적재 위치가 달라질 때마다 수정 부담이 커지지만, 상대 주소는 코드 전체가 함께 이동해도 내부 거리 관계가 유지된다.

또한 실제 프로그램의 분기 대부분은 루프, 조건문, 짧은 함수 호출처럼 현재 위치 근처에서 일어난다. 그래서 매번 32비트나 64비트 절대 주소를 싣는 것보다, 짧은 변위만 싣는 편이 더 경제적이다. [[164_pc|PC]] 상대 주소 지정은 **재배치 유연성**과 **코드 밀도**를 동시에 얻기 위해 등장한 방식이다.

- **📢 섹션 요약 비유**: [[164_pc|PC]] 상대 주소 지정은 "서울시 몇 번지"를 외우는 길찾기가 아니라 "지금 서 있는 곳에서 두 블록 직진"이라고 안내하는 방식과 같다.

## Ⅱ. 아키텍처 및 핵심 원리

[[164_pc|PC]] 상대 주소 지정의 계산 자체는 단순하다. **분기 [[158_instruction|명령어]]에 들어 있는 변위를 부호 확장한 뒤, PC에 더해 목표 주소를 만든다.** 다만 여기서 말하는 PC는 많은 [[157_isa|ISA]] ([[157_isa|Instruction Set Architecture]])에서 "현재 [[158_instruction|명령어]]의 시작 주소"가 아니라 **다음 순차 [[158_instruction|명령어]]의 주소**를 기준으로 쓰는 경우가 많다. 그래서 같은 `-8` 분기라도 아키텍처별 기준점을 알아야 정확한 목적지를 계산할 수 있다.

| 요소 | 역할 | 설계 포인트 |
| :--- | :--- | :--- |
| [[164_pc|PC]] (Program [[059_counter|Counter]]) | 기준 주소 제공 | 대개 다음 [[158_instruction|명령어]] 주소 기준 |
| 변위 필드 ([[179_displacement_addressing|Displacement]] Field) | 상대 거리 저장 | [[073_bit|비트]] 수가 작을수록 도달 범위 제한 |
| 부호 확장 (Sign Extension) | 음수/양수 이동 지원 | 뒤로 가는 루프 분기에 필수 |
| 주소 가산기 | `PC + 변위` 계산 | 파이프라인 [[015_지연_데이터_관점|지연]] 최소화가 중요 |
| 링커 (Linker) | 최종 변위 확정 | 범위 초과 시 veneer/trampoline [[087_process_state_transition|생성]] 가능 |

아래 그림은 조건 분기 명령이 실제 목표 주소를 만드는 과정을 보여 준다.

```text
┌────────────────────────────────────────────────────────────────────┐
│ PC-relative branch target generation                              │
├────────────────────────────────────────────────────────────────────┤
│ instruction @ 0x1000 : BNE -12                                    │
│ instruction length   : 4 bytes                                    │
│                                                                    │
│ step 1. fetch completes -> PC points to next instruction          │
│         PC = 0x1004                                                │
│                                                                    │
│ step 2. displacement field = -12                                  │
│         sign-extend(-12) = 0xFFFF FFF4                            │
│                                                                    │
│ step 3. target = PC + displacement                                │
│         0x1004 + (-12) = 0x0FF8                                   │
│                                                                    │
│ taken     -> PC <- 0x0FF8                                         │
│ not taken -> continue with 0x1004                                 │
└────────────────────────────────────────────────────────────────────┘
```

이 그림의 실질적 포인트는 세 가지다. 첫째, **뒤로 가는 분기**는 음수 변위로 표현된다. 둘째, 하드웨어는 이를 2의 보수 (Two's Complement) 값으로 받아 부호 확장해 덧셈한다. 셋째, 같은 명령 형식으로 앞쪽 분기와 뒤쪽 분기를 모두 처리할 수 있으므로 루프 구현이 매우 효율적이다.

현대 ISA는 이 원리를 제어 흐름뿐 아니라 [[001_dikw_pyramid|데이터]] [[316_reference_pattern_nosql|참조]]에도 확장한다. 예를 들어 x86-64는 [[158_instruction|명령어]] 포인터 기준 상대 [[316_reference_pattern_nosql|참조]]로 전역 상수와 테이블을 읽고, [[195_risc|RISC]] (Reduced [[158_instruction|Instruction]] Set Computer) 계열은 [[164_pc|PC]] 근처 리터럴 풀 (Literal Pool)이나 분기 후 로드 패턴으로 이를 활용한다. 즉 [[164_pc|PC]] 상대 주소 지정은 단순 점프 기술이 아니라 **위치 독립 코드의 기본 문법**이다.

- **📢 섹션 요약 비유**: 이 방식은 내비게이션이 집 주소 전체를 다시 계산하는 대신, 현재 위치에서 남은 거리만 더해 목적지에 도착하는 방식과 같다.

## Ⅲ. 비교 및 연결

[[164_pc|PC]] 상대 주소 지정은 "덧셈을 한다"는 점에서 다른 [[173_addressing_modes|주소 지정 방식]]과 비슷해 보이지만, **무엇을 기준으로 삼는가**가 다르다. 이 차이를 이해해야 [[181_indexed_addressing|인덱스 주소 지정]], 베이스 [[175_register_addressing|레지스터 주소 지정]]과 헷갈리지 않는다.

| 방식 | 기준점 | 가변 값 | 강한 상황 | 한계 |
| :--- | :--- | :--- | :--- | :--- |
| 절대 주소 지정 (Absolute Addressing) | 없음 | 주소 자체 | 멀리 있는 고정 대상 | 재배치 취약, [[158_instruction|명령어]] 길이 큼 |
| 베이스 [[175_register_addressing|레지스터 주소 지정]] ([[180_base_register_addressing|Base Register Addressing]]) | 메모리 구역 시작점 | 작은 변위 | [[001_dikw_pyramid|데이터]] 영역, 재배치 | 현재 명령 흐름 기준은 아님 |
| [[181_indexed_addressing|인덱스 주소 지정]] ([[181_indexed_addressing|Indexed Addressing]]) | [[055_array|배열]]/테이블 시작점 | [[154_database_index_b_tree_search_optimization|인덱스]] | 순차 [[001_dikw_pyramid|데이터]] 순회 | 분기 대상 표현엔 부적합 |
| [[057_register|레지스터]] [[177_indirect_addressing|간접 주소 지정]] ([[178_register_indirect_addressing|Register Indirect Addressing]]) | [[057_register|레지스터]] 안 주소 | 포인터 값 | 동적 호출, 연결 구조 | 포인터 준비 비용 필요 |
| [[164_pc|PC]] 상대 주소 지정 ([[164_pc|PC]]-Relative Addressing) | 현재 명령 위치 | 분기/[[316_reference_pattern_nosql|참조]] 변위 | 지역 분기, PIC, 공유 코드 | 도달 범위 제한 |

특히 베이스 [[175_register_addressing|레지스터 주소 지정]]은 "프로그램이 어느 구역에 적재되었는가"에 강하고, [[164_pc|PC]] 상대 주소 지정은 "현재 실행 지점에서 얼마나 떨어졌는가"에 강하다. [[181_indexed_addressing|인덱스 주소 지정]]이 [[055_array|배열]] 원소 번호를 표현하는 방식이라면, [[164_pc|PC]] 상대 주소 지정은 **제어 흐름의 거리**를 표현하는 방식이다. 같은 덧셈이어도 설계 의도가 서로 다르다.

또한 [[164_pc|PC]] 상대 주소 지정은 [[231_branch_prediction|분기 예측]] ([[231_branch_prediction|Branch Prediction]])과도 잘 맞는다. 루프의 뒤로 가는 분기는 반복 패턴이 강해 예측하기 쉽고, 짧은 상대 분기는 코드 밀도를 높여 [[158_instruction|명령어]] 캐시 효율을 개선한다. 그래서 이 방식은 주소 계산 기법이면서 동시에 **제어 흐름 [[282_performance_tactics|성능]] 최적화 기법**이기도 하다.

- **📢 섹션 요약 비유**: [[181_indexed_addressing|인덱스 주소 지정]]이 책장 안에서 몇 번째 칸을 고르는 방법이라면, [[164_pc|PC]] 상대 주소 지정은 지금 읽는 페이지에서 몇 장 앞으로 넘길지를 정하는 방법에 가깝다.

## Ⅳ. 실무 적용 및 기술사 판단

실무에서 [[164_pc|PC]] 상대 주소 지정은 단순 문법보다 **재배치와 보안, 코드 크기, 도달 범위**의 판단 문제로 나타난다. [[333_shared_library|공유 라이브러리]]나 [[338_pie|PIE]] (Position-Independent Executable)를 만들 때는 코드가 어디에 적재될지 고정할 수 없으므로 [[164_pc|PC]] 상대 [[316_reference_pattern_nosql|참조]]가 사실상 기본값이 된다. 반대로 [[032_firmware|펌웨어]] 이미지가 매우 커져서 분기 목표가 멀어지면 짧은 상대 분기만으로는 닿지 않아 링커가 veneer나 trampoline을 추가해야 한다.

### 실무 판단 기준

1. **분기 대상이 가까운가?** 가까운 루프와 조건 분기라면 [[164_pc|PC]] 상대 주소 지정이 가장 경제적이다.
2. **코드가 재배치되거나 공유될 가능성이 큰가?** [[001_operating_system_purpose|운영체제]], [[333_shared_library|공유 라이브러리]], 동적 로딩 환경이면 상대 [[316_reference_pattern_nosql|참조]] 이점이 크다.
3. **변위 [[073_bit|비트]] 폭이 충분한가?** 범위를 넘으면 far branch, veneer, [[177_indirect_addressing|indirect]] jump 같은 보조 수단이 필요하다.
4. **ISA가 어떤 [[164_pc|PC]] 기준을 쓰는가?** "현재 [[158_instruction|명령어]] 주소"인지 "다음 [[158_instruction|명령어]] 주소"인지 헷갈리면 어셈블리 버그가 난다.

### [[128_water_scrum_fall_anti_pattern|안티패턴]]

- 위치 독립 코드가 필요한 환경에서 절대 주소를 직접 박아 넣는 설계
- 어셈블리 작성 시 [[164_pc|PC]] 기준점과 [[158_instruction|명령어]] 길이를 잘못 계산해 분기 위치를 틀리는 실수
- 분기 범위 한계를 무시한 채 코드 배치를 키웠다가 링커 오류를 만나는 설계

기술사 관점에서는 "[[164_pc|PC]] 상대 주소 지정 = 재배치 가능하고 짧은 분기에 유리하다"까지만 말하면 부족하다. 반드시 **범위 제한**, **링커 보조 기법**, **[[374_aslr|ASLR]]/PIC과의 연결**까지 말해 줘야 설계 판단이 살아난다.

- **📢 섹션 요약 비유**: 이 방식은 이동식 캠핑카 내부 동선처럼, 주차 위치가 바뀌어도 냉장고와 침대 사이 거리는 그대로라 다시 설계할 필요가 없는 구조와 같다.

## Ⅴ. 기대효과 및 결론

[[164_pc|PC]] 상대 주소 지정의 가장 큰 효과는 **코드를 절대 위치 의존성에서 해방한다**는 점이다. 덕분에 [[001_operating_system_purpose|운영체제]]는 프로그램을 다양한 주소에 안전하게 적재할 수 있고, 개발자는 짧은 분기 명령으로 코드 밀도와 캐시 효율을 높일 수 있다. 즉 이 방식은 단순히 "주소를 다르게 적는 법"이 아니라, 현대 실행 환경을 가능하게 한 유연성의 핵심이다.

물론 모든 문제를 해결하는 것은 아니다. 상대 변위가 짧으면 먼 대상에 닿지 못하고, ISA별 [[164_pc|PC]] 기준 차이를 잘못 이해하면 디버깅이 어려워진다. 그래서 현대 시스템은 [[164_pc|PC]] 상대 주소 지정, 간접 점프, [[329_base_register|베이스 레지스터]], 링커 보조 기법을 함께 조합한다.

정리하면 [[164_pc|PC]] 상대 주소 지정은 **"절대 번지"가 아니라 "현재 위치 + 거리"로 기억해야 하는 [[173_addressing_modes|주소 지정 방식]]**이다. 프로그램이 어디에 놓이든 내부 관계를 유지하면서 실행되게 만드는, 제어 흐름 설계의 핵심 문법으로 기억하면 된다.

- **📢 섹션 요약 비유**: 좋은 길 안내는 주소책 전체를 외우게 하지 않고, 지금 자리에서 몇 걸음 움직일지만 알려준다. [[164_pc|PC]] 상대 주소 지정도 바로 그런 방식이다.

```text
        ├──────────────▶ PIC · 공유 라이브러리 · ASLR 대응
        └──────────────▶ 범위 초과 시 veneer · trampoline 보완
```

이 흐름도는 [[164_pc|PC]] 상대 주소 지정이 단순한 분기 기법을 넘어, 재배치 가능 코드와 현대 실행 보안 구조로 이어지는 흐름을 보여 준다.

### 👶 어린이를 위한 3줄 비유 설명

1. [[164_pc|PC]] 상대 주소 지정은 "학교 정문 주소"를 외우는 대신 "지금 서 있는 곳에서 세 칸 앞으로 가"라고 알려주는 방법이에요.
2. 그래서 학교가 다른 동네로 이사 가도, 안에서 움직이는 방법은 그대로라 길을 다시 외울 필요가 없어요.
3. 컴퓨터는 이 방법 덕분에 프로그램을 여기저기 옮겨 놓아도 쉽게 점프하고 달릴 수 있어요.
