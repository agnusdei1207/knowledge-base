## Ⅰ. 개요
- **정의**: 행렬 곱셈 연산에 특화된 ASIC으로, 딥러닝 학습·추론을 가속하는 도메인 전용 프로세서
- **배경/필요성**: 딥러닝 모델의 연산 대부분이 행렬 곱셈이므로, 범용 GPU(050 참조)보다 연산 효율과 전력 대비 처리량이 높은 전용 하드웨어가 필요함
- **비유**: GPU가 만능 공구 세트라면, TPU는 나사만 조이는 전동 드라이버로 특정 작업에서 압도적으로 빠름

| 출제 의도 | 반드시 짚을 핵심 | 감점 회피 포인트 |
|:---|:---|:---|
| AI 전용 하드웨어 아키텍처 이해 | 시스톨릭 배열 구조와 데이터 재사용 원리 | GPU와의 차이를 유연성-효율 축으로 구분할 것 |

> 요약: TPU는 행렬 곱셈에 특화된 ASIC으로, 시스톨릭 배열을 통해 딥러닝 연산을 가속하는 도메인 전용 프로세서임

## Ⅱ. 구성요소
```text
Host(CPU) --PCIe/CXL--> TPU Chip
                           |
              +------------+------------+
              |            |            |
        Matrix Multiply   Activation   Normalization
          Unit (MXU)       Unit          Unit
              |
     Systolic Array (128x128 / 256x256)
        PE -- PE -- PE -- PE -->
        |     |     |     |
        PE -- PE -- PE -- PE -->
        |     |     |     |
        v     v     v     v
              |
         Accumulator
              |
      Unified Buffer (SRAM)
              |
         HBM (Off-chip)
```

| 구성요소 | 설명 | 비유 |
|:---|:---|:---|
| 시스톨릭 배열(MXU) | PE가 격자 형태로 배열되어 데이터가 한 방향으로 흐르며 곱셈-누적을 수행함 | 공장 컨베이어 벨트에서 부품이 한 방향으로 이동하며 조립되는 구조 |
| PE(Processing Element) | 1회 클록에 INT8 또는 BF16 곱셈-가산 1회를 수행하는 최소 연산 단위 | 컨베이어 위 개별 작업자 |
| Unified Buffer | 중간 결과를 저장하는 온칩 SRAM, 약 24~32 MB 용량 | 작업대 위 임시 적재 공간 |
| HBM | 고대역폭 외부 메모리, 대역폭 약 900 GB/s~2 TB/s | 대형 자재 창고 |
| Activation Unit | ReLU 등 비선형 활성화 함수를 하드웨어로 처리함 | 완성품 검수 라인 |
| ICI(Inter-Chip Interconnect) | TPU 칩 간 직접 연결, 다수 칩을 Pod 단위로 확장함 | 공장 간 전용 물류 통로 |

> 요약: 시스톨릭 배열 기반 MXU, 온칩 버퍼, HBM, 칩 간 인터커넥트가 TPU의 핵심 구성요소임

## Ⅲ. 절차
```text
가중치 로드(HBM-->Buffer) --> 입력 행렬 투입
    --> 시스톨릭 배열 곱셈-누적
        --> 활성화 함수 적용
            --> 결과 저장/다음 레이어 전달
```
- 1단계: HBM에서 가중치 행렬을 Unified Buffer로 사전 로드함
- 2단계: 입력 텐서를 시스톨릭 배열의 좌측과 상단에서 동시에 투입하여 PE가 곱셈-누적을 수행함
- 3단계: 누적 결과에 Activation Unit이 비선형 함수를 적용함
- 4단계: 처리 결과를 Buffer에 저장하고, 다음 레이어 입력으로 재투입하거나 Host로 반환함

> 요약: 가중치 로드-행렬 투입-시스톨릭 연산-활성화 적용의 4단계 파이프라인으로 레이어별 연산을 수행함

## Ⅳ. 문제점
- 범용성 부족: 행렬 곱셈 외 연산(정렬, 그래프 탐색 등)은 지원하지 않아 비정형 워크로드에 활용이 불가함
- 생태계 종속: 특정 클라우드 플랫폼과 프레임워크(TensorFlow/JAX)에 최적화되어 타 프레임워크 전환 시 성능 저하가 발생함
- 정밀도 제약: INT8/BF16 위주 연산으로 FP64가 필요한 과학 계산에는 정확도가 부족함

> 요약: 범용성, 생태계 종속, 정밀도 제약이 TPU 확산의 주요 한계임

## Ⅴ. 개선방안
1. 단기: 희소 행렬 연산·컨볼루션 등 추가 연산 패턴을 MXU에 하드웨어 가속 기능으로 확장함
2. 중기: ONNX 등 표준 모델 포맷 지원과 오픈 API 제공으로 프레임워크 독립성을 확보함
3. 장기: 가변 정밀도(FP32/FP64) 연산 유닛을 추가하여 HPC 및 과학 계산 영역으로 적용 범위를 확대함

> 요약: 연산 패턴 확장, 프레임워크 독립, 가변 정밀도 지원으로 TPU의 한계를 단계적으로 해소함

## Ⅵ. 전망
- 발전 방향: 수천 칩 규모 Pod 클러스터와 LLM 학습 전용 아키텍처로 대규모 AI 학습 인프라의 핵심이 됨
- 기술사적 판단: GPU(050 참조)와 ASIC(TPU) 간 선택은 워크로드 고정 여부에 따라 결정되며, 하이브리드 구성이 확산될 전망임
- 기술사 제언: AI 가속기 선정 시 연산 유형·정밀도·생태계 호환성을 종합 평가하는 의사결정 프레임워크 수립이 필요함
