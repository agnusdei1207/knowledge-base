# 🌌 사내 지식저장소 (Knowledgebase)

본 프로젝트는 마크다운(Markdown) 기반의 문서를 개발자와 비개발자, 그리고 AI 에이전트가 완벽하게 공유하고 관리할 수 있도록 설계된 하이브리드 지식 저장소 허브입니다.

---

## 1. 시스템 전체 흐름도 (System Workflow)

각 구성 요소가 어떻게 상호작용하는지 나타낸 흐름도입니다.

```text
                     [ 비개발자 (Human Editor) ]
                                 │
                                 ▼ (웹 브라우저로 접속)
┌─────────────────────────────────────────────────────────────────┐
│                        1. Decap CMS                             │
│               (http://localhost:8080/admin/)                    │
└───────────┬────────────────────┬────────────────────▲───────────┘
            │                    │                    │
            │ (A. OAuth인증)     │ (C. 파일수정/커밋)  │ (D. 수정사항 실시간 빌드)
            ▼                    ▼                    │
┌───────────────────────┐ ┌───────────────┐     ┌─────┴───────────┐
│  2. Local OAuth 서버  │ │ 3. GitHub /   │ ──▶ │ 4. Quartz Server│
│ (scripts/local-oauth) │ │ Local Git     │     │   (포트: 8080)   │
└───────────────────────┘ └──────┬────────┘     └─────────────────┘
                                 │ (Markdown 원본 보관)
                                 │
                                 ▼ (Markdown 파일 마운트)
                        ┌─────────────────┐
                        │  5. MCP Server  │
                        │   (포트: 8090)   │
                        └────────▲────────┘
                                 │ (E. 지식검색 및 도구 호출)
                                 ▼
                          [ 6. AI 에이전트 ]
                        (Claude Code, AI 등)
```

### 작동 프로세스 상세:
1. **로그인 (A):** 사용자가 웹 편집기(Decap CMS)에 접속하여 로그인하면, **Local OAuth 서버**를 통해 깃허브 토큰을 안전하게 획득합니다.
2. **편집 및 저장 (C):** 사용자가 웹 UI에서 문서를 수정하면, 데이터가 즉시 **GitHub 저장소**(또는 로컬 파일)에 자동 커밋됩니다.
3. **웹 게시 (D):** 저장소의 변경사항을 감지하여 **Quartz Server**가 사람이 읽기 편한 웹사이트(연결성 그래프 포함)로 즉시 다시 빌드합니다.
4. **AI 연동 (E):** 변경된 마크다운 원본 문서를 **MCP Server**가 읽어들여, **AI 에이전트**들이 실시간으로 최신 지식을 검색하고 읽을 수 있도록 API 도구(Tools)로 제공합니다.

## 2. 핵심 설정 파일 설명

프로젝트의 중심이 되는 두 가지 설정 파일의 역할입니다.

*   `quartz.config.yaml`
    *   **역할:** **독자(Reader)용 설정** (마크다운 ➡️ 웹사이트 빌드 및 테마 설정)
    *   **주요 정보:** 사이트 타이틀, 다크모드 색상 테마, 검색 기능 제공 방식, 위키링크 해석 규칙 등
*   `static/admin/config.yml`
    *   **역할:** **편집자(Editor)용 설정** (웹 CMS 화면 필드 및 저장소 설정)
    *   **주요 정보:** 글쓰기 화면 UI 레이아웃, 필수 데이터 필드 정의(제목, 태그, 부서 등), 백엔드 Git 저장소 연동 및 OAuth 인증 주소

## 3. 실행 방법 (로컬 테스트 기준)

### ① 전체 서비스 실행 (Docker)
Quartz 웹서버(8080포트)와 MCP 서버(8090포트)를 동시에 백그라운드로 켭니다.
```bash
docker compose up -d
```

### ② 로컬 OAuth 프록시 실행 (Decap CMS 로그인용)
웹 편집기에서 GitHub 계정으로 문서를 저장하고 커밋할 수 있도록 로컬 인증 프록시를 켭니다.
```bash
OAUTH_CLIENT_ID="내_Client_ID" OAUTH_CLIENT_SECRET="내_Client_Secret" node scripts/local-oauth.js
```
*(※ 로그인 없이 로컬 파일만 수정하려면 프록시를 켜지 않고 `config.yml`의 `local_backend: true` 옵션과 `npx decap-cms-proxy-server`를 이용할 수 있습니다.)*
